# 见微：本地业主工作台、公开个人站与远程 Agent 能力改造 Goal

> 这份文字可直接作为新的 Goal。施工目录是 `D:\ALL IN AI\OasisMind-public-site-worktree`，分支是 `codex/public-site-split`。

## 总目标

在独立 Git worktree 中完成见微（OasisMind）的产品边界重构和能力升级，把当前项目明确拆成两种运行形态：

1. **本地业主工作台**：只供项目所有者使用，保留文章编辑、AI、Chat、Agent、审批、本机文件、自动化、QQ/微信、知乎等完整能力。
2. **云端公开个人站**：部署到独立域名，只展示明确发布的内容，提供方便浏览器和其他 Agent 读取的只读接口，不携带本地 AI、编辑器、鉴权后台、配置、运行数据和本机控制能力。

最终结果必须同时满足：内容不会误公开，业主可在本地长期做私人读书批注，公开页面保持当前亮色视觉风格，QQ/微信可稳定收发多模态内容并远程查看本机状态，知乎能力成为可脚本化使用的完整 CLI。改造过程中要清理重复代码和失效功能，新增代码写清楚有用的中文注释。

- 只能修改独立 worktree：`D:\ALL IN AI\OasisMind-public-site-worktree`。
- 不得修改、清理、格式化或同步用户当前工作区 `D:\ALL IN AI\OasisMind-full-clone`，尤其不得触碰该工作区正在编辑的 `content/`。
- 不批量修改现有文章内容。功能若需要新的 frontmatter，由代码兼容现状并提供检查结果，不替用户改文章。
- 保留现有首页和整体亮色风格，不做暗色版本，不把公开站改成另一套陌生设计。
- 本地完整项目和公开站必须是两个部署边界。公开站不得通过“隐藏按钮”继续携带本地 Agent 或写接口。
- GitHub 仓库可以公开，但密钥、Cookie、SQLite、私人批注、运行数据和本机路径不得进入 Git 或公开构建产物。
- 访客默认没有评论和批注写入能力。第一版公开站不提供任何文章写接口；以后若开放评论，必须另做审核、限流和反滥用设计。
- 不保留旧接口兼容层。接口和模型变化时，在同一切片修改全部调用方并删除旧路径。
- 不用 `setTimeout`、额外 `useEffect` 或刷新页面掩盖状态竞态；状态不变量应放在所属 Service、store 或 reducer。
- 用户没有明确指定的默认值、阈值或附加行为，代码中必须标记 `[OM-FREEPLAY]` 并说明依据。

## 一、发布安全和公开内容管道

### 要完成的行为

- 所有文章创建入口默认 `published=false`，包括编辑器、tRPC、Chat 转文章、Agent 工具结果和 Inbox 蒸馏。
- Markdown 全量扫描和增量扫描都只把 YAML 布尔值 `published: true` 视为已发布。
- `published` 缺失、字符串 `"true"`、数字 `1`、损坏的 YAML 都必须按未发布处理。
- 新建公开内容生成器，不允许公开站直接读取完整 `content/` 或本地 SQLite。
- 生成器只输出已发布文章所需的白名单字段、正文、搜索索引和明确引用的附件。
- 禁止复制 `config/`、`data/`、`.private/`、未发布文章、未引用附件、数据库、可执行文件和未知文件类型。
- 本地附件解析必须阻止路径穿越和指向 `content/` 外部的符号链接。
- 公开图片应在不改原图的前提下压缩，重复文件按内容哈希去重；文章取消发布后，旧 JSON 和旧资源不能残留在部署产物中。
- frontmatter 解析失败时输出明确警告并跳过，不得用正则猜测发布状态。

### 验收证据

- Schema、Service、TypeScript 扫描器、Rust 扫描器都有默认草稿测试。
- 构建测试覆盖草稿排除、错误类型排除、损坏 YAML、资源白名单、路径穿越、去发布清理。
- 在真实知识库运行公开构建成功，并报告文章数、花园数、资源数、产物体积和跳过原因。
- 对生成目录搜索后，找不到未发布文章正文、私人目录、配置或密钥字段。

## 二、本地永久私人批注和手写效果

### 数据边界

- 私人批注不写进文章正文，不进入公开 API，也不依赖可随时重建的 SQLite。
- 批注事实源放在 `content/.private/annotations/`，加入 `.gitignore`；每条批注独立保存，服务重启和数据库重建后仍可读取。
- 批注接口全部使用业主鉴权 procedure。公开站不实现对应路由，访客无法通过猜 URL 写入。
- 文件写入要防路径穿越，并采用可恢复的临时文件/备份替换流程，避免中途退出破坏已有笔记。

### 锚点和交互

- 选择正文后可执行：高亮、手写下划线、波浪线、添加评论。
- 锚点至少保存选中文字 `exact`、前文 `prefix`、后文 `suffix`、纯文本起止偏移。
- 页面加载时先按偏移校验；正文变化后按 exact + 上下文重新定位；无法定位的批注进入“失配”列表，不能静默消失。
- 批注侧栏显示引文、评论、样式、时间和状态，可跳转到原文、修改评论/样式、删除批注。
- 保存后打开中的页面立即更新，刷新后仍存在。
- Markdown 内已有 `<mark data-annotation="...">` 的手写效果恢复工作。sanitize 只能放行所需的受限 data 属性，事件处理器、脚本和危险协议仍必须被移除。
- 私人批注交互只出现在本地业主阅读页；公开站不展示批注按钮和私人内容。

### 验收证据

- 单元测试覆盖创建、重启后读取、更新、删除、孤儿文章拒绝、损坏文件报错和路径隔离。
- 锚点纯函数测试覆盖原文未变、前方插入、重复引文消歧和完全失配。
- 浏览器测试覆盖选择文字、保存批注、刷新保留、点击侧栏跳转、删除后消失。
- 安全测试证明手写 data 属性保留，而 `onerror`、`javascript:`、`script` 等仍被清洗。

## 三、独立公开个人站与只读 Agent API

### 页面和设计

- 新建 `apps/site`，作为可独立构建和部署的公开站。
- 保留现有首页的亮色、留白、字体层级和品牌气质；不做暗色主题。
- 页面至少包括：首页、文章/知识库总览、花园页、文章页、标签/分类筛选、搜索、About、404。
- 公开站只消费公开内容生成器的产物，不连接本地 Express、Prisma、Agent 或 tRPC 写接口。
- 文章页支持 Markdown、GFM、KaTeX、代码高亮、目录、图片、视频、音频、附件链接和现有手写标注。
- 抽取真正可共享的 Markdown 渲染核心，避免本地站和公开站维护两套不一致规则；本机专属功能通过外层组件注入，不进入公共核心。

### 只读接口

- 提供版本化只读接口，例如 `/api/v1/index.json`、`/api/v1/search.json`、单篇文章 JSON/Markdown、花园索引和资源地址。
- 输出稳定字段和 schemaVersion，文章有稳定 id、garden、slug、title、excerpt、category、tags、content、contentHash。
- 支持 Agent 先取索引/搜索结果，再按路径读取单篇，避免一次下载整个知识库。
- 不存在公开的 POST、PUT、PATCH、DELETE；不暴露草稿、私人批注、编辑器状态和本地文件路径。
- 配置 robots、sitemap、RSS/Atom、OpenGraph 和基础缓存头。

### 收拢旧博客

- `apps/site` 的公开阅读链路稳定后，删除本地 `/blog` 的重复页面、匿名评论入口和“访客可见编辑链接”。
- 本地 `/posts` 保留为业主文章工作台：阅读、编辑、私人批注和 AI 辅助都在这里完成。
- 菜单、内链、搜索结果和文档全部指向唯一的新入口，禁止留下两套文章展示页面。

### 验收证据

- `apps/site` 可单独 lint、test、build，构建产物中搜索不到 Agent、Chat、审批、密钥和私人批注代码。
- 未登录浏览器只能读到生成器输出的发布文章，找不到编辑按钮和写请求。
- 公开 API 契约测试覆盖索引、搜索、单篇、404、草稿不可见和方法拒绝。
- 对主要页面做桌面与移动端截图检查，确认风格未偏离现有首页。

## 四、QQ/微信统一多模态与远程查看本机

### 统一附件模型

- 建立统一 `ChannelAttachment`，覆盖 text、image、video、audio、file。
- 字段至少包括 id、kind、fileName、mimeType、size、sha256、source、localPath/storageKey、remoteUrl/remoteId、caption 和传输状态。
- QQ、微信入站消息先归一化到统一模型，再交给 Agent；Agent 出站结果先生成统一附件，再由通道适配器发送。
- 去掉“非图片附件降级成一段路径文字”的旧逻辑。

### 收发可靠性

- 入站图片、视频、语音和普通文件下载到受控目录，校验大小、MIME、哈希和安全文件名。
- 出站支持文本、图片、视频、音频、文件以及文本加附件；平台限制导致失败时返回明确原因。
- 同一消息重试不能重复发送；传输状态可查询，失败可安全重试。
- 大文件、超时、平台不支持格式和失效 URL 有明确提示，不允许静默吞掉。

### 远程本机查看

- 提供统一的桌面截图、指定窗口截图、网页可视区截图和网页全页截图工具。
- 截图必须能作为图片附件通过 QQ/微信回传，而不是只返回本机路径。
- 支持读取和发送用户授权目录内的文件，所有本机访问继续受 `hostAccess` 根目录和危险操作审批约束。
- Agent 能完成“查看当前桌面 → 截图回传 → 根据用户反馈继续调试”的闭环。
- 修正文档/Skill 与实际截图参数不一致的问题，只保留一套真实契约。

### 验收证据

- 统一附件 schema 和适配器有单元测试，覆盖五种附件、错误 MIME、重复消息和发送失败。
- QQ 与微信各有入站和出站集成测试；没有真实凭据时使用严格 mock，但必须保留真实平台探测命令。
- 实机烟测至少完成一次网页截图和一次桌面/窗口截图，并验证返回结果可被通道发送。

## 五、知乎 CLI 完善

### 命令能力

- 保留已有登录状态、搜索、读取回答、评论、关注检查和保存能力，并统一为稳定 CLI。
- 支持搜索置顶/高赞文章、按问题 id 或 URL 获取回答。
- 支持按赞同数、评论数、时间、相关度等明确字段排序；不支持的组合直接报错。
- 支持只看已关注作者、排除已关注作者、不做关注过滤。
- 支持按话题/标签搜索与过滤，并能组合关键词、问题、作者、时间范围和分页。
- 每个命令同时支持适合人看的表格输出和适合 Agent 的 `--json` 结构化输出。
- 支持稳定的 limit、cursor/page、超时、退出码和错误信息；Cookie 只读本地受控目录，不打印到日志。
- 搜索结果字段至少包括内容类型、id、标题/摘要、作者、问题、赞同数、评论数、发布时间、关注状态、标签和 URL。

### 验收证据

- 解析与过滤逻辑用离线 fixture 测试，不依赖每次都访问知乎。
- CLI 帮助文本列出所有参数和示例；非法组合返回非零退出码。
- 在有效登录态下做真实只读烟测：关键词搜索、指定问题回答、排序、关注过滤、标签过滤各至少一次。
- 真实烟测不得执行关注、点赞、评论或发布等外部写操作。
