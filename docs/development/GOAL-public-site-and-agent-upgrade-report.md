同日继续补齐 GitHub Pages 上线准备：新增公开站专用工作流，构建时自动适配默认项目路径
`/OasisMind` 或未来自定义域名根路径；文章 JSON、Markdown、图片、搜索、Manifest、robots、
sitemap 和 RSS 使用同一个部署地址。工作流只上传 `apps/site/out`，上传前拒绝符号链接、
硬链接、私密顶层目录和超过 1 GiB 的产物。最终上传审计还会逐个读取可检查文本，拒绝本机项目路径、
用户主目录、私人批注目录、SQLite 本地连接、私钥正文和高置信密钥赋值。账号侧尚未开启 Pages，
因此这里只记为“可部署”，不冒充“已经上线”。

发布安全复审还发现并修复了一条增量同步边界：文章原先为已发布状态、随后把 YAML 改坏时，
TypeScript `scanFile` 会返回空结果，使 SQLite 可能保留旧 `published=true`。现在损坏 YAML 会产生
明确警告，并以不读取任何元数据的 fail-closed 记录覆盖缓存，update/create 两侧都强制写入
`published=false`。Rust 全量扫描和 TypeScript 增量扫描均增加缺失、字符串、数字与损坏 YAML
测试；公开构建测试也直接验证文章取消发布后旧 JSON、Markdown 和内容寻址附件一起消失。

## 最终边界

```text
本地业主工作台
  Markdown / YAML 事实源
  ├─ 文章编辑、AI、Agent、审批和自动化
  ├─ content/.private/annotations（私人批注）
  ├─ QQ / 微信适配器与受控本机访问
  └─ 知乎只读 CLI
            │
            │ public:content 严格白名单生成
            ▼
公开内容产物
  ├─ api/v1/index.json / search.json
  ├─ 单篇 JSON / Markdown
  └─ 按哈希去重的引用资源
            │
            ▼
apps/site 纯静态公开站
  首页 / 知识库 / 花园 / 文章 / 搜索 / About / 404
  只有 GET / HEAD / OPTIONS，不包含本地 tRPC、编辑器或 Agent
```

本地完整项目和公开站不是一套页面靠按钮显隐，而是两个构建、两个运行边界。公开站只消费生成产物，不连接 Express、Prisma、SQLite 或本机文件系统。

## 通道和截图验收

统一附件覆盖 `text`、`image`、`video`、`audio`、`file`。QQ 与微信都经过同一附件事实模型，再由平台适配器处理平台差异。发送台账以通道、目标、消息和附件哈希形成幂等键，失败状态可查询并安全重试。

顶层适配器测试不是把平台 helper 换成测试替身：它从真实 `sendAttachment` 入口发出五类统一附件，并以只接受正式协议端点的网络桩核对平台请求。QQ 的四类媒体分别映射为官方 `file_type=1/2/3/4`；微信依次映射为上传 `media_type=1/2/4/3` 和消息 `type=2/5/3/4`，因此统一模型的 `audio` 到两端 voice 的转换也被直接锁定。QQ 与微信入站测试分别把 JPEG、MP4、MP3 和 PDF 下载、校验、哈希并落到受控目录，错误 MIME 仍保留失败附件和明确原因。

`capture_screenshot(web_viewport)` 的真实 PNG 落盘结果分别交给 QQ、微信严格适配器发送；两条路径均得到 `sent` 台账，再用相同幂等键调用一次，平台发送函数仍只执行一次。该测试证明截图结果能够进入统一通道发送链路，而不只是返回一个本机路径对象。
