## 来源与数值核对

[LongHorizon-Harness 原论文](https://arxiv.org/html/2608.01964)引言及 §2 讨论相互依赖步骤中的错误传播、任务状态管理与独立环境验证。图中的数据库迁移和时间戳来自配套正文自拟的教学例子；图片以机制示意为目的，与原论文图及实验数据分开记录。

正文给定 A=`12:00:00.120`、B=`12:00:00.870`，相差 `870−120=750` 毫秒。字段只保留到秒时，两条记录均变为 `12:00:00`；若只按该字段排序且没有第二排序键，原来的先后顺序无法从新字段恢复。图上两条输入、两个并列输出与正文一致。

字段定义位于 `t1`，灰度验证在 `t5` 首次发现排序碰撞，所以式 (6) 的验证距离为 `5−1=4` 步。橙色括号仅圈出依赖该字段的 `t2` 写迁移脚本、`t3` 转换旧数据、`t4` 修改读路径，共三项待复查动作；若式 (7) 的后继节点集合也纳入 `t5` 验证事件，则单位权重下后继数至少为四。三项待复查不等于三项都已出错。

## 制作记录边界

当前制作记录表明先用 `image_gen.imagegen` 生成候选，因内容过简未采用，随后生成并选定现版 PNG。现存 Git 提交只有 PNG 与正文，没有可编辑源文件或原始生成提示词；PNG 也没有标明底层模型版本的元数据。因此**无法确认模型版本和逐字提示词**，不把此前的任务要求冒充工具提示词。可核实的制作要求是：把两条不同毫秒时间戳变成同一秒级排序键的过程放进图中，同时标出四步验证延迟和三项受影响后继，并使时间值与正文一致。

本次核对实际使用本地图像查看、Pillow 读取格式与尺寸、`Get-FileHash` 计算 SHA-256，并逐项比对正文数字、公式和图内标签；没有重新生成或修改 PNG。
