# 技术文章写作规范(见微)

> 2026-09-27 立。这是**活规范**: 新规则只往上叠, 不另起文档, 不用只含一条新规则的片段覆盖本文。模型库专项细则见 `docs/development/model-library-writing-plan.md`, 本文是总纲; 两者冲突时以本文为准。
>
> 适用: 模型库对照稿(bi)/技术解析(analysis)/知识库一切技术文章。

## 1. 总则

1. **读者锚点**: 训练, 推理与系统, 架构与数学, 评测与 Agent 四层都涉猎, 但都不深入。读者读过很多技术报告。不写谁都能答的入门内容, 不重讲教科书概念(RoPE, MHA, SFT, AdamW, next-token prediction)。
2. **说人话**: 去 AI 味。同型句式骨架(成串「不是 X, 而是 Y」)和「非常」类渲染词降密度。技术文按 `config/skills/shuorenhua/` 的 docs 场景 minimal 档过一遍, 保公式/数字/术语不漂移。
3. **直接陈述, 不写元评论**: 不写「本篇只钉」「源文 §4.2」「先看配置」「把 37B 复核一遍」「证据状态」「流传的」「旧稿」这类交代自己怎么读稿/怎么改稿的话。从模型本身说: 从架构上看, 从路由上看。
4. **Changelog 不进正文**: 变更记录(「● Updated...」「Fixed typo...」「### 2026 年 2 月 6 日」这类修订历史)是写给维护者看的, 不是给读者的。源文里的 Changelog 节整节删除, 页标记保留。
5. **报告里没给的数, 要么不写, 要么标「报告里没写, 是纯猜的」**, 不要写成「估算, 报告没有给」。

## 2. 术语死命令

1. **专名留英文**: token, Scaling, Scaling Laws, decoder-only, MLA, MoE, MTP, CoT, GRPO, PPO, RoPE, GQA, YaRN, DPO, SFT, next-token prediction, RLHF。首次出现可写 **MTP** (一次再多预测一个 token), 之后只用英文缩写。
2. **禁用中文译名**: 令牌, 缩放律, 多令牌预测, 多头潜变量注意力, 混合专家, 思维链。
3. **保持中文**: 预训练, 微调, 强化学习, 编码器, 潜变量, 词表, 评测时。
4. **两条轴不许混**:
   - **缩放** 只指部署前把模型和数据做大(第一轴)。禁止用缩放说推理时多花算力。
   - **TestingTime** 是第二轴: 推理时多花的算力(test-time scaling / compute / reasoning)。中文禁止写「测时」「测试时」, 就写 TestingTime。
   - **评测时** 不是 TestingTime。评测时指跑榜, 保留中文。
5. 错例: 「测时算力成了第二轴: OpenAI o 系列缩放强化学习与测时推理」。对例: 「缩放指部署前投入更多算力. TestingTime 算力是第二轴: OpenAI o 系列把强化学习与 TestingTime 推理做大.」

## 3. 语言与标点

1. 中文正文全用**英文标点**: , . : ; ( ) " "。术语和专名按第 2 节。
2. 中文引语用直角引号「」; 英文原文里的引号留在英文段。不要把整篇中文都换成直引号, 也不要用中文弯引号“”。
3. 加粗只给关键机制名和判断(负特征值, safe-completion, 路由器); 年份, 页码, 表号, 随手出现的百分数不加粗。不用比喻 (见 §3.6.1)。
   - 加粗和直角引号不互斥, 可以同时出现: `**「推拉结合」**` 和 `「**自注意力只做一件事**」` 都可以, 按语义选, 不用为了避开其中一个去删另一个 (2026-10-04 用户定). `humanwrite/references/scy.md` 里「不使用 Markdown 加粗」是科学空间的习惯, 本库不照搬.
4. 长句优先拆短。能落到式子/表/图的判断, 必须指回去。

## 3.5 花园首页（2026-09-27 用户驳回后立的新规）

首页是门脸，不是目录。机械罗列链接的写法一塌糊涂。

1. **散文定位**: 开头一段有味道的散文——这个花园回答什么问题、为什么存在、读完变成什么样。不用比喻 (见 §3.6.1)。
2. **导航克制**: 不放裸链接清单，不放逐条罗列（文章列表由页面自动渲染，首页不需要复制一份）。链接按主线分组, 每组配成段的导读。
3. **给读法不给清单**: 内容多的园子给阅读路径（从哪进、按什么顺序、赶时间怎么读），让读者自己走进林子。
4. **门脸三禁**: 无元评论（改稿历史、迁移备注、工作流说明），无日期戳，无机器生成的 slug 列表。
5. **所有首页不少于 2000 汉字** (2026-10-04 用户定, 废止上一版「小园子首页不超过 20 行」和「索引页只做导航」): 花园首页, 章首页, 节首页一律适用. 篇幅来自真内容: 这一章各篇之间的关系和演进顺序, 共用的概念和记号在这里定义一次, 各方法的关键差别 (可以用对照表, 表后要有成段的解释), 按读者背景给的读法. 内容取自本章文章, 数字与正文一致. 不许凑字, 不许把每篇的摘要排成一列.
6. **禁止模板化导读** (2026-10-04 用户定): 不写「本节回答的问题」「本章回答的问题」「这一篇回答什么」这类小节, 也不用「篇 | 回答的问题」这种表头. 文章开头不写「这一篇回答什么」的问题清单, 直接进入材料和问题. 各篇的结构跟着内容走, 不要每篇都套同一副骨架 (例如每个小节末尾固定一个「归类」小节).
7. **目录与编号** (2026-10-04 用户定): 每篇文章放在同名文件夹里, 写成 `{编号-名}/{编号-名}.md`, 不许把文章裸放在章节目录下; 有子文档的父文档也必须是同名文件夹里的同名文件 (`2.5-线性注意力/2.5-线性注意力.md`): 侧栏 (`PostTreeNav` 的 `buildTree`) 只把「最后一段与上一段同名」的文档挂到文件夹节点上, 文件夹里没有同名文件, 侧栏只显示一个点不开正文的空分组. 同一目录下的编号从 1 (或 0) 连续往下排, 删篇或挪篇后要补号, 不许留 01, 02, 04 这种断档; 同一目录只用一种编号, 节一级用 `x.y.z-`, 节下的文章用 `01-`, 不许两种混在一层; 有编号的目录下不许出现无号文章. 文件夹名不用全角冒号, 顿号和空格. 内容重复的旧稿删掉, 链接改指留下的那篇. 检查脚本: `layout_check.py` (BARE / GAP / MIX / PREFIX / NOIDX / NONUM / NAME 全为 0).

## 3.6 技术文章硬规范 (2026-09-28 并入, 源自账号计划 STYLE.md + H2O 示范稿 scy.md)

叠在第 1–3 节上; 冲突时以更严者为准。

1. **禁止比喻/类比/拟人化** (废止 §3 第 4 条的「每段最多一个比喻」). 直接陈述机制, 不打比方。标明「入门类比」并写清局限的也不行, 作者自己旧稿里的类比 (如 2.2.1 的「图书馆检索」) 一样删掉, 换成直接的机制陈述或手算例子 (2026-10-04 用户定)。
2. **默认不写 `## 太长不看版`** (2026-10-04 用户定: 不是每篇都需要, 很多文章没法总结, 只有真的太长才可能需要). 只有同时满足两条才加: 正文超过约 10000 汉字; 内容能收成几条确定的结论和数字 (一个方法的核心改动与效果, 一个模型的关键改动与成绩). 推导型, 综述型, 多个机制并列, 讲过程的文章不写. 加的话只写一段, 三到五句, 不复述目录, 不列清单. 小标题不许叫「先给结论」.
3. 符号第一次出现就地解释 (包括输入从哪来), 不甩符号表, 不跳步. 术语前后一致, 改名必须交代「X(即前文的 Y)」.
4. 每个机制写清四件事: 谁算, 谁和谁计算, 缓存/状态怎么变, 丢了什么.
5. ~~数学公式一律 `$$` 独占一行, 禁止行内单个 `$`.~~ (2026-10-04 用户废止: 不包 `$` 的符号会把 LaTeX 源码直接给读者看.) 现行规则: 正文里出现的符号, 变量, 下标, 短式子一律用 `$...$` 包裹 (写 $\theta_k$, 不写 θ_k; 写 $d_k=3$, 不写 d_k=3), 不允许裸写 LaTeX 或带下划线的纯文本符号. 需要推导, 编号或较长的式子用 `$$` 独占一行. 公式与文字同步: 文字讲到哪一步, 公式就跟到哪一步, 不许纯文字跳公式也不许纯公式不解释.
6. 代码块只放需等宽的纯 ASCII 图 (掩码/层排布/路线图), 禁止在代码块里写伪公式.
7. **少用指代**: 「这套」「那个」「它」「同样的」必须落成具体名词; 前文没讲清的先补定义再引用.
8. 变量注释用 `\underbrace` 挂在单个变量下方 (一个变量一条, 不许多变量共用一个大括号).
9. **篇幅** (2026-10-04 用户定): 每一篇正文不少于 5000 汉字. 大多数文章在 8000 汉字左右, 内容复杂的可以到 15000. 不允许凑数: 篇幅来自把机制, 推导, 实验, 前后版本和边界讲透, 不来自重复前文, 套话, 空泛总结或换说法再讲一遍. 材料本身单薄时, 补的是相关技术的来龙去脉和对照, 并且每一处都有出处.
   - 适用范围: 正文文章. 花园首页 `_garden.md`, 章首页, 节首页按 §3.5 第 5 条, 不少于 2000 汉字.
   - **少分节, 少分点** (2026-10-04 用户定: 「段落不要分那么多, 动不动七八点甚至十几个点」「大标题内没有小标题就很无意义」): 一篇正文的 `##` 一般 3 到 5 个, 最多 6 个 (参考文献不计). 每个 `##` 下至少两个 `###`; 撑不起两个子节的 `##`, 并进别的 `##`. 列表最多 5 项, 超过的改写成段落或表; 不要用列表代替论述, 能写成连贯段落的就写段落.
   - **一个标题下不许只有一段话** (2026-10-04 用户明确禁止): 任何 `##`/`###` 标题下 (到下一个标题前) 至少两段成文的内容; 只有一张表, 一个式子或一个列表也不行, 必须配解释段. 内容只够一段的, 并进相邻小节, 删掉这个标题, 不要为了撑出第二段去凑字. 合并后重排节号, 文中的「§x.y」「第 x.y 节」引用同步改.
   - 例外: 一个主题确实讲透了还不到 5000, 再写只能加空洞内容时, 就不到 5000. 这个例外要慎之又慎: 先查机制, 推导, 实验, 前后版本, 边界条件, 工程细节是不是都讲到了; 同主题的短篇能合并的先合并. 都做了还不够, 才停.
10. **不能有 AI 味** (2026-10-04 用户强调): 写完按 `config/skills/shuorenhua/` 或 `.cursor/skills/humanizer-zh/` 回读一遍. 重点查: 开头和结尾的套话, 口号式总结, 成串的「不是 X, 而是 Y」, 「非常 / 深刻 / 至关重要 / 本质上」一类渲染词扎堆, 三连排比, 每段都以加粗金句收尾, 「值得注意的是 / 需要指出的是」一类空转连接词, 以及审计式元评论 (见 §7). 同一种句式骨架在一节里出现三次以上就改写.

## 3.7 作者的拆解方式与表达习惯 (2026-10-04, 从 llm-guide 2.1 / 2.2 提炼)

本节记录作者自己写的 2.1 深度学习基础组件, 2.2.1 自注意力机制, 2.1.2 归一化层里反复出现的做法. 这些是**讲清一个东西时会从哪些方面想**, 不是模板: 不要求每节都出现, 不许拿来当小标题抄. 哪个角度能把问题讲清就用哪个, 用不上就不用. 第 7 节「谁算, 和谁算, 缓存/状态怎么变, 丢了什么」「改了什么, 为什么改, 机制, 代价, 效果」同理.

### 3.7.1 拆解方式

1. **先讲它要解决的困难, 再讲它是什么.** 2.1.2 开头先写「训练深层网络非常依赖初始化, 学习率和梯度裁剪」, 再引出归一化. 不从定义起笔.
2. **先摆粗略说法, 再给更严格的理解.** 「最常见的粗略说法是: 归一化层可以减少内部协变量偏移. 这种说法有启发性, 但不够准确. 更严格的理解是……」. 指出粗略说法哪里不准, 不是直接否定它.
3. **开篇列出本文回答的几个问题**, 用编号. 2.1.2 是「本文围绕五个问题展开」, 后文按问题推进.
4. **公式一层层往下展开到能算的程度.** 矩阵式 → 单个 token 的行向量 → 按分量求和. 每展开一层, 紧跟一句这一层回答了什么: 「这一步看起来只是把向量写长, 但它其实回答了一个很实际的问题: 后面所有点积, softmax 和加权求和, 最终都是在这些坐标分量上发生的.」
5. **每个量出现后说它回答什么问题.** 「$\mu_L$ 回答的问题不是这一批样本平均怎样, 而是这一个 token 自己当前整体偏到哪里去了.」
6. **小维度手算, 一步不省.** 2.2.1 用 `[大模型, 太, 牛逼, 了]`, $d_k=3$, 把点积, 缩放, softmax 的分子分母, 逐维加权全部写出来, 最后放回矩阵视角: 「矩阵公式没有比标量公式多做别的事, 它只是把每个 token 都做一遍同样的计算并行化了.」 反向传播用「步骤 | 计算 | 结果」的走查表.
7. **同一对象的几个视角放进一张表**: 视角, 一句话版本, 回答的问题. 并写明哪个视角只是近似, 它在哪里不准 (「软检索视角是近似: 真实检索是 hard top-k, 注意力是对所有 Value 的 soft 混合」).
8. **对照着讲两个相近的方法**, 落到同一个可比的维度上. BatchNorm 和 LayerNorm 比的是统计轴; Post-Norm 和 Pre-Norm 并排写两个式子: 「这两个公式看起来只是顺序交换, 但训练行为差异很大.」
9. **讲「为什么不适合」时分条给原因**, 写在段内: 「原因主要有三个. 第一……第二……第三……」.
10. **随手补边界.** 结论后面跟一句它不能推出什么, 或者取决于什么: 「这只是权重分布而不是解释」; 「局部统计稳定不等于全局损失曲面, 收敛速度或最终性能的保证」; 「RMSNorm 的计算减少不代表 LayerNorm 的数学目标错误; 具体融合收益取决于实现和硬件」.
11. **每张图紧跟图注, 图注后再写「图 N 解析」.** 图片下一行必须是图注 `> 图 N: <这张图画的是什么>` (一句完整话, 写清对象, 横纵轴或模块, 出处如「原文 Figure 3」); 连续几张子图共用一个图注, 写在最后一张下面. 图注之后才是「图 N 解析」, 2–4 条: 节点和边各是什么, shape 是什么, 图里没画什么, 不能据此推出什么. 只给实际存在的图写; 图没有就不写解析. bi 稿里原文有英文题注的保留原文题注 (题注不译), 原文没有题注的图补一行中文图注. 图片统一放在文章所在目录的 `images/` 下, 不建 `<文章名>-images` 这类平级目录. 检查: `python scripts/caption-check.py <目录>`.
12. **落到工程检查项.** 归一化层最后按训练, 量化, 长上下文三个场景列「该监控什么」. 工程影响常按训练, 推理, 量化三段分开讲.
13. **代码对应公式.** docstring 写「对应公式: ……」, 注释写 shape, 用 assert 验维度, 手算梯度和 autograd 对照打印.
14. **出处跟在第一次提到的地方**: [Ba, Kiros, & Hinton (2016)](https://arxiv.org/abs/1607.06450) 提出的 Layer Normalization. 历史只给年份, 人物和一句后果 (Minsky 和 Papert 1969 年证明单个感知机只能解线性可分问题).
15. **讲完好处, 紧跟代价.** 「但代价是位置上限被固化在参数表中」「但 ReLU 也有明确代价:」. 对比表的最后一列通常是「代价」或「想解决的问题」.
16. **演进史按「每一步补上一步的缺口」排**, 最后把几条路线的分歧收成一个轴: 「这几条路线的分歧, 不在有没有位置信息, 而在位置信息应该加在哪一层」.
17. **展开后交换求和顺序, 让原式里看不出的结构露出来.** MHA 式 (12) 把检索权重 $\alpha$ 和 $W_V$ 拆开; MLA 把分数写成系数与位置无关的双线性型, 由此得到矩阵吸收.
18. **一族方法放到同一条参数轴上, 两端退化成已知方法.** GQA 的组数 $G=H$ 是 MHA, $G=1$ 是 MQA; Block AttnRes 的 $N=L$ 是 Full AttnRes, $N=1$ 退回标准残差.
19. **先立参照系, 后面只写相对它改了什么, 没改什么**: 「MQA 不改变式 (8) 的形式; 压缩只发生在 cache 里的 $k_s, v_s$」.
20. **同名方法按「作用在哪一截张量上」区分**: 注意力子层从输入到残差加法有六处可以加门, 列一张表写清每个方法加在哪一处.
21. **推理按 Prefill 和 Decode 分开算**, 计算量和访存各算一遍; 「存下来的」和「临时算的」分开: 历史 Q 不存也不读, 是计算, 不是缓存.
22. **数字标口径**: 来自哪张表, 哪个规模, 训了多少 token. 正面陈述 (「74.64 是 Table 1 的 Hellaswag 一列」), 不写成「核对要点: 不是 MMLU」.
23. **消融逐条写「换掉了什么, 数值变成多少, 为什么」**: 「softmax 换成 sigmoid, 1.741, 缺了竞争归一化」.
24. **失效模式单独一节**, 常以「最常见的失效不是 A, 而是 B」开头, 再分「若太小……若太大……」.

### 3.7.2 句子习惯

1. 术语第一次出现就地解释, 括注英文: 「logits 指模块在 softmax 或离散决策前输出的原始分数」「reduce 指沿某个维度把很多数聚合成少量统计量」.
2. 一句话记忆点, 加粗单独成段: 「**自注意力只做一件事: 在 token 之间搬运信息——QK 决定从哪搬, OV 决定搬什么, 写去哪.**」 后面紧跟一段解释这句话为什么比常见说法更接近本质.
3. 核心判断加粗: 「**归一化不是通用的, 而是强依赖数据结构和推理模式.**」 一节最多一两处.
4. 高频连接: 「也就是说」「换句话说」「这里的关键不是 X, 而是 Y」「它回答的问题不是 X, 而是 Y」. 后两个句式受 §1.2 密度约束, 一节一次为宜.
5. 例子可以口语化 (「牛逼」), 数字必须能复算. 作者原稿里的口语句 (「拍桌子」「这个方法不是白送的」) 改稿时保留, 不改成中性说法.
6. 公式前的引导写动作: 「代入式 (7)–(8) 可得:」「交换求和顺序:」「同理:」, 或「X 给出的形式是:」. 公式后马上解释符号, 再用「式 (N) 说明……」接一句它的作用.
7. 手算前先声明假设和省略了什么 (「省略 RoPE 与 $\sqrt{d_h}$ 缩放」「仅示意, 非训练所得」), 再分步, 每步标对应的式号.
8. 小标题可以是问句, 正文第一个词直接回答: 「约束和为 1 会不会降低表达力——不会, 前提是……」.
9. 用「只」「仅」划清改动范围: 「GQA 的改动仅在 cache 的 KV 组数 $G$」.
10. 代码注释写 shape 和共享关系; 代码后一段写「这段代码说明两件事. 第一……第二……」或逐项列「`inv_freq` 对应式 (3) 的频率谱」.

### 3.7.3 作者文里混进的, 不算作者风格

以下是批量插入或别人写的, 改稿时删除, 不得模仿:

- 公式前后的空套话: 「基于前述物理直觉, 给出数学形式:」「推导过程如下:」「为建立定量关系, 定义如下表达式:」「此式将上述直觉形式化, 各项分别对应输入变换, 非线性激活与输出生成.」「该关系式明确了系统的数学约束」.
- 引错的式号 (「如式 (26) 所示」而式 (26) 不存在).
- 章节首页末尾成串的「为什么……」「最重要的心智模型」「真正意义」「学习重点清单」, 重复前文.
- 自己写的抽象式后面声明「这不是论文原式」. 有原式用原式; 需要抽象时直接写, 不加声明.
- 「技术前瞻」「本节小结」只复述前文或以口号收尾的, 删掉; 有出处的趋势可以留.
- 批量插入的「## 设计取舍」节 (「在 X 与 Y 之间存在持续张力……最终取决于……」).
- 对着不存在的图写的「图 N 解析」, 以及混进正文的画图指令 (「避免把……误画成……」「不用箭头冒充 tensor 流」).
- 「不要把 X 写成 Y」成串的警告, 「核对要点」, 「本次未打开 PDF」「本会话」这类改稿记录.
- 双语模板的文献题 (「注意力就是你所需要的一切(Attention Is All You Need)」). 文献题保留原文.
- 机器截断的 excerpt (停在半句, 带转义的 LaTeX 或不带 `$` 的符号).
- 「真正的 X 不是 A, 而是 B」扎堆. 这是作者的句式, 但一节最多一次.

## 6. 对照译稿(bi)规范

1. 按 MinerU 源文结构**全文对照**, 不是摘要。每个英文段落在前, 中文意译(信达雅)紧接在后。
