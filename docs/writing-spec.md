# 技术文章写作规范(见微)

> 2026-09-27 立。这是**活规范**: 新规则只往上叠, 不另起文档, 不用只含一条新规则的片段覆盖本文。模型库专项细则见 `docs/development/model-library-writing-plan.md`, 本文是总纲; 两者冲突时以本文为准。
>
> 适用: 模型库对照稿(bi)/技术解析(analysis)/知识库一切技术文章。

## 1. 总则

1. **读者锚点**: 训练, 推理与系统, 架构与数学, 评测与 Agent 四层都涉猎, 但都不深入。读者读过很多技术报告。不写谁都能答的入门内容, 不重讲教科书概念(RoPE, MHA, SFT, AdamW, next-token prediction)。
2. **说人话**: 去 AI 味。同型句式骨架(成串「不是 X, 而是 Y」)和「非常」类渲染词降密度。技术文按 `config/skills/shuorenhua/` 的 docs 场景 minimal 档过一遍, 保公式/数字/术语不漂移。
3. **直接陈述, 不写元评论**: 不写「本篇只钉」「源文 §4.2」「先看配置」「把 37B 复核一遍」「证据状态」「流传的」「旧稿」这类交代自己怎么读稿/怎么改稿的话。从模型本身说: 从架构上看, 从路由上看。
4. **Changelog 不进正文**: 变更记录(「● Updated...」「Fixed typo...」「### 2026 年 2 月 6 日」这类修订历史)是写给维护者看的, 不是给读者的。源文里的 Changelog 节整节删除, 页标记保留。
5. **报告里没给的数, 要么不写, 要么标「报告里没写, 是纯猜的」**, 不要写成「估算, 报告没有给」。

## 2. 术语死命令

1. **专名留英文**: token, Scaling, Scaling Laws, decoder-only, MLA, MoE, MTP, CoT, GRPO, PPO, RoPE, GQA, YaRN, DPO, SFT, next-token prediction, RLHF。首次出现可写 **MTP** (一次再多预测一个 token), 之后只用英文缩写。
2. **禁用中文译名**: 令牌, 缩放律, 多令牌预测, 多头潜变量注意力, 混合专家, 思维链。
3. **保持中文**: 预训练, 微调, 强化学习, 编码器, 潜变量, 词表, 评测时。
4. **两条轴不许混**:
   - **缩放** 只指部署前把模型和数据做大(第一轴)。禁止用缩放说推理时多花算力。
   - **TestingTime** 是第二轴: 推理时多花的算力(test-time scaling / compute / reasoning)。中文禁止写「测时」「测试时」, 就写 TestingTime。
   - **评测时** 不是 TestingTime。评测时指跑榜, 保留中文。
5. 错例: 「测时算力成了第二轴: OpenAI o 系列缩放强化学习与测时推理」。对例: 「缩放指部署前投入更多算力. TestingTime 算力是第二轴: OpenAI o 系列把强化学习与 TestingTime 推理做大.」

## 3. 语言与标点

1. 中文正文全用**英文标点**: , . : ; ( ) " "。术语和专名按第 2 节。
2. 中文引语用直角引号「」; 英文原文里的引号留在英文段。不要把整篇中文都换成直引号, 也不要用中文弯引号“”。
3. 加粗只给关键机制名和判断(负特征值, safe-completion, 路由器); 年份, 页码, 表号, 随手出现的百分数不加粗。一个段落最多一个比喻。
4. 长句优先拆短。能落到式子/表/图的判断, 必须指回去。

## 3.5 花园首页（2026-09-27 用户驳回后立的新规）

首页是门脸，不是目录。机械罗列链接的写法一塌糊涂。

1. **散文定位**: 开头一段有味道的散文——这个花园回答什么问题、为什么存在、读完变成什么样。可以有比喻，不堆砌。
2. **导航克制**: 不放裸链接清单，不放逐条罗列（文章列表由页面自动渲染，首页不需要复制一份）。链接最多三四组，每组一句人话导读；小园子首页不超过 20 行。
3. **给读法不给清单**: 内容多的园子给阅读路径（从哪进、按什么顺序、赶时间怎么读），让读者自己走进林子。
4. **门脸三禁**: 无元评论（改稿历史、迁移备注、工作流说明），无日期戳，无机器生成的 slug 列表。

## 4. 禁用词总表

出现过即打回, 不适用「引用原文」豁免(引原文时也该改写或截断):

- 本篇只钉, 写死, 钉死, 打死, 钉在(比喻义)
- 若只记三件事, 有三处值得记住, 值得记住的近亲表述
- 往下钻, 工程账, 机制账, 一本总账, 第二本账, **记账**
- 一座桥, 一律外链, 不在此重推, 不注水, 架构精读
- 这里我卡住了, 别混账
- **面试**(见第 5 节: 疑惑答案里禁止出现面试腔)
- **打通**(比喻义, 如「打通章节/打通链路」; 技术实义如「打通梯度/通信」可用)
- **说清**(「把 X 说清」口头禅, 用「讲清/说明白」或删掉)
- **专文**(用「单独成篇/单独一篇」)

「钉在」作实义(钉在某一层的设置)可用, 作比喻(把 claim 钉在参照上)禁用。

## 6. 对照译稿(bi)规范

1. 按 MinerU 源文结构**全文对照**, 不是摘要。每个英文段落在前, 中文意译(信达雅)紧接在后。
2. **必须翻**: 正文一切散文(Abstract, Introduction, 各节正文, Conclusion)。**不翻**: References, Acknowledgements, 作者名单, 图表题注, 目录, Changelog(删除而非保留), 被试模型输出/提示样本(保留原文, 可加「引用样本保留原文」标注)。
3. 页标记 `<!-- page k of N -->` 从 1 到 N 各一次, 顺序不下降, 位置与源文对应, 删内容时页标记保留。
4. **跨页断句算一段**: 英文句子被分页/图切断时, 译文合成一段, 放在最后一个断片之后; 不要把译文也切成两截。
5. 常规标题不译也不另起一行: Abstract, Introduction, References, Conclusion, Appendix。其余标题保留中文时写在同一行。
6. 公式, 表, 图, images/ 路径保留, 数字不改。禁止把 14.8 拆成 14. 8, 禁止拆开 ../, .md, https://。

## 7. 技术解析(analysis)规范

1. 不是第二遍翻译, 不是辞藻堆砌。写这篇真正用到的技术的前世今生: 它是什么, 为什么这样设计, 怎么做, 代价, 在这篇怎么用, 与其他技术怎么拼, 效果, 同队前后版本改了什么。这些是思考线索, **禁止当小节标题抄**。
2. llm-guide 已有推导就链接(先确认文件存在, 相对路径 ../../../../llm-guide/..., 文件名里的中文冒号不改), 不重推 MLA, RoPE, GRPO, PPO。
3. 小节编号: 篇名 `#` 不编号, 大段 `## 1.`, 机制 `### 1.1.`, 需要才用 `#### 1.1.1.`。每个有内容的 ## 至少两段中文。禁止通篇同级标题一路排, 也禁止小标题一串每节两三行。
4. 汉字 ≥5000(完整论文)。短公告/模型卡文首写 `[OM-FREEPLAY] 材料不够 5000`, 禁止凑字数编架构, 材料不够就停。
5. 长度跟着机制走: 论文规定了几件就讲完几件, 讲完了短就保持短。公式按项写开, 消融写清关掉的是哪个量, 配比/日程/损失写到能复述。
6. 禁用词按第 4 节; 不写审计式元评论; 报告没给的数标「报告里没写, 是纯猜的」。

## 8. 评审清单(交付前必过)

- [ ]  正文无未翻译散文(参考文献/致谢/作者/题注/目录除外); 无 Changelog 残留
- [ ]  全文无第 4 节禁用词(含疑惑块内); 疑惑答案无面试腔
- [ ]  术语按第 2 节; 两条轴没混; 评测时没写成 TestingTime
- [ ]  中文全部英文标点; 引号按第 3 节
- [ ]  疑惑块(如有): 标签全白名单, 无废题, 无入门题, 答案指回本文式/表/图
- [ ]  页标记 1..N 各一次; 图路径与源文一致; 源文 SHA256 写前写后一致
- [ ]  analysis: 编号层次合规, 字数达标或有短材料标记, 链接打得开
