# 技术文章写作规范(见微)

> 2026-09-27 立。这是**活规范**: 新规则只往上叠, 不另起文档, 不用只含一条新规则的片段覆盖本文。模型库专项细则见 `docs/development/model-library-writing-plan.md`, 本文是总纲; 两者冲突时以本文为准。
>
> 适用: 模型库对照稿(bi)/技术解析(analysis)/知识库一切技术文章。
>
> 新建知识库、面对陌生领域选择分类轴或设计整棵目录时, 先读 [`knowledge-base-design.md`](knowledge-base-design.md). 本文负责文件结构与文章写法, 该手册负责知识库类型、调研建树和拆分决策.

## 1. 总则

1. **读者锚点**: 训练, 推理与系统, 架构与数学, 评测与 Agent 四层都涉猎, 但都不深入。读者读过很多技术报告。不写谁都能答的入门内容, 不重讲教科书概念(RoPE, MHA, SFT, AdamW, next-token prediction)。
2. **说人话**: 去 AI 味。同型句式骨架(成串「不是 X, 而是 Y」)和「非常」类渲染词降密度。技术文按 `config/skills/shuorenhua/` 的 docs 场景 minimal 档过一遍, 保公式/数字/术语不漂移。
3. **直接陈述, 不写元评论**: 不写「本篇只钉」「源文 §4.2」「先看配置」「把 37B 复核一遍」「证据状态」「流传的」「旧稿」这类交代自己怎么读稿/怎么改稿的话。从模型本身说: 从架构上看, 从路由上看。
4. **Changelog 不进正文**: 变更记录(「● Updated...」「Fixed typo...」「### 2026 年 2 月 6 日」这类修订历史)是写给维护者看的, 不是给读者的。源文里的 Changelog 节整节删除, 页标记保留。
5. **报告里没给的数, 要么不写, 要么标「报告里没写, 是纯猜的」**, 不要写成「估算, 报告没有给」。

## 2. 术语死命令

1. **专名留英文**: token, Scaling, Scaling Laws, decoder-only, MLA, MoE, MTP, CoT, GRPO, PPO, RoPE, GQA, YaRN, DPO, SFT, next-token prediction, RLHF。首次出现可写 **MTP** (一次再多预测一个 token), 之后只用英文缩写。
2. **禁用中文译名**: 令牌, 缩放律, 多令牌预测, 多头潜变量注意力, 混合专家, 思维链。
3. **保持中文**: 预训练, 微调, 强化学习, 编码器, 潜变量, 词表, 评测时。
4. **两条轴不许混**:
   - **缩放** 只指部署前把模型和数据做大(第一轴)。禁止用缩放说推理时多花算力。
   - **TestingTime** 是第二轴: 推理时多花的算力(test-time scaling / compute / reasoning)。中文禁止写「测时」「测试时」, 就写 TestingTime。
   - **评测时** 不是 TestingTime。评测时指跑榜, 保留中文。
5. 错例: 「测时算力成了第二轴: OpenAI o 系列缩放强化学习与测时推理」。对例: 「缩放指部署前投入更多算力. TestingTime 算力是第二轴: OpenAI o 系列把强化学习与 TestingTime 推理做大.」

## 3. 语言与标点

1. 中文正文全用**英文标点**: , . : ; ( ) " "。术语和专名按第 2 节。
2. 中文引语用直角引号「」; 英文原文里的引号留在英文段。不要把整篇中文都换成直引号, 也不要用中文弯引号“”。
3. 加粗只给关键机制名和判断(负特征值, safe-completion, 路由器); 年份, 页码, 表号, 随手出现的百分数不加粗。不用比喻 (见 §3.6.1)。
   - 加粗和直角引号不互斥, 可以同时出现: `**「推拉结合」**` 和 `「**自注意力只做一件事**」` 都可以, 按语义选, 不用为了避开其中一个去删另一个 (2026-10-04 用户定). `humanwrite/references/scy.md` 里「不使用 Markdown 加粗」是科学空间的习惯, 本库不照搬.
4. 长句优先拆短。能落到式子/表/图的判断, 必须指回去。
5. **重点必须能扫读出来** (2026-10-05 用户补充): 技术文章不能从头到尾保持同一视觉权重. 每个主要小节应挑出一到两个真正影响理解的机制判断、结论或边界, 用 `**...**` 加粗; 方法名、概念标签、需要辨析的短语和作者原话式命名可用直角引号 `「...」` 标出. 加粗不是给名词涂色, 也不是把整段变粗: 单个 `###` 通常不超过两处, 连续两段不要都以粗体句开头. 读者只扫标题和粗体时, 应能抓住文章的论证主线; 直角引号用于界定概念, 不能替代正常论述.

## 3.5 花园首页（2026-09-27 用户驳回后立的新规）

首页是门脸，不是目录。机械罗列链接的写法一塌糊涂。

1. **散文定位**: 开头一段有味道的散文——这个花园回答什么问题、为什么存在、读完变成什么样。不用比喻 (见 §3.6.1)。
2. **导航克制**: 不放裸链接清单，不放逐条罗列（文章列表由页面自动渲染，首页不需要复制一份）。链接按主线分组, 每组配成段的导读。
3. **给读法不给清单**: 内容多的园子给阅读路径（从哪进、按什么顺序、赶时间怎么读），让读者自己走进林子。
4. **门脸三禁**: 无元评论（改稿历史、迁移备注、工作流说明），无日期戳，无机器生成的 slug 列表。
5. **所有首页不少于 2000 汉字** (2026-10-04 用户定, 废止上一版「小园子首页不超过 20 行」和「索引页只做导航」): 花园首页, 章首页, 节首页一律适用. 篇幅来自真内容: 这一章各篇之间的关系和演进顺序, 共用的概念和记号在这里定义一次, 各方法的关键差别 (可以用对照表, 表后要有成段的解释), 按读者背景给的读法. 内容取自本章文章, 数字与正文一致. 不许凑字, 不许把每篇的摘要排成一列.
6. **禁止模板化导读** (2026-10-04 用户定): 不写「本节回答的问题」「本章回答的问题」「这一篇回答什么」这类小节, 也不用「篇 | 回答的问题」这种表头. 文章开头不写「这一篇回答什么」的问题清单, 直接进入材料和问题. 各篇的结构跟着内容走, 不要每篇都套同一副骨架 (例如每个小节末尾固定一个「归类」小节).
7. **知识库目录树** (2026-10-05 用户修订): 文件是否必须使用同名目录, 只由它是不是叶子节点决定. 叶子文章下面没有子知识节点, 可以直接写成父目录下的 `{编号-名}.md`, 也可以写成 `{编号-名}/{编号-名}.md`; 两种形式都合法. 叶子文章带有 `images/` 等配套资源时, 通常保留同名目录更便于收拢. 非叶子文章下面还要容纳子知识节点, 必须写成 `{编号-名}/{编号-名}.md`, 子节点放进这个同名目录. 不得把需要承载子知识节点的父文章裸放在上一级目录.

   **层级从花园内部开始计数, 不把知识库根目录和 `_garden.md` 算作一级.** 例如 `sparse-attention/02-动态路由/NSA.md` 只有“大章 → 具体技术”两级, 即使从文件系统路径看已经经过知识库根目录, 也不能称为三级. 真正的三级应为“大章 → 技术路线 → 具体技术”, 例如 `02-动态路由/01-原生稀疏/02-NSA.md`; 如果具体技术下面还要拆论文版本、训练与内核等子节点, 具体技术也必须升级为同名目录和同名首页. “至少三级”指真实的知识关系, 不得用空目录、只有链接的壳页或把同一篇文章机械切段来凑层数.

   中间层首页承担路线综述: 说明这条路线解决什么问题、方法之间按什么轴分化、先读哪篇以及共同使用哪些记号. 写到典型方法时, 用一两句点明关键改动并直接链接到该方法的详细解析页; 不在路线首页重复一遍详细页, 也不只列方法名和链接. 例如介绍动态索引路线时可以概括 DSA、HISA、MISA 的关系, 但推导、训练目标、内核和实验应进入各自叶子文章.

   | 节点类型 | 合法结构 | 说明 |
   |---|---|---|
   | 叶子文章 | `2.1-训练目标.md` 或 `2.1-训练目标/2.1-训练目标.md` | 没有下级知识节点时, 平铺和同名目录两种形式都合法. |
   | 非叶子文章 | `2.5-线性注意力/2.5-线性注意力.md` | 同名 Markdown 是该节点首页, 子内容与它同处一个目录. |
   | 花园首页 | `_garden.md` | 只放在花园根目录, 不再套 `_garden/`. |
   | 章或节首页 | `03-后训练/03-后训练.md` | 章或节必然承载下级内容, 所以属于非叶子节点; 花园根目录不计入知识层级. |

   判断时看完整知识树, 不看当前文件扩展名. 一个 `.md` 只要还有下级知识内容, 就是父节点, 必须进入同名目录. 一个目录如果在侧栏中代表可打开的文章节点, 必须包含与目录同名的 `.md`. 纯分组目录可以只组织若干叶子文章, 不强制虚构一篇同名首页; 纯资源目录也不算知识节点, 例如 `images/`, `assets/` 和论文处理产生的中间目录. 分组目录和资源目录不得冒充文章参与文章编号序列.

   侧栏 (`PostTreeNav` 的 `buildTree`) 通过“Markdown 文件名与所在目录名相同”识别文章节点首页. 非叶子文章缺少同名 Markdown 时, 侧栏只能显示无法打开的空节点, 因此属于结构错误; 明确只承担分类职责的分组目录不受此条约束. 叶子 Markdown 直接挂在父目录下时仍是可打开文章, 不属于裸文件错误. 如果叶子后来新增子知识内容, 必须在同一次改动中创建同名目录, 把原 Markdown 移为该目录的同名首页, 并修正所有站内链接; 如果父文章删到不再有子知识节点, 可以继续保留同名目录, 也可以收拢成上一级目录中的叶子 Markdown, 变更路径时要同步修正链接.

8. **编号与命名**: 同一父目录下的知识节点按显示顺序连续编号, 从 1 开始; 明确需要序章时可以从 0 开始. 删篇、挪篇或把叶子升级为父节点后都要重查同级编号, 不得出现 `01, 02, 04` 之类的断档. 同一层只用一种编号体系: 章节层使用 `01-`, `02-`; 章节内部可使用 `1.1-`, `1.2-`; 某一节下的论文或文章可重新使用 `01-`, `02-`. 同一目录不得混用 `01-` 与 `1.1-`, 有编号的同级知识节点中不得夹入无编号文章.

   目录名、文件名和标题各司其职. 目录与 Markdown 基名必须逐字一致, 包括编号、大小写和连字符; 文件系统名称不用全角冒号、顿号或空格. `title` 可以使用正常中文标题, 不要求复制文件名中的编号. 内容重复的旧稿应删除, 所有站内链接改指保留稿; 不保留兼容副本、跳转壳文件或两套并行目录.

9. **结构变更验收**: 新建、移动、重编号或删除知识节点时, 必须同时检查父节点首页、侧栏层级、相对链接、图片路径和 frontmatter. 验收结果至少满足: 非叶子文章均进入同名目录并有同名首页; 叶子文章无论平铺还是保留同名目录都能正常打开; 同级编号连续且格式一致; 有编号的层级没有无号知识节点; 目录名与文章首页基名一致; 链接和图片路径可达. 历史检查项中的 `BARE` 只表示“承载子知识节点却仍裸放的父文章”, 不得把合法的叶子 Markdown 判成 `BARE`; `NOIDX` 只表示应当可打开的文章节点缺同名首页, 不得把纯分组目录和资源目录判成 `NOIDX`. 其他结构错误沿用 `GAP`, `MIX`, `PREFIX`, `NONUM`, `NAME` 分类.
10. **顶级名称展开缩写**: 文件夹 slug 保持简短稳定, 花园 `title` 和正文 H1 面向读者写完整. 技术缩写采用「缩写 · 英文全称 · 中文含义」, 例如 `OPD · On-Policy Distillation · 在线策略蒸馏`、`RSI · Recursive Self-Improvement · 递归自我改进`; 已经清楚的品牌名或普通中文名不强行套三段式. 标题用于解释这座库是什么, 不把宣传语、版本号或文章数量塞进名称.

### 3.5.1 页面职责与拆分时机 (2026-10-06 用户补充)

文件树表达知识关系, 正文结构表达论证关系. 两者必须一起设计, 不能先把文件随意摊平, 再靠首页补链接;也不能为追求目录层数把一篇完整论证机械切成几份.

1. **花园首页给全局坐标**: 说明领域为什么形成, 几条主线怎样相连, 读者可以从哪里进入. 可以使用路线图或家族对照表, 随后必须有成段解释. 首页不承担某个算法的完整推导.
2. **章首页建立共同问题**: 定义本章共享的对象、反馈来源、参照方法与比较口径. 例如偏好优化章先区分比较数据、reward model、reference 与在线采样, 再分 RLHF 和直接偏好优化. 章首页不把每个叶子算法各摘要一遍.
3. **路线首页建立家族参照系**: 三个以上叶子方法共享一套起点、记号或失效模式, 且这些共同内容足以写成不少于 2000 汉字的独立文章时, 增加真实的中间节点. 路线首页先把 baseline 推到可比较的位置, 再说明各叶子究竟改了哪一个量. 例如 `偏好优化 → 直接偏好优化 → DPO / IPO / ORPO / SimPO / KTO`.
4. **算法叶子完成一条闭合论证**: 写清问题在什么约束下出现, 朴素 baseline 怎样运行、解决了什么又留下什么, 再解释后续方法分别改变哪个变量、为什么可能有效、证据有多强以及新增了什么代价. 材料适合从反常实验、版本变化或旧路线复活进入时, 就从那里进入. §3.5.2 给出完整的思考框架;它约束论证是否闭合, 不规定小标题和段落顺序.
5. **比较页只做真正的横向比较**: 先固定基础模型、数据、采样预算、奖励、reference 和指标口径, 再比较算法. 如果一页主要在讲某个方法自己的推导, 就归入该方法叶子, 不因为标题里出现“对比”便另建比较节点.
6. **中间层的建立条件**: 只有一个叶子, 或共同内容只能写成几行链接时, 不建路线首页. 两个叶子若形成明确分叉且共同机制足够完整, 可以建立;方法很多但彼此没有共同 baseline, 应分到不同路线, 不能只因为缩写相近塞进同一目录.
7. **正文去重按职责处理**: 共同定义、统一记号和家族比较留在上层首页;完整公式、手算、伪代码、实验数字与单篇论文边界进入叶子. 上层提到典型方法时用一两句点出改动并链接, 叶子不再重写整章导论. 迁移内容后逐段检查, 不用删除整篇或回滚整个版本代替去重.
8. **导航来自结构, 不是正文模板**: 侧栏由目录树生成, 正文无需重复一份裸目录. 页面开头可以给前置链接或阅读顺序, 但不能让每篇都出现完全相同的“一句话、动机、方法、实验、参考”七段标题. 统一的是读者需要获得的信息, 不是标题措辞和段落数量.

### 3.5.2 算法发展因果链 (2026-10-07 用户确认)

算法史的主线是问题和约束怎样推动方法演进. 单按年份排列论文, 这条线很容易被论文名淹没. 一条技术路线真正需要讲清的是: **问题怎样在一组具体约束下产生, 朴素解法把问题推进到哪里, 哪些故障仍然存在, 后续算法分别改了什么, 这些改动为何有效, 又把代价转移到了哪里.** 读完以后, 读者应当能够面对一篇新论文, 自己判断它修改了数据、状态、目标、估计器、模型结构还是系统实现, 以及它解决的故障是不是当前场景的主要瓶颈.

写作时在脑中检查下面这条因果链:

1. **问题与外部条件**: 目标是什么, 当时受哪些硬件、数据、规模、接口和训练阶段约束, 原方法又默认了哪些假设. 同一个算法在不同约束下可能得到相反评价, 所以不能先写“谁更好”再补条件.
2. **可运行的朴素 baseline**: 说明输入、输出、中间状态、数据来源和目标函数;给出必要的复杂度或小规模手算;同时交代它在哪些条件下已经够用. 后续方法必须能指回这个参照点.
3. **沿因果链拆故障**: 把“效果差”拆成目标偏差、估计方差、状态覆盖、优化不稳、系统吞吐、模型容量、数据质量或评测口径等可区分原因. 不同故障需要不同修法, 不能用一个算法名覆盖整条链.
4. **算法究竟改了哪个变量**: 固定其余条件, 说明方法改变了轨迹来源、反馈粒度、散度、采样器、状态表示、网络结构、更新规则还是硬件映射. 同一家族的方法放在共同坐标中比较, 不逐篇复述摘要.
5. **为什么有效以及证据有多强**: 严格区分四种证据. **理论证明**给出假设下的收敛、无偏性、方差或复杂度结论;**机制推导**解释梯度、概率质量或状态怎样变化;**受控实验**在固定底座、数据、预算和解码后验证因果变量;**大规模实践规律**来自多个规模、任务或系统的重复观察. 机制推导不能直接冒充 benchmark 结论, 经验规律也不能写成无条件定理.
6. **新问题与代价转移**: 每个改进都要追踪新增代价. 稀疏计算可能引入索引器和不规则 kernel;critic 提供状态条件化估计, 同时引入价值偏差和额外训练;回放提高利用率, 同时增加策略陈旧. 算法解决了多少、代价转移到哪里, 决定它是否真的适合当前场景.
7. **后续分叉与负结果**: 说明后续方法分别修哪一个遗留故障, 包括理论漂亮但假设不成立、只在小规模有效、benchmark 上有效却无法部署的路线. 失败方法可以解释设计空间为何收敛到今天的位置, 不应从技术史中消失.
8. **旧路线为什么复活**: 检查硬件、模型规模、数据、上下文长度、训练阶段、系统组件和评价目标是否发生变化. 过去的主要缺陷可能被新 kernel、可靠验证器或更大规模摊薄, 也可能只是降为次要矛盾. 写清变化的外部条件, 避免用“风水轮流转”代替原因.
9. **算法贡献与系统增益分开**: 横向比较尽量固定底座、数据、训练 token、采样预算、推理预算、奖励、解码方式和硬件实现. 若收益主要来自更强基础模型、更长输出或新 kernel, 就按实际来源说明, 不全部记到算法名下.
10. **形成选择能力**: 文章结尾可以总结, 但总结应收敛成条件判断. 读者需要能够回答“长度扩大十倍时哪个假设先坏”“教师只能返回文本时哪些目标失效”“硬件不支持不规则稀疏时 FLOPs 降低是否有意义”这类问题, 而不只是背出论文结论.

**这十项是作者脑中的检查框架, 不是正文模板.** 禁止把每篇文章机械写成十个同名小节, 也禁止为了覆盖检查项补空泛段落. 具体文章应从材料最有力量的位置进入:有的从朴素方法的失败开始, 有的从一条反常实验曲线开始, 有的从硬件条件变化带来的旧算法复活开始. 标题、顺序和篇幅都跟着论证走, 最终让上述因果链在全文中闭合即可.

## 3.6 技术文章硬规范 (2026-09-28 并入, 源自账号计划 STYLE.md + H2O 示范稿 scy.md)

1. **禁止比喻/类比/拟人化** (废止 §3 第 4 条的「每段最多一个比喻」). 直接陈述机制, 不打比方。标明「入门类比」并写清局限的也不行, 作者自己旧稿里的类比 (如 2.2.1 的「图书馆检索」) 一样删掉, 换成直接的机制陈述或手算例子 (2026-10-04 用户定)。
2. **默认不写 `## 太长不看版`** (2026-10-04 用户定: 不是每篇都需要, 很多文章没法总结, 只有真的太长才可能需要). 只有同时满足两条才加: 正文超过约 10000 汉字; 内容能收成几条确定的结论和数字 (一个方法的核心改动与效果, 一个模型的关键改动与成绩). 推导型, 综述型, 多个机制并列, 讲过程的文章不写. 加的话只写一段, 三到五句, 不复述目录, 不列清单. 小标题不许叫「先给结论」.
3. 符号第一次出现就地解释 (包括输入从哪来), 不甩符号表, 不跳步. 术语前后一致, 改名必须交代「X(即前文的 Y)」.
4. 每个机制写清四件事: 谁算, 谁和谁计算, 缓存/状态怎么变, 丢了什么.
5. ~~数学公式一律 `$$` 独占一行, 禁止行内单个 `$`.~~ (2026-10-04 用户废止: 不包 `$` 的符号会把 LaTeX 源码直接给读者看.) 现行规则: 正文里出现的符号, 变量, 下标, 短式子一律用 `$...$` 包裹 (写 $\theta_k$, 不写 θ_k; 写 $d_k=3$, 不写 d_k=3), 不允许裸写 LaTeX 或带下划线的纯文本符号. 需要推导, 编号或较长的式子用 `$$` 独占一行. 公式与文字同步: 文字讲到哪一步, 公式就跟到哪一步, 不许纯文字跳公式也不许纯公式不解释.
6. 代码块只放需等宽的纯 ASCII 图 (掩码/层排布/路线图), 禁止在代码块里写伪公式.
7. **少用指代**: 「这套」「那个」「它」「同样的」必须落成具体名词; 前文没讲清的先补定义再引用.
8. 变量注释用 `\underbrace` 挂在单个变量下方 (一个变量一条, 不许多变量共用一个大括号).
9. **篇幅** (2026-10-07 用户修订): 每一篇正文不少于 5000 汉字, **通常控制在 8000–12000 汉字**. 超过 12000 汉字时, 必须存在无法自然拆开的连续推导、版本演进或实验论证;超过 15000 汉字时, 原则上拆成真实叶子或压缩, 不再把 20000 汉字当作目标. 过长正文会超出稳定回读和整体修订能力, 容易出现重复、概念漂移、伪标题与前后矛盾. 篇幅来自把机制、推导、实验、前后版本和边界讲透, 不来自重复前文、套话、空泛总结、通用工程检查表或换说法再讲一遍. 材料本身单薄时, 可以补相关技术的来龙去脉和对照, 每一处都要有出处;补完仍不足 5000 时记录材料边界, 不为达标制造内容.
   - 适用范围: 正文文章. 花园首页 `_garden.md`, 章首页, 节首页按 §3.5 第 5 条, 不少于 2000 汉字.
   - **少分节, 少分点** (2026-10-07 用户再次强调): 一篇正文的 `##` 一般 3 到 5 个, 最多 6 个 (参考文献不计). 每个 `##` 通常放 2 到 4 个 `###`, 全篇 `###` 通常控制在 8 到 16 个; 禁止把几十个平级小节从 `5.1` 一路编号到 `5.28`, 也禁止改用 `**5.28. ...**`、列表项或同段粗体继续模拟第四级标题. 相邻小节若共享同一个问题、推导或实验, 合并成连续段落、表格或一次完整走查. 撑不起两个子节的 `##` 并进相邻大节. 列表最多 5 项, 超过的改写成段落或表; 不要用列表代替论述, 能写成连贯段落的就写段落.
   - **一个标题下不许只有一段话** (2026-10-04 用户明确禁止): 任何 `##`/`###` 标题下 (到下一个标题前) 至少两段成文的内容; 只有一张表, 一个式子或一个列表也不行, 必须配解释段. 内容只够一段的, 并进相邻小节, 删掉这个标题, 不要为了撑出第二段去凑字. 合并后重排节号, 文中的「§x.y」「第 x.y 节」引用同步改.

## 3.7 作者的拆解方式与表达习惯 (2026-10-04, 从 llm-guide 2.1 / 2.2 提炼)

本节记录作者自己写的 2.1 深度学习基础组件, 2.2.1 自注意力机制, 2.1.2 归一化层里反复出现的做法. 这些是**讲清一个东西时会从哪些方面想**, 不是模板: 不要求每节都出现, 不许拿来当小标题抄. 哪个角度能把问题讲清就用哪个, 用不上就不用. 第 7 节「谁算, 和谁算, 缓存/状态怎么变, 丢了什么」「改了什么, 为什么改, 机制, 代价, 效果」同理.

### 3.7.1 拆解方式

1. **先讲它要解决的困难, 再讲它是什么.** 2.1.2 开头先写「训练深层网络非常依赖初始化, 学习率和梯度裁剪」, 再引出归一化. 不从定义起笔.
2. **先摆粗略说法, 再给更严格的理解.** 「最常见的粗略说法是: 归一化层可以减少内部协变量偏移. 这种说法有启发性, 但不够准确. 更严格的理解是……」. 指出粗略说法哪里不准, 不是直接否定它.
3. **开篇列出本文回答的几个问题**, 用编号. 2.1.2 是「本文围绕五个问题展开」, 后文按问题推进.
4. **公式一层层往下展开到能算的程度.** 矩阵式 → 单个 token 的行向量 → 按分量求和. 每展开一层, 紧跟一句这一层回答了什么: 「这一步看起来只是把向量写长, 但它其实回答了一个很实际的问题: 后面所有点积, softmax 和加权求和, 最终都是在这些坐标分量上发生的.」
5. **每个量出现后说它回答什么问题.** 「$\mu_L$ 回答的问题不是这一批样本平均怎样, 而是这一个 token 自己当前整体偏到哪里去了.」
6. **小维度手算, 一步不省.** 2.2.1 用 `[大模型, 太, 牛逼, 了]`, $d_k=3$, 把点积, 缩放, softmax 的分子分母, 逐维加权全部写出来, 最后放回矩阵视角: 「矩阵公式没有比标量公式多做别的事, 它只是把每个 token 都做一遍同样的计算并行化了.」 反向传播用「步骤 | 计算 | 结果」的走查表.
7. **同一对象的几个视角放进一张表**: 视角, 一句话版本, 回答的问题. 并写明哪个视角只是近似, 它在哪里不准 (「软检索视角是近似: 真实检索是 hard top-k, 注意力是对所有 Value 的 soft 混合」).
8. **对照着讲两个相近的方法**, 落到同一个可比的维度上. BatchNorm 和 LayerNorm 比的是统计轴; Post-Norm 和 Pre-Norm 并排写两个式子: 「这两个公式看起来只是顺序交换, 但训练行为差异很大.」
9. **讲「为什么不适合」时分条给原因**, 写在段内: 「原因主要有三个. 第一……第二……第三……」.
10. **随手补边界.** 结论后面跟一句它不能推出什么, 或者取决于什么: 「这只是权重分布而不是解释」; 「局部统计稳定不等于全局损失曲面, 收敛速度或最终性能的保证」; 「RMSNorm 的计算减少不代表 LayerNorm 的数学目标错误; 具体融合收益取决于实现和硬件」.
11. **每张图紧跟图注, 图注后再写「图 N 解析」.** 图片下一行必须是图注 `> 图 N: <这张图画的是什么>` (一句完整话, 写清对象, 横纵轴或模块, 出处如「原文 Figure 3」); 连续几张子图共用一个图注, 写在最后一张下面. 图注之后才是「图 N 解析」, 2–4 条: 节点和边各是什么, shape 是什么, 图里没画什么, 不能据此推出什么. 只给实际存在的图写; 图没有就不写解析. bi 稿里原文有英文题注的保留原文题注 (题注不译), 原文没有题注的图补一行中文图注. 图片统一放在文章所在目录的 `images/` 下, 不建 `<文章名>-images` 这类平级目录. 检查: `python scripts/caption-check.py <目录>`.
12. **落到工程检查项.** 归一化层最后按训练, 量化, 长上下文三个场景列「该监控什么」. 工程影响常按训练, 推理, 量化三段分开讲.
13. **代码对应公式.** docstring 写「对应公式: ……」, 注释写 shape, 用 assert 验维度, 手算梯度和 autograd 对照打印.
14. **出处跟在第一次提到的地方**: [Ba, Kiros, & Hinton (2016)](https://arxiv.org/abs/1607.06450) 提出的 Layer Normalization. 历史只给年份, 人物和一句后果 (Minsky 和 Papert 1969 年证明单个感知机只能解线性可分问题).
15. **讲完好处, 紧跟代价.** 「但代价是位置上限被固化在参数表中」「但 ReLU 也有明确代价:」. 对比表的最后一列通常是「代价」或「想解决的问题」.
16. **演进史按「每一步补上一步的缺口」排**, 最后把几条路线的分歧收成一个轴: 「这几条路线的分歧, 不在有没有位置信息, 而在位置信息应该加在哪一层」.
17. **展开后交换求和顺序, 让原式里看不出的结构露出来.** MHA 式 (12) 把检索权重 $\alpha$ 和 $W_V$ 拆开; MLA 把分数写成系数与位置无关的双线性型, 由此得到矩阵吸收.
18. **一族方法放到同一条参数轴上, 两端退化成已知方法.** GQA 的组数 $G=H$ 是 MHA, $G=1$ 是 MQA; Block AttnRes 的 $N=L$ 是 Full AttnRes, $N=1$ 退回标准残差.
19. **先立参照系, 后面只写相对它改了什么, 没改什么**: 「MQA 不改变式 (8) 的形式; 压缩只发生在 cache 里的 $k_s, v_s$」.
20. **同名方法按「作用在哪一截张量上」区分**: 注意力子层从输入到残差加法有六处可以加门, 列一张表写清每个方法加在哪一处.
21. **推理按 Prefill 和 Decode 分开算**, 计算量和访存各算一遍; 「存下来的」和「临时算的」分开: 历史 Q 不存也不读, 是计算, 不是缓存.
22. **数字标口径**: 来自哪张表, 哪个规模, 训了多少 token. 正面陈述 (「74.64 是 Table 1 的 Hellaswag 一列」), 不写成「核对要点: 不是 MMLU」.
23. **消融逐条写「换掉了什么, 数值变成多少, 为什么」**: 「softmax 换成 sigmoid, 1.741, 缺了竞争归一化」.
24. **失效模式单独一节**, 常以「最常见的失效不是 A, 而是 B」开头, 再分「若太小……若太大……」.

### 3.7.2 句子习惯

1. 术语第一次出现就地解释, 括注英文: 「logits 指模块在 softmax 或离散决策前输出的原始分数」「reduce 指沿某个维度把很多数聚合成少量统计量」.
2. 一句话记忆点, 加粗单独成段: 「**自注意力只做一件事: 在 token 之间搬运信息——QK 决定从哪搬, OV 决定搬什么, 写去哪.**」 后面紧跟一段解释这句话为什么比常见说法更接近本质.
3. 核心判断加粗: 「**归一化不是通用的, 而是强依赖数据结构和推理模式.**」 一节最多一两处.
4. 高频连接: 「也就是说」「换句话说」「这里的关键不是 X, 而是 Y」「它回答的问题不是 X, 而是 Y」. 后两个句式受 §1.2 密度约束, 一节一次为宜.
5. 例子可以口语化 (「牛逼」), 数字必须能复算. 作者原稿里的口语句 (「拍桌子」「这个方法不是白送的」) 改稿时保留, 不改成中性说法.
6. 公式前的引导写动作: 「代入式 (7)–(8) 可得:」「交换求和顺序:」「同理:」, 或「X 给出的形式是:」. 公式后马上解释符号, 再用「式 (N) 说明……」接一句它的作用.
7. 手算前先声明假设和省略了什么 (「省略 RoPE 与 $\sqrt{d_h}$ 缩放」「仅示意, 非训练所得」), 再分步, 每步标对应的式号.
8. 小标题可以是问句, 正文第一个词直接回答: 「约束和为 1 会不会降低表达力——不会, 前提是……」.
9. 用「只」「仅」划清改动范围: 「GQA 的改动仅在 cache 的 KV 组数 $G$」.
10. 代码注释写 shape 和共享关系; 代码后一段写「这段代码说明两件事. 第一……第二……」或逐项列「`inv_freq` 对应式 (3) 的频率谱」.

### 3.7.3 作者文里混进的, 不算作者风格

以下是批量插入或别人写的, 改稿时删除, 不得模仿:

- 公式前后的空套话: 「基于前述物理直觉, 给出数学形式:」「推导过程如下:」「为建立定量关系, 定义如下表达式:」「此式将上述直觉形式化, 各项分别对应输入变换, 非线性激活与输出生成.」「该关系式明确了系统的数学约束」.
- 引错的式号 (「如式 (26) 所示」而式 (26) 不存在).
- 章节首页末尾成串的「为什么……」「最重要的心智模型」「真正意义」「学习重点清单」, 重复前文.
- 自己写的抽象式后面声明「这不是论文原式」. 有原式用原式; 需要抽象时直接写, 不加声明.
- 「技术前瞻」「本节小结」只复述前文或以口号收尾的, 删掉; 有出处的趋势可以留.
- 批量插入的「## 设计取舍」节 (「在 X 与 Y 之间存在持续张力……最终取决于……」).
- 对着不存在的图写的「图 N 解析」, 以及混进正文的画图指令 (「避免把……误画成……」「不用箭头冒充 tensor 流」).
- 「不要把 X 写成 Y」成串的警告, 「核对要点」, 「本次未打开 PDF」「本会话」这类改稿记录.
- 双语模板的文献题 (「注意力就是你所需要的一切(Attention Is All You Need)」). 文献题保留原文.
- `*-bi.md` 是对原论文或仓库文档的忠实翻译. 原作者使用 `we` 陈述方法、实验或观察时, 中文可保留「我们」; 这不属于站点作者与读者套近乎. 此豁免只覆盖原文第一人称, 不覆盖译者插入的审稿记录、写作说明或协作口吻.
- 机器截断的 excerpt (停在半句, 带转义的 LaTeX 或不带 `$` 的符号).
- 「真正的 X 不是 A, 而是 B」扎堆. 这是作者的句式, 但一节最多一次.

## 4. 禁用词总表

出现过即打回, 不适用「引用原文」豁免(引原文时也该改写或截断):

- 本篇只钉, 只钉, 钉成, 写死, 钉死, 焊死, 打死, 钉在(比喻义), 缺的格不编
- 若只记三件事, 有三处值得记住, 值得记住的近亲表述
- 往下钻, 工程账, 机制账, 系统账, 算法账, 训练账, 成本账, 算力账, 通信账, 显存账, 一本总账, 第二本账, 同一笔账, 两张账, **记账**
- 一座桥, 一律外链, 不在此重推, 不注水, 架构精读
- 这里我卡住了, 别混账
- 疑惑答案与普通技术正文中的**面试腔**(如「面试高频」「面试必问」「标准答案」). `content/llm-interview` 讨论的对象就是面试, 可正常使用名词「面试」, 但高频程度和年份变化必须有可靠依据, 不能用它代替技术解释.
- **打通**(比喻义, 如「打通章节/打通链路」; 技术实义如「打通梯度/通信」可用)
- **说清**(「把 X 说清」口头禅, 用「讲清/说明白」或删掉)
- **专文**(用「单独成篇/单独一篇」)

「钉在」作实义(钉在某一层的设置)可用, 作比喻(把 claim 钉在参照上)禁用。

「本篇不从截图读数」「本节不另报数字」「本章不重复推导」属于编辑过程说明, 不能留在读者正文。直接写公开材料提供了哪些数、采用哪套口径, 或链接到已有推导。类似的「钉住」「坑同款」也改成具体机制与条件。

扫描器会把所有「账/账本」「锁死」「焊在一起」以及「本篇/本花园/单独成篇」列为软提示。它们并非逐字一律删除: 财务账单、数据库记账、物理焊接等实义可以保留; 技术正文用它们比喻成本、约束或文章分工时必须改成直接表述。

## 6. 对照译稿(bi)规范

1. 按 MinerU 源文结构**全文对照**, 不是摘要。每个英文段落在前, 中文意译(信达雅)紧接在后。
2. **必须翻**: 正文一切散文(Abstract, Introduction, 各节正文, Conclusion)。**不翻**: References, Acknowledgements, 作者名单, 图表题注, 目录, Changelog(删除而非保留), 被试模型输出/提示样本(保留原文, 可加「引用样本保留原文」标注)。
3. 页标记 `<!-- page k of N -->` 从 1 到 N 各一次, 顺序不下降, 位置与源文对应, 删内容时页标记保留。
4. **跨页断句算一段**: 英文句子被分页/图切断时, 译文合成一段, 放在最后一个断片之后; 不要把译文也切成两截。
5. 常规标题不译也不另起一行: Abstract, Introduction, References, Conclusion, Appendix。其余标题保留中文时写在同一行。
6. 公式, 表, 图, images/ 路径保留, 数字不改。禁止把 14.8 拆成 14. 8, 禁止拆开 ../, .md, https://。

## 7. 技术解析(analysis)规范

1. 不是第二遍翻译, 不是辞藻堆砌。写这篇真正用到的技术的前世今生: 它是什么, 为什么这样设计, 怎么做, 代价, 在这篇怎么用, 与其他技术怎么拼, 效果, 同队前后版本改了什么。这些是思考线索, **禁止当小节标题抄**。
2. llm-guide 已有推导就链接(先确认文件存在, 相对路径 ../../../../llm-guide/..., 文件名里的中文冒号不改), 不重推 MLA, RoPE, GRPO, PPO。
3. 小节编号: 篇名 `#` 不编号, 大段 `## 1.`, 机制 `### 1.1.`, 需要才用 `#### 1.1.1.`。每个有内容的 ## 至少两段中文。禁止通篇同级标题一路排, 也禁止小标题一串每节两三行。
4. ~~汉字 ≥5000(完整论文)。短公告/模型卡文首写 `[OM-FREEPLAY] 材料不够 5000`, 禁止凑字数编架构, 材料不够就停。~~ (2026-10-07 由 §3.6.9 取代) 篇幅按 §3.6.9: 每篇不少于 5000 汉字, 通常 8000–12000, 超过 15000 原则上拆分或压缩. 短公告/模型卡材料不够时, 补这篇用到的技术本身的来龙去脉、同队前后版本对照和相关论文机制, 每处有出处;仍然禁止编架构、禁止凑字.
5. 长度跟着机制走: 论文规定了几件就讲完几件, 讲完了短就保持短。公式按项写开, 消融写清关掉的是哪个量, 配比/日程/损失写到能复述。
