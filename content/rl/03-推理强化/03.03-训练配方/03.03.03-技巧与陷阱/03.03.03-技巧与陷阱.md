## 1. 动机: 同一设计轴上的相反结论

### 1.1 冲突来自配方, 不来自机制

2025 年推理 RL 的 recipe 迅速堆积, 同一个设计问题在不同论文里给出相反答案. 归一化: GRPO(1.3.1.1 节) 对组内奖励做均值标准差归一化, REINFORCE++ 主张批级归一化, 理由是只在单一 prompt 内比较会诱发 reward hacking, 妨碍泛化; Dr. GRPO (1.3.1.1 节 §3) 又要求整个删掉标准差项, 以消除难度偏差. baseline 设计: RLOO(1.3.1.2 节) 用 leave-one-out 均值做基线, 与 GRPO 的组均值基线争同一个位置. 损失聚合: GRPO 按 response 粒度平均, DAPO(1.3.2.1 节) 改按 token 粒度求和, 1.3.2.2 节的 GSPO 把重要性比提升到序列粒度, 1.3.2.3 节的 GMPO 留在 token 级但把算术平均换成几何平均. 每个改动都有独立的动机与论文背书, 但没有一份工作在同一个框架里把它们摆在一起逐项测过.

Tricks or Traps 将冲突归因于实验设置、训练数据与模型初始化的差异: 同一个 trick 换到另一套条件下, 效果方向可能反转. 因而论文不做统一排名, 而是在固定框架里隔离评估主流技巧, 给出各自的适用场景, 并组合出只含两项技巧的 Lite PPO.

这种方法延续了经典 RL 的机制分析传统. Engstrom 等人 2020 年对 PPO 实现的拆解, 以及 Andrychowicz 等人 2020 年对 on-policy RL 超参的系统研究, 都表明实现细节足以翻转算法结论. Tricks or Traps 把同一流程用于推理 RL: 固定框架与协议, 每次只动一个设计轴, 再用多难度数据和多种模型初始化交叉验证. 其结论都受这套实验协议约束, 不能直接外推到协议之外.

论文把常见技巧归为七类: baseline 设计, 裁剪, 归一化, 过滤, 损失聚合粒度, 辅助损失 (KL, SFT), reward 设计 (长度惩罚, 格式奖励). 实验集中分析归一化, 裁剪, overlong filtering 与损失聚合; 辅助损失与 reward 设计没有得到同等强度的消融. 后两类与任务 reward 形态耦合最强, 因而现有结果对其他任务的迁移能力仍缺少直接实验支持.

### 1.2 统一协议与两条基线事实

所有实验在 ROLL 框架上运行. 训练目标是 vanilla PPO loss, 优势用 REINFORCE 估计, 全程无 critic. 全局采样 batch 为 1024: 每轮 128 个 prompt, 每个 prompt 采 8 条回复; 最大回复长度 8192 token; 学习率 $10^{-6}$; 采样 top_p = 0.99, top_k = 100, 温度 0.99. 策略模型取 Qwen3-4B 与 Qwen3-8B 各两个变体: base 与 aligned, 共四个. 训练数据只用开源集, 按难度分三档: easy 档从 SimpleRL-Zoo-Data-Easy 随机抽 5000 题 (GSM8K 与 MATH-500 level 1 难度), medium 档取 DeepMath-103K 中难度标注最容易的 5000 题, hard 档按难度标注加权采样 5000 题.

数据侧还有一处容易被忽略的清洗: 两类数据集里都剔除了真值仅为 True/False 的样本, 因为模型可能从错误的推理链凑出正确的二值答案, 构成噪声监督 (案例见论文附录 B.2). 这个决定和结论无关却直接影响可比性——别的复现若不排除这类样本, 同一技巧的评分会被噪声监督拉偏. 评测在六个数学 benchmark 上取平均: MATH-500, OlympiadBench, MinervaMath, AIME24, AIME25, AMC23, 覆盖从基础算术到竞赛数学的难度谱. 平均分的口径与 DAPO (1.3.2.1 节 §7) 的报告方式一致, 跨论文引用时可以直接对齐.

基线实验给出两项事实. 第一, aligned 模型起点准确率更高, 初始回复也更长, RL 只能再带来约 2% 的准确率提升; base 模型起点低, 提升空间大得多. 第二, 训练准确率曲线对数据难度敏感: 难题上模型倾向生成更多 token, 长度与难度同时变化. **Trick 的效果必须同时标明模型类型与数据难度.**

Aligned 模型只有约 2% 的提升空间, 因而 1 到 2 个点的组件差异需要多个 seed 与置信区间才能和噪声区分. Base 模型的提升空间更大, 组件排序相对清晰, 但训练动态也更不稳定. 结果必须同时报告终局分, 收敛速度, 振荡幅度和中途崩溃情况.

读曲线还有两个口径细节. 论文的训练曲线统一用 11 步滑动窗口加指数平滑 (系数 0.8) 处理, 阴影带是平滑后均值加减若干倍标准差, 用来展示振荡幅度. 平滑让曲线可读, 但也把短期崩溃藏了进去: 一条「平滑后缓慢上升」的曲线, 原始曲线可能在中段剧烈震荡. 对比两条 trick 的收敛速度时, 要看未平滑的步进值, 或至少把平滑参数对齐, 否则平滑口径本身就能制造「谁收敛快」的假差异. aligned 模型上 2% 量级的差异尤其脆弱, 这类比较更应回到原始数据.

## 2. 归一化: 均值与标准差可以分开选

### 2.1 组级与批级的失效条件

记一个 prompt 采 $K$ 条回复, 奖励 $\{r_k\}_{k=1}^K$. 组级归一化:

$$A_k^{group}=\frac{r_k-\mathrm{mean}(\{r_j\}_{j=1}^{K})}{\mathrm{std}(\{r_j\}_{j=1}^{K})}.$$

批级归一化把统计量换到整个 rollout batch ($N$ 个 prompt, 共 $N\times K$ 条回复):

$$A_i^{batch}=\frac{r_i-\mathrm{mean}(\{r_j\}_{j=1}^{N\times K})}{\mathrm{std}(\{r_j\}_{j=1}^{N\times K})}.$$

默认二值 reward ($r\in\{0,1\}$, 答对 1 答错 0) 下, 组级归一化在两个模型尺寸上都比批级和无归一化收敛更稳, 终局性能更高; 批级归一化对 batch 内奖励分布的倾斜高度敏感, 不平衡时少数离群样本主导优势估计, 训练可能中途崩掉. 把 reward 编码改成 $r\in\{-1,1\}$ (答错 -1) 后, 批级归一化恢复有效性.

同一个技巧只改 reward 尺度就会得到相反结果, 因而技巧收益必须绑定具体场景. 无归一化对照组直接把原始 reward 当作优势, 梯度幅度由 reward 编码决定, 换任务后通常需要重调学习率. 该设置在实验中只承担消融参照, 不属于推荐配方.

### 2.2 手算: 倾斜 batch 下的优势放大

假设用总体标准差 (除以 $n$, 不除以 $n-1$), $K=8$, $N=128$. 情形 A: 全 batch 通过率 $p=0.5$, 批均值 0.5, 批标准差 $\sqrt{0.5\times0.5}=0.5$. 答对样本的批级优势 $(1-0.5)/0.5=1$, 答错样本 $(0-0.5)/0.5=-1$, 正负对称. 情形 B: 训练后期整体通过率升到 $p=0.9$, 批均值 0.9, 批标准差 $\sqrt{0.9\times0.1}\approx0.3$. 答对样本优势 $(1-0.9)/0.3\approx0.333$, 答错样本 $(0-0.9)/0.3=-3$. 负方向更新强度变成正方向的 9 倍, 而答错样本在 batch 里只占 10%: 梯度被极少数样本主导, 单步更新方向由离群样本说了算.

这就是「倾斜 batch 下批级归一化崩溃」的数值形态, 和二值 reward 的尺度直接相关: $r\in\{0,1\}$ 时批标准差的上界只有 0.5, 通过率一高, 分母先塌, 少数负样本的优势被放大到支配地位. 换成 $r\in\{-1,1\}$, 批标准差上界变为 1, 同样的通过率下分母大一倍, 离群放大被压住——批级归一化在 reward 尺度改变后「恢复有效」的原因就在这里.

组级归一化对全局难度不敏感. 取某个 prompt 的组内 8 条回复 3 对 5 错: 组均值 0.375, 组标准差 $\sqrt{0.375\times0.625}\approx0.484$, 答对样本的组级优势 $(1-0.375)/0.484\approx1.291$, 答错样本 $(0-0.375)/0.484\approx-0.775$. 优势尺度只反映这组内部的相对表现, 不随全局通过率漂移. 代价同样清楚: 组内全对或全错时标准差为零, 优势没有定义; 且 8 个样本估两个统计量, 噪声大. RLOO(1.3.1.2 节) 的 leave-one-out 基线缓解的是组均值基线自身的耦合问题, 但标准差尺度带来的放大, leave-one-out 同样没有碰.

### 2.3 标准差项与混合归一化

批级归一化的不稳定是否由标准差项引起? 消融把标准差从批级归一化中删掉, 只减均值, $A_k^{\neg std}=r_k-\mathrm{mean}(\{r_j\})$. 结果分两种数据形态: easy 数据上训练迅速收敛到行为高度一致, 奖励分布集中, 标准差曲线快速跌到低值, 此时除以标准差得到极小的分母, 异常放大优势, 引发梯度爆炸; 删掉标准差后训练恢复稳定. hard 数据上奖励方差天然较大, 标准差维持高位, 删不删差别不大.

std 缩放的力度可以手算: 组内 8 条 7 对 1 错, 组均值 0.875, 总体标准差 $\sqrt{(7\times0.125^2+0.875^2)/8}=\sqrt{0.875/8}\approx0.331$. 那条错答的优势带标准差是 $(0-0.875)/0.331\approx-2.646$, 只减均值是 $-0.875$, 放大 3.02 倍; 若该组 8 条全对, 标准差直接为零, 除零. 也就是说, 标准差项把「组内个别样本的差异」按组内一致性的倒数加权: 一致性越高, 越小的差异获得越大的更新. easy 数据上模型快速全员答对, 一致性顶到天花板, 这正是灾难的来源.

最终方案把两个统计量拆开选: 均值取组级, 标准差取批级, $A_k=(r_k-\mu_{group})/(\sigma_{batch}+\epsilon)$. 组均值保留 prompt 内的相对比较, 批标准差提供跨 prompt 稳定的全局尺度, 两个模型尺寸上这套混合归一化都最稳. 论文给出的机制解释: 批级标准差压住了梯度幅度, 防止过大更新, 与稀疏 reward 下粗粒度优势估计的偏置更匹配; REINFORCE++ 报告的批级归一化收益, 在这个混合形态下也部分复现.

这个结果回应了 1.3.1.1 节 §3 的「删 std」争论. Dr. GRPO 指出的难度偏差来自组内 std 对微小奖励差异的放大; 批级标准差把放大因子改由整个 batch 的奖励离散度决定. **组内竞争由组均值确定, 全局尺度由批标准差确定, 两个统计量可以独立选择.** 实现时 $\epsilon$ 只负责防除零, 不应大到改变尺度; 训练若对 $\epsilon$ 敏感, 说明分母已经接近 $\epsilon$, 应检查 reward 分布.

### 2.4 归一化的监控口径

无论选哪种归一化, 有三条曲线要进默认监控. 一是批标准差与组标准差的分布曲线: std 快速下塌是「马上要有麻烦」的先行指标, 比损失曲线更早. 二是按难度分桶的梯度范数: 「std 归一化在 easy 上炸」的机制判断, 最终要落到「easy 桶的梯度范数是否系统性高于 hard 桶」这个可测的量上. 三是全同组占比: 组内全对或全错的比例上升, 组级归一化的有效样本随之减少, 优势估计的噪声放大.

这三条曲线还有一个共同用途: 判断自己的任务像论文的哪一档. 批标准差长期高于 0.3, 全同组占比低, 说明任务落在 hard 档的形态, 归一化风格的选择空间很大; 批标准差压到 0.1 以下, 全同组占比过半, 则落在 easy 档的形态, 标准差项是头号风险源. 用曲线给任务画像, 再决定抄哪个配方, 比按模型规模对号入座可靠.

监控之外还有诊断顺序. std 下塌时, 先查数据难度构成, 再查归一化实现: 难度构成漂移 (easy 样本占比上升) 是数据侧原因, 换一批数据就恢复; 实现侧原因 (std 算错轴, 把批级写成了组级) 则任何数据下都在. 用一个全对 batch 和一个半对 batch 分别喂进去, 比较输出优势的分布, 两种原因立刻分开, 这比逐行核对实现快.

## 3. 裁剪: Clip-Higher 的收益绑定模型类型

### 3.1 base 模型为什么无感

Clip-Higher 把 ratio 上界从 $1+\epsilon$ 抬高到 $1+\epsilon_{high}$, 下界不动 (DAPO, 1.3.2.1 节 §2). 这篇论文复现后给出使用边界: base 模型上抬高上界收益微小, 甚至低于标准裁剪; aligned 模型上抬高上界明显减缓熵坍缩, 中等难度与复杂推理任务上的评测准确率随之上行. 两侧的机制证据都落在 clip fraction (被裁剪样本占比) 上: base 模型只有约 0.003, 相邻两轮策略的 ratio 极少越过 0.2 边界, 抬高上界改的是一个几乎不被触发的约束; aligned 模型初始 token 分布更平坦, 高概率 token 少, ratio 更容易在训练初期冲出边界, 上界抬高直接扩大了可更新区域.

换个角度, Clip-Higher 松绑的对象是「被压制的强化」. base 策略表达力有限, 采不出高奖励轨迹, 松绑没有对象; aligned 策略已有能力, 对称裁剪反复在 $1+\epsilon$ 处截停正优势, 正确的推理模式推不到位, 才需要松绑. 这个结论与 DAPO 的原始场景 (32B 强模型) 自洽, 也把适用范围标清: 在小尺寸 base 模型上做消融时, Clip-Higher 不该作为默认收益项计入配方, 否则消融表里的正收益可能是别的改动借来的. **Clip-Higher 的收益前提是策略已经训出了可松绑的探索, 这个前提在 base 模型上不成立.**

论文用 clip fraction 近似衡量 off-policy 程度, 而 rollout 复用次数直接影响这个指标. 复用越多, ratio 通常偏离 1 越远, clip 触发越多, Clip-Higher 的潜在收益也越大. rollout 与更新严格交替且每批只用一次时, 论文没有提供独立消融, 因而需要重新测量 clip fraction 后再判断是否采用 Clip-Higher.

### 3.2 上界取值与连接词证据

上界并非越高越好. 4B aligned 模型的性能随 clip 上界增加, 在 0.32 达到最高; 8B aligned 模型的最优上界是 0.28, 继续增加没有收益. 论文称其为裁剪上界的 scaling law, 但实验只覆盖两个规模, 也没有给出跨尺寸拟合公式. 0.28 与 0.32 不能直接外推到 32B 以上模型.

语言学层面的 token 分析解释了严格裁剪为什么伤推理. 上界取 0.2 时, 被裁剪压制最多的是 discourse connectives (因此, 如果, 但是一类连接词): 这些词常出现在句首, 标记推理的转折与分叉, 新旧策略在它们身上的概率比最容易越过阈值, PPO 的 min 结构对它们施加最强压制. 推理链的分叉点恰好被压在更新范围之外, 生成多样推理结构的能力随之受限. 上界放宽后, 裁剪的落点转移到高频功能词上, 连接词的更新空间被释放, 结构稳定性与推理多样性同时保住.

这与 1.3.2.2 节 GSPO 的观察指向同一病灶: 粒度过细的逐 token 约束在长链推理上会截停关键位置的更新, 两家分别从 clip 边界与重要性比粒度两侧动手. GMPO(1.3.2.3 节) 留在 token 级, 改的是聚合统计量对离群比率的敏感度. 三条路线并存说明「裁剪该卡在哪」仍是开放问题, 共同点是都承认: 把每个 token 一视同仁地限制在小位移内, 和让推理链保持分叉能力, 这两个目标在训练深入后是冲突的.

下界 $1-\epsilon_{low}$ 在实验中保持不变, 扫描只改变上界. 因此 clip fraction 应按正优势与负优势分开统计. 负侧触发远多于正侧时, 错误动作的下压先达到裁剪边界, 正确动作仍有上调余量, 这正是 Clip-Higher 针对的失衡. 两侧接近则说明 off-policy 程度较低, 抬高上界的收益空间有限. 这项分流指标属于实现侧诊断, 原实验没有报告对应曲线.

### 3.3 熵监控的口径

论文为「熵坍缩」规定了可操作的测量口径: 熵曲线按固定温度在探针集上测量. 训练采样温度会随课程和阶段变化, 直接记录采样分布的熵会混入温度调度信号. 复现时沿用固定探针与固定温度, 两条曲线才可比较.

组内唯一回答数是另一个比 token 级熵更稳健的代理指标: 组内 $G$ 条回复去重后的数量下降, 直接说明探索在收缩, 且不受温度口径影响. 两个指标配合使用: 熵曲线看趋势, 唯一回答数看阈值. 唯一回答数掉到 1 附近时, 组内优势恒为零, 训练实质已经停摆, 这时再调 clip 上界属于事后补救, 应提前在该指标上设告警.

## 4. 过滤与损失聚合

### 4.1 overlong filtering 的有效区间

Overlong filtering 掩掉超过预设生成长度的回复奖励, 避免将因截断而未完成的推理链直接当作错误样本. 短中程任务上, 过滤提高准确率并减少重复输出; 长尾任务上的收益较小, 因为超长样本中也包含有效的正确解. Repeat ratio 同时下降, 但实验没有单独分离重复抑制对准确率的贡献.

和 DAPO 的 overlong reward shaping 区分开 (1.3.2.1 节 §5): shaping 是改 reward 数值 (三段线性惩罚), 超长链仍参与梯度, 拿的是「正确答案减去长度代价」; filtering 是 mask, 超长链直接退出梯度, 也不提供「长度有边际成本」的信号. 两者处理同一个痛点, 作用方式相反, 长尾任务上的取舍也相反. 选型依据是任务的长度分布: 回复长度集中在阈值以下的任务, 用 filtering 干净利落地去掉截断噪声; 长链本身就是交付物的任务, 应该用 shaping 或干脆放宽阈值.

论文还扫了最大生成长度本身的影响: 上限收紧会同时改变准确率与回复长度, 收紧过头把「能解的题」变成「截断的题」. 这个扫描提醒我们, filtering 的有效区间不是固定的, 它随生成上限, 任务难度和训练阶段移动. 实操上先画训练集回复长度的分位数曲线, 让过滤阈值落在 P95 到 P99 之间, 再按评测表现微调, 比在论文默认值上硬套稳.

### 4.2 token-level 还是 sequence-level

sequence-level 聚合先把每条回复的损失按自身长度平均, 再对回复等权平均 (GRPO 方式); token-level 用整个 batch 的有效 token 总数做分母 (DAPO 方式). 结论再次分模型: base 模型上 token-level 收敛更快更稳, hard 数据上差距最明显; aligned 模型上 sequence-level 更优, token-level 提升有限. 论文归因: aligned 模型的输出结构已被后训练塑形, 按回复等权有助于维持结构一致性; base 模型长度方差大, 每条等权让长回复的每个 token 被系统性稀释, 恰好是 Dr. GRPO 分析的长度偏差方向 (1.3.1.1 节 §3).

权重差别可以手算. 一个 batch 两条回复, 200 token 与 2000 token, 共 2200 个有效 token. 序列级下两条回复各分一半梯度预算, 长回复的每个 token 权重是 $0.5/2000=2.5\times10^{-4}$, 短回复是 $2.5\times10^{-3}$, 相差 10 倍. token 级下每个 token 等权, 一律是 $1/2200\approx4.5\times10^{-4}$, 长回复的单 token 权重被放大 1.8 倍, 短回复被压到 1/5.5. 两种分母没有谁绝对正确, 改的是长回复在批梯度中的占比, 而这个占比的合理性取决于任务与模型, 论文的「base 用 token 级, aligned 用 sequence 级」就是这个依赖的经验形态.

还要注意两个语义都没变: 同一回复内所有 token 仍共享序列级优势, reward 仍是整条回答一个标量, 没有发生 token 级信用分配; 变的是回复之间的相对权重. 记成一句话: **GRPO 按「条」投票, token-level 按「token 数」投票** (1.3.2.1 节 §4.1 的同一句结论, 这里从消融侧独立复现). 实现上归约分母要和 clip 边界, 学习率当成一个整体调: 换分母改变梯度的有效尺度, 等效于动学习率, 只换分母不动其余, 常见结果是曲线有变化但说不清变好变坏.

### 4.3 过滤与归一化的联动

动态采样与过滤直接改写 batch 的奖励分布, 奖励分布又决定归一化分母. 过滤全对组后, batch 内剩余样本的通过率整体下移, 批均值下降, 批标准差先升后降;这些变化直接进入批级归一化尺度. 因而过滤开关不同, 归一化面对的数据形态也不同, 消融数值无法直接横比.

一个可算的极端情形: batch 内 prompt 通过率两极分化, 一半 prompt 通过率 0.9, 一半 0.1, 每组 $G=8$. 不过滤时批均值 0.5, 两极分布把批标准差拉满. 过滤后, 0.9 那侧约 $0.9^8\approx0.43$ 比例的组全对被移除, 0.1 那侧约同样比例的全错组被移除, 留下的 batch 集中于中间难度, 批标准差显著收窄, 归一化的放大因子随之整体上调: 同样的原始奖励差异, 在过滤后的 batch 里获得更大的优势幅度. 过滤与归一化不是两个独立开关, 通过 batch 构成耦合在一起. 做联合消融时, 两个开关要同时列入变量列表, 先跑单开关再跑组合, 顺序不能省, 否则组合组里的收益分不清是谁的贡献.

实操建议沿用 1.3.2.1 节 §3.4 的口径: 有效组占比, 过滤比例, 补采成本分开报; 归一化消融要注明是否带过滤, 否则「批级归一化稳不稳」的结论无法跨实现比较.

与动态采样联动时, 聚合粒度的选择还多一层考虑: 过滤与补采改变了 batch 的长度构成, token 级分母把这部分变化直接写进梯度尺度, sequence 级分母则只按「条」均摊, 对长度构成的变化不敏感. DAPO(1.3.2.1 节 §3) 把过滤, 补采与 token 级 loss 打包使用, 二者在同一个 batch 构成剧烈波动的系统里互相放大; 只抄其中一半的团队, 应预期到另一半的缺席会改变效果排序.

## 5. Lite PPO 与复现清单

### 5.1 两技巧组合的准确定位

Lite PPO 把消融中两个在其设置下最稳的选择组合起来: 组级均值加批级标准差的混合归一化, token-level 损失聚合, 配合 vanilla PPO loss 与 REINFORCE 优势, 无 critic, 无 KL 项, 无动态采样. 在 base 模型设置下, 这个两技巧组合在六个数学 benchmark 的平均分上稳定超过 GRPO 与 DAPO 两个多技巧 recipe. 作者将其解读为: 复合 recipe 里多出的组件在 base 模型语境里引入了干扰, 而非技巧堆叠存在普遍溢价.

这两个组件在 base 模型上处理不同阶段的问题. 训练初期几乎所有回答都错误, 组内差异微弱, 批标准差提供跨组尺度, 避免组内 std 接近零时放大梯度. 随着训练推进, 长度方差增大, token 级分母避免长回复中的正梯度被过度稀释. Aligned 模型的奖励分布较稳定, 输出结构也更固定, 两项收益都会减弱. 因此 Lite PPO 的结果与 base 模型条件绑定.

GRPO 在损失里保留对参考策略的 KL 正则, DAPO (1.3.2.1 节 §6) 与 Lite PPO 去掉 KL, 主要依靠 clip 限制策略偏移; REINFORCE++ 则保留 KL. Lite PPO 没有对去 KL 做独立消融, 这一设置继承自 PPO 基线, 无法从现有实验中单独归因收益.

Aligned 模型上 token-level 聚合本身提升有限, 现有结果不足以把 Lite PPO 当作 aligned 模型的默认方案. Lite PPO 是消融得到的组件组合, 没有额外的显存, 学习率或吞吐保证. 「两个组件胜过复合 recipe」只在论文设置下成立; 当 aligned 模型频繁触发上侧裁剪, 或训练数据存在大量全同组时, Clip-Higher 与动态采样仍可能直接处理这些异常.

与 GRPO, DAPO 对比时还有一个口径细节: 论文报告的是六个 benchmark 的平均分, 每个设置只覆盖 Qwen3 两个尺寸. 单 benchmark 上的胜负分布, 平均分内部的方差, 以及 Qwen3 之外的模型族, 论文都没有报告. 因此「稳定超过」只表示平均分稳定领先, 不能推出每个 benchmark、每个种子都占优.

### 5.2 教学实现

```python
import torch

def lite_ppo_advantage(rewards, eps=1e-8):
    """对应式: A = (r - mean_group(r)) / (std_batch(r) + eps)
    rewards: [N, G], N 个 prompt, 每组 G 条回复"""
    group_mean = rewards.mean(dim=-1, keepdim=True)   # [N, 1], 组级均值
    batch_std = rewards.std()                         # 标量, 批级标准差
    return (rewards - group_mean) / (batch_std + eps) # [N, G]

def lite_ppo_loss(ratio, advantage, mask, eps=0.2):
    """对应 PPO 式: L = -sum(min(ratio*A, clip(ratio)*A)) / mask.sum()
    ratio, advantage, mask: [N*G, T], advantage 已广播到 token"""
    clipped = ratio.clamp(1 - eps, 1 + eps)
    token_obj = torch.min(ratio * advantage, clipped * advantage)
    return -(token_obj * mask).sum() / mask.sum()     # token-level 分母
```

这段代码说明两件事. 第一, 混合归一化的均值与标准差来自两个统计轴, 实现里两者必须分别可开关, 否则后续消融无法逐项拆掉. 第二, 分母是 `mask.sum()` 而不是回复条数或每条回复的长度, 这是 token-level 与 sequence-level 的全部实现差别, 与 1.3.2.1 节 §4 的 DAPO 分母同款. old log-prob 必须作为采样策略的常数保存, ratio 的分母不能进计算图, 这是 1.3.1.1 节 §2 强调过的同一纪律.

### 5.3 不依赖训练的验证清单

四条不变量, 全部在合成张量上可测. 其一, 全同组: 构造组内奖励全等的 batch (全 1, 全 0, 全任意常数), 组级 std 归一化在此处除零, 混合归一化下优势应精确为零, 不得出现 NaN 或 Inf. 其二, 组大小退化: $G=1$ 时组均值等于样本自身, 优势恒为零, 梯度为零; 实现若允许 $G=1$, 应显式给出这个退化行为的告警, 而不是静默产出零梯度假装在训练. 其三, 聚合等价: batch 内所有回复等长时, token-level 与 sequence-level 损失只差常数因子 $B|y|/\sum_i|y_i|=1$, 逐点对比可拦住分母写错. 其四, 裁剪退化: $\epsilon_{high}=\epsilon_{low}=\epsilon$ 时, Lite PPO 的 clip 应逐点退化为标准 PPO 的 $\mathrm{clip}(r,1-\epsilon,1+\epsilon)$.

上线前再补一个集成级检查: 固定种子跑 50 步, 记录 clip fraction. 按论文报告, base 模型的 clip fraction 量级约 0.003; 若自己的 base 模型实现报出 0.1 以上, 大概率是 old log-prob 没作为常数保存 (ratio 分母被反向传播污染), 或 clip 分支写反. 这类 bug 不报错, 损失照常下降, 只在指标曲线上留痕迹, 所以要把 clip fraction, 组内标准差分布, 有效 token 数三条曲线纳入默认监控, 而不是等训练崩了再回查. 这套清单与 1.3.2.1 节 §8.2 的 DAPO 验收套件是同一思路: 先在不依赖模型的不变量上拦住实现错误, 再用集成检查兜住时序与分布式带来的第二类错误.

消融开关也需要回归测试. 切换归一化或聚合粒度时, 用同一个合成 batch 跑遍所有配置, 保存损失与优势. 性能优化、分布式改造或精度调整完成后重跑, 数值对不上就表示语义已经改变. 这能将技巧耦合与实现偏差分开排查.

分布式训练还要验证统计量的归属范围. 组均值若只在单卡计算, 同一 prompt 的回答一旦跨卡分片, 优势就会随切分方式改变; 批标准差若在各卡独立计算, 每张卡又会使用不同尺度更新同一组参数. 合成测试应把同一批 rewards 用两种设备切分方式各算一次, all-reduce 后的优势、有效 token 数和梯度范数必须一致. 这项检查能区分算法差异与并行实现差异, 也能防止扩卡后训练曲线突然改变.

混合精度会进一步影响标准差与 ratio 的尾部. Reward 和 advantage 可以用 FP32 统计后再转换到训练精度; 若直接用 BF16 计算接近零的组内方差, 小差异可能被舍入成零, 触发与真实全同组相同的分支. Ratio 也应先在 log 空间求差, 再按裁剪需要取指数, 避免极低概率 token 下溢. 合成 batch 可加入一组只相差 $10^{-3}$ 的奖励和一组绝对 log-prob 很大但差值很小的样本, 检查 FP32 参考结果与混合精度路径的误差.

容差应按统计量分别设置, 不能用一个阈值覆盖优势、loss 和梯度. 这样精度误差与公式错误才不会混在同一条失败日志里.

## 6. 奖励稀疏: 零梯度之外还有选择偏差

二元终局奖励只回答最终答案是否通过验证. 对同一道题采 $G$ 条回答, 单条成功率为 $p$, 全错概率是 $(1-p)^G$, 全对概率是 $p^G$, 能产生组相对优势的概率为

$$
P_{\mathrm{active}}=1-p^G-(1-p)^G.
$$

这条曲线在 $p=0.5$ 附近最高, 在两端降到零. 因而 GRPO 即使均匀抽题, 真正进入梯度的题也集中在当前策略的中等难度区间. 这是估计器自带的「隐式课程」. 容易题和极难题仍消耗生成预算, 只是优势归零.

$G=8$ 时, $p=0.01$ 的有效组概率约 $7.7\%$, $p=0.1$ 时约 $57.0\%$, $p=0.5$ 时约 $99.2\%$, $p=0.9$ 又回到约 $57.0\%$. 如果题库一半题的 $p$ 接近零, 固定 prompt batch 256 远不等于 256 个有效训练样本. 训练日志应记录全错、混合与全对三类组, 不能用平均 reward 替代.

动态采样会丢弃全同组并补入新题, 提高每步有效组数; GHPO 给全错题加入真值前缀, 试图把它搬入混合区; JustRL 接受零梯度成本, 用固定流程换简单稳定. 三种路线都围绕同一条概率曲线, 取舍落在算力、数据分布与提示轨迹是否存在.

### 6.1 全错组不等于题目客观困难

全错是有限采样事件. $p=0.2,G=8$ 时仍有 $0.8^8\approx16.8\%$ 的概率整组失败. 温度、top-p、随机种子和组内相关性都会改变判定. 把一次全错永久写成难题标签, 会让抽样波动变成数据课程.

更严重的是格式与截断. 模型推理正确却没输出 `\boxed{}`, 验证器给零;回答在最终答案前达到长度上限, 也给零. 这两类全错组需要修格式和上下文预算, 难度过滤只能隐藏症状. 全错日志至少按数学错误、格式失败、截断、验证异常与执行超时拆分.

### 6.2 稀疏奖励下的方差

设一个 batch 中有效组数为随机变量 $M$. 梯度近似是 $M$ 个组贡献的平均, 条件于 $M$ 的方差大致随 $1/M$ 下降. $M$ 在相邻 step 从 20 跳到 80, 即使 prompt batch 固定, 梯度噪声也会明显变化. 动态采样能稳定 $M$, 同时改变题目分布;批标准差归一化负责优势尺度, 对零组依然给不出方向.

可复算诊断是记录每步 $M$、有效 token 数和梯度范数, 再按 $M$ 分桶比较范数方差. 若小 $M$ 桶尖峰显著, 稀疏性正在转化为优化噪声. 增大 batch、补采、调低题目难度或提供引导都可能降低噪声, 应按成本分别消融.

## 7. 组采样相关性: 八条回答未必有八份信息

组内优势常按回答条件独立来理解, 实际八条 rollout 共享模型、prompt、解码设置和大量高概率前缀. 若模型总在同一步走错, 多采几条只会得到措辞不同的同一错误. 用同组奖励相关系数 $\rho$ 近似, 有效样本量为

$$
G_{\mathrm{eff}}\approx\frac{G}{1+(G-1)\rho}.
$$

$G=8,\rho=0.3$ 时, $G_{\mathrm{eff}}\approx2.58$; $\rho=0.7$ 时只剩约 1.36. 组大小翻倍并不会按比例降低估计方差. BroRL 式大组采样能否发挥作用, 取决于新增回答是否探索了新路径.

### 7.1 完全相关的反例

设模型对某题有两种隐状态: 一半概率选中正确解法, 此时八条全对;一半概率选中错误模板, 此时八条全错. 单条边际正确率仍为 0.5. 独立假设给出的全同组概率是 $2\times0.5^8\approx0.78\%$, 真实构造却是 $100\%$. 平均正确率完全相同, 组相对训练一个几乎总有信号, 另一个永远零优势.

这个反例说明单条 pass rate 无法预测 GRPO 的有效性. 至少还要看「每组成功条数分布」. 若 $k\in\{0,G\}$ 的质量远高于二项分布预期, 组内相关性很强. 可以用 beta-binomial 拟合过度离散, 或直接比较实测 $\operatorname{Var}(k)$ 与 $Gp(1-p)$.

### 7.2 温度与多样性

提高温度常能增加路径多样性, 也会降低高概率正确链的稳定性. 对容易题, 高温可能把全对组拉回混合区, 恢复梯度;对困难题, 高温可能探索到稀有正确链, 也可能制造更多无意义输出. 最佳温度依赖 $p$ 与错误模式, 一条全局日程很难同时照顾两端.

诊断时同时记录答案正确性与路径差异. 路径差异可用首个分叉 token、答案去重率、推理步骤嵌入距离或 n-gram 重合度. 若温度升高只增加表面措辞, 奖励相关性仍高, 探索收益有限. 若成功条数分布明显从两端移向中间, 组优势才真正变丰富.

### 7.3 跨卡分组错误

同一 prompt 的回答跨设备分片时, 组统计必须全局聚合. 每张卡只看局部两条回答, 可能一张卡全对、另一张卡全错, 局部优势都为零;全局四条本应形成正负对比. 扩卡后学习突然变慢, 常见原因之一就是 group all-gather 缺失或 group id 错位.

合成测试可以构造全局奖励 $[1,1,0,0]$, 用不同分片方式计算优势. 单卡、两卡与四卡结果必须一致. 这项测试比训练曲线更直接, 也能检查批标准差是否在正确通信域内统计.

## 8. 长度偏置来自三个位置

长度问题常被缩成「回答太长」, 其实至少有奖励、归约和截断三条路径. 奖励侧的 overlong penalty 直接降低长回答分数;归约侧决定一条长回答在 loss 中占多少权重;截断侧把没来得及输出答案的轨迹判为失败. 三条路径可以方向相反, 也会互相遮蔽.

### 8.1 response-level 与 token-level

设第 $i$ 条回答长度为 $T_i$, token 代理项为 $\ell_{i,t}$. response-level 归约写成

$$
L_{\mathrm{seq}}=\frac1B\sum_{i=1}^{B}\frac1{T_i}\sum_{t=1}^{T_i}\ell_{i,t},
$$

每条回答总权重相同. token-level 归约写成

$$
L_{\mathrm{tok}}=
\frac{\sum_i\sum_t\ell_{i,t}}{\sum_iT_i},
$$

每个 token 权重相同, 长回答拥有更多总权重. 所有回答等长时两者一致;长度与奖励相关时, 差异会系统化.

手算两条回答. 正确链长 1000, 优势 $+1$;错误链长 100, 优势 $-1$, 假设每个 token 的 ratio 都为 1. response-level 下两条总贡献抵消. token-level 下正侧累计权重是负侧十倍. 若长链通常更正确, token-level 强化长推理;若长链多为循环错误, 它会放大坏轨迹. DAPO 采用 token-level 有其训练动态背景, Lite PPO 也保留这一选择, 迁移时应先看长度—正确率关系.

### 8.2 overlong shaping 的偏差

长度惩罚把成本写进奖励, 改变优化目标. 若目标本来只关心正确率, 惩罚会引入偏差: 一条 15K token 的正确证明可能输给一条 2K token 的错误近似, 具体取决于惩罚强度. 它的价值是控制硬截断和吞吐, 代价是压制需要长链的难题.

取二元正确奖励 1, 长度惩罚在 12K 后线性降到 -1. 一条 15K 的正确回答可能得到负总分, 组内优势转为负, 策略会远离正确链. 设置惩罚区间前, 应先确认超长回答中的正确链占比、重复率与截断率.

### 8.3 截断造成的伪负样本

最大输出长度是硬边界. 模型在边界处仍沿正确方向推导, 验证器看不到最终答案, 奖励为零. 若训练中长回答越来越多, 全错率上升可能来自预算而非能力退化. 日志必须保存终止原因与截断前文本.

可复算实验把同一批截断回答延长生成, 不更新模型. 延长后若大量转为正确, 应先调整上下文或停止策略;延长后仍然错误且重复, 长度控制才有更强依据. 这种离线续写比直接训练一轮长度惩罚更容易归因.

### 8.4 prompt 长度也会改变预算

长 prompt 占用上下文窗口, 留给回答的空间减少. 不同题型输入长度差异大时, 固定 response 上限可能仍受总 context cap 截断. 按 response 长度统计不足以发现, 需要记录 prompt+response 总长度与剩余预算. GHPO 这类加入真值前缀的方法尤其要区分输入增长与输出缩短.

## 9. 熵塌缩: 先确认测的是什么

策略熵可以指每个位置对全词表分布的熵, 也可以用采样 token 的负 log-prob 近似. 前者需要完整 logits, 后者更便宜但混入采样偏差. 还要说明只统计 completion、是否排除格式 token、按 token 还是按序列平均. 不统一口径, 论文间的熵数值无法直接比较.

熵下降有两种含义. 模型学会确定的正确算法时, 无关分支减少, 熵下降是能力收敛;模型过度集中到固定模板、失去替代路径时, 熵下降才是塌缩. 判断需要和 reward、验证分数、答案多样性、错误恢复能力一起看.

### 9.1 clip-higher 的作用边界

正优势回答的 ratio 更容易向上越过裁剪边界. 对称 clip 在 $1+\epsilon$ 处停止增强, clip-higher 把正侧上界放宽, 让稀有成功链继续获得梯度. DAPO 在其设置中发现收益, 「技巧与陷阱」论文则观察到收益依赖模型类型: base 模型 clip fraction 极低时, 放宽一个几乎从未触及的边界自然无效.

因而决定是否启用 clip-higher 的指标是正优势上界命中率及其优势分桶, 不是模型名称. 若命中率只有 0.003, 1.2 与 1.28 的目标几乎一样;若大量高优势 token 堆在 1.2 附近, 放宽才改变优化路径. 负侧下界应分开记录, 总 clip fraction 会掩盖方向.

### 9.2 熵奖励的反例

显式熵奖励鼓励分布变平, 可能恢复探索, 也可能让模型在已掌握的格式和算术 token 上制造无用随机性. 若塌缩只发生在推理分叉位置, 对全 token 加统一熵系数会把成本撒到大部分无关位置. 更精细的办法是先定位位置与题型, 再决定是否需要熵干预.

一个可证伪消融是保持 rollout 不变, 扫描熵系数, 按 token 类型报告熵变化. 如果验证分数提升只伴随标点与连接词熵上涨, 机制解释站不住;如果关键推理位置的路径多样性恢复、正确率同步增加, 才能说探索得到改善.

### 9.3 奖励锐化与塌缩

强验证器、长度惩罚和格式奖励会改变组内排序. 奖励更严格时, 正样本变少, 单个正样本标准化优势变大;错误的负样本也更多. 这可能加速概率集中. JustRL 的组合消融中, 加长度惩罚与更强验证器后熵和分数一起下降, 但组合实验无法把两者独立归因. 二乘二消融才可区分主效应与交互.

## 10. clip 与 off-policy 失配

PPO 代理目标依赖行为策略 $\pi_{\mathrm{old}}$ 的 log-prob. rollout 由哪个版本生成, 分母就必须来自哪个版本, 并在更新中 stop-gradient. 异步系统若让样本在队列停留太久, learner 已更新多个版本, ratio 分布会远离 1, 大量 token 被裁剪, 数据实际利用率下降.

设每次参数更新使某 token 概率乘 1.05, 样本延迟十次更新后才消费, ratio 约为 $1.05^{10}\approx1.63$, 已远超常见上界. clip 把目标限制在边界, 却不能恢复这条陈旧样本本应属于的 on-policy 分布. 延迟越大, 越多计算花在裁剪平台上.

### 10.1 分母版本错位

最严重的实现错误是 old log-prob 由当前 learner 重算, 或按不同 prompt/template 重算. ratio 可能被人为拉回 1, 让 off-policy 延迟从日志中消失;也可能因模板差异产生巨大尾部. 每条样本应保存行为策略版本、完整 prompt 哈希与生成时的 old log-prob.

集成检查在任何更新前重算少量样本, current log-prob 应与 old log-prob 在数值容差内一致, ratio 接近 1. 若第一 mini-batch 已大幅偏离, 版本、tokenizer、mask 或精度路径有错. 后续 mini-batch 随更新逐渐扩散才是正常现象.

### 10.2 token ratio 与 sequence ratio

GRPO、DAPO 常在 token 粒度计算 ratio 和裁剪;GSPO 将变化聚合到序列粒度, 缓解长回答中少数 token 极端比值造成的不稳定. 两者约束的对象不同. token clip 允许一条序列内部分 token 更新、部分停在平台;sequence clip 给整条轨迹共同权重.

长序列下, token ratio 的乘积会数值下溢, 序列方法通常在 log 空间聚合或取长度归一的平均. 公式与实现必须说明. 把未归一 log-ratio 求和后直接指数化, 序列越长越容易远离 1, 裁剪几乎总触发;长度归一后含义又变成每 token 的几何平均变化.

### 10.3 PPO epoch 与数据复用

同一 rollout 做多个 PPO epoch 能提高样本利用, 也会增加 off-policy 程度. 第一个 epoch ratio 接近 1, 后续逐渐扩散. 若 clip fraction 在第二个 epoch 已接近饱和,继续复用几乎没有有效梯度. 应按 epoch 与 mini-batch 序号分别统计 ratio, 而非只报整轮平均.

可复算诊断是计算「未裁剪有效 token 比例」与每个有效 token 的生成成本. 增加 epoch 后总 loss 计算翻倍, 有效比例若减半以上, 额外计算价值可疑. 这比观察 loss 是否继续下降更直接.

## 11. 验证器漏洞会经过优势扩散

规则验证器负责把文本映射成奖励. 常见漏洞包括固定抽取首个或末个数字、忽略单位、错误处理集合顺序、把未闭合 LaTeX 解析成合法答案、代码测试覆盖不足、超时与错误混为一类. 策略会主动搜索这些边界, 训练越久越容易找到稳定捷径.

一条假阳性不仅强化错误回答, 还会提高组均值, 压低其它回答的优势. 设真实奖励全零, 验证器误把一条判为 1, $G=8$ 时该回答优势约 $2.646$, 其余七条约 $-0.378$. 一个判定错误制造了完整的正负训练信号. 因而假阳性通常比假阴性更危险.

### 11.1 验证器互换实验

准备轻量规则、符号验证与人工审计三种判定. 对同一批 rollout 离线打分, 得到分歧矩阵. 若强验证器主要把规则假阴性改正, 正奖励率会上升且人工一致率提高;若它引入新的假阳性, 训练风险反而增加. 「更强」需要以独立标注衡量, 不能由模型规模定义.

训练时保留原始解析答案、规范化结果、错误类型和验证器版本. reward 只有一个标量, 出问题后无法追查捷径来自哪里. 对高优势、重复出现和新格式的答案优先抽检, 比均匀抽样更容易发现策略正在利用的漏洞.

### 11.2 过程奖励的偏差

过程奖励可以缓解终局稀疏, 同时引入更密集的模型偏差. 一个步骤被奖励模型判好, 未必能导向正确答案;局部看似错误的探索也可能最终自我修正. 把过程分逐 token 相加, 还会天然偏好长轨迹, 除非做长度归一或折扣.

终局规则奖励与过程模型奖励组合时, 需要分别报告两项与最终正确率的相关性. 若过程分上涨、终局准确率下降, 模型正在优化代理目标. 先在固定 rollout 上做离线重打分与排序一致性, 再进入昂贵训练.

### 11.3 代码验证器的特殊风险

单元测试不足会奖励过拟合程序;沙箱漏洞可能让模型读取测试、访问文件或利用异常退出;超时上限会偏向短程序. 代码 reward 应区分编译错误、运行错误、超时、部分测试通过与全部通过. 只给 0/1 会丢掉大量可诊断信息, 即使最终优势仍使用二值分数, 日志也应保留细分结果.

## 12. 数据课程与分布偏移

数据课程的目标是让训练题保持在可学习区间. 静态课程按预先难度排序, 动态采样按当前组奖励筛选, GHPO 用提示降低同一道题的条件难度. 三者分别依赖人工标签、在线采样与真值轨迹, 产生的分布偏差也不同.

动态过滤全同组会让训练分布集中到当前中等题. 过滤后混合组占比上升, 极难题和容易题进入更新的频率下降. 模型能力变化后, 过滤结果也随之变化, 数据分布会反过来影响策略. 补采若没有上限, 少数 batch 可能反复抽不到有效题, 造成吞吐尾延迟. 日志可并列记录补采轮数、过滤题型、生成 token 与最终有效组, 据此计算每个有效组的成本以及各题型在梯度中所占的比例.

### 12.1 课程的采样统计

对每道题维护采样次数、全错次数、混合次数、全对次数、累计生成 token 与最近成功率. 按题型汇总三种占比, 就能看到课程实际把预算投在哪里. 训练集原始占比、rollout token 占比与有效梯度占比应同时报告.

设题型 $c$ 原始占比为 $w_c$, 进入有效组的概率为 $e_c$, 则无重加权时梯度占比近似正比于 $w_ce_c$. 动态采样提高低 $e_c$ 类型的重试次数, 也可能因始终失败而最终降低其占比. 单看数据加载器比例无法知道真正课程.

### 12.2 难度估计会过期

离线难度来自某个参考模型, 换模型或训练后都会过期. 一道对 7B 困难的题可能对蒸馏 1.5B 反而熟悉, 因为蒸馏数据覆盖不同. 动态统计更贴近当前策略, 代价是采样噪声. 可以用历史窗口平滑, 同时设置遗忘因子让旧标签退场.

过长窗口把早期弱模型的失败带到后期, 题目继续被当作困难;过短窗口又会因偶然全错频繁跳桶. 选择窗口应通过标签翻转率和固定探针稳定性判断, 不应只凭经验写一个 epoch 数.

### 12.3 防止课程偷看测试集

若难度由目标 benchmark 表现决定, 或训练题与测试题近重复, 课程会间接针对评测优化. 课程设计只使用训练侧信号, benchmark 保留给最终评估. 数据去重要覆盖题面、公式结构、答案与参考解, 仅做字符串匹配抓不到换变量和翻译版本.

## 13. KL 与参考策略

KL 项把当前策略锚定在参考策略附近. 常见近似目标写成

$$
J=J_{\mathrm{PG}}-\beta\,\mathbb E[D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}})].
$$

$\beta$ 大时更新保守, 可抑制 reward hacking 与语言退化;过大也会阻止模型提高稀有正确链概率. 规则数学 reward 较坚硬、clip 已控制单步移动时, DAPO、JustRL 等工作选择弱化或移除 KL;开放式 reward 与易投机环境里, 参考锚仍可能重要.

### 13.1 old policy 与 reference policy

$\pi_{\mathrm{old}}$ 是采样时行为策略, 用于 importance ratio; $\pi_{\mathrm{ref}}$ 通常是冻结的初始或 SFT 策略, 用于 KL. 二者职责不同. old policy 随更新刷新, reference 可以长期固定. 把二者混用会让 KL 锚不断移动, 或让 ratio 分母永远停在初始模型.

实现日志应分别记录 policy version 与 reference revision. 即使目标不加 KL, 也可离线监控到 reference 的散度, 用来发现长期漂移. 监控量不必自动进入损失, 先观察再决定是否干预.

### 13.2 KL 的方向与估计

前向 KL $D_{\mathrm{KL}}(\pi_{\mathrm{ref}}\|\pi_\theta)$ 与反向 KL $D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}})$ 偏好不同. 前者惩罚当前策略漏掉参考覆盖的模式, 更偏保覆盖;后者强烈惩罚当前策略把质量放到参考低概率区域, 更偏模式寻优. 实际 LLM RL 常用采样 token 上的近似, 与全词表精确 KL 也不同.

论文或代码只写 `kl` 不够, 需要确认估计公式、采样分布、token mask 与归约. 长回答按 token 累积 KL 会天然惩罚长度;按序列平均则每条回答等权. KL 与长度偏置因此会耦合.

### 13.3 自适应 KL 的反馈环

自适应控制根据实测 KL 调整 $\beta$. 目标 KL 设为 $K^*$, 当前值高于目标就增大系数, 低于目标就减小. 这能保持漂移尺度, 也增加一条反馈控制器. 测量噪声大或延迟高时, 系数可能振荡, 训练曲线随之周期变化.

可复算诊断画出 $K_t,\beta_t$ 与参数更新范数, 检查系数变化是否滞后以及是否过冲. 固定 $\beta$、自适应 $\beta$ 与无 KL 三组按 token 对齐, 才能判断控制器是否解决了已有问题.

### 13.4 参考模型重置

部分配方在 KL 过大时把 reference 更新为当前策略, 相当于移动信任域中心. 它能立刻降低 KL, 也会永久接受此前漂移. 若策略已经利用奖励漏洞, 重置会把坏行为变成新基线. 重置规则必须绑定独立质量指标, 不能只看 KL 数值.

一个反例: reward 持续上涨、真实验证下降、KL 快速增大. 此时重置 reference 会让 KL 清零, 曲线看似恢复, 验证退化仍在. 正确动作是先审计 reward 与样本, 而非把散度报警器归零.

## 14. 训练不稳定的可复算诊断

「训练崩了」至少包含五种状态: 数值溢出、策略更新过大、奖励信号消失、探索集中、数据或验证器分布改变. 它们可能同时表现为 loss 尖峰或验证分数下降, 修复方式完全不同. 诊断要从能复算的量出发, 沿数据流逐层排除.

### 14.1 奖励层: 三类组与错误类型

每步记录全错率 $z_t$、混合率 $m_t$、全对率 $o_t$, 满足 $z_t+m_t+o_t=1$. 同时记录格式失败、截断、验证异常与真实错误. 若 $z_t$ 上升而截断率同步上升, 优先查长度;格式失败上升则查模板;两者稳定、真实错误上升, 才可能是能力退化或题目变难.

用固定探针集区分策略变化与 batch 难度. 每隔固定步数对同一批题、同一解码设置重采, 得到 $z_t^{probe},m_t^{probe},o_t^{probe}$. 训练批曲线异常、探针稳定, 说明数据抽样变化;两者同步异常, 策略或系统发生变化.

### 14.2 优势层: 均值、尺度与尾部

组内中心保证每组优势和接近零, 批标准差决定不同组共享尺度. 每步记录奖励 batch std、优势绝对值 P50/P95/P99、零优势 token 比例和裁剪优势比例. 批 std 很小时, 同样的奖励差会被放大;加入 $\epsilon$ 只能防除零, 无法保证尺度合理.

手算一个极端 batch. 100 个组中 99 组全零, 1 组奖励 $[1,0,\ldots,0]$. 组均值中心化后, 大部分样本为零, 唯一混合组产生正负差. 批标准差被大量零稀释, 混合组优势可能比组内 std 归一更大. 混合归一化提高了跨组稳定性的一面, 在有效组极少时也可能放大尾部. 优势 clipping 或最低有效组阈值需要用这类构造测试.

### 14.3 ratio 层: 分布而非平均

平均 ratio 接近 1 无法排除尾部失控. 一半 token ratio 0.1、另一半 1.9, 平均仍是 1, 大多数 token 已越过裁剪区. 应记录 log-ratio 的 P1/P50/P99、正负优势两侧 clip fraction、按 mini-batch 序号和样本延迟分桶的分布.

定义裁剪有效率

$$
E_{\mathrm{clip}}=
\frac{\#\{t:\text{token 在未裁剪区且 mask=1}\}}
{\#\{t:mask=1\}}.
$$

它衡量一次 loss 计算中多少 token 仍能通过原始 ratio 分支提供梯度. $E_{\mathrm{clip}}$ 随 PPO epoch 快速下降, 说明数据复用过度;第一 mini-batch 就低, 指向版本错配或学习率异常.

### 14.4 梯度层: 范数和方向

总梯度范数尖峰可能来自少数层. 分层记录 embedding、attention、MLP、输出头的范数, 再记录相邻 step 梯度余弦. 范数平稳但方向频繁翻转, 表明噪声大;范数尖峰且方向稳定, 可能是优势尺度突然放大;某一层单独异常, 更像数值或并行问题.

梯度裁剪会隐藏尖峰. 同时记录裁剪前后范数与触发比例. 若每步都触发, 实际更新由裁剪阈值主导, 学习率的名义值失去解释. 先找到上游的优势或 ratio 尾部, 再决定是否调整阈值.

### 14.5 参数更新层: 实际步长

AdamW 的实际参数变化受一阶、二阶矩影响, 只看梯度不足. 可记录相对更新范数

$$
U_t=\frac{\|\theta_{t+1}-\theta_t\|_2}{\|\theta_t\|_2}.
$$

不同层分别统计更有解释力. loss 正常而 $U_t$ 突增, 可能是优化器状态丢失、断点恢复错误或混合精度缩放异常. 恢复训练前后把同一 batch 跑一遍, 参数更新应在容差内一致.

### 14.6 熵层: 位置与题型

总体熵按格式 token、推理主体、数字/符号、答案区域拆开. 格式熵下降常代表模板掌握;推理主体熵降到很低且答案多样性同步消失, 才更接近塌缩. 再按题型与难度桶比较, 避免容易题占比变化造成总体熵下降.

用固定 prompt 多次采样, 计算首个推理分叉位置、不同最终答案数和正确解路径数. 熵指标与这些行为量一致变化, 解释更可信. 只报告一个标量熵, 无法说明探索发生在哪里.

### 14.7 长度层: 分位数与终止原因

平均长度会掩盖长尾. P50 稳定、P99 接近上限时, 少数回答已经拖慢同步采样并产生伪负奖励. 记录 P50/P90/P99、截断率、EOS 率、循环重复率和正确率—长度分桶. 这些量能区分必要长推理与退化循环.

长度变化还要按 reward 分开. 正确链变长、错误链稳定, 可能是难题获得更完整推导;错误链变长、正确链稳定, 更像探索退化. 一个统一长度惩罚对两类轨迹方向相同, 因此需要先做分桶.

### 14.8 数值层: NaN 之前的征兆

BF16 下 log-prob 差通常安全, 直接对极小概率求比可能下溢或溢出. ratio 应从 $\exp(\log\pi_\theta-\log\pi_{old})$ 计算, 并监控 log-ratio 绝对值. 标准差、reward 聚合与重要统计可在 FP32 完成.

NaN 出现前常有 loss scale 连续回退、梯度范数尾部扩张、某层激活 Inf 或 ratio 极值. 把这些告警设在有限值检查之前, 能保存触发 batch 和完整样本. 只在 NaN 后跳过 step, 会丢失根因.

### 14.9 一个最小诊断矩阵

| 现象 | 首查指标 | 常见根因 | 可证伪动作 |
|---|---|---|---|
| reward 平台 | 三类组、格式率 | 零优势或验证失败 | 固定人工混合组 |
| 熵骤降 | 分位置熵、答案多样性 | 模板集中或奖励锐化 | 关闭单一 shaping |
| 梯度尖峰 | 优势 P99、log-ratio P99 | 尺度放大或版本延迟 | 固定 batch 重算 |
| 长度触顶 | 截断率、重复率 | 预算不足或循环 | 离线延长生成 |
| clip 饱和 | 分 epoch clip fraction | 数据陈旧或更新过大 | 降 epoch/学习率 |
| 验证涨、测试跌 | verifier 分歧、去重集 | reward hacking 或记忆 | 人工审计高奖励样本 |

矩阵里的动作都能在短程或离线完成. 只有证据指向算法缺口时才增加技巧. 如果固定人工混合组也无法更新, 问题在实现;离线延长即可答对, 问题在长度预算;强弱验证器大量分歧, 问题在 reward 口径. 这些结论比「换一个更先进算法试试」更节省算力.

## 15. 每种技巧的假设、收益与反例

### 15.1 组内均值中心化

作用机制是消除同一道题的公共难度, 让回答只和同组同伴比较. 假设同组奖励可比, 且至少存在差异. 收益是无需 critic;反例是全同组与验证器系统误判. 与 GRPO 的关系是核心定义, Lite PPO 仍保留组均值.

若组内回答来自不同 prompt、不同提示档位或不同策略版本, 公共基线失去含义. GHPO 的原题探测组与提示后训练组不能混在一起归一, 正是这一假设的直接结果.

### 15.2 组内标准差归一

机制是让每组优势方差接近 1, 防止奖励尺度影响更新. 假设组内样本足够代表分布. 收益是各题尺度统一;反例是单成功组把稀有样本放大、全同组除零. Dr. GRPO 与相关分析质疑标准差项引入难度偏置, Lite PPO 改用批标准差就是另一种选择.

### 15.3 批标准差归一

机制是所有组共享一个尺度, 保留组内中心. 假设 batch 覆盖足够多题且奖励分布稳定. 收益是避免每组小样本 std 抖动;反例是有效组极少时零值稀释尺度, 不同 domain 混批时大尺度任务支配. 多领域训练应考虑按 domain 统计或先统一 reward 尺度.

### 15.4 动态采样

机制是过滤全同组, 补采直到有效组数满足要求. 假设题库有足够中等难度题, 补采成本可控. 收益是稳定有效 batch;反例是难题被长期排除、数据分布漂移、尾延迟. DAPO 将它作为核心技巧, JustRL 在适中题库上展示了关闭它也能长程训练.

### 15.5 clip-higher

机制是放宽正优势 ratio 上界, 延长成功链的强化区间. 假设正侧裁剪确实频繁, 且额外更新不会造成漂移. 收益可能是保留探索与稀有正确路径;反例是 base 模型 clip fraction 近零, 开关几乎无效. 应以方向化 clip 统计选型.

### 15.6 token-level loss

机制是让每个有效 token 等权, 长回答总权重更大. 假设长链包含更多有价值决策, 或希望消除每序列平均造成的 token 权重差异. 收益是充分利用长轨迹;反例是长错误循环被放大. 与 DAPO、Lite PPO 相连, 与 GSPO 的序列级 ratio 属于不同坐标: 一个改归约, 一个改重要性比粒度.

### 15.7 overlong filtering 与 shaping

filtering 可以丢弃截断样本, shaping 则连续惩罚接近上限的回答. 假设长尾主要是退化, 且被移除轨迹没有关键正确解. 收益是吞吐与长度稳定;反例是难题正确链恰好更长, 惩罚直接改变最优策略. 实验应按正确性和终止原因拆分长回答.

### 15.8 KL 正则

机制是限制相对参考策略的长期漂移. 假设参考策略质量可靠, reward 存在投机风险. 收益是语言能力与分布稳定;反例是参考策略缺少目标能力, KL 阻碍新推理模式. 数学规则奖励下可弱化, 开放式奖励下需重新评估.

### 15.9 熵正则

机制是提高动作分布熵. 假设性能下降源于探索不足, 且全 token 熵与有用路径多样性相关. 收益是延缓集中;反例是格式、算术与答案 token 被无差别随机化. 位置化诊断应先于系数扫描.

### 15.10 优势裁剪

机制是限制极端标准化优势, 减少单组主导更新. 假设尾部主要来自估计噪声. 收益是梯度稳定;反例是稀有正确链本来就应获得大权重, 裁剪会降低学习速度. 报告被裁剪样本的真实正确率与组成功数, 才能判断尾部是噪声还是信号.

### 15.11 reward clipping

连续 reward 或多个奖励项叠加时, clip 可防异常分数放大. 假设极值不携带比例信息. 二元奖励已经有界, 再 clip 没有作用;过程奖励中若高分步骤确实更关键, clip 会丢信息. 先画 reward 分布与人工质量关系, 再设阈值.

### 15.12 更大组与更多 prompt

固定生成预算下, 增大 $G$ 提高每题探索, 增大 prompt batch 提高题目覆盖. 假设稀有正确链是瓶颈时偏向大组, 数据多样性是瓶颈时偏向更多 prompt. 用 $(B,G)$ 网格并按 $p$ 分桶评测, 比照搬某篇论文的组大小可靠.

## 16. 与 GRPO、DAPO、GSPO 等方法的严格坐标

| 维度 | GRPO | DAPO | GSPO | Lite PPO | GHPO | JustRL |
|---|---|---|---|---|---|---|
| 优势中心 | 组均值 | 组均值 | 可沿用组优势 | 组均值 | 内层通常组均值 | 标准 GRPO |
| 优势尺度 | 常见组 std | 配方实现决定 | 配方实现决定 | 批 std | 内层实现决定 | 组 std |
| ratio 粒度 | token | token | sequence | token | 内层实现决定 | token |
| loss 归约 | 常见 response-level | token-level | 独立于 ratio 定义 | token-level | 内层实现决定 | 默认 GRPO |
| 数据路由 | 无 | 动态过滤 | 无固有要求 | 移除 overlong filtering | 全零题加提示 | 不动态过滤 |
| 关键问题 | 无 critic 优势 | 长程稳定与效率 | 长序列 ratio 稳定 | 最小技巧组合 | 稀疏全零组 | 固定长程基线 |

这张表把容易混淆的三个粒度分开: advantage 在哪个集合统计, ratio 在哪个范围聚合, loss 用什么分母归约. GSPO 的 sequence ratio 不自动意味着 sequence-level loss;DAPO 的 token-level loss 也不决定优势必须按 token 估计. 组合方法时每一列都要单独填写.

### 16.1 一个组合反例

某实现宣称使用「GSPO + DAPO」, 实际把 token log-ratio 求和得到序列 ratio, 又将同一序列 ratio 广播到 token, 按所有 token 平均. 长回答通过 log-ratio 求和更容易触发 clip, 在 token loss 中权重也更大, 两种长度效应方向可能冲突. 若未说明长度归一方式, 方法名无法确定实际目标.

### 16.2 Lite PPO 的位置

论文最终提出的 Lite PPO 保留 vanilla PPO loss 结构, 采用组内均值中心、批标准差缩放与 token-level loss, 并移除 overlong filtering 等冗余组件. 它的主张来自统一框架下的隔离实验: 技巧价值依赖模型与数据, 两项组合在所测设置中稳定有效.

这不等于批 std 和 token-level loss 在所有任务上必胜. 批 std 假设 batch 代表性, token-level loss 假设长度权重合理. 多领域混批、长错误轨迹或极端稀疏 batch 都可能破坏条件. 官方 ROLL 文档也把均值类型、std 类型和 token-level loss 暴露成独立配置, 说明它们应当可消融.

### 16.3 选择流程

先测四个基础分布: 每题成功率与三类组占比、组内相关性、长度—正确率关系、ratio/clip 分布. 全错率高时处理奖励稀疏;组内相关高时改善探索;长错误占主导时处理长度;clip fraction 高时研究裁剪或 off-policy. 指标健康却性能不涨, 再查数据覆盖和 reward 对齐.

每次只改变一个统计轴. 从组 std 换批 std 时保持采样与归约;从 response-level 换 token-level 时保持优势;启用 GSPO 时保持 loss 分母;加动态采样时按总 token 对齐. 这样结果才能映射回具体机制.

## 17. 可证伪消融与验收

第一组实验围绕奖励稀疏. 固定模型与题库, 扫描 $G\in\{4,8,16\}$, 比较原始采样、动态补采与 GHPO 引导. 按总生成 token 对齐, 报告有效组、零提示验证分数和吞吐. 若动态补采只提高每 step 分数、按 token 无收益, 价值主要来自额外采样;若 GHPO 受助分数涨而零提示不涨, 迁移假设未成立.

第二组围绕归一化. 组均值固定, 比较无尺度、组 std、批 std 与按 domain 批 std. 使用正常 batch、有效组极少 batch、混合 reward 尺度 batch. 报告优势 P99、梯度方差和最终性能. 批 std 若在极稀疏 batch 产生尾部, 应能由合成反例提前预测.

第三组围绕长度. 二乘二比较 response/token 归约与无/有 overlong shaping, 再按正确性和长度桶拆结果. 若 token-level 只在长正确链多的数据上有效, 机制得到支持;若 shaping 缩短回答却降低难题正确率, 偏差已经显现.

第四组围绕裁剪. 扫描对称 clip、clip-higher 与 GSPO 序列 clip, 按正负优势、回答长度和 mini-batch 序号报告命中率. 任何最终分数差都应能在 ratio 分布中找到对应变化. clip 几乎从未触发时, 上界改动缺少作用通道.

第五组围绕 KL 与熵. 固定 rollout 与 reward, 比较无正则、KL、熵、二者组合. 报告 reference KL、分位置熵、答案多样性、人工质量与 reward hacking 率. 若熵上涨只发生在格式 token, 或 KL 降低同时目标能力停滞, 正则没有完成预期任务.

第六组围绕验证器. 对同一批回答用轻量规则、强模型与人工判定, 计算假阳性、假阴性及组优势翻转率. 训练消融按离线重标后的 reward 先做短跑. 强验证器只有在人工一致率提高且最终能力上升时, 才能称为更强.

上线验收从合成张量开始: 全同组零优势, 跨卡分组一致, 等长回答两种归约等价, 对称上下界退化为标准 PPO, 更新前 ratio 近 1, padding 与 prompt token 不进 loss. 随后跑固定小数据, 检查 verifier、终止原因、三类组和 clip 分布. 所有条件通过再启动长程训练.

训练中保留完整数据谱系: prompt/group id、策略版本、reference 版本、old log-prob、采样参数、终止原因、验证器原始输出、reward、advantage、ratio、mask 和 loss. 指标异常时可以从最终梯度追到原始回答, 才称得上可诊断.

一项技巧值得保留, 需要同时满足四条: 基线确实出现它针对的故障;开关改变了预期中间指标;固定预算下验证能力提高;在至少一个相邻模型或数据设置中复现. 缺少第一条, 技巧没有作用对象;缺少第二条, 机制解释不成立;缺少第三条, 只有过程曲线好看;缺少第四条, 结论可能依赖偶然配置.

## 18. 一次异常训练的完整推演

假设一个数学 RLVR run 使用 256 个 prompt、每题八条回答、温度 1.0、组均值与组 std、token ratio 裁剪、response-level loss. 训练到第 600 步后出现四个现象: reward 继续上升, 保留集分数下降, 平均长度从 3000 涨到 7000, 策略熵下降. 单看这些曲线, 可以讲出许多故事: 模型在做更深推理, 模型过拟合, 奖励器被攻击, 或探索塌缩. 需要把故事变成可复算判断.

第一步检查三类组. 假设全错率从 30% 降到 15%, 混合率从 60% 降到 35%, 全对率从 10% 升到 50%. 训练 reward 上升主要由全对组增加贡献, 有效组反而减少. 这意味着每步真正提供梯度的 prompt 从约 154 个降到约 90 个, 梯度方差可能上升. 仅凭 reward 上升无法认定训练更健康.

验证器结果显示, 高 reward 回答里有大量输出在末尾重复多个候选答案, 轻量规则只取末个 `\boxed{}`;模型写出若干尝试后靠枚举命中. 人工判断这些回答缺少可靠推导, 规则验证器仍给 1. 假阳性从训练早期的 1% 上升到 8%, reward 与真实质量已经分叉.

第三步看长度分桶. 0 至 2K token 的正确率基本不变, 2K 至 6K 略涨, 6K 以上的规则 reward 很高、人工正确率却低, 且重复率显著增加. 长度增长的主要来源是枚举与重复, 不属于更深推理. 此时简单增加最大输出长度只会给漏洞更多空间.

分位置熵显示格式和答案区大幅下降, 推理主体变化较小. 多次采样的文本虽有差异, 收尾都集中到相同的多答案模板. 这是策略集中到 reward 捷径的证据, 尚不足以证明全局探索能力消失. 对全 token 加熵奖励可能提高措辞随机性, 未必破坏捷径.

第五步检查优势扩散. 一组八条中, 某条枚举命中得到 1, 七条正常推理失败得到 0. 标准化后捷径回答优势约 $2.646$, 其余各约 $-0.378$. 验证器漏洞被组归一放大:模型不仅强化捷径, 还压低正常探索链. 若这种组越来越多, 策略集中会自我加强.

第六步检查 ratio 与 clip. 正优势上界命中率从 5% 升到 40%, 高优势、长回答桶最集中. clip-higher 在这里会放宽捷径正样本的更新, 可能让问题更快. 技巧本身按设计工作, 只是奖励把错误方向标成正优势. 继续调裁剪边界无法修复目标错位.

基于这些证据, 首要修复是验证器:限制答案格式, 多答案输出按明确规则处理, 用独立符号检查或人工标注验证. 修复前保存同一批 rollout, 用新旧验证器离线重打 reward, 计算优势翻转率. 如果大量高优势捷径变为负优势, 根因得到确认.

修复后从第 500 步 checkpoint 重启, 避免已经集中的策略继续带来数据偏置. 对照组从第 600 步直接继续, 两组使用相同后续 prompt 与生成 token 预算. 若重启组的人工正确率与保留集恢复, 枚举模板占比下降, 验证器修复有效. 如果 reward 下降但真实分数上升, 也属于预期:奖励口径变严, 曲线纵轴已经改变.

现在换一个版本. 假设人工审计没有发现漏洞, 长回答多数推理连贯, 但 35% 在输出最终答案前达到长度上限. 离线把上限从 8K 延到 16K, 其中一半完成正确答案. 同样的四条异常曲线, 根因变成上下文预算不足. 修复方向是延长输出、改善停止策略或训练更紧凑的推理, 强化 verifier 没有帮助.

再换一个版本. 长度与验证都正常, 但第一 mini-batch 的 ratio P99 已达到 2.5, 样本平均延迟十二个 learner 版本. clip fraction 超过 70%, 大部分 token 在平台. 根因是异步 off-policy 失配. 限制版本延迟、同步 old log-prob 与减少队列积压后, ratio 回到合理范围. 加 KL 只能限制 learner 漂移, 无法让陈旧样本重新变成当前分布.

三个版本的表面症状接近, 对应修复分别位于 reward、长度和时序. 这说明训练技巧的选择必须晚于数据流诊断. 一个组件可能在自己的机制上完全正确, 却因上游信号错误而加速坏方向.

还可以继续做成本核算. 验证器漏洞版本中, 长回答把每步生成 token 从约 600 万推到 1400 万, 有效组却从 154 降到 90. 单位有效组成本从约 3.9 万 token 升到约 15.6 万, 增加四倍. reward 曲线更高、系统实际学习效率反而更差. 这个比值比每秒 token 更接近训练目标.

定义

$$
C_{\mathrm{active}}=
\frac{\text{累计生成 token}}
{\text{累计有效组数}},
$$

再配合每百万 token 的保留集增益, 可以比较动态采样、长度控制和异步调度. 动态采样通常降低每有效组成本, 但补采与验证也计入分子;长度惩罚可能降低 token 成本, 同时损伤难题分数;异步系统提高硬件利用率, 若样本陈旧又会降低有效 clip 比例. 单一吞吐指标无法覆盖这些交换.

一次完整事故复盘应保存四类材料. 原始样本证明模型实际做了什么;统计曲线证明现象何时出现;合成或离线实验隔离机制;对照重启证明修复改变了最终能力. 只留下「加了某技巧后好了」, 下一次换数据或模型仍会重复踩坑.

这套推演也能用于正常训练. 每隔固定步数抽取代表性组, 将 reward、优势、ratio、clip、长度和最终梯度串在同一份记录里. 总体曲线展示趋势, 单组记录解释因果链. 二者结合, 才能看清一个技巧究竟在哪个环节发挥作用.

训练后期还要防止「容易题饱和」被误判为平台. 全对组增长、混合组下降时, reward 可能继续上涨, 梯度密度却下降. 若更难保留集仍有提升空间, 可以扩充题库或启用动态课程;若所有保留集都趋稳, 正常停止比添加技巧更合适. 平台有时只是任务已经学完.

相反, 全错组占比高且固定不降, 表示课程断层. 增大 $G$ 的收益可由 $(1-p)^G$ 预估;若估计 $p$ 极低, 从 8 增到 16 仍几乎全错, 采样加倍不划算. 这时提示引导、过程奖励、较易数据或 SFT 预热更可能建立第一批成功链.

对每项改动都应保留撤回路径. 验证器升级保留旧版离线分数, 动态采样保留原始抽样流, KL 调整保存 reference checkpoint, 数据课程记录每题进入概率. 改动无法提升固定预算下的保留集能力, 就恢复基线. 可撤回性让复杂配方仍然能够归因.

「技巧」最终是一条条件命题: 在某个可观测故障出现、若干假设成立时, 改变某个统计量会提高目标能力. 「陷阱」则是省略条件, 只保留组件名字. 把故障、假设、中间指标与反例写全, 才能让同一项技术在不同模型上得出不同结论时仍保持一致解释.

另一个常被忽略的量是随机种子方差. RL rollout、题目抽样与 mini-batch 顺序同时随机, 单次 run 的局部平台或尖峰可能没有稳定含义. 长程实验成本太高时, 可以先用多个种子跑较短窗口, 比较三类组、熵、长度和验证分数的置信区间. 若某技巧的收益小于种子间波动, 暂时不能宣称它解决了问题.

短跑也有局限. 有些技巧只在长期漂移后显效, 例如 KL 约束和课程退坡;有些技巧前期加速、后期损伤, 例如过强长度惩罚. 因而实验可采用「多 seed 短跑 + 少 seed 长跑」: 短跑测早期稳定概率, 长跑检查累积偏差. 两类证据分别报告, 避免用一个终点概括全部阶段.

统计显著之外还要看实际效应. 九个 benchmark 平均提高 0.3 点, 若成本增加一倍、某些难题下降, 价值有限;提高 0.3 点却显著降低崩溃率, 对大规模训练可能很重要. 报告均值、方差、最差 run、计算成本与题型分解, 才能判断技巧服务的是性能、稳定还是效率.

数据混合会让许多诊断失去单一解释. 数学、代码和通用问答的 reward 尺度、长度与验证噪声不同, 共用批标准差时一个 domain 可以决定全部优势尺度;共用 token-level 分母时长代码轨迹可能压过短数学答案. 多领域训练至少按 domain 记录奖励分布和有效 token, 必要时先域内归一再跨域加权.

假设数学 reward 为 0/1, 代码 reward 是通过测试比例 0 到 100. 直接混合后, batch std 几乎由代码决定, 数学优势被缩小. 即使两者都规范到 0 到 1, 代码连续分数与数学二值分数的方差仍不同. 「统一尺度」需要看分布, 不能只看取值上下界.

多 reward 组合也有同样问题. 正确性、格式、长度和风格按权重相加, 权重就是对目标的声明. 某项方差大, 即使系数小也可能主导组内排序. 应记录每项 reward 的均值、方差、与总 reward 的相关性以及移除该项后的优势翻转率. 优势翻转比权重数值更能说明实际控制力.

设正确性分为 1, 格式分为 0.1. 一条错误但格式正确的回答得 0.1, 一条正确但解析格式失败的回答可能得 1 或 0, 取决于验证流程. 如果正确答案因格式被归零, 格式项就从微小辅助变成门控. 奖励代码的执行顺序与缺失值处理必须写进规格.

参考策略选择也会改变 KL 的含义. 以 base 模型为 reference, 会惩罚蒸馏推理风格;以 distill 起点为 reference, 则保护长链行为;训练中重置 reference, 锚点又随时间移动. 同一个 $\beta$ 在三个设置中约束不同对象. 实验报告必须给出 reference 的精确 revision.

off-policy 程度不能只用版本差衡量. 某些 step 更新很小, 相隔十版仍接近;某次异常更新很大, 相隔一版也可能远离. 更直接的量是行为样本上的 log-ratio 分布与有效裁剪率. 版本延迟适合系统告警, ratio 才是算法实际看到的偏移.

组内相关性也不只来自解码. 数据本身存在近重复题时, 不同 prompt 组之间的梯度高度相关, prompt batch 256 的有效题目多样性可能远低于 256. 对题面与解法做聚类, 统计一个 batch 覆盖多少簇, 可以补足组内多样性指标. 增大 batch 若只增加同模板题, 方差下降有限.

梯度累积会放大这个问题. 若相邻 micro-batch 按数据顺序装入同一题型, 累积梯度偏向局部 domain. 打乱顺序能改善, 分布式 sampler 若各 rank 使用相同种子又可能重复抽题. 每个 global batch 的唯一 prompt 数、模板簇数与跨 rank 重复率都可直接核对.

评测同样需要守住随机性口径. 温度、top-p、采样次数和最大输出长度改变 pass@1;模型验证器会修正规则假阴性, 也引入自己的偏差. 比较技巧时固定评测协议, 保存原始输出, 以题为单位 bootstrap 置信区间. 把同题多次采样当独立题会低估误差.

训练与评测验证器不一致时, 分数变化有两种来源:策略真的更强, 或输出形式更适合某个判定器. 对一批 checkpoint 用两种验证器交叉评分, 检查排名是否稳定. 若排名频繁翻转, 方法结论依赖评测器, 需要人工审计分歧题.

当所有指标看似健康而性能仍停滞, 数据覆盖可能是瓶颈. 当前题库只训练代数, 保留集主要是几何, 再精细的裁剪与归一化也无法补足知识. 按题型计算训练覆盖、有效组和验证提升, 可以看到哪些能力根本没有信号. 此时扩数据比改优化器更合理.

反过来, 数据覆盖充分而特定题型持续全错, 可能缺少基础能力或推理支架. 先用更强模型估计题目可解性, 再用当前模型在提示、过程奖励或较易变体下测试. 提示后能解说明能力链缺一段;提示后仍失败, 可能是知识缺口、标注错误或验证问题.

最终形成的训练报告不必堆满所有曲线, 但原始日志应能回答这些问题. 正文挑与结论直接相关的中间指标, 附录提供配置、统计口径和失败样本. 读者能够从技巧名称一路追到公式、数据和具体回答, 结论才具备可复查性.

模型更新前后的行为对照也值得保留. 对固定 prompt 使用相同采样种子, 比较 token 分叉位置、答案、长度和 verifier 判定;再换不同种子测总体分布. 相同种子便于定位一次更新具体改变了哪里, 多种子用于判断分布性结果. 两类对照混在一起, 容易把个别路径变化误认为整体策略变化.

如果一次更新让正确链概率上升, 还要看它来自哪些 token. 核心推理步骤的 log-prob 上升说明模型更偏好该解法;只有 `\boxed{}`、答案数字或固定连接词上升, 则可能主要学到格式. 将正优势回答按推理区、格式区和答案区拆分平均 log-ratio, 可以把「学会做题」与「学会交卷」区分开.

同理, 负优势更新可能压低有价值的失败探索. 一条回答前九步正确、第十步算错, 二元 reward 会给整条序列同一个负优势, 前九步 token 也被压制. 组相对终局奖励的信用分配十分粗糙. 过程奖励、步骤级 advantage 或只对后缀更新可以缓解, 同时会引入新的标注与偏差. 是否值得采用, 取决于失败链中正确前缀的比例.

可从错误回答抽样, 标注首个错误位置, 统计错误前正确 token 占比. 如果大量失败链直到末尾才出错, 序列级广播的偏差较大;如果错误通常在开头发生, 终局负优势更合理. 这项小规模人工分析能直接决定是否需要更细信用分配, 比抽象争论过程奖励更有用.

训练技巧最终围绕三个量展开: 哪些样本进入梯度, 每个样本获得多大权重, 一份行为数据允许策略移动多远. 动态采样与课程主要改变第一项;归一化、长度归约和 reward shaping改变第二项;clip、KL 与 off-policy 控制改变第三项. 把新方法放进这三个坐标, 机制与潜在冲突通常就能看清.

三个坐标还提供了统一验收口径: 样本分布、权重分布与策略位移都要有训练前后的实测记录, 方法名称本身不能替代这些数据.
