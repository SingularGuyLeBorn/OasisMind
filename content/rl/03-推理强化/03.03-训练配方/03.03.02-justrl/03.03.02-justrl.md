# JustRL: 固定配方的单阶段 GRPO 基线

**论文信息**:
- **标题**: JustRL: Scaling a 1.5B LLM with a Simple RL Recipe
- **作者**: Bingxiang He, Zekai Qu, Zeyuan Liu 等(清华大学, UIUC, 上海人工智能实验室; 通讯作者 Ning Ding, Zhiyuan Liu)
- **年份**: 2025 年 12 月
- **论文**: [arXiv:2512.16649](https://arxiv.org/abs/2512.16649), [作者代码仓库](https://github.com/thunlp/JustRL)

**前置知识**: GRPO(1.3.1.1 节), DAPO(1.3.2.1 节)

过去一年小模型推理 RL 的工作不断叠加训练阶段, 动态调度和课程策略, JustRL 反着走: 单阶段, 超参数全程不动, 数据不过滤, 只在 veRL 默认 GRPO 上保留 clip-higher 一项技巧. 论文的主张很具体: 在两个 1.5B 蒸馏 backbone 上, 这个固定配方训四千步左右, 没有塌缩, 没有需要干预的长平台, 平均分不低于同期更复杂的方法, 估计 token 预算约为对手的一半; 把两种「标准技巧」加回基线, 分数反而下降. 这篇按开关逐项拆这个配方, 再给训练动态, 消融, 计算量对比和复现清单.

## 1. 动机: 复杂度是否必要

### 1.1 小模型推理 RL 的技术堆叠

DeepSeek-R1 之后, 1.5B 级别的数学推理 RL 在一年内堆出一长串稳定化技术. STILL 调超参数并在训练中重置 KL 参考; DeepScaleR 把训练切成三段, 上下文逐段加长 8K→16K→24K; FastCuRL 扩到五段, 长短思维链交替压缩与扩展; ProRL 分八段并加计划式长度惩罚, ProRL-V2 换成余弦日程; BroRL 把每题 rollout 加到 512 条; POLARIS 做动态数据过滤加自适应温度; QuestA 用部分推理链做提示, 按难度排课程. 论文表 1 把这九类技术缩写成 EC, THP, TTP, RKL, LC, AT, RR, DS, ST 九列, 除 JustRL 外的每个模型至少勾三列, 勾法几乎不重样.

这种堆叠带来的直接后果是不可归因. 每个方法各自报告收益, 但各自的基线里已经躺着别人的技巧: 在复杂基线上加一个稳定化模块, 收益可能来自模块本身, 也可能来自对既有技巧副作用的补偿, 两种情形在论文的数字里无法区分. 论文给这组堆叠的诊断是一句话: 累积的「最佳实践」可能在互相打架, 而不是在对抗 RL 的根本困难. 多一次阶段切换就多一次数据分布和优化目标的跳变, 每加一个动态调度, 学习率和探索的有效含义就随时间变一次, 模块之间的交互没有人单独测过.

这些工作几乎都从蒸馏模型起步, 初始训练状态相近, 最终采用的组件组合却明显不同. 这说明技巧选择包含路径依赖: 先发表的配方成为后续工作的基线, 新增组件的收益以已有复杂度为条件, 组件越多越难单独归因. 一个不过滤, 不切换, 不动态调参的基线可以减少交互项, 使每项新增复杂度的影响更容易识别.

**新增组件本身也可能引入不稳定性**, 这是论文检验的假设. 如果简单基线没有出现 reward 塌缩, 熵漂移或长度爆炸, 对应干预就缺少明确作用对象, 甚至可能降低性能. JustRL 先完整训练简化基线, 再分别加入两种常用组件, 直接比较它们带来的收益与副作用.

### 1.2 论文的主张与自我设限

论文的两个主张. 第一, 规模给足后的简单配方够用: 固定超参数在 DeepSeek-R1-Distill-Qwen-1.5B 和 OpenMath-Nemotron-1.5B 上分别训 4380 步与 3440 步, 九基准平均 54.87% 与 64.32%, 不低于九阶段的 ProRL-V2 (53.08%) 和使用课程学习的 QuestA (63.81%), 估计 token 预算约为对手的一半. 第二, 盲目加技巧有代价: 在基线上叠加 DAPO 式长度惩罚, 再叠加更强的验证器, AIME24 从约 55% 掉到约 45%, 伴随策略熵坍缩. 两个训练后的模型和代码随之公开, 这个基线可以被直接拿来当对照.

实验覆盖两个 1.5B backbone, 数学规则验证和四千步量级训练. 平滑曲线说明这套固定配方在这些条件下可以稳定训练, 无法证明简单方法在其他模型与任务上总是更稳, 也没有识别每个复杂技巧对不稳定性的独立贡献. JustRL 自己同样在基线上增加技巧做消融; 区别在于先测量病症, 再决定是否打开对应开关.

评估新技巧时, 基线需要有足够长且稳定的训练记录. 基线仍在明显波动时, 收益数字同时混入组件效应与随机训练波动. JustRL 提供的固定基线减少了后一项, 使组件贡献更容易通过受控消融识别.

## 2. 配方: 开关逐项

### 2.1 保留的 GRPO 主体

优化器是 veRL 的默认 GRPO (1.3.1.1 节), 一行奖励一行判别. 奖励是二元结果分: 规则验证器判对 1 判错 0, 验证器直接沿用 DAPO (1.3.2.1 节) 的轻量规则版, 不引 SymPy 之类的符号库. 组优势按 GRPO 的标准做法: 同一题采 $N=8$ 条, 组内均值标准差归一, 序列级优势广播到该条全部有效 token, old-policy 的 log-prob 用 stop-gradient, padding 不进 token 平均.

奖励侧的选择贴着任务走. 数学推理的 reward 可规则验证: 最终答案和 ground truth 比对即可, 不需要 reward model, 也不需要人工打分, hacking 面集中在答案格式, DAPO 验证器的解析规则已经覆盖. 二元结果分丢掉过程信息 (哪一步推导出错), 换来零成本和零标注偏差; 对组归一的优势估计, 丢过程信息的代价由同题多条对比补偿, 这也是 GRPO 与二元 reward 天然适配的原因 (1.3.1.1 节的组优势设计).

保留的唯一技巧是 clip-higher, 裁剪区间 $[0.8, 1.28]$, 即负侧 $\epsilon_{low}=0.2$, 正侧 $\epsilon_{high}=0.28$. 机制与 DAPO 的推导一致: 正优势样本的上界放宽, 正确的推理模式可以被强化到位而不在 $1+\epsilon$ 处被截停, 负优势的压制照旧. 单 token 的损失写成

$$u_t=\min\left(r_t \hat A_i,\ \operatorname{clip}^{+}(r_t,\hat A_i)\,\hat A_i\right),$$

其中 $r_t=\pi_\theta(y_t|y_{<t})/\pi_{old}(y_t|y_{<t})$ 是逐 token 的重要性比率, $\hat A_i$ 是第 $i$ 条回答的组优势, 正优势时 clip 上界取 $1+\epsilon_{high}$, 负优势时下界取 $1-\epsilon_{low}$. 论文把 clip-higher 算作基线的一部分, 表 2 的 "Clip Ratio Range [0.8, 1.28]" 是全套配置里唯一带技巧色彩的数字. 实现层面, 损失带负号交给梯度下降最小化, 与最大化裁剪代理目标完全等价; veRL 代码里的 loss 下降正是这套符号约定的结果.

### 2.2 移除的每一项

表 2 的完整开关状态: 不用 KL loss, 不用 entropy regularization, train batch 256, PPO mini batch 64, micro batch 每 GPU 1, 学习率 $1\times10^{-6}$ 常数, 温度 1.0, rollout $N=8$, max prompt 1K, max response 15K, 总上下文 16K. max prompt 1K 加 max response 15K 恰好拼成 16K 总上下文, 训练长度边界由这两个数决定, 超界直接截断. 数据用 DAPO-Math-17k, 不做离线难度过滤, 不做在线动态采样, prompt 后缀固定一句「Please reason step by step, and put your final answer within `\boxed{}`」, 不调.

逐项看移除的理由. 去 KL: 数学规则 reward 的 hacking 面小, KL 锚定的价值从防 hacking 退化为防不稳, clip 已承担这部分, DAPO 同样去 KL (1.3.2.1 节 §6). 去熵正则: 熵控制由 clip-higher 承担, 目标函数里不再加项. 单阶段: 每多一个阶段就多一次分布与超参的跳变, 阶段切换本身是不稳定的来源. 固定超参: 自适应温度和动态 batch 改变的是学习率与探索的有效含义, 调它们的收益必须大于引入的时变因素才划算. 四项移除指向同一条原则: 每个开关都要有证据支持, 没有证据的开关默认关掉.

优化器的层次结构也要记全. train batch 256 拆成 4 个 PPO mini batch (每个 64), 每个 mini batch 在每张 GPU 上 micro batch 1, 32 张卡各算一份再聚合, 等效于 micro batch 32 的梯度累积. 一份 rollout 数据被 4 个 minibatch 复用一次, 这是 2.4 手算里 ratio 偏离 1 的直接来源, 复用次数越多, 数据的第二次访问离采样点越远, clip 触发的占比随之上升. 学习率 $10^{-6}$ 常数, 没有 warmup 与 decay 日程, 与「超参数全程不动」的约定一致, 代价是训练末段没有学习率退火提供的隐式收敛辅助, 末段涨分斜率变缓时, 先确认这不是自然现象再考虑动日程.

有一处容易读混. 论文表 1 在 EC (entropy control) 一列给 JustRL 打了勾, 表 2 又写 "Use Entropy Regularization: No". 两个表述不矛盾, 说的是两层东西: 表 1 的 EC 按机制归类, 把 clip-higher 视为熵控制手段; 表 2 描述目标函数, 确认 loss 里没有 $\mathbb{E}[\log\pi]$ 之类的熵正则项. 引用时分开: 机制层面 JustRL 有熵控制, 目标函数层面没有熵项.

### 2.3 手算一: 二元奖励下的组优势

声明假设: $N=8$, 奖励按 $\pm1$ 编码 (论文没写具体编码, 图 2 的 reward 曲线落在 $[-1,1]$ 区间内, 与 $\pm1$ 相容), 优势 $\hat A_i=(R_i-\mu)/\sigma$ 用总体标准差, 除以 $N$, 与 veRL 一致. 取一组 8 条, 3 对 5 错. 第一步算均值: $\mu=(3\times1+5\times(-1))/8=-0.25$. 第二步算方差: 对的 3 条偏差 $1-(-0.25)=1.25$, 平方 $1.5625$; 错的 5 条偏差 $-0.75$, 平方 $0.5625$; 方差 $=(3\times1.5625+5\times0.5625)/8=(4.6875+2.8125)/8=0.9375$. 第三步标准差 $\sigma=\sqrt{0.9375}\approx0.9682$. 第四步优势: 对的每条 $\hat A=(1-(-0.25))/0.9682\approx1.291$, 错的每条 $\hat A=(-0.75)/0.9682\approx-0.775$.

再看无效组. 8 条全对或全错时 $\sigma=0$, 优势无定义, 实现掩成 0, 这组 8 条 rollout 的算力花掉, 梯度贡献为零. 无效组概率随组内通过率 $p$ 变化: $p^8+(1-p)^8$. $p=0.5$ 时 $2\times0.5^8\approx0.78\%$; $p=0.25$ 时 $0.25^8+0.75^8\approx10.0\%$; $p=0.1$ 时 $0.9^8+0.1^8\approx43.0\%$. DAPO 用动态采样过滤全同组再补采 (1.3.2.1 节 §3), JustRL 明确不这么做, 让无效组留在 batch 里, 换调度简单与 batch 尺寸恒定. **不过滤是一个明确的配方决定**: 代价是低通过率的题上近一半采样注定无效, 论文的判断是这笔固定浪费小于动态补采的系统复杂度与分布漂移.

手算一同时给出监控口径. 全同组占比曲线就是题库难度分布在训练中的镜像: 模型变强, 一批题从「有对有错」滑向「全对」, 占比上移; 某类题塌掉, 滑向「全错」, 同样上移. 训练时把这个占比画出来, 等于免费拿到一份难度迁移记录, 动态采样团队用过滤率看的东西, 不过滤的团队用同一个公式看, 成本只是统计. 另一个附带结论: $N=8$ 时 std 归一把优势幅度放大到 1.3 量级 (上面的 1.291), 与 $N=2$ 或 $N=4$ 相比, 组越大优势方差越小, 学习率的有效含义随 $N$ 变, 换 $N$ 要连带重调学习率.

### 2.4 手算二: clip-higher 的有效梯度区间

沿用 2.3 的优势值, 看单 token 损失 $u=\min(r\hat A, \operatorname{clip}(r)\hat A)$ 随比率 $r$ 的变化, 假设当前策略刚更新过一步, $r$ 离开 1. 正确链某 token, $\hat A\approx1.291$: $r=1.10$ 时未触 $1.28$ 上界, $u$ 对 $r$ 的斜率就是 $1.291$, 梯度全额; $r=1.28$ 时到达平台起点; $r=1.30$ 时 min 结构取 clip 支, 斜率跳成 0. 错误链某 token, $\hat A\approx-0.775$: $r=0.85$ 时未到 $0.8$ 下界, 斜率 $-0.775$, 负梯度仍在压这条链的概率; $r=0.75$ 时越过下界, 斜率 0.

和对称裁剪 $\epsilon=0.2$ (区间 $[0.8,1.2]$) 并排: 正确链的 $r$ 落在 $1.2$ 到 $1.28$ 之间时, 对称裁剪已经截停, clip-higher 仍给全额梯度. 这个区间为什么重要: train batch 256 分成 4 个 PPO mini batch, 同一份 rollout 数据复用, 每条数据进入更新时策略已经偏离采样点, $r$ 系统性离开 1, 正优势样本的 $r$ 聚集区就在 1.2 附近. clip-higher 放开的恰好是信号最密的一段, 这也是 DAPO 消融里 Clip-Higher 单项贡献显著的同一处机制 (1.3.2.1 节 §2.3).

顺手留下两个检查口径. 其一, 训练时分别统计正优势触发上界与负优势触发下界的比例, 两侧严重失衡说明更新在「压错」上先饱和, 而「扶正」还有余量, 这是 clip-higher 针对的失衡. 其二, 画 clip 曲线时两个分支分开画, 只有 $A>0$ 的分支相对对称裁剪右移, $A<0$ 的分支纹丝不动, 画成整体右移会重新引入「对称区间」的错误直觉 (1.3.2.1 节 §2.3 的同一处提醒).

## 3. 训练动态: 四千步无干预

### 3.1 三条曲线各说明什么

论文图 2 对 JustRL-DeepSeek-1.5B 的 4380 步做了逐段记录. 策略熵在后期于 1.0 到 1.6 之间震荡, 中枢 1.2 到 1.4, 没有系统性上移 (探索消失) 也没有系统性下移 (过早收敛). 平均训练 reward 从约 $-0.6$ 单调爬到约 $+0.4$, 有噪声但趋势连续, 没有需要打断的长平台或骤降. 平均响应长度从约 7000 到 8000 token 起步, 前 1000 步自发压到 4000 到 5000, 之后稳定, 全程没有长度惩罚项参与.

三条曲线要合起来读. 熵不降说明采样多样性还在, reward 单调升说明组内对比持续有信号, 长度收敛说明生成成本随训练下降: 同样 2048 条响应, 后期平均 4500 token 对起步的 7500 token, 每步 rollout 的 token 数几乎砍半, 四千步能跑完本身就有长度收敛的功劳. 时间顺序也有信息: 压缩发生在前 1000 步, 早于分数的主要爬升段, 说明长度是最先稳定下来的量, 后续涨分发生在长度已稳的区间里, 不存在「边涨分边失控变长」的耦合.

二元奖励没有直接惩罚冗长推理, 但同题组内对比仍可能推动长度下降: 固定生成预算下, 短而正确的链能够完成更多采样, 组内优势随之把概率质量推向这类回答. 这项机制与论文曲线相容, 尚未经过受控消融. 显式长度惩罚则直接创造长度与正确率之间的对抗压力 (见 1.3.2.1 节 §5). 两种机制可以通过长度 P50/P99 以及长度—正确率分桶曲线区分.

ProRL-V2 观察到长度漂移, 因此引入计划式余弦长度惩罚; BroRL 遇到平台期, 因此把每题 rollout 提到 512; 多个工作在 KL 发散时重置参考模型. JustRL 的四千步训练没有出现这三类现象: 长度自行收敛, 曲线没有平台期, 目标函数也不含 KL. 这只是跨工作的观测对照, 无法分离组件造成和缓解不稳定性的效应; 它能支持的结论限于当前初始条件下不需要对应干预.

### 3.2 稳定性依赖起点与数据分布

论文把稳定性归给 clip-higher 与「规模给足」的组合. 规模侧的数字: 4380 步对 DeepScaleR 的 1750 步与 ProRL-V1 的 2450 步, 每步 256 题乘 8 条共 2048 条样本, 组优势的大样本方差被压平, 学习率 $10^{-6}$ 恒定, 不需要日程保护. clip-higher 侧: 正优势不被提前截停, 策略不用拿「模棱两可的稳妥」换稳定, 熵自然停在高位区间 (1.3.2.1 节 §2.2 对同一机制的解释: Clip-Higher 改的是优化路径不是目标函数). 两个因素各司其职, 缺一个都难说.

DAPO 从 Qwen2.5-32B 基础模型起步, 训练初期熵高, 长度失控风险明显, 因而 shaping 与动态采样有明确作用对象. JustRL 从蒸馏模型起步, 初始熵已经落在稳定区间, 相同组件反而可能干扰训练. 两项工作使用 clip-higher, 相同验证器和相同数据, 其余开关却方向相反, 原因在于基线动态不同. 迁移组件前应先确认自己的基线出现了对应异常.

两个 backbone 都是蒸馏过的推理模型, 起始熵落在可用区间, 没有从随机初始化或弱 SFT 起步; DAPO-Math-17k 对 1.5B 模型又以中等难度题为主, 无效组占比天然较低 (见 2.3 的手算). 因此稳定性同时来自配方, 模型起点与数据难度分布. 换成弱基座, 另一种任务或明显偏难的数据后, 同一配方可能出现不同动态. 小规模试跑应先测全同组占比与起始熵.

## 4. 结果, 计算量与消融

### 4.1 九个基准的报告口径

硬件与时长: 两个 backbone 各用 32 张 A800-80GB, 训约 15 天. DeepSeek-R1-Distill-Qwen-1.5B 训 4380 步, 九基准平均 54.87, 高于 ProRL-V2 的 53.08 与 DeepScaleR 的 44.88, 九个里六个领先; backbone 自身平均 37.65, 相对起点提升约 17 个点. 分行数字如下 (论文表 3):

| 模型 | AIME24 | AIME25 | AMC23 | MATH-500 | Minerva | Olympiad | HMMT | BRUMO | CMIMC |
|---|---|---|---|---|---|---|---|---|---|
| Backbone | 29.90 | 22.40 | 63.82 | 84.90 | 34.65 | 45.95 | 13.44 | 30.94 | 12.89 |
| JustRL-DeepSeek | 52.60 | 38.75 | 91.02 | 91.65 | 51.47 | 67.99 | 21.98 | 52.71 | 25.63 |

分行读. 提升最大的是 BRUMO (+21.77) 与 CMIMC (+12.74) 这类较新的基准, 最小的是 MATH-500 (+6.75), 起点 84.90 已接近饱和; Minerva 训完也只有 51.47, 长文本竞赛题仍是 1.5B 的短板. 论文图 1 的 AIME24 曲线端点是 28% 到 58%, 表 3 同一模型同一基准的 avg@32 值是 52.60, 两处对不上, 报告没解释差异, 引用时分开标注. Nemotron 一侧 (论文表 5): AIME24 69.69, AMC23 96.02, MATH-500 94.15, Minerva 只有 30.24 (从 26.93 涨上来, 是九个里涨幅最小的一格), 平均 64.32 高于 QuestA 的 63.81, 九个里五个领先, backbone 自身平均 56.74.

评测协议本身也是配方的一部分: Pass@1 对每题 $N$ 次采样取平均, MATH-500, Minerva Math, OlympiadBench 三家用 $N=4$, 其余六家用 $N=32$; 评测温度 0.7, top-p 0.9, 生成上限 32K, 比训练的 16K 上下文宽一倍, 评测温度也低于训练采样温度 1.0, 两处温度要分开记录, 混用会让 Pass@1 不可比. 训练侧用规则验证器, 评测侧在规则判定之上再加 CompassVerifier-3B 模型判定器处理 false negatives. 这套协议意味着: 单次 greedy accuracy 与论文数字不可互换, 复现报告必须记录 checkpoint step, seed, 采样协议, 生成上限与判定器版本.

### 4.2 计算量对比与量级复算

论文表 4 与表 6 用近似 token 预算对比总计算: JustRL-DeepSeek 为 $1.4\times10^8$ k, ProRL-V2 为 $2.8\times10^8$ k, BroRL 为 $6.8\times10^8$ k; JustRL-Nemotron 为 $1.1\times10^8$ k, QuestA 为 $2.6\times10^8$ k, 摘要据此给出「约一半计算」. 口径要小心: 对用动态采样的方法按 POLARIS 的 50% 过滤率估算补采成本, 这是估算不是实测, 单位 k 指千 token; 论文声明即使按 0% 过滤 (对 JustRL 有利的假设方向) 计算量仍相当或更低. BroRL 的 6.8×10^8 k 来自每题 512 条 rollout, 是把采样密度推到极致的路线; 这组对比的不是算法优劣, 是两种算力花法: 花在更多题上 (batch 256) 还是花在每题更多条上 (N=512).

用公开配置估算 DeepSeek 侧的计算量. 假设每步 256 题, 每题 8 条响应, 稳态平均响应长度 4500 token, prompt 平均 500 token. 每步 rollout 约为 $2048\times(4500+500)\approx1.0\times10^7$ token; 乘 4380 步得到 $4.4\times10^{10}$ token. 若把训练侧前向反向与 reference 前向合计为约 3 倍 rollout 成本, 总量约 $1.3\times10^{11}$, 与论文报告的 $1.4\times10^{11}$ 同一量级. 由于每步长度分布和分项成本没有公开, 这项计算只用于检查数量级.

Nemotron 一侧的对比方向相同, 细节不同. JustRL 训 3440 步, 比 QuestA 的 2000 步多七成, 总计算反而只有对方的四成出头 ($1.1\times10^8$ k 对 $2.6\times10^8$ k), 差距主要来自三处: QuestA 的上下文上限 32K 是 JustRL 的两倍, rollout N=16 是两倍, 动态采样按 50% 过滤率估算的补采成本再抬一截. 步数多而总算力少, 是「长训练 + 小每步」对「短训练 + 大每步」的直接对照, 论文用这组数字说明拉长训练阶段不需要以计算量为代价, 前提是每步的效率 (上下文长度, 每条长度) 控制住.

### 4.3 消融: 两个开关加回去

论文在 JustRL-DeepSeek 上运行了超过 3000 步的改动实验. DAPO 式 overlong penalty 覆盖末尾 4K token: 响应进入 12K 到 16K 区间开始扣分, 到 16K 扣满. 配套的验证器版本换用 DeepScaleR 的规则, 目标是减少轻量验证的 false negatives.

AIME24 从约 55% 降到约 50%, 再降到约 45%. 相应版本的终点策略熵落到 0.5 至 0.6, 原配方维持在 1.2 至 1.4 区间.

长度惩罚给推理链施加压缩压力, 采样多样性随之收窄, 组内正确链趋同, 熵下降后有效探索信号变少. 第二组实验在长度惩罚之上同时更换验证器, 因而无法识别验证器的独立效应; 它只表明这项组合没有提升 AIME24. 三个设置均没有重复 seed 或误差区间, 所以约 55, 50 与 45 只能支持方向性判断: 两个新增开关没有兑现收益, 并伴随可观测的熵下降.

消融给出的通用原则是: 增加组件前, 先在基线上确认它针对的异常确实存在. 这个原则不依赖论文的具体模型规模. 异常不存在时保持基线不变; 异常出现时逐项打开对应组件, 并记录受控消融.

消融与主结果的口径差也要记下. 消融只报 AIME24 单基准, 九基准平均在消融组上没有报, 长度惩罚对另外八个基准的影响是未知数, 竞赛基准和课程基准对长度的敏感度不同, 单点结论外推到「长度惩罚全面有害」超出了这份消融能支撑的范围. 复现消融时, 至少把 MATH-500 与 BRUMO 补进评测集, 一个代表近饱和区间, 一个代表高区分度区间, 两点能把单点结论的轮廓补出大概.

## 5. 实现

### 5.1 教学实现

```python
import torch

def group_advantage(rewards):
    # rewards: [B, N]，二元奖励 +1/-1；对应论文 rollout N=8
    # 返回: [B, N] 组优势，全同组（std=0）掩成 0
    mu = rewards.mean(dim=-1, keepdim=True)                 # [B, 1]
    sd = rewards.std(dim=-1, keepdim=True)                  # [B, 1]，总体标准差（除 N）
    adv = (rewards - mu) / (sd + 1e-8)
    return torch.where(sd > 1e-8, adv, torch.zeros_like(adv))

def justrl_loss(new_logp, old_logp, advantages, mask,
                eps_low=0.2, eps_high=0.28):
    # new_logp/old_logp: [B, T] 有效 token 的对数概率
    # advantages: [B] 序列级优势；mask: [B, T] 有效 token 为 1
    # 对应 clip-higher 目标: u_t = min(r_t * A, clip(r_t) * A)
    ratio = torch.exp(new_logp - old_logp.detach())         # [B, T]，old 侧截断梯度
    adv_t = advantages.unsqueeze(-1) * mask                 # 广播到 token
    upper = torch.where(adv_t > 0, torch.full_like(ratio, 1 + eps_high),
                        torch.full_like(ratio, float("inf")))
    lower = torch.where(adv_t < 0, torch.full_like(ratio, 1 - eps_low),
                        torch.full_like(ratio, float("-inf")))
    clipped = ratio.clamp(lower, upper)
    per_tok = torch.min(ratio * adv_t, clipped * adv_t) * mask
    per_resp = per_tok.sum(-1) / mask.sum(-1).clamp(min=1)  # 每回答先按长度平均
    return -per_resp.mean()                                 # 再对回答等权平均

def check_without_model():
    # 手算一的对照组: 3 对 5 错，N=8
    rewards = torch.tensor([[1., 1, 1, -1, -1, -1, -1, -1]])
    adv = group_advantage(rewards).squeeze(0)               # [8]，逐格对照手算一
    T = 5
    new = torch.zeros(8, T, requires_grad=True)             # r = 1，落在未裁剪区
    old = torch.zeros(8, T)
    mask = torch.ones(8, T)
    loss = justrl_loss(new, old, adv, mask)
    loss.backward()
    expect = -adv / (8 * T)                                 # 清单第 3 条的闭式解
    assert torch.allclose(new.grad,
                          expect.unsqueeze(-1).expand(8, T), atol=1e-6)
```

这段代码对应论文表 2 的 loss 侧全部开关: 无 KL 项, 无熵项, 裁剪区间 $[0.8, 1.28]$ 即 `eps_low=0.2`, `eps_high=0.28`, 归约沿用 GRPO 默认 (每回答先按长度平均, 再对回答等权), 没有用 DAPO 的 token-level 归约 (1.3.2.1 节 §4). rollout 侧的配置不进 loss: $N=8$, batch 256, mini batch 64, 学习率 $10^{-6}$ 常数, 温度 1.0, 总上下文 16K, 这些是调度参数, 与 loss 的验证无关. 实现里两个容易错的点: 其一, `std` 用总体标准差 (除 $N$) 而非样本标准差 (除 $N-1$), 两者差一个因子 $\sqrt{8/7}\approx1.07$, 优势整体缩放, 等效于微调学习率; 其二, `torch.std` 默认总体标准差, 换手写实现时别把分母写成 $N-1$.

`check_without_model` 不加载任何模型: `new_logp` 与 `old_logp` 取零, 比率恰为 1, 落在未裁剪区, 梯度有闭式解 $-\hat A/(N\cdot T)$, 与 eps 取值无关. 把 `new` 整体加 $\log 1.3$ 或 $\log 0.75$, 对应 token 的梯度应立即变 0, 清单第 2 条由此落地; 把 `rewards` 换成全 1, `group_advantage` 输出全 0, 梯度全 0, 清单第 1 条落地. 梯度对数与手算一的 1.291 和 -0.775 逐格对上, 实现和手算就互为印证.

### 5.2 不依赖模型的验证清单

以下四条只喂合成对数概率与合成奖励, 不需要语言模型, 也不依赖随机种子:

1. 全同组零梯度. 取 `rewards = torch.ones(4, 8)`, 过 `group_advantage` 后应为全 0, 进一步 `justrl_loss` 对任意 `new_logp` 的梯度恒为 0. 这条验证 2.3 的无效组掩码路径, 也验证「全对组不贡献梯度」这一与动态采样相对的设计决定.
2. 裁剪边界位置. 固定 $\hat A=+1$, 扫 $r\in\{1.27, 1.28, 1.29\}$, autograd 给出的 $\partial u/\partial r$ 应在前两点为 1, 第三点跳变为 0; 固定 $\hat A=-1$, 扫 $r\in\{0.81, 0.80, 0.79\}$, 前两点斜率 $-1$, 第三点 0. 这条直接验证 $[0.8, 1.28]$ 两个端点落在实现里.
3. $r=1$ 处的梯度恒等式. 令 `new_logp == old_logp` (即 $r=1$), 损失对 `new_logp` 的梯度应恰为 $-\hat A/(N\cdot T_i)$ 每条回答 (未经裁剪区), 与 eps 取值无关. 这条验证 stop-gradient 接对了位置: 若 old 侧没 detach, 该恒等式立即破坏.
4. mask 不变量. 对任意 padding 位置的 `new_logp` 加一个常数, `justrl_loss` 的返回值应分毫不变. 这条验证 padding 既不进分子也不进分母.

四条全过, loss 侧实现即与配方对齐; 再补一条 rollout 侧的系统级检查: 记录每个 batch 的全同组占比与熵, 对照 2.3 手算的概率公式与图 2 的熵区间. 系统级检查不需要等训练出结果才有意义, 前 100 步的曲线形状 (熵的起点, 占比的初始水平) 就能判断初始条件是否落在论文的温和区间内.

清单的执行顺序也有讲究: 先跑第 1 条和第 4 条 (纯张量操作, 秒级), 再跑第 2 条和第 3 条 (需要 autograd, 分钟级). 前两条挂了说明掩码或归约有错, 后两条挂了说明 clip 或 detach 接错, 按挂的位置直接定位, 比调一通 loss 曲线再回头找快得多. 这个排错顺序对应一个事实: 归约与掩码是结构性错误 (结果整体不对), clip 与 detach 是接线错误 (特定区间不对), 两类错误的症状不同, 检查的次序应该利用这个区别.

## 6. 边界, 定位与选型

### 6.1 不能外推的结论

三条常见外推都不在论文支持范围内. 「单卡可训 7B」: 论文是 32 张 A800-80GB 训 15 天, 与单卡场景无关. 「技巧普遍有害」: 消融只动两个开关, 且第二个开关与长度惩罚纠缠, 被证伪的是这两个开关的叠加, 不是技巧这一大类. 「固定配方换任务仍稳」: 全部是数学规则验证场景, 奖励 hacking 面小, 起点是蒸馏模型; 换 reward model 打分或代码任务, 熵动态与最优裁剪区间都会变. 论文真正支持的范围是: 两个 1.5B backbone, DAPO-Math-17k, 规则验证, 四千步量级, 在这套边界内「固定基线可以长时间平滑训练」.

GRPO (1.3.1.1 节) 定义组优势与 ratio 裁剪, JustRL 保留算法结构, 只固定训练配置. RLOO (1.3.1.2 节) 去掉 importance ratio 与裁剪, 改用 leave-one-out 基线; JustRL 则保留 ratio 与 clip. **这里的简单指减少配置决策, 不表示删去所有机制.** DAPO (1.3.2.1 节) 提供验证器, 数据集与 clip-higher; JustRL 关闭动态采样, token-level loss 和 overlong shaping, 保留 clip-higher, 并延长训练步数.

对社区的直接价值在基线本身. 推理 RL 论文里的对照基线质量参差, 相当一部分复杂方法的收益是相对于一个没被调好的基线报告的; JustRL 把「简单 + 验证过 + 开源 + 四千步」四个条件凑齐, 之后的工作可以拿它当共同参照, 声称超过它之前, 先说明自己加了哪个开关, 治什么病. 这个用法不依赖论文的任何具体数字, 依赖的是它作为参照系的确定性.

更强的验证需要三组补充实验. 多个随机种子可以为平滑曲线给出波动区间; 非蒸馏起点可以分离配方效应与温和初始化; 调高初始温度或换成更难题库, 则能观察固定配方在高熵或高无效组占比下的行为. 这些实验分别检验随机波动, 模型起点和数据难度三个变量.

### 6.2 什么时候照抄, 什么时候逐项决策

这套固定配方适合蒸馏过的推理基座、规则可验证任务、足够跑四千步的算力，以及无效组占比和初始熵都健康的小规模试跑. 条件齐全时可以直接从固定配方起步, 出现问题后按 §4.3 逐项加入技巧并保留消融. 条件不齐时则回到 §2 重选开关: 弱基座先查初始熵, 难题库先估无效组占比, 长输出任务先确定长度口径, reward 容易被 hack 的任务先加 KL 或更换验证器.

训练判断依赖三个信号: 全同组占比 (2.3 的概率公式给出预期区间), 熵区间 (图 2 的 1.0 到 1.6) 和长度 P99 距 15K 上限的余量. 三者都在健康区间时无需增加稳定化组件; 某项越界后, 只打开直接对应的开关. 验收顺序是 §5.2 的四条 loss 不变量, 前 100 步 reward 与熵趋势, 以及 MATH-500 和 AIME24 两个子集的端点. 三层都通过后再运行九基准全量评测.

固定配方也要求固定数据消费口径. Batch 256 指 prompt 数, 每题 8 条 rollout 后实际生成 2048 条回答; mini batch 64 若按 prompt 切分, 每次更新包含 512 条回答, 若框架按回答切分则只有 64 条. 两种实现的梯度方差和一次 rollout 的复用次数不同. 日志中应同时记录 prompt batch、response batch、有效 token 数和每条 rollout 被消费的次数, 这样学习率 $10^{-6}$ 与 clip fraction 才能跨实现比较.

长序列下还要把吞吐变化与配方效果分开. 回答长度增长会降低每步可容纳的样本数, sequence packing 又会改变 padding 比例; 若训练后半程吞吐下降, 固定 optimizer step 并不等于固定 token 预算. 评测 checkpoint 最好同时按 step 和累计有效 token 对齐, 否则更长回答可能仅因消耗更多计算而获得额外训练量, 被误认为固定配方在后期继续提升.

若显存限制迫使 micro batch 改变, gradient accumulation 要同步保持有效 prompt 数与 response 数不变. 日志里同时给出两种计数, 才能确认配置仍与基线一致.

累计步数也要记录.

## 7. 「最小配方」到底最小在哪里

JustRL 的最小化对象是训练过程中的决策数量, 不是把 RLVR 压缩成一条损失. 它仍然需要两份策略状态、同题多回答采样、规则奖励、组内标准化、重要性比、非对称裁剪、长序列并行与分布式 rollout. 省掉的是阶段切换、动态难度筛选、显式长度塑形、KL 项、熵奖励和随训练变化的超参数. 因而「简单」更准确的含义是「固定且可复现」.

把单步数据流列开, 配方共有六段. 第一, 从 DAPO-Math-17k 取 256 个 prompt. 第二, 每题用温度 1.0 采八条回答. 第三, 轻量规则验证器给终局二元分数. 第四, 同题八条分数求均值与标准差, 得到序列级优势. 第五, 优势广播到回答 token, 与新旧策略比一起进入 $[0.8,1.28]$ 的裁剪目标. 第六, 以常数学习率更新, 随后进入下一批. 固定配方的可解释性来自每一步都能单独记录, 不需要先判断当前处于哪个课程阶段.

### 7.1 固定不等于没有时间变化

超参数固定, 数据分布仍会随策略变化. 模型变强后, 同一道题八条回答中正确条数上升; 平均回答长度可能缩短; ratio 分布会随每次 PPO 更新变化; 全错组逐渐迁往混合组, 混合组又逐渐迁往全对组. 固定的是外部控制器, 内部状态仍是一套动态系统.

这一区分很重要. 若训练后期全对组增加, 有效梯度密度会下降, 即使 batch、学习率和温度完全不动, 每步实际更新强度也在变化. 固定超参数因此不等于固定有效学习率. 可定义

$$
\eta_{\mathrm{eff},t}=\eta\cdot
\frac{N_{\mathrm{active},t}}{N_{\mathrm{total},t}},
$$

其中 $N_{\mathrm{active},t}$ 是优势非零的有效 token 数. 这只是诊断量, 不是论文使用的新学习率; 它能说明同样的 $10^{-6}$ 在不同训练阶段对应多少有效梯度.

### 7.2 删除组件也会留下隐式替代物

没有 KL loss, 仍有 PPO clip 约束策略移动; 没有熵正则, 温度 1.0 的采样与 clip-higher 仍保留探索; 没有长度惩罚, 上下文上限与终局正确奖励仍会间接选择长度; 没有动态采样, 固定题库与组内全同零优势仍在自动降低过易和过难题的梯度权重. JustRL 的结果不能解读成这些目标完全无人承担, 更准确的说法是显式组件被已有机制部分代替.

例如全对题的优势为零, 等价于它在该步自动退出更新; 全错题同样退出. 这形成一条隐式的中间难度课程, 只是采样成本已经支付, 题目也没有被数据加载器剔除. 动态采样会补入另一道可能有效的题, JustRL 则接受这部分空梯度, 以换取实现与分布的稳定.

## 8. 奖励、优势与估计误差

规则奖励看似只有 0 和 1, 实际由答案抽取、规范化、等价判断和异常处理组成. `\boxed{}` 是否完整、分数是否约分、集合顺序是否无关、单位是否允许、多个答案如何对齐, 都会改变最终标签. JustRL 使用轻量 DAPO verifier, 没有用符号系统替每个表达式做完整代数证明. 这种选择速度快, 也使误差集中在表达式等价与格式边界.

设真实正确标签为 $Z\in\{0,1\}$, 验证器输出为 $R$. 假阴性率 $\alpha=P(R=0\mid Z=1)$, 假阳性率 $\beta=P(R=1\mid Z=0)$. 模型真实正确率为 $p$, 则观测正奖励率为

$$
\tilde p=p(1-\alpha)+(1-p)\beta.
$$

假阴性会把正确链当作负优势, 假阳性会强化错误链. 对组相对方法, 错误还会经过组均值扩散: 一条假阳性提高自己的优势, 同时压低组内另外七条回答的相对优势. 验证器的一次误判影响整组基线, 风险高于逐样本独立监督.

### 8.1 二值编码不改变标准化优势

现稿用 $\{-1,+1\}$ 手算, 代码实现可能使用 $\{0,1\}$. 对组内标准化, 两者给出相同优势. 令 $R'=2R-1$, 则

$$
\frac{R'_i-\bar R'}{s_{R'}}
=\frac{2R_i-1-(2\bar R-1)}{2s_R}
=\frac{R_i-\bar R}{s_R}.
$$

因此奖励曲线的纵轴会变, 策略梯度的标准化优势不变. 这个结论依赖奖励只有仿射变换且标准差非零. 若加入格式分、长度罚或连续验证分, 排序和间距改变, 优势也会改变.

### 8.2 成功条数决定优势幅度

对 $G$ 条二值奖励, 其中 $k$ 条成功, 成功率 $u=k/G$. 使用总体标准差时, 成功回答优势为

$$
A_+=\sqrt{\frac{1-u}{u}},
$$

失败回答优势为

$$
A_-=-\sqrt{\frac{u}{1-u}}.
$$

$G=8$ 时, $k=1$ 得 $A_+=\sqrt7\approx2.646$, $A_-=-1/\sqrt7\approx-0.378$; $k=4$ 时两侧恰为 $\pm1$; $k=7$ 时镜像翻转. 稀有一侧拥有更大的单样本优势, 多数一侧则靠数量抵消. 在每条回答等权且长度相同的理想条件下, 一组优势之和为零.

回答长度不同后, token 级累计贡献未必抵消. 唯一正确链若长 8000 token, 七条错误链各长 1000 token, token-level 归约会让正侧权重占明显优势; response-level 归约则保持八条轨迹等权. JustRL 沿用默认 GRPO 的响应级处理, 这项选择与奖励公式同样属于配方.

### 8.3 组大小同时控制探索与方差

$G=8$ 不只是显存参数. 单次成功率为 $p$ 时, 混合组概率为

$$
P_{\mathrm{mix}}=1-p^G-(1-p)^G.
$$

$p=0.1$ 时, $G=4$ 的混合概率约 $34.4\%$, $G=8$ 约 $57.0\%$, $G=16$ 约 $81.5\%$. 增大组大小能让低成功率题更容易出现至少一条正确回答, 却线性增加采样量. BroRL 把每题 rollout 推到 512, 选择的是极高组内探索; JustRL 取 8, 把预算分给更多题与更多步.

固定总回答数 2048 时, $G=8$ 对应 256 道题, $G=16$ 只剩 128 道. 前者覆盖更多题目, 后者提高每题发现稀有成功链的概率. 哪一侧更重要由通过率分布决定. 若大多数题 $p$ 位于 0.2 到 0.8, 八条已足够形成混合组; 若大量题 $p<0.01$, 八条几乎总是全错, 增大组或降低题目难度才会带来信号.

### 8.4 组内相关性削弱有效样本量

八条回答共享 prompt、模型与解码设置, 并不独立. 用组内奖励相关系数 $\rho$ 近似, 有效样本量可写成

$$
G_{\mathrm{eff}}\approx\frac{G}{1+(G-1)\rho}.
$$

若 $G=8,\rho=0.2$, 有效样本量只有约 3.33; $\rho=0.5$ 时约 1.78. 温度过低、固定首 token 或高度模板化的蒸馏模型都会提高相关性. 这解释了为什么单纯增加 rollout 数有时收益很小: 新回答只是重复同一种错误路径.

可用答案去重率、推理步骤编辑距离或首个分叉位置估计多样性. 如果全错组的文本也高度相似, 问题在探索; 如果路径很多却全部错, 题目可能确实超出能力. 两种情况都表现为零优势, 对策并不相同.

## 9. clip-higher 与训练稳定性

标准 PPO 裁剪通常给新旧概率比一个对称区间. JustRL 使用 $[0.8,1.28]$, 只放宽正优势方向的上界. 对 $A>0$, 当 $r>1.28$ 后梯度被截断; 对 $A<0$, 当 $r<0.8$ 后梯度被截断. 这里的非对称发生在更新约束, 没有改变奖励和优势.

为什么它可能维持探索? 在组相对训练中, 一条稀有正确链常有较大正优势. 对称裁剪若很早截停这条链, 负样本的压制可能相对更充分, 概率质量向少数已有模式集中. 放宽正侧允许成功链获得更长的更新区间, 尤其当 mini-batch 复用让 ratio 已偏离 1 时. 不过这只是机制解释, 熵变化还受数据、温度和回答长度影响, 不能从裁剪区间单独推出.

### 9.1 一个带长度的裁剪手算

设组内一条正确回答优势 $A_+=2.646$, 长 2000 token; 七条错误回答优势 $A_-=-0.378$, 各长 500 token. 某次更新后, 正确链 token 的平均 ratio 为 1.24, 错误链为 0.82. 在对称 $[0.8,1.2]$ 下, 正确链大部分 token 已触上界; 在 $[0.8,1.28]$ 下仍能更新. 错误链两种配方都未触下界.

若下一次更新把正侧推到 1.30, 负侧压到 0.78, 两侧都进入平台. 此时继续对同一 rollout 做 PPO epoch 不再产生主要梯度, 多次复用数据只是增加计算. clip fraction 按正负优势拆开记录, 能直接看到数据复用何时失效. 固定 mini-batch 配置之所以重要, 正是因为它决定每条样本在离采样策略多远时进入更新.

### 9.2 clip 无法约束的变化

裁剪只作用于采样到的 token. 模型在未采样 token、其它 prompt 或长链后部的概率变化没有直接边界. 参数共享使一次更新可以改变许多未观察位置, 这也是 KL 有时仍有价值的原因. JustRL 在数学蒸馏模型上没有观察到需要 KL 干预的失稳, 并不意味着 clip 与 KL 在所有场景等价.

奖励容易投机时, 策略可能在少数可获分格式上快速集中, 即使每个已采 token 的 ratio 都受 clip 控制, 多步累积仍会远离起点. 监控参考模型 KL、词表熵和答案格式分布可以提前发现. 配方里没有把 KL 加进目标, 诊断日志仍然可以离线计算它.

### 9.3 稳定曲线需要多个尺度

reward 单调上升、熵保持区间、长度趋稳是论文展示的主要证据. 复现时还应记录 ratio 均值与尾部、两侧 clip fraction、梯度范数、全错/混合/全对组比例、验证器异常率. reward 平滑可能来自题目抽样平均, 局部题型已经退化;总体熵稳定也可能掩盖某些 token 位置塌缩. 按题型、长度桶和训练阶段切片, 才能看清稳定性发生在哪一层.

## 10. 数据、模型与计算如何归因

JustRL 的结果由四个对象共同产生: 两个已经蒸馏出推理行为的 1.5B backbone, DAPO-Math-17k 的难度与格式, 规则奖励的低噪声, 以及 32 张 A800 持续约十五天的训练规模. 固定配方证明这些条件组合起来足以得到强结果, 还没有把四项贡献逐个分离.

### 10.1 蒸馏起点提供了什么

DeepSeek-R1-Distill-Qwen-1.5B 与 OpenMath-Nemotron-1.5B 在 RL 前已经会输出较长推理链、遵循答案格式, 也拥有一定数学成功率. 因此八条采样较容易形成混合奖励组, 二元终局奖励可以直接区分好坏. 从普通 base model 起步, 八条可能全错或格式不可解析, 相同优势估计器会长期给零.

检验起点贡献最直接的实验, 是在同架构的 base、SFT、distill 三个 checkpoint 上使用完全相同配方与 token 预算. 报告前一百步全错率、格式通过率、熵与最终零样本准确率. 若只有蒸馏起点稳定, 「简单配方」的适用条件就应明确包含已有推理先验.

### 10.2 数据集提供了什么

DAPO-Math-17k 经过整理, 题目有可验证答案, prompt 格式统一, 难度又能让 1.5B 蒸馏模型产生一定比例的正确链. 这恰好满足 GRPO 的甜点区: 同题组内有差异, 验证便宜, 奖励噪声较低. 数据不过滤不等于数据未经筛选; 训练前的数据构造已经决定了题库边界.

要分离数据贡献, 可保持模型和算法不动, 比较原始题库、按难度匹配的替代题库、随机混合题库与人为提高难度的题库. 关键协变量是训练初期 $p$ 的分布. 若两套数据的题数相同而 $p$ 分布差异很大, 最终结果不能归因于题数或来源名称.

### 10.3 长训练提供了什么

四千多步意味着约九百万条回答级采样, 具体 token 数随长度变化. 固定超参数是否有效, 可能部分来自足够长的训练把早期噪声平均掉. 与只跑数百步的复杂方法比较时, 应对齐累计生成 token、优化 token 与硬件时间, 否则「简单」和「训练得更久」纠缠在一起.

学习曲线可以做面积比较. 在相同累计 token $C$ 下, 记录验证分数 $S(C)$; 最终分数之外再报告达到某阈值所需成本 $C_{50}$、$C_{60}$. 若 JustRL 最终更高却早期更慢, 它适合有充足预算的场景; 若全程占优, 才能称为样本效率也更好.

### 10.4 两个 backbone 证明到哪一步

相同超参数迁移到两个 1.5B 模型, 比单模型结果更有说服力. 不过两者都属于数学推理小模型, 训练任务、奖励、上下文和硬件一致. 这证明配方对两个相近起点具有一定稳健性, 尚未覆盖参数规模、架构族、语言、代码执行或开放式评分的变化.

进一步外推至少需要三条轴: 0.5B 到 7B 的规模轴, base 到 distill 的初始化轴, 数学到代码或工具使用的任务轴. 每条轴只改一个变量, 才能判断哪个条件触发了 KL、动态采样或长度控制的必要性.

## 11. 与 GRPO、DAPO、GHPO 的坐标

JustRL 不是与 GRPO 并列的新优势估计器, 它是一套以 GRPO 为内核的训练配方. GRPO 决定同题分组、优势标准化和 PPO 式裁剪; JustRL 决定数据不动态过滤、训练不分阶段、学习率与采样温度固定、目标中不加 KL 和熵项, 并保留 clip-higher. 一个是算法骨架, 一个是经过长程验证的开关组合.

| 方法 | 主要改动位置 | 是否改变采样题目 | 是否改变 prompt | 是否改变损失/裁剪 | 核心目标 |
|---|---|---|---|---|---|
| GRPO | 优势与代理目标 | 否 | 否 | 是 | 用组内相对奖励免去 critic |
| DAPO | 数据、裁剪、归约、长度 | 是 | 否 | 是 | 提高有效样本密度并稳定长程训练 |
| GHPO | 难度路由与提示 | 视实现而定 | 是 | 内层可不变 | 把全零题搬回可学习区间 |
| JustRL | 全流程配置 | 否 | 否 | 保留 clip-higher | 用固定基线检验复杂组件是否必要 |

### 11.1 与 DAPO 的继承和删减

JustRL 使用 DAPO-Math-17k、轻量验证器与 clip-higher, 同时关闭 DAPO 的动态采样、token-level policy gradient loss 和 overlong reward shaping. 它是在 DAPO 组件上做受控删减, 其中唯一保留的稳定化技巧 clip-higher 也来自前一套配方的经验.

动态采样的分歧最清楚. DAPO 丢弃全对与全错组, 重新补题直到收集足够有差异的组; JustRL 让它们留在 batch 中贡献零梯度. 前者每个优化步拥有更稳定的有效样本数, 后者每步的数据消费与调度更确定. 当题库难度适中、全同组少时, 补采收益很小; 当大部分题全错时, JustRL 会浪费大量 rollout.

token-level loss 的分歧落在长度权重. DAPO 让所有有效 token 等权, 长回答因 token 多而贡献更大; 默认 GRPO 常先对每条回答平均, 长短回答等权. JustRL 的训练中回答长度从七八千下降到四五千, 归约方式会影响这条变化的梯度解释. 将 DAPO 的归约加回时, 必须单独报告, 不能把结果归给动态采样或长度惩罚.

### 11.2 与 GHPO 的互补和冲突

GHPO 专门处理原题全零组: 先探测, 再添加真值解答前缀重采. JustRL 接受全零组的零梯度. 当全零率低时, JustRL 的固定路径更省; 当全零率高且有可信过程轨迹时, GHPO 可以提高有效梯度密度. 两者的选择取决于数据难度相对模型能力的位置.

组合也可行: 保留 JustRL 的常数学习率、无 KL、无熵项和 clip-higher, 只给全零组加 GHPO 路由. 但这会破坏「每题八条、每步固定采样量」的成本口径, 也改变最终 prompt 分布. 比较时需按总生成 token 对齐, 并在零提示验证集上确认收益迁回独立能力.

一个具体反例能说明冲突. 若原题单次成功率 $p=0.15$, $G=8$ 时全零概率约 $27.2\%$. GHPO 会给四分之一以上题目追加至少一轮采样; JustRL 则把这些预算用于更多训练步. 若提示带来的迁移弱, 额外采样不如直接推进下一批. 若 $p=0.001$, 原题几乎必然全零, JustRL 在该题上长期无信号, GHPO 才有明显作用空间.

### 11.3 与 GSPO、GMPO、GDPO 的组合顺序

GSPO 改变重要性比和裁剪的粒度, GMPO 改变组内优势聚合, GDPO 关注难度或组贡献权重. 它们都可能替换 JustRL 的内层估计器, 但替换后已经不再是原版固定配方. 最干净的实验顺序是先复现 JustRL, 每次只换一层, 其余数据、采样量和学习率保持一致.

序列级裁剪可能更适合长回答, 也可能让一条回答中少数关键 token 的变化被平均. 稳健组基线可能降低「一条成功七条失败」的极端优势, 也可能削弱稀有正确链的学习速度. 难度加权可以补偿全错题无信号吗? 如果奖励仍全同, 任何有限权重乘零优势仍是零; 它只能重新分配已有信号, 无法凭空制造对比. 这些机制需要按操作层级判断, 缩写相近并不代表功能重叠.

## 12. 为什么简单配方可能有效

第一条原因是问题与奖励高度匹配. 数学题有明确终局答案, 二元验证便宜, 同题多样采样能提供相对信号. 奖励不需要训练模型, 也没有偏好标注者之间的尺度差异. 当环境已经给出清楚反馈, 复杂 reward shaping 的边际价值自然降低.

第二条原因是起点已经进入可学习区间. 蒸馏模型能生成格式正确、偶尔答对的长推理链, GRPO 从第一批就能看到正负样本. RL 负责重新分配已有行为的概率, 而不是从零发现完整推理语言. 这降低了课程、过程奖励和强探索控制的必要性.

第三条原因是固定配置避免了控制器互相干扰. 动态温度改变采样分布, 动态过滤改变题目分布, 长度惩罚改变奖励, 阶段切换改变上下文与预算. 多个控制器同时根据训练曲线响应时, 一个控制器造成的变化可能触发另一个控制器, 形成难以归因的反馈环. 固定配方把这类反馈拿掉, 优化器只需适应策略自身变化.

第四条原因是规模平滑了噪声. 每步 256 道题、每题八条回答, 跨四千余步持续训练, 单批异常对总轨迹的影响较小. 大 batch 和长训练不能消除系统偏差, 却能降低随机奖励组合与题目抽样带来的波动. 很多短跑实验中需要的保护措施, 在稳定大样本平均下可能不再触发.

第五条原因是 clip-higher 并没有真的把稳定机制全部删光. 它保留了 PPO 裁剪, 又对正优势放宽上界, 为稀有正确链留出更新空间. 这项机制可能承担了部分熵控制与探索保护. 因而论文支持的是「一个关键稳定器加固定长跑」, 不是完全裸奔的策略梯度.

### 12.1 奥卡姆剃刀的训练版本

组件越多, 超参数搜索空间越大. 假设有五个二元开关, 就有 $2^5=32$ 种组合; 再给每个开关两个强度, 组合数继续扩大. 论文往往只报告少量路径, 最优组合可能带有验证集选择偏差. 固定基线减少自由度, 同一套超参数迁移到两个 backbone, 也降低了针对单模型调参的嫌疑.

简单并不会自动带来正确. 它的优势是失败更容易定位: reward 不涨时, 先查验证器、组内差异、ratio 和优化器; 长度失控时, 先看截断与长度分桶; 熵塌缩时, 看裁剪和采样分布. 动态组件少, 日志变化的可能来源也少.

### 12.2 隐式课程已经存在

设题目 $q$ 的当前成功率为 $p_q$. 它产生混合组的概率为 $1-p_q^G-(1-p_q)^G$, 在 $p_q=0.5$ 附近最大, 在 0 和 1 附近趋近零. 因而固定均匀采题经过组相对优势后, 梯度自动集中于中等成功率题. 这是一条由估计器产生的隐式课程.

随着模型变强, 每道题的 $p_q$ 上升, 梯度峰值沿题目难度移动. 容易题变成全对后退出, 原本困难题进入混合区后接棒. 若题库覆盖连续难度, 这条课程可以平滑运行, 无需人工阶段. 若难度出现断层, 大量题从全对直接跳到几乎全错, 隐式课程中间没有桥, 固定配方就会停滞.

### 12.3 常数学习率也有隐式退火

学习率固定为 $10^{-6}$, 但有效梯度会随全同组增加、clip 命中和回答长度变化而缩小. 后期更多容易题全对, 部分 token 超出裁剪区, 平均更新幅度自然下降. 这形成一种数据驱动的隐式退火. 它可能解释为何没有显式 decay 仍能平滑收敛.

这项解释可以证伪: 记录每步参数更新范数、有效 token 比例和 clip fraction. 若学习率固定而更新范数确实随训练下降, 隐式退火存在; 若更新范数保持不变, 收敛更可能来自目标局部形态. 不应只从验证分数趋缓反推.

## 13. 不可外推处与反例

### 13.1 弱基座上的零信号

设弱基座对训练题平均成功率只有 $p=0.002$, $G=8$. 至少一条成功的概率为 $1-0.998^8\approx1.59\%$. 256 道题一批, 期望只有约四道题出现成功, 其余大多全错. 即使这四组提供强正优势, 有效批也太小, 梯度方差巨大. 延长到四千步会反复支付无效采样, 未必能跨过冷启动.

这时课程数据、SFT 预热、GHPO 提示或更大组采样都有明确作用对象. JustRL 的成功不能作为删除这些组件的理由, 因为初始成功率条件已经改变.

### 13.2 奖励可投机的任务

开放问答、摘要或对话常用模型奖励, 分数会受文风、长度和模板影响. 策略可能学会触发奖励器偏好, 训练 reward 上升而真实质量下降. KL、参考模型约束、多奖励器或人工审计在这里承担防投机作用. 数学规则验证中「答案对不对」相对坚硬, 这项优势无法直接带到开放任务.

代码执行奖励也并非天然安全. 模型可以利用脆弱测试、超时边界或解析器漏洞; 某些题只有少量公开测试, 过拟合测试并不等于程序正确. 简单终局奖励仍可用, 前提是测试覆盖与沙箱安全经过审计.

### 13.3 长上下文与截断

JustRL 给 prompt 1K、response 15K 的预算. 如果任务本身需要 8K 输入, 原配置无法直接容纳; 若强行压缩 response, 长推理更容易截断并被判错. 截断产生的零奖励会把长度约束误写进能力信号. 工具轨迹或证明任务经常超过 16K, 显式长度处理可能重新变得必要.

手算一个边界. 一组八条回答中, 四条推理正确但在输出答案前被 15K 截断, 四条自然结束且答案错误, 验证器给全零, 整组无梯度. 增加上下文即可救回, 更强裁剪或更长训练都无效. 因而全错组必须按结束原因拆分.

### 13.4 多语言与格式差异

固定后缀要求最终答案放在 `\boxed{}` 中, 对英文数学数据很自然. 多语言题目、带单位答案、证明题或选择题可能需要不同模板. 格式解析失败会被当成能力失败, 起始全错率随之升高. 在迁移配方前, 先用少量人工正确答案测试验证器召回率, 比直接启动长跑更便宜.

### 13.5 大模型上的更新尺度

同样的 $10^{-6}$ 学习率、batch 256 与 clip 区间在 1.5B 上稳定, 不保证 32B 或混合专家模型也合适. 参数化、梯度噪声尺度、并行策略与激活分布都会变化. 大模型单条 rollout 成本更高, 四千步也未必现实. 「超参数跨两个 1.5B backbone 迁移」与「跨规模迁移」是两种证据.

### 13.6 多随机种子的空缺

一条平滑训练曲线不能给出失败概率. 若同配方十次里九次稳定, 结论很强; 若恰好展示唯一成功 run, 含义不同. 长程 RL 成本高, 多 seed 难做, 但至少可以对前几百步跑多个 seed, 测量熵、reward、长度和全同组的分叉程度. 最终 checkpoint 也应报告评测采样方差, 避免把生成随机性当作训练提升.

## 14. 可证伪的消融设计

JustRL 最有价值的用途是作为受控基线. 新组件加入后, 问题不该只写成「分数是否更高」, 还要写明它准备修复哪条异常曲线、付出多少额外计算、是否引入新的分布变化. 下面的消融都能在结果不符合预期时推翻对应解释.

### 14.1 固定步数与固定 token 双重对齐

长度惩罚会缩短回答, 动态采样会增加补采, 强验证器会增加判定成本. 只按 optimizer step 对齐, 各组实际计算不同. 每项消融至少给两张横轴: step 与累计生成 token;条件允许时再加 GPU 小时. 若某组件按 step 更快、按 token 没有优势, 它可能只是改变了每步预算.

具体可以设置四组: 原始 JustRL; 加动态采样; 加 overlong shaping; 加二者. 所有组先跑固定 500 步, 再在相同累计 token 处截取 checkpoint. 报告九基准平均、全同组率、平均长度、有效 token 比例和成本. 交互项用

$$
\Delta_{\mathrm{int}}=
S_{\mathrm{both}}-S_{\mathrm{dynamic}}-S_{\mathrm{length}}+S_{\mathrm{base}}
$$

计算. $\Delta_{\mathrm{int}}$ 显著非零, 说明两个组件不能靠单项收益简单相加.

### 14.2 clip-higher 的真正贡献

比较 $[0.8,1.2]$、$[0.8,1.28]$、$[0.8,1.4]$ 三个上界, 其余不动. 每组记录正优势上界命中率、负优势下界命中率、策略熵和稀有成功组的保留率. 如果 1.28 的收益来自给正样本更多更新空间, 它应降低正侧过早裁剪, 同时保持验证性能. 上界继续放到 1.4 若导致 KL 或熵异常, 可以看到稳定与学习速度的折中.

再做一个按优势幅度分桶的分析. $k=1$ 的组拥有最大正优势, 理论上最受上界影响; $k=4$ 的组优势对称, 影响应更小. 若 clip-higher 的收益主要出现在 $k=1$ 与 $k=2$ 的组, 机制解释得到支持. 若各桶完全一致, 收益可能来自其它实现差异.

### 14.3 常数学习率与日程

比较常数 $10^{-6}$、线性 warmup 后常数、余弦衰减三组, 对齐总 token. 常数配方的假设是初始蒸馏模型已经稳定, 无需 warmup; 后期有效梯度自然退火, 无需 decay. 若 warmup 只改善前几十步而最终相同, 可以继续保留简单设置. 若某个 backbone 初期出现 ratio 尾部或梯度尖峰, warmup 可能有明确价值.

评价日程不能只看末点. 画验证分数、更新范数和有效 token 比随累计 token 的曲线. 余弦衰减末期分数更稳却提前停止学习, 与防止塌缩是两回事. 常数学习率后期仍涨分且无尖峰, 才支持「长跑不需调度」.

### 14.4 数据难度扫描

按照初始模型的 pass@8 把题目分为全错、低成功、混合、高成功和全对五桶, 从每桶等量采题构造训练集. 分别训练短程模型, 测量每百万 token 的有效组数与验证增益. 预期中间桶最适合原版 JustRL; 全错桶需要更多探索或支架; 全对桶几乎没有梯度.

这项实验能直接检验「数据不过滤」的条件. 若均匀原始数据已经让多数预算落在中间桶, 动态过滤的收益有限. 若原始数据两端占比很高, 不过滤仍获胜, 就需要寻找调度开销、分布偏移或难题长期收益等其它解释.

### 14.5 验证器强度与熵塌缩

论文消融中, 加入更强验证器与长度惩罚后性能下降, 但两个变量若同时改变, 无法单独归因. 应构造二乘二实验: 轻量/强验证器乘以无/有长度惩罚. 四组使用同一 rollout, 尽可能离线重打 reward, 可以减少采样差异.

对验证器分歧样本做人工审计. 强验证器若主要修复轻量规则的假阴性, 理应恢复正确链; 若它把开放形式的答案判得更严格, 可能降低奖励密度. 熵塌缩究竟由奖励更尖锐还是长度项推动, 二乘二结果会给出答案. 不能把组合消融直接写成「强验证器有害」.

### 14.6 组大小与题目覆盖

固定每步 2048 条回答, 比较 $(B,G)=(512,4),(256,8),(128,16)$. 三组每步回答数一致, prompt 覆盖与每题探索不同. 再按累计 token 对齐, 测量混合组数量、独立题目数、梯度方差和验证分数.

若训练题多数通过率适中, $G=4$ 已能制造对比, 更大 $B$ 可能更好; 若成功链稀有, $G=16$ 可能救回更多题. 这个实验也能判断 BroRL 式大组采样与 JustRL 式广覆盖之间的分界. 结果应按初始 $p$ 桶拆分, 总平均会掩盖两类题的相反偏好.

### 14.7 蒸馏先验的必要性

选同一 Qwen 架构的 base、instruct、reasoning-distill 三个起点, 固定数据与训练预算. 第一阶段只跑 100 步, 观察格式成功率、全错率和长度; 第二阶段对仍有稳定信号的模型跑到 1000 步. 如果 base 在前百步几乎全零, 没必要盲目烧到四千步, 结论已经显示配方缺少冷启动机制.

还可以把 distill 模型的输出格式 SFT 单独施加到 base, 区分「会按格式回答」与「已有推理路径」两种先验. 格式 SFT 若降低解析失败却仍无正确链, 表明核心条件是推理能力; 若训练随即启动, 格式才是主要门槛.

## 15. 官方实现核对与复现审计

官方仓库公开训练、评测、数据说明与模型链接, README 把配方概括为标准 GRPO、二元结果奖励、单阶段、固定超参数、DAPO-Math-17k、16K 上下文和 clip-higher. 这些内容与论文主线一致. 真正复现时, README 的摘要不足以替代配置文件, 因为 batch 的计量单位、优势标准差实现、rollout 后端和验证器版本都会改变数值.

### 15.1 配置要冻结成一份清单

模型侧记录精确 checkpoint revision、tokenizer revision、聊天模板与是否启用远程代码. 数据侧记录数据集 commit、去重版本、prompt 后缀和 train split 哈希. 采样侧记录温度、top-p、最大 prompt/response token、每题回答数和随机种子. 优化侧记录学习率、optimizer 参数、train/mini/micro batch、PPO epoch、裁剪上下界、优势归一口径、KL 与熵系数. 系统侧记录 veRL commit、推理后端、并行策略、GPU 数量与精度.

缺少任一项都可能出现「配置看似相同, 实际训练不同」. 例如 tokenizer 更新会改变 15K response 边界;聊天模板多一个 assistant prefix 会改变格式成功率;标准差使用 $G-1$ 会缩小优势;mini batch 若按 response 而非 prompt 计数, 数据复用和 ratio 漂移都会变化.

### 15.2 一次 rollout 的数据谱系

每条回答至少保存 `prompt_id`、`group_id`、模型版本、采样参数、原始文本、token ids、old log-prob、终止原因、解析答案、奖励、优势、有效 mask 与最终 loss. 同题八条通过 `group_id` 聚合, 任何跨题混组都会破坏优势估计.

验证器应同时保存原始解析结果和最终二元分数. 只留 0/1, 后续无法区分数学错误、格式失败、超时与解析异常. 长程训练中验证器代码升级也必须改变版本号, 否则同一 reward 曲线混有不同判定规则.

### 15.3 batch 语义的手算核对

若 train batch 256 表示 prompt, 每题八条, 一轮 rollout 有 2048 responses. PPO mini batch 64 若同样按 prompt, 每个 mini batch 含 512 responses, 四个 mini batch 覆盖整轮数据. 若 micro batch per GPU 为 1 prompt, 32 张 GPU 同时处理 32 prompts, 一个 mini batch 需要两次累积. 这套算术应与运行日志中的 optimizer step 数对上.

如果框架把 mini batch 64 解释为 responses, 一个 mini batch只有 8 道题等价量, 一轮要 32 个 mini batch. 梯度方差、通信次数与样本进入更新的时刻全部改变. 复现脚本必须打印展开后的 prompt 数、response 数和 token 数, 不能只打印配置键名.

### 15.4 规则验证器的单元测试

至少准备五类样例: 整数与小数等价, 分数约分, 多个 `\boxed{}`、集合顺序、非法或空输出. 每类包含应判对与应判错的成对样本. 再加入超长输出尾部缺失、LaTeX 不闭合、答案带单位和科学计数法. 单元测试的期望由人工确认, 随验证器版本一起保存.

训练前用 backbone 在一小批题上采样, 人工审计验证器的假阳性与假阴性. 假阳性优先级更高, 因为它会强化错误轨迹;假阴性提高全错率, 主要损害样本效率. 两者都应按答案类型分桶, 总错误率低也可能在某类题上集中失败.

### 15.5 评测与训练必须隔离

论文评测采用温度 0.7、top-p 0.9、部分基准四次采样、部分三十二次采样, 输出上限 32K, 并使用额外模型验证器处理规则判定的假阴性. 训练则温度 1.0、输出上限 15K、轻量验证器. 两套配置承担不同目的, 不能共用一份默认参数.

评测结果应保存每道题的全部采样与判定详情. Pass@1 在多次随机采样下是样本均值, 仍有标准误. 若某基准题数为 $n$, 单题平均正确率方差还受同题采样相关性影响, 简单把所有回答当独立样本会低估误差. 至少以题为单位 bootstrap, 给出置信区间.

### 15.6 断点续训的隐形变化

四千步训练很可能经历断点恢复. 恢复时要同时加载策略、优化器、学习率状态、全局步数、数据迭代位置和随机数生成器. 只加载模型会重置 AdamW 动量, 曲线可能在断点处出现短暂变化;重置数据位置会重复消费一段题目;重置采样种子会改变后续 rollout.

固定配方特别适合作为断点审计对象: 超参数没有主动变化, 曲线在恢复点突变通常意味着状态遗漏或系统变化. 日志标出每次恢复、代码 commit 与硬件变更, 后续才能解释异常.

## 16. 逐步手算一个完整更新

考虑一道题采八条回答, 奖励为 $[1,0,0,0,0,0,0,0]$. 总体均值 $\bar R=1/8=0.125$, 总体标准差

$$
s=\sqrt{\frac{(1-0.125)^2+7(0-0.125)^2}{8}}
=\sqrt{0.109375}\approx0.3307.
$$

正确回答优势为 $0.875/0.3307\approx2.646$, 每条错误回答优势为 $-0.125/0.3307\approx-0.378$. 假设正确回答只有三个有效 token, 新旧 ratio 分别为 $[1.10,1.25,1.30]$. clip-higher 上界为 1.28, 三个 token 未取负号前的代理值分别是

$$
1.10\times2.646=2.911,
\quad
1.25\times2.646=3.308,
\quad
1.28\times2.646=3.387.
$$

第三个 token 的原始值 $1.30\times2.646=3.440$, min 结构取裁剪值 3.387. 这条回答按长度平均得到约 $(2.911+3.308+3.387)/3=3.202$.

再取一条错误回答三个 token, ratio 为 $[0.90,0.82,0.75]$. 负优势下, PPO 的裁剪方向要小心: 当 ratio 低于 0.8, min 与负数相乘后会选择更保守的边界. 三项有效代理分别约为

$$
0.90\times(-0.378)=-0.340,
\quad
0.82\times(-0.378)=-0.310,
\quad
0.80\times(-0.378)=-0.302.
$$

第三个 token 的原始值是 $-0.284$, 但裁剪分支为 $-0.302$, min 取后者; 对最大化目标而言, 继续降低错误 token 概率不会再获得更高目标. 实现最终对代理目标取负做梯度下降.

### 16.1 把八条回答合起来

假设七条错误回答都有相同三 token 代理均值 $(-0.340-0.310-0.302)/3\approx-0.317$. 组平均代理为

$$
\frac{3.202+7\times(-0.317)}{8}\approx0.123.
$$

这个正值表示当前 batch 在给定 ratio 下的裁剪代理, 与准确率口径不同. 如果所有 ratio 都回到 1, 正确回答贡献 2.646, 七条错误合计约 $-2.646$, 组平均为零; 各回答的 log-prob 导数不同, 梯度依然存在. 只有全同奖励组的优势全零时, 策略梯度才随之归零.

### 16.2 padding 与长度

若正确回答实际长 3000 token, 错误回答长 500 token, response-level 平均仍让八条回答等权. 每条先除自身有效长度, padding 不进入分母. 若误用统一最大长度 3000 做分母, 短错误链权重会缩小到六分之一, 正侧相对占优, 训练行为悄悄变成长度加权. 这类 bug 不会报错, 只能靠 mask 不变量与合成长度测试发现.

### 16.3 多 mini-batch 后的 ratio

rollout 时所有 ratio 为 1. 第一 mini-batch 更新模型后, 尚未消费的数据在当前策略下 ratio 开始偏移;越晚进入的 mini-batch, 偏移通常越大. 如果数据只消费一个 PPO epoch, 每条回答只进入一次 loss, 但顺序仍影响裁剪命中. 随机打乱 group 顺序可以降低系统性偏差, 同组八条则必须保持优势与回答对应.

ratio 分布应按 mini-batch 序号记录. 第一批接近 1, 后续逐渐扩散属于预期;第一批已经远离 1, 指向 old log-prob 或策略版本错位;末批大部分 token 被裁剪, 则要检查 mini-batch、学习率与数据复用次数.

## 17. 验收标准与停止条件

开始长跑前, 先完成三层短测. 张量层验证优势、裁剪、mask 和 detach;小模型层用几十道题确认生成格式与 verifier;系统层跑十到一百步确认 group 组装、old log-prob、断点恢复和日志字段. 这些检查成本远低于四千步后发现配方没有真正复现.

训练健康时, reward 在较长窗口内上升, 全错组逐步下降, 全对组缓慢上升, 混合组保持足够占比;熵在稳定区间波动, 长度分布远离硬上限, 正负裁剪命中率没有长期饱和. 单项短暂尖峰可以由题目批次造成, 多项同时异常才需要停机检查.

应立即暂停的信号包括: verifier 异常率突然上升;大部分回答达到 15K 上限;old/new ratio 在更新前就偏离 1;同一 group 混入不同 prompt;reward 上升而人工正确率下降;断点后优化器状态缺失. 这些属于数据或实现故障, 延长训练无法修复.

需要观察后再决策的信号包括短期 reward 平台、熵缓慢变化、平均长度波动和全对组增加. 平台可能来自题目抽样, 全对组增加也可能是能力增长. 用固定验证集和滑动窗口判断, 避免一次抖动就加新组件.

最终停止可以同时参考验证分数斜率与累计 token. 连续多个评测点提升小于预设阈值, 有效组比例持续下降, 且更难保留集没有继续增长时, 继续训练的边际回报已经很低. 对新模型可按这套条件停机, 论文的四千步则保留为复现参照.

JustRL 给出的经验是先让一个清楚、稳定、训练足够久的基线跑到能力边界, 再要求每项复杂度用受控消融证明价值. 对数学蒸馏小模型, 这套基线恰好很强; 对其它场景, 它更适合作为一把标尺. 标尺本身越确定, 新方法的收益越不容易被弱基线、额外算力或评测差异冒领.

## 18. 从异常曲线反查原因

训练曲线异常时, 最危险的做法是立刻加入一个名字熟悉的稳定化技巧. 同样的 reward 平台可能来自零优势、验证器错误、ratio 被裁剪或学习率过低; 同样的熵下降可能代表能力收敛, 也可能代表格式捷径. JustRL 的组件少, 很适合把异常拆成一条诊断链.

### 18.1 reward 从第一步就不涨

先把 reward 拆成格式可解析率与答案正确率. 格式率接近零时, 规则验证器没有可靠输入, 应检查聊天模板、后缀指令与 tokenizer;格式正常而正确率接近零时, 再看每组是否全错. 如果九成以上组全错, 当前模型与数据难度不匹配, 优化器没有足够信号. 如果混合组不少却 reward 不涨, 才轮到优势、loss mask、old log-prob 和梯度更新.

可以构造一个人工组验证端到端链路: 同一道题放入一条已知正确回答和七条已知错误回答, 跳过生成, 直接送入 verifier 与 loss. 正确回答应得到正优势, 错误回答得到负优势, 一次小学习率更新后正确回答 token 的平均 log-prob 上升. 这条测试把模型能力从训练管线中拿掉, 能快速定位接线问题.

### 18.2 reward 上涨而验证分数不涨

第一种可能是训练题记忆. 比较训练集、严格去重新题与题面改写集;只有训练集上涨, 表明泛化有限. 第二种可能是 verifier exploitation. 人工抽查高奖励回答, 看它们是否真正正确. 第三种可能是评测协议错位: 训练输出 15K、评测 32K, 温度和判定器又不同, checkpoint 的相对排序可能变化.

还要检查 reward 的聚合口径. 若训练曲线只对有效组求均值, 全错组增加也不会拉低曲线;若对全部回答求均值, 口径又不同. 日志必须同时给总体正确率、有效组内正确率和三类组占比. 单条 reward 曲线不足以说明整体能力.

### 18.3 熵快速下降

先确认熵的定义与统计位置. token 熵是在全部词表上求、只在 completion 上平均, 还是只统计采样 token 的负 log-prob? 三种数值不可直接比较. 再按 token 位置画曲线: 开头格式 token 熵下降通常正常, 推理主体与答案位置同时塌缩才值得警惕.

若正优势上界命中率很高、负优势下界命中率较低, 可以检查 PPO 数据复用与 mini-batch 顺序; ratio 漂移过快时, 降低学习率或减少 epoch 比盲目加熵奖励更直接. 若熵下降伴随 reward 上升、验证分数上升和回答多样性仍健康, 它也可能只是策略学会了更确定的正确路径.

### 18.4 长度持续触顶

把达到 15K 上限的回答分成三类: 推理仍在继续、重复循环、已经得到答案却未正确结束. 第一类需要更长上下文或更高效推理;第二类指向生成退化;第三类多半是 EOS、模板或停止条件问题. 同一个 overlong penalty 对三类回答施加相同惩罚, 会把不同病因混在一起.

检查长度与正确率的二维分桶. 若最长桶正确率最高, 强行缩短可能伤害难题;若最长桶几乎全错且重复度高, 长度控制有清楚目标;若中等长度最好, 可以研究软惩罚或截断感知奖励. 论文消融里长度惩罚降低性能, 说明其设置下长链仍承载有用探索, 不能据此否定所有长度控制.

### 18.5 梯度范数尖峰

尖峰可能来自一条极端长回答、单成功组的高优势、ratio 尾部、混合精度溢出或数据异常. 按 group 计算梯度贡献近似值, 找出尖峰 batch 中的主导题. 如果总由 $k=1$ 组触发, 可以比较标准差平滑、优势裁剪或更大组;如果来自超长回答, 先核对归约与 mask.

clip 只能截策略比目标, 不会直接限制所有参数梯度. 即使代理目标被裁剪, 共享层的梯度叠加仍可能很大. 梯度裁剪、数值精度和优化器状态属于另一层稳定机制, 官方配置如何设置应从实际脚本确认, 不宜由 PPO clip 名字推断.

### 18.6 训练吞吐突然下降

平均与 P99 回答长度需要和 padding 比例、推理后端队列、verifier 延迟一起检查. 少量接近 15K 的长尾会拖住同步 batch, 平均长度看起来仍正常. 每条 rollout 的完成时间能显示个别长题是否支配整批耗时.

吞吐下降还会改变实验公平性. 固定训练天数时, 长尾更多的配置完成步数更少;固定步数时, 它消耗更多 GPU 小时. 因而所有涉及长度的消融都要同时报告 token 与时间, 否则收益可能来自多跑或少跑.

### 18.7 全对组快速增加

这通常意味着模型掌握了题库中的容易部分, 同时有效梯度密度下降. 可检查训练题与验证题的差距: 两者同步上涨属于正常学习;训练题迅速饱和、验证停滞则可能记忆. 继续均匀采样会把越来越多预算花在零优势容易题上, 动态采样或扩充难题开始有明确作用空间.

不过切换数据会改变训练分布. 一个稳妥实验是在原配方旁开新 run, 只替换已连续多次全对的题, 与继续长跑基线按 token 对齐. 若新 run 显著更好, 数据更新有证据;若没有, 全对题可能仍通过共享参数或采样分布提供了间接稳定作用.

### 18.8 全错组在后期反弹

模型总体分数上涨时, 全错组反弹可能来自题目批次更难, 也可能是灾难性遗忘或探索下降. 使用固定探针集消除批次差异, 再按题型比较早晚 checkpoint. 若旧题退化, 检查 KL 漂移、熵与数据覆盖;若只是新批次更难, 训练本身未必异常.

验证器版本变化也会制造反弹. 长程训练期间任何规则更新都应离线重算一段历史样本, 建立旧新 reward 映射. 直接把两个版本的曲线拼接, 会把判定口径变化误认为策略变化.

### 18.9 两个 backbone 表现分叉

相同超参数在两个模型上总体有效, 不代表每项动态完全一致. 若一个模型长度收敛、另一个持续增长, 先比较初始回答长度与 tokenizer;若一个全错率高, 比较数据与其预训练数学覆盖;若 clip fraction 差异大, 比较 old/new ratio 与梯度尺度.

相同配置是一项实验控制, 并不要求所有内部指标重合. 分叉恰好能帮助定位配方依赖的初始条件. 对每个 backbone 单独给出起点统计, 比只报最终平均更能支持跨模型稳健性的主张.

**一张诊断顺序.**

排查顺序可以固定为五步: 数据与模板字节一致性, verifier 人工样例, group/优势/mask, old/new 版本与 ratio, 熵/长度/有效组. 前四步属于正确性, 第五步才进入算法选择. 正确性尚未通过时增加算法开关, 只会让错误更难定位.

每次修改只动一个变量, 保存修改前后的短程曲线与固定探针结果. 如果改动没有修复它针对的异常, 就撤回而非继续叠加补丁. 这正是 JustRL 作为基线最实用的地方: 它让每一次复杂化都承担清楚的举证责任.

还有一类问题不会立刻出现在曲线上: 数据重复. DAPO-Math-17k 规模不大, 四千步、每步 256 个 prompt 意味着累计抽取超过一百万次 prompt, 每道题平均会被访问许多次. 即使每次 rollout 都不同, 模型仍可能逐渐记住题目结构与答案. 训练增益中有多少来自同题反复强化, 有多少迁移到新题, 需要严格去重的保留集判断.

可以按题目文本、公式结构和答案三层去重. 只做字符串去重抓不到换数字、换变量或翻译后的近重复;只按答案去重又会误伤大量共享数值的独立题. 更可靠的做法是先用规范化文本和公式树筛候选, 再人工审计相似度最高的一小部分. 去重结果应与评测分数一起保存, 因为不同规则会改变 benchmark 难度.

训练数据重复也会影响全同组解释. 某题早期是混合组, 多次访问后变成全对, 既可能是掌握了通用方法, 也可能是记住该题. 固定探针集应同时包含训练原题、同模板换数字题和结构相似的新题. 三条曲线一起上涨, 才能支持技能迁移;只有原题上涨, 则隐式课程正在把记忆过的题移出梯度, 未必提高一般推理.

计算归因还应区分 rollout 与优化. 长回答主要增加生成成本, 大模型反向传播主要增加优化成本. JustRL 在 1.5B 上 rollout 占比与更大模型不同, 因而「省一半 token」不一定等于「省一半 GPU 小时」. 对比方法若使用不同推理后端、并行策略或序列打包, token 估算更不能直接代表实际成本.

一份完整成本表至少列出生成 token、参与 loss 的 completion token、prompt prefill token、验证器调用、策略前向、反向以及空闲等待. 动态采样会提高生成与验证成本, token-level loss可能改变有效训练 token, 强验证器还可能占用额外 GPU. 把这些项目拆开, 才能回答复杂组件究竟把预算花在哪里.

checkpoint 选择也会改变结论. 若每隔若干步在验证集上挑最高点, 报告的最终分数含有选择收益;另一方法只报末步, 比较会偏. 应同时给末步 checkpoint、预先规定步数 checkpoint 与最佳验证 checkpoint, 并说明选择集是否与九个测试 benchmark 隔离. 固定配方减少了训练中人工干预, checkpoint 选择仍可能引入事后自由度.

JustRL 的「无需干预」最好落实为可审计协议: 开跑前固定数据、超参数、最大步数、评测间隔和停止规则;训练中只因硬件或确定的实现故障暂停;最终按照预先写好的规则选择模型. 做到这一点, 平滑长程曲线才真正证明固定配方能独立运行, 而不是依赖研究者在后台不断挑选.

复现报告还应保留失败 run. 训练中途发生熵塌缩、长度爆炸或 reward 回落的记录, 对判断稳定概率比单条成功曲线更有价值. 失败由实现错误导致, 就写清错误与修复;配置完全相同却因随机种子失败, 则应纳入稳定性统计. 删除失败记录会把偶然成功包装成配方性质.

跨方法比较时, 数据泄漏也要独立检查. 数学 benchmark 的题目、改写版本或参考解如果进入 DAPO-Math-17k, 最终分数会混入记忆收益. 去重范围应覆盖题面、答案和结构近似, 并报告删掉疑似重叠题后的结果. 强验证器若在目标 benchmark 上训练过, 评测判定也可能带来另一层依赖.

一篇可信的 JustRL 复现最终需要同时交付配置、代码版本、训练日志、原始评测输出、验证器判定和成本统计. 模型权重只能证明某个结果存在, 这些过程材料才能证明结果如何得到. 论文与官方仓库已经给出重要起点, 后续使用者应把自己的硬件、框架改动和数据差异补齐, 避免只复制配方名字.

若新实验最终仍选择增加复杂组件, JustRL 基线也完成了它的任务: 组件面对的是日志里已经出现的具体故障, 收益在相同预算与评测协议下得到验证. 这样的复杂化能够解释、能够撤销, 也能被下一位复现者逐项核对. 真正需要避免的是在基线尚未跑稳时同时更换数据、奖励、采样和损失, 最终只剩一个无法归因的总分.

这套研究纪律也适用于负结果. 某个组件在一套稳定基线上没有收益, 就限定模型、数据、预算和实现报告负结果;换到另一种初始条件后出现明确故障, 再重新评估它. 组件价值由它解决的问题决定, 配方价值则由边界是否写清楚决定.
