# GSPO (Group Sequence Policy Optimization)

**论文信息**:
- **标题**: Group Sequence Policy Optimization
- **作者**: Qwen Team, Alibaba Inc.
- **年份**: 2025
- **论文**: [arXiv:2507.18071](https://arxiv.org/abs/2507.18071)
- **验证**: Qwen3 全系列模型 (Instruct, Coder, Thinking) 的核心训练算法

**前置知识**: GRPO(1.3.1.1 节), DAPO(1.3.2.1 节)

## 1. 动机: 奖励的单位与优化的单位

### 1.1 GRPO 的 token 级 surrogate

GRPO 的 surrogate 在每个 token 上构造重要性比率 $\rho_{i,t}=\pi_\theta(y_{i,t}|y_{i,<t})/\pi_{old}(y_{i,t}|y_{i,<t})$, 再和广播到 token 的序列优势相乘, 逐 token clip. 1.3.1.1 节 §2.8 已经指出这个结构里藏着粒度不匹配: reward 是整条回答一个标量, 优化却是几百上千个位置各自为政. GRPO 用得好时这个不匹配被组内比较盖住, 但它从未消失——一旦单 token 的 log-prob 波动变大, 覆盖它的统计结构就撑不住了.

波动从哪来? 训练深入后 policy 每步更新都让 token 分布移动, 长链推理的单条样本几千个位置, 每个位置的 $\rho_{i,t}$ 偏离 1 一点, 整条链的 surrogate 方差按位置数累积. clip 能在每个位置截停大偏差, 但截停本身制造「零梯度区」, 有效信号密度随训练下降. 这是 GRPO 系在长链推理上的共有瓶颈, DAPO 从 clip 边界和归约分母两侧打了补丁, GSPO 选择了更根本的改法.

把三家的应对排在一起能看出问题层次: 方差累积是病, DAPO 的两处补丁是缓解症状 (截停更晚, 分配更匀), GSPO 改的是病灶本身 (让修正量回到序列粒度). 不是谁对谁错, 是改动成本与收益的组合不同: DAPO 的补丁不改变 GRPO 的任何接口, 现有基建零改动; GSPO 换 surrogate, 存储, 日志, 监控都要跟着变, 换来的是方差结构的根治.

### 1.2 MoE 崩溃: 压垮骆驼的那根稻草

Qwen 团队碰到的具体症状是 MoE 模型的训练崩溃: 在 Qwen3 级别的 MoE 上用 GRPO 训练, loss 周期性爆炸, 模型质量断崖下跌, 且重试 seed 也救不回来. 定位到的机制是**专家路由的放大效应**: MoE 的 router 对每个 token 决定送哪个专家, policy 参数的微小变化会让一大批 token 的路由集体翻转, 这些 token 的 log-prob 同时剧烈变化——逐 token 比率上同时出现大量离群值, 每个离群值都被 clip 单独处理, 但它们的**联合效应** (整条链的 likelihood 实际变了多少) 没有任何结构去约束.

Dense 模型也有同样的物理, 只是幅度温和; MoE 把「参数扰动 → 概率扰动」的增益放大了一个量级, 于是 GRPO 的 token 级假设率先在 MoE 上破产.

值得补一句: 这个机制解释是事后重建的. Qwen 团队先观察到崩溃现象, 再定位到路由波动与逐 token  clip 的相互作用; 「单位对齐」的论点是这个定位的理论包装, 不是事先的设计公理. 读论文时把「现象 → 机制 → 论点」的三层分开, 能避免把论点当成已被严格证明的定理. 论文的论点因此带场景限定: 它不是宣称 GRPO 数学上错误, 而是指出 token 级修正在路由敏感架构下方差失控.

### 1.3 单位对齐论点

GSPO 的核心主张一句话: **奖励的单位是序列, 优化的单位也应该是序列**. 序列级 reward 配序列级 surrogate, 粒度对齐后, off-policy 修正在和 reward 相同的抽象层上进行, 单 token 的噪声被长度归一平均掉, 路由翻转这类「集体事件」在序列比率上只表现为一个受 clip 约束的标量, 不会穿透成几百个独立的 clip 决策.

这个论点是对称的镜像: 批评者可以说「token 级信用分配更细」, 支持者可以说「细粒度在没有 token 级 reward 时只是噪声分配」. 双方都同意的事实是: 粒度错配存在, 且后果随架构敏感度放大. GSPO 是把粒度对齐到 reward 一侧, 另一条路 (token 级过程奖励) 是把 reward 细化到优化一侧, 1.3 节的后续篇目会回到这条路. GSPO 与过程奖励的组合空白 (§6.2), 本质就是「序列粒度上限」问题的另一种表现形式.

补充第三个条件的工程来源: 复用深度是被 rollout 成本逼出来的, 而 rollout 成本在长链 MoE 上恰恰最高——三个条件因此经常同时出现, 不是巧合. 这也是为什么「GSPO 只在 MoE 有用」的说法低估了它: 在 DeepSeek-V3 级别的稠密长链训练上, 深复用同样会把 GRPO 的 token 级方差问题推到台前.

反过来, 有一个条件反向放大 GRPO 的优势: 需要精细控制链内局部行为时 (例如「别在第 N 步用某种格式」), token 级 clip 能做外科手术, 序列级 clip 只能整体升降. 安全约束类任务里这类需求常见, 是 GSPO 适用域的明确边界.

## 2. 序列级重要性比率

### 2.1 定义

GSPO 把一条回答的全部 token log-ratio 做 masked mean, 再指数化, 得到长度归一的序列比率:

$$s_i^{GSPO}=\exp\left(\frac{1}{|y_i|}\sum_{t=1}^{|y_i|}\log\frac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{old}(y_{i,t}|x,y_{i,<t})}\right).$$

$|y_i|$ 是有效 token 数, mask 排除 prompt 和 padding. 统计直觉直接: 若单 token log-ratio 的方差是 $\sigma^2$ 且近似独立, 均值的方差约为 $\sigma^2/|y_i|$——几千 token 的链把方差压掉三个数量级. 独立性假设在真实模型里当然不成立 (相邻 token 高度相关), 但「平均降方差」的方向稳健, 这也是长度归一在 SimPO (1.2.5 节) 里扮演过同一角色的原因.

一个实现细节: mask 的分母是「有效 token 数」而不是序列维度的固定长度, 和 SimPO 的 $|y|$ 约定一致. 混用 padding 长度或 batch 最长长度做分母, 短回答的 $s_i$ 会被系统性压低, 这类 bug 在长度混合不均匀的早期训练里几乎不可见, 后期才显形, 用 §7.2 的不变量提前拦住.

长度归一的统计收益也随链长增长而放大: 200 token 的链把方差压 200 倍, 4000 token 压 4000 倍. 短链场景 (代码补全, 短问答) 里这个收益聊胜于无, 序列比率和逐 token 比率的方差差异不大, GSPO 的理由相应变弱——又回到 §4.2 的三条件判断.

### 2.2 与「token 比率乘积」的区分

先纠正一个流传甚广的误读: GSPO **不是**把 GRPO 的逐 token 比率乘起来. 序列似然比 $\prod_t\rho_{i,t}$ 是 off-policy 修正理论里的完整似然比, 它的对数是 log-ratio 之和, 不带 $1/|y_i|$; 而 GSPO 取的是**对数的平均**, 差一个长度因子. 两者在长链上数值行为完全不同: 乘积形式随长度指数漂移 (T 个 1.001 的乘积是 $e^{0.001T}$), 平均形式对长度不敏感. 把 GSPO 描述成「token 乘积的 clip」会在数值上推出错误结论, 引用时注意.

RLHF 采用小步迭代, 每轮重新采样会继续修正前一轮的估计偏差; 方差过大却可能一次就把参数推得太远, 使后续校正追不上. PPO 选择 clip 而非无截断的 importance sampling 已经体现了这项权衡, GSPO 又在序列级采用了相同取舍.

历史对照再多一层: sequence-level 的 surrogate 在经典 RL 里不新鲜 (选项框架, 宏动作都做序列级 credit assignment), LLM 场景的新意在于「序列 = 自然语言回答」这个语义绑定, 以及长度归一让不同长度的回答可比. 经典文献的教训同样适用: 序列级修正步幅大, 配合保守的 clip 和小学习率, 这套超参搭配在经典 RL 里已验证过, GSPO 的超参性格 (clip 极小) 与之吻合. 换句话说, GSPO 的「反常」超参在经典 RL 的传统里并不反常, 只是和 LLM 社区习惯的 token 级量纲错位; 跨领域移植数值前先换量纲, 这条纪律值得写进任何团队的 onboarding 文档. 一个具体的检查动作: 迁移任何超参时, 先写出它的量纲推导 (例如「0.28 = 单位置对数概率的相对漂移上限」), 量纲写不出来就不许搬. 这个动作用在 clip 数值, 学习率, KL 系数上同样有效, 是跨论文复现的第一道闸.

这个区分也说明 GSPO 与经典 importance sampling 的关系: 经典的序列级修正用乘积 (无偏但方差爆炸), GSPO 用平均 (方差小但修正有偏——它修正的不再是「整条链的似然比」而是「平均每 token 的似然漂移」). GSPO 论文没有回避这一点, 它的立场是: 有偏但方差可控的修正, 在训练价值上胜过无偏但方差爆炸的修正.

### 2.3 手算: 数值对照

取一条 4 token 的回答, 逐 token log-ratio $d=[0.01,0.02,-0.01,0.00]$. 序列比率: 均值 $0.005$, $s=e^{0.005}\approx1.00501$. 逐 token 比率各自是 $[1.010,1.020,0.990,1.000]$, GRPO 的 surrogate 在这四个位置上分别 clip 后加权; GSPO 只在 $s=1.005$ 一个标量上做 clip 决策.

再看漂移场景: 假设 minibatch 复用让 policy 偏离 old, 每个 token 的 log-ratio 漂到 $0.01$ (同向), 序列比率变成 $e^{0.01}\approx1.010$. GRPO 里每个位置的 $\rho=1.010$, 均未触 1.2 的平台, 全部保留梯度; GSPO 里 $s=1.010$ 同样远在平台外. 两种情况梯度结构相同. 差异出现在**异向漂移**: token log-ratio 有正有负, 均值接近 0, GSPO 的 $s\approx1$ 表示「整条链平均没动」, 不做更新; 而 GRPO 逐位置处理, 正漂移的位置照常强化, 负漂移的位置照常压制——它在执行一条「平均意见为零但内部撕裂」的更新.

哪个更好没有先验答案, 但有一个可操作的判别: 异向漂移若来自路由翻转这类「集体伪影」, GSPO 的平均是对的; 若来自链内「前对后错」的真实结构, GRPO 的位置级处理保留了信息. 判别手段是探针分析——找一批 $s_i\approx1$ 但 GRPO 会大更新的样本, 人工检查它们是哪种形态, 占比决定取舍. 哪个更合理取决于任务, 这正是 §5 要展开的争论.

### 2.4 手算二: 方差的对照

把 §2.3 的直觉量化. 设单 token log-ratio 方差 $\sigma^2=0.01$ (这是 minibatch 复用中期的常见量级), 链长 $T=2000$. 独立性近似下, 均值 $\bar\ell$ 的标准差是 $\sqrt{0.01/2000}\approx0.0022$, $s=e^{\bar\ell}$ 的相对波动约 $0.22\%$——远在 clip 区间 (±0.03%) 之外还是之内? $0.22\%$ 的波动已经把 $s$ 推过 1.0003 到 1.0004 的边界, 意味着这批样本接近半数次触发 clip. 这个算术说明 GSPO 的 clip 区间虽小, 和序列比率的天然波动是同量级的, clip 不是摆设, 它持续参与塑形.

对比 GRPO 的同一时刻: 单 token 标准差 $0.1$, clip 在 $\pm0.2$, 约 $95\%$ 的 token 落在平台外保留梯度, 但保留下来的梯度方向由逐 token 的随机漂移主导, 信噪比低. 两个算法的 clip 触发率可能接近, 但 GSPO 的每次触发是「整条链的判决」, GRPO 的触发是「几千次局部判决」, 前者的信息密度高几个量级. 这是「clip 次数压缩」在统计上的真实含义.

## 3. 序列级 clip 与损失

### 3.1 clip 粒度的改变

GSPO 的损失:

$$L^{GSPO}=-\mathbb{E}\left[\min\left(s_i\hat A_i,\ \operatorname{clip}(s_i,1-\epsilon_{low},1+\epsilon_{high})\hat A_i\right)\right].$$

结构和 PPO 相同, 只是 clip 的对象从每个 token 的 $\rho_{i,t}$ 换成每条回答一个的 $s_i$. 一条 4000 token 的链, GRPO 做 4000 次独立 clip 决策, GSPO 做一次. clip 决策数的压缩不是细节, 是方差来源的压缩: 4000 次决策里只要有百分之几的位置路由翻转, GRPO 的更新方向就被这些位置主导; GSPO 的单一决策只反映平均漂移, 路由翻转被平均进标量.

注意「一次决策」不等于「信息少」: 决策的输入是整个 $s_i$, 它由全部 4000 个位置的 log-ratio 共同决定, 信息没有丢, 丢的是「位置维度的独立性」. 如果某个任务真的需要位置级的重要性区分 (例如已知第 2000 个 token 是错误步骤的起点), 序列级 clip 会把这条信息抹平——粒度对齐的另一面是粒度上限.

### 3.2 梯度结构的差别

把两边的有效梯度写开. GRPO: 未触平台的 token 贡献梯度 $\propto A_i\nabla\log\pi_\theta(y_{i,t})$, 每个 token 独立判断. GSPO: $s_i$ 对所有 token 的参数共享依赖 (它是全部 log-ratio 平均的指数), 链上每个 token 的梯度都通过 $s_i$ 耦合, 有效梯度 $\propto A_i\,s_i\nabla\bar\ell_i$, 其中 $\bar\ell_i$ 对各 token 的导数都带 $1/|y_i|$ 因子. 两个后果: 其一, 长链的每个 token 分到的梯度天然小 (除以长度), 和 token-level loss (DAPO §4) 的效果方向一致; 其二, 链内 token 的梯度方向完全一致 (同乘 $A_i$), 不再出现 GRPO 里「一部分 token 被强化一部分被压制」的内部撕裂.

这个「方向一致」的性质值得单独强调: 它让 GSPO 的更新更像 SFT 的形状 (整条序列同向加权), 只是权重由 reward 决定而非固定为 1. 工程上的好处是行为可预测——调试时看到的梯度异常更容易归因到数据或优势, 而不是 clip 触发模式的组合爆炸.

代价方面同样要记录: 方向一致意味着链内任何位置的参数变化都带同一个符号的梯度, 长链对参数的「拉力」比 GRPO 更整体化; 如果链的前半和后半需要相反方向的调整, GSPO 一次更新只能满足其一, 收敛路径会被拉长. 这类「链内冲突」的频率可以用探针集测出, 是评估 GSPO 适配度的第二个指标 (第一个是 §4.2 的三条件). 两个指标都不需要训练就能测 (探针集前向即可), 符合「先测后训」的调试纪律.

### 3.3 clip 区间为什么那么小

论文实验设置的 clip 区间是 $[1-4\times10^{-4},\,1+3\times10^{-4}]$ 量级——比 GRPO 常见的 0.2 小了三个数量级, 这个数字经常被误读为「GSPO 更新极保守」, 其实根源是**比率的定义不同**. 序列比率 $s_i$ 是平均漂移的指数, 它的可接受范围由「平均每 token 漂移多少」决定: 平均每 token 漂 $4\times10^{-4}$, 4000 token 的链总漂移已达 $e^{1.6}\approx5$ 倍似然, 已经很激进. token 级 clip 的 0.2 是「单位置漂 20% 就算出格」, 两者量纲不同, 数值没有可比性. 复现 GSPO 时把 3e-4/4e-4 直接换成 0.2, 等于没有 clip; 反过来把 GRPO 的 0.2 换成 3e-4, 训练会慢到不动.

标定序列级 clip 的实用方法: 先跑若干步无 clip 的 pilot (或用极宽 clip), 记录 $s_i$ 的分布 (P50, P95, P99), 把 clip 边界设在 P95 附近, 让约 5% 的样本触发截停. 这个流程和 GRPO 调 $\epsilon$ 的「clip fraction 目标区间」思路一致, 只是分布的量纲不同, 必须先重新测.

## 4. 与 GRPO, DAPO 的并排

### 4.1 三个损失并排

| 维度 | GRPO | DAPO | GSPO |
|------|------|------|------|
| **比率级别** | 逐 token $\rho_{i,t}$ | 逐 token (解耦 clip) | 序列级 $s_i$ |
| **clip 粒度** | token, 对称 | token, 正负异界 | 序列, 对称 |
| **clip 量级** | $\epsilon\sim0.2$ | $\epsilon_{high}=0.28,\ \epsilon_{low}=0.2$ | $\epsilon\sim3\times10^{-4}$ |
| **归约分母** | 每回答等权 (或 token 级, 见 DAPO) | 批内 token 统一分母 | 内建于比率 (长度归一) |
| **MoE 稳定性** | 崩溃 (Qwen 观察) | 缓解 | 解决 (Qwen 报告) |
| **来源** | DeepSeekMath | ByteDance Seed | Qwen Team |

三者的关系是「同一骨架上的三处补丁」: GRPO 是基线; DAPO 不动比率定义, 改 clip 边界, 采样过滤, 归约分母; GSPO 动比率定义本身, clip 和归约随之重写. 没有谁取代谁的问题——DAPO 的技巧 (动态采样, 长度塑形) 可以和 GSPO 的比率组合, Qwen 自己的训练系统里也保留了这些工程件.

这张表还揭示了一个命名学现象: 三个名字 (GRPO, DAPO, GSPO) 各自的论文都把自家版本写成「默认之上的修正」, 但修正的落点不同——采样端, clip 端, 比率端. 把它们当成同一坐标系里的三个点而不是三个竞争的「算法」, 讨论会清晰得多: 选 surrogate 坐标 (GRPO vs GSPO), 再选 clip 坐标 (对称 vs 解耦 vs 序列级), 再选采样坐标, 三轴独立. 这个坐标视角也解释了社区实现的分叉: verl, OpenRLHF, TRL 各自的「GRPO」其实是坐标系里的不同点, 报配置时按三轴展开, 比报一个名字信息量高一个量级.

### 4.2 GSPO 的优势什么时候显性化

按论点的机制推, 三个条件放大 GSPO 的收益. 第一, 模型是 MoE 或路由敏感的架构, token 概率的集体波动大. 第二, 链长, 位置数多, token 级决策的方差累积明显. 第三, minibatch 复用深, off-policy 程度大, 每位置漂移普遍. Dense 模型, 短链, 严格 on-policy 的场景, 三个条件都不满足, GSPO 相对 GRPO 的差距会缩到噪声以内——此时选 GSPO 的理由是基建统一 (Qwen 系), 不是算法收益.

反过来, 论文没有覆盖的场景也要列出: 过程奖励 (token 级 reward 出现时, 「单位对齐」论点反转, token 级优化反而成了对的粒度); 极短回答 (长度归一的统计收益消失); 多轮交互 (序列的边界模糊, 「一条回答」的定义要重新想).

### 4.3 与 DAPO 技巧的组合

读者常问: GSPO 和 DAPO 的技巧能不能混用? 答案分技巧看. 动态采样和长度塑形作用于采样与 reward 端, 与 surrogate 的定义正交, 组合无障碍——事实上任何 GRPO 系实现都应该默认带上这两项. Clip-Higher 和 GSPO 的序列级 clip 结构上冲突: 序列级只有一个 clip 决策, 「正负解耦」在标量 $s_i$ 上仍然可以定义 (正优势用 $\epsilon_{high}$, 负优势用 $\epsilon_{low}$), 语义保持, 只是实现里按 $A_i$ 符号分流. 真正不能照搬的是数值: DAPO 的 0.28/0.2 是 token 级量纲, 序列级要重新标定 (§3.3).

归约分母的差别在组合时自然消解: GSPO 的比率内建了 $1/|y_i|$, DAPO 的 token 统一分母作用在 token 粒度, 两者同时存在会双重计数长度因子. 用 GSPO 时, 损失分母回到「每条回答等权」即可, 不要再叠 DAPO 的分母. 这类「组合时只保留一层长度处理」的原则, 适用于所有跨方法拼接的场景.

## 5. 稳定性机制再分析

### 5.1 MoE 路由与集体波动

把 §1.2 的机制说得更具体. MoE 的 router 是 $y_{i,<t}$ 的函数, 和 attention 共享输入但走独立的小 MLP; policy 更新改变 router 权重后, 一批历史 token 的路由决定集体改变, 它们的 FFN 输出从专家 A 换成专家 B, 两个专家对同一输入的 logits 差异直接变成 log-prob 跳跃. 在逐 token surrogate 里, 这批跳跃是几十个位置同时出现 $\rho$ 离群, 每个都触发 clip, clip 后的梯度仍保留方向 (min 结构下未触平台的另一侧), 几十个同方向的 clip 后梯度叠加, 参数被猛推, 下一步更多 token 路由翻转——正反馈.

GSPO 里这批跳跃先被平均: 几十个 $+0.5$ 的 log-ratio 和其余几千个 $+0.001$ 混合, 均值可能只有 $0.01$, $s_i$ 落在 clip 区间内, 更新按平均意见大小进行, 不放大集体事件. 这是「平均抑制集体波动」的机制, 代价是集体波动里可能包含真实信号 (某个专家确实更该被用), 也被一并抑制了.

这个「信号与噪声一起被平均」的性质, 是 GSPO 所有争议的根源: 它在方差和分辨率之间选了方差. 选得对不对, 最终由任务决定——路由敏感的 MoE 上噪声主导, 平均赢; 步骤结构清晰的任务上信号主导, 逐 token 更值. 论文的场景是前者, 移植到后者时要重新评估, 这是 §6.3 选型建议的底层逻辑.

### 5.2 长度归一的另一面

$s_i$ 对长度归一, 意味着两条平均漂移相同但长度差十倍的链获得相同的 clip 处理; 长链的「总漂移」其实大十倍, 按似然比的账它偏离得更远. GSPO 接受这个偏离, 等于宣布「平均每 token 漂移」才是关心的量. 这个选择和 DAPO 的 token-level loss (按 token 数加权) 在哲学上相反: DAPO 认为长链该多投票, GSPO 认为该按平均计. 两个都自称解决了长度问题, 方向相反, 说明「长度问题」本身没有统一定义——它取决于你认为 reward 惩罚/奖励的是「整条行为」还是「平均行为」.

实践上这个分歧没有看起来大: GRPO 系的 token 级 clip 下, 长链内部的大漂移早被逐位置截停, 实际生效的更新也被压向「平均意见」; GSPO 只是把这个效果显式化. 真正的实验分歧出现在极端长度差的 batch 上, 日常混合 batch 里两者差距有限.

这个「日常差距有限」的判断可以量化验证: 取历史训练的 batch, 分别用两种分母重放梯度, 比较参数更新的余弦相似度. 相似度高于 0.99 就说明在你的数据上这个争论无关紧要, 低于 0.95 才值得专门消融——先测再争论, 是这类「哲学分歧」的标准化解法.

这个方法也适用于 5.1 的「平均抑制集体波动」之争: 与其论证平均对不对, 不如统计训练 batch 中集体波动的占比——占比低, 平均无害; 占比高, 该担心的不是平均, 是路由为什么如此敏感, 那是模型侧的问题. 顺着这个思路, MoE 训练稳定的另一条路线是 router 正则与负载均衡损失的调校, 和 surrogate 的选择正交, 值得并行排查. 工程上这两路的排查成本不同: surrogate 替换要动训练器, router 调校只动模型配置, 先排查成本低的一侧. 当然, 若两路排查完崩溃仍在, 就该回头怀疑「崩溃」的归因本身, 而不是继续叠加补丁.

### 5.3 与 Dr. GRPO 之争的关系

1.3.1.1 节 §3 记录过 Dr. GRPO 对 GRPO 的两项批评: 组内标准差归一造成难度偏差, 按回答长度归约造成长度偏差. GSPO 和这组批评的关系微妙. 一方面, GSPO 的序列比率内建了长度归一, 长链的 token 梯度带 $1/|y_i|$ 因子, 和 Dr. GRPO 的方向一致; 另一方面, GSPO 论文保留组内标准差归一的优势构造, 没有采纳 Dr. GRPO 的去归一建议. 也就是说, Qwen 接受了「长度维度」的批评, 没接受「难度维度」的批评.

这个选择性采纳本身有信息量: 难度归一的偏差影响的是「不同题之间的梯度配比」, 在 Qwen 的生产设置里可能由课程和采样策略兜底; 长度偏差影响的是「同题内长短链的判决」, 直接作用于序列比率, 不修就炸. 优先级由崩溃模式决定, 不由论文的批评顺序决定——这是读方法论文时常见的落差: 批评的学术价值和修复的工程紧迫性是两回事.

从读者角度, 这个案例给出的通用教训是: 面对相互矛盾的论文建议, 先问每条建议针对的失效模式在自己的系统里是否存在, 再决定采纳与否; 失效模式存在性检查往往比方法比较实验便宜得多.

## 6. 实验, 边界与选型

### 6.1 论文报告了什么

论文报告 GSPO 在 Qwen3 系列 (Instruct, Coder, Thinking 及 MoE 变体) 的大规模 RL 中替代 GRPO, 训练稳定性显著改善, MoE 崩溃不再出现, 下游能力持平或更好. 作为方法学证据, 它的分量来自「生产管线全量替换」: 不是消融跑分, 是一个头部团队把主力算法的 surrogate 换掉并公开背书. 序列级实现也简化了工程记录: 每条回答只需存一个 $s_i$, 日志、监控和异常分析都从 token 矩阵降到标量向量, 调试成本随之降低.

也要按口径读这组证据: 生产替换没有公开的对照组 (同样的算力, 同样的数据, 只换 surrogate 的严格消融), 论文给出的是「换之前崩, 换之后不崩」的前后对照加下游指标. 这比单次跑分可信, 比严格消融弱; 「GSPO 全面优于 GRPO」不是这组证据能支撑的结论, 「在 Qwen3 的规模和架构上, GSPO 是可靠的默认选择」是.

这篇论文的另一层影响在方法论之外: 它是头部实验室第一次把「替换成自家的 surrogate」作为技术报告公开, 之后的 Kimi k1.5, MiniMax 等工作沿用了「生产算法的论文即规格书」的写法. 读这类论文时, 规格书价值 (告诉我怎么复现) 通常大于科学价值 (告诉我什么是对的), 定位不同, 期待也不同.

### 6.2 批评与开放问题

第一, 有偏修正的理论账没有结清: 平均 log-ratio 的指数不是似然比, off-policy 复用时偏差多大, 论文用实验回答, 缺理论刻画. 第二, 「MoE 崩溃由 token 级优化导致」是机制假说, 论文的证据是「换 surrogate 后崩溃消失」, 不排除其他解释 (例如序列级 clip 恰好等价于更保守的学习率). 第三, clip 值 3e-4/4e-4 与具体模型和步长绑定, 迁移时的重新标定没有公开方法论, 复现者容易在量纲上踩坑 (§3.3).

另一个开放问题是和过程奖励的兼容性: 一旦 reward 信号细化到步骤级, 「单位对齐」的论点要求优化也细化, GSPO 的序列级比率反而成了错配. 论文没有涉及这个组合, 社区实践也还没给出标准答案——步骤级 reward 配 token 级优化, 序列级 reward 配序列级优化, 中间的混合形态是留给后续工作的空白.

「混合粒度 surrogate」正在探索这个空白: 有工作尝试步骤级比率与序列级比率的加权组合, 在保留步骤信号的同时控制方差. 该方向尚无定论, 开源框架 (verl, OpenRLHF) 的 recipe 变化通常比正式论文更早显露工程选择.

### 6.3 选型

MoE 或路由敏感架构 + 长链推理 + 深复用, 三个条件占两个以上, GSPO 值得作为默认 surrogate 试跑. Dense 模型短链场景, 留在 GRPO/DAPO 生态更省事实验. 无论选哪个, §4.1 的六行对照表都是核对实现的清单, 尤其 clip 量级那一行——它和比率定义绑定, 迁移时必须先重标定.

生产报告还显示了一项论文指标之外的收益: GSPO 的日志从 token 矩阵降到标量后, 某个 prompt 的组内方差异常或单条链的 reward 离群更容易暴露. 团队若长期受 GRPO 调试复杂度影响, 这项可观测性改善本身就可能抵消迁移成本. 评估 surrogate 改动时, 可以把平均异常定位时间与下游指标一起记录; 基建收益常会在前一项上体现.

## 7. 实现

### 7.1 教学实现

```python
import torch

def gspo_loss(new_logp, old_logp, advantages, mask, eps_low=4e-4, eps_high=3e-4):
    # new_logp, old_logp: [batch, seq]（有效 token 的 log π）
    # advantages: [batch]，序列级优势
    # mask: [batch, seq]，有效 token 为 1
    log_ratio = (new_logp - old_logp.detach()) * mask
    mean_log_ratio = log_ratio.sum(-1) / mask.sum(-1)   # [batch]
    s = torch.exp(mean_log_ratio)
    clipped = s.clamp(1 - eps_low, 1 + eps_high)
    surr = torch.min(s * advantages, clipped * advantages)
    return -surr.mean()
```

和 GRPO 实现的 diff 只有三行: log-ratio 先 mask 求平均再 exp, clip 移到序列级, 逐 token 的 surrogate 循环消失. 注意 `old_logp.detach()` 和 GRPO 一样必须做; `advantages.detach()` 同理. 存储上 GSPO 更省: 每条回答只需留 old logp 的和与有效长度两个数, 不用留整段 old_logp 张量.

这个存储优势在长链场景的工程价值不小: 一次 rollout 存全部 old_logp 是 GB 级的 I/O, 只存标量后降两个数量级; 对异步 rollout-train 流水, 传输和序列化的瓶颈随之缓解. 算是 surrogate 选择附赠的基建红利.

### 7.2 验证清单

三个不变量. 第一, 归一正确性: 构造 mask 不规则的输入 (padding 穿插), 用朴素循环重算 $\sum_t m_t d_t/\sum_t m_t$ 对比向量化结果, 逐位一致. 第二, 长度不敏感性: 把同一条 log-ratio 序列复制成两倍长度 (均值不变), $s$ 必须不变; 这个不变量直接检验「平均而非求和」, 漏除长度是最常见的实现错误. 第三, clip 退化: $\epsilon\to\infty$ 时损失退化为 $-\mathbb{E}[s_i A_i]$, 与解析值对照. 另补一个集成检查: 全链 log-ratio 同号且均值超界时, clip 必须按 $s$ 的整体值触发一次, 而不是按 token 触发 (和 GRPO 实现交叉对比两者的触发计数).

存储上的另一个测试点: 只存 $\sum_t\ell^{old}_{i,t}$ 和 $|y_i|$ 两个标量的实现, 必须能在重新前向时还原 mean log-ratio 到 float32 精度; 半精度下先求和再相减会丢精度, 建议在 log 空间全程 float32 运算, 这一点和 ORPO (1.2.4 节) 的数值纪律相同.

## 8. 一手来源

- [Group Sequence Policy Optimization](https://arxiv.org/abs/2507.18071)
- [verl](https://github.com/volcengine/verl): 支持 GSPO 的开源训练框架.
- [DAPO](https://arxiv.org/abs/2503.14476): 同一骨架上的另一组补丁, 1.3.2.1 节.

序列级概率比率解决了 token 级比率在 MoE 路由扰动下的高方差, 但它也把局部异常压进一个聚合量. 调试时应同时保留序列比率和逐 token 对数比率分位数. 若序列比率仍在 clip 区间内, 但个别 token 的对数比率出现长尾, 聚合目标可能暂时看不出局部策略突变. 这类突变会在后续采样中改变整条推理链, 因而不能因序列损失稳定就忽略.

设回答有 $T$ 个有效 token, 序列对数比率可写为 $\bar r=T^{-1}\sum_t\log(\pi_\theta/\pi_{old})$. 采用平均而非求和使阈值较少受长度影响, 但也意味着单个 token 的异常贡献被 $T$ 稀释. 工程监控需要同时看最大绝对 token 比率与 $\bar r$, 两者分别回答局部是否失控、整条序列是否越界.

长度分桶也不可省略. 若长回答的局部极值明显更大而序列均值相近, 说明平均聚合正在随长度增强稀释效应. 此时应先检查生成尾部是否集中出现模板化或重复 token, 再决定是否添加局部约束.
