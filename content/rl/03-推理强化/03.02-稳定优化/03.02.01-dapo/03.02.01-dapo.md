## 1. 动机: GRPO 在推理 RL 中的三个裂缝

### 1.1 熵坍缩与对称裁剪

推理 RL 训练到中后期, 一个普遍观察是策略熵快速塌缩: 采样越来越像贪心解码, 组内 $G$ 条回答趋于雷同, 探索消失, 之后再也采不到能改进的样本. DAPO 把矛头指向 PPO 系的对称裁剪: 标准 clip 用 $[1-\epsilon,1+\epsilon]$ 一视同仁地限制正负优势, 对正优势样本, 概率涨到 $1+\epsilon$ 就被截停. 问题在于, 正优势样本正是「这个行为该被强化」的方向, 截停它等于压低学习的上限; 反复截停后, 模型在最该保持多样性的方向上被迫收敛.

DAPO 的解法叫 Clip-Higher: 正优势的上界放宽到 $1+\epsilon_{high}$ ($\epsilon_{high}=0.28$), 负优势的下界保持 $1-\epsilon_{low}$ ($\epsilon_{low}=0.2$). 名字的意思是「把上界抬高」. 这一项单独的贡献在论文消融里很显著: 熵曲线不再单调下塌, AIME 分数上了一个台阶.

### 1.2 全同组的空转

第二个裂缝在 1.3.1.1 节算过: 二值 reward 下, 组内全对或全错的概率是 $p^G+(1-p)^G$, 这类组的优势全零, 不贡献任何梯度, 但 rollout 成本一分不少. 难题太多或模型太弱时, 有效组占比低得惊人, 大量算力花在注定无用的采样上. 这个浪费不是实现问题, 是 GRPO 配方的一部分——它没有规定拿这些组怎么办.

DAPO 之前, 工程上的常见做法是把这些组留在 batch 里 (反正优势为零不影响梯度) 或简单丢弃. 留在 batch 里的问题是它们仍占 rollout 和显存, 丢弃的问题是不补采, 有效 batch 越训越小. 动态采样是第一种把这件事做成「保持产出恒定」的系统化处理.

### 1.3 归约方式与长度的纠缠

第三个裂缝最隐蔽: GRPO 的损失先按每条回答的长度归一 ($\frac{1}{|y_i|}\sum_t$), 再对回答求平均. 这个「每回答等权」的约定, 和逐 token ratio 相乘之后, 长回答的每个 token 获得更小的梯度权重. Dr. GRPO (1.3.1.1 节 §3) 指出这引入长度偏差: 推理任务里正确链往往更长, 长度归一等价于压低正确答案的更新力度. DAPO 从工程侧独立走到同一个结论, 并直接改了归约.

三个裂缝合起来说明一件事: GRPO 的默认配方是为「reward 稠密, 长度均匀」的场景设计的, 推理 RL 的场景恰好相反——reward 二值稀疏, 长度方差巨大, 探索随时可能塌掉. DAPO 的四个技术逐一对应这三个裂缝, 没有一项是凭空的新算法.

DAPO 保留 GRPO 的主体, 但按推理任务的结构重新校准默认参数. 任务从数学推理迁到代码修复后, 四个现成数字很快会失去依据; 熵坍缩、全同组空转和长度权重错配都要在新数据上重新检查. 它提供的配方工程流程是先拆出默认配置的隐含假设, 再按任务结构逐项重校.

## 2. Clip-Higher: 解耦裁剪

### 2.1 裁剪曲线与梯度结构

写全 DAPO 的裁剪目标. 记 $r_t=\pi_\theta(y_t|y_{<t})/\pi_{old}(y_t|y_{<t})$, 序列优势 $A_i$ 广播到每个 token, 单 token 的损失是

$$u_t=\min\left(r_t A_i,\ \operatorname{clip}^{DAPO}(r_t,A_i)\,A_i\right),$$

其中

$$\operatorname{clip}^{DAPO}(r_t,A_i)=\begin{cases}\min(r_t,\,1+\epsilon_{high}), & A_i>0,\\ \max(r_t,\,1-\epsilon_{low}), & A_i<0.\end{cases}$$

注意这不是「$A>0$ 时只裁上界, 下界不管」的字面意思——PPO 的 min 结构天然保证取下界的那一支只在梯度层面生效, 改的是平台的位置. $A>0$ 时, 平台在 $r=1+\epsilon_{high}$ 形成, 之前 $rA$ 一路上涨, 之后截平; $A<0$ 时镜像, 平台在 $r=1-\epsilon_{low}$. 把 $\epsilon_{high}$ 从 $0.2$ 抬到 $0.28$, 等于把正优势的平台右移, 好动作的概率可以在更大的幅度内继续获得梯度.

### 2.2 为什么放松上界能防熵坍缩

机制链条是这样: 推理 RL 的有效信号来自「同一题采到对和错两条链」, 它们的差异就是熵. 对称裁剪反复在 $1+\epsilon$ 处截停正优势, 正确链的概率提升受限, 模型学会「模棱两可的稳妥」——每种推理方向都保留一点概率, 但没有任何一个方向被推到位; 更糟的是负优势的截停同样对称生效, 错误链压不下去, 组内 reward 差异缩小, 下一步的信号更弱, 恶性循环. 放宽正侧上界打破这个循环: 正确的推理模式被允许大幅强化, 错误模式照旧压, 分布变尖的方向是「该尖的方向」, 熵的塌缩从「全面保守」变成「选择性收敛」, 同时保住了探索.

要诚实交代边界: Clip-Higher 不是熵正则, 它没有显式鼓励高熵的目标项, 只是不再主动压制「该强化的强化」. 训练后期该收敛的还是会收敛, 论文的熵曲线也只是「不塌」而非「不降」. 把它当熵控制工具用, 期望会落空.

和显式熵正则 (在 loss 里加 $\mathbb{E}[\log\pi]$ 项) 相比, Clip-Higher 不改变目标函数的形状, 只改变优化器到达目标的路径; 好处是不引入新的超参权衡, 坏处是它没有「熵下限」的保证. 这个不对称决定了排查顺序: 它改的是优化路径不是目标, 所以诊断熵问题时, 先查裁剪配置再查目标函数, 顺序反了会白调一轮熵系数.

监控上, 「熵不塌」的直接指标是组内唯一回答数和 n-gram 多样性, 比 token 级熵的数值曲线更可靠——后者受温度设置和分桶方式影响, 噪声大. 论文报告的熵曲线是按固定温度在探针集上测的, 复现时应沿用同一口径, 否则两条曲线不可比. 实践里两者可以共存, 但先上 Clip-Higher, 熵还是守不住再加显式正则, 顺序别反——先加正则会掩盖裁剪的问题.

### 2.3 手算: 梯度权重对比

取 $\epsilon_{low}=0.2$, $\epsilon_{high}=0.28$, 看 $r_t$ 在不同位置的有效梯度. $A>0$: $r=1.10$ 时未触平台, 梯度权重 $\sigma$ 意义上的斜率就是 $A$; $r=1.25$ 时在平台内 (未到 $1.28$), min 结构下梯度为零; $r=1.30$ 越过平台, 梯度恢复. $A<0$: $r=0.85$ 未到 $0.8$ 平台? $0.85>0.8$, 未触平台, 梯度正常; $r=0.75$ 在平台内, 零梯度.

和标准 PPO 对比的关键数字: 正优势样本在 $r\in[1.20,1.28]$ 区间, PPO 已经截停 (零梯度), DAPO 仍在更新. 这个区间正是「正确且刚被强化」的样本最常见的位置——off-policy 程度随复用 minibatch 数加深, ratio 系统性偏离 1, 正方向偏离集中在 1.2 附近. 换句话说, Clip-Higher 放松的恰好是信号最密集的地带.

顺带修正一个常见的画图误解: 把 PPO 和 DAPO 的 clip 曲线画在一起, 容易看成「DAPO 整体右移」. 实际只有 $A>0$ 的分支右移, $A<0$ 的分支纹丝不动; 画图时两条分支要分开画, 否则「对称区间」的直觉会回来, 误导后续的调参判断.

### 2.4 手算二: ε 边界对有效更新区间的影响

把 clip 的数值结构再算透一点. 有效梯度区间 (平台之外) 的宽度, 正优势侧是 $r\in(0,1+\epsilon_{high})$, 负优势侧是 $r\in(1-\epsilon_{low},+\infty)$ 在 min 结构下实际生效的分支. 设 $\epsilon_{low}=0.2,\epsilon_{high}=0.28$: 好动作的更新空间比坏动作宽 40%. 再考虑 minibatch 复用导致的 ratio 分布: 复用 $K$ 次, ratio 的标准差大约随 $K$ 增长, 正侧平台右移意味着「前几个 minibatch 的正优势样本几乎全部保留梯度」, 而负侧在第二个 minibatch 就开始大量触平台.

由此得到一个调参方向: 如果监控里 clip fraction 显示负侧触发远多于正侧 (常见), 说明更新在「压错」上先饱和, 而「扶正」还有余量, 这正是 Clip-Higher 针对的失衡. 反过来, 如果两侧触发率接近, 说明 off-policy 程度不深, Clip-Higher 的收益空间有限, 优先排查别处.

## 3. Dynamic Sampling: 动态采样

### 3.1 过滤规则

规则本身一行: 组内 reward 全同的 prompt 丢弃, 其余保留. 实现上判据是 $\max_j R_j>\min_j R_j$, 和 reward 的编码无关——二值 $0/1$, 正负 $-1/1$, 连续分数都适用, 不要写成 `rewards.std() > 0` 之外的特定形态, 也不要把「全错组」和「解析失败组」混为一谈, 后者应进 verifier error 通道 (1.3.1.1 节 §5.2), 不该被动态采样默默吸收.

过滤改变了训练分布: 留下来的组偏向「难度适中」的 prompt. 这是有意为之——全对组没有新信息, 全错组在模型当前能力下也没有, 砍掉它们是按信息量重新配权, 不是偷懒. 但要知道代价: 已掌握的简单题和完全不会的难题都被移出梯度, policy 在两端的行为无人约束. DAPO 不显式保留 KL 项 (见 §6), 两端的漂移靠 clip 本身兜着, 这是它配方里最大胆的一处.

### 3.2 补采策略与吞吐

过滤不是终点, 要保持有效 batch 大小恒定, 就得补采: 丢弃多少组, 就再拉多少新 prompt 进来重采, 直到凑满. 这改变了 rollout 流水的调度结构——采样变成「有条件的循环」, 每轮的采样量不再是固定值而是随机变量, 流水线的负载均衡要按最坏情况 (大量全错) 设计. 工程上常见的配套是预筛: 用上一轮的全对/全错记录预测当前 prompt 的有效概率, 优先采预计有效的, 补采只作兜底.

补采还带来一个监控陷阱: 报告「每组平均 rollout 成本」时, 忽略补采会低估真实成本, 合并计算又会掩盖动态调度的波动. 因此应分开报告首采成本、补采成本和有效组产出率. 单个平均数无法还原动态采样的资源消耗.

成本口径之外还有一个正确性问题: 补采的新 prompt 从哪个分布抽, 决定过滤后的训练分布是否还代表目标任务. 从原题库均匀补, 训练分布向「题库平均难度」收缩; 从难度分层的题库按层补, 保留人为控制的课程. DAPO 论文用后者 (SIA 数据集带难度标注), 复现时若题库没有难度结构, 补采分布就是隐形的超参. 给题库补难度标注的成本不高 (用当前模型小采样估 pass rate 即可), 回报是补采和课程都变得可控, 这笔投入在任何规模下都值.

### 3.3 与难度分布的联动

动态采样把「选什么题」从数据侧的静态决定, 变成了训练过程的动态反馈: 模型变强, 昨天的中等题今天全对, 被过滤; 昨天的难题今天有对有错, 进入梯度. 题目难度分布随训练自动迁移, 这相当于一个隐式的课程学习. 好处是自适应, 坏处是不可控: 如果模型在某类题上突然塌掉 (比如长除法), 这类题会退化成全错组被过滤掉, 塌掉的事实从梯度里消失, 直到下游评测才发现.

防御手段还是监控: 记录每个 prompt 的历史通过率, 过滤组的比例按题目类别拆开报. 某类题的有效组占比持续走低, 是它正在掉出能力边界的信号, 此时应主动回灌该类题的 SFT 数据, 而不是任由动态采样把它移出视野.

这道防御的本质, 是给「自适应课程」装一个人工瞭望哨: 自动机制负责把算力分配到当前最有信息量的区域, 人工监控负责发现「信息量消失」本身可能就是事故. 两类职责不能都交给同一个自动机制.

### 3.4 过滤的统计后果

动态采样让「进入训练的 prompt 分布」成为模型能力的函数, 这带来一些不直觉的统计性质. 有效组条件是「组内至少一对 reward 不同」, 对二值 reward 等价于「组内既有成功又有失败」, 即 pass rate $p$ 落在 $(0,1)$ 开区间. 过滤后的 prompt 分布密度正比于 $1-p^G-(1-p)^G$, 这个函数在 $p=0.5$ 附近最宽, 两端迅速收窄——所以动态采样天然把训练质量押在中等难度题上, 且 $G$ 越大押得越集中.

一个直接推论: 组大小和过滤强度耦合. $G=16$ 时, $p=0.1$ 的题几乎永远被过滤 (有效概率约 $1-0.9^{16}-0.1^{16}\approx81\%$ 尚可, 但 $p=0.05$ 时降到约 $56\%$), 模型如果要在难题上爬坡, 大 $G$ 反而拖慢. DAPO 的 $G$ 取 8 到 16 区间, 配合动态采样, 是在信号稳定和资源之间的折中, 不是越大越好.

## 4. Token-Level Policy Gradient Loss

### 4.1 两种归约的代数差别

把 GRPO 和 DAPO 的归约并排. GRPO: 每条回答先按自身长度平均, 再对回答等权平均,

$$L^{GRPO}=-\frac1B\sum_{i=1}^B\frac{1}{|y_i|}\sum_t u_{i,t}.$$

DAPO: 批内所有有效 token 共享一个分母,

$$L^{DAPO}=-\frac{1}{\sum_i |y_i|}\sum_i\sum_t u_{i,t}.$$

两者相差的不是常数, 而是「每条回答的权重」: GRPO 里回答 $i$ 的权重是 $1/B$ (等权), DAPO 里它的权重是 $|y_i|/\sum_j|y_j|$ (按长度加权). 长回答在批梯度中的占比从「和其它回答一样」变成「和它的 token 数成正比」.

注意两个语义都没有变: 同一回答内的所有 token 仍共享序列优势, 序列 reward 并没有被拆成 token 级信用分配; 变的只是「回答之间」的相对权重. 把这个差别记成一句话: GRPO 按「条」投票, DAPO 按「token 数」投票.

按 token 数投票还有一个常被忽视的含义: batch 内各条回答的权重不再和采样顺序无关. 同一次 rollout 里, 先采完的回答和后采完的长度分布可能不同 (难度高的生成久), 分桶和调度策略会间接改变梯度构成. 想完全消掉这层影响, 只能按长度分组后再归约, 这又回到 §4.2 的分桶建议.

### 4.2 与长度偏差的关系

按 token 数投票为什么更符合推理任务? 一条 2000 token 的正确链和一条 200 token 的正确链, 在 GRPO 里贡献相同的梯度预算, 但前者包含十倍的推理步骤, 它的正确性携带的信息量也更大; 更重要的是, 错误链也有长有短, 长度归一会让「长的正确链」相对「短的错误链」在梯度里被系统性压低估——恰好和 Dr. GRPO 分析的方向一致. DAPO 的消融显示 token-level loss 单项贡献约 2 到 3 个 AIME 点, 是四项技术里第二大的.

也要记下它的代价: 按 token 加权后, 批梯度的方差受长度分布影响更大. 长度方差大的 batch, 少数超长回答主导梯度, 学习率的有效尺度随 batch 构成漂移. 配套的做法是 length grouping (按长度分桶采样), 让 batch 内长度尽量齐, 把加权的影响限制在桶内.

长度分桶还有一个被动收益: 桶内序列长度相近, padding 浪费减少, rollout 和 training 的吞吐同时受益. 所以即便不关心长度偏差的团队, 也常把分桶当纯工程优化用——这是推理 RL 里少有的「正确性和效率同向」的技术.

### 4.3 归约变体的全景

按「条」投票和按「token 数」投票之间, 还有中间态, 一并列出免得选型时漏看. 其一是按 $\sqrt{|y_i|}$ 加权, 折中两种极端, 部分缓解长度偏差又不让超长回答主导; 其二是按「有效步数」加权 (例如按换行或段落数), 对推理链这种结构化的输出, 步数比 token 数更接近「推理量」; 其三是 Dr. GRPO 的保留长度归一但修正 std 归一, 从优势侧而不是损失侧动手. 四者没有全面的公开对照, 选型依据只能是自己的长度分布和消融.

无论选哪种, 有一条不变: 归约方式必须和 clip 边界, 学习率, KL 系数当成一个整体调. 换分母改变梯度的有效尺度, 等效于动了学习率; 只换分母不动其他, 常见的结果是「改了但没完全改」——曲线有变化, 说不清变好变坏.

## 5. Overlong Reward Shaping

### 5.1 软惩罚的形状

推理链长度不断增长是推理 RL 的常态, 硬截断 (超了直接给 0 分或判错) 有一个恶果: 一条推理了 16000 token 即将答对的链, 因为超线前功尽弃, 且「超长」和「答错」在 reward 里不可区分, 模型收到的是混乱信号. DAPO 用三段线性软惩罚替代: 期望长度 $L_{max}-L_{cache}$ 以内不罚, 超过后每 token 线性扣分, 到 $L_{max}$ 扣满 $-1$, 再往上保持 $-1$ 直到生成上限.

论文的具体数字: 期望最大长度 16384, 软惩罚窗口 4096, 总生成上限 20480. 也就是说 16384 以下零惩罚, 16384 到 20480 之间线性从 0 降到 -1, 超 20480 的链惩罚封顶但 reward 仍来自验证器——「答对但超长」的链拿的是「正确答案 reward 减 1」, 而不是一刀切零分.

对比硬截断的账: 一条 16384 token 的临界链, 硬截断下 reward 从「即将到手的 +1」掉到 0 或解析失败, 负 advantage 落在整条链上, 惩罚的是「想得久」这个行为本身; 软惩罚下它拿 0 到 -1 之间的连续值, 且越接近上限罚越重, 模型学到的是「长度有边际成本」而不是「长度是灾难」. 两者的训练动态差异, 在长链任务上能差出几个点.

### 5.2 与动态采样的配合

软惩罚和动态采样之间有直接的相互作用: 惩罚让超长组的 reward 出现连续值差异 (原来全对全错的组, 现在因长度不同产生分差), 一部分原本「全同被过滤」的组变成了有效组, 有效组占比上升. 这个红利在论文里没有单独量化, 但方向上明确:  shaping 不只是「保护长链」, 也顺手改善了采样效率. 想量化这个红利也不难: 对比开 shaping 前后的有效组占比曲线, 差值就是长度项创造的「新信号」. 这也是判断 shaping 强度是否合适的实用指标: 占比提升过小说明窗口太窄没在创造差异, 提升过大则说明惩罚在主导排序, 两者都不健康.

使用时有两个参数要按自己的任务重设: 期望长度和窗口. 窗口太小, 惩罚太陡, 长链任务被误伤; 期望长度定得保守, 等于提前给模型套上长度天花板, 和训练目标 (让链自然变长以解决难题) 直接冲突. 调参时看长度分布的 P90 和 P99 相对两个阈值的距离, 让 P99 落在窗口中段是常见的初始配置.

还要注意软惩罚和 reward 量纲的匹配: 惩罚上限是 -1, 与「答错」的常见编码同量级, 相当于把「答对但超长」判成「答错」. 如果任务的 reward 不是二值而是连续分, -1 的相对含义会变, 要么按 reward 的尺度重新标定惩罚幅度, 要么显式把长度惩罚作为独立维度进优势.

### 5.3 长度塑形的替代方案与组合

软惩罚不是处理超长的唯一手段, 列出两个常见替代及取舍. 其一是「长度进 reward 的乘法项」: 最终 reward 乘一个长度折扣因子 (例如 $R\cdot\exp(-\max(0,|y|-L_0)/tau)$), 答错的链长度无意义, 惩罚只作用在答对的链上, 语义比加法项更准, 但折扣因子引入新的尺度超参 $\tau$, 调参空间更大. 其二是「双 reward 通道」: 答案正确性和长度分别进两个优势, 加权合并, 相当于多目标 RL 的简化版, 可控性最好, 代价是实现复杂度.

软惩罚胜在简单和可解释, 且与二值 reward 的加法结构兼容; 任务 reward 本身连续或多维时, 再考虑乘法或双通道. 无论哪种, 处理超长的总原则和 §5.1 一致: 让「长」有边际成本, 而不是让「长」等于「错」.

## 6. 移除 KL 与其他细节

### 6.1 KL 去哪了

DAPO 的目标函数里没有 KL 项, 靠 clip 承担全部的偏移约束. 这和 R1 时代的多数推理 RL 配方一致——推理任务的 reward 是规则验证, hacking 面小, KL 锚定的主要价值从「防 reward hacking」变成「防训练不稳」, 而 clip 加动态采样已经覆盖了大部分不稳来源. 代价是 §3.1 说的两端漂移无人约束, 以及对参考策略的依赖消失后, 训练日志里少了一个重要的健康指标 (KL 曲线), 监控体系要补上替代物 (熵, clip fraction, 长度分布).

这不是「KL 无用」的证据. 换成 reward model 打分或开放任务, hacking 面回来, KL 或等效约束就应回来. DAPO 的去 KL 是场景特定的设计决定, 搬配方时最容易被误抄的一项.

替代监控的具体做法: 把「policy 与初始 SFT checkpoint 的 KL」单独算出来记一条曲线, 训练里不加这项的梯度, 只观测. 它恢复了一部分 KL 曲线的预警功能, 又不改变 DAPO 的目标; 成本是每轮多一组 reference 前向, 和恢复 KL 项本身同价, 换来的是可观测性.

### 6.2 完整算法流程

一个 DAPO 迭代周期: 对每个 prompt 采 $G$ 条, 验证器给分, 过滤全同组并补采至有效 batch 恒定; 组内做均值标准差归一得到优势 (保留 GRPO 的标准差归一, 没有用 Dr. GRPO 的修正); token 级 ratio 进解耦 clip, 批内有效 token 统一分母归约; 单轮 (或多 minibatch) 更新. 论文设置 $G$ 在 8 到 16 之间, $\epsilon_{high}=0.28$, $\epsilon_{low}=0.2$.

和 GRPO 的骨架差异至此全部列出: 采样端加过滤和补采, 损失端换 clip 边界和归约分母, reward 端加长度塑形, 正则端去掉 KL. 每个开关都独立, 这也是判断任一实现「是不是 DAPO」的清单: 四项缺一项, 就该改名.

这个「四项缺一即改名」的纪律, 对引用和对比都重要: 把「用了 Clip-Higher 的 GRPO」叫 DAPO, 等于把四项消融的结构信息抹掉, 后续读者的复现基线就歪了. 命名即契约, 尤其在 trick 密集的推理 RL 领域. 类似的命名漂移几乎每个季度都在发生, 养成核对「名字, 定义, 实现」三者的习惯, 比记住任何单项技术都保值.

### 6.3 与开源实现的差异核对

verl 等框架的 DAPO 实现和论文配方之间存在已知差异, 复现时逐条核对. 标准差归一: 论文保留 GRPO 的组内 std 归一 (与 Dr. GRPO 的批评并存), 有些实现默认关掉, 这改变了优势尺度, 也改变了 Clip-Higher 生效区间的实际位置. 采样端: 论文是「补采到有效 batch 恒定」, 部分实现只做过滤不补采, 等效于动态 batch 大小, 学习率的实际含义不同. 长度塑形: 有的实现把惩罚加在 reward 上 (论文方式), 有的直接 mask 掉超长 token, 后者不改 reward 分布, 只改梯度覆盖, 效果不等价.

核对的方法沿用 1.3.1.1 节的五个开关拆分: advantage 怎么算, ratio 在 token 还是 sequence 级, clip 边界各是多少, 归约分母是什么, 采样怎么过滤和补. 把任意两个「DAPO 实现」的这五行对齐再比数字, 比争论谁的复现「更忠实」有效得多.

## 7. 实验, 边界与选型

### 7.1 论文报告了什么

DAPO 在 Qwen2.5-32B 上报告 AIME 2024 达到 50 分, 超过同期的 DeepSeek-R1-Zero-Qwen-32B (47 分) 等开源复现, 且完整开源了代码和数据 (SIA 集). 方法层面可靠的结论是: 四项看似工程化的改动, 每一项都有独立消融支撑, 叠加后构成一个可复现的推理 RL 强基线; 推理 RL 的收益大头来自「把采样端和损失端的默认配置对准任务结构」, 而不是新算法. 论文的叙事重心在系统: 训练框架, 调度, 数据集全部公开, 这是它被大量复现的原因.

这组数字也要按口径读: AIME 是单任务竞赛数学, 50 分是在 32B 规模上的成绩, 不代表通用推理能力; 且对比的 R1-Zero-Qwen-32B 是社区复现而非 DeepSeek 官方 32B. 方法比较的公平性依赖「同基座, 同数据预算, 同评测协议」, 论文基本满足, 引用时保持这个限定即可.

### 7.2 批评与边界

第一, 消融是在一个模型一个任务族上做的, 四项技术的相对贡献换个基座可能重排, Clip-Higher 的收益尤其依赖「熵是否真的在塌」——基座和采样温度不同, 熵动态不同. 第二, 去 KL 加动态过滤的组合让训练分布持续漂移, 论文对两端行为 (过易过难) 的约束方案语焉不详, 长训时这是风险点. 第三, token-level loss 和长度分桶的交互 (§4.2) 论文没有展开, 复现时这部分要自己补实验.

另一个未被充分讨论的点是四项技术的相互作用: 消融报告的是「从全有到全无」的单项贡献, 但 Clip-Higher 的收益部分来自动态采样改变了 ratio 分布, token-level loss 的收益部分来自长度塑形改变了长度分布——单项之和大于总收益是可能的. 全量配方作为基线没问题, 拆解归因时要留这个心眼.

### 7.3 什么时候用哪一项

不必四项打包. 熵曲线在塌, 先上 Clip-Higher; 有效组占比低, 先上动态采样; 长度方差大且怀疑长度 bias, 换 token-level loss; 长链被硬截断误伤, 加长度塑形. 每项都可以单独嫁接到 GRPO 基建上, verl 等框架的开关式实现正是这么设计的. 反过来, 如果四项症状一个都没有, 保持 GRPO 原版, 别为升级而升级.

还有一个反向场景: 症状全有但只想验证一项时, 用「单项消融 + 固定其余三项」的结构, 而不是从 GRPO 只加这一项. 因为四项之间存在 §7.2 说的相互作用, 单项效果在三项齐全和三项缺席的上下文里不同; 想知道自己管线里哪项真正起效, 只能在自己的全量基线上做减法.

## 8. 实现

### 8.1 教学实现

```python
import torch

def dapo_clip(ratio, advantages, eps_low=0.2, eps_high=0.28):
    # ratio, advantages: [batch, seq]，advantages 已广播到 token
    upper = torch.where(advantages > 0,
                        torch.full_like(ratio, 1 + eps_high),
                        torch.full_like(ratio, float('inf')))
    lower = torch.where(advantages < 0,
                        torch.full_like(ratio, 1 - eps_low),
                        torch.full_like(ratio, float('-inf')))
    clipped = ratio.clamp(lower, upper)
    return torch.min(ratio * advantages, clipped * advantages)

def dapo_loss(token_losses, mask):
    # token_losses: [batch, seq]（已含 -u_t），mask: 有效 token
    return -(token_losses * mask).sum() / mask.sum()
```

动态采样的过滤一行是 `group_rewards.max(dim=-1).values > group_rewards.min(dim=-1).values`, 配合外层补采循环. 长度塑形按 §5.1 的三段式实现, 注意惩罚作用在 reward 上 (进优势), 不要直接加在 loss 上——两者的梯度路径不同.

补采循环的骨架也值得写清: 它本质是「采样-过滤-再采样」的 rejection sampling, 在分布式 rollout 里要处理「部分 worker 已返回, 部分还在跑」的取消与合并; 最简单的正确实现是先全量采完再统一过滤, 代价是尾部延迟, 优化的空间在流水化而不在算法.

### 8.2 验证清单

三个不变量. 第一, clip 退化: 设 $\epsilon_{high}=\epsilon_{low}=\epsilon$, DAPO 的 clip 应退化成标准 PPO 的 $\operatorname{clip}(r,1-\epsilon,1+\epsilon)$, 对随机 ratio 和优势向量逐点验证. 第二, 归约退化: 构造 batch 内所有回答等长的情形, token-level 与 response-level 两种归约应给出相同损失 (差常数因子 $B\cdot|y|/\sum|y_i|=1$). 第三, 过滤退化: 全同组 (全零, 全一, 全任意常数) 必须被过滤, 含一对差异的组必须保留, 覆盖 reward 编码的三种形态. 三条都能在合成张量上写成单测, 是这套实现的最小验收.

上线前再补一个集成级检查: 用固定种子跑 50 步, 对比 clip fraction 的左右侧触发比, 论文量级是正侧略多于负侧 (放宽上界的效果); 如果自己的实现负侧远多于正侧, 大概率是 clip 分支写反——这类 bug 不会报错, 损失还在降, 只是训练方向拧了.

同理, 归约不变量 (等长 batch 下两种分母等价) 能拦住「分母用错但大部分 batch 长度均匀」的隐蔽 bug——只有在刻意构造的极端长度差 batch 上才显形, 值得单独一个测试用例. 三个不变量加两个集成检查, 构成 DAPO 实现的最小验收套件, 全部不依赖训练就能跑.

## 9. 一手来源

- [DAPO: An Open-Source LLM Reinforcement Learning System at Scale](https://arxiv.org/abs/2503.14476)
- [verl (集成 DAPO 的开源框架)](https://github.com/volcengine/verl)
- [Dr. GRPO](https://arxiv.org/abs/2503.20783): 长度 bias 的独立分析, 1.3.1.1 节 §3.

DAPO 的几个开关应分开做消融, 因为它们作用在不同统计量上. dynamic sampling 改变进入更新的 prompt 分布, token-level loss 改变长短回答的权重, asymmetric clipping 改变概率比率的可行区间. 三者同时打开后只看最终奖励, 无法判断收益来自更有信息量的数据, 还是来自不同的梯度加权. 最小实验矩阵应保留共同随机种子和相同有效 token 预算, 逐次只切换一个开关, 同时报告被丢弃 prompt 比例、回答长度分位数与上下 clip 命中率.

动态采样还会造成训练分布随能力变化. 某类题一旦全部答对或全部答错便可能被过滤, 后续梯度转向剩余难度区间. 因此 checkpoint 比较要保留每步实际训练的难度直方图; 否则奖励上升可能部分来自样本组成变化, 不能全部归因于策略改善.
