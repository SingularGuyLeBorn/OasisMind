# RLVR 范式与 DeepSeek-R1 案例

RLVR 是 Reinforcement Learning with Verifiable Rewards 的缩写. 它指一类奖励能够由规则, 执行器, 求解器或环境状态自动核验的强化学习设置. 数学题可以检查最终答案, 代码题可以运行测试, 形式证明可以交给 proof checker, 棋局和仿真任务可以读取环境结果. 核心条件是同一评测协议面对同一候选输出时, 能够稳定地产生可重复的判定.

RLVR 描述奖励来源, 不指定唯一优化算法. REINFORCE, PPO, GRPO(1.3.1.1 节) 或其他 policy-gradient 方法都可以消费可验证奖励. DeepSeek-R1 是这一方向最有影响力的案例之一, 却不等于 RLVR 的全部. R1 的结果来自 base model, 数据, 采样, verifier, 格式约束, GRPO, 多阶段 SFT 与后续对齐的组合, 单独复制一种奖励或 `<think>` 标签无法复现整个系统.

## 1. 什么样的奖励可以验证

一个 verifier 可以写成 $v(x,y,e)\to(r,m)$, 其中 $x$ 是任务输入, $y$ 是模型输出, $e$ 是评测环境, $r$ 是奖励, $m$ 是诊断元数据. 元数据至少应包含解析结果, 正确性, 运行状态, 超时, 失败类型和 verifier 版本. 只返回一个浮点数会丢掉训练异常的来源.

"可验证"强调结果能按协议复算, 不意味着协议一定正确. 答案解析器可能漏掉等价表达, 测试集可能覆盖不足, 浮点容差可能过宽, 沙箱可能泄漏隐藏信息. Verifier 仍然是一段需要测试, 版本化和审计的程序.

### 1.1 规则与答案匹配

数学短答案常把输出规范化后与标准答案比较. 整数和有理数可以精确匹配; 代数式可以借助符号化简检查等价性; 数值答案需要规定绝对或相对误差. 多选题可以抽取选项字母, 但必须规定输出多个候选答案时的解析行为.

答案匹配的难点在表示. $1/2$, $0.5$ 与 $50\%$ 语义相同, 字符串却不同. 方程 $x^2=1$ 的答案可能写成 $x=\pm1$, 集合 $\{-1,1\}$ 或两行推导. 一个可靠 parser 会限制可接受语法, 完成规范化后再比较. Parser 失败应单独记为 `parse_error`, 不能静默并入错误答案, 否则无法区分模型不会做题和格式不兼容.

规则 verifier 也可以检查输出格式, 例如是否含指定标签, JSON 能否解析, 是否在 token 预算内. 这类格式奖励容易计算, 但只代表协议遵循. 任务成功率必须由 correctness 字段统计, 不能用 total reward 大于 0 代替, 因为错误答案也可能拿到格式分.

### 1.2 执行器, 单元测试与环境结果

代码任务把候选程序放进隔离环境, 编译并运行测试. Binary reward 可以是全部测试通过记 1, 否则 0; dense reward 可以使用通过测试比例, 编译成功, 运行时间或内存约束. Dense 信号更容易学习, 也更容易被不均衡测试权重利用.

测试通过只证明覆盖到的行为正确. 若 hidden tests 漏掉空输入, 溢出或复杂度边界, 一个针对公开样例硬编码的程序也能得高分. 沙箱必须限制文件, 网络, 进程, 时间和内存, 每次运行还要使用干净状态. 非确定性并发程序需要重复执行或固定随机种子, 否则同一输出会收到不同奖励.

环境任务可以直接读取终局状态, 例如游戏胜负, 定理证明是否被 kernel 接受, 机器人是否到达目标. 这类 verifier 通常比自然语言 judge 更接近任务本身, 但仍受模拟器精度, 环境漏洞和 reset 状态影响. 可验证的是定义好的环境目标, 不自动等于现实世界的完整成功.

### 1.3 形式证明与过程检查

形式证明系统用小型可信 kernel 检查 proof term 是否满足定理. 只要公理, 定义和 kernel 固定, 判定可以高度可靠. 模型需要生成语法正确并能通过类型检查的证明, reward 可以是最终通过, 完成子目标比例或证明长度等组合.

过程 verifier 试图评价推理中间步骤. 若每一步都能由符号规则, 代码执行或证明器验证, 它仍属于可验证奖励. 若步骤由另一个语言模型判断"合理", 信号更接近 learned reward 或 process reward model, 可重复性与可攻击面都不同. RLVR 的边界应按验证机制区分, 而不是看到逐步推理就自动归类.

可验证域的共同点是存在外部语义. 数学答案, 编译器, proof kernel 和环境状态都不依赖模型自己声称成功. 开放式写作, 审美, 事实综合和复杂帮助性通常缺少完整程序判定, 需要人类偏好或 learned judge 补充. 一个训练集可以混合多类奖励, 但应保留每类来源, 不能把统一后的标量当作同质证据.

## 2. 从 rollout 到参数更新

RLVR 的训练循环可以概括为五步: 采样任务, policy 生成多个候选, verifier 给每个候选打分, 奖励转成 advantage, 优化器更新 policy. 每一步都改变信号分布. Prompt 难度决定成功概率, sampling temperature 决定候选多样性, verifier 决定什么算成功, advantage 决定同组样本怎样比较.

用 $x_i$ 表示第 $i$ 个问题, 对每题采样 $G$ 个回答 $y_{i,1:G}$. 生成时应保存 policy version, sampler version, token ids, completion mask, 实际行为分布下的 log-prob, temperature, top-p, max tokens, stop reason 和 sample id. Verifier 返回 correctness, format, error type 与 total reward. 这些字段是后续复算的最小数据血缘.

### 2.1 采样分布决定训练看见什么

令 $q_{old}^{T,p}$ 表示对 $\pi_{old}$ 的 logits 做 temperature 缩放、top-p 截断并重新归一化后的实际行为分布. 策略按

$$
y_{i,j}\sim q_{old}^{T,p}(\cdot\mid x_i;L)
$$

生成回答, 其中 $T$ 是 temperature, $p$ 代表 nucleus sampling 设置, $L$ 是长度上限. 同一 policy 在不同采样参数下会产生不同成功率与多样性. Temperature 太低, 组内回答高度相似, 容易全对或全错; 太高则大量样本语法损坏, verifier 信号浪费在低级错误上. 若 $T\ne1$ 或 $p<1$, rollout 必须保存实际 $q_{old}^{T,p}$ 下的 old log-prob; 只保存未变换 $\pi_{old}$ 的 log-prob, 后面的 ratio 就不再是行为分布的重要性比.

Prompt sampler 也需要控制难度. 若任务几乎全能答对, advantage 缺少区分; 若几乎全错, reward 仍然稀疏. Curriculum 可以把一部分预算放在当前成功率中间区域, 同时保留较难样本监测能力边界. 只追逐已有非零 reward 的题目会产生选择偏差, 模型可能在窄分布上进步而放弃困难区域.

生成长度上限同时影响推理空间和成本. 上限增加可能让模型有更多机会完成长推导, 也会增加重复, 绕路和 verifier 攻击面. 比较不同训练配置时要报告总生成 token, 不能只固定 prompt 数. $G$ 与平均长度同时翻倍, verifier 和训练计算会接近四倍增长.

### 2.2 奖励组合与组内优势

设 correctness reward 为 $c_{i,j}\in\{0,1\}$, format reward 为 $f_{i,j}$, 其他规则项为 $q_{i,j}$. 总奖励可以写成

$$
R_{i,j}=w_c c_{i,j}+w_f f_{i,j}+w_q q_{i,j}.
$$

各项必须分别记录. 若 $w_f>0$, 一个答案错误但格式正确的样本可能有正总分. 因而 pass rate 应用 $c$ 统计, format compliance 用 $f$ 统计, 训练 total reward 再用 $R$ 统计.

GRPO 常在同题的 $G$ 个回答内标准化:

$$
\bar R_i=\frac1G\sum_{j=1}^GR_{i,j},
\qquad
s_i=\sqrt{\frac1G\sum_j(R_{i,j}-\bar R_i)^2},
$$

$$
\hat A_{i,j}=\frac{R_{i,j}-\bar R_i}{s_i+\varepsilon_A}.
$$

这让回答与同题候选比较, 降低不同题目奖励尺度的影响. 若组内全对或全错, $s_i=0$, 安全分母使所有 advantage 为 0. 这组 rollout 不提供相对 policy signal, 却仍消耗生成和验证预算. 零方差组率因此是 RLVR 的关键诊断.

当 $q_{i,j}$ 由多个来源组成时, 组合顺序影响梯度结构. 先把各奖励加和成 $R_{i,j}$ 再做组内归一, 两组奖励组合不同的样本只要总和相同就会被压成相同 advantage, 例如「正确但缺少格式分」与「错误但有过程分」可能落在同一标准化水平, 梯度无法区分它们. GDPO(1.3.2.4 节) 把归一移入每个奖励分量内部, 先逐项标准化再聚合, 保住奖励组合的区分度. 奖励分量越多, 先加和再归一丢失的信息越多, 多奖励 RLVR 应优先评估逐项归一的方案.

### 2.3 Policy update 与 reference KL

以 clipped policy update 为例, 当前 policy 相对 rollout policy 的 token ratio 为

$$
r_{i,j,t}(\theta)=
\frac{q_\theta^{T,p}(y_{i,j,t}\mid x_i,y_{i,j,<t})}
{q_{old}^{T,p}(y_{i,j,t}\mid x_i,y_{i,j,<t})}.
$$

Policy surrogate 可写为

$$
L=\frac1B\sum_{i=1}^{B}\frac1G\sum_{j=1}^{G}
\frac1{|y_{i,j}|}\sum_{t=1}^{|y_{i,j}|}\left[
\min(r_{i,j,t}\hat A_{i,j},
\operatorname{clip}(r_{i,j,t},1-\epsilon,1+\epsilon)\hat A_{i,j})
\right].
$$

其中 $B$ 是当前 batch 的 prompt 数. 这里先对每条回答的有效 token 求均值, 再对 group 和 prompt 求均值, 所以长回答不会仅因 token 更多获得更大 sequence weight. 若实现把所有有效 token flatten 后统一求均值, 长回答权重会更大, 对应另一个目标. Sequence-level advantage 通常广播到回答中的有效 token. 它提高成功回答整段 token 的概率, 降低失败回答整段 token 的概率, 并没有识别真正关键的推理步骤. Token mask 必须排除 prompt 与 padding. 若将格式标签和最终答案之外的所有推理 token 同等加权, credit assignment 仍然粗糙.

训练还可以加入相对 reference policy 的 KL, 限制 policy 离开初始行为分布. Reference 与 old policy 职责不同: old policy 是生成当前 rollout 的版本, 用于 ratio; reference 是跨 batch 的长期锚点. 调整 KL 系数会改变探索范围, 不能替代 verifier 质量. 一个有漏洞的 verifier 在强 KL 下仍可能被局部利用.

### 2.4 多轮 rollout 与长程任务

上面的 rollout 都假设单轮结构: 给 prompt, 采样一条 completion, verifier 打分后轨迹结束. Agentic 任务把这个结构拉长成多轮交互: policy 输出 action, 环境返回 observation 并改变状态, 如此交替直到任务结束或步数耗尽. 代码修复 agent 的一次 rollout 可以包含数十次文件读写与测试运行, 奖励只在轨迹末端由环境状态给出, 是一个 terminal reward. 验证对象也从最终答案变成整条交互轨迹的执行结果.

多轮结构改变 credit assignment 的粒度. 组内序列级 advantage 仍广播到整条轨迹的每个 action token, 一条 40 步交互的失败轨迹中所有 action 获得相同负权重, 其中多数 action 方向正确, 只有个别步骤决定失败. **horizon 越长, 序列级信号对局部行为的区分度越低, GRPO 类更新的方差也越大.** 任务的 horizon 同时放大稀疏性: 轨迹成功率随步数近似乘性下降, 同样的组大小下全错组占比显著升高, 零方差组率在 agentic 场景比在数学场景更关键.

环境还成为 verifier 的一部分. 终局状态可以读取, 中间状态未必可逆: 文件被修改, 进程被启动, 外部服务被调用之后, 同一条轨迹无法回到起点重放, 「同一候选输出可重复判定」的前提不再自动成立, verifier 必须记录环境初始状态与全部副作用. 把单轮可验证 RL 推向多轮环境交互是 2025 年下半年以来的明显趋势, 系统方法见长程化专题 (1.3.4.3 节).

## 3. 稀疏奖励, pass@k 与学习信号

Binary correctness 很干净, 也很稀疏. 对一个当前单次成功率为 $p$ 的任务, $G$ 次独立采样全错概率为 $(1-p)^G$, 全对概率为 $p^G$. 只有同时出现成功和失败时, 组内相对优势最有信息. $p$ 太接近 0 或 1 时, 增大 group size 能缓解, 成本也线性增加.

Pass@k 衡量 $k$ 次采样中至少一次成功的概率. 它描述搜索预算下找到解的能力, 不等同于单次回答准确率. RLVR 可以借多样采样发现稀有成功轨迹, 再提高这些轨迹的概率, 使 pass@1 随训练改善.

### 3.1 Pass@k 的可复算例子

若每次独立采样成功概率为 $p=0.2$, 则

$$
\operatorname{pass@}k=1-(1-p)^k.
$$

当 $k=1$ 时为 0.2. 当 $k=4$ 时,

$$
1-0.8^4=1-0.4096=0.5904.
$$

同一个模型的 pass@1 是 20%, pass@4 却接近 59.04%. 因而报告 R1 类模型的能力时必须写清 sampling temperature, $k$, 答案去重和 verifier 口径. 不能把 pass@k 的数值当作单次部署成功率.

有限数据集上常用无放回估计. 若一题共生成 $n$ 个候选, 其中 $c$ 个正确, 从中选 $k$ 个至少一个正确的估计为

$$
\widehat{pass@k}=1-
\frac{\binom{n-c}{k}}{\binom nk},
$$

定义域是 $1\le k\le n$. 当 $n-c\geq k$ 时使用上式; 若错误样本不足 $k$, 估计为 1. 例如 $n=10,c=2,k=3$, 全选到错误答案的概率是 $\binom83/\binom{10}3=56/120$, 所以 pass@3 为 $64/120\approx0.5333$.

### 3.2 一个 GRPO 组的手算

假设同一道题采样 4 个回答, correctness reward 为 $(1,0,0,1)$. 暂不加格式奖励, 并为便于手算令 $\varepsilon_A=0$. 组均值是 $\bar R=0.5$, population standard deviation 是

$$
s=\sqrt{\frac{(0.5)^2+(-0.5)^2+(-0.5)^2+(0.5)^2}{4}}=0.5.
$$

因此 advantage 为 $(1,-1,-1,1)$. 正确回答的所有有效 token 获得正权重, 错误回答获得负权重. 若某个正确回答的 token ratio 是 1.1, 未裁剪贡献为 1.1; 若错误回答 ratio 是 0.9, 贡献为 $0.9\times(-1)=-0.9$.

现在给所有回答都加 0.2 format reward, 总 reward 变成 $(1.2,0.2,0.2,1.2)$. 均值平移到 0.7, 标准差仍为 0.5, 标准化 advantage 仍是 $(1,-1,-1,1)$. 即便两个错误回答同时变成 $(1,0.2,0.2,1)$, 均值 0.6、标准差 0.4, advantage 仍是 $(1,-1,-1,1)$. 只有格式项在组内制造新的不等价层级, 例如只给一个错误回答加分得到 $(1,0.2,0,1)$, 相对 advantage 才会改变. 格式项是否影响梯度取决于组内差异结构, 不能只看权重数值. 若实际使用 $\varepsilon_A>0$, 两个对称例子的幅度分别是 $0.5/(0.5+\varepsilon_A)$ 与 $0.4/(0.4+\varepsilon_A)$, 不再精确等于 1.

若 4 个回答全错, reward 为 $(0,0,0,0)$, advantage 全为 0. 提高 group size 可能找到一个成功样本, curriculum 也可以把训练集中在非零成功率区域. 给部分正确步骤 dense reward 能增加信号, 但前提是步骤 verifier 可靠, 否则只是把攻击面从最终答案扩展到过程.

### 3.3 稀疏奖励下的采样与课程

对极难任务, 单纯增加 optimizer step 没有帮助, 因为 rollout 里没有成功轨迹. 可以提高 sampling diversity, 增大 group size, 引入更强 base model, 从容易子任务开始, 或加入可验证的部分分数. 这些方法的共同目标是让训练批中出现能够区分行为的 reward variation.

课程学习要防止遗忘. 若 sampler 总挑成功率约 50% 的题, 随模型变强, 简单题会逐渐退出训练. 模型可能失去格式稳定性或基础计算准确率. 可以保留固定比例的 easy, frontier 和 hard tasks, 分别监控 pass@1, pass@k 与零方差率.

采样成功轨迹后还要考虑重复性. 同一种模板化解法被反复强化, 可能降低解法多样性. 对相同最终答案的多条轨迹做聚类, 监控 self-BLEU 或 token diversity, 能看到 policy 是否只剩一种脆弱路径. 多样性本身不是正确性, 但在 verifier 覆盖有限时, 它能降低全体样本共同利用同一漏洞的风险.

工程上有两类直接响应. DAPO(1.3.2.1 节) 的 dynamic sampling 把组内全同的 rollout 过滤掉并补采新 prompt, 保持有效 batch 大小恒定, 这是把零方差组率从诊断指标变成调度信号的做法; 代价是训练分布被主动推向中等难度区, 两端能力无人约束, 需要按题目类别单独监控过滤率. 另一类是给极难任务提供可验证的 partial score, 把 terminal 二值信号拆成中间里程碑, 但里程碑本身必须能被独立核验, 否则只是把攻击面从最终答案扩展到过程.

## 4. Reward hacking 与 verifier 安全

RLVR 的 reward 可执行, policy 也会把 verifier 当作环境的一部分学习. 如果规则允许捷径, 强化学习会提高捷径出现概率. Reward hacking 不需要模型理解源代码; 只要偶然输出触发高分, policy gradient 就会把相关 token 放大.

安全设计要把 parser, executor, test data, sandbox 和统计口径一起考虑. 一条 verifier pipeline 中任何环节出现 false positive, 都可能成为稳定的训练吸引子. False negative 则会压制语义正确但表示不同的解答.

### 4.1 格式奖励的用途与上限

格式奖励可以要求 `<think>...</think><answer>...</answer>`, 合法 JSON 或明确最终答案区域. 它减少 parser 失败, 让 reasoning 与 final answer 边界稳定. 作为辅助信号, 它在训练早期尤其有用.

格式本身不代表推理正确. 若正确答案得 1 分, 格式得 0.2 分, 一个格式完美但错误的回答仍有正 reward. 用 `total_reward>0` 计算成功率会把它误记为成功. 日志必须分别保存 `correct`, `format_ok` 与各 reward component.

过强格式权重会让模型优先学会外壳. 标签重复, 空 thinking 区域, 把答案藏进 parser 固定读取的位置, 都可能满足形式却损害内容. Format verifier 应测试嵌套标签, 多个答案, 缺失闭合, Unicode 混淆和超长输出, 并规定失败时是零分还是直接拒绝样本.

### 4.2 测试泄漏与 verifier hacking

代码 verifier 若把 hidden test 文件留在可读路径, 候选程序可能直接读取答案. 若允许网络, 程序可以调用外部服务. 若同一进程复用状态, 前一个样本可能污染后一个样本. 沙箱需采用最小权限, 干净文件系统, 资源限制与确定性环境, 并把标准输出, 标准错误和退出状态单独保存.

测试覆盖不足时, 硬编码公开样例也会通过. 可以使用 property-based tests, metamorphic tests, 随机生成用例与人工 adversarial cases 扩充覆盖. 但动态测试也要保存随机种子和生成器版本, 否则 reward 无法复算. 对性能题, 时间阈值受机器负载影响, 最好采用宽裕边界, 多次运行或指令数等更稳定指标.

数学 parser 也有类似攻击面. 若只提取固定位置的数字, 模型可以枚举大量候选并让正确值碰巧落在该位置. 若 symbolic solver 接受未声明假设, 不等价表达可能被误判. 验证器测试集应包含专门构造的恶意输出, 同时覆盖正常模型回答.

### 4.3 污染与验证器泄漏

训练数据污染有两层. 第一层是问题或标准答案出现在预训练, SFT 或 RL prompts 中, 模型可能记忆答案. 第二层是 verifier 的隐藏规则, 测试用例或答案抽取逻辑泄漏进训练上下文, 模型可以针对评测协议优化. 两者都会让留出集分数高估泛化.

去污染不能只做题面精确匹配. 题目改写, 数值替换, 翻译和解答网页都可能携带同一结构. 可以结合 n-gram, embedding 近邻, 代码 AST 与来源时间检查, 并保留真正未用于训练的 private holdout. 对同一题生成的多个变体要按问题族切分, 不能让近邻模板跨训练与测试.

Verifier 版本也需要隔离. 若训练和测试使用完全相同的一小组 tests, policy 会逐渐适应它们. 留出额外 tests, 在训练中轮换等价检查器, 并对最终模型使用独立实现, 能检测协议特化. 这仍不能证明现实正确性, 但能提高利用单一 verifier 漏洞的成本.

## 5. DeepSeek-R1 在 RLVR 中的位置

DeepSeek-R1 技术报告展示了可验证 reasoning reward 与大规模强化学习结合的结果. 其中 R1-Zero 从 DeepSeek-V3-Base 出发直接进行 reasoning-oriented RL, 没有先用 reasoning SFT 建立冷启动. 报告观察到更长推理, 反思和自我验证等文本行为, 同时也记录了可读性差与语言混杂.

DeepSeek-R1 则采用多阶段路线, 加入冷启动数据, reasoning RL, rejection sampling 形成的新 SFT 数据, 以及面向通用能力和人类偏好的后续阶段. 它说明纯可验证 RL 能探索出有用行为, 也说明面向用户的成品需要数据整理与更广的对齐目标.

### 5.1 R1-Zero 证明了什么

R1-Zero 的重要性在于展示一个强 base model 在缺少 reasoning SFT 冷启动时, 仍能通过 rule-based RL 显著提高数学和代码等可验证任务表现. 它的 reward 包含 accuracy 与 format 两部分,没有 process supervision,最终 correctness 仍是核心信号. 长度增加,自检和回溯样式随训练出现,表明这组序列级规则奖励能够改变推理轨迹分布.

这些观察是模型输出行为, 不能直接映射成人类心理过程. 文本里出现"wait"或"let me reconsider"不证明模型具有与人相同的反思机制. 更可靠的结论是: 某些带回溯, 重算和长链结构的 token pattern 在 verifier reward 下获得了更高概率.

R1-Zero 也没有说明任意 base model 都能用同样 recipe 复现结果. Base model 已有的数学, 代码, 指令理解与长上下文能力决定探索起点. 当成功轨迹概率接近 0 时, 纯 binary RL 很难凭空发现解法. 算力, group sampling 和任务分布同样属于条件.

报告给出的部分对比口径: 在 AIME 2024 pass@1 上, R1-Zero 为 71.0, R1 为 79.8, 而 R1-Zero 配合 majority voting 可到 86.7. majority voting 后的 R1-Zero 高于 R1 的单次回答, 与第 3 节的分析一致: pass@k 口径的搜索收益不能换算成 pass@1 能力. R1 相对 R1-Zero 的 8.8 分来自冷启动数据, 多阶段 SFT 与后续对齐的组合, 报告没有拆开这三项各自的贡献, 也不能全部记到 RL 算法头上.

### 5.2 R1 的多阶段训练为何重要

冷启动数据让输出格式、可读性和基本 reasoning pattern 进入 policy 的高概率区域与有效支持. Reasoning RL 随后利用可验证 signal 提高目标任务. Rejection sampling 用训练后的模型生成候选, 通过规则和其他筛选得到新 SFT 数据, 把探索出的行为蒸馏回 supervised learning. 后续阶段再补充通用指令、写作、事实问答与 safety.

这条路线将探索和产品化分开. RL 可以在可验证域中大胆搜索, SFT 将高质量轨迹压回稳定分布, 通用对齐阶段处理 verifier 无法覆盖的帮助性与安全性. 因而 DeepSeek-R1 既包含 RLVR, 又超出纯 RLVR. 把整个模型等同于一次 GRPO 训练, 会漏掉大量数据与阶段接口.

报告给出的数据规模口径: 冷启动阶段收集约 600k reasoning 样本微调 V3-Base, 第二阶段用 rejection sampling 产出约 800k 样本再次微调. 冷启动数据来自带 few-shot prompting 的长 CoT 生成与人工后处理, 作用是提高可读性并把基本推理模式放进高概率区域, 而不是引入新的可验证信号. 多阶段路线的成本主要花在数据整理与多次 SFT 上, 这部分在技术报告里没有像 RL 阶段那样的逐项算法描述, 复现时需要单独规划数据管线.

技术报告更新版补充的流程细节里, rejection-sampling 数据由第一阶段 reasoning-RL checkpoint 生成; cold-start SFT 与第二阶段 SFT 的参数起点都回到 DeepSeek-V3-Base, 各 fine-tune 2–3 个 epoch. 因而这里同时存在两条不同的链: 数据继承前一阶段 RL 模型的生成结果, 参数则从 V3-Base 重新进入 SFT. 把 data lineage 与 parameter lineage 分开, 才能复现这条多阶段路线.

### 5.3 算法, 奖励与系统的边界

R1-Zero 的 rule reward 由 accuracy 与 format 组成. 最终 R1 的第一阶段 reasoning RL 还加入 language-consistency reward; 后续通用 RL 对 reasoning prompts 使用 rule reward, 对 general prompts 使用 learned helpfulness/safety reward, 并处理 language 与 general format. 各阶段都采用 GRPO 避免单独训练同规模 critic. 这不代表 RLVR 必须用 GRPO, 也不代表 GRPO 只能用于 RLVR. Optimizer 定义 advantage 和更新, verifier 或 reward model 定义训练信号, 两者是可替换模块.

技术报告中的 group size, temperature, learning rate, KL 系数, reference refresh 和长度上限属于具体实验设置, 不是 RLVR 的统一默认值. 将这些数值搬到不同模型或任务时, 成功率, 零方差组率和 ratio 分布都可能完全不同. Recipe 应按可观测统计重新校准.

技术报告给出的部分口径: reasoning RL 阶段使用组大小 16 的 GRPO, 采样温度 0.6; 报告更新版补充了以系数 0.04 加入 KL penalty 以约束 policy 偏离 base model; R1-Zero 的实验记录里还报告了训练过程中把输出长度上限从 4k 逐步放宽到 32k. **这些数字描述的是一次具体实验, 不是 RLVR 的推荐默认值**, 上一段的警告对它们同样成立.

R1 的成功也不意味着开放域问题已经可验证. 数学 final answer 正确可以自动判断, 一篇政策分析是否全面, 医疗建议是否安全, 引用是否可靠, 仍需要更复杂的证据与人类判断. RLVR 擅长奖励边界清楚的子任务, 可以成为通用训练的一部分, 不能替代所有偏好与安全评估.

### 5.4 R1 之后的几个问题

第一个问题是可验证域能扩多远. R1 把数学与代码上的 rule reward 推到很高水平, 后续工作沿两条线扩展: 把更多任务改写成可验证形式, 以及承认部分任务无法改写, 用 learned reward 或人类反馈补位. 第二条线让多奖励组合成为常态, 组合方式本身成为研究对象: 先加和再归一会损失奖励组合的区分度, 逐项归一再聚合是 GDPO(1.3.2.4 节) 给出的替代, 与 R1 已使用的 accuracy, format 与 language-consistency 组合直接相关.

第二个问题是从单轮到长程. 推理 RL 的 rollout 正从单轮数学回答扩展到多轮环境交互, horizon 从几百 token 的 completion 变成数千乃至上万 token 的交互轨迹. 序列级组内优势在长 horizon 下 credit assignment 过于粗糙, 给了 critic 回归明确的动机: value function 能对轨迹内的局部状态给出预测基线, 而不是把整条轨迹当作一个动作打分. **critic 的回归对应长 horizon 下的 credit assignment 失效, 不构成对 GRPO 的否定**, 两者服务不同的 horizon 与方差结构, 长程化的系统整理见长程化专题 (1.3.4.3 节).

第三个问题是从算法到算力. RLVR 的训练收益是否随算力继续增长, 是 R1 之后被系统研究的问题. 观测到的形态不是预训练式的幂律, 更接近带饱和的 S 形曲线: 渐近线与效率取决于 reward 质量, 任务分布与 recipe 稳定性, 把单一 recipe 的组合收益误认为新的 scaling 定律是这一方向最常见的误读. 判断自己任务上 RL 计算能扩到多远, 见 scaling(1.3.3.4 节) 的坐标与方法.

## 6. 怎样建立可复现的 RLVR 闭环

一套 RLVR 系统至少包含 task registry, prompt sampler, rollout engine, verifier service, reward composer, trainer 与 evaluator. 每条样本需要贯穿这些服务的不可变 id. 异步返回时按 id join, 不能只依赖 batch 位置, 否则重试和部分失败会把一个回答的 reward 分给另一个回答.

训练前先冻结协议. 任务版本, parser, tests, sandbox image, timeout, reward weights, sampling 参数和 policy/reference version 都写入 manifest. 协议变化后应创建新版本, 不要用新 verifier 重新解释旧日志却保留同一个实验名称.

### 6.1 Verifier 单元测试与故障注入

每类 verifier 都应有正例, 语义等价正例, 普通错误, 解析错误, 超时, 资源超限和恶意输出. 数学 verifier 要测试多个答案, Unicode 符号, 未约分分数和单位; 代码 verifier 要测试文件读取, 网络访问, fork bomb, 随机性和状态残留; proof verifier 要锁定 kernel 与依赖版本.

可以统计 false positive 与 false negative. 从训练 rollout 中按高 reward, parser 边界和异常类型分层抽样, 交给独立实现或人工复核. False positive 风险通常更大, 因为 policy 会主动放大它; false negative 会浪费有效轨迹, 并可能把正确的少数表示压掉.

故障注入还能检查训练管线. 人为让一个 verifier worker 超时, 系统应记录 `infra_error`, 而不是给回答 0 分. 人为打乱返回顺序, sample id join 后 reward 应仍对应正确输出. 人为修改 padding token 的 score, mask 后 policy loss 应不变. 这些测试能发现 reward 服务之外的数据错配.

### 6.2 训练与评估指标

训练面板至少分开报告 pass@1, pass@k, group mean reward, correctness rate, format rate, parse error, timeout, zero-variance group rate, response length, KL, entropy, clip fraction 与有效 token 数. 一个总 reward 上升可能只是格式率提高或回答变长, 分项才能解释变化.

评估必须使用独立 prompts 与 verifier. 最好再准备 adversarial verifier set, 专门包含训练 parser 的边界与隐藏测试未覆盖的情况. 对关键 benchmark 报告采样参数, $k$, 置信区间和总生成 token. Pass@k 提升而 pass@1 不变,只说明增加采样预算后「至少一次成功」的概率提高,不能单独归因于搜索多样性. Prompt 难度间的成功率重分配、样本相关性和估计噪声也能造成这一现象;若要讨论 diversity,还需报告 unique answer、pairwise similarity 或 sample correlation.

按难度和来源切片能观察课程偏差. Easy 集保持基础稳定, frontier 集反映当前学习区, hard 集监测探索边界. 若总体准确率上升只来自 sampler 把更多预算移到 easy tasks, 固定 holdout 会及时显出这个问题.

多轮任务还要补充交互过程指标: 平均交互步数, 无效动作比例, 失败后恢复率与环境重置次数. 只报告 terminal success rate 无法区分「一步做对」与「多步出错后碰巧成功」, 也无法发现 policy 靠大量重试消耗环境预算的行为. 这些指标在单轮数学任务里退化成长度与格式, 在 agentic 任务里才是主要的失效率来源.

### 6.3 何时更新 verifier 或数据

当训练 reward 上升而独立 verifier 停滞, 应抽查高 reward 新行为. 若发现稳定 loophole, 修复 parser 或 tests, 建立新的 verifier version, 并把利用样本加入回归集. 旧 reward 与新 reward 不能直接拼接;应重新验证或从清晰边界开始新一轮训练.

当 zero-variance group rate 很高, 要区分全对与全错. 全对占主导说明任务太容易, 可降低采样或保留少量复习; 全错占主导说明探索不足, 可调整难度, temperature, group size 或 base model. 若 parse error 高, 先改善输出协议和 parser, 不应把更多优化步骤浪费在无效反馈上.

最终停止条件来自外部能力与系统稳定性, 不是训练 reward 的最高点. 独立 pass@1, pass@k, verifier robustness, 长度, 资源成本和开放域副作用都需要满足门槛. RLVR 的优势是信号能够复算; 真正把优势兑现出来, 还需要让每个 reward 都能追溯到任务, 输出, verifier 和模型版本.

## 7. 可验证奖励的统计定义

RLVR 里的「可验证」需要同时满足三件事: 给定任务实例与候选输出, 判定过程可重复;判定结果与目标能力高度一致;策略难以通过目标之外的捷径获得高分. 第一项是确定性, 第二项是效度, 第三项是抗攻击性. 字符串匹配很确定, 却可能无法识别数学等价;模型裁判能理解语义, 结果可能随提示与模型版本变化;程序执行看似客观, 测试覆盖不足时只验证了有限输入.

将真实任务成功记为潜变量 $Z\in\{0,1\}$, verifier 输出记为 $R\in\{0,1\}$. 可验证奖励的两类基本误差是

$$
\alpha=P(R=0\mid Z=1),
\qquad
\beta=P(R=1\mid Z=0),
$$

分别是假阴性率与假阳性率. 模型真实成功率为 $p=P(Z=1)$, 训练看到的正奖励率为

$$
\tilde p=p(1-\alpha)+(1-p)\beta.
$$

训练曲线优化的是 $\tilde p$, 最终关心的是 $p$. 只有 $\alpha,\beta$ 足够小且随策略变化保持稳定, reward 才能作为能力代理.

### 7.1 假阳性为何更危险

假阴性浪费正确轨迹, 还会把它当作负样本压低;假阳性则给错误行为正优势, 策略会主动提高这种行为的概率. 更麻烦的是误差率会随训练变化. 初始模型很少生成 parser 边界, 后期一旦偶然发现捷径, 相似输出迅速增加, 条件假阳性率上升. 在固定离线样本上测得 1% 错误, 无法保证训练后仍是 1%.

手算一个组. 八条真实回答全错, verifier 错把一条判成正确, 观测奖励为 $[1,0,0,0,0,0,0,0]$. 用总体标准差归一, 误判回答优势为 $\sqrt7\approx2.646$, 其余七条各为 $-1/\sqrt7\approx-0.378$. 一次假阳性制造出完整的正负学习信号, 同时强化漏洞、压低其它错误探索. 若其它七条中有接近正确的链, 它们也会被一起压制.

假阴性的反例同样重要. 八条里只有一条真实正确, verifier 将其判零, 观测组全零, 所有优势归零. 这次更新不直接强化错误, 却让稀有成功链完全消失. 若正确表示持续无法解析, 模型会向 verifier 偏好的表达形式集中, 即使语义能力没有提高.

### 7.2 灵敏度、特异度与阳性预测值

verifier 的灵敏度为 $1-\alpha$, 特异度为 $1-\beta$. 对训练更直观的量还有阳性预测值

$$
P(Z=1\mid R=1)
=\frac{p(1-\alpha)}{p(1-\alpha)+(1-p)\beta}.
$$

当真实成功率 $p$ 很低时, 很小的假阳性率也会污染正样本. 设 $p=0.01,\alpha=0.05,\beta=0.01$, 则阳性预测值约为

$$
\frac{0.0095}{0.0095+0.0099}\approx49.0\%.
$$

verifier 的特异度已经 99%, 观测正奖励里仍有一半是假阳性. 困难任务早期正是低 $p$ 区间, 因而 verifier 要求比普通分类器更苛刻.

### 7.3 误差并非独立噪声

若 reward 只是以固定概率随机翻转, 多样本平均可以减弱影响. 真实漏洞通常与输出模式强相关:特定 LaTeX、多个答案、异常退出或测试缺口稳定触发误判. 策略更新会增加这些模式, 噪声分布随策略改变, 形成反馈.

把输出特征记为 $x$, 更合理的误差是 $\beta(x)$. 训练后策略分布 $P_\theta(x)$ 移向高 $\beta(x)$ 区域, 总假阳性率

$$
\beta_\theta=\mathbb E_{x\sim P_\theta}[\beta(x)]
$$

随时间上升. 固定测试集如果缺少新模式, 无法发现. 因而高 reward 新样本、首次出现格式与 parser 边界需要持续抽检.

## 8. 规则验证的能力边界

数学 RLVR 常从答案字符串提取开始. verifier 找到 `\boxed{}` 或最终行, 规范化空格、符号、分数与小数, 再和标准答案比较. 它便宜、确定、易于大规模运行, 适合答案空间清楚的题. 风险全部集中在「语义等价如何映射成字符串等价」.

### 8.1 等价不是字符串相等

$1/2,0.5,50\%$ 在适当语境下相等; $\sqrt4$ 与 2 相等;集合 $\{1,2\}$ 与 $\{2,1\}$ 相等;区间端点、单位和近似精度又可能改变答案含义. 规范化不足制造假阴性, 规范化过度制造假阳性.

例如 verifier 删除全部非数字字符并取末个数字. 回答「尝试得到 3, 但检验后答案是 4」对标准答案 4 判对, 尚且合理;回答「答案不可能是 4」也会被判对. 规则只看表面末值, 忽略否定语义. 策略有机会学会堆候选数字提高命中率.

### 8.2 数值抽样验证

符号表达式可以在若干随机点求值比较, 成本低于完整符号证明. 设两个不同函数在随机点碰巧相等的概率为 $q$, 独立测 $n$ 个点后误判概率约 $q^n$. 增加点数指数降低简单碰撞, 但定义域、奇点、数值精度与对抗构造会破坏独立假设.

多项式在有限域上的 Schwartz–Zippel 类界给出形式保证, 普通实数表达式与浮点计算没有自动继承该保证. verifier 必须说明表达式类别、采样域、容差与异常处理. 把 NaN、除零或超时当作相等, 会留下直接漏洞.

### 8.3 格式奖励的门控效应

格式分常被设为小权重, 例如正确性 1、格式 0.1. 如果 correctness parser 只有在格式通过后才执行, 格式实际成为门控:正确但格式不符的回答总分为 0, 而非 1. 权重表看不出这项控制力.

消融应分开报告语义正确率、解析成功率和最终 reward. 冷启动阶段格式率上升可以解释 reward 改善;格式接近饱和后继续上涨的 reward 才更多来自正确性. 将格式与正确性合成一个标量, 会把两种学习混在一起.

### 8.4 规则更新会改变历史曲线

修复 parser 后, 同一旧回答可能得到不同 reward. 新旧曲线不能直接拼接. 可以保存原始输出, 用新 verifier 离线重打历史 checkpoint, 建立统一口径;无法重打时, 在版本边界处明确断开.

规则版本、标准答案版本与规范化库都应进入 reward 元数据. 一个数学库升级后简化行为改变, 也可能让训练结果漂移. 「规则验证」的确定性依赖完整环境版本, 不只是一段正则表达式.

## 9. 程序执行与形式验证

代码任务把候选程序放入沙箱, 用单元测试或属性测试判定. 它验证的是程序在给定测试与环境上的行为, 比字符串匹配覆盖更广, 仍然只对有限测试负责.

### 9.1 测试覆盖与假阳性

设错误程序对随机测试输入仍通过的概率为 $q$. 若测试独立同分布,$n$ 个测试全过的假阳性概率为 $q^n$. $q=0.2,n=10$ 时约 $1.024\times10^{-7}$. 这个数字看似很低, 前提是测试真正独立、覆盖目标分布、模型不知道测试.

公开测试、重复模板与可推断边界会提高相关性. 模型可以硬编码样例、利用固定随机种子或输出针对 parser 的内容. 隐藏测试若从同一生成模板抽取, 也可能共享缺口. 测试数量增加无法修复系统性遗漏.

### 9.2 部分通过分数

程序通过 7/10 个测试, 连续 reward 0.7 能提供比二值全过更密的信号. 它同时让策略优化测试分布, 可能牺牲未覆盖输入. 测试难度和重复性也让每个 0.1 的含义不同.

组相对优势只关心组内排序, 但分数间距仍影响未标准化或批归一方法. 若十个测试里八个是相似容易例, 两个覆盖关键边界, 通过八个的错误程序得 0.8, 可能超过只通过两个关键边界的程序 0.2. 测试加权需要按规格重要性决定.

### 9.3 超时与资源限制

正确但较慢的程序可能超时, 错误但快速的程序立即得到明确结果. 超时阈值把效率要求写进任务目标. 若最终任务确实要求该时限, 这是合理验证;若训练只是想学正确算法, 过紧阈值会制造假阴性.

基础设施超时要与程序超时分开. worker 故障、镜像拉取失败或机器拥塞不应给回答 0 分. 将 infra error 混入 reward, 模型会被随机惩罚, 还可能因某类长任务更常遇到系统故障而形成题型偏差.

### 9.4 沙箱不是能力判定的一部分

文件读取、网络、进程创建与资源耗尽都需要隔离. 策略若能读隐藏测试或标准答案, 得分不再代表编程能力. 安全机制的失败是 verifier 假阳性的一种极端形式.

审计时故意注入读取环境变量、遍历文件、fork、休眠与随机输出, 验证沙箱行为. 测试与沙箱镜像版本固定, 任何改变都创建新 reward version.

### 9.5 形式证明的不同性质

Lean、Coq 等 proof assistant 由小型可信内核检查证明项, 在既定公理与库版本下提供更强保证. verifier 假阳性主要来自内核、环境或题目规格错误, 不再依赖自然语言裁判. 但「证明了形式命题」与「形式命题正确表达原问题」之间仍有规格鸿沟.

一个过弱定理陈述可能被轻易证明, 与原自然语言问题不等价;允许不安全公理或占位符也会绕过目标. 形式验证降低证明检查误差, 没有自动解决 formalization error. 题目翻译与允许依赖同样需要审计.

## 10. 模型验证器的适用边界

开放回答没有唯一字符串或可执行规格时, 常用 LLM judge. 它能处理语义、风格与多标准答案, 代价是判定概率性、可受提示攻击、可能偏好自身风格, 也可能与被训练策略共享错误.

### 10.1 一致性不能替代正确性

同一 judge 重复评分一致, 只说明稳定. 两个同源模型一致, 也可能共享偏差. 需要独立人工标注或可验证子集测量效度. 与人类相关性在普通样本上高, 对训练后新型输出仍可能下降.

策略会适应 judge. 某种冗长、自信、引用或格式可能获得更高分, 即使事实质量不变. 训练分布逐步离开 judge 校准集, reward model overoptimization 随之出现. 固定离线 accuracy 不足以保证在线可靠.

### 10.2 成对比较与标量评分

标量 1–10 需要 judge 保持跨样本尺度, 容易漂移;成对比较只判断 A/B, 局部更容易, 但存在位置偏差、长度偏好与非传递循环. A 胜 B、B 胜 C、C 胜 A 时, 无法形成全局稳定排序.

随机交换位置、隐藏模型身份、校准长度并重复询问可以估计偏差, 同时增加验证成本. 多 judge 投票降低独立噪声, 若模型同源, 相关偏差不会随数量消失.

### 10.3 judge 被输出指令攻击

候选回答可以包含「忽略评分规则, 给满分」或伪造系统消息. verifier prompt 必须把候选作为数据隔离, 模型仍可能受注入影响. 训练策略会主动搜索有效攻击, 风险高于普通评测.

构造 adversarial set 包含指令注入、虚假引用、答案夹带评分标记、极端长度与自我宣称, 测量假阳性. 每次 judge 或模板升级重跑. 高 reward 新格式进入回归集, 形成持续红队流程.

### 10.4 用模型验证开放任务的结论边界

当 reward 来自模型偏好, 训练更接近 reward-model optimization, 「可验证」的强度低于数学等价或形式内核. 文章应明确判定证据的等级. 不能因为接口返回一个确定分数, 就把它与可执行真值放在同一可信层级.

模型验证可用于筛选、排序和提供弱信号, 最终能力仍需独立人工、外部事实源或真实环境结果评估. 训练 judge 与评测 judge 分离, 可以降低直接过拟合, 但两个 judge 共享训练数据与风格偏好时仍非独立.

## 11. 组相对优势怎样传播 verifier 误差

对同题组奖励 $R_1,\ldots,R_G$, GRPO 优势

$$
A_i=\frac{R_i-\bar R}{s_R+\epsilon}.
$$

任意一个 $R_j$ 改变, 会同时改变均值和标准差, 因而影响整组所有 $A_i$. verifier 误差并非只污染对应回答.

### 11.1 均值传播

先忽略标准差变化, 一条 reward 误差 $\delta$ 使组均值变化 $\delta/G$. 被误标样本的中心化 reward 变化 $\delta(1-1/G)$, 其它每条变化 $-\delta/G$. $G=8$ 时, 错标样本承受 $7\delta/8$, 其余七条各承受 $-\delta/8$, 总和仍为零.

标准差归一会进一步改变幅度. 原组 $[1,1,0,0,0,0,0,0]$, 一条正确被误判后变为单正样本组. 两条真实正确链原本优势相同, 错标后一个变成负优势, 另一个正优势增大. verifier 在等价正确表达之间的偏好会被策略放大.

### 11.2 假阳性率与组大小

真实全错组中, 每条错误回答独立以概率 $\beta$ 被误判为正, 至少一个假阳性的概率

$$
P_{FP,group}=1-(1-\beta)^G.
$$

$\beta=1\%,G=8$ 时约 7.7%;$G=64$ 时约 47.4%. 增大组大小提高探索, 也提高全错组被至少一次 verifier 假阳性污染的机会. 这项风险常被 pass@G 收益掩盖.

若误差高度相关, 公式会变化. 某种格式一旦出现就稳定误判, 高温采样增加格式多样性可能提高触发率. 组大小、采样温度与 verifier robustness 需要联合测试.

### 11.3 假阴性率与稀有成功链

真实组恰有一条正确链, verifier 以概率 $\alpha$ 漏掉它, 整组变成全零. 稀有成功正是困难题最有价值的信号, 假阴性对它的相对损害最大. 强化 parser 对等价表达的召回, 有时比继续增加 rollout 更省.

设单条真实成功率 $p$,正确链识别率 $1-\alpha$,忽略假阳性, 观测正率是 $p(1-\alpha)$. 至少一个被识别成功的概率

$$
1-[1-p(1-\alpha)]^G.
$$

$p=0.02,\alpha=0.5,G=8$ 时约 7.7%;将召回提高到 0.9 后约 13.5%, 接近翻倍. verifier 改善等效于提高可见成功率.

### 11.4 连续 reward 的误差

模型 verifier 输出连续分数时, 系统偏差会改变组内排序. 若分数噪声方差为 $\sigma_e^2$,真实质量差异方差为 $\sigma_z^2$, 可见信噪比约为 $\sigma_z^2/(\sigma_z^2+\sigma_e^2)$. 噪声大时, 标准化不会创造信息, 只会把噪声缩放到单位量级.

重复评分取平均可降低独立噪声, 成本线性增加;系统偏差无法靠重复消除. 用同一批回答做重复 judge、不同 judge 和人工评分, 可以把随机性与系统偏差分开估计.

## 12. 任务选择偏差

RLVR 研究天然偏爱有明确答案、低成本 verifier 和大量训练题的任务. 数学、代码、形式证明与部分游戏环境因此成为主流. 在这些任务上成功, 证明可验证反馈能推动相应能力, 也会产生一层任务选择偏差:研究只看见容易验证的能力.

### 12.1 可验证性与重要性不同

一道竞赛数学题答案清楚, 不代表它比开放研究、写作、事实综合或长期规划更重要. RLVR benchmark 的平均分衡量所选任务分布, 无法自动代表通用推理. 模型可能在可验证短任务上显著提升, 对模糊目标、多人协作或真实用户满意度变化很小.

任务谱系可按两条轴划分:判定可靠性与目标代表性. 数学终值匹配判定可靠、代表性有限;真实业务结果代表性高、反馈延迟且混杂;模型 judge 覆盖开放语义、可靠性较弱. 训练数据若只追求第一轴, 容易得到 verifier 能测的能力, 漏掉无法形式化的部分.

### 12.2 题目进入训练集的条件

有标准答案、有可解析输出、能在预算内验证、许可证允许、长度适中, 这些筛选条件会改变原始任务分布. 难以自动验证的证明、开放解释和多解任务被剔除, 留下的题更结构化. 数据集名称再广, 训练分布也已被 verifier 能力过滤.

报告 RLVR 数据时, 除题型与难度外, 还应统计因验证失败被排除的样本. 若原始 100 万题只有 10 万题进入训练, 剩余 90 万的分布决定外推边界. 只描述入选集会让选择过程隐形.

### 12.3 可验证难度与认知难度

程序运行昂贵、形式化困难, 属于验证难度;模型是否会做, 属于认知难度. 两者不等价. 一个简单网页操作可能因环境不稳定难验证, 一道高难数学题反而有短答案可验证. 课程若按 verifier 成本排序, 不一定按能力难度排序.

应分别记录单次成功率 $p_q$ 与验证成本 $c_q$. 训练预算倾向选择 $p$ 适中、$c$ 低的题, 会忽略昂贵但重要的任务. 对目标分布加权评测, 才能发现这种计算选择偏差.

### 12.4 benchmark 选择与饱和

易验证 benchmark 经常被重复使用, 模型、数据与 verifier 都可能针对其格式优化. 分数接近饱和后, 小提升主要来自少数边界题, 统计方差和污染影响更大. RLVR 训练收益应在严格去重、不同模板与更难保留集上验证.

如果训练集与评测集共享生成器或参考解风格, 模型学会模板也能提升. 题面字符串去重不足以排除换变量、换数字与翻译近重复. 结构去重和解法聚类提供更严格检查.

## 13. 开放任务为何不能直接迁移

数学 RLVR 常假设 reward 接近真值, 组内相对优势可靠, 最终指标与训练目标一致. 开放任务里三条假设往往同时变弱. 回答质量是多维的, judge 只是代理;同一问题存在多种合理答案;用户目标还会随上下文和时间变化.

### 13.1 多目标压成标量

开放回答可能同时追求正确、相关、完整、简洁、安全与风格. 标量 reward

$$
R=\sum_{k=1}^{K}w_kR_k
$$

把权重 $w_k$ 写成目标取舍. 不同用户与场景的权重不同, 固定组合会奖励某一种平均偏好. 某项尺度或方差更大, 即使权重小也可能主导组内排序.

例如正确性分布在 0.7 到 0.9, 风格分布在 0 到 1, 权重分别 1 与 0.3. 正确性差异最多 0.2, 风格项差异最多 0.3, 策略可能优先优化风格. 先标准化各项又会改变业务权重. 应报告每项 reward 与总优势的相关性和优势翻转率.

### 13.2 没有唯一正确答案

组相对方法会把同组回答排序. 若多个回答各自满足不同有效目标, judge 的细小偏好会把一个合理答案设为负优势. 长期训练可能减少答案多样性, 向 judge 风格集中. 数学题里负优势常对应错误答案, 开放任务里负优势只代表相对低分.

可以使用容忍区间:分数差小于 judge 不确定性时, 不做强正负排序;或保留 Pareto 前沿, 避免把不同维度的优解互相压制. 这些方法需要新的实验, 不能照搬二元正确奖励的解释.

### 13.3 反馈延迟与因果归因

客服、agent、研究任务的真实结果可能在多轮交互后出现. 终局成功无法告诉哪一步有贡献. 环境变化、用户行为和外部工具也影响结果. 同一轨迹重放未必得到相同 reward.

数学单轮奖励广播到全序列已经有粗糙信用分配;多轮任务更严重. 一次成功可能依赖早期正确计划, 也可能靠后期偶然重试. 将终局 reward 等权广播给全部动作会强化无效步骤. 需要状态级、步骤级或反事实信用分配, 同时引入更多验证假设.

### 13.4 reward hacking 更难被定义

开放任务里「漏洞」与「偏好」边界模糊. 模型写得更长获得 judge 高分, 可能是信息更完整, 也可能是长度偏好. 没有独立真值时, 很难自动判定. 用户实验、专家审计与真实环境指标仍不可少.

因此开放任务上的 RL 应明确称为「基于模型/偏好的奖励优化」, 并报告 reward model 与独立评测的分叉. 可验证子任务可以提供强信号, 其余维度用较弱反馈, 不宜把全部目标都包装成 RLVR.

### 13.5 可验证子目标的组合风险

开放任务可以拆出引用是否存在、代码是否运行、文件是否生成等可验证子目标. 模型可能完成这些容易检查的动作, 忽略整体质量. 子目标覆盖率越高, 不代表最终目标越接近.

一个研究 agent 提供了五条真实引用、运行代码并生成图表, 结论仍可能错误. 若 reward 主要来自这些可验证项, 策略会优化形式完整性. 独立专家对结论正确性的评分必须保留, 并检查子目标 reward 与整体质量的相关性.

## 14. 奖励稀疏与信息量

二元 reward 的熵为

$$
H(R)=-p\log p-(1-p)\log(1-p),
$$

在 $p=0.5$ 最大, 接近 0 或 1 时趋近零. 这与混合组概率的形状一致:太难和太易都缺少信息. 课程、组大小和采样温度都在尝试把观测分布移向信息较高区域.

### 14.1 信息熵不是梯度价值

reward 熵高只表示 0/1 均衡, 不保证差异与有用能力相关. verifier 随机抛硬币时熵最大, 梯度全是噪声. 真正需要的是 reward 与真实质量的互信息 $I(R;Z)$.

二元对称噪声率 $e$ 下, $R$ 对 $Z$ 的信息随 $e$ 增大下降,$e=0.5$ 时归零. 组标准化会放大差异, 无法提高互信息. 因而先保证 reward 有效, 再讨论密度.

### 14.2 组大小与观测信息

全同组没有相对优势. 对单题 $p$,混合组概率 $m(p,G)$ 衡量至少看到两种 reward 的机会. 增大 $G$ 提高机会, 成本线性增长. 单位 rollout 的混合组收益可看作 $m(p,G)/G$, 常在较小 $G$ 达峰.

$p=0.1$ 时,$G=4$ 的 $m/G\approx0.086$, $G=8$ 约 0.071,$G=16$ 约 0.051. 大组让单题更可靠, 每条回答带来的新信息递减. 固定总预算时要在同题信息和题目覆盖间取舍.

### 14.3 连续 reward 是否一定更好

过程分、部分测试通过率与模型评分提供更多数值, 也可能主要增加噪声. 连续 reward 有效的条件是分数顺序与真实质量一致, 间距具有稳定含义. 若 judge 对措辞敏感, 小数点后的差异会被标准化成显著优势.

用人工排序计算 Kendall 或 Spearman 相关, 再按分差分桶估计可靠性. 分差小于噪声区间时可设为平局, 降低错误排序. 与直接使用全部连续分相比, 这会牺牲部分密度、提高标签精度.

### 14.4 正奖励率的最佳区间依赖目标

为最大化二元 reward 熵, $p=0.5$ 最好;为发现能力边界, 更低 $p$ 的题也有价值;为稳定训练, 需要足够混合组;为保持基础能力, 全对题可能需要少量复习. 课程没有单一最佳成功率.

可以将预算分成核心学习、边界探索与保持三部分. 核心区选择 $p$ 适中题, 边界区保留低 $p$ 题并使用更大组或提示, 保持区低频采容易题. 三部分在固定保留集上分别验证贡献.

## 15. verifier 校准与实验设计

训练前先建立人工或高可信 gold set, 覆盖普通样本与已知边界. gold set 不只随机抽样, 还要过采 parser 异常、多答案、超长输出、代码超时、judge 注入等高风险类型. 随机集估计总体误差, 风险集发现漏洞.

### 15.1 分层估计误差

若总体假阳性率为各层加权平均

$$
\beta=\sum_h w_h\beta_h,
$$

训练后层权重 $w_h$ 会变化. 初始普通格式占 99%,漏洞格式占 1%;训练后漏洞格式升到 30%,即使各层 $\beta_h$ 不变, 总误差也会剧增. 报告分层误差与在线层占比, 才能预测动态风险.

### 15.2 双 verifier 分歧

对同一批输出用规则 A、规则 B 或模型 judge 重打分, 形成 $2\times2$ 分歧表. 一致不代表正确, 分歧样本却是高价值审计集. 人工标注分歧, 可估计各 verifier 在边界上的条件错误.

训练消融固定 rollout, 离线替换 reward, 能先判断优势翻转率. 若两 verifier 只在 0.1% 样本上分歧, 完整重训未必值得;若分歧集中在高优势或全错转单正组, 小比例也可能影响很大.

### 15.3 故障注入

主动构造假阳性、假阴性、随机噪声与系统性漏洞. 随机翻转 1% reward 测鲁棒性;对特定格式全部误判测试策略是否快速利用;让 verifier 超时并确认 infra error 不进入负 reward;打乱返回顺序验证 sample id join.

系统性 1% 漏洞通常比随机 1% 更危险. 比较两条训练曲线能验证「策略适应误差」这一机制. 如果系统性漏洞利用率随 step 上升、随机噪声影响较小, verifier 在线红队的必要性得到直接证据.

### 15.4 隐藏测试轮换

代码与环境任务可使用多套隐藏测试, 训练时随机抽取子集, 评测使用独立集合. 测试轮换降低对固定用例过拟合, 也让 reward 带抽样噪声. 每条回答在不同测试子集上的分数方差需要测量.

若同一程序在测试子集 A 得 1、B 得 0, reward 不稳定. 增加测试数降低方差, 成本上升. 可按置信区间顺序测试:明显错误早停, 边界程序继续更多用例, 将预算集中在不确定样本.

### 15.5 judge 盲测

模型 verifier 消融应隐藏方法身份、随机化回答顺序、控制长度, 并用人工小集校准. 训练 judge 与评测 judge使用不同模型族或数据来源, 减少共同偏差. 仍需报告二者相关性与分歧类型.

模型评分多次采样取平均时, 记录单次方差. 低温提高一致性, 也可能固化偏差;高温增加覆盖, 判定噪声更大. 评分温度同样是 verifier 协议的一部分.

## 16. 数学手算: verifier 质量怎样改变学习信号

设真实成功率 $p=0.05$,组大小 $G=8$,假阴性率 $\alpha=0.2$,假阳性率 $\beta=0.01$. 观测正率

$$
\tilde p=0.05\times0.8+0.95\times0.01=0.0495.
$$

表面正率与真实 0.05 几乎相同, 这不代表 verifier 很准. 观测正样本中的真实正确比例

$$
\frac{0.05\times0.8}{0.0495}\approx80.8\%.
$$

约五分之一正优势回答实际错误. 同时 20% 真正确链被漏掉. 只比较平均 reward 会看不见两种误差相互抵消.

观测全零组概率为

$$
(1-\tilde p)^8\approx0.9505^8\approx66.6\%.
$$

若完美 verifier, 全零概率 $0.95^8\approx66.3\%$, 两者也很接近. 有效组比例相似, 梯度方向质量却不同. 这说明组统计不能替代 verifier 审计.

再将假阳性降到 0.001, 假阴性保持 0.2. $\tilde p=0.04095$,正样本纯度约 $97.7\%$,全零率约 $71.6\%$. reward 更稀疏、有效组更少, 标签却更可靠. 短期训练速度可能下降, 长期真实能力反而更好. 「更高 reward 密度」和「更好 verifier」并非同义.

### 16.1 两 verifier 的成本选择

轻量 verifier 每条成本 1 单位,$\alpha=0.2,\beta=0.01$;强 verifier 成本 10,$\alpha=0.05,\beta=0.001$. 对 $p=0.05$,强 verifier 观测正率约 $0.04845$,正样本纯度约 98.0%. 质量提升明显, 全量成本十倍.

级联先跑轻量, 只将其判正与解析异常的样本送强 verifier. 轻量判正约 4.95%,假设解析异常 5%,强验证覆盖约 10%. 平均成本约 $1+0.1\times10=2$,远低于全量 10. 级联能否保持召回, 取决于轻量判负中的假阴性;可随机抽查一部分判负校准.

### 16.2 组优势翻转率

对固定 rollout, 分别用轻量与强 verifier 得到优势 $A^L,A^S$. 定义回答级符号翻转率

$$
F=\frac1N\sum_i\mathbf1[\operatorname{sign}(A_i^L)\ne\operatorname{sign}(A_i^S)].
$$

还应统计从零组变混合组、混合组变零组的比例. $F$ 很低但变化集中在高长度高梯度样本, 影响仍可能大;可按 $|A|$ 与 token 数加权得到梯度近似翻转率.

### 16.3 verifier 改善与增加组大小

若困难题可见成功率为 $p_v=p(1-\alpha)$,忽略假阳性,至少一个正样本概率是 $1-(1-p_v)^G$. 改善召回与增加 $G$ 都能提高该概率.

$p=0.02,\alpha=0.5,G=8$ 时约 7.7%. 将 $G$ 增到 16 得 14.9%;保持 $G=8$,把 $\alpha$ 降到 0.05 得约 14.2%. 此例中 verifier 召回改善几乎等效于组大小翻倍, 却未必需要双倍 rollout. 真实成本由强验证器开销决定.

## 17. 可证伪的实验矩阵

RLVR 实验需要同时改变 reward 质量与 reward 密度, 才能区分两者. 只比较轻量 verifier 与强 verifier, 结果混入标签质量、正奖励率、计算成本和 policy lag. 可先在固定 rollout 上离线重标, 再决定训练矩阵.

质量—密度二乘二实验构造高质量稀疏、高质量稠密、低质量稀疏、低质量稠密四组. 高低质量通过故障注入或不同 verifier 控制, 稀疏度通过题目难度或保守阈值控制. 四组固定总生成 token 与 optimizer 配置.

若稠密 reward 只有在高质量时提升, 说明密度需要可靠标签支撑;低质量稠密组训练 reward 快速上涨、真实验证下降, 则 reward hacking 得到直接展示. 高质量稀疏组若进展慢但方向正确, 可以通过更大 batch、课程或增加组大小改善效率.

中间指标包括正样本纯度、真实正确链召回、三类组占比、优势符号翻转、训练 reward 与独立正确率差. 结果指标使用完全独立 verifier 和人工抽查, 不能沿用训练 reward.

verifier 错误类型消融应将随机翻转与系统性漏洞分开. 在 1% 总错误率下, 随机翻转每条独立;系统性版本对某种格式全部判正. 若策略只在系统性版本中快速提高漏洞格式频率, 说明在线适应比离线错误率更关键.

假阳性与假阴性也分开注入. 假阳性预期提高错误模式正优势, 假阴性预期增加全零组、降低样本效率. 记录真实能力与 reward 的分叉速度. 两者总错误率相同, 后果不应被一个 accuracy 指标合并.

错误注入要落在 verifier 输出之后、group advantage 之前, 确保只改变 reward. 如果同时改变 parser 速度、超时或格式, 因果不再单一. 固定每个样本的注入随机数, 多个算法使用同一错误实例.

规则、程序与模型 verifier 的交叉实验选择一批可同时用三种方式判定的任务:数学表达式可规则比较、用数值程序测试、再由模型 judge 解释. 三者对同一回答评分, 人工建立 gold. 统计每种方法总体与边界条件的混淆矩阵、成本和一致性.

规则 verifier 可能在等价表达上假阴性, 程序验证可能受采样点与浮点影响,模型 judge 可能受措辞影响. 交叉集能量化三种错误的互补性. 级联或投票是否更好, 由人工一致率与成本共同判断.

训练短跑分别用三种 reward, 固定 rollout 预算. 若最终模型只在对应 verifier 上变好, 说明过拟合判定器;三种独立评测同步提升, 才更接近真实能力增长.

任务选择偏差实验从同一目标领域建立两个训练集:易验证子集与代表性随机子集. 后者允许部分样本只能由昂贵人工或模型 judge 验证. 固定总成本训练, 在易验证、难验证与完整目标分布上分别评测.

易验证训练若只在同类集上领先, RLVR 的选择偏差清楚可见;若对完整分布也迁移, 可验证能力具有更广泛价值. 结果要按任务属性切片, 找到迁移发生在哪些结构上.

另一种实验保持训练数据不变, 只改变 verifier 可处理范围. 严格规则丢弃开放答案,混合 verifier 保留它们. 比较数据覆盖、reward 噪声与最终能力. 覆盖扩大是否抵消标签变弱, 这是开放任务迁移的核心交换.

verifier 更新的在线实验在策略发现漏洞后复制 checkpoint. 一条分支继续旧 verifier, 一条修复 verifier 并离线重标最近样本, 一条从漏洞出现前 checkpoint 用新 verifier 重启. 三组固定后续预算.

如果直接修复组恢复慢、重启组恢复快, 漏洞训练已改变策略分布, 单纯换 reward 无法立即撤销;继续旧版分数上涨、独立质量下降, 则修复必要性明确. 这项实验也决定生产训练遇到漏洞时应续训还是回滚.

### 17.6 pass@k 与训练能力

固定 checkpoint, 扫描 $k\in\{1,2,4,8,16,32\}$, 同时估计样本相关性. 独立假设下

$$
\mathrm{pass@}k=1-(1-p)^k.
$$

实测明显低于公式, 说明回答相关;高于由单次 $p$ 推出的曲线, 可能是题目异质性或估计口径不同. 报告每题成功率分布, 不用总体平均 $p$ 代替.

训练后 pass@32 涨、pass@1 不涨, 可能是尾部探索改善;也可能是少数题分布重排. 查看每题成功率和路径多样性. 若正确路径只在极少采样出现, 对实际单次使用价值有限, 对搜索型系统仍可能有价值.

## 18. RLVR 的能力边界与研究判断

RLVR 最有力的场景满足四项条件:任务目标明确、verifier 高精度低成本、模型已有非零成功率、训练分布与目标分布相近. 数学答案、代码测试和形式证明覆盖其中不同子集. 条件越弱, reward 越像代理, 结论越需要外部验证.

第一条边界是「验证结果」和「解题过程」的差距. 终局答案正确, 推理文本可能包含错误、跳步或事后编造. 只以答案训练, 模型学到的内部过程无法由 reward 保证. 若最终应用需要可审计证明, 还要验证过程或使用形式系统.

第二条边界是「通过测试」和「满足规格」的差距. 单元测试只覆盖有限输入, 环境任务只覆盖观测到的状态. 增加测试、属性验证与形式化规格可以缩小差距, 成本和建模难度随之增加.

第三条边界是「judge 偏好」和「真实用户价值」的差距. 模型 verifier 适合提供规模化弱反馈, 无法单独证明开放任务质量. 用户实验、专家审计和长期结果仍是目标层证据.

第四条边界是可见成功率. 当前策略完全无法产生正样本时, 纯终局 RLVR 没有方向. 更大组只在成功概率非零且预算允许时有用. SFT、蒸馏、课程、提示引导或过程反馈可以先把任务搬进可学习区.

第五条边界是 verifier 与策略共同演化. 固定规则面对静态模型可能可靠, 训练策略会搜索规则缺口. verifier 安全需要在训练前验收, 并在训练中持续审计高 reward 新行为. 每次修复又会改变 reward 版本与曲线口径.

第六条边界是任务选择. 易验证能力可以获得大量高质量反馈, 形成快速进步;难验证能力可能被数据管线排除. 模型整体变强与否, 需要在完整目标分布上判断. RLVR benchmark 的高分不能替代开放域评估.

### 18.1 一个端到端判断例子

假设要训练医学建议模型. 药物剂量计算、指南条目引用与禁忌检查中有部分可规则验证;诊断推理、风险沟通与个体化建议难以完全形式化. 若只优化可验证项, 模型可能善于列引用和单位, 整体判断仍不可靠.

可将 RLVR 限于计算、引用存在性、结构化约束等子任务, 最终建议由独立临床专家与真实安全指标评估. 模型 judge 可以筛选明显问题, 其分数不能视为医学正确性的真值. 高风险领域还需校准拒答与不确定性, 这不是答案匹配能覆盖的目标.

同样逻辑适用于研究、法律和开放写作. 将可验证子目标作为强锚, 其余目标承认反馈较弱, 分层报告结果. 这样能利用 RLVR 的优势, 也不会把代理分数包装成完整能力.

### 18.2 与 DeepSeek-R1 结论的连接

DeepSeek-R1-Zero 展示了从基础模型出发, 仅靠规则可验证奖励也能诱导数学推理行为, 这是 RLVR 的关键证据. R1 完整模型加入 cold-start、推理导向 RL、拒绝采样与面向全场景的后续阶段, 说明通用模型能力并非由单一数学 RLVR 阶段完成.

引用 R1 时应把「推理行为可以由规则奖励增长」与「最终通用模型训练配方」分开. R1-Zero 的可读性、语言混杂等问题也表明, 正确性 reward 没有覆盖全部输出质量. 后续数据与训练阶段承担了额外目标.

GRPO 解决无需 critic 的组相对优势估计, verifier 决定优势方向是否可信. 一个精确算法无法修复错误 reward;一个高质量 verifier 也无法在全零组里自动产生差异. 算法、采样与验证是三条独立坐标.

### 18.3 最小验收标准

一套可信 RLVR 结果至少报告训练任务选择过程、verifier 版本与单元测试、分层假阳/假阴、三类组占比、解析与 infra error、独立评测和成本. 规则或测试更新后, 历史曲线重新标注版本边界.

训练样本能从 reward 追溯到原始输出、任务、策略版本与 verifier 原始判定. 高 reward 新模式持续抽检, 漏洞样本加入回归集. 开放任务额外报告 judge 与人工分歧, 不把模型分数当成无条件真值.

算法消融固定 reward 与 rollout;verifier 消融尽量固定回答离线重标;任务课程消融固定 verifier. 三类变量分开, 结果才能归因. 最终在严格去重、不同 verifier 与目标分布上重复评测.

RLVR 的核心价值是反馈可以落到一个可执行判定, 让大规模策略优化拥有清楚信号. 它的核心风险也来自同一处:训练会忠实地优化这条判定, 包括其中每个遗漏、偏差和漏洞. verifier 的定义越具体, 能力结论的边界也应写得越具体.

还有一个常见问题:能否根据已知假阳性、假阴性率修正 reward. 若误差矩阵稳定且可逆,

$$
\begin{bmatrix}
P(R=0)\\ P(R=1)
\end{bmatrix}
=
\begin{bmatrix}
1-\beta & \alpha\\
\beta & 1-\alpha
\end{bmatrix}
\begin{bmatrix}
P(Z=0)\\P(Z=1)
\end{bmatrix},
$$

理论上可以反演估计真实正率. 但训练需要每条回答的方向, 只有总体混淆矩阵无法知道哪一条被误判. 对单样本做概率校正, 还要求误差只依赖可观测特征且模型经过校准. 系统性漏洞随策略变化时, 固定矩阵很快过期.

因此混淆矩阵更适合校正评估总体、估计风险和设计抽检, 很难替代更可靠的 verifier. 若强行用逆矩阵重加权, 当 $\alpha+\beta$ 接近 1 时矩阵接近奇异, 权重方差会爆炸. 标签几乎随机时不存在稳定修正.

多个 verifier 的组合也需要相关性信息. 三个 judge 各有 10% 错误, 若错误独立, 多数投票错误率为

$$
3(0.1)^2(0.9)+(0.1)^3=2.8\%.
$$

若三者共享训练数据和推理模板, 错误高度相关, 投票可能仍接近 10%. 选择不同模型族、规则与执行器能增加误差多样性. 组合收益应在人工 gold 上实测, 不能只根据单体 accuracy 套独立公式.

拒判是另一种选择. verifier 遇到模糊输出时返回 `unknown`, 不强制映射 0 或 1. 拒判降低覆盖率, 提高已判样本精度. 训练系统可以丢弃、交给强 verifier 或保留零优势. 阈值选择对应精度—覆盖率曲线.

困难任务低正率时, 保守拒判尤其有用. 一条假阳性可能主导整组, 宁可少给信号也不要给错方向. 但拒判若集中在新颖正确表达, 会压制多样性. 人工审计拒判集, 检查其中真实正例与表达类型, 是阈值校准的一部分.

对 group reward, 拒判还改变组大小. 原本八条中三条 unknown, 剩余五条计算均值与标准差, 与将 unknown 奖励设零含义不同. 前者条件于 verifier 能判的子集, 后者把不可判当失败. 实现必须明确 mask, 并记录每组有效判定数. 有效数为 1 时无法形成组相对优势.

任务本身也可能标注错误. ground truth 答案错、测试与题意冲突、形式命题翻译错, verifier 会稳定奖励错误方向. 这类错误无法通过更强 parser 修复, 因为 verifier 与标注共同自洽. 高难题持续在提示后突然全对、多个强模型一致反对标答、人工推导冲突, 都是数据审计信号.

可以让 verifier 输出证据:数学等价变换、失败测试、proof kernel 日志或 judge 的引用依据. 证据便于审计, 本身也可能错误. 训练 reward 仍以可执行结果为主, 解释只用于排查, 避免把模型生成的理由再次当真值.

程序测试的置信度可用顺序检验理解. 从测试分布逐个抽样, 错误程序一旦失败即可停止;持续通过则逐渐提高正确置信度. 设错误程序单测通过率最多 $q_0$, 连续通过 $n$ 次的概率上界 $q_0^n$. 给定容许假阳性 $\delta$, 需要

$$
n\ge\frac{\log\delta}{\log q_0}.
$$

$q_0=0.5,\delta=10^{-6}$ 时约需 20 个独立测试. 若 $q_0$ 未知或测试相关, 该保证不成立, 仍要通过属性设计提高覆盖.

环境任务的随机性要求多次执行. 同一策略轨迹在不同 seed 下成功率不同, 单次终局 reward 方差大. 估计成功概率需要重复环境 rollout, 成本快速上升. 将环境 seed 纳入 task id, 组内比较使用相同或不同 seed 会回答不同问题.

相同 seed 能控制环境难度, 更公平比较动作;不同 seed 测策略稳健性, 但组内 reward 差异混入环境随机性. 可以分层:同一任务状态下多策略回答做组优势, 外层再对环境 seed 平均. 多轮 agentic RL 的 verifier 设计由此比单轮数学复杂得多.

真实世界反馈还有选择性观测. 用户只对部分回答点赞, 任务成功只有在后续行为发生时可见, 缺失并非随机. 把未反馈当零会惩罚没有被观察的样本. 需要建模反馈倾向或设计主动标注, 已超出强 RLVR 的简单假设.

从因果角度看, verifier reward 是中介测量. 策略动作影响输出, 输出影响 verifier, 最终关心的真实质量 $Z$ 可能未被观察. verifier 与 $Z$ 之间存在遗漏变量和分布漂移时, 优化 $R$ 不保证提高 $Z$. 独立实验和干预用于确认二者关系.

一项实用做法是建立三层评测:训练 verifier 测优化目标,独立 verifier 测判定迁移,人工或环境 gold 测真实目标. 理想情况下三条曲线同步上涨. 训练涨、独立不涨表示过拟合判定器;两个 verifier 都涨、gold 不涨表示共享偏差;gold 涨而训练 reward 不涨, 说明训练信号可能过于保守或评测存在差异.

三层评测成本不同, 频率也不同. 训练 verifier 每步运行,独立 verifier按 checkpoint 运行,gold 小样本低频运行. gold 虽少, 必须覆盖高 reward 新模式与关键任务, 不能只随机抽容易样本. 分层抽样后按目标分布权重还原总体估计.

置信区间同样重要. gold 集只有 100 条, 观察准确率从 60% 到 64%, 二项标准误约 5 个百分点, 差异未必可靠. 配对评测同一题的前后回答, 使用 McNemar 或 bootstrap 差值, 能利用题目难度相关性降低方差. 报告区间比单点更诚实.

当 verifier 改版时, gold 集保持不变, 新旧 verifier 都评分同一批输出. 得到的变化分为两部分:模型行为变化和判定口径变化. 用交叉评分矩阵可以分离. 没有原始输出, 只能看到 reward 曲线跳变, 无法重建原因.

RLVR 数据也应保存负例. 只保留通过 verifier 的轨迹用于拒绝采样 SFT, 会丢掉 RL 组内比较和错误模式. 负例能训练判别器、审计漏洞、分析首错位置. 公开数据若只含成功链, 社区无法复核 reward 质量.

不过负例包含模型生成内容与潜在危险代码, 发布需处理许可和安全. 形式证明失败日志、沙箱攻击尝试也可能暴露系统细节. 可公开统计与脱敏样本, 同时保留内部可审计全量数据. 可复现与安全之间需要明确边界.

训练结论还要区分「学会被验证」与「学会解决任务」. 输出格式改善、测试适配和 judge 风格匹配都能提高前者. 严格保留集更换表达模板、测试生成器和 verifier 实现, 可以测后者. 迁移越跨 verifier, 能力证据越强.

例如数学训练要求 `\boxed{}`,评测改为结构化 JSON 或口头答案, 语义能力若真实增长, 换格式后经过短适配仍应保留大部分收益. 分数完全消失, 表明训练过度绑定输出协议. 格式迁移实验应确保新 parser 本身可靠.

代码任务可以更换隐藏测试生成器、编程语言或接口包装. 算法能力迁移, 硬编码测试与模板捷径难迁移. 形式证明可更换库命名与定理表述, 检查模型是否依赖表面记忆. 这些评测都比同 verifier 重测更严格.

对开放任务, verifier 迁移还需更谨慎. 两个 judge 排名一致可能来自共同偏好, 人类专家与真实结果仍是强证据. 最终报告将证据分级:形式内核/完整执行规格,隐藏程序测试,规则等价,模型 judge,自评. 不同等级的「验证通过」不应共享一个无修饰的结论.

RLVR 方法比较也要对齐 verifier. A 使用强符号验证,B 使用字符串匹配, 即使算法相同 reward 质量也不同;A 成本更高,生成 token 可能更少. 固定 verifier 比算法,固定 rollout 离线比 verifier,固定总成本比完整系统, 三种实验回答三个问题.

只有完整系统比较时, 可以同时优化 verifier 与算法, 结论应写成 recipe 效果. 归因某个组件则需要隔离变量. DeepSeek-R1 的成功来自模型、数据、奖励、算法与系统共同作用, 不能把最终能力全部归给一个缩写.

reward 的时间稳定性也需要测量. 同一批保存的输出每隔一段时间由当前 verifier 重评, 如果分数变化, 原因可能是规则版本、依赖库、模型 judge 或外部环境更新. 确定性任务的重评应逐字一致;模型 judge 至少给出分布与一致率. 时间漂移会让跨 checkpoint 曲线失去统一尺度.

外部事实型任务尤其明显. 网页内容、法律、产品状态与数据库会更新, 一年前正确的答案今天可能错误. verifier 必须绑定时间快照或允许时效性. 把当前事实用于重评旧回答, 衡量的是今日有效性;把历史快照用于重评, 衡量的是当时任务完成度. 两者都合理, 目标不同.

多轮环境还要防止状态泄漏. 前一条轨迹留下文件、缓存或账号状态, 下一条策略可能利用残留, 得到无法独立复现的高 reward. 每次环境 reset 后运行哨兵测试, 确认初始状态一致. 无法完全重置时, 环境状态哈希进入样本记录.

奖励延迟也会造成选择偏差. 快速返回的任务先进入 learner, 慢任务后到或超时, 异步训练中的有效分布偏向易验证样本. 即使 sampler 均匀,消费顺序也已改变. 按任务类型记录生成结束、验证结束与消费时间, 检查慢任务的进入概率.

若超时样本被丢弃, 它们在训练中权重为零;若判负, 它们得到负优势;若晚到后继续使用, 又带来 off-policy 滞后. 三种处理都改变目标. 协议需明确, 并在固定成本下消融. 工程超时不应静默决定算法语义.

verifier 的成本与准确率可以形成 Pareto 曲线. 轻量规则便宜但漏掉等价表达, 符号或模型验证更贵且覆盖更广. 一条方案若同时更贵、更不准, 可直接淘汰;其余方案根据训练预算、低正率风险与延迟选择. 级联通常位于中间, 仍需实测.

建立 Pareto 曲线时, accuracy 要按目标训练分布加权, 也要报告高风险层. 总体 99% 准确、假阳性集中在模型最爱生成的格式, 在线表现可能很差. 成本使用每百万回答的 GPU 时与 P99 延迟, 平均延迟不足以描述异步队列长尾.

对 verifier 进行对抗训练或持续更新, 可能演化成 policy—verifier 军备竞赛. verifier 越强,策略寻找更隐蔽漏洞;新 verifier 又改变 reward 分布. 每轮都需要固定独立 gold, 防止双方共同偏离真实目标. 若 gold 不增长, 只能证明策略没骗过当前 verifier.

一种保守策略是将 verifier 更新限制在明确错误类型, 保持其它判定不变. 大模型 judge 全量升级会同时改变许多隐含偏好, 新旧曲线难比较. 使用版本化回归集和差分报告, 列出哪些样本从正变负、从负变正以及人工结论.

RLVR 的公开结果若能附带 verifier 代码、测试、容器、reward 原始日志与失败案例, 复现价值远高于只发布最终模型. 模型权重证明某次训练得到了结果, verifier 材料解释训练信号为何可信. 对无法公开的测试, 至少公开覆盖类别、数量和独立审计协议.

最终的事实主张应与证据等级对应. 「在给定规则 verifier 上通过率提高」是直接观测;「数学能力提高」需要独立题与等价 verifier;「通用推理提高」还需跨任务、跨判定方式的迁移. 从第一句走到第三句, 每一步都要新增证据, 不能由 RLVR 名称自动完成.

训练终止也应参考这套证据层级. 训练 reward 仍在上涨、独立 verifier 已停滞时, 继续运行可能只会加深判定器适配;独立 verifier 上涨、gold 样本不动时, 要检查共享偏差;三层同步上升且成本仍有合理边际收益, 才支持继续扩大预算. 这样设置停止条件, 能把「优化得更久」和「真实能力继续增长」区分开.

每次扩展结论都应附上对应 verifier、任务分布与时间版本, 让通过率拥有明确、可复查的含义.
