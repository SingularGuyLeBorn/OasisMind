# long-horizon Agentic RL 与信用分配:为什么 GLM 把 PPO 请了回来

**前置知识**: PPO(1.1.7 节), GRPO(1.3.1.1 节), RLOO(1.3.1.2 节)

---

过去一年半, 很多人对大模型强化学习的叙事是这样的: PPO 是上一代 RLHF 的老工程, 昂贵、复杂、难调; GRPO 去掉 critic, 更轻、更适合推理模型; 所以未来大模型 RL 会越来越 GRPO 化.

这个判断不算错, 但它漏掉了一个关键前提: **任务形态**. 在数学题、代码题、可验证问答这类短程、单轮、结果清晰的 RLVR 任务里, GRPO 的确是很漂亮的工程折中. 但到了 long-horizon agentic RL——模型连续多轮调用工具、观察环境、压缩上下文、拆分子任务、执行几十甚至上百步——问题的结构变了. 智谱 GLM-5.2 的技术博客提到, 他们在长程任务训练中从 group-wise optimization 转向 critic-based PPO. 这件事值得认真看: 它不是「PPO 复辟」, 也不是「GRPO 失败」, 而是提醒我们 **PPO 和 GRPO 是适配不同 credit assignment 结构的两种工具**.

## 1. GRPO 成功的前提, 是任务结构而不是算法本身

### 1.1 短程 RLVR 的三个隐含假设

GRPO 的设计对应一组任务性质. 第一, **组是整齐的**: 同一 prompt 采 $G$ 条完整回答, 长度有差异但结构同质, 组内均值是有意义的「平均水平」参照. 第二, **终局 reward 足够细**: 答案对就是对, 错就是错, 序列级的成败信号压到整条链上不算太冤. 第三, **轨迹边界清晰**: 一条 rollout 就是一条训练样本, 采样分布就是训练分布.

DeepSeek-R1 的训练范式让 GRPO 获得极高关注, 它的美感在于**用更多采样换掉一个复杂的 critic** (1.3.1.1 节). 对短程 RLVR, 这个交换很划算: 采 8 条的边际成本远低于训一个 value model, 而组内比较提供的相对信号足够强. R1 之后社区的经验也反复确认了这一点——在短程任务上, GRPO 与其变体 (1.3.2.1 到 1.3.3.1 节) 的改进空间主要在方差与稳定性, 不在基本结构.

RLOO (1.3.1.2 节) 的留一基线修正了 GRPO 的统计性质, 但修正的对象仍是「组基线是否无偏」——它让组比较在数学上更干净, 没有改变组比较适用的大前提. 同理, Dr. GRPO 的标准差之争 (1.3.1.1 节 §3) 是在组内争论优势的尺度, 不触碰组的结构. 这些工作越漂亮, 越说明短程假设下的组结构还有油水; 长程任务的问题在另一个维度上.

### 1.2 前提的检验方法

判断一个任务是否满足 GRPO 的前提, 有三个可测量的量. 组整齐度: 同组 rollout 的长度分布和结构相似度, 方差小则组均值可信. 信号粒度: 终局 reward 与过程质量的相关, 高则序列级信用分配误伤小. 轨迹规整度: compaction, 截断, 多轮拼接是否改变训练样本的边界. 短程数学推理三项全优, agentic 任务三项全劣——差异不是程度, 是性质.

这三个量也是监控量: 从短程任务迁移到长程任务时, 先把三项测出来, 哪项劣化最严重, 就在那里优先补结构. 这比「先上 GRPO 试试」省一轮返工.

再给一个量化锚点: 组整齐度可以直接用组内轨迹长度的变异系数 (标准差/均值) 衡量. 短程数学推理的组内长度变异系数常见在 0.2 上下; 报过数值的 agentic 训练里, 同一 prompt 的轨迹长度从几步到几十步, 变异系数轻松超过 1——组均值在这个离散度下基本是噪声的函数, 不是水平的度量. 这个数字不需要精确复现, 量级感足够指导判断: 变异系数过 0.5, 组基线的可信度就该打问号.

## 2. Agentic 任务的三重破坏

### 2.1 组不再整齐

Agentic RL 里, 模型不再一次性输出答案, 而是在环境里连续行动: 观察, 思考, 调工具, 得到反馈, 再行动. 一个修 bug 的 coding agent 可能五步完成, 也可能五十步还在绕; 有的 rollout 调了搜索, 有的进了代码执行, 有的中途触发上下文压缩. **同一 prompt 下的多个 rollout 不再是同质的回答, 而是形态差异巨大的交互历史**.

组均值基线在统计学上仍然可以计算, 但语义变了: 「这组轨迹的平均水平」对一条五步成功的轨迹和一条五十步失败的轨迹, 不构成有意义的比较基准. GRPO 的优势 $A_i=R_i-\bar R$ (1.3.1.1 节) 隐含组内可交换性, 形态差异巨大时可交换性不成立, 优势的方差暴涨而偏差结构复杂. 1.3.3.4 节的 scaling 视角下, 这表现为同样的计算预算, 有效信号占比骤降.

一个具体的失真场景: 组里五条轨迹三条五步短轨迹, 两条五十步长轨迹, 短的全对长的全错, 组均值给长轨迹发强负优势. 但长轨迹未必差——它们敢碰难题, 短轨迹挑了软柿子. 组比较在这里惩罚了「尝试难度」, 策略学到的是「挑简单的做」, 长程能力反而退化. 这类奖励 hacking 在短程任务里少见 (题难度均匀), 长程任务里比比皆是.

### 2.2 终局 reward 太粗

长轨迹最终成功, 不代表中间每个动作都值得强化——可能前 80% 是绕路, 最后一步才是关键. 长轨迹最终失败, 也不代表每个动作都该惩罚——可能推理全对, 只是某个工具调用的参数错了. GRPO 把终局 reward 的组内相对值广播到全部 token (1.3.1.1 节 §2.8), 在短链上「误伤率」可接受; 链长一到几十上百步, **序列级成败被过度传播到局部动作**, 信用分配的粗糙度随步数线性放大.

critic 在这里的价值重新显现: 它回答的问题是「走到当前这个状态, 未来成功的期望有多大」——这正是长程任务最需要的中间刻度. 「打开某个文件」这一步没有即时 reward, 但如果它显著提高后续修复成功率, critic 能学到它是好动作; 终局 reward 做不到这种细粒度区分. 代价是 critic 的训练成本与引入的不稳定性 (1.1.7 节), 这个交换在短程任务上是亏的, 在长程任务上开始变赚.

还有一点常被忽略: agentic 任务的观测是带噪声的. 工具返回可能很长 (日志, 报错堆栈), 环境反馈可能延迟 (测试跑完才知道成败), 甚至部分环境没有确定性的终局判定 (「这个重构够好吗」). 观测噪声直接进上下文, 影响策略的每一步输出; 终局 reward 对这些噪声没有任何中间刻度, 而 critic 至少能学会「这类噪声观测出现后不慌」——把环境的不确定性部分吸收进价值估计.

粗糙度随步数放大还有一个常被引用的经验比例: 同样的终局对错, 步数翻十倍, 广播式信用的「有效信噪比」大约掉一个量级——这不是严格定理, 是从多个复现里归纳的量级感. 用法和 §1.2 的变异系数一样: 不求精确, 用来决定「什么时候该停止给广播法加预算, 转投 critic」.

### 2.3 compaction 改变训练样本结构

这是 GLM-5.2 博客的关键技术点, 也是最容易被忽略的一点. 长轨迹因为上下文窗口限制或训练组织的需要, 会被**压缩 (compaction) 并拆分成多个 sub-trace**: 原始交互历史被摘要后继续, 训练时则按子段组织. 后果是, 同一个 prompt 下不同 rollout 产生的**可训练轨迹数量不同、长度高度不均匀**——一条 rollout 拆出三段, 另一条拆出八段.

GRPO 天然依赖「组」的结构: 同 prompt 采 $G$ 条候选再做相对比较. 训练对象从「完整回答」变成「不等长不等数的轨迹片段」后, 组结构碎掉了: 按原始 rollout 分组, 组内样本是异质片段; 按 sub-trace 分组, 同组样本可能来自不同 rollout 的不可比片段. 两条路都破坏组基线的语义, 而 GRPO 没有第三条路——它的优势构造就是围绕组设计的.

更深一层的困难: compaction 把「一段交互是否保留」变成了策略无关的环境决定. 窗口满了就压, 压多少取决于轨迹长度, 而轨迹长度又受策略影响 (爱啰嗦的策略更早触发 compaction). 训练分布因此带上了策略自身的印记, 组比较在这个印记下更难解释. critic 方案至少把每个 sub-trace 当作独立的状态序列处理, 不必在「组」的语义废墟上做相对比较.

## 3. compaction 的技术细节与 sub-trace 上的优势估计

### 3.1 compaction 为什么必要

上下文窗口是硬约束: 几十步的 agentic 交互, 每步的 observation 和工具返回都能占掉大量 token, 整条轨迹很快顶到窗口上限. compaction 的做法是周期性地把历史交互摘要化, 只保留继续任务所需的状态. 对推理 (inference) 这是纯工程问题; 对训练, compaction 引入了一个新对象: **训练单位不再是自然轨迹, 而是人为切分的 sub-trace**.

再补一层动机: compaction 不只是窗口不够时的补救, 它改变了**模型实际见到和优化的对象**. 推理时 compaction 是状态管理; 训练时 compaction 决定 credit assignment 的边界——「哪段交互对最终结果负责」这个问题, 在 sub-trace 切分方式确定之前没有答案. 切分按窗口硬切 (每 N token 一段) 简单但语义差, 切分按任务阶段 (读代码, 改代码, 跑测试) 语义好但需要标注或启发式. GLM-5.2 博客没有展开切分策略的细节, 这是复现时自己要做的第一个设计决定.

每个 sub-trace 有自己的上下文前缀 (compaction 后的摘要) 和局部输出, 它的奖励没有天然的标量——整个 rollout 的终局 reward 要按某种方式落到各个 sub-trace 上. 常见做法是把终局 reward 广播到全部 sub-trace (信用分配依然粗糙), 或者用 critic 估计每个 sub-trace 起点状态的价值, 用后一段价值减前一段价值构造局部优势. GLM-5.2 选择了后者: 用 critic 估计 token-level advantage.

### 3.2 手算: 同一 rollout 的两种优势

设一条 rollout 终局成功 ($R=1$), 被拆成 3 个 sub-trace. 方法一 (广播): 三个片段的优势都是 $+1$ (组内归一前). 方法二 (critic 差分): 某 token 位置的 advantage 是 $A_t=\delta_t+\gamma V(s_{t+1})-V(s_t)$ 形式 (GAE, 1.1.7 节), 设 critic 给出的价值序列在片段边界上是 $V_0=0.3$, $V_1=0.6$, $V_2=0.8$, 折现 $\gamma=1$, 每段内无即时 reward, 则三个片段的边界优势分别是 $0.6-0.3=+0.3$, $0.8-0.6=+0.2$, $1.0-0.8=+0.2$——总增量同样是 $1.0-0.3=0.7$, 但**分配到了具体位置**: 第一段贡献最大, 因为 critic 认为任务是从 0.3 的完成度推进到 0.6.

这个手算展示的是两种方法的结构性差别: 广播把 credit 均匀撒在全程, critic 差分把 credit 按「状态价值的实际推进」分配. 长程任务里价值推进高度不均 (关键决策点少, 重复性步骤多), 差分法的分配更接近真实贡献结构. 代价是 critic 本身的估计误差会进优势, 这就是 1.1.7 节价值网络的老问题——它从来没有被解决, 只是在长程任务上变得值得承担.

再看失败分支: 同一条 rollout 若终局失败 ($R=0$), 广播法给三个片段都发 $-1$; 差分法在 $V$ 序列 $0.3,0.6,0.8$ 下发的是 $+0.3,+0.2,-0.8$——前两段被奖励, 只有最后一段受罚. 哪个对取决于 ground truth: 如果失败真的是最后一步的锅, 差分法避免了误伤前两段; 如果前两段的「推进」其实是死胡同里的忙碌, 差分法反而奖励了绕路. critic 的分配质量完全取决于它学到的价值函数质量, 这就是为什么 critic 的训练稳定性 (1.1.7 节的老大难) 在长程任务里被放大成系统级风险.

切分策略的差异也能放进这个框架: 硬切 ($N$ token 一段) 的段边界随机落在动作中间, 段价值差分天然带噪; 按任务阶段切的段边界对齐语义单元, 段间 TD 残差更接近「这个阶段的实际贡献」. 手算里的 $0.3,0.6,0.8$ 序列, 若三段分别是「定位, 修改, 验证」, 分配有明确含义; 若三段是「前 500, 中 500, 后 500 token」, 同样的数字说不清任何事.

## 4. 重新理解 PPO 回归: 复杂度换的是什么

### 4.1 不是复辟, 是价格重估

「GLM 把 PPO 请回来」的准确读法: **当 horizon 变长、轨迹变不规则、局部决策价值变重要时, critic 的成本开始变得值得支付**. PPO 相对 GRPO 多出的东西——value model 的参数与前向, GAE 的额外计算, actor-critic 联合训练的不稳定性——买的是 token 级的信用分配能力. 短程任务里这个能力用不上 (终局 reward 够用), 长程任务里它从奢侈品变成必需品.

反过来说, 这也预告了 PPO 回归的边界: 如果长程任务出现不依赖 critic 的信用分配方案 (过程奖励、记忆增强的组比较、单流方法), PPO 的相对优势会再次收窄. 1.3.1.14 节会展开这条谱系. 算法史上的「回潮」大多是这种情况: 不是旧方法变强了, 是成本结构变了, 旧方法的价格落进了新的可接受区间.

这个读法还纠正一个隐含假设: 「技术进步是单向的」. RL 算法的演化更像生态位的扩张——新任务形态出现, 旧工具在新生态位里重新占优. GRPO 没有「淘汰」PPO, 只是短程任务的生态位太耀眼, 把 PPO 挤出了聚光灯. 长程任务把这个生态位补了回来, 两者从此长期共存.

### 4.2 选择判据

给任务选 PPO 还是 GRPO, 可以用三个问题定. 轨迹规整吗 (无 compaction, 长度方差小)? 信号细吗 (终局 reward 与过程质量高相关)? 组整齐吗 (同 prompt 多 rollout 结构同质)? 三问全「是」选 GRPO 系, 有一问「否」先补结构再评估, 两问以上「否」直接评估 critic-based 方案. 这个判据比「社区流行什么」可靠, 也比「哪个论文数字高」可靠——数字绑定别人的任务结构, 判据绑定你自己的.

工程上还有一个中间态: 保留 GRPO 的 rollout 基建, 只把优势构造换成 critic 差分 (sub-trace 边界用 value 差分, 段内用组比较). 混合方案的优势是基建复用, 代价是两个信号源的配比需要重新调. GLM-5.2 没有完全走这条路, 但社区里类似的混合尝试不少, 值得按任务结构评估.

判据里「先补结构」值得展开: 组不整齐有时可以靠采样策略补 (按预估步数分组采样, 让组内形态接近), reward 太粗可以靠过程验证器补 (每步的工具调用单独判分). 这些补救各自有成本, 当补救的成本逼近 critic 的成本时, 选 critic 就是更直的路——判据的用法是逼出这个比较, 而不是替你做决定.

## 5. 社区叙事与误读

### 5.1 「PPO 复辟」与「GRPO 失败」都不对

GLM-5.2 的消息传出后, 两种解读最常见, 也都站不住. 「PPO 复辟」暗示 GRPO 错了——但短程 RLVR 上 GRPO 的成功是真实的, R1 及后续一整套结果不会因为长程任务换了算法就被推翻. 「GRPO 失败」暗示组比较这条路线到头了——但 1.3.1.14 节会看到, 社区正在沿着「组到底有什么用」这条线继续榨取组结构的剩余价值 (2-GRPO, 单流方法), 谈不上失败.

还有一种更隐蔽的误读: 「长程任务都要 critic」. 这个推断同样跳步——critic 是 token 级信用分配的一种实现, 不是唯一实现. 过程奖励, 子目标验证, 记忆增强的比较信号 (1.3.1.14 节的 MemGRPO 路线) 都在补同一个洞, 且各有代价结构. GLM-5.2 的选择是其一, 不是标准答案; 复刻之前先问自己的任务, critic 的洞补得上吗, 还是别的方案更便宜.

准确的读法是任务分化和算法分工: RL 的战场从「一个算法打所有任务」变成「按 credit assignment 结构选工具」. 这对知识库组织也是好消息——1.3 节的家族谱系不再需要一个「最终胜利者」, 每篇变体的适用域写清楚, 读者按自己的任务结构自取.

历史对照能帮这个判断落地: actor-critic 与无 critic 的路线在经典 RL 里交替占优几十年, 每次交替都伴随任务形态变化 (Atari 时代 critic 主流, 机器人 sim2real 时代无模型方法回潮, 大模型短程 RLVR 时代 GRPO 胜出). GLM-5.2 的切换放在这条长线上看, 毫无意外, 意外的是社区每次都要重新争论一遍「谁淘汰了谁」.

### 5.2 对 1.3 节家族的坐标修订

把 1.3.1.1 到 1.3.3.1 节的变体放进长程视角重新看, 可以发现一个规律: 这些方法主要改善组内信号的方差与利用率, 基本沿用原来的组结构. 短程任务里, 方差确实是主要矛盾; 长程任务的困难却转向组语义碎裂 (§2.1, §2.3), 原有改进因而无法覆盖新的失效位置. 读算法谱系时, 应先核对论文假设的任务结构与当前任务相差多远.

scaling 视角 (1.3.3.4 节) 同样适用: PPO 回归是稳定性坐标上的动作 (critic 防崩溃), 代价是效率坐标 (更多前向, 更难的调参). 长程任务里稳定性是硬门槛, 效率可以靠基建 (异步 rollout, 流水线) 补, 坐标的优先级和短程任务正好反过来.

还有一个跨篇目的观察: 1.3 节的变体命名越来越长, 每篇的适用域越来越窄——这本身是社区成熟的标志. 早期论文承诺「通用更优」, 后期论文承认「在 X 任务结构上更稳」. 读者的心态也该跟着调: 不再找最强的算法, 而是维护自己的「任务结构 → 算法」映射表, 新论文进来先填表, 再决定要不要读细节.

1.3 节因此按任务结构组织算法: 1.3.1.1 给出组采样的基准坐标, 后续变体分别对应稳定性、训练配方和长程信用问题. 读者可以从自己的任务结构跳到相应变体, 再回到 1.4 章做横向选型, 无须按论文发布时间逐篇推进.

## 6. 实现要点与监控

### 6.1 sub-trace 组织

实现 compaction 训练的关键数据结构: 每个 rollout 带一个 sub-trace 列表, 每个 sub-trace 记录 (所属 rollout, 段序号, 边界价值 $V_{start}$/$V_{end}$, 有效 token 范围). 优势按段构造, 归一化按 batch 而非按组 (组已碎). 过滤规则沿用 1.3.2.1 节的动态采样思想, 但判据从「组内 reward 全同」改为「段价值差近零且无即时 reward」——这类段没有学习信号.

有一个容易漏的边界: compaction 边界和 tokenizer 边界不对齐, 一个 sub-trace 的最后一个 token 可能把工具返回拦腰截断. 这类段的上下文前缀是「半个观测」, critic 在它上面的价值估计天然不准. 实现协议必须固定一种处理方式: 要么把截断的观测整体移到段尾之外, 要么在 mask 里标记这类 token 不进 critic loss; 数据管线不能随机选择.

```python
import torch

def subtrace_advantages(rewards, v_starts, v_ends, gamma=1.0):
    # rewards: [n_subtraces] 段内即时 reward（通常为 0，仅最后一段有终局 reward）
    # v_starts / v_ends: [n_subtraces] critic 在段首段尾的状态价值估计
    td = rewards + gamma * v_ends - v_starts
    # 批级标准化（组结构已碎，不能按组归一）
    adv = (td - td.mean()) / (td.std() + 1e-8)
    return adv.detach()
```

注意三段约定: 价值估计 detach, 优势 detach, 梯度只走 policy 分支. `v_starts`/`v_ends` 由 critic 前向给出, 与 1.1.7 节的 GAE 结构兼容.

### 6.2 监控与验证

验证不变量三条. 第一, 全段求和: 一条 rollout 全部 sub-trace 的 TD 残差之和, 等于终局 reward 加边界项 ($\gamma^{L}V_{end}-V_{start}$), 数值上可核对. 第二, 无 compaction 退化: 当所有 sub-trace 就是完整 rollout 时, 段价值差分退化成终局 reward 减初值, 与广播法只差一个常数, 训练行为应接近. 第三, 价值一致性: 相邻段的 $V_{end}$ 与前一段的 $V_{start}$ 在无环境重置处应连续 (误差范围内), 偏差大说明 compaction 摘要丢失了状态信息, critic 在猜.

监控上加两项: 段价值在段边界的跳变分布 (compaction 质量), 优势按段序号的衰减曲线 (信用是否过度集中在末段——若是, 说明 critic 没学到中间状态的价值). 两项都能在训练日志里直接画出, 是长程训练的两个早期报警器.

把两个报警器的判据写具体. 边界跳变: 同 rollout 相邻段的 $|V_{end}^{(k)}-V_{start}^{(k+1)}|$ 分布, P95 超过段间 TD 残差的量级, 说明 compaction 在丢信息. 段序号衰减: 按段序号分桶统计平均优势绝对值, 若从第一段到最后一段单调递减超过一个数量级, 信用分配退化成「只看结局」——那等于白付 critic 的成本, 不如回广播法.

验证不变量适合进 CI, 报警器适合进在线看板: 前者拦实现错误, 后者拦训练漂移, 职责分开, 别用一个系统兼两个职.

### 6.3 rollout 基建的复用

从 GRPO 切到 PPO, rollout 侧 (异步采样, 环境调度, compaction 管理) 一行不用改, 改的是训练侧 (加 critic 前向与 GAE) 和优势构造. 这意味着已经搭好 agentic rollout 系统的团队, 换算法的边际成本主要在 critic 的训练稳定性上, 不在基建重写上. slime 一类面向 agentic 的 RL 框架 (见 llm-infra 库的 rollout 基建讨论) 把环境交互, 轨迹管理和训练解耦, 也是为这个层面的可替换性准备的.

反过来, 如果 rollout 基建还没搭好, 先别纠结 PPO 还是 GRPO——长程任务里 rollout 侧 (环境沙箱, 观测截断, compaction 策略) 的工程量远大于算法侧, 而且算法选择随时可以换, 基建选错了返工成本更高. 这个顺序建议和 1.3.2.1 节 §7.3 一致: 先修症状最重的那层.

对资源规划还有一个提醒: critic 方案的显存峰值约为策略侧的 1.5 到 2 倍 (value model 参数加激活), 长上下文场景的激活项被 sub-trace 切分部分缓解. 预算评估时把这个倍数和 rollout 侧的既有占用相加, 再对照硬件余量——很多「PPO 回归」的可行性判断, 最后卡在的是显存而不是算法.

## 8. 与推理范式的衔接

### 8.1 compaction 是训练问题还是推理问题的回波

一个值得想透的问题: compaction 本质是推理时的状态管理技术, 它的训练副作用 (sub-trace 不等长, 组结构碎裂) 是「推理实现细节倒流进训练目标」的典型案例. 类似的情况在 RLHF 历史上有过: chat template 的格式选择本属部署工程, 却成了训练分布的一部分 (1.3.1.1 节 §5.1 的 template 版本事故). 规律是: **凡是影响模型行为的工程决策, 迟早都会变成训练问题**.

顺着这个规律可以预测: 随着 agentic 系统越来越复杂 (多 agent 协作, 长期记忆, 工具生态), 还会有更多推理侧机制 (记忆压缩, 上下文路由, 子 agent 调度) 以同样的路径进入训练侧, 各自带来自己的信用分配问题. 1.3.1.14 节的谱系讨论会再次遇到这个模式——每个新方法都是在给某个工程机制补训练语义.

这个规律对团队分工也有含义: 推理工程和训练算法的边界需要有人盯着, 否则两侧会互相踩出看不见的问题. 小团队里这个角色通常落在最懂两边的人身上, 这不是效率安排, 是风险控制.

### 8.2 对 infra 的反向要求

算法选择也会直接改变 infra. critic-based PPO 要求 rollout 与训练保持更紧的版本耦合, 为 value model 预留显存, 并让数据管线支持 sub-trace. slime 一类框架强调的训推一致性、权重同步和轨迹管理, 正好承接这些要求. GLM-5.2 从算法侧增加 critic 后, 基建侧也必须同步承担新的状态与调度成本.

对选型的推论: 如果你的基建是围绕 GRPO 的轻量管线 (无 critic 前向路径), 换 PPO 的隐性成本要计入显存峰值重估, 权重同步频率重调, 以及崩溃恢复逻辑 (critic 状态也要存 checkpoint). 这些infra 侧改动经常被算法对比忽略, 却常常决定迁移的实际工期.

## 9. 从轨迹回报到可训练样本

### 9.1 截断处如何定义状态

长程任务把一条轨迹切成 sub-trace 后, 截断点必须携带足够状态才能继续估值. 对工具调用任务, 状态不仅是对话 token, 还包括工具返回值、文件版本、环境变量以及尚未提交的外部动作. 若训练数据只保存可见文本, critic 学到的是同一段文本的平均后果, 无法区分环境已改变和环境未改变两种状态. 这种观测混叠会增加不可约误差, 再大的 value 网络也补不回来.

一个直接检查方法是寻找文本相同但后续回报不同的样本, 再核对它们是否缺少环境字段. 若差异由隐藏状态造成, 应扩充状态序列化; 若差异来自策略随机性, 才适合让 value 学条件期望. 状态字段加入后还要版本化 schema, 否则旧轨迹与新轨迹混训会让相同字段位置表达不同含义.

### 9.2 bootstrap 的偏差逐段传播

设第 $j$ 段包含 $H_j$ 步, 段内折扣回报为 $G_j$, 截断处用 critic $V(s_{j+1})$ 补尾, 则目标为

$$
\hat V(s_j)=G_j+\gamma^{H_j}V(s_{j+1}).
$$

如果尾部估值误差为 $\epsilon_{j+1}$, 它传到当前段的误差就是 $\gamma^{H_j}\epsilon_{j+1}$. 段越短, 尾部误差衰减越少; 段越长, 环境交互更多, 回报方差又会上升. sub-trace 长度因此同时控制 bootstrap 偏差和采样方差, 不能只按上下文窗口整齐切分.

可以用多种切分长度训练小规模对照: 固定总轨迹和有效 token, 比较 value 的校准、优势方差与最终成功率. 若短段的 value loss 很低但策略收益差, 常见原因是模型过度拟合相邻 bootstrap 目标; 若长段梯度极不稳定, 则需要降低截断长度或采用多步目标混合.

### 9.3 稀疏成功下的反事实检查

只有终局成功奖励时, 正优势容易集中在成功轨迹的全部步骤上, 包括与结果无关的探索和冗余操作. 判断信用是否合理, 可以对轨迹做受控删除: 移除一段不改变环境的空操作, 价值预测应近似不变; 移除决定性工具结果后, 后续成功概率应显著下降. 这类反事实不是新增奖励, 而是检查 critic 是否把相关性错当成因果贡献.

对不可重放的外部环境, 可以先在确定性沙箱里执行同类检查, 再把监控迁移到真实任务. 训练日志记录每个 sub-trace 的优势分布、截断长度和工具类别, 便能定位某类工具是否长期获得不合比例的正优势. 最终奖励相同并不代表中间归因正确, 而错误归因往往要到策略开始利用漏洞时才显现.

如果某类工具调用长期只有正优势, 还需检查失败调用是否在数据清洗时被提前删除. 过滤失败轨迹会产生幸存者偏差, 使 critic 把工具出现本身当成成功信号. 保留失败类型并用 mask 控制不可训练字段, 比直接丢整段轨迹更利于识别这种偏差.
