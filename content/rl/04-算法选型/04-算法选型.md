# 算法选型

## 1. 先把问题写成统计对象

算法选择从可观测数据开始。固定胜负回答对对应离线偏好学习；当前策略持续生成回答并由标量奖励评分，对应在线策略优化；反馈来自可执行验证器时，采样覆盖和稀疏奖励成为主要矛盾；环境包含多轮工具调用时，还需要状态、转移与长程信用分配。名字相近的算法可能服务于不同统计问题，直接横向排名会丢掉前提。

统一地写，训练希望估计

$$
\nabla_\theta J(\theta)=\mathbb E_{z\sim p_\theta}
[g_\theta(z;R,V,\pi_{\rm ref})].
$$

$z$ 可以是 token、完整回答、偏好对或交互轨迹。选择方法时应逐项确定：$p_\theta$ 是否随训练变化，$R$ 来自人、奖励模型还是程序，是否需要价值函数 $V$，参考策略是否进入目标，有限样本估计 $g_\theta$ 有多大偏差和方差。组件清单只是资源结果，这些对象才决定算法行为。

### 1.1. 数据覆盖与反事实信息

固定偏好对只告诉我们已出现回答之间谁更好，无法评价从未采样的动作。DPO、IPO、ORPO、SimPO 与 KTO 可以高效使用这类数据，结果受候选生成策略支持集限制。在线 RL 能让更新后的策略探索新回答，再由奖励函数给反馈；它扩大覆盖，也会进入奖励模型未见区域。

奖励只能对完整回答评分时，在线采样仍没有动作级反事实：我们知道这条轨迹得分多少，不知道在某个前缀换一个 token 会怎样。critic、过程奖励与树搜索分别用函数逼近、额外反馈和更多采样补足信息。三者引入不同误差，资源预算也不能相互替代。

数据复用次数是另一条轴。On-policy 方法要求样本接近当前策略，更新后很快失效；离线方法可以反复遍历固定数据，却只能优化数据覆盖范围内的相对概率。PPO 类方法位于中间：同一 rollout 做若干 epoch，靠比率与裁剪控制漂移。复用越多，每个生成 token 承担更多优化步，同时重要性权重更偏离 $1$。

### 1.2. 反馈误差怎样被优化放大

设观测奖励为 $\hat r=r^*+\epsilon$，其中 $r^*$ 是真正关心的效用，$\epsilon$ 是反馈误差。优化器最大化 $\hat r$ 时，会同时寻找高 $r^*$ 与高 $\epsilon$ 的区域；策略越能探索分布外回答，越可能发现奖励模型或验证器漏洞。提高优化强度无法区分两项。

KL 正则限制离参考策略的距离，可以降低进入高误差区域的速度，却不能保证奖励正确。更可靠的办法是扩大独立评估覆盖、对抗检查反馈、报告奖励与真实目标的分歧，并把关键硬条件放入可行域。偏好标签若系统性偏爱长回答，直接偏好优化会准确学到长度倾向；奖励模型若把格式整洁当作正确性，PPO 会进一步利用它。

### 1.3. critic 的收益与代价

critic 估计条件期望，理想情况下通过状态相关 baseline 降低策略梯度方差。它需要额外参数、价值 target 和训练预算，也引入函数逼近偏差。长序列终局奖励下，critic 能利用前缀预测成功概率，给不同 token 更细的优势；价值网络若学不准，错误优势会持续引导 actor。

无 critic 的 REINFORCE、RLOO 与 GRPO 类方法用序列回报或组内基线，尤其适合每个提示可以并行采样多条回答的场景。它们把代价转移到 rollout 数量：组太小，基线方差大；组内全同，优势消失；昂贵环境中，多采样可能比训练 critic 更贵。

可以用条件方差判断 critic 的潜在价值。若给定前缀后最终回报仍高度随机，准确价值函数能显著降方差；若奖励几乎完全由提示难度决定，提示级组内基线已经吸收大量变化；若每个提示只能获得一条昂贵轨迹，组内方法缺少比较样本。选择本质上是估计预算的分配。

### 1.4. 约束落在哪个空间

参数范数、token ratio、token KL 与序列 KL 控制的对象不同。参数距离和函数变化没有稳定对应；token 级裁剪限制已采样动作的代理贡献；平均 KL 衡量完整分布的局部偏移；序列 log-ratio 会随长度累积。方法声称「限制更新」时，需要明确限制量、期望所用状态分布和聚合单位。

硬约束与惩罚也不同。约束优化要求散度不超过阈值，拉格朗日惩罚用系数交换奖励与散度。固定系数不能保证每批数据都满足同一 KL 上限，自适应系数又形成额外控制回路。PPO clip 是代理目标中的截断，不等于显式 KL 约束；实际 KL 仍需独立观察。

参考模型约束适合保留基础能力，也会限制必要的分布移动。可验证数学任务可能需要产生参考模型极少使用的长推理；安全对齐则可能要求对高风险回答施加强约束。统一系数会把异质提示压到同一交换率，按任务或风险调整约束更符合目标结构。

### 1.5. 失效模式与比较口径

只有高质量固定偏好对且无法在线评分时，直接偏好方法适配数据，主要风险是离线覆盖、标签噪声与长度偏置。奖励模型可靠且能够在线生成时，PPO/RLOO 类方法可以探索新回答，主要风险转为奖励外推、策略陈旧和高方差。反馈可程序验证且每个提示可多采样时，组内估计较自然，全对全错组和长程信用分配需要另行处理。

多轮 agent 环境不能直接套用单轮回答口径。状态包含工具结果和外部副作用，轨迹更长，同一动作会改变后续可见信息。episode 边界、无效工具调用、超时截断和跨步奖励都要进入定义。过程价值、层级策略或模型式搜索可能比替换一个序列损失更关键。

公平比较应固定基础模型、提示分布、候选生成预算、总 token 数和验证器版本。算法若使用不同组大小或最大长度，仅固定训练步数会给它们不同采样预算。指标至少覆盖真实任务成功率、奖励、KL、生成长度、熵和随机种子方差。对可验证任务，pass@1 与固定预算 pass@$k$ 分别反映单次策略和推理搜索收益。

消融应围绕对象展开：只改 advantage 时保持采样与约束不变，只改 reduce 口径时保持奖励不变，只改参考项时保持数据不变。一次同时更换数据、基础模型、训练预算与损失函数，最终分数无法归因。算法选型的价值，在于把收益归回可复用的机制。

对齐算法的名字往往来自某个损失变体,实际训练系统的差异却遍布整条数据链.离线偏好优化读取已经收集的 prompt 与回答比较,不在更新过程中生成新回答;在线策略优化必须维护 rollout 推理服务,用当前或旧策略采样回答,再由奖励模型或验证器打分.前者的主要约束来自数据覆盖、参考策略与序列概率口径,后者还要处理优势估计、重要性比、策略漂移、采样吞吐和训练—推理版本同步.

算法选择由反馈形态、采样方式、约束对象和系统成本共同决定, 发布时间或单项 benchmark 排名不能替代这些条件.[DPO 家族比较](./04.01-dpo比较/04.01-dpo比较.md)覆盖 DPO、IPO、SimPO、ORPO 与 KTO,重点比较成对或非成对反馈、参考模型和序列目标.[GRPO 家族比较](./04.02-grpo比较/04.02-grpo比较.md)覆盖组采样策略优化及相关变体,重点比较优势归一化、token 或 sequence 概率比、裁剪、损失聚合和 KL.两组方法使用同一组选择维度,从而区分“无需 value model”“无需 reference model”和“无需在线 rollout”对应的不同成本.

## 2. 先固定比较对象

### 2.1 策略、参考策略与数据分布

用 $x$ 表示 prompt,$y=(y_1,\ldots,y_T)$ 表示回答,$\pi_\theta(y\mid x)$ 表示待训练策略,$\pi_{ref}$ 表示冻结参考策略.偏好数据可以是成对样本 $(x,y_w,y_l)$,其中 $y_w$ 优于 $y_l$;也可以是带 desirable/undesirable 标签的单回答.在线训练还会从 rollout policy $\pi_{old}$ 或当前策略为同一个 $x$ 采样一组回答 $\{y_i\}_{i=1}^G$,再获得奖励 $r_i$.

策略、参考策略和采样策略承担不同职责.$\pi_{ref}$ 定义偏离基准或隐式奖励的参照,$\pi_{old}$ 记录生成当前 batch 数据的行为分布,$\pi_\theta$ 是更新后的目标.实现中三者有时共享 checkpoint,却不能在公式中当成同一对象.若 rollout 系统滞后于 trainer,$\pi_{old}$ 与 $\pi_\theta$ 的差距会增大,重要性比和 Off-policy 偏差随之改变.

### 2.2 序列概率和 token 概率

自回归策略满足

$$
\log\pi_\theta(y\mid x)=\sum_{t=1}^{T}
\log\pi_\theta(y_t\mid x,y_{<t}).
$$

有些目标使用序列 log-prob 之和,有些除以有效 token 数,有些在 token 级计算 ratio 后再聚合.长度归一化会改变长短回答的相对权重;先对 token ratio 取几何平均与先求序列 log-prob 再指数化虽有关联,仍要检查 mask、长度和裁剪位置.算法名相同但概率口径不同,梯度尺度和长度偏好可能明显不同.

## 3. 六条统一选择维度

### 3.1 数据来源与反馈形态

第一条维度是数据是否在线产生.DPO、IPO、SimPO、ORPO 和 KTO 通常可在固定偏好数据上训练,训练循环接近监督微调;GRPO 类方法需要对 prompt 进行组采样,奖励在训练期间计算.离线方法避免 rollout 成本,但无法主动探索当前策略尚未覆盖的回答;在线方法能更新数据分布,也可能因奖励漏洞扩大坏行为.

第二条是监督单位.成对偏好只提供同一 prompt 下两个回答的顺序,KTO 可使用非成对二元反馈,RLVR 常给每个回答可验证结果.反馈信息量和标注噪声不同,不能在数据条件不匹配时仅凭损失形式选算法.如果只有 chosen/rejected 对,DPO 家族有直接接口;如果能为大量新采样答案廉价验证,组采样策略优化才拥有数据优势.

### 3.2 偏差、方差与 credit assignment

离线偏好损失直接对回答概率差求梯度,没有 Monte Carlo 策略梯度的奖励采样方差,却依赖偏好模型假设和固定数据分布.例如 DPO 从 KL-regularized RL 目标与 Bradley–Terry 偏好模型得到分类损失;若真实标注过程不符合假设,或数据由远离当前策略的模型生成,目标与在线最优策略之间会产生偏差.

GRPO 从同一 prompt 的 $G$ 个回答构造相对优势.组均值 baseline 可减少 prompt 难度带来的方差,组标准差归一化又会改变不同 prompt 的权重;当组内奖励几乎相同时,优势信号弱或数值不稳定.序列级奖励分配到所有 token 还会产生粗粒度 credit assignment.可验证最终答案并不表示中间推理 token 获得了准确奖励.

### 3.3 约束与参考分布

参考策略 KL 常用于限制模型偏离初始行为.DPO 将相对 $\pi_{ref}$ 的 log-ratio 写进隐式奖励;KTO 使用 KL 相关参考点;某些 SimPO 或 ORPO 配方取消显式 reference forward,改用 margin 或 SFT 项稳定训练.GRPO/PPO 类训练可把 KL 作为 reward penalty 或 loss 项,也可能通过 clipping 和早停控制更新.

“不需要 reference model”只说明训练时少一次冻结模型 forward 或存储,不表示目标没有任何分布锚点.SFT loss、固定数据和 margin 都会约束行为.同样,有 reference model 也不保证实际 KL 很小,因为系数、估计方式和序列长度共同决定约束强度.选型时要写清 KL 方向、计算粒度、系数与监控值.

### 3.4 稳定性与失效模式

离线方法常见失效包括 chosen/rejected 概率同时下降、长度偏置、过度拉大 preference gap 和对噪声标签过拟合.IPO 试图用有限最优 gap 避免可分数据上差距无限增长;SimPO 的目标 margin 与长度归一化需要联合调节;ORPO 把 SFT 与 odds ratio 组合,其稳定性依赖两项权重;KTO 的 desirable/undesirable 比例和 KL baseline 估计影响更新平衡.

在线方法还会出现奖励 hacking、熵快速下降、组内奖励零方差、ratio 爆炸、clip fraction 过高和 rollout/trainer 偏移.只看 reward 上升无法判断策略是否改善,必须同时监控验证集正确率、回答长度、熵、KL、组奖励分布和重复模式.**稳定性是数据、目标、采样和优化器共同结果,没有只靠算法缩写提供的保证.**

### 3.5 样本复用与 On-policy 程度

固定偏好数据可跨 epoch 重复使用,但重复次数过多会记忆偏好样本并偏离未覆盖 prompt.在线策略梯度的数据有效期更短;从 $\pi_{old}$ 采样后多 epoch 更新需要 ratio 校正和 clipping,更新越多,当前策略与行为策略差距越大.严格 On-policy 提高分布一致性,代价是 rollout 吞吐和奖励计算.

可复用性还取决于 reward 是否可重算.规则验证器可以对保存回答重新评分,奖励模型升级后旧分数可能需要刷新;人工偏好数据的原始比较可保留,但生成策略和采样温度决定覆盖范围.数据资产是否包含 prompt、完整回答、token mask、旧 log-prob、reward 分项与版本信息,会直接限制能切换哪些算法.

### 3.6 系统成本

离线偏好训练至少需要 policy forward/backward,DPO 等还需要 reference log-prob,可预计算或在线计算.预计算节省 GPU,但固定了 tokenizer、模板和 reference 版本.在线 GRPO 系统还需要高吞吐 rollout、组采样、验证或奖励服务、旧策略 log-prob、训练 batch 组装和权重同步.长回答会同时增加生成成本和反向激活显存.

显存比较应列出训练策略、reference、value model、optimizer state 和 activation.移除 value model 只减少其中一项;若每个 prompt 生成 $G$ 条长回答,rollout 与训练 token 数可能成为更大成本.系统吞吐还受生成端 Decode、训练端长序列 Prefill 和跨节点传输共同限制.

## 4. 两条家族路线

### 4.1 DPO 家族

进入[DPO 家族比较](./04.01-dpo比较/04.01-dpo比较.md)时,先固定数据形态和 log-prob 聚合.DPO 使用 policy 与 reference 对 chosen/rejected 的相对 log-ratio;IPO 将目标改成有限 gap;SimPO 以策略自身的长度归一化 log-prob 和 margin 比较回答;ORPO 把 SFT 与 odds-ratio preference 项放在一个阶段;KTO 接受非成对二元反馈并使用 KL 参考点.

选型不应从“哪个更新”开始.有高质量成对离线数据且可承担 reference 时,DPO 是清晰基线;担心 preference gap 无界时比较 IPO;希望取消 reference 时必须同时评估 SimPO/ORPO 的长度与 margin 行为;数据天然是单回答好坏标签时再考虑 KTO.所有比较都应锁定数据、模板、有效 token mask、batch token 数和评测.

### 4.2 GRPO 家族

[GRPO 家族比较](./04.02-grpo比较/04.02-grpo比较.md)按优势估计、概率比、裁剪、聚合与 KL 五条轴展开.组采样提供 prompt 内相对 baseline,但 reward normalization 是否除标准差、loss 是否按 token 或 sequence 平均、ratio 是 token 级还是 sequence 级,都会改变样本权重.这些差异不能都概括成“GRPO 小改进”.

DAPO 等方法通常是一组训练系统与目标改动,包括采样、过滤、裁剪或聚合设计,不能缩成一条非对称 clip 公式.GSPO 等 sequence-level ratio 方法改变约束粒度,需要结合回答长度与策略漂移评估.阅读具体变体时,逐项填入六维比较表,比按论文给出的总分排序更可靠.

## 5. 实际决策顺序

第一步确定反馈来源.只有静态比较数据时从 DPO 家族建立基线;拥有可扩展验证器或奖励服务,并能持续 rollout 时才进入在线组采样.第二步确定约束:是否需要 reference,允许多大 KL,是否保留 SFT 项.第三步选择概率与聚合口径,尤其是长回答中的 token mask、求和或平均.

第四步估算方差和系统预算.记录每 prompt 回答数、平均生成长度、reward 成本、训练 token 数、reference/value forward 和显存.第五步制定诊断:离线训练看 chosen/rejected margin、两侧 log-prob、长度和 KL;在线训练再加 reward 分布、零方差组、entropy、ratio、clip fraction 和 rollout lag.最后才比较能力与安全评测,并保留未参与训练的 prompt 分布.

任何结论都要绑定模型起点、数据版本、奖励、采样温度、组大小、上下文长度、训练预算和评测协议.离线方法更便宜不等于质量必然较低,在线 RL 能探索也不等于必然超过固定偏好优化.**选型的核心是让数据生成方式、估计量假设、分布约束和系统能力彼此匹配.**
