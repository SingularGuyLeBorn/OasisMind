# GMPO 理论与实现核对

GMPO 实现最容易出现的错误,是把 `rewards` 送进 `log()`.正确的数据流是:组内奖励先按 GRPO 得到每条 rollout 的 $\hat A_i$;当前/旧策略给出每个响应 token 的 log-prob;两者之差形成 token importance ratio;最后在**同一序列的有效 token**上做几何均值.

最小测试应覆盖:

1. 所有 token ratio 都为 1 时,几何均值为 1;
2. padding token 不参与乘积或分母;
3. 固定其余 ratio 为 1，将一个 ratio 从 1 向上增大，核对算术平均与几何平均的数值变化；这项标量检查不代替合成梯度范数比较；
4. 正,负 advantage 使用论文定义的方向敏感裁剪;
5. `old_log_probs` 不接收梯度;
6. 在 log space 聚合,避免长序列乘积上溢或下溢；
7. `min` 同时接收原始有向 log-ratio 与 `clamp` 输出；正 advantage 对应上侧截断，负 advantage 对应下侧截断；
8. 有效 token 数大于零，零 advantage 的主项为零；组内零标准差在 advantage 构造阶段显式处理。

importance ratio 的分母使用产生当前 rollout 的 `old policy`。Reference 若用于 KL 正则，应作为另一角色说明；论文 recipe 省略 KL 项仍保留 old-policy 比率。完整的来源连线、数值例子与正负方向见 [GMPO 主文](../1.3.5-gmpo.md) 中三张配图。

本地最小实现未包含 GRPO advantage 计算,rollout,分布式训练,奖励器和评测,不能标为 `verified-reference`.
