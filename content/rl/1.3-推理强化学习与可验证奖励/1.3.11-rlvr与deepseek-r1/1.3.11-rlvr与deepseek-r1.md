# RLVR 范式与 DeepSeek-R1 案例

RLVR(Reinforcement Learning with Verifiable Rewards)描述**奖励如何获得**:数学最终答案,代码测试,形式证明或环境任务能由规则,执行器或证明检查器给出可重复判定.它不限定优化器必须是 GRPO,也不保证 reward 完全无噪声.

任务成功率应由 `correct_i` 统计，不能直接拿总 reward 是否大于零代替。例如格式得分为正，不代表答案正确。超时、解析失败和部分通过如何映射到数值奖励，也应在训练前固定，并保留输出 ID 以便追溯。

## 1. 验证器为什么不是"0 方差"

同一输入和同一输出交给确定性程序,结果可以重复;但训练信号仍受策略采样,答案抽取,浮点容差,测试覆盖,沙箱状态,超时,隐藏用例和数据错误影响.组内 rollout 全对或全错时,GRPO 的归一化 advantage 还可能变成零方差组.

因此要分别测试:语义等价答案,解析失败,恶意输出,执行超时,非确定性程序,部分通过,奖励冲突,以及 verifier false positive / false negative.

若一组 rollout 的总 reward 完全相同，中心化后的分子为零，采用安全分母的 GRPO advantage 也为零。应分别记录任务成功率、零方差组率、格式得分占比、异常率和留出集正确率。具体字段与故障测试见[验证器设计](./01-验证器设计/01-验证器设计.md)。

## 2. DeepSeek-R1-Zero 与 DeepSeek-R1

- **DeepSeek-R1-Zero**:从 base model 直接进行大规模 RL,没有先做 SFT;论文报告自我验证,反思和长推理等行为出现,同时存在可读性差和语言混杂.
- **DeepSeek-R1**:先用冷启动数据,再做 reasoning-oriented RL;随后用 rejection sampling 等构造 SFT 数据,并进行面向通用能力与人类偏好的后续 RL.

一个容易漏画的区别是：报告 v2 的 §B.4.2 将两次 SFT 的参数起点都说明为 DeepSeek-V3-Base。因而第二次 SFT 同时接收 **Base 参数初始化** 与 **约 800K 训练数据**，不应把第一阶段 RL checkpoint 到第二次 SFT 画成单纯连续的参数微调。随后再进行第二阶段 RL，结合 reasoning rule reward、通用 helpfulness/safety reward 与语言一致性信号。[报告 v2，§3、§B.3.3、§B.4.2](https://arxiv.org/html/2501.12948v2)

R1 与 R1-Zero 的训练路径应分别理解。训练直接优化可验证结果与格式等信号；长推理、反思和自我验证是报告中的文本行为观察，不能据此证明它们对应人类认知过程。

## 3. 奖励与算法边界

DeepSeek-R1 的 reasoning RL 使用 accuracy reward 和 format reward,并采用 GRPO 以避免单独训练同规模 critic.技术报告中的系统提示,模型,数据,奖励提取器和训练规模共同决定结果;单独复制 `<think>` 标签或一个算术 verifier 不能复现 R1.

图中的 $G=16$、rollout 温度 1、学习率 $3\times10^{-6}$、KL 系数 0.001、每 400 步刷新 reference，以及 8.2K step 前后的 32,768/65,536 token 长度上限，均属于报告 v2 的 R1-Zero 设置，不是 RLVR 的统一默认值。[报告 v2，§§2.1–2.2](https://arxiv.org/html/2501.12948v2)
