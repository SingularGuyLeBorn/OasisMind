# 推理强化学习与可验证奖励

大模型把强化学习重新带回舞台中央以后，最容易被混在一起的三个东西是：**可验证奖励、组内相对优势和推理能力增长**。数学题答案能由规则检查，于是我们可以便宜地获得大量奖励；同一道题采样多个回答，于是可以用组均值代替单独训练的价值模型；训练后模型偶尔会写出更长的推理链，于是人们又很自然地把所有变化都归到“RL 让模型学会了推理”。这三件事确实互相作用，却不在同一个层级。

「可验证奖励强化学习」（Reinforcement Learning with Verifiable Rewards，RLVR）首先规定的是**奖励怎样产生**。给定 prompt $x$，策略生成回答 $y$，验证器 $V(x,y)$ 根据最终答案、测试用例、形式证明器或受控执行环境返回奖励 $r$。奖励可以是二元的 $r\in\{0,1\}$，也可以拆成格式分、正确性分和过程约束。接下来怎样用 $r$ 更新策略，仍然可以选 PPO、REINFORCE、RLOO、GRPO 或别的策略梯度估计器。**RLVR 是训练范式，不是某一个优化器的别名。**

这条区分决定了本章的组织方式。前半部分逐个拆开优势估计、重要性比、裁剪和损失聚合，后半部分再讨论验证器、计算扩展以及推理任务里真正棘手的 credit assignment。读完以后，看到一个新的“某某 PO”缩写，应该能判断它究竟改了采样、baseline、ratio、clip、KL、聚合还是训练系统，而不是只记住论文中的总分。

## 1. 从回答奖励到参数更新

设 prompt 为 $x$，回答 token 序列为 $y=(y_1,\ldots,y_T)$，当前待优化策略为 $\pi_\theta$，生成这批回答时的行为策略为 $\pi_{old}$。对同一个 prompt 采样 $G$ 个回答：

$$
y_i\sim\pi_{old}(\cdot\mid x),\qquad r_i=V(x,y_i),\quad i=1,\ldots,G.
$$

验证器只看到完整回答时，$r_i$ 是序列级信号。最直接的 REINFORCE 梯度估计为

$$
\hat g_i=(r_i-b(x))\sum_{t=1}^{T_i}
\nabla_\theta\log\pi_\theta(y_{i,t}\mid x,y_{i,<t}),
$$

其中 $b(x)$ 是不依赖当前采样动作的 baseline。它不改变期望梯度，却能减少“题目本身很难或很容易”造成的波动。PPO 通常由价值网络估计 baseline；RLOO 用同一 prompt 下其他回答的平均奖励；GRPO 则常把组内奖励减均值、再除标准差。三者解决的都是优势估计问题，但额外模型、估计偏差和组大小依赖并不相同。

做一个最小手算。同一道题生成四个回答，奖励为 $(1,1,0,0)$，组均值是 $0.5$，标准差按总体标准差计算也是 $0.5$，归一化优势为 $(1,1,-1,-1)$。如果奖励变成 $(1,1,1,1)$，组内差异消失，四个优势全为零，这批样本没有策略梯度信号。由此能看出：验证器返回确定结果，不等于梯度没有方差；采样得到哪些回答、组内是否有差异、长度多长、旧策略与当前策略差多远，都会改变更新。

将序列奖励复制到每个 token 还有一个明显边界：正确回答中的每一步都会收到同号优势，模型并不知道哪一步真正贡献了正确答案；错误回答里某些有价值的中间推理也会一起受罚。终局验证降低了人工标注成本，却没有自动解决长推理链的「信用分配」。过程奖励、步骤验证、搜索树回传和结果重采样都在补这个缺口，只是它们又引入新的标注或计算假设。

## 2. 为什么需要重要性比和裁剪

回答由 $\pi_{old}$ 采样，参数更新却发生在 $\pi_\theta$ 上。二者不一致时，常用 token 级重要性比

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{old}(y_{i,t}\mid x,y_{i,<t})}
$$

修正分布差异。PPO 风格目标取未裁剪项与裁剪项的较小者，限制单批数据把动作概率推得过远。这里有三个容易藏进实现细节的选择：ratio 是逐 token 计算还是先组合成序列比；损失按 token 平均还是按序列平均；长短回答怎样获得权重。它们会改变有效优化目标，所以“都使用 GRPO”不代表训练的是同一个东西。

裁剪提供局部更新约束，并不保证真实 KL 始终很小。训练还可能显式加入相对参考策略 $\pi_{ref}$ 的 KL 惩罚：

$$
J(\theta)=\mathbb E[r(x,y)]-
\beta\,\mathbb E\!left[
\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}
\right].
$$

$\pi_{old}$ 和 $\pi_{ref}$ 的职责也不同：前者说明数据由谁采样，用来处理 On-policy 偏移；后者定义希望策略不要远离的行为锚点。实际系统可能让二者暂时来自同一个 checkpoint，但概念上不能合并。rollout 服务更新滞后时，$\pi_{old}$ 会越来越旧；参考模型一般保持冻结。把两者混写，会让 ratio、KL 和权重同步问题全部失去口径。

## 3. 一串算法名究竟各自改了哪里

阅读顺序从 [GRPO](./1.3.1-grpo/1.3.1-grpo.md) 开始。它提供最常见的组采样框架：同题多答、组内标准化、无需单独价值模型，然后在 PPO 式代理目标中更新策略。[RLOO](./1.3.2-rloo/1.3.2-rloo.md) 用 leave-one-out baseline 避免把当前样本自己的奖励放进基线；两者都借助同题多样本降方差，但优势的缩放方式不同。

[DAPO](./1.3.3-dapo/1.3.3-dapo.md) 应当作为一整套训练配方阅读，其中包含采样、过滤、裁剪和聚合设计，不能压缩成单个公式。[GSPO](./1.3.4-gspo/1.3.4-gspo.md) 把约束粒度推向序列级；[GMPO](./1.3.5-gmpo/1.3.5-gmpo.md)、[GDPO](./1.3.6-gdpo/1.3.6-gdpo.md) 与 [GHPO](./1.3.7-ghpo/1.3.7-ghpo.md) 则继续调整优势、聚合或长度权重。比较它们时要固定模型、prompt、组大小、采样温度、最大长度、奖励与训练 token 预算，否则无法判断收益来自目标变化，还是更贵的 rollout。

[JustRL](./1.3.8-justrl/1.3.8-justrl.md) 把问题拉回一个很重要的工程判断：复杂技巧是否在受控对照里仍然必要。[Tricks or Traps](./1.3.10-tricks-or-traps/1.3.10-tricks-or-traps.md) 进一步检查看似稳定训练的技巧会不会改变样本权重、吞掉有效梯度或掩盖奖励问题。算法改动越小，实验口径越要严；否则一个 batch 组织差异就足以制造“新算法”的优势。

## 4. 推理能力来自哪里

[RLVR 与 DeepSeek-R1](./1.3.11-rlvr与deepseek-r1/1.3.11-rlvr与deepseek-r1.md) 讨论可验证奖励怎样与推理模型相遇。数学、代码和形式任务适合 RLVR，是因为最终结果能以较低成本核验，模型可以在大量在线样本上探索。不过奖励只覆盖可验证部分：表达质量、事实完整性、风险边界和开放问题通常没有同样可靠的判定器。若训练分布长期偏向“有唯一答案”的任务，模型也可能学会迎合验证器格式，而没有获得可迁移的通用推理。

[强化学习计算扩展](./1.3.9-强化学习计算扩展/1.3.9-强化学习计算扩展.md) 关心增加 prompt 数、每题采样数、回答长度和更新步数后，能力是否按可预测方式增长。这里的成本不能只算 trainer FLOPs。每个 prompt 采样 $G$ 条长回答，往往让 Decode、验证器执行和跨节点数据传输成为瓶颈；旧 log-prob、mask、奖励分项和策略版本也必须与样本一起保存，训练端才能知道自己在优化哪一批行为数据。

[OREO](./1.3.12-oreo/1.3.12-oreo.md) 将视线转向离线推理优化：已有推理轨迹能否在不持续在线 rollout 的条件下被利用。离线方法省去实时采样系统，却受到数据覆盖和分布偏移限制。好的离线轨迹没有覆盖到的行为，目标函数无法凭空探索出来；坏轨迹过多时，价值或偏好估计又会把数据噪声吸进模型。

## 5. 本章采用的统一检查口径

后续每篇算法文章都应回答同一组问题：样本由哪个策略生成；一个 prompt 产生多少回答；奖励作用在 token、步骤还是完整序列；baseline 怎样计算；ratio 在什么粒度定义；是否使用参考策略；KL 在 reward 还是 loss 中；裁剪发生在哪里；损失按 token 还是序列聚合；数据能复用多少轮；rollout 与 trainer 允许多大版本差；训练成本里谁占主要部分。

实验结果还要同时观察 reward、验证集正确率、回答长度、熵、KL、组内零方差比例、ratio 与 clip fraction。**reward 上升只说明模型更会拿当前验证器的分，不足以证明推理更可靠。**真正值得相信的增长，应当在未参与训练的问题、不同验证环境和受控预算下仍然存在，并且没有靠无限加长回答、利用解析漏洞或牺牲其他能力换取。

顺着这条路线，本章最终会形成一套「奖励来源—采样分布—优势估计—约束粒度—系统实现—能力结论」的分析框架。新的 GRPO 变体再多，也可以落回几个可计算、可检查的问题上。
