# JustRL:固定配方的单阶段 GRPO 基线

JustRL 的"简单"指减少训练阶段切换和动态干预,不是发明一个无裁剪的新优化器.论文明确使用 **veRL 的标准 GRPO 实现**,二元结果奖励和 DAPO 的轻量规则验证器.

## 1. 保留与移除的内容

| 设计 | 论文设置 |
|---|---|
| 优化器 | veRL 默认 GRPO |
| 奖励 | binary outcome reward,DAPO 规则验证器 |
| 训练阶段 | 单阶段连续训练 |
| 超参数 | 全程固定,两种 1.5B backbone 共用 |
| 数据 | DAPO-Math-17k,不做离线难度过滤或在线动态采样 |
| 长度 | 最大上下文 16K,不加入显式长度惩罚 |
| KL / entropy loss | 均不使用 |
| 裁剪 | 保留 clip-higher,比例范围 `[0.8, 1.28]` |

注意:"No PPO clipping""直接用 REINFORCE + group norm""group size 64+"这些说法都不是论文配方.论文表 2 的 rollout N 是 8,学习率为固定 `1e-6`,训练 batch 256.

**图 1 解析**

- `max prompt=1K`,`max response=15K`,`max context=16K` 共同定义训练长度边界.
- KL loss,entropy regularization 和 explicit length penalty 在该 recipe 中设为 off;这不等于删除 GRPO 的 importance ratio 或 clipping.
- 同一配置只在论文给出的两个 1.5B backbone 上得到验证,不能直接外推到其他规模与数据.

**图 2 解析**

- $\hat A_i$ 在同一 response 的全部有效 token 上共享,与 GAE 无关.
- old-policy log-prob 使用 stop-gradient,padding token 不进入 token 平均.
- 图中 loss 带负号并使用 gradient descent,等价于最大化 clipped surrogate objective.
- recipe 关闭的 KL/entropy/length 项不改变图中 clipped GRPO 主体.

## 2. 实验范围

论文在 DeepSeek-R1-Distill-Qwen-1.5B 与 OpenMath-Nemotron-1.5B 两个 backbone 上训练,使用 32 张 A800-80GB,约 15 天;同一组超参数分别训练 4,000+ 与 3,000+ steps.作者在九个数学基准上报告约 54.9% 与 64.3% 的平均准确率,并把总计算与若干复杂 recipe 比较.

这些结论属于两个 1.5B 数学推理设置.不能外推为"单卡可训练 7B""PPO 普遍有害"或"所有稳定性机制都不需要".论文真正支持的是:在其规模和协议里,一个经过验证的固定基线可以长时间平滑扩展.

**图 3 解析**

- MATH-500,Minerva Math,OlympiadBench 每题采样 $N=4$;其余六个 benchmark 使用 $N=32$.
- 论文报告的是对 $N$ 次采样的 Pass@1 correctness 取平均,不能用一次 greedy accuracy 替代.
- 复现必须记录 checkpoint step,seed,temperature/top-p,各 benchmark 的 $N$,最大生成长度和 judge/fallback 版本.

## 3. 为什么移除旧实现

旧 `implementation.py` 用 `torch.randn(..., requires_grad=True)` 伪造 log-prob,梯度与模型参数无关,同时删掉了论文实际使用的 importance ratio 和 clip-higher.它已与 Notebook,无关 LIMA PDF 一起移入不公开归档(`_archive/unverified/`),不再出现在公开算法目录.
