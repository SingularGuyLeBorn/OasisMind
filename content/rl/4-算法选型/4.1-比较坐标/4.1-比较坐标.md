# 离线偏好与在线组采样的比较坐标

算法选型不能先问 DPO、PPO 还是 GRPO。先问训练数据由谁生成、反馈以什么形态出现、当前策略能否继续探索，以及系统能否承担 rollout、reference、reward model 与 critic。算法名字只是这些条件落到估计器和代理目标后的组合。

[DPO 家族比较](./4.1.1-dpo家族比较.md)处理固定离线反馈。成对偏好、独立二元标签、是否保留 reference、序列分数求和还是平均，会分别导向 DPO、IPO、ORPO、SimPO 与 KTO。离线方法复用数据方便，却无法从固定支持集之外自动获得新行为证据。

[GRPO 家族比较](./4.1.2-grpo家族比较.md)处理当前策略对同一 prompt 的成组采样。组均值、留一 baseline、标准差归一、token 或序列级 ratio、动态采样与 loss 归约是彼此独立的设计轴。它省去 critic，却用更多 rollout 换取组内反事实，并受到全同组与长程信用广播限制。

比较两类方法时，训练 step 和 epoch 不是公平预算。应同时报告标注样本、生成 token、训练 token、模型驻留、执行环境成本与独立评测。在线方法能够发现新失败模式，也会主动寻找 verifier 漏洞；离线方法更稳，也可能持续拟合数据偏差。选择来自问题条件，不来自一张脱离语境的排行榜。
