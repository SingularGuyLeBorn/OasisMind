# 演员-评论家算法 (Actor-Critic)

REINFORCE 用完整轨迹的 MC return 更新策略,公式直接,但一个早期 action 会背负之后所有环境随机性.Actor-Critic 同时学习策略 $\pi_\theta(a\mid s)$ 与价值函数 $V_\phi(s)$:Actor 决定 action,Critic 估计当前策略从状态 $s$ 出发的期望回报.

Critic 提供的是相对基准和 bootstrap 终点. 它通常降低 estimator 方差,也把 value 预测误差带进 Actor. 这一章沿着 MC、TD、n-step 与 GAE 展开,并把采样版本、终止边界、detach 和更新顺序放进同一条训练链.

真正需要掌握的是每个 target 由哪些已观察 reward 和哪些预测 value 组成,以及这些量对应哪一个策略版本.

---

## 1. 从REINFORCE到Actor-Critic

Actor-Critic 保留 policy gradient 的 score-function 骨架,改变的是 $Q^\pi$ 或 advantage 的估计方式.REINFORCE 等到 episode 结束后用 $G_t$;Actor-Critic 让学习中的 $V_\phi$ 提供 baseline,并在 TD target 中预测尚未发生的未来.

这一步换来更及时、更低方差的更新,也增加了一个会犯错的估计器. 所以阅读 Actor-Critic 时需要同时追踪两条误差:Actor 的采样梯度噪声,以及 Critic 的 bootstrap 偏差.

### 1.1 回顾REINFORCE的痛点

在REINFORCE中,我们最大化目标函数:

$$ J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta} [R(\tau)],\qquad R(\tau)=\sum_{t=0}^{\infty}\gamma^t r_t $$

其梯度为:

$$ \nabla_\theta J(\theta) = \mathbb{E}_{\tau}\left[\sum_{t=0}^{\infty}\gamma^t\nabla_\theta \log \pi_\theta(a_t|s_t) \cdot G_t\right] $$

其中 $G_t = \sum_{k=0}^\infty \gamma^k r_{t+k}$ 是从 $t$ 时刻开始的**实际累积回报**. 外部的 $\gamma^t$ 来自起点折扣目标; 如果将时间步按 discounted occupancy 采样, 它可以吸收到采样分布中. 实践里对 rollout 时间步做普通均值的 Actor loss 会重新加权各时刻, 是常用 surrogate, 不能在没有说明采样口径时直接称为上述 $J$ 的逐项无偏估计.

**痛点**: $G_t$ 对路径极其敏感. 如果环境本身是随机的(例如在这个状态采取同一个动作,有时得100分,有时得-10分),或者策略本身是随机的,那么 $G_t$ 的波动会很大. 为了获得准确的梯度估计,我们需要采样成千上万条轨迹来平均掉这些噪声.

### 1.2 引入基线 (Baseline)

为了降低方差,我们可以引入一个基线 $b(s_t)$:

$$ \nabla_\theta J(\theta) = \mathbb{E}_{\tau}\left[\sum_{t=0}^{\infty}\gamma^t\nabla_\theta \log \pi_\theta(a_t|s_t) \cdot (G_t - b(s_t))\right] $$

只要 $b(s_t)$ 不依赖于动作 $a_t$,这个梯度就是无偏的(我们在1.1.4 节已经证明过).
工程上最常用的基线是状态价值 $V^\pi(s_t)$. 它只依赖状态,可以在不改变策略梯度期望的前提下消除不同状态本身的回报尺度差异.

### 1.3 评论家登场

如果我们将 $G_t$ 替换为一个**学习到的函数**,会发生什么?
我们定义一个参数为 $\phi$ 的神经网络 $V_\phi(s)$ 来拟合状态价值 $V^\pi(s)$.

这时,我们可以用 $Q^\pi(s_t, a_t)$ 的估计值来替代 $G_t$.
根据贝尔曼方程:
$$ Q^\pi(s_t, a_t) = \mathbb{E} [r_t + \gamma V^\pi(s_{t+1}) ] $$

那么,梯度更新中的 $(G_t - b(s_t))$ 变为:
$$ \text{Target} - \text{Baseline} = (r_t + \gamma V_\phi(s_{t+1})) - V_\phi(s_t) $$

这个量正是**TD误差 (TD Error)** ,通常记为 $\delta_t$. 这也是**优势函数 (Advantage Function)** 的一种估计:

$$ A(s_t, a_t) \approx r_t + \gamma V(s_{t+1}) - V(s_t) $$

**Actor-Critic的核心思想**:
- **Critic**: 负责学习 $V_\phi(s)$,目标是最小化TD误差的平方 (或其他Value Loss).
- **Actor**: 负责学习 $\pi_\theta(a|s)$,沿着Critic指出的优势方向更新,最大化 $A(s, a)$.

## 2. 偏差-方差权衡 (Bias-Variance Tradeoff)

MC 与 TD 不只是两种代码写法,它们使用的信息范围不同.MC 等待真实未来,不依赖末状态 value;TD 只观察短期 reward,把余下未来交给 Critic. n-step return 在两端之间选择 bootstrap 的位置.

偏差和方差也不是算法的固定标签.Critic 越准确,TD bias 越小;环境未来越随机,MC variance 越大;轨迹截断、终止 mask 和 value target 的实现又会改变两者. 因此需要在同一采样口径下比较 estimator.

这是理解RL算法设计的核心视角.

### 2.1 蒙特卡洛 (MC) vs. 时间差分 (TD)

| 方法 | 目标值 (Target) | 偏差 (Bias) | 方差 (Variance) | 依赖模型? |
|------|-----------------|-------------|-----------------|-----------|
| **MC (REINFORCE)** | $G_t$ (完整 on-policy 回报) | 边界与采样口径正确时对相应 value 无偏 | 通常较高,受整条路径随机性影响 | 否 |
| **TD (Actor-Critic)** | $r_t + \gamma V(s_{t+1})$ | 取决于 Critic; $V=V^\pi$ 时单步 target 的条件期望正确 | 通常较低,但仍受 reward、transition 与 value 误差影响 | 否 (Model-Free) |

- **REINFORCE**: 单条采样轨迹获得高回报时, 轨迹中的动作都会收到正向更新, 即使高分主要来自随机性. (High Variance)
- **Actor-Critic**: "我有了一个对未来的估计 $V$. 这次拿了 $r_t$,如果 $r_t + \gamma V_{next} > V_{curr}$,说明比预期好,我就鼓励这个动作. " (Low Variance, Biased if $V$ is wrong)

### 2.2 多步自举 (n-step Bootstrapping)

为了平衡偏差和方差,我们可以不仅仅看一步,而是看 $n$ 步:

- **1-step**: $G_t^{(1)} = r_t + \gamma V(s_{t+1})$ (通常方差较低;近似 Critic 会引入 bootstrap bias)
- **2-step**: $G_t^{(2)} = r_t + \gamma r_{t+1} + \gamma^2 V(s_{t+2})$
- ...
- **$\infty$-step**: $G_t^{(\infty)} = G_t$ (MC) (完整 on-policy 轨迹和正确边界下无 bootstrap bias,方差通常较高)

我们可以混合使用这些目标. 这引出了**Generalized Advantage Estimation (GAE)** .

### 2.3 MC、TD 与 advantage 怎样连起来

在策略 $\pi$ 下,状态价值和动作价值分别为:

$$
V^\pi(s_t)=\mathbb{E}_\pi[G_t\mid s_t],\qquad
Q^\pi(s_t,a_t)=\mathbb{E}_\pi[G_t\mid s_t,a_t].
$$

优势函数比较「指定动作」与「该状态下按策略随机行动」的期望差异:

$$
A^\pi(s_t,a_t)=Q^\pi(s_t,a_t)-V^\pi(s_t).
$$

REINFORCE 用采样回报 $G_t$ 估计 $Q^\pi(s_t,a_t)$,于是 $G_t-V_\phi(s_t)$ 是 MC advantage. Actor-Critic 再利用 Bellman 关系

$$
Q^\pi(s_t,a_t)=\mathbb{E}_\pi[r_t+\gamma V^\pi(s_{t+1})\mid s_t,a_t]
$$

把未知的完整未来替换成一步 reward 加下一状态的 value,得到 TD error:

$$
\delta_t=r_t+\gamma(1-d_t)V_\phi(s_{t+1})-V_\phi(s_t).
$$

$d_t=1$ 表示环境在这一步真正终止,此时没有后续回报,bootstrap 项必须归零. 若 rollout 只是因为固定长度、时间限制或 batch 边界而被**截断**,环境状态仍有未来,$d_t$ 不应直接设成 $1$;应额外计算末状态 value. 把截断误当终止会系统性低估边界附近的 return.

MC target 在环境随机性下波动较大,但只要 episode 完整且采样、折扣处理正确,它不依赖一个学习中的 value 预测. TD target 只看一步随机结果,方差通常更低,却把 $V_\phi(s_{t+1})$ 的误差带进目标. 这里的偏差还会随训练变化:Critic 越准确,bootstrap 误差越小;Critic 很差时,Actor 会被一个错误基准持续引导.

### 2.4 手算一:同一轨迹上的 MC target 与 TD target

设一条三步轨迹的 reward 为 $r_0=1,r_1=0,r_2=2$,在 $t=2$ 后真正终止,折扣因子 $\gamma=0.9$. 完整 MC return 从后往前计算:

$$
G_2=2,
$$

$$
G_1=0+0.9\times2=1.8,
$$

$$
G_0=1+0.9\times1.8=2.62.
$$

假设 Critic 当前给出 $V(s_0)=2.0,V(s_1)=1.5,V(s_2)=1.0$. 对 $t=0$,一步 TD target 为

$$
y_0^{\mathrm{TD}}=1+0.9\times1.5=2.35,
$$

因此 $\delta_0=2.35-2.0=0.35$. MC advantage 则为 $G_0-V(s_0)=2.62-2.0=0.62$. 两者都认为 $a_0$ 比基准好,但强度不同.TD 没有等待后两步全部展开,代价是依赖 $V(s_1)=1.5$ 的准确性. 若 rollout 在 $s_1$ 处只是被采样长度截断,仍应用 $1+0.9V(s_1)$;只有 $s_1$ 是真实终止状态时,target 才退化为 $1$.

## 3. 广义优势估计 (GAE)

GAE 将相邻 TD error 按指数权重累加,用一个 $\lambda$ 控制多远的真实 reward 进入 advantage. 它不改变 policy-gradient 的形式,只构造更平滑的 $\hat A_t$.

推导的关键是 n-step advantage 可以拆成 TD error 的望远镜和. 实现的关键是从后向前递推,并在真实终止处切断、在时间截断处保留 bootstrap.

**论文**: "High-Dimensional Continuous Control Using Generalized Advantage Estimation" (Schulman et al., 2015)

GAE 是现代Policy Gradient算法(PPO, TRPO)的标配. 它通过加权平均不同步数的TD误差,巧妙地在偏差和方差之间取得平衡.

定义一步 TD error:
$$ \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t) $$

先看二步 return 对应的 advantage:

$$
\begin{aligned}
\hat A_t^{(2)}
&=r_t+\gamma r_{t+1}+\gamma^2V(s_{t+2})-V(s_t)\\
&=r_t+\gamma V(s_{t+1})-V(s_t)\\
&\quad+\gamma[r_{t+1}+\gamma V(s_{t+2})-V(s_{t+1})]\\
&=\delta_t+\gamma\delta_{t+1}.
\end{aligned}
$$

第二行人为加上再减去 $\gamma V(s_{t+1})$,两项恰好把二步 return 拆成相邻的 TD error. 同理,

$$
\hat A_t^{(k)}=\sum_{l=0}^{k-1}\gamma^l\delta_{t+l}.
$$

GAE定义为所有这些 $k$-step 优势的指数加权平均:

$$ A^{GAE(\gamma, \lambda)}_t = (1-\lambda) (A^{(1)}_t + \lambda A^{(2)}_t + \lambda^2 A^{(3)}_t + ...) $$

现在把同一个 $\delta$ 的系数逐项收集. $\delta_t$ 出现在所有 $k\ge1$ 的项里,系数是 $(1-\lambda)(1+\lambda+\lambda^2+\cdots)=1$. $\delta_{t+1}$ 从 $k=2$ 开始出现,系数为

$$
(1-\lambda)\gamma(\lambda+\lambda^2+\cdots)=\gamma\lambda.
$$

一般地,$\delta_{t+l}$ 的系数为 $(\gamma\lambda)^l$,于是:

$$ A^{GAE(\gamma, \lambda)}_t = \sum_{l=0}^\infty (\gamma \lambda)^l \delta_{t+l} $$

**参数 $\lambda$ 的作用**:
- $\lambda = 0$: $A_t = \delta_t = r_t + \gamma V_{t+1} - V_t$ (即普通的 Actor-Critic,通常方差较小;Critic 不准时会有 bootstrap bias)
- $\lambda = 1$: $A_t = \sum \gamma^l \delta_{t+l} = G_t - V_t$ (边界处理正确时接近 REINFORCE 基线法,通常方差较大;不能脱离轨迹与 Critic 条件宣称偏差必然更小)

$\lambda$ 越小,估计越依赖近期 bootstrap,通常方差较低但更敏感于 Critic 偏差;$\lambda$ 越接近 $1$,越多真实 reward 进入估计,通常降低 bootstrap 偏差并提高轨迹方差. 在有限 rollout 中,$\lambda=1$ 只有在末端是真终止,或者截断边界使用了正确的 bootstrap value 时,才能对应相应的 MC 形式.

**递归计算公式**(代码实现关键):
由于 $A_t = \delta_t + \gamma \lambda A_{t+1}$,我们可以从后往前递归计算GAE,很高效.

```python
last_gae = 0
advantages = []
for t in reversed(range(len(rewards))):
    delta = rewards[t] + gamma * values[t+1] * bootstrap_mask[t] - values[t]
    gae = delta + gamma * lambda * trace_mask[t] * last_gae
    advantages.insert(0, gae)
    last_gae = gae
```

这里必须区分两个 mask. `bootstrap_mask=1-terminated` 决定能否使用 terminal observation 的 value: 真终止取 0, time-limit truncation 仍可取 1. `trace_mask` 决定 $A_{t+1}$ 是否属于同一 episode; 遇到 termination、truncation 或 auto-reset 边界都取 0, 防止 reset 后新 episode 的 `last_gae` 串回旧 episode. 单纯到达 rollout buffer 尾部但环境未结束时, 可以用末状态 value bootstrap, 反向递推则在本批边界以 `last_gae=0` 截断.

### 3.1 手算二:从 TD error 到 GAE

沿用前面的三步轨迹,取 $\gamma=0.9,\lambda=0.8$,并补充终止状态 $V(s_3)=0$. 三个 TD error 为:

$$
\delta_0=1+0.9\times1.5-2.0=0.35,
$$

$$
\delta_1=0+0.9\times1.0-1.5=-0.60,
$$

$$
\delta_2=2+0-1.0=1.00.
$$

从后向前递推,$\gamma\lambda=0.72$:

$$
\hat A_2=1.00,
$$

$$
\hat A_1=-0.60+0.72\times1.00=0.12,
$$

$$
\hat A_0=0.35+0.72\times0.12=0.4364.
$$

也可以直接展开验证:$0.35+0.72(-0.60)+0.72^2(1.00)=0.4364$. 一步 TD 只给 $a_0$ 优势 $0.35$;GAE 把后续先坏后好的信息按指数衰减带回,得到 $0.4364$;完整 MC advantage 是 $0.62$. 三个数体现的正是不同 bootstrap 深度下的 bias/variance 选择,不能据单条轨迹断言哪一个更准确.

### 3.2 $\lambda$-return 与 Critic target

GAE 给 Actor 提供 advantage. Critic 可以使用与之匹配的 $\lambda$-return:

$$
\hat R_t^{\lambda}=\hat A_t^{\mathrm{GAE}}+V_{\phi_{\mathrm{old}}}(s_t).
$$

右侧 value 应来自采样时保存的旧预测,并作为固定 target. 若一边更新 $V_\phi$,一边让 target 随当前 $V_\phi(s_t)$ 反向传播,回归目标本身也跟着移动,梯度不再对应预期的 value fitting. 实现时应对 advantage、bootstrap value 和 $\lambda$-return target 做 `detach` 或在无梯度环境中构造.

## 4. 数据由谁采样,梯度更新给谁

Actor-Critic 的 loss 很短,数据依赖却很严格. Action 由行为策略采样,value 与 log-prob 对应特定参数版本,GAE 使用同一条轨迹上的 reward 和终止标记. 其中任一版本错位,都会让公式表面正确、实际 estimator 失去目标.

梯度边界同样重要.Advantage 是 Actor 的固定权重,return 是 Critic 的固定 target. Detach 不是性能优化,而是在声明哪个网络负责拟合哪个量.

标准 A2C 是 on-policy 方法. rollout 中的动作由当前行为策略 $\pi_{\theta_{\mathrm{old}}}$ 采样:

$$
a_t\sim\pi_{\theta_{\mathrm{old}}}(\cdot\mid s_t).
$$

收集固定长度的 $s_t,a_t,r_t,d_t$ 后,冻结这批数据,计算旧 value、GAE 和 return target,再更新 Actor 与 Critic. 如果同一批轨迹被反复训练很多轮,新策略逐渐偏离采样策略,on-policy 梯度假设就不再成立.PPO 会显式使用概率比率并限制偏离;纯 A2C 通常采一批、更新一次或少数受控步骤,然后丢弃数据.

Actor 的最小化目标为:

$$
L_{\mathrm{actor}}(\theta)
=-\frac{1}{N}\sum_t
\log\pi_\theta(a_t\mid s_t)\,\operatorname{stopgrad}(\hat A_t).
$$

当 $\hat A_t>0$ 时,梯度提高已采样动作的概率;当 $\hat A_t<0$ 时,梯度降低它.Critic 的目标为:

$$
L_{\mathrm{critic}}(\phi)
=\frac{1}{2N}\sum_t
\left(V_\phi(s_t)-\operatorname{stopgrad}(\hat R_t^\lambda)\right)^2.
$$

即使 Actor 与 Critic 共享 backbone,两项损失的语义也没有改变. advantage 对 Actor 必须 detach,避免策略损失沿着 $\hat A_t$ 反向推动 Critic 去制造更有利的权重;Critic target 也 detach,避免 bootstrap 两端一起追逐. 共享表示仍会同时接收 policy loss 与 value loss 的梯度,这属于多任务共享,需要用损失权重和梯度裁剪控制干扰.

一个稳妥的更新顺序是:

1. 用旧参数与环境交互,保存 reward、终止标记、动作 log-prob 和 value;
2. 对 rollout 末状态再算一次 value. 真终止取 $0$,时间截断或固定长度截断保留预测;
3. 在无梯度环境中从后向前计算 TD error、GAE 和 $\lambda$-return;
4. 用已冻结的 advantage 计算 Actor loss,用已冻结的 return target 计算 Critic loss;
5. 合并熵项与加权 value loss,清空梯度,反向传播,裁剪后更新参数;
6. 丢弃旧 rollout,再用更新后的策略采下一批数据.

若 Actor 与 Critic 是完全独立网络,可以分别 backward 和 step;若共享 backbone,通常合并损失后做一次 backward 更清楚. 无论采用哪种顺序,同一批 target 应保持固定,不能先更新 Critic 后重新计算 advantage,再把变动后的数交给 Actor.

### 4.1 手算三:baseline 怎样改变策略梯度方向

考虑某个状态下只有动作 $a_1,a_2$,策略概率分别为 $0.6,0.4$. 一次 batch 在该状态采到两条样本:

| 样本 | 动作 | MC return | value baseline | advantage |
|---|---|---:|---:|---:|
| 1 | $a_1$ | $5$ | $3$ | $2$ |
| 2 | $a_2$ | $1$ | $3$ | $-2$ |

忽略平均系数,Actor loss 是

$$
L_{\mathrm{actor}}
=-[2\log 0.6+(-2)\log 0.4]
=-2\log0.6+2\log0.4.
$$

最小化它会提高 $a_1$ 的概率并降低 $a_2$ 的概率. baseline 并没有要求「return 大于零就奖励」,而是在问动作结果是否高于该状态下的平均预期. 如果不减 baseline,两个 return 都为正,两次样本都会推动各自动作概率上升;batch 内仍可能通过归一化约束形成相对变化,但梯度噪声更大,也更难跨回报尺度不同的状态比较.

Critic 对这两条样本若使用 MC target,在同一个状态看到 target $5$ 和 $1$,MSE 最优预测是均值 $3$. 这也解释了 value baseline 的含义:它预测条件期望,而不是复述某一条轨迹. 换成 TD 或 $\lambda$-return 后,target 的方差会变小,但其均值会受到 bootstrap 预测误差影响.

### 4.2 advantage 归一化不能修复错误 target

实现常把一批 advantage 标准化:

$$
\tilde A_t=\frac{\hat A_t-\mu_A}{\sigma_A+\epsilon}.
$$

它能控制不同 batch 的梯度尺度,通常也让优化更稳定,但不会让有偏 advantage 自动变成无偏. 若终止 mask 写错、末状态没有 bootstrap,整批边界样本都被低估;减均值只能重新居中,不能恢复丢失的未来价值. 同样,标准化范围也属于算法口径:按全 batch、按单条 episode 或按环境分别计算,会产生不同的相对权重.

熵正则的梯度则直接来自策略分布,不经过 advantage. 它鼓励策略在证据不足时保留探索,但系数过大也会抵消 Actor 已经学到的偏好. Value loss 权重、熵权重和梯度裁剪共同决定共享 backbone 收到的更新比例;它们是优化超参数,不能用来掩盖采样策略或 return 计算上的错误.

标准化还会改变不同轨迹在 batch 中的相对权重. 若一个 batch 混合多个 reward 尺度差异很大的环境,全局标准化可能让低方差环境的微小差异被放大,也可能压低高方差环境的重要事件. 更稳妥的做法是先明确训练目标是否真的允许这些环境共享尺度,再决定按全 batch、按任务或按环境统计.

当 batch 很小,$\mu_A$ 与 $\sigma_A$ 自身也有明显采样噪声. 训练日志应同时保存归一化前后的 advantage 分布,否则只看 policy loss 很难判断更新变小是 Critic 更准、reward 变窄,还是标准化统计发生变化.

### 4.3 为什么这批数据不能无限复用

设轨迹由行为策略 $\mu$ 采样,当前希望更新的策略是 $\pi_\theta$. 当二者不同,直接使用 $\nabla\log\pi_\theta(a_t\mid s_t)\hat A_t$ 会把 $\mu$ 访问到的状态—动作分布当成 $\pi_\theta$ 自己的分布. 最基本的动作概率修正是重要性比率:

$$
\rho_t=\frac{\pi_\theta(a_t\mid s_t)}{\mu(a_t\mid s_t)}.
$$

但长轨迹的完整分布修正涉及多个比率连乘,容易产生很高方差;Critic target 也可能对应旧策略的未来价值. 因此纯 A2C 不把 replay buffer 当作主要数据源. 采样后的短暂计算阶段允许参数保持不变,更新结束后就重新采样. PPO、IMPALA、SAC 等方法各自增加约束、截断修正或 off-policy 目标,正是在处理数据复用和策略漂移,不能只把 A2C 的 batch 多跑几遍就当成等价替代.

还有一个容易漏掉的边界:并行环境在同一轮采样时使用的必须是同一个可识别 policy 版本. 如果某些 worker 已拉取新参数,另一些仍在用旧参数,行为策略 $\mu$ 就变成混合分布. A3C 允许一定程度的异步和 stale gradient,这是它明确接受的系统折中;同步 A2C 的价值之一,正是让采样版本和更新边界更清楚.

Critic 版本也要和 rollout 对齐. 轨迹末端的 bootstrap value、每一步保存的 value 与 GAE 递推若来自不同更新阶段,$\delta_t$ 会混合多个 value function. 同步实现通常在 rollout 完成后、参数更新前一次性计算这些量,并把 target 固定到本轮优化结束.

如果确实需要异步收集,数据结构应保存 policy version 和 value version,训练端按允许的 stale 范围过滤或修正. 把所有 worker 输出直接拼接,再靠更大的 batch 平均,无法消除系统性的版本偏移.

## 5. A2C vs A3C

A2C 与 A3C 共享 Actor-Critic 数学目标,主要差异在采样和参数更新的系统组织.A3C 允许 worker 异步推送梯度,A2C 等待并行环境组成同步 batch. 两者对 stale policy、吞吐和硬件利用的权衡不同.

无论采用同步还是异步,都必须知道数据由哪个策略版本生成. 系统并行可以降低样本相关性、提高吞吐,却不会自动修正 advantage 偏差或 off-policy drift.

Mnih 等人在 2016 年的论文 *Asynchronous Methods for Deep Reinforcement Learning* 中系统化提出 **A3C (Asynchronous Advantage Actor-Critic)**. 随后工程实现广泛采用同步收集的 **A2C (Advantage Actor-Critic)**,以便把多个环境的数据组成规则 batch 并交给 GPU 处理.

### 5.1 A3C架构

- **异步 (Asynchronous)** : 多个Worker在CPU的多个线程中并行与多个环境交互.
- **参数更新**: 每个Worker计算出梯度后,异步地推送到全局参数服务器 (Parameter Server),并拉取最新参数.
- **优点**: 打破了训练数据的相关性(即使没有Replay Buffer),适合CPU集群.
- **缺点**: 难以利用GPU的大Batch并行能力; 异步更新导致梯度过时 (Stale Gradients).

### 5.2 A2C架构

- **同步 (Synchronous)** : 多个Environmental Workers并行采样,等待所有人都采集完一批数据.
- **批处理**: 将所有数据拼成一个大Batch,送入GPU进行一次前向和反向传播.
- **优点**: 极高地利用了GPU并行计算能力; 梯度更新确定性,收敛更稳.
- **工程位置**: 同步向量环境更容易组成规则 batch 并利用 GPU,A3C 的异步 worker 则适合另一类系统约束. PPO 的 rollout 收集也常采用同步或分批并行环境,但 PPO 还引入了概率比率和更新约束,不能与 A2C 画等号.

---

### 5.3 Actor、Critic 与熵的联合目标

Actor-Critic的总体损失函数通常由三部分组成:

$$ L_{total} = L_{policy} + c_1 L_{value} - c_2 L_{entropy} $$

#### 策略损失 (Actor)

$$ L_{policy} = - \frac{1}{N} \sum_{i=1}^N \log \pi_\theta(a_i|s_i) \cdot \hat{A}_i $$

其中 $\hat{A}_i$ 是 detach 过的优势值(不传梯度给 Critic).

#### 价值损失 (Critic)

Critic的预测 $V_\phi(s_t)$ 应接近真实的回报目标(通常使用 $R_t = A_t + V_{old}(s_t)$ 或 $\lambda$-return).

$$ L_{value} = \frac{1}{N} \sum_{i=1}^N (V_\phi(s_i) - R_i)^2 $$

这是一个回归问题,使用MSE Loss.

#### 熵正则化 (Entropy Bonus)

为了鼓励探索,防止策略过早收敛到局部最优(deterministically choosing suboptimal actions),我们加上策略分布的熵:

$$ H(\pi(\cdot|s_t)) = - \sum_a \pi(a|s_t) \log \pi(a|s_t) $$

我们在损失函数中**减去**熵(因为我们希望**最大化**熵,而优化器通常是**最小化**损失).

---

### 5.4 baseline 无偏性的另一种写法

这是一个关键的性质,也是AC成立的基础.

我们要证明:
$$ \mathbb{E}_{a \sim \pi} [ \nabla_\theta \log \pi_\theta(a|s) \cdot b(s) ] = 0 $$

证明:
$$
\begin{aligned}
\text{LHS} &= \int \pi_\theta(a|s) \cdot \frac{\nabla_\theta \pi_\theta(a|s)}{\pi_\theta(a|s)} \cdot b(s) \, da \\
&= \int \nabla_\theta \pi_\theta(a|s) \cdot b(s) \, da \\
&= b(s) \int \nabla_\theta \pi_\theta(a|s) \, da \\
&= b(s) \nabla_\theta \int \pi_\theta(a|s) \, da \\
&= b(s) \nabla_\theta (1) \\
&= 0
\end{aligned}
$$

只要基线 $b(s)$ 不依赖本次采样 action,减去它就不改变策略梯度期望. 它仍可能增加或降低有限样本方差;选择 $V(s)$ 的理由是状态价值通常能解释 return 中与 action 无关的大部分变化.

直接使用一个随 action 变化的普通函数作为 baseline,上面的归一化证明不再成立,通常会引入偏差. 这不等于自动变成 Q-learning.Q-learning 的关键是 Bellman optimality target 与离策略 value update,和「baseline 是否依赖 action」不是同一个分类轴.

### 5.5 网络共享、连续动作与 off-policy 边界

#### Critic是否一定要是独立网络?
不一定. 在深度学习中,Actor和Critic通常共享大部分卷积层/Transformer层作为特征提取器 (Backbone),只在最后分叉出两个头 (Policy Head 和 Value Head).
- **优点**: 特征共享,训练效率高.
- **缺点**: 两个任务 (Policy和Value) 的梯度可能会相互干扰. 有时需要精细调节 $c_1$ 权重.

共享 backbone 时,一次反向传播会把 policy loss、value loss 和 entropy loss 的梯度相加. Value 系数改变的不只是 Critic head 学习速度,也改变公共表示受到的监督比例. 工程上应分别监控 policy gradient norm 与 value gradient norm,避免某一项长期压过另一项.

完全独立网络避免表示梯度直接冲突,却需要两次前向和更多参数. 选择哪一种结构取决于观察模态、模型规模和算力预算,并不改变 Actor 与 Critic 的目标定义.

#### 连续动作为什么适合 Actor-Critic?
DQN虽然也可以用连续变体(如NAF),但其核心基于 $\max_a Q(s,a)$,这在连续空间很难求.
AC架构直接输出 $\mu(s), \sigma(s)$,天然支持采样连续动作,因此在机器人控制任务中占主导地位.

以对角 Gaussian policy 为例,Actor 输出每个动作维度的均值和 log 标准差,随后从分布采样并计算 log-prob. Policy gradient 直接通过 log-prob 回传,无需在连续空间枚举 action 或解析求解 $\arg\max_aQ(s,a)$.

动作若有上下界,常用 squashed Gaussian 或其他有界分布. Tanh 变换会改变概率密度,log-prob 需要加入 Jacobian 修正;只裁剪采样 action 而不修正密度,会让训练 loss 与真实行为策略不一致.

#### Off-policy Actor-Critic
本章讨论的 A2C 是 on-policy 的,因为 rollout 由当前策略采样,并在参数更新后丢弃.
如果想做 Off-policy,可以使用 **DDPG (Deep Deterministic Policy Gradient)** 或 **SAC (Soft Actor-Critic)** ,它们使用 Replay Buffer.

是否 on-policy 不由 loss 里有没有 $\log\pi$ 单独决定,而由数据分布和修正方式决定.A2C 的轨迹由当前策略采样,更新后丢弃;SAC 的数据来自 replay buffer,其 Bellman target 与策略目标按 off-policy 方式构造.

将 A2C rollout 直接放进 replay buffer 反复训练,会让状态—动作分布越来越偏离当前策略. Importance sampling、V-trace 或专门的 off-policy Actor-Critic 目标用于处理这种偏移,不能只靠 advantage 标准化补救.

### 5.6 一次 A2C 更新

一次更新从固定 policy version 收集 $n_{env}\times n_{step}$ 个 transition. 存储项至少包括 state、action、reward、真实终止标记、截断标记、采样 log-prob 与采样时 value. Rollout 末端若未真正终止,还要用同一版本 Critic 计算 bootstrap value.

GAE 和 return target 在参数更新前一次性算好并 detach. 随后把环境维与时间维展平,计算 Actor、Critic 与 entropy 三项 loss. 更新完成后重新采样,避免新参数继续使用旧 batch 却仍声称是严格 on-policy.

```text
Initialize params theta, phi
Initialize vectorized environments E

Loop forever:
    # 1. Collect Data
    Reset gradients d_theta = 0, d_phi = 0
    Storage = []

    For t = 0 to n_steps - 1:
        Get states S_t from all envs
        Run Policy: pi, v = Network(S_t)
        Sample actions A_t ~ pi
        Step Envs: S_{t+1}, R_t, Terminated, Truncated, FinalObservation
        Store (S_t, A_t, R_t, Terminated, Truncated, FinalObservation, v)

    # 2. Compute Returns / Advantages
    Get last value v_next = Network(S_{n_steps})
    For truncated transitions, bootstrap from FinalObservation, not auto-reset observation
    Calculate GAE for each trajectory using v_next

    # 3. Update Network
    Flatten the batch (n_steps * n_envs)

    Loss_Policy = -mean(log_pi(a|s) * Advantage)
    Loss_Value = mse(V(s), Return)
    Entropy = mean(Entropy(pi))

    Loss = Loss_Policy + 0.5 * Loss_Value - 0.01 * Entropy

    Optimize(Loss)
```

伪代码中的 `0.5` 与 `0.01` 只是示意权重,不属于 A2C 定义. 真实实验需要报告 loss 系数、gradient clipping、advantage normalization 与 rollout 长度,这些量会共同改变更新尺度和 bias-variance 取舍.

验证实现时,可以在短轨迹上手算 TD error 与 GAE,再比较程序输出. 还应分别构造 terminal 与 truncated episode,确认 bootstrap mask 不同. 这两项测试比只看训练 reward 是否偶然上升更容易定位边界错误.

## 6. 联合网络里的张量、梯度边界与更新次序

设并行环境数为 $N$，rollout 长度为 $T$，离散动作数为 $K$。一次 A2C rollout 常见张量是 `obs[T,N,d_s]`、`action[T,N]`、`reward[T,N]`、`value[T,N]`、`logp[T,N]` 和若干 mask；网络前向输出 `logits[T,N,K]` 与 `value[T,N,1]`。最后一维的 value 要么显式 `squeeze(-1)`，要么全程保留，不能依赖广播「碰巧算对」。例如 `[T,N,1] - [T,N]` 在部分框架里会广播成意外的三维张量，loss 仍是有限数，含义却已经改变。

共享主干时，总损失可写成

$$
L(\theta,\phi)=
-\frac1M\sum_{t,n}m_{t,n}\log\pi_\theta(a_{t,n}|s_{t,n})
\operatorname{sg}(\widehat A_{t,n})
+c_v\frac1M\sum_{t,n}m_{t,n}(V_\phi(s_{t,n})-\widehat R_{t,n})^2
-c_e\frac1M\sum_{t,n}m_{t,n}\mathcal H(\pi_\theta(\cdot|s_{t,n})),
$$

其中 $M=\sum m$，$\operatorname{sg}$ 表示停止梯度。优势通常由 value 计算，却应在 Actor loss 里 detach；否则 Actor loss 会推动 Critic 改写 advantage 本身，产生一条并非策略梯度定理给出的捷径。与此同时，共享主干会同时收到 policy、value 与 entropy 三路梯度，所以「detach advantage」并不等于 Actor 与 Critic 完全独立。

把三路梯度写成 $g_p,g_v,g_e$，共享参数实际得到 $g=g_p+c_vg_v-c_eg_e$。若 $g_p^\top g_v<0$，两项在共享特征上冲突；增大 value coefficient 可能降低 value loss，却损害策略。分离网络能消除共享主干上的直接冲突，代价是参数和前向计算增加。选择共享或分离不能只看最终 return，还应观察 policy gradient norm、value gradient norm 与表示层更新规模。

### 6.1 一个共享参数的手算

假设某个共享标量参数上，policy、value、entropy 三项导数分别为 $g_p=-0.30$、$g_v=0.80$、$g_e=0.10$，$c_v=0.5,c_e=0.01$。总导数为

$$
g=-0.30+0.5\times0.80-0.01\times0.10=0.099.
$$

梯度下降会减小该参数。若把 $c_v$ 从 $0.5$ 降至 $0.2$，则 $g=-0.141$，更新方向反转。这里没有哪一项计算错了，方向变化来自多任务目标的权衡。这也是为什么只抄「value coefficient 常用 0.5」并不够：网络尺度、reward 尺度与共享深度变化后，同一个系数代表的梯度比例完全不同。

## 7. GAE 的完整边界与偏差来源

对环境流 $n$，令 $u_{t,n}$ 表示真实终止后的 bootstrap mask，$c_{t,n}$ 表示 GAE 是否跨到下一采样位置。两者在普通中间步都为 $1$，但在 rollout 边界、自动 reset 与时间上限截断处未必相同：

$$
\delta_t=r_t+\gamma u_tV(s_{t+1})-V(s_t),
$$

$$
\widehat A_t=\delta_t+\gamma\lambda c_t\widehat A_{t+1}.
$$

时间上限截断如果只是采样器停止，$u_t$ 应为 $1$，需要从截断前的 final observation 取 value；但 $c_t$ 通常为 $0$，不能把 reset 后新 episode 的优势接回来。真实 terminal 则 $u_t=c_t=0$。这两个 mask 合并，会在截断点丢 bootstrap，或把两局游戏串成一条轨迹。

设 $gamma=0.9,\lambda=0.8$，截断前一步 reward 为 $1$，$V(s_t)=2$，截断状态 $V(s_{t+1})=3$。正确 TD error 是 $1+0.9\times3-2=1.7$。若误当 terminal，得到 $1-2=-1$；同一个 action 从明显正优势变成负优势。若自动 reset 返回的新状态 value 为 $0.5$，误用它则得到 $-0.55$。这不是小数值误差，而会直接翻转 Actor 梯度。

GAE 的偏差有两层来源。第一层是 bootstrap：$V_\phi$ 有误时，较小 $\lambda$ 更依赖 Critic。第二层是有限 rollout：尾部优势必须用边界 value 或明确截断，估计误差会向前按 $(\gamma\lambda)^k$ 衰减。较大 $\lambda$ 减少对 value 的依赖，却引入更多真实 reward 随机性；因此「$\lambda$ 越大越准确」只在特定 value 误差与采样预算下成立。

Critic target 常取 $\widehat R_t=\widehat A_t+V_{\text{old}}(s_t)$。这里的 old value 应是生成 GAE 时冻结的预测。若每个 optimizer step 后用新 value 重算 target，Critic 会追逐移动目标，Actor 的 advantage 也随 epoch 改变。A2C 通常一批数据只做一次或少量更新；若要多轮复用，必须像 PPO 那样显式处理 policy ratio，并仍然控制分布漂移。

## 8. 采样吞吐、相关性与实验公平性

A3C 的 worker 异步把梯度推向共享参数，worker 计算梯度时读到的策略与应用梯度时的策略可能不同，这叫 parameter staleness。A2C 同步收齐 $N$ 个环境的 $T$ 步再更新，没有这类异步延迟，但同一时刻的环境若使用相同 seed 或确定性 reset，样本仍可能高度相关。**并行环境数增加的是吞吐，不保证等比例增加有效样本数。**

比较 rollout 配置时，应区分每次更新样本数 $NT$ 与数据新鲜度。固定 $NT=2048$，取 $N=32,T=64$ 会得到较多独立起点、较短时间链；取 $N=2,T=1024$ 则覆盖更长的单轨迹依赖。二者计算量相近，GAE 尾部误差、样本相关性和可见稀疏 reward 却不同。若任务奖励需要数百步才出现，过短 rollout 会让大量早期状态只能依赖 Critic bootstrap。

on-policy 也不是指「每条数据只能计算一次」。在参数没有变化前，可以对同一 rollout 完成 return、GAE 和多个诊断；关键是用它做过更新后，行为策略与当前策略开始分离。裸 A2C loss 没有 importance ratio，多次 epoch 会逐渐变成未校正的离策略更新。小学习率下可能暂时有效，但这属于经验近似，需要报告 epoch 与策略 KL，不能因为 reward 上升就把它称作仍然严格 on-policy。

实验验收至少包含四类量：采样端的 episode return、长度和成功率；估计端的 advantage 均值/标准差、explained variance 与截断比例；优化端的三项 loss、各自梯度范数和 entropy；系统端的每秒环境步、策略版本延迟和无效 padding 比例。loss 不必单调下降，因为数据分布不断更新；Critic loss 很低也可能只是 reward 尺度小或短期过拟合。

一个可靠的单元测试可以造两条轨迹：一条真正终止，一条在同一步时间截断，并令 final observation 的 value 非零。手算两条的 TD、GAE 与 return，确认只有截断轨迹保留 bootstrap。然后冻结 rollout，分别只反向 policy loss 与 value loss，检查 advantage/target 没有梯度、共享参数确实收到预期梯度。最后改变 $N,T$ 但保持总样本数，确认损失归一化不随 padding 比例漂移。做到这些，Actor-Critic 才从一组公式变成可复算的训练系统。

## 9. Critic 到底在拟合哪个分布

价值函数的训练样本来自当前或近期策略访问到的状态，因此 $V_\phi$ 只在该分布上被监督。策略更新后，状态分布改变，旧 Critic 在新区域可能外推失真。即使旧 rollout 上 explained variance 很高，也不代表新策略下仍准确。Actor-Critic 的交替过程可以理解成两条追逐链：Actor 根据当前 Critic 改策略，Critic 再追上新策略的价值分布。

以平方误差训练 Critic 时，理论目标是条件均值。若同一状态后续回报以一半概率为 $0$、一半概率为 $10$，最优预测是 $5$，最小不可约均方误差仍为 $25$。所以 value loss 长期不降到零并不表示实现失败；随机环境里它包含回报本身的条件方差。反过来，value loss 很小也可能只是 reward 被缩得很小。explained variance

$$
1-\frac{\operatorname{Var}(\widehat R-V)}{\operatorname{Var}(\widehat R)}
$$

消除了整体尺度的一部分影响，但当 target 方差接近零时会不稳定，也不能揭示系统性校准误差。

Critic 训练次数同样是偏差—过拟合取舍。同一 rollout 上做很多 epoch 会降低训练误差，却可能记住 Monte Carlo 噪声；做得太少则 GAE 持续依赖落后的 value。可以划分 rollout 内的训练/诊断切片，或至少观察下一批新数据上的 value error。对于稀疏奖励任务，还应按距离终点的时间位置画误差，因为整体均值容易被大量无奖励中间状态主导。

### 9.1 Off-policy Actor-Critic 的分界

经验回放对 Critic 很诱人，因为 Bellman target 可以从旧 transition 构造；Actor 梯度却对应当前策略的状态—动作分布。DDPG、SAC 等算法用不同的 off-policy 目标和校正思路，并不是把 A2C rollout 原封不动塞进 replay buffer。若行为策略为 $\mu$，离散动作可用 $\pi(a|s)/\mu(a|s)$ 修正动作条件，但状态分布仍有差异，而且 ratio 会增大方差。

因此阅读「Actor-Critic」时要区分架构与估计器：有 Actor 和 Critic 只是网络角色；A2C 的 on-policy score-function、DDPG 的确定性策略梯度、SAC 的熵正则 off-policy 目标并不是同一算法。**Critic 的存在降低了优势估计方差，却没有自动赋予数据无限复用能力。**这条边界也解释了为什么 PPO 要保存 old log-prob，而基础 A2C 通常更新后立即丢弃 rollout。

部署前还应单独校准 Critic。把状态按预测 value 分桶，比较每桶平均预测与实际回报；若高 value 桶持续高估，Actor 会过度强化这些状态附近的动作。校准图不能替代策略评估，却能指出 advantage 偏差集中在哪里。对安全敏感任务，还应专门统计低频失败轨迹，而不是让大量普通状态的低误差稀释它们。

校准应使用未参与 Critic 拟合的新轨迹，否则训练集上的漂亮曲线仍可能只是记住了采样噪声。
