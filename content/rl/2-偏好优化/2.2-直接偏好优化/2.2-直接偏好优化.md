# 直接偏好优化

经典 RLHF 先用比较数据训练 reward model,再让策略在线采样,再用 PPO 最大化预测奖励.这条链路把「人更喜欢哪个回答」转成可以优化的标量,代价是训练对象多、采样成本高,而且 reward model 与当前策略之间会不断发生分布偏移.DPO 给出了另一条入口:在 Bradley–Terry 偏好模型与 KL 正则化策略目标成立时,最优策略和奖励之间存在闭式关系,因此可以把 reward model 从训练流程里消去,直接用 chosen/rejected 的策略概率训练语言模型.

这类方法经常被统称为「DPO 家族」,但后续工作改动的位置并不相同.IPO 改的是偏好似然带来的过拟合行为;ORPO 把偏好项并入 SFT,希望用一个阶段同时完成示范学习与排序;SimPO 用长度归一的平均 log-prob 和显式 margin 改写隐式奖励;KTO 不再要求同一 prompt 下的成对回答,只使用 desirable/undesirable 标签.把这些名字放在同一张榜单里看,很容易错过一个更重要的问题:训练数据提供的是成对次序、单条好坏还是完整示范,损失又对序列总概率、平均概率还是相对 reference 的变化施加约束.

## 1. 从 KL 正则化目标到偏好损失

设输入为 $x$,回答为 $y$,待训练策略为 $\pi_\theta$,参考策略为 $\pi_{\mathrm{ref}}$.RLHF 常见的策略目标写成

$$
\max_\pi\;\mathbb E_{x,y\sim\pi}[r(x,y)]
-\beta\,\mathbb E_xD_{\mathrm{KL}}
\bigl(\pi(\cdot\mid x)\Vert\pi_{\mathrm{ref}}(\cdot\mid x)\bigr).
$$

对固定 $x$ 求最优策略,可以得到 $\pi^*(y\mid x)\propto\pi_{\mathrm{ref}}(y\mid x)\exp(r(x,y)/\beta)$.把关系反解后,奖励差由 chosen 与 rejected 相对 reference 的 log-ratio 差表示,与 $x$ 有关的配分函数在两项相减时消失.DPO 再把这个差放回 Bradley–Terry 似然,得到不需要显式 reward model 的二分类目标.

**闭式改写消掉的是训练流程中的 reward model 与在线策略优化,没有消掉偏好模型、参考分布和数据覆盖假设.** 固定数据只告诉模型已出现候选之间的次序.训练后的策略一旦生成远离这些候选的新回答,损失函数仍要在缺少比较信息的区域外推.这也是离线偏好优化与在线 RL 最主要的分界:前者复用固定数据更便宜,后者能持续观察当前策略产生的新状态,同时也更容易放大验证器或 reward model 的漏洞.

### 1.1. 序列概率怎样进入目标

自回归策略对完整回答的 log-prob 是逐 token log-prob 的和:

$$
\log\pi_\theta(y\mid x)=
\sum_{t=1}^{|y|}\log\pi_\theta(y_t\mid x,y_{<t}).
$$

因此,偏好损失虽然在回答层定义,梯度仍会流向回答中的每个 token.求和还会把长度带进隐式奖励:如果每个 token 的平均 log-ratio 相近,较长回答会积累更大的绝对变化.SimPO 选择平均 log-prob,ORPO 使用 odds ratio 并保留 SFT 项,DPO 与 IPO 则在 reference-relative 的序列差上工作.它们对长度、生成概率和参考分布的偏好并不相同.

长度归一也不是免费修复.平均以后,短回答中的单个 token 对总分影响更大;代码、摘要与开放问答的必要长度分布也不同.比较算法时需要同时看 chosen/rejected 的原始长度、训练后的生成长度、逐 token log-ratio 与独立偏好胜率.只看损失下降,无法判断模型学到了内容偏好还是长度捷径.

### 1.2. reference 承担什么作用

$\pi_{\mathrm{ref}}$ 给隐式奖励提供坐标.某个回答本来就在参考策略下具有高概率时,策略不需要很大的相对变化便能进一步提高它;参考策略几乎不支持的行为,则需要更多数据和更强梯度才能进入可见区域.$\beta$ 控制偏好差与分布移动的交换率,数值越小,同一比较产生的策略位移通常越大,标签噪声也会被更快放大.

去掉 reference 可以节省一次冻结模型前向或一份缓存,却需要别的约束维持生成质量.ORPO 保留 SFT 的正似然项,SimPO 引入目标 margin,这些设计都在回答同一个问题:没有显式 KL 坐标后,怎样避免策略只把 rejected 概率压低,同时让 chosen 的绝对概率也不断下降.

## 2. 家族分叉发生在哪里

| 方法 | 数据形态 | reference | 主要改动 | 先检查的风险 |
| --- | --- | --- | --- | --- |
| [DPO](2.2.1-DPO.md) | 成对偏好 | 需要 | 用闭式关系消去显式 reward model 与 PPO | chosen/rejected 同降,分布外外推 |
| [IPO](2.2.2-IPO.md) | 成对偏好 | 需要 | 用有限间隔的平方目标限制易分样本上的无限放大 | margin 与噪声水平不匹配 |
| [ORPO](2.2.3-ORPO.md) | 成对偏好兼示范 | 不需要 | SFT 似然与 odds-ratio 偏好项联合训练 | 两项梯度尺度和长度偏置 |
| [SimPO](2.2.4-SimPO.md) | 成对偏好 | 不需要 | 平均 log-prob 加显式 margin | 长度归一改变任务偏好 |
| [KTO](2.2.5-KTO/2.2.5-KTO.md) | 单条好坏标签 | 需要 | 用前景理论价值函数处理非成对反馈 | 类别不均衡与 KL 参考点估计 |

这张表只确定算法在哪一层分叉,不构成效果排名.数据若天然只有点赞、点踩或是否通过测试,KTO 避免了强行配对;同一 prompt 已经有可靠的 chosen/rejected,DPO 是最直接的基线;希望把 SFT 与偏好阶段合并时,ORPO 的联合目标更贴近训练流程;显存无法容纳 reference 时,SimPO 与 ORPO 减少了一项模型开销,但要额外检查分布漂移.

IPO 解决的是另一类问题.DPO 的 sigmoid 似然会继续拉大已经容易区分的偏好差,在可分数据上可能把策略推得过远.IPO 为目标 gap 设置有限尺度,使易分样本不再无限获得更新.这个变化是否有用取决于标签噪声、偏好强度与 $\beta$;如果比较本身代表明显而稳定的能力差异,过早限制 gap 也可能减弱有效信号.

## 3. 数据比算法名字更早决定上限

偏好数据至少包含四层条件:prompt 来自什么分布,候选由哪个模型和采样参数生成,标注者依据什么准则比较,同一个 prompt 有多少候选.两个回答都很差时,chosen 只代表相对较好;两个回答几乎相同时,标签主要反映标注噪声.从 $K$ 个候选两两构造比较对,记录数会快速增加,独立信息量却仍受这 $K$ 个回答限制.训练和评测划分应按 prompt 或候选组切分,不能把同组比较随机拆到两侧.

不同来源的偏好混合后,单一标量效用还会压缩相互冲突的标准.准确、简洁、风格与安全可以形成循环偏好,Bradley–Terry 的一维效用只能寻找折中排序.如果数据没有保留标注准则和来源,算法无法判断两条冲突标签来自噪声,还是来自不同人群对目标的不同权重.

在线迭代可以缓解数据陈旧:训练一轮策略,重新采样候选并收集比较,再进入下一轮.这会逐步接近当前策略的生成分布,同时提高数据和标注成本.旧数据完全丢弃可能遗忘早期能力,全部等权又会让弱策略时期的候选长期占据训练量.轮次采样、数据权重与 reference 更新频率需要和损失函数一起报告.

## 4. 阅读顺序与比较口径

先读 [DPO](2.2.1-DPO.md),完整走一遍「KL 正则目标 → 最优策略 → 反解 reward → Bradley–Terry 损失」.这条推导是整个家族的参照系.随后按手里的数据读:成对数据但担心过拟合,进入 [IPO](2.2.2-IPO.md);希望合并 SFT,读 [ORPO](2.2.3-ORPO.md);不保留 reference 且关注长度,读 [SimPO](2.2.4-SimPO.md);只有单条好坏标签,读 [KTO](2.2.5-KTO/2.2.5-KTO.md).

横向实验需要固定基础模型、prompt 集、候选生成策略和训练 token.算法只改变损失时,reference 是否驻留、是否预计算 log-prob、序列概率怎样归一化也要保持可比.结果至少同时报告独立偏好胜率、能力基准、生成长度、chosen/rejected log-prob 和相对 reference 的 KL.若只给一个裁判模型的总胜率,长度与风格偏好可能掩盖事实性和任务能力变化.

直接偏好优化适合把已有比较信息写回策略,它无法提供数据中从未出现的成功轨迹.数学、代码或工具任务需要当前模型继续探索时,应与 [推理强化学习](../../3-推理强化/3-推理强化.md) 对照;训练链仍需要显式 reward model 与在线采样时,回到 [RLHF 流水线](../2.1-rlhf流水线.md).三条路线的选择先由反馈形态与数据生成方式决定,随后才是损失函数之间的细节差异.
