# PPO-based RLHF 训练流水线

RLHF 是一类从人类反馈构造训练信号的流程，不固定等于“四个同尺寸模型同时驻留 GPU”。以 InstructGPT 路线为典型案例，它包含三段：用示范数据做 SFT，训练能给回答打分的奖励模型，再让策略对当前 prompt 生成回答，用 PPO 提高奖励并限制相对参考策略的漂移。

三段分别改变三种对象。SFT 把预训练模型变成能够遵循指令的初始策略；奖励模型把有限的人类比较扩展成可对新回答打分的函数；PPO 在当前策略自己生成的数据上提高预测奖励。策略更新后，rollout 分布也会变化，奖励模型开始面对偏好数据覆盖之外的回答，这个闭环才是 RLHF 最难的地方。

## 1. 数据对象与模型角色

用 $x$ 表示 prompt，$y=(y_1,\ldots,y_T)$ 表示 completion。自回归回答概率为

$$
\pi_\theta(y\mid x)=
\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}).
\tag{1}
$$

流水线中常见四种角色：

- **policy** $\pi_\theta$：正在训练的生成模型，产生新回答并接收 PPO 梯度；
- **old policy** $\pi_{old}$：生成当前 rollout batch 时的策略快照，用于重要性比；
- **reference policy** $\pi_{ref}$：通常冻结在 SFT checkpoint，定义长期 KL 锚点；
- **value model** $V_\psi(s_t)$：估计从前缀状态 $s_t=(x,y_{<t})$ 出发的期望回报。

$\pi_{old}$ 和 $\pi_{ref}$ 可能在训练开始时来自同一 checkpoint，职责仍然不同。PPO 复用一批 rollout 多个 epoch 时，$\pi_{old}$ 保持为采样版本；$\pi_{ref}$ 往往跨许多 batch 都不变。把 ratio 分母错用 reference，会把局部 On-policy 校正与长期分布约束混成一个量。

奖励模型 $r_\phi(x,y)$ 可以与 policy 使用不同架构或 tokenizer。此时系统应从原始 prompt/response 文本分别编码并保留字符边界，避免 policy 侧被截断的回答在 RM 侧变成另一段输入。RM 输出通常是序列标量，不天然提供每个 token 的 credit。

## 2. SFT 建立策略起点

示范数据为 $(x,y^*)$，常见损失只在 assistant completion token 上计算：

$$
\mathcal L_{SFT}(\theta)
=-\sum_{t=1}^{T}m_t
\log\pi_\theta(y_t^*\mid x,y_{<t}^*),
\tag{2}
$$

$m_t\in\{0,1\}$ 是 loss mask。系统提示、用户消息和 padding 可以参与条件输入，却不一定进入损失。若把 prompt token 也计入训练，模型会花容量复述用户；若 EOS 被错误 mask，生成可能学不会停止；不同样本 padding 侧不一致时，position 与 mask 还会错位。

SFT checkpoint 提供可读的初始回答分布，成为 rollout 起点，并经常复制为 reference。初始策略太弱时，奖励模型要在大量低质量回答上外推，PPO 也很难从稀疏高分样本中学习。SFT 决定 RL 开始探索的区域，不只是格式热身。

## 3. 从比较数据训练奖励模型

对同一个 prompt 生成 $K$ 个候选，标注者按指定标准排序。将排序拆成 chosen/rejected 对 $(x,y_w,y_l)$，Bradley–Terry 模型写为

$$
P_\phi(y_w\succ y_l\mid x)
=\sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right).
\tag{3}
$$

对应负对数似然为

$$
\mathcal L_{RM}(\phi)
=-\log\sigma(r_w-r_l).
\tag{4}
$$

令 $\Delta=r_w-r_l$，则

$$
\frac{\partial\mathcal L}{\partial\Delta}
=\sigma(\Delta)-1.
\tag{5}
$$

若 $r_w=0.2,r_l=-0.1$，$\Delta=0.3$，$\sigma(0.3)\approx0.574$，梯度约为 $-0.426$。梯度下降会增大 chosen 相对 rejected 的分数。式 (4) 只约束差值：给所有回答奖励同时加 10，偏好概率不变。RM 的绝对零点和尺度不是人类效用单位，进入 PPO 前需要固定口径。

同一组 $K$ 个回答可以产生 $K(K-1)/2$ 个比较，但这些 pair 共享回答，不是独立样本。若按 pair 随机切分训练和验证，同一个回答可能同时出现在两侧。应按 prompt 或原始候选组切分，并避免候选更多的 prompt 获得不成比例权重。

帮助性、事实性、安全性和简洁性可能冲突。把所有比较压进单一标量，模型会学习标注分布中的隐含权衡。标注者一致率低的样本可以保留不确定性或降低权重，强行给唯一顺序会把争议写成确定奖励。

## 4. 从序列奖励构造 token 回报

常见策略目标在奖励之外加入参考策略约束：

$$
R_{total}(x,y)=R_\phi(x,y)
-\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}.
\tag{6}
$$

工程实现通常保存每个有效 token 的 policy log-prob $\ell_t^\theta$ 与 reference log-prob $\ell_t^{ref}$，定义 token KL 近似成本

$$
k_t=\ell_t^\theta-\ell_t^{ref}.
\tag{7}
$$

非终止 token 的 shaped reward 为 $r_t=-\beta k_t$，最后一个有效 completion token 再加 RM 分数。回答长度为 3，log-ratio 是 $(0.1,0.2,-0.1)$，$\beta=0.05$，RM 分为 1.2，则 token reward 为 $(-0.005,-0.010,1.205)$，总和是 $1.19$，等于序列 RM 减去 $0.05\times0.2$。

这种写法把 KL 信号放到对应动作附近，没有解决 RM 终局分数的 token credit。GAE 会借助 critic 把未来回报传播到各位置，准确程度取决于 value 估计。回答因最大长度被截断时，终点究竟是 terminal 还是仍应 bootstrap 必须明确；把 truncation 一律当自然 EOS 会让 value target 产生系统偏差。

KL 还有不同估计口径。式 (7) 是已采样 token 上的 log-ratio，其样本均值估计 $D_{KL}(\pi_\theta\|\pi_{ref})$；另一些实现使用非负近似或全词表 KL。它们的数值尺度不同，$\beta$ 不能直接搬运。报告需要说明方向、粒度、mask 与聚合。

## 5. GAE 与 PPO 更新

对 token 状态 $s_t=(x,y_{<t})$，TD residual 为

$$
\delta_t=r_t+\gamma V_\psi(s_{t+1})-V_\psi(s_t).
\tag{8}
$$

GAE 将多步 residual 指数加权：

$$
\hat A_t=\sum_{l=0}^{T-t-1}(\gamma\lambda)^l\delta_{t+l}.
\tag{9}
$$

value target 为 $\hat R_t=\hat A_t+V_{old}(s_t)$。$\lambda$ 小时更接近低方差一步 TD，$\lambda$ 接近 1 时更接近高方差 Monte Carlo。语言生成里常让 $\gamma$ 接近 1，因为一个回答内部 token 没有明显时间折扣，具体配方仍需报告。

PPO 计算当前 policy 相对生成数据的 old policy 的 ratio：

$$
\rho_t(\theta)=
\exp\left(log\pi_\theta(y_t\mid s_t)
-\log\pi_{old}(y_t\mid s_t)\right).
\tag{10}
$$

clipped surrogate 为

$$
L_t^{clip}=\min\left(ho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right).
\tag{11}
$$

若 $\hat A_t=2$、$\epsilon=0.2$，ratio 为 1.3 时，未裁剪项为 2.6，裁剪项为 2.4，目标只取 2.4；继续提高动作概率没有额外收益。若 $\hat A_t=-2$、ratio 降到 0.7，未裁剪项为 -1.4，裁剪项为 -1.6，最小值是 -1.6，阻止把坏动作概率一次降得太快。正负优势下 `min` 的效果方向不同，不能把 clip 理解为先截断 ratio 再统一相乘。

value loss 可写为

$$
\mathcal L_V(\psi)=
\frac12\sum_t m_t(V_\psi(s_t)-\hat R_t)^2.
\tag{12}
$$

并可对 value 更新做类似裁剪。policy loss 还可能加入 entropy bonus。优势进入 policy loss 前通常按 batch whitening；若跨不同长度、任务难度和 reward source 混合 whitening，会改变各组相对权重，必须写清 grouping 口径。

### 一条三 token 回答的 GAE 手算

设 $\gamma=1,\lambda=0.8$，三个位置 shaped reward 为 $(0,0,1)$。旧 value 预测为 $(0.2,0.4,0.5)$，终止后的 value 为 0。TD residual 逐个计算：

$$
\delta_1=0+0.4-0.2=0.2,
$$

$$
\delta_2=0+0.5-0.4=0.1,
$$

$$
\delta_3=1+0-0.5=0.5.
$$

从后向前累积：

$$
\hat A_3=0.5,
$$

$$
\hat A_2=0.1+0.8\times0.5=0.5,
$$

$$
\hat A_1=0.2+0.8\times0.5=0.6.
$$

对应 return target 为 $(0.8,0.9,1.0)$。虽然正奖励只在最后 token 出现，前两个动作通过 bootstrap 与指数加权得到正优势。若 $\lambda=0$，优势只剩 $(0.2,0.1,0.5)$，更依赖 critic 的一步预测；若 $\lambda=1$，三个 return 都等于最终回报 1，优势为 $(0.8,0.6,0.5)$，critic 偏差更少，样本方差更大。

现在把第三个 token 改成长度截断，真实回答尚未结束。若错误地令终止 value 为 0，仍得到 $\delta_3=0.5$；若 continuation 的 bootstrap value 应为 0.7，则 $\delta_3=1+0.7-0.5=1.2$，前三个优势都会变化。`terminated` 与 `truncated` 的一位标志可以改变整条回答的训练信号。

### PPO 数据为什么只能有限复用

仍取 $\hat A=2$。生成数据时动作概率为 $\pi_{old}(a|s)=0.2$，第一次更新后当前概率为 0.22，ratio 为 1.1，梯度仍处于 clip 区间；若同一 batch 反复训练到概率 0.30，ratio 为 1.5，正优势项被截到 1.2，此样本继续提高动作概率的直接贡献消失。负优势样本也会在另一侧饱和。

因此多 epoch 不等于免费使用更多数据。epoch 增加后 clip fraction 上升、有效样本比例下降，value model 还可能继续拟合同一批 return。若同时在 epoch 之间刷新 old log-prob，ratio 又被人为重置，算法就不再是对固定行为策略数据的 PPO。实现应冻结每条 rollout 的 `old_logp`，将训练 epoch、clip fraction 与近似 KL 一起报告。

## 6. 一批数据怎样流过系统

一次迭代可以按以下顺序检查：

1. 从 prompt 数据集抽取 $B$ 条输入，记录数据版本与模板。
2. rollout worker 用策略版本 $v$ 生成回答，保存 token、mask、old log-prob、采样温度和停止原因。
3. reference worker 对相同 token 序列计算 ref log-prob；RM 对原始文本或重编码序列给分。
4. trainer 组合 shaped reward，运行 value 前向，计算 GAE 与 return。
5. 使用固定 $\pi_{old}$ 的 batch 做若干 minibatch epoch，更新 policy 与 value。
6. 到同步点后发布新策略版本 $v+1$，新的 rollout 才使用它。

异步系统里，rollout 返回时 trainer 可能已更新多个版本。样本仍应以生成它的 old log-prob 计算 ratio，并设置最大版本滞后；拿当前 policy 当 old policy 会让 ratio 人为接近 1，掩盖 Off-policy 程度。版本过旧的数据即使有 ratio 也可能方差很大，裁剪后大部分样本没有有效梯度。

同一回答在 RM、reference、value 与 policy 之间必须共享 completion 边界。聊天模板多一个 assistant header、EOS 处理不同或左右 padding 混用，都可能让 reward 加在错误 token、KL 对错位置。系统验收应构造极短人工样本，逐 token 打印四路 token id、mask、log-prob 和 reward，手算式 (7)–(12) 再与实现对齐。

一个两样本验收批就能抓住许多错误。样本 A 正常 EOS，completion mask 为 $(1,1,1,0)$；样本 B 达到最大长度，mask 为 $(1,1,1,1)$ 且 `truncated=true`。对 A，RM 分只能加在第三个位置；对 B，加在第四个位置后仍按截断规则决定是否 bootstrap。将 padding token 的 policy/ref log-prob 人为设成极大值，最终 KL 和 loss 应完全不变；否则 mask 泄漏。再让 new log-prob 等于 old log-prob，所有有效 ratio 应精确为 1；不为 1 时优先检查 tokenizer、模板和策略版本。

分布式系统还要验证样本没有错配。给每条回答附上不可变 `sample_id`，RM、reference 与 value 返回结果时按 id join，禁止只按 batch 位置拼接。异步 worker 重试或部分失败会改变顺序，位置拼接可能把一个回答的奖励赋给另一个回答，而且 loss 依然能正常下降。

## 7. 资源账本

“四个模型”描述逻辑角色，不等于四份同尺寸参数同时驻留。policy 训练需要参数、梯度和优化器状态；value 可以共享 policy 骨干或单独部署；reference 与 RM 只做前向，可以量化、分片或卸载；rollout 还可能使用专门推理引擎。

真正的成本经常来自生成 token。若每个 prompt 平均生成 $T$ 个 token，batch 为 $B$，一次 rollout 产生 $BT$ 个动作；PPO 再对这些 token 做多轮前向反向。回答长度翻倍，同时增加生成延迟、KV、RM/reference 前向和训练激活。比较算法时要固定总生成 token，不能只固定 prompt 数。

Reference log-prob 可以离线预计算的前提是回答固定、reference checkpoint、tokenizer 和模板不变；在线 rollout 的回答每轮变化，通常仍需在线 reference forward。RM 分数可以异步计算，但版本必须随样本保存，混用新旧 reward 会改变训练目标。

## 8. 失败模式与诊断

Reward 上升可能来自真正质量提高，也可能来自长度偏置、格式漏洞、重复高分短语和 RM 分布外利用。至少同时画 RM reward、独立评测、回答长度、KL、entropy、clip fraction、value explained variance 和截断率。

chosen 回答若系统性更长，RM 可能把长度当质量；PPO 随后不断拉长回答。可以在数据构造、RM 评测和 policy 监控中按长度分桶，不能只在 policy loss 中临时加惩罚后宣称问题解决。安全 reward 与帮助性 reward 合并时也要保存分项，否则总分上涨可能掩盖某一维退化。

KL 太低可能表示更新无效，也可能是 $\beta$ 太强；KL 高可能带来新行为，也可能离开 RM 可靠区域。自适应 $\beta$ 只是围绕目标 KL 的控制器，不是质量保证。PPO clip fraction 接近零表示更新很小，接近一则说明数据迅速过时或学习率过大。

最终验收必须回到与 RM 独立的数据和判定。训练 reward、RM 验证准确率和人类偏好胜率回答不同问题，其中任何一个单独上升，都不足以证明系统整体对齐。

## 9. 实现边界

本目录的 `pipeline_skeleton.py` 只有阶段接口和 `pass`，状态明确为 `illustrative-pseudocode`。它没有 GAE、mask、PPO minibatch、模型同步或分布式状态，不能称为完整 PPO 实现。旁边的[系统验收](./01-系统验收/01-系统验收.md)给出最小的数据血缘与版本检查。
