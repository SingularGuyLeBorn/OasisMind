# RL · 强化学习

强化学习在大模型领域很容易被学成一串缩写. MDP, Q-learning, REINFORCE, Actor-Critic, TRPO, PPO 还没连起来, RLHF, DPO, GRPO 和 RLVR 又接着出现. 如果只从大模型后训练开始, PPO 的 ratio, advantage 和 KL 约束像是凭空写进损失函数; 如果只学经典控制, 又很难理解为什么生成模型要按 token 计算 log probability, 按整段回答给奖励, 还要处理一个 prompt 下多条采样之间的相对比较.

这座库从最基础的随机过程开始重建这条路线. 强化学习研究的是序列决策: 智能体在状态 $s_t$ 下按策略 $\pi(a_t\mid s_t)$ 选择动作 $a_t$, 环境返回奖励 $r_t$ 和下一状态 $s_{t+1}$. 当前动作会改变以后能看到的状态, 所以学习目标不能只评价眼前一步, 而要评价一条轨迹上的累计回报. 价值函数, Bellman 方程, 策略梯度和优势函数都从这个依赖关系中产生.

到了语言模型, 状态通常是 prompt 与已经生成的 token, 动作是下一个 token, 一条回答构成一条轨迹. 环境可能是真实工具, 代码解释器或数学判定器, 也可能只是一个奖励模型. 这个映射让经典算法能够进入大模型训练, 但动作空间, 序列长度和奖励稀疏性也改变了算法的工程形态. **理解 RLHF 和 RLVR, 先要指出经典 RL 中的状态, 动作, 策略, 行为策略和回报在语言模型里分别落在哪里, 再去读新的损失.**

## 1. 先把算法放进同一张地图

大模型强化学习里最容易误读的地方，是把奖励来源、优势估计和优化约束混成同一种“算法”。RLHF 与 RLVR 说明反馈从哪里来；PPO、GRPO、RLOO 主要改变怎样估计并使用策略梯度；DPO 家族则把带 KL 约束的偏好优化改写成离线目标。它们位于不同层级，可以组合，也可能互相替代某一段训练流程。

| 家族 | 数据怎样产生 | 反馈形态 | 核心估计或目标 | 主要入口 |
| --- | --- | --- | --- | --- |
| 经典策略梯度 | 当前策略与环境交互 | 逐步或终局回报 | REINFORCE、baseline、Actor-Critic、GAE | [基础](01-基础/01-基础.md) |
| PPO 式在线 RLHF | 行为策略在线采样 | 奖励模型或环境标量 | critic、GAE、importance ratio 与 clip | [RLHF 流水线](02-偏好优化/02.01-rlhf流水线/02.01-rlhf流水线.md)、[PPO](01-基础/01.07-ppo/01.07-ppo.md) |
| 离线偏好优化 | 固定 chosen/rejected 或好坏标签 | 人类、模型或规则偏好 | 闭式策略目标、margin、reference 与长度归一 | [偏好优化](02-偏好优化/02-偏好优化.md) |
| 无 critic 的在线推理 RL | 同一 prompt 在线采样一组回答 | 可验证终局奖励为主 | 组内标准化、留一基线、序列或 token 级裁剪 | [推理强化](03-推理强化/03-推理强化.md) |
| 长程与 Agent RL | 策略在多轮环境中行动 | 延迟奖励、工具反馈与过程信号 | 长程信用分配、轨迹过滤和状态版本控制 | [验证与长程](03-推理强化/03.04-验证与长程/03.04-验证与长程.md) |

遇到新的“某某 PO”，先定位它改了表中的哪一列。只换 advantage，不等于换了奖励来源；只换 clip，不等于解决了长程信用分配；验证器给出确定答案，也不代表策略梯度没有采样方差。这个阅读习惯能过滤掉相当一部分缩写带来的噪声。

## 2. 四章的学习顺序

### 01. 数学基础与经典强化学习

[数学基础与经典强化学习](./01-基础/01-基础.md)从条件概率, 期望和重要性采样进入 MDP. Bellman 方程把「当前奖励加未来价值」写成递归关系, Value Iteration 与 Policy Iteration 分别围绕价值和策略迭代. Monte Carlo 用完整轨迹估计回报, Temporal Difference 用一步 bootstrap 更新价值, 两者的偏差与方差差异贯穿后面的算法.

策略梯度直接对参数化策略的期望回报求导. REINFORCE 给出无偏但高方差的估计; baseline 在不改变期望梯度的条件下降低方差; Actor-Critic 用价值网络提供更及时的估计; GAE 用参数 $\lambda$ 在多步回报之间连续调节偏差与方差. TRPO 再把策略更新限制在信任域中, PPO 用更容易实现的 surrogate objective 近似控制更新幅度. 这一章要把每一步怎样从上一式得到写完整, 而不是把 PPO 当作起点.

### 02. 偏好优化与 RLHF

[偏好优化与 RLHF](./02-偏好优化/02-偏好优化.md)从人类比较数据开始. 同一个 prompt 下, 标注者选择更好的回答; Bradley-Terry 模型把偏好概率写成两个隐式奖励的差; 奖励模型学习这个差异, PPO 再用奖励模型提供的标量更新策略. 这里需要同时跟踪四个对象: 生成数据的策略, 被优化的策略, 限制漂移的参考策略和提供分数的奖励模型.

DPO, IPO, ORPO, SimPO 与 KTO 改变的是训练信号进入策略的方式. 有的方法消去显式奖励模型, 直接从偏好对构造目标; 有的方法改变 margin, 参考策略或样本形式. 它们不能只按排行榜比较, 还要比较数据需要什么标注, 损失对噪声怎样反应, 训练后策略离参考模型有多远.

### 03. 推理强化学习与可验证奖励

[推理强化学习与可验证奖励](./03-推理强化/03-推理强化.md)处理数学, 代码和形式化证明等可以自动判定结果的任务. RLVR 用规则或执行结果给奖励, 减少了奖励模型自身判断错误的问题. 一个 prompt 可以采样多条回答, 组内相对奖励能够构造 advantage; GRPO 正是利用这组样本省去独立的 critic, 后面的 DAPO, GSPO, GMPO, GDPO 与其他变体继续修改裁剪, 归一化, 采样和信用分配.

这一章尤其要区分算法公式与完整训练系统. 奖励是否只看最终答案, 长回答怎样归因到 token, 全错或全对的组是否还能提供梯度, 旧 rollout 重复使用多少轮, 训练策略与推理服务何时同步, 都会改变同一目标函数的实际行为. DeepSeek-R1 一类结果应该放回这些条件中理解.

### 04. 算法比较, 工程边界与选型

[算法比较与选型](./04-算法选型/04-算法选型.md)把前三章放到统一坐标中. 三条判断轴分别是反馈来自环境规则、人类偏好还是模型评判, 数据由当前策略在线生成、旧策略生成还是固定离线数据, 以及训练是否需要 critic、reference model、reward model 和执行环境. 这些条件比算法名字更直接地决定显存, 吞吐, 稳定性和可扩展性.

选型不能脱离失败方式. 奖励可被钻空子时, 更强的优化器可能只会更快放大奖励漏洞; 偏好对有系统偏差时, 直接偏好优化会忠实拟合这种偏差; 可验证任务如果只奖励最终答案, 模型可能得到正确结果却形成不可复用的中间过程. 比较章要把这些边界与工程成本放在公式旁边.

## 3. 这座库怎样使用

### 3.1. 公式需要落回采样过程

读任何目标函数时, 先标出期望对哪个分布计算. 若轨迹由 $\pi_{\mathrm{old}}$ 采样, 梯度却更新 $\pi_\theta$, 两个分布之间怎样校正; 若一条轨迹只有末尾奖励, token 级 advantage 怎样得到; 若使用组内标准化, 组大小和奖励方差怎样影响估计. 这些问题能够防止把形式相近的损失误认为同一种算法.

每条重要推导都应配一个小规模例子. 两状态 MDP 足以手算 Bellman 更新, 两动作策略足以检查策略梯度方向, 四条采样足以算一次 GRPO 的组内 advantage. 数字例子不能证明算法在大模型上有效, 但可以验证符号, 正负号和归一化是否理解正确.

### 3.2. 与训练课程和模型报告合读

[CS336 第 15 讲](../cs336/15-第15讲/15-第15讲.md)和[第 16 讲](../cs336/16-第16讲/16-第16讲.md)给出后训练日程与推理强化学习的课程视角. [DeepSeek](../deepseek/_garden.md), [OLMo](../olmo/_garden.md)和[模型库](../model-library/_garden.md)则记录具体模型采用的方法与训练配置, 可以用来核对共同机制在不同版本中的实际实现.

读完四章后, 面对一个新算法, 应能把它放进已有坐标: 它改变了数据分布, 奖励, advantage, surrogate objective 还是约束; 它减少了哪个组件, 又把误差转移到了哪里. 当这些问题能够独立回答时, 新缩写就不会重新把整条路线打散.

四章也共享一条记号纪律. 状态与动作写成 $s_t,a_t$, 环境转移写成 $P(s_{t+1}\mid s_t,a_t)$, 策略写成 $\pi_\theta(a_t\mid s_t)$, 折扣回报写成 $G_t$. 进入语言模型后,正文会明确说明状态何时等于 token 前缀, 动作何时等于下一个 token, 奖励何时只在序列末尾出现. 同一个字母若在论文中承担别的含义, 当前文章会重新定义, 不要求读者猜上下文.

实现代码的职责是验证推导. 简化实现应标出 tensor shape, 采样策略和 detach 边界, 并用手算结果检查符号与广播. 生产训练框架还包含分布式 rollout, 权重同步, 混合精度和故障恢复, 这些系统问题会单独讨论, 不会用几十行教学代码冒充完整训练系统.

真正读懂这些内容以后，看到一条新的训练配方，至少应该能判断收益来自估计量、数据分布还是系统预算，而不是只记住论文给出的最终分数。

## 4. 一条目标函数背后有四层对象

强化学习论文常把几十页方法压缩成一行期望。真正需要追踪的第一层是「希望最大化什么」。经典折扣回报写成

$$
J(\theta)=\mathbb E_{\tau\sim p_\theta(\tau)}
\left[\sum_{t=0}^{T-1}\gamma^t r(S_t,A_t)\right],
$$

其中轨迹分布 $p_\theta(\tau)$ 也依赖策略参数。语言模型中的序列奖励、逐 token KL 惩罚和长度归一化都会改变括号里的随机变量；偏好学习则可能从比较概率出发，根本不显式构造逐步奖励。因此，两篇文章都写「优化策略」，并不表示它们优化的是同一个总体目标。

第二层是「用什么量代替无法直接观察的总体目标」。价值函数、优势函数、奖励模型、规则验证器与成对偏好都属于训练信号，却处在不同位置。价值函数预测当前策略继续行动时的条件期望；优势函数衡量一个动作相对状态平均水平的增量；奖励模型拟合人类比较中隐含的排序；验证器只检查可判定结果。把这些对象统称为 reward，会掩盖它们的统计含义，也会掩盖误差怎样进入梯度。

第三层是估计器。真实的策略梯度是总体期望，训练只能得到有限批样本。Monte Carlo return、TD residual、GAE、组内标准化和 leave-one-out baseline 都在构造可计算估计量。它们的差别可以沿三条轴展开：是否引入 bootstrap 偏差，是否共享同组样本造成相关性，以及分母或基线是否随样本共同波动。估计器的期望、方差与尾部行为决定训练信号是否可信，不能用「更稳定」四个字带过。

第四层才是优化器实际接收的损失。重要性比率、裁剪、KL 正则、熵奖励与梯度裁剪会改变有限步更新。即使两个方法采用同一个 advantage，只要一个按 token 求平均、另一个按序列求平均，它们就会给长度不同的回答分配不同权重。**目标、代理信号、统计估计器与优化约束必须分层阅读；任何一层的改动都可能改变最终策略。**

## 5. 从经典 MDP 到语言模型的映射

给定提示 $x$，自回归模型生成 $y=(y_1,\ldots,y_T)$。第 $t$ 步状态可写成 $s_t=(x,y_{<t})$，动作是 $a_t=y_t$，策略为 $\pi_\theta(y_t\mid x,y_{<t})$。若只在结尾得到可验证奖励 $R(x,y)$，则中间步奖励为零，所有动作共同影响同一个终局结果。这是长程信用分配的来源：最后一次采样并没有单独「制造」答案，前面的定义、变形和分支选择同样改变成功概率。

这个映射也暴露出语言模型训练与小型控制任务的差异。动作空间是词表，轨迹树的分支因子很大；相同提示可以产生长度不同的终止轨迹；环境有时只在完整字符串上判定；策略的一个参数更新会同时影响大量前缀。于是，按序列得到的奖励怎样分配给 token、怎样处理长度、旧策略样本能复用几轮，都成为算法定义的一部分。

参考策略 $\pi_{\rm ref}$ 提供另一条坐标。常见 KL 正则目标可写成

$$
\max_\pi\;\mathbb E_{x,y\sim\pi}[r(x,y)]
-\beta\,\mathbb E_x D_{\mathrm{KL}}
\bigl(\pi(\cdot\mid x)\Vert\pi_{\rm ref}(\cdot\mid x)\bigr).
$$

系数 $\beta$ 决定奖励改善与分布漂移之间的交换率，也决定偏好最优策略相对参考策略能移动多远。若奖励存在系统漏洞，减小 $\beta$ 会让策略更快利用漏洞；若参考策略本身限制了探索，过大的 $\beta$ 又会压低可达到的改进。因此，KL 曲线必须和奖励、长度、熵以及真实验证通过率一起读。

## 6. 误差怎样沿训练链传播

训练链可以写成「采样分布 → 反馈 → 优势估计 → 代理目标 → 参数更新」。采样覆盖不足时，反馈函数再准确也看不到未探索区域；反馈含噪时，无偏估计器仍会忠实放大错误标签；优势归一化遇到近零组方差时会产生不稳定尺度；裁剪比例过高则说明样本对应的旧策略已离当前策略太远。每个环节都有自己的可识别症状。

一个简单反例能说明为何只看平均奖励不够。设验证器给真正正确答案奖励 $1$，给带有某个格式漏洞的错误答案也给 $1$。策略学会漏洞后，训练奖励上升，KL 仍可能很小，熵甚至保持正常，但真实正确率下降。此时问题位于反馈定义。换更强优化器只会加速错误方向。

再看组内归一化。若同一提示的 $G$ 条样本奖励全部相同，标准化后的优势没有可用排序信息；若只有一条成功，成功样本的相对优势会随组大小和标准差定义变化。组内方法消除了跨提示奖励尺度差异，却也让一个样本的权重依赖同组其他样本。讨论 GRPO、RLOO 及其变体时，需要把这种耦合明确写入估计器，不能只比较是否需要 critic。

## 7. 理论结论的适用条件

策略梯度的无偏性依赖样本来自声明的行为策略、支持集能够覆盖目标策略动作，并且重要性权重按正确分布构造。信任域的单调改进界依赖精确优势、受控散度与理想化求解；PPO 的裁剪目标是实用代理，并不自动继承全部保证。偏好优化从 Bradley–Terry 模型推导时，还假设比较概率可由标量效用差描述。人类偏好若包含上下文依赖、不可传递循环或标注者群体差异，这个模型只能给出压缩近似。

可验证奖励也有边界。数学最终答案与单元测试覆盖的是可判定部分，不能天然保证推理过程可靠、安全或可迁移。稀疏终局奖励可以驱动搜索，却很难区分多条偶然成功的路径；过程奖励提供更密集反馈，又引入步骤标注或过程验证器误差。两者之间没有脱离任务结构的统一胜者。

这座知识库以这些条件为共同底板。每一篇算法文章都需要回答：总体目标是什么，数据由谁生成，估计量对什么随机性取期望，约束限制哪个分布差异，以及结论在哪些假设失效后不再成立。这样读论文，缩写数量再多也只是同一组对象的不同组合。

还有一个常被平均数遮住的问题：**训练数据中的提示分布也是目标的一部分。** 假设一半提示极易通过，另一半提示始终失败。按全体样本报告平均奖励时，模型可能只提高简单提示的采样效率；在组内全对与全错都不给相对梯度的方法中，两端样本还会同时失去学习信号。课程采样、难度重加权和动态过滤会改变有效优化目标，因为它们改变了哪些状态前缀更频繁进入期望。

设原始提示分布为 $q(x)$，采样器实际使用 $\tilde q(x)$。若希望仍估计原目标，理论上需要权重 $q(x)/\tilde q(x)$；实际系统往往直接优化重加权后的目标。这样做可以把预算集中到仍有学习信号的区域，但也可能牺牲原分布上的校准。评估时应分难度区间报告通过率、响应长度和奖励方差，否则总体均值无法区分「更多简单题」与「同一批题真正学得更好」。

最后要区分训练时改进和推理时搜索。增加采样条数、best-of-$N$ 或树搜索能够在参数不变时提高命中率；强化学习则改变单次采样的策略分布。若评测预算不同，两者的收益会混在一起。公平比较至少固定生成预算，或同时给出 pass@$k$ 曲线与单样本准确率。这个区分会贯穿 RLVR、计算扩展和长程验证三条路线。
