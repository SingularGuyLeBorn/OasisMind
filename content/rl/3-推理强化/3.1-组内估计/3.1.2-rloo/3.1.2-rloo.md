# 留一法策略梯度优化 (REINFORCE Leave-One-Out, RLOO)

- **年份**: 2024
- **论文**: [arXiv:2402.14740](https://arxiv.org/abs/2402.14740) **前置知识**: REINFORCE(1.1.4 节), GRPO(1.3.1.1 节)

## 1. 动机: 把基线从「拟合」改回「采样」

### 1.1. REINFORCE 的老问题

策略梯度定理给出 $\nabla J(\theta)=\mathbb{E}_{y\sim\pi_\theta}[(R(y)-b)\nabla\log\pi_\theta(y|x)]$, 常数基线 $b$ 不改变期望, 但决定方差. 奖励不经处理的原始 REINFORCE, 梯度的方差大到几乎不可用, 这是它几十年里被 actor-critic 压制的原因. PPO 的解法是学一个价值网络 $V_\phi$ 当基线: 效果好, 但代价是多一份参数, 一组前向, 和一个必须跟 policy 同步训练的额外优化目标.

到 LLM 的 RLHF 场景, 价值网络的麻烦被放大. 状态是 prompt 加已生成 token, 价值要在每个 token 位置给出预测, 而 reward 只在序列末尾出现一次; 用最终 reward 监督每个位置的 value, 本身就是个困难的信用分配问题. PPO 在 LLM 上能 work, 但工程复杂度成了它的主要成本.

还有一个更实际的观察: value model 的预测质量受 reward 稀疏性的限制, 在 reward 只在序列末出现的设定下, value 的 bootstrapping 链条很长, 训练早期它的估计接近噪声. 用一个噪声基线降噪, 收益自然有限——这正是「回到采样统计」路线的动机之一.

### 1.2. 组基线: 不训练, 用采样平均

GRPO 的思路是彻底放弃「学习基线」, 改用统计基线: 同一 prompt 采 $G$ 条回答, 组内均值 $\bar R$ 就是基线. 这个基线不需要训练, 不需要额外前向, 天然和 policy 同步 (同一 checkpoint 采出来的组). 它隐含一个假设: 组均值是「这个动作好不好的平均参照」.

问题出在数学上. 基线 $b_i=\bar R=\frac{1}{G}\sum_j R_j$ 包含了 $R_i$ 自己, 而 $R_i$ 依赖 $y_i$, $y_i$ 的采样分布由 $\pi_\theta$ 决定——于是基线和策略参数相关. 策略梯度的无偏性证明要求基线与当前动作独立; 组均值基线违反这个条件, 梯度估计带有偏差. 偏差随 $G$ 增大而减小 ($R_i$ 在均值里的权重是 $1/G$), 大组训练时实践中没人感到疼, 但小 $G$ 时偏差不可忽略.

严格地说, 这个偏差的量级是 $O(1/G)$ 乘上 reward 与 score 的协方差项, 而协方差项在「reward 高的样本恰好梯度大」时非零——偏偏训练中后期 reward 和 logprob 高度相关, 协方差项不小. 所以「大 $G$ 就没事」是按偏差的渐近阶说的, 落到具体任务的数值, 还是值得做一次留一版对照.

**留一法: 差一个样本的距离。**

RLOO 的修改小得惊人: 基线改为「除自己以外其他样本的均值」

$$b_i=\frac{1}{G-1}\sum_{j\neq i}R_j.$$

$R_i$ 不进入自己的基线, 基线与动作严格独立, 无偏性恢复. 其余的工程优势原封不动保留: 不训练网络, 不多前向, 只做一次组采样. 论文标题的 Back to Basics 指的就是这个姿态: 不带 actor-critic 的REINFORCE, 配上一个统计上站得住的基线, 就够和 PPO 打. 留一法在统计学习里是个老技术 (jackknife 的核心操作), 用在策略梯度基线上并不新鲜, 新鲜的语境是 LLM RLHF: 采样一组回答的边际成本远低于训练一个 value model, 「用计算换统计」在这里是划算的. 这个「划算」有个隐含前提: 采样的边际成本确实低.

RLOO 与 GRPO 的差异同时落在统计性质和成本结构上. 短输出时, 多采一条样本换取更干净的估计仍可能划算; 输出增长到数千 token 后, 额外采样成本近似线性上升, 样本复用的收益随之变大. 推理 RL 更偏向 GRPO, 很大程度上来自这种成本结构的变化.

## 2. 留一法基线的推导

### 2.1. 无偏性

把 RLOO 的梯度估计写出来. 对组内第 $i$ 条样本, 贡献是

$$g_i=(R_i-b_i)\nabla\log\pi_\theta(y_i|x),\qquad b_i=\frac{1}{G-1}\sum_{j\neq i}R_j.$$

无偏性要求 $\mathbb{E}[g_i]=\nabla J$ 的对应分量. 关键一步: $b_i$ 只由 $\{y_j\}_{j\neq i}$ 决定, 而 $y_i$ 由 $\pi_\theta$ 独立采样, 所以 $b_i$ 对 $y_i$ 的分布而言是常数. 于是

$$\mathbb{E}\left[b_i\nabla\log\pi_\theta(y_i|x)\right]=\mathbb{E}_{j\neq i}\left[b_i\cdot\underbrace{\mathbb{E}_{y_i}\left[\nabla\log\pi_\theta(y_i|x)\right]}_{=\,0}\right]=0,$$

内层期望是 score function 的零均值恒等式. 基线项整体消失, 剩下的正是策略梯度. 对比组均值基线: $b_i$ 含 $R_i$, 不能从内层期望里提出来, 零均值恒等式用不上, 偏差项 $\frac{1}{G}\mathbb{E}[R_i\nabla\log\pi_\theta(y_i|x)]$ 留在估计里. 直观理解这个偏差: reward 高的样本, 它的梯度在被基线缩放之前先被自己「加注」了一次, 模型被额外鼓励重复已经高 reward 的行为, 探索受到抑制. 方向上这个偏差让训练更保守——不一定是坏事, 但要知道它在那里.

### 2.2. 方差

无偏不等于好用, 还要看方差. 留一基线的方差有两个来源: 采样方差 (只有 $G-1$ 条样本估计「平均水平」) 和 reward 本身的方差. 对固定的组, $A_i^{RLOO}=R_i-\frac{1}{G-1}\sum_{j\neq i}R_j$ 的方差随 $G$ 增大按 $1/(G-1)$ 收缩——和任何样本均值一样. $G=8$ 时基线方差约为单样本方差的 $1/7$, 这已经足够把 REINFORCE 从「不可用」拉到「稳定训练」. 论文还指出了一个不太显眼的事实: 留一基线和组均值基线在数值上只差一个缩放.

这个事实的另一面: 凡是对两组优势施加相同后处理 (比如同样的标准差归一或同样的 batch 标准化) 的系统, 两者的差别会进一步缩小, 最终收敛到同一个估计量. 所以争论「GRPO 还是 RLOO」之前, 先检查自己的管线里做了哪些后处理, 很可能争论的对象早被后处理抹平了. 直接展开:

$$A_i^{RLOO}=R_i-\frac{G\bar R-R_i}{G-1}=\frac{G}{G-1}\left(R_i-\bar R\right)=\frac{G}{G-1}A_i^{GRPO}.$$

不做标准差归一化时, GRPO 和 RLOO 的优势**完全相同, 只差常数因子 $G/(G-1)$** ($G=8$ 时是 $1.14$). 这意味着两者的训练动态在理想条件下几乎一致, 留一法的价值主要体现在理论上干净, 以及它对小 $G$ 更稳; 实践差距要等 reward 分布和归一化方式参与进来才会拉开.

**数值对照。**

取 $G=4$, rewards $R=[10,5,8,2]$. 组均值 $\bar R=6.25$. GRPO (不归一) 的优势: $A=[3.75,-1.25,1.75,-4.25]$. RLOO 的留一基线: $b_1=(5+8+2)/3=5$, $b_2=(10+8+2)/3=6.67$, $b_3=(10+5+2)/3=5.67$, $b_4=(10+5+8)/3=7.67$. 优势: $A^{RLOO}=[5,-1.67,2.33,-5.67]$. 逐项验证 §2.2 的缩放关系: $3.75\times 4/3=5.0$, $-1.25\times4/3\approx-1.67$, 其余两项同样成立. 两个观察. 第一, RLOO 的优势绝对值系统性偏大 $33\%$, 如果直接搬 GRPO 的学习率和 KL 系数, 等效更新步长会变大. 第二, 排序完全一致, 符号完全一致, 所以这个差别是纯尺度的——它不改变每个组内的相对判决, 只改变判决的力度.

把缩放关系用于调试很实用: 实现里同时算出两种优势, 断言它们的比值恒为 $G/(G-1)$, 就同时验证了基线和均值两条代码路径; 比值偏离说明其中一条算错, 而训练 loss 对此完全不敏感——没有这条断言, 这类 bug 能活到训练结束.

再补一组退化检查: 若组内四条 reward 全等 ($[c,c,c,c]$), 两种优势都应为零, 这对应「该组无可学信号」的语义. 若只有两条样本 ($G=2$), 留一基线变成对方一条样本, 优势恒为 $\pm(R_1-R_2)$, 基线的降噪作用消失, RLOO 退化成裸 REINFORCE 的两样本对照——$G=2$ 在实际中应避免. 这个退化检查适合放进 CI: 随机生成 reward 向量, 覆盖全零, 全同, 两极, 一般四种形态, 逐一对解析解. 四个 case 加起来不到二十行, 能拦住向量化实现里大部分的索引错位.

**一个更细的方差分解。**

把 RLOO 梯度的方差拆成两项看, 能看清组大小到底买什么. 展开 $\mathrm{Var}(g_i)$, 主导项是 $\mathrm{Var}(A_i)\cdot\mathbb{E}[\|\nabla\log\pi\|^2]$ 加上优势与 score 的协方差项; 在常见设定下第二项小, 可以只盯 $\mathrm{Var}(A_i)$. $\mathrm{Var}(A_i)=\mathrm{Var}(R)+\frac{\mathrm{Var}(R)}{G-1}$, 即「reward 本身的方差」加「基线估计的方差」. 组大小只压第二项, 第一项是任务的固有属性, $G\to\infty$ 也压不掉.

这个分解直接给出一个实践推论: 当 reward 方差本身很大时 (例如人工打分的开放任务), 增大 $G$ 的收益递减得很快, 有效手段是改 reward (减少标注噪声, 收窄评分维度); 当 reward 方差小而基线估计噪声占主导时 (例如二值 reward 且 pass rate 接近 0.5), 增大 $G$ 几乎线性改善估计质量. 判断自己处于哪种情形, 打印每组 reward 的组内方差分布就够了.

方差分解还解释了为什么「reward 减均值」这类粗糙预处理有时也有效: 它动的是第一项 (reward 固有方差), 和基线无关. 把 reward 中心化到零均值区间, 优势的量级随之收缩, 优化器的有效步长跟着变——效果是隐式调了学习率, 调试时要意识到这层因果.

## 3. 目标函数与训练循环

### 3.1. REINFORCE 目标与 KL 的位置

RLOO 直接优化带基线的 REINFORCE 目标, 附加对参考策略的 KL 惩罚:

$$J(\theta)=\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^G A_i^{RLOO}\log\pi_\theta(y_i|x)\right]-\beta\,D_{KL}(\pi_\theta\,\|\,\pi_{ref}).$$

KL 放在哪个表达式里是个实现选择. 论文实验了两种: 把 KL 作为 loss 的独立项直接减去 (loss 版), 和把 KL 估计成 per-token 惩罚加进 reward 再进优势 (reward 版). 两种都常见, 但估计量不同: loss 版用解析 KL 或其采样近似, reward 版用 k3 估计量 $\mathbb{E}[\log\frac{\pi_{ref}}{\pi_\theta}]-\log\frac{\pi_{ref}}{\pi_\theta}$... 具体形式见原论文 §3, 要点是 k3 是低方差且(在 on-policy 下)无偏的 KL 采样估计. 选哪种影响 KL 项的方差, 进而影响有效学习率, 复现时不能随意混用.

两种放法的监控口径也不同: loss 版直接看 KL 项的数值曲线, reward 版看的是「带 KL 的 reward」分布. 把两种口径的日志混在一起对比, 会得出 KL「忽大忽小」的假性结论. 论文自己的实验对两种都做了, 结论是不区分优劣, 按实现方便选, 但一个 run 内要统一.

### 3.2. on-policy 语义与 clip

RLOO 是严格的 on-policy 算法: 组由 $\pi_\theta$ 采出, 同一 batch 内更新一次 (或少数几次 minibatch), 然后丢弃. 这带来两个性质. 第一, importance ratio 恒为 1, PPO 的 clip 机制在纯 RLOO 里没有作用对象——有些实现仍保留 ratio 和 clip, 那是为了支持多次 minibatch 复用 (变成 PPO-LOO), 不是 RLOO 本身的需要. 第二, 数据效率低: 每个组只贡献一次梯度就扔掉, 同样 rollout 成本下参数更新的样本量远小于离线方法. 论文的实证发现是, on-policy 的「新鲜度」收益能抵消数据效率的损失: 梯度方向基于最新策略, 估计更准, 大步更新不易踩偏. 这呼应了同期社区的一个广泛观察: 在 LLM RLHF 的尺度上, 估计质量比数据复用更重要.

这个观察有个边界条件值得写明: 「估计质量优先」成立的前提是策略更新本身很小步 (学习率受 KL 约束). 一旦放开步长, off-policy 的修正误差随 ratio 偏离二次增长, clip 这种硬截断的粗糙性会显出来. RLOO 去 clip 的底气一半来自无偏基线, 一半来自小步更新——两个条件缺一个, 「不需要 clip」都不成立.

**归一化的位置。**

RLOO 理论上不需要标准差归一化——优势已经是有统计意义的量. 但工程上常见的做法是在 batch 级对优势做标准化 ($A\leftarrow(A-\mu)/(\sigma+\epsilon)$), 目的是稳住优化器的有效步长. 这个标准化和 GRPO 的组内标准差归一不是一回事: batch 级标准化的均值方差跨 prompt 混合, 抹掉了组间难度差; 组内归一保留每个 prompt 的相对结构. Dr. GRPO 对组内归一的批评 (1.3.1.1 节) 在这里以另一种形式出现: 归一化放哪儿, 决定了难度的信息保留多少. 实践建议: 训练初期 reward 方差大时做 batch 级标准化; 中后期方差稳定后可以关掉, 让优势回到原始尺度, KL 系数和优势尺度的配比更直观.

无论归一化放哪儿, 有一条纪律不变: 优势的「零点」和「尺度」是两个独立的设计决定. 零点由基线决定 (RLOO 的组内零和性质保证每组正负平衡), 尺度由 reward 的量纲决定; 归一化只动尺度, 不应移动零点. 发现某版实现归一化后组均值不为零, 大概率是标准化写在了基线之前, 属于实现 bug 而非风格差异.

**训练循环的工程形态。**

RLOO 的一个完整迭代周期: 对 batch 内每个 prompt 采样 $G$ 条, 算 reward, 算留一优势, 一次梯度更新, 丢弃数据, 进入下一轮. 这个循环里没有 PPO 的多 epoch minibatch 结构, 代码骨架接近 SFT 训练循环, 只是把「前向算 loss」换成「采样算 reward 再前向算 loss」. rollout 和 training 的同步关系因此更简单: 每组数据从采样到消费间隔极短, 不存在版本漂移问题, 这是纯 on-policy 的结构性红利.

但 rollout 本身的工程一点也不简单: 自回归生成的延迟, batch 内长度不齐的 padding 浪费, reward 计算 (尤其是调用外部验证器或 reward model 服务) 的排队, 都和算法无关却决定吞吐. RLOO 论文的实验环境把这些都搭好了, 复现时若只搬算法不搬这些基建, 体验会差很多. 一个常见的折中: rollout 仍走异步流水, 但队列极浅 (一到两个 batch), 牺牲少量利用率保住近似 on-policy 的语义.

rollout 的 batching 还影响 reward 估计的口径: 若 batch 内 prompt 难度不均, 简单 prompt 的组早早采完, 难题的组还在生成, 平均等待时间被最长的组拖住. 按预估长度分组采样 (把预计输出长的 prompt 放一起), 是这类流水线的常用优化, 不改算法只改调度.

## 4. RLOO 与 GRPO 的并排

### 4.1. 一张对照表装不下的差别

| 维度 | GRPO | RLOO |
|------|------|------|
| **基线** | 组均值 (含自身, 有偏) | 留一均值 (无偏) |
| **优势尺度** | 差常数因子 $G/(G-1)$ | 基准 |
| **归一化** | 组内标准差 (Dr. GRPO 已质疑) | 通常不做 |
| **ratio 与 clip** | 保留 (支持 off-policy 修正) | 通常不需要 (纯 on-policy) |
| **数据复用** | 组可 minibatch 复用数次 | 一次即弃 |
| **来源** | DeepSeekMath (2024.02) | Cohere (2024.02, 同期) |

两篇文章几乎同时发表 (2024 年 2 月), 从同一观察出发——value model 太贵, 组统计可以替代——走到同一个家族. 分歧在细节: DeepSeek 保留 PPO 的 ratio-clip 骨架, 方便复用现有基建和多次更新; Cohere 回到纯 REINFORCE, 换来理论干净和实现简单. 两家的选择都自称「简单」, 但简单的方向相反: DeepSeek 的简单是「和已有 PPO 基建兼容」, Cohere 的简单是「不依赖任何既有基建也能从头写完」.

两家公司后续的路线延续了各自的工程选择: DeepSeek 沿 GRPO 骨架逐步加入训练技巧并走到 R1, Cohere 后续工作则没有继续围绕 RLOO 展开. 算法能否进入主流实现, 同时取决于效果和既有基础设施. 已有 PPO 基建时, GRPO 的改造成本更低; 从头搭建小型训练器时, RLOO 的实现链条更短.

### 4.2. 什么时候差别显著

由 §2.2 的缩放关系, 不归一时两种优势只差 $G/(G-1)$, 实际差别来自三个附加结构. 第一, **组内标准差归一**: GRPO 除以 $\sigma_R$, 难题 (高分差) 和易题 (低分差) 的梯度被拉到同一尺度, RLOO 不做这个, 难题天然获得更大梯度. 第二, **clip**: GRPO 的 clip 改变大优势样本的有效更新, RLOO 没有这层. 第三, **数据复用**: GRPO 可以一个组训多个 minibatch, RLOO 一次即弃, 同样的 rollout 成本下两者每步的「信息新鲜度」不同.

小 $G$ (4 到 8) 时偏差因子和尺度因子最大, 两种算法的理论差距最明显; $G$ 到 32 以上, 无偏性差异几乎消失, 差别收敛到工程习惯. 选择因此更多是基建问题: 已有 PPO 基建 (异步 rollout, minibatch 复用, clip 监控) 的团队用 GRPO 顺手; 新建管线或追求实现极简的团队, RLOO 的代码路径短一半. 还有一个容易被忽略的组合选项: 用 GRPO 的骨架 (ratio, clip, 复用) 配 RLOO 的优势. 两者不冲突, 留一基线只是优势的一种构造方式, 喂给带 clip 的 PPO 式损失完全合法, 有实现就是这么做的. 组合之后还要检查 off-policy 偏差: clip 之外, 复用数据时 ratio 不再为 1。无偏基线保证基线项独立于当前动作，采样分布偏离当前策略则需要另行修正。即使基线无偏，整个估计仍会因数据复用产生可控的 off-policy 偏差.

**与 DAPO 之后工程趋势的衔接。**

2025 年之后的推理 RL 工程实践 (DAPO 1.3.2.1 节, verl 等框架) 大量采用「GRPO 骨架 + 各种 trick」的形态, 纯 on-policy 的 RLOO 相对少见. 推理 RL 的大部分时间消耗在 rollout 上, 复用一组样本多更新几步可以直接提高吞吐, clip 则为这种复用提供安全边界. RLOO 要求每组样本保持新鲜, 梯度估计更干净, 代价是降低样本利用率. 论文中 RLOO 与 PPO 相当的效果来自特定成本结构, 无法单独证明 on-policy 更新普遍优于样本复用.

成本结构还在继续演化: 随着 rollout 加速手段 (投机解码, 前缀缓存, PD 分离) 普及, 采样的边际成本在下降, on-policy 路线的相对竞争力在回升. 选择路线时应使用当前系统的采样与训练成本重新计算, 不能直接沿用论文发布时的成本结论.

**两阶段用法: SFT 打底与 KL 锚。**

论文实验流程依次经过 SFT、RLOO 与 KL 约束. SFT 把策略推入高质量区域，RLOO 在该区域内估计相对优势，KL 惩罚限制策略远离 SFT 锚点. 这组结果对应 SFT 冷启动条件；预训练模型直接进入 RLOO 的表现仍需另做实验验证，现有消融无法回答这个问题.

KL 锚的选择有个细节: 参考策略用 SFT checkpoint 还是更早的 checkpoint. 用 SFT checkpoint, KL 约束保护的是「格式和能力不退化」; 用更早的 checkpoint, 约束更松, 探索空间更大但崩坏面也更大. 论文用 SFT checkpoint, 是社区的主流选择; 想在探索上加预算的团队, 更稳妥的做法是减小 $\beta$ 而不是换参考点. 减小惩罚系数的边界是「格式崩坏出现在 KL 预警之前」: 一旦监控里发现输出格式开始漂移 (模板 token 缺失, 截断率上升), 说明探索预算已经花过线, 应回退系数而不是继续降.

## 5. 组大小与 reward 分布

**组大小的作用。**

留一基线的质量由 $G-1$ 条样本支撑, 组大小的选择和 GRPO 一样关键, 但方向略有不同. $G$ 小, 基线方差大, 无偏性价值被噪声吃掉一部分; $G$ 大, 基线准, 但留一和组均值的差别也消失, 退化成同一个算法. 论文的实验设置在 $G=4$ 到 $G=16$ 之间, 结论是 $G\ge 8$ 后收益递减. 对二值 reward (答案对错), 组内至少要有成败各一才有非零优势, $p^G+(1-p)^G$ 的全同概率和 1.3.1.1 节一样约束有效组占比. 动态组大小在这里同样适用但动机不同: GRPO 调 $G$ 是为了组统计稳定, RLOO 调 $G$ 更多是为了覆盖 reward 分布的两端. 对 pass rate 极低的难题, 与其堆 $G$, 不如先用 SFT 或拒绝采样把 pass rate 抬到 0.3 以上再进 RL——基线再好, 组里全是零也榨不出信号.

### 5.2. reward 分布形态的影响

留一基线假设组内 reward 可比较, 这对标量 reward (reward model 打分) 和二值 reward (验证器) 都成立, 但对方差结构敏感. reward 高度偏斜时 (比如大多数样本 0 分, 极个别 1 分), 留一基线对小 $G$ 近似等于「别人的均值接近 0」, 优势退化成 reward 本身, 基线价值缩水. 这和 GRPO 的处境相同, 缓解方式也相同: 调整 prompt 难度分布, 让组内成败混合. 另一个形态问题是 reward 的尺度漂移. reward model 更新 (如果用 iterative RM) 或验证器规则调整, 会让历史组和当前组的 reward 不可比. on-policy 的 RLOO 对此天然免疫——每组数据即采即用, 不存在跨版本比较; 这算是一个被低估的优点.

**基线之外: reward 的校准。**

留一基线解决的是「和组内平均水平比」, 不解决「reward 本身标定对不对」. reward model 的分数漂移, 验证器的规则漏洞, 标注者的系统性偏好, 都会原样穿过基线进入梯度. 论文讨论的 reward 来源是训练好的 reward model, 那时 iterative RM 更新带来的分布漂移是主要校准负担; 今天的可验证 reward 场景, 负担转移到规则覆盖度 (等价答案, 多解, 格式变体).

一条通用的校准纪律: 训练全程冻结 reward 来源的版本, 任何更新都新开 run, 不中途切换. 中途切换 reward 等价于偷偷移动损失表面的地形, 历史优势和新优势不可比, 而 on-policy 的短记忆会让这个问题更隐蔽——每组数据都「新鲜」, 新旧 reward 的差异被采样噪声盖住, 直到下游评测才显形.

校准还有一个轻量手段: 定期用固定探针集 (一批固定 prompt 的固定回答) 过一遍 reward, 把分数曲线画出来. 探针集不训练, 只测量 reward 的漂移; 曲线平, 说明 reward 稳定; 曲线系统性上移或下移, 先查 reward 再查 policy. 探针集本身也要版本管理: prompt 集和回答集都是固定的, 改 reward 时同时跑新旧两版探针, 漂移的归因才有对照. 这套探针机制不独属于 RLOO, 任何 RLHF 管线都值得配一套. 它和版本冻结, 不变量单测一起, 构成 RL 训练可审计性的三件套.

**与拒绝采样的组合。**

RLOO 和拒绝采样 (best-of-n 蒸馏) 是互补关系, 不是竞争. 拒绝采样用同一套组采样产出 SFT 数据: 采 $G$ 条, 留最好的, 做一轮 SFT; RLOO 用同一套采样产出梯度: 采 $G$ 条, 留一基线, 直接更新. 前者的数据可以喂给后者当 SFT 阶段, 后者的 rollout 基建可以被前者复用. 工程上把它们设计成同一条流水线的两个开关, 是这类系统最常见的形态.

组合的顺序有讲究. 对 pass rate 极低的任务, 先拒绝采样把模型抬到「组内有时对错」的区间, 再进 RLOO, 信号效率最高; 反过来先 RL 后拒绝采样, 容易在零信号区空转大量 rollout. 这个「先蒸馏后 RL」的次序, 和 1.3 节推理 RL 的主流配方 (R1 的 cold start + RL) 完全一致. 拒绝采样还有一个隐性收益: 它产出的 SFT 数据经过质量过滤, 同时建立了「格式正确」的底线, 让后续 RL 的 reward 里不再混入格式噪声. 这个清洗作用在 open-ended 任务上尤其明显.

## 6. 实验证据与边界

**论文报告的结果。**

论文在 6B 到 70B 的模型上, 用 summarization 和对话任务对比了 RLOO, PPO, GRPO 等, 报告 RLOO 在多数设置下匹配或超过 PPO, 且实现更简单, 训练更稳. 方法层面可靠的结论是: 在 LLM RLHF 的典型规模上, 策略梯度的估计质量 (无偏, 低方差) 比算法的 off-policy 能力更重要, 一个干净的 REINFORCE 变体足以成为生产选项. 论文没有覆盖可验证 reward 的推理场景——那是 GRPO 系在 R1 之后的主场, RLOO 在那里的表现需要看后续复现.

实验设计上, 论文的 controlled setting (固定任务, 固定 reward, 多个 seed) 比单点跑分更能支撑方法学结论, 这一点值得肯定: RL 训练的高方差使得单次跑分的差异经常不显著, 多 seed 报告是该领域的必要纪律, 这篇是早期做到位的论文之一. 论文仍留下三项开放问题: 在优势构造相同的前提下, on-policy 与复用式更新在长程训练中的差距缺少系统对比; 二值且极稀疏 reward 下的表现没有覆盖; 与后来 Dr. GRPO 式修正的组合效果仍未知.

### 6.2. 局限与批评

第一, on-policy 的样本效率在 rollout 昂贵时是硬伤, 论文的成本结构 (相对小的模型, 较短的输出) 下放大了 RLOO 的相对优势. 第二, 留一基线依赖「同 prompt 组内可比」, 对需要跨 prompt 比较的场景 (例如全局质量排序) 没有结构支持. 第三, 论文的对比基线没有包含之后出现的 Dr. GRPO, DAPO 等修正版, 「RLOO 优于 GRPO」的说法在今天要加限定: 优于的是哪个版本的 GRPO.

这些局限都不致命, 它们圈定的是适用域而不是缺陷: 把 RLOO 用在它设计的场景 (中小规模, 中等长度输出, 标量 reward), 它依然是学习和调试策略梯度方法的最佳起点, 因为它的每个量都可以手算验证, 每个偏差都有名字. 这批局限在 2025 年以后的实践里部分被绕开: 长输出场景的采样加速 (投机解码, 前缀缓存) 直接改善了 on-policy 的成本结构, 可验证 reward 的兴起则把「标量 reward 校准」问题从模型漂移换成规则覆盖度. 算法骨架没变, 适用域的边界在移动.

**什么时候选 RLOO。**

新建 RLHF 管线, 模型规模中小, 输出不长, rollout 成本可控时, RLOO 是最快拿到稳定 baseline 的选择——代码短, 超参少, 理论干净, 调试空间小. 推理 RL 长输出场景, rollout 占绝对大头时, 优先看带 clip 和复用的 GRPO 系. 需要严谨的 off-policy 修正 (例如异步流水导致的版本偏移) 时, RLOO 帮不上忙, 回到 PPO 骨架. RLOO 用很短的实现同时呈现了三个核心问题: 基线为何需要独立、无偏性与方差如何权衡, 以及 on-policy 约束需要付出多少采样成本. 沿着这三个量再看 PPO 和 GRPO, 各自增加的状态与近似会更清楚. RLOO 的 reward、基线、优势和 KL 都能逐项打印并手工核验. 在故障排查阶段, 这种可审计性有时比几个百分点的效率差异更重要.

**实现。**

**教学实现。**

```python
import torch

def rloo_advantages(rewards):
    # rewards: [batch, group]，同一 prompt 的 G 条 reward
    G = rewards.shape[1]
    total = rewards.sum(dim=1, keepdim=True)
    loo_baseline = (total - rewards) / (G - 1)   # [batch, group]
    return rewards - loo_baseline def rloo_loss(logprobs, advantages, kl_penalty=None, beta=0.0):
    # logprobs: [batch, group]，每条 response 的 token 平均 log π
    # advantages: [batch, group]，来自 rloo_advantages
    policy_term = -(advantages.detach() * logprobs).mean()
    loss = policy_term
    if kl_penalty is not None:
        loss = loss + beta * kl_penalty
    return loss
```

向量化技巧的核心一行是 `(total - rewards) / (G - 1)`: 免循环算出所有留一基线. 注意 `advantages.detach()`: 基线和优势都不该吃梯度, 梯度只走 logprob 分支; 漏 detach 不会报错, 会静默多一条反向路径. KL 项的实现建议单独封装: 传入的 `kl_penalty` 应该是已经估计好的标量 (k3 或解析形式), 损失函数内部不再采样. 把采样逻辑留在训练循环里, 损失函数保持纯函数, 才能复用 §7.2 的全部不变量测试.

**验证清单。**

三个不依赖模型的不变量. 第一, 缩放关系: 对任意 reward 向量, `rloo_advantages(R) == (G/(G-1)) * (R - R.mean(dim=1, keepdim=True))`, 逐元素成立, 可直接写成单元测试. 第二, 零均值性: 每组 RLOO 优势的和恒为 0 (所有基线都是组均值的无偏重组), 数值误差外不应偏离. 第三, $G=2$ 退化检查: 留一基线退化成单条对方样本, 优势 $A_1=R_1-R_2$, $A_2=R_2-R_1$, 严格反号. 三条配合 §2.3 的手算样例, 可以在不启动训练的情况下验证实现正确性.

再补一条数值不变量: 全零 reward 组的优势必须全零, 全一同 reward 组同理. 这两类退化组在实际训练里占比不低 (难题全错, 易题全对), 实现里对它们跳过时, 跳过逻辑本身也要被这条不变量测试覆盖——否则过滤条件写错 (比如把「全同」写成「全零」), 会静默改变训练分布.

### Leave-one-out 的无偏条件

对固定 prompt $x$，从同一行为策略独立采样 $k$ 条轨迹 $y_1,\ldots,y_k$，回报为 $R_i$。RLOO 为第 $i$ 条轨迹定义

$$
b_{-i}=\frac1{k-1}\sum_{j\ne i}R_j,
\qquad
A_i=R_i-b_{-i}.
$$

策略梯度项为 $A_i\nabla_\theta\log\pi_\theta(y_i|x)$。给定 $x$ 时，$b_{-i}$ 只依赖其他独立轨迹，与当前动作 $y_i$ 条件独立，因此

$$
\mathbb E[b_{-i}\nabla\log\pi(y_i|x)\mid x]
=\mathbb E[b_{-i}|x]\,
\mathbb E[\nabla\log\pi(y_i|x)|x]=0.
$$

第二个期望为零来自 score-function 恒等式。于是减去 leave-one-out baseline不改变期望梯度，只改变方差。无偏结论依赖同 prompt、条件独立采样、baseline不含当前动作，以及 log-prob确实对应采样策略。 若组内候选由 correlated decoding产生，例如 diverse beam search共享搜索树，其他 reward与 $y_i$ 不再条件独立。baseline可能携带当前动作信息，无偏证明不直接成立。普通独立采样也共享 prompt，但给定 prompt 后随机性独立，这是允许的。 若 reward包含组内排序、去重惩罚或“只有组内最佳得 1”，$R_j$ 本身依赖 $y_i$，leave-one-out baseline也间接依赖当前动作。目标成为组级交互 reward，不能沿用单轨迹无偏证明。 如果 $b_{-i}$ 参与自动微分，reward或 baseline通常不可导，问题不大；若使用 learned differentiable reward并让梯度穿过 baseline，就会出现额外路径。策略梯度实现应 stop-gradient advantage。

**Leave-in、Leave-out 与组相关性。**

组均值 baseline包含当前样本：

$$
R_i-\bar R
=\frac{k-1}{k}(R_i-b_{-i}).
$$

因此不做标准差归一化时，leave-in中心化与 RLOO方向相同，只差 $(k-1)/k$ 缩放。该缩放可被学习率部分吸收，但小组时明显：$k=2$ 缩小一半，$k=4$ 缩小四分之一。 GRPO常再除组标准差，改变 prompt间权重；RLOO原始形式通常保留 reward绝对尺度。两者差异不止是否排除自己，还包括标准化、clip、KL位置、token归约与数据复用。 同组 $A_i$ 彼此相关。每条轨迹都出现在其他人的 baseline中，优势之和为零：

$$
\sum_i A_i=0.
$$

这不表示参数梯度和为零，因为每条轨迹的 score gradient不同。它说明组内更新是纯相对的，给所有 reward加同一常数不会改变 advantage。 reward乘常数 $c$ 会让 RLOO advantage乘 $c$；标准化 GRPO大致不变。RLOO保留 reward量纲，reward设计与任务权重直接进入梯度。

**组大小与归约粒度。**

$k=1$ 时 leave-one-out baseline无定义，RLOO至少需要两条轨迹。$k=2$ 时每条以另一条 reward为 baseline，优势互为相反数，reward噪声直接进入差值。 若 reward独立且方差为 $\sigma^2$，$b_{-i}$ 方差为 $\sigma^2/(k-1)$。$A_i=R_i-b_{-i}$ 的方差在独立假设下为

$$
\operatorname{Var}(A_i)=\sigma^2+\frac{\sigma^2}{k-1}
=\frac{k}{k-1}\sigma^2.
$$

增加 $k$ 降低 baseline噪声，$A_i$ 仍包含当前 reward固有方差，收益逐渐递减。固定 rollout预算下，大组减少独立 prompt数，prompt覆盖与组内基线精度形成取舍。 同组轨迹共享 prompt，不能当作 $k$ 个独立任务。评估区间以 prompt group为 cluster。训练有效样本量也更接近独立 prompt和语义簇数量，而非轨迹行数。 二元 reward成功率为 $p$ 时，全同组概率 $p^k+(1-p)^k$。全同组 RLOO advantage全零。极难和极易 prompt都少信号，中等成功率任务成为自然课程。 自适应组大小先采少量，若全同再追加。它提高有效组率，也按早期 reward选择预算。记录每个 prompt最终 $k$，否则训练权重与成本不可解释。 若组大小不一而所有 token全局 mean，大组 prompt贡献更多。若每组先 mean再跨 prompt mean，则 prompt等权。RLOO baseline与最终 loss归约是两个独立层级。

**Sequence 与 Token 归约。**

序列 reward $R_i$ 产生一个 $A_i$，通常广播到回答所有 token。REINFORCE序列形式为

$$
L_i=-A_i\sum_{t=1}^{T_i}\log\pi_\theta(y_{i,t}|x,y_{i,<t}).
$$

长回答包含更多 log-prob项，序列 sum使其参数梯度通常更大。若除以 $T_i$，变成每 token平均，回答级等权更强，却改变原始序列概率目标。 token-global mean、sequence mean与group mean可以组合出不同权重。设一条 10 token、一条 100 token，token mean中长轨迹约占十倍；先 sequence mean后二者各占一半。公式必须写到最终标量归约。 优势广播提供粗粒度 credit。成功轨迹中的绕路都被提高，失败轨迹的正确前缀也被压低。过程 reward、reward-to-go或 value模型能提高时间分辨率，属于扩展目标。 EOS 是策略动作。自然 EOS进入 token loss；截断轨迹没有自然结束，不能伪造 EOS。overlong penalty会鼓励早停，需按任务完整性评估。 多轮工具轨迹只对 policy产生的 token求 log-prob。用户、工具结果与环境观察是条件。把观察计入 loss会给模型无法控制的文本梯度。

### KL、奖励噪声与方法边界

RLHF/RLOO常把 KL 惩罚并入每条轨迹 reward：

$$
R_i=R_i^{task}-\beta
\sum_t\left(\log\pi_\theta(y_{i,t}|h_{i,t})
-\log\pi_{ref}(y_{i,t}|h_{i,t})\right).
$$

再用 RLOO baseline中心化。由于同组各轨迹 KL不同，它影响相对 advantage。也可把 task advantage的 policy loss与显式 KL loss分开，两种梯度并不总等价，尤其当 KL项随 current policy更新且做 stop-gradient处理不同。 reference与行为 old policy角色不同。reference锚定长期能力，old policy是 rollout生产者。on-policy REINFORCE可以没有 PPO ratio，仍需要记录行为版本；若训练期间 policy已经变化，样本便逐渐 off-policy。 序列 KL随长度累积，长回答受到更大惩罚。token mean KL减少长度效应，却改变约束。policy loss若 sequence sum、KL token mean，两项相对强度随长度变化。 采样 log-ratio是正向 KL的 Monte Carlo项，单样本可以为负。完整词表 token KL非负但成本高。日志注明估计方式、采样分布和 reduction。 把 KL并入 reward后，组内 baseline会减去其他轨迹的 KL。所有轨迹同时高 KL时，相对项可能很小，绝对漂移仍大。独立监控 policy-reference KL，不能只看中心化 reward。

**数据分布、奖励噪声与方法边界。**

严格 REINFORCE期望要求轨迹来自当前 policy。实际系统采样一批再更新多个 minibatch，从第一次更新后就开始 off-policy。RLOO论文配方若使用 PPO-style ratio或只做一次更新，边界不同。 没有 ratio时复用旧轨迹会产生分布偏差。使用重要性 ratio可校正期望，完整序列 ratio方差很高；token ratio和 clip降低方差，引入 PPO式偏差。此时算法已接近 RLOO baseline加 PPO surrogate。 异步 rollout worker产生 policy lag。每条轨迹保存 producer version与 old log-prob。只用当前 policy重算分母，会把行为分布改写成未发生的概率。 top-p、top-k、温度与 grammar mask改变实际行为。模型原始 softmax log-prob不一定等于采样后分布。理论 ratio要对应行为支持，工程近似需明确。 teacher轨迹、replay成功样本和外部数据属于 off-policy。没有行为 log-prob时，更清楚的用法是 SFT replay。直接当 on-policy RLOO样本缺乏无偏依据。

policy lag按版本步数不够，需看 ratio分布、KL或 effective sample size。队列太长时，吞吐提高而有效更新下降。权重广播与训练 epoch联合调节。

**奖励噪声、全同组与长度偏置。**

reward噪声会同时进入当前回报和其他样本 baseline。若每次执行独立噪声方差为 $\tau^2$，advantage噪声包含 $\tau^2+\tau^2/(k-1)$。增大组降低 baseline噪声，不能消除当前轨迹噪声。 工具环境随机失败、judge随机性和测试不稳定都可能制造假 winner。重复执行、固定环境或对 reward取均值。环境故障应与模型失败分开。 全失败组没有方向。极难任务需要提高探索、部分 reward、teacher暖启动或更容易课程。反复采样全失败而不改变成功概率只消耗算力。 全成功组同样为零。若还想优化效率、过程与风格，必须加入能区分候选的 reward。保留原成功任务回归，防止共享更新遗忘。 长度偏置来自序列 sum、KL累积、reward设计与截断规则，不是 RLOO baseline单独决定。按成功轨迹更长、等长、更短分桶，比较 advantage与梯度。

内容反事实应保持正确性，增删冗余；再保持长度，修改关键事实。两组共同判断模型利用长度还是内容。

**与 REINFORCE、PPO、GRPO 的关系。**

RLOO 是 REINFORCE-style policy gradient加 leave-one-out Monte Carlo baseline。它不需要 learned critic，baseline只在同 prompt组内估计。REINFORCE无 baseline时方差更高，期望方向相同。 PPO增加 old-policy ratio、clip，通常还含 critic与 GAE。用 RLOO advantage替换 critic advantage、保留 clip后，是两种组件的组合。不能把所有带 RLOO baseline的实现都称为纯 REINFORCE。 GRPO与 RLOO同样依赖同 prompt多样本。去 std时，leave-in GRPO advantage与 RLOO只差缩放；标准 GRPO还做组方差归一。工程框架中的 token clip、KL与长度处理会进一步拉开差异。 PPO critic可跨 prompt泛化价值并提供时间步差异；RLOO每个 prompt都要多采样，且序列共享 advantage。critic失准时 RLOO避免 value偏差，组采样昂贵且全同组无信号。 公平比较固定 rollout token、独立 prompt、update token、KL、reward与评估。RLOO省 critic资源，额外组采样仍有成本。报告显存、吞吐与 wall-clock。

**数值手算与端到端验收。**

设 $k=4$，reward为 $(3,2,1,0)$。对第一条，baseline为 $(2+1+0)/3=1$，$A_1=2$；第二条 baseline为 $4/3$，$A_2=2/3$；第三条 baseline为 $5/3$，$A_3=-2/3$；第四条 baseline为 $2$，$A_4=-2$。优势和为零。 组均值为 $1.5$，leave-in中心化为 $(1.5,0.5,-0.5,-1.5)$，恰好是 RLOO的 $3/4$。手算验证 $(k-1)/k$关系。 若 reward全部加 10，优势不变；全部乘 2，优势乘 2。若实现额外 std normalization，缩放后应近似不变。这组不变量能识别 RLOO与 GRPO路径。 $k=2$、reward $(1,0)$ 时优势为 $(1,-1)$；leave-in为 $(0.5,-0.5)$。$k=1$ 必须报错或跳过，不能用 baseline零静默退化。 全同组 $(1,1,1,1)$ 优势全零。若加入 KL后各轨迹 KL不同，总 reward不再全同，会产生更新。日志应区分 task reward与 KL-shaped reward的全同率。 给第一条序列两个 token、第二条四个 token，手算 sequence sum与 mean。优势相同不表示回答贡献相同，最终 reduction决定长度权重。 若使用 ratio，加入正负 advantage四象限，验证 clip方向。若纯 on-policy无 ratio，确认 loss只含 $-A_i\log\pi$ 与 KL/entropy等明确辅助项。

**可证伪的实验。**

若声称 leave-one-out无偏，使用独立采样 toy bandit与相关 beam候选对照。前者平均梯度接近解析值，后者偏差揭示独立条件的重要性。 若声称大组降方差，固定总 rollout预算扫描 $k$，同时报告 baseline方差、独立 prompt数与最终质量。只看单 prompt方差会忽略覆盖损失。 若声称优于 GRPO，逐项对齐 std normalization、clip、KL、token归约和采样。只换算法名字不够。 若声称 KL控制漂移，用独立 current-policy采样或完整词表 KL验证，并报告能力。中心化 KL reward可能隐藏共同漂移。 若声称适合稀疏奖励，按初始成功率分桶。极难桶若全失败，无梯度就无法支持提升归因。记录有效组率。 若声称无长度偏置，提供长度反转与内容反事实，分别报告 token/sequence reduction。平均生成长度不能单独证明。

若声称 off-policy复用提高效率，报告 policy lag、ratio、effective sample size和质量。没有行为概率的 replay不纳入同一结论。 多种子、prompt-cluster区间与预先定义切片用于统计。最终测试不反复参与超参选择。

**端到端验收与恢复。**

rollout保存 prompt、group、producer、解码、token、old log-prob、reward分量、环境、EOS与截断。token IDs为训练权威，不能从清洗文本重建。 组测试覆盖 $k=1,2,4$、全同、线性平移缩放、噪声、不同长度与相关候选。每条有预期 baseline、advantage和 loss。 分布式 group统计必须跨完整组。group被拆到 worker后，先聚合 reward再计算 leave-one-out。改变分片结果不变。 恢复保存 policy、producer版本、rollout队列、optimizer、scheduler、随机状态、KL controller与 dataloader cursor。连续两步与保存恢复对齐。 训练日志记录 reward、baseline、advantage、全同率、有效组、长度、KL、ratio/clip、梯度、policy lag与独立 prompt数。均值之外给分位数。 生成评估使用当前 checkpoint重新采样，不复用旧 rollout。可执行任务、过程、能力、安全、多语言、长度、多样性与成本共同验收。

**部署与回流。**

上线反馈、工具成功与规则标签可以产生 pointwise或组 reward，但 RLOO训练仍需同 prompt多采样。线上单条日志不能自动提供 leave-one-out baseline，需重新 rollout或合理分组。 回流候选混合当前 policy、旧模型与探索策略时，行为分布不同。没有正确 ratio时，外部轨迹更适合 SFT或离线目标。标准 RLOO组保持同一 producer独立采样。 线上环境与 verifier版本化。系统故障退出 reward，模型失败保留。固定环境回归与近期真实环境并列。 回滚绑定模型、模板、解码、reward与工具配置。量化、合并 adapter后重新 rollout评估，旧 log-prob不可继承。 停止条件结合固定任务 reward、KL、能力、安全、长度与成本。训练 reward上升而独立指标退化时回滚或修 reward。

**结论与参考资料。**

RLOO 用同 prompt其他轨迹的平均回报作为 baseline，在条件独立采样与正确行为 log-prob下保留 REINFORCE期望梯度，并降低 baseline估计方差。它省去 critic，把成本转移到每 prompt多次 rollout。 leave-one-out排除自身 reward，避免 action-dependent baseline的直接相关。组内优势仍彼此相关，group是更合理的统计单位。组大小提高 baseline精度，同时减少固定预算下的 prompt覆盖。 与 GRPO相比，去 std时两者中心化方向只差缩放；标准差归一、clip、KL与归约才是实践差异的大头。与 PPO相比，RLOO缺少 learned value与逐时间步 credit，优势是实现和资源更简单。 序列 reward广播、全同组、奖励噪声、长度与 off-policy复用决定方法边界。无偏证明不能覆盖相关解码、组依赖 reward或未知行为策略。实验必须主动构造这些反例。

可信复现同时保留 token级 rollout、group统计、reference/old policy版本和独立生成评估。公式短并不意味着训练语义自动统一，最终 reduction与数据流必须写全。 **20.1 方差最优 baseline 与样本均值.** 只依赖状态 $x$ 的 baseline 不改变 score-function 梯度期望。最小化梯度二阶矩时，最优 baseline 还要按 score gradient 范数加权：

### 6.3. 方差最优基线与组内相关

$$
b^*(x)=
\frac{\mathbb E[R\|\nabla\log\pi(y|x)\|^2\mid x]}
{\mathbb E[\|\nabla\log\pi(y|x)\|^2\mid x]}.
$$

只有 reward与 score norm关系较弱时，它接近条件均值。RLOO用其他样本 reward平均估计 $\mathbb E[R|x]$，实现简单、无需 critic，却不保证达到理论最小方差。 learned critic可以利用跨 prompt特征逼近更复杂 baseline，拟合误差又会增加偏差与训练成本。RLOO选择 Monte Carlo组均值，是把模型误差换成采样误差。哪一种更好取决于 critic质量与 rollout预算。 若组内回答长度差异大，score norm通常随长度变化，未加权 reward均值离方差最优 baseline更远。按长度或 score norm加权可能降方差，同时 baseline权重若依赖当前轨迹自身会破坏无偏条件。权重只能从其他轨迹或独立信息构造。 可以在 toy policy上枚举动作，算出真实最优 baseline、条件 reward均值和 RLOO有限样本分布。比较梯度方差，验证 leave-one-out无偏不等于方差最优。 **20.2 相关候选怎样破坏证明.**

独立温度采样给定 prompt后随机种子互不共享，满足常见证明条件。beam search候选共享前缀竞争与剪枝，某一候选出现会改变另一候选集合，reward相关来自生成机制。 diverse beam search还显式惩罚候选相似度，其他轨迹的存在进入当前轨迹概率。此时 $b_{-i}$ 与 $y_i$ 条件相关，baseline项期望未必为零。仍可把它当启发式相对目标，不能继续宣称标准 REINFORCE无偏。 best-of-n后只保留部分候选也引入选择。若组由预筛后的 top 与 bottom组成，样本分布条件于 reward model，行为概率需要包含筛选事件。直接使用原 policy log-prob不完整。 去重过滤同样产生依赖。重复回答被删除后，组大小与组成随当前样本变化。训练可使用去重组，但无偏证明的随机对象已改变。保存过滤前组，评估影响。

组 reward若包含相对排名，$R_j$ 由整组决定。leave-out baseline排除 $R_i$，其他 $R_j$ 仍可能因 $y_i$ 改变。使用绝对 verifier reward更接近独立假设。 **20.3 Baseline 相关性与协方差.** 梯度方差不只由 $\operatorname{Var}(A_i)$ 决定，还包含 advantage与 score gradient的协方差。同一 reward方差下，不同策略参数化可有不同梯度方差。只报告 reward标准差不足以评价 estimator。 可记录 per-sample gradient norm近似、组内梯度余弦和 batch gradient方差。全参数 per-sample梯度昂贵，可在输出层、adapter或随机投影上估计。 组内优势和为零，但共享 prompt前缀上的梯度可能高度相似，正负项相互抵消。候选只在末尾不同，前缀 token的大量计算贡献很少净更新。语义与步骤多样性比字符串数量更重要。 反过来，候选完全不同，baseline更稳定但梯度方向方差大。增加 $k$ 是否有效，需要同时看 reward估计和梯度多样性。 **20.4 KL-shaped reward 的留一效应.** 令总 reward $R_i=r_i^{task}-\beta K_i$。RLOO advantage为

$$
A_i=(r_i^{task}-\bar r_{-i})
-\beta(K_i-\bar K_{-i}).
$$

KL只通过相对组均值进入 policy梯度。如果整组 $K_i$ 同时增加相同常数，中心化项不变；策略可能整体远离 reference而 RLOO KL advantage看不到公共漂移。 因此通常仍需要监控或显式加入绝对 KL penalty/controller。把 KL仅放进中心化 reward并不等价于全局 trust region。固定 prompt组内相对约束与跨 prompt整体漂移是两个问题。 若 task reward与 KL负相关，正确长推理既得高任务分又付大 KL，$\beta$ 决定组内排序。质量—KL前沿应跨多个系数比较，不用单点总 reward判断。 reference对某类正确答案概率极低时，KL惩罚可能压制探索突破。更强 SFT起点、rolling reference或较小 $\beta$可缓解，同时改变长期约束。每种选择都需能力回归。 **20.5 Reward 标度与任务权重.** RLOO保留 reward线性尺度。把某任务 reward乘十，该任务 advantage与梯度也乘十。多任务 reward单位不同会直接决定训练权重。

先在任务内归一化 reward可以平衡尺度，估计均值/方差的分布又随训练变化。固定 normalization统计更可比，在线更新更适应当前 policy。保存状态与版本。 业务权重最好显式乘在 group loss上，而不是隐含在 verifier分数单位里。这样任务价值与正确性尺度分开。权重极端时报告有效样本量与 gradient clip率。 reward clipping限制离群影响，也压平真正的大质量差。rank transform只保留组内顺序。两种都改变原始 RLOO目标，使用反例检验。 **20.6 稀疏二元奖励的闭式结构.** 组有 $m$ 个成功、$k-m$ 个失败。对成功轨迹，其他样本均值为 $(m-1)/(k-1)$，所以

$$
A_{success}=1-\frac{m-1}{k-1}=\frac{k-m}{k-1}.
$$

对失败轨迹，baseline为 $m/(k-1)$，

$$
A_{failure}=-\frac{m}{k-1}.
$$

唯一成功时 $A=1$，失败各为 $-1/(k-1)$；唯一失败时反向。与 std-normalized GRPO的少数类幅度约 $\sqrt{k-1}$ 不同，RLOO单样本幅度有界于 1。 所有 advantage和为零，成功总正权与失败总负权抵消。增大 $k$ 不会让唯一成功幅度超过 1，但会增加更多小负样本。最终 token reduction仍可能让长失败占更多参数梯度。 二元 reward整体尺度固定，使 RLOO不同 prompt权重更可比；有效组概率仍依赖成功率。极易与极难任务全同，训练关注中间难度。 给 reward加入部分分数后，闭式结构消失，更多组产生非零信号。部分分必须可靠，微小 verifier噪声也会进入 advantage。 **20.7 长度偏置的精确拆分.** 第一层来自 policy loss：sequence sum让长轨迹有更多 score项；sequence mean使每 token系数随长度反比。第二层来自 KL：序列 KL通常随长度累积。第三层来自 reward：长推理可能更易成功或更易超时。

第四层来自采样与截断：固定 max tokens让长轨迹更容易被截断得零分。第五层来自 group：长短候选是否在同 prompt内出现，决定 baseline比较。任何长度结论都要说明五层。 构造 2×2 反事实：正确/错误与长/短正交。保持最终答案，增删冗余；保持长度，替换关键步骤。按层观察 reward、advantage、score norm、KL和最终梯度。 EOS概率单独记录。模型可能通过更早 EOS降低 KL和序列梯度，却损失完整性。自然结束与截断区分。 **20.8 Off-policy 重要性采样.** 完整轨迹重要性比为

长序列乘积方差极高。log空间可避免数值下溢，不能解决统计方差。token-level ratio与 clipping是实践折中。 若使用 trajectory ratio乘整个 RLOO advantage，少数极端权重主导；self-normalized importance sampling降低方差、引入偏差。报告 effective sample size。 PPO clip把 RLOO advantage放进 surrogate，形成 RLOO-PPO混合。clip后不再是严格无偏 REINFORCE，但通常更稳定。结论要使用准确配方名与公式。 纯 RLOO若每批只更新一次并立即重新采样，最接近 on-policy，生成成本最高。多 epoch提高利用率，逐渐转向 off-policy。画质量对 rollout token而非仅 update step。 **20.9 有限样本方差的数值实验.** 构造三动作 bandit，policy概率为 $(0.5,0.3,0.2)$，reward为 $(1,0.4,-0.2)$。解析目标 $J=0.58$，可以枚举 score-function真梯度。分别用无 baseline、真实均值 baseline和 $k=2,4,8$ 的 RLOO重复采样，比较梯度均值与协方差。

独立采样下，各估计均值应靠近解析梯度；RLOO方差随 $k$ 下降并趋近使用真实均值 baseline。若平均梯度长期偏移，检查 baseline是否含当前 reward、采样是否相关或实现是否让 advantage参与梯度。 再把采样改成“无放回选择动作”，组内候选相关。leave-one-out baseline不再与当前动作条件独立，实验可直接测出偏差。这个反例比口头说 beam search可能有问题更清楚。 给 reward加入独立高斯噪声，验证增大 $k$只降低 baseline噪声，当前 reward噪声仍在。重复评估同一轨迹后取均值，则两部分都会降低，成本也增加。 将 reward整体加 10，梯度样本逐次完全不变；乘 10，梯度乘 10。若使用 Adam，一步参数变化可能因自适应归一化不严格乘十，但 loss层不变量应成立。 **20.10 Reward 攻击与错误信号.**

数学最终答案 verifier可能奖励猜测。正确数字配错误推导得满分，近乎正确但末步笔误得零。RLOO会把前者作为组内 winner提高整条轨迹。过程评估用于揭露。 代码公开测试可被硬编码、超时或环境漏洞利用。隐藏测试、资源限制和静态安全形成独立检查。训练测试与最终测试隔离。 格式 reward容易优化。若正确性和格式简单相加，模型可能通过固定模板获得相对优势。用正确性门控格式分，或分别报告 reward分量。权重改变会直接改变 RLOO advantage。 judge model可能偏爱长度、位置和自身风格。组内候选随机展示、左右交换、多 judge与人评校准。回答中的提示注入也要进入对抗集。

环境随机失败会制造假 loser。工具、网络或沙箱错误退出训练 reward，模型自身错误保留。环境版本与随机种子写入轨迹。 reward更新后，旧轨迹分数若重算，会改变当时训练数据；若不重算，新旧组使用不同尺子。最稳妥是 reward版本绑定 rollout，升级后开始新数据版本并保留 anchor对照。 **20.11 Group 内的多样性与覆盖.** RLOO baseline只有在组内 reward提供信息时有效。多个候选文本不同但最终答案和推理路径相同，组采样成本没有换来新方向。按最终答案、步骤、工具动作与语义簇统计。 温度提高多样性，也降低平均质量。选择使有效组率与任务成功兼顾的区域。只追求最大熵可能产生大量无意义失败，全同率下降却学习价值不高。

混合解码策略会让组内样本来自不同行为分布。纯 on-policy证明要求同一 policy分布；若温度不同，每条轨迹记录自己的 $\mu$。组 reward仍可比较，策略梯度需校正行为概率。 group去重后重新采样直到满 $k$，最终分布条件于唯一性。它提升表面多样性，改变概率。报告去重策略，并在无需严格无偏的启发式目标与理论 estimator之间划清界限。 固定总生成预算，比较更多 prompt小组与少量 prompt大组。最终评估按独立 prompt，不把轨迹数当样本量。不同难度桶可能有不同最佳 $k$。 **20.12 Prompt 课程与全同组.** 初始成功率估计来自历史 rollout。按 $p$ 预测有效组概率，优先采中间题能提高训练效率。仍保留线上分布与极难/极易回归，否则模型只优化边界题。

极难题长期全失败，增加 replay次数没有梯度。teacher SFT、部分 reward、拆解子任务或提高探索先创造成功。第一条偶然成功出现后，RLOO给它最大正 advantage之一，应复验 verifier。 极易题全成功，其他任务更新可能让它遗忘。周期性回归而非持续大量训练更省预算。若要优化效率，新增能区分候选的 reward。 自适应 $k$ 根据首批 reward追加采样。追加规则导致困难 prompt消耗更多 token，但若 group loss按 prompt mean，它们未必获得更大梯度权重。计算预算和目标权重应分别定义。 prompt难度随 policy变化。固定初始桶便于解释学习轨迹，动态桶便于采样效率。两套标签同时保存，防止样本迁移造成曲线错觉。 **20.13 分布式 Group 统计.** 一个 group跨 worker时，每条 baseline需要其他 $k-1$ 个 reward。先按 group ID聚合 reward，再广播 baseline。worker本地 leave-one-out会把同组拆成多个错误小组。

packing、长度排序和过滤后，group ID不能依赖连续位置。显式保存轨迹 ID、prompt ID与 group index。单元测试随机打乱 batch顺序，结果应不变。 某条 reward异常或序列无效被过滤后，剩余组的 $k$ 改变。重新计算 baseline；使用过滤前 baseline会让已删除 reward影响梯度。若剩余仅一条，跳过该组。 worker尾批 group不完整时，缓存到下一批或全局组装。不能用 padding伪造 reward零轨迹。日志统计 sampled group、valid group与 skipped group。 loss归约按 group等权时，各 worker聚合 group loss sum与 group count；按trajectory等权时聚合 trajectory count；按token等权则聚合有效 token。三种分母不可混用。 **20.14 异步系统与 Policy Lag.** rollout worker异步获取权重，trainer消费队列。每条轨迹保存 producer hash、生成时间与 old log-prob。队列越长，lag通常越大。 纯 RLOO没有 ratio时，对 lag十分敏感。可以拒绝过旧样本、减小队列、提高广播频率或加入重要性校正。拒绝数据会损失生成算力，需要统计 discard rate。

使用 PPO ratio与 clip后，lag大的 token更易越界，有效样本量下降。按 lag画 ratio分位数、clip fraction与实际梯度。版本步数只是代理，分布距离更可靠。 producer使用量化、speculative decoding或不同 kernel时，实际采样分布可能与 trainer重算不同。manifest保存服务精度与采样实现。固定 prompt对比 token频率与 log-prob。 old policy、reference和current policy是三个对象。old给行为概率，reference给长期 KL，current接受更新。日志分别写 hash，不能用“base model”一个字段混合。 **20.15 完整训练手算.** 设三条轨迹 reward $(2,1,-1)$，长度 $(2,4,2)$。RLOO优势：第一条 baseline为 $0$，$A_1=2$；第二条 baseline为 $0.5$，$A_2=0.5$；第三条 baseline为 $1.5$，$A_3=-2.5$，和为零。 若 sequence-sum REINFORCE，假设每 token log-prob梯度标量代理都为 1，则三条贡献与 $A_iT_i$ 成比例，分别 $4,2,-5$，不再相互抵消。长度通过 score sum进入梯度。 sequence-mean时贡献近似 $2,0.5,-2.5$，和恢复零仅因为假设每 token方向相同。真实网络 Jacobian不同，advantage和零不意味着参数梯度和零。

加入 task reward相同而 KL分别 $(0.1,0.4,0.2)$，$\beta=1$ 后总 reward改变。重新计算 leave-one-out，而不能先用 task advantage再逐样本减 KL，除非目标明确采用分离 penalty。 若使用 PPO clip，给每条选一个 ratio并做四象限手算。RLOO只定义 advantage，surrogate如何使用它由训练算法决定。教学代码与配置必须一致。 **20.16 估计器与优化器的交互.** 无偏梯度估计不保证有限步参数无偏。Adam、gradient clip、学习率 schedule和 early stopping都会非线性处理随机梯度。理论无偏主要说明 baseline不改变一阶期望方向。 reward尺度乘十时，SGD更新近似乘十，Adam可能部分抵消；clip频繁触发时完全不同。比较 reward尺度要报告裁剪率与 optimizer状态。 少数高 reward轨迹可污染 Adam二阶矩，后续许多 step步长改变。即使 RLOO baseline减均值，离群差值仍可能大。稳健 reward或权重上限需要消融。

组内正负梯度在一个 batch聚合，与分成多个 microbatch后分别 clip不等价。global clip应在完整有效 batch梯度累积后执行。否则切分改变目标。 混合精度 overflow跳过 step时，scheduler与 producer更新节奏可能错位。记录成功 optimizer update、处理 rollout与权重广播版本。 **20.17 统计区间与多种子.** 同 group轨迹相关，按 group bootstrap。prompt来自模板或用户簇时，再按更高层 cluster。多次采样同 prompt不能当独立题。 算法比较使用相同 prompt配对，bootstrap每个 prompt的指标差。reward、长度、成功与成本都给区间。tie与环境异常单独统计。 多随机种子按生成 token和 wall-clock对齐。首次成功轨迹出现时间会造成路径依赖，单次曲线可能非常乐观或悲观。 主要切片预先确定：初始难度、长度、任务、语言、风险、producer lag。查看大量切片后只报告最好者会产生选择偏差。

验证集频繁选择 checkpoint会过拟合。开发集负责调参，最终测试一次性使用。固定 anchor用于训练监控，不承担最终结论。 **20.18 可执行发布清单.** 数学不变量包括 baseline 排除自己、优势和为零、平移不变、缩放关系、$k=1$ 处理、打乱顺序不变与过滤后重算。 随后跑 token不变量：padding不变、prompt与观察 mask、EOS、截断、左右 padding、逐条与拼接前向一致。old/reference/current token完全相同。 再跑分布式不变量：group跨 worker、microbatch切分、tail batch、不同 world size与恢复。loss和一步更新在容差内一致。 行为评估覆盖固定 verifier 任务、未见 prompt、过程、能力、安全、多语言、长度、多样性、工具环境与成本，并在最终服务栈上接受测试。 每次改 tokenizer、模板、reward、producer或 reduction，固定探针重新运行。探针通过说明数学对象一致，真实任务决定对象是否有用。 **20.19 部署后的反馈闭环.**

线上单条 thumbs反馈可训练 pointwise方法，不能直接形成 RLOO组。要为同 prompt重新采样候选并用可靠 reward，或将历史反馈作为 SFT/其他离线信号。 只对失败 prompt重新 rollout，会改变训练 prompt分布。按线上权重评估，并保留随机流量样本。失败挖掘提高效率，不代表总体目标。 当前 policy很少生成的模式逐渐离开数据。混入旧模型与探索候选可保覆盖，但属于多行为分布，需要正确处理 log-prob。没有校正时用于监督数据更清楚。 线上工具和环境变化会改变 reward。固定环境回归与近期环境评估并列。模型、verifier与环境各自版本化。 回滚条件包含严重安全、关键成功率、事实退化、成本与延迟。模型、模板、解码、reward和工具作为整套版本回滚。 **20.20 最终边界.**

RLOO解决的是 Monte Carlo policy gradient的 baseline问题，没有解决奖励正确性、时间信用、探索成功与 off-policy复用。它让 critic变得可选，同时要求每个 prompt付出多轨迹成本。 无偏性是条件命题：同 prompt独立采样、baseline排除当前动作、行为 log-prob正确、reward不依赖整组且 advantage stop-gradient。条件改变，结论也改变。 组大小降低 baseline方差并提高找到差异的机会，固定预算下减少 prompt覆盖。reward噪声、长度与归约会进入实际参数梯度。最优配方只能由目标分布与成本共同确定。 把这些条件、公式、数据版本和反例写全后，RLOO的“回到 REINFORCE 基础”才有准确含义：回到一个可审计的 Monte Carlo估计器，而非回到没有工程边界的简单训练。 **20.21 Reference、Old 与 Current 三个坐标.**

采样时 producer 是 old policy，长期锚点是 reference，接受更新的是 current policy。纯 on-policy一步更新开始时 current与 old相同，之后便分开；reference通常来自 SFT并长期固定。 若无 PPO ratio，RLOO score gradient直接使用 current对 old样本的 log-prob，严格性随 policy lag下降。若有 ratio，分母必须是各轨迹真实 old log-prob。reference不能替代行为分母。 KL reward使用 current/reference log-ratio，importance weight使用 current/old ratio。两个 ratio看似相近，含义和更新时机不同。日志分别记录，避免缓存键错用。 rolling reference会控制局部漂移，固定 reference控制总漂移。多轮 rolling后，当前模型可能离初始 SFT很远。评估同时计算对当前 reference和初始 reference的 KL。 reference cache绑定 tokenizer、模板、EOS、截断、精度与 checkpoint。old log-prob还绑定实际解码温度和行为 mask。任一版本变化都失效。 **20.22 Reward 分项与 Pareto 取舍.** 任务 reward常含正确性、格式、过程、效率、安全和工具成本。简单加权和定义一个标量，再由 RLOO组内比较。权重改变 winner与 baseline，属于任务定义。

正确性可设硬门控：未通过时，格式与风格不提供正分。这样避免模型靠易学格式领先。通过正确性后，再比较效率与表达。 多目标存在 Pareto前沿。更完整的解释可能更长，成本更高；更安全的回答可能减少帮助性。总 reward隐藏取舍，评估同时展示各分量。 组内所有候选在某分量相同时，该分量中心化后不产生梯度。想优化它，需要采样产生差异或改变任务。提高常数权重没有作用。 reward model分数随 policy分布移动会失准。固定 anchor、对抗样本和人评校准。训练与评估使用同一 RM时，结论限定为 RM一致性。 **20.23 长度、KL 与成功率的三方反例.**

长回答更可能包含正确推理，也累积更多 KL与 score项。短回答成本低、易早停，可能猜中。总 reward如何组合成功与长度，决定策略方向。 构造四条：短正确、长正确、短错误、长错误。分别计算 task reward、KL、advantage和最终梯度。若长正确因 KL被排到短错误以下，$\beta$ 或 reward优先级不合理。 再对正确长回答删除冗余，保持结论与必要步骤；对短正确补必要解释。内容匹配反事实区分效率与完整性。单纯按 token数惩罚可能压低必要推理。 截断轨迹的 task reward与 KL都只看到前缀。给它零分并累积长前缀 KL，会产生强负 advantage，鼓励避免长链。记录截断原因并单独评估。 EOS漏算使终止动作不受梯度，伪造 EOS则把 max-length当自然结束。生成长度问题先核对 mask，再解释算法。 **20.24 过程信用的局部替代.**

若每步有 verifier reward $r_t$，可定义 reward-to-go $G_t=\sum_{u\ge t}r_u$，并为每个时间步构造跨轨迹 baseline。不同轨迹步骤难以对齐，简单按位置比较可能把不同语义阶段混合。 按环境状态或子目标对齐更合理，成本高。工具任务可在共享状态下比较下一动作；数学自然语言步骤边界更模糊。没有可靠对齐时，序列 RLOO仍更清楚。 将步骤 reward累加成序列总分，只增加 reward密度，不提供 token级 credit。文档应区分“更密 reward”和“更细 advantage”。 局部 verifier也可能错误奖励形式化步骤。使用同义改写、步骤合并拆分与错误关键等式反例。过程分数不能代替最终正确性。 **20.25 参数化与优化空间.** LoRA、全参数和不同冻结层能实现的策略集合不同。RLOO估计器无偏针对给定参数化的 policy gradient，不保证有限子空间达到同一最优策略。

低 rank可能主要调整格式与常见模式，难以改变深层推理。比较训练 reward、未见任务与参数梯度分布。扩大 rank也会增加遗忘风险。 共享参数让一个 prompt更新其他 prompt。某组优势为零不表示该 prompt行为固定，其他组梯度仍会改变它。全同组任务需要回归监控。 梯度冲突可按任务估计余弦。长期负相关提示采样权重或参数隔离问题。总体 reward上升可能遮住小域退化。 **20.26 模型合并、量化与服务差异.** 训练后 adapter合并会改变 logits，原 rollout的 old log-prob与 KL不再适用。合并模型作为新 policy重新生成评估。 量化服务产生的行为分布可能不同于高精度 trainer。若 rollout在线服务量化模型，old log-prob应来自相同分布；用高精度重算是近似，需要测量差异。

speculative decoding在严格保持目标分布时可等价，自定义接受规则可能改变。固定 prompt统计 token频率与保存的 log-prob，验证服务实现。 stop sequence、最大长度与工具解析都属于 policy环境。发布配置变化会改变 reward和长度。最终服务栈重新跑全部任务。 **20.27 失败症状的定位顺序.** 全同率高、KL低、reward不升时，先查成功概率与采样多样性；没有信号时调学习率无效。创造有效组比增加更新步更重要。 reward升、KL高、能力下降时，检查 reward窄化与正则。SFT replay、更强 KL或更广任务可缓解，分别做预算对齐消融。 ratio极端或纯 RLOO训练震荡时，查 producer lag、old log-prob、温度与 token对齐。第一步就异常通常是数据流错误，逐步变大更像 policy更新。

生成变长时，拆 task reward、KL、token reduction与截断；生成变短时查 EOS、overlong penalty与猜答案策略。不要把长度变化自动称为推理增强或退化。 某语言或任务崩坏时，查 sampler权重、reference能力、reward覆盖和共享梯度。总体均值无法定位。 多种子差异大时，查看首次成功轨迹、极端 reward与 optimizer状态。固定 seed只隐藏不稳定，不能证明配方可靠。 **20.28 最终实验记录.** 实验表先列 estimator：$k$、baseline、reward/advantage normalization、sequence/token归约、on/off-policy、ratio/clip与 KL。没有这些字段，RLOO名称不足以复现。 数据表列独立 prompt、group、trajectory、有效组、全同率、长度、截断、任务、语言、producer与 verifier。训练行数不等于独立证据。 预算表列 rollout token、update token、PPO epoch、discard、wall-clock、显存和 verifier成本。RLOO省 critic，但 rollout与执行可能主导总成本。 结果表列固定 task reward、独立生成、过程、能力、安全、多语言、长度、多样性、KL和成本，并给 prompt-cluster区间与多种子。

案例表覆盖全失败、唯一成功、reward攻击、长短反例、policy lag、环境故障和回滚。成功案例与失败案例同样保留。 结论将理论、经验与部署分开。无偏性来自条件证明；某模型胜率来自当前实验；线上长期效果仍由分布与反馈闭环决定。 **20.29 一组最终判据.** 数学上，leave-one-out必须排除自身，优势和为零，reward平移不变，$k=1$明确处理。独立 toy环境平均梯度接近解析值。 实现上，token、mask、EOS、group、producer log-prob、reference和归约可复算。不同切分与恢复得到相同更新。 数据上，reward可靠、环境故障分离、全同与有效组可见、prompt覆盖符合目标。相关候选与筛选偏差明确记录。 评估上，固定 rollout指标能迁移到当前 policy自由生成，关键能力与风险不回退，长度与成本在可接受范围。

部署上，最终服务版本通过回归，监控和回滚可执行，回流数据不会把未知行为策略伪装成 on-policy。 五层同时通过时，RLOO 的简洁才真正成立：不用训练 critic，也没有把价值估计、采样分布和信用问题藏起来。 **20.30 用条件期望把无偏性写完整.** 固定一个 prompt $x$，从同一行为策略独立采样 $K$ 条轨迹 $y_1,\ldots,y_K$。记 $R_i=R(x,y_i)$，分数函数为 $g_i=\nabla_\theta\log\pi_\theta(y_i\mid x)$，留一基线为

$$
b_{-i}=\frac{1}{K-1}\sum_{j\ne i}R_j.
$$

证明的关键在于 $b_{-i}$ 在给定 $x$ 后与当前动作 $y_i$ 条件独立。于是

### 6.5. 无偏性的条件期望证明

$$
\mathbb E[b_{-i}g_i\mid x]
=\mathbb E[b_{-i}\mid x]\,\mathbb E[g_i\mid x]
=\mathbb E[b_{-i}\mid x]\nabla_\theta\sum_y\pi_\theta(y\mid x)=0.
$$

因此

$$
\mathbb E[(R_i-b_{-i})g_i\mid x]
=\mathbb E[R_i g_i\mid x],
$$

再对 prompt 分布取期望，便得到原始 REINFORCE 梯度。这里真正需要的是「基线不依赖当前采样动作」，基线是否精确等于价值函数并不影响无偏性。价值函数的作用是减小方差；把它训练得更准通常有益，却不是梯度成立的前提。

这个证明也指出了实现中最容易被忽略的边界。若候选先由当前模型生成，再根据整组最高分、重复率或格式一致性筛选，保留下来的 $b_{-i}$ 已经通过选择事件依赖 $y_i$；若 reward 本身包含组内排名，其他候选的分数也会随 $y_i$ 改变。此时上面的条件独立分解不能直接使用。算法未必完全不可用，但它优化的是经过筛选或相对奖励重新定义后的目标，不能继续把无偏性当作现成结论。

还要区分两种「和为零」。同一组的标量优势满足 $\sum_i(R_i-b_{-i})=0$，这是确定性代数恒等式；参数梯度 $\sum_i(R_i-b_{-i})g_i$ 通常不为零，因为每条轨迹的 $g_i$ 不同。若实现测得整组参数梯度也恒为零，往往是把同一个平均 log-prob 错误广播给了所有候选，或在归约时丢失了候选维度。 **20.31 相关采样时协方差从哪里进入.** 独立采样只是理想条件。实际系统可能让候选共享随机前缀、复用 speculative decoding 的草稿、采用无放回搜索，或从同一棵搜索树分叉。此时 $R_i$ 与 $R_j$ 相关，留一平均仍可计算，却不再自动与当前分数函数独立。 把单条估计写成 $Z_i=(R_i-b_{-i})g_i$，组平均方差为

### 6.6. 有效样本量与相关性

$$
\operatorname{Var}\!\left(\frac1K\sum_i Z_i\right)
=\frac{1}{K^2}\left(\sum_i\operatorname{Var}(Z_i)+2\sum_{i<j}\operatorname{Cov}(Z_i,Z_j)\right).
$$

若各项方差近似为 $\sigma_Z^2$、任意两项相关系数近似为 $\rho_Z$，则

$$
\operatorname{Var}(\bar Z)\approx\frac{\sigma_Z^2}{K}\bigl[1+(K-1)\rho_Z\bigr].
$$

独立时方差按 $1/K$ 下降；正相关时收益很快饱和。例如 $K=16,\rho_Z=0.2$，相对于一条样本的方差约为 $0.25\sigma_Z^2$，有效样本量只有约四条，而不是十六条。继续扩组会增加解码成本，却几乎不增加统计信息。负相关采样可能更高效，但若负相关来自人为强制候选互异，目标分布也可能随之改变。

相关性是否引入偏差，要看联合采样机制。若先采公共随机变量 $u$，再令候选在给定 $u,x$ 后独立，而且基线可以条件于 $u$，则应在证明中把 $u$ 纳入条件；若当前候选决定其他候选如何展开，例如发现一个正确答案后停止其余搜索，联合机制直接依赖 $y_i$，普通证明便断开了。最稳妥的诊断是构造可枚举的小策略，精确求出真实梯度，再对系统实际 sampler 重复模拟，检查经验均值是否收敛到解析值。

组内 reward 方差也不能单独代表有效信号。两组可能具有相同的 reward 标准差，一组差异来自真正的解题路径，另一组差异来自 verifier 抖动；前者的梯度方向可复现，后者在重打分后翻转。可以对同一批轨迹重复运行 verifier，分解轨迹间方差与同轨迹重评分差异，再决定扩大组、改进奖励还是增加独立 prompt。 **20.32 Prompt 加权决定了训练目标.** RLOO 先在 prompt 内构造相对优势，再把不同 prompt 的梯度聚合。假设第 $m$ 个 prompt 有 $K_m$ 条有效轨迹，常见的两种归约是

$$
\hat g_{\text{prompt}}=\frac1M\sum_{m=1}^{M}\frac1{K_m}\sum_{i=1}^{K_m}Z_{mi},
$$

与

$$
\hat g_{\text{traj}}=\frac{1}{\sum_mK_m}\sum_{m=1}^{M}\sum_{i=1}^{K_m}Z_{mi}.
$$

当所有 $K_m$ 相等时二者一致；发生超时、过滤和环境失败后，它们对应不同目标。前者让每个 prompt 权重相同，后者让保留轨迹较多的 prompt 权重更大。若困难任务更容易超时，按轨迹平均会悄悄降低困难任务权重，即便采样 prompt 时原本完全均匀。

过滤还可能让 $K_m=1$。留一基线在这一组没有定义，直接把分母钳到一会制造虚假的零基线；复制唯一轨迹则制造重复样本。可选处理包括丢弃该组并记录选择偏差、为它使用跨批次基线，或补采至至少两条。三种做法优化的统计对象不同，应通过失败率和 prompt 类型分布说明代价。

若 prompt 本身按课程难度或数据源带权采样，目标为 $J(\theta)=\mathbb E_{x\sim q}[R]$。训练想逼近另一分布 $p(x)$ 时，需要 prompt 级权重 $p(x)/q(x)$；它与轨迹级 importance ratio 处在不同层级。前者修正问题出现频率，后者修正给定问题后的答案分布。把两者混成一个 clip ratio，会同时改变课程目标和策略更新。

一个直观例子是两个题域：代数题每组八条，代码题因环境昂贵每组只有两条。按轨迹平均时代数天然获得四倍权重；按 prompt 平均时两域等权。如果线上流量确实是四比一，前者可能符合部署目标；如果只是代码执行超时造成样本减少，前者是在奖励基础设施更稳定的题域。选择哪种归约不能由张量形状顺手决定。 **20.33 Token 归约改变了长度偏好.** 序列回报 $A_i$ 广播到每个生成 token 后，至少存在三种常见损失：

$$
L_{\text{sum}}=-\frac1K\sum_i A_i\sum_{t=1}^{T_i}\log\pi_\theta(a_{it}\mid s_{it}),
$$

$$
L_{\text{seq}}=-\frac1K\sum_i A_i\frac1{T_i}\sum_{t=1}^{T_i}\log\pi_\theta(a_{it}\mid s_{it}),
$$

$$
L_{\text{token}}=-\frac{\sum_iA_i\sum_t\log\pi_\theta(a_{it}\mid s_{it})}{\sum_iT_i}.
$$

第一式是标准序列 score function 的直接形式，长轨迹包含更多动作项，因此梯度范数通常更大。第二式先对每条序列取平均，让每条候选的总权重接近一致，却不再等于原始序列回报目标的无偏梯度。第三式让每个 token 权重一致，长序列仍贡献更多项，但整批分母随长度组成变化。三者都可以训练，含义却不能互换。

设同组两条正确轨迹的优势均为一，长度分别为十和一百。若各 token 分数梯度方向近似同向，求和归约会让长轨迹贡献约十倍；序列平均使二者接近等权；token 全局平均还会让其他组的长度影响当前组尺度。若长轨迹只是冗余，求和会奖励啰嗦；若长轨迹包含不可省略的推理动作，序列平均又可能低估这些动作的联合概率变化。

长度问题不能只靠给 reward 加一个线性惩罚解决，因为 reward 长度项和梯度归约作用位置不同。前者改变候选之间的优势排序，后者改变同一优势如何分配到参数更新。二者同时存在时可能重复惩罚：较长候选先得到更低优势，又因序列平均失去动作数贡献。验收实验应交叉比较 reward 是否含长度项与三种归约，观察正确率、有效推理步数、冗余率和截断率，而不是只看平均 token 数。

token 级 PPO ratio 还会引入另一层差别。将每个 token 的 ratio 分别裁剪，再乘同一个序列优势，得到的是局部受限更新；先把 log-ratio 沿序列求和形成轨迹 ratio，长序列的乘积更容易极端。前者更稳定，却没有严格等价于整条轨迹 importance sampling。文档与实验必须写明 ratio 的层级，否则同名「RLOO+PPO」可能是不同估计器。 **20.34 稀疏成功下的信号概率.** 对二元 reward，设单条轨迹成功概率为 $p$。一组全部同值的概率为

$$
P_{\text{flat}}=p^K+(1-p)^K,
$$

至少同时出现一个成功和一个失败的概率为

$$
P_{\text{signal}}=1-p^K-(1-p)^K.
$$

这给出了组大小最直接的下界依据。若 $p=0.01$、$K=8$，有效组概率约为 $7.7\%$；即便每个 prompt 采八条，九成以上的组仍不给二元组内比较提供信号。把 $K$ 提到六十四，有效组概率约为 $47.4\%$，但 rollout 成本增长八倍。此时引入更密集且可靠的过程奖励、改进初始化或调整题目难度，往往比盲目扩组更有效。

当 $p$ 接近一时情况对称：模型已经掌握任务，组内全成功也会让优势归零。全成功不代表没有提升空间，它只说明当前 reward 分辨不出答案之间的效率、鲁棒性或表达差异。若再加入可验证的次级指标，必须确认它与真正目标一致，否则训练会在正确率饱和后专门钻次级评分的漏洞。 给定总 rollout 预算 $B=MK$，有效组的期望数为

$$
M_{\text{eff}}=\frac{B}{K}\left[1-p^K-(1-p)^K\right].
$$

增大 $K$ 一方面提高每组出现差异的概率，另一方面减少独立 prompt 数。对极低成功率，$P_{\text{signal}}\approx Kp$，于是 $M_{\text{eff}}\approx Bp$，一阶近似下扩组并不会增加有效组总数，只会改变每个有效组内候选构成。选择 $K$ 还应考虑并行效率、相关性、reward 尾部与 prompt 覆盖，而不能从「大组更容易找到正确答案」直接推出「大组训练一定更好」。

如果 reward 连续但被量化或裁剪，仍可定义有效差异阈值 $\epsilon$，统计 $\max_iR_i-\min_iR_i>\epsilon$ 的组比例。阈值应高于 verifier 重评分噪声的典型幅度，否则所谓有效组只是噪声组。训练曲线同时报告原始方差、去噪后的可复现方差和产生非零梯度的组比例，才能判断信号究竟来自能力差异还是测量误差。 **20.35 归一化、裁剪与组间尺度.** 留一优势已经完成组内中心化，许多实现还会除以组内标准差：

$$
\tilde A_i=\frac{A_i}{\sqrt{\frac1K\sum_jA_j^2+\epsilon}}.
$$

这一步让 reward 尺度较大的组不再天然主导梯度，也让同一 reward 的仿射缩放近似不影响更新。但它同时改变 prompt 之间的权重：回报差异只有 $0.01$ 的组与差异为 $10$ 的组，标准化后都可能产生数量级相近的优势。若小差异来自评分噪声，归一化会把噪声放大到与明确成败相同的尺度。

二元 reward 的组内标准差由成功数决定。组中只有一个成功时，成功轨迹获得最大的正优势，大量失败轨迹分别承担较小负优势；成功与失败各半时，单条优势更温和。标准化会进一步抹去「罕见成功」与「普通分歧」的绝对尺度。它可能有助于从稀疏成功中学习，也更依赖 verifier 对这个唯一成功的判断。

$\epsilon$ 不是纯数值细节。组内差异趋近零时，较大的 $\epsilon$ 会压低微弱信号，较小的 $\epsilon$ 会放大浮点误差和奖励噪声。可以用 verifier 重评分方差确定噪声地板：只有组内可复现差异超过该地板时才标准化更新，其余组标记为无可靠信号。这样做引入阈值选择，却比让机器精度决定梯度更容易审计。

跨整个 batch 再做 advantage 标准化，会把不同 prompt 的难度与 reward 标尺混合。若一部分任务给零一分，另一部分给零到一百分，全局中心化甚至可能让某个 prompt 内所有候选同号，破坏组内相对比较的直观含义。保留原始优势、组内归一化优势和实际进入损失的优势三份统计，能够直接发现这类尺度迁移。

gradient clipping 位于更下游。优势裁剪限制单样本信号，ratio clipping 限制策略相对行为策略的变化，global gradient clipping 限制所有样本聚合后的参数步长。三种裁剪的对象不同：第一种会压掉 reward 尾部，第二种主要影响 off-policy 或多 epoch 更新，第三种可能让一个异常组缩小整批其他组的有效步长。只报告一个 `clip` 参数无法复现实验。

设正常组梯度范数为一，某个 reward 攻击组范数为一百，全局阈值为十。聚合后裁剪会把整批缩小，正常组的贡献也随之下降；逐样本优势裁剪则先限制攻击组，正常组基本不变。前者保护优化器数值稳定，后者改变估计目标。稳健方案可以先按可靠的 reward 范围处理异常，再使用全局裁剪防止偶发数值爆炸，并分别记录触发比例。

Adam 的二阶矩还会留下时间记忆。一次极端梯度即便被裁剪，也可能抬高后续若干步的分母，让学习率长期变小。分析 reward 攻击或训练骤停时，需要同时查看原始梯度范数、裁剪后范数、优化器二阶矩与有效步长。仅从当步 loss 恢复正常，无法确认污染已经消失。

归一化策略最终应由不变量和外部指标共同选择。平移 reward 后更新应保持一致；按正数缩放 reward 时，未归一化版本的梯度应相应缩放，标准化版本应近似不变；加入低于噪声地板的扰动时，策略不应明显改变。随后再比较固定预算下的正确率、校准、长度、KL 与跨任务退化，才能判断稳定性究竟来自更好的估计，还是来自把真实差异一并压平。

还有一个容易藏在平均值里的现象：组内归一化会让每个有效组大致贡献相近尺度，但各组梯度方向的可信度并不相同。八条候选中四条由确定性判题器判对、四条判错，方向通常比八条分数都挤在 reward model 决策边界附近更可靠。可以依据重评分一致性、判题器类型和环境完成状态估计置信度，再把置信度作为 prompt 级权重；它应在构造组内相对优势之后使用，避免改变同组候选的排序。置信度本身也可能带偏，尤其当判题器对某类语言或解法系统性不利，因此需要按任务域报告覆盖率和校准误差。

自适应采样与归一化还会形成反馈环。某类 prompt 经常产生高方差梯度，调度器便给它更多样本；更多样本又使其在优化器状态中占据更大份额。若高方差源于学习价值，这能加速训练；若源于不稳定 verifier，系统会持续追逐噪声。区分二者可以观察新增样本是否缩小梯度方向的置信区间，以及独立验证指标是否同步改善。只有方差下降而能力不变时，应先修奖励和环境，再继续增加预算。

最终报告应把「有多少组产生更新」「这些更新有多少通过重复评分」「通过的梯度方向在不同随机种子间是否一致」连在一起。非零优势只说明组内出现数字差异，可复现差异才提供可学习信号，跨种子方向一致才说明优化可能积累。三层比例比单一的 advantage 标准差更接近 RLOO 真正吃到的有效监督量。

RLOO 的实现可用一个守恒关系做单元测试. 对同一 prompt 的 $K$ 个回报 $R_i$, 留一基线为 $b_i=(\sum_jR_j-R_i)/(K-1)$, 因而优势满足 $\sum_i(R_i-b_i)=0$. 这个等式不依赖回报取值, 浮点误差之外应始终成立. 如果不成立, 常见原因是 padding 样本被计入分母、跨 prompt 混组, 或某些失败 rollout 被过滤后仍沿用了过滤前的 $K$. 守恒并不意味着方差一定小. 当 $K=2$ 时, 两个优势就是 $R_1-R_2$ 与 $R_2-R_1$, 单个异常回报会完整传给另一个样本; 增大 $K$ 可平滑基线, 却线性增加 rollout 成本. 因而组大小应与奖励尾部分布一起选择, 而不能只按显存余量决定. 若奖励含离群值, 可同时报告原始优势与截断后优势, 观察稳定收益是否以系统性偏差为代价. **20.36 奖励依赖的提前停止反例.**

RLOO 的标准证明默认先确定组大小 $K$，再从同一策略独立采满整组。线上系统却常为节省算力而采用「首次成功即停止」：按顺序生成候选，一旦 verifier 判定成功便取消余下请求。此时组大小不再是外生预算，而是已观察回报的函数；某条轨迹能否进入训练集也取决于它之前的轨迹。即使随后仍按留一公式计算优势，估计对象也已经改变。 考虑成功概率为 $p$ 的二元 reward，最多生成两条并在首次成功后停止。可观察序列只有

$$
[1]\quad(p),\qquad [0,1]\quad((1-p)p),\qquad [0,0]\quad((1-p)^2).
$$

长度为一的组无法定义留一基线。若把它们丢弃，进入训练的数据就条件化在「第一条失败」上：第一位置的 reward 恒为零，第二位置才保留原来的伯努利分布。若把单条成功组的优势设为零，概率为 $p$ 的立即成功事件全部不提供正梯度；只有序列 $[0,1]$ 产生 $(-1,+1)$ 的成对优势。两种处理都不再是固定 $K=2$ 时策略梯度的无偏估计，并且会把更新过度归因于「一次失败之后」才出现的动作。复制唯一成功样本作 padding 同样无效，因为两个相同回报的优势都为零，还虚构了第二次独立采样。

偏差的来源是停止规则读取了 reward，而非组大小随机这一事实。若组大小由训练前抽取、且与本组动作和回报独立，可以把它纳入外层期望；若分配器看到成功、超时或部分 verifier 分数后再决定是否续采，保留概率通常依赖轨迹。用逆保留概率可以在已知采样机制时修正某些选择偏差，但罕见路径的权重会很大，而且取消后从未生成的动作没有可恢复的 reward。工程上更稳妥的做法是预先承诺每个 prompt 的 $K$ 并完成全部 rollout；若必须自适应分配，可用独立的试探批次决定下一批预算，再让真正进入梯度估计的批次保持固定规则。

这个问题可用小型 bandit 做精确回归测试：枚举所有停止序列，分别计算真实策略梯度、固定组 RLOO 期望和提前停止估计量的期望，并扫描 $p$ 与最大组大小。系统测试还应记录每组的预定 $K$、实际 $K$、停止原因、被取消数和 reward 分布；若成功率上升时平均组大小同步下降，却没有显式选择修正，训练信号很可能正在被停止策略重新加权。只有估计均值在样本数增加后收敛到解析梯度，才能把节省 rollout 的收益与估计偏差区分开。 **20.37 参考资料.**
