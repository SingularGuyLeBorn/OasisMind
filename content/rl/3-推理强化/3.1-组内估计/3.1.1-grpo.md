# 组相对策略优化 (Group Relative Policy Optimization, GRPO)

**论文信息**:

- **标题**: DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models
- **作者**: Zhihong Shao et al. (DeepSeek)
- **年份**: 2024
- **论文**: [arXiv:2402.03300](https://arxiv.org/abs/2402.03300)

GRPO 由 DeepSeekMath 提出,后来进入 DeepSeek-R1 的推理强化学习配方. 它对同一 prompt 采样一组回答,用组内 reward 统计量构造相对 advantage,从而省去单独训练 value model. 算法仍然依赖 old policy 采样、PPO-style ratio、clip 与 reference KL. 组统计怎样计算、序列 reward 怎样广播到 token、zero variance 怎样处理,都会改变实际 estimator. R1 的最终能力还取决于基座、数据、验证器、采样预算和训练系统,不能只归因于 GRPO.

同一 prompt 的组内样本必须视为一个统计单元. 若分布式切分让一组回答散落在不同 worker, 每张卡只用局部均值和标准差, 得到的 advantage 就不再等价于全组标准化. 一个可复算的测试是构造奖励 $[0,1,3,4]$, 先整体计算标准化结果, 再模拟两张卡各持有两个样本; 局部结果会退化成两组近似 $[-1,1]$, 抹掉中间间隔. 因此通信应聚合组内的计数、和与平方和, 或直接保证整组同卡, 不能只同步最终 loss.

当奖励几乎相同时, 标准差下界决定梯度尺度. 训练日志至少同时保存未归一奖励跨度、标准差下界触发率和归一后 advantage 的分位数. 仅观察平均奖励无法发现大量组被放大噪声的问题; 触发率上升通常意味着题目已饱和、验证器分辨率不足, 或采样温度过低.

---

## 1. 从PPO到GRPO的动机

REINFORCE 用序列 reward 直接加权 token log-prob,PPO 再加入 old-policy ratio、clip 与 value advantage.GRPO 保留策略更新骨架,将 learned value baseline 换成同 prompt 组内比较. 这种替换减少显存和 value fitting 负担,同时把 estimator 质量交给组采样. Group size、采样温度、reward ties 与 prompt 难度共同决定是否有可用相对信号.

### 1.1. PPO在LLM中的问题

回顾PPO的优势估计需要**价值网络** $V_\phi(s)$:

$$
A_t = r_t + \gamma V(s_{t+1}) - V(s_t)

$$

**公式符号详解**:

| 符号      | 含义                                                                    | 类型 | 取值范围                  |
| ----------- | ------------------------------------------------------------------------- | ------ | --------------------------- |
| $A_t$     | 时刻$t$ 的**优势函数**(Advantage),衡量当前动作相对于平均水平的好坏      | 标量 | $\mathbb{R}$              |
| $r_t$     | 时刻$t$ 获得的**即时奖励**(Reward)                                      | 标量 | 通常$[-1, 1]$ 或 $[0, 1]$ |
| $\gamma$  | **折扣因子**(Discount Factor),决定未来奖励的权重                        | 标量 | $(0, 1)$,通常0.99         |
| $V(s_t)$  | 状态$s_t$ 的**价值函数**(Value Function),预测从该状态出发的期望累计奖励 | 标量 | $\mathbb{R}$              |
| $s_t$     | 时刻$t$ 的**状态**(State),在LLM中是prompt + 已生成的tokens              | 向量 | 状态空间                  |
| $s_{t+1}$ | 采取动作后的**下一个状态**                                              | 向量 | 状态空间                  |

**LLM场景的问题**:

1. **价值函数开销**: PPO 需要估计 value;它可以是独立的同规模网络,也可以是共享 backbone 上的 value head
2. **联合训练误差**: value 与 policy 的版本、target 和更新节奏必须对齐
3. **资源占用**: 独立 value model 会增加参数、激活和 optimizer state;共享骨干能降低增量,但会引入梯度干扰,不能一概写成显存翻倍

### 1.2. GRPO的解决方案

**核心洞察**: 在 LLM 生成场景,可以对同一个 prompt 采样多个 response,用组内 reward 做中心化,从而不再单独拟合 value function.

$$
A_i = R_i - \underbrace{\bar{R}}_{\text{组内样本均值}}

$$

**公式符号详解**:

| 符号                                                 | 含义                                                                                  | 类型     | 取值范围                   |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------- | ---------- | ---------------------------- |
| $A_i$                                                | 第$i$ 个response的**优势值**,表示该response相对于组内平均水平的好坏                   | 标量     | $\mathbb{R}$               |
| $R_i$                                                | 第$i$ 个response获得的**奖励**(来自奖励模型或规则验证器)                              | 标量     | 通常$[0, 1]$ 或 $\{0, 1\}$ |
| $\bar{R}$                                            | **组内样本均值**,所有 response 奖励的算术平均 $\bar{R} = \frac{1}{G}\sum_{j=1}^G R_j$ | 标量     | 同$R_i$                    |
| $i$ | response的**索引**,$i \in \{1, 2, \ldots, G\}$ | 整数                                                                                  | $[1, G]$ |                            |
| $G$                                                  | **组大小**(Group Size),即每个prompt采样的response数量                                 | 整数     | 通常$4, 8, 16$             |

$\bar R$ 包含当前样本自身的 $R_i$,所以它不等同于与 action 独立的经典 baseline. 对未标准化的 $R_i-\bar R$,这种 self-inclusion 会让期望 policy-gradient 相对 leave-one-out mean 缩放为 $(G-1)/G$. Leave-one-out 均值由另外 $G-1$ 个独立回答构成,可去掉这项 self-coupling;再除以随机组标准差时,估计量还会获得额外的 prompt-dependent weighting.

**优势**:

- 无需价值网络 → 节省显存
- 无需训练价值函数 → 更稳定
- 更符合LLM的评估方式(比较多个response)

### 1.3. 从 REINFORCE 和 PPO 到 GRPO

REINFORCE 对整条回答 $y=(y_1,\ldots,y_T)$ 的基本梯度估计是:

$$
\hat g=\sum_{t=1}^{T}\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})\,(R-b(x)).

$$

$R$ 是回答完成后得到的序列级 reward,$b(x)$ 是不依赖本次 action 的 baseline. 在语言模型里,同一个 prompt 的难度会大幅改变 reward 分布. 若不设 baseline,「简单题答对」可能产生大量正梯度,却没有告诉模型这条回答相对同题其他回答好在哪里. PPO 先用旧策略 $\pi_{\mathrm{old}}$ 采样,再用概率比率

$$
\rho_t(\theta)=\frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\mathrm{old}}(y_t\mid x,y_{<t})}

$$

修正当前策略与采样策略的差异,并裁剪过大的更新. 经典 PPO 常由 value model 估计 advantage.GRPO 保留「旧策略采样 + ratio + clip」这套更新骨架,把 value baseline 换成**同一 prompt 下多个回答的组内 reward 统计量**. 因此,GRPO 解决的是 advantage 的构造和 value model 的开销;它没有让数据突然变成 off-policy 可无限复用,也没有消除 PPO clipping 自身的近似. 设训练 batch 中有 $B$ 个 prompt,每个 prompt 从同一个 rollout policy 采样 $G$ 个回答. reward tensor 的形状是 $[B,G]$,回答 token 的 log-prob 和 mask 通常是 $[B,G,T_{\max}]$. 组均值与标准差只沿 $G$ 维计算,再广播到该 prompt 的所有有效 token. 若错误地跨 prompt 求均值,简单题和难题会互相充当 baseline,「组相对」的含义就丢了.

---

**GRPO 在推理强化学习中的位置。**

DeepSeekMath 在 2024 年为数学推理提出 GRPO，处理缺少可靠 value信号时的 RL；DeepSeek-R1 随后将它用于更大规模的推理训练，并采用规则验证器。规则 reward语义通常比 learned reward稳定，同时仍可能存在验证漏洞。组大小、标准差归一和 KL 的合理性都依赖信号形态；换成连续 judge分数后，需要重新验证。稀疏二值奖励还使采样组大小、温度和难度筛选直接决定可用信号上限。

**GRPO的数学推导。**

一次 GRPO batch 的基本单位是 prompt group,不是单个 response. Reward 先在组维做中心化或标准化,再把每条 response 的标量 advantage 广播到该回答所有有效 token. Policy update 则保留 token 维 old/new ratio 与 clip. 序列 reward 提供回答级方向,token ratio 决定每个生成位置的局部概率变化;两者粒度不同,不能用「每个 token 都有独立 reward」解释.

**组采样设置。**

对于每个prompt $x$,采样 $G$ 个response:

$$
\{y_1, y_2, \ldots, y_G\} \sim \pi_{old}(\cdot \mid x)

$$

**公式符号详解**:

| 符号        | 含义                                         | 类型             | 说明                                              |
| ------------- | ---------------------------------------------- | ------------------ | --------------------------------------------------- |
| $x$         | **输入prompt**,用户的问题或指令              | 字符串/token序列 | 例如 "Solve: 2+2="                                |
| $y_i$       | 第$i$ 个**采样的response**,模型的完整回复    | 字符串/token序列 | 例如 "The answer is 4."                           |
| $G$         | **组大小**,每个prompt采样的response数量      | 正整数           | 典型值: 8                                         |
| $\pi_{old}$ | **Rollout 策略**,生成当前组样本的 checkpoint | 概率分布         | $\pi_{old}(y\mid x)$ 表示给定 $x$ 生成 $y$ 的概率 |
| $\theta$    | 更新中 current policy 的**可训练参数**       | 向量             | 模型权重;不改变本组样本来自$\pi_{old}$ 的事实     |
| $\sim$      | **采样符号**,表示从分布中采样                | 操作             | -                                                 |

每个response获得奖励:

$$
R_i = r(x, y_i) \quad \text{for } i = 1, \ldots, G

$$

**公式符号详解**:

| 符号        | 含义                                                | 类型 | 说明                       |
| ------------- | ----------------------------------------------------- | ------ | ---------------------------- |
| $R_i$       | 第$i$ 个response的**奖励值**                        | 标量 | 通常$\in [0, 1]$           |
| $r(x, y_i)$ | **奖励函数**,评估response $y_i$ 对prompt $x$ 的质量 | 函数 | 可以是奖励模型或规则验证器 |
| $i$         | response的**索引**                                  | 整数 | $i \in \{1, \ldots, G\}$   |

### 1.4. 组内优势估计与标准差归一

**原始GRPO**使用归一化的优势:

$$
\boxed{A_i = \frac{R_i - \bar{R}}{\sigma_R + \epsilon}}

$$

**公式各项详解**:

| 符号       | 含义                             | 计算方式                                 | 说明                        |
| ------------ | ---------------------------------- | ------------------------------------------ | ----------------------------- |
| $A_i$      | 第$i$ 个response的**归一化优势** | 见公式                                   | 正值=好于平均,负值=差于平均 |
| $R_i$      | 第$i$ 个response的**奖励**       | 由奖励函数给出                           | -                           |
| $\bar{R}$  | **组内均值基线**                 | $\bar{R} = \frac{1}{G} \sum_{j=1}^G R_j$ | 所有response奖励的平均值    |
| $\sigma_R$ | **组内标准差**                   | 对同一 prompt 的$G$ 个 reward 计算       | 衡量奖励的离散程度          |
| $\epsilon$ | **数值稳定项**                   | 由具体实现设置                           | 防止除以零                  |
| $G$        | **组大小**                       | 正整数                                   | 每个 prompt 的采样回答数    |

**标准差归一化的作用。**

- 当奖励差异大时($\sigma_R$ 大),缩小优势幅度,防止过大更新
- 当奖励差异小时($\sigma_R$ 小),放大优势幅度,加速学习

DeepSeekMath 论文公式写作 $\operatorname{std}(R_1,\ldots,R_G)$,没有覆盖所有框架的自由度. 实现仍需明确使用总体标准差还是样本标准差、零方差怎样处理、数值稳定项取什么值. 这些选择会改变 advantage 尺度,不能把某个库的默认值反写成原论文唯一配方.

**手算一:组内均值与标准差优势。**

对同一道题采样四个回答,规则验证器给出 reward

$$
R=[1,1,0,0].

$$

组均值为 $\bar R=0.5$. 若采用总体标准差,

$$
\sigma_R=\sqrt{\frac{(0.5)^2+(0.5)^2+(-0.5)^2+(-0.5)^2}{4}}=0.5.

$$

归一化 advantage 是

$$
A=[1,1,-1,-1].

$$

去掉标准差归一化时,advantage 则为 $[0.5,0.5,-0.5,-0.5]$. 两种写法的符号相同,梯度尺度相差两倍. 若优化器、KL 系数和裁剪范围保持不变,这不是一个无关紧要的常数:policy loss 相对 KL 和其他损失的权重已经改变. 再看 $R=[1,1,1,1]$ 或 $R=[0,0,0,0]$. 此时 $R_i-\bar R=0,\sigma_R=0$. 数学上这组回答没有相对排序信号,合理结果应是全零 advantage. 实现不能只做除法后产生 `NaN`;可以显式识别零方差组,或者使用稳定项并确认分子仍为零. 这类组是否继续用于 KL 更新,则属于 recipe 选择,应在实验配置中说明.

**图解:GRPO 组采样与优势估计。**

**图片详细说明**:

图按两层读取。上层把单个 prompt $x$ 输入同一策略 $\pi_\theta$，得到 $G$ 个 responses；每个 $y_i$ 与同一个 $x$ 独立进入奖励函数 $r(x,y_i)$，产生 $R_i$ 并组成完整奖励向量 $R=[R_1,\ldots,R_G]$。 下层把同一个 $R$ 展开成三条有明确消费者的路径：完整 $R$ 进入组均值；完整 $R$ 与均值 $\bar R$ 共同进入样本标准差；按索引从 $R$ 取出每路自己的 $R_i$。随后，$R_i$、广播的 $\bar R$、广播的 $\sigma_R$ 与独立稳定项 $\epsilon$ 分别进入优势计算，得到

$$
A_i=\frac{R_i-\bar R}{\sigma_R+\epsilon},\qquad i=1,\ldots,G.

$$

正优势表示该 response 高于组内平均，负优势表示低于组内平均。均值只替代 value baseline；它不会让组内各 response 共用同一个 $R_i$。

### 1.5. GRPO 损失与逐 token 裁剪

GRPO 基于 PPO 的裁剪目标,但重要性比保留 **token 维**:

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{\theta_{old}}(y_{i,t}\mid x,y_{i,<t})}
=\exp\left(\ell^{new}_{i,t}-\ell^{old}_{i,t}\right).

$$

$$
\mathcal{L}^{GRPO}=-\mathbb E_x\left[
\frac1G\sum_{i=1}^G\frac1{|y_i|}\sum_{t=1}^{|y_i|}
\min\left(\rho_{i,t}A_i,
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i\right)
\right].

$$

**公式各项逐一详解**:

| 符号                                              | 含义                                   | 详细说明                          |
| --------------------------------------------------- | ---------------------------------------- | ----------------------------------- |
| $\mathcal{L}^{GRPO}$                              | **GRPO损失函数**,需要最小化            | 负号是因为我们想最大化期望回报    |
| $\mathbb{E}_x$                                    | 对所有**prompt $x$** 的期望            | 遍历训练数据中的prompts           |
| $\frac{1}{G}$                                     | 对组内求**平均**                       | 每个prompt有$G$ 个response        |
| $\frac1{|y_i|}\sum_t$                             | 先在回答内按有效 token 平均            | 这是损失归约,不是序列概率比       |
| $\rho_{i,t}(\theta)$                              | 第$i$ 条回答第 $t$ 个 token 的重要性比 | 形状与 response token mask 相同   |
| $A_i$                                             | 第$i$ 个response的**优势值**           | 由2.2节公式计算                   |
| $\text{clip}(\rho_{i,t}, 1-\epsilon, 1+\epsilon)$ | **逐 token 裁剪函数**                  | $\epsilon$ 是具体 recipe 的超参数 |
| $\min(\cdot, \cdot)$                              | 取**较小值**                           | 悲观估计,防止过大更新             |

旧策略 log-prob 属于 rollout 数据,优化当前策略时必须停止梯度.GRPO 不会把 $\rho_{i,t}$ 沿序列相乘,也不会先把 token log-prob 求和再构造一个回答级 ratio.

**裁剪机制的作用**:

| 情况                               | $A_i > 0$(好response) | $A_i < 0$(差response) |
| ------------------------------------ | ----------------------- | ----------------------- |
| $r_i > 1+\epsilon$                 | 裁剪生效,限制增加     | 不裁剪,鼓励降低       |
| $r_i < 1-\epsilon$                 | 不裁剪,鼓励增加       | 裁剪生效,限制降低     |
| $r_i \in [1-\epsilon, 1+\epsilon]$ | 正常更新              | 正常更新              |

**手算二:逐 token ratio 为什么按 advantage 符号裁剪。**

设某条回答的序列 advantage 为 $A_i=1.2$,clip 范围是 $[0.8,1.2]$. 某个 token 的 old log-prob 为 $-1.0$,new log-prob 为 $-0.7$,于是

$$
\rho_{i,t}=\exp(-0.7-(-1.0))=\exp(0.3)\approx1.35.

$$

未裁剪项为 $1.35\times1.2=1.62$,裁剪项为 $1.2\times1.2=1.44$. PPO surrogate 取较小的 $1.44$,不再奖励这一 token 概率继续大幅增加. 若另一条差回答有 $A_j=-1.2$,并且某 token 的 ratio 为 $0.6$,未裁剪项是 $-0.72$,裁剪项是 $0.8\times(-1.2)=-0.96$. 两者取较小值 $-0.96$,从最大化 surrogate 的角度看,继续把 ratio 压到 $0.8$ 以下得不到额外收益. 这说明 clip 不是简单地把所有 ratio 截断后再计算;`min` 与 advantage 的正负共同决定哪一支生效.

同一回答的所有 token 共享 $A_i$,但 ratio 和裁剪逐 token 计算. 这给出了密集的优化项,并没有凭空获得 token 级 credit:验证器只说整条回答成功或失败,算法无法知道错误究竟发生在哪一步推理. 正确答案中的偶然冗余 token 也会获得正 advantage,错误答案中有价值的前缀也会获得负 advantage. 过程 reward、步骤验证器或更细的 outcome decomposition 才能改变这个 credit assignment 边界.

**完整目标函数。**

加上KL惩罚防止偏离参考模型:

$$
\mathcal{L} = \mathcal{L}^{GRPO} + \beta \cdot \mathbb{E}\left[D_{KL}(\pi_\theta \| \pi_{ref})\right]

$$

**公式各项详解**:

| 符号                              | 含义             | 说明                                                    |
| ----------------------------------- | ------------------ | --------------------------------------------------------- |
| $\mathcal{L}$                     | **总损失函数**   | 需要最小化                                              |
| $\mathcal{L}^{GRPO}$              | **GRPO策略损失** | 见2.3节                                                 |
| $\beta$                           | **KL惩罚系数**   | 由具体 recipe 决定,控制偏离程度                         |
| $D_{KL}(\pi_\theta \| \pi_{ref})$ | **KL散度**       | 衡量当前策略与参考策略的差异                            |
| $\pi_{ref}$                       | **参考策略**     | 在当前内层优化窗口冻结;跨外层迭代是否更新由 recipe 决定 |

DeepSeekMath 的原始目标把 KL penalty 放在回答内逐 token 求和项中,并写出基于 reference/current 概率比的 k3 估计. 对 $k=\log\pi_\theta-\log\pi_{ref}$,样本来自当前 $\pi_\theta$ 时,$e^{-k}-1+k$ 才是 $D_{KL}(\pi_\theta\Vert\pi_{ref})$ 的无偏样本估计. Rollout 来自 $\pi_{old}$、current 已经过 minibatch 更新后,直接在旧 token 上平均不再严格无偏,除非 $\pi_{old}=\pi_\theta$ 或另加分布修正. 后续训练库可能改用采样 token 上的近似、显式 KL reward,或者直接移除 KL loss 并用其他约束控制漂移. 这些都可以叫「GRPO 训练」,但已不是逐项相同的 DeepSeekMath 配方. 阅读实现时应分别核对采样版本、advantage、ratio 粒度、loss 归约和 KL 位置.

---

**序列 reward 到 token 的广播及其代价。**

GRPO 的 reward 是序列级的, 但策略更新是 token 级的, 中间靠广播: 一条 response 的标量 advantage 乘到它每个 token 的 ratio 上. 这种广播同时带来粗粒度信用分配和密集优化项. 代价是 credit assignment 粗糙。一条 500 token推理链若末步算错，整条 advantage为负，前面的正确 token也收到负梯度；成功轨迹中的绕路同样收到正梯度。sequence-level RL普遍面对这种粗粒度信用，组内 baseline不会改变时间维归因。最终答案与过程错误高度相关时，这种近似可能有效；多跳任务频繁出现“前面正确、末步出错”时，过程奖励或 step-level价值估计更有意义。也可以用规则逐步校验，在不新增 learned value模型的情况下提高粒度。

实践上的一个配套约定: 广播只到有效 token, prompt 和 padding 不进 loss, 和 SFT 的 mask 约定一致. 另一个容易忽略的点: advantage 广播后再按组归一或按 batch 归一, 顺序不同结果不同. 先广播后归一, 归一的尺度作用在 token 粒度; 先归一后广播, 尺度作用在序列粒度. 原论文按序列构造 advantage 再广播, 属于后者, 改顺序属于偏离配方的实现变体.

### 1.6. 标准差归一争议与数据复用

中心化决定回答相对组均值的正负,标准差归一化进一步改变不同 prompt 组之间的梯度尺度. 二元 reward 下,混合成功/失败组有信号,全对或全错组则产生 zero variance. 这一部分还需要把统计选择与 policy version 分开. 组内样本必须来自同一个 old policy;reference 在一次内层更新窗口中冻结,更新后的 current policy 只出现在 ratio 分子和 KL 当前项中. Reference 是否跨整段 RL 固定,取决于 recipe.

**问题发现。**

论文 "Dr. GRPO" 指出原始GRPO中除以标准差可能有问题:

**小方差组的放大。**
当所有 response 奖励完全相同时,$\sigma_R=0$ 产生 $0/0$,实现应显式返回全零或使用 epsilon. 当 $\sigma_R$ 很小但非零时,分子也同时缩小,标准化结果不会仅因 $\sigma_R\to0$ 就数学发散;真正变化是原本很小的 reward 差被放大到 $O(1)$,并由随机分母改变跨 prompt 权重.

**组间隐式权重。**
即使原始奖励差很小,归一化后可能变得很大.

**Dr. GRPO的建议。**

**移除标准差归一化**:

$$
A_i^{Dr} = R_i - \bar{R}

$$

**公式符号详解**:

| 符号       | 含义                       | 与原始GRPO的区别 |
| ------------ | ---------------------------- | ------------------ |
| $A_i^{Dr}$ | Dr. GRPO的**未归一化优势** | 不除以$\sigma_R$ |
| $R_i$      | 第$i$ 个response的奖励     | 相同             |
| $\bar{R}$  | 组内均值基线               | 相同             |

Dr. GRPO 还移除按**实际回答长度**归一:将 masked token surrogate 的分母替换为固定生成预算等全局常数.标准差归一和长度归约是两个独立开关;Dr. GRPO 仍使用逐 token ratio.

**代码对比。**

```python
# 原始 GRPO
def grpo_advantage(rewards, group_size, eps=1e-5):
    rewards = rewards.view(-1, group_size)
    mean = rewards.mean(dim=1, keepdim=True)
    std = rewards.std(dim=1, keepdim=True)
    return ((rewards - mean) / (std + eps)).view(-1)

# Dr. GRPO
def dr_grpo_advantage(rewards, group_size):
    rewards = rewards.view(-1, group_size)
    mean = rewards.mean(dim=1, keepdim=True)
    return (rewards - mean).view(-1)
```

**难题权重与组统计带来的偏差—方差。**

对二元正确性 reward,设某个 prompt 在当前策略下答对的概率为 $p$. 若一组样本里正确比例为 $\hat p$,不做标准差归一时,正确回答的 advantage 是 $1-\hat p$,错误回答是 $-\hat p$. 当题目几乎总对或几乎总错时,组内差异很少,梯度自然变弱;在 $p$ 接近中间区域时,同组更容易同时出现正负样本,比较信号最丰富.

除以 $\sqrt{\hat p(1-\hat p)}$ 后,只要组内同时出现成功和失败,不同难度 prompt 的 advantage 尺度会被拉得更接近. 但对一个很难的问题,偶然采到单个成功回答时,$\hat p$ 很小,该回答会得到较大的正优势;对很容易的问题,偶然失败回答也会得到较大的负优势. 这就是 question-level difficulty weighting 的来源之一. 若整组全对或全错,标准差为零,该 prompt 本轮又没有相对信号. 因此「难题一定权重更大」并不准确;权重还由组大小和本轮是否采到混合结果决定.

组均值本身也由当前 $G$ 个 reward 估计,所以 $G$ 小时 baseline 噪声较大. 更大的 $G$ 能更稳定地估计同 prompt 的相对位置,代价是 rollout 成本按组增长. 由于 $\bar R$ 包含 $R_i$ 自身,$R_i-\bar R$ 相对 leave-one-out baseline 会收缩一个与组大小有关的比例;标准差又是随机分母,进一步改变估计量的偏差和方差. GRPO 的优势是避免单独训练 value model,并不代表 advantage 估计没有统计误差.

**采样版本、更新版本与数据复用。**

一组 $G$ 个回答应由同一个可识别的 $\pi_{\mathrm{old}}$ 采样. 如果生成过程中某些 worker 已经换上新 checkpoint,同一组 reward 的比较对象就来自不同分布,old log-prob 也不再对应一个统一版本. rollout 至少要保存 prompt id、policy version、采样温度、每个 token 的 old log-prob、有效 token mask、reward 与 verifier version. 训练阶段可以在固定 rollout 上做若干 minibatch 更新,每次都用当前 $\pi_\theta$ 与保存的 $\pi_{\mathrm{old}}$ 计算 ratio. 更新越多,策略离采样版本越远,更多 token 进入 clip 区域,有效梯度减少. clip 只能限制 surrogate,不能把很旧的数据重新变成严格 on-policy 数据. 因此复用轮数、clip fraction 和近似 KL 都应一起监控;长期 replay 需要额外的 off-policy 修正,不属于原始 GRPO 公式自动提供的能力.

一轮可核对的训练顺序是:

1. 冻结并登记 rollout policy $\pi_{\mathrm{old}}$;
2. 对每个 prompt 独立采样 $G$ 个回答,保存 old token log-prob;
3. 用固定版本的 verifier 计算序列 reward,区分无效样本和真实零分;
4. 只沿组维计算 $\bar R$ 与标准差,零方差组按 recipe 明确处理;
5. 将序列 advantage 广播到回答的有效 token,构造 token ratio、clip surrogate 与 KL;
6. 在设定的 minibatch/epoch 内更新,记录 clip fraction、KL、response length 和各难度段成功率;
7. 结束后发布新 policy version,下一轮重新采样,不让一个组跨版本拼接.

验证器异常不能静默写成 reward $0$. 答案确实错误、输出无法解析、sandbox 超时和判定服务不可用,对 policy 的含义并不相同. 若基础设施失败被混进零分组,组均值和标准差会一起改变,同组其他正常回答的 advantage 也受到污染. 数据管道应先完成有效性判定,再在有效回答之间计算组统计;若有效样本数不足,整组重采样或跳过,并单独报告丢弃比例.

**原始 GRPO 与后续实现差在哪里。**

**DeepSeekMath 是 GRPO 的原始出处.** 其目标包含同 prompt 组采样、组 reward 标准化、逐 token PPO-style ratio 与 clipping,以及相对 reference policy 的 KL penalty. DeepSeek-R1 随后把 GRPO 用于推理强化学习,但 R1 的结果还依赖基座、可验证 reward、数据与大规模训练流程,不能缩成「只换了一种 optimizer」.

后续工作沿不同轴修改配方:

| 配方     | 相对 DeepSeekMath 的主要变化                                               | 不能混写的点                        |
| ---------- | ---------------------------------------------------------------------------- | ------------------------------------- |
| Dr. GRPO | 移除组 reward 的标准差归一,并调整按回答长度归约造成的 bias                 | 仍可使用逐 token ratio;它不是 GSPO  |
| DAPO     | 在 GRPO 系谱上加入动态采样、clip-higher、token-level loss 等工程与算法改动 | 不能把 DAPO 的全部技巧说成原始 GRPO |
| GSPO     | 用长度归一的序列级 ratio 做回答级裁剪                                      | 与 GRPO 的逐 token ratio 粒度不同   |

各训练库还可能改变 KL 的放置方式、是否保留 reference model、标准差实现、loss 分母、超长回答 mask 和零方差组过滤. 判断一个实现时,最有效的做法是把公式拆成五个独立开关:advantage 如何算,ratio 在 token 还是 sequence 级,clip 怎样做,token 怎样归约,KL 在 loss 还是 reward 中加入. 只看配置项叫 `grpo` 不能证明它逐项复现了 DeepSeekMath.

## 2. GRPO变体

后续工作沿三个互相独立的轴修改 GRPO:reward 是否除组标准差,loss 按 token 还是回答长度归约,importance ratio 在 token 还是 sequence 级计算. 名称相近不代表公式相同. 比较实现时应把 advantage、ratio、clip、KL 和 loss denominator 分别列出. 只写「使用 GRPO」不足以复现实验,也容易把 DAPO 或 GSPO 的技巧倒写成 DeepSeekMath 原始配方.

### 2.1. GSPO (Group Sequence Policy Optimization)

**来源**: *Group Sequence Policy Optimization*, arXiv:2507.18071.

**创新**: 长度归一的序列级重要性比率

$$
s_i(\theta)=\exp\left(\frac1{|y_i|}\sum_t\log\frac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{old}(y_{i,t}|x,y_{i,<t})}\right)

$$

**公式符号详解**:

| 符号                              | 含义                                 | 说明                                 |
| ----------------------------------- | -------------------------------------- | -------------------------------------- |
| $s_i^{GSPO}$                      | **长度归一的序列级比率**             | masked mean log-ratio 后再 exp       |
| $\sum_t$                          | 对所有**token位置 $t$** 求和         | $t = 1, 2, \ldots, T$,$T$ 是序列长度 |
| $\log \pi_\theta(y_t\mid y_{<t})$ | 当前策略对第$t$ 个token的**log概率** | 条件于前面的tokens                   |
| $\pi_{old}$                       | 旧策略                               | 采样时的策略                         |
| $\exp(\cdot)$                     | 指数函数                             | 将log空间转回原空间                  |

**与GRPO的区别**:GRPO 直接在每个 token 上使用并裁剪 $\rho_{i,t}$;GSPO 才把 masked mean log-ratio 压成一个回答级 $s_i$,随后按整条回答裁剪.两者差别不是"直接乘积"和"log-space 乘积".

---

### 2.2. DAPO 与实现分叉

DAPO 在 GRPO 系谱上加入动态采样、clip-higher、token-level policy gradient loss 等改动,目标是改善长推理训练中的熵坍缩、无效组和长度 bias. 这些部件可以与组相对 advantage 同时使用,却不属于 DeepSeekMath 原始公式. Dr. GRPO 主要针对标准差与长度归约 bias,GSPO 改变 ratio 粒度,DAPO 则组合多项训练改动. 复现实验要按公式核对,不能只按项目名称推断.

**变体选择的实践判断。**

三个变体 (原始, Dr. GRPO, GSPO) 的差别可以压成一句选型建议: 训练初期 reward 稀疏、组内方差大时, 标准差归一带来的尺度不稳定比它声称的 length bias 更实际, Dr. GRPO 的去归一更稳; 训练后期信号密集、长回答变多时, 按长度归约的 bias 开始显性化, 再评估换 GSPO 或调 loss denominator. 不建议在第一次复现时同时引入多个变体——先把原始配方跑通拿到基线曲线, 每次只改一个开关, 这是五个开关拆分的直接用途.

社区里还有一批不改名的小改动: clip-higher (上界放宽, 给正确回答更大的更新空间), token-level loss 归约 (分母从组内 token 总数改成按回答), dynamic sampling (在线丢弃全对全错组并按需补采). 它们单项影响不大, 叠加后却会改变训练动态; DAPO 的贡献之一正是把这些 trick 系统化成消融. 因此「GRPO 训出了某能力」必须连同具体配方理解, 含有这些改动的实现与原始算法并不等价.

**可验证奖励、训练协议与工程边界。**

GRPO 在数学推理中常配合规则验证器:答案可以由 exact match、执行结果或形式化检查给出 reward. 可验证降低了 reward model 的主观误差,仍然会受到解析、等价答案和 reward hacking 影响. 训练协议需要冻结 old policy 生成整组回答,用固定 verifier 计算 reward,再做有限轮 policy update. Reference policy、old policy 和 current policy 各有不同职责,任何版本混用都会改变 ratio 或 KL. 每轮训练都应保留逐 prompt reward 向量,这样 zero variance、ties 与异常过滤可以事后复算. 没有这个向量, 事后遇到「某段 loss 异常」就只剩猜测, 无法回放当时的组统计.

**核心公式与版本链。**

三份 policy 不能混为一个对象. Reference policy $\pi_{ref}$ 在一次内层优化窗口中冻结,用于 KL 锚定;有些配方让它跨整段 RL 固定,DeepSeekMath Algorithm 1 的 iterative GRPO 则会在外层 iteration 将 reference 重置为当前 policy. Old policy $\pi_{old}$ 是本轮 rollout checkpoint,生成组样本并提供 ratio 分母;current policy $\pi_\theta$ 在 minibatch 更新中变化,提供 ratio 分子. 一轮结束后,current 才成为下一轮 old;reference 是否同时更新必须由 recipe 明确规定. 若 reference 也随每轮更新,KL 坐标不断移动;若组内回答来自不同 old checkpoint,组 reward 与 ratio 不再共享采样分布;若重算 old log-prob 时使用了新 chat template,分母也失去原含义. 版本 manifest 应同时记录三者 checkpoint、tokenizer、template 与采样参数.

一个具体的事故模式: 异步流水里 rollout worker 和 trainer 的 tokenizer 或 chat template 版本不一致时, old log-prob 是 template A 下算的, training 前向在 template B 下重算, ratio 分母系统性偏掉, clip 大量触发而 loss 看起来还在降. 这类事故从外面看像「训练发散」, 根因却在数据管线, manifest 和启动时的版本断言就是为此准备的.

| 公式名称      | 数学表达式                                                                                            | 关键符号说明                          |
| --------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 组优势 (原始) | $A_i = (R_i - \bar{R}) / \sigma_R$                                                                    | $\bar{R}$=组均值, $\sigma_R$=组标准差 |
| 组优势 (Dr.)  | $A_i = R_i - \bar{R}$                                                                                 | 无标准差归一化                        |
| GRPO损失      | $-\mathbb{E}[\frac1G\sum_i\frac1{|y_i|}\sum_t\min(\rho_{i,t}A_i,\operatorname{clip}(\rho_{i,t})A_i)]$ | $\rho_{i,t}$ 是逐 token 比率          |
| 组均值基线    | $\bar{R} = \frac{1}{G}\sum_j R_j$                                                                     | $R_j$=第$j$个response的奖励           |

**可执行验证与失败分类。**

可验证 reward 也需要错误分类. `wrong_answer` 表示 verifier 成功运行且答案不满足条件;`parse_error` 表示输出无法进入判定器;`verifier_error` 表示检查程序本身失败;`environment_error` 表示执行环境不可用. 后两类若直接记成零分,会污染组均值并惩罚 policy 无法控制的故障.

数学答案还存在等价表示. 字符串不同可能在代数上等价,单位、区间端点和多解集合也需要规范化. Verifier 应用参考正确解、等价解和已知错误解做回归测试,并固定版本. 规则可执行不代表规则没有漏洞;policy 可能学会输出触发 parser 缺陷的文本. Group size 影响同时采到成功与失败的概率. 设单次成功率为 $p$,组内全同 reward 的概率为

$$
p^G+(1-p)^G.

$$

例如 $p=0.5,G=2$ 时该概率是 $0.5$;增大到 $G=4$ 时是 $0.125$. 更大组更容易获得相对信号、组均值也更稳定,但 rollout 成本线性增加. 当 $p$ 极接近 $0$ 或 $1$ 时,即使扩大组也可能频繁全错或全对,动态采样或调整题目难度才更有效. 评测至少同时报告 reward、zero-variance group 比例、有效 group size、clip fraction、KL、response length 与 verifier error. 只看平均 reward,无法区分 policy 真正改善、采样温度改变、无效组被过滤或验证器版本变化. 其中 zero-variance group 比例最值得单独追踪: 它直接反映 prompt 难度分布和采样预算是否匹配, 比例持续偏高说明大量 rollout 在空转, 是调整难度筛选或组大小最直观的依据.

**采样预算与 prompt 难度分布。**

GRPO 的信号量由采样预算决定, 预算的分配和组大小一样是能调的设计. 直觉上 prompt 分三档: 模型基本全对的 (pass rate 接近 1), 基本全错的 (接近 0), 和有时对有时错的. 只有第三档在固定组大小下能稳定产生非零 advantage: 全对组的 advantage 全零 (没有学习信号), 全错组也全零. 训练的有效样本占比因此远低于采样量, 这是 GRPO  rollout 贵的原因之一. 把无效组过滤掉再报「每组平均成本」会掩盖这一点, 统计口径里应保留过滤前的数字.

据此有两条预算策略. 一是难度加权采样: 按预估 pass rate 偏向中间档 prompt 采样, 预估器可以用一个轻量 reward model 或历史 rollout 统计. 二是动态组大小: 对预估方差大的 prompt 采更多条. 两条都在开源框架里有实现, 但都不是 DeepSeekMath 原配方, 引入时要重新验证. 还有一个省预算的方向: 全对组并非完全无用——它们贡献 KL 约束项, 防止 policy 在已掌握的题目上漂移; 把全对组整体丢掉会静默削弱 KL 正则, 过滤策略要和 KL 系数一起重新调.

工程上, rollout 和 training 的配比也是预算问题. Rollout 是串行的自回归生成, training 是并行的梯度计算, 两者硬件特征不同; 成熟的做法是 rollout 与 training 异步流水, rollout worker 持续产组, trainer 消费组, 中间用队列解耦. 队列深度的选择影响 policy 版本的新鲜度: 队列越深, 消费时 policy 离产出组的 old checkpoint 越远, ratio 越偏离 1, clip 触发率上升, 有效梯度变少. 同步更新则没有这个问题, 代价是 rollout 期间 GPU 空闲, 硬件利用率掉一半左右; 选异步还是同步, 本质是花钱买利用率还是买估计精度. 监控 clip fraction 是观察这个漂移最直接的指标. 当 clip fraction 持续走高, 第一反应应是收缩队列或加快权重同步, 而不是调大 clip 范围把症状压下去.

---

**从 PPO 到 GRPO 的逐项消元。**

PPO 的 actor 更新依赖优势 $\hat A_t$，而优势通常由 reward-to-go 减去 critic 估计的状态价值。LLM 推理轨迹很长、最终奖励稀疏，训练一个与 policy规模相近的 critic既占显存，也要面对值函数拟合误差。GRPO 保留 old policy ratio、clip 与 KL 约束，用同 prompt 的一组采样奖励构造相对优势，省去显式 critic。 对 prompt $x$，old policy 生成 $G$ 条回答 $o_1,\ldots,o_G$，每条得到序列奖励 $R_i$。原始常见形式定义

$$
\bar R=\frac1G\sum_{j=1}^G R_j,
\qquad
s_R=\sqrt{\frac1G\sum_{j=1}^G(R_j-\bar R)^2+\epsilon},
$$

$$
\hat A_i=\frac{R_i-\bar R}{s_R}.
$$

同一条回答的优势随后广播到所有 response token。这个量表示该 prompt、该采样组内的相对序列成绩，不具备状态价值优势的逐步语义。critic 被组均值替代后，时间维信用分配仍由序列标签近似。 PPO token ratio 为

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(o_{i,t}\mid x,o_{i,<t})}
{\pi_{old}(o_{i,t}\mid x,o_{i,<t})}.
$$

clipped surrogate 写为

$$
L_{clip}=-\mathbb E_{i,t}
\left[\min\left(
ho_{i,t}\hat A_i,
\operatorname{clip}(\rho_{i,t},1-\varepsilon,1+\varepsilon)\hat A_i\right)\right].
$$

$\hat A_i>0$ 时，ratio 上升超过 $1+\varepsilon$ 后被截住；$\hat A_i<0$ 时，ratio 下降低于 $1-\varepsilon$ 后被截住。`min` 与 advantage 符号共同决定有效边界，不能先 clip ratio 再统一解释。 KL 项通常约束当前 policy 与 reference，而 ratio 的分母是 old policy。两者角色不同：old policy控制一次或若干次更新相对采样策略的步长，reference限制相对 SFT/初始模型的长期漂移。把两个模型混称为 reference 会导致实现与日志混乱。 一个常见采样—更新周期为：冻结 $\pi_{old}$ 生成组，计算 reward 与优势，随后对同一 rollout做若干 minibatch epoch；周期结束再令 old policy追上当前 policy。epoch 越多，数据越 off-policy，ratio 与 clip越重要。若每一步都重新采样，计算成本更高，分布最接近 on-policy。

critic 消失后，显存和训练组件减少，方差转移到组采样。$G$ 越大，组均值更稳定、每个 prompt 的 rollout成本越高。相同总生成预算下，提高 $G$ 会减少独立 prompt数，组内估计与任务覆盖形成直接取舍。

## 3. 组均值估计的偏差与方差

### 3.1. Leave-in baseline 的相关性

$R_i-\bar R$ 的 baseline 包含当前样本自身。写成

$$
R_i-\bar R=\frac{G-1}{G}left(R_i-\bar R_{-i}\right),
$$

其中 $\bar R_{-i}$ 是除去 $i$ 的均值。leave-in 形式相对 leave-one-out 缩小 $(G-1)/G$。再除组标准差后尺度变化更复杂，但自包含相关性仍存在。 在经典 REINFORCE 中，baseline若依赖当前动作会引入偏差。GRPO 的组构造和归一化不是简单的 action-independent baseline；其目标更适合解释为组内相对优化估计器，而非逐样本无偏策略梯度的直接替代。

**组大小的方差。**

假设同 prompt 奖励独立同分布，均值方差为 $\sigma_R^2/G$。增大 $G$ 改善 prompt 内基线估计，也减少固定预算下的 prompt覆盖。若 reward为 Bernoulli，组内全同的概率为

$$
p^G+(1-p)^G.
$$

$p$ 接近 0 或 1 时，即使 $G$ 不小，全同组仍常见；$p\approx0.5$ 时多样组更多。训练数据会自然集中在当前模型成功率居中的 prompt。 这种自动课程可能有益：太易和太难题都少更新，边界题提供最多信号。它也可能遗忘容易能力，并永久放弃极难题。固定回归集、难题补充信号与 prompt重采样用于控制这一偏好。

**跨 prompt 不可比较。**

标准化后每个非退化组均值为零、方差约一。奖励尺度大的 prompt 与尺度小的 prompt被拉到相近范围，组内相对名次主导更新。这样减少 reward尺度异质性，也丢失跨 prompt绝对难度与价值差异。 一个高风险任务的微小奖励差，可能与普通任务的巨大差异获得相似标准化权重。业务权重应在 prompt采样或显式系数中表达，不能指望组标准差保留绝对价值。

**标准差归一化的难题偏置。**

当组奖励方差很小但非零，除以小 $s_R$ 会放大细小差异。二元奖励中，一组只有一个成功或一个失败时，优势幅度随成功比例变化。不同难度 prompt因此获得不同隐式权重。 Dr. GRPO 去掉标准差除法，保留中心化 $R_i-\bar R$，减少小方差放大。代价是 reward尺度重新进入梯度。二者没有脱离 reward设计的统一胜者，应在相同 prompt与预算下比较。

**Leave-one-out 对照。**

RLOO 对每条样本使用其他 $G-1$ 条 reward均值作为 baseline：

$$
\hat A_i^{RLOO}=R_i-\frac1{G-1}\sum_{j\ne i}R_j.
$$

它去掉自身 reward对 baseline 的直接影响，和中心化 GRPO只差确定缩放时不做标准差归一化。加入 std 后，GRPO又多了组尺度变化。比较两者时先对齐归一化、token reduction与 KL。

### 3.2. 全同组、稀疏奖励与课程偏差

组内 reward全相同时，中心化优势全为零。$\epsilon$ 只能防止除零，不能创造方向。若所有回答都失败，GRPO不知道哪条“没那么坏”；若全部成功，也不知道哪条更优。 对稀疏二元奖励，极难 prompt常产生全失败组，被训练静默跳过。提高 $G$ 增加偶然成功概率，成本呈线性增长；改进采样温度、课程难度或提供部分奖励，可能更高效。

部分奖励可以来自答案格式、步骤验证、单元测试通过数或工具阶段成功。它增加密度，也引入 reward hacking。每个 shaping项都要用反例检查：格式正确但答案错误、通过公开测试但隐藏测试失败、调用工具却未完成任务。 全成功组也可能仍有长度、效率和解释差异。二元 verifier看不到这些维度。加入次级 reward会改变任务目标，必须明确优先级，避免风格分盖过正确性。 只丢弃全同组会改变 prompt分布。训练日志中的“有效 prompt”越来越集中于中等难度，原始采样数量无法代表实际更新覆盖。报告 sampled、nonzero-advantage和产生有效梯度的 prompt数。

可用自适应 $G$：先少量采样，检测全同后追加 rollout。它把预算集中到可能获得方差的 prompt，却引入基于早期 reward的选择。评估成本与分布时记录最终组大小和追加规则。 困难题若长期全失败，可以由更强 teacher生成成功轨迹，或先做 SFT/mid-training再进入 GRPO。把 teacher回答直接混入同组会改变行为策略与 ratio，需要区分 on-policy样本和外部示范。 容易题长期全成功仍应保留少量回归评估。训练不更新不表示能力永远保持，其他 prompt梯度可通过参数共享造成遗忘。定期采样或 replay用于监测。

**Token 与 Sequence 归约。**

**序列奖励广播的含义。**

同一 $\hat A_i$ 赋给回答每个 token，表示整条轨迹的相对结果共同监督所有动作。成功答案中的错误绕路也被提高，失败答案中的正确前缀也被压低。GRPO 没有定位关键步骤的机制。 当 verifier只看最终答案时，信用尤其粗。过程 reward、步骤验证或 outcome-to-go可以改善定位，同时增加标注与建模假设。原始 outcome GRPO的结论不能直接归到这些扩展。

**Token mean 与 sequence mean。**

先对所有有效 token取 mean，相当于每个 token等权，长回答贡献更多 token；先在每条 sequence内 mean，再跨 sequence mean，使回答等权。两种 reduction在长度差异大时给出不同目标。 设短回答 10 token、长回答 100 token。token-global mean中长回答约占十倍权重；sequence mean中二者各一半。若长回答更常成功，前者会放大长度与奖励相关性。

**Length bias 的两个方向。**

长回答产生更多 token梯度，在 token等权目标中占比高；sequence内平均又让每个 token系数随长度反比。不同实现可能偏长或偏短，不能只说“GRPO 有长度偏置”而不写 reduction。 EOS 也是动作。漏掉 EOS会低估终止决策，截断样本伪造 EOS会奖励到达最大长度。按自然结束、截断和异常缺尾分别统计。

**Token ratio 与 sequence ratio。**

原始 PPO式 GRPO对每个 token计算 ratio并 clip。GSPO等方法改用 sequence-level ratio，减少长序列中 token独立裁剪造成的不一致。sequence ratio是 token ratio的乘积，直接计算会有数值与方差问题，常在 log空间聚合。 token clip允许同一回答部分位置被截断、部分仍更新；sequence clip让整条轨迹共享一个步长判断。前者粒度细，可能破坏轨迹整体性；后者一致性强，长序列 ratio方差更大。选择需结合采样复用与长度。

**按长度分桶的反事实。**

评估将组按成功答案比失败答案更长、等长、更短分桶，分别报告 advantage、clip fraction和生成变化。再构造相同答案增删冗余的反事实，测试 reward和 policy是否利用长度。 只看最终平均长度无法判断。变长可能增加必要推理，变短可能去除冗余，也可能省略步骤。任务成功与完整性指标必须同行。

**Clip、KL 与策略步长。**

clip限制 old-policy ratio 对 surrogate的收益，不是严格 KL trust region。大量 token同时位于边界内，整条序列分布仍可明显变化；已超出边界的 token也可能被其他 loss更新。 clip fraction应按 advantage符号、位置、长度和任务分桶。总体比例相同，可能是少数长回答大量 token被 clip，或许多回答各少量位置被 clip，行为含义不同。 KL penalty常使用 reference模型，并有多种估计形式。`k1` log-ratio、非负近似与完整词表 KL的偏差/方差不同。写明公式、采样分布和 reduction，不能只报一个“KL”。 old policy与 reference可能相同于训练第一步，随后角色分离。多 epoch内 old固定，当前 policy移动；reference通常跨周期固定。若 rolling reference，长期约束也改变。

增大 KL系数能限制漂移，也可能压制探索成功轨迹，尤其当 reference对正确长推理概率低。质量—KL前沿比单一系数更有解释力。clip、KL和学习率共同决定步长，需要联合扫描。 自适应 KL controller根据观测 KL调系数，会引入另一动态系统。观测估计噪声、目标 KL与控制速度影响稳定性。日志保存 controller状态，恢复训练时不能重置。 ratio 的 old log-prob cache绑定 policy版本、tokenizer、模板、mask与精度。采样后重新格式化文本会改变 token序列，ratio不再对应真实行为策略。rollout产物应保存原 token与 old log-prob。

## 4. On-policy 与 Off-policy 边界

严格 on-policy要求样本由当前待更新 policy生成。实际 GRPO先采样再做多次更新，从第二个 minibatch epoch起就逐渐 off-policy。ratio进行重要性修正，clip限制高方差，但不能完全消除分布偏差。 policy lag来自异步 rollout worker、权重广播延迟和队列积压。吞吐提高时，样本可能由多个旧版本产生。每条轨迹保存 producer version，按 lag分桶看 ratio与 clip。 混合不同 old policy的 batch时，每条 token必须使用自己的行为 log-prob作分母。统一用最近 checkpoint重算，会把行为概率改写成未发生的分布。若 producer配置含不同温度，行为概率还包括采样温度变换。

top-k、top-p和 grammar mask改变行为支持。训练 policy的未截断 softmax与实际采样分布不同；ratio究竟用模型概率还是采样后概率，需要与目标一致。行为支持外的 token无法由重要性采样恢复。 外部 teacher轨迹、replay buffer与历史成功样本属于 off-policy数据。可以用于 SFT或专门离线目标；直接塞进 GRPO ratio需要已知行为概率和支持条件。没有 log-prob时不能假装由 old policy生成。 增加 PPO epoch提高样本利用率，也增加 ratio方差与 clip比例。报告每批实际更新次数、policy lag、effective sample size和最终生成质量。只按训练 step比较会遗漏 rollout复用。 近似有效样本量可由重要性权重计算 $(\sum w)^2/\sum w^2$。少数极端 ratio会让有效样本量远低于 token数。clip降低极端影响，同时引入偏差。

### 4.1. 与 PPO、RLOO 的精确关系

PPO 使用 learned critic估计状态价值，能为不同时间步提供 advantage；GRPO用同 prompt组 reward中心化，通常整条序列共享 advantage。去掉 critic节省资源，也失去逐状态价值与跨 prompt绝对基线。 RLOO用其他采样的 reward均值作 baseline，避免自身包含在 baseline。若 GRPO去掉 std并适当缩放，二者中心化方向接近。实现中的 KL位置、token reduction、clip与 reward shaping仍可能不同。 PPO的 GAE在稠密时序 reward下平衡 bias与variance；最终 outcome reward时，所有早期 token都依赖相同回报。GRPO不是 GAE的等价替换，它更像用多轨迹横向比较替代纵向 critic。 固定 rollout预算下，PPO可为更多 prompt各采少量轨迹并依靠 critic泛化；GRPO需要每 prompt一组才能估 baseline。哪个方差更低取决于 critic质量、组大小、prompt异质性与 reward。

critic若严重失准会系统偏置优势，GRPO避免这类误差；组 reward若全同或 std很小，GRPO失去信号或放大噪声。二者只是把估计难点放在不同位置。 公平比较要对齐生成 token、prompt数量、更新 token、KL、模型与 reward。GRPO省 critic训练，但更多同 prompt rollout也有成本。总 wall-clock与显存均应报告。

### 4.2. 奖励设计与可验证性

可验证 reward 的优势是标签明确、规模化便宜。数学最终答案、代码测试、格式约束与工具状态都能自动检查。验证器覆盖范围决定训练目标，漏掉的质量维度不会自动出现。 最终答案 verifier可能奖励猜测。模型输出正确数字但推导错误，仍得满分；过程很接近但算术笔误，可能全零。加入过程检查能增加密度，也可能把特定解法固化。reward设计必须与任务成功定义一致。 代码公开测试会被 reward hacking。模型可硬编码样例、利用评测漏洞或生成超时程序。隐藏测试、资源限制、静态安全和多版本测试共同降低漏洞。训练与评估测试严格隔离。

格式 reward常比正确性容易学。若多个 reward直接相加，模型可能先靠格式获得稳定分数，组内优势被格式差异主导。设置正确性门控，例如失败时格式分不生效，可以保持任务优先级。 reward尺度影响 std normalization。给正确性 1 分、格式 0.1 分与把二者放大十倍，在标准化 GRPO中组内线性缩放大体抵消；去 std 的 Dr. GRPO则梯度随尺度变化。算法变体与 reward标度要联合讨论。 非线性裁剪、门控和多项组合会改变排序。两个回答总分相同可能在关键维度不同。日志保留各 reward分量与总分，按分量构造反事实。

人工或模型 judge reward更稠密，带入偏见与可利用模式。若 judge同时用于训练和评估，胜率是同源一致性。加入可执行指标、独立人评或另一 judge。 长程工具任务的终局状态可验证，轨迹中间观察随机。reward只归因于 policy动作，环境失败与工具服务错误要区分。将系统故障记为模型零分会训练错误回避。

## 5. 组采样预算与 Prompt 分布

固定总 rollout数 $B$ 时，组大小 $G$ 意味着约 $B/G$ 个 prompt。大组改善 prompt内相对估计，小组提高任务覆盖。最佳 $G$ 取决于 reward成功率与 prompt异质性。 二元 reward下，一个组产生信号的概率为

$$
1-p^G-(1-p)^G.
$$

若 $p=0.5,G=4$，有效概率为 $0.875$；若 $p=0.05,G=4$，约为 $0.185$。极难题仅增加小幅 $G$ 仍多为全失败。先提高 policy成功率或提供 shaping通常更重要。 自适应组大小可根据首批结果追加采样。首批全失败不代表追加必然无用，追加上限与停止规则要明确。选择性追加使每个 prompt成本不同，训练权重与数据统计必须按实际组记录。 prompt sampler决定课程。均匀题目、按难度、按线上流量和按有效组概率采样对应不同目标。追逐高方差 prompt会提高学习信号，可能忽略重要但当前全失败/全成功的任务。

可以混合三股数据：线上分布保证代表性，边界题提高学习效率，固定风险集维持关键能力。三者比例写入配置，验证按部署权重汇总。 同一 prompt反复生成会记忆题目。语义近重复模板也会造成过拟合。训练验证按题源、模板、时间和语义簇切分，数学与代码按生成种子与测试结构去重。 采样温度改变组方差。低温容易全同，高温增加行为多样性，也产生无意义错误。混合 greedy、常温与较高温候选可覆盖不同区域；行为 log-prob必须对应实际温度与截断采样。

组内候选若通过 best-of-n预筛，再用于 GRPO，reward分布已被选择器改变。保存未筛选随机流估计偏差。只在高分候选上训练会丢失失败模式。

### 5.1. 完整数值手算

设同一 prompt采样四条回答，reward为 $(1,1,0,0)$。组均值 $0.5$，population std为 $0.5$，标准化优势为 $(1,1,-1,-1)$。若只中心化，则为 $(0.5,0.5,-0.5,-0.5)$，方向相同、尺度减半。 取某个正优势 token ratio $\rho=1.3$、clip $\varepsilon=0.2$。未裁剪项为 $1.3$，裁剪项为 $1.2$，`min` 取 $1.2$；继续提高 ratio不再增加 surrogate。负优势 $A=-1$ 且 $\rho=0.7$ 时，未裁剪为 $-0.7$，裁剪后为 $-0.8$，`min` 取 $-0.8$，对应 loss惩罚不再因继续降低 ratio而改善。 若正优势 ratio为 $0.7$，未裁剪 $0.7$、clip项 $0.8$，`min` 取 $0.7$，梯度仍推动上升。负优势 ratio为 $1.3$ 时，未裁剪 $-1.3$ 比 clip项 $-1.2$ 更小，梯度仍推动下降。clip只截断“朝有利方向走太远”的收益。 再看稀疏组 $(1,0,0,0)$。均值 $0.25$，population std为 $\sqrt{3}/4\approx0.433$，优势为成功样本 $\sqrt3\approx1.732$，失败样本各 $-1/\sqrt3\approx-0.577$。唯一成功得到更大正权重，三个失败总和抵消。

组 $(1,1,1,0)$ 则相反：三个成功各约 $0.577$，唯一失败约 $-1.732$。标准差归一化让少数类获得更大单样本幅度。它会强调组内稀有结果，无论稀有的是成功还是失败。 全组 $(0,0,0,0)$ 加 $\epsilon$ 后优势仍全零。若实现得到非零，reward、mean或 mask存在错误。全组常数 reward平移也应保持优势不变。 把 reward全部乘 10，在无 $\epsilon$ 主导时标准化优势不变；只中心化的优势乘 10。这个不变量能区分 GRPO 与 Dr. GRPO实现。给 reward加常数，两者中心化后都不变。 序列有不同长度时，明确 reduction。短序列两个 token、长序列四个 token，sequence mean先各自平均再取均值；token mean则长序列占两倍。手算二者并写入单元测试。

KL 项若按 token mean，也要确认与 policy loss的归约兼容。某些实现 policy按 sequence等权、KL按 token等权，长回答受到更强正则。不是必然错误，但目标需要写清。

### 5.2. 长度与信用分配反例

成功长答案包含一段关键推理和大量冗余，整条序列共享正优势。GRPO会提高冗余 token，只因它们与成功同轨迹。之后模型可能生成更长答案，增加碰到正确结论的机会，也增加成本和错误。 失败答案前半段推理正确、末尾算术错误，所有 token共享负优势，正确前缀也被压低。过程 verifier或分段 reward可减轻，但需要可靠的步骤标签。 两个答案结论都正确，短答案 reward与长答案相同，组内全同则无更新。若目标偏好简洁，需要效率 reward；若目标需要解释，需要完整性 reward。二元正确性无法决定风格。

截断答案若未给出结论通常得零，模型会学习更早输出答案。这可能提高成功，也可能诱导“先猜后解释”。单独检查答案位置、推理完整性与 EOS。 token-global mean放大长轨迹，sequence mean让短轨迹每 token系数更大。结合 reward与生成变化做长度反事实，不能从公式名字推断方向。 多轮 agent轨迹中，早期工具选择决定最终成功。序列 reward广播会提高所有后续措辞，局部 credit模糊。共享前缀下比较下一动作或学习 value能提供更精细信号，已超出原始 GRPO。 环境观察不属于 policy token。把搜索结果、测试输出或用户消息纳入 loss，会给不可控文本梯度。action mask必须逐段验证。

## 6. 统计误差与置信区间

同组回答共享 prompt，reward与梯度相关。把 $G$ 条回答当独立样本计算区间会低估方差。评估以 prompt group为 cluster，训练有效样本量也更接近 prompt数而非轨迹数。 prompt又可能来自相同模板或题源，需要更高层 cluster。十万 rollout若来自少数题型，不能代表十万独立任务。报告 prompt、语义簇、题源和有效组数。 组标准差是有限样本估计。使用 population分母 $G$ 还是 sample分母 $G-1$ 会改变尺度，尤其小 $G$。实现与公式必须一致。$\epsilon$ 的位置是在方差内还是 std后相加，也会改变小方差组。 reward噪声经过标准化后可能放大。重复执行 verifier、固定随机种子或估计环境方差，区分策略差异与环境随机。随机工具失败不应决定组内 winner。

多随机种子报告训练结果。RL rollout、prompt顺序和少数成功轨迹会造成路径依赖。一次成功训练不足以说明配方稳定。 比较算法时使用配对 prompt与相同生成预算，bootstrap prompt差值。只比较各自均值会混入题目难度。tie和执行异常单独报告。 统计显著与任务价值分开。容易题大量小提升可能显著，关键难题仍全失败。按难度、任务和风险报告效应与区间。

### 6.1. 可证伪的实验设计

若声称 std normalization提高稳定性，比较标准化、仅中心化与固定 reward尺度，在相同 KL与预算下报告梯度、有效组和生成。小 loss方差不等于更好策略。 若声称 GRPO省 critic且不损失效果，与 PPO对齐 rollout token、更新 token、显存和 wall-clock。报告 critic质量与解释方差。只数模型参数不够。 若声称组内估计改善难题，按初始成功率分桶。理论上中间成功率组信号最多，极难组全失败。结果不符合时检查 reward密度、采样温度和 prompt sampler。 若声称长度无偏，比较 token/sequence reduction与长度反事实。chosen更长、等长、更短桶都要报告。最终平均长度不足以证明。 若声称多 epoch提高样本效率，按 policy lag、ratio、clip fraction和 effective sample size展示收益。生成退化时不能用训练 throughput抵消。

若声称 KL控制漂移，使用独立 policy采样或完整词表 token KL验证。训练 estimator可能有偏。能力回归与 KL同行。 若声称过程涌现来自 outcome reward，构造最终答案相同、过程正确性不同的样本，并做独立过程评估。只看最终 benchmark无法证明推理过程改善。 若声称某变体优于原始 GRPO，逐项消融 std、clip、ratio level、overlong handling与 sampling。一次替换多个组件无法定位原因。 主要指标、停止规则和切片预先定义。反复看同一测试挑 checkpoint会产生开发过拟合。最终集一次性评估。

### 6.2. 训练与发布验收

rollout manifest保存 prompt、producer policy版本、解码、token、old log-prob、reward分量、环境版本和结束状态。训练重算必须使用相同 token与 mask，不能把文本重新模板化。 日志包含组 mean/std、全同率、有效 prompt数、优势分位数、ratio、clip fraction、KL、长度、截断、梯度范数和 reward各项。按难度、任务、长度与 producer lag分桶。 数值测试覆盖 reward平移/缩放、全同组、单成功/单失败、advantage和为零、clip四象限、padding/EOS、token/sequence reduction、多卡归约与恢复一致。 训练恢复保存 policy、old policy版本、optimizer、scheduler、随机状态、dataloader cursor、KL controller和 rollout队列。恢复后 producer version与 ratio分母必须一致。 上线评估使用最终服务栈，包括量化、模板、工具与 stop rule。固定离线回归、未见 prompt生成、可执行任务、安全、多语言、长度和成本全部通过后再发布。

回流数据保留随机探索与旧模型候选，避免当前 policy模式自我强化。固定风险集与容易题回归，防止训练只关注中等难度。 回滚条件预先定义。严重安全、关键成功率或系统性事实退化触发回滚；普通波动等待足够 prompt。模型、模板、解码与工具配置作为一个版本回滚。

**从一次 Rollout 到可复现结论。**

一次完整 GRPO 数据流从 producer policy版本开始。rollout worker拿到权重、tokenizer、模板和解码配置，对 prompt生成 $G$ 条原始 token序列，同时保存每个 policy action 的 old log-prob。reward worker在版本化环境中计算各分量，trainer按 prompt group构造优势，再执行 ratio、clip、KL与归约。 任何阶段重建文本都可能破坏行为概率。清理空格、重新套 chat template、替换 EOS或截断，会让保存的 old log-prob与训练 token不匹配。rollout产物以 token IDs为权威，文本用于审计，不用于重新定义轨迹。 producer policy包含权重与采样变换。温度采样时，行为分布来自缩放后的 logits；top-p进一步截断并重新归一化。若 ratio分母使用原始模型 softmax，它不等于实际行为策略。目标究竟校正到哪种分布，需要在实现中明确。

许多训练框架保存模型下的 log-prob，而采样 truncation仅用于选择 token。这样得到的是针对未截断模型分布的 surrogate，不是严格行为重要性比。它可能实践有效，理论解释应限定。对照实验可关闭 top-p，只保留温度，观察差异。 异步系统中，rollout队列含多个 producer版本。每条轨迹绑定 version与 log-prob；trainer当前 policy与对应 old逐项计算 ratio。用最近 old checkpoint替换所有分母，会系统误估 lag较大的数据。 policy lag不仅按 step衡量，还看参数与分布距离。相同十步在训练早期与晚期差异不同。按 producer-current KL或 ratio分位数分桶，比只记版本差更准确。

若 lag过大，大量 token触发 clip，轨迹贡献降低，生成算力被浪费。队列长度、权重广播频率与 PPO epoch共同决定有效利用率。吞吐优化应同时看生成 tokens/s和未被 clip的有效 token比例。 clip fraction高不一定意味着所有轨迹失效。正负优势边界不同，同一序列部分 token仍有梯度。记录 sequence中 clipped token比例，并统计完全无 policy-gradient贡献的轨迹，更接近实际利用率。 KL 梯度仍可能更新被 policy surrogate clip住的 token。说“clip后不再更新”只针对 clipped surrogate对应方向，不包含 KL、entropy或其他辅助 loss。调试时分别计算各项梯度范数。 entropy bonus若存在，会鼓励分布展开，与 reward和 KL共同作用。推理 RL中熵变化可影响探索、长度和模式坍缩。即使系数为零，也记录 policy entropy作为诊断。不同框架的 entropy reduction可能按 token或sequence。

KL penalty的参考方向也要确认。常见采样估计从当前 policy轨迹计算 log policy/reference ratio，期望对应正向 KL；某些近似为了非负性加入指数项。公式不同，数值不可直接比较。 若 KL按 old-policy rollout采样，而 current policy已更新，估计分布并非当前 policy。多 epoch中偏差增大。可以在固定 probe prompt上用 current重新采样独立 KL，验证训练日志趋势。 clip与 KL可能重复限制步长，也可能作用于不同坐标。clip相对 old，KL相对 reference；rolling old每周期更新，固定 reference长期不动。训练后期 current与 old很近、与 reference很远时，clip fraction低而 KL高完全合理。 学习率同样决定 ratio移动。增大 clip范围但降低学习率，实际步长可能更小；单独报告 $\varepsilon$ 无法描述更新。质量—KL—计算前沿比单点超参数更适合比较。

组优势若按 batch重新计算，而 reward模型或 verifier版本变化，同一 rollout的 advantage也会变化。reward结果应随轨迹冻结，版本升级后重算需形成新数据版本，不能在训练中静默混合。 环境随机任务可对同一轨迹重复执行，估计 reward噪声。若噪声接近组内差异，排序不可靠。增加执行次数、固定随机种子或使用置信区间 reward。重复执行成本也纳入预算。 二元 reward组的标准差由成功数决定。设成功 $k$ 条、失败 $G-k$ 条，均值 $p=k/G$，方差 $p(1-p)$。成功优势为 $(1-p)/\sqrt{p(1-p)}=\sqrt{(1-p)/p}$，失败优势为 $-\sqrt{p/(1-p)}$。少数结果获得更大幅度。 这个公式显示，唯一成功的正优势约 $\sqrt{G-1}$，唯一失败的负优势约 $-\sqrt{G-1}$。随着 $G$ 增大，稀有结果幅度增长。std normalization不是简单稳定尺度，它显式强调组内少数类。

若 rare success是真正突破，这种放大有益；若来自 verifier误判或随机执行，影响也被放大。单成功组与单失败组应成为重点审计切片，统计其复验通过率。 加入 $\epsilon$ 后，小组和极小 reward差的幅度受实现影响。$\sqrt{var+\epsilon}$ 与 $\sqrt{var}+\epsilon$ 不等价。固定数值例子覆盖零方差、微小方差和正常方差，确保配置迁移不改公式。 连续 reward若存在离群点，均值/std都受影响。winsorize、rank normalization或 robust scale可降低离群影响，同时改变目标。任何稳健化都要用已知 reward分布和生成结果消融。 rank advantage只保留组内次序，舍弃差值。它对 reward尺度与离群更稳，却把巨大质量差和微小差异视为相邻等级。可验证任务中，部分通过与完全错误是否值得同等间隔取决于目标。

组内标准化还可能让 reward hacking相对化。若整组都使用同一漏洞获得高分且分数相同，优势为零，不会进一步强化；若只有一条更会利用漏洞，它获得大正优势。增加对抗 verifier负责堵漏洞，归一化本身不提供安全保证。 奖励攻击测试应主动生成格式正确但内容错、公开测试通过但隐藏失败、答案正确但推理矛盾、工具调用成功但最终状态错误等轨迹。每个 reward分量都要有最小反例。 若 reward包含模型 judge，提示注入可出现在回答中。judge输入隔离、输出解析与对抗样本属于 verifier安全。policy会搜索任何稳定得分通道，不能把自然语言 judge当作不会被攻击的标注者。

组采样的多样性也要量化。不同字符串不等于不同推理路径。按最终答案、工具序列、语义簇和关键步骤去重。组内候选实际相同，reward方差再高也可能来自 verifier随机。 温度提高通常增加多样性，也会降低平均质量与行为概率稳定性。绘制温度—有效组率—成功率—生成成本曲线，选择带来最多有效学习信号的区域，而非盲目追求最大差异。 同一个 prompt可用混合解码策略生成候选，但组内样本不再来自同一行为分布。每条轨迹使用自己的行为 log-prob，组 baseline仍可比较 reward；理论与实现要记录解码策略标签。

prompt难度估计可来自历史成功率。按成功率分桶后，极易与极难组的有效率低，中间组高。sampler若只追逐中间桶，训练曲线漂亮，却不代表整体部署提升。线上权重评估与固定极难挑战集共同约束。 对极难题引入 teacher成功轨迹时，可将其用于 SFT暖启动，再由 policy重新采样形成 on-policy组。直接把 teacher轨迹与 policy失败放一组，teacher没有可用 old-policy ratio，不能按同一 surrogate处理。 对极易题，可以提高任务难度、增加隐藏条件或减少提示，而非反复采样全成功。课程变换会改变任务，保留原始题回归，确认能力未因追难题退化。

组大小自适应还会改变 prompt权重：追加采样的困难 prompt产生更多 token，token-global reduction进一步加权。若希望 prompt等权，应在最终 group内部归约，再跨 prompt平均。计算预算与训练权重分开处理。 分布式系统常把一个 group拆到不同 worker。组 mean/std必须跨完整 group计算，不能各 worker局部归一化。最简单测试是改变 group分片，优势与 loss保持一致。 若为了并行将不同 prompt候选混在一个 batch，group ID必须稳定。排序、packing或过滤无效样本后，不能按固定连续块猜 group。显式索引并测试组内 advantage和为零。

过滤超长或 verifier异常轨迹会改变组大小。剩余候选重新计算 mean/std，还是保留原组统计，需要明确。用已删除样本参与 baseline却不参与 loss，会产生隐藏权重；通常应在定义有效组后统一计算。 overlong punishment若给截断轨迹额外负 reward，会训练更早结束。它可能减少浪费，也可能压制必要长推理。按任务长度需求、答案位置和截断原因切片，不能只看平均 token下降。 动态最大长度随训练增加时，reward分布、全同率和成本都变化。每阶段分别报告，不把 curriculum阶段混成一条无解释曲线。长度升级前后固定 prompt对照。

在数学推理中，最终答案抽取器可能因格式失败给零分。模型随后更重视格式，未必提高推理。分别记录“无法解析”“解析但错误”“正确”，对解析失败提供格式修复信号，对内容错误保持任务信号。 代码执行失败也应分类：编译、测试、超时、资源、安全和环境。环境故障退出训练标签，模型错误保留。把所有非零退出码统一为零 reward会混淆原因。 agent任务的成功可能依赖外部状态。相同动作在不同网页或数据库版本得到不同结果。rollout保存环境快照或版本，回归评估固定环境。线上近期环境另做漂移测试。

训练日志中 reward上升可能来自 sampler变易、verifier更新或模型进步。固定 anchor prompt、固定环境和固定解码周期性评估，提供可比坐标。动态训练流与固定评估流不能混用。 advantage mean按组理论为零，跨训练 batch也应接近零。偏离可能来自 mask、过滤、权重或数值。按 group检查比看全局均值更敏感。std normalization后非退化组二阶矩也有预期值。 policy loss为负或正本身没有统一质量含义。surrogate受 advantage、ratio和 reduction影响。生成 reward、有效组率、KL与能力才是效果指标。不同实现 loss零点不同，不横向比较数值。 clip loss下降可能因更多 token进入饱和区，实际有效梯度减少。同步记录 unclipped objective、clipped objective与 clip fraction。只看最终 loss会把“无法继续利用数据”误作收敛良好。

KL低可能是更新保守，也可能是 policy梯度因全同组为零。将 KL与有效 advantage token数同行。若二者都低，先检查数据是否提供信号，再调正则。 KL高且 reward不升，说明更新离开 reference却未获得任务收益。检查 reward噪声、off-policy lag、学习率和长度捷径。继续训练通常只扩大漂移。 reward升而通用能力下降，说明目标窄化。加入固定能力门槛、SFT replay或更强 KL都可尝试；每种方案改变预算与目标，需消融。不能用训练 reward抵消广泛遗忘。 SFT replay与 GRPO混合时，分别记录梯度范数与 token来源。replay可稳定格式和知识，也会压制新推理策略。采样比例是主要超参数。

模型合并、量化和 adapter路由会改变 rollout概率。最终发布物重新生成评估，旧 policy轨迹不能直接用于新模型 ratio训练。任何新的 producer都开始新的版本链。 一次可信实验的最小产物包括：固定手算 group、版本化 rollout样本、reward/verifier测试、训练配置、曲线与 checkpoint、未见 prompt生成、能力/安全回归和成本。数据不能公开时，提供 schema与聚合分布。

最终结论应精确到机制。可以说“在该 reward和预算下，组内中心化无需 critic也获得某项提升”；不能从一次结果推出 critic永远无用、组标准化普遍无偏或长推理自然涌现。公式支持什么，实验测到什么，部署还未知什么，三者分开写。

**Clip 四象限的有限差分。**

clip 实现最容易在负优势上写反。固定 $A=1$，分别取 ratio $0.7,1.0,1.3$；再固定 $A=-1$ 重复。自动微分与解析分段对照，确认正优势只截上界、负优势只截下界。 边界恰好等于 $1\pm\varepsilon$ 时，框架的次梯度选择可能不同，测试允许边界点约定差异，边界两侧方向必须正确。用 $1\pm\varepsilon\pm10^{-4}$ 覆盖邻域，比只测远端可靠。 若代码先把 ratio clip再与 advantage相乘，数值 surrogate在常见公式中可等价，日志却可能误报“所有越界都被截断”。对不利方向，`min` 仍选择未裁剪项，梯度存在。测试直接检查参数梯度。 token mask也进入 clip统计。padding、prompt和环境观察不能计入 fraction。若大量 padding ratio默认 1，会人为压低 clip比例，让长短 batch不可比。

sequence内部分 token被 clip时，回答仍可能由其他 token更新。统计完全 clipped、部分 clipped和未 clipped三类轨迹，结合 advantage符号。仅给总体 token fraction无法判断样本利用率。

**KL 的三种手算口径。**

给定单 token词表，policy $p=(0.6,0.3,0.1)$，reference $q=(0.5,0.25,0.25)$。完整正向 KL 为

$$
0.6\log1.2+0.3\log1.2+0.1\log0.4.
$$

从 policy采样 token时，$\log p/q$ 的样本均值估计该 KL，但单样本可为负。不能因为某个 token log-ratio负，就判定 KL实现错误。 常见非负近似 $k_3=e^{qlog-p log}-(qlog-p log)-1$ 或等价写法在每个样本上非负，期望与真实 KL存在近似关系。具体方向和变量命名必须核对实现，避免把 policy/reference顺序颠倒。 完整词表 KL数值稳定、成本较高；采样 log-ratio便宜、方差大；非负近似便于监控、带估计差异。训练与报告明确使用哪一种。超参数 KL coefficient不能跨口径直接复用。 序列 KL按 token sum随长度增长，token mean减弱长度影响。policy surrogate若 sequence等权、KL token-global，正则相对强度随长度变化。用一短一长轨迹手算总 loss，确认设计。

**组内相关性与有效样本量。**

同 prompt轨迹共享输入，reward也由同一 verifier处理。即使采样随机独立，梯度在共享前缀上高度相关。$G$ 条轨迹不等价于 $G$ 个独立 prompt。 估计训练不确定性时，以 group为 cluster。比较 group size时固定 rollout总数，也报告独立 prompt数。大 $G$ 曲线更平滑可能只是 prompt更少、分布更集中。 同一组的 advantage和为零，使梯度存在负相关结构。对共享 token前缀，正负轨迹更新可能相互抵消；分叉后的 token提供差异。生成多样性不足时，大组也可能增加很少有效方向。 可用组内语义簇数、独特最终答案数与梯度余弦作为诊断。字符串去重不足，格式变化会制造假多样性。工具轨迹按动作序列聚类。

prompt sampler权重 $w_x$ 与组大小共同决定总贡献。若每组先 mean再按 prompt mean，group size不直接加权；若 token全局 mean，大组和长轨迹都获得更多权重。公式、代码与日志保持同一层级。

**恢复、扩容与异步一致性。**

训练恢复不仅保存 trainer policy。old policy版本、rollout队列、每条轨迹 log-prob、reward版本、KL controller、optimizer、scheduler、scaler与随机状态都要恢复。丢掉队列后重新采样，虽可继续训练，却不再逐步复现。 恢复测试选一个小固定队列。连续更新两步，与一步保存再恢复一步比较 ratio、advantage、loss、KL和参数。rollout不可重新生成，否则采样随机性掩盖状态缺失。 改变 world size时，group不能被不一致拆分。全局组统计、loss sum/count和梯度累积均按相同单位归约。扩容后 scheduler按实际 optimizer update或处理 token推进。 异步 worker权重广播可能失败或延迟。producer每次 rollout写入权重 hash，trainer拒绝未知或过旧版本。只记录全局 step无法确认 worker实际加载了什么。

verifier也要 hash。代码测试、judge提示或解析器更新会改变 reward。新旧 reward混合时，组内比较甚至可能使用不同尺子。一个 group必须使用同一 verifier版本。

**五类决定性反例。**

第一类是全失败极难题。若算法声称改善极难推理，却没有成功轨迹、部分 reward或 teacher信号，组优势始终为零，结论无法由这些 prompt的 GRPO梯度支持。 第二类是唯一成功但 verifier误判。std normalization把它放大约 $\sqrt{G-1}$，模型快速学习漏洞。重复验证与隐藏测试应推翻这种伪成功。 第三类是长成功、短失败。token-global reduction可能把长度与 reward混在一起。交换冗余长度而保持正确性，检查更新是否仍跟内容走。 第四类是 off-policy旧轨迹。producer lag增大后 ratio极端、clip比例上升，继续增加 PPO epoch不再提高有效利用。按 lag画质量与有效样本量，可以否证“复用越多越省”。

第五类是正确结果、错误过程。只用 outcome reward会提高整条轨迹，不能据此声称过程推理更可靠。独立过程验证或最小错误步骤反例用于检验。 这五类覆盖信号缺失、reward攻击、长度混杂、分布偏差和信用分配。任何 GRPO 配方都应明确其中哪些已处理、哪些仍是边界。

**最终复现清单。**

数据层保存 prompt来源、group ID、producer、解码、token、old log-prob、结束状态、reward分量与 verifier版本。过滤、重采样和 overlong规则全部版本化。 目标层写明 advantage公式、std分母、$\epsilon$位置、reward归约、token/sequence loss、ratio层级、clip、KL公式、reference与 old policy更新时机。 训练层记录 $G$、prompt batch、rollout/更新 token、PPO epoch、学习率、optimizer、gradient clip、并行、policy lag与恢复状态。吞吐和峰值显存用于成本比较。 诊断层记录全同率、有效组、成功率分桶、advantage、ratio、clip、KL、entropy、长度、截断、梯度与 reward攻击案例。均值之外给分位数。 评估层包含固定 verifier任务、未见 prompt生成、过程与 outcome、能力、安全、多语言、工具环境、长度、多样性和成本。最终服务栈重新运行。 统计层以 prompt/group为单位给置信区间，多种子报告稳定性，主要切片预先定义。动态 sampler训练曲线与固定分布评估分开。

结论层只陈述证据覆盖的范围。GRPO去掉 critic并不消除 baseline估计问题，组相对优势也不等于逐 token信用。它的价值是把同 prompt多采样转成可计算的相对信号；它的代价是 rollout预算、组分布偏差与粗粒度 credit。 按步骤给出过程奖励时，需要明确怎样转成 token advantage。把每步 reward-to-go广播到该步 token，可提供更局部的方向；将步骤分数先合成序列 reward，仍保留粗粒度信用。两种实现应分别报告。 步骤边界来自模型标记、解析器或工具事件。模型可能操纵分步格式以获得更多奖励，解析失败也会把正确过程变成零分。固定语义步骤反例、不同格式等价推导与隐藏检查用于验证。

过程 reward model自身会被策略利用。训练早期相关性良好，policy分布移动后可能出现高分伪推理。周期性人工审计与独立 verifier负责发现。只看 PRM 分数上升会形成同源闭环。 outcome 与过程 reward组合时，优先级要明确。过程看似正确、最终答案错误时，是给部分分还是硬失败？不同选择会改变模型是否愿意探索长推理。按任务定义，不应由方便的加权和自动决定。 组标准化会消除每个 prompt内 reward的线性尺度。若高风险任务本应权重更大，需要在 advantage之后乘 prompt业务权重，或在 sampler中提高频率。仅把其 reward乘十，在无 $\epsilon$ 影响时会被 std除回去。

这个性质很容易造成配置误解。团队提高某 reward系数却发现梯度不变，原因可能是组内整体线性缩放被标准化抵消；改变多项 reward相对构成仍会改变组内排序。分别测试整体缩放与单分量缩放。 去 std 的 Dr. GRPO保留 reward绝对尺度，因此业务权重可通过 reward幅度进入。相应地，不同 verifier量纲也直接影响梯度。采用哪种版本，决定 reward engineering的有效旋钮。 prompt级权重乘在标准化 advantage之后时，组内和仍为零，跨 prompt贡献改变。分布式归约按权重和或 prompt count需要明确。极端权重会降低有效样本量，并放大 verifier错误。

多任务训练中，每个任务 reward范围不同。标准化能缓解尺度差，却让每个非退化组近似等权；按部署价值再加任务权重更透明。验证结果使用线上分布和风险门槛，而非训练 sampler比例。 训练期间 group success rate变化，标准化优势幅度也变化。二元 reward唯一成功与唯一失败获得大幅权重，中间比例单样本幅度较小。相同 prompt在学习前后会经历不同隐式学习率。 跟踪 prompt级成功率轨迹可以观察这种课程。长期从全失败跳到偶发成功时，首次成功会获得大正优势，可能迅速巩固；若首次成功是偶然误判，错误也被快速放大。关键转折点保存轨迹供复验。

组采样随机性使首次成功时间差异很大，多种子曲线应按生成 token而非 step对齐。一个种子早遇到可验证成功，后续训练路径可能完全不同。这是推理 RL方差的重要来源。 扩大 rollout并行能更早找到成功，同时增加陈旧数据风险。吞吐、探索和 policy lag三者共同决定收益。只提高 worker数量而权重广播不变，可能生成更多已过时轨迹。 拒绝过旧轨迹会浪费算力，继续训练会增大 off-policy偏差。可调队列、减少 PPO epoch、提高广播频率或使用更强校正。每种方案对硬件利用和统计效率影响不同。

replay成功轨迹常被用来维持稀有能力。若没有行为 log-prob，作为 SFT replay最清楚；若保留 log-prob并做 GRPO，组 baseline需要与当时同组 reward绑定，不能把单条成功随意放入新组。 历史轨迹与新轨迹混组会比较不同 policy时代的回答。reward可比时仍能排序，但 ratio分母各异，group sampling解释变化。实验应单列，不把它称为标准 on-policy GRPO。 SFT replay的 chosen序列绝对上推，GRPO只用相对优势。混合后概率质量约束更强，也会模仿 teacher风格。记录两项梯度余弦，观察协同与冲突。 模型量化后，old log-prob与训练 policy精度可能不同。rollout用量化服务、训练用高精度权重时，实际行为分布并非训练 checkpoint原始 softmax。producer日志必须记录量化与服务kernel。

speculative decoding理论上保持目标分布时不改变行为概率，近似或自定义接受规则可能改变。使用服务侧采样优化时，验证实际 token频率与声明分布，不能默认等价。 adapter训练中，rollout服务必须加载同一 adapter版本。只广播 base hash而漏 adapter，会让 ratio异常。每个 producer manifest包含 base与adapter双版本。 模型合并后的策略不等于两个 policy概率的线性混合。合并权重不能继承原 GRPO的 old log-prob或 KL结果。作为新 policy重新 rollout与评估。 上线环境中的 prompt分布可能比训练更容易或更难。固定 benchmark reward上升，不代表实际有效组课程覆盖线上。影子流量评估任务成功、长度、拒答、工具错误与成本。

用户偏好任务若没有可验证 reward，judge评分加入组内优势。judge位置、长度和风格偏差会被相对采样放大。随机展示、多 judge与人评校准是最低控制。 同一 judge给整组打分时，批次上下文可能造成相互影响。逐条独立评价与列表评价不是同一分布。若使用列表排序，保存展示顺序并随机化，防止第一项偏差。 reward normalization跨组若再做一次全局 whiten，会叠加尺度变换。组内 std、batch whitening与 advantage clipping各自改变权重。配置中逐层写出，消融一次只改变一项。 advantage clipping限制稀有成功的大幅度，降低误判风险，也削弱突破信号。对单成功组复验准确率与生成收益，决定阈值。不能仅凭梯度更平稳选择。

reward clipping同样会合并质量等级。超过阈值的正确答案失去差异，组内可能变全同。查看 clip前后有效组率与排序翻转。 梯度 norm clip作用在聚合后参数梯度，不能保证每条轨迹影响受限。多个异常轨迹方向抵消时可能不触发；同方向正常信号也会一起缩小。记录 per-group proxy和全局范数。 训练停止不以 reward单调上升为唯一条件。固定 prompt成功率平台、KL继续增长、长度成本上升、能力或安全回退，都提示停止。保留质量—KL—成本前沿上的多个 checkpoint。 checkpoint评估需要重新生成，不能只复用训练 rollout。旧 rollout条件于 old policy与 sampler，无法展示当前行为。固定 seed便于配对，多 seed衡量采样方差。

上线监控的 reward不能完全复用训练 verifier。策略已经针对它优化，继续只看同一分数会漏漏洞。独立规则、人工抽样和真实任务结果构成外部验证。 回流失败案例时，先分类为知识、推理、工具、格式、环境或 verifier。知识缺失可能需要 SFT/mid-training，推理错误适合新可验证题，环境故障不应训练 policy，verifier漏洞先修尺子。 如果某类 prompt总是全失败，持续增加训练频率没有梯度。先检查能否产生任何成功、是否需要 teacher或部分 reward。日志显示 sampled很多而 effective为零时，应停止浪费 rollout。 如果某类总是全成功，GRPO也不更新。想提高效率或风格需新增区分 reward；只增加采样不会产生信号。仍保留少量回归，确认共享更新未破坏。

如果 reward方差来自随机环境而非策略差异，标准化会把噪声当优势。重复执行与环境控制先降低噪声。无法控制时，使用期望 reward估计或置信区间，代价是更多执行。 如果 ratio始终接近 1、clip为零且 reward不变，可能学习率太小，也可能 advantage全零或梯度相消。依次检查有效组、优势、参数梯度与 optimizer update，不先盲调 clip。 如果 ratio迅速极端、clip很高，检查学习率、PPO epoch、policy lag、old log-prob对齐与混合精度。token错位会让 ratio从第一步就异常，通常比真正策略更新更剧烈。 如果 KL突然跳升而 ratio正常，reference模板、mask或 cache可能变化；old ratio与 reference KL使用不同模型，故障可以只影响后者。固定探针同时计算两条坐标。

如果生成越来越长但成功率上升，先判断额外 token是否必要。用内容压缩反事实、答案位置和过程正确率区分推理扩展与冗余。成本是部署指标，不能等训练结束才看。 如果生成变短且格式正确，检查是否提前猜答案、截断推理或过度 EOS。最终答案 reward可能奖励这种策略。加入过程或一致性验证，而非单纯长度奖励。

所有诊断最终回到一个可复算链条：哪个 policy以什么分布生成了哪些 token，哪个 verifier在什么环境给出 reward，同组统计怎样产生 advantage，ratio与 clip怎样选择梯度，KL和其他项怎样修改更新，新的 policy又生成了什么。链条完整，GRPO的收益与失败才都能解释。 复现交付时还应保留一组最小固定轨迹。它包含全成功、全失败、唯一成功、唯一失败、连续 reward、小方差、长短序列与 producer lag。每条给出预期 group统计、advantage、ratio、clip选择、KL和最终 loss。框架升级或并行策略变化后，先逐项对齐这组轨迹。

固定轨迹验证数学语义，动态生成验证策略行为。前者通过而后者失败，问题多半在 reward覆盖、数据分布或探索；前者本身失败，则无需继续解释 benchmark。把两个层级分开，可以避免用大规模曲线掩盖基础实现错误。

还要保留一组跨版本探针 prompt，每次权重、verifier、模板或解码变化都重新 rollout。相同 prompt下比较组成功率、全同率、长度、advantage、ratio与最终生成，可以判断变化来自采样分布、奖励尺子还是策略更新。只比较最终 benchmark会把这些来源混在一起。 探针不追求覆盖全部任务，它负责让版本链可解释；大规模固定评估负责统计把握，线上样本负责发现新分布。三者采用不同数据集，避免反复调参把探针和测试集变成训练反馈。

如果训练结果只在某个 verifier版本、某个组大小或某种 reduction下成立，结论就明确限定在该配方。GRPO 的公式短，实际目标由采样、组统计、token归约、clip、KL和 reward共同定义。把这些组件写全，别人才能复现实验，也才能知道下一次改动究竟改变了什么。 这种版本化记录还便于复查负结果，避免把采样不足、验证器故障或归约变化误判成算法失效。

从每个 reward成功率桶抽取真实回答，核对 verifier判断、长度、过程与最终答案。极难桶检查是否拥有非零学习信号，中间桶检查相对优势能否区分质量，极易桶检查共享更新造成的遗忘。三类结果共同刻画组内课程是否符合目标。

组采样系统还要保存 prompt 到 rollout 的稳定映射. 同一 prompt 的 $G$ 条回答若在队列中被打散, 训练端不能依靠 batch 相邻位置恢复组号, 应携带明确的 `prompt_id` 与 `rollout_id`. 补采样产生的新回答也必须并回原组统计, 不能把补采结果当成新 prompt. 这个约束决定组均值、标准差和全同组率是否对应公式中的同一条件分布.
