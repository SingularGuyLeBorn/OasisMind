## 1. 为什么预训练的幂律在这里不够用

### 1.1. 有界指标与饱和

预训练 scaling law 研究 loss 随参数, 数据和计算的幂律变化, loss 无上界, 幂律在几十倍尺度上拟合良好. RL 的观测指标不同: accuracy, pass rate, reward 都有上界, 训练常在高计算区间饱和, 个别 recipe 还会退化或发散. 用无界幂律拟合有界曲线, 外推时必然系统性高估——这是把预训练直觉搬进 RL 的第一个坑. 第二个不同是噪声结构. 预训练的 loss 曲线平滑, 单 run 能看趋势; RL 的奖励曲线方差大, 同配置不同 seed 能差出几个点, 单条曲线的外推充满陷阱. 论文的方法论贡献一半在曲线模型, 一半在多 seed、多尺度的实验纪律, 后者比前者更难抄.

还有一个常被忽略的差异: RL 的计算量定义本身模糊. 预训练算 FLOPs 相对干净; RL 的计算分布在 rollout (自回归生成), 训练前向, 奖励计算 (可能调外部验证器), 和参考策略前向之间, 各环节硬件特征不同. 论文用 GPU-hours 统一度量是务实的妥协, 代价是跨集群不可比 (§5.1), 因而计算量数字必须同时标明集群与利用率口径. rollout 的自回归生成大量时间花在内存带宽和调度上, 有效 FLOPs 远低于峰值. 按峰值 FLOPs 统计会系统性高估训练端, 低估生成端; GPU-hours 至少保留了「时间」这个统一维度. 两种口径可以混用: 对内优化 (找瓶颈) 用分环节计时, 对外报告 (比方法) 用 GPU-hours, 两者在协议里都留字段. 只报一个数的人, 往往是不愿意让人看出瓶颈在哪.

### 1.2. 三阶段形态

论文观测到的典型 RL 计算—性能曲线分三段: 低计算区学习缓慢 (策略还没碰到可用信号, 组内全同居多), 中间区快速提升 (信号密集, 每单位计算都有产出), 高计算区接近有界上限 (提升趋零, 噪声主导). 这个形态和「S 形」一致, 和「直线 on log-log」不一致——后者只在中间区局部成立, 拿中间区拟合整条曲线是常见错误.

这个衔接关系也是检验拟合结果的快速方法: 把拟合出的四参数分别在早期区, 中期区, 饱和区复算残差, 若某一段的残差系统性偏大, 说明该段有 S 形没 capture 到的结构 (例如中期一次配方切换造成的台阶), 先检查实验记录里是否有未记录的变更, 再考虑更复杂的模型. 还有一个更朴素的检验: 把拟合曲线和原始点画在同一张图上直接看. 四参数的拟合失败极少是数值问题, 几乎都是数据本身不符合 S 形——肉眼十秒能发现的事, 别让优化器替你猜.

三阶段形态直接回应一个实践问题: 「再训一轮有没有用」. 答案取决于当前在曲线的哪一段——低计算区加算力大概率有用, 高计算区加算力大概率白烧, 中间区要看效率参数. 定位自己在哪一段, 需要拟合 (§2), 不能凭 loss 曲线的肉眼斜率. 三阶段里第二段 (快速提升区) 是资源效率最高的窗口, 也是各种 trick 争相比较的区间——这带来一个观察偏差: 论文默认展示的曲线多取自第二段, 因为那里最好看. 读图时先找横轴的量程, 量程只到中段的对高计算区结论保持沉默, 沉默不代表「外推成立」.

## 2. S 形曲线模型

### 2.1. 四参数逐个讲

论文采用的拟合模型:

$$R(C)=R_0+\frac{A-R_0}{1+(C_{mid}/C)^B}.$$

四个参数各有职责. $R_0$ 是起始性能, 基本由基座和冷启动决定, RL 动不了多少. $A$ 是渐近上限, 回答「这个 recipe 最终能到哪里」. $C_{mid}$ 是中点尺度, $R(C_{mid})=(R_0+A)/2$, 回答「多快走到一半」. $B$ 是斜率, 控制中间区的陡峭程度, 和 $C_{mid}$ 一起刻画计算效率. 四个参数里, $A$ 是能力坐标, $B$ 和 $C_{mid}$ 是效率坐标, $R_0$ 是基线坐标——后文所有「哪个技巧改了什么」的判断, 都要落到具体参数上, 不接受「提升了性能」这种笼统说法. 一个实用的参数化直觉: $B$ 大则曲线陡, 效率窗口窄但猛; $B$ 小则曲线缓, 长尾但上限附近爬得久. $C_{mid}$ 小则整条曲线左移, 同样的性能用更少计算. 两个 efficiency 参数的混淆是文献里常见的报告混乱, 读别人的拟合结果时先问「改的是斜率还是位置」.

四个参数里只有 $A$ 和 $R_0$ 是「性能」的绝对读数, $B$ 和 $C_{mid}$ 是相对量——同一个 $C_{mid}$ 在小模型上和大模型上含义完全不同. 跨模型比较时, 先把 $C_{mid}$ 按模型规模或基线计算量归一, 否则效率比较会被规模差异污染.

### 2.2. 手算: 拟合一条曲线

取一组论文风格的设定: $R_0=0.2$, $A=0.8$, $C_{mid}=10^3$ (单位是 GPU-hours), $B=1$. 算三个点. $C=10^2$: $(C_{mid}/C)^B=10$, $R=0.2+\frac{0.6}{11}\approx0.2545$. $C=10^3$: 比值 $1$, $R=0.2+0.6/2=0.5$, 恰在中点. $C=10^4$: 比值 $0.1$, $R=0.2+0.6/1.1\approx0.7455$. 再看效率的含义: 从 $0.25$ 到 $0.75$ 要走两个数量级的计算 ($10^2$ 到 $10^4$), 从 $0.75$ 到渐近 $0.8$ 的余量只剩 $0.055$, 却还要烧掉远超两个数量级的计算——高计算区的边际收益塌缩, 这就是「饱和」的定量形状. 反过来用: 若实测点 $(10^2,0.30),(10^3,0.55),(10^4,0.76)$, 三点定出 $R_0\approx0.2$, $A\approx0.82$, $C_{mid}\approx10^3$, $B\approx1.1$. 外推 $C=10^5$: $R\approx0.2+0.62/1.01\approx0.814$. 外推值比 $C=10^4$ 的实测只高 $0.05$——**继续加两个数量级计算, 预期收益五个点**. 这个算术比任何「scaling 还有效吗」的争论都直接.

拟合还有一个反直觉的用法: **用曲线判断该不该提前停**. 若中段点的外推显示剩余预算的期望收益低于换配方重新起跑的期望收益 (新配方可能 $R_0$ 更高, 因为可以从当前 checkpoint 继续), 停是理性而非失败. 这需要同一基座的多次拟合经验作参考, 值得团队积累自己的参数库.

**与幂律的衔接。**

高计算极限下, 令 $C\ll C_{mid}$ 不成立, 取 $C\gg C_{mid}$: $(C_{mid}/C)^B\to0$, $R\to A$, 逼近方式是 $A-R(C)\approx(A-R_0)(C_{mid}/C)^B$——**饱和区确实是幂律**, 误差随 $C^{-B}$ 衰减. 这解释了为什么「RL 也服从幂律」的说法有时看起来成立: 在饱和区局部拟合, S 形的尾部和无界幂律几乎重合. 但同一条曲线在早期 ($C\ll C_{mid}$) 是 $R-R_0\approx\frac{A-R_0}{C_{mid}^B}C^B$ 的另一种幂律, 斜率相同而含义不同; 中段则是两种极限都不适用的过渡区. 用一个幂律贯穿三段, 是把三个现象压成一个参数, 外推必翻车.

幂律叙事还有一个历史包袱: 预训练社区习惯的「参数/数据/计算三轴 scaling law」在 RL 里没有对应物——RL 的计算不是数据量的单调函数 (rollout 数, 长度, 过滤率共同决定), 模型规模也随训练过程被策略更新反复改写. 所以「给 RL 写一条 Chinchilla 式定律」的尝试, 起点就缺两个干净的自变量, 可靠结论只能来自固定协议内的有界拟合.

**拟合的工程细节。**

四参数的非线性拟合有两个工程坑. 第一是参数耦合: $C_{mid}$ 和 $B$ 强相关 (同样形状的曲线可以靠同时缩放两者复制), 拟合的置信区间在这两个方向上拉得很长, 单独解释它们的置信度要谨慎; 论文报告的区间通常对 $A$ 和 $R_0$ 较紧, 对效率参数较松, 读数时按参数分别对待. 第二是数据权重: 低计算区的点噪声大 (方差随信号稀疏增长), 不加权的 least squares 会被低质量点带偏, 常见做法是按 seed 方差的倒数加权, 或干脆舍掉最不可靠的头部点从中间区起拟合. 拟合优度还要检查残差. 残差呈系统形状, 例如前段偏高、后段偏低, 表明两个过程可能叠加, 需要先拆分能力增长与格式退化等机制. 拟合函数只承担测量任务, 其形状应由数据与保留点预测误差决定.

拟合的实现成本不高: 四参数模型用 scipy 的 `curve_fit` 即可完成, 主要工作在 §5 的数据记录与实验控制. 第一版 scaling 工具可以由 Jupyter 模板和协议文档组成; 流程稳定后再建设统一实验平台. 模板的第一版还应该带上「拟合失败」的出口: 三点拟不出稳定参数时 (置信区间爆表), 允许只报原始点不强行拟合. 强行给烂数据套模型, 比没有模型更误导决策. 同理, 拟合参数的有效期要写进模板: 基座换代, 框架大版本升级, 数据分布大改, 三者任一发生, 旧参数作废重拟. 作废的动作也要写进记录, 否则半年后没人知道哪组数字还能用. 这类「参数治理」看似琐碎, 却是 scaling 实验无法省略的维护成本.

## 3. 三个判断坐标: 渐近, 效率, 稳定性

### 3.1. 三个坐标的定义

| 判断 | 参数/现象 | 回答的问题 |
|---|---|---|
| 渐近能力 | $A$ | 训够久最终到哪里 |
| 计算效率 | $B$, $C_{mid}$ | 用多少计算接近上限 |
| 稳定性 | 多 seed 方差, 截断率, 崩溃与退化 | 曲线可重复吗, 能继续扩吗 |

某个技巧可能让早期曲线升得更快 (改 $B$ 或 $C_{mid}$) 却不改 $A$; 也可能抬高 $A$ 但需要更多计算才兑现 (改 $A$ 同时右移 $C_{mid}$). 只比较单个 checkpoint 的准确率, 两种改变分不开——这是论文最想纠正的测量习惯. 正确的比较是把两条曲线都拟合出四参数, 逐参数对照, 每个技巧的报告格式应该是「$A$ 从多少到多少, $B$ 从多少到多少」, 而不是「比 baseline 高 X 点」.

稳定性独立成坐标的原因: 不稳定的 recipe 拟合出的 $A$ 是假象——曲线在达到「渐近」前崩溃, 拟合程序会把未完成的上升外推成一个虚高的上限. 论文观察到不稳定 recipe 在继续加算力后退化, 「多训一定更好」对它不成立. 稳定性的判据因此要在拟合之前过: 多 seed 的曲线簇不散, 截断率和熵不漂移, 才有资格谈渐近.

### 3.2. 手算: 单点比较为什么骗人

构造一个对照. Recipe X: $R_0=0.2$, $A=0.8$, $C_{mid}=10^3$, $B=2$ (陡). Recipe Y: $R_0=0.2$, $A=0.9$, $C_{mid}=10^4$, $B=1$ (缓但上限高). 在 $C=10^3$ 处: X 的 $(C_{mid}/C)^B=1$, $R=0.5$; Y 的比值 $10$, $R=0.2+0.7/11\approx0.2636$. 单点比较 X 大胜 (0.50 对 0.26). 在 $C=10^5$ 处: X 的 $R=0.2+0.6/1.01\approx0.794$, Y 的 $R=0.2+0.7/1.1\approx0.836$. Y 反超. 同一份数据, 比较点不同结论相反——「谁好」没有脱离计算预算的答案, 报告必须带预算坐标. 工程含义: 选 recipe 前先定预算. 快速验证期 (低预算) 选效率型 (X), 生产训练期 (高预算) 选渐近型 (Y). 预算变化时重新选, 一条曲线用到底不是纪律是惰性. 实际团队里预算往往是分期的 (先 POC 后扩量), X/Y 对调的场景因此常见: POC 期选中的效率型 recipe, 扩量后应重新评估是否换渐近型. 把切换条件写进计划, 可以避免低预算阶段的选择被直接沿用到不再适合的训练规模.

**多种子的统计纪律。**

单 run 的曲线不能进入拟合. 同 budget 的多个 seed 先求均值和方差, 拟合对象是「均值曲线」, 方差用于加权 (§2.4) 和报告置信带; seed 数三到五是最低限度, 稳定性坐标本身就需要至少三个 seed 才能估计方差是否随计算增长. 若 seed 间的方差随 budget 扩大 (曲线簇发散), 稳定性坐标的红灯已经亮了, 此时拟合出的 $A$ 没有统计意义——先把方差压住再谈渐近. 一个常被跳过的对照: 同 recipe 同 budget 的「时间切片」方差 (同一 run 内相邻评测点的波动) 和「seed 间」方差要分开报. 前者是优化噪声, 后者是配置敏感性; 时间切片方差大而 seed 方差小, 说明曲线本身稳但评测频率太密, 平滑即可; seed 方差大, 说明配置对初始化敏感, 平滑是自欺.

seed 数不够时的补救是「准 seed」: 同配置改数据顺序, 改评测子集, 改采样温度微小的扰动, 产生伪独立的 run. 准 seed 能估计一部分方差, 但会系统性低估配置敏感性 (扰动相关性高), 报告中要标注「准 seed」的身份, 不能冒充真 seed.

## 4. ScaleRL: 组合 recipe 的逐项拆解

### 4.1. 清单与每项解决的故障

论文把多项消融中稳定胜出 (或至少不劣) 的选择组合为 ScaleRL. 系统侧: 异步 rollout-train 流水 (解决 GPU 利用率), 有限 off-policyness (深复用省计算, 浅到 ratio 不失控), 长度控制 (防长链空转), logit 的 FP32 计算 (防半精度数值事故, 和 1.2.4 节 §4 的纪律同源). 目标/数据侧: prompt-level loss aggregation, batch-level advantage normalization, truncated importance-sampling REINFORCE (CISPO 类更新), zero-variance filtering, no-positive resampling (长期高通过率的问题不再重复消耗 rollout). 逐项对应关系值得写明, 这是「组合不是黑盒」的证据: 异步流水治吞吐, 有限 off-policy 治数据效率, FP32 logit 治数值, prompt-level 聚合治回答间权重 (和 DAPO §4 的 token-level loss 是同一坐标的两端, 论文选 prompt-level), batch-level 优势归一治尺度漂移, 截断 IS 治 ratio 爆炸, 零方差过滤治无效采样, no-positive resampling 治简单题空转. 每项都有名字明确的故障, 没有一项是「因为效果好所以加」.

这份逐项对应表还有一个用法: 排障时按症状反查. 症状「训练后期简单题浪费 rollout」直接指向 no-positive resampling; 「loss 尖峰伴随数值异常」指向 FP32 logit; 「曲线中段停滞但有效 batch 正常」指向聚合或归一坐标. 把表存成 runbook 的一页, 比翻论文快. 反查表的维护成本很低: 新 trick 加入清单时, 同时登记它的症状与失效模式, 表就一直在位. 真正让它失效的是症状描述漂移——新故障模式出现时老表对不上号, 这时补一行比重建整张表划算. 排障记录的追加式维护和曲线拟合互相补足: 前者定位单点故障, 后者判断长期趋势. 两者共同追踪每次算力投入产生了什么变化、变化能否复现、换人后能否沿原口径继续测量. 工具会换代, 结论会过时, 稳定的测量协议才能跨 run 和跨团队保留.

### 4.2. 为什么组合不是新定律

论文自己明确: ScaleRL 是现有技术的组合, 不是新算法. 这个声明有两个含义. 第一, 复现 ScaleRL 等于逐项实现清单, 没有捷径, 「用了 ScaleRL」的报告应按 §4.1 的逐项清单核对, 缺项即改名 (和 1.3.2.1 节「四项缺一即改名」的纪律同构). 第二, 组合的渐近上限 $A$ 不高于其最优成分的理论上限——组合提升的是稳定性和效率 ($B$, $C_{mid}$), 以及把各单项的收益同时兑现的兼容性, 不创造新的能力来源. 对复现者的直接推论: 如果你的目标是某个具体任务的绝对性能, 把预算花在更好的基座和数据上, 通常比复刻 ScaleRL 清单的边际收益大; 清单的价值在于**当你不得不自己搭系统时, 不用重犯一遍每个单项的坑**——它是避坑清单, 不是性能秘籍.

这句定位也适用于 1.3 节的所有变体论文: 先确认新方法避开了哪个已知失效, 答不上来的算法可以降低试验优先级. 阅读和实验都应以原版坐标系为参照, 逐项核对变体改了什么、对应哪种症状. 若只把若干组件组合起来, 其收益应归入工程整合, 不能直接算作算法突破. 这也解释了消融的价值: 论文的贡献不在于某个单项 (单项大多有先例), 在于**系统性地验证这些单项在自己的大配方里兼容且互不抵消**——单项论文常在自己的小设置里验证, 组合到大系统里互相打架是常态, 不打架本身就是结果.

这一节对「recipe 工程」的定位可以收拢成一句话: 大模型 RL 的进步, 正在从「发明新算法」转向「系统性地组合与验证已知组件」, ScaleRL 是标志, 1.3 节后续各篇的稳定化变体是同一趋势的注脚. 读这个方向的论文, 期待值应从「新机制」调整为「新组合的兼容性证据」.

**各单项的 scaling 坐标归属。**

把 §4.1 的清单按三个坐标归类, 这决定了「哪些值得花算力验证」. 改稳定性的 (FP32 logit, 截断 IS, 零方差过滤): 先验最强, 因为它们防止的崩溃会直接摧毁曲线, 没有稳定性就没有渐近和效率可言. 改效率的 (异步流水, no-positive resampling, 有限 off-policy): 收益直接体现在 $C_{mid}$ 左移, 可以用小规模 run 测出方向再放大. 改渐近的 (prompt-level 聚合, batch-level 归一): 最难测, 收益绑定 $A$, 需要长训练才能兑现, 论文里这两项的证据也最谨慎. 这个归类对排期有直接意义: 稳定性项是门票, 先全部加上; 效率项在小预算阶段逐个消融; 渐近项留到生产 run 再定. 反过来, 如果某个声称改渐近的 trick 没有长 run 证据, 先按效率项对待——短 run 里「更好」几乎都是效率信号 (§3.2 的 X/Y 问题).

## 5. 怎样做自己的 RL scaling 实验

### 5.1. 固定协议

记录项包括模型与 tokenizer 版本, 训练/验证数据版本, 奖励器版本, rollout 数与采样温度, 最大长度与截断策略, 权重/梯度/logit 精度, 并行拓扑, GPU 类型与数量, 有效 GPU-hours, 评测频率与验证集版本. 有效 GPU-hours 在不同硬件间也无法直接等价为 FLOPs;跨集群比较需注明设备、利用率、网络拓扑与故障率, 并附 utilization 曲线. 协议固定后还有一个执行纪律: 任何一项变更都新开 run, 不中途切换. 中途换奖励器, 换数据, 换精度, 相当于在曲线中间换了函数, 前后数据点不可比, 拟合程序会把断点当成噪声平滑掉. 协议里最容易漏记的是负结果. 发散的 run, 崩溃的 run, 被手动掐掉的 run, 都要留档并注明原因. 只留成功 run 的协议, 等于在数据收集阶段就实施了 §6.1 的幸存者偏差, 后面的统计再严谨也救不回来.

### 5.2. 拟合与外推纪律

至少需要三个计算预算点才能初步判断曲线形状; 每个关键 recipe 使用多个随机种子, 同时保留原始点和方差. 前半区用于拟合, 后半区用于外推检验, 报告外推误差, 参数置信区间和残差分布. 拟合优度只衡量已知点上的插值, 未见区间的预测误差才能检验模型是否具备外推能力. 一个实用判据: 若后半区实测系统性地低于前半区拟合的外推, 说明曲线在上凸变缓 (接近饱和) 或训练开始不稳, 此时「继续加算力」的决策要重新评估, 而不是换个更灵活的拟合函数把误差抹平——后者是把警报关掉.

外推误差采用相对口径还是绝对口径, 取决于参数用途. $A$ 用来判断「还差多少到顶」, 绝对误差更有意义; $B$ 和 $C_{mid}$ 用于预算规划 (§5.4), 相对误差更有意义. 两种口径混用会掩盖各参数的不确定性.

**失败信号清单。**

监控项: 奖励方差 (组内), 响应长度分布, 截断比例, KL, 熵, 重要性比率的分布 (P95/P99), 有效 batch 大小 (过滤后), 零方差组占比, 独立验证集性能, reward hacking 探针 (固定集上的 reward 与人工评分的相关). 训练奖励上升不能替代独立验证集——reward 上升可能是真的变好, 也可能是向验证器的漏洞迁移, 两者在训练曲线里长得一样, 只有独立验证集分得开.

监控清单的项目按响应速度分层: 比率分布, clip fraction, 零方差组占比是分钟级信号, 用于在线熔断; 长度分布, 截断率, 熵是小时级信号, 用于每日调参决策; 独立验证集是 epoch 级信号, 用于继续/停止的决策. 把慢信号当快信号用 (每步看验证集) 是焦虑, 把快信号当慢信号用 (崩溃后才发现比率爆炸) 是失职.

**预算规划的算术。**

把曲线模型用于预算决策. 目标: 在性能达到 $R^*$ 的前提下最小化计算. 由 S 形反解: $C=C_{mid}\left(\frac{A-R^*}{R^*-R_0}\right)^{-1/B}$. 实际算法: 先拟合四参数, 再对目标 $R^*$ 反解 $C$, 留 50% 余量作为饱和区减速和意外开销的缓冲. 手算: 接 §2.2 的拟合 ($R_0=0.2,A=0.82,C_{mid}=10^3,B=1.1$), 目标 $R^*=0.75$: $(A-R^*)/(R^*-R_0)=0.07/0.55\approx0.127$, 逆幂 $0.127^{-1/1.1}\approx10^{0.9}\approx8$, $C\approx8\times10^3$, 加余量定预算 $1.2\times10^4$ GPU-hours. 若只有 $5\times10^3$ 的预算, 同一公式给出可达 $R\approx0.2+0.62/(1+(10^3/(5\times10^3))^{1.1})\approx0.73$——差两个点, 值不值取决于下游用途. 预算公式还有一个隐藏假设: 曲线参数在预算变化时不变. 换预算往往伴随换并行规模, 而并行规模影响有效 batch 和优化动态 (1.3.1.1 节 §5.3), 参数可能漂移. 大预算 run 的头几百个 GPU-hours 应视为「重新标定期」, 用早期点修正拟合, 而不是直接沿用 POC 的四参数.

这套算术的价值不在精确 (四参数本身有置信区间), 在于**把「加预算」从口号变成可比较的数字**: 多投入一个数量级的算力, 预期能换来多少增益, 可以直接写进预算评审.

## 6. 常见错误与边界

### 6.1. 错误清单逐条

论文与社区实践总结的常见错误: 用预训练「20 tokens/parameter」直接规划 RL 预算 (两个阶段的计算结构不同, 这个换算没有依据); 把单一准确率曲线称为新的普适 scaling law (单曲线, 单 seed, 单任务, 三个单凑不出 law); 只拟合成功 run, 忽略发散 run (幸存者偏差把不稳定 recipe 的虚高 $A$ 坐实); 把 GPU-hours 当跨集群无条件等价; 在同一数据上选 recipe, 拟合曲线又报告最终效果 (选择和评估共用数据, 过拟合); 把 recipe 里所有技巧都解释为改变渐近上限 (多数技巧改的是效率, §4.1). 每条错误的共同根源是测量纪律松弛: 想得到一个干净的结论, 于是绕开了让结论变脏的步骤. 对治不需要新理论, 把 §5.1 的协议执行到位即可.

错误清单里「选 recipe 与报告共用数据」值得单独强调, 因为它披着「高效」的外衣: 用全部 run 挑最优配方, 再用同一批 run 报告它的效果, 效果数字里已经包含了选择本身的过拟合. 正确的做法是留出从未参与选择的 held-out run, 数量可以少 (一两个 budget 点), 但必须有.

### 6.2. 结论的适用范围

论文的结果是**大规模实证观察**, 不是对 all 模型和奖励成立的物理定律. 曲线模型是现象学拟合, 四参数没有微观机制支撑, 迁移到新领域 (新任务族, 新奖励结构, 新基座规模) 至少要重新拟合, 保留多 seed 和外推误差. 「S 形比幂律好」也只是在有界指标 + 饱和观测下成立; 若指标的界很宽或训练远未饱和, 幂律仍然够用, 不必为了用 S 形而 S 形. 「Fokker-Planck 方程解释 RL 训练」「推理热力学」「RL 五大定律」等说法与其所引论文的内容不一致, 不能作为 RL 计算扩展的结论. 可复用的结论应能对应到原文的公式、实验设置或数据表.

适用范围还有一层时间维度: RL infra (框架版本, 硬件代际) 以季度为单位换代, 半年前的拟合参数可能因框架默认行为变化而失效. 引用历史结论时连同当时的框架版本一起引用, 新版本重跑一次 cheap 检查, 是成本最低的保险.

**报告模板。**

一份可复核的 scaling 报告至少包含三部分. 方法部分按坐标系逐项列出 recipe (聚合粒度, clip, 采样过滤, KL, 归一, §4.1 清单式), 每项注明版本. 实验部分至少使用三个预算点和三个 seed, 报告均值曲线的四参数拟合值、置信区间、后半区外推误差和失败信号时序图. 结论部分给每个 claim 标出渐近、效率或稳定性坐标, 同时注明计算预算与对照组配置. 缺少其中任一部分, 结论的可引用强度都应下调. 模板的最大敌人不是复杂, 是「下次再补」——三个 seed 的钱在第一次 run 里不花, 后面补跑的隐性成本 (代码漂移, 数据版本变化) 往往更高. 把多种子写进默认配置, 比写进检查清单有效.

**和 RL 家族的关系。**

**7.1 各变体在 scaling 视角下的位置.** 把 1.3 节的方法谱系放进 scaling 坐标: GRPO 及变体 (DAPO, GSPO, GMPO, GDPO, GHPO) 的论文大多报告单 budget 的对比, 它们的差异落在哪个坐标上, 需要 scaling 实验才能定位——某变体「更好」可能是渐近更好 ($A$), 也可能是效率更好 ($B$), 也可能是只在低 budget 更好 (§3.2 的 X/Y 对调). 拿到多预算曲线后, 先拟合, 再逐参数对照; 单点结果无法区分这三种收益. 每季度按同一套拟合口径复盘历史 run, 常会发现一些曾被归因于算法的差距实际来自效率. 及时降低这类结论的可信度, 比继续累积未经复核的新结论更能改善决策质量.

scaling 实验也直接影响方法选择: 预算小的团队按效率坐标选 recipe (陡曲线), 预算大的按渐近坐标选 (高 $A$), 稳定性坐标则是所有预算的硬门槛. 1.4 章的家族比较沿用这三个坐标, 让不同算法的结果落到同一套测量口径上. **算法论文中的「更好」必须拆到渐近、效率和稳定性三个坐标上**, 再判断结论是否可信、是否值得迁入现有管线. 这套测量纪律不提出新算法, 但决定了算法比较能否成立.

**计算预算先拆成四本账。**

optimizer step 只是调度计数, 无法表示一次 RL 实验用了多少计算. 同一步可以包含不同 prompt 数、每题不同 rollout 数、不同回答长度与不同补采比例. 更可用的分解是

$$
C_{\mathrm{total}}
=C_{\mathrm{gen}}+C_{\mathrm{score}}+C_{\mathrm{train}}+C_{\mathrm{idle}},
$$

分别对应生成、验证、策略更新和等待浪费. 四项使用 GPU 时最容易相加, 但算法分析还要同时保留 token 与样本计数, 因为同样 GPU 时在不同硬件和后端上含义不同. 生成预算近似为

$$
C_{\mathrm{gen,tok}}
=\sum_{q=1}^{N_p}\sum_{j=1}^{K_q}(T_q^{\mathrm{prompt}}+T_{q,j}^{\mathrm{resp}}).
$$

若采用动态采样, 被过滤的组也已经完成生成和验证, 必须计入分子. 若某步原计划 256 道题、每题 8 条、平均 prompt 500 token、平均回答 4000 token, 单轮约生成 $256\times8\times4500=9.216$ 百万 token. 过滤 25% 组并补到原有效批大小, 在长度分布不变的理想条件下成本除以 $1-0.25$, 上升到约 12.288 百万 token. 训练预算与生成预算不同. 一条回答可能做一个或多个 PPO epoch, 每次都需要 actor 前向与反向;reference 或 critic 还会增加额外前向. 因而

$$
C_{\mathrm{train,tok}}
=E_{\mathrm{ppo}}\sum_i T_i^{\mathrm{loss}},
$$

其中 $T_i^{\mathrm{loss}}$ 只含参与 loss 的有效 token. prompt token 用于前向上下文, 通常不进入策略损失;padding 也不应计入有效训练 token. 报告生成 token 与 loss token, 才能说明预算花在探索还是数据复用. **8.1 四种效率不要混用.** 「吞吐效率」是每秒生成或训练多少 token;「样本效率」是每个样本带来多少能力提升;「计算效率」是每 GPU 时或 FLOP 的提升;「统计效率」是每个有效梯度样本的方差. 高吞吐系统可以因样本陈旧而降低样本效率, 最终计算效率未必提高. 设同步系统每小时生成 10 亿 token, 每十亿 token 验证分数提高 1 点;异步系统每小时生成 18 亿 token, policy lag 让每十亿 token 只提高 0.6 点. 同步每小时提高 1 点, 异步提高 1.08 点, 仍有 8% 墙钟收益. 若样本效率降到 0.5, 异步每小时只提高 0.9 点, 吞吐更高却更慢达到目标.

因此扩展系统时应画两条曲线: 能力对累计 token, 能力对墙钟时间. 前者测算法与样本效率, 后者包含系统收益. 两条都改善才是无条件收益;墙钟改善、token 曲线变差表示用更多并发抵消了统计损失. **8.2 空闲成本也会随规模增长.** 同步 rollout 的 step 结束时间由最慢回答决定. 大多数回答 2K token, 少数达到 16K, 其它 worker 会等待长尾. worker 数越多, 每批碰到极端长样本的概率越高. 设单条成为长尾的概率为 $p$, 一批 $n$ 条至少出现一条长尾的概率为 $1-(1-p)^n$. $p=0.001,n=2048$ 时约为 $87.1\%$, 长尾虽稀少, 几乎每批都会出现. 异步调度能减少等待, 代价是样本生成与消费解耦. 计算扩展的核心矛盾由此出现: 同步保住 on-policy 新鲜度却受长尾拖累, 异步提高设备利用率却引入 policy lag. 最优点不能只靠吞吐决定.

**rollout 吞吐与策略滞后。**

定义样本 $i$ 的版本滞后为

$$
\Delta_i=v_{\mathrm{consume},i}-v_{\mathrm{generate},i}.
$$

$\Delta=0$ 表示当前更新消费当前策略生成的数据;异步队列里 $\Delta$ 可以大于零. 版本差只是系统代理量, 算法真正看到的是

$$
\rho_{i,t}=
\frac{\pi_{\theta_{\mathrm{consume}}}(a_{i,t}\mid s_{i,t})}
{\pi_{\theta_{\mathrm{generate}}}(a_{i,t}\mid s_{i,t})}.
$$

每次更新幅度不同, 相同 $\Delta$ 对应的 ratio 分布也不同. 因而日志同时记录版本差、log-ratio 分位数和裁剪命中率. **9.1 一个滞后手算.** 假设某类 token 每次更新后概率平均乘 1.04, 样本滞后 10 个版本, ratio 约为 $1.04^{10}\approx1.48$;滞后 20 个版本约为 $2.19$. 常见 PPO 上界 1.2 或 1.28 下, 两者都落在裁剪平台. 这条样本完成昂贵生成, 更新时却无法通过原始正优势分支持续提供梯度. 概率变化不会在所有 token 上同向, 平均 ratio 可能仍接近 1. 应观察 log-ratio P1/P50/P99, 并按正负优势拆 clip fraction. 一半 token ratio 0.5、另一半 1.5, 算术均值为 1, 实际大部分已越界. **9.2 吞吐扩展的非单调收益.** 令 worker 数为 $W$, 生成吞吐 $g(W)$ 通常先近线性增长, 后受通信、队列与服务拥塞影响变缓. 样本新鲜度 $f(W)$ 则可能随队列增长下降. 单位时间有效学习信号可粗略写成

$$
H(W)=g(W)\,f(W)\,u(W),
$$

其中 $u(W)$ 是非零优势且未被裁剪的 token 比例. $g$ 上升不保证 $H$ 上升. 最优 worker 数位于边际吞吐增益等于新鲜度与有效率损失的位置. 可证伪实验固定模型、数据与总生成 token, 扫描不同 $W$ 和最大队列长度. 报告完成时间、版本滞后、clip fraction 与最终验证分数. 如果增加 worker 只改善墙钟、不改变 token 曲线, 系统扩展没有统计代价;token 曲线下降则量化了 off-policy 损失. **9.3 队列上限与丢弃策略.** 限制最大滞后能保持新鲜度, 超限样本采用等待、丢弃或重算, 会形成不同成本. 丢弃已经生成的样本会降低样本利用率;等待期间版本会继续变旧;用当前策略重算 old log-prob 会掩盖行为分布, 无法恢复 on-policy 属性.

更合理的选择是缩短队列、降低每次 learner 更新幅度, 或采用明确的 off-policy 校正. 任何丢弃都记录生成 token 与原因, 否则吞吐日志看起来很高, 实际大量预算没有进入 loss. **9.4 PipelineRL-8 的含义.** ScaleRL 配方采用 PipelineRL-8 这类流水化设置, 目标是在可控滞后下提高资源利用. 数字 8 属于论文实验配置, 不能脱离更新幅度与硬件拓扑解释成通用最优并发. 换模型规模、回答长度或学习率后, 相同流水深度对应不同 ratio 漂移. 复现应把「8」还原成可测量分布:平均与 P99 版本差、样本年龄、ratio 尾部、有效裁剪比例. 这些量相近, 两套系统才具有相似 off-policy 条件.

**组大小、题目覆盖与有效样本数。**

固定每步回答数 $R=B\times G$, 增大组大小 $G$ 会减少 prompt 数 $B$. 组大提高每题发现稀有成功链的概率, 组小覆盖更多题. 这是训练采样预算最基本的分配问题. 二值奖励下, 单题成功率 $p$, 混合组概率

$$
m(p,G)=1-p^G-(1-p)^G.
$$

期望有效组数为

$$
M(B,G)=B\,\mathbb E_{p\sim\mathcal D}[m(p,G)],
\qquad B=R/G.
$$

最大化有效组数时, 增大 $G$ 同时提高 $m$、降低 $B$. 哪一项占优取决于题目成功率分布 $\mathcal D$. **10.1 固定 2048 条回答的手算.** 若所有题 $p=0.1$, $G=4$ 时 $m\approx0.3438$, $B=512$, 期望有效组约 176; $G=8$ 时 $m\approx0.5695$, $B=256$, 期望约 146; $G=16$ 时 $m\approx0.8147$, $B=128$, 期望约 104. 按有效组数量, 小组更好;按每道题至少看见一条成功链, 大组更好. 若 $p=0.01$, $G=4$ 有效组概率约 $3.94\%$, 期望约 20; $G=8$ 约 $7.73\%$, 期望仍约 20; $G=16$ 约 $14.85\%$, 期望约 19. 三者有效组数接近, 大组优势主要表现为同题更多探索, prompt 覆盖则下降. 这说明「最大化有效组」无法独立决定 $G$. 每个有效组的优势估计方差、题目覆盖与梯度相关性也要进入目标. 可定义粗略效用

$$
U(G)=M(B,G)\cdot d(G)\cdot c(B),
$$

$d(G)$ 表示组内路径多样性,$c(B)$ 表示跨题覆盖. 两者需由数据测量, 不存在只看 $G$ 的普适答案. **10.2 组内相关性降低有效回答数.** 若同组奖励相关系数为 $\rho$, 有效回答数近似

$$
G_{\mathrm{eff}}=\frac{G}{1+(G-1)\rho}.
$$

$G=16,\rho=0.5$ 时只有约 1.88 个独立样本. 将 rollout 从 8 加到 16, 若解码路径高度相关, 计算翻倍而统计信息几乎不变. 温度、多样化前缀或搜索策略可能比继续增大 $G$ 更有效. 测量相关性可比较实测成功条数方差与二项分布 $Gp(1-p)$. 方差显著更大, 表示回答成团全对或全错. 文本层再看首个分叉位置与解法聚类, 区分表面改写和真正路径探索. **10.3 有效 token 而非有效回答.** 一组混合奖励不代表每个 token 都有同等训练价值. padding、prompt、截断后位置不进 loss;clip 平台 token 的原始梯度也被限制. 定义

$$
N_{\mathrm{eff,tok}}
=\sum_{i,t}\mathbf 1[A_i\ne0]\,
\mathbf 1[\text{mask}_{i,t}=1]\,
\mathbf 1[\text{未进入裁剪平台}].
$$

每百万生成 token 对应多少有效 token, 是连接系统吞吐与优化信号的关键指标. 动态采样提高非零优势比例, 异步滞后降低未裁剪比例, 长回答提高生成成本与潜在 loss token, 三者可以在同一分式里核算.

**验证器成本与计算分配。**

规则数学验证器成本接近字符串解析, 在总预算中很小;代码任务需要编译、执行与沙箱;开放问答可能调用另一个大模型. 当验证成本与生成接近时, rollout 扩展会把瓶颈移到 scorer. 设每条回答生成耗时 $t_g$, 验证耗时 $t_v$, 并行度分别为 $W_g,W_v$. 稳态吞吐受较慢阶段限制:

$$
Q\approx\min\left(\frac{W_g}{t_g},\frac{W_v}{t_v}\right).
$$

只扩生成 worker, 当验证器已经饱和时总体吞吐不再增加, 队列反而拉长、policy lag 上升. 最优资源分配让两阶段处理率接近, 同时保留异常长验证的缓冲. **11.1 强验证器是否值得.** 强验证器可能减少假阴性和假阳性, 提高每个 reward 标签的信息质量, 同时增加成本. 可以用「每 GPU 时获得的正确优势标签数」比较:

$$
E_v=\frac{N_{\mathrm{labeled}}(1-e_v)}{C_{\mathrm{score}}+C_{\mathrm{gen}}},
$$

其中 $e_v$ 是经人工抽查估计的验证错误率. 强验证器把错误率从 5% 降到 1%, 但成本增加十倍, 是否划算取决于错误经组归一放大后的损害. 一条假阳性会在全错组中制造完整正负优势, 通常比假阴性更危险. 成本敏感的级联验证可先用轻量规则, 只把解析失败、多个答案或高风险格式交给强验证器. 级联阈值通过人工分歧集校准, 不应只按置信度直觉决定. **11.2 重复验证与缓存.** 同一回答文本可缓存确定性规则结果, 但模型验证器若版本或提示变化, 缓存键必须包含判定配置. 代码执行还依赖环境、测试版本与超时设置. 缓存命中节省成本, 错误复用会改变 reward 口径.

训练数据近重复时, 缓存验证不等于缓存 rollout. 回答由旧策略生成, 不能因验证结果相同就当作当前 on-policy 数据. 只复用环境结果, 不复用行为概率的语义. **11.3 验证延迟也制造 off-policy.** 生成很快、验证很慢时, 样本在 scorer 队列等待, learner 消费时已经陈旧. 因而 policy lag 不只由 rollout worker 数决定. 日志将生成结束、验证结束、进入 learner 三个时间戳分开, 才能找到延迟来源. 若强验证器提高标签质量却让滞后显著增大, 最终收益可能抵消. 固定生成 token 的消融同时报告验证错误率、样本年龄、clip fraction 与验证分数, 才能完成成本—质量比较.

**难度课程也是预算分配。**

一道成功率接近 1 的题常形成全对组, 一道成功率接近 0 的题常形成全错组, 两者每次都支付生成成本. 课程的计算目标是把更多预算投到能产生学习信号、又覆盖目标能力边界的题上. 设题目 $q$ 的当前成功率为 $p_q$, 单次采样成本为 $c_q$, 期望混合组概率为 $m(p_q,G)$. 只追求短期有效组时, 可按

$$
\frac{m(p_q,G)}{c_q}
$$

排序. 但这会偏爱短、适中难度题, 可能牺牲长题和能力边界外题. 长期价值还应包含迁移收益 $v_q$, 理想分数变为 $m(p_q,G)v_q/c_q$. $v_q$ 无法直接观察, 需要保留集或历史学习进展估计. **12.1 学习进展比当前奖励更有用.** 课程可以跟踪同类题成功率的变化 $\Delta p/\Delta C$. 当前成功率 0.5 但长期不变, 可能已经到瓶颈;成功率从 0.05 升到 0.15 的难题虽有效组较少, 边际进展更大. 预算按学习进展分配, 能避免长期困在最容易产生梯度的区域. 估计进展需要固定探针与平滑窗口. 窗口太短会追逐采样噪声, 太长会滞后策略变化. 报告课程权重、原始数据占比与最终有效梯度占比, 才能审计控制器是否过度偏向某类题. **12.2 动态过滤的隐藏成本.**

过滤全同组后补采, 每个 optimizer step 的有效 batch 更稳定, 生成预算却成为随机变量. 若有效组概率为 $m$, 收集 $B$ 个有效组的期望尝试数约 $B/m$. $m=0.5$ 时成本翻倍; $m=0.1$ 时约十倍. 题库难度变化会让墙钟突然失控. 应给补采设置预算上限, 到达上限后允许较小有效 batch 或调整题目分布. 上限如何影响梯度方差与吞吐, 可以通过负二项分布近似并用实测校准. 只报告最终 step 数会隐藏所有失败尝试. **12.3 引导课程的计算账.** GHPO 类方法先用原题探测, 全错后加入真值前缀重采. 一道困难题最少付两组 rollout, 多档提示可能付更多. 它用额外计算换取该题留在训练分布. 是否优于丢弃补新题, 取决于提示后有效组概率和零提示迁移.

固定总 token 比较三种处理: 丢弃全错题、原题继续多采、加入提示重采. 若提示组 reward 高、零提示保留集不涨, 计算只提高受助能力;若迁移明显, 它可能是比盲目增大 $G$ 更好的预算投向.

**扩展律参数如何指导预算。**

S 形曲线把最终能力上限与达到上限的速度分开. 可写成四参数 logistic:

$$
R(C)=R_0+\frac{A-R_0}{1+\exp[-k(\log C-\log C_{\mathrm{mid}})]}.
$$

$R_0$ 是起点,$A$ 是渐近性能,$C_{\mathrm{mid}}$ 是到达中点的计算量,$k$ 控制过渡陡峭程度. 一个技巧降低 $C_{\mathrm{mid}}$ 而不改变 $A$, 属于计算效率收益;提高 $A$ 才改变渐近能力. **13.1 边际收益.** 对 $x=\log C$ 求导:

$$
\frac{dR}{dx}
=k(A-R_0)\sigma(k(x-x_m))[1-\sigma(k(x-x_m))].
$$

中点附近边际收益最大, 两端较小. 低预算区看不到明显提升, 不一定代表方法无效;高预算区进入饱和, 继续加算力也可能不值. 至少三个预算点很难稳定拟合四参数, 更可靠的实验需要更多点或对部分参数加先验约束. **13.2 两条曲线交叉.** 方法 X 的上限高、效率低, 方法 Y 的上限低、效率高. 小预算下 Y 领先, 大预算下 X 反超. 单点 benchmark 会把预算位置误当算法排序. 决策应先确定可用预算 $C^*$, 比较 $R_X(C^*)$ 与 $R_Y(C^*)$, 再看外推不确定性. 手算例子: 两者起点 30. X 的上限 70、中点 1000;Y 的上限 62、中点 200, 取相同 $k=2$. 在 $C=200$ 附近 Y 已到约 46,X 仍接近低段;在远大于 1000 的预算下 X 向 70 靠近并超过 Y. 「更好」必须带预算区间. **13.3 预测不确定性.**

拟合参数高度相关. 只观察曲线前半段时, 更高 $A$ 与更晚 $C_{mid}$ 都能解释缓慢上涨. 应保留后半区做外推验证:用低预算点拟合, 预测高预算点, 比较误差. 多 seed 给出观测噪声, bootstrap 给参数置信区间. 稳定 recipe 才可能形成可预测曲线. 中途发生 reward hacking、长度爆炸或数据阶段切换, 单条 sigmoid 会把结构突变硬拟合成参数. 先检查训练动态, 再谈 scaling law. **13.4 论文结果的边界.** ScaleRL 研究投入超过 40 万 GPU 小时, 并把最佳配方扩到单次约 10 万 GPU 小时, 展示了可预测性. 论文观察到 loss 聚合、归一化、课程与 off-policy 算法等许多选择主要改变计算效率, 部分 recipe 的渐近上限仍不同. 这些是所测模型、数据与验证协议下的经验规律, 换任务后需要重新拟合.

**最优预算分配。**

给定总预算 $C$, 可以在 prompt 数 $B$、组大小 $G$、训练复用 $E$、验证强度 $V$ 与训练步数 $S$ 间分配. 粗略约束为

$$
C\approx S\,[C_{gen}(B,G)+C_{score}(B,G,V)+C_{train}(B,G,E)].
$$

增加任一维度都会挤压其它维度. 最优分配要求各项追加一单位计算带来的边际验证收益接近;某项边际收益明显更低, 预算应移走. **14.1 rollout 与更新的平衡.** rollout 太少, 每步梯度样本少、方差高;rollout 太多, learner 来不及消费、样本变旧. learner 更新过多, 同一数据 ratio 远离 1;更新过少, 生成的有效信号没有充分利用. 可以扫描 rollout/train compute 比例, 对每组记录 token 曲线与墙钟曲线. 一个简单在线指标是队列增长率. 生成率长期高于消费率, 队列长度与滞后持续上升, 额外 rollout worker 的边际产出趋近于零. 消费率高于生成率, learner 等待, 可增加生成资源. 平衡点还需满足 clip fraction 与样本年龄阈值. **14.2 组大小与训练步数.**

固定总 rollout 数, 大组减少步数或每步 prompt 覆盖. 对低成功率题, 大组提高发现正确链概率;对中等题, $G=4$ 或 8 已足够, 多余回答不如用于新题和更多更新. 按初始成功率分桶选择不同 $G$ 是自然扩展, 但会改变各题采样成本与梯度权重. 自适应 $G$ 应记录每题总 token, 并在 loss 中决定是否重加权. 否则困难题因采样更多, 既更可能产生有效组, 又可能在 batch 中占更多回答, 获得双重权重. 这种偏置可能有意, 也可能只是调度副产品. **14.3 验证预算.** 轻量验证全量运行, 强验证只覆盖分歧或高风险样本, 是常见预算分配. 阈值可用价值信息近似:某样本的强验证结果有多大概率翻转组优势, 翻转会影响多少 token. 优先验证可能改变梯度方向的样本, 比随机抽取更省.

若一组奖励已经是四对四, 单条标签翻转仍保持混合组, 主要改变优势幅度;全零组中一条疑似假阳性, 翻转会让整组从有信号变为零, 影响更大. 验证优先级可以据此设置. **14.4 探索预算与数据预算.** 同一道题多采回答属于组内探索, 增加题目属于数据覆盖. 固定总 token 下, 两者的最佳比例取决于错误相关性与题型覆盖. 若回答高度相关, 更多题优先;若许多题存在稀有正确链, 组内探索优先. 可做二维网格 $(B,G)$, 保持 $BG$ 与生成 token 近似相同, 再按题型报告有效组和验证增益. 仅比较最终平均会掩盖容易题偏好小组、极难题偏好大组的相反结果.

**反例与可证伪实验。**

反例一: 将 worker 从 64 扩到 256, 吞吐提高 2.5 倍, 版本滞后从 1 升到 20, 未裁剪 token 比例从 90% 降到 25%. GPU 利用率更高, 每百万 token 的验证增益下降四倍, 总墙钟反而没有改善. 这推翻「吞吐等于训练速度」. 反例二: 把 $G$ 从 8 增到 64, 单题 pass@G 大涨, prompt 覆盖降到八分之一, 组内回答又高度相关. 有效组数与题型覆盖同时下降, 最终泛化变差. 这推翻「更多 rollout 必然提高 RL 信号」. 反例三: 强验证器把假阴性降低一半, 耗时却是规则验证的二十倍, scorer 队列制造更大 policy lag. reward 标签更准, token 与墙钟效率都下降. 这推翻「验证越强越好」, 同时提示使用级联. 反例四: 动态课程只选当前成功率 0.3 到 0.7 的短题, 训练 reward 与有效组数很好看, 长题和极难题从数据流消失. iid 验证提升、能力边界测试不涨. 这推翻「有效组密度代表全部能力进展」.

可证伪实验一固定总生成 token, 扫描同步、不同流水深度与完全异步. 中间指标为版本滞后、ratio 尾部与有效 token;结果指标为验证分数与墙钟. 若异步 token 曲线不降, off-policy 偏差在该范围可忽略;若下降随滞后单调增加, 可拟合允许的队列阈值. 实验二固定 $BG$, 扫描组大小, 再以相同初始 $p$ 分桶. 同时测文本路径相关性. 若大组收益只出现在低 $p$ 且低相关题, 组大小可以按桶分配;若相关性高时普遍无收益, 优先改善解码多样性. 实验三固定 rollout, 离线用轻量与强验证器重打 reward, 计算组优势翻转率. 只对可能翻转的组调用强验证器, 与全量强验证对比质量和成本. 级联达到相近人工一致率且成本更低, 说明预算分配有效.

实验四选至少五个计算点, 每点多 seed, 对不同 recipe 拟合 sigmoid. 用前四点预测第五点, 比较外推误差. 若某 recipe 小预算领先、渐近更低, 曲线应显示交叉;若拟合无法预测保留点, 暂不适合用作扩展律. 实验五在相同总 GPU 时下比较动态过滤、无过滤与提示引导. 报告生成 token、有效组、零提示验证与题型覆盖. 任何方法若只在 step 横轴领先, 换到 token 或时间横轴消失, 收益来自额外计算或系统口径.

**从边际收益求计算最优点。**

将预算分给生成、验证与更新, 可以视为约束优化. 设三类计算分别为 $C_g,C_v,C_u$, 总预算固定:

$$
C_g+C_v+C_u=C.
$$

验证能力写成 $R(C_g,C_v,C_u)$. 内部最优点满足各项边际收益相等:

$$
\frac{\partial R}{\partial C_g}
=\frac{\partial R}{\partial C_v}
=\frac{\partial R}{\partial C_u}.
$$

如果生成侧每增加一 GPU 时提升 0.02 点, 更新侧只提升 0.003 点, 预算继续放到更新不合理. 真实训练无法直接求导, 可以在当前配置附近做小幅扰动, 用有限差分估计边际收益. 例如基线把 60% 时间用于生成、10% 用于验证、30% 用于更新. 三个短程对照分别将 5% 总预算从另两项挪入某一项, 保持总 GPU 时一致. 观察固定保留集增益, 得到局部斜率. 这种实验不能一次找到全局最优, 却能判断当前分配应向哪个方向移动. **16.1 生成预算的边际递减.** 增加 rollout 有三种用法:更多 prompt、更大组、更多重采. 更多 prompt 扩展数据覆盖;更大组降低同题优势估计噪声并提高稀有成功发现率;重采替换全同组. 三者都消耗生成 token, 边际收益曲线不同. 对固定成功率 $p$, 至少一次成功概率为 $1-(1-p)^G$, 对 $G$ 的边际增益

$$
\Delta_G=(1-p)^G p.
$$

它随 $G$ 指数下降. $p=0.1$ 时, 从 $G=1$ 加到 2 的增益是 0.09;从 8 加到 9 只有约 0.043;从 32 加到 33 约 0.0034. 若目标只是发现至少一条成功链, 大组最终会迅速进入边际递减. 但组相对优势还要求同时有失败样本. 有效组概率 $m(p,G)$ 在 $G$ 增大时趋近 1, 全对概率也会随 $p$ 变化. 对 $p=0.9$ 的容易题, 增大 $G$ 主要减少全对概率, 重新制造混合组;这可能继续训练已掌握题, 是否有价值取决于遗忘与泛化. **16.2 更新预算的边际递减.** 固定 rollout 做多个 PPO epoch, 第一轮数据最接近 on-policy, 后续 ratio 扩散、clip fraction 上升. 第 $e$ 个 epoch 的有效 token 数记为 $N_e$. 更新计算的有效利用率

$$
U_E=\frac{\sum_{e=1}^{E}N_e}{E\,N_1}.
$$

若 $N_1=100$ 万,$N_2=60$ 万,$N_3=25$ 万, 三个 epoch 的 $U_3\approx0.617$. 第三个 epoch 只增加 25% 首轮有效量, 却支付完整训练前后向. 与其继续复用, 可能更适合生成新数据. 实际梯度不会简单由未裁剪 token 数决定, 但 $U_E$ 提供可复算下界. 配合每 epoch 的验证增益与更新范数, 可以选择数据复用次数. 学习率变化会改变 ratio 扩散, 因而 $E$ 与学习率需联合扫描. **16.3 验证预算的信息价值.** 强验证器的价值来自修正标签. 对样本 $i$, 轻量与强验证器产生不同标签的概率为 $d_i$, 标签翻转后改变组优势与 loss 的影响为 $w_i$, 强验证成本为 $c_i$. 优先级可按

$$
\mathrm{VOI}_i\approx\frac{d_iw_i}{c_i}
$$

排序. 这个公式是一种预算分析方法, 未被论文规定为固定算法. 全零组里一条可疑正奖励的 $w_i$ 很大;已经四对四的组里一条边界样本翻转, 影响相对较小. 用历史人工审计拟合 $d_i$, 特征可以是解析异常、多答案、单位、表达式复杂度与验证器置信度. 级联策略按 VOI 选样本, 再与全量强验证做等质量成本比较. 若级联漏掉的假阳性集中在某种新格式, 分布漂移会破坏历史估计, 需要持续抽检. **16.4 等边际原则的失效条件.** 各类计算存在离散门槛. 少于某个组大小可能完全采不到成功链;验证器 GPU 少于一组会成为硬瓶颈;模型并行要求固定卡数. 预算也存在互补:没有正确 reward, 再多更新无用;没有 rollout, verifier 空闲. 等边际条件只适合门槛之上的连续近似.

长程能力还可能需要先投入短期看不见收益的难题. 纯局部边际优化会把预算都给容易上涨的区域, 形成短视课程. 保留固定比例用于边界题与分布外探针, 相当于探索预算, 防止控制器把训练收缩到局部甜点区.

**扩展曲线怎样拟合才可信。**

计算横轴先统一. 最少同时保存累计生成 token、累计 loss token、验证器 GPU 时、总 GPU 时与墙钟. 论文使用计算量刻画 scaling, 复现若只能拿到 GPU 时, 要说明硬件、精度、并行与利用率;不同设备的 GPU 时不能直接等价. 纵轴使用 held-out iid 验证集的 expected reward 或 mean@K, 避免训练 reward. 训练数据课程会改变题目难度, 训练 reward 可能因分布变易上涨;验证集固定才能拟合能力随计算的变化. ScaleRL 使用固定验证协议周期评测, 正是为了给曲线稳定纵轴. **17.1 预算点的选择.** 预算点若都在 sigmoid 早期, $A$ 与 $C_{mid}$ 无法分辨;都在饱和区, $k$ 与起点也难估. 先用廉价 pilot 确定开始上升与趋缓的大致区间, 再在 log-compute 上均匀取点. 例如 $C\in\{1,2,4,8,16,32\}$ 比线性取 $\{1,2,3,4,5,6\}$ 更容易覆盖多个阶段.

每个点可以来自独立 run 或同一 run 的 checkpoint. 后者便宜且共享随机轨迹, 参数间相关;前者更独立但成本高. 使用 checkpoint 时, 不确定性估计应考虑时间相关, 不能把六个点当作六次独立实验. **17.2 多 seed 如何分配.** 总预算固定时, 多 seed 与更多计算点竞争. 早期 pilot 可在低成本点多跑 seed, 估计噪声和失败概率;高成本点减少 seed, 但保留至少一次外推验证. 如果某 recipe 崩溃率高, 只拟合成功 run 会高估性能, 失败应作为结果进入期望曲线. 设成功概率为 $s(C)$, 成功条件下 reward 为 $R_{ok}(C)$, 失败时为 $R_{fail}(C)$. 实际期望

$$
\mathbb E[R(C)]
=s(C)R_{ok}(C)+(1-s(C))R_{fail}(C).
$$

只报告最佳 seed 等价于把 $s$ 当作 1. 稳定性改进即使不改变成功 run 上限, 也可通过提高 $s$ 改善期望性能. **17.3 拟合与保留点.** 先将最高预算点留出, 用其余点拟合, 预测保留点. 外推误差小, 才能用曲线规划更大预算. 若所有点都用于拟合再报告 $R^2$, 只能说明插值, 无法证明预测能力. 参数置信区间可用 bootstrap:以 seed 或 prompt 为单位重采, 重复拟合, 得到 $A,C_{mid},k$ 分布. prompt 级 bootstrap 测评测噪声, seed 级 bootstrap 包含训练随机性. 两者回答不同问题, 应分别标注. **17.4 曲线交叉的置信度.** 两条拟合曲线交叉点 $C_\times$ 也有不确定性. 对每次 bootstrap 拟合计算交叉点, 得到分布. 若一半样本没有交叉, 或区间跨越两个数量级, 不能据此制定预算决策. 此时在预测交叉区新增实验点, 比继续争论渐近参数有效. **17.5 结构突变不能硬拟合.**

训练中途更换数据阶段、长度上限、reference 或验证器, 曲线可能有折点. 单一 sigmoid 会把两个机制混成一个平滑过渡. 配方发生变化时分段拟合, 或把阶段作为模型变量. 最干净的 scaling 实验保持 recipe 固定. 异步系统的 policy lag 随规模变化, 即使配置固定, 算法条件也可能改变. 因而每个预算点都报告滞后与 clip 分布, 确认曲线变化确实来自更多计算, 没有同时改变 off-policy 程度. **17.6 由曲线反推预算.** 给定目标分数 $R^*$, logistic 可反解所需计算:

$$
C^*=C_{mid}
\left(\frac{R^*-R_0}{A-R^*}\right)^{1/k}.
$$

若 $R^*$ 接近 $A$, 分母 $A-R^*$ 很小, 所需预算急剧增长, 参数误差也被放大. 目标设在估计上限之外时没有有限解. 预算规划应给点估计与区间, 并设置超过预算后的停止条件. 手算: $R_0=30,A=70,C_{mid}=1000,k=2$, 目标 $R^*=60$. 比值 $(60-30)/(70-60)=3$, $C^*=1000\sqrt3\approx1732$. 目标改为 68, 比值 $38/2=19$, 所需约 4359. 分数只多 8 点, 预算约增加 2.5 倍, 体现饱和区边际递减.

**端到端预算案例与验收。**

假设团队有 10,000 GPU 小时, 训练 7B 数学模型. pilot 显示 rollout 占 65%,训练占 25%,验证占 5%,等待占 5%;每步 256 prompt、$G=8$, 平均回答 4000 token, 全同组 35%,异步 P99 滞后 6 个版本,未裁剪有效 token 比例 70%. 先算当前有效信号. 每步 2048 条回答, 混合组约 166 个. 假设每条有效 completion 平均 3500 token, 未裁剪比例 70%, 则粗略有效 token 为 $166\times8\times3500\times0.7\approx3.25$ 百万. 总生成 completion token 约 $2048\times4000=8.19$ 百万, 未计 prompt 时信号比约 39.7%. 方案 A 增加 worker, rollout 吞吐提高 40%, P99 滞后升到 18, 未裁剪比例降到 35%. 每小时生成量乘 1.4, 有效比例约减半, 每小时有效 token 变为原来的 $1.4\times0.5=0.7$, 反而下降. 方案 A 不应直接全量采用. 方案 B 保持 worker, 动态过滤把混合组率从 65% 提到 85%, 补采让生成成本增加 25%, 滞后不变. 单位生成 token 的有效组比例增益约 $0.85/(1.25\times0.65)\approx1.046$, 只有约 4.6%. 若题型覆盖还变窄, 收益可能不值复杂度. 仅看每 step 有效组会误以为提高 30.8%.

方案 C 将 verifier 改为级联, scorer 成本从 5% 升到 7%, 假阳性减半, 滞后不变. 人工审计显示假阳性常将全错组变成单正样本组, 对梯度方向影响大. 即使有效 token 数不增,标签质量提高可能带来更高验证收益. 这项需要短程对照, 无法由吞吐公式直接决定. 方案 D 把 $G=8$ 改为 4, prompt 增至 512, 总回答数不变. 根据 pilot 的 $p$ 分布模拟, 期望有效组从 166 增到 210,题型覆盖增加,组内优势方差上升. 短跑若梯度范数可控且验证增益提高, 它比扩 worker 更接近计算最优. 这组案例说明预算优化先做静态估算, 再用短程实验验证无法由公式确定的迁移与方差. 公式能排除明显亏损方案, 不能替代模型训练. **18.1 扩容前验收.**

小规模 run 先验证数据语义:group 不跨 prompt, old log-prob 与生成版本一致, padding/prompt 不进 loss, verifier 误差可接受. 这些条件没通过, 扩容只会更快地产生错误数据. 随后记录基线四本账、版本滞后、ratio 分位数、三类组、长度分布与有效 token. 没有基线, 扩容后吞吐变化无法换算成学习信号. **18.2 扩容中验收.** 每增加一档 worker 或流水深度, 固定生成 token 跑短程对照. 监控吞吐增益、队列、样本年龄、clip fraction 与验证斜率. 一次跨太多档位, 出现退化后难以找到转折点. 资源增加时保持模型、数据、学习率和 batch 语义不变. 全局 batch 若随卡数放大, 扩容同时改变算法条件, 结果无法只归因于系统. **18.3 扩容后验收.**

按累计 token、GPU 时与墙钟三条横轴比较. token 曲线衡量统计损失,GPU 时曲线衡量硬件计算效率,墙钟曲线衡量交付速度. 再报告成本构成, 看收益来自减少等待、加快生成还是改变采样量. 若墙钟更快而 GPU 时更差, 属于用更多并行资源换时间;若 GPU 时更好但 token 曲线更差, 系统效率弥补了样本效率;三条都改善才是完整扩展收益. **18.4 停止扩展的信号.** worker 增加后队列持续增长、P99 滞后越过裁剪可接受区, 应停止加生成资源. 组大小增加后路径相关性高、有效组边际增益接近零, 应把预算转向更多 prompt. PPO epoch 增加后未裁剪 token 快速耗尽, 应生成新数据. 强验证器成本上升而优势翻转率很低, 应缩小调用范围.

scaling 曲线进入饱和区、目标分数的反解预算超过上限, 应停止同配方长跑. 若业务仍需更高能力, 需要提高渐近上限的改动:更好的数据、模型起点、奖励或算法, 而非继续沿原曲线烧计算. **18.5 最终报告.** 报告应包含计算定义、硬件与软件版本、每个预算点的四本账、训练与评测协议、拟合参数和保留点误差. 算法改动同时标注它主要改变上限、效率还是稳定性. 异步实验必须给版本滞后与 ratio 分布, 动态采样给过滤与补采成本,强验证器给错误率与调用成本.

计算扩展追求新增计算转化为新鲜、正确、具有非零优势且尚未被裁剪的训练信号. 生成吞吐、有效样本、策略新鲜度和验证质量共同决定转化率. 每张卡的利用率只是其中一项系统指标, 任何扩容方案都应沿完整链路验收. **19. 六个容易算错的扩展问题.** **19.1 optimizer step 相同, 计算量为何能差数倍.** 设实验 X 每步 128 个 prompt、每题 8 条、平均回答 2000 token, 无补采;实验 Y 每步同样 128 个 prompt、每题 16 条、平均回答 3500 token, 过滤率 20% 并补齐. 忽略 prompt,X 每步生成 $128\times8\times2000=2.048$ 百万 token;Y 为

$$
\frac{128\times16\times3500}{1-0.2}
=8.96\text{ 百万 token}.
$$

同跑 1000 step,Y 的 rollout 预算约为 X 的 4.375 倍. 如果 Y 最终高 3 分, 结论只能是更大计算下表现更高, 还不能归因于算法. 应在 X 曲线上找到相近 8.96B token 的 checkpoint, 或将 Y 截到 2.048B token 比较. 训练计算也可能不同. Y 的回答更长、PPO epoch 更多或使用 reference 前向, 总差距会继续扩大. 所以 step 只适合单一配置内部定位 checkpoint, 不适合跨 recipe 的 scaling 横轴. **19.2 每秒 token 更高, 为什么 GPU 时可能更差.** 一个系统把生成与训练放在同一组 GPU 上, 利用率 70%, 每秒生成 100 万 token;另一个系统拆分资源, 生成侧每秒 160 万 token, learner 与 scorer 另占一倍 GPU. 若总卡数从 64 增到 128, 后者的单位 GPU 吞吐从每卡 15625 token/s 降到 12500 token/s. 墙钟更快 60%, 计算效率下降 20%. 业务可能愿意用更多钱换更短交付时间, 但论文声称「更高计算效率」时必须按总资源归一. 报告总吞吐、每 GPU 吞吐、GPU 时与墙钟, 四个数才能覆盖这项交换.

**19.3 动态采样提高有效 batch, 为什么不一定提高样本效率.** 设无过滤每 100 组有 60 个混合组, 成本 100 单位;动态采样补到 90 个混合组, 共尝试 160 组. 无过滤每成本有效组为 0.60, 动态采样为 $90/160=0.5625$, 反而略低. 每 optimizer step 的有效组提高 50%, 每生成成本的有效组下降 6.25%. 动态采样仍可能提高训练稳定性, 因为每步梯度批大小更固定;也可能通过选择更有学习价值的题提高单组质量. 这些收益需要验证曲线证明, 不能由有效组数量自动推出. 补采失败、验证和等待全部计入成本. 进一步考虑题型. 被过滤的多为困难长题, 补入的多为短中等题, 平均长度下降, 系统吞吐上涨;能力边界却可能收缩. 按题型报告有效梯度占比, 才能发现计算效率是通过改变任务分布获得的.

**19.4 更大组降低方差, 为什么梯度方差仍可能上升.** 组内样本增加可以改善组均值和标准差估计, 固定总回答数时却减少独立 prompt. 跨题梯度差异通常很大, prompt 数下降会增加 batch 对题目抽样的敏感度. 总方差可粗略分为组内与组间:

$$
\operatorname{Var}(g)
\approx\frac{\sigma^2_{\mathrm{between}}}{B}
+\frac{\sigma^2_{\mathrm{within}}}{BG_{\mathrm{eff}}}.
$$

增大 $G$ 降低第二项, $B=R/G$ 下降又放大第一项. 当题型多、组内回答相关时, 组间方差占主导, 大组反而让总梯度更噪. 手算:固定 $R=2048$, 设组间方差 4,组内方差 1,回答独立. $G=8,B=256$, 方差近似 $4/256+1/2048\approx0.0161$; $G=32,B=64$, 约 $4/64+1/2048\approx0.0630$, 接近四倍. 若组内方差极高或成功链极稀有, 大组才可能抵消这项损失. 实验要估计组内和组间梯度差异. 只看 reward 方差会漏掉 token 梯度方向:不同题即使 reward 相同, 更新方向也可能不同. 可在小模型上计算 per-group gradient sketch 或输出层梯度, 估计两项量级. **19.5 异步样本带 importance ratio, 为什么仍有偏差.** 理论上重要性采样可校正行为策略与当前策略差异. 长序列的整轨迹权重是 token ratio 乘积, 方差随长度爆炸;逐 token clip 降低方差, 同时引入偏差. ratio 越远离 1, clip 越频繁, 校正越不完整.

设正优势 token 真 ratio 为 1.8, clip 上界 1.2. 代理目标只按 1.2 计, 相对未裁剪校正少三分之一. 这项偏差换来稳定. 当异步扩展让大量 token 从 1.05 移到 1.8, 算法已经进入另一种偏差—方差工作点. 序列级方法也不能消除分布支撑问题. 行为策略几乎不会生成的路径, 当前策略再喜欢也没有样本;行为策略生成、当前策略概率极低的路径则产生极端权重. 保持样本新鲜仍是最直接的控制. 可证伪实验按样本年龄分桶, 在同一 checkpoint 上重算 ratio 与梯度贡献. 如果老样本在校正后仍与新样本给出相近方向, 滞后影响小;方向偏离或有效率骤降, 队列深度需要限制. **19.6 scaling 曲线更陡, 为什么未必值得采用.**

曲线斜率更大可能伴随较低渐近上限、更高崩溃率或更昂贵单点成本. 一个 recipe 在 10K GPU 时达到 60 分, 另一个 20K 达到 60 分;若前者上限 62、后者上限 75, 目标 70 时只能选后者. 若前者有 30% 概率崩溃, 期望重跑成本也要计入. 假设方法 X 单 run 成本 10K、成功率 0.7, 失败后完全重跑, 成功一次的期望尝试数为 $1/0.7\approx1.43$, 期望成本约 14.3K. 方法 Y 单 run 12K、成功率 0.95, 期望成本约 12.6K. 单次成功曲线看 X 更省, 纳入稳定性后 Y 更省. 失败不一定能早期发现. 若通常在 80% 预算后崩溃, 重跑成本接近完整 run;若前 5% 即可由指标预警, 期望损失小得多. scaling 报告应给失败时刻分布与早停规则, 稳定性才可换算成计算.

扩展曲线也可能因评测饱和显得平. MATH-500 已接近上限时,$A$ 受 benchmark ceiling 限制, 不代表模型能力停止增长. 使用难度更高、污染更少且分辨率足够的保留集, 才能观察高预算阶段. 多个 benchmark 可分别拟合, 再看哪些能力先饱和. 这六类算术指向同一条原则: 每个分子都要对应完整分母. 分数提升对应多少生成 token、GPU 时与失败重跑;有效组对应多少补采;吞吐对应多少设备;稳定性对应多少成功概率. 分母缺失时, 计算扩展结论往往只是换了一种计数方式. 对 ScaleRL 配方还要逐轴阅读. ScaleRL 汇总 PipelineRL-8、CISPO loss、FP32 logits、prompt-average、batch normalization、zero-variance filtering 与 no-positive-resampling 等选择. 这些组件分别影响系统流水、重要性采样、数值精度、聚合、优势尺度与数据分布. 把它们合在一起能形成强 recipe, 仍需逐轴理解贡献.

FP32 logits 主要保护 log-prob 与 ratio 精度, 成本落在计算和显存;batch normalization 改变优势尺度;zero-variance filtering 提高有效梯度密度;no-positive-resampling 决定全错题如何进入数据流;PipelineRL-8 在吞吐与滞后间取点;CISPO 处理 off-policy 更新. 同一组件可能只改变效率参数, 组合却通过交互影响稳定性. 迁移到新系统时, 先复现可观测工作点:FP32 与低精度路径的 ratio 误差、过滤率、补采成本、版本滞后、clip fraction、每 prompt 与每 token 权重. 工作点接近后再比较曲线. 只复制配置名字, 硬件与 batch 语义变化可能让算法条件完全不同. 论文的大规模结果证明该 recipe 在其设定下可以沿预测曲线扩到约 10 万 GPU 小时. 它提供的是一套经过系统消融的强起点和测量框架. 新任务仍需小预算拟合、保留点验证与成本拆账, 再决定是否进入大规模 run.

计算扩展记录应覆盖原始谱系. 每个 checkpoint 保存累计 prompt、responses、prompt token、completion token、loss token、被过滤 token、丢弃的陈旧 token、验证器调用与 GPU 时. 系统侧保存各角色卡数、利用率、队列长度与空闲时间;算法侧保存版本滞后、ratio、clip、有效组和有效 token;评测侧保存固定协议得分与置信区间. 这些字段可以重建三条核心曲线:能力—token、能力—GPU 时、能力—墙钟. 也可以重算每有效组成本、每有效 token 成本和失败重跑成本. 日后框架升级时, 新旧 run 仍能在共同分母上比较. 如果只能优先保留少数字段, 首选原始样本的生成版本、token 数、reward、优势、ratio、mask 与时间戳. 聚合指标可以离线重算, 原始谱系丢失后无法恢复. 扩展到数十万 GPU 小时时, 可审计性和计算本身一样重要.

计算口径还需处理失败任务. worker 因超时、显存溢出或网络错误重试, 首次尝试已经消耗资源. 只统计成功返回的 token 会系统性低估长样本成本, 并让更容易失败的 recipe 显得高效. 失败前已生成的 token、占用时间与重试次数全部进入成本, reward 侧则按预先规则决定是否丢弃或判零. 故障率会随集群规模上升. 单卡每小时故障概率很低, 上千卡连续运行数天时几乎必然遇到节点问题. checkpoint 频率因此也是预算决策:保存过密占用 I/O 与暂停时间, 保存过疏会在故障后重算大量 rollout 和更新. 最优间隔取决于 checkpoint 成本与平均故障间隔. 设保存一次耗时 $t_s$, 集群平均故障间隔 $T_f$, 两次保存间隔为 $I$. 粗略地, 每次故障平均丢失 $I/2$ 的工作, 单位时间保存开销约 $t_s/I$, 故障重算开销约 $I/(2T_f)$. 两项之和

$$
L(I)=\frac{t_s}{I}+\frac{I}{2T_f}
$$

在 $I^*=\sqrt{2t_sT_f}$ 附近最小. 这是经典 checkpoint 算术在 RL 长跑中的直接应用. 异步系统还要保存队列与策略版本关系, 仅恢复模型会让 old log-prob 与行为策略错位. 预占式云资源让故障模型更复杂. 节点被回收的价格便宜, 重启和样本丢弃更多;按需资源稳定但单价高. 计算效率应以真实费用和成功训练概率评估. 便宜 40% 的卡若让 30% run 在后期失败, 期望成本可能更高. 数据读取与 prompt 构造也消耗墙钟, 通常不是 GPU 主项, 规模扩大后可能成为串行瓶颈. 若所有 worker 等同一个数据服务, 增卡只增加等待. 系统指标中保留每阶段队列时间, 根据瓶颈阶段扩资源. 这属于 Amdahl 定律:串行比例 $s$ 存在时, 无限并行的最大加速比为 $1/s$.

假设 10% 墙钟用于无法并行的协调与数据准备, 其余 90% 可随 worker 理想并行. 将并行资源增至 16 倍, 总加速比

$$
S(16)=\frac{1}{0.1+0.9/16}\approx6.4,
$$

远低于 16. 若扩容后还增加通信与滞后, 实际更低. 先测串行比例, 可以避免对线性扩展抱不切实际的预期. 生成长度方差进一步破坏理想加速. 动态 batching 与连续批处理能填补部分空洞, 但短请求可能在长请求之间排队. 统计每张卡的 active token 时间、padding、等待与重计算, 比总体 utilization 更能解释损失. utilization 高也可能在处理即将被丢弃的陈旧样本, 系统忙碌不等于算法有效. 模型规模变化时, prefill 与 decode 比例也会变. 长 prompt、短 response 偏向 prefill;短 prompt、长推理偏向逐 token decode. GHPO 加提示会增加 prefill, 长思维链增加 decode. 同一套 worker 配比在两种负载下不一定最优. 预算表将 prompt 与 completion token 分开, 才能迁移容量规划.

MoE 模型的每 token FLOP 与通信模式又不同. 激活参数少不表示 rollout 成本按总参数同比下降, expert parallel 可能受负载不均和 all-to-all 限制. scaling 论文的 GPU 时参数不能直接套到不同架构. 共同横轴可用真实成本或校准后的有效 FLOP, 同时保留硬件实测. 量化 rollout 可以提高生成吞吐, 但行为策略变成量化近似. learner 若用 BF16/FP32 权重计算 old log-prob, 量化生成分布与记录分母不完全相同. 误差小时可忽略, 规模扩展后仍要实测:固定 prompt 与随机种子比较量化/高精度 logits、答案分布和 ratio. 吞吐收益应扣除因此产生的 off-policy 偏差. FP32 logits 在 ScaleRL 配方中正是精度轴的选择之一. log-prob 差值进入指数, 小数值误差在长序列和尾部 token 上可能放大. 低精度节省计算与通信, 若导致 ratio 尾部更宽、clip 更多, 每 token 学习信号下降. 精度消融同时报告吞吐与 ratio 误差, 不能只看 tokens/s.

序列打包能减少 padding, 提高训练 token 吞吐. 如果 loss 聚合先按序列平均, 打包实现必须保留每条回答边界与独立分母;若错误地对整包 token 平均, 算法语义悄悄变成 token-level. 系统优化前后的合成 batch loss 应逐项一致, 才能把吞吐提升归为无损优化. 验证器并行也有 batch 效应. 模型判定器大 batch 吞吐高, 为凑 batch 等待会增加样本年龄;小 batch 低延迟、设备利用率差. 最优 batching 同样位于吞吐与滞后之间. 可以给验证器设置最大等待时间, 扫描 batch size 与超时, 用最终 learner clip fraction参与选择. 课程与系统负载相互影响. 难题回答更长、验证更慢, 提高难题占比会降低吞吐;如果 scaling 横轴只用 step, 课程改动看起来更慢;按生成 token 可能相近;按 GPU 时还包含长尾等待. 算法比较应保留三条横轴, 说明代价来自样本本身还是系统实现.

预算规划还要给评测留出成本. 九个 benchmark、多次采样、32K 输出与模型验证器可能耗费可观 GPU 时. 高频评测能早停坏 run, 也会挤占训练. 评测间隔的价值来自提前发现故障与估计曲线, 不是越密越好. 设一次评测成本 $C_e$, 坏 run 每训练一单位预算损失 $l$, 故障从发生到发现的平均延迟约为评测间隔一半. 评测过疏的期望浪费随间隔增长, 过密的固定成本随频率增长. 可以用历史故障率估计一个合理间隔, 高风险早期密一些,稳定后逐渐拉长. checkpoint 选择还会带来统计选择成本. 评测越频繁, 从噪声中挑到偶然高点的机会越多. scaling 曲线最好使用预定 step 或平滑后的 checkpoint, 并把选择规则固定. 最高验证点可以附带报告, 不能与别的方法末点直接比较.

目标能力若由多个 benchmark 组成, 平均分也隐含预算权重. 易饱和 benchmark 在高预算阶段变化小, 难 benchmark 决定曲线;简单平均可能让不同题数和业务价值等权. 在训练前固定聚合权重, 分项曲线与总曲线一起报告. 事后改变权重会产生新的选择偏差. 对于多领域模型, 总预算还要在数学、代码、工具和通用对话之间分配. 每个领域有自己的 sigmoid 与迁移效应. 如果独立近似, 拉格朗日条件仍要求各领域边际收益按业务权重相等;存在正迁移时, 给数学的计算也可能提高代码, 需要测交叉导数.

构造领域预算矩阵:行表示训练 domain, 列表示评测 domain, 元素是增加一单位训练计算带来的验证变化. 对角线测域内收益, 非对角线测迁移或干扰. 预算优化基于整张矩阵, 不只看各领域自己的分数. 某领域短期收益低但对其它领域有正迁移, 仍可能值得投入. 实际决策可以用迭代方式. 先给每个领域小额探索预算估计局部斜率, 将下一批预算分给加权边际收益高的领域, 同时保留固定探索比例. 每轮重新估计, 因为边际收益随饱和变化. 这比一次性按数据量固定比例更能适应学习进展.

迭代控制也会追逐噪声. 使用置信上界时, 估计不确定的领域得到额外探索预算;只按点估计, 早期偶然低分的领域可能被永久饿死. 计算扩展因此与 bandit 预算分配相似, 但每次训练更新还会跨领域迁移, 独立臂假设并不完全成立. 所有优化最终都应回到目标分数的成本. 达到同一验证阈值所需 token、GPU 时、墙钟与失败概率, 比固定预算末点更直观. 若某方法永远达不到阈值, 记录为未达到, 不能用外推曲线强行给出精确成本. 当目标接近估计上限, 反解预算对 $A$ 极敏感. 给 $A$ 的置信区间上下界分别计算预算, 区间可能跨越数量级. 这时继续投入大 run 风险很高, 先增加中高预算测量点缩小不确定性更合理. 测量本身也是预算的一部分.

最终, compute-optimal 并非一个脱离约束的常数. 截止日期强调墙钟, 资金限制强调 GPU 时, 稀缺数据强调样本效率, 高失败成本强调稳定性. 把约束写进目标函数, 同一套测量才能给出符合场景的选择. 还可以把一次大规模 run 拆成「测量预算」和「利用预算」. 前者用于 pilot、多 seed、曲线拟合、验证器审计与系统压力测试;后者用于最终长跑. 测量预算过小, 最终配置可能选错, 大 run 浪费更多;测量预算过大, 又会消耗本可用于训练的资源. 配置不确定性越高、最终 run 越贵, 越值得先测量.

设候选配置 X 与 Y 的单位计算收益估计差为 $\hat\Delta$, 标准误为 $s$. $|\hat\Delta|$ 与 $s$ 同量级时, 直接押注高预算风险大;增加 pilot 可以缩小 $s$. 当新增测量的期望决策收益低于其成本时, 才进入最终 run. 这属于信息价值问题, 小规模消融由此成为大规模训练前的风险控制投入. pilot 必须保留与长跑相同的关键条件. 小规模使用更短回答、更容易数据、同步 rollout, 长跑切到长上下文、困难课程与异步流水, pilot 得到的效率排序可能失效. 可以缩短步数与模型规模, 但要验证组奖励分布、长度、policy lag 和瓶颈阶段仍具有代表性.

模型缩放还会改变最佳采样预算. 更强模型对同一题的 $p$ 上升, 原本全错的题进入混合区, 同样 $G$ 产生更多有效组;容易题又更快全对. 数据难度需要随模型调整, 否则更大模型把大量预算花在饱和题上. 比较不同模型规模时, 固定数据测量真实效应, 自适应数据测量各自 compute-optimal 效应, 两组问题应分开. 如果目标是比较算法, 固定模型、数据、硬件与计算横轴;如果目标是寻找给定预算下的最佳系统, 可以联合改变模型规模、数据与 recipe. 前者强调归因, 后者强调最终效用. 将两种实验混在一起, 很容易把更大模型或更好数据的收益写成优化算法收益.

训练规模还决定评测分辨率. 高预算阶段曲线每增加一万 GPU 时只涨 0.2 点, 而评测标准误为 0.3 点, 无法判断边际收益. 增加评测题或采样次数可以降低噪声, 也要花计算. 评测预算应让测量误差小于希望识别的能力差距. 以二值题目准确率近似, $n$ 道独立题、真实正确率 $p$, 标准误约

$$
\sqrt{\frac{p(1-p)}{n}}.
$$

$p=0.5,n=1000$ 时约 1.58 个百分点. 想稳定识别 0.2 点差距, 单次 1000 题远远不够, 需要更多题、配对比较或多次采样. scaling 曲线看似光滑, 也可能只是拟合压平了评测噪声. 配对评测通常更省样本. 两个 checkpoint 在同一批题、同一采样种子下比较, 题目难度的公共波动被抵消;独立采样则方差更高. 随机生成无法完全共用路径, 仍可固定题集并用题目级 bootstrap. 报告差值置信区间, 比分别报告两个均值更适合判断扩展收益. 污染会制造虚假的高预算增益. 模型训练越久, 越有机会记住近重复题或特定答案格式. 扩展曲线在普通验证集上继续上升, 严格去重集可能已经饱和. 至少准备 iid 保留集、结构去重集与边界难度集, 三条曲线共同描述效率、泛化和能力上限.

当 iid 曲线可预测、边界集不涨时, recipe 可能只提高当前分布效率;边界集也随预算上升, 才有证据支持能力范围扩大. 这与论文区分渐近性能和计算效率的思路一致, 只是将纵轴进一步按泛化强度拆分. 最终的扩展决策可以写成一页表:目标分数与截止时间, 候选 recipe 的拟合曲线和区间, 四类成本,失败概率,policy lag,验证器误差,题型覆盖,以及达到目标的预计预算. 表中任何一格没有测量, 就标作未知并为它留风险余量. 这种做法比给出一个看似精确的 GPU 小时数字更诚实.
