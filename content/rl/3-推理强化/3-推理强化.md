# 推理强化学习

## 1. 从可验证信号到可用梯度

### 1.1. 可验证奖励改变反馈来源

数学答案、代码测试和形式证明可以由程序检查，给出了比通用奖励模型更明确的反馈。令验证器为 $v(x,y)\in\{0,1\}$，最直接的目标是
$$
J(\theta)=\mathbb E_{x\sim q,y\sim\pi_\theta(\cdot\mid x)}[v(x,y)].
$$
这个期望就是单次采样通过率。验证器确定并不意味着梯度确定：回答由离散 token 构成，训练仍要用采样估计策略梯度；奖励只在序列末尾出现时，所有 token 共用同一个终局信号；困难提示几乎全错、简单提示几乎全对时，有限组样本没有可用的组内差异。

若每个提示采样 $G$ 条回答，朴素成功率估计的条件方差为 $p_x(1-p_x)/G$，其中 $p_x$ 是当前策略在提示 $x$ 上的通过概率。$p_x$ 接近 $0$ 或 $1$ 时，样本几乎不给出成功与失败的对照。信息较多的区域通常位于中等成功率附近，因此难度课程、增加采样和保留探索性会直接改变有效训练分布。

### 1.2. 从序列奖励到 token 梯度

对完整回答使用 REINFORCE，可得
$$
\nabla_\theta J=\mathbb E\left[(v(x,y)-b(x))
\sum_{t=1}^{|y|}\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})\right].
$$
同一序列中的每个 token 被乘以相同优势，这在期望上可以成立，却不能指出哪一步推理真正改变了结果。早期选错方向和最终算术失误得到相同负信号；一条偶然猜对的路径会让全部 token 获得正信号。序列级奖励解决了结果判定，信用分配仍然存在。

先对每条序列求 token 平均再对序列平均，会让每条回答权重相等；把 batch 中所有 token 直接平均，则长回答贡献更多梯度项。若优势在序列层定义而长度与成功率相关，两种 reduce 口径会产生不同策略偏好。算法比较必须分开 reward granularity、advantage granularity 和 loss reduce。

过程奖励试图给中间步骤反馈。若过程验证器能判断每一步是否合法，可构造稠密回报；但局部正确不保证整条推理通向答案，过程标签也可能偏爱熟悉写法。另一条路线从最终结果反推步骤价值，用蒙特卡洛续写估计「从此前缀继续成功」的概率。它接近价值函数定义，代价是每个前缀需要额外采样。
组内相对优势的统计结构。 对同一提示的奖励 $R_1,\ldots,R_G$，常见组内标准化写成
$$
\hat A_i=\frac{R_i-\bar R}{s_R+\epsilon},\qquad
\bar R=\frac1G\sum_{j=1}^G R_j.
$$
它消除了不同提示奖励均值和尺度差异，让不需要 critic 的组内比较成为可能。代价是样本之间发生耦合：$R_i$ 同时出现在分子、本组均值和标准差中，一个样本的优势会随其他回答变化。组大小改变后，即使原始奖励相同，优势幅度也可能改变。

二值奖励尤其容易手算。若组内有 $k$ 条成功，成功与失败各自得到两个固定优势值；$k=0$ 或 $k=G$ 时方差为零，整组没有相对信号。随着训练推进，简单题更频繁进入全对区，困难题停在全错区，中间难度提示承担大部分更新。这会隐式形成课程，也可能导致两端能力停滞。

RLOO 采用 leave-one-out baseline：
$$
\hat A_i=R_i-\frac{1}{G-1}\sum_{j\ne i}R_j.
$$
当前奖励不进入自己的基线，避免样本与基线的直接自相关。它不除以组内标准差，因此保留奖励尺度，同时对异常值更敏感。GRPO 式标准化与 RLOO 的差别还包括有限样本偏差、提示间权重和奖励缩放不变性。
裁剪比率与策略版本。 rollout 由旧策略 $\pi_{\rm old}$ 生成，更新使用 token 比率
$$
r_{i,t}(\theta)=\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{\rm old}(y_{i,t}\mid x,y_{i,<t})}.
$$
比率在 token 层定义，奖励和优势可能在序列层定义。裁剪限制已采样 token 对代理目标的贡献，不能约束未采样 token，也不能保证整个序列 KL 落在给定区间。同一批 rollout 更新多轮后，策略逐渐远离行为策略，clip fraction 与近似 KL 上升，有效样本量下降。

异步训练还会产生策略陈旧。生成服务开始长回答时使用版本 $k$，优化器收到样本时可能已到 $k+m$。旧 log probability 必须和实际采样时的温度、截断及词表掩码一致，否则 ratio 不是真实重要性权重。序列级 ratio 连乘所有 token，长序列方差很大；token 级 ratio 方差较小，却只做局部校正。
探索与验证器边界。 当前策略从未采到正确轨迹时，纯结果奖励无法给出移动方向。提高温度或熵能扩大覆盖，也会降低单条轨迹质量；best-of-$N$ 能找到稀有成功样本，若只保留成功轨迹，更新又带有选择偏差。数学推理可能需要高层分支多样，在算术与语法 token 上保持确定，统一 token 熵无法区分这些层次。

程序验证器也可能不完整。单元测试只覆盖有限输入，字符串解析可能接受格式漏洞，形式证明内核保证证明项有效，却不保证定理陈述符合用户意图。多个信号简单线性相加时，策略还可能用大量低成本格式分抵消关键错误。隐藏测试、对抗样本与人工抽查仍是反馈系统的一部分。

基础模型的初始覆盖给出了另一条硬边界。若正确推理在当前策略下的概率远低于有限 rollout 能触及的范围，组内估计无法凭空产生正样本。监督冷启动、课程采样和搜索可以先把成功轨迹带入支持集，强化学习随后重新分配概率质量。报告 RLVR 收益时，基础模型、冷启动数据和每题采样预算都属于必要条件。

pass@$k$ 衡量固定策略采样 $k$ 次至少一次成功的概率。独立同分布时理论值为 $1-(1-p)^k$，真实样本存在模式相关，独立假设往往偏乐观。强化学习提高单次成功率 $p$，推理搜索改变有效 $k$ 与样本相关性。固定总生成 token 后再比较，才能区分训练收益与额外推理预算。

大模型把强化学习重新带回舞台中央以后，最容易被混在一起的三个东西是：**可验证奖励、组内相对优势和推理能力增长**。数学题答案能由规则检查，于是我们可以便宜地获得大量奖励；同一道题采样多个回答，于是可以用组均值代替单独训练的价值模型；训练后模型偶尔会写出更长的推理链，于是人们又很自然地把所有变化都归到“RL 让模型学会了推理”。这三件事确实互相作用，却不在同一个层级。

「可验证奖励强化学习」（Reinforcement Learning with Verifiable Rewards，RLVR）先规定的是**奖励怎样产生**。给定 prompt $x$，策略生成回答 $y$，验证器 $V(x,y)$ 根据最终答案、测试用例、形式证明器或受控执行环境返回奖励 $r$。奖励可以是二元的 $r\in\{0,1\}$，也可以拆成格式分、正确性分和过程约束。接下来怎样用 $r$ 更新策略，仍然可以选 PPO、REINFORCE、RLOO、GRPO 或别的策略梯度估计器。**RLVR 是训练范式，不是某一个优化器的别名。**

算法之间的差异可以落到几个明确位置：优势估计、重要性比、裁剪、损失聚合、验证器、计算扩展和 credit assignment。遇到新的“某某 PO”缩写时，应先确认它改了采样、baseline、ratio、clip、KL、聚合还是训练系统，再判断总分差异来自哪里。

本章按问题而不是按论文发布时间分成四组。先进入[组内估计](./3.1-组内估计/3.1-组内估计.md)，比较 GRPO 与 RLOO 怎样从同题多次采样构造优势；再进入[稳定优化](./3.2-稳定优化/3.2-稳定优化.md)，追踪裁剪、序列聚合和多奖励归一化；随后用[训练配方](./3.3-训练配方/3.3-训练配方.md)检查复杂技巧是否胜过受控的简单基线，以及收益能否随计算扩展；并在[验证与长程](./3.4-验证与长程/3.4-验证与长程.md)里把终局验证、离线轨迹和 Agent 信用分配连起来。四组之间存在依赖，但不是线性算法榜单：前两组说明梯度怎样形成，第三组说明实验怎样成立，第四组说明奖励究竟能约束什么。

## 2. 从回答奖励到参数更新

设 prompt 为 $x$，回答 token 序列为 $y=(y_1,\ldots,y_T)$，当前待优化策略为 $\pi_\theta$，生成这批回答时的行为策略为 $\pi_{old}$。对同一个 prompt 采样 $G$ 个回答：
$$
y_i\sim\pi_{old}(\cdot\mid x),\qquad r_i=V(x,y_i),\quad i=1,\ldots,G.
$$
验证器只看到完整回答时，$r_i$ 是序列级信号。最直接的 REINFORCE 梯度估计为
$$
\hat g_i=(r_i-b(x))\sum_{t=1}^{T_i}
\nabla_\theta\log\pi_\theta(y_{i,t}\mid x,y_{i,<t}),
$$
其中 $b(x)$ 是不依赖当前采样动作的 baseline。它不改变期望梯度，却能减少“题目本身很难或很容易”造成的波动。PPO 通常由价值网络估计 baseline；RLOO 用同一 prompt 下其他回答的平均奖励；GRPO 则常把组内奖励减均值、再除标准差。三者解决的都是优势估计问题，但额外模型、估计偏差和组大小依赖并不相同。

做一个最小手算。同一道题生成四个回答，奖励为 $(1,1,0,0)$，组均值是 $0.5$，标准差按总体标准差计算也是 $0.5$，归一化优势为 $(1,1,-1,-1)$。如果奖励变成 $(1,1,1,1)$，组内差异消失，四个优势全为零，这批样本没有策略梯度信号。由此能看出：验证器返回确定结果，不等于梯度没有方差；采样得到哪些回答、组内是否有差异、长度多长、旧策略与当前策略差多远，都会改变更新。

将序列奖励复制到每个 token 还有一个明显边界：正确回答中的每一步都会收到同号优势，模型并不知道哪一步真正贡献了正确答案；错误回答里某些有价值的中间推理也会一起受罚。终局验证降低了人工标注成本，却没有自动解决长推理链的「信用分配」。过程奖励、步骤验证、搜索树回传和结果重采样都在补这个缺口，只是它们又引入新的标注或计算假设。

## 3. 为什么需要重要性比和裁剪

回答由 $\pi_{old}$ 采样，参数更新却发生在 $\pi_\theta$ 上。二者不一致时，常用 token 级重要性比
$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{old}(y_{i,t}\mid x,y_{i,<t})}
$$
修正分布差异。PPO 风格目标取未裁剪项与裁剪项的较小者，限制单批数据把动作概率推得过远。这里有三个容易藏进实现细节的选择：ratio 是逐 token 计算还是先组合成序列比；损失按 token 平均还是按序列平均；长短回答怎样获得权重。它们会改变有效优化目标，所以“都使用 GRPO”不代表训练的是同一个东西。

裁剪提供局部更新约束，并不保证真实 KL 始终很小。训练还可能显式加入相对参考策略 $\pi_{ref}$ 的 KL 惩罚：
$$
J(\theta)=\mathbb E[r(x,y)]-
\beta\,\mathbb E\!left[
\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}
\right].
$$
$\pi_{old}$ 和 $\pi_{ref}$ 的职责也不同：前者说明数据由谁采样，用来处理 On-policy 偏移；后者定义希望策略不要远离的行为锚点。实际系统可能让二者暂时来自同一个 checkpoint，但概念上不能合并。rollout 服务更新滞后时，$\pi_{old}$ 会越来越旧；参考模型一般保持冻结。把两者混写，会让 ratio、KL 和权重同步问题全部失去口径。

## 4. 一串算法名究竟各自改了哪里

阅读顺序从 [GRPO](./3.1-组内估计/3.1.1-grpo.md) 开始。它提供最常见的组采样框架：同题多答、组内标准化、无需单独价值模型，然后在 PPO 式代理目标中更新策略。[RLOO](./3.1-组内估计/3.1.2-rloo.md) 用 leave-one-out baseline 避免把当前样本自己的奖励放进基线；两者都借助同题多样本降方差，但优势的缩放方式不同。

[DAPO](./3.2-稳定优化/3.2.1-dapo.md) 应当作为一整套训练配方阅读，其中包含采样、过滤、裁剪和聚合设计，不能压缩成单个公式。[GSPO](./3.2-稳定优化/3.2.2-gspo.md) 把约束粒度推向序列级；[GMPO](./3.2-稳定优化/3.2.3-gmpo.md)、[GDPO](./3.2-稳定优化/3.2.4-gdpo.md) 与 [GHPO](./3.3-训练配方/3.3.1-ghpo.md) 则继续调整优势、聚合或长度权重。比较它们时要固定模型、prompt、组大小、采样温度、最大长度、奖励与训练 token 预算，否则无法判断收益来自目标变化，还是更贵的 rollout。

[JustRL](./3.3-训练配方/3.3.2-justrl.md) 把问题拉回一个很重要的工程判断：复杂技巧是否在受控对照里仍然必要。[Tricks or Traps](./3.3-训练配方/3.3.3-技巧与陷阱.md) 进一步检查看似稳定训练的技巧会不会改变样本权重、吞掉有效梯度或掩盖奖励问题。算法改动越小，实验口径越要严；否则一个 batch 组织差异就足以制造“新算法”的优势。

## 5. 推理能力来自哪里

[RLVR 与 DeepSeek-R1](./3.4-验证与长程/3.4.1-rlvr.md) 讨论可验证奖励怎样与推理模型相遇。数学、代码和形式任务适合 RLVR，是因为最终结果能以较低成本核验，模型可以在大量在线样本上探索。不过奖励只覆盖可验证部分：表达质量、事实完整性、风险边界和开放问题通常没有同样可靠的判定器。若训练分布长期偏向“有唯一答案”的任务，模型也可能学会迎合验证器格式，而没有获得可迁移的通用推理。

[强化学习计算扩展](./3.3-训练配方/3.3.4-计算扩展.md) 关心增加 prompt 数、每题采样数、回答长度和更新步数后，能力是否按可预测方式增长。这里的成本不能只算 trainer FLOPs。每个 prompt 采样 $G$ 条长回答，往往让 Decode、验证器执行和跨节点数据传输成为瓶颈；旧 log-prob、mask、奖励分项和策略版本也必须与样本一起保存，训练端才能知道自己在优化哪一批行为数据。

[OREO](./3.4-验证与长程/3.4.2-oreo.md) 将视线转向离线推理优化：已有推理轨迹能否在不持续在线 rollout 的条件下被利用。离线方法省去实时采样系统，却受到数据覆盖和分布偏移限制。好的离线轨迹没有覆盖到的行为，目标函数无法凭空探索出来；坏轨迹过多时，价值或偏好估计又会把数据噪声吸进模型。

### 5.1. 本章采用的统一检查口径

后续每篇算法文章都应回答同一组问题：样本由哪个策略生成；一个 prompt 产生多少回答；奖励作用在 token、步骤还是完整序列；baseline 怎样计算；ratio 在什么粒度定义；是否使用参考策略；KL 在 reward 还是 loss 中；裁剪发生在哪里；损失按 token 还是序列聚合；数据能复用多少轮；rollout 与 trainer 允许多大版本差；训练成本里谁占主要部分。

实验结果还要同时观察 reward、验证集正确率、回答长度、熵、KL、组内零方差比例、ratio 与 clip fraction。**reward 上升只说明模型更会拿当前验证器的分，不足以证明推理更可靠。**真正值得相信的增长，应当在未参与训练的问题、不同验证环境和受控预算下仍然存在，并且没有靠无限加长回答、利用解析漏洞或牺牲其他能力换取。

这些检查项串成「奖励来源—采样分布—优势估计—约束粒度—系统实现—能力结论」的分析框架。新的 GRPO 变体仍可落回这几个可计算、可检查的问题上。
