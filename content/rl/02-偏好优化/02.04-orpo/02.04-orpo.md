## 1. 从两阶段到单阶段

### 1.1 DPO 去掉的是什么, 留下的是什么

DPO 已经把 RLHF 的三阶段 (SFT, 训 reward model, PPO) 压成两阶段 (SFT, DPO), 但它仍然需要一个参考策略 $\pi_{ref}$. 参考策略承担两件事: 一是给隐式 reward 提供归一化基准 $\log\pi_{ref}(y|x)$, 二是通过 $\pi$ 与 $\pi_{ref}$ 的偏离程度隐式限制策略更新步长. 代价是显存与计算: 训练时要为参考模型保留一份参数 (是否额外占用显存取决于是否预计算 reference log-prob, 参数共享, 量化与分布式策略, 不能统一概括为翻倍), 每个 batch 还要为 chosen 和 rejected 各做一次参考模型前向.

ORPO 的问题是: 这两件事能不能都不做. 归一化基准可以省掉吗? 限制更新步长可以换成别的形式吗? ORPO 对两个问题的回答都是肯定的, 而且换来一个额外收益: **SFT 阶段可以直接从预训练模型出发, 不需要先单独做一轮 SFT warm-up**.

从预训练模型直接做偏好对齐有一个真实障碍: 预训练模型只见过 next-token prediction 目标, 没见过对话格式, 更没见过「在这个 prompt 下应该回答成什么样」. DPO 的偏好项只给相对信号 (chosen 要比 rejected 分数高), 不给绝对信号 (chosen 本身应该长什么样). 如果对话格式在偏好数据里覆盖不足, 只跑 DPO 的模型输出格式会退化. 所以 DPO 流程里 SFT 阶段不可或缺. ORPO 把绝对信号 (chosen 的 NLL) 和相对信号 (odds ratio 偏好项) 放进同一个损失, 同一个阶段联合优化, 这就是标题里 Monolithic 的含义.

### 1.2 Odds 为什么是比概率更合适的素材

DPO 的隐式 reward 是 $\beta\log\frac{\pi_\theta(y|x)}{\pi_{ref}(y|x)}$: 概率比. ORPO 换用**优势比 (odds ratio)**. 模型对回复 $y$ 的优势定义为

$$\text{odds}_\theta(y|x)=\frac{P_\theta(y|x)}{1-P_\theta(y|x)}.$$

一个事件的优势是它的发生概率与不发生概率之比. 概率 $p$ 靠近 $1$ 时被压缩在 $(0,1)$ 里, 从 $0.9$ 到 $0.99$ 只移动了 $0.09$; 换成优势后同样是从 $9$ 到 $99$, 动态范围被拉开. 优势比 $OR=\text{odds}(y_w)/\text{odds}(y_l)$ 把一个「乘法意义下的相对量」变成「加法意义下的差值」: 取对数后 $\log OR$ 就是两个 log-odds 的差, 这正好接得上 logsigmoid 偏好损失的形式.

更重要的是 $1-P$ 这一项的语义. $\log\text{odds}(y)=\log P(y)-\log(1-P(y))$ 同时依赖 $P(y)$ 和它的补数. 语言模型对一条普通回复的序列分数通常很小 (几何平均意义上, $P$ 常见量级在 $10^{-1}$ 甚至更低下), 此时 $1-P\approx 1$, odds 与 $P$ 几乎重合; 当模型对某条回复很自信时, 补数项开始起作用, 优势增长快于概率. 论文正是利用这一点构造偏好信号: 既奖励提高 chosen 的分数, 也通过分母惩罚 rejected 的优势. 这个设计不需要任何外部基准, 全部信息来自当前模型自己的输出分布.

### 1.3 长度归一化: $P_\theta$ 到底是什么

对包含 $T$ 个有效 response tokens 的回复, 先计算平均 log probability, 再取指数:

$$s_\theta(y|x)=\frac{1}{T}\sum_{t=1}^{T}\log\pi_\theta(y_t|x,y_{<t}),\qquad P_\theta(y|x)=\exp(s_\theta(y|x)).$$

两个细节必须先定下来. 第一, $P_\theta$ 是 token 条件概率的几何平均分数, 取值在 $(0,1)$, 它不是对所有完整序列归一化的概率分布, 全序列概率的乘积形式 $\prod_t\pi_\theta(y_t|x,y_{<t})$ 随长度指数衰减, 不能直接比较长短不同的回复. 第二, 求和只对 response tokens 进行, prompt 和 padding 不参与. 平均而非求和就是长度归一化本身, 它让 $s_\theta$ 成为「每个 token 平均有多确定」的度量, 两条长度不同的回复可以在同一尺度上比较.

后文的 odds 全部基于这个几何平均分数计算, 不基于未归一化的序列概率. SimPO (1.2.5 节) 后来沿用了同样的长度归一化思路, 说明这个选择本身被后续工作接受了.

### 1.4 时间线里的位置

把 ORPO 放回 2023 到 2024 年偏好优化的演进序列里看, 它的定位更清晰. 2023 年 5 月 DPO 提出, 证明偏好对齐可以不跑 PPO; 随后几个月里 RLHF 社区的主要批评集中在 DPO 仍需要参考模型和单独 SFT 阶段. 2024 年初 KTO 换掉了成对比较的信号形式, IPO 讨论识别性 (identifiability) 问题, 3 月 ORPO 给出「参考自由 + 单阶段」的组合答案, 6 月 SimPO 在同一方向上继续削减, 用长度归一化分数加 margin 替代 odds ratio. 这条线的共同趋势是: 每一步都在删组件 (reward model, 参考模型, SFT 阶段, 偏好损失的函数形状), 代价都是把被删组件承担的控制责任转移给剩余的超参.

这个趋势在实践上体现出的内容是: DPO, ORPO, SimPO 这些方法之间的差距, 远小于「做不做偏好对齐」之间的差距, 也远小于「偏好数据好和差」之间的差距. 与其纠结选哪个损失函数, 不如先把数据管好; 方法选型留在后面, 等 1.4 章的家族对比篇展开再细说.

### 1.5 论文要解决的具体痛点

论文引言批评的对象值得复述准确. 在 ORPO 之前的实践里, 即使采纳了 DPO 这类免 RL 方法, 一个完整的对齐流程仍包含: 先收集 SFT 数据训一个基础对话模型, 再收集偏好对做 DPO, 偏好阶段还需要一个冻结的参考模型提供 log-prob. 论文认为两个「额外」都可以砍: SFT 阶段可以通过在损失里并入模仿项来砍掉, 参考模型可以通过用 odds ratio 替代概率比来砍掉. 砍完之后的流程是: 预训练模型 + 偏好对数据 + 一个损失函数, 直接出对齐模型.

「砍掉 SFT 阶段」说的是数据组织方式：高质量示范以偏好对中的 chosen 进入训练，无需另建一份 SFT 数据集。模型仍要从这些示范中学习能力。chosen 质量平庸时，单阶段模型的上限也会被数据限制，这是流程简化绕不开的约束。

## 2. ORPO 损失逐项推导

### 2.1 整体目标与两项分工

ORPO 把监督微调损失和偏好损失合并:

$$\mathcal{L}_{ORPO} = \mathcal{L}_{SFT} + \lambda \cdot \mathcal{L}_{OR}.$$

$\mathcal{L}_{SFT}$ 是 chosen 回复的负对数似然, 提供**绝对信号**: 教会模型在目标格式下说出 chosen 那样的回答. $\mathcal{L}_{OR}$ 是 odds ratio 上的 logsigmoid 损失, 提供**相对信号**: 让 chosen 的优势相对 rejected 拉大. $\lambda$ 控制偏好的相对权重, 它和 batch 构造方式, 数据噪声水平, 模型规模都相关, 需要按实验调节, 不是可以拍死的常数.

两项损失由同一个模型计算, 所有梯度都作用在同一组参数 $\theta$ 上. 这是它和 DPO 流水线最本质的结构差别: DPO 阶段模型已经见过 SFT 数据, 偏好项是在一个「格式已经学会」的模型上继续推; ORPO 从预训练模型出发, 两项必须同时学会, 数据配比和 $\lambda$ 的调节空间因此更大, 训练动态也更难伺候.

### 2.2 SFT 项: 逐 token 的模仿

$$\mathcal{L}_{SFT} = -\frac{1}{T_w}\sum_{t=1}^{T_w}\log\pi_\theta(y_{w,t} | y_{w,<t}, x)=-s_\theta(y_w|x).$$

这里采用单样本, 仅 response tokens 的平均 NLL, 与 $s_\theta$ 的定义一致. 批量训练时对样本再取一次平均. 实际实现里要显式处理 token mask (排除 prompt 和 padding) 和 reduction 方式, $\lambda$ 的取值要和这套约定配套: 如果实现改成按 token 求和而非按样本平均, 损失数值整体缩放, 同一个 $\lambda$ 就不再等价.

这项只作用在 chosen 上. rejected 回复不提供模仿信号, 模型对 rejected 的分布变化完全由偏好项间接驱动. 这和 DPO 一致, 和后面 KTO (1.2.6 节) 的「好坏样本都给信号」形成对照. 间接驱动意味着 rejected 侧没有显式锚点: 模型对 rejected 做什么, 取决于 odds 分母的位置而不是任何绝对目标, §5.4 的第四种失败模式就源于此.

另一个实现约定值得写明: 很多复现把 $\mathcal{L}_{SFT}$ 也按 batch 平均后再加偏好项, 这等价于给 $\lambda$ 乘上一个与 batch 内 SFT 损失均值相关的隐式缩放. 官方实现在样本级加权, 两者在损失均值随 batch 波动时不等价. 对比不同复现的数字前先确认这一约定, 否则 $\lambda$ 无法直接搬用.

### 2.3 Odds ratio 项: 从 OR 到 logsigmoid

偏好项直接最大化优势比, 取对数后套 logsigmoid:

$$\mathcal{L}_{OR} = -\log \sigma \left( \log \frac{\text{odds}_\theta(y_w|x)}{\text{odds}_\theta(y_l|x)} \right).$$

展开 $\log\text{odds}(y)=\log P(y)-\log(1-P(y))$, 并令

$$\Delta=\log\text{odds}_\theta(y_w|x)-\log\text{odds}_\theta(y_l|x),$$

则 $\mathcal{L}_{OR}=-\log\sigma(\Delta)$. 它的形状和 DPO 的 Bradley-Terry 损失完全一样, 差别只在 $\Delta$ 的构造: DPO 的 $\Delta$ 是 $\beta(\log\pi_\theta(y_w)-\log\pi_{ref}(y_w)-\log\pi_\theta(y_l)+\log\pi_{ref}(y_l))$, ORPO 的 $\Delta$ 是两个 log-odds 的差, 不含任何参考项.

### 2.4 梯度逐项展开

对 $\Delta$ 求导:

$$\frac{\partial\mathcal{L}_{OR}}{\partial\Delta}=-\sigma(-\Delta)=-\frac{1}{1+e^{\Delta}}=-\frac{1}{1+OR}.$$

$\sigma(-\Delta)$ 是 $(0,1)$ 之间的权重: 当 chosen 相对 rejected 的优势已经很悬殊 ($OR$ 很大), 梯度权重趋近 $0$, 这条样本基本不再推动参数; 当两者接近 ($OR\approx 1$), 权重接近 $0.5$, 推动最强. 这和 DPO 的梯度权重 $\sigma(-\beta\log\frac{\pi_\theta(y_w)\pi_{ref}(y_l)}{\pi_\theta(y_l)\pi_{ref}(y_w)})$ 是同一类饱和结构.

参数梯度还要乘上 $\nabla_\theta\Delta$. 每一项的形状由 $\partial\log\text{odds}/\partial s$ 决定:

$$\frac{\partial\,\log\text{odds}(y|x)}{\partial s_\theta(y|x)}=\frac{\partial}{\partial s}\left[s-\log(1-e^{s})\right]=1+\frac{e^{s}}{1-e^{s}}=\frac{1}{1-e^{s}}.$$

$s$ 是负数, $e^s\in(0,1)$, 所以这个因子恒大于 $1$: log-odds 对分数的敏感度高于 log 概率本身. $s$ 越接近 $0$ (模型越自信), $1-e^s$ 越小, 因子越大. 这意味着 ORPO 的偏好项在模型高置信区域施加了比 DPO 更强的梯度, 训练中需要留意这是否带来更激进的更新.

### 2.5 数值手算一: 从分数到损失

取一对教学用样本: 模型对 chosen 的几何平均分数 $P_w=0.8$, 对 rejected 的 $P_l=0.2$. 两步算到偏好损失.

第一步, odds 与优势比. $\text{odds}(0.8)=0.8/0.2=4$, $\text{odds}(0.2)=0.2/0.8=0.25$, 所以

$$OR=\frac{4}{0.25}=16,\qquad \Delta=\log 16\approx 2.7726.$$

第二步, logsigmoid. $\sigma(2.7726)=1/(1+e^{-2.7726})=1/(1+0.0625)=0.9412$, 因此

$$\mathcal{L}_{OR}=-\log 0.9412\approx 0.0606.$$

同时 $\mathcal{L}_{SFT}=-\log 0.8\approx 0.2231$. 若 $\lambda=1.0$, 单样本总损失约 $0.2837$. 注意在这个例子里 SFT 项反而是大头, 因为 $0.8$ 的几何平均分数对真实模型来说高得不寻常; 训练初期的真实模型, $s_\theta$ 常见量级在 $-1$ 到 $-3$, 对应 $P$ 在 $0.05$ 到 $0.37$, SFT 项数值远大于这里.

### 2.6 数值手算二: 梯度权重随训练进程的变化

固定 rejected 的分数, 让 chosen 的分数从接近 rejected 拉到很悬殊, 看 $\partial\mathcal{L}_{OR}/\partial\Delta$ 怎么变. 取 $s_w=s_l=-1$ (即 $P_w=P_l\approx 0.368$, odds 都是 $0.582$, $OR=1$), 此时梯度权重 $\sigma(0)=0.5$, 偏好项推动最积极. 训练把 chosen 拉高到 $s_w=-0.2$ ($P_w=0.819$, odds $=4.53$), rejected 保持在 $-1$, 则 $OR=7.79$, $\Delta\approx 2.053$, 梯度权重降到 $\sigma(-2.053)\approx 0.114$. 再过一步 $s_w=-0.05$ ($P_w=0.951$, odds $=19.5$), 权重只剩约 $0.048$.

这个饱和曲线有一个直接后果: ORPO 自动把训练预算集中在「还没拉开差距」的样本上, 已经排好序的对子逐渐失效. 它和 DPO 一样存在多 epoch 复用收益递减的问题, 已排好序的样本重复喂入只贡献很小的梯度.

### 2.7 数值手算三: 一个 batch 的完整前向

把上面所有 pieces 拼到一个三样本的 batch 上, 走一遍完整计算. 设 $\lambda=0.1$, 三个偏好对的几何平均分数如下:

| 样本 | $s_w$ | $s_l$ | 状态 |
|------|-------|-------|------|
| A | $-0.51$ | $-1.61$ | 已排好序 ($P_w=0.60$, $P_l=0.20$) |
| B | $-0.92$ | $-0.92$ | 尚未排序 ($P_w=P_l\approx 0.40$) |
| C | $-2.30$ | $-0.51$ | 排反了 ($P_w=0.10$, $P_l=0.60$) |

样本 A: $\log\text{odds}(0.60)=\log 1.5\approx 0.405$, $\log\text{odds}(0.20)=\log 0.25\approx-1.386$, $\Delta_A\approx 1.792$, 梯度权重 $\sigma(-1.792)\approx 0.167$. 偏好项 $\mathcal{L}_{OR,A}=-\log\sigma(1.792)\approx 0.184$, SFT 项 $0.51$, 加权和 $0.51+0.1\times 0.184=0.528$.

样本 B: $\Delta_B=0$, 梯度权重 $0.5$ 最大, 偏好项 $\log 2\approx 0.693$, 总损失 $0.92+0.069=0.989$. 样本 C: $\Delta_C=-1.792$, 梯度权重 $\sigma(1.792)\approx 0.833$, 偏好项 $-\log\sigma(-1.792)\approx 1.969$, 总损失 $2.30+0.197=2.497$.

batch 平均 $(0.528+0.989+2.497)/3\approx 1.338$. 这个数没有独立的语义, 但它展示了 batch 内部的结构: 一个排反的对子贡献的损失接近其他两个样本之和, 梯度权重也是最大的. 训练初期排反的对子多, 损失大, 更新激进; 随着训练推进, 排反的对子被修正后权重反而降下来. 损失的下降有一部分来自「难样本变少」, 这不等于模型质量同步提升, 看训练曲线时要分清这两种来源.

### 2.8 ORPO 也是 Bradley-Terry 的一种取值

DPO 的推导从 Bradley-Terry 模型出发: 人类偏好 chosen 胜过 rejected 的概率建模为 $P(y_w\succ y_l|x)=\sigma(r_w-r_l)$, reward 取 $\beta\log\frac{\pi_\theta}{\pi_{ref}}$ 后配分函数相消, 得到 logsigmoid 损失. ORPO 没有重走这条推导, 但它的损失形状 $-\log\sigma(\Delta)$ 正是 Bradley-Terry 在 $\Delta$ 取 log-odds 差时的特例: 相当于把 reward 定义为 $r_\theta(y|x)=\log\text{odds}_\theta(y|x)$, 参考 reward 恒为 $0$.

这个视角解释了为什么 ORPO 和 DPO 的梯度结构如此相似: 它们共享同一个排序模型, 只在 reward 的构造上不同. 它也显出 ORPO 的一个理论弱点: Bradley-Terry 推导中配分函数相消依赖 reward 的特定参数化, 换成 log-odds 后「配分函数为零」这一步不再有任何推导支撑, 损失就是直接定义的. 这不构成反对——所有 reference-free 方法都在某种意义上是直接定义的损失——但意味着它的理论动机是「工程合理」而非「从偏好公理推出」. IPO (1.2.3 节) 对 DPO 做的识别性批评, 换一个 reward 参数化后要重新分析, ORPO 原文没有做这件事.


把 reward 取成 $r(y|x)=\log\text{odds}(y|x)$ 后, 偏好损失 $-\log\sigma(r_w-r_l)$ 为 reward 差采用 logistic 噪声模型。Bradley-Terry 从这一模型出发，ORPO 则把模型自身置信度变换成 reward，尺度会随训练阶段漂移。训练早期的 $s$ 接近起点模型，$r$ 集中在窄带，$\Delta$ 方差较小；训练推进后 $s$ 向两侧展开，$\Delta$ 分布也变宽。同一个 $\lambda$ 在早期和晚期拥有不同实际强度，调参应按阶段观察 $\Delta$ 与梯度分布。

## 3. 与 DPO 逐点对照

### 3.1 参考项的缺席改变了什么

把 DPO 和 ORPO 的 $\Delta$ 并排放:

$$\Delta_{DPO}=\beta\left[s_\theta(y_w)-s_\theta(y_l)\right]-\beta\left[\log\pi_{ref}(y_w)-\log\pi_{ref}(y_l)\right],$$

$$\Delta_{ORPO}=\left[s_\theta(y_w)-\log(1-e^{s_\theta(y_w)})\right]-\left[s_\theta(y_l)-\log(1-e^{s_\theta(y_l)})\right].$$

参考模型的作用在 DPO 里有两层. 第一层是基准: 只比当前模型的分数差, 模型可以靠整体压低所有回复的分数来「作弊」地拉大相对差 (DPO 的归一化讨论详见 1.2.2 节). ORPO 用 odds 替代概率, $\log(1-P)$ 项在一定程度上扮演了对分数尺度的约束: 模型不能无代价地把 $P$ 压向 $0$, 因为那样 rejected 的 odds 也会塌缩, 优势比反而变小. 第二层是步长限制: DPO 里 $\pi$ 偏离 $\pi_{ref}$ 越远, 隐式 KL 越大, 梯度权重自动衰减. ORPO 没有这个机制, 它的步长控制完全交给 $\sigma(-\Delta)$ 的饱和和优化器的全局设置, 这是省掉参考模型换来的代价.

也要诚实交代省了什么: ORPO 不需要参考模型前向, 但 chosen 和 rejected 的两次前向和反向一个都不少, 和 DPO 完全同量级. 它省的是参考模型的那组前向和一份参数, 不是偏好训练本身.


两边都用了长度归一化: DPO 在序列概率上, ORPO 在几何平均分数上. 长度效应的来源是对齐社区反复讨论的问题: 偏好标注里 chosen 往往比 rejected 更长, 不做归一化的目标会系统性奖励啰嗦. ORPO 的平均 log probability 天然带归一化, 但它引入了一个相反的隐患: 平均分数相同的回复, 短的哪个 token 都更确定, 长的允许局部含糊. 论文没有宣称这个问题被解决, 实际效果依赖数据里长度差的分布.


三条方法的流程差异可以收进一张表:

| 特性 | RLHF (PPO) | DPO | ORPO |
|------|------------|-----|------|
| **阶段数** | SFT, RM, PPO 三段 | SFT, DPO 两段 | 一段 |
| **参考模型** | 需要 | 需要 | 不需要 |
| **绝对模仿信号** | SFT 阶段提供 | SFT 阶段提供 | 损失内的 $\mathcal{L}_{SFT}$ |
| **相对偏好信号** | reward 标量 | 概率比 logsigmoid | 优势比 logsigmoid |
| **每 batch 前向** | rollout, value, ref, policy | policy×2, ref×2 | policy×2 |

表内「每 batch 前向」只数计算角色, 参数可共享或分离; 训练速度和显存应在相同模型, 硬件与配置下测量.

### 3.2 与 SimPO, KTO 的边界

随后出现的 SimPO 保留了参考自由与长度归一化分数，使用 $\mathcal{L}_{SimPO}=-\log\sigma\left(\frac{\beta}{|y_w|}\log\pi_\theta(y_w|x)-\frac{\beta}{|y_l|}\log\pi_\theta(y_l|x)-\gamma\right)$，并显式加入 margin $\gamma$。两者都让当前模型分数差承载偏好信号。SimPO 作者指出，odds 中的 $\log(1-P)$ 会放大高置信区域的梯度，直接使用归一化分数更容易控制。具体收益仍取决于基座、数据与超参数。

KTO 走的则是另一条路: 放弃成对比较, 对每条样本单独给「好/坏」的效用信号. ORPO 和 DPO 一样依赖 pair 内 rejected 的质量: rejected 太差不提供信息, rejected 是高质量的 hard negative 时贡献最大. KTO 不受此约束, 代价是它不再直接优化两两排序, 与人类偏好的 Bradley-Terry 形式更远. 三类方法的分界不在公式细节, 而在信号形式: pair 排序 (DPO, ORPO, SimPO) 对 pointwise 效用 (KTO), 参考自由与否是第二个轴.


### 3.3 单阶段的代价与显存真相

「不需要参考模型」在宣传语境里常被读成「显存减半」, 这个推论不成立, 前文已经拆过计算角色. 这里给出正确的测量口径. 训练时显存的主要成分: 模型参数 (BF16 下每 $N$ 参数占 $2N$ 字节), 梯度 ($2N$), 优化器状态 (AdamW 混合精度下约 $12N$), 激活 (随 batch 和序列长度变化), 以及参考模型——如果它存在, 占 $2N$ 参数加一次前向的激活. 参考模型的显存占比是 $2N/(16N+\text{激活}+\text{参考 }2N)$ 量级, 在激活不主导的常见配置下约 $10\%$, 远没有一半. 如果参考 log-prob 是预计算缓存的, 参考模型甚至可以不进显存.

ORPO 的真实收益在流程和工程复杂度: 少维护一个模型实例, 少一组前向的代码路径, 少一份分布式切分的配置. 在单卡能放下模型的规模上, 这些收益是主要部分; 在模型大到需要切分的规模上, 省一个计算角色也可能意味着切分方案少一种约束. 衡量收益时按自己的配置实测, 不引用宣传数字.

单阶段不是没有代价的. 两阶段流程里, SFT 先把模型固定在一个「格式正确, 内容平庸」的区域, DPO 在这个区域内做相对排序; 两个阶段的问题被解耦, 各自好调. ORPO 把两个问题缠在一起: 早期 $\mathcal{L}_{SFT}$ 主导 (预训练模型离对话格式很远), 偏好项的梯度被淹没; 后期格式学会了, 偏好项接管, 但此时 $\lambda$ 已经定型. 调节 $\lambda$ 实际上是在调「两个阶段的时间配比」, 它没有两阶段流程那么直观. 官方实现和其他复现普遍报告 $\lambda$ 敏感, 这与上面的分析一致.

### 3.4 数据构造的差别

两阶段流程的数据分两种: SFT 数据 (独立的优质示范) 和偏好对 (成对比较). ORPO 单阶段只消费偏好对, 这改变了数据部门的约束: 偏好对里的 chosen 必须同时承担「示范」职责, 质量要求比 DPO 流程里更高——DPO 的 chosen 只要比 rejected 好, ORPO 的 chosen 就是模型唯一模仿对象. 如果偏好数据来自自动构造 (例如用 reward model 或拒绝采样生成多个候选再排序), 两阶段流程可以把「最高分候选」送 SFT, 把「高分对低分」送 DPO; ORPO 只剩后一种数据, 对自动构造管线的利用率反而下降.

反过来, 当偏好数据来自人工标注且 chosen 本身质量高时, ORPO 的数据效率更高: 同一份标注同时完成了「教格式」和「教偏好」两件事. 方法选型因此在很大程度上是数据管线的选型, 这与 §1.4 时间线一节得到的结论一致.

## 4. 实现与数值稳定

### 4.1 log1mexp: 一个小数减法的陷阱

实现里需要 $\log(1-e^{s})$, 其中 $s<0$. 当 $s$ 接近 $0$ (模型对回复高度自信) 时, $e^s$ 接近 $1$, $1-e^s$ 发生灾难性消减, 有效数字全丢, 取对数后得到 `-inf` 或 garbage. 稳定的分段算法是

$$\log(1-e^{s})=\begin{cases}\texttt{log1p}(-e^{s}), & s<-\log 2,\\ \log(-\texttt{expm1}(s)), & s\ge -\log 2.\end{cases}$$

分界点 $-\log 2\approx-0.693$ 的选择理由: $s$ 比它小时 $e^s<1/2$, $1-e^s>1/2$, 直接减法至少保留一位有效数字, `log1p` 精确处理 $\log(1+u)$; $s$ 比它大时用 `expm1(s)` 精确计算 $e^s-1$ 这个小量, 再取 $\log(-\texttt{expm1}(s))=\log(1-e^s)$. 两个分支在分界点连续, 覆盖了整个 $s<0$ 的定义域.

另一个精度细节: $s$ 至少要按 float32 计算. 半精度下 $1-e^s$ 在 $s>-0.01$ 附近就已经没有足够的有效位数, 即使分段算法也救不回来.

$s=0$ 对应 odds 发散。实现里若出现 $s\ge 0$，例如 padding 混入或数值异常，`log1mexp` 会产生 NaN，所以上面的断言需要主动拦截。每条回复至少有 $T\ge 1$ 个有效 token；空回复应在数据清洗阶段剔除，损失函数不接收这类输入。

### 4.2 完整教学实现

下例对应[官方实现](https://github.com/xfactlab/orpo/blob/main/src/orpo_trainer.py) 的 log-odds 差和加权损失逻辑, 并采用 §2.2 的 response 平均 NLL 约定. 两个输入均为形状 `[batch]` 的平均 log probability.

```python
import math
import torch
import torch.nn.functional as F

def log1mexp(s):
    # s 是有效 response tokens 的平均 log probability，必须严格小于 0。
    s = s.float() if s.dtype in (torch.float16, torch.bfloat16) else s
    if not torch.all(torch.isfinite(s) & (s < 0)):
        raise ValueError("平均 log probability 必须有限且小于 0")
    out = torch.empty_like(s)
    low = s < -math.log(2.0)
    out[low] = torch.log1p(-torch.exp(s[low]))
    out[~low] = torch.log(-torch.expm1(s[~low]))
    return out

def orpo_loss(lambda_or, chosen_logps, rejected_logps):
    log_odds_chosen = chosen_logps - log1mexp(chosen_logps)
    log_odds_rejected = rejected_logps - log1mexp(rejected_logps)
    delta = log_odds_chosen - log_odds_rejected
    preference_loss = -F.logsigmoid(delta)
    sft_loss = -chosen_logps
    return (sft_loss + lambda_or * preference_loss).mean()
```

`chosen_logps` 和 `rejected_logps` 由同一模型在 teacher forcing 下计算, 全程保留梯度. `log_softmax` 沿词表维求出每个位置真实 response token 的 log probability, mask 排除 prompt 和 padding 后按有效 token 数取平均. 这条链上任何一步换成「先取概率再取对数」都会引入不必要的下溢, 应保持 log 空间运算.


### 4.3 分布式, 显存与测试

偏好损失要求 chosen 和 rejected 两条序列在同一训练步内完成前向和反向, 这是 DPO 系列共同的工程约束. 实现上有三条常见路径: 把 pair 拼进同一个 batch (实现最直接), 分两次前向后累加梯度 (峰值显存相同, 代码路径清晰), 或借梯度累积把 pair 拆到不同 micro-batch (流水线友好). 三条路径的数学结果一致, 差别只在显存曲线和吞吐.

一个容易踩的坑是 padding 策略. 平均 log probability 的分母是有效 token 数, 如果 batch 内序列长度差异大, 按 batch 最长序列 padding 会浪费算力; 按长度分组 (length grouping) 能压掉无效计算, 且不改变损失定义. 另一个坑是 logits 的显存峰值: `log_softmax` 沿词表维度展开, $[\text{batch},\text{seq},V]$ 的中间张量在长序列上超过激活主体, 应在 gather 出目标 token 的 log-prob 后立即释放完整 logits.


---

给教学实现写单元测试时, 有一个不依赖随机性的不变量可测: 对任意合法的 $s_w, s_l<0$, 分段 `log1mexp` 实现与朴素实现对数恒等式必须在 float32 精度内一致. 测试用例覆盖三段区间: $s$ 接近 $0$ (如 $-10^{-4}$) 考验 `expm1` 分支, $s$ 在 $-\log 2$ 附近考验分段连续性, $s$ 很负 (如 $-20$) 考验不溢出. 再补一条性质: $\Delta$ 反号后损失满足 $\mathcal{L}_{OR}(-\Delta)=\mathcal{L}_{OR}(\Delta)+\Delta$, 它来自 $\log\sigma(-x)=\log\sigma(x)+x$, 任何正确实现都应精确满足.

## 5. 实验边界与后续演化

### 5.1 论文报告了什么, 没报告什么

论文在 Llama-2, Mistral, Gemma-2 等开源模型上对比了 ORPO 与 SFT+DPO, SFT+SimPO 等流程, 报告 AlpacaEval 2 胜率与 IFEval, 指令跟随评测的改善. 可以从中取出的结论是: 在论文设定的数据与评测组合下, 单阶段 ORPO 达到了或超过了先 SFT 再 DPO 的两阶段基线, 且流程更短. 不能从中取出的结论更多: 单阶段收益有多少来自 odds ratio 目标本身, 有多少来自数据配比; $\lambda$ 的敏感区间; 在更大模型或更脏的偏好数据上是否仍然成立. 这些在论文里没有给出系统消融, 引用它时应按这个边界陈述.

这组实验还带来一个读评测口径的提醒. AlpacaEval 2 报告胜率的同时受基座模型和 generation config 影响, 长度控制 (length-control) 变体试图剥离「靠变长取胜」的成分; IFEval 考察指令约束的精确遵循. 一个方法在前者赢而后者平, 通常说明它优化的是风格而非约束遵循, 两者都要看. ORPO 论文同时报了两组, 这个做法本身值得沿用: 任何偏好方法的单一胜率数字都不足以支撑选型结论.

### 5.2 后续工作怎样回应 ORPO

ORPO 留下的两个讨论点都被后续工作接住了. 第一是**长度归一化**: SimPO 沿用几何平均分数, 并把参考自由的思路推到更简的目标上, 直接用长度归一化分数的差加 margin 作为偏好损失. 第二是**偏好目标的形状**: odds ratio 与 Bradley-Terry 在饱和结构上同源, 后续 DPO 家族的比较工作 (1.4.1 节) 把 ORPO, SimPO, KTO 放在同一个实验框架里对照, 结论取决于数据分布和基座模型, 没有单一胜出者.

ORPO 表明偏好对齐并不必然需要独立参考模型, 代价是需要标定 $\lambda$ 并处理更大的梯度尺度. 如果训练管线已经通过参数共享或预计算 log-prob 降低参考模型成本, ORPO 的显存优势会缩小, 主要收益转为简化训练流程.

### 5.3 训练配置与超参实践

复现 ORPO 时, 超参的调节顺序比具体数值更重要, 因为数值随模型和数据变化. 一个可靠的顺序是: 先只用 $\mathcal{L}_{SFT}$ 跑少量 step, 确认对话格式和基本能力在预期轨道上; 再加偏好项, 把 $\lambda$ 从小往大扫, 每一步看三个指标——chosen 分数 $s_w$ 是否上升, 优势比 $OR$ 的分布中位数是否离开 $1$, 以及 held-out 上的生成是否有退化迹象 (重复, 截断, 格式崩坏). 三个指标里任何一个恶化, 先回退 $\lambda$, 再检查数据.

学习率和 scheduler 沿用 SFT 的常见设置即可, 不要因为损失多了一项就激进调大. odds 项在高置信区域的梯度因子 $1/(1-e^s)$ 恒大于 $1$, 模型进入高置信区后偏好项的实际步长比公式表面看起来更大, 这相当于一个隐式的自适应步长放大器. 遇到损失震荡, 第一件要查的事是 batch 里是否混入了 $s$ 异常接近 $0$ 的样本 (通常是数据问题, 不是优化问题).

数据侧的两个实践. 第一, 剔除 chosen 与 rejected 几乎相同的对子, 它们的 $\Delta\approx 0$ 虽然梯度权重大, 但标注噪声也大, 持续推动它们相当于让模型拟合标注者的随机抖动. 第二, 控制 pair 内长度差; 归一化之后长度差不再直接操纵分数, 但长回复的平均分数方差更小, 极端长度差仍会引入系统性偏移.

### 5.4 常见失败模式

第一种是**格式退化**. 预训练模型没见过对话模板时, 偏好数据里如果 system/user 格式覆盖不全, 单阶段训练可能学会偏好信号却没学会格式. 判断方法很直接: 固定一批 prompt 周期性生成, 肉眼检查模板 token 是否稳定出现. 两阶段流程里这个问题由 SFT 阶段兜住, ORPO 必须自己兜.

第二种是**过度自信**. odds 的梯度因子在高置信区放大, 模型一旦对某类回复建立了优势, 偏好项会继续把它推向 $s\to 0$ 的极端. 症状是生成长度塌缩到很短 (平均分数最容易被拉高) 或多样性骤降. 缓解手段是降低 $\lambda$, 或在数据里保留足够的长度多样性.

第三种是**已排序样本的空转**. 如 §2.6 手算所示, 排序正确的对子梯度权重快速衰减, 继续训练它们几乎不贡献更新, 但 loss 曲线上它们仍占主体 (数值小但数量多). 如果 epoch 数按 loss  plateau 来定, 会严重过度训练. 按 $OR$ 分布的饱和程度定 epoch 数更合理.

### 5.5 什么时候选 ORPO

管线从预训练或 mid-training checkpoint 出发、希望合并 SFT 阶段且偏好数据质量较高时，ORPO 是合理选项。已有可靠 SFT checkpoint并能接受参考模型开销时，DPO 与 ORPO 的取舍更多落在目标和调参成本。偏好噪声很大或需要 KTO 式逐样本效用记号时，单一 odds-ratio 信号往往不够细致。

还有一个反直觉的观察: 方法之间的胜负经常随基座模型翻转. 即使实现质量相同, 不同损失与基座置信度分布的耦合方式也会改变结果. ORPO 的 odds 变换对高置信区更敏感, 基座越自信 (预训练越充分, 格式越规整), 它的偏好项起效越早; 基座越弱, 前期越依赖 SFT 项, 偏好训练被推迟. 因此应在自己的管线上小规模扫描 $\lambda$, 观察 §5.4 的四种失败模式谁先出现; 论文超参只能作为扫描起点.

这种耦合还能用分桶实验验证. 按初始模型给 chosen 回答的平均 token 对数概率分成低、中、高三桶, 分别记录 SFT 梯度范数与 odds-ratio 梯度范数. 若高置信桶的偏好梯度先占主导, 而低置信桶仍主要受 SFT 项推动, 就与上面的判断一致. 若三桶完全没有差异, 应优先检查序列 mask、长度归一和梯度累积口径, 因为这些实现细节很容易抹平理论上应出现的置信度差异.

分桶边界应由训练前模型确定并保持不变. 若每个 checkpoint 重新分桶, 样本会随模型置信度迁移, 曲线变化便混合了模型改进与样本组成变化, 难以解释.

## 6. Odds 变换的概率几何

### 6.1 从概率到赔率

对 $0<P<1$，赔率定义为 $P/(1-P)$，log-odds 为

$$
o(P)=\log P-\log(1-P).
$$

ORPO 比较 chosen 与 rejected 的 log-odds 差

$$
\Delta=o(P_w)-o(P_l)
=\log\frac{P_w/(1-P_w)}{P_l/(1-P_l)}.
$$

若 $P_w=P_l$，$\Delta=0$，偏好损失为 $\log2$；$P_w>P_l$ 时 $\Delta>0$。这里的 $P$ 在原实现中来自回答 token 概率的几何平均，数值落在 $(0,1)$，并非完整序列概率。把序列概率乘积直接代入会使长回答的 $P$ 极接近零，赔率几乎退化为概率本身，也会改变论文使用的尺度。

log-odds 的导数为

$$
\frac{do}{dP}=\frac1P+\frac1{1-P}=\frac1{P(1-P)}.
$$

概率接近 0 或 1 时变换很敏感。若输入改为平均 log probability $s=\log P$，则

$$
o(s)=s-\log(1-e^s),\qquad
\frac{do}{ds}=\frac1{1-e^s}.
$$

$s$ 很负时导数接近 1；$s\to0^-$ 时导数发散。这个高置信放大是 ORPO 与简单 log-prob margin 的关键差别。

### 6.2 完整梯度链

偏好项 $L_{OR}=-\log\sigma(\Delta)$ 对 $\Delta$ 的导数为 $-\sigma(-\Delta)$。因此

$$
\frac{\partial L_{OR}}{\partial s_w}
=-\frac{\sigma(-\Delta)}{1-e^{s_w}},
\qquad
\frac{\partial L_{OR}}{\partial s_l}
=\frac{\sigma(-\Delta)}{1-e^{s_l}}.
$$

chosen 还受到 SFT 项 $-s_w$ 的梯度。总损失 $L=-s_w+\lambda L_{OR}$ 给出

$$
\frac{\partial L}{\partial s_w}
=-1-\lambda\frac{\sigma(-\Delta)}{1-e^{s_w}},
\qquad
\frac{\partial L}{\partial s_l}
=\lambda\frac{\sigma(-\Delta)}{1-e^{s_l}}.
$$

梯度下降会提高 $s_w$、降低 $s_l$。chosen 同时得到模仿与偏好两股信号，rejected 只由偏好项压低。两股 chosen 梯度可能在高置信区很大，因此 $lambda$ 的含义依赖当前分数分布，不能只看损失项数值占比。

### 6.3 饱和来自两处竞争

$\sigma(-\Delta)$ 在排序充分正确时趋近零，降低偏好梯度；$1/(1-e^{s_w})$ 在 chosen 高置信时增大，放大梯度。最终权重由两者乘积决定。说“logsigmoid 饱和后样本不再更新”并不总准确，因为 odds 导数可能抵消一部分饱和。

设 rejected 分数固定，chosen 越来越接近 0。此时 $o(s_w)$ 快速增大，使 $\Delta$ 增大，$\sigma(-\Delta)$ 下降。渐近量级需要两项一起算，不能单看其中一个因子。数值日志最好直接记录总的 $|\partial L_{OR}/\partial s_w|$ 分位数。

rejected 若也接近 0，其 odds 导数同样放大。两个高置信回答难分时，偏好项可能产生很强的相反更新，这正是高质量 hard pair 的价值，也会放大错误标签。数据质量越不确定，越需要检查高置信冲突 pair。

### 6.4 OR 不等于序列事件的真实赔率

语言模型完整回答概率极小，几何平均将其转换为典型 token 概率：

$$
P(y\mid x)=\exp\left(\frac1{|y|}\sum_t\log p(y_t\mid x,y_{<t})\right).
$$

这个量表示长度归一化分数，与生成整条回答的概率含义不同。odds 变换由此形成训练信号，用户选择完整回答的真实赔率仍需偏好数据估计。论文中的命名描述数学构造，实验解释应回到模型分数。

若回答每 token 平均概率为 0.2，odds 为 0.25；平均概率为 0.4，odds 为 0.667，二者 odds ratio 为 2.667。序列长度十或一百，只要平均 log probability相同，ORPO 分数相同。真实完整序列概率却相差许多数量级。这正是长度归一化的设计效果与理论口径变化。

## 7. SFT 与偏好项怎样共同塑造概率

### 7.1 Pair 差无法确定公共移动

偏好项关心 $s_w,s_l$ 形成的 odds 差，两者共同移动时 $\Delta$ 可能近似不变。SFT 项要求 chosen 的平均 log probability提高，从而选择公共移动方向。ORPO 去掉 DPO 的显式 reference，并由 chosen 模仿项承担一部分锚定。

候选空间还有大量未出现回答。提高 chosen、降低 rejected 后，归一化所需概率质量可能来自其他序列；pair loss 无法指明具体来源。自由生成可能出现第三种更好答案，也可能收缩到固定模板。离线两项分数不足以判断概率质量去向。

### 7.2 λ 是目标权重也是梯度权重

$\lambda$ 在公式中控制偏好项相对 SFT 项的权重，但实际参数梯度还乘各自 Jacobian。若偏好项的 odds 导数很大，小 $\lambda$ 也可能主导；若多数 pair 已有大正 $\Delta$，较大 $\lambda$ 仍可能贡献很小。报告未加权两项 loss、加权后数值与梯度范数，才能解释训练阶段。

一种实用诊断是计算两个参数梯度的余弦。正值表示 SFT 与偏好项在当前 batch 协同，负值表示提高 chosen 似然与拉开 odds 在共享参数上竞争。总体余弦会掩盖层间差异，可同时查看 embedding、中层和输出层。

梯度冲突并不自动表示目标错误。参数共享使某些 token 同时服务多种任务，局部竞争可能换来总体折中。若冲突长期集中在某类 prompt，并伴随能力退化，才需要调整数据权重、$\lambda$ 或参数化方式。

### 7.3 单阶段从什么起点开始

ORPO 可以从预训练或已有 SFT checkpoint 训练。前者需要 chosen 数据同时教授对话格式、指令遵循与偏好；后者已有较高 chosen 似然，odds 项更早进入高敏感区。同一 $\lambda$ 在两种起点上的有效强度不同。

从较弱起点出发时，rejected 也可能包含流畅表达与任务知识。偏好项压低整个 rejected 回答的平均分数，无法只删除错误片段。chosen 数据覆盖不足时，模型可能连有用能力一起压低。两阶段 SFT 先建立更完整的正向分布，随后偏好优化，仍有其价值。

“单阶段”描述目标同时优化，不表示数据只能有一种。可以混入 chosen-only SFT 样本与 pair 样本，但采样比例会决定任务权重。没有 rejected 的样本只贡献 SFT；pair 样本同时贡献两项。统计训练 token 时，应区分两类来源。

### 7.4 Rejected 中的正确部分

回答常常局部正确、结论错误。序列级 rejected 信号降低整段 token 的联合分数，teacher forcing 梯度会分布到各有效位置。它没有天然的片段级信用分配，正确推导也可能受压。

构造 pair 时让两项尽量只在关键错误附近不同，可以减少无关信号；对开放回答很难做到。另一方法是提供编辑后的 chosen，使正确部分共享、错误部分被替换，但共同后缀在不同前缀下仍有不同条件概率，不能假定梯度只落在编辑位置。

若有可验证步骤标签，可补充 token 或步骤级监督；这已经超出原始 ORPO。实验应区分收益来自 ORPO 目标还是额外信用信号。

## 8. 长度、EOS 与模板边界

### 8.1 几何平均消除了什么

完整序列 log probability随长度累加，通常对长回答更负。除以有效 token 数后得到平均交叉熵尺度，直接线性长度效应减弱。它没有消除内容与长度的相关性：长回答可能包含更多低概率推理 token，短回答可能由高频套话组成。

构造四组反事实最清楚：短正确、长正确、短错误、长错误。若模型只偏爱短文本，短错误也会得到高分；若它识别内容，正确性应跨长度保持。仅报告训练后平均长度无法分辨。

### 8.2 EOS 是否进入平均值

自然结束的 EOS 是模型决策，应计入 response mask。截断样本没有真实 EOS，强行补入会把“达到最大长度”误作自然结束。数据源丢失尾部也应单独标记，不能与正常结束混合。

EOS 计入后，短回答中它占更大比例。安全拒答、简短事实答案与长推理受到的影响不同。应按自然结束、截断与异常缺尾分别统计分数和生成长度。

### 8.3 Prompt 与 response 必须共享条件

chosen/rejected 应使用同一 system prompt、用户消息、工具描述和历史。prompt token 不进入平均 log probability，但会改变后续条件分布。两侧模板不同，比较的已不是同一问题下两个回答。

chat template 的 assistant 起始标记通常属于条件还是回答，要由实现统一。policy 两侧和所有 checkpoint 必须采用同一边界。模板升级后，旧缓存和旧分数都应失效。

### 8.4 分词差异会进入长度归一化

平均按 token 而非字符计算。中文、英文、代码和公式的 token 密度不同，相同信息量可能得到不同分母。混合语言训练时按语言报告有效长度、$s_w,s_l$ 与 $\Delta$，可以发现分词尺度造成的系统差异。

更换 tokenizer 会同时改变 token 概率与长度，旧超参数不可直接迁移。即使模型词表兼容，只要切分方式不同，几何平均分数就换了定义。

## 9. 噪声偏好与比较图

### 9.1 冲突标签的期望方向

同一无序 pair 若 A 以概率 $q$ 获胜，正向样本使用 $\Delta$，反向样本使用 $-\Delta$。期望偏好损失为

$$
q[-\log\sigma(\Delta)]+(1-q)[-\log\sigma(-\Delta)].
$$

其最优点满足 $\sigma(\Delta)=q$，即 $\Delta^*=\log(q/(1-q))$。因此保留重复冲突标签时，ORPO 的 logistic 部分会反映经验胜率；多数票硬化会把任何略高于一半的 $q$ 推成趋向确定的方向。

SFT 项打破上述纯偏好对称性，因为每次 winner 都作为 chosen 被模仿。A 赢时提高 A，B 赢时提高 B，重复比例也决定正向模仿频率。分析冲突 pair 不能只看 logistic 最优点，还要看两个回答的 SFT 贡献。

### 9.2 Tie 与双输

平局可能表示同样好、同样差或无法判断。随机指定 winner 会同时制造偏好方向和 SFT chosen。对同样好的两项，可作为独立 SFT 正例而不加方向；双输应重写候选或退出正向模仿；无法判断则送复审。

被迫二选一的数据容易把较轻错误当理想答案。相对偏好算法都面临这个问题，ORPO 因含 SFT 项更直接地提高相对 winner 似然，因此绝对质量门槛尤其重要。

### 9.3 图中的循环与跨级边

把候选看作节点、偏好看作边，logistic 排序仍隐含标量 score。A 胜 B、B 胜 C、C 胜 A 无法全部得到大正差。训练会按边权折中；高 loss 不一定来自实现错误，也可能是偏好非传递。

即便排序传递，不同边强度也有信息。A 明显胜 C、A 略胜 B，若全部硬标签，logistic 只知道方向，重复投票才逐渐表达置信。保存投票比例比只保存最终 winner 更有价值。

### 9.4 标注者与多目标

不同人可能分别重视准确、简洁、安全和语气。混合后得到由采样比例决定的平均偏好。保存匿名群体或任务角色，可检查某一群体是否被总体胜率掩盖。

分项 rubric 能定位冲突。事实错误应由验证器否决，表达偏好再由 pair 处理；安全可以设置硬门槛。把所有维度压成一个 winner，无法解释训练后哪一项改善、哪一项退化。

## 10. 离线覆盖与迭代收集

### 10.1 候选生成器定义学习边界

低温弱模型产生的 pair 多为明显好坏，适合学习基本方向，却缺少高质量边界；强模型高温采样覆盖更广，也增加不可判定样本。混合生成器时保存模型、温度、top-p 与版本，并按来源组合评估。

若 chosen 总来自强模型、rejected 总来自弱模型，模型名称、自述、格式和长度会成为捷径。去掉来源标记、随机位置，并加入同源模型内部比较，能减少这种偏差。

### 10.2 Pair 数不等于独立信息量

八个候选可产生二十八条 pair，同一回答反复出现。逐 pair 平均会让候选多的 prompt 获得更大权重。若希望 prompt 等权，应先组内平均；若希望随机边风险，则保留逐 pair 权重。

训练验证要按 prompt 或 candidate group 切分。同一回答跨集合会造成泄漏，近重复 prompt 也应按语义簇和来源检查。有效样本量更接近独立 prompt 与候选组数量，而非表格行数。

### 10.3 迭代 ORPO 的移动分布

当前 policy 生成新候选并回流标注，可以暴露旧数据未覆盖的错误，也会改变比较分布。每轮保留固定锚点集，再冻结一份当轮挑战集，才能区分模型变化与题目变化。

只用最新轮容易遗忘，只累积历史会让早期简单 pair 占多数。按任务、轮次、难度重采样，关键安全样本永久保留。采样比例属于目标定义，应写进 manifest。

### 10.4 主动选择 high-loss 样本的风险

高 loss 可能是真难例、错标、模板错误或截断故障。统一回流会放大最脏的数据。先按四项分数、长度、来源与人工复审分类，再决定补标、修复或提高权重。

低 loss 也不一定无用。它们可以稳定格式与基础能力，完全删除会让训练集中只剩边界冲突。保留一定锚点比例，有助于监控遗忘。

## 11. 数值稳定与逐层验收

### 11.1 log1mexp 的两个区间

计算 $\log(1-e^s)$ 时，$s$ 接近零会发生消减。稳定实现按 $s<-\log2$ 分段：较负区域使用 `log1p(-exp(s))`，靠近零使用 `log(-expm1(s))`。分界处两式相等，单元测试应检查函数值和梯度连续。

$s$ 必须严格小于零。出现正值通常说明输入并非 log probability、mask 后错误求和，或先做了不合法归一化。用 clamp 把正值压回负数会隐藏故障，并在边界制造错误梯度，应让训练明确失败并保存样本。

### 11.2 低精度与高置信区

当 $s$ 极接近零，$1-e^s$ 很小，float16 容易舍入为零。log-odds、差值和 logsigmoid 至少用 FP32 计算。token log-prob 可以来自混合精度前向，聚合与非线性应升精度。

高置信 token 的平均不一定让整段 $s$ 接近零，因为一个低概率 token 足以拉低均值。若短回答全由高频 token 构成，才更容易进入敏感区。按长度和 $s$ 联合画分布，比只看最大值更有用。

### 11.3 拼接前向的等价条件

chosen/rejected 在 batch 维拼接可共用一次前向。等价要求各自 attention 独立、position ids 正确、response mask 分开，并在输出后按 pair ID 配对。按长度排序或 packing 后，不能依赖相邻位置恢复 pair。

随机抽样逐条前向，与拼接版本比较每个有效 token log-prob。padding 方式变化后结果也应不变。若 packing 允许跨样本注意，即使最终 mask 只选 response，条件概率已经被污染。

### 11.4 Batch reduction

每条 pair 先得到 $L_i=L_{SFT,i}+\lambda L_{OR,i}$，再按目标权重归约。分布式 worker pair 数不同，应聚合 loss sum 与 count；本地 mean 等权平均会放大小 worker。梯度累积同理。

复制整个 batch 两次，mean loss 与梯度应不变。复制单一 prompt 的全部边，在 prompt 等权方案下也应不变。这两个不变量分别检查 pair 层和 group 层归约。

### 11.5 梯度的符号与有限差分

固定两个标量 $s_w,s_l<0$，自动微分结果应与解析式一致。用中心有限差分检查 chosen 导数为负、rejected 导数为正。交换两侧后，偏好差反号，但 SFT 项随新 chosen 改变，因此总损失没有简单对称式。

在 $s$ 接近零、$-\log2$ 和很负三个区域分别检查。若只测普通区间，分段函数与高置信放大错误都可能漏掉。

## 12. “Reference-free”的准确含义

### 12.1 少了显式 Reference，没有少先验

ORPO 训练不需要冻结第二个模型计算 log-ratio，因此常称 reference-free。当前 policy 仍从预训练或 SFT 权重出发，SFT chosen 项也持续锚定数据分布。初始化、数据与优化器共同形成隐式先验。

没有显式 reference 后，无法用同一个训练公式直接读出 policy 相对固定锚点的漂移。实验仍可另行保留初始 checkpoint，在验证时计算 KL 或 log-ratio。这不会改变训练，只提供可比坐标。

### 12.2 显存节省应按实现测量

DPO 若在线前向 reference，需要额外权重或前向；预计算 reference log-prob、adapter 切换与参数分片都能降低成本。ORPO 省去这条路径，但 chosen/rejected 双序列、logits 和反向激活仍占主要显存。

报告峰值显存、tokens/s、预计算成本和总训练时长，才能说明优势。只数模型份数会忽略 activation、词表 logits 和缓存。不同并行策略下瓶颈也会变化。

### 12.3 没有 KL 约束后的漂移

SFT 项鼓励 chosen，偏好项压低 rejected，但没有显式逐 prompt KL 惩罚。小 $\lambda$ 或短训练可能自然保持接近起点，不能视为理论保证。长时间、多 epoch 或窄数据会造成能力遗忘与分布收缩。

用固定初始模型评估 token KL、生成行为和通用能力，能观察漂移。若需要明确 trust region，可加入额外 KL；此时方法已成为新的混合目标，应单独报告系数。

## 13. 与 DPO、SimPO、SFT 的公平比较

### 13.1 先对齐概率口径

DPO 常用完整 response log-prob sum，ORPO 原实现使用平均 log probability，SimPO也常使用长度归一化分数。若直接复用同一 $\beta$ 或 margin，数值尺度并不一致。先明确 token mask、sum/mean、EOS 与截断，再谈算法差异。

同一批四项 token log-prob 可以派生多种目标，适合做控制实验。每种方法用其标准公式，同时对齐实际训练 token、数据和 checkpoint 选择，避免预处理差异冒充算法收益。

### 13.2 对齐漂移而非只对齐步数

ORPO、DPO 的梯度尺度不同，相同步数与学习率不会产生相同策略距离。训练多个超参数，比较质量—初始模型 KL 前沿。某方法在同等漂移下更好，结论比单点胜率更稳。

还要对齐正向模仿预算。ORPO 每个 pair 都有 chosen SFT，DPO 纯偏好目标没有。给 DPO 增加 SFT 混合项后，比较对象又变了。实验表应明确每个 token 接受哪些损失。

### 13.3 数据预算与计算预算

单阶段节省训练阶段，不代表偏好数据免费。chosen/rejected 仍需生成、筛选和标注。比较总成本时纳入候选生成 token、人工判断、reference 预计算和训练算力。

如果 ORPO 从预训练起点训练更多 epoch，而基线使用现成 SFT，简单计算训练 GPU 时会漏掉 SFT checkpoint 的获得成本；反过来，已有 SFT 是共享资产时，又不应重复计费。成本边界需要按实际决策场景定义。

### 13.4 共同外部指标

不同 loss 数值不可横比。共同指标包括未见 prompt 生成胜率、可执行正确率、长度、拒答、安全、语义多样性、初始模型 divergence 与计算成本。固定 pair 排序可作诊断，不能代替生成。

judge 与训练标签同源会偏向相同风格。优先使用规则或测试，开放任务加入独立人评，并随机左右位置。所有模型使用同一解码配置，同时补充多温度检查稳健性。

## 14. 生成评估与因果边界

### 14.1 Pair accuracy 能证明什么

固定 pair 上 $\Delta>0$ 表示模型分数按标签排序。它不说明 chosen 会被自由生成，也不说明候选外答案质量。ORPO 的 SFT 项提高 chosen 概率，仍无法保证生成落在数据中的理想模式。

记录 chosen/rejected 的绝对平均 log probability和 odds 差。若两者都下降、rejected 降得更多，排序改善却可能伴随正向似然恶化；这通常提示其他答案吸走概率质量。

### 14.2 长度控制不能只做回归

长度与质量可能有真实因果关系，简单把长度从胜率回归掉会删除必要解释。内容匹配的反事实更可靠：保持结论与关键推理，增删冗余；或者保持长度，替换事实错误。分任务报告长度—胜率关系。

解码 `max_new_tokens`、温度与 stop rule 也会影响长度。算法对比固定这些配置，另做敏感性扫描。某 checkpoint 在低温更好、高温崩坏，说明概率分布形状发生变化。

### 14.3 多样性与模板捷径

偏好数据常奖励结构完整的回答，模型可能学会固定开头、总结和项目符号。judge 胜率提高时，检查跨样本短语重复、语义簇数量、结论分布和自重复。字符串不同不等于语义多样。

对格式有硬要求的任务，模板化可能是能力；开放写作中过度模板则降低质量。按任务判断，避免一个全局多样性分数掩盖差异。

### 14.4 可执行任务的硬验证

代码用隐藏测试、资源和安全约束，数学检查答案与关键推导，工具任务核对最终环境状态。偏好 judge 负责多个正确方案间的表达选择，不能覆盖执行失败。

若语言 judge 偏爱详细但错误的回答，硬验证应先否决。报告中将 pass rate 与通过样本上的偏好分开，避免大量流畅失败样本抬高总胜率。

## 15. 训练监控、停止与回滚

### 15.1 必须记录的分布

日志至少包含 SFT loss、OR loss、$s_w,s_l$、$\Delta$、log-odds、有效长度、截断状态、两项梯度范数、学习率、$\lambda$ 与裁剪事件。均值外还要有分位数，少数高置信样本会藏在均值中。

按任务、语言、来源、长度差、标注一致率与生成器分桶。总体改善时某个高风险桶可能已经退化，不能让大体量闲聊平均掉。

### 15.2 停止条件

训练 loss 持续下降不足以继续。未见 prompt 胜率平台、初始模型 KL 上升、chosen NLL 恶化、能力或安全回归，都提示停止。先满足硬门槛，再在质量—漂移前沿选 checkpoint。

若偏好项饱和而 SFT 仍下降，后续训练主要变成 chosen 模仿；若 SFT 平稳但 OR 尾部扩大，可能在追逐异常 pair。分项曲线能解释阶段转换。

### 15.3 回滚需要完整版本

checkpoint 要绑定 tokenizer、模板、解码、数据 manifest 与工具配置。只回滚权重而保留新版模板，行为未必恢复。optimizer、scheduler、随机状态和 dataloader cursor 也应保存，以便训练恢复复现。

上线硬风险失败可直接触发回滚，普通偏好波动需等待足够样本。阈值在发布前确定，避免看到结果后临时改变标准。

### 15.4 失败案例回溯

从生成失败回到训练链：定位相似 prompt 与 pair，核对标签、长度、mask、$s_w,s_l$、odds 差和梯度权重。知识缺失、候选覆盖、错标与模板故障需要不同修复。

高 loss 样本不应自动删除或加权。人工确认后，真难例补覆盖，冲突偏好补投票，数据故障修预处理。残差是入口，不是原因。

## 16. 一组从 token 到更新的完整手算

设 chosen 有三个有效 token，policy 给出的 log probability 为 $(-0.4,-0.8,-0.6)$；rejected 有两个有效 token，对应 $(-1.0,-1.4)$。采用平均口径，

$$
s_w=-0.6,qquad s_l=-1.2,qquad
P_w=e^{-0.6}\approx0.5488,\qquad P_l=e^{-1.2}\approx0.3010.
$$

两侧 log-odds 为

$$
o_w=-0.6-\log(1-e^{-0.6})\approx0.196,
$$

$$
o_l=-1.2-\log(1-e^{-1.2})\approx-0.844.
$$

因此 $\Delta\approx1.040$，偏好损失 $-\log\sigma(1.040)\approx0.303$，SFT loss 为 $0.6$。取 $\lambda=0.1$，单 pair 总损失约为 $0.6303$。这个数可以用独立计算器与训练代码逐项对照。

标量梯度中，$\sigma(-\Delta)\approx0.261$。chosen odds 导数因子为 $1/(1-e^{-0.6})\approx2.216$，rejected 为 $1/(1-e^{-1.2})\approx1.431$。于是

$$
\frac{\partial L}{\partial s_w}
\approx-1-0.1\times0.261\times2.216=-1.0579,
$$

$$
\frac{\partial L}{\partial s_l}
\approx0.1\times0.261\times1.431=0.0374.
$$

chosen 的更新主要来自 SFT，偏好项提供额外上推；rejected 只接受较小的下推。若把 $\lambda$ 增到 1，偏好梯度扩大十倍，chosen 总梯度约为 $-1.579$，rejected 为 $0.374$。这说明 $\lambda$ 不只改变 rejected 压力，也改变 chosen 在 SFT 之外的加速。

再把 chosen 提高到 $s_w=-0.1$，保持 rejected 不变。$P_w\approx0.9048$，chosen log-odds 约为 $2.252$，$\Delta\approx3.096$，$\sigma(-\Delta)\approx0.0433$；chosen odds 导数却增至约 $10.51$。二者乘积约 $0.455$，并没有像单看 sigmoid 那样降到 $0.0433$。高置信放大抵消了相当一部分排序饱和。

若 rejected 也很高，例如 $s_l=-0.12$，两项都接近概率 1，细小平均 log probability差会被 odds 放大。此时标签翻转或浮点误差的影响都更明显。训练日志看到 $s_w,s_l$ 同时靠近零时，应优先抽查这类 pair 的实际文本与 mask。

把长度口径改为 sum，会得到 $s_w=-1.8,s_l=-2.4$。相应 $P$ 很小，odds 修正项较弱，$\Delta$ 更接近普通 log-prob 差 $0.6$。同一 token 数据、同一 $\lambda$ 产生完全不同的损失和梯度，说明聚合口径属于算法定义的一部分。

batch 中再加入第二条 pair，假设其总 loss 为 $1.4$、有效回答 token 共二十个。若逐 pair mean，两条样本各占一半；若把所有 token 混合平均，第二条会因长度获得更大权重。ORPO 公式先构造回答级分数，再构造 pair loss，因此默认归约单位是 pair。改变权重可以，但要显式写出目标。

这个手算还能验收自动微分。将四个输入 token log-prob 设为独立变量，chosen 三个 token 对 $s_w$ 的贡献各为 $1/3$，所以每个 chosen token 的标量梯度约为 $-1.0579/3$；两个 rejected token 各为 $0.0374/2$。padding 与 prompt token 梯度应为零。若实测不符，mask、长度分母或 shift 至少有一处错误。

## 17. 数据权重与概率目标

逐 pair 平均隐含“每行数据同等重要”。现实数据的行由候选数、标注次数和过滤规则共同产生，不等于部署任务权重。某个 prompt 有十六个候选，pair 展开后可以淹没只有两个候选的 prompt。先在 prompt 内平均再跨 prompt 平均，能恢复 prompt 等权。

若部署频率已知，可以为 prompt group 设置权重 $w_g$：

$$
L=\frac{\sum_g w_g\frac1{|E_g|}\sum_{i\in E_g}L_i}{\sum_g w_g}.
$$

这里 $E_g$ 是该 prompt 的边集合。分布式实现必须聚合加权 loss sum 与权重和。用 batch size 作分母会让不同 worker 的任务组成改变全局目标。

极端业务权重会降低有效样本量，近似量为 $(\sum w)^2/\sum w^2$。少数高频请求不应无限支配训练；可截断权重并保留专门回归集。截断改变目标分布，需要同时报告原始与训练权重。

重复标注要区分判断次数与数据复制。十位独立标注者给同一 pair 投票，保留十条记录可以表达经验胜率；把同一硬标签复制十遍只会提高边权。schema 中分别保存 `pair_id` 与 `annotation_id`，才能区分两者。

多数票聚合会同时影响偏好项和 SFT 项。六比四的 pair 若聚合为 A 胜，A 获得一次完整 SFT；保留十条时，A 六次、B 四次成为 chosen，正向模仿也反映不确定性。这可能不符合“只模仿绝对合格答案”的要求，因此更合理的数据设计是先做绝对质量筛选，再保留相对投票。

列表排序拆 pair 时，相邻项与首尾项信息不同。全 pair 展开让一个列表产生 $n(n-1)/2$ 条边，并重复模仿排名靠前的回答。可以只采相邻边、按距离加权或使用列表目标。无论选择哪种，都保留原始列表，便于恢复权重和研究替代目标。

样本权重也会与平方或 logistic 形状不同地作用。ORPO 偏好项对大负 $\Delta$ 的导数趋近常数，再乘 odds 导数；高权错标 pair 会持续产生稳定压力。设置单边权重上限、按标注置信校准，并检查高影响样本，比事后只看总体 loss 安全。

课程顺序会造成路径依赖。先用清晰好坏 pair 建立格式与基本方向，再加入高质量 hard pair，可能比一开始混入全部冲突更稳；反过来，过多简单 pair 会让模型先形成高置信，之后 hard pair 进入 odds 敏感区。即使最终看过相同数据，Adam 状态与参数路径也会不同。

比较课程策略要固定总 pair、token 和最终分布，并用多个随机种子。只展示一次更快收敛无法证明最终更好。早期异常 pair 还可能污染 optimizer 二阶矩，后续移除数据也不会立即消除影响。

数据时间戳同样重要。事实会更新，产品 rubric 会变化，旧 winner 可能变成新 loser。按时间切分验证能观察分布移动；固定知识问题与时效问题应分别处理。把所有冲突都当主观噪声，会掩盖可解释的版本变化。

## 18. 分布式、并行与恢复一致性

数据并行最容易出错的是尾批归约。假设 worker A 有八条 pair，worker B 有两条，各自 loss mean 后再平均，相当于两侧各占一半；正确全局 mean 中 A 应占八成。聚合 sum 和 count，或确保每个 worker 数量严格相同，才能保持目标。

gradient accumulation 若 microbatch pair 数不同，也要按总 count 缩放。框架常默认每个 microbatch loss 已是 mean，再除 accumulation steps；动态 batch 下会重权小批。写一个不同切分的等价测试，同一全局 batch 分成 $5+3$ 与 $4+4$，一步更新应在数值容差内一致。

FSDP、ZeRO 和张量并行不改变数学目标，但词表并行 log-softmax 必须跨 shard 计算全局最大值与指数和。只在本地词表归一化会给目标 token产生错误 log probability，数值仍有限，尤其难察觉。抽取固定 token 与单卡实现逐项对照。

activation checkpointing 会重算前向。dropout 或随机算子若状态不一致，同一 token 的重算 logits变化，梯度失真。训练可使用 dropout，但重算必须复现同一随机 mask；评估与手算则关闭随机性。

混合精度 scaler 发生 overflow 时会跳过 optimizer step。日志中的 step 数若仍推进 scheduler，实际学习率轨迹与更新次数错位。记录 skipped step、已处理 pair 和 token，以真实更新计数解释训练预算。

中断恢复要保存模型、optimizer、scheduler、scaler、随机状态、sampler epoch、dataloader cursor 和数据 manifest。只恢复模型并从 epoch 开头读，会重复一段数据；ORPO 同时含 SFT 与偏好信号，重复高密度 prompt 可能明显改变行为。

改变 world size 后，浮点归约顺序和 batch 组成变化，逐 bit 复现通常不可行。仍应保持全局有效 pair batch、按处理 pair 推进 scheduler，并在固定审计样本上比较损失与梯度统计。扩容实验报告实际 pair、response token 和 wall-clock。

parameter-efficient 训练用 adapter 节省状态，却改变可更新空间。低 rank 可能只能调整风格，难以同时提高 chosen 与压低多类 rejected。比较不同 rank 的训练 loss、未见 pair 与自由生成，区分容量限制和优化问题。

训练后量化或模型合并会改变 logits，边界 pair 的排序可能翻转，高置信区 odds 也可能显著变化。发布产物必须重新跑固定 pair、生成和安全评估，不能沿用量化前指标。

## 19. 可证伪的消融矩阵

若主张 ORPO 的收益来自 odds 变换，至少比较相同 SFT 项下的 log-prob margin、odds margin 与其他单调变换，并对齐训练 divergence。只与两阶段 DPO 比较，会同时混入 reference、训练阶段和正向模仿差异。

若主张单阶段更省成本，报告端到端资源：SFT 与偏好训练、reference 前向或缓存、候选生成与标注。已有 SFT checkpoint 和从头训练是两种决策场景，应分别计算。

若主张长度归一化缓解长度偏差，使用长度反转反事实与多语言切片。只看平均输出长度下降无法证明偏好更准确；模型也可能塌缩为短模板。

若主张高置信放大改善 hard pair，按初始 $s_w,s_l$ 分桶，展示梯度权重、排序和生成收益。边界固定在训练前，避免样本随 checkpoint 迁移造成组成变化。

若主张对噪声稳健，人为注入均匀翻转、系统性偏差和高置信错标。三种噪声机制不同：均匀翻转检验一般标签噪声，系统偏差模拟错误 rubric，高置信错标专门攻击 odds 敏感区。只测第一种结论过弱。

若主张不需要 reference 也能控制漂移，必须展示相对初始模型的 KL、能力回归与多 epoch 轨迹。短训练中自然接近起点，不等于目标具有显式约束。

若主张优于 SFT，确保 SFT 基线看到相同 chosen token 数，并调好学习率与 epoch。ORPO 额外看到 rejected 信息，数据预算也应明确。若 SFT 基线只跑默认配置，比较缺乏说服力。

若主张生成改善来自内容而非 judge 风格，加入可执行任务、独立人评、位置交换与模板反事实。训练 judge 与评估 judge 相同的结果只能说明同源一致性。

每项消融都应预先写主要指标、失败判据和停止规则。看到结果后挑最有利 checkpoint 或切片，会把验证集变成训练反馈。探索性发现可以保留，但要与预注册结论分开。

## 20. 从实验记录到最终结论

一份可复算记录先固定数据对象。每条 pair 保存 prompt ID、完整条件上下文、chosen/rejected 原文、原始展示顺序、候选生成器、解码参数、标注者或 judge 版本、投票、tie、轮次和来源。预处理再保存 token ids、response mask、自然结束或截断状态、有效长度与模板版本。只有文本而没有这些字段，无法重建训练使用的概率事件。

模型对象包括起点 checkpoint、tokenizer、chat template、adapter、精度、并行策略和代码版本。ORPO 没有训练 reference，仍应保存起点，用于验证漂移。若词表扩展或 special token 改动，embedding 初始化也要记录；它会影响对话边界的概率。

训练对象包含 SFT 与 OR 两项公式、$\lambda$、sum/mean、EOS 规则、pair/group 权重、optimizer、学习率、scheduler、batch、累积、clip、epoch、随机种子和停止规则。参数名相同而口径不同的实验不可直接比较，尤其是回答分数 $P_\theta$ 的定义。

固定审计集应覆盖短长回答、自然 EOS、截断、多语言、代码、公式、左右 padding、近零 $s$、很负 $s$、chosen/rejected 近似和明显错排。为每条保存逐 token log-prob与预期聚合，框架升级后先通过这组测试，再启动大规模训练。

训练曲线至少同时显示 $s_w,s_l,\Delta,L_{SFT},L_{OR}$ 与总 loss 的分位数。只看总 loss 时，一项改善可能掩盖另一项恶化。加入两项梯度范数与余弦，可以观察优化阶段：早期 SFT 主导、偏好逐渐起效，或者 odds 在高置信区突然主导。

异常样本的诊断顺序应固定。先核对文本与标签，再核对共享 prompt、token 与 mask，随后看长度口径、$s$、log-odds 和梯度，最终才调整优化器。若一见震荡就降学习率，数据故障仍留在训练集，只是破坏速度变慢。

自由生成评估与固定 pair 评估使用不同表格。固定 pair 报告排序、$\Delta$、chosen/rejected 分数和分桶结果；自由生成报告任务成功、独立偏好、长度、拒答、重复、多样性与风险。两者相关但无法互相代替。

生成比较最好使用配对 prompt。基线与 ORPO 在同一请求、同一预算下生成，展示顺序随机，tie 保留。以 prompt 为 bootstrap 单位计算区间；同一 prompt 多次采样属于簇内相关，不按独立样本夸大精度。

若 prompt 又来自同一用户、文档或模板，可以提高聚类层级。十万条由少数模板扩写的 pair，有效样本量远小于十万。报告 prompt 数、语义簇数、来源数和权重有效样本量，比只报行数诚实。

多切片结果要避免选择性汇报。预先确定总体、代码、数学、安全、多语言和长度等关键切片，其余作为探索。某个切片退化时展示具体案例和区间，不能用总体平均遮盖。高风险任务还应设硬门槛，而非参与普通加权。

事实会变化的任务按时间切分。训练前的信息与之后更新的事实分开，避免把知识过期误作偏好学习失败。标注指南也有版本；若 rubric 改变，用固定 anchor pair 测量尺度漂移。

线上反馈不能直接当无偏 winner。用户是否点击、停留或投诉受到位置、延迟、任务难度和个人习惯影响。记录曝光与界面条件，保留随机抽样人评。否则 ORPO 可能学会提高互动率，而非回答质量。

迭代回流时，当前模型很少生成的模式逐渐消失，评价器喜欢的模板反复出现。混合旧模型、其他生成器与随机探索候选，并监控语义簇覆盖。多样性骤降时，即使 judge 胜率上升，也要排查模式收缩。

工具任务需要单独定义 action mask。模型生成的工具名、参数与后续助手回复属于策略动作，搜索结果、代码输出和环境报错属于观察。把环境文本计入回答平均 log probability，会给模型无法控制的 token 分配梯度。

两个工具轨迹若收到不同观察，就不再是完全相同条件下的静态 pair。终局 winner 可以训练整条策略轨迹，但序列级信号无法指出关键决策。若能在共享状态下比较下一步动作，局部 pair 的信用更清楚；若不能，应把轨迹环境和随机种子完整保存，并限制因果解释。

长轨迹的 mean 口径还会把多个决策摊到 token 平均。简短错误调用与长篇最终回复混在一起时，关键动作信号很弱。按决策步聚合或增加步骤监督可以改善，但已经改变原始 ORPO 定义，需要独立公式与消融。

安全数据要区分恶意请求、良性敏感请求、边界请求和普通问题。若 chosen 总是简短拒答，SFT 与 odds 两项都会强化拒答模板，正常帮助能力容易退化。保持主题相近、只改变意图或权限的反事实，可以检验模型是否依据风险条件决策。

拒答也受长度归一化影响。短而高频的固定句式往往平均概率高，odds 进一步放大。按风险类别统计拒答率、帮助性和 $s_w$，识别模型是否通过统一拒答获得离线优势。安全硬门槛与过度拒答指标应同时存在。

事实、代码和数学任务优先采用硬验证。测试通过之前，语言偏好不应把错误回答选为最终 winner。对多个正确方案，再使用风格、效率和解释清晰度排序。这样能避免 ORPO 的 SFT 项模仿“相对较好但仍错误”的答案。

答案内部包含正确与错误片段时，序列级训练会整体上推或下压。数据编辑可以制作最小差异 pair，减少无关内容；仍要记住自回归条件变化会影响后续所有 token。逐 token 梯度图是诊断工具，不是严格因果归因。

模型置信度校准也值得单独观察。ORPO 提高 chosen token 概率、压低 rejected，可能让输出分布更尖。评估预测熵、多个采样的一致性和事实置信，检查模型是否变得过度确定。语言模型 token 概率并不直接等于答案正确率，需要在可验证任务上建立校准曲线。

较尖的分布可能提高低温生成稳定性，却降低探索与多样性。分别在 greedy、常用温度和较高温度评估。若收益只存在于某个解码设置，部署配置必须绑定该 checkpoint，结论也限定在该范围。

参数更新还可能造成灾难性遗忘。通用语料 perplexity只能给粗略信号，任务能力集更直接。以起点模型为基准，追踪知识、推理、代码、多语言和安全；某项跌破门槛就停止或回滚。偏好胜率不能抵消关键能力丢失。

加入少量预训练或 SFT replay 可以缓解遗忘，却再次改变目标与计算预算。报告 replay 数据量、来源和梯度贡献，并与单纯缩短训练对照。否则收益可能来自额外正向数据，而非 ORPO 本身。

早停 checkpoint 的选择会产生验证过拟合。频繁查看同一生成集并挑最高点，相当于把它用于训练决策。保留开发集选择 checkpoint，再用一次性测试集给最终结果；重要结论用多套来源复核。

统计显著与实际重要性要分开。胜率提升不足一个百分点，在大样本上可能显著，用户却难以感知；少量严重安全事件下降，样本少但价值很高。报告效应量、区间、成本和失败严重度，不只给 p 值。

失败实验同样提供边界。若小 $\lambda$ 没有偏好收益，大 $\lambda$ 又导致短模板或能力回退，说明当前数据与起点没有宽阔可用区间。若 odds 变换在高置信错标上不稳，稳健 loss 或更严格数据筛选可能更合适。结论应写清设置，而非把负结果藏掉。

ORPO 的核心贡献可以准确概括为：使用 chosen 的监督微调项维持正向学习，再用 chosen/rejected 的长度归一化 odds ratio 提供偏好压力，从而在一个训练阶段完成模仿与排序。它省去显式 reference 前向，却没有省去对初始化、数据分布和漂移的控制。

这个目标最值得理解的地方是梯度几何。logsigmoid 随正确排序饱和，odds 对高置信概率又会放大，SFT 则持续上推 chosen。三股作用随训练状态变化，任何固定的“更稳定”或“更激进”评价都过于粗糙。把实际 $s$ 分布代入解析梯度，才知道当前 batch 发生了什么。

概率语义最容易混淆。几何平均 token 概率与完整回答概率含义不同，对它取 odds 得到的也只是长度归一化训练坐标。人类选择赔率需要由选择数据估计。实验可以检验该坐标是否有效，解释范围则由公式限定。

选择 ORPO 时，适合的条件包括高质量 chosen/rejected、希望统一 SFT 与偏好阶段、能够细致监控置信区与长度，并愿意通过独立评估控制漂移。若数据噪声大、绝对质量门槛缺失或需要明确 reference trust region，应优先补数据与约束，而非寄望一个 loss 自动解决。

验收链包含这些环节：原始 pair 共享条件，token 与 mask 可复算，平均 log probability口径一致，log1mexp 数值稳定，SFT/OR 梯度方向正确，batch 权重符合目标，固定 pair 改善能在自由生成中复现，关键能力与安全没有回退。任一环断裂，总 loss 都不足以支持上线。

还有几组不变量适合在每次改实现后自动运行。第一组检查数据顺序：交换 batch 内 pair 顺序，总 loss 与梯度不变；交换某条 pair 的 chosen/rejected，偏好差反号，SFT 正例也随之切换。第二组检查 padding：增加任意数量的 pad token，只要 attention、position 与 response mask 正确，四项回答分数不变。第三组检查复制：复制全部 pair 后 mean loss 不变，按 prompt 等权时复制某个 prompt 内全部边也不变。

第四组检查数值分段。对 $s=-\log2$ 左右取非常接近的点，`log1mexp` 的函数值与自动微分应连续；对 $s=-10^{-6}$，结果有限且与高精度基准一致；对 $s=-30$，不能因 `exp(s)` 下溢产生错误符号。第五组检查极限：$s_w=s_l$ 时 $\Delta=0$，偏好 loss 为 $\log2$；$s_w$ 提高时 loss 单调下降，$s_l$ 提高时 loss 单调上升。

第六组检查 mask 语义。prompt token、padding 与环境观察的梯度为零，response token 有梯度；自然 EOS 有梯度，截断样本不存在伪造 EOS。多轮数据中，选择末轮目标时早期 assistant token 也应被 mask；选择整条助手轨迹时它们才进入目标。测试样本要故意让各区域 token 不同，避免重复值掩盖错位。

第七组检查分布式等价。同一全局 batch 用单卡、两卡和不同 microbatch 切分，一步更新的 loss 与梯度在容差内一致。pair 数不整除 worker 时仍按全局 count 归约。动态 batch 下，scheduler 以真实 optimizer update 或已处理 pair 推进，不能由本地 step 偶然改变。

第八组检查恢复。连续训练两步与训练一步、保存、恢复再训练一步的样本 ID、学习率、loss 和参数更新一致。若使用 dropout与 activation checkpointing，还要恢复随机状态。数据 shuffle、sampler epoch 和 cursor 缺一项，第二步就可能读到不同 pair。

这些测试覆盖的是实现一致性，不判断数据标签是否合理。数据验收需要另一组抽查：随机样本、最高 loss、最高 chosen 概率、两侧最相似、长度差最大、截断与多语言。每组查看原始上下文、候选、标签理由和 token 边界。只抽随机样本容易漏掉影响最大的尾部。

相似 pair 尤其值得看。chosen 与 rejected 只有标点、礼貌词或格式差异时，偏好可能真实存在，也可能是随机抖动。高置信模型对两项都给高分，odds 导数会放大这类标签。保存重复投票、设置最低语义差异并人工复核，比统一删除相似项稳妥，因为细粒度编辑有时正是最有价值的监督。

长度差最大的 pair 则检查另一个方向。几何平均虽消除直接累加，长回答包含的罕见 token、公式和引用仍会降低平均概率。若 chosen 长回答系统性得分低，模型可能把“易预测”当“高质量”；若短回答系统性得分高，可能形成简短模板。用内容匹配反事实确认后，再考虑数据平衡或目标修改。

对引用与事实密集回答，还要区分模型概率和真实性。流畅的伪引用可能平均概率很高，ORPO 会在 chosen 标签错误时强力模仿。数据收集阶段验证 DOI、链接、数值和日期，效果远胜训练后用 loss 猜测。偏好方法不能从一对未经核实的文本中创造事实依据。

不同语言的标注规则应保持语义一致。直接翻译英文 pair 可能改变礼貌、简洁和自然度，原 winner 在目标语言中未必仍胜。机器翻译数据需保留原文对应并抽查偏好翻转；本地语言原生候选更能反映实际分布。评估按语言切片，避免高资源语言掩盖退化。

代码回答还存在格式与执行的分离。Markdown 完整、解释清晰的代码可能无法运行；通过全部测试的简短实现可能在语言 judge 中不占优。先用编译、测试、复杂度和安全规则确定合格集合，再在其中用偏好排序。测试失败的答案不能因相对更流畅成为 SFT chosen。

数学回答也类似。最终数值正确可能来自猜测，长推导可能在中间偷换条件。验证器能检查最终答案，人工或形式工具再检查关键等式。构造 pair 时标注错误位置，虽然原始 ORPO 不使用步骤标签，却能帮助失败分析和后续数据修复。

当 chosen 含有模型不应模仿的私人信息、危险操作或受版权约束的长文本时，相对标签无法替代数据治理。训练前过滤敏感内容，记录来源许可和删除请求链路。模型更新一旦吸收文本，事后仅删除数据文件不等于完成遗忘。

模型发布后的监控也应对齐训练切片。若训练按语言、任务、长度和风险分桶，线上日志沿用同一 schema，才能发现分布漂移。新出现的任务先进入观察与人工标注，不立即用隐式反馈回流。早期数据量小时，波动区间很大，自动训练容易追逐噪声。

回流数据的候选生成要保留探索。只比较当前 greedy 输出与一个固定基线，候选空间会越来越窄；混入不同温度、旧 checkpoint 和外部模型，能发现当前策略概率低但质量高的回答。探索比例也属于成本与风险参数，需在安全边界内设置。

若评价器参与候选筛选，应保留一股未经筛选的随机流，用来估计 false negative。否则训练和验证都只看到评价器允许的区域，模型可能在过滤区外产生严重问题而不被发现。同源 judge 的高胜率尤其需要这种对照。

模型间比较还要固定 stop sequence。某模型更早输出 stop，会改变长度、平均 log probability与用户感受；若评估端又截断不同，算法差异混入服务配置。训练模板、离线评分与线上生成使用同一结束语义，版本变更后重新评估。

推理服务的量化、缓存和 speculative decoding通常不改变目标语义，却可能改变边界 token 或采样结果。发布前在真实服务栈复跑关键集，并与离线模型对照 logits 或输出。训练环境全绿不代表部署序列完全一致。

若多个 adapter 按用户切换，每个 adapter 都需要自己的 ORPO 评估。共享 base 更新会让旧 adapter 的行为漂移；固定 base 只训练新 adapter则隔离更好，但路由错误仍会把用户送到不合适的偏好。路由规则与 adapter 版本一起纳入发布 manifest。

最终决策可以采用分层门槛。第一层是数据与数值不变量，任一失败就不进入大训练；第二层是离线 fixed-pair 与通用能力，筛掉明显故障；第三层是独立生成、可执行任务和安全；第四层才是成本、延迟与用户偏好。分层能避免用后面的漂亮指标掩盖前面的基础错误。

ORPO 并不要求每个项目都完成同样规模的评估，小实验也可以保持逻辑完整：一组手算样本、一个固定验证集、一组未见 prompt、一个起点漂移指标和若干关键失败案例。规模扩大时增加覆盖与统计精度，证据链本身不应省略。

理解到这一层，单阶段的意义也更清楚。它把正向模仿与相对偏好放进同一次更新，让二者直接在共享参数中折中；流程少了一段，目标之间的耦合反而更需要观察。$\lambda$、数据比例和置信分布共同决定折中，任何一个默认值都不能代替本地验证。

若实验最终显示 ORPO 与精心调好的 SFT 相当，也不是无效结果。它说明当前 rejected 信息没有提供可迁移增益，可能因 pair 太容易、标签噪声或 chosen 已覆盖主要信号。查看分桶与梯度，能够决定下一步是改候选、补 hard pair，还是停止增加复杂度。

若 ORPO 明显胜过 SFT，却不胜过 DPO，结论可能是偏好数据有效，显式 reference 在该场景更适合；若胜过 DPO 但计算优势不明显，收益可能来自 chosen SFT 或长度归一化，需要进一步消融。把“方法赢了”拆回可检验机制，才能迁移到下一个模型。

若所有方法都随基座翻转，优先研究初始置信、格式能力和数据覆盖。ORPO 对高置信区的特殊敏感性使这种翻转更可能出现。按初始 $s$ 分桶、固定边界并比较梯度，可以把经验现象连接到公式，而不是给算法贴永久排名。

同一结论还要在不同随机种子上复核。若均值提升主要由一次幸运运行贡献，应继续检查数据顺序、异常 pair 和 checkpoint 选择；稳定的小幅收益通常比不可复现的高峰更适合作为训练配方。

还有一种值得单列的情况：chosen 与 rejected 在答案层面差别很大，却共享同一处关键事实错误。偏好标签可能依据文风选出 winner，SFT 项随后强化这个错误。相对比较前先做事实门槛，能够把“哪篇写得好”和“哪篇说得对”分开。无法自动验证的开放问题，可以要求标注者明确列出选择理由，再对理由做抽检。

理由文本不必直接进入训练，也能服务数据审计。若某批标注理由几乎全是“更详细”，而业务目标包含简洁性，说明 rubric 或候选分布失衡；若理由集中在格式，模型可能通过表面特征取胜。按理由类别观察 ORPO 收益，能够判断模型学到了内容还是捷径。

训练后的概率变化也可以按理由回看。事实类 pair 的 $\Delta$ 提高，却没有带来可验证正确率，说明离线排序未迁移；格式类 pair 的提高伴随 IFEval 改善，则机制更一致。对每类都要求外部指标，避免用同一套 pair 同时训练和证明成功。

模型面对未见但等价的表达时，应保持偏好方向。把变量名、句式、语言或代码风格改变，同时保留语义，构造等价变换集。若原句排序正确、改写后翻转，模型可能记住表面模式。等价集按原 prompt 分组评估，防止改写跨入训练集造成泄漏。

反方向的最小扰动也重要：只改一个数值、否定词、权限条件或工具参数，使答案从正确变错误。模型若仍偏好格式更漂亮的旧模板，说明偏好信号没有抓住决定性内容。等价变换与最小反例一起，分别测稳定性和敏感性。

这些测试让“生成更符合偏好”变成可以拆解的命题：面对不影响质量的变化，排序应稳定；面对影响关键事实的变化，排序应改变；自由生成时，这种判断还应转化为更高任务成功率。三步缺一，胜率数字都可能由数据表面相关性解释。

ORPO 能走多远，取决于概率坐标、数据判断和部署行为能否接起来。训练目标给出明确梯度，数据决定梯度方向，评估确认这条方向是否抵达真实任务。三层逐项核对后，单阶段优化才能在缩短流程的同时保留完整证据链。
