# PPO-based RLHF 训练流水线

RLHF 把人的判断变成模型能够反复优化的训练信号. 经典流水线包含三个阶段: 先用示范回答做 supervised fine-tuning, 再用同一 prompt 下的回答比较训练 reward model, 最后让当前 policy 生成新回答, 通过 PPO 提高预测奖励, 同时用 reference policy KL 限制行为漂移.

三个阶段解决不同问题. SFT 决定模型最初会怎样回应指令; preference data 与 reward model 把有限的人类排序扩展为可批量计算的标量; online RL 让 policy 在自身分布上搜索更高奖励的回答. 难点来自最后一个闭环: policy 一旦更新, rollout 分布就变化, reward model 开始评价训练数据中少见的新行为, 模型也有机会寻找评分器的漏洞.

## 1. SFT 决定 RL 从哪里开始

令 prompt 为 $x$, completion 为 $y=(y_1,\ldots,y_T)$. 自回归策略分解为

$$
\pi_\theta(y\mid x)=
\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}).
$$

预训练模型会续写文本, SFT 用高质量指令与回答样本把条件分布移到对话任务附近. 这一步同时建立聊天模板, 停止行为, 风格和基本任务格式, 也为 reward model 与 PPO 提供一个可用的探索起点.

### 1.1 Completion-only 交叉熵

对示范样本 $(x,y^*)$, 常用损失为

$$
\mathcal L_{SFT}(\theta)=
-\sum_{t=1}^{T}m_t
\log\pi_\theta(y_t^*\mid x,y_{<t}^*).
$$

$m_t\in\{0,1\}$ 是 loss mask. 系统消息与用户 prompt 参与上下文条件, 通常不承担 assistant completion 的预测损失. Padding 位置必须为 0, EOS 是否计入取决于模板和训练目标, 但必须与生成停止规则一致. 若把 prompt token 加入 loss, 优化目标会额外建模 system/user 文本并改变各角色权重, 还会稀释 assistant completion 的监督预算; 若 EOS 被全部遮掉, 生成长度可能失控.

多轮对话还要决定哪些 assistant turn 进入 loss. 只训练最后一轮, 每条样本提供的监督较少; 训练全部 assistant turn, 则要确保此前回答确实来自目标分布且格式正确. 这个选择会改变每个 token 的权重, 应随数据版本保存, 不能只记录原始对话 JSON.

### 1.2 数据质量与策略支持

SFT 数据既提供目标行为, 也塑造初始策略的高概率区域与有效支持. Softmax LM 对多数 token sequence 仍有非零数学概率, 但概率质量极低的行为在有限 rollout 中几乎采不到. 若某类推理, 拒答或工具调用从未出现, PPO 需要靠随机探索发现它, 成本会很高. 若示范中含有系统性事实错误, reward model 后续又偏爱流畅表达, RL 可能把错误进一步放大.

去重与来源平衡也会改变结果. 同一模板的大量近重复回答会让模型把固定措辞当成指令遵循. 长回答数量偏多会改变长度先验. 数据验收应按任务, 来源, 语言, 长度和拒答类型切片, 并保留从训练 token 回到原始样本的 id.

### 1.3 SFT checkpoint 的三种职责

完成 SFT 后, checkpoint 通常至少承担三种逻辑职责. 第一份初始化 trainable policy. 第二份冻结为 reference policy, 在 RL 中定义行为锚点. 第三份可以作为产生 preference candidates 的初始策略. 它们开始时参数相同, 版本生命周期却不同.

训练中还会产生 old policy, 即生成当前 rollout batch 的 policy 快照. `old` 与 `reference` 不能混用. Old policy 只用于 PPO probability ratio, 每批更新; reference policy 用于长期 KL, 通常跨许多 batch 固定. 若 ratio 分母误用 reference, 多 epoch 数据复用和策略漂移会被混成同一个量.

### 1.4 SFT 混合比例与能力保留

Instruction data 通常远小于预训练语料. 若 SFT 只覆盖狭窄任务, 多轮训练可能改善对话格式, 同时削弱补全, 多语言或专业领域能力. 团队可以混入部分预训练样本, 使用较小学习率, 限制 epoch, 或按领域验证来控制这种分布迁移. 每种办法都会改变模型到底在优化什么.

混入预训练数据时, 两类 loss 的 token 数不能直接相加后假设权重合理. 一条长网页和一条短对话贡献的 token 数相差很大. 可以按 token 混合, 按 sequence 混合, 或先分别求均值再加权. 三种方法对长短样本和不同域的权重不同, 配方应明确到公式与 sampler.

SFT 结束后的评估也不能只看 instruction benchmark. 需要保留预训练能力, 目标任务, 长度分布, 拒答率与模板鲁棒性等切片. 这些指标构成 RL 起点的账本. 后面 policy 发生变化时, 才能判断退化来自 SFT, reward model 还是 PPO.

## 2. 偏好数据把人的判断变成比较

Preference collection 对同一个 prompt 展示多个候选回答, 要求标注者按 rubric 选择更好的一个或给出排序. 比较比绝对打分容易校准: 标注者不必回答"这个回答值 7.3 分", 只需判断两个具体回答谁更符合帮助性, 正确性, 安全性和风格要求.

比较仍然带有主观性. 两位标注者可能对简洁与完整, 拒答与帮助, 风险与可用性作出不同取舍. 这些分歧不是单纯噪声, 它们揭示了最终单标量 reward 将压缩哪些价值冲突.

### 2.1 候选怎样产生

候选可以来自同一 policy 的不同温度或随机种子, 也可以来自多个 checkpoint 与基线模型. 只比较一个很强和一个明显很差的回答, reward model 容易学到粗糙特征, 却难以区分 policy 训练后遇到的近邻回答. 因此候选难度需要覆盖当前决策边界.

采样元数据应包括 policy version, decoding temperature, top-p, max tokens, stop reason 和模板版本. 长度上限造成的截断回答若与自然 EOS 混在一起, 标注者可能把不完整性学成内容偏好. 同一回答在不同模板下的边界也可能变化.

### 2.2 Pair, ranking 与切分单位

一组 $K$ 个候选可产生最多 $K(K-1)/2$ 个 pair. 这些 pair 共享 prompt 与回答, 统计上高度相关. 若把 pair 随机分到训练集和验证集, 同一个回答可能同时出现在两侧, reward model validation 会虚高.

正确切分单位通常是 prompt 或完整 candidate group. 训练时还要控制每组权重. 一个有 8 个候选的 prompt 能产生 28 个 pair, 若逐 pair 等权, 它会比只有 2 个候选的 prompt 获得 28 倍影响. 可以按 group 归一化, 抽样部分 pair, 或直接使用 listwise objective.

### 2.3 标注一致性与 rubric

Rubric 需要把事实正确, 指令遵循, 帮助性, 安全性和表达质量写成可操作条件. 如果标注者只看到"选更好", 每个人会自行设定权重, reward model 学到的是混合且随批次漂移的隐含标准.

可以用重复标注估计一致性, 对争议样本保留 tie 或软标签, 并分析分歧集中在哪些任务. 强行把 tie 转成随机 winner 会制造不存在的确定性. 若项目确实需要多个价值维度, 保存分项标签比事后从单一 reward 反推更可靠.

### 2.4 主动采样把标注用在决策边界

随机抽取候选 pair 简单, 却会产生大量一眼可判的比较. 当 winner probability 已接近 0 或 1, 新标签对 reward model 决策边界提供的信息有限. 可以优先采样 RM 分差接近 0, 多个 RM 意见不一致, 或当前 policy 与 reference 差异较大的回答, 把标注预算集中到难例.

主动采样会改变训练数据分布. 如果只收集最不确定样本, RM 看到的 easy case 减少, 原始 prompt 分布也可能被高风险域占据. 训练时可混合随机样本与主动样本, 保存采样概率, 并在独立自然分布验证集上评估. 否则 validation 也跟着主动分布移动, 很难判断整体质量.

Policy 迭代后, 旧的难例可能变成常见模式, 新漏洞又会出现. 因而 candidate generation 与 annotation 是持续过程. 每批 preference data 都应关联 producer policy version, RM version 和选择规则. 这条血缘能回答一个关键问题: RM 的高分区域究竟被多少真实人类比较覆盖.

## 3. Bradley-Terry 奖励模型

Reward model 接收 $(x,y)$ 并输出标量 $r_\phi(x,y)$. Bradley-Terry 假设回答 $y_w$ 胜过 $y_l$ 的概率只由分数差决定:

$$
P_\phi(y_w\succ y_l\mid x)=
\sigma(r_\phi(x,y_w)-r_\phi(x,y_l)).
$$

模型通常从 SFT 或预训练 checkpoint 初始化, 在最后 token 或专用位置读取 sequence representation, 再映射为标量. 单个 $r_\phi(x,y)$ 是 latent score; 成对分差 $r_w-r_l$ 才是 sigmoid 使用的 pairwise logit. 这些分数并不是经过物理标定的人类效用单位.

### 3.1 Pairwise loss 与梯度

令 $r_w=r_\phi(x,y_w)$, $r_l=r_\phi(x,y_l)$, $\Delta=r_w-r_l$. 负对数似然为

$$
\mathcal L_{RM}=-\log\sigma(\Delta).
$$

利用 $d[-\log\sigma(z)]/dz=\sigma(z)-1$, 得到

$$
\frac{\partial\mathcal L}{\partial r_w}=\sigma(\Delta)-1,
\qquad
\frac{\partial\mathcal L}{\partial r_l}=1-\sigma(\Delta).
$$

若 $r_w=0.2,r_l=-0.1$, 则 $\Delta=0.3$, $\sigma(0.3)\approx0.574$. 梯度下降让 winner 分数增加约 $0.426\eta$, loser 分数下降约 $0.426\eta$, 其中 $\eta$ 是对两个标量直接优化时的学习率. 差值变大, winner probability 随之上升.

### 3.2 Identifiability 的边界

损失只依赖 $r_w-r_l$. 对任意与 prompt 有关的常数 $c(x)$,

$$
(r_w+c(x))-(r_l+c(x))=r_w-r_l.
$$

因此 reward 的绝对零点不可识别. 训练集上的所有分数同时加 10, pairwise probability 完全不变. 单独查看平均 reward 没有固定语义, 除非给出版本, 数据和校准方式.

尺度也受数据可分性与正则化影响. 将所有分差乘得更大, 对已正确排序且近乎可分的数据会继续降低 logistic loss. Weight decay, early stopping, label smoothing 或显式温度共同决定输出尺度. 换一个 RM checkpoint 后, PPO 的 $\beta$, advantage 标准化和 reward clipping 都可能需要重新校准.

### 3.3 验证 reward model

Pair accuracy 只测 winner 是否得分更高, 对 margin 和校准不敏感. 应同时查看 log loss, 不同任务与长度分桶, 标注分歧组, 以及 policy 新分布上的表现. 若 validation 与训练 candidates 来自同一批模型和模板, 高准确率也不能证明 RM 能评价 PPO 后产生的新行为.

长度偏置是一个常见检查项. 若 chosen 系统性更长, RM 可能学到"更长更好". 可以构造内容近似但长度不同的对照, 在相同长度桶内报告 accuracy, 并检查分数对 token 数的回归斜率. 直接把长度从输入删除不可行, 关键是让偏好数据包含足够反例.

### 3.4 不确定性与 RM ensemble

单个 RM 给出的 5.0 看起来很确定, 但标量本身不包含认识不确定性. 可以训练多个不同初始化, 数据 bootstrap 或架构的 reward models, 比较同一回答的分数方差. Ensemble 均值用作 reward, 方差可作为分布外警报或主动标注依据.

例如三个 RM 对回答 A 打分 $(1.2,1.1,1.3)$, 对回答 B 打分 $(2.0,-0.5,1.8)$. B 的平均分 1.1 与 A 的 1.2 接近, 模型间分歧却大得多. 直接按均值排序会忽略 B 可能位于训练覆盖之外. 可以对高方差样本降低优化权重, 请求人类复核, 或限制 policy 在该区域继续更新.

Ensemble 也会共同继承数据偏差. 所有成员在相同长度偏置数据上训练, 一致高分不代表判断正确. 不确定性诊断只能揭示部分 epistemic uncertainty, 不能替代独立人类评估和有针对性的反事实测试.

## 4. 从 sequence reward 到 token 回报

Policy 生成整个回答后, RM 通常给出一个 sequence-level 标量. PPO 的动作却是逐 token 采样, critic 也在每个 prefix 状态估值. 流水线必须把终局分数, reference KL 和任何规则奖励组合成 token reward, 再用 GAE 分配到各位置.

这一转换最容易出现边界错误. Reward 加在哪个 token, EOS 是否有效, padding 是否泄漏, 长度截断是否 bootstrap, 都会改变整条回答的 advantage. 这些不是实现细节, 而是训练目标的一部分.

### 4.1 Reference-policy KL 目标

一个常见序列目标是

$$
J(\theta)=
\mathbb E_{x\sim D,y\sim\pi_\theta}
\left[R_\phi(x,y)-
\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}\right].
$$

因为自回归概率是 token 条件概率的乘积,

$$
\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}
=\sum_{t=1}^{T}
\left(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{ref}(y_t\mid s_t)\right).
$$

对当前 policy 样本取期望时, 这个 log-ratio 估计 $D_{KL}(\pi_\theta\Vert\pi_{ref})$. KL 惩罚使 policy 为离开 SFT 行为付出代价, 限制它进入 RM 缺少覆盖的区域. $\beta$ 控制 reward improvement 与行为漂移的交换率, 不是普适常数.

### 4.2 Token shaping 与可复算例子

理论目标里的 log-ratio 随当前策略 $\pi_\theta$ 变化. 但标准 PPO 实现先由 rollout policy $\pi_v$ 生成 batch, 再固定 $k_t^{v}=\ell_t^{v}-\ell_t^{ref}$ 构造这一批的 token reward、advantage 和 return. 可以令每个位置 reward 为

$$
r_t^{token}=-\beta k_t^{v},
$$

并在最后一个有效 completion token 上加 sequence reward $R_\phi(x,y)$. 假设三 token 回答的 $k=(0.1,0.2,-0.1)$, $\beta=0.05$, RM 分数为 1.2. Token reward 为

$$
(-0.005,-0.010,0.005+1.2)
=(-0.005,-0.010,1.205).
$$

总和是 1.19, 等于 $02-0.05\times(0.1+0.2-0.1)$. 这项手算可以检查 KL 符号, token mask 和终局奖励位置. 若 padding 上 log-ratio 被设成极大值, 总 reward 仍应不变.

Sampled log-ratio $k=\log\pi_v-\log\pi_{ref}$ 可能逐 token 为负, 虽然其在 $\pi_v$ 下的期望是 $D_{KL}(\pi_v\Vert\pi_{ref})\ge0$. 对同一方向的非负样本近似可以写成 $e^{-k}-1+k$; 若另定义 $\Delta=\log\pi_{ref}-\log\pi_v=-k$, 等价形式才是 $e^{\Delta}-1-\Delta$. 有些系统计算全词表 KL. 若在每个 PPO epoch 用当前 $\pi_\theta$ 重算 reference KL, 它就成为显式 current-reference regularizer, 不再是本批冻结的 reward shaping. 这些口径的数值尺度与梯度性质不同, 不能共用同一 $\beta$ 后直接比较.

### 4.3 Sequence reward 的 credit assignment

终局 RM 分数没有告诉系统哪个 token 造成偏好. Critic 学习前缀的期望回报, GAE 再把后续 TD residual 传播到此前动作. 对状态 $s_t=(x,y_{<t})$, 令 $d_t$ 表示 bootstrap-stop mask: 真正 termination 必为 1; length truncation 若任务把它视作终局也取 1, 若理论过程仍可继续并保留有效 final state 则取 0. $b_t=1$ 表示这一位置后发生 termination、length truncation 或 batch 中的 sequence boundary. $V_{old}$ 是 rollout 时冻结的 value, $\gamma$ 是回报折扣, $\lambda$ 是 GAE trace 系数:

$$
\delta_t=r_t+\gamma(1-d_t)V_{old}(s_{t+1})-V_{old}(s_t),
$$

$$
\hat A_t=\delta_t+\gamma\lambda(1-b_t)\hat A_{t+1}.
$$

Termination 令 bootstrap 与 trace 都停止; length truncation 是否允许 value bootstrap 取决于任务语义, 但 trace 必须在回答边界停止, 不能把下一条回答的 advantage 传回来.

若 $\gamma=1,\lambda=0.8$, reward 为 $(0,0,1)$, value 为 $(0.2,0.4,0.5)$, 终止后 value 为 0, 则 residual 是 $(0.2,0.1,0.5)$, advantage 是 $(0.6,0.5,0.5)$. 前两个 token 获得正信号, 因为它们位于通向高终局 reward 的轨迹上.

这仍是粗粒度信用分配. 一条回答包含事实, 推理和风格多个因素, 单个标量会把它们一起广播给整段 token. Process reward 或可验证中间结果能提供更局部信号, 但需要新的数据与正确性假设. Sequence RM 的限制不应被 GAE 的数学形式掩盖.

### 4.4 Reward 尺度, whitening 与长度

固定 sigmoid link 与 temperature 时, RM 的加性零点严格不可识别, 乘法缩放却会改变 pairwise probability. 不过输出尺度仍会被 label noise、temperature、正则、early stopping 和数据可分性强烈影响, 因而不同 checkpoint 的数值不能直接横比. PPO 又会直接使用 reward 数值. 常见做法是在冻结 policy 生成的校准集上估计均值与标准差, 把 RM 输出变换为近似零均值单位方差. 这个变换必须绑定 RM version 和校准分布. Policy 更新后重新用当前样本归一化, 会让目标随 policy 分布移动, 训练 reward 的跨步比较也失去意义.

Advantage whitening 又是另一层变换. Reward normalization 改变 return 与 critic target; advantage whitening 只在 policy update 前重新缩放优势. 两者同时使用时, value loss, entropy 和 KL 系数的相对尺度都会变化. 报告"做了 normalization"不足以复现, 需要说明统计量来自哪里, 是否冻结, 按 token 还是 sequence 聚合.

Sequence reward 对每个回答只加一次, KL 成本却按 token 累加. 回答越长, 预期 KL 总成本通常越大. 这会自然形成长度压力, 与 RM 的长度偏置相互作用. 若 RM 偏爱长回答, 两者可能暂时平衡; 若额外再加长度 penalty, 就出现第三个长度信号. 应按长度分桶画 RM, KL 和 total return, 而不是只观察总均值.

## 5. PPO 更新与工程闭环

RLHF 中的 PPO 同时面对两个距离. Probability ratio 衡量当前 policy 离生成 rollout 的 old policy 多远, 用于有限复用一批数据; reference KL 衡量 policy 离长期 SFT 锚点多远, 进入 reward 或 regularizer. 两者分母, 更新频率和目标完全不同.

一次训练迭代需要保存完整版本血缘. Prompt 数据版本, policy version, tokenizer, chat template, decoding 参数, RM version, reference version, value version 和 reward 配方, 都会改变样本语义. 只保存 prompt 和 response 无法复算 PPO loss.

### 5.1 PPO ratio 与 clipped surrogate

Rollout 由 $\pi_{old}$ 产生. 对 token 动作 $y_t$,

$$
\rho_t(\theta)=
\exp(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{old}(y_t\mid s_t)).
$$

PPO-Clip 最大化

$$
L^{clip}=\mathbb E_t\left[
\min(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t)
\right].
$$

若 $\hat A=2,\epsilon=0.2,\rho=1.3$, 原始项 2.6, 裁剪项 2.4, 目标取 2.4. 若 $\hat A=-2,\rho=0.7$, 原始项 -1.4, 裁剪项 -1.6, 目标取 -1.6. 平台只阻止 ratio 沿 advantage 建议方向继续走远, 不是把所有 ratio 硬限制在区间内.

### 5.2 一批数据的生命周期

Rollout worker 用 policy version $v$ 生成回答, 保存 token, completion mask, old log-prob, stop reason 和 sample id. Reference worker 对同一 token 序列计算 reference log-prob. RM 可以读取原始文本或自己的 tokenizer 输入, 但返回结果必须按 sample id join. Value model 计算每个 prefix 的 $V_{old}$.

Trainer 组合 token reward, 计算 fixed advantage 与 return, 再对 batch 做若干 minibatch epoch. 每个 epoch 中 `old_logp`, $V_{old}$, advantage 和 return 不变. 当 current-vs-old approximate KL 达到 PPO 早停阈值, 或达到 epoch 上限后, 发布 policy version $v+1$. 新 rollout 才使用新版本. 异步系统需要限制最大 version lag, 过旧样本即便能算 ratio, 也可能因大量 clipping 而几乎没有有效 policy 梯度.

### 5.3 Mask, tokenizer 与分布式对齐

Policy 与 reference 必须共享同一个 token action space、chat template 和 prefix 边界, 它们的 log-prob 才能针对完全相同的 token id 逐位求 ratio 与 KL. Value 可以使用独立参数, 但输出时间步必须与 policy token 对齐. Sequence RM 可以独立重编码文本, 前提是保留 completion 边界并按 sample id 回接标量. Chat template 多一个 assistant header, EOS 插入位置不同或左右 padding 混用, 都会让 KL 和 reward 加到错误位置.

最小验收批可含两个样本. 样本 A 自然 EOS, mask 为 $(1,1,1,0)$; 样本 B 达到长度上限, mask 为 $(1,1,1,1)$ 且 `truncated=true`. A 的 RM reward 只加在第三个位置. B 在第四个位置收终局 reward 后, 是否 bootstrap 由任务语义决定. 将 padding log-prob 设成极端值, 最终 reward 和 loss 应完全不变. 令 current log-prob 等于 old log-prob, 所有有效 ratio 应精确为 1.

### 5.4 自适应 KL 与资源账本

固定 $\beta$ 时, 不同训练阶段的 reference KL 可能差异很大. 一种控制方式是设目标 KL $K_{target}$, 当观测 KL 高于目标时增大 $\beta$, 低于目标时减小. 控制器更新要有时间尺度限制; 若每个 minibatch 都激烈调整, reward 定义会在同一 rollout batch 内变化, fixed advantage 假设也被破坏.

自适应 KL 只控制分布距离, 不直接保证回答质量. 一个 policy 可以在 KL 很小的情况下学到无效的格式偏好, 也可能需要较大 KL 才获得新能力. 目标 KL 应结合独立胜率, reward hacking 诊断和任务风险选择, 不能只追求控制曲线平滑.

资源上, policy training 需要参数, 梯度与 optimizer state; value 可共享骨干或单独部署; reference 与 RM 只前向, 可量化, 分片或卸载; rollout 还可能使用专用推理引擎. 逻辑上有四种角色, 并不要求四个同尺寸模型同时驻留. 真正的大头常是生成 token, 因为回答变长会同时增加 KV cache, policy rollout, reference/RM 前向和 PPO 训练位置数.

## 6. Reward hacking 与独立验收

Reward model 是有限数据上的代理指标. Policy optimization 会主动寻找提高这个指标的方法, 包括标注者真正喜欢的改进, 也包括长度偏置, 固定高分短语, 格式漏洞, 过度拒答或 RM 分布外模式. 训练 reward 上升只说明 policy 更会获得当前评分器的分数.

应把 reward hacking 看作闭环中的分布问题. RM 在旧候选上训练, PPO 产生新候选, 新候选暴露 RM 盲区, 人类再标注这些边界样本并更新数据. 若缺少这条反馈链, 增加 PPO steps 只会给 policy 更多搜索评分器漏洞的机会.

### 6.1 可见的作弊模式

若 chosen 回答普遍更长, RM 会把长度当质量, PPO 随后不断延长回答. 若安全数据里拒答常获胜, policy 可能对无害请求也套用拒答模板. 若数学回答的最终格式比推理正确性更容易判, 模型可能学会输出漂亮结构而不是正确过程.

监控至少应包括 RM reward, 回答长度, reference KL, policy entropy, PPO clip fraction, value explained variance, EOS 与 truncation 率, 以及不同任务上的分项 reward. 总 reward 上升而某个切片下降时, 聚合指标会隐藏真实退化.

### 6.2 独立评估与 holdout judge

最终验收必须使用未参与 reward optimization 的数据和判定. 可以是独立人类评审, 冻结且来源不同的 judge, 可验证任务, 安全红队或事实检查. RM validation accuracy, training reward 与人类胜率回答三个不同问题, 不能互相替代.

评估要保存对照策略和盲化顺序. 只与很早的 SFT baseline 比较, 可能掩盖训练中后期退化. 按 prompt paired evaluation 能减少任务难度差异, 报告置信区间能防止小样本胜率被误读. 对长度和风格敏感的 judge 还要做位置互换与长度分桶.

### 6.3 数据回流与停止条件

当独立评估发现新型失败, 可以把对应 prompt 与对照回答送回 preference collection, 更新 RM 或构造专门约束. 回流数据必须标明来自哪个 policy 与哪轮挖掘, 否则验证集会逐渐被训练过程污染. 新 RM 也会改变 reward 尺度, 需要重新校准 KL 系数与训练阈值.

停止训练的依据应同时包含外部质量, KL 漂移和优化诊断. Reward 继续上升但独立胜率停滞, 是停止或刷新 RM 的信号; KL 激增且 clip fraction 很高, 表示数据迅速过时; entropy 塌缩可能意味着探索不足. RLHF 的成品不是某个最高 reward checkpoint, 而是一套在目标分布上经过独立验证, 仍能追踪数据与模型版本的策略.

### 6.4 一轮失败怎样回到数据

假设监控发现 policy 回答长度从平均 300 token 升到 900 token, RM reward 上升 0.8, reference KL 只小幅增加, 独立人类胜率却下降. 第一步应按长度桶检查 RM 分数和 preference data, 而不是直接把 $\beta$ 调大. 如果 chosen 在训练数据中确实普遍更长, 说明 RM 利用了长度相关特征.

接着构造反事实 pair: 内容相同但删去重复段落, 长短不同但正确性相当, 以及长而空洞与短而完整的回答. 让标注者按明确 rubric 比较, 将这些 group 按 prompt 切分回流. 更新 RM 后, 先在原始 holdout 和长度对照集上确认排序改善, 再用固定 SFT policy 校准 reward 尺度.

最后从同一个 PPO 起点做小规模 A/B rollout, 固定 prompt 与生成 token 预算, 比较旧 RM 与新 RM 下的长度, reward, KL 和独立胜率. 新 RM 若只压低长度但损害复杂任务, 还需检查 rubric 是否过度偏向简洁. 这一整轮把现象, 数据, 评分器和 policy 实验连在一起, 比在 policy loss 里临时添加长度惩罚更容易解释和维护.

每次回流都应保留原始失败样本和修复后的对照, 让后续版本重新接受同一组回归测试.

## 7. 把一条样本从标注追到梯度

前面的模块只有放进同一条数据链里, 才能看出 RLHF 为什么容易出现「每个局部都像是对的, 合在一起却不工作」. 假设 prompt $x$ 生成两个候选 $y_A,y_B$, 标注者选择 $y_A$. 偏好数据先形成记录

$$
(x,y_A,y_B,\text{producer},\text{decode config},\text{rubric},\text{annotator vote}).
$$

RM 训练只读取其中一部分字段来最小化 $-\log\sigma(r_A-r_B)$, 但其余字段不能因此丢掉. Producer 决定回答来自哪一段支持集; 解码参数影响长度与多样性; rubric 与投票记录决定这个硬标签有多确定. 如果同一个 pair 有 3 名标注者, 票数为 $2:1$, 把它与 $3:0$ 都编码成 label 1 会丢掉分歧信息. 一种直接做法是使用软目标 $q=2/3$, 损失写成

$$
\mathcal L_{mathrm{soft}}
=-q\log\sigma(\Delta)-(1-q)\log\sigma(-\Delta).
$$

它对分差的导数为 $\sigma(\Delta)-q$, 最优预测概率就是经验胜率 $q$. 两票对一票只记录了当前样本中的经验胜率, 不能当作真实偏好概率恰好为 $2/3$: 标注者并非独立同分布, 票数少时估计方差也很大. 软标签的价值在于保留这部分分歧信息, 而不是把少量投票包装成精确概率.

进入 rollout 后, 同一条 prompt 由版本为 $v$ 的策略采样出回答 $y=(y_1,\ldots,y_T)$. 系统至少要保存三个形状不同的量:

- `tokens` 与 `response_mask` 是 $[B,T]$;
- `old_logp`、`ref_logp`、token reward、value 与 advantage 也是按有效动作对齐的 $[B,T]$;
- RM 原始分数通常是 $[B]$, 只在最后一个有效回答位置散射到 $[B,T]$.

若第 $i$ 条回答有效长度为 $L_i$, mask 给出的 $L_i-1$ 才是最终 reward 位置. `T-1` 只是张量的固定尾部; 遇到左 padding、右 padding 或生成引擎提前补 EOS, 它可能指向 padding. 最小单测应让一个 batch 同时包含长度 2 与长度 5 的回答, 检查两个序列的 reward 总和都等于各自 RM 分数减去各自 KL 成本.

### 7.1 一个四 token 的端到端手算

设回答有四个有效 token, rollout policy 与 reference 的逐 token log-ratio 为

$$
k=(0.20,-0.10,0.05,0.15),\qquad \beta_{KL}=0.1,\qquad R_{RM}=0.8.
$$

冻结 rollout 时刻的 shaping reward 得到

$$
r=(-0.02,0.01,-0.005,0.8-0.015)
=(-0.02,0.01,-0.005,0.785).
$$

总回报为 $0.77$, 与 $0.8-0.1\times0.30$ 一致. 再令 $\gamma=1,\lambda=1$, value 预测为 $(0.10,0.20,0.25,0.30)$, 终止后的 value 为 0. TD residual 是

$$
\delta=(0.08,0.06,0.045,0.485).
$$

从后向前累加可得 advantage

$$
\hat A=(0.67,0.59,0.53,0.485).
$$

第一项也可用 Monte Carlo return 检查: 从位置 1 起的总 reward 为 $0.77$, 减去 $V(s_1)=0.10$, 正好是 $0.67$. 如果实现结果不同, 应先查终局 reward、value shift 与 mask, 而不是立刻调学习率.

假设更新后四个 token 的 current-old log-prob difference 为 $(0.02,0.01,-0.03,0.00)$, ratio 分别约为 $(1.0202,1.0101,0.9704,1)$. 在这些 advantage 都为正且 $\epsilon=0.2$ 时尚未触发 clipping. 若第一项差值变成 $0.30$, ratio 约为 $1.35$, 该项的正优势目标被截到 $1.2\hat A_1$. **PPO ratio 使用 current 对 old, KL shaping 使用 rollout 对 reference**; 这两个差值恰好能在同一张表出现, 也最容易被变量名混掉.

### 7.2 On-policy 不是「只更新一次」

PPO 常把同一批 rollout 做多个 minibatch epoch, 所以严格说它使用的是短期复用的近似 on-policy 数据. 第一个 epoch 开始时 current 与 old 相同; 随更新进行, current 离 old 变远, importance ratio 才承担分布修正. Clip 会限制部分目标贡献, 却不能把已经过时的数据重新变成当前策略样本.

增加 epoch 能降低采样成本, 也会提高估计偏差. 一批回答里的动作只来自 $\pi_{old}$; 更新后的策略可能在相同 prompt 下生成完全不同的前缀, 那些前缀没有出现在 batch 中. Ratio 只能重加权已经观察到的动作, 无法为未采样轨迹创造 reward. 因此要同时看 sample reuse、current-old KL、clip fraction 与有效 token 数. 当大量正优势 token 被上界裁剪、负优势 token 被下界裁剪时, 继续扫同一批数据往往只让 critic 拟合得更深, policy 获得的新增信息很少.

不同并行 worker 还会制造版本滞后. Worker A 可能用 $v$ 生成, Trainer 已发布到 $v+2$ 才收到该 batch. 只要 old log-prob 与生成策略确实匹配, ratio 在数学上仍可计算, 但方差和 clipping 通常更大. 系统应记录 `policy_version` 并设置最大 lag, 不能用接收时的策略重新计算 old log-prob 后假装样本新鲜.

## 8. 偏差、方差与数据复用的账

RLHF 的总噪声不是一个「采样方差」能够概括. Prompt 抽样、token 采样、标注者分歧、RM 估计误差与 value 误差依次进入闭环. 增大 rollout 数可以降低给定 prompt 分布下的 Monte Carlo 方差, 却不会修复 RM 的系统偏差; 增加同一批数据的 PPO epoch 能复用 reward, 却不会增加新的环境信息.

RM 误差尤其危险, 因为优化会选择性放大它. 写成 $\hat r=r^*+\varepsilon$, 即使 $\varepsilon$ 在旧候选上的均值接近零, policy 也会主动搜索 $\varepsilon$ 为正的区域. 优化后的回答上, 条件期望 $\mathbb E[\varepsilon\mid y\sim\pi_\theta]$ 可以明显为正. 这就是普通验证误差很小, 训练后仍发生 reward hacking 的原因: 评测分布与被优化后的分布不同.

GAE 在 value bias 与 Monte Carlo variance 之间交换. 较小 $\lambda$ 更依赖 critic bootstrap, 方差低但会继承 value 偏差; $\lambda$ 接近 1 更接近完整回报, 对终局 RM 的噪声更敏感. Advantage whitening 能稳定尺度, 却会让一个 batch 中样本相互耦合: 加入一个极端高回报样本会改变其他所有样本的标准化优势. 小 batch 或按设备各自 whitening 时, 不同 rank 甚至优化不同尺度. 分布式实现要明确统计量是否跨 data-parallel group 汇总.

数据复用也分三层. SFT 样本可以跨 epoch 复用, 但会有记忆与域权重问题; preference pair 可以反复训练 RM, 但 margin 饱和后主要继续扩大置信度; rollout batch 只能在 old-policy 距离尚可控时短期复用. 把三者都叫「训练数据多跑几遍」会掩盖它们不同的统计含义.

## 9. 版本化验收表

一套能够复现的 RLHF 实验, 最少应固定下面这些边界:

| 边界 | 必须保存 | 不一致时会发生什么 |
| --- | --- | --- |
| SFT | checkpoint、tokenizer、chat template、loss mask | reference 与动作空间失配 |
| 偏好数据 | prompt/group id、候选来源、解码参数、rubric、投票 | 切分泄漏, 无法解释标签噪声 |
| RM | checkpoint、校准集、输出变换、截断长度 | reward 尺度漂移, 长回答被截断评价 |
| Rollout | policy version、old log-prob、seed、stop reason | ratio 分母错误, 截断与终止混淆 |
| PPO | KL 配方、$\beta$、$\gamma$、$\lambda$、clip、whitening 范围 | 同名指标对应不同目标 |
| 评测 | 固定 prompt、盲化规则、judge version、置信区间 | 训练信号污染最终结论 |

最终应能从任意一个异常 checkpoint 追到: 它看过哪些 prompt, 哪个策略生成了回答, 哪个 RM 给分, token reward 怎样组成, old/reference 各是谁, 哪些 minibatch 更新使用了这条轨迹. 这份血缘并不会让算法自动正确, 但没有它, 训练失败时只能靠猜.

还要单独验收训练与推理的聊天模板。训练时若在 assistant 起始标记后计算动作概率，部署时却由服务端自动多插入一个标记，模型看到的 prefix 已经不同；离线复算出的 KL、old log-prob 与线上真实采样都不再对应。工具调用场景还应把工具返回视为环境观测，而不是 policy 生成动作，对这些 token 计算 policy loss 会把不可控文本当成模型选择。

一次发布前的 smoke test 可以只用十几个固定 prompt，却要贯穿所有角色：用 rollout 引擎生成，训练框架重算 old log-prob，reference 重算 KL，RM 重算分数，再从保存的 token reward 复原 sequence return。两套引擎的 log-prob 不必逐位达到浮点完全相等，但差异应在预设容差内，并能解释量化、并行归约或 kernel 所带来的误差。若误差只集中在 EOS、特殊 token 或截断边界，应先停止大规模训练；这种分布通常指向动作定义不一致，随机数值噪声不会只挑这些边界出现。

**RLHF 流水线的可靠性最终落在可复算性上：每个统计量都能沿版本与 token 边界重新得到相同结果。**

这也解释了为什么小规模端到端演练比单独跑通各模块更重要：接口处的版本、顺序和 mask 错误，往往不会让程序报错，只会悄悄改掉优化目标。
