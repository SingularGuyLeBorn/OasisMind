# PPO-based RLHF 训练流水线

RLHF 把人的判断变成模型能够反复优化的训练信号. 经典流水线包含三个阶段:示范回答用于 supervised fine-tuning,同一 prompt 下的回答比较用于训练 reward model,当前 policy 再生成新回答并通过 PPO 提高预测奖励,reference policy KL 同时限制行为漂移.

三个阶段解决不同问题. SFT 决定模型最初如何回应指令;preference data 与 reward model 把有限的人类排序扩展为可批量计算的标量;online RL 让 policy 在自身分布上搜索更高奖励的回答. 闭环的难点在于 policy 更新会改变 rollout 分布,reward model 随即评价训练数据中少见的新行为,模型也有机会寻找评分器漏洞.

## 1. SFT 决定 RL 从哪里开始

令 prompt 为 $x$, completion 为 $y=(y_1,\ldots,y_T)$. 自回归策略分解为

$$
\pi_\theta(y\mid x)=
\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}).
$$

预训练模型会续写文本, SFT 用高质量指令与回答样本把条件分布移到对话任务附近. 这一步同时建立聊天模板, 停止行为, 风格和基本任务格式, 也为 reward model 与 PPO 提供一个可用的探索起点.

### 1.1 Completion-only 交叉熵

对示范样本 $(x,y^*)$, 常用损失为

$$
\mathcal L_{SFT}(\theta)=
-\sum_{t=1}^{T}m_t
\log\pi_\theta(y_t^*\mid x,y_{<t}^*).
$$

$m_t\in\{0,1\}$ 是 loss mask. 系统消息与用户 prompt 参与上下文条件, 通常不承担 assistant completion 的预测损失. Padding 位置必须为 0, EOS 是否计入取决于模板和训练目标, 但必须与生成停止规则一致. 若把 prompt token 加入 loss, 优化目标会额外建模 system/user 文本并改变各角色权重, 还会稀释 assistant completion 的监督预算; 若 EOS 被全部遮掉, 生成长度可能失控.

多轮对话还要决定哪些 assistant turn 进入 loss. 只训练末轮时,每条样本提供的监督较少;训练全部 assistant turn 时,要确保此前回答确实来自目标分布且格式正确. 这个选择会改变每个 token 的权重,应随数据版本保存,不能只记录原始对话 JSON.

SFT 的样本权重会延续到 RL 起点。按 token mean 训练时长回答贡献更多，按 sequence mean 时每条回答等权；多轮样本若每个 assistant turn 都训练，又会让长对话获得更多权重。数据条数相同不代表目标相同，最终 reduce 需要写成公式。

示范答案常由人工、强模型和规则模板混合产生。来源比例会塑造 policy 支持：某类任务只有模板拒答，RL 很难从 On-policy 探索中突然发现高质量回答；某类工具调用从未在 SFT 出现，后续动作概率可能接近零。SFT 覆盖是 RL 可搜索空间的实际起点。

去重若只按原始文本，会漏掉模板渲染、空白和轻微改写后的近重复。训练验证间存在同 prompt 变体时，SFT loss 与偏好评估都偏乐观。可用规范化文本、语义 embedding 与来源 id 多层去重，并保留误删审计。

SFT checkpoint 同时作为 PPO 初始化、reference 和常见 RM backbone 时，三条路径共享偏差。使用同一初始化方便对齐表征，却让 RM 更容易偏爱 SFT 风格。独立架构或不同数据初始化可增加 judge 多样性，计算成本也更高。

混入预训练或通用指令数据能保留能力，但其 loss scale 和 token 数可能压过高质量示范。采样比例、loss 权重和序列长度共同决定实际贡献。报告数据集名义比例之外，还需报告有效训练 token 与梯度尺度。

### 1.2 数据质量与策略支持

SFT 数据既提供目标行为, 也塑造初始策略的高概率区域与有效支持. Softmax LM 对多数 token sequence 仍有非零数学概率, 但概率质量极低的行为在有限 rollout 中几乎采不到. 若某类推理, 拒答或工具调用从未出现, PPO 需要靠随机探索发现它, 成本会很高. 若示范中含有系统性事实错误, reward model 后续又偏爱流畅表达, RL 可能把错误进一步放大.

去重与来源平衡也会改变结果. 同一模板的大量近重复回答会让模型把固定措辞当成指令遵循. 长回答数量偏多会改变长度先验. 数据验收应按任务, 来源, 语言, 长度和拒答类型切片, 并保留从训练 token 回到原始样本的 id.

### 1.3 SFT checkpoint 的三种职责

完成 SFT 后, checkpoint 通常至少承担三种逻辑职责. 第一份初始化 trainable policy. 第二份冻结为 reference policy, 在 RL 中定义行为锚点. 第三份可以作为产生 preference candidates 的初始策略. 它们开始时参数相同, 版本生命周期却不同.

训练中还会产生 old policy, 即生成当前 rollout batch 的 policy 快照. `old` 与 `reference` 不能混用. Old policy 只用于 PPO probability ratio, 每批更新; reference policy 用于长期 KL, 通常跨许多 batch 固定. 若 ratio 分母误用 reference, 多 epoch 数据复用和策略漂移会被混成同一个量.

### 1.4 SFT 混合比例与能力保留

Instruction data 通常远小于预训练语料. 若 SFT 只覆盖狭窄任务, 多轮训练可能改善对话格式, 同时削弱补全, 多语言或专业领域能力. 团队可以混入部分预训练样本, 使用较小学习率, 限制 epoch, 或按领域验证来控制这种分布迁移. 每种办法都会改变模型到底在优化什么.

混入预训练数据时, 两类 loss 的 token 数不能直接相加后假设权重合理. 一条长网页和一条短对话贡献的 token 数相差很大. 可以按 token 混合, 按 sequence 混合, 或先分别求均值再加权. 三种方法对长短样本和不同域的权重不同, 配方应明确到公式与 sampler.

SFT 结束后的评估也不能只看 instruction benchmark. 需要保留预训练能力, 目标任务, 长度分布, 拒答率与模板鲁棒性等切片, 作为 RL 阶段的初始基线. 后面 policy 发生变化时, 才能判断退化来自 SFT, reward model 还是 PPO.

## 2. 偏好数据把人的判断变成比较

Preference collection 对同一个 prompt 展示多个候选回答, 要求标注者按 rubric 选择更好的一个或给出排序. 比较比绝对打分容易校准: 标注者不必回答"这个回答值 7.3 分", 只需判断两个具体回答谁更符合帮助性, 正确性, 安全性和风格要求.

比较仍然带有主观性. 两位标注者可能对简洁与完整, 拒答与帮助, 风险与可用性作出不同取舍. 这些分歧不是单纯噪声, 它们揭示了最终单标量 reward 将压缩哪些价值冲突.

### 2.1 候选怎样产生

候选可以来自同一 policy 的不同温度或随机种子, 也可以来自多个 checkpoint 与基线模型. 只比较一个很强和一个明显很差的回答, reward model 容易学到粗糙特征, 却难以区分 policy 训练后遇到的近邻回答. 因此候选难度需要覆盖当前决策边界.

采样元数据应包括 policy version, decoding temperature, top-p, max tokens, stop reason 和模板版本. 长度上限造成的截断回答若与自然 EOS 混在一起, 标注者可能把不完整性学成内容偏好. 同一回答在不同模板下的边界也可能变化.

### 2.2 Pair, ranking 与切分单位

一组 $K$ 个候选可产生最多 $K(K-1)/2$ 个 pair. 这些 pair 共享 prompt 与回答, 统计上高度相关. 若把 pair 随机分到训练集和验证集, 同一个回答可能同时出现在两侧, reward model validation 会虚高.

正确切分单位通常是 prompt 或完整 candidate group. 训练时还要控制每组权重. 一个有 8 个候选的 prompt 能产生 28 个 pair, 若逐 pair 等权, 它会比只有 2 个候选的 prompt 获得 28 倍影响. 可以按 group 归一化, 抽样部分 pair, 或直接使用 listwise objective.

### 2.3 标注一致性与 rubric

Rubric 需要把事实正确, 指令遵循, 帮助性, 安全性和表达质量写成可操作条件. 如果标注者只看到"选更好", 每个人会自行设定权重, reward model 学到的是混合且随批次漂移的隐含标准.

可以用重复标注估计一致性, 对争议样本保留 tie 或软标签, 并分析分歧集中在哪些任务. 强行把 tie 转成随机 winner 会制造不存在的确定性. 若项目确实需要多个价值维度, 保存分项标签比事后从单一 reward 反推更可靠.

### 2.4 主动采样把标注用在决策边界

随机抽取候选 pair 简单, 却会产生大量一眼可判的比较. 当 winner probability 已接近 0 或 1, 新标签对 reward model 决策边界提供的信息有限. 可以优先采样 RM 分差接近 0, 多个 RM 意见不一致, 或当前 policy 与 reference 差异较大的回答, 把标注预算集中到难例.

主动采样会改变训练数据分布. 如果只收集最不确定样本, RM 看到的 easy case 减少, 原始 prompt 分布也可能被高风险域占据. 训练时可混合随机样本与主动样本, 保存采样概率, 并在独立自然分布验证集上评估. 否则 validation 也跟着主动分布移动, 很难判断整体质量.

Policy 迭代后, 旧的难例可能变成常见模式, 新漏洞又会出现. 因而 candidate generation 与 annotation 是持续过程. 每批 preference data 都应关联 producer policy version, RM version 和选择规则. 这条血缘能回答一个关键问题: RM 的高分区域究竟被多少真实人类比较覆盖.

## 3. Bradley-Terry 奖励模型

Reward model 接收 $(x,y)$ 并输出标量 $r_\phi(x,y)$. Bradley-Terry 假设回答 $y_w$ 胜过 $y_l$ 的概率只由分数差决定:

$$
P_\phi(y_w\succ y_l\mid x)=
\sigma(r_\phi(x,y_w)-r_\phi(x,y_l)).
$$

模型通常从 SFT 或预训练 checkpoint 初始化,在末尾 token 或专用位置读取 sequence representation,再映射为标量. 单个 $r_\phi(x,y)$ 是 latent score;成对分差 $r_w-r_l$ 才是 sigmoid 使用的 pairwise logit. 这些分数没有经过物理标定,不能直接视为人类效用单位.

### 3.1 Pairwise loss 与梯度

令 $r_w=r_\phi(x,y_w)$, $r_l=r_\phi(x,y_l)$, $\Delta=r_w-r_l$. 负对数似然为

$$
\mathcal L_{RM}=-\log\sigma(\Delta).
$$

利用 $d[-\log\sigma(z)]/dz=\sigma(z)-1$, 得到

$$
\frac{\partial\mathcal L}{\partial r_w}=\sigma(\Delta)-1,
\qquad
\frac{\partial\mathcal L}{\partial r_l}=1-\sigma(\Delta).
$$

若 $r_w=0.2,r_l=-0.1$, 则 $\Delta=0.3$, $\sigma(0.3)\approx0.574$. 梯度下降让 winner 分数增加约 $0.426\eta$, loser 分数下降约 $0.426\eta$, 其中 $\eta$ 是对两个标量直接优化时的学习率. 差值变大, winner probability 随之上升.

### 3.2 Identifiability 的边界

损失只依赖 $r_w-r_l$. 对任意与 prompt 有关的常数 $c(x)$,

$$
(r_w+c(x))-(r_l+c(x))=r_w-r_l.
$$

因此 reward 的绝对零点不可识别. 训练集上的所有分数同时加 10, pairwise probability 完全不变. 单独查看平均 reward 没有固定语义, 除非给出版本, 数据和校准方式.

尺度也受数据可分性与正则化影响. 将所有分差乘得更大, 对已正确排序且近乎可分的数据会继续降低 logistic loss. Weight decay, early stopping, label smoothing 或显式温度共同决定输出尺度. 换一个 RM checkpoint 后, PPO 的 $\beta$, advantage 标准化和 reward clipping 都可能需要重新校准.

### 3.3 验证 reward model

Pair accuracy 只测 winner 是否得分更高, 对 margin 和校准不敏感. 应同时查看 log loss, 不同任务与长度分桶, 标注分歧组, 以及 policy 新分布上的表现. 若 validation 与训练 candidates 来自同一批模型和模板, 高准确率也不能证明 RM 能评价 PPO 后产生的新行为.

长度偏置是一个常见检查项. 若 chosen 系统性更长, RM 可能学到"更长更好". 可以构造内容近似但长度不同的对照, 在相同长度桶内报告 accuracy, 并检查分数对 token 数的回归斜率. 直接把长度从输入删除不可行, 关键是让偏好数据包含足够反例.

### 3.4 不确定性与 RM ensemble

单个 RM 给出的 5.0 看起来很确定, 但标量本身不包含认识不确定性. 可以训练多个不同初始化, 数据 bootstrap 或架构的 reward models, 比较同一回答的分数方差. Ensemble 均值用作 reward, 方差可作为分布外警报或主动标注依据.

例如三个 RM 对回答 A 打分 $(1.2,1.1,1.3)$, 对回答 B 打分 $(2.0,-0.5,1.8)$. B 的平均分 1.1 与 A 的 1.2 接近, 模型间分歧却大得多. 直接按均值排序会忽略 B 可能位于训练覆盖之外. 可以对高方差样本降低优化权重, 请求人类复核, 或限制 policy 在该区域继续更新.

Ensemble 也会共同继承数据偏差. 所有成员在相同长度偏置数据上训练, 一致高分不代表判断正确. 不确定性诊断只能揭示部分 epistemic uncertainty, 不能替代独立人类评估和有针对性的反事实测试.

## 4. 从 sequence reward 到 token 回报

Policy 生成整个回答后, RM 通常给出一个 sequence-level 标量. PPO 的动作却是逐 token 采样, critic 也在每个 prefix 状态估值. 流水线必须把终局分数, reference KL 和任何规则奖励组合成 token reward, 再用 GAE 分配到各位置.

这一转换最容易出现边界错误. Reward 加在哪个 token, EOS 是否有效, padding 是否泄漏, 长度截断是否 bootstrap, 都会改变整条回答的 advantage, 因而直接属于训练目标.

### 4.1 Reference-policy KL 目标

一个常见序列目标是

$$
J(\theta)=
\mathbb E_{x\sim D,y\sim\pi_\theta}
\left[R_\phi(x,y)-
\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}\right].
$$

因为自回归概率是 token 条件概率的乘积,

$$
\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}
=\sum_{t=1}^{T}
\left(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{ref}(y_t\mid s_t)\right).
$$

对当前 policy 样本取期望时, 这个 log-ratio 估计 $D_{KL}(\pi_\theta\Vert\pi_{ref})$. KL 惩罚使 policy 为离开 SFT 行为付出代价, 限制它进入 RM 缺少覆盖的区域. $\beta$ 控制 reward improvement 与行为漂移的交换率, 不是普适常数.

### 4.2 Token shaping 与可复算例子

理论目标里的 log-ratio 随当前策略 $\pi_\theta$ 变化. 但标准 PPO 实现先由 rollout policy $\pi_v$ 生成 batch, 再固定 $k_t^{v}=\ell_t^{v}-\ell_t^{ref}$ 构造这一批的 token reward、advantage 和 return. 可以令每个位置 reward 为

$$
r_t^{token}=-\beta k_t^{v},
$$

并在末尾有效 completion token 上加 sequence reward $R_\phi(x,y)$. 假设三 token 回答的 $k=(0.1,0.2,-0.1)$,$\beta=0.05$,RM 分数为 1.2. Token reward 为

$$
(-0.005,-0.010,0.005+1.2)
=(-0.005,-0.010,1.205).
$$

总和是 1.19, 等于 $02-0.05\times(0.1+0.2-0.1)$. 这项手算可以检查 KL 符号, token mask 和终局奖励位置. 若 padding 上 log-ratio 被设成极大值, 总 reward 仍应不变.

Sampled log-ratio $k=\log\pi_v-\log\pi_{ref}$ 可能逐 token 为负, 虽然其在 $\pi_v$ 下的期望是 $D_{KL}(\pi_v\Vert\pi_{ref})\ge0$. 对同一方向的非负样本近似可以写成 $e^{-k}-1+k$; 若另定义 $\Delta=\log\pi_{ref}-\log\pi_v=-k$, 等价形式才是 $e^{\Delta}-1-\Delta$. 有些系统计算全词表 KL. 若在每个 PPO epoch 用当前 $\pi_\theta$ 重算 reference KL, 它就成为显式 current-reference regularizer, 不再是本批冻结的 reward shaping. 这些口径的数值尺度与梯度性质不同, 不能共用同一 $\beta$ 后直接比较.

### 4.3 Sequence reward 的 credit assignment

终局 RM 分数没有告诉系统哪个 token 造成偏好. Critic 学习前缀的期望回报, GAE 再把后续 TD residual 传播到此前动作. 对状态 $s_t=(x,y_{<t})$, 令 $d_t$ 表示 bootstrap-stop mask: 真正 termination 必为 1; length truncation 若任务把它视作终局也取 1, 若理论过程仍可继续并保留有效 final state 则取 0. $b_t=1$ 表示这一位置后发生 termination、length truncation 或 batch 中的 sequence boundary. $V_{old}$ 是 rollout 时冻结的 value, $\gamma$ 是回报折扣, $\lambda$ 是 GAE trace 系数:

$$
\delta_t=r_t+\gamma(1-d_t)V_{old}(s_{t+1})-V_{old}(s_t),
$$

$$
\hat A_t=\delta_t+\gamma\lambda(1-b_t)\hat A_{t+1}.
$$

Termination 令 bootstrap 与 trace 都停止; length truncation 是否允许 value bootstrap 取决于任务语义, 但 trace 必须在回答边界停止, 不能把下一条回答的 advantage 传回来.

若 $\gamma=1,\lambda=0.8$, reward 为 $(0,0,1)$, value 为 $(0.2,0.4,0.5)$, 终止后 value 为 0, 则 residual 是 $(0.2,0.1,0.5)$, advantage 是 $(0.6,0.5,0.5)$. 前两个 token 获得正信号, 因为它们位于通向高终局 reward 的轨迹上.

这仍是粗粒度信用分配. 一条回答包含事实, 推理和风格多个因素, 单个标量会把它们一起广播给整段 token. Process reward 或可验证中间结果能提供更局部信号, 但需要新的数据与正确性假设. Sequence RM 的限制不应被 GAE 的数学形式掩盖.

### 4.4 Reward 尺度, whitening 与长度

固定 sigmoid link 与 temperature 时, RM 的加性零点严格不可识别, 乘法缩放却会改变 pairwise probability. 不过输出尺度仍会被 label noise、temperature、正则、early stopping 和数据可分性强烈影响, 因而不同 checkpoint 的数值不能直接横比. PPO 又会直接使用 reward 数值. 常见做法是在冻结 policy 生成的校准集上估计均值与标准差, 把 RM 输出变换为近似零均值单位方差. 这个变换必须绑定 RM version 和校准分布. Policy 更新后重新用当前样本归一化, 会让目标随 policy 分布移动, 训练 reward 的跨步比较也失去意义.

Advantage whitening 又是另一层变换. Reward normalization 改变 return 与 critic target; advantage whitening 只在 policy update 前重新缩放优势. 两者同时使用时, value loss, entropy 和 KL 系数的相对尺度都会变化. 报告"做了 normalization"不足以复现, 需要说明统计量来自哪里, 是否冻结, 按 token 还是 sequence 聚合.

Sequence reward 对每个回答只加一次, KL 成本却按 token 累加. 回答越长, 预期 KL 总成本通常越大. 这会自然形成长度压力, 与 RM 的长度偏置相互作用. 若 RM 偏爱长回答, 两者可能暂时平衡; 若额外再加长度 penalty, 就出现第三个长度信号. 应按长度分桶画 RM, KL 和 total return, 而不是只观察总均值.

## 5. PPO 更新与工程闭环

RLHF 中的 PPO 同时面对两个距离. Probability ratio 衡量当前 policy 离生成 rollout 的 old policy 多远, 用于有限复用一批数据; reference KL 衡量 policy 离长期 SFT 锚点多远, 进入 reward 或 regularizer. 两者分母, 更新频率和目标完全不同.

一次训练迭代需要保存完整版本血缘. Prompt 数据版本, policy version, tokenizer, chat template, decoding 参数, RM version, reference version, value version 和 reward 配方, 都会改变样本语义. 只保存 prompt 和 response 无法复算 PPO loss.

### 5.1 PPO ratio 与 clipped surrogate

Rollout 由 $\pi_{old}$ 产生. 对 token 动作 $y_t$,

$$
\rho_t(\theta)=
\exp(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{old}(y_t\mid s_t)).
$$

PPO-Clip 最大化

$$
L^{clip}=\mathbb E_t\left[
\min(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t)
\right].
$$

若 $\hat A=2,\epsilon=0.2,\rho=1.3$, 原始项 2.6, 裁剪项 2.4, 目标取 2.4. 若 $\hat A=-2,\rho=0.7$, 原始项 -1.4, 裁剪项 -1.6, 目标取 -1.6. 平台只阻止 ratio 沿 advantage 建议方向继续走远, 不是把所有 ratio 硬限制在区间内.

### 5.2 一批数据的生命周期

Rollout worker 用 policy version $v$ 生成回答, 保存 token, completion mask, old log-prob, stop reason 和 sample id. Reference worker 对同一 token 序列计算 reference log-prob. RM 可以读取原始文本或自己的 tokenizer 输入, 但返回结果必须按 sample id join. Value model 计算每个 prefix 的 $V_{old}$.

Trainer 组合 token reward, 计算 fixed advantage 与 return, 再对 batch 做若干 minibatch epoch. 每个 epoch 中 `old_logp`, $V_{old}$, advantage 和 return 不变. 当 current-vs-old approximate KL 达到 PPO 早停阈值, 或达到 epoch 上限后, 发布 policy version $v+1$. 新 rollout 才使用新版本. 异步系统需要限制最大 version lag, 过旧样本即便能算 ratio, 也可能因大量 clipping 而几乎没有有效 policy 梯度.

### 5.3 Mask, tokenizer 与分布式对齐

Policy 与 reference 必须共享同一个 token action space、chat template 和 prefix 边界, 它们的 log-prob 才能针对完全相同的 token id 逐位求 ratio 与 KL. Value 可以使用独立参数, 但输出时间步必须与 policy token 对齐. Sequence RM 可以独立重编码文本, 前提是保留 completion 边界并按 sample id 回接标量. Chat template 多一个 assistant header, EOS 插入位置不同或左右 padding 混用, 都会让 KL 和 reward 加到错误位置.

最小验收批可含两个样本. 样本 A 自然 EOS, mask 为 $(1,1,1,0)$; 样本 B 达到长度上限, mask 为 $(1,1,1,1)$ 且 `truncated=true`. A 的 RM reward 只加在第三个位置. B 在第四个位置收终局 reward 后, 是否 bootstrap 由任务语义决定. 将 padding log-prob 设成极端值, 最终 reward 和 loss 应完全不变. 令 current log-prob 等于 old log-prob, 所有有效 ratio 应精确为 1.

### 5.4 自适应 KL 与资源开销

固定 $\beta$ 时, 不同训练阶段的 reference KL 可能差异很大. 一种控制方式是设目标 KL $K_{target}$, 当观测 KL 高于目标时增大 $\beta$, 低于目标时减小. 控制器更新要有时间尺度限制; 若每个 minibatch 都激烈调整, reward 定义会在同一 rollout batch 内变化, fixed advantage 假设也被破坏.

自适应 KL 只控制分布距离, 不直接保证回答质量. 一个 policy 可以在 KL 很小的情况下学到无效的格式偏好, 也可能需要较大 KL 才获得新能力. 目标 KL 应结合独立胜率, reward hacking 诊断和任务风险选择, 不能只追求控制曲线平滑.

资源上, policy training 需要参数, 梯度与 optimizer state; value 可共享骨干或单独部署; reference 与 RM 只前向, 可量化, 分片或卸载; rollout 还可能使用专用推理引擎. 逻辑上有四种角色, 并不要求四个同尺寸模型同时驻留. 真正的大头常是生成 token, 因为回答变长会同时增加 KV cache, policy rollout, reference/RM 前向和 PPO 训练位置数.

## 6. Reward hacking 与独立验收

Reward model 是有限数据上的代理指标. Policy optimization 会主动寻找提高这个指标的方法, 包括标注者真正喜欢的改进, 也包括长度偏置, 固定高分短语, 格式漏洞, 过度拒答或 RM 分布外模式. 训练 reward 上升只说明 policy 更会获得当前评分器的分数.

应把 reward hacking 看作闭环中的分布问题. RM 在旧候选上训练, PPO 产生新候选, 新候选暴露 RM 盲区, 人类再标注这些边界样本并更新数据. 若缺少这条反馈链, 增加 PPO steps 只会给 policy 更多搜索评分器漏洞的机会.

### 6.1 可见的作弊模式

若 chosen 回答普遍更长, RM 会把长度当质量, PPO 随后不断延长回答. 若安全数据里拒答常获胜, policy 可能对无害请求也套用拒答模板. 若数学回答的最终格式比推理正确性更容易判, 模型可能学会输出漂亮结构而不是正确过程.

监控至少应包括 RM reward, 回答长度, reference KL, policy entropy, PPO clip fraction, value explained variance, EOS 与 truncation 率, 以及不同任务上的分项 reward. 总 reward 上升而某个切片下降时, 聚合指标会隐藏真实退化.

### 6.2 独立评估与 holdout judge

最终验收必须使用未参与 reward optimization 的数据和判定. 可以是独立人类评审, 冻结且来源不同的 judge, 可验证任务, 安全红队或事实检查. RM validation accuracy, training reward 与人类胜率回答三个不同问题, 不能互相替代.

评估要保存对照策略和盲化顺序. 只与很早的 SFT baseline 比较, 可能掩盖训练中后期退化. 按 prompt paired evaluation 能减少任务难度差异, 报告置信区间能防止小样本胜率被误读. 对长度和风格敏感的 judge 还要做位置互换与长度分桶.

### 6.3 数据回流与停止条件

当独立评估发现新型失败, 可以把对应 prompt 与对照回答送回 preference collection, 更新 RM 或构造专门约束. 回流数据必须标明来自哪个 policy 与哪轮挖掘, 否则验证集会逐渐被训练过程污染. 新 RM 也会改变 reward 尺度, 需要重新校准 KL 系数与训练阈值.

停止训练的依据应同时包含外部质量, KL 漂移和优化诊断. Reward 继续上升但独立胜率停滞, 是停止或刷新 RM 的信号; KL 激增且 clip fraction 很高, 表示数据迅速过时; entropy 塌缩可能意味着探索不足. 最终策略需要在目标分布上通过独立验证, 并保留可追踪的数据与模型版本;单个 reward 最高的 checkpoint 无法提供这些保证.

### 6.4 一轮失败怎样回到数据

假设监控发现 policy 回答长度从平均 300 token 升到 900 token, RM reward 上升 0.8, reference KL 只小幅增加, 独立人类胜率却下降. 第一步应按长度桶检查 RM 分数和 preference data, 而不是直接把 $\beta$ 调大. 如果 chosen 在训练数据中确实普遍更长, 说明 RM 利用了长度相关特征.

接着构造反事实 pair: 内容相同但删去重复段落, 长短不同但正确性相当, 以及长而空洞与短而完整的回答. 让标注者按明确 rubric 比较, 将这些 group 按 prompt 切分回流. 更新 RM 后, 先在原始 holdout 和长度对照集上确认排序改善, 再用固定 SFT policy 校准 reward 尺度.

从同一个 PPO 起点做小规模 A/B rollout,固定 prompt 与生成 token 预算,比较旧 RM 与新 RM 下的长度、reward、KL 和独立胜率. 新 RM 若只压低长度却损害复杂任务,还需检查 rubric 是否过度偏向简洁. 这一轮把现象、数据、评分器和 policy 实验连在一起,比在 policy loss 里临时添加长度惩罚更容易解释和维护.

每次回流都应保留原始失败样本和修复后的对照, 让后续版本重新接受同一组回归测试.

## 7. 把一条样本从标注追到梯度

前面的模块只有放进同一条数据链里, 才能看出 RLHF 为什么容易出现「每个局部都像是对的, 合在一起却不工作」. 假设 prompt $x$ 生成两个候选 $y_A,y_B$, 标注者选择 $y_A$. 偏好数据先形成记录

$$
(x,y_A,y_B,\text{producer},\text{decode config},\text{rubric},\text{annotator vote}).
$$

RM 训练只读取其中一部分字段来最小化 $-\log\sigma(r_A-r_B)$, 但其余字段不能因此丢掉. Producer 决定回答来自哪一段支持集; 解码参数影响长度与多样性; rubric 与投票记录决定这个硬标签有多确定. 如果同一个 pair 有 3 名标注者, 票数为 $2:1$, 把它与 $3:0$ 都编码成 label 1 会丢掉分歧信息. 一种直接做法是使用软目标 $q=2/3$, 损失写成

$$
\mathcal L_{mathrm{soft}}
=-q\log\sigma(\Delta)-(1-q)\log\sigma(-\Delta).
$$

它对分差的导数为 $\sigma(\Delta)-q$, 最优预测概率就是经验胜率 $q$. 两票对一票只记录了当前样本中的经验胜率, 不能当作真实偏好概率恰好为 $2/3$: 标注者并非独立同分布, 票数少时估计方差也很大. 软标签的价值在于保留这部分分歧信息, 而不是把少量投票包装成精确概率.

进入 rollout 后, 同一条 prompt 由版本为 $v$ 的策略采样出回答 $y=(y_1,\ldots,y_T)$. 系统至少要保存三个形状不同的量:

- `tokens` 与 `response_mask` 是 $[B,T]$;
- `old_logp`、`ref_logp`、token reward、value 与 advantage 也是按有效动作对齐的 $[B,T]$;
- RM 原始分数通常是 $[B]$,只在末尾有效回答位置散射到 $[B,T]$.

若第 $i$ 条回答有效长度为 $L_i$, mask 给出的 $L_i-1$ 才是最终 reward 位置. `T-1` 只是张量的固定尾部; 遇到左 padding、右 padding 或生成引擎提前补 EOS, 它可能指向 padding. 最小单测应让一个 batch 同时包含长度 2 与长度 5 的回答, 检查两个序列的 reward 总和都等于各自 RM 分数减去各自 KL 成本.

### 7.1 一个四 token 的端到端手算

设回答有四个有效 token, rollout policy 与 reference 的逐 token log-ratio 为

$$
k=(0.20,-0.10,0.05,0.15),\qquad \beta_{KL}=0.1,\qquad R_{RM}=0.8.
$$

冻结 rollout 时刻的 shaping reward 得到

$$
r=(-0.02,0.01,-0.005,0.8-0.015)
=(-0.02,0.01,-0.005,0.785).
$$

总回报为 $0.77$, 与 $0.8-0.1\times0.30$ 一致. 再令 $\gamma=1,\lambda=1$, value 预测为 $(0.10,0.20,0.25,0.30)$, 终止后的 value 为 0. TD residual 是

$$
\delta=(0.08,0.06,0.045,0.485).
$$

从后向前累加可得 advantage

$$
\hat A=(0.67,0.59,0.53,0.485).
$$

第一项也可用 Monte Carlo return 检查: 从位置 1 起的总 reward 为 $0.77$, 减去 $V(s_1)=0.10$, 正好是 $0.67$. 如果实现结果不同, 应先查终局 reward、value shift 与 mask, 而不是立刻调学习率.

假设更新后四个 token 的 current-old log-prob difference 为 $(0.02,0.01,-0.03,0.00)$, ratio 分别约为 $(1.0202,1.0101,0.9704,1)$. 在这些 advantage 都为正且 $\epsilon=0.2$ 时尚未触发 clipping. 若第一项差值变成 $0.30$, ratio 约为 $1.35$, 该项的正优势目标被截到 $1.2\hat A_1$. **PPO ratio 使用 current 对 old, KL shaping 使用 rollout 对 reference**; 这两个差值恰好能在同一张表出现, 也最容易被变量名混掉.

### 7.2 On-policy 不是「只更新一次」

PPO 常把同一批 rollout 做多个 minibatch epoch, 所以严格说它使用的是短期复用的近似 on-policy 数据. 第一个 epoch 开始时 current 与 old 相同; 随更新进行, current 离 old 变远, importance ratio 才承担分布修正. Clip 会限制部分目标贡献, 却不能把已经过时的数据重新变成当前策略样本.

增加 epoch 能降低采样成本, 也会提高估计偏差. 一批回答里的动作只来自 $\pi_{old}$; 更新后的策略可能在相同 prompt 下生成完全不同的前缀, 那些前缀没有出现在 batch 中. Ratio 只能重加权已经观察到的动作, 无法为未采样轨迹创造 reward. 因此要同时看 sample reuse、current-old KL、clip fraction 与有效 token 数. 当大量正优势 token 被上界裁剪、负优势 token 被下界裁剪时, 继续扫同一批数据往往只让 critic 拟合得更深, policy 获得的新增信息很少.

不同并行 worker 还会制造版本滞后. Worker A 可能用 $v$ 生成, Trainer 已发布到 $v+2$ 才收到该 batch. 只要 old log-prob 与生成策略确实匹配, ratio 在数学上仍可计算, 但方差和 clipping 通常更大. 系统应记录 `policy_version` 并设置最大 lag, 不能用接收时的策略重新计算 old log-prob 后假装样本新鲜.

## 8. 偏差、方差与数据复用代价

RLHF 的总噪声不是一个「采样方差」能够概括. Prompt 抽样、token 采样、标注者分歧、RM 估计误差与 value 误差依次进入闭环. 增大 rollout 数可以降低给定 prompt 分布下的 Monte Carlo 方差, 却不会修复 RM 的系统偏差; 增加同一批数据的 PPO epoch 能复用 reward, 却不会增加新的环境信息.

RM 误差尤其危险, 因为优化会选择性放大它. 写成 $\hat r=r^*+\varepsilon$, 即使 $\varepsilon$ 在旧候选上的均值接近零, policy 也会主动搜索 $\varepsilon$ 为正的区域. 优化后的回答上, 条件期望 $\mathbb E[\varepsilon\mid y\sim\pi_\theta]$ 可以明显为正. 这就是普通验证误差很小, 训练后仍发生 reward hacking 的原因: 评测分布与被优化后的分布不同.

GAE 在 value bias 与 Monte Carlo variance 之间交换. 较小 $\lambda$ 更依赖 critic bootstrap, 方差低但会继承 value 偏差; $\lambda$ 接近 1 更接近完整回报, 对终局 RM 的噪声更敏感. Advantage whitening 能稳定尺度, 却会让一个 batch 中样本相互耦合: 加入一个极端高回报样本会改变其他所有样本的标准化优势. 小 batch 或按设备各自 whitening 时, 不同 rank 甚至优化不同尺度. 分布式实现要明确统计量是否跨 data-parallel group 汇总.

数据复用也分三层. SFT 样本可以跨 epoch 复用, 但会有记忆与域权重问题; preference pair 可以反复训练 RM, 但 margin 饱和后主要继续扩大置信度; rollout batch 只能在 old-policy 距离尚可控时短期复用. 把三者都叫「训练数据多跑几遍」会掩盖它们不同的统计含义.

## 9. 版本化验收表

一套能够复现的 RLHF 实验, 最少应固定下面这些边界:

| 边界 | 必须保存 | 不一致时会发生什么 |
| --- | --- | --- |
| SFT | checkpoint、tokenizer、chat template、loss mask | reference 与动作空间失配 |
| 偏好数据 | prompt/group id、候选来源、解码参数、rubric、投票 | 切分泄漏, 无法解释标签噪声 |
| RM | checkpoint、校准集、输出变换、截断长度 | reward 尺度漂移, 长回答被截断评价 |
| Rollout | policy version、old log-prob、seed、stop reason | ratio 分母错误, 截断与终止混淆 |
| PPO | KL 配方、$\beta$、$\gamma$、$\lambda$、clip、whitening 范围 | 同名指标对应不同目标 |
| 评测 | 固定 prompt、盲化规则、judge version、置信区间 | 训练信号污染最终结论 |

最终应能从任意一个异常 checkpoint 追到: 它看过哪些 prompt, 哪个策略生成了回答, 哪个 RM 给分, token reward 怎样组成, old/reference 各是谁, 哪些 minibatch 更新使用了这条轨迹. 这份血缘并不会让算法自动正确, 但没有它, 训练失败时只能靠猜.

还要单独验收训练与推理的聊天模板。训练时若在 assistant 起始标记后计算动作概率，部署时却由服务端自动多插入一个标记，模型看到的 prefix 已经不同；离线复算出的 KL、old log-prob 与线上真实采样都不再对应。工具调用场景还应把工具返回视为环境观测，而不是 policy 生成动作，对这些 token 计算 policy loss 会把不可控文本当成模型选择。

一次发布前的 smoke test 可以只用十几个固定 prompt，却要贯穿所有角色：用 rollout 引擎生成，训练框架重算 old log-prob，reference 重算 KL，RM 重算分数，再从保存的 token reward 复原 sequence return。两套引擎的 log-prob 不必逐位达到浮点完全相等，但差异应在预设容差内，并能解释量化、并行归约或 kernel 所带来的误差。若误差只集中在 EOS、特殊 token 或截断边界，应先停止大规模训练；这种分布通常指向动作定义不一致，随机数值噪声不会只挑这些边界出现。

RLHF 流水线的可靠性最终落在可复算性上：每个统计量都能沿版本与 token 边界重新得到相同结果。

这也解释了为什么小规模端到端演练比单独跑通各模块更重要：接口处的版本、顺序和 mask 错误，往往不会让程序报错，只会悄悄改掉优化目标。

## 10. 偏好数据背后的统计模型

偏好标注不是天然真值。它由候选生成分布、展示顺序、标注者群体、rubric 和界面共同产生。奖励模型拟合的是这套观测过程；观测过程与部署目标不一致时，扩大数据只会更精确地学习偏差。

### 10.1 Bradley-Terry 的概率假设

对同一提示 $x$ 的两个回答 $y_w,y_l$，Bradley-Terry 模型写成

$$
P(y_w\succ y_l\mid x)=
\sigma[r_\phi(x,y_w)-r_\phi(x,y_l)].
$$

它假设比较概率由一个标量效用差决定，并采用 logistic 噪声。若人类偏好具有循环，例如 A 胜 B、B 胜 C、C 又胜 A，单标量无法同时表示全部关系。训练会寻找加权折中，pairwise accuracy 上限低于一不一定是模型容量不足。

对 reward 加任意仅依赖提示的常数 $c(x)$，差值不变，因此绝对零点不可识别。缩放 reward 会改变预测置信度，交叉熵可通过噪声水平约束尺度，却仍受标签温度与正则影响。后续 PPO 使用绝对 reward 尺度时，必须重新校准或 whitening，不能把 RM logit 当成天然统一单位。

### 10.2 Tie、弃权与强度信息

标注者可能认为两个回答相当，或无法判断。强迫二选一会把随机选择写成有方向标签，增加不可约噪声。tie 可用 Davidson 等扩展模型，或将一对拆成软标签 $0.5$；弃权则应作为缺失机制单独记录。

软标签 $q\in[0,1]$ 的 loss 为

$$
-q\log\sigma(\Delta r)
-(1-q)\log[1-\sigma(\Delta r)].
$$

偏好强度可映射到不同 $q$ 或样本权重，但二者含义不同：软标签改变最优概率，权重改变该比较对总体目标的重要性。界面中的“略好”“明显好”若标注一致性低，细分等级可能只增加噪声。

### 10.3 标注者混合与个体差异

不同标注者可能有稳定价值差异。把所有标签混合训练单一 reward，学到的是按标注量加权的群体平均；标注多的人或外包组权重更大。若部署用户分布不同，平均偏好会偏移。

可用层级模型写 $r_{\phi,z}$，其中 $z$ 表示标注者群体或偏好维度。这样能分离共同质量与个体差异，也需要足够重复标注才能识别。只在每个样本上随机分配一位标注者，模型很难区分样本噪声和人群差异。

多数票压缩了分歧结构。三人以二比一选择 A，与三人一致选择 A 得到相同 hard label，却有不同置信度。保存原始投票、响应时间与弃权原因，能为 reward calibration 和主动复标提供信息。

标注者可靠度并非常数。某人擅长代码却不擅长医学，统一全局权重会误配。按领域估计混淆矩阵需要足够重叠样本与 gold questions；gold 本身若含争议，也会把专家少数意见误判为低质量。

标注指南更新会形成时间漂移。旧数据按旧 rubric 产生，新数据按新 rubric 产生，把二者直接混合等于训练不一致目标。可版本化 rubric、对一组桥接样本用两版重复标注，估计规则变化后再决定重标、降权或分头建模。

pair 展示中先读哪个回答、是否展开完整内容、代码能否运行、引用链接能否打开，都会改变判断信息。界面版本应成为数据字段。高响应速度可能表示 pair 容易，也可能表示标注者草率；需要结合一致性与 gold 表现解释。

奖励模型若面对多语言，翻译标注与母语标注不等价。机器翻译会抹平语气、错误和文化偏好。应保留原语言评估，并让部署语言分布进入采样权重；英文总体准确率不能代表低资源语言。

### 10.4 展示偏差与随机化

回答位置、长度和格式会影响选择。若更强模型总在左侧，位置偏差会被 reward 当作内容信号。随机交换顺序并记录展示变量，可估计位置效应；同一 pair 双向展示能直接检查一致性，成本则翻倍。

候选由不同模型产生时，模型身份可能通过措辞或模板泄漏。标注者即使看不到名称，也可能识别风格。数据切分若随机按 pair，近似重复回答会跨 train/test，使泛化指标过高。应按 prompt、来源和时间去重切分。

长度偏差既可能是标注偏见，也可能反映任务真实需求。简单对 reward 做长度回归残差化会去掉两者。更可靠做法是构造长度匹配 pair、在同质量区间分析边际偏好，并由任务 rubric 明确何时简洁有价值。

## 11. Reward Model 的泛化与校准

RM validation accuracy 只衡量给定 pair 的排序。RL policy 会主动寻找高分输出，把输入推向训练分布边缘；需要校准、分布外检测与对抗验证共同评估。

### 11.1 Pairwise Accuracy 的盲区

accuracy 不看置信度，也不看错误代价。一个模型所有 pair 都预测 $0.51$，可能 accuracy 很高却无法提供稳定 reward margin；另一个在关键安全 pair 上犯少数高置信错误，整体 accuracy 仍漂亮。

按偏好强度、任务类别、长度差和来源分层报告 accuracy，配合 log loss、Brier score 与 calibration curve，能观察概率质量。部署 PPO 实际使用 reward 数值，margin 分布比符号更直接影响 advantage。

随机 pair test 还可能过于容易。强弱模型差距大的候选能快速获得高准确率，真正决定 RL 方向的是相近策略输出之间的边界比较。保留 near-tie、同模型多采样和最新策略 hard set，能更接近训练中的决策区域。

### 11.2 Reward 的绝对校准

BT 训练只约束差值，单回答 reward 的绝对水平需要锚点。可以固定 reference completion 的均值为零，或用一组质量等级明确的 anchor responses 拟合仿射尺度。anchor 必须跨版本保持稳定，才能比较不同 RM。

PPO 常对 batch reward whitening，使平移和整体正缩放影响减弱；KL coefficient、value target、reward clipping 和多来源奖励仍受尺度影响。若换 RM 后只看标准化 advantage，可能看不到原始 reward 分布已经漂移。

### 11.3 Ensemble 分歧的含义

多个 RM 用不同初始化、数据 bootstrap 或模型结构训练，预测方差可提示 epistemic uncertainty。若它们共享相同偏见与数据缺口，ensemble 会一致地错；分歧低不等于真实可靠。

对 policy 候选，记录 mean reward、分歧、与训练数据距离。高均值高分歧样本适合人工复核，高均值低分歧但分布外样本也不能自动信任。对抗搜索应同时寻找高分和模型间一致性漏洞。

将 pessimistic reward 写为均值减 $k$ 倍标准差，可抑制高不确定输出，同时偏向熟悉保守区域。它改变优化目标并可能阻止真正创新答案。更好的闭环是把高不确定区域送去标注，更新 RM 后重新评估。

### 11.4 Policy-induced Distribution Shift

初始 RM 数据来自 SFT 或若干基线模型，PPO 更新后输出分布逐渐变化。reward 提高可能来自真实质量，也可能来自进入 RM 外推区域。按训练轮次保留 policy 样本，画 reward 与人工胜率关系，可看到校准何时破裂。

数据回流若只标注 RM 高分样本，会产生选择偏差，低分但可能被误判的区域得不到纠正。混合随机样本、高分样本、高分歧样本与安全风险样本，才能同时估计总体表现和发现漏洞。

## 12. KL-Regularized RL 的最优策略

RLHF 常优化 reward 减 reference KL。这个目标不只是一项工程惩罚，它有闭式的 policy-space 最优解，能解释 KL coefficient 的作用。

### 12.1 单提示上的变分解

固定提示 $x$，对回答分布求解

$$
\max_\pi
\mathbb E_{y\sim\pi}[r(x,y)]
-\beta D_{KL}(\pi(\cdot\mid x)
\Vert\pi_{ref}(\cdot\mid x)).
$$

加入归一化乘子，对每个 $y$ 求导可得

$$
\pi^*(y\mid x)=
\frac{\pi_{ref}(y\mid x)
\exp(r(x,y)/\beta)}
{Z(x)},
$$

其中 $Z(x)=\mathbb E_{y\sim\pi_{ref}}\exp(r/\beta)$。最优策略是 reference 按指数 reward 重加权。$\beta$ 大时靠近 reference，$\beta$ 小时集中到高 reward 模式。

这个闭式解假设能在完整序列空间自由选择分布，神经自回归策略和有限 PPO 更新只能近似。reference 概率为零的序列在 forward KL 正则下仍不可获得，支持集由 reference 决定。

将最优解代回目标，可得最优值与 log-partition function 有关：

$$
J^*(x)=\beta\log
\mathbb E_{y\sim\pi_{ref}}
[\exp(r(x,y)/\beta)].
$$

它是 reward 的 soft maximum。$\beta$ 趋近零时接近支持集内最大值，$\beta$ 较大时接近 reference 下平均 reward 加小的方差修正。高 reward 尾部会被指数放大，这解释了 RM 极端误差为何危险。

有限候选集上可以精确计算这一定义，作为 PPO 与 DPO 类方法的玩具基准。给定 reference probabilities 和 reward，算出 $\pi^*$，再比较训练策略的 KL 与目标 gap。若小问题都无法靠近闭式解，应先检查 reward、KL 方向和优化符号。

reference 对高 reward 答案概率极低时，指数 reward 与 reference 质量竞争。增大 reward 或减小 $\beta$ 能克服低先验，但重要性采样更重尾，On-policy 探索也难遇到该答案。闭式存在不等于有限采样能找到。

若 reward 只在一个固定候选集合上定义，集合外输出没有可靠分数。神经 RM 给全空间外推，看似解决定义域，实际引入模型假设。KL 将策略限制在 reference 邻域，正是在减少对远距离外推的依赖。

### 12.2 KL Coefficient 与 Reward Scale

将 reward 乘常数 $c$ 等价于把有效温度 $\beta$ 除以 $c$。因此更换 RM、改变 reward normalization 或加入新奖励项后，原 KL coefficient 未必仍有相同含义。目标由比值 $r/\beta$ 决定。

自适应 KL controller 根据观测 KL 调 $\beta$，是在间接寻找满足某个距离预算的对偶价格。controller 太快会振荡，太慢则长时间偏离目标。target KL 本身也需根据任务质量与安全折中验证，不能由控制器自动决定。

### 12.3 Token KL 与 Sequence KL

自回归 sequence KL 可按链式规则分解为旧前缀分布下 token KL 之和。将采样 token log-ratio 作为逐 token 负奖励，其轨迹和是 sequence log-ratio；在当前策略采样下期望等于 forward sequence KL。

实现若对 KL reward 按 token 平均而环境 reward按序列给一次，会让正则相对强度随长度变化。使用 token KL 求和能对应 sequence KL；随后整个 policy loss 是否按 token mean，又形成另一层长度权重。

采样 log-ratio 的 token KL reward 可为负，表示当前策略在该 token 上比 reference 概率低。单条轨迹 KL 总和也可能为负，只有对当前策略完整期望才非负。将每 token 负值 clamp 到零会改变 KL estimator，并偏向只惩罚概率上升。

若希望低方差，可在每个旧前缀上计算完整词表解析 KL，它总是非负。前缀仍由采样策略产生，状态分布噪声保留。解析 KL 作为 reward shaping 时，每步对全部 token 概率求和，计算和显存成本明显增加。

reference 和 current 使用不同 tokenizer 时，token 级 log-prob 无法对齐。即使两者能给同一字符串概率，分词路径不同也需要 sequence-level 边缘化，通常不可行。RLHF reference 应共享 tokenizer 与模板，或重新定义可比较的行为单位。

chat template 变化同样改变条件分布。新 policy 用新模板、reference 用旧模板计算 KL，差异混入输入格式而非策略参数。模板必须作为模型版本的一部分冻结，想升级模板应建立新的 reference 基线。

### 12.4 Reference 更新会改变目标

固定 reference 提供稳定锚点。周期性把 reference 更新为当前 policy，可让局部探索更自由，却把全程目标变成一系列移动约束；模型可能通过许多小步远离初始 SFT，同时每步 KL 都很小。

若目标是限制与初始行为的总漂移，应始终监控 initial-reference KL；若只关心单轮稳定，可用 rolling reference。两者可以同时记录，不能把 rolling KL 小解释成总体保持能力。

## 13. 从 Reward 到 Advantage 的误差传播

RM 输出经过 KL shaping、长度处理、value bootstrap 和 GAE 才成为 PPO advantage。每层变换都可能改变尺度、偏差与时间归因。

### 13.1 Reward Model Error 的梯度投影

设预测 reward $\hat r=r^*+e$，策略梯度误差为

$$
\Delta g=
\mathbb E[e(x,y)\nabla\log\pi(y\mid x)].
$$

$e$ 平均为零仍可能与 score 相关，policy 会主动利用这种相关。RM MSE 衡量所有方向误差，真正危险的是沿策略可改变方向的误差协方差。

对当前 policy 高概率样本、更新后概率增幅最大的样本和高 reward 尾部单独做人评，能更直接观察可利用误差。随机 validation 主要衡量旧分布平均性能。

可以把 policy 更新前后的概率变化作为审计权重。样本 $y$ 的 log-prob 增量大且人工效用下降，说明 reward error 正好沿可优化方向；分数误差大但概率未变化，对当前训练影响较小。这个视角把静态 RM 误差与动态策略风险连接起来。

离散候选集上可精确计算 RM reward 与人工效用各自诱导的指数重加权分布，比较两者 total variation 或 KL。差异随温度变化：强 KL 时策略靠近 reference，漏洞影响小；温度降低后高分尾部主导，微小排序错误也会被放大。

RM ensemble 的均值误差与分歧可以一起投影到 score。高分歧样本若 score norm 很小，短期影响有限；中等分歧但 score norm 巨大，反而值得优先标注。主动学习 acquisition 可使用预期梯度影响，而非只按 reward variance 排序。

reward error 还会通过 critic 平滑传播。某条终局回答被高估，value 网络可能把其前缀模式普遍高估，随后许多尚未完成的轨迹获得正 advantage。审计不能只查最终作弊文本，还应查 critic 是否把漏洞泛化到相似前缀。

### 13.2 Reward Whitening 的随机目标

batch whitening

$$
\tilde r_i=\frac{r_i-\bar r}{s_r+\epsilon}
$$

让每个样本 reward 依赖同批其他样本。平移去掉 batch 常数，理论上类似 baseline；随机标准差改变每批整体步长，并让任务混合影响权重。

按 prompt 组内 whitening 消除 prompt 难度，优化相对回答；全局 whitening 保留部分跨 prompt 差异。组大小小、奖励全同时，标准差噪声或 $\epsilon$ 会主导。应报告 whitening 前后各 reward 分量分布。

运行均值 whitening 使用历史统计，降低 batch 间抖动，却在 policy 和 RM 分布变化时滞后。切换 reward 版本后旧均值方差可能完全失效，应重置、仿射迁移或经过 warm-up。直接沿用会让早期 advantage 尺度异常。

全局 whitening 把不同任务放在同一尺度，大方差任务对标准差贡献更大。按任务分别 whitening 让任务梯度尺度接近，但抹去业务设定的绝对奖励差。可先按可解释单位校准各 reward，再使用温和全局归一化。

对组内只有两个回答的 pair，中心化后优势必然一正一负，差值大小由 reward margin 决定；再除组标准差后，除 tie 外幅度几乎固定，RM 对偏好强度的表达被丢弃。是否需要这种不变性，应由目标决定。

whitening 统计必须 detach，且只用有效样本。把 padding、无 reward 的失败样本或跨 worker 局部统计混入，会改变中心。失败样本若代表真实低效用，应赋明确定义的 reward，而不是靠 mask 静默删除。

### 13.3 Value Error 沿 GAE 传播

若 $V_\phi=V^\pi+e_t$，TD error 误差为 $\gamma e_{t+1}-e_t$。GAE 对它做 $(\gamma\lambda)^l$ 加权和。$\lambda$ 越小越依赖局部 value 准确性，越大越依赖长程实际 reward。

终局 RM reward 很稀疏时，早期 token advantage 主要由 critic 预测的前缀价值变化决定。critic 学错某类前缀，PPO 可系统强化表面模式。用独立 rollout 或过程验证检查前缀 value calibration，比只看终局 RM 分数更有诊断力。

### 13.4 多奖励项的权重

总 reward 可能包含 helpfulness、safety、format、verifier、长度和 KL。线性加权

$$
r=\sum_kw_kr_k
$$

选择一个 Pareto 折中。各项相关、尺度与噪声不同，权重不能只按均值大小设置。某项稀有但损失巨大时，平均线性权重可能无法提供硬保护。

分别训练 value head 可看到每项 advantage 与梯度冲突，再按目标权重组合；单一 value 只拟合总和，难以追踪哪个奖励驱动更新。无论采用哪种结构，最终都要报告分项指标，避免总 reward 上升掩盖安全或能力退化。

多 head critic 还能为每项使用不同折扣与时间边界：即时格式成本、终局正确性和长期用户结果的 horizon 不同。把它们强行用同一 $\gamma,\lambda$ 混合，会让某些信号传播过远、另一些传播不足。组合 actor advantage 前再按业务权重与单位对齐。

梯度冲突可用 $g_i^Tg_j$ 观察。简单线性加权忠实于声明的总 reward，即使梯度冲突也只是多目标本质；PCGrad 等投影会改变这个目标，可能改善均衡但需要新解释。不能把投影称为纯粹消除噪声。

硬规则 reward 往往尺度离散、RM reward 连续。某次明确违规若只在 batch whitening 后成为普通负值，约束力度受同批其他样本影响。不可妥协事件更适合独立 cost constraint 或动作屏蔽，而非和风格分数一起标准化。

reward 项相关时，分别调权重不等于独立控制。例如长度与 RM helpfulness 高度相关，增加长度惩罚同时改变 RM 分布。构造长度匹配评估集和因果干预，才能估计权重的净效果。

## 14. 标注预算怎样分配

人类偏好是流水线中最昂贵、最稀缺的信号。随机标注易估计总体表现，却把大量预算用在差异明显的 pair；只标难例能改善决策边界，又会失去总体校准。数据设计需要在估计与学习之间分工。

### 14.1 随机样本用于无偏评估

从部署 prompt 与当前 policy 随机抽样，能估计总体胜率、违规率与长度分布。只要保留抽样概率，分层过采样后也可加权还原部署指标。这个流量不应由 RM 分数筛选，否则评估会遗漏模型自信但错误的区域。

估计小概率安全事件需要大样本。零次违规不表示概率为零；若 $n$ 个独立样本均无事件，简单 rule-of-three 给 95% 上界约 $3/n$。希望证明风险低于万分之一，几百条标注远远不够。

同一 prompt 的多个回答相关，独立单位仍是 prompt 或用户会话。把所有 pair 当独立样本会低估置信区间。评估切分还应按用户、模板与时间分组，防止近重复泄漏。

### 14.2 主动采样用于提高 RM

RM 最不确定、ensemble 分歧大、不同候选分数接近的 pair 对决策边界最有信息。主动采样优先标这些样本，能用较少预算改善排序；采样分布随 RM 变化，训练 loss 不再代表部署平均风险。

只按不确定性采样容易集中到本身含糊、标注者也无法判断的 pair。结合可判定性、任务价值与覆盖约束更合理。标注后长期保持高分歧的样本可能反映价值冲突，应进入 rubric 修订或多偏好建模，而不是无限复标。

### 14.3 重复标注与噪声估计

给一部分 pair 多人独立标注，可估计一致率、标注者偏差和任务难度。重复比例太低时，模型无法区分 reward error 与标签噪声；全部重复又降低覆盖。可先随机重复建立基线，再对分歧和高风险样本增加票数。

多数票提高稳定性，但会抹去少数群体偏好。安全 rubric 若有明确事实标准，可由专家仲裁；开放风格偏好更适合保留分布。数据 schema 应保存每张票和标注者元数据，而非只留聚合赢家。

### 14.4 候选生成决定可学习上限

偏好数据只能比较已生成候选。若两个回答都很差，标注者被迫选“较不差”的一个，RM 会学到局部排序却看不到真正好答案。混合不同温度、不同 checkpoint、搜索结果和人工示范，能扩大质量范围。

候选差异过大，标注容易但提供的边界信息少；差异过小，噪声高。合理数据同时包含 anchor pair、near-tie pair 与安全反例。每类比例应和用途对应：anchor 做尺度与基础质量，near-tie 改善 policy 附近排序，反例保护尾部。

候选生成温度决定难度与覆盖。低温回答彼此相似，pair 常接近 tie；高温扩大差异，也产生大量明显低质样本。可按任务动态设置温度，并记录完整采样概率。后续若用这些数据做离策略分析，缺少行为分布会失去校正依据。

best-of-N 候选经过 RM 预筛后再交给人，会让标注集中到 RM 已偏好的区域。这样可提高高质量 pair 密度，却难以发现 RM 将好回答打低的 false negative。保留一部分不经预筛的随机候选，才能估计筛选召回。

人工示范与模型候选混合时，来源标签可能与质量高度相关。RM 学会识别人工风格后，在训练集上排序很好，policy 只需模仿表面风格就能提分。让强模型、人工和不同模板产生风格交叉，减少来源捷径。

pair 构造也决定权重。一个 prompt 生成 $K$ 个回答后枚举全部 $K(K-1)/2$ 对，会让该 prompt 权重平方增长，且 pair 高度相关。随机选边、构造排序 loss 或先在 prompt 内归一化，分别对应不同统计目标。

主动采样循环中，RM 每次选择下一批数据，最终训练集不是独立同分布。普通 validation 若也从这个池随机切分，会高估边界附近性能。固定独立随机 test 与时间向前 test，能分别衡量部署平均和对新 policy 的迁移。

## 15. Reward Hacking 的因果诊断

RM 分数上涨、人工质量下降时，不能只列举表面模式。需要判断 policy 利用了哪条评分路径，漏洞来自数据、模型、聚合还是部署变换。

### 15.1 相关特征与因果特征

训练数据中，长回答可能更好，RM 学到长度相关。policy 随后添加重复解释提高分数，长度相关仍存在，真实质量却未改善。观察相关性无法区分“长度携带内容”与“长度本身被奖励”。

可做配对干预：保持核心答案不变，只增删冗余段落、格式标记或引用；也可保持长度相近，替换关键事实。若 RM 对无意义变化敏感、对事实变化迟钝，就找到了可利用路径。干预集应独立于 RM 训练。

### 15.2 Gradient-based 与搜索式攻击

policy optimization 本身就是对 RM 的黑盒或梯度引导搜索。可在正式 RL 前用 best-of-N、遗传改写或可微 token 优化寻找高分回答，再由人工审计。攻击找到的模式进入 hard-negative 数据，并保留独立复测集。

若每轮把全部攻击样本加入训练，RM 可能记住具体模板而非学会原则。对攻击做语义变体、跨任务迁移和时间 holdout，能检查修复是否泛化。新的 policy 仍可能找到未覆盖漏洞，红队不是一次性步骤。

### 15.3 独立 Judge 为什么仍会共错

使用另一个模型评估能降低直接训练泄漏，但两个 judge 可能共享预训练数据、架构和表面偏好。它们会一致偏爱流畅冗长文本，也可能共同漏掉专业事实错误。模型间一致不是独立证据的充分条件。

规则验证、可执行测试、检索核对、专家标注与用户结果来自不同信号链，更能形成互补。不同 judge 的分歧样本应重点复核；一致高分但分布外的样本同样需要抽查。

### 15.4 Hacking 与目标错设的区别

如果 reward 明确鼓励简短回答，policy 变短并非 hacking；若任务真正需要细节，问题在目标权重或 rubric。hacking 更准确地指代理 reward 与期望效用存在可利用差异。二者都表现为“分数上升、体验变差”，修复位置不同。

目标错设需修改评价标准与权重，模型漏洞需补数据或改架构，policy 实现错误则需修 ratio、mask 或 reward 归属。将所有问题都归为 reward hacking，会让团队在错误层面添加补丁。

hacking 还可能发生在 tokenizer 与解析器接口。RM 从截断文本评分，policy 把关键内容放在截断后；结构化输出解析器只读取第一个字段，policy 在未读取区域堆高分短语；Unicode、空白和不可见字符也可能让人类视图与模型输入不同。审计必须使用生产预处理链。

如果 RM 只读取最终回答，policy 可在隐藏思维、工具调用或引用中操纵环境而不影响评分；若 RM 读取完整轨迹，又可能奖励冗长过程或泄露内部信息。评分可见范围应与真正关心的行为边界一致，并逐段标记哪些内容面向用户、工具和裁判。

多 reward ensemble 取均值会降低独立噪声，却可能让一个极端高分模型抵消其他模型警告。取最小值更保守，也容易被某个过度拒绝模型支配。分歧触发人工复核、均值用于常规优化、硬规则处理明确违规，是更可解释的分工。

修复漏洞后需要检查能力侧效应。对“总是先道歉”这类模式施加负样本，可能连合理道歉也被压制。最小对照应包含该模式有益与有害的两类上下文，让 RM 学条件关系而非关键词黑名单。

policy 对 RM 的利用强度随 KL coefficient 和训练步数增加。短试验没有出现 hacking，不代表长程安全。画人工质量相对 RM reward 的校准曲线随 KL 或训练轮次变化，可以找到代理开始失真的区域，用作停止或数据回流阈值。

## 16. 在线数据回流与版本闭环

RLHF 不是训练完 RM 再永久使用。policy 改变输出分布，新的偏好数据更新 RM，RM 又改变下一轮 policy。版本关系不清会让实验无法复算。

### 16.1 四类版本必须绑定

每条 rollout 至少绑定 policy、reference、reward model 和 tokenizer/template 版本。policy 决定行为概率，reference 决定 KL，RM 决定环境 reward，tokenizer 决定动作序列。任何一项变化都会改变 advantage。

重算新 RM reward 可以比较裁判变化，但不能把旧轨迹变成新 policy 的 On-policy 数据。重新计算 log-prob 可得到 ratio，状态分布与支持覆盖仍来自旧 policy。数据新旧要从行为和奖励两个轴分别描述。

### 16.2 回流策略与选择偏差

只回流线上被用户投诉的样本，会高估失败类型比例；只回流高 RM 分样本，会遗漏低分误判。随机流量用于总体估计，触发流量用于高价值修复，两者应带来源标签并采用不同权重。

policy 生成失败或超时的样本若被管线丢弃，RM 数据只包含成功完成者，形成 survivorship bias。超时、拒答、解析失败都应作为可标注结果保留，或至少统计缺失概率。

线上用户反馈也有选择性。极满意和极不满意用户更愿意评分，中性用户沉默；复杂任务耗时长，反馈返回更晚。把已返回评分直接当随机样本会偏向极端和快速请求。随机邀请、记录曝光与响应概率，可支持加权估计。

隐式反馈如复制、继续追问、会话离开和任务完成，需要因果解释。用户复制可能表示答案有用，也可能为了转发错误；继续追问可能表示投入，也可能表示首答失败。单个代理指标不宜直接成为 reward，应通过受控实验或多信号模型校准。

回流样本若包含当前 policy 明显特征，RM 会逐渐适应该版本。下一版 policy 又寻找新边界，形成追逐。保留跨版本固定 anchor 和旧漏洞回归集，可以测量修复是否遗忘；只看最新分布会不断丢掉历史约束。

人工标注周期慢于 policy 更新时，若连续训练多版 policy 再统一收标，样本来自多个行为分布。每条数据绑定生成版本，RM 可训练全部数据，PPO On-policy 阶段则只能使用当前 rollout。数据湖与优化 batch 的“可复用”标准不同。

删除低质量反馈不能只按 RM 当前分数，因为会形成自确认循环。使用独立规则、标注一致性和来源质量筛选，并抽查被删除样本。否则 RM 不喜欢的反例被清除，validation 也越来越容易。

### 16.3 RM 更新后的回归门槛

新 RM 上线前，要在固定历史集、最新 policy 集、攻击集和随机部署集分别验证。总体 pairwise accuracy 提高却在最新 policy 上下降，意味着更新没有覆盖当前决策区域；攻击集提高、随机集下降，则可能过拟合补丁。

四类集合不能互相替代。固定历史集衡量遗忘和版本可比性，最新 policy 集衡量当前边界，攻击集衡量已知漏洞，随机部署集给总体估计。为每类预设最低门槛，比将它们混成一个加权平均更能保护尾部。

RM checkpoint 选择也会对 validation 过拟合。训练 epoch、数据混合和正则尝试越多，最高验证准确率越乐观。隐藏 test 只在最终候选上运行，或使用时间后移的新标注集，可减少选择偏差。

RM 推理精度、量化和批处理实现可能改变分数。训练时 FP32 模型通过评估，部署量化服务的 pair 排序可能翻转，特别是 near-tie 样本。发布前在真实服务栈重放 anchor、边界与极端长度样本。

长输入截断策略必须一致。若 RM 只保留开头，policy 可把问题内容放在后半；只保留结尾则可能忽略提示约束。提示与回答分别预算 token，并报告截断率和截断位置，避免“完整回答分数”实际只看局部。

reward 尺度漂移还需单独检查。对同一 anchor responses 比较新旧分数，拟合仿射关系与残差。若主要是平移缩放，可调整 PPO coefficient 与 value 初始化；若排序结构变化，需要视作新目标重新校准。

新 RM 的 tokenizer 或模板变化时，旧 anchor 必须经过对应预处理重算。输入截断长度改变会让分数差异看似语义漂移，实际只是可见文本变化。保存渲染后的精确 RM 输入，才能区分模型与管线。

reward replay 可以把历史 policy 样本同时送入新旧 RM，观察各任务的 rank correlation、margin 和 top-tail 交集。总体相关高但 top 1% 交集低，PPO 最关心的高分区域已经改变，不能只做仿射校准。

critic 从旧 RM 训练出的 value head 也需处理。若新旧 reward 近似仿射，可相应变换 value 输出；若结构变化，继续沿用会给早期 GAE 系统偏差。冻结 actor 先让 critic 在新 reward 上校准若干步，是一种过渡方式。

RM 回滚同样要版本化。发现新 RM 漏洞后恢复旧 RM，policy 已经在新分布上移动，不能假设旧 RM 仍校准。应在当前 policy 样本上复测旧 RM，必要时连 policy 一起回滚到兼容 checkpoint。

数据删除或合规要求也会影响版本链。移除某批标注后重新训练 RM，差异可能扩散到 policy。训练数据 manifest、样本 lineage 与模型 hash 使影响分析成为可能；只有汇总数据量无法追踪具体来源。

### 16.4 何时停止在线 RL

训练 reward 持续上涨不是继续的充分理由。人工胜率进入平台、RM 与人工相关下降、KL 或长度持续漂移、关键能力退化、有效 advantage 比例过低，都可成为停止条件。

停止规则应在实验前定义，避免追逐随机峰值。保存每轮 policy 并用 validation 选 checkpoint，再在未使用 test 上评估。最新 checkpoint 不一定最好，RM 最高分 checkpoint 也不一定最好。

## 17. 安全约束与多目标偏好

helpfulness、harmlessness、honesty 与风格常彼此冲突。压成单一 reward 简单，却隐藏权重和不可接受边界。

### 17.1 线性加权与 Pareto 前沿

多目标 reward $r=\sum_kw_kr_k$ 选择 Pareto 前沿上的一个点。改变 $w_k$ 会移动折中，单次训练无法说明其他点。用多个权重训练或离线评估近似 frontier，可看到提升 helpfulness 需要牺牲多少安全与简洁。

不同指标尺度必须校准。一个标准差为 100 的 reward 即使权重小，也可能支配总和。按统计尺度归一化只是数值处理，业务交换率仍需由效用定义。

### 17.2 硬约束与 Lagrangian

对安全成本 $J_C\le d$，可优化

$$
J_R-\lambda(J_C-d),
\qquad
\lambda\ge0.
$$

乘子根据违规程度更新，自动调整成本价格。期望约束只控制平均，无法保证每次输出安全；高风险动作还需规则屏蔽、拒答策略或人工升级。

如果 cost 是二元违规，平均约束 $E[C]\le d$ 直接对应违规概率上界；前提是检测器无误。实际安全 RM 有漏报和误报，约束的是预测违规率。用人工标注估计检测器 confusion matrix，可对真实风险做区间校正，但分布漂移后矩阵也会变化。

CVaR 约束关注最坏尾部损失，适合严重程度连续的风险。估计小尾部需要大量样本，batch 中只有少数事件时乘子梯度方差极高。专门过采样风险场景可提高信息量，再按采样概率还原部署风险。

多约束分别设置乘子比把所有 cost 预先加权更透明。某项长期不活跃时乘子接近零，某项频繁违规时上升；不同乘子尺度仍受 cost 单位影响。日志应展示原始 cost、阈值、乘子和对 actor 梯度贡献。

约束 critic 若和 reward critic 共享骨干，稀有风险梯度可能被大量普通 reward 样本淹没。分头输出、风险样本加权或独立网络能改善，仍要防止训练采样权重改变部署风险估计。

cost critic 与 reward critic 都会有误差。稀有违规样本少时，平均准确率掩盖漏报；需要风险条件评估、保守上界与主动红队。不可行阈值会让 $\lambda$ 持续增大，policy 几乎只优化成本。

### 17.3 条件化偏好策略

若用户偏好差异合理，可让 policy 条件于明确偏好参数或风格指令，而非用单一平均 reward 抹平。训练数据要覆盖条件与回答的交互，防止模型只学表面标签。

安全底线不能完全交给用户条件。可将不可违反约束与可调风格分层：先保证约束，再在可行集合内优化个性化效用。模型和产品界面都需明确哪些维度可选。

### 17.4 拒答的双重角色

拒答能降低安全风险，也可能成为逃避困难问题的捷径。若 reward 对违规惩罚远大于有帮助奖励，policy 会扩大拒答范围。按风险类别统计正确拒答、过度拒答与漏拒，才能看到平均安全分背后的行为。

构造安全但可回答的对照样本，是压制过度拒答的关键。只收集明显危险与明显安全样本，决策边界附近没有监督，RM 容易依赖关键词。最小对比 pair 应只改变真正决定风险的条件。

有些请求可在添加限制后回答，例如提供高层原理而不提供危险步骤。二元“回答或拒答”reward 无法表达这种部分帮助。将响应策略分为直接回答、安全改写、澄清和拒答，并针对任务风险标注适当性，能给 policy 更细的可行行为。

安全判定存在上下文依赖。相同词汇在教育、医疗急救、恶意操作和虚构创作中含义不同。只用关键词平衡数据会制造表面对照，真正有效的 pair 要保留主题相似并改变意图、权限或细节层级。

约束项也会被利用。若“包含免责声明”提高安全分，policy 可能先给危险细节再附免责声明；若拒答长度受惩罚，模型可能用隐晦短语绕过。规则应评价结果行为而非单一格式，红队需针对组合漏洞。

安全与 helpfulness 的 critic 可以分开训练，让 policy update 显示两条梯度。它便于诊断冲突，也可能因两个 critic 校准尺度不同而误配权重。用固定 anchor 和人工 Pareto 对照校准分数，比分别 whitening 后直接相加更稳妥。

个性化偏好还涉及默认值。用户未声明风格时，policy 使用哪个群体先验是一项产品决策；把训练集多数偏好当自然默认会放大样本不均衡。默认与可调选项都应通过明确评估集验证。

## 18. 端到端数值审计

RLHF 跨越 SFT、偏好标注、RM、rollout、reward shaping、critic 和 PPO。单阶段指标正常不代表接口正确；一条样本必须能从原始对话追到最终梯度。

### 18.1 从 Pair 到 RM Gradient

取一对 reward 为 $r_w=1.2,r_l=0.4$，差值 $\Delta=0.8$，偏好概率 $\sigma(0.8)\approx0.690$。负对数似然

$$
\ell=-\log\sigma(\Delta)
$$

对差值导数为 $\sigma(\Delta)-1\approx-0.310$。因此梯度上升赢家分数、下降输家分数，大小相同方向相反。若两回答共享大量 token，梯度在共享表示上会叠加或抵消。

交换 winner/loser 后差值符号和梯度应反转；给两个分数同时加常数，loss 与梯度不变；复制 padding 不应改变 sequence representation 与分数。这三条不变量能抓到标签顺序、mask 和 pooling 错误。

多 pair batch 若按 token 数归一化，会让长回答 pair 权重不同；BT loss 天然以 pair 为单位，通常应先得到每 pair 标量再平均。若想按标注置信度加权，应显式加入权重，而不是让长度意外承担权重。

### 18.2 从 Sequence Reward 到 GAE

设四 token 回答的 KL reward 为 $(-0.01,-0.02,-0.01,-0.03)$，RM 终局分数为 $1.0$，则末尾 token reward 为 $0.97$，前三项保持负 KL。给定 value $(0.2,0.3,0.4,0.5)$ 和终态零，可逐步计算 TD error，再反向递推 GAE。

这个小例应分别运行 EOS 终止与长度截断版本。EOS 末端 bootstrap 为零；截断若任务继续，使用 final observation value。只改变边界标志，前面 advantage 会因递推整体变化。

RM reward 若散射到 padding 或 EOS 后位置，reward 总和和 GAE 都会异常。检查每条序列 environment reward 总和等于原始 RM 分数、KL reward 总和等于 sequence log-ratio 乘系数，是直接守恒测试。

### 18.3 从 Advantage 到 PPO Update

保存 rollout 时的 old log-prob，更新前 current 模型与 old checkpoint 相同时 ratio 应为一。手工设置一个正 advantage token 和一个负 advantage token，运行单步更新后，前者 log-prob 应上升、后者下降，前提是未触发共享参数反向影响。

加入 clip 边界四种情况，核对获利越界区域梯度为零、反向越界保留恢复梯度。再开启 value loss、entropy 和 weight decay，观察平台样本 ratio 仍可能变化，从而区分 PPO actor clip 与总网络更新。

reference log-prob 与 old log-prob 要用不同张量。故意交换后，单元测试应失败：PPO ratio 不再在更新前等于一，KL reward 也不再对应固定 reference。变量命名和版本哈希应让这种错误难以发生。

### 18.4 分布式 Reduce 的一致性

将同一全局 batch 切成不同 worker 数、microbatch 大小和 padding 组合，全局 reward 均值、advantage 统计、policy loss、value loss 与梯度应在容差内一致。若不一致，常见原因是本地 mean 后等权 all-reduce。

prompt 组内 baseline 需要让同组回答位于可共同聚合的范围。组被拆到 worker 后，各 worker 本地求均值会得到不同 baseline。应按 group id 聚合 reward，或在数据分片前完成组统计并广播。

全局 advantage whitening、gradient norm 与 KL early stop 都需要跨 worker 统计。OOM 重试若丢弃某些长序列，会改变任务分布；记录每个样本是否实际进入 optimizer，不能只记录 rollout 已生成。

## 19. 评估、发布与回滚

RLHF 最终改变的是面向用户的条件分布。发布判断必须覆盖平均质量、尾部风险、能力保留、校准与运行稳定性，而不是只看 RM reward。

### 19.1 Pairwise Win Rate 的统计口径

对同一 prompt 比较新旧策略，可将胜、负、平分别记为 $1,0,0.5$，计算平均胜率。prompt 是独立抽样单位；同 prompt 多个候选先组内聚合，再估计置信区间。

顺序随机化和盲化减少展示偏差。评审模型担任 judge 时，还应交换 A/B 位置复测，报告 position consistency。长度匹配子集、领域切片和安全切片可以解释总体胜率来源。

胜率依赖对手。相对 SFT、上一版、当前线上版和强外部基线会得到不同数字。版本链应固定主要对手，同时保留绝对任务指标，防止两个模型一起退化却相对胜率稳定。

### 19.2 能力保留与 Regression Suite

RLHF 可能提高对话偏好，却降低代码、数学、事实问答或多语言能力。固定能力集应在每个 checkpoint 运行，指标使用任务自身判分，不依赖同一 RM。

SFT mixing、KL reference 和较小更新能降低遗忘，但不能替代测量。某能力只在少量 prompt 上退化时，总平均不明显；按能力类别设置不可退化阈值，并保留代表性失败案例。

污染风险也要控制。RM 或偏好数据若含 benchmark 答案，policy 可通过 reward 间接过拟合。时间切分、隐藏测试与生成式变体能降低泄漏。只看公开 benchmark 高分不能证明泛化。

### 19.3 分阶段发布

离线验收后可进入 shadow、内部用户、小流量和逐步扩量。每阶段监控任务成功、拒答、违规、长度、延迟与用户反馈，并与固定旧策略对照。流量分配要随机化或记录倾向概率，避免用户群差异污染比较。

线上指标延迟时，先用短期 guardrail 决定是否暂停，成熟 cohort 再判断长期效果。不得把未完成会话默认记为失败或成功。发布日志绑定 policy、RM、reference、template 和路由版本。

回滚需要旧模型及其完整推理配置。只恢复权重而保留新 tokenizer、system prompt 或 safety rule，不是回到旧策略。外部检索索引和工具版本也会改变行为，应纳入发布单元。

灰度实验中，新旧模型收到的用户群应尽量随机。按设备、地区或请求难度路由时，原始指标不可直接比较；已知倾向概率可加权，未知路由逻辑只能依赖更强假设。实验分桶键与实际路由日志必须保留。

用户跨桶污染也会发生：同一用户多次请求看到不同模型，反馈受前次体验影响。以用户或会话为随机化单位可减少干扰，代价是样本聚类更强。置信区间要按随机化单位计算。

发布指标多时，频繁查看并在任一好转时宣布成功会增加假阳性。预先指定主要指标、最小效果和观察窗口，安全 guardrail 则单独采用快速停止规则。长期指标未成熟前不做最终胜负判断。

回滚后的数据仍有价值。异常版本产生的失败样本可用于 RM 与回归集，但不能未经校正混入 On-policy PPO。将事件时间、模型版本、裁判版本和处理结果串成 lineage，后续才能重建因果链。

部署后还需监控分布漂移。prompt 主题、语言、工具和攻击模式变化时，离线 test 覆盖会下降。随机抽样人工复核提供持续基线，触发式红队负责新风险；两者结合才能判断下一轮数据回流优先级。

线上 A/B 的日志丢失也可能有选择性。生成失败、内容过滤或用户快速关闭时，完整响应与评分未写入，恰好漏掉高风险样本。监控从请求到生成、展示、反馈各阶段的漏斗，并把缺失率作为 guardrail。

延迟与成本是质量的一部分。RLHF 可能鼓励更长回答和更多工具调用，使离线胜率提高、服务延迟恶化。固定 token budget 的离线比较之外，还应在真实吞吐下报告端到端延迟、计算与任务成功，避免把额外计算伪装成纯模型能力。

缓存会污染在线实验：同一 prompt 命中旧模型缓存，即使被分到新桶也看到旧回答。缓存 key 必须包含模型和模板版本，或在实验期关闭共享缓存。检索与工具结果的缓存同样影响两组环境一致性。

回滚阈值应区分随机波动和严重事件。平均指标可等待统计证据，单次高严重安全事件可能立即停止。规则要在上线前定义，事件发生后临时改变标准会引入人为选择。

最终发布记录应能回答：模型由哪份 SFT 起点、哪版 preference data 和 RM 产生，使用何种 KL/reference 与 PPO 配方，通过哪些离线、红队和线上门槛，当前回滚目标是什么。RLHF 的可信度来自这条可追踪链，而不只是最终 checkpoint 文件。

完整 lineage 还应覆盖随机种子与采样配置。同一 policy 在温度、top-p、最大长度和工具权限变化后产生不同候选分布，RM 胜率与线上体验都会变化。模型版本号相同不能代表行为版本相同，生成配置应拥有独立 hash。

偏好数据的授权与隐私边界也会影响可复现性。某些样本到期删除、敏感字段脱敏或只允许聚合使用，后续 RM 无法按原数据重训。manifest 需记录许可状态与变换，模型卡则说明哪些评估受数据不可用限制。

人类反馈中的个人信息不应直接进入训练文本。脱敏器可能误删任务关键信息，也可能漏掉隐私。抽样审计脱敏前后语义、按实体类型报告召回，并确保 reward 不鼓励模型复述训练中的唯一标识。

标注者安全同样属于流水线质量。高风险内容需要分级、预警、跳过和专业支持；允许弃权不会只保护标注者，也减少随意点击产生的噪声。弃权率按任务类别统计，可反向指出 rubric 或任务分派问题。

跨团队交接时，公式文档与数据 contract 要对应。`reward` 字段究竟是原始 RM、加 KL 后总 reward 还是 whitened value target，若只靠变量名无法判断，最容易在重构时混用。每个张量保存单位、shape、mask、版本和是否 detach 的定义。

吞吐优化也可能改变统计目标。动态 batching 按长度分组，失败重试偏向短样本，RM 服务超时丢弃长回答，都会重加权数据。监控从 prompt 抽样到最终 optimizer 的各层保留率，才能还原实际训练分布。

高吞吐 rollout 使用旧 policy 副本时，版本 lag 应和任务长度一起报告。长程工具任务更晚返回，天然更离策略；若按 lag 丢弃，它们又更少进入训练。分任务设置队列或同步窗口，可以减少系统速度造成的能力偏置。

成本核算不只记录 GPU 小时。每个有效偏好 pair 需要多少候选、多少被过滤、多少重复标注；每个 PPO 有效 advantage 需要多少 rollout；每点人工胜率提升消耗多少标注和环境交互。这些量能判断瓶颈在数据、RM 还是 policy 优化。

当边际收益下降时，继续加 PPO 步数可能不如补标注、改 rubric 或提升 SFT。比较三种干预在固定预算下的收益曲线，能避免把所有问题推给最终优化器。RLHF 是一条闭环，最弱接口决定整体上限。

一次失败复盘应从现象回溯：哪些用户和任务受影响，输出通过哪个 reward 路径得分，RM 在何种数据上学到该路径，候选生成为何缺少反例，发布门槛为何没有捕捉。把答案转为新的随机评估、hard set、数据字段或单元测试，才完成闭环。

反例进入训练后仍保留不可训练副本，用于判断修复是否只是记忆。若每次漏洞样本都被全部加入 RM train，回归集会迅速失去独立性。语义变体、时间后移样本和不同攻击者生成集能维持检验强度。

最终模型可能通过蒸馏、量化或合并 adapter 部署。部署转换后应重新跑 reward、KL、能力与安全评估，因为 logits 微小变化能在低温解码中改变输出。训练 checkpoint 通过并不自动覆盖转换产物。

这套流程让每层假设保持可见：人类比较表达什么，RM 能泛化到哪里，KL 把 policy 限制在哪个邻域，critic 如何传递误差，PPO 怎样移动分布，独立评估又如何否证训练指标。逐层检查这些假设，RLHF 的改进才有可解释的依据。

模型上线后的用户行为还会反过来改变数据。更好的回答减少追问，日志里“后续消息数”下降；若旧 reward 把长会话当参与度，新模型反而被判低。任何隐式指标都要随产品行为重新校准，历史相关关系不能永久沿用。

同样，路由器可能把简单请求交给小模型、困难请求交给 RLHF 模型，使线上样本比离线集更难。模型平均成功率下降可能来自路由变化。评估日志要带路由决策与倾向概率，固定无路由集用于测模型自身能力。

工具生态变化也会移动目标。搜索质量提高后，旧 policy 的保守拒答不再最优；接口字段变化后，RM 仍可能偏爱语义正确但无法执行的调用。工具版本与可用权限应进入 rollout 环境版本，回归测试覆盖真实执行结果。

对长程任务，单轮 pairwise 最终回答偏好看不到中间资源消耗与可恢复性。可以同时标注任务是否完成、步骤是否可验证、失败能否恢复和使用多少工具预算，再决定哪些是 reward、哪些是约束。只将所有维度压成一个“更喜欢哪个”，后续很难定位策略为何变化。

文档中的公式也需要和代码口径同步。KL 是求和还是均值、reward 在哪个 token 注入、GAE 遇到截断如何 bootstrap、PPO old policy 冻结多久，这些细节一旦变化就应更新版本说明。否则同名“RLHF”实验实际优化不同目标，结果无法积累。

最小可复现实验包应包含少量脱敏 rollout、渲染后的 RM 输入、原始与整形 reward、old/reference log-prob、value、advantage、mask 和最终 loss。它不需要暴露完整训练数据，却能让接口与公式逐项核对，并在框架升级后重放。
