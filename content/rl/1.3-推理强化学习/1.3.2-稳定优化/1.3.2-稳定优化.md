# 稳定优化

组内优势估计解决了「没有 critic 时怎样构造学习信号」，却没有保证训练会稳定。推理回答往往很长，长度差异大，奖励又常由多个验证器共同给出。一个看似普通的平均操作，就可能决定短答案还是长答案获得更多梯度；一次裁剪，可能保护策略不发生剧烈漂移，也可能让真正有用的正向更新被截断。DAPO、GSPO、GMPO 与 GDPO 的共同主题不是发明四套互不相干的算法，而是重新检查样本、序列、token 与奖励维度之间的聚合边界。

## 稳定到底指什么

训练曲线没有 NaN 只是最低要求。更完整的稳定性至少包含四层。数值稳定要求 log-prob、importance ratio 和优势归一化不溢出；优化稳定要求更新幅度、KL 与裁剪比例处于可解释区间；数据稳定要求每一步看到的难度、长度和奖励分布没有因过滤规则突然改变；能力稳定则要求目标 benchmark 上升时，已有能力不会大面积退化。

这些层次不能靠一个 loss 数值概括。比如平均奖励上涨，可能只是动态采样移除了困难题；KL 很小，可能是大量 token 被裁剪后没有梯度；训练长度变长，可能是模型学会更完整地推理，也可能是序列聚合给长回答更高权重。因此每个算法都要从「它改变了哪一个统计口径」入手。

## DAPO：配方是一体的

DAPO 经常被缩写成非对称裁剪，但它实际把动态采样、clip-higher、token-level policy-gradient loss 和 overlong reward shaping 组合在一起。动态采样排除全对或全错、没有相对信号的组，让算力集中到可学习题目；非对称裁剪给概率上升方向更宽空间；token 级聚合重新分配长短回答的权重；超长处理则避免截断样本把错误信号直接灌入策略。

这些设计互相影响。过滤后 prompt 分布变了，优势分布随之变化；聚合口径改变后，裁剪比例也会变化。只从完整配方里拿一个开关，不能假设仍会复现原结果。实验必须逐项记录启用条件与消融，而不是把「采用 DAPO」当成充分描述。

## GSPO：把比率拉回序列

PPO/GRPO 常在 token 级计算 importance ratio。对长序列而言，局部 token 比率可能高度波动，且推理正确性通常由整条回答共同决定。GSPO 转向序列级比率，希望让优化粒度与奖励粒度对齐。它减少了单个 token 极端比率支配更新的机会，但序列级压缩也会隐藏局部异常：模板 token、推理 token 和答案 token 的行为变化被汇入同一个数。

因此，采用序列级目标后仍需保留 token 级诊断。至少画出位置分桶的 KL、ratio 分位数和 mask 覆盖率。序列目标是训练权重，不是放弃细粒度观测的理由。

## GMPO：几何平均改变长度效应

一串 token 比率相乘容易随长度指数变化，直接算术平均又可能让少数极端 token 支配结果。GMPO 从几何平均出发，在 log 空间聚合 token 变化，使序列尺度更可控。几何平均等价于平均 log-ratio 后再指数化，这与概率乘积的结构更自然地对应。

但「长度归一」不是自动公平。长回答包含更多低信息模板 token，也有更多机会出现异常 token；短回答则可能只给结论。几何平均只定义了如何压缩比率，没有决定奖励是否可靠、mask 是否正确，也没有消除采样长度分布带来的选择偏差。

## GDPO：多奖励不能先糊成一个数

推理训练常同时使用正确性、格式、长度、代码执行、语言一致性等奖励。若先用固定权重求和再统一标准化，高方差或高频奖励可能吞掉其他目标，甚至让某一维的尺度变化改变全部样本排序。GDPO 的关键问题是把奖励维度解耦后再归一化与组合，使不同信号保留自己的统计尺度。

多奖励方法的核对重点不只是最终权重。要检查缺失奖励如何处理、各维奖励在哪个集合上统计、方差接近零时如何稳定、负奖励方向是否统一，以及跨设备聚合是否一致。一个分项若只在少数样本上定义，直接把缺失值当零会把「未评估」误写成「表现中性」。

## 统一诊断表

四类方法可以用同一张脑内表格比较：采样阶段是否过滤；优势在组内怎样归一；importance ratio 在 token 还是序列聚合；loss 对 token、序列、prompt 怎样平均；正负更新的裁剪边界是否对称；多个奖励在合并前是否分别校准；过长与被截断样本怎样进入奖励和损失。只要其中一列不同，实验就不能简单归因于算法名称。

阅读顺序建议从 [DAPO](./1.3.2.1-dapo/1.3.2.1-dapo.md) 开始，先看完整训练配方；再读 [GSPO](./1.3.2.2-gspo/1.3.2.2-gspo.md) 与 [GMPO](./1.3.2.3-gmpo/1.3.2.3-gmpo.md)，比较序列聚合的两条路径；最后读 [GDPO](./1.3.2.4-gdpo/1.3.2.4-gdpo.md)，把单奖励假设扩展到多维反馈。之后进入训练配方章，判断这些机制在受控对照中是否真的必要。

## 从论文数字回到系统

复现时应同时保存策略版本、rollout 引擎版本、tokenizer、聊天模板、采样参数、奖励代码哈希和每种 mask。监控至少包括 reward 分项、回答长度分布、全同组率、有效 token 数、KL、ratio 分位数、上下裁剪率、梯度范数及吞吐。若只保留最终 checkpoint 和总奖励，事后几乎无法判断一次崩溃来自算法、数据、验证器还是推理服务。

稳定优化的终点不是让曲线更平，而是让每次变化都有可追踪原因。真正可靠的配方应该能回答：哪类样本贡献了梯度，哪些更新被裁剪，奖励维度怎样竞争，长度为何改变，以及收益在控制算力和数据后是否仍然存在。

## 从异常现象反推责任层

若奖励突然上涨而验证集不动，先检查动态采样与验证器分布，而不是立刻调学习率。若 KL 与梯度范数同时尖峰，检查策略版本、old log-prob 和 ratio；若 KL 平稳但长度持续增长，检查 token/sequence 聚合与长度奖励；若某一奖励分项改善、其他分项退化，检查多奖励归一化与缺失值处理。把现象与责任层对应起来，能避免用一个超参数掩盖另一层的错误。

裁剪统计需要拆成正优势与负优势两侧。总裁剪率相同，并不代表更新行为相同：大量正优势被上界裁掉会限制提升高质量回答的概率，大量负优势被下界裁掉则会保留不理想行为。还应按回答长度、题目难度和奖励分桶观察。全局平均往往把最需要关注的小群体冲淡。

## 公平比较所需的控制量

比较 DAPO、GSPO、GMPO 与 GDPO 时，至少固定基础模型、数据快照、聊天模板、生成温度、组大小、最大长度、总生成 token、总训练 token 与评测脚本。如果某方法因吞吐较低而在相同墙钟时间内看到更少样本，应同时给出等时间与等 token 两种结果。否则系统效率与统计效率会被混成一个数字。

优化器状态也不能忽略。切换目标函数后沿用已有动量，与从同一 checkpoint 重置优化器开始，可能产生明显不同的短期曲线。严格消融应共享起点，并明确是否继承 optimizer、scheduler 与数据游标。多次运行要报告均值和波动，不能只挑最好种子。

## 最小故障实验

在全规模训练前，可以构造四类小实验。奖励全相同时，优势与策略梯度应接近零；一条正样本配多条负样本时，正负更新方向应符合预期；把同一回答复制成不同长度的等价序列，可以检查聚合是否无意偏爱长度；人为放大某一奖励维度，可以检查多奖励标准化是否真的解耦。再加一组旧策略与当前策略完全相同时的测试，importance ratio 应接近一。

这些实验不证明最终能力，却能快速排除公式抄对、实现含义却变了的问题。推理强化学习一次大规模 rollout 成本很高，把符号、边界和聚合错误留到正式训练后发现，是最昂贵的调试方式。
