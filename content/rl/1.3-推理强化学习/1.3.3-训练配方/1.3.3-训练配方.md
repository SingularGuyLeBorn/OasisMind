# 训练配方

推理强化学习很容易进入「开关越多越先进」的误区。动态采样、难度课程、熵控制、两侧裁剪、长度惩罚、KL、拒绝采样、不同粒度的归一化都可能有效，但它们也会彼此遮蔽。训练配方这一组文章不再只问目标函数长什么样，而是追问：在固定模型、数据、rollout 预算和评测口径后，一个组件是否仍带来稳定收益？如果收益只在某个未对齐的设置里出现，它就不能被归因于算法本身。

## 先建立能工作的简单基线

可靠实验应从最小闭环开始：固定参考模型和旧策略语义，对每个 prompt 采样同样数量的回答，用可复核验证器给奖励，构造组内优势，计算代理损失并完成更新。这个闭环需要先通过符号、mask、版本和数值验收。只有基线能够重复跑出一致趋势，增加技巧才有解释价值。

JustRL 的意义正在这里。它提醒我们，经过合理的数据、采样和工程配置后，简洁的单阶段 GRPO 基线可能已经很强。复杂方法需要与这类强基线比较，而不是与调参不足的实现比较。所谓「简单」也不等于随意：模型版本、训练 token、生成预算、最大长度、验证器、评测脚本和随机种子都要锁定。

## GHPO：根据样本状态调整训练信号

固定配方默认所有 prompt 在同一训练阶段需要同样处理，但实际数据会随策略能力改变。某些题已经全对，某些题仍全错，还有些题正处在可学习区间。GHPO 一类方法尝试依据难度或组内状态调整引导方式，把计算分给仍能产生信息的样本。

这种自适应最需要防止反馈回路。训练策略决定采样结果，采样结果又决定难度标签，难度标签再影响下一轮训练。如果统计窗口太短，随机波动会被当成能力变化；如果只保留当前可学习样本，训练分布会逐步偏离原始任务。日志应保留调整前后的分布，并在固定评测集上独立判断能力，而不是用训练过滤后的奖励证明自己有效。

## 技巧与陷阱：每个开关都改变了估计量

许多技巧表面上只是工程保护，实际会改变优化目标。过滤全同组会改变 prompt 权重；按长度归一会改变长短回答的相对贡献；clip-higher 会改变正负更新的不对称程度；去掉 KL 会扩大探索，也会失去参考策略约束；只保留格式正确样本会让格式验证器参与数据选择。

因此技巧不能按流行程度堆叠。每加入一个开关，都要写清它针对什么可观测症状、改变哪项统计量、预期让哪个监控指标变化，以及失败时如何回退。若没有症状却默认开启，后续收益与退化都难以解释。

一套实用消融顺序是：先固定数据和 rollout；一次只改变一个组件；保持有效训练 token 与生成 token 尽量一致；至少用多个随机种子；同时报告最终指标、学习速度与稳定性；最后做组合实验检查交互。若两个组件分别有效、组合却无额外收益，说明它们可能解决同一瓶颈，不能把单项增益直接相加。

## 计算扩展：算力花在哪里

推理 RL 的总成本远不止反向传播。每个 prompt 的多次长文本生成、验证器执行、旧策略 log-prob 计算、训练端重算、跨节点传输和权重同步都可能成为主瓶颈。扩大训练规模时，需要区分 prompt 数、每题采样数、平均回答长度、更新轮数和模型规模；它们虽然都增加计算，却带来不同的信息增量。

增加 prompt 数扩大任务覆盖；增加组大小改善同题比较和探索；增加长度给复杂推理更多空间，也放大解码成本与信用分配难度；增加更新轮数提高样本复用，但让策略远离行为策略。若只用总 FLOPs 横轴，几条性质不同的扩展路径会被混在一起。

系统指标也应进入配方比较。生成吞吐、训练吞吐、GPU 利用率、验证器延迟、等待比例、样本过期程度和失败重试都会影响同样预算下真正进入更新的数据量。算法论文里的训练步数只有在 batch、序列长度、组大小和有效 token 都对齐时才可比较。

## 阅读路线

先读 [GHPO](./1.3.3.1-ghpo/1.3.3.1-ghpo.md)，理解随样本难度调整引导的收益与反馈风险；再读 [JustRL](./1.3.3.2-justrl/1.3.3.2-justrl.md)，建立强而简洁的对照；随后用 [技巧与陷阱](./1.3.3.3-技巧与陷阱/1.3.3.3-技巧与陷阱.md) 检查每个常用组件到底改变了什么；最后进入 [计算扩展](./1.3.3.4-计算扩展/1.3.3.4-计算扩展.md)，把单次实验结论放进更大的预算与系统约束中。

这条路线刻意把复杂方法放在简单基线之前和之后来回比较。读者需要形成的不是一张「最佳配置」清单，而是一套诊断习惯：先观察症状，再选择机制；先锁定口径，再看收益；先确认统计与实现一致，再扩大规模。

## 一份可执行的实验账本

每次实验应记录模型与 tokenizer 标识、数据快照、prompt 采样权重、生成参数、验证器版本、奖励分项、组大小、有效序列数、最大长度、优势归一化、loss 聚合、裁剪区间、KL 方向、优化器、学习率、总生成 token 与总训练 token。评测则同时保留准确率、格式通过率、长度、pass@k、能力回退和多次运行方差。

账本不是为了增加流程感，而是为了避免最常见的错误归因。推理强化学习的收益常常只有几个百分点，模板、采样温度、答案解析或 token 预算的小差异就足以制造同等幅度的变化。只有把这些变量固定或明确报告，训练配方才从经验口诀变成可以迁移的知识。

## 配方迁移为什么经常失败

一套在数学短答案上有效的配置，迁移到代码、证明或长文本任务后可能立刻失效。数学验证器通常只关心最终答案，代码执行会遇到超时和环境依赖，证明任务有更长的形式约束，开放回答则没有唯一判定。奖励密度、回答长度与失败类型不同，最合适的组大小、过滤比例和最大长度自然也不同。

基础模型同样决定配方。一个已经具备稳定指令跟随和较强推理先验的模型，可能只需要较弱更新；能力较弱的模型生成组长期全错，组内方法没有足够信号。若不报告训练起点，只复制学习率和裁剪参数，所谓复现很可能是在解决另一道题。

## 停止条件也是配方的一部分

训练不能只设置固定步数。应同时观察固定验证集、探索多样性、回答长度、熵、KL、全同组率与能力回退。奖励继续上升而固定验证集停滞，可能表示策略正在适应训练验证器；熵快速下降且 pass@k 下降，可能表示探索过早塌缩；长度持续增长但准确率不变，则说明额外计算没有转化为能力。

一个保守停止策略可以要求核心指标在多个评测周期不再改善，同时没有新的能力维度受益，再决定结束或更换数据。恢复训练时必须保存优化器、调度器、数据游标和策略版本，不能只从模型权重重启后仍把曲线接在一起。

## 最终选择不追求统一答案

配方选择取决于瓶颈。如果大量组全同，先处理数据难度和采样；如果 ratio 极端，检查策略版本与聚合，再考虑裁剪；如果多奖励互相吞噬，处理分项校准；如果训练稳定但成本过高，优化 rollout 与验证器系统；如果简单基线已经达到相同效果，就没有理由承担更复杂的实现与调参面。

这也是本组文章的收束：GHPO 提供自适应视角，JustRL 提供简洁基准，技巧审计负责拆开每个开关，计算扩展负责把收益放回预算。四者组合后，读者得到的应是一套做选择的方法，而不是又一张需要照抄的超参数表。
