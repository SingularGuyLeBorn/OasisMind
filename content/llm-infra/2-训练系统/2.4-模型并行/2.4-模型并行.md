# 模型并行

数据并行把不同样本送给完整模型副本，模型并行则拆开一次样本的计算。当单层权重、整段模型或长序列 activation 无法放入一张 GPU，设备必须共同完成同一次 forward/backward。每种拆法都会缩小一类本地状态，同时在原本不存在的依赖边上加入通信。

模型并行不是一个可随意替换的开关。Tensor parallel（TP）切层内矩阵的 hidden/head 维，collective 几乎每层发生；pipeline parallel（PP）沿深度切连续层，在 stage 间传 activation 与梯度；sequence parallel（SP）切 TP 区域外的 token activation；context parallel（CP）让更完整的网络计算保持序列分片，并处理 attention 的全局 KV 依赖；expert parallel（EP）把 MoE expert 分给不同 rank，再按路由结果交换 token。它们切的维度和复制的状态不同，能够叠加，却不能共用一句模糊的“并行度越高越省显存”概括。

## 从装不下的对象选择切分轴

参数状态占主导时，先判断问题来自整个模型还是单层。整个模型太大而单层可放下，PP 或 FSDP 可以沿层/状态生命周期拆分；单个投影矩阵已经超出设备容量，TP 才是直接切开 GEMM 的手段。Optimizer state 过大但计算参数能放下时，ZeRO-1/2 往往比引入层内 collective 更便宜。

Activation 占主导时要看增长来源。普通 Transformer 中间状态随 micro-batch、序列和隐藏维增长，checkpoint/recompute 与 SP 可减少保存量；超长 attention 的 KV 和注意力中间量还需要 CP 或专门 attention 算法。PP 会把不同层分散到 stage，却可能因多个在途 micro-batch 同时保存 activation 而重新抬高峰值。

切分前先列四项：每层权重 shape、每层 activation shape、必须跨设备求和或拼接的边界、该边界所在的物理链路。形状决定字节，依赖决定 collective 能否推迟，拓扑决定这些字节需要多久。

### 三条主要时间线

TP 位于层内关键路径。Column-parallel 与 row-parallel 线性层成对使用，中间保持 hidden shard，出口才规约局部和。它减少每卡参数和 GEMM，却让 activation all-reduce/all-gather/reduce-scatter 高频出现。因此 TP 通常放在 NVLink/NVSwitch 域，规模以满足容量的最小值为起点。

PP 的通信频率按 micro-batch 与 stage 边界计。增加 micro-batch 可降低填充、排空气泡占比，也会让更多 activation 同时存活。stage 不能只按层数或参数平均：embedding、词表输出、attention、dense MLP 与 MoE 的运行时间不同，最慢 stage 决定流水节拍。

SP/CP 都沿 token 维工作，但生命周期不同。SP 与 TP 绑定，在 TP 计算区边界把序列 shard 转为 hidden shard，再转回来；CP 让 attention 之外的网络持续处理本地 token，并为 attention 交换 KV。SP 解决 TP 复制的逐 token activation，CP 面向更长上下文的全层 activation 与 attention 依赖。

### 组合并行先画 process group

总卡数常写成

$$
W=D\times T\times P\times C,
$$

其中 $D,T,P,C$ 分别表示 DP、TP、PP、CP 规模；MoE 还会加入 EP，并可能与 DP 采用不同折叠方式。乘积只是数量关系。每个 rank 同时属于若干通信组，必须明确同一 TP group 是否位于机内、PP 相邻 stage 是否跨同一 NIC、DP bucket 是否与 TP/CP collective 争用链路。

例如 64 卡取 TP=4、PP=4、DP=4，可将四卡 TP 放在单节点，四个节点组成一条 pipeline，再复制四份。TP 高频通信留在机内；PP 每个 micro-batch 跨节点传 activation；DP 在具有相同 TP 与 PP 坐标的 rank 间同步对应参数 shard。若 rank 排列错误，逻辑 TP 邻居可能跨机架，配置数值完全相同，step time 却会明显恶化。

并行维度还会改变 checkpoint。TP shard、PP stage 与 optimizer DP shard 都要带全局参数名、shape、offset 和并行坐标；恢复到另一组并行度时需要重分片。只验证稳态 step 而不验证保存、加载与 world-size 变化，无法说明方案可用于长时间训练。

## 容量与吞吐要一起验收

理论容量下降不等于可扩展。TP 增大后每卡 GEMM 变窄，collective activation 字节不会同比下降；PP 增大后本地层数变少，bubble 和跨 stage 通信占比上升；CP 增大后本地 token 变少，attention 通信与负载均衡成为新边界；EP 增大后 expert 参数下降，all-to-all 的拥塞与长尾更突出。

候选配置先通过容量明细筛选，再以相同 global batch、有效 token 和数值语义测量。报告至少包括每卡峰值与 reserved memory、各类 collective 字节和分位时间、GEMM shape 与实际吞吐、pipeline bubble、重算 FLOPs、rank 间等待，以及 checkpoint 恢复耗时。短跑峰值 token/s 还要扣除周期保存、故障重启和数据空档，才接近长期有效吞吐。

一种实用选择顺序是：用 DP 扩大吞吐；显存不足时先处理 activation 与 optimizer state；单层仍放不下再提高 TP；深度或总参数仍超出单个 TP 组容量时加入 PP；长上下文再根据 activation 与 attention 边界选择 CP。它不是固定模板，每一步都要用实际 shape 与拓扑验证，但能避免一开始把所有并行维度开到最大。

[《上下文并行》](2.4.3-上下文并行/2.4.3-上下文并行.md)沿序列轴切分长上下文，对比 KV ring 与 sequence↔head all-to-all，计算因果负载、通信与 activation 峰值，并处理全局位置、mask 和多维并行组合。

路线验收不以“支持多少种并行”为标准。读者应能从模型 shape 算出每张卡的矩阵和 activation，写出 process group，估算 collective 字节与容量峰值，再判断瓶颈来自算力、带宽、启动延迟、bubble、负载不均还是恢复路径。

### 一个 64 卡配置怎样缩小搜索空间

假设模型总状态和 activation 在单卡需要 320 GB，设备容量 80 GB。只看除法会认为四卡即可，运行峰值还包含通信 buffer、碎片和临时完整参数，至少要留出 15%—20% 余量。若单层 BF16 权重最大为 18 GB、单层 activation 为 12 GB，TP=2 已能处理单层；剩余总模型可通过 PP 或 FSDP 分散，没有必要先上 TP=8。

候选 A 取 TP=2、PP=4、DP=8，候选 B 取 TP=4、PP=2、DP=8，均使用 64 卡。A 的 TP GEMM 更宽、层内通信较少，pipeline stage 更多、bubble 较大；B 的 pipeline 更短，却让每层 TP collective 规模扩大。用层级 profile 得到单 block 计算与 TP 通信，再用 micro-batch 数估算 PP bubble，二者才可比较。参数量相同并不能预先断言哪套更快。

若序列从 4K 增到 32K，activation 和 attention 依赖可能超过原有容量与通信估算。此时继续提高 TP 会让线性 GEMM 变得更窄；加入 CP 或增加重算可能更合理。配置搜索应固定目标序列、global batch 与硬件拓扑，每次只替换一个瓶颈对应的并行轴。

## 故障与弹性也是并行成本

模型并行组内任一 rank 退出，当前模型副本通常无法继续。TP/PP group 跨越越多节点，单节点故障影响的计算域越大。DP 副本提供一定冗余，但同步训练仍需重新形成合法 world size，并从最近 checkpoint 恢复。长期有效吞吐可粗略写成

$$
R_{effective}=R_{steady}\left(1-\frac{T_{save}+T_{restart}+T_{replay}}{T_{wall}}\right).
$$

峰值吞吐提高 5%，若更复杂的跨节点 TP 使重启和重算占比从 2% 升到 8%，长期产出反而下降。保存频率也受 checkpoint 规模与分片格式影响；并行布局越复杂，越要验证跨布局恢复，而不是只测原配置原地加载。

启动产物应包含每个 DP/TP/PP/CP/EP group 的 rank、主机、GPU、NIC 映射，以及参数 shard 到全局 FQN 的索引。通信 hang、数值分叉和 checkpoint 错位都可从这些坐标回溯。缺少映射时，日志里的 rank 编号几乎无法解释物理链路和状态所有权。

### 数值正确性独立于吞吐调优

每增加一种并行维度，都要与较小规模基线比较 forward、loss、梯度范数和一步参数更新。低精度 collective 的求和顺序不同，允许容差内误差；固定倍数偏差通常意味着梯度平均重复、bias 重复相加或 shard 拼接轴错误。性能优化只能在数值测试通过后比较，否则更快的 step 可能正在训练另一个目标。

动态分支、变长序列和 MoE 路由还会改变各 rank 执行的算子。collective 顺序必须在通信组内一致，token 数不同时则要交换 split size 或 padding。故障注入可让单 rank 延迟、跳过分支或产生 Inf，验证超时诊断、overflow 同步和恢复路径。
