# 成本与运维：约束下的系统选择

LLM Infrastructure 最终要在约束下持续交付计算结果。单卡峰值、集群 MFU 和某一时刻的 GPU 利用率都只是局部观测; 它们没有自动计入 padding、排队、失败重跑、冗余副本、存储流量和人工处置。一个训练集群可以长期显示高利用率, 同时把大量算力花在即将失败的作业上; 一个推理服务也可以把 GPU 填满, 但因 P99 超过服务目标而无法承接更多请求。

成本分析从分母开始。训练可以使用达到目标验证质量所需的有效 token、step 或完整实验; 在线推理可以使用满足质量和时延约束的请求或输出 token。分母包含「有效」与「合格」, 才能识别转移到其他环节的浪费。**基础设施优化的对象是单位有效工作的总成本。** 采购、容量规划、调度、监控、可靠性、功耗和人员投入都使用这一口径。

## 先把成本落到一项工作上

### 训练成本从有效 token 反推

一次训练作业的直接计算成本可以写成设备数量、占用时间与单位设备时间价格的乘积, 但这个数还不能横向比较。数据 padding、梯度累积气泡、checkpoint 停顿、故障回退和低效 kernel 都会消耗 GPU 时间, 却没有增加有效训练 token。更有用的指标是每百万有效 token 的设备时间, 并同时记录达到目标 loss 所需的 token 数。每 token 更便宜但收敛更慢的方案, 总训练成本可能更高。

共享存储、网络和 CPU 也进入同一作业。数据预处理不足会让昂贵 GPU 等待 CPU; checkpoint 写入会占用存储容量与网络出口; 分布式并行会消耗跨机带宽。将这些资源按作业标签归集, 才能区分模型计算、数据管线和可靠性开销。若只计 GPU 租金, 把瓶颈转移到对象存储并不能证明成本下降。

### 推理成本受服务目标约束

推理侧常用每百万输入或输出 token 成本, 但 token 数没有表达请求长度分布、batch 等待和时延目标。离线批处理可以等待形成大 batch, 在线对话却受 time to first token 与 inter-token latency 限制。为了守住 P99, 服务通常保留吸收流量波动和故障的空闲容量。

Prefill 与 decode 的资源行为不同。Prefill 更偏计算, decode 更受 KV cache 容量和带宽影响; 输入很长、输出很短与输入很短、输出很长的请求不能只按总 token 等价计费。成本归因应拆分输入 token、输出 token、cache 占用时间、路由与跨节点传输。质量降级也必须进入约束: 更小模型成本低, 若无法满足任务质量, 其低单价没有比较意义。

## 利用率需要解释空闲发生在哪里

### 平均 GPU 利用率会隐藏排队与碎片

集群平均利用率把时间、设备和作业混在一起。80% 可能表示所有 GPU 稳定使用 80%, 也可能表示一部分设备满载、另一部分因拓扑或显存需求长期空闲。容量规划需要同时查看 allocated、active compute、memory-bound、communication wait 和 idle, 并按 GPU 类型、机架与队列拆分。只有这样才能知道空闲来自需求不足、调度碎片还是作业自身停顿。

大规模 gang scheduling 要一次拿到满足拓扑的整组设备。短作业占据零散节点时, 集群总空闲 GPU 足够, 大作业仍可能无法启动。Backfilling 可以利用预计空隙运行短任务, 前提是运行时间估计可靠且不会拖延已承诺的预约。抢占提高整体利用率, 但 checkpoint 与重启成本会降低有效工作量。调度指标因而要把 queue time、preemption waste 与完成时间一起报告。

### 配额表达的是组织优先级

在共享集群中, 配额既限制资源上限, 也表达不同团队和任务的优先级。静态配额容易在某团队需求低时留下闲置, 完全自由竞争则可能让长训练或线上服务被大量小实验挤占。常用策略是在最低保障、可借用余量和突发上限之间分层, 并为生产推理保留不可被训练耗尽的容量。

成本归因必须能回到团队、项目、模型版本和环境。标签缺失时, 未归属资源会逐渐成为不可优化的固定支出。公共网络、存储缓存和控制面需要选择稳定的分配口径, 同时保留未分配总额。若分配规则每月变化, 趋势本身就失去可比性。

## 容量规划从分布出发

### 在线容量看尾部而非平均请求

在线流量具有日周期、周周期、发布峰值和突发事件。容量模型至少需要请求到达率、输入输出长度分布、模型组合、cache 命中率与时延 SLO。平均 QPS 无法描述短时间集中到达, 平均长度也会低估少量超长请求对 KV cache 的占用。模拟或压测应从真实分布采样, 并观察不同并发下的 P95、P99 与拒绝率。

Autoscaling 受到模型加载时间和 cache 冷启动约束。若扩容需要数分钟, 控制器必须根据领先信号提前准备, 而不是等请求已经超时才增加副本。缩容同样要等待活动请求排空, 防止中断长生成。保留容量、弹性资源和请求降级共同构成容量策略, 三者成本应与可接受的错误预算一起评估。

### 训练容量看作业组合和完成期限

训练需求由不同规模、时长和优先级的作业组成。单次峰值设备需求决定最大可运行实验, 长期设备时间决定集群规模, 两个约束分别计算。容量规划应使用历史作业到达、排队、运行时长和失败率, 评估不同集群规模下的等待时间与完成期限。

硬件代际选择还受到软件成熟度和异构调度影响。新 GPU 的理论性能更高, 但 kernel、通信库和故障经验不足可能降低早期有效产出; 混合代际集群若不能在同一作业中组合, 会增加资源池碎片。采购决策需要比较完整生命周期内的交付 token、维护与能耗, 而不是只比较峰值 FLOPS 与单卡价格。

## SLO 把可靠性成本变成约束

### 错误预算决定可以承受多少变化

服务等级目标需要指定指标、阈值、统计窗口和适用请求。例如「月度 99.9% 请求成功」若不定义超时、用户取消、降级响应和流式中断, 不同团队会得到不同结果。时延 SLO 也要区分 time to first token 与 inter-token latency, 并按模型或长度桶统计, 否则长请求会被总体平均值隐藏。

错误预算把可靠性目标转为可消费额度。预算充足时可以进行发布和实验, 消耗过快时应减少变更并处理主要故障来源。冗余副本、跨故障域部署和故障演练都增加正常成本, 但它们降低超出 SLO 的概率。上一章讨论的恢复时间、checkpoint 与流量切换, 在这里表现为容量与人员成本。

### 监控要支持归因和决策

有效监控从用户结果向下连接请求、模型实例、GPU、网络和存储。仅保留节点平均指标, 无法回答某个模型版本的 P99 为什么升高; 仅保留请求指标, 又无法定位是 batch 调度、KV cache 压力还是网络拥塞。Trace、结构化日志和带稳定标签的 metrics 需要共享请求或作业标识, 才能完成跨层关联。

告警数量不能代表覆盖面。告警应绑定可行动条件, 包含影响范围、持续时间和对应 runbook; 否则值班人员会在大量瞬时波动中遗漏真正故障。运维成本包括 on-call 时间、发布验证、容量调整和故障复盘。这些工作若持续依赖人工判断, 即使没有单独列出费用, 也应进入系统选择。

## 能耗、自建与云资源

### 功耗不是额定 TDP 的简单乘积

设备额定功耗给出上限附近的参考, 实际能耗取决于 workload、频率、利用率和持续时间。降低功率上限可能轻微增加运行时间却显著降低能耗, 也可能让通信等待占比上升而没有收益。评估需要同时测量每步时间、总能耗和达到目标质量的完整训练过程, 不能只比较瞬时瓦数。

数据中心还包含供电转换、散热、网络、存储和 CPU 能耗。PUE 可以描述设施附加开销, 但不同地点、季节和负载下会变化。碳排放进一步依赖电力结构和时间。因而对外报告能耗或排放时, 应注明测量边界、时间窗口和估算因子, 避免把 GPU 遥测值当成完整数据中心成本。

### 自建与云的边界随负载变化

稳定且长期满载的训练或推理适合评估自建资源, 因为固定成本可以被大量有效工作摊薄。需求波动大、硬件迭代快或需要短期峰值时, 云资源提供弹性与更快交付, 但包含溢价、数据出口和可用性约束。Spot 实例降低单价, 同时增加中断与 checkpoint 需求; 其真实收益取决于作业可恢复性和丢失工作量。

混合资源常见于基础容量自建、峰值需求上云。它要求模型、数据和监控能跨环境一致运行, 数据复制与安全也会增加成本。选择时应使用相同的有效工作分母, 把折旧、网络、存储、人员、闲置容量和失败风险都纳入, 再比较不同负载情景。单独对比按小时报价会遗漏主要差异。

## 从局部优化回到总成本

集群利用率、调度与配额、成本归因、容量预测、SLO、能耗以及云与自建选择共用“单位有效工作”这一分母。作业成本、共享资源竞争和可靠性余量因此可以使用同一口径比较。
