# 数据并行：从完整副本到参数分片

单张 GPU 放不下更大的 batch，最直观的办法是多放几份模型，让每份模型处理不同样本，然后把各自看到的梯度合在一起。这句话概括了数据并行，也藏起了最重要的系统问题：哪些状态必须相同，梯度在什么时候合并，optimizer 在哪里更新，以及为了省显存把状态拆开以后，下一次前向又怎样拿回完整参数。

因此 DDP、ZeRO 与 FSDP 不是三个互不相关的名词。它们都要保证一次 optimizer step 在数学上等价于更大的全局 batch，差别在于参数、梯度和优化器状态由谁长期保存，又在计算前后执行什么集合通信。本路线从一份可复算的状态账本出发，再把字节放回反向传播时间线。这样才能解释为什么某个方案省显存，却可能因为小 bucket、逐层 all-gather 或网络拓扑而变慢。

## 1. 不变量是同一步更新，不是每张卡做同样的事

设数据并行规模为 $D$，第 $r$ 个 rank 处理本地 micro-batch $B_r$。若全局目标是样本平均损失，则梯度应为

$$
g=\frac{1}{\sum_r|B_r|}\sum_{r=1}^{D}\sum_{x\in B_r}\nabla_\theta\ell(x;\theta).
$$

当每个 rank 的有效 token 数相同，可以先在本地求平均，再对梯度做 all-reduce 并除以 $D$。但序列 packing、padding mask 或动态长度会让有效 token 数不同，此时应分别规约损失分子与 token 分母，或者保证梯度缩放采用全局 token 数。否则通信完全正确，训练目标仍会悄悄偏向 token 较少或较多的 rank。

数据并行真正要守住的有三件事。step 开始时，参与同一副本组的参数版本一致；step 结束前，用于更新的梯度代表同一个全局 batch；更新完成后，各 rank 对下一步所见参数达成一致。DDP 用“每卡保留完整状态、规约完整梯度”实现它。ZeRO 与 FSDP 则允许大部分时间只持有分片，但必须在参数被计算消费之前临时聚合，并在梯度产生之后把结果送回正确的所有者。

显存与通信必须一起计算。分片把完整状态的长期驻留改成按需聚合：完整参数只在某层计算窗口内存在，完整梯度可以直接归约为分片，optimizer state 由负责对应参数分片的 rank 常驻。live set 随之缩小，同时新增 all-gather、reduce-scatter、预取队列和临时 buffer。

## 2. 三种方案分别把状态放在哪里

先取一个混合精度 Adam 例子。模型有 $\Psi$ 个参数；计算参数和梯度各按 2 byte，FP32 master parameter、first moment、second moment 各按 4 byte。忽略 activation、allocator 对齐和临时 workspace，完整副本的模型状态约为

$$
M_{base}=(2+2+4+4+4)\Psi=16\Psi\ \text{byte}.
$$

这不是所有框架都固定为 16 byte/parameter：BF16 是否保留 master weight、梯度 buffer 的 dtype、optimizer 实现和低精度状态都会改变数字。账本的意义正是把这些假设写出来，而不是背一个常数。对于 $\Psi=7$B 的示例，16 byte/parameter 已是约 112 GB，尚未计算 activation 和碎片，单卡显然放不下。

DDP 在每个 rank 保留完整参数、梯度与 optimizer state，因此这部分不会随 $D$ 下降。它的优势是计算路径简单：forward 直接读本地参数，backward 产生梯度后做 bucketed all-reduce，随后每卡执行相同更新。若模型状态本来放得下，DDP 往往拥有最少的参数搬运与最容易理解的故障边界。

ZeRO-1 先分 optimizer state，上例每卡约为 $4\Psi+(12\Psi)/D$；ZeRO-2 再分梯度，约为 $2\Psi+(14\Psi)/D$；ZeRO-3 连参数也分，稳态模型状态接近 $16\Psi/D$。公式只描述常驻项，不能拿来当峰值：Stage 3 在某层计算前仍要 all-gather 参数，若预取下一层又没有及时释放上一层，瞬时 live set 会包含多个完整 layer。

FSDP 的核心数据流与 ZeRO-3 同属全分片：本地 flat parameter 长期只保留 $1/D$，计算前 unshard，forward 后按策略 reshard，backward 前再次取得参数，梯度产生后 reduce-scatter。二者在抽象上接近，具体实现却会在参数展平、模块边界、prefetch、原始参数视图、checkpoint state dict 与通信调度上表现不同。选型时应比较实际生命周期，而不是只凭“都等于 Stage 3”停止分析。

## 3. 通信要放回反向传播的顺序

DDP 不会等所有梯度生成后才一次性通信。Autograd 从输出层向输入层推进，参数梯度按反向顺序就绪；实现会把参数分进 bucket，某个 bucket 全部就绪后由 hook 发起异步 all-reduce。后续层继续反向计算时，前一个 bucket 可以在通信 stream 上运行。总通信量没有因此消失，真正减少的是暴露在 step 关键路径上的部分。

假设反向计算剩余窗口为 8 ms，当前 bucket 通信需 5 ms，且计算与通信不争用关键资源，这 5 ms 可以隐藏。若通信需 12 ms，至少约 4 ms 暴露；若两者同时抢 HBM 或 PCIe，重叠后的计算也可能由 8 ms 变成 10 ms，真实暴露量便不能用简单的最大值完全描述。bucket 太大，启动晚；bucket 太小，$\alpha$ 启动成本和调度开销增多。最佳值与层的梯度就绪间隔、链路和拓扑有关。

梯度累积又增加一层时间关系。累积阶段的 micro-batch 通常只把梯度写入本地 buffer，通过 `no_sync` 一类机制禁止逐次规约；达到更新边界的 micro-batch 才让 bucket hook 发起通信。若错误地每次都 all-reduce，数学结果可能仍可通过缩放保持一致，但通信调用数会放大，重叠窗口也完全改变。

ZeRO-2 把梯度归约改成 reduce-scatter，使每个 rank 最终只得到自己负责更新的梯度分片；更新后，还要用 all-gather 或等价广播让各 rank 得到一致的计算参数。ZeRO-3/FSDP 则把参数聚合推进到每个模块的消费点。于是关键路径从“一组反向 bucket”变成“参数预取、模块计算、梯度分片归约”交错的流水，模块切分过细会被频繁 collective 的启动成本吞掉，切分过粗又抬高峰值显存。

## 4. 三篇叶子怎样读

[《DDP 与通信重叠》](01-DDP与通信重叠/01-DDP与通信重叠.md)沿 autograd 的梯度就绪顺序画出 bucket 生命周期，并计算 ring all-reduce 字节和可隐藏窗口。时间线里即使出现计算与 NCCL 色块重叠，step 尾部、共享资源争用和末尾 bucket 仍会产生等待。

[《ZeRO 状态分片》](02-ZeRO状态分片/02-ZeRO状态分片.md)逐项列出参数、梯度、master weight 和 Adam 两个 moment，分别推导 Stage 1/2/3 的稳态与峰值。随后沿一个 step 跟踪每个分片的所有者，说明 reduce-scatter、更新与参数同步如何保持同一步 SGD/Adam 语义。

[《FSDP 参数生命周期》](03-FSDP参数生命周期/03-FSDP参数生命周期.md)跟随一个 Transformer block：flat parameter 在何时 unshard，完整参数何时释放，backward prefetch 如何与计算交错，梯度如何回到 shard。文章还会单独处理 checkpoint 重分片与 world size 改变；训练能够完成一次 step，只证明了执行路径，不足以证明状态可以可靠保存和恢复。

显存不足时需要列出状态账本，通信尾巴过长时需要对齐 bucket 与 rank 时间线，FSDP 峰值异常时则要画出模块级参数生命周期。三种排查都追踪同一组事实：状态原来在哪里、由谁保管、消费前通过哪条路径出现，以及代价落在带宽、延迟还是临时容量上。

## 5. 选择不是从最大分片级别开始

如果完整模型状态放得下，而且主要瓶颈是算力，DDP 的简单路径往往更合适。分片级别越高，常驻显存越低，但通信依赖与临时状态越多。为了追求最低理论显存直接上全分片，可能把大 GEMM 前插入大量参数 all-gather，使原本可扩展的训练变成延迟受限流水。

真正的选择顺序应从目标 global batch、单卡 micro-batch、activation 峰值和模型状态账本开始。Activation 占主导时，ZeRO-3 并不能替代 checkpoint/recompute；optimizer state 占主导时，ZeRO-1 已可能解决问题；参数本身也放不下，才必须让参数分片进入计算路径。随后把 DP 组映射到实际互联，确认 collective 是否跨越慢层级。

验收指标包括端到端 step time 与可恢复性。吞吐在相同 global batch、有效 token 和优化器语义下比较；显存同时报告稳态、峰值和 allocator reserved；通信区分总时长与关键路径暴露；checkpoint 要能在目标并行拓扑恢复。所有指标共同说明训练语义、速度与状态生命周期是否闭合，单独下降的显存数字不够。
