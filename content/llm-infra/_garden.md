# LLM Infra · 大模型系统与基础设施


模型系统的困难往往不在某个算子的定义, 而在许多局部正确的数字无法汇成同一个判断. 一张加速卡给出峰值 FLOPs 和显存带宽, 网络规格给出链路速率, 模型配置给出参数量与序列长度, 服务指标给出首 token 时延和每 token 时延. 若这些量没有统一 shape、单位和时间边界, 「算力不够」「通信太慢」「显存爆了」都只是症状描述. 这座知识库把每个系统判断落到可复算的工作量与资源模型: 哪个张量由谁产生, 在哪里驻留, 移动多少字节, 执行多少次运算, 经过哪条链路, 占用多长时间.

**性能数字只有绑定硬件、精度、batch、序列长度、并行布局和测量口径才有意义.** 同一块 GPU 上, prefill 可能受矩阵乘吞吐限制, decode 可能受权重读取带宽限制; 同一个 all-reduce, 跨 NVLink 和跨以太网的时间可能不在一个数量级; 同一个训练 step, activation checkpointing 省下显存却增加重算. 因而这里不收集脱离条件的「最快」结论, 而是保留计算路径和边界.

## 1. 从统一工作量与资源模型进入

### 1.1. 五类量共用一套坐标

系统资源模型记录计算量 $F$ (FLOP), 数据量 $Q$ (byte), 容量 $M$ (byte), 延迟 $T$ (s) 与能量 $E$ (J). 吞吐率是单位时间完成的工作, 如 $P=F/T$ 的单位为 FLOP/s; 带宽是 $B=Q/T$ 的 byte/s; 算术强度 $I=F/Q$ 的 FLOP/byte 把算子放进 roofline. 每个数还要带 shape 与数据类型, 因为元素个数只有乘以每元素字节数才是可分配容量.

[系统模型](./01-系统模型/01-系统模型.md)先建立这套坐标. 其中[工作量与资源模型](./01-系统模型/01-性能模型/01-工作量与性能下界/01-工作量与性能下界.md)负责公式和测量边界, [GPU 层次](./01-系统模型/01-性能模型/02-GPU层次/02-GPU层次.md)解释峰值为何不能直接兑现, [通信拓扑](./01-系统模型/01-性能模型/03-通信拓扑/03-通信拓扑.md)把单卡资源模型扩展到设备组. 后续沿[训练系统](./02-训练系统/02-训练系统.md)、[推理系统](./03-推理系统/03-推理系统.md)、[数据存储](./04-数据存储/04-数据存储.md)、[编译内核](./05-编译内核/05-编译内核.md)、[可靠性](./06-可靠性/06-可靠性.md)和[成本运维](./07-成本运维/07-成本运维.md)继续展开.

### 1.2. 先估下界, 再解释差额

给定峰值计算率 $P_{peak}$ 与可持续带宽 $B_{sus}$, 算子时间下界是 $T_{lb}=max(F/P_{peak},Q/B_{sus})$. 实测时间 $T_{obs}$ 大于下界的差额来自调度空泡、同步、访存不合并、低 occupancy、kernel launch、数据依赖或网络争用. 下界不是预测器, 它用来排除不可能: 若理论读取权重已需 8 ms, 把服务目标定为 2 ms 就需要改变字节量或硬件, 不能靠调参实现.

这套方法也约束优化顺序. 算术强度远低于机器平衡点时, 继续提高 tensor core 理论 FLOPs 没有直接收益; 容量已经不足时, 应先改分片、精度或生命周期, 不能从 kernel 微调开始; 通信延迟主要来自跨节点启动项时, 增大链路峰值带宽未必消除小消息瓶颈.

## 2. 训练与推理的资源计算

### 2.1. 训练看 step 的完整生命周期

训练状态估算同时包含参数、梯度、优化器状态和 activation. 参数量为 $N_p$, 每份状态的字节数由精度决定; 数据并行复制参数, tensor parallel 与 pipeline parallel 切分不同维度. 前向、反向和优化器更新的计算量不能用单个「每 token FLOPs」覆盖, activation checkpointing 还会把一部分前向再次执行. 训练吞吐应同时报告 token/s、step/s 与有效 batch, 否则梯度累积会制造表面提升.

通信放在依赖图上才有意义. 梯度 all-reduce 能否与反向重叠, 取决于 bucket 何时就绪; pipeline bubble 取决于 microbatch 数与 stage 时间差; 数据加载只有在进入关键路径时才决定 step time. **总字节数相同不代表关键路径相同, 能被计算遮蔽的传输不能与裸通信时间直接相加.**

### 2.2. 推理必须分开 prefill 与 decode

prefill 一次处理 prompt 的多个 token, 矩阵乘法通常有较大的批维和序列维; decode 每一步只追加 token, 必须读取权重和历史 KV cache. 因此服务侧至少记录 time to first token、inter-token latency、输出 token/s、请求并发与尾延迟. 把 prefill 和 decode 平均后, 容易同时掩盖长 prompt 的首 token 延迟与长输出的逐 token 成本.

连续 batching、paged KV cache 与请求调度改变的是张量形状、驻留位置和执行顺序. 它们不会取消资源约束. 调度器提高并发后, 单卡总吞吐可能上升, 单请求延迟也可能因排队和批间干扰增加. 推理优化要同时给出吞吐曲线与延迟分位数, 并固定模型、精度、输入输出长度分布和硬件.

## 3. 阅读路线与证据口径

### 3.1. 先算一个小例子

工作量与资源模型中的矩阵乘例子给出 $F$、$Q$、$M$ 和 $T$；GPU 存储层次解释这些量如何落到单卡执行；集合通信再把相同单位延伸到设备间依赖。有 CUDA 与性能分析经验时可以直接进入 GPU 层次，但仍需沿用第一篇的单位定义，避免混用 GiB/s 与 GB/s、单向链路带宽与双向聚合带宽。

后续主题会沿着同一坐标扩展到并行训练、推理引擎、存储与数据管线、编译与 kernel、可靠性和成本. 每章新增系统对象时, 都要说明它改变了哪项工作量或资源约束, 是否移动了关键路径, 以及代价转移到了哪里.

### 3.2. 来源与测量

架构事实优先引用厂商编程指南和互连规范, 算法成本优先引用原论文, 软件行为引用对应版这里档. 厂商峰值只作为上界; 实测数字必须注明设备、驱动与软件版本、精度、shape、预热、重复次数和统计量. 多租户环境、功耗限制、时钟锁定和温度都会改变结果, 这些条件应与数字一起保存.

**一个可审查的性能结论必须允许另一位读者重建分子、分母与计时区间.** 如果只能看到「提速 30%」而看不到基线、工作负载和同步位置, 该数字不能进入跨方案比较. 工作量与资源模型的价值正是在优化前后保持同一口径, 让收益与转移出去的成本同时出现.

## 4. 工作量与资源模型怎样贯穿后续章节

### 4.1. 并行、推理与可靠性共享同一组量

并行训练会把单设备的张量生命周期切开. 数据并行引入梯度归约, 参数分片引入按需聚合, tensor parallel 在层内交换部分结果, pipeline parallel 在 stage 之间发送 activation. 比较这些方案时, 每卡容量只是第一列; 还要列每 step 通信 byte、集合算法轮次、可以遮蔽的比例与负载不均造成的 bubble. 一个方案能放下模型, 不代表它能在目标时间内完成 step.

推理引擎沿用相同方法. KV cache 先进入容量列, 每个 decode step 的读取进入流量列, attention 和线性层进入 FLOPs 列, 调度与排队进入时间列. 量化、prefix cache、speculative decoding 和模型并行改变的条目不同. 统一坐标让这些技术能够组合评估, 也能暴露某项优化把压力从 HBM 移到计算或网络的情况.

可靠性同样有资源成本. checkpoint 写入占用存储带宽, 冗余副本占用容量, 健康检查与重试占用计算和网络, 故障恢复时间进入服务可用性. 若只按无故障峰值规划, 大规模集群中少量慢节点就会把同步作业的尾延迟放大. 后续可靠性章节会把故障率、检测时间与恢复时间接到吞吐和成本模型上.

### 4.2. 成本最终来自资源乘时间

硬件成本不能只按 GPU 小时比较. 相同 GPU 小时可能产生不同有效 token, 训练作业还占用 CPU、内存、网络、对象存储与运维容量. 以每百万有效 token 成本为例, 分母要排除 padding 与失败重跑, 分子要包含整个作业边界. 推理则需要在目标延迟服务等级下比较单位请求或输出 token 成本, 不能用离线满批吞吐替代在线容量规划.

能耗可写成设备功率随时间的积分 $E=int P(t)dt$. 额定功耗不是实测能耗, 低利用率长时间运行也可能比高利用率短时间运行耗能更多. 若优化使 step 从 10 s 降到 8 s, 平均整机功率从 6 kW 升到 7 kW, 单 step 能量从 60 kJ 降到 56 kJ; 结论必须在相同有效工作量下成立.

**这座知识库最终要回答的是约束下的系统选择: 给定模型、数据、延迟目标、可靠性目标和预算, 哪种执行方案能用可复算的证据满足它们.** 工作量与资源模型提供共同语言, 实测提供校正, 依赖图决定哪些成本真正进入关键路径.
