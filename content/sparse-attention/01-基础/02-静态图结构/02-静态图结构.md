# 静态图结构: 窗口、全局与随机连接

稀疏 attention 最早遇到的困难并不神秘. 长度为 $n$ 的序列会产生 $n^2$ 个 query-key 配对, 序列翻倍, 配对数变成四倍. 直接删掉一部分配对很容易, 难的是决定删哪一部分. 只保留相邻 token, 远距离证据要经过很多层才能传过来; 放几个全局位置, 它们又可能同时承担检索、汇聚和广播; 随机连一些远端位置, 图直径会缩短, 但一次随机采样未必碰到任务真正需要的证据. **静态稀疏的核心工作是提前确定一张可执行的通信图, 再让内容决定保留边上的权重.**

主要材料来自 [Sparse Transformer](https://arxiv.org/abs/1904.10509) 及 [OpenAI 的实现说明](https://openai.com/index/sparse-transformer/), [Longformer](https://arxiv.org/abs/2004.05150) 与 [AllenAI 代码](https://github.com/allenai/longformer), [BigBird](https://arxiv.org/abs/2007.14062) 与 [Google Research 代码](https://github.com/google-research/bigbird), 以及 [StreamingLLM](https://arxiv.org/abs/2309.17453) 和 [MIT Han Lab 实现](https://github.com/mit-han-lab/streaming-llm). 这几条路线看起来分散, 实际上都在处理同一组约束: 每个 query 能读谁, 信息需要跨几层传递, 哪些 KV 可以释放, 最终又能否落成连续的矩阵块.

[静态拓扑](./01-静态拓扑.md)已经给出 attention 分数、softmax 和基础窗口公式. 静态图还要把逻辑邻接、跨层可达和硬件执行放进同一套分析. 这三项只要有一项没有说明白, 「线性 attention」就可能只存在于复杂度表里.

## 1. 一张 mask 同时规定计算量与通信路径

### 1.1. 邻接集合比稀疏率更有信息

令序列位置集合为 $V=\{0,1,\ldots,n-1\}$, 对每个 query 位置 $i$ 定义可读的 key 集合 $N(i)$. 若 $j\in N(i)$, 就画一条从 $j$ 指向 $i$ 的有向边. 方向表示位置 $j$ 的 Value 可以进入位置 $i$ 的输出. 单头 attention 写成:

$$
o_i=\sum_{j\in N(i)}
\frac{\exp(q_i^\top k_j/\sqrt{d_h})}
{\sum_{t\in N(i)}\exp(q_i^\top k_t/\sqrt{d_h})}v_j. \tag{1}
$$

静态图固定的是 $N(i)$, 式 (1) 中的分数仍随输入改变. 两个样本可以使用完全相同的边, 每条边的权重却不同. 这一区分很重要: 固定窗口没有把 attention 退化成卷积, 因为窗口内部仍在做内容相关的归一化与加权; 它只取消了窗口外的候选.

一层需要计算的逻辑边数为:

$$
|E|=\sum_{i=0}^{n-1}|N(i)|. \tag{2}
$$

若每行至多保留 $m$ 个 key, 式 (2) 的上界为 $nm$. 稀疏率 $|E|/n^2$ 只告诉我们删了多少边, 无法说明这些边连到了哪里. 一张只连接相邻位置的图与一张混入长边的图可以拥有相同的 $|E|$, 前者的两端通信可能要跨很多层, 后者可能两三层就能到达. **边数决定每层候选量, 边的落点决定有限深度内的信息可达性.**

causal 窗口的边数还能精确写开. 当 $n\ge w$ 时, 最初 $w$ 行的候选数依次为 $1,2,\ldots,w$, 后面每行固定为 $w$, 因而:

$$
|E_{\mathrm{causal}}|=\frac{w(w+1)}2+(n-w)w
=nw-\frac{w(w-1)}2.
$$

取 $n=12,w=4$, 因果稠密 attention 有 $12\times13/2=78$ 条边, 窗口保留 $42$ 条. $nw=48$ 是忽略序列开头边界的上界, 精确值少了 $6$ 条. 训练日志若只按 $nw$ 估算, 短序列或大窗口下的误差会很明显.

当 $n$ 远大于 $w$ 时, 窗口边数与因果稠密边数的比值约为 $2w/n$. 固定窗口下, 序列越长, 被保留的直接历史比例越低. 计算从平方级降到线性级的同时, 更大比例的远距依赖转为跨层传播, 这也是长序列质量不能只看每步 FLOPs 的原因.

编码器和 decoder 还使用不同的方向约束. 双向编码器可以同时保留 $i$ 左右两侧的位置. 自回归 decoder 必须满足 $j\le i$, 否则训练时会读到未来 token. global 或 random 只是额外的选边规则, 不能覆盖因果约束. 把双向 Longformer mask 原样装进 decoder, 即使 loss 正常下降, 训练结果也已经发生未来信息泄漏.

### 1.2. 连通性还要受模型深度约束

一层 attention 只能沿一条边搬运信息. 定义第 $0$ 层可达集合为 $R_0(i)=\{i\}$, 第 $\ell$ 层递推为:

$$
R_\ell(i)=\bigcup_{j\in N_\ell(i)}R_{\ell-1}(j). \tag{3}
$$

$N_\ell(i)$ 允许每层采用不同拓扑. 若所有层共享单侧半径为 $r$ 的双向窗口, 则 $R_L(i)$ 最多覆盖 $[i-Lr,i+Lr]$ 与合法位置的交集. 两个位置相距 $D$, 图上的最短传播层数至少为 $\lceil D/r\rceil$. 当 $r=2$, 相距 $11$ 个位置的证据至少需要 $6$ 层才能进入目标表示. 模型只有 $4$ 层时, 整张窗口图虽然连通, 目标位置依然读不到该证据.

残差连接会保留旧表示, 却不会添加新边. 多头 attention 可以让不同 head 使用不同邻接, 此时一层的有效拓扑是各 head 边集的并集, 但每个 head 仍受自己的投影维度和邻接限制. 下一层混合各 head 的输出后, 信息才可能从一个 head 的路径转到另一个 head. 因此「某个 head 有一条长边」只能证明存在一条通信入口, 无法证明所有信息都沿这条边稳定传递.

图直径描述任意节点对之间最短路径的最大值. 连续窗口的直径随 $n/r$ 增长; 增加一个双向 global 位置后, 普通位置之间通常可以通过两层完成中转. 同步更新要求按层计数: 在第 $1$ 层, global 位置从位置 $a$ 读取信息; 位置 $b$ 在同一层看到的仍是第 $0$ 层 global 表示. 到第 $2$ 层, $b$ 才能读到已经包含 $a$ 的 global 表示. 所以通信距离是两层, 不能按程序里的矩阵乘法顺序误算成一层.

图直径只描述最短路径. 每一次传播都包含投影、softmax 混合和有限维向量, 多条来源会在同一个表示里叠加. 一个 global token 可以让全图两跳可达, 其隐藏维度却没有随序列长度增长. 当许多段落都把细粒度证据压进同一个位置时, 最短路径很短, 信息容量依然可能不够. **可达性回答「有没有路」, 模型质量还取决于路上的带宽与训练是否学会使用这条路.**

### 1.3. 十二个位置的完整手算

取 $n=12$, 双向局部半径 $r=1$, 全局位置 $G=\{0\}$. 再给每个普通 query 加一条预先固定的随机长边. 为方便核对, 只列位置 $5$ 的邻接. 局部集合为 $\{4,5,6\}$, 全局集合为 $\{0\}$, 随机边指向位置 $10$, 因而:

$$
N(5)=\{0,4,5,6,10\}. \tag{4}
$$

假设这五条边的缩放后分数依次为 $[0,\ln 2,0,\ln 2,0]$. softmax 分母为 $1+2+1+2+1=7$, 权重依次为 $[1/7,2/7,1/7,2/7,1/7]$. 再令五个 Value 为 $v_0=(1,0)$, $v_4=(0,1)$, $v_5=(1,1)$, $v_6=(2,0)$, $v_{10}=(0,2)$. 位置 $5$ 的输出为:

$$
o_5=\frac17(1,0)+\frac27(0,1)+\frac17(1,1)+\frac27(2,0)+\frac17(0,2)
=\left(\frac67,\frac57\right). \tag{5}
$$

位置 $1,2,3,7,8,9,11$ 没有进入式 (5) 的分母和加权和. 如果位置 $11$ 保存了关键证据, 当前层无法凭内容相似度临时把它加入候选. 位置 $11$ 只能经局部边逐层靠近, 经它自己的随机边进入别处, 或先写入 global 位置再被位置 $5$ 读取. 静态图允许哪些路径, 训练只能在这些路径内分配权重.

再数边. 不加 global 和 random 时, 半径 $1$ 的十二位置窗口有 $12\times3-2=34$ 条有向边, 减去的是左右端各一条越界边. 把位置 $0$ 设为双向 global 后, 位置 $0$ 读取全部 $12$ 个位置, 其他 $11$ 个位置都读取位置 $0$. 这些边与原窗口有重叠, 所以精确计数要用集合并集, 不能直接把 $34+12+11$ 当结果. 再加入每行一条随机边时也要去重, 随机目标若已经位于窗口或 global 集合, 逻辑边数不会增加. 小图手算可以逐项核对同一个配置名背后的有效邻接、重复边和边界缺口.

## 2. 窗口、dilation、全局位置和随机块各管一件事

### 2.1. 窗口保留局部连续性

对双向窗口, 单侧半径为 $r$ 时:

$$
N_{\mathrm{win}}(i)=\{j:0\le j<n,\ |i-j|\le r\}. \tag{6}
$$

除去边界, 每行有 $2r+1$ 条边. 对 causal 窗口, 设可保留最近 $w$ 个位置, 邻接改为:

$$
N_{\mathrm{causal}}(i)=\{j:\max(0,i-w+1)\le j\le i\}. \tag{7}
$$

式 (7) 同时给出计算上界和 cache 上界. 到位置 $i$ 时, 小于 $i-w+1$ 的普通 KV 不再属于任何未来窗口, 可以释放. 这种确定性是滑动窗口最强的工程优势. 地址按连续区间增长, KV 可以放进环形缓冲区, 每一步覆盖最旧槽位, 无需维护任意索引集合.

窗口丢掉的是窗口外的一层直连. 对语言、音频和图像等具有局部连续性的输入, 邻近边通常值得保留, 但局部性不能自动覆盖所有任务. 文档开头的约束与末尾的结论、代码里的定义与远处调用、对话早期的身份信息与后续回复, 都可能跨出窗口. 增大 $w$ 会线性增加每行边数和 Decode 读取带宽; 依靠层数传播又要求中间位置持续保存并转发信息. 这两种成本需要分开衡量.

Sparse Transformer 将规则拓扑写成「strided」与「fixed」两类因子化模式, 把平方级 attention 降到约 $O(n\sqrt n)$. 以二维展开为例, 一部分 head 关注局部连续位置, 另一部分 head 按固定步长连接远处位置. 这样做保留了可预测布局, 也让远距通信不用完全依赖逐层局部传播. 它仍需要专门 kernel 才能跳过被删掉的矩阵块. 如果先算完整 attention 再置零, 因子化只改变输出, 不改变平方级点积.

### 2.2. dilation 用采样密度换覆盖跨度

dilation 在相同边数下拉大采样间距. 设步长为 $\delta$, 单侧保留 $r$ 个采样点:

$$
N_{\mathrm{dilated}}(i)=
\{i+k\delta:k\in[-r,r]\cap\mathbb{Z}\}\cap V. \tag{8}
$$

当 $r=2,\delta=3$ 时, 位置 $10$ 访问 $\{4,7,10,13,16\}$, 一层跨度达到 $6$, 仍只有五个候选. 代价也写在这组坐标里: 位置 $9$ 和 $11$ 没有直接边. dilation 改善的是几何覆盖, 没有免费获得连续局部细节.

所有层都使用相同 $\delta=3$ 会产生更严重的问题. 位置按模 $3$ 的余数分成三组, 边只在同余位置之间移动, 三组彼此断开. 混入 $\delta=1$ 的 head, 在不同层使用互质步长, 或增加 global 边, 才能让这些分量互相连通. 两层步长分别为 $\delta_1$ 与 $\delta_2$ 时, 可达位移形如 $k_1\delta_1+k_2\delta_2$, 其中 $|k_1|,|k_2|\le r$. 最大跨度很大, 不代表中间每个位置都能到达.

Longformer 把滑动窗口与 dilation 用在长文档编码, 并允许不同层或不同 head 配置不同窗口. 这种规则拓扑比任意逐 token 索引更容易实现, 但 dilation 对 kernel 仍有额外要求. AllenAI 提供的 `sliding_chunks` 路径使用常规 PyTorch 运算, 方便运行在 CPU、TPU 和 fp16 环境, 官方说明同时指出它使用约两倍内存, 不支持 dilation 和 autoregressive attention. 算法定义支持某项能力, 不表示仓库里的每条执行路径都支持它.

### 2.3. global 与 random 解决不同的远距通信

Longformer 的 global attention 由任务明确指定位置. 设全局集合为 $G$, 双向编码器中的邻接可写成:

$$
N(i)=
\begin{cases}
V,&i\in G,\\
N_{\mathrm{win}}(i)\cup G,&i\notin G.
\end{cases} \tag{9}
$$

分类任务可把分类位置设为 global, 问答任务可把问题 token 设为 global. 普通位置能直接读这些任务接口, global query 又能读取全文. 若全局位置数 $g=|G|$ 为常数, 额外边数约为 $O(ng)$, 总量保持线性. $g$ 随序列增长时, 这一项也会逐渐靠近平方级.

global 位置的优点是路径确定. 任何普通位置都知道去哪里汇聚和读取. 相应的代价是集中: 少量向量要承载全文通信, 选择规则也依赖任务结构. 如果关键信息没有被 global query 有效编码, 或新任务没有明确的汇聚位置, 两跳可达仍救不了表示质量. 增加 global 数量可以提高通信容量, 计算和显存也按 $ng$ 增长.

BigBird 采用局部 block、随机 block 和 global block 的组合. 随机边把长程入口分散到多个位置, 减少所有远距信息都经过同一组枢纽的压力. 它提供的是概率覆盖与较短的典型路径, 某个指定 query 仍可能错过指定证据. 通用逼近和图灵完备性的定理依赖 star graph、函数域、误差范数与数值精度等条件. 任意随机 mask 缺少这些前提时, 与稠密 attention 的表达关系需要重新分析.

随机连接通常在 block 级生成. 一个 query block 选中一个 key block 后, 两块内部往往计算完整的 $b\times b$ 配对. 若每块含 $b$ 个 token, 每个普通 query block 访问 $c$ 个局部块、$s$ 个随机块和 $g_b$ 个 global 块, block 数为 $B=\lceil n/b\rceil$, 普通部分的配对量约为:

$$
B(c+s+g_b)b^2. \tag{10}
$$

另有 global query block 读取全序列的开销. 固定 $b,c,s,g_b$ 时, 式 (10) 随 $n$ 线性增长. 逐 token 看, 其中会包含一些没有语义价值的块内配对; 换来的好处是能调用规则矩阵乘法. **随机 block 的价值不只是减少边, 还在于把随机性约束到硬件能够处理的粒度.**

把式 (10) 放进一个可核对的配置. 设序列被分成 $B=16$ 个 block, 每块 $b=64$ 个 token. 普通 query block 访问自己与左右邻块, 即 $c=3$; 随机访问 $s=2$ 个 block; 另有 $g_b=1$ 个 global block. 忽略集合重叠时, 一个普通 query block 访问 $6$ 个 key block, 产生 $6\times64^2=24576$ 个 token 配对. 全连接需要 $16\times64^2=65536$ 个配对, 普通 block 保留了 $37.5\%$ 的候选. 若一个 global query block 读取全部 $16$ 块, 总配对上界为:

$$
15\times24576+16\times64^2=434176. \tag{11}
$$

全连接的总量为 $(16\times64)^2=1048576$, 当前配置约保留 $41.4\%$. 真实数量会因 global、局部和随机集合重叠而下降. 随机采样代码若允许抽到自己、邻块或 global 块, 名义上的 $s=2$ 可能只增加零个或一个新 block. 实现通常会排除已有集合, 或在采样后去重补足, 两种做法产生的度分布并不相同.

随机边的方向也会改变预算. query block $u$ 选择 key block $v$, 只表示 $v$ 的信息可以进入 $u$; 若再强制 $v$ 选择 $u$, 每个节点的出入度更均匀, 边数也可能接近翻倍. 对双向编码器, 有向随机图本身合法, 对称化属于额外设计. 对 causal decoder, $u$ 只能选择编号不大于自己的历史 block, 靠近序列开头的 query 可选集合更小, 各位置的随机度天然不均. 这也是随机拓扑不能只报告「每块两条随机边」的原因.

## 3. 训练图与 Decode cache 必须一起设计

### 3.1. 训练时删边会改变模型学习到的路由

从头使用静态 mask 训练时, 参数会在允许的边上学习路由. 局部 head 可以逐层传递, global 位置可以承担汇聚, 随机块则形成固定或按规则变化的捷径. 直接给一个稠密 checkpoint 套上稀疏 mask, 会一次性删除训练中可能依赖的连接. 两个模型使用相同权重, 函数已经不同. 继续训练能否恢复取决于任务、稀疏程度和剩余路径, 不能只凭图连通判断.

训练配置需要保存窗口口径、每层 dilation、global 位置规则、block size、随机种子, 以及层号和 head 到邻接表的映射. 随机边若按 step 重采样, 模型面对的是变化的结构; 推理时固定一张图, 训练分布又会改变. 若训练和推理都固定, 模型可能适应该组捷径, 更换种子后质量仍可能变化. 因而随机拓扑至少要报告多组种子, 并区分「训练时固定」和「每步重采样」.

causal 训练还要验证每类边的方向. 局部边需要截断右侧, global query 只能读当前及过去位置, 随机目标也必须满足 $j\le i$. 一个常见错误是先生成双向 block 邻接, 再只对局部窗口施加下三角约束, 留下跨块的未来随机边. 小尺寸参考实现应显式生成 $n\times n$ 布尔 mask, 把稀疏输出和稠密 masked attention 的输出、梯度逐项比较. 只检查 loss 是否下降抓不住这类泄漏.

### 3.2. 一个 KV 能否删除, 由所有未来 query 决定

在 Decode 时间步 $t$, cache 已保存位置 $0$ 到 $t$ 的 K/V. 某个旧位置 $j$ 能够安全删除, 条件是后续任何可能出现的 query 都不会再访问它:

$$
\forall i>t,\quad j\notin N(i). \tag{12}
$$

式 (12) 比「当前 query 没用到 $j$」严格得多. 当前步没有访问某个 KV, 后续层、其他 head 或未来 token 仍可能访问. 固定 causal 窗口满足清晰的淘汰规律: 当 $j<t-w+1$ 时, 后续窗口只会继续向右移动, $j$ 永远退出邻接, 因而可以释放. KV cache 维持 $O(w)$ 个位置, Decode 每步也只读取最近 $w$ 个 KV.

global 位置需要单独保留. 若所有未来 query 都能访问开头的若干 global token, 这些位置直到序列结束都不能淘汰. cache 上界变为「常驻 global 集合 + 最近窗口」. 随机边更麻烦: 如果未来 query 的随机目标可以落到任意历史位置, 当前无法证明某个旧 KV 永远不会再被选中, cache 仍可能随序列增长. 随机规则给出有限回看范围, 或提前生成整段邻接并计算每块末次被访问的时间后, 系统就能按式 (12) 安全释放.

块级 cache 还存在粒度差异. 一个 block 中只要有一个 token 以后仍会被访问, 整块 K/V 往往都要保留, 否则会破坏连续布局. 逻辑上按 token 删除与物理上按 page 或 block 回收, 得到的内存上界不同. Page 大小、block size 和拓扑的回看范围需要同时记录, 否则「窗口为 4096」无法直接推出显存中只存在 4096 个有效槽位.

给每个 KV 定义末次访问时间:

$$
\tau(j)=\max\{i:j\in N(i)\}. \tag{13}
$$

Decode 完成位置 $t$ 且 $\tau(j)\le t$ 后, 位置 $j$ 进入可回收集合. causal 窗口的 $\tau(j)=j+w-1$, 再与序列终点取较小值. 常驻 global 的 $\tau(j)$ 等于序列终点; 在线流式生成没有预先给定终点时, 可以视为无穷. 固定随机图若覆盖整段最大长度, $\tau(j)$ 可以离线计算并按时间排序; 随生成动态采样随机目标时, 未来邻接未知, 末次访问时间也无法提前确定.

拓扑只回答 KV 是否还会被访问, 位置编码决定保存下来的 KV 还能否按原方式使用. KV 若已经融合绝对位置或 RoPE 旋转, 淘汰中间 token 后直接把剩余 cache 重新编号, 会改变 query-key 的相对相位. 保持原位置编号又可能超过模型训练过的位置范围. 环形缓冲区可以覆盖物理槽位, 逻辑位置却不能跟着槽位编号循环. 工程实现需要明确 cache position、RoPE 处理和淘汰操作的顺序, 并用未淘汰的完整参考计算核对窗口内输出.

Prefill 与 Decode 对同一邻接也有不同压力. Prefill 同时包含许多 query, 大块窗口和随机 block 能形成足够大的矩阵乘法; 每个 KV 还会被多个 query 复用. Decode 每步通常只有一个 query, 计算量下降后, 从 HBM 读取窗口 KV 和启动 kernel 的时间更突出. static graph 能预生成索引, 但随机 gather 仍会破坏连续读. 因此 Prefill 上明显加速的 block 布局, 到 Decode 可能只减少算术, 没有同比减少时延.

### 3.3. StreamingLLM 说明简单截断为什么会坏

StreamingLLM 研究的是已经用有限上下文训练好的生成模型. 最直接的窗口策略只保留最近 $w$ 个 KV, 一旦序列超过 cache, 最早位置全部丢弃. 论文观察到许多模型会把较高 attention 权重分给开头 token, 即使这些 token 的语义并不重要. 把开头位置全部删掉后, attention 分布和语言模型困惑度会明显恶化.

它使用「初始 attention sink + 最近窗口」的静态保留模式. 设常驻 sink 数量为 $s$, 最近窗口为 $w$, 时间步为 $t$, cache 位置集合可写成:

$$
C_t=\{0,1,\ldots,s-1\}\cup
\{\max(s,t-w+1),\ldots,t\}. \tag{14}
$$

当 $t$ 足够大时, cache 大小稳定在约 $s+w$. 中间历史被删除, 初始 sink 一直保留. 模型只识别 sinks 和最近 token, 丢掉的中间内容不会变成长程记忆. 这套方法能在不反复重算窗口 KV 的情况下持续生成, 无法用来完整总结一部长书.

这个例子也修正了一个过于粗糙的判断: causal 窗口有界, 不代表把任意已训练模型的 KV 直接截成最近窗口就能保持质量. cache 生命周期既受未来邻接约束, 也受训练分布和模型已经形成的 attention 行为约束. 从头训练带固定窗口的模型、给稠密模型做窗口化继续训练、在现有模型上保留 sinks, 三者的图看起来接近, 训练条件和可删状态却不同.

## 4. 逻辑稀疏要穿过 block、padding 与 kernel

### 4.1. token 边数和物理 tile 数并不相等

GPU attention kernel 通常按 tile 处理一块 query 和一块 key. 设 query tile 高度为 $B_q$, key tile 宽度为 $B_k$. 只要某个逻辑边落进 tile 对 $(u,v)$, 朴素 block-sparse 实现就可能计算该 tile 内全部 $B_qB_k$ 个分数. 定义非空 tile 集为 $T$, 物理候选量近似为:

$$
E_{\mathrm{phys}}=|T|B_qB_k. \tag{15}
$$

tile 利用率则为:

$$
\rho=\frac{|E|}{|T|B_qB_k}. \tag{16}
$$

连续窗口会形成规则带状 tile, 边界处有少量多算. 任意随机逐 token 边可能让大量 tile 只含一两个有效配对, $|E|$ 很小, $|T|$ 却接近稠密. 这种布局的 gather、索引和低利用率会吞掉理论节省. 随机性收敛到 block 级后, 每个选中 tile 都较满, 更容易兑现算力收益.

用一个小例子核对式 (16). 序列长度 $n=16$, tile 为 $4\times4$, 每个 query 只访问自己和前一个 token, 逻辑边数为 $16+15=31$. 四个对角 tile 已覆盖全部 self 边和块内前驱边, 另外三个下方相邻 tile 各承载一条跨块前驱边, 因而 $|T|=7$. 物理候选量为 $7\times16=112$, 利用率只有 $31/112\approx27.7\%$. 若 kernel 支持带状边界的细粒度处理, 可以减少多算; 只会整 tile GEMM 的实现则要接受这部分浪费.

把窗口扩大到与 tile 对齐并不一定增加相同比例的 tile 数. 反过来, 窗口只增加一个 token, 也可能越过 tile 边界, 让每个 query tile 多读一个 key tile. 性能曲线因此常呈阶梯状, 而不是随逻辑边数平滑变化. 调窗口时需要同时打印非零 tile 数、有效 token 配对数和 padding 比例.

多头布局还会影响 tile 复用. 所有 head 共用一张静态图时, 邻接元数据可复用, 相同 query-key block 也更容易批量执行. 每个 head 使用独立随机图会扩大边集覆盖, kernel 却需要处理更多索引组合, 小矩阵数量随之增加. 一种折中是让一组 head 共用局部窗口, 另一组 head 共用若干随机模式; 这样仍能增加跨区路径, 调度组合数不会按 head 数线性增长.

数值稳定性也不能从稀疏率推出. 每行候选数变化时, softmax 的归一化集合跟着变化. 边界 query、靠近序列开头的 causal query 和普通内部 query 可能拥有不同度数. kernel 若假设固定 block 数, 需要用 mask 清除 padding block 与越界位置; 被 mask 的分数必须在 softmax 前排除, 不能在得到概率后再把 Value 贡献置零. 后一种写法会让无效位置占用概率质量, 输出与式 (1)不一致.

### 4.2. Longformer 与 BigBird 代码展示了三种执行口径

AllenAI 的 Longformer 仓库提供 `n2`、`tvm` 和 `sliding_chunks` 三条 attention 路径. `n2` 走常规平方实现, 可用来做正确性参考; `tvm` 使用定制 CUDA kernel 跳过窗口外计算; `sliding_chunks` 通过重叠分块调用常规张量运算, 更容易部署, 但官方列出的限制包括约两倍内存、不支持 dilation 与 autoregressive attention. 三条路径可以表达相近的窗口输出, 运行时间、内存和功能范围并不相同.

`sliding_chunks` 还要求把序列 pad 到窗口相关的整数倍. 假设真实长度为 $4100$, 对齐后长度为 $4608$ 或其他实现要求的边界, 多出的 token 虽由 padding mask 排除语义, 仍可能占据张量和 tile. 批次中样本长度差异较大时, 按最长样本统一 pad 会进一步降低利用率. 报告吞吐时只写「4096 窗口」不够, 还要给真实长度分布和对齐后的 shape.

Google Research 的 BigBird 代码把 `attention_type` 分成 `original_full`、`simulated_sparse` 和 `block_sparse`. `simulated_sparse` 适合核对稀疏 mask 的数学结果, 未必减少平方计算; `block_sparse` 才是按块执行的稀疏实现. 官方配置说明当前代码采用三个窗口块、两个 global 块和可配置的随机块数, 并受静态 tensor shape 约束. BigBird 算法本身允许其他 block 配置, 实际范围由对应实现决定.

这两个仓库共同说明了「支持稀疏 mask」与「运行稀疏 kernel」之间的距离. 单元测试可以让稠密参考与稀疏输出一致, 性能验收还要确认执行图没有物化完整 $n\times n$ 分数, profiler 中没有平方级中间张量, HBM 读取也随保留 block 数下降. **mask 对齐稠密参考解决函数正确性, kernel 跳过空 tile 才会降低系统成本.**

### 4.3. 反向传播与分布式切分还有第二份成本

训练需要为反向传播保存或重算 softmax 相关状态. 稀疏边减少分数数量, Q、K、V 投影、残差流和前馈层激活仍按序列长度存在. Sparse Transformer 还专门使用 attention matrix recomputation 降低显存: 前向不长期保存所有 attention 权重, 反向时再计算. 这会减少激活占用, 代价是增加计算. 因此训练显存下降不能全部归因于边数, checkpoint 或 recomputation 策略也要列入对照.

反向的稀疏访问方向与前向不同. 前向按 query 行读取若干 key block, 计算 $\nabla K$ 与 $\nabla V$ 时则要累加所有指向同一个 key block 的 query 贡献. 规则窗口的入边也呈带状, 随机图的入度可能不均匀, 同一个 key block 会接收来自多个不连续 query block 的写入. kernel 可以用转置邻接、分段归约或原子累加处理, 每种方式都有额外元数据或同步成本. 前向速度相近的两张图, 反向时可能因入度分布不同拉开差距.

global block 在反向中尤其集中. 所有普通 query 都读取 global K/V, 相应梯度会汇入少数位置; global query 又读取完整序列. 分布式训练若把 global block 放在单个 rank, 该 rank 还会承担聚合热点. 复制 global 表示可以把读取摊开, 梯度仍需归并. 因此 global 数量同时影响图带宽、单卡显存和跨卡归约, 不能只按前向的 $ng$ 点积计费.

随机索引本身需要存储和生成. 静态 shape 下可以预先生成邻接表, 编译或缓存 kernel 调度; 输入长度变化时, block 数和边界处理也会变化. 各层各 head 使用不同随机图能提高覆盖, 邻接元数据随层数与 head 数增长. 元数据通常小于 KV, 在短序列、小 block 或极稀疏配置下却可能成为不可忽略的启动和访存开销.

序列并行会把拓扑边变成通信需求. 局部窗口主要访问相邻 shard, 可以用 halo exchange 处理; global 位置若由单个 rank 持有, 其他 rank 需要读写这些表示; 随机 block 跨设备时会形成不规则 gather. 单卡边数没有包含这些链路字节. 分布式实现若为了简化通信复制 global KV, 设备间通信下降, 每卡常驻内存则增加. 选拓扑时要把跨 rank 边数和 token 边数放在一起统计.

## 5. 选型从依赖形状出发, 验收落到可复现的小图

### 5.1. 四类边放在同一组约束下比较

| 结构 | 每行或每块预算 | 远距离通信 | KV 生命周期 | kernel 规律性 | 主要损失 |
|---|---:|---|---|---|---|
| 连续 causal 窗口 | 最近 $w$ 个位置 | 约需 $\lceil D/(w-1)\rceil$ 层传播 | 旧 KV 可确定淘汰 | 高 | 窗口外直连消失 |
| dilation 窗口 | $2r+1$ 个采样位置 | 跨度增大, 可达性取决于步长组合 | 由末次访问时间决定 | 较高 | 中间位置可能遗漏 |
| 局部加 global | $w+g$ 及 global 全读 | 普通位置通常两层中转 | global KV 常驻, 普通窗口 KV 可淘汰 | 中等 | 枢纽容量与 $ng$ 成本 |
| 局部加随机 block | $c+s+g_b$ 个块 | 典型路径缩短, 单次连接无确定覆盖 | 取决于未来随机规则 | 中等 | 块内多算、种子波动与不规则通信 |

表中四种结构没有统一胜者. 依赖以邻近内容为主、服务又要求稳定延迟上限时, 连续窗口的地址与 cache 最干净. 文档任务拥有明确的分类位置、问题区段或控制 token 时, global 边能把任务先验直接写进通信图. 依赖分散在未知位置, 同时又不希望增加太多集中枢纽时, 随机块可以增加远距入口, 但要接受概率覆盖和多种子评测.

dilation 适合在固定边数下扩大几何跨度, 条件是其他层或其他 head 能补齐采样空隙. 它不能替代局部连续窗口, 也不能像任务 global 那样保证所有位置经同一接口通信. 实际模型经常混合几类边, 原因就在于它们解决的问题不同. 增大窗口改善局部传播半径, 增加 global 位置提高确定的汇聚带宽, 增加 random block 扩散远端入口. 三个参数一起改, 质量变化就很难归因.

### 5.2. 从一个布尔矩阵验收到完整服务

最小正确性用长度 $8$ 或 $16$ 的序列就够. 生成完整布尔邻接矩阵, 逐行打印 $N(i)$, 检查边界窗口是否少一侧、dilation 是否产生预期余数类、global 边是否双向、causal 条件是否覆盖所有额外边. 再用同一 mask 调稠密 attention 作为参考, 与稀疏实现比较前向输出、Q/K/V 梯度和参数梯度. 随机拓扑固定种子后, 两次运行的邻接和数值都应一致.

第二层检查可达集合. 按式 (3) 迭代 $L$ 次, 对每个目标位置统计在模型实际层数内可读到哪些原始位置. 长距离评测应按图上的最短路径分桶, 不能只按 token 距离分桶. 两个证据都离答案位置很远时, 还要检查它们能否在有限层内先汇合到同一表示, 因为「各自可达答案」与「能在同一层联合推理」并非同一个条件.

系统验收再把逻辑邻接映射到执行. 记录 $|E|$、非空 tile 数 $|T|$、式 (16) 的利用率、真实长度与 padded 长度、峰值显存、HBM 读取、attention kernel 时间和端到端时延. Prefill 与 Decode 分开测: Prefill 有许多 query, 更容易把 block-sparse GEMM 跑满; Decode 每步只有少量 query, 经常受 KV 读取和 kernel 启动支配. 同一拓扑在两个阶段可能需要不同 kernel.

边界样本比随机长序列更容易暴露错误. 序列长度小于窗口时, 稀疏结果应退化成合法方向上的完整 attention; 长度刚好跨过一个 block 边界时, 新增 tile 与 padding 数应符合预期; random 候选集合被局部和 global 集合占满时, 实现需要给出去重后的真实度数. global 位置落在 padding 区、一个 batch 内各样本 global 数量不同、末块只有一个有效 token, 都应与逐元素参考 mask 对齐. 这些案例还能发现 softmax 前后 mask 顺序、越界 block 和错误复用随机邻接等问题.

吞吐测试也要固定比较口径. batch token 数、有效序列长度、padded 长度、dtype、head 维度和 KV 布局保持一致, 再分别改变窗口、global 数或 random block 数. 端到端时间还应拆出投影、attention、通信和前馈网络占比. attention kernel 提速一倍, 若它只占整层时间的四分之一, 整层收益就远小于一倍; 稀疏化把瓶颈转移到前馈网络后, 继续删边也不会带来相同比例的吞吐提升.

### 5.3. 几条容易误判的边界

边数从 $n^2$ 降到 $nw$ 后, 投影层和前馈网络没有变. 序列较短时, attention 原本就不是主要瓶颈, 稀疏索引反而会增加开销. 交叉点取决于设备、dtype、head 维度、batch、block size 和实现, 不能从渐近复杂度直接得到固定长度阈值. 代码仓库给出的经验阈值只适用于对应版本和硬件条件.

图可达也无法证明模型学会使用长路径. 质量测试至少要覆盖局部依赖、单个远距证据、多个分散证据、序列边界和超出窗口的历史引用. 对 global 结构要改变 global 位置数量和语义, 对 random 结构要更换种子, 对窗口结构要改变证据距离. 若边数下降而质量只在远距桶恶化, 问题多半来自传播路径; 若逻辑边少而时延不降, 应检查 tile 利用率、padding 和稠密回退.

Decode cache 的淘汰策略应能用式 (12)解释, 再由实际 cache 页面计数验证. 未来邻接仍可能访问的位置一旦被删除, 模型函数随之改变; 拓扑允许删除时, 还要检查已训练模型是否像 StreamingLLM 暴露的 attention sink 那样依赖特定常驻位置. **完整的静态图设计同时交代邻接规则、有限层可达、KV 末次访问时间和物理 tile 布局.**
