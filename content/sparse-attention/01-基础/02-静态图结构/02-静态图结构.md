# 静态图结构: 窗口、全局与随机连接

稀疏 attention 最早遇到的困难并不神秘. 长度为 $n$ 的序列会产生 $n^2$ 个 query-key 配对, 序列翻倍, 配对数变成四倍. 直接删掉一部分配对很容易, 难的是决定删哪一部分. 只保留相邻 token, 远距离证据要经过很多层才能传过来; 放几个全局位置, 它们又可能同时承担检索、汇聚和广播; 随机连一些远端位置, 图直径会缩短, 但一次随机采样未必碰到任务真正需要的证据. **静态稀疏的核心工作是提前确定一张可执行的通信图, 再让内容决定保留边上的权重.**

主要材料来自 [Sparse Transformer](https://arxiv.org/abs/1904.10509) 及 [OpenAI 的实现说明](https://openai.com/index/sparse-transformer/), [Longformer](https://arxiv.org/abs/2004.05150) 与 [AllenAI 代码](https://github.com/allenai/longformer), [BigBird](https://arxiv.org/abs/2007.14062) 与 [Google Research 代码](https://github.com/google-research/bigbird), 以及 [StreamingLLM](https://arxiv.org/abs/2309.17453) 和 [MIT Han Lab 实现](https://github.com/mit-han-lab/streaming-llm). 这几条路线看起来分散, 实际上都在处理同一组约束: 每个 query 能读谁, 信息需要跨几层传递, 哪些 KV 可以释放, 最终又能否落成连续的矩阵块.

[静态拓扑](./01-静态拓扑.md)已经给出 attention 分数、softmax 和基础窗口公式. 静态图还要把逻辑邻接、跨层可达和硬件执行接成一条完整链路. 这三项只要有一项没有说清, 「线性 attention」就可能只存在于复杂度表里.

## 1. 一张 mask 同时规定计算量与通信路径

### 1.1. 邻接集合比稀疏率更有信息

令序列位置集合为 $V=\{0,1,\ldots,n-1\}$, 对每个 query 位置 $i$ 定义可读的 key 集合 $N(i)$. 若 $j\in N(i)$, 就画一条从 $j$ 指向 $i$ 的有向边. 方向表示位置 $j$ 的 Value 可以进入位置 $i$ 的输出. 单头 attention 写成:

$$
o_i=\sum_{j\in N(i)}
\frac{\exp(q_i^\top k_j/\sqrt{d_h})}
{\sum_{t\in N(i)}\exp(q_i^\top k_t/\sqrt{d_h})}v_j. \tag{1}
$$

静态图固定的是 $N(i)$, 式 (1) 中的分数仍随输入改变. 两个样本可以使用完全相同的边, 每条边的权重却不同. 这一区分很重要: 固定窗口没有把 attention 退化成卷积, 因为窗口内部仍在做内容相关的归一化与加权; 它只取消了窗口外的候选.

一层需要计算的逻辑边数为:

$$
|E|=\sum_{i=0}^{n-1}|N(i)|. \tag{2}
$$

若每行至多保留 $m$ 个 key, 式 (2) 的上界为 $nm$. 稀疏率 $|E|/n^2$ 只告诉我们删了多少边, 无法说明这些边连到了哪里. 一张只连接相邻位置的图与一张混入长边的图可以拥有相同的 $|E|$, 前者的两端通信可能要跨很多层, 后者可能两三层就能到达. **边数决定每层候选量, 边的落点决定有限深度内的信息可达性.**

causal 窗口的边数还能精确写开. 当 $n\ge w$ 时, 最初 $w$ 行的候选数依次为 $1,2,\ldots,w$, 后面每行固定为 $w$, 因而:

$$
|E_{\mathrm{causal}}|=\frac{w(w+1)}2+(n-w)w
=nw-\frac{w(w-1)}2.
$$

取 $n=12,w=4$, 因果稠密 attention 有 $12\times13/2=78$ 条边, 窗口保留 $42$ 条. $nw=48$ 是忽略序列开头边界的上界, 精确值少了 $6$ 条. 训练日志若只按 $nw$ 估算, 短序列或大窗口下的误差会很明显.

当 $n$ 远大于 $w$ 时, 窗口边数与因果稠密边数的比值约为 $2w/n$. 固定窗口下, 序列越长, 被保留的直接历史比例越低. 计算从平方级降到线性级的同时, 更大比例的远距依赖转为跨层传播, 这也是长序列质量不能只看每步 FLOPs 的原因.

编码器和 decoder 还使用不同的方向约束. 双向编码器可以同时保留 $i$ 左右两侧的位置. 自回归 decoder 必须满足 $j\le i$, 否则训练时会读到未来 token. global 或 random 只是额外的选边规则, 不能覆盖因果约束. 把双向 Longformer mask 原样装进 decoder, 即使 loss 正常下降, 训练结果也已经发生未来信息泄漏.

### 1.2. 连通性还要受模型深度约束

一层 attention 只能沿一条边搬运信息. 定义第 $0$ 层可达集合为 $R_0(i)=\{i\}$, 第 $\ell$ 层递推为:

$$
R_\ell(i)=\bigcup_{j\in N_\ell(i)}R_{\ell-1}(j). \tag{3}
$$

$N_\ell(i)$ 允许每层采用不同拓扑. 若所有层共享单侧半径为 $r$ 的双向窗口, 则 $R_L(i)$ 最多覆盖 $[i-Lr,i+Lr]$ 与合法位置的交集. 两个位置相距 $D$, 图上的最短传播层数至少为 $\lceil D/r\rceil$. 当 $r=2$, 相距 $11$ 个位置的证据至少需要 $6$ 层才能进入目标表示. 模型只有 $4$ 层时, 整张窗口图虽然连通, 目标位置依然读不到该证据.

残差连接会保留旧表示, 却不会添加新边. 多头 attention 可以让不同 head 使用不同邻接, 此时一层的有效拓扑是各 head 边集的并集, 但每个 head 仍受自己的投影维度和邻接限制. 下一层混合各 head 的输出后, 信息才可能从一个 head 的路径转到另一个 head. 因此「某个 head 有一条长边」只能证明存在一条通信入口, 无法证明所有信息都沿这条边稳定传递.

图直径描述任意节点对之间最短路径的最大值. 连续窗口的直径随 $n/r$ 增长; 增加一个双向 global 位置后, 普通位置之间通常可以通过两层完成中转. 同步更新要求按层计数: 在第 $1$ 层, global 位置从位置 $a$ 读取信息; 位置 $b$ 在同一层看到的仍是第 $0$ 层 global 表示. 到第 $2$ 层, $b$ 才能读到已经包含 $a$ 的 global 表示. 所以通信距离是两层, 不能按程序里的矩阵乘法顺序误算成一层.

图直径只描述最短路径. 每一次传播都包含投影、softmax 混合和有限维向量, 多条来源会在同一个表示里叠加. 一个 global token 可以让全图两跳可达, 其隐藏维度却没有随序列长度增长. 当许多段落都把细粒度证据压进同一个位置时, 最短路径很短, 信息容量依然可能不够. **可达性回答「有没有路」, 模型质量还取决于路上的带宽与训练是否学会使用这条路.**

### 1.3. 十二个位置的完整手算

取 $n=12$, 双向局部半径 $r=1$, 全局位置 $G=\{0\}$. 再给每个普通 query 加一条预先固定的随机长边. 为方便核对, 只列位置 $5$ 的邻接. 局部集合为 $\{4,5,6\}$, 全局集合为 $\{0\}$, 随机边指向位置 $10$, 因而:

$$
N(5)=\{0,4,5,6,10\}. \tag{4}
$$

假设这五条边的缩放后分数依次为 $[0,\ln 2,0,\ln 2,0]$. softmax 分母为 $1+2+1+2+1=7$, 权重依次为 $[1/7,2/7,1/7,2/7,1/7]$. 再令五个 Value 为 $v_0=(1,0)$, $v_4=(0,1)$, $v_5=(1,1)$, $v_6=(2,0)$, $v_{10}=(0,2)$. 位置 $5$ 的输出为:

$$
o_5=\frac17(1,0)+\frac27(0,1)+\frac17(1,1)+\frac27(2,0)+\frac17(0,2)
=\left(\frac67,\frac57\right). \tag{5}
$$

位置 $1,2,3,7,8,9,11$ 没有进入式 (5) 的分母和加权和. 如果位置 $11$ 保存了关键证据, 当前层无法凭内容相似度临时把它加入候选. 位置 $11$ 只能经局部边逐层靠近, 经它自己的随机边进入别处, 或先写入 global 位置再被位置 $5$ 读取. 静态图允许哪些路径, 训练只能在这些路径内分配权重.

再数边. 不加 global 和 random 时, 半径 $1$ 的十二位置窗口有 $12\times3-2=34$ 条有向边, 减去的是左右端各一条越界边. 把位置 $0$ 设为双向 global 后, 位置 $0$ 读取全部 $12$ 个位置, 其他 $11$ 个位置都读取位置 $0$. 这些边与原窗口有重叠, 所以精确计数要用集合并集, 不能直接把 $34+12+11$ 当结果. 再加入每行一条随机边时也要去重, 随机目标若已经位于窗口或 global 集合, 逻辑边数不会增加. 小图手算可以逐项核对同一个配置名背后的有效邻接、重复边和边界缺口.

## 2. 窗口、dilation、全局位置和随机块各管一件事

### 2.1. 窗口保留局部连续性

对双向窗口, 单侧半径为 $r$ 时:

$$
N_{\mathrm{win}}(i)=\{j:0\le j<n,\ |i-j|\le r\}. \tag{6}
$$

除去边界, 每行有 $2r+1$ 条边. 对 causal 窗口, 设可保留最近 $w$ 个位置, 邻接改为:

$$
N_{\mathrm{causal}}(i)=\{j:\max(0,i-w+1)\le j\le i\}. \tag{7}
$$

式 (7) 同时给出计算上界和 cache 上界. 到位置 $i$ 时, 小于 $i-w+1$ 的普通 KV 不再属于任何未来窗口, 可以释放. 这种确定性是滑动窗口最强的工程优势. 地址按连续区间增长, KV 可以放进环形缓冲区, 每一步覆盖最旧槽位, 无需维护任意索引集合.

窗口丢掉的是窗口外的一层直连. 对语言、音频和图像等具有局部连续性的输入, 邻近边通常值得保留, 但局部性不能自动覆盖所有任务. 文档开头的约束与末尾的结论、代码里的定义与远处调用、对话早期的身份信息与后续回复, 都可能跨出窗口. 增大 $w$ 会线性增加每行边数和 Decode 读取带宽; 依靠层数传播又要求中间位置持续保存并转发信息. 这两种成本需要分开衡量.

Sparse Transformer 将规则拓扑写成「strided」与「fixed」两类因子化模式, 把平方级 attention 降到约 $O(n\sqrt n)$. 以二维展开为例, 一部分 head 关注局部连续位置, 另一部分 head 按固定步长连接远处位置. 这样做保留了可预测布局, 也让远距通信不用完全依赖逐层局部传播. 它仍需要专门 kernel 才能跳过被删掉的矩阵块. 如果先算完整 attention 再置零, 因子化只改变输出, 不改变平方级点积.

### 2.2. dilation 用采样密度换覆盖跨度

dilation 在相同边数下拉大采样间距. 设步长为 $\delta$, 单侧保留 $r$ 个采样点:

$$
N_{\mathrm{dilated}}(i)=
\{i+k\delta:k\in[-r,r]\cap\mathbb{Z}\}\cap V. \tag{8}
$$

当 $r=2,\delta=3$ 时, 位置 $10$ 访问 $\{4,7,10,13,16\}$, 一层跨度达到 $6$, 仍只有五个候选. 代价也写在这组坐标里: 位置 $9$ 和 $11$ 没有直接边. dilation 改善的是几何覆盖, 没有免费获得连续局部细节.

所有层都使用相同 $\delta=3$ 会产生更严重的问题. 位置按模 $3$ 的余数分成三组, 边只在同余位置之间移动, 三组彼此断开. 混入 $\delta=1$ 的 head, 在不同层使用互质步长, 或增加 global 边, 才能打通这些分量. 两层步长分别为 $\delta_1$ 与 $\delta_2$ 时, 可达位移形如 $k_1\delta_1+k_2\delta_2$, 其中 $|k_1|,|k_2|\le r$. 最大跨度很大, 不代表中间每个位置都能到达.

Longformer 把滑动窗口与 dilation 用在长文档编码, 并允许不同层或不同 head 配置不同窗口. 这种规则拓扑比任意逐 token 索引更容易实现, 但 dilation 对 kernel 仍有额外要求. AllenAI 提供的 `sliding_chunks` 路径使用常规 PyTorch 运算, 方便运行在 CPU、TPU 和 fp16 环境, 官方说明同时指出它使用约两倍内存, 不支持 dilation 和 autoregressive attention. 算法定义支持某项能力, 不表示仓库里的每条执行路径都支持它.

### 2.3. global 与 random 解决不同的远距通信

Longformer 的 global attention 由任务明确指定位置. 设全局集合为 $G$, 双向编码器中的邻接可写成:

$$
N(i)=
\begin{cases}
V,&i\in G,\\
N_{\mathrm{win}}(i)\cup G,&i\notin G.
\end{cases} \tag{9}
$$

分类任务可把分类位置设为 global, 问答任务可把问题 token 设为 global. 普通位置能直接读这些任务接口, global query 又能读取全文. 若全局位置数 $g=|G|$ 为常数, 额外边数约为 $O(ng)$, 总量保持线性. $g$ 随序列增长时, 这一项也会逐渐靠近平方级.

global 位置的优点是路径确定. 任何普通位置都知道去哪里汇聚和读取. 相应的代价是集中: 少量向量要承载全文通信, 选择规则也依赖任务结构. 如果关键信息没有被 global query 有效编码, 或新任务没有明确的汇聚位置, 两跳可达仍救不了表示质量. 增加 global 数量可以提高通信容量, 计算和显存也按 $ng$ 增长.

BigBird 采用局部 block、随机 block 和 global block 的组合. 随机边把长程入口分散到多个位置, 减少所有远距信息都经过同一组枢纽的压力. 它提供的是概率覆盖与较短的典型路径, 某个指定 query 仍可能错过指定证据. 通用逼近和图灵完备性的定理依赖 star graph、函数域、误差范数与数值精度等条件. 任意随机 mask 缺少这些前提时, 与稠密 attention 的表达关系需要重新分析.

随机连接通常在 block 级生成. 一个 query block 选中一个 key block 后, 两块内部往往计算完整的 $b\times b$ 配对. 若每块含 $b$ 个 token, 每个普通 query block 访问 $c$ 个局部块、$s$ 个随机块和 $g_b$ 个 global 块, block 数为 $B=\lceil n/b\rceil$, 普通部分的配对量约为:

$$
B(c+s+g_b)b^2. \tag{10}
$$

另有 global query block 读取全序列的开销. 固定 $b,c,s,g_b$ 时, 式 (10) 随 $n$ 线性增长. 逐 token 看, 其中会包含一些没有语义价值的块内配对; 换来的好处是能调用规则矩阵乘法. **随机 block 的价值不只是减少边, 还在于把随机性约束到硬件能够处理的粒度.**

把式 (10) 放进一个可核对的配置. 设序列被分成 $B=16$ 个 block, 每块 $b=64$ 个 token. 普通 query block 访问自己与左右邻块, 即 $c=3$; 随机访问 $s=2$ 个 block; 另有 $g_b=1$ 个 global block. 忽略集合重叠时, 一个普通 query block 访问 $6$ 个 key block, 产生 $6\times64^2=24576$ 个 token 配对. 全连接需要 $16\times64^2=65536$ 个配对, 普通 block 保留了 $37.5\%$ 的候选. 若一个 global query block 读取全部 $16$ 块, 总配对上界为:

$$
15\times24576+16\times64^2=434176. \tag{11}
$$

全连接的总量为 $(16\times64)^2=1048576$, 当前配置约保留 $41.4\%$. 真实数量会因 global、局部和随机集合重叠而下降. 随机采样代码若允许抽到自己、邻块或 global 块, 名义上的 $s=2$ 可能只增加零个或一个新 block. 实现通常会排除已有集合, 或在采样后去重补足, 两种做法产生的度分布并不相同.

随机边的方向也会改变预算. query block $u$ 选择 key block $v$, 只表示 $v$ 的信息可以进入 $u$; 若再强制 $v$ 选择 $u$, 每个节点的出入度更均匀, 边数也可能接近翻倍. 对双向编码器, 有向随机图本身合法, 对称化属于额外设计. 对 causal decoder, $u$ 只能选择编号不大于自己的历史 block, 靠近序列开头的 query 可选集合更小, 各位置的随机度天然不均. 这也是随机拓扑不能只报告「每块两条随机边」的原因.

## 3. 训练图与 Decode cache 必须一起设计

### 3.1. 训练时删边会改变模型学习到的路由

从头使用静态 mask 训练时, 参数会在允许的边上学习路由. 局部 head 可以逐层传递, global 位置可以承担汇聚, 随机块则形成固定或按规则变化的捷径. 直接给一个稠密 checkpoint 套上稀疏 mask, 会一次性删除训练中可能依赖的连接. 两个模型使用相同权重, 函数已经不同. 继续训练能否恢复取决于任务、稀疏程度和剩余路径, 不能只凭图连通判断.

训练配置需要保存窗口口径、每层 dilation、global 位置规则、block size、随机种子, 以及层号和 head 到邻接表的映射. 随机边若按 step 重采样, 模型面对的是变化的结构; 推理时固定一张图, 训练分布又会改变. 若训练和推理都固定, 模型可能适应该组捷径, 更换种子后质量仍可能变化. 因而随机拓扑至少要报告多组种子, 并区分「训练时固定」和「每步重采样」.

causal 训练还要验证每类边的方向. 局部边需要截断右侧, global query 只能读当前及过去位置, 随机目标也必须满足 $j\le i$. 一个常见错误是先生成双向 block 邻接, 再只对局部窗口施加下三角约束, 留下跨块的未来随机边. 小尺寸参考实现应显式生成 $n\times n$ 布尔 mask, 把稀疏输出和稠密 masked attention 的输出、梯度逐项比较. 只检查 loss 是否下降抓不住这类泄漏.

### 3.2. 一个 KV 能否删除, 由所有未来 query 决定

在 Decode 时间步 $t$, cache 已保存位置 $0$ 到 $t$ 的 K/V. 某个旧位置 $j$ 能够安全删除, 条件是后续任何可能出现的 query 都不会再访问它:

$$
\forall i>t,\quad j\notin N(i). \tag{12}
$$

式 (12) 比「当前 query 没用到 $j$」严格得多. 当前步没有访问某个 KV, 后续层、其他 head 或未来 token 仍可能访问. 固定 causal 窗口满足清晰的淘汰规律: 当 $j<t-w+1$ 时, 后续窗口只会继续向右移动, $j$ 永远退出邻接, 因而可以释放. KV cache 维持 $O(w)$ 个位置, Decode 每步也只读取最近 $w$ 个 KV.

global 位置需要单独保留. 若所有未来 query 都能访问开头的若干 global token, 这些位置直到序列结束都不能淘汰. cache 上界变为「常驻 global 集合 + 最近窗口」. 随机边更麻烦: 如果未来 query 的随机目标可以落到任意历史位置, 当前无法证明某个旧 KV 永远不会再被选中, cache 仍可能随序列增长. 随机规则给出有限回看范围, 或提前生成整段邻接并计算每块末次被访问的时间后, 系统就能按式 (12) 安全释放.

块级 cache 还存在粒度差异. 一个 block 中只要有一个 token 以后仍会被访问, 整块 K/V 往往都要保留, 否则会破坏连续布局. 逻辑上按 token 删除与物理上按 page 或 block 回收, 得到的内存上界不同. Page 大小、block size 和拓扑的回看范围需要同时记录, 否则「窗口为 4096」无法直接推出显存中只存在 4096 个有效槽位.

给每个 KV 定义末次访问时间:

$$
\tau(j)=\max\{i:j\in N(i)\}. \tag{13}
$$

Decode 完成位置 $t$ 且 $\tau(j)\le t$ 后, 位置 $j$ 进入可回收集合. causal 窗口的 $\tau(j)=j+w-1$, 再与序列终点取较小值. 常驻 global 的 $\tau(j)$ 等于序列终点; 在线流式生成没有预先给定终点时, 可以视为无穷. 固定随机图若覆盖整段最大长度, $\tau(j)$ 可以离线计算并按时间排序; 随生成动态采样随机目标时, 未来邻接未知, 末次访问时间也无法提前确定.

拓扑只回答 KV 是否还会被访问, 位置编码决定保存下来的 KV 还能否按原方式使用. KV 若已经融合绝对位置或 RoPE 旋转, 淘汰中间 token 后直接把剩余 cache 重新编号, 会改变 query-key 的相对相位. 保持原位置编号又可能超过模型训练过的位置范围. 环形缓冲区可以覆盖物理槽位, 逻辑位置却不能跟着槽位编号循环. 工程实现需要明确 cache position、RoPE 处理和淘汰操作的顺序, 并用未淘汰的完整参考计算核对窗口内输出.

Prefill 与 Decode 对同一邻接也有不同压力. Prefill 同时包含许多 query, 大块窗口和随机 block 能形成足够大的矩阵乘法; 每个 KV 还会被多个 query 复用. Decode 每步通常只有一个 query, 计算量下降后, 从 HBM 读取窗口 KV 和启动 kernel 的时间更突出. static graph 能预生成索引, 但随机 gather 仍会破坏连续读. 因此 Prefill 上明显加速的 block 布局, 到 Decode 可能只减少算术, 没有同比减少时延.

### 3.3. StreamingLLM 说明简单截断为什么会坏

StreamingLLM 研究的是已经用有限上下文训练好的生成模型. 最直接的窗口策略只保留最近 $w$ 个 KV, 一旦序列超过 cache, 最早位置全部丢弃. 论文观察到许多模型会把较高 attention 权重分给开头 token, 即使这些 token 的语义并不重要. 把开头位置全部删掉后, attention 分布和语言模型困惑度会明显恶化.

它使用「初始 attention sink + 最近窗口」的静态保留模式. 设常驻 sink 数量为 $s$, 最近窗口为 $w$, 时间步为 $t$, cache 位置集合可写成:

$$
C_t=\{0,1,\ldots,s-1\}\cup
\{\max(s,t-w+1),\ldots,t\}. \tag{14}
$$

当 $t$ 足够大时, cache 大小稳定在约 $s+w$. 中间历史被删除, 初始 sink 一直保留. 模型只识别 sinks 和最近 token, 丢掉的中间内容不会变成长程记忆. 这套方法能在不反复重算窗口 KV 的情况下持续生成, 无法用来完整总结一部长书.

这个例子也修正了一个过于粗糙的判断: causal 窗口有界, 不代表把任意已训练模型的 KV 直接截成最近窗口就能保持质量. cache 生命周期既受未来邻接约束, 也受训练分布和模型已经形成的 attention 行为约束. 从头训练带固定窗口的模型、给稠密模型做窗口化继续训练、在现有模型上保留 sinks, 三者的图看起来接近, 训练条件和可删状态却不同.

## 4. 逻辑稀疏要穿过 block、padding 与 kernel

### 4.1. token 边数和物理 tile 数并不相等

GPU attention kernel 通常按 tile 处理一块 query 和一块 key. 设 query tile 高度为 $B_q$, key tile 宽度为 $B_k$. 只要某个逻辑边落进 tile 对 $(u,v)$, 朴素 block-sparse 实现就可能计算该 tile 内全部 $B_qB_k$ 个分数. 定义非空 tile 集为 $T$, 物理候选量近似为:

$$
E_{\mathrm{phys}}=|T|B_qB_k. \tag{15}
$$

tile 利用率则为:

$$
\rho=\frac{|E|}{|T|B_qB_k}. \tag{16}
$$

连续窗口会形成规则带状 tile, 边界处有少量多算. 任意随机逐 token 边可能让大量 tile 只含一两个有效配对, $|E|$ 很小, $|T|$ 却接近稠密. 这种布局的 gather、索引和低利用率会吞掉理论节省. 随机性收敛到 block 级后, 每个选中 tile 都较满, 更容易兑现算力收益.

用一个小例子核对式 (16). 序列长度 $n=16$, tile 为 $4\times4$, 每个 query 只访问自己和前一个 token, 逻辑边数为 $16+15=31$. 四个对角 tile 已覆盖全部 self 边和块内前驱边, 另外三个下方相邻 tile 各承载一条跨块前驱边, 因而 $|T|=7$. 物理候选量为 $7\times16=112$, 利用率只有 $31/112\approx27.7\%$. 若 kernel 支持带状边界的细粒度处理, 可以减少多算; 只会整 tile GEMM 的实现则要接受这部分浪费.

把窗口扩大到与 tile 对齐并不一定增加相同比例的 tile 数. 反过来, 窗口只增加一个 token, 也可能越过 tile 边界, 让每个 query tile 多读一个 key tile. 性能曲线因此常呈阶梯状, 而不是随逻辑边数平滑变化. 调窗口时需要同时打印非零 tile 数、有效 token 配对数和 padding 比例.

多头布局还会影响 tile 复用. 所有 head 共用一张静态图时, 邻接元数据可复用, 相同 query-key block 也更容易批量执行. 每个 head 使用独立随机图会扩大边集覆盖, kernel 却需要处理更多索引组合, 小矩阵数量随之增加. 一种折中是让一组 head 共用局部窗口, 另一组 head 共用若干随机模式; 这样仍能增加跨区路径, 调度组合数不会按 head 数线性增长.

数值稳定性也不能从稀疏率推出. 每行候选数变化时, softmax 的归一化集合跟着变化. 边界 query、靠近序列开头的 causal query 和普通内部 query 可能拥有不同度数. kernel 若假设固定 block 数, 需要用 mask 清除 padding block 与越界位置; 被 mask 的分数必须在 softmax 前排除, 不能在得到概率后再把 Value 贡献置零. 后一种写法会让无效位置占用概率质量, 输出与式 (1)不一致.

### 4.2. Longformer 与 BigBird 代码展示了三种执行口径

AllenAI 的 Longformer 仓库提供 `n2`、`tvm` 和 `sliding_chunks` 三条 attention 路径. `n2` 走常规平方实现, 可用来做正确性参考; `tvm` 使用定制 CUDA kernel 跳过窗口外计算; `sliding_chunks` 通过重叠分块调用常规张量运算, 更容易部署, 但官方列出的限制包括约两倍内存、不支持 dilation 与 autoregressive attention. 三条路径可以表达相近的窗口输出, 运行时间、内存和功能范围并不相同.

`sliding_chunks` 还要求把序列 pad 到窗口相关的整数倍. 假设真实长度为 $4100$, 对齐后长度为 $4608$ 或其他实现要求的边界, 多出的 token 虽由 padding mask 排除语义, 仍可能占据张量和 tile. 批次中样本长度差异较大时, 按最长样本统一 pad 会进一步降低利用率. 报告吞吐时只写「4096 窗口」不够, 还要给真实长度分布和对齐后的 shape.

Google Research 的 BigBird 代码把 `attention_type` 分成 `original_full`、`simulated_sparse` 和 `block_sparse`. `simulated_sparse` 适合核对稀疏 mask 的数学结果, 未必减少平方计算; `block_sparse` 才是按块执行的稀疏实现. 官方配置说明当前代码采用三个窗口块、两个 global 块和可配置的随机块数, 并受静态 tensor shape 约束. BigBird 算法本身允许其他 block 配置, 实际范围由对应实现决定.

这两个仓库共同说明了「支持稀疏 mask」与「运行稀疏 kernel」之间的距离. 单元测试可以让稠密参考与稀疏输出一致, 性能验收还要确认执行图没有物化完整 $n\times n$ 分数, profiler 中没有平方级中间张量, HBM 读取也随保留 block 数下降. **mask 对齐稠密参考解决函数正确性, kernel 跳过空 tile 才会降低系统成本.**

### 4.3. 反向传播与分布式切分还有第二份成本

训练需要为反向传播保存或重算 softmax 相关状态. 稀疏边减少分数数量, Q、K、V 投影、残差流和前馈层激活仍按序列长度存在. Sparse Transformer 还专门使用 attention matrix recomputation 降低显存: 前向不长期保存所有 attention 权重, 反向时再计算. 这会减少激活占用, 代价是增加计算. 因此训练显存下降不能全部归因于边数, checkpoint 或 recomputation 策略也要列入对照.

反向的稀疏访问方向与前向不同. 前向按 query 行读取若干 key block, 计算 $\nabla K$ 与 $\nabla V$ 时则要累加所有指向同一个 key block 的 query 贡献. 规则窗口的入边也呈带状, 随机图的入度可能不均匀, 同一个 key block 会接收来自多个不连续 query block 的写入. kernel 可以用转置邻接、分段归约或原子累加处理, 每种方式都有额外元数据或同步成本. 前向速度相近的两张图, 反向时可能因入度分布不同拉开差距.

global block 在反向中尤其集中. 所有普通 query 都读取 global K/V, 相应梯度会汇入少数位置; global query 又读取完整序列. 分布式训练若把 global block 放在单个 rank, 该 rank 还会承担聚合热点. 复制 global 表示可以把读取摊开, 梯度仍需归并. 因此 global 数量同时影响图带宽、单卡显存和跨卡归约, 不能只按前向的 $ng$ 点积计费.

随机索引本身需要存储和生成. 静态 shape 下可以预先生成邻接表, 编译或缓存 kernel 调度; 输入长度变化时, block 数和边界处理也会变化. 各层各 head 使用不同随机图能提高覆盖, 邻接元数据随层数与 head 数增长. 元数据通常小于 KV, 在短序列、小 block 或极稀疏配置下却可能成为不可忽略的启动和访存开销.

序列并行会把拓扑边变成通信需求. 局部窗口主要访问相邻 shard, 可以用 halo exchange 处理; global 位置若由单个 rank 持有, 其他 rank 需要读写这些表示; 随机 block 跨设备时会形成不规则 gather. 单卡边数没有包含这些链路字节. 分布式实现若为了简化通信复制 global KV, 设备间通信下降, 每卡常驻内存则增加. 选拓扑时要把跨 rank 边数和 token 边数放在一起统计.

## 5. 选型从依赖形状出发, 验收落到可复现的小图

### 5.1. 四类边放在同一组约束下比较

| 结构 | 每行或每块预算 | 远距离通信 | KV 生命周期 | kernel 规律性 | 主要损失 |
|---|---:|---|---|---|---|
| 连续 causal 窗口 | 最近 $w$ 个位置 | 约需 $\lceil D/(w-1)\rceil$ 层传播 | 旧 KV 可确定淘汰 | 高 | 窗口外直连消失 |
| dilation 窗口 | $2r+1$ 个采样位置 | 跨度增大, 可达性取决于步长组合 | 由末次访问时间决定 | 较高 | 中间位置可能遗漏 |
| 局部加 global | $w+g$ 及 global 全读 | 普通位置通常两层中转 | global KV 常驻, 普通窗口 KV 可淘汰 | 中等 | 枢纽容量与 $ng$ 成本 |
| 局部加随机 block | $c+s+g_b$ 个块 | 典型路径缩短, 单次连接无确定覆盖 | 取决于未来随机规则 | 中等 | 块内多算、种子波动与不规则通信 |

表中四种结构没有统一胜者. 依赖以邻近内容为主、服务又要求稳定延迟上限时, 连续窗口的地址与 cache 最干净. 文档任务拥有明确的分类位置、问题区段或控制 token 时, global 边能把任务先验直接写进通信图. 依赖分散在未知位置, 同时又不希望增加太多集中枢纽时, 随机块可以增加远距入口, 但要接受概率覆盖和多种子评测.

dilation 适合在固定边数下扩大几何跨度, 条件是其他层或其他 head 能补齐采样空隙. 它不能替代局部连续窗口, 也不能像任务 global 那样保证所有位置经同一接口通信. 实际模型经常混合几类边, 原因就在于它们解决的问题不同. 增大窗口改善局部传播半径, 增加 global 位置提高确定的汇聚带宽, 增加 random block 扩散远端入口. 三个参数一起改, 质量变化就很难归因.

### 5.2. 从一个布尔矩阵验收到完整服务

最小正确性用长度 $8$ 或 $16$ 的序列就够. 生成完整布尔邻接矩阵, 逐行打印 $N(i)$, 检查边界窗口是否少一侧、dilation 是否产生预期余数类、global 边是否双向、causal 条件是否覆盖所有额外边. 再用同一 mask 调稠密 attention 作为参考, 与稀疏实现比较前向输出、Q/K/V 梯度和参数梯度. 随机拓扑固定种子后, 两次运行的邻接和数值都应一致.

第二层检查可达集合. 按式 (3) 迭代 $L$ 次, 对每个目标位置统计在模型实际层数内可读到哪些原始位置. 长距离评测应按图上的最短路径分桶, 不能只按 token 距离分桶. 两个证据都离答案位置很远时, 还要检查它们能否在有限层内先汇合到同一表示, 因为「各自可达答案」与「能在同一层联合推理」并非同一个条件.

系统验收再把逻辑邻接映射到执行. 记录 $|E|$、非空 tile 数 $|T|$、式 (16) 的利用率、真实长度与 padded 长度、峰值显存、HBM 读取、attention kernel 时间和端到端时延. Prefill 与 Decode 分开测: Prefill 有许多 query, 更容易把 block-sparse GEMM 跑满; Decode 每步只有少量 query, 经常受 KV 读取和 kernel 启动支配. 同一拓扑在两个阶段可能需要不同 kernel.

边界样本比随机长序列更容易暴露错误. 序列长度小于窗口时, 稀疏结果应退化成合法方向上的完整 attention; 长度刚好跨过一个 block 边界时, 新增 tile 与 padding 数应符合预期; random 候选集合被局部和 global 集合占满时, 实现需要给出去重后的真实度数. global 位置落在 padding 区、一个 batch 内各样本 global 数量不同、末块只有一个有效 token, 都应与逐元素参考 mask 对齐. 这些案例还能发现 softmax 前后 mask 顺序、越界 block 和错误复用随机邻接等问题.

吞吐测试也要固定比较口径. batch token 数、有效序列长度、padded 长度、dtype、head 维度和 KV 布局保持一致, 再分别改变窗口、global 数或 random block 数. 端到端时间还应拆出投影、attention、通信和前馈网络占比. attention kernel 提速一倍, 若它只占整层时间的四分之一, 整层收益就远小于一倍; 稀疏化把瓶颈转移到前馈网络后, 继续删边也不会带来相同比例的吞吐提升.

### 5.3. 几条容易误判的边界

边数从 $n^2$ 降到 $nw$ 后, 投影层和前馈网络没有变. 序列较短时, attention 原本就不是主要瓶颈, 稀疏索引反而会增加开销. 交叉点取决于设备、dtype、head 维度、batch、block size 和实现, 不能从渐近复杂度直接得到固定长度阈值. 代码仓库给出的经验阈值只适用于对应版本和硬件条件.

图可达也无法证明模型学会使用长路径. 质量测试至少要覆盖局部依赖、单个远距证据、多个分散证据、序列边界和超出窗口的历史引用. 对 global 结构要改变 global 位置数量和语义, 对 random 结构要更换种子, 对窗口结构要改变证据距离. 若边数下降而质量只在远距桶恶化, 问题多半来自传播路径; 若逻辑边少而时延不降, 应检查 tile 利用率、padding 和稠密回退.

Decode cache 的淘汰策略应能用式 (12)解释, 再由实际 cache 页面计数验证. 未来邻接仍可能访问的位置一旦被删除, 模型函数随之改变; 拓扑允许删除时, 还要检查已训练模型是否像 StreamingLLM 暴露的 attention sink 那样依赖特定常驻位置. **完整的静态图设计同时交代邻接规则、有限层可达、KV 末次访问时间和物理 tile 布局.**

## 6. 用构造规则定义静态图

给出一张长度固定的 mask 很容易，真正的模型定义必须回答任意长度 $n$、任意层 $\ell$ 和任意 head $h$ 时怎样生成邻接。把构造器写成

$$
\mathcal G(n,\ell,h,\theta,\xi)\longrightarrow N_{\ell,h}^{(n)}(i),
$$

其中 $\theta$ 表示窗口、block size、global 位置等确定参数，$\xi$ 表示随机种子。拓扑族由规则定义，某个长度上的邻接矩阵只是实例。随机图还要给出种子、采样空间、排除集合和去重规则；「随机连接」四个字缺少生成一张图所需的信息。

### 6.1. 长度扩展需要满足一致性

假设模型在 4K 上训练、准备扩到 16K。窗口规则天然具有前缀一致性：生成 16K 图后截取前 4K，局部边与直接生成 4K 图相同。随机 block 若按总 block 数均匀采样，长度改变会改变归一化范围；即使前 4K 内容完全相同，它们的随机邻居也可能整体重排。模型看到的旧前缀通信图随最大长度变化，这是一种隐藏的分布转移。

可以要求构造器满足前缀一致性：对 $n_1<n_2$，长图限制在前 $n_1$ 个节点后，与短图相同。基于位置哈希生成候选，再过滤越界位置，是一种可行办法；直接用伪随机数生成器连续抽样，结果是否一致取决于遍历顺序和 rejection sampling 次数。前缀一致并非所有任务都必需，却应明确记录。否则，同一句输入仅因服务端配置了更大的最大长度，就可能采用另一张随机图。

Block size 改变时，一致性更难保持。长度 4096、block 64 得到 64 个节点，block 128 只剩 32 个节点；相同随机 block 编号代表不同 token 区间。若研究问题是块大小本身的影响，应该先构造 token 级目标分布，再分别投影到两种 block 划分，或者承认拓扑与粒度同时改变。只保持「每块两个随机邻居」没有控制实际 token 距离和覆盖概率。

窗口扩展也有两种口径。每个 query 固定读 $w$ 个 token，长度越大时局部比例下降；窗口按 $n$ 的比例增长，边数又从 $O(n)$ 逐渐回到 $O(n^2)$。实验声称能扩展到更长上下文时，需要说明保持的是绝对窗口、稀疏率还是每层 FLOPs。三者不可能同时保持。

### 6.2. 并集、优先级和重复边必须有确定语义

混合拓扑通常从多个生成器取得候选：局部集合 $L(i)$、全局集合 $G(i)$、随机集合 $R(i)$ 与结构集合 $S(i)$。最终邻接可以写为

$$
N(i)=L(i)\cup G(i)\cup R(i)\cup S(i).
$$

集合并集意味着重复候选只保留一次。若实现把各类候选直接拼接，重复 key 会在 softmax 中出现两次。相同 logit 被复制后得到两份指数项，相当于人为提高该 key 的概率质量。这个错误不会产生 NaN，输出还能正常训练，却已经不再对应集合定义。

随机预算在去重前还是去重后计数，也会改变图。先抽 $s$ 个 block 再去重，真实新增度数是随机变量；排除局部与 global 集合后反复抽到 $s$ 个新 block，度数固定，但采样分布变成条件分布。靠近序列开头的 causal query 候选少，甚至没有 $s$ 个合法新 block，此时要缩小度数、重复已有边还是启用 fallback，也必须固定。

结构边之间若有优先级，可以把预算写成逐步填充。先保留不可删的局部边和任务 global，再从剩余容量里放随机边；或者固定各类独立预算，让总度数随重叠变化。前一种保持总成本，后一种保持各路覆盖尝试。论文只给总稀疏率时，无法判断采用了哪种语义。

Self edge 也不能省略说明。某些实现依赖残差保存当前 token，因此 mask 不含 $i\to i$；另一些实现把 self 放进 attention 候选。两者都可运行，但 softmax 分母、边数和全 mask 行的处理不同。极小长度、全局位置与 padding 组合时，遗漏 self 可能产生没有合法 key 的 query，softmax 全是负无穷，最终得到 NaN。

### 6.3. 静态图可以按层变化

「静态」表示邻接不依赖当前 Q/K 内容，不要求所有层使用同一张图。令相邻层采用不同 stride、不同窗口宽度或不同随机种子，可以让图的复合覆盖远大于单层。跨层可达由邻接矩阵的布尔乘积决定：

$$
A_{1:L}=A_L\odot A_{L-1}\odot\cdots\odot A_1,
$$

其中布尔乘法把普通乘法换成逻辑与，把求和换成逻辑或。$[A_{1:L}]_{ij}=1$ 表示位置 $j$ 的信息存在一条长度不超过相应层数的路径到达位置 $i$。普通矩阵幂 $A^L$ 只适用于每层同图，层间变化时不能偷换。

周期性调度可以减少需要保存的拓扑元数据。例如四层为一个周期：两层局部、一层 dilation、一层带 global。周期重复后，长程信息每四层获得一次跨区机会。若模型深度不是周期整数倍，尾部多出的局部层只加工已经到达的信息，不会再开辟远路。层数消融必须保留完整周期，随意截断会同时改变深度和图组成。

随机图按层独立采样时，多层并集覆盖增加；全部层共享同一随机图时，模型更容易适应稳定捷径，覆盖增长却受限。二者的元数据、可复现性和训练难度也不同。可以用相同的总随机边数比较「少数层各有大量随机边」与「每层少量独立随机边」，前者单层候选竞争更强，后者需要更多跳数，却把入口铺在整个深度上。

### 6.4. 因果图应在展开后的时间轴上检查

只验证邻接矩阵下三角还不够。多种特殊节点会改变时间语义：段落摘要何时生成，global 槽位何时允许读入内容，下一位置何时能读取更新后的摘要。把同一位置在不同层写成节点 $(i,\ell)$，attention 边从 $(j,\ell-1)$ 指向 $(i,\ell)$，残差边从 $(i,\ell-1)$ 指向 $(i,\ell)$，因果性要求所有 attention 边满足 $j\le i$。

如果摘要 token 放在段尾，它能够汇聚该段历史，后续 token 可以读取；段首摘要无法在单次左到右生成中预先知道段内未来内容。训练时一次并行计算整段，也不能绕开这个时间限制，因为 causal mask 仍限制段首 query。双向编码器中的全局节点可以先读取全文再广播，自回归 decoder 中的固定开头 sink 只能提供一个被所有位置读取的锚点，这两个 global 机制在图上完全不同。

分层摘要还要计算等待时间。一段有 $b$ 个 token，段尾摘要在位置 $b-1$ 生成；章节摘要若位于若干段之后，最早也要等这些段完成。面向流式输入的模型只能用已经闭合的段摘要，当前未结束段仍靠局部窗口。由此得到的 cache 生命周期和离线文档编码不同，不能用同一张无向层级图概括。

## 7. 随机连接的收益是概率命题

随机边的直觉常被压缩成「少量长边把图直径降下来」。这句话缺少三个变量：从哪个分布抽边、每个节点抽多少条、保证针对平均节点对还是最坏节点对。BigBird 把随机边与窗口、global 边合在一起；理论结论落在组合图上，不能删掉确定性骨架后仍照搬。

### 7.1. 一个指定证据被直接抽中的概率

对 causal query 位置 $i$，假设局部窗口外还有 $M$ 个合法历史 block，从中不放回均匀抽取 $s$ 个随机 block。某个指定证据 block 被直接选中的概率为

$$
P(\text{hit})=\frac{s}{M}.
$$

当 $M=1000,s=4$ 时，直接命中概率只有 $0.4\%$。随机边的价值显然不主要来自每个 query 都直接撞到答案，而是许多节点、多层和局部传播共同形成捷径。若任务必须读取唯一且位置未知的远端证据，单层随机命中率就是很严格的提醒。

证据占据 $m$ 个 block 时，不命中任何证据的概率为

$$
P(0)=\frac{\binom{M-m}{s}}{\binom{M}{s}},
$$

命中率为 $1-P(0)$。证据跨度增大，命中机会随之提高；这意味着随机稀疏在「答案线索散布一大片」与「答案只藏在一个短字符串」上的表现可能完全不同。评测只报告平均上下文长度，会掩盖证据占据的 block 数。

多个 head 或多层独立抽样时，如果把每次抽样近似看作独立，至少一次直接命中的概率为 $1-(1-s/M)^K$，$K$ 是独立抽样次数。共享随机图让 $K$ 不随层数增加；不同层独立图才增加命中机会。实际存在排除集合、边界和路径中继，精确概率会变化，这个近似仍能揭示种子共享为何是模型定义的一部分。

### 7.2. 均匀抽 token、均匀抽 block 与均匀抽距离

三种「均匀」产生不同偏置。均匀抽历史 token 时，每个 token 概率相同，距离为 $d$ 的单点概率不随 $d$ 变；把距离按线性区间统计，远区间因为包含更多 token 获得更多总概率。均匀抽 block 类似，但短尾块的 token 被命中概率更高或更低，取决于选中后是否整块计算。

均匀抽距离桶则先将距离分成若干尺度，例如 $[1,2),[2,4),[4,8)$，再在桶内选位置。每个尺度获得相近预算，单个远端 token 的概率更低。对依赖分布跨多个尺度的任务，这种 log-uniform 规则可能比全历史均匀更合适；它已经不是 BigBird 中任意随机块的同义替换，需要独立验证。

固定每个 query 的出度，不会固定每个 key 的入度。均匀随机图中，部分 key block 会被许多 query 读取，部分几乎无人读取。入度高的节点在反向时形成归约热点，也更容易成为信息广播点。可以限制入度或构造近似正则图，但限制后各 query 的边不再独立，采样算法与图性质都改变。

随机边对位置的分布还受 causal 候选数量影响。早期 query 历史短，排除局部窗口后几乎无处可抽；后期 query 候选巨大。若强行维持固定 $s$，早期边会大量重复或落进局部集合。按实际新增边计费时，序列前部度数较小。这个不均匀性应保留在小图参考中，不能先生成双向正则图再简单砍掉上三角。

### 7.3. 随机捷径仍要经过模型深度

假设证据 block $a$ 没有被目标 $z$ 直接抽中，却被中间 block $u$ 抽中，而 $u$ 又能通过局部或随机边到达 $z$。这条路径至少需要两层；若边方向是 key 到 query，还要确保 $a<u<z$。无向小世界图中的短路径可能来回穿越时间，自回归模型只能使用单调向后的有向路径。

对某个固定 $L$，最相关的量是 $L$ 层可达率，而非无限步连通率。可以从每个目标 query 反向扩展邻居，计算 $|R_L(i)|/i$；再统计远距证据到达目标所需的最小层数分布。平均图直径下降不保证 32 层模型覆盖所有节点，因为最坏路径和尾部分位数可能仍很长。

多层随机扩展近似分支过程：忽略重叠时，每层有 $s$ 条新远边，可达节点数可能按 $s^L$ 增长；真实图很快遇到重复、局部聚团和边界，增长会饱和。可达数量大也没有保证包含任务指定证据。把证据位置在全序列均匀采样，得到的是平均覆盖；把证据放在最难到达区间，测的是最坏情况，两者都需要。

### 7.4. 随机种子方差本身就是结果

同一权重更换 mask 种子，衡量模型对当前路径的依赖；不同种子各自从头训练，衡量方法作为训练方案的方差。这两项不能混合。前者下降可能来自模型熟悉了固定邻接指纹，后者方差则包含训练随机性和图随机性。

至少应同时报告图统计和任务统计。图统计包括实际新增度数、入度分布、$L$ 层可达率、最短路径分位数与最小割；任务统计按种子给均值、标准差和最差值。只选一个效果最好的种子，会把随机搜索预算隐藏进方法结果。

随机 mask 若在每个 batch 重采样，还会改变优化噪声。相同样本两次出现时能走的路径不同，模型被迫减少对单条捷径的依赖；另一方面，关键证据有时根本不可达，梯度目标本身带结构噪声。训练时重采样、推理固定一张图，等于从图分布切换到单个实例。推理时集成多张图能减小方差，却会增加计算并改变边预算。

## 8. KV 回收是未来邻接上的活跃性分析

Global、dilation 和跨层访问会让部分旧 token 在最近窗口之外继续存活。编译器会跟踪仍可能被读取的活跃变量，KV cache 也适用同一判据。位置 $j$ 仍会被未来 query 读取时保持活跃，最后一次读取结束后死亡；$\tau(j)$ 记录该时刻。

### 8.1. 单层规则的末次访问时间

对宽度 $w$ 的 causal 窗口，未来位置 $i$ 读取 $j$ 当且仅当 $j\le i\le j+w-1$，因此

$$
\tau(j)=\min(n-1,j+w-1).
$$

处理完 query $i$ 后，所有满足 $\tau(j)\le i$ 的普通 KV 都可释放。在线无限流里没有 $n-1$，公式退化为 $j+w-1$。这给出严格的环形 cache：写入新 KV 前，被覆盖槽位对应的位置已经离开所有未来窗口。

若 dilation 只访问偏移 $0,\delta,2\delta,\ldots,r\delta$，位置 $j$ 最晚可能被 $j+r\delta$ 读取，但只有与 $j$ 同余的未来 query 会读取它。cache 仍可在 $r\delta$ 后释放，期间的访问呈稀疏周期。物理实现若只支持连续窗口，为了保留这些离散位置可能把整个区间都留在内存，逻辑活跃集大小是 $r+1$，物理覆盖跨度却是 $r\delta+1$。

多种固定偏移并集 $D$ 的末次访问为 $j+\max D$，前提是所有未来层都使用相同单层规则。若每层拓扑不同，Decode 时每一层拥有自己的 KV cache；第 $\ell$ 层位置 $j$ 的死亡时间由未来第 $\ell$ 层 query 邻接决定，不应把所有层的最大回看范围强加给每层。分层窗口可让部分层使用小 cache、少数远距层保留更长 cache。

Global key 的末次访问取决于读它的 query。开头 sink 被所有未来位置读取，在线流中永不死亡；段落摘要只供接下来 $q$ 段读取，关闭窗口后可以释放。Global query 读取普通 key，只影响普通 key 是否要活到该 global query 出现。一旦摘要完成且原 token 不再被其他未来 query 读取，原段 KV 就能释放，只留下摘要。这是一种确定的状态压缩协议。

### 8.2. 图上可删除不等于状态可恢复

删除 KV 后，未来输出仍可能通过已经生成的中间表示受到它影响。窗口模型每一步把历史混入当前 token，旧信息理论上能够沿 token 链向前传播；释放原始 KV 不会抹掉已经写入后续状态的内容。问题在于中间状态是否保存了未来需要的细节，模型并不知道尚未出现的 query。

这与无损数据库归档不同。一个 $d$ 维隐藏状态同时承载局部语言建模、位置和多种历史关系，不能假设它完整复制被删 KV。拓扑给出的安全只表示执行与定义一致：模型定义本来就不允许未来直接读取已过期位置。它没有保证定义本身保留全部历史语义。

如果先用 full attention 训练，再在部署时按窗口删除 KV，删除的位置原本仍属于 $N(i)$，函数被修改；即使模型此前很少给它们高 attention，也无法从单个样本推出永远无用。若从头以窗口 mask 训练，过期 KV 在模型定义中已经不可见，释放它们才是严格等价的存储优化。

静态图还允许离线证明等价。给定最大长度，生成每层未来邻接，计算每个 KV 的 $\tau_\ell(j)$，模拟释放，并将逐步 Decode 输出与不释放任何 KV 的同拓扑参考逐 token 比较。两者应在数值误差内一致。这个测试只比较 cache 管理，不拿稠密 attention 当参考，避免把拓扑差异误判成淘汰错误。

### 8.3. Page 粒度会延迟物理回收

设一个物理 page 含 $p$ 个连续位置。只要 page 内任一 KV 仍活跃，整页就不能归还分配器。Page $P$ 的死亡时间是

$$
\tau(P)=\max_{j\in P}\tau(j).
$$

连续窗口中，同一页位置的死亡时间依次错开，最早位置虽然已经过期，还要等待页尾位置。稳态下额外保留不到一个 page，浪费上界约为 $p-1$ 个位置。若拓扑访问离散、某个旧位置被设为 global，它会把整页寿命拖到序列末尾；将常驻 token 单独放页可以避免这种放大。

Block-sparse attention 的逻辑 block 与 cache page 未必相同。逻辑 block 128、page 16 时，一个 block 跨八页；回收能更细，但索引更多。逻辑 block 16、page 128 时，八个 block 共享一页，一个远距边会保活整片区域。两种粒度共同决定实际 cache 曲线，不能用 attention block 数直接推算显存。

内存碎片也来自不同序列的死亡时间。连续 batching 中，各请求长度和窗口位置不同；逻辑上每个请求都只保留 $w$，物理 page 可能散落。一个理想的静态图 cache 上界还需要加上 allocator 的内部碎片与尚未压实页面。这里不必展开服务调度细节，但评测至少要同时报告活跃 KV 数和已分配 page 数。

### 8.4. 位置编码是状态身份的一部分

KV cache 保存的不只是 token 内容。以 RoPE 为例，key 已根据逻辑位置旋转，query 也按当前位置旋转，点积体现相对相位。环形缓冲覆盖物理槽位时，逻辑位置仍应单调增加；把槽位编号当作位置会让相隔一个窗口长度的 token 获得错误相位。

删除中间历史后压缩位置编号，同样会改变保留 key 与新 query 的相对距离。StreamingLLM 的实现需要处理 cache position，使 sink 与滑动窗口内 token 的位置关系符合模型使用方式。不同位置编码对平移、截断和外推的响应不同，静态 cache 规则不能脱离模型的位置机制单独声明等价。

一个直接测试是保留完全相同的 KV 张量，只改变 position id 或 cache slot 映射，比较 logits。再将窗口 Decode 与同位置编号的批量 masked attention 对齐。若前者不一致，错误来自增量位置处理或 cache 布局；若二者一致却与 full attention 不同，那是预期的拓扑差异。

## 9. Attention sink 是归一化现象与训练行为的交点

StreamingLLM 观察到，许多现成模型会把大量 attention 概率分给开头位置，开头 token 本身却未必保存关键语义。删除这些位置会突然改变 softmax 分母和剩余候选的概率，困惑度随之恶化。保留少量初始 KV，再加最近窗口，可以稳定流式生成。

### 9.1. Softmax 必须把概率质量分给某处

对一个 query，softmax 权重总和固定为 1。某些 head 在当前上下文没有值得读取的 value，却仍要在候选中分配全部概率。若某个位置的 key 容易获得较大 logit，而对应 value 对输出影响较小，它可以充当吸收多余概率的 sink。开头 token 在所有位置的可见集合中长期存在，训练中更容易形成这种角色。

考虑一个简化例子：sink logit 为 $a$，其余 $m$ 个候选 logit 均为 0。Sink 权重为

$$
\alpha_s=\frac{e^a}{e^a+m}.
$$

删掉 sink 后，其余候选从每个 $1/(e^a+m)$ 重新归一化为 $1/m$。即使 sink value 接近零，删除它仍将其他 value 的总权重从 $m/(e^a+m)$ 放大到 1。输出突变来自归一化结构，不要求 sink 携带有用内容。

这个解释也说明，按 value 范数判断 sink 是否重要会漏掉它对分母的作用。Attention map 中的高权重也不等同于语义贡献：高权重乘上接近零的 value，直接输出贡献小，却稳定了其他候选的尺度。分析 sink 要同时观察 key logit、归一化权重、value 路径和删除干预。

### 9.2. Sink 与 global memory 的角色不同

任务 global token 的目标是汇聚或广播内容，通常希望它的 value 含有任务相关表示；attention sink 可以主要吸收概率，value 未必承载语义。二者都常驻 cache、都被许多 query 读取，表面拓扑相同，训练作用不同。

把开头若干 token 保留为 sinks，并不会恢复被删除中间历史中的事实。模型能够无限向前运行，是因为 cache 大小保持有界且困惑度不崩溃；它的有效语义记忆仍大致受最近窗口限制。询问很早以前只出现一次的随机字符串，模型没有直接 KV 路径，除非该信息偶然被中间状态持续携带。

专门在预训练时加入占位 sink，可以让内容 token 少承担归一化缓冲角色。这个设计改变训练分布和模型结构；对已有 checkpoint，任意插入一个新 token 并不会自动获得相同功能。复用 StreamingLLM 结论时，应区分「保留模型原本依赖的开头 token」与「训练一个专用 sink token」。

多个 sink 也不必各有不同语义。它们可能分担不同 head 的偏好，或共同提供更大的 logit 吸收空间。逐个遮蔽、交换位置、替换内容，并测量输出与 attention 变化，才能判断模型依赖的是位置、token 身份还是其中携带的 value。

### 9.3. 为什么滑窗重计算仍不能替代 sink

一种基线保留最近窗口的 token，每前进一步都用窗口内容重新计算 K/V，使这些 token 的位置编号落回训练范围。它付出重复计算，并且窗口一旦不含初始 sink，softmax 行为仍可能改变。缓存式滑窗则复用旧 K/V，但要处理位置外推。两条路径的误差来源和成本不同。

把 sink 常驻后，cache 集合出现两个不连续区间：开头 $s$ 个位置与最近 $w$ 个位置。Kernel 需要读取两段 K/V，逻辑边数为 $s+w$，地址连续性略差于单一窗口；由于 $s$ 很小，这部分通常容易处理。它仍是一张静态图：所有未来 query 的邻接都包含固定 sink 集合和移动窗口。

评测流式稳定性不能只看短回答。随着生成长度越过训练上下文、越过窗口若干倍，记录逐段困惑度或损失；同时加入早期事实回忆任务，区分「语言模型分布稳定」与「长期信息仍可访问」。前者是 StreamingLLM 的主要目标，后者需要真正的记忆、摘要或检索机制。

### 9.4. Sink 数量和窗口大小需要分开消融

固定总 cache 预算 $C=s+w$ 时，增加 sink 会缩短最近窗口；减少 sink 可能破坏归一化稳定。最佳分配取决于 checkpoint 已形成的 sink 行为。若同时增加 $s$ 和 $w$，质量提升无法判断来自更稳定的分母还是更多近期内容。

可以先固定较大窗口，只扫描 $s$，找出困惑度稳定所需的最小 sink 数；再固定该 $s$ 扫描 $w$，测近期依赖范围。对每层、每 head 的 sink 权重分布也可能不同，统一保留数量是实现上的简化。某些层不需要 sink，仍可因为共享 cache 布局而一并保留。

输入模板会移动真正的开头内容。系统提示、BOS、特殊占位符与用户文本的排列改变后，哪个位置成为 sink 可能变化。只在一种 prompt 模板上测得 $s=4$，不能保证另一模板仍覆盖模型依赖的位置。保留规则最好锚定真实 token 位置，并在目标模板上重新核对。

## 10. 静态图的表达能力取决于通信协议

同一张图可以承载不同算法。窗口模型可能学会逐层复制某个标记，global 槽可能学会主题摘要，随机边可能只提供正则化。图结构规定可用通道，却没有指定通道上编码什么。讨论表达能力时，应把「存在一组权重能完成」与「常规训练能找到」分开。

### 10.1. 局部传播可以模拟全局读取，但会消耗深度

长度为 $n$ 的 causal 序列，窗口宽度 $w$。若要把位置 0 的一个 bit 传到末尾，可以让每层把该 bit 复制到窗口中最远的后继，至少需要 $\lceil(n-1)/(w-1)\rceil$ 层。这个构造证明局部图并非永远无法表达远距依赖，也明确展示了深度代价。

真实任务通常不只传一个 bit。若每个位置都有独立信息，末尾 query 可能按内容选择任意一个值，中间状态就需要同时保存许多候选或提前知道查询。纯 causal 场景中查询出现在末尾，早期中继无法预知该保留哪项；固定维度状态产生信息竞争。于是「单个标记可传播」不能证明任意随机访问都可由窗口完成。

Global 槽把传播层数缩短，却把多项信息压进少数向量。随机直连保留被选中 token 的独立 value，却不能保证选中。窗口、global、random 分别在深度、压缩和覆盖概率上付费，这也是三类边能够互补的根本原因。

### 10.2. 任务 query 出现的时间决定最优图

双向问答编码器在编码阶段已经看见问题，问题 token 能够作为 global query 读取全文并按内容选择信息。自回归模型读入长文档后才出现问题，文档阶段不知道未来问题；如果旧 KV 已被窗口删除，只剩摘要，精确选择所需的原始候选已经消失。

这一区别常被长上下文 benchmark 的输入格式掩盖。问题放在文档前面时，模型可以让问题表示随窗口逐步向后传播，并在遇到证据时更新；问题放在文档末尾时，只能依赖文档状态向后保存证据。相同 token 距离、相同窗口，通信难度不同。评测应同时交换 query 与证据顺序。

任务 global 是一种把 query 时间提前的接口。Encoder-decoder 模型可先编码全文，再让 decoder cross-attention 读取编码结果；如果 encoder 使用 Longformer global 问题位置，问题必须在编码输入中已知。开放式生成或未来用户提问缺少这一条件，需要外部检索、持久 KV 或可更新记忆补上。

### 10.3. 多证据联合需要相遇点

假设证据 $a$ 与 $b$ 分别能在 $L$ 层内到达答案位置 $z$，并不表示模型有足够层数联合二者。两条路径若都恰好在第 $L$ 层到达 $z$，该层 attention 输出才第一次同时包含它们；需要在到达后再经过 MLP 或下一层完成非线性组合。模型总深度正好为 $L$ 时，输出头是否足以完成组合取决于架构。

更一般地，寻找一个节点 $u$ 和层 $t$，使两份证据在第 $t$ 层前都到达 $u$，随后从 $u$ 到答案还有计算余量。这个共同可达问题比每份证据单独到达更严格。Global 节点天然提供相遇点，却可能容量拥挤；随机图中两条路径可能在很晚才汇合。

可以构造需要比较两个随机数、求奇偶校验或验证两个远端实体关系的任务。单证据检索成功、多证据组合失败，通常说明传播后的计算余量或汇聚带宽不足。只用 needle-in-a-haystack 单点复制，会高估静态图对组合推理的支持。

### 10.4. 位置与边类型共同形成归纳偏置

局部边告诉模型邻近位置更容易通信，global 边告诉模型某些特殊位置值得汇聚，随机边则打破纯距离结构。若所有边进入同一种 QK 打分，模型仍可通过位置编码分辨相对距离；为边类型加入独立 bias，则直接改变不同通道的先验权重。

边类型 bias 很大时，某类边可能在训练早期垄断 softmax，其他路径几乎没有梯度。Bias 很小时，新增远边与大量局部边共同归一化，未必获得足够权重。把不同边类型分配给不同 head，可以避免它们在同一 softmax 分母里竞争，代价是每类通道只占部分表示维度。

静态图的强归纳偏置在数据结构匹配时节省样本，结构错配时也会形成硬盲区。文档局部性、图像二维邻域、代码语法边和音频时间邻域各不相同。把文本窗口原样用于展平图像，会让行尾与下一行行首成为线性邻居；把二维轴向图用于文本，则人为引入周期 stride。边数相同，语义假设完全不同。

## 11. 一套不混淆层次的比较方法

静态稀疏最容易出现的争论，是一方在说逻辑边，另一方在说 kernel；一方测预训练后的任务质量，另一方给零训练的 mask 裁剪；一方处理双向编码，另一方讨论 causal Decode。把比较拆成定义、训练、状态和执行四层，许多看似矛盾的结果会自然分开。

### 11.1. 定义层先冻结通信图

先记录每层每个 head 的邻接生成规则、方向、去重、边界、随机种子和 global 语义。对几个小长度导出完整布尔矩阵，计算逻辑边数、度分布、有限层可达率、最短路径和割。这个阶段不运行模型，也不讨论 GPU 快慢。

比较两张图时至少保持一种预算相同：总逻辑边、每层边、每个 head 候选或非空 block 数。不同预算回答不同问题。固定逻辑边比较拓扑效率，固定物理 tile 比较硬件预算下的结构选择，固定端到端时延才接近部署选择。

长度增长实验同时列出绝对窗口、稀疏率、随机度数与 global 数。固定窗口会让稀疏率继续下降；固定稀疏率会让每行候选增长；固定延迟可能因 kernel 阶梯而采用另一组参数。只给模型名和上下文长度无法复现真正的图。

### 11.2. 训练层区分原生稀疏与事后裁剪

原生稀疏模型从第一步就在该图上优化，能够发展中继和摘要策略。事后裁剪模型失去曾经可用的边，短期下降同时包含拓扑能力和分布转移。稠密模型裁剪后继续训练，处于两者之间；恢复速度与最终差距都值得报告。

训练 token、优化步数、参数量和总 FLOPs应分别给出。稀疏 attention 省下计算后，若用相同 wall-clock 训练更多 token，最终质量提升既来自拓扑也来自数据量；若固定 token，稀疏模型可能用更少总算力。两种比较都有价值，结论不能混写。

随机图还增加一个轴：固定图训练、重采样图训练、固定图推理和重采样图推理。四种组合里，训练和推理同分布最容易解释；跨分布组合需要额外鲁棒性实验。任何「随机边有效」的结论都应绑定具体组合。

### 11.3. 状态层验证 cache 等价与记忆边界

先用不回收 KV 的稀疏参考跑 Decode，再开启按 $\tau(j)$ 回收，两者输出应一致。这一步证明实现遵守同一拓扑。随后与稠密模型比较，差异才归于方法本身。若跳过参考，cache position 错误、错误释放与稀疏近似会混在一个质量数字里。

同时测两类任务：局部分布稳定性和历史事实访问。StreamingLLM 可以在极长流上保持困惑度稳定，却没有声称任意早期事实仍可恢复。窗口模型在常规生成上自然，远端随机键值检索可能失败；这两个结果可以同时成立。

Cache 报告包含逻辑活跃 KV、物理 page、常驻 global/sink、位置编号范围和每步读取字节。只写「cache 长度 4096」看不出是否另有 4 个 sink、是否按层窗口不同、是否为 page 对齐保留了更多状态。

### 11.4. 执行层把空边真正变成省下的工作

稠密参考加 mask 用于数值正确性，不能用于性能结论。Profiler 应确认没有物化完整分数矩阵，非空 tile 数随图预算变化，HBM 读取和 kernel 时间没有被索引开销吞没。Prefill、训练前向、训练反向和 Decode 分别测量，它们的矩阵形状与瓶颈不同。

规则窗口最适合连续 tile，随机 block 适合块级 gather，逐 token 随机边可能拥有最少逻辑边却触发最多碎片 tile。报告 $|E|$ 与 $|T|B_qB_k$ 的比值，能直观看到逻辑稀疏到物理工作的膨胀。不同 block size 的性能比较还要带上 padding 后长度。

端到端速度最终受整层其余部分限制。Attention 从 40% 层时间降到 20%，即使自身加速两倍，整层也只从 100 降到 80 左右；继续删边的收益会更小。性能数字应同时给 attention kernel 与完整模型，避免把局部加速当成服务吞吐。

### 11.5. 最终结论绑定适用条件

一句可复现的结论应类似这样：在 causal 原生训练、长度 32K、窗口 2K、每层两个随机 block、固定四个 sink、block 64 的条件下，某项远距任务与 full baseline 的差距是多少，Prefill 和 Decode 分别节省多少，种子方差多大。条件看起来繁琐，却都是静态图的一部分。

如果某条路线只在双向编码器验证，就保留这一边界；如果仓库的高效 kernel 不支持 dilation，就区分算法定义与当前实现；如果理论保证要求特定 global 结构，就不把结论外推到任意随机 mask。这样得到的知识不追求一句话包办所有场景，而是让读者知道下一次换长度、换任务、换执行路径时该重新检查什么。

## 12. 三组反例把模糊判断变成可验证命题

静态图的很多误判来自只看平均语言建模损失。平均损失由大量局部 token 主导，一条只影响少数远距样本的断路很容易被淹没。下面三组构造分别针对可达、容量与执行，把问题压缩到能够手算的规模。

### 12.1. 相同边数不保证相同可达

取 $n=16$、四层网络，每个 query 每层最多读取四个 key。图 A 使用 causal 窗口 $w=4$；图 B 让位置按奇偶分组，每个 query 读取同组内最近四个位置。忽略开头边界，两张图每行候选相同，逻辑边数接近。

在图 A 中，每层最多向前移动 3，四层最远回看 12；末尾位置 15 能到达位置 3，却到不了位置 0。在图 B 中，每一步最多跨越 8 个线性位置，但所有路径保持奇偶性；位置 15 永远到不了任何偶数位置。图 B 的最大几何跨度更大，对一半节点却永久断开。

现在给图 A 的第一层加入一条从 0 到 15 的长边，同时删掉一条局部边保持边数。位置 15 一层就能读取 0，但其他目标位置没有受益；平均最短路径可能略降，最坏覆盖几乎不变。边数、最大跨度、某个样本的最短路径各自只描述一部分结构。

测试数据可以为每个目标位置随机选择一个合法历史位置，要求复制其 token。按目标—证据奇偶、距离和最短图路径分桶，图 A 会在超过 12 的距离桶失败，图 B 会在异余数桶失败。若只把证据固定在位置 1、目标固定在 15，得到的结论会被这两个位置的偶然关系支配。

若模型含有一层 full attention，图 A 与图 B 都在该层获得全局直连，但此前的表示仍由不同局部图产生。Full 位于网络入口时，后续层加工全局混合结果；位于网络末端时，输出前才发生一次全局选择。两种调度的最终可达都为全图，功能仍不等价。可达矩阵无法表示这段层间计算顺序。

### 12.2. 两跳全局图仍可能丢失精确细节

构造 $m$ 个随机键值对，每个 value 是独立的 $b$ bit 字符串。所有键值只能先写入一个 global token，末尾 query 再从 global token 读取，图距离恒为 2。若要对任意 query 精确返回任意 value，global 表示必须保留足够区分 $2^{mb}$ 种输入组合的信息。

数学上的连续实数向量具有无限精度，不能简单以维数宣布绝对不可能；实际模型使用有限精度、有限参数和带噪训练。更稳妥的实验是固定隐藏维度和 dtype，逐步增加 $m$ 与 $b$，观察准确率何时下降，再增加 global 槽位数 $g$。若转折点随 $g$ 后移，而直接稀疏边参照仍稳定，证据支持摘要通道存在容量竞争。

为了排除 query 选择困难，可让 query 键非常清楚，并在 full attention 参照上验证任务接近满分。为了排除训练不足，对小 $m$ 训练到收敛，再继续增加 $m$；也可用 oracle 把所需 value 直接写入 global 的指定子空间，确认下游读取没有问题。反例关注通信瓶颈，不应把数据格式或优化失败混进来。

把一个 global 槽换成 $g$ 个槽时，还要规定普通 token 写向哪些槽。所有 token 平均写入全部槽，多个槽可能学成冗余副本；按位置分片写入，容量分散但 query 要知道目标在哪一片；让内容路由选择槽，又从静态图进入动态路由。槽位数增加只是提供可能的带宽，训练协议决定能否使用。

同一反例也能比较层级摘要。每 16 个键值写入段摘要，再由章节摘要汇总。总边保持线性，路径从 2 变成多层，单个槽的竞争减少，顶层仍要支持 query 定位。若段摘要直接保留多个可寻址槽，效果可能优于单向量平均；这说明「树直径对数级」仍不足以描述节点内表示。

### 12.3. 最少逻辑边可能产生更多物理工作

取 $n=64$，tile 为 $16\times16$。图 C 每个 query 读取连续的 16 个 key，逻辑边约为 1024，非空 tile 形成对角带。图 D 每个 query 也读 16 个 key，但把它们均匀散到四个 key tile；逻辑边仍约 1024，几乎每个 query tile 都要触发全部四个 key tile，物理 tile 接近稠密。

图 C 的边在 tile 内集中，即使边界有多算，$\rho$ 仍较高；图 D 每个 tile 只有少量离散边，整 tile kernel 会算掉大量被 mask 配对。若使用真正的逐元素 gather，点积减少了，却引入不连续读取和许多小操作。两种执行路线都可能让图 D 比图 C 更慢。

把随机边改成 block 级后，选中一个 key tile就计算完整 256 条配对。逻辑 token 边表面增加，tile 利用率接近 1，矩阵乘单元更容易跑满。于是「更稠密」的 block 图可以比「更稀疏」的 token 图快。渐近边数没有出错，只是设备执行单位与理论单位不同。

这个反例应在 profiler 中看到：图 D 的非空 tile 数高、有效率低，或 gather kernel 的访存事务与启动次数高。若框架悄悄回退到完整 attention，图 C 与图 D 都会接近平方成本；此时 mask 输出正确，性能实验无效。检查计算图和中间张量比只看 wall-clock 更能定位原因。

### 12.4. 一个完整的 32 位置验收题

设长度 32、四层、block size 4。每层保留最近两个 block，第一与第三层各增加一个固定随机历史 block，第二与第四层让 block 0 作为 global key。生成 causal 邻接时，当前 block 内还要对 token 使用下三角 mask，不能让块内早期 query 看到后续 token。

四层的 block 邻接和 token mask 构成验收输入。随机目标编号不得超过 query block；global block 作为 key 能被后续读取，作为 query 时只能读取自己的历史；局部、随机与 global 重叠后去重；尾块中的 padding 不进入 softmax。每层每行的真实度数也随邻接一并记录。

第二步从位置 31 反向计算四层可达。分别标记哪部分来自局部链、随机捷径和 global key。注意作为 global key 的 block 0 没有自动汇聚其他 block 信息，它只广播自身；若希望它先汇聚全文再广播，causal 时间顺序无法在序列开头完成。这个配置能快速抓住「global」方向写反的问题。

第三步计算每层 KV 的末次访问。最近两块窗口让普通 block 在两个后继块后过期，固定随机边会延长某些 block 的寿命，block 0 常驻。把 token 寿命汇总到 cache page，再模拟每一步释放。开启回收与保留全部 KV 的稀疏参考输出应一致。

数值核对阶段，用普通稠密 attention 实现四层 mask，再运行目标 block-sparse kernel，比较前向、输入梯度和参数梯度。性能核对记录逻辑边、非空 tile、padding、峰值内存与时间。这个 32 位置玩具题把图定义、因果性、cache 和 kernel 串在一起，比直接跑 128K benchmark 更容易指出错误发生在哪一层。

### 12.5. 如何标记确实没有答案的地方

静态图分析可以精确回答边、路径、寿命和 tile，无法仅凭这些量预测最终质量。给定最小割大小，不能直接换算准确率；给定 attention sink 权重，也不能断言它完全没有语义；给定理论通用逼近，更不能推出有限规模训练一定成功。这些地方应保留实验条件，而不是补一个听起来确定的结论。

当两个方法使用不同训练 token、不同位置编码或不同 kernel 时，现有公开结果不足以隔离拓扑贡献。合理的写法是列出可核查差异，并给出需要的对照实验。缺少对照并不妨碍理解原理，伪造单一归因才会让后续知识失去可信度。

同样，理论复杂度 $O(nw)$ 说明固定 $w$ 时的增长阶，不能确定某张 GPU 上从多长开始更快。交叉点必须实测，并随软件版本、dtype、head 维度和 batch 改变。原理文章可以说明影响方向和测量方法，把具体阈值留给对应环境。

## 13. 从需求反推拓扑参数

静态图设计不必从方法名开始。先写出任务允许的通信延迟、必须确定到达的信息、可接受的摘要压缩、cache 上限和执行粒度，再反推窗口、global、random 与 block 参数，得到的选择通常更清楚。

### 13.1. 用依赖距离分布选择窗口

统计任务中 query 与必要证据的距离分布 $P(D)$。模型有 $L$ 层，若希望纯窗口路径覆盖距离分位数 $D_p$，因果窗口至少满足

$$
w\ge 1+\left\lceil\frac{D_p}{L}\right\rceil.
$$

这是结构下界。考虑到多跳衰减和到达后还需计算，实际窗口往往要留余量，或加入远距边。选择 $p=0.95$ 表示允许最远 5% 的依赖交给其他通道，不表示这些样本可以直接丢弃。

距离统计也要按任务单位计算。代码里的定义—使用、文档中的问题—证据、对话中的约束—回复各有不同分布。把所有 token 的自相关距离当成任务依赖，会让高频局部关系压过少量关键长关系。人工标注、合成控制任务和注意力干预可以共同估计。

窗口确定后，先计算逻辑边与 tile 阶梯。若 $w$ 恰好跨过新的 key tile，少量缩小可能明显减少物理工作；若仍位于同一 tile 档位，缩小不会带来预期速度。结构下界与硬件档位之间的空隙，适合留作鲁棒余量。

### 13.2. 用确定性需求分配 global

系统指令、问题 token、分类槽与文档标题若必须被所有位置稳定访问，可以进入 global 集合。Global 数量不应只按平均质量选择，还要看它形成的割容量。多个相互独立的控制源共用一个摘要槽，可能在复杂输入下竞争；给不同角色独立槽位，边数按 $ng$ 增长。

Global 的方向由任务决定。只需让所有 token 读取系统指令时，系统位置作为 global key 即可，无须让它作为 query 读取全文。问答编码器中的问题要汇聚文档，则问题位置既作 global query 又常作 global key。少一个方向能省边，也避免不必要的信息回流。

如果 global 位置由输入结构确定，应把解析失败纳入测试。标题缺失、问题区段为空、模板改变或特殊 token 被截断时，fallback 是退回普通窗口、选择固定槽还是拒绝输入。规则越依赖结构，越需要覆盖异常结构。

### 13.3. 用剩余风险决定随机预算

窗口和 global 建好后，仍未覆盖的未知远距关系才交给随机边。设窗口外候选 block 为 $M$，单个关键 block 的目标直接命中率为 $p$，最粗略的随机度数需要 $s\ge pM$。当 $M$ 很大时，这个成本迅速失去吸引力，说明随机边更适合改善多层扩张和平均路径，不适合作为唯一的精确检索保证。

预算可以分散到多层独立图，增加累计覆盖；关键层保留相同固定图，则提高训练适应性。若最差样本不能接受概率失败，就应增加规则远边、内容索引或外部检索。把 random 数量继续堆高，最终会逼近稠密，同时仍缺少逐样本确定性。

随机预算还要用种子尾部结果验收。平均准确率满足要求、最差种子不满足时，部署选定一个验证过的固定种子可以降低风险，但这相当于做过图搜索，选择过程要记录；每次启动重新生成邻接则可能落到坏图。

### 13.4. 用状态预算检查设计能否流式运行

给定每层 cache 上限 $C_\ell$，先由邻接规则计算活跃 KV 峰值，而后加入常驻 sink/global 与 page 碎片。若固定随机边可能在很晚访问早期 block，峰值可能接近全历史，即使每步只读取少量边。此时算术是稀疏的，状态并不稀疏。

要实现严格有界 cache，所有非永久位置必须有有限的最大未来回看距离，或先经过一个有界摘要协议。Random 目标从全部历史在线采样与严格淘汰互相冲突：旧 KV 既可能被未来抽中，就不能安全释放。限制随机采样范围能恢复上界，也缩短了它提供的捷径。

最终配置应同时写出每步读取上限和常驻状态上限。前者影响 Decode 带宽，后者影响并发容量。只优化读取、保留整段 KV，单请求延迟可能下降而服务并发仍受显存限制；只压缩 cache、kernel 仍读取碎片 page，也未必得到低延迟。

这样反推得到的拓扑会自然呈现混合形态：窗口覆盖高频局部依赖，少量定向 global 承担必须到达的接口，随机或结构远边降低剩余关系的路径长度，cache 规则则约束所有远边的时间范围。每一类边都有明确责任，后续消融也知道该删除什么、观察哪类失败。
