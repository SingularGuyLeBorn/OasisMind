# 基础: 成本、静态图与混合流式拓扑

稠密注意力把长度为 $n$ 的序列展开成 $n\times n$ 的交互图。这个表示法干净，也让任意两处信息在一层内直接相遇；代价是序列每扩大一倍，分数配对扩大四倍。Sparse Attention 的第一批方案没有训练路由器，也不按输入内容临时检索，而是预先规定哪些边存在。静态拓扑因此成为分析整条技术路线的参照系：边数可以数，最短路径可以算，kernel 能否规则化也可以直接检查。

邻接矩阵 $M$ 用来表示 mask。对因果模型，$M_{ij}=1$ 必须满足 $j\le i$；对双向编码器则没有这条时间约束。第 $i$ 行非零位置构成集合 $N(i)$。注意力仍然执行缩放点积与 softmax，只把归一化范围限制到 $N(i)$。稀疏改变的是可交互集合，softmax 定义保持不变。

## 1. 先把四类成本拆开

### 1.1. 配对、激活与 cache

单个 head 的稠密 $QK^\top$ 约需 $2n^2d_h$ 次浮点运算，随后用权重乘 $V$ 还需近似相同数量。若每行只有 $k$ 个有效 key，理想工作量降为 $O(nkd_h)$。训练还要为反向传播保存或重算选择、概率与归一化统计量；FlashAttention 通过分块重算降低峰值显存，却仍执行所有合法配对。

Decode 的成本构成不同。第 $t$ 步只有一个新 query，稠密注意力计算约为 $O(td_h)$，同时读取 $t$ 个历史 key 与 value。此时主要压力常来自 KV cache 容量和带宽。静态窗口若只保留最近 $w$ 个 KV，可把每步容量与读取限制在 $O(wd_h)$；若实现仍保留并扫描全部 cache，再在末尾应用窗口 mask，理论边数没有转化为系统收益。

### 1.2. 路径长度是另一项成本

边少会增加信息传播距离。半径为 $r$ 的双向窗口每层最多把信息向左右各推进 $r$ 个位置，两个相距 $D$ 的 token 至少要经过 $\lceil D/r\rceil$ 层才能建立路径。因果窗口只向历史读取，较早信息向后传播的最短层数同样随距离增长。增加全局 token 可以缩短图直径，但所有远距离交换都可能集中到少数通道。

**复杂度下降与有效感受野扩大是两条不同曲线。** 边数只说明算多少，图路径只说明理论上能否到达；优化是否学到跨层转发，还要由训练任务和实验证据回答。

## 2. 三种静态构件

### 2.1. 滑动窗口

窗口注意力让位置 $i$ 只访问邻近位置。对因果模型可写成 $N(i)=\{j:\max(1,i-w+1)\le j\le i\}$，其中 $w$ 包含当前位置。长度 $n=8,w=3$ 时，各行有效 key 数依次为 $1,2,3,3,3,3,3,3$，总边数是 $1+2+6\times3=21$；完整因果注意力有 $8\times9/2=36$ 条边。窗口省去 15 条边，但位置 8 在一层内看不到位置 1。

窗口规则适合块化并能配合环形 KV cache。它的边界也明确：依赖距离超过多层感受野时，信息必须被中间 token 连续携带；一旦中间表征没有保留所需细节，后层无法重新访问原始 KV。

### 2.2. 全局与随机连接

Longformer 给少量位置配置全局注意力。全局位置既读取全部 token，也可被全部 token 读取；任务分类 token 或问题 token 因而可以聚合整段信息。若有 $g$ 个全局位置，额外边数约为 $O(ng)$。当 $g\ll n$ 时仍保持线性增长，但 $g$ 不是免费的：全局位置增加稠密条带，并要求任务预先知道哪些位置承担中转。

BigBird 将局部窗口、全局 token 与随机连接组合。随机边让图更快混合，并降低只靠局部链路造成的长路径。理论结论依赖特定随机图和全局连接假设，不能直接推出任意手写 mask 都保持完整注意力的表达性质；实践中还要固定随机模式、块大小和实际可执行 kernel。

## 3. 三篇正文怎样衔接

### 3.1. 成本模型先于方法名

[成本与阶段](./01-成本与阶段/01-成本与阶段.md)先统一计算口径, [成本模型](./01-成本与阶段/01-成本模型.md)再按训练、prefill、decode 分别计算 FLOPs、激活、KV 容量和读取量。相同的 $O(nw)$ 在三个阶段并不对应相同收益：训练可能受算力约束，decode 可能受带宽约束，动态路由还可能先读完整 cache 才得到选择结果。

[静态图结构](./02-静态图结构/02-静态图结构.md)组织窗口、全局与随机连接, [Longformer 与 BigBird](./02-静态图结构/01-静态拓扑.md)把静态 mask 展开到逐行邻接集合，并比较局部、全局和随机边。重点是每种边解决哪一种路径问题，以及论文结论在编码器、因果生成和硬件实现之间能否直接迁移。

### 3.2. 混合层与 attention sink

[混合与流式](./03-混合与流式/03-混合与流式.md)说明层轴与 token 轴的组合方式, [Hybrid SWA 与 attention sink](./03-混合与流式/01-混合拓扑.md)讨论两类常被混在一起的保真手段。局部层之间插入全局层，是沿深度轴周期性恢复全局通信；保留序列开头的 sink token，则是为 streaming decode 保留 softmax 中稳定吸收多余概率质量的位置。前者改变层级拓扑，后者改变 cache 边界，两者不能相互替代。

静态方案适合作为基线，是因为系统能预先知道访问地址。后续动态稀疏必须证明内容相关选择的质量收益足以覆盖路由、索引和负载不均衡成本。若静态窗口已经满足任务依赖，动态方法增加的复杂度未必值得。

## 4. 判断结论的适用范围

### 4.1. 编码器与生成模型

Longformer 和 BigBird 的经典实验大量面向双向编码任务，位置可以同时读取左右邻居。自回归语言模型只能读取过去，随机边也不能越过因果边界。把双向 mask 改为因果 mask 后，图直径、全局 token 的信息流向和任务接口都会变化，因此不能只凭方法名称认定生成阶段具有相同性能。

窗口训练与窗口 decode 也要匹配。训练时若使用稠密注意力，部署时突然截断 KV，模型可能依赖从未受限的远距离边；训练时一直使用窗口，则模型有机会学习跨层搬运或把稳定状态写到保留位置。两者仍不保证窗口外事实被可靠保存，长距离检索必须单独评测。

### 4.2. mask 与 kernel

规则 mask 只有在实现能跳过无效块时才节省时间。块稀疏 kernel 通常要求块大小对齐，边界位置和全局 token 可能造成补零或额外分支。短序列上，索引与调度开销会使稀疏版本慢于优化充分的稠密 kernel；长度增长后，少读数据与少做矩阵乘法才逐渐占优。

因此报告结果时要同时给出模型维度、窗口宽度、全局 token 数、块大小、序列长度、batch、精度、硬件与基线 kernel。**静态拓扑提供可预测的边集合，但端到端收益仍由执行这些边的系统决定。**

### 4.3. 质量结论也要按距离分桶

平均困惑度会把大量局部预测与少量长依赖混在一起。一个窗口模型可以在局部语言建模上保持良好均值，却在窗口外的精确引用上完全失败。评测应把 query 与证据的距离分成窗口内、一到两倍窗口、多层理论可达区和理论不可达区，再分别报告准确率。若加入全局 token，还应改变全局位置的数量与放置规则，检查提升来自更短路径还是更多参数化接口。

静态随机边的评测还要固定随机种子或报告多次采样。不同图可能具有相近边数，却出现不同的局部瓶颈和最短路径。图论性质只给出结构条件，模型是否学会利用随机连接仍需消融。这样的分桶能把「平均表现没有下降」改写成可定位的结论：哪些距离、哪些任务和哪些拓扑真正受益。

### 4.4. 训练拓扑必须写进模型定义

mask 不只是部署参数。训练期间每个 token 看见哪些上下文，会改变梯度路径和模型形成的内部策略。推理时缩小窗口属于近似执行，推理时扩大窗口也不保证模型会使用新出现的远距离边。若一个模型在不同层采用不同窗口或周期性全局层，这张层表应与权重配置一同保存。

可复现配置至少给出每层模式、左右或因果窗口、全局位置规则、块大小与特殊 token。这样才能由配置重建邻接矩阵，进一步复算边数、cache 和路径。只留下「使用 sliding window」的文字标签，会丢失决定行为的主要参数。

## 5. 证据口径

### 5.1. 三层来源各自回答什么

「论文结论」只用于原作者直接证明或实验展示的内容，例如 Sparse Transformer 的特定稀疏分解、BigBird 在含常数个全局 token 等条件下的表达性结论，以及 StreamingLLM 对初始 token 的观测。「工程事实」来自作者仓库和实现说明，例如 Longformer 的 TVM 与 sliding-chunks 路径、BigBird 代码的 block 参数和静态 shape 限制、FlashAttention 的精确注意力实现。

统一边数、分阶段 cache 和混合层加权的公式是基于已声明邻接集合的条件推导，可以独立复算，不属于任何论文报告的实验结论。实际加速仍需对应硬件上的 benchmark。

### 5.2. 三类结论不能互相替代

复杂度、表达能力和工程吞吐是三类命题。BigBird 的线性边数与通用逼近属于不同结论，各有自己的构造与假设；FlashAttention 的 IO 优化也不等于删除边。正文为每项判断保留对应层级，不用一种证据替另一种背书。

数值手算只对给定 $n,w,g$ 和层表成立。真实系统还包含 block 对齐、kernel 调度与通信，因此手算给出上界或下界后，仍要通过作者实现和目标硬件测量闭环。
