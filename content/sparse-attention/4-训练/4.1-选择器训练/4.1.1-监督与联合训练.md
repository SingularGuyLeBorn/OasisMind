# 监督与联合训练

一个选择器真正要学的东西，可以压成一句话：用很便宜的表示，把主 attention 最舍不得丢掉的位置排进有限预算。训练同时面对检索与生成两个目标。检索目标要求候选集合覆盖关键证据，生成目标要求稀疏模型仍能预测下一个 token。单独优化检索会得到高召回却不会用证据的模型，单独优化生成又可能让路由依赖数据捷径。

## 1. oracle 到底教什么

**从 attention 分布构造集合。**

对第 $i$ 个 query，稠密教师 logits 与概率写成

$$
z_{ij}=\frac{q_i^\top k_j}{\sqrt d}+m_{ij},\qquad
p_{ij}=\frac{e^{z_{ij}}}{\sum_{s\le i}e^{z_{is}}}. \tag{1}
$$

$m_{ij}$ 包含因果与 padding mask。若部署预算为 $k$，最朴素的 oracle 是 $G_i=\operatorname{TopK}(p_i,k)$。选择器产生低成本分数 $r_{ij}$，再得到 $S_i=\operatorname{TopK}(r_i,k)$。集合召回为

$$
R_i@k=\frac{|S_i\cap G_i|}{|G_i|}. \tag{2}
$$

它容易解释，却把教师 top-k 内部的权重差异抹平。假设教师前四项概率为 $(0.70,0.20,0.06,0.04)$，预算 $k=2$。候选 A 选中第 1、3 项，recall 为 $1/2$，概率质量为 $0.76$；候选 B 选中第 2、3 项，recall 同样为 $1/2$，概率质量只有 $0.26$。集合指标完全相同，输出风险显然不同。

因此还要计算

$$
C_i=\sum_{j\in S_i}p_{ij}, \tag{3}
$$

即候选覆盖的教师概率质量。$C_i$ 直接关联被裁掉的 attention mass，但也不是最终任务质量的充分条件：两个 value 可能几乎相同，漏掉其中一个影响很小；也可能一个低概率 value 恰好携带唯一变量值。集合召回、质量覆盖和任务正确率要并列报告。

**token、块与 GQA 的标签不可混用。**

MoBA 与 NSA 的 selection 以连续块为单位。若块 $b$ 覆盖位置集合 $B_b$，可以把 token 概率求和为块标签

$$
P_{ib}=\sum_{j\in B_b}p_{ij}. \tag{4}
$$

求和适合估计整个块的概率质量；取最大值更重视块中单个尖峰；用块表示与 query 重新打分则训练的是代理相关性。三种定义会给出不同 oracle。实际 kernel 会读完整块，评测既要报告逻辑命中的关键 token，也要报告随块带入的总 token 数。

GQA 又多一层共享。同一 KV head 对应多个 query heads，部署若只允许一组共享候选，教师标签也应在组内聚合。可用各 head 块质量之和

$$
P^{\mathrm{group}}_{ib}=\sum_{h\in\mathcal H_g}P^{(h)}_{ib}. \tag{5}
$$

它偏向服务多数 heads，少数检索 head 的唯一证据可能被淹没。训练时同时保留 per-head oracle 与 group oracle：前者给出质量上界，后者对应真实访存。两者差距很大时，问题来自共享粒度，而非 selector 容量。

**正例之外要设计困难负样本。**

随机负样本常常太容易。远处无关文本与 query 的主题差异明显，选择器只学关键词匹配便可分开；长上下文里真正危险的是同主题、同实体、同模板的错误片段。例如代码仓库里出现十次同名函数，文档里每章都有相同标题，工具轨迹里反复出现近似 JSON。

困难负样本可以来自教师 top-k 边界附近、同一文档的重复段、相邻块以及旧版本答案。边界样本训练排序精度，相邻块暴露块表示的模糊性，重复段检验位置与语义能否共同消歧。负样本池还要随长度增长；32K 内只有一个同名实体，扩到 1M 后可能出现几十个，训练难度已经改变。

**oracle 也会泄漏与漂移。**

若用答案 token 的 hidden state 回头标注 prompt 中的证据，标签可能含有训练时才知道的未来信息。自回归 selector 在位置 $i$ 只能使用 $x_{\le i}$ 产生的状态，教师标签也必须遵守同一因果边界。离线预处理时尤其容易出错：整段编码后再抽取 query 表示，双向信息或答案后缀可能悄悄进入标签。

教师还会随着主干更新而变化。联合训练开始时，稠密 checkpoint 的 attention 是一套 oracle；主干适应稀疏图后，query、key 与 head 功能都会漂移。始终使用旧标签，selector 可能准确模仿一套已经不存在的分布。每步重跑当前稠密教师最及时，也最昂贵。折中方案包括周期性刷新、教师参数的指数滑动平均，以及固定一部分探针 batch 比较新旧 oracle 的 Jaccard 与概率质量。

不同层的 attention 也不能合成一份通用标签。浅层常偏局部与词法，深层可能检索实体、指令或中间结论；同一个位置在相邻层的重要性会改变。跨层共享 selector 时，标签聚合规则就是模型假设：求和偏向多层共同需要的位置，取最大值保护只在单层突出的证据，分层蒸馏则保留差异但增加参数和缓存。共享带来的节省必须与单层 oracle 的损失一起测量。

### 1.1. 损失怎样穿过 top-k

**KL 蒸馏训练低维 indexer。**

DSA 的 Lightning Indexer 用低维 key 与多组 query 表示给全部历史位置打分。稠密预热阶段可以把主 attention 分布作为教师。令选择器概率

$$
\hat p_{ij}=\operatorname{softmax}_j(r_{ij}/\tau), \tag{6}
$$

则蒸馏损失可写成

$$
\mathcal L_{\mathrm{KL}}=
\sum_i\sum_{j\le i}p_{ij}\log\frac{p_{ij}}{\hat p_{ij}}. \tag{7}
$$

温度 $\tau$ 控制教师尾部是否可见。温度过低时，梯度几乎只来自最大项，边界排序学得慢；温度过高时，大量无关位置占据损失。若稠密矩阵无法长期保存，可以只保留教师 top-$m$ 与一个 tail mass，但 $m$ 必须大于部署 $k$，否则 selector 从未看到最危险的近邻负样本。

DSA 的公开训练路线先用稠密 attention 预热 indexer，再启用 token 选择并联合优化全部参数。预热解决冷启动：随机 selector 若直接控制主 attention，早期候选近似随机，主干输入随 step 剧烈变化。联合阶段则让主干适应被裁剪后的分布。两阶段之间的 $k$、长度和学习率切换都可能造成 loss 台阶，需要单独记录。

**排序损失直接盯住边界。**

KL 拟合完整概率形状，但部署只关心谁跨过第 $k$ 名。对正例 $j^+$ 与困难负例 $j^-$，可以用 margin loss

$$
\mathcal L_{\mathrm{rank}}=
\frac1{|mathcal P_i|}\sum_{(j^+,j^-)\in\mathcal P_i}
\max(0,\gamma-r_{ij^+}+r_{ij^-}). \tag{8}
$$

手算一个例子：$\gamma=0.2$，正例分数 $0.7$，负例 $0.65$，损失为 $0.15$；负例降到 $0.4$ 后损失归零。它把梯度集中在排序不够安全的 pair 上。若只采最容易的负例，损失很快为零；若永远只采最难一个，又容易追逐教师噪声。可混合边界负例、随机负例与同主题负例。

cutoff margin

$$
\Delta_i=r_{i,(k)}-r_{i,(k+1)} \tag{9}
$$

也值得监控。$\Delta_i$ 很小时，FP8 量化、并列排序和不同 kernel 的归约顺序都可能翻转候选。平均 recall 没变，不代表这些翻转不会集中发生在关键 query 上。

**soft routing 与 straight-through。**

soft routing 令 $g_{ij}=\operatorname{softmax}(r_i/\tau)_j$，用 $g$ 对所有候选加权。它的梯度干净，计算仍接近稠密。训练早期可用较高温度保持探索，随后降低温度，使分布接近 hard selection。温度降得太快会冻结错误排序；一直很高又让主干依赖许多部署时会消失的小权重。

straight-through 用 hard mask $h$ 做前向，用 soft gate $g$ 近似反向：

$$
\tilde h=\operatorname{stopgrad}(h-g)+g. \tag{10}
$$

数值上 $\tilde h=h$，所以前向只看选中候选；对 $r$ 求导时，stop-gradient 项消失，梯度沿 $g$ 返回。这个估计让训练形状贴近部署，却把离散跳变当作连续变化，梯度有偏。应与纯教师监督、扩大候选训练做消融，而不是把「有梯度」等同于「梯度正确」。

**候选探索给集合外样本一次机会。**

hard top-k 的另一种训练办法是在预算外加入少量探索位置。设部署预算为 $k$，训练前向取 $k$ 个高分位置，再从其余位置按概率或分桶抽取 $e$ 个探索样本。探索样本参与教师排序或主 attention，但不计入部署质量。随着训练进行，$e$ 从较大值退火到零。

均匀随机探索在百万候选中很难撞到关键位置。更有效的抽样来自三处：教师高分而学生漏掉的位置，学生 cutoff 附近的位置，以及距离、主题、文档段落分桶后的代表项。第一类直接纠错，第二类稳定排序边界，第三类防止训练只覆盖高频距离。抽样概率进入 loss 时需做重要性校正，否则频繁被抽中的位置会被过度加权。

假设候选空间有 1024 块，部署 $k=16$，再抽 16 个均匀探索块。某个唯一漏选证据被碰到的概率只有 $16/(1024-16)\approx1.59\%$。若先用教师或粗索引缩到 64 个困难块，再从剩余 48 个里抽 16 个，概率升到 $33.3\%$。探索是否有效，取决于采样池是否含有有价值的错误，单纯增加若干随机块效果很弱。

**NSA、MoBA 与 KDA 的边界。**

NSA 的压缩分支对全局压缩条目做 attention，其权重汇总成 selection 的块重要性。压缩输出本身参与最终结果，因此这条全局路径能正常接收语言模型梯度；选中的原始块补充细节，滑窗保证局部连接。hard top-k 的集合边界仍不可导，但压缩分支不会因某个原始块漏选就完全失去全局信号。训练时应分别观察三个 gate、压缩质量和 selected-block recall。

MoBA 把块视作 attention experts。query 对块打 gate 分数，选中块与当前块进入精确 attention。它可以在 full 与 sparse 模式之间切换，适合先以较宽候选训练再收紧；代价是切换后每个 query 的归一化集合变化。若 full 阶段的 gate 只作旁路打分，主干可能从未承受漏选，切到 hard top-k 时仍会掉点。

Kimi Delta Attention（KDA）通过门控递归状态保存历史，属于线性 attention。它没有为每个 query 从全部历史 token 中产生 hard top-k 集合，因而 recall@$k$、候选负载均衡和随机 gather 不是它的核心训练指标。KDA 更关心有限状态能否写入、擦除并保留关联记忆，以及周期性 full attention 怎样弥补状态压缩。把它列在同一章的意义是划清训练问题，而非声称所有长上下文结构都有一个 selector。

### 1.2. 联合目标与预算手算

**四项损失各管一件事。**

一个可操作的联合目标是

$$
\mathcal L=
\mathcal L_{\mathrm{LM}}
+\lambda_d\mathcal L_{\mathrm{KL}}
+\lambda_r\mathcal L_{\mathrm{rank}}
+\lambda_b\mathcal L_{\mathrm{budget}}. \tag{11}
$$

$\mathcal L_{\mathrm{LM}}$ 校正最终预测，KL 保留教师概率结构，排序损失盯住 top-k 边界，预算项限制选择规模。四个数相加后得到的总 loss 很难诊断，日志中必须拆开。$\lambda_d$ 太大时，学生被迫复现教师的细小尾部差异；$\lambda_r$ 太大时，分数 margin 增大但概率校准变差；$\lambda_b$ 太大时，选择器可能为了省预算放弃困难 query。

预算项若写成平均 gate 数，只控制均值。设四个 query 的候选数为 $(2,2,2,10)$，平均为 4；定长 kernel 的预算若是 4，三个短行浪费槽位，长行仍要截掉 6 个。更接近部署的约束是对超预算部分惩罚：

$$
\mathcal L_{\mathrm{over}}=
\frac1N\sum_i\max(0,\sum_jg_{ij}-k)^2. \tag{12}
$$

它仍不能生成固定形状，所以后期要用真实 hard top-k 前向。

**一次预算与质量手算。**

假设 8 个历史块的教师质量为

$$
p=(0.30,0.22,0.16,0.11,0.08,0.06,0.04,0.03),
$$

部署选择 3 块。oracle 覆盖 $0.68$。学生排序选中第 1、2、5 块，recall@$3=2/3$，质量覆盖为 $0.60$。若每块 64 token，主 attention 读取 192 token；加上 128-token 固定窗口，实际读取 320 token。上下文为 8192 token 时，主 attention 的逻辑读取比例为 $320/8192=3.90625\%$。

若 selector 为每块读取一个 32 维 BF16 摘要，8 块只读 $8\times32\times2=512$ 字节；扩到 1M token、块长 64 时共有 15625 块，单 query 摘要读取约 0.95 MiB。主 attention 虽保持 320 token，selector 扫描成本却随长度增长。训练损失只约束候选质量，不会自动消除这部分带宽。

把长度从 8192 扩到 131072，仍选 3 个全局块与 128 个窗口 token，主读取比例降到约 $0.244\%$。比例更稀疏并不意味着任务更容易：候选块从 128 个增至 2048 个，困难负样本增加 16 倍。长度外推必须同时看 selector 召回与扫描成本。

**概率质量可以控制自适应预算。**

固定 $k$ 对尖锐分布很浪费，对平坦分布又可能不够。若 selector 已经过概率校准，可以选择最小集合 $S_i$，使累计代理质量达到阈值 $\rho$：

$$
k_i=\min\left\{m:\sum_{j\in\operatorname{TopM}(r_i,m)}\hat p_{ij}\ge\rho\right\}. \tag{13}
$$

例如排序概率为 $(0.55,0.25,0.10,0.06,0.04)$，$\rho=0.9$ 时需要 3 项；另一行是 $(0.22,0.21,0.20,0.19,0.18)$，同一阈值需要 5 项。这能把预算给更困难的 query，前提是 $\hat p$ 的校准在长度外仍可靠。

实际 kernel 可把 $k_i$ 量化到几个档位，如 64、128、256、512，再按档位组 batch。这样比完全 ragged 更容易获得规则 tile，也比全批统一最大值少浪费。日志中要同时给平均 $k$、P95/P99 $k$ 和每档请求比例；只报平均值会隐藏少数超长行造成的尾延迟。

**预算课程不能和长度课程绑死。**

若长度从 8K 提到 32K，同时把 $k$ 从 16 降到 4，质量下降无法归因。更清楚的实验分三组：固定长度只退火 $k$，固定 $k$ 只增加长度，再测试两者联合调度。证据距离和干扰块数量也分别控制，才能判断模型怕远距离，还是怕相似负样本。

训练时可以用 $k_{train}=2k_{deploy}$ 起步，随后逐步缩小。每个阶段都在部署 $k$ 上跑旁路评测，否则大候选掩盖的问题会在切到部署预算时集中爆发。若模型只在大预算下稳定，应回到标签与负样本，而非继续增加退火步数。

## 2. 训练—推理一致性

**一致的是数据流，不只是参数。**

训练保存 BF16 selector key，推理量化成 FP8；训练每个 head 独立选取，推理按 GQA 组共享；训练输出任意 token 索引，kernel 按页或块扩张；训练允许候选 512 个，服务配置截成 256 个。参数完全相同，实际邻接图已经不同。

最直接的检查是把部署 selector 与 kernel 索引器接回训练框架，在同一 batch 保存三组集合：教师 oracle、训练实现候选、部署实现候选。逐层计算交集、概率质量和输出误差，再按 query 类型分桶。只比较最终 perplexity 会把少量严重漏检淹没在大量局部 token 中。

并列分数要有确定规则。top-k 在 cutoff 处出现相同值时，不同设备可能返回不同索引；activation checkpointing 的 backward 若重算出另一集合，梯度会对应错误前向。可固定次级排序键，或在 forward 保存索引而不重算。保存索引增加 activation，重算则要求随机状态、量化与归约顺序完全可复现。

**索引缓存与参数版本要同步。**

选择器 key 常在 token 写入时计算并缓存。训练中参数每步更新，若一条长序列被切成多个 micro-batch，旧 token 的缓存可能来自旧参数，新 token 来自新参数；两者被同一个 query 打分，分数尺度未必一致。完整序列并行训练通常一次构造全部 key，在线继续训练或带状态训练则必须定义缓存版本。

可选方案有三种：每次参数更新后重算活跃序列索引；在一个序列完成前冻结 selector key 投影；或用慢速 EMA 参数生成缓存，使跨 step 漂移更小。第一种精确但贵，第二种限制优化频率，第三种引入教师滞后。无论采用哪种，训练模拟和服务端都要遵循同一更新边界。

跨层共享也需要版本标记。上游层生成的候选交给若干下游层复用时，下游梯度若无法回到候选生成器，训练目标应显式包含这些层的联合 oracle。否则 selector 只对产生索引的那一层准确，下游层只能被迫适应一组并不合适的固定候选。

**teacher forcing 会放大路由偏差。**

语言模型训练看到真实前缀，生成时看到自己的历史输出。早期生成错误会改变后续 query 表示，selector 随之访问不同证据。普通自回归模型已有这种暴露偏差；动态路由又增加一层离散放大：query 轻微变化可能让第 $k$ 与第 $k+1$ 名交换。

可以用带噪 query、短段自由生成或学生轨迹蒸馏检验稳定性。语义相近的 query 应保住关键块，同时允许次要候选随表达变化。记录 Jaccard、质量覆盖差与 cutoff margin，比只看 router logit 的均方误差更贴近部署。

**稀疏 backward 也要兑现。**

训练原生稀疏只有在 forward、backward 都沿稀疏边执行时才节省训练成本。若 forward 选少量块，backward 为了方便又物化稠密 mask 或完整分数矩阵，显存和计算仍可能平方增长。NSA 强调训练、prefill 与 decode 的硬件对齐，正因为反向 kernel 也是完整方法的一部分。

训练报告应列出每层保存的索引、softmax 统计量和压缩状态，区分逻辑 FLOPs 与实测 step time。selector 教师若周期性运行稠密 attention，还要按频率摊入平均训练成本。

### 2.1. 长度外推与召回验收

**三类召回指标。**

第一类是集合 recall@$k$，用于快速比较排序。第二类是式 (3) 的概率质量覆盖，能区分教师强弱项。第三类是证据召回：数据已知答案依赖哪些 span，检查候选是否覆盖这些 span。三者回答不同问题。

还可计算 selected attention 与 dense attention 的输出差

$$
E_i=\frac{\|o_i^{\mathrm{sparse}}-o_i^{\mathrm{dense}}\|_2}
{\|o_i^{\mathrm{dense}}\|_2+\epsilon}. \tag{14}
$$

输出差包含 value 冗余信息，但仍停留在单层。最终要用长文问答、代码定位、多证据合成和 agent 轨迹回放验证。平均指标之外报告最差分位数，尤其关注低 margin、高熵与证据极远的 query。

**长度网格怎样设计。**

至少在训练长度内、训练长度边界和数倍外推长度上画曲线，例如 8K、32K、128K、512K。每个长度保持任务难度有可比版本，再增加固定数量与随长度增长的干扰项。若只把无关填充重复到更长，容易高估外推能力。

固定 $k$ 曲线揭示候选竞争加剧；固定保留比例曲线揭示质量需要多少计算；固定概率质量阈值曲线揭示每个 query 需要多少自适应预算。三条曲线一起看，才能决定线上采用定长 top-k、分桶预算还是质量阈值。

**失败模式对应哪些日志。**

路由塌缩表现为少数块访问频率极高、候选熵下降、不同 query 集合趋同；先检查负载损失和局部数据捷径。边界抖动表现为 $\Delta_i$ 接近零、量化前后候选交集下降；检查分数尺度、难负样本和确定排序。长度退化表现为短序列 recall 稳定、长序列随负样本数快速下降；需要扩大训练候选池与相似干扰，而非只调位置编码。

辅助损失下降但 LM 质量变差，常见原因是教师 attention 只代表一条合理路径，selector 过度拟合某个 head 的概率形状，或预算迫使主干失去可替代信息。训练正常、部署突然退化，则对比候选粒度、共享规则、量化和尾页 mask，避免把实现偏差误诊成模型能力。

**多证据任务要测联合覆盖。**

单点 passkey 命中一次便可答对，容易掩盖 selector 只会抓最显眼证据。若答案需要 $a,b,c$ 三段信息，逐段召回率分别为 $0.95,0.9,0.9$，粗略独立假设下三段同时命中的概率只有 $0.95\times0.9\times0.9\approx76.95\%$。单段指标看起来都很高，完整推理仍可能频繁断链。

数据应标注证据组，并计算 all-evidence recall、至少命中一个证据的 any-recall 以及证据出现的最远距离。对于存在多套等价证据的问题，标签用若干可接受集合表示；强迫模型命中某一套固定 span，会把合理路径误判为错误。代码任务还要覆盖定义、调用点与修改点同时检索，工具轨迹则覆盖早期观察、后续状态和最终约束。

### 2.2. 让每个实验都能回到具体原因

**最小消融矩阵。**

一组紧凑消融应包含：无辅助损失、仅 KL、仅排序、KL 加排序；soft routing、straight-through 与 hard teacher selection；随机负样本与困难负样本；独立 head 与 GQA 共享候选；训练长度内与长度外。每组固定主 attention 预算和实际块大小。

DSA 类 indexer 还要区分稠密预热 token 数与稀疏联合训练 token 数。NSA 类结构分别关掉 compression、selection 和 window，观察某条保护路径是否掩盖选择器失败。MoBA 类结构比较 full 到 sparse 的切换时点与候选数。KDA 不进入这套 top-k 消融，它应测试状态容量、门控和 full-attention 层比例。

训练过程可以明确写成四个状态。状态 A 只收集教师统计，确认不同层和 head 的分布是否值得压缩；状态 B 冻结主干，训练 selector 到召回与 margin 达标；状态 C 开启稀疏前向，以较宽预算联合优化；状态 D 收紧到部署预算，并接入真实量化与 kernel。每次状态切换只改变一组变量，还要留出固定 token 数的重叠评测窗口。

状态 B 中 selector loss 下降而 recall 不动，通常是概率尾部主导 KL，可提高教师温度的同时增加边界排序样本。recall 上升而质量覆盖不动，说明命中的多是低质量 oracle 项，应按教师概率加权。状态 C 中 LM loss 突升、selector 指标稳定，问题多半落在主干尚未适应、attention 归一化集合改变或 value 路径。状态 D 才退化，则优先检查预算、量化和 kernel 索引。

这套状态机也便于计算成本。假设稠密预热 20B token、宽预算联合训练 100B、部署预算训练 200B，报告中应分别列出三段吞吐与总 GPU 时。只报部署预算阶段200B token的稀疏吞吐，会漏掉为 selector 取得可靠起点所付出的稠密成本。若教师每 100 step 刷新一次，也把该 step 的额外计算摊回平均值。

**一张验收表。**

模型侧记录 LM loss、perplexity、下游准确率和长上下文任务；选择侧记录 recall@$k$、质量覆盖、证据召回、cutoff margin、候选熵和量化前后交集；系统侧记录 selector 时间、top-k 时间、主 attention 时间、HBM 字节、索引 activation 与通信不均衡；成本侧记录稠密教师频率和完整训练 step 吞吐。

所有指标都绑定长度、层、head 或 GQA 组、块大小和预算。一个「平均召回 95%」若没有这些条件，无法判断它对应 8K 还是 1M、token 还是 block、独立候选还是共享读取。

验收表还要保留分布，不只保留均值。对每层画 $C_i$ 与 $\Delta_i$ 的直方图，再按 query 位置、证据距离和任务类型切片。若总体质量覆盖为 0.97，但靠近输出的 10% 层只有 0.82，生成任务可能仍在深层整合时失败。若平均 cutoff margin 尚可，而少量长序列行接近零，线上尾部错误会集中在这些请求。

系统指标与选择指标用同一个样本 ID 对齐。某些 query 的候选分散在大量物理页上，逻辑 token 数相同，HBM 事务却更多；某些 batch 的 GQA 组并集过大，单 head recall 很高，实际读取没有下降。把 profiler 结果聚合到另一批数据上，会失去定位算法错误与布局代价的机会。

一个实用的回归门槛可以同时包含：长度内概率质量下降不超过给定阈值，长度外 all-evidence recall 不低于基线，P99 候选数不越过 kernel 档位，量化前后候选交集达到目标，端到端吞吐超过 full attention。具体数值由模型和业务决定，但不能用吞吐提升抵消证据召回失败，也不能用高召回掩盖预算溢出。

概率校准也应进入验收。把 query 按 selector 预测的覆盖置信度分桶，比较每桶真实教师质量；若模型声称有 0.9 覆盖的样本实际只有 0.6，自适应预算会过早停止。Expected Calibration Error 可以概括差距，可靠性图则能看出偏差集中在高置信还是低置信区。长度变化后重新画图，因为 32K 上校准良好的分数，面对 1M 候选时可能系统性过度自信。

线上没有稠密教师时，可以保留极小比例的影子流量，在离线环境重放完整 attention；正常请求只记录候选数、margin、距离分布、页数和耗时等不含正文的统计量。影子样本要覆盖长尾长度与低 margin 区间，随机均匀采样会被大量简单短请求占满。发现漂移后先冻结模型版本和 selector scale，再回放同一批输入，避免服务负载变化与模型变化混成一个原因。

对涉及隐私的线上数据，影子回放可以只保留经过授权的评测集与合成难例。候选统计按层和长度聚合，原始 token、页地址与用户标识都不落盘。这样仍能观察预算和边界漂移，又不会为了诊断 selector 建立另一份长上下文副本。

**从一次错误反推训练环节。**

假设长代码任务回答错了，稠密模型能答对。先把生成答案固定在错误前一 token，运行稠密教师与部署 selector。关键定义不在候选中，就查看教师是否把它列为高质量项；教师高、学生低，属于 selector 排序问题；教师也低，oracle 或主干 attention 已没有提供正确监督。关键定义已入选而输出仍错，则检查 sparse attention 数值、value 聚合和后续层是否再次丢失。

若错误只在 FP8 selector 出现，比较量化前后 $r_{i,(k)}$、$r_{i,(k+1)}$ 与 scale。大量翻转集中在小 margin 行，可用量化感知训练、分层 scale 或更稳的次级排序；直接扩大 $k$ 虽能止血，却会永久增加读取。若错误只在 batch 较大时出现，继续检查变长行 padding、候选缓冲区溢出和跨请求页表，训练 loss 无法覆盖这些实现问题。

若同一证据在 32K 能召回、128K 消失，固定 query 与正例分数，观察新增负样本中谁越过 cutoff。同主题重复块占满 top-k，说明难负样本不足；远距离正例分数系统下降，说明位置或表示外推存在偏差；selector 仍命中而 GQA 聚合后丢失，则共享规则压制了少数 head。三种现象需要完全不同的修复。

**可复现性落在索引细节上。**

复现实验至少保存 selector 参数版本、教师 checkpoint、温度、top-k 并列规则、负样本采样种子、块边界、尾块有效长度和 GQA 聚合方式。若使用周期性 oracle，还要记录刷新间隔与每次刷新覆盖的 token。它们共同决定训练期间实际出现的稀疏图。

检查点除了模型与优化器状态，还要包含课程进度、当前预算、温度、EMA 教师和采样器状态。恢复训练时若预算退火回到初值，模型会突然看到更多候选；若教师 EMA 丢失，KL 目标会跳变；若随机负样本序列改变，短窗口内的 route loss 也难以逐步对齐。

端到端复现应固定一小组索引探针。每次保存 checkpoint 时，对同一输入输出逐层 top-k、分数 margin 与质量覆盖。模型质量出现回归后，可以沿 checkpoint 追到最早发生候选翻转的层和长度，不必只凭最终 benchmark 猜测原因。

**最终判断。**

router loss 收敛只完成了训练日志中的一项。部署数据流还要用规定预算召回证据，主干能够使用这组候选，长度增加后的退化也能被指标定位。oracle 给方向，代理梯度解决可训练性，预算把模型约束到可执行形状，联合训练让主干学会在缺边的图上工作。

四者的顺序也很重要：确认教师标签与部署粒度一致之后，再选择 KL、排序或 straight-through；随后逐步收紧预算，并用真实 kernel 回放候选。若一开始就把所有技巧堆进总 loss，训练即使稳定，也很难知道究竟是哪条路径支撑了结果。

## 3. 教师计算与分布式训练

**稠密教师会不会抵消训练节省。**

如果每个稀疏训练 step都额外运行完整稠密 attention产生教师, forward成本可能重新接近平方级. DSA式预热明确接受这笔开销, 目标是先获得可靠selector; 稀疏联合阶段则要检查教师分数是全量重算、只在候选上重算, 还是由周期checkpoint提供. 三种路径的监督强度和训练成本不同.

离线教师可以预先为固定语料保存 top位置与概率, 不必在学生训练时重复稠密前向. 代价是标签绑定教师checkpoint和当时的tokenization、位置与数据增强. 学生主干继续更新后, 旧教师描述的attention偏好可能不再匹配. 在线EMA教师跟随学生更及时, 需要维护额外参数或稠密计算.

周期性刷新是中间方案. 每隔 $R$ step运行一次稠密教师, 中间使用缓存标签. 平均教师开销约降到原来的 $1/R$, 标签陈旧度上升. 应记录刷新前后recall和LM loss是否跳变; 若每次刷新都出现明显冲击, 说明学生表示变化快, $R$ 太大或教师目标不稳定.

**不要保存平方概率矩阵。**

KL监督看起来需要教师整行分布, 长序列下直接保存 $n\times n$ attention不可接受. 一种做法是在FlashAttention重算中流式提取 top-$m$教师位置、对应logits与行log-sum-exp. 对选中位置 $j$, 概率可由:

$$
p_{ij}=\exp(s_{ij}-\operatorname{LSE}_i) \tag{15}
$$

恢复. 未保存的长尾可聚合为剩余质量, 或用采样负例近似. 这样标签容量为 $O(nm)$, $m$ 仍需说明. 只保留 top-$m$会丢掉尾部分布, KL含义已经从全分布蒸馏变成截断蒸馏.

Block selector可在tile内直接累计块质量, 保存 $O(N_qN_k)$ 的块矩阵仍可能很大. 进一步只保留每行 top blocks和LSE, 或边计算边产生困难负样本. 教师提取kernel需要与训练attention共享QK计算, 若另起一次完整前向, 省下的activation可能换成重复FLOPs.

**Sequence Parallel 下怎样构造全局标签。**

历史token分散在 $P$ 张卡时, 每卡只拥有本地keys和局部教师候选. 全局 top-$m$可先在本地取 $m$ 项, 再交换最多 $Pm$ 项做merge. 这与分布式检索相同, 通信从全部分数降为候选对 `(score,index)`. 全局位置要带序列分片offset, merge后再广播学生需要的标签.

概率质量还需要全局LSE. 每卡先求局部最大值 $a_p$ 与指数和 $z_p$, all-reduce得到:

$$
a=\max_p a_p,\qquad
z=\sum_p e^{a_p-a}z_p. \tag{16}
$$

随后 $\operatorname{LSE}=a+\log z$. 只合并top候选而用本地分母, 会高估本地概率并给不同rank不一致的教师. 这个collective位于训练关键路径, 要进入step time.

若主attention heads按Tensor Parallel切分, 共享selector教师还要在head维聚合. 可以先各rank计算本地head贡献, 再归约token分数; 也可以让每rank生成局部重要token并合并集合. 前者更接近全局教师, 通信量大; 后者保留专用head峰值, 候选并集可能膨胀. 训练配置必须与部署时共享规则一致.

**路由负载与优化器状态。**

MoBA或少head indexer包含离散路由时, 某些块、head长期不被选, 对应参数收到的梯度稀少. 负载均衡损失可以提高使用率, 也可能强迫query选择并不相关的路径. 应同时观察路由频率和每条路径的独占教师召回: 低频但承载罕见证据的head不能仅因使用率低而裁剪.

路由参数通常远小于主模型, 可使用不同学习率与优化器组. 稠密预热阶段只有selector更新时, scheduler步数不应误推进主模型的退火; 联合阶段再分别设置. 检查点必须保存各组step和momentum. 恢复时若selector优化器被重置, 候选会在短期漂移, 主模型即使参数未变也会看到不同稀疏图.

梯度裁剪最好分组记录. 主LM梯度稳定而selector梯度频繁触顶, 可能来自极小cutoff margin或少数困难样本; 全局统一裁剪会顺带压低主模型更新. 反过来, selector loss数值较小也不表示梯度小, KL温度和候选数都会改变尺度.

### 3.1. Oracle标签与真实输出之间还有一层距离

**最大attention权重未必对应最大输出贡献。**

教师注意力把分数变成概率 $p_j$，输出为 $o=\sum_jp_jv_j$。若删去位置j并在其余位置重新归一化，输出变化可以精确写成

$$
o^{(-j)}-o=\frac{p_j}{1-p_j}(o-v_j). \tag{17}
$$

这条式子把“权重大”和“删掉以后影响大”分开了。$p_j$ 很大，但 $v_j$ 与当前输出接近，删除影响仍可能很小；$p_j$ 较小，但 $v_j$ 携带一个方向独特的特征，变化会更显著。直接用attention top-k作oracle，默认概率质量足以代表value贡献，这个近似在value高度冗余时尤其粗糙。

输出感知标签可以使用 $p_j\|v_j-o\|$ 作为单点重要性近似。它来自式(14)忽略 $1-p_j$ 后的主项，计算只需教师概率、value和输出。块级标签则可比较删除整块后的输出变化，或对块中单点贡献求和。多个value方向会相互抵消，逐点求和仍会高估；直接做块消融更准确，成本也更高。

训练可混合两类oracle。概率质量标签稳定、容易流式计算，输出感知标签更贴近当前层表示。令

$$
y_j=\alpha p_j+(1-\alpha)
\frac{p_j\|v_j-o\|}{\sum_s p_s\|v_s-o\|}, \tag{18}
$$

$\alpha$控制教师分布忠实度与输出敏感度。这个标签仍然只描述单层局部影响，不能直接替代语言模型损失；它的价值在于给边界位置提供更有区分力的监督。

**成组删除揭示证据之间的互补与替代。**

稀疏选择一次删除很多位置，单点贡献相加无法表示交互。两个token单独删除都影响很小，合并删除却可能丢掉全部证据，因为它们互为备份；另一些token分别承载事实和限定条件，需要共同保留才能回答。集合价值可以记为

$$
F(S)=-D\bigl(o_S,o_{\mathrm{dense}}\bigr), \tag{19}
$$

其中 $o_S$ 是只保留集合S得到的输出，D可取均方误差、余弦距离或下游logit散度。训练selector实际在有限预算下寻找高F集合。

若F近似满足边际收益递减，贪心扩展集合具有良好性质：每轮加入让F提升最大的块。attention重归一化、value抵消和后续非线性会破坏严格次模性，因此它更适合作为oracle构造启发，而非普遍定理。离线可在小候选池上贪心生成高质量集合，再蒸馏给廉价selector。

替代证据要求标签允许多解。文档中两处都写明同一事实，固定teacher top-k可能只选其中一处，学生选择另一处仍能保持输出。将标签写成唯一二元集合会制造伪负例。可用输出保持作为软判据，或把等价证据簇标成“命中任意一个即可”。多解标签会降低表面集合recall，却更忠实地反映任务。

**下游logit蒸馏把层误差映射到预测空间。**

选择器最终服务于下一个token分布。令dense模型输出logit为 $u$，稀疏模型为 $\tilde u$，可加入

$$
\mathcal L_{\mathrm{out}}=
\tau_o^2\operatorname{KL}
\left(\operatorname{softmax}(u/\tau_o)\middle\|
\operatorname{softmax}(\tilde u/\tau_o)
\right). \tag{20}
$$

温度平方用于补偿软化后梯度尺度。它允许稀疏模型采用与attention教师不同的内部路径，只要预测分布保持接近。缺点是归因较弱：logit变化可能来自selector、主干适应或其他层误差，单靠输出蒸馏无法告诉哪一层漏掉了什么。

一种折中是随机选择少量层单独稀疏，其余层保持dense，测该层引起的logit KL。这样可为各层生成敏感度权重，训练时给高敏感层更强监督或更大预算。逐层消融成本高，不必覆盖每个step；周期性探针足以估计相对排序。

语言模型交叉熵与logit蒸馏也会冲突。教师在某个样本上预测错误时，完全模仿教师会阻碍学生学习正确标签；只用真值交叉熵又可能让稀疏路径偏离dense能力。可让蒸馏权重随教师真值概率变化，教师越确信正确答案，保持其分布的价值越高。

**因果oracle只能使用选择时可见的信息。**

标签可以由未来结果评估，selector输入却必须受部署因果性约束。例如生成完整答案后，能够知道早期哪个文档片段真正有用，并把它作为监督标签；训练时selector仍只能看当时query与历史缓存。这样的后见标签类似强化学习中的回报，不构成输入泄漏。泄漏发生在未来token、答案表示或未来层状态进入selector特征时。

应把“标签可使用的信息”和“策略可使用的信息”列成两张表。标签侧可以用dense attention、完整答案正确性、块消融和后续logit变化；策略侧只有当前层query、已缓存索引、位置与合法元数据。离线生成标签时把答案拼入双向编码器，再将该编码器表示喂给线上selector，会得到不可部署的高分。

工具调用轨迹的因果边界更细。当前决策可以读取已经返回的工具结果，下一次工具调用结果尚不可见；训练记录里二者常被存成完整轨迹，切片稍有错误就会泄漏。按事件时间戳构造可见前缀，并为每个路由决策保存visibility mask，能把约束落实到数据层。这条边界需要用自动测试固定下来。

### 3.2. 离散选择的梯度究竟在估计什么

**Softmax松弛优化的是加权混合。**

用soft gate $g_j$ 替代hard top-k时，主attention看到所有位置的连续混合。部署函数记为 $f(h(r))$，训练松弛函数为 $f(g_\tau(r))$。当温度趋近零且分数无并列时，$g_\tau$逐渐集中；有限温度下，两个函数的前向行为不同，梯度

$$
\nabla_r f(g_\tau(r))
$$

描述“轻微调整每个位置权重”的收益，无法完全代表“把第k与第k+1项交换”的离散收益。温度越低，函数更接近hard选择，softmax导数也更容易集中或消失。

可用训练—部署差距直接监控松弛质量。同一batch分别运行soft门、hard门和扩大预算hard门，比较输出与梯度方向。soft质量很好而hard质量差，说明主干利用了大量小权重；两者前向接近但selector梯度方向差异大，则可能存在边界不稳定。只观察训练loss无法区分这两种情况。

稀疏化可以使用连续阈值门，再在后期切换top-k。阈值门允许每行候选数变化，适合学习“哪些位置值得保留”；top-k强制固定容量，适合部署。切换前需让阈值产生的候选数分布靠近目标K，否则一次形状变化会同时改变质量和负载。

**Straight-through估计器的偏差可以被测量。**

straight-through把hard前向的梯度替换成soft代理梯度。设真实期望目标为 $J(r)=\mathbb E_h[L(h)]$，代理给出的 $\widehat\nabla J$ 一般有偏。小候选空间中可以枚举或有限差分估计真实变化：逐个提高边界候选分数，观察hard集合翻转后的loss差，再与代理梯度符号比较。

符号一致率比梯度均方误差更有解释力。选择问题关心某个候选应上升还是下降；尺度可以由优化器吸收，方向反转会持续强化错误排序。可在训练探针上报告边界位置的符号一致率、余弦相似度以及发生集合翻转时的实际loss变化。

代理温度、margin和候选间隔共同影响偏差。分数差很大时，集合稳定，代理梯度主要做无用的继续拉开；分数接近时，集合敏感，过低温度又可能让梯度只落到当前赢家。训练可把梯度重点放在一个cutoff带内，例如第 $k-m$ 到 $k+m$ 名，避免对显然无关的长尾消耗容量。

**随机门控可以得到无偏但高方差的估计。**

将选择视为从分布 $\pi_\theta(S|q)$ 采样集合，REINFORCE给出

$$
\nabla_\theta\mathbb E_{S\sim\pi_\theta}[L(S)]
=\mathbb E[(L(S)-b)\nabla_\theta\log\pi_\theta(S|q)]. \tag{21}
$$

在采样与损失计算正确时，该估计无偏；集合空间巨大，方差往往难以接受。baseline b可取同query的滑动平均、dense损失或另一个价值网络。采样若直接从百万token中进行，绝大多数集合质量很低，学习信号接近噪声。

分层采样可先由便宜规则缩小候选池，再在池内随机探索。还可成对采样两个仅差一个块的集合，用损失差作为局部优势，抵消共享噪声。它与困难负样本排序相连：排序loss使用教师给局部交换定方向，策略梯度使用任务loss评估交换结果。

随机估计更适合后期微调少量边界选择，而非从零训练整个indexer。先靠蒸馏建立可用排序，再用任务回报修正教师代理目标与真实质量的偏差，可以显著缩小探索空间。

**Gumbel扰动训练的是随机排序分布。**

给每个分数加入独立Gumbel噪声再取top-k，可从无放回的排序分布采样集合。训练中使用可微近似，能让边界外候选按分数获得探索概率。噪声尺度大时集合多样，主干承受更强随机缺失；尺度小时接近确定top-k，探索迅速消失。

随机路由相当于结构化dropout，会迫使模型减少对单一路径的脆弱依赖，也可能降低精确检索能力。应分别测确定推理与随机训练下的质量，确认收益来自鲁棒性而非测试时继续采样多个集合。线上若只运行一次确定top-k，训练目标最终要向该行为收敛。

Gumbel噪声的可复现性涉及sequence parallel。各设备若对同一全局候选生成不同噪声，归约后集合不再对应单一采样；应使用全局位置派生随机数或由负责分片生成并带分数归并。activation重算也要恢复同一随机流，否则backward看见另一集合。

## 4. 预算约束可以写成优化问题

**拉格朗日乘子给计算定价。**

固定K把所有query视作同样困难。若允许每个query选择不同数量 $k_i$，可优化

$$
\min_\theta\;\mathbb E[L_i(S_i)]
\quad\text{s.t.}\quad
\mathbb E[c(S_i)]\le B, \tag{22}
$$

其中c是读取字节、FLOPs或时延代理，B是平均预算。拉格朗日形式为

$$
\mathcal J=\mathbb E[L_i(S_i)+\lambda c(S_i)]-\lambda B,
\qquad \lambda\ge0. \tag{23}
$$

$\lambda$可以理解为每单位计算的价格。质量对额外候选很敏感的query愿意付出更多预算，容易query主动收缩。训练可交替更新模型参数与 $\lambda$：预算超标时提高价格，预算富余时降低价格。

成本代理必须接近部署。按token数计费会偏爱零散选择，实际kernel按块读取时成本取决于触及块数；按FLOPs计费忽略不规则gather，带宽受限硬件上的排序可能错误。可以用微基准拟合分段成本表，把长度、K、块大小和batch档位映射到时延，再在训练中查表。

**平均预算之外还要约束尾部。**

平均K达标仍可能产生少量超大候选，拖慢整个batch。若kernel以batch内最大K分配，实际成本接近 $\max_i k_i$；continuous batching中，P99大K请求也会占据更多调度时间。可以加入分位数或条件风险约束：

$$
\operatorname{CVaR}_\alpha(c)=
\min_\eta\left[
\eta+\frac{1}{1-\alpha}\mathbb E(c-\eta)_+
\right]. \tag{24}
$$

它关注最昂贵的尾部样本。$\alpha=0.95$时，目标主要压制最高5%的成本。与简单最大值相比，CVaR梯度更稳定，也不会让单个异常样本支配训练。

部署若只有若干K档，训练也可预测档位概率。成本使用对应档位的真实表项，hard前向按选中档执行。档位边界会产生新的离散问题，可用相邻档探索或straight-through处理。验收要报告各档占比和同batch填充浪费，而非只给每query理论K。

**每层预算分配类似受限资源调度。**

总预算B可以在L层间分配 $k_1,\ldots,k_L$。第l层多给一个块带来的边际质量收益记为 $\Delta_l(k_l)$。若收益曲线近似递减，最优分配趋向让各层边缘预算的收益接近。均匀K隐含所有层同等敏感，通常缺乏依据。

边际收益可通过离线干预估计：固定其他层预算，只改变第l层K，测logit KL或任务loss变化。得到曲线后初始化层预算，再让联合训练微调。相邻层候选高度重合时，还可共享读取或复用索引；共享节省成本，也会把两层决策耦合，应在成本函数中体现。

层预算不能无限收缩。局部窗口、sink和最低全局候选构成安全下限；超过某一层的最大有效K后，新增候选几乎不改善质量，可设置上限。投影到上下界约束的预算单纯形，比自由gate加一个平均惩罚更容易得到可部署形状。

**质量阈值需要概率校准。**

自适应预算依赖selector概率代表真实重要性。排序准确并不保证校准：所有logit乘10，top-k完全不变，累计概率却会更尖锐，质量阈值会过早停止。可按长度、层和query熵计算expected calibration error，或比较预测累计质量与教师真实覆盖。

温度缩放能校正整体尺度，无法修复不同query类型的系统偏差。分桶温度可依据层、长度或检索类型设置；更灵活的校准器又会增加部署状态。校准数据必须覆盖训练外长度，因为候选数增加后softmax分母和极值统计都会变化。

保守部署可以给预测漏失质量加安全余量。若验证集上某分桶的预测误差95分位为 $\epsilon$，目标覆盖 $\rho$ 时让selector累计到 $\rho+\epsilon$。这不是严格分布无关保证，至少把经验校准误差转化为明确预算，而非凭感觉多加固定K。

### 4.1. 联合训练中的梯度冲突

**四项损失可能把selector推向不同方向。**

KL要求复制teacher分布，排序loss只关心cutoff，预算loss鼓励少选，LM loss关心最终预测。对selector参数 $\theta_s$，分别得到梯度 $g_d,g_r,g_b,g_{lm}$。若 $g_a^\top g_b<0$，两个目标在当前step发生冲突。简单加权会让范数最大的梯度主导，权重数值本身又受loss尺度影响。

训练日志可记录梯度范数和两两余弦。若预算梯度长期与LM梯度反向，当前B可能低于模型可承受范围；若KL与LM持续冲突，teacher attention可能不是保持预测的唯一或最佳路径；排序与KL冲突常来自尾部分布拟合和边界margin竞争。

可使用梯度投影减少直接冲突，或动态调整权重让各目标贡献接近。算法选择之前，更重要的是识别冲突发生在哪些层和样本。全局平均余弦可能掩盖长上下文困难样本上的强反向，因此要按长度、预算和query类型分桶。

**Selector与主干会形成移动目标。**

selector改变邻接图，主干适应新图；主干更新query/key后，selector的标签与打分空间又改变。两个模块同时大步更新会产生追逐：刚学会的候选在下一轮主干变化后失效，loss表现为周期振荡。预热只能解决初始冷启动，联合阶段仍需控制相对时间尺度。

一种做法是交替冻结。若干step固定主干训练selector，使其追上当前oracle；随后固定或降低selector学习率，让主干适应稀疏图。另一种做法是teacher使用EMA主干，标签变化更平滑，学生主干仍正常更新。EMA滞后过大时，selector会服务旧表示，需要监控新旧oracle差异。

更新频率应与缓存语义一致。selector key被预计算并在多个step复用时，参数快速变化会让旧key失效；冻结key投影一段时间可同时稳定缓存与目标。query投影和主干仍能更新，但需检查新query对旧尺度key打分是否漂移。

**路由塌缩可能被语言模型掩盖。**

主干很强时，即使selector总选局部窗口或少数高频块，短训练样本的LM loss仍能下降。模型利用局部统计绕开检索，selector看似稳定，长任务才暴露失败。需要对选择行为施加直接诊断：块访问频率、不同query候选Jaccard、距离分布和已知证据召回。

负载均衡损失可以鼓励全batch覆盖更多块，却不能要求单个query选择正确证据。过强均衡甚至会把候选推向无关冷门块。更合适的组合是以teacher或证据标签决定正确性，用均衡项防止共享专家长期闲置，并把均衡统计限制在语义相近的可比样本内。

塌缩也可能发生在多个selector head之间。所有head学习相同分数可提高共同热门证据的稳定性，却浪费多头容量。可记录head候选重合与各自oracle覆盖，适度加入多样性项；若任务确实只需同一证据，强制多样会损害质量，所以多样性只能作为有条件的正则。

**稀疏图改变了优化噪声。**

hard选择使相邻step的计算图随分数边界跳变。即便输入相似，第k名附近的微小变化也会让一个整块进入或离开，主干梯度出现结构性噪声。增大batch只能平均不同样本，无法消除同一样本的边界翻转。

提高cutoff margin、使用候选滞回或训练时并入边界缓冲区都能降低翻转。滞回可让新块分数超过旧块一定幅度才替换，部署集合更稳定，但可能延迟真正重要的新证据。边界缓冲区在训练读取 $k+m$ 块，loss仍要求前k排序正确，随后逐渐减小m。

优化器状态也会受到稀疏更新频率影响。某些块表示或专家参数很少被路由到，二阶矩估计陈旧，偶尔激活时步长异常。可让selector表示共享参数、周期性加入探索样本，或对低频参数使用独立优化设置。报告全局学习率不足以复现这种行为。

### 4.2. 数据课程要增加检索难度而非只增加长度

**长度由多个可分离变量组成。**

把序列从8K扩到128K同时改变了证据距离、候选数量、主题数量与重复模式。selector失败后无法知道是哪一项造成。数据生成应独立控制：固定距离增加干扰块，固定干扰数拉远证据，固定长度增加同名实体，再固定前述变量改变证据数量。

候选数量影响极值竞争。即使负样本分数分布不变，样本数增加后最大负分数也会上升，top-k边界更难守住。训练只重复无关填充，负样本过于容易，无法模拟这种统计压力。困难干扰需要在词汇、实体、结构或推理角色上接近真证据。

位置分布也应覆盖边界。若训练证据总在块中央，部署证据跨块时聚合表示可能把两半都判低。随机移动block offset、改变分词后长度、加入未满尾块，可以让selector学到对分页偶然性的鲁棒性。

**单证据课程之后要进入组合证据。**

单点检索主要训练高精度匹配。多跳问题要求同时覆盖若干弱相关块，任何一块单独看都不一定获得最高分。课程可从唯一强证据开始，逐渐加入两段关系链、相互约束的数值条件和跨文件定义—调用关系。

标签应保存证据依赖结构。若A和B必须同时命中，loss可惩罚联合缺失概率；若A1与A2任选其一再搭配B，标签是析取与合取的组合。简单把所有标注span视为独立正例，会要求模型浪费预算覆盖全部等价证据。

组合任务还要防止答案捷径。若最终答案在某个局部块直接出现，模型无需读取推理链，证据召回训练会与LM目标分离。构造时可让每个块只提供中间变量，答案必须由组合得到，并用反事实替换检查模型是否真的依赖各段。

**真实语料负责暴露合成规则没想到的模式。**

合成数据能精确控制变量，却容易留下格式线索：固定提示词、特殊分隔符、证据总出现在某种模板。selector可能学会模板定位，在自然文档中失效。真实长文、代码仓库、对话与工具轨迹应进入后半程训练和全程验证。

真实数据缺少完整证据标注，可用dense teacher、检索扰动和块消融产生弱标签。把某块替换为相似错误块，观察答案logit或损失变化，可以估计因果重要性。弱标签有噪声，适合用软权重和多视角一致性训练，避免当作绝对二元真值。

数据混合比例应按“路由现象”统计，而不只按领域名。需要知道单/多证据、重复实体、局部/远程依赖、块边界和query熵各占多少。两个都叫代码的数据集，若一个只做局部补全，另一个要求跨仓库定位，对selector的训练价值差别很大。

**课程切换要留下可归因的对照。**

长度、预算、噪声、hard路由和主干解冻若在同一步切换，loss台阶无法解释。每次只改变一个轴，并保留旧阶段验证集。进入更长长度后，短长度质量下降可能是灾难性遗忘；短长度稳定、长长度差则说明外推未建立。

每个阶段保存selector checkpoint和固定探针候选。探针包括容易query、边界query、多证据query和训练外长度query。比较集合、分数margin与输出误差，能看到课程究竟改变了排序能力、校准还是主干容错。

训练结束前应运行一次完全匹配部署的数据流：相同量化、块大小、GQA共享、K档、位置编码和kernel索引。这个阶段不再追求大量参数更新，主要暴露实现切换造成的落差。发现明显退化时回到对应训练轴修正，避免用延长训练掩盖结构不一致。

## 5. 一套能判定训练是否成功的验收逻辑

**Oracle上限先判断预算是否可行。**

在评价学生selector前，先用真实teacher分数或输出感知贡献，在同样粒度和预算下构造oracle集合。若oracle本身无法保持质量，问题出在预算、块大小或静态约束，继续扩大selector容量没有意义。Oracle应经过同一GQA共享和局部窗口规则，避免给出不可部署上限。

至少比较三种上限：按attention质量选块、按输出贡献选块、允许任务损失搜索的集合。它们之间的差距说明代理目标有多少损失空间。学生接近attention oracle却离任务oracle很远时，应改标签；学生远低于所有oracle时，才主要检查模型容量、优化和数据。

随机、距离优先和静态高频块是必要下限。复杂selector若只略高于局部窗口，可能主要利用位置先验；若在同主题困难负样本上仍显著领先，内容相关表示才真正发挥作用。基线使用同样总读取字节，不能让selector额外摘要成本被忽略。

**将误差拆成表示、排序与预算三部分。**

给定selector表示，可用精确打分全排序，得到表示与打分能力；给定真实teacher分数，再施加部署K，得到预算上限；给定学生分数但扩大K，观察排序错误能否被宽预算弥补。三组实验形成误差分解。

表示误差表现为正负块在embedding空间难以分开，即使优化排序器也无济于事；排序误差表现为表示含有信息，但训练目标或优化未把边界排对；预算误差表现为学生排序尚可，K仍不足以覆盖平坦分布。不同误差对应增加维度、改损失与增预算三种完全不同的动作。

量化误差单独放在部署层。比较FP32分数、训练精度分数与部署量化分数的集合变化，关注cutoff附近翻转。若浮点学生已接近oracle，量化后骤降，继续训练主干收益有限，应校准尺度或做量化感知训练。

**成对反事实检查selector是否依赖正确特征。**

构造两条只改变关键事实的上下文，query保持相同，正确候选应随事实位置移动；再固定事实内容只改变位置，候选应保住语义块，同时允许位置先验产生合理变化。成对样本能检测selector是否只记关键词、位置或模板。

还可以交换两个同名实体的属性，保留表面词频。若selector始终选择最近或出现最多的实体，说明它没有利用query关系。代码中可交换函数实现而保留签名，工具轨迹中可让早期成功结果在后续被撤销，检验路由是否读取最新有效状态。

反事实不只看候选是否变化，还要看主干输出是否随正确证据变化。selector选对而答案不变，主干可能忽略远程信息；答案变化但候选没变，可能由局部捷径驱动。二者联测才能确认完整因果链。

**训练曲线需要和行为曲线对齐。**

总loss下降不能代替路由验收。每个checkpoint至少同步绘制teacher质量覆盖、证据联合召回、cutoff margin、候选多样性、预算分布、dense—sparse输出差与任务质量。某条辅助曲线改善而任务恶化时，可定位代理目标错配。

曲线应按长度和难度分面。总体提升可能只来自大量短样本，训练外长度持续退化；平均margin增大也可能牺牲少数多证据query。对最差分位样本保存匿名化错误类型和中间指标，便于回到数据或损失设计。

验收通过的含义可以明确成四项：同预算oracle证明容量可行，学生与oracle差距处于容忍范围，部署实现与训练候选高度一致，任务质量在目标长度和困难子集上保持。四项同时成立，才能说联合训练得到了一条可用稀疏路径。

### 5.1. 多头共享会把监督问题变成多目标覆盖

**每个attention head看到的证据价值不同。**

同一层里，不同head可能分别编码局部语法、实体指代、位置模式和远程检索。若为每个head独立构造teacher top-k，标签集合的交集往往有限。共享selector需要用一组候选服务多个head，相当于在有限预算内覆盖多组需求。

设组内head集合为H，第h个head对块b的teacher质量为 $P_{hb}$。简单求和分数

$$
Y_b^{\mathrm{sum}}=\sum_{h\in H}P_{hb} \tag{25}
$$

最大化总覆盖，容易牺牲只有单个head需要的块；最大值

$$
Y_b^{\max}=\max_{h\in H}P_{hb} \tag{26}
$$

保护尖锐需求，却会让一个噪声head支配选择。还可使用饱和覆盖目标 $\sum_h\min(\sum_{b\in S}P_{hb},\rho_h)$，某个head达到所需质量后，新增预算转给覆盖不足的head。

训练验收应报告每head覆盖分布，尤其是最差head和低分位head。平均覆盖高可能由几个宽分布head贡献，真正承担远程检索的少数head持续漏选。若最差head对任务影响很小，可用敏感度权重降低其优先级；若它携带唯一证据，组级平均就会误导。

**共享表示和共享候选是两个独立决定。**

多个head可以共享低维key索引，但保留各自候选；也可以各自打分后合并成共享候选。前者减少索引存储与投影参数，后者进一步减少KV读取。把两步同时切换，质量变化无法归因。

共享key表示要求它保留多个head需要的方向。假设每个head的key投影子空间差异很大，单一低维表示会产生信息瓶颈。可用分组表示、共享主干加小型head适配器，或提高维度。独立候选实验能先判断表示是否足够：若共享表示下逐headtop-k已经退化，合并候选只会继续放大问题。

共享候选还涉及物理复用。各head独立选出的集合若高度重合，取并集只增加少量页，几乎无质量损失；重合率很低时，固定组预算必须做艰难取舍。训练前统计oracle集合Jaccard，可为GQA分组大小和selector共享粒度提供依据。

**Head重要性权重需要来自干预。**

按attention熵或权重峰值判断head重要性很方便，却不一定对应输出敏感度。可在dense模型中逐head替换为局部窗口、均匀输出或零输出，测下游logit与任务质量变化。干预得到的敏感度 $w_h$ 可以进入组级标签：

$$
Y_b=\sum_{h\in H}w_hP_{hb}. \tag{27}
$$

单head删除会被其他head补偿，因此敏感度依赖同时干预的集合。完整组合实验指数增长，实际可用随机head mask拟合局部贡献，或只对候选共享组做小规模组合消融。权重随层、任务和训练阶段变化，固定一次后长期使用可能过时。

权重过于集中也有风险。训练会优先服务当前最敏感head，其余head逐渐失去功能，进一步强化权重集中。可给每个head设置最低覆盖，再用敏感度分配剩余预算；周期性重算敏感度，检查是否出现这种自我强化。

**Head多样性应服务于覆盖而非形式差异。**

对selector head加入正交或候选排斥损失，能降低重复集合。若多个head确实需要同一关键事实，排斥会迫使一部分head选择次优块。多样性目标应只奖励“新增有效覆盖”，例如某块已经被其他head高质量覆盖后，另一个head选择新的teacher正例才获得奖励。

可以定义边际覆盖

$$
\Delta_{h,b}=F(S_{<h}\cup\{b\})-F(S_{<h}), \tag{28}
$$

让第h个selector按增益选择。顺序会影响结果，可在训练中随机head顺序，或用并行近似估计当前公共集合之外的贡献。这样学到的是互补检索，而非单纯让embedding角度不同。

多样性还应区分位置和内容。两个head选择相邻块可能内容互补，位置Jaccard却认为重复；选择远处两个完全相同副本，位置多样但语义没有新增。证据簇、文档段落ID或value相似度能提供更贴近内容的重复判断。

**跨层共享需要处理延迟监督。**

一个selector为连续多层生成候选时，早期层的query负责预测后续层会需要什么。后续层teacher标签可以反向监督该selector，形成多层联合目标

$$
\mathcal L_{\mathrm{shared}}=
\sum_{l=l_0}^{l_1}\beta_lD(y^{(l)},\hat y^{(l_0)}). \tag{29}
$$

各层oracle冲突时，共享候选只能折中。将所有层标签求和偏向反复被需要的块，取最大值保护单层尖峰，分配少量层私有预算则能修复局部需求。

跨层复用的价值来自减少索引扫描与gather变化，也会让候选无法随表示演化。可测相邻层oracle重合率和共享后输出误差，选择自然稳定的层段；跨越功能变化明显的层边界通常代价更大。共享范围应由数据决定，层号整齐并不构成充分理由。

训练中还需明确梯度汇聚。后续多层损失同时更新早期selector，梯度范数可能随共享层数增长；归一化 $\beta_l$ 或按层敏感度加权可防止某层独占。主干是否允许通过候选分数回传，也会改变selector学到“预测后续需求”还是只模仿离线标签。

### 5.2. 鲁棒训练要覆盖部署中的数值与分布变化

**量化感知训练应盯住排序边界。**

selector部署常用FP8或INT8表示与分数。量化误差对远离cutoff的候选影响很小，最危险的是第k名附近。训练中插入伪量化，既计算常规排序loss，也比较浮点与量化后的候选集合。边界一致性项可写成浮点正例与量化困难负例之间的margin。

量化尺度按tensor、head或通道设置，会改变哪些维度损失最大。低维indexer若少数通道幅值异常，全tensor尺度会浪费大部分量化级别；通道尺度更精细，元数据和kernel更复杂。应同时报告分数误差、候选翻转率和任务误差，分数均方误差小仍可能在密集边界产生大量翻转。

饱和值需要单独统计。训练分布内没有溢出，长度外query范数或位置变换可能扩大幅值，部署量化突然截断。对query/key范数做分位监控，并在训练加入接近部署范围的幅值扰动，可提前暴露问题。直接强制很小范数会削弱分数margin，范围与可分性需要一起优化。

**并列与有限精度要求稳定排序策略。**

低精度会制造大量相同分数。top-k在并列区选择哪些位置，可能依赖线程归约和设备实现。训练若默认连续浮点几乎无并列，就没有学会处理这种集合不确定性。可在分数上加入与量化步长相当的扰动，测关键证据在并列选择中的生存概率。

确定次级键能提供复现性，例如分数相同时按位置或块号排序。次级键本身会引入偏好：按最近位置优先会加强局部性，按块号优先偏向前缀。训练与部署使用同一规则，并在评测中构造关键证据位于并列区不同位置的样本，才能知道该偏好的代价。

另一种办法是在cutoff并列时扩大候选，读取全部同分页。质量更稳，K变成动态值，最坏情况下可能大幅膨胀。可限制最多扩展m个位置，超出后使用确定规则。训练预算模型需要包含这部分尾部成本。

**分布漂移往往从负样本开始。**

新领域中，关键证据可能仍然是清晰实体或关系，干扰项的形式却大幅变化。代码有同名符号和生成文件，法律文书有重复条款，agent轨迹有失效旧状态。selector在训练域学到的负样本边界不足，会把这些相似干扰排到前面。

无标签线上数据可监控分数熵、cutoff margin、候选距离和块访问集中度。它们偏离训练分布时，提示排序环境变化，却无法直接证明质量下降。抽取匿名化或授权样本跑dense teacher，才能测真实覆盖。困难负样本回流训练时，应保留旧域数据，避免修复新域后破坏原能力。

域适配可先只更新selector或小型适配器，主干保持固定。这样成本低、因果清晰；若selector已能选对而答案仍差，再考虑主干适配。把所有参数一起更新会让oracle同步漂移，难以判断收益来自检索还是模型知识。

**长度外推可以看成候选极值漂移。**

设无关块分数服从某个尾部分布。候选数从N增到cN，即使单块分布不变，最高无关分数也会提高。正例分数没有同步增长时，召回自然下降。这一现象解释了训练长度内margin充足、外推后突然拥挤的常见曲线。

训练可模拟更大候选池，无需每次运行完整超长主干。保存或在线生成大量困难负块表示，与真实query共同计算selector分数；主attention只对少量候选运行。这样的负池训练节省主干成本，但缺少长序列位置编码、主题演化与缓存状态，需要定期用真实长序列校验。

极值视角还提示margin应随候选数校准。固定 $\gamma$ 在N很小时足够，N增大后可能需要更强分离；盲目增大margin又会让表示范数膨胀。可使用归一化表示、温度与按长度分桶的排序目标，区分角度可分性和尺度增长。

**回退路径也应参与训练与验收。**

线上系统可能在低margin、高熵、容量溢出或摘要异常时扩大K，甚至切回dense。若训练从未模拟回退边界，模型在两种路径切换处可能出现输出跳变。可随机让部分样本采用扩大预算，加入不同预算间的输出一致性约束，同时保留更大预算带来的真实改进空间。

回退判据要测精确率和召回率：真正困难query有多少被识别，容易query有多少被误判而浪费计算。把“是否需要更大K”作为辅助标签，可由小K与大K的loss差生成。这个元选择器同样会随长度和领域漂移，需要保守阈值。

验收时同时给常规成本与含回退的期望成本：

$$
\mathbb E[C]=(1-r)C_{\mathrm{sparse}}+rC_{\mathrm{fallback}}, \tag{30}
$$

r是回退率。若困难任务几乎全部回退，平均质量可接近dense，稀疏方法却没有兑现目标场景收益。按任务类型和长度报告r，才能看到selector的真实覆盖范围。

### 5.3. 把一个训练batch从教师信号推到参数更新

**一次完整更新需要保留哪些量。**

设batch中第n条序列长度为 $L_n$，块长为S，第l层第h个query为 $q_{nlhi}$。稠密教师产生分数 $z_{nlhij}$、概率 $p_{nlhij}$ 与输出 $o_{nlhi}$。部署按块选择，因此先把token概率聚合为

$$
P_{nlhib}=\sum_{j\in B_b}p_{nlhij},
\qquad b=1,\ldots,\left\lceil L_n/S\right\rceil. \tag{31}
$$

若GQA组共享候选，再按组内head聚合。聚合前保留逐head质量，便于计算最差head覆盖；聚合后标签才对应实际读取集合。padding块、因果边界之外的块和当前未完成块中的无效token均应掩掉。只要这一层标签粒度与部署不一致，后面的loss再精细也在优化另一张邻接图。

selector用低维映射产生query索引 $\bar q$ 与块索引 $\bar k_b$，分数为

$$
r_{nlhib}=\frac{\bar q_{nlhi}^{\top}\bar k_{nlhb}}
{\sqrt{d_s}}+a_{nlhib}, \tag{32}
$$

$a$可包含位置先验、局部mask与合法性约束。训练需要同时生成soft概率、hard候选和部署量化候选。soft概率供KL或代理梯度使用；hard候选驱动稀疏主干；量化候选只作旁路对照或直接用于量化感知前向。三者的集合交集、cutoff margin与teacher质量覆盖进入日志。

候选集合可拆为固定局部集合 $W_i$、保底集合A和动态集合D：

$$
S_i=W_i\cup A_i\cup
\operatorname{TopK}_{b\notin W_i\cup A_i}(r_{ib},K_d). \tag{33}
$$

动态预算必须扣除固定集合已经占用的物理块，并去重。若局部窗口与sink仍进入Top-K排序，同一页面可能重复占位，训练记录的K与实际独立读取数产生偏差。组内head共享时还要在这一刻完成并集或组级选择，不能等attention输出后才合并。

稀疏主干只加载S中的K/V，分别维护每个query head的softmax状态。得到 $o^{sp}$ 后，局部输出保持损失可写为

$$
\mathcal L_{hid}=
\frac{1}{N_q}\sum_i
\frac{\|o_i^{sp}-\operatorname{sg}(o_i^{de})\|_2^2}
{\|o_i^{de}\|_2^2+\epsilon}. \tag{34}
$$

教师输出使用stop-gradient，防止dense路径为了迎合稀疏学生而退化。若dense与sparse共享全部主干参数，同一batch运行两条路径会使显存翻倍，可只在抽样层或抽样query计算 $\mathcal L_{hid}$；其余样本依靠LM与路由蒸馏。

路由监督可由块质量交叉熵与边界排序组成：

$$
\mathcal L_{route}=
-\sum_b\widetilde P_b\log\hat P_b
+\mu\sum_{(b^+,b^-)\in\mathcal E}
[\gamma-r_{b^+}+r_{b^-}]_+, \tag{35}
$$

其中 $\widetilde P$ 是归一化teacher块质量，$\mathcal E$从teacher正例与cutoff附近困难负例构造。正例不必局限于teacher前K，可从累计质量达到 $\rho$ 的最小集合采样；这样teacher分布平坦时会提供更多正例，分布尖锐时监督集中在少数块。

任务侧运行语言模型交叉熵，并可加入dense—sparse logit蒸馏。总目标为

$$
\mathcal L=
\mathcal L_{LM}+\lambda_o\mathcal L_{out}
+\lambda_h\mathcal L_{hid}
+\lambda_r\mathcal L_{route}
+\lambda_c\mathcal L_{cost}. \tag{36}
$$

更新前分别计算各项对selector参数的梯度范数与余弦。预算项压倒路由项时，selector容易通过普遍降低gate逃避成本；路由项压倒LM时，模型会精确模仿teacher attention，却未必保持任务输出。权重可以按梯度尺度归一，但验证集上的质量—成本曲线才决定最终取值。

反向传播要确认hard候选之外的selector能否收到信号。纯hard前向若只有选中块参与主干，漏选正例无法从LM loss获得直接梯度；式(32)的教师监督负责把它拉回。使用straight-through时，LM梯度还会沿soft gate返回，需记录它与教师梯度是否同向。探索块被加入前向后，应标记其采样概率，避免高频抽样块在loss中获得不成比例的权重。

分布式训练中，sequence parallel设备各自拥有一段块。每卡先计算本地候选分数，再进行全局top-k归并。teacher标签也必须全局归一化，局部softmax概率无法直接相加。稳定做法是先归约全局最大logit，再归约指数和，随后生成块质量；只交换每卡局部top-k虽然节省通信，却可能漏掉大量中等分数共同构成的概率质量，尤其影响质量阈值标签。

参数更新之后，缓存索引的版本随之变化。普通独立batch会在下次前向重算全部索引；跨step保留长序列状态时，需要冻结索引投影、重算活跃缓存或使用带版本的EMA投影。版本策略属于训练算法的一部分，因为同一query同时面对新旧尺度key会改变排序分布。checkpoint除模型与优化器外，还应保存预算乘子、温度、课程阶段、量化尺度与随机路由状态。

一次batch结束后的最小统计包括：LM与各辅助loss、各自梯度范数、teacher质量覆盖、证据联合召回、每层K分布、cutoff margin、浮点—量化候选交集、head最差覆盖、跨设备负载和dense—sparse输出差。性能统计还需给teacher额外开销、selector扫描、稀疏前反向和通信时间。缺少其中任何一组，训练变差时都可能只看见总loss或step time，而找不到原因。

周期性验证要冻结参数并运行真正的部署路径，禁用训练探索和soft旁路，启用相同的量化、确定排序、页表与K档。验证同时跑dense参考与若干oracle：若部署候选差于训练hard候选，检查数值和索引实现；训练候选差于同预算oracle，检查表示与优化；oracle也无法维持质量，则扩大预算或减小块粒度。这个判定顺序把实现、学习和结构上限分开，避免靠继续训练处理一个根本不可行的预算。

自由生成轨迹也需要复测。教师强制batch固定了query序列，适合比较数值和集合；自由生成中一次漏选可能改变token，后续query与缓存随之分叉。应记录首次分叉位置、分叉前的候选margin与证据覆盖，以及分叉后是否触发回退。若教师强制误差很小而自由生成频繁失稳，训练需要增加学生轨迹或路由扰动，单纯提高静态recall未必能解决闭环敏感性。

损失归一化也会悄悄改变样本权重。若对所有query直接求平均，长序列贡献更多query，训练会自然偏向长样本；若先在序列内平均再对batch平均，每条序列权重相同，短序列中的单个困难query影响更大。路由loss还可只在需要远程证据的query上计算，局部query作为容易负例抽样加入。选择哪种归一化应与目标流量分布一致，并在日志中给出各长度桶的有效权重。

块级teacher质量存在大量接近零的长尾。完整KL会让海量尾部项合计出可观梯度，selector可能花容量拟合无关细差。可将teacher前m块保留精确概率，其余质量合并成一个tail桶；学生的尾部总概率与该桶对齐，尾部内部不再逐块拟合。m应覆盖部署K与足够的边界负例，过小会隐藏真正竞争者，过大又回到稠密监督成本。

困难负样本挖掘应避免使用当前学生分数的单一快照。若每步只挑学生最高误报，数据会围绕少数异常块振荡；维护短期队列，混合当前边界、历史误报和teacher相似块，能提供更稳定的负池。队列中的块索引若由可训练投影产生，参数更新后表示会陈旧，需存原始特征重算或限制队列寿命。

梯度累积下的预算统计也有区别。拉格朗日乘子若按micro-batch更新，会追逐每个小批的长度波动；在完整global batch聚合平均成本后更新更稳定。各数据并行设备需归约真实候选成本，否则某卡以短序列为主、另一卡以长序列为主时，本地乘子会朝不同方向漂移。乘子属于全局训练状态，应与模型checkpoint同步恢复。

混合精度的loss scaling可能让小型路由loss下溢。主LM loss数值正常时，selector梯度仍可能在FP16累积中消失，表现为辅助loss缓慢下降、分数几乎不动。应单独检查selector梯度非零比例与更新范数，必要时让路由loss在FP32归约、使用独立scale或BF16。只提高 $\lambda_r$ 会同时改变多目标权衡，未必是正确修复。

当模型采用activation checkpointing时，hard候选索引最好作为轻量状态保存。重新计算selector若包含随机探索、Gumbel噪声或不确定并列排序，重算集合可能与前向不同，backward便沿另一张图传播。保存索引的开销通常远小于保存完整attention矩阵；若坚持重算，必须恢复随机种子、量化尺度和确定排序环境。

这些细节最终都落在同一个原则上：训练中被优化的稀疏图，应当与部署时真正执行的稀疏图一致。教师负责告诉模型哪些连接有价值，离散优化负责让价值穿过选择边界，预算目标负责给计算定价，主干损失负责检验这些连接能否完成预测。四者若在粒度、因果信息或数值实现上错开，总loss依然可能下降，部署质量却没有可靠含义。

选择器的更新还应接受“零收益检查”。在固定候选集合下冻结selector，只训练主干；再冻结主干，只训练selector，并与联合更新比较。如果主干单独训练已经获得几乎全部收益，路由监督可能只在追随模型适应；如果selector单独训练提高teacher覆盖却不改善LM，标签与任务目标之间存在断层；联合更新显著超过两条单独路径，才说明两者的协同适应真正有效。这个三路对照无需贯穿完整预训练，可在代表性阶段运行短窗口，并使用相同token、学习率积分和预算，避免训练量差异制造假结论。

模型规模变化后也要重新做这项检查。更强主干可能靠残差和多层冗余容忍漏选，使同一selector recall对应更小质量损失；更宽head或不同GQA比例又会改变索引表示与共享冲突。把小模型上调好的 $\lambda$、K和块长原样搬到大模型，缺乏稳定的尺度依据。迁移时先复算oracle上限、层敏感度和成本交叉点，再决定哪些超参数可以继承。

同一配置还应在多个随机种子上重复，特别关注低召回尾部与训练切换点。选择边界具有离散性，单次运行的平均质量稳定，并不足以证明困难样本和预算分布同样稳定。
