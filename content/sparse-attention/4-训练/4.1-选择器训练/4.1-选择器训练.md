# 选择器训练

动态稀疏 attention 有两个模型叠在一起：主 attention 负责聚合信息，选择器负责决定主 attention 能看到哪些历史位置。主干只要收到正确候选，就能照常计算 QK、softmax 与加权求和；真正麻烦的是候选集合由一次离散排序产生。漏掉关键 token 后，它既不贡献输出，也没有主任务梯度告诉选择器「刚才漏了谁」。因此，选择器训练先是一项检索学习任务，再才是稀疏算子的参数优化。

这条路线可以从三个问题进入。教师怎样定义重要位置，决定训练信号是否贴近最终 attention；top-k 怎样进入前向与反向，决定未选候选能否获得梯度；候选预算怎样固定，决定训练出来的分数能否直接落进部署 kernel。三项中任何一项含糊，离线 loss 都可能很好看，部署时却出现召回下降或成本失控。

## 1. 从稠密 attention 取得监督

### 1.1. oracle 不只是一组最大分数

设稠密教师在 query $i$ 上的 attention 概率为 $p_{ij}$，选择器分数为 $r_{ij}$。最直接的标签是教师 top-$m$ 集合 $G_i$，训练学生把集合内位置排到前面。但教师分布可能很尖，也可能摊在许多近似位置上。只比较集合交集会把「漏掉 0.4 概率的唯一证据」与「漏掉 0.001 概率的重复标点」算成同一次错误。

更稳妥的做法是同时保存两种信号：离散集合用于检验排序，概率质量用于衡量漏选的实际影响。候选集 $S_i$ 的质量覆盖为

$$
M_i=\sum_{j\in S_i}p_{ij}.
$$

两个选择器都达到 recall@$k=90\%$ 时，$M_i=0.99$ 的那个通常更接近教师输出。训练标签还要保留因果 mask、padding 与 GQA 分组规则，否则教师允许的边与部署路径并不相同。

### 1.2. 标签生成也有成本

用完整 attention 产生 oracle，需要在训练阶段计算本来想省掉的稠密矩阵。DSA 的继续训练因此先做稠密预热，让 indexer 对齐主 attention，再切换到稀疏路径；这能利用已有 checkpoint，但总训练计算仍要包含稠密预热。NSA 从头训练压缩、选择与滑窗三条分支，压缩 attention 同时提供全局输出和块重要性，无需为每一步另跑完整 token 级教师。

MoBA 把序列划成块，以 query 与块表示的匹配分数选择若干块。块内仍执行正常 attention，训练标签也自然落到块级。一个关键 token 会让整块成为正例，块内其他 token 随之被读入；这种标签与 token 级 oracle 的含义不同，不能只用相同的 top-k 数字比较。

## 2. 离散选择怎样学习

### 2.2. hard top-k 切断了集合外梯度

令 $S_i=\operatorname{TopK}(r_i,k)$，稀疏输出只依赖 $j\in S_i$。排序边界在分数发生交换时跳变，常规反向传播无法给未选位置连续梯度。训练初期若选择器碰巧偏爱局部块，远程证据长期进不了主 attention，主干还可能学会绕开远程信息，形成自我强化。

常见解法各自承担不同代价。soft routing 对所有候选使用温度 softmax，梯度完整但训练计算仍稠密；straight-through estimator 前向用 hard mask，反向把 mask 当作连续概率，部署形状一致而梯度带偏；教师损失绕开主任务路径，直接要求 $r_{ij}$ 复现 oracle 排序；候选过采样则在训练时取大于部署预算的集合，为边界附近样本保留探索机会。

**可微分数不等于可微执行。**

NSA 的压缩分支可以连续训练，压缩 attention 权重还能给 selection 分支排序；top-k 选块本身依然离散。主任务梯度能通过压缩输出和门控回到压缩器，却不等于 selection 的集合边界获得了精确梯度。MoBA 的 gate 分数同样可微，真正送入块 attention 的 hard top-k 仍只保留被选 experts。

因此要画清两张图：一张是数值图，标出哪些张量参与输出；另一张是梯度图，标出 stop-gradient、代理梯度与辅助损失。只说「端到端可训练」无法回答漏选块靠什么被纠正。

### 2.1. 预算属于训练目标

**固定 k 与概率阈值。**

部署 kernel 往往要求每行固定 $k$，这样工作量和显存上界清楚。训练若使用不受限的 soft gate，模型会倾向多开候选以降低语言模型损失。可加入预算惩罚

$$
\mathcal L_{\mathrm{budget}}=\left(\frac{1}{N}\sum_i\sum_j g_{ij}-k\right)^2,
$$

其中 $g_{ij}$ 是连续门值。它约束平均预算，却容许个别 query 远超上限；真正的定长 kernel 仍会截断这些行。若部署按 top-$k$，训练评测也必须在同一 $k$ 下报告结果。

top-$p$ 按累计概率决定候选数，能给分散 query 更多位置，却让 batch 内行长不齐。工程上可以设置 $k_{\min}$ 与 $k_{\max}$，再把 ragged 候选分桶。此时模型质量、平均预算和尾部预算要同时报告。

**负载均衡不能替代相关性。**

当块分布到不同设备时，热点块会形成通信与等待。均衡损失可以限制一批 query 对各块的访问次数，但共享系统提示或长文主题本就会产生语义热点。把利用率强行拉平，可能让选择器为了均衡而读错块。相关性损失控制「该读谁」，负载损失控制「设备能否承受」，两条曲线应分开观察。

## 3. 训练与推理必须使用同一问题

### 3.2. 粒度、共享与精度

训练按 token 选择、部署改成 page 读取，会把一个命中扩成整页；训练按 head 独立 top-k、部署让 GQA 组共享候选，会把多个排序合并；训练以 BF16 排序、部署以 FP8 indexer 分数排序，会在边界附近翻转名次。这些改动都改变了选择问题，而不只是 kernel 优化。

验收时应把部署实现产生的索引回放到训练张量上，比较候选交集、概率质量覆盖与最终输出。若索引差异集中在低概率位置，任务指标可能稳定；若唯一远程证据恰在 cutoff 附近，极少的翻转也会造成明显错误。

**长度外推改变负样本难度。**

训练长度为 32K、部署长度为 1M 时，固定 $k$ 的保留比例缩小 32 倍。新增历史并非无害填充，其中会出现大量语义相似的困难负样本。选择器在短序列上学会粗糙主题匹配，到了长序列可能把正确段落淹没在重复章节中。

长度课程需要同时控制证据距离、重复干扰数量和候选预算。只把位置编码拉长，无法验证检索器是否能在更大的候选池中保持排序。合成 passkey 可检验单点召回，多证据问答、长代码变量追踪和重复模板文档更适合暴露困难负样本。

### 3.1. 一条可执行的训练路径

**分阶段而不是一步裁剪。**

已有稠密 checkpoint 可以先冻结主干，用稠密 attention 产生教师分布，训练轻量 selector；随后打开稀疏主 attention，以较大候选预算联合训练；再把预算退火到部署值，并启用完全一致的量化、分组与 block 规则。每次切换都记录语言模型 loss、教师质量覆盖、索引边界 margin 和真实读字节。

从零预训练的结构可让稀疏路径从第一步参与优化，但仍要避免早期路由坍缩。局部窗口、全局压缩或周期性 full layer 能提供确定的信息通道；温度和预算则逐步收紧。保护通道不能在部署时悄悄删除，否则训练稳定性来自一条线上不存在的路径。

## 4. 选择器的标注与校准

稠密 attention 给出的 top-$k$ 是最常见标签，但边界会随主干参数、层和 head 变化。对 query $i$，教师 logits 排序为 $s_{i(1)}\ge\cdots\ge s_{i(n)}$，边界间隔

$$
\Delta_i=s_{i(k)}-s_{i(k+1)}
$$

刻画标签稳定性。$\Delta_i$ 很小时，微小数值扰动就会交换第 $k$ 与第 $k+1$ 名；把这类样本当成硬二分类，会惩罚功能上几乎等价的排序。可用教师概率或 pairwise margin 加权，让大间隔错误承担更高损失。

top-$k$ 也不一定是最符合最终输出的标签。两个高权重 key 若 value 几乎相同，漏掉一个可以由另一个补偿；较低权重但 value 独特的位置可能更重要。输出蒸馏以

$$
\mathcal L_{out}=\|o_i^{dense}-o_i^{sparse}\|_2^2
$$

提供功能监督，却允许不同候选误差互相抵消。训练可同时使用排序、概率质量和输出损失，三项分别约束候选身份、被覆盖权重与最终聚合。

### 4.1. 困难负样本来自排序边界

随机抽取远处 token 多半是容易负样本，选择器只需粗略主题判断便能分开。更有效的负样本包括教师第 $k+1$ 到 $k+r$ 名、与正例同实体但数值不同的段落、重复代码模板以及相邻块内的错误版本。它们迫使低维索引保留精细差异。

困难负样本挖掘要防止偏向当前选择器。只收集这一版模型误召回的块，下一版可能遗忘其他负例；可混合随机、教师边界和历史误例，并保留各自采样权重。长序列增加后，负例总数增长，训练 batch 内的负样本数量也应明确，否则短长度实验与长长度实验优化的是不同排序难度。

### 4.2. 召回概率需要校准

若选择器输出分数只用于固定 top-$k$，分数尺度并不影响集合；若部署采用阈值或自适应预算，分数必须能反映不确定性。可以在验证集上按预测置信度分桶，对比每桶的教师质量覆盖。高置信桶仍频繁漏选，说明阈值无法可靠控制风险。

长度变化会破坏校准。候选数从 512 增到 16384 时，即使单个负例分布不变，最大负分数也会上升。阈值应显式依赖候选池大小，或在训练中覆盖目标长度。固定阈值在短序列上召回充分，到长序列可能被极值统计击穿。

## 5. 探索与路由坍缩

hard top-$k$ 只给入选项主任务梯度，初始偶然高分的块更容易继续获得训练，形成正反馈。向路由 logits 加噪声、扩大训练候选或保留少量随机块，可以让未入选区域得到探索机会。探索比例过高会增加训练成本并扰动主干，通常需要随训练退火。

负载均衡损失也可能掩盖坍缩。选择均匀不等于语义多样；路由器可以按位置轮流选择无关块，得到完美负载却没有召回。坍缩检测至少同时观察块使用分布、教师概率质量、query 间候选互信息和主任务 loss。若使用局部窗口兜底，还要单独测远距分支，否则主任务短期稳定会遮住远距路由失效。

### 5.2. 预算退火的两种顺序

第一种先固定长度，逐步把 $k$ 从大预算收紧到部署值，再增加长度；它能先让模型适应删边。第二种先在较大保留比例下增加长度，再固定绝对 $k$；它能让路由器先见到长距离和困难负样本。两条路径到达相同 $(n,k)$，优化轨迹可能不同。

应保存中间 checkpoint 做交叉评测：同一权重在多组 $(n,k)$ 下计算质量曲线。如果模型只在训练轨迹附近稳定，说明它学到特定预算课程；若邻近预算也平滑，部署才有调整吞吐的空间。突然收紧预算导致 loss 跳升时，先扩大候选恢复，再降低学习率继续退火，通常比维持小预算硬训更容易区分暂时冲击与不可恢复容量不足。

### 5.1. 反事实干预检验选择器

高召回只说明选择器复制教师排名。为了验证候选确实影响任务，可以对同一输入构造三种集合：真实路由集合、包含已知证据的 oracle 集合、与真实集合大小相同但替换关键证据的干预集合。若 oracle 没有改善，问题在后续 attention 或推理；若替换证据也不降低结果，当前任务可能没有真正使用长上下文。

对训练样本还可以交换两个相似块中的关键数值，观察选择器是否随 query 改选。只根据主题或位置的索引器会保持原集合，能辨别具体约束的索引器应跟随内容变化。此类成对样本比随机 NIAH 更难利用表面词汇捷径。

跨层共享选择时，干预可定位共享跨度。先只在组首强制 oracle，再在组中某层重新索引，比较组尾输出。若中途重索引明显恢复，说明组首候选随表示变化而陈旧；若没有恢复，误差可能来自有限预算或更早的信息压缩。

## 6. 监督样本怎样加权

一段长序列包含大量局部、低熵 query，真正依赖远距证据的 query 占比可能很小。若对所有位置平均路由损失，选择器只要做好局部高频模式就能得到很低的均值。可按教师远距概率质量

$$
w_i=\sum_{j:i-j>w}p_{ij}
$$

为 query 加权，$w$ 是局部窗口。$w_i$ 高的位置更依赖窗口外信息，训练时获得更大权重。还可按教师熵、边界间隔和证据稀有度分层采样，保证 batch 中持续出现困难路由。

加权不能完全丢掉普通 query。局部位置仍用于校准索引器的基础相似性，且某些任务通过多层局部传播完成。较稳妥的采样器混合均匀样本、远距高质量样本和历史误例，并报告三类上的独立召回。训练集若只保留教师远距尖峰，选择器可能在一般语言建模中产生过多随机远边。

### 6.2. Head 的样本量不应被平均吞掉

不同 head 的教师分布和可稀疏性不同。把所有 head 的损失先平均，会让大量容易 head 主导更新。可以为每个 head 维护概率质量覆盖的滑动统计，对低覆盖 head 提高采样或损失权重；若某些 head 始终接近均匀，固定小 $k$ 本身就无法覆盖，应增加预算或回退稠密，而非无限提高损失权重。

共享索引器时，head ID 或组表示可以作为条件输入，使同一低维空间保留不同关系。完全独立索引器表达力更高，却增加参数、索引状态和训练样本需求。消融应在相同物理 KV 读取预算下比较，不能让独立 head 的候选并集无意中获得更多页。

监督权重、候选预算和物理读取量应随 checkpoint 一同保存。缺少其中任何一项，都无法复现选择器实际优化过的风险分布。

### 6.1. 路线入口

[监督与联合训练](./4.1.1-监督与联合训练.md)给出 oracle 构造、KL 与排序损失、straight-through、预算手算和完整验收表，并对照 DSA、NSA 与 MoBA。KDA 采用递归状态更新，训练问题集中在有限状态记忆和混合层配比，不经过相同的 hard top-k 候选流程；它适合作为边界参照，不应套用选择器召回指标。

判断一次训练是否真正成功，可以看四组量：主任务质量有没有恢复，oracle 概率质量有没有覆盖，部署预算有没有严格兑现，训练长度之外是否仍能召回证据。四项缺一，低 loss 或高吞吐都不足以证明选择器已经学会工作。
