# 稀疏长上下文微调: 训练图可以和推理图不同吗

把模型的上下文从4K扩到32K或100K, attention训练成本会随长度平方增长. 序列扩大8倍, 单层QK与AV配对约扩大64倍; activation、反向状态和通信也随之上涨. 参数高效微调能减少优化器状态, 却不会自动缩小attention矩阵. 因而长上下文适配还有另一项问题: 能否在训练时只计算一部分连接, 学完以后仍用原模型的full attention推理.

这条路线与[选择器训练](../4.1-选择器训练/4.1-选择器训练.md)处理的对象不同. 选择器训练要得到一套部署时真正执行的动态候选, 训练与推理应尽量一致. 稀疏长上下文微调把稀疏结构当作训练近似, 主要目标是降低适配成本; 推理可以恢复full attention. 两者都减少训练配对, 前者学习路由, 后者利用固定拓扑传递梯度.

## 1. 长上下文适配的三笔成本

### 1.2. Attention计算

序列长度为 $N$, head维度为 $D$ 时, 每个head的QK与AV主体为 $O(N^2D)$. FlashAttention避免物化 $N\times N$ 概率矩阵, 仍要执行这些乘加. 把序列切成长度 $G$ 的组, 只在组内attention, 主体降为 $O(NGD)$. 当 $G=N/4$ 时, 配对数约为full attention的四分之一.

**参数与优化器状态。**

LoRA冻结主干矩阵, 只训练低秩增量, 显著减少梯度和优化器状态. 但上下文扩展还涉及位置范围、输入表示与各层数值尺度. 只在Q/V投影挂LoRA, embedding与normalization完全冻结, 可能不足以适应新的长度分布. LongLoRA的重要经验就是让embedding与normalization参与训练.

**数据与通信。**

长样本容易被padding浪费, packing又会引入样本边界mask. 多卡训练若按序列切分, 局部attention可以减少跨设备通信; 若每组跨rank, 则必须交换Q/K/V或重新排列token. 稀疏模式的理论边数只有真正映射到FlashAttention支持的连续组时, 才会变成训练吞吐.

### 1.1. 固定稀疏拓扑如何传递远距信息

**不平移的局部分组。**

最简单的分组把序列切成 $[0,G),[G,2G),\ldots$. 每个token只能访问所在组内的历史. 组边界永久隔开相邻内容: 位置 $G-1$ 与 $G$距离只有1, 却不在同一attention图中. 多层堆叠也无法跨越边界, 因为每层使用相同分组.

**平移半数heads。**

LongLoRA的S²-Attn把heads分成两半. 第一半使用原分组, 第二半沿序列平移半个组再分组. 原边界附近的token在平移heads中进入同组, 信息可以穿过固定边界. 下一层重复后, 感受范围沿深度扩展.

**训练稀疏、推理稠密。**

S²-Attn只改变微调阶段的attention mask与张量重排, 模型参数形状不变. 推理时关闭分组和平移, 恢复标准full attention. 这样没有新增selector、索引cache或稀疏kernel依赖. 代价是训练和推理计算图不同, 必须用full attention评测最终checkpoint, 不能只验证训练mask下的loss.

## 2. LongLoRA这条路线

### 2.2. S²-Attn降低配对数

S²-Attn通过reshape把batch与组维合并, 每个组调用普通或FlashAttention. 平移heads在reshape前滚动半个组, attention后再移回. 这种实现不需要不规则稀疏索引, kernel看到的仍是连续定长序列.

**改进的LoRA参数范围。**

LongLoRA使用LoRA适配主干线性层, 同时训练embedding与normalization. 论文消融表明, 上下文扩展不能只照搬常规短任务LoRA配置. embedding要适应长序列输入分布, normalization的scale也会随更长依赖与位置范围调整.

**位置扩展与长数据。**

稀疏attention减少训练成本, 不负责单独解决位置编码外推. 长度扩展仍需相应的RoPE缩放或位置设置, 并使用足够长的训练文本. LongLoRA还发布LongAlpaca长指令数据, 用于让模型在长输入上执行指令, 而不只是在连续语料上降低困惑度.

### 2.1. 训练时必须核对的边界

**因果mask与padding。**

平移会把序列末端的一部分token卷到开头. 实现需要在reshape后维持因果关系并屏蔽padding, 不能让循环移位变成未来信息泄漏. 样本packing时还要叠加document mask, 防止同一组内不同样本互相attention.

**组大小与层数。**

组越小, 训练越省, 单层可见范围越窄. 平移只能连接相邻组, 远距信息需要多层传播. 若任务要求某一层直接比较远距离位置, 小组仍可能损失质量. 组大小、层数和训练长度应一起做消融.

**Full-attention回放。**

训练期间定期在相同batch上同时运行S²-Attn与full attention, 比较loss、输出差和梯度方向. 最终评测只用部署图. 若稀疏训练loss下降而full-attention评测不改善, 模型可能过度适应训练mask.

**分布式边界。**

序列按rank切分时, 原分组可以与设备边界对齐, 平移heads却需要相邻rank交换半组token. 若每张卡只在本地序列内平移, rank边界会重新成为永久断点, 得到的attention图与单卡实现不同. 通信实现要么交换边界halo, 要么先执行all-to-all重排; 性能报告需把这部分字节和等待时间计入.

Tensor Parallel按heads切分时, 每个rank应获得数量接近的原分组heads和平移heads. 把两类heads完全分到不同设备虽不改变输出定义, shift操作和mask处理会造成负载不对称. Context Parallel、Tensor Parallel与group size共同决定S²-Attn能否保持规则kernel.

## 3. 读法与验收

**从张量重排开始。**

先手算8个token、4个heads、组长4的分组和平移, 再看官方实现中的shift、reshape和inverse shift. 这一步能直接发现边界token、head拆分与causal mask怎样对应.

**再看参数和数据。**

随后核对LoRA挂载层、embedding与normalization是否训练, 位置编码采用何种扩展, 长样本如何packing. 任何一项变化都可能影响最终长度能力, 不能把结果全部归给S²-Attn.

**核算端到端成本。**

训练报告应列出attention FLOPs、step time、峰值显存、通信量和总训练token. 推理恢复full attention后, Decode KV与时延不会因S²-Attn自动降低. **这条路线节省的是长上下文适配成本, 不是部署时的稀疏推理成本.**

**故障从边界位置开始查。**

正确性测试可用8个token、4个heads、组长4. 显式列出每个query在两类heads中的可见位置, 再与张量shift实现逐项比较输出和Q/K/V梯度. 测试长度取1、3、4、5、7、8, 能覆盖空组、完整组和未满尾组. Packing场景再让两个文档边界分别落在组内和组边缘, 改变前一文档内容不应影响后一文档表示.

训练loss异常低时，检查roll是否让序列开头看到尾部。单卡正确、多卡质量下降时，核对平移所需的跨rank token是否完整交换。S²-Attn训练评测正常、恢复full attention后退化时，在同一batch上比较两种图的logits、attention熵与重要位置质量；full图新增大量组外keys后，softmax竞争可能稀释训练期间的组内高分。

**参数与数据消融。**

拓扑消融至少比较full attention、无平移局部分组和S²-Attn, 三组使用相同长度与训练token. 参数消融比较仅LoRA、LoRA加embedding、LoRA加normalization及完整组合. 位置方案保持固定, 才能区分S²-Attn、参数范围与RoPE扩展各自贡献.

数据按长度分桶报告样本和token比例. 最大长度达到100K不代表大部分优化step都见过100K关系. 连续长文本适合训练语言建模, 长指令数据检验从远距证据完成任务; 两类结果应分别呈现, 并同时检查短上下文能力是否保留.

恢复训练时还要保存当前训练长度、group ratio、位置设置和数据采样器状态. 其中任何一项回到初值, 模型都会突然面对另一张attention图或另一种长度分布.

### 3.1. S²-Attn 的层间传播

设序列按组长 $G$ 划分。普通分组注意力只允许第 $r$ 组 query 读取第 $r$ 组 key；shifted 分支把半数 head 的分组边界平移 $G/2$。第一层中，未平移 head 建立组内联系，平移 head 连接相邻组边缘。多层交替后，信息可逐步跨组传播。

若每层最多跨越半个组，经过 $L$ 层的结构可达距离约随 $LG/2$ 增长，而 full attention 一层即可直连任意历史位置。可达性仍弱于可靠传递：中间 token 必须在有限维状态中保存信息，残差与 MLP 还会混合其他内容。S²-Attn 降低微调显存的代价，是把远距直接边换成多跳路径。

这种图适合微调阶段的原因之一，是部署可恢复 full attention。模型在训练中学到的局部与跨组表示被放到更密的图上运行，通常不会缺边；新增边会改变 softmax 分母，原有高分可能被大量新 key 稀释。因此「恢复 full」仍需实测 logits 和任务质量，不能由集合包含关系直接推出等价。

### 3.2. Shift 的因果边界

对自回归模型，平移不能让 query 读取未来 token。实现常先在 head 维分组，再对一半 head 的序列张量滚动，执行分组 causal attention，末尾逆向滚动。若直接用环形 `roll` 而没有屏蔽首尾包裹，序列开头会看到末尾，形成训练泄漏。

合法 mask 应由原始位置决定。对平移后的 query 位置 $\pi(i)$ 与 key 位置 $\pi(j)$，仍需满足 $j\le i$，并且两者属于同一文档。仅检查平移坐标的大小不够，因为置换可能跨过序列首尾。最小测试让每个 token 值等于位置编号，显式列出可见集合，再与 kernel 输出比较。

packed sequence 更容易出错。两个文档在同一训练样本中相邻，shift 后可能落进同一计算组；必须同时应用文档 segment mask。改变前一文档内容而后一文档 logits 变化，说明边界泄漏。这个测试比只看 loss 更敏感，泄漏往往会让训练 loss 异常好看。

## 4. 微调参数范围为何影响长上下文

LongLoRA 不只更新低秩 attention 投影，还强调 embedding 与 normalization 等参数的训练。长上下文扩展同时改变位置相位、激活分布和 attention 竞争。仅用 LoRA 调整少量线性层，可能难以校准所有层的尺度；开放 normalization 能改变残差支路的相对幅度，开放 embedding 能适应新的位置与数据分布。

参数消融要在相同 token 和优化步下比较。开放更多参数会增加优化容量，也增加通信与优化器状态；若训练 loss 更低，不能直接归因于 Sparse Attention。可分别报告短上下文、训练长度和外推长度指标，检查扩展是否以牺牲短程能力为代价。

LoRA 的秩也与层敏感性有关。统一 rank 方便配置，却未必适合所有层；对长距检索敏感的层可能需要更高秩。可用 full 与 S² 输出差、梯度范数或单层替换实验寻找敏感层，再分配参数预算。该策略的目标是让有限可训练参数修复拓扑变化最大的部位，而非平均增加所有层容量。

### 4.1. RoPE 扩展与稀疏拓扑要拆开

训练长度增长通常伴随 RoPE scaling 或位置插值。位置方案决定不同距离的 QK 相位，S²-Attn 决定哪些位置对参与计算。二者同时改变时，长程提升无法归因。至少需要四组对照：原位置加 full、扩展位置加 full、扩展位置加分组、扩展位置加 S²。

稀疏训练看不到大量远距直接边，可能降低对极端相对位置的梯度覆盖；恢复 full 后，这些边第一次参与竞争。位置外推若在这些距离上产生异常高 logits，会显著改变 softmax。可按相对距离统计 logits 均值、方差和最大值，比较 S² 训练与 full 训练的差异。

训练样本长度也要分布化。所有样本都填满最大长度会减少短样本比例并改变每个优化 step 的文档组成；只用少量最大长度样本又可能让远距关系梯度太少。按 token 而非样本报告长度桶，才能知道模型实际看过多少长距离配对。

## 5. 训练节省如何估算

full causal attention 的合法边约为 $n(n+1)/2$。分组长度为 $G$，忽略尾组时，每组 causal 边约为 $G(G+1)/2$，共有 $n/G$ 组，总边数约为

$$
E_{group}\approx\frac{n(G+1)}{2}=O(nG).
$$

shift 改变边的位置，不改变同阶边数。逻辑边比约为 $(G+1)/(n+1)$。若 $n=65536,G=2048$，比例约 3.13%。这只是 attention 矩阵部分；QKV 投影、MLP、通信和优化器不随边数同比下降。

训练显存还含激活、梯度和参数状态。FlashAttention 已经避免保存完整 $n^2$ 概率矩阵，所以 S²-Attn 相比朴素 attention 的显存比例，不能直接按边数推导。应分别测峰值显存、每 step 时间和可容纳 microbatch，再计算固定 token 数下的总时间。若节省显存只被用来增大 batch，吞吐提升与单 step 加速要分开报告。

**相同 token 预算下比较。**

不同长度的 batch size 往往不同。令一次优化更新处理 token 数为 $N_{tok}$，梯度累积步数为 $a$，microbatch 为 $B$，序列长度为 $n$，则 $N_{tok}=aBn$。比较 full 与 S² 时固定 $N_{tok}$ 和全局 batch 语义，避免某方案因看到更多 token 而质量更高。

吞吐用有效训练 token/s 表示，并把 padding 和跨文档边界排除。若 S² 允许更长样本但平均有效 token 比例下降，标称序列长度会高估数据利用。最终还要比较达到相同验证 loss 所需 token 数；单 step 变快但收敛变慢，整体节省会缩小。

### 5.1. 训练图与部署图的配对实验

可在同一 checkpoint 上运行四种图：训练时 S²、无 shift 分组、full causal 与部署 kernel 的 full attention。S² 对比无 shift 衡量跨组连接，S² 对比数学 full 衡量图近似，数学 full 对比部署 full 检查实现一致性。每组都记录 logits KL、困惑度与长程任务。

若 S² 训练图表现正常、full 图下降，检查新增边是否产生异常高分；若数学 full 正常而部署 full 异常，问题落在 mask、RoPE offset 或 packed layout；若无 shift 已接近 S²，训练数据可能没有提供跨组依赖。这样的配对把拓扑、训练和 kernel 三类问题分开。

### 5.2. 哪些依赖不适合 S² 近似

若答案依赖一个距离很远、只出现一次且无法由中间 token 概括的精确字符串，多跳传播要求每一层都保留这份细节。层数不足或中间表示容量有限时，结构上可达也可能无法恢复原值。长代码中的变量定义、文档开头的随机标识和跨章节数值约束都属于高风险样本。

相反，主题、文体和多次重复的事实更容易沿局部与 shifted 边传播。训练数据若以重复语义为主，会高估 S² 对精确远距引用的适应。评测要同时放入可摘要信息与不可压缩字符串，并让两类证据跨越相同组数。

组边界还会制造位置差异。位于两个组交界附近的 token 可以较快进入 shifted 邻组，位于组中央的 token 要经过不同 head 和更多层。把同一证据在组内平移，保持绝对距离不变，可以测出边界敏感性。准确率若呈周期性波动，模型显然受分组拓扑影响，没有形成平滑的距离响应。

**用图距离预测难例。**

对给定层表，可以计算证据到 query 的最短跨层路径长度 $d_G(j,i)$。按 $d_G$ 分桶后，若质量随图距离下降，拓扑是主要限制；若同一图距离内部差异仍大，再检查内容干扰和位置编码。full attention 的合法历史边图距离为一，可作为参照。

S² 的路径还带 head 类型。某些路径必须在 shifted head 与普通 head 之间通过输出投影交换信息，单纯的节点可达矩阵会低估限制。更细的图把「位置—head」作为节点，输出投影提供同层 head 混合边。虽然图更大，却能解释为什么相同位置路径在不同 head 配置下质量不同。
