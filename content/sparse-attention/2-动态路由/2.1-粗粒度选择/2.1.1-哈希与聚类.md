# 哈希与聚类: 用内容建立稀疏注意力邻域

长序列注意力的难点可以写成一个近邻搜索问题. 对查询 $q_i\in\mathbb{R}^{d_h}$, 稠密注意力读取全部 $k_j\in\mathbb{R}^{d_h}$, 计算 $q_i^\top k_j$, 再由 softmax 决定哪些位置真正获得权重. 如果只有少数点积进入 softmax 后仍然重要, 一条自然路线是先找近邻, 再只对近邻执行精确注意力. 哈希和聚类都在生成这个候选集合: 哈希把向量映射为离散码, 聚类把向量分配给中心, 同码或同中心的 token 才互相计算.

[Reformer](https://arxiv.org/abs/2001.04451) 使用局部敏感哈希(Locality-Sensitive Hashing, LSH)近似角度相似性, 将相近向量以较高概率送进同一桶. [Routing Transformer](https://arxiv.org/abs/2003.05997) 则使用在线 k-means, 让 query 和 key 按与聚类中心的距离进入内容簇. 两者都把注意力图从完整的 $n\times n$ 矩阵改成若干小子矩阵, 但索引的性质不同: LSH 的桶由随机旋转和排序得到, k-means 的簇中心从数据中学习. **桶只负责候选召回, 桶内的 QK 点积、causal mask、softmax 和 Value 聚合仍然是精确注意力.**

## 1. 从全量点积到内容桶

### 1.1. 输入、输出与邻接集合

设 batch 为 $B$, 注意力头数为 $H$, 序列长度为 $n$, 单头维度为 $d_h$. 投影后的张量为 $Q,K,V\in\mathbb{R}^{B\times H\times n\times d_h}$. 为简化记号, 先固定一个样本和一个 head, 写成 $Q,K,V\in\mathbb{R}^{n\times d_h}$. 路由器接收 $Q$ 与 $K$, 输出每个查询的候选索引 $I\in\mathbb{N}^{n\times m}$; $m$ 是每个查询最多读取的 key 数. 第 $i$ 行 $I_i$ 定义邻接集合 $\mathcal N(i)$. 稀疏注意力只在 $j\in\mathcal N(i)$ 上计算:

$$
s_{ij}=\frac{q_i^\top k_j}{\sqrt{d_h}},\qquad
\alpha_{ij}=\frac{\exp(s_{ij})}{\sum_{t\in\mathcal N(i)}\exp(s_{it})},\qquad
o_i=\sum_{j\in\mathcal N(i)}\alpha_{ij}v_j. \tag{1}
$$

输出 $O\in\mathbb{R}^{n\times d_v}$ 与稠密 attention 的 shape 相同, 所以后续输出投影与残差路径无需改变. 变化发生在 softmax 的定义域. 一旦关键位置 $j^*$ 没进入 $\mathcal N(i)$, 式 (1) 的分母和加权和都看不见 $j^*$. 增大桶、使用多轮哈希或同时保留局部窗口, 都是在降低这种漏选概率. 候选集合还必须服从任务掩码. 自回归模型要求 $j\le i$; padding 位置不得参与; 某些实现还禁止 query 与自身比较. 因此完整集合应写成:

$$
\mathcal N(i)=\mathcal B(i)\cap\mathcal C(i)\cap\mathcal P(i), \tag{2}
$$

其中 $\mathcal B(i)$ 是内容路由给出的桶, $\mathcal C(i)$ 是 causal 可见集合, $\mathcal P(i)$ 是有效 token 集合. 先分桶再加 causal mask 不会自动保持固定候选数: 排序后的一个桶可能大半来自未来位置. kernel 若按固定块分配空间, 需要把被屏蔽槽位保留为 padding, 或额外读取相邻桶补足历史候选.

### 1.2. 路由成本决定复杂度是否成立

若每个桶含 $m$ 个 token, 桶内 QK 与 AV 的计算约为 $O(nmd_h)$. 这个表达式没有包含建桶. 假如为了决定候选而先计算 $QK^\top$, 路由阶段已经支付 $O(n^2d_h)$, 后续稀疏化只减少 softmax 和 AV. 哈希的目的正是用 $O(nd_hR)$ 左右的随机投影与 $O(n\log n)$ 排序替代全量点积; 聚类则用 $O(nCd_h)$ 的中心打分替代 $n^2$ 配对, $C$ 是中心数. 以等大桶近似, $C=n/m$. 聚类打分和桶内 attention 合计为:

$$
T(m)\approx O\left(\frac{n^2d_h}{m}+nmd_h\right). \tag{3}
$$

式 (3) 第一项来自每个 token 与 $C=n/m$ 个中心比较, 第二项来自桶内配对. 令两项同阶可得 $m\approx\sqrt n$, 因而总量为 $O(n^{3/2}d_h)$. Routing Transformer 报告的 $O(n^{1.5}d)$ 口径就来自这项平衡. 它低于平方, 却不是线性; 中心数太少会形成大桶, 中心数太多又让路由打分变贵. **稀疏率只描述式 (1) 保留多少边, 无法单独预测端到端速度.** 排序、分桶、前缀和、索引重排、gather/scatter 与不均衡 padding 都会占时间. 小序列上, 一次规则的稠密矩阵乘通常比多次不规则 kernel 更快. 长序列上也要确认实现没有先生成稠密 mask, 再调用普通 attention.

## 2. Reformer 的局部敏感哈希

### 2.1. 随机旋转怎样产生桶号

Reformer 的出发点是点积注意力与角度近邻之间的关系. 当 query 和 key 共享投影并做长度归一化时, 较大的内积对应较小的角度. 对向量 $x\in\mathbb{R}^{d_h}$, 取随机矩阵 $R\in\mathbb{R}^{d_h\times b/2}$, 计算旋转投影 $u=xR\in\mathbb{R}^{b/2}$. 再把正负方向拼接:

$$
z=[u,-u]\in\mathbb{R}^{b},\qquad h(x)=\arg\max_{r\in\{1,\ldots,b\}}z_r. \tag{4}
$$

$b$ 是哈希桶方向数. 式 (4) 把球面划成 $b$ 个区域. 两个方向接近的向量更可能在同一随机旋转下取得相同最大坐标, 但结果不是确定的最近邻保证. 随机矩阵不同, 分区边界也不同. 因此 Reformer 使用多轮哈希: 第 $r$ 轮得到桶号 $h_r(x)$, 一个 query 可从任意一轮同桶 token 中获得候选. 原始 Reformer 的 self-attention 令 $Q=K$, 避免 query 与 key 采用不同表示后难以用一个哈希排序对齐. 这项约束会改变标准 Transformer 的参数化. 哈希不是可插拔的通用 ANN 服务: 它利用了共享 QK 和角度相似性. 如果模型仍分别学习 $W_Q$ 与 $W_K$, 应先证明哈希空间保持原 QK 排序, 或专门训练一个路由投影.

形状上, 一轮哈希的输入为 $X\in\mathbb{R}^{B\times H\times n\times d_h}$, 随机旋转可为每个 head 独立, 也可共享. 桶号张量为 $H_r\in\mathbb{N}^{B\times H\times n}$. 实现把桶号与位置组合为排序键, 对 token 做稳定排序, 得到置换 $\pi\in\mathbb{N}^{B\times H\times n}$. 排序后的 Q/K/V 在连续内存里按 chunk 切分, 每个 query chunk 访问自身 chunk 和前一个 chunk. 访问前一块能覆盖哈希边界附近的近邻, 也为 causal 场景提供较早位置.

### 2.2. 排序、分块与反置换

一轮 LSH attention 先对共享 QK 向量归一化, 再按式 (4) 计算桶号并把 `(bucket, position)` 编成排序键. 按键排序得到置换 $\pi$, Q、K、V 依照该置换重排并切成长度 $m$ 的 chunk. 每个chunk与自身及前一个chunk计算局部attention, 同时应用原始位置上的causal与padding mask. 计算完成后, 逆置换 $\pi^{-1}$ 把输出恢复到原序列顺序. 桶号相同不等于一个桶恰好有 $m$ 个 token. 某个方向可能吸收大量向量, 另一些方向为空. 排序后固定长度切块是在离散桶之外再施加工程分块. 同一哈希桶被切成多个 chunk 时, 只看当前与相邻 chunk 会漏掉同桶的远端成员; 不同桶在边界处也可能进入相邻 chunk. 因而算法里的「同桶注意力」与 kernel 实际计算的候选集合并不逐项相等.

多轮哈希可把每轮输出分别计算后合并. 设第 $r$ 轮对位置 $i$ 产生归一化常数 $Z_i^{(r)}$ 与输出 $o_i^{(r)}$. 不能简单平均每轮 softmax 输出, 因为同一 key 可能重复出现, 不同轮的分母也不同. 工程实现需要对重复配对做掩码, 并按各轮的 log-sum-exp 权重合并. 多轮提高召回, 代价近似随轮数 $R$ 线性增长, 索引与排序也要重复. **LSH 的性能来源包含两层结构: 概率哈希缩小语义候选, 排序后的定长 chunk 把候选变成可批处理的矩形.** 只有第一层会留下尺寸不定的 ragged 桶, 很难直接映射到高吞吐矩阵核; 只有第二层又会让分块边界主导召回.

**一个二维手算。**

取四个归一化向量, 仅示意一轮哈希, 省略 batch、head 和位置编码:

$$
x_1=(1,0),\quad x_2=(0.9,0.1),\quad x_3=(0,1),\quad x_4=(-0.8,0.2). \tag{5}
$$

取两个随机方向组成 $R=\begin{bmatrix}1&0\\0&1\end{bmatrix}$, 式 (4) 拼接后的坐标依次对应 $(+e_1,+e_2,-e_1,-e_2)$. $x_1$ 与 $x_2$ 的最大坐标都是第一维, 所以 $h(x_1)=h(x_2)=1$; $x_3$ 进入桶 2; $x_4$ 的最大坐标是 $0.8=-(-0.8)$, 进入桶 3. 排序顺序可写成 $(1,2,3,4)$, 桶大小为 $(2,1,1)$. 令 query 为 $q=x_2$, 桶内只有 $k_1=x_1$ 与 $k_2=x_2$. 省略 $\sqrt{d_h}$ 缩放, 得分为 $0.9$ 与 $0.82$. 若 $v_1=(2,0)$, $v_2=(0,2)$, 则:

$$
\alpha_1=\frac{e^{0.9}}{e^{0.9}+e^{0.82}}\approx0.520,
\qquad \alpha_2\approx0.480, \tag{6}
$$

$$
o_2=0.520(2,0)+0.480(0,2)=(1.040,0.960). \tag{7}
$$

稠密 attention 还会计算 $q^\top x_3=0.1$ 与 $q^\top x_4=-0.70$. 这两个候选较弱, 本轮漏掉的影响很小. 若把 $x_3$ 改成 $(0.71,0.70)$, 它仍可能因第二坐标略小于第一坐标而进入桶 1; 若分区边界轻微变化, 一个与 $q$ 角度接近的向量也可能落入相邻桶. 多轮随机旋转就是为这种边界误差提供第二次相遇机会.

## 3. Routing Transformer 的在线 k-means

### 3.1. 中心、分配和稀疏矩阵

Routing Transformer 为每个 attention head 维护 $C$ 个中心 $\mu_c\in\mathbb{R}^{d_h}$, 组成矩阵 $M\in\mathbb{R}^{C\times d_h}$. 对 query 与 key 分别计算到中心的相似度. 用内积形式写, 分配为:

$$
a_Q(i)=\arg\max_c q_i^\top\mu_c,\qquad
a_K(j)=\arg\max_c k_j^\top\mu_c. \tag{8}
$$

候选集合由相同中心连接:

$$
\mathcal N(i)=\{j:a_K(j)=a_Q(i)\}. \tag{9}
$$

实际方法还会限制每个簇保留的 query 和 key 数, 并与局部 attention head 组合. 式 (9) 给出内容拓扑: 属于同一语义区域的 token 即使位置相距很远, 也能在一层内直接交互. 与 LSH 相比, 中心由训练数据持续更新, 分区能贴合模型表示的分布; 相应地, 中心漂移、空簇与热点簇都进入训练稳定性问题. 路由打分张量为 $S_Q=QM^\top\in\mathbb{R}^{n\times C}$ 和 $S_K=KM^\top\in\mathbb{R}^{n\times C}$. argmax 后得到两个长度为 $n$ 的簇 ID 向量. 对 ID 排序便可把同簇 token 放到连续区间, 再为每个簇构造 QK 子矩阵. 若每簇最多容纳 $m$ 个 query 和 $m$ 个 key, 物理 attention 张量可整理为 $C\times m\times m$. 输出再根据 query 的逆置换散回 $n\times d_v$.

这种布局让复杂度容易核算. 当 $C\approx\sqrt n$, $m\approx\sqrt n$ 时, 中心打分为 $nC=O(n^{3/2})$, 簇内配对为 $Cm^2=O(n^{3/2})$. 如果数据分布均匀, 两项平衡. 若一个簇实际收到 $u\gg m$ 个 token, 实现必须截断、溢出到备用簇, 或把该簇拆成多个物理块. 截断损害召回, 溢出增加控制流, padding 则浪费算力.

### 3.2. 在线更新与训练阶段

中心不宜只靠主任务对 argmax 直接反向传播. argmax 对簇 ID 的导数几乎处处为零, 未被选择的中心也收不到正常 attention 路径的梯度. Routing Transformer 使用在线 k-means 风格更新, 根据分配到中心的向量移动质心. 对中心 $c$, 一个批次内收到的向量集合为 $A_c$, 批均值为:

$$
\bar x_c=\frac{1}{|A_c|}\sum_{x\in A_c}x. \tag{10}
$$

用动量 $\beta$ 更新:

$$
\mu_c\leftarrow\beta\mu_c+(1-\beta)\bar x_c. \tag{11}
$$

式 (11) 把中心视为训练状态. 分布式训练时, $|A_c|$ 与向量和需要跨设备聚合, 否则不同副本会形成不同路由空间. 空簇没有 $\bar x_c$, 需要保留旧中心或从数据重置. 更新过快会让簇边界抖动, 更新过慢又跟不上表示层随训练变化. 中心的学习率、归一化和同步频率都会影响最终拓扑. 局部 attention 与 routing attention 通常分配给不同 head. 局部 head 保留相邻语法与连续状态, routing head 提供远程内容边. 这种组合还有一个训练上的保护作用: 即便远程路由早期不稳定, 信息仍可沿局部窗口传播. 代价是动态路由并没有支配全部 head, 总体复杂度和质量取决于两类 head 的比例.

推理阶段中心停止按请求更新, 否则相同前缀可能因之前服务过的请求不同而产生不同路由. 固定中心后, 每次输入仍要计算 $QM^\top$ 与 $KM^\top$, 所以索引是动态的, 参数是静态的. Prefill 可一次处理整段并排序; 自回归 Decode 每步只有一个新 query, 但新 key 要加入对应簇的数据结构. 若实现每步重排全部历史 token, 算法收益会消失. 更合理的 Decode 路径是为每个簇维护追加式 KV 列表, query 只查对应列表, 同时处理容量和分页.

**六 token 的聚类手算。**

取 $d_h=2$, 两个单位中心 $\mu_1=(1,0)$, $\mu_2=(0,1)$. 六个 key 为:

$$
k_1=(1,0),\ k_2=(0.8,0.2),\ k_3=(0.6,0.4),\
k_4=(0.1,0.9),\ k_5=(0,1),\ k_6=(0.3,0.7). \tag{12}
$$

按式 (8), 前三个 key 进入簇 1, 后三个进入簇 2. 取查询 $q=(0.7,0.3)$, 有 $q^\top\mu_1=0.7$, $q^\top\mu_2=0.3$, 所以只读取 $k_1,k_2,k_3$. 三个精确得分分别为 $0.7,0.62,0.54$. 为方便手算, 令对应 Value 是标量 $v_1=1,v_2=2,v_3=4$. softmax 分母为:

$$
Z=e^{0.7}+e^{0.62}+e^{0.54}\approx2.014+1.859+1.716=5.589. \tag{13}
$$

权重约为 $(0.360,0.333,0.307)$, 输出为:

$$
o=0.360\times1+0.333\times2+0.307\times4=2.254. \tag{14}
$$

现在把 $k_6$ 改为 $(0.49,0.51)$. 它仍被分到簇 2, 但与 $q$ 的点积为 $0.496$, 已接近簇 1 中的 $k_3$. 硬分配在边界处产生不连续漏选. 若允许 query 访问 top-2 中心, $k_6$ 会被召回, 但本例只有两个中心, 候选立刻退化为全量. 更大系统中可以取少量多中心路由, 其作用与 LSH 多轮相似: 用额外预算覆盖分区边界. 按式 (10) 更新簇 1, 均值为 $\bar x_1=(0.8,0.2)$. 若 $\beta=0.9$, 新中心为 $(0.98,0.02)$, 再归一化后方向略向簇内数据转动. 这一步显示在线聚类的状态来源: 中心由历史 mini-batch 的分配累计形成, 不是当前样本即时计算的均值.

## 4. 质量、性能与工程边界

### 4.1. 召回误差从哪里产生

哈希的主要误差是概率碰撞与分区边界. 相近向量可能落入不同桶, 不相近向量也可能碰撞; 多轮哈希提高前者的相遇概率, 同时扩大候选和重复项. 聚类的主要误差是中心表达能力与硬分配. 一个多义 token 只能进入少量簇, 长尾语义可能被大簇吞没. 两者都可能在平均 loss 变化很小时漏掉单个关键证据.

表示空间也会改变邻域含义. attention 真正排序的是带 RoPE 等位置变换后的 QK 分数, 哈希或聚类若作用在变换前向量上, 内容近邻未必等于最终 attention 近邻. 若在变换后路由, 每个位置的旋转又会让同一内容随距离改变方向. 论文或实现必须说明路由发生在投影与位置编码的哪一侧, 不能只写「按相似度分桶」. 评测候选质量时, 可用稠密 attention 的 top-$t$ 作为参照. 对 query $i$, 稠密重要集合为 $G_i$, 稀疏候选为 $\mathcal N(i)$, 召回率为:

$$
\mathrm{Recall}_i=\frac{|G_i\cap\mathcal N(i)|}{|G_i|}. \tag{15}
$$

还应计算被候选覆盖的稠密概率质量 $\sum_{j\in\mathcal N(i)}\alpha^{\mathrm{dense}}_{ij}$. top-$t$ 召回把第 1 名和第 $t$ 名视为同等, 概率质量更接近输出误差, 但两者都不能替代任务准确率. 多跳问答、唯一证据检索与代码变量引用对单次漏选尤其敏感.

### 4.2. kernel、负载和分布式执行

哈希和聚类都需要把逻辑分组转换为连续块. 典型流水线是生成整数 ID, radix sort 或 bucket sort, 计算每组 offset, gather Q/K/V, 执行分块 attention, 再 scatter 输出. 排序会读写索引与特征, 当 $d_h$ 较小或桶内计算很稀时, 数据搬运可能超过点积. 若每层都重新分桶, 这项成本按层重复; 若多层共享桶, 路由更便宜, 却使用了较陈旧的表示空间.

GPU 喜欢尺寸规则的矩形块. 大小不同的桶通常被补齐到上限, 或按多个 kernel 分批. 设真实桶大小为 $u_c$, 物理容量为 $m_c$, attention 有效率可粗写为 $\sum_cu_c^2/\sum_cm_c^2$. 少数热点桶会同时拉低效率与召回: 不截断时拖慢整批, 截断时丢 token. 因而负载均衡不是附属指标, 应报告桶大小分布、最大/平均比、截断率和 padding 比.

张量并行会让问题更复杂. 若每张设备持有一部分 head, 每个 head 的路由可本地完成; 若按序列切分, 同簇 KV 分散在设备间, 候选生成后需要 all-to-all 或远程 gather. 通信量取决于路由结果, 热门簇会造成目的端拥塞. 复制中心几乎没有压力, 复制全部热门 KV 则增加显存. **算法上的内容邻域只有与数据放置共同设计, 才能在多卡上保持稀疏收益.**

**训练与推理要分别核算。**

Reformer 和 Routing Transformer 都改变了模型训练时的注意力结构, 质量结论来自按该结构训练的模型. 它们不能直接保证把一个已训练的稠密 LLM 换成分桶 attention 后仍保持行为. 稠密模型可能把某些 head 用作低幅度但分布广泛的聚合, 硬桶会改变 softmax 分母; 训练期使用的局部 head、共享 QK 或中心状态也不是现成模型必然具备的.

训练时要保存置换、桶 offset、softmax 统计量和路由状态供反向传播. 哈希随机性影响可复现性; 在线中心需要跨数据并行副本同步. 推理时不再保存反向激活, 但要处理变长请求和 KV Cache. Prefill 的排序能对长矩阵摊销, Decode 每步的索引维护与小 kernel 启动更突出. 所以同一方法在训练、Prefill 和 Decode 上可能有三套不同的瓶颈.

实际选择可以落到几个明确条件. 序列足够长、内容近邻稳定、桶较均匀并且有原生分桶 kernel 时, 哈希或聚类能减少关系数. 任务高度依赖唯一远程证据时, 应增加多轮、多中心或固定全局边. 现有稠密模型不能重训时, 更适合采用后续 [MInference](./2.1.2-MInference.md) 一类按既有 attention 模式做近似的方法. 短序列、强局部任务或高度不均衡表示下, 规则窗口与优化良好的稠密 FlashAttention 往往更直接.

## 5. 索引维护与更严格的对照

### 5.2. 哈希碰撞概率怎样换成召回预算

LSH 的价值不在哈希表查找本身, 而在碰撞概率随相似度单调变化. 设一轮哈希中, 目标近邻与 query 同桶的概率为 $p_1$, 一个无关点同桶的概率为 $p_2$, 且 $p_1>p_2$. 使用 $R$ 轮相互独立的哈希, 只要任意一轮同桶就进入候选, 目标近邻至少一次被召回的概率为:

$$
P_{\mathrm{hit}}=1-(1-p_1)^R. \tag{16}
$$

若 $p_1=0.6$, 一轮召回概率为 $0.6$, 两轮为 $1-0.4^2=0.84$, 四轮为 $1-0.4^4=0.9744$. 同时, 无关点至少一次碰撞的概率也从 $p_2$ 增为 $1-(1-p_2)^R$. 取 $p_2=0.1$, 四轮后已是 $0.3439$. 多轮既提高召回也扩大候选, 并不会免费接近精确最近邻. 式 (16)还假设各轮独立. 若随机旋转相关、向量集中在低维子空间, 实际增益会小于公式. 训练过程中共享随机种子有利于复现, 但固定分区可能让模型表示主动适应桶边界. 每步重采样提高分区多样性, 又会增加梯度噪声. Reformer 的实现选择必须与论文配置一起读, 不能把「LSH」当成唯一确定的算子.

候选预算还受桶大小影响. 设一轮平均桶大小为 $m$, $R$ 轮不去重的候选上限约为 $Rm$. 实际唯一候选数量为并集大小, 与各轮桶重合有关. 如果表示坍缩到少数方向, $m$ 会远大于设计值, 关系数重新接近平方. 所以监控哈希质量时, 除 recall@k 外还要记录每轮桶大小分位数、跨轮候选并集、重复率以及被截断的 token 数.

**聚类容量不是普通超参数。**

在线 k-means 常被简写成「分配到最近中心」, 但 attention kernel 需要有界容量. 设每个中心的容量为 $m$, 第 $c$ 个中心收到 $u_c$ 个 token. 当 $u_c>m$ 时, 至少 $u_c-m$ 个 token 无法留在该物理桶. 可以保留最接近中心的 token, 把溢出项送到第二近中心, 或把逻辑簇拆成多个物理 chunk. 三种处理分别改变召回、索引成本和同簇连通性.

保留最近 token 会偏向簇中心, 恰好位于语义边界的 token 更容易丢失. 送往第二中心需要保存 top-2 分配, 并可能把拥塞传递给另一簇. 拆 chunk 保留全部成员, 但同簇 query 若只访问一个 chunk, 仍看不见其他 chunk; 若访问全部 chunk, 热门簇成本为 $O(u_c^2)$. 因此「均衡簇」不是单纯为了 GPU 整齐, 它决定式 (9)是否仍代表实际邻接集合. 可以为中心增加容量正则, 让分配比例接近 $1/C$. 设批内中心使用率为 $p_c=u_c/n$, 均匀目标为 $1/C$, 一个简单惩罚为:

$$
L_{\mathrm{bal}}=C\sum_{c=1}^{C}\left(p_c-\frac1C\right)^2. \tag{17}
$$

惩罚过弱时热点持续存在, 过强时语义天然集中的 token 被迫分散. 最小化式 (17)也不保证每个 mini-batch 都均衡, 更不保证分布式每张设备的通信均衡. 对训练系统而言, 应同时观察语义损失与物理负载, 不能用单一系数代替容量设计.

**Q 与 K 不对称时发生什么。**

标准 attention 分别学习 $W_Q$ 与 $W_K$, 相似性是双线性关系 $x_i^TW_QW_K^Tx_j$. Reformer 通过共享 QK 让一个向量能同时作为查询和索引项. Routing Transformer 可以分别把 Q 与 K 分配给同一组中心, 但同中心并不保证原始 QK 分数高. 如果 Q 分布和 K 分布尺度不同, 中心可能更贴近其中一侧. 一种修正是分别维护 query 中心与 key 中心, 再学习中心之间的连接. 设 $M_Q,M_K\in\mathbb{R}^{C\times d_h}$, query 进入 $c_q$, key 进入 $c_k$, 只允许中心对 $(c_q,c_k)$ 属于集合 $E_C$. 这样表达力更强, 但中心图本身需要训练或搜索, 候选不再由同 ID 直接得到. 另一种做法是先把 Q/K 投影到共享路由空间 $d_r<d_h$, 用便宜的路由内积选候选, 再回到原空间计算式 (1). 这正是后续许多 indexer 路线采用的结构.

路由空间的监督目标应与最终 attention 对齐. 仅让投影重构 Q/K, 未必保持 top-k 排序. 可以从稠密 attention 提取教师集合 $G_i$, 训练路由分数 $r_{ij}$ 让正例超过负例, 例如使用 margin 损失:

$$
L_{\mathrm{route}}=\sum_i\sum_{j\in G_i}\sum_{t\notin G_i}
\max(0,\gamma-r_{ij}+r_{it}). \tag{18}
$$

式 (18)直接优化相对排序, 但构造 $G_i$ 需要稠密教师, 训练期仍可能支付平方成本. 采样负例降低训练量, 会漏掉最难干扰项. 哈希与在线聚类绕开显式教师, 代价是只能通过结构假设近似原 QK 邻域.

### 5.1. Prefill、Decode 与 KV 状态

**Prefill 可以全局排序, Decode 需要增量插入。**

Prefill 一次拿到整段 Q/K/V. 哈希可批量生成桶号并排序 $n$ 个 token, 聚类可批量计算 $n\times C$ 的中心分数. 排序开销由整段 attention 摊销, 同桶矩阵也足够大. 反向传播时, 同一置换还能用于组织梯度. 对训练和长 prompt Prefill, 这是分桶路线最自然的执行形态. Decode 每次只新增一个 $k_t,v_t$, 历史 KV 已存于 cache. LSH 若每步用新随机旋转或因表示变化重算历史桶, 成本不可接受. 固定哈希函数后, 新 key 可在 $O(d_hR)$ 时间得到桶号并追加到桶列表; query 计算桶号后读取相应列表. 聚类同理, 新 key 与 $C$ 个中心比较后插入. 每个桶因此需要可增长的页表、长度和容量管理, 不能只保存 Prefill 的连续排序结果.

历史 KV 的物理布局通常按时间分页, 分桶索引只保存逻辑位置. query 命中一个桶后仍要从多个页面 gather K/V. 若为了连续访问再复制一份按桶排列的 KV, cache 容量近似翻倍, 更新也变复杂. 若直接重排唯一 KV, causal 时间顺序与其他 head 的访问布局会受影响. 因此 Decode 的理论 $O(m)$ 候选未必换来同等带宽下降.

**KV 量化会改变路由排序。**

KV Cache 量化通常将历史 K/V 存为低比特值并配套尺度. 如果路由器直接在量化 K 上算哈希或中心分数, 量化误差可能让边界附近 token 换桶. 若为路由保留一份高精度低维摘要, 索引更稳定, 但增加额外 cache. 设路由 key 为 $k_j^r=P k_j\in\mathbb{R}^{d_r}$, 可以高精度保存 $k_j^r$, 主 attention 命中后再反量化完整 $k_j,v_j$. 这种双表示的容量为每 token 的量化 KV 加 $d_r$ 个路由元素. 当 $d_r$ 很小, 开销可控; 若每层每 head 独立保存摘要, 总量仍明显. 摘要还要与 RoPE 位置保持一致. 先量化再旋转、先旋转再量化以及把位置项从路由分数中分离, 会得到不同桶. 内核融合也不同: 路由阶段只需 K 摘要, 精排阶段才读取和反量化完整 KV.

量化误差应通过路由 recall 与最终输出共同评估. 稀疏选择和量化是两次近似, 误差可能叠加. 若量化恰好改变边界分配, 关键 key 会在精确 attention 之前消失, 后续高精度计算无法恢复. 一个稳健做法是扩大路由候选后再用原 Q 与反量化 K 精排, 以更多带宽换回召回.

**cache 淘汰与路由漏选不能混为一谈。**

某一步没有选择 key $j$, 只表示 $j\notin\mathcal N(i)$; key 仍在 cache, 后续 query 可以再次命中. cache 淘汰则永久删除当前请求中的某段 KV, 除非从更早状态重算. 两者对错误恢复的含义不同. 哈希或聚类路由可以通过多轮、多中心扩大候选, 却无法找回已经淘汰的 KV. 如果系统同时使用动态路由与 KV 淘汰, 淘汰策略不应只看过去被选次数. 哈希边界可能让一个未来重要 key 长时间未命中, 频率统计会进一步把它删除. 应把路由置信度、局部保留和特殊 token 保护纳入驱逐策略, 并分别报告「存在但未选」与「已不存在」的错误. 这两类错误在输出上相似, 修复手段完全不同.

**失效模式与评测协议。**

**边界、热点和路由抖动。**

最常见的失效来自分区边界. 两个几乎相同的向量可能因极小扰动进入不同桶, 从而让邻接集合发生离散跳变. 训练时这种抖动增加梯度方差; Decode 时相邻 query 的候选变化过大, 会降低 K/V cache 层次中的复用. 多路哈希与多中心分配能平滑召回, 也让索引和候选增长.

热点是第二类失效. attention sink、高频标点或相似模板 token 可能集中进同一桶. 热点桶既增加计算又挤掉容量内的长尾 token. 单看平均桶大小会隐藏问题, 应报告最大值、P95/P99、Gini 系数和截断比例. 分布式场景还要按目标设备统计接收字节, 因为全局桶均衡不代表网络链路均衡. 第三类失效是路由空间与任务空间错位. 语言模型 loss 主要由局部可预测 token 构成, 路由器可能学会稳定处理常见局部结构, 却在罕见跨段引用上失误. 因此仅比较困惑度不足. 评测集应控制证据频率、距离、干扰项相似度和需要汇总的证据数量.

**一个可复现的评测矩阵。**

算法层先固定稠密教师与候选预算. 对每层每 head 计算 recall@$m$、稠密概率质量覆盖、候选重复率与桶容量溢出. recall@$m$ 的教师 top-k 数不能随方法改变. 若一个方法访问整块, 既报告逻辑命中的 token 数, 也报告整块实际读取的 token 数. kernel 层记录建桶、排序、gather、attention、scatter 各段时间, 以及 HBM 读写、有效 FLOPS 与 padding. 对照至少包含同 dtype 的优化稠密 kernel和规则窗口. 序列长度应跨过方法的收益门槛, batch 与 head 维度保持一致. 预热、编译和首次内存分配不能混入稳态数字.

任务层同时测试局部语言建模、远程单证据、多证据聚合、相似干扰和长度外推. 训练型方法还要区分训练长度内与更长长度, 并报告中心或哈希配置是否随长度改变. 性能与质量最终画在同一预算轴上: 横轴为实际读取的 KV 字节或物理关系数, 纵轴分别为任务质量和时延, 才能判断某个召回增益是否值得.

**选择路线的判断。**

哈希适合角度相似性明确、希望避免学习大型路由器并能接受概率召回的结构. 聚类适合表示分布可由有限中心描述、训练过程能够维护中心且愿意处理容量均衡的结构. 两者都更适合从训练阶段纳入架构. 对已有稠密模型, 另行训练路由投影或直接使用观察到的空间模式往往更稳妥.

无论选择哪条路线, 首要问题都是索引器读了什么. 只读低维摘要, 节省可能成立; 扫描全部高维 K, 可能仍受内存带宽限制; 计算完整 QK 后才选 top-k, 则没有减少主配对. 第二个问题是候选如何进入 kernel. 连续定长块能兑现吞吐, 任意索引会付出 gather 和负载代价. 第三个问题才是稀疏率. **内容路由的完整成本是「建索引 + 组织数据 + 精确 attention」, 完整质量是「候选召回 + 桶内计算 + 未命中补救」.** 用这两个等式检查实现, 才能判断哈希或聚类是在减少工作, 还是把平方计算换成了另一组同样昂贵的索引操作.

**从算法图到可运行实现。**

**索引张量必须携带哪些信息。**

一个可运行的分桶 attention 不能只输出桶号. kernel 至少需要每个 query 块的起始偏移、有效长度、对应 key 块列表以及原位置, 才能恢复 causal 关系. 对 batch 和 head 独立分桶时, 常用压缩行格式: `row_ptr` 记录每个 query 组在索引数组中的起止, `col_idx` 记录 key 组编号, `perm` 与 `inverse_perm` 负责重排和恢复. 这些整数张量虽然小于 KV, 仍会被每层读取. 变长 batch 需要把样本边界编码进排序键, 否则相同桶号会把不同请求的 token 排在一起. 一个安全排序键可由 `(batch_id, head_id, round_id, bucket_id, position)` 组成. causal mask 使用的是原始 position, 不是排序后的槽位. 只按槽位比较先后会允许未来 token 泄漏, 训练 loss 可能因此异常变好.

反向传播还要保存或重建置换. 保存所有层的 `perm` 增加激活内存; 重建要求哈希随机数与中心状态完全一致. activation checkpointing 若在重算期间中心已被式 (11) 更新, 会产生与前向不同的桶. 因而中心更新应位于优化步骤的确定边界, 重算阶段读取同一版本.

**重复候选和归一化。**

多轮哈希、多中心分配以及局部窗口组合都会产生重复 key. 假设同一 $j$ 在两条候选路径出现, 若直接拼接后 softmax, $e^{s_{ij}}$ 会在分母出现两次, 等价于人为给该 key 增加 $\log2$ 的分数. 重复不是无害的多算, 会改变输出. 去重应发生在 softmax 前, 或由互斥的块划分保证. 显式排序唯一化会增加索引开销. 块级 kernel 可以规定优先级: 先计算局部块, 内容桶只计算局部范围外的元素; 多轮哈希则给每个配对指定最小轮号, 后续轮屏蔽已出现配对. 这种规则需要能在 kernel 内廉价判断, 否则去重 bitmap 本身可能接近 $n^2$.

不同候选分支也不能各自 softmax 后相加. 正确方法是共享行最大值与指数和, 或用 log-sum-exp 合并分支. 若局部分支有 64 个 key, 路由分支有 8 个 key, 分支级平均会让后者获得与前者相同总质量, 与单一候选集合上的 softmax 不同.

**最小正确性测试。**

小尺寸测试应先绕开性能. 取 $n\le16$, 明确列出每行候选, 用普通张量索引实现参考结果, 再与稀疏 kernel 比较. 测例要覆盖空桶、满桶、溢出、重复候选、序列首尾、padding、causal 边界、多轮哈希以及 GQA 共享. 只与稠密 attention 比较不够, 因为稀疏候选本来就允许输出不同; 应先验证 kernel 与同一候选集合的参考实现一致. 随后固定候选为全量, 稀疏实现应退化到稠密结果. 固定为局部窗口, 应与规则窗口实现一致. 这两个退化测试能发现 softmax 合并、逆置换和 causal mask 的错误. 退化测试通过后再测哈希或聚类生成的真实候选, 把算法近似误差与 kernel 数值误差分开.

性能测试则必须关闭调试排序与 Python 循环, 预热编译, 同步计时. 如果参考实现逐 head 循环而稠密基线批量执行, 得出的速度没有比较意义. 只有相同 batch、head、dtype、序列长度和硬件下的端到端层时间, 才能回答分桶是否值得. 还有一个必要基线: 在相同物理读取预算下比较随机桶、固定窗口和内容桶. 若内容路由只比稠密快, 却不比相同预算的固定窗口准, 在线建索引没有产生可识别收益. 反过来, 内容桶召回明显更高但端到端更慢, 说明算法信号成立而执行路径尚未兑现. 将质量增益与索引增量分别报告, 才能判断下一步应改路由目标还是改 kernel.

生产统计还应按请求隔离. 汇总后的均衡分布可能由一半请求集中在簇 1、另一半集中在簇 2 形成, 单请求依旧严重热点. 延迟尾部取决于单请求最大桶, 训练稳定性则更关心跨批中心使用率. 两个尺度不能互相替代.

**LSH 的召回来自角度碰撞概率。**

局部敏感哈希用整数桶号表达一种概率关系：向量越相似，落进同一桶的机会越高。Reformer 使用随机投影构造 angular LSH，再把同桶 token 排序到连续位置。碰撞概率把哈希轮数、桶数和候选预算连了起来。 **7.1. 随机超平面的基本概率.** 取单位向量 $x,y$，夹角为 $\theta\in[0,\pi]$。随机采样方向 $r$，用一位哈希

$$
h_r(x)=\operatorname{sign}(r^\top x).
$$

随机超平面将两向量分到同侧的概率为

$$
P[h_r(x)=h_r(y)]=1-\frac{\theta}{\pi}.
$$

角度越小，碰撞概率越高；正交向量概率为 $1/2$，方向相反时为 0。这个公式不保证任何特定相似 key 一定碰撞，只给单轮概率。 若把 $b$ 个独立 bit 拼成桶号，两向量同桶概率为

$$
p_b(\theta)=\left(1-\frac{\theta}{\pi}\right)^b.
$$

增加 bit 会快速降低随机碰撞，桶更细；真正近邻也更容易被切开。假设夹角 $30^\circ$，单 bit 碰撞概率 $5/6$，$b=8$ 后同桶概率约 $0.233$。仅用一张哈希表会漏掉多数这样的 pair。 **7.2. 多轮哈希把漏召回降下来.** 使用 $R$ 轮独立哈希，只要任一轮同桶就成为候选，命中概率为

$$
P_R(\theta)=1-[1-p_b(\theta)]^R.
$$

仍以 $p_b=0.233$ 为例，$R=4$ 时命中约 $65.4\%$，$R=8$ 时约 $88.1\%$。召回提高的代价是候选并集、排序和去重成本增加。 轮次之间若共享投影或只有轻微扰动，独立公式会高估收益。训练中固定随机旋转，模型也可能适应桶边界；推理换种子会改变候选。论文配置中的轮数必须和随机生成方式一起解释。 多轮候选会重复。重复 pair 若直接进入 softmax，相当于提升其 logit；正确集合语义要去重。实际物理预算近似由各轮桶大小之和决定，逻辑唯一候选则取并集，两者之间的差值就是重复开销。 **7.3. 桶边界产生不连续路由.** 向量轻微变化时，只要跨过哈希超平面，桶号就会跳变。Attention 分数对 Q/K 连续，候选集合却离散。落在边界附近的 pair 可能在相邻训练 step 反复出现和消失，形成路由噪声。

多轮哈希提供冗余：某轮跨界，其他轮仍可能保留。也可以检查相邻桶或采用 multi-probe，但候选预算增加。把路由视为固定 mask 时，梯度只通过被选边的 attention 分数传播，桶号本身通常没有可微梯度。 边界鲁棒性可以用扰动测试：固定输入，给 Q/K 加小幅各向同性噪声，统计候选 Jaccard、目标近邻召回和最终输出变化。平均召回相同的两套哈希，边界稳定性可能不同。 **7.4. Angular LSH 与点积排序并非完全一致.** Angular LSH按方向相似度路由，attention logit 为 $q^\top k/\sqrt d$，同时受范数影响。LayerNorm 或投影后的范数分布较窄时，两者接近；范数变化大时，一个方向略差但范数很大的 key 可能拥有更高点积，却被哈希漏掉。

可以将向量归一化后路由、保留原向量计算 attention。路由目标变成 cosine 近邻，最终目标仍是点积 top-k。二者偏差要通过 oracle 对照测量：全量点积 top-k 中有多少进入哈希候选，而非只测 cosine 近邻召回。

**Reformer 的排序分块是一种候选近似。**

同桶内两两 attention 仍可能形成大块。Reformer 将哈希桶排序后切成固定 chunk，并让 query 关注本 chunk 和相邻 chunk，以控制最大工作量。桶语义与执行 chunk 不是同一层概念。 **8.1. 从桶到 chunk 会截断大桶.** 某个桶含 $m$ 个 token，完整桶内 attention 需要 $m^2$ 配对。固定 chunk size 为 $c$，只读自身和前一个 chunk时，每个 query 候选约为 $2c$，总成本线性于 $m c$。相距多个 chunk 的同桶 token不会直接比较。 哈希碰撞只说明排到同一桶，不能保证进入同一执行邻域。评测路由召回时应分两层：目标 key 是否同桶，以及排序分块后是否真正进入 query 候选。只报桶碰撞会高估最终召回。 桶小于 chunk 时，排序数组可能用 padding 或拼接下一个桶。不同桶之间必须用 bucket mask 隔离，否则执行便利会引入错误边。大桶与小桶的 padding比例不同，负载分布直接影响物理工作。 **8.2. 排序键必须保持因果信息.**

排序会把原序列位置打乱。Causal attention 的合法性仍由原位置 $j\le i$ 判断，而非排序后索引。若只对排序矩阵施加下三角 mask，早出现但排序靠后的 key 会被错删，晚出现但排序靠前的未来 key会泄漏。 正确候选同时满足同桶/邻 chunk与原始因果条件。排序数组需要携带原 position，softmax 前逐元素比较。逆置换只负责把输出放回原 query 顺序，不能修复已经进入计算的未来边。 小例子可将原位置 $[0,1,2,3]$ 排成 $[2,0,3,1]$。排序下三角对 query 原位置 0 会允许读取排序在前的原位置 2，立即暴露错误。这个测试比随机 loss 更可靠。 **8.3. 哈希 Q 与 K 的一致性.** Self-attention 中 query 和 key 来自不同线性投影。若分别哈希，相关 q/k 可能因投影空间不同而不碰撞。Reformer 采用共享 QK 表示，使同一投影既作 query 又作 key，路由和打分处于共同空间。

共享 QK 降低模型自由度。标准 attention 可以让读取条件与被读取索引使用不同表示；强制共享将两者耦合。性能收益与架构变化同时存在，比较时不能把全部质量差异归因于 LSH。 若保留独立 Q/K，可训练额外路由投影 $r_q,r_k$ 对齐到共同空间。路由召回有监督或蒸馏目标，复杂度增加，也进入学习型索引范畴。 **8.4. 可逆层与 LSH 是两项独立设计.** Reformer 还采用 reversible residual layers 来减少激活内存。可逆结构允许反向从输出重建输入，LSH 减少 attention 配对。两者同时降低训练内存，却作用不同。 Attention matrix recomputation、可逆层和稀疏候选的成本应分别核算。重算哈希要求随机旋转、排序和桶配置与前向一致；随机状态不同会产生另一张图，梯度不再对应前向函数。

复现实验时，质量问题先固定哈希种子验证候选，内存问题再检查可逆与 checkpoint。把三项绑成一个开关，很难定位收益和错误。

**K-means 路由是在线向量量化。**

Routing Transformer 为 Q/K 分配聚类中心，只在同簇内计算 attention。它把近邻搜索改成中心分配，再用中心索引召回候选。近似误差包含量化误差、簇容量截断和中心漂移。 **9.1. 最近中心分配的几何边界.** 给定中心 $\mu_1,\ldots,\mu_C$，向量 $x$ 分配到

$$
a(x)=\arg\min_c\|x-\mu_c\|_2^2.
$$

两个中心之间的边界是超平面，空间被划成 Voronoi cells。真正相似的 q/k 若落在边界两侧，会被分到不同簇；距离中心很远的离群点，即使同簇，彼此也未必相似。 可以让每个向量分配多个最近中心，提高边界召回。Top-$m$ 分配把候选和中心打分成本放大约 $m$ 倍，还产生重复 key。另一方法检查相邻中心，但需要中心邻接表。 量化残差 $\|x-\mu_{a(x)}\|$ 是局部误差指标。残差大的 token 更可能错分，可给它们更多中心或 fallback；固定每个 token相同路由预算则更规则。 **9.2. 中心更新与非平稳表示.** 训练期间 Q/K 投影不断变化，向量分布也移动。中心若更新太慢，会落后于表示；更新太快，又随 batch 噪声抖动。在线 EMA 可写为

$$
\mu_c\leftarrow(1-\eta n_c)\mu_c+\eta\sum_{i:a(x_i)=c}x_i,
$$

实际实现会按计数归一化并控制步长。空簇没有样本更新，可能长期失活；热点簇接收大量异质 token，容量溢出。 中心更新不一定通过反向梯度。若属于外部状态，checkpoint 必须保存它们，分布式 rank 需要同步统计。只恢复模型权重、不恢复中心，会让同一输入路由改变。 **9.3. 簇均衡与语义纯度冲突.** 理想 K-means 最小化平方量化误差，不保证簇大小均衡。自然数据存在高频模式，热点中心可能吸收大量 token。固定 kernel希望每簇接近容量 $m=n/C$，否则最大桶决定尾延迟。 加入 capacity 后，超过上限的 token 必须丢弃、改投次近中心或进入 overflow。丢弃降低召回，次近分配提高路由成本，overflow 可能形成大桶。容量因子与 MoE 类似，但这里溢出会删除 attention 候选，直接影响信息路径。

强制完全均衡会把相似 token 拆开，增加量化误差。应同时报告簇大小分位数、中心残差和 oracle top-k 召回。只优化均衡度，可能得到执行漂亮却语义无效的分桶。 **9.4. Query 与 key 的共同聚类目标.** 若 Q/K 使用共享中心，目标是让高点积 pair 分到至少一个共同簇。普通 K-means分别最小化向量到中心距离，并未直接优化 pair recall。Q 与 K 分布不对称时，共同中心可能偏向样本更多或范数更大的那侧。 一种诊断是分别计算 query 残差和 key 残差，再按 attention top-k pair 统计共簇率。若单侧量化误差低、pair recall 仍差，中心目标与 attention 关系不匹配。 学习路由可以用 dense teacher top-k 作为监督，直接奖励候选覆盖；代价是训练期需要 dense 或近似 oracle。哈希/聚类的无监督简单性与学习索引的任务适应性形成明确交换。

**从候选召回到 attention 输出误差。**

候选 recall 是中间指标。漏掉一个 key 对输出的影响取决于其 dense attention 概率和 value。数量 recall 对所有 top-k 等权，无法描述概率质量。 **10.1. 被删概率质量.** Dense attention 权重为 $p_j$，候选集合为 $C$，被删总质量

$$
\epsilon=\sum_{j\notin C}p_j.
$$

Sparse softmax 在 $C$ 内重新归一化，权重为 $p_j/(1-\epsilon)$。若 value 范数有界 $\|v_j\|\le V$，可得到输出差异与 $\epsilon V$ 同阶的上界。$epsilon$ 比候选数量 recall 更接近函数误差。 漏掉十个极小权重 key 可能几乎无影响，漏掉唯一高权重 key 会严重偏移。路由评测应报告 captured mass：$\sum_{j\in C}p_j=1-\epsilon$，并按 head、层和距离分桶。 **10.2. Softmax 重归一化会放大剩余边.** 即使被删 value 总和接近零，删除它们仍改变分母。剩余权重统一放大 $1/(1-\epsilon)$。Sink 或低 value norm token 可能主要贡献分母，数量/语义判断都会低估它们。 候选分支各自 softmax 后相加，会给每个分支固定总质量，与统一集合重归一化不同。哈希多轮、局部窗口与聚类候选合并时，应共享行最大值与指数和，或精确实现等价 log-sum-exp。 **10.3. Oracle 路由分离索引与稀疏容量.**

固定候选数 $k$，使用全量点积 top-k 作为 oracle mask，测量理想选择下的质量；再换成哈希或聚类候选。Oracle 也下降，说明 $k$ 或稀疏 attention 本身不足；oracle 好、实际路由差，问题在索引召回。 同一 $k$ 下加入固定窗口、随机候选作基线。内容路由若不优于随机，桶未捕获语义；不优于窗口，任务依赖主要局部或路由开销没有价值。Oracle 差距给出可改进上限。 **10.4. 多层误差不会简单相加.** 某层漏边改变 hidden state，后续 Q/K、桶号和候选都会变化。早期小误差可能跨越边界导致路由离散跳变，形成级联；残差也可能抑制影响。单层 captured mass 无法直接预测最终 loss。 可采用 teacher forcing 式诊断：只替换某一层为稀疏，其余层保持 dense，扫描层号；再逐步增加稀疏层。早层敏感说明表示与后续路由放大误差，晚层敏感可能直接影响输出。

**Causal Decode 让全局重排变成增量索引。**

Prefill 已知整段 Q/K，可以批量哈希、排序或聚类。Decode 每次只新增一个 key 和一个 query，重排整个历史会让每步成本回到线性甚至更高。在线索引必须支持插入与查询。 **11.1. 哈希桶的增量维护.** 固定投影下，新 key 计算桶号并追加到对应列表，查询只读取 query 桶。插入均摊接近常数，桶列表随历史增长；每桶如果无限增长，查询成本仍会增加。 设置桶容量后，需要保留最近、随机抽样、按分数淘汰或分裂桶。任何淘汰都改变可访问历史。只保留最近桶内 token，会让远端 key退出；保留代表样本则变成摘要。 多轮哈希维护多份列表，内存约乘轮数。列表以 page 存储时，碎片和指针访问影响 Decode。Prefill 排序得到的连续布局随增量插入逐渐破碎，周期重建可恢复连续性，重建会产生时延峰值。

**11.2. 在线聚类的插入与中心漂移.** 新 key 分配到最近中心并加入簇。中心若随 Decode 更新，旧 key 的所属簇基于旧中心，索引逐渐不一致；全部重分配成本高。固定 Prefill 结束时中心，Decode 分布变化时又可能失配。 可以更新中心但不迁移旧 key，把中心视为簇摘要；此时 nearest-center 分配不再对应当前 Voronoi 划分。查询召回需要实测，不能继续引用标准 K-means误差。 另一方案使用训练得到的全局中心，推理不更新。索引稳定、不同请求共享中心，个别请求分布可能高度偏斜。请求级热点需要单独统计。 **11.3. Future access 决定 KV 能否淘汰.** 内容路由的未来 query 未知，任何旧 key 都可能再次成为近邻。除非索引规则限制时间范围或明确淘汰，无法证明旧 KV 安全删除。每步只读取 $k$ 个不代表 cache 只有 $k$ 个。

这一区别对服务很关键：计算稀疏但状态仍线性增长。要获得有界 cache，需要将哈希/聚类限制在滑动时间窗、把旧簇压成摘要，或外置索引与 KV。每种方案都改变精确召回。 **11.4. Prefill 与 Decode 路由一致性.** Prefill 若按全局排序完整构建桶，Decode 用增量列表，两条路径在相同前缀上应产生相同候选。桶容量、并列排序、中心版本和去重次序都可能导致差异。 验证方法是同一序列分别一次 Prefill 和逐 token 插入，导出每步候选集合、attention 输出与梯度适用部分。候选不一致时先修索引，不能用浮点容差掩盖。

**训练信号与路由器状态。**

哈希通常固定随机投影，聚类中心则在线维护。两者都可能与模型表示共同演化，只是可学习路径不同。 **12.1. 固定哈希促使表示适应桶.** 哈希投影固定后，Q/K 投影可以学习让需要交互的 token 落入相同方向区域。虽然桶号不可微，只有碰撞后的 pair 获得 attention 梯度；未碰撞的相关 pair 没有直接信号，学习存在冷启动。 多轮和局部窗口提供基础路径，使相关信息先通过其他通道影响 loss，再逐渐塑造表示。完全依赖单轮 LSH，早期随机漏选可能让模型永远看不到应学习的关系。 更换哈希种子后，适应的边界改变。固定权重跨种子下降，反映模型利用了特定分区；不同种子从头训练的方差反映方法稳定性，两项要分开。 **12.2. 聚类中心是 checkpoint 状态.**

在线中心、计数和可能的方差统计都影响候选，属于模型运行状态。Checkpoint 只保存参数而遗漏中心，恢复后路由不同；分布式训练中，各 rank 中心未同步也会让相同 token 路由不同。 Activation checkpoint 重算期间不应更新中心。前向用版本 $c_t$ 生成候选，反向重算必须读取同一版本。中心更新放在 optimizer step 边界，并保存版本号，是较清楚的事务语义。 **12.3. 负载正则与召回目标.** 可加入中心使用均衡损失，惩罚某些簇过热；也可蒸馏 dense attention，奖励 top pair 共簇。两个目标可能冲突：真实数据确有热点关系时，强制均衡会拆散语义簇。 损失权重应通过 Pareto 曲线选择，同时观察最大桶、captured mass 与任务质量。只报告平均簇利用率，无法确认均衡是否以召回为代价。 **12.4. 路由冻结与后期漂移.**

训练早期表示变化快，中心需要适应；后期冻结中心可稳定候选和 kernel 负载。冻结太早，中心落后；始终更新，评测 checkpoint 附近仍可能波动。 可以在冻结前重新运行一段中心估计，再固定并继续训练权重。最终发布需要说明中心来自哪段数据、是否随微调更新。下游领域偏移后，固定中心可能失配；更新中心又改变预训练路由。

**一套针对粗粒度路由的验收表。**

验收顺序从数学候选开始，再到数值 attention、训练状态和系统成本。大模型最终分数无法替代这些分层证据。 **13.1. 候选生成金样.** 构造单位圆上的若干向量，手算角度、哈希 bit 和多轮并集；构造二维中心，手算最近簇与边界点。覆盖相同分数并列、空桶、满桶、overflow、padding 和 causal 顺序。 固定随机种子与中心版本，两次生成候选应完全相同。改变 batch 排列不应改变单样本路由，除非算法明确使用 batch 级在线中心更新；这种依赖需要记录。 **13.2. 数值 attention 金样.** 给定显式候选集合，用普通 gather 计算统一 softmax，作为稀疏 kernel 参考。覆盖重复 pair 去重、多轮合并、局部与内容候选重叠、空候选 fallback 和全候选退化。 前向、Q/K/V 梯度和参数梯度均比较。Causal mask 使用原 position，排序索引只用于布局。一个未来 token 混入候选就应让测试失败。 **13.3. 召回与误差指标.**

对 dense top-k 报告 pair recall、captured probability mass、value-weighted error，并按层、head、距离、桶大小和请求分桶。平均指标之外给尾部分位数与最差请求。 Oracle top-k、固定窗口、随机块和相同预算内容路由构成四个基线。质量收益与路由时间分别报告，明确算法空间和系统空间的差距。 **13.4. 在线状态与性能.** Prefill 记录排序、中心分配、attention kernel 与逆置换时间；Decode 记录哈希/中心查询、列表插入、候选 gather 和 softmax 时间。索引内存、KV 内存和临时 workspace 分开。 长度增长时画最大桶、非空桶、page 数和 TPOT。热点请求单独展示，避免批平均掩盖尾延迟。周期重建若存在，报告峰值而非只给摊销均值。 **13.5. 反例边界.** 把真正 top key 放在哈希边界另一侧、聚类相邻簇、容量溢出尾部和序列开头候选不足处，检查 fallback。再让 Q/K 范数差异很大，验证角度路由与点积目标偏差。

若路由漏选但 oracle 正确，问题在索引；oracle 同样失败，预算或稀疏 softmax不足；候选正确而 kernel 输出错误，问题在实现；单步正确、训练不收敛，则查离散路由与中心状态。每类失败有明确下一步。

**桶占用分布决定真实复杂度。**

理论分析常假设 $C$ 个桶平均各含 $n/C$ 个 token。实际哈希与聚类产生不均匀占用，attention 成本由桶大小平方和决定，而非只由平均值决定。 **14.1. 平方和为什么放大热点.** 若第 $c$ 个桶大小为 $m_c$，完整桶内 attention 边数为

$$
E=\sum_{c=1}^{C}m_c^2,\qquad \sum_cm_c=n.
$$

完全均衡时 $m_c=n/C$，得到 $E=n^2/C$。只要分布不均，由凸性可知平方和增加。一个包含大量 token 的热点桶足以主导整层成本。 设 $n=1024,C=16$。均衡时每桶 64，边数为 65536。若一个桶有 304，其余 15 个各 48，总数仍为 1024，平方和变为 $304^2+15\times48^2=127{,}  ？$。精确计算为 92416+34560=126976，接近均衡成本两倍。平均桶大小仍是 64，完全看不出热点。 因此要报告 $\sum m_c^2$、最大桶和高分位，而非只报告非空桶数。固定 chunk 截断大桶能控制成本，却把多余同桶关系变成漏召回。 **14.2. 随机均匀分桶也有尾部.** 即使每个 token 独立均匀选择 $C$ 个桶，桶大小服从 occupancy 分布，不会完全相等。期望为 $n/C$，方差约为 $n(1/C)(1-1/C)$。最大桶通常高于均值，短 batch 和大桶数时相对波动更明显。

多轮哈希会对每轮重复这种波动。Kernel按全局最大桶分配固定缓冲，会为多数桶浪费空间；使用变长列表则带来 prefix sum 和不规则调度。算法中的随机均衡不能直接当作系统中的固定 shape。 **14.3. 语义热点比随机热点更严重.** 常见标点、空白、格式 token 或相似位置可能形成密集方向，聚到同一桶。模型训练后也可能主动把大量 token 投向有用中心，使热点成为学习结果。强制均衡会打散这些关系。 按 token 类型和位置分析热点，能判断是数据结构、位置编码还是路由退化。若所有 token集中少数桶，实际接近 dense 且其他中心没有梯度；若每种语义各有热点，可能需要层次分桶或提高对应容量。 **14.4. Capacity factor 的概率解释.**

平均容量 $n/C$ 乘 capacity factor $\gamma$ 得到上限 $M=\lceil\gamma n/C\rceil$。$\gamma$ 越大，溢出概率低，预留与最坏计算高；$\gamma$ 越小，执行规整，更多 token 改投或丢弃。 不同序列长度下固定 $\gamma$ 保持相对容量，绝对桶变大，桶内 attention 成本仍增长。固定绝对 $M$ 则总桶数需随长度增长，中心分配成本和模型外推随之变化。

**分布式路由把语义边变成通信。**

序列或 KV 沿设备切分时，同桶 token 可能分散在多个 rank。要在同桶内 attention，需要搬运 K/V 或把 query 发往持有候选的设备。内容分布决定通信，负载也随输入变化。 **15.1. 本地哈希与全局哈希的差别.** 每个 rank 只在本地 token 中分桶，避免通信，却漏掉跨 rank 相似 key；全局桶保留算法定义，需要 all-to-all 按桶重排。二者候选不同，不能把本地版本称为纯实现优化。 全局哈希桶号可在各 rank 本地计算，再按目标桶 owner 发送 token。热点桶 owner 接收大量数据，成为通信和计算热点。对桶做多 owner 分片可均衡，但同桶 attention 需要跨分片处理或再次归约。 **15.2. 聚类中心同步与数据并行.** 数据并行 rank 看到不同 batch，在线更新中心若各自独立，模型参数虽同步，路由器状态却分叉。全局归约中心统计保持一致，增加通信；周期同步降低成本，中间 step 使用不同候选。

中心属于 checkpoint 的事实在分布式中更重要。保存单 rank 中心时，要确认它与全局版本一致；弹性训练增加或减少 rank 后，计数和 EMA 步长也要重新定义。 **15.3. 序列并行的桶重排.** 原序列按位置连续切分，窗口 attention 只需邻居 halo；内容桶可能把任意位置发往任意 rank，形成 all-to-all。计算边数减少，通信距离增加。长序列下跨设备字节可能支配收益。 静态窗口与内容路由混合时，局部部分留在原 shard，内容候选走重排。两个分支需要统一 softmax，若分别计算再平均会改变函数。分布式 log-sum-exp 要交换每行最大值、指数和与加权 value 累积。 **15.4. 路由元数据也要传输.** 除了 K/V，接收端需要原 query/key 位置、桶号、请求 ID、causal position 和逆置换索引。元数据相对大张量通常较小，在极稀疏、小 head dimension或 Decode 单 token 时占比会上升。

压缩索引到 16/32 bit 要保证最大长度范围，跨请求 batching 还需偏移。索引溢出往往只在超长输入出现，应纳入边界测试。

**四组可复算反例。**

反例把「内容相似就能找到」拆成碰撞、容量、方向和在线维护四个可验证条件。 **16.1. 角度近邻被哈希边界切开.** 二维单位圆上取 $x=(\cos(\epsilon),\sin(\epsilon))$，$y=(\cos(-\epsilon),\sin(-\epsilon))$，两者夹角仅 $2\epsilon$。若随机超平面恰为 $y$ 轴，即按第二坐标符号分桶，$x,y$ 落入相反桶。 相似度趋近 1，单次哈希仍可能漏掉。随机超平面公式只说明这种坏方向的测度随 $\epsilon$ 变小，不会消失为逐样本保证。多轮或邻桶 probe 降低风险。 将这个 pair 设为唯一高 attention key，其他 key 与 query 正交。Dense 输出由 $y$ 主导，漏选后结果完全不同；随机自然文本平均指标可能掩盖这种边界样本。 **16.2. 热点桶容量溢出删掉最佳 key.** 一个桶容量 4，按原位置保留前四个 key。五个 key 都与 query 同桶，真正最高点积的是第五个。路由碰撞 recall 为 100%，执行候选 recall 为 0%，因为容量策略丢掉目标。

改成随机保留时命中概率为 $4/5$，按中心距离保留又可能与 query 点积不一致。容量策略需要作为路由算法一部分评测。只看簇分配会错误归因给 attention。 **16.3. 角度路由漏掉大范数 key.** Query $q=(1,0)$，key $k_1=(1,0)$，$k_2=10(0.8,0.6)$。Cosine 更偏好 $k_1$，点积分别为 1 与 8，attention 应偏好 $k_2$。Angular LSH 更容易把 $q$ 与 $k_1$ 放在一起。 若模型投影后范数分布宽，路由目标与最终分数存在系统偏差。归一化 Q/K 会消除这个例子，同时改变 attention 本身；只归一化路由副本则保留点积计算，需要训练接受两套表示。 **16.4. 在线中心漂移留下陈旧索引.** 时刻 0 有中心 $\mu_1=-1,\mu_2=1$，旧 key $x=0.2$ 分到中心 2。后来数据让中心移动到 $\mu_1=0,\mu_2=3$，按新中心 $x$ 应属于中心 1，但索引仍放在桶 2。Query $q=0.1$ 分到新中心 1，无法找到 $x$。

更新中心而不重分历史会产生这种陈旧；完全重分成本随 cache 增长。固定中心避免漂移，却可能不适应新数据。在线聚类必须选择并记录这项交换。

**从需求反推哈希或聚类。**

哈希无需维护学习中心，映射便宜且多轮易并行；聚类能适应数据分布，中心维护和容量问题更重。选择从候选质量、在线更新和硬件粒度三方面出发。 **17.1. 相似度稳定时优先固定哈希.** 表示经过归一化、角度相似与 attention 目标接近，固定 angular LSH 有清晰概率。训练与推理映射一致，不需同步中心。多轮数由目标角度的命中率反推。 若需要逐样本确定召回，LSH 概率保证不足，应保留窗口、global 或 oracle 类 fallback。哈希适合作为扩散远端入口，不宜单独承诺关键控制信息必达。 **17.2. 数据存在稳定簇时采用聚类.** 语义分布形成可压缩簇、中心残差低且负载可控，K-means 路由能用较少中心定位候选。领域变化大、在线表示漂移快时，中心维护会成为主要风险。

训练中心、全局固定中心和请求自适应中心是三种不同方案。全局中心便于共享 kernel与索引；请求中心更贴合当前文档，却要在 Prefill 建立，短请求可能得不偿失。 **17.3. Block 粒度由 kernel 决定下限.** 逐 token路由召回高，物理 gather 碎片多；block 路由一次选入整块，候选冗余增加，矩阵乘更高效。Block size 应通过质量—tile 利用率曲线选择。 块内内容异质时，中心可由均值、最大池化或代表 token 产生。均值可能抹掉唯一关键 token，最大池化依赖维度，代表 token 需要学习。Block 表示方式也是路由器的一部分。 **17.4. 路由成本必须小于省下的点积.** 全量中心打分成本 $O(nC d_r)$。若 $C$ 随 $\sqrt n$ 或更快增长，路由本身可能可观；哈希投影、排序为 $O(n\log n)$ 或相应 kernel 成本。短序列上 dense attention 常更快。 定义总时间

$$
T=T_{route}+T_{reorder}+T_{sparse\ attn}+T_{merge}.
$$

只测 sparse attention kernel 忽略前三后处理项。与 dense 的交叉长度由硬件和实现实测，渐近复杂度无法给固定答案。 **17.5. 最终配置要绑定失败回退.** 空桶、溢出、索引未初始化、中心 NaN 或候选少于最低数量时，fallback 可以读局部窗口、增加邻桶或退回 dense。不同 fallback 影响质量和尾延迟，应计入统计。 生产监控记录 fallback 率、最大桶、captured mass 的可用代理和索引版本。平均延迟正常但 fallback 集中在关键长请求，用户体验仍会恶化。 **17.6. 多尺度候选比单一桶更稳.** 单一细桶擅长高精度近邻，边界漏召回明显；粗桶覆盖更广，候选噪声和成本更高。可以并行使用粗细两级：细桶提供主要候选，粗桶只在细桶不足或 query 残差大时补充。

两级候选共享 softmax，并在进入计算前去重。粗桶的触发条件若依赖 query 到中心距离，仍是可提前计算的路由信号；阈值决定 fallback 率。报告细桶单独召回、粗桶增量召回和增量物理块，才能判断第二级是否值得。 层次聚类也可从根节点逐层选择子中心，把中心打分从 $C$ 降到树深与分支因子的乘积。早期选错分支会永久漏掉目标；beam 搜索多个分支提高召回，又增加候选。树的训练与平衡成为新的状态。 **17.7. 局部窗口是内容路由的稳定底座.** 语言中的相邻依赖高频且执行规则。固定窗口保证每个 query 至少拥有连续历史，哈希或聚类只负责补远端候选。路由失败时模型仍可局部生成，训练早期也有梯度路径。

总预算 $k$ 可分成窗口 $w$ 与内容候选 $k-w$。增大 $w$ 提高确定局部覆盖，压缩远端探索；减小 $w$ 增加路由自由度，也让简单句法依赖承担不必要风险。按证据距离分桶的 oracle 实验可反推分配。 窗口候选与内容桶会重叠。重叠率高说明路由把预算浪费在本已可见的局部 token；训练时可排除窗口范围后建远端索引，或允许重叠以保持纯相似度。两种规则的分布不同。 **17.8. Query 自身所属桶不应泄漏未来.** 在 causal Self-attention 中，当前 query 与当前 key可以有 self edge，未来 key尚未生成。Prefill 批量分桶时，同桶列表包含未来位置，必须用原位置 mask。Decode 增量桶天然只有历史，Prefill 与 Decode 若处理不同，输出会不一致。 排序 chunk 可能让一个 query 与未来 token 位于同块。整块 GEMM 后再在 value 输出处清零已经太晚，未来分数进入 softmax 分母。Mask 必须在指数归一化前应用。

训练若发生微小泄漏，loss 会异常好，推理质量却下降。将未来 token 替换为随机内容，当前位置 logits 应不变；这个反事实测试能抓住跨桶泄漏。 **17.9. GQA 的路由共享口径.** 多个 query head 共享一个 KV head。若每个 query head独立路由，同一 KV head需要读取各候选并集，物理 K/V gather可能远大于单 head预算；若一组 query head共享路由，成本低，head 多样性减少。 可以用组代表 query 生成候选，再让组内 head各自计算分数。代表取均值可能漏掉某个 head独特近邻；取候选并集提高召回与成本。报告的 top-k 应说明按 query head、KV group 还是 token计数。 **17.10. Position bias 会改变 oracle 近邻.** Attention logit常含 RoPE、ALiBi 或相对位置 bias。若路由只看内容投影，dense top-k 可能由位置项改变。远端内容相似 key受到距离惩罚后不再重要，近端普通 key反而进入 top-k。

Oracle recall应按完整 attention logit计算。路由向量可以加入位置特征或将固定窗口单独保留，让内容索引专注远端。位置编码外推变化时，路由与打分偏差也会随长度改变。 **17.11. 温度改变候选预算需求.** Softmax 温度低、分布尖锐时，只要捕获少数最高 key，就能保留大部分概率质量；温度高、分布平坦时，需要更多候选。Head dimension缩放、QK norm与训练都会影响熵。 按 attention entropy分桶报告 captured mass。高熵 query 即便 top-k数量 recall高，删除尾部总质量仍大；低熵 query 漏掉第一名则灾难。动态候选数可按熵代理调整，执行 shape 更不规则。 **17.12. 路由器也可能成为对抗入口.** 输入能够操纵 Q/K 表示时，攻击者可能制造热点桶，放大计算和尾延迟；也可能让关键内容跨桶，降低召回。固定窗口成本上界清楚，内容桶的输入相关负载需要限额。

Capacity、防止单请求占满共享桶、按请求隔离索引和最大重建频率，都是资源保护。强行截断会影响该请求质量，但不能让一条异常输入拖垮整个 batch。 监控热点应保留请求级分布。集群平均均衡可能掩盖某个恶意请求的单桶爆炸。随机种子保密不是核心防线，确定容量与超时才是可验证边界。 **17.13. 离线索引与在线表示不一定相容.** 若把旧 K/V 外置并预先建索引，模型权重更新后，新的 query表示空间可能与旧 key索引不匹配。即便原文本相同，投影变化会改变中心和哈希。 索引版本必须绑定模型权重。跨版本复用需要重新编码 key，或训练稳定的独立检索表示。后者与 attention K不同，候选进入最终 attention前仍用当前模型 K/V 计算。

量化外置 key也会改变桶号或中心分配。先量化再索引与先索引再量化可能得到不同候选，流程需要固定。 **17.14. Chunk size 同时控制计算与语义.** 排序后 chunk越大，同桶内覆盖更完整，$c^2$ tile成本增加；chunk越小，漏掉远处同桶 token。相邻 chunk数 $a$ 将候选扩到约 $(a+1)c$，边界召回提高。 最佳 chunk与桶占用分布相关。大多数桶很小时，大 chunk padding浪费；少数热点桶很大时，小 chunk截断严重。固定一个全局 chunk便于 kernel，分桶自适应 chunk更复杂。 **17.15. 训练长度改变桶统计.** 固定桶数 $C$，序列长度增长时平均桶大小按 $n/C$ 增加，成本上升；固定桶容量则需增加桶数，哈希 bit或中心数量变化。模型在训练长度上适应的负载和碰撞率不会自动外推。

长度外推实验应保持哪项不变必须明确：桶数、桶容量、候选数还是稀疏率。保持不同量会得到不同算法。聚类新增中心还需要初始化，哈希增加 bit会改变所有桶号。 **17.16. 结果报告的最小充分信息.** 哈希路线给出向量预处理、bit数、轮数、随机生成、chunk、邻 chunk、去重和种子；聚类路线给出中心数、分配数、容量、overflow、更新步长、同步与冻结时刻。共同部分给窗口、causal、位置、head共享和 fallback。 质量报告 oracle差距、captured mass、任务分数与多种子方差。系统报告路由、重排、attention、合并分项，最大桶、padding、通信和在线索引内存。缺少这些信息，同一个「LSH attention」或「routing attention」名称可能对应完全不同函数。 **17.17. 何时放弃粗粒度内容路由.**

若任务依赖主要局部，固定窗口在相同预算下已达到质量，内容索引只增加开销；若必须逐样本保证关键证据可达，概率桶也不适合作唯一通路；若 Decode 索引维护比省下的点积更贵，应选择规则拓扑或更粗阶段。 内容路由真正有价值的区域是：远距相关位置随输入变化，固定图需要大量边才能覆盖，允许少量近似失败，且硬件能以块粒度兑现候选。Oracle 基线先证明这个区域存在，再投入 kernel与训练。 粗粒度桶也可以只做第一阶段，之后用细粒度打分重排。桶负责把全历史缩到几百候选，indexer再选几十 key。此时端到端召回是各阶段召回的乘积，任何阶段漏掉目标都无法恢复；预算与监督需联合设计。 **17.18. 两阶段召回的乘法下界.**

设粗路由召回目标 key 的概率为 $r_1$，细排在已召回条件下保留它的概率为 $r_2$，端到端召回为 $r_1r_2$。两阶段各有 95%，最终只有 90.25%；四阶段各 95%，降到约 81.45%。 阶段越多，每段召回损失都会累积。末级 indexer 的精度受粗桶召回上限约束。条件召回和总体召回应同时报告，预算也应优先投入损失最大的阶段。 训练时若只监督最终候选，前级离散漏选没有梯度。Dense teacher可分别给粗级簇和细级 key目标，或者用正样本强制注入候选再训练打分；推理去掉强制注入后仍需测真实召回。 **17.19. 多正样本任务需要覆盖率而非单点 recall.** 一个 query 需要同时读取 $m$ 个证据，单证据召回率为 $r$，若近似独立，全部召回概率约为 $r^m$。$r=0.95,m=10$ 时只有约 59.9%。平均 pair recall很高，多证据联合仍可能频繁缺项。

应报告每个 query 的 evidence coverage：所需证据集合被覆盖的比例，以及完整覆盖率。证据路由相关时，独立近似不成立；同一桶可能一起命中，也可能被容量一起截断。Query级指标直接反映联合风险。 随机键值任务常只问一个 key，无法揭示这项放大。多跳问答、代码依赖闭包和集合统计更适合测试完整覆盖。 **17.20. 中心数量的偏差—方差交换.** 中心少时，每簇宽，量化偏差高、候选多；中心多时，簇细，边界更多，每个中心样本少，在线估计方差上升。空簇和失活中心也更常见。 增加 $C$ 同时提高中心打分成本 $O(nC)$。若用层次或近似中心搜索降低成本，又引入上层漏召回。最佳 $C$ 应在残差、边界召回、桶平方和与路由时间的联合曲线上选择。

训练数据规模也影响中心稳定。低频领域只有少量样本，细中心可能被高频领域占满；分领域中心提高覆盖，部署需先识别领域或多查几套中心。 **17.21. 哈希 bit 与轮数不是可互换参数.** 减少 bit让每轮桶更粗，单轮命中高，桶内候选和平方成本大；增加轮数保持细桶，每轮候选少，却重复投影、排序、元数据和去重。相同理论命中率的两组参数，系统成本不同。 给定目标角度 $\theta$，可枚举 $(b,R)$ 满足 $1-(1-p_b)^R\ge r$，再用真实桶分布筛选。公式只估指定 pair，负样本碰撞决定候选量，还要用数据测量。 Decode 中多轮意味着每个 key插入多个列表，内存与随机写增加；粗桶只插一次但查询列表长。Prefill 与 Decode 可能偏好不同组合，若采用不同参数又会改变模型函数。 **17.22. 桶内再排序可以恢复部分精度.**

粗桶候选仍可用真实 QK 点积选 top-k，然后做最终 softmax。这样聚类只负责召回，桶内排序修正中心距离与 attention score 的偏差。候选 $m$、最终 $k$ 时，额外计算 $m$ 个点积但只保留 $k$ 个 value读取。 若 QK 点积本就是主要成本，$m$ 不能太大；若 value带宽或 softmax更重，两阶段仍可能划算。报告粗候选数和最终候选数，避免只写 top-k 掩盖前级工作。 Top-k 选择也有排序与 kernel成本。Block级执行若最终 key分散，token top-k可能破坏 tile利用率；选择 top block 再块内 dense，是精度与规则性的折中。 **17.23. 重复 token 与近似副本会占满桶.** 长文档可能包含模板、代码样板或重复段落，表示相近的 token集中同桶。它们彼此冗余，却占据容量，真正相关但稍远的 key被挤出。

去重内容副本需要额外指纹或段落级压缩；按时间保留少量副本能释放容量，但当前 query可能需要特定位置版本。位置 bias与上下文差异使表面重复并非完全可替换。 评测可控制重复率：复制无关段落多次，观察目标召回与最大桶。对重复鲁棒的路由应让候选预算随独立信息增长，而非随副本数线性增长。 **17.24. 中心塌缩的早期信号.** 有效中心数下降、最大桶上升、中心间余弦趋近、空簇比例增加，都是塌缩信号。任务 loss可能暂时正常，因为局部窗口或少数热点桶承担计算；路由优势已经消失。 重新初始化空中心、均衡正则和中心排斥可以缓解，每种操作都会改变候选。训练日志应把中心事件与 loss尖峰对应，checkpoint保存重初始化计数与随机状态。

塌缩后继续按名义 $C$ 估复杂度会过于乐观。实际有效中心 $C_{eff}$ 可由占用熵 $H(p)$ 转成 $\exp(H)$，与最大桶和平方和一起报告。 **17.25. 软分配只把离散问题移到预算上.** 对中心使用 softmax 权重，训练时路由可微；若推理仍取 top-m 中心，边界重新出现。训练温度高时分配平滑，推理硬化产生差距；逐步降低温度可以缩小差距。 完全使用所有中心权重不再稀疏，计算回到全量或低秩混合。Soft routing的价值在学习中心与置信度，最终仍需预算截断。报告训练和推理的中心数与温度。 Straight-through estimator 给硬选择伪梯度，优化方便但梯度有偏。最终效果由实验验证，不能把可微近似当作真实离散目标的精确梯度。 **17.26. 请求自适应中心的冷启动.**

长文档 Prefill 可先用前若干 token估计中心，再路由其余部分；早期 token在中心成熟前如何处理成为冷启动问题。用全局预训练中心初始化，再向请求分布微调，是一种折中。 中心自适应会让同一 token在不同请求落不同桶，跨请求 prefix cache和批量调度更困难。全局中心更易共享，个体适应性较弱。请求长度短时，建中心成本可能超过稀疏收益。 **17.27. 路由的可解释性来自候选干预.** 看到一个桶聚集相似词不代表模型依赖该语义。将目标 key强制移出桶、强制加入候选、交换两个中心，再观察输出和任务变化，才接近因果证据。 强制加入 oracle key后恢复，说明漏召回是主因；加入仍失败，可能是softmax、value或后层计算。强制平衡桶后速度提升、质量下降，量化了负载与语义的交换。

这些干预应在固定权重下进行，随后从头训练可回答模型能否适应新路由。即时敏感性与可训练性是两个问题。 **17.28. 一个端到端预算例子.** 序列 $n=65536$，目标每 query最终读取 128 个 key。粗聚类 $C=256$，平均桶 256；先查两个中心得到约 512 候选，点积细排到 128。中心打分每 query需256个低维分数，粗候选点积512个，最终value读取128个。 若最大桶达到1024，两个中心可能产生超过1280候选，细排成本和临时buffer显著增加。Capacity截到每桶384可控制上限，却可能删目标。该配置的关键指标是双中心 oracle覆盖、截断后覆盖和候选分位数。 固定窗口128只需规则读取，无中心和细排。内容路线必须在远距任务上明显优于窗口，且路由+细排总时间低于省下的 dense点积，配置才成立。 **17.29. 长尾 key 的中心学习.**

高频 token 对中心更新贡献大，长尾专业词和随机标识可能被分到宽泛簇。恰恰是这些低频 key 更需要精确召回，因为语言先验难以猜测其 value。按频率分桶测 pair recall，能发现平均指标中的偏差。 对中心更新做频率重加权可以照顾长尾，也会扭曲真实密度并增加热点外的容量。保留一组专门的 rare buckets、让随机标识走固定哈希，属于显式混合策略。 **17.30. 跨层复用索引的条件.** 多层 Q/K 表示不同，直接复用第一层桶到后续层可省路由成本，却假设近邻结构跨层稳定。计算相邻层候选 Jaccard、dense top-k转移和 captured mass，能够验证这项假设。 若只复用 key索引、query每层重新分配，中心空间仍需对齐；若连 query桶也复用，后层内容变化完全无法调整。Cross-layer routing sharing减少元数据与排序，可能限制层级语义演化。 **17.31. 负样本碰撞决定候选纯度.**

正 pair命中率高只是召回，桶中无关 key数量决定 precision和计算。对角度 $\theta_-$ 的负样本，单轮碰撞概率同样由 $1-\theta_-/\pi$ 决定。高维向量若大量接近正交，单 bit仍有一半概率碰撞，必须依靠多 bit细分。 选择 $(b,R)$ 时同时约束正样本命中和负样本候选数。增加轮数会把各轮负碰撞并入候选，召回与噪声一起上升。数据上的 ROC 曲线比单一理论角度更实用。 **17.32. Query 路由置信度可指导预算.** 聚类中最近与次近中心距离差很大，query位于 cell内部，单中心较可靠；差距很小，query靠近边界，可查两个或更多中心。定义 margin

$$
\Delta(q)=d_2(q)-d_1(q),
$$

margin小则提高预算。动态策略把计算集中到困难 query，平均候选下降，batch shape与尾延迟更不规则。 哈希也可用投影绝对值作为边界置信度：某 bit的 $|r^\top q|$ 很小，轻微扰动会翻转，可 probe 对应相邻桶。置信度需要校准到真实 top-k召回。 **17.33. 最终判断依赖三张曲线.** 第一张是候选预算—captured mass，判断索引质量；第二张是候选预算—端到端时间，判断实现成本；第三张是 captured mass—任务质量，判断漏边敏感性。三张曲线共同决定工作点。 若第一张差，改哈希或中心；第一张好、第二张差，改布局与kernel；前两张好、第三张仍差，问题可能在稀疏softmax训练或任务需要更多联合证据。单个最终分数无法提供这种定位。

配置发布时保留曲线而不只保留最佳点。硬件、长度或数据分布变化后，可以沿曲线重新选预算，无需把旧超参数当成普遍结论。 **17.34. 路由版本应进入可复现标识.** 随机投影、中心张量、容量规则、排序稳定性和 overflow策略任一变化，候选图都会改变。模型权重文件之外，应保存路由状态哈希；Prefix cache和已构建在线索引也绑定该哈希。 微调若更新 Q/K 而冻结中心，表示与索引可能逐渐失配；更新中心又让旧 cache桶号过期。发布新版本时，要么重新构建索引，要么证明路由空间保持兼容。Shape相同不足以支持跨版本复用。 **17.35. 短序列退化应有明确路径.**

当 $n$ 小于候选预算或只有少数 block，dense attention往往更便宜也更精确。实现可在阈值以下切换 dense，阈值以上启用路由；两条路径在交叉长度附近应输出一致，前提是候选已覆盖全部合法 key。 阈值属于性能选择，不应改变模型可见集合。若短序列路由仍只选 top-k，而 dense fallback看到全部 key，模型函数随长度跨阈值跳变。安全 fallback在候选预算足以覆盖全量时才使用 dense等价路径，否则需要按同一 mask计算。 **17.36. 粗路由与精确 attention 的职责边界.** 哈希或中心只决定候选，不应直接把桶相似度当最终 attention 权重。最终 QK分数、causal mask、softmax和value聚合仍按模型定义执行。桶内所有 token等权会把方法变成聚类池化，表达能力不同。

调试沿数据流展开：候选集合、候选上的精确 attention、端到端训练。候选正确而输出错误时，中心并非故障点；输出正确而召回不足时，kernel 也补不回被删除的 key。 粗粒度路由的价值最终体现在「用便宜索引保留大部分重要概率质量，并把候选排成硬件可执行的块」。召回、布局和索引成本必须同时成立，少一项都只是纸面稀疏。 当数据领域、上下文长度或硬件变化时，这三项都应重新测量。旧配置可以作为起点，不能替代新的候选分布和执行证据。 这份记录也让后续优化保持可比：每次只改变一个路由变量，其余预算与基线不动，收益才有明确归因。
