# Quest：用 min/max 上界筛选 KV 页

长上下文 decode 每次只生成一个 token，却要在每一层读取历史所有 key 和 value。以 FP16 Llama-2-7B、32K 上下文为例，Quest 论文按 32 层、32 个 KV head、head dimension 128 计算出约 16 GB KV；论文在 RTX 4090 上的测量中，加载这些 KV 至少需要约 11 ms，并占单步推理时间的一半以上。点积规模已经很窄，同一批历史状态被每个新 query 重新从 HBM 读取，带宽等待因而占据主要时间。

[Quest](https://arxiv.org/abs/2406.10774)选择保留完整 KV，再按当前 query 动态挑页。它没有沿用「过去重要，所以以后也重要」的累计分数，而是给每个 KV 页维护一个很小的 key 包围盒：逐维最小值与最大值。当前 query 到来后，包围盒给出页内最大点积的上界；系统按这个上界取 Top-K 页，只加载候选页的完整 K/V 并执行 attention。完整 cache 仍在，所以这一步漏掉的页没有被永久删除，下一个 query 还可以重新选择。

- 上界筛选可以产生假阳性, 候选页内部的 QK、softmax 与 AV 仍按原定义计算.

## 1. 为什么重要性必须跟着 query 变化

### 1.1. 同一个历史 token 会突然变得重要

考虑 prompt 中出现过 `A is B. C is D.`，模型继续生成到 `A is`。在先前许多步里，`B` 的 attention 权重可能都很低；当前 query 表达对 `A` 的补全需求时，`B` 才突然成为高分位置。累计权重、最近窗口或一次性 prompt 压缩都可能在问题出现前把它判成低价值，而 query-aware 选择会在每一步重新估计候选。

论文用 LongChat-7B 的 attention map 展示了这种变化，并以稠密 attention 的 Top-10 token 为参照比较召回。H2O、TOVA 等 eviction 路径可能已删除未来才会变得关键的 KV；Quest 保留完整 cache，只决定当步读哪些页。两者即使使用相同 token budget，失败性质也不同：eviction 是状态不再存在，Quest 是当前候选没召回。

这一区分还能解释为什么历史 attention 分数很难充当未来价值。第 $t$ 步的权重由 $q_t$、历史 key 与当步 softmax 分母共同决定，累计量记录的是已经发生过的 query 分布。未来任务突然要求复述一个早期编号时，新的 $q_{t+r}$ 可能与那一页高度匹配；过去长期低分没有给出反证。Quest 每步重新扫描页摘要，付出的代价是持续索引开销，换来对这种相关性突变的响应。

### 1.2. 稀疏程度也随层变化

Quest 在 PG19 上以困惑度增加不超过 0.01 为约束测量各层可删除比例。论文报告前两层可利用的稀疏度低于 10%，后续多数层超过 90%，因此实验默认前两层使用完整 KV，仅在后续层应用 Quest。跳过两层来自论文两类模型与评测设置下的实测结果，换模型后需要重新测量，不能当作固定架构规则。

部署新 checkpoint 时应重新画每层预算曲线。若某层需要较大候选才能维持召回，直接使用稠密 attention 可能比运行摘要扫描和大 Top-K 更快。按层设置预算也优于全模型统一压缩率：前层保留传播所需的广覆盖，后层再使用更强的 query-aware 稀疏。

head 之间也会出现类似差异。某些 head 稳定读取局部标点、sink 或固定位置，另一些 head 才承担内容检索；把所有 head 的候选召回取平均，会让少数关键 head 的漏选被大量简单 head 稀释。更稳妥的诊断是先按 layer-head 画预算与 attention mass 曲线，再决定是否共享页集合。共享候选能减少地址分歧，代价是并集变大或个别 head 被迫接受别人的排序。

稀疏预算还会随生成阶段变化。问题刚进入上下文时，query 可能持续读取指令页与最近页；开始组织答案后，引用位置会移动到正文证据；生成格式化尾部时，局部页再次占主导。固定 K 的实现简单，但各步的实际需求不同。可变预算若由页分数间隔或累计上界决定，需要额外停止条件，并保证不同 batch 项仍能高效执行；否则节省的页会被控制流分歧抵消。

## 2. Min/max 上界从哪里来

### 2.1. 逐维区间给出点积上界

设页 $p$ 含 $S$ 个 key，单个 key 为 $k^{(r)}\in\mathbb{R}^{d_h}$，$r=1,\ldots,S$。对第 $j$ 个维度，页摘要保存

$$
m_{p,j}=\min_r k_j^{(r)},\qquad M_{p,j}=\max_r k_j^{(r)}. \tag{1}
$$

当前 query 为 $q\in\mathbb{R}^{d_h}$。任意页内 key 的第 $j$ 维贡献 $q_jk_j^{(r)}$ 都不会超过区间两个端点中的较大者：

$$
u_{p,j}(q)=\max\bigl(q_jm_{p,j},q_jM_{p,j}\bigr). \tag{2}
$$

当 $q_j\ge0$ 时，式 (2) 选择 $M_{p,j}$；当 $q_j<0$ 时选择 $m_{p,j}$。逐维相加得到页分数

$$
U_p(q)=\sum_{j=1}^{d_h}u_{p,j}(q). \tag{3}
$$

对页内任意 $r$，每个维度都有 $q_jk_j^{(r)}\le u_{p,j}(q)$，所以

$$
q^\top k^{(r)}\le U_p(q),\qquad
\max_r q^\top k^{(r)}\le U_p(q). \tag{4}
$$

式 (4) 是 Quest 选择器的数学依据。RoPE 已作用后的 key 与当前 query 进入同一坐标系，摘要必须对应 attention 实际使用的 key；若实现对 cache 中 key 采用不同旋转或反量化路径，索引与主 attention 的坐标约定也要同步。

softmax 不影响上界排序的第一步，因为指数函数对 logit 单调。页内最高未缩放点积的上界除以同一个 $\sqrt{d_h}$，仍是缩放后最高 logit 的上界。不过 attention 概率还依赖所有候选的分母，Quest 无法仅靠单页 min/max 得到某页最终概率质量的严格上界。它筛选「页内可能出现很大 logit」的页面，无法承诺这一页必然贡献多少输出。

### 2.2. 一个二维手算

取一页三个 key：

$$
k^{(1)}=(1,4),\qquad k^{(2)}=(3,-2),\qquad k^{(3)}=(-1,1).
$$

逐维最小值和最大值为 $m=(-1,-2)$、$M=(3,4)$。令 query 为 $q=(2,-1)$。第一维 $q_1>0$，取 $2\times3=6$；第二维 $q_2<0$，取 $(-1)\times(-2)=2$。页上界是

$$
U_p(q)=6+2=8. \tag{5}
$$

三个真实点积依次为 $-2$、$8$、$-3$，式 (5) 在这个例子中恰好等于页内最大值。换一组 key，$k^{(1)}=(3,4)$、$k^{(2)}=(-1,-2)$，摘要不变，真实点积变为 2 与 0，上界仍是 8。原因是第一维最大值 3 与第二维最小值 -2 来自不同 token；包围盒角点 $(3,-2)$ 并不存在。

Min/max 分数保证不低估页内最大点积，却不保证上界足够紧。页内各维极值来自不同 token 时会出现假阳性。Top-K 预算有限时，许多松上界页可能排在真正关键页之前，所以 Quest 的候选召回仍需通过实验测量，式 (4) 单独给不出召回保证。

高维空间会放大这项松弛。若 $d_h=128$，式 (3) 可以从 128 个不同 token 分别取得有利端点，最终分数对应一个页内从未出现过的合成向量。真实 key 在各维之间有相关结构，轴对齐包围盒没有保存这种相关性。减小 page size 会减少页内异质性；使用更复杂的摘要可以更紧，却会增加索引字节和评分算力。Quest 选择 min/max，正是把摘要扫描控制在简单逐维乘法与 reduction 上。

### 2.3. 从页上界到候选召回

设真实最关键 token 位于页 $p^*$。式 (4) 保证 $U_{p^*}$ 不低于该 token 的点积；然而另一些页的真实点积较小，上界却可能更大。只有当 $p^*$ 的上界进入前 K，关键 token 才会参与第二阶段 attention。page size 增大往往使包围盒更松，K 增大则提高召回并增加流量。

召回应按真实稠密 attention 做参照。对每层每 head，取真实 Top-R token，映射到物理页，再检查 Quest Top-K 页覆盖了多少。还要报告 attention mass recall，即候选页包含的稠密 softmax 权重总和。前者关心最高分 token，后者关心被删除概率质量；两项都高，任务仍可能因多步误差累积而下降，所以还需长程任务验证。

一个四页小例子可以看清「上界正确但召回失败」。设页 A 的真实最大 logit 为 10、上界为 10；页 B、C 的真实最大值只有 3 和 2，上界却分别为 14 和 12；页 D 的真实最大值为 1、上界为 4。若 $K=2$，排序会选 B、C，真正包含全局最高 logit 的 A 被排除。把预算提到 3 才召回 A。式 (4) 没有失效，问题来自假阳性消耗了有限名额。

这一例子也说明无法用「上界覆盖真实值」直接证明 exact top-k。若要获得严格召回，可以先按上界排序，再维护当前已读取页中的第 R 大真实 logit；只有尚未读取页的最高上界低于这个阈值时才停止。这样的 branch-and-bound 会给出更强保证，读取页数却变成数据相关量，最坏情况仍扫描并读取全部页。Quest 采用固定预算，选择了稳定执行时间与经验召回，而没有提供 exact top-k 证书。

候选 attention 会在选中集合 $C$ 内重新做 softmax。令稠密概率为 $p_j$，被排除位置的总概率质量为 $\epsilon=\sum_{j\notin C}p_j$，并假设 $\lVert v_j\rVert\le V_{max}$。稠密输出和候选输出分别为

$$
o=\sum_jp_jv_j,\qquad
o_C=\sum_{j\in C}\frac{p_j}{1-\epsilon}v_j. \tag{6}
$$

两者相减后，候选内权重放大带来的误差至多为 $\epsilon V_{max}$，删除集合的直接贡献也至多为 $\epsilon V_{max}$，因而

$$
\lVert o-o_C\rVert\le2\epsilon V_{max}. \tag{7}
$$

式 (7) 说明 attention mass recall 比单纯 Top-R token recall更接近输出误差：若候选覆盖了 99% 稠密概率质量，单层 value 混合有可解释的上界；但该界通常较松，也没有覆盖输出投影、残差和多层累积。Quest 的 min/max 排序直接逼近高 logit 页，最终仍应测 $\epsilon$，不能只数命中了几个最高分 token。

## 3. 索引怎样随 KV cache 更新

### 3.1. Prefill 建页与 Decode 追加

prefill 产生整段 prompt 的 K/V，并按 $S$ 个 token 一页写入 cache。每写入一个 key，就对对应页、layer、head 的 min/max 做逐维更新：

$$
M_{p,j}\leftarrow\max(M_{p,j},k_j),\qquad
m_{p,j}\leftarrow\min(m_{p,j},k_j). \tag{8}
$$

满页封口后摘要不再变化。decode 新 token 写入尾页时继续执行式 (8)；尾页满后分配新物理页，并用 $-\infty$、$+\infty$ 分别初始化 max 与 min。官方代码的页写入测试同时覆盖 prefill 和单 token decode，候选摘要按 head 与 feature dimension 保存，说明索引更新属于 cache append 路径，而非每次查询重新扫描页内 key。

摘要张量的逻辑 shape 可写成 $[L,P,H_{kv},2,d_h]$，其中 2 对应 min/max。batch 的页表再把每条请求的逻辑页映射到全局物理页池。实际实现可以按 layer 分配或复用工作区，但不能把不同 layer 的 key 极值合并，因为每层投影空间不同。页复制、prefix fork 或 beam search 共享物理 KV 时，摘要也应跟随物理页共享，避免复制一份已经封口的统计量。

更新式只需读取新 key 与当前页摘要，成本对上下文总长度为常数。摘要精度需要单独验证：若 KV 使用量化格式，min/max 可以在量化域维护，也可以反量化后维护；前者更省，量化尺度与零点会影响上界的保守性，后者增加转换和存储。论文的「与量化兼容」表示两种技术可以叠加，不代表任意量化索引都自动保持式 (4)。

尾页的有效长度需要单独处理。假设 page size 为 16，当前页只有 5 个有效 token，剩余 11 个槽位可能尚未初始化。min/max 只能由 5 个真实 key 更新，候选 attention 也必须携带 `last_page_len=5`；若填充值参与摘要或 softmax，会产生虚假的极值与非法 attention mass。官方页测试显式计算尾页长度，复现时应把长度为 1、15、16、17 的序列都纳入正确性用例。

### 3.2. 完整状态仍在，索引只是读取入口

Quest 不会因某一步未选择某页而删除物理 KV。下一步 query 改变后，全部页摘要重新参与排序。这个设计保住未来召回机会，也意味着峰值 cache 容量没有降低。若系统把冷页 offload 到 CPU，Quest 选中冷页后还要承担 PCIe 传输；此时页上界可充当预取入口，但论文 GPU 常驻结果不能直接当作分层存储延迟。

完整保留也让错误更容易定位。把 page budget 提高到总页数，Quest 应退化为完整读取，并与稠密分页 attention 在容差内一致；若此时结果仍不一致，问题落在页表、位置、数值精度或 kernel，而非候选算法。这个稠密回退是必要的调试路径，也能测出摘要与 Top-K 的纯额外开销。

prefix sharing 也需要区分物理页和逻辑页。多个请求可以引用同一前缀物理页，min/max 摘要随物理页共享；每条请求的 query 和候选 Top-K 不共享。页的引用计数决定何时释放，某条请求未选中该页不改变其他请求对它的所有权。

beam search 或 speculative decoding 会产生更多分支。多个 beam 在分叉前共享相同页与摘要，分叉后各自追加尾页；候选排序使用各 beam 的 query。speculative draft 一次提出多个 token 时，后续 query 依赖前面草稿 token，不能用第一个 query 的页集合替代整个验证块，除非验证 kernel 明确定义了逐位置候选。状态共享由 cache 管理，候选共享会改变 attention 近似，二者需要独立配置和验收。

## 4. HBM 流量与 block size

### 4.1. 读取比例逐项推导

令单个 key 或 value 向量占 $M$ bytes，上下文含 $L$ 个 token，每页 $S$ 个 token，共有 $P=L/S$ 页，选中 $K$ 页。稠密 attention 读取 K 与 V，流量近似为

$$
T_{dense}=2ML. \tag{9}
$$

Quest会读取每页的两条key摘要，即min与max：

$$
T_{index}=2MP=\frac{2ML}{S}. \tag{10}
$$

随后读取 $K$ 个候选页的完整 K/V：

$$
T_{selected}=2MKS. \tag{11}
$$

忽略 Top-K 索引与输出写回，Quest 相对稠密读取比例为

$$
\rho=\frac{T_{index}+T_{selected}}{T_{dense}}
=\frac{1}{S}+\frac{KS}{L}
=\frac{1}{S}+\frac{K}{P}. \tag{12}
$$

取 $L=65536$、$S=16$，token budget 为 4096，所以 $K=4096/16=256$ 页。式 (12) 得到 $1/16+4096/65536=1/8$，理想 KV 读取降低 8 倍。4096 表示 token budget，对应 256 页；选择 4096 页会读完整个 64K cache。

再落到字节。若单个 head 的 $d_h=128$ 且 KV 为 FP16，则一个 key 或 value 向量占 $M=256$ bytes。单层单个 KV head 的完整 64K K/V 读取是 $2\times256\times65536=32$ MiB；摘要读取是 2 MiB，256 个候选页再读 2 MiB，合计 4 MiB。层数和 head 数会同时放大两条路径，比例仍为 $1/8$。索引、页号和输出写回没有计入这 4 MiB，所以硬件计数应略高于公式值。

### 4.2. Page size 的两端代价

式 (12) 似乎鼓励增大 $S$，因为索引项 $1/S$ 会下降；候选 token budget $B=KS$ 固定时，第二项 $B/L$ 不变。但较大的页把更多 key 放进同一个轴对齐包围盒，上界更松，有限 K 下候选召回可能下降。若为了恢复召回而提高 $B$，第二项随之反弹。

小页让摘要更紧，索引容量和扫描量按 $1/S$ 增长。Top-K 项数也增多，page table 更长，kernel 处理更多离散块。物理 page size 还要与 attention tile、cache line 和线程块对齐；逻辑页 12 token 若 kernel 按 16 token tile 读取，公式中的 $S=12$ 会低估实际字节。评测应同时报告逻辑 page size、物理 tile 和有效末页长度。

可以把 page size 与 token budget 做二维扫描。固定 $B=2048$ 时，$S=8,16,32$ 分别对应 $K=256,128,64$ 页；索引比例依次是 $1/8,1/16,1/32$，候选比例都为 $B/L$。若质量随 $S$ 增大下降，原因主要落在上界松弛与块内混入，而非候选 token 数改变。若速度没有随索引比例下降，则 Top-K、页表或 kernel tile 已成为瓶颈。

### 4.3. 为什么 8 倍流量不等于 8 倍端到端加速

论文报告最高 7.03 倍 self-attention 加速与 2.23 倍端到端推理加速，两个数字对应不同范围。模型每步还有 QKV 投影、输出投影、FFN、归一化、采样、调度和 kernel 启动；Quest 又新增摘要扫描与 Top-K。只有 attention 占比较高、上下文足够长时，流量下降才接近子模块速度收益。

论文在 32K、2048 token budget 下报告 FP16 权重端到端约 1.74 倍，4-bit AWQ 权重约 2.23 倍。权重量化降低了其他权重读取，KV attention 在总时间中的占比变大，所以同一 KV 优化表现出更高的整体收益。换硬件、batch 或模型宽度后，占比会改变，不能把 2.23 倍当作固定常数。

可以用 Amdahl 关系检查数字是否合理。假设稠密 decode 中 attention 占 60%，Quest 把 attention 时间降到原来的 $1/7.03$，其余 40% 不变，则整体时间比例约为

$$
0.4+\frac{0.6}{7.03}=0.485, \tag{13}
$$

对应约 2.06 倍加速。若 attention 只占 40%，整体约为 $1/(0.6+0.4/7.03)=1.52$ 倍。权重量化降低非 attention 时间后，attention 占比上升，2.23 倍便更容易出现。这项手算不复刻论文具体 breakdown，只用于核对子模块与端到端数字的量级关系。

多 batch 时还要重算比例。KV 读取可被更多并发隐藏，FFN 的矩阵乘法利用率也会提高，attention 与非 attention 的占比一起变化。单请求延迟最受带宽影响，不等于高吞吐服务一定获得相同倍数。报告应同时给出 batch size、并发序列长度和每步 active token 数。

## 5. 分页 KV、批处理与 GQA

### 5.1. 候选页直接进入 attention

较差的实现会先把 Top-K 页 gather 到新的连续张量，再调用普通 attention。这样至少多出一次候选 KV 的读写和临时 buffer，且不同请求的候选大小会制造分配开销。Quest 的官方路径基于 FlashInfer 的分页 attention：Top-K 返回页编号，attention kernel 按编号从原 cache 读取 K/V，未选页不进入主数据流。

正确性测试需要对照完整 KV 加显式页 mask 的参考 attention 与直接 sparse-load 的分页 kernel。输出误差之外还需检查尾页、候选重复、页编号乱序和 batch 中零长度/短长度请求。若 Top-K 含当前未写满页，kernel 只能读取有效 token，填充槽不能进入 softmax。

多页 softmax 要使用同一行的全局最大值与归一化和。每个候选页可以先求局部最大值，再用 online softmax 规则合并；不能对每页单独 softmax 后平均，因为那会让每页总概率都变成 1。候选页的物理顺序不应改变输出，随机打乱页号后仍应与同一 mask 的参考实现一致。

### 5.2. Continuous batching 的 ragged 形状

设 batch 中请求 $r$ 有 $P_r$ 页、预算 $K_r$。摘要扫描总量是 $\sum_rP_r$，候选读取总量是 $\sum_rK_rS$。把所有请求 padding 到 $P_{max}$ 或 $K_{max}$ 会引入无效工作，尤其当长短请求混在同一轮。分页索引应用 indptr 描述每条请求的区间，调度器则可按页数或预算分桶。

Top-K 的尾延迟也不能只看平均 5–10 微秒。batch 增大后，需要同时处理 layer、head 与 request 三个维度的分数；候选数量不同会造成线程块工作不均。端到端基准应记录 p50/p95 每 token 延迟，并说明摘要扫描和 Top-K 是否与其他层重叠。

例如两个请求分别有 4096 页与 256 页，若统一 padding 到 4096 页，短请求的摘要扫描会产生 3840 个空项；若候选预算分别为 256 页与 32 页，又统一调用固定 256 页 kernel，短请求会为 224 页填充买单。ragged indptr 能消除逻辑空项，GPU 是否仍以最大形状分配线程块则要从 kernel profile 判断。

### 5.3. MHA、GQA 与 head 共享

MHA 中每个 query head 有自己的 key head，页摘要与页分数自然按 head 独立计算。GQA 让一组 query head 共享同一 key/value head，但组内 query 不同，最相关页也可能不同。可以为每个 query head 单独选页，再让共享 KV head 读取候选并集；也可以先聚合组内页分数，使用统一候选。前者召回更细，后者访存更规则。

Quest 公开 kernel 覆盖 MHA，尚未实现 GQA。迁移到 GQA 模型时必须定义组内合并规则、候选预算按 query head 还是 KV head 计数，并重新测试实际 HBM 字节。若组内候选并集接近完整页集，GQA 的共享关系会削弱读取稀疏收益。

取 8 个 query head 共享 1 个 KV head。若每个 query head 独立选择 64 页，最坏并集可达 512 页；统一选 64 页只读一次，却可能漏掉某个 head 独有的相关页。折中办法包括按组聚合上界取较大值、给每个 head 一部分私有预算再合并，或让相近 query 共享候选。无论采用哪条路径，attention 输出仍按 query head 独立计算，页集合共享不能顺手写成注意力权重共享。

若用组内最大页分数 $U_{g,p}=\max_{h\in g}U_{h,p}$，任一 head 高估的页都会进入共享排序，假阳性会在 head 轴上再次累积；若用均值，少数 head 的强相关页可能被其他 head 稀释。候选并集保持每个 head 的原排序信息，但读页数上限随组大小增长。GQA 迁移的核心取舍由此落在同一个问题上：共享 KV 节省存储，而 query 仍保留多样性，页选择必须决定这份多样性占多少带宽。

Context Parallel 会把历史位置分散到多张卡，页摘要也随 KV 分片。每张卡可以用本地 query 计算页上界并取局部候选，但「每卡 Top-K」会让总预算随设备数增长；若每卡只取 $K/N$，真实前 K 又可能集中在一张卡。严格的全局 Top-K 需要交换页分数或局部候选，再广播最终页号。通信的数据量远小于搬运完整 KV，却会进入每个 decode step 的关键路径。报告多卡收益时，应把这次 collective 与远程页读取计入，不能只测单卡候选 attention。

Tensor Parallel 若按 head 切分，设备各自拥有部分 KV head，可以独立选择并计算局部 attention，随后在输出投影处合并；此时各卡页集合不同是合法的。若按 hidden dimension 切分同一个 head，单卡只掌握点积的一部分，局部 min/max 上界也只是部分和；得到全页分数需要跨卡归约。分片方式决定索引放在哪里，也决定 Quest 能否同时减少本地 HBM 与互连流量。

## 6. 失败模式与可复算评测

### 6.1. 上界松、预算小与多证据聚合

第一类失败来自松上界。页内 key 分布跨越很大范围时，min/max 组合出许多不存在的角点，假阳性页挤占 Top-K。第二类失败来自预算不足：单个 passkey 只需召回一个页，多文档总结、代码依赖和多跳问答可能同时需要大量页，固定 1K token budget 会截断证据集合。第三类失败来自层差异，前层或特定 head 本就不稀疏，强行使用统一比例会破坏信息传播。

还有 softmax 重归一化。即使候选覆盖真实最高分 token，删除大量低分项也会改变分母；这些项单个权重小，总和却可能不小。attention mass recall 比 Top-R token recall更能暴露这个问题。需要时可扩大预算、为前层回退稠密，或给局部窗口与 sink 保留固定页，再把剩余预算用于 query-aware 候选。

固定保留最近窗口和 sink 还能降低最坏行为。设总预算为 2048 token，可先留 512 个最近 token 与 4 个 sink，再用剩余 1532 个名额对应的整页预算做 Quest。这样局部语言连续性不完全依赖 min/max 排序，远距页仍由当前 query 决定。代价是动态预算变小，组合策略必须在相同总读取量下与纯 Quest 比较。

多证据任务还会出现「每页都不够高，但合起来才有用」的情况。十个页各自包含一条约束，任何单页最高 logit 都排不到前 K，模型却需要同时聚合十条约束才能作答。Min/max 排序按单页最大点积估分，没有表示页与页之间的互补关系。扩大预算、分阶段生成或让后续层重新检索可以缓解，却无法从单步页分数中提前证明完整性。因而 passkey 的高召回只能证明单证据检索能力，不能代替多页组合评测。

位置编码外推也会改变页分数分布。长到训练范围之外时，RoPE 缩放、数值精度和 key 方向都会影响 min/max 松弛；Quest 只能从现有 key 中筛选，无法修复基础模型在超长位置本来就失真的表示。评测应先确认 full attention 在目标长度上的质量，再计算稀疏差额。把基础模型的长上下文失败归到候选漏选，会得到错误的预算结论。

同一组实验还应保留不同随机种子与不同文档顺序，检查候选是否只对固定位置或固定提示格式有效。

### 6.2. 质量实验怎样避免平均值遮住漏选

论文评测包含 PG19 困惑度、10K/100K passkey 与六项 LongBench，并让问题或指令按 token 进入 decode，以暴露未来 query 改变后 eviction 无法恢复的问题。复现时还应改变证据深度、页内位置与相似干扰项。若关键数字恰好落在页边界，只测单一位置会高估或低估某个 page size。

PG19 主要检查连续语言建模，局部依赖占比较高。论文用 4096 token budget 测 32K 文本，Quest 的困惑度接近 full cache；这能说明截断后没有明显破坏常规预测，无法单独证明稀有远距事实一定召回。passkey 正好补上这一缺口：10K LongChat 在 64 token budget、100K Yarn-Llama-2 在 1024 token budget 时，论文表格中的 Quest 接近或达到满分，而几种提前淘汰方法在问题到来前已经丢掉答案页。

LongBench 的实验把材料先 prefill，再把问题与指令逐 token 喂入，以模拟 query 在 decode 中逐渐变化。论文在 NarrativeQA、HotpotQA、Qasper、TriviaQA、GovReport 与 MultiFieldQA 上比较多个预算，并报告 Quest 在约 1K token budget 时可接近 full cache。这个设置比把问题一并塞进 prefill 更能检验 query-aware 选择，因为选择器必须随着问题 token 更新候选。

这些结果仍受基础模型、prompt 拆分与任务长度约束。LongChat-7B-v1.5-32K 和 Yarn-Llama-2-7B-128K 的层/head 分布不代表新模型；passkey 只需找一个短答案，也比多证据综合容易。复现新模型时应保留论文任务作为对照，再增加模型目标场景，尤其是需要同时引用多页的总结、代码修改和长对话约束。

一组可复算的实验至少报告：每层与每 head 的候选页召回、attention mass recall、任务准确率、预算、page size、前几层是否稠密、模型的 KV head 结构。对相同请求同时运行 full attention，才能区分基础模型本来答错与 Quest 漏选。若 full attention 也失败，不能把错误归到稀疏选择。

还应加入「相关性反转」样本：prompt 前部放两个相似实体，后文先反复讨论实体 A，使 A 的历史权重占优，生成末尾再突然询问实体 B 的编号。累计重要性容易偏向 A，Quest 应随当前 query 转向 B 所在页。把 B 放在页首、页中和页尾，可以同时检查 page boundary 与 min/max 召回。

消融需要分别关闭三件事。把 query-aware 分数换成固定页排序，可以测当前 query 的贡献；把 min/max 上界换成读取完整 key 后的 oracle 页分数，可以测摘要松弛；保留候选不变而换回普通 gather，可以测专用分页 kernel 的贡献。三项一起改变时，质量或速度回退无法归因。

### 6.3. 系统实验必须核对真实字节

kernel 侧分别测摘要更新、criticality estimation、Top-K 与候选 attention；端到端再加入模型其余部分。长度扫描应覆盖索引开销大于收益的短上下文交叉点，以及预算固定后 Quest 增长速度变慢的长上下文区间。batch、page size、token budget 和量化格式都要保持明确。

性能计数器应验证式 (12)：摘要扫描接近多少字节，候选 K/V 实际读了多少，是否存在 gather 临时量，未选页有没有被通用 kernel 读取。Quest 依靠减少 KV 搬运获得收益，仅在逻辑上把 attention 矩阵标成稀疏还不够。若 HBM 流量不降，候选召回再漂亮也不会得到论文所示的 decode 加速。

最终报告最好给出一张长度扫描图：横轴从 2K 到模型上限，纵轴同时画 full attention、摘要扫描、Top-K 和候选 attention 的时间。短上下文区域可能由固定开销主导，超过某个交叉点后 full attention 随 $L$ 增长，候选 attention 主要受固定 budget 控制，摘要扫描按 $L/S$ 缓慢增长。只有这条曲线能说明 Quest 在真实流量长度分布中覆盖多少请求，而单个 32K 点无法回答部署收益。

官方仓库给出的 kernel 基准覆盖 `page_budget` 从 64 到 512，并提供 batch decode、单元测试与 PyTorch 参考结果；端到端脚本基于 LongChat-7B-v1.5-32K 和 Yarn-Llama-2-7B-128K。复现时应保存 commit、CUDA、GPU 与 FlashInfer 版本，因为分页接口和 kernel 调度会变化。结果若只剩算法脚本而没有对应 CUDA 路径，只能证明候选逻辑，不能证明系统加速。

上线监控还要区分选择失败与服务退化。候选页召回需要稠密参考，无法对每个生产 token 都计算；可以抽样请求或在离线回放中计算。在线则记录摘要扫描、Top-K、候选 attention 的时间与实际页数，监测预算是否因回退频繁膨胀。质量报警出现后，用保存的请求在 full attention 下重放，确认问题是否随恢复全部页而消失。

## 7. 页摘要、量化与缓存生命周期

### 7.1. 未满页需要增量更新

对每个 KV head和维度, Quest页摘要保存当前页的最小值与最大值. 新 key $k_t$ 进入未满页 $p$ 时更新:

$$
m_{p,r}\leftarrow\min(m_{p,r},k_{t,r}),\qquad
M_{p,r}\leftarrow\max(M_{p,r},k_{t,r}). \tag{13}
$$

页第一次写入时令 $m=M=k_t$. 页填满后摘要变为只读, 可以随 prefix cache共享. 当前尾页继续追加, 多个会话分支不能共同修改同一摘要; fork时要么复制尾页, 要么使用copy-on-write. 只复制 K/V却让两个分支共享可变 min/max, 会让一个请求的候选受另一个请求影响.

Rollback也要恢复摘要. 已填满并整体回滚的页可以直接移除; 回滚落在尾页内部时, 仅靠当前 min/max无法删除被撤销 token的贡献. 若被撤销 key恰好提供某维极值, 摘要会继续覆盖不存在的点. 解决办法是重新扫描尾页有效 key生成摘要, 或为 speculative token保留临时摘要, 接受后再合并. 页面较小时重扫通常直接可靠.

### 7.2. KV量化会改变上界含义

若 attention实际读取量化后重构的 key $\hat k$, 页摘要可以基于原始 $k$ 或重构值 $\hat k$. 基于 $\hat k$ 时, 式 (13)对实际点积保持区间上界; 基于原始值时, 量化误差可能让重构值落到区间外. 可以给每维区间扩张误差界 $\epsilon_r$:

$$
[m_{p,r}-\epsilon_r,\ M_{p,r}+\epsilon_r]. \tag{14}
$$

扩张保证安全, 上界会更松, 假阳性页增加. 每页/每通道 scale越粗, $\epsilon_r$越大. 另一种做法是在写入量化 cache后, 直接从量化码与scale更新重构区间, 让selector与主 attention使用完全相同的 key语义.

Value量化不影响页选择分数, 会影响候选 attention输出. 消融时分别恢复 K和V精度: 候选集合变化来自 K摘要与打分, 候选不变而输出改善来自主 QK或V重构. 将二者一起切换只能看到总质量, 无法判断应把更高bit预算给哪一侧.

### 7.3. 摘要压缩本身有代价

每页若保存 min和max, 摘要元素数为原 K cache的 $2/S$, $S$ 是页内token数. page size 16时约为 K元素的12.5%, page size 64时约3.125%, 未计scale与对齐. 摘要通常比完整KV小很多, 在大量层和并发请求下仍是需要核算的常驻状态.

摘要dtype也影响扫描. FP16 min/max稳定但字节较多; FP8摘要减少带宽, 需要保持区间外包. 普通舍入可能把最小值向上或最大值向下, 上界不再严格. 若要保守, min采用向负无穷方向量化, max向正无穷方向量化, 或额外扩大一个量化步长. 保守量化增加假阳性, 不会漏掉因摘要收缩造成的候选.

摘要布局应按 criticality kernel的读取顺序排列. 若一个 query head连续扫描所有页, 按 head-page-dim布局容易合并; GQA若组内 query heads共享 KV head, 同一摘要会被多次读取, 留在L2的机会增加. 布局转换不能在每个decode step临时进行, 应在页写入时一次形成.

### 7.4. Prefix复用与页表映射

Quest selector返回逻辑页号, PagedAttention通过block table映射到物理页. Prefix cache让多个请求的逻辑页指向同一物理页, 摘要也应绑定物理页内容, 避免为每个请求重复保存. 当前请求的候选表仍是query相关状态, 不能随prefix直接共享.

页面迁移或offload时, 摘要可留在GPU帮助先选页, 选中后再把完整KV从主机或远端搬回. 这样才真正减少链路流量. 若摘要随KV一起offload, 每步为了选页先搬摘要仍可行, 延迟取决于摘要大小和链路; 若先搬全部KV再计算criticality, Quest已经失去主要价值.

物理页回收必须同时释放摘要. 复用槽位写入新请求前先初始化min/max, 否则旧极值会让新页上界异常高, 长期占据候选. 单元测试应让同一物理槽经历分配、填满、释放、再分配, 并与新分配页的摘要逐维比较.

这项检查也应覆盖实际量化页.

## 8. 页上界可以用凸几何重新理解

### 8.1. Min/max摘要描述轴对齐包围盒

页内keys组成有限集合 $K_p=\{k^{(1)},\ldots,k^{(S)}\}$. Min/max摘要定义轴对齐盒

$$
B_p=[m_{p,1},M_{p,1}]\times\cdots\times[m_{p,d},M_{p,d}],
$$

并满足 $K_p\subseteq B_p$. 对query $q$, 页内最大点积是集合的support function

$$
h_{K_p}(q)=\max_{k\in K_p}q^\top k,
$$

Quest计算的上界正是盒子的support function $h_{B_p}(q)$. 集合包含关系保证 $h_{K_p}(q)\le h_{B_p}(q)$, 对应前文逐维证明.

这种表达揭示了松弛来源. $B_p$包含所有逐维极值组合, 其中大多数角点不属于真实keys的凸包. Query方向恰好朝向不存在的角点时, $h_{B_p}$显著高估. Page size增大、页内语义更混杂或维度相关性更强, 盒子和真实凸包之间的空隙通常更大.

严格说, 最大线性函数在集合与其凸包上相同, 因而最紧凸上界是 $\operatorname{conv}(K_p)$. 保存完整凸包在高维中不可行, min/max用 $2d$ 个数换取极低扫描成本. Quest的设计点由此很清楚: 它选择一个便于增量维护和GPU向量化的保守外包, 接受由此产生的假阳性.

### 8.2. 上界松弛可以逐页量化

给定query $q$, 定义页松弛

$$
g_p(q)=U_p(q)-\max_{k\in K_p}q^\top k\ge0.
$$

离线用full keys可计算 $g_p$. 按page size、层、head和query类型统计其分布, 能直接看到假阳性来自哪里. 只测候选召回无法区分“上界普遍松”与“预算恰好太小”; 松弛分布把摘要质量单独拿出来.

还可观察排序后悔. 设Quest选中的第K个页上界阈值为 $\tau_U$, 真实页最大值排名阈值为 $\tau_s$. 被错误选中的页通常具有大 $g_p$, 被漏页则真实分数高而上界排序受其他假阳性挤压. 将二者配对, 可以估计增加预算需要吞下多少假阳性.

页松弛并不等同于输出误差. 一个页真实最大点积高, 其softmax质量仍受其他keys与value影响; 某些大松弛页即使被选中, 只增加带宽而不伤质量. 因此 $g_p$用于诊断索引, attention mass与任务分用于验证模型影响.

### 8.3. 旋转坐标会改变盒子, 不改变真实点积

对任意正交矩阵 $R$, 有 $(Rq)^\top(Rk)=q^\top k$. 真实attention logits不变, 轴对齐min/max盒却依赖坐标系. 某个旋转可能让页内keys更接近轴对齐、缩小包围盒; 另一个旋转会把相关结构摊到许多维度, 上界更松.

这说明Quest摘要会随坐标旋转而变化. RoPE本身按位置对通道做旋转, cache保存旋转前还是旋转后keys会影响摘要定义; 主attention在哪个坐标系计算点积, selector就必须在同一坐标系给出上界. 任意额外旋转都要同时施加到query与keys.

理论上可学习或选择改善盒子紧度的全局正交变换, 但它会增加Q/K变换成本、影响增量cache和量化. 若只为了selector使用低维旋转投影, 得到的分数通常不再是完整点积的严格上界, 需要重新评估漏召回. Quest原方法的优势在于直接利用现有key坐标, 不增加训练.

### 8.4. 多盒摘要能在字节与紧度之间插值

将一页keys聚成 $c$ 个子组, 每组保存min/max, 页分数取各子盒上界的最大值. 当 $c=1$ 时回到Quest, 当每个key一组时上界等于真实页最大值, 摘要大小也接近完整K. 中间值构成连续的索引精度—带宽交换.

子组若按token连续切分, 更新和布局简单, 实质上接近减小page size; 按key聚类可以更紧, 却需要在线分配与多个中心. 固定cache页仍可包含多个逻辑摘要块, attention读取时再合并同一物理页. 这样摘要粒度和内存页粒度无需完全相同.

比较多盒方案时保持候选token读取量一致. 一个物理页的任一子盒入选后, kernel可能仍读取整页; 多个子盒命中同页要去重. 摘要召回提高若没有降低物理页数, 系统收益不会同步增加.

## 9. 固定Top-K之外的停止规则

### 9.1. 分数间隔可以提示当前query难度

排序后的页上界记为 $U_{(1)}\ge\cdots\ge U_{(P)}$. 固定K让所有query读取相同页数, 无视分数是否集中. 若 $U_{(K)}-U_{(K+1)}$ 很大, 当前边界相对清晰; 间隔很小表示许多页难以区分, 增加预算可能更有价值.

上界间隔没有直接质量保证. 两个页上界都很松时, 大间隔也可能是假象; 小间隔页的真实分数可能都很低. 它适合作为动态预算特征, 需要在开发集上校准 $P(\text{覆盖不足}\mid\text{gap})$, 再在独立测试集验证.

动态K会造成ragged工作量. 平均读取下降并不保证P99下降, 少数困难query可能接近full. 报告平均、P95、最大K和fallback比例, 同时检查batch调度能否处理行长差异.

### 9.2. Branch-and-bound可以给exact top-R证书

页上界允许一种严格搜索. 先按 $U_p$ 从高到低读取页, 维护已见真实token logits的第R大值 $\tau_R$. 当下一个未读页的上界 $U_{next}<\tau_R$ 时, 余下所有页都不可能包含全局Top-R token, 搜索可以停止.

这个过程保证exact token top-R, 但读取量数据相关. 上界很松时几乎全部页都要打开; 上界紧、真实高分突出时很早停止. 它还需要在读取页后计算真实logits并动态更新阈值, 调度比固定Top-K更复杂.

Exact top-R也没有保证覆盖全部softmax质量. 大量略低于第R名的tokens仍可贡献可观分母. 若目标是概率质量, 可以结合未读页上界估计指数质量上限, 但仅知每页最大值时, 最保守界还要乘页内token数, 常常很松.

### 9.3. 概率质量停止需要控制未读分母

设已读集合的log-sum-exp为 $Z_C=\sum_{j\in C}e^{s_j}$, 未读页 $p$ 含 $S_p$ 个token且每个logit不超过 $U_p$. 未读指数质量满足

$$
Z_{\bar C}\le\sum_{p\notin C}S_pe^{U_p}.
$$

因此被删除概率质量上界为

$$
\epsilon\le
\frac{\sum_{p\notin C}S_pe^{U_p}}
{Z_C+\sum_{p\notin C}S_pe^{U_p}}.
$$

若该上界低于目标容差, 可停止读取. 公式严格, 但页上界松且乘以 $S_p$ 后常接近1. 它更适合解释为什么单纯min/max难给强概率证书, 也可用于识别少数非常容易的query.

计算 $Z_C$ 需要实际读取候选并执行QK, 形成多轮搜索. 每轮增加kernel launch和同步, 可能抵消少读页的收益. 实现可批量读取若干页再检查, 在证书紧度与调度开销之间折中.

### 9.4. 局部与sink保底改变预算分配

实际生成通常希望始终保留最近窗口与少量sink页, 剩余预算交给Quest. 总候选集合为

$$
C=C_{local}\cup C_{sink}\cup C_{quest}.
$$

三者可能重叠, 实际页数要在并集后计算. 固定总预算时, local越大, query-aware远距名额越少; 长答案局部连贯性与远端证据召回形成直接交换.

保底集合还能降低Quest上界错误的后果. 当前query常依赖最近tokens, 无需让它们与数千远端页竞争; sink负责模型长期形成的固定attention模式. 评估纯Quest与混合策略时, 保持最终物理页数相同, 才能判断质量来自结构先验还是更多读取.

不同层可使用不同分配. 前层较稠密时扩大local或直接full, 中后层让Quest承担更多远距选择. 层预算表比全模型统一K更接近论文观察, 也让系统实现需要支持ragged per-layer page counts.

## 10. 两阶段选择会产生哪些误差

### 10.1. 假阳性只耗成本, 假阴性会改模型函数

页上界高但真实logit低的假阳性被读入后, 第二阶段精确attention会给它合理的小权重, 主要代价是带宽与计算. 真实重要页未进入Top-K的假阴性则永久缺席当步softmax, 同时改变分子、分母和输出.

因此selector的precision与recall并不同价. 在固定预算下, precision低会通过名额竞争间接增加假阴性; 预算足够时, 多读假阳性仍可保持质量. 调参应优先守住重要页recall和attention mass, 再优化precision降低成本.

页级标签也有歧义. 一页含一个高分token和许多无关token时, 页是正例, token precision却低. 比较不同page size时同时报页召回、token质量覆盖与物理读取量, 不能只用页分类指标.

### 10.2. 重归一化会放大候选内权重

若候选覆盖稠密概率质量 $1-\epsilon$, 候选softmax把每个保留位置概率除以 $1-\epsilon$. 即使漏掉的values彼此抵消, 保留位置也被统一放大. 当 $epsilon$ 在层间反复出现, 残差路径会把偏差传播到后续query和keys.

单层输出界提供最坏情况, 实际误差取决于value方向. 可以直接记录full与Quest输出的余弦、相对L2和下游logits KL, 按层定位偏差何时增长. 只看最终文本会漏掉尚未翻转token的累积差异.

高attention mass recall也不保证任务正确. 被漏掉的极小概率token可能携带对后层关键的独特信息; 反过来, 较大概率集中在冗余局部token上. Mass是接近数值输出的代理, 任务仍是最终证据.

### 10.3. 每步近似会改变后续query

第t步Quest误差改变hidden state和生成token, 第t+1步的query因此不同. 即使在教师强制token下每步候选召回很高, 自由生成中早期一个token分叉会让后续路径完全变化. 这叫closed-loop累积, 不能从独立单步误差直接相加得到.

评估可分teacher-forced与free-running. 前者固定真实或Full生成序列, 对齐每步query附近的表示, 适合诊断selector与kernel; 后者测完整应用质量. 两者差距大时, 早期小logit变化触发了生成分叉.

配对自由生成要固定采样设置. Greedy减少随机性, 仍可能因近似改变argmax. 使用采样时, 相同随机种子无法保证后续随机数对应相同条件分布, 应多次运行或比较目标答案似然.

### 10.4. 多层候选交互没有单层上界那么简单

每层有自己的keys与query, 页上界也不同. 某证据页在早层未被选中, 信息可能通过局部token或其他层已传播; 某页在一层命中也不保证后续保留. 单层recall与端到端成功之间存在模型内部路径.

可记录证据页首次命中层、命中层数和相邻层候选Jaccard. 若证据直到输出附近的层才被读取, 它可能来不及参与复杂组合; 早层命中后长期不再读取则依赖hidden state保持. 将这些统计与任务失败配对, 能分辨持续访问需求.

Oracle实验也应按层定义. 所有层强制加入证据给出较宽上界; 只在某一层或层组注入可以定位哪里需要访问. Oracle页会增加预算, 结果解释要同时报告新增读取.

## 11. 摘要维护与量化的严格边界

### 11.1. 区间量化必须向外舍入

若min/max摘要压到低精度, 普通round-to-nearest可能让min增大、max减小, 原key落在量化区间之外. 对任意 $q$ 的上界性质随之失效. 保守量化要求

$$
\hat m_{p,j}\le m_{p,j},\qquad
\hat M_{p,j}\ge M_{p,j}.
$$

可以对min向负无穷舍入、max向正无穷舍入, 或在重构端扩张一个已知误差界. 外扩只增加假阳性, 不会因摘要收缩漏掉真实最大值.

Per-page scale若由当前极值决定, 尾页追加token后scale可能改变, 已存量化摘要需要重新编码. 使用固定per-channel scale更新简单, 精度可能较差. 摘要格式应与更新频率一起设计.

测试随机生成keys与queries, 比较量化摘要 $\hat U_p(q)$ 是否始终不低于重构keys的真实最大点积. 只测平均误差无法证明区间安全, 需要直接统计违反次数与最大负裕量.

### 11.2. K量化与摘要量化有两层误差

主attention实际使用重构key $\tilde k$, selector摘要可能来自原始key $k$、重构key或另一个量化近似. 最容易保持一致的是先确定主cache语义, 再对 $\tilde k$ 建保守区间. 若摘要来自原始 $k$, 它对 $q^\top\tilde k$ 未必上界.

可以把重构误差写成 $\tilde k=k+e$, 若每维 $|e_j|\le\epsilon_j$, 原区间外扩 $\epsilon_j$ 后仍包含重构值. Query相关点积误差界为 $\sum_j|q_j|\epsilon_j$. 这个额外项随query范数变化, 统一最坏界可能很松.

消融时分三条路径: full精度K/V与摘要; 量化K/V但高精度保守摘要; K/V和摘要都量化. 第一到第二的差异是cache量化, 第二到第三的候选变化是摘要压缩. 这样能决定质量预算应该优先给K、V还是索引.

### 11.3. 回滚和分支需要可逆状态策略

Min/max是单调聚合, 插入容易, 删除无法从两个极值恢复. Speculative decode拒绝草稿、beam pruning或编辑式生成都会撤销尾部token. 若回滚落在未满页, 必须重扫剩余keys或保留更丰富统计.

页很小时重扫成本有限, 且回滚只影响尾页. 可以把已提交页与临时页分开: 草稿写入临时K/V和摘要, 验证接受后再并入正式页; 拒绝时直接丢弃. 接受跨越页边界时, 需要正确封口并发布新物理页.

Copy-on-write保证会话分支不会共享可变尾页. 封口页及其摘要可安全共享; 第一个分叉写入发生时复制有效tokens与摘要, 随后各自更新. 引用计数与页回收必须覆盖摘要对象.

### 11.4. 摘要一致性需要独立校验

缓存管理bug可能让K/V正确而摘要过期. 可以在抽样请求上从物理页重算min/max, 与增量摘要逐维比较. 校验覆盖prefill、逐token追加、页封口、fork、rollback、释放和槽位复用.

摘要错误的表现不总是质量下降. 旧极值过宽会让页长期成为假阳性, 只拖慢系统; 区间收缩才可能漏选. 因而在线可监控候选页重复率、上界分布和预算命中, 离线重放再检查严格包含.

版本升级改变KV布局、RoPE或量化时, 摘要不能从旧cache直接复用, 除非坐标与数值语义完全兼容. Cache版本要包含模型、layer布局、位置处理与量化格式.

## 12. 服务调度决定收益能否兑现

### 12.1. Criticality扫描本身是一次带宽kernel

每步每层都要读取所有页的min/max摘要并与query计算上界. 它的流量随 $P=L/S$ 增长, 计算约为 $O(Pd_h)$. 当token budget很小, 摘要扫描可能占Quest路径的大部分; 当上下文短时, 直接full读取反而更快.

扫描与Top-K可以融合或分阶段. 融合减少中间分数写回, top-k需要跨tile归约; 分阶段实现简单, 会把 $P$ 个分数写入HBM再读. 具体选择取决于页数、batch和候选K.

性能表应单列criticality、selection和sparse attention. 若只报合并kernel, 无法知道page size变化改善了摘要流量还是候选attention. 交叉点由这三项与dense路径共同决定.

### 12.2. Top-K排序无需完整全排序

目标只取K个最大页, 可以用分块局部top-k再归并, 无需排序全部P项. K较小且固定时, 堆、bitonic或选择网络各有适用范围; P和K动态时, 通用算法可能产生额外workspace.

稳定排序通常不影响集合语义, 分数相等时tie-breaking会改变候选. 对完全相同上界页, 固定按页号处理有利于复现; 随机tie可能增加运行方差. 如果临界同分页很多, 质量也说明摘要分辨率不足.

Top-K结果应去重且检查范围. GQA合并多个query-head候选时, 先各自top-k再取并集会保留逐头需求, 先聚合分数再top-k则直接优化组级预算. 性能和质量对照要明确哪一步发生归并.

### 12.3. Ragged预算需要工作窃取或分桶

动态K、不同长度和不同head候选并集会让每行页数变化. 静态grid按最大行长分配时, 短行空转; 每行一个CTA时, 长行拖尾. 可以按K分桶、拆长行或用persistent queue分配任务.

调度重排不能改变逻辑位置. Page ID可按物理地址排序改善coalescing, score_mod和RoPE仍使用逻辑token位置. 在线softmax允许任意块遍历顺序, 有限精度会有小差异, 应在容差内与固定顺序reference比较.

服务batching还要考虑请求公平. 一个近full预算的困难请求可能拖住同batch的短请求. 调度器可按长度和预算分池, 代价是降低batch聚合机会. P99而非平均吞吐决定是否值得分池.

### 12.4. CUDA Graph与缓存键需要容量分档

CUDA Graph希望地址、grid和workspace稳定, Quest候选数与batch形状却动态. 可以按最大页数、K和batch建立容量档, 运行时用有效计数屏蔽空任务. 档太粗会浪费, 档太细会增加图与编译缓存.

缓存键至少包含模型层结构、dtype、head dimension、page size、预算档、MHA/GQA布局和kernel版本. Query与页摘要内容是运行时数据, 不应进入编译键; 页表shape和stride变化可能需要不同图.

Graph miss、workspace扩容和fallback都要打点. 单步Quest热kernel很快, 频繁miss仍会让请求尾延迟恶化. 压测使用真实长度与预算分布, 才能评估容量档设计.

## 13. 多查询头共享时怎样分配读取预算

### 13.1. GQA把若干query映射到同一组KV

设一组共享同一KV头的query为 $q_1,\ldots,q_g$。第 $r$ 个query对第 $p$ 页的上界记为 $U_{r,p}$。MHA里每个query head拥有独立KV，逐头选页天然对应各自的真实点积；GQA里同一页只要读进片上存储，组内多个query都能使用，因此“每个头各选K页”常常重复读取。若先分别求候选集合 $C_r$，再取并集

$$
C_{\mathrm{union}}=\bigcup_{r=1}^{g}C_r,
$$

召回语义最直接，实际页数却会在 $K$ 到 $gK$ 之间波动。query关注位置相近时，并集接近K；关注位置互不重合时，并集接近 $gK$。固定每头K无法给出固定的组级流量，调度器必须为最坏并集留容量，或者允许运行时使用变长页表。

组级排序可把一页的多个上界聚合成单分数。取最大值

$$
U_p^{\max}=\max_r U_{r,p}
$$

会保护组内最强需求，只要某个query认为该页重要，它便有机会入选。取平均值会偏向多头共同认可的页，却可能淹没仅对一个头关键的证据。用 $
\operatorname{LSE}_\tau(U_{1,p},\ldots,U_{g,p})$ 可以在最大值和平均趋势之间连续调节；温度越低，行为越接近最大值。聚合分数改变了优化目标，不能把它当成无损的实现合并。

更稳妥的预算可以拆成共享部分与私有部分。先按 $U_p^{\max}$ 或组内投票选 $K_s$ 个共享页，再给每个query保留 $K_h$ 个私有页，总读取集合为

$$
C=C_s\cup\bigcup_r C_{r,h}.
$$

$K_s$负责摊薄带宽，$K_h$保护头间差异。极端情况下某个query专门检索早期实体，其他query集中在最近窗口；纯共享候选容易牺牲前者，少量私有预算便能修复。合适的 $K_s:K_h$ 与模型层、GQA组大小和任务有关，应由候选重合率与漏选损失共同决定。

### 13.2. 候选重合率揭示共享是否划算

单看最终并集大小很难判断预算浪费发生在哪里。对一组query，可以记录平均两两Jaccard系数

$$
J=\frac{2}{g(g-1)}\sum_{r<s}\frac{|C_r\cap C_s|}{|C_r\cup C_s|},
$$

也可以记录每页获得的“选票数” $v_p=\sum_r\mathbf 1[p\in C_r]$。高Jaccard和高票页占比意味着共享读取能显著摊薄KV流量；低Jaccard说明每个query在执行不同的检索任务，强制共享会制造召回损失。这个统计还能按层观察：靠近输入的层可能表现为局部模式一致，较深层的语义头则出现更强分化。

重合率还受top-k阈值影响。K很小时，各头只保留尖峰页，交集可能很小；K增大后，公共的近期页逐渐进入所有集合，Jaccard随之上升。因此报告单个K上的重合率仍不完整，更有信息量的是 $J(K)$ 曲线，以及并集大小 $|C_{\mathrm{union}}(K)|$ 相对 $gK$ 的压缩率。两条曲线能区分“头确实关注不同位置”和“预算太紧导致尖峰分裂”。

共享收益应按物理读取计数。若页已经进入L2或共享内存，多个query消费同一份K/V，逻辑访问次数虽多，HBM字节只发生一次。反过来，kernel若按query分别发起gather，即便候选页相同，也可能重复搬运。算法层面的集合重合与实现层面的字节复用要分别测量，再检查二者能否对齐。

### 13.3. 固定总预算可以写成一个覆盖问题

当组级总预算固定为B页时，目标是选择一个集合C，使多个query丢失的注意力质量尽可能小。若能得到每个query在每页上的真实质量 $m_{r,p}$，一个带权覆盖目标可以写成

$$
\max_{|C|\le B}\sum_{r=1}^{g}w_r\sum_{p\in C}m_{r,p}.
$$

真实 $m_{r,p}$ 需要读取页内K才能计算，在线阶段只能用上界、历史统计或廉价代理。这个形式仍然有用，因为它说明预算聚合的核心是覆盖多个需求，并且揭示了头权重 $w_r$ 的作用。某些头对最终输出更敏感时，平均分配预算并不合适。

若代理质量对集合具有边际收益递减，贪心法每次加入当前增益最大的页便能获得可解释的近似保证。组内最大上界对应一种极简代理：某页只由最强query决定。求和代理 $\sum_r f(U_{r,p})$ 会奖励同时服务多个query的页。还可以使用截断函数，让同一query已经获得足够候选后边际权重下降，把余下页让给覆盖不足的query。

覆盖视角也解释了为什么简单平均分有时失败。一个对所有query都“中等相关”的页可能压过仅对单个query“极其关键”的页，平均目标获得较好总体数值，却让一个头的关键路径断裂。可在目标中加入每头最低覆盖约束，例如要求每个query至少获得 $b_r$ 个私有或高分候选，然后将剩余预算用于共享收益。这种约束比事后观察最差头更直接。

### 13.4. Head合并必须保留softmax各自归一化

共享页表只合并了地址集合，组内每个query仍有独立分数、最大值和softmax分母。执行时可共同加载K/V tile，再让不同query寄存器分别完成点积与在线softmax。若把多头分数先求和再做一次softmax，模型函数已经改变；页选择阶段的聚合分数没有资格进入最终注意力归一化。

在线softmax对每个query维护状态 $(m_r,\ell_r,o_r)$。读入新块后，按各自块最大值 $m'_r$ 更新缩放：

$$
\widetilde m_r=\max(m_r,m'_r),\qquad
\widetilde\ell_r=e^{m_r-\widetilde m_r}\ell_r+
\sum_j e^{s_{r,j}-\widetilde m_r},
$$

$$
\widetilde o_r=e^{m_r-\widetilde m_r}o_r+
\sum_j e^{s_{r,j}-\widetilde m_r}v_j.
$$

同一 $v_j$ 可被多个query复用，三组状态不能交叉。这个区分看似基础，却直接决定融合kernel的寄存器规模：组越大，驻留的query状态越多，occupancy越容易下降。GQA在复用KV的同时增加寄存器压力，还要处理候选并集，三方代价需要一起权衡。

对照实验可以设置三条路径：逐头独立选页并独立读取；逐头选页取并集后共享读取；组级分数直接选固定B页。第一条给出质量基线，第二条隔离物理复用收益，第三条同时改变预算语义。若直接比较第一条与第三条，一旦质量或速度变化，无法判断来自共享搬运还是候选规则。

## 14. 位置编码怎样进入页上界

### 14.1. RoPE后的key才是实际被点积的对象

标准RoPE在每个二维子空间施加位置相关旋转。令 $R_t$ 表示位置t的分块旋转矩阵，实际分数为

$$
s_{t}=\frac{(R_i q)^\top(R_t k_t)}{\sqrt{d_h}}
=\frac{q^\top R_{t-i}k_t}{\sqrt{d_h}}.
$$

页摘要若对缓存中已经旋转后的 $R_tk_t$ 逐维取min/max，那么当前query也应使用 $R_iq$ 与摘要计算上界。这样仍满足区间盒子的几何条件，只是同一语义方向在不同位置发生了旋转。摘要若建立在旋转前key上，却直接拿旋转后query求界，上界关系通常不再成立。

旋转会影响页内包围盒紧度。一个页面覆盖多个位置，二维坐标轴随t变化；即使旋转前key集中在窄方向，旋转后点云也可能扫出较宽区域，min/max盒子包含大量实际不存在的角点。页越长、旋转角跨度越大，这种几何膨胀越明显。高频RoPE维度在短位置间就转过较大角度，往往比低频维度贡献更多松弛。

这个现象给page size增加了一项原理约束。较大页减少摘要数，却让位置旋转和语义多样性共同扩大盒子；较小页的摘要更紧，但扫描量和元数据上升。最佳页长因此依赖RoPE频谱、上下文位置和层内key分布，无法只由GPU对齐宽度决定。

### 14.2. 相对位置变换会让摘要依赖当前query位置

等式 $q^\top R_{t-i}k_t$ 表明，同一历史页相对于不同decode位置i具有不同的有效方向。直接缓存旋转后key摘要可以保持摘要静态，query侧旋转随i更新；若希望在旋转前空间建立更紧摘要，则需要处理页内多个相对旋转。把整页统一近似为中心位置的旋转会产生额外误差，而且该误差随页宽和频率增长。

可以对频率分组构造更细的界。二维子空间中，旋转后点积可展开为

$$
q_x(k_x\cos\theta-k_y\sin\theta)+
q_y(k_x\sin\theta+k_y\cos\theta).
$$

若页内位置使 $\theta$ 落在区间 $[\theta_-,\theta_+]$，key坐标也有各自范围，就能对三角函数和key联合求保守区间。这样的界可能比对所有旋转后点直接取轴对齐盒更紧，计算和摘要成本也显著增加。它适合说明改进空间，并不意味着在线系统一定值得采用。

另一条路径是把页拆成若干位置子块，各自保存旋转后摘要。选择先在粗页上筛选，再对子块复排。它等价于层次索引：第一层用少量元数据快速排除明显无关区域，第二层用更紧的局部盒减少假阳性。层次数、每层分支数与最终KV读取量之间需要联合优化。

### 14.3. RoPE缩放会改变训练外长度的选择分布

长上下文扩展常使用频率缩放或分段变换。缩放方案改变 $R_t$，也会改变旋转后key的坐标分布与页摘要松弛。一个在原始上下文范围内校准的固定预算，进入更长位置后可能召回下降；原因既可能来自模型外推能力，也可能来自索引上界排序发生变化。两类因素若不拆开，容易把选择器退化误判成基础模型退化。

可在同一批长序列上同时记录dense注意力质量、Quest候选召回和页上界松弛。若dense模型仍能定位证据，候选召回却随位置下降，选择器承担主要责任；若候选召回稳定而任务准确率下降，应更多检查位置外推和模型本身。上界松弛还可按RoPE频段分解，观察高频维度是否在远距离页上制造大量虚高分数。

缩放配置属于摘要语义的一部分。缓存跨请求复用时，只要模型采用的RoPE参数不同，旧摘要和旧KV都不能混用。动态缩放若依赖实际序列长度，同一token前缀在不同请求中甚至可能得到不同旋转坐标，prefix cache键必须包含相关配置。忽略它会造成难以复现的选择错误。

### 14.4. ALiBi与显式位置偏置可以直接并入上界

若分数写成

$$
s_t=\frac{q^\top k_t}{\sqrt{d_h}}+b(i,t),
$$

且偏置 $b(i,t)$ 可由当前位置与历史位置直接计算，页上界可以加上该页内最大偏置：

$$
U_p(q,i)=U_p^{\mathrm{dot}}(q)+\max_{t\in p}b(i,t).
$$

对单调距离惩罚，页内最大偏置通常出现在离i最近的边界token，计算只需页起止位置。这个上界保持保守性，同时把模型偏好的局部性带进排序。若忽略位置偏置，远处页的点积上界可能虚高，筛选器会浪费预算。

页级最大偏置依然可能松。点积达到上界的token与位置偏置达到最大值的token未必相同，两项分别取最大再相加，相当于组合了两个不同token。可把一页再按位置分段，或存储若干候选极值点，缩小这种错配。这里与min/max盒角点松弛具有相同结构：分量级最优组合未必由真实元素共同实现。

带相对位置桶的偏置同样可以处理。页跨越多个桶时，取覆盖桶中的最大偏置；页完全落在一个桶内时，偏置为常数，不增加松弛。由此可以预先分析页边界与位置桶边界的对齐关系，选择让常见页尽量不跨桶的page size或起始对齐。

## 15. 从漏失概率质量推到输出误差

### 15.1. 注意力输出误差由漏失质量直接控制

对一个query，完整注意力权重记为 $a_j=e^{s_j}/Z$，候选集合C保留的总质量为 $1-\delta=\sum_{j\in C}a_j$。稀疏路径在C内重新归一化，得到

$$
\widehat a_j=\frac{a_j}{1-\delta},\qquad j\in C.
$$

完整输出 $o=\sum_j a_jv_j$，稀疏输出 $\widehat o=\sum_{j\in C}\widehat a_jv_j$。设所有value范数不超过V，将保留项与漏失项分别整理，可得

$$
\|o-\widehat o\|
\le 2\delta V.
$$

推导的关键是保留项因重归一化产生总变化量 $\delta$，漏失项本身也有质量 $\delta$。这个界较粗，却把候选质量和表示误差连接起来。它说明固定页比例没有统一语义：同样读取10%的页，若漏失质量分别为0.001和0.2，输出风险完全不同。

更细的界可以使用value离散度。令候选内均值为 $\widehat o$，则

$$
o-\widehat o=sum_{j\notin C}a_j(v_j-\widehat o).
$$

于是误差取决于漏失value与候选输出的距离。漏掉的token即使有一定注意力质量，只要value接近当前输出，影响仍小；反之，小质量的异常value也可能产生明显方向变化。这解释了只看top-k分数召回为何不能完整预测下游误差。

### 15.2. 页上界可以给未读分母构造证书

选择完成后，对未读页p已有分数上界 $U_p$。若页含 $n_p$ 个有效token，则该页对softmax未归一化分母的贡献满足

$$
Z_p=\sum_{j\in p}e^{s_j}\le n_pe^{U_p}.
$$

将所有未读页求和得到 $Z_{\mathrm{miss}}^{\mathrm{ub}}$。候选页真实分数已经计算，可得到精确 $Z_C$，从而给漏失质量上界

$$
\delta\le
\frac{Z_{\mathrm{miss}}^{\mathrm{ub}}}
{Z_C+Z_{\mathrm{miss}}^{\mathrm{ub}}}.
$$

这提供了按query自适应停止的理论接口：逐批读取页并更新 $Z_C$，当右侧低于容忍阈值便停止。困难在于 $n_pe^{U_p}$ 往往很松，尤其一页只有一个token接近U，其余分数远低于U时，乘以页大小会严重高估。

可为每页保存多级统计改善分母界。例如记录若干分数相关的key投影无法预先适配任意query，但把页拆成更小子块、保存多个包围盒，能够把 $n_pe^{U_p}$ 换成各子块 $n_{p,r}e^{U_{p,r}}$ 的和。由于指数函数放大上界松弛，哪怕点积分数只紧一点，概率质量证书也可能改善很多。

数值实现应在log域累计：

$$
\log Z_{\mathrm{miss}}^{\mathrm{ub}}
=\operatorname{LSE}_p(\log n_p+U_p).
$$

这样能避免长上下文和大分数下溢出。候选真实分母也用在线log-sum-exp维护。证书计算本身增加归约开销，适合用于动态预算、困难样本回退或离线诊断；若每次都付出高成本，节省的KV流量可能被抵消。

### 15.3. 分数裕量只能提供局部信号

常见启发式观察第K页与第K+1页上界差值

$$
\gamma=U_{(K)}-U_{(K+1)}.
$$

较大裕量意味着排序边界稳定：小幅摘要误差不容易交换入选与落选页。它不能直接证明漏失概率质量很小，因为大量落选页即使各自略低，指数贡献相加后仍可能可观。上下文越长，这种“单页不强、总量很大”的风险越突出。

可把裕量与落选页数结合。若候选中已知最大真实分数为m，所有P-K个落选页上界不超过u，每页至多S个token，则漏失分母至多 $(P-K)Se^u$。u相对m的差距需要超过 $\log((P-K)S)$ 才能压住数量效应。由此可见，固定分数间隔在不同长度上不具有相同置信度。

页排序还存在上界拥挤现象。许多页面的U都由包围盒虚角产生，它们的真实最大值远低于U，边界裕量接近零，却未必真的困难。可以抽样读取部分边界页，估计上界松弛分布，再校准动态预算。校准属于统计保证，数据分布变化后需重新检查。

### 15.4. 多层误差传播需要观测真实轨迹

单层界控制当前注意力输出，后续残差连接、归一化和MLP会变换误差。若第l层后续映射的局部Lipschitz常数记为 $L_l$，粗略传播形式为

$$
\|\Delta h_{L}\|\le
\sum_{l=1}^{L}\left(\prod_{r=l+1}^{L}L_r\right)
\|\Delta o_l\|.
$$

这个式子通常过于宽松，神经网络全局范数界会放大到失去实用价值。它仍提醒我们：每层相同的漏失质量阈值没有充分依据，早期层误差经过更多变换，敏感度可能与后期层不同。

实践中可用成对运行估计局部敏感度。对同一prompt和同一decode步，选择某一层切换dense/Quest，记录最终logit差、隐藏状态角度和后续层误差增长。逐层扫描得到敏感度剖面，再按层分配预算。此实验只改变一个位置，比所有层同时稀疏更能定位因果来源。

自回归还会进入分支效应：微小logit变化一旦改变采样token，后续query和KV轨迹全部分叉。教师强制轨迹适合测数值误差，真实生成适合测最终行为，二者回答不同问题。前者在固定token序列上比较每步误差，后者统计任务成功率、生成长度和输出分布。完整评测应同时保留这两条轨迹。

## 16. 怎样找到Quest真正的退化区间

### 16.1. 预算曲线要同时画质量、字节与时延

横轴只用“保留页比例”会隐藏页大小和摘要流量。更完整的预算轴至少包含候选KV字节、摘要扫描字节与总HBM字节；纵轴同时报告候选召回、下游质量、attention时延和端到端时延。这样才能看清某个质量点对应的真实系统代价。

对每个长度L和预算K，可构造四元组

$$
(R_{L,K},Q_{L,K},B_{L,K},T_{L,K}),
$$

分别表示召回、质量、字节与时间。帕累托前沿上的配置无法在不损失其他指标的情况下继续改进；被支配配置通常意味着page size、kernel或预算规则存在明显问题。只挑一个“看起来最好”的点会丢掉方法适用范围。

长度扫描应保持任务难度可控。Passkey可改变证据位置和干扰项数量，合成长文可控制相关token密度，真实长文任务则验证分布外行为。若长度增长同时让问题本身更难，质量下降无法归因给选择器。可以先以dense同模型结果归一化，再观察Quest相对dense的差距。

### 16.2. 对抗页能直接测量min/max松弛

轴对齐包围盒最容易被坐标极值来自不同token的页面欺骗。可构造d维页：每个token只在一个坐标上取大正值，其他坐标取负值或零；min/max摘要在多个维度都显示大值，任意真实token却无法同时实现这些坐标。对全正query，上界接近各维最大值之和，真实最大点积只获得其中一小部分。

随着维度和页内token数增长，上界与真实最大值的间隔可以系统扩大。该合成实验不代表自然数据分布，却能检验实现是否理解最坏情况，并比较旋转、分块、多盒摘要等改进在同一几何难题上的效果。若方法只在自然平均样本上报告结果，很难知道安全余量来自算法还是数据恰好温和。

另一类对抗样本针对概率质量：安排大量页面各含一个中等分数token，让任何单页都排不到前列，但它们总softmax质量很大。固定Top-K可能保留尖峰而丢掉长尾总量。这个实验揭示页级最大值排序与概率质量目标的差异，可用于检验动态分母证书或多样化预算。

### 16.3. 证据位置、密度与查询类型应分轴控制

长上下文任务常把“证据在远处”当成唯一难度。Quest还会受证据密度影响：单个尖锐事实通常容易形成高分页，多段弱证据需要跨页聚合，每页上界未必突出。可以分别构造单证据、多证据交集、多证据求和和否定证据，观察候选召回与最终答案的关系。

查询类型也会改变query向量的选择性。精确实体检索可能产生清晰尖峰，主题总结会对大量段落分配中等权重，代码依赖追踪则可能同时需要定义、调用点和当前局部窗口。相同K在这些类型上对应不同漏失质量。分组结果比总平均值更能说明方法适合哪些读取模式。

证据位置应覆盖页首、页中、页尾和跨页边界。边界样本能暴露分词、页填充、未满页摘要与位置偏置的交互。若一段语义单元跨两页，每页只含一半线索，页级分数可能低于完整段落位于单页的情况。改变page offset并重复测试，可以区分内容难度与分页偶然性。

### 16.4. 消融顺序要能回答因果问题

第一组消融固定候选集合，仅替换dense gather与稀疏gather，用于测量执行收益；第二组固定稀疏kernel，分别输入oracle候选、Quest候选和随机候选，用于测量选择质量；第三组固定总读取字节，改变page size与摘要形式，用于测量上界紧度。每次只改变一个机制，结果才容易解释。

Oracle候选可以用真实页内最大点积排序，也可以用真实页softmax质量排序。前者对应Quest上界试图逼近的目标，后者更接近输出保真目标。两种oracle之间若已有明显差距，说明“按页最大分数选页”本身存在目标错配；Quest与最大点积oracle之间的差距才主要归因于min/max松弛。

系统消融还需保持编译、batch、精度和缓存状态一致。冷启动与稳态分别报告，避免首次编译或图捕获淹没kernel差异。端到端实验记录prefill、decode、采样、通信等分项，使attention加速未传导到总时延时能找到瓶颈。

实验应给出退化阈值，单说“长文本更快”没有交代适用区间。例如在某硬件、某batch和某head dimension下，长度超过多少、预算低于多少时总字节开始下降；候选召回达到给定水平需要多少页；哪类任务在该预算下最早失效。阈值随模型与机器变化，但这种报告方式能让读者迁移方法时重新测量关键边界。

## 17. Quest在选择器谱系中的位置

### 17.1. 静态窗口提供确定性局部先验

滑动窗口直接保留最近W个token，地址只由位置决定，几乎没有索引计算。它擅长承接语言模型的局部连续性：当前token往往依赖附近的句法、代码行和对话轮次。代价也很明确，窗口外证据没有内容相关的返回通道。Quest依据当前query给远处页面排序，正好补上动态检索能力。

两者可以共用一个预算。先无条件保留局部窗口与少量attention sink，再由Quest填充远程页。设总页预算为B，局部页数为 $B_{\mathrm{local}}$，动态页数为 $B-B_{\mathrm{local}}$。局部份额过大时，远程召回空间被挤压；动态份额过大时，筛选器必须反复找回本来稳定有用的近邻。按层调整份额通常优于全模型使用同一个比例。

局部页也应从Quest排序池中排除，否则动态Top-K可能重复选中已经保留的页面，表面预算为B，实际独立页面更少。实现可先给局部页打已选标记，再对远程页做selection；评测则同时报告保底集合、动态集合及其交集。这样才能看出质量来自模型固有局部性还是query-aware检索。

### 17.2. Eviction与读取稀疏解决不同的资源约束

KV eviction永久或长期移除部分历史状态，主要降低容量占用；Quest保留完整KV，只在每一步减少读取。设完整缓存容量为M，每步读取比例为r，Quest后的容量仍接近M，单步KV流量约降到rM对应的部分。显存容量装不下完整上下文时，单靠读取选择无法解决驻留问题。

二者串联时，eviction决定可检索全集E，Quest从E中选当前候选C。若关键token已经被逐出，任何上界都无法召回。评测需要依次测完整dense、仅eviction、仅Quest、eviction加Quest，才能分离容量损失和读取损失。组合方案的误差一般高于任一单独方案，速度收益也受到两级元数据与调度成本影响。

层级存储提供另一种组合：完整KV可放在较慢介质，近期或高频页驻留HBM，Quest决定本步需要迁入哪些冷页。此时上界扫描必须访问常驻的小摘要，候选页的缺页延迟成为主要风险。预取可利用前一层或前一步候选预测，错误预取则消耗链路带宽。这里的Quest从attention稀疏器进一步变成数据移动决策器。

### 17.3. 学习型indexer用训练成本换表达能力

学习型选择器可把query和页面压缩成低维向量，再用近似近邻或轻量打分检索。它能学习坐标相关性，避免轴对齐min/max盒把互斥极值相加，理论上会产生更紧的候选。训练数据、目标函数和分布迁移随之进入系统：选择器在某类任务上学到的访问模式，换到代码、数学或更长上下文后可能失效。

Quest的区间上界具有清楚的保守含义，只要摘要计算正确，页内真实最大点积不会超过它。学习分数通常没有这种逐页证书，漏选风险依赖经验召回率。可以让学习型indexer先给出候选，再用Quest上界扩充边界页；也可以用学习分数排序、用上界决定停止。前者偏向平均效率，后者保留一定可验证结构。

训练目标最好贴近最终用途。模仿真实top-k页只学习最大点积排序；以漏失softmax质量为损失更关心概率总量；直接蒸馏hidden state或logit则把value和后续网络敏感度纳入目标。三个目标可能选出不同页面。比较方法时需确认它们优化的是同一种质量定义。

### 17.4. 路由器成本决定复杂索引能否胜出

任何选择器都位于dense attention之前，它节省的时间上限等于被跳过KV读取和点积的成本，索引自身成本从这笔收益中扣除。记dense attention时间为 $T_d$，索引时间为 $T_i$，稀疏attention时间为 $T_s$，加速为

$$
S=\frac{T_d}{T_i+T_s}.
$$

当候选比例已经很低，$T_s$继续下降，$T_i$会成为新的下界。增加多级摘要、学习网络或复杂停止规则只有在减少的 $T_s$ 大于新增 $T_i$ 时才有净收益。

索引成本还包含同步。选择结果决定后续gather地址，两个阶段之间存在依赖；若分别启动kernel，launch和中间写回都会进入关键路径。融合能减少同步，却让寄存器、共享内存和编译形状更复杂。算法论文给出的FLOPs减少无法自动转化为这部分收益。

适用区间可以用break-even条件表达。若摘要扫描每页成本为c，页数P，读取一个KV页成本为g，候选数K，则近似路径成本为 $cP+gK$，dense成本为 $gP$。只有

$$
\frac{K}{P}<1-\frac{c}{g}
$$

才可能节省纯读取成本。c/g越大，需要越激进的稀疏度才能越过交叉点。短上下文、很小head dimension或高效dense kernel都会抬高Quest的相对门槛；长上下文和带宽受限场景更有利。

### 17.5. Query-aware选择与预取存在时间差

Quest依赖当前层当前token的query，因此候选在query生成后才能确定。计算图先完成前一子层，再扫描摘要、选页、搬KV，关键路径呈串行关系。若希望提前预取，只能用上一层query、上一token候选或轻量预测器猜测即将需要的页面。预测命中能隐藏内存延迟，预测失败会带来多余流量，并且仍需等待真正候选补齐。

相邻decode步的候选通常有一定连续性，因为上下文只追加一个token，语义主题也常保持稳定。可记录集合保持率

$$
H_t=\frac{|C_t\cap C_{t-1}|}{|C_t|},
$$

并把上一时刻候选分成预取部分与待验证部分。高保持率场景可以先加载旧候选，同时计算新上界；低保持率场景则应缩小投机量。保持率需按任务和层统计，代码跳转、话题切换或工具返回之后可能突然下降。

预取不会改变最终候选语义，只改变数据到达时刻。实验应分别报告命中率、额外字节和被隐藏的等待时间。单看命中率会高估收益：若命中的页面本来就在L2，或预取距离太短，命中也未必减少关键路径；若投机页挤出其他缓存内容，还可能产生负收益。

### 17.6. 可验证性来自逐级保存中间量

Quest的错误可能来自摘要、分数、排序、页表或稀疏attention任一环节。可复算测试应保存少量样本的query、页min/max、页上界、候选页号、候选内真实分数和输出。CPU高精度实现按数据流逐级重算：上界覆盖页内最大点积，top-k集合对应排序结果，稀疏softmax对应候选内的精确参考值。

上界违规是最严重的信号。只要某页出现真实最大值高于U，就应优先检查量化舍入、padding、RoPE空间、未满页更新和dtype溢出。候选质量较差但没有上界违规，通常来自界太松或预算不足。两类问题的修复路径完全不同，不能只用最终任务准确率定位。

随机测试还应覆盖负query分量、全负key、极端幅值、重复分数、空页、单token页和非整页长度。尤其要验证分支表达式：$q_i\ge0$ 时取max，$q_i<0$ 时取min；符号分支写反会在普通数据上偶尔看似正常，在构造样本上立刻暴露。GPU结果可允许浮点容差，上界属性本身则要考虑计算dtype带来的舍入余量。

运行时监控无需保存用户内容。系统可以聚合候选比例、上界裕量、回退频率、页重合率和各阶段时延分位数，按模型版本与长度桶观察漂移。质量异常出现时，再用离线授权样本复算中间量。这样既保留诊断能力，也避免把原始KV或prompt写入普通性能日志。

回归测试还要固定若干“选择指纹”。对给定模型权重、prompt、精度和页长，保存每层少量query对应的候选页哈希、上界排序前缀与输出误差。更换编译器、kernel或量化参数后重跑，指纹变化能快速暴露语义漂移。浮点归约顺序可能让临界同分页互换，因此指纹比较应区分集合变化、顺序变化和数值容差内变化；真正需要报警的是关键页消失、上界违规或误差跨过既定阈值。

当生产路径触发保守回退时，也应记录触发原因。例如候选容量溢出、动态证书未达阈值、摘要版本不匹配、页表校验失败分别计数。把所有回退合并成一个比例会掩盖根因：容量溢出提示预算分布估计不足，证书失败提示当前query难筛，版本不匹配则属于缓存生命周期错误。清晰的原因码让Quest从一次离线加速实验变成可维护的推理组件。
