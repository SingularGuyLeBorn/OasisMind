# 粗粒度选择: 从内容分组到动态稀疏块

动态 Sparse Attention 必须在完整 QK 计算以前决定读取哪些 K/V. 粗粒度选择把 token 先归入桶、簇或二维块, 再以组为单位保留候选. 选择结果未必精确到最终高权重 token, 却能把不规则关系整理成 GPU 可以执行的连续 tile. 这条路线关心的核心量是候选块召回、块内多算、建索引成本与负载分布. 只比较逻辑非零比例, 会同时漏掉索引器和物理扩张.

设输入为 $Q,K,V\in\mathbb{R}^{B\times H\times n\times d_h}$, 每个物理块包含 $b$ 个 token. 路由器不直接输出 $n\times n$ mask, 而是生成块索引 $J\in\mathbb{N}^{B\times H\times N_q\times k_b}$, 其中 $N_q=\lceil n/b\rceil$, $k_b$ 是每个 query 块选择的 key 块上限. kernel 根据 $J$ 读取原始 K/V, 在选中 tile 内计算精确 QK、causal mask、在线 softmax 与 AV. 输出 shape 仍为 $B\times H\times n\times d_h$.

**粗粒度选择保留的是计算区域, 不是提前决定 attention 权重.** 块内每条边仍由原 QK 分数竞争. 代价是一个关键 token 会带入同块的其他 token; 好处是 K/V 连续、索引短、矩阵核利用率高. 块尺寸 $b$ 越大, 索引越便宜而多算越多; $b$ 越小, 召回更精细而 gather、top-k 和 kernel 调度更重.

## 1. 两条进入路线

### 1.1. 从表示空间形成桶

[哈希与聚类](./01-哈希与聚类.md)从向量本身构造邻域. Reformer 用随机旋转产生 LSH 桶, 相似向量以较高概率碰撞; Routing Transformer 用在线 k-means 中心把 query 与 key 分入内容簇. 两种方法通常在训练阶段已经改变 attention 拓扑. 模型会在局部 head、内容桶和容量约束下学习表示, 推理时沿用同一分桶规则.

哈希的状态是随机投影与多轮桶号, 聚类的状态是持续更新的中心. 前者以概率召回换取无需学习中心, 后者让分区贴合数据, 同时承担中心漂移、空簇和热点簇. 二者都要排序、计算 offset、重排 Q/K/V、执行桶内 attention, 再逆置换输出. 算法里的同桶关系只有经过这些步骤才成为实际加速.

这条路线适合从训练开始共同设计. 若直接替换已训练稠密模型, 共享 QK、中心分布和桶内 softmax 都可能改变原模型行为. 评测需要把路由 recall、桶容量溢出、物理 padding 和任务质量放在一起, 不能用语言模型平均 loss 掩盖唯一证据漏选.

### 1.2. 从已有 attention 归纳空间模式

[MInference](./02-MInference.md)面向已经训练完成的长上下文模型. 它先离线观察每层每个 head, 在 A-shape、Vertical-Slash 与 Block-Sparse 中选择模式和预算; 在线再根据当前输入生成具体列、斜线或块坐标. 模式类型固定, 索引位置动态. 这种分层把昂贵的模式比较移出请求路径, 在线只解决受限几何中的候选选择.

MInference 的目标是 Prefill. 整段 prompt 同时产生大量 query, 稠密关系为平方级, 专用稀疏 kernel 能获得足够工作量. Prefill 结束后仍保存完整 KV Cache, 原方法并未把未访问 token 删除. Decode 每步只有一个新 query, 索引摊销、cache 布局与访存瓶颈不同, 不能从 Prefill 加速直接推出 Decode 收益.

两条路线的区别不在有没有动态性. 哈希与聚类让动态分组成为模型结构, MInference 从稠密模型已有的 head 形状中寻找可执行近似. 前者可在训练中适应漏边, 后者以免训练部署为主要价值. 比较时必须注明模型是否重训、稀疏发生在哪个阶段以及稠密教师是否只在离线使用.

### 2. 统一的成本与质量口径

#### 2.1. 索引器先花了多少

设最终物理 attention 关系数为 $\tilde E$, 主计算约为 $O(\tilde E d_h)$. 总时间还包含路由投影、摘要、排序或 top-k、整数索引写入、Q/K/V 重排以及输出 scatter. 若索引器计算完整 $QK^T$ 后才选块, 主平方成本已经发生. 有效索引器必须读取低维摘要、少量采样 query、有限中心或规则几何.

哈希常付出 $O(n\log n)$ 排序, k-means 付出 $O(nCd_h)$ 中心打分, MInference 的在线索引付出采样 QK 与 reduce/top-k. 渐近式仍不足以预测延迟. GPU 上需要记录 HBM 字节、kernel 启动、同步和排序轮数. 短序列时稠密 FlashAttention 往往占优, 长度跨过阈值后稀疏主计算的减少才覆盖索引固定成本.

#### 2.2. recall@k 不能只按 token 算

以稠密 attention 的 top-$t$ 集合 $G_i$ 为教师, 候选集合为 $\mathcal N(i)$, token recall 为 $|G_i\cap\mathcal N(i)|/|G_i|$. 对块方法还应报告物理预算: 一个命中 token 可能要求读取整个块. 两个方法 token recall 相同, 物理 tile 数可能相差很大. 稠密概率质量覆盖能区分教师第一名与边缘 top-$t$, 仍需任务质量确认误差传播.

平均 recall 也会隐藏少数致命 query. 应按层、head、query 区间和任务类型观察尾部, 尤其是唯一远程证据、多跳汇总、相似干扰与代码引用. 对训练型路由还要分训练长度内和长度外; 对离线配置要分校准域和部署域. 候选召回回答算法近似, kernel 对同一候选的误差回答实现正确性, 两者要分开测.

#### 2.3. 块大小连接算法与硬件

逻辑索引可以选择单列或单 token, kernel 往往以 $64\times64$ 等 tile 执行. 物理扩张增加边数, 也换来连续加载和矩阵核利用率. 因此预算搜索最好直接使用物理 tile 成本, 而非只最小化逻辑 mask. 多个逻辑候选落进同一 tile 时应合并, 不同分支重叠时必须去重, 否则 softmax 分母会重复计数.

负载均衡同样受块影响. 热点簇或热门 key 块会拖慢一个执行 wave, 在序列并行中还会形成通信热点. 固定 top-k 给出工作上限, 不能保证实际设备均衡. 应报告每行 tile 数、最大/平均比、padding、溢出和跨设备字节. 粗粒度方法的工程成败经常取决于这些分布量, 而非论文图上的平均稀疏率.

## 3. 从一个 query 块走完数据路径

粗粒度选择最容易被热图迷惑. 热图里一块区域看起来很稀疏, 并不说明执行时真的只读了这些位置. 要判断一个方法有没有节省, 可以固定一个 query 块, 沿着路由、索引、取数、计算和归一化走一遍. 设 query 块大小为 $b_q$, key 块大小为 $b_k$, 当前 query 块记作 $Q_r\in\mathbb{R}^{b_q\times d_h}$. 路由器为它选出 $k_b$ 个 key 块:

$$
J_r=(j_1,j_2,\ldots,j_{k_b}),\qquad
K_{J_r},V_{J_r}\in\mathbb{R}^{k_b\times b_k\times d_h}. \tag{1}
$$

式 (1) 只是地址列表. kernel 还要将这些地址变成实际加载. 如果 K/V 按 token 连续存放, 单个 key 块内部可以合并读取; 不同块之间仍是 gather. 若 $J_r$ 已按地址排序, 相邻块有机会合并, L2 命中也更稳定. 若它只按路由分数降序排列, 数学结果不受影响, 访存顺序却可能来回跳. 因此索引既有「选中了谁」这一语义, 也有「以什么顺序访问」这一物理属性.

候选进入 kernel 后, 每个 tile 仍计算原始点积:

$$
S_{r,t}=\frac{Q_rK_{j_t}^{\mathsf T}}{\sqrt{d_h}}
\in\mathbb{R}^{b_q\times b_k}. \tag{2}
$$

自回归 mask、末块 padding 和重复候选必须在 softmax 前处理. 多个 key 块不能各自做一次 softmax 后再平均, 因为它们共享一行分母. FlashAttention 的在线归一化可以直接延伸到稀疏块. 处理第 $t$ 个块时维护行最大值 $m^{(t)}$、指数和 $\ell^{(t)}$ 与未归一化输出 $u^{(t)}$. 新块的行最大值为 $\hat m$, 指数和为 $\hat\ell$, 加权 Value 为 $\hat u$, 则:

$$
m^{(t)}=\max(m^{(t-1)},\hat m), \tag{3}
$$

$$
\ell^{(t)}=
e^{m^{(t-1)}-m^{(t)}}\ell^{(t-1)}+
e^{\hat m-m^{(t)}}\hat\ell, \tag{4}
$$

$$
u^{(t)}=
e^{m^{(t-1)}-m^{(t)}}u^{(t-1)}+
e^{\hat m-m^{(t)}}\hat u. \tag{5}
$$

最后输出 $u^{(k_b)}/\ell^{(k_b)}$. 式 (3) 到式 (5) 说明稀疏块顺序可以变化, 但一个候选不能被无意计算两次. 局部窗口、全局块和动态 top-k 常会重叠. 若同一 key 块从两个分支进入, 直接拼接会把它的指数项加入两遍, 这已经改变数学定义. 去重可以放在索引生成阶段, 也可以给分支规定互斥范围; 在 kernel 内靠逐项比较去重通常太贵.

粗粒度选择的完整数据路径由此分成五个可测阶段: 生成 query 摘要, 对候选块打分, 选择并整理块号, 加载 K/V tile, 合并稀疏 softmax. 论文若只报告最后一个 kernel, 还不足以说明端到端收益. 部署时至少要分别计时路由和 attention, 并确认计时包含索引张量从生成位置到消费位置的同步.

## 4. 路由分数怎样代表一个块

### 4.1. 中心、池化和最大值回答的问题不同

一个块含 $b_k$ 个 key, 路由器不可能先让每个 query 与块内所有 key 点积, 否则候选阶段已经接近原计算. 常见做法是把一个块压成摘要 $c_j$. 最简单的是均值:

$$
c_j=\frac{1}{b_k}\sum_{s=1}^{b_k}k_{j,s},\qquad
g_{rj}=\operatorname{pool}_{q\in Q_r} q^{\mathsf T}c_j. \tag{6}
$$

均值中心适合块内方向相近的情况. 若一个块包含一个强相关 key 和许多无关 key, 这个信号会被稀释. 最大池化可保留尖峰, 但要么读取更多细粒度特征, 要么依赖额外摘要. 学习得到的 block representative 可以针对召回优化, 代价是训练状态、额外参数以及部署时的一致性要求.

query 侧也要聚合. 用最后一个 query 代表整个块, 偏向块尾需求; 对所有 query 得分取最大值, 能照顾任意一个 query 的强匹配, 同时容易被异常高分支配; 取均值更稳定, 可能漏掉少数查询的唯一证据. 所以「块分数」没有脱离聚合规则的统一含义. 评测路由器时, 应把块内每个 query 的召回分别保留, 再汇总均值和低分位, 不能只用聚合分数自证准确.

MoBA 采用块级门控, query 对历史 KV 块的代表进行打分并选择少数块, 当前块保留因果范围内的细粒度注意力. 它把 MoE 的 top-k 路由思路移到注意力块, 但 expert 与 KV 块有一处根本差别: expert 是可学习函数, KV 块是当前序列产生的状态. 热门 KV 块不会带来 expert 参数争抢, 却会造成大量 query 重复读取同一段 K/V. 这可能提高缓存复用, 也可能形成某些工作项远重于其他工作项. 判断方向取决于调度和缓存层级, 不能只从 top-k 数字推出.

NSA 的压缩分支也生成粗粒度表示, 但它不是单纯用摘要决定随后读取哪些原始 token. 压缩分支本身参与输出, 与选择分支、局部分支共同组成 attention. 因此「摘要只用于路由」和「摘要本身也是 Value 信息通道」要分开. 前者的质量依赖原始块是否被召回, 后者即使没有回读原块也能传递压缩信息, 同时会引入压缩误差.

### 4.2. top-k、阈值与容量约束

固定 top-$k_b$ 让每个 query 块拥有相同的工作上限, kernel 调度最直接. 它也把内容难度压成同一预算: 简单局部段落可能多读, 跨文档、多跳或代码依赖可能少读. 阈值选择允许候选数随分数分布变化, 质量更贴合样本, 但产生 ragged 行. 工程上常将阈值结果再裁到 $k_{\max}$, 同时保留 $k_{\min}$, 于是规则写成:

$$
k_r=\min\left(k_{\max},
\max\left(k_{\min},\left|\{j:g_{rj}\ge\tau_r\}\right|\right)\right). \tag{7}
$$

$\tau_r$ 可以是绝对阈值、相对最大值的差, 也可以由累计路由概率决定. 绝对阈值对层间尺度敏感; 相对阈值在所有分数都很差时仍会选出一些块; 累计概率依赖路由分数的校准. 无论采用哪种, 物理执行通常仍按若干容量桶分组, 例如把 $k_r$ 向上归入 4、8、16. 逻辑候选变长并不意味着 kernel 真正按每行精确长度运行.

训练时的容量约束还会影响梯度. top-k 之外的块没有主 attention 梯度, 路由器若只从最终语言模型损失学习, 早期错选可能长期收不到纠正信号. 解决办法包括稠密教师产生的路由监督、可微近似、辅助负载损失或由其他分支维持信息通路. 每一种都改变训练成本. 「推理只算稀疏块」与「训练从头到尾都省去稠密 QK」也需要分别核实.

### 4.3. 因果边界不能交给块号猜

对第 $r$ 个 query 块, 历史完整 key 块编号满足 $j<r$; 当前块 $j=r$ 只能看块内下三角. 若块大小为 64, query 位置 130 位于第 2 块, 它能看到第 0、1 块全部位置, 以及第 2 块中的 128 到 130. 路由器可以只为完整历史块打分, 当前块作为固定局部分支加入. 这样 top-k 不会浪费在必选当前块上, 索引协议也更简单.

变长 batch 会增加一层边界. 同一个物理 batch 中不同样本的有效块数不同, 块号必须相对样本起点解释. packed sequence 还可能把多个文档放进连续 token 区间, 单纯的 $j\le r$ 无法阻止跨文档访问. kernel 需要 sequence ID 或累积长度边界. 稀疏索引正确而文档边界错误, 输出仍会发生信息泄漏.

### 5. 三类粗粒度路线的真实分叉

#### 5.1. 内容分组改变模型看到的图

LSH 与在线聚类先把 token 放进内容邻域, 注意力图由桶成员关系决定. 它们适合在训练期使用, 因为表示可以逐渐适应分组规则. Reformer 的共享 QK、随机旋转和多轮哈希是一整套约束, Routing Transformer 的中心更新与局部 head 也是模型设计的一部分. 把其中一个索引器直接塞进已有模型, 不能假定原 QK 排序仍然成立.

这类方法的好处是分组不限于位置模板. 两个相距很远但表示相似的 token 可以进入同桶. 问题也来自同一点: 桶成员数量不可预知, 相似性空间会随层与训练阶段变化. 排序、容量裁切和跨设备重排不是附属实现, 它们决定算法能否保持预期候选.

#### 5.2. 空间模式近似已有稠密模型

MInference 观察已训练模型的 attention 图, 用 A-shape、竖线-斜线和块稀疏三类模板覆盖不同 head. 它没有让任意 token 在表示空间里自由配对, 而是先把候选限制在容易执行的几何族内. 离线阶段决定每个 layer-head 使用哪一类模式及预算,在线阶段才根据输入确定具体列、斜线或块.

这种路线保留原模型权重, 适合超长 Prefill. 它的风险是配置域迁移: 校准数据里的 head 形状不一定覆盖另一语言、代码、表格或多轮上下文. 模式名称相同也不表示索引一致. VS 分支怎样采样 query、怎样聚合列分数、斜线位移如何选择, 都会影响召回. 因此配置文件要与模型权重、长上下文训练版本和 head 编号绑定.

#### 5.3. 原生块路由让模型适应选择

MoBA 直接让 query 路由到 KV blocks, NSA 则把压缩、选择和局部通道联合训练. 它们与免训练近似相比, 允许模型围绕稀疏图重新组织表示. 训练适应可以弥补部分漏边, 也意味着结果不能脱离训练配方比较. 一个从头使用稀疏 attention 的模型与一个把稠密模型后装稀疏 kernel 的模型, 即便物理边数相近, 误差来源也不同.

原生训练还把反向传播带入系统设计. forward 选了哪些块, backward 至少要重算或保存相同索引; 路由器本身需要梯度或辅助监督; 分布式训练要处理索引对应的 K/V 所在设备. NSA 明确把训练、前向和解码一并纳入硬件对齐目标, 这比只优化 Prefill 推理覆盖更广. MoBA 允许从 full attention 平滑过渡到 sparse attention, 其价值包含训练过程中的兼容性, 不能缩成一句「块 top-k」.

这三类路线可以放进同一张坐标表:

| 路线 | 候选依据 | 是否依赖重训 | 主要执行单位 | 主要风险 |
|---|---|---:|---|---|
| LSH/聚类 | 表示空间的桶或簇 | 是 | 排序后的桶与 chunk | 碰撞漏选、热点桶、重排成本 |
| MInference | 稠密 head 的空间模式 | 否 | 列、斜线、二维 tile | 校准域迁移、代理索引误差 |
| MoBA | 学习到的块门控 | 是 | KV block | 块摘要失真、top-k 训练信号 |
| NSA | 压缩、选择与局部多分支 | 是 | 压缩块、选择块、局部窗口 | 分支融合、训练与内核复杂度 |

表里的「是否依赖重训」描述原方法的使用方式, 不表示任何一类绝对优于另一类. 已有权重无法重训时, 免训练近似更现实; 能控制预训练时, 原生稀疏可以把训练成本也纳入优化. 路由自由度越高, 通常越难获得规则内存访问; 几何约束越强, 又越容易遇到分布外模式.

## 6. Prefill、Decode 与训练不是同一道题

### 6.1. Prefill 有足够多的 query 摊薄索引

Prefill 同时处理整段输入. 一个 query block 的路由决定可以被 $b_q$ 行共享, 块摘要也能被许多 query 复用. 当序列很长时, 稠密下三角 QK/AV 占比迅速上升, 稀疏 tile 的减少容易覆盖索引固定成本. 这正是 MInference 主要瞄准的阶段.

但 chunked prefill 会改变条件. 服务系统可能把长 prompt 切成多个 chunk, 每次只处理新增 query, 历史 K/V 已写入 cache. 路由器要同时面对当前 chunk 和全部历史块; 如果每个 chunk 重建所有历史摘要, 复杂度会悄悄增长. 更合理的做法是摘要随 KV Cache 一起追加, 当前请求只计算新块摘要. 配置与缓存状态必须在抢占、迁移和 prefix cache 复用后保持一致.

### 6.2. Decode 的主成本是读取历史 K/V

Decode 每步常只有一个 query. 块路由可以减少 K/V 读取, 对内存带宽瓶颈很有吸引力, 但此时没有 $b_q$ 个 query 共同摊销路由. 若路由器为每步扫描全部 $N_k$ 个块摘要, 成本为 $O(N_kd_r)$; $d_r$ 是摘要或低维索引维度. 它仍小于读取全部 $N_kb_kd_h$ 个 K/V, 前提是摘要足够小、连续且常驻较快存储.

Decode 还要处理索引随新 token 变化. 固定使用 Prefill 最后一行选出的块, 会错过后续 query 的新需求; 每步重新 top-k 又带来小算子和同步. 跨层共享、跨 token 复用以及候选缓存因此变得重要. 这些优化要测命中率: 上一步选中的块在下一步是否仍覆盖高概率质量, 浅层索引能否服务深层. 复用不是免费结论, 它用陈旧候选换取较低延迟.

### 6.3. 训练还包含反向与激活生命周期

训练使用整段 query, 与 Prefill 在前向形状上相近, 但需要反向传播. 稀疏 attention 若保存索引和 softmax 统计, 会占用激活显存; 若重算路由, 随机哈希、top-k 平局和中心状态必须可复现. 分布式序列并行时, 某个 query 选择的 KV 块可能位于另一设备, 路由结果会转化为不规则通信.

原生稀疏训练的收益应报告完整 step time, 包含 forward、backward、优化器之外的路由和通信. 只测 forward kernel 会高估训练收益. 质量方面也不能只在相同 step 数比较: 若稀疏训练每步处理更多 token, 应同时报告总训练 token、计算量和收敛曲线. NSA 将算术强度与硬件执行共同考虑, 说明训练型稀疏已经不能只用理论边数描述.

### 7. 一次可复算的块预算

设序列长度 $n=8192$, $b_q=b_k=64$, 因而共有 $N=128$ 个块. 单个 head 的稠密因果 attention 约处理:

$$
E_{dense}\approx\frac{n(n+1)}{2}\approx 3.36\times10^7
\tag{8}
$$

个 token 对. 现在让每个 query 块固定保留最近 2 个块、1 个全局起始块, 再动态选择 5 个历史块. 忽略序列开头不足预算以及分支重叠, 每行最多 8 个 key 块, 物理关系数约为:

$$
\tilde E=128\times8\times64\times64=4{,}194{,}304. \tag{9}
$$

相对稠密下三角约为八分之一. 这个数字还不能写成 8 倍加速. 假设索引器先让每个 query 块摘要与全部 128 个 key 块摘要点积, 摘要维度 $d_r=32$, 路由乘加约为 $128^2\times32$. top-k 还包含选择与索引写入. 主 attention 的每条边则做 $d_h$ 维 QK 和 AV, 若 $d_h=128$, 工作量远大于摘要打分, 路由在长序列上可能划算.

再看块内浪费. 若动态分支真正需要的每个块只有 8 个 token, 5 个动态块的逻辑关系为 $64\times5\times8=163{,}840$; 物理执行却是 $64\times5\times64=1{,}310{,}720$, 放大 8 倍. 把块改成 16 能减少多算, tile 数和索引长度会增加 4 倍, 小 tile 的矩阵核效率也可能下降. 块大小不是算法论文末尾的实现参数, 它直接决定召回和吞吐之间的工作点.

如果局部分支与动态分支有两个块重叠, 去重后的总块数是 6 而非 8, 式 (9) 会降为 $3{,}145{,}728$. 如果没有去重, 重叠块还会污染 softmax. 因此性能计数和正确性检查都会用到同一个指标: 每行唯一物理 tile 数.

这个例子还省略了 causal 三角. 当前块只有一半左右的有效关系, 历史块是完整矩形. 高性能 kernel 可能仍按整 tile 做矩阵操作, 用 mask 去掉上三角, 因而 FLOPs 统计和有效边数不同. 报告结果时应说明采用有效 token 对、物理 tile FLOPs 还是 profiler 实测指令量.

## 8. 质量评测要追踪被删掉的概率质量

### 8.1. 三层验证各自回答一件事

第一层固定候选索引, 比较稀疏 kernel 与朴素 masked attention. 这一步检查 causal mask、重复 tile、在线 softmax和 GQA head 映射, 不评价路由器. 给定相同 $J$, 两者应在 dtype 容差内一致.

第二层将路由候选与稠密 attention 比较. top-$t$ recall 适合观察高分边, 概率质量覆盖更直接:

$$
C_i=\sum_{j\in\mathcal N(i)}\alpha_{ij}^{dense}. \tag{10}
$$

$C_i$ 接近 1 表示候选覆盖了稠密 softmax 大部分质量. 它仍不是输出误差的充分条件: 被漏掉的 Value 方向可能互相抵消, 也可能恰好承载关键内容. 可以再计算稠密输出与稀疏输出的相对误差、余弦相似度, 并按 layer-head-query 保存分布.

第三层是语言模型与下游任务. 困惑度观察平均预测, Needle 类任务检查远程定位, KV retrieval 对相似干扰更敏感, 多跳和代码任务检查多次信息搬运. 单一 passkey 很容易被全局列或局部规律解决, 无法证明动态路由已经可靠. MInference 官方资料分别使用 RULER、InfiniteBench、Needle 与 PG-19, 对应的长上下文能力也应分项报告.

### 8.2. 平均值会藏住最危险的 query

若 99% query 的覆盖率为 0.99, 1% query 为 0, 平均覆盖仍接近 0.98. 那 1% 可能正是答案位置、函数定义或否定条件. 应至少报告低分位、最差 layer-head、不同位置区间以及不同输入类型. 对粗粒度块还要区分「路由没选中目标块」与「目标 token 在选中块内但 softmax 权重变化」.

长度外推需要单列. 训练或校准在 32K, 部署到 128K 时, 块数量增加, 固定 top-k 对历史覆盖比例下降. 路由分数的极值分布也随候选数变化, 固定阈值可能选出更多或更少块. 只在训练长度内得到的 recall 不能推出更长上下文稳定.

### 8.3. 稠密回退怎样使用

回退路径适合三类情况: 序列短到稀疏没有收益, 模型或 shape 不在已验证配置中, 线上监控发现质量或数值异常. 回退应在请求开始前由明确条件选择, 避免某一层候选为空时静默切到稠密, 使延迟分布难以解释. 影子评测可以抽样运行稠密对照, 但主流量双算会抵消节省.

回退也不能掩盖实现错误. 固定索引的单元测试若不过, 应修正 kernel; 路由覆盖不足, 才考虑增加预算、重新训练或重新校准. 把所有异常都切回稠密, 最终只能得到一个偶尔加速且不可预测的系统.

### 9. 从索引到 kernel 的验收表

#### 9.1. 索引表示会反过来限制算法

候选集合可以用四种常见形式传给 kernel. 第一种是稠密布尔 mask, shape 为 $N_q\times N_k$. 它最容易验证, 却仍占平方空间, 极长序列下仅生成 mask 就可能成为瓶颈. 第二种是定长块号表 $J\in\mathbb{N}^{N_q\times k_b}$, 配合固定预算, 地址计算直接, 也是块稀疏实现最常见的接口. 第三种是 CSR 一类压缩行格式, 用 `row_ptr` 表示每行起止, 用 `col_idx` 保存所有候选. 它支持变长预算, kernel 的循环长度与负载更不规则. 第四种是隐式规则, 例如局部窗口、固定 sink 或斜线位移; kernel 根据 query 块号现场算出 key 坐标, 不需要写出完整索引.

混合路线通常同时使用多种表示. 局部窗口采用隐式规则, 动态块放在定长或 CSR 表里, 全局块只保存一份短列表. 这比把所有分支展开成统一 COO 坐标更省控制数据. 代价是 kernel 必须合并多个来源, 并处理重叠. 若先在主机端把分支展开、排序和去重, GPU attention 会等待 CPU; 若在 GPU 上做通用集合运算, 小整数算子又可能占据显著时间. 更常见的选择是从规则上减少重叠, 例如动态 top-k 明确排除局部窗口覆盖的块.

索引 dtype 也有边界. 16 位整数能表示的块数有限, 但在百万 token、64 token 一块时仍只有 15625 个块, 单条序列可容纳; batch 偏移、物理页号或全局地址可能超过范围. 32 位索引更稳妥, 控制数据与带宽翻倍. 采用相对位移可以压缩局部候选, 任意远程块仍要绝对编号. 编码之前应先明确编号对象是序列内逻辑块、batch 展平后的块, 还是 KV 分页器里的物理页.

排序索引不会改变 softmax 结果, 却可能显著改变缓存行为. 同一个 query 行的 key blocks 若按物理地址升序访问, K/V 加载更连续; 按路由分数排序没有数学优势, 因为在线 softmax会正确合并任意顺序. 多个 query 行之间还可以按候选签名分组, 让相似工作项连续执行. 分组本身需要排序或哈希, 只有复用收益大于整理开销时才值得.

#### 9.2. 块摘要也属于缓存状态

训练时可以从当前 K 临时计算摘要, 推理服务更适合在写 KV Cache 时同步写入. 若每产生一个完整块就计算 $c_j$, 摘要数量随序列线性增长. 当前未满块需要增量状态. 对均值摘要, 保存向量和与计数即可:

$$
s_j^{(t)}=s_j^{(t-1)}+k_t,\qquad
c_j^{(t)}=\frac{s_j^{(t)}}{r_j}, \tag{11}
$$

其中 $r_j$ 是当前块已有 token 数. 学习型压缩器可能需要保留一小段 token 到块完成后统一前向, 或支持流式更新. 摘要更新发生在 KV 量化之前还是之后也会影响一致性. 若路由器在 FP16 key 上训练, 部署却从 INT4 KV 解码近似摘要, 路由误差与主 attention 量化误差会叠加.

prefix cache 复用时, 只复用原始 KV 而重新扫描前缀生成摘要, 会让长前缀命中的延迟收益缩水. 摘要应与 prefix block 使用相同的内容哈希和引用计数. 当多个请求共享物理 KV 页时, 摘要也可以共享, 因为它只由 key 内容决定; query 相关的 top-k 索引不能共享, 除非 query 状态也相同.

滑动窗口删除旧页后, 逻辑位置可能继续增长而物理页循环复用. 路由索引不能把物理槽号当成永久块 ID. 一种稳妥的协议是让路由器输出请求内单调逻辑块号, KV 管理器在 attention 启动前读取当前 block table 完成映射. 这样分页器可以搬迁页面, 路由语义保持不变. 映射表若在 CPU, 每步传输会成为新开销; 生产实现通常要求它常驻设备.

#### 9.3. 正确性

先构造小尺寸张量, 手写每个 query 块的索引. 覆盖第一个块、最后一个不足整块的尾部、重复索引、空动态分支、当前块因果三角以及 packed sequence 边界. 对同一索引运行朴素实现与目标 kernel, 逐层比较 logits 行最大值、指数和和最终输出. 只比较最终生成 token, 会让误差经过几十层后才暴露.

GQA 要验证 $h_q\mapsto h_{kv}$ 映射. tensor parallel 要验证本地 query head 使用正确的全局路由配置. 如果索引按全局块号生成而 K/V 在各 rank 分片, 还要明确块号到本地地址的转换. 一个错误配置通常 shape 完全合法, 结果也未必出现 NaN, 因而需要特定断言.

#### 9.4. 性能

至少记录 $T_{route}$、$T_{select}$、$T_{attn}$ 和整层时间. CUDA 异步执行要求在计时边界同步或使用事件; 首次编译与稳态分开. 同时记录序列长度、batch、query/KV head、$d_h$、dtype、块大小、每行唯一 tile 数、候选长度分布和硬件版本. 缺少这些条件, 倍数无法复现.

与稠密 FlashAttention 比较时使用同一 QKV 布局、同一 dtype 和同一 causal 语义. 稀疏实现若省略 padding 而稠密基线处理大量 padding, 比较会把变长打包收益算进注意力方法. 反过来, 稀疏实现若额外转置和复制, 也要计入端到端路径, 不能只截取最内层 kernel.

#### 9.5. 服务状态

KV block 摘要、索引缓存和原始 KV 的生命周期要一致. prefix cache 命中时, 摘要也应复用或可由缓存重建; 请求被抢占并恢复时, block 数和位置偏移不能变化; sliding window 丢弃旧 KV 时, 相应摘要与块号也要更新. 索引状态若仍指向已释放页面, 错误会表现为静默读取另一请求的数据, 远比普通精度下降严重.

Paged KV Cache 下, 逻辑块与物理页未必相同. 路由器输出逻辑 token block, block table 再映射到物理页. 若注意力块跨两个页面, kernel 需要两次加载或调整块对齐. 因此算法块大小最好与分页粒度协同, 但两者服务的目标不同: 算法块控制召回, 物理页控制内存分配. 强行设成同一个值可能牺牲其中一侧.

### 10. 阅读顺序与路线导航

[哈希与聚类](./01-哈希与聚类.md)从向量生成内容桶, $O(n^{3/2})$ 来自中心打分与桶内配对的平衡, 训练、Prefill、Decode 则各自维护索引. LSH 碰撞与在线中心更新的手算还能直接说明一件事: **索引本身也是算子, 它同样消耗计算、状态和同步.**

再读[MInference](./02-MInference.md), 可以把同一套判断用于免训练 Prefill. 重点是离线按 head 选模式与在线索引的分工, 三类形状如何变成不同 tile, 以及在线 softmax怎样跨稀疏 tile 合并. 如果只关心已有模型的百万 token prompt 加速, 可以直接从这一篇进入, 但仍应回看前篇的 recall、重复候选与索引成本口径.

MoBA 与 NSA 也属于粗粒度动态选择的重要节点. 前者强调块级门控, 后者把压缩、选择与局部分支共同纳入训练. [NSA](../04-训练原生稀疏/01-NSA.md)已有独立解析; MoBA 应沿「块摘要—top-k—当前块因果注意力—稀疏 kernel」这一链条阅读. 路线首页提供共同坐标, 具体论文页负责参数、实验与代码路径.

下一层的细粒度 indexer 会把候选生成压到 token 或小组级, 常用低维代理分数先召回、再由原 QK 精排. 它能减少块内多算, 同时更容易被 top-k、随机访存和 KV 反量化限制. 跨层共享则进一步复用 main KV、indexer K 或 top-k 索引, 用较旧的路由结果换取更低开销. 三条路线应使用同一质量和性能口径, 才能比较节省来自稀疏本身还是来自共享.

**阅读任何动态路由方案时, 先沿数据路径逐项核对: 路由输入是什么, 索引 shape 是什么, 候选何时生成, 完整 KV 何时读取, softmax 在哪里归一化, 缓存保存什么, 未命中怎样影响后续层.** 这些问题能把相似的热图还原为不同的训练与执行机制.

## 11. 粗粒度路由的统一数学对象

把长度为 $N$ 的序列切成 $B=\lceil N/b\rceil$ 个块，每块最多 $b$ 个 token。第 $u$ 个 query 块记为 $Q_u\in\mathbb R^{b\times d}$，第 $v$ 个历史块为 $(K_v,V_v)$。路由器先为块生成摘要 $c_v=f(K_v,V_v)$，再计算

$$
s_{uv}=g(Q_u,c_v),\qquad
\mathcal I_u=\operatorname{TopK}_{v\le u}(s_{uv},k).
$$

稀疏注意力只展开候选集合中的原始 K/V：

$$
O_u=\operatorname{Attn}\left(Q_u,
\operatorname{Concat}_{v\in\mathcal I_u}K_v,
\operatorname{Concat}_{v\in\mathcal I_u}V_v\right).
$$

这三步分别对应「压缩」「检索」「精算」。摘要并不直接替代原始 Value，它只决定哪些原始块值得读取；因此质量取决于 $f,g$ 的召回，性能取决于摘要生成、全块打分、top-k 和稀疏核的总成本。只计算最后一项，会把路由器当成免费组件。

若每个 query 块与全部 $B$ 个摘要打分，索引复杂度约为 $O(B^2d_r)$，其中 $d_r$ 是路由维度；精算部分约为 $O(Bkb^2d)$。代入 $B=N/b$：

$$
C_{route}=O\left(\frac{N^2d_r}{b^2}\right),\qquad
C_{attn}=O(Nkbd).
$$

块越大，路由矩阵越小，块内多算越多；块越小，候选更精确，top-k 与不规则访存更重。这不是单调的「块越细越好」。设相关 token 在命中块内平均只占比例 $\rho_b$，每读取一个有效 token 需要搬运约 $1/\rho_b$ 个 token；$\rho_b$ 随块变小上升，kernel 效率却可能下降。最佳块大小由召回曲线、显存带宽和 tile 形状共同决定。

局部窗口、全局 sink 与动态块最好写成集合并集：

$$
\mathcal N_u=\mathcal L_u\cup\mathcal G\cup\mathcal I_u.
$$

实现前要去重。若同一块出现在局部和动态集合里，数学上只能进入 softmax 一次；重复加载后把两份 logit 当作两个元素，会把该块概率质量近似翻倍。正确的 kernel 可以分别遍历多个分支，但在线 softmax必须以唯一逻辑位置合并。性能报告也应使用唯一 tile 数，否则名义稀疏率和实际读取量不一致。

### 摘要是检索键，不是块的完整语义

均值池化摘要 $c_v=b^{-1}\sum_iK_{v,i}$ 隐含假设：同一块内与未来 query 相关的方向能够在线性平均后保留。若块内大多数 token 属于主题 A，只有一个 token 含关键实体 B，均值会把 B 稀释。最大池化保留各维极值，却可能把来自不同 token 的维度拼成一个不存在的向量。学习型压缩器能针对训练分布调整，仍受固定维度的信息瓶颈限制。

一个块同时含互不相关的两段事实时，单摘要尤其危险。对查询 $q_1,q_2$，理想打分分别由不同 token 决定：

$$
s_v(q_1)=\max_{i\in v}q_1^Tk_i,qquad
s_v(q_2)=\max_{i\in v}q_2^Tk_i.
$$

单个中心 $c_v$ 未必同时逼近两个最大值。多摘要可把块切成若干子中心，召回提高，控制数据和打分又相应增加。粗粒度路线的上限因此与块内语义熵有关：内容越混杂，单摘要越难代表；若输入天然按文档、段落或函数边界分块，摘要会更可靠。

摘要训练还存在目标错位。用语言模型 loss 端到端学习时，梯度偏向高频、容易影响下一个 token 的关系；真正的长程关键事实出现稀少，可能被平均 loss 淹没。额外的检索监督可以用稠密 attention top mass、已知引用边或任务答案位置构造，但每种标签只代表一种相关性。稠密 attention 本身也可能分散或错误，不能自动视为真值。

### Query 块共享候选的代价

为了让 kernel 规整，常让一个 query 块的所有 token 共享 $\mathcal I_u$。若块中不同 token 需要不同历史，候选取并集才能维持召回。设每个 query token 各需 $k_0$ 个块，彼此重叠率低，块级并集可能接近 $bk_0$，稀疏收益迅速消失；若只取固定 $k$，则部分 token 必然漏召回。

可以用每个 token 的理想候选集合 $S_i$ 定义共享损失：

$$
L_{share}=1-\frac1b\sum_{i\in Q_u}
\frac{|S_i\cap\mathcal I_u|}{|S_i|}.
$$

相邻 token 的语义连续时，$S_i$ 重叠较高；代码跳转、表格列和多问题拼接会让重叠下降。评测应按输入类型报告，而非只给平均 recall。自适应 query 块可在语义边界切分，但动态 shape 会增加调度难度；固定物理 tile 加逻辑子组是一种折中。

### 12. 路由训练的梯度与不可微选择

top-k 是离散操作。若只有被选块进入 attention，未选块无法从主 attention 输出获得直接梯度，路由器容易延续早期的错误选择。常见缓解包括连续松弛、辅助蒸馏、共享可微分支和探索候选。四种方法改变的假设不同。

连续松弛在训练时对所有或更多摘要做 softmax，使用概率加权近似硬选择：

$$
\tilde c_u=\sum_{v\le u}p_{uv}c_v,qquad
p_{uv}=\frac{e^{s_{uv}/\tau}}{\sum_je^{s_{uj}/\tau}}.
$$

温度 $\tau$ 降低时分布更尖，接近硬路由；训练仍计算全部摘要贡献，省算只在推理出现。松弛目标优化的是摘要混合，不完全等于选择原始 K/V。若多个摘要的线性组合能表达答案，而任何单个 top-k 集合都不够，训练—推理会出现离散化缺口。

蒸馏让路由分数拟合稠密 attention 聚合质量。令块质量

$$
m_{uv}=\sum_{i\in Q_u}\sum_{j\in K_v}\alpha_{ij}^{dense},
$$

可用 KL、排序或 top-k recall loss 训练 $s_{uv}$。它给所有块监督，代价是训练需要稠密 teacher，长序列上成本高；并且 $m_{uv}$ 偏爱总质量大的块，一个只对单个关键 query 有高权重的块可能仍被平均淹没。使用最大值或高分位聚合能保护尖峰，又会让路由对噪声异常值敏感。

共享可微分支让摘要注意力始终参与输出，NSA 一类结构正利用这一点。即使某块未进入精细选择，它仍通过压缩分支获得梯度。隐含假设是适合低分辨率压缩注意的块，也应在高分辨率阶段被选中。若摘要足以提供主题，却丢掉块内精确数值，压缩分支可能认为它不必精读，选择分支反而漏掉关键细节。

探索候选在训练中给 top-k 外块少量随机机会，类似路由器的探索。随机率太低无法纠正早期偏差，太高又增加计算并扰动优化。可以按路由不确定性分配：top-k 边界分差小时增加探索，分数稳定时减少。探索样本的梯度要区分「被路由器主动选中」和「随机插入」，否则随机命中会被误当成当前排序正确。

负载均衡也不等于语义召回。若把历史块视作专家，均衡损失会鼓励不同块被相近频率选择；真实文本中近期块、系统提示或关键定义本就更常用。强行均衡可能牺牲质量。容量约束适合限制极端热点和硬件拥塞，目标应是允许符合数据分布的偏斜，同时避免少数块让所有 query 集中读取。

#### 路由器坍缩的三种形态

第一种是位置坍缩：无论内容都选最近若干块，动态分支退化成更宽局部窗口。第二种是 sink 坍缩：总选开头或特殊 token 所在块。第三种是主题坍缩：高频领域块长期占据候选，稀有事实很少被检索。只看负载直方图能发现前两类的一部分，无法判断选择是否正确。

诊断需要条件化统计。比较固定相对位置下的内容扰动，检验路由是否随语义变化；打乱块顺序但保留位置编码，观察选择是否跟内容移动；插入相似干扰块，测量目标块的名次变化；按领域和频率分桶报告召回。若交换内容后候选仍固定在原位置，路由器主要学了位置先验。

位置先验并非全无价值。语言本来具有强局部性，稳定局部分支可以直接编码它，让动态分支专注非局部关系。把两者混在一个 top-k 路由器中，容易让便宜的近期命中占满预算。候选集合先预留局部窗口，再从其余历史中动态选择，能把职责分开；训练损失也应单独评估动态分支是否提供新增覆盖。

## 13. 选择误差怎样传到注意力输出

设稠密注意力概率为 $\alpha_j$，候选集合为 $S$，漏掉的概率质量为 $\delta=\sum_{j\notin S}\alpha_j$。稀疏注意力在 $S$ 内重新归一化：$\hat\alpha_j=\alpha_j/(1-\delta)$。若 $\|v_j\|\le V$，输出误差满足

$$
\left\|\sum_j\alpha_jv_j-
\sum_{j\in S}\hat\alpha_jv_j\right\|\le2V\delta.
$$

这个上界说明应该测概率质量覆盖，而非只数 top token 命中率。它仍很松：被漏 Value 方向互相抵消时实际误差小；一个低概率但 Value 范数极大的 token 会违反统一 $V$ 的温和假设。多层网络还会经残差、归一化和非线性放大或吸收误差，单层覆盖率不能完全预测最终任务。

块级召回有两层误差。路由器先决定目标 token 所在块是否入选；块入选后，原始 QK softmax 再决定目标 token 的权重。若块摘要与具体 token 相关性不一致，第一层漏掉；若候选包含很多干扰 token，第二层被重新归一化稀释。扩大块可以减少第一层漏召回，却增加第二层竞争和读取成本。

多头注意力还会放大稀有失败。平均所有 head 的覆盖率很高，某个专门负责引用、分隔或位置的 head 仍可能持续漏召回。若各 query head 独立路由，索引量和分歧增加；若 GQA 组共享候选，组内 head 需求冲突。可以取组内分数最大、均值或并集：最大保护任一 head 的尖峰，均值偏向共识，并集最稳但预算膨胀。选择应与实际 kernel 的 head 分组一起评测。

长度增长会改变极值。候选块从 512 增至 8192，即使无关分数分布不变，最大噪声分数也会上升，目标块名次可能下降。固定 top-k 的覆盖比例同时缩小。训练在 32K、推理到 1M 时，路由器面对的并非同一分类问题。可以按长度校准分数、分层检索或让 $k$ 随候选数缓慢增长，仍要实测额外成本。

分层检索先在大区段中选若干，再在区段内选细块，复杂度从全量打分降下来。它引入级联召回：目标若在第一层被删，第二层无从恢复。总召回近似受各层召回乘积限制。例如两层各 95%，联合上限约 90.25%。层数增加前要确保每层非常高的召回，或保留跨层旁路候选。

### 14. 因果掩码、位置与块边界

自回归注意力要求 query 只能访问当前位置之前。完整历史块满足矩形因果关系，当前 query 块对应的 key 块需要块内三角掩码。若路由器以整块摘要打分，摘要不能包含 query token 尚不可见的未来位置。训练时一次并行计算全序列，最容易在这里发生泄漏。

对第 $u$ 块第 $r$ 个 query，当前块摘要只能由 $0\ldots r$ 的 key 构造。若预先计算整块中心再供块内所有 query 使用，前部 token 已间接看见后部 key。安全做法是当前块始终走局部三角分支，不参与动态历史摘要；完整块结束后才写入索引。若需要块内动态选择，则使用前缀可更新摘要，并验证每个位置的可见范围。

packed sequence 把多条样本放在同一张量中，块可能跨样本边界。仅按全局位置 $v\le u$ 过滤不够，候选还需匹配 sequence ID。末尾不足整块的 padding 不能进入摘要和 softmax。一个越界块可能读取另一用户或另一训练样本的 KV，既是正确性错误也是数据隔离问题。

RoPE 等位置编码通常在 K 上携带绝对或相对位置信息。摘要若直接平均已旋转 K，不同位置相位可能抵消；先聚合未旋转表示再选一个代表位置，又会扭曲查询相关性。可学习路由器常使用独立低维投影与位置特征，主 attention 仍读取原始带位置 K。路由分数与最终 QK 因此属于两个空间，需要专门测量排序一致性。

块边界人为切断连续片段。重叠块能让边界 token 出现在两个摘要中，提高召回，却产生重复候选和更多状态。按语义边界切分可减少混杂，但块长不规则，kernel 仍需落到固定 tile。可采用逻辑段落映射到若干物理 tile：路由按逻辑段落打分，执行展开为物理块；超长段落再分片，短段落合并时保留子段标识。

位置外推还会影响路由先验。训练长度内「很远」可能是 16K，百万上下文中它只是相对近处。若路由分数直接使用绝对块号嵌入，未见位置缺乏校准。相对距离桶、对数距离或内容主导的打分更容易外推，但模型仍可能依赖训练中的长度分布。评测必须覆盖超过训练长度的多个点，观察召回和候选距离分布怎样变化。

## 15. Prefill 与 Decode 的两个成本函数

Prefill 同时拥有大量 query，可以把块路由写成矩阵乘并形成大批次稀疏 tile。Decode 每步通常只有一个新 query，历史 KV 很长，索引与内存访问更难摊薄。同一稀疏模式在 Prefill 上加速，并不保证在 Decode 上有效。

Prefill 将 $B$ 个 query 块与 $B$ 个历史摘要打分，形成下三角路由矩阵。若路由维度 $d_r$ 较小，这一步可用 GEMM 高效完成；随后 top-k 选择和候选重排仍可能产生同步。稀疏 attention 的 query tile 足够多，GPU 可以并行调度。主要问题是是否要为整层保存 $B\times k$ 索引，以及反向传播时如何重算路由。

Decode 每生成一个 token，只需对 $B$ 个摘要打分，算术量为 $O(Bd_r)$，却要读取全部摘要。摘要缓存若每块一个 $d_r$ 向量，长度百万、块 64、$d_r=128$、FP16 时约为

$$
15625\times128\times2\approx4\text{ MB/层/请求}.
$$

32 层便约 128 MB，还未计算原始 KV。若每层独立摘要，索引缓存并非可以忽略。共享层间路由或压低 $d_r$ 能减小成本，也可能损失各层不同的相关性。

Decode 的 top-k 对短向量并不总是便宜。打分 GEMV、选择、逻辑块到物理页映射、K/V gather 和 attention 之间多次 kernel launch，会让算术节省被控制开销吞掉。融合打分与选择、固定 $k$、让摘要和 block table 常驻设备能减少开销；若候选数很大，分层检索或近似最大内积搜索才可能必要。

Prefill 的路由可以利用整段 query 块摘要，Decode 只能用当前 token 隐状态。这会改变候选质量。块内多个 query 的合并能覆盖不同需求，单 token 打分更尖锐也更不稳定。把 Prefill 索引沿用到后续 Decode 可以省计算，却假设新 token 的信息需求与 prompt 尾部相似；对生成中途转题、引用早期细节或工具返回插入的新内容，这个假设会失效。

一种折中是分层更新：局部窗口每步变化，远程动态候选每 $m$ 步更新，中间复用。若路由集合随 query 的变化速度较慢，可明显降低索引成本。可以用相邻步候选 Jaccard 相似度

$$
J_t=\frac{|\mathcal I_t\cap\mathcal I_{t-1}|}
{|\mathcal I_t\cup\mathcal I_{t-1}|}
$$

判断复用潜力。平均相似度高仍不足以保护关键转折，应单独观察候选骤变的 token，例如新问题、否定词、代码符号或工具结果到达之后。

训练阶段还包含梯度和激活。硬选择只保存选中 K/V 的 attention 激活，却要为路由器保存摘要、分数或重算所需输入。若用稠密蒸馏监督，训练成本可能仍接近全注意力。所谓「训练原生稀疏」需要明确前向、反向和辅助 loss 都没有偷偷恢复平方主项；若只在推理使用稀疏，收益属于部署优化，不应混写为训练扩展。

### KV Cache 与索引缓存的一致性

原始 KV、块摘要、候选索引和分页表构成一组派生状态。写入新 token 时先更新 KV，块完成后生成摘要并发布；若摘要先可见而 KV 尚未持久，路由可能选到无法读取的块。可以给每个逻辑块设置状态 `open`、`sealed`、`evicted`，动态检索只访问 sealed，当前 open 块由局部分支处理。

Prefix cache 命中时应同时命中摘要。若缓存只保存 KV，服务每次仍需扫描长前缀生成索引，首 token 延迟会很高。摘要的 cache key 包含模型层、路由器版本、量化方式和块边界；主模型权重相同但路由器更新后，旧摘要未必兼容。候选索引依赖 query，一般不能只凭前缀共享。

Paged KV 把逻辑连续块映射到不连续物理页。路由器输出逻辑块号，attention 启动前经 block table 翻译。请求抢占和恢复会搬迁物理页，逻辑号保持稳定；若索引直接缓存物理地址，恢复后可能读取另一请求的数据。所有跨步缓存的候选都要在使用时重新映射或绑定页 generation。

量化会同时影响主 attention 与路由。若摘要从量化前 K 计算并以 FP16 保存，路由质量较好，却多占缓存；若从 INT4 K 反量化生成，摘要误差与最终 K/V 误差相关。更危险的是训练路由看 FP16、部署路由看低比特摘要，top-k 排名在分数接近处频繁翻转。需要测路由 margin 与量化扰动：第 $k$、$k+1$ 名分差小于扰动尺度时，候选不稳定。

滑动窗口或内存淘汰删除旧 KV 后，对应摘要必须同步删除。若逻辑位置继续增长，候选空间中会出现空洞；top-k 前要 mask 无效块。异步删除时，路由打分和 gather 之间可能发生竞态，可通过引用计数或版本化快照保证一次 attention 使用一致的 block table。

### 16. 三类粗粒度路线的归因差别

哈希与聚类路线先按内容重组邻接图。Routing Transformer 让 token 只与同簇内容和局部邻居交互，候选关系来自聚类中心；Reformer 通过 LSH 碰撞近似相似 QK。它们改变模型训练时看到的图，优势是稀疏结构从一开始就参与表示学习，代价是桶更新、排序和碰撞本身需要状态，且因果序列上的在线维护较复杂。

免训练空间模式路线先观察稠密模型的 attention 热图，再选择竖线、斜线、块等规则。MInference 的核心价值在于把不同 head 的稀疏形状映射到可执行 kernel，适合长 prompt Prefill。它近似已有稠密模型，不要求重新训练；也因此受原模型 attention 模式、校准样本和 Prefill 场景限制。把它与原生动态路由混成一种方法，会忽略训练目标和 Decode 状态的差异。

MoBA 一类块门控把每个 key/value 块视作候选专家，query 对块表示打分后选 top-k，再在块内做标准注意力。它使选择逻辑清楚，便于块稀疏 kernel；当前块还需因果处理。模型可在训练中适应门控，却面临不可微 top-k、负载和块摘要代表性问题。

NSA 把压缩、选择与滑窗并列。压缩分支给全局低分辨率覆盖，也为选择器提供连续训练信号；选择分支恢复少量原始块细节；滑窗保护局部关系。它缓解单一路由失败的风险，三分支各自的 K/V 投影、门控与缓存也增加复杂度。其「原生」指训练目标中已有该结构，不能简化成给稠密模型外挂 top-k。

DSA 等 token 级路线虽然常与 NSA 一起讨论，粒度已经不同。低维 indexer 对 token 或小组打分，能减少块内多算，top-k 更长、随机 gather 更重。粗粒度页适合解释块摘要和硬件 tile，细粒度页再讨论 proxy score、精排与 indexer；二者的质量指标可以共用，性能瓶颈却不一样。

CSA、HCA、HySparse 等后续路线可以落在同一坐标系中比较：候选单位是什么，索引器看到何种表示，路由结果是否跨 head、跨层共享，完整 K/V 在何时读取，局部与全局兜底占多少预算。技术名称本身不能替代这五个问题。某方案即使都叫 content-aware，如果只在大块间选与在 token 间选，其精度—访存曲线会完全不同。

#### 内容路由与结构路由可以组合

文档边界、代码函数、对话轮次属于结构先验，向量相似度属于内容证据。纯内容路由可能把多个相似但来源不同的片段混在一起，纯结构路由又可能漏掉跨段引用。可先按结构生成候选区段，再用内容分数排序；也可分别保留结构预算与内容预算，最后合并。

若先筛后排，总召回受第一层限制。比如结构层只保留同文档，跨文档引用永远无法进入。并列预算更稳健：局部、同结构、内容 top-k 和固定全局各占若干块。代价是预算碎片化，某一分支暂时无用时不能自动把容量让给其他分支。门控可动态分配预算，但会再次引入训练和负载问题。

层级语义也可以成为结构。浅层更依赖局部词法，深层更可能检索语义与任务指令；所有层用同一候选会节省索引，却限制层间分工。跨层共享适合相邻层，仍需用 oracle 对照测量每层独立 top-k 的收益上限。如果独立候选几乎相同，共享是免费优化；若深层候选变化明显，强制共享会丢能力。

### 17. 训练分布、长度与任务难度

动态路由学习的是训练分布中的相关性。短序列里局部窗口覆盖大部分历史，路由器很少需要远程块；长序列比例不足时，它会学会稳定选择局部和 sink，却没有足够梯度区分远程候选。训练课程应包含需要远程证据的样本，并让关键位置跨越不同距离和块边界。

简单 needle 任务可能被关键词相似度解决，不能代表多跳组合。更困难的样本包含多个近似实体、冲突事实、否定条件和需要联合两块的信息。若答案必须同时读取 A、B 两块，top-k 只命中其一仍失败。可以定义联合覆盖率

$$
C_{joint}=\Pr(\{A,B,\ldots\}\subseteq\mathcal I_u),
$$

它通常低于单块 recall 的乘积，尤其当多个证据路由分数相互竞争。评测要保留证据集合，而非只标一个答案位置。

训练长度混合也影响 top-k 难度。候选数不同，softmax温度和分数极值不同；直接混合 4K 与 128K，路由 loss 的尺度可能失衡。可以按长度归一分数、使用分位排名监督，或在每个长度桶内计算辅助 loss。任何校准都要在更长未见长度验证，避免只把训练桶对齐。

领域转移会改变块内语义。自然语言段落内部连贯，代码文件的定义与调用相隔很远，表格的相关 token 沿列分布，多轮对话又受角色与轮次约束。一个在书籍文本上学到的块摘要未必适合代码。比较路线时要给相同模型在多域上的候选覆盖、块内有效比例和任务结果，不能只用平均困惑度宣称通用。

路由错误还会自我强化。早期层漏掉关键证据，后续 hidden state 已缺少相关线索，深层路由器更难把目标找回来。局部与压缩兜底提供一部分恢复通道；也可让浅层候选在深层保留少量、或周期性设置高预算层。高预算层像重新同步点，成本可控，但需要证明它确实修复了累积误差。

微调阶段若改变任务分布，路由器是否一起更新是重要选择。冻结路由保留预训练稳定性，可能无法适应新领域；全量更新容易在小数据上把候选偏向任务模板。可以降低路由学习率、保留通用校准集或只调门控与少数深层。评测同时观察新任务和原领域的候选分布，路由遗忘往往先于语言模型总 loss 暴露。

### 18. 一套可证伪的评测矩阵

第一轴是索引 oracle。使用稠密 attention 聚合后选最优块，得到给定粒度和预算下的近似上限；实际路由与 oracle 的差距属于 indexer；oracle 自身与稠密模型的差距属于块粒度和稀疏预算。没有 oracle，质量下降无法归因是路由没学好，还是 $k$ 太小。

第二轴是执行一致性。固定同一候选，朴素 masked attention 与目标 kernel 应一致。这里失败属于实现，不应通过增加训练补救。测试覆盖因果尾块、重复候选、空候选、GQA、packed sequence、非整块长度和量化 KV。

第三轴是候选扰动。随机替换一个高分块、交换目标与干扰、移动证据跨块边界、扩展无关前缀，观察输出和任务如何变化。真正使用内容的路由应跟随证据移动；只记位置的路由会留在原处。对抗干扰能测 margin，而普通 recall 只看目标是否偶然入选。

第四轴是预算曲线。对多个 $k,b,d_r$ 报告质量、路由时间、attention 时间、峰值显存和有效带宽。单个工作点无法判断方法是否优于简单加宽窗口。若提高 $k$ 后质量迅速恢复，主要限制是预算；若仍不恢复，摘要或训练目标存在问题。

第五轴是长度与阶段。Prefill 和 Decode 分开，训练长度内与外推长度分开，短请求回退路径也单列。每个点给候选数、唯一 tile、摘要缓存、P50/P99 和任务指标。只有端到端延迟随长度的曲线，才能看见索引何时超过节省。

第六轴是失败分层。记录目标块未入选、入选但目标 token 权重低、候选正确但 kernel 错误、环境或任务本身失败。对于多跳任务，还记录缺了哪一块。将全部失败压成准确率，会让改进方向变成猜测。

一个结论若声称「内容路由优于固定窗口」，应在相同 KV 预算、相同局部兜底、相同 kernel 质量和相同训练 token 下比较；如果声称「硬件友好」，就要把路由、top-k、索引整理和 gather 包进端到端时间；如果声称「长上下文泛化」，就要展示超过训练长度的联合证据任务。三类主张分别需要质量、系统与外推证据，不能用其中一张表替代全部。

## 19. 从稠密注意力到块选择的误差分账

粗粒度方案经常把所有质量差异归给「稀疏率」，实际至少有五项误差。第一项来自底座变化：原生稀疏模型和稠密模型可能训练 token、参数或超参不同。第二项来自候选预算：即使拥有完美 oracle，固定 $k$ 也可能覆盖不了全部相关块。第三项来自摘要和路由器，实际候选与 oracle 不同。第四项来自稀疏 kernel 数值和 mask。第五项来自训练—部署配置差异，例如量化、长度和缓存复用。

可把任务损失差粗略写成一组干预量：

$$
\Delta L=\Delta L_{base}+\Delta L_{budget}+
\Delta L_{router}+\Delta L_{kernel}+\Delta L_{deploy}+\epsilon.
$$

这些项不严格可加，$\epsilon$ 包含交互；它们仍能指导实验。使用同一 checkpoint 与精确 masked kernel 固定底座和执行，oracle 候选估计预算上限；把 oracle 换成学习路由器得到 indexer 差距；最后换目标 kernel 与线上缓存，测实现和部署。若一开始只比较完整系统，任何下降都无法定位。

Oracle 也有多种定义。按稠密 attention 概率质量选块，目标是近似当前模型；按删除某块后的 loss 增量选，目标更接近因果贡献，但需要大量前向；按任务标注证据块选，目标是人工语义，却未必覆盖模型实际依赖。三种 oracle 的候选不一致很正常，报告时说明它回答的问题。路由器超过 attention-mass oracle 也不矛盾，它可能学会了对最终任务更有用的选择。

预算误差存在不可消除的反例。构造一个 query 需要从 $k+1$ 个不同块各取一个独立比特，答案是它们的奇偶校验。任何只读 $k$ 块的路由，无论摘要多强，只要摘要不携带原始比特，就无法保证正确。增加训练不能突破信息访问上限。局部或压缩分支若已经把所有比特聚合进状态，问题才改变；这也说明比较选择分支时要注明其他分支提供了多少全局信息。

摘要容量同样有信息上限。把含 $b$ 个任意 $d$ 维 key 的块压成一个 $d_r$ 维向量，要求它对所有未来 query 保留精确最大内积，一般做不到。数据分布具有低维结构时近似才有效。路由论文的经验成功，本质上说明语言与模型表示中存在可利用结构，不等于对任意序列都有保证。对随机 key、对抗 key 与真实文本分别评测，可以看见方法依赖何种结构。

### 手算一次质量—成本工作点

设上下文 $N=131072$，块大小 $b=64$，共有 $B=2048$ 块。每个 query 块保留局部 4 块、动态 12 块和全局 2 块，去重后平均 16 块。物理 token 对数量约为

$$
B\times b\times16b
=2048\times64\times1024
=134{,}217{,}728.
$$

稠密因果注意力有效 token 对约为 $N^2/2\approx8.59\times10^9$，名义关系数降到约 1.56%。如果动态与局部平均重叠 2 块而实现未去重，执行 18 块，实际比例升到约 1.76%，还可能产生概率错误。这个差异看似只有 0.2 个百分点，对多层大 batch 已是可观读取量。

再设路由维度 $d_r=128$，每个 query 块与全部历史摘要打分。下三角分数约 $B(B+1)/2\approx2.1$ 百万，每个分数做 128 维点积，约 2.7 亿乘加。主稀疏 QK 若 head dim 128，单 head 约 1.34 亿 token 对乘 128，仍大得多；但路由 GEMM、top-k 和 gather 的硬件效率与主核不同，不能只用 FLOPs 比例推导时间。

假设稠密 attention 概率质量覆盖均值 97%，P1 只有 72%。平均困惑度可能变化很小，关键 query 的输出上界却松得多。把动态预算从 12 增到 20 后，均值到 98.5%、P1 到 90%，物理关系数约升至 2.34%。是否值得取决于任务是否集中在低分位和延迟预算；只给平均覆盖会让 12 块看起来已经足够。

若摘要缓存每层为 $2048\times128\times2=0.5$ MB，32 层单请求约 16 MB。原始 GQA KV 假设 8 个 KV head、head dim 128、FP16，约为

$$
2\times N\times8\times128\times2\approx512\text{ MB},
$$

摘要约占 3%。这个比例可接受；换成每个块 8 个摘要、每层独立，便升到约 24%，索引不再轻量。具体结论必须带上层数、KV head、dtype 和摘要数。

### 20. 与细粒度 Indexer 的分界

粗粒度路由读取一个块，就支付整块 K/V；细粒度 indexer 试图在块内继续找 token 或小组。两者共同目标是减少主 attention 的候选，区别在候选控制数据和内存访问。粗粒度浪费块内无关 token，却能连续加载并使用标准 tile；细粒度更精准，却要保存更长索引并做离散 gather。

设粗粒度命中 $k_b$ 个块，每块 $b$ token，其中有效比例 $\rho$；有效 token 数约 $k_bb\rho$，实际读取 $k_bb$。细粒度若读取同样数量的有效 token，理想可省 $1/\rho$ 倍数据，但索引器必须为更多候选打分，gather 也可能无法达到连续带宽。$\rho$ 较高时粗粒度更合理，$\rho$ 很低且 indexer 足够便宜时细粒度才显出优势。

二级路线先粗召回块，再在块内精排 token。它避免全局 token 打分，召回上限受第一层约束。目标 token 若粗层漏掉，细层再准也没用。总成本为

$$
C=C_{block-route}+C_{within-route}+C_{gather}+C_{attn}.
$$

粗层 $k_b$ 太大，细排候选多；太小，联合召回下降。评测要画二维预算曲线，而非只调最终 token 数。相同总 token 预算下，不同 $(k_b,k_t)$ 能揭示瓶颈在粗召回还是块内浪费。

共享 indexer 可降低成本。多个 query head 共用候选、相邻层复用 indexer K、若干步复用 top-k，都把一次选择摊给更多 attention。共享也降低自由度：不同 head、层和时间可能需要不同历史。可以先测独立 oracle 的候选重叠，只有重叠高时共享才有依据。直接强制共享再观察模型是否适应，会把架构上限和训练能力混在一起。

Indexer 的训练标签常来自主 QK 或最终 loss。低维 proxy 分数要保持 top-k 排序，不必重建全部 logit。排序 margin 小时，轻微量化和投影误差就会翻转候选；margin 大时低维近似足够。因而除了 recall，还应报告第 $k$ 与 $k+1$ 名 margin、候选稳定性和误选块的概率质量。

粗粒度并未因细粒度兴起而失去价值。分页 KV、GPU tile 和分布式传输仍以块为自然单位；细粒度选择最终也可能把相邻 token 合并成物理块读取。合理层级往往是：粗索引决定在哪些页面找，细 indexer 决定页面内哪些 token 进入计算，kernel 再按硬件粒度打包。概念上的 token 稀疏与物理上的块加载可以同时存在。

### 21. 分布式训练与推理中的路由

上下文并行把序列块分到多个设备。若每个 query 都可能选择任意历史块，路由结果决定跨设备通信。先汇总所有摘要再打分，摘要通信量较小；选出远程块后仍需传 K/V 或把 query 发到持有设备计算。两种方案分别偏向 KV 传输和 query 传输，取决于 query 数、候选块和 head 数。

设每设备持有 $B/P$ 块，query 块选 $k$，远程比例约 $1-1/P$。直接拉取 K/V 的通信随 $kbhd$ 增长；发送 Q 到远程设备并返回部分 softmax统计，需要处理多个设备的全局归一化。每个设备可返回局部最大值 $m_p$、指数和 $l_p$ 与加权输出 $o_p$，再按在线 softmax公式合并。路由集合分散越广，参与设备越多，启动和同步越重。

可以给路由加入 locality-aware 成本，偏好本地块，但这会改变模型目标。通信便宜的候选未必语义相关。更稳妥的是先报告 oracle 候选的设备分布，利用放置和复制优化：高频 sink、共享前缀或热门块可以复制，长尾块保持分片。复制消耗显存，却能降低大量跨设备读取。

训练时负载由 query 选择决定。某设备持有的块成为热点，会接收更多远程请求，即使 token 数均匀分片，计算和网络仍不均衡。块放置可根据访问图分区，把经常共同访问的块与 query 靠近；访问图随模型更新，频繁迁移又有成本。固定按位置分片简单稳定，适合先建立基线。

Tensor parallel 分割 head 时，路由可以每个 rank 独立计算本地 head 候选，也可跨 rank 聚合后共享。独立选择保留 head 特化，无需候选同步，但 K/V 页可能被不同 rank读取；共享候选减少控制分歧，需通信路由分数或候选。GQA 中多个 query head 本就共享 KV head，可以先在组内共享，再决定组间是否合并。

流水并行使不同层位于不同 stage。跨层复用候选需要把索引随激活传递，控制通信增加很小，但下一层的逻辑块必须与前层一致；若层间改变 token 压缩或缓存布局，就不能直接复用。路由版本和块定义进入 pipeline metadata，避免 stage 升级后索引语义错位。

服务端 continuous batching 将不同长度请求混合。固定 $k$ 仍有不同候选数上限，CSR 变长格式会造成 warp 分歧；定长表便于批处理，可用无效 sentinel 填充。调度器可按长度、块大小和 $k$ 分桶，减少 kernel shape；过细分桶会降低批量。稀疏方法的吞吐要在真实请求分布下测，单一长度大 batch 容易夸大收益。

## 22. 稳定性、回退与线上监控

路由器分数的绝对尺度可能随层、长度和量化漂移。top-k 对单调缩放不敏感，对近邻 margin 很敏感；阈值路由则同时依赖尺度。监控候选数量、top-k margin、分数熵、距离分布和各分支门控，可以在任务指标下降前发现漂移。

线上无法对所有请求运行稠密对照，可以抽样影子计算较短前缀，或在少数层提高预算测量输出变化。若增加候选后 logits 变化异常大，当前路由可能漏掉重要块。这个信号不是答案真值，却能作为不确定性指标，触发高预算或稠密回退。

回退条件应在请求级或明确的层级决策中记录。短序列直接使用稠密通常更快；未知模型 shape、索引版本不兼容、候选为空或数值异常也应回退。回退比例、原因和额外延迟进入监控。若系统靠大量静默回退维持正确，平均加速无法代表稳定服务能力。

动态提高预算比全稠密回退更平滑。路由熵高、margin 低或任务进入关键阶段时增加 $k$；稳定局部生成时减少。这样把计算集中到不确定 query。校准时要检查不确定性与真实漏召回是否相关，否则模型可能对错误选择也很自信。

路由故障可能表现为重复文本、事实遗忘、引用错位和代码变量混淆，未必产生 NaN。监控可加入长程一致性探针：定期要求恢复早期随机标记、比较缓存前后固定 prompt logits、验证 prefix cache 命中与未命中结果。服务版本发布前对同一轨迹重放，候选与输出差异按层定位。

索引缓存属于用户状态，隔离错误会读取其他请求 KV。逻辑块号与物理页映射必须绑定 request、generation 和长度；复用内存前清理旧索引。安全测试构造两个请求使用相同物理槽，强制抢占和恢复，确认候选永不跨租户。质量回归不能替代这类隔离测试。

### 23. 内容上限与结论边界

粗粒度选择能够讲清的核心，是如何用块摘要把平方注意力变成「廉价全局检索加少量原始块精算」，以及这种转换在训练、缓存、kernel 和长度外推中付出什么代价。它不能仅凭统一公式断言某个具体系统更好，实际结论仍依赖论文 checkpoint、预算、硬件与任务。

Reformer、Routing Transformer、MInference、MoBA、NSA 分别覆盖哈希聚类、稠密模式近似、块门控与多分支原生稀疏。后续 CSA、HCA、HySparse 等路线需要在各自论文页依据正式材料解释具体结构；本页提供共同坐标和链接，避免把尚未公开或无法核查的细节补成事实。

理论误差界通常以稠密 attention 为参照，假设 Value 有界，并未保证下游任务。语言模型可以在稀疏结构下重新训练并形成不同表示，既可能弥补稠密近似误差，也可能学出新的脆弱路径。静态近似与原生训练的实验不能直接互换。

系统加速也没有脱离硬件的永久倍数。块大小、显存层级、top-k 实现、KV 量化、batch 和设备互联都会改变结果。可长期复用的是成本分解与验收方法：索引时间、唯一 tile、实际字节、端到端延迟和质量低分位；具体数字应随实现重新测量。

当一篇工作没有公开训练数据、完整 kernel 或长长度评测时，能确认的范围应停在公式与已报告实验。缺失证据应明确留下，不能用相邻路线的结果补齐。粗粒度选择的真正价值不在于承诺所有长上下文都能低成本解决，而在于提供一个可训练、可测量的候选接口，让「模型应该看哪里」成为独立研究对象。

## 24. 把稀疏图看成信息传播网络

一层注意力只允许 query 从候选邻居读取信息，多层堆叠后，信息可以沿稀疏边逐层传播。单层没有直连，并不代表最终无法影响；关键在图直径、边的稳定性和表示是否在中途保留。固定局部窗口经过 $L$ 层最多传播约 $Lw$ 的距离，动态远程边能缩短路径，却需要每一跳都选中正确中继。

令第 $\ell$ 层的有向邻接矩阵为 $A^{(\ell)}$，从位置 $j$ 到 $i$ 在 $L$ 层内可达，需要乘积图中存在路径：

$$
\left(A^{(L)}A^{(L-1)}\cdots A^{(1)}\right)_{ij}>0.
$$

这个可达性只说明拓扑允许，未保证信息强度。softmax权重、Value 投影、残差与非线性会让信号衰减。评测单层 top-k recall 时，也应检查关键证据是否在后续层持续可达。某层漏掉原位置后，前层可能已把信息搬到局部 token；把每层候选都与原始答案位置比较，会低估这种表示迁移。

反过来，依赖中继也会产生脆弱性。若关键事实必须经过三次动态选择，每次条件成功率 0.95，三跳联合约为 $0.95^3=0.857$。增加层数提供更多路径，也增加失误机会。全局 sink、周期性高预算层和压缩分支相当于给图增加稳定骨架，减少完全依赖随机动态边的路径。

图连通性还关系到训练。某些 token 长期没有入边，梯度很少经 attention 回到它们；路由器可能进一步认为它们不重要。可以统计每个位置的入度、跨层累计覆盖和长期孤立比例。均匀入度并非目标，但出现大批从不被读取的内容，说明有效上下文远小于名义长度。

块级路由把一个 tile 的所有 token 同时连入，图边粗而密；token indexer 的边细而精。前者更容易形成稳定连通骨架，后者有更高选择自由度。混合架构可以让少数块边保证可达，再由细粒度边提高有效信息比例。这也解释了为什么后续路线重视 indexer，却未必彻底抛弃块结构。

### 路由概率需要校准

top-k 只使用排序，无法告诉系统当前选择有多可靠。若将分数经 softmax 得到 $p_{uv}$，它也未必是「该块应被选择」的真实概率，因为训练目标、候选数量和温度都会影响尺度。可以在带 oracle 标签的数据上做可靠性图：预测置信度为 0.8 的块，实际进入 oracle 的比例是否接近 0.8。

校准后的置信度可以用于自适应预算。累积概率质量达到阈值 $\gamma$ 后停止选择：

$$
k_u=\min\left\{k:\sum_{v\in\operatorname{TopK}(p_u,k)}p_{uv}\ge\gamma\right\}.
$$

简单 query 使用少量块，分散 query 使用更多。若概率未校准，模型可能过度自信地选很少候选。还要设置最小、最大预算，防止空选择和长尾失控。

候选数随长度增长时，原 softmax概率会被更多无关块稀释。可以用温度、分数标准化或极值校准缓解，但这些方法都需要长度外数据。排名 margin 比绝对概率更稳定一些，仍受候选极值影响。线上预算策略应把长度作为显式条件，而非假设同一阈值通用。

校准标签选择也决定含义。以稠密 attention top block 为标签，置信度表示复现稠密模型；以任务证据为标签，表示检索人工证据；以反事实 loss 增量为标签，更接近因果贡献。三套概率不可混用。系统回退关心最终风险，应优先用与任务失败相关的校准，即使训练路由仍采用便宜的 attention标签。

## 25. 四个容易误判的反例

第一个反例是高 recall、错误输出。候选命中了全部标注证据，也额外引入一个高度相似的错误块。重新归一化后干扰块占据主概率，模型输出错误。召回只惩罚漏检，不惩罚强干扰；需要同时报告 precision、概率覆盖和输出误差。

第二个反例是低 recall、任务成功。前层已经把远程事实写进当前局部表示，后层不再访问原证据，却仍回答正确。按每层原始证据 recall 会判失败。应追踪表示搬运，或用移除候选后的任务差异判断当前层是否仍依赖原块。

第三个反例是高稀疏率、没有加速。候选只占 2%，但路由要扫描所有高维 K、top-k 分成多个小 kernel、gather 随机读取，batch 又太小，端到端比稠密 FlashAttention 更慢。名义 FLOPs 不包含索引和带宽。只有 profiler 与真实延迟能验证系统主张。

第四个反例是短长度稳定、长长度崩溃。路由器在 32K 对目标块有明显 margin，扩展到 1M 后无关块的最高分超过目标，固定 top-k 漏检。困惑度可能只略变，稀有检索任务却断崖下降。长度评测需要观察目标名次与 margin，而非只看最终均值。

这些反例共同说明，路由、注意力和任务属于三层对象。路由指标回答候选是否合理，注意力指标回答给定候选如何改变数值，任务指标回答模型是否完成目标。三层同时测量，才不会用一项好看数字代替整条因果链。

### 最小复现实验

复现粗粒度方案时，先选一个短到能运行稠密注意力的长度，保存逐层 Q、K、V 与稠密输出。按论文规则生成块摘要和候选，用朴素 mask 实现稀疏 attention；这一步不接目标 kernel，先确认块号、因果边界、去重和 softmax正确。随后计算候选概率质量、输出相对误差与任务结果，建立 oracle、实际路由和随机路由三条基线。

第二步替换成目标 kernel，固定候选逐项比较。若数值不一致，检查在线 softmax合并、GQA 映射、尾块和 dtype；此时不调整路由器。kernel 通过后再测路由、选择、gather 和 attention 的分项时间，warmup、编译与稳态分开。只有完整路径快于稠密基线，才进入更长长度。

第三步扩大长度，同时保持任务证据结构可控。每个长度记录目标块名次、top-k margin、候选距离、唯一 tile、摘要缓存和 P99 延迟。若任务下降，先用 oracle 候选判断预算上限；oracle 正常而实际路由失败，问题在索引；oracle 也失败，则需要增加预算、缩小块或改变多分支结构。

第四步改变领域和边界。把同一证据移动到块首、块尾和跨块位置，加入多个近似干扰；再测试自然语言、代码、表格和多轮对话。候选随内容移动、对边界不敏感且在干扰下保持 margin，才说明摘要捕获了可迁移相关性。

最后接入服务状态。Prefix cache 命中与未命中应给相同 logits，请求抢占恢复后候选逻辑块不变，KV 量化前后召回差异可解释，滑窗淘汰后没有悬空索引。再做跨租户页复用测试，确认逻辑—物理映射不会读到其他请求。至此，算法正确、kernel 正确和服务正确才形成闭环。

复现报告还应保留失败配置。某个块大小在短序列最快、到长序列却因 top-k 和 gather 变慢，或者某个摘要在自然语言有效、到代码上召回下降，这些都在界定机制。只发布最佳点会让读者误以为参数选择具有普遍性。将候选预算、块大小、路由维度与长度组成完整矩阵，再标出显存不足、kernel 不支持和质量越界的区域，才能看见可用工作区有多宽。工作区很窄的方法或许能刷新单点速度，却更难进入混合长度、混合任务的真实服务。

同样需要公开随机种子与重复次数。路由训练、任务采样和系统测时都有方差，单次最优结果无法说明工作点稳定。至少给中位数、离散范围和逐长度原始记录，读者才能区分真实机制收益与偶然调度优势。
