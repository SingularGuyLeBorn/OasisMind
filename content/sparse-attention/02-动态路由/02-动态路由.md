# 动态路由：从内容中选择注意力连接

静态窗口提前规定每个 query 能看见哪些位置，执行规则，却无法知道远处哪段内容会在当前问题下重新重要。动态路由把邻接集合写成输入的函数 $N(i;x)$：先用较便宜的信号缩小候选集，再对候选 key 执行精确注意力。真正需要解释的并不是「选 top-k」，而是选择器在读取多少状态以后得到 top-k。若路由阶段已经扫描全部 key 并计算完整点积，后面的稀疏 softmax 只节省物化与聚合，没有消除主要配对。

本章沿四个量组织后续正文：候选生成的计算和访存、关键 token 的召回率、离散选择怎样训练、索引怎样映射到块级 kernel。内容相关路由可能使用块摘要、低维投影、聚类中心、近似最近邻或可学习门控。它们对局部连续性、远距离检索和批内负载的假设不同，不能只用统一的稀疏率比较。

## 路由器到底在计算什么

设输入序列的 key 被切成 $m$ 个块，每块包含 $b$ 个 token，路由器先为第 $r$ 个块构造摘要 $s_r$。当前 query $q_i$ 不再直接与全部 $n$ 个 key 计算高维点积，而是先计算 $q_i$ 与 $m=n/b$ 个摘要的相关分数，从中选出 $k$ 个块。第二阶段才读取这些块内的原始 key 和 value。若摘要维度为 $d_r$，粗略计算量从稠密注意力的 $O(nd_h)$ 变成 $O(md_r+kbd_h)$；$d_h$ 是 attention head 维度。这个式子同时暴露两个容易被忽略的条件：块数 $m$ 仍随序列长度增长，而且被选中的块通常要整块读取。

摘要怎样产生，会改变路由器能看到的信息。均值池化保留块的整体方向，却可能稀释只出现一次的关键实体；最大池化偏向局部强响应；额外训练的代表向量能适配任务，但会增加参数和训练目标。聚类方法把相近 key 放进同一桶，哈希方法通过离散码缩小候选，低维投影则用较便宜的内积近似原始注意力排序。几条路线都在估计同一件事：如果执行完整注意力，哪些位置会获得较大权重。估计错误发生在精确计算之前，后续 softmax 无法补回没有进入候选集的 key。

有些动态方法把路由放在 attention 层外，用前一层状态或独立索引预测候选；另一些方法复用当前层已经产生的局部统计。前者可以提前准备索引和数据搬运，后者与当前 query 更一致，却更难隐藏路由时延。训练时若索引随参数每步变化，还要考虑重建成本和旧索引带来的偏差。推理时索引虽然只读，批内每个请求选择的块数和位置不同，又会形成不规则 gather。算法图里的一次 top-k，落到执行层通常包含打分、选择、去重、排序、地址生成和数据搬运。

## 从静态拓扑到内容相关连接

[基础章](../01-基础/01-基础.md)中的滑动窗口把位置距离作为唯一选择信号。动态路由没有必要取消局部窗口。更常见的结构是保留一组确定的局部边，再增加少量内容相关的远程边。局部边保证相邻 token 的语法与短程状态稳定传播，动态边负责召回远处的实体、定义或约束。两部分预算应该分别报告，否则同样写成每个 query 访问 $K$ 个 token，可能一个方法将大部分预算留给局部窗口，另一个方法几乎全部用于远程检索。

块级选择与 token 级选择也不能直接比较。块级路由更容易生成规则 kernel，地址连续，代价是块内许多 token 只因邻近关键位置而被一并计算。token 级 top-k 更接近注意力权重的细粒度排序，但随机地址读取、去重与负载均衡更困难。两者之间还有分层选择：先选粗块，再在块内选 token。分层选择能控制索引规模，却会叠加两次召回误差。评测时需要分别记录粗选召回和细选召回，避免最终质量下降时只看到一个总路由准确率。

MInference 一类方法从输入中识别适合不同 head 的稀疏模式，MoBA 将长序列划块并按 query 对块进行选择，NSA 则把压缩、选择与局部窗口组合进原生可训练的结构。它们都带有动态成分，但动态对象不同：有的方法选择模式，有的方法选择块，有的方法同时保留多条注意力分支。比较时应回到 $N(i)$ 的产生过程，写清每条分支提供哪些边、各自占多少预算，以及不同分支的输出怎样合并。方法名不能代替邻接关系。

## 训练信号与失败方式

top-k 是离散操作。只有入选候选参与精确注意力时，未入选块通常收不到来自主任务的直接梯度。训练可以使用稠密 attention 产生教师排序，也可以为路由器增加对比损失、召回损失或负载均衡项；还可以在训练早期扩大候选集，随后逐步收紧预算。每种做法都改变训练成本。若教师分支需要计算完整注意力，训练仍可能保持平方复杂度，只在部署阶段获得稀疏收益。

路由器还会遇到「热门块」问题。许多 query 同时选择少数块时，模型行为可能没有立即恶化，执行系统却会在持有这些块的设备上形成热点。负载均衡损失可以鼓励候选分散，但分散本身不保证语义相关；惩罚太强会迫使 query 选择次优块。分布式部署还要决定被选块是远程读取、提前复制，还是按路由结果做 all-to-all。三种策略分别增加时延、容量和通信，对应的最优选择随 batch、块大小和拓扑变化。

最危险的失败不是平均召回略低，而是关键证据被稳定漏掉。长文中一条约束可能只出现一次，它在块摘要里权重很小，却决定最终答案。局部窗口可以在证据附近保存表示，但如果经过有限层数仍无法传播到 query，动态边的漏选就会直接表现为推理错误。因此质量评测要加入稀有实体、相似干扰块、多跳证据和不同相对距离；仅用语言模型 loss 会被大量容易预测的局部 token 稀释。

阅读时先固定预算：每个 query 最多访问多少 token 或块，路由器额外读多少字节，训练和推理是否使用同一选择规则。随后检查失败路径：关键块未入候选时能否由局部边或全局层补救，路由抖动是否破坏缓存复用，热点块是否让不同设备负载失衡。后续将以这套口径比较哈希、聚类、两阶段检索和学习式路由，并把算法召回与端到端时延放在同一张表中。

动态路由与下一章的 [KV 选择](../03-KV选择/03-KV选择.md)共享索引，却改变不同对象。路由决定当前 query 读取哪些仍然存在的状态，KV 淘汰决定未来还能从哪些状态中选择。一个块本步没有被选中，不妨碍下一步重新进入候选；一个块从 cache 中删除后，任何路由器都无法恢复它。训练章会继续处理离散选择的梯度与稠密到稀疏迁移，内核章则检查候选索引能否在读取完整 KV 之前生成。

## 导航

动态路由先从[粗粒度选择](./01-粗粒度选择/01-粗粒度选择.md)进入. 这条路线把 token 整理成桶、簇或二维块, 用块内多算换取连续访存和规则 kernel. [哈希与聚类](./01-粗粒度选择/01-哈希与聚类.md)解释训练型内容分组, [MInference](./01-粗粒度选择/02-MInference.md)解释已有模型如何离线选择 head 模式并在线构造 Prefill 索引. 后续的细粒度索引与跨层共享将沿同一套候选召回、索引成本和物理 tile 口径展开.

[细粒度索引](./02-细粒度索引/02-细粒度索引.md)把最终候选压到 token级. [DSA 与索引器](./02-细粒度索引/01-DSA与索引器.md)从 Lightning Indexer 的目标、训练和 Sparse MLA 数据路径进入, 再比较 HISA、MISA 与 LISA 分别缩小 token 搜索域、active heads 或增加线性全局通道. 这条路线尤其需要同时核算低维全扫、top-k 和主 KV 的随机 gather.

[跨层共享](./03-跨层共享/03-跨层共享.md)进一步减少逐层重复的 KV、索引与 Prefill 计算. [CSA、HCA 与 CSA2](./03-跨层共享/01-CSA与CSA2.md)解释 Full、Reindex、Reuse 层怎样共享主 KV、索引器 K 和候选位置; [HySparse 与 HySparse2](./03-跨层共享/02-HySparse.md)解释 full attention oracle、block/token 选择、KV Reuse 与两段 decoder 的 KV Bridging. 两条路线都必须按组尾误差和真实读取字节验收.

[训练原生稀疏](./04-训练原生稀疏/04-训练原生稀疏.md)把稀疏结构贯穿前向、反向、Prefill 与 Decode. [NSA](./04-训练原生稀疏/01-NSA.md)以全局压缩、重要连续块和局部滑窗三分支为核心, 复用压缩分数做 block 选择, 并让 GQA 组共享候选以对齐实际 KV 读取. 这条路线必须用原生训练结果验证, 不能从稠密模型的后处理表现直接外推.

读完本章后，读者应能把一种动态 Sparse Attention 拆成完整的数据路径：摘要由哪些状态构造，query 与多少摘要计算，候选以 token 还是块为单位，top-k 结果如何变成地址，精确 attention 读取多少 KV，漏选后有没有补救通道。具备这条路径后，论文里的复杂度、代码里的索引张量和 profiler 里的访存才能对应到同一个方法。
