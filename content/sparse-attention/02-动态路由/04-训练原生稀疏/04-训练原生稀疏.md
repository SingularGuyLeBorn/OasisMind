# 训练原生稀疏: 让模型在稀疏图上学习

稀疏 attention 有两种完全不同的使用方式. 第一种先训练全注意力模型, 部署时再删除一部分连接、KV 或 attention blocks. 它能直接使用已有 checkpoint, 也要承受训练函数与推理函数之间的差异. 第二种把稀疏计算图放进优化过程, 模型从训练中就知道哪些历史会被压缩、哪些候选会被 top-k 截断、哪些局部位置始终可见. **训练原生稀疏的核心是「模型在部署时使用的稀疏图上学习」, 起点可以是随机初始化, 也可以是已有全注意力 checkpoint.**

[Native Sparse Attention(NSA)](./01-NSA.md)是这条路线最完整的例子. 它把压缩、选择和滑窗做成三条独立 attention 分支, 从前向、反向一直覆盖 Prefill 与 Decode. MoBA 从另一侧进入: 每个 query 路由到少量 KV blocks, 结构不增加 attention 参数, 因而可以在 full attention 与 MoBA 之间切换. DSA 又采用两阶段转换: 先保留 dense attention 训练 Lightning Indexer, 再让主模型在 token 级稀疏 attention 上继续训练. 三者都训练稀疏结构, 候选来源、梯度路径和硬件粒度并不相同.

判断一种训练原生稀疏方案, 要同时追踪五件事: 稀疏图何时进入优化过程, 多路 attention 怎样共同更新, hard top-k 截断哪些梯度, token 预算怎样落到 kernel 与 KV 读取, 以及从头预训练和继续训练各自承担多少适应成本. [NSA 解析](./01-NSA.md)列出了具体 block 参数、论文实验和 kernel 流程; NSA、MoBA 与 DSA 则可以放进同一组符号中比较训练路线.

## 1. 分界落在计算图与优化过程

### 1.1. 后插稀疏改变已经学好的函数

令全注意力在位置 $t$ 的输出为

$$
o_t^{\mathrm{full}}=
\sum_{s\in V_t}\alpha_{t,s}v_s,
\qquad
\alpha_{t,s}=
\frac{\exp(q_t^\top k_s/\sqrt d)}
{\sum_{j\in V_t}\exp(q_t^\top k_j/\sqrt d)}. \tag{1}
$$

$V_t$ 是因果可见历史. 部署阶段选一个集合 $S_t\subset V_t$, 再把 softmax 分母限制到 $S_t$, 输出变成

$$
o_t^{\mathrm{sparse}}=
\sum_{s\in S_t}\widehat\alpha_{t,s}v_s,
\qquad
\widehat\alpha_{t,s}=
\frac{\exp(q_t^\top k_s/\sqrt d)}
{\sum_{j\in S_t}\exp(q_t^\top k_j/\sqrt d)}. \tag{2}
$$

即使 $S_t$ 覆盖了大部分原始 attention mass, 分母变化也会重新缩放所有保留位置. 一个低概率 token 若是随机字符串、变量定义或工具返回值的唯一来源, 漏选造成的影响远高于它在平均 attention 中的占比. 全注意力训练也没有压力把信息写入确定会保留的窗口、压缩状态或全局 token.

后插路线依旧有价值. KV eviction、Quest、MInference 一类方法能在没有大规模训练预算时改造现有模型, 其中一些还保留精确 attention 计算, 只近似候选集合. 它们节省的是指定部署阶段, 训练原生路线则把结构限制带入参数学习. 两类方法应分别比较 checkpoint 迁移成本、训练节省、推理节省和质量恢复成本.

### 1.2. 「原生」要求四个阶段共享结构契约

一个稀疏层可以写成候选构造器 $R_\theta$ 与主 attention $A_\phi$ 的组合:

$$
S_t=R_\theta(q_t,K_{:t}),qquad
o_t=A_\phi(q_t,K_{S_t},V_{S_t}). \tag{3}
$$

训练原生稀疏至少满足三项条件. 前向确实在 $S_t$ 上计算主 attention, 训练 loss 观察到候选遗漏后的输出; 反向不依赖完整 $t\times t$ attention map 才能完成; 部署时的候选粒度、预算、因果规则与训练一致. Prefill 和 Decode 可以使用不同 kernel, 数学上的 $R_\theta$ 与 $A_\phi$ 仍应一致.

「使用同一结构」也不要求每个训练 step 都保持固定稀疏率. 课程训练可以先用 full attention, 再逐步减小候选预算; 某些层可以保留 full attention; 短序列可以退化到 dense kernel. 关键在于模型经历过准备部署的稀疏图, 并且最终优化阶段覆盖部署配置. MoBA 的 full/sparse 切换与 DSA 的 dense warm-up 都符合这一点.

反向算子的存在是硬条件. 前向只读取 $k$ 个 blocks, backward 若重新物化所有 QK 分数, 预训练仍支付平方成本. NSA 为 selection attention 设计 forward 与 backward kernel, 并把连续 KV blocks 与 GQA group放进同一执行约束. 训练速度要报告完整 step time、峰值显存和重算开销, 单独的 forward latency 无法代表原生训练收益.

### 1.3. NSA、MoBA 与 DSA 位于三种位置

NSA 从架构层面定义三路输出. 压缩分支覆盖全局低分辨率历史, selection 分支回读少量连续原始 blocks, sliding-window 分支承担局部模式, 三路通过可学习 gate 融合. 压缩 attention 的概率还生成 selection importance. 它同时改变 attention 表示、候选生成和 kernel, 适合从预训练开始共同学习.

MoBA 保留普通 Q/K/V 参数, 用每个 KV block 的 mean-pooled key 给 query 打分, top-k 后在选中 blocks 内运行精确 attention, 当前 block 强制进入并使用 causal mask. 官方实现明确要求继续训练, 无法直接把预训练模型换成 MoBA 后立即获得可靠质量. 它又能把 $k$ 扩到全部 blocks 退化为 full attention, 因而适合渐进转换和 full/sparse 混合训练.

DSA 在 MLA 主 attention 之外增加低维 Lightning Indexer. Dense warm-up 阶段保留完整主 attention, 冻结主模型, 用聚合后的主 attention 分布监督 indexer. Sparse training 阶段启用 top-k token selection, 再优化整个主模型适应稀疏图. Indexer 输入从主计算图 detach, indexer 只接受自己的 KL loss, 主模型只接受语言模型 loss. 这是一种训练原生的转换方案, 其主 attention 与 selector 使用两条明确分开的梯度路径.

三条路线可以按「稀疏从哪里进入训练」区分. NSA 让稀疏成为 attention layer 的原始结构; MoBA 保留参数形状, 在 attention mask 与 query-to-block assignment 上进入; DSA 保留 MLA 主干, 用新增 indexer 改变主 attention 的 token集合. 因而「是否增加参数」与「是否训练原生」没有必然关系. MoBA 不增加参数但需要继续训练, DSA 增加 selector并做两阶段训练, NSA 连分支投影都从预训练中学习.

| 路线 | 候选单位 | 稀疏训练信号 | 与 full attention 的切换 | 主要固定通路 |
| --- | --- | --- | --- | --- |
| NSA | 连续 blocks | LM loss 经三路输出, coarse probability 同时用于 route | 需要架构级转换 | compression 与 window |
| MoBA | KV blocks | LM loss 适应 hard routed attention | $k$ 覆盖全部 blocks 时恢复 full | 当前 block |
| DSA | 单个 tokens | Indexer KL + 主模型 LM loss | dense warm-up 后进入 sparse stage | 由 main MLA 与训练配方决定 |

训练成本的比较也要统一 token口径. 从头 sparse预训练节省大量长序列 attention, 但若为了达到同等质量多训练更多 tokens, 总 FLOPs可能回升. 继续训练路线保留已有 checkpoint价值, 转换阶段本身仍是成本. 报告应同时列出起始 checkpoint、转换 tokens、最大长度、有效训练 FLOPs和最终质量, 单看每 step加速会忽略适应成本.

## 2. 压缩、选择与滑窗怎样共同训练

### 2.1. 三个分支各自归一化再融合

设分支集合 $\mathcal C=\{\mathrm{cmp},\mathrm{slc},\mathrm{win}\}$, 每条分支拥有自己的 K/V 投影与可见集合 $S_t^c$. 分支输出为

$$
o_t^c=\operatorname{Attn}
\left(q_t^c,K_{S_t^c}^c,V_{S_t^c}^c\right),
\qquad c\in\mathcal C. \tag{4}
$$

NSA 使用 MLP 与 sigmoid 产生分支 gate $g_t^c$, 最终输出写成

$$
o_t=\sum_{c\in\mathcal C}g_t^c o_t^c. \tag{5}
$$

每条分支有自己的 softmax 分母. 同一原始位置可能通过压缩表示、selected raw KV 和 window raw KV 多次影响输出, 三个概率不能直接拼成一张统一 attention map. 把三路 K/V 合并后做一次 softmax 会改变式 (5), 训练目标和 kernel也随之改变.

独立 K/V 投影给三个分支分配不同表示空间. Window 分支可以专注邻近词法和局部状态; compression 分支学习把一个 block 可用的信息聚合进单个 entry; selection 分支保留精细 token. 共享全部投影能减少参数, 也会让局部梯度与远距压缩梯度在同一 K/V 上竞争. NSA 选择独立投影来降低这种干扰.

### 2.2. Coarse 分支既输出内容也产生路由信号

令 compression block 长度为 $l$, stride 为 $d$, 第 $r$ 个重叠 block 的表示为

$$
\widetilde k_r^{\mathrm{cmp}}=
\phi_K(x_{rd+1:rd+l}),\qquad
\widetilde v_r^{\mathrm{cmp}}=
\phi_V(x_{rd+1:rd+l}). \tag{6}
$$

$\phi_K,\phi_V$ 是带 block 内位置编码的可学习映射. 到位置 $t$ 时, 可用 compressed entries 数近似为

$$
N_{\mathrm{cmp}}(t)=
\left\lfloor\frac{t-l}{d}\right\rfloor+1. \tag{7}
$$

Compression attention 对这些 entries 做完整低分辨率覆盖. 它直接参与式 (5), 因此语言模型梯度会训练压缩表示保存可用于输出的信息. 同一 attention 的概率

$$
p_{t,r}^{\mathrm{cmp}}=
\operatorname{Softmax}_r
\left((q_t^{\mathrm{cmp}})^\top
\widetilde k_r^{\mathrm{cmp}}\right) \tag{8}
$$

还承担 selection 分支的 importance source. 这让 coarse 表示同时服务「产生输出」和「指出原始细节位于哪里」. 两项职责可能冲突: 对生成有用的压缩 Value 不一定对应最佳路由 key, 训练时应分别观察 compression 输出质量与候选 recall.

Compression blocks 与 selection blocks 的划分可以不同. 用一个固定稀疏映射矩阵 $A_{b,r}$ 表示 compressed entry $r$ 对 selection block $b$ 的空间覆盖, GQA group 内有 $H$ 个 query heads, 则 block importance 可以统一写成

$$
u_{t,b}=\sum_{h=1}^{H}\sum_r
A_{b,r}p_{t,r}^{\mathrm{cmp},(h)}. \tag{9}
$$

NSA 论文给出了由 block length、stride 与重叠关系展开的具体求和. 式 (9)保留其核心: coarse probability 先按空间关系投到原始 blocks, 再跨 GQA heads 聚合, 组内共享一套 top-$n$.

### 2.3. Fine 分支的主 attention 梯度到不了未选位置

令 $I_t=\operatorname{TopN}(u_t,n)$, selection block 长度为 $l'$, 则 fine 分支读取

$$
S_t^{\mathrm{slc}}=
\bigcup_{b\in I_t}
\{bl'+1,\ldots,(b+1)l'\}. \tag{10}
$$

在一次前向中固定 $I_t$, selected attention 与普通 attention 相同. 设上游梯度为 $g_t=\partial\mathcal L/\partial o_t^{\mathrm{slc}}$, 对选中位置 $s$ 的 logit $z_{t,s}$ 有

$$
\frac{\partial\mathcal L}{\partial z_{t,s}}
=\alpha_{t,s}\,g_t^\top
\left(v_s-o_t^{\mathrm{slc}}\right),
\qquad s\in S_t^{\mathrm{slc}}. \tag{11}
$$

未选位置不参与 fine attention, 对这条路径的 Q/K/V 梯度为零. Hard top-$n$ 的集合变化也没有普通导数, 式 (11)不会告诉一个落榜 block「差一点就入选」. NSA 的 $u_{t,b}$ 来自可微的 compression attention, 这条 coarse 输出路径持续训练 query 与 compressed K/V; selection 集合本身仍是离散操作.

这条梯度边界可以写得更明确. Selection 集合在一个不跨越排序边界的小邻域内保持不变, 因此

$$
\frac{\partial o_t^{\mathrm{slc}}}{\partial u_{t,b}}=0
\quad\text{a.e.}, \tag{12}
$$

其中 a.e. 表示除 top-$n$ 交换边界外几乎处处. 在边界上集合发生离散跳变, 普通导数也不存在. $p^{\mathrm{cmp}}$ 收到的实际梯度主要来自 coarse output, 它作为 route score 的用途不会自动添加一条平滑梯度. 这解释了为什么候选 recall必须单独测量, LM loss下降不能直接证明 selector排序正确.

做一个两位置手算. Selected set含位置 $1,2$, softmax权重为 $(0.75,0.25)$, Value为 $v_1=(2,0),v_2=(0,2)$, 则输出 $o=(1.5,0.5)$. 令上游梯度 $g=(1,-1)$. 式 (11)给出第一个 logit梯度 $0.75\,(1,-1)\cdot((2,0)-(1.5,0.5))=0.75$, 第二个为 $0.25\,(1,-1)\cdot((0,2)-(1.5,0.5))=-0.75$. 排名第三但未选的位置即使 Value更适合当前任务, fine路径梯度仍为零.

若把 hard top-$n$ 换成 soft relaxation、Gumbel或 straight-through estimator, selector能获得近似梯度, 训练图与部署图也会出现新差异. Soft routing训练时读取所有 blocks, 无法获得原生稀疏训练节省; straight-through前向 hard、反向 soft, 梯度带有估计偏差; 随机采样还会增加 kernel shape波动. 采用哪种方案要同时报告 forward实际稀疏率与 backward是否扫描全历史.

候选训练可以额外加入 teacher loss, 但这属于可选设计, 不能与 NSA 原论文的语言模型训练混为一项. 若有 full attention 教师分布 $p_{t,s}^{*}$, 可以定义 block target $P_{t,b}^{*}=\sum_{s\in b}p_{t,s}^{*}$, 再加入

$$
\mathcal L_{\mathrm{route}}=
\sum_tD_{KL}
\left(P_t^{*}\Vert\operatorname{Softmax}(u_t)\right). \tag{13}
$$

DSA 的 indexer warm-up 正是这类显式教师对齐, 只是其候选粒度为 token, target 来自主 attention heads 的聚合. NSA 依靠 compression 路径与 LM loss 联合适配, 两者提供给 selector 的监督方式不同.

### 2.4. Window 分支抑制局部捷径对长程分支的干扰

Window 集合为 $S_t^{\mathrm{win}}=\{\max(1,t-w+1),\ldots,t\}$. 局部模式往往收敛更快, 若 compression 与 selection 和局部 token 混在同一 softmax 中, 大量近邻高分会压低远距路径的梯度. NSA 把最近 $w$ 个 token 放进独立分支, 让 coarse 与 fine 分支继续收到自己的归一化信号.

分支 gate 的梯度也很直接. 令 $g_t^c=\sigma(a_t^c)$, 上游梯度为 $r_t=\partial\mathcal L/\partial o_t$, 则

$$
\frac{\partial\mathcal L}{\partial a_t^c}
=r_t^\top o_t^c\,
g_t^c(1-g_t^c). \tag{14}
$$

某条分支的输出尺度更大时, gate 容易优先沿它下降; gate 接近 $0$ 或 $1$ 后, sigmoid 饱和又会降低更新. 训练日志要记录分支输出范数、gate 分位数与分支梯度, 只看平均 gate 不能判断某条路径是否在少量长程样本中发挥作用.

Window 与 selected blocks 可能重叠, 两条分支仍独立计算. 这部分重复是稳定训练换来的成本. 若实现为了省算直接从 selection 中删除 window blocks, fine 分支的 softmax 分母和训练输入都会变化. 可以把「允许重叠」和「去重」作为结构消融, 不能在部署 kernel 中悄悄改动.

## 3. 从主任务梯度到训练配方

### 3.1. 总损失要区分主模型与路由器

一个通用训练目标可以写成

$$
\mathcal L=
\mathcal L_{\mathrm{LM}}
+\lambda_r\mathcal L_{\mathrm{route}}
+\lambda_b\mathcal L_{\mathrm{balance}}
+\lambda_g\mathcal L_{\mathrm{gate}}. \tag{15}
$$

$\mathcal L_{\mathrm{LM}}$ 优化最终 token 预测; $\mathcal L_{\mathrm{route}}$ 对齐 teacher 或提高候选质量; $\mathcal L_{\mathrm{balance}}$ 约束 block 热点与设备负载; $\mathcal L_{\mathrm{gate}}$ 防止分支过早关闭. 具体方法未必包含后三项. NSA 的核心训练结果来自端到端 LM 目标与三路结构; MoBA 使用 parameter-less gate, 没有独立 router 参数; DSA 明确加入 indexer KL loss.

梯度归属决定各项能优化什么. DSA sparse stage 将 indexer input detach, $\mathcal L_{\mathrm{route}}$ 只更新 indexer, $\mathcal L_{\mathrm{LM}}$ 只更新主模型. 这样避免 indexer loss 扭曲主 hidden state, 也让 LM loss 无法直接修正 selector. NSA 中 compression attention 同时参与输出和 importance, LM loss 会更新 coarse query/K/V 与 gate, hard top-$n$ 仍隔断集合边界. MoBA 的 block score由 Q 与 mean-pooled K 计算, 选中 blocks 内的 LM 梯度能更新 Q/K/V, 未选 block 的路由边界依旧没有连续梯度.

预算通常作为结构约束直接进入 $n,k,w,l'$ 等超参数, 比对总 loss 加一个「稀疏率惩罚」更容易控制 kernel shape. 动态预算可以为每个 query 预测 $n_t$, 训练时还需约束 batch 内最大值、分位数和设备负载. 平均预算满足目标, 少数 query 激活大量 blocks 时, 真实 step time 仍由最慢 row 决定.

### 3.2. 从头预训练能让表示完整适应稀疏图

从随机初始化训练 NSA, 所有层一开始就面对 compressed、selected 与 window 三路约束. 模型可以把长期状态写入压缩器容易保存的表示, 让 fine route 的 query 与 coarse importance 共同成形, 也能在局部窗口外建立逐层传播路径. 论文实验在 27B 总参数、3B 激活参数的 MoE 骨干上预训练, 再做长上下文继续训练; 这一结果对应特定模型、数据与 GQA 配置.

从头训练的风险落在早期路由. 随机 query 与 compressed keys 产生的 top-$n$ 接近随机, fine 分支可能长期读不到有用远距 token. Window 与 compression 路径提供稳定信号, 还可以在初期增大 $n$、提高 coarse gate 或周期性插入 full layers, 再逐步收紧预算. 每次预算变化都要观察 loss 是否出现跳变、route entropy 是否塌缩以及长距离 recall 是否恢复.

训练长度分布同样重要. 大部分样本短于 window 时, 模型几乎没有动力训练 compression 与 selection. 平均 LM loss 会被大量短位置支配, 长序列末端的退化很难看见. 需要同时报告 trailing loss、按 query-evidence 距离分桶的 loss, 并确保足够样本真正跨过 $w$ 和 $nl'$.

### 3.3. 继续训练适合已有 checkpoint, 但要留足适应量

MoBA 与普通 attention 使用同一组 Q/K/V 参数, $k$ 覆盖全部历史 blocks 时可恢复 full attention. 官方论文利用这一性质测试两阶段训练: 大部分 token 使用 MoBA, 后段切回 full attention; 还在 SFT 中保留若干 full attention 层, 缓解 prompt loss mask 导致的稀疏梯度传播问题. 这些实验说明切换可以平滑, 具体比例仍要随模型和任务重新验证.

DSA 给出更明确的转换流程. Dense warm-up 保留完整主 attention, 冻结主模型, 用主 attention heads 聚合后的 target distribution训练 Lightning Indexer. 报告中的 warm-up 为 $1000$ steps、每步 $16$ 条 $128$K 序列. 随后 sparse stage 每个 query 选择 $2048$ 个 KV tokens, 优化主模型与 indexer共 $15000$ steps; indexer 继续在选中集合上做 KL 对齐, 主模型用 LM loss 适应稀疏输入.

两阶段 KL 的可见范围不同. Warm-up 的 teacher覆盖整个合法历史, 能直接惩罚 indexer漏掉高质量 token. Sparse stage的对齐限制在当前 selected set内, 更侧重让已选 token的相对 score接近主 attention; 集合外 token无法通过这项受限 KL重新进入. Dense warm-up提供了初始全局排序, sparse stage再保持入选集合内的校准, 主模型则围绕实际 top-k结果调整表示.

转换过程需要三条曲线. 第一条是 full-history teacher上的 indexer mass recall, 检查 selector是否仍能找到主 attention需要的位置; 第二条是 sparse LM loss与 full reference的差距, 检查主模型适应程度; 第三条是 indexer KL, 检查打分校准. KL持续下降而 full-history recall下降时, 受限集合内拟合正在掩盖候选遗漏.

NSA 增加压缩器、三套 K/V 投影与 gate, 从 dense checkpoint 转换时没有 MoBA 那样的参数同构. 可以从原 Q/K/V 复制或分支初始化, 再用 dense teacher做输出蒸馏与 candidate supervision, 但需要重新验证分支平衡. 很短的 SFT 无法替代长上下文继续预训练, 因为 selector 需要看到多种距离、结构和证据密度.

一份可执行的转换日程可以分四段. 第一段保留 full attention, 初始化新分支并做输出蒸馏; 第二段以较大候选预算启用 sparse forward, 让主模型适应漏边; 第三段逐步收紧 $n$ 或 $k$, 同时增加长样本比例; 第四段固定部署预算完成长上下文继续训练与 SFT. 每段都保存 checkpoint, 发生 loss跳变时回到上一个预算, 比一次性从 full切到目标稀疏率更容易定位问题.

预算课程还要避免只按 step变化. 模型在短序列上即使 $n$ 很小也可能覆盖大部分历史, 到长序列才真正稀疏. 可以按实际可见比例 $\rho_t=|S_t|/|V_t|$ 或 evidence距离控制课程, 确保训练早期和后期都包含跨窗口样本. 对混合长度 batch, 记录每个长度桶的 $\rho$ 分布比记录全局平均更准确.

### 3.4. SFT 与 RL 会重新改变稀疏梯度分布

SFT 常把 prompt token 的 LM loss mask 掉, 梯度只从 response 回传. Full attention 能让 response query直接连接全部 prompt, block sparse route 若漏掉某段 prompt, 那段表示在多层中收到的监督会更弱. MoBA 论文用高层 full attention缓解这一现象, 也提示训练原生稀疏不能只在预训练阶段验收.

RL 的 rollout 由推理引擎生成, 训练框架再重放序列. 两边必须对 candidate selection、top-k tie、量化和因果 mask保持一致. 同一 token 在 rollout 与训练中看到不同 blocks, log probability 差异会混入 off-policy error. 保存 route indices可以提高一致性, 代价是额外轨迹存储; 重新计算则要求两个 runtime 数值对齐.

长 CoT 还会改变预算压力. Prompt 证据在生成后段距离越来越远, 固定 window 无法覆盖, selection 要持续找回早期状态. 训练集若只有短 response, selector 可能只学到 Prefill 内检索, 到长 rollout 后段召回下降. RL 验收要按生成位置记录候选覆盖、gate 与 TPOT, 不能只比较最终 reward.

## 4. 稀疏预算必须同时满足数学和硬件

### 4.1. 三路总预算可以直接手算

NSA 在位置 $t$ 读取的逻辑条目数近似为

$$
N_{\mathrm{NSA}}(t)=
N_{\mathrm{cmp}}(t)+nl'+w. \tag{16}
$$

取论文训练配置 $l=32,d=16,l'=64,n=16,w=512$, 当 $t=65536$ 时, $N_{\mathrm{cmp}}=4095$, selected raw tokens 为 $1024$, window 为 $512$, 总计 $5631$, 约占 full history 的 $8.59\%$. 三路各自计算 attention, 重叠位置也会重复, 所以这个比例表示逻辑 keys 数, 还不能直接当成 kernel 加速比.

整个长度 $T$ 的训练前向成本可近似写成

$$
C_{\mathrm{NSA}}(T)
\propto
\sum_{t=1}^{T}
\left(\frac{t}{d}+nl'+w\right)d_h
=O\left(\frac{T^2d_h}{d}
+T(nl'+w)d_h\right). \tag{17}
$$

压缩分支仍随历史增长, 系数由 stride $d$ 缩小; selection 与 window 在预算固定后对每个 query 为常数. 计算 compressed entries 的 MLP、importance 映射、top-$n$ 和 gate 还要另计. Decode 的常驻状态则包含三套分支 cache 与压缩表示, 它的字节比例和式 (17)不同.

MoBA 的成本结构更简单. 长度 $t$、block size $B$、top-$k$ blocks 时, router 扫过约 $t/B$ 个 block keys, 主 attention 读取最多 $kB$ 个 raw tokens, 当前 block包含在 $k$ 内. $t=32768,B=512,k=3$ 时, 主 attention 读取最多 $1536$ tokens, 即 full history 的 $4.69\%$, 另加 $64$ 个 block summaries 的路由. Block 越细, route candidates 增加; block 越粗, 每次选中带入更多无关邻居.

MoBA 把当前 causal block与历史 non-causal blocks分别送入变长 FlashAttention, 再用 online softmax合并两部分. 合并需要保存每部分的 row max与归一化和. 若当前块输出为 $(o_c,m_c,l_c)$, 历史块输出为 $(o_h,m_h,l_h)$, 统一最大值 $m=\max(m_c,m_h)$, 则

$$
o=\frac{
e^{m_c-m}l_co_c+e^{m_h-m}l_ho_h}
{e^{m_c-m}l_c+e^{m_h-m}l_h}. \tag{18}
$$

直接把 $o_c,o_h$ 平均会丢失两个分区的 softmax分母, 与在候选并集上做一次 attention不等价. 当前块强制入选还解决了 causality: block mean可能包含 query之后的 token, 它不能用于决定当前块是否可见, 当前块内部必须继续使用 triangular mask.

计算稀疏也不自动压缩常驻 cache. Selection 分支为了让未来 query任意选择历史 block, 通常仍要保存全长 raw K/V; window分支只保存最近 $w$; compression分支保存约 $t/d$ 个 entries. 假设 $H_{kv}=4,d_k=192,d_v=128$, BF16下每 token一套 K/V为 $4(192+128)\times2=2560$ bytes. $t=65536$ 时, selection cache约 $160$ MiB, window cache约 $1.25$ MiB, compression entries约 $10$ MiB, 都是单层逻辑值. 三路独立投影的总 cache可能超过一层 full attention, NSA主要节省 attention计算与每步实际读取, cache容量必须单独核算.

这也影响「训练原生」的系统目标. 长 Prefill与训练关注少算 QK/AV, Decode关注少读实际候选 KV; 高并发服务还关心常驻容量. 一个结构可以在前两项获益, 第三项持平或变差. 若要同时压 cache, 还需跨层共享、量化、淘汰或固定状态机制, 这些改动会引入新的训练约束.

### 4.2. GQA 共享候选决定真实 KV 读取

假设一个 GQA group 有 $H=16$ 个 query heads, 每个 head 独立选择 $n=16$ 个 blocks. 若集合互不重合, KV 读取并集达到 $256$ blocks; 即使每个 head 的算术都很稀疏, group 共享的 K/V 仍要加载巨大并集. NSA 先用式 (9)把 heads 的 importance 相加, 再为整个 group 选择 $16$ blocks, 让同一份 K/V 在 SRAM 中供 $16$ 个 queries复用.

共享也会压低 head 专门化. 一个只负责远距代码定义的 head, importance 可能被其他局部 heads 的总量盖过. 验收要比较独立 head oracle、group-shared candidate 的 per-head attention-mass recall, 再记录实际 unique blocks 与 HBM bytes. 平均 recall 很高时, 最差 heads 仍可能决定代码、复制和精确检索能力.

Kernel block $B_k$ 与 selection block $l'$ 还要整除或有清楚的 padding规则. NSA 让连续 selected blocks 配合 Tensor Core tiles, group-centric kernel 按一个位置的一组 query heads装入 SRAM, 再依次加载共享 KV blocks. 算法把 $l'$ 从 $64$ 改到 $48$, 可能提高候选纯度, 也可能破坏 tile、引入 padding 和分支. 预算搜索应使用真实 kernel shape, 不要只按理论 token 数排序.

### 4.3. Forward、backward、Prefill 与 Decode 是四条曲线

训练 forward 有大量 queries, 主要关注矩阵计算与 tile 利用率; backward 还要计算 $dQ,dK,dV$, 并重用或重算 route indices. 保存全部 indices增加显存, 重算要求 top-$n$ 与 tie-breaking确定. Dropout 若参与 score, backward 重算还要恢复相同随机状态.

Prefill 与训练 forward接近, 但无需保存反向激活, 可以使用更激进的 workspace复用和量化. Decode 每次只有一个 query, 常由 KV cache读取与小 kernel launch主导. NSA 论文在 $64$K 上分别报告 Decode、Forward、Backward 相对 full attention 的加速, 这种分阶段口径比单一「attention 加速」更有信息量.

DSA 展示了另一种成本分解. 主 Sparse MLA 从 $O(T^2)$ 降到 $O(Tk)$, Lightning Indexer 仍对全历史做低维扫描, 理论上保留 $O(T^2)$ 项. 训练 indexer、top-k 与 main KV gather 都必须计入 step time. MoBA 的 mean pooling、Q-to-block score、query 重排与 online softmax合并也属于总成本, official efficient implementation 与 naive mask实现的差距说明 route glue不可忽略.

短上下文的交叉点可以用固定开销解释. 设 dense attention耗时近似 $aT^2$, sparse主计算为 $bT(nl'+w)+cT^2/d$, route、排序和重排为 $rT$. Sparse开始占优的长度满足

$$
aT^2>
bT(nl'+w)+\frac{cT^2}{d}+rT. \tag{19}
$$

当 $T$ 很小时, $rT$ 与 kernel launch占比高, 优化过的 dense GEMM可能更快; $T$ 增长后, full attention的平方系数开始主导. 实测交叉点随 dtype、batch、head维、GPU和 backward策略变化, 应从长度曲线读取, 不能由逻辑稀疏率直接推算.

Backward 的工作量还受参数梯度累积影响. Selection blocks分散时, 多个 queries会向同一 K/V block写入梯度, 实现可按 block聚合 query后做规则 GEMM, 或使用原子累加处理散射. 前者需要 query重排与offset metadata, 后者可能发生写冲突. NSA 的 group-centric布局不仅服务 forward KV复用, 也影响 backward如何汇总 $dK,dV$.

### 4.4. 分布式训练把候选变成通信计划

Context parallel把序列切到多张卡时, query 选中的 blocks 可能位于远端 rank. 所有 rank先计算本地 coarse scores, 再做 global top-$n$, 随后只交换入选 K/V; 或先复制 compressed summaries, 每个 query owner独立路由. 前者减少 summary副本, 多一次同步; 后者让路由本地化, 需要维护全局压缩状态.

候选负载也不均匀. 大量 queries选中同一早期 block 时, 其 owner成为通信热点; 完全随机分布则增加 all-to-all目的地. $\mathcal L_{\mathrm{balance}}$ 可以改善流量, 也可能强迫 query离开最佳证据. 数据并行、tensor parallel和context parallel组合后, 应记录每 rank发送字节、最大接收量、等待时间与 route recall.

Pipeline parallel同样受 branch 影响. 三套 K/V 投影与 gate若跨 stage, activation生命周期会延长; full/sparse hybrid layers分布不均还会造成 stage time差异. 分层预算应与 stage划分一起搜索, 训练 FLOPs 总量相同并不保证 pipeline均衡.

## 5. 失效模式与消融要能定位责任

### 5.1. 四类失败有不同指纹

第一类是 coarse blindness. Compression output在 LM loss 上可用, importance 却找不到原始关键 block. 表现为 coarse 分支质量尚可、fine candidate recall低, 把 oracle blocks强制加入后任务立刻恢复. 需要调整压缩器容量、stride、importance映射或 route supervision.

第二类是 fine budget不足. Candidate 排序基本正确, $n$ 太小导致多证据任务只能取回一部分. 增大 $n$ 后 recall 与质量同步改善, group内最差 head提升明显. Block size过大也会浪费预算: 一个关键 token带入整块邻居, 占用本可容纳其他证据的名额.

第三类是 local domination. Window gate长期接近 $1$, compression 与 selection梯度很小, 短文本 loss正常而窗口外任务失败. 增加长样本、调整 gate初始化、分支 dropout或限制训练初期 window容量可以验证原因. 删除 window 后 loss剧烈上升并不表示它应无限增强, 还要观察另外两路是否获得长期学习机会.

第四类是 system mismatch. 训练使用 $n=16$、完整 group-shared blocks, 部署 kernel因 workspace限制截成 $n=12$ 或采用不同去重顺序; Prefill处理不完整 compression block时泄漏未来 token; backward重算 top-$n$ 与 forward tie顺序不同. 这些问题常表现为离线 PyTorch正确、fused kernel质量下降或梯度不稳定.

因果边界需要覆盖三套规则. Compression entry 只有在其 block末端不超过 query位置时才能使用, 重叠 stride会让相邻 entries拥有不同完成时间; selection block若包含 query自身, block内要应用 triangular mask; window 起点则为 $\max(1,t-w+1)$. Packed sequence还要在文档边界重置三路状态, 否则 compressed block可能拼接两篇文档, selected index也可能跨样本读取.

第五类是 routing hotspot. 某些通用开头、sink或模板段落被大量 queries选中, 质量保持正常, 单个设备或 KV page却成为带宽热点. 随机打散 block owner能改善负载, 会增加位置映射; balance loss能分散候选, 也会影响证据准确性. 系统侧应把 block访问频次直方图与 per-rank等待时间一起记录.

第六类是长度外退化. 训练到 $32$K 时, coarse selector只需在约 $32K/d$ 个 entries中排序; 部署到 $128$K 后候选数增为四倍, top-$n$ 预算不变, 排名边界更拥挤. Route entropy可能上升, 关键 block的 margin下降. 评测要固定 evidence类型逐步拉长 distractors, 才能区分距离问题与候选数量问题.

还有一类误差来自跨层传播. 某层没有直接选中证据, 证据可能先由 compression分支写入中间 token, 下一层再经 window或selection读取这个中间表示. 单层 candidate recall低并不必然造成最终失败, 但传播路径变长后需要足够层数, 中间表示也可能丢失精确字符串. 训练原生模型会利用这类替代路径, 评测仍要知道它依赖了多少层.

可以把每层稀疏图记为邻接矩阵 $A^{(l)}$, 从输入位置 $s$ 到输出位置 $t$ 的 $L$ 层可达性由布尔乘积

$$
R^{(1:L)}=A^{(L)}\odot A^{(L-1)}\odot\cdots\odot A^{(1)} \tag{20}
$$

决定, $\odot$ 表示布尔矩阵乘法. Window使局部信息逐层移动, compressed nodes提供远距低分辨率边, selected blocks提供远距高分辨率边. Candidate recall测直接边, 式 (20)测最终是否存在传播路径, 两者共同解释任务结果.

可达性只说明路径存在, 没有衡量信息在每次 residual、normalization和非线性变换后还剩多少. 可以继续记录证据位置对目标 logit的梯度范数, 或逐层做 activation patching, 观察替换某层证据表示后输出变化. 图可达但影响接近零时, 传播通路在数值上已经失效; 直接边缺失但 patching仍有效时, 模型使用了中间 relay.

传播消融可以只在一层注入 oracle block, 再逐步增加注入层数. 单层注入无效、多层连续注入后恢复, 说明证据需要持续高分辨率访问; 早期一层注入即可恢复, 说明后续层能通过 hidden state携带信息. 对随机字符串复制, 中间压缩通常更难; 对主题分类, 一次 coarse读取可能已经足够.

层间共享 selector还会改变传播图的多样性. 每层独立候选可能让不同深度依次读取多个证据, 跨层复用则重复同一组边. 它能降低 route成本, 多跳任务的覆盖可能下降. 原生训练若计划部署共享 candidates, 训练阶段也应使用相同共享组, 让模型在固定图上学习传播策略.

### 5.2. Oracle replay把路由误差与容量误差分开

对每个 query计算高预算或 full attention teacher, 取其最优 block集合 $S_t^*$. Learned candidate 的集合 recall为

$$
R_t^{\mathrm{set}}=
\frac{|S_t\cap S_t^*|}{|S_t^*|}, \tag{21}
$$

attention-mass recall则为

$$
R_t^{\mathrm{mass}}=
\frac{\sum_{s\in S_t}p_{t,s}^{*}}
{\sum_{s\in S_t^*}p_{t,s}^{*}}. \tag{22}
$$

集合 recall 与质量 recall可能给出相反印象. 假设 oracle选中四个 blocks, attention mass分别为 $(0.70,0.20,0.08,0.02)$. Learned route选中第一、第二个和两个无关 blocks, set recall为 $2/4=50\%$, mass recall却达到 $0.90/1.00=90\%$. 对一般语言建模可能已经够用, 第三个 block若包含任务唯一答案, 任务仍会失败. 因此 recall还要按证据标签、head和任务类型切分.

Oracle 本身也要说明来源. 用同层 full attention top blocks测的是「若保留稠密模型分布, selector能否模仿」; 用任务标注证据测的是「候选是否覆盖外部真值」; 用梯度或删边反事实得到的 oracle测的是「哪个 block真正影响 loss」. 三种集合不必一致. 训练原生模型可能发展出与 full teacher不同但有效的稀疏路径, 不能把 teacher overlap当作唯一质量标准.

先用 learned route 跑一次, 再把 $S_t$ 换成同预算 oracle. Oracle恢复说明 selector承担主要误差; oracle仍差, 则 block粒度、预算或三路输出容量不足. 再把预算扩大到覆盖全部 blocks, 可以检查 sparse kernel与 full reference 是否数值对齐.

NSA 还要分别替换三路. 保持总读取 tokens不变, 用均匀 compressed blocks、oracle selected blocks和固定 window组合, 才能区分 coarse输出、route与local通路. MoBA可以从 top-$k$ 平滑扩大到 all blocks检查收敛; DSA可以保持 main model不变, 替换 indexer positions定位 selector质量.

### 5.3. 基础消融覆盖结构、训练和硬件

结构消融至少扫描 $l,d,l',n,w$, gate类型, 分支独立或共享 K/V, GQA group-shared或per-head candidates. 每个点同时给出逻辑 keys、unique blocks、真实读取字节和质量. 只保持相同理论稀疏率不够: $8$ 个 $128$-token blocks 与 $16$ 个 $64$-token blocks读取量相同, 候选分辨率与 kernel效率不同.

训练消融比较从头 sparse、full-to-sparse课程、dense teacher蒸馏、不同 route loss权重, 以及候选预算收紧速度. 对已有 checkpoint还要报告继续训练 tokens, 不能把很长的转换训练描述成零成本插件. MoBA 官方实现提示需要 continue training; DSA报告了 warm-up与 sparse stage规模; NSA报告从预训练到长上下文适配的完整路径.

系统消融关闭 fused top-k、query重排、group KV复用、backward重算和低比特 cache, 观察每项对 step time与显存的贡献. 短序列下 route固定开销可能超过省下的 attention, 长度增加后才出现交叉点. 曲线至少覆盖窗口内、候选预算刚饱和、中长上下文和训练长度外四段.

消融还要保持有效训练计算可比. Sparse模型每 step更快时, 固定 steps意味着它使用更少 wall-clock却处理相同 tokens; 固定 wall-clock又会让它看到更多 tokens. 两种比较回答不同问题. 至少同时给出等 tokens、等训练 FLOPs和等 wall-clock中的两种, 并报告学习率 schedule按 steps还是 tokens推进.

数据消融按依赖形态组织. 局部续写检验 window, 跨段主题与统计聚合检验 compression, 随机字符串和代码定义检验 selection, 多证据推理检验 $n$ 是否容纳全部 blocks. 将 evidence放在 block中心、边界和跨两个 blocks的位置, 能发现 block segmentation造成的召回差异.

数值正确性从很短序列开始. 把 $n$ 增到覆盖所有 selection blocks, $w$ 增到覆盖历史, 再逐分支与 PyTorch reference对齐 output和 $dQ,dK,dV$. 随后恢复目标预算, 固定 indices比较 sparse kernel; 这一关通过后再启用 route、量化和分布式通信. 逐级加入功能能将数值误差与候选误差分开.

### 5.4. 最终验收同时看学习、召回与执行

学习侧记录总 LM loss、trailing loss、三路输出范数、gate分布、route loss和每路梯度范数. 召回侧记录 per-layer、per-head、per-distance的 set recall、attention-mass recall, 以及代码、随机字符串、多证据和长 CoT任务. 执行侧记录 Forward、Backward、Prefill、Decode latency, 峰值显存、HBM bytes、unique pages、top-k时间与通信不均衡.

Checkpoint还要携带稀疏结构元数据: block length、stride、top-$n$、window、GQA grouping、full/sparse layer表、route loss版本与 tie-breaking规则. 权重相同而其中一个字段变化, attention图已经不同. Runtime加载时应核对这些字段与 kernel支持的 tile, 遇到不兼容配置直接报错, 避免静默 padding或预算截断.

复现实验保存每层采样的 route indices与 gate即可显著提高可诊断性. 同一 batch在 reference、训练 kernel和服务 kernel各跑一次, 比较候选、分支 output与最终 logits. 候选相同而 output不同, 排查 kernel和量化; 候选先分叉, 排查 score、mask和 top-k; output一致而训练曲线不同, 再检查 backward与优化器状态.

训练原生稀疏的收益最终要同时满足三件事: 模型在目标稀疏图上收敛; selector在预算内保留任务需要的证据; kernel确实跳过未选计算与内存读取. 任意一项缺失都会产生常见假象: loss正常但远距检索差, recall漂亮但GPU没有加速, kernel很快但反向传播仍在计算稠密 attention.

NSA、MoBA 与 DSA给出了三种可复用的设计模板. NSA用可微 coarse路径支撑 hard fine selection, 并单列局部窗口; MoBA用参数同构换取 full/sparse平滑转换; DSA用 teacher warm-up和解耦梯度训练低维 token selector. 新结构可以组合其中的思想, 也必须重新说明候选监督、主 attention梯度、训练阶段和硬件预算.
