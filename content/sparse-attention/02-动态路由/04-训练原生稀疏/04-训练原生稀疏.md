# 训练原生稀疏: 让模型在稀疏图上学习

稀疏 attention 有两种完全不同的使用方式. 第一种先训练全注意力模型, 部署时再删除一部分连接、KV 或 attention blocks. 它能直接使用已有 checkpoint, 也要承受训练函数与推理函数之间的差异. 第二种把稀疏计算图放进优化过程, 模型从训练中就知道哪些历史会被压缩、哪些候选会被 top-k 截断、哪些局部位置始终可见. **训练原生稀疏的核心是「模型在部署时使用的稀疏图上学习」, 起点可以是随机初始化, 也可以是已有全注意力 checkpoint.**

[Native Sparse Attention(NSA)](./01-NSA.md)是这条路线最完整的例子. 它把压缩、选择和滑窗做成三条独立 attention 分支, 从前向、反向一直覆盖 Prefill 与 Decode. MoBA 从另一侧进入: 每个 query 路由到少量 KV blocks, 结构不增加 attention 参数, 因而可以在 full attention 与 MoBA 之间切换. DSA 又采用两阶段转换: 先保留 dense attention 训练 Lightning Indexer, 再让主模型在 token 级稀疏 attention 上继续训练. 三者都训练稀疏结构, 候选来源、梯度路径和硬件粒度并不相同.

判断一种训练原生稀疏方案, 要同时追踪五件事: 稀疏图何时进入优化过程, 多路 attention 怎样共同更新, hard top-k 截断哪些梯度, token 预算怎样落到 kernel 与 KV 读取, 以及从头预训练和继续训练各自承担多少适应成本. [NSA 解析](./01-NSA.md)列出了具体 block 参数、论文实验和 kernel 流程; NSA、MoBA 与 DSA 则可以放进同一组符号中比较训练路线.

## 1. 分界落在计算图与优化过程

### 1.1. 后插稀疏改变已经学好的函数

令全注意力在位置 $t$ 的输出为

$$
o_t^{\mathrm{full}}=
\sum_{s\in V_t}\alpha_{t,s}v_s,
\qquad
\alpha_{t,s}=
\frac{\exp(q_t^\top k_s/\sqrt d)}
{\sum_{j\in V_t}\exp(q_t^\top k_j/\sqrt d)}. \tag{1}
$$

$V_t$ 是因果可见历史. 部署阶段选一个集合 $S_t\subset V_t$, 再把 softmax 分母限制到 $S_t$, 输出变成

$$
o_t^{\mathrm{sparse}}=
\sum_{s\in S_t}\widehat\alpha_{t,s}v_s,
\qquad
\widehat\alpha_{t,s}=
\frac{\exp(q_t^\top k_s/\sqrt d)}
{\sum_{j\in S_t}\exp(q_t^\top k_j/\sqrt d)}. \tag{2}
$$

即使 $S_t$ 覆盖了大部分原始 attention mass, 分母变化也会重新缩放所有保留位置. 一个低概率 token 若是随机字符串、变量定义或工具返回值的唯一来源, 漏选造成的影响远高于它在平均 attention 中的占比. 全注意力训练也没有压力把信息写入确定会保留的窗口、压缩状态或全局 token.

后插路线依旧有价值. KV eviction、Quest、MInference 一类方法能在没有大规模训练预算时改造现有模型, 其中一些还保留精确 attention 计算, 只近似候选集合. 它们节省的是指定部署阶段, 训练原生路线则把结构限制带入参数学习. 两类方法应分别比较 checkpoint 迁移成本、训练节省、推理节省和质量恢复成本.

### 1.2. 「原生」要求四个阶段共享结构契约

一个稀疏层可以写成候选构造器 $R_\theta$ 与主 attention $A_\phi$ 的组合:

$$
S_t=R_\theta(q_t,K_{:t}),qquad
o_t=A_\phi(q_t,K_{S_t},V_{S_t}). \tag{3}
$$

训练原生稀疏至少满足三项条件. 前向确实在 $S_t$ 上计算主 attention, 训练 loss 观察到候选遗漏后的输出; 反向不依赖完整 $t\times t$ attention map 才能完成; 部署时的候选粒度、预算、因果规则与训练一致. Prefill 和 Decode 可以使用不同 kernel, 数学上的 $R_\theta$ 与 $A_\phi$ 仍应一致. 「使用同一结构」也不要求每个训练 step 都保持固定稀疏率. 课程训练可以先用 full attention, 再逐步减小候选预算; 某些层可以保留 full attention; 短序列可以退化到 dense kernel. 关键在于模型经历过准备部署的稀疏图, 并且最终优化阶段覆盖部署配置. MoBA 的 full/sparse 切换与 DSA 的 dense warm-up 都符合这一点.

反向算子的存在是硬条件. 前向只读取 $k$ 个 blocks, backward 若重新物化所有 QK 分数, 预训练仍支付平方成本. NSA 为 selection attention 设计 forward 与 backward kernel, 并把连续 KV blocks 与 GQA group放进同一执行约束. 训练速度要报告完整 step time、峰值显存和重算开销, 单独的 forward latency 无法代表原生训练收益.

### 1.3. NSA、MoBA 与 DSA 位于三种位置

NSA 从架构层面定义三路输出. 压缩分支覆盖全局低分辨率历史, selection 分支回读少量连续原始 blocks, sliding-window 分支承担局部模式, 三路通过可学习 gate 融合. 压缩 attention 的概率还生成 selection importance. 它同时改变 attention 表示、候选生成和 kernel, 适合从预训练开始共同学习. MoBA 保留普通 Q/K/V 参数, 用每个 KV block 的 mean-pooled key 给 query 打分, top-k 后在选中 blocks 内运行精确 attention, 当前 block 强制进入并使用 causal mask. 官方实现明确要求继续训练, 无法直接把预训练模型换成 MoBA 后立即获得可靠质量. 它又能把 $k$ 扩到全部 blocks 退化为 full attention, 因而适合渐进转换和 full/sparse 混合训练.

DSA 在 MLA 主 attention 之外增加低维 Lightning Indexer. Dense warm-up 阶段保留完整主 attention, 冻结主模型, 用聚合后的主 attention 分布监督 indexer. Sparse training 阶段启用 top-k token selection, 再优化整个主模型适应稀疏图. Indexer 输入从主计算图 detach, indexer 只接受自己的 KL loss, 主模型只接受语言模型 loss. 这是一种训练原生的转换方案, 其主 attention 与 selector 使用两条明确分开的梯度路径. 三条路线可以按「稀疏从哪里进入训练」区分. NSA 让稀疏成为 attention layer 的原始结构; MoBA 保留参数形状, 在 attention mask 与 query-to-block assignment 上进入; DSA 保留 MLA 主干, 用新增 indexer 改变主 attention 的 token集合. 因而「是否增加参数」与「是否训练原生」没有必然关系. MoBA 不增加参数但需要继续训练, DSA 增加 selector并做两阶段训练, NSA 连分支投影都从预训练中学习.

| 路线 | 候选单位 | 稀疏训练信号 | 与 full attention 的切换 | 主要固定通路 |
| --- | --- | --- | --- | --- |
| NSA | 连续 blocks | LM loss 经三路输出, coarse probability 同时用于 route | 需要架构级转换 | compression 与 window |
| MoBA | KV blocks | LM loss 适应 hard routed attention | $k$ 覆盖全部 blocks 时恢复 full | 当前 block |
| DSA | 单个 tokens | Indexer KL + 主模型 LM loss | dense warm-up 后进入 sparse stage | 由 main MLA 与训练配方决定 |

训练成本的比较也要统一 token口径. 从头 sparse预训练节省大量长序列 attention, 但若为了达到同等质量多训练更多 tokens, 总 FLOPs可能回升. 继续训练路线保留已有 checkpoint价值, 转换阶段本身仍是成本. 报告应同时列出起始 checkpoint、转换 tokens、最大长度、有效训练 FLOPs和最终质量, 单看每 step加速会忽略适应成本.

### 1.4. 支持集是模型的一部分

对位置 $t$, 稀疏 attention 先从合法历史 $V_t$ 中选出支持集 $S_t\subseteq V_t$, 再在 $S_t$ 上计算主 attention. 写成

$$
S_t=\operatorname{Select}(x_{\le t};\theta_r),
\qquad
y_t=\operatorname{Attn}(q_t,K_{S_t},V_{S_t};\theta_a).
$$

$\theta_r$ 是路由参数, $\theta_a$ 是主 attention 参数. 稠密模型固定 $S_t=V_t$;训练原生稀疏把 $S_t$ 也纳入学习过程. 支持集决定主模型能看到哪些变量, 它既是离散结构, 也是梯度传播的边界. 如果目标位置 $s^*$ 没进入 $S_t$, 主 attention 对 $K_{s^*},V_{s^*}$ 的直接梯度为零. 训练信号只能通过路由辅助损失、连续代理或其他层的信息路径告诉 selector「这里漏了」. 若这些通道也没有覆盖 $s^*$, 当前错误不会自动教会路由器把它选进来. 这与普通参数初值不好不同: 未选位置连局部导数入口都不存在.

因此可学习性至少包含三层. 表达层要求存在某组路由参数能把必要位置放入预算;信号层要求漏选时有梯度或探索机会;优化层要求训练动态不会过早收缩到局部捷径. 三层中任一失败, 模型都可能拥有理论容量却学不到正确稀疏图. 预算 $k$ 还定义了结构上限. 若某一步需要同时读取 $m>k$ 个相互独立的 values, 单个 sparse head无法全部纳入支持. 多 heads、coarse summary、跨层积累或更大 $k$ 可以补偿, 但支持容量不会由训练技巧突破. Oracle top-k 在预算 $k$ 下仍失败时, 问题落在容量或主 attention, 不在 selector学习.

### 1.5. 离散 top-k 为什么没有普通梯度

令 selector score 为 $z_s$, hard top-k mask 为

$$
m_s=\mathbf1[s\in\operatorname{TopK}(z,k)].
$$

只要 score 的微小扰动没有改变排序边界, $m_s$ 完全不变, 对 $z_s$ 的导数为零. 第 $k$ 与第 $k+1$ 名交换时 mask跳变, 该点又不可导. 因而从主任务 loss经过 hard mask反传, 常规链式法则无法给未跨边界的 selector score提供有效梯度. 已选 token 的主 attention score仍有梯度, 但这只优化集合内权重. 若 selector 与主 attention共享 query/key参数, 集合内梯度会间接改变未来 selector score;它没有直接说明哪个集合外 token应该进入. 共享参数提供弱耦合, 不能代替明确路由监督. soft relaxation把 mask换成连续权重, 例如

$$
\pi_s=\frac{\exp(z_s/\tau)}{\sum_j\exp(z_j/\tau)}.
$$

温度 $\tau$ 大时分布平滑, 每个位置都有梯度, 训练计算接近稠密;温度变小时接近离散选择, 梯度集中在少量边界位置并可能饱和. 训练用全量 soft权重、推理用hard top-k还存在支持不一致, 模型可能依赖许多小权重的合计贡献. straight-through estimator前向使用 hard mask, 反向假装经过某个连续函数. 它提供低偏差前向和有偏梯度. 代理梯度是否指向更好的支持集没有普遍保证, 需要通过 oracle、探索和任务曲线验证. Gumbel噪声等随机松弛可以采样离散候选, 方差和温度调度又成为训练变量.

另一条路线用教师分布训练 selector. 稠密 attention、高预算路由或 coarse branch产生目标 $p_s$, selector最小化 KL、排序或覆盖损失. 这样未选位置只要教师给质量就有梯度. 教师计算增加训练成本, 可以只在部分层、部分 batch或短片段启用. 教师自身若偏向局部捷径, 学生会继承.

### 1.6. 原生稀疏不等于从第一步就用最硬预算

从头训练时 hidden与selector都未形成, 立即使用很小 $k$ 会让早期随机集合决定哪些参数得到梯度. 某些位置偶然被选后优化更快, 又更容易继续入选, 形成自增强. 训练可以从较大预算、较高温度或更多随机探索开始, 随表示稳定逐步收紧. 设训练步 $u$ 的预算为 $k(u)$, 一个简单日程从 $k_0$ 降到目标 $k_1$. 大预算阶段提高必要位置进入支持的概率, 主模型先学会使用长程信息;收紧阶段迫使 selector保留最有价值部分. 若收紧太晚, 模型长期依赖稠密支持, 目标稀疏图适应不足;太早则回到随机锁定.

预算退火与学习率相互作用. 支持结构变化会突变每层输入分布, 在大学习率阶段可能持续重排, 在学习率很小时又来不及适应新预算. 可在预算变化后保留一段稳定训练, 观察路由 recall和主 loss重新收敛. 单纯按总 token百分比设日程没有跨模型通用值. 探索也可保留固定比例随机候选. 令支持由 exploitation top-k 与 exploration随机 $r$ 个位置组成. 随机位置为集合外参数提供被主任务看见的机会, 同时消耗预算并加入噪声. $r$ 随训练下降, 类似从探索转向利用. 对唯一远距证据, 均匀随机命中概率约为 $r/N$, 长上下文下可能很低, 分块或教师引导探索更有效.

原生训练的关键是目标结构贯穿足够长训练, 让主模型与路由器共同适应. 允许早期软化、宽预算和教师辅助不违背这一点;只在训练末尾临时套一个稀疏 mask, 适应 token不足, 才更接近后插转换.

## 2. 压缩、选择与滑窗怎样共同训练

### 2.1. 三个分支各自归一化再融合

设分支集合 $\mathcal C=\{\mathrm{cmp},\mathrm{slc},\mathrm{win}\}$, 每条分支拥有自己的 K/V 投影与可见集合 $S_t^c$. 分支输出为

$$
o_t^c=\operatorname{Attn}
\left(q_t^c,K_{S_t^c}^c,V_{S_t^c}^c\right),
\qquad c\in\mathcal C. \tag{4}
$$

NSA 使用 MLP 与 sigmoid 产生分支 gate $g_t^c$, 最终输出写成

$$
o_t=\sum_{c\in\mathcal C}g_t^c o_t^c. \tag{5}
$$

每条分支有自己的 softmax 分母. 同一原始位置可能通过压缩表示、selected raw KV 和 window raw KV 多次影响输出, 三个概率不能直接拼成一张统一 attention map. 把三路 K/V 合并后做一次 softmax 会改变式 (5), 训练目标和 kernel也随之改变. 独立 K/V 投影给三个分支分配不同表示空间. Window 分支可以专注邻近词法和局部状态; compression 分支学习把一个 block 可用的信息聚合进单个 entry; selection 分支保留精细 token. 共享全部投影能减少参数, 也会让局部梯度与远距压缩梯度在同一 K/V 上竞争. NSA 选择独立投影来降低这种干扰.

### 2.2. Coarse 分支既输出内容也产生路由信号

令 compression block 长度为 $l$, stride 为 $d$, 第 $r$ 个重叠 block 的表示为

$$
\widetilde k_r^{\mathrm{cmp}}=
\phi_K(x_{rd+1:rd+l}),\qquad
\widetilde v_r^{\mathrm{cmp}}=
\phi_V(x_{rd+1:rd+l}). \tag{6}
$$

$\phi_K,\phi_V$ 是带 block 内位置编码的可学习映射. 到位置 $t$ 时, 可用 compressed entries 数近似为

$$
N_{\mathrm{cmp}}(t)=
\left\lfloor\frac{t-l}{d}\right\rfloor+1. \tag{7}
$$

Compression attention 对这些 entries 做完整低分辨率覆盖. 它直接参与式 (5), 因此语言模型梯度会训练压缩表示保存可用于输出的信息. 同一 attention 的概率

$$
p_{t,r}^{\mathrm{cmp}}=
\operatorname{Softmax}_r
\left((q_t^{\mathrm{cmp}})^\top
\widetilde k_r^{\mathrm{cmp}}\right) \tag{8}
$$

还承担 selection 分支的 importance source. 这让 coarse 表示同时服务「产生输出」和「指出原始细节位于哪里」. 两项职责可能冲突: 对生成有用的压缩 Value 不一定对应最佳路由 key, 训练时应分别观察 compression 输出质量与候选 recall. Compression blocks 与 selection blocks 的划分可以不同. 用一个固定稀疏映射矩阵 $A_{b,r}$ 表示 compressed entry $r$ 对 selection block $b$ 的空间覆盖, GQA group 内有 $H$ 个 query heads, 则 block importance 可以统一写成

$$
u_{t,b}=\sum_{h=1}^{H}\sum_r
A_{b,r}p_{t,r}^{\mathrm{cmp},(h)}. \tag{9}
$$

NSA 论文给出了由 block length、stride 与重叠关系展开的具体求和. 式 (9)保留其核心: coarse probability 先按空间关系投到原始 blocks, 再跨 GQA heads 聚合, 组内共享一套 top-$n$.

### 2.3. Fine 分支的主 attention 梯度到不了未选位置

令 $I_t=\operatorname{TopN}(u_t,n)$, selection block 长度为 $l'$, 则 fine 分支读取

$$
S_t^{\mathrm{slc}}=
\bigcup_{b\in I_t}
\{bl'+1,\ldots,(b+1)l'\}. \tag{10}
$$

在一次前向中固定 $I_t$, selected attention 与普通 attention 相同. 设上游梯度为 $g_t=\partial\mathcal L/\partial o_t^{\mathrm{slc}}$, 对选中位置 $s$ 的 logit $z_{t,s}$ 有

$$
\frac{\partial\mathcal L}{\partial z_{t,s}}
=\alpha_{t,s}\,g_t^\top
\left(v_s-o_t^{\mathrm{slc}}\right),
\qquad s\in S_t^{\mathrm{slc}}. \tag{11}
$$

未选位置不参与 fine attention, 对这条路径的 Q/K/V 梯度为零. Hard top-$n$ 的集合变化也没有普通导数, 式 (11)不会告诉一个落榜 block「差一点就入选」. NSA 的 $u_{t,b}$ 来自可微的 compression attention, 这条 coarse 输出路径持续训练 query 与 compressed K/V; selection 集合本身仍是离散操作. 这条梯度边界可以写得更明确. Selection 集合在一个不跨越排序边界的小邻域内保持不变, 因此

$$
\frac{\partial o_t^{\mathrm{slc}}}{\partial u_{t,b}}=0
\quad\text{a.e.}, \tag{12}
$$

其中 a.e. 表示除 top-$n$ 交换边界外几乎处处. 在边界上集合发生离散跳变, 普通导数也不存在. $p^{\mathrm{cmp}}$ 收到的实际梯度主要来自 coarse output, 它作为 route score 的用途不会自动添加一条平滑梯度. 这解释了为什么候选 recall必须单独测量, LM loss下降不能直接证明 selector排序正确. 做一个两位置手算. Selected set含位置 $1,2$, softmax权重为 $(0.75,0.25)$, Value为 $v_1=(2,0),v_2=(0,2)$, 则输出 $o=(1.5,0.5)$. 令上游梯度 $g=(1,-1)$. 式 (11)给出第一个 logit梯度 $0.75\,(1,-1)\cdot((2,0)-(1.5,0.5))=0.75$, 第二个为 $0.25\,(1,-1)\cdot((0,2)-(1.5,0.5))=-0.75$. 排名第三但未选的位置即使 Value更适合当前任务, fine路径梯度仍为零. 若把 hard top-$n$ 换成 soft relaxation、Gumbel或 straight-through estimator, selector能获得近似梯度, 训练图与部署图也会出现新差异. Soft routing训练时读取所有 blocks, 无法获得原生稀疏训练节省; straight-through前向 hard、反向 soft, 梯度带有估计偏差; 随机采样还会增加 kernel shape波动. 采用哪种方案要同时报告 forward实际稀疏率与 backward是否扫描全历史.

候选训练可以额外加入 teacher loss, 但这属于可选设计, 不能与 NSA 原论文的语言模型训练混为一项. 若有 full attention 教师分布 $p_{t,s}^{*}$, 可以定义 block target $P_{t,b}^{*}=\sum_{s\in b}p_{t,s}^{*}$, 再加入

$$
\mathcal L_{\mathrm{route}}=
\sum_tD_{KL}
\left(P_t^{*}\Vert\operatorname{Softmax}(u_t)\right). \tag{13}
$$

DSA 的 indexer warm-up 正是这类显式教师对齐, 只是其候选粒度为 token, target 来自主 attention heads 的聚合. NSA 依靠 compression 路径与 LM loss 联合适配, 两者提供给 selector 的监督方式不同.

### 2.4. Window 分支抑制局部捷径对长程分支的干扰

Window 集合为 $S_t^{\mathrm{win}}=\{\max(1,t-w+1),\ldots,t\}$. 局部模式往往收敛更快, 若 compression 与 selection 和局部 token 混在同一 softmax 中, 大量近邻高分会压低远距路径的梯度. NSA 把最近 $w$ 个 token 放进独立分支, 让 coarse 与 fine 分支继续收到自己的归一化信号. 分支 gate 的梯度也很直接. 令 $g_t^c=\sigma(a_t^c)$, 上游梯度为 $r_t=\partial\mathcal L/\partial o_t$, 则

$$
\frac{\partial\mathcal L}{\partial a_t^c}
=r_t^\top o_t^c\,
g_t^c(1-g_t^c). \tag{14}
$$

某条分支的输出尺度更大时, gate 容易优先沿它下降; gate 接近 $0$ 或 $1$ 后, sigmoid 饱和又会降低更新. 训练日志要记录分支输出范数、gate 分位数与分支梯度, 只看平均 gate 不能判断某条路径是否在少量长程样本中发挥作用. Window 与 selected blocks 可能重叠, 两条分支仍独立计算. 这部分重复是稳定训练换来的成本. 若实现为了省算直接从 selection 中删除 window blocks, fine 分支的 softmax 分母和训练输入都会变化. 可以把「允许重叠」和「去重」作为结构消融, 不能在部署 kernel 中悄悄改动.

### 2.5. 路由目标分别约束排序、覆盖与成本

分布蒸馏令教师概率为 $p_s$, selector概率为 $q_s$, 使用

$$
L_{KL}=\sum_{s\in V_t}p_s\log\frac{p_s}{q_s}.
$$

它利用全历史概率, 对每个位置都有信号. 教师 attention若多 heads、多层, 还要决定聚合方式. 概率平均偏向共同关注, 最大值或并集目标强调任一 head需要的位置. 学生预算有限时无法同时覆盖所有教师尖峰, 聚合规则会塑造稀疏图. 排序目标直接比较正负位置. 对教师高质量位置 $s^+$ 与低质量位置 $s^-$, hinge loss可写为

$$
L_{rank}=\max(0,\mu-z_{s^+}+z_{s^-}).
$$

它要求正例至少高出 margin $\mu$, 不要求拟合完整概率尺度. 负例如何采样很重要: 随机远离边界的负例太容易, 当前 top-k附近的 hard negatives更能稳定支持集. 只用教师 top-k作正例又会忽略集合外仍有一定质量的位置. 覆盖目标关注选中集合承载的教师质量. 若 soft mask为 $m_s\in[0,1]$, 可用

$$
L_{cov}=-\sum_s p_sm_s.
$$

hard mask下这就是最大化教师 mass recall, 梯度仍需连续代理或策略估计. 覆盖比集合 recall更贴近输出, 唯一低概率证据可能在教师尚未识别时被忽略. 下游任务 loss用于补足教师度量与真实行为之间的差距. 成本目标约束选择量:

$$
L_{cost}=\lambda\sum_sm_s
$$

或约束超过预算的部分. 固定 top-k已让数量等于 $k$, 成本差异仍来自 block/page布局与负载. 若目标硬件按块执行, 正则应惩罚非空块或页面数, 只惩罚 token数可能学出高度分散的支持. 训练目标与实际执行粒度要一致. 四类损失回答不同问题: KL拟合教师分布, ranking稳定边界, coverage保留重要质量, cost控制资源. 把它们简单相加需要标度校准. 主任务 loss常按 token平均, 路由 loss可能按边或query求和;序列长度变化会改变相对权重. 先明确归一化分母, 再调系数.

### 2.6. 负载均衡与证据覆盖不是同一目标

MoBA式 block experts中, router把 query分给少量 KV blocks. 若少数 blocks持续热门, 对应设备或线程承担更多工作. 负载均衡损失鼓励各 block接收相近流量, 提升并行利用率. 语义分布本来就可能不均匀, 例如开头说明、最近窗口或固定文档标题确实被频繁访问. 强行均匀会牺牲路由正确性. 设 block $b$ 接收的query比例为 $f_b$, 平均router概率为 $p_b$. 常见均衡项与 $\sum_bf_bp_b$ 或方差相关. 它控制总体使用, 不保证每个query覆盖必要证据. 一个router可以均匀地把queries送到错误blocks, 均衡指标仍很好. 容量上限又与均衡不同. 每个 block或专家最多接收 $C_b$ 个queries, 超出的 token要丢弃、重路由或进入保底分支. overflow率直接改变实际支持. 训练只计算理想 top-k、推理受capacity截断, 就会出现支持不一致. 训练中要模拟相同容量与冲突解决规则.

覆盖也有 head维度. 多个 query heads共享候选时, 候选集合要覆盖各 heads的重要位置. 若用平均attention mass训练, 专门复制数字或代码符号的少数 head会被主流 heads淹没. 可优化最差 head覆盖、分位数或对专门化 heads加权, 相应候选并集会扩大. 局部 window分支会天然吸收大量高频近邻依赖, 让全局router专注远程位置. 如果教师分布包含局部 mass, selector预算可能再次被近邻占满, 与 window重复. 训练可在给定 window覆盖后, 用剩余教师质量监督远程分支. 局部 token依然重要, 只是已经由window承担, 远程预算应减少重复边.

### 2.7. 探索不足会形成支持塌缩

训练初期某些blocks因位置偏置、初始化或数据频率略占优势, 被选次数更多, 获得更多主任务梯度, 表示变得更有用, 之后继续被选. 冷门blocks很少进入支持, keys和router都缺少学习信号. 这种正反馈可以在总体 loss正常下降时发生. 塌缩有几种形态. 位置塌缩长期只看最近窗口或开头 sinks;内容塌缩偏向高频标点、标题和模板;head塌缩让多个router heads选择相同集合;样本塌缩对不同query给几乎固定mask. 每类都要用不同统计识别:位置直方图、token类型分布、head间Jaccard和query间集合熵. router熵高也不保证探索有效. 概率分布可以很平, hard top-k仍因微小固定偏置选择相同边界;加入噪声后才会更换支持. 反过来, 熵低可能表示模型对正确唯一证据很自信. 熵是诊断量, 不能单独作为目标最大化.

随机探索应遵守因果与分块结构. Prefill位置 $t$ 只能从 $V_t$ 采样;packed batch不能跨文档;block采样要避免用未来 token统计决定早期query. 若探索单位与推理单位不同, 训练学到的支持分布也会错位. 推理按block选, 训练随机token边不能完整模拟. 一种保守策略保留确定性局部窗口和少量随机远程blocks, 再让学习router分配剩余预算. 局部通道保证基础语言建模, 随机通道提供新证据曝光, 学习通道逐步接管. 随训练推进减少随机份额, 观察远程 recall是否保持. 如果随机份额一撤就下降, selector尚未学会稳定替代.

### 2.8. 支持抖动与支持僵化都可能伤害训练

第 $k$ 与第 $k+1$ 名score接近时, 很小参数更新会让位置频繁交换. 主 attention每步看到不同图, 梯度方差上升. 这种支持抖动在量化、分布式top-k tie和低精度累加下更明显. 可以监控相邻训练step在固定probe batch上的Jaccard与margin. 提高margin、降低router学习率或使用短期候选平滑能减少抖动. 平滑过强又会让支持僵化, 新证据难以进入. 训练目标是让有明确偏好的query稳定, 对不确定query保留探索, 不是让所有mask固定. EMA teacher可提供较慢变化的路由目标. 学生仍按当前参数执行, 教师分布用于蒸馏. 它降低目标漂移, 可能滞后于主模型新学到的表示. teacher更新率需要与预算日程和模型学习速度匹配.

支持变化还会改变不同参数的有效batch size. 某个历史key只有被许多queries选中时才积累稳定梯度, 冷门key更新稀疏. 对路由参数统计被选频次与梯度方差, 能发现一部分状态长期没有训练. 仅看全模型梯度范数会掩盖这种不均匀.

## 3. 从主任务梯度到训练配方

### 3.1. 总损失要区分主模型与路由器

一个通用训练目标可以写成

$$
\mathcal L=
\mathcal L_{\mathrm{LM}}
+\lambda_r\mathcal L_{\mathrm{route}}
+\lambda_b\mathcal L_{\mathrm{balance}}
+\lambda_g\mathcal L_{\mathrm{gate}}. \tag{15}
$$

$\mathcal L_{\mathrm{LM}}$ 优化最终 token 预测; $\mathcal L_{\mathrm{route}}$ 对齐 teacher 或提高候选质量; $\mathcal L_{\mathrm{balance}}$ 约束 block 热点与设备负载; $\mathcal L_{\mathrm{gate}}$ 防止分支过早关闭. 具体方法未必包含后三项. NSA 的核心训练结果来自端到端 LM 目标与三路结构; MoBA 使用 parameter-less gate, 没有独立 router 参数; DSA 明确加入 indexer KL loss. 梯度归属决定各项能优化什么. DSA sparse stage 将 indexer input detach, $\mathcal L_{\mathrm{route}}$ 只更新 indexer, $\mathcal L_{\mathrm{LM}}$ 只更新主模型. 这样避免 indexer loss 扭曲主 hidden state, 也让 LM loss 无法直接修正 selector. NSA 中 compression attention 同时参与输出和 importance, LM loss 会更新 coarse query/K/V 与 gate, hard top-$n$ 仍隔断集合边界. MoBA 的 block score由 Q 与 mean-pooled K 计算, 选中 blocks 内的 LM 梯度能更新 Q/K/V, 未选 block 的路由边界依旧没有连续梯度. 预算通常作为结构约束直接进入 $n,k,w,l'$ 等超参数, 比对总 loss 加一个「稀疏率惩罚」更容易控制 kernel shape. 动态预算可以为每个 query 预测 $n_t$, 训练时还需约束 batch 内最大值、分位数和设备负载. 平均预算满足目标, 少数 query 激活大量 blocks 时, 真实 step time 仍由最慢 row 决定.

### 3.2. 从头预训练能让表示完整适应稀疏图

从随机初始化训练 NSA, 所有层一开始就面对 compressed、selected 与 window 三路约束. 模型可以把长期状态写入压缩器容易保存的表示, 让 fine route 的 query 与 coarse importance 共同成形, 也能在局部窗口外建立逐层传播路径. 论文实验在 27B 总参数、3B 激活参数的 MoE 骨干上预训练, 再做长上下文继续训练; 这一结果对应特定模型、数据与 GQA 配置. 从头训练的风险落在早期路由. 随机 query 与 compressed keys 产生的 top-$n$ 接近随机, fine 分支可能长期读不到有用远距 token. Window 与 compression 路径提供稳定信号, 还可以在初期增大 $n$、提高 coarse gate 或周期性插入 full layers, 再逐步收紧预算. 每次预算变化都要观察 loss 是否出现跳变、route entropy 是否塌缩以及长距离 recall 是否恢复.

训练长度分布同样重要. 大部分样本短于 window 时, 模型几乎没有动力训练 compression 与 selection. 平均 LM loss 会被大量短位置支配, 长序列末端的退化很难看见. 需要同时报告 trailing loss、按 query-evidence 距离分桶的 loss, 并确保足够样本真正跨过 $w$ 和 $nl'$.

### 3.3. 继续训练适合已有 checkpoint, 但要留足适应量

MoBA 与普通 attention 使用同一组 Q/K/V 参数, $k$ 覆盖全部历史 blocks 时可恢复 full attention. 官方论文利用这一性质测试两阶段训练: 大部分 token 使用 MoBA, 后段切回 full attention; 还在 SFT 中保留若干 full attention 层, 缓解 prompt loss mask 导致的稀疏梯度传播问题. 这些实验说明切换可以平滑, 具体比例仍要随模型和任务重新验证. DSA 给出更明确的转换流程. Dense warm-up 保留完整主 attention, 冻结主模型, 用主 attention heads 聚合后的 target distribution训练 Lightning Indexer. 报告中的 warm-up 为 $1000$ steps、每步 $16$ 条 $128$K 序列. 随后 sparse stage 每个 query 选择 $2048$ 个 KV tokens, 优化主模型与 indexer共 $15000$ steps; indexer 继续在选中集合上做 KL 对齐, 主模型用 LM loss 适应稀疏输入.

两阶段 KL 的可见范围不同. Warm-up 的 teacher覆盖整个合法历史, 能直接惩罚 indexer漏掉高质量 token. Sparse stage的对齐限制在当前 selected set内, 更侧重让已选 token的相对 score接近主 attention; 集合外 token无法通过这项受限 KL重新进入. Dense warm-up提供了初始全局排序, sparse stage再保持入选集合内的校准, 主模型则围绕实际 top-k结果调整表示. 转换过程需要三条曲线. 第一条是 full-history teacher上的 indexer mass recall, 检查 selector是否仍能找到主 attention需要的位置; 第二条是 sparse LM loss与 full reference的差距, 检查主模型适应程度; 第三条是 indexer KL, 检查打分校准. KL持续下降而 full-history recall下降时, 受限集合内拟合正在掩盖候选遗漏.

NSA 增加压缩器、三套 K/V 投影与 gate, 从 dense checkpoint 转换时没有 MoBA 那样的参数同构. 可以从原 Q/K/V 复制或分支初始化, 再用 dense teacher做输出蒸馏与 candidate supervision, 但需要重新验证分支平衡. 很短的 SFT 无法替代长上下文继续预训练, 因为 selector 需要看到多种距离、结构和证据密度. 一份可执行的转换日程可以分四段. 第一段保留 full attention, 初始化新分支并做输出蒸馏; 第二段以较大候选预算启用 sparse forward, 让主模型适应漏边; 第三段逐步收紧 $n$ 或 $k$, 同时增加长样本比例; 第四段固定部署预算完成长上下文继续训练与 SFT. 每段都保存 checkpoint, 发生 loss跳变时回到上一个预算, 比一次性从 full切到目标稀疏率更容易定位问题.

预算课程还要避免只按 step变化. 模型在短序列上即使 $n$ 很小也可能覆盖大部分历史, 到长序列才真正稀疏. 可以按实际可见比例 $\rho_t=|S_t|/|V_t|$ 或 evidence距离控制课程, 确保训练早期和后期都包含跨窗口样本. 对混合长度 batch, 记录每个长度桶的 $\rho$ 分布比记录全局平均更准确.

### 3.4. SFT 与 RL 会重新改变稀疏梯度分布

SFT 常把 prompt token 的 LM loss mask 掉, 梯度只从 response 回传. Full attention 能让 response query直接连接全部 prompt, block sparse route 若漏掉某段 prompt, 那段表示在多层中收到的监督会更弱. MoBA 论文用高层 full attention缓解这一现象, 也提示训练原生稀疏不能只在预训练阶段验收. RL 的 rollout 由推理引擎生成, 训练框架再重放序列. 两边必须对 candidate selection、top-k tie、量化和因果 mask保持一致. 同一 token 在 rollout 与训练中看到不同 blocks, log probability 差异会混入 off-policy error. 保存 route indices可以提高一致性, 代价是额外轨迹存储; 重新计算则要求两个 runtime 数值对齐. 长 CoT 还会改变预算压力. Prompt 证据在生成后段距离越来越远, 固定 window 无法覆盖, selection 要持续找回早期状态. 训练集若只有短 response, selector 可能只学到 Prefill 内检索, 到长 rollout 后段召回下降. RL 验收要按生成位置记录候选覆盖、gate 与 TPOT, 不能只比较最终 reward.

### 3.5. 训练与推理必须共享支持语义

训练期 selector若在全精度 score上取 token top-k, 推理期改成量化 block top-k, 两者预算同为 $k$ 也不是同一支持. block会带入组内额外 token, 量化会改变排序, page对齐与capacity截断还会继续修改集合. 模型部署前要用推理真实规则做足够长适配. 支持一致性可以逐项列出: 合法集合 $V_t$、选择单位、预算、tie-breaking、局部/window合并、去重、容量溢出、精度和fallback. 任一项变化都可能改变 $S_t$. 训练可用慢参考实现, 数学语义必须与推理kernel相同;kernel优化不能偷偷改变边界规则. Prefill与Decode也可能使用不同支持实现. Prefill成块处理许多queries, Decode逐 token;如果训练只覆盖Prefill block mask, 逐步Decode的候选更新与state追加可能未学到. 在训练或验证中用逐 token路径重放同一序列, 与并行因果实现对齐, 能检查支持和logits一致性.

dropout会让训练支持更丰富, 推理关闭后分布收缩. 对attention probability dropout问题较小, 对router score或mask dropout会直接改变可见图. 若它被用作探索, 需要确认关闭后 learned selector仍有足够覆盖. 可在训练末段降低router dropout, 让模型适应确定性支持. 长度一致性同样关键. 训练长度 $N_{train}$ 内每个query可从有限历史选择, 推理到更长 $N$ 后, 候选竞争数增加, top-k比例下降, score极值分布变化. 固定 $k$ 在长度外更稀疏. 训练应包含目标长度或使用能控制长度分布变化的目标, 不能只验证kernel能运行.

### 3.6. 路由器与主模型的学习速度要协调

selector学得太快, 会在主 attention尚未形成前根据早期噪声固定支持;学得太慢, 主模型长期在随机或粗糙图上优化, 学会绕过远程分支. 可以为router使用独立学习率、warmup与梯度裁剪, 目标是让支持随表示改善而更新, 又不在每步剧烈跳变. 冻结方案能帮助定位. 先用teacher或高预算训练主模型, 暂时冻结selector;再固定主模型训练selector模仿oracle;随后联合微调. 分阶段降低耦合难度, 最终质量可能受早期图限制. 从头联合训练更原生, 优化相互依赖更强. 两种配方回答不同问题, 应在相同token预算下比较.

梯度尺度也不一致. 主loss按每个token一个标量, selector可能为每个query-key对产生大量logits. 若路由loss对所有边求和, 长度翻倍会显著增大梯度;若按合法边平均, 单个关键正例信号被大量负例稀释. 常见做法按query归一化, 再对正负样本或教师mass加权. 共享Q/K参数时, 主attention梯度与router辅助梯度可能冲突. 一个方向有利于候选排序, 另一个有利于候选内表示. 可以测梯度余弦, 冲突明显时分开投影、使用adapter或调整损失权重. 参数共享节省容量并传递信号, 也把两个目标绑定在同一空间. 训练日志应把主loss、路由loss、coverage、margin、support churn与分支梯度分开. 总loss下降无法说明selector改善, 因为主模型可能越来越依赖window捷径. 路由recall提高也不保证任务变好, 教师目标可能与最终主attention不同. 多条曲线要在同一probe batch上对应.

### 3.7. SFT 会改变支持分布

预训练文本的依赖多由局部语言统计主导, SFT指令包含问题、上下文、格式约束与答案, 远程证据位置和输出结构不同. router在预训练阶段形成的局部偏好可能不适合长文问答. SFT需要继续更新selector, 或至少验证冻结路由是否覆盖指令数据所需证据. 短SFT样本还会使长程分支缺少梯度. 即使底座支持128K, SFT大多只有几千 token, selector会在局部样本上继续优化, 产生遗忘. 混入长上下文SFT、保持预训练路由蒸馏或降低router学习率, 可以保护长程能力. 哪种做法有效取决于SFT数据量和支持漂移.

答案only loss让context token本身没有直接next-token监督, 路由仍通过答案位置反传到被读取证据. 若答案很短, 每个样本提供的router query很少. 在问题理解和中间推理位置加入监督可增信号, 也会改变SFT目标. 至少要统计有效router queries数量, 不能只看总context tokens. 格式模板容易形成捷径. selector持续选择开头system prompt、末尾问题和最近token, loss也能下降;正文中段证据被忽略. 随机化证据位置、加入无关段落和相同模板下的不同答案, 能迫使支持依赖内容. 固定模板上的高准确率不足以证明动态路由.

### 3.8. RL 的稀疏奖励更延迟

RL中一条长轨迹只在结果或若干步骤得到奖励, selector在早期漏掉证据与最终失败相隔很远. 策略梯度方差已经较高, 离散支持再增加一层信用分配. 若router动作被视为策略的一部分, 需要记录其log-prob并纳入重要性比率;若router确定性地由hidden产生, 梯度主要通过模型输出策略间接到达. 奖励可能鼓励更长推理, 同时增加Decode steps与历史长度. 固定 $k$ 下支持比例进一步下降, selector要处理不断增长的轨迹. agent任务还会插入observation, 这些片段在后续步骤的重要性可能突变. RL数据分布与预训练文本差别很大.

成本可以进入reward, 例如惩罚选中blocks或full attention调用. 若惩罚过强, 策略会选择便宜但信息不足的图;奖励稀疏时, 成本信号每步都有, 更容易主导优化. 应先在固定质量边界下调成本系数, 并监控任务分桶, 避免平均reward用短任务收益遮住长任务退化. off-policy数据还存在支持不一致. 旧策略生成轨迹时的hidden与selector不同, 当前模型重放同一tokens会选择新集合. 如果训练只存token不存路由状态, 无法精确重现行为策略计算图. 对常规语言模型更新可以重新前向, 对把router视为显式动作的算法则要保存或重建其概率.

RL阶段预算若与部署一致, 模型有机会适应真实成本;为了训练吞吐临时用更大预算, 部署收紧会再次产生结构偏移. 可以在部分rollout或更新batch使用目标预算, 测质量-成本曲线. 稀疏支持属于策略执行的一部分, 不能只在RL结束后替换.

### 3.9. 课程学习要覆盖距离、干扰与操作类型

只增加序列长度不是完整课程. 路由难度还取决于候选数量、相似干扰、证据位置和记忆操作. 单一needle、无干扰时, selector可能靠表面模式找到证据;加入多个相似keys、覆盖更新与多跳关系后, 才能训练细致支持. 距离课程从窗口内、刚越过窗口到多个窗口外, 检查模型何时启用远程分支. 干扰课程增加相似但错误的blocks, 训练margin. 操作课程区分复制原文、取最新值、累计统计和多证据组合. 四类任务需要不同支持, 能防止router把「远」简单等同于「重要」.

预算课程与任务课程联动. 简单阶段用大预算会让模型不必精确选择, 难阶段突然收紧容易崩溃. 可以先在大预算下学会任务, 再逐步缩小并增加干扰;也可以固定目标预算、从少候选到多候选增长长度. 两条路径分别控制支持容量与搜索难度. 课程转换处要看旧能力. 学会远程检索后加入大量局部数据, router可能重新塌缩;学会最新值覆盖后加入计数, 过强遗忘会伤害累计. 混合replay与分桶验证能发现灾难性遗忘. 平均loss连续下降并不保证每种记忆操作保持.

## 4. 稀疏预算必须同时满足数学和硬件

### 4.1. 三路总预算可以直接手算

NSA 在位置 $t$ 读取的逻辑条目数近似为

$$
N_{\mathrm{NSA}}(t)=
N_{\mathrm{cmp}}(t)+nl'+w. \tag{16}
$$

取论文训练配置 $l=32,d=16,l'=64,n=16,w=512$, 当 $t=65536$ 时, $N_{\mathrm{cmp}}=4095$, selected raw tokens 为 $1024$, window 为 $512$, 总计 $5631$, 约占 full history 的 $8.59\%$. 三路各自计算 attention, 重叠位置也会重复, 所以这个比例表示逻辑 keys 数, 还不能直接当成 kernel 加速比. 整个长度 $T$ 的训练前向成本可近似写成

$$
C_{\mathrm{NSA}}(T)
\propto
\sum_{t=1}^{T}
\left(\frac{t}{d}+nl'+w\right)d_h
=O\left(\frac{T^2d_h}{d}
+T(nl'+w)d_h\right). \tag{17}
$$

压缩分支仍随历史增长, 系数由 stride $d$ 缩小; selection 与 window 在预算固定后对每个 query 为常数. 计算 compressed entries 的 MLP、importance 映射、top-$n$ 和 gate 还要另计. Decode 的常驻状态则包含三套分支 cache 与压缩表示, 它的字节比例和式 (17)不同. MoBA 的成本结构更简单. 长度 $t$、block size $B$、top-$k$ blocks 时, router 扫过约 $t/B$ 个 block keys, 主 attention 读取最多 $kB$ 个 raw tokens, 当前 block包含在 $k$ 内. $t=32768,B=512,k=3$ 时, 主 attention 读取最多 $1536$ tokens, 即 full history 的 $4.69\%$, 另加 $64$ 个 block summaries 的路由. Block 越细, route candidates 增加; block 越粗, 每次选中带入更多无关邻居. MoBA 把当前 causal block与历史 non-causal blocks分别送入变长 FlashAttention, 再用 online softmax合并两部分. 合并需要保存每部分的 row max与归一化和. 若当前块输出为 $(o_c,m_c,l_c)$, 历史块输出为 $(o_h,m_h,l_h)$, 统一最大值 $m=\max(m_c,m_h)$, 则

$$
o=\frac{
e^{m_c-m}l_co_c+e^{m_h-m}l_ho_h}
{e^{m_c-m}l_c+e^{m_h-m}l_h}. \tag{18}
$$

直接把 $o_c,o_h$ 平均会丢失两个分区的 softmax分母, 与在候选并集上做一次 attention不等价. 当前块强制入选还解决了 causality: block mean可能包含 query之后的 token, 它不能用于决定当前块是否可见, 当前块内部必须继续使用 triangular mask. 计算稀疏也不自动压缩常驻 cache. Selection 分支为了让未来 query任意选择历史 block, 通常仍要保存全长 raw K/V; window分支只保存最近 $w$; compression分支保存约 $t/d$ 个 entries. 假设 $H_{kv}=4,d_k=192,d_v=128$, BF16下每 token一套 K/V为 $4(192+128)\times2=2560$ bytes. $t=65536$ 时, selection cache约 $160$ MiB, window cache约 $1.25$ MiB, compression entries约 $10$ MiB, 都是单层逻辑值. 三路独立投影的总 cache可能超过一层 full attention, NSA主要节省 attention计算与每步实际读取, cache容量必须单独核算.

这也影响「训练原生」的系统目标. 长 Prefill与训练关注少算 QK/AV, Decode关注少读实际候选 KV; 高并发服务还关心常驻容量. 一个结构可以在前两项获益, 第三项持平或变差. 若要同时压 cache, 还需跨层共享、量化、淘汰或固定状态机制, 这些改动会引入新的训练约束.

### 4.2. GQA 共享候选决定真实 KV 读取

假设一个 GQA group 有 $H=16$ 个 query heads, 每个 head 独立选择 $n=16$ 个 blocks. 若集合互不重合, KV 读取并集达到 $256$ blocks; 即使每个 head 的算术都很稀疏, group 共享的 K/V 仍要加载巨大并集. NSA 先用式 (9)把 heads 的 importance 相加, 再为整个 group 选择 $16$ blocks, 让同一份 K/V 在 SRAM 中供 $16$ 个 queries复用. 共享也会压低 head 专门化. 一个只负责远距代码定义的 head, importance 可能被其他局部 heads 的总量盖过. 验收要比较独立 head oracle、group-shared candidate 的 per-head attention-mass recall, 再记录实际 unique blocks 与 HBM bytes. 平均 recall 很高时, 最差 heads 仍可能决定代码、复制和精确检索能力. Kernel block $B_k$ 与 selection block $l'$ 还要整除或有清楚的 padding规则. NSA 让连续 selected blocks 配合 Tensor Core tiles, group-centric kernel 按一个位置的一组 query heads装入 SRAM, 再依次加载共享 KV blocks. 算法把 $l'$ 从 $64$ 改到 $48$, 可能提高候选纯度, 也可能破坏 tile、引入 padding 和分支. 预算搜索应使用真实 kernel shape, 不要只按理论 token 数排序.

### 4.3. Forward、backward、Prefill 与 Decode 是四条曲线

训练 forward 有大量 queries, 主要关注矩阵计算与 tile 利用率; backward 还要计算 $dQ,dK,dV$, 并重用或重算 route indices. 保存全部 indices增加显存, 重算要求 top-$n$ 与 tie-breaking确定. Dropout 若参与 score, backward 重算还要恢复相同随机状态. Prefill 与训练 forward接近, 但无需保存反向激活, 可以使用更激进的 workspace复用和量化. Decode 每次只有一个 query, 常由 KV cache读取与小 kernel launch主导. NSA 论文在 $64$K 上分别报告 Decode、Forward、Backward 相对 full attention 的加速, 这种分阶段口径比单一「attention 加速」更有信息量. DSA 展示了另一种成本分解. 主 Sparse MLA 从 $O(T^2)$ 降到 $O(Tk)$, Lightning Indexer 仍对全历史做低维扫描, 理论上保留 $O(T^2)$ 项. 训练 indexer、top-k 与 main KV gather 都必须计入 step time. MoBA 的 mean pooling、Q-to-block score、query 重排与 online softmax合并也属于总成本, official efficient implementation 与 naive mask实现的差距说明 route glue不可忽略. 短上下文的交叉点可以用固定开销解释. 设 dense attention耗时近似 $aT^2$, sparse主计算为 $bT(nl'+w)+cT^2/d$, route、排序和重排为 $rT$. Sparse开始占优的长度满足

$$
aT^2>
bT(nl'+w)+\frac{cT^2}{d}+rT. \tag{19}
$$

当 $T$ 很小时, $rT$ 与 kernel launch占比高, 优化过的 dense GEMM可能更快; $T$ 增长后, full attention的平方系数开始主导. 实测交叉点随 dtype、batch、head维、GPU和 backward策略变化, 应从长度曲线读取, 不能由逻辑稀疏率直接推算. Backward 的工作量还受参数梯度累积影响. Selection blocks分散时, 多个 queries会向同一 K/V block写入梯度, 实现可按 block聚合 query后做规则 GEMM, 或使用原子累加处理散射. 前者需要 query重排与offset metadata, 后者可能发生写冲突. NSA 的 group-centric布局不仅服务 forward KV复用, 也影响 backward如何汇总 $dK,dV$.

### 4.4. 分布式训练把候选变成通信计划

Context parallel把序列切到多张卡时, query 选中的 blocks 可能位于远端 rank. 所有 rank先计算本地 coarse scores, 再做 global top-$n$, 随后只交换入选 K/V; 或先复制 compressed summaries, 每个 query owner独立路由. 前者减少 summary副本, 多一次同步; 后者让路由本地化, 需要维护全局压缩状态. 候选负载也不均匀. 大量 queries选中同一早期 block 时, 其 owner成为通信热点; 完全随机分布则增加 all-to-all目的地. $\mathcal L_{\mathrm{balance}}$ 可以改善流量, 也可能强迫 query离开最佳证据. 数据并行、tensor parallel和context parallel组合后, 应记录每 rank发送字节、最大接收量、等待时间与 route recall. Pipeline parallel同样受 branch 影响. 三套 K/V 投影与 gate若跨 stage, activation生命周期会延长; full/sparse hybrid layers分布不均还会造成 stage time差异. 分层预算应与 stage划分一起搜索, 训练 FLOPs 总量相同并不保证 pipeline均衡.

### 4.5. 前向边数只是训练成本的第一项

设每个query保留 $k$ 个keys, head维为 $d_h$, query数为 $N$. QK与PV前向主项约为

$$
F_{attn,fwd}\approx4NH_qkd_h.
$$

反向要计算 $dQ,dK,dV$ 和概率梯度, 主矩阵乘法通常约为前向的两倍, 前反向合计可粗估为 $12NH_qkd_h$. 这是规则稀疏图上的理想算术, 未计selector、索引、gather/scatter与负载不均. selector若用 $H_I$ 个 $d_I$ 维heads全扫历史, Prefill点积约为 $O(N^2H_Id_I)$, Decode单步为 $O(NH_Id_I)$. 主attention已经从 $N^2$ 降到 $Nk$, selector仍全扫时会成为新主项. Head fusion、低维摘要、分块筛选和跨层共享分别减少 $H_I$、$d_I$、候选位置和层重复. 索引保存也有训练容量. int32 positions为 $4Nk$ bytes/层;若反向重用相同support, 需要保存或重算. $N=32768,k=2048$ 时单层256 MiB, 多层独立会很大. block mask可以用block id压缩, support规则化还可由参数重建. 训练稀疏不仅减少attention probability, 离散图本身也是激活. gather前向从主KV读取选中token, 反向要把 $dK,dV$ scatter回原位置. 多个queries选择同一key时发生归约, 热门位置产生写冲突与负载倾斜. block稀疏可组织为矩阵乘法, 任意token图更依赖排序或原子操作. 理论边数相同, 反向墙钟可能差很多.

若训练使用soft relaxation对全部历史保留非零权重, 主图仍近似稠密. 只有在前向和反向真正裁剪支持时, 才获得稀疏训练成本. 可以先用soft/teacher阶段学习router, 再切hard sparse完成大部分token训练;总成本按各阶段token数加权, 不能只报最终阶段复杂度.

### 4.6. Block预算与token预算不能直接换算

block大小为 $B_k$, 每个query选 $b$ 个blocks, 名义token预算为 $k=bB_k$. 边界block内可能只有一部分合法或重要token, 物理kernel仍执行整块. block利用率 $u$ 定义为有效目标token数除以被选block槽位, 理想token级工作被放大约 $1/u$. block越大, 矩阵kernel利用率更高、索引更短, 候选粒度更粗;block越小, 路由接近token级, 元数据和调度增加. 训练可以让相邻重要token聚集到同一block吗? 序列位置固定, 模型只能学习在已有文本布局上选择. 文档段落和局部语义常有连续性, 随机键值检索可能高度分散. MoBA将KV blocks视为attention experts, query路由到top-k blocks. 负载由每个block接收多少queries决定, 不由每个query选择数决定. 固定每query $b$ 保证总边数, 仍可能所有queries拥挤到同一block. 并行实现要在语义热门与计算均衡之间处理容量.

覆盖的分母也要按目标定义. token recall计算教师top-k token有多少落入选中blocks;block recall计算教师重要blocks;attention-mass recall给token加权. 一个block只含一个重要token也算block命中, 剩余槽位是执行浪费. 同时报告三者, 才能判断路由质量和硬件效率. window与global blocks合并时要去重. 每个query总物理blocks可能小于 $b_{window}+b_{global}$, 若全局router重复选择窗口内block, 远程覆盖下降. 可以在router合法集合中排除window, 或去重后补足global预算. 两种规则影响训练梯度和推理support, 需要保持一致.

### 4.7. 稀疏率随长度怎样变化

固定 $k$ 时支持比例 $k/N$ 随历史长度下降. 训练在8K长度、$k=2048$时保留25%;推理到128K只保留1.56%. 模型同时面对更多候选与更严格压缩, 即使selector参数不变, 难度已经变化. 长度外推需要验证绝对预算是否足够. 固定比例 $k=\rho N$ 保持覆盖率, attention复杂度仍为 $O(N^2)$, 只降低常数. 容量和kernel规模随长度增长, 不能称为线性. 介于两者之间可取 $k=cN^\alpha$, $0<\alpha<1$, 成本为 $O(N^{1+\alpha})$. $alpha$控制能力与渐近成本. 分层预算允许少数层用较大 $k$, 其余层小预算. 总边数为 $N\sum_lk_l$. 若关键检索层预算大、局部加工层小, 可能优于每层平均分配. 训练要让信息在大预算层进入后被后续层利用. 只按层号手工分配未必适合所有任务.

query自适应预算让简单位置小 $k$, 困难位置大 $k$. 平均成本下降, batch执行受最大或分桶预算影响. 训练要学习「不确定性」, 并防止router为省成本系统性低估. 可用margin、熵或覆盖预测决定档位, 监督来自oracle所需预算. 长度变化还影响极值. 历史候选越多, 随机高score更可能出现, top-k阈值上升. 如果score校准只在短序列完成, 长序列会出现更多假阳性, 挤掉真实证据. 对比学习的负样本数量与推理候选规模需要匹配, 或采用长度稳健的归一化.

### 4.8. 分布式成本由稀疏图拓扑决定

序列按设备分片时, query的选中blocks可能位于本地或远端. 训练前向要取得远端K/V, 反向把梯度送回owner. 若每个query随机选全局blocks, 通信接近all-to-all;若主要选择局部连续blocks, 邻居通信即可. 相同边数对应不同网络代价. router先在各设备算本地score, 上送local top-k再做global top-k, 可以精确恢复全局结果: 未进入某设备local top-k的元素不可能进入global top-k. 每设备上送 $k$ 个候选, 汇总规模为 $pk$. 若最终只取 $k$, 大部分上送候选被丢弃, 仍比传全量score小. 负载热门block所在设备会接收大量query. 复制热门KV blocks可减通信热点, 增加状态副本与一致性;迁移queries到KV owner可在远端计算局部attention, 再归并在线softmax统计. 哪种方式更好取决于query bytes、KV bytes与复用次数. 机制理解只需明确图拓扑决定通信, 不把token稀疏率直接当网络稀疏率.

训练反向通信可能比前向更复杂. forward将query发到选中KV设备, backward需要 $dQ$ 返回query owner, $dK,dV$在KV owner聚合. 支持图动态变化时, 每步通信计划也变化. block级路由和固定容量让消息可批量, token级散点会产生碎片. 负载均衡loss若按block计数, 应考虑设备映射. 每个block使用均匀不推出每设备均匀, 因为block可能不均匀分布或复制. 直接约束每设备预计字节/计算更贴近系统, 会把硬件拓扑写入训练目标. 模型迁移到不同设备数时, 路由正则语义也会变化.

## 5. 失效模式与消融要能定位责任

### 5.1. 四类失败有不同指纹

第一类是 coarse blindness. Compression output在 LM loss 上可用, importance 却找不到原始关键 block. 表现为 coarse 分支质量尚可、fine candidate recall低, 把 oracle blocks强制加入后任务立刻恢复. 需要调整压缩器容量、stride、importance映射或 route supervision. 第二类是 fine budget不足. Candidate 排序基本正确, $n$ 太小导致多证据任务只能取回一部分. 增大 $n$ 后 recall 与质量同步改善, group内最差 head提升明显. Block size过大也会浪费预算: 一个关键 token带入整块邻居, 占用本可容纳其他证据的名额. 第三类是 local domination. Window gate长期接近 $1$, compression 与 selection梯度很小, 短文本 loss正常而窗口外任务失败. 增加长样本、调整 gate初始化、分支 dropout或限制训练初期 window容量可以验证原因. 删除 window 后 loss剧烈上升并不表示它应无限增强, 还要观察另外两路是否获得长期学习机会.

第四类是 system mismatch. 训练使用 $n=16$、完整 group-shared blocks, 部署 kernel因 workspace限制截成 $n=12$ 或采用不同去重顺序; Prefill处理不完整 compression block时泄漏未来 token; backward重算 top-$n$ 与 forward tie顺序不同. 这些问题常表现为离线 PyTorch正确、fused kernel质量下降或梯度不稳定. 因果边界需要覆盖三套规则. Compression entry 只有在其 block末端不超过 query位置时才能使用, 重叠 stride会让相邻 entries拥有不同完成时间; selection block若包含 query自身, block内要应用 triangular mask; window 起点则为 $\max(1,t-w+1)$. Packed sequence还要在文档边界重置三路状态, 否则 compressed block可能拼接两篇文档, selected index也可能跨样本读取. 第五类是 routing hotspot. 某些通用开头、sink或模板段落被大量 queries选中, 质量保持正常, 单个设备或 KV page却成为带宽热点. 随机打散 block owner能改善负载, 会增加位置映射; balance loss能分散候选, 也会影响证据准确性. 系统侧应把 block访问频次直方图与 per-rank等待时间一起记录.

第六类是长度外退化. 训练到 $32$K 时, coarse selector只需在约 $32K/d$ 个 entries中排序; 部署到 $128$K 后候选数增为四倍, top-$n$ 预算不变, 排名边界更拥挤. Route entropy可能上升, 关键 block的 margin下降. 评测要固定 evidence类型逐步拉长 distractors, 才能区分距离问题与候选数量问题. 还有一类误差来自跨层传播. 某层没有直接选中证据, 证据可能先由 compression分支写入中间 token, 下一层再经 window或selection读取这个中间表示. 单层 candidate recall低并不必然造成最终失败, 但传播路径变长后需要足够层数, 中间表示也可能丢失精确字符串. 训练原生模型会利用这类替代路径, 评测仍要知道它依赖了多少层. 可以把每层稀疏图记为邻接矩阵 $A^{(l)}$, 从输入位置 $s$ 到输出位置 $t$ 的 $L$ 层可达性由布尔乘积

$$
R^{(1:L)}=A^{(L)}\odot A^{(L-1)}\odot\cdots\odot A^{(1)} \tag{20}
$$

决定, $\odot$ 表示布尔矩阵乘法. Window使局部信息逐层移动, compressed nodes提供远距低分辨率边, selected blocks提供远距高分辨率边. Candidate recall测直接边, 式 (20)测最终是否存在传播路径, 两者共同解释任务结果. 可达性只说明路径存在, 没有衡量信息在每次 residual、normalization和非线性变换后还剩多少. 可以继续记录证据位置对目标 logit的梯度范数, 或逐层做 activation patching, 观察替换某层证据表示后输出变化. 图可达但影响接近零时, 传播通路在数值上已经失效; 直接边缺失但 patching仍有效时, 模型使用了中间 relay.

传播消融可以只在一层注入 oracle block, 再逐步增加注入层数. 单层注入无效、多层连续注入后恢复, 说明证据需要持续高分辨率访问; 早期一层注入即可恢复, 说明后续层能通过 hidden state携带信息. 对随机字符串复制, 中间压缩通常更难; 对主题分类, 一次 coarse读取可能已经足够.

层间共享 selector还会改变传播图的多样性. 每层独立候选可能让不同深度依次读取多个证据, 跨层复用则重复同一组边. 它能降低 route成本, 多跳任务的覆盖可能下降. 原生训练若计划部署共享 candidates, 训练阶段也应使用相同共享组, 让模型在固定图上学习传播策略.

### 5.2. Oracle replay把路由误差与容量误差分开

对每个 query计算高预算或 full attention teacher, 取其最优 block集合 $S_t^*$. Learned candidate 的集合 recall为

$$
R_t^{\mathrm{set}}=
\frac{|S_t\cap S_t^*|}{|S_t^*|}, \tag{21}
$$

attention-mass recall则为

$$
R_t^{\mathrm{mass}}=
\frac{\sum_{s\in S_t}p_{t,s}^{*}}
{\sum_{s\in S_t^*}p_{t,s}^{*}}. \tag{22}
$$

集合 recall 与质量 recall可能给出相反印象. 假设 oracle选中四个 blocks, attention mass分别为 $(0.70,0.20,0.08,0.02)$. Learned route选中第一、第二个和两个无关 blocks, set recall为 $2/4=50\%$, mass recall却达到 $0.90/1.00=90\%$. 对一般语言建模可能已经够用, 第三个 block若包含任务唯一答案, 任务仍会失败. 因此 recall还要按证据标签、head和任务类型切分. Oracle 本身也要说明来源. 用同层 full attention top blocks测的是「若保留稠密模型分布, selector能否模仿」; 用任务标注证据测的是「候选是否覆盖外部真值」; 用梯度或删边反事实得到的 oracle测的是「哪个 block真正影响 loss」. 三种集合不必一致. 训练原生模型可能发展出与 full teacher不同但有效的稀疏路径, 不能把 teacher overlap当作唯一质量标准. 先用 learned route 跑一次, 再把 $S_t$ 换成同预算 oracle. Oracle恢复说明 selector承担主要误差; oracle仍差, 则 block粒度、预算或三路输出容量不足. 再把预算扩大到覆盖全部 blocks, 可以检查 sparse kernel与 full reference 是否数值对齐.

NSA 还要分别替换三路. 保持总读取 tokens不变, 用均匀 compressed blocks、oracle selected blocks和固定 window组合, 才能区分 coarse输出、route与local通路. MoBA可以从 top-$k$ 平滑扩大到 all blocks检查收敛; DSA可以保持 main model不变, 替换 indexer positions定位 selector质量.

### 5.3. 基础消融覆盖结构、训练和硬件

结构消融至少扫描 $l,d,l',n,w$, gate类型, 分支独立或共享 K/V, GQA group-shared或per-head candidates. 每个点同时给出逻辑 keys、unique blocks、真实读取字节和质量. 只保持相同理论稀疏率不够: $8$ 个 $128$-token blocks 与 $16$ 个 $64$-token blocks读取量相同, 候选分辨率与 kernel效率不同. 训练消融比较从头 sparse、full-to-sparse课程、dense teacher蒸馏、不同 route loss权重, 以及候选预算收紧速度. 对已有 checkpoint还要报告继续训练 tokens, 不能把很长的转换训练描述成零成本插件. MoBA 官方实现提示需要 continue training; DSA报告了 warm-up与 sparse stage规模; NSA报告从预训练到长上下文适配的完整路径. 系统消融关闭 fused top-k、query重排、group KV复用、backward重算和低比特 cache, 观察每项对 step time与显存的贡献. 短序列下 route固定开销可能超过省下的 attention, 长度增加后才出现交叉点. 曲线至少覆盖窗口内、候选预算刚饱和、中长上下文和训练长度外四段.

消融还要保持有效训练计算可比. Sparse模型每 step更快时, 固定 steps意味着它使用更少 wall-clock却处理相同 tokens; 固定 wall-clock又会让它看到更多 tokens. 两种比较回答不同问题. 至少同时给出等 tokens、等训练 FLOPs和等 wall-clock中的两种, 并报告学习率 schedule按 steps还是 tokens推进. 数据消融按依赖形态组织. 局部续写检验 window, 跨段主题与统计聚合检验 compression, 随机字符串和代码定义检验 selection, 多证据推理检验 $n$ 是否容纳全部 blocks. 将 evidence放在 block中心、边界和跨两个 blocks的位置, 能发现 block segmentation造成的召回差异. 数值正确性从很短序列开始. 把 $n$ 增到覆盖所有 selection blocks, $w$ 增到覆盖历史, 再逐分支与 PyTorch reference对齐 output和 $dQ,dK,dV$. 随后恢复目标预算, 固定 indices比较 sparse kernel; 这一关通过后再启用 route、量化和分布式通信. 逐级加入功能能将数值误差与候选误差分开.

### 5.4. 最终验收同时看学习、召回与执行

学习侧记录总 LM loss、trailing loss、三路输出范数、gate分布、route loss和每路梯度范数. 召回侧记录 per-layer、per-head、per-distance的 set recall、attention-mass recall, 以及代码、随机字符串、多证据和长 CoT任务. 执行侧记录 Forward、Backward、Prefill、Decode latency, 峰值显存、HBM bytes、unique pages、top-k时间与通信不均衡. Checkpoint还要携带稀疏结构元数据: block length、stride、top-$n$、window、GQA grouping、full/sparse layer表、route loss版本与 tie-breaking规则. 权重相同而其中一个字段变化, attention图已经不同. Runtime加载时应核对这些字段与 kernel支持的 tile, 遇到不兼容配置直接报错, 避免静默 padding或预算截断. 复现实验保存每层采样的 route indices与 gate即可显著提高可诊断性. 同一 batch在 reference、训练 kernel和服务 kernel各跑一次, 比较候选、分支 output与最终 logits. 候选相同而 output不同, 排查 kernel和量化; 候选先分叉, 排查 score、mask和 top-k; output一致而训练曲线不同, 再检查 backward与优化器状态.

训练原生稀疏的收益最终要同时满足三件事: 模型在目标稀疏图上收敛; selector在预算内保留任务需要的证据; kernel确实跳过未选计算与内存读取. 任意一项缺失都会产生常见假象: loss正常但远距检索差, recall漂亮但GPU没有加速, kernel很快但反向传播仍在计算稠密 attention. NSA、MoBA 与 DSA给出了三种可复用的设计模板. NSA用可微 coarse路径支撑 hard fine selection, 并单列局部窗口; MoBA用参数同构换取 full/sparse平滑转换; DSA用 teacher warm-up和解耦梯度训练低维 token selector. 新结构可以组合其中的思想, 也必须重新说明候选监督、主 attention梯度、训练阶段和硬件预算.

### 5.5. Oracle分层能给出三个上限

第一种oracle保留模型当前主attention参数, 用稠密或高预算attention的真实质量选择最佳 $k$ 个位置. 它回答当前表示与预算下, selector若完美能达到什么结果. 若该oracle仍明显低于稠密, 预算或稀疏主attention是瓶颈. 第二种oracle扩大预算到 $M>k$, 观察质量随预算曲线. 若从 $k$ 到 $2k$ 快速恢复, 当前预算靠近能力拐点;扩大很多仍无改善, 问题可能在训练表示、分支融合或任务本身. 曲线比单一oracle点更能指导预算. 第三种oracle允许每层独立支持, 与共享support、共享block或固定pattern比较. 它分离层级适应性上限. 如果独立oracle显著更好, 跨层共享或规则mask限制了换证据;差异很小, 可进一步压缩路由计算.

oracle还要避免未来信息. 使用最终答案标注直接挑证据可作为任务上界, 不能当可部署selector的教师唯一来源;它可能使用当前query无法推断的信息. 稠密attention教师只依赖前缀, 更符合因果性, 也可能尚未学会正确关注. 将oracle分数与learned selector比较, 可定义可学习缺口

$$
\Delta_{learn}=Q_{oracle}(k)-Q_{learned}(k),
$$

容量缺口为

$$
\Delta_{cap}=Q_{dense}-Q_{oracle}(k).
$$

前者大应改路由信号、探索与优化;后者大应增预算、增加分支或改变稀疏结构. 两者都小而系统没加速, 问题转向kernel、布局与通信.

### 5.6. 八个反例检验原生稀疏的边界

第一个是随机索引. 序列包含大量随机键值, 末尾随机查询任意key. selector必须在不知道查询前保存所有keys的可检索表示, 查询后从长历史中准确选一个. 固定小预算可完成单次读取, 路由器需要足够表达和训练覆盖;随机探索在超长历史中的命中率很低. 第二个是多证据求和. 答案依赖 $m$ 个分散values, 若 $m>k$, 单层单head的support上限不足. 多heads各选不同集合、coarse summary或跨层逐步累积可以解决, 训练必须形成互补支持. 所有heads塌缩到同一top-k时, 名义总预算被重复浪费. 第三个是最新值覆盖. 同一key多次赋值, 任务问当前值. 稠密attention可能选择最近一次, router若按内容相似把所有版本都选入, 占用预算;window或位置偏置更合适. 只用随机needle训练, 模型不一定学会版本语义.

第四个是计数. 序列每处出现事件都要累计, 精确答案依赖大量位置. 选择少数原token不适合, coarse compression或recurrent state能维护充分统计. 这个反例说明动态top-k并非所有长程任务的自然表示. 第五个是局部捷径. 训练数据中答案经常出现在问题附近, window分支即可降低loss, global selector没有动力. 测试把证据随机移远后性能骤降. 原生训练也会学数据捷径, 架构包含远程分支不保证使用. 第六个是支持外推. 训练最长8K、top-k为2K, 测试128K保持2K. 候选数增16倍, 支持比例从25%降到1.56%, score极值与干扰都变化. 模型结构支持128K不代表selector在这个压缩率上受过训练. 第七个是hard/soft错位. 训练soft distribution让100个低权重位置合计贡献重要信号, 推理hard top-k删除其中大部分, 单个权重都小却总质量很大. 训练loss优秀, hard评测下降. 在训练中执行目标hard support才能暴露.

第八个是负载容量. router语义上选对热门block, 设备capacity溢出后把部分queries改路由或丢弃. 离线无限capacity质量正常, 在线吞吐配置失败. capacity规则必须进入训练或至少进入端到端验证. 这些反例分别测随机定址、支持容量、覆盖更新、充分统计、数据捷径、长度外推、支持一致性和系统容量. 单一长上下文benchmark通常只覆盖其中少数. 原生稀疏的边界由任务需要的记忆操作决定, 不由上下文长度一个数字决定.

### 5.7. 支持多样性如何量化

对同一query的 $H$ 个heads, 支持集合为 $S_1,\ldots,S_H$. 平均两两Jaccard高表示heads重复, 低表示多样. 低重合不自动更好, 各head可能随机分散. 还要看并集的教师mass与每个head输出贡献. 有效总预算为并集大小

$$
k_{eff}=\left|\bigcup_{h=1}^{H}S_h\right|.
$$

名义预算 $Hk$ 在完全重合时 $k_{eff}=k$, 完全不重合时最多 $Hk$. GQA共享候选会主动降低多样性, 换取KV读取复用. 是否值得取决于不同query heads需要的证据是否相近. 跨层也可定义支持多样性. 相邻层重合高利于共享, 多跳任务可能需要层间更新. 目标不应统一最大化或最小化重合, 而是让重复边承担持续加工, 新边在表示获得新线索时进入. 按任务阶段观察集合进入/退出比静态平均更有解释力. router熵、Jaccard和并集覆盖组合起来能区分三种状态: 低熵高重合是确定性塌缩;高熵高重合可能是score不确定但top-k固定;低重合高覆盖表示有效分工;低重合低覆盖则是随机噪声. 再看任务loss与margin确认.

多样性正则若直接惩罚head重合, 会迫使heads避开共同重要token. 可只对超出最低共享核心的部分鼓励差异, 或以教师mass增益为目标: 新head选择的位置应增加并集覆盖. 这样多样性服务于证据, 不成为独立审美指标.

### 5.8. 支持的因果性需要专门测试

替换位置 $t$ 之后的未来tokens, 所有 $i\le t$ 的selector scores、support与logits都应保持不变. 这项测试同时检查router输入、block摘要、负载统计和candidate阈值. 若训练用整个sequence统计block重要性, 早期query可能间接看到未来. 动态阈值尤其危险. 若阈值由batch或整段score分布估计, 包含未来queries或其他文档, 当前support依赖非法信息. 每query top-k天然只使用当前score行, 但block摘要生成也必须causal. 可共享的统计只能来自合法前缀或固定参数. MoBA类路由中, KV block表示若用block内所有tokens聚合, 一个query不能选择包含未来token的未完成block, 或必须在block内再次causal mask且确保未来内容没参与router score. Prefill块边界要精确定义. Decode中只有已完成历史blocks, 问题较简单. packed documents需要独立合法集合. 一个batch tensor中的相邻token可能属于不同样本, block router若按物理连续分块会跨文档聚合. block边界应与sequence boundary对齐或带mask生成摘要. loss mask不能修复已经进入support选择的跨文档信息.

负载均衡统计可以跨batch聚合用于辅助loss, 但不能反馈进当前token的选择阈值或容量顺序而泄漏未来? 它若只改变训练梯度, 不进入前向logits, 因果输出不受影响;若实时capacity按整批排序queries, 某个token是否被接纳会依赖batch中其他位置. 推理采用不同batch时支持变化, 属于batch依赖, 需要明确接受或消除.

### 5.9. 从训练日志判断哪一层出了问题

主loss下降、oracle gap大且learned recall低, selector尚未学会;增加路由监督或探索. Learned recall高、oracle gap仍大, 预算/结构不足;增大 $k$ 或增加coarse/recurrent分支. 两个gap都小、推理质量下降, 检查训练推理support规则与精度. 路由loss下降、support churn高, 可能score整体拟合但边界margin小;加ranking margin或检查tie. 负载均衡很好、coverage下降, 正则过强;overflow高, capacity不足或数据热点真实存在. heads重合高且并集coverage不足, 出现head塌缩;重合低但coverage仍低, 探索无目标. 短长度正常、长长度下降, 检查固定预算比例、score极值和训练长度. Prefill正常、Decode下降, 检查逐步state、KV追加和kernel规则. 单卡正常、多卡下降, 检查global top-k、通信capacity与分片边界. FP32正常、低精度下降, 检查margin和量化scale.

SFT后长程下降, 看长样本比例与router梯度;RL后成本大降但任务下降, 看成本reward是否主导. 训练后期selector使用率突然收缩, 对照学习率、预算退火和loss权重日程. 日志需要保存配置变化点, 否则曲线难以归因. 最有用的probe batch固定随机种子, 覆盖各记忆操作和长度. 每隔若干步用同一批计算support、margin、oracle gap、head并集和层间变化. 训练数据随机batch反映平均进度, 固定probe揭示真实结构漂移. 两者缺一会误判.

### 5.10. 离散梯度估计的偏差与方差

将支持 $S$ 看成从分布 $p_\theta(S|x)$ 采样, 期望任务损失为

$$
J(\theta)=E_{S\sim p_\theta}[L(S)].
$$

score-function estimator给出

$$
\nabla_\theta J
=E[(L(S)-b)\nabla_\theta\log p_\theta(S|x)],
$$

$b$ 是不依赖当前动作的baseline. 这个估计在条件满足时无偏, 方差可能很大, 因为一次support采样的loss还混入主模型、数据和其他随机性. top-k组合空间巨大, 直接策略梯度通常需要强baseline、多个样本或结构化采样. straight-through estimator用hard前向和soft反向, 方差较低, 梯度有偏. 偏差意味着优化的代理目标不同于真实hard support loss;它仍可能在实践中有效. 有效性取决于hard验证上的coverage、任务质量和稳定性是否改善. 连续松弛的reparameterization梯度方差通常更低. Gumbel-softmax把随机性写成参数无关噪声, 对soft样本可反传;温度降到接近hard时梯度变尖. top-k需要无放回或排序松弛, 计算和内存也会上升. 训练全历史soft分布会失去稀疏成本.

教师监督绕开了对选择动作的策略梯度, 将问题变成有标签排序. 它的偏差来自教师: 教师attention不一定等于任务所需support, 多head聚合会丢信息, 稠密模型可能使用不同表示. 任务loss仍要保留, 让selector与主模型共同修正教师局限. 可以组合估计器. 例如大部分batch用教师ranking与hard sparse前向, 少量batch运行高预算oracle计算coverage;对不确定query增加随机候选;主loss通过已选边训练attention. 各通道分别覆盖排序、探索与表示. 组合复杂度上升, 每个loss都应有独立消融. baseline质量直接影响策略梯度方差. query级baseline可以预测当前输入在平均support下的loss, self-critical baseline用贪心support作参照. 支持选择对整条长序列loss的影响延迟时, 为每个query分配credit更困难. 构造局部证据任务与教师信号通常比纯结果奖励更高效.

梯度估计还受采样相关性影响. 多heads若共享Gumbel噪声, supports相关, 多样性下降;独立噪声提高探索, 并集预算增大. 跨层共享采样可减少计算, 也让同一错误support影响多层. 随机变量的共享方式本身就是结构假设.

### 5.11. 支持边界的扰动分析

令selector score为 $z$, 当前第 $k$ 与第 $k+1$ 名margin为 $m=z_{(k)}-z_{(k+1)}$. 参数更新引起score扰动 $\delta z$. 若 $\|\delta z\|_\infty<m/2$, top-k保持不变. margin小的query容易抖动, margin大时hard mask在许多更新内固定. 固定mask区间内, 主loss对selector score的直接hard梯度为零;只有共享参数、辅助loss或随机探索继续更新router. 这解释hard top-k为何可能僵化:一旦margin拉大, 未选位置没有信号跨过边界. ranking教师若持续给外部正例, 能推动边界变化. 量化与数值误差也可放进同一条件. 若FP8 score误差上界或实测高分位为 $\epsilon_z$, margin $m<2\epsilon_z$ 的queries存在集合翻转风险. 报告margin分布能预测低精度support稳定性. 只看score均方误差会被大量远离边界的位置稀释. block top-k的margin定义在block score上. block score若由max、mean或learned summary得到, 对单个关键token的敏感度不同. mean会被大量无关token稀释, max易受偶然极值干扰, learned summary需要训练覆盖. 选择聚合函数也是支持可学习性的一部分.

margin正则鼓励正例与负例分开, 过大会让router过度自信, 探索消失. 校准和稳定之间存在交换. 对教师不确定的query可使用较小margin或soft target, 确定query用大margin. 统一margin简单, 未必匹配样本难度.

### 5.12. 何时停止增加训练技巧

如果oracle在目标预算下已经失败, 继续改离散梯度、探索或路由loss不会突破支持容量. 应增加 $k$、引入coarse/recurrent summary或调整任务假设. 这是首个停止条件. 如果learned selector接近oracle, 路由缺口很小, 总质量仍低, 问题落在主attention、表示训练或其他网络模块. 再堆router正则只会增加冲突. 第二个停止条件来自 $\Delta_{learn}$ 已经足够小. 如果质量达到目标而训练/推理没有物理加速, 应检查block/page聚集、反向scatter、通信与selector占比. 算法support正确不代表硬件执行稀疏. 此时工作属于布局与kernel, 不靠更多训练loss解决. 如果动态预算、fallback和多种辅助目标只换来很小质量增益, 固定规则窗口加少量global blocks可能更稳. 学习路由的价值来自内容自适应;当任务证据结构规则, 手工mask具有更低训练与验证复杂度.

如果负载均衡与证据覆盖长期冲突, 可以调整数据/设备映射、复制热门blocks或接受不均衡, 而非继续扭曲语义router. 系统约束不一定都要通过模型loss吸收. 把设备拓扑写进目标会降低迁移性. 如果训练需要长期稠密teacher、soft全历史和大预算才能稳定, 总训练成本可能高于节省. 高调用量推理仍可能值得, 研究应报告全生命周期, 不只展示稳定后的sparse step. 原生稀疏强调最终模型在稀疏图上学会工作, 没有要求整个训练从头到尾都用同一成本.

### 5.13. 最小完整实验矩阵

结构轴包含dense、固定window/block、learned hard sparse、soft训练hard推理、teacher训练hard sparse. 预算轴至少有目标 $k$、两倍 $k$ 和oracle. 长度轴覆盖训练内、训练上限和外推长度. 交叉这些配置能定位结构、预算与长度因素. 优化轴包含无辅助loss、distribution、ranking、coverage、探索和负载目标. 不需要盲目穷举所有组合, 先用oracle判断容量, 再针对learned gap选择信号. 每加一项记录它改善的中间指标与任务, 没有可观察作用就删除. 一致性轴比较参考hard mask与推理kernel、Prefill与逐步Decode、FP32与目标dtype、单卡与分布式、无限capacity与真实capacity. 这些对照主要查语义漂移, 不用于证明模型能力. 任一路径support不同都先解释原因. 能力轴包括局部建模、随机键值、多个分散证据、最新值覆盖、计数、多跳、代码符号和agent observation. 系统轴包括前向/反向吞吐、峰值激活、support索引容量、HBM bytes、通信与负载分位数. 两轴并列才能看出收益交换.

报告每个点的support统计: recall、mass recall、margin、churn、head并集、位置分布、overflow与fallback. 任务下降时这些量提供诊断;性能下降时block/page与负载统计给出原因. 只保留最终平均分会丢失原生稀疏最关键的学习过程. 最终结论应落到明确条件: 在什么训练长度、预算、mask粒度、capacity和任务分布上, learned support接近哪个oracle, 付出多少训练附加成本, 推理保持何种一致性. 条件之外的长度与任务属于待验证范围, 不能由一个平均benchmark外推.

### 5.14. 没有信息时探索命中率有明确上限

假设 $N$ 个历史位置中只有一个目标, 在观察query之前各位置等可能, selector没有任何区分信息, 随机选择 $k$ 个位置的命中概率为

$$
P(\text{hit})=\frac{k}{N}.
$$

$N=131072,k=2048$ 时只有 1.5625%. 增加训练步不能突破无信息条件, 模型必须从query与keys学到相关结构. 随机探索只负责偶尔暴露目标, 不能替代可泛化的索引特征. 若有 $m$ 个等价目标, 无放回选择至少命中一个的概率为

$$
P(\text{hit})=1-
\frac{\binom{N-m}{k}}{\binom Nk}.
$$

$m$ 增大或相关证据形成连续block时, 探索容易得多. 因而needle任务中单一随机目标比大量冗余线索更能检验路由;真实文本的语义冗余又可能让小预算有效. 分块探索的命中率由目标所在block数决定. 目标token与无关token共享block时, 命中block即可让主attention在块内找到它, 代价是读取整块. token级困难被转成粗粒度召回与块内精排. block大小越大, 随机命中概率提升, 物理工作也增加. 教师将无信息探索转成有方向监督. 如果teacher给目标较高概率, ranking loss每次都能更新, 不必等随机支持命中. teacher计算贵却显著改善样本效率. 这解释了为什么训练期可接受部分稠密oracle:它购买的是路由学习信号, 不代表部署继续支付.

### 5.15. 支持集也会产生确认偏差

模型只在选中证据上生成输出, 训练根据输出更新selector. 如果错误support仍能靠语言先验猜对答案, loss不会惩罚路由;selector把猜测路径当成成功证据. 数据中答案泄漏、模板和局部相关性会强化这种确认偏差. 反事实数据能打破捷径. 保持问题与局部上下文相同, 改变远程证据使答案变化;或交换两个相似文档的目标值. 模型必须读取证据才能区分. 只增加长文本长度而答案仍可从常识猜出, 不会训练远程support. 证据dropout也可检验依赖. 暂时遮掉selector最常用局部blocks, 观察是否能转向远程证据;遮掉标注证据时答案应下降. 若两者都不影响, 模型可能没有使用上下文. dropout用于诊断或适量训练, 过强会改变任务.

attention可视化本身不是因果证明. 一个位置被选中且权重高, 不代表输出依赖它;替换或删除该value后的logit变化更直接. 对原生稀疏, support是必要入口, 集合内仍可能存在无用边. 评测可结合支持统计与干预.

### 5.16. 一个分阶段训练示例如何核算

假设总训练 1T tokens. 前 100B 使用较宽预算 $4k$ 并在10% batch运行高预算teacher;中间 600B从 $4k$ 退火到 $k$;后 300B固定目标hard $k$, 关闭大部分teacher, 保留1% probe. 最终有90% tokens在逐步收紧或目标稀疏图上训练, 不是末尾短适配. 训练计算不能只按最终 $k$ 报告. 令目标hard step成本为1, 宽预算近似attention部分4倍, teacher batch另有附加成本 $c_T$. 总相对计算由每阶段tokens与实际模块占比加权. 若attention只占全模型一部分, 宽预算不会让整step严格4倍;应以profiler或模块FLOPs计算. 阶段切换设置验收门. 宽预算阶段要求远程任务与teacher coverage达到阈值;退火阶段每降一档等待loss、oracle gap和support churn稳定;目标阶段要求训练与推理kernel对齐, 长度分桶不回退. 未达阈值时延长阶段比按固定日期切换更合理.

这组数字用于展示核算方式, 配方会随模型规模、数据与router初始化变化. 它包含三个原则: 早期提供学习信号, 大部分训练暴露目标结构, 收尾阶段在真实推理支持上充分收敛. 只做短继续训练往往难以重塑深层表示.

### 5.17. 最终边界落在任务的最小充分状态

若任务答案可由固定维统计量递推, 稀疏token检索并非最低成本表示;recurrent或coarse状态更合适. 若答案需要任意历史原文, 必须保留可寻址表示或外部存储. 若只依赖最近窗口, 动态全局router可能没有必要. 原生稀疏的价值集中在「历史很长、每步只需少量内容相关位置、相关位置可由当前prefix预测」这一类问题. 必要位置无法从当前prefix预测时, selector最多依赖先验与探索. 未来随机指定任意历史位置的任务需要保留索引, 查询到来后仍可搜索;这要求历史keys完整存在, 不代表每步都读取全部KV. 若连keys也被不可逆删除, 未来查询无法恢复.

证据数量超过预算时, 多层、多head或摘要状态可以逐步聚合. 聚合过程是否保留任务所需信息决定上限. 训练技巧能帮助模型逼近这个上限, 无法违反容量与因果约束. Oracle replay正是区分可学习缺口与结构上限的方法. 硬件友好性再加一条约束: 可学习support必须聚集到可高效执行的block/page, 或接受gather/scatter成本. 语义最优的散点图可能不是系统最优. 训练目标把执行粒度纳入后, 模型学的是受硬件约束的稀疏图, 质量比较也应在相同物理预算下进行. **训练原生稀疏成立的完整条件是: 任务存在低预算支持, selector有信号和探索找到它, 主模型长期在同一支持语义上适应, 推理系统确实跳过未选工作.** 四项缺一, 「原生」都只剩结构名称.

模型对支持的依赖还要经过干预确认. 在保持其他计算不变时替换候选为随机集合, 质量应明显下降;替换为oracle集合, 质量应上升或至少不降;扩大预算后若完全无变化, 当前任务可能没有使用远程通道. 三个反事实比单看router热力图更能证明支持发挥作用. 同样要检查支持外信息是否从旁路泄漏. Coarse summary若汇聚全历史, fine branch看似只读 $k$ 个token, 模型仍可能通过coarse获得答案. 这不是错误, 但能力应归因于压缩通道与稀疏通道的组合. 消融coarse、window和fine后分别测任务, 才能知道低预算support独立贡献.

外部检索也会改变边界. 如果系统先把相关文档缩到短上下文, 模型内部router面对的 $N$ 已显著降低;内部稀疏与检索召回串联, 总召回率近似受两阶段共同限制. 训练内部selector时使用oracle文档, 上线检索错误会形成分布偏移. 端到端评测需同时包含外部候选与内部support. 当这些条件都明确后, 稀疏预算才有可解释含义: 它表示模型在给定历史表示、辅助分支和外部候选下实际读取的主KV范围, 不代表系统总共接触的信息量. 这种口径能避免把coarse扫描、router全扫或检索预处理藏到「只看了 $k$ 个token」后面. 因此评测必须把主KV读取量、路由扫描量和辅助状态更新分别列出, 三项相加才是完整支持成本.
训练与推理都应使用这套统一口径.
