# 读取选择：完整保存，按 query 取页

长上下文 decode 的麻烦很具体：每生成一个 token，当前 query 都要与历史 key 计算分数，再按 softmax 权重读取 value。上下文增长到数万乃至数十万 token 后，单步矩阵已经接近 matrix-vector 运算，算术强度很低，时间主要耗在把逐层 KV 从 HBM 搬到计算单元。若当前 query 最终只把显著权重放在少数历史位置，先找到这些位置，再读取对应 KV，就有机会绕开大部分数据流量。

「读取选择」保留完整 cache，不提前宣布某段历史永远无用。第 $t$ 步没有被读取的页，第 $t+1$ 步仍可被另一个 query 选中。这一点与 eviction 有根本差别：eviction 同时减少容量与读取，但误删以后无法恢复；读取选择只减少当步流量，设备上仍要容纳完整历史，或把完整历史放进可再次访问的分层存储。它适合重要性随 query 快速变化的任务，也把成本从一次性淘汰判断改成每步索引查询。

## 1. 选择发生在 HBM 读取之前

### 1.2. 先算完整扫描为什么没有意义

设一层有 $P$ 个 KV 页，每页 $S$ 个 token，单个 head 的维度为 $d_h$。若为了选 Top-K 先把全部 key 读入并计算 $q^\top k$，选择阶段已经产生 $PSd_h$ 级别的乘加和完整 key 读取；后面的稀疏 attention 只省了 value 聚合，长上下文 decode 的主要流量并没有消失。选择器需要读取远小于完整 key 的索引，而且索引必须在 KV 写入时增量维护。

页级摘要满足这个条件。每个物理页只保存少量与页内 key 有关的统计量，decode 时用当前 query 扫描摘要，得到候选页编号，再让 attention kernel 直接按页表读取候选 KV。这里有两次读取：第一次读小索引，第二次读少数完整页。若实现把候选页 gather 到另一块连续张量，额外拷贝会吞掉节省；较合适的路径是让分页 attention 直接消费候选页编号。

**读取稀疏不改变 cache 容量。**

完整 KV 的容量仍为 $2LnH_{kv}d_hb$，其中 $L$ 是层数，$n$ 是上下文长度，$H_{kv}$ 是 KV head 数，$b$ 是每个元素的字节数。读取选择额外增加索引，并把每步参与 attention 的 token 数从 $n$ 限制到预算 $B$ 左右。于是容量继续按 $n$ 增长，单步读取可以接近按 $B$ 增长。

这条边界影响部署判断。显存足以放下完整 cache、decode 又明显受 HBM 带宽限制时，读取选择很合适；显存本身已经装不下目标并发，单纯少读不能腾出新请求的位置，还要结合量化、GQA、offload 或 eviction。报告「读取了 1/8 KV」时，应同时给出完整驻留容量与索引容量，避免把带宽收益写成显存收益。

### 1.1. 页级选择为什么比 token 级更容易落地

**连续地址与候选粒度。**

token 级 Top-K 可以少算更多无关位置，返回的地址却可能散布在整个 cache。GPU 会按 cache line、内存事务和线程块读取数据，离散 token 容易产生低合并度访问。页级选择把 $S$ 个相邻 token 当作执行单元，选中一个关键 token 时连同同页其余 token 一起读入，逻辑稀疏率略差，地址和 kernel 形状却规则得多。

page size 同时控制三项成本。$S$ 增大时，页数与索引扫描量下降，但每个候选携带更多无关 token，页摘要也会变松；$S$ 减小时，候选更精确，索引元数据、Top-K 项数和调度开销上升。不存在脱离模型、序列长度和 GPU 的统一最优值，必须把召回率与墙钟延迟画在同一组 $S$ 和预算上。

**分页 KV 已经提供了物理接口。**

推理引擎通常用页表管理不同长度的请求，逻辑连续的 token 不要求在物理地址上连续。读取选择可以复用页编号、末页有效长度和引用计数，无需另建一套 token 搬移系统。新 token 追加到当前尾页，页满后分配新页；共享前缀页可以被多条请求共同引用，但候选列表仍属于各自的 query、layer 和 head。

批处理中每条请求拥有不同页数和不同 Top-K 地址，attention 输入因此是 ragged page table。内核要处理请求级指针、每条请求的有效候选数与末页长度。为了把 batch 填成整齐矩阵而统一读取候选并集，会把其他请求不需要的页重新搬回 HBM；更合理的做法是保留 ragged 索引，并按实际候选工作量调度线程块。

## 2. Quest 给出的第一条完整路径

### 2.2. Min/max 摘要怎样筛页

[Quest](./3.1.1-Quest页级选择.md)为每页、每个 key 维度保存最小值与最大值。当前 query 的某一维为正时，该维点积的最大可能贡献来自最大 key；query 为负时来自最小 key。逐维取更大的乘积并求和，可得到页内任意真实 key 点积的上界。摘要大小约为完整 key 的 $2/S$，与完整 K+V 相比约为 $1/S$。

这个上界不会低估页内最大点积，却可能明显高估。各维极值可能来自不同 token，把它们拼在一起得到的角点并非页内真实 key。Top-K 页按上界排序时，松上界会占据预算，所以「上界成立」不等于有限 K 下必然召回真实 Top-K token。页越大、页内 key 分布越分散，松弛通常越明显；提高页预算可以换回召回率，也会增加 KV 流量。

**索引、Top-K 与稀疏 attention 连成一条链。**

Quest 的写入路径在追加 key 时逐维更新当前页的 min/max；封口页的摘要之后保持不变。读取路径先扫描全部页摘要，计算当前 query 对每页的上界，再取 Top-K 页，末尾只在这些页中执行原始点积、softmax 和 value 聚合。近似发生在候选筛选，候选页内部仍做精确 attention。

官方实现把 kernel 正确性测试、批量 decode 基准和端到端路径一并公开，并基于 FlashInfer 与分页 KV 完成执行。公开 kernel 覆盖 MHA，尚未实现 GQA；公式可以按 KV head 分组扩展，组内 query 如何合并候选仍需另外设计。详细推导、手算、流量模型与失败测试放在 [Quest 页级选择](./3.1.1-Quest页级选择.md)。

### 2.1. 评测必须同时看召回和流量

**候选召回比平均注意力误差更直接。**

读取选择最先影响的是「需要的页有没有进入候选」。可用稠密 attention 的真实 Top-R token 作为参照，测这些 token 所在页被候选覆盖的比例，并按层、head、生成阶段和依赖距离拆分。候选页召回很高而最终任务下降，问题可能来自预算内 softmax 重新归一化；候选召回已经低，继续调 attention kernel 没有用。

平均困惑度偏向局部预测，容易掩盖偶发的远距漏选。长程评测应包含延后很久才出现的问题、多个相似数字、事实更新和多证据聚合。前两层或某些 head 若天然不稀疏，可以直接回退稠密读取；统一预算看起来整齐，却会在最难稀疏的层上浪费质量。

**系统收益要从完整流水线测量。**

端到端时间至少拆成摘要更新、摘要扫描、Top-K、候选 attention、QKV 投影、FFN 与调度。上下文较短时，Top-K 和 kernel 启动可能比少读的 KV 更贵；上下文增长后，固定预算才逐渐摊薄选择开销。只报 attention 子模块加速会高估用户看到的 token 延迟。

流量核对可以由硬件计数器与公式互证：摘要实际读了多少字节，候选页是否被重复 gather，未选页有没有被 kernel 预取，批处理填充浪费多少。若逻辑预算下降但 HBM 字节几乎不变，说明稀疏停留在索引层，没有进入真实数据路径。**读取选择成立的标志很直接：完整 KV 仍可恢复，而当前 step 未选中的页没有进入 attention 的 HBM 读取。**

## 3. 页级上界的几何意义

一页 key 在 $d_h$ 维空间形成点集 $K_P$。逐维最小值与最大值构成包含该点集的轴对齐包围盒

$$
\mathcal B_P=[l_1,u_1]\times\cdots\times[l_{d_h},u_{d_h}].
$$

给定 query $q$，Quest 使用包围盒上使线性函数 $q^\top x$ 最大的角点：

$$
U(q,P)=\max_{x\in\mathcal B_P}q^\top x
=\sum_r\max(q_rl_r,q_ru_r).
$$

因为 $K_P\subseteq\mathcal B_P$，页内真实最大点积一定不超过 $U(q,P)$。这个上界的计算只需读取每页 $2d_h$ 个统计量，不需要主 KV。它的松紧取决于不同维度极值是否来自相近 token：若所有有利坐标恰好由同一个 key 提供，上界接近真实最大值；若每一维极值分散在不同 token，上界对应一个并不存在的角点，会把该页排名抬高。

上界偏高只会多选页，通常不会把真实高分页数压低。但 Top-K 仍可能漏页：许多宽松上界占据名额时，一个真实高分、包围盒较紧的页可能排在第 $K$ 之后。扩大候选数、缩小页或使用更紧摘要能缓解这个问题。缩小页会增加摘要条目和 top-k 长度，因而存在质量与索引成本的交叉点。

### 3.2. 旋转坐标会改变包围盒

轴对齐包围盒不具备旋转不变性。同一组 key 乘以正交矩阵后，真实点积若 query 同步旋转不会改变，逐维 min/max 上界却可能明显变松或变紧。可学习低维投影或分组旋转有机会让页内点云更适合包围盒，但它们增加训练与推理成本，也可能使索引随模型参数变化。

将维度分组并为每组保存更丰富的凸包近似，可以收紧上界，同时增加摘要字节。索引设计可以写成一个率失真问题：每页允许多少摘要字节，能把多余候选页降到多少。优化目标是在覆盖关键页的约束下减少主 KV 读取；单纯缩小上界数值误差，并不保证候选排序更好。

### 3.1. 从页候选到 token 概率质量

页排名依据最大可能 logit，attention 输出却由整页所有 token 的 softmax 质量决定。某页包含一个高分 token 时，最大值上界很合适；若一页有许多中等分 token，它们的概率质量之和可能超过一个孤立高分 token，却因页最大值不突出而排名靠后。可以定义页的真实 log-sum-exp：

$$
z_P=\log\sum_{j\in P}e^{s_j}.
$$

页概率质量与 $e^{z_P}$ 成正比。只用最大分数 $m_P$ 时有

$$
m_P\le z_P\le m_P+\log |P|.
$$

相同页大小下，最大分数可以作为粗排序；页内分数平坦程度不同，误差可接近 $\log|P|$。若目标是覆盖 softmax mass，可以结合上界和页内分布统计估计 $z_P$，但统计必须能随新 key 低成本更新。

候选页选定后，页内全部 token 参与精确 softmax。设候选页并集为 $C$，稠密概率在集合外的质量为 $\tau$，截断分布与稠密分布的总变差距离为 $\tau$。因此评测页索引时，既要记录真实 top token 所在页的召回，也要记录 $1-\tau$。前者关心尖峰，后者关心整体概率。

## 4. Query 组怎样共享候选

GQA 的多个 query head 共享一组 K/V。若每个 query head 独立选 $K$ 页，物理读取集合是各头候选的并集：

$$
C_{group}=\bigcup_{h=1}^{g}C_h.
$$

最坏情况下并集含 $gK$ 页，GQA 的 KV 共享优势会被候选差异削弱。强制整个组共享同一候选，可以只读 $K$ 页，却可能牺牲专门 head。折中方法给组共享 $K_s$ 页，再为每头保留 $K_h$ 个独立页；物理集合上限为 $K_s+gK_h$。

共享候选可依据各头页上界的最大值、平均值或加权 log-sum-exp。取最大值保护任一头的强响应，容易被单个异常上界占据；平均值偏向多头共同需要的页，可能漏掉专门关系。评测应报告每头概率质量和组并集页数，不能只给平均召回。

Prefill 中相邻 query 也可以共享页集合。长度为 $B_q$ 的 query tile 若采用并集候选，可形成规则块矩阵；代价随 tile 内需求差异增加。局部语义连续时共享有效，跨越文档边界或问题切换时并集迅速膨胀。文档边界与 causal 边界应参与 query 分组。

### 4.1. 索引陈旧与更新频率

对固定模型推理，已写入 key 不再变化，页 min/max 可以增量维护；当前未满页每加入一个 token 更新一次，封口后保持不变。训练时投影矩阵每步更新，旧 key 摘要对应旧参数，无法直接复用。若在前向中由当前 key 构建摘要，索引成本进入每个 batch；若跨优化 step 缓存，则引入参数陈旧误差。

跨层共享索引也有类似问题。第 $\ell$ 层构造的页摘要用于第 $\ell+r$ 层时，query 和 key 表示已经变化。可测量旧索引候选对新层教师概率质量的覆盖，并据此决定共享跨度。固定每四层重建一次只是结构超参数，只有覆盖曲线才能说明这个间隔是否合适。

Decode step 间复用候选依赖 query 连续性。相邻生成 token 的 query 往往相关，却会在主题切换、代码括号闭合或工具结果返回后突变。可设置变化检测量，例如归一化 query 的余弦距离；超过阈值立即重索引，平稳阶段沿用旧候选。检测本身只读当前 query，成本小，但阈值需同时约束漏选与重建频率。

## 5. 读取选择的可恢复性实验

完整 KV 保留意味着理论上可恢复，实际实现还要证明回退路径可用。对同一 decode 状态，先运行稀疏读取，再将候选扩到全部页并复算输出。若 full 回退恢复任务答案，误差来自候选；若没有恢复，问题可能在更早层的稀疏传播或模型本身。

还可以做延迟恢复：连续若干步限制候选，第 $t$ 步恢复 full，观察 logits 差异是否立即消失。当前层读取误差会经残差写进后续 token 表示，即使 KV 从未删除，已经生成的 token 和状态也不会自动重算。读取选择在存储意义上可逆，在自回归轨迹上仍可能产生不可逆分叉。这正是需要逐步质量曲线而非单步输出误差的原因。

### 5.1. 读取预算的自适应停止

固定 Top-K 页让 kernel shape 稳定，却会给容易 query 分配过多页，给困难 query 分配不足。若页上界按 $U_{(1)}\ge U_{(2)}\ge\cdots$ 排序，已经精算候选页后可得到当前 softmax 分母 $Z_C$。对未读页，利用上界可构造剩余概率质量的保守估计：

$$
Z_{tail}\le\sum_{r>K}|P_r|e^{U_{(r)}},
\qquad
\tau\le\frac{Z_{tail}}{Z_C+Z_{tail}}.
$$

当右侧低于容许误差即可停止扩展；上界宽松时会继续读取更多页，但不会用乐观估计提前结束。这个规则把预算从固定页数改为概率质量证书，代价是需要维护剩余页上界的聚合。实际实现可以分轮增加候选，每轮复用已经得到的 online-softmax 状态。

分轮读取增加 kernel 启动和同步。批处理中，有些 query 一轮结束，另一些继续扩展，会产生 ragged 控制流。较实用的折中是提供少数离散预算档位，例如 8、16、32 页，由上界间隔选择档位，再按档位分组执行。这样保留部分自适应能力，也让每组拥有规则 shape。

停止规则还要给局部窗口预留固定页。局部页若与检索页重合，应先去重再计算总预算；否则靠近当前位置的 query 会无意中获得较少远距候选。全局 sink 页也采用同样处理。最终块表由固定集合与自适应集合求并集，质量统计按两部分分别记录，才能看出远距召回究竟来自索引还是固定兜底。
