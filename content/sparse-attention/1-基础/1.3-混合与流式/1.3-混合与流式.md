# 混合与流式: 注意力、窗口和递归状态

长序列模型混合的是几种完全不同的历史状态. 全 attention 把过去保存成逐 token 的 K/V, 需要精确回看时直接读取; 滑动窗口只保留最近一段 K/V, 远处内容依靠跨层传递; 线性 attention 或 SSM 把历史更新进固定大小的矩阵或向量状态, Decode 成本不再随历史长度增长, 原始 token 级细节也不再单独存在. 三种状态放进同一模型以后, 训练图、cache 管理和服务调度都要跟着分层.

可核对的实例已经从单一 Hybrid SWA 扩展到多条路线. [Gemma 2](https://arxiv.org/abs/2408.00118)交替使用 local 与 global attention. [Jamba](https://arxiv.org/abs/2403.19887)沿深度交错 Transformer 与 Mamba 层. [Hymba](https://arxiv.org/abs/2411.13676)在同一层并行放入 attention heads 和 SSM heads. [Olmo Hybrid](https://arxiv.org/abs/2604.03444)把 Olmo 3 7B 的大部分 SWA 层换成 Gated DeltaNet, 官方[模型卡](https://huggingface.co/allenai/Olmo-Hybrid-7B)给出的排布是三层 Gated DeltaNet 后接一层多头 attention. [StreamingLLM](https://arxiv.org/abs/2309.17453)则从时间轴处理状态淘汰, 永久保留少量 attention sinks 与最近窗口.

这些设计共同回答一个问题: **模型把什么状态留到下一步, 又愿意为哪类历史访问支付线性或平方成本.** 层级交替、head 级并行和按 token 路由会得到不同答案. 只报「75% 线性层」或「窗口 4096」还不够, 因为剩余 attention 层可能决定全部 KV 上界, 一个动态路由分支也可能迫使服务端保留两套状态.

## 1. 三种序列混合器对应三种历史状态

### 1.1. 全 attention 保存逐 token 的 K/V

设第 $t$ 步之前已有 $t$ 个 token, 每层有 $h_{kv}$ 个 KV heads, 单个 head 维度为 $d_h$. 全 attention 的 cache 元素数约为:

$$
M_{\mathrm{full}}(t)=2t h_{kv}d_h. \tag{1}
$$

系数 $2$ 对应 K 与 V. Decode 新 query 需要读取全部历史 K/V, 单层点积与 Value 混合成本随 $t$ 线性增长. Prefill 同时处理 $n$ 个 query, 因果边数为 $n(n+1)/2$, attention 主体呈平方增长. FlashAttention 可以减少中间矩阵写回, 但合法的 query-key 配对仍会计算.

全 attention 保存的是「可重新寻址的历史」. query 变化时, 模型可以对同一组历史 K/V 重新打分. 这种高分辨率访问很适合精确复制、任意位置检索和内容相关聚合, 相应代价是 cache 随序列增长. GQA 通过减少 $h_{kv}$ 降低式 (1), 没有改变对全部历史位置的读取范围.

把式 (1)换成实际字节更直观. 假设 $h_{kv}=8$, $d_h=128$, KV 使用 BF16, 每个元素 $2$ bytes. 单层每个 token 占 $2\times8\times128\times2=4096$ bytes. 长度 $32768$ 时, 单层约占 $128$ MiB; $32$ 层全部保留完整 KV 时约占 $4$ GiB, 还没有计入页表、对齐和分配器碎片. GQA 把 KV heads 从 $32$ 降到 $8$ 时, cache 缩为四分之一, attention query heads 仍可保持 $32$.

Decode 的字节读取也按同一规模增长. 一个新 query 若需要读取这一层全部 BF16 K/V, 长度 $32768$ 时理论数据量约为 $128$ MiB. 实际 kernel 会受 cache hierarchy、批处理与量化影响, 但历史越长、每步读取越大的趋势不变. attention 的算术强度在单 token Decode 较低, 所以减少 KV heads、窗口或完整 attention 层数经常先表现为带宽收益.

### 1.2. 滑动窗口只保存最近 K/V

因果窗口宽度为 $w$ 且包含当前位置时, 第 $i$ 个 query 的可见集合为:

$$
N_{\mathrm{win}}(i)=\{j:\max(0,i-w+1)\le j\le i\}. \tag{2}
$$

cache 达到稳态后的元素数为 $2wh_{kv}d_h$, Decode 每步读取至多 $w$ 个历史位置. Prefill 边数在 $n\ge w$ 时为:

$$
E_{\mathrm{win}}(n,w)=nw-\frac{w(w-1)}2. \tag{3}
$$

窗口外 K/V 被淘汰后, 当前层无法重新读取原始表示. 早期信息仍可能被后续 token 的 hidden state 携带, 但它已经经过投影、softmax 混合和非线性变换. 窗口因此提供固定 cache 上界, 同时把远距精确访问改成跨层状态传递问题.

Mistral 7B 的 rolling buffer 展示了这一生命周期: 物理槽位循环复用, 逻辑位置继续向前增长. 环形地址不能直接替代 RoPE 位置. 当写指针覆盖旧槽时, kernel 仍需按逻辑顺序解释窗口, 否则物理相邻的两个槽可能来自序列中相隔近一个窗口的位置.

加入 $s$ 个 attention sinks 后, 稳态 cache 变成约 $2(w+s)h_{kv}d_h$. sinks 常驻, 最近窗口继续滚动. 在序列刚开始时, sink 也位于最近窗口内, 集合并集要去重; 达到稳态后, 常驻槽和环形槽才完全分开. StreamingLLM 的配方保留开头位置是为了维持模型已有的 attention 分布, 这些旧 K/V 在标准 Transformer 中不会随着后文重新写入.

窗口对训练和 Decode 的影响也不完全相同. 训练时所有 query 同时存在, 带状 attention 能形成较大的规则 tile; Decode 每层只有一个新 query, 主要工作变成读取最近 $w$ 个 K/V. 训练吞吐受 tile 利用率与反向传播影响, Decode 受 HBM 带宽、页表和 kernel launch 影响. 同一个 $w$ 在两个阶段得到的加速比例通常不同.

**线性递归把历史压进固定状态。**

最简归一化线性 attention 令特征映射为 $\phi(\cdot)$, 保存矩阵状态 $S_t$ 与归一化状态 $z_t$:

$$
S_t=S_{t-1}+\phi(k_t)v_t^\top,\qquad
z_t=z_{t-1}+\phi(k_t). \tag{4}
$$

query 输出为:

$$
o_t=\frac{\phi(q_t)^\top S_t}
{\phi(q_t)^\top z_t+\epsilon}. \tag{5}
$$

若 $\phi(k_t)\in\mathbb{R}^{d_k}$, $v_t\in\mathbb{R}^{d_v}$, 则 $S_t\in\mathbb{R}^{d_k\times d_v}$, 状态大小与序列长度无关. Decode 每步执行一次状态更新和矩阵向量乘, 不读取全部历史 token. 历史已经叠加进 $S_t$, query 无法像 softmax attention 那样重新选择某个原始 K/V.

训练阶段还有另一条执行路径. 式 (4) 可以逐 token recurrent scan, 也可以借助结合律做 chunk 或并行 scan. [Flash Linear Attention](https://github.com/fla-org/flash-linear-attention)中的 DeltaNet 层同时提供 `chunk`、`fused_recurrent` 与 `fused_chunk` 等 kernel 入口, 训练长序列和单 token Decode 使用的最佳路径并不相同. **固定状态降低的是时间轴长度, 训练并行度仍取决于递推能否转成高效 scan.**

状态大小也可以直接算. 取 $d_k=d_v=128$, 一个 head 的 $S_t$ 有 $16384$ 个元素, BF16 下为 $32$ KiB; 再加 $z_t$ 只多 $256$ bytes. 八个 heads 约占 $258$ KiB, 与序列长度无关. 相比之下, 八个 full KV heads 在单层长度 $32768$ 时约占 $128$ MiB. recurrent state 的常数并不小, 但长序列下远低于逐 token KV.

固定 state 也带来信息碰撞. 两个 key 特征若相同或高度相关, 它们的外积会写入相同方向. 式 (4)只保存加权总和, 后来的 query 很难区分是哪一个 token 贡献了这部分 Value. 增大 $d_k$ 可以提供更多方向, 仍没有建立逐 token 地址. 这类模型在持续统计、局部模式和状态更新上很自然, 对精确复制的表现则依赖训练、state update 和保留的 attention 通道.

**用状态转移算子统一三种记忆。**

三类混合器都可以写成「读旧状态、处理新 token、产生新状态」. 令第 $t$ 步输入为 $x_t$, 状态为 $c_t$, 输出为 $y_t$, 抽象形式是

$$
c_t=U(c_{t-1},x_t),\qquad y_t=R(c_t,x_t).
$$

full attention 的 $c_t$ 是不断增长的 K/V 序列, $U$ 执行 append, $R$ 用 query 对全部历史重新加权;窗口 attention 的 $c_t$ 是有限队列, $U$ 在 append 后淘汰最旧普通位置;递归混合器的 $c_t$ 是固定维矩阵或向量, $U$ 原地做代数更新. 统一写法没有抹平差异, 它把差异集中到三个可计算的问题: $c_t$ 的维度是否随 $t$ 增长, $U$ 是否可逆, $R$ 是否还能访问单个历史项.

full KV 的 append 在保留页面时可逆: 从尾部删除新 token 就回到 $c_{t-1}$. 窗口队列一旦覆盖最旧槽, 只靠当前队列无法恢复覆盖前状态;若把被淘汰项另存, 才能逆转. 递归更新能否逆转取决于 $U$. 加法更新 $S_t=S_{t-1}+u_t$ 在保存 $u_t$ 时可逆, 带衰减的 $S_t=\gamma_tS_{t-1}+u_t$ 需要保存 $\gamma_t$ 与 $u_t$, 且 $\gamma_t=0$ 时信息已经不可逆地擦除. delta rule 中 $u_t$ 又依赖旧状态读数, 回滚所需记录更多.

这个视角能直接解释 speculative decoding. 草稿 token 连续执行 $U$ 得到 $c_{t+m}$, 验证只接受前 $a<m$ 个. append 状态可以截到 $t+a$;不可逆递归状态需要从 $c_t$ 重放 $a$ 步, 或为每步保存足以逆转 $U$ 的日志. checkpoint 间距决定状态副本与回放计算的交换, 与 attention 的页截断属于不同操作.

状态维度也决定信息容量的形式. full attention 的状态维度约为 $O(td)$, 为每个位置保留单独向量;窗口是 $O(wd)$, 只保存有限时间范围;矩阵 recurrence 是 $O(d_kd_v)$, 将任意长历史映射到固定维空间. 若输入空间连续且序列无界, 固定维有限精度状态不可能无损保存任意历史. 它能保留哪些信息, 由更新算子、训练分布和状态精度共同决定.

**固定矩阵状态的秩限制。**

无衰减外积更新可展开为

$$
S_t=\sum_{i=1}^{t}\phi(k_i)v_i^\top.
$$

每一项秩至多为 1, 因而

$$
\operatorname{rank}(S_t)\le\min(t,d_k,d_v).
$$

当 $t$ 超过 $\min(d_k,d_v)$ 后, 新关联继续写入相同有限子空间. 秩达到上限不等于状态立即失效, 因为许多任务只需要低维充分统计量;它说明逐 token 独立地址不会随着序列继续增加. full KV 的位置数却始终增长, query 可以对每个位置给不同权重.

考虑 $d_k=d_v=2$. 最多只有两个线性独立的 key 方向. 第三个 key 必可写成 $k_3=ak_1+bk_2$, 它的写入会同时改变由 $k_1$ 和 $k_2$ query 读出的结果, 除非 value 与已有状态恰好抵消. key 投影和非线性特征映射可以让常见输入在有限空间中较好分离, 不能突破维度上限. 增大 state dimension 提高容量, 每步矩阵更新和读取成本也随之增加.

delta rule 不再是简单外积总和, 仍在同一个 $d_v\times d_k$ 矩阵中更新. 它通过误差校正减少相同 key 方向的无条件叠加, 更像在线拟合从 key 到 value 的线性映射. 对归一化 key 且 $\beta_t=1$, 沿 $k_t$ 方向的新预测被改到 $v_t$;与 $k_t$ 不正交的其他 key 查询也会受到变化. 所以「定向覆盖」的方向由 key 几何决定, 并非独立哈希槽.

若 keys 两两正交且数量不超过 $d_k$, delta update 可以分别维护这些方向. keys 高度相关时, 更新一个关联会干扰另一个. 训练可以学习拉开需要独立保存的 key, 也会受到输入分布、归一化和有限维度制约. 远距关联任务应控制 key 相似度, 才能看出模型依靠真正定址还是数据中的表面提示.

门控衰减又给容量加上时间权重. 若更新写成

$$
S_t=\gamma_tS_{t-1}+U_t,
$$

展开后得到

$$
S_t=\left(\prod_{j=1}^{t}\gamma_j\right)S_0+
\sum_{i=1}^{t}\left(\prod_{j=i+1}^{t}\gamma_j\right)U_i.
$$

第 $i$ 次写入的保留系数是之后所有 gate 的乘积. gate 数据相关时, 模型可以在边界处快速清空, 在稳定区间接近保留;同一个小于 1 的常数长期连乘则形成指数遗忘. 式 (9)同时描述前向记忆与沿状态通路的梯度衰减, 是判断长程稳定性的核心量.

**窗口传播与递归传播的路径长度。**

窗口层虽然看不到 $w$ 以外的原始 K/V, 多层堆叠后信息可以逐步向前传播. 若每层窗口宽度为 $w$ 且每个位置能把窗口内信息写入自己的 hidden state, 经过 $L$ 层后理论感受野约为 $1+L(w-1)$. 这是可达范围上界;远处信息需要经过多次压缩和非线性变换, 与一层 full attention 直接读取原位置不同.

层级 hybrid 中插入 full attention 会重置路径长度. 假设每三层 recurrent 或 window 后有一层 full attention, full 层可以直接聚合此前所有仍保存的 token 状态, 后续局部层再加工. 若 full 层使用完整 KV, 任意历史到当前 token 的最短路径可以很短;若 full 层也改为窗口, 全模型只剩有限速度的局部传播与递归摘要.

递归状态每一步都从 $S_{t-1}$ 传到 $S_t$, 早期信息到第 $t$ 步经历 $t-i$ 次转移. 从图距离看路径很长, 每次状态却是固定成本;从数值看, 转移 Jacobian 的谱决定信息与梯度能否保留. full attention 的历史 value 到当前输出可通过一次加权连接到达, 代价是保存和读取逐 token 状态. 混合架构正是在「短路径高分辨率」和「固定状态长链」之间分配层与通道.

对状态转移 $S_t=F_t(S_{t-1})$, 小扰动满足

$$
\delta S_t\approx J_t\delta S_{t-1},
$$

其中 $J_t=\partial F_t/\partial S_{t-1}$. 从位置 $i$ 传播到 $t$ 的扰动约为 $J_tJ_{t-1}\cdots J_{i+1}\delta S_i$. 若乘积范数持续小于 1, 远程信息衰减;持续大于 1, 数值误差与梯度可能放大;接近 1 的方向适合长期保留, 但也更难快速擦除. 数据相关 gate 和 delta 更新让不同方向拥有不同转移行为.

固定窗口没有这类同一状态上的长连乘, 却有跨 token、跨层的传播链. 每一跳都会经过 attention、残差和 MLP. 因而「窗口能靠层数覆盖全序列」只说明图上可达, 没有保证原信息保持精确. 随机字符串复制、远端键值绑定和累计状态三类任务分别测试路径分辨率、关联覆盖与递推稳定性, 不应由单一困惑度代替.

## 2. 混合可以发生在层、head 和时间三条轴上

### 2.1. 层级混合便于分开管理状态

层级混合为每层指定一种模式 $m_\ell\in\{F,W,R\}$, 分别表示 full attention、window attention 和 recurrent mixer. 模型总状态是各层状态之和:

$$
M(t)=\sum_{\ell:m_\ell=F}2t h_{kv,\ell}d_{h,\ell}
+\sum_{\ell:m_\ell=W}2w_\ell h_{kv,\ell}d_{h,\ell}
+\sum_{\ell:m_\ell=R}|S_\ell|. \tag{6}
$$

Gemma 2 的 local/global 交替属于 $W/F$ 层表. Olmo Hybrid 的三层 Gated DeltaNet 接一层 attention 属于 $R/R/R/F$ 层表. Jamba 则在 Transformer 与 Mamba 层之间交错. 这类排布让一整层共享同一种 kernel 与状态布局, 服务端也容易按层创建完整 KV、窗口 KV 或递归 state.

式 (6)还揭示一个常被平均比例掩盖的事实. 只要存在 full attention 层, 总 cache 仍含随 $t$ 线性增长的部分. 把 $75\%$ 层改成 recurrent 后, 增长项的系数降到原来的约四分之一, 剩余 attention 层继续提供 token 级回看, 整模型 cache 依旧随历史增长.

取 $32$ 层的 $R/R/R/F$ 排布, 假设各层 hidden 与 head 配置相同. 八个 full attention 层保存完整 KV, 二十四个 recurrent 层保存固定矩阵. 忽略 recurrent 常数项后, 长序列 cache 约为 $32$ 层全 attention 的 $25\%$. 若保留的 attention 层使用窗口 $w$, 增长项也会消失, 状态上界变成八层窗口 KV 加二十四层矩阵 state. 两种层表只差一个 `full` 与 `window` 配置, 长度渐近行为完全不同.

层的位置也会改变信息路径. attention 层靠前时, 它能读取较原始的 token 表示, 后面的 recurrent 层继续压缩和更新; attention 层靠后时, query 看到的是多层 recurrence 已经加工过的历史 K/V. 均匀插入可以限制任意两个 attention 层之间的最大 recurrent 深度. 把八个 attention 层全部放在末尾, cache 大小相同, 训练动力学与可用信息却不同.

### 2.2. Head 级混合在同一层并行处理输入

Hymba 的「hybrid-head」把 attention heads 与 SSM heads 放在同一层, 两组 heads 同时读取相同输入, 再融合输出. 设 attention 分支为 $A(X)$, recurrent 分支为 $R(X)$, 一种抽象写法是:

$$
Y=W_o[A(X)\Vert R(X)], \tag{7}
$$

其中 $\Vert$ 表示沿通道拼接. 每层都能同时获得高分辨率检索与固定状态摘要, 不用等待下一种层出现. 代价是两类 kernel 都要执行, 状态也要同时保存. attention heads 的数量减少会缩小 KV 系数, recurrent heads 没有逐 token cache.

head 级混合对 GQA 和 cache 布局提出额外要求. 若 attention heads 共享少量 KV heads, recurrent heads 使用自己的矩阵状态, 两类 state 可以分区存放. 若为了实现方便仍给所有 heads 分配同长 KV, 纸面上的 cache 优势不会出现. 多卡按 head 切分时也要均匀分配 attention 与 recurrent heads, 否则持有 attention heads 的 rank 会承担更大的 cache 与带宽.

并行分支的融合方式也影响参数与数值范围. 直接拼接后用 $W_o$ 投影, 两类输出各占固定通道; 相加要求维度一致, 还要控制分支尺度; 带 gate 的融合可以按 token 调整比例. Hymba 的核心选择是 attention 与 SSM heads 在同一层并行处理相同输入, 再通过统一输出路径合并. 这一结构让每层都具备两类记忆, 相应 kernel 调度比单一 head 类型更复杂.

cross-layer KV sharing 可以继续压缩 attention 状态. 若相邻若干层复用同一份 K/V 投影, cache 不再按 attention 层数线性复制, 各层 query 仍可产生不同权重. 代价是这些层失去独立 K/V 表示, cache 所有权也从单层提升到层组. 回收、量化和 prefix 复用都要按共享组管理, 其中一层仍需历史时整组 K/V 不能释放.

**时间级路由会把未来需求带回当前状态。**

更激进的设计让每个 token 或 chunk 决定走 full、window 或 recurrent 分支. 路由器输出 $r_t$, 计算可写成:

$$
y_t=f_{r_t}(x_t),\qquad r_t\in\{F,W,R\}. \tag{8}
$$

式 (8)要减少计算, 被选中之外的分支需要真正跳过. 三个分支都执行完再按权重融合时, 路由器只改变输出比例, 计算成本等于各分支之和. hard routing 能省算, 也会让一个 batch 内不同 token 进入不同 kernel, 产生 gather、负载不均和小矩阵问题.

状态生命周期比当前分支更棘手. 位置 $t$ 选择 recurrent 分支时, 未来位置 $t+k$ 仍可能选择 full attention 并希望读取位置 $t$ 的 K/V. 如果系统在 $t$ 当下没有生成或保存该 K/V, 未来路由已经失去所需历史. 时间级路由通常需要持续维护各候选分支的状态, 或把未来路线限制成可预知的单向切换. **路由省下当前算子之前, 未执行分支的历史状态也要有明确归属.**

chunk 级路由比逐 token 路由更容易执行. 一个长度为 $b$ 的 chunk 共享模式, 可以形成足够大的矩阵乘法或 scan, 邻接和 state transition 也能批量准备. 逐 token 路由拥有更细选择粒度, 同一 warp 内的分支分歧却会降低利用率. chunk 越大, 调度更规则, 路由对局部变化的反应越慢.

路由决策还受因果可用信息限制. 位置 $t$ 的 router 只能根据当前与过去 hidden state 选择, 无法知道很久以后会不会有人精确查询当前 token. 因此「当前内容看起来不重要」不足以授权删除 K/V. 一种安全设计让 full KV 始终生成但低频读取, 省带宽却不省容量; 另一种设计只允许从 full 状态单向切换到 recurrent 状态, 切换后明确放弃后续精确回看. 状态承诺必须早于回收动作.

**串联与并联不是同一种函数。**

层级混合把不同算子串联. 两层分别为 $A$ 与 $R$, 忽略残差时得到 $R(A(X))$ 或 $A(R(X))$;head 级混合则近似并联, 得到 $W_o[A(X)\Vert R(X)]$. 串联让第二个算子读取第一个算子已经改写的表示, 并联让两者读取同一输入后再融合. 即使参数量和各算子调用次数相同, 两种计算图也没有一般性的等价关系.

若 $A$ 负责从远处取回一个 value, $R$ 放在其后可以把取回结果写入固定状态, 供后续 token 持续使用. 顺序反过来时, $R$ 先压缩当前历史, $A$ 再从保存的 token 表示中检索. 前者适合「偶尔读取、持续维护」, 后者让 attention query 建立在递归加工后的表示上. 交替排布的位置因此决定远程信息何时进入状态, 不能只用 attention 层比例描述.

并联结构允许当前 token 同时得到 $a_t$ 与 $r_t$, 融合层可以保留两者的不同方向. 若融合仅为标量加权, $y_t=\alpha_ta_t+(1-\alpha_t)r_t$, 两个分支被压到同一通道空间, 相反方向会互相抵消. 拼接后线性投影能按通道学习不同组合, 参数与计算也更多. 若输出投影秩不足, 分支虽在计算上独立, 融合后仍可能丢失一部分信息.

残差连接进一步改变函数. Pre-Norm block 可写成

$$
x_{\ell+1}=x_\ell+M_\ell(\operatorname{Norm}(x_\ell)),
$$

其中 $M_\ell$ 是 attention、window 或 recurrent mixer. 即使某个 recurrent 层的状态遗忘了早期信息, 残差流仍把当前 token 表示向上传递;它不会凭空恢复窗口外 token 的独立表示. attention 层随后能读取的是各历史位置当时写入并保存的 K/V, 这些 K/V 来自对应层输入, 与当前残差流中的早期信息不是同一对象.

若同层有并联分支, 一种形式是

$$
x_{\ell+1}=x_\ell+W_o[a_\ell\Vert r_\ell].
$$

另一种形式先让两条分支各自带残差或 normalization 再相加. normalization 放在共享输入、分支内部或融合之后, 会改变分支尺度与 gate 梯度. 对比架构时应把这些位置一起列出, 否则质量差异可能来自 normalization 和参数规模, 不全来自记忆机制.

**混合比例如何决定状态上界。**

设总层数为 $L$, full、window、recurrent 层比例分别为 $p_F$、$p_W$、$p_R$, 三者之和为 1. 假设各 attention 层使用相同 KV 配置, 每 token、每层 KV 字节为 $q$, recurrent 每层固定状态为 $m_R$ bytes. 长度为 $t$ 时, 单请求状态近似为

$$
M(t)=Lp_Ftq+Lp_W\min(t,w)q+Lp_Rm_R.
$$

当 $t>w$ 后, 对长度的导数为

$$
\frac{dM}{dt}=Lp_Fq.
$$

所以长期容量增长只由 full 层比例决定. $p_F$ 从 1 降到 0.25 会把斜率降为四分之一, 不会得到固定上界;只有 $p_F=0$ 或 full 层另有淘汰/压缩时, 状态才可能在窗口填满后稳定.

head 级混合可以得到相似公式. 设每层 attention KV heads 数为 $H_F$, window KV heads 数为 $H_W$, recurrent state 为 $m_R$, 则

$$
M(t)=2Lbd_h\left(H_Ft+H_W\min(t,w)\right)+Lm_R.
$$

query heads 与 KV heads 的共享关系要单独代入. 四个 attention query heads 可能只共享一个 KV head, 此时容量由一个 KV head 决定, 计算输出仍有四个 query heads. 把「attention heads 占比」直接当成 KV 占比, 会在 GQA 或 cross-layer sharing 下算错.

状态上界还受精度影响. recurrent matrix 为了长期稳定可能使用 FP32 累加, attention KV 使用 BF16 或更低位宽. 即使 recurrent heads 数量较多, 固定状态字节仍可能在短序列占显著比例. 令 full 增长项与 recurrent 常数相等,

$$
t_{eq}=\frac{p_Rm_R}{p_Fq}.
$$

$t<t_{eq}$ 时固定矩阵可能是主要状态, $t>t_{eq}$ 后 full KV 增长项占优. 所以“递归状态远小于 KV”只在超过具体交叉长度后成立.

**时间路由的状态承诺可以形式化。**

令 $G_t^m\in\{0,1\}$ 表示第 $t$ 步是否执行模式 $m$, $P_t^m\in\{0,1\}$ 表示是否维护该模式未来所需状态. 执行 full attention 需要此前每个位置都生成了可读 K/V, 因而

$$
G_t^F=1\Longrightarrow P_i^F=1,qquad \forall i\le t.
$$

当前不走 full 分支并不能令 $P_t^F=0$, 除非路由规则保证未来永不再走 full, 或未来 full 分支接受缺失当前位置. 计算选择 $G$ 与状态维护 $P$ 是两组变量. soft/hard routing 常只展示 $G$, 服务成本却由 $P$ 决定.

recurrent 状态也有类似约束. 若位置 $t$ 跳过 recurrent update, 后续恢复该分支时的状态不包含 $x_t$. 可以定义 skip 为合法语义, 也可以让状态每步更新、只跳过输出读取. 前者减少更新计算并改变记忆内容, 后者只省下读取或融合的一部分. 论文与实现需要说明 gate 控制的是 update、read 还是整个分支.

窗口分支更容易间歇执行, 因为只需最近 $w$ 个位置. 若中间 token 没有生成 window K/V, 下一次执行时窗口中会出现空洞. 系统可以始终生成 K/V 但只在选中时做 attention, 也可以把最近原始 hidden 暂存并在恢复时补投影. 前者保留投影与容量成本, 后者增加补算与隐藏状态缓存. 时间路由没有免费的缺省状态.

单向阶段切换能放宽约束. 例如前 $T_0$ token 使用 full attention, 此后永久切到 recurrent, 切换时将已有历史压入递归状态并释放 KV. 切换之后不再承诺精确回看, 状态生命周期清晰. 反向从 recurrent 切回 full 则无法重建此前未保存的逐 token K/V, 除非原始 hidden 或 token 能被重放. 可逆路线必须在状态设计中提前付费.

因果路由还不能读取未来执行结果. 训练时若先计算三条分支完整序列, 再让位置 $t$ 的 router 使用包含双向或未来信息的统计量选择, 推理时无法复现. router 输入、负载统计和辅助目标都要遵守 causal prefix. batch 级负载均衡可以使用同一批未来 token 的总量来分配容量, 但这属于训练调度信号, 不能渗入单个 token 的模型输出.

## 3. 线性状态、门控和精确回看的差别

### 3.1. 一个标量状态手算

把式 (4)缩成标量, 令 $\phi(k_t)=\phi(q_t)=1$, 初始状态为 $S_0=z_0=0$. 第一个 Value 为 $v_1=2$, 更新后 $S_1=2,z_1=1$, 输出 $o_1=2$. 第二个 Value 为 $v_2=4$, 更新后 $S_2=6,z_2=2$, 输出 $o_2=3$. 两个历史值在状态里只剩和与计数, query 无法单独取回 $v_1$.

加入衰减 $\lambda=0.5$ 后, 更新改为 $S_t=\lambda S_{t-1}+v_t$, $z_t=\lambda z_{t-1}+1$. 第二步得到 $S_2=5,z_2=1.5$, 输出约为 $3.333$. 近期值占比更高, 旧状态按指数衰减. 这类 gate 决定记忆更新速度, 与滑动窗口的硬截断不同: 窗口内 token 各自保留, 线性状态从写入开始就发生混合.

向量状态增加了按 key 写入和按 query 读取的能力, 容量仍由 $d_kd_v$ 决定. 长度增长时, 更多 token 共用同一矩阵. 某些任务只需要累积统计或平滑状态, 固定矩阵很合适; 精确复制随机字符串或从大量相似 key 中取回单项时, token 级 attention 通常更有优势. 混合架构保留少量 attention 层或 heads, 正是为了给这类高分辨率访问留出通道.

二维状态能看到碰撞怎样发生. 令 $k_1=k_2=(1,0)^\top$, $v_1=(2,0)$, $v_2=(0,4)$, 使用无归一化外积累加. 两次更新后, $S_2$ 的第一行方向同时包含两个 Value 的和. query $q=(1,0)^\top$ 只能读到合成结果 $(2,4)$, 无法指定返回 $v_1$ 或 $v_2$. 若两个 key 正交, 它们会写入不同状态方向, query 才能分开读取.

真实 key 是连续向量, 完全相同并不常见, 高相似 key 仍会互相干扰. 归一化、衰减、delta rule 和更大 state 可以减轻冲突, 无法把固定维矩阵变成无限个独立槽位. 精确关联召回任务因此是线性模型的重要压力测试, 平均困惑度很难暴露这种定址能力差异.

### 3.2. Delta rule 对已有槽位做定向修改

DeltaNet 不只是把新外积加进状态. 设 $S_{t-1}\in\mathbb{R}^{d_v\times d_k}$, 归一化 key 为 $k_t$, 当前 key 从旧状态读出的预测为 $S_{t-1}k_t$. delta update 使用误差 $v_t-S_{t-1}k_t$ 修改对应方向:

$$
S_t=S_{t-1}+\beta_t
\bigl(v_t-S_{t-1}k_t\bigr)k_t^\top. \tag{9}
$$

$\beta_t\in[0,1]$ 控制写入强度. 当同一 key 方向再次出现时, 式 (9)会先减去旧预测与新 Value 的差, 比无条件累加更适合覆盖关联. [Gated Delta Networks](https://arxiv.org/abs/2412.06464)再加入数据相关的遗忘 gate, 让状态能够快速擦除, delta rule 负责定向更新. Olmo Hybrid 使用的正是 Gated DeltaNet 层, 并允许负特征值以增强状态跟踪能力.

标量例子可以逐步核对覆盖行为. 取 $S_0=0,k_1=k_2=1,\beta_1=\beta_2=0.5$. 第一次写入 $v_1=4$, 得到 $S_1=0+0.5(4-0)=2$. 第二次同方向写入 $v_2=6$, 得到 $S_2=2+0.5(6-2)=4$. 无条件外积累加会得到 $10$, delta update 则朝新目标 $6$ 移动. 若继续重复写入 $6$, 状态依次变成 $5,5.5,5.75$, 逐步逼近目标.

再加入全局遗忘系数 $\gamma_t$, 一种抽象更新为 $S_t=\gamma_tS_{t-1}+\beta_t(v_t-S_{t-1}k_t)k_t^\top$. $\gamma_t$ 小会同时衰减许多旧方向, $\beta_t$ 主要控制当前 key 方向的修正. 具体 Gated DeltaNet 的参数化与并行算法更复杂, 但「全局保留强度」和「定向覆盖」这两个动作可以分开理解.

递归 gate 改变的是 state transition. 它与 attention 输出门控、分支路由器有三种不同语义. 遗忘 gate 控制旧状态保留多少; 输出 gate 控制当前分支向残差流写多少; router 决定执行哪种混合器. 三者都可能使用 sigmoid, 参数名相似, 状态生命周期却完全不同.

**输出融合不自动带来系统节省。**

设 attention 输出 $a_t=(2,-1)$, recurrent 输出 $r_t=(0,3)$, 融合系数 $\alpha_t=0.25$. 软融合得到:

$$
y_t=\alpha_t a_t+(1-\alpha_t)r_t=(0.5,2). \tag{10}
$$

这一步需要先得到 $a_t$ 和 $r_t$. 即使 $\alpha_t$ 很小, attention 的 QK、softmax 与 KV 读取已经发生. 软 gate 可以改善表示, 对时延的直接收益接近零. 只有结构级稀疏、hard routing 或能在计算前预测并跳过分支的 gate 才会减少算子工作.

hard gate 又引入训练问题. 离散选择需要 straight-through、采样或其他梯度估计, 路由容易塌缩到更易优化的分支. 容量约束与负载均衡损失可以维持分支使用率, 但均匀率无法回答每个 token 是否选对记忆机制. 评测应把路由选择与依赖类型对齐: 局部模式、状态更新、精确远距检索分别用了哪条分支.

成本也可以写成一条简单式子. 设三条分支单 token 成本分别为 $C_F(t)$、$C_W(w)$ 与 $C_R$, 软融合成本约为 $C_F+C_W+C_R+C_{gate}$. top-1 hard routing 的理想成本是被选分支成本加 $C_{gate}$. 实际系统还要加 token 重排、padding 和分支间同步; 当每个分支只收到少量 token 时, 理想节省会被低利用率吃掉.

门控训练还要处理尺度差异. attention 输出、window 输出和 recurrent 输出的方差可能不同, router 会偏向数值幅度较大或早期梯度更容易的分支. 分支前后使用独立 normalization、限制 gate 初始化和监控各分支梯度, 能让比较更公平. 只看平均 gate 值会漏掉层间差异, 因为靠前层与靠后层承担的记忆动作本来就不同.

训练拓扑与 Decode 拓扑需要一致. soft gate 训练后强行改成 top-1 推理, 会删除训练时一直存在的另一条输出; full attention 训练后按 gate 阈值释放 KV, 也会改变未来可见状态. 若部署目标是 hard routing, 训练中就要让模型经历相同的分支缺失和 state update, 再单独测路由错误带来的质量下降.

**门控梯度决定分支是否真的学得到。**

令两个分支的输出为 $a_t$ 和 $r_t$, gate logit 为 $g_t$, $\alpha_t=\sigma(g_t)$, 融合输出仍写成 $y_t=\alpha_ta_t+(1-\alpha_t)r_t$. 若损失对输出的梯度为 $u_t=\partial L/\partial y_t$, gate logit 收到的梯度为:

$$
\frac{\partial L}{\partial g_t}
=u_t^\top(a_t-r_t)\alpha_t(1-\alpha_t). \tag{11}
$$

式 (11)包含两个容易测出的量. $a_t-r_t$ 表示两条分支在当前 token 上给出了多大差异; $\alpha_t(1-\alpha_t)$ 表示 sigmoid 还剩多少可训练空间. 两条分支输出接近时, router 很难从任务损失中获得方向. $\alpha_t$ 接近 $0$ 或 $1$ 时, sigmoid 饱和同样会压低梯度. 这解释了为什么 gate 使用率看似稳定, 路由分工仍可能很弱.

取一维例子, $a_t=4,r_t=1,u_t=2$. 当 $\alpha_t=0.5$ 时, $\partial L/\partial g_t=2\times3\times0.25=1.5$. 若 gate 已经偏到 $\alpha_t=0.99$, 梯度降为 $2\times3\times0.0099=0.0594$, 只有前者的约 $3.96\%$. 再把两个分支改为 $a_t=1.1,r_t=1$, 即使 $\alpha_t=0.5$, 梯度也只有 $0.05$. 初始化过饱和和分支输出过近都会让 router 很早停止形成清晰分工.

分支本身收到的梯度也受 gate 缩放: $\partial L/\partial a_t=\alpha_tu_t$, $\partial L/\partial r_t=(1-\alpha_t)u_t$. 若训练初期 $\alpha_t$ 长期接近 $1$, recurrent 分支几乎得不到任务梯度; 后续再用负载均衡把 token 分给它, 也可能只是把输入送进一个训练不足的分支. 门控初始化、分支 dropout 与最低路由容量需要共同设计, 仅约束平均选择比例无法补回早期缺失的梯度.

状态更新还多一条跨时间梯度. 写成 $S_t=f_t\odot S_{t-1}+U_t$, 从时刻 $T$ 回传到 $t$ 的直接通路包含 $\prod_{i=t+1}^{T}f_i$. 若每步 $f_i=0.99$, 相隔 $100$ 步后系数约为 $0.366$; 相隔 $1000$ 步后约为 $4.32\times10^{-5}$. 若 $f_i=0.999$, 相隔 $1000$ 步仍约为 $0.368$. 很小的 gate 差异经过长序列连乘后会形成数量级差别, 因而长程训练样本不能只在末尾检查输出, 还应统计不同距离上的 state 保留率与梯度范数.

这种连乘也影响训练长度外推. 模型在长度 $4096$ 上学到的平均保留率, 到 $65536$ 步可能已经把早期状态衰减到数值噪声附近. 训练时可以对 $\log f_t$ 做分桶统计, 因为 $\log\prod_i f_i=\sum_i\log f_i$, 长距离保留量能够直接累加估算. 对需要永久保存的控制变量, 应观察对应状态方向是否具有接近单位幅值的转移; 对需要快速覆盖的槽位, 则检查 delta update 后旧值残留多少.

训练日志至少应按层记录 gate 均值、分位数、饱和比例、两个分支输出余弦相似度和各自梯度范数. 若 gate 的 $1\%$ 与 $99\%$ 分位都挤在 $0.5$ 附近, 模型可能一直做平均融合; 若大部分值落在 $0.01$ 以下或 $0.99$ 以上, 要继续确认离散选择是否与依赖类型一致. 这些数值与质量分桶对应后, 才能判断门控是在选择记忆动作, 还是只在补偿分支尺度.

**遗忘 gate 的半衰期。**

常数 gate $\gamma\in(0,1)$ 下, 一次写入经过 $n$ 步后的系数为 $\gamma^n$. 令它降到一半, 半衰期满足

$$
\gamma^{n_{1/2}}=\frac12,
\qquad
n_{1/2}=\frac{\log(1/2)}{\log\gamma}.
$$

$\gamma=0.9$ 时半衰期约为 6.58 步, $\gamma=0.99$ 时约 68.97 步, $\gamma=0.999$ 时约 692.8 步. gate 看起来只差一个小数位, 可记忆时间尺度相差约十倍. 若目标需要跨越 32K token, 固定 $0.999$ 仍会衰减到约 $1.25\times10^{-14}$. 长记忆不能仅依赖一个略小于 1 的统一衰减.

数据相关 gate 允许某些时段接近 1, 在边界处迅速下降. 用累积对数表示更稳定:

$$
\log r_{i\rightarrow t}=\sum_{j=i+1}^{t}\log|\gamma_j|.
$$

$r_{i\rightarrow t}$ 是第 $i$ 步状态到第 $t$ 步的直接保留幅值. 统计平均 gate 不足以推断它, 因为乘积由对数和决定. 一串 $0.9999$ 中混入一次 $0.1$, 早期状态立即缩小十倍;算术平均仍可能接近 1. 训练诊断应观察累计对数保留量及其在不同状态方向上的分布.

若转移允许负特征值, 状态方向可在相邻步之间翻转符号, 从而表示振荡模式. 标量递推 $s_t=\lambda s_{t-1}+u_t$ 中, $\lambda=-1$ 会让旧状态每步换号且幅值不衰减; $|\lambda|<1$ 时振荡同时衰减; $|\lambda|>1$ 时幅值增长. 多维状态由转移矩阵的特征值或奇异值控制, 非正规矩阵还可能在所有特征值幅值小于 1 时产生暂态放大.

稳定性因此不能只看 gate 是否落在 $[0,1]$. delta update 的状态 Jacobian随 key 与写入率变化, normalization、残差和输出投影还会改变扰动进入下一层的尺度. 实测可对长序列记录 state norm、最大奇异值近似、NaN/Inf、输出方差与梯度范数. 范数稳定也不保证记忆正确: 状态可能被新内容不断覆盖后维持相同幅值.

**Delta update 的误差传播。**

把式 (9)写成 $S_t=S_{t-1}+\beta_t(v_t-S_{t-1}k_t)k_t^\top$. 假设另一条数值路径产生微小状态误差 $E_{t-1}$, 两条路径使用相同的 $k_t$、$v_t$、$\beta_t$. 相减可得

$$
E_t=E_{t-1}-\beta_tE_{t-1}k_tk_t^\top
=E_{t-1}(I-\beta_tk_tk_t^\top).
$$

若 $\|k_t\|_2=1$ 且 $0\le\beta_t\le1$, 沿 $k_t$ 方向的误差缩小为 $1-\beta_t$, 与 $k_t$ 正交的方向保持不变. 单次 delta update 不会清除所有数值误差, 它只修正当前 key 方向. keys 长期覆盖整个空间时, 各方向误差都有机会被压低;keys 集中在低维子空间时, 正交方向的误差会保留.

加入全局 gate $\gamma_t$ 后, 一种更新形式给出

$$
E_t=E_{t-1}(\gamma_tI-\beta_tk_tk_t^\top).
$$

沿正交方向乘 $\gamma_t$, 沿 key 方向乘 $\gamma_t-\beta_t$. 当 $\beta_t>\gamma_t$ 时 key 方向会翻转符号;绝对值若超过 1, 误差可能放大. 具体 Gated DeltaNet 参数化需要按其公式分析, 这个简式展示了遗忘与定向更新如何共同决定局部稳定性.

输入量化误差也会进入状态. 若 $v_t$ 带误差 $\epsilon_t$, 更新额外写入 $\beta_t\epsilon_tk_t^\top$. 后续 query 只要与 $k_t$ 相关就会读到它. KV cache 的量化误差保留在对应 token, 每步 attention 重新加权;recurrent state 的误差被写进共享矩阵, 会参与未来更新. 这就是固定 state 常采用较高累加精度的数学原因.

chunk scan 与逐步 recurrence 的差异可视为浮点舍入产生的 $E_t$. 结合律在实数中成立, 浮点加法与矩阵乘法并不严格结合. chunk 大小改变归约顺序, BF16 输入、FP32 state 与输出转换共同决定误差. 对齐测试应随序列长度画最大绝对误差和相对误差, 还要跑多次连续 chunk, 因为单个短块接近不能保证长流稳定.

**门控塌缩有多种形态。**

第一种是输出 gate 饱和. $alpha_t$ 长期接近 1, recurrent 分支几乎不影响损失, 梯度逐渐减弱;长期接近 0 时 attention 分支遭遇同样问题. 第二种是两分支同质化: $a_t\approx r_t$, 式 (11)中的差值很小, gate 即使位于 0.5 也学不到明确分工. 第三种是状态 gate 退化, 始终保留导致旧内容干扰, 或始终遗忘导致长期记忆消失.

第四种发生在 hard routing 的负载约束. router 为满足均衡损失把 token 平均分给分支, 任务损失却没有教会「哪类 token 该去哪」. 使用率看起来健康, 路由与依赖类型无关. 第五种是系统容量截断: router 想把许多 token 送到 full 分支, capacity factor 将溢出 token 改送其他分支或丢弃, 训练时看到的实际路径已经偏离 router logits.

区分这些形态需要联合观察. gate 直方图显示饱和;分支输出余弦与差值范数显示同质化;按距离和任务类型统计选择显示语义分工;溢出率和每分支 token 数显示容量约束;分别冻结或删除分支的消融显示模型是否真正依赖它. 单个平均 gate 或负载均衡损失无法覆盖这些问题.

正则也有副作用. 提高 gate 熵能避免过早饱和, 也会鼓励长期软混合, 与部署时 top-1 路由产生差距. 强负载均衡能提升硬件利用率, 可能迫使本应走 attention 的远距 token 进入递归分支. 分支 dropout 能让两边独立学习, dropout 频率过高又改变正常联合计算. 每个辅助项都要通过对应的行为评测确定强度.

初始化决定早期学习顺序. 若 attention 分支来自成熟结构, recurrent 分支随机初始化, gate 一开始偏向 attention 可以保护损失, recurrent 得到的任务梯度却更少. 偏向 0.5 能让两边都参与, 随机分支噪声会直接进入残差. 一种可行路径是先让新分支模仿或蒸馏已有输出, 再逐步开放 gate;这会增加训练阶段, 但能将结构替换与路由学习分开.

**精确回看也有边界。**

full attention 保存逐 token K/V, 提供重新打分的可能, 不保证模型一定找到目标. query-key 表示可能没有编码所需属性, softmax 在大量相似 keys 中会分散, 位置编码可能在训练长度外退化. 因而 full 分支是高分辨率访问通道, 不是检索正确性的充分条件.

窗口内的 token 也可能因有限 heads 和 softmax 竞争而被忽略. recurrent state 在特定任务上反而更合适: 累计计数、有限状态机或持续更新的单值变量不需要保存全部历史, 一个定向状态可直接维护答案. 把所有长程任务归到 full attention, 会错过问题需要的是原文重取还是充分统计量.

可以用两组对照构造反例. 第一组给出大量随机键值对, 末尾随机查询其中一个 key;每个 value 都可能被选, 逐 token 地址有明显优势. 第二组给出连续的加减操作, 末尾只问总和;保存全部操作并非必要, 固定状态若学会准确更新会更直接. 第三组不断覆盖同一个变量, 测试 delta rule 能否忘掉旧值而无条件累加会不会混淆.

混合模型的目标不是让一个分支统治全部任务. attention 通道保留可寻址细节, recurrent 通道维护可压缩状态, window 通道处理高频局部关系. 有效组合需要模型学会把信息送进合适通道, 并在后续层读取. 仅把三种算子装进网络而缺少覆盖这些记忆动作的数据, 结构潜力不会自动出现.

## 4. 流式状态的创建、更新、淘汰与回滚

### 4.1. 三类状态有不同生命周期

full KV 在 Prefill 时为每个 token 追加 K/V, Decode 每步继续 append, 请求结束后整体释放. window KV 同样追加, cache 满后覆盖或回收最旧普通位置. [StreamingLLM 官方实现](https://github.com/mit-han-lab/streaming-llm)把少量 sinks 设为常驻槽, 中间旧 KV 淘汰, 最近窗口继续滚动. sink 保持 softmax 的稳定支点, 已淘汰正文不会写回这些旧 KV.

recurrent state 每步原地更新. 标准 causal 递归中, $S_t$ 已经包含位置 $0$ 到 $t$ 的压缩历史, 旧 token 没有独立页面可释放. state 大小固定, 但请求结束前一直存活. batch 中每个请求都有自己的 state, packed sequence 还要在文档边界重置, 否则前一文档状态会泄漏到下一文档.

层级 hybrid 需要 per-layer state table. 以 $R/R/R/F$ 为例, 三个 recurrent 层各保存自己的矩阵状态, attention 层保存完整或窗口 KV. 服务框架若提供统一 `past_key_values` 接口, 内部条目仍要携带类型、shape、有效长度和位置. 把所有条目强行补成同一 tensor, 常会造成大量无效内存或错误裁剪.

attention sinks 只属于会执行 softmax attention 的层. recurrent 层接收开头 token 后, 这些 token 的影响已经进入矩阵 state, 不需要另外保存 sink KV. full attention 层本来就保留全部历史, sink 也没有减少 cache 的作用. 真正需要「sink + window」双区 cache 的是会淘汰普通旧 KV 的 window attention 层. 把 sink 数作为全模型统一状态参数, 容易为无关层分配多余槽位.

请求生命周期还包含暂停、换出和恢复. KV page 可以按层序列化, recurrent state 则通常是一组连续小矩阵. 换出时只保存逻辑有效页与当前 state, 环形 buffer 的空槽无需写盘; 恢复时还要带回写指针、逻辑位置和 sink 页面. 丢失任何一个位置元数据, 数值 state 即使完整也可能在下一 token 使用错误坐标.

量化策略也要按状态类型选择. KV cache 常用逐 token、逐 head 或按 page 量化; recurrent state 每一步都会继续参与乘法和更新, 量化误差会累积进入未来. 对固定 state 使用更高精度, 对大体积 KV 使用低比特, 可能比全局统一 dtype 更合适. 这种不对称配置需要 kernel 和 cache schema 一起支持.

### 4.2. Prefill 与 Decode 使用不同 kernel

Prefill 有完整序列并行度. full attention 适合 FlashAttention 一类分块精确 kernel, window attention 适合带状或块稀疏 kernel, recurrent mixer 则使用 chunk scan 把长递推拆成块内并行与块间状态传递. chunk 大小会影响并行度、临时状态和数值误差, 它属于 kernel 参数, 不改变式 (4)或式 (9)定义的逻辑递推.

Decode 每次只有一个或少量新 token. full attention 受历史 KV 读取带宽限制, window attention 把读取限制在 $w$ 与 sinks, recurrent mixer 适合 fused recurrent kernel. Flash Linear Attention 的 DeltaNet 实现同时暴露 chunk 与 fused recurrent 模式, 正好反映两个阶段的差别. 用训练时的 chunk kernel 硬跑单 token, 或用逐步 recurrent kernel 处理长 Prefill, 都可能得到正确输出却浪费硬件.

hybrid 会在层间频繁切换 kernel. 若每个小层都单独 launch, 固定状态层省下的算术可能被调度开销抵消. CUDA Graph、连续层融合和按类型批量调度能降低开销, 但残差依赖限制了跨层任意重排. 性能报告需要拆开各类 layer time, 仅给整模型平均值很难定位 attention 层是否重新成为瓶颈.

recurrent scan 的数值路径也值得单独验收. 顺序 scan、树形并行 scan 和 chunk scan 的浮点加法顺序不同, BF16 或 FP16 下会出现累积差异. state 经几万步反复更新, 小误差可能逐渐放大. 常见实现让输入与输出采用低精度, state 累加或部分归约使用 FP32, 再在块边界转换. 精度选择会改变吞吐与 state 字节, 需要和质量一起报告.

可变长度 batch 会让 chunk kernel 遇到边界. padding token 不能更新 recurrent state, packed sequence 的 `cu_seqlens` 或等价边界要在 scan 中触发 reset. attention mask 只屏蔽输出而 state 仍然更新, 会把 padding 或上一文档写进下一段. 单元测试应把两个样本拼接运行, 与分别运行后拼接输出比较.

window 与 recurrent 分支融合时还可能出现时间对齐错误. window branch 的第 $t$ 个输出应使用到位置 $t$ 的合法 K/V, recurrent branch 的 $S_t$ 也要包含同一位置或共同采用先读后写约定. 一个分支用 $S_{t-1}$, 另一个分支包含当前 token, 融合后就出现一位偏移. 公式和 kernel 都要明确 update-before-read 或 read-before-update.

**Prefix cache 与 speculative rollback 更难处理递归 state。**

KV cache 支持按 token 或 page 截断. speculative decoding 验证失败时, 删除未接受 token 对应的尾部 K/V 即可回到接受位置. recurrent state 已经把草稿 token 写入矩阵, 一般无法仅凭当前 $S_t$ 精确减掉若干步. 系统需要保存检查点、记录可逆更新所需信息, 或从最近检查点重放接受前缀.

设每隔 $c$ 个 token 保存一次 state snapshot. 最坏回放长度为 $c-1$, snapshot 内存约增加原状态的 $1/c$ 每 token 摊销量. $c$ 小时回滚快、内存高; $c$ 大时内存低、拒绝后重算多. 混合模型还要同时截断 attention KV 与恢复 recurrent state, 两者必须落在同一个已接受 token 边界.

Prefix cache 也需要保存完整的 hybrid 状态包. 相同文本前缀只有在权重、层表、窗口、sink、位置编码和 recurrent kernel 数值语义一致时才能复用. 缓存键应包含这些配置的版本标识. 只缓存 attention KV 而遗漏 recurrent state, 续写会从零状态开始; 只缓存 recurrent state 而遗漏 attention KV, 精确回看分支又失去历史.

连续 batching 中, 不同请求可能处于 Prefill、Decode、回滚和换出阶段. full KV page、window 环形页与 recurrent state 的增长速度不同, 调度器不能用统一 token 长度估算内存. 一个拥有很长 full history 的请求即使当前只生成一个 token, 仍会占据大量 attention pages; 一个同长度的纯 recurrent 请求只占固定 state. admission control 应按实际层表预测增量和常驻量.

beam search 也会复制状态. KV cache 可让多个 beam 共享未分叉前缀页, 分叉后只写新页. recurrent state 在分叉点可以共享只读 snapshot, 每个 beam 的后续更新需要 copy-on-write. state 虽小, 每层每个 beam 都复制一次仍会放大. 合并 beam 时, 两个不同 recurrent state 无法像概率一样简单平均后继续保持原函数.

异常恢复需要一致性边界. 如果服务进程在 token $t$ 写完部分层后失败, 仅记录输出 token 数无法判断各层 state 是否都到达 $t$. 状态提交可以在整 token 完成后统一推进版本号, checkpoint 只保存已提交版本. 这样 full KV、window 指针和 recurrent matrix 在恢复时对应同一个前缀.

**流式因果约束覆盖读、写、路由三步。**

自回归位置 $t$ 的输出只能依赖 $x_{\le t}$. 对 attention, causal mask 约束 query 不能读取未来 K/V;对 recurrence, 顺序更新天然只从 $S_{t-1}$ 和 $x_t$ 产生 $S_t$;对混合路由, router 自身也必须只读前缀. 三处任何一处泄漏, 训练 loss 都可能异常变好, 单 token Decode 却无法复现.

当前 token 是否先写再读需要统一. update-before-read 使用

$$
S_t=U(S_{t-1},x_t),\qquad y_t=R(S_t,x_t),
$$

当前输出包含 $x_t$ 的状态贡献. read-before-update 使用

$$
y_t=R(S_{t-1},x_t),\qquad S_t=U(S_{t-1},x_t).
$$

二者相差一个位置. 标准 causal self-attention 通常允许位置 $t$ 看自身 K/V, 更接近前一种约定. 若 recurrent 分支采用后一种而 attention 分支采用前一种, 同层融合会产生时间错位. 可以在投影或标签移位中补偿, 但训练和 Decode 必须采用同一约定.

chunk 并行最容易在边界破坏因果性. 一个 chunk 内若先聚合全部 token 得到共享状态, 再为每个位置读取, 前部位置会看到 chunk 后部. 正确 scan 要为 chunk 内每个位置构造前缀状态, 或利用严格下三角结构. chunk 间只传递前一块结束状态. 验证时把同一序列用不同 chunk 大小运行, 各位置输出应在浮点容差内一致.

bidirectional scan 适用于编码器或非因果任务, 不能直接用于自回归训练. 某些实现接口同时支持 causal 与 bidirectional 模式, 配置错误可能不会报 shape 异常, 只会让评测时表现与生成时脱节. 最小测试是在序列后半段替换 token, 前半段 logits 必须保持不变;这一性质同时检查 attention mask、recurrent scan 与 router 输入.

padding 与 packed sequence 也属于因果状态边界. padding token 若继续执行 $U$, 后续真实 token 会读取被污染状态;两个文档打包后不 reset, 第二篇开头会依赖第一篇. attention 可用 block-diagonal mask 隔开文档, recurrence 需要在对应边界显式将状态归零或加载各自初态. 只对 loss mask 掉 padding 并不能阻止状态更新.

**训练并行与逐 token 推理需要代数等价。**

线性 recurrence 能否并行, 取决于状态转移能否组成结合算子. 仿射递推

$$
S_t=A_tS_{t-1}+B_t
$$

可把一步表示为二元组 $(A_t,B_t)$. 连续两步的组合为

$$
(A_2,B_2)\circ(A_1,B_1)
=(A_2A_1,A_2B_1+B_2).
$$

这个组合满足结合律, 因而可用 parallel scan 计算所有前缀. 树形 scan 改变乘加顺序, 实数结果相同, 浮点结果存在小差异. 训练用 chunk/parallel 路径, Decode 用 recurrent 路径时, 两者需要先在实数公式上等价, 然后再处理精度容差.

数据相关 $A_t$ 没有破坏结合性, 因为每步的 $(A_t,B_t)$ 在组合前已经确定. 若 $A_t$ 或 $B_t$ 依赖当前状态 $S_{t-1}$ 的非线性函数, 就无法提前独立生成全部二元组, 简单 scan 不再适用. delta rule 看似依赖 $S_{t-1}k_t$, 通过代数整理可得到对旧状态的线性变换加写入项, 从而构造相应 scan;实现是否使用该形式要以具体算子为准.

dropout 会破坏朴素对齐. 训练并行路径与逐步路径若随机数消费顺序不同, 即使公式一致也会生成不同 mask. 做数值等价测试时先关闭 dropout;测试训练一致性时, 使用由位置和通道确定的无状态随机索引, 或接受统计等价而非逐元素相等. normalization 若跨时间统计也会引入未来信息, causal mixer 通常使用逐 token 通道归一化.

混合 attention 的训练与推理还有 mask 差异. 训练可能用完整序列上的带状 mask, Decode 用环形 buffer. 两者必须在逻辑位置、sink 集合和 RoPE 坐标上等价. 训练只见固定长度 $N$, 推理滚动到远大于 $N$ 的绝对位置时, 位置编码与环形寻址仍要使用真实逻辑坐标, 不能把槽位号当位置号.

soft gate 训练、hard gate 推理是另一类不一致. 若训练输出为两个分支的凸组合, 模型可能依赖两者共同抵消误差;推理只留最大 gate 分支会发生分布偏移. 可在训练后期逐渐降低温度、使用 straight-through 离散路由, 或直接保留软融合并接受双分支成本. 选择哪条路径属于模型定义, 不应到部署时临时改变.

状态 dtype 也应一致到可接受范围. 训练可能在 BF16 激活上用 FP32 scan, 推理为了速度把 recurrent state 降成 BF16;误差会随长序列持续进入更新. 短 benchmark 接近不能代表 100K token 后仍接近. 应在目标长度上比较 logits 漂移、任务质量和 state norm, 再决定是否允许不同累加精度.

**记忆容量要按独立请求与共享前缀计算。**

每个请求的 recurrent state 取决于完整前缀, 两个不同前缀一般不能共享. 两个请求若前缀完全相同, 可以共享只读 state snapshot;一旦各自追加 token, 必须复制或 copy-on-write. state 大小固定, 复制成本与前缀长度无关;full KV 的共享前缀页可能很大, copy-on-write 只复制分叉后的新页.

设 recurrent state 每请求为 $R$ bytes, full KV 每 token 为 $q_F$ bytes, window 固定为 $Wq_W$ bytes. $B$ 个无共享请求、平均长度 $S$ 的混合状态约为

$$
M_B=B(R+Wq_W+Sq_F).
$$

若它们共享长度 $P$ 的前缀且 full KV 页可共享, 总量变为

$$
M_{share}=R+B(R_{branch})+Pq_F+B(S-P)q_F+BWq_W,
$$

这里 $R$ 是共享前缀 snapshot, $R_{branch}$ 表示分叉后每请求独立 state 的完整副本或增量实现. 常见实现会在分叉点复制整个 fixed state, 因而 $R_{branch}\approx R$. KV 的共享收益随 $P$ 增长, recurrent state 的共享收益至多省掉若干固定矩阵副本.

beam search 在同一分叉点产生多个候选, 正好符合这种结构. attention 前缀页只读共享, recurrent snapshot 初始共享;第一个新 token 更新 state 时, 每个 beam 得到不同矩阵. 若 state 更新可表示为持久化增量, 可以延迟完整复制, 读取会变复杂. 由于 fixed state 相对长 KV 较小, 直接复制往往更简单, 大 beam 或大状态维度下仍需计入.

外部检索记忆又是第四类状态. 模型可以把被窗口淘汰的文本存入外部索引, 需要时取回若干片段重新进入上下文. 这恢复的是原文本或编码后的片段, 不等同于内部 recurrent state. 外部记忆容量可独立扩展, 查询有检索延迟和召回误差;内部 state 每 token 自动更新, 读取固定成本但细节受容量限制. 混合模型可以同时使用两者, 评测时要说明远距答案来自内部状态还是外部检索.

**状态损坏会沿两条路径扩散。**

attention KV 中一个 token 的误差留在该位置. 后续每个 query 对它分配权重 $p_t$, 输出扰动约为 $p_t\delta v$ 加上 key 误差引起的权重变化. 若后续长期不给该位置权重, 误差影响很小;某次重新检索它时, 误差又会出现. window 淘汰该位置后, 直接路径消失, 先前输出中已经传播进后续 hidden 的影响仍在.

recurrent state 的误差每一步都经过转移, 可能衰减、保留或放大, 并参与后续写入. 令理想状态与实际状态之差为 $E_t$, 一般有

$$
E_t\approx J_tE_{t-1}+\epsilon_t,
$$

$\epsilon_t$ 汇集当前步舍入、量化与输入误差. 展开为

$$
E_t\approx J_t\cdots J_1E_0+
\sum_{i=1}^{t}J_t\cdots J_{i+1}\epsilon_i.
$$

即使每步误差很小, 长时间累积后也由 Jacobian 乘积决定. 这与 attention 的逐位置误差存放方式不同: fixed state 把误差写进共享未来, attention 把误差保留在独立槽位等待被读取.

混合层还有跨分支扩散. recurrent 输出进入下一层 hidden 后, 后续 attention 会把受污染的表示投影成 K/V 并长期保存;attention 取回的错误内容也会被下一 recurrent 层写入状态. 分支并不构成隔离容器. 因此单层数值测试之外, 还要在完整层表上运行长序列, 观察误差是否在某种排布下被放大.

reset 错误属于幅度最大的状态损坏. 文档边界漏 reset 会把前文状态带入下一文;过早 reset 会清空合法历史;只 reset recurrent state 而保留 attention pages, 两条分支看到不同前缀. 每个请求需要一个统一逻辑版本, 各类 state 的创建、更新、回滚和释放围绕同一 token 边界提交.

## 5. 数值预算与验收要同时覆盖质量和系统

### 5.1. 八个 heads 的状态预算手算

构造一个便于跟算的 head 级 hybrid. 每层共 $8$ 个 heads, 其中 $2$ 个 full attention heads, $2$ 个 window heads, $4$ 个 linear heads. 令 $d_k=d_v=2$, 窗口 $w=4$, 当前历史长度 $t=10$. 每个 attention head 的一个位置需要 $d_k+d_v=4$ 个 cache 标量.

两个 full heads 保存 $2\times10\times4=80$ 个标量. 两个 window heads保存 $2\times4\times4=32$ 个标量. 每个 linear head 保存 $2\times2$ 的 $S_t$ 与长度为 $2$ 的 $z_t$, 四个 heads 共 $4\times(4+2)=24$ 个标量. 总状态为 $136$ 个标量. 若八个 heads 全是 full attention, 状态为 $8\times10\times4=320$ 个标量.

把历史扩到 $t=1000$, hybrid 状态变成 $2\times1000\times4+32+24=8056$, 全 attention 为 $32000$. 比例从 $42.5\%$ 降到约 $25.2\%$, 但仍随 $t$ 增长, 因为两个 full heads 一直保存历史. Decode 第 $10$ 步的 attention 候选数为 $2\times10+2\times4=28$, linear heads执行固定大小矩阵向量乘. 这组数字把「四分之一 full heads」同时映射到了 cache 与每步读取.

再看层级排布. 设四层一组, 前三层 recurrent state 各有 $24$ 个标量, 第四层使用八个 full heads. $t=10$ 时, 一组状态为 $3\times24+8\times10\times4=392$. 四层全 attention 为 $4\times320=1280$. $t=1000$ 时两者分别为 $32072$ 与 $128000$, 比例逼近 $25\%$. head 级和层级混合在这个对称例子里有相近渐近比例, 执行形态却不同: 前者每层启动两类 kernel, 后者每层只运行一种混合器.

若第四层改成窗口 attention, $t=1000$ 时一组状态降为 $3\times24+8\times4\times4=200$, 彻底去掉随 $t$ 增长的项. 对精确召回而言, full layer 能访问所有 token 级 K/V, window layer 只能读取最近四个位置. 这 $31872$ 个标量的差额对应明确的能力交换: 状态容量显著下降, 窗口外的逐 token 地址也随之消失.

状态字节还要乘 batch 与 beam 数. 以 BF16 计算, 单请求 $32072$ 个标量约 $62.6$ KiB; batch $128$ 约 $7.8$ MiB. 真实模型维度大得多, 但计算方法相同. admission control 可以从层表直接求出每新增一个请求和每生成一个 token 的内存增量.

### 5.2. 质量评测要按记忆动作分组

局部语言建模检查窗口分支, 精确 needle retrieval 与随机字符串复制检查 attention 的高分辨率回看, 状态机、计数和持续更新任务检查 recurrent state. 多证据推理还要区分证据是否需要同时保留原文, 或只需累计一个统计量. 把所有任务压成平均分, 很容易让大量局部样本遮住远距召回崩溃.

距离分桶仍然必要. query 与证据分别放在窗口内、刚越过窗口、多个窗口以外和训练长度外, 再观察 full heads 数量、attention 层周期或 recurrent state 大小时的变化. 对时间路由还要记录每个桶实际选择的分支, 否则无法判断质量来自正确路由, 还是某个昂贵分支始终被调用.

流式评测同时包含稳定性与历史问答. StreamingLLM 已说明保留 sinks 能维持其测试模型的流式困惑度, 官方 FAQ 也明确其 cache 只保留 sinks 与最近 token. 对已经淘汰的中间历史进行精确问答是另一项能力. 两项指标分开, 才能区分「持续生成不崩」和「长期内容仍可检索」.

state tracking 需要专门数据. 例如序列中不断出现 `set A=3`、`set A=7` 与 `query A`, delta rule 应覆盖旧关联, 无衰减累加可能混入多个值. 计数任务则需要持续累积, 过强遗忘会丢失早期增量. 两类任务分别测「改写」与「保留」, 能直接检验 gate 和 delta update 是否承担预期动作.

对 head 级 hybrid, 消融不能只删掉整个 attention 分支. 还应固定总参数和 FLOPs, 改变 attention heads 比例、KV heads 数和 window heads 比例. 若减少 attention heads 同时扩大 recurrent state, 质量变化包含两项因素. 对层级 hybrid, 固定 attention 层数后移动它们的深度位置, 可以分辨收益来自数量还是排布.

动态路由需要额外统计 confusion matrix. 把样本按局部依赖、累计状态、远距精确召回标注, 再记录 router 选择 $W$、$R$、$F$ 的比例. 总准确率提高但远距样本仍频繁走 $R$, 说明模型可能靠其他层补救, router 没有学到可解释分工. 路由熵、每批最大负载和被迫溢出比例也会影响实际吞吐.

**系统验收直接检查状态是否真的缩小。**

系统侧至少记录 TTFT、TPOT、每请求 state 字节、HBM 读取、kernel 时间、连续 batching 吞吐和 speculative rollback 代价. Prefill 与 Decode 分开画长度曲线. linear 或 SSM 层的 Decode 时间应在 cache 稳定后接近常数, window 层应在填满 $w$ 后稳定, full attention 层仍随历史增长.

正确性从长度很小的参考实现开始. full 与 window 分支可以和显式 mask 的稠密 attention 对齐; recurrent 分支比较逐步 scan、chunk scan 与 fused recurrent 输出和梯度. packed batch 在文档边界插入 reset, 再与逐样本单独运行比较. speculative rollback 则生成一段草稿, 回滚后重放接受 token, 最终 state 应与从未见过被拒 token 的参考路径一致.

性能曲线要跨过三个区间. 短序列下, full attention 的高效 GEMM 可能快于复杂 hybrid; 中等长度时, window 与 recurrent 层开始减少带宽和算术; 极长序列下, 少量 full 层可能重新主导 TTFT 与 TPOT. 如果曲线没有出现预期转折, 应检查 full 层比例、窗口是否实际裁剪、recurrent kernel 是否走了逐 token 慢路径.

稳态内存也要用长时间运行验证. 连续生成超过两倍窗口后, window pages 应保持固定; recurrent state shape 不变; full pages继续增长; sinks始终有效. 请求结束、取消和异常后, 三类状态都要释放. 只测单次短请求无法发现页引用泄漏与 snapshot 没有回收的问题.

数值检查与性能检查使用同一批 shape. kernel autotune 可能按长度、dtype 和 head 维选择不同路径, 某条少见 shape 才触发误差或回退. 保存每次选择的 backend、tile 和 accumulation dtype, 能把质量波动与执行路径对应起来. hybrid 层表越复杂, 这种逐层可观测性越重要.

部署前还要观察真实分配. full heads 数量下降后, KV 页面是否按 head 比例减少; window 页面是否在超过 $w$ 后归还; recurrent state 是否因框架统一 shape 被扩成序列长度; 路由未选中的分支是否仍执行. **混合架构的收益落在四个可测对象上: 少算了哪些 kernel, 少读了哪些历史, 少留了哪些状态, 哪类记忆因此变弱.**

**每个新 token 增加多少常驻状态。**

窗口填满以后, 新 token 会覆盖一个旧位置, window cache 的净增长为零. recurrent state 更新原矩阵, 净增长也为零. full attention 层仍为新 token 追加 K/V. 因此混合模型每生成一个 token 的常驻状态增量为:

$$
\Delta M=2\sum_{\ell:m_\ell=F}h_{kv,\ell}d_{h,\ell}. \tag{12}
$$

式 (12)按元素计, 再乘 dtype 字节数与 batch 请求数即可得到内存增长速度. full 层使用 KV 量化时, 元素字节下降; full heads 做 cross-layer sharing 时, 共享组只计一份. window 与 recurrent 层仍占固定基线, 但不进入长时间运行的斜率. 监控曲线的斜率若高于式 (12), 通常还有未裁剪页面、重复 cache 或 snapshot 没有回收.

沿用 $h_{kv}=8,d_h=128$ 的配置, 若模型保留 $8$ 个 full attention 层, 每生成一个 token 增加 $2\times8\times8\times128=16384$ 个 KV 元素. BF16 下等于 $32$ KiB. 单请求从空上下文生成到 $32768$ token, 仅这八层就增加约 $1$ GiB. 若服务同时运行 $16$ 个请求, 每个请求以每秒 $10$ token 生成, 全局 cache 每秒增加约 $5$ MiB. window 与 recurrent 层已经进入稳态时, 这条斜率可以直接从进程显存曲线核对.

prefix 很长、输出很短的服务则由初始存量主导. Prefill 一次性建立八层完整 KV, Decode 只追加少量 token. 长时间聊天与持续日志相反, 初始 prompt 可能很短, 输出不断增长, 式 (12)决定容量何时触顶. 同一模型的并发上限因此还取决于请求长度分布, 只用最大 context length 估算会过度保守或过度乐观.

local/global Transformer 适合仍需高分辨率 token 访问, 同时愿意让部分层承担完整历史的场景. Gemma 2 的交替排布说明 local 与 global attention 可以沿深度组合. 这类模型能直接复用成熟 attention kernel, 状态增长由 global 层决定. 请求长度受控、精确远距召回重要时, 它的工程风险较低.

attention-recurrent 层级 hybrid 把大部分层的状态换成固定矩阵, 少量 attention 层保留精确通路. Olmo Hybrid 的 $R/R/R/F$ 排布与 Jamba 的 Transformer/Mamba 交错都属于这一方向. 长上下文下的 cache 系数明显下降, 服务端需要同时支持 scan、recurrent Decode 与 attention KV. 训练时还要准备能奖励状态更新和精确召回两类行为的数据.

hybrid-head 让每层同时拥有两种记忆, 适合希望低层和高层都能访问 attention 与 recurrent 表示的设计. 它缩短了两类混合器相遇的深度, 每层也要运行两种 kernel. 若 attention heads 占比不低, KV 增长仍然明显; 若占比过低, 精确召回通道可能不足. Hymba 还结合 partial sliding window 与 cross-layer KV sharing, 说明 head 比例只是 cache 设计的一部分.

纯窗口加 sinks 适合允许遗忘远处正文的持续生成. cache 容量与 TPOT 能在窗口填满后稳定, 代价是窗口外非 sink 内容退出可见集合. 日志续写、局部对话和实时流在外部系统另存长期历史时, 这种状态契约很清楚. 任意历史都可能被精确追问的任务则需要 attention 层、检索或外部记忆继续保存可寻址内容.

具体选择取决于任务要求保留原文、最新状态、累计量还是局部关系, 四种需求对应不同的最小状态.

**一组小规模手算怎样暴露路由差异。**

设历史中依次写入三个键值对: $(k_1,v_1)$、$(k_2,v_2)$、$(k_3,v_3)$, 其中 $k_1=(1,0)^\top$, $k_2=(0,1)^\top$, $k_3=(1,0)^\top$, values 分别为标量 2、4、8. full attention 保留三个独立位置. query 若对第一个与第三个位置具有不同位置偏置, 可以在相同内容 key 下仍区分二者;忽略位置时, 两者分数相同, softmax 只能混合 2 与 8.

无衰减线性状态 $S=\sum_i k_iv_i$ 得到 $S=(10,4)^\top$. query $q=(1,0)^\top$ 读出 10, 已无法拆分第一次的 2 与第三次的 8. delta update 取 $\beta=1$ 且 keys 已归一化, 第一次将第一方向写为 2, 第二次将第二方向写为 4, 第三次把第一方向覆盖为 8, 最终 $S=(8,4)^\top$. 若任务语义是「同一变量取最新值」, delta rule 正确;若任务问「第一次写入是什么」, 覆盖正好删除答案.

窗口 $w=2$ 在第三步只保留第二、第三位置. 它能返回最新的 8 与第二键的 4, 第一次写入的 2 已淘汰. 这三个结果没有统一优劣, 因为任务所需记忆动作不同. full attention 保留三条记录, 无衰减状态求和, delta state 覆盖, window 保留最近事件. 评测数据若主要要求最新值, delta 模型会显得很强;换成首次值查询, 排名可能相反.

再加入 hybrid gate. 假设 attention 分支能返回首次值 2, delta 分支返回最新值 8, gate 输出 $\alpha=0.5$, 融合得到 5. 这个值对两个问题都不正确. soft mixture 只有在下游层能从向量通道区分分支时才可能保留两种答案;若两者已经压成同一标量, 平均会摧毁离散语义. 拼接或多维输出比标量凸组合保留更多可分信息.

如果 router 根据 query 类型选择分支, 「first」走 attention, 「latest」走 delta, 两项任务都能答对. router 必须从当前 query 识别操作类型, 训练集中还要包含足够对照. 若只有 latest 样本, attention 分支得不到必要监督;上线出现 first 查询时, 有结构也未必会使用. 这个四步例子把架构容量、融合形式和数据监督分开了.

**长流测试需要哪些可复算指标。**

对每种 recurrent 层, 可定义状态漂移

$$
D_t=\frac{\|S_t^{chunk}-S_t^{step}\|_F}
{\|S_t^{step}\|_F+\epsilon},
$$

其中 $S_t^{chunk}$ 来自训练用 chunk 路径, $S_t^{step}$ 来自逐 token 参考路径. 随 $t$ 画 $D_t$, 能判断差异是稳定在舍入噪声, 线性累积, 还是指数放大. 同时比较 logits 与最终任务结果, 因为 state 有差异不一定改变输出, 小 logit 漂移也可能在接近决策边界处改变采样 token.

窗口层可定义有效集合一致率. 对位置 $t$, 参考集合为 sinks 与 $[t-w+1,t]$ 的并集, runtime 实际页表展开为集合 $C_t$. 检查 $C_t$ 与参考集合完全相等, 比只看 cache 长度更强: 环形指针错一位时长度仍为 $w+s$, 内容已经错误. RoPE 使用逻辑位置, 也要逐项验证物理槽位复用没有改写位置坐标.

混合路由可记录状态维护开销比

$$
\rho_{state}=\frac{C_{maintain}}{C_{executed}},
$$

$C_{executed}$ 是被选分支的算子成本, $C_{maintain}$ 是为未来路线而生成 K/V、更新未读状态或保存快照的成本. 若 $ho_{state}$ 很大, hard routing 省下的主算子可能被状态维护抵消. 这个比值还应拆成计算、容量和写带宽, 因为维护 KV 可能计算不高却持续占用显存.

记忆能力可按距离定义保持曲线. 在距离 $d$ 放置需要保留的信息, 末尾测准确率 $A(d)$. window 模型在 $d$ 跨过窗口时可能出现明显转折;full attention 更可能随位置外推平滑下降;recurrent 模型的曲线受 gate 半衰期和状态干扰影响. 将 $A(d)$ 与累计 gate 保留量、attention 权重及路由选择并排, 才能知道下降来自不可见、未检索还是状态覆盖.

覆盖任务可定义陈旧值错误率. 连续写入同一 key 的 $m$ 个 values, 查询最新值时若返回早期 value, 说明覆盖不彻底;查询指定历史版本时若只能返回最新值, 说明状态只保留当前映射. 两个指标相互牵制, delta rule偏向前者, full token 记录具备支持后者的状态条件. 模型是否学会版本查询仍取决于 key、位置和训练.

流式稳定性需要运行远长于训练长度. 记录每固定步数的 loss/perplexity、state norm、gate 累积对数、NaN 比例、窗口集合一致性和显存斜率. StreamingLLM 一类方法的核心目标包含持续生成稳定, 这与窗口外问答准确率分开报告. 一个模型可以困惑度稳定却忘掉中间事实, 也可以保留某些事实却因位置或数值问题逐渐退化.

**三类反例决定适用边界。**

第一类反例针对窗口传播. 假设第一位置给出一个随机 128-bit 字符串, 中间有大量无关 token, 末尾要求逐字复制. 窗口外信息只能通过后续 hidden 逐层搬运;若模型没有专门学习这种传递, 图上可达不等于能无损保存 128 bits. 少量 full attention 层保留第一位置 K/V, 提供直接读取条件, 仍需 query 正确匹配.

第二类反例针对固定状态. 序列包含超过状态有效容量的大量随机键值, 序列末端随机查询其中任意一个. 所有键值独立且查询直到末尾才确定, 没有可提前丢弃的充分统计量. 固定维有限精度 state 必须让许多关联共享表示, 冲突随集合扩大. 增大 state 或保留 attention 通道能推迟瓶颈, 无法让固定容量无损承载无限随机映射.

第三类反例针对 full attention 的成本合理性. 输入是一个二状态自动机, 每个 token 只要求根据当前符号翻转或保持状态, 序列结束时输出当前位. 保存全部 K/V 并在末尾重新检索所有历史没有必要;一个标量递归状态足够. full attention 可以通过学习实现, 状态与读取成本随长度增长, 与问题最小充分状态不匹配.

还有一类反例针对软融合. 两个分支分别准确表示互斥离散值, 融合层用单标量平均, 得到不存在的中间值. 如果下游任务需要保留两个假设, 应使用拼接、多通道门控或在路由前做明确选择. soft gate 的连续性适合组合可加信息, 不适合所有离散记忆语义.

时间路由的反例是延迟需求. 某 token 当下看起来普通, 很久以后被随机指定为查询目标. 如果当时没有维护 full K/V, 未来 router 再选择 full 也无内容可读. 任何依据当前重要性永久删状态的方法, 都会在对抗性的未来随机查询上失败. 若业务保证查询只涉及特定结构或外部索引可恢复原文, 才能放宽这一边界.

speculative decoding 给不可逆 state 另一个反例. 草稿连续写入十步, 验证只接受一步. 若系统没有 checkpoint 或逆更新日志, 当前 state 混入九个拒绝 token;继续生成会偏离目标模型. attention KV 可以截尾, recurrent matrix 不能假设同样操作成立. 回滚协议是模型服务语义的一部分, 不是附加优化.

**从需求反推混合方式。**

若任务需要任意历史位置的原文级访问, 基础条件是保留某种可寻址状态: full attention 层/heads、外部检索或足以重放的 token 存储. recurrent state 可以辅助汇总, 不能单凭固定矩阵承诺无损随机访问. 若任务只需要最近局部上下文与少量全局控制, window 加 sinks 或固定全局位置更直接.

若任务核心是不断更新的变量、累计统计或有限状态, recurrent mixer能让 Decode 成本与历史长度解耦. 仍要验证状态维度、gate 半衰期与覆盖行为. 在同一工作负载中同时存在局部模式、累计状态和偶发精确检索时, 层级或 head 级 hybrid 提供三种通道, 数据要显式覆盖三类动作.

层级混合的优势是状态所有权清楚, 每层只运行一种主 mixer, kernel 形状较大. 它让两类信息在相邻层之间交换, 交换频率受排布周期限制. head 级混合每层都能同时读取两类记忆, 融合更及时, 每层也要维护两套状态并调度两类计算. 两者应按信息需要多快交汇与系统能否高效执行来选.

时间路由只有在状态承诺可控时才真正省资源. 如果为了未来 full 分支仍要为每个 token 生成完整 KV, 它主要节省当前读取和 attention 计算;如果连 KV 都不生成, 未来路线必须接受不可逆缺失. chunk 路由比 token 路由更容易形成规则执行, 选择粒度也更粗. 路由收益应扣除维护、重排、负载不均和快照.

流式服务还要先确定是否允许遗忘. 允许窗口外正文退出内部状态时, cache 可以固定;不允许遗忘且要求精确回看时, 存储必须随历史增长或移到外部系统;只要求保留压缩语义时, fixed state 合适, 但要用任务验证压缩是否足够. 「无限流式」描述运行时间, 不自动等于无限记忆容量.

训练方案由部署语义反推. 部署采用逐 token recurrence, 训练 chunk scan需代数等价;部署采用 hard routing, 训练应经历相同分支缺失;部署会窗口淘汰, 训练不能一直使用完整历史;部署 state 低精度, 训练或后期适配应暴露相应误差. 训练与推理共享同一状态转移定义, 优化 kernel 可以不同.

模型能力与状态成本应同时写成契约. full 通道保留哪些层或 heads, window 宽度与 sinks 是多少, recurrent state 的 shape 与 dtype, router 控制 update 还是 read, 哪些状态可回滚、共享和释放, 都能由公式和测试验证. 这样的混合架构才有明确边界: 它知道自己保存了什么, 也知道丢掉了什么.

**混合输出的误差如何传到下一层。**

设理想 attention 与 recurrent 输出为 $a$、$r$, 实现误差分别为 $e_a$、$e_r$, gate 为 $\alpha$. 软融合的输出误差是

$$
e_y=\alpha e_a+(1-\alpha)e_r.
$$

若 gate 本身还有误差 $\delta\alpha$, 一阶展开增加

$$
e_y\approx\alpha e_a+(1-\alpha)e_r+
\delta\alpha(a-r).
$$

第三项说明两分支差异越大, gate 的小偏差影响越大. 当两分支相近时 gate 不敏感, 路由也更难学出分工;当两分支承担完全不同功能时, 离散选择错误会带来较大输出变化. router 置信度必须与分支差异一起看.

经过下一层映射 $f$, 扰动近似为 $J_fe_y$. 多层堆叠后由各层 Jacobian 连乘. 残差结构提供恒等通路, 不代表误差不会积累;若 mixer 输出误差与残差同方向, 每层都可能追加偏移. normalization 会重新调整尺度, 仍可能改变方向和相对通道. 长流数值测试需要覆盖完整层表, 单个 mixer 对齐只证明局部实现.

hard routing 的误差不能用小扰动描述. 目标分支为 $a$, router 误选 $r$, 输出跳变量为 $r-a$. 设误选概率为 $p$, 平均平方误差包含

$$
E\|e\|^2=p\|r-a\|^2
$$

这一项. 降低误选率与缩小分支差距都能减少误差, 可缩小分支差距又可能让两条路线同质化. 这形成明确张力: 专业分工越强, 每次错路的代价越大, router 监督就越重要.

top-2 或保底分支能降低错路风险. 例如始终执行 recurrent, 仅在 router 认为需要精确回看时增加 attention. 漏选 attention 会损害少量远距样本, 多选 attention 主要增加成本;这个不对称可通过阈值控制. 相反, 如果 attention 是默认分支、router 决定何时省略, 错误省略直接损害能力. 两种 gate 写法在相同使用率下风险不同.

门控还会改变方差. 假设两分支均值为零, 方差分别为 $\sigma_a^2$、$\sigma_r^2$, 协方差为 $c$. 融合方差为

$$
\operatorname{Var}(y)=\alpha^2\sigma_a^2+(1-\alpha)^2\sigma_r^2
+2\alpha(1-\alpha)c.
$$

若两分支独立且方差相同, $\alpha=0.5$ 会把方差降为单分支的一半;若高度正相关, 方差几乎不降;若负相关, 可能强烈抵消. 融合后的 normalization 可以恢复整体尺度, 不能恢复抵消掉的特定信息方向. 初始化输出投影时要考虑拼接与加权对方差的不同影响.

**容量增加为何不保证长期记忆增加。**

扩大 recurrent state 从 $d_k\times d_v$ 到 $2d_k\times2d_v$, 元素数增加四倍, 理论秩上限也提高. 模型是否利用新增方向取决于 key/value 投影、优化信号和数据. 若所有 keys 仍集中在原低维子空间, 额外维度接近空置;若 gate 过快遗忘, 更大矩阵也无法延长半衰期. 容量、写入几何与保留动力学缺一不可.

增加 full attention heads同样不保证检索提升. 多个 heads 可能学到相似模式, KV heads 又可能共享. 有效多样性可从 attention 分布、输出子空间和消融观察, 不能只数 heads. cross-layer KV sharing 减少状态副本, query 仍可因层而异;若共享 K/V 表示缺少某层需要的特征, 更多 query heads也无法补回.

扩大窗口 $w$ 提高直接可见范围, 训练数据若从未要求使用新增距离, 模型可能保持局部偏好. 位置编码与训练长度也会限制窗口外推. 从 4K 扩到 32K 的运行能力只说明 mask 与 cache 支持该长度, 远端利用需要距离分桶评测. 这也是容量指标和能力指标必须并列的原因.

attention sinks 占用少量固定槽, 作用是维持流式 attention 分布的稳定锚点. 增加 sink 数不等于增加可用长期正文记忆: sinks 保存的是开头若干 token, 中间被淘汰内容仍不可见. 若任务依赖固定系统提示, sinks 可能刚好保留重要内容;依赖任意中段事件时, 需要其他通道.

外部记忆容量可以很大, 检索器召回率与读入上下文预算成为新瓶颈. 内部 full KV 保留每层投影后的状态, 外部系统通常保留文本或单独 embedding;取回后还要重新 Prefill. 两者的「可寻址」含义不同. 混合模型将内部状态压小后依赖外部检索, 应把检索延迟、召回失败和重计算一起纳入成本.

真正的长期记忆需要三个条件同时成立: 信息被写入某个状态, 在漫长转移中没有被不可接受地覆盖或衰减, 查询到来时存在可用读取路径. 写入容量只覆盖第一项. gate 半衰期、状态冲突与路由选择分别约束后两项. 因此扩维、加 heads、扩窗口都要配合对应行为测试, 不能由参数和 cache 字节直接推断能力.

**训练目标怎样塑造分支分工。**

next-token prediction 只通过最终 logits 给混合器信号. 若大部分训练 token 依赖短程局部统计, window 或 recurrent 分支足以降低平均损失, 少量远距精确访问对总梯度贡献很小. 模型即使保留 full attention 通道, 也可能没有学会在稀有场景调用. 增加长程样本的比例、难度和位置随机性, 才能让精确回看对损失产生稳定贡献.

辅助路由损失可以直接监督分支, 前提是标签确实对应记忆动作. 用「距离远」作为 attention 标签过于粗糙: 远处信息可能只需累计统计, 近处也可能需要精确复制. 更合适的标签来自构造任务或教师行为, 区分局部模式、覆盖更新、累计状态和随机地址检索. 没有可靠标签时, 任务损失与成本正则共同学习更稳妥, 可解释分工不一定自然出现.

成本正则可写成期望执行代价

$$
L_{cost}=\lambda\sum_t\sum_m p_t(m)C_m,
$$

$p_t(m)$ 是 router 对模式 $m$ 的概率, $C_m$ 是该模式在当前 shape 下的估计成本. 固定常数 $C_m$ 会忽略 full attention 随历史增长、window 填满后稳定和 recurrent 固定的差异. 更准确的成本随 $t$、batch 和状态维护变化. 若只惩罚分支执行而不惩罚 KV 维护, router 可能看似便宜, 服务端容量仍未下降.

负载均衡损失与成本损失目标不同. 前者避免所有 token 挤到一个分支, 有利于并行利用率;后者偏向低成本路径. 强行均衡会让昂贵分支达到预设使用率, 即使任务不需要;过强成本惩罚又会让 router 回避 full attention. 两个系数应通过质量-成本曲线选择, 不能只看训练 loss.

蒸馏能提供更密集信号. 以全 attention teacher 的 hidden 或 logits 为目标, hybrid student 学习在有限状态下逼近. 这会教 student 保留 teacher 常用信息, teacher 本身未必具有理想状态更新. 对覆盖、计数等 fixed-state 擅长任务, 直接任务监督可能比模仿 full attention 更合适. 蒸馏目标与结构归纳偏置需要共同评估.

课程长度会改变优化难度. 直接在极长序列上训练, recurrent 梯度跨越很多步, 稀有远距信号更弱;从短到长逐步增加距离, 模型先学写入和读取, 再学习长期保留. 课程也可能让模型过度依赖早期短窗口策略, 延长后不主动使用新增容量. 每个长度阶段都应保留跨全范围采样, 避免只见单一距离.

训练数据中的文档边界必须与 state reset 一致. packing 提高 token 利用率, 边界错误会让模型学习跨文档使用无关状态, loss 甚至可能因重复模板而下降. attention block mask、window 环形状态和 recurrent reset 要共享同一边界元数据. 训练正确性先于吞吐优化, 因为边界泄漏会直接改变模型定义.

损失落点也会影响长期信号. 若只对答案末尾少量 token 计算 loss, 从早期写入到答案的梯度路径很长, router 与 gate 得到的监督稀疏. 在中间插入状态查询、覆盖确认或局部预测, 可以缩短部分信用分配路径, 但会改变数据分布. 更稳妥的做法是同时保留自然 next-token loss 与针对记忆动作的辅助样本, 并分别报告两部分曲线.

混合比例搜索应控制总参数与训练计算. 增加 recurrent state 维度同时减少 attention heads, 参数量、FLOPs 和优化难度都发生变化;直接比较最终分数无法归因. 一组消融可以先固定总 hidden width, 只改变通道分配, 再固定状态字节比较不同表示, 随后固定训练 FLOPs 比较收敛. 三个控制口径回答的问题不同.

训练长度分布还决定 full attention 的使用价格. 短序列上 full 分支成本与 recurrent 接近时, 成本正则难以教会模型为长序列节省;只在极长序列上训练又会压低 batch 和数据多样性. 混合长度训练需要让成本项按当前长度计算, router 才能学到同一动作在不同历史长度下代价不同.

部署阈值不应脱离训练分布单独调到极端. 为追求吞吐把 attention 使用率从训练时的 20% 压到 2%, 相当于改变模型计算图. 合理阈值位于质量-成本曲线上, 并在长度、任务类型和并发条件变化时重新验证. 若要显著降低使用率, 继续训练或蒸馏通常比直接改阈值可靠.
