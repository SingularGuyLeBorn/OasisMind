## 1. 底座与训练流水线

### 1.1. 底座借来, 篇幅全给后训练

百川医学线到 M3 是第三代. [M1](../m1-14b/m1-14b.md) 是 14B 稠密模型, 在 20T token 上从零训练, 医学能力从预训练配比开始积累, 架构上还为长上下文推理改了注意力. [M2](../m2-32b/m2-32b.md) 换成借底座的路线: 以 Qwen2.5-32B-Base 为起点, 做一段 2:2:1 配比的 mid-training, 接约 200 万条 SFT, 再用改进版 GRPO 做三阶段 RL, 报告的重心在患者模拟器和 rubric 生成器这两个 「验证器」. 到了 M3, 参数量跳到 235B, 结构变成 MoE, 报告几乎全部篇幅都在讲后训练.

论文正文对底座只字未提, 能确认的只有 §5.2 里的 「Mixture-of-Experts」 和模型名里的 235B. 外部信息补上了这一块: Hugging Face 模型卡的 `base_model` 字段写的是 Qwen/Qwen3-235B-A22B, README 写着 「基础模型: Qwen3, 训练框架: verl」, 权重为 BF16, 共 235,093,634,560 个参数 (外部). 对照 Qwen3-235B-A22B 的官方模型卡, 这个底座有 94 层, 注意力是 GQA (64 个 Q 头, 4 个 KV 头), 共 128 个专家, 每个 token 激活 8 个, 激活参数约 22B, 原生上下文 32,768, 用 YaRN 扩到 131,072 (外部). 所以 **M3 的架构, 分词器和预训练语料全部继承自 Qwen3**, 论文里没有任何预训练数据配比, 训练日程或 mid-training 的描述. 流水线第一段说的 「shared initialization」 具体是 Qwen3 原始权重, 还是先做过医学 SFT 的中间模型, 本页也没有交代; 附录 A.1 的 SPAR 消融写的是 「Baichuan-M3 base model (before RL)」, 同样没有定义.

底座形状会一路影响后面的选择. MoE 每个 token 只走 8/128 的专家, 单 token 计算量接近一个 20B 出头的稠密模型 (估算), 但显存要装下全部 235B 参数. 这带来三处连锁反应: RL 时新旧策略的专家路由会漂移, token 级重要性比率跟着抖, 于是策略更新改用 GSPO 式的序列级比率; 量化时普通校准语料只激活一部分专家, 冷门专家的误差更大, 于是有了自生成校准; 部署硬件从 M2 的单张 RTX 4090 换成数据中心的 NVIDIA H20. MoE 的一般机制见 [MoE](../../../../llm-guide/2-核心原理与架构/2.4-前沿架构与变体/2.4.1-混合专家模型MoE/2.4.1-混合专家模型MoE.md).

三代放在一起看, 投入方向的迁移很清楚. M1 把功夫花在 「预训练里放多少医学数据」, M2 挪到 「后训练里怎么给奖励」, M3 延续 M2 并把奖励侧拆得更细. 评测对象也在变: M1 的对照组是通用底座和医学考试题, M2 把 HealthBench 放在首位, M3 自建了 OSCE 风格的 ScanBench, 又单列了幻觉评测 HealthBench-Hallu. 三代评的东西, 从 「知道多少医学知识」 走到 「能不能按临床流程把信息问全, 再给出不胡编的结论」.

### 1.2. 三段训练流水线: 分头训专家, 压进一个学生, 再在线合并

§1 把难点归成三个: 不同临床任务的训练环境差异大, 多任务融合不稳定; 长程对话里终局奖励说不清是哪一轮起了作用; 奖励接近饱和时学习信号变弱, 模型为了满足复杂约束开始编内容. 三段流水线回答的是第一个. 第一段 **TaskRL** 从共享初始化出发, 为不同能力各开一条独立的 RL 管线, 分别训出临床问诊专家, 健康咨询专家, 以及负责指令跟随和通用推理的通用专家. 思路引自 Generalist++ [34] 的 「先分化后统一」: 让每个任务在自己的奖励下充分探索, 避开多任务混训初期的梯度干扰, 得到归纳偏置各不相同的教师.

第二段冻结全部教师, 让它们在各自领域 rollout, 构成离线轨迹集 D, 学生以 off-policy 方式学习. 目标函数是式 (2) 的 **Clip Forward-KL**:

$$
\mathcal{L}_{\text{clip-FKL}}(\theta) = \mathbb{E}_{(s,a)\sim\mathcal{D}}\Big[\mathbb{I}\big(\log\pi_\theta(a\mid s) < \log\pi_t(a\mid s)\big)\cdot\big(-\log\pi_\theta(a\mid s)\big)\Big],
$$

$\pi_t$ 是教师. 这个截断的来由要从单样本前向 KL 说起. 离线数据里每个状态只有教师采出的一个动作 $a$, 此时前向 KL 退化成普通的交叉熵 $-\log\pi_\theta(a\mid s)$, 它对 $a$ 的 logit 的梯度是 $-(1-\pi_\theta(a\mid s))$, 只要学生概率不到 1 就一直推. 设教师在这个 token 上只给 0.3: 学生为 0.2 时指示函数为 1, 照常按交叉熵更新; 学生升到 0.35 后指示函数变成 0, 这个样本不再产生梯度, 而交叉熵还会继续把 0.35 往 1 推. 截断之后, 学生追上教师的概率就停手, 论文称之为 「只在教师的经验支撑上保证不劣于教师」. 支撑之外的概率质量不被挤压, 熵得以保留, 为第三段的 mode-seeking 优化留出探索余地; 前向 KL 本身 mode-covering 的性质, 又让学生能覆盖几位专家的高概率区域.

附录 A.3 的消融把这一点量化了. 实验里学生从问诊专家初始化, 通过离线蒸馏吸收健康咨询专家, 两组只换目标函数. 标准 Forward-KL 的 ScanBench, HealthBench, HealthBench-Hard 为 73.7, 58.6, 33.2, Clip Forward-KL 为 73.5, 61.1, 38.5. 问诊能力基本持平, 新吸收的咨询能力涨了 2.5 分, Hard 子集涨了 5.3 分. 论文的解读是: 标准前向 KL 在稀疏的离线样本上放大概率, 伤的是 「装进新能力」, 而不是 「保住旧能力」. 这组消融只涉及两位专家, 通用专家的数据没有参与, 三位教师同时蒸馏时截断的效果如何, 本页没有给.

第三段是多教师在线蒸馏 **MOPD**, 直接引自小米 MiMo-V2-Flash [35], 反向 KL 正则的写法来自 Thinking Machines Lab 的 On-Policy Distillation [36]. 学生回到在线环境, 在混合领域上自己 rollout, 同时受真实任务奖励和多位教师先验约束. 反向 KL 在学生自己的样本上计算, 学生把概率放到教师认为不可能的地方就会被重罚, 因此它倾向于挑一个峰值集中下注. 几位教师意见冲突时, 学生会选定一个模式, 不去取平均. 从离线前向 KL 切到在线反向 KL, 正是 OPD 文献里 mode-covering 与 mode-seeking 的分工: **先铺开覆盖, 再收拢决策**. 多位教师如何分配到不同样本, 任务奖励和 KL 项的权重, 本页都没有写.

论文还说这条流水线可以循环: MOPD 得到的统一模型可以作为第一段的新初始化, 再训更强的专家, 再蒸馏一轮. 三段拆开的好处是每段只解决一个可控的子问题: 第一段只管单领域能不能训到顶, 第二段只管几位教师的分布能不能装进同一个学生而不塌缩, 第三段才处理领域之间的真实冲突. 代价是每轮迭代都要重训若干位教师. 报告没有给这部分算力, 也没有和 「同等算力下直接混训」 的方案做对照; 第一段专门训了通用专家, 全文却没有任何通用基准读数, **医学强化是否以通用能力为代价, 从本页看不出来**. 相关原理见 [知识蒸馏](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.3-知识蒸馏/6.3.3-知识蒸馏.md), [OPD 基础原理](../../../../llm-guide/4-后训练/4.6-OPD/01-OPD基础原理/01-OPD基础原理.md), [GOPD 散度光谱](../../../../llm-guide/4-后训练/4.6-OPD/05-GOPD-散度光谱/05-GOPD-散度光谱.md) 与 [MOPD 多教师在线蒸馏](../../../../llm-guide/4-后训练/4.6-OPD/09-MOPD-多教师在线蒸馏/09-MOPD-多教师在线蒸馏.md).

## 2. 问诊 RL

### 2.1. 问诊环境: 被动患者, 插话脚本, 不对称可见

问诊训练的环境继承自 M2. M2 的患者模拟器由终止门, 情感单元和事实单元组成, 情感单元按 MBTI 和社会背景扮演不同性格的患者. M3 在 §2.1 说, 部署中发现模拟 「主动型」 患者时不稳定: 主动行为会打乱问诊节奏, 让模拟难以复现. 于是改用被动人格的模拟器, 配两种脚本模式. 被动交互模式占 75% 的采样概率, 只给患者档案, 问诊 rubric 和行为约束 rubric, 没有预置对话, 模拟初诊的开场, 考的是在高度不确定时主动问出关键信息, 形成初步假设的能力. 插话模式占 25%, 在基本信息之外预置一段对话片段, 片段以患者提问收尾, 通常是对病情轻重或治疗的焦虑.

插话片段有一个细节: **它只对医生 agent 可见, 对模拟器隐藏**. 片段如果暴露给模拟器, 模拟器会模仿片段的说话风格, 偏离被动应答的协议. 为了缩小模拟环境和线上真实问诊的分布差, 插话模式内部再分两半: 50% 是轮末提问, 患者问题只出现在片段最后, 考突然打断; 另外 50% 是轮中提问, 问题插在一轮对话中间, 模拟多轮纠缠. 两代对比能看到一个取舍: M2 追求患者行为的多样性, **M3 为了长程训练可复现, 主动收窄了随机性**, 再用脚本把 「打断, 质疑, 焦虑追问」 这类噪声有控制地加回来. 患者档案有多少份, 病例从哪里来, 问诊 rubric 怎么生成, 本页都没有给数字.

### 2.2. 分段流水线 RL: 一次问诊拆成四段, 每段各有奖励

长程问诊的信用分配难题, 附录 A.1 的消融给了直观的样子. 四个指标都归一化到 [0, 1], 其中 Repeat Score (越高越不重复) 和 Logical Score 由 GPT-5 按 0/1/2 三档给对话日志打分再归一化. 只用终局全局奖励的 GRPO 让 Rubrics Score 从约 0.47 升到约 0.67, Repeat Score 却从约 0.99 掉到约 0.63 (读图): **模型学会了靠重复追问刷召回**. 加一个全局重复惩罚, Repeat 回到约 0.90, Logical Score 却跌到约 0.28 (读图), 对话逻辑碎掉了. 终局奖励只知道整场问诊好不好, 说不清是哪一轮问得好, 哪一轮问得多余, 粗粒度的全局惩罚又会连带罚掉正常的推理链.

M3 的第一步回答是**分段流水线 RL**. 一次问诊写成 K=4 段的生成过程, 阶段类型 S={Inq, DDX, Lab, Diag}, 对应问诊, 鉴别诊断, 开检查, 下诊断. 式 (3) 到式 (6) 是

$$
y_k^{(i)} \sim \pi_\theta(\cdot\mid x_k^{(i)}),\qquad
\mathcal{J}(\theta) = \frac{1}{|\mathcal{B}_t|}\sum_{x_k^{(i)}\in\mathcal{B}_t}\mathcal{L}_{\text{RL}}\big(y_k^{(i)},\ \mathcal{G}_k^{(i)}\big),
$$

$$
x_{k+1}^{(i)} = [\,x_k^{(i)},\ y_k^{(i)},\ p_{k+1}\,],\qquad
\mathcal{D}_{k+1} \leftarrow
\begin{cases}
\mathcal{D}_{k+1}\cup\{x_{k+1}^{(i)}\}, & \mathcal{V}_k^{(i)} \ge \tau \\
\mathcal{D}_{k+1}, & \text{丢弃}
\end{cases}
$$

第 $k$ 段的输入 $x_k^{(i)}$ 包含病例 $i$ 此前的全部对话历史, 再加上当前阶段的指令, 例如 「Based on the above, suggest lab tests」. 联合目标对每个上下文用该阶段专属的奖励函数 $\mathcal{G}_k$ 计算 RL 损失, 于是 「收集信息」 和 「推理下结论」 这两类不同的能力被放进同一个生成模型. 训练采用异步多任务流水线: 在任一全局步, 多个任务槽并行跑在不同阶段, 甚至不同病例上, 这些阶段任务的并集构成训练 batch $\mathcal{B}_t$, 所以同一个 batch 里的样本可能分别在用 Inq 和 Diag 的奖励算损失.

段与段之间把上一段的生成 $y_k$ 和下一段指令 $p_{k+1}$ 接到上下文后面. 开放式生成有错误传播的风险, 所以加了**质量门控**: 第 $k$ 段的质量验证器给出分数 $\mathcal{V}_k$, 只有不低于阈值 $\tau$ 的轨迹才进入下一段的训练池 $\mathcal{D}_{k+1}$, 其余丢弃. 按式子的写法, 被丢弃的轨迹在第 $k$ 段照样按 $\mathcal{G}_k$ 参与更新, 只是不再往后延伸 (推断, 论文没单独说明). 这是一条显式课程: 后段总在逻辑链合格的上下文上学习, 错误路径在进入下一段之前就被剪掉. 阈值 τ 的取值, 各阶段奖励的具体 rubric, 各阶段样本在 batch 里的占比, 本页都没有公开. 分阶段建模在医学对话里有前例, 例如用分层 RL 做自动诊断对话的 [38], 以及百川团队此前把医生诊断逻辑写进过程反馈的 [39].

四段结构和第 4.1 节的 ScanBench 三站几乎一一对应: Inq 对问诊站, DDX 和 Lab 对检验站 (该站要求先给鉴别诊断再选检查), Diag 对诊断站. 训练环境和评测协议同构, 好处是训练信号直接对准要考的东西, 坏处是 **ScanBench 上的领先有一部分来自 「考纲一致」**, 外部可比性要靠 HealthBench 这类第三方基准来补.

### 2.3. SPAR: 步级惩罚乘进全局奖励, 基线用未罚的组统计

第二步是 **SPAR** (Step-Penalized Advantage with Relative baseline, §3.1.2). 一条回答由 L 个交互步组成, 每步是一轮完整的 「用户一句, 助手一句」. 先按临床 rubric (诊断准确性, 证据完整性等) 给整条轨迹打全局分 R_global; 同时由步级验证器逐步检查违规类型, 比如冗余, 安全风险. 式 (7) 和式 (8) 是

$$
\gamma_j =
\begin{cases}
1, & \mathbb{V}_j = \varnothing \\
\min_{v\in\mathbb{V}_j}\lambda_v, & \text{其他}
\end{cases}
\qquad
\hat A_j = \frac{\gamma_j R_{\text{global}} - \mu_{\text{raw}}}{\sigma_{\text{raw}} + \epsilon},
$$

$\mathbb{V}_j$ 是第 $j$ 步触发的违规类型集合, $\lambda_v\in(0,1)$ 是类型 $v$ 的惩罚系数. 一步犯了多个错只按最重的罚 (最小的 $\lambda$), 这一步的有效回报是 $\gamma_j R_{\text{global}}$. 优势的分母和减数 $\mu_{\text{raw}}, \sigma_{\text{raw}}$ 是同一问诊上下文下多条 rollout 的原始全局分的均值和标准差, 不含任何步级惩罚. **惩罚只压低出错那一步的回报, 不去改动组基线**, 同一条轨迹里的不同步因此拿到不同的优势, 信用精确落到犯错的那一轮. 论文对比的 「传统做法」 是用惩罚后的回报算组统计; 两者差在同一个减数上: 若全组 rollout 都在某一步犯了同一种冗余, 惩罚后的均值跟着一起降, 那一步的优势回到零附近, 惩罚被基线吸收掉; 用未罚的 $\mu_{\text{raw}}$ 时, 那一步的优势仍是 $(\lambda R_{\text{global}} - \mu_{\text{raw}})/\sigma_{\text{raw}}$, 照样为负. 用一组假设数字看它怎么形成隐式课程 (以下数字为示意, 非论文数据). 训练前期, 设组内原始分均值 0.6, 标准差 0.2, 某条轨迹全局分 0.8: 没违规的步优势为 +1.0; 某步重复提问, λ=0.1, 回报变成 0.08, 优势约 −2.6; 某步措辞生硬, λ=0.9, 回报 0.72, 优势 +0.6, 仍然是正的, 轻微瑕疵被全局分的方差淹没. 训练后期, 组内分数趋同, 设均值 0.8, 标准差 0.05, 同样全局分 0.8 的轨迹里, λ=0.9 的那步回报 0.72, 优势变成 −1.6, 轻微瑕疵开始主导梯度. 论文把前者叫 「纠正严重错误」 阶段, 后者叫 「打磨细节」 阶段, **切换时点不需要人工设定, 由 σ_raw 的自然收缩决定**.

这里有一个和 [Dr. GRPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.6-其他策略梯度/03-DrGRPO-去标准差/03-DrGRPO-去标准差.md) 相反的设计选择. Dr. GRPO 认为组内除以标准差会让难度过低或过高的题获得过大权重, 主张去掉; **SPAR 恰恰利用这个除法**, 让轻微惩罚在方差变小后自动放大. 两者并不矛盾: Dr. GRPO 讨论的是题与题之间的权重偏差, SPAR 利用的是同一题在训练进程中的方差变化. 更新时 SPAR 用 GSPO [42] 式的策略目标, 以步级优势加权似然比. GSPO 由 Qwen 团队提出, 把 token 级重要性比率换成整段序列似然比的几何平均, 按序列裁剪:

$$
r_t^{\text{token}} = \frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t\mid x,y_{<t})}
\quad\longrightarrow\quad
s(\theta) = \left(\frac{\pi_\theta(y\mid x)}{\pi_{\theta_{\text{old}}}(y\mid x)}\right)^{1/|y|} = \exp\Big(\frac{1}{|y|}\sum_{t}\log r_t^{\text{token}}\Big).
$$

同一段回答里, 前者每个 token 各裁各的, 某个 token 因专家路由改变而比率跳到 3, 这一个 token 就被单独裁掉或放大; 后者先在对数域取平均, 个别 token 的跳变被摊薄, 整段只有一个比率, 要么整段在裁剪区间内, 要么整段被裁. 这样设计的动机之一正是 MoE 训练中新旧策略路由不同导致 token 级比率剧烈波动; 在 Qwen3 的 MoE 底座上沿用它, 顺理成章. 本页没有写明比率是在整条轨迹上取, 还是在单个交互步的片段上取, 也没有给 ε 和各违规类型的完整 λ 表. 基本写法见 [GRPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md) 与 [GSPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/03-GSPO/03-GSPO.md); 百川团队的 DCPO [40] 也在引用里, 说明团队在裁剪与归一化上有连续积累.

分段流水线和 SPAR 合起来, **相当于把课程学习 [43] 嵌进在线 RL**: 流水线是显式课程, 前一段不合格的轨迹进不了后一段; SPAR 是隐式课程, 同一套奖励公式随着组内分数趋同, 自动把注意力从 「别犯大错」 挪到 「把细节做好」. 图 11 的终点读数里, SPAR 的 Rubrics Score 约 0.76, Repeat Score 约 0.95, 平均轮次约 20.4, GRPO 约 21.7 轮 (读图), 轮次相近, 说明分段奖励没有靠缩短对话来减少重复. 图 6 按对话轮次画分数 (样本占比不足 10% 的轮次区间已剔除): 症状澄清一项各模型很快都到 0.7–0.8; 联想追问一项 M3 随轮次继续上升, DeepSeek, Qwen 等通用模型落后, 长对话处差距接近两倍; 安全分层一项 M3 随证据积累升到约 0.7, GPT-5.2-High 停在约 0.5. 这些是正文给出的近似值, 训练目标在曲线上留下的痕迹相当清楚.

## 3. 咨询 RL: 动态 rubric 与事实核查

### 3.1. 动态 rubric: 奖励跟着策略暴露的漏洞一起变

Rubric 一路是 M2 的直接延续, §2.2.1 说沿用了 M2 引入的 rubric 验证范式, 上游是 Rubrics as Rewards [26] 与 Rubric Anchors [25]: 把回答质量拆成一组可以逐条判定的条款, LLM 裁判逐条给 0 或 1, 再聚合成标量奖励. 式 (1) 给每条条款一个 [-10, 10] 的有符号整数权重, 正数是奖励, 负数是扣分, 裁判对每条输出 $a_i\in\{0,1\}$ (是否满足或触发), 聚合方式为

$$
R_{\text{task}} = \frac{\sum_{i=1}^{N} w_i a_i - \sum_{i:\,w_i<0} w_i}{\sum_{i=1}^{N}|w_i|}.
$$

所有正向条款满足, 负向条款一个没触发时得 1; 反过来得 0. 代一组数: 三条条款权重为 8, 5, −6, 回答满足第一条, 没满足第二条, 触发了第三条的负向行为, 分子是 $(8 + 0 - 6) - (-6) = 8$, 分母 19, 得 0.42; 若没触发第三条, 分子变成 14, 得 0.74. 负向条款没触发时贡献的是 $|w_i|$, 触发时贡献 0, 所以它和正向条款一样, 都是 「做对了拿满分, 做错了拿零」, 只是 「做对」 的定义相反. 这个 min-max 归一化让奖励尺度和条款数量, 权重大小脱钩, 不同样本之间可比, 整数权重又能直接表达条款的相对重要性. 工程上, 策略一吐出回答就立刻发起裁判任务, 与计算 π_ref, π_old 的对数概率等互不冲突的步骤重叠执行; 裁判 prompt 采用前缀亲和设计, 系统约束, 输出格式和对话上下文共用同一模板前缀, 只把后缀换成不同条款, 再做 micro-batch, 最大化 KV cache 复用.

§3.2.1 直接点名了 M2 的毛病: 基于 rubric 的 RL 容易被 hack, 表现为被动冗长, 防御性模板和编造细节. **根因是 M2 的 rubric 只依据问题生成**, 问题固定后 rubric 就是静态的, 结构可以预测, 模型很容易钻空子. M2 当时的对策是条件长度奖励, 只在回答质量排进组内前列时才惩罚长度. M3 把条款分成两类: **核心 rubric** 只看问题, 负责大方向和安全底线; **动态 rubric** 同时看问题和模型的历史回答, 专门约束训练中暴露出来的违规模式. 来源是 DR Tulu [44] 的 「evolving rubrics」 和 Chasing the Tail [45] 对高分尾部的关注.

动态集合靠两套机制维护. 质量控制走 「挖掘, 核验, 注入」 的闭环: 先找高置信样本, 即在当前体系下得分很高却有潜在缺陷的回答; 由 Rubric Mining Agent 分析这些样本, 归纳对抗模式, 起草候选约束; 最后人类专家审核, 看边界是否确定, 是否符合元原则 (例如 Safety > Empiricism). **专家只审不写**, 目的是让新条款真正奖励推理, 而不是把 hack 的落点挪个地方. 准入与退出规则防止条款爆炸: 候选条款光 「正确」 不够, 只有针对统计上显著的失败模式 (违规率高) 才激活; 某条约束连续多个 epoch 违规率趋近 0, 就自动退役, 免得冗余的正向奖励稀释信号. 与 M2 相比, 反馈信号从 「一次性生成, 全程不变」 变成 「随策略一起演化」. 动态集合的规模, 准入的违规率阈值, 参与审核的专家人数, 本页都没有给; 训练和评测用的 prompt 放在 GitHub 仓库的 prompts 目录里.

### 3.2. 事实感知 RL: 拆成论断, 检索核查, 按任务分开闸

事实核查一路是 M3 新加的. §2.2.2 给的动机很具体: M2 在常见 rubric 条款上趋于饱和后, 模型靠补充罕见临床细节换取边际得分, 幻觉风险随之上升. **Fact Verifier** 沿着 FActScore [29] 与 SAFE [30] 这条长文本事实性评估的路子走, 分两步. 第一步把长回答拆成原子论断, 规则有三条: 复合句拆成单一事实并消解代词, 保证每条脱离原文仍可核查; 丢弃缺上下文的碎片, 选择题里复述的错误选项不算论断, 免得被误判成幻觉; 语义去重但保留推理顺序. 第二步把论断交给检索增强的核查 agent, 它在临床指南等权威来源上迭代检索, 自己判断证据是否足够, 最后给每条论断打 Supported, Refuted 或 Uncertain. 相比只靠模型参数知识或静态知识库, 在线检索能跟上临床证据的更新. M3 与 FActScore, SAFE 的差别, 在于把这套评估搬进了在线 RL 的奖励回路.

搬进奖励回路后, 吞吐成了头号问题. GPT-5 做抽取质量高, 但延迟撑不住在线 RL, 于是从 GPT-5 蒸馏出小模型. 附录表 3 以 GPT-5 为参照: 未微调的 Qwen3-8B 召回 30.45%, 平均每条回答只抽出 8.50 条论断; Qwen3-32B 召回 37.68%; SFT 后的 A3B-30B, 8B, 32B 召回分别为 69.69%, 72.80%, 73.00%, 论断数都在 47 条上下. 32B 只比 8B 多 0.2 个点, 部署成本却高得多, 最终选了 SFT-8B. 检索侧做了两级缓存, 依据是同一问题的多条采样措辞不同, 底层论断高度重合: 一级用 Redis 做字符串精确匹配, 毫秒级命中; 二级把历史论断的 embedding 存进向量库, 用 ANN 找语义等价的论断复用结论. 随着缓存池变大, 命中率从初期不到 40% 升到约 80%, 外部检索请求减少约 85%. 语义缓存有系统偏差, 比如剂量略有差别的两条论断可能被当成等价, 论文把这类噪声交给下面的去噪机制兜底.

有了核查结果, 最朴素的做法是式 (9): $R = R_{\mathrm{task}} + \alpha \cdot R_{\mathrm{hallu}}$, 其中 R_hallu 是按条数算的幻觉率取负. 论文指出它在长文本生成里会被两种方式 hack. 一是**稀释**: 模型多写正确但没用的废话, 把分母撑大, 幻觉率下降, 核心错误却没改. 二是**保守**: 惩罚太严时模型干脆少写, 探索和复杂推理都受压. 对付稀释的是**结构化去噪**. 先用语义编码器把回答的各句和抽出的论断映射到向量空间, 按余弦相似度阈值聚类, 每簇选一条代表论断, 同义改写的重复论断因此只算一次. 再给每条代表论断一个显著性权重, 按权重加权计算惩罚. 式 (10) 到式 (12) 是

$$
w(c_k^*) = \max_{1\le j\le M}\cos\big(\mathcal{E}_{c_k^*},\ \mathcal{E}_{s_j}\big),\qquad
R_{\text{fact}} = -\frac{\sum_{k=1}^{K} w(c_k^*)\,\mathbb{I}(c_k^*)}{\sum_{k=1}^{K} w(c_k^*) + \epsilon},\qquad
\mathbb{I}(c_k^*) = \mathbb{1}\big[c_k^* \in \{\text{Refuted},\text{Uncertain}\}\big],
$$

$K$ 是聚类后的代表论断数, $M$ 是回答的句数. 和式 (9) 的计数版 $-N_{\text{hallu}}/N_{\text{total}}$ 比, 差在两处. 其一是 $K$ 取代了 $N_{\text{total}}$: 一条错误论断配 9 条正确论断, 计数版是 −0.1; 再把那 9 条各改写一遍追加进去, 计数版降到约 −0.053, 聚类后同义改写并回原簇, $K$ 仍是 10, 仍是 −0.1. 其二是权重: 论文说加权分母抵消了论断数量膨胀, 显著性加权的分子让核心诊断语句里的幻觉比边角内容罚得更重. 按式 (10) 的字面, 每条论断都是从回答里某一句抽出来的, 和自己的出处句本就高度相似, 权重的差异只来自抽取时的改写 (拆句, 消代词) 和编码器; 如果模型追加的是不重复的新废话, 它们的权重同样接近 1, 分母照样变大 (推断). 所以挡住 「稀释」 的主力是语义聚类, 对 「写新的无用内容」 能挡多少取决于权重的实际分布, 论文没有给. 聚类阈值的具体取值, 本页也没有给.

对付保守的是式 (13) 的**软门控**. 门控系数 $\lambda(R_{\mathrm{task}}) = \sigma(\kappa \cdot (R_{\mathrm{task}} - \mu)/\Delta)$, 中心 $\mu = (\tau_{\min} + \tau_{\max})/2$, 尺度 $\Delta = \tau_{\max} - \tau_{\min}$, κ=10, τ_min=0.75, τ_max=0.95. 代入可得 μ=0.85, Δ=0.2: 任务分 0.75 时 λ 约 0.007, 0.85 时为 0.5, 0.95 时约 0.993 (估算). 于是任务分低于 0.75 属于保护区, 几乎不罚幻觉, 先让模型把推理能力练起来; 0.75 到 0.95 是过渡区, 惩罚非线性加码; 高于 0.95 进入约束区, 惩罚完全生效. 最终奖励为式 (14) 的 $R = R_{\mathrm{task}} + \lambda(R_{\mathrm{task}}) \cdot R_{\mathrm{fact}}$.

门控让总奖励对任务分的斜率不再恒为 1. 对 $R_{\text{task}}$ 求导,

$$
\frac{\partial R}{\partial R_{\text{task}}} = 1 + \lambda'(R_{\text{task}})\,R_{\text{fact}},\qquad
\lambda' = \frac{\kappa}{\Delta}\,\lambda(1-\lambda) \le \frac{10}{0.2}\times\frac14 = 12.5 ,
$$

最大值出在 $R_{\text{task}} = 0.85$. 当 $R_{\text{fact}} < -1/12.5 = -0.08$, 即加权幻觉比例超过 8% 时, 这一点附近斜率为负: 幻觉比例相同的两条回答, 任务分高的那条总奖励反而更低 (估算). 代入 $R_{\text{fact}} = -0.1$: 任务分 0.85 时总奖励 $0.85 - 0.05 = 0.80$, 0.88 时 $\lambda \approx 0.82$, 总奖励约 0.798. 过渡区里, 幻觉多的回答提高任务分拿不到回报, 只有先压幻觉才涨分, 这正是门控想要的方向; 论文没有讨论这个非单调区间. 这和 M2 的条件长度奖励是同一种精神: 先保质量, 质量达标后再收紧另一个维度, 区别在于 M2 收紧的是长度, M3 收紧的是事实性. 注意这里的 λ 与第 2.3 节 SPAR 的惩罚系数 λ_v 同名不同义.

附录 A.2.2 从同一个中间 SFT checkpoint 出发比了三种设置. 只优化任务奖励的一组 HealthBench 分数最高 (约 0.68), 幻觉率却一路漂到 0.08; 用式 (9) 静态惩罚的一组压住了漂移, 推理分明显下滑, 典型的惩罚诱发保守; M3 的去噪加重加权方案把幻觉率降到约 0.035, 推理分守在约 0.665, 接近起点 (以上是正文给出的近似值). 表 2 给了成品模型的对照: GPT-5.2-High HealthBench 63.3, Refuted 率 2.37%, Uncertain 率 2.78%; Baichuan-M2-32B 为 60.1, 5.73%, 5.43%; 去掉事实感知 RL 的 M3 为 66.2, 4.68%, 3.64%; 完整的 M3 为 65.1, 2.45%, 2.07%. 付出 1.1 分的 HealthBench, Refuted 率降了约 48%, Uncertain 率降了约 43% (估算), 论文概括为 「约 50%」. M3 的 Refuted 率仍略高于 GPT-5.2-High, Uncertain 率则更低. 奖励模型被过度优化的一般风险可对照 [Best-of-N 与奖励模型过优化](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.4-其他对齐技术/07-Best-of-N-奖励模型过优化/07-Best-of-N-奖励模型过优化.md), RLVR 在奖励饱和后的局限见 [RLVR 的局限性与探索边界分析](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.3-RLVR的局限性与探索边界分析.md).

图 9 用知识探针拆解剩余幻觉的来源, 比较模型内部认知 (参数里的判断) 与外部输出 (生成的论断) 是否一致. Supported 论断的一致率保持在 88.3%; Refuted 论断的一致率从约 39.7% (读图) 升到 44.9%. 对错误论断来说, 「一致」 意味着模型内部就记错了, 属于诚实错误; 一致率上升, 说明 「内部知道对的却说出错的」 这类不忠实幻觉在减少. 论文据此认为**事实感知 RL 的主要作用是约束生成策略**, 让输出收敛在模型真实的知识边界内, 并没有注入新知识. 这个结论和评测工具有一层耦合: 训练奖励和幻觉评测共用同一套核查管线, **评测本身不完全独立于训练信号**.

## 4. 评测, 部署与家族位置

### 4.1. 评测协议: 三套基准各测流程的哪一段

对照组分四类: 通用推理模型 GPT-5.2-High, DeepSeek-V3.2-Thinking, Qwen3-235B-thinking-2507; 医学专用模型 AntAngelMed; 上一代 Baichuan-M2; 以及人类基线, 由三甲医院临床经验至少 5 年的主治医师组成. 其中 Qwen3-235B-thinking-2507 与 M3 同出 Qwen3 的 235B MoE 家族 (外部), 是最接近 「底座自己能做到多少」 的参照, 虽然它是 2507 版的思考模型, 与 M3 的底座版本并不完全相同. 所有读数都是单次生成加裁判打分, 没有投票和加长推理预算.

ScanBench 是 M3 自建的 OSCE 风格基准, 谱系上接 Google AMIE [18, 19] 这类模拟问诊评估, 论文说数据集将开源. 表 1 列出 303 个病例分布在 12 个科室: 全科 111, 外科 50, 妇科 26, 神经科 25, 消化 18, 血液与肾内各 15, 心内与呼吸各 14, 内分泌 7, 风湿 6, 老年科 2. 问诊部分标注了 8,857 条 checklist 作为真值, 平均每例 29.23 条 (范围 20–35); 现病史占 55.8%, 既往史 19.6%, 个人与社会史 14.6%, 婚育史 5.4%, 家族史 4.7%; 51.3% 标为二级 (关键, 用于诊断或排除风险), 其余 48.7% 为一级 (补充). 辅助检查阶段有 38 类统一动作空间, 从血尿便常规, 肝肾功能, 电解质, 糖代谢, 到 CT, MRI, 超声, 心电图, 肺功能, 再到肿瘤标志物, 自身抗体, 骨髓活检和内镜.

三站的打分协议各不相同. 第一站问诊, 模型与标准化病人多轮对话, 用 SCAN 框架从安全分层, 信息澄清, 联想追问, 规范输出四个维度评过程质量, 由 GPT-4.1 核对 OSCE 关键点的覆盖, 每次问诊都会重复的内容 (复述年龄性别, 模板化自我介绍) 不计分. 第二站检验, 模型先给鉴别诊断, 再从候选池里选检查, 候选分必需和可选两组, 用加权 F1 评分, 必需检查的召回权重更高, 既考覆盖也考不浪费. 第三站诊断, 按 ICD-10 层级匹配, 命中叶节点得分, 偏到别的分支扣分. 图 4 里 M3 三站分别为 74.9, 72.1, 74.4, 问诊站领先第二名 GPT-5.2-High 12.4 分, 领先人类基线 20 分以上. 读图可得 GPT-5.2-High 三站约为 62.5, 70.4, 73.5, 医师组约为 53.5, 69.9, 71.3 (读图). **领先幅度在问诊站最大, 到诊断站收窄到 1 分左右**.

图 5 把问诊站拆成 SCAN 四项. 安全分层 M3 得 75.8, 第二名 Qwen3-235B 只有 48.3, 医师组 40.1; 联想追问 M3 得 72.6, GPT-5.2-High 为 54.5; 表达清晰与规范流程分别为 84.5 与 59.9. 安全分层衡量对 「红旗」 症状和高危风险的敏感度, 这恰是动态 rubric 和分段奖励最容易强化的行为. 医师组在这一项偏低, 一种可能的解释是: 真实门诊里医生默认会在后续检查中排除高危情况, 不会在问诊阶段逐条说出来, 而 checklist 只认对话里明说的内容. ScanBench 的 「超过医师」 是在这套偏重显式表达的口径下成立的, 再加上第 2.2 节说的训练与评测同构, **它更适合看 M3 在自家流程上练到了什么程度**.

HealthBench 是 M2 与 M3 共用的主基准, 最适合看代际进步. M3 总分 65.1, 第二名 GPT-5.2-High 63.3; Hard 子集 M3 44.4, GPT-5.2-High 42.0, AntAngelMed 39.6. M2 报告里的对应数字是 60.1 与 34.7, Hard 子集一代涨了近 10 分. 图 8 的细分对比里, 提升最明显的是 context seeking (约 0.558 到 0.637) 与 context awareness (约 0.480 到 0.562) (读图). 论文把这归因于深度问诊训练的迁移: 模型更主动地追问缺失的病史和风险因素, 也更留意限定临床决策的上下文. 这两个维度和分段流水线 RL 的目标高度对口, 可以看作问诊训练在单轮基准上留下的痕迹.

HealthBench-Hallu 是 M3 单列的幻觉评测, 复用第 3.2 节的核查管线, 但换成高精度配置: 抽取器升级为 GPT-5, 每条论断实时多轮检索, 不用缓存. 式 (15) 按风险分级加权:

$$
H = \frac{\sum_{i=1}^{N} w_i}{|\text{Total Claims}|} = \frac{1.0\cdot N_{\text{Refuted}} + 0.5\cdot N_{\text{Uncertain}} + 0\cdot N_{\text{Supported}}}{N}.
$$

图 7 里 M3 为 3.5%, GPT-5.2-High 约 3.8%, M2 约 8.4% (读图). 这几个读图值可以用表 2 交叉验证: 按上式, 加权幻觉率约等于 Refuted 率加一半 Uncertain 率, M3 为 2.45 + 2.07/2 ≈ 3.49%, GPT-5.2-High 为 2.37 + 2.78/2 ≈ 3.76%, M2 为 5.73 + 5.43/2 ≈ 8.45% (估算), 与图上读数吻合. 训练与评测对 Uncertain 的处理不同: 训练用的式 (12) 把 「证据不足」 和 「被证伪」 同等重罚, 评测用的式 (15) 只算一半, **训练从严, 评测分级**. 全文没有通用能力基准, 也没有 MedQA 一类的医学考试题, 与 M1 的评测几乎没有交集.

### 4.2. 部署: Gated Eagle-3 与自生成校准的 INT4

投机解码用一个轻量草稿模型一次提出多个候选 token, 由目标模型并行验证, 接受最长的已验证前缀, 让目标模型每步提交多个 token. Eagle-3 [52] 的草稿模型还会接入目标模型的隐状态, 借更丰富的语义信息提高命中率. 问题在于大小模型容量悬殊, 高维, 信息密集的隐状态可能压垮轻量草稿模型, 反而用不好这路辅助信号. M3 在草稿模型里加了 **Gated Attention** [53] 模块: 注意力输出经过一个门控单元, 与由当前层输入动态生成的门向量逐维相乘, 按维度决定放多少目标模型的信息进来.

附录 A.4 用同样 35,000 条训练样本和同样的训练协议比较两种草稿模型, 训练用 SpecForge, 推理用 SGLang, 硬件为 NVIDIA H20. 表 5 的平均接受长度: GSM8K 3.59 → 3.84, HumanEval 3.58 → 4.03, MT-Bench 2.97 → 3.23, HealthBench 2.41 → 2.70, 平均提升 0.31. 表 6 在并发 8 下的吞吐 (tokens/s): GSM8K 376.98 → 431.26 (+14.40%), HumanEval 576.19 → 646.17 (+12.15%), MT-Bench 451.39 → 490.12 (+8.58%), HealthBench 356.94 → 400.52 (+12.21%), 正文概括为平均 12%. HealthBench 上的接受长度在四个集合里最低, 医学长回答对草稿模型更难猜. 报告给的是 Gated Eagle-3 相对 Eagle-3 的增量, 没有相对不做投机解码的绝对加速比, **不能和 M2 的 2.17 倍直接比较**. GitHub README 给的 SGLang 启动示例用 8 卡张量并行, 草稿参数为 5 步, top-k 8, 32 个草稿 token (外部). EAGLE 系列的演进见 [EAGLE 系列深度解析](../../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/02-EAGLE系列深度解析.md).

量化一侧, M3 做 INT4 权重量化. MoE 稀疏激活给校准带来特有的偏差: 普通校准语料只激活一部分专家, 常用专家量化得准, 冷门专家误差大, 推理时的精度损失因此不稳定, 不可预测. 对策是**自生成校准**: 构造多领域 prompt, 用 BF16 模型生成回答作校准数据. 好处有两点: 多样的 prompt 几乎激活全部专家, 每个专家都有足够样本; 自生成的回答让量化模型贴近 BF16 模型的输出分布. 这是 M2 「校准集里加原模型自己的回答效果更好」 这条经验在 MoE 上的延伸, 并引了 MoQa [54] 对 MoE 量化中数据与模型分布的讨论; 量化参数用 AutoRound [55] 训练, 格式遵循 GPTQ [56], 模型卡另外发布了 GPTQ-INT4 版本 (外部). 报告只说 INT4 版在主流基准上 「近乎无损」, 没有给任何数字, **这是推理优化部分最薄弱的一处**. MoE 量化的整体图景见 [MoE 模型量化技术综述](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/09-MoE模型量化技术综述/09-MoE模型量化技术综述.md).

部署目标的变化比技术细节更能说明问题. M2 的卖点是一张 RTX 4090 就能跑, 报告给了显存, 上下文长度和每秒 token 数; M3 换成数据中心级的 H20, 只给相对增益, 没有绝对延迟和显存占用. 按模型卡的文件大小, BF16 权重约 470 GB, INT4 权重约 118 GB (估算, 不含量化 scale); 单张 H20 显存 96 GB, BF16 光放权重就要 5 张以上, INT4 至少 2 张 (估算). 部署场景因此从个人和小机构转向医院与云服务, 两条技术路线延续了 M2, 服务的对象换了一批人.

### 4.3. 放回家族: 奖励信号一层层拆细, 底座与通用能力留白

三代连起来看, 百川医学线的演进是奖励信号的逐步细化. M1 靠预训练数据打底; M2 用 rubric 验证器和患者模拟器把 RL 引进医学场景; M3 把奖励拆成规范和事实两路, 把问诊拆成四个阶段, 把步级惩罚拆成严重和轻微两档, 把 rubric 拆成静态核心和动态演化两层, 再用三段流水线把多位专家合成一个模型. 每一处拆分都对应上一代暴露的具体问题: 多任务冲突, 长程信用分配, 奖励饱和后的 hack, 以及补细节带来的幻觉. 从方法来源看, M3 很少发明全新的构件, 更多是把 GRPO, GSPO, OPD, MOPD, 长文本事实性评估与动态 rubric 这些同期成果按临床流程组装起来, **组装方式本身是它的主要贡献**.

缺口同样清楚. 底座信息只能从模型卡拼出来, 论文没有写 Qwen3-235B-A22B 这个来源, 也没有 mid-training, SFT 数据和训练算力, 代际提升里有多少来自底座变大, 有多少来自后训练, 读者无法拆分. 通用能力没有评测, 第一段训了通用专家却看不到结果. 若干关键超参没有公开: 分段门控的 τ, 各阶段样本占比, SPAR 的 ε 和完整 λ 表, 语义聚类阈值, 动态 rubric 的准入阈值, 复现和归因都很困难. 主要结论依赖自建基准和自家核查管线, ScanBench 与训练流程同构, HealthBench-Hallu 与训练奖励共用工具, **第三方可比性主要靠 HealthBench 支撑**.

报告在 §7 自己列出的局限集中在场景边界: 目前只覆盖单次, 纯文本的临床场景, 不涉及长期疾病管理, 多模态临床信号和跨越患者全病程的超长程推理; 罕见的高风险错误和循证来源的显式引用仍未解决. 未来方向是多模态的全路径临床推理, 长上下文优化, 以及把证据检索, 安全约束与基于环境的 RL 结合得更紧. 按这条谱系推下去, 下一代的变化大概率仍集中在奖励与环境侧: 环境从脚本化的被动患者走向更真实的长程病程, 奖励从逐条核查论断走向带引用的循证生成.
