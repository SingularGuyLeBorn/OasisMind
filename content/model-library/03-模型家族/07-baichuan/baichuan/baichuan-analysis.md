# 百川智能官网首页: 七张产品卡背后的训练路线转向

公开材料是百川智能官网首页的抓取 `baichuan.md` (9 页, 16 图), 不是技术报告. 全文没有公式, 没有架构表, 没有训练配方, 唯一的数据图是一组 2×3 的医疗基准柱状图.

来源: 同目录 `baichuan.md` (页标记 `page 1 of 9` 到 `page 9 of 9`), 对照译稿见 `baichuan-bi.md`. 抓取造成的碎片 (如被裁掉的 M3 卡) 不补写. 标 「读图」 的数字来自柱状图上的标注.

## 1. 页面构成与产品卡

### 1.1. 一张门面页上有哪几面, 缺哪几面

九页可以按页分成四块. 第 1 到第 4 页是医疗 C 端产品宣传: 口号 「明明白白看医生, 安安心心管家人」, APP 与 BOT 两种形态, 三条卖点和五项能力. 第 5 页是 「海纳百川」 免费 API 计划的条款, 加上一排产品卡. 第 6 页是基准图, 学术支持入口和合作伙伴 logo 墙. 第 7 到第 9 页是公司介绍, 创始人寄语, 员工语录和备案信息.

一个模型通常要从数据, 结构, 训练算法, 预训练, 后训练和评测几面一起看. 这页覆盖得很不均匀: 数据只剩卡面上 「1.2T」, 「2.6T」, 「20T」 这样的语料数; 结构一个字也没有, 连 decoder-only, MoE, GQA 都没提; 训练算法只在学术区的博客摘要里留了几个名词, 比如 「大型验证器系统」, 「患者模拟器」; 评测有六格柱状图, 但全是医疗基准. 所以**这页更适合当目录和时间线来读**, 训练细节要去页面自己给的出口找: Baichuan2 技术报告, M1 的 arXiv 2502.12671, M2 与 M3 的技术博客, Baichuan2 的中间 checkpoint.

### 1.2. 卡面上的 「语料」 一栏悄悄换了含义

通用线四张卡的规格很整齐. Baichuan-7B 为 70亿参数, 1.2T 语料; Baichuan-13B 为 130亿, 1.4T, 两者标 「中英双语」. Baichuan2-7B 与 Baichuan2-13B 为 70亿和 130亿, 语料统一为 2.6T, 标签换成 「多语言」. 四张卡的上下文全是 4K. 这四个 T 数都是各自从零预训练时见过的 token 量, 和 [Baichuan-7B](../baichuan-7b/baichuan-7b-analysis.md), [Baichuan-13B](../baichuan-13b/baichuan-13b-analysis.md), [Baichuan 2](../baichuan-2/baichuan-2-analysis.md) 各自的 README 或报告能一一对上.

医疗线的口径变了. Baichuan-M1 卡写 140亿参数, 「20T 医疗增强语料」, 32K 上下文, 自称 「首个医疗增强模型」. 按 M1 技术报告的表 1, 这 20T 是从零预训练的总量, 按语种分为英文 12T, 中文 4T, 多语 2T, 代码 2T, 医疗数据掺在其中. 卡面把整个 20T 都叫 「医疗增强语料」, 容易让人以为有 20T 医疗文本, **实际描述的是配方的侧重**. 到 M2 卡, 语料一栏干脆消失, 只写 320亿参数, 「推理模型」, 32K, HealthBench 60.1. 原因在 M2 报告里: 它的底座是 Qwen2.5-32B-Base, 百川做的是 mid-training, SFT 和 RL, 没有从零预训练, 自然报不出一个 T 数. M3 卡在抓取时被裁掉, 唯一线索是 Hugging Face 链接里的 `Baichuan-M3-235B`; 它的模型卡把 base_model 写成 Qwen/Qwen3-235B-A22B, 这一点首页上看不出来.

## 2. 路线转向与产品承诺

### 2.1. 从 「自己训底座」 到 「在别人底座上做后训练」

把七张卡按时间排开, 能看到一条比 「4K 到 32K」 更重要的线: **百川的主要投入从预训练移到了后训练**. 第一代和 Baichuan 2 的公开材料里, 篇幅最大的是分词器, 数据清洗, 位置编码, 训练稳定性和分布式系统; M1 仍从零训了 20T token, 还改了注意力结构. 到 M2 和 M3, 底座换成了现成的 Qwen 系列, 技术报告的主体变成了验证器, 奖励设计和强化学习流程. 首页学术区的三段摘要正好反映这个变化: Baichuan2 报告写的是 「数据, 模型结构, 目标函数, 分布式计算系统, 模型动态评估」, M2 博客写的是 「大型验证器系统, 患者模拟器, 医疗领域增强训练」, M3 博客写的是 「幻觉抑制, 满血问诊, 推理能力」.

这一转向对读卡的人有两个实际影响. 其一, M2 和 M3 的结构参数 (层数, 注意力形式, 是否 MoE) 取决于所选底座, 百川自己的技术贡献不在结构上, 首页不写结构也就不奇怪. 其二, 卡面上 「140亿 → 320亿 → 235B」 看起来是规模一路上涨, 实际上 M3 用的是 MoE 底座, 按 Qwen3-235B-A22B 的公开配置每个 token 只激活约 22B 参数, **和稠密的 32B 不是同一种 「大」**. 后训练方法的一般脉络可对照 [GRPO](../../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md) 与 [GSPO](../../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/04-GSPO/04-GSPO.md), 分别是 M2 和 M3 在报告里用的 RL 算法.

### 2.2. 产品承诺在训练里各有对应物吗

第 3 页把能力概括为 「问不倒, 讲得清, 记得住」, 第 4 页展开成五项: 医学水平, 沟通能力, 无限耐心, 全科覆盖, 全家记忆. 其中 「全科覆盖」 的定义是 「覆盖问诊, 就医准备, 结果解读, 后续管理等多个环节」, 指就医流程的环节, 不是临床科室的广度. 这几项里, 有训练对应物的是主动问诊和低幻觉. 主动问诊对应 M2 报告的患者模拟器和 M3 报告里按问诊, 鉴别诊断, 检查, 诊断四段拆开的分段 RL; 要训练模型追问病史, 就得有一个能被追问的模拟病人. 低幻觉对应 M3 的事实感知 RL, 报告正文给出的幻觉率是 3.5%.

另外三项在公开材料里找不到训练侧的对应. 「全家记忆」 的定义是 「支持家庭成员健康信息管理」, 页面没说靠长上下文, 外部数据库还是别的机制, 也没有容量和保留期限; 「无限耐心」 是交互层的承诺, 更像产品设计而非模型能力; 「沟通能力」 把术语讲成大白话, 可以关联到 M2, M3 报告里 rubric 对沟通质量的打分, 但首页没有建立这层联系. 读产品页时, **能在技术报告里找到奖励信号或训练数据的承诺, 才算有模型层面的支撑**.

## 3. 免费计划, 基准图与家族索引

### 3.1. 海纳百川计划: 免费 API 的边界条件

计划对象是 「为医务工作者提供服务的机构」, 不面向个人. 核心权益是永久免费调用 Baichuan-M3 Plus API (页面一处拼成 「M3-PIus」), 卖点是低幻觉率, 「一次性解决大模型编文献的问题」, 以及 「证据锚定」 技术与证据段落 95% 精准匹配. 95% 这个数没有给出测量方法: 匹配的单位是句子还是论断, 由人工还是模型判定, 样本多大, 页面都没写. 证据锚定的思路接近检索增强里的引用溯源, 衡量方式可对照 [RAG 评测运维与安全](../../../../llm-guide/7-LLM应用开发/7.2-RAG/7.2.4-评测运维与安全/7.2.4-评测运维与安全.md).

限制写在四组条款里. 场景只限两类: 临床辅助决策和医学教育. 用途只能是真实服务场景, 「不得用于数据生产」. 产品必须展示 「Powered by 百川」, 不得对输出做影响准确性的修改. 准入审核与解释权归百川. 「不得用于数据生产」 这一条和前面的训练路线有关: M 系列自己就是靠验证器, 模拟器和蒸馏批量生产训练信号做出来的, 条款禁止下游拿 M3 Plus 的输出去造训练数据, **等于把这条路对合作方关上**. 「不得修改输出」 则把准确性责任和模型绑在一起, 属于部署治理的范畴, 背景见 [部署治理与持续保证](../../../../llm-guide/5-评测、安全与治理/5.4-部署治理与持续保证/5.4-部署治理与持续保证.md).

### 3.2. 基准图: 自选对手, 自选基准, 没有评测设置

第 6 页的总题注是 「Overall benchmark comparison across medical benchmarks」, 六格如下 (读图, 按图内标题整理, 不按图片文件名):

| 基准 | Baichuan-M4 | GPT-5.5 | Opus 4.7 | DeepSeek-V4-Pro |
|---|---|---|---|---|
| HealthBench Total | 68.6 | 58.4 | 54.1 | 51.0 |
| HealthBench Hard | 49.7 | 33.8 | 26.1 | 19.5 |
| HealthBench Professional | 55.1 | 51.8 | 50.5 | 28.4 |
| Hallucination Rate (越低越好) | 3.3 | 3.8 | 6.9 | 9.8 |
| Scan-Bench V1 | 79.0 | 68.8 | 71.7 | 71.4 |
| Scan-Bench V2 | 74.7 | 67.7 | 66.9 | 63.2 |

六格里 M4 都排第一. 对手是三家通用旗舰, 没有医疗专用模型, 也没有自家的 M3, M2. 想看代际进步只能跨文档比: M3 报告里 HealthBench 为 65.1, Hard 为 44.4, 幻觉率 3.5%, 对应本图 M4 的 68.6, 49.7, 3.3. 但两边的对手版本 (M3 报告对比的是 GPT-5.2-High, 本图是 GPT-5.5) 和裁判设置未必一致, **这组差值只能算方向性参考**. Scan-Bench 在 M3 报告里叫 ScanBench, 按问诊, 检查, 诊断三站分别打分, 本图的 V1, V2 是单一分数, 如何从分站汇总, 页面没说. M4 在本页没有产品卡, 也没有技术报告, 结构和训练方法都无从核对.

**评测设置的缺口更根本**. 页面没有样本数, 没有误差条, 没有评分方式 (HealthBench 原本用模型裁判按 rubric 打分), 也没写各家是否开启推理模式, 用了多少 TestingTime 预算, 采样几次取平均. 医疗回答长, 评分依赖细则, 这些设置对分数影响不小. 标语 「HealthBench全球第一, 从问对一次到长程托付」 暗示重点转向多轮陪伴, 但六格里没有一项是长程或多轮基准. 厂商自报图的一般读法见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

### 3.3. 放回家族: 这页能当哪几件事的索引

作为时间线, 这页给了两个锚点: 百川成立于 2023年3月24日, 不到 100 天发布 Baichuan-7B 和 Baichuan-13B, 下载量突破百万. 学术区还提到 「Baichuan2 公开全过程切片」: 从 200B 到 2640B 数据的中间权重全部开源, **这是全页唯一直接服务于研究的开放物**, 可以用来观察能力随 token 数增长的轨迹. 合作伙伴区是一面 logo 墙, 没有说明各家的合作内容.

各代的技术细节按以下顺序读: [Baichuan-7B](../baichuan-7b/baichuan-7b-analysis.md) 和 [Baichuan-13B](../baichuan-13b/baichuan-13b-analysis.md) 是 LLaMA 式配方加中文词表; [Baichuan 2](../baichuan-2/baichuan-2-analysis.md) 补上了数据清洗, NormHead, max-z loss 和 PPO 对齐; [Baichuan-M1](../m1-14b/m1-14b-analysis.md) 是最后一个从零预训练的版本; [Baichuan-M2](../m2-32b/m2-32b-analysis.md) 和 [Baichuan-M3](../m3-235b/m3-235b-analysis.md) 在 Qwen 底座上做医疗后训练; [Baichuan-Omni-1.5](../omni-1-5/omni-1-5-analysis.md) 是另一条全模态支线, 首页没有给它产品卡. 首页没回答的问题, 比如 M3 Plus 与开源 M3 的差别, 4090 单卡部署用的量化精度, 都要到这些报告和模型卡里去找.
