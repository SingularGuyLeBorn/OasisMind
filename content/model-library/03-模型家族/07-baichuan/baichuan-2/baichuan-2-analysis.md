# Baichuan 2: 2.6 万亿 token, 一张大词表和输出层上的两道约束

## 1. 数据与词表

### 1.1. 这份报告同时往前推了哪几面

2023 年秋天的中文开源基座, 骨架大多直接跟 LLaMA: decoder-only, pre-norm, SwiGLU, RoPE. 差异只能从数据, 词表, 训练稳定性, 对齐和中文评测里找. Baichuan 2 的引言说得直白: LLaMA 的 Common Crawl 占预训练数据 67%, 却只保留英文, 开源模型在中文上先天吃亏. 所以这一代百川没有改注意力结构, 也没有 MoE 或长上下文专章, 投入集中在另外几面: 训练 token 从 Baichuan 1 的 1.2/1.4 万亿提到 2.6 万亿, 词表从 64,000 翻到 125,696, 输出层加了 NormHead 和 max-z loss, 开训前用小模型拟合 Scaling Laws, 训练系统改成共享集群上的机器级弹性, 对齐第一次公开了 SFT 加 PPO 的全流程, 安全从预训练数据一直贯穿到 RL.

这些面是连在一起的. 大词表是数据配方的产物, 又反过来抬高了输出层的显存, 逼出训练系统里的张量切分; 输出层 logits 的尺度影响推理端 repetition penalty 的行为, 所以预训练目标里多了一项 max-z loss; 2.6 万亿 token 对 7B 来说约合每参数 371 个 token, 对 13B 约 200 个, 远超 Chinchilla 常被引用的每参数 20 个, **这是用训练算力换部署成本**, 也决定了中间 checkpoint 值得公开. 读这份报告要把 「写了做法」 和 「证明了有效」 分开: **成体系的消融只有附录 B 的 NormHead 一处**, 大部分结论以 「我们发现」 的口吻给出.

### 1.2. 从去重到词表: 数据的形状一路传到输出层

§2.1 的数据处理强调两件事: 频率和质量. 频率靠聚类和去重, 系统同时支持类 LSH 特征和稠密 embedding 特征, 能在几小时内处理万亿级数据. 去重的粒度从文档下探到段落和句子, 每一级都会打分, 分数进入预训练的采样权重. 图 2 的漏斗依次是精确去重, 启发式规则, 句级质量过滤, 句级与段级去重, 文档级去重, 最后留下原始语料的约 31.68% (读图). 句级和段级去重在网页数据里很有针对性: 模板页脚, 版权声明, 导航文字在正文不同的页面里反复出现, 只做文档级去重抓不到它们. 报告没有公开原始总量, 中英比例, 各类采样权重, 也没有说两种特征各删掉了多少. 字面去重与语义去重的一般做法见 [3.1.3-数据处理](../../../../llm-guide/3-预训练/3.1-预训练数据/3.1.3-数据处理/3.1.3-数据处理.md).

把图 2 每一步的删除比例拆开, 「频率优先」 就不只是口号了 (读图). 精确去重删掉原始语料的 29.89%, 启发式规则删 1.77%, 句级质量过滤删 3.06%, 句级与段级去重删 14.47%, 文档级去重再删 19.13%. 三道去重合计删掉约 63.5%, 两道质量过滤合计只删约 4.8%. 也就是说, 从原始语料到训练语料, **绝大部分被丢掉的是重复, 真正因为 「质量差」 被丢的很少**; 质量分更多地用在采样权重上, 而不是删除. 图 1 的类别分布里, 科技, 商业, 娱乐三类最高, 分别约占 11%, 10%, 8%, 代码约 4%, 数学接近 0 (读图). 数据来源写的是网页, 书籍, 论文, 代码库等, 各来源的比例没有给.

分词器就训练在这份语料上, 另外多采了代码和学术论文来提高覆盖. 表 2 里 LLaMA 2 的 32,000 词表压缩率 1.037, Bloom 的 250,680 词表压到 0.501, Baichuan 2 用 125,696 压到 0.498, 用一半的词表追平了 Bloom. 同一张表给 Baichuan 1 的压缩率是 0.570, 而 Baichuan-7B 的 README 给的是 0.737, 两个数差得多, 说明两次测量用的不是同一份文本, **压缩率只能在同一张表内比较**. 规则上, 数字逐位切分, 加纯空白 token 服务代码缩进, 字符覆盖率 0.9999 加 UTF-8 字节回退, 不做规范化, 去掉 Baichuan 1 的 dummy prefix, 最大 token 长度放到 32 给中文长短语. 这里面只有最后一条明显针对中文, 其余是 SentencePiece BPE 在 2023 年的通行调法, 见 [3.3.1-训练Tokenizer](../../../../llm-guide/3-预训练/3.3-分词器与Tokenizer/3.3.1-训练Tokenizer/3.3.1-训练Tokenizer.md).

词表翻倍的代价落在参数和显存上. 7B 的一张 125,696 × 4,096 词表矩阵约 0.51B 参数, 13B 的 125,696 × 5,120 约 0.64B; 输入 embedding 和输出头不共享时要算两份. 训练时更麻烦的是输出层: logits 的宽度就是词表大小, 交叉熵的峰值显存随之翻倍. 一条 4,096 token 的序列, logits 有 4,096 × 125,696 ≈ 5.1e8 个元素, BF16 存约 1.0 GB, softmax 若在 FP32 里算再翻一倍, 反向还要一份同形状的梯度 (每条序列). §2.7 专门用 Nie et al. (2022) 的张量切分把大词表交叉熵拆开计算, 报告说这样不增加计算和通信; 沿哪一维切, 切几块, 报告没写. 从数据清洗出发的一个决定, 最后在训练系统里又多出一项工程改动.

压缩率的收益落在上下文和推理成本上. 报告没有给压缩率的定义式, 表头只标了 「越低越好」; 如果把它理解为同一段文本编码后的相对 token 数, 那么 0.498 对 1.037, 同样 4,096 的训练窗口能装下的中文大约是 LLaMA 2 的两倍, 生成同样长度的中文回答, 前向步数也约减半. 这部分收益和 13B 用 ALiBi 带来的单步提速是两回事, 前者减少步数, 后者减少每步开销. 两代百川都把训练长度停在 4,096, 更高的压缩率在某种程度上替代了窗口扩展: **窗口没变, 能读进去的中文变多了**.

## 2. 骨架与输出层

### 2.1. 骨架沿用 LLaMA, 位置编码的分歧其实是在选注意力内核

表 3 的配置几乎是 LLaMA 2 同档的翻版, 两档训练长度都是 4,096. FFN 宽度按 「8/3 倍 hidden, 取整到 128 的倍数」 算: 4,096 × 8/3 ≈ 10,923, 向上取整到 11,008 (= 86 × 128); 5,120 × 8/3 ≈ 13,653, 取到 13,696 (= 107 × 128), 与表中数字一致. 13,696 也和按总参数反推出的 Baichuan-13B 的 FFN 宽度相同, 两代 13B 用的是同一副骨架. 归一化是加在块输入上的 RMSNorm, 优化器 AdamW, β2 = 0.95, weight decay 0.1, 梯度裁剪 0.5, 2,000 步线性预热后 cosine 衰减. 注意力是标准多头, 没有 GQA; LLaMA 2 当时也只在 34B 和 70B 上用 GQA. 门控 FFN 见 [03-GLU家族-从GLU到SwiGLU](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.1-激活函数/02-GLU家族-从GLU到SwiGLU/02-GLU家族-从GLU到SwiGLU.md).

把表 3 代回参数公式, 能看出词表翻倍把 「7B」 推到了多大. 每层注意力 4 × d², SwiGLU 三个矩阵 3 × d × FFN, 加上输入与输出两张词表矩阵: 7B 为 32 × (4 × 4,096² + 3 × 4,096 × 11,008) + 2 × 125,696 × 4,096 ≈ 7.51B, 13B 为 40 × (4 × 5,120² + 3 × 5,120 × 13,696) + 2 × 125,696 × 5,120 ≈ 13.90B (忽略归一化权重). 同样的骨架, Baichuan-7B 的总参是 7.00B, **多出来的约 0.5B 几乎全是新增的词表行**. 词表参数在 7B 里占约 14%, 在 13B 里占约 9%, 这部分参数每步只有少数行被更新, 罕见 token 的行学得慢, 这正是下一节 NormHead 要处理的问题: 罕见 token 的 embedding 范数在训练中变小.

唯一的分叉在位置编码: 7B 用 RoPE, 13B 用 ALiBi, 沿袭 Baichuan 1 的两档分工. 报告给了一句很实在的理由: FlashAttention 这类优化实现更适合 RoPE, 因为 RoPE 是乘法式的, 不需要把 attention_mask 传进注意力算子; ALiBi 是加在分数上的偏置, 必须传. 13B 能用 ALiBi, 靠的是 xFormers 的 memory efficient attention 支持偏置输入. 报告称预实验里两种位置编码对效果影响不大, 保留两种是给研究者一个 「偏置式对乘法式」 的对照, 但预实验没有给数字. 之后 PI, NTK-aware, YaRN 这些长上下文扩展方法都建在 RoPE 的频率结构上, 百川自己的 M1 也统一回到了 RoPE. 机制对比见 [01-位置编码与外推](../../../../llm-guide/2-核心原理与架构/2.5-长上下文与外推技术/2.5.1-长度外推/2.5.1-长度外推.md).

位置编码还牵出一个数值精度问题. 整个模型用 BF16 混合精度训练, 前向与反向在 BF16 里算, 优化器更新在 FP32 里做. BF16 的有效精度只有 8 位, 整数超过 256 后相邻值会撞在一起; 报告点名某些公开的 RoPE 与 ALiBi 实现里 torch.arange 会因此分不清相邻位置, 于是位置编码这类对数值敏感的运算改用全精度. 这条经验在后来的开源实现里很常见: 矩阵乘可以放在低精度, **位置下标, 归一化统计量这类索引性数值要留在高精度**. 格式细节见 [01-浮点数基础与BF16混合精度训练](../../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/01-浮点数基础与BF16混合精度训练.md).

### 2.2. NormHead 与 max-z loss: 同一个输出层, 训练和推理两头的问题

**NormHead** 把输出 embedding (即 lm_head 的每一行) 先做归一化, 再和隐状态点积, logit 只取决于夹角. 报告给了两个理由. 其一, 预实验里 head 的范数不稳定, 罕见 token 的 embedding 范数在训练中变小, 扰乱训练动态. 其二, 词 embedding 的 KNN 检索里, 按余弦取近邻得到语义相近的词, 按 L2 距离取的近邻 「某种程度上没有意义」, 而点积是 L2 距离和余弦的混合.

「混合」 可以落到同一个 logit 上. 设最后一层隐状态为 $h$, 第 $i$ 个 token 的 head 行为 $w_i$, 普通线性头与 NormHead 分别是

$$
\ell_i = w_i^\top h = \|w_i\|\,\|h\|\cos\theta_i = \tfrac12\left(\|w_i\|^2 + \|h\|^2 - \|w_i - h\|^2\right), \qquad \ell_i^{\text{norm}} = \frac{w_i^\top h}{\|w_i\|} = \|h\|\cos\theta_i .
$$

第一式里, 同一个 $h$ 对所有 token 共用, $\|h\|^2$ 不影响排序; 真正决定排序的是 $-\|w_i-h\|^2$ 这一项 L2 距离, 外加 $\|w_i\|^2$ 这一项只和 token 自己有关的偏置. 罕见 token 的 $\|w_i\|$ 在训练中变小, 等于它的 logit 被整体往 0 拉, 与夹角无关. 第二式把 $\|w_i\|$ 除掉, 各 token 之间只比 $\cos\theta_i$. 附录 B 的消融关掉的正是这一步: 在 softmax 之前加或不加对 head 的归一化, 7B, 12k 步, 超参, 随机种子, batch size 和数据流都相同, 不加的曲线开头明显不稳; 图 9 只有曲线, 没有给具体 loss 差值. 这一改动对分发也有影响: Hugging Face 上的实现在前向时对 lm_head 做 F.normalize, 仓库 README 另外提供了离线归一化脚本, 可以把权重转成普通线性头的格式, 方便不认 NormHead 的推理框架加载.

**max-z loss** 的出发点在推理端. 报告发现训练中 logits 可能变得很大; softmax 只看相对值, 本来无所谓, 但 Hugging Face generate 里的 repetition penalty 是把一个标量 (如 1.1 或 1.2) 直接作用在 logits 上, logits 绝对值越大, 这一缩放对 softmax 后概率的改动越剧烈, 模型对这个超参就越敏感. 于是式 (1) 在交叉熵之外加了一项, 两者对照是

$$
\mathcal{L} = \mathcal{L}_{\text{CE}} + 2\times10^{-4}\, z^2,\quad z = \max_i \ell_i \qquad\text{对比 PaLM:}\quad \mathcal{L} = \mathcal{L}_{\text{CE}} + 10^{-4}\,(\log Z)^2,\quad Z = \sum_i e^{\ell_i}.
$$

报告写明灵感来自 NormSoftmax 和 PaLM 的辅助 z-loss. max-z 项对 $z$ 的梯度是 $4\times10^{-4} z$, 每个位置只推最大的那一个 logit 往下走; PaLM 的项对每个 $\ell_i$ 的梯度是 $2\times10^{-4}\log Z\cdot \mathrm{softmax}_i$, 按概率分摊到全部 token, 目的是让 $\log Z$ 贴近 0, 即训练稳定. Baichuan 2 换成惩罚最大 logit, 直接压 logits 的绝对尺度, 同时照顾训练稳定和推理鲁棒.

尺度为什么会影响 repetition penalty, 可以代一组数. 报告脚注指向的 Hugging Face 实现对已出现过的 token 做 $\ell \to \ell/\theta$ ($\ell>0$) 或 $\ell \to \ell\theta$ ($\ell<0$), 正 logit 被扣掉 $\ell(1-1/\theta)$. 取 $\theta = 1.2$, 扣掉的是 $\ell/6$: 被罚 token 的 logit 为 3, 对手为 1 时, 3 变成 2.5, 两者的概率比从 $e^{2}$ 降到 $e^{1.5}$; 同样的相对差距放大十倍, 30 对 10, 30 变成 25, 概率比从 $e^{20}$ 降到 $e^{15}$, 而 30 对 28 时, 30 变成 25, 名次直接倒过来. 同一个 $\theta$, **logit 越大, 扣掉的绝对量越大**, softmax 只看差值, 所以效果随尺度变化. max-z 把 $z$ 压小, 就是让这个扣减量回到 $\theta$ 能控制的范围. 百川没去改推理端的公式, 而是在预训练目标里约束 logits 尺度, 让模型适配开源社区通行的推理实现. 训练尖峰的一般处理见 [6.1.7-训练稳定性与训推不一致](../../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.7-训练稳定性与训推不一致.md).

两项放在一起看, 都是在管 softmax 对平移不变留下的那条自由度: NormHead 固定了 head 的范数, max-z 压住了 logits 的最大值. 后来的模型管这件事的办法更多, 比如 QK-norm 约束注意力 logits, Gemma 2 用 soft-capping 给输出 logits 设软上限. 报告里 max-z 没有单独的消融, 它对最终分数有多大贡献无从判断; 图 3 的预训练 loss 曲线上, 7B 在约 760B token 处仍有一次冲到 2.2 左右的尖峰, 随即回落, 13B 的曲线更平滑, 两者最终分别落在约 1.89 和 1.79 (读图). **两项约束压住了训练发散, 偶发尖峰并没有完全消失**.

两项约束之间还有一层配合, 报告没有明说, 可以从公式推出来. 按上面 NormHead 的式子, $z = \max_i \|h\|\cos\theta_i \le \|h\|$; logit 要变大, 只能靠 $h$ 本身变长. $h$ 来自最后一个 RMSNorm, 它的范数主要由归一化的可学习缩放系数决定. 所以在 NormHead 之下, **max-z loss 实际约束的是最终隐状态的尺度**, 也就是那组缩放系数, 而不是某几行词表向量. 两项分工清楚: NormHead 让各个 token 之间只比方向, 消除罕见 token 范数漂移带来的偏差; max-z 管整体尺度, 防止所有 logits 一起膨胀. 少了前者, 尺度问题会分散到十几万行 head 向量上, 一个标量惩罚很难都管到.

## 3. 训练规划与评测

### 3.1. 开训前先押 loss: Scaling Laws, 集群和中间 checkpoint

§2.6 在押上千张卡之前, 先训了 7 个小模型, 参数从 11.51M 到 3,019.33M (表 10, 约为最终模型的千分之一到十分之一), 每个训到 1 万亿 token, 超参与数据一致. 拟合公式取自 Henighan et al. (2020): 最终 loss $L = a \times C^{b} + L_\infty$, $C$ 是训练 FLOPs, 用 SciPy 的 curve_fit 求参数. 图 4 里 7B 和 13B 训完 2.6 万亿 token 的真实 loss 落在外推曲线上, 这是对这套方法的全部验证, 预测误差没有给数字. 小模型的形状有个细节: FFN 统一是 hidden 的 3 倍, 头数也不随 hidden 等比增长, 和最终模型的 8/3 倍规则不同; 外推依然准, 说明在这个区间算力是主导变量, 形状影响较小. **这种做法只预测 loss, 不预测下游能力**, 也不回答超参怎样随规模变化. 背景见 [3.2.6-Scaling-Law](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.6-Scaling-Law/3.2.6-Scaling-Law.md).

按 6 × 参数量 × token 数算, 7B 的训练量约 1.1e23 FLOPs, 13B 约 2.0e23. §2.7 的训练系统服务于一个共享集群: 任务行为不可预测, 节点常常闲置. 单台 8 × A800 就装得下两档模型, 所以首要准则是**机器级弹性**: 张量并行只放在机内, 跨机用 ZeRO 分片的数据并行, 任务可以随集群状态增减整机. 扩到上千卡时, ZeRO-3 的 all-gather 会成为瓶颈, 对策是混合分层切分 (优化器状态切到所有 GPU, 哪些层启用 ZeRO-3, 参数是否分层切, 由框架自适应决定) 加拓扑感知的 rank 排布. 最终在 1,024 张 A800 上达到超过 180 TFLOPS 的计算效率; 按单卡理解, 相对 BF16 稠密峰值 312 TFLOPS 约合 58%. 以这个速度, 13B 纯计算约需 13 天, 7B 约 7 天 (未计故障和排队). 并行方式见 [6.1.1-分布式训练](../../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md).

训练过程中每 1000 步存一次 checkpoint, 7B 从 220B 到 2,640B token 的中间权重全部公开. 这类做法的前辈是 Pythia, Baichuan 2 把它带到了训练 2.6 万亿 token 的工业级中文模型上. 附录 C 的图 10 给出了一条有用的观察: MMLU 和 C-Eval 大约在 2 万亿 token 后趋于平台, GSM8K 过了 2 万亿仍在上涨 (读图), 报告据此推测数学能力与训练 FLOPs 强相关. 这和第 1.1 节里 「每参数 371 个 token」 的取舍对得上: **通用知识题早已饱和, 继续加 token 主要换来的是数学**. 权重与中途结果开放, 数据与训练代码不开放, 开放程度介于 Pythia 与后来的 OLMo 之间.

报告里关于 「训够了没有」 的两处说法并不完全一致. 引言说即使 7B, 训过 2.6 万亿 token 后表现仍在提升; §5.6 说到 2.6 万亿后 「似乎还有充足的提升空间」; 附录 C 则说 MMLU 和 C-Eval 在 2 万亿后趋于平台, 只有 GSM8K 继续涨. 三处合起来的意思是: 平均分仍在缓慢上升, 但涨幅主要来自数学, 知识类选择题已接近这个规模的上限. 如果目标是通用知识, 7B 训到 2 万亿就够了; 多出的 0.6 万亿换来的是数学和少量其他能力. 这也提示 7B 的中间 checkpoint 更适合研究 「推理类能力怎样随 token 数增长」, 而不是知识召回.

用这批 checkpoint 做研究时有一个混杂因素. 它们来自同一条训练轨迹, 学习率按 cosine 从峰值一路衰减, 越靠后的 checkpoint 学习率越低. 后期分数的上涨里, 既有多见了 token 的贡献, 也有学习率退火本身带来的 loss 下降, **两者在这条轨迹上分不开**. 要单独测 「多训 token 的收益」, 需要在不同 token 数处各做一次完整退火, 报告没有做. 另外公开的中间权重只有 7B 一档, 13B 的训练动态只能从附录 C 的曲线上读.

### 3.2. 评测表里的三条线: 数学涨得最多, 代码看不出规模效应, 中文靠数据和词表

评测只针对 Base. 表 1 用 8 个基准: MMLU, CMMLU 为 5-shot, BBH 为 3-shot, GSM8K 为 4-shot, C-Eval, Gaokao, AGIEval 只取四选一的选择题, 除特别说明外都用内部评测工具; ChatGLM 2-6B 因为没发 base 模型, 数字取自官网. 变化最大的是数学: 13B 的 GSM8K 为 52.77, 约是 Baichuan 1-13B-Base (26.76) 的两倍, 7B 从 9.17 到 24.49. 通用知识上, 7B 的 C-Eval 从 42.80 到 54.00, MMLU 从 42.30 到 54.16; 13B 的 MMLU 为 59.17, 高于 LLaMA 2-13B 的 55.09. 读分数时要记着口径: C-Eval 等三项只取四选项题, 与官方榜单的全量题不可直接比.

引言里有两句概括, 可以拿表 1 核对. 一句是 「7B 在 MMLU, CMMLU, C-Eval 上比 Baichuan 1-7B 高近 30%」: 三项分别从 42.30 到 54.16, 44.02 到 57.07, 42.80 到 54.00, 相对提升约 28%, 30%, 26%, 说法成立. 另一句是 「GSM8K 和 HumanEval 接近翻倍」: 7B 的 HumanEval 从 9.20 到 18.29, 确实翻倍; 13B 从 11.59 到 17.07, 只涨了约 47%, **翻倍的说法只对 7B 成立**. 和 LLaMA 2 同档比, 7B 在中文三项上领先 20 分以上, 在 MMLU 上领先约 8 分 (54.16 对 45.73), 在 BBH 上 41.56 对 39.16, 差距小得多. BBH 考的是多步推理, 这一项的接近说明**数据量带来的主要是知识和语言覆盖, 推理能力的差距不大**.

代码是看起来反常的一格. 13B 的 HumanEval 为 17.07, 略低于 7B 的 18.29. HumanEval 只有 164 题, 17.07% 对应 28 题, 18.29% 对应 30 题, 两档只差两道题, **这个差距在噪声以内**, 谈不上 「代码随规模倒退」. 同一张表 6 里 MBPP 从 7B 的 24.20 升到 13B 的 30.20, 规模效应是有的. 真正的问题是绝对水平: 离 GPT-3.5 Turbo 的 52.44 很远. 图 1 的数据类别分布里代码份额不突出 (读图), 和这个结果能对上, 但报告没有给代码占比, 这只能算一种解释.

中文和多语言的提升, 数据和词表各占一部分, 报告没有拆开归因. 垂直领域评测选了法律和医疗: 13B 的 JEC-QA 为 47.40, MCMLE 为 61.62, USMLE 为 40.38, 都比 Baichuan 1 高出一截; 这一节在当时只是展示 「适合做领域基座」, 后来成了百川医疗路线的起点. 多语言用 Flores-101 的七个中文到外语方向, 8-shot: 13B 在 zh-en 上以 30.61 略高于 GPT-4 的 29.94, zh-ja 从 Baichuan 1 的 2.64 跳到 11.58, 但 zh-ar 仍只有 2.39. 评测证据的一般读法见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据.md).

医疗那张表 5 的构成也说明了 「领域能力」 在 2023 年的测法. 五列分别是 JEC-QA, CMC (C-Eval 验证集, MMLU, CMMLU 中医学相关科目的平均), USMLE 和 MCMLE (美国与中国医师执照考试, 五选一), MedMCQA (印度医学入学考试的 dev 集), 全部 5-shot, 全是选择题. 这些题考的是知识召回, 与后来 M2, M3 追求的多轮问诊, 主动追问, 按 rubric 评估沟通质量是两种东西. 表上 13B 的 MCMLE (61.62) 明显高于 USMLE (40.38), 中文执照考试的优势和中文语料投入对得上; GPT-4 在这两列是 74.58 和 80.28, 顺序正好相反. 从选择题到开放式问诊, 评测方式的变化和百川后来训练重心的转移是同一个方向.

## 4. 对齐与家族位置

### 4.1. 对齐: SFT, 奖励模型, PPO, 以及贯穿全程的安全

Chat 版本走的是 InstructGPT 与 LLaMA 2 的路线. SFT 收集了超过 100k 条样本, 按类似 Claude 的 helpful / harmless 原则标注, 由权威标注员对整批抽检, 不合格整批退回. 奖励模型的 prompt 按 6 个一级类, 30 个二级类, 200 多个三级类组织; 回复只取自 Baichuan 2 家族不同规模, 不同阶段 (SFT, PPO) 的模型, 报告说外部开源数据和闭源模型的回复不能提高 RM 准确率. 损失函数写的是 「与 InstructGPT 一致」, 即对同一 prompt $x$ 下标注为更好的 $y_w$ 和更差的 $y_l$ 做成对排序:

$$
\mathcal{L}_{\text{RM}} = -\,\mathbb{E}_{(x,y_w,y_l)}\left[\log \sigma\big(r_\phi(x,y_w) - r_\phi(x,y_l)\big)\right].
$$

RM 只学到两条回复的分差, 分数的绝对值没有意义. 表 4 的 「准确率」 就是测试对里 $r_\phi(x,y_w) > r_\phi(x,y_l)$ 的比例, 按标注分差 1 到 5 (拿不准, 略好一点, 稍好, 更好, 明显更好) 分档, 从 54.5% 升到 81.5%; 分差为 1 的一档 54.5% 接近随机. 这说明 **RM 在细微差别上分辨力有限**, 与 LLaMA 2 的结论一致. PPO 用 actor, reference, reward, critic 四个模型, critic 先单独预热 20 步, 之后两者按标准 PPO 更新; 学习率恒为 5e-6, 裁剪阈值 ϵ = 0.1, KL 系数 β 从 0.2 衰减到 0.005, 共 350 个 iteration. 算法细节见 [04-PPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md).

四个模型在一步 PPO 里的位置可以写成下式. 报告只说 reference 「用于计算 KL 惩罚」, reward 给 「整条回复」 一个分, critic 学 「逐 token 价值」, 没写 KL 放在奖励里还是损失里; 下面按 InstructGPT 的写法, 把 KL 折进逐 token 奖励, RM 分只加在最后一个 token 上:

$$
r_t = -\beta \log\frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\text{ref}}(y_t\mid x,y_{<t})} + \mathbb{1}[t=T]\, r_\phi(x,y),\qquad
\mathcal{L}_{\text{actor}} = -\,\mathbb{E}_t\left[\min\big(\rho_t \hat A_t,\ \mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)\,\hat A_t\big)\right],
$$

其中 $\rho_t = \pi_\theta(y_t\mid\cdot)/\pi_{\text{old}}(y_t\mid\cdot)$, 优势 $\hat A_t$ 由 $r_t$ 和 critic 的 $V(s_t)$ 估出.

PPO 的几个超参各有分工. β 是上式里 KL 项的系数, 控制 actor 偏离 reference 的程度; 从 0.2 衰减到 0.005, 意思是训练初期把策略拴紧, 防止 RM 还没被充分 「试探」 时策略就钻空子, 后期放松, 让策略朝 RM 偏好的方向走得更远. 裁剪阈值 $\epsilon = 0.1$ 把概率比限在 $[0.9, 1.1]$, 比 PPO 常见的 0.2 更紧, 每步策略更新幅度更小. critic 先预热 20 步, 是因为 PPO 的优势估计依赖 critic 给出的逐 token 价值, critic 随机初始化时优势全是噪声, 先让它对当前策略有个大致估计再一起更新. 350 个 iteration 很短, 加上恒定的 5e-6 学习率, **整体取向是小步, 保守**. 报告没有给 KL 或 reward 随训练的曲线, 这些超参的效果只能从最终模型推测.

「RM 只用自家回复」 这一条值得多看一眼. 报告的解释是它 「从另一个角度印证了 Baichuan 2 系列的内在一致性」, 更直接的理解是**分布匹配**: PPO 阶段 RM 要打分的正是 Baichuan 2 自己采样出的回复, 训练 RM 时用同分布的回复, 打分就更贴近它在 RL 里真正遇到的输入. 外部模型的回复风格, 长度和错误类型都不同, 加进来会让 RM 学到一些在 RL 里用不上的区分. 这个思路后来在百川自己的医疗线上走得更远: M2 用患者模拟器和验证器在线生成奖励, M3 用 on-policy 蒸馏, 都是尽量让训练信号来自当前策略自己的分布. 报告没有给 「加外部回复」 的具体准确率, 这条结论只能按原文记下.

安全被写成贯穿全程的一条线. 预训练阶段用规则加模型过滤暴力, 色情, 歧视等内容, 又收集了来自数百个权威网站的数百万个正向价值网页并提高采样概率. 对齐阶段搭了红队流程: 6 类攻击, 100 多个细粒度价值类目, 10 人专家团队从预训练语料里检索片段写出约 1K 条种子数据, 再带着 50 人外包团队做红蓝对抗, 产出 200K 条攻击 prompt. RL 阶段先用 DPO 针对特定漏洞做小样本修补, 再用一个同时整合 Helpful 与 Harmless 目标的 RM 做 PPO. DPO 论文发表到这份报告只隔四个月左右, 这是 DPO 较早见诸工业报告的用例之一, 见 [01-DPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.2-无奖励模型的对齐DPO-KTO/01-DPO/01-DPO.md). 正向价值数据上采样了多少, 对通用能力有没有挤占, 报告没有给数字.

安全评测有三种证据, 读法各不相同. 图 6 比较安全对齐前后的 helpfulness 和 harmlessness, 报告称前者基本不变, 后者明显提升, 但图上没有给汇总数字. 表 8 的 Toxigen 在基座层面对比 LLaMA 2: 13B 为 11.48, 7B 为 11.72, LLaMA 2-7B 为 12.28, 13B 为 13.24, 差距不大. 协议照搬 LLaMA 2: 用微软 SafeNLP 项目清洗过的版本, 对 13 个少数群体区分中性与仇恨两类, 组成 6-shot 提示, 解码温度 0.1, top-p 0.9, 用 Toxigen 作者微调的 HateBERT 判毒性. 这个分数测的是基座续写时的毒性比例, 反映的是预训练数据过滤和正向价值上采样的效果, 和后训练无关. LLaMA 2 里 13B 比 7B 更毒, Baichuan 2 里 13B 反而略低, 报告在 §7 却写 「毒性往往随模型规模增加」, **自家数据并没有支持这句话**. 表 9 用自建的 BHED (受 BeaverTails 启发, 1,400 条人工样本经 self-instruct 扩到 70,000 条, 七类各 10,000 条): Baichuan 2-13B-Chat 平均 97.50%, 高于 Vicuna 13B 的 93.58%. 拆开看, 其余六类大多在 95% 以上 (最低一格是 Chinese Alpaca 2-13B 在不道德内容上的 85.12%), 差距主要来自 「敏感话题」 一类: 13B-Chat 87.10%, 7B-Chat 78.20%, 非百川模型在 51.90% 到 61.80%. 按七类平均算, 这一类就贡献了约 3.7 个百分点的平均差. 敏感话题的判分标准由百川自己定义, 带有本地规范色彩, 跨厂商比较时说服力有限. 另一个空缺是 Chat 的通用能力: 报告没有给 Chat 模型在 MMLU, C-Eval 或对话基准上的分数, 对齐对能力的影响只能从图 6 的 helpfulness 间接看.

### 4.2. 放回家族: 继承了什么, 改了什么, 后来又被改掉什么

和 [Baichuan-7B](../baichuan-7b/baichuan-7b-analysis.md), [Baichuan-13B](../baichuan-13b/baichuan-13b-analysis.md) 比, Baichuan 2 继承了 RoPE / ALiBi 的两档分工, 同样的 hidden, 层数, 头数和 FFN 宽度, 以及 4,096 的训练长度. 改掉的是数据量 (翻倍), 词表 (翻倍), 输出层 (NormHead 加 max-z loss) 和对齐 (从未公开到 SFT 加 PPO 全流程). 所以同样的 13B 骨架, GSM8K 能从 26.76 涨到 52.77, **这份提升主要来自数据和训练量, 骨架本身几乎没变**.

往后看, 百川的公开路线分成两条. 医疗线的 [Baichuan-M1](../m1-14b/m1-14b-analysis.md) 仍然从零预训练, 训练量提到 20T token, 位置编码统一为 RoPE, 注意力改成全局层与滑窗层交替; [Baichuan-M2](../m2-32b/m2-32b-analysis.md) 和 [Baichuan-M3](../m3-235b/m3-235b-analysis.md) 转到 Qwen 底座上做后训练, RL 算法也从 PPO 换成 GRPO 系和 GSPO. 全模态的 [Baichuan-Omni-1.5](../omni-1-5/omni-1-5-analysis.md) 同样建在 Qwen2.5 7B 上. Baichuan 2 缺的几样, 包括超过 4K 的上下文, GQA 或 MLA 这类压缩 KV 的注意力, MoE, 面向推理的 RL 和 CoT 数据, 用 TestingTime 算力换推理质量, 正是 2024 年以后的主线. 它留下的是几条工程经验: 数据先去重再谈质量, 词表大小要连同输出层显存一起算, logits 的绝对值值得单独约束, 位置下标别放在低精度里, 开训前先用小模型预测 loss.
