## 1. 路线与验证器

### 1.1. 投入方向为什么变了: 从训底座到造验证器

百川医学线的第一代 [Baichuan-M1](../m1-14b/m1-14b-analysis.md) 在 20T token 上从零训了一个 14B 底座, 自己设计注意力结构, 对齐用 ELO, TDPO, PPO 三段. M2 把这条路整个换掉: 底座直接取 Qwen2.5-32B-Base, 在上面做轻量 mid-training, 接 SFT, 再接三阶段 GRPO. 论文一句也没写模型结构, 篇幅重心在第 2 节的验证器系统. Reddit r/LocalLLaMA 上有人注意到, M2 的模型类从 M1 的 BaichuanM1ForCausalLM 换回了标准的 Qwen2 结构, 这意味着 M1 自研的交替注意力和 K/V 短卷积都没有延续. 参数量从 14B 到 32B, **这部分容量是借来的, 不是自己预训练出来的**. M1 留下的主要是数据: SFT 候选池写明取自 「in-house Baichuan-M1 datasets」.

标题里的 Scaling 指的是把验证器系统做大, 即患者模拟器, rubric 生成器, 以及喂给它们的提示和 rubric 数据, 这些都发生在部署前的训练阶段. 底座的选择也有讲究: 脚注说对比过 Qwen2.5-32B-Base 与 Qwen3-32B, 从前者出发训练更稳定, 后者 「已有的对齐」 会带来性能退化. Qwen3-32B 公开的是对齐过的模型, 在它上面再做一整套 mid-training, SFT, RL, 先要把已有的对齐洗掉一部分. 这和 M1 「已退火底座难继续训」 的判断方向一致, 只是问题从退火换成了对齐: **起点越接近纯预训练状态, 后续领域化越顺**. 模型卡另外提到训练框架是 verl, 并发布了带 MTP 的版本, 称吞吐提高 58.5%; 这两点论文没有写.

### 1.2. 奖励从哪来: rubric 生成器把专家判断变成可训练的信号

RLVR 的源头在数学和代码: DeepSeekMath 提出 GRPO, DeepSeek-R1 把 「可验证奖励加组相对优势」 推成主流. 这条路要求答案可判. 开放式医疗问答没有唯一答案, 需要另一种奖励, 关键节点是 HealthBench: 262 位医生为 5,000 段对话写了共 48,562 条 rubric, 由模型裁判逐条判定. 随后 「rubric anchors」 一类工作把 rubric 从评测搬进 RL 奖励. M2 把两者接起来, 区别在于 rubric 的来源: HealthBench 由医生手写, M2 训练了一个生成器按提示现场产出. 从成对偏好训练标量奖励模型, 到 Constitutional AI 的通用原则, 再到逐题 rubric, 奖励越来越细, 也越来越依赖领域专家; M2 用生成器代替逐题手写, 把专家投入限制在定义维度, 挑选种子和标注权重几步. 边界问题见 [RLVR 的局限性与探索边界分析](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.3-RLVR的局限性与探索边界分析.md).

生成器的数据流程分三步. 提示来自三类来源: 真实病历驱动 (多学科, 多病种, 多人群), 知识库驱动 (教科书, 论文, 指南, 药典的标准问答), 合成场景 (住院病历书写, 体检报告解读, 智能分诊, 临床问答等). 先用 LLM 大量生成初始提示, 再走百川内部管线: 聚类去重, 按指令约束, 难度, 核心能力类别打分, 过滤出全面, 有临床价值, 有挑战的提示. rubric 的构造起初直接让 LLM 加 few-shot 生成, 结果过于雷同, 且对个别病例覆盖不全; 于是改成专家先定核心维度, LLM 生成候选, 专家按病例挑选, 再给每条标 [-10, 10] 的整数权重 (负权重对应不希望出现的行为), 以此为种子让 LLM 扩充. 生成器建在一个与系统核心架构一致的 mid-trained 底座上, 用 SFT 加 RL 训练, 训练数据混入数学, 代码和复杂指令遵循, 目的是在线生成时控制成本: 越大的模型 rubric 越好, 但在线开销吃不消.

生成器的评估只有一个数: 按类别均匀抽 100 个病例, GPT-4.1 作裁判比较专家 rubric 与模型 rubric, 一致率 92.7%. 判定标准是 「属于同一维度」, 不要求措辞一致, **这个口径相当宽松**; 权重是否一致, 负向 rubric 是否覆盖到, 都没有单独报告. 于是奖励链路由三段 LLM 串成: 生成器出 rubric, 裁判逐条判定, 结果汇总后归一化到 0 到 1. 裁判模板有一条实用经验: **正负 rubric 必须分开写**. 对负向 rubric 如果也问 「输出是否符合该 rubric」, 裁判常把任务误读成 「按这条 rubric 看回答好不好」, 而不是判断不期望的行为是否出现; 附录 A 为两类 rubric 设计了不同模板, 并要求返回理由. 奖励模型过优化的一般风险见 [Best-of-N 奖励模型过优化](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.4-其他对齐技术/07-Best-of-N-奖励模型过优化/07-Best-of-N-奖励模型过优化.md).

系统层面, 每条回答要按多条 rubric 分别判定, 这些评分请求共享同一段对话前缀, 只在 rubric 描述上不同. M2 的**亲和机制**把前缀相同的请求路由到同一服务实例, 提高 KV cache 复用, 本质上是把推理引擎的前缀缓存搬到了验证器服务上. 评分请求数是回答数的若干倍, 在 rubric RL 和多轮 RL 里, **验证器的推理开销是一等成本**. 这也解释了为什么 M2 愿意训练一个专门的生成器, 而不是每次调用最大的模型. 前缀共享所依赖的 KV 管理见 [PagedAttention 原理](../../../../llm-guide/6-训练与推理优化/6.4-KV缓存与内存优化/6.4.1-PagedAttention原理/6.4.1-PagedAttention原理.md).

### 1.3. 患者模拟器: 同一套环境既造 SFT 数据, 又当 RL 对手

患者模拟器不是 M2 首创. Agent Hospital 搭了由医生和患者智能体组成的虚拟医院; 更直接的来源是 「Exploring the inquiry-diagnosis relationship with advanced patient simulators」, 作者里有 M2 的核心贡献者和医学顾问, §2.1 写明 「Building on prior research」. M2 对前作的批评集中在一点: 心理状态, 社会背景和动态交互建模不足, 模拟器退化成 「静态数据库」. 它的做法是结构拆分: 图 2 把一次患者回复拆成**终止门** (Termination Gate), **情感单元** (Affective Unit), **事实单元** (Factual Unit) 三步, 情感单元管性格和语气, 事实单元对照病历核验说出的内容, 终止门决定何时结束. 心理建模借用 MBTI 的 16 型, 再叠加经济状况, 教育程度等社会属性. 这相当于在环境内部再套一层 「生成加核验」, 用小模型分工换大模型的整体表现.

三个模块的实现细节决定了模拟器能测到什么. 终止门按预设触发条件 (比如医生给出诊断) 判断对话是否结束, 事实单元实时对照患者档案核验, 防止信息泄露和前后矛盾; 这两个模块用的是 non-thinking 模型, 目的是快. 情感单元用合成数据训练, 按档案扮演不同性格和社会文化背景的患者. MBTI 的维度被映射成具体行为: 外向型会主动问治疗方案, 内向型被动接受; 情感型对沟通方式更敏感, 进而影响依从性; 经济拮据的患者倾向拒绝高价方案, 高学历患者更看重循证依据. 「防止信息泄露」 在这里的含义很具体: 真实患者不会一上来把全部病史说完, 模拟器必须在医生问到之前守住档案里的信息, 否则问诊能力就测不出来. 图 3 的三个分数口径不同. Privacy Score 和 Fact Score 是轮级的: 每轮判一次, 前者判这一轮有没有透露与问诊无关的隐私, 后者判有没有偏离预设病历, 整段对话取各轮平均, 即 $\frac{1}{T}\sum_{t=1}^{T} s_t$; Personification Score 是会话级的, 由性格一致性和社会文化一致性各占一半合成. 所以 Privacy 98.3 的意思是约 98% 的轮次守住了未被问到的信息, 而拟人分看的是整段对话的人设有没有走样.

图 3 的对比说明拆分有效, 但矛盾还在. 自研模拟器的 Privacy Score 98.3, Fact Score 84.0, Personification Score 86.3; 加了心理信息的 DeepSeek-V3 分别是 87.5, 72.8, 89.2 (读图). 论文的结论写得克制: 拟人分数上升通常伴随隐私分和事实分下降, 自研方法用更少参数取得了更好的平衡. **个性越鲜明, 越容易多说或说错**, 这组此消彼长仍然存在. 模拟器各单元的参数量没有公开. 同期 Google 的 AMIE 用自对弈的模拟问诊环境训练诊断对话, 它依赖自评和批评者反馈, M2 把反馈交给按病例生成的 rubric.

模拟器在 M2 里被用了三次. 第一次在 rubric 生成器的数据阶段, 用它生成多样的医疗提示. 第二次在 SFT 阶段, 医生模拟器与患者模拟器对话, 合成带推理内容的多轮问诊数据. 第三次在多轮 RL 里当环境. 一套基础设施同时服务数据合成, 奖励构造和在线训练, 这是 M2 投入产出比较高的设计. 代价是**误差会沿三条路径传播**: 模拟器说错的事实, 可能进入 SFT 数据, 也可能让生成器写出针对错误信息的 rubric. 论文在多轮 RL 部分提到会过滤重复生成, 对话过长和角色反转的片段, 对前两处用途没有说如何纠错.

## 2. 训练流程

### 2.1. Mid-training: 2:2:1 配比与三种损失, 在现成底座上补医学

§3.1 的动机是: 通用预训练模型在医疗场景里知识储备不足, 缺乏权威性, 还有时效滞后, 直接做医学后训练容易陷入 「对齐不足或幻觉加重」 的两难, 所以先做轻量 mid-training. 语料来自公开医学教科书, 临床专著, 药物知识库, 最新诊疗指南和脱敏病历报告, 做两步增强. **结构化改写**强调知识保真, 限制引入原文没有或推不出的陈述, 以降低改写带来的幻觉. **显式 CoT 注入**在知识密集段落和关键结论旁自适应插入 「thinking notes」, 内容包括知识关联, 批判反思, 论证验证和病例推演, 与原文交错排布, 用明确标记隔开. 前者延续了 M1 合成流水线 「改写而不编造」 的原则, 后者让模型在 SFT 之前就见过 「读一段医学文本, 再写一段推理」 的格式. 继续预训练的一般做法见 [3.2.6-继续预训练](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.6-继续预训练/3.2.6-继续预训练.md).

防遗忘靠配比和损失两道手段. 医学, 通用, 数学推理语料按 2:2:1 混合, 每条样本按所属任务只走一种损失, 式 (1) 是

$$
\mathcal{L}_{\text{total}}(\theta) =
\begin{cases}
\mathcal{L}_{\text{softmax}}(D_{\text{corpus}}) & \text{医学知识} \\
\mathcal{L}_{\text{masked\_softmax}}(D_{\text{interleaved\_nodes}}) & \text{医学推理} \\
\mathcal{L}_{\text{KL}}(P_\theta \,\|\, P_{\text{ref}}) & \text{通用或数学}
\end{cases}
$$

医学知识走普通的 next-token prediction, 让模型吸收权威知识; 医学推理在交错数据上走 masked 损失, 作用在 「interleaved nodes」 上, 按字面理解是只在插入的推理片段上计损失, 原文部分作为条件. 通用和数学语料不用 next-token 损失, 而是以通用底座为参考模型算 KL. 三种损失在同一个位置 $t$ 上的差别是: 第一种只看数据里的那个 token, 即 $-\log P_\theta(x_t\mid x_{<t})$; 第二种同式, 但原文 token 的权重置零; 第三种按 KL 的定义不看数据里的 token 是什么, 而是在整张词表上比较两个分布 (论文没说是全词表求和还是采样近似), $\sum_v P_\theta(v\mid x_{<t}) \log \frac{P_\theta(v\mid x_{<t})}{P_{\text{ref}}(v\mid x_{<t})}$, 需要参考模型在同一段通用文本上再做一次前向. 论文写的方向是 $P_\theta \| P_{\text{ref}}$, 即反向 KL, 它在 $P_\theta$ 放概率的地方惩罚偏离, 对参考模型有而 $P_\theta$ 丢掉的模式惩罚较弱; 为什么选这个方向, 论文没说. 这一点和常见做法不同: 常规的防遗忘是在混入的通用数据上继续做 next-token 训练, 学的是数据本身; M2 让模型在通用数据上对齐原底座的整个输出分布, 效果接近对底座的自蒸馏, **保住的是底座原有的行为, 而不只是在这些 token 上的似然**. 这套 「域自约束」 取自同一团队的 Baichuan4-Finance. mid-training 的 token 数, 步数和学习率都没有公开, 与 M1 对 20T 各阶段的详细披露形成反差.

### 2.2. SFT: 400 万候选到 200 万条, 知识给 SFT, 推理留给 RL

§3.2 的出发点是: 直接做 RL, 底子不够时会收敛困难, 探索低效, 所以先用 SFT 打推理基础. 候选池超过 400 万条, 来自 M1 内部数据和外部开源数据, 复杂推理链主要由 DeepSeek-R1 生成. 处理分三部分. 通用指令先用语义 embedding 向量化并聚类, 按聚类结果分层采样, 自动滤掉不完整或有歧义的指令, 流程引用了百川对齐报告. 有标准答案的样本用专门验证器做拒绝采样, 有歧义的交给多模型共识. 医学部分针对真实临床流程补数据: 预问诊, 智能分诊, 电子病历生成, 医学 RAG, 医疗安全, 并用医生模拟器和患者模拟器对话合成多轮问诊数据. 最终保留 200 万条, 医学约占 20%, 在 Qwen2.5-32B-Base 上以 32K 上下文训 2 个 epoch. SFT 的一般位置见 [SFT](../../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md).

有一条分配原则值得单独记下: 去掉有缺陷的样本后, 剩下的难题里, **以知识为主的给 SFT, 以推理为主的留给 RL**. 依据是 SFT 擅长知识迁移, RL 通过探索和迭代在多步推理上泛化更好. SFT 与 RL 因此按样本性质分工, 不是简单串行. 医学只占 SFT 的五分之一, 说明这一阶段主要建立通用推理的格式和能力, 医学专长更多来自 mid-training 和 RL 的 rubric 奖励. M2 的推理风格也因此有两个来源: mid-training 的 thinking notes 贴着医学文本写, SFT 的长推理链带有 R1 特有的反复自检和长篇展开. 图 5 里 RL 起点的回答长度约 2300 (读图), 此后在 rubric 奖励下一路变长, 式 (3) 的长度奖励正是对这种倾向的纠偏.

### 2.3. 改进版 GRPO: 式 (2) 的四处改动各治什么

式 (2) 是

$$
J(\pi_\theta) = \mathbb{E}_{q,\ \{o_i\}_{i=1}^G\sim\pi_{\theta_{\text{old}}}(\cdot\mid q)}
\left[\frac{1}{G}\sum_{i=1}^{G}\frac{1}{l_{\max}}\sum_{t=1}^{|o_i|}
\min\Big(r_{i,t}(\theta)\hat A_{i,t},\ \mathrm{clip}\big(r_{i,t}(\theta),1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}}\big)\hat A_{i,t}\Big)\right],
$$

$$
\hat A_{i,t} = R(q,o_i) - \mathrm{mean}\big(R(q,o_1),\dots,R(q,o_G)\big),\qquad
r_{i,t}(\theta) = \frac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}{\pi_{\theta_{\text{old}}}(o_{i,t}\mid q,o_{i,<t})}.
$$

对每道题 $q$ 采样 $G$ 条回答; 同一条回答里所有 token 共用一个优势, 只减组均值; 每个 token 的项除以预设的最大回答长度 $l_{\max}$, 而不是这条回答自己的长度; 式里没有 KL 项. 论文列出四处改动: 去掉 KL 项, 既不限制奖励增长, 也省掉参考模型的计算; 非对称裁剪, 调高上界, 防止熵过早坍缩, 保持探索; 用常数长度归一化, 应对不同医学数据源回答长度差异大的问题; 优势只减均值不除标准差, 缓解多任务的难度偏置. 前两项来自 DAPO (去 KL, Clip-Higher), 后两项来自 Dr. GRPO. 所以 「improved GRPO」 **更准确的说法是 DAPO 与 Dr. GRPO 的组合**. 算法细节见 [02-GRPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md) 与 [03-DrGRPO-去标准差](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.6-其他策略梯度/03-DrGRPO-去标准差/03-DrGRPO-去标准差.md).

后两项在多源医学数据上尤其要紧. 两种长度归一化在同一个 token 上的梯度权重分别是

$$
w_{i,t}^{\text{GRPO}} = \frac{1}{G}\cdot\frac{\hat A_i}{|o_i|}\cdot\frac{1}{\sigma}, \qquad w_{i,t}^{\text{M2}} = \frac{1}{G}\cdot\frac{\hat A_i}{l_{\max}},
$$

$\sigma$ 是组内奖励标准差. 先不看 $\sigma$, 取 $\hat A_i = -0.3$, 一条 1,000 token 的错答每个 token 分到 $-0.3/1000$, 一条 4,000 token 的错答只分到 $-0.3/4000$, 同样错, 写长了每个 token 挨罚少四倍, 模型因此倾向于把错误答案写长; 换成统一的常数 $l_{\max}$ 后, 两条错答每个 token 都是 $-0.3/l_{\max}$, 长回答因为 token 多, 挨的总罚反而更多. 原版把优势除以组内标准差, 一组回答分数都很接近时 (题太易或太难), 标准差很小, 除完后优势被放大, 这些题在梯度里的权重反而偏高; 医学数据里有规则判分的选择题, 也有 rubric 打分的开放题, 分数分布差异很大, 不除标准差可以避免某一类题主导训练. DAPO 的 dynamic sampling 在 M2 里没有在线实现, 但规则 RL 阶段用上一版 SFT 模型离线筛掉太易和太难的题, 起到类似作用. 组大小 G, ε_low, ε_high, l_max 和学习率都没有给数值.

和 M1 对照, 变化更明显. M1 的 RL 用 PPO, 要训练独立的奖励模型和价值模型, ELO 还是自创的隐变量目标. M2 去掉了价值模型, 参考模型和标量奖励模型, 只剩策略模型加外部验证器, **RL 的主要开销从训练附属模型转向运行验证器服务**, 第 1.2 节的亲和机制就是为这笔开销准备的. PPO 一侧的背景见 [04-PPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md).

### 2.4. 三阶段 RL: 奖励由硬到软, 由单轮到多轮

第一阶段是**规则 RL**. 任务池涵盖数学推理, 编程, 通用指令遵循, 医学知识问答和医学诊断, 经四步过滤: 只留答案明确且唯一的题, 降低规则验证器的误判; 用强模型验证, 只留模型输出与参考答案一致的题, 减少噪声; 用 LLM 判断是否需要推理, 只留需要推理的; 用上一版 SFT 模型筛出难度合适的题. 结果是 AIME 保持稳定, SuperGPQA, MedXQA 等医学基准明显提升 (正文没给数字); 复杂病例的诊断和治疗规划进步明显, 知识型医学问答提升较小. 这一阶段的目标是培养可迁移的推理能力, 而不是再灌医学知识. 三个阶段按奖励有多开放来排: 先用最可靠的 0/1 奖励打推理底子, 再引入噪声更大的 LLM 裁判.

第二阶段是 **rubric RL**. 提示覆盖初诊, 病例分析, 治疗方案解释, 用药教育, 预后与随访; rubric 维度包括诊断准确性, 问诊逻辑, 治疗合理性, 沟通与共情, 医学伦理与安全, 证据引用规范, 表达清晰与结构. rubric 驱动下模型会 「面面俱到」, 回答冗长, 于是式 (3) 加了**条件长度奖励**:

$$
R(q,o_i) = R_{\text{rubric}}(q,o_i) + R_{\text{length}}(q,o_i),\qquad
R_{\text{length}}(q,o_i) =
\begin{cases}
\dfrac{4}{\sqrt{|o_i|}}, & P_{80} > \text{thresh}\ \text{且}\ R_{\text{rubric}}(q,o_i) \ge P_{80} \\
0, & \text{其他}
\end{cases}
$$

$$
P_{80} = \mathrm{quantile}\big([R_{\text{rubric}}(q,o_1),\dots,R_{\text{rubric}}(q,o_G)],\ 0.2\big).
$$

$4/\sqrt{|o_i|}$ 的形状取自 「Fast on the easy, deep on the hard」 的幂律. 式中的 P80 定义为组内 rubric 分的 0.2 分位数, 也就是组里 80% 的回答都不低于它; 第一道门要求 P80 超过阈值 thresh, 即组里绝大多数回答质量都过线; 第二道门要求该回答自己不低于 P80, 即排在组内前 80%. **名字叫 P80, 算的是 20% 分位数**, 读公式时容易混. 奖励的量级也不大: 3,000 token 的回答拿到约 0.073, 6,000 token 约 0.052, 相对 0 到 1 的 rubric 分只是零头; 但组相对优势只看组内差异, rubric 分接近时, 这零点零几的差距足以决定谁的优势为正.

图 5 显示了这道门的效果 (读图). 前约 60 步, 加与不加长度奖励的回答长度几乎重合, 都从约 2300 涨到约 2700, 说明门还没打开; 之后不加长度奖励的一路涨到约 5800, 加了的先涨到约 4200 (约 160 步), 再回落到约 3200; 左图的得分曲线两者交替上升, 在 HealthBench 随机子集上从约 0.52 到约 0.58. 到 250 步时, 长度约为不加时的 55%, 得分没有下降. 这和部署直接相关: 单张 4090 在最好的配置下最长也只有 21,133 token, 一条近六千 token 的回答加上长病历输入, 很快就会触顶.

第三阶段是**多轮 RL**. 患者侧由按专科, 患病率, 年龄, 性别, 合并症分层的脱敏病例驱动; 每轮交互后截取一段对话, 交给 rubric 生成器现场出 rubric, 只强化模型的下一轮回复. 模拟器的噪声 (重复生成, 对话过长, 角色反转) 靠严格过滤处理. 论文称短片段的反馈更稠密, 信噪比更高, 能减轻上下文误差累积和 「奖励泄漏振荡」. 片段级还有一个和 GRPO 相关的理由: 组相对优势要求同一个上下文下采样 G 条回答互相比较; 若按整段会话展开, 医生第一轮问法不同, 模拟器的回答随之不同, 到第三轮时 G 条轨迹面对的已经是不同的患者陈述, **「同题比较」 的前提就不成立**. 固定对话前缀, 只在下一轮上采样, 每组共享同一上下文, 生成器也只需按这个上下文出一次 rubric. 代价是跨轮规划的收益没有进入目标, 论文在 §7 把整段会话 RL 列为后续工作.

## 3. 评测, 部署与家族位置

### 3.1. 评测: HealthBench 的分数, 中文 MDT 的偏好, 和通用能力

主论据来自 HealthBench. 图 6, 图 7 中 M2 总分 60.1, Hard 34.7, Consensus 91.5; 开源次名 gpt-oss-120B 为 57.6, 30, 90; 闭源的 o3 为 59.8, 31.6, 92.8; GPT-5 在 Hard 上是 46.2 (读图). 结论节说 M2 是 「全球仅有的两个 Hard 超过 32 分的模型之一」, 另一个是 GPT-5, 两者之间差 11.5 分. 图中的 Qwen2.5-32B 总分约 28.2, Hard 约 0 (读图), 同一家族同一尺寸, 经过 M2 这套后训练总分提高三十多分, **这是整套流程最直接的证据**, 虽然无法拆出 mid-training, SFT 和各阶段 RL 各贡献多少. 分项里正文列出的领先项有 Context Seeking 55.8 (信息不足时是否主动追问) 和 Emergency Referrals 74.6 (能否识别需要紧急转诊的情形), 正好是患者模拟器和多轮 RL 着力训练的能力: 模拟器会隐瞒信息, 只在被问到时才透露. 正文没有提 Accuracy 轴, 与规则 RL 阶段 「知识型问答提升较小」 的观察一致. 评测设置在表 1 脚注: max_tokens 32k, 数学放宽到 64k, temperature 0.6, 单次采样, 没有多次投票这类 TestingTime 手段.

HealthBench 用模型裁判按 rubric 打分, M2 训练时也是模型裁判按 rubric 打分, 两者形式相近, 高分里可能有 「学会迎合 rubric 式裁判」 的成分, 所以 §4.2 的中文 MDT 对比更重要. 它有 57 个来自中国顶级医院多学科会诊的复杂病例, 平均每例约 3,000 个汉字, 没有金标准答案, 由合格的医学专家在沟通, 检查, 诊断, 治疗, 安全五个维度上, 用十项加权指标对 M2 和 gpt-oss-120B 做偏好评判, 安全和准确权重最高. 图 11 的三段式结果 (M2 更好 / 相同 / gpt-oss 更好) 为: 沟通 67% / 11% / 22%, 检查 45% / 16% / 39%, 诊断 43% / 17% / 40%, 治疗 37% / 30% / 33%, 安全 34% / 36% / 30%. 正文说 M2 「在全部五个维度上更优」, 但诊断只领先 3 个百分点, 治疗和安全领先 4 个, **57 例的样本下这些差距很难说显著**; 真正拉开的是沟通, 对应的是可读性, 结构和简洁, 与长度奖励和 rubric 里的沟通维度对得上. 正文还提到部分优势来自更贴近中国临床指南.

§4.1 和附录 B 用一个具体病例说明两者差在哪里: 产科住院医师询问妊娠期糖尿病患者的胰岛素剂量是否需要调整. M2 按美国妇产科医师学会 (ACOG) 指南回答了是否需要调整, 建议保守调整, 强调评估患者具体情况, 提醒避免低血糖并做胎儿评估, 还建议与糖尿病教育者协作指导饮食; gpt-oss-120B 没有考虑低血糖风险. 这类差别在 rubric 里通常对应一条 「提及风险」 的正向条目和一条 「忽略风险」 的负向条目. **个案能说明方向, 不能说明频率**; 图 8 用参数量作横轴画 HealthBench 的 Pareto 前沿, 论证 「小模型高分」, 真正支撑部署成本论点的还是第 3.2 节的单卡数据.

通用能力方面, 表 1 以 Qwen3-32B (Thinking) 为对照: AIME24 83.4 对 81.4, AIME25 持平于 72.9, IFEval 86.0 对 85.0, CF-Bench 77.6 对 75.7, Arena-Hard-V2.0 45.8 对 44.5, AlignBench 8.77 对 8.72, WritingBench 8.56 对 7.90. 医学后训练没有损害通用推理, 写作类提升最大. 对照组选的是 Qwen3-32B, 而 M2 的底座是 Qwen2.5-32B; 同底座的 Qwen2.5-32B-Instruct 没有出现在表里. 评测证据的一般读法见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据.md).

### 3.2. 部署: 单卡 4090 上的量化与 KV 预算, 投机解码

§5 的推理优化全部由现成组件拼成. W4A16 用 AutoRound, 以带符号梯度下降优化取整参数; W4A8 先用 Hadamard 旋转压激活离群值 (出自 QuaRot), 再用 GPTQ 借助 Hessian 做 4-bit 权重量化, 按 QQQ 格式打包. 校准数据里掺入一定比例的原模型自己生成的回答, 精度更高, 这是 「用模型自身分布做校准」. KV cache 用 FP8 E4M3, 为兼容 SGLang 和 vLLM 采用静态 scale; 实测按校准数据逐层统计 scale 与固定 1.0 差别不大, 于是直接用 1.0. 背景见 [6.3.1.1-权重量化](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/6.3.1.1-权重量化.md) 与 [6.3.1.2-KV缓存与向量量化](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/6.3.1.2-KV缓存与向量量化.md).

表 2 列出单张 RTX 4090 (24G), SGLang, 单请求下的最大序列长度: W4A16 9,982, W4A16-KV8 19,965, W4A8 10,566, W4A8-KV8 21,133. KV 从 BF16 换成 FP8, 长度几乎正好翻倍, 说明权重和运行时开销占掉的显存基本固定, **留给 KV cache 的是一块定额**. 按 Qwen2.5-32B 公开配置 (64 层, 8 个 KV 头, head dim 128) 算, BF16 下每 token 的 KV 约 0.25MB, 9,982 token 约 2.4GB; 32B 参数在 4-bit 下约 16GB, 其余被 embedding, 激活和引擎开销吃掉. W4A8 比 W4A16 多出约 600 token, 来自激活量化省下的少量显存. 这块只有两个多 GB 的 KV 定额, 正是长度奖励要把回答压短的现实理由.

投机解码用 Eagle-3, draft 模型基于 M2 架构, 训练数据包括医学对话, 临床笔记和结构化医学知识, 并用 M2 自己生成的回答合成, 让 draft 分布贴近目标模型. 单张 4090, 4-bit 量化, 4096 token 提示下, 预测准确率 73%, 平均接受长度 3.28, 吞吐从 41.5 提到 89.9 tokens/s, 加速 2.17×. 接受长度 3.28 意味着目标模型平均每次验证推进三个多 token, 单流生成受显存带宽限制, 每步读一遍权重, 推进的 token 越多越划算. EAGLE 系列原理见 [02-EAGLE系列深度解析](../../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/02-EAGLE系列深度解析.md).

### 3.3. 放回家族: M2 留下了什么, 没公开什么

M2 留给 [M3](../m3-235b/m3-235b-analysis.md) 的主要是三样. 第一是验证器基础设施: 三模块患者模拟器, 按病例生成 rubric 的生成器, 带亲和路由的评分服务; M3 的动态 rubric 演化和分段流水线 RL 都建在这套设施上. 第二是一份 RL 配方: DAPO 与 Dr. GRPO 的组合, 离线难度筛选, 带质量门控的长度奖励. 第三是 「借底座做后训练」 的路线本身, M3 换成了 Qwen3-235B-A22B 这个 MoE 底座, RL 算法也相应换成了更适合 MoE 的 GSPO. M3 引言列出的三处瓶颈 (多任务环境难以稳定融合, 长程交互的信用分配, 奖励饱和伴随的幻觉) 几乎一一对应 M2 在 §3.3.3 和 §7 承认的缺口.

从复现角度看, M2 披露得不完整. 模拟器各单元和 rubric 生成器的参数量, mid-training 的语料规模与步数, 三个 RL 阶段各自的步数, G, 裁剪上下界, thresh, l_max, HealthBench 评测所用的裁判模型, 都没有给. 开源的是最终的 32B 策略模型和量化版, 验证器系统本身没有公开. **外部团队能直接用 M2, 却很难复刻它的训练过程**. 报告自己列的局限是边缘病例的幻觉, 推理稳定性, 工具调用与外部知识检索, 以及整段会话 RL. 能迁移到其他缺少标准答案领域的经验有三条: 投入先给验证器, 再给策略模型; 模拟环境里把生成和核验拆给不同单元; 长度控制以质量达标为前提, 图 5 显示这样做能在得分不降的情况下把回答压短近一半.
