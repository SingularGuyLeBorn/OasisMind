# Claude 3 (2024): 三档家族, 视觉入场和拒答率的回调

> 源文是 Anthropic 在 2024 年 3 月 4 日发布的产品公告 「Introducing the next generation of Claude」, 属于博客式发布页, 不是技术报告. 页面有两张评测表, 四张图表和三档价格, 但没有参数量, 层数, 训练数据, 训练方法或架构描述. 公告和模型卡都没写的环节, 标 「本页没有」.

来源: 同目录 `claude-3.md` 与 `claude-3.pdf`, 共 15 页, 配图 10 张 (均在 `images/`). 对照译稿和逐段疑问见 `claude-3-bi.md`. 引用的原文数字和链接以源 md 为准. 同一代的模型卡正文在同级目录 `claude-3-opus` 与 `claude-3-sonnet` 两篇, 本文只借用其中与公告对得上的几句.

## 1. 材料与阵容

### 1.1. 材料性质: 一篇数字比往年多的产品页

这份 PDF 分成两块. 第 1 页到第 10 页是公告正文, 从发布 Claude 3 家族开始, 依次讲智能, 速度, 视觉, 拒答, 准确率, 长上下文, 安全, 易用性, 三张模型卡片, 上线渠道和后续路线, 最后是一条脚注. 第 10 页末尾到第 15 页是 2026 年抓取时存下的推荐文章, 导航和页脚, 其中的 Mythos, Fable 等名字不属于这次发布.

和一年前的 Claude 发布页相比, 信息量多了不少: 一张 10 行 7 列的文本能力表, 一张 5 行 6 列的视觉能力表, 一张拒答率柱状图, 一张事实问答三分类柱状图, 一张 200K 范围的大海捞针热力图, 以及每百万 token 的价格. 按 「数据, 架构, 算法, 预训练, 后训练, 评测」 去对, 公告本身只覆盖评测和后训练结果; 数据与训练方法要去同日发布的模型卡找. 模型卡写明: 预训练语料是截至 2023 年 8 月 的公开网页, 第三方非公开数据, 标注服务与外包人员提供的数据, 以及内部生成的数据, 做过去重和分类过滤, 没有用用户提交的 prompt 或输出. 架构和参数量, 两份材料都没有.

### 1.2. 三档定位与发布节奏

公告把 Claude 3 定义成一个家族, 按能力从低到高排成 Haiku, Sonnet, Opus, 让用户在智能, 速度, 成本之间取舍. Opus 是 「most intelligent」, 面向高度复杂的任务; Sonnet 是 「ideal balance between intelligence and speed」, 面向企业级大规模部署; Haiku 是 「fastest, most compact」, 面向近乎即时响应的场景. 用途跟着分层: Opus 列任务自动化, 研发, 战略分析; Sonnet 列 RAG 与检索, 销售, 代码生成; Haiku 列客服, 内容审核, 物流和库存.

发布是分批的. 当天 Opus 和 Sonnet 在 claude.ai 和 API 上可用, API 在 159 个国家全面开放; Haiku 三次被写成 「available soon」. Sonnet 驱动免费版, Opus 给 Claude Pro 用户. 云平台方面, Sonnet 当天上 Amazon Bedrock, 在 Vertex AI Model Garden 是私测. 三档共用同一套训练流程还是各自独立, 模型卡的数据说明对三款统一写 「Claude 3 models are trained on ...」, 大小差别和是否互相蒸馏都没写. 三档结构从这一代起固定下来, 后续 3.5, 4, 4.5 代都沿用.

## 2. 能力, 速度与价格

### 2.1. 文本能力表: 设置不对齐的比较

第 3 页的表列了十个基准: MMLU, GPQA Diamond, GSM8K, MATH, MGSM, HumanEval, DROP, BIG-Bench-Hard, ARC-Challenge, HellaSwag. 对比对象是 GPT-4, GPT-3.5, Gemini 1.0 Ultra, Gemini 1.0 Pro, 脚注说只选了已商用且公布过评测的模型. Opus 在十行里都排第一, Sonnet 大体与 GPT-4 和 Gemini 1.0 Ultra 同一梯队, Haiku 普遍高于 GPT-3.5 和 Gemini 1.0 Pro. 差距最大的集中在推理和数学: GPQA Diamond Opus 50.4% 对 GPT-4 35.7%; MATH 60.1% 对 52.9%; MGSM 90.7% 对 74.5%; HumanEval 84.9% 对 67.0%. MMLU, ARC-Challenge, HellaSwag 这类较早的基准上, 头部几家分差在 1 个百分点以内.

每个格子都带评测设置, 这是读表时绕不过去的部分. Claude 一侧几乎全用零样本, 推理类加 CoT; 对手一侧不少来自多样本, GSM8K 行两款 Gemini 用的是 32 次采样多数表决, 属于 **TestingTime** 多花算力. 零样本 CoT 能拿高分, 本身说明模型在后训练里学过 「先写推理再答」 的格式, 这是 SFT 和 RL 阶段的产物, 不是预训练能力的直接读数 (推测). 脚注还补了一句: 有人针对评测优化提示词后, 给新版 GPT-4T 报出过更高分. 放在一起看, 这张表适合判断三档之间的相对位置和 Opus 在推理, 数学, 代码上的大致领先幅度, 不适合拿单个格子下精确结论. 设置对分数的影响见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

### 2.2. 速度, 价格与上下文窗口

速度部分没有绝对数字. Haiku 是 「fastest and most cost-effective model on the market for its intelligence category」, 读一篇约 10k token, 带图表的 arXiv 论文不到 3 秒; Sonnet 在绝大多数工作负载下比 Claude 2 和 2.1 快 2x; Opus 与 Claude 2 和 2.1 速度相近. 没有延迟分布, 吞吐或硬件条件.

价格是全文最硬的数字. 每百万 token, Opus 输入 \$15, 输出 \$75; Sonnet \$3 / \$15; Haiku \$0.25 / \$1.25. 三款输出价都是输入价的 5 倍, Opus 是 Sonnet 的 5 倍, Sonnet 是 Haiku 的 12 倍. 第 2 页 「智能对成本」 示意图横轴是对数刻度的价格, 纵轴是无刻度的基准分. 上下文窗口发布时统一 200K; 公告说三款都能接受超过 1 million tokens 的输入, 可能向特定客户开放, 模型卡片上只有 Opus 的 200K 带星号. 1M 靠什么实现, 本页没有, 通用路线见 [长上下文与外推技术](../../../../llm-guide/2-核心原理与架构/2.7-长上下文与外推技术/2.7-长上下文与外推技术.md).

### 2.3. 视觉能力: 第一次作为新模态推出

Claude 3 是这个系列第一次在公告里推出视觉. 页面说它能处理照片, 图表, 曲线图和技术示意图, 并点出企业客户的知识库里多达 50% 是 PDF, 流程图, 演示文稿这类格式. 视觉编码器是什么, 图像怎样变成 token 进入语言模型, 训练用了哪些图文数据, 公告和模型卡都没有; 一般做法见 [视觉语言模型](../../../../llm-guide/8-多模态/8.2-视觉语言模型/8.2-视觉语言模型.md).

视觉表有五个基准: MMMU (val), 文档视觉问答 (ANLS), MathVista (testmini), AI2D, 图表问答. 对比对象是 GPT-4V, Gemini 1.0 Ultra, Gemini 1.0 Pro. Claude 3 在 AI2D 上领先较多, 三款都在 86% 以上, 对手在 80% 以下; 其余几行与 Gemini 1.0 Ultra 互有高低. 公告对视觉用的词是 「on par with other leading models」, 与文本部分的 「outperforms」 不同, 和表里的数字一致. 一个细节是三档在文档问答和图表问答上几乎一样, Haiku 的图表问答 81.7% 甚至最高; 说明这两类任务更吃视觉编码和 OCR 质量, 语言模型大小的作用不大 (推测). 基准介绍见 [VLM的评测与基准](../../../../llm-guide/8-多模态/8.2-视觉语言模型/06-VLM的评测与基准/06-VLM的评测与基准.md).

## 3. 行为与安全

### 3.1. 拒答回调与事实准确率

公告把 「更少的拒答」 单列一节, 自我检讨说以前的 Claude 常常拒绝本可以回答的问题. 配图对比三款 Claude 3 和 Claude 2.1 在无害提示上的错误拒答率, 前者都在 10% 上下, 后者约 25% (读图). 这和同级目录 Claude 2.1 一篇的发现正好接上: 2.1 把错答挪到了拒答, 这一代则在往回拉. 能对上的公开说明是, Anthropic 在 「Claude's Character」 一文里写, Claude 3 是第一个在对齐微调里加入 **character training** 的模型: 列出好奇, 开放, 深思等性格特征, 让模型针对相关消息生成多个回答, 按与这些特征的契合度给自己的回答排序, 再用这些排序训练偏好模型, 属于 **Constitutional AI** 的一个变体. 模型卡还写明宪法新增了一条尊重残障权利的原则, 来自 Collective Constitutional AI 研究. 这些改动和拒答率下降之间有没有直接因果, 两份材料都没给实验.

准确率一节用一批复杂的事实性问题, 挑当前模型的已知弱点, 把回答分成答对, 答错 (幻觉), 承认不知道三类. 结论是 Opus 的答对比例是 Claude 2.1 的 两倍, 答错也有所下降. 三分类的好处是能看出模型是在更多尝试回答, 还是在更少胡说; 结合拒答图, 这一代的变化方向是 「少拒, 多答对, 错答不增」. 同一节预告了引用功能, 让模型指向参考材料里的具体句子, 发布时尚未开放. 题量, 判分者和误差, 公告都没给.

### 3.2. 长上下文召回和一次 「识破测试」

长上下文部分用大海捞针评测 (NIAH). 公告对它做了两处加固: 每个提示从 30 组随机的 needle/问题对中取一组, 语料换成众包的多样化文档. Opus 召回准确率超过 99%, 配图是一张 16 个长度乘 15 个位置的热力图, 覆盖 12k 到 200k, 几乎整片深绿. 这组加固正对着同级目录 Claude 2.1 一篇里的问题: 单一 needle 和固定语料容易被 prompt 写法左右.

插曲是 Opus 在某些情况下认出了 needle 句子像是人为插进原文的, 公告写成 「identified the limitations of the evaluation itself」. 这句话后来被反复引用, 因为它是 「评估意识」 在公开材料里较早的一次露面: 模型不仅完成测试, 还说出了自己在被测试. 从评测方法看, 它提示 NIAH 这类合成测试的天花板: needle 与上下文语义不连贯时, 找到它更像异常检测. 同级目录 Sonnet 4.5 之后的系统卡把评估意识当作专门的风险项测量, 起点可以追到这里. 测试方法见 [大海捞针测试](../../../../llm-guide/3-预训练/3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md). 页面最长实测到 200K, 1M 没有配数据.

### 3.3. 安全分级, 偏见和易用性

安全部分列了风险清单: 虚假信息, CSAM, 生物滥用, 选举干预, 自主复制能力. 方法上只点名 Constitutional AI, 措辞是 「continue to develop methods such as」, 另说针对新模态做过隐私方面的调整. 分级结论是 **ASL-2**: 公告承认 Claude 3 在生物知识, 网络安全知识和自主性上比前代进步, 但依据 **Responsible Scaling Policy** 和红队评估, 判断造成灾难性风险的可能性微乎其微, 会继续监测离 ASL-3 门槛多远. RSP 的思路是先定能力阈值, 模型越过阈值就必须上对应等级的防护, 评估在发布前做. 偏见方面引用 BBQ 基准, 说比之前的模型偏见更少. 具体分数都交给了模型卡. 分级框架背景见 [部署治理与持续保证](../../../../llm-guide/5-评测、安全与治理/5.4-部署治理与持续保证/5.4-部署治理与持续保证.md).

「Easier to use」 一节讲三点: 更能遵循复杂的多步指令, 更能贴合品牌语气, 更擅长输出 JSON 这类结构化格式. 最后一节的路线是几个月内频繁更新, 推出 Tool Use (function calling), 交互式编程 (REPL) 和更高级的 agent 能力, 都是将来时. 所以发布当天的 Claude 3 是一个能读图, 处理 200K 上下文, 输出结构化文本的对话模型, 工具调用和引用都在后面. 指令遵循和结构化输出属于后训练数据覆盖的问题, 公告没给评测数字. 结构化输出背景见 [结构化输出](../../../../llm-guide/13-Agent/13.1-Agent核心组件/13.1.5-结构化输出/13.1.5-结构化输出.md).

## 4. 配图与边界

### 4.1. 十张配图

承载信息的有四张: 第 2 页的价格与能力示意图, 第 5 页的错误拒答率和事实问答三分类, 第 6 页的 Opus 大海捞针热力图. 四张都没标数值, 读数只能目测. 抽取工具按紧随其后的标题给图片命名, 导致三张图文件名与画面错位: p05-improved-accuracy 画的是拒答率, p05-long-context-and-near-perfect-recall 画的是准确率, p06-responsible-design 画的是热力图.

其余六张是页面元素: 第 1 页橙底白色人头剪纸插画, 第 10 页 X 和 LinkedIn 分享图标, 第 11 页三张推荐卡片上的向右箭头, 以及 p11-pricing-https-claude-com-pricing, 它是页脚 Products 栏截图, 画面里没有价格.

### 4.2. 材料边界

这篇公告能回答 「Claude 3 有哪三档, 各自多强, 多快, 多贵, 何时在哪里能用」, 以及拒答, 准确率, 长上下文召回三项内部评测的方向. 它回答不了模型规模, 架构, 视觉编码方式, 长上下文实现和后训练配比. 第 1.1 节的数据说明和第 3.1 节的 character training, 残障权利原则来自模型卡与 Anthropic 博客, 不是本页原文.
