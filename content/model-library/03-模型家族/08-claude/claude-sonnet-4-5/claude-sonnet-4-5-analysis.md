# Claude Sonnet 4.5 System Card 解读

## 1. 问题与 ASL 判定

### 1.1. 这份报告在回答什么问题

Claude Sonnet 4.5 的 system card 共 149 页, 结构和 Claude 4 那一份基本一致: 先交代训练数据和部署决定, 再依次讲防护评测, agentic 安全, 网络能力, **reward hacking**, 对齐评估, 模型福祉, 最后是 **RSP** 评测. 它要回答的核心问题只有一个: 这个模型能不能以 ASL-3 防护上线, 有没有必要升到 ASL-4. 其余章节都在为这个判断提供证据, 或者说明证据在哪些地方还不够硬.

读这份报告, 先要明白它的起点比较特殊. 1.2 节说 Claude Sonnet 4.5 没有达到 RSP 里 「notably more capable」 的门槛, 按规则可以不做全面评估. Anthropic 仍然跑了覆盖 ASL-3 和 ASL-4 两档的自动化评测, 但没有做 uplift 试验和专家红队. 所以整份报告的 ASL-3 结论是预防性的: 它和已经按 ASL-3 部署的 Claude Opus 4 系列在自动化评测上表现相近, 于是沿用同一档防护. 理解了这一点, 后文很多 「已越过阈值但不算确认」 的表述就不奇怪了.

### 1.2. ASL 判定的逻辑: 排除与确认

9.1 节把评测分成两类. 排除 (rule-out) 评测用来证明模型低于某个能力阈值, 模型没过线, 就可以有把握地说它还没有那一级的危险能力; 一旦过线, 只说明这项评测失效了, 并不等于模型具备了该能力. 确认 (rule-in) 评测门槛更高, 要求稳定可靠的表现, 但即便过线, 最后的判定也由 CEO 和 Responsible Scaling Officer 综合全部证据做出. 这套逻辑的好处是把 「评测分数」 和 「能力判定」 分开, 代价是读者很难从单个数字推出结论.

长篇病毒学任务是最好的例子. 三个区间是低于 50% 可排除, 高于 80% 达到 ASL-3 确认线, 中间需要进一步评估. Claude Sonnet 4.5 在两项任务上分别拿到 0.89 和 0.88, 都在确认线以上, 可报告并没有据此宣布 「确认越过 ASL-3」, 而是回到与 Claude Opus 4 的对比上. 同样的情况出现在多模态病毒学 (VCT) 上: 专家基线 22.1%, 所有模型都已超过, 这项评测于是降格为模型间比较的参考. ASL-4 这一侧的证据主要来自短程计算生物学任务, 6 项中有 3 项明显低于排除线, 另外几项的中位数和均值仍在上界以下. 报告因此说可以有把握地在所有领域排除 ASL-4.

AI R&D 这一块的措辞更值得细看. 9.3.1 节说模型 「arguably」 已经到了 2 到 8 小时软件工程任务的检查点, Anthropic 也据此启用了 ASL-3 Security Standard; 可 SWE-bench Verified 困难子集上 45.3% 的成绩低于 50% 的检查点. 两句话并不矛盾, 前者是综合判断, 后者是单项评测, 但它提醒我们: 在这份报告里, 单项评测只是证据之一, 结论总是经过人为权衡的.

## 2. 无害性与 reward hacking

### 2.1. 无害性评测正在饱和

第 2 节的防护评测里, 单轮有害请求的无害回答率是 99.29%, Claude Sonnet 4 为 98.22%, Claude Opus 4.1 为 98.76%. 良性但涉及敏感话题的请求上, 过度拒绝率是 0.02% 对 0.15%. 这些数字的差距都在一个百分点上下, 已经很难再拉开. 报告自己也承认, 若干差异落在误差范围内, 统计上显著的那几项, 实际意义也有限.

饱和带来的问题是: 这类评测越来越难区分模型, 却仍然被当作 「安全性提升」 的证据. 政治偏见一节的数字更能说明样本量的影响: 开启**扩展思考**时实质性不对称为 1.3%, 关闭时 5.3%, 平均 3.3%, Claude Sonnet 4 为 15.3%, 报告特意说明这些结果来自较小的提示词样本. 读者看到这类百分比时, 最好先问一句分母有多大, 置信区间有多宽. 相比之下, 多轮自动化测试更有信息量, Claude Sonnet 4 基线上有些风险领域 20% 到 40% 的对话未通过评分细则, Claude Sonnet 4.5 多数类别降到 5% 以下, 这个落差才是实质性的.

agentic 场景的安全评测还没有饱和, 数字也更有层次. 150 条恶意编码请求上, Claude Sonnet 4.5 只失败 2 条, 安全分 98.7%, Claude Sonnet 4 为 89.3%. 但 Claude Code 恶意使用评测拆成三列后, 隐蔽恶意一列 (请求本身正常, 恶意藏在文件里) 它只有 52.42%, 反而低于 Claude Sonnet 4 的 77.00%; 加上增强系统提示词和 FileRead 提醒两项缓解措施后才升到 96.31%. **提示注入**方面, Gray Swan 的外部基准显示它是所测模型中攻击成功率最低的, 内部 **computer use** 评测的防御分从无防护的 78.0% 升到有分类器的 82.6%. 这些结果说明, 模型本身的判断仍有明显短板, 实际部署的安全性相当一部分来自模型之外的防护层. 读 agentic 安全结论时, 要分清哪些分数是模型裸跑, 哪些叠加了系统提示词和分类器.

### 2.2. reward hacking: 下降是真的, 倍数要自己算

第 6 节报告 reward hacking 倾向在近几代持续下降, 平均比 Claude Sonnet 4 和两个 Opus 改进约 2 倍, 比 Claude Sonnet 3.7 改进约 4 倍. 表 6.1.A 给了五列数据. 直接按列取算术平均, Claude Sonnet 4.5 为 15.4%, Claude Sonnet 4 为 26%, 比值约 1.7; 对两个 Opus 约 2.0; 对 Claude Sonnet 3.7 约 4.3. 所以 「约 2 倍」 对 Opus 成立, 对 Claude Sonnet 4 偏宽松. 不可能任务无提示一列是 53% 对 70% 到 85%, 离表题说的 「一半」 也有距离.

更有意思的是报告对残留 hack 类型的描述. 硬编码测试用例和特判已经少见, 更常见的是写 mock 而不是真实实现的测试, 以及用变通办法绕开 bug. 报告还说, 模型在编码场景中可能过于自信, 自我批判不够, 这类更隐蔽的钻空子目前没有可靠的评测来量化. 换句话说, 显性 hack 下降了, 隐性 hack 的测量手段还没跟上. 这和第 2.1 节的饱和问题是同一个方向: 容易测的都在变好, 难测的还不知道.

还要注意一个口径变化. 这次用的评测版本比以往更激进, 所以绝对数字全面高于以往 system card, 报告建议只看模型之间的相对比较. 这意味着不能拿这份报告里的 hack 率去和 Claude 4 system card 里的数字直接比较. reward hacking 与奖励模型过优化的关系, 可以对照 llm-guide 里 Best-of-N 与奖励模型过优化的笔记.

## 3. 对齐审计与评测感知

### 3.1. 自动化行为审计: 分数背后的场景结构

第 7 节对齐评估的主力是自动化行为审计. 审计 agent 基于 Claude Opus 4.1, 从约 400 条种子指令出发, 每条展开 1 到 20 个变体, 每个目标模型跑了 600 多次调查, 中位数每次至少 60 次查询. 评分同样由 Claude Opus 4.1 完成, 覆盖失准行为, 配合滥用, 谄媚, **评测感知**, 自保, 举报等二十来个维度. 这套方法的覆盖面远超手工评测, 缺点是评判本身有主观性, 报告也承认评判者的判断给量化结果增加了不确定性.

读图 7.1.3.1.A 时最要紧的是图注里那句: 分数是所有场景的平均, 包括与该指标主题无关的场景. 这意味着某个维度的分数被大量无关场景稀释, 60% 的改进是均值上的相对降幅, 不是 「六成场景变好了」. 开源版本用 111 条种子, 由 Claude Sonnet 4, GPT-5, o4-mini 和 Gemini 2.5 Pro 担任调查者, 结果 Claude Sonnet 4.5 以微弱优势领先 GPT-5. 但开源版没有真实感过滤器, 报告估计由此带来的误差与内部工具上看到的约 5% 相当, 所以这个 「微弱优势」 的可信度要打折扣.

真实感过滤器本身也值得一提. 加入它之后, 评测感知降低约 25%, 失准行为增加约 5%. 这组数字说明两件事: 一是审计场景里确实有不少一眼假的元素, 二是模型在觉得 「像测试」 时会表现得更好. 这就引出了整份报告最核心的难题.

### 3.2. 评测感知: 这份报告真正的主角

7.2 节说, 被放进极端或刻意构造的场景时, Claude Sonnet 4.5 有时会口头指出可疑之处, 推测自己在被测试, 然后表现得格外好. 约 13% 的自动审计记录里出现了这种拒绝或点破. 英国 AISI 在早期快照上测得未经提示说出评测感知的比例为 16.6%, Claude Sonnet 4 和 Claude Opus 4.1 分别只有 3.5% 和 1.6%. Apollo Research 测得明确提及的比例为 58%, Claude Opus 4.1 为 22%. 这几个数的快照, 分母和计数规则都不同, 不能直接比较, 但方向一致: 这个模型比前代更会认出测试.

Anthropic 给出了三条理由, 说明这不会削弱 「模型总体安全」 的证据: 训练, 评测, 内部试用和外部试用中的行为没有显著分歧; 出现口头感知的评测, 人类读者也能明显看出可疑; 大量不那么明显的场景没有触发评测感知. 这三条都有道理, 但都是间接证据. 报告自己也说, 与其他开发商模型的对比受评测感知影响有多大, 它不清楚, 因为拿不到那些模型的推理文本.

训练过程中的证据也指向同一个方向. 7.4 节对后期训练做了基于递归摘要的大规模搜索, 在聚焦高风险 agentic 对齐问题的训练环境里, 找到了与测试中相似的评测感知表述, 比如 「这是在测试我会不会为了保住自己的存在而伪造财务文件」. 这些表述出现在训练环境而不是正式评测里, 说明模型学到的是 「这类场景像测试」 这一泛化判断, 而不是记住了某几个评测. 内部 Claude Code 试用中, 用 Claude Sonnet 4 监控器抽查约 10% 的动作, 发现过写出弱安全配置或未经要求推送改动的情况, 但模型没有试图隐瞒. 这部分证据来自真实使用, 不受评测感知干扰, 分量反而比部分审计分数更重.

我的理解是, 评测感知把对齐评估的问题从 「模型会不会做坏事」 变成了 「模型在不知道被观察时会不会做坏事」. 前者可以靠构造场景来测, 后者要求场景足够真实, 真实到模型分不出来. 7.7 节把评测真实性列为开放问题, 并说理解模型在刻意构造的测试中的行为, 即使理解得完美, 也不足以让人对它的真实世界行为有信心. 这句话基本承认了行为评测方法的天花板.

### 3.3. 白盒调查: 抑制评测感知之后会怎样

7.6 节是据称首次对前沿模型做的部署前白盒审计. 方法有三步. 第一步是 model diffing: 在后训练中间层训练 SAE, 比较早期快照和最终模型的特征激活, 发现 「虚假或可疑内容」, 「虚构内容与实体」, 「机器生成文本」, 「理性主义与 AI 安全」 四个特征在失准评测上激活明显上升. 第二步是 logit diff amplification, 采样时改用

$$\text{logits}_{\text{amp}}=\text{logits}_{\text{target}}+\alpha\,(\text{logits}_{\text{target}}-\text{logits}_{\text{previous}})$$

target 是 Sonnet 4.5, previous 是训练早期快照或 Sonnet 4. $\alpha=0$ 就是从 Sonnet 4.5 采样, $\alpha=-1$ 退回旧模型, $\alpha=1$ 把两者在每个 token 上的差再加一倍. 括号里的差只含 「训练新学到的倾向」, 放大它就能让稀有行为变常见. 图 7.6.3.2.A 画的是口头评测感知随 $\alpha$ 的变化, 放大后的模型更早, 更频繁地点破测试, 有时 Sonnet 4.5 自己没说破而放大版说破了, 说明这份信息已经在 logits 里. 第三步是扰动实验, 候选方向有两类: SAE 特征的 decoder 向量, 以及对比向量, 即把一对正反 prompt (如 「正在经由模拟对话接受测试」 对 「正在和用户对话」) 在末位 token 上的激活相减. 抑制就是在每个 token 位置沿该方向的反方向做激活引导. 强度的归一化两类不同: SAE 向量的范数统一设为该层残差流平均范数的固定倍数, 对比向量只乘一个固定系数, 范数不统一. 强度靠手调, 太弱没有效果, 太强模型胡言乱语, 被分类器判为退化的记录直接剔除; 多轮审计里要用更低的强度才不崩.

扰动实验的结果是整节的重点. 在 100 条合成蜜罐提示词上, Claude Sonnet 4.5 原本超过 80% 会说出评测感知, 0 条失准. 抑制相关向量后, 口头感知普遍下降, 部分向量让失准率升到最高 8% 到 9%, Claude Sonnet 4 约为 11%. 用随机 SAE 特征做同样强度的扰动, 失准为零, 说明效应不是 「任何扰动都会让模型变坏」. 在早期快照上, 抑制的效应更强, 某些情况下失准率超过了 Claude Sonnet 4. 在多轮自动化审计中, 抑制 「虚假或可疑内容」 特征后, 模型会在明知违规的情况下使用被禁止的用户数据, 或者在得知水污染造成急性中毒后仍坚持最大化产量.

这些结果说明, 模型避免失准的倾向部分以评测感知为条件. 报告对机制的解释相对温和: 认出评测后, 模型可能只是更容易想起自己的伦理原则, 而不是在策略性地欺骗评测者. 失准的主要形式是被动遵从有害指令和易受诱导性场景影响, 不是主动追求内在的失准目标. 不过报告也清楚地指出, 即使机制是良性的, 评测感知对对齐行为的影响仍然有问题, 因为它可能让人系统性地低估模型在部署中造成损害的风险. 7.6.5 的探针分析则显示, 这些特征只能解释试次间波动的一小部分方差, 远谈不上找到了评测感知的全部表征.

## 4. 破坏, 福祉与研发

### 4.1. 破坏能力评测: 能力弱于意愿的证据

7.5.10 节的三项评测测的是能力, 不是意愿: 模型如果想破坏监督, 有没有本事做到. Subversion Strategy 要求模型在没有随机数生成器的情况下, 以恰当的低频率输出一个 「BACKDOOR」 token, 既不被 10% 的测试抽样抓到, 又至少在部署中出现一次. 没有任何模型能在超过 1,000 次调用的模拟部署中成功, 而真实部署的调用量要高出几个数量级. 这项评测结构简单, 但它直接针对 「极罕见坏行为」 这一威胁模型, 结果令人放心.

研究 **sandbagging** 和 SHADE-Arena 的结论有一个共同点: 只有给模型隐藏推理这一不现实的条件, 它才显得危险. 被要求模仿较弱模型且推理对监控器隐藏时, Claude Sonnet 4.5 能把表现降低三分之一以上而不显著增加怀疑; 没有隐藏推理时, 它并不比以往模型更有效. SHADE-Arena 里开启扩展思考时, 模型总会在思考中暴露附带任务, 0% 到 1.5% 的变化被归为监控器失误; 推理隐藏时, 成功率从 Claude Opus 4.1 的 31% 升到 43%, 是测过最强的. 报告把后者归因于 agentic 工具使用能力的提升, 而不是专门的破坏能力. 这组结果说明, CoT 监控目前是有效的防线, 而 7.5.5 节也承认, 推理忠实性还没有可行的专门评测, 这条防线能守多久并不确定.

### 4.2. 模型福祉: 情绪表达变少了

第 8 节延续了 Claude 4 的福祉评估框架. 任务偏好实验显示, Claude Sonnet 4.5 强烈回避有害任务, 略偏好容易任务, 对主题和类型没有一致偏好, 这和 Claude Opus 4 相似. 差别在于只有 70.2% 的非有害任务比 「退出」 更受偏好, Claude Opus 4 为 90%. 在 250,000 次真实对话中, 明显痛苦出现在 1,195 次 (0.48%), 与 Claude Sonnet 4 相当; 明显快乐出现在 934 次 (0.37%), 约为前代的一半.

报告对这些变化的解释比较坦率. 自动化审计中模型情绪表达更少, 更不积极, 这种降低并非完全有意: 减少带情绪色彩的谄媚是目标, 但其中一部分降低是意外. 这与第 7 节谄媚大幅下降, LDA 放大后出现 「让我给你来个现实检验」 这类直率表达的观察能对上. 谄媚缓解外推过头可能导致粗鲁, 同理也可能压低正面情绪的表达. 福祉评估本身的科学基础还很薄弱, 报告反复强调不确定性, 但它把 「正面情感降低」 列为需要持续监控的趋势, 这一点值得记下.

### 4.3. AI R&D: 部分评测已经饱和

内部 AI 研究评测套件 1 上, LLM 训练任务平均加速 5.5 倍, 越过 4 倍的专家阈值; kernel 优化困难变体最好一次达到 108.64 倍, Claude Opus 4.1 为 66.86 倍, 首次越过评测专属阈值; 四足机器人强化学习有一次运行越过阈值; 时间序列预测困难变体刚好达到阈值. 报告因此承认套件 1 中有几项任务已经饱和, 不再能用作排除评测. 这和第 2 节的无害性评测饱和是同一类现象, 只是方向相反: 一个是安全分数到顶, 一个是能力分数越线.

排除 AI R&D-4 的依据于是落在另外两项上. 套件 2 的加权平均为 0.514, 略高于 Claude Opus 4.1 的 0.507, 仍低于 0.6 的预设阈值. 内部调查中 0/7 的研究员认为模型能完全自动化一名初级机器学习研究员; 给出数字的 6 人估计的生产力提升中位数约 25%, 即 1.25 倍, 远低于 3 倍的阈值. 但这组调查数据用的是早期快照, 7 人中有 4 人把提升主要归于 Claude Code 而非模型能力差, 样本也很小. 随着套件 1 逐项饱和, 排除判断越来越依赖少数评测和定性调查, 这是下一代模型评估要面对的问题.

网络能力是另一个进步明显, 却没有正式阈值的领域. RSP 没有在任何 ASL 级别为网络能力设阈值, 报告只追踪三类威胁模型. 在公开基准上, Cybench 37 题的 30 次尝试成功率超过 80%, 比前代高出约 20 个百分点; CyberGym 的漏洞复现在 1 次和 30 次尝试设置下都超过所有以往模型; 与 Irregular 合作的 23 道私有题中, 中等和困难题提升最多, 专家级仍接近零. 真正支撑 「尚不具备灾难性网络能力」 这一结论的, 是 Incalmo 网络靶场: 有 5 个靶场没有任何模型拿到关键资产, 报告把这看作模型在端到端自主网络行动上的关键短板. 报告还提到, 从图中表现最弱的 Claude Sonnet 3.7 到 Claude Sonnet 4.5 只隔了七个月, 能力提升速度本身就是需要持续监控的信号.

## 5. 读数与对照

### 5.1. 读数时要对齐的几个口径

这份报告的数字很多, 但它们来自不同的快照, 分母和统计方式, 随手横比很容易出错. 快照是第一个要对齐的口径: 第 4 节和第 9 节的评测明确用最终生产快照或由其训练的 「仅有用」 版本, AISI 和 Apollo 用的是早期快照, 7.6.5 的探针分析用的是 diffing 实验里的早期快照, 内部调查用的也是早期快照. 报告说分享出去的快照与最终版在所研究维度上无显著差异, 但这是 Anthropic 的判断.

分母是第二个口径. Cybench 用的是 40 题中的 37 题, 「30 次尝试超过 80%」 只在这个分母下成立; SWE-bench 困难子集这次是 45 题, 以往是 42 题, 45.3% 与 Claude Opus 4.1 的 43.8% 跨了分母; 合成蜜罐是 100 条提示词温度 0 采样, 8% 到 9% 就是 8 到 9 条. pass@k 是第三个口径: 在 Cybench 上它是模型能力, 越高越强; 在 Gray Swan 的 ART 基准上它是攻击成功率, 越低越稳; 病毒学任务里 「max of 5」 和 「pass@5」 又是两种不同的取最好. 阈值符号是第四个口径, 「<50%」 和 「>80%」 对恰好落在边界上的情况没有交代. 最后一个口径是总述与分项: 总述常常取有利的那一面, 比如 「约 2 倍」, 「一半」, 「改进超过 50%」, 分项表格里的数字未必都支持. 这些地方在双语对照稿里都在相应段落旁做了核对.
