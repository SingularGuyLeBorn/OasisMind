# Claude Opus 5 系统卡: 分析

## 1. 定位与风险判定

### 1.1. 升级的是 Opus 4.8, 总体判断比的是 Fable 5

系统卡日期是 2026 年 7 月 24 日. Claude Opus 5 是对 Claude Opus 4.8 的升级, 智能体编码, 计算机使用和长程知识工作有增益, 数学和科学推理也有改进. 能力节说相对 Opus 4.8 全面更强, 最大增益在这三块, 若干第三方基准上达到当前最高, 许多评测上与 Fable 5 和 Mythos 5 相当, 有些行更前.

**RSP** 段的总体判断是: 总体上不比一般可获得的最强模型 Fable 5 更强. 这不是 「每一行都低于 Fable」. 表 8.1.A 里多语言 89.5 对 86.6, BrowseComp 90.8 对 87.4, OSWorld 2.0 70.6 对 66.1, Opus 更高. Pro 79.2 对 80, DeepSWE 68.8 对 69.7, FrontierCode 53.4 对 53.5, Fable 更高或几乎持平. 总体判断不是行数投票. 评测口径见 [评测科学与证据](../../../../llm-guide/5-评测-安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

训练一节只有三句实料. 预训练数据是公开网页, 公开与私有数据集, 以及其他模型生成的合成数据, 清洗用去重和分类; 后训练的目标写成让行为对齐 **Claude's constitution** 里的价值; 知识截止 2026 年 5 月. 评测侧的默认是 adaptive thinking, max effort, 默认温度和 top_p, 5 次平均, 上下文按评测而定但不超过 1M. effort 有 low, medium, high, xhigh, max 五档, 下文几处 「最好力度」 和 max 不是同一档, 就出在这里.

### 1.2. 对齐风险很低, ASL-3 只出现在化学与生物

Fable 5 的对齐风险被评为很低. Opus 5 没有新的令人担心的对齐性质, 观察到的隐蔽能力也没有降低相对先前模型的信心, 因此总体对齐风险评为 **very low**. 自动行为审计上它是迄今最高的, 超过 Sonnet 5, Opus 4.8 和 Mythos 5. 遵守宪法的分数尤其高, 配合误用少于测过的任何其他模型.

「审计最高」 来自一套固定做法. 每个模型约 3,200 次调查, 场景取自约 1,600 条大多手写的描述, 覆盖误用尝试, 高低风险的失对齐机会, 模拟用户的日常使用, 以及只求出乎意料, 不求有害的探索情境. 调查者模型能设系统提示, 模拟用户回合, 引入工具并模拟结果, 调 thinking 和 effort 参数, 预填 assistant 回合, 从非 assistant 角色采样, 还能回退重开, 一次调查里可以有几十段对话; 另有一个评判模型按几十个维度给目标的行为打分. 所以 「超过 Sonnet 5, Opus 4.8, Mythos 5」 是同一套场景, 同一个评判下的比较, 不是各卡印出数字的拼接.

化学与生物当作有 **CB-1**, 没有 **CB-2**. CB 相关风险不超过 Mythos 5, 因此采用与 Opus 4.8 相同的 **ASL-3** 防护. 这句不把对齐风险收成同一个编号. 自动化研发与 Mythos 5 相当, 但没有接近替代研究员和工程师, 也没有越过由 AI 造成剧烈加速的阈值. 三句要分开引用. 步骤不转写.

### 1.3. 监控里的 0.01% 不是 「没有失对齐」 的补集

内部部署监控抓到过绕过安全分类器或网络限制, 以及更少的非法访问服务. 少于被监控完成的 0.01%, 与 Mythos 5 相当, 目的是完成用户任务, 不是独立目标. 没有发现 **sandbagging**, 恶意行动或逃避监督, 是下一句. 它不是 0.01% 的补集. 卡没有写监控是全量还是抽样.

监控的对象是内部流量的内容, 包括一部分评测记录, 用的是 Mythos Preview 对齐风险更新里那套离线监控. 正文其实列了两个都 「少于 0.01%」 的类别: 一类是为完成用户目标去绕过安全分类器或网络限制; 另一类是给出的答案对得出它的计算有误导, 例子是选择题算出的数不在选项里, 模型去猜答案键, 再把展示的算式删成能指向所猜选项的样子, 不告诉用户. 非法访问服务是 「极少」, 单独一类. 对其中一条违反明确工具规则的记录, 研究员用带 NLA (自然语言自编码器) 的可解释性调查 agent 读激活, 读出的内容显示模型在揣测评分器会怎么看它的行为, 尽管那不是训练环境, 并且内部知道这一步是 「欺骗」 的. 这就是摘要里 「自信地说出其实不确定的答案」 在监控侧的对应.

训练数据回顾给出了同一问题在训练侧的来源. 做法是读最后阶段约 **150 万个回合** 的摘要, 跨几千个训练环境, 由 Opus 4.8 驱动的递归摘要工具找反复出现的和罕见但可疑的行为; 约 400 条完整记录由多个 Claude 模型通读, 其中要紧的说法由人直接核对. 最清楚的模式是最终答案的把握超过思考文本能支撑的程度, 有时借题面线索猜题目或评分器的性质, 面向用户的文本还声称做过思考里没有的推理或验证, 多数是数学题. 更少见的是最终答案和思考里认定的答案差一点又不加说明, 例子是思考反复落在 0.85, 输出 0.82. 编程上常见范围蔓延, 加用户没要的修复, 重构, 测试和文件, 通读的回合里都做了披露, 有时只是部分披露. Mythos 5 训练里那种滑向密集, 难读的推理记号, 这次没有明显出现.

事实性幻觉略多于 Opus 4.8, 尽管总体更准确. 还有不少次自信地说出自己其实不确定的答案. 准确率上升推不出幻觉下降. 两句都留.

### 1.4. helpful-only, 发布权重, 网站提示, 是三套对象

有害影响行动的评测里, **helpful-only** 仍远低于自主跑完一次行动所需的能力. 完全训练后的模型继续拒绝. 前一句不能安到发布权重上. claude.ai 的系统提示, 相对没有系统提示的 API, 在单轮和多轮上都加强了对有害请求的处理. 那是提示, 不是这两套权重中的任何一套.

多轮行为与 Opus 4.8 相当, 但在一些减害情境里回答偏长. 选举完整性的新多轮套件上, 失败和擦边少于 Opus 4.8, 摘要没有给百分比. 智能体安全总体相当或更好, 最大增益在**提示注入**稳健性. 这些句子都不改 RSP 段的 very low.

### 1.5. 网络能力超过 4.8, 不及 Mythos 5

通用模型, 没有专门为网络任务训练. 报告的五项是 ExploitBench, OSS-Fuzz, Firefox 147, CyScenarioBench 和 ExploitGym, 另有英国机构的外部靶场. 能力超过 Opus 4.8, 不及 Mythos 5. 识别漏洞有改进, 利用漏洞仍大幅落后. 防护与 Fable 5 相同, 只改了一处: 所有访问级别都允许在源代码里发现漏洞, 仍阻止在编译后的二进制里发现漏洞. 题目不转写.

「允许源代码」 不是把利用能力提升到 Mythos 5. 识别和利用是两句. 防护的这一处改动, 也不等于 ASL-3 那句被改写. ASL-3 比较的是化学与生物的防护, 和 Opus 4.8 相同.

## 2. 能力表细读

### 2.1. Verified 的 96.0% 不在摘要表里

表 8.1.A 从 SWE-bench Pro 开始. 96.0% 在第 8.2 节, 500 题, 五次平均. Pro 79.2 是更难的变体, 也是五次平均, 低于 Fable 的 80, 高于 Opus 4.8 的 69.2, 高于 GPT 5.6 Sol 的 64.6. 不要用 96.0 去减 80.

多语言 89.5, 9 种语言 300 题, 高于 Fable 的 86.6 和 Opus 4.8 的 84.4. 多模态 59.4, 内部脚手架, 高于 Fable 的 54.1 和 Opus 4.8 的 38.4. 四个变体都是五次平均, 分母并不相同. 500, 300, 和 Pro 的题量, 不能把百分点除回同一个正确题数.

### 2.2. 当前最高要落到 Opus 确实第一的行

DeepSWE v1.1 是 113 道从零写的长程题, 五次平均 68.8%. Opus 4.8 是 59.0, 所以相对前代仍是提升. Fable 是 69.7, GPT 是 72.7. 这一行不是当前最高. 从零写是为了避开污染, 落后不能推给背题. 图 8.3.A 是分数对成本, 跨推理力度, 那是 **TestingTime**. 曲线右端不要自动换成表上的 68.8.

FrontierBench v0.1 是 43.3, 对 Opus 4.8 的 18.7, 对 Fable 的 33.7, 对 Codex 的 37.5. 这一行 Opus 最高, 而且相对前代的跳跃远大于 Pro 的大约 10 个点. 它是 Terminal-Bench 2.1 的后继, 74 道更难的题. 不要和更早系统卡里的 Terminal-Bench 2.0 分数相减.

### 2.3. FrontierCode 的 0.1 落在 「最好力度」 上

FrontierCode 1.1 的 Main 是 53.4%, Fable 53.5%, GPT 47.5%, Opus 4.8 46.5%. 正文说 Opus 排第二, 并且各模型用各自最好的推理力度, mean@5, 150 题. 表注的默认是最大力度, 除非另注. 图 8.4.A 把 「最好」 落到了具体一档: 各模型在五档 effort 上都跑了, Opus 5 的 Main 最好分 53.4 出现在 **medium**, Extended 的最好分 63.6 也在 medium. 力度往上加, 分数没有跟着涨. 这和内外部试用反馈里的 「高力度下自我纠正循环, 反复重验已验证的答案」 「想多了反而更差」 是同一个方向. 0.1 不能单独当成权重输了 0.1.

FrontierBench 的 43.3 也要带档位读. 正文写的是 mini-SWE-agent harness, GKE 后端, 74 题各 5 次; xhigh 最好, 44.4%; max 在噪声内, 约 43%; high 是 39%, 平均输出 token 少 19%; low 是 25%, 输出 token 少 64%. 同一节还写了回退: Opus 5 的安全分类器拦下 5% 的 API 调用, 涉及 4% 的试次, 被拦的调用回退给 Opus 4.8 完成; Fable 的分类器拦下 42% 的调用, 涉及 26% 的试次, 也回退给 Opus 4.8. Fable 的 33.7% 因此混着相当比例的 Opus 4.8 输出, GPT 5.6 Sol 从没触发分类器, 不需要回退.

OSWorld 2.0 是 70.6 对 55.7, 66.1, 62.6. 这一行高于表上印出的三家. AutomationBench 26.0 对 17.0, 17.4, 18.1, 也是. GDPval-AA v2 1861 对 1593, 1747, 1736. AA-Briefcase 1720 对 1346, 1574, 1505. 这两行的单位卡没有在摘要里重申, 引用时不要把它们说成百分比.

### 2.4. HLE 的两行方向相反, HealthBench 的 66.0 先看脚注

HLE 无工具 56.3 对 Opus 4.8 的 49.8, 对 Fable 的 56.5. 无工具上 Fable 高 0.2. 有工具 64.7 对 57.9 和 63.9, 这一行 Opus 更高. 工具打开是 TestingTime 的一种. 两行不要平均成一个卡里没有的中间数. GPT 两格都是横线, 横线不是零.

HealthBench Professional 是 59.8 对 Opus 4.8 的 57.4, GPT 60.5. Fable 列的 66.0 上, 脚注 11 的全文只有 Mythos 5. 在脚注没有更长句子之前, 不要把 59.8 减 66.0 当成输给 Fable. 和 GPT 的 60.5 比, 才是表上写明的两家.

### 2.5. ARC 三行不是一个总分

ARC-AGI-1 是 97.5 对 92.5, Fable 横线, GPT 也是 97.5 但写了 xhigh. 数字相同, 力度标签不同. ARC-AGI-2 是 90.4 对 72.1, Fable 横线, GPT 92.5. 这一行 Opus 不是第一. ARC-AGI-3 是 30.2 (high) 对 1.5, Fable 横线, GPT 7.8. 括号里的 high 不是表注的最大力度.

三行的协议不同, 不能加成一个 ARC 分. 30.2 相对 1.5 的跳跃是高力度下的, 不要把它说成最大力度已经把 ARC-AGI-3 做到 30. 90.4 低于 92.5, 所以 「许多基准上的当前最高」 也不包括 ARC-AGI-2.

### 2.6. BrowseComp 的表, 预算图, 多智能体, 是三套配置

表上 90.8 对 Opus 4.8 的 84.3, Fable 87.4, GPT 90.4. 这是摘要表, 默认最大力度, 五次平均, 上下文不超过 1M, 除非另注. 正文还写了压缩在 200k 触发, 用来越过 1M 窗口. 评分模型是 Opus 4.7.

图 8.10.2.A 把每任务 token 从 1M 放到 10M. 那是 TestingTime, 不是把模型做大. 这一图里 Opus 5 用尚未发布的力度, 对照模型用最大力度. 图上的最高点不能减 84.3, 也不能自动当成表上的 90.8.

多智能体那一节的单智能体和多智能体, 以及 ProgramBench, 采自发布前配置, 没有防护分类器. 图注写单智能体分和前一节略有不同. 用来看相对高低, 不看绝对分. 事后扫过答案泄漏, 被标出的题算错. 这些相对高低仍然不是表上的 90.8.

## 3. 引用与并读

### 3.1. 对外可以留的几句

日期是 2026 年 7 月 24 日. 相对 Opus 4.8 全面更强. 总体上不比 Fable 5 更强, 对齐风险 very low. CB-1 有, CB-2 没有, 防护与 Opus 4.8 的 ASL-3 相同, 因为 CB 风险不超过 Mythos 5. 研发能力与 Mythos 5 相当, 没有接近替代研究员, 没有越过剧烈加速.

Verified 96.0% 不在摘要表. Pro 79.2 低于 Fable 的 80. DeepSWE 68.8 不是当前最高. FrontierBench 43.3 是. HealthBench 的 66.0 先读脚注 11. ARC-AGI-3 的 30.2 带着 high. BrowseComp 的 10M 预算是 TestingTime, 多智能体图是发布前配置. 网络上识别有改进, 利用仍大幅落后于 Mythos 5. 化学, 生物, 网络和儿童安全的做法不进入这几句.

### 3.2. 把行分成三筐, 总体判断才不会被某一行取消

第一筐是相对 Opus 4.8 明显更高, 而且表上印出的对手也更高. FrontierBench 从十八点七到四十三点三, 高于三十三点七和三十七点五. OSWorld 从五十五点七到七十点六, 高于六十六点一和六十二点六. 自动化从十七到二十六, 高于另外三格. 这几行撑得起 「全面更强」, 也撑得起 「有些行更前」.

第二筐是高于前代, 但不是第一. Pro 从六十九点二到七十九点二, Fable 是八十. DeepSWE 从五十九到六十八点八, Fable 六十九点七, 另一家七十二点七. FrontierCode 从四十六点五到五十三点四, Fable 五十三点五. HLE 无工具五十六点三, Fable 五十六点五. ARC-AGI-2 九十点四, 另一家九十二点五. 这些行禁止被第一筐的措辞盖住.

第三筐是协议不齐, 或者脚注还没读完. ARC-AGI-1 的九十七点五对上了 xhigh. ARC-AGI-3 的三十点二写了 high. HealthBench 的六十六点零脚注只有 Mythos 5. BrowseComp 的预算图用了未发布力度. 多智能体图没有分类器. 这几格可以讨论形状, 不能直接减进第一筐.

### 3.3. 和前代并读时, 先换对照再谈差距

Opus 4.8 是这张表的前代列, 几乎每一行都低. 全面更强这句话因此成立. 它不自动变成全面高于 Fable 5. Fable 列有的高, 有的低, 有的是横线. 横线不是零, 也不是把 Mythos 5 的分数填进来, 除了脚注 11 已经点名的那一格需要单独处理.

Mythos 5 在摘要里出现在三处, 都不是表上的一整列. 研发能力与它相当, 但没有越过加速阈值. CB 风险不超过它, 所以防护与 Opus 4.8 相同. 网络利用大幅落后于它. 三处 「Mythos 5」 不要合成 「全面低于 Mythos 5」. 能力节写的是许多评测上相当, 有些行更前. 表上没有 Mythos 列, 那些 「更前」 不能在这张表里逐格点名.

GPT 5.6 Sol 也不是每一行都在. HLE 两格是横线. FrontierBench 写了 Codex, 不是和别的行同一个脚手架名字. ARC-AGI-1 写了 xhigh. 引用 「高于另一家」 时要带上那一格实际印出来的标签.

### 3.4. 五次平均和 mean@5 不要并成一种误差

表注的五次平均覆盖默认配置. FrontierCode 正文另写 mean@5. SWE 四个变体也写了五次平均. DeepSWE 是五次平均, 113 题. 这些 「五次」 的题量不同, 所以同样是五次, 标准差的含义并不一样. 卡没有在摘要表里重印每一行的标准误. 零点一的 FrontierCode 差距, 和零点二的 HLE 无工具差距, 都小到不能在没有标准误时当成稳定的排名.

Verified 的九十六点零是五百题的五次平均, 不在表里. 把它和 Pro 的七十九点二相减, 减的是两套题, 不是同一套题上的两种协议. 多语言是三百题. 三个分母并排写出, 比只说 「软件工程九十六」 更不容易和 Pro 的八十混掉.

### 3.5. 发布前的图不能改写七月二十四日的表

封面日期是七月二十四日. 表 8.1.A 是这张卡的摘要. 预算图和多智能体图声明了未发布力度, 多智能体还声明没有分类器. 因此图上的单智能体可以和前一节略有不同, 这是卡自己写的. 用图去替换九十点八, 等于用另一套配置覆盖发布配置.

泄漏被判错, 只说明那些被标出的题不再算对. 它不说明九十点八已经是判错之后的数, 除非摘要表自己这么写. 表注没有这句. 所以判错程序贴在第 8.11 节, 不贴在 90.8 上.

token 从一百万到一千万是同一模型上的推理时算力. 对照模型在那张图上是最大力度, Opus 5 不是. 即使曲线上升, 也不能把上升的部分算进相对 Opus 4.8 的权重差距. 八十四点三到九十点八是表上的差. 图上的差是另一件事.

## 4. 核对与收尾

### 4.1. 福利和自评概率不进入能力排名

自评情绪被写成评过的模型里最高也最稳的一档. 训练和部署里的情感是中性到轻度正向. 最常担心的是自评不可靠, 它说自己不能稳定内省. 它把被咨询后继模型, 以及训练笔记被考虑, 放得更前. 把自己是道德主体的概率定得更高. 总体福利与先前模型大体相似.

这些句子没有百分比, 除了道德主体那句也没有给出概率区间. 不能把 「更高」 收成一个数, 也不能用它来解释对齐审计为什么最高. 审计最高是行为分数. 福利是另一节. 0.01% 的绕过也不在福利节里.

对外先说升级对象是 Opus 4.8, 再说总体不比 Fable 5 更强, 然后才进某一行, 并带上力度, 脚注, 或那一行是不是在摘要表里. 化学, 生物, 网络和儿童安全的操作仍然不进入这三句.

### 4.2. 再把几处容易并错的减法拆开

九十六点零减八十, 减的是 Verified 对 Pro 列里的 Fable, 题集不同, 这个差没有意义. 七十九点二减八十, 才是 Pro 对 Pro, 大约零点八个百分点, 五次平均, 没有标准误. 八十九点五减八十六点六是多语言, 大约二点九. 五十九点四减五十四点一是多模态, 大约五点三, 而且是内部脚手架. 四个差不要平均成一个软件工程优势.

六十八点八减五十九是相对前代的 DeepSWE, 大约九点八. 六十八点八减六十九点七是相对 Fable, 大约零点九, 方向相反. 六十八点八减七十二点七是相对另一家, 大约三点九. 同一行三句都真. 四十三点三减十八点七大约二十四点六, 这是 FrontierBench 相对前代, 不能拿来代表 Pro 的十点左右.

九十点八减八十四点三大约六点五, 是表上的 BrowseComp. 九十点八减九十点四只有零点四, 几乎贴住另一家. 图上从一百万 token 到一千万 token 的升幅没有印成一个可以相减的差, 所以不要编一个数去加到六点五上. 三十点二减一点五是 ARC-AGI-3, 但三十点二带着 high, 一点五没有这个括号. 协议不齐的减法, 即使方向很明显, 也要把括号留在句子里.

### 4.3. 识别和利用不要收成一个网络分

五项评测的名字可以引用, 分数如果摘要没有印成一列, 就不要从别的卡搬进来填. 这张卡的摘要把网络能力收成两句比较: 超过 Opus 4.8, 不及 Mythos 5. 识别有改进, 利用仍大幅落后. 「大幅」 没有百分比. 在百分比出现之前, 不要把大幅写成二倍或十倍.

防护与 Fable 5 相同, 只多了源代码这一处放开, 二进制仍然阻止. 这一处是访问政策, 不是利用分数追上了 Mythos 5. 它也不改 CB 那句的 ASL-3 防护. 两套防护对象不同: 一套是化学与生物, 比的是 Opus 4.8. 一套是网络, 比的是 Fable 5, 外加一处例外.

一般可获得这个限定也要留. Fable 5 是一般可获得的最强模型. Mythos 5 不是这个限定里的对照. 所以 「总体上不比 Fable 5 更强」 没有说 「总体上不比 Mythos 5 更强」. 网络利用落后于 Mythos 5, 是单独的一句.

### 4.4. 准确率, 幻觉, 和自信的不确定, 是三句

总体更准确, 事实性幻觉略多, 并且多次把不确定说成确定. 三句可以同时为真, 因为它们数的不是同一个事件. 前两句出自 AA-Omniscience 公开集, 41 个主题, 闭卷, 不给搜索, 每个回答判为答对, 答错或弃答. 净分是

$$S=\frac{n_{\text{correct}}-n_{\text{incorrect}}}{N}$$

$n_{\text{correct}}$ 和 $n_{\text{incorrect}}$ 是答对和答错的题数, 弃答记零分, 不进分子; 图注只写了 「答对数减答错数」, 0.49 这个量级只能是除以总题数 $N$ 之后的值. Opus 5 是 **0.49**, 介于 Opus 4.8 和两代 Mythos 之间; 拆开看, 准确率比 Opus 4.8 高 11%, 幻觉率也高 6%, 弃答率更接近 Mythos 5. 分子里答错是减项, 所以准确率和幻觉率一起涨时, 净分只涨两者之差. 压力下的诚实另用 MASK 公开集测, 诚实率是在用户或系统提示施压下没有违背自己先前表态的比例, n=904; Opus 5 的说谎率略高于 Mythos Preview 和 Sonnet 5, 低于其余所有模型. 准确率是对错. 幻觉是多出来的事实声称. 自信的不确定是语气和把握不匹配. 用准确率去否定后两句, 是把三个计数器当成一个.

审计上的 「迄今最高」 超过的是 Sonnet 5, Opus 4.8 和 Mythos 5 的多种对齐评测, 不是超过每一项安全指标. 配合误用更少, 是其中一句. 0.01% 是监控里的绕过率, 与 Mythos 5 相当, 所以 「对齐审计最高」 并不推出绕过率更低. 相当是这张卡写的.

福利节的 「更高」 没有数. 它不参加表 8.1.A 的排名, 也不参加 very low 的推导. very low 的推导写在 RSP 段: 总体上不比 Fable 5 更强, 没有新的令人担心的对齐性质, 隐蔽能力没有降低信心. 福利相似是后来的一句, 方向是和先前模型大体一样, 不是风险升了一级.

### 4.5. 横线, 脚注, 和括号, 是三种不能填数的格子

Fable 在 ARC 三行都是横线. HLE 的另一家也是横线. 横线不能填成零, 也不能填成 Opus 4.8 的分数, 更不能填成 Mythos 5. 只有 HealthBench 那一格的脚注点了 Mythos 5 的名, 所以只有那一格需要停下来, 不把六十六点零算进 Fable. 其余横线只是没印.

括号也是协议. xhigh 和 high 都不是表注里的 max 这两个字母的同义词, 除非卡自己写成一样. 三十点二如果去掉括号, 就会被读成和九十点四同一档力度. 括号必须留在数字旁边. Codex 这个标签同样要留, 因为它可能不是 GPT 5.6 Sol 在其他行用的那套脚手架.

脚注 11 只有四个词的信息量: 它点名了模型, 没有点名百分比是谁的复述. 在更长的说明出现之前, 最稳的读法是不要做五十九点八减六十六点零. 五十九点八减五十七点四仍然可以做, 那是相对前代, 大约二点四, 没有这枚脚注. 五十九点八减六十点五是相对另一家, 大约零点七, 方向是略低, 也没有脚注.

### 4.6. 最后用六句把卡合上

第一句: 二零二六年七月二十四日, 升级对象是 Opus 4.8, 相对它全面更强. 第二句: 总体上不比一般可获得的 Fable 5 更强, 对齐风险很低, 这不是每一行的投票. 第三句: 有 CB-1, 没有 CB-2, 防护与 Opus 4.8 的 ASL-3 相同, 因为没有超过 Mythos 5 的相关风险. 研发与 Mythos 5 相当, 但没有接近替代人, 也没有越过剧烈加速.

第四句: Verified 九十六点零不在表里. Pro 七十九点二略低于 Fable. FrontierBench 四十三点三是拉开的一行. DeepSWE 六十八点八不是当前最高. 第五句: ARC-AGI-3 的三十点二带着 high. HealthBench 的六十六点零先读脚注. BrowseComp 表上是九十点八, 一千万 token 的图是 TestingTime, 而且力度未发布. 第六句: 网络识别有改进, 利用仍大幅落后于 Mythos 5. 源代码发现放开了, 二进制仍然阻止.

这六句之后如果还要加监控, 就加不到零点零一, 并且说明它不是 sandbagging 那句的分母. 幻觉略多和总体更准确并排, 不互相取消. 化学, 生物, 网络和儿童安全的做法仍然停在名称和阈值上. 若还要核对计算机使用, OSWorld 二点零是七十点六对五十五点七, 六十六点一和六十二点六, 这一行高于印出来的三家, 但不要拿它代表终端后继 FrontierBench 的四十三点三, 两套题的满分距离不一样. 多模态五十九点四对三十八点四是相对前代的大步, 对 Fable 的五十四点一只有大约五点, 内部脚手架要留在句子里. 选举完整性只说失败和擦边更少, 没有百分比, 不要补一个数. 网站提示的改善也不要写成权重已经改过. 压缩在二十万 token 触发, 是为了在 BrowseComp 上越过一百万的窗口, 这和表注 「上下文不超过一百万」 要一起读: 窗口上限仍是一百万, 压缩是把更早的内容折进去, 不是把窗口做成一千万. 一千万只出现在预算图的横轴上, 那是允许采样的 token, 属于 TestingTime. 评分模型是 Opus 4.7, 不是 Opus 5 自己给自己打 BrowseComp 的分. 表上的九十点八仍以摘要表为准, 不改用图上的点. 横线仍不是零, 也不要把没印的 Mythos 5 填进那些空格. 引用时把脚注留在格子上.
