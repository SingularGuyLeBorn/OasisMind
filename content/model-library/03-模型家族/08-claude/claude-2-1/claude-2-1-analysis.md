# Claude 2.1 (2023): 200K 窗口, 更多拒答和一次大海捞针风波

> 源文是 Anthropic 在 2023 年 11 月 21 日发布的产品公告 「Introducing Claude 2.1」, 属于博客式发布页, 不是技术报告. 全文没有公式, 没有表格, 没有参数量, 训练数据, 训练方法或模型结构; 能核对的定量信息只有正文里几个数字和三张柱状图. 训练手段本页没写的, 标 「本页没有」.

来源: 同目录 `claude-2-1.md` 与 `claude-2-1.pdf`, 共 10 页, 配图 5 张 (均在 `images/`). 对照译稿和逐段疑问见 `claude-2-1-bi.md`. 引用的原文数字和链接以源 md 为准, 图上的数值是目测读数, 只作量级参考.

## 1. 材料与发布

### 1.1. 材料性质: 一篇写给企业的版本说明

这份 PDF 分成两块. 第 1 页到第 6 页是公告正文, 依次讲 200K 上下文窗口, 幻觉率下降, API 工具使用, 开发者体验 (Workbench 与 system prompt), 最后交代上线范围. 第 6 页后半到第 10 页是抓取网页时一并存下的 「Related content」, 站点导航和页脚, 版权行是 2026 年, 其中的 Mythos, Fable, Claude Code 等名字与这次发布无关.

五张配图里, 第 1 页是装饰插画, 第 7 页是右箭头小图标, 真正有数据的是第 3 页一张和第 4 页两张柱状图. 按 「数据, 架构, 算法, 预训练, 后训练, 评测」 去对, 这篇的重心全在评测和后训练的结果上: 两套内部评测, 一个窗口长度, 一个 beta 接口. 架构和数据一个字没有. 第 6 页的 「Claude 2.1」 链接指向 ModelCardClaudev2_with_appendix_v1.pdf, 那份模型卡不在本目录.

### 1.2. 发布内容和产品分档

第 1 页第一段列出企业向的四项进展: 200K token 上下文窗口, 幻觉率显著下降, system prompt, 以及 beta 阶段的工具使用; 价格也一并调整, 覆盖多个模型. 第 5 页另介绍 Console 里的新产品 Workbench. 前两项属于模型本身的表现, 后三项更接近接口和开发工具.

上线范围在第 6 页: API 即日可用, claude.ai 免费版和 Pro 版都换成 Claude 2.1, 但 200K 窗口在 claude.ai 上只给 Pro 用户. 把最长窗口放进付费档, 是产品分档第一次按上下文长度切. 页面的对比对象始终是 Claude 2.0, 没有和其他公司比较; 「industry-leading 200K token context window」 和 「industry first」 是 Anthropic 自己的定位, 没有附对照表.

## 2. 长上下文与诚实性

### 2.1. 200K 窗口: 翻倍, 以及主动承认的延迟

第 1 到 2 页交代了来由: 用户在翻译论文, 起草商业计划, 分析合同这类长文档任务里希望窗口更大, 输出更准. 规格是 200,000 token, 约合 150,000 个英文单词或 500 多页材料, 并说是 「doubling」, 也就是从 Claude 2 的 100K 翻倍. 例子有整个代码库, S-1 财务报表, 以及《伊利亚特》《奥德赛》.

这一节有一句发布稿里少见的提醒: 处理 200K 长度的消息是复杂的工作, 人要几小时完成的任务, Claude 也可能需要几分钟, 延迟有望随技术进步下降. 满窗口的预填充计算随长度增长, 注意力部分还是平方增长, 几分钟的等待在当时的推理条件下是可信的 (按通用原理推断). 窗口靠什么位置编码, 注意力结构或训练阶段做出来, 本页没有; 通用路线见 [长上下文与外推技术](../../../../llm-guide/2-核心原理与架构/2.7-长上下文与外推技术/2.7-长上下文与外推技术.md), 缓存与显存问题见 [KV缓存与内存优化](../../../../llm-guide/6-训练与推理优化/6.4-KV缓存与内存优化/6.4-KV缓存与内存优化.md).

### 2.2. 「诚实性」 评测: 错答换成拒答

第 3 页标题是 「2x Decrease in Hallucination Rates」, 正文说与 Claude 2.0 相比 「2x decrease in false statements」. 评测做法有两句: 挑一大批复杂的事实性问题, 专门针对当前模型的已知弱点; 用 rubric 区分错误断言和承认不确定, 例子是 「玻利维亚人口第五多的城市」. 结论是 Claude 2.1 更愿意表示不确定. 柱状图标题 「Hard Questions」, 只画 「Incorrect」 与 「Declined to answer」 两组, 带误差线. 目测 2.0 错误约 47%, 2.1 约 25%; 拒答从约 24% 升到约 45% (读图).

两组数加起来, 2.0 约 71%, 2.1 约 70%, 剩下的约 30% 是答对. 也就是说, 在这套难题上答对率几乎没动, 变化几乎全部是 「错答挪到了拒答」. 这正是 「诚实」 在后训练里的常见含义: 奖励设计让 「我不确定」 比一个错误答案得分高, 模型就学会在没把握时收手. Anthropic 同期公开的 **Constitutional AI** 和 HHH 研究都把 honest 列为目标之一, 但公告没说 Claude 2.1 的这项变化来自偏好数据, RLAIF 原则还是别的手段, 也没说拒答变多会不会波及本该能答的问题. 题量, 领域, 判分者和误差线算法同样缺席, 「2x」 只能当作内部难题集上的结果引用. 这类权衡的一般讨论见 [上下文生成, 引用与拒答](../../../../llm-guide/7-LLM应用开发/7.2-RAG/7.2.3-上下文生成引用与拒答/7.2.3-上下文生成引用与拒答.md).

### 2.3. 长文档评测和发布后的大海捞针讨论

第 3 页末到第 4 页讲长文档理解, 场景是法律文件, 财务报告, 技术规范. 正文给两个数: 错误回答减少 30%; 错误认定 「文档支持某个论断」 的比例低 3-4 倍. 两张配图标题都是 「Long context question answering—errors」, 分别在 70K 和 195K 上下文下, 按 Beginning, Middle, End, Average 四组比较两代错误率, 纵轴上限 10%. 两个长度下 2.1 的柱子都低于或持平 2.0, 错误率大致在 2% 到 8% 之间 (读图). 正文的 30% 与 3-4x 在图上找不到一一对应的柱子, 引用时宜标 「正文陈述」.

公告发布后不久, 社区用 「大海捞针」 测试把 Claude 2.1 的长上下文召回画成热力图, 在不少深度和长度组合上表现很差. Anthropic 随后发文解释: 模型不愿根据一句与上下文格格不入的插入句作答, 在 assistant 回合开头加上 「Here is the most relevant sentence in the context:」 之类的引导后, 召回率大幅回升. 把这件事和第 2.2 节放在一起看, 一种说得通的解释是: 训练出来的 「没把握就不答」 倾向, 在人工插针这种不自然的设定下表现为拒绝, 被读成了 「找不到」 (推测). 它也说明长上下文评测的分数高度依赖 prompt 写法. 测试方法见 [大海捞针测试](../../../../llm-guide/3-预训练/3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md). 这场讨论本身不在本页里.

## 3. 工具, 开发者接口与边界

### 3.1. 工具使用 (beta): 接口先行

第 4 到 5 页介绍 API 工具使用, 定位是 「a new beta feature」. 能力有三块: 在开发者定义的函数或 API 之间协调调用, 搜索网络来源, 从私有知识库检索. 用法是用户先定义一组工具并提出请求, 模型判断需要哪个工具, 代表用户执行操作. 五个例子是计算器, 把自然语言转成结构化 API 调用, 查数据库或调搜索 API, 通过私有 API 在软件里做简单操作, 连接商品数据集给推荐并帮用户下单.

页面说这项功能处在 「early development」, 开发者功能和 prompt 指南还在做. 本页没有调用格式, 没有 schema, 没有成功率. 模型要稳定地输出合规的工具调用, 通常需要在后训练里专门加入工具调用轨迹; 公告没说 Claude 2.1 有没有这样训练, 还是主要靠 prompt 约定. 后来 Claude 3 的模型卡把工具使用写成正式能力, 同级目录那篇有交代. 方法背景见 [Function Calling](../../../../llm-guide/7-LLM应用开发/7.4-FunctionCalling/7.4-FunctionCalling.md) 与 [工具调用演进](../../../../llm-guide/13-Agent/13.1-Agent核心组件/13.1.4-工具调用演进/13.1.4-工具调用演进.md).

### 3.2. Workbench 与 system prompt

Workbench 是 Console 里的 playground 式 prompt 迭代界面: 用新的模型设置调优行为, 为不同项目建多个 prompt 并切换, 修改自动保存以保留历史, 生成代码片段在 SDK 里使用. 「new model settings」 具体是哪些, 页面没列.

system prompt 在第 6 页介绍, 用于给 Claude 自定义指令, 设定上下文, 扮演指定角色, 或以更一致的方式组织回答; 附了文档链接, 没有效果数字. 第 1 页把它和 200K 窗口, 幻觉率一起列为 「key capabilities」, 第 6 页又放进开发者体验, 两处归类不一致. 模型要区分 system 与 user 两种指令的优先级, 也需要后训练里有对应的数据, 本页没有交代. 用法见 [Prompt 工程](../../../../llm-guide/7-LLM应用开发/7.1-Prompt工程/7.1-Prompt工程.md).

### 3.3. 材料边界

这篇公告能回答 「Claude 2.1 比 2.0 多了什么, 在哪里能用」: 200K 窗口, 一套难题上的错答与拒答比例, 两个长度下的长文档错误率, beta 工具使用, Workbench 和 system prompt. 三张图的读数都是目测, 正文的 2x, 30%, 3-4x 与图的对应关系要小心.

它回答不了 Claude 2.1 的规模, 架构, 训练数据, 长上下文的实现, 诚实性来自哪种训练信号, 以及工具调用是否专门训练过. 第 2.3 节的大海捞针讨论和第 2.2 节的训练解释来自公开资料和推断, 引用时要和公告原文分开.
