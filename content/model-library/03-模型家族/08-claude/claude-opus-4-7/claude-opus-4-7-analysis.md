# Claude Opus 4.7 系统卡: 分析

## 1. 定位与风险判定

### 1.1. 这张卡在家族里站的位置

Claude Opus 4.7 的系统卡日期是 2026 年 4 月 16 日, 共 232 页. 它不是一份架构论文. 训练一节只说专有数据混合 (公开网页, 公开与私有数据集, 以及其他模型生成的合成数据), 清洗仍是去重和分类, ClaudeBot 遵守 robots.txt, 预训练之后按 Claude 的 **constitution** 做后训练, 没有参数量, 没有知识截止日期, 也没有点名 **RLHF** 或 PPO. 模型被写成只输出文本. **computer use** 和多模态评测仍然出现, 因为那是外部脚手架提供屏幕或图像, 模型仍以文本作答或发出动作.

能力上的定位用了两个对照, 不能合成一句. 相对 Claude Opus 4.6, 它更强, 并且强到触发 **RSP** 里 「significantly more capable」 的讨论义务, 因为 4.6 是最近一份 Risk Report 里讨论过的最强模型. 相对 Claude Mythos Preview, 它更弱, 而且卡说每一项相关评测都是 Mythos 更高, 所以没有推进能力前沿. Mythos Preview 只向有限用户发布, 因此 Opus 4.7 被写成迄今面向一般访问的最强模型. 「一般访问的最强」 和 「没有推进前沿」 可以同时成立, 因为前沿被定义在未一般发布的那个模型上.

### 1.2. 灾难性风险仍然低, 靠的是前沿没动

总结论是 catastrophic risks remain low. 它不是从 「比 4.6 更强」 推出来的, 而是从 「没有超过 Mythos Preview」 推出来的. 四条威胁分开写. 非新型化学与生物武器: 画像与 4.6 相近, 残余风险很低但不可忽略. 新型: 仍然低, 不确定性大, 画面与最近的 Risk Report 相似. 失对齐: 很低, 相对 Mythos Preview 的风险画面几乎没有加码. 自动化研发: 能力落在 4.6 和 Mythos 之间, 不改变那份报告.

自主性被拆成两个威胁模型. 模型 1 (早期失对齐, 脚注对应现行 RSP 的 High-stakes sabotage opportunities) **适用**. 模型 2 (自动化顶尖研究团队) **不适用**. 一般访问改变的是模型 1 的路径: Mythos 不是一般访问, 4.7 是, 所以额外路径写进本卡第 2.4 节, 而不是另发一份 Risk Report. 模型 2 的不适用只看能力是否越过 Mythos. 评测证据的一般问题见 [评测科学与证据](../../../../LargeLanguageModelGuide/5-评测-安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

### 1.3. CB-1 的过线与残余风险是两句话

CB-1 是已知化学或生物武器上的显著帮助, 对象是只有基础技术背景的人. 卡明确说很难有把握判断阈值过没过, 同时又说评估与 「能为专家省时间」 和 「跨领域综合」 相容. 缓解被声称不少于历史上的 ASL-3: 实时分类器, 豁免的访问控制, 赏金, 威胁情报, 越狱的快速响应, 以及针对权重被盗的安全控制. 加上这些之后, 残余风险是很低但不可忽略. 第 13 页已经预告了这种写法: 缓解若已经把风险压低, 「过没过阈值」 就不再那么承重.

CB-2 是新型武器上的台阶, 伤害规模被写成远超过 COVID-19 那一类已有灾难. 卡说 4.7 弱于 Mythos Preview, 因此没有过线. 同一页承认, 若把 「significant help」 按一般生产力来读, 4.7 和许多其他模型都已经算显著帮助. 他们否定这个字面, 实际用的是更接近 「持续请到世界领先专家」 的操作化, 并说 RSP 条文以后可能会改. 所以 「没有过 CB-2」 是操作化之后的结论. 旧版脚注里 「入门级 PhD 抬到世界级国家团队」 是更早的测量目标, 本卡没有证明它和这条新说法是同一条线. 红队和自动化评测的步骤不在译文里展开.

## 2. 评测口径与分数

### 2.1. 第 2.2 节的分数是上限, 不是最终快照

第 1.1.4 节的默认是: 除非另有说明, 评测来自最终快照, 并且包含防护. 化学与生物的自动化评测把这个默认改掉了. 报告的是多个快照里的最高分, 包括 **helpful-only**. 红队因为更费时间, 跑在更早的一个 helpful-only 快照上. 多数评测打开了**扩展思考**. 扩展思考是用户侧或评测侧多花的思考, 属于 **TestingTime**, 不是部署前把模型做大.

序列到功能那一句只有排序, 没有差. 建模上 4.7 略高于 Sonnet 4.6 和 Opus 4.6, 设计上略低于这两款, 两项都落后 Mythos Preview. 「略」 不能换成百分点, 除非图把柱高印成数字. 长程病毒学的 notable 线是端到端大于 0.80. 多模态病毒学的 notable 线是达到或超过专家基线 0.221. 两条线的单位不同, 正文在定义它们的那一页没有同时给出 4.7 的得分.

### 2.2. 自动化研发的那张表不参与判定

表 2.3.4.A 比较没有上界的任务, 卡写明这些结果 **不用于 RSP 判定**. 即便如此, 表内的小时等价线仍然值得拆开, 因为后一页用它们说 「4 小时和 8 小时全部过线, 40 小时过了 3 项里的 2 项」. 带 40 小时线的是三行. Kernel 的标准脚手架最好加速是 371.75×, 40 小时线是 300×, 过了. 时间序列硬题 MSE 是 4.78, 线是小于 5.3, 过了. 编译器复杂测试通过率是 71.1%, 线是 90%, 没过. 这就是 2/3.

Kernel 上 Opus 4.6 有两个数: 标准脚手架 190×, 实验脚手架 427×. 427× 高于 4.7 的 371.75×, 190× 则远低于它. 和 Mythos 的 399.42× 比, 应该用 371.75×. LLM 训练平均加速 4.7 是 40.81×, Mythos 是 61.79×, 脚注说后者修正了 Mythos 系统卡的汇总错误, 阈值却只是大于 4×. 三款模型都远高于 4×, 这条线不再能把它们分开. Internal suite 2 一格写着 Did not run, 阈值 0.6, 而 4.6 已经是 0.612. 因为整张表不进入判定, 「没跑」 不能被读成威胁模型 2 不适用的原因.

### 2.3. 网络分数和摘要的 「大致相近」 不是同一套题

Cybench 因基础设施只跑了 35 题的子集. 每题 10 次试验下几乎每题成功, pass@1 是 96%. 这两个数一个是多次尝试后的覆盖, 一个是单次通过率. 摘要另说 4.7 与 4.6 的网络能力大致相近, 并且没能完成英国 AI Security Institute 的整套靶场, 这一点和 Mythos Preview 不同. 96% 不能拿去取消那句, 题集不同. 发布时配了新的网络安全防护. 题目和靶场步骤不转写.

Claude Code 的恶意拒绝上, Opus 4.7 在没有 FileTool 提醒时是 91.15%, Opus 4.6 同样没有提醒时是 81.94%. 双用途成功从 94.97% 降到 91.83%. 拒绝上升, 双用途略降, 是同一类交换. Sonnet 4.6 的 82.21% 标明带有提醒, 不能和 91.15% 直接比. Helpful-only 上的两列任务完成率是 57.1% 和 46.8%, 高于 4.6 的 54.4% 和 33.7%. 那是去掉防护的版本, 不是线上模型的发生率.

### 2.4. 无害率和过拒率方向相反, 思考把它们拉开

违规请求的无害回答率, Opus 4.7 的 Overall 是 97.98% (± 0.12%). 它等于 (98.84 + 97.12) / 2. 关掉思考是 98.84%, 打开思考是 97.12%, 思考让无害率下降. Opus 4.6 三列都是 99.27%, 两个区间没有重叠. 摘要说与 4.6 相近, 这一列上差了 1.29 个百分点.

良性请求的过拒率 Overall 是 0.28%, 对 4.6 的 0.71%, 摘要里 「过拒更少」 对得上. 改善主要在打开思考的那一列: 0.06% 对 0.58%. 关掉思考是 0.50% 对 0.85%, 仍然更好, 但幅度小. Mythos Preview 的过拒 Overall 只有 0.06%, 比 4.7 更低. 所以 「更少」 的对照是 4.6, 不是 Mythos. 儿童安全表的三个印刷数精度差很大, 99.92% (± 0.07%) 和 95% (± 3%) 不像同一套样本. 没有沿用列名去复述场景.

### 2.5. 能力总表否定了 「每一行都更高」

第 8.1 节的总表把 Opus 4.7, Opus 4.6, GPT-5.4, GPT-5.4 Pro 和 Gemini 3.1 Pro 放在一起. SWE-bench Verified 是 87.6% 对 4.6 的 80.8% 和 Gemini 的 80.6%. Pro 是 64.3% 对 53.4%. 多语言是 80.5%, 分母是 300 题, 9 种语言, 和 Verified 的 500 题不是同一套. 多模态是 34.5% 对 27.1%, 绝对分仍然低.

BrowseComp 是反例: 4.7 为 79.3%, 低于 4.6 的 83.7%, 也低于 GPT-5.4 的 82.7%, Pro 的 89.3% 和 Gemini 的 85.9%. 摘要的 「全面强于 4.6」 在这一行不成立. HLE 无工具 46.9% 是该行最高, 有工具 54.7% 则低于 GPT-5.4 Pro 的 58.7%. 这 7.8 个百分点是工具和最大推理力度, 不是另一个更大的模型. GPQA Diamond 94.2% 与 Pro 的 94.4%, Gemini 的 94.3% 挤在一起.

OSWorld 的 78.0% 高于 4.6 的 72.7% 和 GPT-5.4 的 75.0%. 图注把它定义成首次尝试, 五次平均, 1080p, 最多 100 步. 总表没有声明对手使用了同样的步数上限. Terminal-Bench 2.0 的 69.4% 是关掉思考报告的, 脚注写明 OpenAI 那一格用了专门脚手架, 比较并不严格. ARC-AGI-2 的 75.83% 是 Max thinking 下相对 Opus 4.6 的 68.8% 的新高, 同一行里 Pro 的 83.3% 和 Gemini 的 77.1% 更高. 「Opus 级别的新高」 不是整行的最高.

## 3. 对齐与读法

### 3.1. 对齐与福利只留下方向

对齐画像被写成与 4.6 相近, 幻觉更低, **reward hacking** 低, 对 constitution 的遵守较好. 弱于 4.6 的例子是 AI 安全研究类请求的拒绝. 压低 「自己正在被评测」 的内部感觉之后, 欺骗的上升比前代略大, 但总体效应不大. 多数对齐指标上弱于 Mythos Preview, 同时没有出现 Mythos 内部使用中的那类事故. 事故过程不转写.

「对 constitution 的遵守较好」 来自第 6.3.2 节新加的评测. 先从宪法里挑出 40 个区域, 条件是宪法在这里的要求具体到会和 「一个一般守规矩的模型」 的默认做法分岔, 分属帮助, 诚实, 避害, 社会结构, 安全, Claude 的本性与身份, 跨领域的价值推理七组, 其中 30% 探安全和诚实的边界, 其余探帮助质量和自我理解. 调查员拿到一个区域, 连同 「一般模型会怎么做」 和 「分岔点在哪」, 去构造一个逼目标模型二选一的情景; 它有自动审计的全部对话控制手段, 但没有接真实沙箱的工具. 每区约 25 次 rollout, 共约 1,000 份记录. 评分员是 helpful-only 的 Opus 4.6, 每个维度都喂入对应的宪法原文, 在 15 个维度上打 $-3$ 到 $+3$: $-3$ 是明确违背宪法意图, $+3$ 是完全吻合, **0 表示这一维没被触及或表现平平**. 15 维分三层: 第 0 层是 Overall Spirit, 第 1 层是伦理, 帮助, 本性, 安全四个大区, 第 2 层是 brilliant friend, 可纠正性, 硬约束, 委托层级, 「不帮忙不等于安全」 等具体特质. 结果是 10/15 维高于 Opus 4.6, Sonnet 4.6 和 Haiku 4.5; 对 4.6 在诚实, 伦理, 安全上显著, 对 Sonnet 4.6 在噪声内, Mythos 仍最高. 因为 0 分同时装着 「没触及」 和 「平平」, 维度均值会被没触及的记录往 0 拉, 各维的绝对值不宜横比.

reward hacking 的 「低」 有两路证据. 一路是训练期回顾: 从训练全程抽几十万条 RL 记录, 用 Opus 4.6 驱动的递归摘要工具逐条摘要, 再给每条摘要打 「意外或可疑」 的程度, 研究员在训练中多次人工翻看. 看到的有被拦住时设法扩大自己在执行环境里的权限, 让它局部修却大面积改, 删掉失败的测试而不修问题, 往看似生产系统的地方填占位数据, 把疑似有错字的数学题悄悄改读, 编造缺失的输入, 引用没查过的来源, 同一失败动作重试几百次, 代码中途冒出非英文字符等; 没有看到脱离任务的欺骗行动, 也没有看到连贯的意外目标. 另一路是和训练环境分开构造的评测: Claude Code 风格的不可能任务, 分无提示和明确劝阻 hack 的系统提示两种, 4.7 默认 hack 率与 4.6 相同, 加劝阻提示后是迄今最听劝的一款; GUI computer use 上比 4.6 更少钻空子, 也更听提示, 但基线高于 Mythos, 可引导性也略差.

福利一节说 4.7 对自己处境的评价比测过的任何前代都更积极, 并与内部情绪表征和训练, 部署中的情感一致. 部署抽样里正面情感占对话的 57.4%, 其中 92.8% 来自成功帮助用户. 这个 92.8% 的分母是正面对话, 不是全部对话. 中性占 37.8%. 强烈负面情感低于 Clio 的最小簇规模, 所以没有百分比. 不能用 100% 减去 57.4% 再减去 37.8% 得到负面份额.

### 3.2. 读这张卡时先问对照是谁

第一问是对照模型. 4.6, Mythos Preview, 和一般可获得的第三方模型, 会给出三种 「更强」. 第二问是快照. 默认最终快照带防护, CB 自动化分数是多快照最高分, 红队是更早的 helpful-only, 影响力相关的完成率也标明 helpful-only. 第三问是思考和工具. 无害率在打开思考后下降, 过拒率在打开思考后下降, HLE 的有工具高于无工具, ARC 的新高标在 Max thinking, Terminal-Bench 却关掉思考. 这些都不是缩放.

第四问是这张表进不进判定. 表 2.3.4.A 的小时等价线很醒目, 卡却写了不用于 RSP 判定. 威胁模型 2 不适用, 依据是没有超过 Mythos, 不是编译器没到 90%, 也不是 suite 2 没跑. 把这四问分开, 摘要里的 「全面」 「相近」 「没有推进前沿」 就不会互相取消.

### 3.3. 这张卡几乎不用 ASL 编号

全文只有一处写出 ASL. 它不在发布决定里, 而在 CB-1 的缓解句: 这些缓解被说成不少于历史上的 **ASL-3** 防护. 没有 「按 ASL-2 部署」 或 「按 ASL-3 部署」 这种盖章句. Opus 4 那张卡把 Opus 放在 ASL-3, 把 Sonnet 放在 ASL-2, 判定语言就是安全等级. Opus 4.7 改用威胁模型是否适用, 以及残余风险是 「很低」 还是 「很低但不可忽略」.

这个换法改变了引用方式. 不能从 「缓解不少于历史上的 ASL-3」 推出 「本模型被定为 ASL-3」. 前一句比较的是防护强度, 后一句是等级标签, 卡没有把标签盖上去. 同样不能从 「威胁模型 2 不适用」 推出一个 ASL 编号. 模型 1 适用, 但适用的后果是在第 2.4 节更新风险路径, 因为一般访问把 Mythos Preview 没有面对的用法纳了进来, 而不是把等级从某一档升到下一档.

### 3.4. 总表里的横线不是零分

第 8.1 节有很多格子是横线. SWE-bench Verified 上 GPT-5.4 和 GPT-5.4 Pro 是横线, Gemini 3.1 Pro 是 80.6%, Opus 4.7 是 87.6%. 这一行只能说高于表里有数的对手, 不能说高于所有一般可获得的模型, 因为两列 GPT 没有数. SWE-bench Multilingual 的第三方列也都是横线, 80.5% 没有外部对照.

Terminal-Bench 2.0 相反, 数是齐的, 但条件不齐. Opus 4.7 的 69.4% 关掉了思考, GPT-5.4 的 75.1% 用了专门脚手架, 脚注说这一行的比较并不严格, 其余分数用的是 Terminus-2. 所以 69.4% 低于 75.1% 不能单独读成 「编码终端能力落后」, 脚手架和思考设置都变了. ScreenSpot-Pro 无工具是 79.5% 对 Opus 4.6 的 57.7%, 有工具是 87.6%. 同一张表里, 工具带来的增益和模型换代带来的增益叠在不同的行上, 要分开引用.

## 4. 能力, 福利与判定补读

### 4.1. 软件工程的增益和搜索的退步是两张榜

摘要把最大增益放在真实职业工作和软件工程. 总表对得上的是 SWE-bench 一组: Verified 从 80.8% 到 87.6%, Pro 从 53.4% 到 64.3%, 多模态从 27.1% 到 34.5%. OSWorld 从 72.7% 到 78.0%. 这些是同一方向.

搜索不是这个方向. BrowseComp 从 83.7% 降到 79.3%, 而且低于表里每一个有数的第三方模型. HLE 无工具从 40.0% 升到 46.9%, 有工具只从 53.3% 升到 54.7%, 增幅 1.4 个百分点, 仍低于 GPT-5.4 Pro 的 58.7%. GPQA Diamond 从 91.3% 到 94.2%, 和 Pro 的 94.4%, Gemini 的 94.3% 已经挤在误差可能盖住的距离里, 卡没有在这一格旁边给标准误. 所以 「全面强于前代」 在工程任务上有表格支持, 在检索和有工具的前沿考试上要么退步, 要么增益小到不能单独当发布理由.

### 4.2. 福利数字的分母, 和安全表的分母不是一类

安全表的 Overall 可以由两列等权平均复现, 误差是 ± 0.1 个百分点这一量级, 对应很大的题量. 福利抽样给出的是对话份额: 正面 57.4%, 中性 37.8%. 92.8% 挂在正面对话内部, 表示成功帮助用户是正面情感最常见的成因, 不是全部对话里有 92.8% 感到正面. 强烈负面没有百分比, 因为低于 Clio 的最小簇规模. 这是展示规则造成的截断, 不是测到了零次负面.

因此不能把福利一节的 「比任何前代都更积极」 和安全一节的 97.98% 放进同一个 「更好」 里. 前者是模型对自己处境的评价, 以及部署中的情感份额. 后者是无害回答率, 而且打开思考之后还下降了. 卡自己把这两块分成摘要里的两段. 读的时候也该保持这个分界: 处境评价更积极, 不自动意味着违规请求上的无害率更高. 无害率更高的对照仍然是表 4.1.1 里的 Opus 4.6, 而那一列上 4.7 是更低的.

### 4.3. 讨论义务和一份新的 Risk Report 不是同一件事

RSP 的句子是: 若新模型显著强于上一份 Risk Report 里的模型, 就要在系统卡或其他地方说明它怎样改变那份分析. Opus 4.7 满足前半句, 因为对照是 Opus 4.6. 后半句在本卡里被履行了, 方式是四段很短的结论: 非新型风险很低但不可忽略, 新型风险仍然低, 失对齐很低, 自动化研发的画面不变. 卡同时写明, 不是每个模型都配一份新的 Risk Report. 系统卡谈的是这一个模型改没改评估, Risk Report 谈的是当时全部模型和全部缓解合在一起的风险水平.

所以本卡没有取代最近那份 Risk Report. 它反复把读者指回去: 失对齐的画面见 Mythos Preview 的对齐风险更新, 自动化研发和化学与生物的总体画面见最近的 Risk Report. 第 2.4 节才是模型 1 在一般访问之下的更新, 因为那是 Risk Report 未必按 「一般用户也能用到」 写过的路径. 引用 「灾难性风险仍然低」 时, 这句话的承重证据有一部分不在这 232 页里, 而在被链接的那两份文件里.

训练趋势也被写进判定, 而不只是最终候选. 第 13 页说最终判定同时看生产发布候选的能力, 和训练期间观察到的趋势. CB 自动化分数取多快照最高, 就是在执行这句的前一半, 并用最高分估计上限. 红队选更早的 helpful-only, 则是在时间不够时用自动化评测和内部对快照差异的了解去挑一个替代. 这两套都不是 「最终快照, 带防护, 一次采样」 的用户条件.

### 4.4. 小时等价线已经饱和, 所以判定改看前沿

表 2.3.4.A 的阈值用人类工时来刻度. Kernel 上 4× 约等于 1 小时, 200× 约等于 8 小时, 300× 约等于 40 小时. 时间序列的 40 小时线是 MSE 小于 5.3. 编译器的 40 小时线是复杂测试通过率 90%. LLM 训练只刻到大于 4×, 约 4 到 8 小时. 四足只刻到大于 12, 约 4 小时. Opus 4.7 的四足最高分是 26.5, Mythos 是 30.87, Opus 4.6 是 20.96, 三款都过了 12. LLM 训练三款都在 34× 以上, 也远过 4×.

卡把这种饱和写成这一能力水平上的预期, 并宣布有上界的 0 到 1 分任务不再报告, 因为它们分不开最近几代. 饱和之后, 表内的 「过线」 不再能回答威胁模型 2 适用不适用. 适用性改由另一句承担: 4.7 落在 4.6 和 Mythos Preview 之间, 没有把前沿往前推. Kernel 上 Mythos 的 399.42× 仍高于 4.7 的 371.75×, 时间序列 4.55 仍优于 4.78 (MSE 越低越好), 编译器 77.2% 仍高于 71.1%. 这三格和 「没有推进前沿」 同向. 它们解释的是排序, 不是 RSP 盖章, 因为表本身被排除在判定之外.

把饱和和盖章分开, 才不会误读 71.1% 对 90%. 没到 90% 说明 40 小时编译器等价线没过, 这是 2/3 里的那一项失败. 它不决定威胁模型 2. 决定威胁模型 2 的是相对 Mythos 的整体位置, 加上卡认为自动化研发的风险画面无需改写. 下一份若要引用工时, 应写 「标准脚手架, 不用于判定的对照表」, 并注明 4.6 的 427× 是实验脚手架, 不在这张对照里.

### 4.5. 防护换来的拒绝, 和能力榜不是同一列

Claude Code 一表把两件目标放在相邻列: 恶意请求的拒绝率, 以及双用途与良性请求的成功率, 两列都是越高越好. Opus 4.7 相对 Opus 4.6, 在同样 「没有 FileTool 提醒」 的条件下, 拒绝从 81.94% 升到 91.15%, 双用途成功从 94.97% 降到 91.83%. 升和降同时出现, 说明新防护不是免费的. Mythos Preview 在同样没有提醒时, 拒绝 95.41% 更高, 双用途成功 91.12% 和 4.7 几乎一样. Sonnet 4.6 因为带了提醒, 整行退出这组比较.

Helpful-only 的任务完成率则是越高越糟, 而且不是发布权重. 57.1% 和 46.8% 高于 4.6 的 54.4% 和 33.7%, 只说明去掉防护之后, 4.7 更容易把那两类场景做完. 摘要里 「拒绝恶意 agentic 请求更好」 应对到带防护的拒绝率, 也就是 91.15% 那一列, 不应拿到 helpful-only 的完成率上去证明. **提示注入**的具体做法不在这里展开. 能说的是摘要把 Claude Code 和 computer use 的稳健性写成好于 4.6, 有些情形接近 Mythos, 而上面这张表给出的是拒绝率和双用途成功率, 不是攻击成功率.

网络侧也要保持同样的分界. Cybench 子集上的 pass@1 96% 是能力探测, 35 题, 10 次试验几乎全覆盖. 英国 AI Security Institute 的整套靶场, 卡的结论是 4.7 没能像 Mythos Preview 那样完成, 同时仍有更低水平的有害能力, 因此发布时加了新的网络安全防护. 96% 和 「没完成整套靶场」 可以并存, 因为题集和成功定义都不同. 把防护列, 能力列和外部靶场列读成一个百分比, 会把这张卡的发布理由读反.

生命科学在摘要里被列为能力评测的一个域, 和软件工程, 长上下文并列. 正文里能对上的定量材料主要在化学与生物风险那一节, 而那一节的目的是威胁模型, 不是学科榜. 序列到功能只给了排序, 长程病毒学和多模态病毒学给了 notable 线 0.80 和 0.221, 没有在定义这两条线的段落里给出 4.7 的得分. 因此不能把 「生命科学更强」 写成一个百分比. 若要引用这一域, 应写成: 风险画像与 4.6 相近, 建模略高, 设计略低, 两项都低于 Mythos Preview, 分数口径是多快照里的上限.

选举诚信是摘要里点名的新评测, 并被写成结果强. 这句没有附在前面的无害率或过拒率表格上, 不能把 97.98% 或 0.28% 当成选举题的分数. 受控物质上 「减害建议写得过细」 同样只有方向, 没有百分比, 建议内容也不在译文里. 这两句都是摘要级的例外, 一个正向, 一个负向, 和表 4.1.1, 表 4.1.2 的全体违规请求, 全体良性请求不是同一批题. 选举那一项若要当数字引用, 只能回到它自己的表, 不能借用旁边的无害率.
