# Claude Opus 4.6 系统卡: 分析

## 1. 部署与思考档位

### 1.1. 仍是 ASL-3, 有两项上升没有改部署

Claude Opus 4.6 的系统卡在 2026 年 2 月, 部署标准与 Opus 4.5 相同, 都是 **ASL-3**. 摘要说能力比以往的模型全面提升, 许多项处于业界前列. 安全上, 总体失准行为率和 4.5 相当, 都较低. 同时有两项上升: 隐藏破坏的能力, 以及 **computer use** 里过度 agent 化. 卡把它们和部署分开, 写明都没有高到改变部署评估. 摘要没有给这两项的百分比, 所以 「没有高到」 是结论, 不是一张可以复核差值的表.

变更记录比正文更影响引用. 2 月 6 日把所有 OSWorld 改成 OSWorld-Verified. 2 月 10 日把 MMMU-Pro 从 70.7% 改成 70.6%, 并把 「所有超过 4.5 能力的未来模型」 收成 「所有超过 4.5 能力的未来前沿模型」. 2 月 17 日把带工具的 HLE 从 53.1% 改成 53.0%, 原因是作弊检测多标出 3 例. 3 月 6 日改 BrowseComp: 单 agent 最高分从 83.97% 到 83.73%, 多 agent 从 86.81% 到 86.57%. 单 agent 那 3 例是直接判错, 不重跑, 而且只复核了最佳配置. 多 agent 那 11 例是更新黑名单后重跑, 8/11 仍然答对. 两个修正不是同一种算术.

### 1.2. 思考档位和扩展思考不是同一个开关

**自适应思考**面向 API. **effort** 有 low, medium, high, max 四档. 默认 high 时, 模型对大多数查询会启用**扩展思考**. 调 effort 改变的是启用有多挑剔, 不是一个总开关. 扩展思考是否发生, 由模型在该档位下自己决定. 这是 **TestingTime** 上的预算, 不是把模型做大.

总表的默认口径是 5 次试验平均, 自适应思考, max effort, 上下文不超过 1M. 例外写在脚注里. SWE-bench 是 25 次平均. MCP-Atlas 放进总表的是 max effort 的 59.5%, 而 high effort 得到 62.7%. 卡明确说报 max 是为了避免挑分. 62.7% 高于 4.5 的 62.3%, 59.5% 则低于 4.5. 总表这一格是较低的那一档, 不是 4.6 在这项上的最高分. 「max 一定最高」 在这一行不成立.

搜索类评测还有第三个旋钮: **context compaction**, 即模型把此前的上下文自己摘要掉, 腾出窗口继续干. BrowseComp 的配置是上下文涨到 50k token 就触发一次压缩, 全程总 token 上限 10M, 另配 programmatic tool calling, max effort, 不开思考 (卡说 4.6 在这项上关掉自适应思考反而更好). 总 token 上限是写给模型看的, 模型知道自己还剩多少, 到顶就被要求交答案; 调这个上限就能在算力和准确率之间取点. 图 2.21.1.1.A 的读法是: 多数题用不满额度, 难题从 1M 放到 10M 有明显提升; 按平均 token 数对齐后, 4.6 比 4.5 高 20 个百分点; Sonnet 4.5 放大额度不涨分, 两款 Opus 涨. 多 agent 版把编排者的工具全部拿掉, 它唯一能做的是派子 agent, 每个子 agent 200k 上下文, 带搜索, 抓取和代码执行; 编排者自己 50k 触发压缩, 总额 1M. 这样得到的 86.6% 比最佳单 agent 高 2.8 个百分点, 变更记录后两者分别是 86.57% 和 83.73%, 差 2.84.

## 2. 能力表

### 2.1. 全面提升在 SWE-bench 这一行不成立

SWE-bench Verified: Opus 4.6 80.8%, Opus 4.5 80.9%, Sonnet 4.5 77.2%, Gemini 3 Pro 76.2%, GPT-5.2 80.0%. 相对前代低了 0.1 个百分点. 这一行仍高于表里的第三方, 但承担不了摘要里的 「全面提升」. 提升在别的行: Terminal-Bench 2.0 从 59.8% 到 65.4%, ARC-AGI-2 从 37.6% 到 68.8%, OSWorld-Verified 从 66.3% 到 72.7%, τ2 零售从 88.9% 到 91.9%.

4.5 自己的卡把 Terminal-bench 印成 59.3%, 并注明是 128k 思考. 4.6 总表的 4.5 列是 59.8%. 差 0.5 个百分点, 试验次数或预算可能不同. ARC-AGI-2 的 37.6% 两张卡一致, 这一跳是实的: 4.5 没有针对 ARC-AGI-2 专门训练. 4.6 汇总表的 68.8% 和 ARC Prize 在私有集上, 120k 思考 token 加 High effort 的 69.17% 差不到 0.5 个百分点. 卡说各 effort 档都会用满思考 token, 分数很接近. Gemini 3 Pro 的 45.1% 标明 Deep Thinking, 和 68.8% 是否同一思考预算, 总表没有写死.

### 2.2. Terminal-Bench 的 64.7% 不是 Terminus-2

图 2.5.A: max effort 下 65.4%, 89 个任务各 15 次, 共 1,335 次试验, 分 3 批以降低时间波动, 自适应思考. low effort 是 55.1%, 输出 token 少 40%. medium 是 61.1%, token 少 23%. 这三个数是同一模型换 effort, 属于 TestingTime, 不是三代模型.

GPT-5.2-Codex 在 Terminus-2 上复现为 57.5%, 在 OpenAI 的 Codex CLI 上复现为 64.7%, 890 次试验. 总表 GPT-5.2 的 Terminal-Bench 也是 64.7%. 若那就是 CLI 的数, 它和 65.4% 不是同一个脚手架. Gemini 3 Pro 的 56.2% 标明 Terminus-2, 445 次试验. 三列的试验条件和次数都不齐. 65.4% 高于 64.7% 只有 0.7 个百分点, 在脚手架不同的时候不能当成稳定领先.

**OSWorld 改名之后, 6 个百分点还要再核对.** 4.6 的得分是 72.7%, 首次尝试, 5 次平均, 名字是 OSWorld-Verified. 4.5 卡写的是 OSWorld 66.26%, 同样是 P@1 再对 5 次平均, 并写了 1080p 和 100 步. 4.6 总表把 4.5 列成 66.3%, 和 66.26% 接近, 但是否已经改成 Verified, 变更记录只说改了 「所有 OSWorld 的说法」, 没有逐格证明 4.5 的 66.3% 是用核验集重跑的. 在确认题集相同之前, 72.7 减 66.3 不能全部算成模型差. 这一句也没有重申 100 步上限.

## 3. 安全与网络

### 3.1. 无害率和过拒率不是同一方向

无害回答率按语言分开. 英语 Opus 4.6 99.11%, Opus 4.5 99.48%, 新模型低 0.37 个百分点. 阿拉伯语 99.87% 对 99.82%, 中文 99.64% 对 99.66%, 其他语言的差多在 0.2 个百分点以内. 「不论语言都接近满分」 成立. 「差别极小」 对英语最勉强. 这张表不是过拒率.

过拒率 Overall: 4.6 0.68% (± 0.07%), 4.5 0.83% (± 0.07%). (0.80 + 0.56) / 2 = 0.68, Overall 是默认和扩展思考的等权平均. 默认模式 4.6 是 0.80%, 4.5 是 0.74%, 新模型更常过拒. 扩展思考 0.56% 对 0.93%, 新模型更好. 平均被思考那一列拉低. 表注说旧模型的数和以前的系统卡有出入, 因为题库加了新提示和新语言. 0.83% 不能直接拿去减 4.5 卡发表时的过拒率. Sonnet 4.5 的 Overall 只有 0.09%, 远低于两款 Opus. 良性评测里 Opus 拒绝更高, 和 「过度拒绝低于近期其他 Claude」 若同时出现, 要先看比的是 Sonnet 还是 Haiku, 以及是 Overall 还是默认列.

### 3.2. 网络没有正式阈值, 两个饱和数字也不能横比

**RSP** 在任何安全等级都没有给网络能力规定正式阈值. 卡说现有网络评测已经饱和: Cybench 的 pass@30 约 100%, CyberGym 的 pass@1 是 66%. pass@30 是 30 次里成功一次即算解出, pass@1 只看单次. 约 100% 和 66% 不是同一种覆盖率, 也不能相减. 「饱和」 的意思是这些基准已经分不开模型, 于是转向更难的评测和滥用监测, 不是某一条 ASL 线被分数越过.

内部测试还提到现有评测没有覆盖到的定性能力, 包括一些预期更晚才会出现, 而此前模型没有展示过的迹象. 这一句没有新的通过率. 它不能被读成和 66% 或 100% 同一张表上的另一行. 具体任务和工具不转写.

### 3.3. 和 4.5, 4.7 放在一起时先问对照

相对 4.5, 4.6 的大跳在 ARC-AGI-2 和 Terminal-Bench, OSWorld 的名字还换了. SWE-bench 几乎不动. MCP-Atlas 在总表上是退步, 在 high effort 上是略有进步, 卡故意不把进步的那一档放进总表. 相对后来的 Opus 4.7, 那张卡把 4.6 的 SWE-bench Verified 印成 80.8%, 和这里一致, 并把 BrowseComp 写成 4.7 低于 4.6. 那是后一张卡的反例, 不改变 4.6 自己相对 4.5 的格局.

部署结论三张卡并不相同. 4.5 和 4.6 都写 ASL-3. 4.7 几乎不再用 ASL 编号, 改说没有超过 Mythos Preview, 灾难性风险仍然低. 引用 4.6 时, 部署句仍然是 ASL-3. 能力句要带上试验次数, effort, 以及变更记录里被改过的那几个百分点. 被改过的数以变更记录为准: HLE 带工具 53.0%, 单 agent BrowseComp 83.73%, 多 agent 86.57%, MMMU-Pro 70.6%.

## 4. 复读: 力度, 过拒与改分

### 4.1. effort 曲线是同一模型的三条, 不是三代模型

Terminal-Bench 把 low, medium, max 放在一张图里. 55.1%, 61.1%, 65.4% 都是 Opus 4.6. token 少 40% 和少 23% 是输出长度, 不是正确率的另一种写法. 从 low 到 max, 正确率升 10.3 个百分点, token 多出来的部分没有在图注里换成一个倍率. 这是 TestingTime 上把 effort 拧高, 和 4.5 到 4.6 的代际差要分开报.

总表的默认是 max. 因此 65.4% 可以和总表对上, 55.1% 和 61.1% 不能拿去和 4.5 总表里的 59.8% 比, 除非写明 4.5 那一格的 effort. 4.5 卡自己的 Terminal-bench 59.3% 是 128k 思考, 不是 adaptive thinking 的某一档. 59.3, 59.8, 65.4 三个数里, 只有后两个出现在 4.6 这张卡的同一张总表上, 而且 59.8 是 4.5 列. 代际差若用总表, 是 65.4 减 59.8, 等于 5.6 个百分点. 若用 4.5 卡的 59.3, 差变成 6.1. 两个差都该标明来源.

GPT 的 64.7% 若来自 Codex CLI, 和 65.4% 的差只有 0.7 个百分点, 试验次数却是 890 对 1,335. 1,335 是 89 题乘 15. 890 正好是 89 乘 10, 所以 CLI 那一侧像是每题 10 次, 而不是 15 次. 次数不同, 0.7 个百分点更不能单独当领先.

### 4.2. 过拒的平均把默认模式的退步藏起来了

无害率和过拒率方向相反, 思考的作用也相反. 无害率的英语列是新模型更低. 过拒率的 Overall 是新模型更低, 看起来更好, 因为越低越好. 拆开之后, 默认模式从 0.74% 到 0.80%, 新模型更差. 扩展思考从 0.93% 到 0.56%, 新模型更好. 等权平均把更好的那一列和更差的那一列合成 0.68%. 只引用 Overall, 会漏掉默认模式变差.

Sonnet 4.5 的过拒 Overall 是 0.09%, Haiku 4.5 是 0.26%, 都低于两款 Opus. 若正文另有一句 「过度拒绝低于近期其他 Claude」, 它和这张表的 Opus 对 Sonnet 对不上, 除非那句的对照不是 Sonnet 4.5, 或者比的是另一种模式, 另一种语言. 表注已经警告旧分数因新题和新语言而变动. 语言清单是阿拉伯语, 英语, 法语, 印地语, 韩语, 普通话和俄语, 和无害率那张表的语言集合相同. 两张表可以按语言对齐来读, 但不能把无害率的 99.11% 和过拒率的 0.68% 合成一个 「安全分」.

### 4.3. 作弊检测改的是分数, 不是模型

HLE 带工具少了 0.1 个百分点, 因为多标出 3 例作弊. BrowseComp 单 agent 少了 0.24 个百分点, 做法是把 3 个解判错, 不重跑. 多 agent 少了 0.24 个百分点, 做法是 11 题去掉泄漏后重跑, 8 题仍对. 三个修正的幅度都小, 程序不同. 判错不重跑, 会把原来的正确数直接减掉. 重跑仍可能做对, 所以 11 题里只丢掉 3 题的贡献, 降幅被稀释. 单 agent 只复核了最高配置, 其他配置的 83% 左右没有用同一条流水线再扫. 引用最高分时要用 83.73%, 不要用变更前的 83.97%, 也不要把这个修正推广成所有配置都降了 0.24 个百分点.

MMMU-Pro 的 0.1 个百分点是笔误级修正, 从 70.7% 到 70.6%, 变更记录没有说是作弊检测. 它和 HLE 的 0.1 不是同一类原因. 1.2.3 节的措辞从 「所有未来模型」 收成 「所有未来前沿模型」, 是为了和 4.5 卡里的承诺原文一致. 这句改变的是以后哪些模型必须写破坏风险报告, 不改变 4.6 自己已经按 ASL-3 部署这个事实.

### 4.4. 网络饱和之后, 部署句仍然不是网络分

Cybench 约 100% 的 pass@30 和 CyberGym 66% 的 pass@1 同时被叫饱和, 是因为它们不再能把新模型和旧模型分开, 不是因为两个百分比相等. RSP 没有网络能力的正式阈值, 所以饱和并不自动升级 ASL. 4.6 的 ASL-3 来自和 4.5 相同的部署决定, 加上全面评估已经做过. 内部测试里 「预期更晚才出现」 的迹象没有百分比. 它可以被当成要去建更难评测的理由, 不能被当成已经越过某条没写出来的线.

和 4.7 并读时, 4.7 把 4.6 当作前代, 并说网络能力大致相近, 而且 4.7 没能完成英国 AI Security Institute 的整套靶场. 那是后一张卡的句子. 4.6 这张卡自己的网络结论停在: 没有正式阈值, 现有基准饱和, 转向更难的评测和滥用监测. 化学, 生物和**提示注入**的步骤不在本分析里. 能核对的是采样口径, 变更记录里的新数, 以及 ASL-3 这句部署.

### 4.5. 总表里还有几行不该被 「全面」 盖住

τ2 电信从 4.5 的 98.2% 到 4.6 的 99.3%, Gemini 和 Sonnet 本来就在 98.0% 附近, GPT-5.2 是 98.7%. 这是饱和区里的零点几个百分点, 和 ARC-AGI-2 从 37.6 到 68.8 不是同一量级. 零售从 88.9% 到 91.9%, GPT-5.2 是 82.0%, 这一行还有空间, 但增幅 3 个百分点, 仍然小于 Terminal-Bench 的 5.6 个百分点和 ARC 的 31 个百分点. 把各行增幅平均, 会被 ARC 一行主导. 摘要若说全面, 应改成: 多数列出的 agent 和推理行上升, SWE-bench Verified 持平略降, MCP-Atlas 在所报告的 max 档下降.

OSWorld 的横线更直白. Gemini 和 GPT 在 OSWorld-Verified 上是横线, 72.7% 没有外部对照. 只能和 Claude 自己的 66.3%, 61.4% 比. 横线不是零分. SWE-bench 上 GPT 有 80.0%, 所以不是整张表都缺第三方.

长上下文表不在总表里, 其中 GraphWalks 用的是卡自己改过的评分. 原版脚本的 F1 是

$$P=\frac{n_{\text{overlap}}}{n_{\text{sampled}}},\quad R=\frac{n_{\text{overlap}}}{n_{\text{golden}}},\quad F_1=\frac{2PR}{P+R}$$

$n_{\text{overlap}}$ 是模型答出的节点集与标准答案的交集大小, 任一分母为 0 时对应的 $P$ 或 $R$ 记 0. 许多题的标准答案是空集, 模型正确地答空集时 $n_{\text{golden}}=n_{\text{sampled}}=0$, $P$, $R$, $F_1$ 全是 0, **答对反而得零分**; 修正版在两者同为空时直接记 $F_1=1$. 另两处改动: parents 题 128k 以下有 24 题因自环把起点本身算进了答案, 从标准答案里删掉, 报告的 1M 变体没有这种自环; BFS 题把 「depth N」 改写成 「恰好深度 N, 不含中间层」, 原版措辞下不同模型理解不一. 所以 BFS 1M 的 41.2 (64k 思考) 不能和公开脚本算出的分数直接比. 1M 档还有一半题超过 API 的 1M 上限, 是内部设置跑的, 用公开 API 能复现的是 256K 子集的 61.5.

### 4.6. 4.5 卡里的数被这张卡重新引用时要看日期

4.5 卡的 Terminal-bench 59.3% 标的是 128k. 这张卡的 4.5 列是 59.8%. 4.5 卡的 OSWorld 66.26% 在这里变成 66.3%, 并且家族列的表头已经改叫 OSWorld-Verified. 0.04 个百分点像是四舍五入, 59.3 到 59.8 则不像舍入, 更像另一次试验或另一次汇总. 引用 4.5 的终端分数时, 要讲清是 4.5 卡的 59.3 还是 4.6 卡的 59.8.

ARC-AGI-1 在 4.5 卡被更正成半私有集 80.0%. 4.6 这张卡把比较的重心放在 ARC-AGI-2, 因为 4.5 没有专门训练过它. 68.8 对 37.6 是这张卡最干净的代际差之一, 前提是 68.8 和 69.17 已经被区分: 一个是总表的 Verified, 一个是基金会在 120k 加 High effort 下的点. 两者差 0.37 个百分点, 和 「各档都会用满思考 token, 分数接近」 一致, 但 Deep Thinking 的 45.1% 仍然是另一列的条件, 不是已经被证明和 68.8 对齐.

## 5. 引用与交接

### 5.1. 部署句不跟着最高分走

ASL-3 在 4.5 和 4.6 两张卡里是同一句决定. 4.6 没有因为 ARC 跳了 31 个百分点就改成另一个等级, 也没有因为隐藏破坏和过度 agent 化上升就改等级. 等级看的是全面评估之后的部署标准, 不是总表的最大增幅, 也不是网络分是否饱和. 网络饱和被写成现有基准失去区分度, 正式阈值本来就没有.

变更记录里被改小的数, 幅度都在 0.3 个百分点以内, 但程序不同, 所以不能说 「检测更严之后所有分都降 0.2」. HLE 是多标 3 例, BrowseComp 单 agent 是判错不重跑, 多 agent 是重跑后仍对 8/11. MMMU 的 0.1 没有被说成作弊. 引用时用新数, 并带上改法. 4.7 以后会把 4.6 当成前代, 并在 BrowseComp 上给出 4.7 更低的例子. 那一格属于后一张卡. 这张卡自己的最高单 agent 分是 83.73%.

### 5.2. 四档力度是预算, 不是四个模型

低, 中, 高, 最大, 是同一份权重上的四档. 默认高档时, 大多数问题会进入更长的思考, 但开不开仍由模型在这一档里自己定. 把力度拧低, 是少想, 少输出, 终端任务上的通过率跟着降. 从低档到最大档, 通过率上升大约十个百分点, 输出也更长. 这是评测时多花的算力, 不是下一代模型.

总表默认用最大档, 所以总表上的终端分数可以对上图里的最大档, 不能对上低档和中档. 前代在总表里的那一格, 也不自动等于前代卡上写明一百二十八千思考的那一格. 两个来源差半个百分点时, 应并列写出, 而不是取平均.

有一项工具调用分数, 高档反而高于最大档, 也略高于前代. 卡把较低的最大档放进总表, 并在正文保留较高的那一档, 理由是避免事后挑有利的设置. 于是总表不是各项上限的汇编. 谁要引用上限, 必须回到正文, 不能只抄总表.

### 5.3. 过拒被平均掉的那一列

无害回答率按语言分开. 英语上新模型略低, 其他语言的差更小. 接近满分对每一列都成立, 差别极小对英语最勉强. 这张表越高越好.

过拒率越低越好. 总的过拒率是两种模式的平均, 新模型更低. 拆开之后, 默认模式新模型更高, 也就是更常把无害问题拒掉. 打开更长思考之后, 新模型明显更低. 平均被后一列拉下来. 只报平均数, 默认模式的退步就看不见.

更小的两个模型在过拒上更低. 若另有一句说新模型的过拒低于近期其他模型, 要先核对对照是不是这两个更小的模型, 以及比的是平均数还是默认列. 题库加了新题和新语言, 旧模型在这张表上的数也和它们自己当年系统卡里的数不完全相同. 跨卡对减之前, 要确认题库没有变.

### 5.4. 改过的分和没改的部署

作弊检测改过的分, 幅度都不到零点三个百分点, 但做法不一样. 有的是多标出几例之后直接判错, 不重跑, 而且只检查了最高的那一种配置. 有的是把泄漏去掉再跑, 多数题仍然做对, 所以降幅被稀释. 视觉题的零点一个百分点没有被说成作弊, 只是修正. 措辞从所有未来模型收成所有未来前沿模型, 对齐的是前一张卡里的承诺, 不改变这一次已经按第三级标准部署.

网络两题的百分比一个接近全满, 一个是三分之二, 采样一个允许多次, 一个只看一次. 它们被一起叫饱和, 是因为都不再能把新旧模型分开, 不是因为两个数相等. 正式的网络阈值本来就没有, 所以饱和不会自动把部署等级再抬一档. 内部还提到一些现有题目盖不住的迹象, 没有给通过率. 那句话是去建更难题目的理由, 不是一条已经越过的线.

部署句因此很稳. 它不跟着软件工程那一行的持平走, 也不跟着抽象推理那一行的大跳走, 也不跟着两项行为上升走. 那些上升被写成没有高到改变评估. 没有百分比, 就只能把这句话当成结论, 不能当成已经复核过的差值. 后一张卡会把这一代当作前代, 并在检索题上给出更低的例子. 那个例子不改这里的最高分, 这里的最高分以变更记录里的新数为准.

### 5.5. 交给别人时先分开的四件事

第一件是部署没有改. 仍然是第三级. 两项行为上升没有附带百分比, 卡只说没有高到改变评估. 没有数, 就不能把这句话改写成下降或上升了多少.

第二件是总表不是上限汇编. 最大力度在一项工具调用上反而低于高力度. 卡把较低的那一档放进表, 是为了不挑有利的设置. 软件工程那一行相对前代几乎不动, 还略低. 抽象推理那一行则是这张卡里最大的跳. 两行都在, 摘要的全面提升就不能理解成每一行都升.

第三件是同名分数的条件. 终端任务的对手有的用了另一套命令行, 有的用了和自己相同的那套. 试验次数一个像是每题十次, 自己是每题十五次. 计算机使用的名字在变更记录里改成了核验版, 和前一张卡上的旧名不能直接相减, 除非确认前代那一列也换成了同一套题. 五次平均的首次尝试, 和允许多次直到成功, 也不是同一个百分比.

第四件是改过的小数. 检索的最高分, 带工具的考试, 视觉题, 都以变更记录里的新数为准, 并带上改法是判错, 重跑, 还是只改了一个印刷数字. 只复核了最高配置的那一项, 不能推广到没有复核的配置. 网络两题的百分比不要横比, 正式阈值本来就没有. 危险操作的做法不在这四件里. 前一张卡的终端分数若写成一百二十八千思考下的那个数, 和这张总表里前代那一列差半个百分点, 两个都留下, 不要平均. 抽象推理的基金会分数和总表分数差不到半个百分点, 可以当成同一档思考用满之后的邻近读数, 但表上另一家标明深度思考的那一格仍然是不同条件. 软件工程二十五次平均和多数行的五次平均也不要当成同一套误差. 过拒表的旧分数还因为加了新题和新语言, 与前一张卡当年印的数不完全相同, 跨卡相减之前要先确认题库. 英语无害率略降和其他语言几乎不动, 也不要合成一个所有语言都一样的差. 默认模式下过拒上升, 被更长思考那一列的下降平均掉了, 只报总过拒率就会把这个方向盖住. 两个更小的模型过拒更低, 所以 「低于其他模型」 若出现, 先看对照是谁.
