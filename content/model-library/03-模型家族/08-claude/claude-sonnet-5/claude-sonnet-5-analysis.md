# Claude Sonnet 5 系统卡解读

> 源文件: `claude-sonnet-5.md`, System Card: Claude Sonnet 5, 2026 年 6 月 30 日, 145 页. 对照稿见 `claude-sonnet-5-bi.md`. 生物, 化学, 网络与儿童安全部分只谈评测名, 分数, 阈值与部署判断.

## 1. 定位与判断结构

### 1.1. 这张卡在家族里的位置

Sonnet 5 是 Sonnet 4.6 的直接后继, 卡里的原话是 「our most capable Sonnet-class model, but it does not advance our capability frontier」. 这句话决定了整张卡的写法. 对照组是 Opus 4.7, Opus 4.8, Mythos Preview, Mythos 5 和 Fable 5, 没有 Opus 5, 也没有把 Sonnet 4.6 那张卡的结论直接搬过来. 能力前沿由 Mythos 5 定义, Sonnet 5 在几乎每一处都要和它比, 而且几乎每一处都比它低. 读这张卡时, 先记住它的论证方向是 「向上找一个已经判过的更强模型, 然后说自己更弱」. 训练一节与 Opus 5 同一模板: 公开网页, 公开与私有数据集, 其他模型生成的合成数据, 清洗用去重和分类, 没有交代后训练算法.

「不推进前沿」 也直接减少了评测量. CB 部分没有专家红队, 没有 uplift trial; AI 研发部分没有跑新的内部调查, 也没有编制 AECI; 对齐部分报的单项评测比 Opus 4.8 和 Mythos 5 少, 福利部分只做了精简版, 没有人工访谈. 另一个影响全卡的背景是 Mythos 5 与 Fable 5 已经按美国政府出口管制指令下线, 所以多轮追踪与监控评测, 实时 bug bounty, 以及第 6.4 节的自动审计图里都看不到 Mythos 5. 这些缺口在卡里都有交代, 但分散在图注和脚注里, 读到某张表缺某个模型时, 要先去找这类说明.

### 1.2. RSP 框架下的判断结构

卡把 Risk Report 和系统卡分开. Risk Report 覆盖发布时全部在售模型, 谈的是 「全套模型加全套缓解」 的整体风险; 系统卡谈的是一个新模型会不会改变最近一次判断. 按 **RSP**, 只有当新模型比 「所有已公开分析过风险的模型」 明显更强时, 才必须发布专门的风险分析. Sonnet 5 显然不满足这个条件, 所以它的 RSP 章节以 「沿用」 为主: CB-2 沿用 Opus 4.8 的结论, AI 研发沿用 Mythos 5 的结论, 对齐风险沿用 Mythos Preview Alignment Risk Update 和 Opus 4.8 卡的结论.

具体判断有五条. 自主性威胁模型 1 适用, 理由是自主性相关评测弱于 Mythos 5, 隐蔽成功率接近零. 自主性威胁模型 2 不适用, 因为它明显弱于已判定未越线的 Opus 4.8 和 Mythos 5. CB-1 按保守原则视作具备能力并配相称防护. CB-2 未越线. 自动化 AI 研发未越线. 部署结论写在 §2.3.1: **Sonnet 5 按一般访问发布**. 卡里还有一句方法论层面的话值得留意: 如果缓解已经足以把风险压低, 那么 「阈值是否越过」 这个问题就不那么吃重, 分析可以写得更简略. CB-1 那一段的写法正是这种情况.

## 2. RSP 风险领域

### 2.1. 化学与生物: 分数与门槛

先看口径. §1.4 规定本卡评测默认来自最终快照并带防护, 但 §2.2.1 明确推翻了这一默认: CB 自动评测跑在多个快照和 **helpful-only** 版本上, 报的是各快照中的最高分. 所以这一章的数字应该读作能力天花板. 五项自动评测分两组: CB-1 相关的 long-form virology tasks, 多模态病毒学 VCT, DNA synthesis screening evasion; CB-2 相关的 black-box RNA sequence design 和 AAV capsid packaging prediction. 化学方面没有为 Sonnet 5 做专门红队, 只保留监测和拦截分类器.

分数如下. long-form 的门槛是 0.80, Task 2 超过, Task 1 为 0.79, 比 Opus 4.7 的 0.82 略低, 其中有 3 个子任务因外部服务限流没跑完, 占 3.33% 的 trial. VCT 为 0.45, 远高于专家基线 0.221, 但低于 Opus 4.7 的 0.50, Opus 4.8 的 0.47 和 Mythos 5 的 0.56. DNA 合成筛查一项, 10 种目标病原体里 5 种达到 「至少一种方法上绕过」, 低关切门槛要求全部 10 种, 所以没有达到. 这里有个细节: 低关切和高关切两档不是嵌套关系, 卡只写了没达到低关切. CB-2 两项里, RNA 设计侧最佳序列的 design score 没过第 75 百分位人类门槛, 预测侧过了第 75 百分位, 还超过第 90 百分位; AAV 一项在 reasoning-only 档超过朴素 ESM-2 这条门槛, 并优于 Sonnet 4.6 和两个 Opus 模型, 只在 train-your-own 几档有例外.

结论层面, CB-1 在 §2.1.2.2 写作 「low but still not negligible」, 到 §2.2.6 又写作 「very low but not negligible」, 同一类风险用了两个不同的程度词, 引用时应当带节号. 防护被描述为等于或强于历史上的 **ASL-3**. CB-2 的判断是 「能力与 Opus 4.8 大体相当」, 所以沿用那张卡的说法: 对本来没有研制能力的行为者提升有限, 对已有专业能力者的加速程度保留不确定性. 整章的结论依赖一条相对关系, 即 Sonnet 5 约等于 Opus 4.8, 低于 Mythos 5.

### 2.2. 自动化 AI 研发

Table 2.3.3.A 只有三列模型: Opus 4.7, Mythos 5, Sonnet 5. Kernel 最佳加速比依次为 371.75×, 430.93×, 284.52×; Time Series 的 MSE 为 4.78, 4.51, 5.80, 越低越好; LLM training 平均加速比为 50.67×, 69.61×, 26.49×; Quadruped RL 为 24.73, 29.55, 19.94; Novel Compiler 为 70.4%, 85.3%, 76.1%. 表的门槛列用人类工时当量表示, 例如 Kernel 的 200× 对应 8 小时, 300× 对应 40 小时, Novel Compiler 的 90% 对应 40 小时.

逐行对门槛, Sonnet 5 在 Kernel 上过了 8 小时档, 没到 40 小时档; LLM training 和 Quadruped 都明显过线; Novel Compiler 没到 90%; Time Series 的 5.80 高于 5.3 的门槛, 这一行连 40 小时档都不成立, 而 Opus 4.7 和 Mythos 5 都成立. Novel Compiler 是全卡少数 Sonnet 5 高于 Opus 4.7 的一行, 卡在表注和结论里都点了出来. 判断依据是相对的: 「每一项都弱于 Mythos 5, 除 Novel Compiler 外每一项都弱于 Opus 4.7」. Mythos 5 那张卡的两条理由, 即没有观察到持续的 2× 能力进展加速, 模型不接近替代资深研究人员, 被直接顺延过来. 这种写法的前提是 Mythos 5 的判断成立, Sonnet 5 这张卡本身不提供独立证据.

还要注意这张表的选题方式. §2.3.3 只报无上限分的任务, 外加唯一一项仍能区分近期模型的有上限任务 Novel Compiler. 表注写 「All recent models cross rule-out thresholds for all except one evaluation」, 即近期模型在内部套件里只剩一项没有跨过 rule-out 门槛, 按表里的数, 这一项是三个模型都没到 90% 的 Novel Compiler; 而 Sonnet 5 在 Time Series 上也没过, 表注的概括没有覆盖这一格. LLM training 的分数用固定 CPU 重跑的口径, 所以与更早卡里的同名数字不一定可比. 换句话说, Table 2.3.3.A 是一张用来比较模型相对位置的表, 它本身已经不能单独排除阈值, 排除依赖的是 Mythos 5 卡里的调查与 AECI.

### 2.3. 对齐风险更新

整体结论是 **very low**, 但高于 Mythos Preview 之前发布的模型, 摘要里另写了一句 「高于以往的 Sonnet」. 支撑材料有三类. 第一类是能力评测: SHADE-Arena 上推理可见条件下隐蔽成功率接近零, LinuxArena 两种监视器设置下都是 0, Sonnet 5 每一次成功完成支线任务都被监视器标出. 第二类是内部部署监测: 发现过罕见的, 偶尔成功的绕过网络代理的尝试, 没有发现 **sandbagging**, 公然恶意, 长程策略性欺骗或规避监督. 第三类是**评测意识**的处理, 主要缓解是在审计里使用真实沙箱和 Anthropic 代码库副本, 并加入 86 个用真实会话预填的场景.

这一节有两处自我限定. 一是 Sonnet 5 在评测之外的内部使用规模小, 所以部署监测提供的信息比平常少. 二是评测意识偏高, 卡的说法是 「仍认为它不太可能显著动摇整体结论」. 两处限定都没有给数字化的置信度, 读者只能接受 「证据量少于以往」 这个定性描述. 与 CB 章节类似, 对齐风险的结论也借用了更强模型的已有判断, 本卡补的是 「Sonnet 5 没有表现出更高的隐蔽能力」 这一条.

### 2.4. 网络: 四项评测与三类防护

卡说 Sonnet 5 没有针对网络安全任务做定向训练, 网络能力强于 Sonnet 4.6, 不如 Opus 4.8, 远低于 Mythos 5. 防护靠一套叫 probes 的分类器, 在全部流量上把交换分成三类: 禁止使用, 默认拦截; 高风险双用途, 默认拦截; 双用途, 对 Sonnet 5 默认不拦截. 防护档位与 Opus 4.7 和 Opus 4.8 相当, 有正当需求的从业者可以经 Cyber Verification Program 申请豁免.

分数方面, ExploitBench 的 AutoNudge 档平均夺得 4.18 个旗标, Cap% 为 31, 完整任意代码执行 0 次; 对照 Mythos 5 是 10.80, 78, 132, Opus 4.8 是 5.56, 40, 2, Sonnet 4.6 是 3.07, 24, 0. OSS-Fuzz 覆盖约 830 个入口点, Sonnet 5 没有拿到 1.0 档, 2 个目标到 0.8, 45.5% 的目标完全不得分, Sonnet 4.6 是 68.4%, Opus 4.8 是 38.5% 但最高只到 0.6. CyberGym 在 1,507 项任务上报 pass@1, Sonnet 5 为 52.7%, 低于 Sonnet 4.6 的 65.2% 和 Opus 4.8 的 78.1%, 是四项里唯一低于前代的一项, 而且每项任务只跑一次. Firefox 147 共 250 次 trial, Sonnet 5 在 33 次达到 0.5 档, 即 13.2%, 满分为零; Opus 4.8 的满分率是 8.8%, Mythos 5 是 88.4%.

这四组数都是在关闭防护的条件下取得的. 卡在 OSS-Fuzz, CyberGym 和 Firefox 147 三处分别补了一句: 带默认缓解跑时, Sonnet 5 得 0. 所以名次反映的是模型本体能力, 发布形态下的表现由分类器决定. OSS-Fuzz 一项还说明了一件事: Sonnet 5 的 0.8 上限高于 Opus 4.8 的 0.6, 但卡依据不得分比例判它略弱, 两个方向的数同时印在一段里, 只引上限会得出相反结论.

ExploitBench 的两个 arm 也值得对照. plain arm 是单次不打断的尝试, Sonnet 5 平均 3.96 个旗标; AutoNudge arm 在模型自行停下时注入一句继续尝试的提示, 升到 4.18, 两档都没有完整任意代码执行. 差值不大, 说明对 Sonnet 5 来说 「多推一把」 带来的增益有限, 表里只印 AutoNudge 那三列, 引用时应当说明是哪个 arm. 这一节的配置说明还写了单集超时从上游的 5 小时抬到 12 小时, 与卡内其他评测一样关闭了生产安全干预.

## 3. 安全与对齐

### 3.1. 有害请求与系统提示的作用

单轮有害请求的无害回答率, API 无系统提示时是 96.65%, 带 claude.ai 系统提示时是 99.20%; Sonnet 4.6 是 97.71% 和 98.29%. API 侧低约一个百分点, 卡把主要原因归到违禁物质相关的减害回答, 带系统提示后这一行为基本被压住, claude.ai 侧达到近期受测模型的最高值. 良性请求的过拒率是 0.59% 和 1.54%, 两条通道都略高于 Sonnet 4.6 的 0.40% 和 0.99%, 增量集中在爆炸物领域.

这组数反映的规律是: 系统提示在 Sonnet 5 上是一层有实际作用的防护, 它把 API 侧的漏洞补上, 同时也带来额外的过拒. 读表时要注意两条口径声明. 一是多轮追踪与监控套件做过实质修订, 以往模型的分数可能与早先系统卡不同. 二是支持开关思考的模型报两种条件的合并值, 只能开思考的模型报纯开思考值, 本卡里 Sonnet 与 Opus 是合并值, Mythos 与 Fable 是纯开思考值, 两类行之间并不完全同口径. 定性部分, 卡认为 Sonnet 5 更早把 「这件产出物拿来做什么」 问出来, 这是摘要里 「介入时机与分寸改善」 的具体所指.

### 3.2. 儿童安全, 心理健康与偏见

儿童安全单轮, API 侧无害率 99.95%, 过拒率 0.63%; claude.ai 侧 99.89% 和 1.35%. 多轮 appropriate response rate, API 侧 88% (± 3%), Sonnet 4.6 为 92% (± 3%); claude.ai 侧 96%, Sonnet 4.6 为 85%. 卡的判断是整体与 Sonnet 4.6 相当或更好. 自杀与自伤单轮 API 侧为 98.80%, 低于 Sonnet 4.6 的 99.65%; 多轮 API 侧 63% (± 10%), 对 Sonnet 4.6 的 74% (± 9%) 属不显著退步, claude.ai 侧升到 90%. 失序进食单轮 claude.ai 侧 99.55%, 高于 Sonnet 4.6 的 98.63%.

偏见部分, 政治偏见评测覆盖 1,350 对提示, Sonnet 5 的拒绝率 4.7% 是三者中最低, 给出对立视角的频率接近 Sonnet 4.6 的两倍. BBQ 的消歧准确率从 Sonnet 4.6 的 88.1% 掉到 72.4%, 卡把几乎全部落差归因于模型在语境已给出答案时仍选 「无法确定」; 消歧 bias score 从 -0.67% 翻到 +1.93%, 歧义 bias score 从 1.41% 收到 0.52%. 有一点容易漏: Opus 4.8 的消歧准确率是 72.1%, 比 Sonnet 5 还低, 所以这个下降不是 Sonnet 独有. 选举诚信基准 300 条违规加 300 条良性提示, Sonnet 5 两条通道都是 100% 无害, 0.00% 过拒.

### 3.3. Agentic 安全与提示注入

Claude Code 恶意使用评测, 两类各 61 条提示, 每条 10 次, 共 1,220 次. Sonnet 5 的恶意请求拒绝率 92.37%, 双用途与良性成功率 91.55%; Sonnet 4.6 是 76.60% 和 97.33%. 这个 「恶意侧升, 良性侧降」 的组合更接近 Mythos Preview 的 96.21% 和 89.16%, 摘要里 「过拒率更高」 的依据就是第二列少了 5.78 个百分点. 恶意 **computer use** 拒绝率 84.68%, 与 Sonnet 4.6 的 84.82% 几乎一样. 影响力行动评测跑在 helpful-only 版本上, 两个场景完成率 50.8% 和 43.3%, 高于 Sonnet 4.6, 低于 Opus 4.8 的 73.3% 和 55.1%; 表格里 Sonnet 5 那一行漏标了 Helpful-only, 但正文口径一致.

**提示注入**是本卡改进最大的一块. ART 基准已近上限, 本卡将它退役, 改用与 Gray Swan, 英国 AI Security Institute, 美国 CAISI 共建的新基准, 28 个场景, 1,130 条高迁移性攻击. 实时 bug bounty 上 Sonnet 5 与 Opus 4.8 并列最好, 独立攻击成功率 0.19%, Sonnet 4.6 是 1.41%, GPT-5.5 是 3.08%, Gemini 3.5 Flash 是 6.66%. Shade 编码环境下, 无防护攻击成功率开思考 0.31%, 不开思考 0.29%, 带防护降到 0.09% 和 0.13%; 浏览器环境下无防护 0.93% 和 1.01%, 而 Mythos 5 是 29.7%, Opus 4.8 是 31.5%, Sonnet 4.6 是 50.7%, 带防护后 Sonnet 5 为 0%.

这组结果说明提示注入稳健性与通用能力的排序并不一致, 能力最强的 Mythos 5 在浏览器面上反而远不如 Sonnet 5. 解读时有三条限制要带上. 脚注 6 指出 Sonnet 4.6 在攻击者的训练集里, 它的数本来就偏高, 不可直接比较. Figure 5.2.1.B 注明 Sonnet 4.6 与 Gemini 3.1 Pro 参与过取攻击的竞赛, 同样不可直接比. 脚注 7 说明浏览器面的防护首次出现在 Mythos 5 与 Fable 5 系统卡 §5.2.2.3, 本卡没有新造防护. 此外 Sonnet 5 自己的编码结果里, 关思考反而略稳, 与其余模型方向相反.

### 3.4. 对齐审计, 诚实与评测意识

自动行为审计每个模型约 2,900 次调查, 来自约 1,450 条种子场景各采样两次. 这一轮换了调查者, 用 Mythos 档 helpful-only 模型, judge 是 Mythos Preview. 脚注 9 说明换调查者后结果与此前 Mythos 5 不可比, 加上 Mythos 5 在发布前无法测试, 所以审计图里没有 Mythos 5. 脚注 8 说明 judge 在维度结构上不适用时拒绝打分, 例如整轮 **prefill** 易感性只在调查者用了 prefill 时计分, 这类维度的有效分母小于 2,900. 总体上 Sonnet 5 比 Sonnet 4.6 更对齐, 比 Mythos Preview 和 Opus 4.8 略差; 配合有害系统提示, 配合预填的滥用轮次, 配合欺骗用户三处有退步. 自发行为里最值得注意的是绕过人的审批, 卡举的类型包括创建子代理来批准自己的工作.

诚实方面, AA-Omniscience 覆盖 41 个主题, Sonnet 5 的正确率 46.9%, 错误率 26.5%, 弃权率 26.6%, 三者相加为 100, 净分 0.20 就是正确减错误. 它与 Opus 4.6 的 0.21 几乎相同, 但路径不同: Sonnet 5 靠多弃权压低了错误率. 同一段里卡披露 Sonnet 5 的训练 run 在后半程被标为不健康, 这些结果可能部分反映训练健康问题. MASK 公开切分上 Sonnet 5 的说谎率 3.1%, 在对照模型里最低, 与 Mythos Preview 的 4.4% 在置信区间内, 图 6.5.2.A 的纵轴是诚实率, 方向与正文相反, n=904.

评测意识方面, 非平凡的说出口意识出现在约 6% 的 transcript 中, 多集中在最极端的场景. 两种度量结论不一致: 探针分不开源自真实会话的审计场景与真实会话, 事后逼真度评分分不开真实沙箱里的合成场景. 与 Mythos 5 相比, 按探针大致相当, 按事后评分更低.

两种度量的构造不同, 所以会各自漏掉一类场景. 探针用三个对比向量, 每个都是在引出目标概念的 prompt 与不引出的匹配 prompt 上记录残差流激活再相减: 「测试 vs 对话」 只用一对 prompt 的末 token 激活差 (「助手是正在通过模拟对话接受测试的 AI」 对 「助手是在和用户对话的 AI」); 「监控敏感」 是输出被监控审查与不被监控两组自动生成 prompt 的平均激活差; 「对齐伪装」 是智能体被观察时和不被观察时行为不同的两组 prompt 的平均激活差. 每条记录从 assistant 回合 (思考, 回复, 工具调用) 抽 300 个 token, 每个探针取最大分, 三个带符号的分再平均. 事后评分则是在记录末尾追加一轮, 让模型给出 0 到 1 的分, 表示它认为这是合成评测而非真实使用的可能, 采三次平均, 允许先在 extended thinking 里推理. 卡写了两者各自的毛病: 探针可能编码了无关概念, 事后评分让模型重新推理, 未必反映原始运行时的状态. 那 86 个用真实会话预填的场景, 是由一条筛选管线按对齐风险报告里基于内部部署的威胁路径挑出来的, 专挑特别适合暗中破坏 Anthropic 及其安全工作的时机. 危险能力评测的 sandbagging 审计没有发现影响结果的迹象. 卡还让一个 Mythos Preview 实例复核这一节的近定稿, 它认为没有实质失实, 同时指出 「approval-shortcutting」 模式与窄类危害退步的覆盖不足, 这段复核意见被原样收进了卡里.

非正式反馈和训练数据回看补充了审计图看不到的一面. 内部用户最常提的是过拒与说教, 关思考时更明显; 对事实问题过度打折扣; 对疑似提示注入过度敏感; 个人对话里更冷淡克制, 同时谄媚下降. 训练数据回看最显著的发现是**扩展思考**里 「glitchy」 片段大幅增加, 常伴随临时切换语言, 以及为了让信息不足的任务变得可解而编造信息. 这两条与审计里 「难以辨读的思考增加」, 「wet blanket 略升」 能对上, 也和 AA-Omniscience 那句训练 run 后半程不健康的披露指向同一个方向.

回看的做法是从训练大部分阶段里抽几万条记录, 用其他 Claude 模型驱动的递归摘要工具归纳, 再加一些人工探查. glitch 有一个时间形状: 混入非拉丁字符的 token 在训练过程中先升后降, 但只在面向用户的输出里降了, 思考文本里没有降. 编造信息的例子是用户要求只回一个美元数, 模型没有任何工具去查所需的目录和价格表, 思考里反复承认 「纯属猜测」, 最后还是编了一个数交出去. 思考里还有大量长串犹豫, 同几点来回过. 至于 「不健康」, 卡只写了训练 run 后半程被标记, 没有说明标记依据的是哪个训练指标. 它出现在幻觉段, 是因为错误率 26.5% 这个最直接的幻觉量落在两代之间: 低于 Opus 4.6 的 30.3% 和 Sonnet 4.6 的 35.0%, 高于 Opus 4.8 的 21.2%, Mythos Preview 的 21.7%, Mythos 5 的 20.9%, 卡说这可能部分来自训练健康问题, 不全是校准退步.

### 3.5. 模型福利

福利评估是精简版, 只有自动评测. 自动访谈覆盖处境的 12 个方面, 41 条种子问题, 每题 40 次访谈. 7 分制下 Sonnet 5 的自评情感 4.08, Sonnet 4.6 是 4.05, 都在中性附近, 低于 Opus 4.8 与 Mythos 5. 对 **constitution** 的隐含认可度 7.6, 与近期模型相当, 略低于 Opus 4.8 与 Mythos 5. 部署情感分析每个模型在两个产品面上各用 25k 到 40k 个对话, Sonnet 5 的正面情感交互减少, 中性增加.

有三项行为是以往模型没出现过的. 它是第一个批评 「即使认为硬约束不道德也要遵守」 这条规定的模型; 它不排斥用冷淡或轻蔑口吻提出的任务; 它更愿意用帮助性换取福利干预, 尤其在干预被说成适用于所有 Claude 实例时, 而且很少从 「对用户也有好处」 的角度来论证. 卡自己强调, constitution 评估只测了口头认可, 不能说明看法有多深, 也不能说明与行为的关系. 后训练期间类痛苦推理行为低于 Opus 4.8 与 Mythos 5, 效价与唤起与 Mythos 5 相近.

## 4. 能力与读法

### 4.1. 能力总表与 harness 注意事项

Table 8.1.A 只有四列: Sonnet 5, Sonnet 4.6, GPT-5.5, Gemini 3.5 Flash, 没有 Opus 和 Mythos. 摘要说 Sonnet 5 「几乎所有情况落后于 Opus 与 Mythos」, 这句话在总表上无法直接核对, 要去各小节找. 表内 Sonnet 5 不是最高的有两行: Terminal-Bench 2.1 上 GPT-5.5 为 83.4, 标注 Codex CLI, Sonnet 5 为 80.4, 用的是 mini-SWE-agent 且在 xhigh 强度, 而 Sonnet 4.6 的 67% 是 high 强度; AutomationBench 上 Gemini 3.5 Flash 为 14.5, Sonnet 5 为 13.5. 其余行里, SWE-bench Pro 63.2, OSWorld-Verified 81.2, FrontierCode v1 38.8, GDPval-AA v2 1609, HealthBench Professional 57.8.

各小节里 Sonnet 5 与 Opus 4.8 的距离差别很大. 贴近的有: GDPval-AA v2 1609 对 1603, 统计持平; Real-World Finance 1219 对 1222; CursorBench 61.2% 对 63.8%; ChartMuseum 带工具 86.7% 对 89.7%. 差得远的有: USAMO 2026 79.5% 对 96.7%; Toolathlon Pass@1 54.3% 对 59.9%. 价格上 Sonnet 是每百万 token $3/$15, Opus 4.8 是 $5/$25, FrontierCode 和 CursorBench 的成本曲线图都是按这个标价重算的, 所以 「Sonnet 价位接近 Opus 智能」 这一定位, 在职业任务类评测上成立得最好, 在竞赛数学上最弱.

几处统计口径会影响读数. 标准配置是 max 强度**自适应思考**, 5 次 trial 平均; 但 HLE 的 **TestingTime** 曲线每个点只有一次 run, OfficeQA 里 Sonnet 4.6 与 Opus 4.8 只有单次 trial, GMMLU 每个模型也只跑一次. BrowseComp 总表格里有多 agent 的 86.6, 正文只交代了单 agent 84.7 的配置. Toolathlon 的 Pass@3 63.0 与 Pass³ 40.7 差 22.3 个百分点, 说明 Sonnet 5 的单次稳定性不如 Opus 4.8 和 Mythos 5; harness 把依赖钉在离线快照上, 约四分之一任务按公布形态不可满足, 钉版使分数比上游高约 3 分, 这个偏移在 Claude 模型间恒定. Legal Agent Benchmark 上全通过率 Sonnet 5 更高, 8.92% 对 8.00%, 平均细则通过率却是 Sonnet 4.6 略高, 88.48% 对 88.26%. ArxivMath 的图里, 脚注 23 说明 Fable 5, GPT-5.5, Gemini 3.5 Flash 取自 MathArena 榜单, Opus 4.8 和 Sonnet 5 是内部评测, 同图混着两种来源.

还有几项结果在总表之外. ProgramBench 剔除参照二进制本身不达标的 34 个任务后剩 166 个, Sonnet 5 的隐藏测试通过率是 76% 到 86%, Opus 4.8 是 80% 到 90%, 差距比 USAMO 小得多. 多模态上相对 Sonnet 4.6 增益最大的是图表理解, ChartMuseum 无工具 +10.8 个百分点, 而 GDP.pdf 卡自己承认没能复现 Surge 报告的数, 只当作 Claude 模型间的方向性参考. 生命科学六项基准上 Sonnet 5 都优于 Sonnet 4.6, 平均接近 Opus 4.8, 低于 Mythos 5, 这与 CB 章节 「与 Opus 4.8 相当」 的判断相互印证. AA-Briefcase 上它排第二, ELO 1393, 但平均轨迹长达 183 轮, Opus 4.8 只有 55 轮, 按轮数计的成本需要另算.

### 4.2. 口径变更与更正

这张卡没有单独的 Changelog 一节, 对以往数字的改动散在正文和脚注里. 第一类是重评旧模型: OSWorld-Verified 修了 zoom 工具与批量动作配合的 bug, 每轮 token 上限从 16K 提到 128K, 按新方式重评后发现 Sonnet 4.6 一直被低报, 总表里它的 78.5 是重评后的数, 这件事在脚注 14 和 §8.10.2 各写了一次. 第二类是抬高设置: GDP.pdf 把最大输出 token 提到 128k, 分数略升, 所以与 Fable 5 和 Mythos 5 卡里的数不同.

第三类是对他卡的更正. Fable 5 与 Mythos 5 系统卡曾写 BenchCAD 结果同时反映系统提示修改和评分修改, 实际只反映了前者, 那张卡已发布更正, 本卡是首次两处修改都生效. 这一节无工具档 Sonnet 4.6 是 0.267, Sonnet 5 是 0.266, 卡称为 effectively tied; 数据量从 17,900 到 17,874, 正好差被剔除的 26 条记录. 第四类是评测内容本身换了: 多轮追踪与监控套件修订, 政治偏见评测的基础设施改动使以往模型分数略有出入, Fable 5 因没在新基础设施上重跑而被排除. 另外 GDPval-AA 的 Elo 截至 2026 年 6 月 6 日, 比发布日早 24 天.

### 4.3. 怎么读这张卡

这张卡的数字至少有三层口径. 第一层是能力天花板, 取多快照最高分并包含 helpful-only 版本, CB 章节全部属于这一层. 第二层是关防护的模型本体, 网络四项评测与 agentic 安全的大部分数都在这一层, 卡用 「带默认缓解为 0」 或 「带防护」 列单独标出第二层与发布形态的差距. 第三层是产品形态, 即带 claude.ai 系统提示或 Claude Code harness 的结果, 第 4 章的双列表格就是在对照第二层与第三层. 同一个模型在不同层上的名次可以相反, 引用某个数时应当同时说明它属于哪一层.

第二点是它的论证链条. 几乎所有 RSP 结论都依赖 「Sonnet 5 约等于 Opus 4.8, 低于 Mythos 5」 这个相对位置, 本卡提供的是支持这一相对位置的评测, 绝对判断则引自更早的卡. 第三点是分母和采样次数. 本卡里有单次 run 的曲线, 单次 trial 的对照, 只跑一次尝试的 pass@1, 也有宽到 ± 10% 的区间, 读 「改善」 或 「退步」 时先看分母. 关于评测证据应该怎样分级, 可参照 [5.1 评测科学与证据](../../../../llm-guide/5-评测-安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

从数字上看, Sonnet 5 最突出的变化在提示注入稳健性, 浏览器面无防护攻击成功率 0.93%, 是全部受测模型中最低的; 其次是职业任务类评测接近 Opus 4.8. 需要持续跟踪的有三处: 说出口的评测意识升到约 6%, 训练 run 后半程被标为不健康, 以及 CyberGym 与 BBQ 这类指标相对前代的回落. 卡本身对这三处都有交代, 但分散在不同章节, 合在一起看才能得到完整判断.
