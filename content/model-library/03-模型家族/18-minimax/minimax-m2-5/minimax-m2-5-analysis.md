## 1. 这是一份什么材料

15 页的分布很清楚。第 1 到 2 页是 Hugging Face 的页面框架：标签，下载量，模型树，评测结果栏。第 3 到 11 页是发布博客，依次讲编程，搜索与工具调用，办公，效率，成本，进步速度，RL Scaling 和 MiniMax Agent 里的落地。第 11 到 12 页是部署说明和推理参数，第 13 到 14 页是附录表和评测方法，第 15 页是网站页脚。32 张图里，24 张是基准柱状图或折线图，1 张是 Forge 架构图，剩下 7 张是图标和角标，没有数据。

这份材料最缺的是模型结构。全文唯一的规模数是第 1 页 Hugging Face 自动统计的 229B params，没有层数，专家数，注意力形式，上下文长度，也没有每 token 激活多少参数。`minimax_m2` 标签和 「M2-series」 的叫法暗示它和 M2 同属一个系列，第 2 页的合集还挂着一篇 arXiv 论文，但本页没有说那篇论文讲了什么，也没有说 M2.5 和 M2 的结构是否相同。所以这篇解读不谈结构，只谈页面上印出来的成绩，速度，价格和训练方法。

## 2. 谱系：三个半月里的三个版本

本页交代的谱系只有一句话：从 10 月下旬起的三个半月里，先后发布了 M2, M2.1, M2.5。第 8 页的折线图补上了时间和分数：M1 约在 2025 年 6 月，SWE-bench Verified 56.0%；M2 约在 10 月下旬，69.4%；M2.1 约在 12 月，74.0%；M2.5 约在 2026 年 2 月，80.2%。相邻两代的涨幅分别是 13.4, 4.6, 6.2 分。M2.1 在所有柱状图里都作为对照出现，这让读者能逐项看出 M2.5 相对上一代涨了多少，这一点比很多只和外部模型比的发布稿更有用。

拿折线图横向比，Anthropic 从 Sonnet 3.7（约 2025 年 2 月，62.3%）到 Opus 4.6（约 2026 年 2 月，80.8%）大约一年涨 18.5 分，每月约 1.5 分；MiniMax 从 M1 到 M2.5 大约八个月涨 24.2 分，每月约 3 分。第 8 页 「进步速度明显快于同行」 的说法有这张图撑着，不过两点要一起看：MiniMax 的起点低，从 56% 往上涨比从 80% 往上涨容易；图底注明分数来自各家官方公告，脚手架可能不同。到 2026 年 2 月，图上三家的最新点都挤在 80% 上下，Opus 4.5 的 80.9 仍是最高点。

本页能看出的继承关系有两条。一是 RL 算法：CISPO 被说成 「去年年初我们提出的」，M2.5 继续用它；本页只给了公式，没有交代它最早出自哪篇文章，也没有和别的算法对比。二是 M2 系列的定位：第 7 页说 M2 系列的设计目标就是 「跑复杂 agent 不用操心成本」，M2.5 被描述为接近这个目标。属于 M2.5 这一代新增或强化的，按本页说法有这几项：训练中自己冒出来的写 Spec 倾向，并行工具调用，过程奖励和完成时间奖励，Lightning 高速版，以及 MiniMax Agent 里的 Office Skills。

## 3. 编程：分数贴近前沿，排名跟着脚手架走

编程六项相对 M2.1 的涨幅是：SWE-Bench Verified +6.2, SWE-Bench Pro +5.7, Terminal Bench 2 +3.8, Multi-SWE-Bench +4.1, SWE-Bench Multilingual +2.2, VIBE-Pro +11.8。和同图里最高的闭源模型比，M2.5 只在 Multi-SWE-Bench 上领先（51.3 对 Opus 4.6 的 50.3，这张图没有 GPT-5.2），其余五项分别落后 0.7, 1.5, 3.4, 3.7, 1.4 分。差距最大的是 Terminal Bench 2 和 SWE-Bench Multilingual，后者恰好是第 4 页说 「尤其突出」 的多语言方向。说 「达到 SOTA 水平」 偏宽，说 「和前沿差一两分」 更贴近图上的数。

脚手架这件事值得单独拿出来。主评测用 Claude Code，覆盖了默认系统提示，取 4 次平均；第 5 页又用 Droid 和 OpenCode 测了一遍，用默认提示。换脚手架后，M2.5 从 80.2 掉到 79.7 和 76.1，分别少 0.5 和 4.1 分；Opus 4.6 从 80.8 掉到 78.9 和 75.9，分别少 1.9 和 4.9 分。所以 「分布外框架泛化更好」 这个说法，看的是掉分幅度比 Opus 4.6 小，不是绝对分数高出多少，领先的 0.8 和 0.2 分本身很薄。第 2 页评测结果栏里还有一个带星号的 75.8，来自 swebench.com。同一个基准在这份材料里一共出现了四个数。

VIBE-Pro 是 MiniMax 的内部基准，用 Claude Code 自动验证程序的交互逻辑和视觉效果，取 3 次平均。第 5 页把它拆成 Web，Simulation，Android，iOS 四个子集，按四项等权平均能复现总分：M2.5 为（36.9 + 81.4 + 50.6 + 47.9）/ 4 = 54.2，其他模型也都对得上。M2.5 在 Simulation（81.4 对 81.2）和 iOS（47.9 对 45.7）上小幅领先，在 Android 上落后 Opus 4.5 7.8 分，总分因此落后。相对 M2.1，iOS 子集涨了 19.1 分，Android 涨了 14.6 分，移动端是这一代涨得最多的地方，和第 4 页 「覆盖 Web，Android，iOS，Windows 全栈」 的描述能对上。

## 4. 搜索与工具调用：一项领先，一项接近满分

这一组五张图里，M2.5 只在 BFCL 多轮上排第一，76.8 比第二名 Opus 4.5 的 68 高 8.8 分；相对 M2.1 的 37.4，涨了 39.4 分，是全部图表里单项最大的代际涨幅。τ² Telecom 上六个模型都在 97.8 到 99.3 之间，已经接近满分，M2.5 的 97.8 排倒数第二，但这个区间里的差距意义不大。BrowseComp，Wide Search，RISE 三项的最高分都是 Opus 4.6，分别是 84, 79.4, 62.5，M2.5 落后 7.7 到 12.3 分（BrowseComp 按 76.3 算）。第 6 页 「在 BrowseComp 和 Wide Search 上业界领先」 的说法和图对不上。

评测设置要一起读。BrowseComp 和 Wide Search 都用 WebExplorer (Liu et al., 2025) 的 agent 框架；RISE 在同一框架上加了基于 Playwright 的浏览器工具。BrowseComp 图标题里的 「w/ctx」 指上下文管理：token 用量超过最大上下文的 30% 就丢弃全部历史。页面没给 M2.5 的最大上下文，这个阈值换算不成 token 数；也没说其他模型的柱子是否用了同样规则。至于 「轮次比 M2.1 少约 20%」，页面只给了一个比例，没有每个基准的平均轮数，也没有说是三个基准平均还是各自都少 20%。

## 5. 办公：三项内部基准，涨幅最大的一组

办公三项都是内部或改造过的基准。GDPval-MM 上 M2.5 为 59，排第三；MEWC 74.4，排第四；Finance Modeling 21.6，排第三。相对 M2.1 的涨幅分别是 34.4, 18.8, 4.3 分，GDPval-MM 从 24.6 涨到 59，是翻了一倍多。这一组三项的最高分都属于 Opus 4.6。第 6 页说 「对其他主流模型的平均胜率 59.0%」，这是 M2.5 自己那根柱子的值，不代表它赢过了图里每个模型。

三个基准的设计各有要注意的地方。GDPval-MM 基于开源的 GDPval 测试集，由 LLM 评审对完整轨迹做胜，平，负的两两判定，但没说平局如何计分，对手池有哪些模型；它还按各家官方 API 价格（不计缓存）统计了每任务 token 成本，可本页没有印出这组成本数字。MEWC 取自 2021 到 2026 年 Excel 电竞比赛的 179 道题，按单元格逐个比对答案，这是三项里最客观的一个。Finance Modeling 用专家设计的量表打分，取 3 次平均，最高分只有 33.2，说明题目本身很难。

MEWC 上还有一个没人解释的数：GPT-5.2 只有 41.3，比 M2.1 的 55.6 还低，而它在 GDPval-MM 上是 54.5，在 Finance Modeling 上是 20，并不弱。本页没有说明对手模型的分数是 MiniMax 自己测的还是引自各家公告，这种异常值是否来自工具调用适配问题，从页面上判断不了。

## 6. 速度：37% 是速度比，不是省下的时间

第 3 页和第 7 页都说 M2.5 跑 SWE-Bench Verified 比 M2.1 快 37%。按第 7 页的数，时间从 31.3 分钟降到 22.8 分钟，省了 27.2%；37% 来自 31.3 / 22.8 ≈ 1.37，是速度比。同期每任务 token 从 372 万降到 352 万，只少了 5.4%，所以提速的大头不是少用 token，而是页面提到的并行工具调用，以及可能的服务端吞吐。第 7 页把耗时拆成任务拆解，token 效率，推理速度三个因素，但没有给每个因素各贡献多少。

352 万 token 这个量本身也值得算一下。摊到 22.8 分钟（1,368 秒）上，约每秒 2,570 个 token，是标称输出速度每秒 100 token 的二十多倍。这说明 「每任务 token 数」 统计的是 agent 多轮调用里反复送进模型的全部上下文加上输出，大部分是输入。如果假设这 352 万全按 Lightning 版输入价每百万 0.3 美元计，不计缓存和输出，一个任务约 1.06 美元（基于假设）。页面说总成本只有 Opus 4.6 的 10%，但没有印出两边的绝对成本。22.8 分钟对 Opus 4.6 的 22.9 分钟，两者几乎一样；这个耗时是在标准版还是 Lightning 版上测的，页面没说。

## 7. 价格：几笔账能对上，几笔对不上

价格部分给了两个版本。M2.5-Lightning 每秒 100 token，每百万输入 token 0.3 美元，输出 2.4 美元；标准版 M2.5 每秒 50 token，价格减半，也就是输入 0.15 美元，输出 1.2 美元（按 「减半」 推）。两版都支持缓存，缓存价格没给。按输出价格，M2.5 的成本被说成 Opus，Gemini 3 Pro，GPT-5 的十分之一到二十分之一；这里写的是 GPT-5，不是图里的 GPT-5.2，三家的单价本页也没有印。

按单价重算页面上的几句话：每秒 100 token 跑一小时是 36 万 token，按 2.4 美元每百万计是 0.864 美元，页面写 1 美元；每秒 50 token 一小时 18 万 token，按 1.2 美元每百万计是 0.216 美元，页面写 0.3 美元，就算拿 1 美元按速度和价格各减半也只有 0.25 美元。「1 万美元让四个实例跑满一年」 按 0.3 美元每小时算是 10,512 美元，能对上；按 1 美元每小时就是 35,040 美元。可见这句说的是标准版。

还有一个命名上的冲突。第 7 页 Efficiency 小节说 「M2.5 原生每秒 100 token，接近其他前沿模型两倍」，紧接着 Cost 小节把 100 TPS 分给了 Lightning，M2.5 本身是 50 TPS，倍数也改成了 「两倍」。第 3 页 「每秒 100 token 一小时 1 美元」 里的 M2.5 同样指 Lightning。引用这些速度和价格时，最好把版本名写全。

## 8. RL: Forge 的分层和 CISPO 的奖励

第 9 页的 Forge 架构图分三层。顶层是 agent，分黑盒和白盒两种：黑盒只暴露 API；白盒是一个 Agent Loop，分别连着 LLM Server, Env Server, Reward Server。中层是 Gateway Server，两种 agent 都通过它和底层交互，它把轨迹写进 Data Pool；数据池里存补全（prompt\_ids，response\_ids 等）和奖励，奖励分 outcome 和 process 两类。底层是 Rollout Engine 和 Train Engine，训练端通过 「sync weights」 把权重同步给推理端。这张图对应正文说的 「中间层把训练推理引擎和 agent 彻底解耦」：agent 不用改成训练框架的格式，黑盒 agent 也能接进来。约 40 倍的训练提速来自异步调度和训练样本的树状合并，但页面没说是和什么基线比。

CISPO 的公式有几个可以直接读出的特点。归一化用的是一组 G 条输出的总 token 数，属于 token 级平均；截断后的重要性采样比套了停止梯度，只当权重用，梯度走对数概率那一项；截断区间是 0 到 1 + ε，比值本身非负，实际只截上界。优势是从第 t 步到第 T 步的速度奖励和表现奖励之和减去基线，奖励是按步给的，这正是正文说的 「解决长上下文 rollout 的信用分配」。公式里没有单独的过程奖励符号，T，基线 B，ε 的取值都没定义，页面说以后另发技术博客。源文 md 把分母下标和期望下标分别识别成了 t=1 和 α，PDF 图片里是 i=1 和 a。

训练环境的规模，本页有两个说法：第 3 页和第 9 页说 RL 用了 「几十万个」 环境，大部分来自公司内部的任务和工作空间；第 4 页说编程训练覆盖 「20 万个以上真实环境」，13 种编程语言。两个数是否有包含关系，页面没说。第 11 页的内部落地数字（30% 任务，80% 新提交代码）和第 9 页 「我们训练模型，也受益于模型」 形成闭环，但这两个比例的统计口径没有交代。

## 9. 附录与评测设置

附录表补了六项通用能力：AIME25, GPQA-D, HLE w/o tools, SciCode, IFBench, AA-LCR. M2.5 在六项里没有一项是全表最高。相对 M2.1，AA-LCR 涨得最多，从 62.0 到 69.5；HLE w/o tools 反而从 22.2 退到 19.4，少了 2.8 分；IFBench 两代都是 70.0. GPQA-D 的 85.2 和第 2 页评测结果栏里的 GPQA Diamond 一致。表中多了一列 Claude Sonnet 4.5，前面的柱状图里都没有它。这六项是 MiniMax 按 Artificial Analysis 的公开评测集和方法内部测出的，不是榜单官方数。

评测方法这一节给了不少实现细节。SWE 系列和 Terminal Bench 2 取 4 次平均，VIBE-Pro 和 Finance Modeling 取 3 次；Terminal Bench 2 用 Claude Code 2.0.64，修改了部分题目的 Dockerfile，沙箱统一扩到 8 核 CPU，16 GB 内存，超时 7,200 秒，超时不重试，但空响应会重跑。这些改动让 M2.5 的 Terminal Bench 2 分数和别处按原始设置报的分数不能直接比。更关键的是，本页从头到尾没有说明柱状图里闭源模型的分数是 MiniMax 按同样设置自己跑的，还是引自各家公告。第 8 页折线图的底注明说用的是官方公告，而折线图里 Gemini 3.0 Pro 是 76.2%，柱状图里是 78，可见两处来源不一样。

## 10. 本页对不上的数字

下面是这 15 页内部互相对不上，或按页面给的数重算后对不上的地方。

- SWE-Bench Verified：正文和柱状图 80.2，评测结果栏 75.8（带星号），Droid 79.7, OpenCode 76.1.
- BrowseComp：第 3 页小图和正文 76.3，第 5 页图 75.1，其余五个模型两图相同。
- Gemini 3 Pro 的 SWE-Bench Verified：柱状图 78，折线图 76.2%。
- 「快 37%」：实际省时 27.2%，37% 是速度比。
- 100 TPS 属于谁：Efficiency 小节说 M2.5，Cost 小节说 Lightning；倍数一处 「接近两倍」，一处 「两倍」。
- 一小时 1 美元：按 Lightning 输出价重算 0.864 美元。一小时 0.3 美元：按标准版输出价重算 0.216 美元，按减半推算 0.25 美元。
- 编程语言：写 「超过 10 种」，括号里列了 13 种。
- 多语言 「尤其突出」：SWE-Bench Multilingual 74.1，低于两个 Opus，相对 M2.1 只涨 2.2 分。
- 「SOTA」：8 张总览小图里 M2.5 只拿到 Multi-SWE-Bench 和 BFCL 多轮两个第一，两张图都没有 GPT-5.2。
- CISPO 公式：源文 md 的分母下标 t=1 和期望下标 α，PDF 图片里是 i=1 和 a。
- 默认系统提示：在 PDF 里就断在 「built by」。

这些不一致大部分不影响结论方向，但会影响引用。一个数出自哪张图，用了哪个脚手架，是哪个版本，最好在引用时一起写上。页面时间也要分清：正文的 「现在」 按折线图约在 2026 年 2 月，第 2 页合集却显示 5 月 27 日更新，这个页面是之后才抓取的。

## 11. 小结

按本页印出的数，M2.5 在编程上和最强的闭源模型差一两分，在 BFCL 多轮这类多轮工具调用上明显领先，在深度搜索和办公上仍落后 Opus 4.6 一截。它真正拉开差距的是速度和价格：SWE-Bench Verified 每任务 22.8 分钟，和 Opus 4.6 持平，总成本只有后者的 10%；标准版一小时约 0.3 美元。相对 M2.1，这一代在 VIBE-Pro，BFCL 多轮，GDPval-MM 上的涨幅都在 10 分以上，进步集中在 agent 场景。

读这页要带着三点保留。一是结构全缺，229B 只是 Hugging Face 的文件统计，其他结构数一概没有。二是评测大量依赖内部基准和改造过的设置，闭源对手的分数来源没交代。三是训练方法只给了框架图和一个缺参数的公式，细节要等页面承诺的那篇 RL 技术博客。
