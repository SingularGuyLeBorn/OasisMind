## 1. 谱系: 这一页交代了哪些继承关系

本页对 M2.7 的出身说得很少. 能直接读出的线索只有三条: 架构标签是 minimax\_m2, 模型被收进名为 MiniMax-M2 的合集, 8 组柱状图里的自家对照是 M2.5. 由此可以把它放进 M2 这条产品线, 排在 M2.5 之后. 标签 minimax\_m2 通常对应 Transformers 里的模型类, M2.7 用这个标签, 说明它和 M2 共用同一套加载代码; 但本页没有写 「结构与 M2 相同」, 也没写 M2.7 是在 M2.5 权重上继续训练还是另起一轮. 这两件事本页都不回答.

规模上, 本页只给了 229B 这一个数. 没有激活参数, 没有专家数, 没有层数, 也没提 MoE. 读这一页的时候, 不应该从 M2 论文或其他模型页里搬数字来填空. 本页真正想讲的 「新东西」 不在结构上, 而在开发方式上: 它把 M2.7 称为 「第一个深度参与自身进化的模型」, 并用一张 M2\* 模型迭代系统图来说明. 所以这一代的谱系重点, 按本页的叙述, 是训练流程里多了模型自己动手这一环, 而不是结构换代.

## 2. 「自我进化」: 本页说了什么, 没说什么

第 3 页列了三件模型参与自身开发的事: 更新自己的记忆, 为 RL 实验搭几十个复杂 skill, 按实验结果改进自己的学习流程. 能给出数字的只有一例: M2.7 的一个内部版本对一套编程脚手架自主优化了 100 多轮, 每轮是 「分析失败轨迹, 改代码, 跑评测, 决定保留或回退」, 最终性能提升 30%. 第 4 页的示意图把这件事画成一个循环: 人配置 harness 和护栏, agent 在 harness 里读文档, 自审代码, 串联 skill, 写报告, 最后 「产出下一代模型 (递归循环)」.

这组叙述缺的东西不少. 30% 没有起点分数, 没有说是哪个基准, 也分不清是相对提升还是绝对百分点; 100 多轮只有下限; 脚手架是什么, 本页没说. 示意图里 「1 名工程师, 4 天, 人写代码 0 行」 描述的是 Agent Harness 的搭建成本, 而不是训练 M2.7 的成本. 图里的 M2\* 本页也没定义, 我倾向于把它读成 M2 系列迭代中的内部版本. 所以 「自我进化」 在本页是一个工作流描述, 有一个带数字的例子, 但这个数字无法复核.

示意图下半部分的 RL 团队五步流程倒是写得具体: 实验计划 (人 + AI), 实验开发与运行 (AI), 分析与报告 (AI), 审阅与讨论 (人 + AI), 迭代循环 (人 + AI). 五步里有两步完全交给 AI, 三步是人机合作, 没有一步是纯人工. 回路有两条: agent 分析后自动继续, 或者人触发下一轮. 这张图说明的是分工边界: 人管目标, 护栏和最终决策, agent 管执行和报告. 它和 「模型完全自主进化」 不是一回事, 本页自己的图也没有这样画.

## 3. 八组柱状图: 对 M2.5 和对闭源模型

第 3 页四张图共 8 组基准, 每组最多 6 个模型: M2.7, M2.5, Gemini 3.1 Pro, Sonnet 4.6, Opus 4.6, GPT-5.4. 先看和上一代 M2.5 的差 (按柱顶数字相减): SWE Bench Pro +0.8, GDPval-AA +15, Multi-SWE Bench +1.4, Toolathlon +8.0, VIBE-Pro +1.4, MM-ClawBench +5.1, MLE-Bench lite +15.1, Artificial Analysis +8. 三项纯编码基准 (SWE Bench Pro, Multi-SWE, VIBE-Pro) 只涨 1 分左右, 大涨的是办公 (GDPval-AA), 工具使用 (Toolathlon) 和机器学习工程 (MLE-Bench lite). 这和正文的重心一致: M2.7 这一代主推的是 agent 和生产力任务, 编码能力大体持平.

再看和图中最强者的差:

| SWE Bench Pro | 56.2 | 57.7 (GPT-5.4) | -1.5 | 6 个里第 4 |
| GDPval-AA | 50 | 58 (GPT-5.4) | -8 | 6 个里第 4 |
| Multi-SWE Bench | 52.7 | 52.7 (M2.7) | 0 | 5 个里第 1 |

8 组里 M2.7 只在 Multi-SWE Bench 拿第一, VIBE-Pro 接近第一, 其余多数排第 4. 编码类的差距在 1.5 分以内, agent 和综合类的差距在 7 到 13 分. 还要注意两点: Multi-SWE 和 VIBE-Pro 这两组恰好各缺一个模型 (前者没有 Gemini, 后者没有 GPT-5.4), 排名分母只有 5; Artificial Analysis 一组正文完全没提, 而这恰是 M2.7 排名最低的一组.

## 4. 软件工程: 正文数字和它的对照

第 4, 5 页的软件工程部分, 定性描述占大头: 日志分析, bug 排查, 重构, 代码安全, 机器学习; 系统级推理包括关联监控指标, 链路追踪, 在数据库里核实根因, 做 SRE 级决策. 唯一的实战数字是 「多次把线上事故恢复时间压到三分钟以内」, 没有次数, 没有基线, 也没有说是哪类事故. 这些是内部使用体验, 本页没有提供可复现的材料.

带分数的六项是 SWE-Pro 56.22%, SWE Multilingual 76.5, Multi SWE Bench 52.7, VIBE-Pro 55.6%, Terminal Bench 2 57.0%, NL2Repo 39.8%. 前四项在柱状图或评测面板里能找到, 后两项只有 M2.7 自己的数, 没有任何对照. 正文的比较对象也和图不一致: 正文说 SWE-Pro 「与 GPT-5.3-Codex 持平」, 图里没有 GPT-5.3-Codex, 图里的 GPT-5.4, Opus 4.6, Sonnet 4.6 都比 M2.7 高 1 到 1.5 分; 正文说 VIBE-Pro 「几乎与 Opus 4.6 持平」, 图里两者都是 55.6, 实际是完全相同, 而 Sonnet 4.6 的 56.1 还高一点. 正文挑选的比较对象, 总是图中对 M2.7 最有利的那个.

Agent Teams 在正文里只有一句: 原生支持多 agent 协作, 角色身份稳定, 能自主决策. 第 5 页的截图给了一个具体样子: 电商项目 Sprint #12, Manager, WebDev, Frontend, Backend, Tester 五个角色, 任务 2/6 完成. 截图说明的是界面形态和分工方式, 没有任何量化指标. 本页没有给 Agent Teams 的基准分数, 也没有说它和单 agent 相比好在哪里.

## 5. 办公和 agent 任务: 量纲不一的几组数

办公部分的数字最乱. GDPval-AA 正文是 ELO 1495, 图里是 50, 两个数量纲不同, 本页没解释图里那个 50 是什么. 正文说 「开放权重中最高」 并 「超过 GPT5.3」, 图里既没有 GPT-5.3, 开放权重模型也只有自家的 M2.5; 图里能看到的闭源三家 (GPT-5.4 58, Sonnet 4.6 57, Opus 4.6 55) 都在 M2.7 之上. 能从本页确认的只是: M2.7 比 M2.5 高 15, 比 Gemini 3.1 Pro 高 9.

Toolathon 和 Toolathlon 拼写不同, 分数都是 46.3, 应是同一基准. 正文称 「全球第一梯队」, 按图排第 4, 离第一差 8.3. MM Claw 相关有两个数: 40 多个 skill 上的 97% 遵循率 (没有图, 没有对照), 端到端 62.7 (对应图里的 MM-ClawBench). 正文说 62.7 「接近 Sonnet 4.6」, Sonnet 4.6 是 64.2, 差 1.5, 确实接近; 但 Opus 4.6 的 75.4 和 GPT-5.4 的 73.6 高出 11 到 13 分, 正文没提. 第 2 页评测面板里的 WildClawBench 33.8 是另一个基准, 来自 InternLM, 名字相近, 不能和 MM-ClawBench 混读.

第 2 页的评测面板和正文的交集只有 SWE Bench Pro 和 SWE Multilingual. 另外两组, WildClawBench (总分 33.8, 平均耗时 551, 平均花费 7.2) 和 SkillsBench v1.1 (34.9, 带星号), 正文没有提. 551 和 7.2 没有单位, 星号没有脚注. 引用时只能照原样写, 不能补单位, 也不能把星号当作 「官方认证」 之类的意思去解释.

## 6. 部署, 权重和推理参数

权重侧本页只给了 229B 参数和三种张量类型. 按每参数 1 字节估, FP8 权重约 229GB; 全按 BF16 估约 458GB. 带 fp8 标签, 实际下载大小应靠近前者, 但 F32 的部分占多少, 本页没写. 量化衍生有 115 个, 是微调衍生 27 个的约 4.3 倍, 社区的主要动作是把它压小, 这和 229B 的本地部署门槛相符. 官方张量类型里最低是 8 bit, 更低比特的版本应来自这些衍生仓库.

部署入口列了五个: SGLang, vLLM, Transformers 三个推理框架各有一份部署指南, 权重另可从 ModelScope 取, 也可以直接用 NVIDIA NIM 端点. 页面称三个框架 「按字母顺序排列」, 实际顺序 SGLang, vLLM, Transformers 并不是字母序, 应是 SGLang, Transformers, vLLM. 这不影响使用, 只是说明这段文字可能经过增补.

推荐的采样参数是 temperature 1.0, top\_p 0.95, top\_k 40. temperature 取 1.0, 意味着官方推荐的是不压低温度的原始分布, 再用 top\_p 和 top\_k 截尾. 默认系统提示词在本页被截断, 停在 「Your name is MiniMax-M2.7 and is built by」, 后半句本页没有. 用这段提示词时要去仓库取完整版本, 不要自己补.

## 7. 社区数据: 下载, 衍生和 Space

第 1, 2 页的社区数字: 点赞 1.25k, 组织关注 10.9k, 上月下载 1,326,813, 微调 27, 合并 3, 量化 115, 使用本模型的 Space 100 个. 上月下载量按 30 天摊, 约每天 4.4 万次. Space 一栏展示了 5 个, 加上 「另有 95 个」 正好 100, 这一处是自洽的. 展示出来的 5 个 Space 里, 有两个是分词器可视化 (tokenizers-wasm-demo, Tokenizer-Visualizer), 两个是排行榜, 一个是通用查看器, 没有一个是具体应用.

还有一个容易读错的小图. 文件名叫 downloads-last-month 的图标印着 45, 但它在版面上紧跟 「Community」, 应是讨论区的计数徽标, 不是下载量. 合集卡片上的 「28」 按排版像是点赞数. 这些数字只反映页面打印那一刻的状态, 会随时间变化, 引用时要带上 「打印时」 这个前提.

## 8. 本页对不上的数

把本页正文, 柱状图, 曲线和评测面板互相对照, 对不上的有这几处:

- MLE Bench Lite 排名: 正文说 66.6% 「仅次于 Opus-4.6 和 GPT-5.4」, 柱状图里 Sonnet 4.6 (72.7) 也更高, Gemini 3.1 Pro 同为 66.6, M2.7 实际并列第 4.
- MLE Bench Lite 比赛数: 22 × 66.6% ≈ 14.65 场, 不是整数. 第 4 页奖牌率曲线的台阶高约 1/23, 终点处金 10/23, 银 5/23, 铜 2/23, 合计 17/23 ≈ 73.9% (读图), 分母像 23 不像 22; 两条终点 (约 73.9%, 约 65.2%) 都不是 66.6%.
- GDPval-AA: 正文 ELO 1495, 柱状图 50, 量纲不同且本页未解释; 正文比较的 GPT5.3 不在图中, 图中三家闭源都更高.
- SWE-Pro: 正文说与 GPT-5.3-Codex 持平, 图中没有该模型; 56.22% 与面板和图里的 56.2 一致.
- VIBE-Pro: 正文说 「几乎持平」 Opus 4.6, 图里两者同为 55.6.
- Toolathon / Toolathlon: 正文和图拼写不同; 「全球第一梯队」 对应图中第 4.
- 推理框架: 称 「按字母顺序」, 实际不是.

另外几处不算矛盾, 但本页给不出答案: 30% 提升没有基线; Terminal Bench 2 和 NL2Repo 没有对照; WildClawBench 的 551 和 7.2 没有单位; SkillsBench 的星号没有脚注; 系统提示词被截断; Artificial Analysis 一组正文没提. 这些都应该当作 「本页未说明」 记下, 不要从其他来源拿数字补齐.

整体看, 本页的柱状图比正文更可靠, 因为它把同一批对照模型放在一起, 数字也直接印在柱顶. 正文的比较句多数挑了图外的模型 (GPT-5.3-Codex, GPT5.3) 或者图中对自己最有利的那一家. 读这张模型卡时, 以图为准, 正文当作厂商自评来读.
