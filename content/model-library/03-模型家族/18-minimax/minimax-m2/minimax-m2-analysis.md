# MiniMax-M2 系列解读：9.8B 激活怎样撑起 agent 场景

## 1. 定位：一份写给 agent 场景的系列报告

报告编号 arXiv 2605.26494v2，共 35 页，正文到第 31 页上半，之后是 3 页多参考文献和 1 页作者名单。它讲的是一个系列，不是单个模型：架构和预训练数字都属于旗舰 M2，数据管线和 Forge 被描述为从 M2 到 M2.5 再到 M2.7 一路演进的组件，主评测则几乎全押在最新的 M2.7 上。报告用 「checkpoint」 称呼 M2.7，暗示三者共用同一套骨架，但正文没有明说 M2.5 和 M2.7 的参数量是否与 M2 相同，读的时候要把 「M2 的架构数」 和 「M2.7 的评测数」 分开看。

篇幅分配很能说明作者的重心。架构和预训练合起来只占第 3 到 7 页，后训练数据占第 7 到 16 页，近 10 页；RL 算法和 Forge 系统占第 16 到 23 页；交错思考和自我进化 2 页；评测第 25 到 30 页。也就是说，这份报告的主角是数据和 RL 系统，模型结构只是交代背景。反过来，读者最想要的一些量化信息几乎都没有：后训练用了多少条数据，SFT 训了多少 token，RL 跑了多少步，奖励系数取多少，整体用了多少算力，全文一个数都没给。

## 2. 谱系：从 Text-01 的混合注意力退回全注意力

只按本文的说法，M2 和 MiniMax 自家前作的关系有两条线。第一条是注意力。第 3 页和第 4 页两次强调，M2 不再沿用 MiniMax-Text-01 那种把 Lightning Attention 和全注意力交错排布的混合设计，所有层都回到完整的多头注意力。第二条是 RL 算法。第 17 页的 CISPO 引自 MiniMax (2025a)，也就是参考文献里的 MiniMax-M1 报告，本文说的是 「adapt」，即在 M2 系列上做了改造。除了这两处引用，本文没有拿 M1 或 Text-01 的任何分数来对比，也完全没有提到 M2.1；系列内对比只出现了 M2，M2.5 和 M2.7 三个点。

如果只看结构上的借鉴，M2 离 DeepSeek 一脉反而更近。细粒度专家引的是 DeepSeekMoE (Dai et al., 2024)，用专家偏置减少辅助损失引的是 Wang et al. (2024a) 的无辅助损失负载均衡，MTP 明说 「following the design of DeepSeek-V3」，图 2 的结构也是 DeepSeek-V3 式的串联模块：嵌入和输出头共享，每个模块把上一层的隐藏状态和右移后的 token 嵌入各过一次 RMSNorm，拼接投影后再过一个 Transformer 块。不同的是注意力：M2 用的是 GQA，没有用 MLA。所以从谱系上说，M2 是 MiniMax 放下了自研的线性注意力路线，转而采用业界已被验证的 「细粒度 MoE 加 GQA 加 MTP」 组合，再把差异化押在数据和 RL 系统上。

## 3. 架构：两个数，以及几处没给的数

229.9B 总参数和 9.8B 激活参数是两个量。估算激活比例约为 9.8 / 229.9 ≈ 4.3%，而专家层面的比例是 8 / 256 = 3.125%。前者比后者高，原因是每个 token 都要走的稠密部分（注意力投影，路由器，归一化，嵌入和输出头）不参与稀疏化。本文没有给这部分的拆分，但嵌入可以粗算：200,064 × 3,072 ≈ 0.61B，若输入嵌入和输出头不共享权重，两者合计约 1.23B，占 9.8B 激活参数的八分之一左右。这说明在激活只有 10B 量级的模型里，20 万级别的词表本身就是一笔不小的开销。

注意力这边，48 个 query 头配 8 个 KV 头，每 6 个 query 头共享一组 KV。本文没给 head dim，所以 KV 缓存无法准确算。如果按常见取法做个假设：head dim 取 128 时，每 token 每层存 2 × 8 × 128 = 2,048 个数，62 层合计约 12.7 万个数，BF16 下约 248KiB（基于假设）；192K 上下文就是约 46GiB（基于假设）。若 head dim 是 64，这两个数都减半。不管取哪个，全注意力加 192K 上下文的 KV 开销都相当可观，这也是第 23 页要做全局 L3 KV 缓存池，第 27 页评测在 token 超过上下文 30% 时丢掉历史回复的背景。

MoE 部分的三个设计都围绕 「让路由更顺」。细粒度专家提高组合多样性；sigmoid 门控让每个专家的分数互相独立，去掉 softmax 的零和约束；可学习的专家偏置调节负载，让辅助损失可以 「greatly reduced」。注意措辞是大幅减小，不是去掉。本文也没有提到共享专家，没有给单个专家的 FFN 宽度，所以 229.9B 里专家参数占多少，注意力占多少，无从拆分。

## 4. 注意力取舍：为什么放弃 SWA

第 4 到 6 页是全文实验证据最扎实的一段。作者先交代评估困难：做 Text-01 时，混合注意力在 MMLU，BBH，MATH，LongBench 上看起来和全注意力持平，规模一大就在多跳推理上露馅；代理指标和真实下游表现的相关性也不稳。然后交代基础设施差距：线性注意力训练时常受显存带宽限制，推理时对低精度存储敏感，缺原生前缀缓存，和投机解码怎么配合也没谱。这两条合起来，意思是 「不是高效注意力不好，是我们在生产环境里没法可靠地证明它够好」。

表 2 和表 3 给了 M2 规模上全注意力和混合 SWA 的对照。预训练阶段，32K 的 RULER 两项都是 99.0 对 99.0，MMLU 和 MATH 几乎不变，掉分集中在 128K: RULER 128K CWE 从 90.0 掉到 72.0，MQ 从 99.0 掉到 93.0；另外在上下文里学新语言的 MTOB 掉得很厉害，e-k ChrF 从 44.8 掉到 27.2. SFT 之后，超过 32K 的 agent 任务 SWA 明显吃亏，SWE-verified 54.7 对 50.2，BrowseComp-zh 32.8 对 28.7; 32K 以内则有输有赢，IFBench 和 XBench-ds 上 SWA 反而更高。最难解释的是 τ²-Bench: retail 子集 SWA 高 5.2，telecom 子集 SWA 低 11.5（均为估算差值），同一个基准家族方向相反，作者没有讨论。第 5 页的 「Outlook」 留了口子：上下文继续变长，GPU 算力增长放缓，次二次复杂度注意力迟早会回来，只是 M2 这一代不赌。

## 5. MTP：一份训练信号，一条草稿通路

MTP 在 M2 里有两个身份。预训练时它是辅助目标，只有 1 个模块，损失权重从 0.3 退火到 0.1。表 1 的小模型消融（2B 激活，17.8B 总参数，500B token）显示 MATH 从 19.6 升到 21.3，KorBench 从 14.1 升到 15.0，HumanEval 从 29.7 升到 30.1，但 MMLU 从 39.8 降到 39.7。正文写 「consistently improves」，严格说并不成立，只是降幅只有 0.1，远在单次实验的噪声范围内。同一张表里细粒度专家一列的变化更大，而且 2/32 和 8/128 都是 1/16，说明提升来自切分粒度而不是激活更多。

第二个身份是推理加速。继续预训练的衰减阶段，模块从 1 个扩到 3 个，新模块用复制的权重初始化，先冻结主模型只训 MTP，等损失稳定再联合训练；作者还说试过全程冻结主模型，效果更差。到 RL 阶段，MTP 通过 top-K KL 散度损失和策略持续联合训练（第 22 到 23 页），目的是让策略一边变，草稿接受率一边保持。这一点很实际：RL 里策略分布一直在漂，如果草稿头不跟着更新，投机解码的收益会越来越小。可惜本文没给接受率，也没给 3 个草稿 token 下的实际加速倍数。

## 6. 预训练数据：29.2T 能加出来，但也只有这么多

预训练总量可以核对：恒定阶段 19.9T 加衰减阶段 9.3T 正好 29.2T. 上下文分三步扩：8K，32K，192K，长文本主要来自拼接的高质量代码，天然长篇的 PDF 和按主题打包的相关文档。数据来源列了网页，学术文献，书籍，代码，结构化问答；质量评估用 「基于模型的奖励打分加辅助分类器」，代码，数学和 STEM 显著上采样。

除此之外就没有更多数字了：各来源占比，上采样倍数，三段上下文分别用了多少 token，去重和过滤的比例，都没给。和后训练那边大段的流程描述比，预训练数据这一节只有一页，读者能拿到的只有总量和阶段结构。

## 7. 后训练数据：先把奖励做可信

第 2 页的主要贡献里有一句话概括了整节的思路：提高每条被接收轨迹的奖励质量和可信度，是释放基座潜力的关键。后面的每条管线都在落实这句话。SWE 管线从 GitHub PR 出发，用 agent 构建多语言 Docker 环境，按 bug 修复，功能新增，性能优化分别构造测试奖励，再用模型检查描述和测试是否一致，最后做 bug 注入，提交合并，SWE-Test 转换，代码审查四类增强。AppDev 管线没有现成的测试，就让专家写元查询，系统提示和量表，再用 Agent-as-a-Verifier 真的把应用部署起来，分执行层，交互层，视觉美观层三层验证，执行层不过直接淘汰。Terminal-Gym 以 Stack Overflow 为种子，改写成结构化任务后分四档只留前两档，然后生成 Dockerfile 和测试，抹掉指令里的提示，用统一测试集防止过拟合描述风格。

协作办公四个领域的共同点是 「验收信号和产物格式对齐」：深度搜索要求答案来自实际检索到的证据，开放式报告改用量表评审；办公任务用多轴量表外加一轮清除编造内容的清理；财务表格优先做数值级精确匹配，由外部引擎重算公式后比对单元格；幻灯片则叠加执行成功，agent 评判，规则化版式检查和把渲染结果当图像打分的视觉评分器。推理数据走的是 Scaling 路线，沿 Query 侧，Response 侧，Training 侧三条轴扩充，再加一条质量保障管线。通用对话和角色扮演各有一节，角色扮演还专门做了 Role-Play Bench。代码安全方向只提到正在扩展 CVE-Factory，没有展开。

这一整节的问题和优点一样明显。优点是流程写得具体，读者能看出每一步在防什么。问题是几乎没有数量：六个阶段各淘汰多少 PR，AaaV 三层的权重和阈值，Terminal-Gym 四档的占比，提示蒸馏丢掉多少指导，全都没有。第 12 页还有一句 「Experimental results demonstrate the efficacy」，对应的实验全文找不到。另外，办公任务的种子取自 GDPval，评测又用 GDPval-AA，本文没交代二者之间有没有隔离。

## 8. RL 目标：CISPO 和三段式奖励

第 16 到 17 页先把问题建模清楚：LLM 是策略，生成接口之外的一切，包括上下文管理，记忆，子 agent 通信，都算环境。这样训练就可以以单个（s_t, a_t）对为原子样本，不管 s_t 是追加消息，截断上下文还是整段重写得来的，策略都不用关心；信用分配仍在整条轨迹上做。这个抽象后面直接变成了 Forge 的系统边界。

CISPO 的目标函数（式 2）有三个特点：按全组 token 总数归一化；重要性比值做停止梯度，只调节梯度大小；比值裁剪到 [0, 1 + ε]。概率比本来就不小于 0，所以下界 0 实际上等于不裁下限，真正生效的是上界。优势用 reward-to-go 减轨迹级基线，奖励由三部分组成：过程奖励（惩罚语言混杂和工具调用格式错误，奖励结构良好的中间推理），完成时间奖励（实际耗时相对参考时间，经单调递减函数整形），以及任务表现奖励。完成时间奖励值得多看一眼：它鼓励模型并行调用工具，这是纯正确性目标学不到的。不过 α，β，h 的形状，T_baseline 的取法，式（6）的 γ，ε_high 都没给，式（4）和式（6）一个有折扣一个没折扣，也没讲清最终用哪个。

混合领域训练是另一条要点。每个阶段同时从推理，编程，agent，通用四个领域取数据，阶段之间调三条轴：领域比例（前期偏推理和通用，后期提高 agent 和编程），按领域扩上下文长度，难度分布逐步变难。作者的理由是单领域训练会遗忘，按领域依次训会负迁移。这是当前多数 agent 模型的共识做法，本文同样没有给各阶段的具体比例。

## 9. Forge：不可能三角里的三处取舍

第 19 到 20 页把 RL 基础设施的目标写成 「吞吐乘样本效率」，约束是梯度方差有界，收敛误差有界，并且对任意 agent 架构成立。三个目标两两冲突：rollout 时长从几秒到几小时，追吞吐就会破坏分布一致；支持任意 agent 就难以和训练逻辑紧耦合；长轨迹的稳定信用分配又和偏向短任务的吞吐最优调度相冲突。Forge 的回答是三层结构：agent 侧只产轨迹；中间件的 Gateway Server 统一路由补全请求，Data Pool 异步收集数据；引擎层的 Rollout Engine 和 Train Engine 各自扩展，靠权重同步连起来。

白盒和黑盒的区分是 Forge 最有意思的地方。白盒 agent 把上下文管理注册到框架里，训练时能精确重建每一步的状态，适合滑动窗口截断，定期摘要这类规则明确的策略；黑盒 agent 只把请求发到 Gateway，框架只收集外部可见的（s_t, a_t, o_t）。作者说这套设计已在数百种脚手架，数千种工具调用格式上验证过。这也解释了评测部分为什么敢让所有模型共用 Claude Code 脚手架：训练时 M2 系列已经在大量第三方脚手架上练过。

调度和计算优化各有一招。窗口化 FIFO 只允许在大小为 W 的滑动窗口里贪心取已完成的轨迹，窗口外一律等待，正文给的是 W = 0.3N；图 5 的示例却是 N = 8，W = 4，即 0.5N，还标出 「最大乱序容忍 3 = 4 - 1」 和 「最大 off-policy 滞后 10 = 8 + 3 - 1」 两个正文没提的公式。前缀树合并利用同组样本的共享前缀，前向只算一次再分叉，数学上和逐样本训练等价，最高加速 40 倍，但没给平均值。推理侧还有预填充和解码分离，以及以 DFS 为后端的全局 L3 KV 缓存池，同样只有描述没有数字。

## 10. 交错思考与自我进化

交错思考的定义很简单：轨迹写成（r_1, a_1, o_1, r_2, a_2, o_2, ...），每一轮的完整输出，包括思考块，都追加进历史，供下一轮使用（式 10）。对照组是两种常见做法：所有推理都放在最前面，或者每轮删掉之前的推理。图 7 用三列消息序列画出了不思考，扩展思考和交错思考的区别。作者说消融显示保留思考块在各 agent 基准上都有收益，深度搜索和软件工程尤其明显，但第 24 页一个数字都没有。保留思考块的代价是上下文增长更快，这和第 27 页评测配置里 「超过 30% 上下文就丢历史」 的做法形成了一个值得追问的张力，本文没有讨论。

自我进化部分给了三个数：RL 团队的日常迭代工作量中，M2.7 承担 30% 到 50%；在优化内部编程脚手架的任务上自主跑了 100 轮，内部评测提升 30%；Agent Harness 本身由内部 M2.7 生成，没有人写的代码。三个数都没有口径说明：工作量按什么算，30% 是相对什么基线，评测集是什么，都要靠读者信任。图 8 倒是把分工画得很清楚：实验规划，审阅讨论，迭代决策由人参与，开发运行和分析汇报由 AI 自主，分析环节允许 agent 自动续跑，进入下一轮必须由人触发。这个 「人掌方向，模型动手」 的边界比那几个百分比更有参考价值。

## 11. 评测：表 4 应该怎么读

表 4 共 23 行，按能力分五组。先看 M2.7 相对 M2.5 的变化。23 行里 22 行上涨，唯一下降的是 MMLU-Pro (85.2 → 81.8)。估算 23 行平均涨 7.2 分；分组看，编程 agent 平均 +6.4，应用开发 +4.8，搜索 +6.8，办公与工具 +13.0，推理与知识 +4.6。办公与工具一组涨得最多，其中 Finance Modeling Pro +23.2，GDPval-AA +15.0，MEWC v2 +13.5，这和第 28 页 「这一组系列内提升空间最大」 的说法吻合，也对应了第 13 到 14 页新写的办公和财务数据管线。

再看和闭源模型的相对位置。23 行里 M2.7 单独拿到最高分的只有 Multi-SWE-bench (52.7) 一行；VIBE-Pro 和 Opus 4.6 并列 55.6，但 Sonnet 4.6 的 56.1 更高；MLE Bench Lite 和 Gemini 3.1 Pro 并列 66.6，但三个模型更高。和 Opus 4.6 逐行比，M2.7 赢 6 行（Multi-SWE-bench, MEWC v2, AIME 2026, GPQA-Diamond, IFBench, AA-LCR），平 1 行，输 16 行，平均差约 -3.0 分。和 GPT 5.4 在双方都有分数的 21 行比，M2.7 赢 4 行（SWE-bench Multilingual, Multi-SWE-bench, RISE, IFBench），平均差约 -5.7 分。差距最大的几行是 Terminal-Bench 2.0（比 GPT 5.4 低 18.1），Finance Modeling Pro（低 18.3），HLE（比 Gemini 3.1 Pro 低 16.7）和 MM Claw（比 Opus 4.6 低 12.7）。所以 「approaches the strongest closed-weight frontier systems」 的说法大体可以接受，但更准确的描述是：在多数 agent 编程和部分推理基准上贴近，在终端操作，专业办公和前沿知识题上仍有明显差距。

读表时还要注意几件事。一是评测配置不完全统一：GPT 5.4 在 SWE 系列上用的是它自己的 CodeX 脚手架，Terminal-Bench 2.0 的部分基线直接引用官方报告。二是多个基准是内部的（NL2Repo, VIBE-Pro, HyperTask, RISE, MM Claw, MEWC v2, Finance Modeling Pro），外人无法复现。三是 IFBench 上 M2.7 的 76.0 远高于 Opus 4.6 的 53.1 和 Sonnet 4.6 的 56.6，差距大到值得怀疑两家在这个基准上的配置是否可比，本文只把它归功于多领域 RL 和量表过滤。四是 「闭源模型每 token 激活多一个数量级」 这句话出现了两次，但本文没有给任何闭源模型的参数量，这句话无法在本文内核对。

## 12. 系列内进步：图 9 的十一项

图 9 是全文唯一能看到原版 M2 分数的地方，十一项基准，每项三根柱子。按图上的数估算，M2 到 M2.7 的总涨幅平均约 18.7 分；其中 M2 到 M2.5 这一步贡献约 136.3 分，M2.5 到 M2.7 贡献约 69.0 分，前一步占总涨幅的三分之二左右。分项看差异很大：BrowseComp 从 44 到 77.8 涨了 33.8，但几乎全发生在第一步（+32.3）；GDPval-AA 从 34 到 50 涨了 16，却几乎全发生在第二步（+15.0）；MLE-Bench Lite 两步分别是 +11.5 和 +15.1。这说明各项能力不是同步推进的，每一代补的方向不同，和作者 「稳定的提升轨迹」 的总结并不完全一致。

作者在第 28 页还说，M2 原本就强的 SWE-bench Multilingual 和 Multi-SWE-bench 「进步更平缓」。按图 9 的数，这两项从 M2 到 M2.7 分别涨了 20.0 和 16.5，比 GPQA-Diamond (+11.8), AA-LCR (+11.0), Wide Search (+12.9) 都多，只有第二步（+2.4, +1.4）是小步；而 Multi-SWE-bench 的起点 36.2 也谈不上强。另外两个口径差异也要记住：图 9 的 AIME 是 2025 年那一届，表 4 用的是 2026 年；图 9 里 M2 的 BrowseComp 取自 Hugging Face 官方分数，不一定在同一脚手架下评测。

## 13. 本文数字核对：对不上的地方

逐页核对下来，以下几处数字或说法在本文内部对不上。它们大多不影响主结论，但读者引用时应当注意。

- 第 2 页说图 1 预览了主要数字，但文中点名的 SWE-bench Multilingual 76.5，Terminal-Bench 2.0 57.0，BrowseComp 77.8，AIME 2026 94.2，GPQA-Diamond 89.8 都不在图 1 里；图 1 的 Artificial Analysis 面板（M2.7 为 50，M2.5 为 42）在表 4 中又没有对应行。图 1 的图注说覆盖推理与知识，实际八个面板里没有单独的推理基准。
- 第 5 页说 MTP 在各基准上 「consistently」 提升，表 1 里 MMLU 从 39.8 降到 39.7。
- 第 21 到 22 页正文给 W = 0.3N，图 5 的示例是 N = 8，W = 4，即 0.5N。
- 第 28 页说绝对涨幅最小是 「+11 points (AA-LCR, GPQA-Diamond)」，同段又写 GPQA-Diamond +11.8；严格说最小的只有 AA-LCR 的 +11.0。
- 第 28 页说 SWE-bench Multilingual 和 Multi-SWE-bench 进步更平缓，图 9 显示两者 M2 到 M2.7 涨 20.0 和 16.5，高于推理类和 Wide Search。
- 第 30 页说最好一次是 9 金 5 银 1 铜，共 22 个竞赛，按 22 算是 68.2%；图 10 末端的金，银，铜和任意奖牌率约为 39.1%，21.7%，8.7%，69.6%，恰好对应 9/23, 5/23, 2/23, 16/23（读图），分母像是 23，铜牌像是 2 枚；图 10 横轴还画到约 26.7 小时，超过正文说的 24 小时。
- 三次平均 66.6%: 22 个竞赛乘 3 次共 66 个任务次，44/66 = 66.67%，四舍五入应为 66.7, 66.6 只能来自截断。
- 第 25 页写自主迭代 100 轮，第 30 页写 「hundreds of rounds」，两处说的是不同案例，但后者没有给轮数。
- 第 5 页说新 MTP 模块从 「main model」 复制权重，第 7 页图 2 的 「Copy & Initialize」 箭头画在 MTP 模块之间。
- 第 18 页式（4）的优势不带折扣，式（6）带 γ，并且用 τ 作求和下标，与第 17 页的轨迹记号重名。
- 表 4 里 MMLU-Pro 是 23 行中唯一退步的一项（85.2 → 81.8），正文没有提。

这些问题里，分量最重的是 MLE Bench Lite 的计数。第 30 页把它作为自我进化最直接的证据，但正文的竞赛数，奖牌数，时长和图 10 各差一点，平均数的取整也对不上。单看任何一处都可能只是笔误或作图口径不同，合在一起就说明这组数据在成文时没有被仔细对过。引用 「66.6% 奖牌率」 时，最好同时注明报告里这几处不一致。

## 14. 读完之后留下什么

这份报告最有价值的部分，不在模型结构，而在它把 agent 训练拆成了三个可以独立推进的问题：数据要有和产物对齐的可信奖励，RL 系统要能接住任意脚手架和长短悬殊的轨迹，模型自己要能参与下一轮迭代。前两条都有相当具体的流程描述，窗口化 FIFO，前缀树合并，白盒黑盒统一接入，这些设计换到别的团队也能直接借鉴。第三条目前更像方向声明，支撑它的几个百分比都缺口径。

它的短板同样集中：几乎所有和规模，超参数，算力相关的数字都缺席，多个关键基准是内部的，自我进化的核心证据在计数上还有出入。对读者来说，比较稳妥的读法是：把 229.9B 总参数，9.8B 激活，29.2T token 和表 4 的分数当作硬数据；把数据管线和 Forge 当作可以参考的工程设计；把自我进化的 30% 到 50%，100 轮和 30% 提升当作团队的自我报告，等有更多公开细节时再核对。
