公开材料是 x.ai 在 2025 年 8 月 28 日发布的一篇产品公告，共 8 页，不是技术报告，也没有附技术附录。正文讲了定位，速度，价格，一个基准分数和发布计划；参数量，网络结构，上下文窗口，训练数据配比，评测对照组页面一个都没有。

# Grok Code Fast 1：一篇速度公告里能读出什么

来源：同目录 `grok-code-fast-1.md`（共 8 页），对照译稿 `grok-code-fast-1-bi.md`，散点图数值回查 `grok-code-fast-1.pdf` 第 4 页。配图 4 张，没有一张是技术图：`images/p01-a-speedy-daily-driver.png` 是猎豹状的营销主视觉，`images/p05-mario-rodriguez-...png` 是 GitHub 首席产品官的头像，`images/p05-try-free-on-github-copilot-...png` 是试用按钮的图标，`images/p06-2026-spacexai-llc.png` 是 SPACEXAI 字标。全文唯一的数据图，即第 3, 4 页的 TPS 对输出价格散点图，没有被 MinerU 抽成图片，只剩两根轴的标签和一个错认的表格，读数要靠 PDF 原文。

这篇公告能回答三件事：grok-code-fast-1 的 API 定价是多少，官方测的 TPS 是多少，SWE-Bench-Verified 自测分数是多少。它回答不了模型多大，什么结构，上下文多长，以及那个 70.8% 在公开口径下能不能复现。

## 1. 公告构成：三块卖点，一张图，一个分数

第 1, 2 页是定位段：现有模型在 agentic coding 工作流里「循环推理加工具调用慢得让人沮丧」，所以 xAI 从头做了一个专攻这个场景的推理模型，训练时与首发平台共同打磨行为，掌握 grep，终端，文件编辑等工具。第 2 页起三段小标题把卖点摆开：**Blazing fast** 讲 serving 速度和 prompt caching，**A versatile programmer** 讲语言覆盖和任务类型，**An economical choice** 讲三档定价。第 3 页夹了一条用户推文和一张预告性质的图题，第 4 页是 Methodology 和评测口径，第 5 页是合作伙伴背书和 API 定价复述，第 6 页是发布计划和模型卡链接，之后到第 8 页全是网站页脚。

按篇幅算，与机制有关的文字只有第 2 页「brand-new model architecture」一句，第 2 页「several innovative techniques」一句，和第 4 页 Methodology 一小段，加起来不到一段。其余是产品语言：每块卖点都是形容词加一个数或者一个数都没有。

## 2. 速度：一个 190，三种混在一起的「快」

### 2.1 TPS 190 与它的口径

第 4 页 Methodology 写了测量方式：通过各家 API 直接测回答生成速度，**只算最终回答的 token**. PDF 第 4 页的文字层给出图上唯一一个数值：Grok Code Fast 1 标注 190 TPS。这个口径的选择本身就是产品声明的一部分：推理模型的 CoT 也按输出 token 计费，但不计入 TPS 的分母，所以「推理慢」在这张图上被口径结构性抹掉了，剩下的只是答案正文的吐字速度。第三方测速机构对推理模型通常也采用类似口径，即思考时间之后的输出速度，可见这是一个行业惯例而非 xAI 独创，但惯例不等于无偏：用户体感里的「快」更多取决于从提问到首个有用输出的总延迟，而那个量在这张图里没有。

### 2.2 图的坐标设计与四个 serving 栈

散点图横轴是每 1M token 的输出价，右端点标 \$20，纵轴是 TPS，除 Grok Code Fast 1 自己的 190 外没有任何刻度。图上 6 个点：橙色的 grok-code-fast-1 独占左上高位，灰点是 Qwen3-Coder，Gemini 2.5 Pro，Claude Sonnet 4，GPT-5 和 Grok 4，全部挤在中下部，具体 TPS 一个都读不出来。这张图的视觉结论「又快又便宜」是设计出来的：唯一能读的两个数都长在自家点上，竞品只剩相对位置。

可比性问题在 Methodology 的三条子弹里：Gemini 2.5 Pro，GPT-5，Claude Sonnet 4 走各家公开 API，Grok Code Fast 1 和 Grok 4 走 xAI API，Qwen3-Coder 走 DeepInfra 的 fp4 低精度托管。TPS 的一半测的是模型，一半测的是部署：同样的权重，serving 栈，并发档位，精度配置不同，数字可以差出几倍。页面对前四项一个都没对齐，对 Qwen3-Coder 反而自承 fp4「reduces response quality」，等于在同一张宣传速度的图里放进了一个「更快但质量打折」的参照点。低精度换来吞吐和显存收益是量化的常规取舍，见 [量化](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/6.3.1-量化.md)；推理侧还能叠投机解码，连续批处理这类与模型无关的加速手段，见 [推理框架与高级优化](../../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6-推理框架与高级优化.md)。公告把 serving 团队的头功记在「several innovative techniques」名下，技术是什么，哪一项贡献了多少，页面一字未提。

还有第三种「快」根本不在图的坐标里：第 2 页那句「你还没读完 CoT 第一段，模型已经调了几十次工具」描述的是 agentic 循环的响应性，也就是工具往返之间的等待短。这是产品体验里的关键一环，但页面没有给任何一次工具往返的延迟数，三种快混在一起用一个 190 代言。

## 3. 定价：三档单价与缓存经济学

第 3 页给出三档 API 定价，每 1M token 计：输入 \$0.20，输出 \$1.50，缓存输入 \$0.02。第 5 页原样复述一遍，功能是区分两条获取通道：七家首发合作伙伴限时免费，xAI API 按价常态收费。三档之间的倍数结构传递了明确的计费信号：缓存输入是常规输入的 1/10，鼓励客户端稳定地复用前缀；输出是输入的 7.5 倍，而推理模型的 CoT 按输出计费，等于对 TestingTime 直接收费 —— 想得越久，账单越厚。

prompt caching 的省钱逻辑对应服务端复用前缀的 KV，省掉重复的预填充计算，一般机制见 [KV 缓存与内存优化](../../../../llm-guide/6-训练与推理优化/6.4-KV缓存与内存优化/6.4-KV缓存与内存优化.md)。公告给的命中率数字是「与首发合作伙伴配合使用时经常超过 90%」，两个限定都重要：命中靠的是合作伙伴平台把系统提示，工具定义，代码上下文这些重复前缀原样发回，换一个不复用前缀的客户端，命中率无从谈起；「经常」是频率词，分母按请求算还是按 token 算，页面没定义。xAI 的缓存窗口最短多长，保留多久，命中怎么判定，也都没写。

把价格放回那张散点图：横轴选输出价而不是输入价，正是三档里最高的口径，grok-code-fast-1 的 \$1.50 在 \$20 量程的最左端，竞品的输出价越远越靠右。图和定价互相成就，各自挑了对自己最有利的轴。

## 4. 训练与评测：流程词很多，机制词一个都没有

### 4.1 训练：从零开始，然后没了

第 2 页关于训练的全部信息是四句：从全新架构从零构建；预训练语料编程内容丰富；后训练数据取材真实 pull request 和编码任务；训练全程与首发平台协作打磨行为。这四句里没有一个可核实的量：参数量，层数，注意力结构，词表，上下文长度，数据规模，训练算力，全部缺失。「brand-new model architecture」是唯一一句结构声明，与 [Grok 4 公告](../grok-4/grok-4-bi.md) 里「scaled next-token prediction pretraining」级别的叙述相比，信息量只多一个新字。后训练用了 SFT 还是强化学习，奖励怎么设计，页面没写；模型卡链接（日期 2025-08-26）是全文唯一指向更多技术信息的出口。

与首发平台协作训练这一点值得单独一句：让 Cursor，GitHub Copilot 这类平台在训练期就参与打磨，本质是把「在真实 agentic 环境里的行为」提前变成训练信号，和第 6 页「根据反馈部署多个新 checkpoint」是同一条迭代线的两端。这解释了为什么公告里 agentic 能力的描述（掌握 grep，终端，文件编辑）没有配套基准 —— 平台侧的使用数据就是它自己的评估场，只是这个数据不公开。

### 4.2 评测：70.8% 的三个限定词

全文唯一一个基准分数：SWE-Bench-Verified 完整子集 70.8%，用的是 **xAI 自己的内部 harness**。三个限定词各砍一刀横向可比性。「SWE-Bench-Verified 完整子集」：Verified 本身就是从 SWE-Bench 全集中人工核验出的子集，full subset 指把这 500 题跑全，不跑子采样。「internal harness」：脚手架，提示词，工具配置不公开，同一模型换一套公开脚手架分数可以差好几个点。缺对照组：全文没有给任何竞品在同一基准上的分数，70.8% 是孤岛数字。评测口径的通用问题见 [Benchmark 与 Eval](../../../../llm-guide/13-Agent/13.5-Agent应用与治理/13.5.2-Benchmark与Eval.md)，SWE-Bench 这类解题基准在 agentic coding 里的角色见 [IDE 与 Coding Agent](../../../../llm-guide/13-Agent/13.5-Agent应用与治理/13.5.1-IDE与Coding-Agent.md)。

第 4 页后半段是评测哲学：基准不能完整反映真实软件工程，所以要配常态化人工评估和自动化评估。这套说法与第 5 页「被程序员评价为又快又可靠」衔接，但人工评估的样本量，评分量表，是否盲评，和谁对比，全部缺失，披露粒度止于「这是训练信号的一部分」。页面诚实地把这套评估的定位写明了 —— 「to guide our model training」 —— 它是训练的罗盘，不是独立的第三方验证。

## 5. 发布策略：stealth，免费，以天为单位的迭代

grok-code-fast-1 的发布路径分三步：先以 sonic 为代号 stealth 上线约一周，期间盯社区反馈并多次换 checkpoint；再以 70.8% 和 190 TPS 两个自测数字正式公告，同时用七家合作伙伴的限时免费铺量；最后承诺「改进以天而不是周到来」。这套打法把传统「训练完再发布」改成「边发布边训练」，代价是公告里每个数字的时效性都变短：第 6 页明说多个 checkpoint 已经轮换过，读者看到的 70.8% 对应哪个 checkpoint，页面不保证。

第 6 页「未来几周」预告了一个新变体：支持多模态输入，并行工具调用，更长上下文，已在训练中。这句话的反面就是当前版本的能力边界，页面没说破但读得出来：纯文本输入，串行工具调用，上下文有限。具体窗口多大，一次能并发调几个工具，都没给数字 —— 报告里没写，也不替它猜。

## 6. 本页的空白与对不上的地方

空白是主体：参数量，架构，词表，上下文窗口，训练数据规模，后训练方法，竞品的任何分数，上下文长度，全部缺失；安全，拒答，幻觉，长上下文评测也都不在这篇公告里。页面上两处措辞值得记下：「full subset of SWE-Bench-Verified」的子集叠子集写法，和把人工评估当训练信号却用「rated by programmers」的验证句式收尾。

对不上的地方集中在这几处。一是三档价格在第 3, 5 页重复出现，数字一致，不是改价而是通道区分。二是公告日期 2025 年 8 月 28 日与页脚「© 2026 SpaceXAI LLC」并存，后者是 xAI 与 SpaceX 合并后换上的网站模板，同家族 [Grok 4 公告](../grok-4/grok-4-bi.md) 有同样现象。三是抓取痕迹：第 2 页英文行里夹着的孤立「8」和「由 Cline」是三个免费试用按钮被 OCR 拆散的残留；第 3 页「Example 1 of 2」说明原站有 2 条演示，只抓到 1 条；第 5 页评价轮播只剩 GitHub 一张卡片，表里的 `[caco2]` 是翻页箭头的 OCR 残留；第 3, 4 页的散点图没有被抽成图片，轴标签被错认成两格表格，图上 6 个点的 TPS 除 190 外无从读起。除这些之外，页面上仅有的几个数字 —— \$0.20，\$1.50，\$0.02, 190, 70.8%，90% —— 彼此没有矛盾，只是每一个都缺对照或缺口径。
