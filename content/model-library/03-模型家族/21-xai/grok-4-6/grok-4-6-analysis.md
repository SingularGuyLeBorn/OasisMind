# Grok 4.6: 一次以长程 agent 为中心的后训练迭代

来源: 同目录 `grok-4-6.md` (页标记 `page 1 of 7` 到 `page 7 of 7`), 对照译稿 `grok-4-6-bi.md`. 配图 4 张, 只有 `images/p02-com-p-https-x-ai-etitor-fi-g-https-x-ai-ures-are-drawn.png` 带数据 (Artificial Analysis Intelligence Index 柱状图), 另外三张是 API key 图标, SPACEX 字标和深色模式开关. 表格注明的「最优加粗」在 md 和 PDF 文字层里都查不到, 哪几格加粗无法核实; 第 2 页顶部有一段 0:01 / 0:46 的演示视频, 内容没被抓下来. 数字一律回源 md.

这份材料能回答的问题是: 从 Grok 4.5 到 Grok 4.6 的一个月里, xAI 动了训练流水线的哪几段, 评测上换到了哪个坐标系, 以及价格渠道有没有变. 它回答不了模型本身长什么样, 也回答不了那些定性说法背后有没有数字支撑.

## 1. 在家族里的位置: 4.5 之后四周, 重心从「会做题」移到「做得久」

[Grok 4.5 公告](../grok-4-5/grok-4-5-bi.md) 发布于 2026 年 7 月 16 日, 自我定位是 coding, agentic 任务和知识工作的最强模型, 训练面讲的是大规模数据过滤和覆盖几十万任务的强化学习, 连推理吞吐都给了具体数字 (80 TPS). Grok 4.6 四周后到来, 定位句几乎刻意地换了个轴: 不再强调单次能力, 而是「long-running agents」和「more ambitious interactive and visual work」——能陪着一个复杂任务走很多步, 以及做出更像成品的交互和视觉结果. 定价原样保留 (后详), 对手坐标系从 Datacurve 的一套编程基准换成了 Artificial Analysis 指数加 GPT-5.6 Sol Max, Fable 5 Max 两个新名字.

结构上这篇公告是家族里少见地把训练讲出了流水线感的: 补充训练 run 打底, 用上一代模型重生成 SFT 轨迹, 再上大范围的 agentic RL, 三段各有一句具体做法. 和 [Grok 4 公告](../grok-4/grok-4-analysis.md) 那种「强化学习推到了预训练量级」的宏大但缺口径的叙述相比, 4.6 这段说的都是可指认的动作, 只是每个动作都停在名称层面, 往下再一层就是空白. 按篇幅算, 正文一大半仍是评测表和产品信息, 训练部分浓缩在三段话里.

## 2. 训练: 三段流水线各动了一刀

### 2.1 补充训练 run: 更长, 数据更人造, 优化器换过

第一段说 Grok 4.6 经历了一轮比 4.5 **更长的补充训练 (supplemental training run)**, 配方是三样: 为推理和高级技术概念精选的**模型生成数据**, 高质量工程数据, 改进过的**优化器和训练配方**. 它的功能定位写得很清楚: 为后面的 SFT 和 RL 阶段提供一个更强的 foundation, 也就是说这一段扮演的角色介于预训练和真正的后训练之间. 页面没说这轮训的是什么目标 (续训 next-token prediction 还是别的混合目标), 多少数据, 多少卡, 一个数都没有.

把「模型生成数据」放进这个阶段是有代表性的做法: 推理和高级技术概念这类内容, 真实文本的覆盖和密度都有限, 用模型自造数据可以按需求定制难度和题材, 代价是数据分布被人造痕迹污染的风险, 需要过滤.「改进的优化器」没有名字, 不知道动的是优化器本身还是只是超参和课程安排, 两者的工作量差一个量级, 这里无法区分. 补充训练这个概念上接预训练, 下接 SFT, 业内常叫 mid-training, 是不是这个含义, 报告里没写, 是按行文的推测.

### 2.2 用 Grok 4.5 重生成 SFT 轨迹: 教师就是上一代

第二段是全篇信息浓度最高的一句: **用 Grok 4.5 重新生成 SFT 轨迹**, 覆盖不同推理强度, 不同 agent 框架, 以及 STEM, 软件工程, 知识工作等领域, 然后用模型自动检查**过滤掉有问题的轨迹**. 「regenerate」意味着 4.5 当年训练时已有过一版轨迹, 现在是按新需求重做; 教师选 4.5 的理由页面没写, 最朴素的解释是时间线——造数据时 4.6 还不存在, 4.5 就是手上最强的模型. 用上一代模型给下一代造 SFT 数据, 是自蒸馏 (self-distillation) 的标准形态: 数据风格统一, 难度可控, 比复用旧轨迹更贴合新的训练目标, 但学生的天花板被教师压住, 教师的错误和习惯会原样传下去.

过滤那句是对这个风险的标准回应, 但也埋着循环: 检查器本身是模型, 没通过的轨迹「有问题」是按检查器的标准判的, 检查器的盲区就是数据集的盲区. 这套「生成—过滤—再训」的闭环和拒绝采样式 SFT 是同一个骨架, 更系统的机制见 [OPD 与自蒸馏](../../../../LargeLanguageModelGuide/4-后训练/4.9-OPD/4.9-OPD.md); 数据侧的质量筛选一般做法见 [SFT 数据质量筛选与训练技巧](../../../../LargeLanguageModelGuide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md). 覆盖面上有两个值得留意的维度: 「reasoning efforts」复数, 暗示轨迹按不同推理强度分档标注或生成; 「agent harnesses」复数, 说明数据不是只在一个脚手架下采的, 模型要学的动作模式跨多个框架.

### 2.3 agentic RL 的任务面: 往重环境扩

第三段列了 **agentic RL** 的任务范围: 知识工作, 通用编程, 加上面向**内核优化, 网页开发, 计算机辅助设计 (CAD)** 的专门环境. 和 4.5 公告里「几十万任务, 多步软件工程为主」的口径比, 任务面从纯软件往物理感更强的领域扩了一步. 这几类环境的共同点是有现成的客观判据: 内核可以看加速比, 网页可以跑测试, CAD 可以看几何约束和渲染结果, 都属于奖励能自动核对的任务, 和 4.5 写的「automated and model-based grading」衔接得上. 奖励里有没有模型当评委的部分, 各占多少, 本页没说.

重环境是 agentic RL 的真成本所在: 内核和 CAD 的 rollout 环境要真的能编译, 能跑, 能测量, 环境本身的工程量常常超过训练代码, 页面把这几个领域并列列出, 至少说明环境侧已经搭到了能进训练循环的程度. 一般性的做法和难点见 [AgenticRL 训练](../../../../LargeLanguageModelGuide/13-Agent/13.4-Agent训练与进化/13.4.1-AgenticRL训练/13.4.1-AgenticRL训练.md). 到这里三段流水线拼起来的图景是: 底座靠补充续训加固, 行为靠自蒸馏的 SFT 定型, 长程能力靠多环境 RL 磨出来——每一步的输入都讲清了名字, 每一步的剂量都没给.

## 3. 长程能力: 从「做完」到「自己检查」, 但全是定性

公告对能力的描述集中在「Turning ambitious ideas into working projects」一节, 通篇没有一个数字. 可指认的说法有四个: 模型能把宽泛的产品想法做成能跑的第一版; 能调研陌生领域, 搭结构, 实现核心交互, 在多轮反馈里继续打磨; 在更长的轨迹上「开始看到」更多**自我测试和自我验证**; 视觉和交互项目的首版更强, 能**一次性**确立结构和视觉语言, 之后建议的工作流是「先拿出一个相当成形的初版, 再在循环里迭代」. 最后一个说法和它在 Cursor, Grok Build 里的落点互相印证: 这类产品的用法本来就是 agent 循环, 模型的价值在于每轮循环的产出质量, 而首版越成形, 迭代轮数越少.

「自我测试和自我验证」要拆开读. 外部可判定的检查——跑测试, 编译, 在环境里试——可信度取决于环境给的信号强不强; 纯自省的检查——重读自己的输出找错——检查者和被检查者是同一个模型, 容易共享盲区, 更像是在表现「会检查」. 页面没区分这两类, 也没给任何成功率或轨迹长度数据, 「started to see」的措辞本身就说明这是观察不是测量. 这一节和训练一节是呼应的: SFT 轨迹按 agent harnesses 覆盖, RL 任务按长程环境铺, 目标都是把「陪任务走很多步」从偶发行为训成默认行为; 至于训没训出来, 评测表里没有任何一行直接测长程续航, Terminal-Bench 的 26% 是离这个目标最近的外显数字, 而它在四个模型里垫底.

## 4. 分数怎么读

### 4.1 十行表: 赢三行, 但每一行都比 4.5 高

逐项对上一代, Grok 4.6 的十行**全部上涨**: AA Intelligence Index 从 56 到 61, GDPVal-AA v2 从 1526 到 1753, CursorBench v3.2 从 66.7% 到 69.9%, DeepSWE v1.1 从 54% 到 65.9%, FrontierCode v1.1 从 56.6% 到 61.3%, APEX-Agents 从 47.1% 到 57.5%, Terminal-Bench v3.0 从 15.7% 到 26%, APEX-SWE 从 53.6% 到 56.4%, AA-Briefcase 从 1313 到 1577, Harvey LAB 从 12.9% 到 15.8%. 四周迭代能全行上涨, 最合理的读法是底座和 SFT 的改动吃到了所有任务上, 但采样次数, 方差都没给, 小差距的行 (如 APEX-SWE 的 2.8 个点) 按惯例要打折看.

对 contemporaneous 对手, 格局是三足: Fable 5 Max 赢五行 (AA Index 62, CursorBench 70.5%, FrontierCode 63.6%, APEX-Agents 59.2%, APEX-SWE 58.8%), GPT-5.6 Sol Max 赢两行 (DeepSWE 73%, Terminal-Bench 34.6%), Grok 4.6 赢三行 (GDPVal-AA 1753, AA-Briefcase 1577, Harvey LAB 15.8%). 换句话说, 这篇公告主打「agentic coding 前沿」, 但两个最硬的编程 agent 基准 (DeepSWE, Terminal-Bench) 恰好都不在 Grok 4.6 手里; 它赢的三行偏知识工作和专业领域. 表注还写明对手分数「取自自报或公开结果中的最好值」, 而 Grok 自己的数大概率是统一评测跑的, 两边口径不对称, 分差小的行不宜过度解读.

### 4.2 「打平 GPT-5.6 Sol」是复合口径上的平

第 2 页的柱状图上, Grok 4.6 与 GPT-5.6 Sol (Max) 同为 61, Fable 5 (Max) 以 62 居首, Grok 4.5 (High) 56. 这个 61 是 **Artificial Analysis Intelligence Index**, 九个基准的复合分数, 权重和成分都定义在第三方手里, 本页只说「composite score of nine benchmarks」, 没列是哪九个——第 4 页那张十行表也显然不是指数的逐项展开. 复合指数的并列意味着加权后的总分相等, 逐项可以差得很开: 这张表里 Grok 4.6 对 GPT-5.6 Sol Max 既有 Terminal-Bench 落后 8.6 个点, DeepSWE 落后 7.1 个点, 也有 Harvey LAB 领先 13.3 个点, 量尺不同, 全靠权重折算成一个数. 所以「打平」在这一个口径上成立, 换个权重分配完全可能翻盘.

另一个口径问题是档位的名字: Grok 这边列的是 **High**, 对手列的是 **Max**, 说明评测时各家开了不同的推理强度档, 而「最高档」的实现和花费在各家并不等价. 跑分的是 High 档, 产品里默认给用户的是哪档, fast 变体对应哪档, 页面没写, 评测口径的一般问题可以对照 [Benchmark 与 Eval](../../../../LargeLanguageModelGuide/13-Agent/13.5-Agent应用与治理/13.5.2-Benchmark与Eval/13.5.2-Benchmark与Eval.md). 表注承诺的「每行最优加粗」在 md 和 PDF 文字层里都查不到, 按数值重算的结果 (Grok 4.6 赢三行) 只能当作还原, 不能当作原文.

## 5. 价格与渠道: 原地不动, 加了一个 fast 变体

定价和 4.5 完全一致: 每百万输入 token 2 美元, 输出 6 美元, 连「starts at」的措辞都一样. 新增的是一个 **fast 变体, 价格翻倍**——按字面就是输入 4 美元, 输出 12 美元, 具体数字报告里没列. 更值得注意的是没说出口的部分: 4.5 公告里有 80 TPS 和「两倍 token 效率」这种硬指标, 4.6 对 fast 只给了价格没给速度, fast 到底快多少, 和 4.5 的 80 TPS 什么关系, 全部空白; 「starts at」也可能意味着高强度档或长上下文另计价, 没写.

渠道面是对 4.5 的直接延续: Grok Build, Cursor 首发, API 加 OpenRouter, Vercel, Cloudflare 分销, 第一周 Grok Build 和 Cursor 的随附用量翻倍. 2x 指的是订阅产品里打包的额度, 不是 API 降价, 额度基线没公布. 安全一节同样是定性的: 三层测试结构 (部署前, 部署后, 第三方) 可指认, 「历来最宽的测试套件」没有任何数字, 拒答率, 越狱指标一个没给; 整篇公告里唯一像安全外显数据的, 是评测表里 Harvey LAB 那一行 15.8% 对 2.5%——法律这个高风险领域的巨大领先, 但页面没把这行和安全评估挂上钩.

## 6. 没说的事与对不上的地方

模型本身的全部参数——参数量, 结构, 词表, 上下文窗口, 训练卡数——这篇一个字没有, 连 4.5 还有的「数万张 GB300」这次都没提. 训练三段只给了名字没给剂量: 补充 run 的数据量, 重生成轨迹的规模, RL 的环境数量和奖励构成, 全部空白. 评测不给采样次数和方差, 定性能力描述不给成功率, 安全一节不给指标, 这些信息缺口本身构成这篇公告的轮廓: 它想让你记住的是「4.5 的底座上, 用自蒸馏 SFT 加多环境 agentic RL, 一个月后全行上涨」, 而不是任何可复现的细节.

对不上的地方多是抽取和措辞层面的, 数字本身没有发现互相矛盾. 图和表对同一个模型用了两套名字 (图里「Grok 4.6」, 表里「Grok 4.6 High」); 「matches GPT-5.6 Sol」与 Fable 5 Max 的 62 并不冲突, 原文只承诺打平不承诺第一, 但「frontier intelligence」的横幅和十行里只赢三行的事实之间, 需要读者自己消化. md 层的损伤照例有几处: 标题「Grok4.6l」是 OCR 残字, 开头的「A」和第 5 页的「B」是字标和图标残字, 「modelgenerated」「longrunning」丢了连字符, 「Com[p]etitor fi[g]ures」里塞的链接是站标叠字, 0:01 / 0:46 的演示视频没被抓下来. 这些只影响阅读, 不影响数字.
