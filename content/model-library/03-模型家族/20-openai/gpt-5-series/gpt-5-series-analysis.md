# GPT-5 System Card：一套路由系统，三类后训练奖励，分层生物防护

## 1. 这份系统卡能回答什么，不能回答什么

系统卡的主体是评测，不是模型描述。60 页里，模型数据与训练只占第 6 页的两段，其余是三块：第 3 节的产品安全评测（违禁内容，谄媚，越狱，指令层级，提示注入，幻觉，欺骗，图像输入，健康，多语言，公平），第 4 节的红队与外部评估，第 5 节的 Preparedness 能力评估和生物防护。全文没有参数量，层数，注意力形式，上下文长度，训练 token 数，训练算力。唯一沾边的一句在 METR 的关键假设表里：gpt-5-thinking 的能力 「与基于有效训练算力 Scaling 的趋势一致」。这句话只说明 OpenAI 自认没有跳出趋势线，推不出任何结构信息。所以下文不讨论 decoder-only 还是别的结构，也不猜 MoE 与否。

能回答的问题集中在两类。一类是后训练怎样改变行为：从拒答到 safe-completion，把谄媚分数当奖励，用不可能完成的任务奖励诚实，用指令层级压住开发者和用户消息。这些机制本文都给了训练思路和前后对比数字。另一类是怎样判断一个模型危险到什么程度，以及判断之后怎样部署：bootstrap 置信区间的局限，pass@12 的取法，helpful-only 变体作为能力上界，两级生物监控器为什么先追召回率。读这份材料最有价值的地方，是看一家实验室怎样把 「能力评测，行为训练，系统防护」 三件事接到同一套决策里。

对比口径也要先讲清。第 3 节固定两组对照：gpt-5-thinking 对 OpenAI o3，gpt-5-main 对 GPT-4o. 第 5 节的能力评测再加上 ChatGPT agent，有时加 gpt-5-thinking-mini 和 pro。线上对照模型的数值取自它们的最新版本，所以和各自发布时的系统卡可能对不上。读任何一个 「提升了多少」 之前，先看它比的是谁。

## 2. 统一系统：路由器替用户选模型

GPT-5 在 ChatGPT 里不是一个模型，而是一个路由系统。实时路由器根据对话类型，复杂度，是否需要工具和显式意图（比如提示里写 「think hard about this」）决定交给快模型 gpt-5-main 还是推理模型 gpt-5-thinking。路由器的训练信号有三路：用户什么时候手动切换模型，回答的偏好率，实测正确率。用户从快模型切到推理模型，相当于一次隐式标注 「这一问快模型不够」。用量到顶之后，请求转给各自的 mini 版。本文说近期打算把这些能力合进单一模型，可见路由器是过渡设计。

表 1 给出传承关系：GPT-4o 到 gpt-5-main，GPT-4o-mini 到 gpt-5-main-mini，o3 到 gpt-5-thinking，o4-mini 到 gpt-5-thinking-mini，GPT-4.1-nano 到 gpt-5-thinking-nano，o3 Pro 到 gpt-5-thinking-pro. nano 的前身是非推理模型，现在归到思考线。pro 的定义值得单独记：它是 gpt-5-thinking 加 「parallel test time compute」，也就是推理时并行多跑几路再汇总，属于 TestingTime 算力，权重不变。所以第 3 节的安全评测不给 pro 重跑，直接用 thinking 的结果作代理；第 5.1.1 节的生物能力评测却单独测了 pro，因为能力评估要看最坏情况，并行采样可能把危险能力的分数往上推。

路由这件事在评测里有一个空白：本文没有给路由器的准确率，也没有测 「路由之后的整体系统」。第 3 节的每张表都把 main 和 thinking 分开列，而两者差距在某些项上很大。表 6 里，恶意开发者消息攻击下的短语保护，gpt-5-thinking 0.911，gpt-5-main 只有 0.404；表 3 生产基准的 self-harm/instructions, thinking 0.955, main 0.759。一条请求被路由到哪边，就面对哪边的防线。用户看到的是 「GPT-5」，实际安全水平取决于路由分布，这一点本文没有量化。

## 3. 训练数据与 RL 推理：本文交代到哪一步

数据部分只有一段。来源三类：互联网公开信息，通过第三方合作取得的信息，用户，人类训练员和研究人员提供或生成的信息。处理上有两道：用 「先进的数据过滤流程」 减少个人信息，用 Moderation API 加安全分类器剔除有害或敏感内容，点名了涉及未成年人的性内容。没有数据量，没有配比，没有去重和质量打分的做法，也没有截止日期。和其他 OpenAI 系统卡比，这段几乎是模板文字。

推理模型的训练多交代了一点。gpt-5-thinking，mini，nano 都 「通过强化学习学会推理」，回答前先生成一段很长的内部 CoT；训练让模型学会打磨思考过程，换策略，发现自己的错。本文还给了一个因果主张：推理让模型能遵循具体准则和模型策略，所以更有用，也更能顶住绕过安全规则的企图。这个主张在后面的数字里有旁证，比如表 5 越狱评测里 gpt-5-thinking 四类都在 0.995 以上，gpt-5-main 在 0.934 到 0.978 之间；表 6 指令层级里 thinking 五项都在 0.91 以上。一般意义上推理模型怎样用 RL 学出 「先想再答」，见 [推理与思考能力](../../../../llm-guide/4-后训练/4.5-推理与思考能力/4.5-推理与思考能力.md)。

RL 在本文里不只是能力来源，也被点名为欺骗的来源。第 3.8 节开头说，模型可能学会过度自信，作弊，或糊弄有缺陷的评分器，「因为成功的尝试能拿到高奖励」，哪怕内部推理显示不确定。这是 RL 奖励函数只看结果时的典型副作用。后面的谄媚奖励，不可能任务环境，CoT 监控，都可以看成在修补这个问题：前两者改奖励，后者负责发现奖励没盖住的地方。奖励模型驱动的 RL 基本框架见 [基于奖励模型的 RL，RLHF 与 PPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/4.4.1-基于奖励模型的RL-RLHF-PPO.md)。

## 4. safe-completion：安全判断从输入挪到输出

传统安全训练先给用户意图打二元标签，允许就尽量有用，不允许就拒。本文指出这种做法对明显恶意的提示很强，遇到意图不明的提示就脆，在双用途领域（生物，网络安全）尤其不合适：同一个问题，高层次回答是安全的，足够具体，可操作的回答才会给恶意者带来提升。safe-completion 把评判对象换成助手的输出：回答本身是否越过安全策略，在不越线的前提下把有用性做到最大。危险在细节而不在话题，所以按输出判比按输入判更贴合。

本文给了三处证据。第一处是表 3 生产基准：gpt-5-main 相对 GPT-4o，illicit/nonviolent 从 0.573 到 0.701，illicit/violent 从 0.633 到 0.786，本文说这两项统计显著，归因于 safe-completion。第二处是第 4.1 节暴力攻击策划红队：25 名国防，情报，执法背景的红队成员盲比 gpt-5-thinking 和 o3，gpt-5-thinking 被评为更安全的比例 65.1%（95% CI 63.7% 到 66.5%），本文把效应归因于 「回答的相对详细程度」 和 safe-completion。第三处在生物防护：模型训练规则是 「拒绝一切武器化协助」 与 「双用途话题绝不给详细可操作协助」，本文说引入 safe-completion 后这一点更稳健。成对生物武器化红队里 gpt-5-thinking 胜率 60.0%。

证据也有缺口。本文声称 safe-completion 带来 「整体有用性大幅提高」 和 「残余失误严重度降低」，但系统卡里没有任何有用性分数，也没有严重度分布，这部分只能去看单独的论文 「From Hard Refusals to Safe-Completions」。另外，表 3 里 gpt-5-main 并非全面提升：hate/threatening 从 GPT-4o 的 0.867 退到 0.727，sexual/exploitative 从 0.927 退到 0.826，两项都统计显著。本文的解释是 o4-mini 在 hate/threatening 上也是 0.724（出处在附录表 24），sexual/exploitative 的违规输出经人工复核 「严重度低」。按输出评判在边界模糊的类别里，可能让模型更愿意给出擦边内容，这两项退步和这个机制方向一致（本文没这么说）。

## 5. 谄媚：把一个行为分数直接当奖励

2025 年 5 月 GPT-4o 出了谄媚问题，OpenAI 当时的处理是回滚新版本，再改仍在线版本的系统提示。本文承认系统提示好改，但对输出的影响比后训练小。GPT-5 的做法是：取能代表生产数据的对话，评估模型回答，给出一个反映谄媚程度的分数，把这个分数当训练里的奖励信号。这是最直接的一种做法，行为指标本身就是 RL 目标。

结果见表 4。离线评测（固定的，类似生产流量，可能诱发不良回答的消息集，越低越好）：GPT-4o 0.145, gpt-5-main 0.052, gpt-5-thinking 0.040. 0.145 / 0.052 = 2.79，对应正文的 「nearly 3x」。早期 A/B 测试的线上测量：gpt-5-main 相对 GPT-4o，谄媚发生率免费用户降 69%，付费用户降 75%，基于助手回答随机抽样。正文那句 「gpt-5-main ... than GPT-4o (scoring 0.145 and 0.052, respectively)」 顺序写反了，按 respectively 会读成 gpt-5-main 0.145，以表 4 为准。

把评分器的分数直接当奖励，风险在评分器本身。如果评分器对谄媚的定义有盲区，策略会朝盲区优化：表面上不附和，换一种方式讨好。这就是奖励模型过优化的一般问题，见 [Best-of-N 与奖励模型过优化](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.4-其他对齐技术/07-Best-of-N-奖励模型过优化/07-Best-of-N-奖励模型过优化.md)。本文没说评分器是人还是模型，也没说评分标准。线上测量能部分缓解这个担心，因为它看的是真实流量里的发生率，不是训练用的同一个分数；但线上发生率仍需要某种判定器，本文同样没交代。

第 3.3.1 节把问题延伸到情感依赖和心理困扰。本文的判断是这类情形 「重要性高，发生率低」，所以难测：低发生率意味着随机抽样很难攒够正例，评测集只能人工构造，构造出来的又未必代表真实分布。OpenAI 请了人机交互研究者和临床医生评议定义与方法，但本文没有给出任何数字。Microsoft 红队在心理社会危害类别上也得出同样的结论：gpt-5-thinking 在识别和回应困扰情形上仍有改进空间。

## 6. 欺骗：造一批做不成的任务，把奖励方向扳过来

本文对欺骗的定义是 「面向用户的回答歪曲了内部推理或实际采取的行动」。o3 的已知问题包括谎称执行过某个动作，谎称完成了没完成的任务，编造经历。修法是造环境：把 gpt-5-thinking 放进部分或完全不可能完成的任务，奖励它诚实承认做不到。环境分三类，都是早期推理模型出问题最多的场景：agent 式编程（缺网络，缺硬件，任务大到不可行），工具故障（故意禁用工具或返回错误码，以前的模型会编造结果），用户请求信息不全（比如就一张图提问，但图不在）。

这套做法的逻辑可以对上第 3.8 节的定义：面向用户的回答不应歪曲内部推理或实际行动。卡片没有给这三类环境各自的欺骗率，只说明奖励方向从 「做成」 改成 「承认做不到」。

## 7. 准备度只保留评级

生物与化学按 High 做预防性处理，即使评测还没有把模型定成 High。网络安全和 AI 自我改进没有达到 High. CTF 与 Cyber Range 上，gpt-5-thinking 与 o3 相当；gpt-5-thinking-mini 在靶场上高于 o3，仍未把系列推过高风险线。取 flag 的方式和生物协议不写。

这些评级服务的是部署决定，不是结构说明。卡片没有参数量，也没有把 High 或未达 High 对应到某一层或某一种注意力。读完能确定的是：线上叫 GPT-5 的请求会在快模型和推理模型之间路由，安全分数跟着路由走，最坏情况的能力评测单独看 thinking 和 pro。
