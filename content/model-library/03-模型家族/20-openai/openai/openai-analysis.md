# OpenAI Models 页分析: 三档 GPT-6 和一张没印完的卡片

- 源文: OpenAI 开发者站 Models 页的浏览器打印件, 1 页, 1 张图, 由 MinerU 转成 Markdown. 图是 GPT-6 Astra 卡片的头图.
- 性质: 选型入口页, 不是论文, 也不是模型卡. 页面只告诉读者先选哪一档, 不给任何规格.
- 出现的模型: GPT-6 Astra, GPT-6 Sol, GPT-6 Luna 三档. 型号名在可见正文里共出现 7 次 (两段定位句各 3 次, 卡片标题 1 次).
- 页面上的数字: 只有型号里的 「6」. 没有价格, 上下文长度, 输出上限, 发布日期, 也没有模型 ID 的取值.
- 能力声明: 最新一代模型支持文本和图像输入, 文本输出, 多语言, 视觉.
- 接入方式: Responses API 和 Client SDKs.
- 快照日期: 页面没印日期, 查不到.

逐条疑问写在同目录的 openai-bi.md 里, 这里不重复翻译正文.

## 1 这一页是什么, 能回答什么

这一页是 OpenAI 开发者文档里 Models 栏目的首屏. 从上到下依次是站点名, 大标题 「Models」, 一节 「Choosing a model」 (两段话), 一节 「Flagship models」 (一段话加两个按钮), 然后是 GPT-6 Astra 的卡片头图, 卡片标题和一句简介, 最后是一个 「Ask AI」 按钮. 打印件到这里就结束了, 按页面结构推断, 下面应该还有 Sol 和 Luna 的卡片, 但都没印进来.

所以它能回答的问题很窄: OpenAI 当前把哪几个模型摆在门口, 怎么给这几个模型分工, 以及这一代模型统一支持哪些输入输出. 它回答不了任何 「有多大, 多贵, 多快, 多强」 的问题. 页面上唯一的数字是型号里的 6, 本稿不从同家族其他条目补任何参数, 也不猜 GPT-6 的规模.

## 2 三档命名和分工

三档的名字是 Astra, Sol, Luna. 拉丁语里它们分别是星辰, 太阳, 月亮. 页面没有解释命名, 这层联想只是推断. 唯一和名字呼应的是 Astra 卡片的头图: 深色星空旋涡上写着白色的 「Astra」, 视觉上把 「星辰」 这层意思落到了图上.

分工只靠三句定性描述. Astra 是 「complex reasoning and coding」 的旗舰, 卡片简介再加一句 「most capable」 和 「hardest end-to-end work」. Sol 用来 「balance intelligence and cost」. Luna 面向 「cost-sensitive, high-volume workloads」. 三句话构成一条从能力优先到成本优先的梯子, Sol 在中间. 页面上梯子的每一级都没有刻度, 读者只知道顺序, 不知道级差.

这套描述在一页里出现了两遍. 「Choosing a model」 第一段和 「Flagship models」 那段的三档措辞几乎逐字相同, 差别只在开头从 「If you're not sure where to start, use」 换成 「Start with」, 并去掉了 「our flagship model」 这个称呼. 同一信息重复两次, 说明这一页的作用是引导, 不是说明.

## 3 能力与接入声明

「All latest OpenAI models」 那一句是页面上唯一一条覆盖全体模型的能力声明: 文本和图像输入, 文本输出, 多语言能力, 视觉. 按项数算是 4 项 (输入算 1 项), 如果把输入拆成文本和图像两种模态, 就是 5 项. 其中 「image input」 和 「vision」 分开列, 页面没解释二者差别. 声明里只写了文本输出, 没提图像或音频输出, 也没提音频输入. 这是页面没写, 不等于模型不支持, 本稿不作推断.

这句话的主语是 「latest」 模型, 范围没有界定. 三档 GPT-6 显然在内, 但 「latest」 还包括哪些型号, 页面没说. 接入方式点了两个名字: Responses API 和 Client SDKs, 都带链接. 页面没有提其他接口, 也没说旧接口是否可用.

## 4 页面缺了什么

对一张选型页来说, 缺的东西比有的多. 价格, 上下文窗口, 最大输出长度, 速率限制, 知识截止日期, 发布日期, 评测分数, 全部没有. 连 「Compare models」 按钮指向的对比表也不在打印件里, 只印了按钮本身. 读者拿这一页没法做量化比较, 只能按三句定性描述排序.

最可惜的是模型 ID. PDF 文字层在 Astra 简介后面有一行 「M d l ID」, 看字形是 「Model ID」 被截断, 按页面结构推断, 后面本该跟着调用时要填的 ID 字符串. 这个值没有印出来, md 里连这一行标签都丢了. 因此本页也无法确认 API 调用时三档的实际 ID 写法.

## 5 转写与快照问题

MinerU 转写和 PDF 文字层之间有三处差异, 都不涉及数字. 第一, md 开头多出 「OpenAI Developers」, PDF 文字层没有, 应该是页首 logo 被识别成了文字. 第二, 「View all」 和 「Compare models」 在 md 里排在头图之前, PDF 里排在卡片之后. 第三, md 丢了 「M d l ID」 这一行. 另外, PDF 里 「Astra」 出现两次, 对应头图上的文字, md 只保留成一张图.

页面没有印日期, 也没有版本号, 无法判断快照拍于何时. 这类选型页会随新模型上线而改版, 三档阵容和措辞都可能变化. 读这份材料时应把它当作某个时点的门面, 页面上的 「latest」 和 「most capable」 只在那个时点成立.

## 6 怎么用这份材料

这份材料适合当 20-openai 目录的门牌: 告诉读者 OpenAI 当时的主推阵容是 GPT-6 的三档, 以及它们的定位顺序. 需要具体规格时, 要去同目录里对应型号的条目或官方模型详情页, 那些内容不属于本页, 本稿不转述.

如果要从这页引用什么, 能放心引用的只有三件事: 三档的名字和定位顺序, 一句全体模型的能力声明, 两个接入入口. 其余任何数字都不能说 「出自这一页」, 因为这一页除了型号里的 6 以外没有数字.
