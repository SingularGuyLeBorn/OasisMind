# Qwen2: GQA, 32K 预训练加 DCA, 一档 upcycle 的 MoE, 和 7T 高质量课表

来源: [Qwen2 Technical Report](https://arxiv.org/abs/2407.10671) (arXiv:2407.10671v4, 2024-09-10). 对照译稿见同目录 `qwen2-bi.md` (`page 1 of 26` 至 `page 26 of 26`), 表内数字, 公式与图号以源文 `qwen2.md` 为准. Hugging Face, ModelScope, GitHub 入口在摘要脚注.

Qwen2 是 Qwen 与 Qwen1.5 之后的一次底座换代, 交出四档 Dense (0.5B, 1.5B, 7B, 72B) 和一档 MoE (57B-A14B, 每 token 激活 14B). 旗舰 Base 的 MMLU 84.2, GSM8K 89.5, HumanEval 64.6; 旗舰 Instruct 的 MT-Bench 9.12, Arena-Hard 48.1, LiveCodeBench v1 35.7. 这些分数背后是几件同时发生的事: 数据从约 3T 扩到 7T, 而且守住质量阈值; 注意力全面换成 GQA, 把每 token 的 KV 压薄; 预训练末段把窗口从 4096 拉到 32768, 推理期再叠 YaRN 与 Dual Chunk Attention 推到 131072; MoE 档从 7B Dense 切出细粒度专家; 后训练用协作标注和自动合成减少人工, 偏好优化走离线 DPO 加在线 DPO. 下面把这些面放在一起讲, 看它们怎样互相牵制.

## 1. 架构: 档位, 长上下文与 MoE

### 1.1. 从 Qwen1.5 到 Qwen2: 这一代换了哪几样

Qwen 初代的底座训练窗口只有 2048, 长文本靠推理期 NTK, LogN 和窗口注意力补; 注意力是满头 MHA; 规模停在 14B (Qwen1.5 扩到 72B, 110B, 但没有单独的技术报告). Qwen2 要面对的是 Llama-3 发布后的开源格局: 70B 档英文能力大幅抬高, 长上下文从 「能不能」 变成 「128K 是否稳定」. 报告的回答不是换骨架, 而是把几处推理期会心疼的零件换掉, 同时把数据做厚.

换掉的部件可以列得很具体. 注意力从 MHA 换成 **GQA**; 长上下文从 「训练 2048 + 推理期补丁」 换成 「预训练末段训 32K + 推理期 YaRN 与 DCA」; 规模从 14B 为止扩到 0.5B 到 72B, 并开出 MoE 线; 数据从约 3T 到 7T, 代码, 数学, 多语显著加量; 偏好优化从 PPO 换成 DPO. 没换的部分也要记住: byte-level BPE 词表 (常规 token 151643 加控制 token 3), QKV bias, SwiGLU, RMSNorm, Pre-Norm, RoPE, 以及 ChatML 格式. 这些延续让 Qwen2 能直接复用 Qwen 系列已有的工具链.

词表不动还有一个容易忽视的理由. 这一代把多语覆盖扩到约 30 种语言, 如果同时换分词器, 多语数据的压缩率, 下游微调生态, 推理框架的 tokenizer 适配都要重来一遍. 报告只写了一句 「压缩率相对竞品更好, 用来支撑多语」, 没有像初代那样给出分语种的压缩率图, 这一面本页没有. 分布式训练需要对齐张量切分, embedding 的实际尺寸会比可见词表略大, 读 Table 1 时看到的 151646 就是这个原因.

### 1.2. 端侧到多卡: 档位和 KV 头一起设计

Table 1 给出五档骨架. 0.5B: hidden 896, 24 层, Query 头 14, KV 头 2. 1.5B: hidden 1536, 28 层, 头 12/2. 7B: hidden 3584, 28 层, 头 28/4. 72B: hidden 8192, 80 层, 头 64/8. MoE 与 7B 同宽同层. Embedding tying 只在 0.5B 和 1.5B 打开. 训练 token 一栏: 0.5B 吃 12T, 1.5B, 7B, 72B 吃 7T, MoE 在 upcycle 之后再吃 4.5T.

报告把小模型的部署面写成手机, 耳机, 智能眼镜, 大模型留给不同规模的 GPU. 这条光谱决定了每档的配置. 小档打开 tying 省下一份 151646 维的词表矩阵, 对 0.5B 来说这部分占比很高; KV 头收到 2, 让端侧内存装得下更长的上下文. 7B 对齐 「单卡 16GB 跑 16-bit」 的常见约束. 72B 的 64 个 Query 头只配 8 个 KV 头, 相对满头 MHA, 每 token 要缓存的 K/V 组数降到八分之一 (按头数比估算), 报告的说法是相对 Qwen1.5 「substantially lower KV size per token」.

FFN 中间宽度依次是 4864, 8960, 18944, 29568, 分别约为 hidden 的 5.4, 5.8, 5.3, 3.6 倍 (按表计算). 72B 的比例明显更低, 容量更多放在层数上 (80 层). Head size 除 0.5B 是 64 外都是 128. Table 5 还给了非 embedding 参数: 0.5B 只有 0.3B, 1.5B 是 1.2B. 换句话说 0.5B 里约四成参数是词表矩阵 (按 0.5B 与 0.3B 之差估算), 这就是小档必须打开 tying 的原因; 不共享的话, 输出投影还要再占一份同样大小.

GQA 的收益主要在推理期, 尤其是长上下文. 训练窗口一旦拉到 32K, 推理期再推到 128K, KV cache 会随长度线性增长; 如果还是满头注意力, 72B 在 128K 下的 KV 显存会变得很难服务. 所以 GQA 和第 1.3 节的长上下文课表是同一次决策的两面: 先把每 token 的缓存压薄, 才谈得上把窗口做长. 报告没有给出具体的 KV 显存或吞吐数字, 这一面本页没有.

### 1.3. 32K 训练, 128K 可用: RoPE base, 长文数据, YaRN 与 DCA 分工

长上下文在预训练末段完成. 窗口从 4096 拉到 32768, 同时加大高质量长文档比例, RoPE base 从 10000 提到 1000000, 做法与 Xiong et al. (2023) 一脉. 提高 base 等于降低每一维的旋转频率, 让 32K 范围内的相位不至于转得太快. 落到最慢的一对维度上算 (head size 128, 按 $\theta_i=b^{-2i/d}$ 计算, 报告没有给这组数): 最低频维的周期是 $2\pi b^{(d-2)/d}$, $b=10^4$ 时约 5.4 万 token, 32768 的窗口要转掉约 0.6 圈, 这一维在训练窗口里已经出现相位接近重复的远近 token; $b=10^6$ 时周期约 507 万 token, 32K 只转掉不到 1% 圈, 远处 token 的相位仍落在单调区间里. 配合长文档, 模型在权重里真正见过这个长度的分布. 这和初代完全靠推理期补丁不同, 长度能力第一次写进了权重.

32K 之外靠两件推理期工具. **YaRN** 按频率分段插值, 并对注意力 logits 乘一个随扩展倍数变化的温度 (mscale); 报告只说它用来 「rescale the attention weights」, 下面的式子取自 YaRN 原论文. 设扩展倍数 $s=L/L_{train}$, 第 $i$ 维在训练窗口内转过的圈数为 $r_i=L_{train}\,\theta_i/2\pi$, 新频率取
$$\theta_i'=\big(1-\gamma(r_i)\big)\frac{\theta_i}{s}+\gamma(r_i)\,\theta_i,$$
$\gamma$ 是在 $r_i\le\alpha$ 时为 0, $r_i\ge\beta$ 时为 1, 中间线性过渡的斜坡. 转圈多的高频维 ($\gamma=1$) 原样保留, 转不满一圈的低频维 ($\gamma=0$) 按 PI 除以 $s$, 只有中间段混合. 温度一项是 $\mathrm{softmax}\big(q^\top k/(t\sqrt d)\big)$, $\sqrt{1/t}=0.1\ln s+1$; 从 32K 推到 128K 时 $s=4$, logits 整体放大约 $(0.1\ln4+1)^2\approx1.30$ 倍, 用来抵消插值后注意力分布变平. Dual Chunk Attention (**DCA**, An et al., 2024) 把长序列切成若干 chunk, 注意力拆成三类: chunk 内部照常计算; 相邻 chunk 之间保留局部连续性; 跨较远 chunk 时把相对位置映射回训练见过的范围. 报告的表述是: 输入能装进一个 chunk 时, DCA 与原注意力结果完全相同; 否则它负责在 chunk 内外都捕捉相对位置. 按 DCA 原论文, 设 chunk 大小为 $c$, 局部窗口为 $w$, key 的位置一律取 $j \bmod c$; query 的位置按三种情形改写: 同 chunk 内取 $i \bmod c$, 相对距离与原注意力相同; 看相邻的上一个 chunk 时, query 在本 chunk 前 $w$ 个位置取 $c+(i \bmod c)$, 与上一 chunk 末尾的 key 保持真实的近距离, 其余位置取下面的常数; 看更远的 chunk 时 query 一律取常数 $c'-1$ ($c'$ 是预训练长度), 相对距离被压在 $[c'-c, c'-1]$ 内. 三种情形算出的 logits 拼回同一个 softmax, 所以任何一对 token 的相对位置都不会超过训练见过的最大值. DCA 原论文的标题就强调 training-free, 预训练不需要它.

社区实现可以帮助理解两者怎样拼在一起. Qwen 维护者在 GitHub issue 里解释, YaRN 与 DCA 结合时, 只是把 $q\cdot k$ 乘上 YaRN 的 mscale 标量; vLLM 为 Qwen2 实现 DCA 时暴露的配置是 `chunk_size` (如 32768), `local_size` (如 2048) 和 `original_max_position_embeddings` (32768). 维护者还建议 chunk 大小不超过预训练长度, 让位置 id 始终落在见过的范围内. 这些细节来自开源实现讨论, 不在报告正文, 但和报告 「32K 以内行为不变」 的说法一致.

评测侧, Figure 1 的 NIAH 热力图显示 72B-Instruct 在 128K 全深度检索稳定, 7B-Instruct 也能到 128K, MoE 约到 64K, 两个小模型约 32K (读图). Table 12 在 NeedleBench 和 LV-Eval 上对比: 加 YaRN+DCA 后, 7B 可以和宣称 1M 窗口的 ChatGLM4-9B-1M 打平, 72B 随长度衰减更缓; 在 32K 以内, 加不加这两件工具分数不变. NIAH 测的是 「找得到」, NeedleBench 多针与 LV-Eval 多证据测的是 「拼得齐」, 后者更接近真实长文任务.

三项长文评测的协议各不相同. NIAH 构造 8K, 16K 直到 128K 的文本, 把事实放在不同深度, 每 10% 深度区间放两个样本, 超过 32K 的长度统一打开 YaRN. NeedleBench 在一段文本里放 2 到 5 个事实, 要求同时找到并做多跳推理. LV-Eval 包含 11 个问答数据集, 每题需要同时理解多条证据; 报告认为它原来的指标过严, 假阴性太多, 改用关键词召回率作为分数. 正文给出的对比是: 72B-Instruct 随长度增加只掉约 6 分, ChatGLM4-9B-1M 掉约 11 分, 而且后者起点更低. 指标改过, 和 LV-Eval 原论文的分数不能直接比.

同一个 GitHub 讨论里, 维护者还说明了 Base 与 Instruct 的差别: 两者都在 32K 上训练, Base 模型从 32K 直接外推到 128K 时 PPL 退化不明显, 所以配置里的最大位置写成 128K; Instruct 模型则建议打开 YaRN 或 DCA 才能获得更好的长文表现. 这说明 「PPL 不崩」 和 「长文任务做得好」 仍是两回事, 和初代 Table 3 只报 PPL 的局限一脉相承. Qwen2 用 NeedleBench 和 LV-Eval 补上了任务级证据, 这是相对初代的实质进步.

### 1.4. 57B-A14B: 细粒度专家, 共享专家, 从 7B upcycle

MoE 层用一组专家 FFN 替换原 FFN, 门控为

$$\mathbf{p}=\operatorname{softmax}(G(\mathbf{x})),\qquad \mathbf{y}=\sum_{i\in\operatorname{top}_k(\mathbf{p})}\mathbf{p}_i E_i(\mathbf{x}).$$

报告强调三点. 专家粒度: 不走 Mixtral 8x7B 那种 「每个专家等于一个原 FFN, 八选二」 的粗切, 而用更小的专家, 同时激活更多个, 在总参和激活参相同的预算下获得更多组合. 路由: **共享专家**常开, 路由专家按门控挑选. Table 1 写路由专家 64, 每 token 激活路由专家 8, 共享专家 8, 每个专家的中间宽 2560; 表注说明 「激活专家」 一列不含共享专家.

初始化是这一档最有特色的地方. 做法类似 upcycling (Komatsuzaki et al., 2023): 给定目标专家中间宽 $h_E$, 专家数 $n$, 原 FFN 中间宽 $h_{\mathrm{FFN}}$, 把 7B 的 FFN 复制 $\lceil n\cdot h_E/h_{\mathrm{FFN}}\rceil$ 份, 沿中间维打乱, 再切出细粒度专家, 多余维度丢弃, 每个细专家另有 50% 参数随机重初始化. 打乱保证从不同副本切出的专家不完全相同, 重初始化进一步加入随机性, 目的是让专家在训练中更快分化. 如果直接复制, 所有专家起点一样, 路由很难学出差异.

代入 Table 1 的数字可以把这个过程算具体 (以下按表计算, 报告没有直接写出). 专家中间宽 $h_E=2560$, 专家数按路由加共享取 $n=64+8=72$ 或只算路由 $n=64$, 7B 的 $h_{\mathrm{FFN}}=18944$. 按 $n=64$ 算, $\lceil 64\times2560/18944\rceil=\lceil 8.65\rceil=9$, 即把 7B 的 FFN 复制 9 份, 切出 64 个宽 2560 的专家, 剩下的维度丢弃. 每个 token 实际经过 8 个路由专家加 8 个共享专家, 合计中间宽 16×2560=40960, 约为 7B 原 FFN 的 2.2 倍. 注意力和 embedding 与 7B 相同, FFN 激活宽度翻倍多, 这就是 「激活 14B」 的来源. 报告说这一档的结构 「紧随 Qwen1.5-MoE-A2.7B」, 细粒度加共享专家的配方在上一代的小 MoE 上已经试过.

细粒度带来的组合空间可以粗算一下 (按组合数估算, 不是报告给出的数字). Mixtral 八选二, 每层可选的专家组合只有 28 种; 64 选 8 则有四十多亿种. 组合越多, 不同 token 就越可能用上不同的专家搭配, 专家之间的分工也可以更细. 代价是路由决策更难学, 每个专家更小, 通信和访存的碎片更多. 共享专家在这里起的作用是兜底: 所有 token 都需要的通用变换交给常开的共享专家, 路由专家只负责差异化的部分, 这样细粒度专家不必每个都重复学一遍语法和常识.

这一档从 7B 起步, 再训 4.5T token. 报告的目标是: 激活 14B 时性能接近同系列约 30B 的 Dense. Table 3 的对照组是 Yi-1.5-34B, Qwen1.5-32B, Mixtral-8x7B, Jamba: 57B-A14B 的 HumanEval 53.0, MBPP 71.9, GSM8K 80.7, MATH 43.0, C-Eval 87.7, CMMLU 88.5, 代码和数学尤其亮. 但 §2.2.2 只给了门控和 Top-K 加权和, 没有写负载均衡损失, token dropping, 设备限路由, 也没有 「关掉打乱」 或 「关掉重初始化」 的消融. 负载均衡怎么做, 这一面本页没有, 不能从 DeepSeek-V2 等别家报告补进来.

Table 3 也有 MoE 不如 Dense 的地方. MMLU 76.5 略低于 Yi-1.5-34B 的 77.1; MMLU-Pro 43.0 低于 Yi 的 48.3; BBH 67.0 远低于 Yi 的 76.4; Winogrande 79.5 是表中最低. 报告的说法是 「自然语言理解与 Yi-1.5-34B 相当」, 从逐项看, 推理类的 BBH 差距不小. 代码和数学上的领先 (HumanEval 53.0 对 46.3, MultiPL-E 49.8 对 39.5) 和 7B 底座本身代码数学强是同一来源: **upcycle** 继承了 7B 的能力分布, 再训 4.5T 也没改变这个形状.

## 2. 预训练课表与后训练

### 2.1. 7T 与 12T: 质量阈值和课表分叉

数据相对前代有三处加码. 过滤加入启发式与模型打分, 并用 Qwen 模型合成高质量预训练样本; 代码, 数学, 多语显著加量, 覆盖约 30 种语言; 用缩小的模型做配比实验, 让混合分布更合理. 总量从约 3T 到 7T. 报告还试过放宽**质量阈值**得到 12T 数据, 在大模型上相对 7T 没有明显增益, 于是大模型守 7T, 只让 0.5B 吃 12T. 和初代一样, 预训练里混入高质量多任务指令数据, 用来抬 in-context learning 和指令跟随.

「12T 没赢 7T」 常被引用成 「数据质量比数量重要」, 但要读准范围. 报告只记录了这一次放宽阈值的尝试, 并说明量增未必总有益, 把更大规模的探索留给后续; 它不是拟合过的 Scaling Laws 曲线. 小模型吃 12T 也符合当时的一个共识: 小模型容量有限, 多看数据的边际收益比大模型更大, 类似 Llama-3-8B 训到 15T 的思路.

配比实验用缩小的模型做, 这是当时常见的省钱办法: 在几亿参数的代理模型上试不同的数据混合, 选出下游表现最好的一组, 再用到大模型上. 报告说目标是让混合分布 「更接近人类学习」, 但没有给出最终的代码, 数学, 多语, 网页比例, 也没有代理模型的规模和实验曲线. 所以代码数学加量能从分数上看出来, 具体加了多少, 读者无从得知.

用 Qwen 自己过滤和合成预训练数据, 等于把模型卷进数据流水. 好处是过滤阈值可以随模型能力一起涨, 坏处是分布可能向模型自己的偏好收窄. 报告没有公开过滤模型版本, 拒稿率和合成数据占比, 这一面本页没有. 读 Table 2 时还要记得预训练见过指令数据, 基座的 few-shot 分数有一部分来自这里, 但不能因此把 Base 榜当成 Instruct 榜.

### 2.2. 后训练数据: 协作标注和自动合成

先说为什么要这样设计. 到 2024 年, 靠人工逐条写高质量回复已经跟不上模型能力: 标注员在数学, 代码, 长文写作上常常不如模型本身, 写出来的答案反而拉低上限. 所以人工的位置被挪到 「定标准」 和 「做排序」 上, 生成交给模型. 这个分工决定了下面每条流水的形状.

对齐目标写成 helpful, honest, harmless, 方法上强调 scalable alignment, 少用人工. 数据分成演示集 $\mathcal{D}=\{(x_i,y_i)\}$ 和偏好集 $\mathcal{P}=\{(x_i,y_i^+,y_i^-)\}$. **协作标注**链路是: 用 InsTag 从大规模指令中抽出本体标签, 人工校对; 按多样性和复杂度筛指令; 用 self-evolution 给指令加约束, 让它变难; 多个规模的模型对同一指令生成多条回复, 人工排序, 排序结果同时产出演示数据和偏好对.

自动合成有四条. 数学这类有确定答案的任务用拒绝采样: 多次生成, 保留答案正确且推理合理的轨迹, 正确与错误轨迹还能配成偏好对. 代码用 execution feedback: 编译运行, 用测试用例判断对错; 带格式约束的指令跟随, 则让模型写 Python 校验函数来检查回复. 文学写作和角色扮演承认非专业标注员写不出高水平回复, 于是反过来, 从公域作品和 Wikipedia 人设出发, 让模型生成对应的指令, 把高质量原文当作回复. 安全用 Constitutional Feedback, 按预设原则生成合规和违规的对照回复.

这套数据构造和后面的训练方法是咬合的. 拒绝采样和执行反馈天然产出 「对与错」 的配对, 正好喂给 DPO; 人工排序产出的多回复排名, 也能拆成偏好对. 所以 Qwen2 选 DPO 不只是因为它比 PPO 省, 还因为数据流水本来就在批量产出偏好对. 报告没有给出各类合成数据的数量, 人工参与比例和拒绝率, 这一面本页没有.

### 2.3. SFT 接 32K, 偏好优化走离线和在线 DPO

SFT 超过 500000 条, 覆盖指令跟随, 代码, 数学, 逻辑, 角色扮演, 多语, 安全. 训练两个 epoch, 序列长 32768, 学习率从 $7\times10^{-6}$ 降到 $7\times10^{-7}$, weight decay 0.1, 梯度裁剪 1.0. 序列长度直接对齐预训练末段的 32K, 避免 「底座见过长文, 对齐又缩回短窗」 的割裂; 这也是 Instruct 版本能在 128K 检索上稳定的前提之一.

偏好优化分两段. 离线阶段在预先构建好的偏好集上做 DPO, 拉大 $y^+$ 与 $y^-$ 的似然差. 报告只写了这句目标, DPO 原论文的损失是
$$\mathcal{L}_{\mathrm{DPO}}=-\mathbb{E}_{(x,y^+,y^-)\sim\mathcal{P}}\Big[\log\sigma\Big(\beta\log\frac{\pi_\theta(y^+\mid x)}{\pi_{ref}(y^+\mid x)}-\beta\log\frac{\pi_\theta(y^-\mid x)}{\pi_{ref}(y^-\mid x)}\Big)\Big].$$
「似然差」 拉大的不是裸概率, 而是两条回复各自相对参考模型 (这里是 SFT 模型) 的对数概率比之差; $\beta$ 同时扮演 PPO 里 KL 系数的角色, 越大越不许 $\pi_\theta$ 离开 $\pi_{ref}$. Qwen2 没有公布 $\beta$. 在线阶段每轮用当前策略对同一问题采样多条回复, 由奖励模型挑出最好和最差的组成新偏好对, 再做 DPO. 在线的好处是偏好对来自当前模型自己的分布, 缓解离线 DPO 数据与策略分布不匹配的问题. 这里没有 PPO 的 critic 和 GAE, 奖励模型只在在线阶段负责打分选对, 奖励模型本身的结构和训练数据也没有公开.

2024 年社区对 DPO 的主要批评是: 离线 DPO 只在固定数据上拟合, 策略一旦偏离数据分布, 偏好信号就变弱, 效果通常不如 PPO. 迭代式或**在线 DPO** 的思路是每轮重新采样, 让偏好对跟着策略走, 在不引入 critic 的前提下缩小与 PPO 的差距. **Qwen2 的两段式正是这个折中**: 离线阶段用高质量人工和合成偏好对打底, 在线阶段用奖励模型持续产出新配对. 省掉的是 critic 的显存和调参, 付出的是每轮采样与打分的推理成本.

对齐税用 Online Merging Optimizer 处理. 这是 Qwen 团队 2024 年的另一篇工作: 在 RLHF 每一步把 SFT 模型与预训练模型之间的参数差并进梯度方向, 让奖励上升的同时不偏离 SFT 学到的能力. 它和初代 PPO 里的 pretrained gradient 是同一个问题的两种解法: 前者在参数空间里合并, 后者在损失里加预训练项. Qwen2 报告只点名使用, 没有给出开关前后的对照分数.

## 3. 评测与可信度

### 3.1. Base 和 Instruct 分层读分

先看评测协议. Base 模型都用 few-shot 或 zero-shot 提示: MMLU, MMLU-Pro, GPQA, Theorem QA 都是 5-shot, BBH 3-shot, HellaSwag 10-shot, Winogrande 5-shot, TruthfulQA 0-shot, ARC-C 25-shot; HumanEval, MBPP, EvalPlus, MultiPL-E 都是 0-shot, MultiPL-E 覆盖 Python, C++, Java, PHP, TypeScript, C#, Bash, JavaScript 八种语言; GSM8K 5-shot, MATH 4-shot, C-Eval 和 CMMLU 5-shot. 多语评测分四类: 考试 (M3Exam 只取不需要图的题, IndoMMLU, ruMMLU, 八种语言的翻译版 MMLU), 理解 (BELEBELE, XCOPA, XWinograd, XStoryCloze, PAWS-X), 数学 (MGSM 8-shot CoT), 翻译 (Flores-101 5-shot). Table 2 到 Table 4 的 「Multilingual」 四行就是这四类的均分.

Table 2 是 Base few-shot 主榜. 72B 对 Mixtral-8x22B, Llama-3-70B, Qwen1.5-72B 和 110B: MMLU 84.2, MMLU-Pro 55.6, GPQA 37.9, Theorem QA 43.1, BBH 82.4, HumanEval 64.6, MBPP 76.9, GSM8K 89.5, MATH 51.1, C-Eval 91.0, CMMLU 90.1. 相对 Llama-3-70B, 知识和科学项拉开, 推理三项大致打平; 相对自家 Qwen1.5-72B, HumanEval 高 18.3 个点, MATH 高 17.0 个点, 这是代码与数学数据加码的主要证据.

### 3.2. 内部评测, 多语与安全

Table 10 和 Table 11 是内部中英自动评测, 补开放榜看不到的维度. 中文均分上 72B-Instruct 69.58, 超过 Qwen1.5-110B-Chat 的 65.86, 参数少了三分之一仍然赢, 说明这一代的提升大头在数据和对齐. MoE 相对 Qwen1.5-32B-Chat 多数域更好, 知识理解例外, 作者归因于预训练 token 不够, 计划继续训. 英文均分上 72B-Instruct 72.94, 略低于 Llama-3-70B-Instruct 的 74.06, 差距被归到英文预训练量和后训练数据多样性.

多语人工评测 Table 13 抽了十种语言, 72B-Instruct 均分 3.93, 高于 GPT-3.5-Turbo 的 3.16, 接近 GPT-4-Turbo 的 3.98, 略低于 Claude-3-Opus 的 4.15. 预训练宣称覆盖约 30 种语言, 人评只抽 10 种, 前者是课表, 后者是人评预算. 安全 Table 14 用有害回复占比 (越低越好): Illegal, Fraud, Privacy 三类 72B-Instruct 优于或持平 GPT-4, 明显好于 Mixtral-8x22B-Instruct; Pornography 仍是最难的一类, 有害比例 22.91%.

两张内部表的分项更有信息. 中文表分知识, 考试, 理解, 代码, 数学, 推理六项: 72B-Instruct 均分 69.58, 略高于 GPT-4o 的 68.87; 知识 76.19 远高于 GPT-4o 的 66.68, 代码 49.53 却明显低于 GPT-4o 的 59.58. MoE 的知识项 64.15, 低于 Qwen1.5-32B-Chat 的 68.63, 这就是报告说的 「知识理解例外」. 英文表分知识, 理解, 代码, 数学四项: 72B-Instruct 数学 82.15 高于 Llama-3-70B-Instruct 的 79.70, 理解 73.58 对 76.31, 代码 53.03 对 57.18, 落后集中在理解和代码.

多语人评的做法是每种语言请一名该语种专业出身的标注员, 对每条回复打 1 到 5 分. 逐语种看, 72B-Instruct 最弱的是印尼语 3.83 (GPT-4o 4.39) 和泰语 3.75 (GPT-4-Turbo 4.11), 韩语 4.14, 俄语 4.15 则接近闭源. GPT-4o 均分 4.09, 72B 与它相差约 0.16 分. 安全评测收集了容易越狱的提示词, 覆盖多种语言, 看模型能否拒答; Illegal 一类 GPT-4 和 72B 都是 0.00, Mixtral-8x22B 是 6.87; Pornography 一类 GPT-4 也有 23.63, 各家都难.

内部评测的意义在于它不受公开榜过拟合影响, 也能覆盖知识理解, 创作, 角色扮演这些公开榜难以量化的维度. 代价是外人无法复现, 只能当作团队自己的诊断信号. 72B 在中文内部评测上赢了 110B, 在英文内部评测上略输 Llama-3-70B, 这种不对称和预训练语料以中文见长的背景一致. 读这两张表时, 可以把它们当作开放榜的补充, 不宜当作跨团队排名.

### 3.3. 去污染协议与分数可信度

训练侧去污染用两道约束: n-gram 重叠, 以及**最长公共子序列** (LCS). 去标点分词后, 如果某条训练样本与测试序列的 $|\mathrm{LCS}|\ge 13$, 且覆盖率 $\ge 0.6\times\min(|s_t|,|s_e|)$, 就剔除该训练样本. 加 LCS 条件是为了减少假阳性: 数学公式和常见代码片段很容易撞上 13-gram, 却不代表真的泄漏了题目.

评测侧反过来用更严的口径检查: 只看 13-gram, 不加 LCS 条件, 切出 「非污染子集」. Table 15 显示 HumanEval, MultiPL-E, MATH 等集合的污染率很高, HumanEval 达到 75.0%, 但原集和非污染子集的分数很接近, 例如 72B-Instruct 的 HumanEval 原集 86.0, 非污染子集 87.0. 作者据此认为高污染率主要来自常见片段造成的假阳性, 分数没有被背题抬高. 读代码和数学分时, 应把 Table 15 的差值一起看, 不必整张代码榜作废, 也不能完全不管.

Table 15 的其他行: MMLU 污染率 11.2%, 72B 原集 82.3, 非污染子集 83.2; MMLU-Pro 11.6%; GSM8K 只有 0.7%; MBPP 29.6%; MultiPL-E 37.7%, 差值为 0. 最大的差值出现在 MATH: 污染率 31.7%, 72B 原集 69.0, 非污染子集 74.6, 高出 5.6 分; 7B 的 HumanEval 非污染子集比原集高 7.9 分. 差值为正说明被判为 「污染」 的样本反而更难, 模型并没有靠背题在这些样本上占便宜, 这和 「常见公式和代码片段造成假阳性」 的解释一致.

两道口径的方向要分清. 训练侧的 n-gram 加 LCS 是 「剔训练数据」, 宁可少剔也不误伤大量常见片段; 评测侧只用 13-gram 是 「切评测子集」, 宁可多切也要看分数会不会塌. 一松一严, 前者保证训练数据不被过度清洗, 后者给分数可信度一个保守下界. 这种写法比单报一个污染率更有信息量, 也比初代只写 「13-gram 剔除」 更进一步. 当然, 字面重合检测抓不到改写过的题目, 这个局限两代报告都有.

## 4. 几块合起来看, 以及谱系位置

把前面串起来, Qwen2 的分数形状可以找到对应的部件. 72B Base 相对 Qwen1.5-72B 在代码和数学上大涨, 对应 7T 课表里代码数学加量和模型过滤. 128K 检索稳定, 对应 GQA 压薄 KV, 32K 预训练加 RoPE base 调整, SFT 也在 32K, 推理期 YaRN 加 DCA 四件事一起到位, 少任何一件都不行. 57B-A14B 用 14B 激活追 30B Dense, 对应细粒度专家和打乱加重初始化的 upcycle. 7B-Instruct 的 IFEval 缺口, 对应后训练数据里指令约束类样本不够, 下一代 Qwen2.5 专门补了这块.

报告没写的东西也要记住: 没有负载均衡的具体设计, 没有 Scaling Laws 拟合, 没有奖励模型细节, 没有合成数据比例, 没有训练集群与吞吐, 没有 Online Merging Optimizer 的开关对照. 谱系上, Qwen2 是对标 Llama-3 时代的一代, 把 Qwen 系列从 「中文强的中档模型」 推到 「多档齐全的开源旗舰」. 下一代 Qwen2.5 继续放大数据到 18T, 把 MoE 转到 API 侧, 后训练加入 GRPO; 那些变化以 Qwen2.5 报告为准. 本文任一数字可按表号回到 `qwen2.md`, 英中对照见 `qwen2-bi.md`.
