# Qwen2-VL：原生分辨率，M-RoPE 和图视频统一入口

来源：[Qwen2-VL Technical Report](https://arxiv.org/abs/2409.12191) (arXiv:2409.12191v2, 2024-10-03)。仓库 https://github.com/QwenLM/Qwen2-VL. 对照译稿见同目录 `qwen2-vl-bi.md`，表内数字以源文 `qwen2-vl.md` 为准。

Qwen2-VL 的能力来自几件事同时改动。视觉编码器去掉绝对位置编码，换成 2D-RoPE，让任意尺寸的图直接进 ViT；语言侧换成 Qwen2，位置编码升级为三分量的 M-RoPE；视频用 2 fps 采样和深度为 2 的 3D 卷积，与图像共用一条通路；预训练累计约 1.4 万亿 token，数据里 OCR，文档和多语文字的比重很高；后训练用 ChatML 格式的指令数据，覆盖 grounding 和 agent；评测上文档与 OCR 最强，大学级多学科推理和三维导航落后。这些改动互相依赖：没有原生分辨率，OCR 数据的收益会被缩放抹掉；没有 M-RoPE，视频的时间顺序就只能靠序列先后表达。报告没有系统的 RL 阶段，后训练只写了 SFT。

## 1. 输入端：原生分辨率

### 1.1. 从 Qwen-VL 出发：固定分辨率卡在哪里

Qwen-VL 已经证明 「视觉编码器 + 连接器 + LLM」 这条路能做通才模型。它的问题在输入端：图像常被压到固定分辨率，例如 224×224，或者先缩放再 padding。高清文档，细长截图和极端宽高比都会丢细节。编码器沿用 CLIP 风格的预训练权重，训练中基本冻结，在细粒度识别和复杂推理上是否够用，也一直有疑问。同期的 LLaVA-NeXT 和 InternVL 1.5 用切块（tiling）处理高分辨率：把大图切成若干固定尺寸的小块，分别编码后拼回去。

Qwen2-VL 走了另一条路：不切块，让 ViT 直接吃原生尺寸。表 1 给出三档：2B 的语言模型 1.5B，7B 的语言模型 7.6B，72B 的语言模型 72B，三档共用约 675M 的 ViT。视觉侧不随语言侧放大，这是算力分配上的选择：旗舰贵在语言模型，视觉配方三档共享，不用每开一档重训一个视觉塔。摘要里出现的 8B 是体量粗说，型号名以 7B 为准。

和 Qwen2 纯文本报告对照，这份报告的增量几乎全在视觉通路和多模态位置编码上。文本侧的 GQA，词表，Scaling Laws 和后训练流程都在 Qwen2 报告里，本页不重复。引言提到 LVLM 的 Scaling Laws 还在早期，报告自己的证据是图 6 对模型规模和第二阶段 token 量的经验曲线，没有给出可复算的拟合公式。

### 1.2. Naive Dynamic Resolution：分辨率直接决定 token 数

做法很短。ViT 去掉原来的绝对位置编码，换成 **2D-RoPE**，于是任意高宽的 patch 网格都能编码。推理时多张图打包进同一条序列，用打包长度控制显存。ViT 之后接一个 MLP，把相邻 2×2 个视觉 token 合成 1 个，前后加 `<|vision_start|>` 和 `<|vision_end|>`。报告的例子：224×224 的图，`patch_size=14`，网格是 16×16 = 256 个 patch，合并后 64 个，加上两个特殊 token，进 LLM 前是 66 个。脚注说这项技术先在内部的 Qwen-VL Plus 和 MAX 上用过。名字里的 「naive」 是作者有意为之：不加自适应模块，不切块，不 padding，分辨率直接换算成 token 数。

2D-RoPE 在实现上也很直接。vLLM 和 Hugging Face 的代码里，ViT 的 rotary 只作用在一半的 head 维度上（`partial_rotary_factor=0.5`），这一半再分给行坐标和列坐标，各自按 RoPE 的频率旋转。所以位置编码不需要查表，任意（h, w）都有定义。这是 「去掉绝对位置编码」 之后能接受任意网格的前提，也是 ViT 要从 DFN 权重出发重新训练的原因：原权重学的是绝对位置，换成 RoPE 后必须重新适应。

2×2 合并的位置也有讲究。它放在 ViT 之后，所以 ViT 内部仍按 14 像素的粒度看图，细节在编码阶段不丢；合并只压缩送进 LLM 的序列长度，相当于每个 LLM token 对应 28×28 像素。这也是配置里 min_pixels 和 max_pixels 都写成 「若干 × 28 × 28」 的原因。

### 1.3. 动态分辨率到底省了什么：表 7 和图 4

表 7 把固定 token 数和动态分辨率放在一起比。固定取 64, 576, 1600, 3136 时没有一档通吃：64 个 token 时 InfoVQA 只有 28.85; 3136 个把 InfoVQA 拉到 77.27，OCRBench 却掉到 786。动态分辨率平均约 1924 个 token，InfoVQA 75.89，RealWorldQA 70.07，OCRBench 866，MMMU 53.44，几项都在顶档，而且用的 token 比 3136 少。固定组按恒定 token 数缩放，保持宽高比；动态组只设 min_pixels = 100×28×28 和 max_pixels = 16384×28×28。

把表 7 的几行逐列看，各任务对分辨率的反应完全不同。InfoVQA 随 token 数单调上升：28.85, 65.72, 74.99, 77.27. RealWorldQA 从 56.47 升到 70.59 后趋平。OCRBench 在 576 个 token 时最高（828），1600 时 824, 3136 时反而降到 786，固定分辨率的任何一档都不如动态的 866. MMMU 四档在 52.78 到 53.44 之间来回，几乎不动。信息图要大分辨率，小图 OCR 怕被过度放大，多学科推理和分辨率无关，这三种反应只有 「按原图大小给 token」 能同时照顾到。

图 4 继续调 min_pixels。小图被放大到阈值以上时，InfoVQA，HallusionBench 和 OCRBench 等感知任务变好，报告归因于给了更多计算。min_pixels 太高，OCRBench 反而大幅掉分：这个评测集里有很多极小的图，过度放大后偏离了训练分布。MMMU 对 min_pixels 几乎不敏感，说明它的瓶颈在知识和推理，不在像素。

这两组结果合起来，给部署的结论是：**min_pixels 和 max_pixels 要按业务分布设**。文档，PDF 截图，密集中文页要给足像素；场景闲聊可以克制。和切块方案相比，整图可变网格不浪费 padding，竖屏长截图能按原比例贡献 token；代价是超大图会一次吃掉大量上下文，所以要有打包长度和 max_pixels 两道上限。报告没有和切块方案做同等条件下的直接对比，两者优劣本页没有定量证据。

## 2. 位置与视频：M-RoPE

### 2.1. M-RoPE：把位置拆成时间，高，宽

文本是一维序列，图像是二维网格，视频再加一维时间。只用 1D-RoPE，空间邻接和时间先后都被压成一条轴。**M-RoPE** 把旋转编码拆成 temporal，height，width 三个分量。文本的三个分量取同一个 position ID，效果等同 1D-RoPE；图像的时间 ID 不变，高和宽按网格位置编号；视频按帧递增时间 ID，高宽同图像。多种模态拼接时，后一段从前一段的最大 ID 加一开始。图 3 是示意图。

实现上，head 维度 128 对应 64 组频率，Hugging Face 配置里的 `mrope_section=[16, 24, 24]` 表示前 16 组给时间，接下来 24 组给高，最后 24 组给宽（代码里乘 2 变成通道数 32, 48, 48）。写成旋转角，位置为 $(t,h,w)$ 的 token 在第 $j$ 组频率上转过的角度是
$$\phi_j=\begin{cases}t\,\theta_j, & 0\le j<16\\ h\,\theta_j, & 16\le j<40\\ w\,\theta_j, & 40\le j<64\end{cases}\qquad \theta_j=b^{-2j/128}.$$
1D-RoPE 在同一步算的是 $\phi_j=n\,\theta_j$，所有组共用一个序号 $n$；M-RoPE 只换了 「每组乘哪个位置标量」，频率表和旋转方式都不变。文本 token 取 $t=h=w=n$，三段拼起来就退回 $n\,\theta_j$，这是 「文本上等同 1D-RoPE」 的全部含义；同一张图里的 token 共享 $t$，所以前 16 组对它们的 q·k 不产生相对旋转，空间关系全由后 48 组的 $h, w$ 差给出。这个切分有个后果：RoPE 的频率随维度下标递减，时间分量拿到的全是高频，宽度分量拿到的全是低频。社区后来对这一点有不少讨论，Qwen3-VL 改成交错分配频率，就是针对这个问题。本报告没有讨论频率分配，也没有给出切分比例的消融。

为什么**频率偏置**会伤长视频？高频维度对小的位置差很敏感，但位置差一大就迅速转圈，相对距离的信息被混叠；低频维度转得慢，适合编码远距离。时间分量只有高频，帧与帧之间隔得一远，模型就难以从位置编码里读出先后。Qwen3-VL 报告明确说原始切分 「导致频谱不平衡，后续研究显示会降低长视频理解表现」，并把 t，h，w 交错排列在各频段上。这个问题在 Qwen2-VL 的评测里没有暴露，因为视频训练上限只有 16384 个 token，时间跨度有限。

M-RoPE 还有一个副作用：一张合并后 64×64 网格的图，用 1D 编号要占 4096 个位置，用 M-RoPE 只让最大 ID 增加 64 左右（按报告的编号规则估算）。报告把这一点当成长度外推的原因之一：图像和视频的位置 ID 数值变小，给推理阶段的更长输入留出空间。

### 2.2. M-RoPE 的证据：表 8 和图 5

表 8 在小骨干上做消融（Qwen2-1.5B + ViT-L），报的是预训练后的下游分数。视频的 PerceptionTest，NextQA，STAR 都涨；多数图像评测持平或小涨，RealWorldQA 从 54.5 降到 53.7。主要收益在视频，不在每张图都涨几分。这张表的骨干远小于 72B，它证明的是换位置编码的方向，不能代替旗舰的总表。

逐项看：PerceptionTest 46.6 到 47.4，NextQA 43.9 到 46.0，STAR 55.5 到 57.9，三个视频评测都涨 1 到 2 分多。图像上最意外的是 MathVista，从 39.2 涨到 43.4，涨了 4.2 分，可能和几何图形的空间关系有关，报告没有解释。MMBench 58.6 到 60.6；MMStar 都是 36.7；DocVQA，ChartQA，TextVQA 各涨零点几；InfoVQA 50.8 降到 50.3。文档类任务对位置编码的形式不敏感，可能因为读字主要靠局部特征，二维位置的作用已经由 ViT 里的 2D-RoPE 承担了。

图 5 直接画在 72B 上：训练时单个视频最多 16384 个 token，推理时在 Video-MME Medium 上把输入拉到约 80K 仍然稳定。训练长度和推理长度差了约 5 倍，能外推的原因报告归于 M-RoPE 压低了位置 ID。报告没有做 「1D-RoPE 下同样外推」 的对照，所以这个解释是作者的判断，不是消融结论。

两组证据来源不同：消融在小模型上，外推在大模型上。放在一起读，才能支持 「换成 M-RoPE 值得做」 这个结论；单看任何一组都不够。

### 2.3. 视频：2 fps，3D 卷积，图像当两帧

视频没有单独做一个编码器。采样率 2 fps；ViT 前端用深度为 2 的 **3D 卷积**，每次吃两帧组成的 tube，在不拉长序列的前提下吞下更多帧。图像被复制成两帧相同的画面，走同一条卷积通路。每个视频的总 token 数通过动态调整分辨率控制，上限 16384。图和视频在编码器入口就对齐，混合训练时不需要两套预处理。代价是图像路径多算一帧，视频要在帧率，分辨率和 token 上限之间权衡。这笔权衡可以按报告的规则算出来（以下是按 patch 14，时间深度 2, 2×2 合并推算，报告没有列）：一个 tube 覆盖 2 帧，进 LLM 的 token 数是 $\frac{H}{14}\cdot\frac{W}{14}\cdot\frac14$；2 fps 下一个 tube 正好是 1 秒。448×448 的帧每秒 256 个 token，16384 的上限只装得下 64 秒；要塞进 20 分钟（1200 秒），每秒只能分到约 13 个 token，相当于每帧压到约 100×100 像素量级。时间深度 2 让同样时长的序列减半，但没有改变 「时长乘分辨率受上限约束」 这件事。

宣传里的 「20 分钟以上长视频理解」 和评测协议要分开。Video-MME 的评测协议给每个视频最多 768 帧，报告承认这可能影响更长视频的分数。按 2 fps 估算，768 帧约对应 6 分 24 秒的稠密采样（按 768/2 秒估算）；更长的视频要么降低帧率，要么降低每帧分辨率。报告的时间 ID 按帧递增，和真实时间没有绑定：采样率变了，同样的 ID 差就对应不同的秒数。这是 Qwen2.5-VL 引入绝对时间对齐要解决的问题。

表 4 是视频成绩。72B 的 MVBench 73.6，PerceptionTest 68.0，EgoSchema 77.9，Video-MME 无字幕 71.2，有字幕 77.8. EgoSchema 高于 GPT-4o 的 72.2；Video-MME 有字幕略高于 GPT-4o 的 77.2，无字幕低于 Gemini 1.5-Pro 的 75.0。有字幕等于多了一条文本通道，对白密集的长视频会明显变容易，两列不要混读。

## 3. 训练：数据，后训练与基础设施

### 3.1. 数据与预训练：三阶段，只监督文本

训练分三阶段，沿用 Qwen-VL。第一阶段只训 ViT，做图文对齐，约 6000 亿 token，LLM 从 Qwen2 初始化，ViT 从 DFN 初始化并把位置编码换成 2D-RoPE，重点是图文关系，OCR 和图像分类。第二阶段全参放开，再加约 8000 亿图像相关 token，提高图文交错，VQA 和多任务数据的比重，同时保留纯文本，防止语言能力退化。第三阶段锁住 ViT，只对 LLM 做指令微调。

数据截止 2023 年 6 月，包括图文对，OCR，交错图文，VQA，视频对话和图像知识，来源是清洗过的网页，开源数据集和合成数据。报告没有给出每类数据的具体配比和清洗规则，这一面本页没有。累计 1.4 万亿 token 里既有文本也有图像 token，但**损失只算在文本 token 上**：视觉部分通过 「让下文预测正确」 间接得到训练，这是 next-token prediction 在多模态上的直接延伸。

图 6 分两张。图 6(a) 按模型规模画五个能力维度：大学级题目用 MMMU；数学用 MathVista 和 MathVision 的平均；文档和表格用 DocVQA，InfoVQA，ChartQA，TextVQA，OCRBench，MTVQA 的平均；通用问答用 RealWorldQA，MMBench-V1.1，MMT-Bench，HallBench，MMVet，MMStar 的平均；视频用 MVBench，PerceptionTest，EgoSchema，Video-MME 的平均。数学能力和参数量的正相关最明显，OCR 类任务小模型已经相对强。表 2 可以印证：MathVista 从 2B 的 43.0 到 7B 的 58.2 再到 72B 的 70.5，每档涨十几分；DocVQA 从 90.1 到 94.5 到 96.5，每档只涨几分。

图 6(b) 是 7B 在第二阶段加数据时的曲线：AI2D 和 InfoVQA 随 token 量较单调地上升，VQA 有波动。数据配比和任务类型相互影响，不能假设多训一定平滑上涨。做继续预训练或领域适配时，应分任务监控，只看平均分会漏掉局部退化。

### 3.2. 后训练：ChatML，grounding 坐标和 agent 协议

指令微调用 **ChatML** 格式，覆盖图像问答，文档解析，多图比较，视频理解，视频流对话和 agent。报告只写了 SFT，没有 DPO，PPO 或 GRPO 这类偏好对齐或 RL 阶段，也没有给出指令数据的规模。这一点和同期 Qwen2 文本模型不同，后者有离线和在线的偏好学习。

只做 SFT 意味着模型的对话风格，拒答边界和格式遵循都来自指令数据本身，没有奖励模型再校正。对 OCR 和 grounding 这类有明确答案的任务，SFT 已经够用；对开放式描述和多步推理，缺少偏好信号会让长回答更容易出现幻觉或啰嗦。报告没有给出这方面的对比，这是结合后续 Qwen2.5-VL 加入 DPO 的做法做出的推断。

Grounding 的框坐标归一化到 [0, 1000)，写成左上角和右下角两个点，用 `<|object_ref_start|>` 一类特殊 token 把框和指代文本绑在一起。这样坐标就成了普通文本，不需要检测头。缺点是坐标和原图尺寸脱钩，模型要自己换算；Qwen2.5-VL 后来改用绝对像素坐标，正是从这里改起。

Agent 任务被统一写成序贯决策：先定义允许的动作和函数调用格式，然后循环 「观察，推理，动作，新观察」。UI 操作，机器人控制，纸牌游戏和导航都走这个格式。点击坐标同样是 0 到 1000 的量纲，但和 grounding 框是不同的输出。数据格式一节用颜色标出了 ChatML 中哪些 token 进损失，复现时要注意只监督助手回复。

报告给了 agent 的 system prompt 样例。先在 「# Actions」 下列出可用动作，每个动作有名字，说明和参数表，例如 Tap 的参数是一个点，坐标范围 0 到 1000；Home 没有参数。之后模型按固定关键词输出：*FUNCTION* 写动作名，*ARGS* 写参数，环境返回 *RESULT*，最后 *RETURN* 基于结果回复。这套关键词格式来自 Qwen-Agent 框架。动作空间按任务单独定义，手机，机器人，游戏各有一套，没有统一；统一成跨平台共享动作空间是 Qwen2.5-VL 才做的事。

对话数据的格式也很简单：每轮用 `<|im_start|>` 和 `<|im_end|>` 包起来，多张图各自用 vision_start 和 vision_end 包裹，直接插在用户文本前。Grounding 样例写成 「the eyes on a giraffe」 加上 `(176,106),(232,160)` 这样的坐标对。所有结构都以文本 token 表达，不引入检测头或分割头，这是后来 Qwen 各代 VL 模型都保留的做法。

### 3.3. 训练基础设施：动态长度带来的麻烦

§2.3 写了基础设施。算力来自阿里云 PAI-灵骏，带弹性调度，自动续跑和掉队节点检测。文本数据放在 CPFS 上用 mmap 读，视觉数据放 OSS，训练时并发拉取，并调整重试策略，避免触发 QPS 上限。长视频解码是瓶颈，试过开源和自研方案后改为缓存解码。检查点把每张 GPU 的优化器和模型状态写回 CPFS。

并行策略是 DP + TP + PP，配 ZeRO-1 和序列并行，并做选择性激活重计算。开 TP 时 ViT 和 LLM 一起切分，vision merger 参数少，不切。卷积算子的非确定性会让本应共享的权重在不同卡上漂移，他们用离线归约消除，省掉一次额外的 all-reduce. 72B 用 1F1B 流水线，ViT，适配器和若干 LLM 层合并为一个阶段；交错 1F1B 实测更慢。软件栈是 PyTorch 2.1.2，CUDA 11.8，FlashAttention，融合的 LayerNorm，RMSNorm 和 Adam。

对只做推理部署的人，这一节有两处有用。一是动态序列长度要在流水线前广播，服务端 batching 不能假设视觉段定长。二是 vision merger 参数少，连接器不是算力大头；线上成本主要看每个请求带来多少视觉 token，以及是否处理视频。报告没有给出 GPU 小时数，训练总成本本页没有。

## 4. 评测

### 4.1. 图像评测：文档和 OCR 最强

表 2 是总对照。文档和读字：DocVQA 96.5, InfoVQA 84.5, TextVQA 85.5, OCRBench 877。通用感知：RealWorldQA 77.8, MMVet 74.0, MME 2482.7, MMBench-EN 86.5, MMBench-CN 86.6, MMStar 68.3。数学：MathVista 70.5，MathVision 25.9，后者低于 GPT-4o 的 30.4。大学级多学科：MMMU 64.5 对 GPT-4o 69.1，MMMU-Pro 46.2 对 51.9。文档理解的领先幅度明显，专家级综合推理仍落后。

量纲要看清。MME 是多个子任务的累加分 2482.7，OCRBench 是 877 这样的量表分，DocVQA 才是百分比。同表横比可以，换算成统一的 「准确率」 会误导。HallusionBench 平均 58.1，高于此前最好的 55.2，幅度远小于文档榜的提升，说明幻觉问题有改善，但没有解决。

也有几项没赢。ChartQA 88.3，低于 Claude 3.5 Sonnet 的 90.8；AI2D 88.1，表里 Claude 和 GPT-4o 的括号分数（94.7, 94.2）是另一种评测设定，不能直接比。其他评测里，MMT-Bench 71.7 比此前最好的 63.4 高出 8 分多，这个评测覆盖 32 个元任务，162 个子任务；MMBench-V1.1 85.9；VCR 英文简单设定 91.9。小档里 7B 的 MMMU 54.1, 2B 41.1，和 72B 的差距比文档类大得多。

再看数学评测的构成。MathVista 有 6141 道题，混合数学和视觉任务；MathVision 有 3040 道来自真实数学竞赛的题，覆盖 16 个学科，5 个难度。前者 72B 拿到 70.5，后者只有 25.9。竞赛题要求更深的数学推理，这和 MMMU 落后是同一个问题。

MMMU 落后和图 4 的结论对得上：**调像素救不了知识和推理**。语言侧用的是 Qwen2-72B，报告没有做 RL，这两点都可能限制多学科推理，但报告没有给出拆分这两个因素的实验。

### 4.2. 多语 OCR 与 grounding

表 3 是内部多语 OCR 评测：韩语 94.5，日语 93.4，法语 94.1，德语 91.5，意大利语 89.8，俄语 97.2，越南语 73.0，多数高于 GPT-4o；阿拉伯语 70.7，低于 GPT-4o 的 75.9，正文明确写了这个例外。公开的 MTVQA 上 72B 得 30.9，高于 GPT-4o 的 27.8 和 Claude 3.5 Sonnet 的 25.7. VCR 中文简单设定上是 65.4，GPT-4o 只有 14.9。

读多语能力时，公开榜，内部榜和阿拉伯语例外要放在一起看。内部评测集的构造方法报告没有公开，可复现性不如 MTVQA。这些结果和预训练里大量 OCR 数据对应，也和原生分辨率对应：小字和密集排版最怕缩放。

表 6 是指代表达。72B 在 RefCOCO val 93.2，test-A 95.3，test-B 90.7，RefCOCO+ val 90.1，RefCOCOg val 89.9，在通才模型里领先，和专门的检测定位模型也有竞争力。定位任务最依赖局部细节，固定低分辨率在这里最容易丢分，所以这组结果和动态分辨率的设计是同一件事的两面。

和前代比，Qwen-VL 在 RefCOCO val 是 89.4，test-B 85.3，RefCOCO+ test-B 77.2；Qwen2-VL-72B 分别是 93.2, 90.7, 85.6，最难的 test-B 子集涨幅最大。和专用模型比也不是全胜：UNINEXT-H 在 RefCOCO test-B 是 91.5，高于 Qwen2-VL 的 90.7。小档 2B 的 RefCOCO val 是 87.6，已经接近 Shikra 的 87.0，说明定位能力在小模型上也能保持。

### 4.3. Agent 评测：会选工具，导航弱

函数调用没有公开的 LVLM 评测集，团队自建了一个：按场景收图，用强 LVLM 抽取内容，再用强 LLM 生成需要调函数的问题和参数。指标分 Type Match（选对函数）和 Exact Match（参数全对）。表 5 中 TM 93.1, GPT-4o 90.2; EM 53.2, GPT-4o 50.0. TM 高而 EM 一般，说明会选工具，参数常常要额外校验。报告认为 GPT-4o 落后有两个原因：不确定时倾向少用工具，中文 OCR 较弱。

UI 操作用 AITZ，动作包括点击，输入和滑动，Qwen2-VL 的 EM 72.1，GPT-4o 只有 35.3，差距主要来自 UI grounding。机器人控制用 ALFRED，接 SAM 提高操作精度，valid-unseen 上 SR 67.8，GC 75.8，略高于专用的 ThinkBot。纸牌环境来自 RL4VLM: Number Line 100.0，BlackJack 42.6，EZPoint 100.0，Point24 4.5，这些任务同时考认牌和多步决策。四个游戏的规则分别是：用加一减一操作到达目标数；和庄家比牌，决定要牌还是停牌；用基本算术凑出 12；用算术凑出 24. Point24 只有 4.5，GPT-4o 3.0，此前最好 2.6，大家都接近零，凑 24 需要搜索多种组合，单次生成很难做到。

UI 操作的评测细节：AITZ 从 AITW 清洗出核心测试集，动作是点击，输入和滑动。例如在 Google 地图上找附近的比萨店，要输入 「pizza」，滑动选店，再点链接。TM 看动作类型是否对，EM 看点击位置，输入文本，滑动方向是否都对。Qwen2-VL 的 TM 89.6，此前最好 83.0, GPT-4o 70.0。机器人控制的 ALFRED 在 AI2THOR 模拟器里做家务，例如烤面包，切苹果；高层动作集是 GotoLocation, Pickup, PutDown, Open, Close, Clean, Heat, Cool, Slice。只有识别到物体才能操作，所以接入了 SAM. SR 看整个任务是否完成，GC 看子目标完成率。

函数调用评测的构造也要看清。TM 是调用了正确函数的次数占总调用次数的比例；EM 检查每次调用的参数是否和图像内容信息里记录的完全一致。评测集的问题和参数由 LLM 根据 LVLM 抽取的图像内容生成，所以 EM 实际考的是 「从图里读出正确参数」 的能力，和 OCR 高度相关。

**导航是报告自己写明的短板**。R2R SR 51.7，高于 GPT-4o 的 43.7，远低于专用模型约 79.0；REVERIE 31.0，和 GPT-4o 的 31.6 接近，远低于专用模型约 61.0。原因是多张图拼出的地图信息不完整，三维场景建图很难。多轮任务在最长 32K 上下文里保存观察和动作的历史。把四类任务放在一起看：有明确动作空间，靠读屏就能决策的任务表现好；需要持续三维空间记忆的任务就不行。

## 5. 部署与边界

### 5.1. 选型与部署

端侧或资源紧张时先看 2B: DocVQA 90.1，OCRBench 809，RealWorldQA 62.9，够很多读字和轻量问答场景。7B 是性价比档：DocVQA 94.5，OCRBench 866，Video-MME 有字幕 69.0，表 7 和图 4 的消融也主要在 7B 上做。冲闭源对比，文档 agent 或 EgoSchema 这类长视频，上 72B. 三档换的是语言模型体量，视觉配方不变。

视觉 token 是随输入变化的成本。动态分辨率省下的是 「小图不必放大到固定高分辨率」，大图仍然贵。部署前可以按三个问题检查：输入图的分辨率分布是否落在训练时的 min_pixels 和 max_pixels 之间；视频是否按接近 2 fps 抽帧，总 token 会不会超；工具调用是否同时验收 TM 和 EM。三项都满足，报告的分数才有可能迁移到自己的流量上。

TestingTime 方面，报告没有多采样，搜索或自我验证的实验，表中分数都是单次生成。视频外推到约 80K 是推理阶段放宽输入长度，不是多花算力做搜索。

推理框架的支持也要提前确认。M-RoPE 需要为每个 token 准备三维位置 ID，并在拼接多模态段时计算偏移，vLLM 和 Hugging Face 都为此写了专门的位置计算函数。自己改框架或做量化部署时，如果位置 ID 退化成一维，模型仍能输出，但图像和视频的空间感会明显变差，这类错误不容易从日志里发现。

### 5.2. 谱系位置与边界

往前看，Qwen2-VL 继承了 Qwen-VL 的三阶段训练和 「ViT + 连接器 + LLM」 结构，换掉的是固定分辨率和一维位置编码。往后看，同目录的 [Qwen2.5-VL](../qwen2-5-vl/qwen2-5-vl-analysis.md) 在 ViT 里加 window attention 降低高分辨率的计算量，把 M-RoPE 的时间 ID 和绝对时间对齐，grounding 改用绝对坐标；[Qwen3-VL](../qwen3-vl/qwen3-vl-analysis.md) 再把 M-RoPE 的频率分配改成交错式。这三步改动都直接针对本报告留下的问题：大图计算量，时间 ID 与秒数脱钩，相对坐标和频率切分。

报告没有 MoE 视觉塔，没有 MLA，没有 MTP，没有 RL 阶段。知识截止 2023-06，对照模型是 2024 年中的 GPT-4o，Claude 3.5 Sonnet，InternVL2 和 Gemini 1.5-Pro，拿去和更新的闭源模型比会错位。附录图 7 到图 31 的定性例子展示读屏，多语 OCR，数学题，网页 agent 和纸牌，用来建立直觉，不能代替表 2 到表 8 的定量结论。

代价也要一起算：动态分辨率让显存和延迟随输入变化；M-RoPE 增加实现复杂度，推理框架需要专门支持三维位置 ID；图视频统一让图像多算一帧；导航明显弱于专用模型。如果业务是扫描件，多语招牌和手机 UI，这份报告的强项正好对口；如果是竞赛级多学科推理或室内导航，需要另找模型补齐。对不上的数字以 `qwen2-vl.md` 为准，英文原句开 `qwen2-vl-bi.md` 对照。
