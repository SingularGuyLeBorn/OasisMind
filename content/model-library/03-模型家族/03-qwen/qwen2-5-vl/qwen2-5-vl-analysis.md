# Qwen2.5-VL: 窗口 ViT, 绝对时间 MRoPE 和绝对坐标

来源: [Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923) (arXiv:2502.13923v1, 2025-02-19). 仓库 https://github.com/QwenLM/Qwen2.5-VL. 对照译稿见同目录 `qwen2-5-vl-bi.md`, 表内数字以源文 `qwen2-5-vl.md` 为准.

Qwen2.5-VL 在 Qwen2-VL 的原生分辨率和 M-RoPE 上继续改, 几处改动互相配合. 架构上, ViT 从零训练, 多数层改成窗口注意力, 让计算量随 patch 数近似线性增长; M-RoPE 的时间分量从帧号改成和绝对时间对齐. 数据上, 预训练从约 1.2 万亿 token 扩到约 4.1 万亿, 文档统一写成带坐标的 HTML, grounding 改用绝对像素坐标, 并加入大量 GUI 操作轨迹. 预训练分三阶段, 最后一段把序列长度拉到 32768. 后训练冻结 ViT, 做 SFT 和 DPO, SFT 数据里的推理样本靠拒绝采样筛选. 评测上文档解析, 计数, GUI grounding 和长视频事件定位进步最大, 桌面开放任务 OSWorld 仍落后 Claude. 语言模型沿用 Qwen2.5, 没有换成 MoE, 也没有 RL 阶段.

## 1. 起点与规格

### 1.1. 起点: Qwen2-VL 留下的四个问题

Qwen2-VL 用原生分辨率和 M-RoPE 把文档和 OCR 做到顶档, 但留下了几个问题. 第一, ViT 全部层都是全注意力, 大图的计算量随 patch 数平方增长, 训练和推理负载随图片尺寸剧烈波动. 第二, M-RoPE 的时间 ID 按帧递增, 和真实秒数脱钩, 采样率一变, 同样的 ID 差就对应不同的时长. 第三, grounding 用 0 到 1000 的归一化坐标, 模型看不到物体的真实像素尺度. 第四, 后训练只有 SFT.

报告自己列的增量是四条: ViT 加窗口注意力; 动态 FPS 采样, 把动态分辨率伸到时间维; M-RoPE 时间分量对齐绝对时间; 预训练语料从 1.2T 扩到 4.1T, 并加强 SFT 数据筛选. 这四条正好对上前面四个问题中的前三个, 第四个由 DPO 补上. 引言把当时的 LVLM 比作夹心饼干的中间层: 样样能做, 但哪样都不顶尖. 本代的目标是把细粒度感知做扎实, 再在上面做多模态推理和可操作的 agent.

能从正文读到的继承关系: 语言模型从 **Qwen2.5** 初始化; 位置编码建立在 Qwen2-VL 的 M-RoPE 上; 后训练沿用 ChatML; 数据分类器 **Qwen2-VL-Instag** 由 Qwen2-VL-72B 衍生. 读这份报告, 要先把 Qwen2-VL 的动态分辨率和三维位置编码当作已有底座.

### 1.2. 三档规格: 视觉塔不变, 语言塔放大

表 1 给出三档 3B, 7B, 72B. 三档共用同一套 ViT: 隐层 1280, 32 层, 16 个头, patch 14, 窗口 112, 全注意力层下标 `{7, 15, 23, 31}`. 语言侧按档分: 3B 为 36 层, 2 个 KV 头; 7B 为 28 层, 4 个 KV 头; 72B 为 80 层, 8 个 KV 头; head size 都是 128. 词表统一 151646, 3B 额外做 embedding tying. 三档训练 token 都是 4.1T.

视觉塔三档共享, 说明团队认为视觉感知的瓶颈不在编码器体量, 而在分辨率处理和数据. 语言侧用层数和 GQA 的 KV 头数换容量, 所以端侧和旗舰在 KV cache 宽度上差别很大: 3B 只有 2 个 KV 头, 长视频推理时缓存压力小得多. 选型时只说 「Qwen2.5-VL」 会忽略这一点, 表 1 的 KV 头一列就能看出差别.

Merger 的输入维固定 1280, 输出维按档变为 2048, 3584, 8192, 正好等于各档 LLM 的隐层维度. 视觉塔和语言塔的接口只有这一层 MLP, 换档时改动很小.

## 2. 架构: 窗口 ViT, 坐标与时间

### 2.1. 窗口注意力 ViT: 为什么从零训练

原生分辨率输入下, 全图自注意力随 patch 数平方增长. 报告的做法是多数层用**窗口注意力**, 最大窗口 112×112 像素, 对应 8×8 个 patch; 只有四层做全局自注意力; 小于窗口的区域不补 padding. 这样计算量近似随 patch 数线性增长, 同时每隔约 8 层有一次全局信息交换, 最后一层也是全注意力, 在进入 Merger 前做一次整图汇总. 这和 Swin Transformer 的窗口思路相近, 但没有移位窗口, 跨窗口交流全靠那四层全注意力. 落到一张 1792×1792 的图上算注意力打分的 q·k 对数 (按表 1 结构推算, 报告没有给): patch 网格 128×128, 共 $N=16384$ 个 patch. 全注意力层每层要算 $N^2\approx2.7\times10^8$ 对; 窗口层每个 patch 只和同窗的 64 个 patch 算, 每层 $64N\approx1.0\times10^6$ 对, 少了 $N/64=256$ 倍. 32 层全用全注意力是约 $8.6\times10^9$ 对; 28 层窗口加 4 层全局约 $1.1\times10^9$ 对, 其中 97% 来自那 4 层全局层. 所以 「近似线性」 只对 28 个窗口层成立, 图再放大, 总量仍由 4 层全局层的 $N^2$ 主导, 只是系数从 32 降到了 4.

ViT 也向 LLM 的写法靠拢: 归一化用 **RMSNorm**, FFN 用 **SwiGLU**, 位置用 **2D-RoPE**. 训练从零开始, 依次做 CLIP 预训练, 视觉语言对齐和端到端微调, 训练时按原宽高比动态采样分辨率. 从零训的原因报告没有直接写, 结合结构看: 换了归一化, 激活函数和注意力模式, 原有 ViT 权重已经很难直接复用.

代价有三处. 一是要维护窗口层和全局层的混合调度; 二是图像高宽要先调整到 28 的倍数, 和 14 的 patch 以及后面的 2×2 合并对齐; 三是文档里相距很远的表头和单元格, GUI 上对角的图标和菜单, 只能靠四层全局层把信息拉到一起. 报告没有给出 「全局层改成 8 层」 或 「全部全注意力」 的消融, 也没有给出窗口化前后的 FLOPs 曲线, 省了多少计算这一面本页没有定量数字.

### 2.2. Merger 与绝对坐标

Merger 把空间上相邻的 4 个 patch 特征拼接, 经两层 MLP 投到文本嵌入的维度. 序列长度降到约四分之一, 并且随分辨率自然变长变短. 和 Qwen2-VL 的 2×2 合并相同, 每个 LLM token 对应 28×28 像素.

更关键的改动在坐标. Qwen2.5-VL 不再用归一化坐标, 而是用输入图实际尺寸上的**绝对像素坐标**表示框和点. 归一化坐标抹掉了物体的真实尺度, 一个占满 200 像素的物体在大图和小图里会变成不同的数值比例; 绝对坐标让模型能学到像素跨度和物体大小的关系. 前提是标注必须写在 「实际送进模型的那张图」 的像素系里, 调整到 28 倍数的那一步也要同步改坐标. 社区复现时常见的错误, 就是用原图坐标去训练缩放后的输入.

Grounding 数据同时有框和点, 格式包括 XML, JSON 和自定义格式, 用 copy-paste 增强, Grounding DINO 和 SAM 等现成模型扩充. 开放词表检测扩到超过 10,000 个类别, 还合成了 「图中不存在的类别」 和多实例图, 训练模型拒绝乱指. 点 grounding 混合了开源的 PixMo 和自动合成的细粒度指点数据. 评测上 ODinW 43.1 mAP, PointGrounding 67.5, CountBench 93.6, 后者用 「先检测再计数」 的提示, 说明计数主要依赖可靠的定位中间结果.

表 6 显示定位并非全面领先. RefCOCO val 上 72B 是 92.7, 低于 InternVL2.5-78B 的 93.7; RefCOCO+ testB 83.7 对 86.9, RefCOCOg val 89.9 对 92.7, 都落后. ODinW 的 43.1 远低于专用检测模型 Grounding DINO 的 55.0, 报告的说法是 「缩小了通才和专才的差距」. PointGrounding 的 67.5 也略低于 Molmo-72B 的 69.2. CountBench 的 93.6 则高于所有对照, 包括 Molmo 的 91.2. 所以定位这一块, 本代的强项是计数和 GUI 这类需要绝对坐标的任务, 传统指代表达评测已接近饱和, 没有拉开差距.

### 2.3. 绝对时间 MRoPE 和动态 FPS

Qwen2-VL 的时间 ID 按帧号递增, 模型学不到内容变化的快慢, 也学不到事件发生在第几秒. Qwen2.5-VL **让时间 ID 的间隔对应真实时间**: 同样隔 1 秒, 不管采样率是 1 fps 还是 4 fps, 时间 ID 的差值都一样. Hugging Face 的实现里, 相邻时间 patch 的 ID 间隔是 `tokens_per_second × temporal_patch_size / fps`, 其中 temporal_patch_size 为 2, 即两帧一组. 按这个公式, 采样率越低, 相邻组之间的 ID 跳得越大, 跳的幅度正好补偿帧的稀疏. 举个例子 (按公式代入): 若 tokens_per_second 取 2, fps 为 2, 间隔是 2 × 2 / 2 = 2, 相邻两组帧相隔 1 秒, ID 差 2; fps 降到 1, 间隔变成 4, 两组帧相隔 2 秒, ID 差 4. 每秒对应的 ID 增量固定, 模型就能从 ID 差读出真实时长. 代价是低帧率视频的时间 ID 增长更快, 长视频的最大位置 ID 也更大, 这对外推有压力.

同期很多模型用文本时间戳或额外的时间预测头做时间定位. 报告强调自己的做法不增加 token, 也不加额外模块, 时间信息直接编码在位置里. 代价是模型必须从位置编码里读出秒数, 可解释性不如文本时间戳直观. 后来 Qwen3-VL 改回显式文本时间戳, 理由是更简单直接, 这说明两种做法各有取舍, 本报告没有和文本时间戳做对照实验.

**动态 FPS** 是配套的训练策略: 训练时按可变帧率抽样, 让训练集的 FPS 分布更均匀. 超过半小时的视频用多帧 caption 合成管线构造长视频描述; 时间戳标注同时提供秒数和 「时:分:秒:帧」 两种格式. 评测协议每个视频最多 768 帧, 视频 token 总数不超过 24,576. 两帧一组之后, 实际时间粒度还要再粗一档, 所以 「能看小时级视频」 不等于每一秒都有独立的视觉 token.

## 3. 数据与训练

### 3.1. 文档: 统一写成 HTML

传统文档处理拆成版面分析, 文字抽取, 图表解释, 插图处理几个专门模型. Qwen2.5-VL 把表格, 图表, 公式, 自然图和合成图, 乐谱, 化学式**统一写成 HTML**, 每个元素带 `data-bbox` 坐标, 按阅读顺序排列. 图表节点里还嵌 `<table>` 装数值, 乐谱用 ABC 记谱法, 化学式用 SMILES. 版面, 文字, 图和表落在同一棵结构树上, 模型直接学 「看文档, 吐出可解析的结构」.

OCR 数据混合合成的野外文字图, 开源和内部数据, 并扩到法, 德, 意, 西, 葡, 阿, 俄, 日, 韩, 越等语言. 图表约 100 万条合成样本; 表格约 600 万条真实样本, 用离线端到端识别模型标注后, 过滤低置信, 重叠和过稀疏的表. 这类数据的构造成本很高, 既要框又要结构, 还要多类元素的可读文本; 收益是下游不用维护 「先版面, 再 OCR, 再问答」 的脆弱级联.

图表数据用 matplotlib, seaborn 和 plotly 合成, 类型包括柱状图, 关系图和热力图. 合成图表的好处是底层数值完全已知, 可以直接生成 `<table>` 形式的标注, 不需要人工读图; 缺点是风格和真实论文, 报表里的图有差距. 表 5 里 ChartQA 89.5 低于 Claude 3.5 Sonnet 的 90.8, CharXiv 的推理题 RQ 49.7 也明显低于 Claude 的 60.2, 描述题 DQ 却是 87.4 领先. 能读出图上写了什么, 不等于能基于图做推理, 合成数据主要补的是前者.

评测上 CC-OCR 79.8, OCRBench 885, OCRBench_v2 英文 61.5, 中文 63.7, DocVQA 96.4, InfoVQA 87.3, CharXiv DQ 87.4. OmniDocBench 用编辑距离, 越低越好, 72B 英文 0.226, 中文 0.324; 英文最好, 中文和 InternVL2.5-78B 持平. OCRBench_v2 上报告说英文和中文分别比 Gemini 1.5-Pro 高 9.6% 和 20.6%. 小模型也有反常: TextVQA 上 7B 是 84.9, 高于 72B 的 83.5; VCR 英文困难集 7B 80.5, 也高于 72B 的 79.8, 说明纯读字任务到 7B 已接近饱和. 表 5 把解析, 理解和综合分开列: 解析榜看结构还原, 理解榜看读图答题, 综合榜两者都考. InfoVQA 和 CharXiv 这类信息图和论文图的高分, 和 HTML 数据形态出自同一条数据管线.

### 3.2. 预训练: 1.5T + 2T + 0.6T 三阶段

表 2 把 4.1T 拆成三段. 视觉预训练 1.5T, 只训 ViT, 序列长 8192, 数据以 caption, 视觉知识和 OCR 为主. 多模态预训练 2T, ViT 和 LLM 全部放开, 加入纯文本, 图文交错, VQA, 视频, grounding 和 agent 数据. 长上下文预训练 0.6T, 序列长提到 32768, 加强长视频, 长 agent 轨迹和长文档. 顺序是先对齐视觉, 再学复杂多模态任务, 最后拉长上下文; 一开始就上 32K 长序列混长视频, 既贵又不稳定.

交错图文数据先做常规清洗, 再用内部模型**按四个维度打分**: 纯文本质量, 图文相关性, 图文互补性, 信息密度平衡. Agent 数据包括手机, 网页, 桌面截图的描述和 UI grounding, 多端操作统一成共享动作空间的 function call; 逐步操作轨迹还配有人工和模型标注的操作意图推理, 让模型学 「为什么点这里」, 不只背点击序列. 报告没有给出各类数据的具体配比, 这一面本页没有.

打包策略也随阶段变. 报告说视觉塔参数少且已窗口化, 主要计算在 LLM, 所以按 LLM 输入序列长度动态打包, 让各 GPU 负载接近; 前两段打包到 8192, 第三段到 32768. 这说明长上下文能力是换课程和换打包长度同时做出来的, 不是把短数据简单拉长重放. 训练总 GPU 小时数报告没有给.

ViT 的初始化来自 DataComp 和部分内部数据, 语言模型来自 Qwen2.5. 第一阶段的视觉知识数据包括名人, 地标, 动植物识别, 这类数据只能靠大规模图文对积累, 放在只训 ViT 的阶段, 是为了让视觉表示先学会 「认东西」, 再去学 「怎么和语言一起推理」. 第二阶段新增的多模态数学和学术题, 是 MathVista 和 MMMU 进步的直接数据来源.

交错图文在报告里有三个明确用途: 支持带图文线索的 in-context learning; 图像缺失时保持纯文本能力; 覆盖广泛的通用知识. 问题是大量网页交错数据里图和文关系很弱, 图片只是装饰. 四维打分里的 「互补性」 要求图和文各自提供对方没有的信息, 「信息密度平衡」 要求不能一边倒, 这两条专门针对装饰性配图. 打分模型是内部评估模型, 阈值和保留比例报告没有公开.

### 3.3. 后训练: 冻结 ViT, SFT 加 DPO

后训练两段: SFT 和 DPO, **两段都冻结 ViT**. SFT 用 ChatML 格式, 数据约 200 万条, 纯文本和多模态各占 50%, 但多模态样本因为带图像和视频, 消耗的 token 和算力明显更多. 领域覆盖通用 VQA, 描述, 数学, 代码, 安全, 文档 OCR, grounding, 视频和 agent. DPO 只用图文和纯文本偏好数据, 每条样本只过一次. 报告没有给出 DPO 偏好对的数量.

SFT 数据以中文和英文为主, 补充少量多语数据; 既有单轮也有多轮, 既有单图也有多图序列. 查询来源主要是开源数据, 另有购买的数据集和线上真实查询. 报告说 ChatML 相对预训练格式带来三点变化: 显式的多模态轮次角色标记, 视觉嵌入和文本指令的结构化注入, 以及格式感知的打包方式保持跨模态的位置关系. 第三点和 M-RoPE 有关: 多条样本打包进同一序列时, 每条样本的三维位置 ID 要各自从头计算, 不能串到下一条.

冻结 ViT 的含义是: OCR 和 grounding 的视觉分辨力在预训练阶段定型, 后训练只负责听懂指令, 按偏好回答, 把已有的视觉证据用进推理. 如果后训练继续解冻 ViT, 成本高, 还可能破坏已经对齐的原生分辨率几何. 报告把这部分预算省下来用在数据过滤和拒绝采样上.

和同期文本模型比, Qwen2.5 语言模型的后训练有离线 DPO 和在线 GRPO 两段, 而 Qwen2.5-VL 只有 DPO. 多模态模型的在线 RL 在当时还不成熟, 缺少可自动校验的多模态奖励. 这一步要到 Qwen3-VL 才补上, 本报告没有 RL.

### 3.4. 数据筛选与拒绝采样

筛选分两段. 第一段用 Qwen2-VL-Instag 把问答样本分到 8 个主领域, 30 个细类, 例如编程, 规划等. 第二段按领域做规则过滤 (去重复, 去截断, 去有害内容) 和奖励模型多维打分. 分领域的好处是每类数据可以用不同的阈值, 不会因为一个全局分数把某类小众但有用的数据全筛掉.

以编程为例, 主领域下再分代码调试, 代码生成, 代码翻译和代码理解四个细类. 规则过滤主要针对文档处理, OCR 和 grounding 数据: 合成数据里常见的重复模式, 不完整或格式错误的回答都会被去掉, 和问题无关或可能引出有害输出的问答也删掉. 模型过滤用在 Qwen2.5-VL 系列上训练的奖励模型: 问题按复杂度和相关性打分, 只留难度合适的; 回答按正确性, 完整性, 清晰度, 相关性和有用性打分; 视觉相关任务还要额外检查是否正确理解和使用了图像信息.

**拒绝采样**针对数学, 代码和专业领域 VQA: 用中间版本的 Qwen2.5-VL 生成回答, 只保留最终答案和标准答案一致的样本, 再过滤语言混用, 过长和重复的输出. 这是 rejection fine-tuning 在多模态上的直接应用, 和 Qwen2.5-Math 的做法一脉相承.

报告还承认一个没解决的问题: 多模态 CoT 的中间步骤可能忽略或误读图像, 即使最终答案碰巧对了. 他们用规则和模型检查中间步骤是否真正用到了视觉信息, 但也写明最优的模态对齐仍是开放问题. 所以 SFT 的监督同时看最终答案和中间步骤的视觉整合, 不只是复制文本推理的格式.

## 4. 评测

### 4.1. 通用评测与纯文本能力

表 3 中 72B 的 MMMU 70.2, MathVista 74.8, MATH-Vision 38.1, MMBench-EN 88.6, MuirBench 70.7, MMVet 76.2, 进入开源第一梯队. 和 Qwen2-VL-72B 的 MMMU 64.5 比, 提高约 6 分, 这部分进步来自更强的 Qwen2.5 语言模型, 更多的推理数据还是 DPO, 报告没有拆分.

表 4 验证纯文本能力没有退化: MMLU-Pro 71.2, MATH 83.0, IFEval 86.3, HumanEval 87.8, MultiPL-E 79.5, LiveBench-0831 57.0, 整体和 Qwen2.5-72B 同档. 多模态继续训练常被认为会伤语言能力, 这张表是反证; 做法上靠多模态预训练阶段混入纯文本, SFT 里纯文本占一半.

逐项对比 Qwen2.5-72B: MMLU-Pro 71.2 对 71.1, GPQA 都是 49.0, MATH 83.0 对 83.1, 基本持平; MMLU-redux 85.9 对 86.8, GSM8K 95.3 对 95.8, 小幅下降; LiveBench-0831 57.0 对 52.3, MultiPL-E 79.5 对 75.1, IFEval 86.3 对 84.1, 反而更高. 上升的几项和指令遵循, 代码有关, 可能来自 SFT 里的代码和格式数据, 也可能是 DPO 的作用, 报告没有拆分. 知识类评测小幅下降, 符合 「多模态训练稀释了部分文本知识」 的一般经验.

也有持平或偏弱的项. HallusionBench 上 72B 为 55.2, 低于 Qwen2-VL-72B 的 58.1. RealWorldQA 75.7, 也低于 Qwen2-VL-72B 的 77.8 和 InternVL2.5-78B 的 78.7; MME 总分 2448, 低于 Qwen2-VL 的 2483. 这几项都是通用感知或幻觉类, 本代的数据重心放在文档, 定位和 agent 上, 通用感知出现小幅回落, 报告没有解释原因.

主观评测方面, MMVet 76.2, MM-MT-Bench 7.6, 后者略低于 GPT-4o 的 7.72. 多图理解 MuirBench 70.7, BLINK 64.4, 高分辨率真实场景 MME-RealWorld 63.2. MMMU-Pro 51.1, 和 GPT-4o 的 51.9 接近. 多语 MTVQA 31.7, 比 Qwen2-VL 的 30.9 略高, 但不如 InternVL2.5-78B 的 31.9. 小档 7B 和 3B 在 MMStar, OCR 和视频子集上仍然可用, 对应摘要说的 「从端侧到高性能」. 读表时按能力分块看, 不要只用 MMMU 一个数概括全文.

### 4.2. 视频评测

长视频是本代的重点. Charades-STA 上 72B 的 mIoU 50.9, GPT-4o 是 35.7; LVBench 47.3, MLVU 74.6. 此外 TempCompass 74.8, EgoSchema 76.2. Charades-STA 是时间定位任务, 要求说出事件的起止秒数, 这正是绝对时间 MRoPE 要解决的问题, 分数的提升和机制改动直接对应.

比较不同模型时要对齐帧预算: 本报告是 768 帧, 24,576 个视频 token. 其他论文的上限不同, 跨论文横比时差异不能全部归到 M-RoPE 上. 报告没有做 「帧号 ID 对比绝对时间 ID」 的消融, 所以 Charades-STA 的提升里有多少来自位置编码, 多少来自时间戳标注数据, 本页没有证据拆开.

EgoSchema 从 Qwen2-VL-72B 的 77.9 降到 76.2, 说明长程自我中心视频问答没有继续提升. 本代的视频进步集中在时间定位和长视频检索类任务, 和改动的方向一致.

表 8 里也有落后的项. Video-MME 无字幕 73.3, 有字幕 79.1, 都低于 Gemini 1.5-Pro 的 75.0 和 81.3; LongVideoBench 60.7, 低于 GPT-4o 的 66.7; MMVU 62.9, 低于 GPT-4o 的 67.4; Video-MMMU 60.2, 略低于 GPT-4o 的 61.2. MMVU 和 Video-MMMU 考的是视频里的专业知识, 和图像上的 MMMU 类似, 瓶颈在知识和推理. 小模型的时间定位也不差: Charades-STA 上 7B 43.6, 3B 38.8, 都高于 GPT-4o.

### 4.3. GUI agent 评测

Agent 上 ScreenSpot 87.1, 略低于 Aguvis-72B 的 89.2; ScreenSpot Pro 43.6. ScreenSpot Pro 是高分辨率专业软件界面, Qwen2-VL-72B 只有 1.6, Aguvis-72B 是 23.6, 提升幅度很大. 这和窗口 ViT 能处理大图, 绝对坐标, 以及大量 UI grounding 数据都有关. Android Control Low EM 93.7, High EM 67.36, AndroidWorld 成功率 35%, MobileMiniWob++ 68%. Low 和 High 的区别是前者给出每一步的低层指令, 后者只给高层目标, 模型要自己规划; 两者相差约 26 分, 规划仍是主要难点. 线上评测中, 部分对照模型因为定位能力不足完成不了任务, 评测方给它们的输入加了 Set-of-Mark 标注 (在截图上给可点元素编号); Qwen2.5-VL 不加标注, 仍在 AndroidWorld 和 MobileMiniWob++ 上领先. 评测协议不对称, 对比时要记住对照组拿到了额外帮助.

Agent 能力的数据来源在预训练阶段就埋下了. 感知部分用合成引擎给手机, 网页, 桌面截图生成描述和 UI 元素定位标注, 描述任务让模型理解界面, 定位任务让它对齐元素的外观和功能. 决策部分把三端操作统一成共享动作空间的 function call, 轨迹来自开源数据和在虚拟环境里跑 agent 框架合成. 每一步还要补推理: 把标准操作在截图上高亮, 连同全局任务和操作前后两张截图交给标注者 (人或模型), 让他们写出这一步的意图, 再用模型过滤低质量的推理. 报告说这样做是为了防止模型死记标准操作序列, 在真实环境里更稳健.

桌面开放任务仍落后: OSWorld 8.83, Claude 是 14.90. OSWorld 需要跨应用的长程规划和错误恢复, 单步定位准确并不够. 这和 Qwen2-VL 在导航任务上的短板是同一类问题: 有明确动作空间, 靠读屏就能决策的任务表现好; 需要长程规划的任务就吃力.

GUI agent 和文档解析放在同一个模型里, 因为两者依赖同样的能力: **高精度定位加结构化输出**. 文档输出 HTML 和 bbox, 界面输出点击坐标或 function call. 报告用 ScreenSpot Pro 和 CC-OCR, OmniDocBench 两头验证, 比只报一个综合 VQA 分数更能说明 「细粒度」 细在哪里.

## 5. 部署与边界

### 5.1. 部署与 TestingTime

选型上, 3B 和 7B 适合端侧和性价比场景, 72B 用于文档 agent, 长视频定位和 GUI 操作. 部署时要注意三件事: 输入图要调整到 28 的倍数, 坐标同步换算; 视频按接近训练分布的帧率抽取, 总 token 不超过预算; 推理框架要支持三维位置 ID 和按 fps 计算时间间隔, 否则时间定位会失效.

窗口注意力降低了 ViT 的计算量, 但 LLM 侧的成本仍随视觉 token 数增长. 一张 4K 截图经过 2×2 合并后仍有数千个 token (按 28×28 像素一个 token 估算), 视频更多. 所以线上成本主要看每个请求的像素量, 用 min_pixels 和 max_pixels 控制仍然必要.

TestingTime 方面, 报告没有多采样, 搜索或自我验证的实验, 也没有 thinking 模式, 表中分数都是单次生成. 推理时多花算力换精度, 要到 Qwen3-VL 的 thinking 版本才出现.

### 5.2. 谱系位置与边界

往前看, Qwen2.5-VL 保留了 Qwen2-VL 的原生分辨率, 2×2 合并和三维位置编码, 改掉的是全注意力 ViT, 帧号时间 ID, 归一化坐标和只有 SFT 的后训练. 往后看, [Qwen3-VL](../qwen3-vl/qwen3-vl-analysis.md) 把绝对时间 MRoPE 换成显式文本时间戳, 把 M-RoPE 的频率分配改成交错式, 用 DeepStack 把 ViT 多层特征注入 LLM, 并加入 MoE 版本和 thinking 版本. 前一代见 [Qwen2-VL](../qwen2-vl/qwen2-vl-analysis.md).

报告没有 MoE, 没有 MLA, 没有 MTP, 没有 RL, 没有公开完整的 agent 动作空间定义. 窗口注意力的效率收益, DPO 的数据规模, 训练总成本都没有给数字. 报告点名的应用场景是发票, 表单和表格的结构化抽取, 图表版面分析, 小时级视频的秒级事件定位, 以及电脑和手机上的操作 agent. 这些场景都需要模型同时知道 「在哪」 (绝对空间), 「何时」 (绝对时间), 以及 「点什么, 填什么」 (grounding 加 function call).

对照译稿和源文都是 23 页, 图 3 张. 表内数字冲突时, 以 `qwen2-5-vl.md` 原表为准. 如果业务是文档和 GUI, 先核对自己的数据分布是否被 HTML 解析和绝对坐标 grounding 数据覆盖; 如果是视频, 先对齐帧预算和是否带字幕, 再比较分数.
