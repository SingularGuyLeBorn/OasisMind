# Qwen 初代：中档 Dense 底座上，语料，词表，外推与 RLHF 怎样一起定型

来源：[QWEN TECHNICAL REPORT](https://arxiv.org/abs/2309.16609) (arXiv:2309.16609v1, 2023-09-28)。仓库：https://github.com/QwenLM/Qwen. 对照译稿见同目录 `qwen-bi.md`（page 1 of 59 至 page 59 of 59），表内数字与超参以源文 `qwen.md` 为准。

2023 年 9 月的 Qwen 不是靠某一个新算子出名的模型。它能在当时的开源榜上站住，靠的是几件事互相咬合：中英为主的语料和一张约 152K 的词表先把中文序列压短，标准 decoder-only 骨架上几处小改保证训练稳定和长度外推，预训练只训 2048 长度，推理期再用一组 training-free 手段把可用长度推过 8192，最后用 ChatML 格式的 SFT，先预训练再微调的奖励模型，以及带预训练梯度的 PPO 把 Chat 版本做出来。工具调用，代码，数学三条线又从同一个底座分出去。单看任何一块都算不上新，放在一起才解释得了 Table 2 里 C-Eval 高，MMLU 仍落后 LLaMA2-70B 的那种分数形状。

## 1. 底座：约束，词表与骨架

### 1.1. 2023 年秋的约束：中档参数，中英语料，可复现

Table 1 只有三档 Dense: 1.8B（hidden 2048, 16 heads，24 层，2.2T token），7B (4096 / 32 / 32, 2.4T), 14B (5120 / 40 / 40, 3.0T)。三档峰值学习率都是 $3.0\times10^{-4}$，batch 都是 4M token。摘要里的 「up to 3 trillion tokens」 只对应 14B，小档没有吃满。同期 LLaMA 2 把火力放在 70B，国内的 Baichuan2，InternLM，ChatGLM2 在 7B 到 13B 之间抢位置。Qwen 的选择是把参数控制在常见单卡或双卡能部署的范围，然后**用 token 数和中文覆盖去换分数**。

这个选择决定了后面每一块怎么做。参数不大，就更依赖数据质量，所以清洗流水写得很细。中文是主场，就需要一张对中文友好的词表，否则同样一段中文要切成更长的序列，2048 的训练窗口会显得更短。训练窗口短，长文档就只能靠推理期外推补。三档共用一套峰值学习率，说明团队用 token 预算而不是超参去区分规模；报告没有给 Scaling Laws 拟合曲线，也没有解释 2.2T / 2.4T / 3.0T 这组配额是怎么算出来的，这一面本页没有。到代码继续预训练阶段才给 14B 和 7B 分开设更小的学习率，「通用阶段一套超参，领域阶段再收紧」 是有意分层。

Figure 1 画的谱系也要先记住。基座 Qwen 经 SFT 得到 Qwen-Chat，再经 RLHF 得到 Qwen-Chat-RLHF；Code-Qwen，Code-Qwen-Chat，Math-Qwen-Chat 从同一个基座用类似技术分出去；更早开源的 Qwen-VL 与 Qwen-VL-Chat 也建立在这个基座上。这意味着底座一旦定型，后面至少五条产品线都继承它的词表，位置编码和训练长度。所以底座阶段的每个取舍，影响的不只是 Table 2 的一格分数，还有下游每个分支能做到什么程度。

### 1.2. 词表和 embedding 要放在一起算

§2.2 从 tiktoken 的 cl100k_base 出发做 BPE，补进常用汉字，词语和其他语种的词，数字拆成单个 digit，最后约 152K. Figure 3 用每种语言 100 万篇文档比压缩率，以 XLM-R 为基准 1：中英和代码保持住，th，he，ar，ko，vi，ja 等也压得更紧。社区讨论这张图时通常只盯中文一条，其实报告的卖点在于一长串非英语语种一起变短。数字逐位切分跟 LLaMA 一致，是为了算术题不被多位数合并 token 干扰。

词表放大的直接效果是序列变短，注意力和 KV 的成本跟着下降；间接代价是 embedding 矩阵变大。§2.3 又选了 **untied embedding**，输入 embedding 和输出投影各存一份。这两件事要连着看：一边为了压缩率把 V 做大，一边为了生成质量不共享权重，等于**词表矩阵的显存付了两次**。按 $V\approx152\text{K}$ 乘 Table 1 的 hidden 估算，一份矩阵在 1.8B 上约 0.31B 参数，在 7B 上约 0.62B；untied 之后翻倍，1.8B 档光词表两端就占掉约 0.62B，接近总参数的三分之一。报告的理由只有一句 「初步实验显示效果更好」，放大词表不伤下游也只给了结论，没有给消融表。读者可以从压缩率和部署成本推断这笔交易划算，但不应假设有一张隐藏的 MMLU 对照。

站在 cl100k 上扩，而不是从零训分词器，还有一层生态考虑。直接沿用 cl100k，英文和代码切得顺，中文却碎；完全自研，又和 GPT 系工具链对不上。Qwen 取中间路线，保住与 tiktoken 接口的兼容，再把中文和多语补齐。后面 Qwen2，Qwen2.5 一直沿用大词表，起点在这里。

### 1.3. 骨架沿用 LLaMA 配方，改动都指向稳定和外推

§2.3 写得很直白：整体跟 LLaMA 的开源路线走，改五处。除了上面说的 untied embedding，其余四处是：RoPE 的逆频率矩阵用 FP32 而不是 BF16/FP16；多数层去掉 bias（跟 PaLM），但**注意力的 QKV 投影保留 bias**，理由是有助于外推（Su, 2023b）；Pre-Norm 加 RMSNorm；FFN 用 SwiGLU，中间维从 4× 收到 $\frac{8}{3}$× hidden。注意力仍是标准多头形式，没有 GQA，更没有 MLA 或 MoE。

这几处改动单独看都来自已发表的组件，合起来却指向同一个目标：在 2048 的训练窗口下，**给推理期外推留余地**。FP32 的频率表是担心低精度相位在长距离上累积误差；QKV bias 是苏剑林指出的外推友好设置；RMSNorm 和 Pre-Norm 管训练稳定。SwiGLU 的门控提高表达力，把 FFN 宽度收窄正好抵掉多出的一个投影矩阵。落到参数上：标准 FFN 是 $W_2\,\sigma(W_1x)$，两个 $d\times4d$ 矩阵共 $8d^2$；SwiGLU 是 $W_2\big(\mathrm{Swish}(W_1x)\odot W_3x\big)$，其中 $W_1x$ 过 Swish 当门，$W_3x$ 是被门控的值，逐元素相乘后再由 $W_2$ 投回 $d$ 维。三个矩阵若仍取 $4d$ 宽就是 $12d^2$，收到 $\frac{8}{3}d$ 后是 $3\cdot\frac{8}{3}d^2=8d^2$，与标准 FFN 同参数量，差别只在中间多了一次逐元素门控。所以第 2.1 节的推理期手段能起作用，有一部分功劳在这里的架构选择。

训练设定见 §2.4：上下文 2048, Flash Attention, AdamW ($\beta_1=0.9$, $\beta_2=0.95$, $\epsilon=10^{-8}$)，余弦衰减到峰值的 10%，BF16 混精。和后来直接训 32K，128K 的报告相比，这里的训练长度很克制，也没有用当时已经出现的 GQA 去压 KV cache。基础设施只点到 Flash Attention 与混精，没有并行策略，集群规模和 MFU 数字，这一面本页没有。

组 batch 的方式也写了一句：文档先打乱，再拼接，最后截成 2048 的片段。报告没有提文档边界处的注意力掩码，按这句描述，一个片段里前后两篇文档的 token 可以互相看到。这在 2023 年是常见做法，后来很多报告改为跨文档掩码。三档的 head 维度都是 128（按 Table 1 的 hidden 除以 heads 计算：2048/16, 4096/32, 5120/40），放大规模时同时加宽和加深，层数与头数一起从 24/16 增到 40/40。

不用 GQA 在当时说得通。训练和默认推理都在 2048 以内，KV cache 占的显存有限，满头 MHA 的质量更有保障。问题出在推理期把长度推到 8K，16K 时：KV cache 随长度线性增长，14B 的 40 个 KV 头全部要存，长文本服务的显存压力会很快上来。报告没有给这部分的显存数字。到 Qwen2 把 GQA 写进架构，和把训练窗口拉长是同一次调整，两件事在初代里是一起缺的。

## 2. 训练窗口外推与预训练数据

### 2.1. 训练 2048，推理 8K 以上：training-free 外推

§2.5 用了三件推理期工具。第一是 **NTK-aware interpolation**: PI 把所有维度等比压缩，高频维也被压，近距离分辨率受损；NTK-aware 改的是 RoPE 的 base，等效于高频少压，低频多压。报告只给了这句描述，没写公式；bloc97 原帖的定义是：RoPE 第 $i$ 对维度的频率为 $\theta_i=b^{-2i/d}$ ($i=0,\dots,d/2-1$)，要把长度放大 $s$ 倍时，PI 把每个 $\theta_i$ 都除以 $s$，NTK-aware 则把 base 换成
$$b'=b\cdot s^{\frac{d}{d-2}},\qquad \theta_i'=\theta_i\cdot s^{-\frac{2i}{d-2}}.$$
$i=0$ 的最高频维完全不动，保住相邻 token 的分辨率；$i=d/2-1$ 的最低频维正好被除以 $s$，和 PI 一样把远距离的相位压回训练见过的范围；中间维按指数插值。报告用的是 dynamic 版本，「按块改变 scale」：$s$ 不是固定值，而是随当前序列长度 $L$ 与 $L_{train}$ 之比变化（开源实现的取法见本段末），长度没出训练窗口时不缩放，频率表与训练时完全一致。YaRN 论文（Peng et al., 2023）里专门提到 Qwen-7B 采用了 「Dynamic NTK」。公开的 `modeling_qwen.py` 按实际序列长度计算 ntk_alpha，vLLM 后来为兼容 Qwen1 配置把它写成 $\alpha=2^{\lceil\log_2(L/L_{train})+1\rceil}-1$；这个公式出自开源实现，不在报告正文。

第二是 **LogN-Scaling** (Chiang & Cholak, 2022; Su, 2023a)。序列变长后，softmax 分母里的项变多，注意力分布会被摊平，熵随长度上升。LogN 的做法是按 「当前长度与训练长度之比」 的对数放大 logits，让熵保持稳定。报告原文写的是缩放 「query and value」 的点积；开源实现是在 RoPE 之后把位置超过训练长度的 query 乘以 $\log_{L_{train}}(pos)$，训练窗口内这一项恒为 1。两种说法落到 logits 上是同一回事，读实现以代码为准。写成式子是
$$\mathrm{Attn}(q_n,K,V)=\mathrm{softmax}\Big(\frac{\max(1,\log_{L_{train}} n)}{\sqrt{d}}\,q_nK^\top\Big)V.$$
$1/\sqrt d$ 是原有的温度；前面多乘的 $\log_{L_{train}} n$ 随位置 $n$ 缓慢增大，把 logits 之间的差距拉开，抵消分母里项数从 $L_{train}$ 涨到 $n$ 带来的摊平；$\max(1,\cdot)$ 保证窗口内的计算和训练时逐位相同，这也是 Table 3 前两列四行数字完全一样的原因。第三是 **window attention**，而且是分层的：下层对外推更敏感，用短窗；上层更稳，用长窗。

Table 3 用 arXiv 文档的 PPL 验证。裸 7B 在 16K 飙到 2645.09；加 dynamic NTK 降到 5.71；再加 LogN 到 4.62；三件齐上到 4.32. 14B 裸跑 16K 是 3168.35，全套后 3.42。这张表**证明的是语言建模不崩**，不等于长文档问答，检索，摘要都能做好，报告也只说 「超过 8192 token 仍能维持表现」。这里没有 needle 类检索测试，也没有长文 QA 基准。代价同样清楚：长度分布没有写进权重，后来 Qwen2 改为在预训练末段拉长窗口，就是换掉这条路线。

中间几列更能看出每件工具管哪一段。1024 和 2048 两列，四行都是 4.23 和 3.78，说明三件工具在训练窗口内完全不起作用，不会伤害短文本。裸模型在 4096 就已经崩到 39.35, 8192 是 469.81，刚出窗口两倍就不能用。Dynamic NTK 单独就把 4096 和 8192 拉回 3.59 和 3.66，是主力；LogN 在 8192 再降到 3.56，window attention 降到 3.49。后两件的作用主要在 16K 这种更远的长度上显现。14B 同样如此，4096 从 22.79 降到 3.29, 8192 从 334.65 降到 3.18。

同一时期的另一条路是 Code Llama 的做法：手动把 RoPE base 提到 1M（后来被称为 ABF, adjusted base frequency），再用长序列继续训练，让模型真正见过长距离的位置。YaRN 论文把两者都归入 NTK 一族，区别在于要不要训练。Qwen 初代选了不训练的一支，好处是底座发布时不用多付一轮长序列算力，用户在配置里打开 `use_dynamic_ntk` 和 `use_logn_attn` 就能用；坏处是外推质量取决于推理框架是否实现了这两个开关，vLLM 直到后来才补上对 Qwen1 这两项配置的支持。

### 2.2. 清洗流水和评测污染写在同一处

§2.1 的数据来源是公开网页，百科，书籍，代码，以英中为主。流水包括 HTML 抽取，语种识别，精确去重与 MinHash+LSH 模糊去重，规则加模型打分过滤，人工抽检，以及对部分来源选择性上采样。预训练里还掺了高质量指令数据，用来抬 zero-shot 和 few-shot 表现。这在 2023 年并不少见，但会直接影响后面基座评测的含义：基座的对话格式感和答题习惯，有一部分是预训练阶段就学到的。

报告的应对是用 13-gram 重叠剔除与评测集撞车的指令样本，做法仿 GPT-3 (Brown et al., 2020). 13-gram 只能抓字面重合，改写过的题目抓不到；报告没有给出剔除比例，也没有给出去污染前后的分数对照，这一面本页没有。因此读 Table 2 时要记得这份底座不是 「纯网页预训练」，同时要知道**去污染只做到字面层**。

Table 2 的横比里，Qwen-14B 的 MMLU 66.3, C-Eval 72.1, GSM8K 61.3, MATH 24.8, HumanEval 32.3. C-Eval 明显高于 LLaMA2-70B 的 50.1，MMLU 仍低于 LLaMA2-70B 的 69.8。这种形状正是语料配比和词表选择的结果：中文知识密度高，英文知识题靠参数量。附录 A.2.1 按 OpenCompass 把考试，语言，知识，理解，推理分类摊开，可以看到优势主要集中在中文考试类。数学和代码两项的基座分数不高，GSM8K 与 HumanEval 都明显低于后面专项分支和 Chat 版本，这也提示通用预训练阶段的代码与数学比例有限，专项能力要靠第 4.2 节的继续预训练和指令数据补上。报告没有公布预训练各类数据的具体比例，读者只能从分数形状反推，不能当成已知配比。

Table 2 的评测协议是 MMLU 5-shot，C-Eval 5-shot，GSM8K 8-shot，MATH 4-shot，HumanEval 0-shot，BBH 3-shot；MBPP 在表头写 3-shot，正文写 0-shot，两处不一致，读时以表为准并留意这个出入。对照模型的分数取自各家官方结果和 OpenCompass，不是统一重测，横比时 prompt 和解码设置未必对齐。报告说 14B 在三项上超过 LLaMA2-70B，逐列对照是 C-Eval（72.1 对 50.1），MATH（24.8 对 13.5），HumanEval（32.3 对 29.9）；GSM8K（61.3 对 63.3），MBPP（40.8 对 45.0），BBH（53.4 对 64.9）仍然落后，BBH 差距最大。

小档的数字同样有意思。7B 为 MMLU 58.2，C-Eval 63.5，GSM8K 51.7，HumanEval 29.9，超过 LLaMA2-13B，和 Baichuan2-13B 相当。1.8B 的 C-Eval 是 54.7，已经高于 LLaMA2-70B 的 50.1，MMLU 却只有 44.6。同一个模型在中英两套考试上相差 10 分，比任何一句叙述都更直接地说明了语料和词表的偏向。

## 3. 对齐：SFT，奖励模型与 PPO

### 3.1. SFT: ChatML 格式与 loss mask

§3.1 的 SFT 用 **ChatML** 区分 system，user，assistant，只对 assistant 部分计算 loss。序列 2048，batch 128, 4000 step，前 1430 step 线性 warmup 到峰值学习率 $2\times10^{-6}$；weight decay 0.1，dropout 0.1，梯度裁剪 1.0. warmup 占总步数三分之一以上，学习率又比预训练低两个数量级，加上 dropout，这组设置的意图很明确：SFT 数据量小，最大的风险是过拟合和冲掉预训练知识。附录 A.1.1 解释为什么不用 「Human: / Assistant:」 这类自然语言分隔：常见词容易和正文撞车，特殊 token 的边界更干净。这条格式后来成了 Qwen 各代 chat template 的基础，很多第三方微调框架也直接支持。

ChatML 的关键在于 `<|im_start|>` 和 `<|im_end|>` 两个特殊 token 从未出现在预训练语料里。预训练阶段掺过指令数据，如果 SFT 继续用自然语言分隔符，模型很难区分 「这是对话结构」 还是 「这是正文里恰好出现的词」，多轮对话里还可能被用户输入伪造角色。**专用 token 把结构和内容分开**，loss mask 再保证模型只学习 assistant 的输出，两者一起才让多轮对话的边界稳定。后面 PPO 和工具调用都建立在这个边界之上。

数据侧，报告仿照 InstructGPT 标注 「人类风格的对话」，不用传统数据集里 「问题，指令，答案」 的固定写法；排除了会限制泛化的固定 prompt 模板；安全标注覆盖暴力，偏见和色情内容；并强调多样性。SFT 数据总量和来源比例没有公布，这一面本页没有。和后面的 RLHF 对照，SFT 在这里的定位是 「先把对话格式和基本服从做对」，泛化和创造性交给奖励模型与 PPO。报告自己也写了一句：SFT 的泛化与创造能力有限，容易过拟合。

### 3.2. 奖励模型先预训练，PPO 再加预训练梯度

§3.2 的奖励模型分两步。第一步是 **preference model pretraining** (PMP, Bai et al., 2022b)：在大量成对比较数据上先学 「两条回复哪条更好」 的通用特征。第二步在更高质量的标注比较对上微调。为了让 prompt 分布足够宽，团队建了约 6600 个细粒度标签的分类体系，用兼顾多样性与复杂度的均衡采样挑 prompt；回复由不同规模的 Qwen 模型用不同采样策略生成，回复越多样，标注越容易分出高下。奖励模型用同规模 Qwen 初始化，加 pooling 层输出标量。Table 4 显示 PMP 模型在外部 OOD 集上泛化较好，微调后的 RM 在自家 Helpful 集上更高，并非对所有外部集都更好。

RM 训练的超参是常数学习率 $3\times10^{-6}$，batch 64，序列 2048，只训 1 个 epoch，pooling 层取特定结束 token 位置的表示输出分数。Table 4 逐项看：自家 Helpful-base 从 PMP 的 62.68 升到 RM 的 74.78，Helpful-online 从 61.62 升到 69.71；Anthropic Helpful-base 却从 76.52 降到 73.98，Helpful-online 从 65.43 降到 64.57；OpenAI 摘要，Stanford SHP，PRM800K 三项基本持平。两个自家集的区别是 base 的回复来自未做 RLHF 的 Qwen，online 的回复来自做过 RLHF 的 Qwen，后者更难分。微调让 RM 贴近自家分布，代价是外部分布上略有退化，报告说准确率是 「重要但不唯一」 的指标。

PPO 阶段用 policy，value，reference，reward 四个模型。开训前先冻结 policy，单独更新 value 50 step，让价值估计先对上奖励分布。每个 query 同时采两条回复，KL 系数 0.04，奖励按滑动均值归一化。这两项作用在同一个标量上：报告没写式子，按 InstructGPT 系 PPO 的标准写法，policy 优化的是
$$R(x,y)=\tilde r_\phi(x,y)-\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)},\qquad \beta=0.04,$$
$\tilde r_\phi$ 是 RM 分数按滑动均值归一化后的值（报告只说 running mean，是否再除标准差没写），让奖励的零点跟着训练漂移，value 模型不用追一个不断抬高的基线；第二项是 policy 相对 SFT 参考模型的对数概率比，$\beta$ 越大越不许偏离 SFT。下文说 「KL 惩罚已经足以保护常识」，指的就是这一项。policy 与 value 学习率分别为 $1\times10^{-6}$ 和 $5\times10^{-6}$，value loss 裁剪 0.15。采样 top-p 设为 0.9，报告观察到熵比 top-p=1.0 略低，但奖励涨得更快，最终评测奖励更高。这类细节在 2023 年的公开报告里少见，对复现很有用。

最后一块是 **pretrained gradient**，用来压 alignment tax。它和 InstructGPT 的 PPO-ptx 同源，社区通常写成 $g=g_{PPO}+\gamma\,g_{pretrain}$。报告给的经验是：在这个奖励模型下，KL 惩罚已经足以保护常识，阅读理解类基准，代码和数学才需要预训练梯度出手；预训练数据量必须远大于 PPO 数据；$\gamma$ 太大会拖住对奖励的拟合，太小又几乎没用。$\gamma$ 的具体取值没有公布。Qwen 团队 2024 年的 Online Merging Optimizer 论文继续沿这条线，把 SFT 与预训练模型的参数差并进 RLHF 每一步的梯度方向，可以看作对同一问题的后续回答。

人评用 300 条中文指令，对比 7B-SFT, 14B-SFT, 14B-RLHF, GPT-3.5, GPT-4. Figure 4 显示 RLHF 相对 SFT 胜率明显更高，仍落后 GPT-4. Table 5 的自动评测里，14B-Chat 在开源同档整体领先，HumanEval 43.9 比基座高出一截。报告承认传统基准难以刻画对齐后的对话模型，所以人评和自动评要分开读。

Table 5 同时报零样本和少样本，用来看指令遵循。14B-Chat 的 MMLU 零样本 64.6, 5-shot 66.5；C-Eval 69.8 和 71.7；GSM8K 零样本 60.1 反而高于 8-shot 的 59.3；BBH 零样本 46.9, 3-shot 58.7，差了近 12 分。BBH 的题型格式特殊，没有示例时模型不容易按要求的格式作答，所以零样本差距最大。和基座对比，5-shot MMLU 从 66.3 到 66.5，C-Eval 从 72.1 到 71.7，对齐几乎没动知识；HumanEval 从 32.3 到 43.9，对齐阶段的代码指令数据作用明显。人评方面，每条指令由 3 名标注者按有用性，信息量，正确性等综合排序，GPT-3.5 和 GPT-4 取自 0613 版 API。

附录 A.2.2 用 Elo 列出同一问题下 7B-SFT，14B-SFT，14B-RLHF 的回复，可以看出 RLHF 改的是什么（以下为读附录案例的归纳）。问北京大学的前身，SFT 版本一两句答完，RLHF 版本补上京师大学堂的学科设置和 1912 年改名；问应县木塔也类似。RLHF 回复更长，更完整，更像 「解释给人听」。这正是奖励模型学到的偏好，也解释了为什么人评胜率明显上升，而知识类自动评测变化不大：知识本身来自底座，对齐改的是表达。

## 4. 工具与专项分支

### 4.1. 工具与 Code Interpreter：同一权重上混训

§3.4 的 agent 数据用 **self-instruct** 生成：给 Qwen 几个 ReAct 格式的示例，让它自己造 query 和按格式作答，规则加人工过滤后并入训练集，再用更新后的模型重复这个过程。最终留下约 2000 条高质量样本，和通用 SFT 数据混在一起训，不单开阶段，以免冲掉通用对话能力。这个取舍决定了 Qwen-Chat 是同一套权重既聊天又调工具，而不是另起一个 agent 专用模型。

评测分三条。ReAct 调用未见过的插件，Table 6 上 7B 和 14B 选工具准确率到 98，误报率（不该调却调了）从 1.8B 的 19.3 降到 14B 的 2.4；GPT-3.5 在这个偏中文的基准上误报 75.0，报告归因于它倾向 「至少调一个工具」。作者自己也说这个基准可能偏易。Code interpreter 拆成可执行率（Table 7）和正确率（Table 8）：14B 可执行 All 81.7，可视化正确率 All 56.4，两个数之间的差说明 「代码能跑」 不等于 「结果对」。

可视化题要先读 CSV 结构再写绘图代码，考的是多步规划。Code Llama-Instruct-13B 的数学可执行率可以到 93.2，Vis.-Hard 正确率却只有 27.4，Qwen-14B-Chat 是 53.6；Figure 5 的案例显示 Code Llama 常按文件名臆造列名。判断可视化结果是否正确时，报告用 Qwen-VL 看图打分，多模态支线在这里变成了评测器。数学题的正确性要求标准数值答案同时出现在代码执行结果和最终回复里，只算对不说出来，或者说出来但代码没算出来，都不算。

ReAct 基准的设置是从最多 5 个候选插件里选一个，训练集里出现过的插件全部从评测集剔除。Hugging Face Agent 基准（Table 9）分 Run Mode 和 Chat Mode: Run Mode 下 14B 的工具选择 93.5，代码正确率 87.0，GPT-4 是 100 和 97.4；Chat Mode 下 14B 工具选择 97.9，和 GPT-4 持平，代码正确率 95.5 对 98.5。小档的短板在代码正确率，1.8B 的 Run Mode 只有 61.1. Table 7 还有一个反常：General 类可执行率 14B 是 65.5，低于 7B 的 67.2，报告没有解释。

读这些表时，要把 ReAct 格式遵循，工具选择，入参质量，误报四件事拆开看。选工具准确率很快到顶，说明这项已经不是瓶颈；误报率随规模下降，说明大模型更敢判断 「这次不需要工具」；入参质量用 Rouge-L 衡量，提升幅度小于选择准确率。一个 Acc 概括不了 agent 能力。报告的贡献在于把 2023 年散落在 demo 里的工具能力收成可复现的混训配方和公开基准，后来的 Qwen-Agent 仓库沿用了这套评测做法。

### 4.2. 代码线继续预训练，数学线直接 SFT

§4 的 Code-Qwen 从 Qwen 基座**继续预训练**约 90B token，上下文拉到 8192，服务工具调用和代码解释这类长上下文场景。14B 学习率 $6.0\times10^{-5}$，7B 为 $3.0\times10^{-5}$，3% warmup，不衰减。之后做多阶段 SFT 得到 Code-Qwen-Chat。这条路线对齐 Code Llama：从混过文本和代码的通用底座继续训，比只在代码上从零预训练更能保住自然语言接口。Table 10 到 11 里，Code-Qwen-Chat-14B 的 HumanEval 66.4，HumanEvalPack 均分 51.9，在同档开源里很强，仍低于 GPT-3.5 的 73.2 与 GPT-4 的 86.6。

§5 的 Math-Qwen-Chat 不做数学继续预训练，直接在增强过的数学指令数据上 SFT。序列 1024，峰值学习率 $2\times10^{-5}$，50000 step，**对 system 和 user 做 mask**，理由是考题输入格式高度重复，模型容易背题干。Table 12 里 14B 的 GSM8K 69.8, MATH 24.2, Math401 85.0, Math23K 78.4. Math401 与 Math23K 分别测算术和中文小学应用题，避免只用英文竞赛题概括 「数学能力」。

Code-Qwen-Chat 的 SFT 是多阶段的，报告说经过一系列实验后多阶段效果最好，但没有说分几段，每段用什么数据。学习率 14B 为 $2.0\times10^{-6}$，7B 为 $1.0\times10^{-5}$，余弦 warmup 3% 后保持常数。大模型用小五倍的学习率，和继续预训练阶段 「14B 学习率更大」 正好相反，报告没有解释。Table 11 的 HumanEvalPack 里有一个反常值：Code-Qwen-14B 基座的 C++ 只有 18.2，低于通用 Qwen-14B-Chat 的 24.4；做完 SFT 的 Code-Qwen-Chat-14B 升到 54.2。继续预训练的代码语料可能偏 Python 和 Java（Java 从 42.7 升到 57.3），多语言能力主要是在 SFT 阶段补上的。Rust 在所有开源模型上都偏低，Code-Qwen-Chat-14B 也只有 28.7。

Table 12 用 greedy 解码，MATH 用 Lightman et al. 的测试子集。Math-Qwen-7B-Chat 的 MATH 17.2 高于 Minerva-8B 的 14.1; 14B 的 GSM8K 69.8，MATH 24.2，在追 Minerva-62B (52.4, 27.6) 和 GPT-3.5 (80.8, 34.1)。算术和中文题上反超：Math401 85.0 高于 GPT-4 的 83.5，Math23K 78.4 高于 GPT-4 的 74.0。同档开源对照 GAIRMath-Abel-13B 是 66.4 和 17.3，Math-Qwen-14B 两项都更高。通用 Qwen-14B-Chat 本身是 60.1 和 18.4，数学 SFT 在 GSM8K 上加了近 10 分，MATH 上加了约 6 分。

两条线的经济学不同。代码对话同时服务补全，调试，解释和工具，分布杂，需要长上下文，所以付得起继续预训练和多阶段 SFT。数学以解题轨迹为主，序列短，mask 掉题干后监督信号干净，单阶段 SFT 就够。这一分岔后来分别长成 Qwen2.5-Coder 和 Qwen2.5-Math，前者继续走大规模代码继续预训练，后者在 SFT 之外加了奖励模型和 RL，但分岔的形状在初代报告里已经定下。

## 5. 读分与边界

### 5.1. 各部件怎样落到分数上

把前面几节串起来，可以给 Table 2 到 Table 12 的主要数字各找一个来源。C-Eval 72.1 高于 LLaMA2-70B，对应中文语料比例和 152K 词表：同样 2048 窗口里，中文题能装进更多上下文，中文知识密度也更高。MMLU 66.3 仍低于 LLaMA2-70B，对应参数量差距，这是中档路线主动接受的代价。基座的 zero-shot 表现不错，有一部分来自预训练里掺入的指令数据，这一点要和 13-gram 去污染一起读。

Table 3 的 16K PPL 从 2645.09 降到 4.32，功劳分在推理期三件工具和架构里的 FP32 频率表，QKV bias 上。人评里 RLHF 胜过 SFT，对应 PMP 加 6600 标签采样训出的奖励模型；常识和阅读理解没有明显掉分，对应 KL 惩罚，代码和数学靠预训练梯度兜底。Table 6 到 Table 9 的工具表现，对应 2000 条 self-instruct 样本和通用 SFT 混训。Code-Qwen 的 HumanEval 66.4 对应 90B token 继续预训练，Math-Qwen 的 GSM8K 69.8 对应数学指令 SFT 和题干 mask。这样读，**每个数字都有归属**，不会把中文考试的优势说成全面领先，也不会把人评落后 GPT-4 说成底座不行。

### 5.2. 读这份报告时的边界

这份报告把底座，Chat，工具，代码，数学五块放在一份文档里，每块都给了可复现的超参，这是它在 2023 年的价值。它没有给的东西也要记住：没有 Scaling Laws 拟合，没有词表和 untied embedding 的消融表，没有去污染前后的分数对照，没有长文 QA 基准，没有训练集群与吞吐数据。人评只有 300 条中文指令，工具基准作者自认偏易，Figure 2 的雷达图在同规模上领先前代开源 13B，仍落后 GPT-3.5 与 GPT-4。

放到谱系里看，Qwen 初代接住的是 LLaMA 立下的 decoder-only + RoPE + SwiGLU + SFT/RLHF 配方，交出的是中英语料，152K 词表，推理期外推组合，ChatML，以及工具，代码，数学三条产品线。下一代 Qwen2 (arXiv:2407.10671) 换掉的部件很具体：注意力换成 GQA，长上下文从推理期补丁改成预训练末段拉长窗口加 YaRN 与 DCA，规模扩到 0.5B 和 72B 并开出 MoE 线。没换的是大词表，QKV bias，ChatML 和 「底座 + 专项分支」 的产品形状。对照 `qwen-bi.md` 的页标记，可以把本文任一数字回溯到 Table 1 到 Table 12 的原格。
