# Doubao-1.5-pro: 稀疏 MoE, 训练-推理一体, 和 1.5 代所有分支的起点

来源: 同目录 `pro.md` (MinerU 抽取, 12 页, 8 张图), 字节跳动 Seed 团队 2025.01.22 发布的中文产品页. 中英对照稿见 `pro-bi.md`. 数字回到源 md 与图片核对; 从柱状图, 曲线图上目测读出的数值标 「约」 或 「读图」.

## 1. 为什么这一代是分叉点

Doubao-1.5-pro 是一份产品页, 不是论文, 但它交代的技术面比很多技术报告还宽: MoE 结构与稀疏度 Scaling Law, 参数动态调整, 四象限推理系统, 不用其他模型数据的后训练, 自研 Doubao ViT, Speech2Speech 语音框架, 以及一张深度思考模式的 AIME 小图. 页面没有印出专家数, 每 token 激活的专家数, 总参数量, 激活参数量, 层数和上下文长度. 这些缺口决定了哪些结论能在页内核对, 哪些只能照单记录.

把后面的家族成员放回来看, **这一页是 1.5 代所有分支的起点**. 三个月后的 Seed1.5-Thinking 用 Doubao-Pro 1.5 清洗 STEM 题, 沿用它的 RL prompt, 偏好数据和 SFT 数据; 页上的 「深度思考模式」 (型号 AS1-Preview) 就是那条推理线的预告. 再过一个月的 Seed1.5-VL 走的是另一条视觉路线, 编码器换成了 532M 的 Seed-ViT. 同一天发布的 Doubao-1.5-lite 在发布推文里只拿到一段话. 所以读这一页, 要同时看它自己做了什么, 以及哪些做法在后代里被展开, 哪些被换掉.

## 2. 结构与推理系统

### 2.1. 稀疏度 Scaling Law 与 7 倍性能杠杆

页 2 给出的设计出发点是训练和推理效率: 用稀疏 MoE, 预训练阶段只激活较少参数, 性能即可超过 Llama3.1-405B 这类超大稠密模型. 团队称通过 **「稀疏度 Scaling Law」** 的研究确定了性能与效率平衡的稀疏比例, 再根据 MoE Scaling Law 确定小激活量即可达到一流性能. 这两条定律页上都没有公式和拟合参数, 稀疏比例也没有数值. MoE 的一般机制见 [MoE 模型](../../../../llm-guide/2-核心原理与架构/2.4-前沿架构与变体/2.4.1-混合专家模型MoE/2.4.1-混合专家模型MoE.md), Scaling Laws 的一般形式见 [Scaling Law](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.6-Scaling-Law/3.2.6-Scaling-Law.md).

页 3 定义了 **「性能杠杆」**: 表现相同的稠密模型总参数量, 除以 MoE 模型的激活参数量. 例子是 IBM Granite, 800M 激活的 MoE 接近 2B 总参数的稠密模型, 杠杆约 2.5 倍. 页面说业界普遍 「不到 3 倍」, Doubao 在完全相同的部分训练数据 (9T token) 下, 用激活参数仅为稠密模型 1/7 的 MoE 超过了稠密模型, 杠杆到 7 倍. 对照条件做得干净: 同数据, 同 token 数. 缺的是绝对量: 稠密模型多大, MoE 激活多少, 页面都没印, 7 倍成了页内无法复算的比值. 判定标准也不对称, Granite 写的是 「接近」, Doubao 写的是 「超过」, 两者用 loss 对齐还是下游基准对齐, 页面没说.

两张训练图给出两种 「表现相同」 的读法. 页 3 的 loss 图横轴画到约 8T (读图), 比正文的 9T 短; 前约 1.4T MoE 的 loss 略高于稠密, 之后低于稠密, 2T 到 3T 差距最明显, 7T 以后两线基本重合, 末端都在约 1.60 (读图). 页 4 的柱图以 Doubao-Dense 为 100%, MoE 依次是 GPQA 110.4, MMLU_PRO 107.5, BBH 100.2, MBPP 100.0, MATH 96.4, MMLU 99.2, AGIEval 100.4; 七项简单平均约 102.0, 去掉 GPQA 和 MMLU_PRO 后约 99.2. 所以 **「略优于」 主要来自两项知识类任务, 数学是 MoE 落后最多的一项**. 同图的 Llama3.1-405B 用 15T token 的最终结果对比 Doubao 9T 的中间结果, 页面据此推出 「数据质量和训练超参更优」, 但参数量, token 数, 数据分布三样同时不同, 这个推断分不出是哪个因素.

7 倍杠杆换成算力更好理解. 训练算力大致按 6 × 激活参数 × token 数计, 同样 9T token, 激活参数为稠密模型 1/7 的 MoE, 主干的训练 FLOPs 也约为稠密模型的 1/7, 路由和 attention 的差别先不计. 推理时每个 token 的计算量同样约为 1/7. 但 MoE 的总参数远大于激活参数, 所有专家都要放在显存里, 推理的瓶颈因此从 「算得动」 转到 「放得下, 读得快」. 这正是下一节四象限推理系统要处理的问题: **省下的是计算, 多出来的是访存和通信**, 训练-推理一体指的就是在设计稀疏度时把后者也算进去.

loss 曲线前 1.4T MoE 略高, 也有常见的解释. MoE 训练初期路由还没分化, 各专家分到的 token 少, 每个专家的有效训练量低于同期的稠密模型; 路由稳定后, 总参数更多的优势才显现, 这时 MoE 的 loss 反超. 7T 以后两线重合, 说明在这个数据量上, 1/7 激活的 MoE 与 7 倍参数的稠密模型学到的东西差不多, 优势主要在训练前中期. 页面没有给 9T 以后的曲线, 只说完整训练后的 MoE 比 9T 中间版本 「有更大提升」, 稠密模型是否也继续训, 没写.

### 2.2. 训练-推理一体: 模型大小本身是可调旋钮

页 2 把设计哲学叫 **「训练-推理一体」**: 从预训练开始就把推理成本算进模型设计, 在最强性能和最优推理成本之间取平衡. 页 4 最后一段给出具体手段: 在预训练模型基础上, 从深度, 宽度, MoE 专家数, 激活专家数, 隐藏 token 推理等维度对参数扩增或缩小, 按应用挑能力与成本的平衡点. 这是页上唯一提到专家数和激活专家数可调的地方, Doubao-1.5-pro 本身的取值仍然没有. 反过来说, 同名 Doubao-1.5-pro 在不同产品线上可能对应不同配置, 页 2 与页 7 的基准数属于哪一个, 页面没说.

这句话里混着两类旋钮. 深度, 宽度, 专家数这些在部署前决定模型有多大, 属于 Scaling 一侧; 「隐藏 token 推理」 只出现一次, 字面上像是在输出前生成不展示给用户的中间 token, 用推理时的额外算力换能力, 属于 TestingTime 一侧. 页面把两类放在同一句里, 可见团队把 「部署前定大小」 和 「推理时加算力」 都当作能力与成本的调节手段. 段末还有一句组织层面的理由: 较小的预训练模型让迭代更快, 能同时支持多条产品线. 这和 1.5 代同时放出 pro, lite, vision-pro, 语音模型的节奏对得上.

### 2.3. 推理系统: 四个象限各用一套办法

页 5 的**四象限**图把推理拆成 Prefill/Decode 两个阶段, Attention/FFN 两类算子. 图上标注: Prefill Attention 「计算瓶颈, 多 chunk 不平衡」; Prefill FFN 「强计算瓶颈」; Decode Attention 「单 batch 内多 query 不平衡, 需适配 SpecDecode」; Decode FFN 「强访存瓶颈」. 页 4 称 Doubao-1.5-pro 是 「高度稀疏的 MoE」, 四个象限计算与访存特征差异大, 所以用异构硬件加不同低精度策略分别处理, 目标是兼顾 TTFT 和 TPOT, 提升吞吐, 降低总成本.

Prefill 一侧放在计算访存比高的设备上, 做 **Chunk-PP Prefill Serving**, 线上 Tensor Core 利用率接近 60%. Attention 用 MMA/WGMMA 指令扩展开源 FlashAttention 的 8-bit 实现, 配合 **Per N tokens Per Sequence 量化**; 再通过建模不同长度分片的耗时加动态**跨 Query Batching**, 消除卡间负载不均. FFN 用 **W4A8** 量化降低稀疏专家的访存, 靠跨 Query Batching 给 FFN 更多输入, MFU 提到 0.8. 两个数口径不同, 60% 是 Prefill 系统的 Tensor Core 利用率, 0.8 是 FFN 阶段的 MFU. 图上 Prefill FFN 标计算瓶颈, 正文却说 W4A8 降访存, 两者能对上: 稀疏专家各自分到的 token 少, 不 batching 时会退回访存受限, 跨 Query Batching 才把它推回计算一侧. FlashAttention 见 [FlashAttention](../../../../llm-guide/2-核心原理与架构/2.3-高效与稀疏注意力/2.3.1-硬件高效注意力/01-FlashAttention/01-FlashAttention.md), 权重量化见 [权重量化](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/6.3.1.1-权重量化.md).

Decode 一侧放在计算访存比较低的设备上换 ROI, 配合低成本 Sampling 和 Speculative Decoding 降 TPOT. Attention 用 TP 部署, 用启发式搜索和激进的长句拆分处理同一 batch 内 KV 长度差异大的情况, 并保证随机采样中 KV Cache 只访问一次; FFN 保持 W4A8, 用 EP 部署. 系统层还有三项: 定制 RPC Backend 用零拷贝, 多流并行优化 PD 分离下的 KV Cache 传输; Prefill 与 Decode 集群按角色各自做 HPA 弹性扩容; GPU 算第 N 步时 CPU 提前发射第 N+1 步 kernel. 页 6 又补了自研服务器集群支持低成本芯片, 定制网卡与自研协议优化小包通信, 算子层计算通信 Overlap. 整节没有端到端延迟, 吞吐或单价.

几个名词背后的机制可以按常见做法补全 (以下是读法, 页上只有名词). Chunk-PP 利用的是页面自己点出的 「单向注意力」: 长 prompt 切成若干块, 每块只看自己和前面的块, 于是可以像流水线一样, 第一块在后面的设备上算的同时, 第二块已经进入前面的设备. 问题是越靠后的块要看的前文越长, attention 耗时越大, 各块不等长, 流水线就会空转, 这就是图上 「多 chunk 不平衡」 的意思, 页面给的对策是先建模不同长度分片的耗时, 再把多个请求的块动态拼进同一批. Per N tokens Per Sequence 量化字面上是每条序列里每 N 个 token 共用一个缩放系数, 比整张量一个系数更细, 能吸收不同位置之间的数值差异, 页面说它让 8-bit attention 在不同架构 GPU 上 「无损」, 但没给精度对照.

Decode FFN 为什么是 「强访存瓶颈」, 可以粗算 (硬件参数取 H800 一类 GPU 的量级, 页面没说用什么卡). 一个专家的 FFN 在 decode 时对 b 个 token 做矩阵乘, 计算量约 2·b·d·d_ff, 权重按 4-bit 存, 读取量约 0.5·d·d_ff 字节, 计算访存比约 4b FLOPs/字节. 这类 GPU 的 8-bit 算力与显存带宽之比在 300 FLOPs/字节量级, 要打满算力, 每个专家一次要分到约 75 个 token. 高度稀疏的 MoE 里, 每个 token 只去少数几个专家, 一个 batch 摊到每个专家头上往往只有个位数到十几个 token, 离 75 差得远. 所以 decode 侧的办法都是在 「少读」 和 「多攒」: W4A8 让权重读取量比 8-bit 再减半, EP 把各卡上去同一专家的 token 汇到一处, 跨 Query Batching 在 prefill 侧做的也是同一件事. 投机解码见 [投机解码原理与应用](../../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/01-投机解码原理与应用.md), PD 分离见 [SGLang 与 Prefill-Decode 分离](../../../../llm-guide/9-AI工程化与基础设施/9.4-推理服务框架/9.4.1-SGLang与Prefill-Decode分离.md).

## 3. 数据与后训练

### 3.1. 数据: 预训练几乎空白, 后训练强调独立

预训练数据这一面页上几乎没有. 能读到的只有对照实验停在 9T token, loss 图画到约 8T; 完整训练的 token 总数, 语料来源, 配比, 学习率, batch 大小, 专家负载均衡方法都没提. 页 4 用 Llama 对比推出 「数据质量和训练超参更优」, 是唯一一句关于预训练数据质量的判断, 而上一节已经说过它的对照条件不足以支撑这个推断.

后训练数据的立场写得很重. 页 6 说 PostTraining 阶段建了一套高度自主的数据生产体系, 标注团队与模型自提升技术结合, 「不使用任何其他模型的数据」; 页 10 深度思考模式又重复一次. 这句话在 2025 年初有明确的背景: 当时社区对不少模型用 GPT-4 类模型蒸馏数据多有议论, 字节在这里公开划了一条线. 页面无法验证这条声明, 引用时应写明是官方说法. 视觉部分还提到预训练数据除了搜索引擎的海量图文对和图文交织数据, 还用渲染引擎, 传统计算机视觉模型和模型自迭代合成数据, 这是页上唯一具体到来源的预训练数据描述.

### 3.2. 后训练: Seed1.5-Thinking 的零件在这里已经露面

SFT 阶段有一套算法驱动的训练数据优化系统, 覆盖多样性优化与 「精确人题匹配」 (字面上是把题目派给合适的标注员, 页面没解释), 结合模型自演进 (Self-evolve) 提升标注的多样性和难度. Reward Model 部分列了一条数据生产 pipeline: prompt 分布优化, response 筛选, 多轮迭代, active learning; 融合同等规模的合成与挖掘数据来规避数据冲突和 pattern hacking; 多阶段 RM 训练; 基于梯度筛选和迭代过滤, 用 25% 的数据达到近似全量的效果; 把 Verifier 和 Reward Model 融合成**统一的 Reward 框架**; 提出**生成式 RM**, 称在 OOD 泛化和 reward hacking 防御上显著提升. 奖励模型路线的背景见 [基于奖励模型的 RL](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/4.4.1-基于奖励模型的RL-RLHF-PPO.md).

RL 阶段基于 veRL 打造多角色训练推理一体框架, 兼容不同类型的数据和奖励方式; 用自适应数据分布调节机制解决多任务训练冲突; 攻克价值函数训练难点, 实现 token-wise 稳定建模, 收敛速度提升 4 倍, 高难度任务性能提升超过 10 个绝对点; 用对比学习方法缓解 reward hacking. 把这段和 Seed1.5-Thinking 对照, 几乎每一条都能找到后者的对应: 统一 Reward 框架对应 「验证器 + 成对生成式奖励」, 自适应数据分布对应 Online Data Distribution Adaptation, 价值函数的 token-wise 稳定建模对应 Value-Pretraining 与 Decoupled-GAE 这条 actor-critic 路线, veRL 是 HybridFlow 的开源实现. **产品页只给结论, 三个月后的报告才给出机制**. PPO 本身见 [PPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md).

这一节的三个数字都没有对照基线. 25% 相对哪个全量集, 「近似」 差多少; 4 倍相对哪种价值函数训练方式; 10 个绝对点落在哪些任务, 页面都没有交代. 页面还说借鉴字节在推荐, 搜索, 广告上的 AB Test 经验, 用豆包的大规模用户反馈建了从问题发现, 数据挖掘, 人机结合标注到快速迭代的闭环, 即**用户数据飞轮**. 这些是流程描述, 页内没有可核对的实验. 社区讲这一代时常把 「用户反馈闭环」 当作字节的特殊资源, 这一点页面确实写了, 但它贡献了多少分, 页面没有.

奖励模型那一串做法各自针对一种已知的失败方式, 按常见机制可以这样对应 (读法). 「同等规模的合成与挖掘数据」 是在防奖励模型学到数据来源的指纹: 若合成数据多是某种格式, 挖掘数据多是另一种, 奖励模型可能只学会分辨格式, 页面称之为 pattern hacking. 「梯度筛选」 通常指按样本梯度与目标集梯度的相似度挑数据, 只留对目标能力真正有贡献的样本, 25% 数据接近全量效果正是这类方法常报的结论形态. 生成式 RM 让奖励模型先写判断再给结论, 与三个月后 Seed1.5-Thinking 的 Seed-Thinking-Verifier 和成对生成式奖励是一条线. 「对比学习缓解 reward hacking」 页面只有一句, 具体是对比什么, 无法推断.

视觉后训练里 **「去除长度偏好的 RM 训练集」** 针对的是奖励模型最常见的偏差: 标注员和模型裁判都倾向于给更长的回答打高分, RL 于是学会越写越长. 构造训练集时让偏好与长度脱钩, 比如同样质量的长短回答各占一半, 或者短而准确的回答胜过长而冗余的回答, 奖励模型就不能靠长度拿分. 页面给出的目标是 「准确, 实用的前提下保持简洁」, 与页 6 说视觉回复模式 「更加精简, 友好」 呼应. 这和 Seed1.5-VL 标注前先做长度均衡过滤是同一类处理.

## 4. 视觉与语音

### 4.1. 视觉: Doubao ViT, 原生动态分辨率和偏 RL 的后训练

页 6 说相比上一版本, 视觉在多模态数据合成, 动态分辨率, 多模态对齐, 混合训练上都有提升, 并把视觉理解融进同一模型. 页 7 的小节标题是 「高效的原生动态分辨率训练」: 支持任意分辨率和极端长宽比的输入, 称文档识别和细粒度识别提升明显. 自研 **Doubao ViT** 正文写 「仅凭 2.4B 规模便在综合评分上取得 SOTA, 超越 7 倍于自身规模的模型」; 页 8 表格的参数一格却印成 24B. 按 2.4B 算, EVA-CLIP-18B 的 17.5B 约是它的 7.3 倍, 与正文吻合, 所以**表格那一格是漏了小数点**. 视觉编码器的一般做法见 [CLIP 与视觉编码器](../../../../llm-guide/8-多模态/8.2-CLIP与视觉编码器/01-CLIP与视觉编码器.md), 高分辨率输入的难点见 [高分辨率 VLM 的技术挑战](../../../../llm-guide/8-多模态/8.2-视觉语言模型/8.2.4-高分辨率VLM的技术挑战.md).

ViT 表内 6 个分类任务里, Doubao ViT 在 ImageNet-V2 (78.5), ImageNet-A (87.8), ObjectNet (82.5) 三项第一, ImageNet-1K 84.3 与 DFN5B-CLIP-H/14+ 打平, ImageNet-R 和 ImageNet-S 各低 0.3 和 0.1; AVG 83.9 比 EVA-CLIP-18B 的 83.6 高 0.3. **SOTA 成立, 领先很窄**. 训练侧的信息有三条: 针对动态分辨率的前向, 反向负载优化让整体训练吞吐提升 60% 以上; VLM 各阶段混入一定比例的纯文本数据并动态调学习率, 比例未给; 后训练把绝大部分算力和数据工作放在 RL 阶段, 按 prompt 类型建不同偏好标准, 并构造去除长度偏好的 RM 训练集, 让回复准确而简洁.

60% 吞吐提升那句的原文是 「以通信传输消除不均衡计算带来的同步等待」, 机制是这样的: 动态分辨率下, 每张卡分到的图片张数和尺寸都不同, 视觉编码器的计算量差别很大, 算得快的卡要等算得慢的卡同步梯度. 与其让每张卡按自己的数据硬算, 不如把视觉 token 在卡之间重新分配, 用一次通信换掉大段空等. Seed1.5-VL 引言里的 「vision token redistribution」 和按 FLOPs 降序贪心分配, 就是这句话的展开版. 混合训练一段的 「动态调整学习率平衡视觉与语言能力」 页面没给调度方式; Seed1.5-VL 给出的替代答案是固定混入约 5% 纯文本加分阶段的学习率日程, 两者是否同一套做法, 无从判断.

把这一节和四个月后的 Seed1.5-VL 放在一起, 能看到路线的延续和更换. 延续的是: 原生分辨率, 混入纯文本保语言能力, 视觉编码器的负载均衡, 以及偏重 RL 的后训练. 更换的是编码器本身: Seed1.5-VL 用的是 532M 的 Seed-ViT, 而不是这里的 2.4B Doubao ViT, 报告强调的是 「紧凑」. 两个编码器是什么关系, 两份材料都没说. 这说明 1.5 代的视觉线在编码器规模上做过取舍, 至少在对外报告里, 更小的编码器接管了主线.

### 4.2. 语音: Speech2Speech 端到端

页 9 提出 **Speech2Speech 端到端框架**, 把语音和文本 token 融合, 与 ASR+LLM+TTS 级联方式对比, 称对话效果有 「质的飞跃」, 模型兼具高理解力, 语音高表现力与高控制力, 以及回复内容和语音上的情绪承接. 框架设计上, 语音与文本 token 融合被写成 「为语音多模态数据的 Scaling 提供必要条件」; Pretrain 阶段开发多样的数据生产和使用方式, 通过 Scaling 融合语音与文本能力; PostTraining 阶段平衡表现力数据与智商数据, 做数据筛选和多模态 RL 的专项提升. 语音与全双工的一般讨论见 [音频与语音模型](../../../../llm-guide/8-多模态/8.3-音频与语音模型/8.3-音频与语音模型.md) 和 [Omni 与全双工](../../../../llm-guide/8-多模态/8.7-Omni与全双工/8.7-Omni与全双工.md).

这一部分没有任何基准数字, 只有一段演示视频的截图 (字幕 「豆包 你可以用欲哭无泪的语气」). 语音 token 化方式, 码率, 是否全双工, 延迟多少, 都没写. 所以能记下的只有路线: 1.5 代已经把语音当作和文本同一序列里的 token 来训, 不再走级联. 后来 Seed 门户上的音视频全双工模型是否从这里演化而来, 仅凭报告无法回答.

## 5. 评测与演示

### 5.1. 文本基准表: 14 行的胜负分布

页 2 的表有 7 列模型, 14 行基准. 逐行数下来, Doubao-1.5-pro 严格第一的有 6 行: MMLU_PRO (80.1), McEval (70.2), FullStackBench (65.1), DROP (93.0), CMMLU (90.9), C-Eval (91.8); GPQA 65.0 与 Claude-3.5-Sonnet-latest 并列第一; 其余 7 行不是第一: MMLU 由 GPT4o-0806 的 88.7 领先, Math 与 OlympiadBench 由 Gemini-exp-1205 领先 (89.7, 64.7), MBPP+ 由 DeepseekV3 的 79.3 领先, BBH 与 SysBench 由 Gemini 和 Claude 领先, IFEVal 由 Gemini 的 89.8 领先. 两个中文基准领先最多, CMMLU 高第二名 6.6, C-Eval 高 5.3; 最大的落后是 OlympiadBench, 比 Gemini-exp-1205 低 4.9.

表下注有两句要逐字读. 一是 「其它模型的评测指标来自官方评测结果, 官方评测结果中不含的部分来自内部评测平台结果」, 同一行里可能混着对手官方数和字节内部平台数, 表中不做区分; 所以 MMLU 差 0.1, BBH 差 0.1, IFEVal 差 0.3 这类格子只能读成持平. 二是 GPT4o-0806 「在语言模型公开评测指标中显著优于 GPT4o 其它版本」, 视觉表另选 GPT4o-1120, 两张表里的 GPT4o 是两个模型. 表里还有离群格: GPT4o-0806 的 DROP 只有 79.8, 其余六列在 87.4 到 93.0; Qwen2.5 的 SysBench 47.2 比倒数第二低 11.7. 这种突然掉一截, 可能是能力短板, 也可能是 shot 数或评分脚本不同. 评测口径的一般讨论见 [评测科学与证据](../../../../llm-guide/10-评测、安全与治理/10.1-评测科学与证据.md).

柱图与表放在一起看, 能读出一条贯穿预训练到产品的走向. 柱图里 MoE 最强的是 GPQA 和 MMLU_PRO, 表里这两行也是 Doubao 的强项; 柱图里 MoE 最弱的是 MATH, 表里 Math 与 OlympiadBench 正是输给 Gemini 的两行. **知识类偏强, 数学偏弱, 从 9T 中间结果一直延续到最终产品**. 这也给三个月后 Seed1.5-Thinking 让 STEM 训练题里数学占八成以上, 提供了一个合理的动机, 虽然那份报告自己没有这样解释.

### 5.2. 视觉基准表: 大学题和数学领先, 通用问答与视频不是第一

页 7 的视觉表有 6 列模型, 18 行基准, Doubao-1.5-pro 严格第一的有 10 行: MMMU(val) 73.8, MMMU-Pro 59.3, MathVision 48.6, OlympiadBench 48.5, MathVista 78.8, InfoVQA 88.0, DocVQA 96.7, RealWorldQA 78.9, Blink 68.4, CountBench 89.6. 领先最多的是数学推理组, MathVision 比 Gemini-2-flash 高 7.3. 没拿第一的 8 行分布有规律: InternVL-2.5-78B 在 MMStar, MMBench-en, MMBench-cn 三行领先, 这是通用视觉问答的主体; Qwen2-VL-72B 在 TextVQA 和 EgoSchema 领先; Gemini-2-flash 在 Video-MME 领先; Claude3.5-Sonnet 在 ChartQA 领先.

OlympiadBench 在文本表和视觉表各出现一次, 结论相反: 文本表里 59.8 输给 Gemini-exp-1205 的 64.7, 视觉表里 48.5 领先 Gemini-2-flash 的 43.6. 两张表对比的 Gemini 是两个模型, 视觉表用的应是带图题目, 页面没写各取哪个子集. 视频两行的评测依赖抽帧数和分辨率, 页面没有给设置, EgoSchema 一行还写着 「subest」, 应是 subset, 子集多大没写. VLM 评测的一般问题见 [VLM 的评测与基准](../../../../llm-guide/8-多模态/8.2-视觉语言模型/8.2.5-VLM的评测与基准.md).

### 5.3. 深度思考模式: AIME 图的两行

页 10 说在不用其他模型数据的条件下, 通过 RL 算法突破和工程优化, 发挥 test time scaling 的算力优势, 完成 RL Scaling, 研发了深度思考模式. 按本库用词, 这是 TestingTime 一侧的投入. AIME 小图有两行: pass@1 上 Doubao-1.5-pro-AS1-Preview 70.0, O1-preview 44.6, O1 74.4, O1 第一; cons@k 上 Doubao 86.7 (cons@32), O1-preview 54.7 (cons@64), O1 83.3 (cons@64), Doubao 第一. 推理与思考能力的一般讨论见 [推理与思考能力](../../../../llm-guide/4-后训练/4.5-推理与思考能力/4.5-推理与思考能力.md).

正文说 「在 AIME 上已经超过 O1-preview, O1」, **对 O1 只在 cons@k 一行成立**. 采样数不对等的方向要看清: Doubao 只投 32 票, O1 投 64 票, 这一点对 Doubao 不利, 所以投票一行的领先在采样数上没占便宜; 问题在单次作答的 pass@1 上 Doubao 低 4.4, 正文只挑了投票那一行. 图也没写 AIME 是哪一年. 有意思的是, 三个月后 Seed1.5-Thinking 报的 AIME 2024 恰好也是 86.7, 但那是 32 次的平均准确率, 这里是 32 票的多数投票, 两个同值的数口径不同, 不能看成同一次结果.

### 5.4. 页面上的两个演示: 结构化输出和推理泛化

页 9 的 「复杂指令遵循」 演示是一张手机截图加一段检查点分析: 模型逐项判断页面上能否触发刷新, 能否触发转发, 每项先写理由, 再用 &lt;RESULT&gt;TRUE/FALSE&lt;/RESULT&gt; 和 &lt;CONFIDENCE&gt;数字&lt;/CONFIDENCE&gt; 两组标签给出结论和置信度. 抽取稿里第一项的标签被截成了 「LT>」 和 「FIDENCE>」, 是 MinerU 的识别残缺, 第二项完整. 这类 「看界面, 按格式判断可操作性」 的任务, 就是后来 Seed1.5-VL 里 GUI 数据 (元素类型, 框, 状态变化描述) 和 GUI agent 评测要做的事. 页面把它放在指令遵循下面, 说明在 1.5 代初期, 界面理解还被当作多模态指令遵循的一个用例, 还没有独立成 agent 能力.

页 11 的演示归在 「推理能力的初步泛化」 下, 问题是 「宫廷玉液酒, ebay bar ebay 是啥意思」. 回答先认出 「宫廷玉液酒」 出自 1996 年春晚小品《打工奇遇》的 「一百八一杯」, 再把 「ebay bar ebay」 拆开试了几种假设: eBay 加 bar 的字面组合, 模仿另一句台词, 网络暗号, 最后按发音对到 「一杯 八 一杯」, 与 「一百八一杯」 的节奏对上. 中间有一个假设把小品里 「群英荟萃」 和 「萝卜开会」 的关系说错了, 回答没有回头改掉, 只是用 「这只是一种猜测」 带过; 按发音对应, 第一个 ebay 读作 「一百」 更贴切 (读法). 这个例子展示的是提出假设, 逐个排除, 用发音验证的搜索过程, 与数学推理的形式相同, 用来说明 RL 训出的推理习惯会迁移到非数学问题. 它也说明, 搜索过程中错误的中间假设会留在输出里, 这是长 CoT 模型常见的副作用.

## 6. 页面没有印出的量

结构层面: 专家数, 每 token 激活专家数, 总参数量, 激活参数量, 层数, 隐藏维度, 上下文长度, 稀疏比例都没有. 训练层面: 完整训练的 token 总数, 学习率, batch, 负载均衡方法没有. 评测层面: 文本表未标哪些格子来自内部平台, 没给 shot 数与 prompt; AIME 未标年份; 语音没有任何评测.

能从表和图直接读出的有: 文本表 14 行 6 胜 1 平 7 负的分布; 视觉表 18 行 10 行第一; 训练 loss 在 7T 后与 7 倍参数的稠密模型重合; 相对性能七项里两项明显领先, 数学一项明显落后; AIME pass@1 低于 O1, cons@k 在更少采样下高于 O1. 只能照单记录的有: 7 倍杠杆背后的绝对参数, 稀疏比例, 25% 数据, 4 倍收敛, 10 个绝对点, 以及 「不用其他模型数据」 的声明. 放进家族谱系里, 这一页最有价值的是把后训练的零件, 视觉的路线和推理的方向都先亮了出来, 后面几份报告各自把其中一块展开.
