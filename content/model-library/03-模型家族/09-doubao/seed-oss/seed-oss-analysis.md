# Seed-OSS-36B: MoE 家族里的一个稠密开源分支

源文是 Hugging Face 上 ByteDance-Seed/Seed-OSS-36B-Instruct 模型页的抓取, 13 页里夹着大量站点导航, 正文只有一张结构表, 两张评测表, 一段思考预算说明和几组部署命令, 技术报告标着 「Coming Soon」.

来源: [ByteDance-Seed/Seed-OSS-36B-Instruct](https://huggingface.co/ByteDance-Seed/Seed-OSS-36B-Instruct) 模型页 (发布日期 2025/08/20). 逐段对照稿见同目录 `seed-oss-bi.md`, 页码指抓取稿 `seed-oss.md` 的 13 页, 数字以源文为准.

## 1. 在家族里的位置

Doubao-1.5-pro, Seed1.5-Thinking, Seed1.5-VL 这一路都是 MoE, 而且权重不公开. Seed-OSS-36B 是 Seed 团队放出可下载权重的通用语言模型 (代码专用的 Seed-Coder 另算), **结构却换成了稠密**: 卡上写的是 「常见的因果语言模型结构」, 配 RoPE, GQA, RMSNorm 和 SwiGLU, 没有提专家或路由. 它以 Apache-2.0 发布, 一次放出三个版本: 默认的 Base (预训练掺了合成指令数据), 不掺合成数据的 Base-woSyn, 以及 Instruct. 卡上列的特点有思考预算, agent 能力, 研究友好和原生长上下文, 另说主要为国际化 (i18n) 场景优化; 其中 「研究友好」 一条解释了为什么要另发一版 woSyn.

从 Seed1.5-Thinking 到这里, 能看到一条后训练能力的延续: 前者让模型学会先想再答, 这里把 「想多久」 做成了**用户可设的预算**. 评测表里自家的参照列也说明了血缘: Base 表对照的是 Seed1.6-Base, Instruct 表对照的是 Seed1.6-Thinking-0715. Seed1.6 在卡上没有参数量, 表注说粗体和下划线只在开源模型里排, 所以这两列是一条内部上限线, 不在名次里. Seed-OSS 和 Seed1.6 是否共用预训练数据或后训练流程, 卡上没说.

## 2. 结构与训练

### 2.1. 结构: 一张表能算出什么

结构表只有七行: 64 层, 隐藏维 5120, Q/K/V 头数 80/8/8, 头维 128, 词表 155K, 上下文 512K, RoPE 基频 1e7. 最不显然的是 Q 的宽度: 80 × 128 = 10240, 是隐藏维的两倍, Q 投影把 5120 维升到 10240 维, 输出投影再压回来. K 和 V 各 8 头, 共 1024 维, 每 10 个 Q 头共用一组 K/V. 这是 **GQA** 的典型配法, 机制见 [GQA](../../../../llm-guide/2-核心原理与架构/2.2-基础注意力机制/2.2.2-多头注意力变体/03-GQA-在性能与缓存之间折中/03-GQA-在性能与缓存之间折中.md); SwiGLU 和 RMSNorm 分别见 [GLU 家族](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.1-前馈网络FFN与激活函数/03-GLU家族-从GLU到SwiGLU/03-GLU家族-从GLU到SwiGLU.md) 和 [归一化层](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.2-归一化层/2.1.2-归一化层.md).

KV cache 可以直接算. 每 token 每层存 K, V 共 2 × 1024 = 2048 个值, BF16 每个 2 字节, 即 4 KiB; 64 层合计每 token 256 KiB. 128K (131,072) token 约 32 GiB; 512K 按 524,288 算约 128 GiB. 如果 K, V 也用 80 头, 这些数都要乘 10. 所以**即使有 GQA, 512K 上下文也要靠多卡或 KV 量化才装得下**, 卡上 vLLM 示例正是 8 卡张量并行. 参数量也能部分对上: 注意力四个投影每层约 115.3M, 64 层约 7.38B; 词表嵌入按 155,000 × 5120 约 0.79B, 不共享时约 1.59B; 余下 27B 到 28B 应在 SwiGLU 前馈里, 反推中间维约 2.7 万到 2.9 万. 前馈中间维和嵌入是否共享, 卡上都没有, 这组数只能当量级看. KV cache 的一般优化见 [KV 缓存与内存优化](../../../../llm-guide/6-训练与推理优化/6.4-KV缓存与内存优化/6.4-KV缓存与内存优化.md).

### 2.2. 预训练: 12T token 和合成指令数据的取舍

卡上说整个系列只用了 12T token 训练, 数据构成没写. 真正讲清楚的只有一个取舍: 预训练里掺合成指令数据, 多数基准会涨, 所以默认 Base 是掺了的; 但这会影响后训练研究, 于是另发不掺的 woSyn. 社区讨论 「预训练里混指令数据」 时, 常说它会让 Base 在零样本评测上好看, 却让 「base 模型到底学会了什么」 变得难以分辨, woSyn 就是给做后训练研究的人一个干净起点. 这 12T 里合成数据占多少, 是什么形态, 卡上没有.

Base 表给了两版并排的数. 11 行里 w/ syn. 赢 9 行, 输的两行是 GPQA-D (31.7 对 35.2) 和 SimpleQA (5.8 对 7.4). 差距最大的是 MATH: 81.7 对 61.3, 相差 20.4, 其余各行都不超过 6.0 分. **合成指令数据的收益高度集中在数学一行**, 而知识类的 SimpleQA 反而掉了. 长上下文这一面, 卡上只有一句 「原生训练到 512K」, 以及唯一一项长上下文评测 RULER (128K) 94.6; 有没有分阶段拉长, 用没用 YaRN 一类的插值方法, 都没交代, **512K 本身没有评测支撑**. RoPE 长度外推的一般做法见 [从 PI 到 YaRN 的频率扩展](../../../../llm-guide/2-核心原理与架构/2.5-长上下文与外推技术/RoPE/03-长度外推：从PI到YaRN的频率扩展.md).

### 2.3. 后训练与思考预算

后训练用了哪些阶段, SFT 还是 RL, 数据多少, 卡上都没写. 唯一讲细的是**思考预算**: 用户给一个以 token 计的预算, 模型在 `<seed:think>` 段里思考, 中途周期性插入 `<seed:cot_budget_reflect>` 报告已用和剩余的量, 预算用完就结束思考段转入回答. 第 8 页 512 预算的例子里, 三次自检是 129+383, 258+254, 393+119, 加起来都是 512, 间隔约 129 到 135 token. 预算计数写在模型自己的输出里, 不是外部截断, 这说明**它是训练出来的行为**.

用法规则也在卡上: 预算优先取 512 的整数倍 (512, 1K, 2K, 4K, 8K, 16K), 因为训练集中在这些档位; 预算为 0 时直接回答, 小于 512 的都建议设成 0. 这等于把 TestingTime 算力交给用户按题目难度调, 与 Qwen3 的 thinking budget, s1 论文的 budget forcing 属于同一类思路, 区别在于 **Seed-OSS 让模型自己数 token 并中途反思**. 卡上说难题 (AIME, LiveCodeBench) 分数随预算上升, 简单题 (IFEval) 只是波动, 但配套的曲线只是一个链接, 抓取里没有这张图, 各档位对应多少分读不到. 还有一处默认值要注意: generate.py 的 thinking_budget 默认 −1 (不限), max_new_tokens 默认 4096, 难题的长思考可能在给出答案前就被截断.

## 3. 评测与缺口

### 3.1. 评测: 同一格里有几种来源

Instruct 表六列来源不同: 自家 Seed1.6-Thinking-0715 不带星号; OAI-OSS-20B, Qwen3-30B-A3B-Thinking-2507, Qwen3-32B 带星号, 格式是 「复现值 (原报告值)」; Gemma3-27B 抄自技术报告; Seed-OSS 是自测. 生成配置是 temperature 1.1, top_p 0.95. 按开源列比, Seed-OSS 第一的行有 MMLU-Pro 82.7, LiveCodeBench v6 67.4, TAU1-Retail 70.4, SWE-Bench Verified (OpenHands) 56, RULER (128K) 94.6; 数学推理几行输给 OAI-OSS-20B: AIME24 91.7 对 92.7, AIME25 84.7 对 90.3, BeyondAIME 65 对 69. IFEval 85.8 是六列最低. 评测口径的一般讨论见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据.md).

AIME 的分数能看出采样次数的线索 (读数推断). 每年 30 题, 单次作答只能是 3.33 分的整数倍, 91.7 约合 27.5 题, 84.7 约合 25.4 题, 都不是整数, 说明是多次采样平均, 但次数没印. BeyondAIME 这一行值得一提, 它正是 Seed1.5-Thinking 自建的那套 100 题, 在这里成了开源模型之间的公共尺子. SWE-Bench Verified 同一基准配了两套 agent 框架, OpenHands 下 56, AgentLess 4*10 下 47, 差了 9 分, **框架本身就是变量**.

### 3.2. 卡上没有的面

对照一份技术报告应有的内容, 这张卡缺的很多: 前馈中间维和嵌入是否共享; 12T token 的来源与配比; 合成指令数据的形态和比例; 后训练的阶段, 方法和数据; 思考预算怎样训出来; 512K 上下文的训练方式与评测; 评测的采样次数和最大生成长度; 任何中文基准. 这些都要等 「Coming Soon」 的技术报告.

在这些限制下能稳妥读出的是: 一个 64 层, 隐藏维 5120, Q 侧 10240 维, K/V 各 1024 维的 GQA 稠密模型, 约 36B 参数, BF16 发布, 声称原生训练到 512K, 带显式的思考预算控制, Apache-2.0 开源. 放回家族里看, 它是 **MoE 主线之外给研究者用的一个稠密样本**, 延续了 Seed1.5-Thinking 的长思考, 把 TestingTime 的开关交到了用户手上.
