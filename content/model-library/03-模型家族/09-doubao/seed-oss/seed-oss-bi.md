## Introduction

## 简介

Seed-OSS is a series of open-source large language models developed by ByteDance's Seed Team, designed for powerful long-context, reasoning, agent and general capabilities, and versatile developer-friendly features. Although trained with only 12T tokens, Seed-OSS achieves excellent performance on several popular open benchmarks.

Seed-OSS 是字节跳动 Seed 团队开发的开源大语言模型系列, 面向强长上下文, 推理, agent 和通用能力, 另带多种方便开发者的功能. 虽然只用了 12T token 训练, Seed-OSS 在多个常用公开基准上表现出色.

We release this series of models to the open-source community under the Apache-2.0 license.

我们以 Apache-2.0 许可证向开源社区发布这一系列模型.

Seed-OSS is primarily optimized for international (i18n) use cases.

Seed-OSS 主要针对国际化 (i18n) 场景做了优化.

### Key Features

### 主要特性

**Flexible Control of Thinking Budget**: Allowing users to flexibly adjust the reasoning length as needed. This capability of dynamically controlling the reasoning length enhances inference efficiency in practical application scenarios.

**思考预算灵活可控**: 用户可以按需调节推理长度. 这种动态控制推理长度的能力, 能在实际应用中提高推理效率.

**Enhanced Reasoning Capability**: Specifically optimized for reasoning tasks while maintaining balanced and excellent general capabilities.

**推理能力增强**: 专门针对推理任务优化, 同时保持均衡且出色的通用能力.

**Agentic Intelligence**: Performs exceptionally well in agentic tasks such as toolusing and issue resolving.

**Agent 能力**: 在工具调用, issue 修复这类 agent 任务上表现突出.

**Research-Friendly**: Given that the inclusion of synthetic instruction data in pre-training may affect the post-training research, we released pre-trained models both with and without instruction data, providing the research community with more diverse options.

**方便研究**: 预训练里加入合成指令数据可能影响后训练方面的研究, 所以我们同时发布了含指令数据和不含指令数据的预训练模型, 给研究社区更多选择.

**Native Long Context**: Trained with up-to-512K long context natively.

**原生长上下文**: 原生训练的上下文长度最长到 512K.

> **问:** 「up-to-512K」 加上 「natively」, 是不是说卡上在 512K 长度评过?
> 没有. 512K 只出现在这条特性和第 4 页结构表里, 卡上最长的评测是第 7 页的 RULER (128K), Seed-OSS 得 94.6; 没有 512K 的 RULER 或检索类数字. 「512K」 是 512,000 还是 524,288 也没写. 部署侧同样没把 512K 当默认: 第 10 页 generate.py 的 max_new_tokens 默认 4096, 第 11 页 vLLM 启动命令没有设最大序列长度. 能读到的只有 「训练时最长到 512K」 这一句声明.

> **拆开:** 表里写 Parameters 36B, 用其余几行能不能加回 36B?
> 加不全. 能算的部分: Q 头 80 × 头维 128 = 10240, 是隐藏维 5120 的两倍, 所以 Q 投影是 5120→10240, 输出投影 10240→5120; K 和 V 各 8 × 128 = 1024 维. 每层注意力约 5120×10240×2 + 5120×1024×2 ≈ 115.3M, 64 层约 7.38B. 词表按 155,000 × 5120 算约 0.79B, 输入输出嵌入不共享就是约 1.59B. 剩下 27B 到 28B 应在 SwiGLU 前馈里, 但表上没印前馈中间维; 按每层 3 × 5120 × I 反推, I 约在 2.7 万到 2.9 万之间, 这是估算, 不是卡上的数. 「36B」 和 「155K」 都是取整值, 第 1 页 Safetensors 栏也只给到 36B.

If no thinking budget is set (default mode), Seed-OSS will initiate thinking with unlimited length. If a thinking budget is specified, users are advised to prioritize values that are integer multiples of 512 (e.g., 512, 1K, 2K, 4K, 8K, or 16K), as the model has been extensively trained on these intervals. ## Quick Start

## 快速开始

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import os
import re

model_name_or_path = "ByteDance-Seed/Seed-OSS-36B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_name_or_path)
model = AutoModelForCausalLM.from_pretrained(model_name_or_path, device messages = [
    {"role": "user", "content": "How to make pasta?"},
]
tokenized_chat = tokenizer.apply_chat_template(
    messages,
    tokenize=True,
    add_generation_prompt=True,
    return_tensors="pt",
    thinking_budget=512 # control the thinking budget)

outputs = model.generate(tokenized_chat.to(model.device), max_new_token

output_text = tokenizer.decode(outputs[0])
```
