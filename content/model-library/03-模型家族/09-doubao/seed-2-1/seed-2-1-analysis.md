# Seed2.1: 把 harness 算进分数, 让模型参与自己的研发

来源: Seed2.1 Model Card: Agentic Intelligence for Productivity (字节跳动 Seed, 共 73 页). 逐段对照译稿见同目录 `seed-2-1-bi.md`, 数字以源文 `seed-2-1.md` 为准. 表号, 图号都指原文编号.

## 1. 家族走到这一步: 复杂需求第一次排在流量前面

引言把 Seed2.1 称为家族的转折点: 日常生活, 专业生产和前沿探索里的复杂需求, 第一次被放到研发优先级的中心, 排在流量驱动的通用使用之前. 这一版有两个变体, Seed2.1 Turbo 面向高吞吐的产品场景, Seed2.1 Pro 面向更强的推理, agent 执行和复杂生产工作流. Seed2.0 发的是 Mini, Lite, Pro 三档, 所以 Seed2.1 Pro 对 Seed2.0 Pro 可以一一对应, Turbo 在上一代没有同名型号, 不宜硬配 Lite.

卡的形态延续了 Seed2.0: 没有架构, 参数量, 上下文长度, 训练数据配比和训练算力, 也没有 Abstract 和 Conclusion; 正文四章是通用 agent, 生产级编程, 前沿研究和 Seed for Seed. 引言列出三条研发方法: 让内部用户, 受邀测试者和众测开发者持续试用; 围绕 Claude Code, Trae 等产品里的真实体验构建评测, 并用用户回传的坏例扩充基准; 让 Seed 模型自己参与评测构建, 失败分析, 数据清洗, 数据合成, 训练迭代和基础设施优化. 第三条就是第 4 章的 Seed for Seed, 也是这张卡里唯一碰到训练环节的地方. 引言还有一个判断决定了全卡的结构: 评测正在从静态基准转向真实用户体验, 模型表现越来越和 harness, 工具与产品环境绑在一起. 所以自研基准和众测占了很大篇幅, 公开基准退到附录 C.

## 2. 对手, 口径与两代变化

### 2.1. 对手换了一代, 两代分差要先剥掉对手

Seed2.0 卡的对手是 GPT-5.2 High, Claude-Sonnet-4.5, Claude-Opus-4.5 和 Gemini-3-Pro High; Seed2.1 的自动评测表换成 GPT-5.5, Claude-4.7 Opus 和 Gemini-3.1 Pro, 视频表换成 Gemini-3.1-Pro 和 Gemini-3.5-Flash. 于是 「相对对手的名次」 和 「相对上一代的进步」 成了两件事. Seed2.0 Pro 在 BrowseComp 上 77.3, 与 GPT-5.2 High 的 77.9 基本持平; Seed2.1 Pro 在 BrowseComp (带搜索) 上 86.2, 对 GPT-5.5 的 84.4 领先. 两次看起来都是 「与 GPT 同档」, 实际上 **Seed 自己涨了约 9 分, 对手也涨了约 6.5 分**.

同一张卡里 Claude 的版本也不统一: 众测对手是 Opus 4.6, Trae 众测是 Opus 4.7, 自动评测表是 Claude-4.7 Opus, 数据清洗对比里是 Claude Opus 4.8. 引言说 「偏好排名高于 Claude Opus 4.6」, 比较对象比自动评测表里的对手低一个版本. 读 「超过 Claude」 这类句子时要先看是哪一个版本. 表 1 的专业生产力行也要按对手逐项看. Seed2.1-Pro 在 GDPval 上 87.9, 高于 GPT-5.5 的 84.9; Agent Startup Bench 68.8 对 68.1; 在 Finance Agent v1.1 上 60.7 落后 GPT-5.5 的 65.3, OneMillion Bench 68.8 落后 Claude 的 73.0, APEX Agents 33.8 与 Claude 的 33.9 持平. 领先的几行多是按 rubric 或偏好评交付物的任务, 落后的几行更依赖领域事实和可核对的数字, 这与第 2.2 节 「长尾知识没有追上」 的判断一致. 评测证据怎样分级, 可以参考 [评测科学与证据](../../../../llm-guide/10-评测、安全与治理/10.1-评测科学与证据.md).

### 2.2. 同一把尺子上的两代变化

编程上变化最大的是仓库级任务. NL2Repo-Bench 从 Seed2.0 Pro 的 27.9 到表 5 的 47.0, 超过 GPT-5.5 的 45.1, 仍低于 Claude-4.7 Opus 的 58.2; Seed2.0 卡当时专门承认 「与 Claude 在 NL2Repo 上差距较大」, 这一代补了一大截. SWE-Bench Pro 从 46.9 到 SWE-Pro Bench 57.5, SciCode 从 48.5 (另一张表 52.1) 到 59.8. 推理上, ARC-AGI-2 从 37.5 到 62.5, 是全卡最大的单行涨幅, 但 GPT-5.5 是 85.0; MathArena Apex 20.3 到 31.3, AetherCode 60.6 到 65.8. 知识类基本停住: SuperGPQA 68.7 到 70.8, Gemini-3.1 Pro 是 76.6; BeyondAIME 86.5 到 87.0. Seed2.0 引言承认的两处差距, **编码缩小了, 长尾知识没有**.

NL2Repo-Bench 的那 19 分要再看一眼定义. Seed2.0 卡说它衡量 「从自然语言规格一次性端到端完成整个软件仓库」, 考的是从零构建; Seed2.1 卡说它衡量 「把自然语言需求转成仓库级的代码修改」, 强调先理解已有代码库, 再选文件, 推依赖, 做多文件修改. 同一个名字, 两张卡描述的任务形态不同, 可能是基准本身改了版本, 也可能是两份文字各写了一面, 卡里没有说明. 对手列也提示设定有变: Seed2.0 表里 GPT-5.2 High 是 49.3, Seed2.1 表里更新的 GPT-5.5 反而只有 45.1; Claude 从 Opus 4.5 的 43.2 跳到 4.7 Opus 的 58.2. 新一代 GPT 分数下降, 更像评测设定变了, 不像模型退步. 如果任务确实从 「从零建仓」 变成 「在已有仓库上改」, 这 19 分里就有一部分来自任务变容易, 而且正好落在 Seed2.1 的强项上: Trae 众测显示它在维护型工作上占优, 从零生成是短板.

视觉表 (表 9) 涨得最整齐: MathVision 88.8 到 92.6, VisuLogic 47.4 到 54.3, VisFactor 36.8 到 51.4, ZeroBench main 12.0 到 18.0, 只有 ChartQAPro 从 71.2 微降到 70.9. 视频表 (表 10) 有涨有跌: TOMATO 从 59.9 跳到 79.5; ContPhy 从 67.4 降到 63.6, MotionBench 75.2 到 74.9, VideoMME 89.5 到 89.2, LiveSports-3K 78.0 到 76.8. 下降的几行都依赖连续帧之间的状态跟踪, §C.2 也承认细粒度时序跟踪, 物理动态建模和实时跨上下文推理仍是短板. 这条短板在谱系里很长: Seed1.5-VL 的局限一节就写过 「分不清连续动作的先后」, 两代以后仍在同一处. LiveSports-3K 上 Gemini-3.1-Pro 的 89.0 高出 12.2 分, 上一代 Seed2.0 Pro 在这一行还领先 Gemini-3-Pro.

### 2.3. 名字相同, 口径不同

Terminal Bench 最容易看错: Seed2.0 报 2.0 版, Pro 55.8; 表 5 报 2.1 版, Seed2.1-Pro 71.0, 任务集和评分都可能变了, **这 15 分不能算作进步**. HLE 也一样: Seed2.0 的 HLE-Verified 73.6 在搜索 agent 表里, 带工具; 表 11 的 HLE-Verified 写明 「no tool」, Seed2.1 Pro 只有 42.9. 能对应的是 HLE-textonly (with Search) 55.7 对 Seed2.0 的 HLE-text 54.2.

IMO 2025 差得更远. Seed2.0 用逐题 7 分制报 35/42; 表 7 里 Seed2.1 Pro 65.2, Deep Think 81.0, 没有单位. 35/42 约合 83.3%, 若表 7 是百分制, 普通模式反而远低于上一代的竞赛设定, 显然是设置不同. DUDE 从 72.4 到 82.8, 同时 Gemini 从 70.1 变成 82.1, 对手和自家同步跳 10 分, 更像评测设置换了. TOMATO 的 19.6 分跳升也可能和方法有关: Seed2.0 卡写过在 TOMATO 上用 Thinking with Tracking, 这张卡没说是否沿用. FrontierScience-Research 在卡内三张表里给了三组 Seed 数 (表 6 Turbo 33.3, Pro 28.3; 表 7 Pro 33.3; 表 11 Turbo 23.3), 对手列完全相同.

## 3. 能力与推理时配置

### 3.1. 通用 CUA: 从 Seed1.5-VL 的 GUI 数据到一个统一策略

GUI 能力在家族里有一条清楚的来路. Seed1.5-VL 的 GUI 数据主要来自 UI-TARS, 带元素类型, 框, 文本和多步轨迹, 当时 OSWorld 36.7, Windows Agent Arena 39.6; Seed2.0 把 Vision Agent 单列一组; Seed2.1 提出 **Generalist Computer-Use Agent**, 把感知, 推理, 控制和执行放进一个策略, 由模型自己决定何时看, 点, 搜, 写代码或调工具. 作者的理由是单一范式各有短板: 代码和命令行 agent 擅长规划与工具, 遇到视觉界面和意外屏幕状态就脆; GUI agent 能看软件, 却没有高效访问代码, 文件和命令的途径. 工具调用的一般讨论见 [工具使用与 MCP](../../../../llm-guide/13-Agent/13.1-Agent核心组件/13.1.3-工具使用与MCP.md).

图 5 把这个设定的作用量了出来. 同一模型在 OSWorld 上, 仅 GUI 时 Turbo 73.2%, Pro 72.6%; 允许发命令和调工具后, Turbo 76.4%, Pro 78.8%, 平均步数从 27.5 降到 22.3, 从 28.2 降到 24.2. 正文把降幅写成 −18.7% 和 −16%, 按端点值算是 18.9% 和 14.2%, 「约五分之一」 也偏高. 仅 GUI 时 Pro 反而略低于 Turbo, 表 4 里 Pro 的 OSWorld 78.8 有相当一部分来自动作空间的设定, 对手是否同样开放, 卡里没说. 正文与表 4 还对不上: 正文写 OSWorld 78.2, MobileWorld 73.3 (对手 62.4, 56.4, 58.1), 表 4 是 78.8 和 73.1 (对手 54.7, 57.1, 48.4); 表 4 的 78.8 与图 5 吻合, 应以表为准. 同一段说 OSWorld 上 「接近 GPT-5.5」, 表上最高的是 Claude-4.7 Opus 的 82.8. 作者给出的部署理由是成立的: 每一步都有延迟, 成本和不可逆错误的风险, 更短的轨迹更可靠.

表 4 的另外三项各考一种组合. MobileWorld 只跑 GUI 部分, MCP 测试集因部署问题被排除; GameWorld 考浏览器游戏里的多模态交互, Seed2.1-Pro 31.2, 低于 GPT-5.5 的 34.1; 自研的 CreativeWork 在 Notion, Canva, Figma 三个环境里考文档管理, 视觉设计和界面编辑, 任务是开放目标, 由模型自己决定什么时候走工具, 什么时候退回界面. 按设计, MCP 负责建页面, 复制文档, 生成素材, 改对象属性这类结构化操作, GUI 负责工具做不到的部分: 读版式, 在属性面板里导航, 解析空间指代, 检查视觉结果, 确认屏幕上的最终状态. Seed2.1-Pro 在这一项 42.5, 领先所有对手十分以上. CreativeWork 正是 「统一策略」 这个设计最直接的考题, 也是自研集, 领先幅度要打个折扣来读.

### 3.2. 多模态 harness: VideoCut 的思路推到所有媒体

Seed1.5-VL 对长视频用固定 token 预算, 超了就抽帧; Seed2.0 的 VideoCut 让模型在推理时回放片段. Seed2.1 的**多模态 agent harness** 把这条思路推广到文档, 图表, 截图和视频: 专门的感知工具按高分辨率渲染页面, 密集抽帧, 保住小字和密集版式; 多模态内容渐进加载, 图片和页面按需分批读, 视频先粗看一遍, 需要细看时再加载更密的帧. 作者的分析是, 改进感知通路能提高多次采样的一致性 **Pass^k**, 即使单次可解率不变. 这和 Seed1.5-VL 的数据约定一脉相承: 28×28 像素一个 token 的密度决定了能看清多少, 现在变成由 agent 自己决定在哪里花这些 token.

表 3 与表 1 的同一基准能看出 harness 的分量. Office QA Pro 在两张表各出现一次, Claude 和 Gemini 两列完全相同 (76.5, 72.5), GPT-5.5 从 62.9 变成 69.5, Seed2.1 Pro 从 70.9 变成 72.2, Turbo 从 62.8 变成 71.1. 换成多模态 harness 以后 Turbo 涨了 8.3 分, 比两代模型之间多数行的差距还大. 表 1 标题对 OfficeQA-Pro 加了注 「含内部实现和适配, 与官方排行榜相比可能有波动」, 同样的注释其实适用于大多数行. §2.2.1 引用的 Workspace Bench 原论文里 Gemini-3.1 Pro Total 31.6, 表 1 却是 32.8, 分项逐项不同, 可见对手分数是在 Seed 的 OpenClaw 设定下重跑的. 重跑让所有模型共用一套 harness, 也意味着表 1 与各家官方数字不能混用.

harness 能提高 Pass^k 的说法, 在表 3 里有一个对应的读点. Claw-Eval 多模态部分报 Pass^3, 同一任务三次全过才算过, Seed2.1-Pro 51.0, Turbo 46.0, Claude 44.0, GPT-5.5 43.0, Gemini 27.0; 这是 Seed 在多模态 agent 表里领先最多的一行, 而在只看单次平均分的 WildClawBench 上, Pro 61.7 落后 Claude 的 67.0. 稳定性指标领先, 平均分指标落后, 与作者 「感知通路改善一致性, 不一定改善单次可解率」 的分析方向一致. 但卡里没有同一模型开关 harness 的 Pass^3 对照, 所以这只是方向吻合, 算不上消融证据.

### 3.3. Turbo 和 Pro 不是简单的大小关系

读者会假设 Pro 处处高于 Turbo, 表格不支持. Workspace Bench 上 Turbo 54.7 高于 Pro 53.0; PostTrainBench 18.3 对 16.5; 表 11 的推理行里 LiveMathematicianBench 27.7 对 20.9, MathArena Apex 35.4 对 31.3, BeyondAIME 88.0 对 87.0; 表 5 的 Error Fix Python 74.0 对 70.7. Pro 领先的地方集中在 agent 和多模态: MCP-Atlas 83.8 对 80.3, Claw-Eval Pass^3 51.0 对 46.0, CreativeWork 42.5 对 34.5, Agent Startup Bench 68.8 对 54.0, BabyVision 73.7 对 62.9, VLMsAreBiased 83.6 对 68.3.

一个合理的读法是两个变体的训练侧重不同: Pro 在长程工具使用和感知上投入更多, Turbo 在纯文本数学和研究型推理上并不吃亏. 这和 Seed2.0 三档之间出现的倒挂是同一类现象, 说明 **Seed 家族的档位不是同一配方下只改规模**. §C.3 正文说 「Pro 在知识基准上稳定高于 Turbo」, 只对知识行成立. 部署前的 Scaling 在这一代依然看不到: 两个变体多大, 差在哪里, 卡里都没有.

### 3.4. Deep Think: 验证循环从流水线变成产品配置

验证在家族里走过三步. Seed1.5-Thinking 训练会思考的验证器, 用在奖励侧; Seed2.0 的 IMO 35/42 出自 solve-verify-refine 流水线, 验证搬到了推理侧, 但只是附录里的一套流程; Seed2.1 把它做成可调用的 **Deep Think** 配置, 流程是推理, 核验, 修改, 选择的循环, 可调用网页搜索和沙箱代码执行, 组件可替换. 这是 TestingTime 的产品化: 推理时多花算力, 按需开启. 表 7 里它相对 Seed2.1 Pro 的提升很大: IMO 2025 65.2 到 81.0, IMOProof-Adv 54.3 到 83.8, IPho 2025 79.3 到 89.0; 对 Gemini-3.1 Deep Think, IMO 2025 81.0 对 81.5 略低, IMOProof-Adv 83.8 对 76.7 领先.

整节没有 TestingTime 预算: 候选数, 轮数, 每题 token 上限, 墙钟时间, 工具调用次数都没给, Gemini 的数是自跑还是引用也没说. 因此提升里多少来自多采样, 多少来自核验器, 多少来自搜索, 拆不开. 核验器若就是 Seed2.1 Pro 本身, 它的错误会与生成器相关, 迭代越多收益越小; IMO 2025 和 IPho 2025 都是已公开赛题, 允许联网时有检索到题解的可能, 卡里没说是否屏蔽. Seed1.5-Thinking 用一道混合三元组题说明过, 验证器的假阴性会把正确答案判错; 到 Seed2.1, 验证器的质量仍然决定这条循环的上限, 却没有一个数字交代它. 把两家的基础模型和 Deep Think 放在一起减一下, 能看出优势从哪里来. 表 7 的四行里, Seed 的增益分别是 IMOProof-Adv +29.5, IPho 2025 +9.7, FrontierScience-Research +7.4; Gemini 的增益是 +27.7, +11.4, +6.6 (IMO 2025 缺 Gemini-3.1 Pro 的数). 两家的循环带来的增量在同一量级, IPho 上 Gemini 的增量还略大. Seed2.1 Deep Think 领先 Gemini-3.1 Deep Think 的地方, 主要是基础模型本来就领先的地方: FrontierScience-Research 上 Pro 与 Gemini-3.1 Pro 是 33.3 对 16.7, Deep Think 以后是 40.7 对 23.3, 差距几乎原样保留. 所以这张表支持的结论是 **「推理时循环对两家都有效」, 而不是 「Seed 的循环设计更好」**; 后一个结论要在相同预算下对比才能成立.

推理时多花算力的一般讨论见 [推理与思考能力](../../../../llm-guide/4-后训练/4.5-推理与思考能力/4.5-推理与思考能力.md).

## 4. 自研评测与 Seed for Seed

### 4.1. 众测和自研基准

众测数可以复算. Turbo 对 GLM 5.1: 100 胜 / 19 平 / 59 负, 胜率约 56.2%; Pro 对 Opus 4.6: 136 / 26 / 68, 胜率约 59.1% (分母含平局). Trae 众测对 Claude Opus 4.7, 167 个有效任务里 Seed2.1-Pro 被偏好 81 次, 胜率 48.5%; 一次完全做对的比例 29.3% 高于对手的 20.4%, 落入 「不可用」 档的比例 11.4% 却高于 7.8%, 主要扣在指令遵循 (3.96 对 4.11) 和边界遵守 (4.16 对 4.38). 其他细项也指向同一个方向: 可接受交付率 94.0% 对 92.2%, 严重损坏的交付 0.0% 对 2.4%, 综合可用性里 「完全可用」 档 58.7% 对 54.5%. **做对时更干净, 不听话时更多**, 这是一种高方差的分布, 维护型工作约六到七成被偏好, 从零生成是短板, 与表 5 里 DeepSWE 32.7 对 GPT-5.5 70.0 的方向一致.

表 5 的 ProgramBench 用三个数把 「从零生成」 的难度摆得更清楚: 完全解决 / 几乎解决 / 平均通过率, 几乎解决指测试通过率至少 95%. 五个模型的完全解决率都在 0.5 以下, Seed2.1-Pro 是 0 / 1 / 50.3, GPT-5.5 是 0.5 / 5.5 / 65.9. 所有模型都能写出一半左右能过测试的程序, 几乎没有一个能交出完整可用的程序; 在这一端, Seed 与 GPT-5.5 的差距比仓库修改类基准大得多. 这一行和众测, DeepSWE 放在一起, 画出的是同一条能力边界: **在已有结构里改得好, 独立搭起一个完整系统还差得远**.

自研基准的构造贴近产品: **SeedClawBench** 从 5,000 多个线上任务和 600 多个众包任务改写出 100 个任务, 用 **Agent-as-Judge** 评分, 与人工一致率 89.69% (样本 37 个任务, 262 个 rubric 条目), 表 2 上 Seed2.1-Pro 66.6 对 GPT-5.5 66.4, 在这个评判精度下只能读成同档. **Doubao Multi-Turn Bench** 从线上对话里筛出用户不满意的那一轮让模型重答; Agent Startup Bench 先调研 AI 原生创业公司, 访谈深度用户, 由专家转成带 rubric 的任务. 自研基准并没有一边倒地偏向自家: xDailyBench 上 Seed2.1-Pro 61.0, 落后 GPT-5.5 的 73.0.

几个自研集的判分机制各不相同, 决定了分数能读到什么程度. SeedClawBench 的裁判读 agent 的完整记录, 工具调用轨迹, 最终交付物和外部状态快照, 再调用只读工具为每条 rubric 收集证据, 输出带证据链的二元判断; 交付物可能是 PDF, 表格, 图片或视频, 所以文本和多模态各用一条内部判分流水线, 并给裁判配了查看这些产物的技能. xDailyBench 覆盖日常生活, 学习研究和白领工作的 30 多个垂直场景, 用多维 rubric 评任务完成度, 事实正确性, 信息覆盖和实用性, Gemini-3.1-Pro 只有 35.2, 远低于它在其他集上的位置, 说明 rubric 与某些模型的回答风格可能不匹配. Image2Floorplan 给一套公寓的多张室内照片, 要求重建户型, 输出的是房间连通图而非图片, 用加权图相似度对照人工标注并以基线归一化; Pro 48.0 比 Turbo 的 35.9 高出一截, Gemini-3.1 Pro 55.1 最高. Claw-Eval 报 Pass^3, 三次全过才算过, 衡量的是稳定性而非单次可解. SeedKernelBench 从 FlashInfer, SGLang, FlashAttention, DeepGEMM, CUTLASS, cuDNN 等库里挖算子级任务, 报相对参考实现的平均加速比, 要求内核既对又快, 这也是第 4.2 节 Kernel Loop 的练兵场. 但评测集和训练信号来自同一批用户坏例, 两者怎样隔离, 只能靠自述.

Doubao Multi-Turn Bench 的构造有一个不那么显眼的偏置. 它从线上用户与豆包模型的大量对话里过滤, 只留下用户对 AI 回答不满意, 且对话本身反映真实需求的那一轮, 以历史对话为上下文让被测模型重答. 被挑出来的轮次, 是豆包旧模型已经答砸的地方, 题目分布天然偏向豆包的弱点; 另一方面, 这些日志也可能进过豆包的训练数据. 两种效应方向相反, 卡里都没有讨论. 表 2 上 GPT-5.5 62.5 领先, Seed2.1-Pro 52.5, Gemini 52.0, Claude 49.8, Turbo 49.0, 除 GPT 外几家挤在三分之内. 这类 「从失败里取题」 的做法, 与第 4.2 节 GUI 纠错循环里 「失败轨迹进训练」 是同一种思路, 只是一个用来考, 一个用来练. Agent 评测的一般问题见 [Benchmark 与 Eval](../../../../llm-guide/13-Agent/13.5-Agent应用与治理/13.5.2-Benchmark与Eval.md).

### 4.2. Seed for Seed: 训练环节露出的一角

Seed2.0 卡完全没有训练环节, Seed2.1 卡在这一节第一次重新提到预训练数据清洗, SFT 数据合成和 RL 框架的做法, 只是换成了 「模型怎样参与」 的角度. **Data Loop** 里, Optimizer 与 Evaluator 两个 agent 轮流迭代预训练数据的正则和规则过滤器, 约束是精确率 ≥ 0.95, 预算是 300M token, 验证召回率 Seed 2.1 Pro 43.3%, GPT-5.5 44.5%, Claude Opus 4.8 51.6%. 这说明 Seed 的预训练清洗仍有大量规则过滤, 而规则由模型在高精确率门槛下迭代改写. **Training Loop** 里, Master Agent 调度 Actor (合成数据, 训练, 部署) 和 Critic (独立评测), 每轮最多 5 个并行 SFT 变体, 扫的是学习率和数据配比, 3 轮 13 个实验 4.9 天, 冠军分数从 0.40 到 0.70. **GUI 纠错循环**对比成功与失败轨迹, 找到第一个分叉步: 失败轨迹没按价格排序, 选了 ¥576 的 G531, 成功轨迹选了 ¥296 的 D11, 系统提炼出约 40 token 的纠正技能, 注入后重试成功, 票价降 48.6%, 整个周期不到 30 秒. 更关键的是这对失败与成功轨迹随后被存成训练数据: 技能和轨迹对成为下一轮的训练信号, 同一对轨迹还用来筛选今后的题库. 失败直接变成训练输入, 这是 Seed1.5-VL 那种 「RL 模型答对的题收回来进下一版 SFT」 的迭代循环, 被搬到了 GUI agent 的轨迹层面.

卡里另有一句关于训练的线索, 藏在 Toolathlon 的结果说明里: Seed2.1 在这一项的表现 「得益于持续, 可扩展的环境学习」. 这是全卡唯一点到 RL 训练环境的地方, 说明 agent 能力的训练依赖不断扩充的交互环境, 但环境有多少, 怎样生成, 怎样与评测环境隔离, 都没有. 联系 GUI 纠错循环里 「同一对轨迹用来筛选题库」 那句, 训练环境与评测题库之间的界线, 在这一代比 1.5 代更难看清.

另外几个循环与 1.5 代的做法能对上. **Infra Loop** 用 actor 与 critic 两类 agent 改写 RL 框架, 已跑一个多月, 600+ 轮, 作者明说不报最终基准; 1.5 代的 RL 框架是 HybridFlow/veRL, 这里没说改的是不是同一套. **Eval Loop** 的 **ProEval** 审计 Seed 2.0 Pro 的 puzzle_zero_shot, 用 241 道探测题发现 18 个百分点的失败来自评判器假阴性 (格式匹配, 只接受单一答案), 这和 Seed1.5-Thinking 训练会思考的验证器时要解决的问题完全相同, 两代之后, **评测侧的判分器仍在犯奖励侧当年犯过的错**. 这次审计还找出三处硬性能力上限: 搜索深度 (数独在给定数少于 27 时断崖式下跌), 全局约束整合 (Skyscrapers 在 n = 6 时断崖), 以及生成性词汇; 并发现对这类受能力上限约束的题, 专家级的提示工程完全没有作用. 这与 Seed1.5-Thinking 的附录里验证器要先推导再判断是同一个道理: 分数低时先查判分器, 判分器没问题再查能力, 而**能力上限不会被提示词挪动**. **Kernel Loop** 在 H800 的分页 attention decode 上, 调优后 1.36 ms, 显存带宽利用率 MBU 94%, 比 eager PyTorch 快 5.90×, 与 FlashAttention-3 持平; decode 受访存限制, Doubao-1.5-pro 产品页的四象限图里就这样标过, 这里用的指标正是带宽利用率. 这些循环都说 「无人工干预」, 但目标和质量门槛由人定, 门槛设得宽, 循环就容易 「成功」, 所以这一节展示的是过程, 不能当作能力分数引用.

## 5. 案例和安全

正文和附录有十几个案例: 回测应用, Android 内存泄漏重构, 硬件问答, PySINDy 功能开发, 振荡积分中的张量构造, 以及教育, 金融, 法律, 医疗, 航空和政务排程任务. 这些案例附了执行轨迹的重建, 能看到过程质量: 回测案例里模型发现买入持有 +3742% 而策略 −98%, 没有直接交付, 而是查出均线窗口没预热; 硬件案例里它放弃二手博客, 去解析官方原理图和装配图. 但每类任务跑了多少次, 成功多少次, 卡里没说. 数学案例由研究者独立核验, 证据等级最高, 表 6 的 HorizonMath 只有 2.0 则提醒它不代表稳定能力.

安全相关的内容只有表 5 的 CyberGym 一行: GPT-5.5 81.8, Claude-4.7 Opus 73.1, Seed2.1-Turbo 67.0, Pro 70.2, 放在编程 agent 基准里当作能力报告, 没有阈值, 也没说用于什么发布决策. 对一个以 agent 在真实工作流里自主执行为主线的发布来说, 长程工具使用, GUI 操作和一个多月的自主循环都会带来越权和不可逆动作的风险, §2.5.2 自己也说 「每一步都可能是一次不可逆错误」, 卡里没有配套的安全评测. Agent 安全的一般讨论见 [Agent 安全与对齐](../../../../llm-guide/13-Agent/13.5-Agent应用与治理/13.5.3-Agent安全与对齐.md).

## 6. 这一代在谱系里的位置

同名基准上, Seed2.1 Pro 的进步集中在仓库级编程 (NL2Repo-Bench 27.9 到 47.0, SWE-Bench Pro 46.9 到 57.5), 抽象推理 (ARC-AGI-2 37.5 到 62.5) 和大部分视觉基准; 知识类基本持平, 视频有四行下降, 最难的编程 agent 基准和研究型数学 (HorizonMath 2.0 对 GPT-5.5 的 7.1) 仍明显落后. 换了版本或设定的行 (Terminal Bench 2.0 与 2.1, HLE 带不带工具, IMO 的两种单位) 不能与 Seed2.0 相减; 正文与表冲突时以表为准.

从 1.5 代读过来, Seed2.1 延续的是三条线. 视觉 grounding 和 GUI 数据长成了通用 CUA; 长视频的 token 预算变成 agent 自己管理的多模态 harness; 验证器从奖励侧走到推理侧, 再变成 Deep Think. 这三条线的共同点是把越来越多的能力放在 harness 和推理时的流程里, 所以**分数里有相当一部分来自设定而不是模型本身**. 配方仍不公开, Seed for Seed 露出的规则清洗, SFT 扫参和 RL 框架改写, 只说明这些环节存在, 以及模型开始参与其中.

和 Seed2.0 卡比, 这一代公开的东西在两个方向上变了. 训练侧多露出一角: 预训练仍有规则清洗, SFT 按学习率和数据配比扫参, agent 能力靠持续扩充的交互环境, 失败轨迹会回流成训练数据. 评测侧则更依赖自家的尺子和 harness: 对手分数在 OpenClaw 设定下重跑, 多模态 harness 能让同一模型差出 8 分, 自研集用 Agent-as-Judge 判分, 众测对手的版本前后不一. 读这一代的分数, 先问三件事: 同名基准的定义变没变, 对手是哪一个版本, 分数是在谁的 harness 里跑出来的. 三件事都对上了, 两代之间的差距才能当作模型的进步来读.
