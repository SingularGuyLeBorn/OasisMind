# Seed1.5-VL: 给一个现成的 20B 激活 MoE 装上眼睛

来源: [Seed1.5-VL Technical Report](https://arxiv.org/abs/2505.07062) (arXiv:2505.07062v1, 2025-05-11; 文首日期 June 13, 2025; 模型 ID doubao-1-5-thinking-vision-pro-250428). 逐段对照译稿见同目录 `seed-1-5-vl-bi.md`. 表号, 图号, 式号都指原报告编号, 数字以源文 `seed-1-5-vl.md` 为准.

## 1. 在家族里的位置: 视觉线和推理线在这里汇合

1.5 代的视觉能力最早出现在 2025 年 1 月的 Doubao-1.5-pro 产品页: 自研 2.4B 的 Doubao ViT, 原生动态分辨率, 混入纯文本保语言能力, 后训练偏重 RL. 4 月的 Seed1.5-Thinking 则把长 CoT 的推理 RL 写成了完整配方. Seed1.5-VL 的模型 ID 是 doubao-1-5-thinking-vision-pro, 名字里同时有 thinking 和 vision, 报告也同时报 thinking 与 non-thinking 两种模式. 从谱系上看, **它是视觉线和推理线的第一次汇合**. 2026 年 Seed2.0 模型卡的引言把 Seed1.5-VL 列为支撑产品的家族成员之一, 可见它在对外报告里是 1.5 代视觉的主线.

汇合的方式是 **「事后适配」**. §3.2 开头把多模态训练分成两条路: 从一开始联合训练, 或先训好语言模型再适配视觉; Seed1.5-VL 选后者, 理由是方便消融, 迭代快. 语言模型从一个激活约 20B 的内部 decoder-only MoE 初始化, 已在数万亿纯文本 token 上训过. Seed1.5-Thinking 同样是激活 20B 的 MoE, 两者是否同一底座, 两篇报告都没说, 这里只记为同一量级. 视觉编码器没有沿用 pro 产品页的 2.4B Doubao ViT, 换成了 532M 的 **Seed-ViT**, 报告反复强调 「紧凑」, 这是 1.5 代视觉线在编码器规模上的一次取舍.

## 2. 模型与编码器

### 2.1. 架构: 一条很窄的接口

模型只有三个部件: Seed-ViT, 两层 MLP adapter, 语言模型. §2.1.1 的数据流是: 图像先用双线性插值调到最接近的 28 像素倍数, 切成 14 像素的 patch; 多张图的 patch 序列按 **NaViT** 的做法拼成一个长序列, 用注意力掩码隔开; 经过表 1 规格的 transformer (深度 27, 宽度 1280, 20 个头, 每头 64 维, MLP 比 4.0, 2D RoPE) 之后做 2×2 平均池化, 再过两层 MLP 进入语言模型. 视觉 token 和文本 token 拼在同一条序列里, 没有 cross-attention 支路, 也没有 Q-Former 式的可学习查询. 视觉 RoPE 见 [视觉与多模态扩展](../../../../LargeLanguageModelGuide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md), 其他 token 压缩做法见 [QFormer 与视觉 Token 压缩](../../../../LargeLanguageModelGuide/8-多模态/8.2-视觉语言模型/03-QFormer与视觉Token压缩/03-QFormer与视觉Token压缩.md).

表 1 能粗略验算 532M: 每层注意力约 4d², MLP 比 4 时约 8d², 合计 12d²; d = 1280 时每层约 19.7M, 乘 27 层约 530.8M, 再加 patch 嵌入, 与 532M 吻合. 所以 Seed-ViT 是一个标准宽度的 ViT, 没有窗口注意力或分支结构, **原生分辨率能力全部来自 2D RoPE 和 NaViT 式打包**. 2×2 池化用平均, 不引入参数, 可学习的对齐只发生在两层 MLP 里. §2 给出保留编码器的理由: 无编码器架构结果好坏参半, 训练效率吃亏, 编码器能先把图像压缩一遍. 这里的压缩有具体数字: 进 LLM 的每个视觉 token 对应 28×28 像素, 比直接喂 14 像素 patch 少四倍序列长度.

第二条设计原则是编码器架构在 ViT 预训练和 VLM 阶段完全一致, 不替换位置编码, 不做插值. 很多同代模型拿固定分辨率预训练的编码器, 接入 VLM 时再把 1D 位置嵌入换成 2D RoPE 或插值到新形状, 这一步会引入不一致. Seed1.5-VL 把原生分辨率建模提前到 ViT 预训练的第一阶段, 接入语言模型时编码器不改结构. 语言模型这一侧, 报告只给了激活参数, 总参数, 专家数和路由方式都没披露. §6.3.2 拿它和 Llama 4 Maverick (报道为 17B 激活) 比规模, 所以 **「紧凑」 指每 token 实际参与计算的参数量, 不是存储量**.

### 2.2. 编码器怎样训出来: MIM, 对比学习, 全模态

Seed-ViT 在接入语言模型前单独走三个阶段 (§2.1.2, 表 2). 第一阶段是**带 2D RoPE 的 MIM**: 学生随机初始化, 以 EVA02-CLIP-E 为教师, 遮掉 75% 的 patch, 用余弦相似度让学生在被遮位置重建教师的 CLIP 特征. 教师用可学习位置嵌入, 学生用 2D RoPE, 报告说这种不一致不伤性能, 反而让学生具备原生动态分辨率识别能力. 这一阶段用 2.2B 张无标注图像, 只占 token 预算的 4.0%, 但作者说放大 MIM 后, VLM 在图表, 文档和 OCR 上明显变好. 社区把这类做法归到 「特征蒸馏式 MIM」, EVA 系列就是这样用 CLIP 特征当重建目标的.

第二阶段是**原生分辨率对比学习**, 4.8B 个图文对, 占 token 预算的 91.2%, 是 ViT 预训练的主体. 视觉侧用 MIM 学生初始化, 文本侧用 EVA-02-CLIP-E 的文本编码器初始化, 联合优化 SigLIP loss 和 SuperClass loss. 这里的注意力池化只用来得到全局嵌入, 接入 VLM 时用的是 2×2 平均池化, 两套池化互不相干. 第三阶段按 **MiCo** 框架从视频构造 「视频帧, 音频, 视觉描述, 音频描述」 四元组, ViT 同时编码帧和音频, 只有 65M 个元组, 占 4.8% 的 token, 报告说明显提升了图像和视频理解. 视觉编码器的一般做法见 [CLIP 与视觉编码器](../../../../LargeLanguageModelGuide/8-多模态/8.8-CLIP与视觉编码器/01-CLIP与视觉编码器/01-CLIP与视觉编码器.md).

表 2 的超参数把三段的性质分得很开. 批大小依次是 55,296, 32,768, 1,024; warmup 步数 1,692, 2,000, 12,800; 峰值学习率 7.06e-3, 1.0e-4, 5.0e-5. MIM 阶段学生随机初始化, 目标是余弦相似度, 可以用很大的学习率快速学出几何和结构; 对比阶段从 MIM 学生起步, 学习率降两个数量级, 避免把前一段学到的局部结构冲掉; 全模态阶段批只有 1,024, warmup 却最长, 每个元组要同时编码多帧和音频, 单样本很重, 编码器已经成形, 只需要缓慢地把音频对齐进来. 按一遍数据粗算步数 (报告没给 epoch 数): MIM 约 4 万步, 对比约 14.6 万步, 全模态约 6.3 万步.

这三段的顺序也有讲究. 先 MIM 再对比, 等于先让编码器学 「图里有什么结构」, 再学 「这些结构叫什么」; 若直接从对比学习起步, 编码器会偏向与文本描述相关的全局语义, 对文字笔画, 表格线这类细节不敏感. 作者在 MIM 一段写 「放大 MIM 后图表, 文档, OCR 明显变好」, 与这个顺序的动机一致, 但报告没有做 「去掉 MIM」 的对照表. 2D RoPE 从 MIM 第一步就在, 三段都用原生分辨率, 这让后面接入 VLM 时不用再改编码器.

表 5 用零样本分类检验这个编码器: 五个 ImageNet 系列与 ObjectNet 平均 82.5, 与 6B 的 InternVL-C 持平, 低于 17.5B 的 EVA-CLIP-18B (83.6); ImageNet-A 上 85.5 明显高于 DFN-5B CLIP-H/14++ 的 79.6. 顺带对照 pro 产品页: 2.4B 的 Doubao ViT 在同类表上平均 83.9. 两张表的对手和子集不完全一样, 不能直接相减, 但方向很清楚: 532M 的 Seed-ViT 用约五分之一的参数换来了略低的分类分数, 报告要的是接入 LLM 后的整体效率, 而不是编码器单独的榜单.

## 3. 数据

### 3.1. 数据: 按能力分桶, 用合成补标注

引言把 VLM 和 LLM 的差别说得很直白: LLM 有大量高质量文本语料, VLM 却缺同样丰富的视觉语言标注, 尤其是低层感知类概念. 对策是为 OCR, grounding, 计数, 视频理解, 长尾知识做预训练阶段的合成管线, 为视觉谜题和游戏做后训练阶段的合成. §3.1 的预训练语料共 3 万亿源 token, 按目标能力**分桶**. 通用图文桶除常规的 CLIP 分数, 尺寸, 去重和域名过滤外, 专门讨论了长尾: 表 3 的 Biotrove 沙盒用 1.1B 激活的小 VLM, 固定 12B token 预算, 随机采样时稀有物种 Rare2k 只有 10.46, 每物种最多 100 个样本并训 3 个 epoch 升到 89.41, 但常见物种掉到 60.31. 由此得出的做法是用前代 VLM 给数据打领域标签, 把占比低于平均领域频率 50% 的领域的 alt 文本复制一份. 数据工程的一般讨论见 [视觉指令微调数据工程](../../../../LargeLanguageModelGuide/8-多模态/8.2-视觉语言模型/04-视觉指令微调数据工程/04-视觉指令微调数据工程.md).

OCR, grounding, 3D 几桶大量依赖合成与自动标注. OCR 桶超过 1B 样本, 其中合成文字密集图像超过 200M, 图表超过 100M, 渲染表格超过 50M. grounding 桶里, 开源检测数据重构出 48M 样本; Grounding DINO 自动标注约 200M 样本; 指点数据约 170M 条; 计数约 8M 样本. 所有坐标归一化到 [0, 999], OCR 和 GUI 数据用同一协议, 输出坐标因此与输入分辨率解耦. 视频桶有三类流式数据: 交错描述与问答, 主动推理 (逐帧判断何时回应), 实时解说; STEM 桶有 3.2M 条教育类 grounding, 4.5M 张化学结构图, 超过 100M 道 K12 习题; GUI 桶主要来自 UI-TARS. 这些桶和后面的评测亮点一一对应, 读评测时要把这层对应放进去.

### 3.2. 数据桶的内部: 合成管线和样本长度

表 3 的中间一行常被略过, 但它才是最终方案的原型. Max1k-46M 把每个物种封顶 1,000 个样本, 总量和随机采样一样是 46M, 常见物种 79.17 几乎不变 (随机采样是 78.92), 稀有物种从 10.46 升到 44.85. Max100-15M 把稀有物种推到 89.41, 代价是常见物种掉 19 分. 作者最后的做法是给低频领域的 alt 文本复制一份, 而不是给常见领域大幅减量, 取向更接近 Max1k: 常见概念保持足够多样, 稀有概念多见几次. 这个沙盒用的是 1.1B 激活的小模型和 LLM 裁判的开放问答, 结论能否原样放大到 20B 激活, 报告没有验证.

OCR 桶的合成分几条线. 文字密集图用 SynthDog 和 LaTeX 渲染, 覆盖手写, 艺术字和非拉丁文字, 再加模糊, 摩尔纹和透视, 弯折, 褶皱等畸变; 图表一部分用 ECharts, Matplotlib 生成, 另一部分让 LLM 先写标题, 图例等文本部件, 再转成 LaTeX 或 Python 代码执行出图; 表格从网页 HTML, GitHub README 和 arXiv LaTeX 里抽文本, 渲染成图, 训练模型转回 HTML, LaTeX, Markdown. 在这些结构化数据之上, 还用前代 VLM 以少样本提示按 OCR 结果, 图表内容和表格文本出问答对, 再由内部 LLM 过滤问答不相关的样本. 作者说这份 VQA 数据显著提升了读图中文字的能力. 前代模型出现了三次: 给 alt 文本打领域标签, 检查开源检测数据的框, 以及生成 OCR 问答, 这与 Seed1.5-Thinking 用 Doubao-Pro 1.5 过滤题目是同一种做法.

grounding 桶的 token 数能读出样本形态. 开源检测重构 48M 样本 41B token, 每样本约 850 token; Grounding DINO 自动标注 200M 样本 200B token, 每样本约 1,000; 指点 170M 条 110B token, 每条约 650; 计数 8M 样本 13B token, 每样本约 1,600. 一张约 1000×1000 的图就要一千多个视觉 token, 所以大部分样本接近 「一张图加一小段指令」. 计数样本最长, 因为 「先指点后计数」 的格式要把每个目标的坐标都写出来再报总数, 输出长度随目标数增长. 这四项合计约 3,640 亿 token, 按 3 万亿源 token 算约占 12%, 计数数据是从前两者抽样的, 实际占比略低.

3D 与 STEM 桶同样按 token 计量. 相对深度排序从 2M 张网络图用 DepthAnything V2 推深度, 只取深度差超过 20% 的物体对, 共 3.2B token; 绝对深度来自公开数据的深度图, 18M 条指令 28B token; 3D grounding 770K 条 1.3B token. 相对深度只要 20% 以上的差距, 是在避开伪标签本身分不清的近邻对, 这是用弱模型造数据时常见的保守阈值. STEM 桶除前面提到的几项外, 还有 300 类教育 grounding, 10M 张结构化表格, 1.5M 张坐标系图, K12 描述里 100,000 条人工描述和 1M 条机器描述. GUI 桶来自 UI-TARS, 每张截图配元素类型, 框, 文本和层级, 叠加 Set-of-Mark 标记, 推理部分是带观察, 中间思考和动作的多步轨迹. 各桶在阶段 1 和阶段 2 里怎样配比, 报告只给了定性描述, 没有比例表.

### 3.3. token 预算: 分辨率怎样变成序列长度

图像侧没有固定 token 数, 分辨率对齐到 28 的倍数后, token 数就是 (H/28)×(W/28). 一张约 1000×1000 的图约 1,300 个视觉 token, 一张 2000×1000 的截图约翻倍. 报告没给单张图的分辨率上下限. 视频侧有明确预算: §2.2 的**动态帧率-分辨率采样**把一个视频的上限定在 81,920 token, 每帧从六档里选 {640, 512, 384, 256, 160, 128}; 帧率按任务切换, 默认 1 FPS, 需要细致时间信息的 2 FPS, 计数和运动跟踪 5 FPS. 81,920 除以 640 是 128 帧, 除以 128 是 640 帧; 超过预算时在整段视频上均匀抽帧. §6.1.3 的 「128K 上下文最多 640 帧」 与此一致. 视频理解的一般做法见 [视频理解模型](../../../../LargeLanguageModelGuide/8-多模态/8.4-视频理解模型/8.4-视频理解模型.md).

每帧前面还有一个**时间戳 token** (如 [1.5 second]). 帧与帧之间的真实时间间隔不靠位置编码隐式表达, 而是写成文本, 帧率可以随任务改, 不用重新定义位置语义. 视频 grounding 数据也按秒直接预测起止时间, 输入端和输出端用的是同一种时间表达. 空间上 28×28 像素换一个 token, 时间上按任务选帧率, 总量受上下文约束, 这套预算保住了 OCR 和细粒度定位需要的细节 (表 6 的 DocVQA 96.9, InfographicVQA 91.2), 也把长视频的成本直接暴露在序列长度上: 表 7 里 VideoMME 77.9 对 Gemini 2.5 Pro 的 87.0, 是视频类差距最大的一行. 高分辨率的一般难点见 [高分辨率 VLM 的技术挑战](../../../../LargeLanguageModelGuide/8-多模态/8.2-视觉语言模型/05-高分辨率VLM的技术挑战/05-高分辨率VLM的技术挑战.md).

## 4. 训练

### 4.1. 预训练: 三阶段节奏和按桶拟合的 Scaling 曲线

表 4 把 VLM 预训练分三段. 阶段 0 用 16B token 只训 MLP adapter, 编码器和语言模型冻结; 阶段 1 用 3T token 全参数训练, 主要是描述, 交错图文, grounding 和 OCR; 阶段 2 用 240B token, 配比更均衡, 加入视频, 代码和 3D 空间理解, 序列长从 32,768 提到 131,072. 两个经验值得记下: 阶段 1 混入约 5% 纯文本 token 就能维持语言能力; 预训练里加少量指令跟随数据能让评测更可靠, 从而把预训练开发与后训练开发解耦. 报告还做了一个对照: 像 Qwen2-VL, InternVL 那样在阶段 0 同时训 adapter 和编码器, 效果更差. 作者的解释是编码器会去补偿冻结 LLM 的不足, 从而损害感知能力. 继续预训练的一般讨论见 [继续预训练](../../../../LargeLanguageModelGuide/3-预训练/3.5-继续预训练与长上下文训练/3.5.1-继续预训练/3.5.1-继续预训练.md).

表 4 的日程可以换算成步数. 三段的批大小分别是 8.4M, 71M, 71M token, 所以阶段 0 约 1,900 步, 阶段 1 约 42,000 步, 阶段 2 约 3,400 步. 优化器三段都是 AdamW, β1 = 0.9, β2 = 0.95, weight decay 0.1, 偏置和归一化参数不做衰减. 学习率的安排是: 阶段 0 从 2.52e-4 余弦降到 4.50e-5, 只动 adapter, 可以用大学习率; 阶段 1 从 5.22e-5 余弦降到 5.22e-6, 整整降一个数量级; 阶段 2 直接从阶段 1 的终点 5.22e-6 起步并保持常数, 加载阶段 1 的优化器状态, 所以不需要 warmup.

阶段 2 这种安排值得多说一句. 它在数据上换了配比, 加了视频, 代码和 3D, 序列长度还从 32K 拉到 128K, 按常理这些变化都容易引起 loss 尖峰. 作者的做法是把学习率压在阶段 1 的最低点, 并保留 Adam 的一阶, 二阶矩估计, 让优化器不从零开始重估梯度尺度. 这相当于在一个已经收敛到低学习率的点上做小步的继续训练, 新数据和长上下文靠数据本身带进来, 而不靠一次新的学习率周期. 3,400 步只占总步数的 7% 左右, 阶段 2 在这里扮演的是 mid-training 的角色. 报告没有给出这种做法与 「重新 warmup」 的对照.

阶段 0 的必要性报告只给了一句: 跳过它, loss 略高, 效果略差. 阶段 1 的 3T token 与语料的 3 万亿源 token 数字相同, 但源 token 经过复制和各桶上采样后不等于训练 token, 所以不能直接读成 「恰好一个 epoch」. 5% 纯文本这条经验和 Doubao-1.5-pro 产品页 「混入纯文本保语言能力」 是同一件事的两次表述, pro 页没给比例, 这里给了.

§3.3 的 Scaling 分析只看阶段 1. 模型结构固定, 式 (1) 退化成只依赖训练 token 数 D 的式 (2), 取对数后是直线. 按能力分桶后, OCR 与 grounding 的训练 loss 斜率分别是 −0.1817 和 −0.0785: token 翻倍时, OCR loss 约降 11.8%, grounding loss 约降 5.3%. 第二层关系更实用: 子类 loss 与下游指标近似 log-linear, 例如 ChartQA 准确率约等于 −0.0968 log(loss_ocr) + 0.7139. 这给了预训练期间一把廉价的尺子, 看分桶 loss 就能大致判断对应能力的走向. Scaling Laws 的一般形式见 [Scaling Law](../../../../LargeLanguageModelGuide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).

报告对这把尺子的适用范围说得很克制. 准确率有上界, log-linear 只在局部成立; 图 3 的指标是预训练后的分数, 与 RL 之后的最终结果不能比. 更关键的是, **只拟合了数据维度, 没有改变模型大小**, 所以回答不了 「参数翻倍收益多少」. §6.3.2 用 「3 万亿 token 后 loss 仍无饱和迹象」 支持继续放大, 这句话的证据来自数据维度, 模型维度的收益是推断.

### 4.2. 后训练: Seed1.5-Thinking 的配方搬到视觉上

图 4 是骨架: 先用冷启动数据训 SFT 模型, 再做在线 RL, 把 RL 模型在新难题上答对的回答收回来并入下一版 SFT, 迭代到 prompt 池耗尽, 当前版本已过 4 轮. SFT 数据很小: 众包约 13,000 条, 从约 1.5M 条开源数据筛出约 30,000 条, 加上 self-instruct 合成的复杂 prompt, 多模态部分约 50,000 条, 与内部纯文本 SFT 和 LongCoT 数据合并训 2 个 epoch; SFT 时视觉编码器冻结. 通用指令和 LongCoT 各配一个 system prompt, 同一个模型可以切换是否长思考. 表 6 的 thinking 与 non-thinking 两列就是这个开关的两端.

SFT 数据的来路比数量更有信息. 众包的 13,000 条按一张 「能力分类表」 收集, 分类表综合传统视觉任务和 VLM 的实际用法; 开源部分先用自有的图文嵌入模型聚类, 按任务类别降采样保多样性, 再让对齐过的 SFT 模型多次 roll-out, 以原始标准答案为参照用 LLM-as-a-judge 判对错, 最后用奖励模型挑出最符合人类偏好的回答, 这就是 rejection sampling fine-tuning 的数据. 150 万条开源数据只留 3 万, 其余提前放进预训练. 之后随预训练能力变强, 逐步减少单一能力就能答的简单 prompt, 用 self-instruct 把几个简单 prompt 按逻辑结构组合成复杂 prompt, 回答再经人工二次核验. 作者特别说明, 核验时会剔除超出模型当前能力的数据, 以降低幻觉风险.

SFT 的训练日程写得完整: 序列长 131,072, 批大小是序列长的 16 倍, 约 2.1M token; AdamW 参数与预训练相同; 前 10% 步 warmup, 然后余弦从 2e-5 降到 2e-6. 这组学习率与 Seed1.5-Thinking 的 SFT 完全一样, 两份报告相隔一个月, 可以看作同一套后训练流程的两次使用. 视觉编码器在 SFT 时冻结, 只在预训练阶段 1, 2 里跟着全参数一起动.

RLHF 这一路的奖励模型是**生成式**的: 用指令微调过的 VLM 初始化, 直接输出 「哪条更好」 的指示 token, 两种顺序都算一遍抵消位置偏置. 偏好数据一半来自人工 5 分制排序, 一半来自有标准答案的 prompt, 按 「格式对答案对, 格式对答案错, 格式错」 三档自动排序. RL prompt 还要过一道筛: K 个回答中最高奖励与平均奖励之差低于阈值的丢掉, 只留奖励模型有区分力的题. 这和 Seed1.5-Thinking 删掉 「奖励方差低」 的 prompt 是同一个思路. RLVR 这一路给视觉任务造可验证答案: 视觉 STEM 题去掉选项, 每题采 16 个回答, 只留 SFT 模型答对 1 到 12 次的题, 用 sympy 比对; grounding 用 IoU 当奖励; 视觉谜题合成 20k 以上; 「找不同」 游戏既要文字解释也要输出差异区域的框. RLVR 的一般讨论见 [RLVR 的局限性与探索边界分析](../../../../LargeLanguageModelGuide/4-后训练/4.5-GRPO家族与RLVR/09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md).

偏好数据的细节里有几处针对奖励模型弱点的设计. 人工标注前, 候选回答先按编辑距离, 语义相似度和长度均衡过滤, 保证候选之间真有差别; 标注员除了排序, 还要选出 「改动最少就能变好」 的那一条, 并标出幻觉, 信息量等问题, 奖励模型先给出预排序供标注员参考. 合成偏好刻意没有用 「故意改错」 造正负对, 理由是奖励模型会学到 「改过的和原始的」 之间的表面差异而非质量; 改用有标准答案的 prompt 采 K 次, 按对错和格式三档排序, 描述任务另按 FeedQuill 造偏好对降幻觉, 所有合成偏好再按偏好强度精修. 奖励模型输出指示 token, 作者说它比 Bradley-Terry 标量模型更稳, PPO 时还会把标准答案或 SFT 模型的 best-of-N 回答作为参考答案一并给奖励模型.

RL 的 prompt 从偏好数据里来, 作者观察到 prompt 分布的覆盖面对 RL 结果影响很大. 流程是: 训一个打标签模型给 prompt 标能力类别, 分层抽样平衡各类; 用内部最强模型对每题采 K 个回答, 按 「最高分减平均分」 过滤; RL 初期, 奖励和 KL 同时快速上升的 prompt 被视为偏简单, 降采样. 最后一条与 Seed1.5-Thinking 删掉 「在 Doubao 1.5 Pro 的 RL 中奖励涨幅已过阈值」 的 prompt 如出一辙, 区别是那边离线删, 这边在线降权. 视觉 STEM 题超过 100 万道, 大部分是数学, 除了去选项和按 SFT 准确率筛题, 还专门删掉只看文字或只看文字加描述就能答对的题, 防止 RL 强化文字捷径. 找不同游戏的训练对有两种来源: 开源图随机遮挡后用扩散模型补全, 再滤掉补得太像原图的; 修改 SVG 的线宽, 尺寸等属性, 制造细微差异.

两路在 §4.4 合进一个 **PPO 变体**. 格式要求 &lt;think&gt; 思考 &lt;/think&gt; 解, 不守格式奖励置零; 通用 prompt 交给奖励模型, 可验证 prompt 交给验证器, 送奖励模型时截掉思考只留解, 即只监督结果不监督 CoT. 两类奖励都在 [0, 1] 里, 共用一个 critic, 用奖励模型权重初始化并预热 100 步; KL 系数通用 prompt 1e-5, 可验证 prompt 0; 每个 episode 采 4,096 条 roll-out, mini-batch 512. 和 Seed1.5-Thinking 对照: 同样是带 critic 的 PPO, 同样是生成式奖励加验证器, 同样要求两类奖励同尺度. 报告最后一句值得注意: **RL 只用 LongCoT 回答训练, non-thinking 回答也明显变好**. PPO 本身见 [PPO](../../../../LargeLanguageModelGuide/4-后训练/4.4-强化学习基础/04-PPO/04-PPO.md).

混合 RL 的日程是这一代 Seed 报告里给得最全的一组. 上下文长 8,192, 最大输出 16,384; 每个 episode 4,096 条 roll-out, mini-batch 512, 每个 episode 做 8 次梯度更新, 4,096 除以 512 正好 8, 即每条 roll-out 在一个 episode 里只用一次 (读法); PPO clip 范围 0.2; actor 学习率 6e-7, critic 7.5e-7. 每个 prompt 的采样数不同: 奖励模型打分的通用 prompt 只采 1 次, 验证器打分的采 4 或 8 次, 难题需要更多探索. clip 用的是对称的 0.2, 报告没有提 Clip-Higher; 可验证 prompt 的 KL 系数设为 0, 与 DAPO 去掉 KL 项的思路一致, 通用 prompt 保留 1e-5 的小 KL 防 reward hacking.

§4.5 把 RL 和 SFT 串成迭代. LongCoT 的冷启动 SFT 最早只有少量质量不高的样本, 由 base 模型在几条人工示例上做上下文提示生成; 作者观察到冷启动越强, LongCoT RL 之后的最终模型越强, 所以每发布一版 RL 模型, 就用数据管线收集新难题, 用 RL 阶段同一套验证器确认答对的回答, 再用手写正则去掉无限重复, 过度思考和其他语言瑕疵, 并入下一版 SFT. 这和 Seed1.5-Thinking 的 「几十条种子, 训出助手, 再拒绝采样」 是同一个循环, 只是这里把循环显式写成了四轮迭代. Seed1.5-Thinking 的表 3 提醒过, 从 RFT 模型直接起 RL 更早饱和; 这里 RFT 数据进入的是下一版 SFT, 不是直接当 RL 起点, 两份报告在这一点上并不矛盾.

### 4.3. 系统: 为视觉与语言的不对称设计并行

第 5 节的出发点是不对称: 编码器 532M, 语言模型激活 20B, 每个样本的图像数和分辨率还不一样. 现有框架要么把编码器当预处理, 要么完全拆开, 都会负载不均. Seed1.5-VL 分开并行: 编码器和 MLP 用 ZeRO 数据并行, 语言模型用专家并行, 交错流水线并行, ZeRO-1 和上下文并行组成的 **4-D 并行**. 把小编码器塞进流水线某一级, 会让那一级比其他级重, 这是分开的理由. MoE 并行的一般做法见 [MoE 系统与并行](../../../../LargeLanguageModelGuide/6-训练与推理优化/6.1-训练基础设施/6.1.8-MoE系统与并行/6.1.8-MoE系统与并行.md).

编码器侧的负载均衡用经典贪心: 按每张图的 FLOPs 降序, 依次分给当前负载最低的 GPU, 只在 128-256 张 GPU 的组内均衡. 数据加载也按并行结构改: 流水线组内只有一张卡读数据, 其余广播元数据; 编码器纯数据并行, 每张卡只处理自己那份图像. pro 产品页说动态分辨率的负载优化让训练吞吐提升 60% 以上, 这里给的是具体算法, 两者是同一个问题. 算力按 H800 折算: VLM 预训练 1.3M GPU 小时, RL 60k, 奖励模型 24k, RL 约为预训练的 4.6%; 不含 Seed-ViT 的独立预训练和语言模型自身的纯文本预训练. 后训练框架基于 verl, rollout 用 vLLM, 验证器以独立进程部署.

系统的其他部分偏向稳定性. 数据加载器按并行结构去重之外, 还在把批次搬上 GPU 前先滤掉本卡用不到的图像, 减少 PCIe 流量, 并用预取器让 IO 和计算完全重叠; 通用优化包括用于上下文并行的高性能 attention kernel, 选择性激活重计算和卸载, kernel 融合与细粒度通信重叠. 容错交给 MegaScale 框架, 检测到软硬件故障就从最近一次成功的 checkpoint 恢复, checkpoint 的保存和加载用 ByteCheckpoint, Seed1.5-Thinking 的训练系统里也有它. RL 框架是 single controller 管各 RL 角色之间的数据流, multi-controller 管角色内部的数据和模型并行, 这与 Seed1.5-Thinking 所说的 HybridFlow 是同一个抽象; actor 和 critic 用 3-D 并行更新, rollout, 奖励模型和参考模型推理用带张量并行的多副本.

从算力比例看这一代的重心. RL 60k GPU 小时加奖励模型 24k, 合计约为 VLM 预训练 1.3M 的 6.5%. 同一个语言模型底座的纯文本预训练和 Seed-ViT 的三段预训练都没计入, 所以真实的 「后训练占全流程比例」 更低. 与此相对, 长思考后训练在部分推理任务上带来的变化接近十分 (如下文的 Video-MMMU). 算力比例小, 评测上的影响大, 这是读法而非报告的结论, 报告没有给出 「只做 SFT 不做 RL」 的对照.

## 5. 评测与局限

### 5.1. 评测: 38/60 的三个分母

38/60 有三个分母: 视觉语言 21/34, 视频 14/19, GUI agent 3/7, 分别对应表 6, 7, 8. 视频类胜率最高, GUI 最低. 另一个分母藏在列里: Seed1.5-VL 同时报 thinking 和 non-thinking, SOTA 按较高者算, 对手每家只有一列. 对照条件也不完全相同: 表 6 带星号的分数是 2025 年 4 月 API 自采, Gemini 2.5 Pro 选了 MMMU 更高的 03-25 版; 表 8 里 UI-TARS 1.5 在 7 项中有 4 项高于 Seed1.5-VL, 而 GUI 数据本身就来自 UI-TARS, 正文把结论收窄到 「基础 VLM」. VLM 评测的一般问题见 [VLM 的评测与基准](../../../../LargeLanguageModelGuide/8-多模态/8.2-视觉语言模型/06-VLM的评测与基准/06-VLM的评测与基准.md).

表 10 的内部基准给了另一种读法. 13 个子类加权平均, 按表中权重可以复算出 Seed1.5-VL 59.3, Gemini 2.5 Pro 61.6. 权重最高的是 OOD (0.15), 恰好是 Seed1.5-VL 领先的一项. 裁判是 LLM, §6.3.1 说选择题一致率平均超过 95%, 开放题超过 90%, 但表 11 里文本指令 「输出格式」 一格只有 75.4%. 所以**内部基准上 1 分以内的差距落在裁判误差之内**. 评测口径的一般讨论见 [评测科学与证据](../../../../LargeLanguageModelGuide/5-评测-安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

各表的解码和采样协议不同. 表 6 除 Claude 3.7 Sonnet 用推荐的默认采样外, 全部贪心解码, 报 Pass@1; FSC-147 计数用 MAE, NYU-Depth V2 用 AbsRel, 越低越好. 表 7 的视频评测帧率是分数据集定的: MotionBench, MVBench, TOMATO, TVBench 用 2 FPS, Dream-1K 用 3 FPS, 其余 1 FPS, 视频 grounding 报 mIoU; 由于 API 超时和视频处理错误, Gemini 2.5 Pro 没能跑全, 表中对手分数取公开报告与自采中较高者. 表 8, 表 9 的 agent 评测只用 thinking 模式; 表 9 的 14 个 Poki 小游戏每局最多 100 步, 多次运行取平均. 内部基准有 100 多个任务, 12,000 多个样本, 做了去重并定期换题, 图像尽量来自非公开抓取. 这些协议决定了哪些数能横向比: 同一张表里带星号的自采分和引用分, 本就不是同一次运行.

**thinking 与 non-thinking 的差别不是一边倒**. 知识推理类任务上长思考帮助明显, Video-MMMU 从 72.1 升到 81.4; 感知和实时类任务上反而可能吃亏, StreamingBench 主动回应子任务 non-thinking 82.8, thinking 只有 68.0, SUN-RGBD 3D 检测 non-thinking 33.5 AP@15, thinking 降到 32.0, DA-2K 与 NYU-Depth 也是 non-thinking 略好. 主动回应要求模型在流里判断 「现在该说话」, 先想一大段再开口正好与任务冲突. 这组对照说明, 同一个模型里放一个长思考开关是必要的, TestingTime 多花的算力只在需要推理的任务上换得到收益.

agent 表里还有两处要读细. 表 9 的 Hex-Frvr 一行, Seed1.5-VL 1414.0 高于 CUA 和 Claude, 但低于 UI-TARS-1.5 的 1583.7, 正文只拿前两者做对比. 图 6 把各游戏按参考分归一化后平均, 画出交互轮数增加时分数的变化, 作者称之为 inference-time scaling, 按本库用词这属于 TestingTime 的一种: 不是思考更长, 而是交互步数更多. 另有一项接入搜索工具的有用率评测, 作为豆包用户场景的代理, Seed1.5-VL 62.6%, Gemini 2.5 Pro 0325 57.4%, 样本数和评判方式报告没给.

### 5.2. 局限和留给后代的接口

§6.4 的局限可以归成三类. 细粒度感知: 不规则排列, 颜色相近或遮挡时计数不准, 找不同漏细节; 计数数据走 「先指点后计数」 的格式, CountBench 拿到 93.7, 但遮挡时指点本身就会漏. 时间与多图推理: 分不清连续动作的先后, 难以综合多图中强相互依赖的线索. 需要搜索或想象的推理: 图 27 的质数谜题只有 1024 种组合, 模型却给出错误解; 图 26 画的是非标准的残差连接, 模型却按标准 Transformer 写出代码, **语言模型的先验压过了视觉证据**, 这是事后适配路线天然要面对的张力.

结论给出的下一步是: 放大模型参数与训练算力, 把理解与图像生成统一以支撑视觉 CoT, 纳入稳健的工具使用. 后代的模型卡只露出了其中一部分: Seed2.0 卡里 VideoCut 让模型在推理时回放视频片段, TOMATO 上试了逐帧输出目标框的 Thinking with Tracking; Seed2.1 卡的多模态 agent harness 提供高分辨率渲染和按需加载的媒体工具. 这些都是 TestingTime 一侧的工具化, 与这里 「代码和外部工具接进 VLM」 的方向一致. 但 Seed2.0 和 Seed2.1 都没有再披露编码器, token 预算和训练配方, Seed1.5-VL 仍是 Seed 视觉线里接口写得最完整的一份.
