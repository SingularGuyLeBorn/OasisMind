# Llama 3.1 目录说明: 与 llama3 同源

## 1. 两份源文是同一个文件

`llama3-1/llama3-1.md` 和 `llama3/llama3.md` 都是 384318 字节, SHA256 前缀都是 6db6ff9cd19703cb. 字节相同意味着标题, 表格, 公式, 图路径, 页标一个字符都不差, 不存在 「3.1 版多写了一段」 这种情况.

同样比过的还有 PDF 和图: 两份 PDF 都是 9833173 字节, SHA256 前缀 481f1599468f95a0; 两边 `images/` 各 39 个文件, 文件名集合相同, 逐个哈希也相同. 源 md 引用的 39 条图路径和这 39 个文件一一对应.

## 2. 为什么会有两个目录

论文是 arXiv 2407.21783v3, 标题 The Llama 3 Herd of Models. 第 1 页原文说全文结果都来自 Llama 3.1 模型, 为了简洁统称 Llama 3; 第 2 页表 1 把 Llama 3 (2024 年 4 月) 和 Llama 3.1 (2024 年 7 月) 的 8B, 70B, 405B 并排列出, 表注再说一遍全文结果都是 3.1.

所以 Meta 并没有给 3.1 单独出一篇技术报告. 模型库按家族版本建目录时, llama3 和 llama3-1 都指向这篇论文, 抽取时就得到了两份相同的 md, PDF 和图. 这两个目录是同一篇论文的两个入口, 内容上没有先后或增补关系.

## 3. 这份对照稿怎么读

`llama3-1-bi.md` 保留了 92 个页标, 每页一句中文说明这一页属于哪一节, 39 张图挂在原来的页上. 它的用处是对页: 拿着 PDF 翻到第 k 页, 在对照稿里找 `page k of 92`, 就知道这一页讲的是预训练数据, 并行方案, 安全评测还是参考文献.

逐段的中英对照放在 llama3 目录那一份对照稿里. 两份源文相同, 那边的每一句译文对这边同样成立, 在这里再译一遍只会产生两份需要同步维护的译稿, 以后改一处漏一处. 对照稿里的几条疑惑也都围绕这件事: 标题和目录名为何不一致, 图路径要不要改指向, 无编号碎片图为何两边都有, 页数和末条是否一致.

## 4. 目录里各文件的角色

本目录现在有五样东西: 源文 `llama3-1.md`, 原始 `llama3-1.pdf`, 图目录 `images/`, 以及新写的 `llama3-1-bi.md` 和本文件. 源 md 和 PDF 没有改动, 图也没有动, 新增的两份只做说明和对页.

图路径都是 `images/` 开头的相对路径. 本目录自带一份和 llama3 一样的图, 所以对照稿里的图直接引用本地路径就能显示, 不需要跨目录引用 `../llama3/images/`. 这样即使以后单独移动其中一个目录, 这边的图也不会断.

## 5. 以后维护时要注意的

如果将来 llama3 那份对照稿或分析稿有勘误, 这边不需要跟着改正文, 因为这边本来就不重复正文. 需要复查的只有一件事: 两份源 md 是否仍然字节相同. 可以用 `Get-FileHash` 或 Python 的 `hashlib` 比一次 SHA256, 前缀还是 6db6ff9cd19703cb 就说明没变.

如果哪天两份源文真的出现差异, 比如某一边换成了 arXiv 的其他版本, 那时再单独给差异部分写对照, 并在本文件第 1 节写明差在哪几页. 在那之前, 这个目录的读法就是去读 llama3 那一份.
