## 1. 这份报告讲了什么

「The Llama 3 Herd of Models」 是 Meta 在 2024 年 7 月放出的技术报告, 正文 70 多页, 加上贡献者名单和参考文献一共 92 页. 标题里的 herd 指一群模型: 语言模型有 8B, 70B, 405B 三个规模, 每个规模都有预训练版和指令微调版, 另外还有安全分类器 Llama Guard 3, 以及接在语言模型上的图像, 视频, 语音实验. 第 1 页先交代了一个容易混的地方: 全文所有分数都是 Llama 3.1 这一批的, 为了简洁统称 Llama 3. 2024 年 4 月那批 8B 和 70B 只在表 1 里出现, 标注为不支持长上下文和工具调用.

作者把开发一个好基础模型的抓手归成三条: 数据, 规模, 管住复杂度. 数据这一条, 预训练语料从 Llama 2 的 1.8T token 涨到约 15T 多语言 token. 规模这一条, 旗舰模型用了 3.8 x 10^25 FLOPs, 比 Llama 2 最大的 70B 多出接近 50 倍, 405B 参数, 15.6T token. 复杂度这一条落在两个选择上: 用标准稠密 Transformer 而不是 MoE, 后训练用 SFT, 拒绝采样, DPO 这套简单流程, 不用 PPO 一类更难调的强化学习算法. 整篇报告就是围绕这三条展开的.

## 2. 预训练数据从哪里来

语料的知识截止到 2023 年底. 网页数据的处理链条比较长: 先去掉个人信息多的域名和已知成人域名, 再用自研解析器从 HTML 里抽正文, 数学和代码页面单独保留公式与代码结构. 去重分三层, URL 级保留每个页面最新的版本, 文档级跑全局 MinHash, 行级仿照 ccNet, 在每 3000 万篇文档一个桶里删掉出现超过 6 次的行. 作者承认行级去重会误删一部分高质量文本, 但下游评测显示整体收益明显.

去重之后还有三道启发式过滤: 用重复 n-gram 覆盖率删日志一类的长重复行, 用脏词计数补域名黑名单的漏网之鱼, 用 token 分布的 KL 散度删异常 token 过多的文档. 再往后是模型打分, 快的有 fasttext 判断文本像不像会被维基百科引用, 慢的是用 Llama 2 标注数据训练的 DistilRoberta 质量分类器. 代码和数学另有专门的抽取管线, 多语言部分先用 fasttext 语言识别分成 176 种语言, 再按语言分别去重和过滤.

配比靠两样工具定: 一个知识分类器, 用来压低网上过多的类别 (例子是艺术和娱乐); 一套小模型缩放实验, 在候选配比上训练小模型, 预测大模型的表现, 反复几轮再拿大一点的模型验证. 最终配比约 50% 通用知识, 25% 数学与推理, 17% 代码, 8% 多语言. 这组数字在后训练部分还会被拿来对照, bi 第 22 页有一条疑惑专门区分了预训练配比和多语言 SFT 内部构成两套口径.

退火数据是另一条线. 作者发现在训练末尾用少量高质量代码和数学数据退火, 能抬高关键基准的分数, 而且刻意不放任何常用基准的训练集. 用 GSM8K 和 MATH 训练集做退火实验时, 8B 预训练模型在两个验证集上分别提升 24.0% 和 6.4%, 405B 几乎没有提升. 作者由此认为旗舰模型的上下文学习能力已经够强, 不需要领域内样本. 退火还被当成评估小数据集价值的工具: 把训练到一半的 8B 模型在 40B token 上把学习率线性降到 0, 新数据占 30% 权重, 比给每个小数据集都跑一遍缩放实验便宜得多.

## 3. 架构和表 3

架构基本沿用 Llama 2 的稠密 Transformer, 改动只有几处. 第一处是分组查询注意力 GQA, 三个规模都用 8 个 Key/Value 头, 目的是加快解码, 缩小 KV cache. 第二处是文档掩码, 同一条序列里拼接的不同文档之间不做自注意力; 作者说这一点在标准预训练里影响有限, 到超长序列的继续预训练里就变得重要. 第三处是词表, 128K 个 token, 其中 100K 来自 tiktoken, 另加 28K 服务非英语语言. 英语样本上的压缩率从 Llama 2 的每 token 3.17 个字符升到 3.94 个, 同样的算力能读更多文本. 第四处是 RoPE 的基频提到 500,000, 原文引 Xiong et al. (2023) 说明这个值在 32,768 长度以内有效.

表 3 把三个规模的超参放在一起. 8B 是 32 层, 模型维度 4,096, FFN 维度 14,336, 32 个注意力头, 峰值学习率 3 x 10^-4. 70B 是 80 层, 维度 8192, FFN 28,672, 64 个头, 学习率 1.5 x 10^-4. 405B 是 126 层, 维度 16,384, FFN 53,248, 128 个头, 学习率 8 x 10^-5. 三列共用的只有 KV 头数 8, SwiGLU 激活, 128,000 词表和 RoPE θ = 500,000. 这张表里每个规模的层数, 宽度, 头数, 学习率都是各自的数, 读的时候不能拿一个规模的数套到另一个上.

从表 3 还能算出几件原文没有直接写的事. 每个头的维度在三个规模上都是 128 (4096/32, 8192/64, 16384/128). 每组 GQA 共享 KV 的查询头数分别是 4, 8, 16, 规模越大, KV cache 相对越省. 学习率随规模递减, 405B 的峰值学习率只有 8B 的约四分之一. 作者说 405B 这个尺寸对 3.8 x 10^25 FLOPs 的预算来说大致是算力最优的, 这句话的依据在下一节.

## 4. 缩放实验怎么定下 405B

缩放实验的算力范围是 6 x 10^18 到 10^22 FLOPs, 每个预算下训练 40M 到 16B 参数不等的模型, 学习率余弦衰减到峰值的 0.1, 每步权重衰减为当步学习率的 0.1 倍, 批大小按算力档位固定在 250K 到 4M 之间. 在每个预算上画出损失随模型大小变化的 IsoFLOPs 曲线 (图 2), 用二次多项式拟合, 抛物线最低点就是这个预算下的算力最优模型.

然后假设最优训练 token 数与算力是幂律关系 N*(C) = A C^α, 拟合出 α = 0.53, A = 0.29. 外推到 3.8 x 10^25 FLOPs, 得到的建议是 402B 参数配 16.55T token. 实际训练用的是 405B 和 15.6T, 两个数都和建议值不同. 作者的解释是: 算力越大, IsoFLOPs 曲线在最低点附近越平, 模型大小和 token 数之间小幅挪动对损失影响不大, 所以最后选了 405B. bi 第 8 页的疑惑对的就是这两组数哪组算数.

这一节还有一个比较少见的做法: 不只预测损失, 还预测下游基准的分数. 分两步, 先把基准上正确答案的归一化负对数似然和训练 FLOPs 做线性相关, 再用缩放实验模型加上 Llama 2 各模型, 拟合对数似然和准确率之间的 S 形关系. 以 ARC Challenge 为例 (图 4), 这个两步预测跨了四个数量级, 最终只略微低估了旗舰模型的表现. 这意味着训练开始前就能对 405B 的某些基准分数有一个靠谱的估计.

## 5. 集群, 存储和网络

Llama 1 和 Llama 2 在 Meta 的 AI Research SuperCluster 上训练, Llama 3 迁到了生产集群. 405B 最多用 16K 张 H100, 每张 700W TDP, 80GB HBM3, 服务器平台是 Grand Teton, 每台 8 张 GPU 加 2 颗 CPU, 机内走 NVLink, 作业由全局调度器 MAST 管理. 存储用分布式文件系统 Tectonic, 7,500 台带 SSD 的服务器提供 240 PB 空间, 持续吞吐 2 TB/s, 峰值 7 TB/s. 难点是检查点写入非常集中, 每张 GPU 要存 1 MB 到 4 GB 不等的状态, 短时间内会把存储打满.

网络方面, 405B 用的是基于 Arista 7800 和 Minipack2 交换机的 RoCE, 较小的模型用 Nvidia Quantum2 InfiniBand, 两边 GPU 间都是 400 Gbps. RoCE 集群是三层 Clos: 每个机架 16 张 GPU, 192 个机架组成一个 3,072 卡的 pod, pod 内全对分带宽; 8 个 pod 再经聚合交换机连成 24K 卡的集群, 聚合层有 1:7 的超额订阅. 脚注说明预训练只用了其中最多 16K 张. 并行方式和调度器都按拓扑优化, 尽量减少跨 pod 通信.

负载均衡和拥塞控制各有一招. 大模型训练的网络流又粗又少, 传统 ECMP 哈希分不匀, 所以通信库在两张 GPU 之间建 16 条流而不是一条, 再用 E-ECMP 在 RoCE 包头里多哈希几个字段, 把这 16 条流分到不同路径. 拥塞方面, 骨干层用深缓冲交换机吸收集合通信的瞬时拥塞, 加上 E-ECMP 本身降低了拥塞概率, 最后 24K 卡集群没有启用 DCQCN 这类传统拥塞控制.

## 6. 4D 并行和流水线改造

405B 的切分用 4D 并行: 张量并行 TP 切单个权重矩阵, 流水线并行 PP 按层纵向切成阶段, 上下文并行 CP 沿序列维度切, 数据并行 DP 用 FSDP 实现. 四个维度的顺序是 [TP, CP, PP, DP], 最里面的 TP 要求带宽最高, 延迟最低, 所以放在同一台服务器内; 最外面的 DP 可以异步预取分片权重, 能容忍多跳网络的延迟. FSDP 对优化器状态和梯度做分片, 但前向之后不再重新分片模型参数, 省掉反向时多一次 all-gather.

表 4 列了三个阶段的配置. 8,192 卡时 TP 8, PP 16, DP 64, 序列 8,192, 每卡 430 TFLOPs, BF16 MFU 43%. 16,384 卡时 DP 翻到 128, MFU 降到 41%, 原因是全局 token 数要保持 16M 不变, 每个 DP 组的批变小了. 长上下文阶段序列拉到 131,072, CP 16, DP 缩到 8, MFU 38%. 四个并行度相乘都等于 GPU 数, bi 第 10 页的疑惑把三行都乘了一遍.

流水线这部分改动最多. 现有实现要求每卡批大小能被阶段数整除, 首阶段因为嵌入层和预热微批占内存更多, 末阶段因为要算输出和损失成了延迟瓶颈. 作者的改法是让同一阶段连续处理的微批数 N 可调 (图 6 里 N = 5), 首末两个阶段各少放一层 Transformer, 第一段只放嵌入, 最后一段只放输出投影和损失. 再加上交错调度, 气泡比例是 (PP - 1) / (V x M), 以及异步点对点通信和主动释放不再用的张量. 做完这些, 8K 序列的预训练不需要激活检查点.

上下文并行的做法也和常见实现不同. 序列切成 2 x CP 段, 第 i 个 CP rank 拿第 i 段和第 2 x CP - 1 - i 段, 前后搭配让因果掩码下的计算量均衡. 通信不用环形重叠, 而是先 all-gather K 和 V, 再对本地 Q 算注意力. all-gather 的延迟暴露在关键路径上, 但因为 GQA 让 K, V 比 Q 小得多, 注意力计算是 O(S^2), 通信是 O(S), 开销可以忽略, 还能方便地支持文档掩码. 数值上, 多个微批的梯度用 FP32 累加, FSDP 的 reduce-scatter 也用 FP32.

## 7. 54 天里的故障

同步训练的容错性差, 一张卡坏了可能整个作业重启. 在 54 天的快照期里, 作业一共中断 466 次, 47 次是计划内的固件升级或配置, 数据集更新, 其余 419 次是意外中断. 约 78% 的意外中断归因于确认或疑似的硬件问题, GPU 相关是最大一类, 占 58.7%. 这期间只有三次需要较多人工介入, 其余都靠自动化处理, 有效训练时间保持在 90% 以上.

表 5 是故障分类. 排前面的是故障 GPU 148 次, HBM3 显存 72 次, 软件 bug 54 次, 交换机和线缆 35 次, 主机维护 32 次. 按 419 次换算, 除了故障 GPU 这一行, 其他百分比都对得上; 148/419 是 35.3%, 表里印的是 30.1%, 百分比列加起来只有 94.9%. bi 第 13 页的疑惑把这笔对了一遍, 论文没有说明哪个数有误.

诊断工具方面, 作者大量用 PyTorch 内置的 NCCL flight recorder 把集合通信元数据和栈记到环形缓冲里, 在 NCCLX 看门狗或心跳超时时自动导出. NVLink 故障常表现为 CUDA 核里的 load/store 卡住而不报错, 所以 NCCLX 和 PyTorch 深度配合, 检测到卡住就自动超时, 并给出失败集合操作的内部状态快照. 还有一类问题是没坏但变慢的掉队节点, 一张卡慢会拖住上千张卡, 作者做了工具优先排查可疑的通信组.

两个环境因素值得记一下. 一是昼夜温差, 中午温度高影响 GPU 的动态调压调频, 405B 训练的吞吐因此有 1% 到 2% 的日内波动. 二是电力, 几万张卡同时等检查点或同时启停, 数据中心的功耗会在瞬间波动几十兆瓦, 已经碰到电网的承受边界. 作者把后者列为训练更大模型时仍待解决的问题.

## 8. 预训练的三段配方

405B 的预训练分三段: 初始预训练, 长上下文预训练, 退火. 初始阶段用 AdamW, 峰值学习率 8 x 10^-5, 线性预热 8,000 步, 余弦衰减到 8 x 10^-7, 总共 1,200,000 步. 批大小逐步加大: 开始是 4M token, 序列长 4,096; 训练 252M token 后翻倍到 8M, 序列 8,192; 训练到 2.87T token 后再翻倍到 16M. 作者说这套做法很稳, 损失尖峰很少, 不需要人为干预来纠正发散. 训练过程中还会调数据配比, 例如提高非英语和数学数据的比例, 在后期加入更新的网页数据.

长上下文阶段放在最后, 因为自注意力的计算量随序列长度平方增长, 早做不划算. 上下文从 8K 分六档加到 128K, 每一档训练到两个条件都满足才进下一档: 短上下文评测完全恢复, 以及在当前长度内完美通过大海捞针. 这一阶段总共用了约 800B token, 各档的具体长度和 token 数没有给出.

退火阶段是最后 40M token, 学习率线性降到 0, 上下文保持 128K, 同时上采样质量很高的数据源. 最终的预训练模型不是某一个检查点, 而是退火期间多个检查点的 Polyak 平均. 8B 和 70B 用的是类似的配方. 把三段合起来看, 训练过程是先稳住短序列上的大批量训练, 再把长度推上去, 最后用高质量数据收尾.

## 9. 后训练的骨架

后训练有六轮, 每一轮都是同样的步骤: 先在预训练检查点上用人工偏好数据训练奖励模型, 再用奖励模型对人工标注提示做拒绝采样, 拒绝采样数据和其他来源 (包括合成数据) 一起做 SFT, 最后做 DPO. 每轮收集新的偏好标注和 SFT 数据, 合成数据从最新的模型里采. 对话格式也重新设计了, 用新的头部和终止特殊 token 标记每条消息的来源和去向, 以支持一轮对话里向 ipython 等多个目的地发消息.

几处细节. 奖励模型去掉了 Llama 2 损失里的 margin 项, 因为数据量上去之后它的收益递减; 部分样本有三个回答, 排序是 edited > chosen > rejected, 训练时把提示和多个回答拼成一行并随机打乱. SFT 在目标 token 上算交叉熵, 提示部分不计损失, 最大模型学习率 10^-5, 训练 8.5K 到 9K 步. DPO 学习率 10^-5, β = 0.1, 有两处改动: 从 chosen 和 rejected 的损失里屏蔽格式 token, 避免尾部重复或突然输出终止 token; 在 chosen 序列上加系数 0.2 的 NLL 损失, 稳住格式和 chosen 的对数概率. 作者也试过 PPO, 结论是 DPO 在大模型上算力更省, 指令遵循类基准上表现更好. 每个阶段最后还会把不同数据版本或超参得到的模型做平均.

表 6 给了人工偏好数据的构成: 通用英语占 81.99%, 代码 6.93%, 多语言 5.19%, 推理与工具 5.89%, 平均每段对话 3.8 轮, 每个样本约 1,041.6 个 token. 标注员对偏好强度分四档, 从显著更好到略微更好. SFT 数据的构成在表 7, 通用英语占样本数的一半多, 多语言只占 3.01%, 而多语言 SFT 内部又分成人工标注, 其他 NLP 任务数据, 拒绝采样数据, 翻译推理数据四块, 占比 2.4%, 44.2%, 18.8%, 34.6%.

## 10. 按能力准备数据

第 4.3 节按能力逐项讲数据怎么来. 代码方面, 作者从主预训练分叉出一个代码专家, 在 1T token, 85% 以上是代码的数据上继续预训练, 最后几千步把上下文扩到 16K, 再用它来收集代码标注和做拒绝采样. SFT 用的合成代码样本超过 2.7M 条, 其中一条路子是执行反馈: 405B 用自己生成的数据训练没有帮助甚至会变差, 于是用解析器, lint 和单元测试的结果作为判据, 失败了就让模型带着报错改, 约 20% 的解最初是错的, 后来自己改对了. 另一条路子是回译, 针对文档和解释这类执行结果判断不了质量的任务.

多语言同样有专家模型, 在 90% 多语言 token 的数据上继续预训练, 用来在预训练结束前收集非英语的高质量标注. 数学推理的难点包括提示不够, 缺少标准的逐步推理过程, 中间步骤可能出错, 作者训练结果奖励模型和逐步奖励模型来筛掉中间步骤出错的数据, 对更难的题用蒙特卡洛树搜索配合逐步奖励模型生成有效的推理轨迹, 还让模型把文本推理和 Python 代码结合起来, 用代码执行结果剔除推理无效的样本. 长上下文 SFT 靠合成数据, 覆盖问答, 摘要和代码仓库推理, 消融结果是把 0.1% 的合成长上下文数据混进原有短数据, 长短两类基准的表现同时最好.

工具方面有三个核心工具: Brave Search 查知识截止之后的信息, Python 解释器做计算和数据分析, Wolfram Alpha API 解数学科学题. 训练数据从单步调用, 多步调用 (类似 ReAct 的推理和调用交替) 到文件上传逐步加难, 另外还做了零样本调用未见过的工具. 事实性这一块走的是先治幻觉的思路: 用知识探针检查模型是否真的知道预训练数据里的某个事实, 知道的就答, 不确定的就拒答. 可操控性则通过系统提示控制回答长度, 格式, 语气和人设, 偏好数据用在奖励模型, 拒绝采样, SFT 和 DPO 各个环节.

## 12. 稳健性, 污染和人工评测

稳健性实验看多选题的几种扰动: 换选项标签 (字母, 数字, 罕见符号), 少样本示例里答案都偏向同一个选项, 打乱答案顺序, 换提示格式. 结果是预训练模型对这些扰动都比较稳健, 405B 尤其明显. 对抗基准部分 (图 15) 把 SQuAD, GSM8K, QQP 和它们的对抗版本配对, 复述检测上预训练和后训练模型都没有被 PAWS 的对抗构造难住, 数学推理和问答上对抗版的分数则明显低于非对抗版, 预训练和后训练模型的规律相同.

污染分析用 8-gram 重叠给每个样本打污染分, 再按性能增益最大的原则选阈值, 表 15 报告这个阈值下的污染比例和估计增益. 这里有一个容易读反的地方: 正文说 SQuAD 和 MATH 在低阈值下污染程度高, 表里却印着 0 和 1, 原因是低阈值没有带来增益, 选中的阈值落在了污染少的位置. MBPP, HumanEval, MMLU, MMLU-Pro 等六项在表里空着, 因为 8-gram 给出的污染分偏高, 估不出增益. bi 第 34 页的疑惑解释了这一点.

人工评测按能力划分提示集, 标注员用 7 档量表比较两个模型的回答, 更好或好很多算胜. 对比对象是 GPT-4 (0125), GPT-4o 和 Claude 3.5 Sonnet, 图 17 给出 95% 置信区间, 不计平局. 结论是 405B 和 GPT-4 (0125) 大体持平, 多轮推理和代码上更好, 印地语, 西班牙语, 葡萄牙语的多语言提示上更差; 和 GPT-4o 在英语提示上持平; 和 Claude 3.5 Sonnet 在多语言提示上持平, 单轮和多轮英语上更好, 代码和推理上落后. 作者提到人工评测受语气, 回答结构, 啰嗦程度影响较大, 这些因素正是后训练在调的.

## 13. 安全部分的数字

系统级防护有三个组件: Llama Guard 3 是在 Llama 3 8B 上微调的安全分类器, 在各项基准上平均减少 65% 的违规, 代价是误拒率上升; 它的 int8 量化版体积缩小 40% 以上, 表 27 显示性能几乎不变. 另外两个是基于提示的过滤器 Prompt Guard 和 Code Shield. 表 25 和表 26 分别按语言和按危害类别列出用 Llama Guard 3 做输入或输出过滤时, 违规率 VR 和误拒率 FRR 相对 Llama 3 的变化, 负数表示下降, 越低越好.

语音部分的安全数字在表 33, 数据集是 MuTox, 指标是新增毒性 AT (越低越好) 和丢失毒性 LT (越高越好). 英语上 8B 为 AT 0.84, LT 15.09, 70B 为 0.68, 15.46, Gemini 1.5 Pro 为 1.44, 13.42. 全部语言平均时 8B 为 2.31, 9.89, 70B 为 2.00, 10.29, Gemini 1.5 Pro 为 2.06, 10.94.

## 14. 推理: 两台机器和 FP8

BF16 下 405B 放不进一台 8 卡 H100 机器, 所以推理用两台机器共 16 张卡: 机内 NVLink 带宽高, 用张量并行; 机间带宽低, 延迟高, 用流水线并行. 训练时流水线的气泡是主要问题, 推理没有反向传播, 不需要冲刷流水线, 可以直接用微批提高吞吐. 在 4,096 个输入 token, 256 个输出 token 的负载下, 两个微批在预填充和解码两个阶段都提高了同等本地批大小下的吞吐, 额外的同步点让延迟略升, 但吞吐和延迟的整体权衡更好 (图 24).

FP8 利用 H100 的原生支持, 量化前馈层里大多数参数和激活, 这部分约占推理计算时间的 50%; 自注意力层的参数不量化. 为了保住质量又加了三处约束: 第一层和最后一层 Transformer 不量化; 高困惑度 token (比如日期) 可能让激活值很大, 动态缩放因子上限设为 1200; 缩放按行计算, 不按整个张量. 效果评估没有看基准, 因为基准分数对量化不敏感, 而是看 100,000 条回答的奖励分数分布 (图 26), FP8 和 BF16 基本重合. 效率上 (图 27), FP8 在预填充阶段吞吐最多提升 50%, 解码阶段的吞吐延迟权衡也明显更好.

## 15. 视觉: 交叉注意力接在旁边

视觉能力是组合式接上去的, 语言模型参数全程不动. 图像编码器是 ViT-H/14, 630M 参数, 在 2.5B 图文对上训练了 5 个 epoch, 输入 224 x 224, 切成 16 x 16 个 14 x 14 像素的 patch. 对比学习训练出来的编码器会丢细粒度定位信息, 所以除最后一层外还取第 4, 8, 16, 24, 31 层的特征, 再插入 8 个门控自注意力层, 合计 40 个 Transformer 块, 850M 参数, 每个 patch 输出 7680 维. 适配器是一组交叉注意力层, 每四层自注意力后接一层, 同样用 GQA; 405B 上这些交叉注意力层约有 100B 参数.

适配器预训练先在约 6B 图文对上进行, 图像缩放到最多四块 336 x 336 的 tile, 拼成 672 x 672, 672 x 336, 1344 x 336 等长宽比; 然后在约 500M 张图像上退火, 提高每块 tile 的分辨率. 视频适配器最多输入 64 帧, 时间聚合器是 perceiver resampler, 另外在每四层图像交叉注意力之前加一层视频交叉注意力. 原文写视频部分对 「Llama 3 7B 和 70B」 分别是 0.6B 和 4.6B 参数, 全文没有 7B 这个规模, 应读作 8B, bi 第 57 页的疑惑对过这一处.

后训练依次是 SFT, DPO, 拒绝采样和质量微调. SFT 时把预训练语言模型的权重热替换成指令微调后的权重, 语言模型仍冻结, 只更新编码器和适配器. DPO 的参考模型不固定, 每 k 步按指数滑动平均更新, 人工评测效果更好. 结果方面, 表 29 里 Llama 3-V 405B 在 VQAv2 上 80.2, AI2 Diagram 94.1, ChartQA 85.8, TextVQA 84.8, DocVQA 92.6; 表 30 里视频版 70B 在 PerceptionTest 上 60.8, TVQA 87.9, NExT-QA 30.3, ActivityNet-QA 56.3, 视频只评了 8B 和 70B.

## 16. 语音: 嵌入直接进语言模型

语音和视觉的接法不同. 视觉走交叉注意力, 语音模块的输出直接当 token 表示送进语言模型, 前后用两个新特殊 token 包起来, 所以语音和文本可以交错输入. 编码器是 1B 参数的 Conformer, 输入 80 维梅尔特征, 步长 4 堆叠后帧长 40 ms, 24 层, 隐维度 1536, 24 个注意力头; 适配器约 100M 参数, 卷积步长 2 把帧长再拉到 80 ms. 编码器用约 15M 小时的语音做自监督预训练 (BEST-RQ), 数据用 VAD 阈值 0.7 过滤. 通过文本系统提示切换 ASR, 语音翻译和语音对话几种模式, 支持 34 种语言.

语音生成部分把 Llama 3 8B 第 16 层解码器的嵌入用在两个模块上: 文本规范化 TN 负责把书面文本按上下文改写成口语形式, 韵律模型 PM 负责预测韵律特征, 两者都支持按 token 流式输入. TN 训练集有 55K 条样本, 覆盖数字, 日期, 时间等需要改写的类别. 识别结果在表 31, 用的是词错率, 越低越好: 70B 在 MLS 英语上 4.4, LibriSpeech test-other 3.1, VoxPopuli 英语 5.7, FLEURS 34 种语言 8.2, 均低于 Whisper 和 SeamlessM4T v2. 翻译结果在表 32, 用 BLEU: 70B 在 FLEURS 33 种语言到英语上 33.7, CoVoST 2 的 15 种语言到英语上 38.8.

## 17. 读完之后

回到第 1 节的三条, 这篇报告在每一条上都给出了可以核对的数字. 数据有配比和退火实验, 规模有 IsoFLOPs 拟合和下游分数的预测, 管住复杂度则体现在稠密架构, DPO 和一整章基础设施. 报告最有分量的部分是第 3.3 节, 集群拓扑, 4D 并行, 故障分类这些内容此前很少有团队公开到这个粒度.

多模态部分的定位很清楚: 作者明说图像, 视频, 语音模型仍在开发中, 没有随报告正式发布. 组合式接法的好处是语言模型的文本能力不受影响, 各模态可以并行开发; 代价是 405B 上额外约 100B 的交叉注意力参数, 以及训练时要处理模型和数据的异构. 结论一节作者强调, 高质量基础模型的开发还在早期, 他们在数据质量, 规模和简洁上的取舍会在后续版本里继续推进. 本目录的 llama3-bi.md 按页排了全文对照, 其中 16 条疑惑记下了几处表格笔误和容易混的数字.
