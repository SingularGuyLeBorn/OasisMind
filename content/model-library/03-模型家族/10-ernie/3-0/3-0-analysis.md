## 1. 背景与结构

### 1.1. 2021 年的岔路: 规模路线和知识路线

2021 年上半年, 大模型的主流叙事是 GPT-3: 175B 参数, 纯文本, 自回归, 靠 few-shot 和 zero-shot 展示能力. 摘要先把这条路线摆出来, 再提两处不满. 一是这些模型只吃纯文本, 正文举的例子是 GPT-3 用了 570GB 过滤后的 Common Crawl, 语言知识和世界知识没有显式表示. 二是纯自回归模型用传统微调做理解任务偏弱, 作者引的是 BERT 论文的结论. ERNIE 3.0 的回答是把自回归网络和自编码网络放进同一个框架, 把知识图谱放进预训练语料, 规模做到 10B, 语料 4TB.

这个回答的每一块都能在百度前作里找到来源. ERNIE 1.0 用短语级和实体级遮盖代替 BERT 的随机字遮盖, 它理解的 「知识」 是要整段预测的语言单位, 不往模型里塞实体向量; 这一点对中文尤其要紧, 中文没有天然的词边界, 按字遮盖时模型很容易靠相邻字猜出答案. ERNIE 2.0 带来持续多任务学习和句子重排. ERNIE-Doc 带来同层循环记忆. 3.0 把这三样合在一起, 新加的只有两件: 顶层按理解和生成分成两个任务模块, 以及把三元组和百科句子配对的 **UKTP**. 所以读 3.0 时, 结构, 语料, 损失, 训练日程都要回到这几件事上看, 它们是一起定下来的.

### 1.2. 10B 装在哪里: 共享塔, 任务塔和只给生成的记忆

共享模块和两个任务模块都用 Transformer-XL. 按每层约 $12d^2$ 的权重粗算 (忽略偏置, LayerNorm 和相对位置参数), 共享塔约 $48 \times 12 \times 4096^2 \approx$ 9.66B, 每个任务塔约 $12 \times 12 \times 768^2 \approx$ 85M, 两个合计约 170M. 10B 里约 97% 在共享塔, 剩下约 0.17B 大概落在嵌入层上, 但中文词表大小本文没印, 这一项算不实. 翻译实验另说为了英译中把词表扩了 10K 个英文子词, 按 4096 宽算, 这一步就多出约 41M 嵌入参数.

参数这样分布, 直接决定了 「微调时只更新任务塔」 的含义. 第 3.1 节说框架 permits 只更新任务模块, 若照此做, 可训练参数约 85M, 不到总量的 1%. 这是一个很省的方案, 可本文所有下游表都没有注明是否用了它, 也没有对比冻结共享塔和全量微调. 图 1 把共享塔画成 Block 1 到 Block k, 任务塔画成 Block k+1 到 Block n, 像是同一根栈在第 k 层分叉; 但 4096 维的共享输出怎样接进 768 维的任务塔, 正文和图都没有交代投影层. 读者只能确认两边宽度不同, 接口细节缺失.

记忆的开关也跟着分塔走. 设 $h^{n}_{\tau}$ 是第 $\tau$ 段第 $n$ 层的输出, $\mathrm{SG}$ 是 stop-gradient, $\circ$ 是沿长度拼接. 计算当前段第 $n$ 层时, query 取本段的 $h^{n-1}_{\tau+1}$, key 和 value 取拼接后的 $\tilde h^{n-1}_{\tau+1}$. Transformer-XL 原版是

$$\tilde h^{n-1}_{\tau+1} = \big[\mathrm{SG}(h^{n-1}_{\tau}) \circ h^{n-1}_{\tau+1}\big],$$

ERNIE-Doc 的 **同层循环** 把缓存换成上一段同一层的输出:

$$\tilde h^{n-1}_{\tau+1} = \big[\mathrm{SG}(h^{n}_{\tau}) \circ h^{n-1}_{\tau+1}\big].$$

两式只差缓存的上标. 原版里信息每跨一段就下降一层, 从第 $\tau$ 段传到第 $\tau+k$ 段要消耗 $k$ 层, 最大依赖长度约为层数乘记忆长度; 同层循环不降层, 依赖长度不再受层数限制, 缓存张量的形状没变, 显存也没变. 第 3.1.1 节把记忆写在共享模块一节里, 若记忆贯穿共享塔 48 层和生成塔 12 层, 原版写法的上界约为 $60 \times 128 = 7680$ 个 token, 这是理论上界, 3.0 实际的有效上下文本文没有测. 3.0 的生成塔用的就是这种同层循环, 记忆 128, 当前段 512; 理解塔是双向注意力, 如果也吃这段记忆, 掩码会变得难以定义, 所以正文说记忆只对生成有效, 靠注意力掩码控制. 分塔的动机要放在 2021 年的对照里看. 当时统一理解和生成的主流做法是 UniLM 一类: 一个共享 Transformer, 靠不同的自注意力掩码切换双向, 单向和 seq2seq 三种模式, 参数完全共享. 3.1 节明确把这种做法当作对照, 作者的判断是: 不同任务范式依赖相同的底层词法, 句法特征, 但顶层需要的特征互相冲突, 理解任务偏语义连贯, 生成任务要更多上下文. 于是借用多任务学习里 **「底层共享, 顶层分任务」** 的经典结构. 任务塔选 base 尺寸而不是常见的 MLP 或浅层 Transformer, 作者给了三条理由: base 网络抓语义的能力比 MLP 强; 每个任务塔只增加少量参数, 就能区分不同范式的顶层语义; 任务塔远小于共享塔, 只微调任务塔在工程上可行. 三条都是论证, 没有对应的消融, 第 4.1 节那组任务塔实验用的是缩小到 3 层 256 维的版本.

相对位置编码是 Transformer-XL 能跨段复用记忆的前提, 背景见 [位置编码](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/2.1.4-位置编码.md).

## 2. 语料与预训练

### 2.1. 语料先决定了知识能以什么形状进来

4TB 语料分 11 类: ERNIE 2.0 旧语料 (百科, 维基, feed 等), 百度搜索系产品 (百家号, 知道, 贴吧, 经验), Web, QA-long, QA-short, 小说, 诗词对联, 医疗, 法律, 金融, 知识图谱. 清洗分三层去重: 字符层把连续相同的符号收成一个; 段落层把连续重复的段落 (句数小于 100) 收成一段; 文档层比较最长三句的 MD5 之和. 作者特别说前两层对 「生成不重复内容」 很关键, 这说明清洗目标里已经带着生成塔的需求. 少于 10 个词的句子丢掉, 再用正则切句, 用百度分词工具切词, 后者服务于实体遮盖. 一般的去重流程见 [数据处理](../../../../llm-guide/3-预训练/3.1-预训练数据/3.1.3-数据处理/3.1.3-数据处理.md).

表 1 的 token 列和 multiplier 行放在一起看, 混合的形状才出来. 原始 token 加总约 540.5B, 其中 Web 314.7B 占约 58%. 乘上 multiplier 后的池子约 1.22T: ERNIE 2.0 旧语料 17.8B 乘 20, 从原始约 3.3% 升到约 29%; 百度搜索 42.4B 乘 7, 从约 7.8% 升到约 24%; Web 乘 1, 从约 58% 降到约 26%. 也就是说, multiplier 把混合明显推向了百度自有的高质量来源. 需要留意两点: 正文说 multiplier 是在 「为 NLU 网络预训练截断数据之后」 乘的, 生成侧是否同样加权没写; 实际训练量是 375B token, 只相当于加权池的约 31%, 各库最终被看了多少遍, 本文没有给.

知识图谱这一行最能说明数据和损失是一起设计的. 图谱只有 0.7B token, 中位长度 16, 乘 10. 它进损失的方式由 UKTP 的配对规则限定: 给定一篇百科文档, 先找头实体或尾实体的提及就是文档标题的候选三元组, 再从中挑出头尾两个实体在文档同一句里都出现的三元组, 把三元组和这句话配成一对. 作者明说这相当于关系抽取里的 **远程监督 (distant supervision)**: 两个实体在图谱里有关系, 同时提到它们的句子就可能表达这个关系. 关系抽取文献里, 这条假设最出名的问题是错标, 句子提到了两个实体但讲的是别的关系; 后来的多示例学习把它放宽成 「一组句子里至少有一句表达该关系」. UKTP 用的是逐句配对的原始版本, 噪声比例本文没有测.

表 1 下半部分还给了各库按 ERNIE 3.0 wordpiece 切分后的长度分位, 这组数和上下文设置直接相关. 小说中位 2063 token, 95% 分位 3652; 法律中位 1162, 95% 分位 4587; Web 中位 793, 95% 分位 2757. 而上下文上限是 512. 这意味着小说和法律文本的大多数样本都要被切成多段: 生成塔可以借同层循环的 128 记忆把上一段的信息带过来, 理解塔没有记忆, 只能在单段 512 内工作. 反过来, QA-short 中位 15, 诗词中位 30, 知识图谱中位 16, 远短于 512, 多条样本如何拼进一个序列, 本文没写. 长文本库和短文本库在两个塔上被利用的方式因此不对称, 这一点在论文的结构图里看不出来, 要把表 1 和第 3.1.1 节放在一起才看得到.

### 2.2. 五个预训练任务怎样分到两个塔

理解塔承担四个任务. **Knowledge Masked Language Modeling** 整段遮短语和命名实体, 继承 ERNIE 1.0. 句子重排把一段话随机切成 1 到 m 段后打乱, 让模型在 $k = \sum_{n=1}^{m} n!$ 个类别里选出正确排列; m 取 3 时 k 是 1+2+6=9, 训练时 m 取多少本文没写. 每个类别对应一对 「切成 n 段, 取 n! 种排列中的哪一种」, 所以同一个分类头既判断段数又判断顺序; m 取 4 时 k 是 33, 取 5 时是 153, 类别数按阶乘涨. 句距是三分类: 相邻, 同文档不相邻, 不同文档, 比 NSP 的二分类多出 「同文档但不相邻」 这一类. UKTP 随机遮三元组里的关系或句子里的词: 预测关系时模型要在句子里找到头尾实体再判断关系, 预测词时可以参考三元组给出的逻辑关系. 图 2 的输入是把三元组和句子直接拼成一条序列: `Andersen # Nightingale [SEP] The Nightingale is written by Danish # Hans Christian Andersen [SEP]`, 第一个 # 遮的是关系 Write, 第二个遮的是句中的 author. 头尾实体两边都不遮, 模型预测 Write 时能从句子里读到 「written by」, 预测 author 时能从三元组读到 Write. 正文说遮关系或遮句中的词, 读起来是二选一, 图里两处同时遮, 实际按哪种做, 遮盖比例多少, 本文都没写.

生成塔只有一个任务: **Document Language Modeling**, 也就是带同层循环记忆的 next-token prediction. 作者比较了两类生成预训练: GPT 式单向语言模型, 以及 BART, T5, ERNIE-GEN 那样带辅助解码器的 seq2seq, 选了前者, 理由是降低网络复杂度, 让统一预训练更有效. 这个选择和分塔互相支撑: 没有额外解码器, 生成塔就只是一段单向的 Transformer-XL, 可以和理解塔共享同一个底座. 两边的任务各自按词法, 句法, 知识三个层次安排, 作者对应的说法是 KMLM 练词法, 两个结构任务练句法, UKTP 练知识记忆和推理.

句子重排的写法和 ERNIE-Doc 的 segment-reordering 几乎一样: 那篇也把长文随机切成 1 到 m 块再打乱, 让模型恢复原顺序, 目的是在更长的有效上下文里学段落之间的关系. 区别在于落点. ERNIE-Doc 把它和同层循环记忆放在同一个模型里, 重排的对象可以跨越多个段; 3.0 把重排放进没有记忆的理解塔, 同层循环只留给生成塔, 所以理解塔上的重排只能在 512 个 token 以内进行. 表 1 里小说, 法律这类长文本库的大多数样本比 512 长, 理解塔上的结构任务看到的只是切开后的一段. 这不是论文指出的问题, 是把第 3.1.1 节的记忆开关和第 3.2.2 节的任务放在一起时推出来的 (推测).

这些任务的损失怎样加权, 每个 batch 里各任务占多少, 本文都没写, 只给了 「所有预训练任务的总 batch 是 6144」. 持续多任务学习在 ERNIE 2.0 里意味着任务按顺序逐步加入, 3.0 是否也按这个节奏引入任务, 正文没有展开. 所以 「四个理解任务加一个生成任务」 能确认的是任务清单和它们落在哪个塔上, 配比和调度属于报告缺失的信息.

### 2.3. 前一万步: 渐进学习和 warmup 叠在一起

优化器是 Adam, 学习率 1e-4, $\beta_1=0.9$, $\beta_2=0.999$, L2 权重衰减 0.01. 前 10,000 步学习率 warmup, 之后线性衰减. 同一段一万步里还开着 **渐进学习**: 序列长度, batch, 学习率, dropout 四个量一起从小往大加. 作者把它放在 progressive training 的脉络里, 列了三个前例: BERT 前 90% 更新用短序列, GPT-2 线性加大 batch, 以及按输入尺寸分阶段改正则化系数. 3.0 的改动是把四个旋钮同时, 平滑地往上推.

之后的研究把这几个旋钮拆开看过. 同年 8 月的 sequence length warmup 工作在 GPT-2 上发现, 训练初期的长序列和梯度方差尖峰高度相关, 先短后长能在更大的 batch 和学习率下保持稳定; 同一组作者在 DeepSpeed 文档里还指出, 单用 batch warmup 对稳定性帮助有限, 并且不建议和序列长度课程同时用, 因为两者都在减少每个 batch 的 token 数. 3.0 恰好四个一起开, 表 11 只比了 「开」 和 「关」, 没有逐个旋钮的消融, 所以说不清加速主要来自哪一个. 预训练策略的一般讨论见 [预训练策略](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.3-预训练策略/3.2.3-预训练策略.md).

表 11 的数都在 8 张 V100 上测. ERNIE Base 从 11h30m 降到 4h, 降 65.21%; ERNIE 1.5B (48 层, 隐藏 1536, 24 头) 从 5h55m 降到 3h4m, 降 48.2%. 计时口径是 loss 降到与 ERNIE 3.0 相同数值所需的时间, 不是完整训练的墙钟. Base 的渐进设置是 batch 8 到 2048, 序列 128 到 512, 学习率 0 到 1e-4, dropout 保持 0; 1.5B 是 batch 8 到 8192, 学习率 0 到 6e-4, 靠梯度累积才达到峰值 batch. 对照第 3.3.1 节 「四个量一起加」 的说法, 这两组消融里 **dropout 都停在 0**, 真正在涨的只有三个量; 1.5B 那组没写序列长度, 其余设置写的是 「同 [7]」, 即 ERNIE 1.0. 所以表 11 的 「+Progressive Learning」 关掉再打开的, 是 batch, 序列长度, 学习率三条 ramp 的组合, 对照组是否用了同样的学习率 warmup 也没写. Base 一组每步的 token 数从 $8 \times 128 = 1024$ 涨到 $2048 \times 512 \approx 1.05\text{M}$, 差约 1024 倍. 发布运行的 384 张卡, 375B token 没有对应的小时数. 按 $6ND$ 粗算, 这次预训练约 $6 \times 10^{10} \times 3.75 \times 10^{11} \approx 2.25 \times 10^{22}$ FLOPs, 本文没有报 MFU, 也就无法反推时长.

硬件一侧, 正文只说借助参数分片解决了 「总参数超过单卡显存」 的问题. 按混合精度加 Adam 的常见配置, 每个参数约占 16 字节 (半精度权重和梯度, 单精度主权重和两份矩), 10B 参数就是约 160GB, 而 V100 单卡显存是 16GB 或 32GB, 本文没说用的是哪一种. 不分片的话, 连优化器状态都放不下, 更谈不上激活. 分片引用的是 [48, 49] 两篇, 具体切分方式和通信开销报告没有展开.

## 3. 使用与评测

### 3.1. 没有后训练的模型怎样被使用

以今天的标准看, 这篇没有后训练. 没有 SFT, 没有偏好数据, 没有 RLHF 或 DPO, 模型发布时也不是一个对话模型. 下游用法有两种: 用具体任务的标注数据逐任务微调, 或者不更新任何梯度直接零样本. 引言说的 few-shot 在实验节里没有单独一张表. 指令微调的一般做法见 [SFT](../../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md), 报告不涉及.

零样本的打分方式决定了分数能怎么读. 选择题 (CHID, CMRC2017 等) 把候选 $c$ 填进空里得到序列 $x^{(c)} = (x_1, \dots, x_{T_c})$, 按脚注 19 用 token 数归一化困惑度:

$$\mathrm{PPL}(c) = \exp\Big(-\frac{1}{T_c}\sum_{t=1}^{T_c}\log p\big(x_t \mid x_{<t}\big)\Big), \qquad \hat c = \arg\min_c \mathrm{PPL}(c).$$

$\exp$ 单调, 比困惑度就是比平均每 token 的负对数似然. 分母 $T_c$ 随候选变, 长候选不会因为多几个 token 吃亏; 空前的上下文对所有候选相同, 差距来自候选本身, 以及整句打分时空后文字在该候选条件下的概率. 分类题给标签起一个有语义的名字, 用提示模板改写成选择题. TNEWS 有 15 类, IFLYTEK 有 119 类, 但每个样本只随机抽 3 个负标签, 连正确标签共 4 选 1, 这是为了和 CPM-1, PanGu-α 对齐并省算力: 每个候选都要单独前向一次, IFLYTEK 全量是 119 次, 抽样后是 4 次, 省了约 30 倍. 因此表 5 的 TNEWS 68.40 是四选一的准确率, 随机基线是 25%, **不能和 15 类全量分类的微调分数放在一起比**. 困惑度打分的背景见 [困惑度 PPL](../../../../llm-guide/3-预训练/3.4-预训练评估/3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md).

生成类零样本用 beam search, 宽度 8, 不加长度惩罚, 最大长度按数据集答案长度的 95% 分位设定; 抽取式阅读理解再为每个样本建 Trie 树, 只允许生成原文里出现过的片段. 这种受限解码本身就排除了大量错误答案, 表 5 里 CMRC2018 从 PanGu-α-13B 的 1.46/19.28 到 ERNIE 3.0 的 7.61/25.61, 有多少来自模型, 多少来自解码约束, 没有对照. 作者自己也提醒, AFQMC 和 CSL 的零样本准确率只比随机略高, CSL 55.63 是二分类, 可能和提示写法有关.

提示模板本身决定了零样本分数的上限, 4.3.2 节把几种写法都印了出来. 语义相似度用 「下面两句话语义相同/不同: 句 A. 句 B.」 的形式, 作者承认这个提示可能不是最优. NLI 用 「句 A? 否/是/也许, 句 B」, 其中 CMNLI 由 XNLI 和 MNLI 翻译而来, 和微调节里 XNLI 的翻译质量问题是同一个来源. WSC 把代词依次替换成候选名词, 比较整句困惑度. CMRC2019 每个空随机抽 3 个负候选, 再用 beam search 找整篇的最优填法; PD, CFT, CMRC2017 把空前的文本当输入, 全文出现过的词都当选项. C3 的提示是 「问题: ... 答案: 选项. 答案在下面的文档里: 文档」, 文档放在最后; 闭卷的 WebQA 只给问题. 这些模板大多和 CPM-1, PanGu-α 的写法相近, 但不是逐字相同, 所以表 5 的横向比较里混着提示差异. 微调一侧, 各任务的学习率, epoch 和 batch 本文都没给, 54 个任务的微调超参属于缺失信息.

表 5 里差距最夸张的一格是 WPLC: 按 PanGu-α 的做法把正确词填回遮盖位置, 算整句困惑度, ERNIE 3.0 是 17.03, PanGu-α-13B 是 45.85. 困惑度按 token 归一化, 而 token 由各自的分词器决定. ERNIE 3.0 用自己的 wordpiece, PanGu-α 用它自己的词表, 同一句中文被切成的 token 数不同, 每个 token 承载的信息量也不同, 两个困惑度不在同一把尺子上. 本文没有换算到字级或字节级, 所以这一格能说明方向, 不宜把 17 对 46 读成接近三倍的差距. 同表里基于准确率的格子没有这个问题.

### 3.2. 54 个任务和 SuperGLUE: 分母各不相同

中文评测共 54 个数据集: 理解 45 个分 14 类, 生成 9 个分 7 类. 脚注 4 说先前最好成绩取的是能找到的公开单模型; 脚注 5 说 ERNIE 2.0 和 RoBERTa-wwm-ext 的部分结果由作者自己复现, 已有公开结果的除外. 这两条要连着读. 表 2 里涨幅最大的 WSC2020 从 69.70 到 95.40, 加 25.7, 对照正是标星的 RoBERTa*, 而且是开发集; CMRC2019 的 QAC/PAC 从 82.6/23.3 到 92.53/57.33, 对照同样是 RoBERTa*. **涨幅最大的几项, 恰好落在作者自行复现的基线上**. 评测口径的一般问题见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据.md).

表 2 的集合也不统一. 同一张表里有的行只报开发集 (OCNLI, WSC2020, AFQMC, CSL, TNEWS, IFLYTEK, CLUENER, CMRC2018 等), 有的行开发集和测试集都报, 有的只报测试集; BDCI2019, LCQMC, Weibo, OntoNotes, C3 的开发集对照是横线. 作者真正强调 「参数量相当」 的比较只有两处, 对照都是 11B 的 CPM-2: LCQMC 测试集 90.38 对 89.16, 高 1.2; C3 测试集 86.69 对 86.1, 高 0.6. 这两处最接近同规模对比, 差距也最小. 其余大部分对照是 Large 级别的 ERNIE 2.0, RoBERTa-wwm-ext-large 或 SKEP, 规模差了一个数量级以上, 领先里混着规模带来的部分. XNLI 只高 0.7, 作者的解释是这个集合从英文翻译过来, 质量较差, 本文没有给出支持这一解释的分析.

生成任务 (表 3, 测试集) 里有几项差距很大. LCSTS 的 ROUGE-L 是 48.46, ERNIE 2.0-Large 是 41.38. AdGen 的 BLEU-4 从 CPM-2 的 10.60 到 30.16, 加 19.56. Math23K 从 69.37 到 75.00, 做法是生成后缀表达式再交给 Python eval. KdConv 从 15.75 到 23.85, 作者把这 8.1 分归到知识图谱预训练, 但没做去掉 UKTP 的对照. WMT20 英译中 26.80 只高 CPM-2 的 26.21 一点, 脚注 17 说训练集太大, 报的是 1.5 个 epoch 的检查点, 模型没训到收敛. LUGE 六项平均 59.77, ERNIE 2.0-Large 54.41, 差 5.36.

零样本和人工评测里也有输的格子, 正文没点名. 表 5 的 C3 上 ERNIE 3.0 是 52.62, 低于 PanGu-α-13B 的 54.47 和 PanGu-α-2.6B 的 53.42. 表 6 的 450 条人工评测按连贯性, 流畅性, 准确性各打 0 到 2 分, 平均 1.54/1.34/0.88, 高于 PanGu-α 的 1.38/1.00/0.58; 但食谱生成的连贯性 1.30 低于 PLUG 的 1.67, 单轮对话的流畅性 0.70 低于 CPM-1 的 0.90, 事实问答三项和 CPM-1 完全相同, 都是 1.67/1.50/1.03. 每类只有 30 到 50 条, 评分人数和一致性没报.

人工评测的准确性一列只在问答和释义类任务上打分, 其余是横线. 推理类 30 条里 ERNIE 3.0 的连贯性 1.70, 流畅性 1.60, 都是四个模型里最高, 准确性却只有 0.23, 低于 CPM-1 的 0.27. 也就是说, 它在推理题上写出的回答读起来最顺, 答对的比例并不高. 术语解释是另一个方向: 1.83/1.60/1.33, 准确性明显领先, 和知识图谱, 百科语料的来源相符. 表 7 给的零样本示例里有一道两跳问题: 「发明加减消元法的数学家所在国家有哪些品牌汽车」, 模型答出奔驰, 宝马, 奥迪等德国品牌, 中间那一跳 (数学家是谁, 属于哪国) 没有写出来. 这类挑选出来的样例只能说明模型能做到, 不能说明做到的频率. 脚注 20 还说明, CPM-1, PLUG, PanGu-α 用的是第三方或官方公开的实现, 各模型的解码设置是否一致, 本文没交代.

SuperGLUE 用的是另一个英文版, 语料换成 Wikipedia, BookCorpus, CC-News, OpenWebText, Stories, 结构是否和中文版相同没写. 表 9 由评测服务器在 2021 年 7 月 3 日 计分: ERNIE 3.0 90.6, T5+Meena 90.4, DeBERTa 90.3, 人类 89.8. 摘要的 +0.8% 只指总分. 分项里 BoolQ 91.0 高于人类 89.0, COPA 97.4, RTE 92.6, WiC 77.4, WSC 97.3 四项低于人类的 100, 93.6, 80.0, 100. 和 DeBERTa 比, COPA 低 1.0; 和 T5+Meena 比, BoolQ 低 0.4. 第一名来自八项聚合, 领先第二名 0.2, 表上没有方差.

分项里真正拉开差距的是两个多指标任务. CB 的准确率和 macro-F1 是 98.6/99.2, 高于人类的 95.8/98.9 和 DeBERTa 的 95.7/97.6; MultiRC 的 F1a/EM 是 88.6/63.2, 人类只有 81.8/51.9; ReCoRD 94.7/94.2 也略高于 DeBERTa. CB 是一个类别不平衡的小数据集, 几条样本的对错就能让 macro-F1 摆动几个点, 0.2 分的总分领先有相当一部分来自这里. 英文版的模型规模, 训练 token 数, 是否用了分塔和 UKTP, 本文都没写, 只列了语料来源, 所以 **SuperGLUE 第一名不能直接当作中文 10B 模型的证据**. 表 8 的人工评分细则也值得一提: 准确性 2 分要求 「答案正确」, 1 分是 「部分正确」, 连贯性要求和上下文逻辑一致, 流畅性要求没有自相矛盾, 细则是三档描述, 没有给标注者之间的一致率.

## 4. 消融与家族位置

### 4.1. 消融都在小模型上

第 5 节有三组消融, 都不在 10B 上. 任务塔的消融用 12 层 768 维的统一网络, 任务塔缩到 3 层, 256 维, 4 头, 对照是两种范式共享同一个任务塔. 图 3 画的是生成任务的困惑度. 读图可见, 大约 36K 步之前是共享版困惑度更低, 之后分塔版反超, 到横轴末端 (约 88K 步) 两者约为 16.55 和 16.7, 差约 0.15 (读图). 正文说分塔 「收敛更快」, 这只对后半段成立; 「差距随训练变大」 与曲线一致, 但幅度很小, 而且没有换算成下游分数.

UKTP 的消融 (表 10) 在 ERNIE Base 上做关系抽取: SanWen 从 75.56 到 77.36, 加 1.80; FinRE 从 58.19 到 59.75, 加 1.56. 关系分类打在 [HD], [/HD], [TL], [/TL] 四个特殊 token 最终表示之和上. 关系抽取本身就是 UKTP 最接近的任务, 远程监督的配对方式和下游任务形式几乎同构, 这组增益能说明 UKTP 对同类任务有效, 很难外推到阅读理解或生成. CKBQA 的零样本比较 (20.64 对 PanGu-α-2.6B 的 14.61) 是 10B 模型对别家模型, 不是加不加 UKTP 的对照.

渐进学习的消融已在第 2.3 节说过, 在 Base 和 1.5B 上. 三组合起来, 能确认的是: 小模型上分塔的困惑度后期略低, Base 上 UKTP 对关系抽取有一到两个点的帮助, 8 张卡上渐进学习缩短到达同一 loss 的时间. 发布的 10B 配置没有重复其中任何一组, 所以 10B 在 54 个任务上的领先, 有多少来自规模, 语料, UKTP 或分塔, **本文拆不开**.

### 4.2. 在家族里的位置

3.0 是 ERNIE 系列里知识增强路线走得最远的一版: 知识从 1.0 的实体遮盖, 推进到三元组加百科句子的 UKTP; 结构从 BERT 式的单编码器, 变成共享底座加理解塔, 生成塔的双塔. 同年 12 月百度又发了 ERNIE 3.0 Titan, 沿用这套框架把稠密参数做到 260B, 并加了在线蒸馏; Titan 的数字属于另一份报告, 这里只记它的存在. 蒸馏的一般做法见 [知识蒸馏](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.3-知识蒸馏/6.3.3-知识蒸馏.md).

同目录的后续条目走向另一条路. 4.5 报告是 decoder-only 的 MoE 加多模态, 5.0 是统一自回归的超稀疏 MoE, 分塔和显式的知识图谱损失都不再出现. 从这个角度回看, 3.0 的几个设计选择各有代价: 分塔让理解和生成都能用上一个 10B 底座, 但也意味着对话式的统一生成不是它的目标; UKTP 让知识以可预测的形式进入模型, 但只覆盖能被 「标题匹配加同句共现」 配对出来的事实; 渐进学习加快了前期收敛, 但四个旋钮没有拆开. 这些限制在本文里都有迹可循, 后来的版本换了路线, 原因要去各自的报告里找.

「知识」 这条线在 4.5 里还留着, 只是换了落点. 4.5 不再设计专门的知识损失, 而是在数据层按数据, 信息, 知识, 智慧分成五档, 训练分类器给网页打知识层级并上采样高层级内容, 再从教科书一类材料里抽知识点合成题目. 3.0 的做法是把图谱三元组和句子配对后放进损失, 4.5 的做法是让知识密度高的文本在语料里多出现几次. 前者要求事实能被图谱覆盖, 后者依赖分类器的判断, 两种做法的噪声来源不同.
