# ERNIE 4.5 Technical Report

**ERNIE Team, Baidu**

## Abstract

In this report, we introduce **ERNIE 4.5**, a new family of large-scale foundation models comprising 10 distinct variants. The model family consists of Mixture-of-Experts (MoE) models with 47B and 3B active parameters (the largest containing 424B total parameters), as well as a dense model with 0.3B parameters. For the MoE architecture, we propose a novel multimodal heterogeneous structure that supports parameter sharing across modalities while also allowing dedicated parameters for each modality. This MoE architecture has the advantage of enhancing multimodal understanding while also improving performance on text-related tasks. All of our models are trained with optimized efficiency using the PaddlePaddle deep learning framework, which enables high-performance inference and streamlined deployment. We achieve 47% Model FLOPs Utilization (MFU) during the pre-training of our largest ERNIE 4.5 language model. Experimental results show that our models achieve state-of-the-art performance across multiple text and multimodal benchmarks, particularly in instruction following, world knowledge memorization, visual understanding, and multimodal reasoning. All models are publicly available under the Apache 2.0 license.

ERNIE 4.5 是 10 个变体的家族. MoE 有激活 47B 和 3B 两档, 最大总参数 424B, 另有 0.3B 稠密模型. 多模态异构结构里, 模态之间可以共享参数, 也可以各有专用参数. 最大语言模型预训练的 MFU 是 47%. 模型按 Apache 2.0 公开. 日期写在后页页眉, 是 2025 年 6 月 29 日.

## 2 Architecture

输入可以是图像, 视频, 文本, 输出是文本. 视觉走可变分辨率 ViT, 再经 adapter 投到和文本共享的嵌入空间. 骨干是细粒度 MoE, 加上多模态位置编码.

**异构 MoE**: 文本和视觉分到不同的专家组, 两边都还要过一组共享专家, 以及全部自注意力参数. 视觉专家的参数量是文本专家的三分之一.

> **核对:** 文本 token 会不会被路由进视觉专家?
> 不会. 三类前馈专家: 文本专家只处理文本 token, 视觉专家只处理视觉 token, 共享专家不经路由, 两种 token 都过. 自注意力参数则是全部 token 共用, 路由只发生在前馈. 这和 「注意力也按模态拆开」 不是同一句话.

<!-- page 6 of 72 -->

**模态隔离路由**是为了避免把纯文本 MoE 扩成多模态时路由塌掉, 文本能力下降. 图 2 是留出集上各层专家激活比例: 文本专家更集中, 视觉专家更分散.

视觉组的中间维是文本专家的三分之一. 前馈 FLOPs 随输入维和中间维的乘积走, 所以每个视觉 token 的前馈计算大约少 66%. 最后一层 Transformer 去掉视觉专家, 因为那些权重不进入交叉熵损失.

> **看表:** 「三分之一」 和 「少 66%」 是剩下三分之一, 还是去掉三分之二?
> 是去掉大约三分之二. 中间维变成原来的 1/3, FLOPs 按乘积大约也变成 1/3, 减少量是 1 减 1/3, 约 66%. 正文写 roughly 66% reduction, 不是还剩 66%. 这只改视觉专家的中间维, 不改文本专家, 也不改表 2 里专家个数那一列.

### 2.2 Vision Encoder

图像不强制压成正方形. 高和宽各自调到最接近的 patch 倍数, 尽量保住宽高比. 2D RoPE 分开编码高和宽. 多图可以 pack 进一个 batch.

视频按预设帧率采样. 帧数越界就在上下界上均匀抽. 视觉 token 仍超限就先降分辨率, 再减帧. 多视频按时长比例分帧. 时间戳直接画在帧的左上角, 不额外占 token, 也不依赖位置编码里的时间维. 任意帧率都能用.

### 2.3 Adapter

空间压缩是不重叠的 2×2, token 数降到 1/4. 时间压缩再除以 2. 都用 pixel shuffle 再过 MLP. 静图被复制成两帧, 这样时间和图像走同一条压缩. 所以一张图在 adapter 里先被当成长度为 2 的视频.

### 2.4 Multimodal Position Embedding

视觉用 **3D RoPE**: 时间, 宽, 高分开. 较低频率给变化最慢的时间轴, 其余频率在高和宽之间交错. 文本 token 退回 1D RoPE. 这和视觉编码器里的 2D RoPE 不是同一套: 2D 在 ViT 里, 3D 在后面的视觉语言 Transformer 输入层.

## 3 Pre-Training

### 3.4 Model Optimization

#### 3.4.1 Router Orthogonalization Loss

除了辅助损失和 z-loss, 还有 **路由正交损失** 和 **token 均衡损失**.

式 (1):

$$L_{\mathrm{orth}} = \sum_{i=1}^{k} \sum_{j=1}^{k} (\hat{w}_i^\top \hat{w}_j - \delta_{ij})^2, \quad \hat{w}_i = w_i / \|w_i\|_2.$$

它只依赖路由权重. 若直接加进总损失, 会干扰 Adam 的梯度估计. 所以按 AdamW 的方式, 让这项直接改路由权重, 不进 Adam 的矩. 系数是 $1 \times 10^{-3}$, 而且不像权重衰减那样再乘学习率.

#### 3.4.2 Token-Balanced Loss

常规交叉熵对一条样本里未掩码位置做平均, 式 (2) 的分母是未掩码集合的大小. 多模态训练里只有文本 token 进入损失, 各样本里文本占比差很大. token 均衡损失改成用序列长度来归一, 以减小梯度方差. 图像 token 和 prompt 位置被掩掉.

> **停一下:** 式 (1) 的对角项在归一化之后还剩什么? 系数为什么不乘学习率?
> 向量已经除以 L2 范数, 对角上 $\hat{w}_i^\top \hat{w}_i = 1$, 减 $\delta_{ii}=1$ 之后是 0. 损失只惩罚非对角的内积. 系数 $10^{-3}$ 直接加在权重更新上, 正文写 unlike weight decay, it is not scaled by the learning rate. 所以学习率变了, 这项的步长不变. 这和权重衰减不是同一个旋钮.

> **再看:** 式 (2) 的分母是未掩码 token 数. 改成序列长度之后, 图多的样本损失变大还是变小?
> 变小. 未掩码的是文本 token. 序列里图越多, 文本占比越低. 若分子仍是这些文本位置的对数概率之和, 分母改成整段长度, 图多的样本被除以一个更大的数. 正文的目的是减小梯度方差, 不是让图多的样本在损失里更重.

ERNIE-4.5-300B-A47B 里专家权重超过总参数的 90%. 预填阶段大约占推理时间的 40%, 解码大约 60%. 专家 GEMM 用 W4A8: INT4 权重, INT8 激活. 正文说这套量化没有精度下降. GPTQ 在这个模型上要对付 64 个专家. 未激活的专家, 量化参数取同层已激活专家的平均.

2-bit 相对 BF16 把模型体积降大约 80%. 2-bit 的 300B-A47B 可以放进一张 141GB 的 H20. 4-bit 是 4 张 80GB.

预填和解码拆开之后, 预填用 EP8, 注意力不做张量并行, 量化是分块 FP8. 解码从 EP8 到 EP64, 量化是 W4A8. 没有 prompt cache 时, 每个 H800 节点大约 56k 输入 TPS 和 18k 输出 TPS.

> **想:** 56k 和 18k 是同一阶段的吞吐吗? 4 张 80GB 和 1 张 141GB 又是哪一种量化?
> 56k 是输入 token 每秒, 18k 是输出 token 每秒, 都是每个 H800 节点, 且没有 prompt cache. 预填用 FP8, 解码用 W4A8, 所以两个 TPS 不在同一种量化上. 4 张 80GB 对应 4-bit. 1 张 141GB 的 H20 对应 2-bit, 体积相对 BF16 大约少 80%. 专家超过 90% 参数这句, 解释的是为什么量化打在专家 GEMM 上, 不是 56k 的分母.
