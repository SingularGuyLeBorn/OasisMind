## 1. 定位与结构

### 1.1. 2025 年年中的位置: 从知识增强到开源多模态 MoE

ERNIE 3.0 是 2021 年的 10B 稠密模型, 靠知识图谱配对语料和双塔结构讲 「知识增强」. 四年后的 4.5 已经换了一套问题. 2025 年上半年, DeepSeek-V3 和 Qwen3 先后放出开源权重的 MoE, 开源社区对一个新模型的第一问变成: 总参数多少, 激活多少, 能不能单机跑, 许可证是什么. 4.5 的回答写在摘要第一段: 10 个变体, 激活 47B 和 3B 两档 MoE, 最大总参数 424B, 外加一个 0.3B 稠密模型, 全部 Apache 2.0, 连同训练工具 ERNIEKit 和部署工具 FastDeploy 一起放出.

名字和参数列要按表读. 表 2 里最大档的 Text Params 是 300B, Total Params 是 424B, 所以纯文本版叫 300B-A47B, 视觉语言版叫 VL-424B-A47B, 两者差的 124B (424 减 300) 是视觉侧参数, 其中 ViT 只有 630M, 大头应当是视觉专家, 但报告没把 124B 拆开. 小档是 21B 对 28B, 差 7B. 0.3B 的文本参数列实际印的是 0.36B. 表 1 还有一列 Thinking: 五个 Base 是横线, 三个后训练文本模型是 non-thinking, 只有两个 VL 后训练版是 both. 所以后面文本榜上的 300B-A47B 是不开长推理的版本, 这一点决定了它该和谁比.

### 1.2. 前馈按模态分开, 注意力共用

4.5 的结构改动集中在前馈层. 每层 MoE 有三类专家: 文本专家只接文本 token, 视觉专家只接视觉 token, 共享专家不经路由, 两种 token 都过; 输出是共享专家与对应模态专家的和. 自注意力参数不拆, 两种模态共用一套. 这种做法叫 **modality-isolated routing**, 理由写在 3.1 节: 一个纯文本 MoE 如果中途开始吃视觉 token, 数据分布突变, 路由器容易塌缩, 文本能力随之退化 (引 Liang et al., 2025). 图 2 用留出集画出各层专家激活, 文本专家的激活更集中, 视觉专家更分散 (读图), 作者拿这张图论证两类 token 不该抢同一组专家.

几个工程选择跟着这个结构走. 视觉专家的中间维只有文本专家的 1/3, 前馈 FLOPs 按输入维乘中间维算, 所以每个视觉 token 的前馈计算少约 66%. 最后一层不放视觉专家, 因为损失只打在文本 token 上, 那一层的视觉专家拿不到梯度. 表 2 的共享专家一格, 最大档印横线, 小档印 2; 正文又说所有 token 都过共享专家, 所以大档到底有几个共享专家, 本页没有给出. 视觉专家的初始化也跟训练日程绑在一起: 它们在第二阶段才出现, 由文本专家做 structural pruning 得来, 这正好解释了 1/3 中间维从哪来. 通用背景见 [MoE](../../../../llm-guide/2-核心原理与架构/2.4-前沿架构与变体/2.4.1-混合专家模型MoE/2.4.1-混合专家模型MoE.md).

### 1.3. 视觉 token 的预算: ViT, adapter 和三套 RoPE

图像编码器不把图缩成固定正方形, 高和宽各自对齐到 patch 的整数倍, 保留原始宽高比, 编码器内部用 2D RoPE, 训练时把多张图打包进一条序列. 视频按帧率和分辨率自适应采样, 帧数超限先均匀抽帧, token 还超限就再降分辨率. 时间戳直接画在帧的左上角, 不额外占 token. 这些选择让一段视频的 token 数随时长和画面变化, 而不是一个定值.

adapter 负责把视觉 token 压进语言模型. 空间上把不重叠的 2×2 块合成一个 token, 数量变为 1/4; 时间上再合并相邻两帧, 数量再减半. 静图被复制成两帧, 让同一个 adapter 同时服务图和视频. 一张静图进语言模型时, token 数约为 ViT 输出的 1/8 (两个因子相乘, 报告没有印这个倍数). 语言模型一侧用 3D RoPE: 低频分给时间轴, 其余频率在高和宽之间交错; 文本 token 退回 1D RoPE. 评测节补了一组视频超参: 2 FPS, 最多 480 帧, 最少 16 帧, 最低 360p, 序列长度 32,768. 位置编码的多模态扩展见 [视觉与多模态扩展](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md).

## 2. 数据与预训练

### 2.1. 语料: 知识分层, 合成数据和可复现的数据流

数据节没有给总 token 数和配比表, 只描述了流水线. 文本来自网页, 论文, 文档和合成数据, 先做启发式过滤再做模型过滤, 然后建一张 「数据地图」, 按语言, 知识, 领域, 场景和质量多维打标, 用来调配比和分阶段选数据. 知识侧按 DIKW (数据, 信息, 知识, 智慧) 分成五档, 训练一个分类器给网页打知识层级, 高层级内容上采样. 合成数据从教科书一类材料里抽知识点, 再围绕知识点生成题目和解释. 领域数据用渐进挖掘扩展, 并对部分数据加条件标签做 conditional pretraining, 报告说这对创意写作有帮助, 但没有给数字.

多模态数据分两块. 图文交错数据来自网页和视频, 视频侧用 ASR 转写配关键帧. 图文对先用 CLIP 分数过滤, 再重写 caption, 小图拼成网格提高密度; ASR 转写还会被改写成更规整的文本. 数据管理器 **REEAO** 把所有数据源切成定长记录, 在训练开始前就确定一条逐 bit 可复现的 token 序列, 节点数, 并行策略, batch 或上下文长度中途变化时也不重复, 不遗漏. 这一段和评测是连着的: 报告把 Base 在 CMMLU, ChineseSimpleQA 上的优势归到 「预训练数据的迭代优化」, 把 QA 表现归到常识数据格式优化和高质量合成数据. 这些归因没有配消融, 只能当作作者的解释.

过滤和合成在报告里是一对互相抵消的操作. 启发式规则负责去重和去掉低质量样本, 模型打分负责质量评估, 两步都会削减数据量; 作者承认这是质量和数量的取舍, 补量的办法是自蒸馏和 「多模态转换」 两类合成, 后者大概是把一种模态的内容改写成另一种模态的训练样本, 报告没有给例子. 推理语料单独处理: 挑代表性样本, 按推理类型和难度分组, 再滤掉低质量条目, 报告说这些步骤 「显著」 提升推理能力, 同样没有数字. 图文对在过滤之后还要分类打标, 分成自然场景, 表格, 截图, 图表, 文档等类型, 再抽一部分重写 caption; 图文交错数据要做页内图文去重, 去低分辨率图, 去乱码和广告, 检测顺序错乱的内容. 整条流水线外面套着一个人和模型协作的迭代环: 选核心数据集, 训候选模型评估, 人工分析结果, 再改过滤和挖掘策略.

这一节的空白也要讲清. 报告给了数据地图的维度, 没给按这些维度切出来的配比; 给了 DIKW 五档, 没给每档占多少, 上采样倍数是多少; 说了 「trillions」 级文本 token, 没说图像, 视频各多少样本, 多模态联合阶段里文本占几成. 和 ERNIE 3.0 那张逐库列出 token 数和 multiplier 的表 1 相比, 4.5 在数据上公开的是方法, 不是配方. 所以读者能复述它怎么洗数据, 却无法估算它在每种数据上花了多少算力. 数据处理的通用做法见 [数据处理](../../../../llm-guide/3-预训练/3.1-预训练数据/3.1.3-数据处理/3.1.3-数据处理.md).

### 2.2. 三段预训练: 先把文本骨干练稳, 再接视觉

表 3 把 VL 模型的预训练分成三段. 第一段只训文本: 短上下文在 「trillions」 级文本 token 上打底, 再拉长上下文, 先到 32,768 并把 RoPE 基频从 10k 提到 160k, 再到 131,072 并提到 500k, 全程上采样长于 16k 的文档. 第二段只训视觉: 先让 ViT 配一个较小的语言模型在图文对上预训练, 再冻结 LLM 和 ViT, 只训 adapter, 视觉专家和视觉路由器, 最后解冻 ViT 并上采样高质量图文对, 这三步序列长度都是 8,192. 第三段放开全部参数, 在文本, 图像和视频混合数据上先训 8,192 再训 131,072. 顺序本身就是对路由塌缩的回应: 文本专家先定型, 视觉专家后接入, 共享的注意力在第二段被冻住.

表 3 的短上下文长度印 4,096, 正文同一段写 「8k」, 两处差一倍, 报告没有解释. MFU 那句的序列长度也是 4096, 和表 3 一致. 学习率三档不按参数量缩放: A47B 2.2e-4, A3B 3.14e-4, 0.3B 4.4e-4; batch 分别是 65M, 50M, 8M token; 权重衰减都是 0.1, 梯度裁剪都是 1.0, 两个 MoE 档的 ViT 分层学习率衰减是 0.9. MFU 那句写的全局 batch 是 15120, 乘以序列 4096 约 62M token, 和表 2 的 65M 对不齐, 可能是不同阶段或不同计数口径, 页上没有说明. 所有模型用 WSD 学习率日程. 预训练策略的背景见 [预训练策略](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.4-预训练策略/3.2.4-预训练策略.md).

### 2.3. 两个新损失: 路由正交和按序列长度归一

除了常规的负载均衡辅助损失和 z-loss, 4.5 加了两项. 第一项是 **router orthogonalization loss**. 路由矩阵第 $i$ 列 $w_i$ 是专家 $i$ 的权重向量, 对隐状态 $h$ 的路由 logit 是 $s_i = w_i^\top h$. 式 1 对 $k$ 个专家定义

$$L_{orth} = \sum_{i=1}^{k}\sum_{j=1}^{k}\big(\hat w_i^\top \hat w_j - \delta_{ij}\big)^2, \qquad \hat w_i = \frac{w_i}{\|w_i\|_2}.$$

归一化后 $\hat w_i^\top \hat w_i = 1$, 对角项恒为 0, 式子只剩 $L_{orth} = 2\sum_{i<j}\cos^2(w_i, w_j)$; 64 个专家是 2016 对余弦的平方和. 两个专家的 $w$ 方向接近时, 对任何 $h$ 它们的 logit 同高同低, 在 top-k 里总是成对出现, 这一项把每一对往正交推, 针对的就是专家同质化, 不同专家学出高度重叠的表示. 它只依赖路由权重, 作者认为直接加进总损失会污染 Adam 的一阶和二阶矩估计, 所以仿照 AdamW 处理权重衰减的方式, 把它从梯度里拆出来直接改权重. 按正文描述可以写成 $w \leftarrow w - \eta_t\,\mathrm{Adam}(g) - \lambda\,\nabla_w L_{orth}$, $\lambda = 10^{-3}$, 第二项不乘学习率 $\eta_t$ (报告没印这一式). 所以在 WSD 的衰减段, $\eta_t$ 趋近 0 而正交项的步长不变, 它的相对力度反而变大, 报告没有讨论这一点.

附录 A.1 在 21B-A3B 规模上做了消融, 训练 loss 两边接近, 下游平均分从 50.2 升到 53.1. 涨幅最大的是 CMMLU (51.7 → 63.4), C-Eval (55.4 → 63.5), HumanEval (50.6 → 58.5) 和 MMLU (46.1 → 51.6); GSM8K 反而从 63.3 降到 60.7, Math 从 21.5 到 21.3. 作者把涨点解释成分布外泛化更好, 数学上的下降没有解释. 附录这一段的系数在抽取稿里字符残缺, 能辨认出 1×10 的某次幂, 和正文的 1e-3 是否一致无法确认. 第二项 **token-balanced loss** 管的是多模态样本长度不均: 常规做法用未掩码的文本 token 数做分母, 图多字少的样本梯度会被放大; 改成用整条序列长度做分母后, 每条样本的权重更平均, 目的是减小梯度方差.

把两个分母写出来更容易看清差别. 记样本 $i$ 的掩码区 (图像 token 和 prompt) 为 $M_i$, 未掩码区为 $U_i$, 单 token 损失 $\ell^{(i)}_j = -\log P(y^{(i)}_j \mid y^{(i)}_{<j};\theta)$. 式 2 和式 3 分别是

$$L^{(i)} = \frac{1}{|U_i|}\sum_{j\in U_i}\ell^{(i)}_j, \qquad L^{(i)}_{balanced} = \frac{1}{|U_i| + |M_i|}\sum_{j\in U_i}\ell^{(i)}_j.$$

求和范围相同, 只有分母不同, 两者之比是样本里文本 token 的占比 $|U_i|/(|U_i|+|M_i|)$. 一条 8K 的样本里如果只有 200 个文本 token, 这 200 个 token 每个分到 1/200 的权重; 另一条纯文本样本有 8,000 个文本 token, 每个只分到 1/8,000 (举例用). 前一条样本的单 token 梯度被放大约 40 倍. 换成式 3 后, 两条样本的单 token 权重都约为 1/8,000. 代价是图多字少的样本在总损失里的份额变小, 报告的立场是先保证梯度稳定. 这两项新损失和原有的负载均衡辅助损失, z-loss 叠在一起, 各项系数里只有正交损失公开了 1e-3, 辅助损失和 z-loss 的系数本页没有写.

### 2.4. 用 EMA 看中间 checkpoint

3.5 节给了一段关于 EMA 的推导. 设 $\delta_i = \theta_{i+1} - \theta_i$ 是第 $i$ 步的更新, EMA 递推 $\theta^{EMA}_t = \alpha\,\theta^{EMA}_{t-1} + (1-\alpha)\,\theta_t$, 初值 $\theta^{EMA}_0 = \theta_0$. 展开后是式 4:

$$\theta^{EMA}_n = \theta_0 + \sum_{i=0}^{n-1}\eta^{(\alpha)}_i\,\delta_i, \qquad \eta^{(\alpha)}_i = 1 - \alpha^{\,n-i}.$$

$n=1$ 时代入即得 $\theta_0 + (1-\alpha)\delta_0$. 普通参数给每个 $\delta_i$ 的权重都是 1, EMA 给最早的更新接近 1, 给最后一步只有 $1-\alpha$, 越近的更新权重越小, 形状就像一条衰减到零的学习率曲线. 作者据此定义 **「有效衰减窗口」**: 给定阈值 $\epsilon$ (例如 0.001), $\eta^{(\alpha)}_i < 1-\epsilon$ 的更新算在窗口内. 这个条件等价于 $\alpha^{\,n-i} > \epsilon$, 也就是 $n - i < \log\epsilon / \log\alpha$, 窗口长度 $\hat W = \log\epsilon/\log\alpha$, 反过来就是式 5 的 $\hat\alpha = \exp(\log\epsilon / \hat W)$. 实际做法是每 $s = 4$ 步更新一次 EMA, 窗口按训练步算是 $T = \hat W \cdot s$, 取总步数的 1/10, 所以 $\hat W$ 是总步数的 1/40. 报告没给总步数; 假如是 10 万步 (举例), $\hat W = 2500$, $\hat\alpha = \exp(-6.91/2500) \approx 0.9972$. EMA 累加放在 CPU 上异步做, 不阻塞训练.

这段的用途要读准. 报告的原话是 「decay no more」: 过去为了评估训练中途的模型, 要反复从某个 checkpoint 分叉出来做一次学习率衰减, 现在直接拿 EMA 参数代替. 它没有说最终模型取消了 WSD 的衰减段, 也没有给 EMA 对比显式衰减的具体分数, 只说 「comparable」. 外部文献的结论更谨慎: 权重平均可以近似一段较短的衰减, 但完全去掉学习率衰减通常更差; 另一篇把 checkpoint 合并对应到衰减曲线的工作发现, EMA 对应凸的指数衰减, 效果排在线性衰减和 1-sqrt 衰减之后. 所以 **4.5 这段更适合当评估工具来看**, 能不能替代最终退火, 本页证据不够.

## 3. 训练系统, 后训练与部署

### 3.1. 训练系统: 2016 张卡上的 47%

47% MFU 的对象是最大的语言模型, 条件是 2016 张 H800, RoCE 网络, 序列 4096, 全局 batch 15120, 8 路专家并行, 12 路流水线并行, ZeRO-1 数据并行. 主要手段有四条: 专家并行限制在节点内, 用 NVLink 走 all-to-all, 报告说效果和 DeepEP 相当; 门控乘法挪进专家块内部, 省一次通信; 内存友好的 virtual pipeline 调度; FP8 混合精度, 权重按块, 激活按 tile 量化, 做法和 DeepSeek-V3 相近, 第一次 all-to-all 也用 FP8 传. 再加上算子级重计算和 FlashMask 注意力掩码. FP8 训练的通用背景见 [FP8混合精度训练详解](../../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/02-FP8混合精度训练详解.md).

多模态训练的麻烦在负载不均. ViT 只有 630M, 按数据并行嵌在流水线里, 反向传播单独改写. 每条序列里图文比例不同, 视觉专家和文本专家的负载也跟着变, 报告用轮转分配加打包序列并行做分层负载均衡, VL-424B 端到端最多提速 32%, 这是相对无均衡基线的速度比, 和 47% 的利用率不是一回事. ViT 和 MoE 骨干的并行方式不同, 这是第 5.1 节要解决的第一件事. 如果把 ViT 只放在流水线第一段, 第一段会比其他段重得多; 4.5 的做法是在每张卡上都复制一份 ViT, 让它的数据并行维嵌进骨干的混合并行拓扑里. 前向时每张卡各自算视觉特征, 再汇集到骨干流水线第一段; 反向时自动求导停在骨干的第一个模块, 到不了 ViT, 于是等骨干反向结束后, 把视觉特征的梯度从第一段散发回各卡, 各卡再对自己那份 ViT 做反向, 最后 all-reduce 同步 ViT 梯度. 负载均衡分两级: 先把所有打包序列按 token 数排序, 轮转分给各卡, 让总 token 数大致相等; 再在注意力之外沿序列维均分 (packed sequence parallelism), 注意力之内用一次 all-to-all 把序列维和头维互换, 算完再换回来. 端到端最多 32% 的提速就来自这两级.

骨干一侧有三处省显存的改动. 第一, 门控概率乘法从第二次 all-to-all 之后挪进专家计算块内部, 第二次 all-to-all 的输出用完即可释放, 代价是多一次轻量 all-to-all 和概率重排. 第二, virtual pipeline 一般认为第一段最占激活显存, 但最后一段要算损失, 反而可能成为瓶颈, 4.5 让最后一段算完损失的前向立刻做反向, 最多只保留一个 VPP chunk 的激活; 梯度累积步数少于流水线段数两倍时只能用 F-then-B 调度, 这时每步结束就释放参数梯度占的显存. 第三, FP8 训练里 up-gate 线性层只保留 FP8 输入, 反向算权重梯度时做一次 「反量化, 转置, 再量化」, 第一次 all-to-all 因此也能用 FP8 传; SwiGLU, 门控乘法和 FP8 量化融合成一个算子. 重计算做到算子级: 常规做法对 op1 和 op3 重计算时仍会多存 op1 的输出, 4.5 改为保留 op2 的输出而不是输入, 再按 「省多少显存, 花多少时间」 给每个算子排序, 只对性价比高的做重计算. 多模态预训练序列更长, 视觉专家又多出一批参数, 所以 VL 模型在 EP, PP, ZeRO-1 之外再加张量并行.

容错这一块写得比多数技术报告细. TraceHang 用并行拓扑和通信记录自动找出挂死的发起者; 在线 SDC 扫描利用流水线空泡, 在每段空闲时用固定输入做一次计算和通信, 与标准答案比对, 报告说已抓出几台静默出错的节点, 不影响吞吐; 并行预热让所有流水线段同时跑一个假 chunk, 首步延迟降到基线的 1/p, $p$ 是流水线段数. 零开销 checkpoint 的依据是参数和优化器状态只在优化器执行时改变, 其余时间可以把显存到内存的拷贝拆碎, 塞进不走节点间通信的算子 (注意力, 稠密前馈, 节点内通信) 里, 做到每步都存一次; 节点故障时, 用所有健康网卡通过 RDMA 点对点把内存里的最新 checkpoint 传给替换节点, 与新节点的环境初始化重叠. 端到端自动恢复在 8 分钟以内, 并在 「中断频率与集群规模成正比」 的假设下推算万卡规模有效训练时间超过 98%, 后者是推算, 不是实测.

引言里 「用 96 张 GPU 这样有限的资源也能高效训练」 一句, 在第 7 节有对应: ERNIEKit 的 FP8-QAT 把最大语言模型微调的最低卡数从 96 张降到 16 张, 质量与 BF16 的 SFT 相当. 所以 96 更像是微调或继续训练的门槛, 和 2016 张卡上的预训练不是一回事. 因为本页没有总 token 数, 按 6ND 估算预训练算力这一步做不了.

### 3.2. 后训练: 文本走 PPO 加 UPO, 视觉走 GRPO

文本模型从多模态预训练模型得来: 去掉视觉专家, ViT 和 adapter. SFT 数据按主题分类, 正文说 「十个领域」, 实际列出的是科学与数学, 代码, 逻辑, 信息处理, 创意写作, 多语言, 知识问答, 多轮与角色扮演, 安全, 共九项. 数据再分推理和非推理两类, 推理题会给同一问题配多条不同推理路径的回答, 为后面的 RL 探索留余地. 总量 2.3M 条, 平均训 2 个 epoch. 奖励系统按任务分: 推理题用规则验证器, 参考答案引导的 LLM 评判, 代码沙箱, 以及带参考答案的判别式奖励模型; 非推理题用清单式验证器, 生成式奖励模型和判别式奖励模型. SFT 背景见 [SFT](../../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md).

RL 在 PPO 框架内做, 有两处改动. 一是渐进式 RL: 先只用逻辑语料, 再以数学和代码为主, 最后用混合推理与非推理的通用数据. 二是 **UPO**: 在 PPO 的目标里并入 DPO 的成对偏好损失, online 版在每轮 rollout 的多条回答上拒绝采样组对, offline 版预先生成偏好对; 作者说这样既稳住训练, 又降低 reward hacking 的风险, 但没有给 UPO 的消融数字. 数据侧还有三条过滤: 去掉正确率恒为 0 或 1 的题, 去掉组内奖励方差太小的题, 奖励按来源和主题分组后各自归一化.

这三条过滤各有针对. 一道题如果模型采样的所有回答全对或全错, 组内奖励没有差别, 对按组比较的优势估计来说梯度为零, 留着只占 rollout 算力; 组内方差小的题同理, 提供的区分信息太少. 奖励分组归一化针对的是奖励来源不统一: 规则验证器给的是 0/1, 生成式奖励模型可能给连续分, 判别式奖励模型又有自己的分布, 不同主题的打分区间也不同, 直接混在一个 batch 里, 分数区间宽的来源会主导更新. 报告说这些改进 「减小了奖励信号的异质性」, 没有配训练曲线. 渐进式 RL 的三段顺序 (逻辑, 数学和代码, 通用) 也没有和 「一次混合训练」 做对照, 顺序是否必要, 本页证据不足.

UPO 在机制上值得多看一眼. PPO 的目标是让单条回答的期望奖励变大, 奖励模型打分有噪声时, 策略可能学会讨好打分器; DPO 损失只看同一问题下两条回答的相对好坏, 对打分的绝对值不敏感. 报告没有印 UPO 的公式, 按 「把 DPO 损失并进 PPO 框架」 的描述, 最直接的写法是 $L_{UPO} = L_{PPO} + \lambda L_{DPO}$ (推测), 其中

$$L_{DPO} = -\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}\Big),$$

$y_w$, $y_l$ 是同一 prompt 下的胜负回答. $\lambda$, $\beta$, 以及 $\pi_{ref}$ 取 SFT 模型还是上一轮策略, 报告都没写. 这一项里只有两条回答的对数概率差, 奖励分数只在组对时用来排胜负, 不决定梯度大小, 奖励模型把某类回答整体打高, 只要胜负顺序不变, DPO 项就不受影响. 把 DPO 项并进 PPO, 相当于在逐条回答的奖励信号之外再加一条成对约束, online 版的偏好对来自当轮 rollout 的拒绝采样, 和当前策略分布一致, offline 版预先生成, 成本低但会逐渐偏离当前策略. online 与 offline 各用在哪个阶段, 报告也没有写. 做法参照 [PPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md) 与 [DPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.2-无奖励模型的对齐DPO-KTO/01-DPO/01-DPO.md).

视觉模型是三段 SFT 加一段 RL. 感知数据大量合成: 程序生成的拼图, 几何图形, 函数图像; 真实 STEM 图片则重写 caption, 验证标准是一个纯文本推理模型只看 caption 就能反复答对原题, 能靠图中文字直接答出的样本剔除. 推理冷启动只用纯文本推理数据, 作者观察到模型没见过图, 也会说出 「让我再看一眼图」 这种话. 之后用拒绝采样扩充多模态推理数据, 再把思考与非思考合进一个模型: 非推理样本前面加空的 `<think>` 标签并屏蔽梯度, 同时仿照 DeepSeek-R1T-Chimera 把非思考模型的多模态专家搬进思考模型. RL 阶段的可验证任务有视觉 STEM (选择题改成开放题), 超过 10k 道合成视觉谜题 (两个 LLM 分别查自洽和答案), 以及 UI2Code; 另训一个从 ERNIE-4.5-Base 初始化的 Bradley-Terry 奖励模型做 RLHF. 算法换成 [GRPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md), 加上 DAPO 的动态采样和超长过滤. GRPO 对同一 prompt 采 $G$ 条回答, 优势取组内标准化 $A_i = (r_i - \mathrm{mean}(r))/\mathrm{std}(r)$, 全对或全错时分子恒为 0, 这一组不产生梯度. 文本侧的应对是训练前按正确率离线剔除这类题; 动态采样在每轮 rollout 之后在线做, 丢掉全对全错的组, 继续采样直到 batch 填满有效组, 训练中途模型变强, 原本有区分度的题变成全对, 也会被即时滤掉. 超长过滤按 DAPO 的定义是被长度截断的回答不计损失, 报告只写了名字. 同一份报告里文本和视觉用了两种 RL 算法, 报告没有解释为什么.

### 3.3. 部署: 量化贴着专家走

300B-A47B 里专家权重占总参数 90% 以上, 占预填推理时间约 40%, 解码约 60%, 所以量化首先打在专家的矩阵乘上. W4A8 用按通道的静态 INT4 权重和按张量的静态 INT8 激活. 为了在 64 个专家上做 GPTQ, 报告提出 **MEPC**: 校准只跑预填, 尽量点亮更多专家; 没被点亮的专家直接取同层已激活专家量化参数的平均; 所有专家权重拼成一个张量并行做 GPTQ, Up-Gate 层只对热点专家做完整更新. 张量并行下, 离群值被离线重排集中到一张卡上: 先汇总各卡按通道的激活绝对值最大值, 再全局排序, 把 Up-Gate 的列和 Down 的对应行一起重排. Up-Gate 按列切, Down 按行切, 中间通道 $c$ 的贡献 $W^{down}_{c,:}\,a_c$ 只在最后的 AllReduce 里相加, 列和行一起换卡, 求和项一个不少, 输出不变; 变的是每张卡上的通道集合, 离群通道集中到一张卡后, 其余卡各自的量化 scale 不再被它们撑大. 节点内的离群值用分块旋转加置换来摊平. 和 W8A16 基线比, 通用任务 -0.49%, 指令遵循 -0.06%, 推理 +0.11%, 数学 -0.02%, 代码 -1.10%. 背景见 [MoE模型量化技术综述](../../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.1-量化/09-MoE模型量化技术综述/09-MoE模型量化技术综述.md).

2-bit 用 **卷积码量化 CCQ**, 思路来自 QTIP: 用卷积码构造免查表的码本, 保留向量量化的精度, 推理时仍按标量方式解码. 混合编码把 4-bit 标量量化压到等效 2.75 bit, 3-bit 压到 2.5 bit, 再按码值分布聚类压到等效 2 bit. 体积比 BF16 少约 80%, 300B-A47B 可放进一张 141GB 的 H20; 4-bit 版需要 4 张 80GB. KV cache 和注意力用静态量化, 支持 FP8, INT8, INT4 和按头或按通道两种粒度, 分块 Random Hadamard 变换并进 $W_v$ 和 $W_o$, 推理时没有额外开销. FP8 的量化用式 6:

$$x_q = \mathrm{fp8\_e4m3}\Big(\mathrm{clip}\big(\big\lfloor x_{bf16}\cdot \mathrm{fp8\_max}/\mathrm{scale}\big\rceil,\ -448,\ 448\big)\Big).$$

默认 fp8_max 是 448, 校准得到的 scale 正好映到 E4M3 的最大值; 4.5 把 fp8_max 设得更小, 推理任务准确率约提高 2%, 取值没印. 作者的理由是 E4M3 在 ±448 附近格点稀, 误差大: 3 位尾数下, [256, 448] 内相邻格点相距 32, [128, 256) 内相距 16. 这个说法对绝对误差成立, 按相对误差算, 每个二进制段都是 $2^{-3}$ 一档. fp8_max 调小后, 比 scale 大的值还有 fp8_max 到 448 这段余量才被 clip 截断 (推测); 正文说的是校准时截掉或排除离群值, 哪种效果在起作用, 报告没有拆开.

内核方面, INT4 权重限制在 [-7, 7], 左移 4 位得到 [-112, 112] 的 INT8, 八个数三条指令完成转换. 左移 4 位等于乘 16, INT8 Tensor Core 以 INT32 累加 $\sum_k a_k\,(16 w_k)$, 这个 16 倍可以和按通道的权重 scale, 激活 scale 一起在 epilogue 里除掉 (推测, 报告只说反量化放在 epilogue).

注意力侧 INT8 版的 softmax 用 Schraudolph 的快速指数. float32 的位模式按整数读, 近似等于 $2^{23}(\log_2 y + 127)$, 反过来把 $2^{23}(x\log_2 e + 127)$ 取整后按 float 重新解释, 得到的就是 $e^x$ 的近似, 报告里的 scale 和 bias 就是这类预设常数. $QK^\top$ 以 INT8 算出整数 $x$ 后, 反量化系数 $S_{qk}$ 和指数并成一条 FMA (式 8):

$$e^{x S_{qk}} \approx F_{float}\big(\lfloor 2^{23}\,\mathrm{scale}\,S_{qk}\rfloor\,x + \lfloor 2^{23}\,\mathrm{bias}\rfloor\big),$$

$F_{float}$ 是位模式重解释, 乘数和加数都是离线算好的常数. 这一版在 A800 上 128K 预填比 FlashAttention-2 快 68%.

FP8 版对应 C4 (KV cache 按通道非对称 4-bit), 两次 GEMM 都用 E4M3, 省下的是 CUDA Core 上的转换和反量化. 式 9 把 UINT4 放进 E4M3 的低 4 位, 得 $Y = 2^{-9}X$: E4M3 指数偏置 7, 低 4 位是 1 位指数加 3 位尾数, $X \le 7$ 时指数域为 0, 是非规格数 $\frac{X}{8}\cdot 2^{-6}$; $X \ge 8$ 时指数域为 1, 值为 $(1 + \frac{X-8}{8})\cdot 2^{-6}$, 两段都等于 $2^{-9}X$, **0 到 15 全部精确**, 常数 $2^{-9}$ 并进 scale 即可. 存储时 8 个值按 [0,4,1,5,2,6,3,7] 交错, 一条 SHIFT 加一条 LOP3 转完 8 个, 摊到每个值 0.25 条指令. K 的零点用式 10 消掉: $Q(K^\top - Z_k)S_{qk} = QK^\top S_{qk} - QZ_kS_{qk}$, $Z_k$ 按通道, 每个 key 的零点向量相同, $QZ_k$ 在第 $r$ 行上是同一个常数 $q_r^\top z_k$, softmax 对整行加常数不变, 这一项直接丢掉, K 只剩移位和按位与. V 的零点按式 11 拆成 $O = PVS_v - PZ_vS_v$: $S_v$ 按通道, 而 $PV$ 沿序列维累加, 所以 $S_v$ 可以挪到乘完之后; $PZ_v$ 的第 $r$ 行是 $(\sum_j P_{rj})\,z_v$, 只用到 softmax 本来就维护的行和. 这一版比 FlashAttention-3 的 FP8 实现平均快 50%.

报告还写了一句旧稿漏掉的内容: ERNIE 4.5 带 MTP 模块, 推理时用它做投机解码, 输出吞吐提高 60%, 每 token 延迟与普通自回归相当. 训练节没有交代 MTP 的层数和损失权重, 本页只能确认它存在, 背景见 [多Token预测MTP深度解析](../../../../llm-guide/2-核心原理与架构/2.4-前沿架构与变体/2.4.6-多Token预测MTP深度解析.md). 部署上, 预填用 8 路专家并行和分块 FP8, 注意力不做张量并行; 解码用 W4A8, 专家并行可从 EP8 到 EP64. 节点内 all-to-all 走 NVLink, EP8 比 EP16 效率高 70%; 解码实例可以临时接短输入的预填请求. 在输入 2K, 输出 400, 每 token 延迟不超过 50ms, 不开 prompt cache 的条件下, 每个 H800 节点约 56k 输入 TPS 和 18k 输出 TPS. 预填与解码分离的做法见 [SGLang与Prefill-Decode分离](../../../../llm-guide/9-AI工程化与基础设施/9.4-推理服务框架/9.4.1-SGLang与Prefill-Decode分离.md).

PD 分离系统的效率取决于三件事: KV cache 跨节点传输, 专家路由的 all-to-all, 以及各层负载均衡. KV cache 传输模块基于 RDMA, 只依赖 OFED 这类基础运行时, 减少完成队列条目数并开启 PCIe relaxed ordering, 节点内走 NVLink, 节点间走 RDMA. 负载均衡分三层: 数据并行层由全局调度器按 KV cache 命中率和 token 数分发请求; 专家并行层用 DeepSeek-V3 式的冗余专家和全局重排, 权重预取加异步加载, 灰度重排避免同时触发; PD 比例层持续监控各实例负载并动态调整预填和解码实例的比例. 报告还指出, 线上吞吐常常卡在预填资源上, 所以允许解码实例临时承担短输入请求的预填, 对每 token 延迟几乎没有影响. 最小部署单元是一台 8 卡节点, 预填和解码各自至少一台.

这些能力大多随 FastDeploy 开源. 它兼容 vLLM 和 OpenAI 协议, 支持 W8A8, W8A16, W4A8, W4A16, W2A16 多种精度, 内置的 2-bit 模型据称相对 FP8 接近无损, 可单卡跑在 141GB 的 H20 上; 除 NVIDIA GPU 外, 还能部署到昆仑芯 XPU, 海光 DCU, 昇腾 NPU. 训练侧的 ERNIEKit 覆盖预训练, SFT, LoRA, DPO, QAT 和 PTQ, 其中 FP8-QAT 训出的模型可以直接做离线的按张量 FP8 量化, 推理时省掉预训练阶段那种按块, 按 tile 的动态量化开销. 训练, 量化, 部署三段在同一套 PaddlePaddle 栈里贯通, 这是 4.5 和只放权重的开源模型的主要区别, 也意味着社区用 llama.cpp 或 vLLM 跑它时, 拿不到报告里 2-bit CCQ 这类专用格式的收益.

## 4. 评测与家族位置

### 4.1. 评测: 自测基线, 自动评判和一处图文不符

Base 对比表 4 有 28 项, 报告说 300B-A47B-Base 在其中 22 项超过 DeepSeek-V3-671B-A37B-Base. 按表逐项核对, DeepSeek-V3 领先的可读项是 MMLU (87.9 对 87.4), MMLU-Redux (89.4 对 89.2), DROP (84.6 对 82.8), CLUEWSC (81.4 对 79.9), SVAMP (92.7 对 90.0), MBPP+ (76.7 对 74.9), 正好六项; 知识两项和 MGSM, ASDIV 两项在抽取稿里数字交错, 读不出来, 22/28 能对上的前提是这几项都算 ERNIE 领先. ERNIE 的优势集中在中文: C-Eval 91.5, CMMLU 91.2. 两个对照模型的分数是百度自己重测的, 不是原论文报告值. 21B-A3B-Base 对 Qwen3-30B-A3B-Base 的领先项主要是 BBH (77.5 对 72.7) 和 CMATH (93.7 对 88.9).

Base 评测的协议写得比较全, 读分数前要先对齐 shot 数. 通用知识类 (C-Eval, CMMLU, MMCU, AGIEval, MMLU, MMLU-Redux, MMLU-Pro) 都是 5-shot; SimpleQA 和 ChineseSimpleQA 是 10-shot; BBH 和 DROP 是 3-shot, ARC, HellaSwag, PIQA, WinoGrande, CLUEWSC 是 5-shot; GSM8K 是 5-shot 并去掉了计算器标签, MATH 是 8-shot, 同时有 CoT 和直接作答两种; 代码的 EvalPlus 和 MultiPL-E 是 0-shot. 28 项里数学占 8 项, 推理 8 项, 通用 7 项, 代码 3 项, 知识 2 项, 22/28 这个比例的权重因此偏向数学和推理, 知识题只有两道, 却是报告最强调的优势. 后训练评测的 LiveBench 用 2024-11-25 版, LiveCodeBench 用 v6 (2024-08-01 至 2025-05-01), 这类带时间窗的基准可以减少数据泄漏, 但对照模型的发布时间不同, 窗口对它们的 「新鲜度」 也不同.

后训练文本模型 (表 5) 对手是非思考模式的 Qwen3-235B-A22B, DeepSeek-V3-0324 和 GPT-4.1. ERNIE 领先的是知识和指令遵循: SimpleQA 45.9 (GPT-4.1 为 40.2), ChineseSimpleQA 77.1, IFEval 88.0, Multi-IF 76.6, 另有 MATH-500 96.4, BBH 94.3. 落后的集中在难推理和竞赛: AIME'25 35.1 对 DeepSeek-V3-0324 的 47.7, Zebralogic 58.1 对 81.8, LiveCodeBench 38.8 对 45.4, MMLU-Pro 78.4 对 81.2. 报告把指令和知识上的优势归到统一奖励系统, 这个归因同样没有消融. 表 6 里 21B-A3B 对 Qwen3-30B-A3B, SimpleQA 是 24.2 对 4.7, AIME'25 是 19.7 对 23.2. 评测方法的一般问题见 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据.md).

VL 评测大部分基准加了 LLM-as-judge 流程, 评判模型是 GPT-4.1 和一个从它蒸馏出的小模型; OpenAI-o1 的分数是 2025 年 6 月通过 API 收集的; 视频基准上 Qwen2.5-VL 的数字直接取自其论文或 Hugging Face 页面. 所有多模态任务都用零样本; 只有 OCRBench, RealWorldQA, DocVQA 完全用官方指标, 其余在官方实现之外加了 LLM 评判; CCBench 用 「先描述再作答」 的提示, AI2D 用 transparent 设置并对齐 Molmo 的实现, 视频题按选项字母自动匹配. 这几条都会影响分数: 同一个模型换一种提示或评判器, 在 CCBench 这类题上差几分并不少见, 而 Qwen2.5-VL 的图像分数是百度用开源权重重测的, 视频分数却是引用值, 两类对比的口径不一致. 正文说思考模式在 MathVista, MMMU, VisualPuzzle 等基准上 「有些情况下超过 o1」, 但表 8 里 MMMU 是 o1 77.7 对 ERNIE 70.0, VisualPuzzle 是 48.5 对 46.3, **三项里只有 MathVista (78.9 对 71.4) 真的超过**. 对比表 7 和表 8 还能看到 TestingTime 的代价: 424B 从非思考到思考, MMMU 从 67.3 到 70.0, MMMU-Pro 从 52.6 到 58.8, VisualPuzzle 从 41.0 到 46.3; 但 CountBench 从 93.3 降到 89.0, RealWorldQA 从 75.2 到 73.2, OCRBench 从 883 到 872. **推理类涨, 感知类小降**, 这和正文 「思考模式保持可靠感知」 的说法不完全一致.

小模型的成绩更能看出取舍. VL-28B-A3B 在非思考模式下对 Qwen2.5-VL-7B 和 32B, 中文视觉知识 CCBench 是 81.0, 明显高于对方的 70.4 和 73.0; 但 SimpleVQA 只有 46.0, 低于 51.7 和 53.6, CV-Bench 76.1 也低于 7B 的 79.7. 中文图像知识强, 通用视觉事实和空间感知偏弱, 和预训练数据偏中文的描述一致. 0.3B 稠密模型在表 6 里 C-Eval 32.9, AIME'25 0.2, 报告只说它可以在普通笔记本上推理, 没有把它当成能力对比的主角. 这一档的意义在部署和端侧实验, 读分数时不宜和 A3B 档放在一起比.

### 4.2. 在家族里的位置

从 3.0 到 4.5, 百度换掉的不只是规模. 3.0 的 「知识」 靠知识图谱和百科句子配对放进语料, 模型是理解和生成分塔的稠密网络, 下游靠逐任务微调; 4.5 的知识靠 DIKW 分层和合成数据, 模型是 decoder-only 的异构 MoE, 下游靠 SFT 和 RL, 交付物从一个 API 变成十组开源权重加一整条量化部署链. 中间的 3.5 和 4.0 在本目录只有千帆平台的短材料, 没有技术报告, 所以这四年间的结构演变无法逐代核对.

往后看, ERNIE 5.0 把 4.5 的模态隔离路由换成模态无关路由, 文本, 图像, 音频, 视频共用一个专家池, 并且统一成自回归生成. 4.5 用隔离路由和分阶段接入视觉来躲路由塌缩, 5.0 选择正面处理这个问题, 两篇合起来读, 能看出同一个团队对 「多模态专家该不该分开」 的判断在半年里变了. 4.5 留下的是训练系统, FP8, 量化和 PD 分离这套基础设施, 5.1 的 RL 系统仍在沿用 FP8 和专家并行的思路.
