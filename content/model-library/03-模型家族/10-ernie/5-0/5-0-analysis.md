## 1. 主张与结构

### 1.1. 报告的主张和它没有给的底数

ERNIE 5.0 Technical Report 是 arXiv:2602.04705, 日期 2026 年 2 月 4 日, 正文到 Conclusion 共 27 页, 连贡献者和参考文献一共 36 页, 13 张图, 12 张表, 5 个编号式. 它的主张可以拆成三条. 第一, 一个骨干从零开始同时训练文本, 图像, 视频, 音频, 理解和生成都走自回归. 第二, 骨干是超稀疏 MoE, 专家路由不按模态分配. 第三, 一次预训练里用弹性训练带出一族深度, 专家数, top-k 各不相同的子模型. 摘要最后把这三条合成一个 「首个」 的说法: 公开披露的模型里, 第一个达到生产规模, 能理解也能生成的万亿参数统一自回归模型.

读这份报告要先接受一个事实: 它没有给总参数和激活参数的精确值. 正文里能找到的只有 「trillion-parameter」, 「trillion-level」 和 「激活率低于 3%」. 由此只能推到数量级: 假如总参数就在一万亿附近, 每个 token 激活的参数在三百亿以下. 层数, 专家数, top-k, 隐藏维度, 词表大小, 预训练 token 总数也都没有. 所以后面凡涉及 「多大」 的判断, 都只能停在比例上. 这一点和同目录下 ERNIE 4.5 的报告不同, 两份不能混读. 评测口径的一般问题可以对照 [评测科学与证据](../../../../llm-guide/5-评测、安全与治理/5.1-评测科学与证据/5.1-评测科学与证据.md).

### 1.2. next-group-of-tokens: 统一的是训练范式, 词表并不统一

**「Next-Group-of-Tokens Prediction」** 这个名字容易让人以为各模态共享一个输出头, 每步吐一组 token. 实际上三种模态的 「组」 各不相同. 文本仍是逐 token 预测, 外加 MTP, MTP 损失权重在 8K 阶段是 0.3, 中训降到 0.1. 视觉用 **NFSP**: 一张图按尺度从粗到细生成, 同一尺度内的 token 彼此双向可见并行预测, 之前的尺度和历史帧因果可见, 所以视觉的 「一组」 是一个尺度的全部 token. 音频用 **NCP**: token 率 12.5 Hz, 每个时间位置由若干层 RVQ 码组成, 顶部若干层插入音频头按层依次出码, 所以音频的 「一组」 是一个时间位置上的各层残差码.

组的大小直接影响每组在损失里占多大分量, 可论文没有写预训练损失式. 全文 5 个编号式全在 RL 部分. 与组大小有关的线索只有两条: 视觉生成做了损失重加权, 偏重早期尺度, 用来抵消多尺度 tokenization 造成的 token 数失衡; §3.2 另有一个 「posterior-based loss weighting」, 把各模态的自回归损失调到同一区间. 两者都没给公式. 这意味着 **「统一目标」 在文字层面成立, 在损失层面仍是按模态分别加权再相加**, 权重怎么定看不到.

视觉 tokenizer 还有一个渐进切换: 先用低 bit 小词表, 再逐步换到高 bit 大词表, bit 数直接对应词表大小. 作者说这让骨干早期的优化更平稳, 视觉生成质量更好. 词表在训练中途变化, 输出层和 embedding 怎么随之扩充, 切换发生在哪个阶段, 报告同样没写. 读者能确认的只是方向: 先粗后细, 和 NFSP 在一张图内部先低分辨率后高分辨率的思路一致.

这套视觉生成方案有清楚的来路. 逐尺度预测来自 VAR 的 next-scale prediction: 一张图不按光栅顺序逐 token 生成, 而是先生成最粗的 1×1 或 2×2 token 图, 再逐级放大, 每一级在上一级的基础上预测残差, 同一级内部并行. bitwise tokenizer 引的是 Han et al. (2025), 也就是 Infinity: 它把每个视觉 token 表示成 d 个比特, 词表大小是 $2^d$, 分类头只预测 d 个比特而不是一个 $2^d$ 维的下标, 词表可以做到 $2^{32}$ 甚至 $2^{64}$ 而参数不爆炸. 5.0 的 「按 bit 数渐进切换 tokenizer」 正是利用了这一点: bit 数加一, 词表翻倍, 输出层只多一个比特位. 训练时随机翻转历史 token 的比特, 也和 Infinity 的 bitwise self-correction 同源, 后者在每一级以 0 到 30% 的概率随机翻转并重新量化残差, 让模型学会纠正前几级的错误. 5.0 没有写翻转比例, 也没有写是否重新量化.

5.0 在这条线上加了两样东西. 一是时间维: 静图看成单帧视频, 视频在逐尺度之外再逐帧自回归, 这就是 NFSP 里 「Frame」 的来历, 配套的是窗口化时间注意力和随机遮掉历史帧. 二是把整条视觉生成搬进一个同时做文本, 音频的 MoE 骨干里, 而 VAR 和 Infinity 都是专门的图像生成模型. 代价体现在 token 预算上: 报告自己说, 分辨率一高, 序列变长, 有效 batch 变小, 优化不稳, 所以高分辨率交给单独训练的扩散 refiner. 统一骨干负责语义和布局, 像素细节仍由另一种目标函数完成.

### 1.3. 模态无关路由: 路由器不看模态, 专家照样分模态

§2.1 把路由写成以统一的 token 表示为条件, 不看模态标识, 并与 「之前模型」 的模态隔离路由对比. 这里引的是 ERNIE Team 2025, 也就是 ERNIE 4.5. 5.0 放弃了给每个模态预留专家的做法, 理由有两条: 一是跨模态参数共享可以带来知识迁移, 二是模态超过两个时人工分配专家本身就难做. 负载均衡用 **无辅助损失的 bias 方案**, bias 更新速度在 8K 阶段是 $1 \times 10^{-4}$, 中训降到 $1 \times 10^{-5}$.

这个方案出自 Wang et al. (2024c), DeepSeek-V3 把它用到了大规模训练里: 每个专家带一个偏置, 只加在路由打分上决定 top-k, 不参与门控权重; 每步结束时, 过载专家的偏置减 γ, 欠载的加 γ, γ 就是 「bias 更新速度」. DeepSeek-V3 的 γ 是 0.001, 最后 500B token 设为 0. 5.0 的起点 1e-4 比它小一个数量级, 中训再降到 1e-5, 作者给的理由是压住迭代级的振荡. 在模态无关路由下, 同一个 batch 里图像, 视频, 音频 token 的比例会随样本变化, 各专家负载的波动比纯文本大, 偏置调得太快会跟着噪声来回摆, 这可以解释为什么 5.0 选了更小的 γ (推测). 报告没有给不同 γ 的对照.

§6.4.1 的三张图说明 **「不看模态」 不等于 「不分模态」**. 图 8 里图像, 视频, 音频的专家激活比文本集中, 视觉生成和音频任务又比文本和视觉理解更集中. 图 9 取每个模态激活频次前 25% 的专家算交并比: 文本与音频重叠最高, 与图像视频的重叠随层加深而增大; 图像理解和视频理解重叠高, 图像生成和视频生成重叠高, 视觉理解和视觉生成之间却重叠低. 最后这条最值得注意. 同一个模态的两种任务在路由上几乎分成两拨专家, 原因很可能在输入端: 理解走量化前的 CNN 加 ViT 特征, 生成走量化后的 bit token, 两者的表示分布本来就不同. 路由器不需要模态标识, 也能从表示本身分辨出来.

图 10 用归一化熵 NE 看负载均衡, 定义是 $NE = -\sum_{i=1}^{N}p_i\log p_i/\log N$, $N$ 是专家数, $p_i$ 是分到第 $i$ 个专家的 token 比例; 均匀分到全部专家时为 1, 全部落到一个专家时为 0. 这个量掉得很慢: $N = 64$ 时 token 均匀落在其中 32 个专家上, $NE = \log 32/\log 64 = 5/6 \approx 0.833$ (举例), 一半专家闲置, 读数仍然不低. 文本在几乎所有层都高, 第一层也不低, 作者据此说这和 「早期 MoE 层需要稠密设计」 的常见假设 (Liu et al., 2024) 相矛盾. 这个推论要打折扣. NE 只描述 token 在专家之间分得是否均匀, 不衡量这层用 MoE 比用稠密层好还是差. 报告没有做稠密首层对 MoE 首层的对照, 也没说 NE 在哪批数据上统计. 视觉生成和音频任务的 NE 沿深度起伏, 作者读作专门化与再整合交替出现, 这是对曲线的描述, 并没有被单独检验.

### 1.4. 视觉与音频接口: 理解和生成走两条路

视觉理解这一侧, 报告发现直接用量化后的 token 做理解会丢细节, 因为量化前的特征被压到与 bit 宽对齐的低维. 于是理解改用量化前的双路特征: CNN 出感知特征, ViT 出语义特征. 每个理解 token 对应一组 $K$ 个局部 patch, 两路特征是 $F_{cnn}\in\mathbb R^{N\times K\times D_{cnn}}$ 和 $F_{vit}\in\mathbb R^{N\times K\times D_{vit}}$, $N$ 是理解 token 数. CNN 特征先投影到 $D_{vit}$, 再沿 patch 维和 ViT 特征拼成 $F_{mrg}\in\mathbb R^{N\times 2K\times D_{vit}}$, 在每组 $2K$ 个向量内做多头自注意力, 沿 patch 维平均池化成 $F_{out}\in\mathbb R^{N\times D_{vit}}$, 再投影到骨干的 embedding 维. 图像 K = 4, 取空间相邻的 patch, 一组注意力看 8 个向量; 视频 K = 16, 跨 4 帧, 一组看 32 个. 注意力只在组内做, 代价随 $N$ 线性增长, 进骨干的 token 数是每路 patch 数的 $1/K$. 作者说用 MLP 粗暴融合会互相干扰, 注意力融合在文档和图表理解上收益最大, 但没有给这组消融的表.

生成这一侧是 NFSP 加 **Uni-RoPE**. Uni-RoPE 给每个 token 三元位置 (t, h, w), 文本和音频三维取同一个值, 视觉的 t 是帧号, (h, w) 是帧内位置, 多尺度之间按几何中心对齐. 为对付长序列上的误差累积, 训练时随机翻转历史 token 的 bit, 让模型学会纠错; 视频再加窗口化时间注意力和随机历史帧掩码. 高分辨率交给一个单独训练的级联扩散 refiner: 骨干出低分辨率, refiner 补细节. 这一步很关键, 它说明 **「统一自回归生成」 只覆盖到低分辨率这一段**. 表 5 的 GenEval 90.1 和表 6 的 VBench Semantic 83.40 是否经过 refiner, 报告没说, 所以这些分数应当看作 「自回归骨干加扩散后端」 的系统结果.

音频这一侧, 第一层 RVQ 码从 Whisper 编码器蒸馏语义, Whisper 表示经平均池化对齐到 12.5 Hz. 理解时各层码的 embedding 相加, 占一个序列位置; 生成时顶部若干层的音频头按层依次出码, 并把码的 embedding 加回隐状态, 训练时用 teacher forcing. 这样序列长度只按 12.5 Hz 增长, 不乘 RVQ 层数. 语音合成时再插入说话人 embedding 控制音色. RVQ 层数, 码本大小, 音频头插在哪几层都没有给, 想估算一秒音频在骨干里要花多少计算, 缺少必要的数.

12.5 Hz 加首层语义蒸馏, 这套配置和 Kyutai 为 Moshi 做的 Mimi codec 很接近: Mimi 也是 12.5 Hz, 首个码本从自监督语音模型 WavLM 蒸馏语义, 其余码本编码残差声学细节, 12.5 Hz 的用意是让音频 token 率接近文本 token 率, 减少骨干的自回归步数. Moshi 论文还报告过一个取舍: 把语义蒸馏进单一 RVQ 的第一层, 音素区分度上去了, 重建音质却下降, 因为后面各层只能在第一层的残差上工作; 他们的解法是把语义码本拆成并行的独立 VQ. 5.0 描述的是 「第一个 token 显式负责语义」, 看起来是单一 RVQ 的首层蒸馏, 教师换成了 Whisper 编码器, 报告没有讨论这个音质取舍. 逐层出码的位置也不同: Moshi 用一个单独的小 Depth Transformer 在每个时间步内预测各层码, 5.0 把音频头直接插进骨干顶部若干层, 各层码由骨干自身的深度承担. 这让音频生成完全留在统一骨干里, 但也意味着 RVQ 层数受骨干顶部层数约束, 报告没有给两者的对应关系. 语音模型的通用背景见 [音频与语音模型](../../../../llm-guide/8-多模态/8.3-音频与语音模型/8.3-音频与语音模型.md).

## 2. 预训练与弹性训练

### 2.1. 预训练配方: 能对齐的数和缺的数

§3.2 给出的数值比架构部分多. 8K 阶段用 WSD 调度, 2,000 步线性预热到峰值 $1 \times 10^{-4}$, 之后保持不变; 全局 batch 从 14M token 逐步增加到 56M token; RoPE base 从一开始就设为 1,000,000, 目的是后面扩上下文时不必做插值. 中训阶段先 32K 再 128K, batch 不变, 改用余弦调度把学习率从 $1 \times 10^{-4}$ 退火到 $1 \times 10^{-5}$. 无辅助损失负载均衡的 bias 更新速度同步下调, 作者说这样能压住迭代级振荡.

缺的数同样清楚: 每个阶段多少步, 多少 token, 各模态数据的配比, 文本 tokenizer 的词表大小, 视觉 tokenizer 切换的时点. 数据部分只说文本有 「数万亿 token」, 用 UTF-16BE 编码, 用 BPE dropout, 对中文过滤掉可被分词工具拆开的长无空格短语. 拿 ERNIE 5.0 的配方去对照别家的训练曲线, 能对齐的只有学习率形状和 batch 渐增, 总规模对不上.

学习率形状这一项, 对齐得出奇地整齐. DeepSeek-V3 的预训练是 2K 步线性 warmup 到峰值, 恒定一段, 再余弦衰减到峰值的 1/10; batch 在前 469B token 从 3072 条增到 15360 条, 按 4K 序列长度约合 12.6M 到 63M token; MTP 损失权重前 10T token 为 0.3, 之后为 0.1. 5.0 是 2,000 步 warmup, 恒定, 余弦退火到峰值的 1/10, batch 从 14M 增到 56M token, MTP 权重 0.3 降到 0.1. 除了峰值学习率 (5.0 是 1e-4, DeepSeek-V3 是 2.2e-4) 和阶段切分点, 几乎是同一张日程表. 不同之处在上下文: DeepSeek-V3 预训练用 4K, 之后用 YaRN 扩展; 5.0 从 8K 阶段起就把 RoPE base 设为 1,000,000, 扩到 128K 时不做插值. 同一目录的 4.5 则是训练中把基频从 10k 分两步提到 500k. 三种做法都能到 128K, 报告没有给 5.0 这种一步到位做法的长文本对照. 预训练策略的背景见 [预训练策略](../../../../llm-guide/3-预训练/3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md), 频率扩展的做法见 [长度外推](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md).

数据节还有几句和训练方式直接相关. 所有数据按输入和输出模态组织在一个标准化平台上, 这是 「理解和生成都要」 的直接结果: 同一张图文对, 既可以当图生文样本, 也可以当文生图样本, 按输出模态归类才能控制两类任务的比例. 过滤包括启发式和模型打分, 去不安全内容, 大规模去重, 以及把评测集挡在训练数据之外的去污染, 但去污染用的是 n-gram 匹配还是别的方法, 覆盖了哪些基准, 没有写. 文本 tokenizer 重新训练, UTF-16BE 编码给了一个稳定的字节级回退, 对非拉丁字符更紧凑; 对中文把能被分词工具拆开的长无空格短语过滤掉, 目的是减少词表稀疏. 这和 3.0 用百度分词工具服务实体遮盖是两回事, 分词在 5.0 里只影响 BPE 词表的构成. 分词器背景见 [分词器与Tokenizer](../../../../llm-guide/3-预训练/3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md).

配方里有一个不起眼但对后文很重要的点: **全程不丢 token**. 不丢 token 意味着路由不均时某些专家所在的卡会突然收到大量 token, 峰值显存不可预测, 训练早期尤其容易 OOM. §5.1 的四项显存技术, 包括 FP8 激活, 按需卸载, 子 batch 拆分和碎片整理, 都是为这件事服务的. 这说明作者在 「路由不均时丢 token 换稳定」 和 「保住每个 token 的梯度」 之间选了后者, 并用系统手段承担代价.

### 2.2. 弹性训练: 同一次运行里的三个旋钮

**弹性训练**是这份报告和一般 MoE 报告区别最大的地方. 它不在预训练结束后剪枝或蒸馏, 而是在预训练期间就让一部分样本走子网络. 三个旋钮是: 深度, 随机减少激活的 transformer 层; 宽度, 把每个 MoE 层可选的专家限制在随机子集; 稀疏度, 把 top-k 降到预定义范围里更小的值. 引言说子模型和完整模型在同一次反向传播里优化, 图 4 把三者画在同一个 MoE 上, 所以三个旋钮确实属于同一次预训练. 概率按 §3.3: 深度完整 75%, 降深度 25%; 宽度全专家 80%, 子集 20%; 稀疏度默认 k 占 80%, 更小 k 占 20%.

同一个概率在报告里出现了两个版本. §6.4.2 做小模型深度消融时写 「Consistent with the configuration of ERNIE 5.0」, 用的却是 80% 对 20%, 与 §3.3 的 75% 对 25% 冲突. 三个旋钮对同一样本是联合抽样还是独立抽样, 宽度子集怎么抽, 部署时保留哪些专家, 都没有说明. 若按 §3.3 的概率独立抽, 一个样本三项都走满配的概率是 $0.75 \times 0.8 \times 0.8 = 48\%$, 也就是过半样本至少被砍掉一个维度. 这些细节决定了 「从同一个 checkpoint 抽子模型」 能否复现. 以宽度为例, 训练时专家子集是随机的, 部署时却必须固定一个子集, 而图 8 显示专家激活频次高度不均, 随机留和按频次留结果可能差很多.

弹性训练的思路有来源. 报告把它归到 Once-For-All 一脉, 引了三篇: MatFormer (Devvrit et al., 2023) 做嵌套的 FFN 宽度, Flextron (Cai et al., 2024) 做可伸缩的多合一大模型, Elastic MoE (Gu et al., 2025) 研究 MoE 推理时的 top-k 伸缩, 最后一篇的作者与本报告有重叠. ERNIE 5.0 的变化在于把三类弹性同时放进万亿级多模态模型的预训练, 并且不做表示维度 (hidden size) 的弹性, 报告说那与本设计正交, 留作以后. 这个选择的实际含义是: 所有子模型共享同一套 embedding 和注意力宽度, 只在层数, 专家数和 top-k 上变化, 所以子模型天然继承完整模型的 tokenizer 和位置编码, 不需要额外对齐.

小模型消融给出了三个旋钮各自的代价. 模型有 64 个专家, 454M 激活参数, 3.2B 总参数, 训练 250B token, 默认 top-k = 8. 三张表的训练设置分别写作 Layers ∈ [1, 16], Experts ∈ {64, 32}, Top-k ∈ [1, 8]: 降深度时层数在 1 到 16 之间取, 是截掉顶层还是随机跳层没写; 宽度只在 64 和 32 两档之间切, 32 个专家的子集怎么选没写; top-k 在 1 到 8 之间取, 取值分布没写. 表 9: 基线 16 层验证损失 1.945, 弹性深度训练后 16 层 1.941, 12 层 2.137, 满配略好. 表 10: 基线 1.957, 弹性宽度 64 专家 1.964, 32 专家 2.218. 表 11: 基线 1.945, 弹性稀疏 k = 8 为 1.969, k = 4 为 1.971, k = 2 为 2.003, k = 1 为 2.175.

几个现象值得记下. 深度弹性对满配像是正则化, 稀疏弹性对满配却有约 0.024 的代价. 稀疏弹性下 k 从 8 降到 4 几乎不掉, 降到 1 才明显变差. 表 10 的基线和另外两张不同, 若按 1.945 算, 宽度弹性的满配代价从约 0.007 变成约 0.019. 三张表都只报验证损失, 没有下游任务分数, 而且一次只开一个旋钮, 三者同开的交互效应只能看表 12.

### 2.3. 表 12: 子模型结论能外推到哪里

表 12 是报告里唯一把弹性训练放到大模型上的证据. 主体是 ERNIE 5.0-Exp-Base 和它的后训练版 ERNIE 5.0-Exp, 不是发布的 ERNIE 5.0. 两个变体: ES<sub>25.0</sub>% 只在推理时把 top-k 降到 25%, 不再训练, 平均分 74.43; EA<sub>35.8</sub>% 三个旋钮同开, 保留 53.7% 激活参数和 35.8% 总参数, 再用相同数据和策略做中训与后训, 平均分 75.17; 完整 Exp 是 75.55. 平均分是七项的算术平均, 用表中数字可以复算出来.

七项是 ZebraLogic, LiveCodeBench v6, TAU2, MMMU, MathVista, VisualPuzzle, SimpleVQA. EA 在 ZebraLogic (95.20 对 95.00), MMMU (75.11 对 74.11), MathVista (84.50 对 83.70), VisualPuzzle (60.39 对 59.93) 上反而高于完整模型, 在 LiveCodeBench v6 (70.93 对 73.35) 和 TAU2 (77.23 对 79.35) 上掉得最多. 平均分只差 0.38, 是涨跌相抵的结果, 代码和 agent 两项各掉了 2 分以上. ES 同样在代码上掉得最多, LiveCodeBench v6 只有 70.70. 对部署决策来说, 这比平均分更有用: **砍参数的代价集中在长程生成和多轮工具调用这类任务上**.

外推有两道边界. 第一, Exp 不等于发布版: ZebraLogic 在表 2 是 96.50, 表 12 的完整 Exp 是 95.00; LiveCodeBench v6 在表 2 是 76.21, 表 12 是 73.35. 所以不能说发布版的 35.8% 子模型能拿到表 2 那样的分数. 第二, EA 做过额外的中训和后训, 它和完整模型的差距里已经含有这段再训练的补偿, 不等于 「从超网络里直接抽出来就能用」. 真正零训练直接抽出来的只有 ES, 而 ES 只动 top-k, 不省显存. 引言里 「超过 15% 解码提速」 也只对应 ES, 而且没有给硬件, batch 和序列长度.

53.7% 和 35.8% 这两个比例本身也有信息量. 砍深度时总参和激活一起降, 砍宽度主要降总参, 砍 top-k 只降激活. 注意力和 embedding 这类每个 token 都要用的参数在激活里占比大, 在总参里占比小. 激活保留得比总参多, 说明 EA 的压缩主要落在专家总数上, 这正对应引言所说的显存受限部署. 至于三个旋钮各取了多少, 报告没有给, 无法反推.

## 3. 后训练与基础设施

### 3.1. 后训练: 四个技术各自解决什么, 式子和文字哪里对不上

后训练沿用 ERNIE 4.5 的流程: SFT 之后接统一多模态 RL (UM-RL). 报告认为超稀疏 MoE 让 RL 更难, 原因有三: RL 本身贵, 超稀疏 MoE 放大训推差异, 多场景多模态比单一的 RLVR 复杂. 对应的四个技术是: **U-RB** 解决 rollout 长尾, **MISC** 解决训推失配引起的熵塌缩, **WPSM** 解决在简单题上过拟合, **AHRL** 解决难题拿不到奖励.

U-RB 的出发点是 rollout 占 RL 训练时间 90% 以上. APRIL 的做法是超额发请求, 够数就停, 没完成的留到下轮, 结果是短回答 (通常是简单题) 先进训练, 难度分布随时间漂移. U-RB 加了一条顺序约束: 只有初始化时分给第 t 轮的数据组 $\mathcal{D}_t$ 才能进第 t 轮训练, 推理要等到这组里最长的 rollout 结束. 它并没有省掉等待, 省的是等待时的 GPU 空转: 推理池容量是训练 batch 的 N 倍, 后续批次先开跑. 这样难度分布不漂移, 代价是部分轨迹由旧参数生成, 报告没有讨论这部分离策略的程度.

MISC 从 IcePop 出发. 记 $\rho_{i,j} = \pi_{train}(y_{i,j}\mid x, y_{i,<j};\theta_{old}) / \pi_{infer}(y_{i,j}\mid x, y_{i,<j};\theta_{old})$, 是同一组旧参数下训练引擎和推理引擎给同一个 token 的概率比; $r_{i,j} = \pi_{train}(y_{i,j}\mid\cdot;\theta)/\pi_{train}(y_{i,j}\mid\cdot;\theta_{old})$ 是常规的重要性比值. 式 (1) 是 IcePop 在 GRPO 上的形式:

$$\mathcal J^{GRPO}_{IcePop} = \mathbb E\Big[\frac1G\sum_{i=1}^{G}\frac1{|y_i|}\sum_{j=1}^{|y_i|}\mathfrak M(\rho_{i,j};\alpha,\beta)\cdot\min\big(r_{i,j}\hat A_{i,j},\ \mathrm{clip}(r_{i,j},1-\epsilon,1+\epsilon)\hat A_{i,j}\big)\Big], \qquad \mathfrak M(k) = \begin{cases}k & k\in[\alpha,\beta]\\ 0 & \text{otherwise}\end{cases}$$

$\mathfrak M$ 在区间内返回 $k$ 本身, 所以它不只是掩码: 落在 $[\alpha,\beta]$ 里的 token 乘上 $\rho$ 做一次训推校正, 落在外面的 token 权重为 0. 式 (2) 把它搬到序列级的 GSPO 上, 掩码和重要性比值都换成开 $1/|y_i|$ 次方的序列级量:

$$\mathfrak M\Big(\Big(\frac{\pi_{train}(y_i\mid x;\theta_{old})}{\pi_{infer}(y_i\mid x;\theta_{old})}\Big)^{1/|y_i|};\alpha,\beta\Big)\cdot\min\big(s_i\hat A_i,\ \mathrm{clip}(s_i,1-\epsilon,1+\epsilon)\hat A_i\big), \qquad s_i = \exp\Big(\frac1{|y_i|}\sum_{j=1}^{|y_i|}\log r_{i,j}\Big).$$

掩码的自变量等于 $\exp(\frac1{|y_i|}\sum_j\log\rho_{i,j})$, 即各 token 训推比的几何平均. 一条回答要么整条保留, 要么整条权重为 0, 判据是平均每 token 的 $\log\rho$ 是否越出 $[\log\alpha, \log\beta]$. 图 6 的浅蓝线显示这样会快速熵塌缩, 作者的解释是序列级截断在训推失配下剪掉了大量低熵回答. 式 (3) 把掩码换成逐 token 的 $\mathfrak M_{j\in[1,|y_i|]}(\rho_{i,j};\alpha,\beta)$, 重要性比值仍用序列级的 $s_i$, 这就是 「多粒度」 的含义. 问题在于下标 j 之后没有写合成方式, 文字又说 「按模态敏感度调节信任域」, 式子里却没有模态变量.

把 MISC 放回它引用的两条线里, 能看出它在调和什么. IcePop 出自蚂蚁的 Ling 团队, 针对的是 rollout 引擎和训练引擎算出的 token 概率不一致: 比值落在 [α, β] 之外的 token 直接不参与梯度, 在 MoE 上尤其有用, 因为两边路由稍有不同, 某些 token 的概率就会差出几倍. GSPO 出自 Qwen 团队, 主张重要性比值应在序列级定义 (对序列似然开 $1/|y|$ 次方), 并称序列级比值对训推精度差更宽容, 这是它能稳定 MoE RL 的理由之一. 5.0 的图 6 给了一个反例: 把 IcePop 的掩码直接搬到 GSPO 的序列级比值上, 熵迅速塌缩. 几何平均把单个 token 的失配摊薄到 $1/|y|$, 长回答不会因为一两个 token 被剪; 被整条剪掉的是平均失配越界的回答, 其中训推对得上的 token 也一起失去梯度. 作者说被剪掉的多是低熵回答, 没有解释为什么是低熵. MISC 的折中是掩码按 token 算, 重要性比值按序列算, 而式 (3) 的两种合成读法落在同一个权重上差别很大. 若在 j 上取平均 (推测), 整条回答的权重是 $\frac1{|y_i|}\sum_j\mathfrak M(\rho_{i,j})$, 5% token 越界, 其余 $\rho \approx 1$ 的回答仍保留约 95% 的权重; 由于 $\min(\cdot)$ 只通过 $s_i$ 依赖 $\theta$, $\nabla s_i = s_i\cdot\frac1{|y_i|}\sum_j\nabla\log\pi_{train}(y_{i,j})$, **越界 token 仍经 $s_i$ 拿到梯度**, 掩码只是按比例压低整条回答. 若取乘积, 任一 token 越界整条归零, 比式 (2) 更严, 和图 6 要解决的问题方向相反. 平均的读法更符合作者的动机 (推测). 这组观察对 「序列级比值天然抗失配」 的说法是一个有用的限定, 但只有一张曲线, 没有多种子重复. GSPO 的背景见 [GSPO](../../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/04-GSPO/04-GSPO.md).

系统侧的 Rollout Router Replay 引的是 Ma et al. (2025b). 那篇工作把 MoE 上的训推不一致主要归因于路由不一致: rollout 时某个 token 选了专家 A, 训练时重算却选了专家 B, 概率随之跳变; 解法是在 rollout 时记录每个 token 的路由结果, 训练时按记录回放. 5.0 把它和统一的 FP8 算子一起用, 从源头压低失配, 再由 MISC 处理剩下的部分. 两层手段各管多少, 报告没有拆开. 训推不一致的一般讨论见 [训练稳定性与训推不一致](../../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.7-训练稳定性与训推不一致/6.1.7-训练稳定性与训推不一致.md).

WPSM 的式 (4) 是

$$\mathcal J = \mathbb E\Big[\frac1G\sum_{i=1}^{G}\big[1-\mathbb M^i\big]\min\big(s_i\hat A_i,\ \mathrm{clip}(s_i,1-\epsilon,1+\epsilon)\hat A_i\big)\Big], \qquad \mathbb M^i = \begin{cases}\alpha & \mathcal H_{y^x_i}(\pi_\theta) < \eta\ \text{and}\ acc^x_t > \tau\\ 0 & \text{otherwise}\end{cases}$$

$acc^x_t$ 是这道题在第 t 轮 rollout 组里的平均正确率, 熵按单条回答算, 满足条件的回答乘 $1-\alpha$. 这个 α 与 IcePop 的下界同名不同义, α 越大学得越少, 和正文 「控制补充学习的程度」 的说法方向相反. 条件里只有组正确率和单条熵, 没要求这条回答本身答对, 名字里的 「positive」 在式子里没有体现; 式 (4) 的目标也没带 MISC 的掩码, 两者实际怎样相乘没写. AHRL 的式 (5) 是 $p_{hint}(x^t) = p_{initial}\exp(-\gamma\,t\,pass^x_{initial})$, 查询前面拼上参考思考过程的前 $p_{hint}$ 部分 token, $pass^x_{initial}$ 是 SFT 模型在这道题上的 pass@k. 提示的半衰期是 $t_{1/2} = \ln 2/(\gamma\,pass^x_{initial})$, pass@k 为 0.5 的题比 0.1 的题快 5 倍撤掉提示; pass@k 为 0 的题半衰期无穷大, 永远不衰减, 这和 「逐步过渡到完全自主探索」 对不上. 正文把 $p_{hint}$ 既叫 「揭示比例」 又叫 「概率」, 是每次都揭示这个比例, 还是以这个概率决定揭不揭示, 两种读法都说得通; 参考思考过程从哪来也没写. 四个技术涉及的超参数, 包括 α, β, ε, τ, η, γ, $p_{initial}$ 和 pass@k 的 k, 一个数值都没给. 图 6 是唯一的训练曲线, 只对比了式 (2) 和式 (3).

四个技术里只有 MISC 有一张曲线图, U-RB 没给吞吐提升, WPSM 和 AHRL 没给消融. 所以能从报告里确认的是这些技术存在, 以及它们各自针对的失败模式; 每项贡献了多少分, 从表 2 和表 3 拆不出来. 如果要检验 「超稀疏 MoE 需要特殊的 RL 处理」 这个判断, 最需要的是一组去掉 MISC 或去掉 Rollout Router Replay 的对照, 报告里没有.

### 3.2. 基础设施: 能看出规模的只有并行配置

§5.1 的最终并行配置是 4 路张量并行, 带虚拟阶段的 12 路流水线并行, 64 路专家并行, ZeRO-1 数据并行, 外加长上下文用的上下文并行, 节点间通信用 DeepEP. 这组数字是报告里少数能间接反映规模的信息: 64 路专家并行通常意味着每层专家数是 64 的整数倍. 数据并行路数没给, 总卡数算不出来. 显存方面的四项技术, 即 FP8 混合精度 (沿用 4.5), OOM 时自适应卸载激活, 子 batch 拆分大块分配, 基于 CUDA VMM 的自动碎片整理, 都围绕 「不丢 token 导致峰值显存不可预测」 这一个问题.

多模态特有的两项是 **tokenizer 解耦** 和 **FlashMask**. tokenizer 作为独立服务部署在专用节点上, 骨干通过远程调用取编码结果, 视觉和音频 tokenizer 的负载波动就不会拖住骨干. FlashMask 处理同一 batch 内不同样本的不同掩码: 视觉要局部双向, 文本和音频要因果. 报告给的收益是算子级比 FlexAttention 最多快 200%, 端到端训练快 20% 以上, 与上下文并行结合后比 Megatron-LM 方案快 80%. 三个数的基线和条件各不相同, 不能相乘或相加.

RL 基础设施的要点是训练与 rollout 用同一套 FP8 算子, 再加 Rollout Router Replay, 让 MoE 在两边走同一条路由, 从源头压低训推失配. 这和 MISC 在算法侧做的事是同一个问题的两面: 系统侧尽量让两边算出同样的概率, 算法侧对剩下的失配做掩码. 弹性 CPU 池化把集群里闲置的 CPU 拿来跑环境交互和结果验证, 目的在缩短墙钟时间, 与模型结构无关.

## 4. 评测与结论

### 4.1. 评测表怎么读

语言部分有两张表. 表 1 是基座对基座, 对手是 DS V3.2-Exp-Base 和 Kimi K2-Base, shot 数写在基准名后面. ERNIE 5.0-Base 在知识类领先最多, 例如 PreciseWikiQA 74.48 对 52.60 和 61.66, ChineseSimpleQA 90.09. 源文件丢失了加粗, 需要自己比: C-Eval, CMMLU, MBPP+ 三项都是 Kimi K2-Base 更高. 表 2 是后训练模型, 对手换成 DS V3.2-Thinking, Gemini 2.5-Pro, GPT-5 (High), Gemini 3-Pro. ERNIE 5.0 在 SimpleQA 74.01, ChineseSimpleQA 86.03, MultiChallenge 65.98, Multi-IF 85.56, ACEBench-en 87.70, ACEBench-zh 89.60 上五家最高; 在 MMLU-Pro 83.80, HMMT 2025 79.58, BBEH 66.63 上五家最低; HLE 25.81 仅次于 Gemini 3-Pro 的 37.50, 但差距很大. 作者自己也承认最难的推理基准与 Gemini 3-Pro 有差距.

表 1 的协议写在基准名后面, 读分数前要先对齐. 知识类 (PreciseWikiQA, PopQA, HotPotQA, ChineseSimpleQA) 都是 10-shot; 通用类大多 5-shot, 其中 BBH 标明不用 CoT, 直接作答; MATH 是 8-shot CoT, GPQA-Diamond 是 5-shot; LiveCodeBench v6 (2024-08 至 2025-05) 和 CRUXEval 是 1-shot, HumanEval+ 和 MBPP+ 是 0-shot; 代码题通过 SandboxFusion 执行判分. 基座间差距最大的是知识和 STEM: PreciseWikiQA 74.48 对 61.66, PopQA 65.24 对 51.74, MATH (CoT) 73.89 对 65.90, LiveCodeBench v6 31.94 对 26.30. 报告把 MMLU-Pro 等难题上的提升归因于共享骨干和模态无关路由, 把 STEM 提升归因于统一架构的长程依赖建模和弹性预训练下的稳定优化, 这些归因都没有配 「隔离路由对无关路由」 或 「开弹性对不开弹性」 的同规模基座对照, 只能看作解释.

基座和后训练的对比里还有一个值得记的现象. 正文说知识类在后训练后 「进一步提升」, 但两张表共有的知识项只有 ChineseSimpleQA, 基座是 90.09 (10-shot), 后训练是 86.03, 数字反而低了约 4 分; 两者的提示方式不同, 不能直接相减, 可也撑不起 「进一步提升」 这句话. SimpleQA 只出现在后训练表, 74.01 高于 Gemini 3-Pro 的 69.33. 竞赛数学不占优, AIME 2025 89.06 在五家里排第四, HMMT 2025 79.58 最低. 作者的说法是 5.0 追求 「均衡能力发展」, 没有针对竞赛题做激进优化. 从后训练描述看, UM-RL 把推理, agent, 指令遵循合进同一条多阶段流水线, 四项 RL 技术也都以稳定性为目标, 这和结果一致; 但表里看不出 5.0 是否开了长推理, 以及各对手是否处在最强推理档, 所以 「均衡」 与 「推理预算不同」 两种解释在本页分不开.

视觉与音频的表要注意比较对象. 表 3 的对手多是通用大模型, ERNIE 5.0 在 VLMAreBlind (91.38) 和 DocVQA (95.45) 上最高, 在 MMMU-Pro (68.63) 上落后 Gemini 3-Pro 约 12 分, ChartXiv-RQ (67.10) 落后 GPT-5 和 Gemini 3-Pro 约 14 分. 表 4 只报自己的基座, 理由是公开的视觉基座太少, 没有对照. 表 5 的 GenEval, ERNIE 5.0 是 90.1, 低于 Qwen-Image 的 91.0, 高于 Nano Banana Pro 的 89.0. 表 6 的 VBench, ERNIE 5.0 的 Semantic 83.40 最高, Overall 84.20 则低于 Veo3 的 85.06.

表 7 的 ASR 用 WER, 越低越好. ERNIE 5.0 在 AISHELL-1 (0.31) 和 Fleurs-zh (0.83) 上最好, WenetSpeech 明显落后 Qwen3-Omni-Instruct. 后训练并非全面提升, CommonEval, SD-QA, MMAU, VocalSound 都比 Base 低, 正文只点名升了的项. 表 8 的 SEED-TTS, ERNIE 5.0 为 1.35 和 1.54, 专用 TTS 里 CosyVoice 3 是 0.71 和 1.45. 所有这些都在内部 ERNIE-Eval 上测, 基线数字是自测还是引用没有标注, 这是把这些表当证据用之前需要记住的前提.

### 4.2. 与 ERNIE 4.5 的分界

同一目录下还有 ERNIE 4.5 的报告, 两份要分开读. 5.0 报告自己点明了三处继承: 后训练流程与 4.5 相同, FP8 混合精度训练沿用 4.5, 训练基础设施建在 4.5 之上. 也点明了一处断裂: 4.5 用模态隔离的路由, 5.0 改成所有模态共用一个专家池. 另外, 图像, 视频, 语音的生成能力是 5.0 新加的, 4.5 的多模态输出仍以文本为主, 这正是 5.0 引言批评的 「text-centric」 输出.

引用 5.0 的数字时不要带上 4.5 的参数规模, 反过来也一样. 5.0 没有公开总参数和激活参数, 只能说 「万亿级, 激活率低于 3%」; 4.5 的具体规格要回到 4.5 的报告里查. 5.0 报告内部还有一层区分: 「ERNIE 5.0-Exp」 是内部实验模型, 与发布的 ERNIE 5.0 不是同一个检查点, 表 12 与表 2 的数字不能互相替代.

### 4.3. 仍然缺的信息和能站住的结论

架构层面缺总参数, 激活参数, 层数, 专家数, top-k, 词表大小, RVQ 层数和扩散 refiner 的规模. 训练层面缺各阶段的步数和 token 数, 模态配比, 视觉 tokenizer 的切换时点, 以及弹性三旋钮的联合抽样方式和那张 「pre-defined schedule」. RL 层面缺全部超参数. 评测层面缺基线来源的标注和测速条件. 这些缺口让报告更像一份设计说明, 离可复现的实验记录还有距离.

在这些限制下仍能站住的结论有三条. 其一, 小模型上弹性训练的代价很小, 深度弹性甚至让满配略好, 稀疏弹性把 k 减半几乎不掉 (表 9 到表 11). 其二, 在实验超网络上三旋钮同开并再训练后, 平均分只差 0.38, 但代码和 agent 两项各掉 2 分以上 (表 12). 其三, 路由不看模态时专家仍按任务分化, 视觉理解与视觉生成几乎用两拨专家 (图 8, 图 9). 需要保留的说法也有三条: 「第一个生产级万亿统一自回归模型」 取决于公开披露的范围和 「统一」 的定义, 高分辨率生成还依赖扩散 refiner; 「超过 15% 解码提速」 没有测速条件; 「第一层不必稠密」 只有路由均衡的证据, 没有性能对照.
