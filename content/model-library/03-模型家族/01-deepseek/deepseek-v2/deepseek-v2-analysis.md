# DeepSeek-V2: 用 MLA 压推理显存, 用 MoE 压训练算力

来源: [DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model](https://arxiv.org/abs/2405.04434) (arXiv: 2405.04434v5, 2024-06-19). 仓库: https://github.com/deepseek-ai/DeepSeek-V2

对照译稿: `deepseek-v2-bi.md`. 表内数字与公式编号回源文 `deepseek-v2.md`.

DeepSeek-V2 总参 236B, 每个 token 激活 21B, 上下文 128K, 在 8.1T token 上预训练, 再经 1.5M 条 SFT 和两阶段 GRPO 得到 Chat 版. 摘要里的三组数字最常被引用: 相对 DeepSeek 67B 训练成本省 42.5%, KV cache 减 93.3%, 最大生成吞吐 5.76 倍. 这三组数字分别来自不同的环节: 42.5% 主要来自 MoE 的稀疏计算, 93.3% 是 MLA 和部署期 KV 量化叠在一起的结果, 5.76 倍则是显存省下来以后 batch 能开大的连锁效应. 读这份报告, 要把架构, 数据, 训练日程, 对齐和评测放在一起看, 才能分清哪一部分收益来自哪一步.

## 1. 起点与注意力: MLA

### 1.1. 起点: 67B 卡在哪里

前一代 DeepSeek LLM 67B 是 Dense 模型, 95 层, 隐宽 8192, 64 个 query 头, 8 组 KV 的 GQA, 在 2T token 上训练. 它有两个瓶颈. 训练侧, 每个 token 都要走完全部 67B 参数, 算力随参数线性涨. 推理侧, 每个 token 在每层要缓存 $2\times 8\times 128=2048$ 个 KV 元素, 95 层合计 194,560 个(按 67B 配置推算), BF16 下约 380 KB; 128K 上下文单条请求就要约 47 GB, 一张 80 GB 的卡放不下几条长请求.

V2 同时处理这两个瓶颈. 注意力换成 Multi-head Latent Attention(MLA), 解决推理缓存; FFN 换成 DeepSeekMoE, 解决训练算力. 其余小设定(RMSNorm, SwiGLU 激活, 分词器)沿用 67B, 数据流水线也沿用 67B 的阶段划分. 这意味着 V2 相对 67B 的提升混合了架构, 数据量和数据配比三个因素, 报告没有做「只换架构, 数据不变」的对照, 这一点在看后面的 Base 分数时要记着.

### 1.2. MLA: 把 K, V 压进一个共享的低维向量

标准 MHA 每个 token 每层缓存 $2n_hd_h$ 个元素. GQA 和 MQA 让多个 query 头共用一组 K, V 来减缓存, 代价是表达能力. 附录 D.1 的对照说明了这个代价: 三个约 7B 的 Dense 模型同训 1.33T token, 只改注意力并调层数对齐参数, MHA 的 MMLU 45.2, GQA(8 组) 41.2, MQA 37.9; C-Eval 分别是 42.9, 37.7, 30.0. 在这个规模上, 省缓存的老办法要付出 4 到 13 个点.

**MLA** 换了一个思路: 不减头数, 而是把 K 和 V 先联合压成一个低维潜向量 $\mathbf{c}_t^{KV}=W^{DKV}\mathbf{h}_t$(式 9), 再用 $W^{UK}$, $W^{UV}$ 上投影回每个头的 K 和 V(式 10–11). 推理时只缓存 $\mathbf{c}_t^{KV}$, 每层 $d_c$ 个元素. V2 取 $d_c=512$, 而 MHA 在同样 128 头, 每头 128 维下要存 32,768 个. 更关键的是**矩阵吸收**: 注意力分数 $\mathbf{q}^T\mathbf{k}=\mathbf{h}^TW^{Q\,T}W^{UK}\mathbf{c}$, 中间两个矩阵可以预先乘成一个, 推理时 query 直接和缓存的潜向量做内积, 不用把每个历史 token 的 K 展开出来; $W^{UV}$ 同理吸进输出投影 $W^O$. 中文技术社区的实现笔记指出, 吸收后 128 个头共享同一份 $\mathbf{c}^{KV}$, 计算形态接近 MQA, 算术强度正比于头数, 这对显存带宽受限的解码阶段很有利.

矩阵吸收也有代价. 吸收之后, 每个头的 query 要先映射到 512 维的潜空间, 再和每个历史 token 的潜向量做内积, 单头单 token 的点积长度从 128 变成 512 加 64. 解码阶段每步只有一个新 token, 瓶颈是读缓存的显存带宽, 多算一点不要紧; 预填充阶段一次处理整段 prompt, 算力才是瓶颈, 这时把 K, V 显式展开反而更省. 所以公开的推理实现通常在预填充时展开, 解码时吸收. 报告附录 C 只说「推理时可以吸收」, 没有区分这两个阶段.

Query 也做了低秩压缩, $d_c'=1536$(式 12–13), 但目的只是省训练期的激活显存, 与 KV cache 无关. 低秩压缩会改变层输出的尺度, 所以报告在压缩潜向量之后加了 RMSNorm, 并在宽度瓶颈处(潜向量和路由专家的中间态)乘额外的缩放系数来稳住训练. 缩放系数取多少, 报告没有给. 机制推导见 [MLA: 低秩潜变量与矩阵吸收](../../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md), GQA 的折中思路见 [GQA: 在性能与缓存之间折中](../../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md).

### 1.3. 解耦 RoPE, 以及 93.3% 是怎么算出来的

RoPE 和矩阵吸收不兼容. 如果对上投影后的 $\mathbf{k}_t^C$ 施加 RoPE, 与当前位置相关的旋转矩阵就会夹在 $W^Q$ 和 $W^{UK}$ 中间, 矩阵乘法不满足交换律, 两者不能预先合并, 推理时又得为所有前缀 token 重算 K. 报告的办法是**把位置信息单独拿出来**: 另开每头 $d_h^R$ 维的 $\mathbf{q}_{t,i}^R$ 和一个所有头共享的 $\mathbf{k}_t^R$ 专门承载 RoPE(式 14–15), 内容部分 $\mathbf{q}^C$, $\mathbf{k}^C$ 不加位置编码, 继续走吸收路径; 两部分拼接后算注意力, 分母改成 $\sqrt{d_h+d_h^R}$(式 18). 共享的 $\mathbf{k}_t^R$ 直接从 $\mathbf{h}_t$ 投影, 不经过潜向量, 也要进缓存. 社区里常把 $\mathbf{k}^R$ 描述成「MQA 版的 RoPE」: 位置这一路只有一个头, 内容这一路有 128 个头.

V2 取 $d_h^R=64$, 每层缓存 $512+64=576$ 个元素, 等于 $4.5d_h$. Table 1 说这相当于「只有 2.25 组的 GQA」, 就是由 $2n_gd_h=4.5d_h$ 解出来的. 这个数可以和附录交叉验证: 60 层乘 576 是 34,560, 正好是表 9 里大号 MoE 带 MLA 那一行的 34.6K; Lite 的 27 层乘 576 是 15,552, 对上表 9 小号 MoE 带 MLA 的 15.6K. 相对同配置 MHA 的 32,768, 缩到约 1/57.

再算相对 67B 的缩减. 67B 每 token 194,560 个元素, V2 是 34,560 个, 只按元素数算, 缩减是 82.2%, 不是 93.3%. 报告在 §3.2.3 还写了部署时把 KV 平均量化到 **6 bit**; 如果拿 V2 的 6 bit 对比 67B 的 16 bit, $34{,}560\times 6\,/\,(194{,}560\times 16)\approx 6.7\%$, 缩减正好是 93.3%. 也就是说, 摘要里的 93.3% 很可能把 MLA 和 KV 量化合并计算了, 而 Table 1 的脚注又明确说缓存量「按元素数计, 不论存储精度」. 两处口径不一致, 报告没有说明. 对读者来说, MLA 本身带来的缩减应按 82.2% 理解, 剩下的来自量化.

换成实际显存更直观. V2 每 token 34,560 个元素, BF16 下约 67.5 KB, 128K 上下文单条请求约 8.4 GB; 67B 同长度约 47 GB. 同一台 8×H800 能并发的长请求数因此多出好几倍, 这就是 5.76 倍生成吞吐的主要来源. 吞吐测试用的 prompt 和生成长度分布取自线上 67B 服务的真实流量, 并且叠加了 FP8 权重和 6 bit KV 量化, 所以 5.76 倍衡量的是整套部署方案, 不是 MLA 单独的贡献. 生成吞吐超过 50K token/s, prompt 吞吐超过 100K token/s, 这两个数都是单节点 8 卡的结果.

### 1.4. 注意力消融能证明多少

附录 D.2 用两档 MoE 比较 MLA 和 MHA. 小档总参约 16B, 训 1.33T token: MHA 激活 2.5B, 缓存 110.6K; MLA 激活 2.4B, 缓存 15.6K, 约为前者的 14%; 四项硬基准里 MLA 赢三项(BBH 39.0 对 37.9, MMLU 50.0 对 48.7, CMMLU 53.4 对 52.3), C-Eval 输 0.7(50.9 对 51.6). 大档总参约 250B, 只训 420B token: MHA 激活 25.0B, 缓存 860.2K; MLA 激活 21.5B, 缓存 34.6K, 约为 4%; 四项全赢, BBH 50.7 对 46.6, MMLU 59.0 对 57.5, C-Eval 59.2 对 57.9, CMMLU 62.5 对 60.7.

这组结果支持「MLA 不比 MHA 差」, 但有三处需要注意. 其一, 大档只训了 420B token, 约为正式训练量的 5%, 早期训练阶段的优势能否保持到 8.1T, 报告没有数据. 其二, 从缓存量反推, 小档 MHA 每层 4,096 个元素, 即 16 头乘 128 维, 与 Lite 一致; 大档 MHA 每层约 14,336 个, 若每头 128 维则只有 56 个头, 而 MLA 那一档是 128 头. 报告说两者「除注意力外架构相同」, 但 MHA 的头数和维度并没有列出, 所以这里比的可能是「128 头的 MLA」对「头数更少的 MHA」, MLA 的一部分优势也许来自头数. 其三, 每档每个设置只训一次, 没有误差条, 1 个点以内的差距不能当作确定结论.

表 8 和表 9 合起来看, 报告想说明的是一条链: GQA, MQA 比 MHA 差, MLA 又不比 MHA 差, 所以 MLA 同时拿到了省缓存和保质量. 前半条链在 7B Dense 上测, 后半条在 MoE 上测, 两者不在同一个模型族里. 表 8 为了对齐参数量调整了层数, MQA 版本 7.1B, 另外两个 6.9B, MQA 省下的 KV 投影参数被换成了更多的层, 所以它和 MHA 的差距不是「同样深度下少了 KV 头」那么单纯. MLA 和 GQA 的直接对比, 报告没有给.

## 2. DeepSeekMoE

### 2.1. DeepSeekMoE: 细专家, 共享专家和设备受限路由

FFN 侧沿用 DeepSeekMoE 的两个做法(式 20–22). 一是把**专家切细**: 在总专家参数不变时, 专家越小, 数量越多, 激活组合就越多, 每个专家更容易学到专门的知识. 二是**隔离共享专家**: 每个 token 都经过的共享专家负责通用知识, 减少路由专家之间的重复. V2 除第一层外全部换成 MoE, 每层 2 个共享专家加 160 个路由专家, 专家中间宽 1536, 每 token 激活 6 个路由专家. 一层 MoE 的输出是

$$
\mathbf{h}_t'=\mathbf{u}_t+\sum_{i=1}^{N_s}\mathrm{FFN}_i^{(s)}(\mathbf{u}_t)+\sum_{i=1}^{N_r}g_{i,t}\,\mathrm{FFN}_i^{(r)}(\mathbf{u}_t),\qquad s_{i,t}=\mathrm{Softmax}_i(\mathbf{u}_t^\top\mathbf{e}_i),
$$

$g_{i,t}=s_{i,t}$ 当 $s_{i,t}$ 在 $N_r$ 个亲和度的 Top-$K_r$ 内, 否则为 0. 第一项是残差; 第二项 $N_s=2$ 个共享专家不经门控, 权重恒为 1, 每个 token 都走; 第三项 $N_r=160$ 个路由专家里只有 $K_r=6$ 个非零. $\mathbf{e}_i$ 是专家 $i$ 的中心向量, 亲和度就是 token 和它的内积. Softmax 是在全部 160 个专家上做的, 取 Top-6 之后不再归一化, 所以 6 个门控之和小于 1, 路由越分散, 路由专家这一路的输出就越小, 共享专家那一路的相对分量越大. 这套结构的机制讨论见 [DeepSeek-MoE](../../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md).

细粒度带来一个副作用: 激活专家多, 如果它们散在很多张卡上, 专家并行的 all-to-all 通信就会变贵. 每层 160 个路由专家均匀铺在 8 张卡上($D=8$), 每卡 20 个, 不加限制时一个 token 的 6 个专家最多可能落在 6 张卡上. **设备受限路由**(device-limited routing)先按每张卡上最高的亲和度挑出 $M$ 张卡, 再只在这些卡的专家里做 Top-6. V2 取 $M=3$, 报告说 $M\ge 3$ 时效果与不受限的 Top-K 大致持平. 这个「大致持平」没有附表, 本页也没有 $M=1$ 或 $M=2$ 的数字.

用配置可以反推 236B 和 21B 是怎么构成的. 一个 SwiGLU 专家有三个 5120×1536 的矩阵, 约 23.6M 参数; 每层 162 个专家约 3.8B, 59 个 MoE 层合计约 225B. 每 token 激活 2 个共享加 6 个路由, 共 8 个专家, 59 层约 11.1B. 注意力一层的投影矩阵加起来约 149M(其中输出投影 $W^O$ 就有 128×128×5120, 约 84M), 60 层约 9B. 再加约 1B 的输入输出词嵌入和第一层的 Dense FFN, 激活参数约 21B, 总参约 235B, 与报告的 21B 和 236B 对得上. 这笔推算说明, V2 激活的 21B 里注意力占了四成以上, 专家只占一半左右; MLA 省的是缓存, 不是参数.

这个限制还给了发送端一个硬上界: 每张卡最多向外发送 $MT$ 个隐状态, $T$ 是序列 token 数. 共享专家不需要跨卡, 所以 V2 把共享专家的计算和专家并行的 all-to-all 通信重叠起来, 让等通信的时间也在算东西. 这一步是训练效率的关键之一, 但重叠带来的具体提速比例, 报告没有给.

### 2.2. 三级均衡损失和 token-dropping

路由不均衡有两个后果: 一部分专家训不到, 出现路由塌缩; 专家并行时, 忙的卡拖慢整层. V2 叠了**三级辅助损失**. 专家级一项写全是

$$
\mathcal{L}_{\mathrm{ExpBal}}=\alpha_1\sum_{i=1}^{N_r}f_iP_i,\qquad f_i=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb{1}(\text{token }t\text{ 选中专家 }i),\qquad P_i=\frac{1}{T}\sum_{t=1}^{T}s_{i,t},
$$

$\alpha_1=0.003$. 一个序列 $T$ 个 token 各选 $K_r$ 个专家, 共 $K_rT$ 次选择, 均匀时每个专家分到 $K_rT/N_r$ 次, 前面的系数 $N_r/(K_rT)$ 就是把这个值归一到 $f_i=1$. $P_i$ 是专家 $i$ 在这段序列上的平均 Softmax 亲和度, $\sum_iP_i=1$. 均匀路由时 $\sum_if_iP_i=N_r\cdot1\cdot\frac{1}{N_r}=1$. $f_i$ 来自 Top-K 的指示函数, 不可导, 梯度只经 $P_i$ 流回路由器, 而 $P_i$ 前面的权重正是 $f_i$: 被选得越多的专家, 它的亲和度被往下压得越重, 冷门专家几乎不受压. 这就是乘积形式的作用, 用不可导的计数给可导的概率加权. 设备级 $\mathcal{L}_{\mathrm{DevBal}}$(式 26–28)把同卡专家的 $f$ 取平均, $P$ 求和, $\alpha_2=0.05$. 通信级 $\mathcal{L}_{\mathrm{CommBal}}$(式 29–31)的 $f''$ 统计的是 token 被发往某卡的频率, 用 $D/(MT)$ 归一化, $\alpha_3=0.02$; 归一化的道理和专家级相同: 每个 token 最多发往 $M$ 张卡, 共 $MT$ 次发送, 均匀时每卡 $MT/D$ 次, 归一后 $f''_i=1$; 设备受限路由限住了发送端, 这一项鼓励每张卡接收的量也在 $MT$ 左右.

读公式时会发现, 设备级和通信级两项的 $P$ 完全相同(都是同卡专家亲和度之和), 区别只在 $f$: 一个是同卡专家被选频率的均值, 一个是「被发送到该卡」的频率. 仓库的 GitHub issue 里有人提过这两项几乎等价, 讨论者后来认为差别在于「发送」只计跨卡的 token. 报告正文没有这个解释, 也没有三级损失各自的消融. 三个系数里设备级最大, 专家级最小, 说明作者更在意卡间的均衡, 对专家间的轻微不均更宽容, 这和细粒度专家本来就希望专业化分工的设计一致.

辅助损失保证不了严格均衡, 所以训练时还加了**设备级 token-dropping**: 每卡的算力预算按平均值算(容量因子 1.0), 超出预算时丢掉该卡上亲和度最低的 token, 被丢的 token 在这一层只走残差. 约 10% 的训练序列永远不丢, 这样推理时可以按效率需要选择丢或不丢, 训练里两种情况都见过. 评测时一个 token 都不丢. 这个设计把「训练吞吐」和「评测分数」分开, 但也意味着训练时约 90% 的序列里有一部分 token 在某些层没有经过专家; 实际丢弃率是多少, 本页没有.

## 3. 预训练

### 3.1. 数据与训练日程

67B 的数据流水线分去重, 过滤, 再混合三步, 去重跨 91 个 Common Crawl dump 一起做. V2 沿用这三步, 但做了四处改动: 改进清洗流程, 找回大量此前被误删的网页数据; 显著增加中文; 改进基于质量的过滤算法, 并补充多来源的高质量数据; 过滤争议内容, 减少特定地域文化带来的偏见. 分词器仍是 67B 的 100K 词表 BBPE. 8.1T token 里中文比英文多约 12%. 如果只算中英两种, 英文最多约 3.8T, 这和 §3.2.2 里「英文 token 不到 LLaMA3 70B 的四分之一」的说法一致. 代码, 数学的占比和各来源配比, 报告没有给.

训练超参: 60 层, 隐宽 5120, 128 头, 每头 128 维, 参数初始化标准差 0.006. AdamW, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 0.1, 梯度裁剪 1.0. 学习率前 2K 步线性升到峰值 2.4e-4, 训到约 60% 和 90% token 时各乘 0.316, 这个系数约为 $1/\sqrt{10}$, 两次之后学习率是峰值的 1/10. Batch 在前 225B token 内从 2304 条增到 9216 条, 之后固定. 序列长 4K, 所以稳定期每步约 37.7M token, 剩余约 7.9T token 大约对应 21 万步. 和 67B 比, 峰值学习率从 3.2e-4 降到 2.4e-4, batch 从固定 4608 条变成最终 9216 条. 67B 报告里拟合过超参的 Scaling 规律: 算力预算越大, 最优 batch 越大, 最优学习率越小. V2 的训练算力比 67B 大, 两个超参的调整方向与这条规律一致, 但报告没有说是否按那套公式算出来的. Batch 先小后大, 让早期 loss 下降快的阶段多走几步更新, 等梯度噪声变大再换大 batch, 这是 batch size warmup 的常见理由, 报告只写了做法, 没写理由. 这套分段下降的日程来自 67B 的 Scaling 实验, 好处是可以从中间 checkpoint 续训, 后来 Coder-V2 就是从 V2 的中间 checkpoint 出发继续训练的.

训练框架是自研 HAI-LLM: 16 路 zero-bubble 流水线并行, 8 路专家并行, ZeRO-1 数据并行. 激活参数少, 再对部分算子做重算节省激活显存, 所以完全不用张量并行. 通信, 路由和跨专家的融合线性层都写了专门的 CUDA kernel, MLA 基于改进版 FlashAttention-2. 集群是 H800, 节点内 NVLink/NVSwitch, 节点间 InfiniBand. 实测每训 1T token, 67B 要 300.6K GPU 小时, V2 要 172.8K, 这就是 42.5% 的来源. 按此推算, V2 预训练约 **140 万** GPU 小时, 67B 的 2T 约 60 万. 如果只看激活参数, V2 每 token 的 FFN 计算量约是 67B 的 31%, 实际成本却是 57.5%, 说明 MoE 的通信和负载不均吃掉了接近一半的理论收益(未计注意力计算量差异). 报告只说「MFU 相对较高」, 没有给具体数值.

预训练阶段没有混入任何 SFT 数据. 报告特意点名 MiniCPM 这类在预训练里加入 SFT 数据的做法, 表明 Table 2 的 Base 分数没有被指令数据抬高. 这是评测口径上的声明, 本页没有给出核查方法.

### 3.2. YaRN 把 4K 扩到 128K

预训练结束后用 YaRN 把窗口从 4K 扩到 128K. 在 MLA 里只有解耦的 $\mathbf{k}_t^R$ 和 $\mathbf{q}^R$ 带 RoPE, 所以 YaRN 只作用在这 64 维上. 参数: 扩展倍数 $s=40$, $\alpha=1$, $\beta=32$, 目标上限 160K(4K 乘 40), 期望 128K 可用. YaRN 原版用一个随 $s$ 变化的注意力温度调节 softmax 的熵, 原式是 $\sqrt{1/t}=0.1\ln s+1$; V2 把系数改成 0.0707, 报告写作 $\sqrt{t}=0.0707\ln s+1$, 目标是让困惑度最低. 频率插值的机制见 [长度外推: 从 PI 到 YaRN 的频率扩展](../../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md).

这里有一个实现层面的细节. 原版 YaRN 通常把温度乘到 RoPE 的 cos/sin 上, 让 q 和 k 各自放大 $\sqrt{1/t}$, 点积就放大 $1/t$. 这个做法要求整个 q, k 向量都经过 RoPE; MLA 里只有 64 维带 RoPE, 另外 128 维不带, 乘在 cos/sin 上只会放大一部分. llama.cpp 社区在移植时讨论过这个问题, 公开推理代码的做法是把温度移到 softmax 的缩放系数上. 按 $s=40$ 算, V2 的系数约 1.26, 原版约 1.37. 另外社区指出报告里的 $\sqrt{t}$ 应为 $\sqrt{1/t}$, 属于笔误.

长上下文训练只有 1000 步, 序列 32K, batch 576 条, 合计约 18.9B token, 不到预训练量的 0.3%. 训练只在 32K 上做, 评测却到 128K, Figure 4 的 Needle-In-A-Haystack 在全部长度和深度上都表现良好. 但大海捞针只测「能不能找到一句插入的话」, 不测多跳推理和长文摘要. 本页没有 LongBench, RULER 一类的长上下文评测, 「128K 可用」的证据只有这一张图.

### 3.3. Base 评测: 协议和逐项对比

Table 2 在内部框架里用同一设定重跑了 DeepSeek 67B, Qwen1.5 72B, Mixtral 8x22B, LLaMA3 70B 和 V2. 协议沿用 67B: HellaSwag, PIQA, WinoGrande, RACE, MMLU, ARC, CHID, C-Eval, CMMLU, C3, CCPM 按困惑度评选项; TriviaQA, NaturalQuestions, DROP, MATH, GSM8K, HumanEval, MBPP, CRUXEval, BBH, AGIEval, CLUEWSC, CMRC, CMath 按生成评; Pile-test 用 Bits-Per-Byte, 不同分词器之间才可比. 附录 G 列了每项基准的提示模板. 表注说分差小于 0.3 视为同档.

困惑度评测和生成评测测的东西不一样. 困惑度评测把每个选项接在题目后面, 看模型给哪个选项的概率最高, 不要求模型会按格式作答, 对 Base 模型友好; 生成评测要模型自己写出答案再解析, 格式跟不上就算错. few-shot 数也各不相同: MMLU 5-shot, BBH 3-shot, ARC 25-shot, HellaSwag 10-shot, GSM8K 8-shot, MATH 4-shot, HumanEval 0-shot. Chat 模型的评测以生成式为主, 只保留 MMLU 和 ARC 两个选择题, 所以 Base 和 Chat 之间同名基准的分数变化, 一部分可能来自协议变化, 不全是训练带来的. 报告没有给 Chat 版的 MMLU 具体是按哪种方式评的.

相对 67B, 推理和数学涨得最多: MATH 18.7 到 43.6, GSM8K 63.4 到 79.2, BBH 68.7 到 78.9, MMLU 71.3 到 78.5, C-Eval 66.1 到 81.7. 英文常识类几乎没动, 甚至略降: HellaSwag 86.3 到 84.2, PIQA 83.6 到 83.7, WinoGrande 84.9 持平, TriviaQA 78.9 到 79.9. 这个分布和数据改动方向吻合: 中文和高质量数据加多了, 英文网页常识没有同比例增加. HellaSwag 下降 2.1 个点, 报告没有解释.

对手里, V2 在 MATH(43.6)上表内最高, MMLU 78.5 略低于 LLaMA3 的 78.9, BBH 78.9 与 Mixtral 持平但低于 LLaMA3 的 81.0. 英文常识类 V2 落后: HellaSwag 84.2 对 Mixtral 86.6, LLaMA3 87.9; TriviaQA 79.9 对 82.1 和 81.6. 中文上 V2 大幅领先非中文模型, CCPM 93.1 对 LLaMA3 68.1 和 Mixtral 61.0, 但对 Qwen1.5 72B 在多学科选择题上略输(C-Eval 81.7 对 83.7, CMMLU 84.0 对 84.3). AGIEval 是 V2 明显落后 Qwen 的一项, 51.2 对 64.4, 报告正文没有讨论这个差距. Qwen 的 CHID 因分词器在框架里报错而留空.

## 4. 对齐

### 4.1. SFT 和两阶段 GRPO

SFT 数据扩到 1.5M 条, 其中有用性约 1.2M, 安全约 0.3M, 覆盖数学, 代码, 写作, 推理, 安全等领域, 相对 67B Chat 的版本主要改进是减少幻觉, 提升写作. 训练 2 个 epoch, 学习率 5e-6. 数学和代码数据占比不小, 所以 SFT 后 GSM8K 从 79.2 到 90.8, MATH 从 43.6 到 52.7, HumanEval 从 48.8 到 76.8, 而 MMLU 基本不变(78.5 到 78.4). SFT 的 token 总量, 各领域配比和数据来源, 报告没有给. 讨论节还记了一条: SFT 少于 10K 条时 IFEval 明显下降, 和 LIMA 一类「少量数据就够」的结论相反, 作者的解释是特定技能需要一定数据量, 模型变大可以降低门槛, 但消除不了. SFT 的数据质量问题见 [SFT 数据质量筛选与训练技巧](../../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md).

RL 用 DeepSeekMath 提出的 GRPO. 报告的写法是

$$
\mathcal{J}_{\mathrm{GRPO}}(\theta)=\mathbb{E}_{q,\{o_i\}_{i=1}^G\sim\pi_{\theta_{old}}}\frac{1}{G}\sum_{i=1}^{G}\left(\min\left(\rho_iA_i,\ \mathrm{clip}(\rho_i,1-\varepsilon,1+\varepsilon)A_i\right)-\beta\,\mathbb{D}_{KL}(\pi_\theta\|\pi_{ref})\right),\qquad \rho_i=\frac{\pi_\theta(o_i\mid q)}{\pi_{\theta_{old}}(o_i\mid q)},
$$

$$
A_i=\frac{r_i-\mathrm{mean}(\{r_1,\dots,r_G\})}{\mathrm{std}(\{r_1,\dots,r_G\})}.
$$

每个问题 $q$ 从旧策略采 $G$ 个回答, 各自拿到奖励 $r_i$. 优势 $A_i$ 只和同组其他回答比: 高于组均值为正, 低于为负, 再除以组内标准差, 让难题和易题的优势尺度一致. 这一步替掉了 PPO 里的价值网络, 基线不再是 critic 对 $q$ 的估值, 而是同题 $G$ 个样本的平均奖励. $\rho_i$ 是新旧策略对同一回答的概率比, $\min$ 和 clip 限制一次更新里 $\rho_i$ 最多偏离 1 到 $\varepsilon$ 为止, 超出部分不再给梯度. $\beta$ 项把策略拉向参考模型 $\pi_{ref}$, 防止为了追奖励模型的分数跑到分布外. 对 236B 的模型来说, 省掉一个同规模的价值网络是很实际的考虑. 同组 $G$ 个回答奖励完全相同时, 分子分母都是 0, 这组除了 KL 项拿不到任何梯度; 报告没写怎么处理这种组. 组大小 $G$, 裁剪系数 $\varepsilon$, KL 系数 $\beta$ 和训练步数, 报告都没有给. 式 32 的写法和 DeepSeekMath 有一处不同: DeepSeekMath 按 token 写比率并对输出长度取平均, 这里直接写成整条输出的概率比 $\pi_\theta(o_i|q)/\pi_{\theta_{old}}(o_i|q)$. 这可能只是记号上的简写, 实际实现是按 token 还是按序列裁剪, 本页没有说明. KL 项(式 33)用的是 $\frac{\pi_{ref}}{\pi_\theta}-\log\frac{\pi_{ref}}{\pi_\theta}-1$ 这个无偏且恒为非负的估计量, 与 DeepSeekMath 相同, 它不放进奖励, 而是直接加在损失上. 算法细节见 [GRPO](../../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

训练分两段. 预实验发现代码, 数学这类推理数据上的 RL 和通用数据不一样: 能力可以在更长的训练步数里持续提升. 所以先做推理对齐, 奖励来自一个训出来的 $RM_{\mathrm{reasoning}}$(式 35); 再做人类偏好对齐, 奖励是 $c_1RM_{\mathrm{helpful}}+c_2RM_{\mathrm{safety}}+c_3RM_{\mathrm{rule}}$(式 36), 三个系数没有给. 奖励模型都从 Chat(SFT) 初始化, 用 point-wise 或 pair-wise 损失训练; 代码偏好数据来自编译器反馈, 数学偏好数据来自标准答案. 注意这里的编译器和标准答案只用来造奖励模型的训练数据, RL 时打分的仍是神经网络奖励模型. 到 R1 才把规则判分直接当奖励. 工程上有三项: 训练和推理用不同并行策略的混合引擎, 大 batch 的 vLLM 做采样, 以及模型在 CPU 和 GPU 之间卸载, 回载的调度. 讨论节还说在线 RL 在偏好对齐里明显好于离线, 所以专门搭了在线框架, 但同时说明这个结论可能随场景变化.

### 4.2. Chat 评测与对齐税

Table 3 里, RL 相对 SFT 的变化分成两类. 代码和数学继续涨: HumanEval 76.8 到 81.1, LiveCodeBench 28.7 到 32.5, MBPP 70.4 到 72.0, GSM8K 90.8 到 92.2, MATH 52.7 到 53.9. 知识和推理类选择题回落: BBH 81.3 到 79.7, MMLU 78.4 到 77.8, C-Eval 80.9 到 78.0, AGIEval 63.2 到 61.4, IFEval 64.1 到 63.8. 报告把 BBH 的下降称作 alignment tax, 说通过数据处理和训练策略把代价压到可接受的程度; 实际上 C-Eval 掉了 2.9 个点, 比 BBH 的 1.6 还多, 正文没有提. LiveCodeBench 取的是 2023-09-01 到 2024-04-01 的题, 用时间窗口降低污染风险.

横向比较有两处口径问题. 67B Chat 的数字直接引自前作, 没有在本次框架里重跑, 和其它列的设定不完全一致. 表注还说 LLaMA3 70B Instruct 这类模型不一定遵守 few-shot 格式, TriviaQA, NaturalQuestions 可能被低估, LLaMA3 Instruct 的 TriviaQA 只有 69.1 就是例子. IFEval 上 LLaMA3 Instruct 79.7, 远高于 V2 的 63.8, 这是 V2 Chat 最明显的短板.

开放生成上, Table 4 的 MT-Bench 从 SFT 的 8.62 到 RL 的 8.97, AlpacaEval 2.0 长度控制胜率从 30.0 到 38.9, 分别与 LLaMA3 70B Instruct(8.95)持平和领先(34.4). RL 对开放生成的提升比对标准基准大得多, 这和偏好奖励模型的训练目标一致. Table 5 的 AlignBench 总分 RL 7.91, SFT 7.74, 高于 GPT-4-0613 的 7.53. 需要注意 AlignBench 的裁判就是 GPT-4-0613, 裁判给自己打分和给别人打分是否同一标准, 报告没有讨论. 分项里, RL 的中文理解 8.28 高于 GPT-4-1106-Preview 的 7.33, 但逻辑推理 7.14 低于后者的 7.66, 而且比自己 SFT 版的 7.26 还低; 数学计算则从 7.34 升到 7.77. RL 在中文推理上是一涨一跌, 不是全面提升.

## 5. Lite, 附录和谱系位置

附录 B 放出 DeepSeek-V2-Lite: 27 层, 隐宽 2048, MLA 16 头, 每头 128 维, $d_c=512$, 解耦 RoPE 64 维, 不压缩 query; MoE 为 2 共享加 64 路由, 专家中间宽 1408, 每 token 激活 6 个; 总参 15.7B, 激活 2.4B. 同一份语料从头训 5.7T token, 恒定 batch 4608, 峰值学习率 4.2e-4, 在 80% 和 90% token 处各乘 0.316. 专家全放在同一张卡上, 所以只保留很小的专家级损失($\alpha_1=0.001$), 设备级, 通信级损失和设备受限路由都不需要. 之后扩到 32K 上下文并做 SFT. Table 6 里 Lite 的 MMLU 58.3, 对 DeepSeekMoE 16B 的 45.0; GSM8K 41.1 对 18.8; MATH 17.1 对 4.3. 但 Lite 训了 5.7T, 对手只训了 2T, 语料也换成了 V2 的新版本, 这些差距不能全记在 MLA 头上.

附录 E 解释了 MMLU Humanity-Moral 子集上的落后: 三名标注员独立标注 420 个道德情景, 与标准答案的一致率只有 66.7%, 59.8% 和 42.1%, 标注员之间也只有 57.9% 到 69.0%. 作者据此认为这个子集的答案本身带有地域文化倾向, V2 在这里掉分是预训练去偏的结果. 附录 F 的 SC-Math6 上, V2 Chat(RL) 总准确率 84.54, 与 Ernie-bot 4.0 的 84.38 接近, 低于 GPT-4-1106-Preview 的 89.77.

谱系上, V2 把三条已有的线接到一起: 67B 的数据流水线, 分词器和分段学习率日程, DeepSeekMoE 的专家结构, DeepSeekMath 的 GRPO. MLA 是它自己的新东西, 致谢里点名 Huazuo Gao 和 Wangding Zeng 做出了 MLA 的关键设计, 并感谢苏剑林在位置编码上的讨论. 往后看, V3 保留了 MLA 和细粒度加共享专家的结构, 把规模推到 671B 总参, 37B 激活; 三级辅助损失换成了不靠损失项的偏置调节(auxiliary-loss-free), 设备受限路由改成节点受限, token-dropping 取消, 另加 MTP 和 FP8 训练. V2 里推理 RL 用神经奖励模型, 到 R1 换成规则判分, 并把「推理能力可以随训练步数持续提升」这条观察发展成了主线. 回头看, V2 在 MLA 上的设计后来几乎没有大改, 在负载均衡上的设计则被整套替换.
