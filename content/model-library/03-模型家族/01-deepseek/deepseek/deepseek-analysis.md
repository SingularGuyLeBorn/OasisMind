# DeepSeek LLM: 在自家数据上重拟 Scaling Laws, 再训 7B 和 67B

来源: [DeepSeek LLM: Scaling Open-Source Language Models with Longtermism](https://arxiv.org/abs/2401.02954) (arXiv: 2401.02954). 仓库: https://github.com/deepseek-ai/DeepSeek-LLM

对照译稿: `deepseek-bi.md`. 表内数字回源文 `deepseek.md`.

这是 DeepSeek 家族第一份通用底座报告. 模型本身是 Dense Transformer, 没有 MoE, 没有 MLA, 结构几乎照搬 LLaMA. 真正的分量落在三处: 一套在自家语料上重新拟合的 **Scaling Laws**, 一条把去重做到 91 个 Common Crawl dump 的数据流水, 以及对齐阶段几个「刻意不做」的决定. 后面的 Coder, Math, V2 在分词器, 训练框架, 学习率调度和评测协议上都直接继承了这里的设定, 所以读它更像读家族的地基图纸.

## 1. 底座与数据

### 1.1. 起点: 一个照着 LLaMA 搭的 Dense 底座

微观结构基本是 LLaMA 的配方: Pre-Norm 加 **RMSNorm**, FFN 用 **SwiGLU**, 中间宽度 $\frac{8}{3}d_{\mathrm{model}}$, 位置编码用 **RoPE**. 唯一的注意力改动是 67B 换成 **GQA**, $n_{\mathrm{kv\_heads}}=8$, 目的写得很直接: 省推理成本. 7B 仍用满头 MHA. 这说明当时 DeepSeek 并没有把「推理时 KV cache 太大」当成主要矛盾, 只在大尺寸上顺手压了一下, 真正动注意力结构要等到 V2 的 MLA. GQA 在性能与缓存之间怎么取舍, 见 [03-GQA-在性能与缓存之间折中](../../../../llm-guide/2-核心原理与架构/2.2-基础注意力机制/2.2.2-多头注意力变体/03-GQA-在性能与缓存之间折中/03-GQA-在性能与缓存之间折中.md).

宏观上有两处和 LLaMA 不同. 第一, 层数选成 30 和 95, 报告说这样方便 pipeline 切分. 第二, 67B 用 GQA 省下的参数预算没有照惯例加到 FFN 宽度上, 而是加到深度上, 所以 95 层配 $d_{\mathrm{model}}=8192$. 报告只说「为了更好性能」, 没有给深宽对比的消融, 这一点本页没有证据. 按 Table 2 的规格粗算: 每层注意力约 $2.25d^2$(Q, O 满头, K, V 只有 1/8), FFN 约 $8d^2$, 95 层合计约 65B, 加上词表约 1.7B, 正好落在 67B 附近(估算). 训练框架是自研的 **HAI-LLM**: 数据, 张量, 序列并行加 1F1B 流水, FlashAttention, ZeRO-1 切优化器状态, bf16 前向, fp32 累梯度, cross-entropy 在 kernel 内就地把 bf16 logits 转成 fp32 再覆写成梯度. 权重和优化器状态每 5 分钟异步落盘, 最坏只丢 5 分钟训练. 这些细节后来在 V2 和 V3 里一路沿用.

训练常数写在 §2.3 和 Table 2. 权重按标准差 0.006 初始化, 优化器 **AdamW**, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 0.1, 梯度裁剪 1.0. 两档模型的上下文都是 4096. Table 2 的 batch 以序列计, 7B 为 2304 条, 67B 为 4608 条, 换成 token 分别约 940 万和 1890 万每步; 训完 2T token, 7B 约走 21 万步, 67B 约 10.6 万步(估算). 上下文只有 4K, 报告里没有任何长上下文扩展, 这一面本页没有. 到 V2 才在 4K 预训练之后用 YaRN 把窗口拉到 128K, 那是另一份报告的事.

框架里已经能看到 DeepSeek 后来反复做的那件事: 把通信藏到计算后面. 最后一个 micro-batch 的反向和 ZeRO-1 的 reduce-scatter 重叠, 序列并行里的 GEMM 和 all-gather/reduce-scatter 重叠; LayerNorm, GEMM, Adam 更新尽量融合成单个算子. 训练还支持换一套 3D 并行配置从 checkpoint 续跑, 用来应对集群负载变化. 评测端生成任务走 vLLM, 非生成任务用 continuous batching, 省掉手调 batch 和 padding. 这些在报告里只占一段, 但 V3 的 DualPipe 和算通重叠, 思路上就是从这里一路加码过去的.

### 1.2. 数据: 91 个 dump 一起去重, 以及分词器的几个选择

语料目标是 2T token, 以中英为主. 流水分三步: 去重, 过滤, remix. 去重的力度是这篇最具体的数据贡献. Table 1 给出跨 dump 去重的效果: 只在 1 个 dump 内去重, 去重率 22.2%; 把 91 个 dump 放在一起去重, 去重率到 89.8%, 剔除量大约是单 dump 的四倍. Common Crawl 每一期大量内容是重复抓取的, 单期内部去重看不到跨期重复, 这张表把这件事量化了. 过滤阶段同时看语言学信号和语义信号, remix 阶段把欠采样的领域加回来. 至于过滤器用了什么模型, 阈值多少, 最终各领域配比是多少, 本页都没有给, 只能知道流程顺序.

Table 1 其实给了一整条曲线: 1 个 dump 22.2%, 2 个 46.7%, 6 个 55.7%, 12 个 69.9%, 16 个 75.7%, 22 个 76.3%, 41 个 81.6%, 91 个 89.8%. 从 1 个到 2 个, 去重率翻了一倍多, 说明相邻两期的重复抓取极多; 16 到 22 个几乎不动, 41 到 91 个又涨了 8 个点, 大概是更早年份的 dump 和新近 dump 之间还有大量转载(推断). 最终只留下约十分之一的文档, 2T 的目标 token 量是在这样狠的去重之后凑出来的. 报告没有说去重用的是 MinHash 还是精确哈希, 粒度是文档还是段落, 这一面本页没有. 过滤阶段报告只说结合「语言学和语义」两类评估, 分别从单篇文档和全局视角看质量; remix 阶段提高欠代表领域的占比. 三步里只有去重给了数字.

数据流水和后面的 Scaling 实验不是两件独立的事. 报告 §3.3 说开发过程中数据集迭代了多次, 调整来源比例, 同时提升整体质量; 正是这几轮迭代留下了「早期数据」和「当前数据」两个版本, 让他们能比较同一方法在不同质量数据上拟合出的分配指数. 去重和过滤做得越狠, 数据越干净, 按他们的结论, 同样的算力越该往模型上加. 所以第 1.2 节的流水既是语料工程, 也是第 2.2 节那张 Table 4 的实验变量来源.

分词器用 Hugging Face `tokenizers` 实现的 **BBPE**. 预分词阻止换行, 标点和 CJK 符号跨类合并, 数字拆成单个 digit, 这点和 LLaMA 一样. 常规词表 100000, 加 15 个 special token 到 100015, 训练时模型词表开到 102400, 一是给以后的 special token 留位, 二是让矩阵维度对齐算力. 分词器在约 24 GB 多语语料上训练. 这个 100K 词表被 V2 原样继承(「same tokenizer as used in DeepSeek 67B」), 直到 V3 才换成 128K. 数字逐位切分对后面的数学能力有影响, 但本页没做切分方式的消融.

## 2. Scaling Laws

### 2.1. 超参跟着算力走: batch size 与学习率的幂律

报告第 3 节先解决一个前置问题: 不同算力预算下的模型, 超参是否都调到了最优. 如果没有, 后面拟合出来的 model/data 分配就混进了「没调好」的噪声. 他们认为多数训练常数跨算力不变, 真正敏感的是 batch size $B$ 和学习率 $\eta$. 在 $10^{17}$ FLOPs 下做网格搜索, 发现最优点周围有一片很宽的近最优平台. 于是把「泛化误差不超过最小值 0.25%」的配置都当作近最优, 在 $10^{17}$ 到 $2\times10^{19}$ 的范围里拟合出:

$$
\eta_{\mathrm{opt}}=0.3118\cdot C^{-0.1250}, \qquad B_{\mathrm{opt}}=0.2920\cdot C^{0.3271}.
$$

算力变大, batch 缓慢增大, 学习率缓慢下降, 方向和工程直觉一致. 他们在 $10^{20}$ 量级验证, 拟合值落在最优带中间, 7B 与 67B 的实际超参也按这条曲线取(7B: batch 2304, lr $4.2\times10^{-4}$; 67B: batch 4608, lr $3.2\times10^{-4}$). 报告也承认没考虑算力以外的因素, 并观察到同算力下 model/data 分配不同时, 最优超参区域会轻微移动, 和 Kaplan 那种「最优 batch 只和 loss 有关」的说法不完全一致.

近最优平台很宽, 这件事本身有实际价值. 它意味着大模型训练前不必把 batch 和学习率抠到小数点后几位, 只要落在拟合曲线附近的带子里, 损失就差不到 0.25% 以外. 对只能训一次的 67B 来说, 这比找到一个「精确最优点」更重要: 大模型没有机会反复试错, 需要的是一个事先就能算出来, 而且容错范围够宽的配置. 报告没有公开 7B 和 67B 的训练 GPU 小时, 所以这套方法到底省了多少算力, 本页无法核算. Figure 3 里 7B 和 67B 的蓝星都落在灰色近最优点构成的带子里(读图).

这里有一处容易被忽略的衔接: 让这么多组实验跑得起的, 是 **multi-step** 学习率调度. 预训练不用 cosine, 改成 2000 step warmup 到峰值, 训到 80% token 降到峰值的 31.6%, 训到 90% 再降到 10%. 31.6% 约等于 $1/\sqrt{10}$, 两次各乘 0.316 就是 10%, V2 的写法正是「两次乘 0.316」. Figure 1 显示最终 loss 和 cosine 基本齐平. cosine 的衰减形状依赖总步数, 每改一次训练长度都要从头跑; multi-step 的第一段是常数学习率, 可以被不同长度的实验共享. 报告明确说 $10^{17}$ 到 $2\times10^{19}$ 的那批超参实验就是「复用第一阶段」训出来的. 所以这个调度器既是训练配方, 也是做 Scaling 实验的省钱手段. 他们也试过调三段比例, 效果略好, 最后为了复用率仍选 80%/10%/10%.

### 2.2. 用 M 代替 6N, 以及数据质量怎样改写分配

第二个问题是模型规模怎么计量. 常用的 $C=6ND$ 里, $N$ 用非 embedding 参数($6N_1$)会漏掉注意力本身的算力, 用全参数($6N_2$)又把词表算进来, 而词表对容量的贡献小. 报告改用 **non-embedding FLOPs/token** $M$, 写成 $C=MD$:

$$
M = 72\, n_{\mathrm{layer}}\, d_{\mathrm{model}}^2 + 12\, n_{\mathrm{layer}}\, d_{\mathrm{model}}\, l_{\mathrm{seq}}.
$$

两项都能从每 token 的前向加反向乘加数推出来. 第一项: 每层参数约 $12d_{\mathrm{model}}^2$(注意力 Q, K, V, O 四个 $d\times d$ 矩阵共 $4d^2$, SwiGLU 三个 $d\times\frac{8}{3}d$ 矩阵共 $8d^2$), 每个参数前向 2 FLOPs, 反向再算两倍, 合计 $6\times12=72$, 所以 $72\,n_{\mathrm{layer}}d_{\mathrm{model}}^2$ 就是 $6N_1$. 第二项是 $6N$ 漏掉的部分: 一个 token 的 query 要和 $l_{\mathrm{seq}}$ 个 key 做点积($QK^\top$), 再对 $l_{\mathrm{seq}}$ 个 value 加权求和($AV$), 前向各 $2\,l_{\mathrm{seq}}d_{\mathrm{model}}$ FLOPs, 共 $4\,l_{\mathrm{seq}}d_{\mathrm{model}}$, 乘 3 算上反向得 12. 这一项没有参数, 却随序列长度线性增长, 模型越窄占比越高. 以 Table 3 第一行(8 层, 宽 512, $l_{\mathrm{seq}}=4096$)算: 第一项 $72\times8\times512^2\approx1.51\times10^8$, 第二项 $12\times8\times512\times4096\approx2.01\times10^8$, 合计正是表里的 352M, 注意力那一项反而占了 **57%**. 拟合目标于是写成在 $C=MD$ 约束下求 $\arg\min_{M,D}L$, 而不是在 $C=6ND$ 上求.

Table 3 显示小模型上差异最大: 8 层, 宽 512 的配置, $6N_1/M$ 只有 0.43, $6N_2/M$ 是 1.32, 误差可到 50% 左右; 到 80 层, 宽 8192 时两者分别是 0.92 和 0.94. 拟合 Scaling 曲线主要靠小模型, 小模型上的系统误差会被外推放大, 所以这一改动的意义主要在拟合端. 公式本身也有前提. 第一项的系数 72 对应满头 MHA 加 $\frac{8}{3}$ 宽的 GLU FFN, 第二项按不带因果掩码的完整注意力计. 社区复读这篇时指出过: 67B 用了 GQA, K, V 投影变小, 按 Table 2 规格算, 真实的 $M$ 比公式值小一截, 约 $4.3\times10^{11}$ 而不是 $5.0\times10^{11}$(估算). 因果注意力实际只算一半左右, 第二项也偏大. 这些偏差在大模型上占比不高, 但说明 $M$ 更像一个「更贴近 MHA Dense 模型」的计量, 换架构要重算.

有了 $M$, 用 Chinchilla 的 IsoFLOP 剖面: 8 个预算从 $10^{17}$ 到 $3\times10^{20}$, 每个预算约 10 种 model/data 分配, 指标是 100M token 独立验证集上的 bits-per-byte. IsoFLOP 的思路是固定总算力, 让模型大小和数据量此消彼长, 每个预算下画一条 loss 曲线, 曲线谷底就是该预算的最优分配; 再把各预算的谷底连起来拟合幂律. 每个预算的超参都由上一节的公式给出, 这就是为什么超参 Scaling 要先做. 拟合得到 $M_{\mathrm{opt}}=0.1715\cdot C^{\mathbf{0.5243}}$, $D_{\mathrm{opt}}=5.8316\cdot C^{\mathbf{0.4757}}$, 比 Chinchilla 的 0.49/0.51 更偏向加模型. Figure 5 用小实验的 loss 曲线预测 7B 和 67B, 蓝星落在线上, 跨度约 1000× 算力.

附录 A.2 把同一批 IsoFLOP 实验分别用 $6N_1$, $6N_2$ 和 $M$ 重新计算算力再拟合. 三种口径在高算力段给出的最优分配差别不大, 低算力段差别明显. 外推到大模型时, $6N_1$ 会高估大模型的表现, $6N_2$ 会低估, 只有 $M$ 的预测落在蓝星上. 换句话说, 计量口径的误差不会改变「大算力下怎么分配」的大方向, 但会改变你对大模型 loss 的预期, 而预期准不准, 决定了训练前能不能判断这次投入值不值.

最有信息量的是 Table 4. 同一套方法换三份数据: 早期内部数据 $a=0.450$, 当前内部数据 $a=0.524$, OpenWebText2 $a=0.578$. 报告对三份数据的质量排序是 OpenWebText2 > 当前 > 早期, 指数随之单调变化: 数据越好, 多出来的算力越该给模型. 这给 Kaplan(0.73)和 Chinchilla(0.49)结论打架提供了一个解释: 它们的语料不同. 报告的直觉解释是高质量数据逻辑清楚, 充分训练后预测难度低, 于是更值得加大模型. 这个解释没有被单独验证, 质量排序也来自内部评估, 本页没有给质量指标的定义. 反过来, 分配指数本身可以当成间接的数据质量探针, 这是报告自己提出的用法.

把拟合公式套回 7B 和 67B, 能看到一个报告没有明说的事实: 这两档尺寸是为了对齐开源社区的习惯选的, 并不在拟合出来的最优点上. 按 $C=MD$ 粗算, 67B 训 2T 约 $8.6\times10^{23}$ FLOPs, 公式给出的最优是 $M$ 约 $6\times10^{11}$, 数据约 1.4T; 实际模型更小, 数据多喂了约 1.4 倍. 7B 更明显, 最优数据量只有约 0.5T, 实际 2T, 多了约 4 倍(以上均为估算). 训练算力最优和推理成本最优本来就不是同一个点, 小一点, 多训一点, 部署更便宜. 报告用 Scaling Laws 定了超参和 loss 预期, 尺寸则由部署习惯决定. 附录 A.3 的基准曲线也支持「还没训饱」这个判断: 从训练开始到结束, 各项基准持续上升, 末端没有走平, 报告自己说继续训还会涨(读图). 后来 V2 把语料扩到 8.1T, 方向与此一致.

## 3. 对齐

### 3.1. 对齐: 150 万条 SFT, 重复率, 再接 DPO

指令数据约 **150 万**条, 中英双语. 其中有用性数据 120 万: 通用语言任务 31.2%, 数学 46.6%, 代码 22.2%; 安全数据 30 万. 数学占到将近一半, 这和评测里 Chat 版数学大涨直接对应. 7B 训 4 epoch, 67B 只训 2 epoch, 因为 67B 过拟合明显; 学习率分别是 $1\times10^{-5}$ 和 $5\times10^{-6}$. 他们在看基准分之外还盯一个指标: 用 3868 条中英 prompt 统计「停不下来, 反复生成同一段」的比例, 解码温度设为 0. 温度 0 就是贪心解码, 一旦进入循环, 同一前缀永远选同一个下一 token, 没有采样噪声把它带出来, 所以这个比例测的是模型分布本身有没有自我强化的环, 而不是采样运气. 数学 SFT 数据越多, 重复率越高. 报告的解释是数学数据里推理句式相似, 弱模型学不会推理模式, 只学会了句式循环.

训练过程里 7B 和 67B 的表现也不一样. 7B 的 GSM8K 和 HumanEval 随 epoch 稳步上升, 67B 则很快碰到上限, 这也是 67B 只训 2 epoch 的另一面原因. 报告对 SFT 在推理任务上的作用下了一个很克制的判断: SFT 数据大量是 CoT 格式, Chat 模型在 BBH, NaturalQuestions 上小幅提升, 但 SFT 学到的是推理路径的正确格式, 而不是推理能力本身. 这个判断和后面「数学代码涨 20 分是因为 Base 欠拟合」的解释放在一起看, 意思是: SFT 能补知识, 能教格式, 教不出 Base 没有的推理. 一年后 R1 用大规模 RL 回答的正是这个问题.

处理办法是分阶段. 7B 第一阶段用全部数据, 第二阶段去掉数学和代码只留对话数据. Table 12: 重复率从 0.020 降到 0.014, HumanEval 保持 48.2, GSM8K 63.9 到 63.0, IFEval 从 38.0 升到 41.2. 67B 第一阶段后重复率已低于 1%, 第二阶段反而伤分, 所以只做一阶段. 接着是 **DPO**: 按有用性和无害性构造偏好对, 候选回答由自家 Chat 模型生成, 1 epoch, lr $5\times10^{-6}$, batch 512, 学习率先 warmup 再 cosine 衰减(和预训练的 multi-step 不同, DPO 只跑一轮, 不需要复用中间段). DPO 优化的是 Rafailov 等人的目标:

$$
\mathcal{L}_{\mathrm{DPO}}=-\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right)\right].
$$

$y_w$, $y_l$ 是同一 prompt $x$ 下被偏好和不被偏好的回答. 两个对数比各自度量当前策略 $\pi_\theta$ 相对参考模型 $\pi_{\mathrm{ref}}$(这里就是 SFT 后的 Chat 模型)把该回答的概率抬高了多少; 损失只要求「好回答被抬得比坏回答多」, 不要求绝对概率上升. $\beta$ 控制离参考模型多远: $\beta$ 越大, 同样的对数比差被放得越大, sigmoid 越快饱和, 策略越不需要偏离 $\pi_{\mathrm{ref}}$ 就能把损失压下去. 报告没写 $\beta$ 取多少. 候选回答都由自家 Chat 模型生成, 所以 $y_w$, $y_l$ 本来就在 $\pi_{\mathrm{ref}}$ 的高概率区, 对数比从 0 附近起步, 这也是 1 epoch, $5\times10^{-6}$ 这样小步长就够用的原因(推断). DPO 明显提升开放式生成, 报告的说法是标准基准几乎不动. 细看附录 Table 17, 「几乎不动」里其实有方向: GSM8K 从 84.1 到 85.2, TriviaQA 从 81.5 到 82.9, 但 MATH 从 32.6 降到 30.2, HumanEval 从 73.8 降到 71.3. 偏好数据以写作, 问答, 指令跟随为主, 偏向开放对话的优化对难数学题和代码有轻微拖累, 这和后来 DeepSeekMath 改用基于可验证答案的 RL 的方向一致. 偏好对具体怎么标, 正负样本怎么选, 本页没写. DPO 的推导见 [01-DPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.2-无奖励模型的对齐DPO-KTO/01-DPO/01-DPO.md). 结论末尾一句值得留意: 初步实验显示 RL 能提升复杂推理, 这句话后来在 DeepSeekMath 的 GRPO 里兑现.

安全这一面, 报告说在预训练, SFT, DPO 三个阶段都考虑了, 但只给了 SFT 里 30 万条安全数据和 DPO 里的无害性偏好对, 预训练阶段具体怎么处理本页没有. 评测端倒写得具体: 20 人跨学科专家组搭了一套安全分类体系, 每个子类手写几十道题, 除了覆盖内容类别, 还专门做了提问形式的多样性, 用诱导, 角色扮演, 多轮对话, 预设立场等方式绕过表面检查, 针对的就是当时流传的「奶奶漏洞」一类攻击. 最后得到 2400 题, 标注分安全, 不安全, 拒答三类, 拒答也算安全. 按 Table 10, 67B Chat 在歧视偏见类 500 题里安全 486 题, 其他安全问题类 800 题里安全 767 题. 把拒答算作安全, 意味着这张表衡量的是「不出事」, 而不是「有用且不出事」, 过度拒答的代价在这里看不出来.

### 3.2. 刻意不做的几件事: 选择题, 预训练里的指令数据, system prompt

讨论节记录了几组「做了有效但不采用」的实验. 最有代表性的是选择题数据: 对齐阶段加 **2000 万**道中文选择题, 7B Chat 的 MMLU 从 49.4 到 60.9, C-Eval 从 47.0 到 71.3, CMMLU 从 49.7 到 73.8, 但生成式的 TriviaQA 不动(57.9), 内部 ChineseQA 反而从 75.0 降到 74.4. 他们为此把 C-Eval 验证集和 CMMLU 测试集做了去重, 排除了直接泄漏. 结论是模型学会的是「做选择题」这种格式, 用户在对话里感受不到变聪明, 于是 **预训练和微调都不用选择题数据**. 这等于公开承认当时的中文榜单能被格式数据大幅抬高, 读同期其他模型的 C-Eval 分数时应该带着这个参照.

第二组是预训练末尾混指令数据. 在最后 10% 预训练里混入 **500 万**条指令数据(多为选择题), Base 的榜单分确实上升, 但最终效果和把同样数据放进 SFT 相同. 既然不想用选择题, 非选择题指令又不够多, 就不往预训练里放. 第三组是 system prompt: 7B 加上后 MT-Bench 从 7.15 略降到 7.11, 67B 从 8.35 升到 8.58. 报告的解释是大模型能读懂系统提示的意图, 小模型读不懂, 而且训练与推理的格式不一致还会伤分. 这三组实验合起来, 是这份报告在「别刷榜」上给出的具体证据, 而不只是一句态度.

## 4. 评测

### 4.1. 评测: 分数从哪来, 哪些格子不该过度解读

评测协议后来被 V2 原样沿用: 选择类任务按每个选项的困惑度选最低, ARC 和 OpenBookQA 用无条件归一化, 其余用长度归一化. 两种归一化落在同一步打分上的差别是: 长度归一化给选项 $a$ 打分 $\frac{1}{|a|}\sum_{t}\log p(a_t\mid x,a_{<t})$, 除以选项长度(报告没说按 token 还是按字符计), 防止长选项因为多乘了几个小于 1 的概率而吃亏; 无条件归一化沿用 GPT-3 的做法, 打分 $\log p(a\mid x)-\log p(a\mid x_0)$, $x_0$ 是一个不含题目的固定前缀(如「Answer:」), 减掉的是选项本身「无论问什么都常见」的先验. ARC 和 OpenBookQA 的错误选项常是高频常识短语, 只按长度归一化会偏向它们, 这大概是单独换口径的原因(推断). 报告只引了 GPT-3, 没写 $x_0$ 用的具体字符串; 生成类任务贪心解码后解析答案; Pile-test 用 bits-per-byte, 让不同分词器能公平比. Base 模型对比 LLaMA2(Table 5, 内部框架): 两边都训约 2T token, LLaMA2 以英文为主, DeepSeek 中英各半. 英文理解大致打平, 数学, 代码, BBH 和中文明显更好. 67B 对 70B: GSM8K 63.4 对 58.4, MATH 18.7 对 13.5, HumanEval 42.7 对 28.7, MBPP 57.4 对 45.6, BBH 68.7 对 62.9; 中文 CHID 92.1 对 55.5, CMMLU 70.8 对 53.1. 7B 对 LLaMA2 7B 的优势小得多, 报告归因于小模型更受双语冲突影响. LLaMA2 没专门训中文, CMath 却不差, 说明数学能力能跨语言迁移; 成语类的 CHID 则必须吃够中文 token.

评测套件按能力分成十类: 多学科选择题(MMLU, C-Eval, CMMLU), 语言理解与推理(HellaSwag, PIQA, ARC, OpenBookQA, BBH), 闭卷问答(TriviaQA, NaturalQuestions), 阅读理解(RACE, DROP, C3), 指代消解(WinoGrande, CLUEWSC), 语言建模(Pile), 中文文化(CHID, CCPM), 数学(GSM8K, MATH, CMath), 代码(HumanEval, MBPP), 标准化考试(AGIEval). 同一类里协议可能不同: WinoGrande 走困惑度, CLUEWSC 走生成; CHID, CCPM 走困惑度. 所有对比模型都在内部框架里重跑, Table 5 里的 LLaMA2 分数不是 Meta 官方报的数, 表注还说 few-shot 数是上限, 上下文不够时会减少. 跨报告拿这些数字比较时, 协议差异带来的偏差可能比模型差异还大.

Chat 对 Base(Table 6)变化最大的是数学和代码: 67B 的 GSM8K 63.4 到 84.1, MATH 18.7 到 32.6, HumanEval 42.7 到 73.8. 这和 SFT 里 46.6% 的数学数据, 22.2% 的代码数据一一对应. 报告自己的判断很克制: Base 在这些任务上欠拟合, SFT 补上了一部分知识, 但能力可能集中在代码补全和代数题, 真要全面提升得在预训练阶段加数据, 这正是后来 Coder 和 Math 两条线的出发点. 知识类基准的小幅波动, 报告认为不是 SFT 增减了知识, 而是学会了在 0-shot 对话里接近 Base few-shot 的分数. HellaSwag 这类完形续写任务微调后稳定下降, 更适合纯语言模型. 中文的 CLUEWSC 和 CHID 在 67B Chat 上也掉得明显(81.0 到 60.0, 92.1 到 72.6), 报告没有单独解释. CHID 是成语完形, 走困惑度评测, 和 HellaSwag 同属报告说的「完形续写类任务微调后下降」, 可以用同一个原因解释; CLUEWSC 走生成评测, 下降更可能和 Chat 模型的回答格式有关, 解析器没接住(推断).

读 Table 6 时要记住两边的设定不同: Chat 在 MMLU, GSM8K, MATH, C-Eval, CMMLU 上用 0-shot, Base 仍用 few-shot, 最大序列长度按任务取 2048 或 4096. 所以「Chat 比 Base 高多少」混着两种变化, 一种是能力, 一种是提示方式. 数学和代码涨 20 分以上, 远超提示方式能解释的范围; 知识类上下一两分的波动, 则基本落在提示方式差异里. 这也是报告不把知识类波动解读为「学到或忘掉知识」的原因.

开放生成和保留集用来检查「榜单高, 新题崩」. AlignBench 上 67B Chat 总分 6.43, DPO 后 6.69, 高于 gpt-3.5-turbo-0613 的 6.08, 低于两个 GPT-4 版本; MT-Bench 上 67B Chat 8.35, DPO 后 8.76. 保留集(Table 9)用 2023 年 7 月到 11 月的 LeetCode 周赛 126 题, 匈牙利高中数学考试 33 题(人工打分), 以及 IFEval: 67B Chat 分别是 17.5, 58, 55.5. 报告特别指出 ChatGLM3 在 MBPP 上 52.4, GSM8K 上 72.3, 接近甚至超过 67B, 换成新题就明显落后; 7B 在常规榜单上不如同尺寸对手, 在保留集上反而不差. 安全方面, 20 人专家组建 2400 题分类测试集并人工标注, Do-Not-Answer 上 67B Chat 得 97.8. 这些数字都是 GPT-4 打分或人工打分, 评分器本身的偏差本页没有讨论.

两张开放评测表的分项比总分更能说明 DPO 做了什么. AlignBench(Table 7, gpt-4-0613 打分, 683 题, 8 个一级类): DPO 后语言总分从 7.11 升到 7.60, 中文理解从 6.52 升到 7.47, 角色扮演从 6.91 升到 7.83; 推理总分只从 5.75 到 5.77, 其中数学计算 5.71 升到 6.13, 逻辑推理却从 5.79 降到 5.41. 报告说 DPO 后「语言能力超过最新版 GPT-4」, 对应的是 7.60 对 gpt-4-0613 的 7.59, 差 0.01 分, 落在 GPT-4 评分的波动范围里. MT-Bench(Table 8)的分项同样有涨有跌: 推理从 8.00 升到 9.05, 抽取和角色扮演各涨近 1 分, 编程却从 7.35 降到 6.75. 两张表合起来, DPO 的收益集中在写作, 理解, 角色扮演这类偏好数据覆盖的维度, 编程和中文逻辑推理有回落, 和附录 Table 17 里 HumanEval, MATH 的小幅下降方向一致. 评测时的温度也按 AlignBench 官方设定对齐: 角色扮演, 写作, 开放问答用 0.7, 其余用 0.1.

### 4.2. 拿专用模型对照: 通用底座离代码和数学专家还差多少

附录 A.4 把 67B 和当时的代码, 数学专用模型放在一起. 代码侧(Table 15), 67B Base 的 HumanEval Python 42.7%, 低于 CodeLlama 34B 的 48.2%, 高于 13B 的 36.0%; 多语言 HumanEval 37.2%, MBPP 57.4% 反而高于 CodeLlama 34B 的 55.2%. 指令版 67B Chat 的 HumanEval 73.8%, 和 WizardCoder 34B 的 73.2% 相当. 报告强调 67B 见过的代码数据更少, 而且其他能力更全面. 这组对比说明, 通用语料加大量代码 SFT 能把代码分数推到专用模型附近, 但 Base 阶段的差距是实打实的, 要超过专用模型, 得在预训练里专门加代码数据.

数学侧(Table 16)分两种推理方式. 纯 CoT 下, 67B Chat 的 GSM8K 84.1%, MATH 32.6%, MGSM-zh 74.0%, CMath 80.3%, 都高于 MetaMath 70B(82.3%, 26.6%)和 WizardMath 70B. 用工具集成推理, 也就是让模型写程序算题, 67B Chat 的 GSM8K 到 86.7%, MATH 到 51.1%, 和 ToRA-Code 34B 的 50.8% 相当, 中文的 MGSM-zh 和 CMath 则大幅领先(76.4% 对 41.2%, 85.4% 对 53.4%). MATH 在写程序后从 32.6% 跳到 51.1%, 说明模型的瓶颈很大一部分在计算和符号操作上, 推理框架本身已经能搭起来. 这两张表几乎就是下一步的路线图: 代码数据补进预训练成了 DeepSeek-Coder, 数学语料和工具推理成了 DeepSeekMath.

## 5. 谱系位置: 留给后代的几样东西

报告自己列的局限很常规: 预训练后知识不再更新, 会编造, 第一版中文数据不够全, 中英以外的语言要谨慎. 结尾预告了代码报告和 MoE 报告, 也就是后来的 DeepSeek-Coder 和 DeepSeekMoE, 以及「下一版会显著加强推理, 中文知识, 数学和代码」的数据计划, 这条在 V2 的 8.1T 语料里落地. Scaling 部分的方法论背景可对照 [3.2.6-Scaling-Law](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.6-Scaling-Law/3.2.6-Scaling-Law.md).

从后代往回看, 这份报告留下的东西可以按训练链条排开. 数据端: 跨 dump 全局去重和 100K BBPE 分词器, V2 直接沿用分词器并扩大语料. 结构端: LLaMA 式 Dense 底座, 只在 67B 上用 GQA; V2 把注意力换成 MLA, FFN 换成 DeepSeekMoE, 这是家族第一次在结构上离开 LLaMA. 预训练端: multi-step 学习率(V2 叫 warmup-and-step-decay), HAI-LLM 框架, 超参随算力的幂律. 后训练端: SFT 加 DPO 的两段式, 以及对重复率的关注; 半年后 DeepSeekMath 用 **GRPO** 替掉了 DPO 的位置. 评测端: 困惑度与生成两套协议, BPB 比较 Pile-test, 保留集查过拟合, 刻意排除选择题数据. 这份 Dense 7B/67B 本身的榜单成绩很快被超过, 但它定下的做事方式在后面每一代报告里都还能看到.
