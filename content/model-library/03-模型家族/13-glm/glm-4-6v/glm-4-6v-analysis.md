# GLM-4.6V 博客: 两个型号和一张 34 行的表

来源是同目录 `glm-4-6v.md`, 页标记从 `page 1 of 10` 到 `page 10 of 10`, 6 张图. 逐段对照在 `glm-4-6v-bi.md`. 工具调用, MCP 和视觉反馈回路只保留名称, 不复述步骤.

## 1. 这是博客, 引用指向的是上一篇论文

正文日期是 2025-12-08. 页脚 **© 2026** 是站点版权年, 不是这篇的发布日. Tech Report 按钮和文末 BibTeX 都指向 **arXiv:2507.01006**, 标题是 GLM-4.5V and GLM-4.1V-Thinking. 那篇论文的 v6 日期是 2026-01-01, 比这篇博客更晚改过一版, 但 eprint 号仍是 4.5V 那一篇. 博客请读者引用的就是这篇, 不是一份单独的 4.6V 报告.

因此 4.6V 的结构不能从那篇论文的训练配置往回填. 博客自己只印了两个名字和两个规模标签: **GLM-4.6V (106B)** 写成表头 **106B (A12B)**, **GLM-4.6V-Flash** 写成 9B. 106 和 12 同时出现, 是两个数. 层数, 专家数, 学习率, 持续预训练的步数, 博客都没有.

## 2. 128K 是窗口, 不是评测长度

第 1 页说训练时把上下文窗口扩到 128k token. 第 5 页又说视觉编码器与 128K 对齐, 并给出三个约数: 约 150 页复杂文档, 200 页幻灯片, 一小时视频. 这三个约数没有换算公式, 也没有对应的基准行.

第 7 页长上下文只有三行. **MMLongBench-Doc** 上 4.6V 是 54.9, 4.5V 是 44.7, Flash 是 53.0. **MMLongBench-128K** 上 4.6V 是 64.1, Flash 是 63.4, Qwen3-VL-235B 是 61.8, 4.5V 和 4.1V 印的是 「/」.**LVBench** 上 4.6V 是 59.5, 低于 Qwen3-VL-235B 的 63.6, 高于 4.5V 的 53.8. 视频那一段的足球比赛例子没有单独分数.

## 3. 和 4.5V 比, 不是行行都涨

4.6V 和 4.5V 的列头都是 **106B (A12B)**, 这是表里唯一一对同标签的前后代. 智能体区块里, **AndroidWorld** 两边都是 57.0. **WebVoyager** 是 81.0 对 84.4, 4.6V 更低.**Webquest-MultiQA** 是 59.0 对 60.6, 也更低, 而且还低于 Qwen3-VL-8B 的 60.3. 定位区块里 **RefCOCO-avg (val)** 是 88.6 对 91.3, **Ref-L4-test** 是 88.9 对 89.5. **OCRBench** 两边都是 86.5.

涨得明显的一行是 **MMLongBench-Doc**, 54.9 对 44.7. **Design2Code** 是 88.6 对 82.2, **Flame-React-Eval** 是 86.3 对 82.5, **OSWorld** 是 37.2 对 35.8. 这些是同表同列头下的差, 不是从 4.5V 论文抄来的.

## 4. 「相近规模 SoTA」 和 「表里最高」 不是一句话

博客说在 20 多个基准上评测, 表实际有 34 行数据. 点名的 MMBench, MathVista, OCRBench 只是其中三行. 和 106B 规模相同的开源对照就是 4.5V. Qwen3-VL-235B-A22B 的标签是 **235B (A22B)**, Step3 是 **321B (A38B)**, 都更大.

即便在全表里找最高分, 4.6V 也不是每一行第一. **Design2Code** 上 Qwen 235B 是 93.4, 高于 88.6. **MMStar** 是 78.7 对 75.9. **MathVista** 是 85.8 对 85.2. **OCRBench** 是 87.5 对 86.5, Kimi-VL 是 86.9, 也高于 4.6V.**MMMU (Val)** 是 80.6 对 76.0. 带星号的格子源表没有脚注, 不能当成和未标星的格子同一套复现条件.

## 5. Flash 9B 有两格不低于 106B

Flash 的多数行更低, 例如 **DynaMath** 43.7 对 54.5, **Design2Code** 69.8 对 88.6, **OSWorld** 21.1 对 37.2, **LVBench** 49.5 对 59.5. 但 **AI2D** 上 Flash 是 89.2, 106B 是 88.8, 和 Qwen 235B 的 89.2 相同.**BLINK (Val)** 两边都是 65.5. 9B 和 106B 不能按一个固定折扣来读.

4.1V-9B-Thinking 也是 9B, 和 Flash 同写 9B, 但不是同一个模型. Flash 在表里几乎每一行都高于 4.1V, 例如 MMBench V1.1 是 86.9 对 85.8, MMMU 是 71.1 对 68.0. 同写 9B 仍要带上 4.6V-Flash 和 4.1V-Thinking 两个全名.

## 6. 链接, 图和入口名称

「Call it」 指向 `docs.z.ai/guides/llm/glm-4.6`, 路径是不带 V 的 4.6. HuggingFace 模型页是 `zai-org/GLM-4.6V`, 第 9 页权重合集又是 `zai-org/glm-46v`. 第 8 页聊天入口写成在 Z.ai 里选择 **GLM-4.6**. 三个地址, 两个产品名, 博客没有对照表.

六张图里, `p03`, `p04`, `p05` 的文件名来自三节标题. 第 6 页有两张: 一张文件名来自视频理解那段英文, 一张来自 Overall Performance. 成绩表在第 7 页, 不在这两张图里. `p09-legal.png` 在隐私政策链接旁边, 是页脚, 不是柱状图.

## 7. 技术节能核对的只有窗口和数据量级

架构节只重复了 128K 和持续预训练, 并点名 Glyph. 世界知识节只说十亿级多模态数据, 没有提升点数. MCP 扩展只留下两个名称: 用 URL 标识多模态内容, 以及草稿, 选图, 终稿. 强化学习节只说把工具调用写进目标, 并提到 UI2Code^N 的视觉反馈回路. 这些都没有公式和分数, 所以不能和表 7 的某一行相减.

本地部署点名 vLLM 和 SGLang, 没有吞吐数字. API 只说与 OpenAI 兼容, 没有价格. 前端那一节说缩短了从设计到代码的周期, 也没有给出缩短的比例. 能和前端对上的分数仍是表里的 **Design2Code 88.6** 和 **Flame-React-Eval 86.3**.
