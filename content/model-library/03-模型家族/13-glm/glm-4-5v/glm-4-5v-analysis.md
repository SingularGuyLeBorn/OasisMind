# GLM-4.5V 与 GLM-4.1V-Thinking：一个视觉编码器，两种底座，一套课程采样强化学习

来源：同目录 `glm-4-5v.md`（arXiv:2507.01006v6, 2026-01-01，页标记 `page 1 of 42` 到 `page 42 of 42`）。逐段对照译文和 20 条疑点见 `glm-4-5v-bi.md`。下文的页码都指这份源文；凡是只在同目录 `glm-4-5v.pdf` 里出现，md 没有抓到的内容，都注明 「PDF 里」。文中带 「我算」 字样的数字是按原文数字推出来的，原文没有直接写。

## 1. 这份报告写的是哪几个模型

报告标题只有 GLM-4.5V 和 GLM-4.1V-Thinking，正文却覆盖三代五个名字。GLM-4.1V-9B-Thinking 是 9B 稠密模型，语言部分用 GLM-4-9B-0414，定位是纯思考模型；同一底座还放出了预训练基座 GLM-4.1V-9B-Base. GLM-4.5V 是 106B-A12B 的 MoE 模型，总参数 106B，激活参数 12B，语言部分用 GLM-4.5-Air，同时支持思考和非思考两种模式。v6 又加进两个更新版：GLM-4.6V-Flash（9B，底座同 4.1V）和 GLM-4.6V（106B-A12B，底座同 4.5V），摘要说 4.6V 系列原生支持工具调用，上下文窗口长度 128K. 第 3 页第 2 节把五者的关系写成两条线：9B 线用 GLM-4-9B-0414, 106B 线用 GLM-4.5-Air，视觉编码器都从 AIMv2-Huge 初始化。

版本信息要看第 1 页页眉：「arXiv:2507.01006v6 [cs.CV] 1 Jan 2026」。编号 2507 说明第一版在 2025 年 7 月，当前是第 6 版，日期 2026 年 1 月 1 日。4.6V 在正文里一直以 「updated versions」 和 「for completeness」 的身份出现，第 41 页附录 B 的评测协议只点了 4.1V 和 4.5V，标题也没改。读这份报告要记住，表 2 里 4.6V 那一列是 106B 版本，4.6V-Flash 在全文任何表格里都没有分数。这里的 4.6V 是视觉语言模型，与家族里的纯文本 GLM-4.6 不是同一个东西，本文也没有讨论后者。

## 2. 架构：编码器，投影器，解码器

第 3 页和第 4 页图 2 给出的结构很朴素：ViT 编码器，MLP 投影器，语言解码器三段。改动集中在位置信息上。视觉侧有三处：一是仿照 Qwen2-VL 把 2D 卷积换成 3D 卷积，视频在时间维上做 2 倍下采样，单张图复制成两帧走同一路径；二是在 ViT 自注意力里加 2D-RoPE，让宽高比超过 200:1，分辨率超过 4K 的图也能处理；三是保留 AIMv2 原有的可学习绝对位置嵌入，用式 1 把 patch 坐标归一化到 [−1, 1]，再用式 2 的双三次插值从原嵌入表里取值，这样任意网格大小都能对上预训练时的位置表。语言侧把 RoPE 扩成 3D-RoPE，作者说这样能增强空间理解又不伤文本能力，但文中没有给消融数字。

视频的时间信息靠显式 token 表达：每一帧的 token 后面插一个时间索引 token，内容是把时间戳编码成字符串。图 2 里视频段中间标着 0, 2, 4, 6 的灰色方块就是这些索引。图 2 还给了三组 token 数，可以用来粗估每个 token 对应多少像素。我算：Image 2 是 2548 乘 1596，共 4,066,608 像素，对应 5187 个 token，正好每个 token 784 像素，即 28 乘 28；Image 1 是 952 乘 1274，对应 1574 个 token，每个约 771 像素，和 784 接近。视频 980 乘 546 一帧约 535,080 像素，按 784 像素一个 token 算约 683 个，13650 个 token 大约是 20 组。原文没有写 patch 大小，帧率和合并方式，这组推算只能说明 「28 乘 28 像素一个 token」 和图 2 的数字自洽。

这套位置方案有一个取舍值得说明。2D-RoPE 负责任意宽高比下的相对位置，可学习的绝对位置嵌入负责保住 AIMv2 预训练时学到的东西，两者同时存在，后者靠插值适配新网格。作者的理由写在第 3 页：保留绝对位置嵌入是为了 「preserve the foundational capabilities of the pre-trained ViT」。代价是每换一种分辨率都要插值一次，极端宽高比时插值出来的位置表会被拉得很细长，这部分效果原文没有单独评估。时间维度则完全交给文本形式的时间戳 token，好处是模型能直接读到 「第几秒」，视频定位和问答可以引用真实时间；坏处是每帧多占一个 token，帧数多时这部分开销会跟着涨。图 2 的例子里，两张图加一段 20 秒视频已经用掉两万多个 token，这也解释了为什么评测设置里给视频留了 48,000 token 的输入上限。

## 3. 预训练数据与两阶段训练

第 5 到 7 页的 3.1 节按数据类型列了六类语料，数字都很具体。图像标题数据从超过 100 亿个图文对起步，依次做规则过滤，CLIP-Score 阈值 0.3 的相关性过滤，仿 MetaCLIP 的概念均衡重采样，最后用迭代训练的 recaption 模型改写标题，图 4 给了两个例子，一个英文红雀，一个中文山村。图文交错数据分两路：网页来自 MINT，MMC4，OmniCorpus，用 CLIP-Score 去掉无关图，用分类器去掉广告和二维码，再用 「高知识密度」 分类器挑学术图表和示意图；书籍收集了超过 1 亿本数字化书籍，先按 STEM 等领域筛选再做 PDF 深度解析。OCR 数据 2.2 亿张图，由合成文档，Paddle-OCR 标注的自然场景文字，仿 Nougat 的 arXiv 页面三部分组成。定位数据有 4000 万条自然图像标注（LAION-115M 加 GLIPv2）和超过 1.4 亿个 GUI 指代问答对（CommonCrawl 截图加 Playwright 解析 DOM）。视频数据强调人工细粒度标注，包括运镜和构图。指令微调数据共 5000 万条，做了人工加自动的污染检查。

3.2 节的训练配方分两段。多模态预训练用 8,192 的序列长度，1,536 的全局批大小，训练 120,000 步，不含视频；9B 模型张量并行 2, 106B 模型专家并行 8，流水线并行 4，MoE 路由用无损失方案，偏置更新率 1e-3，另加系数 1e-4 的序列级均衡损失。长上下文继续训练把序列拉到 32,768，加上下文并行 4，再训 10,000 步；4.6V 额外训 2,000 步，批大小 128，窗口扩到 131,072，也就是摘要里的 128K. 我算这三段的 token 容量上限：8,192 乘 1,536 乘 120,000 约 1.51 万亿；32,768 乘 1,536 乘 10,000 约 5030 亿；131,072 乘 128 乘 2,000 约 336 亿。这是按 「打包后接近满长」 估的序列位数，实际有效 token 会少一些，原文没有给总 token 数。

第 4 页图 3 用来论证 「基座决定上限」：在 MathVista 非选择题子集上，GLM-4.1V-9B-Base 的 pass@k 从 k=1 的约 0.615 升到 k=64 的约 0.935，同规模的 InternVL3-9B-Pretrain 从约 0.54 升到约 0.848，每个 k 上都更低。这张图只比了一个子集，一个对手，能说明的是这个 9B 基座在这类题上采样多次后能覆盖更多正确答案，为后面的 RL 留出空间；106B 线的基座没有对应的图。

## 4. 监督微调：长 CoT 冷启动和输出格式

第 7 页第 4 节对 SFT 的定位很明确：它不负责注入知识，只负责把已有的视觉语言理解对齐到更好的思考和回答风格，为 RL 做冷启动。以往流程先做一轮短 CoT 的 SFT，本文省掉这一步，直接做长 CoT。数据以可验证任务为主，也放一些开放式问答；以中英文为主；用预训练模型滤掉太易和太难的题。清洗时强制格式正确，去掉中英混杂和冗余重复的思路，还会把 RL 检查点里采到的好样例回灌进冷启动集。训练用全参数微调，序列 32,768（4.6V 为 131,072），批大小 32，另混入纯文本的长样例保住语言能力。

格式约定是后面奖励系统的前提。回答分 think 和 answer 两段，可验证任务的最终答案必须放在 <|begin_of_box|> 和 <|end_of_box|> 之间，且只能有一个框；这些标签都作为特殊 token 加进了词表。GLM-4.5V 的回答去掉了 answer 标签。GLM-4.6V 的工具调用用 XML 风格：tool_call 里写函数名，每个参数拆成 arg_key 和 arg_value 一对，工具定义放在 system prompt。非思考模式靠在用户 prompt 末尾加 /nothink，让模型输出空的思考内容；作者发现直接拿思考样例的 answer 部分当非思考数据，比单独整理一个子集效果好。第 9 页还有一个有意思的观察：冷启动数据有噪声时 RL 仍然有效，只是干净数据收敛更稳，最终分数更高。

## 5. 奖励系统：一个弱验证器能拖垮全部

第 9 到 12 页的 5.2 节是这份报告写得最细的部分。系统同时支持 RLVR 和 RLHF: RLVR 先抽出答案片段再和参考答案比，给 0/1 或连续奖励；RLHF 直接用奖励模型给答案段打分。答案抽取放弃了 LLM 抽取，改为要求模型用框 token 标出最终答案，理由是多模态开放领域里答案形式太杂，LLM 抽取常出错，答案段过长或循环时更抽不准；又因为 GUI 任务的答案是复杂的函数调用，常见的 \boxed{} 容易解析出歧义，所以另设了专用 token。

图 5 用一个反例说明为什么每个领域都要有好验证器。STEM 验证器调得很好，other-single-image 和 other-multi-image 两个验证器没调好：前者奖励一路涨到约 0.91，准确率却没跟上；后者在 210 步左右突然冲到约 0.92，是典型的奖励投机。结果 STEM 自己的奖励在 180 步后停在 0.72 到 0.78 之间，四条评测曲线 MMStar，MathVista，AI2D，MMMU_Val 全部在后段下跌，MathVista 从约 75.3 跌到约 63.5。第 11 页还举了两个被钻空子的回答：计数题答 「0 到 10 之间的一个正确数字」，相对论题答 「一个非常接近光速的速度」，都骗过了一些基于 LLM 的奖励模型。

对应的做法是按领域拆验证器，共享格式校验，框内容提取，精确匹配等通用函数，每个领域有自己的子模块和单元测试。第 12 页表 1 列了 12 个领域的规则。数学用 Sympy 带容差做数值匹配；物理和化学带单位时交给 LLM 评判；图表数值同数学但年份除外；OCR 用归一化编辑距离，奖励 = 1 − d_edit / max(|ans|, |gt|)，md 把这里的分数线丢了，要以 PDF 为准；定位的奖励是 IoU 大于 τ 的框占总框数的比例；GUI 智能体按动作加 IoU 判。另外还有格式和风格两道检查：不可验证数据的 answer 里出现框 token 给最低奖励，大段中英混杂或重复文字给低奖励，再由文本奖励模型评指令遵循和流畅度。「43」 和 「43.0」 在数学里相等，在 OCR 里不等，这个例子把 「验证器要跟着任务走」 说得很清楚。

从表 1 还能看出规则和模型的分工。12 个领域里，只靠规则的是 OCR 和视觉定位，这两类答案有明确的数学度量（编辑距离和 IoU）；只靠模型的是长文档和空间推理两类，前者答案是自由文本，后者虽然先试精确匹配，表里却只勾了模型和二值两列；其余八个领域规则和模型都用上。连续奖励只出现在 OCR 和定位，其他领域大多是二值。作者说这套奖励系统已经开源在 GitHub 仓库里，本文只给了设计原则，没有给每个领域的评判 prompt 和阈值，例如图表数值的相对容差，定位的 IoU 阈值 τ 都没有具体数字。

## 6. RLCS：在线挑中等难度的题

5.3 节的出发点是 GRPO 的一个性质：一组 rollout 全对或全错时，组内优势为零，没有梯度。作者的试点实验里，仅 200 步后就有一半以上的 prompt 准确率超过 90%，而训练时间大头花在 rollout 上，所以必须把 rollout 花在有信息量的题上。RLCS 的做法是离线和在线两套难度标签合并使用：训练前用几个现成模型或早期 RL 检查点在全量数据上跑 pass@k，再结合专家标注，把数据分成从非常容易到非常难的若干档；训练中记录每次 rollout 的 pass@k，映射到难度档并与离线标签合并。然后按训练迭代的粒度重新分配各难度档的采样比例，压低太易和暂时太难的题，多给中等难度的题。作者只给了 「显著加快提升」 的定性结论，没有 RLCS 与均匀采样的对照数字。

围绕 RLCS 的几项技巧都能在第 13 到 14 页找到。动态采样扩充按 expansion_ratio = 1/(1 − not_valid_sample_rate) 过采样，上一轮一半样本无效就按 2 倍采，再用 EMA 平滑，然后挑正确和错误数量最接近的子集；与 DAPO 的做法相比，好处是总样本数事先确定，方便并行。强制作答在思考超长时插入 </think>，让模型给出答案再按答案给奖励，作者说这让模型学会在任意长度的思考后作答，便于在 TestingTime 动态控制思考预算。去掉 KL 损失，因为 VLM 的 KL 上升更快，压住它会限制能力；去掉熵损失，因为它会引出乱码直至崩溃；采用 clip-higher 提高重要性采样比的裁剪上界；rollout 用 top-p = 1，作者推测完整词表覆盖能避免罕见 token 学习不足；损失按样本平均比按 token 平均更稳；批大小尽量大。这些结论都来自作者自己的实验观察，文中没有列出对照曲线。

还有两条观察值得记下。其一，冷启动从 1,000 步加到 2,000 步，冷启动后平均分高约两个点，但 RL 之后两者收敛到几乎相同的水平，作者据此认为冷启动分数高不代表 RL 潜力大。其二，RL 中的领域干扰比 SFT 小，没训练的正交领域能保持得不错，还常见跨领域迁移，这一点在第 6.3 节有专门实验。第 14 页的稳定性清单里，冷启动数据质量排第一，格式问题要在冷启动阶段解决，不要指望 RL 的格式奖励去纠正。

## 7. 基础设施：把长短不一的样本塞满

5.4 节讲的是 RL 训练侧的四项优化，目标都是应对 「rollout 长度事先不知道」 这件事。第一项在 rollout 之后，分配训练样本之前，按序列长度和计算量在 DP rank 之间做负载均衡，免得某个 rank 分到一堆视频或长文档，拖慢所有人。第二项在 rank 内部把序列打包和梯度累积结合：每个优化步分成若干微步，每个微步把几条样本打包成 32K 长的定长序列，不足补齐，最后按样本数加权平均各微步梯度，数学上等价于整批一次算完。

第三项是在上一项基础上重新打包样本，用尽量少的微步跑完所有样本，作者说这让前向反向时间减半，这是这一节唯一给出的量化收益。第四项把 5.3.1 的动态采样扩充再列一次，强调样本数可以预先算好，方便并行 rollout。这一节没有给硬件规模，训练时长和 rollout 与训练的时间占比，想估算 RL 阶段的算力，本文给不出依据。

## 8. 评测表怎么读

评测设置在第 16 页：推理大多用 vLLM，视频用 SGLang；单条回答最多 8,192 token；图像输入预期上限 6,144 token，视频 48,000 token；答案取框 token 里的字符串；需要语言模型抽取或打分的基准一律用 GPT-4o (2024-11-20)；每个模型在每个基准上的请求成功率不得低于 95%，失败样本不计分。最后这条值得留意：失败样本被剔除，不是按零分计，成功率接近 95% 的模型分数会偏乐观，原文没有公布各模型的实际成功率。

第 15 页表 2 是全文的主表。它有 42 行，八个类别，三列 GLM 并排，对手是 Step-3（321B-A38B，思考），Qwen2.5-VL（72B，非思考），Kimi-VL-2506（16B-A3B，思考），Gemma-3（27B，非思考），对手的分数大多带 「\*」，是作者复现的。所谓 「42 个公开基准」 数的是表 2 的行：6.1 节的清单只有 39 个名字，MMBench 分英文和 CN，Webquest 分 SingleQA 和 MultiQA，VideoMME 分有无字幕，各拆成两行。按表 2 严格比大小，GLM-4.5V 在 42 行里只有 OCRBench 输给 Kimi-VL（86.5 对 86.9），摘要说 「nearly all」 是准确的，6.2 节说 「across all benchmarks」 说过了头。GLM-4.6V 在 GeoBench 上没有分数，其余 41 行里有 27 行高于 4.5V，2 行持平，12 行更低，主要落后在视觉定位（RefCOCO-avg 88.6 对 91.3），HallusionBench（62.3 对 65.4）和 MathVision（63.5 对 65.6）；领先幅度最大的是 MMLongBench-Doc（54.9 对 44.7）和 Design2Code（88.6 对 82.2）。

## 11. 作者承认的局限

第 18 到 19 页的讨论列了三条局限。第一，奖励只看结果不看过程，RL 提高了完成率却不一定提高推理质量，有时答案对而推理步骤错，这类有缺陷甚至带幻觉的推理链只要通向正确答案就会被强化。第二，RL 训练对设置很敏感，早期小改动会让推理深度和输出风格大幅变化，后来靠更好的奖励设计和冷启动数据稳住了，但作者认为深层问题还在。第三，画面杂乱，遮挡，细节含糊时感知出错，推理会退化成猜测，所以感知和推理要一起改进。

展望部分给了三个方向：奖励模型要评估中间步骤，主动识别幻觉和逻辑矛盾，主观任务上要防奖励投机；研究多模态训练能否反过来帮助纯文本推理，例如看图读代码能否提升纯文本编程；评测基准要更难，更有诊断性，能发现走捷径和推理链幻觉。结合前面的核对，还可以补一句本文内部可见的问题：部分宣传数字（29/42, 22 个基准，约 10%）与 v6 的表格对不上或无法复核，引用时应以表 2 和表 3 的原始数字为准，并写明出自哪张表。
