# Olmo 3: 为长推理重排的全开放模型流

来源: 同目录 `olmo-3.md` (arXiv:2512.13961v2, *Olmo 3*, 118 页), 对照译稿 `olmo-3-bi.md`. 下文数字以源文 Table 1–55, Figure 1–43 与正文各节为准; 标了 「心算」 或 「读图」 的是估算.

## 1. 定位与架构

### 1.1. 谱系坐标: 从 「训得稳」 走到 「为推理而训」

OLMo 2 解决的是全开放 dense 模型能不能稳定训完, 以及退火和 RLVR 能不能把它推到开权重的竞争带. Olmo 3 的骨架几乎原样继承: 仍是 dense 的 7B / 32B, Table 33 里 QK-Norm, 作用在子层输出上的 RMSNorm, z-loss 权重 10⁻⁵, embedding 不做 weight decay, RoPE θ = 5×10⁵ 都与上一代一致, 层数 32 / 64, 32B 继续用 40/8 的 GQA. 变化集中在一个方向上: 整条流水线都在为长推理让路. 预训练上下文从 4096 提到 8192 并引入 **sliding window attention (SWA)**, midtraining 提前混入 thinking trace, RL 的 rollout 上限拉到 32K. 这三处分属架构, 数据和后训练, 目标是同一个.

报告把交付物叫作 **model flow**. Base 经三段训练 (预训练, midtraining, 长上下文扩展) 后分成三条线: Think 先写推理过程再作答, Instruct 不产中间思考, 追求短而快并支持 function calling, RL-Zero 从 Base 直接做 RLVR, 用来研究预训练数据怎样影响强化学习. 每个阶段的数据, 检查点和代码都公开, Figure 1 用这一点把 Olmo, Marin, Apertus 与只放最终权重的开权重模型分成两栏. 对这一代来说, 开放不只是姿态: RL-Zero 能否说明问题, 取决于别人能否查到底座见过什么数据, 这一点在第 4.2 节会再出现.

旗舰数字在 Table 1. Olmo 3.1 Think 32B 的 MATH 96.2, AIME 2025 78.1, LiveCodeBench v3 83.3, IFBench 68.1; 同表 Qwen 3 32B 分别是 95.4 / 70.9 / 90.2 / 37.3, Qwen 3 VL 32B Thinking 是 96.7 / 78.8 / 84.8 / 55.1. 数学和精确指令遵循已经追平或超过, 知识类仍落后: MMLU 86.4 对 88.8, GPQA 57.5 对 67.3, ZebraLogic 80.1 对 88.3. 报告称训练 token 约少 6x. 在 7B 档, 作者把知识类落后于 Qwen 3 归因于后者从自家最大模型蒸馏而来, 这是作者的推测, 没有对照实验.

同表 OLMo 2 Instruct 32B 一列可以说明代际差距来自哪里: MATH 49.2, AIME 2025 0.9, IFBench 36.4. 两代的注意力主体, 归一化和优化器几乎不变, 差距主要落在数据配比, midtraining 的推理原料和长 RL 上. 读 Olmo 3 的架构改动时要记住这一点: SWA 的主要用途是让 8K 预训练和 32K 生成付得起算力, 本身不是分数的主要来源.

### 1.2. 注意力怎样为 8K 预训练和 65K 推理让路

§3.2 的 SWA 设定很简单: 每个 token 只看前面 4096 个位置, 每四层里三层用 SWA, 并保证最后一层始终是 full attention. 作者给的理由有两条, 一是让更长序列的预训练可扩展, 二是控制推理成本. 窗口外的信息只能经由 full attention 层或多层堆叠间接传递, 所以全局层的位置 (每四层一层, 且末层必为全局) 决定了远距离依赖的通路. 更系统的高效注意力背景见 [2.3.4-高效注意力全景综述](../../../../llm-guide/2-核心原理与架构/2.3-高效与稀疏注意力/2.3.4-高效注意力全景综述/2.3.4-高效注意力全景综述.md).

信息能传多远可以按层心算. 报告只写了比例和末层约束, 按最自然的排法, 每个四层块是三层 SWA 接一层 full attention. 一层 SWA 让位置 $t$ 读到 $[t-4095,t]$, 信息每过一层最多向后挪 4095 个位置, 连续三层 SWA 最远把位置 $s$ 的内容送到 $s+12285$ 附近 (心算 3 × 4095). 预训练序列只有 8192, 一个块里的三层 SWA 已经能覆盖整条序列, full attention 层在 8K 下提供的是一跳直达. 到 65536 情况就变了: 相距超过约 12K 的两个位置, 在同一个四层块里只能经那一层 full attention 连通. 完全绕开 full attention 也不是不可能, 但需要约 16 层 SWA 首尾接力 (心算 65535 / 4095), 7B 共 24 层 SWA, 32B 共 48 层, 路径在结构上存在, 每一跳却都要把信息恰好搬到窗口边缘, 报告没有讨论这条路是否被用到. **末层固定为 full attention** 的作用落在这里: 最后一层产出 logits 前, 每个位置都能一步读到全部上文, 不依赖前面各层的接力.

推理侧的收益可以按缓存长度估一下. 在 65536 上下文下, full 层要缓存全部位置, SWA 层最多缓存 4096 个, 总 KV 缓存约为全层 full attention 的 29.7% (心算 1/4 + 3/4 × 4096/65536); 在 8192 上下文下约为 62.5%. 32B 再叠加 GQA 的 40/8, 每层缓存再降到同宽 MHA 的 1/5. 报告没有给推理显存或延迟的实测, 这两个比例只是按结构推算, GQA 本身见 [03-GQA-在性能与缓存之间折中](../../../../llm-guide/2-核心原理与架构/2.2-基础注意力机制/2.2.2-多头注意力变体/03-GQA-在性能与缓存之间折中/03-GQA-在性能与缓存之间折中.md).

训练侧, OLMo-core 在序列长 8192, 全程 bfloat16 下, 7B 达到每卡 7700 token/s, 32B 1960 token/s, 约合 43% 与 41% MFU. 手段包括 `torch.compile()`, 自定义 attention 与 LM head kernel, 异步批量收集指标和异步写检查点. Table 34 还给出分阶段吞吐: 7B midtraining 用 128 卡跑到 8.5K, 长上下文阶段用 256 卡, 8 路 **context parallelism** 让每张卡处理每条样本的 8K token, 吞吐降到 4.0K; 32B 三段分别是 2.0K / 2.0K / 1.3K. 作者采用基于 all-gather 的 CP 注意力, 理由是它容易支持 SWA 和文档内掩码这类不规则 mask.

扩展到 65536 时, RoPE 怎么改是一个真正的选择. §3.6.4 试了调整基频, position interpolation 和 YaRN, 每种方法又分 「作用于全部 RoPE」 与 「只作用于 full attention 层的 RoPE」 两种, 结论是 **YaRN 只打在 full attention 层上最好** (Figure 13a). 一种解读是: SWA 层看到的相对距离永远不超过 4096, 预训练时早已见过, 改它们的频率只会扰动已学好的局部模式, 真正需要外推的只有全局层. 报告没有给这层机制的消融, YaRN 本身见 [03-长度外推：从PI到YaRN的频率扩展](../../../../llm-guide/2-核心原理与架构/2.5-长上下文与外推技术/RoPE/03-长度外推：从PI到YaRN的频率扩展.md).

这套设计的代价在 Table 12 的长端. RULER 4K 上, Olmo 3 32B 为 96.10, 是 32B 档最高; 到 65K 降到 79.70, 低于 Mistral Small 3.1 24B 的 88.80 与 Gemma 3 27B 的 84.59. 7B 档更明显: 65K 为 67.96, Llama 3.1 8B 为 86.88, Nemotron Nano 9B 为 85.13. 未参与开发的 HELMET 上, 32B 在 65K 为 43.15, Gemma 3 27B 为 48.60. 短上下文不吃亏, 长端还有缺口, 这与第 2.4 节 「扩展阶段短」 的配方一致.

## 2. Base 的三段训练

### 2.1. 从 9T 池到 6T mix: 数据分配怎样服务后面的阶段

Dolma 3 的预训练池约 9T 清洗 token, 最终训练 mix 约 6T, 另有供低算力实验的 150B 采样 mix (Table 4). 7B 的余弦日程按 5.93T 一个 epoch 设计, 32B 同样按 5.93T 设计但截在 5.5T, 峰值学习率 7B 为 3.0×10⁻⁴, 32B 为 6.0×10⁻⁴, batch 分别是 4M 与 8M token (Table 35). 预训练吃掉整体算力的 90% 以上, 所以作者给数据定了两条原则, 并在 mix 里做了明显的重分配.

重分配从 Table 4 能直接读出来. Common Crawl 在池里有 8.14T, 进 mix 只取 4.51T, 占 76.1%; olmOCR 解析的科学 PDF 池 972B, 取 805B, 占 13.6%; Stack-Edu 池只有 137B, 在 mix 里却占 409B (6.89%), 相当于重复约三遍. 网页被下采样, 代码和学术文本被上采样. 混合优化以逐任务回归预测的平均 bits-per-byte 为目标, 并约束任何域重复不超过约 4–7 次, 小域能拿到的比例由它的可用 token 数封顶.

网页清洗的规模在附录 A.2. 104 个 Common Crawl dump 线性化后是 252.6B 篇文档, DCLM 式启发式过滤加英文过滤后剩 38.7B 篇, 存活率 15.1%, 其中长度过滤一步就去掉 40.42%, 耗时最多的是内部重复检测 (占总时长 31.41%), 整步约 1030 个 i4i.32xlarge 小时, 约 $11,300. 去重分三级: 基于内容哈希的精确去重去掉 66% 文档, 剩 12.7B 篇; 再做 32 路分片的 MinHash 近重去重 (Jaccard 阈值 0.80); 最后用后缀数组去掉重复模板文本. 精确去重与 MinHash 由作者新写的 Rust 工具 Duplodocus 完成.

混合的两件工具值得分开看. **token-constrained mixing** 先用一批小代理模型扫比例 (报告称为 swarm), 再用条件混合把后到的 PDF 域接进已冻结的网页与代码比例, 不必每次重跑整批代理. **quality-aware upsampling** 则在主题比例定下之后, 用一条曲线决定每个质量分位的重复次数: Figure 10 的例子里, 质量最低的 40% 直接丢掉, 最高的 5% 重复 7 次. 网页先按 24 个主题与 20 个质量档切成格子, 两件工具分别在主题轴和质量轴上起作用.

上采样曲线有一套明确的定义. 设某个主题共有 $X$ 个 token, 按质量分成 $Q$ 个有序档, 第 $q$ 档有 $X_q$ 个; Olmix 规定这个主题取 $Z$ 个 token, 任何一档重复不超过 $M$ 次. 问题是找 $Z_q$ 使 $\sum_q Z_q=Z$ 且 $Z_q/X_q\le M$. 为了不在 $Q$ 维上直接搜, 作者把 「质量分位 $x\in[0,1]$ 到重复倍数」 的函数限定为截断幂指数族:

$$f_{p,\lambda}(x)=\begin{cases}0, & x<a\\ C(x-a)^{p}\,e^{\lambda(x-a)}, & x\ge a\end{cases}$$

$a$ 是丢弃线, 分位低于 $a$ 的数据一个 token 都不取; $(x-a)^p$ 决定刚过丢弃线时曲线抬得多快, $e^{\lambda(x-a)}$ 决定高分位的上翘, $C$ 是整体幅度. 三个参数由三条约束解出: $\int_0^1 f\,dx=Z/X$ 让总取量等于 Olmix 给的份额, 这个积分就是该主题的平均重复倍数, 2.0 表示平均取两遍; $\frac{1}{b}\int_{1-b}^{1}f\,dx\le M$ 让最高一档 (宽度 $b$) 不超过 $M$ 次, 曲线单调时最高档一定重复得最多; $\lambda\ge0$ 保证单调. 实现里每个 WebOrganizer 主题都取 **$M=7$, $a=0.40$**, 再数值求出可行的 $p,\lambda,C$; 第 $q$ 档覆盖分位 $[q^-,q^+]$ 时, 它的重复倍数取曲线在这一段的平均 $\frac{1}{q^+-q^-}\int_{q^-}^{q^+}f(x)\,dx$. Figure 10 的 「最低 40% 丢掉, 最高 5% 重复 7 次」 就是这组取值画出的一条曲线, $b$ 的具体数值报告没有写.

这套设计针对的是数据受限的局面: 高质量的独有 token 不够填满 6T, 重复次数就成了可调的旋钮. Table 39 的对照这样搭: 1B 模型训 100B token, 平坦过滤组从 20 个质量档里取最高的若干百分位, 并把重复倍数调到与 「从 4.51T 池里取数」 一致, 例如取前 10% 对应重复 5.6 次, 前 5% 对应 11.1 次; 上采样组用同一套方法, 只把目标池直接设成 100B. 平坦过滤在曲线图上是一个阶跃函数, 线以上同一倍数, 线以下为 0. 模型, 总 token 和候选池都不变, 变的只是各分位分到的重复次数. 结果上采样的 Code BPB 为 0.719, 四种平坦过滤里最好的是 0.880 (越低越好), QA 与 Math 也全面占优. Table 40 再比较主题配比与质量上采样怎样合成一个 (主题, 质量) 格子的取量: 只做配比时 Code 0.872, 只做上采样时 QA 与 Math 最差, 两者取算术或几何平均居中; 去掉 $(x-a)^p$ 只留指数的截断指数族, Code 与最终方案接近 (0.787 对 0.783), QA 与 Math 落后, 截断幂指数族三项都最低. 重复上限卡在 4–7 次, 与 「高质量数据重复几遍收益下降不明显」 的已有经验一致, 这一句是按数据受限 Scaling 文献的一般结论来读的, 报告本身只给了这个上限和 Table 39. Scaling Laws 背景见 [3.2.6-Scaling-Law](../../../../llm-guide/3-预训练/3.2-预训练全流程/3.2.6-Scaling-Law/3.2.6-Scaling-Law.md).

### 2.2. midtraining: 把推理的原料提前放进底座

Dolma 3 Dolmino Mix 共 100B token, 学习率线性衰减到 0. 选料方法分两层: 先用 microanneal 在单一来源上快速试, 典型做法是 5B 目标数据加 5B 网页, 与纯网页 10B 的基线比增量; 有希望的来源再收进 100B 的 integration test, 并接一小段 SFT 看底座的 「可后训练性」. 报告一共迭代了五轮候选 mix, Table 6 展示了其中三轮, 分数从第一轮到最后一轮全面上升.

几类新造的推理数据在 microanneal 里效果最明显. **meta-reasoning** 数据针对自我评估, 回溯, 逆向推理等七种认知能力, 用 GPT-4.1 和 o4-mini 生成思考过程, 相对强数学/代码基线让 Minerva Math 涨约 14 分, HumanEval 涨 14 分, MBPP 涨 20 分. 可程序验证的题目约 250M token (放在 5B 的 microanneal 里) 带来 1–2 分. OpenMathReasoning 的 Full-Thoughts 轻改写版共 850M token, 让 MATH 涨 5.5, GSM8K 涨 8.4. 已有的开源 thinking trace 经过滤后让 GSM8K 最多涨 8 分.

Table 10 回答了一个更根本的问题: 把后训练性质的数据 (指令和 thinking trace) 放进 midtraining, 会不会伤底座. 在总 token 不变的 100B integration test 里, 含这类数据的 mix 在每一列都更好: 平均 50.7 对 48.8, Math 48.7 对 43.1, FIM 31.9 对 29.2. 这些数据把底座的输出分布往 「分步作答」 推了一截, 后面的 RL 就有更长的推理可以放大. Figure 25 给了反面例子: 两个早期 midtrained 底座做 RL-Zero, 推理数据不足的那个回复长度始终不涨, 也学不会回溯和验证答案. **midtraining 在这里决定的是 RL 能走多远**.

格式细节也会反过来咬人. 作者在 Tulu 3 SFT 数据上做 microanneal, 发现 midtraining 数据里带 `<|im_start|>` 这类特殊 token 时, 底座推理时会把它们吐出来, GSM8K 从 49.43 掉到 0, CruxEval 从 32.89 掉到 18.91; 只保留聊天模板, 把特殊 token 换成普通文本, 分数是 46.02 与 29.65. 问题出在预训练没见过的新 embedding, 而不在模板本身. 最终指令数据去掉模板和特殊 token, 改用换行分隔, 特殊 token 留到 SFT 再引入.

单一来源常常此涨彼跌. Table 7 里偏数学/代码的 mix 在数学和代码上明显超过最终 mix, 但 MC 与 GenQA 掉分; 偏 GenQA 的 mix 反过来伤数学和代码. Table 8 的 Reddit-to-Flashcards 抬 MCQA, 伤数学; Table 9 的 meta-reasoning 抬数学代码, 伤生成式问答. 去污染对所有 split 下手, 因为部分开发基准会拿 train split 来降噪, 去掉后 DROP, Minerva, SQuAD 等明显掉分, 另一些几乎不动. 32B 的 midtraining 用两个数据顺序种子各跑一次再合并权重, 合并后 MC<sub>STEM</sub> 涨近 1 分, GenQA 0.4 分, Math 相对两次单跑分别 +2.9 与 +1.6; 这与 OLMo 2 的 soup 做法一脉相承.

### 2.3. 让小实验说真话: OlmoBaseEval 与去污染

上面每个数据决策都依赖小算力实验, 而小模型在数学, 代码和选择题上的分数接近随机, 分差容易被噪声淹没. §3.3 的对策有三件. 其一是**按能力聚类取宏平均**: 用约 23K 条开源模型的基准分数做 Ward 层次聚类, 再人工对齐成 MC<sub>STEM</sub>, MC<sub>Non-STEM</sub>, GenQA, Math, Code, Code FIM 六簇. 其二是用 OLMo 2 的一族 Scaling 模型找小算力下仍有信号的代理指标, 再拿约 70 个开权重模型检查高算力端是否饱和. 其三是提高信噪比: 加样本, 调 pass@k 的 n, 把 CruxEval 这类能力相关但噪声大的任务移出宏平均.

结果是两套套件: Base Easy 用 bits-per-byte 或排序式选择, 服务 1B 级消融; Base Main 在大尺度仍留有区分度, 服务 midtraining 实验. 后训练评测也按方差分桶: 14 个模型各跑 3 次, 取标准差均值, 例如 ZebraLogic 0.5638 归 「稳定」, MMLU 0.2219, PopQA 0.1554 归 「很稳定」. 开发 7B 配方期间, 评测消耗了 10%–20% 的算力. 读表里一两分的差距时, 先看该基准落在哪个方差桶.

去污染贯穿全流程. midtraining 数据对评测集的所有 split 去重; 后训练三阶段的数据按 Tülu 3 流程做 8-gram 匹配, 重叠阈值 0.5, 再用启发式压误报. 最后一道检查放在 RL-Zero: 用与回答质量无关的**随机二元奖励**训练底座 (Shao et al., 2025b 的协议), 如果预训练或 midtraining 见过评测题, 随机奖励也能把记住的答案 「激出来」. Figure 27 显示所有基准要么持平, 要么下降, 作者据此认为去污染有效. 这一步把数据, 评测和 RL 连在一起, 只有全开放的底座才能做.

Base 主结果 (Table 2) 与后面的 Think 表可以对照读. Olmo 3 Base 32B 的 Math 复合 61.9, 高于 Marin 32B 的 49.3, Apertus 70B 的 39.7 与 OLMo 2 32B 的 53.9, 接近 Qwen 2.5 32B 的 64.7; Code 复合 39.7, 高于 Marin 的 30.8, 低于 Qwen 2.5 的 48.3. 差距最大的是知识类选择题: MC<sub>STEM</sub> 74.5, Qwen 2.5 32B 为 82.2, MedQA 53.8 对 68.4. Think 表里 MMLU 与 GPQA 的落后, 在底座阶段就已经存在, 后训练没有补上.

### 2.4. 长上下文扩展: 短而专的一段训练

第三段训练的配方可以浓缩成几条: Longmino 长文档占 34%, midtraining 的高质量短数据占 66%; 7B 训 50B, 32B 训 100B; YaRN 只打在 full attention 层; 用文档打包加文档内掩码; 开发看 RULER, HELMET 留作未见套件. 长短配比来自一个 10B 扩展的早期实验: 长 66% / 短 34% 让 OlmoBaseEval 子集掉 2.5 分, 反过来的 34% / 66% 只掉 0.8 分. Figure 13e 显示扩展 token 越多, 长序列上的 RULER 越好, 于是 32B 的预算翻倍.

长文档的主力是 olmOCR 解析的科学 PDF: 超过 8K token 的文档约 22.3M 篇, 合计约 640B token; 超过 32K 的约 4.5M 篇, 约 380B token. 过滤用 gzip 可压缩性, 去掉最容易压缩和最难压缩的各 20%, 只留中间段. 作者也试了用 LongPpl 找依赖长程上下文的关键 token 来过滤, 几种切法都没有胜过 gzip, 最终没有采用. 长上下文的一般背景见 [2.5-长上下文与外推技术](../../../../llm-guide/2-核心原理与架构/2.5-长上下文与外推技术/2.5-长上下文与外推技术.md).

自然长文档很少提供 「跨全文汇总信息」 的监督, 作者因此往部分 PDF 里插入合成的聚合任务. 难点在于自举: 没有能读长文的模型, 怎么造长文数据. 他们的办法是先用文档统计量代替模型阅读: 取长度在 32768 到 65536 之间的文档, 切成 8K–32K 的分段, 用 tf-idf 找每段最显著的名词短语, 每个短语取 8 个片段, 再交给 OLMo 2 Instruct 32B 生成任务. 任务分两类: CWE 要求数出若干高频词在分段中出现的确切次数, REX 让模型按 12 种场景 (摘要, 师生对话, 抽认卡, 辩论等) 改写与某个短语相关的内容.

训练细节上有两处改动, 改的是不同的量. 预训练和 midtraining 用的是常规做法: 文档首尾拼接, 再按固定长度切块, 切口落在哪里与文档边界无关, 一篇 40K 的文档很可能被劈成两段分进两条 65K 序列, 任何一条样本里都看不到它的完整上下文. 作者指出这种做法到长上下文阶段会让训练样本平均比原文档短. **best-fit 文档打包** (Ding et al., 2024) 改的是切口: 把文档当作物品装进定长的序列, 每篇放进剩余空间最小但仍放得下的那条, 不超过序列长度的文档就不再被切开, 空隙用 padding 补 (装箱规则按 best-fit 的一般含义来读, 报告只写了 「减少被切开的文档, padding 几乎可忽略」). 它改变的是一篇文档在同一条样本里连续出现的长度, 对照拼接切块, 长上下文基准明显提升.

**文档内掩码**改的是注意力矩阵. 同一条序列里拼着几篇文档时, 位置 $t$ 只能注意同一文档里 $s\le t$ 的位置, 跨文档的块整体不可见. 它不改变样本里有哪些 token, 只改变每个 token 能看到的上文, 顺带让 RoPE 的相对距离不会跨越两篇无关文档. 两者互补: 只打包不掩码, 同序列里的无关文档仍会分走注意力, 作者称这会引入伪注意力模式并伤长程表现; 只掩码不打包, 无关文档被挡住了, 被切开的文档却仍只看得到自己的一截, 长程监督没有变多. 第 1.2 节提到的 all-gather 式 CP 注意力能直接支持滑窗与文档内掩码这类不规则掩码, 所以两者可以在 8 路 CP 下同时开.

32B 没有像 midtraining 那样多跑几个种子, 而是把扩展末尾三个检查点 (第 10,000, 11,000, 11,921 步) 平均成最终的长上下文底座. Table 11 还说明, 7B 的 50B mix 只用了 olmOCR 中 64K 以下的长度桶: 8K–16K 2.27B (4.55%), 16K–32K 1.85B (3.70%), 32K–64K 4.81B (9.63%); 64K–128K 桶在池里有 96.0B, 在 mix 里为空. 训练最长只到 65536, 更长的文档只作为池子公开. 把这一点和第 1.2 节的 Table 12 放在一起看: 扩展阶段只有 50B–100B, 且没用超长文档, 65K 端落后于扩展预算更大的模型是可以预期的.

## 3. Think 线的后训练

### 3.1. 模仿饱和之后: SFT 与 Delta Learning

Think 线的第一步是 Dolci Think SFT, 为多个领域构造带长推理过程的监督数据. 训练从 Open Instruct 搬到 OLMo-core, 吞吐提升 8×; 所有模型训两个 epoch 防过拟合. 32B 并行扫四个学习率, 每个 256 卡跑 36 小时, 再花约 12 小时评测, 合并和确认, 最终用 mergekit 把两个学习率的检查点线性合并. SFT 基础见 [4.2-SFT](../../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md).

第二步的发现是整份报告里最反直觉的一条 (Table 21). chosen 回复由 Qwen3 32B Thinking 生成, 它在该子集上的平均分 83.2; rejected 由 Qwen3 0.6B Thinking 生成, 平均 35.1. 开发中的 7B SFT 检查点平均 70.3. 直接在 chosen 上继续 SFT, 平均掉到 64.5, 每一项都降; 同样的 chosen 配上 rejected 做 DPO, 平均升到 72.9, AIME 2025 从 58.8 到 66.3, LiveCodeBench 从 67.0 到 72.6. 作者的解释是: 这些 chosen 相对模型在 SFT 阶段已见过的数据偏弱, 不再值得模仿, 但与更弱模型的回复配对后, 两者之差仍然指出了 「更好」 的方向.

从目标函数看, 这个现象有据可循. Think DPO 优化的是长度归一的 DPO 目标:

$$\max_{\pi_\theta}\ \mathbb{E}_{(x,y_c,y_r)\sim\mathcal{D}}\left[\log\sigma\left(\frac{\beta}{|y_c|}\log\frac{\pi_\theta(y_c\mid x)}{\pi_{\mathrm{ref}}(y_c\mid x)}-\frac{\beta}{|y_r|}\log\frac{\pi_\theta(y_r\mid x)}{\pi_{\mathrm{ref}}(y_r\mid x)}\right)\right]$$

$\pi_{\mathrm{ref}}$ 是起点的 SFT 模型, 两个对数比衡量策略相对起点把 chosen 与 rejected 各抬高或压低了多少; 除以长度 $|y|$ 把整条回复的对数比换成每 token 平均, 上万 token 的思考轨迹不会因为长就主导差值; $\beta$ 乘在隐式 KL 上, 控制策略离参考模型多远, Table 48 里三组训练都取 5. 记括号内为 $z$, 对参数求导得 $\beta(1-\sigma(z))\left[\frac{1}{|y_c|}\nabla\log\pi_\theta(y_c\mid x)-\frac{1}{|y_r|}\nabla\log\pi_\theta(y_r\mid x)\right]$ (按式推导). 梯度方向是两条回复平均对数似然梯度之差, 权重 $1-\sigma(z)$ 只看策略相对参考模型把两者拉开了多少, 与 chosen 的绝对质量无关.

所以 chosen 比当前策略弱也还有信号. 直接 SFT 时, $\nabla\log\pi(y_c)$ 整个被当作目标, Qwen3 32B 回复里不如 SFT 数据的部分也一并被模仿; 放进差值后, 两条回复共有的格式和常见推理步骤大体相互抵消, 剩下的主要是 32B 与 0.6B 之间的差别 (抵消这一层是解读, 报告只给了 Table 21 的结果). 这就是 Geng et al. (2025) 的 **Delta Learning** 假设: 偏好数据的质量主要取决于两者之差, 而非任一方单独的质量. 数据构造与此配套: chosen 经过主题过滤与模型身份过滤, rejected 完全不过滤, 作者认为答错的 rejected 也能给出有用的对比; 7B / 32B 分别用 150K / 200K 对, 只训 1 个 epoch, 学习率与数据量一起扫, 因为偏好调优存在与任务相关的最优停点, 过了会伤下游 (Figure 23). 作者还指出, 收益不只是把 pass@k 转成 pass@1, AIME 上的 pass@k 也提高了 (Figure 20), 推理能力的上界在扩大. DPO 见 [01-DPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.2-无奖励模型的对齐DPO-KTO/01-DPO/01-DPO.md).

代价同样在 Table 21 里: IFEval 从 79.7 降到 75.2, MMLU 从 76.1 降到 75.5. 32B 的 Table 14 呈现同样的形状: SFT 到 DPO, AIME 2025 66.2 → 70.7, LiveCodeBench 75.8 → 81.9, AlpacaEval 69.1 → 78.6, 但 IFEval 83.9 → 80.6, IFBench 37.0 → 34.4. DPO 抬高推理和聊天, 顺手伤了精确指令遵循, 这个缺口留给 RL 去补.

Table 22 进一步比较了 RL 的起点 (7B, RLVR 各训 1000 步, 单次运行): SFT 70.1, SFT+DPO 72.7, SFT+RLVR 71.9, SFT+DPO+RLVR 74.1. Figure 19 归纳出三种情形: RL 不优化的指标 (如 AlpacaEval), DPO 的领先会一直保持; RL 直接优化的指标 (如 OMEGA), 两个起点终点相近; 从 DPO 难再提高的指标 (如 AIME 2025), SFT 起点会追上来. 没有一种情形是 SFT 起点在 RL 后反超. 作者还发现 DPO 模型熵更低, AIME 上的 pass@K 却更高, 这与 「RLVR 把 pass@K 转成 pass@1」 的已有观察相容.

### 3.2. OlmoRL: 把 GRPO 改到能跑 32K 回复

OlmoRL 以 GRPO 为底, 吸收了 DAPO 与 Dr GRPO 的多项改动 (§4.4.1): 丢掉组内奖励全相同, 梯度为零的组; 用 active sampling 补足被丢掉的样本, 保持 batch 大小; 损失按 token 总数归一; 去掉 KL 项; 上裁剪边界略高于下边界 (clip-higher); 乘以截断的重要性采样比; 优势不除以组内标准差. 最终目标是式 (1):

$$\mathcal{J}(\theta)=\frac{1}{\sum_{i=1}^{G}|y_i|}\sum_{i=1}^{G}\sum_{t=1}^{|y_i|}\min\left(\frac{\pi(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})}{\pi_{\text{vllm}}(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})},\rho\right)\min\Big(r_{i,t}A_{i,t},\ \mathrm{clip}\big(r_{i,t},1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}}\big)A_{i,t}\Big)$$

其中 $r_{i,t}=\pi(y_{i,t}\mid x,y_{i,<t};\theta)/\pi(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})$ 是概率比, 回复 $y_i$ 由 vLLM 按 $\theta_{\text{old}}$ 采样; 优势由式 (2) 给出, $A_{i,t}=r(x,y_i)-\mathrm{mean}(\{r(x,y_i)\}_{i=1}^{G})$, 这里的 $r(x,y_i)$ 是验证器给的奖励, 源文两处共用字母 r. Table 49 给出取值: 每题采 $G=8$ 条, $\varepsilon_{\text{low}}=0.2$, $\varepsilon_{\text{high}}=0.272$, 32B Think 与 RL-Zero 的 $\rho=2.0$, 7B Think 与 7B Instruct 这一格印的是 「-」. 作者还试过 overlong filtering, 没有稳定收益. GRPO 见 [02-GRPO](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md).

式中每一项对应列表里的一条改动. 最前面的 $1/\sum_i|y_i|$ 是 **token 级归一**: 按样本归一写作 $\frac{1}{G}\sum_i\frac{1}{|y_i|}\sum_t$, 一条 30K 回复里每个 token 的权重只有 1K 回复的 1/30, 长回复里的错误几乎罚不动; 改成除以 token 总数后每个 token 权重相同 (正文说按整个 batch 的 token 数归一, 式 (1) 只写了一组). 第一个 min 是**截断重要性采样**: 分子分母都用 $\theta_{\text{old}}$, 比值不含当前参数, 只衡量训练引擎与 vLLM 对同一 token 给的概率差多少, 截在 $\rho$ 是为了不让 vLLM 给了极低概率的 token 把梯度放大. 第二个 min 是 PPO 式裁剪, $\varepsilon_{\text{high}}>\varepsilon_{\text{low}}$ 就是 **clip-higher**: $A>0$ 时比值最多到 1.272, $A<0$ 时最低到 0.8. 对 $\pi_{\text{old}}=0.01$ 的 token, 对称裁剪下一步最多抬到 0.012, clip-higher 下可到约 0.0127 (心算); 上限按比例放, 概率越低的 token 绝对增量越受限, 放宽上界主要照顾它们. 按 DAPO 的说法这可以缓解熵塌缩, 报告本身只写了 「允许更大的更新」. 式里没有 $\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$ 项, 这就是**去 KL**, 作者称去掉后没有出现过优化或训练失稳.

式 (2) 只减组均值, 不除组内标准差. 奖励为 0/1 时可以直接算: 8 条里答对 $k$ 条, 答对者 $A=1-k/8$, 答错者 $A=-k/8$. 若再除以标准差 $\sqrt{p(1-p)}$ ($p=k/8$), $k=1$ 时答对者的优势是 $0.875/0.331\approx2.65$, $k=4$ 时是 $0.5/0.5=1$, 只做对一条的难题被放大到 2.6 倍以上 (心算); 不除时两者是 0.875 与 0.5, 优势只反映奖励本身的差. 这是 Dr GRPO 指出的难度偏置, 见 [03-DrGRPO-去标准差](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.6-其他策略梯度/03-DrGRPO-去标准差/03-DrGRPO-去标准差.md). $k=0$ 或 $k=8$ 时组内 $A$ 全为 0, 整组对梯度没有贡献, **丢组**就是把这类组拿掉, 缺口由 active sampling 补. RL-Zero 3.1 还撤回了一个 DAPO 组件: 3.0 版屏蔽被截断的回复, 作者后来发现屏蔽让实际 batch 大小波动, 训练更不稳, 不在超长负样本上训练还让回复更长, 于是 3.1 不再屏蔽, 同时把回复上限从 12K 提到 16K.

**active sampling** 是报告自称的新做法. DAPO 的 dynamic sampling 会生成训练 batch 三倍的提示, 以保证过滤后仍有足够的非零梯度样本; OlmoRL 在全异步框架里持续从结果队列拉取完成的回复, 过滤后不够就继续补, 直到凑满目标数量. Figure 26 在 RL-Zero 数学域上显示, 有 active sampling 时非零优势样本始终占满 batch, 训练 loss 的方差也明显降低; 没有它时, batch 会随训练推进越来越瘦, 这是原版 GRPO 的常见问题.

长推理 RL 的算力形状完全由生成决定 (§4.4.3). rollout 上限 32K, 推理模型平均超过 10K token. 32B 用 8 个 H100 节点训练, 20 个节点推理, learner 约 75% 的时间在等数据, GPU 用量上推理约是训练的 5 倍; 7B 是推理 7 节点对训练 2 节点, 约 14 倍. 一次代表性运行里, 每步平均 1000 秒, 其中训练只占 125 秒, 生成要提速 8 倍以上训练才会成为瓶颈. 32K 上限下平均生成长 14628, 若用静态批处理, 最多浪费 54% 的算力 (心算 (32768 − 14628)/32768).

Table 23 在 2 个 8×A100 节点 (一个训练一个推理) 上逐项加组件: OLMo 2 的 RL 设施 881 token/s, 加 continuous batching 到 975, 改进线程到 1358, 加 inflight updates 到 2949, MBU 从 12.90% 升到 43.21%. **inflight updates** 的做法是训练步结束后直接更新推理引擎的权重, 不暂停生成, 也不清空 KV 缓存; 代价是一条回复可能前半段由旧权重生成, 后半段由新权重生成, 策略略微偏离 on-policy, 截断重要性采样恰好兜住这类偏差 (这是按式 (1) 的结构做的解读). 脚注 43 给了直观对比: 早期一个检查点在 9 个节点上训 14 天才跑完一个 epoch, 加上两项改动后 5 个节点 7 天即可.

### 3.3. RL 之后分数怎样移动

Table 14 把 32B 的四个阶段排在一起 (SFT, DPO, Olmo 3 Think 最终版, Olmo 3.1 Think). 推理与指令遵循一路上升: AIME 2025 66.2 / 70.7 / 72.5 / 78.1, OMEGA 43.1 / 45.2 / 50.6 / 53.4, IFEval 83.9 / 80.6 / 89.0 / 93.8, IFBench 37.0 / 34.4 / 47.6 / 68.1. IFBench 在 3.1 上多出 20.5 分, 是续训 21 天里涨得最多的一项, 精确指令遵循的可验证奖励显然还远没饱和.

另一些格子在 RL 中下降. PopQA 33.1 / 37.0 / 31.9 / 30.9, AlpacaEval 2 LC 69.1 / 78.6 / 74.2 / 69.1, 两项都在 DPO 阶段见顶, 之后随 RL 回落. 长尾知识回忆和开放式聊天没有可验证奖励直接支撑, **长 RL 把模型推向推理与格式服从**, 这两类能力被挤掉一部分. 社区对 Olmo 3 的讨论里也提到 PopQA 下降, 表里的数字可以证实这一点. GPQA 在 Table 14 的 3.1 列是 56.7, Table 1 同一模型写的是 57.5, 引用时要带表号. Safety 在 3.1 上从 68.8 升到 83.6.

混合多个领域的 RL 数据, 是作者对 「过优化」 的主要防线. Figure 20 左显示, 只在 IFEval 上做 RL 时, IFEval 越高 AlpacaEval 越低; 混合训练时有 LM 裁判奖励维持聊天质量, 两者可以兼得. Figure 21 显示混合训练的每个领域训练奖励都低于单领域训练, 下游表现却不差, 作者把它读作 reward hacking 减少的迹象. 最终的 RL 数据把各领域精心过滤后大致等量混合, 起点是 DPO 检查点.

训练动态也有迹可循. Figure 18 里各领域奖励稳定上升, 指令遵循涨得最稳, 代码涨得最慢; 平均回复长度先略降再缓慢上升, 作者的解释是 SFT 与 DPO 已经把回复训练到接近 32K 上限. 这意味着 Think 线的 「推理变长」 主要发生在 SFT 与 DPO 阶段, RL 做的是在长度已饱和的前提下提高正确率, TestingTime 意义上的推理预算在进入 RL 前就基本定型了.

## 4. 另外两条线与成本边界

### 4.1. Instruct: 不思考的那条线

§5 的出发点是: 日常使用大多是求建议和查信息, 用不上 Think 那样的推理预算. Instruct 因此不产中间思考, 追求短而有用, 并专门训练 function calling. SFT 数据加入真实 MCP 轨迹与模拟的 SimFC 多轮工具交互, 并从 Think SFT 检查点热启动 (Table 29), 平均回复长度几乎不被带长. DPO 引入多轮偏好, 并把 chosen 与 rejected 的长度差卡在 100 token 以内, 防止模型靠写长赢偏好. RL 的回复上限按尺度分档: 7B 8K, 32B 16K; 脚注说两种长度在两档上都试过, 评测分几乎不变, 但内部试用中 7B-16K 与 32B-8K 出现不理想行为, 于是按定性测试定档.

Table 25 报的是 Olmo 3.1 32B Instruct, 它的阶段列说明 RL 在 Instruct 上作用更大. MATH 74.4 / 86.6 / 93.4, AIME 2025 8.2 / 23.3 / 57.9, IFBench 29.7 / 36.3 / 39.7. 与 Qwen 3 32B 关闭思考相比, AIME 2025 高 36.6 分 (57.9 对 21.3), IFBench 39.7 对 31.3, LitQA2 55.6 对 46.7; BFCL 58.8 对 63.1, MMLU 80.9 对 85.8, 仍落后. 与 Qwen 3 VL 32B Instruct 相比, AIME 2025 仍差约 6 分 (57.9 对 64.2).

Instruct 的 RL 同样挤掉了聊天和知识: AlpacaEval 2 LC 42.2 / 69.7 / 59.8, PopQA 23.7 / 28.5 / 25.0, Safety 92.1 / 88.9 / 89.5, 都在 DPO 或 SFT 阶段见顶. 这与 Think 线的形状一致, 说明是 **RLVR 数据构成带来的共性**, 而不是某条线的偶然. RL 起点也不止一个: 平均分最高的 DPO 检查点和一个平均略低但试用感受更好的候选各跑一次 RL, 再按平均分, 长度分析和试用结果挑终点.

偏好信号的来源在 Table 32 里比较过. 用 Delta Learning 启发式造的对 (大模型回复为 chosen, 小模型为 rejected) 与带 delta 意识的 GPT 裁判造的对, 在不同任务上的增益分布不同, 两者合用平均最好; 只把生成模型换强而不制造对比, 甚至输给 OLMo 2 的旧偏好数据. Figure 23 还显示偏好数据量存在与任务相关的最优点, 过了之后继续加数据会伤下游. 工具评测 (Table 31) 显示给不给工具的分差因模型和任务而异, 不能默认有工具就涨.

### 4.2. RL-Zero: 可复查的 RLVR 实验床

§6 的立论很直接: 现有开源 RLVR 研究多在不公开预训练数据的开权重底座上做, 评测集可能已混入 midtraining 数据, 于是随机奖励也能和真奖励一样有效, 修正提示模板的收益也可能盖过 RL 本身. Olmo 3 RL-Zero 从 Base 出发, 在数学, 代码, 精确指令遵循, 通用聊天和四者混合五个设定上做 RLVR, 数据 Dolci RL-Zero 对预训练和 midtraining 数据再去污染. RLVR 的边界讨论见 [4.4.3-RLVR的局限性与探索边界分析](../../../../llm-guide/4-后训练/4.4-对齐技术/4.4.3-RLVR的局限性与探索边界分析.md).

数学数据来自 DAPO Math, Klear-Reasoner, Open-Reasoner-Zero 与 Omega, 按语义聚类每簇取一题, 再去掉底座 8 次采样全对的题, 得到 13.3K 条. 由于 Dolmino Mix 几乎不含特殊格式, 简单提示模板明显优于带 `<think>` 的后训练模板, 评测提示也去掉 `\boxed{}` 之类的格式. 算法沿用第 3.2 节, 只是训练回复长 16K, 评测回复长 32K, 温度 1.0, 以便报告 pass@k.

Figure 24 显示底座在最初几百步提升很快, 之后缓慢稳定上升, pass@32 也有提升, 说明多样性没有塌掉. 作者称 7B 的起点和终点分数接近 DAPO, 而 DAPO 用的是更大的 Qwen 2.5 32B, 训练步数多一个数量级 (附录 Figure 38, 这是读图比较). 混合设定下每个领域都比单领域训练欠优化, 作者把它定位成多目标 RLVR 的基准. 这条线的价值在于可复查: 改一处 midtraining 数据, 就能在同一套开放流程里看 RL 行为怎样变化.

### 4.3. 成本, 边界与谱系位置

§2.4 用墙钟而不是单一美元数报成本. 从开始训练到评测 Olmo 3 Think 32B 约 56 天, 集群为 1024 张专供 H100, 按每卡时 $2 折合约 $2.75M. 预训练段约 47 天: 5.5T 的初始预训练先在 512 卡上跑约 9.5 天, 再在 1024 卡上跑 35 天, 含所有崩溃恢复; midtraining 两路各 512 卡并行, 连同合并与评测约 1.5 天; 长上下文扩展连同合并评测约 1 天. 后训练约 9 天: SFT 约两天, DPO 单次学习率扫描约 18 小时 (每任务 64 卡) 但因集群不稳拖了多天, 最终 RL 约 5 天且至少损失一天. 3.1 版是首发后把最好的 RL 再续 21 天 (224 卡) 得到的, 不在 56 天之内.

这组数字的口径要看清. 脚注 2 说明配方是在 7B 或更小模型上开发后快速搬到 32B 的, 56 天只是 「配方定了之后跑一遍」 的时间, 不含配方搜索. 作者也提醒, 预训练占 GPU 小时的大头, 但后训练与阶段切换时的反复评测同样不小, 只报预训练小时会低估整个开发周期. 与 OLMo 2 不同, 这份报告没有能耗, 碳排和用水的表格, 本页因此没有这部分环境成本.

材料边界: 报告没有 MoE, 没有多模态, 训练上下文止于 65536, 更长的文档只在池子里公开; 安全评测放在附录 Table 52–55, 没有专门的安全 RL 章节; SWA 对推理显存与延迟的收益没有实测. 知识类基准相对最强开权重模型的差距从底座一直延续到后训练, 报告没有给出针对性的补救实验.

谱系上, OLMo 1 证明全栈可以公开, OLMo 2 把全开放 dense 线训稳并引入退火与 RLVR, Olmo 3 在同一骨架上为长推理重排了数据, 注意力和 RL 设施. SWA 是这一代在注意力上唯一的结构改动, 它的动机是长序列的算力; 同队后续的 Olmo Hybrid 沿着同一个动机更进一步, 用线性循环层替换大部分注意力层. 选型时, 需要长推理选 Think, 需要低延迟和工具调用选 Instruct, 想研究预训练数据与 RL 的关系选 RL-Zero, 引用分数时写全变体名和是否为 3.1.
