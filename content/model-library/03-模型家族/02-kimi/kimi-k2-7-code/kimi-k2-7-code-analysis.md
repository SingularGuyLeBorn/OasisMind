# Kimi K2.7 Code：编程专用变体，规格沿用 K2，训练过程没有公开

源文是官网 Resources 栏的 7 页产品说明，不是技术报告。规格表，两张基准表，评测设定，thinking 约束和价目可以核对；数据，预训练，后训练，RL 奖励一概没有。

来源：同目录 `kimi-k2-7-code.md`（页标记 `page 1 of 7` 到 `page 7 of 7`，正文写 Updated: 2026-09-14，页眉抓取时间 2026/9/25）。对照译稿见 `kimi-k2-7-code-bi.md`。第 2 页和第 3 页的配图（涨幅图，Performance vs Tokens 图）在源 md 里只有文件名，下文不读图估数。

## 1. 它是什么，和 K2.6 怎么分工

K2.7 Code 是 Moonshot 开源的编程向 agent 模型，副标题写「为长程软件工程而建」。开篇一段就把三件事说完：真实长程编程任务上明显变强，复杂工程流程的端到端成功率更高，thinking token 比 K2.6 平均少约 30%。后面的表，图和 FAQ 都在重复这三点。

页面专门有一节讲选型：K2.7 Code 只为编程设计，写作，分析，对话这类通用工作推荐继续用 K2.6。所以它不是 K2.6 的替代，而是同代的一个专用分支。Kimi Code 里它是默认模型，开 thinking；如果用户在 Kimi Code 里关掉 thinking，请求会自动交给 K2.6。这条路由规则说明两个模型在产品里是并行部署的。

## 2. 规格表和 K2 一模一样

结构一节给了完整规格：MoE，总参 1T，激活 32B，61 层（含 1 层稠密），注意力隐维 7168，每个专家隐维 2048, 64 个注意力头，384 个专家每 token 选 8 个，1 个共享专家，词表 160K，上下文 256K，注意力用 MLA，激活函数 SwiGLU，视觉编码器 MoonViT 400M. 按 384 选 8 算，稀疏度是 48，这是读表相除得到的。

这组数字和 K2 技术报告的配置逐项相同，视觉编码器又和 K2.5 的 MoonViT 同名同量级。由此推断 K2.7 Code 没有换骨架，是在 K2.5/K2.6 这条线上继续训出来的；但它从哪个 checkpoint 出发，追加了多少编程数据，RL 用了什么环境，页面都没说。架构为什么是 384 专家，64 头，可以回看 [K2 的解析](../kimi-k2/kimi-k2-analysis.md) 里稀疏度 Scaling Laws 和注意力头数的讨论；MoE 稀疏激活的一般机制见 [01-DeepSeek-MoE](../../../../llm-guide/2-核心原理与架构/2.4-前沿架构与变体/2.4.1-混合专家模型MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md)。

## 3. 基准：六行分数和它们测的是什么

编程三项，K2.6 / K2.7 Code / GPT-5.5 / Claude Opus 4.8: Kimi Code Bench v2 为 50.9 / 62.0 / 69.0 / 67.4，Program Bench 为 48.3 / 53.6 / 69.1 / 63.8，MLS Bench Lite 为 26.7 / 35.1 / 35.5 / 42.8。正文给的相对涨幅 +21.8%，+11.0%，+31.5% 和表上分数相除一致。相对两家闭源模型，三项全低；最接近的是 MLS Bench Lite，比 GPT-5.5 只差 0.4。

Agent 三项：Kimi Claw 24/7 Bench 为 42.9 / 46.9 / 52.8 / 50.4，MCP Atlas 为 69.4 / 76.0 / 79.4 / 81.3，MCP Mark Verified 为 72.8 / 81.1 / 92.9 / 76.4。正文说相对 K2.6 约涨 10%，逐行算是约 9.3%, 9.5%, 11.4%。六行里唯一超过某个闭源对照的是 MCP Mark Verified 上高于 Opus 4.8。

几个基准的内容本页没写，下面取自 Hugging Face 模型卡。Kimi Code Bench v2 是内部基准，覆盖 10 多种主流语言和生产环境的真实工程任务。Program Bench 只给 agent 一个编译好的二进制和文档，不给源码，不许反编译，不许联网，要求它自选语言从零重写程序，用大量模糊测试生成的行为用例比对输出；任务从小型命令行工具到 FFmpeg，SQLite 这样的大系统。MLS Bench Lite 是 MLS-Bench 的 30 题官方子集，让 agent 为预训练，后训练，强化学习，ML 系统等方向提出可推广的方法改进，每题有 5 小时探索时间。这三项的共同点是任务长，要自己规划，和「长程软件工程」的定位对得上；而 MLS Bench Lite 涨幅最大，分数却最低，说明研究型任务仍然是短板。

## 4. 评测设定：各用各的 harness

方法段写明，K2.7 Code 和 K2.6 通过 Kimi Code CLI 测，开 thinking，temperature 1.0，top-p 0.95，上下文 262,144 token；GPT-5.5 在 Codex 里用 xhigh，Opus 4.8 在 Claude Code 里用 xhigh（模型卡对 MLS Bench Lite 另注 Opus 用 max effort）。每家模型都用自家最顺手的 agent 外壳，分数反映的是「模型加外壳」的整体，不是同一个 runner 下的纯权重对比。

和 K2.6 博客比，采样参数有变化：K2.6 博客自己的评测用 top-p 1.0，这里两代都统一用 0.95。所以本页 K2.6 那一列是按新设定重测的，不能拿去和 K2.6 博客里的分数直接混用。K2.6 博客里的 Kimi Code Bench 没有标版本号，本页用的是 v2，两处分数同样不能对比。例外设定和完整方法，页面说在模型卡里，本页不重复。

## 5. 少 30% thinking token，以及关不掉的 thinking

效率一节先说推理模型爱「想太多」，在简单问题上也烧几千个 token；K2.7 Code 平均比 K2.6 少用约 30% thinking token，在三项编程基准上都是分更高，token 更少。具体每项用了多少 token 只在第 3 页的图上，源 md 没转成文字。怎么做到的，是长度惩罚，预算控制还是别的奖励设计，页面没说。K2.5 报告里有 Toggle 和预算控制奖励这类做法，是否沿用无法从本页判断。

这 30% 分量重，是因为 thinking 关不掉。页面和 FAQ 各写一遍：K2.7 Code 不支持非思考模式，API 和 Kimi Code 都始终开启。官方 API 文档还写了另一层：K2.6 的历史轮次思考默认不保留，要显式设 `thinking.keep` 为 `"all"`；K2.7 Code 则始终保留，不能关闭。也就是说，多轮编程会话里之前的思考内容会一直留在上下文里，思考越省，256K 窗口里留给代码和工具输出的空间就越多。保留思考的机制在 [K2.6 的解析](../kimi-k2-6/kimi-k2-6-analysis.md) 里讲过。

## 6. 接入和价格

两条接入路径：Kimi Code（含终端和 IDE 插件）里它是默认模型；开放平台 API 的模型名是 `kimi-k2.7-code`。第 5 页是 Kimi Code 终端截图，能看到客户端版本 0.14.1，这是客户端版本号，和模型权重版本无关。权重在 Hugging Face 开源，FAQ 确认支持文本，图像，视频输入。

API 按每百万 token 计费：输入缓存命中 $0.19，未命中 $0.95，输出 $4.00，窗口 262,144 token。命中价是未命中价的五分之一，仓库级任务反复发送同一段前缀时，输入成本主要由缓存命中率决定。thinking token 按哪一项计费，本页没说，要查平台文档；如果算作输出，那 30% 的节省会直接按 $4.00 的单价折进账单。Kimi Code 订阅按年付折算的月价分四档：Moderato $15，Allegretto $31，Allegro $79，Vivace $159，区别是每周额度和并发上限，具体额度本页没给。

放回家族里看，K2.7 Code 是 Kimi 第一次把编程单独拆成一个开源变体。骨架不变，训练重心往长程工程和省 token 上挪，通用能力留给 K2.6。能核对的只有结果和部署契约，训练这一面要等技术报告或模型卡补充。
