# Gemma 1：分析

> 对象：Gemma: Open Models Based on Gemini Research and Technology (Gemma Team, Google DeepMind), arXiv:2403.08295v4。全文 17 页，正文约 10 页，其余是作者名单，参考文献和一页附录。对照原文见 [gemma-1-bi.md](./gemma-1-bi.md)。

## 1. 版本，日期和这份报告给了什么

读 Gemma 1 报告先要分清版本。首页右上印的日期是 2024-02-21，与权重公开同一天；左侧 arXiv 戳写的是 **v4, 2024-04-16**。编号 2403 说明首次提交在 2024 年 3 月，arXiv 上 v1 的日期是 2024-03-13. v4 和最初的版本内容不同：正文的人类偏好表（表 5）和安全学术基准表（表 8）换成了 Gemma 1.1 IT，原先 1.0 IT 的两张表挪进第 17 页附录（表 9，表 10）。正文文字没有跟着全部改，人类偏好一节仍写 「Gemma 7B IT」，数值却是表 5 里 1.1 的。所以同一个 「7B IT」，在正文和附录里指的是两个检查点。

与上一代 Gemini 1.0 报告相比，这份报告在模型本身上给得多。表 1 列了两档的全部结构超参数，表 2 给到个位的参数量，训练数据量（3T 和 6T token），芯片数，并行方式，碳排放都有明确数字。没给的也很清楚：batch size，学习率计划，训练步数，数据配比，污染分析的结果，2B 选 multi-query attention 所依据的消融，以及强化学习阶段所用算法的名字和目标函数。前一类数字可以复算，后一类只能读出流程。下文凡是用前一类数字推出来的结论，都注明出处；凡是推断，都标为推断。

篇幅分配也能看出重点。第 1 到第 10 页里，模型架构，训练基础设施和预训练数据合计约两页，指令微调约一页半，学术基准，人类偏好和记忆评测约三页，负责任部署和结论约三页。第 11 到 16 页是作者名单和参考文献，第 17 页是 1.0 IT 的附录。评测只覆盖 18 项学术基准，两类人工评测，记忆评测和 10 项安全学术基准，没有长上下文，多语言或工具使用方面的结果。这与它随权重一起发布的定位相符，主要回答两个问题：模型长什么样，在常见基准上排在哪里。

## 2. 两档模型的结构差在哪几行

表 1 七行里，两档只有 Head size (256) 和 Vocab size (256128) 相同，加上正文说的 8192 上下文。其余几行变化并不同比例。2B 是 d_model 2048, 18 层，8 个查询头，1 个 KV 头；7B 是 d_model 3072, 28 层，16 个查询头，16 个 KV 头。一个容易漏掉的细节：7B 的查询头数乘头宽是 16 x 256 = 4096，比 d_model 的 3072 还宽，注意力投影把 3072 维映射到 4096 维再映射回来；2B 则是 8 x 256 = 2048，与 d_model 相等。头宽 256 在同期开放模型里偏大，两档都这样取，查询头数就少了。

注意力形式的差异对部署影响最大。2B 只有 1 个 KV 头，每个 token 在 KV cache 里要存 2 x 18 x 1 x 256 = 9,216 个数；7B 是 2 x 28 x 16 x 256 = 229,376 个，相差约 24.9 倍。假设按 bf16 存储，8192 上下文下 2B 的 KV cache 约 151 MB，7B 约 3.76 GB. Introduction 一节给两档的定位分别是 「CPU 和端侧」 与 「GPU 和 TPU」，这组数和定位吻合。原文给出的理由是 「消融显示 multi-query attention 在小规模下效果很好」，但消融结果没有出现在任何表里。

逐层看，参数分布也不一样。2B 每层约 1.10 亿参数，其中前馈占 91.4%，注意力只占 8.6%，这是 1 个 KV 头的直接结果；7B 每层约 2.77 亿参数，前馈占 81.8%，注意力占 18.2%。两档的宽深比接近，d_model 除以层数分别约 114 和 110，从 2B 到 7B 宽度和深度大致同比增加。真正改变结构形态的是注意力部分：7B 每层的注意力参数是 2B 的 5.3 倍，前馈只是 2.25 倍。

这也决定了怎么读两档之间的分差。2B 与 7B 同时在宽度，深度，KV 头数和训练数据量（3T 对 6T）上不同，表 6 里两列 Gemma 的差距是这四个因素叠加的结果，不能当成 「参数量从 2B 到 7B」 的单变量效果。报告里没有任何只改一个因素的对照。

## 3. 表 2 的参数量可以逐位复算

表 2 的数字可以用表 1 精确复原。记 d 为 d_model，L 为层数，n_h 和 n_kv 为查询头数和 KV 头数，头宽 256，前馈单支宽度为 h. 每层参数由三部分组成：注意力 2 x d x (n_h x 256) + 2 x d x (n_kv x 256)，GeGLU 的门，上投影和下投影合计 3 x d x h，两个 RMSNorm 共 2d；最后一层之后再加一个 d. 非嵌入参数 = L x（注意力 + 3dh + 2d）+ d. 2B 取 h = 16384，得 1,981,884,416; 7B 取 h = 24576，得 7,751,248,896，与表 2 逐位一致。由此可知表 1 的 「Feedforward hidden dims」 32768 和 49152 是门与上投影两支合在一起的宽度，单支宽度是它的一半。读表 1 时若把 32768 当成单支宽度，2B 的非嵌入参数会算成约 3.79B，接近表 2 的两倍。

嵌入参数同样对得上：256128 x 2048 = 524,550,144, 256128 x 3072 = 786,825,216，只计一份，与正文 「输入输出共享嵌入」 一致。两档总参数因此是 2.51B 和 8.54B. 名字里的 「2B」 和 「7B」 对应的是非嵌入参数（1.98B 和 7.75B），按总参数算，7B 比 LLaMA-2 7B（约 6.7B）和 Mistral 7B（约 7.2B）都大一截，这两个数取自各自的报告。表 6 所谓 「尺寸相近」 的对比，按总参数看 Gemma 7B 是其中最大的。

大词表的代价在两档上不对称。嵌入在 2B 里占总参数的约 20.9%，在 7B 里只占约 9.2%。表 2 的表注说这个词表为大量语言设计，可训练数据以英文为主，正文也明说模型不追求多语言任务上的最佳表现。分词器的几项设置，包括数字逐位拆开，保留多余空白，未知字符退回字节编码，对代码和算术更友好。推断：词表里大量非英文条目在英文为主的数据上用得少，这部分容量对 2B 的相对负担更重。

共享嵌入只省参数，不省计算。输出层每个 token 仍要做一次 d x 256128 的矩阵乘，按 2 x d x V 计，2B 约 **1.05e9** FLOPs，而非嵌入部分约 2 x 1.98e9 ≈ 3.96e9，输出层约占单 token 前向算力的 21%（不计注意力随上下文增长的部分）；7B 这一比例约 9%。对 2B 来说，大词表既占存储也占推理算力，与它面向 CPU 和端侧的定位有些冲突。这是按表 1 推出的，报告没有讨论这笔开销。

## 4. 训练数据，算力和碳排放

两档分别用 3T 和 6T token 训练。按总参数算，2B 每个参数约 1197 个 token，7B 约 703 个；按非嵌入参数算是 1514 和 774. Hoffmann et al. (2022) 给出的计算最优比例约为每参数 20 个 token，两档都远超，思路与 LLaMA 系列相同：多花训练算力，换推理时更小的模型。2B 的数据总量是 7B 的一半，按每参数计却多出约 70%。数据来源只写了网页文档，数学和代码三类，配比经 2B 和 7B 上的消融确定，训练分阶段调整，后期提高相关高质量数据的权重。具体比例，阶段划分和消融结果都没有给出。

训练基础设施一节的数字能拼出完整的并行方案。TPUv5e 每 256 块芯片组成一个 pod，连成 16 x 16 的 2D torus. 7B 用 16 个 pod 共 4096 块，pod 内 16 路模型切分乘 16 路数据副本，整体数据并行度 256，模型并行度 16. 2B 用 2 个 pod 共 512 块，全部是数据并行。优化器状态再按类似 ZeRO-3 的方式切分，跨 pod 的梯度归约走数据中心网络，由 Pathways 编排。单控制器编程范式，GSPMD 切分器和 XLA 编译器都沿用 Gemini 的栈。

碳排放一节只给一个总数：预训练约 **131 tCO2eq**，不含微调，也没有按两档拆开。用 6ND 粗估训练算力（N 取总参数，D 取训练 token 数），2B 约 **4.5e22** FLOPs，7B 约 **3.1e23** FLOPs，7B 约占合计的 87%。这是估算，原文没有这组数，但足以说明 131 吨主要来自 7B. 报告同时声明 Google 数据中心通过能效，购买可再生能源和碳抵消实现碳中和，这与排放估算是两件事，前者并不减少 131 吨这个数。

数据过滤里有一条和评测直接相关：所有评测集都从预训练数据中滤掉，并做了有针对性的污染分析。报告只给了这句陈述，没有给出滤掉的量，也没有给出污染分析的发现；Gemini 1.0 报告至少给过 HellaSwag 的对照实验，这里一项都没有。所以表 6 里数学和代码上的大幅领先，无法用报告自身的材料排除污染因素，能用的旁证只有 GSM8K 在表 7 的独立实现里同样领先。表 7 由 HuggingFace 运行，用的仍是同一批公开基准，它能排除评测实现上的偏差，排除不了训练数据里混入考题。

## 5. 指令微调：流程写清了，配方没给

微调分两步。监督微调的数据是纯英文，纯文本的 prompt-response 对，混合了合成数据和人写数据。数据混合怎么选，报告写得具体：用一个更大的模型做 side-by-side 评判，待测模型和基线模型对同一批留出 prompt 各出一个回答，打乱顺序后由评判模型表态。prompt 集按能力分开构造，包括指令遵循，事实性，创造性和安全；评判模型用 chain-of-thought，评分细则和 constitution 来贴近人类偏好。合成数据要多轮过滤，去掉个人信息，不安全输出，错误的自我身份认定和重复样本。报告还提到，加入鼓励上下文归因，措辞留余地和拒答的数据能提升事实性指标，其他指标不降，但没有给出对应的数字。

格式约定是这一节最能直接用上的部分。表 3 只定义了四个控制串：user, model, `<start_of_turn>`, `<end_of_turn>`。表 4 的示例里每行开头的 「User:」 和 「Model:」 是排版标注，不属于输入。报告明说不用格式器也能生成连贯文本，但属于分布外输入，质量很可能更差。对下游使用者来说，这意味着 IT 检查点的提示模板是固定的，自行改写角色标记会直接影响效果。

监督微调数据和奖励模型的偏好数据都限定为英文，与预训练数据以英文为主一致。后果是 IT 检查点在非英文场景下的表现没有评测：报告没有说明表 5 人类偏好 prompt 的语种，表 8 的 10 项安全学术基准都是英文数据集。256k 的词表让模型能读写多种文字，但报告对非英文的指令遵循和安全表现不作任何说明。要在中文等语言上使用 Gemma 1 的 IT 版本，评测只能自己补。

强化学习阶段只有轮廓。奖励模型在 Bradley-Terry 模型下用人类成对偏好训练，即偏好概率取两者奖励差的 logistic 函数；策略用 「一种新的强化学习算法」 优化，算法名，目标函数和超参数都没有。调超参数和防 reward hacking 同样交给高能力模型做自动 side-by-side. 1.0 到 1.1 之间改了什么，报告也没有说明，只在表 5 和表 9 之间给出了结果差。这一节能读出 Google 的流程设计，复现不了。

## 6. 11/18：分母是表 6，计数规则要自己补

摘要的 「18 个文本任务中赢 11 个」，分母就是表 6 的 18 行：MMLU, HellaSwag, PIQA, SIQA, BoolQ, Winogrande, CQA, OBQA, ARC-e, ARC-c, TriviaQA, NQ, HumanEval, MBPP, GSM8K, MATH, AGIEval, BBH。拿 Gemma 7B 与 LLaMA-2 7B，LLaMA-2 13B，Mistral 7B 三列中的最高分逐行比，严格领先 10 行，BoolQ 与 Mistral 同为 83.2，落后 7 行（PIQA, Winogrande, OBQA, ARC-c, TriviaQA, NQ, BBH）。10 加 1 等于 11，所以 「11」 只有按 「不低于」 计才成立。只和 Mistral 7B 比，严格领先是 12 行；去掉 13B 那列，结果不变。报告没有写这个计数规则，以上是对表推出来的。

领先的幅度差别很大。10 行领先里，HellaSwag 只多 0.2，AGIEval 多 0.5，ARC-e 多 1.0，SIQA 多 1.5（对 LLaMA-2 13B 的 50.3），MMLU 多 1.8；真正拉开的是 MATH +11.6, GSM8K +11.0, HumanEval +6.1, MBPP +4.2, CQA +4.0。落后的 7 行里，TriviaQA 比 LLaMA-2 13B 低 16.2，比 LLaMA-2 7B 也低 8.7；OBQA 低 5.8。表 7 显示，同一个 Gemma 7B 换成 HuggingFace 的实现，ARC-c 差 8.7，Winogrande 差 6.7。设定变化带来的波动有这么大，1 到 2 分的领先只能算打平。

表内来源也不统一。Mistral 列有 7 格带星号，是 Google 重跑的，其余 11 格按表注应是引用值；LLaMA-2 两列因许可限制全部取自 Touvron et al. (2023b). MBPP 另有脚注：Mistral 在另一个划分上报告 50.2，Gemma 7B 在那个划分上是 54.5。平均分可以复算，五列分别是 46.894, 52.367, 54.528, 44.983, 56.856，四舍五入后与表中 46.9, 52.4, 54.5, 45.0, 56.9 一致。按未舍入的平均分，Gemma 7B 比 Mistral 7B 高 2.33 分（56.856 - 54.528）；其中 GSM8K 和 MATH 两行合计多 22.6 分，摊到 18 行是 1.26 分，占了一半以上。平均分的领先同样主要由数学拉动。

## 7. 优势集中在数学和代码，闭卷知识偏弱

图 1 按能力把基准归成四组，图注没列每组的成员。用表 6 能反推两组。Coding 组是 HumanEval 和 MBPP 的平均：Gemma 7B 38.35, Mistral 33.2, LLaMA-2 13B 24.45, LLaMA-2 7B 16.8. Math / Science 组是 GSM8K，MATH，MMLU 三项的平均：45.0, 36.87, 29.13, 20.8。四列都与柱高对得上。Question Answering 和 Reasoning 两组用剩下的 13 行拼不出唯一组合。从柱高看，Question Answering 一组 Gemma 7B 约 62，低于 LLaMA-2 13B 的约 64，所以图 1 也不是四组全胜，两组明显领先，两组接近。

闭卷知识问答是 Gemma 7B 最弱的一块。TriviaQA 63.4 对 LLaMA-2 7B 的 72.1，NQ 23.0 对 25.7，连同尺寸更小的 LLaMA-2 7B 都没追上；Mistral 7B 在这两项上也偏低（62.5 和 23.2）。报告没有解释原因。推断：训练数据明确包含数学和代码，分阶段训练在后期加重 「相关的高质量数据」，这种配比有利于推理类基准，对需要记住长尾事实的闭卷问答帮助有限。这只是与表 6 形态相符的一种解释，报告里没有能直接检验它的消融。

数学和代码上的领先有几个旁证。MBPP 上 Gemma 7B 的 44.4% 超过专门做过代码微调的 CodeLLaMA-7B (41.4%)。表 7 里 HuggingFace 独立跑的 GSM8K，Gemma 7B 50.9 对 Mistral 37.8，差距 13.1，比表 6 的 11.0 还大。MMLU 上 64.3 在表 7 里是 64.6，两套实现结果接近。同时报告也提醒 MMLU 的人类专家门槛是 89.8%，64.3 离它还远。结论一节把 MMLU 64.3% 和 MBPP 44.4% 并列为代表成绩，两者都来自表 6 的预训练 7B 列。

表 7 还有一项表 6 没有的 TruthfulQA: Gemma 7B 44.8 对 Mistral 42.2。表 8 里也有 TruthfulQA，那是 1.1 IT 检查点在 Google 实现（MC2）下的分数，与表 7 的预训练 7B 不是同一个模型，两个数不宜并列。表 7 六项里 Gemma 7B 赢 5 项，只输 HellaSwag（82.2 对 83.3）；表 6 里 HellaSwag 是 Gemma 小胜 0.2，方向正好相反，1 分左右的差距跟着评测实现走，这里又是一例。

## 8. 2B 该放在哪里比

摘要里的 11/18 不含 2B. 表 6 没有与 2B 同尺寸的对手，最近的一列是 LLaMA-2 7B. 2B 只在 7 行超过它：SIQA，CQA，HumanEval，MBPP，GSM8K，MATH，BBH，平均分 45.0 对 46.9。相对优势最大的是 MATH（11.8 对 2.5）和 HumanEval（22.0 对 12.8），最弱的是 NQ（12.5 对 25.7），TriviaQA（53.2 对 72.1）和 BoolQ（69.4 对 77.4）。格局与 7B 一致：数学和代码强，闭卷知识弱，只是整体低一档。

两列 Gemma 之间可以直接比，因为都是 Google 在同一套设定下跑的。7B 在全部 18 行都高于 2B. 差距最大的是 GSM8K（28.7 分），MMLU (22.0), BBH (19.9), AGIEval (17.5)；最小的是 SIQA (2.1) 和 PIQA (3.9)。多步推理和知识密集的基准拉开最多，常识选择题差得最少。这组差距背后同时有结构，注意力形式和数据量三类差异（见第 2 节和第 4 节），不宜直接拿去推算 「参数翻几倍，分数涨多少」。

人类偏好评测里，2B IT 的对手同样是 Mistral 7B Instruct。指令遵循胜率 45%，95% 区间 [43.1%，46.9%] 整段低于 50%，即 2B IT 在这项上输给对手；1.0 版本是 41.6%。对一个参数量约为对手三分之一的模型，这个结果本身不差，但报告摘要和正文都没有正面写出 2B 在指令遵循上落后。读 2B 的成绩，合适的参照是它自己的 7B 兄弟和 LLaMA-2 7B，而不是 「尺寸相近的开放模型」。

部署成本还可以再算一步。按 bf16 存权重，2B 的 2.51B 参数约占 5.0 GB，7B 的 8.54B 约占 17.1 GB；加上 8192 上下文的 KV cache（151 MB 对 3.76 GB），单条满长序列的推理占用分别约 5.2 GB 和 20.8 GB. 7B 的 bf16 全量权重放不进 16 GB 显存的消费级显卡，需要量化；2B 可以直接放进常见的笔记本内存。报告没有给出量化版本的评测，Introduction 一节 「CPU 和端侧」 的定位也没有配任何速度或内存数据，以上都是按表 1 和表 2 推出的。

## 9. 预训练分数和微调分数分属不同检查点

表 6，表 7 和图 1 的列名只写 「Gemma 2B」 或 「Gemma 7B」，没有 PT 或 IT 字样。对照对象是 LLaMA-2 和 Mistral 的基座模型，LLaMA-2 的数取自其报告的基座模型结果，按此推断这几张表是预训练检查点的分数。微调模型的分数只出现在四张表里：表 5 和表 8 是 1.1 IT，表 9 和表 10 是 1.0 IT。记忆评测明确针对预训练模型。人类偏好一节开头说 「除了在微调模型上跑标准学术基准」，但这些学术基准结果全文没有给表。

因此报告里至少有三个 7B 检查点：预训练 7B（表 6，表 7），1.0 IT 7B（表 9，表 10），1.1 IT 7B（表 5，表 8）。同一个检查点在不同实现下的分数也会变。表 7 与表 6 有 5 个重名基准，Gemma 7B 的分数分别是 MMLU 64.6 对 64.3，HellaSwag 82.2 对 81.2，Winogrande 79.0 对 72.3，ARC-c 61.9 对 53.2，GSM8K 50.9 对 46.4。表 7 的平均分按 6 项直接算是 383.4/6 = 63.9，表中写 63.8；Mistral 列 365.9/6 = 60.98，与 61.0 一致。

引用时需要三项信息才能定位一个分数：哪个检查点（预训练，1.0 IT, 1.1 IT），哪套实现（Google 自己的，照搬 Mistral 方法的，HuggingFace 的），哪张表。比如 「Gemma 7B MMLU 64.3」 应写成表 6 的预训练 7B, 5-shot top-1；「Gemma 7B IT 胜率 61.2%」 应写成表 5 的 1.1 IT，指令遵循，对 Mistral v0.2 7B Instruct。

## 10. 人类偏好评测：胜率算法和区间宽度

表 5 的胜率按 「胜 + 平/2」 计算，四格都能复算：7B 指令遵循 52.2 + 18.1/2 = 61.25, 2B 为 37.1 + 15.8/2 = 45.0。指令遵循用约 1000 条留出 prompt，覆盖创意写作，编程和指令遵循；对手只有 Mistral v0.2 7B Instruct 一个。1.1 IT 7B 的区间是 [59.3%，63%]，下界高于 50%。附录表 9 里 1.0 IT 7B 是 51.7%，区间 [49.6%，53.8%]，下界低于 50%，也就是说 1.0 版在指令遵循上相对 Mistral 的优势并不显著，到 1.1 才明确胜出。

区间宽度提供了一个报告没写的信息。若每条 prompt 只有一次评分，1000 个样本，p = 0.612 时二项分布的 95% 半宽约为 3.0 个百分点；表 5 给出的半宽只有 1.85。反推有效样本量约为 prompt 数的 2.7 倍。推断：每条 prompt 大概有多名评分者或多次评分，或者区间用了别的估计方法。报告没有交代评分者人数和区间算法，这两个区间只能按表中数字引用，无法自行复核。

1.0 到 1.1 的变化只体现在结果上。7B 指令遵循从 51.7% 升到 61.2%，2B 从 41.6% 升到 45%。胜平负分项里，7B 的胜从 42.5% 升到 52.2%，负从 39.1% 降到 29.8%，平局基本不变（18.4% 对 18.1%）。报告没有说明 1.1 的微调方案改了什么，所以这 9.5 个点的提升无法归因。

这组人类偏好评测的对照面也很窄。对手只有 Mistral v0.2 7B Instruct 一个，没有 LLaMA-2 Chat，也没有 2B 级别的模型；prompt 只分指令遵循和安全两类，没有按创意写作，编程等子任务给出分项胜率。61.2% 能说明 1.1 IT 7B 在这批 prompt 上更常被评分者选中，说明不了它在某一类具体任务上领先多少，也说明不了它相对其他对话模型的位置。

## 12. 引用这份报告时怎么写

模型本身的数字最可靠。表 1 和表 2 能逐位互相印证，训练 token 数，芯片数，并行方式都有明确出处。引用参数量时，最好同时给出总参数（2.51B, 8.54B）和非嵌入参数（1.98B, 7.75B），并说明名字按后者取。引用前馈宽度时要注明表 1 的数是门与上投影合计的 2h. 引用 2B 的 multi-query attention 时，能给的依据是 KV cache 的算术（第 2 节），原文提到的消融没有数字。

评测数字引用前要先还原口径。11/18 要说明分母是表 6，对照是三列里的最高分，平局计入；数学和代码上的领先（GSM8K +11.0, MATH +11.6, HumanEval +6.1）是这组结果里最稳的部分，其余领先多在 2 分以内，不超出不同实现之间的波动。分数要注明检查点和版本：表 6，表 7 是预训练模型，表 5，表 8 是 1.1 IT，表 9，表 10 是 1.0 IT. 2B 的成绩应拿它和 7B 或 LLaMA-2 7B 比。版本信息写 v4，日期写 2024-02-21，并说明正文的指令模型结果属于 1.1。

想据此复现 Gemma 1，能直接拿到的是结构，参数量，分词器约束，token 总量，硬件和并行方式，以及对话格式。缺的是学习率与 batch size，分阶段训练的切换点和配比，监督微调数据的规模，强化学习算法本身，以及 1.0 到 1.1 的改动。有了前一类信息，可以在同样的结构上训练一个模型；缺了后一类，得不到同样的分数。与后续 Gemma 版本对照时，结构类的数字可以直接对齐，分数类的数字要先对齐检查点和评测实现。
