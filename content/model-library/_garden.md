# 模型库

模型库收录主流大模型的一手材料: 技术报告, 系统卡和模型卡. 每个模型一个目录, 目录里通常有两篇文章, 一篇是原文的逐段中英对照 (bi 稿), 一篇是把整份材料读完之后写成的解析笔记 (analysis 稿). 按家族归档, 共 21 个家族, 265 个模型目录, 其中 264 个同时有 bi 稿和 analysis 稿.

模型库和 [llm-guide](../LargeLanguageModelGuide/llm-guide.md) 分工明确. llm-guide 讲机制: MLA 怎样压缩 KV cache, 无辅助损失的负载均衡怎样工作, GRPO 的目标函数从哪里来. 模型库讲具体模型选了什么: DeepSeek-V3 的 KV 压缩维度是 512, 每 token 激活 8 个路由专家, 预训练用了 14.8T token. 机制的推导只写在 llm-guide 里, 模型库的解析需要推导时链过去; llm-guide 举例时, 也链回模型库的具体版本.

家族的编号顺序是: DeepSeek, Kimi, Qwen, StepFun, MiMo, OLMo 排在前面, 其余按名称排列. 前六个家族的共同点是公开了较完整的技术报告, 架构, 数据和训练配方都有数字可查, 读起来信息密度最高, 适合作为入门的样本. 其余家族的材料完整度差别很大, 有的只有模型卡和评测表.

同一家族内, 目录按版本排列, 既有旗舰模型, 也有代码, 数学, 视觉, 语音等分支. 例如 DeepSeek 家族从最早的 DeepSeek LLM 到 V2, V3, R1, 再到 Coder, Math, Prover, Janus 等分支; Qwen 家族覆盖 Qwen 到 Qwen3 系列, 以及 Coder, Math, VL, Audio 等变体. 每个家族的完整清单见 [目录树](./目录树.md).

### 1.2 三类原始材料

第一类是 arXiv 上的技术报告, 信息最完整. [DeepSeek-V3](./03-模型家族/01-deepseek/deepseek-v3/deepseek-v3-analysis.md) 的报告给出了 671B 总参数, 37B 激活参数, 14.8T 预训练 token, 2.788M H800 GPU 小时; [Kimi K2](./03-模型家族/02-kimi/kimi-k2/kimi-k2-analysis.md) 是 1.04T 总参数, 32B 激活; [GLM-4.5](./03-模型家族/13-glm/glm-4-5/glm-4-5-analysis.md) 是 355B 总参数, 32B 激活. 这类报告通常覆盖架构, 数据, 训练系统, 后训练和评测五个部分.

第二类是系统卡, 闭源模型的主要材料. [Claude Opus 4 的系统卡](./03-模型家族/08-claude/claude-opus-4/claude-opus-4-analysis.md) 有 123 页, 内容集中在安全评估, 对齐审计和发布等级 (它是第一个按 ASL-3 发布的 Claude), 参数量, 层数和训练 token 一概不写. 第三类是模型卡, 篇幅较短, 以规格和评测为主. [gpt-oss](./03-模型家族/20-openai/gpt-oss/gpt-oss-analysis.md) 的模型卡给出了 120b 版本的 116.83B 总参数和 5.13B 激活参数, 并附有风险评估. 读一个模型之前, 先看它属于哪一类材料, 就能预期能从中得到什么.

## 2. 一个模型目录里有什么

### 2.1 bi 稿: 逐段对照

bi 稿按原文顺序, 一段英文接一段中文. 页码用 `<!-- page k of N -->` 标记, 方便和 PDF 对照. 中文部分不是逐字翻译, 而是把这一段说的事用中文讲一遍, 遇到术语保留英文原词. 段落之间插有「解释」行, 补充读这一段需要的背景, 例如 MLA 是什么, 无辅助损失负载均衡的偏置怎样调整, 并链到 llm-guide 的对应小节.

bi 稿的另一个组成部分是疑惑块, 以 `> **问:**`, `> **核对:**`, `> **看表:**` 等标签开头. 每个疑惑块记录一个读报告时容易产生的疑问, 并给出答案. 例如 DeepSeek-V3 的 bi 稿在摘要处问: 2.788M GPU 小时是否包括调参和消融? 答案是不包括, 报告的 Table 1 只统计正式训练 (预训练 2664K 小时, 上下文扩展 119K, 后训练 5K). 大约 239 篇 bi 稿带有这类疑惑块.

### 2.2 analysis 稿: 整合笔记

analysis 稿的第一行是「来源:」, 写明材料的标题, 版本号 (arXiv 编号与版本, 或发布日期) 和仓库地址. 正文用编号标题 (`## 1.`, `### 1.1.`) 组织, 顺序通常是模型结构, 训练系统, 数据与日程, 后训练, 评测. 它不按原文顺序复述, 而是把散落在报告各处的信息拼起来, 回答「这些设计选择之间怎样互相牵连」.

以 DeepSeek-V3 为例, 解析从宽度和专家数出发, 把 37B 激活参数逐项加出来 (MoE 层约 23.0B, MLA 约 11.4B, 嵌入和输出头, 前三层稠密 FFN), 和报告的数字对上; 再算出 MLA 每 token 每层只缓存 576 个元素, 128K 序列的 KV cache 约 9.2GB. 数字的来源分三种标注: 报告原文的直接引用, 「读图估算」, 以及来自公开配置文件或其他论文的「公开资料」, 笔者自己的判断标为「推测」.

### 2.3 原文转写与图片

有 36 个模型目录还保留了 MinerU 转出的原文 markdown, 文件名与目录同名 (例如 `claude-opus-4-5.md`, `llama3-1.md`). 这些转写稿是 bi 稿和 analysis 稿的底本, 保留它们是为了在译文有疑问时回查原文的公式和表格. 原始 PDF 不放在仓库里, analysis 稿的来源行给出了获取地址.

图片统一放在每个模型目录的 `images/` 下, bi 稿和 analysis 稿引用同一套图. 目前只有一个目录例外: xAI 家族的 grok-4-7 只有原文转写, 还没有 bi 稿和 analysis 稿. 家族级的 `_index.md` 和 `03-模型家族.md` 是内部索引, 不对外发布, 按家族浏览请用 [目录树](./目录树.md), 它列出了每个模型目录下有哪些文件.

## 3. 怎么读

### 3.1 先读哪一篇

想快速了解一个模型, 先读 analysis 稿. 它的开头一段通常就交代了模型的规模, 关键设计和这些设计之间的关系, 读完开头和各节标题, 就能判断这份报告值不值得细读. 需要引用某个具体数字或某句原话时, 再去 bi 稿里找对应的段落, 用页码标记回到 PDF 核对.

研究某一份报告的细节, 例如复现它的训练配置, 顺序反过来: 从 bi 稿开始按原文顺序读, 疑惑块能帮助跳过常见的误读; 读完一节后再看 analysis 稿的对应部分, 检查自己有没有漏掉跨章节的联系. analysis 稿里标为「推测」的内容不能当作报告的结论引用.

第一次接触模型库, 不知道从哪个模型开始的读者, 可以按时间顺序读 DeepSeek 家族的四篇: [DeepSeek LLM](./03-模型家族/01-deepseek/deepseek/deepseek-analysis.md) 在自家数据上重新拟合 Scaling Laws, [DeepSeek-V2](./03-模型家族/01-deepseek/deepseek-v2/deepseek-v2-analysis.md) 引入 MLA 和 DeepSeekMoE, DeepSeek-V3 加上 FP8 训练和 MTP, [DeepSeek-R1](./03-模型家族/01-deepseek/deepseek-r1/deepseek-r1-analysis.md) 转向以规则奖励为主的推理强化学习. 四篇连起来, 每一步改了什么, 为什么改, 解析里都有交代.

### 3.2 和 llm-guide 来回读

模型库的解析默认读者了解基本机制. 读 DeepSeek-V3 的解析遇到 MLA 的矩阵吸收, 可以跳到 llm-guide 的 [MLA 低秩潜变量与解耦 RoPE](../LargeLanguageModelGuide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md) 看推导; 遇到 GRPO, 跳到第 4 章的对齐技术. 反过来, 读 llm-guide 时想知道某个机制被哪些模型采用, 采用时选了什么参数, 就来模型库查.

这种来回读的好处是两边的数字能互相校验. llm-guide 推出的公式, 代入模型库里的真实配置, 应当得到报告里的数字; 对不上时, 要么是公式的假设和模型的实现不同, 要么是报告的口径 (是否含 MTP 模块, 是否含嵌入层) 和公式不同. 这类差异往往是理解一个设计的切入点.

### 3.3 跨家族对比

模型库的目录结构让跨家族对比变得容易: 同一类信息在每个 analysis 稿里的位置大致相同. 比较 DeepSeek-V3, Kimi K2, GLM-4.5 和 [Qwen3](./03-模型家族/03-qwen/qwen3/qwen3-analysis.md) 这几个 MoE 旗舰, 可以分别打开它们的模型结构一节, 对照总参数, 激活参数, 专家数, 注意力形式和预训练 token 数.

对比时要注意口径. 不同报告对「激活参数」是否包含嵌入层, 对「训练成本」是否包含消融实验, 定义都可能不同, analysis 稿会在遇到这类问题时注明. 闭源模型的系统卡和开源模型的技术报告之间, 能比较的维度很少, 主要是公开基准上的分数和安全评估的等级, 架构层面通常无从比较.
