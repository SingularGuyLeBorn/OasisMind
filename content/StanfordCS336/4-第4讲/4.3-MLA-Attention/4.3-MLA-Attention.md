# MLA：从低秩 KV 到可吸收的注意力计算

自回归解码每生成一个 token，都要读取此前所有 token 的 Key 与 Value。上下文变长、并发升高后，KV Cache 同时占用大量显存和 HBM 带宽。Multi-head Latent Attention（MLA）用一个低维潜变量承载每个历史 token 的主要 K、V 信息，推理时缓存潜变量，而非完整的多头 K、V。

MLA 不是简单地「把 K、V 压缩后再全部解压」。如果每个 decode step 都把所有历史潜变量恢复成完整 K、V，缓存虽然变小，重建计算和中间流量会抵消收益。它真正巧妙的地方在矩阵结合律：无位置部分的 Key 上投影可以吸收到 Query 一侧，Value 上投影可以吸收到输出投影，使注意力直接在潜在空间完成主要计算。RoPE 无法穿过任意低秩投影，因此另设一条小型位置分支。

## 一、标准注意力的缓存成本

### MHA 每个 token 缓存多少

设模型有 $L$ 层，query head 数为 $H$，单头维度为 $d_h$，因此隐藏维度通常满足

$$
d=Hd_h.
$$

标准 Multi-Head Attention 为每个历史 token、每层保存 $H$ 个 Key 与 $H$ 个 Value。若缓存格式每元素占 $s$ 字节，单 token 全模型缓存为

$$
M_{\text{MHA/token}}
=2LHd_hs
=2Lds.
$$

批量为 $B$、平均上下文长度为 $S$ 时，

$$
M_{\text{MHA}}
=2LBSds.
$$

系数 2 对应 K 与 V。缓存大小随层数、并发和上下文长度线性增长。

### 一组容量手算

取 $L=32,d=4096$，KV 使用 BF16，$s=2$。每 token 缓存

$$
2\times32\times4096\times2
=524288\text{ bytes}
=512\text{ KiB}.
$$

单个 4096 token 请求约需

$$
4096\times512\text{ KiB}
=2\text{ GiB}.
$$

32 个同长度请求就约需 64 GiB，尚未计模型权重、临时张量、分页元数据和内存碎片。KV Cache 会直接限制并发容量。

### 容量之外还有读取带宽

Decode 时每个新 query 都要访问其完整历史 K、V。单步读取量与 $BS$ 成正比。即使显存放得下，长上下文下 attention kernel 也可能被 HBM 带宽限制。增大 batch 能复用线性层权重，却不能复用不同请求各自的 KV Cache。

GQA 与 MQA 通过减少 KV heads 缓解问题。若 KV head 数为 $H_{kv}$，单 token 缓存变为

$$
M_{\text{GQA/token}}
=2LH_{kv}d_hs.
$$

MLA 选择另一条路线：不把每个 token 的内容表示复制成若干 KV heads，而是缓存共享的低维潜变量，再让不同 query heads 通过各自投影读取它。

## 二、MLA 的低秩参数化

### KV 下投影与上投影

设第 $t$ 个 token 的隐藏状态为

$$
h_t\in\mathbb R^d.
$$

MLA 先把它压缩到 KV 潜变量

$$
c_t^{KV}
=W^{DKV}h_t,
\qquad
c_t^{KV}\in\mathbb R^{d_c},
$$

其中 $d_c\ll Hd_h$。再通过上投影生成各头的无位置 Key 与 Value：

$$
k_{t,i}^{C}=W_i^{UK}c_t^{KV},
\qquad
v_{t,i}^{C}=W_i^{UV}c_t^{KV}.
$$

$i=1,\ldots,H$。上标 $C$ 表示内容分支。把所有头拼接后，可以看成

$$
k_t^C=W^{UK}c_t^{KV},
\qquad
v_t^C=W^{UV}c_t^{KV}.
$$

这相当于把原始 KV 投影矩阵分解成低秩形式：

$$
W^K\approx W^{UK}W^{DKV},
\qquad
W^V\approx W^{UV}W^{DKV}.
$$

Key 与 Value 共享下投影 $W^{DKV}$，上投影不同。

### Query 也可低秩压缩

MLA 还可以对 Query 使用独立的低秩路径：

$$
c_t^Q=W^{DQ}h_t,
$$

$$
q_{t,i}^{C}=W_i^{UQ}c_t^Q.
$$

Query 只为当前 token 计算，不进入历史 cache。压缩 Query 的主要目标是减少参数或投影计算，并让参数化更统一；KV 压缩才直接决定缓存大小。$d_c$ 与 Query 潜维度 $d_c^Q$ 可以不同。

训练时下投影和上投影一起学习。它是一项从初始化开始参与优化的架构约束，与训练完成后再对普通 MHA 做矩阵压缩属于不同方案。潜维度太小时，多个头共享的内容瓶颈会损失表达能力；维度太大时，缓存收益下降。选择 $d_c$ 需要质量与系统实验共同决定。

参数量也可以直接核算。KV 路径的下投影含 $d_cd$ 个参数，Key、Value 上投影各含 $Hd_hd_c$ 个参数，总计

$$
P_{\text{KV,MLA}}
=d_cd+2Hd_hd_c.
$$

若 $d=Hd_h$，则

$$
P_{\text{KV,MLA}}
=3dd_c.
$$

标准 MHA 的 K、V 投影含

$$
P_{\text{KV,MHA}}=2d^2
$$

个参数。取 $d=4096,d_c=512$，MLA 内容 KV 路径约有

$$
3\times4096\times512
\approx6.29\text{M}
$$

参数，标准 K、V 约有 $33.55$M。实际 MLA 还有 RoPE 分支、Query 压缩和归一化，完整参数量应按实现补齐。

低秩共享还改变 head 间关系。MHA 的每个 head 可从 $h_t$ 直接生成独立 K、V；MLA 的各头先共享 $c_t^{KV}$，再用不同上投影读取。上投影允许各头形成不同子空间，但所有内容信息都要经过共同瓶颈。这个结构与 GQA 的「多个 query heads 共享同一组完整 KV heads」不同：GQA 在 head 维离散共享，MLA 在连续潜空间中共享。

### 潜在缓存的理论大小

若先忽略位置分支，每层每 token 只需缓存 $c_t^{KV}$：

$$
M_{\text{latent/token}}
=Ld_cs.
$$

相对标准 MHA 的压缩比为

$$
\frac{M_{\text{MHA/token}}}
{M_{\text{latent/token}}}
=\frac{2Hd_h}{d_c}
=\frac{2d}{d_c}.
$$

取 $d=4096,d_c=512$，理论比值为

$$
\frac{2\times4096}{512}=16.
$$

但 MLA 还要缓存 RoPE Key 分支，真实压缩比会略低。这个比值也只比较 KV 数据，不包含页表、对齐、量化 scale 等开销。

## 三、矩阵吸收为何避免完整重建

### Key 上投影吸收到 Query

先看无位置 attention score。第 $i$ 个头当前 query 与历史 Key 的点积为

$$
(q_{t,i}^{C})^\top k_{j,i}^{C}.
$$

代入低秩 Key：

$$
(q_{t,i}^{C})^\top W_i^{UK}c_j^{KV}.
$$

利用结合律：

$$
(q_{t,i}^{C})^\top W_i^{UK}c_j^{KV}
=\left[(W_i^{UK})^\top q_{t,i}^{C}\right]^\top
c_j^{KV}.
$$

定义吸收后的 query

$$
\tilde q_{t,i}
=(W_i^{UK})^\top q_{t,i}^{C}
\in\mathbb R^{d_c}.
$$

于是 score 可直接计算为

$$
\tilde q_{t,i}^\top c_j^{KV}.
$$

历史 token 无需逐个重建成 $d_h$ 维 Key。上投影权重作用在当前 query 上，一次计算后即可与全部潜变量点积。

### Value 上投影吸收到输出

设第 $i$ 个头的注意力权重为 $a_{tji}$，普通输出为

$$
o_{t,i}
=\sum_{j\le t}a_{tji}v_{j,i}^{C}.
$$

代入 Value 上投影：

$$
o_{t,i}
=\sum_{j\le t}a_{tji}W_i^{UV}c_j^{KV}
=W_i^{UV}
\left(
\sum_{j\le t}a_{tji}c_j^{KV}
\right).
$$

多头拼接后还要乘输出投影 $W^O$。由于两者都是线性变换，可以把 $W_i^{UV}$ 与 $W^O$ 的对应分块预先组合。运行时先在潜在空间加权求和：

$$
\tilde o_{t,i}
=\sum_{j\le t}a_{tji}c_j^{KV},
$$

再用吸收后的输出矩阵投回隐藏空间。所有历史 Value 同样不必显式重建。

### 吸收前后的计算形状

若直接重建，长度 $S$ 的历史需要为每个 token 生成 $H d_h$ 维 K 和 V，重建计算与中间流量约随

$$
O(Sd_cHd_h)
$$

增长。吸收后，当前 query 的转换约为 $O(Hd_hd_c)$，随后 score 和加权和约为

$$
O(H S d_c).
$$

潜维度 $d_c$ 可能大于单头维度 $d_h$，所以纯点积 FLOPs 未必比 MHA 少。MLA 的主要收益是显著减少 cache 容量和读取字节；真实速度取决于潜维度、head 数、kernel 实现和 batch。缓存压缩不能直接等同于同倍率加速。

## 四、RoPE 为什么需要单独分支

### 位置旋转破坏简单吸收

RoPE 对位置 $t$ 的 Query、Key 施加旋转矩阵 $R_t$。普通 score 形如

$$
(R_tq_t)^\top(R_jk_j).
$$

若 $k_j=W^{UK}c_j$，则

$$
(R_tq_t)^\top R_jW^{UK}c_j.
$$

$R_j$ 依赖历史位置 $j$，位于上投影 $W^{UK}$ 与潜变量之间。不能像无位置分支那样把 $(W^{UK})^\top$ 一次吸收到当前 query，因为每个 $j$ 都有不同的 $R_j$。

若为每个历史 token 先重建完整 Key 再旋转，便失去潜在缓存的主要带宽优势。MLA 因此把内容与位置职责拆开。

### 解耦的 Query、Key 位置分量

对每个头，Query 由内容分量与 RoPE 分量拼接：

$$
q_{t,i}
=
\begin{bmatrix}
q_{t,i}^{C}\\
q_{t,i}^{R}
\end{bmatrix}.
$$

Key 也由内容与位置分量拼接：

$$
k_{j,i}
=
\begin{bmatrix}
k_{j,i}^{C}\\
k_j^{R}
\end{bmatrix}.
$$

内容部分使用前述低秩吸收；维度较小的 $q^R,k^R$ 接受 RoPE。$k_j^R$ 通常在 heads 之间共享，因此每个历史 token 只额外缓存一份位置 Key，而非每头一份。

score 分为两项：

$$
s_{tji}
=
(\tilde q_{t,i})^\top c_j^{KV}
+(R_tq_{t,i}^{R})^\top(R_jk_j^{R}).
$$

第一项在潜在内容空间计算，第二项提供位置相关性。两项相加后再按总维度缩放并进入 softmax。

### 真实缓存与压缩比

若共享 RoPE Key 维度为 $d_r$，每层每 token 缓存为

$$
M_{\text{MLA/token}}
=L(d_c+d_r)s.
$$

相对 MHA 压缩比为

$$
\rho_{\text{cache}}
=\frac{2Hd_h}{d_c+d_r}.
$$

取 $H=32,d_h=128,d_c=512,d_r=64$：

$$
\rho_{\text{cache}}
=\frac{2\times32\times128}{512+64}
\approx14.22.
$$

若仍取 $L=32,s=2$，每 token cache 为

$$
32\times576\times2
=36864\text{ bytes}
=36\text{ KiB}.
$$

4096 token 请求约占 144 MiB，明显低于前面 MHA 算例的 2 GiB。数字只用于展示公式，具体模型维度应以其配置为准。

## 五、实现、边界与验收

### 训练路径与推理路径

训练时通常按易于并行的形式显式生成多头 Q、K、V，再使用高效 attention kernel；推理时则更关注潜在 cache 和吸收形式。两条路径在代数上应等价，但张量布局、缩放与 RoPE 处理不同，容易产生实现偏差。

一种验收办法是在小尺寸、无 dropout、相同 dtype 下构造两条前向：路径 A 显式上投影完整 K、V；路径 B 使用吸收矩阵和潜在 cache。对相同输入比较 score、softmax 权重、层输出与输入梯度。FP64 或 FP32 下应接近数值误差，随后再测试 BF16/FP16。

吸收后的权重可以在加载 checkpoint 时预计算，也可由 kernel 隐式组合。若训练继续更新原始参数，不能缓存旧的吸收矩阵；纯推理 checkpoint 权重固定，才适合一次生成。量化时还要决定先合并后量化，还是分别量化后运行时组合，两者误差与 kernel 支持不同。

以单层、单个 decode step 为例，张量形状可以按以下路径追踪。当前隐藏状态为

$$
h_t:[B,d].
$$

KV 下投影得到

$$
c_t^{KV}:[B,d_c],
$$

并追加到历史 cache

$$
C_{1:t}^{KV}:[B,t,d_c].
$$

Query 内容分量为

$$
Q_t^C:[B,H,d_h],
$$

吸收 Key 上投影后变为

$$
\widetilde Q_t:[B,H,d_c].
$$

与潜在 cache 点积，得到

$$
S_t^C:[B,H,t].
$$

位置分支产生同形状的 $S_t^R$，相加、缩放、softmax 后得到 $A_t:[B,H,t]$。再与 $C_{1:t}^{KV}$ 做加权和，得到

$$
\widetilde O_t:[B,H,d_c].
$$

随后通过吸收后的 Value—输出矩阵映射到 $[B,d]$。逐个写出 shape 能迅速发现错误广播、错误 head 共享和 cache 轴顺序。

显式路径与吸收路径的浮点运算顺序不同。显式路径先计算 $W^{UK}c_j$，再与 $q$ 点积；吸收路径先计算 $(W^{UK})^\top q$，再与 $c_j$ 点积。实数代数上相等，有限精度中会有舍入差异。测试容差应随 dtype、序列长度和归约维度设置，不能要求 BF16 下逐 bit 相同。

Softmax 缩放也必须与拼接后的总维度一致。若内容分量维度为 $d_h$、位置分量为 $d_r$，常见 score 缩放与

$$
\frac{1}{\sqrt{d_h+d_r}}
$$

相关。实现可能为位置分支或长上下文引入额外 scale，阅读代码时要核对最终 logits 上实际使用的乘子。只复现低秩投影而漏掉 scale，会让注意力熵和训练动态改变。

### 容量、带宽和 FLOPs 分开测

缓存容量按

$$
LBS(d_c+d_r)s
$$

核算，并加入分页块、对齐和 scale 元数据。带宽测试记录 decode 每步实际 HBM 读取量，检查是否接近理论潜在 cache 字节。若实现悄悄物化完整 K、V，容量可能仍小，运行时流量却会显著变大。

FLOPs 要分别统计当前 query 投影、潜在 score、潜在 Value 聚合和输出投影。MLA 可能用更多小型变换换取更少 cache 流量。在低并发长上下文下，带宽节省更容易转化成速度；短上下文或高算术强度 prefill 中，收益结构不同。

性能报告至少给出 batch、上下文长度、生成长度、dtype、KV 格式、硬件和 kernel。只汇报最大上下文能放多长，无法说明 TPOT；只汇报单请求速度，也无法说明并发容量。

可以建立一阶带宽模型。每层、每个 decode step，读取潜在 cache 与位置 Key 的字节约为

$$
M_{\text{read/layer}}
\approx BS(d_c+d_r)s.
$$

全部层约为

$$
M_{\text{read}}
\approx LBS(d_c+d_r)s.
$$

若 attention 确实由 HBM 读取主导，延迟下界为

$$
t_{\text{attn}}
\gtrsim\frac{M_{\text{read}}}{\beta_{\text{HBM}}}.
$$

取 $L=32,B=16,S=4096,d_c+d_r=576,s=2$，读取量约为

$$
32\times16\times4096\times576\times2
\approx2.42\text{ GB}.
$$

若可持续带宽为 2 TB/s，纯 cache 读取下界约 1.21 ms。实际还要加 query 变换、score、softmax、输出投影、权重读取和调度。

与同配置 MHA 比较，其 cache 读取约为

$$
2LBSHd_hs.
$$

代入 $H=32,d_h=128$，约为 34.36 GB。两者理论读取比仍约 14.22。端到端速度不会同倍数提升，因为 MLP、投影、通信和采样未被压缩；这正是性能报告需要给出分算子时间的原因。

Prefill 的情况不同。一次处理 $T$ 个新 token 时，矩阵乘规模更大，完整 Q、K、V 可以在片上分块复用；FlashAttention 避免物化 $T\times S$ 分数矩阵。MLA 仍减少写入未来 cache 的数据，并改变 attention 的维度，但 prefill 往往更偏计算受限，cache 带宽收益不如长上下文 decode 直接。

上下文长度越大，cache 项在步时中的占比越高；batch 越大，模型权重读取能被更多请求共享，cache 流量却随请求数同步增加。因此 MLA 的系统收益常随长上下文和高并发更明显。必须用真实长度分布压测，固定短序列 benchmark 很难体现容量优势。

### 常见错误与完整测试

第一类错误是把 MLA 写成每步解压全部历史 K、V。低秩定义没有错，但漏掉矩阵吸收就解释不了推理效率。第二类错误是说 RoPE 与 MLA 完全不兼容；准确描述是位置相关旋转阻止内容 Key 上投影的直接吸收，因此采用解耦的小型 RoPE 分支。

第三类错误是把 $c^{KV}$ 称为 Key 与 Value 的无损压缩。低秩瓶颈由训练共同适配，表达能力取决于潜维度。第四类错误是认为 Query 压缩减少 KV Cache；Query 不跨时间缓存，直接决定 cache 的是 KV 潜变量与 RoPE Key。

测试应覆盖单 token 与多 token prefill、增量 decode、不同 batch、不同历史长度、因果 mask、padding、位置偏移和 cache 分页。将完整序列一次前向的输出，与逐 token 写入并读取 cache 的输出比较。长上下文测试还要覆盖 RoPE 位置扩展，确认 $R_t,R_j$ 使用实际绝对位置。

测试可以从一个完全可手算的小模型开始。设 $H=1,d_h=2,d_c=1$，历史有两个 token，潜变量

$$
c_1=1,\qquad c_2=2.
$$

令

$$
W^{UK}=
\begin{bmatrix}
1\\
3
\end{bmatrix},
\qquad
q=
\begin{bmatrix}
2\\
1
\end{bmatrix}.
$$

显式 Key 为

$$
k_1=
\begin{bmatrix}
1\\
3
\end{bmatrix},
\qquad
k_2=
\begin{bmatrix}
2\\
6
\end{bmatrix}.
$$

显式 score 为

$$
q^\top k_1=5,
\qquad
q^\top k_2=10.
$$

吸收后的 query 为

$$
\tilde q=(W^{UK})^\top q
=1\times2+3\times1=5.
$$

直接与 $c_1,c_2$ 点积同样得到 5 和 10。这个单元测试不含 softmax 与 RoPE，专门验证 Key 吸收的轴和转置。

Value 也可做相同测试。令

$$
W^{UV}=
\begin{bmatrix}
4\\
-1
\end{bmatrix},
$$

attention 权重为 $a_1=0.25,a_2=0.75$。显式 Value 加权为

$$
0.25W^{UV}c_1
+0.75W^{UV}c_2
=1.75W^{UV}.
$$

潜在空间先聚合：

$$
\tilde o
=0.25c_1+0.75c_2
=1.75,
$$

再乘 $W^{UV}$，结果完全相同。加入多头与输出投影后，逐层扩大测试即可。

RoPE 测试则要刻意使用两个不同位置。先计算显式的

$$
(R_tq^R)^\top(R_jk_j^R),
$$

再与内容 score 相加，与实现输出对照。若错误地把 $R_j$ 移到 $W^{UK}$ 外，位置变化时测试会立刻失败。还应验证 cache 被分页搬动后 position id 不变，物理块地址不能替代序列位置。

Tensor parallel 会引入新的布局问题。Key、Value 上投影可能按 heads 或输出维分片，潜变量可以复制或分片；吸收后的矩阵需要与输出投影的分片方式匹配。若每张卡都保存完整 $c^{KV}$，cache 容量没有随并行度下降；若分片，则 attention 可能需要 collective。性能核算要写清每卡缓存和通信字节。

一种方案按潜维度切分 $d_c$。每卡只保存 $d_c/R$ 个元素，score 是各卡局部点积后 all-reduce；Value 聚合也可能在输出前通信。另一种方案按 query heads 切分，所有卡需要访问共享潜变量，但各自计算部分 heads。两者在 cache 复制、通信与 kernel 形状上不同，不存在脱离拓扑的统一最优方案。

KV 量化可与 MLA 叠加。若潜变量从 BF16 压到 8 bit，名义 cache 再减半，但每个量化块需要 scale，并在 score 与聚合时反量化。潜变量是所有 heads 共享的信息瓶颈，量化误差可能同时影响多个 heads；需要逐层、逐长度测量注意力输出误差和最终模型质量。

缓存写入同样需要检查。每生成一个 token，只应把 $c_t^{KV}$ 与 $k_t^R$ 写入 cache。若通用框架仍按 MHA 接口保存展开后的 K、V，模型公式正确也得不到容量收益。查看 allocator 的实际分配、每 token 增量显存与 cache tensor shape，比只读模型配置更可靠。

故障定位可以按层比较。若 prefill 一次前向正确、增量 decode 错误，优先检查 cache 写入、position id 和分页索引；若显式与吸收路径在第一个 token 就不同，检查转置、head reshape、scale 与权重组合；若 FP32 正确、BF16 偏差随长度扩大，检查归约精度和 softmax 稳定性。

训练稳定性还要观察低秩瓶颈是否退化。记录 $c^{KV}$ 的 RMS、奇异值或协方差谱，以及不同 heads 上投影后的有效秩。若大量维度长期接近零，潜空间可能利用不足；若少数方向幅度异常大，量化和低精度归约会更困难。诊断只说明表示分布，是否调整 $d_c$ 仍要结合损失与吞吐。

若要比较 MHA、GQA 与 MLA，可以先统一 query heads、单头维度和层数。MHA 每 token 每层缓存元素为

$$
e_{\text{MHA}}=2Hd_h.
$$

GQA 为

$$
e_{\text{GQA}}=2H_{kv}d_h.
$$

MLA 为

$$
e_{\text{MLA}}=d_c+d_r.
$$

取 $H=32,H_{kv}=8,d_h=128,d_c=512,d_r=64$，三者分别为 8192、2048 和 576 个元素。相对 MHA，GQA 压缩 4 倍，MLA 约 14.22 倍；相对该 GQA，MLA 约 3.56 倍。这个比较只针对 cache，不代表质量或整层速度排序。

还可以计算在固定显存预算下的最大活跃 token 数。设留给 KV 的显存为 $M_{\text{budget}}$，忽略碎片：

$$
T_{\max}^{\text{MHA}}
=\frac{M_{\text{budget}}}
{2LHd_hs},
$$

$$
T_{\max}^{\text{MLA}}
=\frac{M_{\text{budget}}}
{L(d_c+d_r)s}.
$$

若 $M_{\text{budget}}=16$ GiB，采用前述 $L=32$、BF16 配置，MHA 每 token 512 KiB，可容纳约 32768 个总活跃 token；MLA 每 token 36 KiB，可容纳约 466033 个。分页、临时内存和安全余量会降低实值，但数量级展示了为何 cache 压缩能提升并发。

服务容量不能直接把理论 $T_{\max}$ 填满。若平均请求已缓存 4096 token，MHA 理论约容纳 8 个请求，MLA 约 113 个；可当并发升到百级，模型权重、attention 计算、调度和网络可能先达到吞吐或延迟上限。容量计算给出可行域，压测决定其中哪一点满足 SLO。

矩阵吸收还需要检查参数更新语义。训练显式参数 $W^{UK}$ 与 $W^{Q}$ 时，优化器分别维护状态；若为了训练速度直接把它们合成一个自由参数，参数化和梯度约束就改变了。推理吸收是对已训练线性映射的代数重写，训练期把乘积当作独立矩阵则失去低秩分解所施加的结构。

设吸收矩阵

$$
W^{QK}=(W^{UK})^\top W^Q.
$$

若损失对 $W^{QK}$ 的梯度为 $G$，链式法则给出

$$
\frac{\partial\mathcal L}{\partial W^Q}
=W^{UK}G,
$$

$$
\frac{\partial\mathcal L}{\partial W^{UK}}
=W^QG^\top
$$

（具体转置随张量约定调整）。分别优化两个因子，与直接对 $W^{QK}$ 做一步更新不会得到相同结果。因此实现文档要区分训练参数和推理派生权重。

Dropout 也会影响等价测试。attention 权重 dropout 位于 softmax 之后，显式与吸收路径若使用不同随机 mask，输出自然不同；测试时关闭 dropout，或向两条路径注入同一 mask。训练模式下的等价性还要比较反向梯度，确认低秩因子的梯度与显式公式一致。

位置分支的 head 共享方式需要明确。如果 $k_j^R$ 在所有 heads 间共享，cache 只保存 $d_r$；若实现为每个 head 单独保存，则位置 cache 变成 $Hd_r$，压缩比会明显下降。Query 的 $q_{t,i}^R$ 可以逐 head 不同，因为当前 token 的 Query 不需要长期缓存。

计算 cache 时还要确认是否保存归一化前的潜变量。某些实现会在下投影后应用 RMSNorm，再把归一化结果用于上投影；推理 cache 应保存能直接复用的那一版本。若每步读取未归一化 $c^{KV}$ 后再对所有历史位置归一化，会增加计算；若训练与推理缓存不同版本，则输出不一致。

一份实现清单可以按顺序核对：隐藏状态先生成 $c^{KV}$ 与 $k^R$；二者以正确 dtype 和位置写入 cache；当前 Query 生成内容与位置分量；内容 Query 完成 Key 吸收；两路 score 使用相同 mask 和 scale 相加；softmax 权重在潜变量上聚合；聚合结果经 Value—输出吸收矩阵回到隐藏维；残差与输出 dtype 正确。任何一步都能用前述小模型单元测试单独验证。

性能验收应做消融。先只替换 cache 表示，保持未融合实现，验证质量；再启用 Key 吸收，比较 HBM 流量；接着启用 Value—输出吸收与专用 kernel，比较 TPOT；确认基础路径后再加入量化或并行分片。一次开启所有优化，出现偏差时很难定位来自代数、位置、精度还是系统布局。

模型级评估需覆盖长上下文。短任务可能看不出位置分支和潜在瓶颈在大 $S$ 下的误差积累；needle retrieval 也只能检查部分行为，应同时观察长文本困惑度、检索、多轮生成和真实服务输出。系统评估则按长度桶报告，展示 cache 节省何时转化为吞吐与延迟收益。

上线前可设置三组硬门槛：显式与吸收路径的数值误差不超过预定容差；每 token 实测显存增量接近 $L(d_c+d_r)s$ 加元数据；在目标长度与并发下，TPOT、吞吐和输出质量均达到基线要求。若只通过容量门槛，说明公式已减少存储，却未必得到高效 kernel；若速度通过而质量下降，则要回查潜维度、RoPE 分支、缩放或量化，而不能把偏差归为正常加速代价。

MLA 适合放在完整推理账目中理解：权重读取、MLP 计算、attention cache、跨卡通信和调度分别计时。它直接作用于 cache 表示与 attention 数据流，无法减少 MoE 专家通信，也不会自动压缩模型权重。把收益限定到它真正改变的部分，才能准确判断下一项优化应落在哪里。

最终验收同时看质量和系统指标：用相同训练预算比较验证损失与下游任务；用同一 checkpoint 比较显式路径和吸收路径的数值；测量每 token cache、最大并发、HBM 字节、TPOT 与吞吐。MLA 的结论应落在这些可复算量上：它以低秩共享换取 KV 状态压缩，以矩阵吸收避免历史重建，再用小型位置分支保留 RoPE。
