# 第4讲: MoE 的路由、均衡与专家并行

稠密 Transformer 的每个 token 都经过同一组 FFN 参数. Mixture of Experts 将 FFN 替换为多个专家, 路由器只为每个 token 激活少数专家. 总参数量可以随专家数量增加, 单个 token 的 FFN 计算量则主要由激活专家数决定. 这种条件计算是 MoE 的容量来源, 也带来新的训练与系统约束: Top-K 是离散选择, 路由器容易集中到少数专家, 不同 GPU 接收的 token 数可能不均, 专家跨设备部署还会产生 All-to-All 通信.

[主讲义](./4.1-主讲义/4.1-主讲义.md)从稠密 FFN 到专家并行建立整体框架. [Top-K Routing](./4.4-TopK-Routing/4.4-TopK-Routing.md)说明单个 token 如何选择专家, [Load Balancing Losses](./4.2-Load-Balancing-Losses/4.2-Load-Balancing-Losses.md)解释怎样避免路由坍缩, [DeepSeek MoE](./4.5-lecture4-DeepSeek-MoE/4.5-lecture4-DeepSeek-MoE.md)展示 V1 到 V3 如何把模型级均衡推进到设备级和无辅助损失方案. [MLA Attention](./4.3-MLA-Attention/4.3-MLA-Attention.md)不是 MoE 路由组件, 但它与 DeepSeek 的稀疏 FFN 一起降低大模型推理状态成本, 因而作为案例中的另一条效率线索保留.

## 1. 稀疏激活怎样扩大容量

### 1.1 总参数与激活参数

MoE 层包含 $N$ 个路由专家, 每个专家通常是独立 FFN. 对 token 表示 $u_t$, Router 计算它与各专家的亲和度, 只选最高的 $K$ 个执行, 再按门控权重合并专家输出并接回残差流. 当 $K$ 远小于 $N$ 时, 模型能保存大量专家参数, 每个 token 却不必运行所有专家.

“计算量不增加”需要限定参照. 若专家 FFN 与稠密 FFN 同宽, 每 token 激活 $K$ 个专家会产生约 $K$ 倍 FFN 计算; 实际设计会调整专家粒度和激活数, 使激活参数量落在目标预算. Router、token dispatch、跨设备通信、padding 与容量溢出也会带来额外成本. 因而总参数、每 token 激活参数、理论 FLOPs 与实测吞吐必须分别报告.

### 1.2 细粒度与共享专家

把一个大 FFN 拆成更多小专家能提供更细的组合空间. 在相近激活参数量下, Router 可以从更大的专家集合中选择多项组合. 细粒度也会增加被激活专家数量, 若这些专家分散在不同设备, 单个 token 需要参与更多通信.

共享专家绕过 Router, 所有 token 都会执行, 用于承载常见模式; 路由专家负责条件化容量. 这种职责是设计目标, 不能仅凭路由频率证明某个专家确实学到了特定领域. 专家专化需要结合输入分布、激活统计与干预实验分析. **MoE 保证计算路径稀疏, 不自动保证专家获得清晰可解释的分工.**

## 2. Top-K Router 的数据流

### 2.1 从 score 到稀疏门控

[Top-K Routing](./4.4-TopK-Routing/4.4-TopK-Routing.md)给出标准路径. 输入形状为 $[B,L,D]$, 专家向量或 Router 权重形状为 $[N,D]$, 点积产生 $[B,L,N]$ 的 score. 对专家维选择 Top-K 后, 每个 token 只保留 $K$ 个非零门控值. 被选 token 按专家重新排列形成批次, 各专家执行 FFN, 输出再按原 token 位置聚合.

公式中的稀疏门控张量适合说明语义, 高效实现通常不会实际保存完整的 $[B,L,N]$ 输出并让所有专家计算后乘零. dispatch 会直接建立 token 到专家的索引, 只运行选中路径. 反向传播也只更新收到 token 的专家参数, Router 则从门控权重和相关损失获得梯度.

### 2.2 Softmax 与 Top-K 的顺序

不同实现可能先对全部专家 softmax 再选 Top-K, 也可能先选分数再在选中集合内归一化. 前一种方案中, 保留下来的权重和通常小于 1; 后一种方案的 $K$ 个权重和为 1. 若使用 sigmoid score, 专家之间不再通过全局 softmax 直接竞争, 还需要明确选后是否重新缩放.

顺序差异会改变专家输出的整体尺度和 Router 梯度. 阅读实现时要同时检查 score 函数、Top-K 依据、选后归一化、共享专家是否加权以及残差放置. **“Top-K Router”只描述稀疏选择, 并不足以确定门控的数值行为.**

## 3. 负载均衡为何是训练问题也是系统问题

### 3.1 路由坍缩与辅助损失

训练初期, 某些专家可能因为随机优势获得更多 token. 更多 token 带来更多梯度更新, 优势进一步扩大, 最终形成高负载专家与几乎没有更新的专家. [Load Balancing Losses](./4.2-Load-Balancing-Losses/4.2-Load-Balancing-Losses.md)用实际分配比例 $f_i$ 与平均 Router 概率 $P_i$ 构造辅助项. 接收 token 较多的专家会承受更强的降低概率梯度, 从而形成负反馈.

辅助损失权重过小不能阻止坍缩, 过大则可能迫使 Router 追求均匀而牺牲主任务所需的条件分工. 均匀负载也不代表每个 token 都得到相同质量的专家匹配. 训练监控应同时观察主损失、辅助损失、每专家 token 数、Router 概率、溢出或丢弃比例.

### 3.2 从专家均衡到设备均衡

专家并行把不同专家分布在不同 GPU. 即使每个专家接收量相近, 若一个 token 的多个目标专家跨越过多设备, 通信仍可能成为瓶颈; 若专家到设备的放置或路由统计不均, 最慢 GPU 会拖住同步步骤. 因此 DeepSeek V2 等方案加入设备级约束或 Top-M 设备选择, 先限制 token 涉及的设备集合, 再在其中选专家.

系统目标与模型目标可能冲突. Router 希望选择最匹配的专家, 通信系统希望减少目标设备数并平衡每台设备的批次. 实际设计要度量 All-to-All 数据量、每专家容量、token padding 和计算重叠, 不能只看理论激活 FLOPs. capacity factor 或固定专家容量可能在拥塞时丢弃 token 或转移路由, 这也会改变训练信号.

## 4. DeepSeek MoE 的演进

### 4.1 V1 与 V2: 细粒度扩展到设备路由

[DeepSeek MoE](./4.5-lecture4-DeepSeek-MoE/4.5-lecture4-DeepSeek-MoE.md)给出连续案例. V1 采用共享专家与路由专家, 对路由专家执行标准 Top-K, 并通过专家级辅助损失约束负载. 文中配置为 16B 总参数、2.8B 激活参数, 2 个共享专家和 64 个路由专家, 每 token 选择 4 个路由专家. 这些数字共同说明“总容量大、单 token 路径小”的具体含义.

V2 扩展到 236B 总参数与 21B 激活参数, 路由专家增至 160 个, 每 token 激活 10 个. 更细专家提高组合空间, 也使通信问题突出. Top-M device routing 限制单个 token 所访问的设备数, 通信平衡损失则从专家负载之外继续约束设备流量. 这一步表明 MoE 放大后首先暴露的并非公式中的 FFN FLOPs, 而是 token dispatch 的物理位置.

### 4.2 V3: 偏置驱动的在线均衡

V3 的案例为 671B 总参数与 37B 激活参数. 路由 score 与门控归一化方式发生变化, 并引入不参与专家输出权重的校正偏置. 每步根据专家负载调整偏置: 低于目标负载的专家提高选择机会, 高负载专家降低选择机会. 负载控制从主损失梯度中分离, 可以减少辅助损失对模型目标的干扰.

“无辅助损失”仍不等于完全没有均衡约束. 在线偏置更新本身就是显式控制器, V3 还保留较轻的序列级辅助项以处理单个序列中的极端分配. 评估这种方案应检查负载方差、主损失、偏置更新速度与路由稳定性. 步长过大会引起专家负载振荡, 过小则无法及时响应分布变化.

## 5. MLA 是另一条推理效率线

[MLA Attention](./4.3-MLA-Attention/4.3-MLA-Attention.md)压缩的不是专家参数, 而是自回归推理中的 KV cache. hidden state 被下投影为低维潜变量, cache 保存潜变量而非完整 Key 和 Value; 上投影可通过矩阵结合吸收到 Query 或输出计算中. RoPE 的位置依赖旋转会阻止部分权重直接合并, 因而 MLA 把一小部分带位置的 Key 分量单独处理.

MoE 与 MLA 分别压低两类成本. MoE 让每 token 只激活部分 FFN 参数, MLA 减少每层每历史 token 保存的 Attention 状态. 两者组合后, 总权重容量、激活计算、跨设备专家通信与 KV cache 带宽仍需分别核算. 稀疏参数并不会自动缓解 KV cache, cache 压缩也不会消除专家 dispatch.

## 6. 阅读路线

先读[主讲义](./4.1-主讲义/4.1-主讲义.md), 明确总参数、激活参数、专家粒度和专家并行四个坐标. 然后进入[Top-K Routing](./4.4-TopK-Routing/4.4-TopK-Routing.md), 沿 $[B,L,D]$ 到 $[B,L,N]$ 追踪 score 与门控; 紧接着读[Load Balancing Losses](./4.2-Load-Balancing-Losses/4.2-Load-Balancing-Losses.md), 理解实际分配与 Router 概率怎样形成反馈.

掌握标准路径后, 用[DeepSeek MoE](./4.5-lecture4-DeepSeek-MoE/4.5-lecture4-DeepSeek-MoE.md)比较 V1、V2、V3, 重点记录均衡对象从专家扩展到设备, 再转为在线偏置控制的过程. 最后阅读[MLA Attention](./4.3-MLA-Attention/4.3-MLA-Attention.md), 把 DeepSeek 架构中的 Attention cache 优化与 MoE FFN 分开核算. 时间有限时可沿“Top-K—负载均衡—专家并行”主线阅读前三篇; 需要理解 DeepSeek 完整效率设计时再补 V1–V3 与 MLA.
