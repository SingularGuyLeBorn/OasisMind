# 因果注意力: Mask、缓存与三种执行阶段

自回归语言模型把序列概率分解为 $p(t_{1:T})=\prod_i p(t_i\mid t_{<i})$.训练时整段 token 同时送入 Transformer,如果普通全注意力允许位置 $i$ 读取右侧 token,隐藏状态便包含预测目标,交叉熵会通过信息泄漏迅速下降.因果注意力(Causal Attention)用一张与位置有关的可见性矩阵,让每个查询只能读取已经进入条件集合的键值.

## 约束写进注意力公式

### 从 QK 分数到可见性

设 batch 为 $B$,查询头数为 $H$,序列长度为 $T$,单头维度为 $d_h$.投影后

$$
Q,K,V\in\mathbb R^{B\times H\times T\times d_h},
$$

注意力分数为

$$
S=\frac{QK^\top}{\sqrt{d_h}},\qquad S\in\mathbb R^{B\times H\times T\times T}.
$$

$S_{b,h,i,j}$ 表示第 $i$ 个查询位置读取第 $j$ 个键位置前的原始分数.因果 mask 定义为

$$
M_{i,j}=\begin{cases}0,&j\le i,\\-\infty,&j>i.\end{cases}
$$

将 $M$ 广播到 batch 和 head 维:

$$
A=\operatorname{softmax}(S+M),\qquad O=AV.
$$

当 $j>i$ 时,$e^{S_{i,j}-\infty}=0$,对应权重严格为 0.对角线可见,因为位置 $i$ 的隐藏状态读取输入 token $t_i$,随后输出头用该状态预测 $t_{i+1}$.标签右移由 loss 切片完成,不能为了「预测未来」再把注意力对角线遮掉.

**因果 mask 与 padding mask**

因果 mask 回答「位置关系是否允许」,padding mask 回答「这个键是否属于真实样本」.两者通常合并后加到分数上.若样本有效长度为 $L_b$,键位置还需满足 $j<L_b$.查询侧 padding 位置产生的输出可以保留,但 loss 必须忽略;高效 kernel 往往直接跳过这些查询.

左 padding 会让位置编号与张量列号错开.若一条长度 3 的样本左侧补两个 PAD,真实 token 位于列 2、3、4,因果关系仍按有效 token 的 position ID 定义.RoPE position ID、causal offset 和 padding mask 必须一致,否则真实 token 可能读取 PAD 或错误遮住历史.

**四个 token 的手算**

**构造分数与 mask**

取序列 `[我,爱,数,学]`,省略 batch 与 head 维,假设缩放后的分数为

$$
S=\begin{bmatrix}1&2&0&1\\0&1&2&0\\1&0&1&2\\0&1&0&1\end{bmatrix}.
$$

加上 causal mask 后

$$
S+M=\begin{bmatrix}1&-\infty&-\infty&-\infty\\0&1&-\infty&-\infty\\1&0&1&-\infty\\0&1&0&1\end{bmatrix}.
$$

第一行 softmax 为 $[1,0,0,0]$.第二行分母是 $e^0+e^1=1+e$,权重为 $[1/(1+e),e/(1+e),0,0]\approx[0.269,0.731,0,0]$.第三行分母为 $2e+1$,权重约为 $[0.422,0.155,0.422,0]$.第四行在四个历史位置上归一化.

若 Value 是标量 $V=[10,20,30,40]^\top$,第二个位置输出约为 $0.269\times10+0.731\times20=17.31$.未来的 30 和 40 没有进入求和.矩阵公式与逐位置计算做的是同一件事:先在合法键集合内归一化,再加权汇总 Value.

**为什么不能在 softmax 后乘 0/1**

若先对完整分数做 softmax,再把未来权重乘 0,合法权重之和会小于 1.以第一行 `[1,2,0,1]` 为例,完整 softmax 中当前位置权重约 0.197;乘 mask 后仍是 0.197,输出被无故缩小.若再做一次归一化虽可恢复概率和,却多一次计算且容易产生全遮行除零.标准实现是在 softmax 前加负无穷.

**训练、Prefill 与 Decode**

### 训练:整段并行但信息单向

训练输入 shape 通常为 $[B,T]$,一次前向产生所有位置 logits $[B,T,V]$.Attention 在序列维并行计算,因果 mask 保证第 $i$ 行只读 $0\ldots i$.loss 使用 `logits[:, :-1]` 对 `tokens[:, 1:]`.并行计算不等于双向可见;可见性由 mask 决定,执行是否并行由 kernel 决定.

朴素实现会物化 $T\times T$ 分数与 mask,激活显存随 $T^2$ 增长.FlashAttention 按块读取 Q/K/V,在线维护行最大值与归一化分母,无需把完整分数矩阵写回 HBM.它仍执行相同的 causal softmax,只改变 IO 和计算组织.

**Prefill:提示词内部仍是因果的**

推理开始时，长度 $T_p$ 的 prompt 一次进入模型，称为 Prefill。每个 prompt token 只读取它左侧和自身，同时为所有层生成 K/V 并写入 cache。服务从末个有效位置的 logits 采样第一个新 token，前面位置的 K/V 则成为后续 Decode 的历史状态。

前缀语言模型或 encoder-decoder 的 encoder 可以采用双向 mask,不能与 decoder-only Prefill 混淆.聊天 prompt 即使全部由用户提供,decoder-only 模型仍按训练时的因果结构计算;任意改成双向会改变隐藏状态分布,与预训练不一致.

**Decode:一个查询读取整段历史**

生成第一个新 token 后,下一步通常只计算该 token 的查询、键和值.若 cache 已有 $T_c$ 个位置,query length $T_q=1$,key length $T_k=T_c+1$.分数 shape 是 $[B,H,1,T_k]$.唯一查询位于全局位置 $T_c$,所有缓存键都满足 $j\le T_c$,因此无需显式上三角 mask;padding、滑窗或请求拼批仍可能需要 mask.

一次 Decode 若同时处理多个新 token,例如 speculative verification 的 $T_q=m$,每个新查询可以读取全部旧 cache,也只能读取新块中位于自己左侧的 token.mask 是带 offset 的下三角形,条件写成 $j\le T_c+i$.直接使用从零开始的 $m\times(T_c+m)$ 下三角矩阵会错误遮住历史.

**KV Cache 的状态变化**

**缓存什么**

每层缓存历史 K/V,不缓存历史 Q.新查询只使用一次,历史 token 的 K/V 会被所有后续 token 反复读取.标准 MHA 每 token 每层缓存 $2H_{kv}d_h$ 个元素;GQA/MQA 减少 $H_{kv}$,因果规则没有变化.

Prefill 写入 $T_p$ 组 K/V;每次 Decode 追加一组.请求结束或被驱逐后释放对应块.PagedAttention 把逻辑连续位置映射到物理块,mask 和 position ID 使用逻辑位置,不能用物理页号判断因果顺序.

### 滑动窗口与共享前缀

滑动窗口注意力只允许 $i-W+1\le j\le i$,mask 同时施加因果上界和窗口下界.cache 可只保留最近 $W$ 个位置,但 RoPE 等位置编码仍应使用全局 position ID.丢弃旧 KV 不表示位置从零重新开始.

共享系统前缀可以让多个请求复用相同 KV,前提是模型权重、adapter、精度、position ID 和前缀 token 完全一致.任一项不同都会使缓存失效.后续私有 token 只能追加到各自分支,不能写回共享块污染其他请求.

## 数值与实现边界

### 负无穷怎样表示

布尔 mask 交给 fused attention kernel 最安全.手写加法 mask 时可用 dtype 的负无穷;使用 `-1e9` 在 FP16 会溢成 `-inf`,通常结果正确,但跨 dtype 行为不统一.若一整行都被遮住,softmax 会遇到 $0/0$ 产生 NaN,所以每个有效查询至少应有一个合法键,全 padding 行需单独处理.

softmax 应先减行最大值.被 mask 元素不能参与最大值,否则有限的大负数在极端 logits 下可能泄漏非零概率.混合精度 kernel 常用 FP32 计算最大值和归一化和,再把输出转回低精度.

**API 语义容易相反**

不同库对布尔 mask 的定义可能相反:有的 `True` 表示保留,有的表示遮挡.`torch.triu` 只生成三角结构,并不自动决定语义.使用 `is_causal=True` 时还要确认 kernel 如何处理 $T_q\ne T_k$ 的 offset;版本差异曾导致 Decode 或 cache 场景错位.

最小测试不应只看 shape.把未来 token 改成随机值,比较其左侧 logits:正确 causal 实现中,左侧输出应保持不变.再用显式 mask 与 fused causal kernel 对照输出和梯度,覆盖训练方阵、Prefill padding、单 token Decode 与多 token verification 四种 shape.

**工程检查**

**四类常见故障**

第一类是标签泄漏:Attention 未遮未来,或 logits 与同位置标签对齐.表现为训练 loss 异常低.第二类是 mask 方向颠倒,模型只能读未来或只读极少位置.第三类是 padding 与 causal mask 广播维错误,不同 batch 样本互相采用错误长度.第四类是 cache offset 错位,Prefill 正常但 Decode 从第二个 token 开始退化.

单元测试应断言未来扰动不影响过去、合法行权重和为 1、被遮位置权重为 0、缓存解码与无缓存完整前向在相同位置 logits 接近。缓存等价测试需要在 `eval` 模式关闭 dropout，并统一数值精度。

**复杂度口径**

训练与 Prefill 的标准全注意力计算量随 $T^2$ 增长;causal mask 让约一半分数无效,但通用 dense kernel 未必把理论三角节省转成两倍速度.Decode 单步只有一个查询,注意力计算与 cache 读取随历史长度线性增长,常受显存带宽限制.

因此优化要分阶段测量:训练看前反向吞吐与激活显存,Prefill 看长 prompt 的矩阵计算,Decode 看每步 KV 读取、batch 和延迟.**因果 mask 规定信息可见范围;kernel 与缓存策略决定这条约束以多少计算、访存和显存实现.**

### 反向传播中的可见性

**被遮位置为什么没有梯度**

对单个查询行,令 $a_j=\operatorname{softmax}(s_j+m_j)$,输出 $o=\sum_j a_jv_j$.softmax 导数为

$$
\frac{\partial a_j}{\partial s_k}=a_j(\mathbb 1[j=k]-a_k).
$$

未来位置被遮后 $a_j=0$,该位置对分数与 Value 的梯度都为 0.因此左侧位置的 loss 不会通过 Attention 回传到右侧 K/V.位置 $j$ 仍可从自身及右侧查询获得梯度:早期 K/V 被更多后续位置读取,通常也汇集更多梯度路径.

这个性质可以直接测试.取长度 4 的输入,只对位置 0 的 attention 输出求和并反传;位置 1、2、3 通过 K/V 路径得到的梯度应为 0.再把 loss 改成所有位置之和,各位置梯度恢复.测试应隔离纯 Attention,避免卷积或全局 token 提供旁路.

严格因果约束不应由可学习门控代替.合法区域内可以学习稀疏选择,未来区域始终要保持不可见.若用有限负数乘可学习系数,优化过程中可能重新给未来位置非零概率.

**dropout 不改变约束**

Attention dropout 只在合法 softmax 权重上随机置零并重标度.未来位置在 dropout 前已经为 0,不会因此恢复.训练与对照测试若要逐元素比较输出,必须关闭 dropout;检查统计行为时则固定随机种子并确认 mask 不变量仍成立.

**MHA、GQA 与 MQA 的 shape**

**查询头怎样映射到 KV 头**

MHA 中 $H_q=H_{kv}=H$,Q/K/V 都是 $[B,H,T,d_h]$.GQA 使用较少的 KV 头:$Q$ 为 $[B,H_q,T,d_h]$,K/V 为 $[B,H_{kv},T,d_h]$,且 $H_q$ 通常是 $H_{kv}$ 的整数倍.MQA 是 $H_{kv}=1$ 的端点.

查询头 $h$ 对应的 KV 组可写成

$$
g(h)=\left\lfloor\frac{h}{H_q/H_{kv}}\right\rfloor,
\qquad
S_{b,h,i,j}=\frac{Q_{b,h,i,:}K_{b,g(h),j,:}^{\top}}{\sqrt{d_h}}.
$$

causal mask 仍只依赖 $i,j$,在 batch 与查询头维广播.减少 KV 头改变缓存大小和参数共享,不会改变位置可见性.实现无需真的复制 K/V 到 $H_q$ 个头;错误的 `repeat_interleave` 轴可能让 shape 正确却把查询映射到错误组.

### Decode 缓存

Decode 的 Q 常为 $[B,H_q,1,d_h]$,新 K/V 为 $[B,H_{kv},1,d_h]$,缓存为 $[B,H_{kv},T_c,d_h]$.追加后 key length 是 $T_c+1$,输出为 $[B,H_q,1,d_h]$.缓存容量公式使用 $H_{kv}$,不能误用查询头数.

张量并行会把 head 分到不同 rank.mask 不需要按 head 通信,但 position ID、有效长度与 block table 必须一致.当 KV 头少于并行度时,系统可能复制 KV 头或采用专门切分;这是布局选择,数学公式不变.

## Packed sequence 与块对角 mask

### 多文档拼接

为了减少 padding,训练管线会把多篇文档装入固定长度序列.若只用普通下三角 mask,后文档可以读取前文档.需要隔离时,定义 document ID $d_i$,合法条件为

$$
j\le i\quad\text{且}\quad d_j=d_i.
$$

得到的 mask 由多个下三角块组成,块外全部遮挡.对 `[A_0,A_1,A_2,B_0,B_1]`,查询 $B_0$ 只能读自己,$B_1$ 可读 $B_0,B_1$.EOS 属于哪一块、BOS 是否计入 loss 和 position ID 是否重置,都必须由数据协议明确.

只遮 Attention 还不够.标签 shift 也不能跨边界:若 $A_2$ 后是 EOS,它应预测 EOS;EOS 是否预测下一篇 BOS 取决于训练设计.文档打包测试要同时检查可见性与标签,否则模型可能不读取下一篇,却仍被要求预测下一篇开头.

**Varlen kernel**

FlashAttention 的变长接口常用累计长度 `cu_seqlens=[0,L_1,L_1+L_2,...]`,kernel 只在每段内建立 causal tiles,无需物化 $T\times T$ block mask.累计长度错一位会合并相邻样本或截断末尾,而输出 shape 仍可能正常.

构造两篇短文档即可验收:改变第一篇所有 token,第二篇 logits 应保持不变;改变第二篇未来 token,其较早位置也应不变.同时断言所有分段长度之和等于扁平 token 数.

**显式代码与 fused kernel**

**参考实现**

```python
def causal_attention(q, k, v, key_valid=None):
    # q/k/v: [B, H, T, Dh]
    B, H, T, Dh = q.shape
    score = q @ k.transpose(-2, -1) / (Dh ** 0.5)
    allowed = torch.ones(T, T, dtype=torch.bool, device=q.device).tril()
    allowed = allowed[None, None]  # [1,1,T,T]
    if key_valid is not None:     # [B,T]
        allowed = allowed & key_valid[:, None, None, :]
    score = score.masked_fill(~allowed, float("-inf"))
    prob = torch.softmax(score.float(), dim=-1).to(q.dtype)
    return prob @ v
```

这段实现用于核对公式,没有处理空样本与 padding query.若某行所有键都被遮挡,softmax 会产生 NaN.实际数据应保证有效查询至少能读取自身,并在 loss 侧忽略 padding query.

PyTorch scaled dot product attention 可用 `is_causal=True` 选择 fused kernel.不同版本对 `attn_mask` 与 `is_causal` 同时使用、以及 $T_q\ne T_k$ 时的对齐方式可能不同.小张量上应与显式实现比较输出和 Q/K/V 梯度,而不是仅凭 API 名称假设语义.

### 测试矩阵

测试组合至少覆盖 FP32 基准、BF16/FP16、非连续张量、MHA/GQA、训练方阵、单 token Decode 和多 token verification.低精度允许舍入误差,但未来扰动不影响过去、被遮概率为 0、合法行概率和为 1 这三项必须成立.

多 token verification 中 $T_q=m,T_k=T_c+m$.第 $i$ 个新查询可读旧 cache 全部 $T_c$ 个位置以及新块内 $0\ldots i$.显式 allowed 条件是 $j<T_c+i+1$.从零开始画普通下三角会把旧 cache 大片遮掉.

**从训练到生成的完整走查**

**单请求**

训练样本 `[BOS,海,水,蓝,EOS]` 产生四个标签：BOS 预测「海」，「海」预测「水」，「水」预测「蓝」，「蓝」预测 EOS。五个输入位置都有隐藏状态；EOS 后没有标签时，对应位置不计 loss。每层 mask 保证位置 $i$ 读取 $0\ldots i$。

推理 prompt `[BOS,海,水]` 在 Prefill 中一次计算三个位置，并在每层缓存三组 K/V。位置 2 的 logits 用于采样「蓝」。下一步把「蓝」作为输入执行 Decode，生成其 Q/K/V，把 K/V 追加为第 4 个缓存位置，Query 读取四个位置并产生 EOS logits。

采样得到 EOS 后通常直接停止,无需再把 EOS 输入模型.因此某一时刻「已采样 token 数」可能比 cache 中生成 token 数多 1.调试 cache length 时要注明计数发生在采样前、追加前还是追加后.

**批处理与分页缓存**

两个 prompt 长度为 3 和 5，静态 padding 到 5 时，短请求的 key padding 遮掉两格，首个生成 logits 从位置 2 读取，不能固定取张量末列。连续批处理 Decode 中，每个请求有自己的 context length；kernel 用长度与 block table 找到合法历史。

请求结束后物理块可以复用,新请求的逻辑位置仍从自身 0 开始.复用前必须更新 block table 并覆盖有效槽位.mask 依据逻辑长度限制访问,无法修复指向旧块的错误表项.共享前缀则要求 token、模型权重、adapter、精度和 position ID 全部一致.

### 验收顺序

先用四 token 手算核对 mask 方向和 softmax,再用未来扰动测试信息隔离,随后对照显式与 fused 前反向结果.加入 padding、packed document、GQA、Prefill 和 Decode 后逐项扩展,每增加一种 shape 都保留先前不变量.

性能验收分开测训练、Prefill 与 Decode.训练关注前反向吞吐和激活峰值,Prefill 关注长矩阵计算,Decode 关注 KV 读取、batch 与尾延迟.正确性由位置偏序与数值对照决定,速度数据不能替代它.

## 与其他 Attention mask 区分

### 双向、前缀与 Cross-Attention

BERT 类 encoder 使用双向 self-attention,真实 token 之间没有因果上三角,只遮 padding.它适合从完整输入提取表示,不能直接用同样结构训练从左到右的 next-token 生成.若把 decoder-only 预训练模型的 Prefill 临时改成双向,即使 prompt 已知,产生的 K/V 也偏离训练分布.

Prefix LM 把序列分成条件前缀与生成后缀.前缀内部可双向读取,后缀可以读取全部前缀和自身左侧.其 allowed 矩阵不再是单一三角形,而是左上角全可见、左下角全可见、右下角下三角、右上角不可见.训练样本必须明确边界,否则 mask 无法复现.

encoder-decoder 模型的 decoder self-attention 仍然因果;decoder 到 encoder 的 Cross-Attention 则允许每个 decoder 查询读取所有有效 encoder K/V.Cross-Attention 的 score shape 是 $[B,H,T_{dec},T_{enc}]$,使用 encoder padding mask,不使用 $T_{dec}\times T_{enc}$ 的普通 causal 三角形.把两种 mask 混用会错误遮掉源文本后半段.

**局部与稀疏因果 mask**

滑动窗口把合法集合缩为 $\max(0,i-W+1)\le j\le i$.块稀疏 Attention 还可能加入全局 token、固定跨块连接或内容路由.无论合法历史怎样缩小,$j>i$ 的未来位置仍需遮挡.「稀疏」描述合法历史中选哪些键,「因果」描述时间方向,两条轴不能互换.

局部窗口 Decode 只需保留最近 $W$ 个 K/V,但绝对或旋转 position ID 继续按全局位置增加.若把 cache 截断后位置重置为 0,同一 token 在长序列中的位置相位改变.某些专门训练的循环位置方案另有规则,需要按模型配置执行.

**位置编码与 mask 的分工**

### RoPE 不提供因果约束

RoPE 让 Q/K 点积携带相对位置信息,ALiBi 给不同距离加偏置,绝对位置嵌入把位置向量加入 hidden.这些机制影响合法位置之间的分数,不会自动把未来分数变成负无穷.即便位置编码能区分正负距离,没有 causal mask 时模型仍可学习读取右侧 token.

相反,只有 causal mask 而没有任何位置机制时,每行可见 token 数不同,模型能得到部分顺序信号,却难以区分合法历史内部的具体排列.现代 decoder 通常同时使用位置机制与 mask:前者描述位置关系,后者执行不可越过的可见边界.

**Cache offset 必须进入位置编码**

Prefill 的 position ID 为 $0\ldots T_p-1$.第一步 Decode 的新 token 使用 $T_p$,后续依次增加.若 batch 中请求长度不同,每条请求的新 position ID 也不同,不能简单使用 padding 后的统一列号.左 padding 时尤其要由 attention mask 的累计和构造有效位置.

多 token verification 一次生成 $m$ 个 Q,position ID 是 $T_c\ldots T_c+m-1$;causal offset 与这组 ID 使用同一个 $T_c$.两者若相差一格,mask 可能仍不泄漏未来,但 RoPE 相位与 cache 中历史不连续,输出会与逐 token Decode 不一致.

**故障怎样从现象反推**

训练 loss 在第一批就接近 0 时，应检查 label shift 和未来泄漏。训练正常而生成重复或乱码时，对比完整前向与 cache Decode 的逐位置 logits；若第一个 token 一致、第二个开始分叉，常见原因是 cache append、position offset 或矩形 mask。只有 batch 中短请求异常时，优先检查 padding mask 和有效 logits 索引。

长上下文超过某个块边界才异常,检查分页 block table、滑窗截断和 varlen 累计长度.某些 head 正常、某些 head 异常,检查 GQA 分组与张量并行切分.低精度出现 NaN 而 FP32 正常,检查全遮行、有限负 mask、softmax 累加精度和无穷值传播.

调试时保存一个极小确定性样本的 Q/K/V、score、allowed、softmax 权重与输出.大模型端到端生成只显示症状,小张量逐项对照能指出错误发生在投影、位置编码、mask、softmax 还是 cache.修复后把该样本留作回归测试.

### 资源估算

若不采用优化 kernel,分数与概率各需 $BHT^2$ 个元素.以 BF16 计算,单张矩阵约占 $2BHT^2$ 字节,反向还会保存或重算其他状态.因果三角中虽然约一半位置无效,dense 实现仍可能分配完整方阵.FlashAttention 的主要收益正是避免向 HBM 写出这些完整中间量.

KV Cache 每层每 token 元素数为 $2H_{kv}d_h$.若层数 $L$,每元素字节数 $b$,batch 内总缓存长度为 $\sum_rT_r$,容量近似

$$
2LH_{kv}d_hb\sum_rT_r.
$$

这个式子不含 allocator 碎片、block table、临时 workspace 和模型权重.因果 mask 不减少需要保留的合法历史;GQA/MQA、滑动窗口、KV 量化和淘汰策略才直接改变 cache 容量.

Decode 单步读取几乎全部历史 K/V,序列越长,每生成一个 token 的访存越大.连续 batch 能提高并行度,也让总 cache 读取增加.分析延迟时要同时给 context length、并发请求数、KV dtype 与 $H_{kv}$,只报模型参数量无法解释 Decode 性能.

## 一组最小验收样本

长度 1 样本用于检查对角线:唯一查询必须能读取自身,权重为 1.长度 2 样本用于检查方向:第 0 行只读第 0 列,第 1 行读两列.长度 4 的两文档 packed 样本用于检查块边界.一个带左 padding、一个带右 padding 的 batch 用于检查 position ID 与有效 logits 索引.

随后用同一组 token 分别运行完整前向和「Prefill 加逐 token Decode」,逐位置比较 logits.再把 Decode 改为一次验证两个 token,比较矩形 offset mask.这三条路径结果一致,才能说明 cache 与 mask 没有因执行方式改变数学语义.

测试失败时不要先放宽误差.被遮位置非零、未来扰动影响过去属于逻辑错误,没有数值容差;只有合法区域的浮点差异才使用 `atol` 与 `rtol`.BF16 与 FP16 的阈值可比 FP32 宽,但应记录最大误差发生在哪个位置和 head.

完成正确性检查后再测 fused kernel.基准包含短序列、小 batch、大 batch、长 Prefill 和长 cache Decode,并预热、同步设备、报告分位延迟.这样得到的性能数据才能对应本文定义的同一项因果计算.

实现更换 kernel、缓存布局或并行策略后,这组小样本都应重新运行.它们覆盖的位置关系不会随优化变化,因此适合作为持续集成中的长期稳定自动回归门槛.
