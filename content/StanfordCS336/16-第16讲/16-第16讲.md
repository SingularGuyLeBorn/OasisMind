# 第16讲: 大模型强化学习与可验证奖励

偏好模型能够评价开放式回答,却也带来一个直接问题:policy 会寻找 reward model 容易给高分的输出,而 reward model 对分布外回答未必可靠.数学题、代码题和带确定规则的任务提供了另一类训练信号.答案可以由 exact match、单元测试、编译器或形式验证器判断,reward 不必完全依赖另一个神经网络的主观评分.**可验证奖励把强化学习的反馈端变得更可靠,但模型仍要解决稀疏奖励、长轨迹信用分配和有效探索.**

这一讲从第15讲的 RLHF 继续向 reasoning policy 训练推进.先明确语言模型里的 trajectory、action 与 reward,再看 PPO 为什么维护 value model,GRPO 怎样用同一 prompt 的一组回答构造相对优势,最后把算法放回 DeepSeek-R1 的训练路线.重点不在记住新的缩写,而在跟清一条样本从 prompt、rollout、验证、advantage 到 policy update 的完整路径.

## 语言模型中的强化学习对象

给定 prompt $x$,policy 逐 token 生成 $y=(a_1,\ldots,a_T)$.第 $t$ 步的 state 是 $s_t=(x,a_{<t})$,action 是下一个 token $a_t$.一条 trajectory 的概率为

$$
\pi_\theta(y\mid x)=\prod_{t=1}^{T}
\pi_\theta(a_t\mid x,a_{<t}).
$$

验证器通常在完整回答结束后给出序列级 reward $R(x,y)$.如果只有最终的 0 或 1,前面每个 token 都共享同一条稀疏结果;策略梯度仍然可以估计,但方差很大.模型还可能用正确答案配上无效推导,或者输出验证器解析漏洞.因此 verifier 的输入规范、答案抽取、超时、测试覆盖和反作弊逻辑都属于训练目标的一部分.

[主讲义](./16.1-主讲义/16.1-主讲义.md)把 policy gradient、PPO 与大模型 rollout 放进同一个数据流.对旧策略 $\pi_{\theta_{\mathrm{old}}}$ 采样得到 token 后,新策略的 importance ratio 是

$$
r_t(\theta)=
\frac{\pi_\theta(a_t\mid s_t)}
{\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)}.
$$

PPO 用 $\min(r_tA_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t)$ 限制一次更新对样本概率的改变.$A_t$ 的符号决定裁剪哪一侧生效;正优势鼓励 action,负优势压低 action.语言模型实现还会叠加 reference KL、长度 mask 与 minibatch 更新,所以必须记录 rollout policy 的版本,不能拿无法对应旧策略概率的样本直接计算 ratio.

## 从 value baseline 到组内相对优势

Actor-Critic 用 value model 估计 $V(s_t)$,以 $R_t-V(s_t)$ 作为 advantage 的基础.Baseline 不改变策略梯度期望,前提是它不依赖当前采样 action;它的作用是降低方差.大模型 RL 里的 value network 需要为每个 token 输出标量,训练、部署和同步都增加成本,而且 reward 分布会随着 policy 提升而变化.

[GRPO 数学细节](./16.3-GRPO-Math/16.3-GRPO-Math.md)采用另一种 baseline.对同一个 prompt $x_i$ 一次采样 $G$ 条回答,得到 rewards $R_{i,1},\ldots,R_{i,G}$,用组内均值和标准差构造

$$
\widehat A_{i,g}=
\frac{R_{i,g}-\mu_i}{\sigma_i+\varepsilon},
\qquad
\mu_i=\frac{1}{G}\sum_{g=1}^{G}R_{i,g}.
$$

每条回答的相对优势再广播到对应 completion token,进入 PPO 风格的 clipped objective.这样省掉独立 value model,也让不同难度 prompt 的 reward 在组内比较:一道几乎没人做对的题,只要某个 rollout 相对更好,也能得到正优势.代价是每个 prompt 必须生成多条回答,估计质量依赖组大小;当一组 reward 完全相同时,标准差为 0,所有相对优势接近 0,这个 prompt 在该 batch 中几乎不提供 policy gradient.

**GRPO 改变的是 advantage 的估计方式,没有消除 policy ratio、旧策略版本与 KL 约束.**组内归一化还会丢掉 prompt 之间的绝对 reward 差异.若所有 easy prompt 都得到满分,它们不再贡献区分信号;这可能正好把算力转向未解决问题,也可能浪费大量重复 rollout.数据采样与难度课程因此会直接影响有效梯度比例.

## 可验证奖励怎样进入训练

数学任务可以抽取最终答案并做等价判断,代码任务可以运行测试,形式化证明可以交给 proof checker.一个可靠 verifier 至少要区分「解析失败」「运行失败」「超时」「测试未通过」和「通过」,这些状态是否映射成同一个 0 reward 取决于训练设计.只给二元结果最简单,但无法区分接近正确与完全无关的输出;加入格式奖励或过程奖励可以变密,错误的 shaping 又可能让 policy 优先满足格式而忽略答案.

RLVR 的数据也不只是题目集合.题目是否出现在预训练或 mid-training 数据中,会改变初始成功率;verifier 是否有隐藏测试,会改变作弊空间;采样温度和每题 rollout 数决定探索范围;过滤掉始终全对或全错的题,会改变训练分布.一个 batch 的有效样本比例可以用「组内 reward 方差大于 0 的 prompt 数」衡量,这比只报告平均 reward 更能说明 GRPO 是否获得了比较信号.

题目难度需要与当前 policy 匹配.若每组 rollout 全错,二元 reward 下所有 advantage 都接近 0;若每组全对,同样没有相对排序.课程学习可以按近期成功率调节采样权重,让 batch 保留一定比例的可区分 group.这个策略也有代价:持续追逐中等难度题可能降低对极难领域的探索,所以训练集还要保留一部分固定分布,用来观察真实进步而不是采样器变化.

Verifier 的计算成本会反过来限制 rollout.代码执行与形式证明检查可能远慢于字符串匹配,还可能出现无限循环、资源滥用和非确定性.执行环境应固定依赖、限制 CPU、内存与墙钟时间,并把失败原因写入样本记录.若 verifier version 发生变化,旧 reward 不能悄悄与新 reward 混用,否则同一个数值在两个 batch 中代表不同判定规则.

当 reward 只在末尾给出,同一条回答内所有 token 常共享序列 advantage.这个做法无法区分正确推理步骤、无关铺垫和碰巧猜中的最终答案.Process reward model、step verifier 或 token-level credit assignment 试图提供更细反馈,但会引入新的标注和泛化误差.可验证最终答案保证的是 outcome 可检查,并不自动保证 reasoning trace 忠实或有效.

## DeepSeek-R1 路线说明了什么

[DeepSeek-R1 技术报告](./16.2-DeepSeek-R1/16.2-DeepSeek-R1.md)把 GRPO、可验证任务和 reasoning behavior 放到较大规模上观察.R1-Zero 从 base model 出发直接做强化学习,展示了长 reasoning、反思与自我检查等行为可能在 reward 驱动下出现;R1 则加入冷启动数据和多阶段训练,以改善可读性、语言混杂和通用任务表现.这里要分清研究观察与因果结论:训练流程同时改变数据、reward、采样和后续 SFT,最终模型能力不能只归因于 GRPO 这个算法名.

Reasoning length 上升也不是独立目标.更长的 trajectory 提供更多搜索步骤,同时增加 rollout 成本、错误传播和无效重复.训练时应联合观察 pass rate、每题 token、不同采样预算下的 pass@k、格式失败与 reward 分布.只看平均输出长度,很容易把冗长误认成推理能力.

还要区分单次能力与采样能力.Pass@1 衡量一次生成的成功率,pass@k 同时受单样本质量与样本多样性影响.提高温度或增加 $k$ 可能让 pass@k 上升,却让每次调用更贵;训练后的比较应固定采样协议,并同时报告 token budget.否则一个系统靠生成更多候选获得的提升,会被误写成 policy 本身在单次回答上更可靠.

训练数据还应保留未参与更新的固定验证集.动态课程反映当前学习效率,固定集合用于判断跨 step 的真实变化.两者混在一起时,平均 reward 上升可能只说明采样器挑了更容易的题.

第16讲最终建立的是一条可复查的训练链:当前 policy 对每个 prompt 生成一组回答,verifier 按明确协议返回 reward,组内统计量构造 advantage,旧策略概率与 reference KL 约束更新幅度,更新后的 policy 再产生下一轮数据.任何环节的版本、mask 或样本身份错位,都会让公式仍能运行却失去原来的统计含义.
