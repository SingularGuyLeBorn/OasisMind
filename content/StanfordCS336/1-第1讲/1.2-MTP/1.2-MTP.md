# 多 Token 预测: 从移位目标到顺序预测模块

标准自回归语言模型在位置 $i$ 读取 $t_{\le i}$,预测紧邻的 $t_{i+1}$.一段长度为 $T$ 的序列仍然会产生约 $T$ 个监督项,所以「一次只预测一个 token」不表示一个序列只有一个标签.多 Token 预测(Multi-Token Prediction,MTP)改变的是每个位置的预测跨度:除了 $t_{i+1}$,模型还学习 $t_{i+2},t_{i+3}$ 等更远目标.同一份文本由此从多个偏移量向隐藏状态提供梯度.

这个改动看起来只是把标签多移几格,实际有两个困难.第一,所有预测都必须遵守因果约束,第 $k$ 个预测头不能提前读取目标 $t_{i+k+1}$.第二,多个未来 token 彼此相关;若各预测头完全独立,它们只共享主干表示,无法表达「先预测近处,再利用近处目标构造更远预测状态」的顺序关系.DeepSeek-V3 采用顺序 MTP 模块处理第二个问题,但这些模块在训练时会读取移位后的真实 token 嵌入,因此不能直接当成普通自回归解码器理解.

## 从 next-token loss 到多偏移监督

### 标签到底怎样移动

设输入 token 为 $t_1,\ldots,t_T$,主干 Transformer 输出 $h_i^0$.标准语言模型头给出

$$
p_i^0=\operatorname{softmax}(W_o h_i^0),\qquad p_i^0\approx p(t_{i+1}\mid t_{\le i}).
$$

有效位置是 $i=1,\ldots,T-1$;输入最后一个 token 后,若样本没有额外的 EOS,便没有下一个标签.实现时常把 logits 的最后一列丢掉,把 labels 的第一列丢掉.若批量张量 `tokens` 的 shape 为 $[B,T]$,主 logits 为 $[B,T,V]$,其中 $V$ 是词表大小,则交叉熵接收 `logits[:, :-1, :]` 与 `tokens[:, 1:]`.两者展平后分别是 $[B(T-1),V]$ 和 $[B(T-1)]$.

第 $k$ 个 MTP 深度预测 $t_{i+k+1}$.它相对当前位置多跨过 $k$ 个 token,所以有效位置缩短为 $T-k-1$.对应 logits 与标签可写成

$$
P^k\in\mathbb{R}^{B\times(T-k-1)\times V},\qquad
Y^k=(t_{k+2},\ldots,t_T).
$$

偏移量最容易出现 off-by-one.若把主目标称为 depth 0,则 depth 0 预测下一 token,depth 1 预测下下个 token.有些文章把第一个额外头称为「第 1 个 MTP 头」,又把它描述为预测第 2 个未来 token;两种编号都可以,但公式、切片和日志必须采用同一约定.

**一个可以手算的例子**

取序列 `[春, 风, 又, 绿, 江, 南]`,忽略 BOS 与 EOS.主损失使用五对监督:`春→风`、`春风→又`、`春风又→绿`、`春风又绿→江`、`春风又绿江→南`.depth 1 使用四个更远目标:位置「春」预测「又」,位置「风」预测「绿」,位置「又」预测「江」,位置「绿」预测「南」.depth 2 只剩三个目标.

假设 depth 1 在四个正确 token 上给出的概率依次为 $0.5,0.25,0.5,0.125$,该深度的平均负对数似然是

$$
L_\text{MTP}^{1}=-\frac{1}{4}\log(0.5\times0.25\times0.5\times0.125)
=\frac{9}{4}\log2.
$$

这里必须按有效 token 数平均,不能继续除以原序列长度 $T$.批内若有 padding,分母还应是未被 mask 的标签数.否则短样本、不同 MTP 深度和不同 padding 比例会得到不一致的权重.

### DeepSeek-V3 的顺序 MTP 模块

**每层接收什么**

DeepSeek-V3 技术报告中的第 $k$ 个 MTP 模块把前一深度的表示 $h_i^{k-1}$ 与目标移位后的 token 嵌入 $E(t_{i+k})$ 拼接,分别归一化后再投影:

$$
h_i^{\prime k}=M_k[\operatorname{RMSNorm}(h_i^{k-1});
\operatorname{RMSNorm}(E(t_{i+k}))].
$$

$[a;b]$ 表示沿 hidden 维拼接.若两项都是 $d$ 维,拼接结果是 $2d$,投影矩阵 $M_k$ 把它压回 $d$.对一批序列而言,第 $k$ 层参与计算的张量长度会随偏移缩短;工程实现也可以保留统一的 $T$ 长度再用 loss mask 排除无标签位置,但注意力 mask 与标签 mask 不能混为一件事.

投影后的序列进入该深度自己的 Transformer block:

$$
h_{1:T-k}^{k}=\operatorname{TRM}_k(h_{1:T-k}^{\prime k}),\qquad
p_{i+k+1}^{k}=\operatorname{softmax}(W_o h_i^k).
$$

嵌入层 $E$ 与输出头 $W_o$ 可以和主模型共享,每个深度保留自己的投影与 Transformer 模块.共享词表两端的参数让所有深度在同一 token 空间学习,额外参数主要来自 $M_k$ 和 $\operatorname{TRM}_k$.「额外预测几个位置」并非零成本:训练会增加前向计算、激活保存和反向传播开销.

### 为什么仍然满足因果性

第 $k$ 层在位置 $i$ 读取了 $E(t_{i+k})$,随后预测 $t_{i+k+1}$.它没有读取自己要预测的 token.例如 depth 1 在基础位置 $i$ 读取 $t_{i+1}$ 的真实嵌入,目标是 $t_{i+2}$.这相当于训练阶段的 teacher forcing:已知前一个真实 token,学习再向前一步.模块内部仍使用 causal mask,位置 $i$ 不能访问移位序列中位于其右侧的内容.

这也划出了推理边界.训练时的真实 $t_{i+k}$ 在生成阶段尚不存在,不能把训练图原封不动地用于免费预测多个未来 token.若要让 MTP 帮助解码,需要把模块产生的候选当作草稿,再由主模型验证;接受规则必须保证最终采样分布符合目标模型.仅仅一次输出多个 argmax 会改变生成分布,也可能让早期错误连续传播.

## 损失怎样组合

### 各深度先独立归一化

第 $k$ 个额外深度的交叉熵为

$$
L_\text{MTP}^{k}=-\frac{1}{N_k}\sum_{(b,i)\in\mathcal V_k}
\log p_{b,i}^{k}[t_{b,i+k+1}],
$$

$\mathcal V_k$ 是该深度有效的 batch 与位置集合,$N_k=|\mathcal V_k|$.训练总目标写成

$$
L=L_\text{main}+\frac{\lambda}{D}\sum_{k=1}^{D}L_\text{MTP}^{k},
$$

$D$ 是额外预测深度,$\lambda$ 控制辅助目标相对主 next-token loss 的权重.先对每个深度按自己的有效 token 数归一化,再在深度间求平均,可以避免较近目标仅因位置更多便占据更大权重.

$\lambda$ 太小,MTP 梯度几乎不起作用;太大,主干会优先适配辅助模块,主 next-token 目标可能受损.更远目标的条件熵通常更高,其损失数值和梯度方差也可能更大.因此训练日志至少应分别记录 $L_\text{main}$、每个 $L_\text{MTP}^k$、有效 token 数与梯度范数,只看加权总损失无法判断哪个深度失稳.

**梯度流向**

辅助损失会更新对应的 MTP 模块、共享输出头、共享嵌入以及产生 $h^0$ 的主干.这正是它能影响预训练表示的原因.若误把 $h^0$ `detach`,辅助模块仍可学会在固定表示上预测,但 MTP 不再为主干增加训练信号.相反,若各深度串联且全部反传,较早表示会同时接收多个深度的梯度;深度增加后需要关注梯度尺度与额外激活显存.

参数共享还会产生梯度汇合.主损失和所有辅助损失都通过 $W_o$ 写入词表方向,嵌入共享时也共同更新 $E$.分布式训练中这些参数的归约方式必须和主模型一致,否则某些 rank 只计算部分 MTP token 时会造成梯度口径不一.

### 训练收益、推理用途与失败模式

**MTP 增加了什么监督**

next-token loss 已经覆盖序列中的每个相邻位置,MTP 增加的是同一上下文对更远位置的约束.近处 token 往往受局部语法影响,更远 token 需要隐藏状态保留能够跨过中间词仍有用的信息.因此 MTP 可以被理解为对表示的额外训练要求,而不能简单表述成「标签数量从一个变成多个」.

辅助目标是否改善最终模型仍需由消融确定.比较时要保持训练 token、总 FLOPs 或墙钟时间中的至少一种口径明确;加入 MTP 后每 token 计算量上升,若两组实验只固定训练步数,有 MTP 的一组实际用了更多计算.还要区分主模型质量变化与推理解码加速:前者看移除 MTP 模块后的主模型评测,后者取决于候选接受率、验证开销和服务 batch.

顺序模块也能为推测解码提供候选.当连续候选与主模型分布一致时,一次验证可接受多个 token;候选错误则会缩短接受长度.实际吞吐由平均接受长度、额外模块耗时、主模型验证方式和并发调度共同决定.单请求延迟下降并不自动等于高并发吞吐提高.

### 最容易写错或实现错的地方

第一类错误是标签泄漏.若 depth $k$ 的输入切片包含 $t_{i+k+1}$,模型会直接看到答案,训练损失异常低而生成无效.检查方法是为极短序列打印每个位置可见的 token 与目标,同时验证 causal mask.

第二类错误是移位与分母不一致.不同深度有效长度不同,padding 后更要用标签 mask 统计 $N_k$.把 padding ID 当普通标签、把各深度都除以 $BT$、或者 logits 与 labels 错开一位,都会产生看似平滑但口径错误的损失.

第三类错误是把训练能力直接等同于推理能力.训练阶段读取真实的移位 token,生成阶段只能读取已经接受的 token 或自己提出的候选.任何并行吐出多 token 的方案都需要说明候选如何生成、主模型如何验证、拒绝后从哪里恢复.

第四类错误是忽略计算预算.额外模块提高每个训练 token 的 FLOPs 和激活显存.公平消融应同时报告 $D$、$\lambda$、模块层数、共享参数、训练 token、总计算量以及主模型推理时是否移除这些模块.只有这些口径齐全,才能判断收益来自更密集的监督、更多参数还是更多计算.

实现完成后可以用四项小测试封住边界:用人工序列核对所有 shift;把未来 token 随机打乱并确认对应深度损失上升;令 $\lambda=0$ 验证主训练退化为标准 next-token objective;保存并移除 MTP 模块后,确认主干与输出头仍能独立完成自回归生成.这四项分别检查索引、信息泄漏、损失组合和部署边界.

## 从公式落到训练代码

### 一次前向怎样组织张量

设主干输出 `hidden` 的 shape 为 $[B,T,d]$,token 嵌入 `emb` 同样为 $[B,T,d]$.以 depth 1 为例,前一深度状态取 `hidden[:, :-1]`,移位嵌入取 `emb[:, 1:]`;两者都含 $T-1$ 个位置.拼接后得到 $[B,T-1,2d]$,经 $M_1$ 投影回 $[B,T-1,d]$,再进入 causal Transformer block.输出头产生 $[B,T-1,V]$,但最后一个位置没有 $t_{T+1}$ 标签,所以计算损失时还要缩到 $T-2$ 个位置.

depth 2 接收 depth 1 的状态和再向右移动一格的真实 token 嵌入.若实现选择在每层立即裁短,则第 $k$ 层入口长度为 $T-k$,损失长度为 $T-k-1$.若实现选择一直保留 $T$,就必须维护一张随深度变化的有效位置 mask.前者更容易读懂且减少无效计算,后者便于把不同深度堆进统一容器.两种写法产生的有效监督应完全相同.

下面的伪代码强调切片关系,省去了分布式并行与 fused kernel:

```python
def mtp_loss(tokens, hidden0, embed, modules, out_head):
    # tokens: [B, T], hidden0: [B, T, d]
    token_emb = embed(tokens)                 # [B, T, d]
    previous = hidden0
    losses = []

    for depth, module in enumerate(modules, start=1):
        input_len = tokens.size(1) - depth
        previous = previous[:, :input_len, :] # [B, T-depth, d]
        shifted = token_emb[:, depth:, :]     # [B, T-depth, d]
        state = module(previous, shifted)      # [B, T-depth, d]

        logits = out_head(state[:, :-1, :])   # [B, T-depth-1, V]
        labels = tokens[:, depth + 1:]         # [B, T-depth-1]
        losses.append(masked_ce(logits, labels))
        previous = state

    return sum(losses) / len(losses)
```

`previous` 与 `shifted` 的长度断言是最有价值的检查.还应断言 `logits.shape[:2] == labels.shape`,并在 `masked_ce` 中用非 padding 标签计数.若数据以多个文档拼接成固定长度序列,还要决定跨文档边界的目标是否合法.通常会用 document mask 阻止一个文档末尾预测下一个无关文档的开头;MTP 跨越的距离更远,边界 mask 也要随 depth 扩张.

### 并行训练中的额外状态

采用 tensor parallel 时,共享输出头往往按词表维或 hidden 维切分,MTP logits 应复用主头的并行实现,否则额外 all-gather 会吞掉收益.采用 sequence parallel 时,右移后的 token 嵌入可能跨 rank 边界;每个 rank 需要取得相邻分片开头的少量 token,或者在切分前完成 shift.如果简单地在本地分片内右移,每个分片边缘都会丢掉本应存在的训练目标.

pipeline parallel 还会影响模块放置.把 MTP 模块全部挂在最后一个 stage,实现最直观,但最后一级的计算和激活明显增加,流水线可能重新失衡.将模块拆到其他 stage 又会引入主干末层状态的通信.因此报告 MTP 训练开销时,除了总 FLOPs,还应给出最慢 pipeline stage 的时间和显存峰值.

共享嵌入与输出头意味着 MTP 参数不能被优化器重复登记.常见错误是主模型和辅助模块各自持有同一 Parameter 引用,构造参数组时重复加入,导致更新两次或框架直接报错.保存 checkpoint 时也应明确辅助模块是否独立命名;部署只加载主干时,缺少辅助键应是预期行为,而不是静默漏掉主模型参数.

## 与独立预测头和推测解码的关系

### 并行头与顺序模块回答不同问题

一种更直接的 MTP 方案是在同一 $h_i^0$ 上挂 $D$ 个输出头,第 $k$ 个头预测 $t_{i+k+1}$.它的优点是所有头可并行计算,结构简单;缺点是不同深度仅通过共享主干发生联系,更远预测不能接收中间 token 信息.顺序 MTP 则把前一深度状态和移位 token 嵌入送入下一模块,显式构造预测链,代价是层间串行和额外 Transformer 计算.

两者不能只按「预测几个 token」归为同一实现.对独立头而言,depth 2 直接估计 $p(t_{i+3}\mid t_{\le i})$;对训练阶段的顺序模块而言,depth 2 的计算还接收真实的 $t_{i+1},t_{i+2}$ 所形成的信息链.条件集合不同,损失难度和推理转换方式也不同.比较论文结果时需要先确认采用哪一种结构.

MTP 与 span corruption 也有区别.后者遮住一段内容并根据双向或特定可见上下文复原,可见信息由 corruption scheme 决定;自回归 MTP 保留从左到右的因果方向.它也不同于把未来 token 拼成一个超级类别:输出空间仍是原词表,每个位置分别计算交叉熵,不会产生 $V^D$ 的组合词表.

**推测解码为何需要验证**

假设 MTP 模块一次提出 $y_1,y_2,y_3$,主模型可以对拼接后的候选做一次前向,得到各位置的目标分布.贪心解码中,从左到右比较候选与主模型 argmax,接受最长一致前缀;采样解码则需要拒绝采样校正,不能用「概率差不多」代替严格接受规则.一旦第一个候选被拒绝,其后的候选所依赖的前缀已经改变,不能继续接受.

加速比有明确上限.设一次平均提出 $D$ 个候选,平均接受 $a$ 个,MTP 草稿耗时为 $C_d$,主模型批量验证耗时为 $C_v$,普通单 token 解码耗时为 $C_1$.粗略吞吐收益取决于 $(a+1)C_1/(C_d+C_v)$,其中额外的 $1$ 表示验证轮通常还产生一个主模型 token.当接受率低、验证无法高效并行或服务端已有很大 batch 时,MTP 可能只增加复杂度.

评测应把质量与速度分开.质量侧在相同解码分布下比较输出,确认验证算法没有改变目标分布;速度侧报告 batch、输入长度、输出长度、硬件、精度、平均接受长度、P50/P95 延迟和吞吐.只给「一次预测四个 token」无法推出四倍加速.

### 怎样设计可信的消融

**固定预算与拆分变量**

最基本的对照包含标准 next-token 基线、增加等量普通 Transformer 参数的基线、启用 MTP 但推理时移除模块的模型.第一组测总收益,第二组区分「额外监督」和「单纯增加参数」,第三组确认收益是否已经进入主干.若还要讨论推测解码,再单独比较不同候选深度和验证策略.

固定训练 token 可以回答相同数据量下谁更好,但 MTP 使用更多计算;固定总 FLOPs 更接近预算公平,却会让 MTP 模型看到更少 token.两种口径都值得报告.墙钟时间还受 kernel、并行划分与硬件利用率影响,不能由理论 FLOPs 直接替代.

消融 $D$ 时应同时观察各深度损失.若较远深度始终接近随机猜测,继续增加 $D$ 只会消耗计算;若远处损失下降但主损失变差,可能需要减小 $\lambda$ 或改变模块容量.消融 $\lambda$ 时不能只看训练总损失,因为不同权重下总损失本身没有直接可比性,应比较未加权的主损失和下游指标.

### 数据边界会改变任务难度

代码、数学与自然语言的可预测跨度不同.格式固定的代码可能在局部产生很高接受率,开放式文本的后续分支更多.短文档拼接会让远距离目标频繁跨边界,若不屏蔽便把无关 token 当标签.重复数据还可能让更远预测看起来异常容易.因此 MTP 实验需要报告数据类型、文档拼接规则、EOS 处理和去重策略.

Tokenizer 同样改变跨度含义.预测未来四个英文子词与未来四个中文字节级 token 覆盖的字符距离不同.跨模型比较 $D$ 时,至少同时报告平均每 token 字符数或序列压缩率.这也是 MTP 紧接 Tokenizer 之后学习的原因:训练目标的「一步」由分词协议定义.

最后检查模型是否学到短路.若顺序模块容量很强,它可能主要依靠真实移位嵌入完成局部预测,对主干施加的有效压力有限.可以遮掉或扰动部分移位嵌入做诊断,观察各深度损失和主干梯度怎样变化;这项诊断不是新的训练方案,只用于辨认信息来源.

## 复算一遍索引与边界

### 带 BOS、EOS 和 padding 的完整样本

设原文本编码为 `[BOS,A,B,C,EOS,PAD]`,有效长度为 5.主目标的输入位置依次是 `BOS,A,B,C`,标签是 `A,B,C,EOS`;PAD 不参与损失.depth 1 可用的输入位置是 `BOS,A,B`,移位嵌入来自 `A,B,C`,标签是 `B,C,EOS`.depth 2 则只剩 `BOS,A` 两个位置,移位链最终预测 `C,EOS`.这个例子说明 EOS 是合法预测目标,而 EOS 后面的 PAD 不是.若把 EOS 与 PAD 配成同一个 ID,必须额外保存长度或 attention mask,否则无法仅凭 token ID 区分两者.

打包多个文档时,例如 `[BOS,A,EOS,BOS,X,EOS]`,depth 1 在位置 `A` 上不能把第二篇的 `BOS` 当成更远标签.构造有效 mask 的稳妥方法是给每个 token 保存 `document_id`,只有当前位置到目标位置沿途的 document ID 相同才保留监督.仅检查目标不是 BOS 仍不充分,因为不同数据管线可能省略 BOS 或使用别的分隔符.

位置编码也要和切片同步.若 MTP 模块处理的是裁短后的序列,其 position ID 通常仍对应基础位置 $i$,而移位 token 嵌入代表 $t_{i+k}$.不能因为嵌入向右移动就把整个模块的 causal position 一并改成 $i+k$,否则主干状态、mask 与旋转位置相位可能不再处于同一参照系.具体实现应遵循论文和代码定义,并用逐位置测试确认.

### 训练日志如何判断正常

训练初期,更远深度通常比近处深度难,但损失大小还受词频、模块容量与输入真实 token 的数量影响,不能规定它们必须严格单调.可靠信号是各深度都随训练下降,主损失没有因辅助权重过大而持续恶化,梯度范数没有被某一深度长期支配.若某个深度从第一步起就远低于其余深度,应优先检查标签泄漏和切片错位.

评估主模型时要关闭或移除辅助损失,直接用主输出头计算验证集 next-token NLL.评估 MTP 候选质量时,则分别统计每个深度的 top-1 命中率、连续前缀接受长度和按样本类型切分的接受率.单个深度命中率高不保证连续接受率高:若各位置错误相关,一次早期错误会截断整段候选.

**MTP 的训练目标、候选生成和验证解码是三层不同机制.**训练目标决定梯度怎样进入主干;候选模块决定一次提出哪些未来 token;验证算法决定最终输出是否保持主模型分布.把三层分别检查,才能解释质量变化和速度变化来自哪里.
