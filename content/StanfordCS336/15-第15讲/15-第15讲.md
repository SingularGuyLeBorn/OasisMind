# 第15讲: SFT、偏好数据与 RLHF

预训练让模型学会根据已有 token 预测下一个 token,却没有直接规定它应该怎样回答用户.网页里既有正确答案,也有争论、广告、代码、引用和未完成的句子;最大似然只要求拟合这些分布.一个 base model 可能掌握大量知识,但对话格式不稳定,遇到含糊指令也不知道应该澄清、拒绝还是直接完成.后训练开始于这个落差:**把语言建模得到的能力,约束成用户能够调用、评价和持续改进的行为.**

这一讲沿着数据形态来理解后训练.SFT 使用「prompt—理想回答」;奖励模型和 DPO 使用「同一 prompt 下哪个回答更好」;PPO 等强化学习方法再用当前策略生成的新回答,根据奖励更新策略.三个阶段处理的监督信号不同,也承担不同风险.把它们都称作「对齐」会掩盖真正需要判断的地方:数据是谁生成的,标签表达什么,训练目标在哪个分布上成立,以及模型离开标注数据以后会怎样.

## SFT 先把交互格式变成条件分布

一条 SFT 样本由上下文 $x$ 与目标回答 $y=(y_1,\ldots,y_T)$ 组成.自回归模型优化 completion token 的负对数似然

$$
\mathcal L_{\mathrm{SFT}}
=-\sum_{t=1}^{T}m_t\log\pi_\theta(y_t\mid x,y_{<t}),
$$

其中 $m_t$ 是 loss mask.训练助手时,system 与 user token 通常作为条件输入,assistant completion 才进入损失;多轮数据还要明确每一轮 assistant token 是否都监督.Mask 配错会把用户问题也当成模型需要生成的目标,chat template、special token 和 EOS 处理则共同决定模型实际学到的交互协议.

[主讲义](./15.1-主讲义/15.1-主讲义.md)把 SFT 放回完整后训练流程.SFT 数据量未必需要接近预训练规模,因为它主要改变条件行为与输出分布,而不是重新灌入全部世界知识.数据质量也不能只看答案是否流畅:指令覆盖、长度分布、多轮状态、拒答边界和工具格式都会进入模型.对同一个问题塞入许多近似答案,会提高某类表达的权重,却不会自动增加任务覆盖.

SFT 的监督来自既有答案,因此容易复制数据生成器的能力上限与风格.教师模型写出的答案可以扩大数据规模,但错误也会被稳定地模仿.人工数据更容易控制标准,成本又限制覆盖.真实管线常把人工示范、模型生成、规则验证与去重结合起来,并用 held-out prompt 检查行为,而不是只看 token loss.

## 偏好数据把评价写成成对比较

许多开放任务没有唯一参考答案.标注者面对同一 prompt 的两个回答 $y_w$ 与 $y_l$,选择更符合正确性、有用性和安全要求的一项.成对比较比要求标注者写出一个绝对分数更稳定,但标签仍依赖评价准则.若没有明确优先级,一个回答更准确、另一个更简洁时,不同标注者可能给出相反选择.

[InstructGPT](./15.3-InstructGPT/15.3-InstructGPT.md)展示了经典流水线:先收集示范做 SFT,再收集排序数据训练 reward model,最后用 PPO 优化 policy.Reward model 常输出标量 $r_\phi(x,y)$,用 Bradley-Terry likelihood 拟合偏好:

$$
p_\phi(y_w\succ y_l\mid x)
=\sigma\bigl(r_\phi(x,y_w)-r_\phi(x,y_l)\bigr).
$$

对应 loss 是 $-\log p_\phi(y_w\succ y_l\mid x)$.这个目标识别的是 reward difference;同一 prompt 下所有回答同时加一个常数,不会改变偏好概率.Reward model 因此提供相对排序信号,不能被当成跨 prompt 可直接比较的绝对效用尺.

候选回答来自哪个 policy,会决定偏好数据覆盖什么区域.较弱 policy 产生的 pair 可能差距很大,容易标注,却无法暴露强 policy 的细微错误;只比较当前最强模型又会提高成本和标签分歧.数据集应记录生成器、采样参数、回答长度与标注协议,否则 reward model 可能依赖风格、模板或长度这些旁路特征.

## PPO 为什么需要 reference、value 与在线样本

训练好 reward model 后,policy 对 prompt 采样回答,reward model 给出序列级分数.为了避免 policy 只追逐 reward model 的漏洞,RLHF 通常约束它不要离 reference policy 太远.一个常见目标是

$$
\mathbb E_{x\sim\mathcal D,,y\sim\pi_\theta}
\left[r_\phi(x,y)
-\beta\log\frac{\pi_\theta(y\mid x)}
{\pi_{\mathrm{ref}}(y\mid x)}\right].
$$

这里的样本来自当前或近期 policy,reference 通常由 SFT checkpoint 冻结得到.序列 reward 还要分配到 token trajectory,value model 估计未来回报,GAE 构造 advantage,PPO 再用 clipped importance ratio 更新 actor.训练系统同时维护 actor、reference、reward model 和 value model,并在 rollout 与训练版本之间保持样本身份一致.

**PPO 的价值不只在某条损失公式,而在它能用当前 policy 新产生的数据继续探索.**代价是 rollout 昂贵,多个模型占用显存,reward hacking 和版本错配都可能让训练信号失真.观察训练时应同时记录真实 reward、KL、回答长度、clip fraction、value error 与生成样本,单看优化后的标量 reward 不足以判断行为是否改善.

## DPO 改写了哪一段流程

[DPO 数学推导](./15.2-DPO/15.2-DPO.md)从 KL 正则奖励最大化的闭式最优策略出发,把 reward difference 写成 policy 与 reference 的 log-ratio.对一条偏好 pair,DPO logit 为

$$
z_\theta=\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right],
$$

loss 为 $-\log\sigma(z_\theta)$.训练只需 policy、冻结的 reference 与离线 pair,不再单独拟合显式 reward model,也不在每一步生成 on-policy rollout.Chosen 与 rejected 的 completion log probability 必须使用相同 tokenizer、chat template、EOS 与 mask 口径,reference log probability 才能正确充当坐标系.

DPO 的简化没有消除数据覆盖问题.训练期望来自离线 pair 分布,重复多个 epoch 只能继续拟合这些 pair;policy 更新后新出现的失败模式不会自动进入数据.长度也会影响 sequence log probability sum,因此 pair 的长度分布、模板一致性与生成器来源都需要检查.理论推导说明 DPO loss 从哪里来,真实效果仍由 reference、偏好数据、模型容量和优化设置共同决定.

偏好优化还会遇到可分数据的问题.若模型能够把训练集上所有 chosen 与 rejected 完全分开,logistic loss 仍会继续推动 margin 增大,却没有额外标签告诉模型应该停在哪里.Reference、有限模型容量、训练轮数与显式正则共同限制实际偏移.训练 pair accuracy 达到很高以后,继续降低 loss 可能只是放大已见差异,生成质量反而需要在新 prompt、不同长度与安全场景上重新检查.

从数据生产角度看,后训练通常还是一个迭代过程.当前 policy 生成候选,人工或 verifier 暴露新的失败,再把高价值样本加入下一轮 SFT、偏好训练或 RL.每轮都要记录生成器 checkpoint 与标注协议,因为策略变强以后,旧数据中的明显错误会迅速失去区分度.真正能够持续推进能力的管线,会让数据难度随 policy 更新,而不只是把同一份 pair 多训练几个 epoch.

评测也应按训练信号分层.SFT 可以检查指令遵循、格式和 held-out token loss;reward model 要检查 pair accuracy、校准与长度偏差;PPO 或 DPO 后的 policy 则要直接生成回答,测正确性、安全、风格以及相对 reference 的 KL.任何一层的离线指标都不能替代最终生成评测,因为部署时用户看到的是 policy sample,不是训练集上的 pair logit.

同一套评测还应固定 decoding 参数与 system prompt.温度、top-p 和最大长度一变,回答分布也会变.只有训练前后使用相同采样协议,胜率与错误类型的变化才主要反映 policy 更新.

评测样本也不能与偏好训练 pair 重叠,否则 held-out 胜率会把记忆误当成泛化.

第15讲把后训练看成一组可以拆开的选择:SFT 决定可模仿的目标回答,偏好标注定义比较准则,reward model 把比较推广成标量函数,PPO 用在线样本继续优化,DPO 则直接拟合离线偏好 likelihood.沿着数据来源和目标函数逐步核对,才能判断一个训练 recipe 改了哪里,以及它省下的系统复杂度换来了什么边界.
