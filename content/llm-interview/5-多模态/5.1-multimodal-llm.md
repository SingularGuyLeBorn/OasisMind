# 多模态大模型

多模态模型需要解决三个连续问题：把图像或视频变成可计算的表示，让语言模型能够读取这些表示，再用足够的数据把视觉证据与语言行为对齐。架构名称很多，差异大多落在视觉 token 怎样产生、怎样压缩、在哪一层与文本交互，以及哪些模块参与训练。只背「视觉编码器 + 投影器 + LLM」无法判断分辨率变大后 token 为什么暴涨，也无法解释 OCR、定位和幻觉为何表现不同。

本文用输入图像 $I\in\mathbb{R}^{H\times W\times C}$，patch 大小 $P$，视觉宽度 $D_v$，语言模型宽度 $D_l$。视觉 token 数、连接器输出长度和 LLM 上下文预算是贯穿全文的三条量纲。

## 1. 图像如何变成 token

Vision Transformer 将图像切成不重叠 patch。若高宽都可被 $P$ 整除，patch 数为

$$
N_v=\frac HP\frac WP.
$$

每个 patch 展平后维度为 $P^2C$，通过线性投影得到 $D_v$ 维向量：

$$
X_0=\operatorname{Patchify}(I)W_E+E_{pos},\qquad
W_E\in\mathbb{R}^{P^2C\times D_v}.
$$

以 $336\times336$ 图像、patch $14$ 为例，得到 $24\times24=576$ 个视觉 token。若把分辨率直接加倍到 $672\times672$，token 变成 $48\times48=2304$，增加四倍。全视觉自注意力的 $N_v^2$ 项增加十六倍，送入 LLM 后还会占用四倍上下文。

ViT 编码器经过多层 self-attention 输出 $Z\in\mathbb{R}^{N_v\times D_v}$。不同层的特征性质不同：浅层保留局部纹理，深层更抽象。连接器使用哪一层、是否丢弃 CLS token、是否拼接多层特征都会影响结果。所谓「视觉编码器输出 576 token」必须附上输入尺寸、patch 和特征选择。

**位置编码与任意分辨率**

固定二维绝对位置表在更高分辨率下需要插值。把 $24\times24$ 的位置表双线性插值到 $48\times48$ 可以匹配 shape，却未保证模型学会了新尺度的细节。二维相对位置、旋转位置或坐标归一化提供其他方案，仍需在目标分辨率训练或适配。

动态分辨率模型常把图像缩放后切成多个 tile，每块独立进入视觉编码器，再保留全局缩略图。这样小字获得更多像素，token 数随 tile 数增长。模型必须知道 tile 的二维位置和缩放关系，否则同一局部出现在不同块中难以还原全局布局。

### 1.1. CLIP 的双编码器与对比学习

CLIP 分别用图像编码器 $f_I$ 和文本编码器 $f_T$ 得到向量，归一化后计算相似度：

$$
u_i=\frac{f_I(I_i)}{\|f_I(I_i)\|},\qquad
v_j=\frac{f_T(T_j)}{\|f_T(T_j)\|},
$$

$$
s_{ij}=\frac{u_i^Tv_j}{\tau}.
$$

一个 batch 有 $B$ 对图文，图到文损失为

$$
\mathcal L_{I\to T}=-\frac1B\sum_i
\log\frac{e^{s_{ii}}}{\sum_je^{s_{ij}}},
$$

文到图损失同理，最终取二者平均。batch 内其他样本充当负例，因此 batch 规模、重复样本和 false negatives 会影响训练。同一张图可能有多种正确描述，把语义相近文本一概当负例会产生冲突。

**手算一行对比损失**

假设某图像与三条文本的温度缩放 logits 为 $[2,1,0]$，第一条是配对文本。softmax 分母为 $e^2+e+1\approx11.107$，正确概率约 $0.665$，损失为 $-\log0.665\approx0.408$。若正确 logit 仍为 2，某个负例也升到 2，正确概率降到约 $0.468$，损失增至 $0.759$。

CLIP 的共享空间支持图文检索和零样本分类。分类时把类别写成文本 prompt，比较图像向量与各类别文本向量。prompt 模板会改变文本表示，常对多个模板求平均。双编码器没有逐 token 的跨模态交互，也没有自回归解码器，因此不能单独完成开放式图像问答或长描述生成。

### 1.2. 三类连接方式

**逐 token 投影**

LLaVA 风格连接器把每个视觉 token 从 $D_v$ 映射到 $D_l$：

$$
H_v=\phi(ZW_1+b_1)W_2+b_2,\qquad
H_v\in\mathbb{R}^{N_v\times D_l}.
$$

随后将 $H_v$ 作为一段输入 embedding 插入文本序列。它保留全部 patch token，结构简单且能复用标准 decoder-only LLM。代价是视觉 token 数直接占上下文；连接器只逐 token 映射时，空间聚合主要依赖视觉编码器和 LLM。

线性或 MLP 连接器有效，不代表视觉语言对齐天然简单。训练数据、预训练视觉表示、LLM 能力和输入格式共同承担了工作。面对高分辨率 OCR、密集定位或多图，连接器容量与 token 管理仍可能成为瓶颈。

## 2. Q-Former

BLIP-2 使用一组可学习 query $Q\in\mathbb{R}^{N_q\times D_q}$，通过 cross-attention 从冻结图像特征读取信息：

$$
\operatorname{CrossAttn}(Q,Z)=
\operatorname{softmax}\left(\frac{QW_Q(ZW_K)^T}{\sqrt d}\right)ZW_V.
$$

无论输入有多少视觉 token，Q-Former 可输出固定 $N_q$ 个向量，再投影给语言模型。$N_q=32$ 时，相比直接传 576 token 显著压缩上下文。固定瓶颈也可能丢失小字、计数和密集区域信息。

BLIP-2 的 Q-Former 不只是随机 query 加语言建模损失。其第一阶段使用图文对比、图文匹配和图像条件文本生成等目标，在冻结图像编码器下学习视觉—语言表示；第二阶段再连接冻结 LLM 做生成式训练。说明 Q-Former 时需要区分这两个阶段。

**插入 cross-attention**

Flamingo 先用 Perceiver Resampler 将可变视觉特征压成固定数量 latent，再在冻结语言模型层之间插入 gated cross-attention。文本 token 作为 query 读取视觉 latent，原语言层继续做文本 self-attention。门控初始化可让新模块开始时对冻结 LLM 干扰较小。

这种方案允许文本在多层重复访问视觉信息，代价是修改 LLM block 和推理 kernel。逐 token 前缀方案把视觉 token 当作普通上下文，容易使用现成 serving；cross-attention 则可以分别缓存视觉 K/V 和文本 KV。生产选型依赖任务、token 数、延迟与框架支持，不能固定推荐 MLP。

**训练阶段与冻结策略**

一种常见流程先冻结视觉编码器和 LLM，仅训练连接器，让视觉特征进入语言 embedding 空间；再用多模态指令数据训练连接器与 LLM，必要时解冻视觉编码器；之后可使用偏好数据或可验证奖励改善行为。各模型的阶段数量和冻结策略不同，这不是强制的三段标准。

生成式多模态 SFT 与文本 SFT 类似。输入包含视觉 embedding、用户文本和助手回答，通常只在助手回答 token 上计算交叉熵：

$$
\mathcal L=-\sum_tm_t\log p_\theta(y_t\mid I,x,y_{<t}).
$$

视觉 token 没有离散 label，但梯度可从回答 loss 经过 LLM 与连接器回传到视觉编码器。若视觉编码器冻结，梯度到此停止。

### 2.1. 冻结与解冻的取舍

冻结视觉编码器能节省梯度和优化器状态，并保留已有通用视觉表示；领域差异大时，例如医学影像、遥感或文档小字，原表示可能不足。解冻全部视觉层成本更高，也可能破坏原有能力。可只解冻后几层、使用 LoRA，或先做领域视觉继续预训练。

冻结 LLM 适合测试连接器能否利用已有语言能力，复杂视觉推理往往需要语言层适应视觉 token 分布。解冻时混入纯文本数据可减轻语言能力回退。评价应同时覆盖视觉任务和纯文本基准，不能只看多模态分数上涨。

**数据配比与混合**

图文 caption 数据训练描述与对齐，VQA 数据训练短问答，OCR/文档数据强调文字和布局，grounding 数据提供框或点坐标，多图与视频数据训练跨帧关系。某类数据过多会改变回答风格，例如短答案 VQA 占比过高可能让模型在开放问题中也过短。

合成指令可以快速扩充任务，但教师模型会把错误和语言模式带入数据。图像中不存在的细节若被 caption 模型编入答案，学生会学会视觉幻觉。数据过滤要检查问题是否可由图像回答、答案是否有证据、坐标是否落在目标区域，以及图文是否被模板错配。

### 2.2. 视觉 token 的计算与显存

若视觉 token 与文本 token 一起进入 LLM，prefill 总长度为 $S=N_v+N_t$。普通全注意力每层分数矩阵元素数随 $S^2$ 增长。假设文本 1024 token，加入 576 视觉 token，总长 1600；相对纯文本，二次项比例为

$$
\frac{1600^2}{1024^2}\approx2.44.
$$

加入 2304 视觉 token 后总长 3328，比例约 10.56。实际层耗时还包含线性层和 FFN，FlashAttention 也会减少 IO，但 token 数的影响依旧明显。

图像通常只在 prefill 编码一次。自回归 decode 阶段，视觉 token 的 K/V 与文本历史一起进入 cache。对 $L$ 层、$H_{kv}$ 个 KV 头、每头 $d_h$、元素 $b_e$ 字节，视觉部分 cache 约为

$$
M_v=2BLN_vH_{kv}d_hb_e.
$$

以 $B=1,L=32,N_v=576,H_{kv}=8,d_h=128,b_e=2$ 为例，约 72 MiB。多图请求按图数增长，tile 高分辨率还会进一步增加。Q-Former 或 token merging 的压缩收益可直接从 $N_v$ 代入估算。

**分辨率策略**

固定 resize 会扭曲长宽比，小字也可能消失。保持长宽比后 pad 简单稳定，但空白区域仍生成 token。动态 tile 保留局部细节，代价是更多视觉前向、token 和跨 tile 拼接。AnyRes 一类策略根据原始尺寸选择网格，并加入全局视图。

假设原图 $1344\times672$，目标 tile 为 $336\times336$，可切成 $4\times2=8$ 块；每块 576 token 就是 4608 token，再加全局图 576，共 5184。若直接全部送入 LLM，单图已占据很大上下文。实践中可做 spatial pooling、token pruning、resampler 或只对相关区域二次编码。

区域裁剪需要可靠选择器。先用低分辨率全局图预测感兴趣区域，再高分辨率读取小字，可节省计算；选择器漏掉关键区域时，后续模型无法恢复。评测要单独统计全局关系和局部细节，避免只优化 OCR 后损伤整体理解。

## 3. OCR 与文档理解

自然图像视觉编码器关注物体语义，文档任务还需要识别字符、二维布局、阅读顺序、表格结构和图表关系。较大分辨率只是必要条件之一。视觉 tokenizer 可能压缩掉细笔画，训练数据若缺少小字体和多语言，放大图像也未必解决。

OCR pipeline 可以先用专用识别器输出文字与坐标，再让 LLM处理结构化文本；end-to-end MLLM 则直接从像素回答。前者文字准确率和可追踪性通常更容易控制，后者对图表、版面和自然语言交互更统一。混合系统可把 OCR tokens、坐标与图像特征同时提供。

文档评测应区分文字识别、键值抽取、表格结构、图表问答与跨页推理。exact match 对数字和日期合理，开放问答还需语义与证据检查。模型答对字段却引用错误页，仍会给审计带来风险。

坐标输出必须约定坐标系。若归一化到 $[0,1000]$，原图宽高为 $(W,H)$，框 $(x_1,y_1,x_2,y_2)$ 转为

$$
(\lfloor1000x_1/W\rfloor,\lfloor1000y_1/H\rfloor,
\lfloor1000x_2/W\rfloor,\lfloor1000y_2/H\rfloor).
$$

resize、crop 和 padding 后要保存逆变换，否则模型坐标无法映射回原图。

**Grounding、检测与生成式坐标**

传统检测器直接回归框和类别；生成式 MLLM 可以把框离散成 token 序列，与文本统一解码。统一接口方便多任务训练，但坐标量化引入误差，输出还可能格式非法或框顺序混乱。

框的 IoU 为

$$
\operatorname{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

预测框与真值框的重叠超过阈值才算匹配。小物体上几个像素偏差就会让 IoU 大幅下降，因此只报大物体结果会掩盖定位问题。point grounding、referring expression 和检测回答的评测协议也不相同。

模型先生成对象名称再生成坐标时，语言先验可能盖过图像。可加入负样本和不存在目标的问题，要求输出明确空结果。解析器必须拒绝越界、反向坐标和非数值 token，不能把非法框静默修成有效框后计成功。

### 3.1. 视觉幻觉从哪里来

视觉幻觉指回答声称图中存在未出现的对象、属性或关系。原因包括语言先验强、视觉 token 压缩、训练 caption 自带错误、问题诱导、低分辨率以及生成时缺少证据约束。模型见到厨房图便猜测有冰箱，可能来自训练共现，而非图像像素。

对象存在性可以构造成正负对照。对同一图像询问真实对象与容易共现却缺失的对象，测 precision、recall 和拒答。开放描述可抽取对象 claim，再与检测标注或人工核验比较。只用传统 caption 相似度，虚构细节可能仍因文本流畅获得高分。

缓解方法包括更干净的细粒度数据、加入负例、提高或自适应视觉分辨率、减少过度压缩、在生成中引用区域，以及偏好优化。让模型先描述证据再回答有时有效，但生成出的「证据」也可能是幻觉，不能代替外部验证。

**多图与视频**

多图输入需要区分图像边界与顺序。可为每张图加入 image id 或分隔 token，并让位置编码表达图内二维位置和图间顺序。若所有图的 patch 直接拼接，模型可能把一张图的局部与另一张图混合。训练数据必须包含跨图对比、排序和共指。

视频再增加时间轴。最简单方案均匀采样 $F$ 帧，每帧产生 $N_v$ token，总视觉长度 $FN_v$。16 帧、每帧 576 token 已有 9216 token。减少成本可以降低帧率、空间池化、时序 resampler、选择关键帧或使用时空 token 压缩。

均匀采样会漏掉短暂事件。镜头切分、运动强度和查询相关采样能提高命中率，也引入选择器错误。视频问答至少区分静态外观、动作顺序、长时事件与音视频关系。只在随机单帧就能回答的 benchmark 上得分，不能证明时序理解。

音频可变成频谱 patch 或音频编码器 token，再通过连接器输入 LLM。音视频同步任务需要保留时间戳；单独池化成一个全局向量会丢失「声音发生在画面哪一刻」。不同采样率和帧率还要对齐时间单位。

## 4. 模态位置与 mask

decoder-only MLLM 常将序列组织为 `[system, user text, image tokens, question, assistant]`。视觉 token 通常彼此可见，后续文本能读取全部视觉 token；assistant 保持因果生成。若视觉 token 被放在问题之后，问题 token 是否能看到图像取决于 mask 设计。

训练与推理模板必须一致。图像占位符数量、开始结束标记、newline token 和 tile 顺序变化，都会让模型输入分布改变。processor 负责 resize、normalize、patch 和模板，不能只替换模型权重却沿用另一个版本 processor。

多图 cache 也要与占位符绑定。复用同一图像视觉 embedding 可以节省视觉编码，但若 crop、分辨率或模型 adapter 不同，cache key 必须改变。图像内容 hash 还需防止解码参数或色彩空间差异造成错误复用。

**多模态偏好优化**

偏好样本包含图像、问题和两个回答。DPO 形式仍比较条件序列概率：

$$
\mathcal L=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid I,x)}{\pi_{ref}(y_w\mid I,x)}-
\log\frac{\pi_\theta(y_l\mid I,x)}{\pi_{ref}(y_l\mid I,x)}
\right]\right).
$$

偏好标准可以是正确性、视觉忠实、帮助性和安全性。若 chosen 总比 rejected 长，模型会同时学到长度偏好；若标注者看不清小字，偏好标签也会错误。数据界面应展示原始分辨率与可缩放图像，并记录标注理由。

可验证任务可用 OCR 字符、框 IoU、数学答案或程序执行作奖励。开放图像描述缺少唯一答案，奖励模型可能偏爱华丽但虚构的细节。混合规则奖励和人工偏好时，需要校准尺度，避免某一项因数值范围大而主导更新。

### 4.1. 安全与隐私

图像可能包含人脸、证件、屏幕密钥、地理位置和隐写文本。上传处理前应明确存储期限、训练使用和访问权限。OCR 得到的文本同样属于用户数据，不能因为转成 token 就绕过数据治理。

图像 prompt injection 会把恶意指令写在截图或文档中。它是视觉内容，不应覆盖系统权限。若模型读取网页截图后可以调用工具，执行层仍要做 schema、授权和审批。隐藏文字、极小字体与二维码还可能绕过人工快速检查。

输出安全不能只做文本分类。模型可能从图像识别敏感属性、复原遮挡不充分的信息，或对人物身份作无根据推断。评测集需要覆盖这些视觉特有风险，并按照业务地域与政策定义处理。

**评测与故障定位**

多模态总分会混合感知与推理。可先测基础感知：OCR、对象、属性、空间关系、计数；再测需要知识和多步推理的任务。若 OCR 错，后续文档推理再强也无法补回原字符。按图像分辨率、文字大小、语言和对象尺寸分桶，比单一平均分更有诊断力。

发现模型完全忽略图像时，可做反事实：保持问题相同替换图像，观察 logits 或回答是否变化；遮挡关键区域，正确答案概率应下降；将视觉 embedding 置零，与文本先验基线比较。若结果几乎不变，检查连接器、占位符、attention mask 和训练数据。

小字任务失败先确认原图经 resize 后每个字符剩多少像素，再查看 tile、processor 和视觉 token；空间关系失败检查二维位置和 crop 拼接；多图混淆检查 image id、顺序与训练覆盖；描述幻觉则比较对象 precision、负例和语言先验。

延迟应拆成图像解码、预处理、视觉编码、连接器、LLM prefill 和 decode。高分辨率通常增加视觉编码与 prefill，输出变长则主要增加 decode。batching 时不同尺寸会引入 padding，动态 shape 也可能影响图捕获和 kernel。优化前先确定时间落在哪一段。

### 4.2. 架构比较的统一坐标

比较 CLIP、BLIP-2、Flamingo 和 LLaVA 时，可以固定六个问题：视觉编码器输出多少 token；连接器是否压缩；文本与视觉在哪些层交互；视觉编码器和 LLM 是否冻结；训练目标有哪些；推理能否复用标准 LLM kernel。这样能从机制推出能力和成本，避免把不同版本的模型特性混成品牌标签。

CLIP 的双塔适合大规模检索，跨模态交互发生在全局相似度；BLIP-2 用 Q-Former 建立固定信息瓶颈；Flamingo 通过多层 gated cross-attention 让文本反复读取视觉 latent；LLaVA 将投影视觉 token 直接放进 LLM 序列。它们解决的任务、训练数据和参数冻结方式不同，单一榜单不能隔离架构贡献。

部署选择也沿同一坐标。大量图片检索优先双塔和预计算；开放问答需要生成式连接；高分辨率文档关注 token 压缩与 OCR；多轮图像对话关注视觉 cache；端侧部署还要考虑视觉编码器和 LLM 两部分量化。架构越复杂不保证越适合目标负载。

**Projector 的 shape 与参数量**

假设视觉编码器宽度 $D_v=1024$，LLM 宽度 $D_l=4096$。单层线性 projector 的参数量为

$$
N_{proj}=D_vD_l=4,194,304,
$$

约 420 万，不计 bias。两层 MLP 若中间宽度也是 4096，参数为

$$
1024\times4096+4096\times4096\approx20.97\text{ M}.
$$

它相对数十亿参数 LLM 很小，但承担了把视觉分布映射到语言 embedding 尺度的任务。训练初期若输出范数与词 embedding 相差很大，会影响后续 attention。可记录两类 token 的均值、RMS 和梯度范数，确认连接器没有输出接近零或异常放大。

输入 $Z$ 的 shape 为 $[B,N_v,D_v]$，线性投影后 $[B,N_v,D_l]$。若 batch 中图像 token 数不同，常 pad 到本批最大值并提供视觉 attention mask；也可将 token pack 成变长序列，让 kernel 根据累积长度处理。前者实现简单却浪费计算，后者要求模型和融合算子支持变长边界。

Q-Former 的输出 shape 为 $[B,N_q,D_q]$，再投影到 $D_l$。cross-attention 分数为 $[B,H,N_q,N_v]$，其计算随 $N_qN_v$ 增长。它把进入 LLM 的长度固定为 $N_q$，视觉编码和 Q-Former 本身仍要读取原始 $N_v$ 个 token。压缩节省主要发生在后续大语言模型层。

**Patch merge 与 token pruning**

最简单的空间 merge 将相邻 $2\times2$ patch 拼接或池化，token 数降到四分之一。拼接后通道变成 $4D_v$，需再投影；平均池化保持宽度但可能抹掉细节。自适应 pruning 根据图文相关性或视觉显著性保留部分 token，计算更省，却可能在问题出现前删掉关键区域。

如果同一图像会面对多个后续问题，问题无关的静态压缩便于缓存；问题相关压缩需为每个问题重算选择。文档问答中的关键字可能位于视觉上不起眼的角落，纯显著性选择尤其危险。token 压缩要分别测自然图、OCR、小物体和空间关系。

## 5. 多模态 batch 怎样构造

纯文本样本没有图像，单图、多图和视频样本的视觉长度差异很大。若随机混入同一 batch，最长样本决定 padding，显存利用率会很差。可按视觉 token 长度分桶，控制每 batch 的总 token 预算：

$$
T_{batch}=\sum_i(N_{v,i}+N_{t,i}).
$$

batch size 因样本长度动态变化时，梯度归约要明确按样本还是按有效 token 平均。按 token 平均会让长样本贡献更大；按样本平均则需先计算每样本 loss。多机数据并行还要平衡各 rank 的总 token，否则短 batch 的 rank 会等待长 batch。

图像增强要与任务匹配。随机裁剪适合分类预训练，却可能裁掉 VQA 答案或文档字段；水平翻转会改变左右关系和文字；强颜色变化可能破坏图表颜色语义。训练 pipeline 应按数据类型选择增强，而非所有图像共用一套视觉预训练配置。

数据去重也要跨模态进行。仅按文本 hash 会漏掉同图不同 caption，仅按像素 hash 会漏掉 resize、压缩和裁剪版本。感知 hash、图像 embedding 和文本相似度可组合找近重复。benchmark 图像及其 caption 若进入训练，开放问答分数会被污染。

**视频注意力的计算选择**

把 $F$ 帧、每帧 $N$ 个 patch token 全部做联合时空 attention，长度为 $FN$，二次项为 $F^2N^2$。分解 attention 可以先在每帧内部做空间 attention，再对相同或聚合位置做时间 attention，量级接近

$$
O(FN^2)+O(NF^2).
$$

当 $F=16,N=576$ 时，联合分数元素约 $84.9$ 百万；分解形式约 $5.46$ 百万，数量级差异明显。分解也限制了交互路径，跨帧移动物体需要时间模块正确建立对应。

另一种方案先用视觉编码器逐帧提取，再用 temporal pooling 或 resampler 压到固定 token。池化能服务长视频，精确时刻和短事件容易丢失。层级模型可在片段内保留细粒度 token，再把片段摘要送入长时模块。评测需要包含事件边界、顺序反转和远距离因果，才能区分静态图像能力与时间建模。

视频训练还涉及帧时间戳。可变帧率视频中，第 10 帧不代表固定秒数；均匀按帧索引采样可能在某些片段过密。解码器应输出真实时间，位置编码使用相对时间或规范化 timestamp。音频对齐同样依赖同一时间基准。

### 5.1. 多模态模型的量化部署

视觉编码器、projector 和 LLM 可以使用不同精度。LLM 权重占容量主体，4-bit weight-only 量化收益大；视觉编码器计算集中在一次 prefill，INT8 或 FP16 的速度与 kernel 支持相关；projector 很小，保留 BF16 通常成本有限。统一把所有模块压到 4 bit 可能让视觉特征和坐标任务更敏感。

视觉输入的动态范围由 normalize 配置决定。processor 若使用错误 mean/std，即使权重完全正确，视觉激活也会漂移。量化校准集必须包含实际分辨率、文档、自然图和多图长度。只用 ImageNet 风格中心物体校准，未必覆盖 OCR 的高频纹理和大面积空白。

KV cache 量化会同时影响视觉前缀和文本历史。视觉 token 在整个生成过程中被反复读取，其量化误差可能持续作用。可以分别对视觉前缀与文本 cache 做消融，查看图像问答、长描述和纯文本回归。若框架把二者存入同一 cache 格式，则需要权衡统一 kernel 与模态敏感度。

吞吐测试要把图像预处理计入端到端。JPEG 解码、resize 和 tile 切分若在 CPU 串行完成，GPU 可能等待；将预处理并行化、固定常见 shape 或使用 GPU 解码能降低这部分。仅从预计算视觉 embedding 开始计时，适合测 LLM 部分，却不能代表用户上传图片后的延迟。

**指标的含义与手算**

OCR 常用字符错误率 CER。参考字符数为 $N$，编辑距离中的替换、删除、插入分别为 $S,D,I$：

$$
\operatorname{CER}=\frac{S+D+I}{N}.
$$

参考「模型训练」四个字符，预测「模型炼」少一个「训」，删除数为 1，CER 为 $1/4=25\%$。中文分词不稳定时，CER 比词错误率更容易复现；英文可同时报告 WER。

描述任务的 BLEU、CIDEr 等衡量与参考文本的重合，参考答案不完备时会惩罚合理改写，也未必严厉惩罚视觉幻觉。VQA accuracy 受答案归一化和多标注者一致性影响。图表与数学任务可执行或比较规范化结果，定位任务使用 IoU 或 point distance。

多模态选择题可能被文本偏差解决。可以做 image ablation：遮掉图像后仍保持很高分，说明 benchmark 含强语言线索。还可打乱图像—问题配对，检查准确率是否降到合理基线。对于开放回答，分别评价 correctness、relevance、visual grounding 和 hallucination，比一个 LLM judge 总分更可解释。

置信校准可以按预测置信分桶。第 $b$ 桶平均置信为 $conf(b)$，实际正确率为 $acc(b)$，期望校准误差为

$$
\operatorname{ECE}=\sum_b\frac{|B_b|}{n}|acc(b)-conf(b)|.
$$

生成模型没有天然的整句置信，可使用答案 token log probability、多个采样一致性或独立验证器作为代理，并在标注集上校准。代理分数不能直接当成真实正确概率。

### 5.2. 一个端到端排查例子

用户上传发票，模型把总额 128.50 读成 128.80。先查看原图与 resize 后 crop，确认小数点和数字仍有足够像素；再运行专用 OCR，区分视觉识别失败与 LLM 解码失败；随后检查 tile 是否覆盖该区域、坐标映射是否正确，以及相关视觉 token 是否被压缩。

若视觉编码结果正确但生成错误，可以比较候选数字的 token log probability，检查训练数据中字体与金额格式，并让模型返回字段与引用框。引用框落在错误位置说明 grounding 失败；框正确而数字错更像识别或语言解码。把整张图分辨率盲目加倍会显著增加成本，也可能仍未聚焦目标区域。

修复后建立小数、相似字形、多语言货币、旋转扫描和低对比度回归集。字段抽取同时测 exact match 与框 IoU，任何一个失败都保留样本。线上记录 processor 版本、原始尺寸、tile 布局、模型与解析器版本，才能在模型升级后复现。

**理解模型与生成模型的接口**

多模态理解模型接收图像并生成文本；文生图模型接收文本条件并生成像素或潜变量。二者都谈视觉—语言对齐，训练目标和输出空间却不同。扩散生成模型学习在不同噪声时刻预测噪声、速度或干净样本，LLM 式理解模型通常对回答 token 做交叉熵。

一些统一模型把图像离散成视觉 code，再像语言一样自回归生成；另一些模型共享 Transformer 骨干，却为文本 token 与连续图像 latent 使用不同头和 loss。判断是否真正「统一」，要看参数共享、attention 关系、tokenizer 和训练目标，不能因为一个产品既能看图又能画图就推断内部只有一个生成头。

文生图评测中的 FID 比较生成集与真实集的特征统计，CLIP score 衡量图文相似，但二者都不能完整表示文字渲染、物体数量和空间关系。人类偏好也会受到美学与提示长度影响。理解任务的 VQA 分数与生成任务的图像指标不能直接相加为一个通用多模态能力值。

编辑任务还要检查内容保持：用户只要求改背景时，主体身份、姿态和文字是否被无意改变。可把指令遵循与未编辑区域的一致性分开测。涉及真实人物和版权素材时，生成侧还增加身份滥用、水印与来源追踪问题，这些并不会因模型同时具有理解能力而自动解决。
