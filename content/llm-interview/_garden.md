# LLM 与 Agent 面试知识库

这不是按“网传频率”堆砌的八股题单，而是一套用于技术面试准备和知识自检的最小体系。每个专题都要求读者能够解释定义、推导关键结论、比较替代方案，并说明工程边界与证据来源。

> 内容核验基线：2026-08-31。涉及协议、模型版本和产品能力的题目必须注明版本与资料日期；未经公开证实的面经只用于发现题目，不作为技术答案的证据。

## 一道合格题目的组成

每道题尽量包含：

1. **题目与考察目标**：明确是在考定义、推导、比较、设计还是排障；
2. **短答案**：先给可以在 60–90 秒内表达的结论；
3. **推导或机制**：列出假设、符号、数据流和关键步骤；
4. **追问**：至少包含一个边界条件或替代方案；
5. **常见误区**：指出听起来正确但条件不成立的回答；
6. **证据**：优先论文、正式规范、官方文档、模型卡和官方仓库；
7. **时效信息**：对协议、模型和工具写明核验日期。

## 证据等级

| 等级 | 可用于什么 | 典型来源 |
|---|---|---|
| A | 支撑定义、算法、规格和正式结论 | 原始论文、正式规范、官方模型卡、系统卡、官方仓库 |
| B | 支撑工程做法和独立复现 | 维护良好的框架文档、公开基准、可复现实验 |
| C | 发现可能的考点与追问 | 匿名面经、论坛讨论、二手教程 |

C 级来源不能单独支撑技术答案，也不能证明某题“必问”或具有确定出现率。本库不再使用无可核验样本的五星频率评级。

## 覆盖边界

本库负责“面试时如何证明你理解并能应用”。完整教程和模型百科分别由 `llm-guide`、`classic-papers`、`continual-learning` 等知识库承担。本库允许给出必要推导，但通过链接指向唯一的系统正文，不复制另一套大篇幅教程。

目前六个专题已经建立基础题骨架，后续优先补齐：

- 数据治理、污染检测与评测设计；
- 训练稳定性、故障定位和分布式通信；
- 推理调度、KV Cache、前缀复用和投机解码；
- Agent 的权限、幂等、恢复、评测和提示注入防护；
- 语音、视频、原生多模态与实时全双工系统；
- 从业务约束出发的端到端系统设计题。

## 使用方式

- 第一遍：遮住答案，用自己的话回答；
- 第二遍：补公式、复杂度、系统指标和失败边界；
- 第三遍：对照一手来源，检查版本与事实；
- 模拟面试：先给短答案，再接受连续追问，不背诵长文。

新增题目时先确认它属于哪个能力域；同一问题只保留一个主版本，模型版本变化以小节更新，不通过复制新文件维护。
