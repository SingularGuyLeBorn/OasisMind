# 为什么必须在学生自己的错误上训练

自回归模型第 $t$ 步输出的 token 会进入第 $t+1$ 步输入. 一处小错误会改变后续条件, 后面的预测问题也随之改变. 固定数据训练优化专家访问的前缀, 部署时真正遇到的却是学生自己诱导的前缀. OPD 把教师带到这些学生状态上, 直接处理训练分布与部署分布之间的断层.

## 1. 自回归误差为何会改变问题本身

在独立分类里, 第一个样本分错不会修改第二个样本的输入. 自回归生成不同. 给定 prompt $x$, 第 $t$ 步状态为

$$
s_t=(x,y_{<t}),
$$

学生从 $\pi_\theta(\cdot\mid s_t)$ 采样 $y_t$, 再通过确定的拼接转移到 $s_{t+1}=(s_t,y_t)$. 每个动作同时是当前输出和未来输入的一部分. 早期 token 选错后, 后续模型面对的已经不是原训练轨迹上的问题.

考虑一个括号推导. 正确前缀写成 $2(x+3)=2x+6$, 学生误写为 $2x+3$. 下一步在固定数据里可能是“移项得 $2x=4$”, 但放在学生前缀后会继续建立在错误展开上. 强行提高固定答案的下一 token, 甚至可能造成语法连贯但数学条件不一致的拼接. 教师需要先读取 $2x+3$ 这个真实状态, 决定直接纠错、回溯还是重新开始.

把任务写成状态访问分布更清楚. 专家策略 $\pi_T$ 诱导 $d_{\pi_T}(s)$, 学生策略诱导 $d_{\pi_\theta}(s)$. SFT 的期望损失大致在 $d_{\pi_T}$ 或数据分布上计算, 部署风险却在 $d_{\pi_\theta}$ 上计算:

$$
\mathcal R_{\mathrm{deploy}}(\theta)
=\mathbb E_{s\sim d_{\pi_\theta}}
[\ell(\pi_\theta,s)]. \tag{1}
$$

即使模型在专家状态上的局部错误很低, 式 (1) 仍可能很高, 因为学生会访问专家从不经过的状态. 这就是 exposure bias 的序列决策版本. 单纯增加同分布数据解决不了它;训练样本需要覆盖学生策略产生的状态.

## 2. 从单步误差到累计代价

设每个专家状态上的分类错误率至多为 $\epsilon$. 若错误只损失当前一步, 长度 $T$ 的累计错误约为 $T\epsilon$. 序列任务里, 第 $t$ 步错误还可能让剩余 $T-t$ 步进入坏状态. 用 union bound 粗略计算, 在第 $t$ 步之前至少出过一次错的概率不超过 $(t-1)\epsilon$, 将每步额外代价求和会得到 $O(T^2\epsilon)$ 的最坏界.

这个二次界是上界, 不是对所有语言生成的精确预测. 模型可以自行恢复, 某些 token 对任务无关, 多条轨迹也可能同样正确. 它真正说明的是:只测专家前缀上的单步准确率, 无法控制学生状态上的累计代价. 任务越长、早期决策越不可逆, 这个缺口越值得重视.

恢复能力可以改变实际增长率. 若错误后平均经过 $h$ 步能够回到有效状态, 单次错误影响更接近 $h$ 而非剩余全部长度. 因此评测除了最终正确率, 还应测从中间错误前缀继续生成的成功率、平均恢复步数以及错误首次出现的位置. OPD 若真的改善状态覆盖, 应当提高可恢复状态上的 continuation 成功率, 而不只是降低标准轨迹上的 KL.

错误的严重程度也不同. 标点、措辞或等价变形通常不改变任务状态;错误假设、不可逆工具调用和覆盖文件则会改变可行解集合. 将所有 token 平均对待, 会让大量容易的风格差异淹没少数关键岔路. 状态分布分析需要按语义角色、可恢复性与环境副作用分桶.

## 3. DAgger 为什么成为直接参照

DAgger 的做法是让当前学习者在环境中执行, 收集它实际访问的状态, 再请专家为这些状态标注动作. 新数据加入聚合数据集后重新训练, 学习者下一轮访问分布随之变化. 这条循环直接针对“专家数据没有覆盖学习者错误状态”.

经典 DAgger 可写成第 $k$ 轮使用混合策略

$$
\pi_k=\beta_k\pi_T+(1-\beta_k)\pi_{\theta_k},
$$

其中 $\beta_k$ 逐步减小. 早期多用专家动作, 避免弱学生把环境带到毫无意义的区域;后期让学生承担更多状态生成, 使训练分布接近部署. 数据聚合提高覆盖, 也让旧策略状态继续留在训练集, 因而严格说来包含 off-policy 成分.

语言模型 OPD 与 DAgger 共享“学生访问状态、教师提供方向”的骨架, 监督接口却更丰富. 专家不一定只给一个离散动作, 还可以给完整词表分布、top-$k$ 候选、采样动作 log-prob 或自然语言批评. 软分布能表达多个合理续写及置信度, 同时增加词表投影、通信和 tokenizer 对齐的成本.

LLM 的状态转移也有特殊性. 单轮文本里, 状态近似为前缀, 转移只是追加 token;多轮 Agent 中, 状态还包含工具观察、文件、页面和外部服务. 教师如果只读文本、没有读取学生当时看到的工具结果, 它与学生并不处于同一状态. 此时“在学生前缀上蒸馏”不足以保证 on-policy 语义.

## 4. 哪些学生状态值得教

学生状态并非越多越好. 可以用三个条件筛选:学生部署时确实会访问, 教师在该状态上有稳定增益, 从该状态出发仍有机会改变结果. 三者缺一, 教师调用都可能变成昂贵噪声.

第一类是标准附近状态. 学生只出现局部格式、计算或措辞偏差, 教师容易给出可靠修正. 这些状态信号低方差, 但若占比过高, OPD 会退化成在学生近似正确的轨迹上做风格对齐. 第二类是可恢复岔路. 学生选择了较差路线, 仍可回溯或换方法;这里最能体现教师在学生状态上纠错的价值. 第三类是不可恢复状态. 约束已经矛盾、关键文件被破坏或上下文失去必要信息, 下一 token 再合理也无法完成任务.

可恢复性可用 continuation 实验估计. 从同一前缀分别让学生、普通教师与带参考信息的教师续写多次, 记成功率为 $v_S(s)$、$v_T(s)$ 和 $v_{T+z}(s)$. 若 $v_{T+z}(s)-v_S(s)$ 明显为正, 特权教师在该状态可教;三者都接近零, 应回到更早岔路或重置环境;若教师只提高局部 log-prob、续写成功率不变, 它可能只在修辞层面更自信.

采样温度控制状态覆盖. 温度过低时, 学生反复访问少数高概率轨迹, 难以暴露边缘错误;温度过高时, batch 被乱码和不可恢复前缀占满. Prompt 难度也有同样作用:全是简单题, 教师没有信息增量;全是远超学生能力的题, 教师只能面对崩坏状态. 合适课程让样本集中在学生偶尔成功、教师仍明显更强的能力边界.

支持集决定 reverse-KL 与 sampled-token 方法能看到什么. 教师很偏好的动作若在学生分布下概率近零, on-policy 采样几乎不会选中, 单动作反馈也很难把它召回. Full-vocab forward KL 可以直接提高未采动作, SFT 或教师 roll-in 也能先扩大支持. 所以“状态来自学生”并不保证所有教师知识都能传给学生.

## 5. On-policy、near-policy 与 replay

严格 on-policy 要求监督轨迹来自当前更新策略. 实际系统通常有 rollout worker、教师服务与 learner 三段流水线. Worker 用快照 $\mu$ 生成轨迹时, learner 可能已更新为 $\pi_\theta$. 两者不同时, 训练进入 near-policy 或 off-policy 区域.

单步偏移可用重要性比表示:

$$
\rho_t=\frac{\pi_\theta(y_t\mid s_t)}{\mu(y_t\mid s_t)}. \tag{2}
$$

$\rho_t$ 接近 1 表示当前 learner 对已采动作的概率与行为策略接近. 整条轨迹比率是各步连乘, 长序列中很容易下溢、爆炸或产生巨大方差. 逐 token clipping、限制版本差和减少复用 epoch 都在用偏差换稳定性.

Checkpoint 相差几版只是粗略元数据. 十次很小的更新可能比一次大更新更接近行为策略. 更可靠的日志会重算新旧策略在保存动作上的 log-ratio, 报告中位数、尾部分位数、裁剪比例和有效样本量. 还可比较新鲜样本与不同年龄样本的梯度余弦, 看偏移是否已经造成相反方向.

Token 位置不能代替策略新鲜度. 常规 rollout 用冻结快照完成整条回答, 首 token 与尾 token 来自同一行为版本. 尾部状态的方差可能更高, 因为它包含更长的随机历史, 这与“尾部更旧”是两件事. 只有生成途中热更新权重、异步拼接不同片段或从历史前缀续写时, 一条序列内部才会混入多个版本.

Replay 也不是天然错误. 旧轨迹可以摊薄昂贵生成与教师评分, 保存罕见失败状态, 防止训练只追逐当前高频错误. 关键在于旧样本是否仍代表当前学生的决策边界. 若历史样本梯度与新鲜样本持续冲突, 提高 tokens/s 只会降低有效进度. 回放年龄、状态稀有度、教师优势与梯度一致性应共同决定复用权重.

## 6. 状态轴与目标轴要分开

状态来源回答“在哪里学”, 动作目标回答“站在这里往哪里改”. 学生轨迹上可以计算 forward KL、reverse KL、JSD、硬标签或环境奖励;固定教师轨迹上也可以计算 reverse KL. 因此“用了 reverse KL”不能证明 on-policy,“学生自己生成”也不能证明在做蒸馏.

第三根轴是采样分布是否参与求导. Stop-gradient OPD 把 rollout 当作本轮固定数据, 只对每个已访问状态上的局部损失求导. 序列级 reverse KL 还考虑参数改变当前动作后会怎样改变未来状态, 常用 policy-gradient 估计恢复这部分依赖. 后者更接近完整序列目标, 也会引入长程回报的高方差.

可以用一个二维表先定位常见方法:

| 状态来源 | 教师分布目标 | 环境结果目标 |
|---|---|---|
| 固定数据或教师轨迹 | 离线 KD / reasoning SFT | 离线奖励加权、偏好优化 |
| 当前学生轨迹 | GKD 式 OPD、sampled-token OPD | on-policy RLVR |
| 历史学生轨迹 | replay distillation、off-policy KD | off-policy RL / replay |

表中的每个格子还可继续选择估计器与反馈粒度. 真实方法常跨格子混合:一部分 batch 来自教师数据, 一部分来自当前学生;成功轨迹用结果筛选, 轨迹内部再做 token KL. 混合并不妨碍分析, 前提是分别记录每部分数据由谁生成、保存了什么信号、复用了多久.

判断状态分布是否真的带来收益, 最直接的实验是固定学生、教师、prompt 与局部损失, 只替换前缀来源. 教师前缀、当前学生前缀、历史学生前缀和混合 roll-in 构成一组对照. 再按正确、可恢复、不可恢复状态报告 continuation 成功率, 才能看见 OPD 改善的是学生真实错误, 还是只在标准附近重复离线蒸馏.

### 6.1. 怎样测两个状态分布相差多远

状态是高维前缀, 无法像一维变量那样直接画出完整密度. 最容易测的是同一 prompt 下的行为差异. 固定解码配置, 分别从教师、旧学生和当前学生采样, 比较回答成功率、长度、首个关键分叉位置、工具序列与解法聚类. 这些统计描述轨迹层差异, 仍需进入共同状态才能判断条件策略差异.

一种共同状态来自学生 rollout. 对同一批学生前缀, 同时计算教师、行为策略与当前 learner 的 token 分布. 教师与学生 KL 描述监督强度, 行为策略与 learner KL 描述样本陈旧度, top-$k$ 交集描述候选动作是否重叠. 三个量不能互相替代:教师差距大可能意味着可学信息多, 也可能意味着教师无法理解学生;新旧学生差距大则直接影响 off-policy 估计.

还可以把前缀编码成语义状态. 数学题记录当前已知条件、目标、采用的路线与最近一次有效推导;代码任务记录编译状态、失败测试、已修改文件和剩余子任务;Agent 记录计划节点、工具观察和环境版本. 按这些字段分桶后, 能区分“文本不同但任务状态相同”与“表面相似但环境已经改变”. 纯文本 embedding 距离只能作为辅助, 因为两个措辞相近的工具调用可能产生完全不同的副作用.

分布差异还应按训练轮次画成曲线. OPD 早期学生状态可能远离教师数据, 中期逐渐进入可恢复区域, 后期师生趋同后 KL 下降. 只在训练结束测一次, 会漏掉方法真正产生作用的阶段. 如果 teacher-prefix 与 student-prefix 的收益差只在早期存在, 后期继续支付在线教师成本可能没有必要.

### 6.2. 一个工具任务的状态错位

假设 Agent 的任务是修复仓库测试. 学生先修改 `parser.ts`, 运行测试后得到“第 42 行类型错误”, 随后准备再次编辑. 此时状态包含对话前缀、当前文件内容、测试命令、错误输出与工作树. 教师若只看到对话中一句“测试失败”, 无法知道具体类型错误;若教师读取的是修改前文件, 它给出的 patch 又对应旧状态.

离线成功轨迹可能展示另一条修法:先改 schema, 再改 parser. 把成功轨迹的下一动作直接贴到学生当前状态, 可能覆盖学生已经完成的修改. 真正的 on-policy 教师要读取学生当前工作树, 判断现有路线是否仍可修复, 再决定继续、回滚或迁移到另一方案. 这里的“同一前缀”已经扩展为同一可观察环境.

工具副作用让 replay 更难. 昨天的网页、数据库查询或包版本今天可能已经变化;同一个命令文本不再产生同一个观察. 若要复用旧轨迹, 可以保存环境快照、依赖锁文件与工具输出, 或把训练目标限制在副作用之前的稳定区间. 无法重放时, 历史动作仍可作为离线示范, 却不能冒充当前环境下的 on-policy 状态.

环境错误也要与策略错误分开. 测试服务超时、网络断开和权限不足不应直接当作学生动作失败. 若终局奖励把这些故障记为 0, RL 会惩罚无辜轨迹;若教师根据错误日志逐 token 纠错, OPD 也可能教模型为基础设施噪声负责. 状态记录里需要保留工具退出码、重试结果与环境健康信息, 才能过滤这类信号.

### 6.3. 状态覆盖的实验矩阵

第一组实验固定局部目标为 forward KL, 只改变前缀来源. Off-policy 组使用教师或固定数据前缀;on-policy 组使用当前学生;near-policy 组使用若干轮前的学生;混合组按比例 roll-in. 这组回答状态覆盖本身的作用, 不让散度方向和估计器同时变化.

第二组固定学生前缀, 改变教师信息. 普通教师只看学生状态, 特权教师额外看参考解或反馈, 错误特权组看到打乱内容. 若只有正确特权提高 continuation 成功率, 新信息确实在起作用;三组相近时, 收益更可能来自额外上下文长度、模板或正则.

第三组固定状态与教师, 改变状态筛选. 一组训练所有 rollout, 一组只保留最终成功, 一组保留教师可恢复状态, 一组按教师优势加权. 只保留成功会产生幸存者偏差, 全量训练又会被不可恢复状态拖累. 可恢复性筛选若有效, 应在相同教师 token 预算下得到更高任务收益, 并提高中间状态 continuation 成功率.

第四组测状态迁移. 在原 prompt、改写 prompt、更长轨迹和不同工具环境中复测. 若收益只存在于训练模板, 方法学到的是局部状态表面;若在新表达和相邻难度仍能保持, 才说明学生获得了可迁移的纠错能力. 对旧能力集也要复测, 防止模型为了适应窄 prompt 分布而遗忘通用行为.

每组实验都应保存少量可复算轨迹. 对同一前缀重算师生分布、行为 log-prob、mask 与更新后动作概率, 可以检查状态是否真的一致. 如果 teacher tokenizer、聊天模板或工具观察有任何不同, 条件事件已经改变, KL 数值再精确也没有可比意义.

状态分布视角最终给出一个选择条件. 学生很弱、有效状态几乎访问不到时, 先用 SFT 或教师 roll-in 扩大支持;学生已经能到达关键岔路、教师仍能恢复时, OPD 最有价值;教师与学生都无法从这些状态成功, 继续蒸馏不会创造新路线, 应引入搜索、环境奖励或新的外部信息. 同一算法会随学生能力变化而跨越这三个区域, 训练策略也需要随之调整.

### 6.4. 从训练现象反推是哪种分布问题

若固定数据 loss 很低、自由生成一开始偏离就无法恢复, 应检查专家状态与学生状态的覆盖差. 换成学生 rollout 后 loss 剧烈上升时, 再看教师 continuation:教师仍能成功, 说明这些状态可教;教师也失败, 则采样温度或任务难度把数据推到了不可恢复区域.

若新鲜 rollout 有收益, 同一批数据多训几轮后收益消失, 问题更接近策略陈旧. 这时降低学习率可能暂时减小偏移, 更直接的处理是缩短 rollout 与 learner 的版本差、减少复用或采用可验证的重要性修正. 若行为策略与 learner 很接近, 梯度却互相冲突, 则要检查教师在不同状态桶上的方向是否一致.

若师生 KL 主要集中在标点、解释长度和 EOS, 任务关键步骤几乎没有差异, 状态覆盖虽然正确, 教师信息增量仍然不足. 若教师高概率正确动作始终不在学生 top-$k$, 问题落在动作支持集, 需要 SFT、roll-in 或 full-vocab 目标先把动作概率抬起来. 两者都表现为任务分数不涨, 修法却完全不同.

若训练收益只在与教师模板相同的 prompt 上出现, 状态表示过度依赖表面文本. 改写 prompt、交换无关句顺序、改变工具输出格式后复测, 可以判断模型学到任务状态还是模板匹配. 状态分布分析的意义就在这里:它把一个笼统的“OPD 没效果”拆成覆盖、可恢复性、新鲜度、动作支持和状态表示五种不同故障.

这五类故障还会随训练阶段变化. 早期常缺动作支持, 中期更关心可恢复状态覆盖, 大规模异步训练容易遇到新鲜度问题, 后期师生趋同后则可能只剩表面差异. 因而同一组超参数从头用到尾通常不是最佳选择, 采样与教师预算应跟着主要故障移动.
