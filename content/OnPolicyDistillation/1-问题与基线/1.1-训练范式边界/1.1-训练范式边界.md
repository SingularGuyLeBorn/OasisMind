# 训练范式边界：同一批数据为什么会导向不同目标

SFT、知识蒸馏、OPD 和强化学习都可能使用相同的问题集，也都可能最终更新同一个语言模型。只看训练脚本里的交叉熵或策略梯度，很容易把它们说成几种可以互换的配方。真正决定训练范式的是四件事：前缀由谁产生，目标信号来自哪里，损失在匹配什么，以及模型能否通过采样改变下一轮训练数据。把这四条轴分开，很多争论会自然消失。

## 1. 先固定一个共同问题

设提示为 $x$，模型已经生成前缀 $s_t=(x,y_{<t})$，学生为 $\pi_\theta$，教师为 $\pi_T$。训练需要回答两个问题。第一，$s_t$ 从固定语料、教师回答还是当前学生的 rollout 中来；第二，在这个前缀上，学生接收参考 token、教师分布、偏好比较还是环境奖励。前者决定模型在哪里学习，后者决定它在那里朝哪个方向移动。

SFT 使用固定样本中的前缀和参考 token：

$$
\mathcal L_{\mathrm{SFT}}=-\mathbb E_{(x,y)\sim\mathcal D}\sum_t\log\pi_\theta(y_t\mid x,y_{<t}).
$$

它的优点是稳定、便宜、目标清楚，缺点是训练时只看见数据中的历史。学生部署后走入一个训练集没有覆盖的错误前缀，参考答案后续 token 未必仍是那个状态下合理的纠正动作。

离线知识蒸馏可以把单个参考 token 换成教师分布，却通常仍沿固定前缀计算。它改善了局部目标的信息密度：学生知道其他 token 的相对概率；但状态来源没有变化。OPD 的关键改动就是让当前学生产生部分或全部前缀，再在这些前缀上询问教师。它解决访问状态不一致，至于使用 forward KL、reverse KL、top-$k$ 或 sampled-token 估计器，是下一层选择。

## 2. RL 改变的是评价接口

强化学习通常先让学生完整采样，再由环境、验证器或奖励模型给出序列级评价。策略梯度更新的是提高期望回报：

$$
J(\theta)=\mathbb E_{y\sim\pi_\theta(\cdot\mid x)}[R(x,y)].
$$

它不要求存在一个教师分布，也允许学生找到参考答案之外的高奖励策略。代价是信用分配和采样方差：终局奖励必须传回许多早期动作，奖励漏洞还可能把策略带向错误方向。OPD 若能读取教师在每个前缀上的分布，监督会稠密得多，但它受教师支持集约束，通常不会主动寻找教师没有表达过的策略。

因此，OPD 和 RL 的分界不取决于有没有 rollout。两者都可以 on-policy；rollout 后得到教师局部分布时属于蒸馏，得到任务回报时属于强化学习。一个训练系统可以用 SFT 建立基本能力，再用 OPD 修正学生访问到的错误状态，最终用 RLVR 探索教师之外的成功路径。

## 3. 四种方法的可组合边界

比较方法时至少要控制提示集、生成预算、更新 token 数和评测解码。若 SFT 使用人工精选答案，OPD 使用更强教师，RL 又多采样十倍候选，最终分数不能单独归因于目标函数。更可靠的比较会固定教师调用量或总计算量，再逐一替换状态来源和监督接口。

OPD 也并非天然比 SFT 更好。学生已经与教师接近、任务短且参考答案覆盖充分时，重新 rollout 的收益可能小于成本。教师在学生错误前缀上表现失常时，on-policy 查询还会把这种弱点直接暴露给训练。相反，任务越长、误差越容易累积、教师越能诊断非标准前缀，状态对齐的价值越大。

本节以下的具体文章承担两种职责：[SFT、RL 与 OPD](1.1.1-SFT、RL与OPD.md)逐项比较目标函数和训练循环；状态分布的累积效应放到[状态分布偏移](../1.2-状态分布偏移/1.2-状态分布偏移.md)继续讨论。读完后，判断一种新方法时应能先问“它换了状态、信号还是估计器”，而不是只凭论文给出的名字分类。

## 4. 最小判断表

一项训练若只在固定参考前缀上预测参考 token，它属于 SFT；固定前缀上匹配教师概率，是离线 token 蒸馏；学生生成前缀后再匹配教师局部分布，是典型 OPD；学生生成完整回答并由回报决定更新，则落在 RL。序列蒸馏、偏好优化和自蒸馏会跨越这些格子，判断时仍回到四个变量即可。

这套坐标还有一个实际用途：避免把实现细节错当定义。是否使用 PPO、是否计算 KL penalty、是否缓存旧轨迹，都不能单独决定方法类别。PPO 可以优化教师判别器给出的奖励，KL 既可以是蒸馏目标也可以是策略约束，旧轨迹既可能用于经验复用也可能导致状态陈旧。名称相似不等于学习问题相同，公式相似也不等于数据分布相同。

## 5. 用一个两步任务检查边界

考虑只有两步的任务。第一步可以选 $A$ 或 $B$，选 $A$ 后第二步容易得到正确答案，选 $B$ 后仍有小概率补救。数据集中只有教师走过的 $A$ 路径。SFT 会提高 $A$ 以及其后正确 token 的概率；固定前缀 KD 能告诉学生第一步除 $A$ 外还有哪些次优选择，却仍看不到 $B$ 后的状态。

让学生 rollout 后，OPD 会采到一部分 $B$ 前缀，并询问教师如何补救。只要教师在这个状态上仍有优势，学生便获得离线数据没有的纠错监督。RL 则可能在 $B$ 路径偶然成功后提高整条轨迹概率，也可能因为终局失败同时惩罚第一步和其实合理的补救动作。这个小例子把状态覆盖、局部教师信号和终局信用分配分开了。

若验证器只检查终局答案，RL 可能发现教师从未展示的路径 $C$；OPD 若始终以教师为终点，则不会主动偏好 $C$。反过来，在成功轨迹极少时，RL 很难发现 $C$，而 OPD 能利用教师的逐步判断迅速减少明显错误。二者组合的理由来自各自缺口，与“先蒸馏再强化”这一经验顺序无关。

## 6. 名称之外还要看数据流

论文有时把学生生成的数据再做 SFT 称为 on-policy fine-tuning，也可能把教师对学生样本打分后执行 PPO 称为 on-policy distillation。仅凭名称无法分类。应画出四个节点：学生采样、教师或环境产生信号、训练器计算目标、更新后的策略重新采样。信号在哪个节点加入、是否依赖当前学生，才是可靠依据。

同样，self-distillation 不等于没有教师优势。若同一个模型在教师分支看到参考解、反馈或更长上下文，它与学生分支的条件分布不同；真正要追问的是额外信息从哪里来、部署时学生能否在没有这份信息时复现行为。训练范式边界最终服务于这种因果判断，而不是给论文贴标签。

训练时的 on-policy 与目标里的 on-policy 还需分开。数据由当前学生采样，只能证明状态接近当前策略；若随后使用冻结样本做多轮更新，learner 很快与行为策略分离。论文应说明 rollout 快照、当前参数和 reference 各指谁，否则“在线”这个词仍不足以确定优化对象。

这个区分也决定旧轨迹能否复用以及需要哪一种校正。
