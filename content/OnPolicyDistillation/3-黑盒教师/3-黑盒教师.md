# 黑盒教师：从文本反馈到训练信号

白盒 OPD 的定义很干净：学生生成前缀，教师在同一前缀上返回下一 token 分布，训练器直接比较师生概率。现实里更常见的教师是一个文本 API。它能续写、批改、排序或解释，却不告诉训练器每个 token 的概率。学生仍然可以在自己的状态上求助，难点从“去哪里问”变成“教师回答怎样变成梯度”。

## 1. 黑盒并不等于离线

如果先固定一批提示，让教师完整生成答案，再长期用这些答案做 SFT，状态分布来自教师数据，属于离线序列蒸馏。若每轮先由当前学生产生回答或中间前缀，再让教师针对这些状态续写、批改或比较，反馈随学生策略变化，仍具有 on-policy 成分。二者都只拿到文本，训练问题却不同。

这一区分很重要。离线教师数据稳定、便宜、易缓存，适合冷启动；学生状态上的查询能暴露实际错误，代价是请求量高、反馈会随前缀质量变化。黑盒路线在白盒 logits 之外增加了一层文本到训练信号的转换，这层转换必须有明确语义。

## 2. 两条主要路线

[序列反馈](3.1-序列反馈/3.1-序列反馈.md)从教师可直接返回的对象出发。教师可以从学生前缀续写，把修订答案作为监督序列；也可以对完整回答给偏好、分数或批评，再进入 SFT、DPO 或策略优化。三级文章[文本反馈与 GAD](3.1-序列反馈/3.1.1-文本反馈与GAD.md)进一步讨论 GAD 如何让教师只负责生成文本，再由判别器把师生差异变成 on-policy 奖励。

[判别反馈](3.2-判别反馈/3.2-判别反馈.md)专门研究这个中介。理想判别器的 logit 可以对应教师与学生序列的密度比，有限数据下却可能只学到长度、模板和措辞。三级文章[判别器漂移与奖励投机](3.2-判别反馈/3.2.1-判别器漂移与奖励投机.md)追踪学生、判别器和数据分布共同变化时为何失稳。

## 3. 信号压缩带来的代价

教师完整分布包含词表中所有替代动作的相对关系。一次续写只给出一个样本，偏好只给出两个序列的顺序，标量奖励又把整条回答压成一个数。接口越窄，需要的采样越多，信用分配也越困难。黑盒方法要报告教师请求数、输入输出 token 和候选数量，不能只报训练样本条数。

文字批评看起来信息丰富，却未必能直接优化。训练器要么把批评转成修订答案，要么让另一个模型抽取步骤标签，要么把它放入教师上下文再生成分布。每次转换都会引入偏差。可靠实验应证明转换后的信号与任务成功相关，而不只是语言上显得合理。

## 4. 教师、判别器与环境的职责

教师擅长给出通用语言判断，环境验证器擅长确认代码是否通过、数学答案是否正确。二者不应互相冒充。教师判别奖励可以推动学生更像高质量文本，环境奖励则允许学生找到教师未展示的正确策略。任务有可靠验证器时，黑盒蒸馏通常适合作为稠密指导，与结果奖励并用。

判别器属于训练目标的一部分，而不是可替换的工程附件。它的训练数据、更新频率、负样本来源和校准决定学生真正优化什么。判别器冻结后会陈旧，更新过快又会让奖励不断漂移；这场动态博弈需要锚点样本和独立验证器监控。

## 5. 一次完整训练循环

学生先按当前策略生成回答，记录模型版本与采样配置。教师对这些回答续写、评分或生成对照文本。若采用判别路线，训练器更新判别器并在学生轨迹上计算奖励；若采用修订路线，则构造监督或偏好样本。学生更新后重新采样，不能无限复用最早一批反馈而仍声称严格 on-policy。

循环中的每个缓存都有语义。缓存教师文本节省费用，但对应旧学生状态；缓存判别奖励还多了一层判别器版本陈旧。系统可以做这些折中，只需把策略距离、缓存年龄和性能变化一起报告。

## 6. 什么时候值得使用

强教师只有 API、无法提供 logits，而学生错误又需要针对性诊断时，黑盒路线很有价值。任务短、固定答案数据已经覆盖充分时，反复在线查询可能不如扩充离线 SFT。教师风格与任务正确性差异很大时，判别蒸馏还可能把学生推向表面模仿。

黑盒 OPD 的三个关键变量是教师看到的学生状态、文本信号采用的转换方式，以及转换器能否通过独立验证。三项说清楚后，续写、偏好、判别奖励和 RL 的边界就不会混在一起。

## 7. 与白盒路线的可比实验

若研究环境能够访问一个开源教师的 logits，可以人为限制接口，构造完整分布、top-$k$、单次续写、成对偏好和判别奖励。所有组使用相同学生状态与教师模型，便能测量信息通道逐步压缩后损失了什么。这样的受控实验比跨 API、跨模型比较更能回答黑盒代价。

预期并非白盒一定领先。完整 logits 信息丰富，却需要 tokenizer 对齐和大带宽；黑盒教师可以用自然语言解释复杂错误，也可能通过多轮批改提供白盒单步分布没有的长程信息。关键是把额外交互次数计入预算，并用相同任务目标验收。

### 8. 黑盒反馈的可追溯性

训练样本应保存学生模型版本、原始前缀、教师提示、完整返回、解析后的标签和最终 loss 类型。只保存一个标量奖励，会让后续无法判断教师原本说了什么，也无法在解析器变化后重算。可追溯记录不是通用工程装饰，它直接决定反馈转换能否被审查。

教师 API 更新或非确定采样会让复现实验更难。固定模型版本、系统提示和解码参数，并抽样重复请求估计反馈方差。若同一前缀的教师判断波动很大，学生训练需要聚合或置信度，而不是把每次响应都当作确定标签。

反馈方差还应按错误类型分桶。教师可能稳定识别格式错误，却对开放推理分歧很大；全局一致率会隐藏这种结构。查询策略可优先使用稳定且能改善 continuation 的反馈，把高分歧状态交给环境验证或多教师复核。

### 9. 章内阅读顺序

先读序列反馈，建立“文本怎样进入目标”的接口地图；再读文本反馈与 GAD，观察一种完整训练循环；随后进入判别反馈和漂移文章，理解中介模型为何既提供密度差信号，也制造新的奖励攻击面。四篇内容从可用信号走到动态失效，不把黑盒教师简化成一句“让大模型打分”。
