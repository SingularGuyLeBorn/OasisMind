# 序列反馈：看不到 logits 时怎样向教师学习

商业 API 或闭源模型通常只返回文本，训练器无法读取教师在完整词表上的概率。学生仍可把自己的前缀交给教师，但教师输出必须经过一次转换，才能成为梯度。转换方式决定训练究竟是固定示范学习、偏好优化、奖励学习还是黑盒 on-policy 蒸馏。

## 1. 最朴素的教师续写

学生先生成到状态 $s_t$，教师从该状态继续回答，再把续写当作 SFT 标签。这比从原始提示让教师完整生成更接近学生分布，因为监督起点确实来自学生；然而教师接管之后，训练前缀很快转回教师分布。它适合修补局部错误，却不能完整覆盖学生后续会走的路径。

教师续写还有标签多解问题。教师给出的一个序列只是其分布中的样本，把它当唯一正确答案会丢掉其他合理动作。增加多次采样能缓解，却提高查询费用，也可能让高温解码噪声混入监督。与白盒 logits 相比，黑盒文本用采样次数换取分布信息。

## 2. 批改与偏好

教师可以对学生完整回答给分、排序或写批评。标量分数适合训练奖励模型或直接进入策略梯度；成对偏好可用于 DPO 类目标；文字批评则需要进一步转成修订答案、过程标签或判别特征。三者的信息密度不同，不能都叫“教师反馈”后直接比较。

批评文本的优势是指出错误位置和原因，缺点是自然语言解释未必忠实。把批评再交给同一教师生成修订答案，可以形成“学生尝试—教师诊断—教师修订”的链条，但最终学生究竟学到诊断能力还是只模仿修订风格，需要单独测试。

## 3. GAD 的转换方式

生成式对抗蒸馏让教师和学生各自产生文本，再训练判别器区分来源。判别器分数成为学生 on-policy rollout 的奖励，策略优化推动学生文本向教师分布靠近。教师不需要暴露 logits，学生也不必逐字模仿某一条教师回答。

这种路线的关键中介是判别器。它若学会长度、格式或措辞等表面特征，学生就会优化这些捷径。教师文本与学生文本的数据处理、采样温度和长度分布必须对齐，否则判别任务太容易，奖励没有语义价值。GAD 的具体训练循环放在本路线的三级文章中展开。

## 4. 查询预算改变方法选择

一次教师续写可能返回数百 token，一次打分只返回少量文本或标量；多次采样能近似分布，却迅速放大费用。公平比较应把教师输入、输出 token 和请求次数都纳入预算。只按样本条数比较，会让返回长推理链的方法占据隐性优势。

缓存教师输出能降低费用，但学生状态持续变化，旧反馈未必仍覆盖当前失败。黑盒条件下又难以用策略 KL 精确衡量教师信号陈旧度，因此需要记录前缀来源、模型版本和采样配置，并通过当前策略重放抽样检查。

## 5. 从文本进入参数

序列反馈最终有三条入口：作为监督序列进入交叉熵，作为比较关系进入偏好目标，或作为奖励进入策略梯度。若论文使用“on-policy distillation”这个名称，必须继续看学生 rollout 是否参与构造反馈，以及更新究竟匹配教师文本分布还是最大化某个判别奖励。

本路线与[判别反馈](../3.2-判别反馈/3.2-判别反馈.md)相连：序列反馈关注教师能返回哪些信息，判别反馈研究这些信息压成奖励后会丢掉什么。黑盒教师采用另一种信号接口，同时引入中介模型、查询噪声和奖励投机三类问题，不能按白盒 OPD 的低成本版本理解。

## 6. 修订答案与原回答怎样配对

教师看到学生回答后，可以直接重写，也可以先指出错误再局部修改。完整重写提供流畅正样本，却可能与学生原轨迹差异太大，训练退回模仿教师标准答案；局部编辑保留学生状态，更容易定位变化，但编辑边界和未改片段是否正确需要确认。

一种对照是让教师从原提示独立作答，另一组让教师读取学生回答后修订。两组教师能力相同，差异主要来自学生状态条件。若修订组只在措辞上更接近学生、任务成功没有提升，状态条件没有提供有效诊断。

批评文本还可以作为教师的隐藏条件：教师先写诊断，再生成修订，但学生只学习修订分布。这样避免要求学生模仿可能冗长的批评，同时利用诊断改善教师判断。评估应比较有无批评中间步骤，并计算增加的教师 token 成本。

## 7. 偏好数据的参照对象

教师比较学生回答与教师回答时，偏好几乎总指向强教师，目标混合了来源和质量。更有信息的比较是在多个学生候选之间排序，或让教师对同一回答的局部修订前后配对。前者训练学生内部选择，后者强调具体纠正。

偏好强度也不能从一个二元标签看出。两条几乎等价的回答与一对正确/错误回答被同等处理，会浪费教师置信信息。若接口允许，可收集等级或理由，再通过校准决定是否进入损失；不可靠的自报置信度不能直接当权重。

### 8. 多轮反馈何时有用

一次教师响应可能误解学生意图，多轮对话允许学生提交修订、教师再次检查。它更接近真实辅导，却让状态包含整段交互历史，训练和部署成本都上升。若最终学生部署时没有教师，多轮过程需要被蒸馏回单模型，而不能只展示带教师交互时的成绩。

多轮反馈最适合定位可迭代验证的任务：代码测试失败后修复、证明缺口补全、工具调用错误恢复。开放式问答若没有独立终止标准，轮数增加可能只带来更长文本。路线选择仍由反馈是否改变可验证结果决定。

### 9. 序列反馈的信用位置

教师给出整段修订时，训练器需要决定从哪里开始计算 loss。对整段修订做 SFT 会同时强化未改动内容和真正修复位置，信号被大量容易 token 稀释；只训练编辑区更集中，却要求可靠对齐原回答与修订。可用字符串 diff 作为起点，但语义等价改写会让表面差异过大。

另一种办法是从教师指出的首个错误状态截断，让学生在此前保持原轨迹，之后学习教师 continuation。它直接对应恢复问题，也依赖教师定位准确。实验可比较全序列、编辑区和错误点后三种掩码，观察首次错误位置与最终成功率。

### 10. 反馈解析失败不能静默丢弃

黑盒教师常用自然语言或 JSON 返回批评。解析失败若被直接过滤，会让训练数据偏向格式规范、通常也更简单的样本。应报告解析成功率和失败题型，并保留原始文本重新处理。

强制结构化输出可提高解析率，却可能降低教师解释质量。较稳妥的做法是让教师同时给出短结构标签与自由批评，训练器使用前者路由、后者构造修订。两部分各自的增量应通过消融确认。

### 11. 如何比较不同文本接口

在相同学生前缀上分别请求续写、评分、成对比较和批评，保持教师 token 预算接近，再测它们对一次更新和完整任务的影响。续写信息量大但成本高，评分便宜却稀疏，批评是否有价值取决于后续转换。

比较结果应同时给教师调用成本、反馈一致性、学生梯度方差和任务收益。这样才能解释某接口为什么适合当前任务，而不是把“自然语言更丰富”当作无需验证的优势。
