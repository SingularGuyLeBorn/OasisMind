# 局部分布匹配：教师 logits 怎样进入学生轨迹

白盒教师最有价值的地方，是能在任意学生前缀上返回下一 token 的条件分布。训练不再只有一个正确 token，而能看到替代动作之间的相对关系。不过，“拿到 logits”只是接口条件，真正的学习目标还要回答前缀从哪里来、比较哪一种散度、覆盖多少词表以及怎样估计梯度。

## 1. 共同 baseline

在状态 $s_t$ 上，最直接的目标是 forward KL：

$$
D_{\mathrm{KL}}\!\left(\pi_T\Vert\pi_\theta\right)
=\sum_a\pi_T(a\mid s_t)\log\frac{\pi_T(a\mid s_t)}{\pi_\theta(a\mid s_t)}.
$$

去掉与学生无关的教师熵后，它等价于以教师概率为软标签的交叉熵。教师认为合理的多个 token 都会得到正向监督，适合覆盖多模态答案；代价是需要访问教师较完整的词表分布。若只返回 top-$k$，尾部质量如何处理会直接改变目标。

reverse KL 把权重放在学生分布上，更强调学生当前会采到的动作：

$$
D_{\mathrm{KL}}\!\left(\pi_\theta\Vert\pi_T\right)
=\sum_a\pi_\theta(a\mid s_t)\log\frac{\pi_\theta(a\mid s_t)}{\pi_T(a\mid s_t)}.
$$

它倾向集中到教师高概率模态，也更容易受教师对学生动作给出极低概率的影响。forward 与 reverse 的差异不是“一个离线、一个在线”；前缀来源和散度方向是两条独立轴。

## 2. 三种接口的边界

完整 logits 能精确计算词表求和，但显存、带宽和远程服务接口往往不允许。top-$k$ 需要明确集合来自教师还是学生、截断后是否重归一化、集合外质量怎样处理。只返回已采 token 的 log-prob 最省通信，却把分布匹配变成抽样估计，方差和支持集问题随之出现。

若教师与学生 tokenizer 不同，“同一 token”甚至没有直接定义。可选办法是把监督提升到字符串或字节区间，再对齐多个 token 的联合概率；简单按 token id 对齐会产生静默错误。词表路由属于目标语义，不只是数据预处理。

## 3. 方法怎样落在坐标上

[GKD](2.1.1-GKD.md)把固定数据与学生 rollout 的混合比例、以及散度选择拆成两个旋钮，给出最清楚的局部匹配 baseline。[DistiLLM](2.1.2-DistiLLM.md)通过 skew KL 和自适应 off-policy 数据处理支持集与稳定性，并在后续工作中拆开教师、学生两路回答的训练职责。[逐 token 信号](2.1.3-逐token信号.md)则从接口出发，比较 full-vocab、top-$k$ 与 sampled-token 的实际梯度。

这些方法分别解决不同缺陷。GKD 改变训练状态，DistiLLM 更关心散度在支持集不重合时的行为，接口文章关注计算约束如何改变可实现的目标。把它们都归为“教师打分”会丢掉真正的变量。

## 4. 如何判断局部匹配有效

训练损失下降只说明学生在被查询的前缀上接近教师。更强的证据至少包括三层：教师在学生状态上确实优于学生；局部分布变化能改善从该状态开始的 continuation；完整任务指标在相同生成与教师预算下提高。若第一层不成立，蒸馏没有可靠方向；若前两层成立而终局不涨，关键状态可能没有被采到，或者局部更新没有跨越长程依赖。

实验还应分别消融状态来源、散度、词表截断与轨迹新鲜度。一次同时换掉四项，即便结果上升，也无法判断收益来自哪里。对推理任务，应额外统计错误类型：计算错误、格式错误、提前终止和错误分支对不同接口的敏感度往往不同。

## 5. 新增代价

白盒 OPD 把监督变稠密，也引入教师前向成本、logits 传输、双 tokenizer 对齐和版本同步。教师吞吐不足时，系统会缓存轨迹或概率，训练随即偏离严格 on-policy。工程优化不能只报告速度，还要说明它改变了哪一个统计假设。

在当前模型附近，短暂缓存常能以很小偏差换取明显吞吐；策略更新剧烈或任务存在窄分叉时，同样的陈旧度可能破坏状态覆盖。是否可复用不能靠固定步数判断，应结合策略 KL、行为概率与下游 continuation 变化。下一节的序列目标与旧轨迹会沿这条线继续展开。

## 6. 散度方向背后的行为偏好

设教师在两个合理 token 上分配 $0.6$ 与 $0.4$，学生暂时集中在第一个 token。forward KL 会持续要求学生给第二个 token 保留质量，因为遗漏教师支持会受到明显惩罚；reverse KL 更容易接受学生集中到一个高概率模态。开放式生成里，前者有利于保存多样性，后者可能产生更锐利的输出。若教师尾部包含噪声，forward KL 也会把噪声传给学生。

Jensen–Shannon、skew KL 等中间目标试图在覆盖与稳定之间折中。它们改变了极端概率区域的权重，却没有消除教师校准问题。一个过度自信的教师会让任何依赖其概率的散度产生偏差；温度缩放能改变软硬程度，但温度应在独立状态上校准，而不是只挑最终分数最好的值。

## 7. 从数学目标到一次训练批次

一次可复现的局部匹配更新应明确：用哪个策略生成多少条轨迹；在哪些 token 位置调用教师；教师返回完整 logits、top-$k$ 还是已采 token；学生 loss 对序列和 batch 如何归一化；超长样本怎样截断；教师输出是否缓存。任何一步不清楚，公式相同也可能得到完全不同的有效权重。

长度归一化尤其容易造成隐性差异。按 token 平均让每个位置权重近似相同，按序列平均则让短序列单 token 权重更大；只在回答部分计算又与包含提示 token 不同。推理数据长度分布宽时，这些选择会改变训练重点，应与论文声称的机制保持一致。

教师和学生并行部署后，还要记录精度与数值稳定性。教师 log-prob 若以低精度传输，尾部 token 可能下溢；学生对教师零概率动作计算 log-ratio 会爆炸。裁剪与最小概率可以避免数值错误，但同时改变目标，必须报告阈值并检查被裁剪样本比例。

### 8. 读结果时追踪行为变化

局部分布方法常展示更低蒸馏 loss，却未必展示学生是否在关键状态上变强。最有价值的分析是从失败案例反推：更新前学生在哪一步偏离，教师在那里给了怎样的分布，更新后同类前缀的行为是否改变。这样的轨迹证据能把平均指标与机制连起来，也能揭示教师信号虽然丰富、却落在无关位置的情况。

局部目标还应检查校准而非只看排序。教师给正确动作 $0.4$、错误动作 $0.3$，与给出 $0.99$、$0.001$ 会产生完全不同的梯度尺度。温度改变两者差距，也改变尾部覆盖。报告教师熵、学生熵和关键动作概率，比单独展示 top-1 一致率更能解释训练动态。

当教师和学生尺寸差距很大时，教师分布可能过于尖锐，弱学生无法一次吸收；差距很小时，软分布又几乎没有增量。模型规模变化会改变最合适的温度、散度和查询位置，因此这些超参数不能从一个尺寸无条件搬到另一个尺寸。

同一教师在不同任务上的熵也会变化。代码语法位置通常很尖锐，开放式解释位置更分散；统一温度会让一类位置过硬、另一类位置过软。按位置类型或教师熵分桶观察，比用一个全局平均更容易发现目标失衡。
