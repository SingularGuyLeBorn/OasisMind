# 探索与奖励接口：OPD 之后为什么还需要 RL

OPD 可以高效地把教师行为写入学生，却通常受教师分布的支持集限制。任务有可靠验证器时，学生还能通过探索发现教师没有稳定展示的策略。RLVR 将优化目标从“接近教师”转向“提高任务回报”，承担蒸馏覆盖不到的探索。

## 1. 教师上限与任务上限

教师在大多数学生状态上更强时，模仿是低方差的改进方向。但教师可能偏好固定风格、遗漏新策略，或在特定状态上也会犯错。只最小化师生距离，学生最多逼近被查询条件下的教师行为；最大化可验证回报则允许偏离教师。

偏离并不自动带来提升。探索空间巨大、成功样本极少时，RL 梯度接近噪声。此时教师分布可以作为 proposal、KL 锚点或过程指导，先把学生带到有成功概率的区域，再由回报选择策略。

## 2. 结果奖励的优势与缺口

数学答案、代码测试和形式证明常有明确验证器。结果奖励与任务目标接近，减少奖励模型的主观偏差；然而一个二元结果没有告诉模型错误发生在哪里。长 CoT 中，所有 token 共享终局成败，信用分配方差随长度上升。

OPD 的逐 token 教师信号能补这块缺口。常见组合是对学生 rollout 同时计算教师 log-ratio 与结果优势：前者提供局部方向，后者允许整体策略超越教师。两项尺度若不校准，稠密蒸馏可能压过稀疏回报，使训练退化为模仿。

## 3. 过程反馈并非天然正确

过程奖励模型、教师批改或步骤验证器可在中间位置给分，缩短信号路径。它们也可能误判等价推理、鼓励固定格式，或把局部合理当成全局正确。过程信号应与结果验证器做一致性检查，并在不同推理风格上评估。

当过程反馈来自同一教师时，可将其解释成黑盒蒸馏；当它由环境规则产生，则更接近奖励塑形。来源不同决定误差结构，也决定是否能通过增加教师查询解决。把所有中间分数统称为 dense reward，会掩盖这些差异。

## 4. self-play 与自蒸馏

学生可生成多个候选，让验证器筛出成功轨迹，再把成功经验作为教师条件或训练标签。这形成 self-play 式闭环：探索产生新信息，自蒸馏把一次成功压回参数，下一轮策略因此改变。信息来源仍是环境选择，而非模型凭空创造。

候选数量越多，找到成功答案的概率越高，但训练预算也随之增长。报告 pass@k 提升时，要区分推理时多采样收益和参数更新后的单样本收益。只有后者才能说明蒸馏或 RL 改善了策略本身。

## 5. 组合目标怎样避免互相抵消

设蒸馏优势为 $A_T$，任务优势为 $A_R$，组合更新可抽象为 $A=\alpha A_T+\beta A_R$。两者在教师正确时可能同向，在学生找到教师不偏好的成功策略时会冲突。固定系数无法适应所有状态，可以按验证结果、教师置信度或训练阶段调整，但每一种门控都会引入新的估计误差。

更容易解释的实验从分阶段训练开始：先 OPD，再 RL；然后与联合目标比较。若联合训练更好，再分析优势夹角、冲突样本比例和策略离教师的距离。没有这些中间量，很难判断组合收益来自协同还是额外计算。

## 6. 何时停止模仿

可以跟踪教师在学生状态上的 continuation 优势。当优势持续缩小，而学生探索成功率和验证器可靠性上升时，训练重心可从蒸馏移向 RL。若教师仍在关键错误状态上明显更强，过早停止会浪费稠密监督。

最终选择取决于外部条件：教师访问成本、验证器覆盖、任务长度和学生初始能力。OPD 与 RL 分别承担知识转移与目标探索，可以在同一系统中协作。把二者按问题拆开，才知道性能变化究竟来自哪条链路。

## 7. 验证器覆盖决定探索边界

数学最终答案验证器只能判断结果，无法识别错误步骤恰好抵消；代码测试只覆盖给定输入，可能接受硬编码。RL 会主动寻找这些缺口。扩大测试、加入随机化和对抗样本，比在优化器上增加惩罚更接近根因。

验证器过严也会拒绝等价解，例如表达格式、浮点误差或证明语法差异造成假阴性。训练前应在人工确认样本上测精确率与召回率，并在策略更新后持续抽查，因为学生会进入原验证集未覆盖的新区域。

### 8. 探索温度与策略更新

高温采样扩大候选覆盖，能发现新策略，也产生更多无意义轨迹；低温接近当前最优行为，方差小，却容易困在教师模式附近。温度属于数据生成策略，不能与 learner 的熵正则混为一谈。

训练中改变温度会改变行为策略，off-policy 修正和组内优势分布也随之变化。应报告候选成功率、唯一解比例和策略熵，判断提升来自更好更新还是增加搜索。

### 9. 教师作为 proposal

教师可以直接提供部分候选，也可以只在学生失败后给提示，还可以给 token 级 proposal。约束逐渐增强，早期成功率上升，学生独立发现新策略的比例可能下降。训练数据应标记成功轨迹来源。

[蒸馏信号与 RL 奖励](5.2.1-蒸馏信号与RL奖励.md)进一步展开组合目标、优势冲突、轨迹复用和预算。路线层面的最低验收是纯蒸馏、纯 RL 与组合采用相同或可核算的 rollout，并分别测量教师优势和任务优势。

### 10. 奖励密度与奖励可靠性要分开

过程模型能给每一步分数，密度高却可能不准；结果验证器只在末尾返回成败，稀疏但可靠。选择信号不能只追求密集。可在同一批轨迹上测过程分数对最终成功的校准，并比较它是否真的降低优势方差。

若过程模型在教师标准轨迹上训练，它可能把非标准成功路径判低。加入学生成功轨迹和等价解能扩大覆盖，但也需防止验证器错误进入标注。过程反馈最适合作为辅助，最终仍由独立结果验收。

### 11. 多样性与集中度

reverse KL、教师 proposal 和只保留成功 self-play 都可能让策略集中。集中能提高 pass@1，也可能降低 pass@k 与新策略发现。应报告同题候选的语义聚类、答案熵或独立策略数，而不只看 token 熵。

多样性本身也不是目标。大量无效轨迹只增加成本。需要观察不同策略簇的成功率及其对训练数据的贡献，保留能探索新高回报区域的多样性。

### 12. 组合方法的失败边界

教师与验证器同时不可靠时，组合不会自动互相纠错，反而可能让两个偏差共同强化。教师信号强、奖励弱时退化为模仿；奖励漏洞强、蒸馏弱时仍会投机。只有两类信号各自经过独立检查，组合才有意义。

组合失败时，优势方向、尺度和数据来源会区分原因。同一状态的两种信号长期相反说明目标冲突；信号同向而训练不稳，则更可能来自估计方差或优化器。
