# CoT 蒸馏与 RL 怎样配合

推理模型把 OPD 推到台前, 也让几个概念挤在了一起. 强教师生成长 CoT 后让学生 SFT, 学生自己 rollout 后接受可验证奖励, 教师在学生前缀上返回逐 token 分布, 三者都可能提升数学或代码能力, 训练日志里也都会出现 response token、log-prob 和正确率. 但它们对状态分布、信息来源与信用分配的处理并不相同. **CoT 描述监督内容的形态, on-policy 描述状态由谁产生, distillation 描述目标从谁那里来.**

这一章把推理训练拆成三层. 第一层让学生获得可用的推理语言与基本解题路径;第二层让学生在自己的错误状态上得到局部方向;第三层用结果奖励鼓励教师也未覆盖的新策略. 这三层可以组成流水线, 也可以在同一批 rollout 中形成混合目标.

## 1. 离线 CoT 蒸馏解决冷启动

教师预先生成完整推理轨迹, 学生在这些固定 token 上做最大似然, 属于 sequence-level KD 或 reasoning SFT. 它的优点是稳定、便宜、容易筛选, 特别适合把长推理格式和基本搜索策略放进小模型支持集. DeepSeek-R1-Distill、s1、LIMO 等工作展示了高质量推理轨迹的价值, 但训练时的前缀来自教师数据, 因而仍存在自由生成后的状态失配.

这个阶段的核心变量是数据. 答案正确只是最低条件;还要检查轨迹有没有中途逻辑错误、是否靠泄漏答案完成、长度与难度是否匹配、不同题型是否覆盖. 把错误但写得像推理的长文本交给学生, 只会训练出稳定的错误风格. 对可验证任务, 执行器和答案校验应先筛掉失败轨迹;对开放任务, 多教师或人工复核更可靠.

离线 CoT 对弱学生尤其重要. Reverse-KL 风格的 on-policy 更新主要重排学生已经访问的模式;若学生连合法解题步骤都采不到, 教师在其乱码前缀上逐 token 指导也很难产生新路径. SFT 先把路径放进支持集, OPD 再处理学生沿路径走偏后的局部状态.

冷启动数据的作用可以用支持集解释. 假设一条有效推理路线由 $T$ 个关键选择组成, 学生在每个选择上给正确动作的概率约为 $p_t$. 完整路线被自由采到的概率近似为 $\prod_t p_t$. 即使每一步都有 $0.8$ 的概率, 二十个关键选择全部正确也只有约 $0.8^{20}\approx0.012$. 教师 forcing 把这些动作逐个放到学生可学习的前缀上, 先提高局部概率;当整条路线开始偶尔出现在学生 rollout 中, OPD 和 RLVR 才有机会沿真实状态继续改进.

这也解释了为什么 CoT 数据不能只按最终答案筛选. 两条都答对的轨迹, 一条可能依靠稳定的中间不变量, 另一条可能先写错再碰巧修正;SFT 会同样提高两条轨迹上的每个 token. 数据筛选至少要看结论正确、关键步骤可验证、过程没有使用部署时不可见的信息, 以及长度是否与题目难度相称. 多条正确轨迹可以覆盖不同解法, 但同一道题复制几十种近义表述只会放大措辞频率.

学生容量也会限制可蒸馏路线. 大教师能在长上下文里维持十几个并行假设, 小学生未必有足够表示能力复现. 此时硬逼学生逐 token 模仿会表现为训练 loss 下降、自由生成仍然崩溃. 更适合的处理是把教师轨迹压缩成学生能维持的状态表示, 或选择步骤更短但同样正确的解法, 再用验证结果确认压缩后没有丢掉必要条件. “更长的 CoT”不是天然更好的监督.

## 2. OPD 校正学生自己的推理状态

进入 OPD 后, 学生针对题目生成 $y\sim\pi_\theta$, 教师在每个 $s_t=(x,y_{<t})$ 上读取相同前缀并返回条件分布. 教师此时面对的可能是一段正确推理、一个尚可恢复的岔路, 或已经破坏语义的前缀. 只有教师能在这些状态上持续提供更好的下一步分布, 稠密监督才有意义.

推理风格兼容性因而比独立 benchmark 分数更关键. 一个擅长简短符号推导的教师, 未必能稳定续写学生的自然语言探索;一个习惯从头重做的教师, 在被迫接受错误前缀时可能只会修辞而不会纠错. 可从学生 rollout 截取不同位置, 测教师对可恢复动作的 margin、困惑度和终局成功率. **教师要在学生访问的状态上更强, 不是只在自己的轨迹上更强.**

逐 token 信号也不等于真实过程监督. 教师概率差可能集中在少数位置, 其余 token 只是风格对齐;同源教师还可能和学生共享盲点. 近期 token-level 分析发现, 稠密损失的有效纠正位置可能相当稀疏. 因此需要把 KL 峰值位置与语义角色、后续结果和反事实替换结合分析, 不能用「每个 token 都有 loss」直接推出「每一步推理都被教会」.

学生错误前缀还可以按可恢复性分三类. 第一类只是局部符号或格式偏差, 教师在当前前缀上直接续写即可修复. 第二类已经选择了较差路线, 但通过回溯、补充条件或换工具仍可能成功;教师需要理解学生已走过的路径, 而不是从自己的标准答案重新开始. 第三类前缀已经丢失关键约束或把环境改到不可逆状态, 下一 token 再好也救不回来. 对第三类继续计算高置信 token KL, 往往只会训练出流畅的失败后缀.

可恢复性可以通过 continuation 实验估计. 在同一个前缀上分别让学生、无特权教师和带参考解教师续写多次, 记录最终成功率. 若特权教师明显高于其余两者, 这个状态值得蒸馏;若三者都接近零, 应回到更早的岔路、重新采样或只保留终局负反馈. 若教师只是在当前位置给高概率, continuation 仍无法成功, 局部 logit 优势没有转化成路线优势.

教师逐 token 打分还可能奖励“像教师”而非“能解题”. 可以把 token 按语义角色切分为计划、计算、工具动作、解释、格式与 EOS, 分别统计 KL 与教师优势. 若差异主要集中在连接词和排版, 蒸馏 loss 很密却没有进入推理核心. 反事实替换更有解释力:只替换一个高 KL 位置, 固定其余前缀继续采样;终局成功率随替换改善, 才说明这个位置对能力有实际贡献.

## 3. RLVR 负责探索教师之外的策略

RLVR 让学生在自己的轨迹上接受可验证结果奖励. 数学答案、单元测试、形式证明检查器或工具执行结果不要求教师给出正确下一 token, 因而有机会奖励教师没有展示过的新解法. 代价是信号稀疏, 长轨迹上的信用分配困难, 采样成本也更高.

OPD 与 RLVR 的能力来源不同. OPD 把教师已有行为迁移到学生访问状态, 上限受教师在这些状态上的判断约束;RLVR 用环境结果选择策略, 理论上能够越过固定教师, 但探索效率取决于学生初始能力和奖励可验证性. 把「OPD 比 RL 样本高效」理解成 RL 已经没用, 会漏掉最重要的边界:教师能教的部分适合蒸馏, 教师也不会的部分仍要探索.

二者可以共享 rollout. 对成功轨迹, 环境奖励确认终局有效, 教师分布提供局部替代动作;对失败轨迹, 结果奖励给出负方向, 教师判断哪些前缀尚可恢复. 一个常见混合式目标写成

$$
\mathcal L=\lambda_{\mathrm{distill}}\mathcal L_{\mathrm{OPD}}-\lambda_{\mathrm{rl}}\mathcal J_{\mathrm{RLVR}}+\lambda_{\mathrm{reg}}\mathcal L_{\mathrm{anchor}}.
$$

权重不能只按 loss 数值调到相近. 三项的 token 覆盖、梯度方差和序列长度归一化不同, 应比较梯度范数、夹角与各任务切片的变化.

RLVR 的朴素做法是同一道题采样一组回答, 用可验证结果构造组内相对优势. 当题目太容易时, 一组回答全部正确;题目太难时, 一组回答全部失败. 两种情况的组内方差都接近零, 相对优势无法告诉模型哪个动作更好. 增加组大小有时能采到少数异类结果, 计算成本也按 rollout 数增长. 课程采样、难度分桶和跨题 baseline 可以缓解退化, 但它们改变了训练数据分布, 需要单独验证.

OPD 在这类 batch 上仍可能有信号. 即使八条回答全错, 教师也可能在若干可恢复前缀上给出不同分布;即使八条全对, 教师也可能指出更短或更稳的路径. 反过来, 教师和学生已十分接近时, KL 几乎为零, RLVR 仍能依据外部成功发现新路线. 两种方法的“无信号区”并不重合, 混合训练的价值就在这里, 而不是简单把两个 loss 相加.

真正希望学生超过教师时, 训练中必须保留一条不以教师为上限的通道. 可以让环境奖励决定最终保留哪些轨迹, 教师只提供低方差的局部引导;也可以随着教师优势缩小逐步降低蒸馏权重. 若所有成功轨迹都要先通过教师概率门槛, 教师不熟悉的新策略会在产生收益前被过滤掉. 教师适合作为 proposal 和 regularizer, 不应自动拥有对探索结果的一票否决权.

## 4. 过程反馈与结果反馈怎样配合

结果反馈可信但稀疏, 过程反馈密集却可能错. 最简单的组合是 outcome gating:只有答案通过验证的轨迹才做自蒸馏, 或按结果给 token KL 加权. 更细的方案用执行日志、编译错误、证明器状态或教师批评定位关键步骤, 再对局部区间分配更高权重. 还可以让教师在看到结果后重新评估学生前缀, 把「这条轨迹失败了」转成条件分布变化.

这里要防止答案泄漏. 特权教师可以看到参考解或执行反馈, 学生部署时看不到. 教师对学生已采前缀给分时, 参考答案不能被拼进学生输入、缓存或 label mask 错位的区域. 否则训练指标会很好看, 模型学到的却是读取答案位置. 特权信息只用于构造教师分布, 学生侧上下文必须严格保持部署形态.

另一个风险是 outcome 把探索多样性压没. 若只蒸馏当前能成功的轨迹, 学生会越来越集中在少数容易模式;困难题的失败状态得不到监督. 可保留「失败但教师可恢复」的轨迹, 或按教师优势而非最终成败选样. **结果负责判断整条路线是否奏效, 教师优势负责判断当前状态是否仍值得教.**

把结果直接复制到每个 token 是最粗的时间分配. 一条 2000 token 的失败回答中, 前 1500 个 token 可能完全正确, 错误只发生在一次代数变形;整条同罚会压低大量好动作. 另一端是逐步过程标注, 信息更细, 标注器却可能把“写得像标准解”当成正确. 实用的中间做法是按段落、工具回合或验证检查点切段, 从每个边界重新 continuation, 估计后续成功概率. 成功概率显著下降的位置比固定 token 窗口更接近真正岔路.

代码任务提供了一个清楚例子. 编译器错误可以定位语法和类型问题, 单元测试给出函数级结果, 隐藏测试只给最终通过数. 若编译失败, 教师先利用错误日志修复可执行性;程序可运行后, 再用测试差异寻找语义错误;所有公开测试通过后, 隐藏测试仍负责防止对样例过拟合. 三种反馈处在不同粒度, 不能统一塞进一个标量后期待模型自动还原因果链.

数学任务没有天然的逐步执行器, 但可以使用代入检查、等式验证、约束检查和最终答案验证. 形式证明任务则能让 proof state 直接成为环境状态, 每个 tactic 是否被接受提供局部反馈. 反馈越接近真实状态转移, 越容易区分“文本看起来合理”和“动作真的让问题更接近解决”. 这也是工具增强推理适合研究混合蒸馏的原因:环境可以提供教师语言概率之外的独立证据.

## 5. 长 CoT 带来的特殊问题

异步训练和样本复用会放大策略滞后. 一次长 rollout 结束、教师评分完成并送到 learner 时, 其他 worker 可能已经推进了多个版本;同一批样本再训练多个 epoch, 行为策略与当前 learner 的差距还会继续扩大. 监控可以按 token 位置统计 importance ratio 与师生 KL, 用来发现长上下文中的局部失稳, 但不能据此把尾部 token 叫作“更旧”:常规冻结快照生成的一整条轨迹共享同一个行为策略版本.

长度本身还会成为捷径. 教师更短时, reverse KL 可能过早抬高 EOS;教师更长时, 学生可能学会无效展开. 任务正确率、平均长度、正确样本长度、错误样本长度和单位 token 收益应放在一起看. 对简单题保持短答、困难题增加计算, 比统一拉长 CoT 更接近真正的推理提升.

多轮工具任务把状态从文本前缀扩展为环境状态. 工具调用改变外部世界, 教师若只读取对话文本却没有相同工具结果, 条件分布就不在同一个状态上. Agent-level distillation 需要记录动作、观察、工具版本和环境转移, 并处理跨回合信用. 这也是 OPD 从单轮推理走向 long-horizon 时最明显的研究缺口.

## 6. 一条更稳的训练顺序

先用经过验证的 CoT 数据完成冷启动, 让学生能够生成格式正确且偶尔成功的轨迹. 随后在学生 rollout 上做分布蒸馏, 修正真实暴露的错误前缀. 当师生差距缩小、教师增益开始耗尽时, 增加 RLVR 权重, 用环境奖励探索教师之外的策略. 训练全程保留通用数据或锚定损失, 避免推理专项吞掉对话与知识能力.

这不是固定配方. 强学生可以直接进入 OPD;黑盒教师只能先做 CoT 数据或偏好信号;没有可靠验证器的开放任务更依赖教师分布. 判断顺序的依据是支持集、教师增益与奖励可靠性, 不是方法发布时间.

阶段切换应由可观测量触发. 冷启动阶段关注自由生成的合法率、偶发成功率与关键动作覆盖;当学生已经能访问有价值状态, 才增加 OPD. OPD 阶段关注教师在学生前缀上的 continuation 增益、师生 KL 落在哪些语义位置, 以及 KL 下降能否转成任务收益. 教师增益持续缩小、外部验证仍能区分新策略时, RLVR 权重才有理由上升.

混合训练也可以在一批数据内做, 但路由条件要明确. “答案正确且教师仍有明显优势”可同时使用结果奖励和蒸馏;“答案错误但教师可恢复”以教师信号为主;“教师与学生都不会但验证器可靠”交给探索;“没有可靠教师也没有可靠验证”则不应强行自举. 路由器判断错了会形成选择偏差, 所以要保留随机对照样本, 比较被路由与未路由状态的真实收益.

把三条路线放在同一组问题下, 差别会更清楚:

| 问题 | CoT SFT | OPD | RLVR |
|---|---|---|---|
| 训练前缀来自哪里 | 固定教师轨迹 | 当前或近当前学生轨迹 | 当前或近当前学生轨迹 |
| 主要信息来源 | 教师给出的完整解法 | 教师在学生状态上的条件分布 | 环境或验证器的结果 |
| 信号粒度 | 每个目标 token | 完整词表、top-$k$ 或已采 token | 通常是序列或回合级 |
| 最擅长解决 | 冷启动与路线注入 | 暴露偏差与局部纠错 | 探索教师之外的策略 |
| 主要盲区 | 自由生成状态未覆盖 | 教师盲点与支持集不足 | 稀疏信用和采样成本 |

这张表也能防止名称误导. 使用教师生成 CoT 并不会自动成为 OPD;学生自己采样也不会自动成为 RL, 因为后续目标可能仍是教师分布;采用逐 token reward 也不能自动算作过程监督, 因为每个位置的数值可能只是同一终局结果的展开. 判断方法时先写清前缀、信息源、反馈粒度和估计器, 再使用 SFT、OPD 或 RLVR 的名称.

通用能力锚定也不能只看一个平均分. 推理专项可能提高数学, 同时让回答变长、对话变硬、知识问答下降. 锚定数据应覆盖原模型需要保留的能力, 并与专项梯度做冲突分析. 若两项梯度长期相反, 单纯加大锚定权重只会让优化互相抵消;更合理的做法是检查专项数据是否包含不必要的风格 token, 或把蒸馏限制到真正影响结果的位置.

成本口径同样影响阶段选择. CoT SFT 的教师生成可以离线摊销, OPD 每轮都要重新生成学生轨迹并让教师评分, RLVR 则常为同一题采多条回答. 比较时至少分开教师生成 token、学生 rollout token、教师评分 token 和 learner 训练 token. 只按 optimizer step 计算, 会把一次便宜的 SFT 更新和一次包含多条长 rollout 的 RL 更新当成同样成本. 若 OPD 更快达到某个分数, 还要检查节省的是梯度步、总 FLOPs 还是墙钟时间;三者可能给出不同结论.

最终选择也取决于线上目标. 小模型部署若受输出延迟限制, 蒸馏出更长的推理并不一定有价值;代码 Agent 若允许多次执行, 探索和工具反馈反而比模仿单条教师轨迹更重要. 训练方法应服务于部署时允许的计算、可获得的反馈和错误成本. 同一个学生在离线数学 benchmark 上适合 OPD, 到不可逆工具任务里可能更需要保守的 SFT 冷启动与环境约束.
