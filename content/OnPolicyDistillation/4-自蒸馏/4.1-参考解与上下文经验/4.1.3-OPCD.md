# OPCD:把上下文经验蒸馏进参数

逐题参考解和环境报错之外,还有一类知识藏在长期上下文里:模型过去解决同类问题的经验、经过优化的系统提示词、领域规则或操作手册.传统 context distillation 可以让模型模仿带上下文教师,却常在固定数据或教师轨迹上训练.2026 年 2 月提出的 **On-Policy Context Distillation(OPCD)** 把上下文蒸馏放回学生自己的轨迹:学生生成它实际会访问的状态,条件化教师在这些状态上给出分布,再用 reverse KL 将上下文中的知识压进学生参数.

设部署输入为 $x$,待内化上下文为 $c$,学生轨迹为 $y$.OPCD 的局部结构为

$$
y\sim\pi_{\theta_k}(\cdot\mid x),\qquad
q_t=\pi_T(\cdot\mid c,x,y_{<t}),\qquad
p_t=\pi_\theta(\cdot\mid x,y_{<t}),
$$

并在学生状态上最小化面向 $q_t$ 的 reverse-KL 类目标.训练完成后,学生不再需要携带 $c$.这件事的价值很直接:长系统提示词会占上下文与 Prefill 成本,历史经验会不断增长;若其中稳定、可迁移的部分能进入参数,推理时便可以省掉重复输入.

## 1. 两类上下文

论文先研究**经验知识蒸馏**:从模型过去的解题轨迹中提取可迁移经验,再让条件化教师把这些经验用于新的学生前缀.这里的经验指跨题可复用的策略,并非某一道题的标准答案.另一项应用是**系统提示词蒸馏**:把经过优化的行为规范内化,使模型在没有那段长提示词时仍保持相应行为.

这两类上下文的风险不同.历史轨迹里既有规律,也有偶然成功和错误归因;系统提示词通常更干净,却可能包含必须显式更新的规则.把易变化的合规要求永久压进参数,会降低可审计性与更新速度.因此 OPCD 更适合稳定知识和稳定行为倾向,仍需外部强制的规则就不写进参数里.

## 2. 为什么要保留 on-policy 状态

固定数据上的 context distillation 会教学生复现一组预先收集的回答,但学生自由生成后的错误状态仍可能不在训练集中.OPCD 让当前学生产生轨迹,教师必须在这些真实前缀上使用上下文.若经验只对理想轨迹有用、无法修复学生的偏离,训练会直接暴露这个问题;若经验能够改变错误位置上的候选排序,它才会形成有效梯度.

这也让 OPCD 与提示词模仿不同.学生不需要逐字产生系统提示词描述的风格,而是在自己会遇到的状态上学习条件教师的动作分布.评估除了最终任务分数,还应比较移除上下文后的行为保持、未见任务迁移和错误恢复能力.

把这个区别写成概率分布会更清楚.传统 context distillation 往往先从教师或标注数据取得序列 $y\sim\mu$,再最小化 forward KL:

$$
\mathcal L_{\mathrm{off}}
=\mathbb E_{(x,c),y\sim\mu}
\left[\frac1{|y|}\sum_t
D_{\mathrm{KL}}\!\left(
\pi_T(\cdot\mid c,x,y_{<t})\,\|\,
\pi_\theta(\cdot\mid x,y_{<t})
\right)\right].
$$

这里有两层错位.第一层是状态错位:训练前缀来自 $\mu$,部署前缀来自学生自身.第二层是目标形状:forward KL 会要求学生覆盖教师分布中各个有概率的模式,学生容量不足时容易在多个模式之间摊开概率.OPCD 改成从当前学生采样完整回答,并在每个学生前缀上计算 reverse KL:

$$
\mathcal L_{\mathrm{OPCD}}(\theta)
=\mathbb E_{(x,c)\sim\mathcal D,\,y\sim\pi_\theta(\cdot\mid x)}
\left[
\frac1{|y|}\sum_{t=1}^{|y|}
D_{\mathrm{KL}}\!\left(
\pi_\theta(\cdot\mid x,y_{<t})\,\|\,
\pi_T(\cdot\mid c,x,y_{<t})
\right)
\right].
$$

对第 $t$ 个位置展开后,

$$
D_{\mathrm{KL}}(p_t\|q_t)
=\sum_{v\in\mathcal V}p_t(v)
\bigl[\log p_t(v)-\log q_t(v)\bigr].
$$

学生已经偏向、教师也认可的 token 会继续获得支持;学生概率很高而教师不认可的 token 会被压低.reverse KL 的 mode-seeking 性质使有限容量学生优先追随教师的高概率区域.它并不自动等于「更准确」:教师如果因上下文噪声把错误 token 推到高概率区,学生同样会认真吸收.因此 context 的质量与教师在学生前缀上的条件增益仍是方法成立的前提.

完整词表求和会产生很大的 logits 通信和显存开销.论文实现按学生概率取 top-$k$ token,实验使用 $k=256$,只在这组候选上近似解析 KL.选择学生 top-$k$ 很关键:reverse KL 的期望本来就在学生分布下计算,先覆盖学生当前最可能采取的动作,再询问教师怎样评价这些动作.如果改取教师 top-$k$,学生当前的高概率错误可能根本不在集合内,惩罚会被漏掉.近似同时舍弃了长尾质量,所以复现时至少记录 $k$、截断后的归一化方式和尾部是否单独聚合,不能只写「用了 KL 蒸馏」.

更新从学生 rollout 开始.学生先在不含 $c$ 的输入上生成回答;教师随后读取 $[c;x;y]$,在完全相同的回答前缀上计算目标概率;训练器逐位置形成 reverse KL,只更新学生参数.**on-policy 指轨迹由当前学生产生,不表示教师也要在线更新.** 原论文默认使用冻结教师,同权重且同步更新的 self-OPCD 只是另一种配置.

冻结教师把目标固定住,较适合分析上下文本身贡献了多少能力.同步自蒸馏中,教师和学生共享正在变化的参数,二者只靠输入里有没有 $c$ 产生差异.这种写法省去独立模型,目标却会随着每次更新移动.论文在 Sokoban 和医学任务上的对照中,冻结 teacher-student 配置分别得到 53.9 和 56.8,同步 self-OPCD 为 18.8 和 50.0.这些数值来自特定模型与任务,不能推出自蒸馏普遍无效;它们至少说明「上下文视图更强」还不够,教师时间尺度也决定训练是否稳定.

## 3. 跨尺寸蒸馏

OPSD、SDFT 与 SDPO 强调同源模型可以因额外上下文而成为教师;OPCD 进一步展示较小学生也可以吸收较大教师的上下文经验.此时增益同时来自参数规模差和上下文差,需要通过四组对照拆开:无上下文的小模型、带上下文的小模型、无上下文的大教师、带上下文的大教师.否则很难判断学生学到的是大模型原有能力,还是上下文真正带来的条件增益.

跨 tokenizer 时,逐 token 分布无法直接对齐.可以改用共享字节空间、序列级目标或让教师生成可重新分词的目标,但这些做法已经改变原始分布目标.复现实验时应先确认师生词表与 token 边界,不要只根据「跨尺寸」推断任意模型组合都能直接使用 logits 蒸馏.

### 3.1. 经验怎样从轨迹进入参数

论文先把聊天记录压缩成可迁移经验,再进入三阶段流程.第一步是**提取**:模型解决问题后,根据问题与自己的解答轨迹总结经验条目.这个阶段不使用标准答案,经验可能来自成功路径,也可能来自对失败的反思.第二步是**积累**:把不同问题中抽出的经验条目拼成上下文 $c$,用于帮助后续问题.第三步才是**固化**:以积累后的 $c$ 作为教师上下文,用 OPCD 将其压回不带上下文的学生.

三阶段把「数据从哪里来」与「参数怎样学」拆开了.经验提取器决定 $c$ 的信息密度,OPCD 决定学生如何在自己的状态上吸收 $c$.如果直接保存原始轨迹,旧问题、冗余推理和偶然错误会一起占用上下文.论文的数学实验中,使用 raw trace 作为经验上下文时验证准确率从 75.1 降到 70.5;抽取后的 knowledge 达到 77.4,再经 OPCD 固化为 79.7.这组结果支持的是「先抽象再固化」在该设置中有效,不是所有自动总结都会比原始记录可靠.

经验积累本身还有一个容易忽略的选择问题.论文从验证集问题生成经验,每轮抽取 30 条,重复 10 次形成 300 个候选上下文.一种 test-time 设置从候选池随机取上下文,模拟无法提前知道经验质量的情形;另一种 filtered 设置先在新的验证问题上给候选经验打分,再选出效果最好的上下文.后者自然引入额外评估预算,比较时要把筛选成本算进去.若只报告经过筛选的最好上下文,很容易把选择收益误记成蒸馏收益.

这条路线也给持续学习提供了一个具体接口.模型在真实任务中积累轨迹,周期性提取稳定经验,再用一批可公开或可重放的输入做 consolidation.参数更新后,原始长上下文可以退出在线推理路径.问题在于参数记忆比外部文档难修改:经验一旦过时,不能像删一条检索记录那样立刻撤回.实践中应把带版本号的经验文本、蒸馏数据和 checkpoint 一起保存,并用保留集验证旧经验是否仍然适用.

### 3.2. 系统提示词怎样被内化

系统提示词蒸馏把 $c$ 换成一段经过优化的指令.教师读取系统提示词与用户问题,学生只读取用户问题;二者在学生生成的相同前缀上给出分布.论文在医学问答和安全分类上采用 MetaSPO 优化出的提示词,蒸馏同时覆盖最终选择与解释.训练 50 步,batch size 为 128,最大生成长度为 512,reverse KL 仍使用学生 top-256 词表候选.

这类实验应把三种增益分开.**上下文增益**比较 base 与 in-context,回答提示词本身有没有用;**离线蒸馏增益**比较 in-context 与普通 context distillation,回答参数化是否超过临时提示;**on-policy 增益**比较普通 context distillation 与 OPCD,回答学生状态和 reverse KL 是否带来额外收益.以论文医学表为例,Qwen2.5-7B-Instruct 的四个数依次为 46.4、52.6、58.5 和 62.3.OPCD 相对离线基线多出的 3.8 点才是 on-policy 增量,不能把 15.9 点总提升全部归因于 on-policy.

系统提示词能否蒸馏还受输入可辨识性限制.如果教师行为只依赖一套固定规则,学生可以从训练样本中把规则压进参数.若同一个用户输入在不同租户、时间或权限下需要不同系统规则,部署输入里又没有相应标识,学生面对的是互相冲突的目标.此时应保留可部署条件变量,或者继续把动态规则放在外部上下文中.把冲突规则一起蒸馏只会得到折中分布.

### 3.3. 跨尺寸到底跨了什么

论文用 Qwen3-8B 生成经验并作为冻结教师,学生覆盖 Qwen3-8B、4B 与 1.7B.值得注意的现象是,把大模型提炼出的经验直接放进较小模型上下文,性能可能下降;让大教师读取这份经验,再用 OPCD 监督小学生则能带来提升.一种合理解释是,经验文本的抽象层次与措辞适合生成它的大模型,小模型未必能在一次前向里正确利用;教师先把经验转成学生当前前缀上的 token 分布,相当于增加了一层能力适配.

这并不解除学生容量上限.大教师的分布可能包含小模型无法同时表达的多种策略,reverse KL 会促使学生挑选高概率模式,但也可能损失覆盖度.复现实验应该同时报告任务准确率、回答多样性、校准和未见任务能力.只看平均准确率,无法判断小学生是在吸收经验,还是收缩成少数高频模板.

原论文的 tokenizer 一致,所以 top-$k$ logits 可以逐项对齐.跨模型家族时若 token 集不同,原式中的同一个 $v\in\mathcal V$ 不再存在.把教师 token 强行映射到学生 token 会引入分词歧义;改用教师采样序列做 SFT 又退回 off-policy 状态.更稳妥的研究设计是先限定共享词表模型,或者明确提出新的序列级、字节级对齐目标,并把它作为不同算法评估.

## 4. 实验结果怎样读

论文的经验蒸馏覆盖 DAPO-Math-17K、Frozen Lake 与 Sokoban.数学实验使用 Qwen3-8B;文本游戏分别使用 Qwen3-1.7B 和 Qwen3-4B-Instruct-2507.训练阶段统一做 50 步更新,batch size 为 128;数学最大回答长度达到 16384 token,文本游戏最多交互 5 轮、每轮 1024 token.这些设置说明 OPCD 的主要成本不只是反向传播,还包括学生 rollout、冻结教师的条件前向与 top-$k$ 分布保存.

在随机经验上下文设置中,Qwen3-8B 数学 base、in-context、普通 context distillation 与 OPCD 分别为 75.0、77.6、78.5 和 79.7;Frozen Lake 对应 6.3、20.2、22.9 和 26.5.筛选经验设置中,数学 OPCD 为 80.9,Frozen Lake 为 38.3,Sokoban 为 53.9,都高于论文使用的离线蒸馏基线.这些比较支持 on-policy context distillation 在论文任务上的有效性,但没有隔离 top-$k$ 近似、reverse KL 和学生状态各自贡献多少.完整复现应再加入「学生状态 + forward KL」与「教师轨迹 + reverse KL」两组交叉消融.

遗忘实验尤其值得单独看.作者在经验任务上用 IF-Eval 测分布外指令遵循,又在安全系统提示词蒸馏时用医学任务作 OOD 保留集.OPCD 相对离线 context distillation 在 Frozen Lake 设置的 IF-Eval 高约 2 点;Qwen2.5-3B-Instruct 的安全提示词实验中,OOD 医学表现高约 4 点.一种机制解释是,学生轨迹把训练集中到当前策略实际访问的区域,减少对整个输出分布的无差别改写.它仍不是遗忘保证:如果学生在新任务上频繁访问的状态与旧能力共享参数,或者上下文教师强烈改变通用行为,旧能力照样会退化.

实验里还有三处需要谨慎.其一,checkpoint 每 2 步保存,部分结果报告表现最好的 checkpoint 或前三个 checkpoint 均值,因此训练中途选择规则必须复现.其二,filtered experience 用验证表现挑上下文,会消耗额外数据与推理预算.其三,同权重 self-OPCD 明显不如冻结教师,说明在线目标漂移可能压过自蒸馏收益.如果复现只保留最好设置,就看不到方法对教师配置的敏感性.

一个比较完整的验收表应同时包含任务内表现、OOD 保留、上下文长度、学生生成 token、教师评分 token、top-$k$ logits 体积、训练墙钟和峰值显存.经验蒸馏还要记录提取与筛选开销;系统提示词蒸馏要记录移除提示词后节省的 Prefill 与 KV cache.这样才能判断一次性的固化成本需要多少线上调用才能摊平.

## 5. 与其他自蒸馏路线的关系

OPCD 与 OPSD 都把额外文本放进教师上下文.OPSD 的参考解通常针对当前样本,目的是帮助教师理解一条具体推理;OPCD 的经验与系统提示词更强调跨样本复用.SDFT 从少量专家示范获取新任务规律,OPCD 还覆盖模型自身历史轨迹与优化提示词.SDPO 的条件来自当前 rollout 的环境反馈,时间上更贴近一次失败后的回顾.

四者可以共用学生 rollout 与教师评分基础设施,却不应混成一个无来源标记的上下文框.训练记录必须标明条件来自参考解、专家示范、历史经验、系统提示词还是即时反馈.来源不同,可信度、更新频率与泄漏风险都不同.

从统一记号看,四条路线都在学生状态 $s_t=(x,y_{<t})$ 上构造条件教师 $q_t(\cdot\mid s_t,c)$.差别集中在 $c$ 的生命周期.OPSD 的参考推理通常随样本绑定;SDFT 的示范描述一个任务或技能;SDPO 的反馈由当前尝试即时产生;OPCD 的经验与系统提示词面向一批样本长期复用.生命周期越长,越需要版本管理与撤销机制;生命周期越短,越依赖在线环境吞吐.

OPCD 也不必被限制为自蒸馏.论文默认配置本来就是冻结 teacher-student,并允许更大教师向更小学生传递上下文经验.因此它与「特权教师」章节的其他方法共享数学骨架,能力来源却可能同时包含教师参数优势和上下文优势.做消融时要分别测量

$$
\Delta_{\mathrm{model}}=mathrm{Perf}(T,x)-\mathrm{Perf}(S,x),
\qquad
\Delta_{\mathrm{ctx}}=mathrm{Perf}(T,c,x)-\mathrm{Perf}(T,x).
$$

前者反映模型差距,后者反映上下文给教师带来的条件增益.如果 $\Delta_{\mathrm{ctx}}\le 0$,OPCD 没有值得压缩的上下文能力;如果 $\Delta_{\mathrm{model}}$ 很大而 $\Delta_{\mathrm{ctx}}$ 很小,训练更接近普通大模型蒸馏.只有把两项拆开,才能判断实验究竟验证了 context distillation 还是 teacher distillation.

## 6. 失败条件与复现清单

第一类失败来自**上下文不可迁移**.某条经验只记住旧题答案,换一道题就没有帮助;某个系统提示词依赖部署时不存在的工具或隐含状态.教师在训练样本上看似更强,学生吸收的却是数据泄漏.经验上下文要在与提取问题去重的新问题上先测条件增益,系统提示词则要检查规则所需变量是否出现在学生部署输入里.

第二类失败来自**教师无法修复学生状态**.上下文可能帮助教师从头生成正确答案,但学生已经走进不可逆前缀后,教师也只能继续错误路径.这时在每个 token 上算 KL 仍会产生梯度,却不一定把早期错误的信用传回去.可以按首个分歧位置统计教师优势,比较正确前缀、可恢复错误前缀与不可恢复前缀三类状态.若增益只出现在正确前缀,需要增加重采样、过程验证或更早位置的训练信号.

第三类失败来自**目标漂移与容量竞争**.同步 self-OPCD 里教师随学生一起更新,上下文视图可能越来越强,也可能共同坍缩.冻结教师更稳定,但旧教师无法利用学生后来学会的能力.EMA 教师提供中间时间尺度,仍需报告衰减率与更新频率.跨尺寸蒸馏还要观察学生是否通过模式收缩换取准确率,并用多样性和校准指标补上这一面.

第四类失败来自**把可更新规则错误地固化**.医学指南、安全策略和业务流程会变化.外部 prompt 或检索文档可以按版本替换,参数能力需要再训练才能撤销.适合固化的是长期稳定、跨样本复用、对延迟或上下文成本影响明显的知识;高频变化、必须逐条审计或要求立即撤回的规则继续留在外部控制面.

复现时,每条训练记录至少包含 context 版本与哈希、输入 $x$、无上下文学生 prompt、带上下文教师 prompt、rollout checkpoint、教师 checkpoint、采样参数、回答掩码、top-$k$ token id 与概率、截断规则、loss 和最终评测结果.经验路线还要保存原始轨迹、抽取后的经验及筛选得分;系统提示词路线要保存提示词版本.这些字段能把「经验提取错了」「模板拼错了」「教师漂了」和「KL 实现错了」分开定位.

采用 OPCD 的前提可以直接落到三项检查:上下文 $c$ 是否在学生会访问的前缀上稳定提高教师判断,学生部署输入是否包含重现目标行为所需的信息,省下的在线上下文成本能否覆盖一次性的 rollout、教师前向和训练成本.三项都成立时,OPCD 才真正完成了从临时上下文到持久参数的迁移.
