# 预算对齐与因果消融：OPD 提升究竟来自哪里

一项 OPD 工作通常同时引入学生 rollout、教师查询、新散度、轨迹缓存和训练系统优化。最终分数高于 SFT，只能说明整套方案有效，无法回答提升来自学生状态、软标签、更多生成，还是更强教师。因果消融的任务是建立一组相邻实验，每次只改变一项，使结果能回到算法声称解决的问题。

## 1. 先画出数据流

实验前先把训练分成四个节点：提示从哪里来；谁生成前缀或完整轨迹；教师、环境或参考答案提供什么信号；训练器用什么目标更新学生。系统中的缓存、筛选和重采样也要标在节点之间。只要两组实验在多个节点不同，就不能用一个总差值解释机制。

例如，SFT baseline 使用人工参考答案，OPD 方法使用学生 rollout 上的强教师完整 logits，同时多训练两倍 token。差异至少包含状态来源、标签密度、教师能力和更新预算。可在固定参考前缀上比较硬标签与教师分布，再把相同教师分布迁到学生前缀，最终在同一批学生前缀上替换散度或估计器。

数据流图还会暴露隐性信息。自蒸馏教师若看到参考解，信息来源不是“模型自己”；黑盒判别器若用更多教师候选，奖励质量提升可能来自采样数；SCOPE 类筛选若丢掉困难样本，训练分布也已改变。

### 2. 最小因果矩阵

最基础的一行是固定数据 SFT，使用参考 token。第二行保持固定前缀，换成教师软分布，测量软标签增量。第三行使用学生前缀，但仍给单一教师续写或硬标签，测量状态来源变化。第四行在同样学生前缀上用教师分布，得到典型局部 OPD。

第五行保留学生 rollout，只使用任务结果奖励，比较教师分布与环境回报。第六行组合 OPD 与 RL，检验二者是否互补。若方法还包含序列目标、reference 外推、轨迹加权或反馈条件，应在第四行基础上逐个加入。

## 3. 等 token 不是唯一公平

训练方法消耗至少四类资源：学生生成 token、教师前向或 API token、learner 更新 token，以及验证器或奖励模型计算。等更新 token 衡量优化样本效率，却可能让 OPD 免费使用昂贵教师；等教师调用衡量知识获取效率，却可能允许某组多做 learner step。

实际报告可采用一个主口径和两个补充口径。主口径根据应用约束选择，例如教师 API 是瓶颈时按教师输入输出 token 对齐；自有模型集群则可按总 FLOPs 或墙钟时间。补充报告单位更新 token 与单位生成 token 的收益，使读者能换算到自己的环境。

请求次数不是可靠成本。一次返回完整长 CoT 的黑盒调用与一次只取 top-$k$ log-prob 的请求完全不同；完整词表 logits 的传输和存储也不能忽略。至少记录输入长度、输出长度、教师模型和返回字段。

### 4. 生成预算怎样影响数据质量

学生每题采样一个回答与采样十六个回答，得到的状态覆盖和成功轨迹比例不同。self-play 方法尤其容易把候选数优势写成训练算法优势。应在固定候选数下比较目标，并额外绘制性能随候选数增长的曲线。

温度与 top-$p$ 也改变状态分布。高温 rollout 覆盖更多错误和新策略，却偏离部署分布；低温更接近 pass@1，困难状态可能不足。若 OPD 用高温采样、baseline 用贪心生成，状态增量不能单独归因于教师监督。

筛选同样消耗预算。生成大量候选后只训练成功或高分样本，名义训练集大小很小，背后搜索成本很大。报告应同时给出生成总量、保留率和最终更新量。

### 5. 教师强度要独立变化

使用更强教师常能提高任何蒸馏方法。要证明 on-policy 状态的价值，至少在同一教师下比较固定与学生前缀。进一步可选择两个教师强度，观察学生状态收益是否随教师恢复能力变化。

教师总体 benchmark 与错误状态能力不是同一个量。一个模型在标准题上很强，面对学生自相矛盾的前缀可能继续错误；另一个教师总体略弱，却更善于诊断和恢复。实验应直接测学生前缀 continuation，而不只用教师公开分数代表优势。

自蒸馏中，教师优势来自参考解、反馈或长上下文。消融要保持参数模型相同，只移除特权信息；否则无法区分条件信息与模型尺寸。若使用 EMA 教师，还要单独控制教师更新速度。

### 6. 解码设置必须锁定

训练后评测的温度、候选数、最大长度、停止条件、工具次数和答案提取都会影响结果。主比较必须使用相同解码。方法需要特殊解码才能发挥时，可以另列结果，并明确增加的推理成本。

pass@1 反映单次策略质量，pass@k 同时受多样性和搜索预算影响。OPD 可能使分布更集中，提高 pass@1 却降低多样性；RL 也可能提高候选覆盖。两项同时报告才能看到真实变化。

长度尤其值得单列。更长回答可能改善难题，也可能只增加命中答案格式的机会。应报告平均、分位长度、截断率和单位 token 正确率，并在相近长度子集上复核。

### 7. 超参数选择会制造隐性优势

新方法通常得到更多调参关注，baseline 沿用论文默认值。公平实验应给主要 baseline 相近的搜索预算，至少重新校准学习率、batch、KL 系数和训练步数。若资源不足，公开搜索范围和选择规则。

用测试集反复选择方法版本会产生选择偏差。开发集负责调参，测试集只用于最终确认；多 benchmark 同时挑最佳配置时，也要说明聚合标准。只汇报每个任务各自最优 checkpoint，会夸大可迁移性。

随机种子不能只用于最终最好配置。训练和数据采样都有方差，至少在代表性规模上重复关键组。若计算昂贵，可以用配对 bootstrap 或逐题分析提高统计效率，但不能用单次运行的小差异下强结论。

## 8. 配对统计比总分更有信息

同一组题上比较 baseline 与方法，可将样本分成共同正确、共同错误、只被方法修好、只被方法弄坏四类。净提升来自后两类差值，配对检验能利用题目相关性，比把两个总体比例当独立样本更准确。

进一步按长度、难度、错误类型和教师优势分桶。如果 OPD 的解释是纠正学生状态，它应更多修复首次错误较晚、教师可恢复的样本；若提升只来自简单题或格式，机制解释受到挑战。

置信区间也应与选择过程匹配。尝试几十个配置后只对最佳配置计算一次区间，没有覆盖模型选择不确定性。至少把配置选择与最终复现分开，或在独立种子上确认。

### 9. 污染与教师记忆

学生训练数据未包含评测题，不代表蒸馏安全。教师可能记住题目，参考解生成器可能访问测试答案，self-play 缓存也可能混入评测。应追踪教师、数据源和提示模板，使用时间切分、新生成题或污染较低的私有集合复核。

教师能直接复述标准答案时，OPD 在学生前缀上的高分可能只是把记忆传给学生。对题目数值、实体或表述做保持结构的变换，观察能力是否迁移。只在原题提升而变体不升，是记忆风险信号。

污染风险取决于去重粒度、参考解来源和教师可见信息。无法确认的范围会限制结论；“没有发现重复”只能表示当前检测未命中，无法证明污染必然不存在。

## 10. 系统优化怎样与算法隔离

新的 rollout 引擎、动态 batching、序列打包和缓存能显著提高吞吐，使方法在同样墙钟时间内看到更多数据。它们很有价值，但属于系统增益。算法对比应固定生成与更新量，系统对比则固定时间，分别报告。

异步系统还会改变轨迹新鲜度。一个实现吞吐更高，却让 learner 与 rollout policy 相差更多版本，算法目标也随之变化。报告 tokens/s 之外，应记录版本延迟、策略 KL 和缓存年龄。

混合精度、top-$k$ 压缩与 tokenizer 路由也可能改变教师信号。对吞吐优化做数值对照，测量近似目标与精确目标的误差，才能证明速度不是靠悄悄换目标得到。

### 11. 机制指标怎样进入消融

每个组件都应对应一个中间指标。学生 rollout 对应状态覆盖与首次错误位置；教师分布对应学生状态上的 continuation 优势；序列目标对应早期动作梯度和长程成功；轨迹加权对应有效样本量；reference 外推对应 log-ratio 尾部与策略距离。

组件加入后最终分数上升，而对应机制指标不动，说明解释可能错误。机制指标改善而最终分数不动，则表明下游还有瓶颈。两种结果都比只看总分更能指导下一步。

指标要预先定义，避免结果出来后挑选最有利的解释。对于探索性工作，可以清楚区分预设假设与事后观察，并在新任务或新种子上确认后者。

### 12. 失败模式对应哪些对照

若怀疑收益只是更多教师信息，加入等教师 token 的离线蒸馏；怀疑只是更多学生采样，加入相同 rollout 但不查询教师的 RL 或自训练；怀疑只是答案更长，做长度匹配；怀疑是筛选器挑掉难题，报告全量数据上的分桶结果。

若方法在一个实现上有效，换训练框架后消失，应检查目标归一化、stop-gradient、轨迹版本和 tokenizer 对齐。复现差异未必是“工程细节”，它可能暴露论文公式省略的算法假设。

负结果也要保留。某个散度在小模型有效、大模型无效，可能因为师生差距与支持重叠改变；轨迹复用在短任务安全、长推理退化，说明状态陈旧是关键。这样的边界比平均领先几个点更可迁移。

## 13. 一个可执行的实验顺序

先用小规模模型跑四组：固定硬标签、固定软分布、学生状态硬监督、学生状态软分布。确认状态与软标签各自贡献。然后在最有效组上比较 forward、reverse 或目标近似，保持数据完全一致。

第二阶段加入任务奖励，比较纯 OPD、纯 RL 和组合，并记录教师优势与优势冲突。第三阶段才测试轨迹复用、top-$k$ 压缩和异步系统，绘制性能—成本曲线。这样系统优化不会掩盖算法机制。

主规模实验用于复现关键组，并采用冻结的评测配置和独立种子。若资源只允许少量大实验，预算应集中到最能推翻结论的对照，弱 baseline 无法增加多少证据。

### 14. 表格应该让读者直接计算

主结果表除任务分数外，可列训练更新 token、学生生成 token、教师 token、候选数和推理预算。复杂系统不必把所有硬件细节塞进一张表，但至少让读者知道性能差值对应多少额外资源。

消融表按变量排列，而不是按内部版本号。列出状态来源、教师接口、目标、轨迹年龄、筛选和预算；读者一眼能看出相邻行只差什么。若两行同时差多个变量，就不要用箭头宣称单一组件贡献。

误差条、配对变化和成本曲线可以放附图。最重要的是结果与叙事对应：论文声称解决状态偏移，就展示状态相关收益；声称提高样本效率，就在相同教师或生成预算下比较。

### 15. 最终因果链

OPD 的完整论证应是：固定数据无法覆盖学生部署状态；学生确实访问了不同且重要的前缀；教师在这些前缀上提供更好判断；所选接口和目标把判断传入梯度；相同资源下，状态对齐带来额外收益；收益在独立评测和一致解码中保留。

预算对齐不是为了把所有方法塞进一个绝对公平的数字。不同方法本来就交换不同资源。它的作用是把交换关系公开，使结论带有条件：教师调用稀缺时哪条路线更好，生成便宜时哪条路线更好，长任务里轨迹新鲜度值多少钱。

因果消融也不是机械关闭模块。每个对照都应针对一个可能的替代解释。只要读者能够从实验回答“若不改变学生状态会怎样”“若不给软分布会怎样”“若计算预算相同会怎样”，方法的主要贡献就获得了可检验的边界。

## 16. 教师调用的边际价值

固定教师 token 后，可以比较少量状态返回完整分布，或更多状态只返回 top-$k、采样 token 或文字评分。前者单点信息丰富，后者覆盖更广。最优选择取决于错误状态多样性与教师分布熵，不能从接口成本单独决定。

逐步增加教师预算，绘制任务收益与被覆盖关键分叉的比例。少量查询若已覆盖主要错误，继续增加完整 logits 会饱和；错误状态分散时，扩大覆盖更重要。主动查询还要计入筛选器成本，大模型筛选可能比直接问教师更贵。

### 17. 轨迹新鲜度的因果实验

固定提示和教师接口，只改变 rollout 与 learner 的版本差：当前策略、滞后一轮、滞后多轮。每组保持更新 token 与轨迹量一致，测量策略 KL、importance ratio 尾部、状态覆盖和最终收益。

再让旧状态重新查询当前教师，可区分状态陈旧与教师输出陈旧。若重新查询仍无法恢复，问题主要在状态分布；若明显改善，缓存教师概率是瓶颈。轨迹年龄最好用行为策略与当前策略的 KL 表示，而非只数训练步。

### 18. 目标近似的误差预算

top-$k$、低精度 log-prob、sampled-token 与截断序列都在近似理想目标。小模型上可计算精确梯度，测量近似的偏差、方差和方向余弦；大模型再观察这些指标是否预测最终退化。

近似误差与计算收益应放在同一曲线上。例如 top-$k$ 从 32 增至 128，带宽增加多少、教师质量保留多少、任务分数变化多少。多个近似同时使用时先逐项验证，避免小误差集中在同一困难状态。

### 19. 不同任务长度的外推

在训练长度内有效，不代表更长任务仍有效。状态偏移、奖励延迟和轨迹陈旧都会随长度增长。可按推理步数或环境轮数分桶，并在超出训练长度的任务上测试。

若 OPD 主要修复局部错误，收益可能随长度先增加；教师无法恢复深层错误后又下降。序列目标可能在中长轨迹更占优，同时方差增长。长度分桶还要控制题目难度，不能把简单但啰嗦的回答当成长程任务。

## 20. 从实验回到决策

最终报告应给出选择边界：教师查询贵时采用哪种接口，学生很弱时先冷启动还是在线纠错，长轨迹下复用窗口怎样收紧，验证器可靠时何时转向 RL。规则必须由消融与成本曲线支撑。

实验不足以给出普遍规则时，就把结论限制在已验证模型、任务和预算。因果消融的价值是把配方还原为变量关系，使外部条件变化后仍能重新判断，而不是照抄原配置。

### 21. 结果表中的不确定性

平均分旁边应给出适合指标的区间。逐题正确率可用配对 bootstrap，连续奖励可按题目重采样；多次训练种子则反映优化与数据生成波动。只对样本重采样不能覆盖训练随机性，两类不确定性最好分开。

当差值小于种子波动时，不应仅凭最好一次运行下结论。可以增加种子，也可以把重点转向稳定的成本或机制改善。统计不显著不等于方法无效，但意味着当前证据不足以支持强排序。

多项 benchmark 同时比较会增加偶然领先机会。无需机械套用复杂校正，至少完整报告所有预先选择的任务，避免只留下显著结果，并在独立任务上复核主要结论。

### 22. 资源无法完全对齐时怎样陈述

某些接口天然需要不同资源，强行等 FLOPs 可能让其中一组无法正常训练。此时可给出多种约束下的 Pareto 前沿：教师调用、训练时间、显存和最终性能。方法位于前沿，说明在某种资源偏好下值得选择；不存在脱离约束的绝对冠军。

硬件利用率与算法样本效率也要分开。一种实现每 token 学得更多，却因教师通信而吞吐低；另一种目标较粗，但系统效率高。两者都是真实结论，只需避免把系统领先归因于数学目标。

最终陈述应带条件，例如教师调用受限但生成充足，或完整 logits 可本地获得。清楚写出条件，读者才能将结果迁移到自己的训练环境。

资源报告还应使用同一计量边界：是否计入教师预计算、缓存构建、失败请求和评测搜索必须一致。只给在线训练时间而把昂贵预处理移到表外，会制造虚假的效率优势。把一次性成本和随样本增长的成本分列，才能判断规模扩大后的真实选择。
