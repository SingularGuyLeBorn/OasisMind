# 与 Attention、SSM、RWKV 的边界

全注意力、滑动窗口、状态空间模型、RWKV 与 TTT 家族都在回答“如何让历史影响当前输出”，但历史载体与成本不同。选型应拆成状态、训练并行、prefill、decode、显存和任务质量，而不是只看渐近复杂度。

## 概念对比

| 路线 | 历史载体 | 主要性质 | 主要边界 |
| --- | --- | --- | --- |
| 全注意力 | token 的 K/V 表示 | 当前 token 可直接寻址历史位置 | 训练与长序列 prefill 成本高；KV cache 随上下文增长 |
| 滑动窗口注意力 | 固定窗口 K/V | 成本受窗口限制，实现成熟 | 窗口外信息需其他记忆通道 |
| Mamba / SSM | 固定维度递推状态 | 序列长度方向线性，递推 decode | 历史被压入固定状态，质量依任务和训练而定 |
| RWKV | 时间混合形成的递推状态 | 可并行训练并以 RNN 形式推理 | 同样依赖固定状态压缩与专门实现 |
| TTT Layers / LaCT | 可学习小模型的参数状态 | 状态更新规则可表达、序列递推 | 测试时优化、内存 I/O 与稳定性成本 |
| TTT-E2E | 滑窗注意力 + 更新后的权重 | 用下一词学习保存窗口外信息 | 元学习和测试时权重更新增加系统复杂度 |

表中的性质是机制概括，不是质量排序。同一架构族内部的模型规模、数据、kernel、量化和硬件差异可能大于架构标签本身。

## 三个容易混淆的命题

### 线性时间不等于固定低延迟

序列长度方向线性只描述增长阶。状态大小、更新频率、矩阵形状和 kernel 利用率决定常数；LaCT 的出发点正是早期 TTT 虽具线性结构，却因小批更新造成很低的硬件利用率。

### 固定状态不等于一定遗忘关键事实

SSM 和 RWKV 会压缩历史，但选择性更新和训练目标可让模型保留任务所需信息。应在目标任务上测可检索性和语言建模质量，而不是把状态维度直接换算成“可记 token 数”。

### 参数状态不等于永久知识

TTT 的 fast weights 通常服务当前序列。若把状态跨序列或跨用户保留，就从长上下文机制扩展成部署期持续学习系统，需要额外的隐私、污染、回滚和遗忘评测。

## 选型实验

在相同参数量、训练 token 和硬件上，至少比较：

1. 短、中、长上下文的任务质量曲线。
2. prefill 吞吐和首 token 延迟。
3. decode 吞吐、单 token 延迟与并发能力。
4. 权重、激活、KV cache 或递推状态的峰值显存。
5. 状态重置、跨文档串扰和顺序敏感性。
6. kernel、量化、分布式部署与故障恢复的成熟度。
