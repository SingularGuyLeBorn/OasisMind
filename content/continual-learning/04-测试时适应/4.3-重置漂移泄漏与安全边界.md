# 4.3 重置、漂移、泄漏与安全边界

测试时适应让部署输入参与模型更新，因此评价和生产系统都多了一条状态通道。若不定义状态生命周期，同一模型会因请求顺序不同产生不同输出，甚至被恶意输入长期污染。

## 重置策略

| 策略 | 优点 | 代价与风险 |
| --- | --- | --- |
| 每样本 / 每批次重置 | 状态隔离强，容易复现 | 不能积累跨样本信息 |
| 每已知域重置 | 兼顾域内积累 | 需要可靠域边界，可能使用额外先验 |
| 周期或触发式重置 | 可控制长期漂移 | 需要漂移检测与阈值 |
| 永不重置 | 能持续跟踪变化 | 顺序依赖、误差累积与攻击面最大 |

论文和系统日志都应记录基准模型、当前适应版本、最近重置点与所有可变状态。

## 常见泄漏

- **测试标签泄漏**：用标签调适应步数、学习率或重置阈值。
- **未来样本泄漏**：先看完整目标集、打乱或汇总统计，再声称在线评价。
- **域边界泄漏**：用真实域 ID 决定何时重置，却把结果描述为无边界适应。
- **重复评价泄漏**：同一测试样本既参与更新又反复用于选择超参数。
- **跨用户状态泄漏**：一个用户的输入改变其他用户随后接收的模型。

## 漂移与失败检测

不要只监控适应损失，因为低熵可以对应自信错误。可组合监控：预测分布变化、增强一致性、源域哨兵集、参数距源模型的距离、异常梯度范数和回滚后的对照性能。

当无法取得目标标签时，失败检测本身仍可能不可靠。因此高风险系统应限制可更新参数与步长，并保留不可变源模型和可审计回滚点。

## 安全部署清单

1. 明确哪些请求允许参与适应，敏感或可疑输入默认隔离。
2. 设定参数更新、梯度和状态保留上限。
3. 保留源模型与已验证检查点，支持快速回滚。
4. 把用户、租户或场景状态隔离，避免交叉污染。
5. 对输入投毒、类别失衡、突然域切换和长时间无关流做压力测试。
6. 记录适应前后输出与版本，满足审计和问题定位。
7. 高风险决策不以无监督适应后的置信度作为唯一依据。

## 与持续学习评测的连接

持续不重置的 TTA 应像数据流学习一样报告顺序效应、源域遗忘和恢复时间，不能只报告目标域最终均值。可复用 [3.1 评测协议、指标与任务顺序](../03-评测与实践/3.1-评测协议指标与任务顺序.md) 的性能矩阵与资源账本。
