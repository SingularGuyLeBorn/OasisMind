# 方法体系

**三大经典方法族对应三种不同的「不忘」策略**: 正则化靠惩罚重要参数的偏移,回放靠重新引入旧分布,参数隔离靠给不同任务分配不同的参数子集. 2024 年后 LLM 的 PEFT 持续适配正在成为第四极.

持续学习方法的差别,本质上是用什么资源保留旧知识,又允许哪些部分适应新数据. 这三族方法不是互斥竞赛——实际系统几乎都在做组合. 比如 DER++ 同时回放旧 logits(回放)并用 KD 损失做函数正则化;LoRA-CL 用独立适配器隔离任务再加少量数据回放.

## 方法地图

| 路线 | 保留旧知识的载体 | 主要优势 | 主要代价 |
| --- | --- | --- | --- |
| [正则化](./2.1-正则化方法/2.1-正则化方法.md) | 参数重要性、旧模型输出 | 不一定保存原始样本 | 任务差异大时可能限制可塑性 |
| [回放](./2.2-回放与外部记忆/2.2-回放与外部记忆.md) | 旧样本、特征或生成样本 | 通常是强而通用的基线 | 内存、隐私与采样偏差 |
| [参数隔离](./2.3-参数隔离与动态架构.md) | 掩码、模块或扩展参数 | 减少跨任务参数干扰 | 可能需要任务标识或增长容量 |
| [基础模型持续适配](./2.4-大模型持续预训练与参数高效适配.md) | 预训练表征、适配器、提示、回放 | 可利用强先验并控制可训练参数 | 仍会遗忘;评测与资源账本更复杂 |

在 Class-IL 这个最严格的协议下,纯正则化方法(如 EWC)通常远不如简单的 ER. **同一方法在不同协议下表现差异可以大到完全颠覆排名**,这也是为什么下面先讲「选择方法前先固定协议」.

## 选择方法前先固定协议

1. 测试时是否提供任务标识?
2. 是否允许保存原始样本;若不允许,能否保存特征或合成数据?
3. 模型容量能否增长?
4. 数据是小任务序列,还是无边界在线流?
5. 目标是保住分类精度,还是保持生成能力、指令遵循和事实更新?

同一方法在 Task-IL、Domain-IL 与 Class-IL 中可能表现截然不同. 所有横向比较应同时报告场景、内存、参数增量、训练轮数和任务顺序.

## 组合范式

**回放 + 蒸馏** 是目前 Class-IL 上表现最稳的组合. 旧样本或旧 logits 同时约束表示和决策边界,DER++ 就是这个思路的代表.

**回放 + 参数高效适配** 在 LLM 场景下越来越常见. 固定主干,用 LoRA/Adapter 吸收任务差异,通过少量 replay token 控制遗忘.

**参数隔离 + 共享表征** 让任务专属容量处理冲突,共享容量促进迁移. HAT、SupSup 和 Prompt Pool 都是这条路.

**正则化 + 动态架构** 让重要参数受保护,容量不足时再扩展. Progressive Memory Bank 和 DEN 属此类.

组合越复杂,越需要做消融: 分别计算每个组件的性能收益、内存和计算代价.
