# 大模型持续预训练与参数高效适配

基础模型没有消除持续学习问题，只是改变了知识载体、训练成本和评价对象。**这是 2024–2026 年最活跃的子方向**：从 continual pretraining 的数据工程，到 LoRA 系的参数高效持续适配，再到 model merging 作为 CL 的替代路径，新工作密度极高。

## 持续预训练（CPT）

模型按时间或领域顺序继续进行语言建模训练。简单把新语料接在旧语料后面，仍可能导致旧领域性能下降——这和小模型上的灾难性遗忘是同一个问题，只是规模不同。

### CPT 的典型做法

**数据混合（Data Mixing）**：训练新领域时混入一定比例的旧域数据。经验上 5–10% 的旧域 replay 就能显著缓解遗忘，但比例太高会稀释新领域的学习效率。Llama 2 → CodeLlama 的持续预训练就采用了代码为主、通用文本为辅的混合策略。

**学习率调度**：CPT 不能直接沿用预训练的余弦衰减。典型做法是 **warmup → decay → re-warmup**：先用较小学习率 warmup 到新阶段的峰值（通常是原预训练峰值的 1/5–1/10），再衰减。如果有多个 CPT 阶段，每个阶段重新 re-warmup. Gupta et al.(2023)的实验表明，re-warmup 比直接接续训练能多保留约 **2–5 个百分点**的旧域困惑度。

**课程与顺序**：领域顺序也有影响。相关性高的领域连续训练通常比跳跃式顺序效果好。但在实际部署中，数据到达顺序往往不可控，所以 replay 混合仍是最可靠的兜底。

## PEFT-CL：参数高效持续适配

适配器、LoRA、提示（Prompt）或任务模块能降低每阶段可训练参数与部署成本。它们天然减少了主干参数干扰，但会引入模块路由、累计存储和合并冲突。

### LoRA-CL

最直接的做法：每个任务训一个 LoRA 适配器，推理时按任务标识切换。问题是这退化成了参数隔离——任务数多了之后，存储和路由都是开销，而且跨任务迁移有限。

### O-LoRA(Orthogonal LoRA)

Wang et al.(2023)提出：**让不同任务的 LoRA 子空间正交**。新任务的 LoRA 矩阵被约束到与旧任务 LoRA 矩阵正交的子空间里，使得新任务的更新不会干扰旧任务学到的方向：

$$
\mathcal{L}_{O\text{-}LoRA} = \mathcal{L}_{task} + \beta\sum_{k<t}\|B_t^\top B_k\|_F^2
$$

其中 Bₜ 是当前任务的 LoRA 投影矩阵，Bₖ 是旧任务的。正交惩罚让新旧子空间尽可能不重叠。实验上 O-LoRA 在 15 任务序列上比 naive LoRA-CL 减少了约 **30–40%** 的遗忘。

### InfLoRA

Liang & Li(2024)从无限宽极限（Neural Tangent Kernel）的视角分析 LoRA 持续学习：在无限宽网络下，LoRA 的低秩更新可以被理解为在一个固定核空间里的投影。InfLoRA 利用这个理论指导适配器的初始化和正则化，使得每个新任务的 LoRA 不需要显式存储旧 LoRA 矩阵就能避免干扰。

### 只报告「可训练参数占比」不够

PEFT-CL 的一个常见陷阱：每阶段只训 0.1% 参数，但 20 个任务后累计了 20 份适配器、20 份路由器。**总参数量和存储成本必须一起报告。**

## 指令持续学习（Instruction Tuning CL）

任务或指令集合逐步扩展。Continual-T0(Scialom et al., 2022)的研究表明，经过多任务微调的语言模型可以表现出一定的持续学习能力——但「预训练带来更强先验」不意味着遗忘自然消失。

**关键发现**：指令微调后的 LLM 在学新指令时，对旧指令的遵循能力也会退化。这不是分类精度下降，而是更微妙的行为漂移——回答变得更短、格式变差、安全对齐被冲淡。传统 CL 指标（平均准确率、遗忘率）无法完全捕捉这种退化。

协议仍需说明任务顺序、旧数据访问和测试任务范围。在指令域，「任务边界」本身就是模糊的——「翻译」和「摘要」算两个任务还是一个？

## 模型合并（Model Merging）作为 CL 的替代路径

Model Merging 提供了一条完全不同的思路：**不按序列顺序训练，而是各自独立微调后合并参数**。

### Task Arithmetic

Ilharco et al.(2023)提出：每个任务微调得到 θₜ，计算任务向量 τₜ = θₜ − θ_pre（微调后参数减去预训练参数）。合并时直接加权求和：

$$
\theta_{merged} = \theta_{pre} + \lambda\sum_t \tau_t
$$

简单但有效——在多个 vision 和 NLP 任务上，合并后的模型无需看过任何旧任务数据，就能在所有任务上保持不错的性能。

### TIES-Merging 与 DARE

**TIES**(Yadav et al., 2023)在合并前做三步清洗：裁剪小幅值变化（Trim）→ 解决符号冲突（Elect Sign）→ 合并（Merge）。这能显著减少任务向量之间的干扰。

**DARE**(Yu et al., 2024)更激进：随机丢弃大部分微调增量（保留率 p ≈ 0.1–0.3），然后 rescale 保留的部分。对 7B 及以上的 LLM，DARE + TIES 的组合效果最好。

### Model Merging vs 传统 CL

| 维度 | 传统 CL | Model Merging |
| --- | --- | --- |
| 训练方式 | 按序列逐任务训练 | 各任务独立并行微调 |
| 需要旧数据？ | 视方法而定 | 不需要，各自训各自的 |
| 扩展性 | 受限于序列长度和遗忘 | 受限于合并后的干扰 |
| 任务顺序敏感？ | 是，顺序影响大 | 否，因为独立训练 |
| 局限 | 遗忘和可塑性权衡 | 任务冲突大时合并质量下降 |

Model Merging 的前提是各任务可以独立训练——在流式到达、不能回看的真实 CL 场景下，这个前提不成立。但在「模型工厂」场景（比如给不同客户微调后统一部署）里，它比传统 CL 更实用。

## 与经典方法的连接

- **回放**：混入旧域文本、指令样本或旧模型生成数据。CPT 中 5–10% 的旧域 replay 是标配。
- **函数正则化**：约束旧提示或探针集上的 logits、表征或生成行为。
- **参数隔离**：为领域或任务分配适配器、提示或稀疏子网络。O-LoRA 和 InfLoRA 本质上是把正则化和隔离结合。
- **扩展式方法**：按知识块增加可训练模块，再通过路由选择。

ELLE(Qin et al., 2022)通过功能保留的模型扩展与预训练数据重放研究语言模型的持续预训练；LAMOL(Sun et al., 2019)使用语言模型生成旧任务伪样本，属于生成式回放思路。这些方法解决的设置不同，不能在缺少统一协议时直接排名。

## 基础模型评测应增加什么

1. **保留面**：旧领域困惑度、下游任务、生成质量、安全和校准是否同时保留。
2. **知识时间**：新事实加入后，旧事实是过时、冲突还是仍应共存。
3. **提示敏感性**：结果是否只对特定提示模板成立。
4. **容量账本**：主干、适配器、路由器、回放数据和优化器状态的总成本。
5. **污染控制**：训练语料与评测集是否重叠，生成式回放是否复制评测文本。
6. **更新可逆性**：错误数据进入后能否定位、撤销或隔离。

## 安全施工基线

第一批实验可从「顺序微调、同预算回放、正则化、独立适配器」四组开始。固定任务顺序、token 数、参数增量与回放字节数，再观察旧任务、新任务和通用能力的联合变化。避免一开始就用复杂组合掩盖协议问题。
