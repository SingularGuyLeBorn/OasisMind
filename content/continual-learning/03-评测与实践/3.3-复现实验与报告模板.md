# 3.3 复现实验与报告模板

下面的模板用于防止“方法名称相同、实际协议不同”。先填协议，再运行实验；不要在看到结果后才选择任务顺序、指标或基线。

## A. 问题定义

| 字段 | 填写内容 |
| --- | --- |
| 场景 | Task-IL / Domain-IL / Class-IL / 在线流 / 自定义 |
| 数据到达 | 任务式或无边界；每经验样本数 |
| 监督 | 标签是否可用、何时可用 |
| 任务信息 | 训练与测试时是否给任务标识 |
| 状态 | 跨经验保留哪些参数、优化器、统计量和记忆 |
| 目标 | 最终性能、遗忘、迁移、适应延迟或其他 |

- 数据集、版本、许可与下载地址：
- 划分脚本或配置：
- 类别 / 域 / 时间划分：
- 任务顺序与种子：
- 预训练权重及训练数据说明：
- 训练、验证、测试之间的去重或污染检查：

## C. 资源预算

| 资源 | 预算 | 实际使用 | 计量方式 |
| --- | ---: | ---: | --- |
| 原始回放数据 |  |  | 字节与样本数 |
| 特征、logits、原型 |  |  | 字节 |
| 新增参数与掩码 |  |  | 参数量与字节 |
| 每经验训练量 |  |  | 样本 / token / step |
| 总计算 |  |  | GPU 小时或 FLOPs |
| 峰值显存 |  |  | GiB |
| 适应延迟 |  |  | ms / sample 或 s / batch |

## D. 基线与消融

至少包含：

1. 顺序微调，不做遗忘缓解。
2. 联合训练上界；仅在允许访问全部历史数据的离线参考中使用。
3. 同预算 Experience Replay。
4. 所提方法去除每个关键组件后的消融。
5. 参数量、内存或计算匹配的替代方法。

## 验收规则

若协议、任务标识或内存预算缺失，结果只能作为内部探索，不能进入跨方法结论。若只复现了单个顺序，应明确标记“单顺序结果”，不要宣称方法整体优于另一方法。
