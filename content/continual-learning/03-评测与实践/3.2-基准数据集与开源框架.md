# 3.2 基准数据集与开源框架

数据集名称不等于持续学习协议。相同 MNIST、CIFAR 或 ImageNet 数据可被切成不同任务流，并配置不同的任务标识、输出头、训练轮数和回放预算。

## 常见基准族

### 合成任务序列

- **Split MNIST / Split CIFAR**：按类别拆成多个经验，常用于 Class-IL 或 Task-IL。必须说明每个经验的类别、输出头和任务标识。
- **Permuted MNIST**：对输入像素使用任务特定置换，常形成域或任务增量设置。它适合验证方法机制，但与真实非平稳环境有明显距离。

### 真实连续观测

- **CORe50**：50 个物体在多个采集 session 中被连续观测。官方页面区分 11 个 session，其中 8 个用于训练、3 个用于测试，并提供多种持续学习设置。
- **CLEAR**：以时间变化构造更接近自然演化的数据流，适合研究跨时间迁移和分布变化。使用时应链接具体版本及其拆分。

### 大规模类别增量

CIFAR-100 与 ImageNet 子集常按类别分批。论文间经常在初始任务大小、每批新增类别数、类别顺序和是否使用预训练上不同，因此只写“CIFAR-100”不足以复现。

## 开源框架

### Avalanche

[Avalanche](https://avalanche.continualai.org/) 提供场景、策略、指标和基准构造接口，适合建立统一实验流水线。应锁定版本并保存完整配置，不把框架的默认设置当成论文原始设置。

### Mammoth

[Mammoth](https://github.com/aimagelab/mammoth) 汇集多种持续学习方法与数据集实现，适合复现与同框架比较。引用具体结果时还应核对相应论文、配置和仓库提交。

### Continuum

[Continuum](https://github.com/Continvvm/continuum) 侧重把数据集转换为不同持续学习场景。它解决数据流构造，不自动保证训练预算或评价公平。

## 使用基准的检查表

- 数据版本、下载来源与许可。
- 类别或域的划分、任务顺序和随机种子。
- 任务边界、任务标识与输出头设置。
- 每个经验的训练轮数、数据增强和验证策略。
- 预训练权重及其数据来源，避免潜在评测污染。
- 回放缓冲区、额外参数和计算预算。
- 框架版本、配置文件和代码提交哈希。
