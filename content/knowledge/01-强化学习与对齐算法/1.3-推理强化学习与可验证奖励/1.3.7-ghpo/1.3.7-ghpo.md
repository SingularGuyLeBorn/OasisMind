# GHPO:基于难度检测与自适应提示的混合策略优化

GHPO 的论文标题是 **GHPO: Adaptive Guidance for Stable and Efficient LLM Reinforcement Learning**,方法全称为 Guided Hybrid Policy Optimization.它不是简单地把一个 SFT loss 与 PPO loss 固定加权,而是针对 RLVR 的"能力—难度不匹配"设计动态课程:能被当前策略探索到正确答案的问题继续在线 RL;一组 rollout 全部失败的问题逐步加入真实解题提示,把分布推向可学习区域.

## 1. 为什么困难样本没有有效梯度

对 prompt $q$ 采样 $G$ 个回答,令可验证奖励为 $r_1,\ldots,r_G$.如果:

$$
r_1=\cdots=r_G=0,
$$

组内相对优势也通常全为零,当前 batch 对这一问题不给策略方向.简单丢弃它会浪费数据;直接提供完整答案又可能让任务过易,弱化探索.

GHPO 把"全部 rollout 奖励为零"作为当前策略下的困难信号.它是一个操作性判据,不等同于题目具有客观固定难度:更换模型,采样温度,rollout 数或奖励器后,判定可能变化.

![GHPO 通过同一 prompt 的 group reward 动态检测当前策略难度](./images/redrawn-ghpo-difficulty-routing.png)

> 图 1: 当前/old policy 对同一 prompt $q$ 采样 $G$ 条 rollout,verifier 给出 binary reward.若 $S(q)=\sum_i r_i>0$,保留原始 prompt 做 on-policy group-relative RL;若 $S(q)=0$,组内 advantage 全零,该 prompt 被路由到 ground-truth hint refinement,而不是直接丢弃.

**图 1 解析**

- reward 只在同一 prompt 的 rollout group 内判断,不跨 prompt 汇总.
- “困难”依赖当前 policy,采样温度,$G$ 和 verifier,训练过程中需要重新判定.
- verifier 的错误奖励,答案抽取或执行误判会直接污染路由结果,因此必须单独监控.

## 2. 两个核心模块

### 2.1 自动难度检测

在每轮训练中:

- 如果组内存在成功 rollout,保留原问题并做 on-policy RL;
- 如果组内全部失败,将该问题送入提示精炼流程;
- 判定依赖奖励正确性,因此答案提取器,代码执行器或数学验证器的错误会直接污染课程.

### 2.2 多阶段自适应提示精炼

对困难问题,GHPO 从真实解题轨迹中截取一定比例的前缀作为 hint,附加到 prompt.论文先从较小提示比例开始;若模型仍无法成功,再在后续阶段增加提示长度.

可以抽象为:

```text
原问题
  → G 次采样
  → 至少一次成功:原问题上 RL
  → 全部失败:加入部分真值轨迹
      → 再采样
      → 仍失败:增加提示比例
      → 成功:在被引导分布上获得学习信号
```

这让方法在可处理样本上保留探索,在过难样本上使用近似模仿学习的引导.提示比例,阶段数和真值轨迹质量都是重要超参数.

![GHPO 使用三阶段 ground-truth prefix 逐步调整 hint ratio](./images/redrawn-ghpo-multistage-guidance.png)

> 图 2: 论文 recipe 使用 $\omega\in\{0.25,0.50,0.75\}$.每个 stage 都先在原始 prompt 上重新检测:出现成功 rollout 就继续无 hint 的 on-policy RL;全部失败才构造 $q_s^*=q+\operatorname{Prefix}(h_{f,q},\omega_s)$ 并在 guided prompt 上重新采样.

**图 2 解析**

- 三个 stage 是受阶段控制的 curriculum,不等于一次 optimizer step 内连续重试三次.
- Stage 3 的 $0.75$ 是论文配置的上限;仍未解决的 prompt 应记录并诊断,不能静默暴露完整答案.
- 随着 policy 能力变化,同一 prompt 之后可能只需更短 hint 或完全不需要 hint.

## 3. "Hybrid"具体混合了什么

| 样本状态 | 输入 | 学习模式 | 主要风险 |
|---|---|---|---|
| 当前策略可解 | 原始问题 | 在线 RL 与可验证奖励 | 奖励攻击,探索不足 |
| 当前策略过难 | 问题 + 部分真值提示 | 引导式生成/模仿信号与 RL | 提示泄漏,过度简化,依赖教师轨迹 |

它不是在所有样本上永久使用同一个 `RL loss + λ·SFT loss`;那种固定混合目标与论文方法不符.

![GHPO cold-start,hybrid training 与 no-hint evaluation 的隔离协议](./images/redrawn-ghpo-training-eval-boundary.png)

> 图 3: 论文前 $N=20$ 个 optimization step 可选用原始 GRPO cold-start;随后 Phase 1 按 group reward 在原始 on-policy 路径和 training-only guided 路径之间动态分流.两条路径只在策略参数更新处汇合;Phase 2 的 validation/test 只接收原始 prompt,完全不读取 solution trace 或 hint stage.

**图 3 解析**

- $N=20$ 是论文 recipe,不是 GHPO 的通用常数.
- 训练轨迹存储记录 $h_{f,q},\omega_{stage}$ 与路由结果,但评测流程必须硬隔离这些字段.
- 应同时监控 raw-prompt success,hinted success,各 stage 路由占比,0.75 后未解决数量和 verifier 误判.
- trace 许可证,benchmark 污染,错误教师轨迹与过长 hint 都属于部署前必须审计的边界.

## 4. 数据与评测边界

GHPO 使用 ground-truth solution traces,因此要区分:

- 训练时提示来自何处,是否有许可证,是否包含 benchmark 测试答案;
- 验证和测试时是否完全移除提示;
- 改善来自学会推理,记忆教师轨迹,还是训练/测试污染;
- 对没有可靠真值轨迹的任务,方法如何获得提示.

论文作者报告在六个数学 benchmark 上平均约 5% 的性能提升,并强调稳定性与样本效率.该数字属于其模型,数据和协议,不能直接写成 GHPO 的普遍收益.

## 5. 实现与验收清单

1. 难度检测基于每个 prompt 的完整 rollout 组,不能混用跨 prompt 奖励;
2. 记录每个问题的 hint stage,避免无限增加提示;
3. 真值提示只在训练路径使用,评测路径硬隔离;
4. 同时报告原始问题成功率,带提示成功率与最终无提示测试结果;
5. 对奖励器误判,错误解题轨迹和提示过长做故障注入;
6. 比较"丢弃过难样本""固定提示""自适应提示"和普通课程学习,证明复杂度有收益.
