# Tricks or Traps:推理强化学习技巧的统一消融

这项工作的核心问题是:GRPO,DAPO,REINFORCE++ 等 recipe 同时改变数据,模型,归一化,裁剪,过滤和 loss aggregation,跨论文对比很难判断收益究竟来自哪一项.作者在统一开源框架,多个模型初始化和不同难度数学数据上逐项消融这些技巧.

## 1. 被拆开的设计轴

| 设计轴 | 典型选择 | 需要观察的风险 |
|---|---|---|
| baseline | 原奖励,组均值,leave-one-out | 方差,组内无差异 |
| normalization | 组级/批级均值与标准差 | 奖励尺度,难度偏置,梯度爆炸 |
| clipping | 对概率比,奖励或优势裁剪 | 探索被压制,极端更新 |
| filtering | 过长,全对/全错,难度过滤 | 有效 batch 缩小,数据分布改变 |
| loss aggregation | response/prompt/token 粒度 | 长度偏置与 token 权重 |
| auxiliary loss | KL,SFT 等 | 参考策略漂移,目标冲突 |

一项技巧在 easy data,hard data,base model 和 aligned model 上可能呈现不同效果.因此"某技巧普遍更好"必须被协议限定.

## 2. 概率比不能写错

PPO 类方法的 token 概率比是:

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}
{\pi_{old}(o_{i,t}\mid q,o_{i,<t})}
=\exp\left(\log\pi_\theta-\log\pi_{old}\right).
$$

它不是 `log_prob / old_log_prob`.old log-prob 必须作为采样策略的常数保存,不能在当前更新中反向传播.

## 3. 归一化结论为什么依赖数据

GRPO 常对同一 prompt 的奖励做组内均值与标准差归一化:

$$
A_k^{group}=\frac{r_k-\mu_{group}}{\sigma_{group}+\epsilon}.
$$

当一个组几乎全对或全错时,$\sigma_{group}$ 很小,除以它可能放大微小差异.论文比较了只减均值,组级标准差和批级标准差等组合,并强调选择与奖励分布和任务难度相关.

不能把这个观察简化成"永远删除标准差"或"GRPO 标准化一定有偏".实现应记录标准差分布,梯度范数和不同难度分桶.

## 4. Lite PPO 的准确定位

论文把两个在其设置中表现稳健的选择组合起来:

1. **组级均值 + 批级标准差**的优势归一化;
2. **token-level loss aggregation**.

再配合 vanilla PPO loss,作者将这个简化组合称为 Lite PPO,并在其六个数学 benchmark 的平均结果中报告优于若干更复杂 recipe.它不是"只做动态优势归一化"的独立算法,也不能从名称推出固定显存,学习率或普遍胜过 GRPO/DAPO.

## 5. 如何复现一个可信消融

1. 固定 base/aligned checkpoint,数据,采样温度,rollout 数,奖励和训练预算;
2. 一次只改变一个设计轴;
3. 对 easy/medium/hard 和不同初始化分别报告;
4. 同时记录训练奖励,无提示测试准确率,响应长度,KL,熵,截断和梯度;
5. 至少多 seed,给置信区间;
6. 最后才测试技巧组合,避免把交互作用误归因给单项;
7. 任何结果都绑定模型和论文版本,不写成工业界固定默认.

## 6. 与相邻方法的关系

| 方法 | 这里最关心的差别 |
|---|---|
| GRPO | 组内 reward normalization,response-level 聚合等原始配方 |
| DAPO | 解耦上下裁剪,动态采样,token-level loss,overlong shaping |
| Lite PPO | 本论文依据消融形成的两技巧简化组合 |
| ScaleRL | 另一项大规模 scaling 研究形成的异步复合 recipe |
