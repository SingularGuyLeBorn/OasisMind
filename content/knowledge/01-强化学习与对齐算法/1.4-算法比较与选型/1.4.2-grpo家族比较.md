# GRPO 家族：按五条设计轴比较

> 证据状态：公式和边界按 DeepSeekMath、Dr. GRPO、DAPO、GSPO 与 GMPO 的论文版本核对，更新至 2026-09-01。下表是机制比较，不代表跨论文性能可以直接横比。

这组算法共享“同一提示采样多个回答、用组内奖励估计优势”的外形，但修改的不是同一个旋钮。旧稿把 GRPO 写成 token 概率比的连乘，把 GSPO 写成同一连乘的 log-space 实现；两者都不对。**GRPO 的 PPO surrogate 使用逐 token 重要性比；GSPO 才构造长度归一的序列重要性比，并按整条回答裁剪。**

## 1. 共同记号

对提示 $x$ 采样 $G$ 条回答 $y_i$，得到序列级奖励 $R_i$。组相对优势常写为：

$$
\hat A_i=\frac{R_i-\operatorname{mean}(R_{1:G})}
{\operatorname{std}(R_{1:G})+\epsilon}.
$$

当前策略与采样策略在第 $t$ 个 token 上的比率是：

$$
\rho_{i,t}(\theta)=
\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
{\pi_{\theta_{\mathrm{old}}}(y_{i,t}\mid x,y_{i,<t})}.
$$

组内优势解决“是否另训 critic”的问题；$\rho$、裁剪和损失归约解决“怎样使用离策略 rollout”的问题。它们是不同设计轴。

## 2. 五条设计轴

| 方法 | 组内优势 | 重要性比与裁剪 | 损失聚合 | 额外机制 | 主要边界 |
|---|---|---|---|---|---|
| GRPO | 奖励中心化并除以组内标准差 | 逐 token $\rho_{i,t}$；逐 token PPO 裁剪 | 先在每条回答内按 token 平均，再按回答平均 | 原始 DeepSeekMath 形式还讨论显式 KL 正则 | 组内标准差与每回答长度归一会改变问题和回答的有效权重 |
| Dr. GRPO | 只做奖励中心化，不除组内标准差 | 仍是逐 token PPO surrogate | 去掉按实际回答长度归一，改用固定生成预算等常数归约 | 目标是移除论文指出的题目难度偏置和长度偏置 | “Done Right”是该论文命名；后续工作仍讨论无偏与长度不变之间的取舍 |
| DAPO | 沿用组相对优势；全对/全错组不提供有效梯度 | 逐 token；下界与上界解耦，论文设置 $\epsilon_{low}=0.2$、$\epsilon_{high}=0.28$ | 把批内所有有效响应 token 放在同一分母下归约 | Dynamic Sampling、Clip-Higher、Token-Level PG Loss、Overlong Reward Shaping | 四项技术共同构成论文系统，不能只把 0.28 写成“DAPO 算法” |
| GSPO | 仍用标准化组相对优势 | 长度归一的序列比率 $s_i$；整条回答统一裁剪 | 序列级奖励、裁剪与优化单位对齐 | 论文重点是长序列和 MoE 离策略训练稳定性 | $s_i$ 的裁剪范围与 token 比率的范围量级不同，不能照搬 GRPO 超参 |
| GMPO | 保留 GRPO 的组相对优势 | 保留 token 级结构与符号相关裁剪 | 把一条回答内的重要性加权项从算术平均改为几何平均 | 抑制极端 token ratio 对更新的支配 | 几何平均作用于 token 重要性加权项，不是对组内原始奖励取几何平均 |

## 3. 两个最容易混淆的“几何平均”

GSPO 的序列比率是：

$$
s_i(\theta)=
\left(\frac{\pi_\theta(y_i\mid x)}
{\pi_{\theta_{\mathrm{old}}}(y_i\mid x)}\right)^{1/|y_i|}
=\exp\left(\frac{1}{|y_i|}\sum_t\log\rho_{i,t}\right).
$$

它把一条回答压成一个序列级比率，随后对整条回答统一裁剪。长度归一不是单纯为了“防溢出”，而是为了降低方差并让不同长度共享可用的数值范围。

GMPO 也出现几何平均，但它保留 token 级结构。论文的核心对象是 $|\rho_{i,t}\hat A_i|$ 等重要性加权项，并用 $\operatorname{sgn}(\hat A_i)$ 恢复方向。**GSPO 对齐优化单位与序列奖励；GMPO 改变同一序列内 token 更新项的聚合几何。**名字相近，不是同一目标。

## 4. DAPO 不是一条“非对称裁剪公式”

DAPO 的四项设计分别处理不同失败模式：

1. **Clip-Higher**：放宽正优势 token 的上裁剪界，缓解低概率探索 token 难以被抬高的问题。
2. **Dynamic Sampling**：持续补采样，过滤组内奖励全相同、因而优势为零的提示组，提高有效批次密度。
3. **Token-Level Policy Gradient Loss**：以批内有效 token 总数为分母，而不是先让每条回答拥有相同权重。
4. **Overlong Reward Shaping**：区分合理但被截断的推理与真正低质量输出，减少硬长度惩罚带来的奖励噪声。

论文在 Qwen2.5-32B Base、AIME 2024、avg@32 等特定协议下报告逐项增益。该消融不能外推成“DAPO 对所有长 CoT 都优于其他方法”。

## 5. 选择顺序

先按失败模式选机制，而不是按榜单选缩写：

- critic 成本是主要约束：从 GRPO 类组相对优势出发，但先确认奖励组是否有足够方差。
- 观察到错误回答越训越长、不同难度题权重异常：检查 Dr. GRPO 指出的两种归一化偏置。
- 有大量全对/全错组、熵塌缩或截断噪声：逐项评估 DAPO 的采样、裁剪、归约和长度处理。
- 长序列或 MoE 的 token ratio/路由变化导致离策略训练不稳：评估 GSPO 的序列级校正；不要只换一个裁剪阈值。
- 少量极端 token ratio 主导更新，但仍希望保留 token 级目标：评估 GMPO，并核对实现中的符号、mask、old-policy 停止梯度和几何平均位置。

任何选择都要记录：模型与是否 MoE、rollout/mini-batch 更新次数、group size、奖励分布、全同奖励组比例、响应长度、clip fraction、KL/entropy、截断规则和评测采样预算。
