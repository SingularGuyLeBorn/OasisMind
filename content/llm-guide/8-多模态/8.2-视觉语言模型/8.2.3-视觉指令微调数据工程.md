# 视觉指令微调数据工程

> 数据规模只是账本中的一列。每条样本还需要追踪图像来源、标注来源、生成模型、prompt、许可、去重组与评测隔离状态。找不到这些字段时，不能用一个总样本数替代数据治理。

## 1. 训练样本不是天然的“事实”

视觉指令样本通常写作 $(v,q,a)$：视觉输入 $v$、指令 $q$、回答 $a$。三者可能来自不同权利人和不同生成链：公开图像 + 人工问题 + 模型回答，或网页图像 + 模型 caption + 模型生成问题。发布 JSON 并不自动取得底层图像的再分发权，也不证明回答被视觉证据支持。

建议至少保存以下 provenance：

| 字段 | 最低要求 |
|---|---|
| `media_source` | 原始数据集、URL/稳定 ID、抓取或取得日期 |
| `media_license` | 原图适用条款；未知时写 `unknown`，不得由生成文本许可证覆盖 |
| `annotation_source` | 人工、原数据集、规则生成或模型生成 |
| `generator` | 模型完整名称/快照、API 或本地 checkpoint |
| `prompt_version` | system/user prompt 的版本或哈希 |
| `transform_chain` | OCR、裁剪、缩放、检测框、caption 等中间步骤 |
| `dedup_group` | 原图、近重复图和派生裁剪的共同组 ID |
| `split` | train/dev/test；必须在派生问答前按媒体组划分 |
| `benchmark_overlap` | 与评测媒体、问题、答案的检查结果和工具版本 |

## 2. 可核证的数据规模账本

### 2.1 LLaVA 原始版本

原始 LLaVA 的两个阶段必须分开：

- **对齐预训练**：作者从 CC3M 筛选 595K 图文对，依据名词短语频率改善概念覆盖。
- **指令微调**：LLaVA-Instruct 共 158K，包括 58K conversation、23K detailed description、77K complex reasoning。

这 158K 由 language-only GPT-4 生成。生成器没有直接查看像素，而是接收 COCO caption、bounding box 等文本化的图像信息。因此它是“基于视觉标注上下文的文本模型合成”，不是 GPT-4V 直接看图标注。[论文数据构造](https://arxiv.org/html/2304.08485#S3.1)、[官方 Data.md](https://github.com/haotian-liu/LLaVA/blob/main/docs/Data.md)。

### 2.2 LLaVA-1.5

LLaVA-1.5 的官方口径为：

- 对齐阶段：LCS-558K，即 LAION/CC/SBU 的 BLIP caption 概念均衡子集；
- 指令阶段：665K 混合数据。

论文附录表 7 给出组成：158K LLaVA、40K ShareGPT、83K VQAv2、72K GQA、9K OKVQA、80K OCRVQA、66K A-OKVQA、22K TextCaps、48K RefCOCO、86K Visual Genome。表内数字有四舍五入，引用时保留“665K 官方总数”，不要自行相加后声称更精确。[LLaVA-1.5 表 7](https://arxiv.org/html/2310.03744#A1.T7)。

该混合包含学术任务的训练数据。论文在部分指标旁明确标记训练时见过相应训练图像/标注；这属于任务内监督评测，不等于测试 split 泄漏，也不能宣传为纯 zero-shot。

### 2.3 ShareGPT4V

ShareGPT4V 论文披露两层数据：先用 GPT-4V 得到经过整理的 100K 高质量 caption，再训练 caption 模型扩展到 1.2M 描述。100K 是强模型直接生成子集，1.2M 不应全部标记为 GPT-4V 直接输出。[论文](https://arxiv.org/abs/2311.12793)、[官方仓库](https://github.com/ShareGPT4Omni/ShareGPT4V)。

### 2.4 ALLaVA

ALLaVA 论文摘要写 1.3M 合成样本；后续官方仓库发布页写 1.4M 数据资产，并列出 LAION、Vision-FLAN 与 143K 文本指令等子集。两个数字对应论文口径和后续发布口径，不能择一覆盖另一项。报告实验时应注明所用 release 与子集清单。[论文](https://arxiv.org/abs/2402.11684)、[官方仓库](https://github.com/FreedomIntelligence/ALLaVA)。

### 2.5 LLaVA-OneVision

OneVision 论文表 1 报告 Stage 1 为 558K、Stage 1.5 为 4M、单图指令阶段为 3.2M、OneVision 混合阶段为 1.6M。附录又给出更细的来源与重采样数量；同一媒体可产生多条标注，分项也可能经过筛选和重采样，不能用简单求和替换作者的阶段总数。[训练策略](https://arxiv.org/html/2408.03326#S5)、[数据附录](https://arxiv.org/html/2408.03326#S4)。

## 3. 合成数据：必须记录生成器看到了什么

| 合成路线 | 生成器输入 | 能支持的结论 | 主要风险 |
|---|---|---|---|
| 标注文本 → text-only LLM | caption、框、类别、关系 | 回答与这些文本标注一致 | 生成器没看像素；标注遗漏和错误会被放大 |
| 图像 → 多模态强模型 | 像素 + prompt | 回答由该模型基于图像生成 | 模型幻觉、OCR/计数错误、服务条款与不可复现快照 |
| 强模型种子 → captioner 扩展 | 图像 + 蒸馏模型 | 可规模化生成同风格描述 | 学生继承教师偏差；后续 1.2M 不是强模型逐条直出 |
| 程序化渲染 | 场景参数 + 渲染器 | 标签与生成参数可精确对应 | 与真实图像存在 domain gap，模板分布易被模型记住 |

“合成”不是质量等级。每条合成样本应保存 generator、prompt、温度、日期、输入上下文和安全过滤版本。API alias 会变化，只有完整模型快照或 `as_of` 才能复现。

## 4. 过滤：拒绝神奇阈值

旧稿用一个随机数占位模拟 perplexity 过滤，并声称固定阈值能稳定剔除某个比例的数据；这既不可运行，也不能验证视觉事实。Perplexity 主要衡量回答在参考模型下是否顺畅/可预测，低 perplexity 不等于回答被图像支持。

推荐把过滤拆开并分别记录通过率：

1. **结构有效性**：图片可解码；消息角色交替；`<image>` 数量与媒体数量一致；答案非空。
2. **精确重复**：媒体内容哈希、规范化文本哈希。
3. **近重复**：pHash/视觉 embedding + 文本 embedding；阈值应在人工标注验证集上定标，而不是抄一个通用数字。
4. **视觉 grounding**：对可核验字段做 OCR、检测、计数或人工复核；生成模型自评只能作为弱信号。
5. **回答策略**：保留“不可回答/信息不足”样本，检查无图也能答对的问题，避免语言先验捷径。
6. **安全与隐私**：人脸、身份证件、医疗信息、地理位置和未成年人数据使用专门策略。
7. **许可证门禁**：无法确认训练、修改或再分发权时隔离，不因为“公开下载”就默认可商用。

## 5. 混合：记录采样权重，不伪造 Scaling Law

数据源规模、任务价值与采样概率是三个不同量。可用

$$
p_i=\frac{w_i}{\sum_j w_j}
$$

记录每个来源的显式采样权重 $w_i$，但权重必须来自消融或产品目标。不能把未经论文报告的 `T≈2`、`T≈0.5` 写成 LLaVA-1.5 配方，也不能宣称一个通用的视觉指令数据幂律指数范围。

每次训练应同时记录：

- 原始样本数、去重后媒体数、问答轮数；
- 采样权重、上采样是否允许重复、每 epoch 的实际曝光数；
- 图像/文档/OCR/定位/推理/纯文本比例；
- 短答、多选、自由回答的 response-format prompt；
- 每种语言和目标部署域的覆盖；
- 每个数据源的 loss 与 held-out 指标，避免大源掩盖小源退化。

## 6. 许可不是一个总标签

LLaVA-Instruct-150K 的官方数据卡标注 CC BY 4.0，并要求遵守 OpenAI 使用政策；但其图像仍来自 COCO 等上游来源。LLaVA 官方 Data.md 对 CC3M 图像明确提示：项目不取得图像所有权，使用者仍须遵守 CC3M 与原图权利人的条件。

665K 混合更不可能由一个下游 JSON 许可证覆盖全部上游：COCO、Visual Genome、GQA、OCR-VQA、TextVQA、ShareGPT 和生成文本各有不同条款。上线前应分别核验：

1. 训练权；
2. 修改/派生权；
3. 数据再分发权；
4. 商业使用限制；
5. 生成服务条款；
6. 模型权重的基础模型许可证。

来源：[LLaVA-Instruct-150K 官方数据卡](https://huggingface.co/datasets/liuhaotian/LLaVA-Instruct-150K)、[LLaVA 官方数据说明](https://github.com/haotian-liu/LLaVA/blob/main/docs/Data.md)。

## 7. Benchmark contamination：先按媒体分组，再生成问答

污染不只等于“测试 JSON 被复制进训练集”。同一 COCO/网页图像可以被重新裁剪、压缩、改文件名，再生成全新问题；只查 MD5 会漏掉这类媒体重叠。

安全流程：

1. 在任何 caption/问答生成前建立 benchmark registry，保存测试媒体、近重复指纹、问题与答案。
2. 将原图、裁剪、不同尺寸、视频抽帧归到同一 `dedup_group`。
3. 先按 `dedup_group` 划 train/dev/test，再生成派生指令；禁止生成后随机逐行切分。
4. 用内容哈希查完全重复，用 pHash/视觉 embedding 查近重复，用规范化文本与 n-gram/embedding 查问题答案重合。
5. 人工复核相似度阈值附近样本，并保存工具、阈值和排除清单。
6. 结果表声明 direct overlap、near-duplicate overlap、task-train exposure 和模型可能的预训练暴露；不知道就写未知。

LLaVA-1.5 的论文星号正是一个有用范例：作者显式标识训练图像/标注暴露，而不是把所有结果包装为相同的 zero-shot 协议。

## 8. 可复现的数据发布最小清单

```yaml
dataset_release: "name@immutable-revision"
as_of: "YYYY-MM-DD"
generator:
  model_snapshot: "full-id-or-unknown"
  prompt_hash: "sha256:..."
sources:
  - name: "source-name"
    raw_count: 0
    unique_media: 0
    post_filter_count: 0
    sampling_weight: 0.0
    media_license: "..."
    annotation_license: "..."
split_policy:
  unit: "dedup_group"
  exact_hash: "sha256"
  near_duplicate_method: "name+version+threshold"
benchmark_audit:
  registry_revision: "..."
  direct_overlap: 0
  near_duplicate_reviewed: 0
```

数字为 0 只是字段示例，不是推荐阈值。真正发布时还应提供移除请求、隐私申诉、已知偏差与不适用场景。

## 9. 已删除的无依据内容

- 数据工程占项目工时的固定比例和所谓“高质量数据”的固定提升幅度；
- 未绑定 API 价格日期、token 数、地区与重试的单样本成本表；
- LLaVA-1.5 使用特定 temperature mixing 并带来固定百分点提升的说法；
- ShareGPT4V 使用固定 perplexity 阈值并剔除固定比例数据的说法；
- 视觉指令数据的通用 scaling-law 指数和按固定规模推算的损失下降；
- MinHash/pHash 使用一个通用阈值就必然去除固定比例样本的说法；
- 未定义数据总体的英中语言占比，以及非西方场景的固定下降幅度；
- 只要达到某个真人数据比例即可避免模型崩溃等未给实验条件的处方。
