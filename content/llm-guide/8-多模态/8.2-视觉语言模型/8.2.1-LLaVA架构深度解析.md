# LLaVA 架构深度解析

> 本文只记录论文,项目页和官方仓库能够支持的结论.不同版本,骨干,输入分辨率,训练数据与评测协议不可混用;没有公开证据的准确率变化,失败率和内部机制不作估计.

## 1. 一条主线,四个不同版本

LLaVA 系列共享一个简洁接口:视觉编码器产生视觉特征,连接器把特征映射到语言模型的词嵌入维度,语言模型在视觉前缀与文本上下文上生成回答.这个接口延续了下来,但视觉编码器,连接器,数据配方,可接受的视觉输入和评测协议都在变化.

| 版本 | 公开时间 | 视觉侧与连接器 | 官方披露的数据与训练阶段 | 评测边界 |
|---|---|---|---|---|
| LLaVA | 2023-04 | CLIP ViT-L/14 + 线性投影 + Vicuna | 阶段一:CC3M 筛选后的 595K 图文对;阶段二:LLaVA-Instruct 158K | 论文包含 LLaVA-Bench,ScienceQA 等;ScienceQA 是专项微调结果,不能当通用零样本成绩 |
| LLaVA-1.5 | 2023-10 | CLIP ViT-L/14-336 + 两层 MLP + Vicuna v1.5 | 阶段一:LCS-558K;阶段二:665K 指令混合,其中 158K LLaVA,40K ShareGPT,以及多种学术 VQA/OCR/区域任务数据 | 论文表格用星号标出训练时见过相应训练图像或标注的指标;不能与未见训练分布的零样本结果直接比较 |
| LLaVA-NeXT(LLaVA-1.6) | 2024-01 | 延续 MLP 连接器,引入 AnyRes 多裁块表示 | 官方项目页披露改进的视觉指令数据混合,但首页没有给出一个可跨 checkpoint 套用的统一"760K"总数 | 官方页比较多种 LLM/checkpoint;引用成绩必须同时记录型号,网格,提示模板与数据集版本 |
| LLaVA-OneVision | 2024-08 | SigLIP + 两层 MLP + Qwen2;统一单图,多图和视频接口 | Stage 1:558K;Stage 1.5:论文表 1 记为 4M;Stage 2 单图:3.2M;OneVision 混合:1.6M | 论文使用 LMMs-Eval,作者结果默认 greedy decoding,0-shot,另有说明者除外 |

来源:[LLaVA 论文](https://arxiv.org/abs/2304.08485),[LLaVA-1.5 论文](https://arxiv.org/abs/2310.03744),[LLaVA-NeXT 官方页](https://llava-vl.github.io/blog/2024-01-30-llava-next/),[LLaVA-OneVision 论文](https://arxiv.org/abs/2408.03326).

## 2. 原始 LLaVA:线性连接与两阶段训练

设视觉编码器输出为

$$
H_v \in \mathbb{R}^{N_v \times d_v},
$$

线性连接器将每个视觉特征映射到语言模型的隐藏维度:

$$
Z_v = H_v W, \qquad W \in \mathbb{R}^{d_v \times d_{\text{llm}}}.
$$

这里的作用是维度与分布适配,不是把视觉特征证明为"落在对应词嵌入附近",也不能据此断言投影保留了全部视觉信息.视觉 token 与文本 token 一起进入语言模型;训练损失仍是回答 token 的自回归交叉熵,视觉位置和用户提示位置通常不计入回答损失.

原始论文的阶段边界是:

1. **特征对齐预训练**:冻结视觉编码器和语言模型,只训练投影矩阵.论文将 CC3M 按概念覆盖筛到 595K,并训练 1 个 epoch.
2. **视觉指令微调**:更新投影层与语言模型,使用 158K 指令数据训练 3 个 epoch;视觉编码器保持冻结.158K 包含 58K 多轮对话,23K 详细描述和 77K 复杂推理.

原始论文报告 8 张 A100 上阶段一约 4 小时,阶段二约 10 小时.这是作者特定硬件,实现和超参数下的复现实录,不应外推为所有 LLaVA 变体的成本.[论文训练细节](https://arxiv.org/html/2304.08485#Sx3).

## 3. LLaVA-1.5:MLP,336 像素和公开数据混合

LLaVA-1.5 把连接器改为两层 MLP:

$$
Z_v = \mathrm{GELU}(H_v W_1 + b_1) W_2 + b_2,
$$

这里沿用上文的行向量约定:$W_1 \in \mathbb{R}^{d_v \times d_m}$,$W_2 \in \mathbb{R}^{d_m \times d_{\text{llm}}}$.第一层把每个视觉 token 映射到中间维度,第二层再映射到语言模型隐藏维度.

官方训练配置明确使用 `openai/clip-vit-large-patch14-336` 与 `mlp2x_gelu`.对 336×336,patch size 14 的 ViT-L/14,空间网格为 24×24,即 576 个 patch 位置;具体实现还要核对是否包含或丢弃分类 token,选择视觉塔哪一层.

数据账本不能写成"665K 全是 GPT-4 合成":

- 阶段一是 LAION/CC/SBU 的 BLIP caption 概念均衡子集,共 558K.
- 阶段二总计 665K.论文附录表 7 列出 LLaVA 158K,ShareGPT 40K,VQAv2 83K,GQA 72K,OKVQA 9K,OCRVQA 80K,A-OKVQA 66K,TextCaps 22K,RefCOCO 48K 和 Visual Genome 86K.
- 官方仓库概括为约 150K GPT 生成的多模态指令,加约 515K 学术任务数据.

来源:[官方仓库训练说明](https://github.com/haotian-liu/LLaVA#train),[LLaVA-1.5 数据混合表](https://arxiv.org/html/2310.03744#A1.T7),[官方 Data.md](https://github.com/haotian-liu/LLaVA/blob/main/docs/Data.md).

## 4. LLaVA-NeXT:AnyRes 不是任意网格公式

LLaVA-NeXT 将一张高分辨率图像表示为一个全局视图与若干局部裁块.官方 2024-01 页面列出的原始网格集合为:

$$
\{2\!\times\!2,\ 1\!\times\!\{2,3,4\},\ \{2,3,4\}\!\times\!1\}.
$$

它支持最高 672×672,336×1344,1344×336 三类分辨率/宽高比,作者将其概括为相对 LLaVA-1.5 最多 4 倍像素.选择过程是在预设候选分辨率中匹配原图,不等同于对原始高宽分别做向上取整,也没有一个适用于所有 LLaVA-NeXT checkpoint 的固定 `G_max=6`.

如果每个裁块保留 $T$ 个视觉 token,且实际选择了 $g$ 个局部裁块,那么送入语言模型前的视觉 token 上界可写成:

$$
L_v=(1+g)T,
$$

其中 1 是全局视图.是否加入换行/图像分隔 token,是否做空间池化,$T$ 的取值,都取决于具体实现.不能把这个教学式上界当成任一 checkpoint 的精确 KV cache 账单.

来源:[LLaVA-NeXT 官方技术页](https://llava-vl.github.io/blog/2024-01-30-llava-next/),[官方消融页](https://llava-vl.github.io/blog/2024-05-25-llava-next-ablations/).

## 5. LLaVA-OneVision:跨场景统一不等于"视频版 NeXT"

LLaVA-OneVision 的公开实例使用 Qwen2,SigLIP 和两层 MLP.它为单图,多图,视频选择不同的视觉表示预算:单图可使用 Higher AnyRes;多图使用每张图的基础分辨率;视频对每帧编码后通过插值控制每帧 token 数.论文有意让三个场景的最大视觉 token 预算接近,以支持跨场景迁移.

训练按课程分为:

1. Stage 1:仅训练连接器,558K 对齐数据.
2. Stage 1.5:全模型学习高质量知识;论文表 1 记为 4M.
3. Stage 2 单图:3.2M 单图指令.
4. Stage 2 OneVision:1.6M 单图,多图与视频混合.

论文还公开了更细的数据分项;总数与分项可能因去重,重采样和同一图像对应多种标注而不能直接相加.引用规模时必须注明来自论文表 1 还是数据附录,不能自行求和生成新口径.[训练表与评测协议](https://arxiv.org/html/2408.03326#S5).

## 6. 评测必须绑定协议

| 要记录的字段 | 为什么不能省 |
|---|---|
| checkpoint 与语言模型骨干 | 7B,13B,34B,72B 不可横向当同一模型 |
| 视觉编码器,分辨率,AnyRes 网格与 token 池化 | 同名版本可有不同视觉预算 |
| 数据集版本与 split | 一些训练混合包含学术任务的训练图像或标注 |
| prompt / conversation template | 多选题,短答题和开放回答需要不同格式 |
| decoding | greedy,temperature,采样和最大输出长度会改变结果 |
| evaluator | 精确匹配,官方脚本,GPT judge 不能混为同一指标 |

LLaVA-1.5 论文在学术任务表中用星号明确标注"训练时见过对应训练图像/标注"的结果;这不等于测试集泄漏,但说明它们是任务内监督结果,不应贴上纯零样本标签.OneVision 论文则说明作者结果默认使用 LMMs-Eval,greedy decoding 和 0-shot,另有说明者除外.
