# Q-Former 与视觉 Token 压缩

> “视觉 token 压缩”不是一种算法。Q-Former、Perceiver Resampler 和 TokenLearner 都能把较长视觉表示变短，但训练目标、模块位置、是否使用语言条件以及输出如何进入语言模型并不相同。

## 1. 先区分四种接口

| 接口 | 输入到输出 | 是否改变 token 数 | 主要训练信号 | 典型位置 |
|---|---|---:|---|---|
| Linear / MLP projector | 对每个视觉 token 独立做维度映射 | 否 | 语言建模或指令微调 | 视觉编码器与 LLM 输入之间 |
| BLIP-2 Q-Former | 学习 query 对冻结视觉特征做交叉注意力 | 是；BLIP-2 使用 32 个 query | ITC、ITM、ITG；随后连接冻结 LLM | 视觉编码器与 LLM 之间的跨模态瓶颈 |
| Flamingo Perceiver Resampler | 学习 latent 从图像/视频特征采样固定长度表示 | 是；Flamingo 使用 64 个输出 | 交错图文的自回归语言建模 | 视觉编码器后；输出经门控交叉注意力注入 LLM |
| TokenLearner | 从视觉特征图学习少量空间注意力图并汇聚 token | 是；论文重点实验使用 8 个 token | 图像/视频任务损失 | 视觉主干内部，不要求语言输入 |

来源：[BLIP-2](https://arxiv.org/abs/2301.12597)、[Flamingo](https://arxiv.org/abs/2204.14198)、[TokenLearner](https://arxiv.org/abs/2106.11297)。

## 2. BLIP-2 的 Q-Former 到底做了什么

BLIP-2 冻结预训练图像编码器和大语言模型，用 Q-Former 跨越两者的模态差异。Q-Former 以 BERT-base 权重初始化，包含 188M 参数；论文和官方 LAVIS 配置使用 **32 个可学习 query token**，并每隔一个 Transformer block 插入一次视觉交叉注意力。

设一幅图像的冻结视觉特征为

$$
V \in \mathbb{R}^{M \times d_v},
$$

32 个学习 query 为

$$
Q \in \mathbb{R}^{32 \times d_q}.
$$

一次交叉注意力可概括为：

$$
\operatorname{Attn}(Q,V)
=\operatorname{softmax}\!\left(\frac{(QW_Q)(VW_K)^\top}{\sqrt{d_h}}\right)(VW_V).
$$

输出的第一维由 query 数决定，因此仍为 32，而不是由 $M$ 决定。多层自注意力和交叉注意力继续更新这些 query，最终得到固定长度视觉表示。

### 2.1 “可变视觉输入 → 固定 32 query”准确但有边界

- **成立的部分**：交叉注意力在数学上可读取不同长度 $M$ 的视觉序列，送往 LLM 的视觉前缀长度由 query 数固定为 32。
- **不成立的外推**：BLIP-2 官方预训练配置采用 224×224 图像；“输出固定 32”不代表官方 checkpoint 已在任意分辨率或任意长视觉序列上训练并验证。
- **计算没有消失**：视觉编码器仍处理原始图像，交叉注意力成本仍随 $M$ 增长；被固定的是 LLM 前缀长度，不是整个视觉流水线的成本。
- **容量是超参数而非定理**：32 是 BLIP-2 的已披露选择。其他模型可改 query 数，但必须重新训练和评测，不能直接宣称 64/128 一定改善 OCR 或表格。

官方证据：[LAVIS `num_query_token: 32` 配置](https://github.com/salesforce/LAVIS/blob/main/lavis/configs/models/blip2/blip2_pretrain.yaml)、[Q-Former 实现，`cross_attention_freq=2`](https://github.com/salesforce/LAVIS/blob/main/lavis/models/blip2_models/blip2_qformer.py)。

## 3. 两阶段预训练与注意力掩码

### 3.1 第一阶段：视觉—语言表示学习

BLIP-2 使用三个目标：

- **ITC（image-text contrastive）**：比较图像 query 表示与文本表示；
- **ITM（image-text matching）**：判断图文是否匹配；
- **ITG（image-grounded text generation）**：在视觉 query 条件下生成文本。

Q-Former 同时承载 query 和文本 token，但不同任务使用不同 attention mask。不能把它简化成“每层永远先 cross-attention 再 causal self-attention”。尤其是 query token 本身不是按 1→32 自回归生成的，因此给 query-query 自注意力强加三角因果掩码不是 BLIP-2 的通用实现。

### 3.2 第二阶段：从视觉到冻结 LLM

Q-Former 的 32 个输出经过全连接层映射到目标 LLM 的嵌入维度。OPT 路线把它们作为软视觉提示；Flan-T5 路线按 encoder-decoder 接口连接。LLM 保持冻结，训练 Q-Former 与输出投影，让固定语言模型能够基于视觉前缀生成文本。

因此，Q-Former 的“188M 参数”描述的是论文实例，不是一个仅由 query 数和 patch 数计算出的公式。参数主要由 BERT 规模 Transformer 权重决定；旧稿把注意力 FLOPs 写进参数量公式是量纲错误。

## 4. 与 Perceiver Resampler 的差异

Flamingo 同样把可变视觉输入压到固定长度，但系统接口不同：

1. 视觉编码器处理图像或视频帧；
2. Perceiver Resampler 产生每个视觉输入 64 个 token；
3. 这些 token 不只是放在语言模型输入开头，而是通过新加入的 gated cross-attention dense layers 注入冻结语言模型层间；
4. Flamingo 在交错图文序列上做自回归训练，目标是少样本上下文学习。

因此“Q-Former 与 Perceiver 功能等价”过于宽泛。它们共享“学习 latent/query 聚合变长输入”的形状，但参数初始化、训练任务、与文本 token 的交互和注入 LLM 的位置不同。

## 5. 与 TokenLearner 的差异

TokenLearner 从视觉特征图学习若干空间注意力函数，对空间位置加权汇聚，论文展示用 8 个学习 token 支撑图像和视频识别。它可以插在视觉主干内部，以减少后续视觉 Transformer 的计算。

它不是 Q-Former 的轻量版：

- TokenLearner 不需要语言模型，也不以文本为 query；
- 它学习的是视觉空间汇聚函数；
- 原论文任务是视觉识别而非冻结视觉塔与冻结 LLM 的跨模态桥接。

官方实现：[Google Research Scenic TokenLearner](https://github.com/google-research/scenic/tree/main/scenic/projects/token_learner)。

## 6. 只做可复核的效率账

若 LLM 看到 $T$ 个文本 token，视觉前缀从 $M$ 压为 $K$，仅就标准全注意力的序列二次项而言，比例是：

$$
\frac{(T+K)^2}{(T+M)^2}.
$$

这只是序列长度项，不是端到端 FLOPs 或延迟。完整成本还包括：

- 视觉编码器的分辨率与 patch 数；
- Q-Former / Resampler 自身的交叉注意力与前馈网络；
- LLM 的层数、GQA/MQA 结构、KV cache 精度和实现；
- batch、生成长度、编译器、量化和硬件。

因此不保留未给出软件栈和测量协议的“TTFT 1200ms→180ms”“显存 1.2GB→67MB”或臆测 GFLOPs 表。

## 7. 失效模式与选择原则

固定查询瓶颈可能丢弃任务所需信息，但目前没有一手证据支持旧稿对失败案例所作的固定比例归因。可靠的评测应直接改变 query 数、分辨率与任务类型，并同时报告：

- OCR/文档：字符或字段级指标、输入缩放、裁块策略；
- 细粒度定位：区域/短语 grounding 指标；
- 多图：每图 query 数、图片数、总视觉预算；
- 延迟：视觉塔、压缩器、prefill 与 decode 分项；
- 消融：相同视觉塔、LLM、数据、训练步数和 decoding。

选型时：

- 需要最小实现与保留全部 patch 接口时，用 Linear/MLP projector；
- 需要冻结两端并学习跨模态瓶颈时，Q-Former 是明确基线；
- 需要交错图文/视频和层间视觉注入时，参考 Flamingo；
- 只想在视觉主干内部减少 token 时，TokenLearner 更接近问题本身。

## 8. 已删除的无依据内容

- InstructBLIP 失败案例的未证实固定比例归因；
- 未绑定硬件与实现的 TTFT、KV cache、GFLOPs 和显存数字；
- 旧稿引入但找不到一手出处的动态 query 公式和固定提升幅度；
- 旧稿引入但找不到一手出处的多专家路由和固定提升幅度；
- 把 query 之间的竞争解释为 softmax 导致 query A 抢走 query B 的权重；标准交叉注意力的 softmax 是每个 query 对 key 归一化，不会自动在不同 query 间做排他竞争；
- “2025–2026 工业共识”和 3–5 年市场份额预测。
