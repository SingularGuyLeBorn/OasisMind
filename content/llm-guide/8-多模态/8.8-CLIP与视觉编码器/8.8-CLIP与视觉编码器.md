# CLIP 与视觉编码器：目标、特征接口与工程选型

视觉编码器把像素变成可被检索器、检测头、分割头或语言模型消费的特征。CLIP、SigLIP、EVA-CLIP 和 DINOv2 都可用作视觉骨干，但它们的监督信号、输出空间和擅长任务不同。**“VLM 使用视觉编码器”不等于“所有 VLM 都使用 CLIP”，也不等于换一个更大的视觉 checkpoint 就必然提升问答。**

> **证据与时效边界**：本文截至 2026-09-01。模型家族经常同时发布多个尺寸、分辨率、训练数据和许可不同的 checkpoint；正文只比较可由论文、模型卡或官方仓库核验的家族特性，不把跨论文排行榜差值解释成单一架构因果。

## 1. 先明确视觉编码器要交付什么

给定图像 $x \in \mathbb{R}^{H \times W \times C}$，patch 大小为 $P$，规则网格产生的 patch 数近似为：

$$
n_{\text{patch}} = \left\lfloor\frac{H}{P}\right\rfloor
\left\lfloor\frac{W}{P}\right\rfloor.
$$

视觉 Transformer 可以返回：

- **全局向量** $z_{\text{global}}$：整图分类、检索、去重和相似度排序。
- **Patch 序列** $H_V \in \mathbb{R}^{n_{patch}\times d_v}$：定位、分割、OCR、高分辨率切片和 VLM 连接器。
- **多层特征**：浅层纹理与深层语义的组合，常用于稠密预测。
- **投影后嵌入**：专门映射到图文共享空间，适合与文本向量做相似度。

选型前必须确认下游读取哪一个输出。一个 checkpoint 的全局检索分数很高，并不保证其中间 patch token 已为像素级任务优化。

## 2. 四个核心家族

### 2.1 CLIP：语言监督的双塔基线

CLIP 联合训练独立图像编码器与文本编码器，把匹配图文拉近、batch 内其他组合推远。OpenAI 论文构造了 4 亿图文对的 WebImageText 数据集，并发布 ResNet 与 ViT 视觉塔；具体数据没有随仓库公开，因此不能把“OpenAI CLIP 数据”当作可复现实验集。[CLIP 原论文](https://arxiv.org/abs/2103.00020) · [OpenAI 官方仓库](https://github.com/openai/CLIP)

适合：

- 文本到图像/图像到文本检索；
- prompt-based 零样本分类；
- 作为 VLM 的语言感知视觉初始化；
- 语义去重、聚类和数据过滤，但阈值需按领域校准。

主要边界：

- 全局图文目标对计数、位置、文字和小物体没有直接监督；
- 非对角图文 pair 可能是假阴性；
- prompt 模板与类别词会显著影响零样本分类；
- 互联网图文监督会继承语言和社会偏差。

### 2.2 SigLIP：逐对 sigmoid 的语言—图像编码器

SigLIP 仍是图像/文本双塔，主要改变对比目标：每个已枚举图文 pair 独立使用 sigmoid 损失，而不是进入行列 softmax 分母。它不需要全局相似度视图来做 softmax 归一化，但负对仍存在，跨设备实现也可能交换特征。[SigLIP 原论文](https://arxiv.org/abs/2303.15343) · [Google `big_vision` 官方仓库](https://github.com/google-research/big_vision)

把 SigLIP checkpoint 用作 VLM 视觉塔时，直接可用的是它已经过语言对齐的视觉特征；这不是“sigmoid 对任何 VLM 都更好”的证明。应在相同 LLM、连接器、分辨率、视觉 token 数和训练数据下比较。

SigLIP 2 在原有图文目标上加入字幕生成、自蒸馏、masked prediction 与局部/稠密目标，并扩展多语言训练；因此“SigLIP 2 的稠密特征能力”不能反向归因给原始 SigLIP 的单一 sigmoid 损失。[SigLIP 2 原论文](https://arxiv.org/abs/2502.14786)

### 2.3 EVA-CLIP：CLIP 训练与初始化配方的规模化改进

EVA-CLIP 不是全新的输入输出范式，仍是图文双塔。其论文重点包括用预训练 EVA 视觉表示初始化视觉塔，以及优化器、token dropout、位置嵌入和训练稳定性等组合技巧。官方仓库同时发布多种模型与训练配置。[EVA-CLIP 原论文](https://arxiv.org/abs/2303.15389) · [BAAI EVA 官方仓库](https://github.com/baaivision/EVA/tree/master/EVA-CLIP)

选择 EVA-CLIP 的理由应是某个具体 checkpoint 在你的分辨率、显存、框架和任务上经过验证，而不是直接引用论文中大型模型的 ImageNet headline。论文表格中的 checkpoint 同时改变视觉塔规模、文本塔、样本曝光量、输入分辨率和训练计算，不能只归因于“EVA 初始化”。

### 2.4 DINOv2：不依赖文本的视觉自监督骨干

DINOv2 从图像自监督与自蒸馏中学习视觉特征，不包含与自然语言共同训练的文本塔。Meta 报告从 12 亿候选图像中策划出 1.42 亿图像的 LVD-142M 预训练集；这是 DINOv2 论文系统的数据事实，不是部署所需数据量。[Meta 官方介绍](https://ai.meta.com/blog/dino-v2-computer-vision-self-supervised-learning/) · [原论文](https://arxiv.org/abs/2304.07193) · [官方仓库](https://github.com/facebookresearch/dinov2)

DINOv2 的 patch 特征是分类、深度、分割和视觉对应等稠密任务的重要候选。但它本身没有 CLIP 式文本嵌入空间：不能直接把“一张猫图”与文本 prompt 做同空间零样本分类。若接入 LLM，需要额外投影器、查询器或跨注意力，并通过多模态数据训练接口。

## 3. 家族差异不是一张排行榜

| 家族 | 主要预训练信号 | 原生文本塔 | 典型输出强项 | 接入 VLM 时的注意点 |
|---|---|---:|---|---|
| CLIP | 对称图文对比 | 有 | 全局语义、检索、零样本分类 | patch 细节需实测；prompt 敏感 |
| SigLIP | 逐对 sigmoid 图文损失 | 有 | 全局语言对齐；具体 checkpoint 可作 VLM 塔 | 不要把 loss 变化等同于所有能力提升 |
| SigLIP 2 | 图文、生成、自蒸馏、masked/局部目标 | 有 | 多语言、定位与稠密特征目标更完整 | 与原始 SigLIP 分开记录版本 |
| EVA-CLIP | CLIP 目标 + EVA 初始化及规模化训练技巧 | 有 | 语言对齐与大型视觉塔 | 权重、分辨率、实现与许可逐个核查 |
| DINOv2 | 图像自监督、自蒸馏与正则化 | 无 | 通用视觉和稠密 patch 特征 | 需另学语言接口，不能直接文本检索 |

“语义”和“空间细节”不是完全对立。不同层、分辨率和后训练会改变结果；表格只是训练信号与默认接口的起点。

## 4. 全局嵌入与 Patch 特征

### 4.1 全局池化的价值

整图向量使大规模检索可先离线编码，再用向量索引做近邻搜索。对于 $M$ 张图和 $K$ 条文本，无需对每个图文组合重新跑交叉编码器。

但把二维特征序列池化成单个向量，会隐藏显式位置对应。两张图包含相同对象却关系不同，可能得到相近全局语义；这对检索可以接受，对“杯子在盘子左边还是右边”则不够。

### 4.2 Patch token 的价值与成本

把 $n_v$ 个视觉 token 直接送入语言模型，会占用上下文并增加注意力计算。图像的高和宽各翻倍时，规则二维网格 token 数约变为四倍；多图和视频进一步相乘。

需要同时记录：预处理尺寸、是否保持长宽比、裁剪/填充、patch 大小、是否有全局 token、取哪一层、是否移除 CLS、位置编码如何插值，以及切片如何恢复原图坐标。只写“使用 ViT-L/14”不足以复现实验。

### 4.3 多层特征

最后一层更贴近预训练目标，未必对所有局部任务最好。检测和分割常比较中间层或多层融合；VLM 也可能从倒数若干层选择 patch token。层选择是超参数，必须和连接器共同评测。

## 5. 如何接入语言模型

视觉编码器维度 $d_v$ 与语言模型维度 $d_{llm}$ 通常不同，需要连接器。具体机制见 [多模态对齐](../8.5-多模态对齐技术/8.5-多模态对齐技术.md)。

| 接口 | token 数 | 优点 | 风险 |
|---|---:|---|---|
| 线性/MLP 投影每个 patch | 近似保留 $n_v$ | 简单、空间信息较完整 | 高分辨率和多图成本高 |
| Q-Former / resampler | 固定或受控 | 压缩输入、适配冻结骨干 | query 瓶颈可能丢小字和密集物体 |
| Cross-attention memory | 视觉序列独立保存 | 文本按需读取、支持交错输入 | 修改 LLM 层，缓存与部署复杂 |
| 多尺度/切片汇聚 | 随图像和切片增长 | 小物体、文档和长图更清晰 | 坐标、去重和 token 预算复杂 |

### 5.1 连接器不是无损格式转换

投影器学习的是任务相关接口。相同视觉塔配不同 projector、LLM 和指令数据，结果可以差异很大。官方 LLaVA 模型库特别提醒预训练 projector 必须匹配相同的基础 LLM 和视觉编码器；这说明 connector checkpoint 不是可随意互换的通用适配器。[LLaVA 官方模型说明](https://github.com/haotian-liu/LLaVA/blob/main/docs/MODEL_ZOO.md)

### 5.2 冻结还是微调

- **冻结视觉塔**：训练稳定、成本低、保留原有能力；无法适配未编码的领域细节。
- **LoRA/adapter 或后几层解冻**：在计算与适配间折中；仍需视觉回归测试。
- **全量解冻**：适合充足领域数据与明确视觉目标；更易过拟合并破坏通用表征。

应分别为视觉塔和 LLM 设置学习率、权重衰减和解冻时点。不能把“端到端微调”简化为所有参数使用同一优化配置。

## 6. 选型决策树

### 6.1 任务首先决定候选集

| 任务 | 优先候选 | 必测补充项 |
|---|---|---|
| 文本—图像检索/零样本分类 | CLIP、SigLIP、EVA-CLIP | 领域词汇、语言、prompt、校准 |
| 通用 VLM 视觉输入 | 语言对齐塔或经验证的 DINOv2 接口 | projector、视觉 token、VQA/OCR、文本回归 |
| 分割、深度、对应、局部跟踪 | DINOv2、SigLIP 2 等稠密目标模型 | 中间层、分辨率、线性/轻量 head |
| 文档/OCR/图表 | 高分辨率或切片友好视觉塔 | 字符、布局、长宽比、坐标恢复 |
| 视频/多图 | 可缓存视觉塔 + resampler/时序模块 | 帧采样、顺序、token 预算、延迟 |
| 边缘部署 | 小型 checkpoint、蒸馏或量化版本 | 实际算子支持、峰值内存、精度回归 |

### 6.2 再按工程约束筛选

1. 权重许可、训练数据说明和商业使用边界；
2. 输入分辨率、动态尺寸和位置编码实现；
3. 推理框架是否原生支持，是否需要自定义算子；
4. FP16/BF16/INT8 下的数值与精度回归；
5. 单图、多图、批处理的吞吐和峰值显存；
6. tokenizer、文本塔和预处理是否与 checkpoint 匹配；
7. 是否需要全局向量、patch token、中间层或多尺度输出。

## 7. 不同视觉塔如何公平比较

### 7.1 冻结骨干的探针

- 全局分类：线性 probe、k-NN、零样本分类（仅语言对齐模型）。
- 检索：图到文、文到图 Recall@K，固定候选库与文本处理。
- 稠密任务：冻结骨干 + 同一轻量 head 的分割、深度或对应评测。
- 鲁棒性：分辨率、裁剪、噪声、领域迁移和语言切片。

### 7.2 VLM 端到端比较

固定 LLM、连接器结构、视觉 token 上限、指令数据、训练步数和解码配置，只替换视觉塔。报告：

- VQA、OCR、图表、空间关系、计数和多图能力；
- 纯文本能力是否退化；
- 训练显存、收敛稳定性、首 token 与端到端延迟；
- 视觉 token 数和 KV 缓存；
- 每个数据切片的置信区间，而不只报平均分。

如果两个视觉塔使用不同分辨率、切片数或 token 预算，性能差异不是纯编码器效果。应另做“同计算预算”和“各自最佳配置”两组实验。

## 8. 常见误区与失败模式

1. **所有 VLM 都用 CLIP**：Flamingo、BLIP-2、LLaVA 是不同接口；DINOv2 和早期融合模型又是其他路线。
2. **更高 ImageNet 分数必然带来更强 VQA**：ImageNet、检索、OCR、空间推理的监督与评分不同。
3. **SigLIP 没有负样本**：非匹配 pair 仍承担负标签，只是不共享 softmax 分母。
4. **DINOv2 能直接文本检索**：它没有原生文本塔，需要另行对齐。
5. **Patch 越小越好**：token 数、显存和延迟会显著增加，且数据和位置编码必须匹配。
6. **冻结视觉塔没有损失**：冻结保护通用能力，也限制领域适配。
7. **连接器只改维度**：它还选择、压缩并重新组织视觉信息。
8. **跨论文参数表可直接排名**：数据、预处理、样本曝光量、文本塔和评测协议常不同。
9. **闭源模型行为足以反推视觉塔**：公开系统卡没有披露时，应标为未知。

## 9. 模型卡与上线检查表

- [ ] 记录完整 checkpoint ID、提交哈希、许可和来源。
- [ ] 使用与权重匹配的图像预处理和文本 tokenizer。
- [ ] 明确读取全局、patch、哪一层或哪些层的特征。
- [ ] 记录分辨率、patch 大小、token 数和位置编码处理。
- [ ] Connector 与视觉塔、LLM、训练阶段严格匹配。
- [ ] 检索阈值与零样本 prompt 在领域验证集上校准。
- [ ] 视觉、语言、OCR、稠密任务和安全切片分别回归。
- [ ] 评测集与训练/过滤数据做近重复泄漏检查。
- [ ] 报告延迟分布、峰值显存、吞吐和能耗环境，不只报参数量。
- [ ] 论文结果与生产 SLA 分开，未披露训练细节明确标记。
