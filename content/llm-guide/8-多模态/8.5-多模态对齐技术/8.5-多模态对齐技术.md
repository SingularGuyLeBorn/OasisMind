# 多模态对齐：从共享表征到生成式接口

“多模态对齐”不是单一算法。它可以指图像与文本在同一嵌入空间中可检索，也可以指视觉特征经过连接器后能被语言模型消费，还可以指模型学会依据图像生成文字、依据文本生成图像，或处理图文交错序列。不同目标需要不同数据、损失与评测，不能用一个 CLIP 相似度代表全部多模态能力。

> **证据与时效边界**：本文依据截至 2026-09-01 的原始论文、官方技术报告与官方仓库。对 GPT-4o、Gemini 等闭源模型，只陈述公开材料明确披露的输入输出能力与训练描述；视觉编码器、连接器、视觉 token 化和损失配方未公开时，不从产品行为反推内部结构。

## 1. 到底在对齐什么

| 对齐层次 | 学习对象 | 典型任务 | 不能由它直接证明 |
|---|---|---|---|
| 全局图文对齐 | 整图向量与整句向量 | 检索、零样本分类 | 物体位置、计数、文字识别 |
| 区域—短语对齐 | patch/区域与词或短语 | grounding、检测、指代表达 | 长链推理、可控生成 |
| 时序对齐 | 视频片段/音频帧与文本时间段 | 事件定位、字幕、语音识别 | 实时交互调度 |
| 表征—LLM 接口对齐 | 视觉表示与语言模型嵌入/注意力接口 | VQA、描述、视觉对话 | 视觉事实必然正确 |
| 生成分布对齐 | 条件模态与目标 token 序列 | 图像描述、图像/音频生成 | 跨模态检索天然优秀 |
| 指令与偏好对齐 | 多模态输入下的任务遵循和安全行为 | 助手、Agent、内容安全 | 底层视觉表征已细粒度对齐 |

实际系统常把多个层次叠加：先训练图文表示，再训练连接器，再做视觉指令微调，最后进行偏好与安全后训练。每一步解决的问题不同。

## 2. 五类架构接口

> 图 1：共享嵌入的相似度与训练目标、三种连续视觉连接器，以及连续/离散序列接口的边界。图中只表达公开论文可支持的概念关系，不代表 GPT-4o、Gemini 等闭源模型的未披露内部实现。

### 2.1 双塔共享嵌入

图像编码器 $f_I$ 和文本编码器 $f_T$ 分别输出归一化向量，再在共同维度比较相似度。CLIP、ALIGN 和 SigLIP 属于这一大类。双塔适合离线建索引和大规模检索，因为图像与文本可以独立编码；代价是编码阶段没有细粒度跨模态交互。

OpenAI CLIP 论文使用 4 亿图文对构造 WebImageText 训练集，这个数字只描述该论文设置，不是所有 CLIP checkpoint 的数据规模。[CLIP 原论文](https://arxiv.org/abs/2103.00020)

Google ALIGN 使用 18 亿噪声图文对研究规模化弱监督；论文并没有证明“数据越脏越好”，而是在特定过滤、模型和训练设置下比较规模与噪声。[ALIGN 官方研究介绍](https://research.google/blog/align-scaling-up-visual-and-vision-language-representation-learning-with-noisy-text-supervision/) · [原论文](https://arxiv.org/abs/2102.05918)

### 2.2 Patch token + 线性/MLP 投影器

视觉编码器输出 patch 序列 $H_V \in \mathbb{R}^{n_v \times d_v}$，投影器把通道维映射到语言模型维度：

$$
Z_V = P(H_V), \qquad Z_V \in \mathbb{R}^{n_v \times d_{\text{llm}}}.
$$

这是最直接的“视觉软 token”接口。它通常保留一个 patch 对应一个投影 token，结构简单、吞吐容易估算，但 token 数随图像网格、切片数或视频帧数增长。

原始 LLaVA 的第一阶段冻结视觉编码器与 LLM，只训练投影矩阵；第二阶段仍冻结视觉编码器，训练投影器与 LLM。这个配方是 LLaVA 论文的具体选择，不是所有 VLM 的统一规则。[LLaVA 原论文，第 4 页训练阶段](https://papers.nips.cc/paper_files/paper/2023/file/6dcf277ea32ce3288914faf369fe6de0-Paper-Conference.pdf)

详见 [LLaVA 架构](../8.2-视觉语言模型/8.2.1-LLaVA架构深度解析.md)。

### 2.3 查询器或重采样器

当视觉特征很多时，可以用固定数量的可学习查询从视觉网格中抽取信息：

$$
Z_Q = \operatorname{CrossAttention}(Q, H_V, H_V),
$$

其中查询数决定输出 token 上限。BLIP-2 的 Q-Former 连接冻结图像编码器和冻结 LLM，并分两阶段学习视觉—语言表征与视觉到语言的生成接口。[BLIP-2 原论文](https://arxiv.org/abs/2301.12597)

Flamingo 的 Perceiver Resampler 同样把可变数量的图像/视频特征压到固定数量的视觉输出，再通过插入语言模型的 gated cross-attention 使用这些特征；它不是简单把视觉 token 直接拼到文本前缀。[Flamingo 原论文](https://arxiv.org/abs/2204.14198)

查询器能控制语言模型看到的 token 数，但可能形成信息瓶颈。固定查询数是否足够取决于分辨率、物体密度、OCR、视频长度和任务，而不是越少越先进。详见 [Q-Former 与视觉 Token 压缩](../8.2-视觉语言模型/8.2.2-QFormer与视觉Token压缩.md)。

### 2.4 跨注意力注入

文本隐藏状态作为 query，视觉特征作为 key/value，跨注意力层被插入语言模型的若干位置。它允许每层或多层按当前文本状态读取视觉信息，适合图文交错和多图上下文；同时增加架构侵入性、KV 缓存与推理实现复杂度。

冻结原语言层再训练新增跨注意力层，可以减小语言能力漂移，但不等于视觉能力自然获得。对齐仍来自图文序列数据和生成目标。

### 2.5 离散跨模态 token 与早期融合

另一条路线把图像编码为离散 token，与文本 token 放进同一自回归序列。Chameleon 明确公开为 token-based mixed-modal early-fusion 模型，能够处理和生成交错图文；其结论只适用于公开的 Chameleon 配方。[Chameleon 原论文](https://arxiv.org/abs/2405.09818) · [官方仓库](https://github.com/facebookresearch/chameleon)

离散统一词表让图像理解与生成可共享序列建模接口，但会引入图像 tokenizer 失真、词表/采样平衡、超长序列和不同模态 token 竞争等问题。所谓“统一 token”不代表不同模态具有相同统计性质。

## 3. 对比对齐的两个基本目标

### 3.1 CLIP 的对称 softmax

给定 $N$ 对匹配图文，归一化嵌入为 $u_i, v_i$，可学习 logit scale 为 $s$。相似度 logits 为 $\ell_{ij}=s\,u_i^\top v_j$。CLIP 分别做图像到文本和文本到图像的 batch 内分类：

$$
\mathcal{L}_{\text{CLIP}}
= -\frac{1}{2N}\sum_{i=1}^{N}
\left[
\log\frac{e^{\ell_{ii}}}{\sum_j e^{\ell_{ij}}}
+
\log\frac{e^{\ell_{ii}}}{\sum_j e^{\ell_{ji}}}
\right].
$$

非对角 pair 在这个训练构造中作为候选负对，但其中可能存在语义相关、重复或多描述同图的“假阴性”。更大 batch 提供更多候选，不保证每个候选都是真负例，也不保证跨任务单调变好。

### 3.2 SigLIP 的逐对 sigmoid

SigLIP 保留双塔相似度，但用逐对二元目标替换全局 softmax 归一化。令 $y_{ij}=+1$ 表示正对，$y_{ij}=-1$ 表示所采样的负对，logit 为 $s_{ij}=t\,u_i^\top v_j+b$，一种论文式写法为：

$$
\mathcal{L}_{\text{SigLIP}}
= -\frac{1}{N}\sum_{i=1}^{N}\sum_{j=1}^{N}
\log \sigma(y_{ij}s_{ij}).
$$

关键变化是 pair 不再共享 softmax 分母，不是“不需要负样本”。是否跨设备交换特征、如何抽取负对和怎样归约损失属于实现选择。[SigLIP 原论文](https://arxiv.org/abs/2303.15343) · [Google `big_vision` 官方仓库](https://github.com/google-research/big_vision)

不能把两个不同 checkpoint 的 ImageNet headline 分数相减，再把差异全部归因于损失函数。要比较 CLIP 与 SigLIP 目标，必须尽量固定视觉塔、文本塔、数据、样本曝光量、分辨率和评测协议。

## 4. 对比损失之外的训练目标

| 目标 | 学到什么 | 常见盲区 |
|---|---|---|
| Image-Text Matching | 判断一对图文是否匹配 | 随机负例太容易；不等于区域定位 |
| 自回归文本生成 | 在视觉条件下预测回答/描述 token | 可生成流畅但视觉不忠实的答案 |
| Masked Language/Image Modeling | 用另一模态或上下文补全掩码 | 重建质量不等于下游交互能力 |
| 区域—短语/框损失 | 局部实体、区域与语言对应 | 标注昂贵，开放词表和遮挡困难 |
| OCR/文档目标 | 文字、布局与阅读顺序 | 自然图像能力未必同步提升 |
| 指令监督 | 按多模态任务格式回答 | 容易学习回答风格而不是视觉依据 |
| 偏好/安全后训练 | 有用性、拒答和交互边界 | 不能修复底层视觉信息已经丢失的问题 |

FLAVA 是结合单模态与多模态编码器、对比、匹配和掩码建模目标的具体研究系统。[FLAVA 原论文](https://arxiv.org/abs/2112.04482) Data2Vec 则是在视觉、语音和文本上复用自蒸馏思想的单模态统一框架；原论文并未建立图像—文本共享空间，因此不应把 Data2Vec 本身归为图文对齐方法。[Data2Vec 原论文](https://arxiv.org/abs/2202.03555)

## 5. 冻结与解冻策略

### 5.1 只训练连接器

适合快速验证接口、数据较少或希望保护现有单模态能力的阶段。优点是显存和优化状态较小；缺点是连接器只能重组已有视觉特征，无法找回视觉编码器未保留的信息。

### 5.2 连接器 + 语言模型

可以让语言模型学会消费视觉 token 和遵循视觉指令，但会增加语言能力漂移、灾难性遗忘和幻觉风险。需要混入高质量文本数据或做文本能力回归，而不能只看 VQA 分数。

### 5.3 解冻视觉编码器

适合领域图像与预训练分布差异大、需要 OCR/医学/遥感或细粒度视觉适配的场景。通常使用更小学习率、分层解冻、参数高效适配或保持对比/自监督辅助目标。完全解冻不是自动更优：数据量不足时可能破坏通用视觉表征。

### 5.4 分阶段决策表

| 观察到的问题 | 优先尝试 | 不应直接假设 |
|---|---|---|
| 回答格式不遵循 | 指令数据、解码与 LLM/adapter | 视觉编码器一定需要解冻 |
| 看不见小字/小物体 | 分辨率、切片、patch 特征、视觉塔适配 | 增加语言参数能恢复已丢失像素 |
| 多图 token 过多 | resampler、分层选择、缓存 | 固定压到极少 token 无损 |
| 检索强但问答弱 | 连接器与生成式训练 | CLIP 相似度等于 VQA 能力 |
| 文本能力下降 | 冻结更多语言层、混合文本回放 | 多模态分数提升没有代价 |

## 6. 连续视觉 token、离散 token 与生成式对齐

### 连续视觉 token

视觉编码器的 patch 或 query 表示被投影到语言模型隐藏维度。它们不是词表 ID，而是连续前缀或跨注意力记忆。训练通常最小化条件文本负对数似然：

$$
\mathcal{L}_{\text{gen}}
= -\sum_t \log p_\theta(y_t \mid y_{<t}, Z_V, x_{\text{instruction}}).
$$

这个目标训练模型在视觉条件下生成答案，但只在数据中被监督的内容上提供信号。若训练描述忽略背景、小物体或否定关系，模型可能学会语言先验而不是精确观察。

### 离散视觉 token

图像 tokenizer 把图像量化成代码本 ID，可与文本 token 共同进入自回归模型。优点是理解与生成接口统一；风险是量化丢失、图像 token 数大、不同模态损失尺度不平衡，以及视觉 token 的局部统计与文本 token 差异巨大。

### 闭源“原生多模态”的证据边界

OpenAI 的 GPT-4o System Card 公开称其为跨文本、视觉和音频端到端训练的 autoregressive omni model，但没有披露视觉 tokenizer、视觉编码器、连接器拓扑或完整损失配方。[GPT-4o System Card](https://openai.com/index/gpt-4o-system-card/)

Gemini 技术报告公开多模态能力及有限架构信息，但没有提供足够细节让外部复刻全部视觉 token 化和融合管线。[Gemini 1.0 Technical Report](https://deepmind.google/gemini/gemini_1_report.pdf) 因此本文不使用“它一定采用某种 patch 投影/共享词表/某种早期融合”的推测图。

交互时间轴和全双工系统另见 [Omni 与全双工](../8.7-Omni与全双工/8.7-Omni与全双工.md)；端到端训练声明不能替代实时调度、打断和延迟评测。

## 7. 数据决定模型能对齐到哪里

### 7.1 数据类型

- **图文对**：全局语义、检索和零样本分类；alt-text 常含噪声和网页上下文偏差。
- **交错图文文档**：跨多图、段落与顺序关系；清洗和文档泄漏控制更复杂。
- **描述、VQA 与指令数据**：生成式任务和交互格式；答案可能继承生成器偏差。
- **框、掩码、短语与时间段标注**：细粒度 grounding；标注成本高，类别覆盖有限。
- **OCR、图表与文档数据**：文字和布局；需要保留分辨率、阅读顺序和坐标。
- **视频/音频配对**：时序事件与语音；采样率、同步误差和版权边界重要。

视觉指令数据的构造、去重和泄漏控制见 [视觉指令微调数据工程](../8.2-视觉语言模型/8.2.3-视觉指令微调数据工程.md)。

### 7.2 质量控制

训练前至少检查：重复与近重复、图文是否同指一个实体、文字是否来自图中、语言与地域分布、敏感数据、版权/许可、成人和暴力内容、合成数据来源，以及评测集泄漏。

硬负例必须“难但确实为负”。把同一事件的另一张照片或同义描述误标为负例，会训练模型拆散本应接近的语义。多正例、软标签或去重是可选缓解手段，效果需在具体数据上验证。

## 8. 评测：按能力拆开测

| 能力 | 指标示例 | 报告时必须固定 |
|---|---|---|
| 图文检索 | Recall@K、mAP | 候选库、正例定义、去重、文本语言 |
| 零样本分类 | Top-1/Top-k | prompt 模板、类别名、分辨率、checkpoint |
| 区域/短语对齐 | IoU、mAP、pointing accuracy | 框/掩码定义、开放词表协议 |
| VQA/图表/OCR | exact match、ANLS、任务评分器 | 规范化规则、是否允许外部 OCR |
| 生成忠实度 | 对象/属性/关系错误、人评 | 采样参数、裁判与置信区间 |
| 多图/视频 | 时间定位、跨帧问答 | 帧采样、时长、视觉 token 预算 |
| 鲁棒性与安全 | 分布偏移、对抗文本、敏感属性 | 数据切片、拒答策略、人工复核 |

CLIP 检索强不代表 VQA、计数、空间关系或 OCR 强。完整 VLM 评测见 [VLM 的评测与基准](../8.2-视觉语言模型/8.2.5-VLM的评测与基准.md)。

跨论文 headline 只能作为线索。生产选型应在相同预处理、分辨率、连接器、语言模型、token 预算和推理设置下做 matched evaluation，并报告质量、吞吐、峰值显存和端到端延迟分布。

## 9. 常见失败模式

1. **全局语义压过局部事实**：场景类别正确，但数量、左右、颜色或小物体错误。
2. **语言先验替代观察**：模型给出常识化答案，却没有图像证据。
3. **连接器瓶颈**：固定少量 query 丢失密集页面、长视频或多图细节。
4. **分辨率与裁剪失真**：小字、细线、长宽比和边缘区域在预处理时消失。
5. **假阴性与错误图文对**：对比目标推开真实相关 pair，或把网页噪声学成语义。
6. **模态不平衡**：语言 token/损失占比过高，视觉梯度或视觉证据被忽略。
7. **指令微调遗忘**：视觉对话变好，但纯文本、检索或校准退化。
8. **评测泄漏**：互联网训练数据包含测试图、题目或近重复样本。
9. **安全迁移失败**：文本安全策略未覆盖图像中的提示注入和敏感信息。

## 10. 训练与上线验证清单

- [ ] 明确对齐层次，不用单一“多模态分数”替代能力拆分。
- [ ] 记录视觉塔、连接器、LLM、token 数和冻结策略版本。
- [ ] 对比、生成、定位、OCR 和指令数据的用途与采样比例可追溯。
- [ ] 图文去重、假阴性、泄漏、许可和敏感数据经过审计。
- [ ] 连接器输出 shape、位置编码和 attention mask 有单元测试。
- [ ] 冻结/解冻方案同时回归视觉、语言和检索能力。
- [ ] 评测固定预处理、prompt、分辨率和候选库。
- [ ] 生成答案要求视觉证据；高风险任务保留人工核验。
- [ ] 闭源模型未披露的组件明确标为未知，不用示意图补全猜测。
- [ ] 论文数字与生产 SLA 分开报告。
