# 6.4.3 · 旋转与数据无关 KV Cache 量化：QJL、PolarQuant 与 TurboQuant

长上下文推理会持续保存历史 token 的 Key 和 Value。低比特量化减少的是这部分运行时状态，而不是模型权重；它与 GQA、分页缓存、前缀共享等机制可以同时存在，但每种机制减少的维度不同。

QJL、两篇同名的 PolarQuant 和 TurboQuant 都使用了随机投影、旋转或极坐标表示，却不是同一个算法。它们优化的误差目标也不同：Key 参与 $QK^\top$ 和 softmax，对内积偏差与极端误差更敏感；Value 参与加权求和，通常更接近重构误差问题。因此，“K+V 双压缩”是一种存储策略，不能简单理解为给 Key 和 Value 套用完全相同的编码器。

## 1. 先建立统一的 KV 内存账本

设 batch 大小为 $B$，第 $\ell$ 个会生成 KV cache 的注意力层当前驻留 $T_\ell$ 个 token，KV head 数为 $H_{kv,\ell}$，每个 head 的维度为 $d_\ell$，Key 和 Value 的存储位宽分别为 $w_K$、$w_V$。未压缩缓存的主体大小为：

$$
M_{\text{raw}}
=
B\sum_{\ell\in\mathcal A}
T_\ell H_{kv,\ell}d_\ell
\frac{w_K+w_V}{8}.
\tag{1}
$$

$\mathcal A$ 只包含真正按 token 保存 KV 的层。标准 Transformer 各层参数相同时，式（1）化为：

$$
M_{\text{raw}}
=
BTLH_{kv}d_h\frac{w_K+w_V}{8}.
\tag{2}
$$

容量公式使用 $H_{kv}$：MHA 中等于 $H_q$，GQA 中小于 $H_q$，MQA 中通常为 1。

若 Key、Value 分别以 $b_K$、$b_V$ bit/coordinate 保存，则理想化的编码主体为：

$$
M_{\text{code}}
=
B\sum_{\ell\in\mathcal A}
T_\ell H_{kv,\ell}d_\ell
\frac{b_K+b_V}{8}
+M_{\text{meta}}+M_{\text{align}}.
\tag{3}
$$

$M_{\text{meta}}$ 包括每向量或每组的范数、scale、zero point、残差范数等；$M_{\text{align}}$ 包括 bit packing、页块和内存对齐产生的空隙。码本、旋转矩阵和随机投影矩阵通常由多层或多 token 共享，属于静态开销，不应重复计入每个 token。

忽略元数据时，BF16/FP16 的 K、V 同时降到 4 bit，主体压缩上限是 $16/4=4$ 倍。实际容量依据框架的 packed slot 大小计算，名义位宽只描述式（3）的编码主体。

例如，一个 $L=32$、$H_{kv}=8$、$d_h=128$ 的标准 GQA 模型，在 $B=1$、$T=131072$、K/V 均为 16 bit 时，式（2）给出 16 GiB；若 K/V 编码主体均为 4 bit，则主体为 4 GiB，之后还要加上式（3）中的元数据和对齐开销。

### 1.1 非标准注意力如何记账

- **滑动窗口注意力**：令 $T_\ell$ 等于该层实际保留的窗口长度，而不是请求的总上下文长度。
- **混合注意力或线性注意力**：只对全注意力层计算增长型 KV cache；递归状态、卷积状态等按各自布局单独计量。
- **MLA**：缓存的是低秩 latent 与位置相关状态，不再符合标准 $K/V$ head 张量模型，应使用模型和后端定义的原生缓存布局。
- **分页缓存与前缀共享**：式（1）描述逻辑载荷；进程级显存还取决于实际驻留页、共享前缀、碎片和调度预留。

## 2. QJL：面向内积的 1-bit 随机估计器

[QJL](https://arxiv.org/abs/2406.03482) 是独立提出的 Quantized Johnson–Lindenstrauss 变换。取元素独立服从 $\mathcal N(0,1)$ 的随机矩阵 $S\in\mathbb R^{m\times d}$。对 Key 向量 $k\in\mathbb R^d$，QJL 只保存 $m$ 个符号位：

$$
\mathcal H_S(k)=\operatorname{sign}(Sk)\in\{-1,+1\}^m.
\tag{4}
$$

Query 保持未量化。对任意 $q\in\mathbb R^d$，论文使用非对称内积估计器：

$$
\widehat{\langle q,k\rangle}_{\text{QJL}}
=
\frac{\sqrt{\pi/2}}{m}\lVert k\rVert_2
\left\langle Sq,\mathcal H_S(k)\right\rangle.
\tag{5}
$$

该估计器在对随机矩阵取期望时无偏：

$$
\mathbb E_S\left[
\widehat{\langle q,k\rangle}_{\text{QJL}}
\right]
=\langle q,k\rangle.
\tag{6}
$$

论文还给出高概率误差界：当 $m$ 随 $\varepsilon^{-2}\log(1/\delta)$ 增长时，内积误差以至少 $1-\delta$ 的概率不超过 $\varepsilon\lVert q\rVert_2\lVert k\rVert_2$。这里的“无偏”仍是对随机性取期望的性质，不表示单次量化没有误差。Key cache 除 $m$ 个符号位外还要保存 $\lVert k\rVert_2$；softmax 后的端到端误差需要单独分析。把 QJL 代入式（3）时，Key 的有效主体位宽是 $b_K=m/d$，Key 范数计入 $M_{\text{meta}}$。

QJL 原论文对 Value 使用常规的 token-wise 量化。TurboQuant 则把 QJL 用于 MSE 量化后的残差，并在该构造中取 $m=d$；当前 vLLM 的 TurboQuant 后端又有意省略了 QJL。三种组合需要分开理解。

## 3. 两篇 PolarQuant 的方法边界

2025 年出现了两篇题名相近、都称为 PolarQuant 的工作。第三方仓库 `polarquant-kv` 又复用了这个名称，因此仅写“PolarQuant”不足以确定算法。

| 标识 | 处理对象 | 核心表示 | 实现来源 |
|:---|:---|:---|:---|
| Han 等，arXiv:2502.02617 | KV 向量 | 随机预处理后进行递归极坐标变换，量化角度并保存最终半径 | [论文](https://arxiv.org/abs/2502.02617) |
| Wu 等，arXiv:2502.00527 | post-RoPE Key cache | 按 RoPE 的二维通道对编码半径与角度，用查表计算 Query–Key 内积 | [论文](https://arxiv.org/abs/2502.00527) · [作者仓库](https://github.com/ericshwu/PolarQuant) |
| `hilllief/polarquant-kv` | 仓库自述的 K+V 缓存 | 随机旋转、范数与 Lloyd–Max 码本的社区组合实现 | [社区仓库](https://github.com/hilllief/polarquant-kv) |

### 3.1 Han 等人的递归极坐标量化

该方法先用随机投影或随机旋转预处理 KV 向量，再递归地把笛卡尔坐标转换为角度与半径。对 $d$ 为 2 的幂的向量，递归变换生成 $d-1$ 个角度和一个最终半径：底层处理二维坐标对，上层继续合并前一层得到的半径。

随机预处理使各层角度具有可解析的集中分布，因而可以预先构造角度码本，减少传统分组量化中逐组保存 min/max 或 scale/zero point 的需求。论文的理论分析使用高斯随机 sketch；其实用实现采用随机正交矩阵以精确保留范数和内积。理论分布针对前一种随机性假设，固定旋转后的真实数据仍需检查经验分布。

这篇工作面向完整 KV cache，量化对象是递归极坐标中的角度与半径，而不是 TurboQuant 的“旋转坐标 + 标量质心 + QJL 残差”。

### 3.2 Wu 等人的 post-RoPE Key 量化

RoPE 会成对旋转通道。Wu 等人的 PolarQuant 以这些二维通道对为基本单元，把 post-RoPE Key 表示成量化半径和角度，缓解少数通道离群值对逐坐标量化的影响。解码时，Query–Key 内积可以改写为关于半径、Query 和角度码的查表计算。

该方法的主体针对 Key cache，Value 可另配量化方法；K+V 的完整方案需要同时写明两侧编码器。其 Key 编码也独立于 TurboQuant 的球面坐标 Beta 码本和 QJL 残差编码。

### 3.3 社区实现 `polarquant-kv`：随机旋转与 Lloyd–Max

`hilllief/polarquant-kv` 将自身描述为 TurboQuant 的社区复现与 K+V 扩展，其 README 中的 PQ4 主要由随机正交旋转、向量范数、4-bit Lloyd–Max 索引和自定义 kernel 组成。它属于第三方工程实现，与两篇 PolarQuant 的作者仓库及 TurboQuant 论文实现分开引用。

仓库中的 Qwen2.5-0.5B、RTX 5060 Ti、token 匹配率和 kernel 时延属于该版本、该环境下的项目自测，可用于复现其工程取舍。通用压缩率、质量和端到端性能仍需论文级或框架级多模型评测。

## 4. TurboQuant：旋转、MSE 量化与 QJL 残差

[TurboQuant](https://arxiv.org/abs/2504.19874) 是一个数据无关的在线向量量化框架。论文分别构造了面向重构 MSE 的量化器 $Q_{\text{mse}}$，以及面向无偏内积估计的量化器 $Q_{\text{prod}}$。

### 4.1 随机旋转后的坐标分布

对固定单位向量 $x\in\mathbb S^{d-1}$ 和随机 Haar 正交矩阵 $\Pi$，$u=\Pi x$ 在球面上均匀分布。任一坐标的密度为：

$$
f_d(t)=
\frac{\Gamma(d/2)}{\sqrt{\pi}\,\Gamma((d-1)/2)}
(1-t^2)^{(d-3)/2},
\qquad -1\leq t\leq 1.
\tag{7}
$$

高维时，单个坐标近似服从 $\mathcal N(0,1/d)$。这个结论描述的是固定 $x$ 对随机 $\Pi$ 的分布；共享一次旋转后，真实 KV 数据的经验分布不必严格等于式（7）。

### 4.2 MSE 量化器

给定每坐标 $b$ bit，论文针对式（7）预计算 $2^b$ 个 Lloyd–Max 质心：

$$
\mathcal C_b
=
\arg\min_{c_1,\ldots,c_{2^b}}
\mathbb E_{X\sim f_d}
\left[
\min_j(X-c_j)^2
\right].
\tag{8}
$$

编码时保存 $\Pi x$ 每个坐标最近质心的索引；解码时查表恢复旋转域向量，再乘 $\Pi^\top$ 回到原坐标系。式（8）定义全局目标；工程代码使用迭代数值求解，结果依赖初始化与收敛条件。

对单位向量，论文给出的 MSE 上界为：

$$
\mathbb E\lVert x-\hat x\rVert_2^2
\leq
\frac{\sqrt 3\pi}{2}\,4^{-b}.
\tag{9}
$$

论文同时证明：对任意随机向量量化算法，都存在单位球面上的困难输入，使期望 MSE 至少为 $4^{-b}$。因此式（9）的最坏情形上界在约 2.7 的常数因子内接近该下界。实际 KV 向量还需保存范数或使用等价的 norm correction。

### 4.3 面向内积的 TurboQuant

MSE 最小并不保证内积估计无偏。TurboQuant 在总预算为 $b$ bit/coordinate 时，用 $b-1$ bit 的 $Q_{\text{mse}}$ 编码主体，再对残差使用 1-bit QJL。令：

$$
\hat x_{\text{mse}}
=Q_{\text{mse}}^{-1}(Q_{\text{mse}}(x)),
\qquad
r=x-\hat x_{\text{mse}},
\qquad
q=\operatorname{sign}(Sr),
\qquad
\gamma=\lVert r\rVert_2.
\tag{10}
$$

解码结果为：

$$
\hat x
=
\hat x_{\text{mse}}
+
\frac{\sqrt{\pi/2}}{d}\gamma S^\top q.
\tag{11}
$$

这里的 QJL 符号向量占总预算中的 1 bit/coordinate：$Q_{\mathrm{mse}}$ 使用其余 $b-1$ bit。残差范数 $\gamma$ 等标量元数据仍需进入式（3）的实际账本。

### 4.4 Key 与 Value 的组合方式

TurboQuant 是通用向量量化器，应用到 KV cache 时应分别选择目标：

- Key 的直接误差会进入 $QK^\top$，可使用面向内积的估计器，或在工程实现中使用较高位宽的 MSE/FP8 Key。
- Value 的误差在线性加权和中传播，常使用 MSE 型或均匀低比特量化。
- K/V 位宽不必相同；应分别记录 $b_K$、$b_V$，再由式（3）计算 packed storage。
- QJL、范数修正、首尾层保护和离群通道混合位宽均属于具体实现配置，应随检查点和后端一并记录。

论文在特定模型和 LongBench、Needle-in-a-Haystack 设置下报告了低位 KV cache 结果；迁移到其他模型、上下文长度、采样设置和任务时需要重新评测。

## 5. 当前 vLLM 实现与论文算法的差异

vLLM 已提供 TurboQuant KV cache 后端和多个 `--kv-cache-dtype` 预设。当前[稳定版配置文档](https://docs.vllm.ai/en/stable/api/vllm/model_executor/layers/quantization/turboquant/)中，3/4-bit MSE Key 先做 Walsh–Hadamard 旋转并使用 Lloyd–Max；`turboquant_k8v4` 的 FP8 Key 跳过旋转与 MSE 量化。Value 使用均匀量化，K/V 打包进每个 head、每个 position 的联合 slot。

vLLM 文档还说明，这条 Key 工程路径的核心模式源自 DRIVE/EDEN，与 scalar HIGGS 等价；其早期 KV-cache 应用见 *Cache Me If You Must*。`TurboQuant` 后端名称描述当前集成接口，不代表这些基础算子均由 TurboQuant 论文首次提出。

vLLM 实现 MSE/FP8 工程路径，未实现 $Q_{\text{prod}}$ 的 QJL 残差。常见预设包括：

| 预设 | Key | Value | norm correction |
|:---|:---|:---|:---|
| `turboquant_k8v4` | FP8 | 4 bit | 否 |
| `turboquant_4bit_nc` | 4-bit MSE | 4 bit | 是 |
| `turboquant_k3v4_nc` | 3-bit MSE | 4 bit | 是 |
| `turboquant_3bit_nc` | 3-bit MSE | 3 bit | 是 |

实际每个 slot 的大小由 `key_packed_size + value_packed_size + padding` 决定。vLLM 的[注意力后端文档](https://docs.vllm.ai/en/stable/api/vllm/v1/attention/backends/turboquant_attn/)给出的逻辑布局为：

$$
(\text{num\_blocks},\ \text{block\_size},\ \text{num\_kv\_heads},\ \text{slot\_size\_aligned}).
\tag{12}
$$

容量规划直接采用框架给出的 `slot_size_aligned`，再乘 block、KV head 和 position 数量。

**v0.20.2 评估。** vLLM 项目在 0.20.2 版本上进行的[多模型评估](https://github.com/vllm-project/vllm-project.github.io/blob/main/_posts/2026-05-11-turboquant.md)给出两个重要工程边界：

1. 该 CUDA 实现压缩的是存储，计算注意力前仍会反量化到 BF16；低位缓存因此不等同于低位 Tensor Core 注意力。
2. 4-bit 配置体现的是容量、质量、延迟和吞吐之间的折中；更激进的 3-bit 配置在长上下文检索和推理任务上可能出现明显退化。反量化也会增加单 token 延迟并降低吞吐，但在缓存容量已经成为排队瓶颈时，更多可并发请求可能改善突发负载的 TTFT。

该评估只覆盖标准注意力模型，并注明滑动窗口和混合注意力在 v0.20.2 时尚未支持。

**当前上游 CUDA 后端。** 截至 2026-09-01，[注意力后端特性矩阵](https://docs.vllm.ai/en/latest/design/attention_backends/)列出的 TurboQuant CUDA 路径支持 FP16/BF16、四种现有 KV dtype、block size 16/32/64/128 与 decoder attention。attention sink、non-causal attention、multimodal prefix 和 DCP 尚未列入支持项，MLA 也未列入该后端。当前[混合模型配置逻辑](https://docs.vllm.ai/en/latest/api/vllm/model_executor/layers/quantization/turboquant/config/)可以识别混合层，并把 TurboQuant 路由到其中的 full-attention 层。可用组合仍以部署 commit 的特性矩阵和运行时检查为准。

**当前 Metal 后端。** [vLLM Metal 文档](https://docs.vllm.ai/projects/vllm-metal/en/latest/turboquant/)要求启用 paged attention（`VLLM_METAL_USE_PAGED_ATTENTION=1`），FWHT Metal kernel 只支持 `head_dim` 为 64、128 或 256。混合模型中仅标准 SDPA 层会被压缩，GDN 线性注意力的递归状态保持 FP16；MLA 尚未支持。CUDA 与 Metal 的 kernel、层路由和限制需要分别核对。

## 6. 按误差来源选择编码方案

旋转型 KV 量化是否值得使用，取决于内存是否真的是服务瓶颈，以及低位误差能否通过目标工作负载验证。

- **Key 精度优先**：长上下文检索、工具调用和长链推理对注意力分数敏感，可先从 FP8/INT8 Key 与低位 Value 开始，再逐步降低 Key 位宽。
- **极低内存优先**：同时压缩 K/V 能扩大缓存容量，但需分别评估 Key 引起的 softmax 排序变化和 Value 重构误差。
- **希望直接加速 $QK^\top$**：检查实现是否提供压缩域查表或融合 kernel。完整反量化路径的主要收益是缓存容量；压缩域查表或融合 kernel 才可能提升算术吞吐。
- **混合注意力或 MLA**：先确认哪些状态按 token 增长、哪些层被后端实际压缩，再建立逐层账本。
