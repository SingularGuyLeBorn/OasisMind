# 投机采样与 EAGLE 系列：从原理到 EAGLE-1/2/3 实现

> 本文系统介绍投机采样(Speculative Decoding)原理, 以及 EAGLE-1/2/3 如何利用目标模型内部特征训练轻量草稿模型, 实现高质量 token 推测. 

---

## 1. 投机采样原理

### 1.1 研究动机

LLM 推理慢的两个核心原因：
1. **自回归串行**：生成 $n$ 个 token 需跑 $n$ 次大模型
2. **算力未充分利用**：受限于内存带宽和通信, GPU 算力未用满

**关键观察**：
- 很多 token 的预测并不难, 小模型也能猜得不错
- 可通过增加并行计算来提升速度

### 1.2 算法框架

投机采样由两个模型组成：

| 组件 | 描述 | 特点 |
|:-----|:-----|:-----|
| 目标模型 $M_p$ | 原始大模型 | 准确率高, 推理慢 |
| 草稿模型 $M_q$ | 参数量极小的模型 | 推理极快, 准确率较低 |

**流程**：
1. 草稿模型一次性推测出 $K$ 个 token
2. 目标模型**并行验证**这 $K$ 个 token
3. 接受或拒绝推测的 token
4. 从接受位置继续下一轮

### 1.3 数学保证

**关键性质**：投机采样的输出概率分布与直接使用目标模型生成的概率分布**完全一致**. 

> 注意：这里的一致性是指经过 temperature、top-k、top-p、argmax 等采样方法处理后的概率分布, 不是模型 LmHead 层输出的原始 logit 分布.

## 2. 传统方法的局限

### 2.1 对独立草稿模型的依赖

- 需要额外训练/维护一个独立的草稿模型
- 草稿模型与目标模型之间存在**分布差异**
- 接受率受限于草稿模型质量

### 2.2 特征利用不足

- 草稿模型无法利用目标模型已计算的内部特征
- 重复计算造成资源浪费

---

## 3. EAGLE 系列改进

### 3.1 EAGLE-1：利用目标模型特征

**核心创新**：不再使用独立草稿模型, 直接利用目标模型内部特征训练轻量草稿模型. 

**优势**：
- 草稿模型可以访问目标模型的隐藏状态
- 候选 token 质量显著提升
- 接受率大幅提高

### 3.2 EAGLE-2：动态草图长度

- 根据当前上下文动态调整推测长度
- 在简单区域推测更多 token
- 在复杂区域减少推测长度

### 3.3 EAGLE-3：多轮推测与树形验证

- 引入树形解码结构
- 多分支并行推测
- 更高效的验证机制

### 3.4 2026-08 修订：EAGLE-2 才是动态树，EAGLE-3 是训练时测试（不删上文）

§3.2 / §3.3 把两代写反了。EAGLE-2（arXiv:2406.16858）才是 **上下文感知动态草稿树**：用草稿置信度近似接受率，扩展阶段只长全局最高的节点，起草结束再剪枝；验证用树注意力一次扫整棵树。EAGLE-3（[arXiv:2503.01840](https://ar5iv.labs.arxiv.org/html/2503.01840)）**沿用这棵树**，并不另做「上下文分类器」。它改的是草稿 **怎么训、吃什么特征**：

- 丢掉 $l_{\mathrm{fea}}$，直接预测 token，否则扩训练数据时第 1 步接受率涨、第 2 步崩。
- 训练时测试：把草稿自己的输出 $a$ 喂回下一步，模拟推理时「还没有目标 $g$」的输入。
- 输入从「只复用 LM Head 前一层」改成低/中/高三层拼接再 FC。草稿核心是一层 decoder，不是上文「轻量投影层」能概括的。
- 论文加速比最高约 6.5×、相对 EAGLE-2 约 1.4×；SGLang batch 64 吞吐约 1.38×。§5 表里的 3–5× / 4–5× **不是**这篇论文的表。

图与公式展开在 [6.6.2 修订节](./6.6.2-投机解码.md)。K3 把预训练 MTP 微调成这种 draft，损失是 $\mathcal{L}_{\mathrm{LK}}=-\log\sum_x\min(p,q)$，见 [2.4.6](../../../2-核心原理与架构/2.4-前沿架构与变体/2.4.6-多Token预测MTP深度解析.md)。

## 4. EAGLE 的实现要点

### 4.1 特征复用

```python
# 概念示意：利用目标模型最后一层隐藏状态
hidden_states = target_model.get_hidden_states(input_ids)
draft_logits = draft_head(hidden_states)  # 轻量投影层
```

### 4.2 训练策略

- 以目标模型的输出为监督信号
- 仅在特定层接入草稿头
- 冻结目标模型参数

### 4.3 推理流程

1. 目标模型前向传播, 获取隐藏状态
2. 草稿头基于隐藏状态推测未来 $K$ 个 token
3. 目标模型并行验证
4. 接受部分 token, 从接受位置继续

## 5. 性能对比

| 方法 | 加速比 | 草稿模型开销 | 接受率 |
|:-----|:-------|:------------|:-------|
| 传统投机采样 | 2-3× | 高(独立模型)| 中 |
| EAGLE-1 | 3-4× | 低(共享特征)| 高 |
| EAGLE-2 | 3-5× | 低 | 高(自适应)|
| EAGLE-3 | 4-5× | 低 | 很高(树形)|

上表是 2025 提纲数字。EAGLE-3 论文自己报的是最高约 6.5×、相对 EAGLE-2 约 1.4×（batch 1），以及 SGLang batch 64 约 1.38× 吞吐；树形验证属于 EAGLE-2 起就有的机制。

---

## 6. 总结

EAGLE 系列的核心价值：
- **消除独立草稿模型**：降低部署复杂度
- **特征复用**：提升候选 token 质量
- **自适应/树形扩展**：进一步提升接受率和加速比

**适用场景**：
- 自回归解码是瓶颈的在线服务
- 批处理大小较小的交互式应用
- 对延迟敏感的实时生成任务
