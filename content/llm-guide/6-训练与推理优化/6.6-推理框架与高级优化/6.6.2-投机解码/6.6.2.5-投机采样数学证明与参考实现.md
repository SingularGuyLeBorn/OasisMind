# 6.6.2.5 · 投机采样：数学证明与参考实现

投机采样允许草稿模型先生成候选，再由目标模型批量验证。候选接受时直接提交，首次拒绝时从修正分布补回缺失的概率质量。只要验证阶段使用草稿器实际采样的提议分布 $q$，最终输出便严格服从目标分布 $p$。下文从单步等价推到完整序列，并给出包含采样变换、EOS、长度预算和 KV cache 回滚的参考实现。

不同草稿器的结构见 [投机解码总览](./6.6.2-投机解码.md)、[EAGLE 系列](./6.6.2.1-投机采样与EAGLE系列.md)、[DFlash](./6.6.2.2-DFlash原理解析.md)、[DFlash2](./6.6.2.3-DFlash2原理解析.md) 与 [DSpark](./6.6.2.4-DSpark原理解析.md)。

## 1. 先把 $p$ 与 $q$ 定义准确

给定已经确认的 token 前缀 $h$，设：

- $p_h(v)$：目标模型在前缀 $h$ 下指定的采样分布；
- $q_h(v)$：草稿器在同一前缀下**实际用来产生候选的提议分布**；
- $\mathcal V$：两者可以逐 token 对齐的共同输出空间。

这里的 $p_h,q_h$ 指温度、top-k、top-p、重复惩罚、禁用 token、语法约束等变换完成后，实际进入采样器的归一化分布；两者可以采用不同的采样策略。证明只要求：

1. 候选 $Y$ 确实从保存下来的 $q_h$ 抽取；
2. 验证使用同一前缀下的 $p_h$ 和这个实际 $q_h$；
3. 两个分布位于同一 token 空间。

草稿模型不必与目标模型同架构、同规模或同模型家族，两个分布也不必使用相同温度。本页参考实现假设二者共享 token ID 空间。跨 tokenizer 方法需要额外构造目标 token 空间上的精确提议分布；直接拿不同 tokenizer 的 token ID 相除没有数学意义，也不适用本文的单 token 代码。

为简化记号，本页在固定前缀时写作 $p(v),q(v)$。

## 2. 一轮传统投机采样

草稿器自回归地产生至多 $K$ 个候选：

$$
Y_i\sim q_i(\cdot\mid h,Y_{<i}),\qquad i=1,\ldots,K.
$$

目标模型对 $h,Y_1,\ldots,Y_K$ 做一次块验证，得到 $K+1$ 个条件分布：

$$
p_i(\cdot)=p(\cdot\mid h,Y_{<i}),\quad i=1,\ldots,K+1.
$$

其中 $p_{K+1}$ 是“所有候选都接受后，下一个 token”的分布。随后从左到右验证每个候选。对第 $i$ 个候选独立抽取

$$
U_i\sim\operatorname{Uniform}[0,1),
$$

并按下式接受：

$$
U_i<a_i(Y_i),\qquad
a_i(v)=\min\left(1,\frac{p_i(v)}{q_i(v)}\right).
$$

这里的随机性来自独立 uniform，**不是**让目标模型再采样一次并检查两个 token 是否相同。

一轮只有两种出口：

1. **首次拒绝发生在位置 $j$**：提交 $Y_1,\ldots,Y_{j-1}$，丢弃 $Y_j,\ldots,Y_K$，再从

   $$
   r_j(v)=\frac{[p_j(v)-q_j(v)]_+}{\sum_z[p_j(z)-q_j(z)]_+}
   $$

   抽取一个 correction token，然后结束本轮。

2. **全部 $K$ 个候选被接受**：提交全部候选，再从验证前向已经算出的 $p_{K+1}$ 抽取一个 bonus token，然后结束本轮。

因此，在不考虑 EOS 与长度上限提前截断时，一轮至少输出 1 个、最多输出 $K+1$ 个 token。

## 3. 单步分布等价的严格证明

固定前缀 $h$，令候选 $Y\sim q$。接受函数为

$$
a(v)=\min\left(1,\frac{p(v)}{q(v)}\right).
$$

由于只有 $q(v)>0$ 的 token 才可能从 $q$ 被抽到，所以候选路径上的比值有定义。token $v$ 经“提议并接受”输出的概率质量是

$$
\Pr(Y=v,\text{accept})
=q(v)a(v)
=\min(p(v),q(v)).
$$

总拒绝概率为

$$
\begin{aligned}
\rho
&=\sum_v q(v)(1-a(v))\\
&=\sum_v[q(v)-p(v)]_+\\
&=1-\sum_v\min(p(v),q(v))\\
&=\sum_v[p(v)-q(v)]_+\\
&=\frac12\lVert p-q\rVert_1.
\end{aligned}
$$

最后一个等式就是总变差距离 $D_{\mathrm{TV}}(p,q)$。两个正剩余质量相等，是因为 $\sum_v p(v)=\sum_v q(v)=1$。

若 $\rho>0$，拒绝后使用的修正分布为

$$
r(v)=\frac{[p(v)-q(v)]_+}{\rho}.
$$

于是 token $v$ 经拒绝分支输出的概率质量为

$$
\Pr(\text{reject})r(v)=[p(v)-q(v)]_+.
$$

合并接受与拒绝两条互斥路径：

$$
\begin{aligned}
\Pr(X=v)
&=\min(p(v),q(v))+[p(v)-q(v)]_+\\
&=p(v).
\end{aligned}
$$

所以最终 token $X\sim p$。草稿器只影响拒绝概率 $\rho$，不改变输出分布。

两个退化情形也包含在上述分布中。

**$q(v)=0$**：该 token 不会由草稿器提议，因此不会计算 $p(v)/q(v)$。若 $p(v)>0$，这部分概率质量位于 $[p-q]_+$ 中，可通过 correction 分支输出。若程序声称“从 $q$ 抽到了 $q(v)=0$ 的 token”，说明保存概率、采样变换或数值精度不一致，应当报错而不是静默除零。

**修正分布的归一化常数为 0**：此时 $\rho=0$，进而 $p=q$，拒绝事件在精确算术下不可能发生。工程实现仍应处理浮点退化；常见的保守兜底是记录异常并直接从 $p$ 采样，但这属于数值容错，不是证明的一部分。

## 4. 为什么多 token 序列仍然精确

单步证明需要在每个**实际可达的条件前缀**上重复使用。第 $i$ 个位置的分布随已经接受的候选 $Y_{<i}$ 变化：

$$
p_i(\cdot)=p(\cdot\mid h,Y_{<i}),\qquad
q_i(\cdot)=q(\cdot\mid h,Y_{<i}).
$$

可以把一轮算法看成“单步耦合核 + 递归预计算”。按剩余草稿深度归纳：

1. 在前缀 $h$ 上，第一输出 token 的“接受质量 + correction 质量”严格合成 $p_1(\cdot\mid h)$；
2. 若第一候选被接受，剩余 $K-1$ 个候选在真实前缀 $h,Y_1$ 上构成同一种问题；按归纳假设，其后续输出服从目标条件分布；
3. 若第一候选被拒绝，correction 已恢复 $p_1$，本轮结束；下一轮从真实 correction 前缀继续，不能使用建立在被拒绝候选上的后缀；
4. 递归到最后一个候选时，若它也被接受，bonus 直接从 $p_{K+1}(\cdot\mid h,Y_{1:K})$ 采样，构成归纳基的普通目标采样。

要注意：只看“候选被接受”这一内部事件，接受 token 的条件分布正比于 $\min(p,q)$，并不单独等于 $p$；必须把 correction 路径的剩余质量一起计入。对外部只可见的已提交序列汇总全部内部路径后，每个下一 token 才在其已提交历史条件下服从目标分布。由概率链式法则，重复多轮直到 EOS 或长度上限，最终序列分布与直接从目标模型自回归采样相同。

这也解释了“首次拒绝后必须丢弃整个草稿后缀”：后缀分布条件于被拒绝的 $Y_j$，而 correction 得到的是另一个实际历史，二者不能混用。

## 5. 接受长度与一轮产出

令 $A\in\{0,1,\ldots,K\}$ 表示一轮中连续接受的草稿 token 数。对任意非负整数变量都有尾和公式：

$$
\mathbb E[A]=\sum_{i=1}^{K}\Pr(A\ge i).
$$

精确地说，

$$
\Pr(A\ge i)
=\mathbb E_{Y_{1:i}\sim q}
\left[
\prod_{j=1}^{i}
\min\left(1,\frac{p_j(Y_j)}{q_j(Y_j)}\right)
\right],
$$

其中每个 $p_j,q_j$ 都条件于同一条草稿前缀 $h,Y_{<j}$。没有独立同分布假设时，不能直接把它写成某个固定接受率的幂。

若为了分析而假设：每个已到达位置的平均接受概率都是常数 $\alpha$，且位置间满足论文采用的独立同分布近似，则

$$
\Pr(A\ge i)=\alpha^i,
$$

从而

$$
\mathbb E[A]
=\sum_{i=1}^{K}\alpha^i
=\frac{\alpha(1-\alpha^K)}{1-\alpha},\qquad \alpha\ne1.
$$

无终止截断时，首次拒绝会补一个 correction，全部接受会补一个 bonus，所以一轮产出 token 数 $\tau$ 恒满足

$$
\tau=A+1,
\qquad
\mathbb E[\tau]=1+\mathbb E[A]
=\sum_{i=0}^{K}\alpha^i
=\frac{1-\alpha^{K+1}}{1-\alpha}.
$$

当 $\alpha=1$ 时，$\mathbb E[A]=K$，$\mathbb E[\tau]=K+1$。EOS 或 `max_new_tokens` 在本轮中提前终止时，实际产出会被截短，因此不能再直接套用 $\tau=A+1$。这些公式描述的是目标模型串行调用次数的潜在减少，不等于硬件上的固定加速倍数；真实延迟还取决于草稿成本、块验证成本、batch、上下文长度、缓存和 kernel。

单个位置的平均接受率可以直接写成总变差距离。固定前缀 $h$，有

$$
\beta_h
=\mathbb E_{Y\sim q_h}[a_h(Y)]
=\sum_v\min(p_h(v),q_h(v))
=1-D_{\mathrm{TV}}(p_h,q_h).
$$

所以提高接受率等价于减少实际采样分布之间的总变差距离，而不只是让两个模型的 argmax 更一致。

## 6. 三 token 数值走查

设词表 $\mathcal V=\{A,B,C\}$：

| token | 草稿分布 $q$ | 目标分布 $p$ | 接受概率 $\min(1,p/q)$ |
|---|---:|---:|---:|
| $A$ | 0.5 | 0.6 | 1 |
| $B$ | 0.3 | 0.2 | $2/3$ |
| $C$ | 0.2 | 0.2 | 1 |

若草稿抽到 $B$，再抽到 $U=0.8$，因为 $0.8>2/3$，所以拒绝。修正质量是

$$
[p-q]_+=(0.1,0,0),
$$

归一化后 $r=(1,0,0)$，correction 必为 $A$。

不依赖某次随机结果，完整输出概率可按两条路径核对：

| token | 提议并接受 $\min(p,q)$ | 拒绝后修正 $[p-q]_+$ | 合计 |
|---|---:|---:|---:|
| $A$ | 0.5 | 0.1 | 0.6 |
| $B$ | 0.2 | 0 | 0.2 |
| $C$ | 0.2 | 0 | 0.2 |

合计恰好恢复 $p=(0.6,0.2,0.2)$。

## 7. 采样变换如何进入 $p$ 与 $q$

接受率与 correction 使用的不是原始 logits，而是实际进入采样器的分布。计算顺序为：

1. 目标原始 logits 经过目标采样策略，得到 $p_i$；
2. 草稿原始 logits 经过草稿采样策略，得到 $q_i$；
3. 候选从 $q_i$ 采样，并保存**完整 $q_i$** 或足以无损重建它的数据；
4. 接受率用该候选位置上的 $p_i(Y_i)/q_i(Y_i)$；
5. correction 用同一位置的完整 $[p_i-q_i]_+$。

只保存候选 token 的一个标量 $q_i(Y_i)$ 足够计算接受率，却不足以构造 correction。拒绝后临时重算 $q_i$ 也可能因随机处理器、浮点路径或状态更新不同而不再是实际提议分布。

重复惩罚、频率惩罚、禁词表、语法约束等处理器依赖历史，因此也是生成状态的一部分。验证第 $i$ 个候选时，目标和草稿处理器都要读取准确的前缀 $h,Y_{<i}$；处理器若维护可变状态，也要像 KV cache 一样按接受前缀提交或回滚。

greedy/argmax 可表示为只在 argmax token 上取 1 的退化分布。这样仍可使用同一证明：目标 argmax 之外的草稿候选接受概率为 0，correction 回到目标 argmax。greedy 下的 token 相等比较是这一退化分布的特例，随机采样仍需使用接受率与修正分布。

第 8 节参考代码采用 `token mask/banned → temperature → top-k → softmax → top-p → renormalize` 的顺序；`temperature=0` 时在 mask 后直接返回 greedy 退化分布，不再执行 top-k/top-p。top-k 截断使用分数阈值，因此边界并列时可能保留超过 $k$ 个 token。这是该参考策略的确定语义。接入现有框架时，需要复刻框架实际的 processor 顺序、并列处理与归一化路径，并保存最终进入采样器的 $p_i,q_i$。

## 8. 可执行的正确性参考实现

下面的 PyTorch 参考实现以“给定任意历史返回下一 token 原始 logits”的函数为模型接口，使用 CPU float64 做采样算术，并为每个条件前缀重新计算 logits。它用于验证概率控制流，不提供实际加速；高性能系统可把第 9 节的块验证与事务式 KV cache 接口接入同一状态机。

```python
from __future__ import annotations

from collections.abc import Callable
from dataclasses import dataclass

import torch


LogitsFn = Callable[[torch.Tensor], torch.Tensor]


@dataclass(frozen=True)
class SamplingPolicy:
    temperature: float = 1.0
    top_k: int | None = None
    top_p: float | None = None
    banned_token_ids: tuple[int, ...] = ()


def _normalise(weights: torch.Tensor) -> torch.Tensor:
    weights = weights.detach().to(device="cpu", dtype=torch.float64).flatten()
    if torch.isnan(weights).any() or torch.isinf(weights).any():
        raise ValueError("概率权重包含 NaN 或 Inf")
    if (weights < 0).any():
        raise ValueError("概率权重不能为负")
    total = weights.sum()
    if total <= 0:
        raise ValueError("概率质量必须大于 0")
    return weights / total


def transformed_distribution(
    raw_logits: torch.Tensor,
    policy: SamplingPolicy,
) -> torch.Tensor:
    """把本次使用的采样变换折叠成一个归一化分布。"""
    logits = raw_logits.detach().to(device="cpu", dtype=torch.float64).flatten().clone()
    if torch.isnan(logits).any() or torch.isposinf(logits).any():
        raise ValueError("logits 包含 NaN 或 +Inf")

    for token_id in policy.banned_token_ids:
        if not 0 <= token_id < logits.numel():
            raise ValueError(f"banned token id 越界: {token_id}")
        logits[token_id] = -torch.inf

    if torch.isneginf(logits).all():
        raise ValueError("采样约束屏蔽了整个词表")

    # temperature=0 表示 greedy，并显式转换成退化分布。
    if policy.temperature == 0:
        probs = torch.zeros_like(logits)
        probs[torch.argmax(logits)] = 1.0
        return probs
    if policy.temperature < 0:
        raise ValueError("temperature 不能为负")

    logits /= policy.temperature

    if policy.top_k is not None:
        if policy.top_k <= 0:
            raise ValueError("top_k 必须为正整数")
        k = min(policy.top_k, logits.numel())
        cutoff = torch.topk(logits, k).values[-1]
        logits[logits < cutoff] = -torch.inf

    probs = torch.softmax(logits, dim=-1)

    if policy.top_p is not None:
        if not 0 < policy.top_p <= 1:
            raise ValueError("top_p 必须位于 (0, 1]")
        if policy.top_p < 1:
            sorted_probs, sorted_ids = torch.sort(probs, descending=True)
            cumulative = torch.cumsum(sorted_probs, dim=-1)
            # 保留使累计质量首次达到 top_p 的那个 token。
            keep = cumulative - sorted_probs < policy.top_p
            keep[0] = True
            filtered = torch.zeros_like(probs)
            filtered[sorted_ids[keep]] = sorted_probs[keep]
            probs = _normalise(filtered)

    return _normalise(probs)


def corrected_distribution(
    p: torch.Tensor,
    q: torch.Tensor,
) -> torch.Tensor:
    """计算 norm([p-q]+)；仅精确零残差使用不可达分支的兜底。"""
    p = _normalise(p)
    q = _normalise(q)
    if p.numel() != q.numel():
        raise ValueError("p 与 q 必须位于同一词表")
    residual = torch.clamp(p - q, min=0.0)
    mass = residual.sum()
    if float(mass) == 0.0:
        # p=q 时拒绝事件的概率为零，修正分布不会被访问。
        # 生产实现若实际进入该分支，应记录数值异常。
        return p
    return residual / mass


def acceptance_probability(p_y: float, q_y: float) -> float:
    if q_y <= 0:
        raise ValueError("从 q 采到的 token 必须满足 q(y)>0；请检查概率保存路径")
    if p_y <= 0:
        return 0.0
    return min(1.0, p_y / q_y)


def should_accept(uniform: float, alpha: float) -> bool:
    if not 0.0 <= uniform < 1.0:
        raise ValueError("uniform 必须位于 [0, 1)")
    if not 0.0 <= alpha <= 1.0:
        raise ValueError("alpha 必须位于 [0, 1]")
    return uniform < alpha


def sample_token(probs: torch.Tensor, generator: torch.Generator) -> int:
    probs = _normalise(probs)
    return int(torch.multinomial(probs, 1, generator=generator).item())


def _append(history: torch.Tensor, token_id: int) -> torch.Tensor:
    return torch.cat([history, torch.tensor([token_id], dtype=torch.long)])


def speculative_generate_reference(
    prompt_ids: torch.Tensor,
    draft_logits_fn: LogitsFn,
    target_logits_fn: LogitsFn,
    *,
    max_new_tokens: int,
    eos_token_id: int | None,
    gamma: int,
    draft_policy: SamplingPolicy = SamplingPolicy(),
    target_policy: SamplingPolicy = SamplingPolicy(),
    seed: int = 0,
) -> torch.Tensor:
    """正确性优先的传统双模型投机采样，不使用 KV cache。"""
    if max_new_tokens < 0:
        raise ValueError("max_new_tokens 不能为负")
    if gamma < 0:
        raise ValueError("gamma 不能为负")

    output = prompt_ids.detach().to(device="cpu", dtype=torch.long).flatten().clone()
    prompt_length = output.numel()
    rng = torch.Generator(device="cpu").manual_seed(seed)

    target_vocab_size = target_logits_fn(output).numel()
    draft_vocab_size = draft_logits_fn(output).numel()
    if target_vocab_size <= 0 or draft_vocab_size != target_vocab_size:
        raise ValueError("目标与草稿 logits 必须使用同一非空词表")
    if eos_token_id is not None and not 0 <= eos_token_id < target_vocab_size:
        raise ValueError("eos_token_id 超出共同词表范围")

    def target_dist(history: torch.Tensor) -> torch.Tensor:
        return transformed_distribution(target_logits_fn(history), target_policy)

    def draft_dist(history: torch.Tensor) -> torch.Tensor:
        return transformed_distribution(draft_logits_fn(history), draft_policy)

    while output.numel() - prompt_length < max_new_tokens:
        remaining = max_new_tokens - (output.numel() - prompt_length)

        # 只剩一个位置或 gamma=0 时，直接做一次目标采样。
        # 其他情况预留一个位置给 correction 或 bonus，避免越过长度预算。
        draft_budget = min(gamma, max(0, remaining - 1))
        if draft_budget == 0:
            token = sample_token(target_dist(output), rng)
            output = _append(output, token)
            if eos_token_id is not None and token == eos_token_id:
                break
            continue

        # Draft：保存每个位置实际用于采样的完整 q_i。
        draft_tokens: list[int] = []
        q_distributions: list[torch.Tensor] = []
        draft_history = output.clone()
        for _ in range(draft_budget):
            q_i = draft_dist(draft_history)
            token = sample_token(q_i, rng)
            q_distributions.append(q_i)
            draft_tokens.append(token)
            draft_history = _append(draft_history, token)
            if eos_token_id is not None and token == eos_token_id:
                break

        # Verify：正确性参考版逐前缀计算 p_1,...,p_{K+1}。
        # 高性能实现应在一次块前向中返回完全相同的这些分布。
        p_distributions: list[torch.Tensor] = []
        target_history = output.clone()
        last_draft_is_eos = (
            eos_token_id is not None and draft_tokens[-1] == eos_token_id
        )
        # 草稿以 EOS 结束时不会产生 bonus，无需请求 EOS 之后的分布。
        target_distribution_count = len(draft_tokens) + (0 if last_draft_is_eos else 1)
        for i in range(target_distribution_count):
            p_distributions.append(target_dist(target_history))
            if i < len(draft_tokens):
                target_history = _append(target_history, draft_tokens[i])

        all_accepted = True
        for i, token in enumerate(draft_tokens):
            p_i = p_distributions[i]
            q_i = q_distributions[i]
            if p_i.numel() != q_i.numel():
                raise ValueError("目标与草稿分布必须位于同一词表")

            alpha = acceptance_probability(float(p_i[token]), float(q_i[token]))
            uniform = float(torch.rand((), generator=rng, dtype=torch.float64))
            # torch.rand 可能精确返回 0；使用严格小于可保证 alpha=0 时永不接受。
            if should_accept(uniform, alpha):
                output = _append(output, token)
                if eos_token_id is not None and token == eos_token_id:
                    return output
                continue

            # 首次拒绝：丢弃尚未提交的草稿后缀，并输出一个 correction。
            correction = sample_token(corrected_distribution(p_i, q_i), rng)
            output = _append(output, correction)
            all_accepted = False
            if eos_token_id is not None and correction == eos_token_id:
                return output
            break

        if all_accepted:
            # p_{K+1} 已由验证阶段算出，不需要额外目标模型前向。
            bonus = sample_token(p_distributions[len(draft_tokens)], rng)
            output = _append(output, bonus)
            if eos_token_id is not None and bonus == eos_token_id:
                return output

    return output
```

若还有自定义 logits processor，应让 `draft_logits_fn`、`target_logits_fn` 返回处理器作用后的 logits，或扩展 `transformed_distribution`。候选采样、接受比和 correction 必须使用同一个实际 $q_i$。

## 9. 生产 KV cache 的事务式控制流

下面的伪代码把模型状态定义为 `{kv_state, processor_state, next_logits, cached_prefix_len}`。事务同时覆盖 KV 与有状态 logits processor；`next_logits` 明确对应 `cached_prefix_len` 所表示的前缀。不同框架可以使用不同的 cache layout、paged block allocator 与 attention backend，但要保持相同的提交与回滚语义。

```text
assert configured_K >= 0
draft_state  = draft.prefill(prompt)   # 复合状态：KV、processor、next logits、长度
target_state = target.prefill(prompt)
assert draft_state.cached_prefix_len == len(prompt)
assert target_state.cached_prefix_len == len(prompt)
assert EOS is NONE or 0 <= EOS < target_state.vocab_size

draft_pending  = []
target_pending = []

while not finished:
    # 把上轮已经提交、但尚未进入模型状态的 token 依次前向。
    draft_state  = draft.advance_many(draft_pending, draft_state)
    target_state = target.advance_many(target_pending, target_state)
    draft_pending.clear()
    target_pending.clear()

    h = committed_tokens
    assert draft_state.cached_prefix_len == len(h)
    assert target_state.cached_prefix_len == len(h)

    remaining = max_new_tokens - (len(h) - prompt_length)
    if remaining <= 0:
        finish()
        break

    if remaining == 1 or configured_K == 0:
        emitted = sample(target_state.next_distribution)
        committed_tokens.append(emitted)
        if emitted == EOS or len(committed_tokens) - prompt_length == max_new_tokens:
            finish()
        else:
            draft_pending.append(emitted)
            target_pending.append(emitted)
        continue

    # 草稿最多占 remaining-1 个位置，为 correction 或 bonus 保留一个位置。
    K_cap = min(configured_K, remaining - 1)
    draft_tx  = draft.begin_transaction(draft_state)
    target_tx = target.begin_transaction(target_state)

    # q[i] 是实际变换后的完整提议分布。
    # draft_cached_count 表示 tx 中已经物化 KV/processor 状态的候选数；
    # 典型自回归 drafter 采出 Y_K 时可能只物化到 Y_{K-1}。
    draft_tokens, q, draft_cached_count, draft_tx = draft.propose_autoregressively(
        prefix=h,
        state=draft_tx,
        max_candidates=K_cap,
        stop_at_eos=True,
    )
    K = len(draft_tokens)

    if K == 0:
        draft.rollback(draft_tx)
        target.rollback(target_tx)
        emitted = sample(target_state.next_distribution)
        committed_tokens.append(emitted)
        if emitted == EOS or len(committed_tokens) - prompt_length == max_new_tokens:
            finish()
        else:
            draft_pending.append(emitted)
            target_pending.append(emitted)
        continue

    # target_tx 物化全部 K 个候选的状态，并返回 p[1:K] 与可选 p_bonus。
    p, p_bonus_if_needed, target_tx = target.verify_block(
        prefix=h,
        draft_tokens=draft_tokens,
        state=target_tx,
    )
    assert len(p) == len(q) == K
    assert 0 <= draft_cached_count <= K
    for i in 1..K:
        assert len(p[i]) == len(q[i]) == target_state.vocab_size
        assert 0 <= draft_tokens[i] < target_state.vocab_size

    A = 0
    for i in 1..K:
        if Uniform[0, 1) < min(1, p[i][draft_tokens[i]] / q[i][draft_tokens[i]]):
            A += 1
            if draft_tokens[i] == EOS:
                finished = true
                break
        else:
            emitted = sample(norm([p[i] - q[i]]+))   # correction
            break

    if A == K and not finished:
        emitted = sample(p_bonus_if_needed)           # bonus

    # 两个模型的事务都提交到各自已经物化的接受前缀。
    draft_commit_count = min(A, draft_cached_count)
    draft_state = draft.commit_prefix(draft_tx, draft_tokens[1..draft_commit_count])
    target_state = target.commit_prefix(target_tx, draft_tokens[1..A])

    committed_tokens.extend(draft_tokens[1..A])
    if finished:
        continue

    committed_tokens.append(emitted)
    if emitted == EOS or len(committed_tokens) - prompt_length == max_new_tokens:
        finished = true
        continue

    # 草稿器可能还欠最后几个已接受候选的状态；随后再消费 correction/bonus。
    draft_pending.extend(draft_tokens[draft_commit_count+1..A])
    draft_pending.append(emitted)
    target_pending.append(emitted)
```

缓存实现的关键不变量是**缓存中的 token 身份与已提交历史一致**：

- 首次拒绝前的 $A$ 个草稿 token 可以提交；KV 与 processor 状态按同一前缀提交；
- 被拒绝 token 和所有后缀都必须失效；
- correction 的 KV 必须由 correction 本身重新计算；
- 全接受时，目标模型通常已有全部草稿 KV；草稿器若只物化到 $Y_{K-1}$，会先补算 $Y_K$，再消费 bonus；
- EOS 或长度预算终止后，不再为了“补齐 $A+1$”生成额外 token；
- paged KV 系统应提交接受页、释放或归还拒绝页，不能只改逻辑长度而泄漏物理块。

复合状态中的 `cached_prefix_len` 与 `next_logits` 共同定义接口契约：前者说明 KV 和 processor 已推进到哪个前缀，后者说明下一 token 分布条件于哪个前缀。输出序列可以暂时领先模型状态，领先部分按顺序保存在 pending 队列中。

## 10. 性质测试

性质测试覆盖分布恒等式、退化概率、EOS 和长度预算。下面的 `pytest` 片段直接复用第 8 节函数。

```python
import torch


def exact_one_step_law(p: torch.Tensor, q: torch.Tensor) -> torch.Tensor:
    p = _normalise(p)
    q = _normalise(q)
    accepted_mass = torch.minimum(p, q)
    rejection_mass = torch.clamp(q - p, min=0).sum()
    correction = corrected_distribution(p, q)
    return accepted_mass + rejection_mass * correction


def test_random_distributions_recover_target_exactly():
    rng = torch.Generator().manual_seed(7)
    for _ in range(1_000):
        p = _normalise(torch.rand(31, generator=rng, dtype=torch.float64))
        q = _normalise(torch.rand(31, generator=rng, dtype=torch.float64))
        actual = exact_one_step_law(p, q)
        assert torch.allclose(actual, p, atol=1e-12, rtol=1e-12)


def test_disjoint_support_always_corrects_to_target():
    p = torch.tensor([1.0, 0.0])
    q = torch.tensor([0.0, 1.0])
    assert torch.equal(exact_one_step_law(p, q), p.to(torch.float64))


def test_equal_distributions_have_unreachable_rejection_branch():
    p = torch.tensor([0.2, 0.3, 0.5])
    q = p.clone()
    rejection_mass = torch.clamp(_normalise(q) - _normalise(p), min=0).sum()
    assert rejection_mass == 0
    # 数值兜底仍返回一个合法目标分布。
    assert torch.allclose(corrected_distribution(p, q), _normalise(p))


def test_tiny_positive_residual_is_not_replaced_by_target_distribution():
    p = torch.tensor(
        [0.5000000000000001, 0.4999999999999999], dtype=torch.float64
    )
    q = torch.tensor([0.5, 0.5], dtype=torch.float64)
    correction = corrected_distribution(p, q)
    assert torch.equal(correction, torch.tensor([1.0, 0.0], dtype=torch.float64))
    assert torch.allclose(exact_one_step_law(p, q), p, atol=1e-15, rtol=0)


def test_q_zero_is_allowed_off_proposal_support_but_not_for_sampled_token():
    p = torch.tensor([1.0, 0.0])
    q = torch.tensor([0.0, 1.0])
    # q=0 的目标质量由 correction 恢复。
    assert torch.equal(corrected_distribution(p, q), p.to(torch.float64))
    try:
        acceptance_probability(p_y=1.0, q_y=0.0)
    except ValueError:
        pass
    else:
        raise AssertionError("声称采到 q(y)=0 的 token 时必须失败")


def _constant_logits(token_id: int, vocab_size: int = 4):
    def logits_fn(_history: torch.Tensor) -> torch.Tensor:
        logits = torch.full((vocab_size,), -torch.inf, dtype=torch.float64)
        logits[token_id] = 0.0
        return logits
    return logits_fn


def test_eos_stops_without_bonus():
    eos = 3
    result = speculative_generate_reference(
        torch.tensor([0]),
        _constant_logits(eos),
        _constant_logits(eos),
        max_new_tokens=8,
        eos_token_id=eos,
        gamma=4,
    )
    assert result.tolist() == [0, eos]


def test_correction_eos_stops_immediately():
    eos = 3
    result = speculative_generate_reference(
        torch.tensor([0]),
        _constant_logits(1),
        _constant_logits(eos),
        max_new_tokens=8,
        eos_token_id=eos,
        gamma=1,
    )
    assert acceptance_probability(p_y=0.0, q_y=1.0) == 0.0
    assert should_accept(uniform=0.0, alpha=0.0) is False
    assert result.tolist() == [0, eos]


def test_bonus_eos_stops_immediately():
    eos = 3

    def target_logits(history: torch.Tensor) -> torch.Tensor:
        return _constant_logits(1 if history.numel() == 1 else eos)(history)

    result = speculative_generate_reference(
        torch.tensor([0]),

def test_max_new_tokens_is_never_exceeded_when_all_drafts_accept():

    probs = transformed_distribution(logits, SamplingPolicy(top_p=0.6))

    assert torch.allclose(probs, expected)
```

块验证与 KV 实现可以用下列测试矩阵覆盖融合后的状态路径：

| 场景 | 断言 |
|---|---|
| 给无 cache 版与 KV 版注入相同的 categorical 抽样结果和 uniform 序列 | 两者逐步提交相同 token，并在同一候选位置接受或拒绝 |
| 在每个候选位置强制首次拒绝 | 下一轮 KV 中只保留拒绝前的接受前缀，correction 在该位置重新计算 KV |
| accepted EOS、correction EOS、bonus EOS | 命中 EOS 后立即终止，不再提交候选或 bonus |
| 剩余预算为 $1,2,\ldots,K+1$ | 输出长度不越界，实际草稿块长按预算缩短 |
| 目标与草稿采用不同温度、top-k、top-p 和 token mask | 接受率与 correction 使用各自最终的 $p_i,q_i$，processor 状态按实际前缀推进 |
| 有状态 processor 在候选后缀上发生更新后，前部位置拒绝 | processor 与 KV 回滚到同一接受前缀，下一轮得到与直接前向相同的分布 |
| `configured_K=0` 或 drafter 返回空候选块 | 回滚临时事务，执行一步普通目标采样 |
| 整块接受，但 drafter 只物化到 $Y_{K-1}$ | 草稿 pending 队列依次消费 $Y_K$ 与 bonus，目标 pending 队列只消费 bonus |
| 目标/草稿词表大小不一致、EOS 越界或候选 ID 越界 | 在计算接受率之前显式报错 |
| 随机小词表枚举或大样本频率测试 | 输出频率在设定容差内逼近目标分布 $p$ |
