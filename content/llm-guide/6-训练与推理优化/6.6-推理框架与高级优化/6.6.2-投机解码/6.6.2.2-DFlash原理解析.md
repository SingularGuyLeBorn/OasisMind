# 6.6.2.2 · DFlash：块扩散并行草稿

DFlash 用一个已验证 token 作为锚点，在其后放置多个 mask，并通过一次轻量草稿前向同时预测未来 token。冻结目标模型的多层上下文特征会持续注入草稿网络，以提高非自回归草稿的候选质量；目标模型随后用一次前向验证整组候选。

共同的接受—校正规则见 [6.6.2.5 投机采样数学证明与参考实现](./6.6.2.5-投机采样数学证明与参考实现.md)。下一篇 [6.6.2.3 DFlash2](./6.6.2.3-DFlash2原理解析.md) 在 DFlash 主干上加入局部动态卷积与前驱条件候选选择器。

## 1. DFlash 要消除哪段串行路径

标准投机解码用草稿模型逐 token 生成 $K$ 个候选，再由目标模型一次验证。若一次草稿前向耗时为 $t_d$，草稿阶段近似需要 $Kt_d$；目标模型虽然一次验证多个位置，端到端周期仍受草稿串行链限制。

DFlash 直接构造一个长度为 $B$ 的掩码块：

$$
\underbrace{[a,m_1,\ldots,m_{B-1}]}_{B\text{ 个块位置}}
\xrightarrow{\text{one draft forward}}
\{q_1,\ldots,q_{B-1}\}.
\tag{1}
$$

$a$ 是上一周期由目标模型确认的锚点 token，$m_k$ 是 mask token。草稿 token 数为 $B-1$。各位置的词表分布在同一次 Transformer 前向中产生，草稿主干的时延由一次块前向代替 $B-1$ 次 token 前向。

“块扩散”在这里表示一次掩码块去噪。DFlash 推理没有多轮扩散时间步；每个周期由一次草稿前向和一次目标验证前向组成。

为便于逐位置比较，下面使用已验证前缀“我爱”和 16 个待预测槽位。按式（1）的记号，这个教学例对应 $B=17$；公开名称中的 `b16` 通常表示 16 个块位置，即 1 个锚点和 15 个草稿 token。

```text
位置：x1 x2 x3 x4 x5 x6 x7 x8 x9 x10 x11 x12 x13 x14 x15 x16
目标：人  工  智  能  ，  因  为  它  能   帮   助   我   的   生   活   。
```

DFlash 把锚点“爱”、16 个 mask 槽位和目标模型的上下文特征送入草稿 Transformer，一次得到 $h_1,\ldots,h_{16}$，再由共享 LM head 一次产生 16 份词表 logits。每个位置随后独立选择 token：x6 不会等待 x5 的逗号已经被选中，x7 也不会读取 x6 最终选出的“因”。假设 x6 的 top-1 是“它”、第二名是“因”，x7 的 top-1 是“为”，草稿路径便会包含“它→为”；目标模型验证到 x6 时停止接受，并给出自己的校正 token。

这个例子同时体现 DFlash 的优势与限制：重型草稿主干只运行一次，但同一次前向中的隐藏状态交互不等于读取前一位置已经选出的 token。DFlash2 与 DSpark 后来采用不同方法补充这种条件依赖。

## 2. 目标模型特征如何进入草稿网络

只依靠 token 前缀的小型掩码网络容易受容量限制。DFlash 冻结目标模型，从多个深度抽取上下文隐藏状态。设被选择的目标层为 $l_1,\ldots,l_s$，论文实验取 $s=5$，则融合特征为

$$
\mathbf H_t=\operatorname{RMSNorm}
\left(W_c[\mathbf H^{(l_1)};\ldots;\mathbf H^{(l_s)}]\right).
\tag{2}
$$

$W_c$ 将拼接后的目标隐藏状态投影到草稿维度。融合结果由所有草稿层共享。第 $i$ 个草稿层以草稿状态产生 Query，并把目标特征与草稿状态同时放入 Key、Value：

$$
\begin{aligned}
\mathbf Q_i &= W_i^Q\mathbf H_d,\\
\mathbf K_i &= [W_i^K\mathbf H_t;W_i^K\mathbf H_d]_{\mathrm{seq}},\\
\mathbf V_i &= [W_i^V\mathbf H_t;W_i^V\mathbf H_d]_{\mathrm{seq}}.
\end{aligned}
\tag{3}
$$

目标特征作为额外 KV 项参与注意力，不经过草稿层的 Query、输出投影和 FFN。已投影的目标特征随已验证前缀写入草稿 KV cache；下一周期只追加新提交 token 的特征，从而复用历史计算。

这条设计同时解决两个问题：

1. 草稿网络直接读取目标模型的多层语义表示，减轻小模型重新编码长前缀的压力；
2. 目标特征进入每个草稿层的注意力，条件信息不会只停留在输入层。

## 3. 块内非因果注意力

mask 位置之间可以双向交换隐藏表示，因此同一次前向中的后部位置能够读取前部 mask 的中间状态。第 $k$ 个输出分布仍未显式读取已经采样出的 $y_{k-1}$：所有 unary logits 先同时算出，之后才从各位置分布形成候选路径。

这一区别解释了 DFlash 的并行性。块内注意力建立的是隐藏状态依赖，标准自回归草稿建立的是已选 token 依赖。DFlash2 后来增加候选选择器，正是为了在保留一次主干前向的同时，把已选前驱 token 显式带回路径选择。

## 4. 训练：随机锚点与稀疏块掩码

训练数据包含 prompt 与目标模型生成的 response。目标模型对干净序列提取上下文特征并保持冻结。每个 epoch 从 response 中随机选择若干锚点；第 $j$ 个锚点及其后 $B-1$ 个目标 token 形成

$$
\mathcal B_j=(y_{a_j},y_{a_j+1},\ldots,y_{a_j+B-1}).
\tag{4}
$$

输入保留 $y_{a_j}$，后续位置替换为 mask。多个训练块可拼接进同一序列，注意掩码满足三条约束：

- 同一块内的 mask 位置可以双向交互；
- 不同训练块之间互相隔离；
- 每个块只读取截至本块锚点的目标上下文特征。

第三条约束决定因果正确性。若 mask 能读到对应标签位置或更晚位置的干净目标隐藏状态，训练目标会泄漏未来信息。

论文固定每条长序列采样的锚点数量，以控制训练成本；不同 epoch 重新采样，使训练逐步覆盖更多上下文位置。

## 5. 位置加权交叉熵

草稿块的第一个错误会截断后续连续接受前缀，因此前部位置对平均接受长度的影响更大。DFlash 使用指数衰减权重

$$
w_k=\exp\!\left(-\frac{k-1}{\gamma}\right),
\qquad k=1,\ldots,B-1,
\tag{5}
$$

并最小化

$$
\mathcal L_{\mathrm{DFlash}}
=-\sum_j\sum_{k=1}^{B-1}
w_k\log q_\theta(y_{a_j+k}\mid C_j),
\tag{6}
$$

其中 $C_j$ 表示稀疏注意允许读取的锚点、已验证前缀与目标上下文特征。论文对 block size 16、10、8 分别报告 $\gamma=7,5,4$；迁移到其他模型和块长时需要重新拟合接受长度与计算成本。

DFlash 与目标模型共享 token embedding 和 LM head，并在训练中冻结这两部分；冻结目标模型的参数也不参与优化。共享头保证草稿 logits 与目标词表对齐，同时使草稿检查点绑定特定目标模型、tokenizer 和隐藏层接口。

## 6. 一个完整推理周期

初始 prefill 后，目标模型给出首个已确认 token 及其目标层特征。随后每个周期执行：

1. 将最新已确认 token 放入锚点槽，其后填充 $B-1$ 个 mask embedding；
2. 草稿网络一次处理整个块，产生各位置 unary logits；
3. 运行时从这些分布形成候选序列；
4. 目标模型一次验证候选块；
5. 贪心模式提交连续匹配前缀，采样模式按 $\min(1,p/q)$ 接受并在首次拒绝处从 $[p-q]_+$ 校正；
6. 整块接受时，目标模型的下一位置分布可再产生一个 bonus token；
7. 目标 KV、草稿 KV 与目标特征缓存只推进到实际提交的前缀。

缓存裁剪与概率校正同样重要。被拒绝的草稿后缀不能进入下一周期的有效 KV 长度；EOS、最大生成长度和请求取消也会截断草稿与 bonus 的提交。

## 7. 块长、接受长度与实际时延

设一次周期的草稿时间与验证时间分别为 $T_{\mathrm{draft}}$、$T_{\mathrm{verify}}$，平均每周期提交 token 数为 $\tau$，则平均 token 时延为

$$
L=\frac{T_{\mathrm{draft}}+T_{\mathrm{verify}}}{\tau}.
\tag{7}
$$

DFlash 把草稿主干从多轮 token 前向改为一次块前向，但块长仍会影响注意力、LM head、临时张量、目标验证和无效后缀比例。较大的 $B$ 同时提高潜在接受长度与验证浪费；并发、量化、attention backend 和调度策略会改变最优块长。

DFlash 论文的 Transformers 主实验使用 H200；SGLang 服务表使用单张 B200 与 FlashAttention 4；vLLM 附录另有对应配置。论文中的吞吐和加速数字只对应各表指定的模型、硬件、后端、块长、并发和生成长度。

## 8. 与相邻方法的边界

| 方法 | 草稿路径 | 块内依赖 | 主干前向次数 |
|---|---|---|---|
| EAGLE-3 | 目标多层特征与已采样 token 的特征自回归 | 已选 token/特征逐步进入下一轮 | 多轮 |
| DFlash | 目标多层特征 KV 注入与掩码块 | 同次前向的隐藏状态交互 | 一次 |
| DFlash2 | DFlash 主干、局部卷积、候选路径选择 | 隐藏状态局部传播与已选前驱 token | 一次主干前向，加短路径遍历 |
| DSpark | 并行主干、顺序 Markov 校正与置信度调度 | 前驱 token 校正词表分布 | 一次主干前向，加顺序校正 |
| MTP | 目标模型内置多 token 预测模块 | 由训练时的多预测深度或预测头决定 | 取决于模型实现 |

## 9. DFlash 的收益、局限与下一步

DFlash 的收益来自一次关键改写：草稿模型不再逐 token 重复前向，而是在一个掩码块中同时计算多个位置，并用目标模型的多层特征补足上下文。只要一次生成的候选路径足够准确，目标模型便能在一次验证中连续接受多个 token，草稿阶段的串行等待也随之减少。

这种并行方式仍有一个结构性取舍。所有位置的 unary logits 在选出任何草稿 token 之前就已经算好，后一个位置不能根据前一个位置最终选中的 token 调整自己的选择。由此产生第一类问题：**正确候选已经存在，却没有被选中**。在“我爱”的例子中，x6 的 top-$K$ 已经包含“因”，但独立 top-1 选择了“它”；x7 又独立选择“为”，于是路径变成不连贯的“它→为”。问题不在候选召回，而在缺少前驱条件的候选排序。

第二类问题发生得更早：**正确 token 没有进入候选集**。随着位置向块尾推进，top-$K$ recall 逐渐下降，正确 token 可能从候选集中消失。此时无论怎样重排候选都无法恢复正确路径。增加草稿层数可以改善块尾表示，却会同时增加参数量和每个 draft–verify 周期的计算成本。

因此，后续改进需要分别处理两个阶段：在候选已经存在时，利用已选前驱 token 重新判断相邻候选是否连贯；在候选生成之前，加强相邻槽位之间的局部信息传播，减缓块尾候选质量下降。[DFlash2](./6.6.2.3-DFlash2原理解析.md)保留 DFlash 的一次主干前向，用前驱条件候选选择器针对前一问题，再用局部双抽头动态深度卷积缓解后一问题。
