# 6.6.2 · 投机解码

本页建立投机解码的共同数学与方法全景。EAGLE 的特征草稿与动态树见 [6.6.2.1](./6.6.2.1-投机采样与EAGLE系列.md)，DFlash 与 DFlash2 分别见 [6.6.2.2](./6.6.2.2-DFlash原理解析.md) 和 [6.6.2.3](./6.6.2.3-DFlash2原理解析.md)，DSpark 的半自回归草稿与置信度调度见 [6.6.2.4](./6.6.2.4-DSpark原理解析.md)，完整证明与参考实现见 [6.6.2.5](./6.6.2.5-投机采样数学证明与参考实现.md)。

## 1. 演进脉络与技术演进

自回归生成的数学结构将 $T$ 个 token 的联合概率分解为 $T$ 个条件概率的乘积：

$$
P(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, x_2, \ldots, x_{t-1}) \tag{1}
$$

该分解式暴露了 LLM 推理的核心约束：位置 $t$ 的采样结果通常要成为位置 $t+1$ 的输入，因此生成 $T$ 个 token 至少包含 $T$ 个顺序相关的解码步。必须区分两个阶段：长度为 $L$ 的 **prefill** 会并行处理整段提示，标准全注意力每层包含约 $O(L^2d)$ 的注意力计算和 $O(Ld^2)$ 的投影、FFN 计算；启用 KV cache 后，单个 **decode** 步只为新 token 计算投影，并让其查询已有 $L$ 个 KV，注意力部分约为 $O(Ld)$，但仍要执行各层的权重投影与 FFN。实际时延还受模型结构、batch、量化、kernel、显存带宽和上下文长度影响，不能用一个 $O(N+L^2d)$ 式子同时代表 prefill 与 decode，也不能预设 decode 必然占固定比例。

工程优化可以分为“降低每一步成本”和“让一次目标模型调用推进多个 token”两类；投机解码属于后者，但常与前者组合。

| 技术路线 | 主要优化对象 | 不直接解决的问题 | 评估时至少固定 |
|---|---|---|---|
| KV cache | 避免在 decode 时重复计算历史 K/V | token 之间的顺序依赖 | 上下文长度、KV 精度、注意力类型 |
| 权重/激活量化 | 权重带宽、算力或显存占用 | 质量变化与硬件 kernel 支持 | 位宽、量化粒度、校准集、硬件 |
| 分页式 KV 管理与连续批处理 | 内存利用率、并发和吞吐 | 单请求一定更快 | 到达过程、batch 策略、SLA |
| IO-aware attention kernel | attention 的数据搬运与 kernel 效率 | decode 中的权重读取和串行步数 | 序列长度、head 结构、数据类型 |
| 投机解码 | 每次目标验证可安全推进的 token 数 | 草稿与验证成本 | 目标/提议分布、接受长度、并发、SLA |

投机解码通过较便宜的提议机制先产生候选，再让目标模型批量验证候选位置。Leviathan 等人与 Chen 等人的同期工作分别给出了可恢复目标分布的 draft-then-verify / speculative sampling 方案。此后出现了独立草稿模型、Medusa 多头、EAGLE 特征草稿、prompt lookup，以及把 MTP 模块用作内嵌草稿等路线；它们共同目标是提高“期望推进量 / 一轮成本”，并不构成一条所有后继方法都依次取代前代的单线演进。

## 2. 工业价值与应用场景

多个推理引擎和通用生成库已经提供一种或多种投机/辅助解码入口，但支持的方法、采样语义、batch 限制和版本状态会持续变化。部署能力应以所用版本的官方文档和测试为准。

| 需要确认的能力 | 为什么不能只看“支持投机解码” |
|---|---|
| 提议器类型 | 独立草稿模型、n-gram lookup、Medusa/EAGLE/MTP 头的模型要求与显存成本不同 |
| 接受方法 | 只有与目标采样分布匹配的验证/修正规则才能声称分布无损；启发式接受可能改变输出分布 |
| 批处理与调度 | 单请求延迟收益不等于高并发吞吐收益，变长接受前缀还会影响调度和 KV 管理 |
| 采样支持 | greedy、temperature、top-k/top-p 下的实际 $p$ 与 $q$ 必须定义清楚 |
| 观测指标 | 至少同时报告 TTFT、TPOT/ITL、端到端延迟、吞吐、接受长度、显存和质量 |

投机解码通常首先瞄准解码阶段的 TPOT/ITL，但接受率本身不足以推出固定时延降幅。收益由草稿耗时、验证序列长度、目标模型批量验证效率、batch、上下文和调度共同决定；高接受率也可能被昂贵的草稿器或低效验证抵消。量化、分页式 KV 管理与投机解码可以组合，同时会相互影响：量化可能改变提议分布，投机验证产生临时 KV 状态，连续批处理也会改变最优草稿预算。

投机解码把“预测候选”和“提交输出”拆成两个角色，也推动了多 token 预测（Multi-Token Prediction）模块的系统化研究。Medusa 的多头、EAGLE 的特征草稿与 DeepSeek 系列的 MTP 模块都可以一次提出多个未来位置的候选，但候选仍需经过目标模型验证后才能按既定分布提交。“多 token 预测”描述候选生成能力，不等同于模型已经完成了多步规划。

## 3. 物理直觉与核心机制

标准自回归解码像一位必须逐字落笔的作者：第 $t+1$ 个 token 的条件分布要等第 $t$ 个 token 确定后才能计算。KV cache 避免了反复重算历史 K/V，但没有消除 token 之间的顺序依赖；生成 5000 个新 token 仍需要约 5000 个顺序解码步。

投机解码可类比为“草稿员—主编”协作：较便宜的提议器先写出 $k$ 个候选，目标模型用一次带因果 mask 的前向计算得到各候选位置的条件分布。各位置 logits 可以在同一次前向中计算，但接受事件仍须按前缀从左到右处理。

验证遵循“顺序审阅、首次拒绝即停止”原则。这里没有唯一“正确 token”；接受与否由 $p/q$ 和独立随机数决定。假设前两个候选被接受、第三个被拒绝：

```
位置 1: "深"（接受）
位置 2: "度"（接受）
位置 3: "学"（拒绝，改从修正分布采样）
位置 4: "习"（草稿时条件化于位置 3 的“学”）
```

位置 4 的草稿分布以“深度学”为前缀；而位置 3 被拒绝后，实际输出会由修正分布重新采样，其后缀条件已经改变。因此位置 4 及其后的草稿不能直接提交，必须丢弃并从新前缀继续。这是条件分布改变造成的控制流边界，不是“逐 token 与目标答案判同”。

投机解码的关键性质是**可以严格恢复目标分布**。草稿器先抽取候选 $y\sim q$，验证器再独立抽取 $u\sim\mathrm{Uniform}(0,1)$；当 $u\leq\min(1,p(y)/q(y))$ 时接受 $y$。目标模型不会再独立采样一个 token 与 $y$ 做“相等比较”。若首次拒绝，则从修正分布 $p'(x)\propto\max(0,p(x)-q(x))$ 抽取替代 token，并丢弃草稿后缀。在概率与控制流实现正确时，输出联合分布与目标模型自回归采样一致；实际速度取决于接受率和草稿、验证成本，不能由无损性直接推出固定倍数。

修正分布的物理意义是"目标模型相对于草稿模型的正剩余信息". $p(v) > q(v)$ 意味着目标模型认为 $v$ 比草稿模型估计的更合理; $p(v) \leq q(v)$ 说明草稿模型未低估 $v$. 修正分布仅保留被低估的选项, 按低估程度 $(p(v) - q(v))$ 重新分配概率质量. 

## 4. 数学推导与公式对比

设目标模型分布为 $p(x \mid x_{<t})$, 草稿模型分布为 $q(x \mid x_{<t})$. 单次迭代包含三步. 

**Draft**：草稿模型自回归生成 $k$ 个候选 token：

$$
\hat{x}_{t+i} \sim q(\cdot \mid x_{<t}, \hat{x}_t, \ldots, \hat{x}_{t+i-1}) \quad \text{for } i = 0, \ldots, k-1 \tag{2}
$$
**Verify**：前缀与候选拼接后输入目标模型, 一次 forward pass 输出 $k$ 个位置的真实分布 $p_i(x)$. 

**Accept/Reject**：位置 $i$ 的接受率为

$$
\alpha_i = \min\left(1, \frac{p_i(\hat{x}_{t+i})}{q_i(\hat{x}_{t+i})}\right) \tag{3}
$$

实际判定还需独立随机数 $u_i\sim\mathrm{Uniform}(0,1)$：仅当 $u_i\leq\alpha_i$ 时接受候选。这里没有“目标 token 与草稿 token 是否相同”的事件。

验证从 $i=0$ 顺序执行. 首次拒绝发生在位置 $j$ 时, 从修正分布采样：

$$
x_{t+j} \sim p'_j(x) = \frac{\max(0, p_j(x) - q_j(x))}{\sum_{x'} \max(0, p_j(x') - q_j(x'))} \tag{4}
$$
**分布等价性**：对于任意输出 token $v$, 投机解码单步输出概率 $P_{\text{spec}}(v)$ 严格等于 $p(v)$. 证明分两项求和——"草稿即 $v$ 且被接受"与"拒绝后修正采样到 $v$"——两种情况($p(v) \geq q(v)$ 与 $p(v) < q(v)$)均收敛于 $p(v)$. 

**期望推进量**：令 $A$ 表示本轮被接受的草稿 token 数。若每个位置在其前缀已接受条件下的接受概率均简化为常数 $\alpha$，则

$$
\mathbb{E}[A] = \sum_{i=1}^{k} \alpha^i = \alpha \cdot \frac{1 - \alpha^k}{1 - \alpha},\qquad \alpha\ne1 \tag{5}
$$

当 $\alpha=1$ 时，$\mathbb E[A]=k$。真实位置接受率不同时，令 $\alpha_j$ 表示“前 $j-1$ 个位置已接受”条件下第 $j$ 个位置的接受概率，则应使用 $\mathbb E[A]=\sum_{i=1}^{k}\prod_{j=1}^{i}\alpha_j$。忽略 EOS 与长度预算造成的提前终止时，首次拒绝会产生 correction，全部接受会产生 bonus，因此每轮总推进量为

$$
\mathbb E[\tau]=1+\mathbb E[A]. \tag{6}
$$

若 accepted token 已经是 EOS，或本轮输出达到 `max_new_tokens`，算法不再补 correction 或 bonus，式 (6) 需要按实际截断位置计算。

当 $\alpha=0.7,k=5$ 时，$\mathbb E[A]\approx1.94$，但 $\mathbb E[\tau]\approx2.94$，不能把前者直接称为“每轮产出”。若普通自回归每推进一个 token 的归一化成本为 $C_{\mathrm{AR}}$，一轮草稿与验证总成本为 $C_{\mathrm{round}}$，则示意加速比为

$$
\mathrm{Speedup}=\frac{\mathbb E[\tau]C_{\mathrm{AR}}}{C_{\mathrm{round}}}.
$$
这里给出的等价性成立于标准接受/修正规则及其明确的目标分布 $p$。最优草稿长度不存在脱离硬件和负载的闭式常数；应把 $k$ 或树预算当作在真实成本曲线上的调度变量。

## 5. 算力成本与数值走查

下面只做可复核的玩具账本，不代表任何真实引擎。假设：普通目标解码每 token 成本 $C_{\mathrm{AR}}=1$；自回归草稿每步成本 0.1；目标模型验证 $k$ 个草稿并计算 bonus 分布的成本为 $1+0.05k$。因此 $C_{\mathrm{round}}=1+0.15k$，每 token 成本为 $C_{\mathrm{round}}/\mathbb E[\tau]$，加速比为其倒数。

| 0.90 | 3 | 2.439 | 3.439 | 1.450 | 0.422 | **2.37×** |

## 6. 状态机与实现边界

下面是不可直接运行的算法伪代码，目的是把分布和状态边界写完整。$p_i$、$q_i$ 必须分别是目标模型希望实现、提议器实际采样的分布；任何 temperature、top-k/top-p、token mask 或其他 logits processor 都要先作用到相应分布，再进入接受与修正公式。

```text
while 还未遇到 EOS 且输出未达到 max_new_tokens:
    (y[1:k], q[1:k]) = proposal(prefix, k)
    (p[1:k], p_bonus) = target_verify(prefix + y[1:k])

    for i = 1..k:
        u ~ Uniform(0, 1)
        if u <= min(1, p[i](y[i]) / q[i](y[i])):
            提交 y[i]
            若 y[i] 是 EOS 或已达长度上限：立即结束
        else:
            r = normalize(max(p[i] - q[i], 0))
            z ~ r
            提交 z；丢弃 y[i:k] 及其临时 KV；结束本轮

    if y[1:k] 全部接受且仍未结束:
        z ~ p_bonus
        提交 z
```

提议器不可能采到 $q_i(y_i)=0$ 的 token；实现仍应防御下溢。若精确数学中 $p_i=q_i$，拒绝概率为零，修正分布不会被访问；若浮点误差让残差和接近零，应记录异常并采用与库语义一致的稳定退化策略，不能静默把 $p_i$ 当作修正分布。目标模型批量验证时可以先写临时 KV，但只保留被接受前缀和本轮新增的 correction/bonus 状态。可执行参考实现、三 token 数值例与性质测试见 [投机采样数学证明与参考实现](./6.6.2.5-投机采样数学证明与参考实现.md)。

## 7. 边界条件与失效模式

**分布重叠与接受率**。标准投机采样要求 $p$ 是所需的目标采样分布、$q$ 是实际产生候选的提议分布，并在接受率与修正分布中准确使用二者。数学上不要求两者属于同一模型族，也不要求采用相同温度或截断策略；但模型、领域或采样变换差异通常会降低 $\sum_v\min(p(v),q(v))=1-D_{TV}(p,q)$，从而降低接受效率。若对 logits 做了温度、top-k/top-p 或词表屏蔽，验证应使用变换后的实际 $p$ 与 $q$。

**短输出与固定开销**。投机解码需要草稿、验证和控制流调度；输出很短时，可供摊薄这些成本的解码轮数更少。但不存在跨模型、硬件和并发通用的“20–30 token”开关阈值。应在目标负载上测量启用与关闭两条路径，并把预期剩余长度、当前 batch、草稿成本和接受预测共同用于路由。

**低熵模式错配**。若 $p(:)=0.99$、$q(:)=0.3$，冒号一旦由 $q$ 抽到，其条件接受率是 $\min(1,0.99/0.3)=1$，不是“$p/q$ 很小”。问题在于 $q$ 只有 0.3 的概率提出冒号；若其余 0.7 概率质量主要落在 $p$ 几乎不支持的 token 上，这些候选大多被拒，整体期望接受率约等于两分布重叠质量而偏低。低熵位置在 $q$ 也捕获同一众数时通常具有较高接受率；草稿器漏掉或严重低估目标主模态时，接受率才会显著下降。

**显存开销：双模型的物理代价**。传统方案需同时驻留目标模型、草稿模型及各自运行状态。仅按每参数 2 byte 粗算，70B 与 7B 权重约为 140 GB 与 14 GB；真实占用还包含量化元数据、KV cache、workspace 和运行时碎片，不能据此固定写成“超过 200 GB”。可通过更小或量化草稿、共享组件、prompt lookup、Medusa/EAGLE/MTP 类附加模块等方式降低成本。附加模块的参数比例取决于隐藏维度、词表、head 数与具体实现，不能统一写成 $<1\%$。

**Batch Size $>1$ 的异步推进**。同一 batch 内不同请求可能接受不同长度，候选树形状和 KV 增量也可能不同。实现需要记录每个请求的有效前缀、回收未接受的临时状态，并决定如何重组下一轮 batch。padding、分桶、连续批处理或负载感知验证预算各有取舍；高并发下既可能因验证并行度上升而获益，也可能因草稿和调度竞争而失去收益，结论必须由目标引擎的吞吐—延迟曲线给出。

### 工业前沿：EAGLE 系列——特征级草稿模型

EAGLE 冻结目标模型，复用目标 embedding 与 LM head，并训练一个轻量草稿头。原始 EAGLE 在目标 LM head 之前的高层特征上做自回归，同时输入向前移一位的已采样 token embedding，以消除特征预测对采样分支的不确定性：

$$
\hat f_{t+1}=\operatorname{DraftLM}(f_{\le t},e_{\le t+1}),
\qquad
\hat p_{t+2}=\operatorname{LMHead}(\hat f_{t+1}). \tag{7}
$$

原始 EAGLE 已用静态草稿树与 tree attention。EAGLE-2 的贡献是**上下文感知动态树**：用路径上草稿置信度的乘积近似节点最终存活概率，逐层扩展高价值节点，再对全体节点重排和剪枝，最后展平为连通树供目标模型验证。EAGLE-2 没有重新训练草稿器，也没有改变标准接受/修正规则。

EAGLE-3 改变的是草稿表示与训练：去掉下一特征回归约束，直接优化 token 预测；把目标模型低、中、高层特征融合成输入；在训练时把前一步草稿输出回灌到后续草稿步，这一机制称为 **training-time test**，不是 test-time training。推理时后续位置使用草稿自身状态与已采样 token embedding，树结构沿用 EAGLE-2 的动态草稿树。

| 方法 | 草稿学习重点 | 草稿树 | 论文报告的范围内结果 |
|---|---|---|---|
| EAGLE | 高层特征自回归 + 移位 token；特征/分类联合损失 | 静态树 | LLaMA2-Chat 70B 延迟加速 2.7×–3.5× |
| EAGLE-2 | 沿用 EAGLE 草稿器 | 路径置信度驱动的动态扩展、重排与剪枝 | 3.05×–4.26×，相对 EAGLE-1 快 20%–40% |
| EAGLE-3 | 直接 token 预测、多层特征融合、training-time test | 兼容 EAGLE-2 动态树 | 约 3.0×–6.5×，相对 EAGLE-2 快 20%–40% |

这些数字来自各论文指定模型、任务和环境，不能横向当作统一基准。EAGLE-3 的 SGLang batch 64 吞吐 1.38×也只对应论文给定的单 H100、LLaMA-Instruct 3.1 8B、MT-Bench、链长 3 且不使用树结构的测量。完整机制与证据见 [EAGLE 系列专题](./6.6.2.1-投机采样与EAGLE系列.md)。

**与 Kimi K3、DeepSeek MTP 的边界**：K3 把预训练 MTP 结构在目标冻结后适配为 EAGLE-3 风格草稿，但其损失与特征来源有独立定义，见 [Kimi K3 正本](../../../05-模型家族与选型/5.3-模型家族/kimi/kimi-k3/kimi-k3.md)。DeepSeek V3/V4 的 MTP 是内嵌草稿模块，仍需要投机验证；不能把“多 token 预测”理解为无需验证地一次提交多个 token。训练动力学见 [MTP 深度解析](../../../2-核心原理与架构/2.4-前沿架构与变体/2.4.6-多Token预测MTP深度解析.md)。

## 8. 技术前瞻与演进

投机路线既包括模型训练完成后接入的独立草稿器或 prompt lookup，也包括 Medusa、EAGLE、MTP 这类需要训练附加模块的方案。比较这些路线时，应同时评估提议成本、验证语义、模型兼容性和目标负载。

**Multi-Token Prediction (MTP) 训练目标** 要求模型在训练阶段同时预测未来 $k$ 个 token. 损失函数从标准交叉熵扩展为：

$$
\mathcal{L}_{\text{MTP}} = \mathcal{L}_{\text{next}} + \lambda \sum_{i=1}^{k} \mathcal{L}_i \tag{8}
$$

MTP 把未来 token 预测能力训练进附加模块或预测头；推理时这些输出可作为内嵌草稿，减少另驻一个完整草稿模型的需要，但若要保持目标分布，多个候选仍须由目标模型投机验证，不能直接全部提交。DeepSeek V3/V4 的 MTP 属于这种内嵌 draft；Kimi K3 还会在目标冻结后把预训练 MTP 结构适配为 EAGLE-3 风格草稿。具体训练与验证边界见 [MTP 深度解析](../../../2-核心原理与架构/2.4-前沿架构与变体/2.4.6-多Token预测MTP深度解析.md)。

**自适应投机预算**。固定 $k$ 无法适配每个请求、位置与系统负载，但目标分布熵 $H(p)$ 单独既不决定 $p$ 与 $q$ 的重叠，也不决定验证成本。低熵位置若草稿器捕获同一主模态，反而可能非常容易接受；高熵位置也可能因两分布重叠不足而低效。更可靠的调度信号包括校准后的前缀存活概率、剩余输出长度、draft/verify 计时、batch 容量和 SLA；DSpark 专题给出其中一种负载感知方案。

**与 Test-Time Compute 的结合**。Self-consistency、搜索或长推理轨迹会增加生成预算，因此扩大了解码优化的潜在价值；但链式推理不天然保证高 n-gram 重复，prompt lookup 的收益取决于输出是否复用输入或既有上下文片段。是否启用投机解码仍应由质量约束和目标负载测量决定，不能从“推理 token 更多”直接推出“必要基础设施”。

**端到端多 token 与非自回归路线**。层次化生成、非自回归模型和离散扩散语言模型尝试改变“一次确认一个 token”的生成过程。它们与投机解码在质量、训练成本、并行度和服务复杂度上有不同取舍；目前没有定理证明投机解码是自回归范式内的唯一或全局最优方案。投机解码的现实价值是：在保持既有目标模型与明确采样语义的前提下，以可插拔方式换取延迟或吞吐收益。

## 9. 参考文献

1. Yaniv Leviathan, Matan Kalman, Yossi Matias, [*Fast Inference from Transformers via Speculative Decoding*](https://arxiv.org/abs/2211.17192), Google Research, 2022。给出 draft-then-verify 与目标分布恢复证明。
2. Charlie Chen et al., [*Accelerating Large Language Model Decoding with Speculative Sampling*](https://arxiv.org/abs/2302.01318), 2023。独立给出 speculative sampling、modified rejection sampling 与 Chinchilla 实验；不涉及信息论全局最优性证明。
3. Tianle Cai et al., [*Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads*](https://arxiv.org/abs/2401.10774), 2024。研究附加多解码头和树形候选；是否保持目标分布取决于采用的接受方案。
4. Yichao Fu, Peter Bailis, Ion Stoica, Hao Zhang, [*Break the Sequential Dependency of LLM Inference Using Lookahead Decoding*](https://arxiv.org/abs/2402.02057), 2024。通过 Jacobi 轨迹并行产生、缓存 n-gram 候选，再由 verification branch 验证；不是 prompt 字符串查找。
5. Apoorv Saxena, [*Prompt Lookup Decoding*](https://github.com/apoorvumang/prompt-lookup-decoding), 2023。以提示中的 n-gram 匹配替代神经草稿器；公开方法说明不是 arXiv:2311.04951。
6. Woosuk Kwon et al., [*Efficient Memory Management for Large Language Model Serving with PagedAttention*](https://arxiv.org/abs/2309.06180), 2023。用于分页式 KV 管理的系统背景，不承担投机解码效果证据。
7. Yuhui Li et al., [*EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test*](https://arxiv.org/abs/2503.01840), 2025。直接 token 预测、多层特征融合与 training-time test。
8. [*DSpark*](https://arxiv.org/abs/2607.05147) 与 [DeepSpec 官方仓库](https://github.com/deepseek-ai/DeepSpec)。半自回归草稿、置信度校准与负载感知验证预算。
