# Flash Decoding 原理与实现

> 本文解析 Flash Decoding 的核心原理——在 Flash Attention 基础上进一步优化推理阶段的 Decode 阶段, 通过分块并行化解决长上下文下的内存瓶颈. 

---

## 1. Flash Attention 的局限

Flash Attention 在训练和 Prefill 阶段表现出色, 但在 **Decode 阶段**存在瓶颈：

- **Decode 阶段特性**：每次只生成一个 token, Q 的长度为 1
- **内存瓶颈**：必须从显存读取完整的 KV Cache
- **计算利用率低**：Q 只有一个 token, 无法充分利用 GPU 并行性

## 2. Flash Decoding 的核心思想

### 2.1 分块并行化

Flash Decoding 将 KV Cache 分成多个块(Chunk), 在不同块上并行计算 attention：

1. **分块**：将 KV Cache 按长度维度分成 B 个块
2. **并行计算**：每个块独立计算 attention, 得到局部 softmax 结果
3. **全局归约**：将所有块的局部结果归约为全局 attention 输出

### 2.2 与 Flash Attention 的对比

| 特性 | Flash Attention | Flash Decoding |
|:-----|:----------------|:---------------|
| Q 长度 | 完整序列 | 1(单个 token)|
| KV 处理 | 整体计算 | 分块并行 |
| 核心优化 | 减少 HBM 访问 | 提升并行度 |
| 适用阶段 | Prefill / 训练 | Decode |

## 3. 关键算法

### 3.1 分块 Attention 计算

对于每个块 i, 计算：

S_i = Q @ K_i^T / sqrt(d)
m_i = max(S_i)
P_i = exp(S_i - m_i)
l_i = sum(P_i)
O_i = P_i @ V_i

### 3.2 全局归约

收集所有块的局部结果, 计算全局 softmax：

m_global = max(m_1, m_2, ..., m_B)
l_global = sum(l_i * exp(m_i - m_global))
O_global = sum(O_i * exp(m_i - m_global)) / l_global

### 3.3 在线 Softmax 的扩展

Flash Decoding 扩展了 Flash Attention 的在线 softmax 技术, 使其支持跨块的增量更新：

- 每个块维护局部的 max 和 sum
- 通过两阶段归约(局部 → 全局)得到最终输出
- 无需存储完整的 attention 矩阵

## 4. 性能分析

### 4.1 加速效果

- **短序列**：加速不明显(分块开销 > 并行收益)
- **长序列**：显著加速(并行收益 > 分块开销)
- **临界点**：通常在大约 4K-8K 上下文长度开始显现优势

### 4.2 与 vLLM 的结合

Flash Decoding 可以与 vLLM 的 PagedAttention 结合：
- PagedAttention 管理 KV Cache 的内存布局
- Flash Decoding 优化 Decode 阶段的计算效率
- 两者结合实现极致的推理性能

## 5. 实现要点

### 5.1 Kernel 设计

- **Warp 级并行**：每个 warp 处理一个 KV 块
- **共享内存优化**：利用 SM 的共享内存减少全局内存访问
- **异步加载**：使用 CUDA 异步拷贝(TMA)隐藏内存延迟

### 5.2 与现有系统的集成

Flash Decoding 已被集成到多个推理框架：
- **vLLM**：通过 `--attention-backend flash_decoding` 启用
- **SGLang**：原生支持
- **TensorRT-LLM**：通过插件支持

---

## 6. 总结

Flash Decoding 是 Flash Attention 生态的重要补充：

- **Flash Attention**：优化 Prefill/训练阶段的内存访问
- **Flash Decoding**：优化 Decode 阶段的并行度
- **两者结合**：覆盖 LLM 推理的完整生命周期

## 7. 2026-08 修订：先读 CRFM / PyTorch 博文，再把 FA3 分开（不删上文）

上文转写自 2025 博客。算法骨架（按 KV 切块、块内 softmax、跨块归约）方向对，但有三处不要继续当事实：

1. **「4K–8K 才开始有优势」未出现在一手材料。** [Stanford CRFM 2023-10-12](https://crfm.stanford.edu/2023/10/12/flashdecoding.html) / [PyTorch 同文](https://pytorch.org/blog/flash-decoding/) 写的是：短 prompt 各家差不多；序列从 512 拉到 64k 时，**只有 Flash-Decoding 几乎不掉速**（CodeLlama-34B，**batch 1**）。端到端生成最高约 **8×**；注意力微基准相对当时的 FlashAttention 最高约 **50×**。到 32k 之前，注意力时间大致常数，因为 GPU 已经被占满。PyTorch 博文表（A100，f16，16 个 query 头 / 2 个 KV 头，对齐 CodeLlama-34B 切 4 卡）：`B=1, seqlen=65536` 时 FlashAttention v2.0.9 **2300.6 µs**、Flash-Decoding **64.4 µs**；`seqlen=131072` 为 **4592.2 / 106.6 µs**。不要把上表估成「4K 临界点」。
2. **§5.1 的 TMA、以及 vLLM `--attention-backend flash_decoding`。** 2023 这篇 decode 核跑在 A100 叙事上：切分是 KV 张量的 **view，不另起 GPU 拷贝**；然后 **两个 kernel**（split 上跑 FlashAttention + 用 log-sum-exp 做归约）。TMA / warp-specialization 是 **FlashAttention-3** 在 Hopper 上的招，不要倒灌进 2023 的 Flash-Decoding。vLLM 那条 CLI 本会话未打开文档，**不升格**。
3. **FA3 不是 Flash-Decoding 换皮。** [arXiv:2407.08608](https://arxiv.org/html/2407.08608v2) 解决的是 FA2 在 H100 上只有约 **35%** 利用率（对比 GEMM 80–90%）。三招：warp-specialized producer/consumer 叠 TMA 与 Tensor Core；softmax 藏进异步 WGMMA 的下一块 GEMM；FP8 块量化 + incoherent processing。H100 SXM5：**FP16 相对 FA2 前向 1.5–2.0×，最高约 740 TFLOPs/s（75%）**；反向 1.5–1.75×；FP8 接近 **1.2 PFLOPs/s**；FP8 数值误差相对朴素 per-tensor 约 **2.6× 更低**。论文自己把 **「optimizing for LLM inference」列为未做完的限制**——所以 serving 里的 split-KV 仍是 Flash-Decoding / `flash_attn_with_kvcache` 那条 occupancy 故事，不是 FA3 前向核自动解决 decode。附录点名 LeanAttention 做 decode 的 load balance，本篇不展开。Hopper 核的 pingpong / WGMMA 图在体系章 [04-FlashAttention-v3](../../2-核心原理与架构/2.3-高效与稀疏注意力/2.3.1-硬件高效注意力/01-FlashAttention/04-FlashAttention-v3.md)，这里不重画。

### 2023 博文真正改的并行轴

FlashAttention（训练 / prefill）按 **batch × query 长度** 切块。Decode 时 query 长度通常是 1：若 batch 小于 SM 数（A100 **108**），大量 SM 空转。博文原句：batch 1 时 FlashAttention 用到的 GPU **不到 1%**。

Flash-Decoding 多开一维：**按 KV 序列长度切 split**。三步：

1. 把 K/V 切成若干 chunk（实现上是 view）。
2. 每个 split 上并行跑 FlashAttention，额外写每个 row、每个 split **一个** log-sum-exp 标量。
3. 第二个 kernel 用这些 LSE 把各 split 的 $O_i$ 缩放到全局 softmax。在线 softmax 用两层：split 内一层（FA），split 间一层（归约）。

![Flash-Decoding：Q 长度为 1；KV 切成多段并行做局部注意力；再用每段的 LSE 归约](./images/fig-flash-decoding-splitkv.png)


Dao 仓库 README 的 inference 段与博文同构：query 很短时瓶颈是 **尽快把 KV cache 读进来**，于是把加载拆到不同 thread block，另起 combine kernel。入口是 `flash_attn_with_kvcache`（可原地写 cache、可带 rotary）。包版本：FlashAttention **≥2.2**；xFormers **≥0.0.22** 的 `memory_efficient_attention` 会按 problem size 在 Flash-Decoding 与 FlashAttention 之间 dispatch。

PagedAttention 管的是 **KV 页怎么摆**（[6.4.1](../6.4-KV缓存与内存优化/6.4.1-PagedAttention原理/6.4.1-PagedAttention原理.md)），Flash-Decoding 管的是 **qlen=1 时 SM 占不满**。可以叠，但不是同一个旋钮。投机解码（[6.6.2](./6.6.2-投机解码/6.6.2-投机解码.md)）改的是前向次数，也不是这条。
