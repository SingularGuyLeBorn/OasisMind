# 6.1.1 分布式训练

> 本文系统梳理大模型分布式训练的核心技术，涵盖 3D 并行(DP/TP/PP)、ZeRO 系列优化器、序列并行(Sequence Parallelism)、激活Checkpoint(Activation Checkpointing)等关键技术，并对比 FSDP2、DeepSpeed、Megatron-LM 三大主流框架的选型策略. 

---

## 2. 3D 并行：DP、TP、PP

3D 并行是指**数据并行(Data Parallelism)、张量并行(Tensor Parallelism)、流水线并行(Pipeline Parallelism)** 三种并行策略的组合. 这三种策略分别从不同维度对训练过程进行拆分. 

### 2.1 数据并行(DP)

数据并行是最直观的并行方式：**将训练数据切分到多张 GPU 上，每张 GPU 持有完整的模型副本，各自计算梯度后通过 All-Reduce 通信同步梯度**. 

```
GPU 0: 数据批次 0 → 前向 → 反向 → 梯度
GPU 1: 数据批次 1 → 前向 → 反向 → 梯度
GPU 2: 数据批次 2 → 前向 → 反向 → 梯度
GPU 3: 数据批次 3 → 前向 → 反向 → 梯度
                ↓ All-Reduce 同步
           所有 GPU 获得平均梯度
```

![](./images/fig-dp-allreduce.png)

> 图 1：数据并行：4 张 GPU 各持完整模型副本、不同 micro-batch，反向后 All-Reduce 得到平均梯度。显存按完整副本复制，不是切模型。（PyTorch DDP 设计笔记：[Distributed Data Parallel](https://docs.pytorch.org/docs/2.13/notes/ddp.html)；反向按 bucket 做 All-Reduce，均值写回 `param.grad`。）

**图 1 解析**

- 四列是四张卡，不是四段模型。每列顶部「full model replica W」和「optimizer + grads (full)」同宽：参数、梯度、优化器状态都在本卡各存一份。
- 差别只在数据：mb0–mb3 是同一个 step 里切开的 micro-batch，前向 / 反向都在本地副本上算。
- 底部 All-Reduce 把 $G_0,\ldots,G_3$ 做成均值 $G_{\mathrm{avg}}$，再送回每张卡。之后各卡用同一份平均梯度更新，副本保持对齐。
- DDP 构造时从 rank 0 broadcast `state_dict`，反向用 autograd hook 触发；通信是分桶 All-Reduce，不是把整份梯度当一个张量堵在一起。
- 这张图解释的是「为什么 70B+ 单卡塞不下」：模型没切，显存随完整副本走。切算子是 §2.2 的 TP，切层是 §2.3 的 PP，切状态是 §3 的 ZeRO。

**优点**：
- 实现简单，代码侵入性低
- 计算粒度均匀，流水线气泡少

**缺点**：
- 每张卡需要存储完整模型参数 + 优化器状态 + 梯度
- 对于大模型(如 70B+)，单卡显存不够存储完整模型

**分布式数据并行(DDP)** 是 PyTorch 原生的 DP 实现，使用 `torch.distributed` 完成通信. 与普通 DP 不同，DDP 不依赖 Python 多线程，而是每个进程独立运行在单独的 GPU 上，避免了 GIL 限制. 

### 2.2 张量并行(TP)

张量并行将**单个算子(如 Linear 层、Attention 层)的计算拆分到多张 GPU 上**. 最经典的是 Megatron-LM 提出的列并行(Column-wise)和行并行(Row-wise)切分方式. 

对于线性层 $Y = XA$：

- **列并行**：将权重矩阵 $A$ 按列切分为 $[A_1, A_2]$，分别在不同 GPU 上计算 $XA_1$ 和 $XA_2$，结果拼接
- **行并行**：将权重矩阵 $A$ 按行切分为 $\begin{bmatrix} A_1 \\ A_2 \end{bmatrix}$，在不同 GPU 上计算 $X_1A_1 + X_2A_2$，结果累加

**关键通信模式**：
| 计算阶段 | 通信操作 | 说明 |
|:--------|:--------|:------|
| 前向列并行 | All-Gather | 拼接各 GPU 的部分输出 |
| 前向行并行 | Reduce-Scatter | 累加各 GPU 的部分输出 |
| 反向传播 | All-Reduce | 同步各 GPU 的梯度 |

![](./images/fig-tp-column-row.png)

> 图 2：线性层 $Y=XA$ 的列并行 vs 行并行。图上标 All-Gather / Reduce-Scatter；原版 Megatron-LM 行并行出口的 $g$ 算子是 All-Reduce，与 Reduce-Scatter + All-Gather 同体积，没有第三种集合通信。

**图 2 解析**

- 左：权重 $A$ 按列切成 $A_1\mid A_2$。两张卡都拿完整 $X$，各算 $Y_1=XA_1$、$Y_2=XA_2$。输出隐层维被切开，要拼回完整 $Y$ 才 All-Gather。
- 右：$A$ 按行切成 $\begin{bmatrix}A_1\\A_2\end{bmatrix}$，$X$ 沿收缩维对齐切开。局部 GEMM 得到同形的部分和，Reduce-Scatter 先求和再把 $Y$ 的分片散回各卡。
- 2019 Megatron 的 MLP 把第一层做成列并行、第二层做成行并行，中间 GeLU 本地做、不通信；行并行出口 $g$ 是前向 All-Reduce、反向恒等，列并行入口 $f$ 对偶（前向恒等、反向 All-Reduce）。
- 上表把 All-Reduce 拆成 All-Gather / Reduce-Scatter，方便和后文序列并行（§4.5）对上；不是新原语。
- 列并行省的是输出列上的权重；行并行省的是输入行上的权重。两张卡合起来才是完整 $A$。

**优点**：
- 降低单卡计算量和显存需求
- 适合大矩阵运算(Attention、FFN 层)

**缺点**：
- 通信频繁，每层前/反向都需要 All-Reduce
- 对卡间带宽要求极高(通常需要 NVLink/NVSwitch)

### 2.3 流水线并行(PP)

流水线并行将**模型的层按顺序分配到不同的 GPU 上**. GPU 0 负责前几层，GPU 1 负责中间层，GPU 2 负责后面层，数据像流水线一样依次经过各 GPU. 

```
GPU 0: 层 1-10 → 输出 → GPU 1: 层 11-20 → 输出 → GPU 2: 层 21-30
       ← 梯度 ←             ← 梯度 ←               ← 梯度 ←
```

**流水线气泡问题**：简单实现下，GPU 0 处理完 micro-batch 0 后需要等待 GPU 1 处理 micro-batch 0 才能处理下一个 batch，导致 GPU 空闲(即"气泡"). 解决方法包括：

| 方法 | 说明 | 气泡率 |
|:----|:------|:------|
| **朴素 PP** | 一次只处理一个 micro-batch | 高 |
| **Gradient Accumulation** | 将 batch 拆分为多个 micro-batch 流水执行 | 中 |
| **1F1B 调度** | One-Forward-One-Backward，交错执行前向和反向 | **低** ~10-15% |
| **交错式 1F1B** | 将每个 GPU 的层再拆分，微调流水线粒度 | **更低** ~5-10% |

![](./images/fig-pp-1f1b.png)

> 图 3：朴素流水线（先全部前向再全部反向）的气泡，对比 1F1B。气泡率沿用上表：1F1B ~10-15%，交错式 1F1B ~5-10%。甘特图只画调度，不是吞吐曲线。

**图 3 解析**

- 每一行是一台负责连续若干层的 GPU；时间从左到右。蓝块 F 是某个 micro-batch 的前向，橙块 B 是反向。
- 上图：F 排成阶梯灌满流水线之后，GPU 0 必须空等到尾卡算出反向，才开始 B。灰色虚线区就是气泡。
- 下图：warmup 之后每张卡交替做一块 F 和一块 B（1F1B），气泡收成边角上的小口袋，表里记 ~10-15%。
- 右侧黄框的交错式 1F1B 把每张卡上的层再切细，气泡再降到表里的 ~5-10%。图上没有另编百分比。
- 流水线切的是层，不是把一张卡上的 Linear 切开（那是图 2 的 TP）。卡间只传层间 hidden。
- [OM-FREEPLAY] 表内 ~10-15% / ~5-10% 沿用既有正文，未找到对应一手论文表；不要当成实测 MFU。

**优点**：
- 极大降低单卡显存占用(每卡只保存模型的一部分层)
- 卡间通信量相对较小(仅传递层间的 hidden states)

**缺点**：
- 存在流水线气泡，GPU 利用率受限于流水线深度
- 实现复杂度较高(需处理 micro-batch 调度)

### 2.4 3D 并行组合策略

实践中，大模型训练通常**组合使用上述三种并行策略**：

```
数据并行(DP)      GPU 0 ←→ GPU 1    ←→    GPU 2 ←→ GPU 3
                     ↓ 张量并行 ↑            ↓ 张量并行 ↑
                     GPU 4 ←→ GPU 5    ←→    GPU 6 ←→ GPU 7
                   ←──────── 流水线并行 ────────→
```

以训练一个 100B 模型为例，典型的组合方式：
- **张量并行(TP=8)** ：在 8 张 GPU 组成的节点内拆分 Attention/FFN 算子
- **流水线并行(PP=4)** ：将模型层分为 4 组，每组分配到不同的 GPU 组
- **数据并行(DP=2)** ：在 2 个 GPU 组之间做数据并行

总 GPU 数 = $TP \times PP \times DP = 8 \times 4 \times 2 = 64$ 张 GPU

### 2.5 MoE 模型的专家并行(EP)与混合部署

混合专家模型(MoE)的推理与训练引入了第四种并行维度——**专家并行(Expert Parallelism, EP)** . 与将模型参数均匀拆分到所有 GPU 的 TP/PP 不同，EP 将不同的专家网络分配到不同的 GPU 上，每张 GPU 只负责计算一部分专家的输出. 

**MoE 模块的计算流程**可分解为四个阶段：

1. **Gate 计算**：输入经过 RMSNorm 后，通过路由网络(Router)计算每个 token 对各专家的亲和度分数，选择 Top-K 个专家. 
2. **Dispatch**：根据路由结果，将每个 token 的激活发送到其选中的专家所在的 GPU. 这涉及跨 GPU 的 All-to-All 通信. 
3. **Expert GEMM**：每个专家独立执行前向计算(通常包含 Gate-Up 投影、SiLU 激活、Down 投影). 
4. **Combine**：将各专家的输出按路由权重加权求和，通过 All-to-All 通信将结果聚合回原始 token 位置. 

**DeepGEMM 的两种 Layout 优化**：

| Layout 模式 | 适用场景 | 核心特征 |
|:-----------|:--------|:--------|
| **Contiguous Layout** | Prefill / 训练前向 | 将各专家接收的 token 按顺序拼接为连续 buffer，通过 offset/index 逻辑划分，每个专家对齐到 128 的倍数，最大化 Tensor Core 利用率 |
| **Masked Layout** | Decoding + CUDA Graph | 采用 mask-based grouped GEMM，替代显式分组，兼容 CUDA Graph 的静态图约束，无冗余计算浪费，通过精细控制获得更好性能 |

**多卡 TP 推理 MoE 模型**：在张量并行下，Attention 和 MoE Block 的权重按列/行切分到不同 GPU. 每层 Transformer Block 存在两个 All-Reduce(Attention 输出投影 + MoE Down 投影)，推理过程中还有两个 All-Gather(Embedding 输出 + 最终 logits). 通信模式与 Dense 模型类似，但 MoE 层增加了 Expert 内部的局部计算. 

**多卡 EP 推理 MoE 模型**：在专家并行下，不同专家被分配到不同 GPU. 假设 4 张 GPU、8 个专家，则每张 GPU 存放 2 个专家. 路由后的 All-to-All 通信将 token 发送到目标专家所在的 GPU，计算完成后再 All-to-All 聚合. EP 的优势在于单卡只需存储部分专家参数，显存占用与专家数成正比降低; 代价是引入额外的 All-to-All 通信. 

**TP + EP 混合并行**：工业部署通常采用 TP 与 EP 的混合策略——在节点内(如 8 张 GPU)使用 TP 拆分 Attention 和共享权重，跨节点使用 EP 分配专家. 例如 DeepSeek-V3 的部署：节点内 TP=8 处理 Attention 和共享 FFN，跨节点 EP=16 分配 256 个专家. 这种混合策略在通信效率和显存利用率之间取得平衡：TP 的 All-Reduce 发生在高带宽 NVLink 域内，EP 的 All-to-All 通过 IB/RoCE 跨节点传输. 

### 2.6 2026-08：EP Wave 隐藏条件与压缩注意力的 CP

> 2025 正文停在「EP 多一张 All-to-All」。下面把 6.1 总览里已经写过的 V4 公式落到本文件，避免只在第 14 章出现。稳定性 / 训推不在本节，见 [6.1.7](../6.1.7-训练稳定性与训推不一致.md)。

**Wave 级 EP。** All-to-All 可以完全藏进计算的条件是算力-带宽比盖得住每对 token-expert 的计算/通信比：

$$
\frac{C}{B} \le \frac{V_{\mathrm{comp}}}{V_{\mathrm{comm}}}
$$

$C$ 为峰值 FLOP/s，$B$ 为互联 Byte/s。V4-Pro（SwiGLU FFN，FP8 Dispatch + BF16 Combine）简化成 $C/B \le 2d = 6144$ FLOPs/Byte。把专家切成多个 Wave：当前 Wave 计算、下一 Wave 收 token、已完成 Wave 发结果三者并发。细表与实测倍数在 [6.1 §7.5](../6.1-训练基础设施.md)，此处不重抄加速比柱。

![EP Wave：当前 Wave 在算专家；下一 Wave 收 token；已完成 Wave 发结果。通信叠在计算上](./images/fig-ep-wave.png)


K3 的 MoonEP（每个 EP rank 收恰好 $S\times K$ 个 token）不是新的 $p_i$，指针仍在 6.1 文末。

**Context Parallelism（CP）不是 SP 的别名。** §4 的 Ulysses / Ring 沿**未压缩序列**切。CSA/HCA 压缩后：(1) pack 尾部不足 $m$ 个 token 被丢掉，各 rank 压缩长度不一致；(2) 压缩块可能跨 rank 边界。V4 两阶段：

1. **边界 KV 交换**：每个 rank 把最后 $m$ 个未压缩 KV 发给下一 rank，接收方与本地 KV 一起压缩。
2. **All-Gather + Select-and-Pad**：局部压缩 KV 做 All-Gather，融合算子排成完整集合，padding 放尾部。

因果用可见范围钉死：query $t$ 只能看见满足 $s < \lfloor t/m \rfloor$ 的压缩块 $C_s$。跨过去就是未来泄露，不是「通信多一次」那么简单。

![压缩注意力的 CP 两阶段：先把本 rank 末尾 m 个未压缩 KV 交给下一 rank 再压缩；然后 All-Gather 压缩块，padding 放尾部](./images/fig-cp-two-stage.png)


KDA 的 Context Parallelism 还要交换累积转移矩阵再 prefix scan（不能对从零算的局部状态直接求和），式在 [K3 D2 §9](../../../14-主流开源模型全景解析与技术报告精读/14.5-Kimi/05-Kimi-K3/01-Kimi-K3-架构精译.md)。

## 3. ZeRO 系列优化器

ZeRO(Zero Redundancy Optimizer)由 Microsoft DeepSpeed 团队提出，核心思想是 **消除数据并行中的内存冗余**. 在传统数据并行中，每张 GPU 都保存完整的模型状态(参数 + 梯度 + 优化器状态)，存在大量冗余. 

### 3.1 ZeRO 的三个级别

| 级别 | 分片内容 | 显存节省 | 通信开销 |
|:----|:--------|:--------|:--------|
| **ZeRO-1** | 优化器状态分片 | 4 倍 | 少量 |
| **ZeRO-2** | 优化器状态 + 梯度分片 | 8 倍 | 中 |
| **ZeRO-3** | 优化器状态 + 梯度 + 权重分片 | $N_d$ 倍($N_d$ 为 DP 度) | 高(频繁 AllGather) |

**ZeRO-1**：将优化器状态(如 Adam 的动量 $m$ 和方差 $v$)分片到 $N_d$ 张 GPU 上，每张卡只维护 $\frac{1}{N_d}$ 的优化器状态. 每张 GPU 计算完整梯度后，只更新自己维护的那部分参数，然后通过通信获取完整参数. 

**ZeRO-2**：在 ZeRO-1 的基础上，将梯度也分片. 反向传播时，梯度通过 Reduce-Scatter 分散到各 GPU，每张卡只维护自己分片的梯度. 优化器更新后，再 All-Gather 获取完整权重. 

**ZeRO-3**：最激进的方案，将模型权重也分片. 在前向传播前通过 All-Gather 获取所需层的权重，前向结束后释放非本卡维护的权重. 反向传播类似. 

![](./images/fig-zero-123-shard.png)

> 图 4：ZeRO-1/2/3 分别分片优化器状态、梯度、权重。倍数沿用上表：4× / 8× / $N_d$。

**图 4 解析**

- 四列都是「这一张卡此刻存什么」。宽色条 = 完整副本；细条 = 只持 $1/N_d$。
- Baseline DP 与图 1 同一件事：P、G、OS 全复制。混合精度 Adam 文内按 $16\Psi$ 字节记账（fp16 参数与梯度各 $2\Psi$，fp32 的参数副本 / 动量 / 方差共 $12\Psi$，$K=12$）。
- ZeRO-1 只切 OS（$P_{os}$）：$N_d$ 足够大时约从 $16\Psi$ 收到 $4\Psi$，上表 4 倍。
- ZeRO-2 再切梯度（$P_{os+g}$）：约收到 $2\Psi$，上表 8 倍。反向用 Reduce-Scatter 把梯度送到持有对应 OS 分片的卡。
- ZeRO-3 连权重也切（$P_{os+g+p}$）：模型状态按 $N_d$ 线性降。用某层前 All-Gather，用完释放。论文写通信体积相对 DP 大约 1.5×，不是把 DP 换成别的算法。

### 3.2 ZeRO-Offload 与 ZeRO-Infinity

当 GPU 显存实在不够时，ZeRO 提供了将数据卸载到 CPU 内存甚至 NVMe SSD 的能力：

| 技术 | 卸载目标 | 适用场景 |
|:----|:--------|:--------|
| **ZeRO-Offload** | CPU 内存 | 单卡或小集群，GPU 显存不足 |
| **ZeRO-Infinity** | CPU 内存 + NVMe SSD | 超大模型，需要近乎无限的存储空间 |

**ZeRO-Offload** 的核心策略：将**优化器状态和梯度**卸载到 CPU 内存，GPU 只保留模型权重和计算所需的临时数据. CPU 负责优化器更新(Adam 状态更新)，GPU 负责前向/反向计算. 

**ZeRO-Infinity** 进一步将权重也可以卸载到 NVMe SSD，实现了**训练任意规模模型**的可能性——理论上，只要 CPU 内存和 SSD 空间足够，可以在有限 GPU 上训练万亿参数模型. 

### 3.3 ZeRO 与数据并行的关系

ZeRO 本质上是对**数据并行的显存优化**，它不改变计算图，只是改变了数据分布方式. 因此，ZeRO 可以与其他并行策略(TP、PP)组合使用：

| 组合 | 适用场景 |
|:----|:--------|
| **ZeRO-3 + TP** | 模型过大，需张量并行降低单卡计算量，同时利用 ZeRO 节省显存 |
| **ZeRO-2 + PP** | 流水线并行已有显存节省，用 ZeRO-2 进一步降低优化器状态冗余 |
| **ZeRO-Offload + TP + PP** | 极致显存优化，适合在有限 GPU 上训练极大模型 |

## 4. 序列并行(Sequence Parallelism)

标准 Transformer 训练中，自注意力机制的计算复杂度和显存占用与序列长度 $L$ 呈 **二次关系** $O(L^2)$. 当序列长度达到 128K 甚至 1M 时，注意力计算的显存占用成为主要瓶颈. 

序列并行将**序列维度上的计算和显存进行拆分**，解决长序列训练问题. 

### 4.1 序列并行的动机

以一个 Llama 70B 模型为例，序列长度对显存的影响：

| 序列长度 | 注意力显存 | 总训练显存 | 瓶颈 |
|:-------:|:---------:|:---------:|:----:|
| 4K | 16 MB | ~140 GB | 权重 + 优化器状态 |
| 32K | 1 GB | ~145 GB | 权重为主 |
| 128K | 16 GB | ~160 GB | 注意力显存显著 |
| **1M** | **1 TB** | **>1 TB** | **注意力显存成为绝对瓶颈** |

当序列长度超过 128K 时，**注意力计算的显存需求急剧上升**，仅靠数据并行和模型并行无法有效解决. 

### 4.2 DeepSpeed Ulysses(序列并行)

DeepSpeed Ulysses 是微软 2024 年提出的序列并行方案，核心思想是将**注意力计算的 QKV 投影和注意力分数计算拆分为多个序列片段**. 

**工作原理**：
1. 将长度为 $L$ 的序列平均切分为 $P$ 个片段，分配给 $P$ 个计算节点
2. 每个节点只计算自己片段的注意力输出
3. 通过 All-to-All 通信在节点间交换必要的信息

**通信模式**：All-to-All 通信，每个节点与其他所有节点交换数据. 

**优点**：通信量随序列长度线性增长，适合超长序列(128K+)

> **2026-08 修订（不删上文）。** Jacobs、Tanaka、Zhang、Zhang、Song、Rajbhandari、He（Microsoft）*DeepSpeed Ulysses: System Optimizations for Enabling Training of Extreme Long Sequence Transformer Models*（[arXiv:2309.14509](https://ar5iv.labs.arxiv.org/html/2309.14509)，**2023-09**，不是 2024）。上面第 2 步「每个节点只计算自己片段的注意力输出」**反了**：注意力阶段每张卡拿到的是 **整段序列、互不重叠的少数学头**。第 1 步把序列切成 $N/P$ 只覆盖投影和 MLP；All-to-All 之后本地做的是完整注意力。不是 Ring（Q 留本机、KV 环转），不是 NVIDIA Star Attention（推理块稀疏），也不是 Megatron CP / V4 两阶段 CP。

先分清切法（§3.1、Figure 2）：

1. 输入按序列维切开：$P$ 张卡各持 $N/P$。QKV 张量在文里写成 $N,b,d$（序列、micro-batch、隐层）。
2. **本地**把这段投影成 Q、K、V。
3. **All-to-All**：每张卡换成 **全长 $N$**，但只拿 **互不重叠的头子集**。然后按头做

$$
\mathrm{Output}_{\mathrm{context}}=\mathrm{Softmax}\bigl((QK^{\top})/\sqrt{d}\bigr)V
$$

（文内式 (1)；排版写成了 $\sqrt{(}d)$。）
4. **再一次 All-to-All**：把头维拼回去，序列维再切成 $N/P$，交给 MLP、LayerNorm。

从第 3 步直接推出：**序列并行度 $P$ 不能大于头数**，否则有的 rank 没有头可算。论文没单独写不等式，不是定理编号。GQA/MQA 这篇没讨论，不外推。

通信量（§3.2）。NVSwitch 节点内、fat-tree IB 节点间：大小 $M$ 的 All-to-All 在 $P$ 张卡上 **每条链路 $M/P$**。每层：注意力前对 QKV 做一次，聚合消息 $3Nh$；注意力后再对输出做一次，$Nh$。每链路合计 **$4Nh/P$**，复杂度 $O(N/P)$。**$N$ 和 $P$ 按比例一起加，每链路体积不变。**

对照 Megatron-LM sequence parallelism（Korthikanti et al. 2022；Ulysses 把它写成跟 TP 绑在一起）：每层两次 All-Gather（各 $Nh$）+ 两次 Reduce-Scatter（各 $Nh$）。$P\gg 1$ 时，大小 $M$ 的 AG/RS **每链路仍是 $M$，不是 $M/P$**，合计 **$4Nh$**，比 Ulysses 大 **$P$ 倍。** 这是 Ulysses 的通信账，不是 Korthikanti 原文的符号。ColAI-SP（Li et al.；ACL 2023 / [arXiv:2105.13120](https://arxiv.org/abs/2105.13120)）：Q 本地、先环传 K 再环传 V，复杂度 $O(M)$。本体、式 (4) 和 Table 4 在下文 §4.6。2025 原文「通信量随序列长度线性增长」说的是 Megatron-SP 和这家，不是 Ulysses。Korthikanti 自己的切法、式 (4)–(6) 和 Table 5 在下文 §4.5，不要把 Ulysses 的「All-to-All 换头」套过去。

Table 1（只抄勾、不编常数）：

| 方法 | 通信 | 激活显存 | 参数显存 | 注意力无关 | 好用 |
| --- | --- | --- | --- | --- | --- |

### 4.3 Ring Attention(环形注意力)

Ring Attention 是另一种序列并行方案，它利用**环状通信模式**，将注意力计算分散到多个 GPU 上：

1. 将长序列切分为 $P$ 个块，$P$ 张 GPU 各持一个块
2. GPU 执行环形通信，逐轮交换 key/value 块
3. 每轮计算当前 GPU 的 query 与收到的 key/value 的部分注意力
4. 最终结果通过 Reduce-Scatter / All-Gather 聚合

**关键优势**：通信与计算可重叠(overlap)，Ring Attention 可以在计算当前轮注意力时，同时传输下一轮所需的 key/value，有效隐藏通信延迟. 

> **2026-08 修订（不删上文）。** 第 4 步「Reduce-Scatter / All-Gather 聚合」**不是**这篇论文。Liu、Zaharia、Abbeel *Ring Attention with Blockwise Transformers*（[arXiv:2310.01889](https://ar5iv.labs.arxiv.org/html/2310.01889)，**ICLR 2024**；代码 [lhao499/llm_large_context](https://github.com/lhao499/llm_large_context)）用的是块内 **memory-efficient attention 的在线 softmax 统计**（分子 / 分母 / max），KV 用 `jax.lax.ppermute` 在环上转。**精确**，不做稀疏近似。NVIDIA Star Attention（[2411.17116](https://ar5iv.labs.arxiv.org/html/2411.17116)）Phase 1 **不传 KV**，是另一篇；RULER 倍数见 [2.3.4](../../../2-核心原理与架构/2.3-高效与稀疏注意力/2.3.4-高效注意力全景综述/2.3.4-高效注意力全景综述.md)。也不是 2019 Star-Transformer，不是 Li et al. ACL 2023 那种 **两段环、先物化 $S$** 的 RSA（他们 Related Work 点名；切法在下文 §4.6）。

先分清两层省显存：

1. **块内**已经有 Rabe–Staats / FlashAttention / **Blockwise Parallel Transformer**（Liu & Abbeel, NeurIPS 2023）。BPT 把 FFN 也按块算，一层激活收到 **$2bsh$**（Table 1，bf16）。切法、对照表和「32×」怎么读在下文 **§4.7**，这里不重抄。
2. **层间**还要存整层输出：下一层注意力是 $n$ 对 $n$。文内账：batch 1、$h{=}1024$、**1 亿** token 仍要 **>1000GB**，单卡 HBM 不够。所以要把 **序列维** 切到多机。

做法（Figure 2 / Algorithm 1）：$N_h$ 台机器成环，每台先算自己那一块的 $Q,K,V$。外层循环每台只负责 **自己的 query 块** 和这块的 FFN（这块不通信）。内层对 KV 块的顺序无所谓，只要 softmax 统计拼对。于是算当前 KV 块的同时，把这份 KV **发给下一台、从上台收下一份**。计算时间 $\ge$ 传输时间则通信开销写成 0。正反向同一套。

算术强度：块内注意力他们只计 $4dc^{2}$ FLOPs（$QK$ 和 $PV$ 各 $2dc^{2}$），不算投影和 FFN（故意把条件收紧）。通信 $4cd$ 字节（K 和 V）。要重叠：$c\ge F/B$（FLOPS / 带宽）。每台还要备 6 块：当前 $Q$、当前 $K,V$、正在收的 $K,V$、输出。所以激活 **$6bch$**，**与 $s$ 无关**（Table 1）。于是每台最少序列长 $s=6c$。Table 2 单向带宽：

### 4.4 序列并行与其他并行的组合

序列并行通常与 3D 并行结合使用，形成 **4D 并行**：

```
序列并行(SP) + 张量并行(TP) + 流水线并行(PP) + 数据并行(DP)
```

以 128K 上下文训练为例：
- **TP=8**：节点内拆分 Attention/FFN
- **PP=4**：将模型层分为 4 组
- **SP=2**：将序列分为 2 个片段
- **DP=2**：数据副本数

总 GPU 数 = $8 \times 4 \times 2 \times 2 = 128$ 张 GPU

> **2026-08**：上面 SP=2、128K 是口头 4D 举例。Megatron-LM 那篇 sequence parallelism（§4.5）实验全是 **$s=2048$**，目的是少做激活重计算，不是百万上下文。长序列那条线是 Ulysses / Ring（§4.2–4.3）。三种 SP 不要混成一个旋钮。

### 4.5 Megatron-LM 序列并行（Korthikanti，2205.05198）

Korthikanti、Casper、Lym、McAfee、Andersch、Shoeybi、Catanzaro（NVIDIA）*Reducing Activation Recomputation in Large Transformer Models*（[arXiv:2205.05198](https://ar5iv.labs.arxiv.org/html/2205.05198)，2022-05；进 Megatron-LM / NeMo-Megatron）。**不是** Ulysses，**不是** Ring Attention。这篇要解决的是：张量并行把 Attention / MLP 切开之后，LayerNorm 和 Attention/MLP 后面的 Dropout **仍在每张 TP 卡上复制整段序列**，激活显存把人逼去「整层重计算」。他们加的 sequence parallelism 只切这些 **沿序列维独立、又不适合做 TP** 的算子；注意力仍是 Megatron 式 TP（按头 / 隐层切），不是 All-to-All 换头，也不是环上转 KV。

符号（Table 1）：$s$ 序列，$b$ micro-batch，$h$ 隐层，$a$ 头数，$t$ 张量并行度，$p$ 流水线并行度，$L$ 层数，$v$ 词表。激活按 16-bit、每元素 2 字节计；Dropout mask 1 字节。文内「activations」= 前向产生、反向要用的张量（含 dropout mask），不含参数和优化器状态。小缓冲（LN 的 mean/var）按 $2sb\ll sbh$ 丢掉。

无模型并行时，一层激活（式 (1)）：

$$
sbh\bigl(34+5\tfrac{as}{h}\bigr)
$$

拆账：Attention $11sbh+5as^{2}b$（含 $QK^{\top}$ / softmax / mask / $PV$），MLP $19sbh$（两线性 + GeLU + dropout），两个 LN $4sbh$。$5as/h$ 那一项来自 softmax 变宽之后的二次项。

只做 TP（Shoeybi；Figure 4 的 $f$ / $\bar f$）之后，Attention/MLP **内部**激活按 $t$ 切开，但块入口和 LN/Dropout 仍整段复制。式 (2)：

$$
sbh\bigl(10+\tfrac{24}{t}+5\tfrac{as}{ht}\bigr)
$$

$10sbh$ 就是那些复制算子，**不除 $t$**。

做法（§4.2.2、Figure 5–6）：LN / Dropout 沿 $s$ 切开。进入 TP 区之前、离开 TP 区之后用一对共轭通信 **$g$ / $\bar g$**，不要在 TP 的 all-reduce 外面再加一次集合通信：

| | 前向 | 反向 |
| --- | --- | --- |
| $g$ | All-Gather（沿序列把 LN 输出拼全，供 GEMM） | Reduce-Scatter |
| $\bar g$ | Reduce-Scatter（把两路 GEMM 部分和收成 $s/t$，再 Dropout） | All-Gather |

环 All-Reduce = Reduce-Scatter + All-Gather，所以 **TP 四个 All-Reduce** 和 **TP+SP 四个 AG + 四个 RS** 带宽一样，文内写「不引入额外通信体积」。GEMM 入口那个完整 $Y$ 不存整份：每张卡只留 $Y_i^{s}$，反向再 All-Gather 一次，和 $\partial Y$ 的计算重叠。

于是一层变成式 (1) 除以 $t$（式 (4)）：

$$
\frac{sbh}{t}\bigl(34+5\tfrac{as}{h}\bigr)
$$

流水线（1F1B）：为了压住气泡，**第一段**要存 $p$ 个 micro-batch 的激活；每段 $L/p$ 层，所以第一段仍是 **$L$ 层份**，与 $p$ 无关（式 (5)）：

$$
\frac{sbhL}{t}\bigl(34+5\tfrac{as}{h}\bigr)
$$

交错流水线再乘 $(1+\frac{p-1}{pm})$。词表投影、最后 LN、embedding dropout 相对 34 那一项可忽略（22B 上文内算不到 0.01%）。

**选择性重计算**（§5，Figure 3 红框）：不要整层 checkpoint。只重算 $QK^{\top}$、softmax、softmax dropout、$PV$——FLOPs 低、激活大，对应式 (5) 里的 $5as/h$。剩下 34 那一项存下来。GPT-3（$a{=}96,s{=}2048,h{=}12288$）$5as/h{=}80$，省激活 **70%**，FLOPs 开销 **2.7%**。MT-NLG（$a{=}128,s{=}2048,h{=}20480$）$5as/h{=}64$，省 **65%**，FLOPs **1.6%**。合在一起（式 (6)）：

$$
34\frac{sbhL}{t}
$$

与头数无关，随 $s$ 线性。Table 2 一行对照（字节 / 层）：

| 配置 | 一层激活 |
| --- | --- |
| 无并行 | $sbh(34+5as/h)$ |
| 仅 TP | $sbh(10+24/t+5as/(ht))$ |
| TP+SP | $sbh(34/t+5as/(ht))$ |
| TP + 选择性重计算 | $sbh(10+24/t)$ |
| TP+SP + 选择性重计算 | $sbh(34/t)$ |
| 整层重计算 | $sbh(2)$ |

实验全在 Selene、80GB A100、NVLink/NVSwitch、每节点 8×200Gbps HDR；$s{=}2048$，$v{=}51200$，**$t{=}8$**，**没有 DP**（batch 比端到端训练小）。Table 3：

### 4.6 ColAI-SP / Ring Self-Attention（Li et al.，2105.13120）

Li、Xue、Baranwal、Li、You（新加坡国立大学）*Sequence Parallelism: Long Sequence Training from System Perspective*（预印本 [arXiv:2105.13120](https://ar5iv.labs.arxiv.org/html/2105.13120)，2021-05；正式发表 [ACL 2023 long](https://aclanthology.org/2023.acl-long.134/)，页 2391–2404）。Ulysses 把它叫做 **ColAI-SP**（Li et al. 2022b）。**不是** 2024 的 Ring Attention（§4.3），**不是** Ulysses 的 All-to-All 换头（§4.2），**不是** Megatron-SP 那种跟 TP 绑着切 LN/Dropout（§4.5）。

先分清三件事：

1. **切谁**：整条序列切成 $N$ 段，每卡 $L/N$。Figure 1(c) 写明 **每张卡持有同一份可训练参数**，只是输入子序列不同。Korthikanti（2205.05198）因此说它会复制参数和优化器，不适合大模型——对照的是这篇，不是 Ulysses。
2. **注意力怎么拼**：Ring Self-Attention（RSA）。正文只把双向自注意力写清楚；多头「一视同仁」推广，**没有写因果 mask 的环**。
3. **4D**：摘要说和 DP/PP/TP 兼容、「使 4D 成为可能」；§3.2 / 结论把 **真正接到 4D 留作未来工作**。不要写成他们已经跑过 4D。

记号（§3）：$B$ batch，$L$ 序列，$H$ 隐层，$A$ 头宽，$Z$ 头数，$N$ GPU 数。

RSA 两段（§3.1、Figure 2），**不是**「K 和 V 绑在一起转、在线 softmax」：

1. **先转 K**。$Q^{n}$ 留在本机。先算本地 $Q^{n}(K^{n})^{\top}$，再从上一台收一份 K、算一块，环上走 **$N-1$** 轮。结束时每台有完整分数 $S^{n}\in\mathbb{R}^{L/N\times L}$（列按设备切成 $S^{n}_{i}\in\mathbb{R}^{L/N\times L/N}$）。
2. **再转 V**。用同一套环把 V 转一圈，

$$
O^{n}=S^{n}V=\sum_{i=1}^{N}S^{n}_{i}V_{i}
$$

（式 (4)；HTML 里 $V_{i}=V^{n}$ 是排版笔误，按求和下标读成第 $i$ 份 V。）

所以每台仍要扛一块 **$(L/N)\times L$ 的 $S$**。二次项没消掉，只是除以 $N$。2024 Ring Attention 用块内在线 softmax，激活 $6bch$、**不存**这张 $S$；Related Work 点名的「通信难重叠」就是这套 **先收齐 $S$、再转 V** 的两段环，不是 `ppermute` 那篇。

显存对照 Megatron **张量并行**（Table 1–2，Adam）：

| 块 | TP | 本篇 SP | SP 更省的条件 |
| --- | --- | --- | --- |
| MLP | $\frac{32H^{2}}{N}+\frac{4BLH}{N}+BLH$ | $32H^{2}+\frac{5BLH}{N}$ | $BL>32H$ |
| 多头注意力 | 按头切；$QK^{\top}$ 形状含 $(B,Z/N,L,L)$ | 按 $L$ 切；$S$ 形状含 $(B,Z,L/N,L)$ | $BL>16AZ$ |

MLP 里 SP 的 $32H^{2}$ **不除 $N$**：权重整份复制。注意力里 TP 切头、SP 切长。通信（§3.2.1–3.2.2）：MLP **零通信**；RSA 前向两次环 P2P（算分、算输出），反向两次 All-Reduce + 两次环 P2P。体积前向 $2(N-1)BZ(L/N)A$，反向 $6(N-1)BZ(L/N)A$，合计 **$8(N-1)BZ(L/N)A$**，文内写成和 Megatron TP 四次集合通信的总量一样。Ulysses 把这家记成 $O(M)$：体积随消息变，**不**像 All-to-All 那样每链路再除 $P$。和 PP 接的时候，激活已经按序列切开，流水线级间少一次 split + All-Gather。

### 4.7 Blockwise Parallel Transformer（Liu & Abbeel，2305.19370）

Liu、Abbeel（UC Berkeley）*Blockwise Parallel Transformer for Large Context Models*（预印本 [arXiv:2305.19370](https://arxiv.org/html/2305.19370)，2023-05；NeurIPS 2023 会场标题用复数 *Transformers*）。代码和后来的 Ring 同一仓库：[lhao499/llm_large_context](https://github.com/lhao499/llm_large_context)。**不是** FlashAttention（只把注意力分块，FFN 仍整段），**不是** 2024 Ring（跨机环转 KV），**不是** 序列并行。Related Work 写它和 SP（他们点的是 Korthikanti [2205.05198](https://ar5iv.labs.arxiv.org/html/2205.05198)）是 **正交** 的：SP 把序列拆到多机，BPT 是 **每台机器内部** 对块做注意力+FFN。和 DP/TP 兼容；实验里 **没有开 DP**。

#### 4.7.1 问题：FA / ME 之后瓶颈在 FFN

Vanilla 注意力把 $QK^{\top}$ 和 softmax 物化到 HBM，激活 $O(s^{2})$。FlashAttention（Dao et al. 2022）和 Memory Efficient Attention（Rabe & Staats，[2112.05682](https://arxiv.org/abs/2112.05682)）用在线 softmax，注意力峰值收到 $O(s)$。作者的观察：这时 **FFN 变成主项**——两层线性中间有 $4h$ 宽的激活（文内按 GPT 习惯写 $8bsh$ 字节，bf16）。FA/ME **不管 FFN**，一层仍按 **$8bsh$** 记账。MEA 不是 FA：公式、Table 2 的 59×/32×、与 FA 附录 B.5 的三条差在 [00-MEA](../../../2-核心原理与架构/2.3-高效与稀疏注意力/2.3.1-硬件高效注意力/00-Memory-Efficient-Attention/01-MEA-显存高效注意力.md)。

BPT 的一步：外层按 query 块 $B_{q}$ 扫，内层按 KV 块 $B_{kv}$ 扫；每个 $Q_{i}$ 用在线 softmax 拼出 **全局** 注意力之后，**立刻**在这块上做 FFN 和残差，不等整段注意力算完。HTML 式：

$$
\mathrm{Output}_{i}=\mathrm{FFN}\bigl(\mathrm{Attention}(Q_{i},K,V)+Q_{i}\bigr)+\mathrm{Attention}(Q_{i},K,V)+Q_{i}.
$$

注意力仍是精确的（块间用 max / 分子 / 分母缩放，和 FA 同一条线）。也可以把同样的分块套到最后的交叉熵，正文提了一句，没有单独的表。

实现（Figure 3 / Appendix）：JAX `lax.scan` + `jax.checkpoint`。`blockwise_attn` 外层扫 query chunk，内层 `scan_kv_block` 更新 numerator / denominator / max；bias 按 chunk 下标加，不物化整张 mask。`blockwise_ffn` 把序列 `rearrange` 成 chunk 再 scan 一个 rematerialized FFN。作者自己写：这是 **高层 JAX，优先简单**；要峰值吞吐得再下 CUDA / Triton。不要把它写成已经替换了 FA 的生产核。

#### 4.7.2 一层激活：$2bsh$，不是跨机

§3.1 按 **有 checkpoint、bf16 字节** 记账（$b$ batch，$s$ 序列，$h$ 隐层，$c$ 块长，$a$ 头数）：

| | 注意力峰值 | FFN 峰值 | 一层 |
| --- | --- | --- | --- |
| Vanilla | $O(s^{2})$（物化 $QK^{\top}$） | $8bsh$ | 长序列被 $O(s^{2})$ 盖住 |
| FA / ME | $2bsh$ | 仍 $8bsh$（整段 FFN） | **$8bsh$** |
| BPT | KV 环内 $4bch$；query 输出 $2bsh$。$s\gg c$ 时 **$2bsh$** | 块上 FFN $19bch$ + 循环输出 $2bsh$。$s\gg c$ 时 **$2bsh$** | **$2bsh$** |

$8bsh/2bsh=4$。这是 **激活** 比，不是参数+优化器。加上后两项，作者只敢写上下文能到先前 SOTA 的 **2–4×**，不要把 4× 激活直接说成 4× 上下文。

层间输出仍要 **$2bsh$** 给下一层做 $n$ 对 $n$ 注意力。所以单卡 BPT 把一层收干净之后，超长序列还是要 **Ring**（§4.3）把序列维切到多机。BPT **不是** 设备环：没有 `ppermute`。

SRAM 对 HBM 更快、块内算得动，这条和 FA/ME 同一句话，不是新硬件故事。

## 5. 激活Checkpoint(Activation Checkpointing)

### 5.1 核心原理

激活Checkpoint(又称梯度Checkpoint Gradient Checkpointing)是一种**用计算换显存**的技术. 在标准前向传播中，每一层都会保存中间激活值(Activations)用于反向传播计算梯度. 这些激活值可能占用大量显存——对于一个 70B 模型，单层激活值可能达到 GB 级别. 

激活Checkpoint的核心思想：**在前向传播时丢弃大部分中间激活值，在反向传播时重新计算它们**. 

```
标准模式：
前向 → 保存激活 A1 → 保存激活 A2 → ... → 保存激活 An → 损失
反向 → 使用 A1 计算梯度 → 使用 A2 计算梯度 → ...

Checkpoint模式：
前向 → 不保存激活 → 不保存激活 → ... → 不保存激活 → 损失
反向 → 重新计算激活 A1 → 使用 A1 计算梯度 → 重新计算 A2 → ...
```

### 5.2 计算与显存的权衡

| 策略 | 激活显存占用 | 额外计算开销 | 适用场景 |
|:----|:-----------|:-----------|:--------|
| 无Checkpoint | 最高 | 无 | 显存充足的短序列训练 |
| 选择性Checkpoint | 中等 | ~15-20% | 显存有限的通用场景 |
| 全Checkpoint | 最低 | ~30-33% | 显存极度紧缺的超大模型 |

**选择性Checkpoint**：不是对所有层做Checkpoint，而是对**显存占用大、计算量相对小**的层做Checkpoint. 例如：
- Attention 层：激活占用大，但重计算开销相对较小 → **适合做Checkpoint**
- FFN 层：激活占用大，但重计算开销也大 → **可做可不做**
- Embedding 层：激活占用小 → **不Checkpoint**

> **2026-08 修订（不删上文）。** 上表「全 Checkpoint ~30–33%」接近 Korthikanti 文内观察到的整层重计算 **30–40%** 时间开销（Table 4 的 22B 一层是 **39%**，不是 33% 理论值；他们归因于反向里 All-Reduce 与权重梯度重叠，重计算打乱了重叠）。「按层选哪些层 checkpoint」文内写 MT-NLG 每卡只有三层，粒度不够。他们的 **selective activation recomputation** 是层内选算子：只重算 $QK^{\top}$ / softmax / dropout / $PV$，GPT-3 省激活 70%、FLOPs +2.7%；加上 sequence parallelism 之后 22B 合计开销 **4%**，530B/1T **2%**。数字和式 (6) 在 §4.5，这里不重抄 Table 5。

### 5.3 实现方式

PyTorch 提供了 `torch.utils.checkpoint.checkpoint` 函数，可以轻松包装需要Checkpoint的模块：

```python
import torch.utils.checkpoint as checkpoint

class TransformerBlock(nn.Module):
    def forward(self, x):
        # 包装需要Checkpoint的计算
        def custom_forward(*inputs):
            x = self.attention(inputs[0])
            x = self.ffn(x)
            return x
        return checkpoint.checkpoint(custom_forward, x)
```

在 DeepSpeed 和 Megatron 框架中，激活Checkpoint是内置功能，通过配置文件即可启用：

```json
// DeepSpeed 配置
{
    "activation_checkpointing": {
        "partition_activations": true,
        "number_checkpoints": 100,
        "cpu_checkpointing": false
    }
}
```

## 6. 三大主流框架对比：FSDP2 vs DeepSpeed vs Megatron-LM

当前大模型分布式训练的三个主流框架各有侧重，选型取决于模型规模、团队技术栈和硬件条件. 

### 6.1 框架定位

| 框架 | 出身 | 核心定位 | 设计哲学 |
|:----|:----|:--------|:--------|
| **FSDP2** | PyTorch 官方(2023) | 易用性优先的通用型框架 | 0 代码侵入，原生兼容 |
| **DeepSpeed** | 微软+清华 | 极致显存效率和性能 | ZeRO 优化，显存榨干机 |
| **Megatron-LM** | NVIDIA | 超大模型工业级并行 | 稳定性第一，千亿/万亿级 |

### 6.2 全面对比

| 对比维度 | FSDP2 | DeepSpeed | Megatron-LM |
|:--------|:-----|:---------|:-----------|
| **代码侵入性** | **0 侵入** — 原生 PyTorch 模型直接封装 | 中侵入 — 需修改模型 + JSON 配置文件 | **高侵入** — 需按 Megatron 规范重写模型 |
| **学习成本** | 极低 — 会 PyTorch 就会用 | 中 — 需理解 ZeRO 配置 | 极高 — 需理解并行逻辑 + 重写模型 |
| **并行体系** | DP 为主，原生组合 TP/PP/EP | 四维并行(DP+TP+PP+ZeRO+EP) | TP/PP 优先，三维并行 |
| **显存优化** | 全分片(对标 ZeRO-2/3) | **ZeRO 系列绝对第一**(1/2/3/Offload/Infinity) | 张量分片 + 专家隔离 |
| **训练性能** | 优秀(比 FSDP1 快 30%+) | **极致**(通信压缩 + 梯度量化) | **顶尖**(TP/PP 效率最高) |
| **超大模型** | 千亿级可应对 | **万亿级可应对**(ZeRO-Infinity) | **万亿级最稳定** |
| **MoE 支持** | 动态+细粒度 | 静态+动态混合，负载均衡最优 | 静态+粗粒度，TP 强绑定 |
| **硬件兼容** | 全兼容(NVIDIA/AMD/CPU) | 主要 NVIDIA | **仅 NVIDIA** |
| **社区活跃度** | PyTorch 官方，持续迭代 | 微软维护，文档完善 | NVIDIA 维护，企业级支持 |

### 6.3 选型建议

| 场景 | 推荐框架 | 理由 |
|:----|:--------|:-----|
| **个人/小团队**中小模型(7B~70B) | **FSDP2** | 0 侵入，学习成本最低，落地最快 |
| **大厂**千亿级模型(GPT-3 规模) | **Megatron-LM** | TP/PP 稳定性天花板 |
| **MoE 超大模型**(1.6T+) | **DeepSpeed** | ZeRO + EP 极致优化 |
| **多框架混用** | DeepSpeed + Megatron | DeepSpeed ZeRO + Megatron TP/PP |
| **快速迭代验证** | FSDP2 | 换模型不改代码，实验速度快 |

**核心判断原则**：
- 如果团队**熟悉 PyTorch**，96% 的场景选 **FSDP2** 即可
- 如果追求 **极致性能+显存**，选 **DeepSpeed**
- 如果训练 **万亿级模型**，选 **Megatron-LM**
- **三者可以混用**，各取所长

ZeRO 系列优化器，就能针对不同模型规模和硬件条件设计最合适的最佳训练方案.
