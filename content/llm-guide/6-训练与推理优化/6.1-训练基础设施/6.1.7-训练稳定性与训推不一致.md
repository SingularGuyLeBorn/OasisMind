# 6.1.7 训练稳定性与训推不一致

> 接 [6.1](./6.1-训练基础设施.md) · [6.1.1 分布式](./6.1.1-分布式训练/6.1.1-分布式训练.md) · [05-MuonClip 与 Polar Express](../6.5-优化器/Muon/05-MuonClip与PolarExpress.md) · [03-MXFP4 与 NVFP4](./6.1.2-混合精度训练/03-MXFP4与NVFP4.md)。第 14 章只记「这次发布捆了哪几招」，公式与失效条件写在本篇。

Loss 曲线突然竖起来，和 RL 里 policy 突然崩，看起来都像「训练炸了」。报告里这两件事经常分开写：**稳定性**是前向/反向自己在同一套引擎里发散；**训推不一致**是采样引擎和训练引擎、训练精度和部署精度、随机 top-k 和确定性 top-k **不是同一个算子**。中间那条虚线标的是「不是同一个 bug」。

## 1. 先拆开：两条轴，不要混着用同一剂药

| 轴 | 发生在哪 | 典型症状 | 报告里怎么处理 | 不要当成 |
|----|----------|----------|----------------|----------|
| **稳定性** | 同一套训练图：激活、路由、优化器、精度 | 不可恢复 loss spike；专家几乎只吃一个人；BF16 累加尖峰 | 改初始化/路由时序、clip 激活、换 polar 精度、MuonClip | 「多跑几次就好了」 |
| **训推不一致** | 训练图 vs 采样/部署图 | RL 几步后熵塌、重要性比爆炸、部署比评测差一截 | QAT 让 rollout=训练量化；IcePop / MIS-PO 丢掉离群 token；确定性 `torch.topk`；batch-invariant kernel | 当成 loss spike 去 rollback |

PD 分离（prefill / decode 拆服务）是**推理栈调度**，本体在 [9.4.1](../../9-AI工程化与基础设施/9.4-推理服务框架/9.4.1-SGLang与Prefill-Decode分离.md)，**不是**本篇的训推轴。MTP 训练目标改成 draft 头，才算训推。

## 2. 稳定性：loss spike、专家崩、数值

### 2.1 可恢复 vs 不可恢复

DeepSeek-V3 预训练 14.8T，报告原句：全程 **没有遇到不可恢复的 loss spike，也没有 rollback**（[V3 mineru](../../14-主流开源模型全景解析与技术报告精读/14.1-DeepSeek/05-DeepSeek-V3/04-DeepSeek-V3-mineru-zh.md)）。这句话的信息量是「他们把不可恢复尖峰当成事故」，不是「loss 曲线永远光滑」。

V4 系列把口径改了。同一份系列报告（HF `DeepSeek_V4.pdf`，库内 [D2](../../14-主流开源模型全景解析与技术报告精读/14.1-DeepSeek/10-DeepSeek-V4/01-DeepSeek-V4技术报告精译.md) 与 mineru §4.2.3）写：万亿 MoE **会遇到明显不稳定性**；简单 rollback 只能暂时救现场，**挡不住尖峰再来**。经验上尖峰绑在 MoE 层异常值，路由会把异常值放大。他们从两头拆：打断路由正反馈，以及直接掐异常激活。

Kimi K2 走第三条路：不靠 rollback 叙事，而靠 **MuonClip** 把注意力 logits 钉住。$\tau=100$，15.5T，报告称 **零 loss spike**；前 70,000 步约 12.7% 的头至少触发过一次 QK-Clip，之后 $S_{\max}$ 进阈值、clip 失效。公式与失效条件在 [05-MuonClip](../6.5-优化器/Muon/05-MuonClip与PolarExpress.md)，本篇不重抄 Algorithm 1。

### 2.2 专家崩：路由正反馈

「专家崩」不是饼图好看不好看，是 **gate 把几乎所有 token 送给少数专家**，其余专家梯度饿死，All-to-All 还在按最忙那张卡排队。V4 的经验句：尖峰 **始终与 MoE 层异常值相关，路由本身加剧异常值**。

**Anticipatory Routing（预判路由）。** 步骤 $t$ 用当前参数 $\theta_t$ 算特征，但路由下标用历史参数 $\theta_{t-\Delta t}$ 算并应用。为了避免加载两遍权重，他们在 $t-\Delta t$ 就把 $t$ 步的数据提前取来，先算出路由缓存。基础设施上把这次前向跟 EP 通信重叠，额外 wall-clock **约 20%**。更关键的是 **按需开启**：自动检测到 spike 才短 rollback 并打开预判路由，跑一段时间再退回标准训练。报告承认机制的完整理论仍是开放问题。

这不是新的 $p_i$ 公式，不要写成一种新 MoE。负载均衡本体仍在 [2.4.1](../../2-核心原理与架构/2.4-前沿架构与变体/2.4.1-混合专家模型MoE/2.4.1-混合专家模型MoE.md)；V4 的 bias 更新速度 0.001、单序列平衡损失权重 0.0001 写在同一份报告的 Flash/Pro 训练设置段。

Step-3.5-Flash 把 MoE 稳定性接到 RL：用 **Routing Confidence**（激活专家概率质量的平均）当代理。低置信 = 路由不确定，会放大训推差；高置信才敢做更 off-policy 的更新。细节在 [Step-3.5-Flash D2](../../14-主流开源模型全景解析与技术报告精读/14.7-StepFun/03-Step-3.5-Flash/01-Step-3.5-Flash技术报告精译.md)，本篇只收「监控什么」。

### 2.3 数值：clip 激活，而不是只换 BF16

图里 FP16 → BF16 只覆盖 **动态范围**。2026 报告里还有两类更具体的事故：

**SwiGLU Clamping（V4 Flash 与 Pro 全程）。** 线性支路截到 $[-10,10]$，gate 支路上限 10。报告写：消异常值、大幅稳住训练、不损害他们观测到的性能；原理同样「尚未充分理解」。不要把 SiTU-GLU 的光滑有界（K3，[01-SiTU-GLU](../../2-核心原理与架构/2.1-深度学习基础组件/2.1.1-前馈网络FFN与激活函数/01-SiTU-GLU/01-SiTU-GLU.md)）写成 V4 的 hard clamp——K3 明确不用 hard clamp，理由是边界梯度被掐死。

**Polar Express 的 BF16 加法累积。** Step-3.5-Flash 记录过不可恢复 spike，对策是把 Polar Express **中间量改成 float16**（不是把整个模型改回 FP16）。对照与多项式次数在 [05 文 §2.3](../6.5-优化器/Muon/05-MuonClip与PolarExpress.md)。

6.1 总览 §7.2 的 Loss Scaling / FP8 格式选错，仍是混合精度课，本篇不重复推导。

## 3. 训推不一致：同一权重，两张计算图

训练时 $\pi_{\text{train}}$ 在用 PyTorch 图 + 某种 top-k + 某种量化；rollout / 线上在用另一套 kernel。RL 的重要性比把这个差放大成梯度噪声。

### 3.1 量化：让 rollout 走训练时的假量化

V4 后训练对 **路由专家**做 FP4 QAT（MXFP4 格式本体在 [03](./6.1.2-混合精度训练/03-MXFP4与NVFP4.md)）：FP32 master → 量化到 FP4 → **无损**反量化成 FP8 再前向；STE 把梯度送回 master。推理和 **RL rollout 直接用原生 FP4 权重**，行为跟部署对齐。报告另外提供 **batch-invariant、确定性 kernel**，目标是训练与推理之间逐位可复现——这是 infra，不是又一种量化格式。

Kimi K3 从 SFT 起 QAT：专家 **MXFP4 权重 / MXFP8 激活**，非专家更高精度；**RL rollout 与训练同一套量化**（[K3 D2 §4.1.4](../../14-主流开源模型全景解析与技术报告精读/14.5-Kimi/05-Kimi-K3/01-Kimi-K3-架构精译.md)）。不要把 K3 的 MXFP8 激活抄成 V4 的专家 MXFP4。

### 3.2 IcePop：按比率丢掉离群 token

GLM-5 在 GRPO 上显式区分训练策略与推理策略。不匹配比率（库内 [4.5 链路文](../../4-后训练/4.5-推理与思考能力/01-Agentic能力训练：从GLM-5看基座大模型的完整链路.md) 与 [GLM-5 D2](../../14-主流开源模型全景解析与技术报告精读/14.6-GLM/08-GLM-5/01-GLM-5技术报告精译.md)）：

$$
\rho_{i,t}=\frac{\pi_{\theta_{\mathrm{old}}}^{\mathrm{train}}(y_{i,t}\mid x,y_{i,<t})}{\pi_{\theta_{\mathrm{old}}}^{\mathrm{infer}}(y_{i,t}\mid x,y_{i,<t})}
$$

pop 把落在 $[1/\beta,\beta]$ 之外的 $\rho$ 置零（等价于这些 token 不进梯度）。GLM-5 相对原始 IcePop **去掉 KL 项**，用 pop 区间和 clip $[0.8,1.28]$ 顶住漂移。这是 **RL 目标函数层**的训推对策，不是预训练 clip。

### 3.3 确定性 top-k：同一输入必须选出同一批索引

DSA / 稀疏 indexer 的 top-k 决定「看见哪些上下文」。GLM-5：SGLang DSA indexer 的非确定性 CUDA top-k，在 RL **几步**后性能骤降、熵塌；改用朴素 `torch.topk`（慢、确定）后 RL 才稳住。他们还 **默认冻结 indexer**，避免检索模块自己漂。

这和左列「专家崩」共用 top-k 这个词，但一个是 **训练图内部负载**，一个是 **训练图 vs 推理图选中的集合不同**。图中虚线就是这个意思。

### 3.4 MIS-PO：用二元掩码代替连续重要性权重

Step-3.5-Flash 的 MIS-PO（Metropolis Independence Sampling-Filtered Policy Optimization）：把推理策略当提议分布、训练策略当目标，**token 级 + 轨迹级**二元掩码丢掉离分布样本，留下的当作近似 on-policy。报告对照 PPO：actor 梯度范数噪声更低；对照 GSPO：更能把 $\pi_{\theta_{\mathrm{old}}}/\pi_{\theta_{\mathrm{vllm}}}$ 这类训推密度比钉在稳定区间。公式与消融在该家族 D2，本篇不把 MIS 的 MCMC 证明重写一遍。

### 3.5 稀疏与 MTP：训练课表本身就是在对齐部署

V4-Flash：前 **1T** token 用稠密注意力预热，到 64K 序列长度才引入稀疏；引入时先短阶段预热 CSA 的 lightning indexer，再稀疏到底。这是 **训练课表对齐稀疏部署**，不是推理投机。

K3 把 MTP 层微调成 **EAGLE-3 draft**，优化目标是接受率而不是 KL——训练头的职责改成「给推理投机用」。投机解码本体在 [6.6.2](../6.6-推理框架与高级优化/6.6.2-投机解码/6.6.2-投机解码.md)。

## 4. EP / CP 不在本篇重开教材

并行维度的公式已经写在 6.1 总览的 V4 段和 6.1.1：

- **EP Wave**：通信可隐藏当 $C/B \le V_{\mathrm{comp}}/V_{\mathrm{comm}}$；V4-Pro 简化为 $C/B \le 2d=6144$ FLOPs/Byte（6.1 §7.5）。MoonEP 只在 6.1 文末做指针，不另起 EP 课。
- **CP 两阶段**（压缩注意力）：边界未压缩 KV 交换，再 All-Gather + Select-and-Pad；因果靠可见范围 $s < \lfloor t/m \rfloor$。6.1.1 2026-08 节复述，避免只躺在第 14 章。
- **KDA 的 KCP**：不能对「从零算的局部状态」直接求和，要交换累积转移矩阵再 prefix scan。式在 K3 D2 §9。

本篇只回答：稳定性/训推出问题时，**先分清是数值/路由，还是两套引擎**，再决定是去 clip、去 QAT，还是去对 kernel。

## 5. 失效条件（写进体系章才算讲透）

- 把 V3「无不可恢复 spike」抄到 V4。V4 明确遇到过，并且说 rollback 不够。
- 把 Anticipatory Routing 当成新的 gate 公式，或当成一直开着的 20% 税（报告是 spike 时才开）。
- 把 SwiGLU $[-10,10]$ 抄到 SiTU-GLU，或反过来。
- 把 IcePop 的 pop 当成预训练梯度裁剪。
- 为 V4-Flash 另开第 14 章目录：Flash 与 Pro 在**同一份系列报告**里，规格见下节指针，**B 档不 mkdir**。
- 用 PD 分离解释 RL 熵塌。
