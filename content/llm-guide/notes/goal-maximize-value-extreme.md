# Goal：把 2025 年写的个人读书笔记接到 2026 年 8 月，并把知识体系补完整

把下面整份 brief **原样当作 Goal 的 objective**。用户会把本文件 **反复粘贴** 到新会话。聊天记录会被压缩、会丢。**以磁盘上的活文档为准，不要靠「我记得上次做到哪」。**

## 重复投喂时的第一条动作（写任何笔记之前）

按顺序 Read，禁止跳过：

1. `content/llm-guide/notes/live/GOAL.md`
2. `content/llm-guide/notes/live/PLAN.md`
3. `content/llm-guide/notes/live/PROCESS.md`
4. `content/llm-guide/notes/live/README.md`（只在第一次或忘了规矩时）
5. 需要细则再读本文件其余章节

然后从 `PLAN.md` 的「下一步 3 件」继续。**禁止**每次都从「全库盘点 / P0-A」重来，除非 PLAN 明确写着盘点尚未开始。

每写完 **一篇** 笔记，或连续工作感觉在「凭印象写」时：再读一遍 `GOAL.md` + `PLAN.md`，并追加 `PROCESS.md`。这是抗漂移，不是可选仪式。

**你不用等人选方案。** 技术决策自己拍板。用户要的是笔记完整、准确、有来源。

## 0. 这是什么、不是什么

这是作者 **2025 年写下、一直在长的个人大模型读书笔记**（花园 `content/llm-guide/`）。现在是 **2026-08-30**。一年多里模型、论文、工程常识都变了；当年写的提纲有一批还没写成正文；有些图只留了 prompt，图本身没生成。

成功标准有六件，必须同时成立：

1. **补写**：作者已经写了「要写什么」（六段提纲、空壳 D2/D5、`状态: 待完善`、目录承诺的专文），正文按提纲写满。不要另起炉灶改结构。
2. **配图（必须自绘、禁止水印）**：文里的 prompt / `IMAGE PLACEHOLDER` / `图片占位建议` 全部用 Cursor `GenerateImage` **重新生成**并嵌入。禁止把网页/论文/公众号带水印、带 Logo、带「来源」角标的图直接下下来当配图。已有图若带水印：保留旧文件（不删），新生成一张无水印的替换正文引用。prompt 改成 HTML 注释留着。
3. **校正并接到 2026-08**：过时的全景、时间线、默认假设、已被后文打脸的断言，**折进主叙述**，读者只读一版完整正文。禁止把「修订（不删上文）」当成品。数字与代际必须先 `WebSearch` / 官方页，禁止用 2025 记忆硬写。
4. **知识体系完整（含 GPU / Infra，尽可能不遗漏）**：骨干不断档 + 概念住在体系章 + 每章真地图 + 2026-08 的轴都有落点。**第 9 章 GPU 与基础设施和第 6 章训练/推理优化是体系的硬轴，不是附录。** 防遗漏清单见第 0.2 节。
5. **以顶尖技术报告为轴，拆清每一条技术，不是给模型做名片**：一份能发布的模型报告里，通常绑着架构、积木、数据、优化器、infra、训练框架、稳定性事故与对策、训推不一致。顺着这些面找到 **每条技术的来源、演进、数学推导**，写进体系章；模型目录只当「这一次发布捆了哪些技术」。数字/公式/日期/基准必须来自读过的源。读者目标：初学者能顺着图和推导看懂，已经会的人不必看注水。纪律见第 0.4 节。
6. **2026 年重要发布必须进库（现在差很远）**：2026 出了一大波模型，不能停在「目录里有个 2025 壳」。你 **自己判断** 哪些是架构代际 / 新 trick / 新 infra（S/A 档），读官方技术报告精读，按 0.4 拆进体系。SKU 变体（同一报告的 Flash/mini）不要每个都开空文件夹。作者点名候选与判断标准见第 0.6 节。

**这不是商品。不要做售卖包装。** 不要写 `COMMERCIAL-SLICE`、付费切片、上架方案、君子协定产品化、12 周训练营、面试课大纲。`致读者` 里已有的君子协定原文 **一个字都不要删**，但也不要顺着它去设计商业闭环。

也 **不要** 把这次 Goal 做成「准备发 GitHub」：不写 PUBLIC-SLICE、如何贡献、如何引用、整库 LICENSE。来源可追溯、日期清楚、索引不把空壳算完成——那是笔记对自己诚实，不是开源立项。

**一篇可验收切片做完就 commit**（`content(llm-guide): …`），不要 `git add -A`。不要 push。不要改 `git config`。

### 0.3 多搜索（中英文都搜，事实用搜索，图自己画）

作者开了代理，**流量充足**。不要因为「中文结果已经够写一段」就停。英文论文、官方博客、OpenReview、工程博客往往才是 trick 的出处。

- 搜什么：技术名 + 原始论文；模型报告里点名的组件；口述缩写的**全称和别名**（见 0.7：mHC、XHC、AttnRes、MuonClip）；「loss spike / training instability / MoE load imbalance / train-inference mismatch」这类事故词。
- 语言：**中英文并列**，默认先英文源再中文解析。中文自媒体只当索引，不当时事实。
- 搜索是为了 **找到要读的原文** 和 **发现主题树遗漏**，不是为了盗图。
- 拿不准是否主流：搜；是就写进体系章；传闻就在 PROCESS 标未核实，不要建空目录。
- 课表/讲法白名单与抄袭禁令：`notes/trusted-sources.md`。对覆盖面时 Read 它。**课程不是金科玉律**（CS336 也只是某一学期快照）；不要把讲义当年的「最新」写进 2026-08 正文。事实冲突以一手报告为准。

### 0.4 从技术报告拆技术（违反 = 这篇笔记不合格）

补体系 **不是**「每个模型写一张规格名片」。顶尖模型能发布，是因为架构、数据、infra、训练框架、训推不一致、稳定性事故 **都被处理过**。技术报告里藏着大量细节。**以报告为轴，按技术把世界摊开。**

一个模型对应 **多条** 技术；一条技术也会出现在多个模型里。本体写在体系章，模型文只点名「这次用了它、和前代差在哪」，链回本体。

#### 从一份报告必须拆出的面（缺一面就去搜，不要假装没有）

| 面 | 要落到笔记里的东西 |
|----|-------------------|
| **组件积木** | 注意力变体、归一化、残差、FFN、位置编码、MoE 路由……来源论文 + 公式 |
| **模型架构** | 层配置、稀疏/混合、多 token、视觉/语音塔；为什么这样叠 |
| **数据处理** | 配比、清洗、合成、tokenizer、packing；报告里写了什么、没写什么 |
| **优化器与目标** | AdamW/Muon/…、学习率、损失、RL 算法；公式和适用条件 |
| **Infra / 训练框架** | 并行（DP/TP/PP/EP/CP）、精度、流水线、通信、框架名（Megatron/DeepSpeed/自研） |
| **训练稳定性** | **出过什么问题**（loss spike、专家崩、数值溢出、过拟合某域）以及 **怎么解决的**（改初始化、改路由、改精度、改数据） |
| **训推不一致** | 训练时和推理时不一样的地方（MTP、量化、投机、PD 分离、采样）以及他们怎么对齐 |

拆完一条技术，必须能回答：它解决什么瓶颈、数学上怎么来的（给初学者的完整推导，不跳步、不注水）、最早谁提出、后来谁改了什么、在这份报告里怎么用、何时会失效。图要跟上（自绘/mermaid/表）。

#### 读什么（写作前写入 PROCESS 台账；没进台账的数字不准写）

| 优先级 | 读什么 | 怎么找 |
|--------|--------|--------|
| 1 | **该次发布的技术报告 / 原论文**（轴心） | arXiv、官方 GitHub PDF（本库 `pdfs/` 已有的直接读，**不要为凑 D3 再 OCR 进 git**）、OpenReview |
| 2 | **报告点名的前作**（演进链） | 报告参考文献里的 RoPE/FlashAttention/GQA/PPO…逐条搜原文，不要用记忆讲家谱 |
| 3 | **官方 blog / system card / model card** | 官网、HF、GitHub README |
| 4 | **顶会顶刊版本** | ICLR / ICML / NeurIPS / EMNLP / ACL / TMLR；注意与 arXiv 初稿的差异 |
| 5 | **中英文靠谱解析** | 英文：Lilian Weng、Raschka、SemiAnalysis、官方工程博客、可核对的 lecture notes。中文：苏剑林等可对原文的精读。二次文献有冲突以 1–3 为准 |

预训练知识只允许用来 **决定搜什么关键字**，不准用来填公式、规格、日期、基准。

**禁止：**

- 凭「我训练数据里见过 MLA」直接写公式和规格。
- 只搜中文、或只写模型名字不拆技术。
- 把同一 trick 在第 14 章每个模型里复制粘贴，体系章却是空的。
- 把解析文的配图（含水印）存进本库。
- 把整篇版权 PDF 再 OCR 一份塞进 git。

**每篇笔记文末（或文首）加「本篇来源」**：至少 1 条一手 + 演进链上你实际打开过的前作/解析。数字必须能指回其中某一条。

找不到一手来源：写「未找到一手来源」+ `[OM-FREEPLAY]`，宁可薄，不要用记忆补全。

#### 文风：给初学者看懂，仿科学空间，不要碎片标题

反模式有两个：

1. **懂的人不需要看，不懂的人看不懂。**
2. **一个标题下面只有一句话**（或一句加一个列表），整篇像目录碎片。这完全不行。

正向标准：

- **布局仿苏剑林老师的科学空间**（kexue.fm / spaces.ac.cn）：先有具体问题，再讲已有做法差在哪，再给想法和公式，最后讨论边界。每一节是一块完整想法，篇幅适中——大约能读完一个机制，不要写成论文式十几级空标题，也不要一整章没有小标题的墙。
- 推导写全：符号先定义，从动机到公式一步步来；已经在上文推过的不要换个说法再推一遍，链回去。
- 图文并茂：关键机制至少一张图或一张表，嵌在该节论证里，不要所有图堆文末。
- 禁止先写 800 字「为什么重要 / 家谱定位」；直接进入问题。
- 对齐样本：科学空间的行文节奏 + 本库 `2.1.4/.../01-RoPE本体-旋转位置编码/01-RoPE本体-旋转位置编码.md`、`14.1/.../05-DeepSeek-V3-MLA.md`。

交工时必须多一篇体系地图：

`content/llm-guide/1-导论与基础/1.1-学习路线与知识图谱/知识图谱-2026-08.md`

mermaid 必须画出 **第 6 章与第 9 章**。再加骨干概念表（只链非空壳）。

### 0.6 2026 模型浪潮：自己判断重要性，精读报告，拆进知识库

2026 年发布非常密。作者点名的只是 **候选清单**，不是「每个尺寸都建空目录」。你必须：中英文搜到 **官方名称 + 技术报告或 system card** → 按下面标准分级 → S/A 精读拆技术 → 写进第 14/5 章并反链体系章。

**2026-08-30 库水位（差很远，必须复核）：** 第 14 章大约停在 Qwen3.7、Kimi-K2.6、DeepSeek-V4、GLM-5.1 / 5V-Turbo、GPT-5.5、Claude Mythos / Opus-4.7、Step-3.5-Flash、Llama-4。作者点的 3.8 / Flash Next、K3、K2.7 coding、GPT-5.6、Opus 5 / Fable、Meta Muse、GLM-5.3 Flash、V4 Flash 正式版等，多数还没有按 0.4 拆过的精读。

#### 怎么自己判断（不准问用户「要不要写这个」）
