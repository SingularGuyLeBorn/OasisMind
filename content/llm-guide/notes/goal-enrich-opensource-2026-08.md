# Goal：把 llm-guide 补到「能开源」——其实是把读书笔记补丰满

把下面整份 brief **原样当作 Goal 的 objective**。新开 worktree。只动 `content/llm-guide/` 与其配图（`images/`、`content/uploads/llm-guide/`）。不要改 OasisMind 产品代码，除非不改就无法写进花园。

---

## 0. 你是谁、成功长什么样

你在修作者的**个人大模型读书笔记**（花园 `content/llm-guide/`）。对外叙事可以叫「整理到能开源」；**真正成功标准是知识体系更完整、接到 2026-08-30，而不是真的发 GitHub。** 开源只是质量条：来源可追溯、日期清楚、占位写完、图补上、索引不撒谎。

完成时必须同时成立：

1. 作者已经写了提纲、还没写的正文，已经按提纲写满。
2. 已经写了配图 prompt / `IMAGE PLACEHOLDER` 的图，已经生成并嵌入，prompt 以 HTML 注释留着可再生成。
3. 原理 / 后训练 / Agent / 推理优化等**体系章节**已接到 2026 年 8 月底，而不是只停在 2025 或 2025 年初。
4. 第 14 章家族树补上 2026 年中后沿模型（先核实再写，禁止编造发布日和分数）。
5. **一个字都没删。** 包括 mineru 全文、微信转载、飞书搬迁、`unused_*.jpg`、空壳在写满之前的旧提纲、重复的第 5 章和第 14 章。
6. 仓库里多一篇进度账：`content/llm-guide/notes/2026-08-enrichment-log.md`，记录新建了什么、补了什么、图放在哪、哪些 2026 条目因找不到一手来源而标了 `[OM-FREEPLAY]`。

**不要提交 git，除非用户后来说提交。** 不要 `git add -A`。不要改 `git config`。

## 1. 死命令（违反 = 这次 Goal 失败）

### 1.1 禁止删除

- 禁止 `Delete`、禁止把文件移出仓库当「清理」。
- 禁止删 mineru、pdf、微信图文、飞书《The Document is All You Need》、第 1 章那 160+ 张图、`unused_*.jpg`、空的 `pdfs/README.md`。
- 禁止为了「开源干净」合并第 5 章和第 14 章、禁止删 Ernie/Erine 任一侧。只许**加指针**：「拼写变体见另一目录」。
- 禁止把长文「去 AI 腔」重写成短文而丢掉原段落。允许**追加** 2026 修订节，允许修明显错字（如「范公公式子」→「范式」），允许把占位换成正文。
- 禁止用新文件替换旧文件时丢掉旧内容。更新用补丁（在原文件里写），不要另起一份然后让旧的变孤儿。

### 1.2 怎么写新内容

- 中文正文，英文标识符。frontmatter 对齐邻居文章（`title` / `date` / `tags`；新文 `date: 2026-08-30`，并在文首或文末写 `as_of: 2026-08-30`）。
- 数字、基准、价格、参数量必须有一手链接（arxiv、官方博客、model card、官方 GitHub）。找不到就写「未找到一手来源」+ `[OM-FREEPLAY]`，不要编。
- 文风对齐**最好的笔记**，不是最灌水的百科：
  - 好：`2.1.4/01-RoPE本体-旋转位置编码/01-RoPE本体-旋转位置编码.md`、`14.1/.../05-DeepSeek-V3-MLA.md`、精译里的「译者注」。
  - 差：先写 800 字「为什么重要 / 家谱定位」再进入正题。新文直接讲机制、公式、工程取舍、和旧章节的关系。
- 公式用 LaTeX。结构图优先 mermaid；热力图 / 几何示意图才用生成图。
- 用户没点名的超时、默认值、猜测标 `[OM-FREEPLAY]`。
- Cursor 代理直接改 Markdown 事实源。新建文章放在现有目录树里，slug/路径跟邻居一致。不要为了写笔记去改 `apps/`。
- PowerShell 没有 `&&`：用 `;`。不要 `git add -A`。

### 1.3 先盘点再写

开工第一件事：扫 `content/llm-guide/`，产出账本第一节「盘点」，再动手。至少统计：

- `[待补充` / `状态: 待完善` / `状态: pending` 的文件列表
- `GPT-Image-2 Prompt` / `配图建议` / `IMAGE PLACEHOLDER` / `图片占位` 的文件与条数
- 第 14 章各家族已有模型子目录 vs 2026-08 应有（见第 4 节候选，必须网页核实）
- 第 1 章导论仍画「八章」而总索引已是 14 章 —— 要改导论去对齐现实，不要删第 13/14 章

这些文件里是标准六段提纲（设计动机 / 原理 / 工程 / 对比 / 局限 / 同步），全部按提纲写满，不要另起炉灶改结构：

**B. 近乎空壳但标题已定的 D2/D5（约 1KB 的「架构精译 / 核心技术专题」）**

第 14 章 Gemini、OpenAI 早期、部分 Claude 条目大量只有标题。作者已经决定这些模型要有 D2+D5。你要：

- 用公开论文 / 官方技术报告 / model card **写成真正的精读**，不是再留 1KB。
- 闭源没 PDF 的：D2 写成「公开材料精读」（公告 + model card + 可信二次分析），文首标明材料类型，不要假装有全文翻译。
- 同目录已有写得好的 D5（例如某些 `05-*-核心技术专题.md` 已是长文）就不要重复造第三份；只填空的那份。

**C. 配图 prompt 全部落地**

已知含 `GPT-Image-2 Prompt` 或 `IMAGE PLACEHOLDER` 的文件（再全库搜一遍）：

- `2.2.1-自注意力机制.md`（至少 3 张）

做法：

1. 用 Cursor `GenerateImage`，description **尽量用文里现成的英文 prompt**，学术白底、无装饰、无水印。示意图用 `16:9` 或 `4:3`。

4. 生成成功后，把「配图建议」改成图 + 原有图注；**英文 prompt 改成 HTML 注释保留**，方便以后重画。不要删 prompt 文本。
5. 第 2.3 章 `roadmap/计划.md` 里「有空再做」的配图，能做就做，做完在 roadmap 打勾，不要删 roadmap。

## 3. 质量门（每篇新写/写满的正文）
