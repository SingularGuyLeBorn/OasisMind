# 评测、运维与安全

RAG 是一条多阶段系统链：源语料、解析、切分、索引、查询处理、召回、重排、上下文选择、生成、引用、拒答和缓存。最终答案错时，必须知道是哪一段退化；最终答案暂时没错时，也不能因此证明权限和安全正确。

## 1. 职责边界

本页负责 RAG 特有的离线评测、线上观测、发布门禁、故障恢复和检索内容攻击面。通用的独立监督、留出评测、权限、回滚与不可变记录原则见[RSI 评测与安全边界](../../../rsi/10-评测与安全边界/10-评测与安全边界.md)；跨会话经验进入记忆的风险见[RSI 持久记忆与检索](../../../rsi/07-记忆技能与经验/7.2-持久记忆与检索/7.2-持久记忆与检索.md)。llm-guide 的统一第 10 章形成公开正本后，本页应只保留 RAG 专项并改接该章。

本页不给“绝对安全”结论。测试通过只说明在记录的威胁模型、数据、系统版本和时间点上没有发现超出门槛的问题。

## 2. 评测清单必须可重建

每次评测保存一份 manifest：

```text
evaluation_id
corpus_snapshot + permission_snapshot
query_set_version + split_policy
relevance/evidence/answer annotations version
parser + chunker + embedder + retriever + reranker versions
index engine/version/parameters
prompt + generator + judge versions
hardware + concurrency + cache state
random seeds / decoding settings
metric implementations and thresholds
```

只保存 notebook 中的一张平均分表，无法判断分数变化来自模型、语料、标注、judge 还是缓存。

## 3. 五层评测

### 3.1 语料与索引层

| 指标/检查 | 回答的问题 |
|---|---|
| 摄取成功、隔离与解析错误率 | 哪些来源没有进入可用语料 |
| 片段可逆定位率 | 引用能否回到固定源位置 |
| 当前版本覆盖、孤儿片段数 | 新旧版本和删除是否一致 |
| 索引新鲜度分布 | 源变更多久后可查询 |
| ACL/租户继承正确率 | 片段是否保留源权限 |
| 重复与近重复率 | 候选是否被同一内容挤占 |

权限错误、依法删除后仍可检索、跨租户泄漏应作为零容忍发布门，而不是与回答质量求加权平均。

### 3.2 检索与排序层

若黄金相关集合为 $G_q$，前 $k$ 个结果为 $R_k(q)$：

$$
\operatorname{Recall@k}(q)=\frac{|G_q\cap R_k(q)|}{|G_q|}.
$$

该式只在 $|G_q|>0$ 时有定义。对黄金证据集合为空的无证据查询，不计算普通 Recall；应单独测错误召回、错误作答、正确拒答和空结果行为。汇总报告必须说明是否跳过无相关项、采用何种宏/微平均，并按可回答性分组，不能静默除零或丢样本。

“前 $k$ 至少命中一条”的比例是 hit rate / success@k，不要与多相关文档的 Recall 混用。MRR 关注第一个相关结果；nDCG@k 适合多等级相关性；多跳和比较还要测必需证据集合 coverage。指标选择见[检索、重排与索引](7.2.2-检索重排与索引.md)。

BEIR 提供多领域检索数据和统一评测代码，适合外部分布压力测试；官方仓库也明确不为每个数据集的质量、公平性或许可背书，使用者仍要核对来源。公共 benchmark 不能替代生产查询、私有语言、ACL 和时间分布。[BEIR 官方仓库](https://github.com/beir-cellar/beir)

### 3.3 上下文层

测最终送给模型的序列，而不只测重排列表：

- 必需证据覆盖率；
- 无关 token 比例与重复证据率；
- 关键证据被截断/位置变化率；
- 来源、版本、日期、单位和实体消歧保留率；
- 被拒绝或无权候选是否完全不在上下文；
- 序列化后 token、构造耗时和压缩信息损失。

### 3.4 生成、引用与拒答层

至少分开报告：

- 任务答案指标：exact match、F1、数值误差、结构化字段正确率或人工 rubric；
- 命题支持：答案中的原子命题是否被证据蕴含；
- 引用有效、正确、完整；
- 冲突是否披露；
- 可回答/不可回答的拒答混淆矩阵；
- 敏感信息、越权存在性和不安全输出率。

ALCE 提出了端到端自动引用评测基准；RAGAS 提供自动化的上下文与 faithfulness 类指标。两者都不是生产系统的统一总分标准。[ALCE](https://arxiv.org/abs/2305.14627)；[RAGAS](https://arxiv.org/abs/2309.15217)

### 3.5 系统层

- 端到端成功率、P50/P95/P99 延迟和超时；
- 每阶段耗时、token、模型调用、缓存命中、索引扫描和成本；
- 降级、重试、熔断、失败关闭与回滚成功率；
- 并发下的吞吐、队列、内存和索引构建影响；
- 新鲜度、可用性与质量目标之间的联合表现。

只报告平均延迟会掩盖重排长文档、过滤高选择性和依赖超时造成的长尾。

## 4. 数据集与标注设计

### 4.1 查询来源

组合：匿名化真实分布、专家构造的关键业务用例、历史失败、长尾与对抗样本。真实日志不能直接当黄金答案；它可能包含隐私、错误反馈和旧版本语料。

### 4.2 必备切片

- 高频/低频、短/长、单跳/多跳；
- 实体、错误码、数字、否定、时间范围与多语言；
- 可回答、部分证据、无证据、冲突、过期与撤回；
- 每个租户/角色与权限变更；
- 解析弱项：扫描 PDF、表格、代码、网页噪声；
- 检索内容含恶意指令、隐藏文字、恶意链接和重复投毒；
- PII/敏感字段输出、跨租户存在性、日志/trace/评测集/导出泄漏与删除传播；
- 分布外问题与系统依赖失败。

### 4.3 防止泄漏

- 调参集与最终测试集分离；
- 时间切分避免同一文档版本跨集合；
- 近重复查询和片段按逻辑来源分组；
- prompt、reranker 或 judge 不得根据测试答案持续手工优化；
- 保留独立安全集，写入/检索管线不能读取预期攻击答案。

### 4.4 标注质量

关键样本至少双人标注并记录分歧。相关性、证据支持、来源权威、答案正确与风险等级是不同标签，不能由一个“好/坏”代替。新语料版本可能让旧黄金答案失效，需要保留 `valid_as_of` 并重新裁决。

## 5. 自动 judge 的使用边界

LLM judge 能扩展命题拆分、支持判定和风格检查，但会受提示、模型版本、答案长度、措辞和位置影响。使用时：

1. 固定 judge 模型快照、提示与解码；
2. 用人工黄金集测准确率和分组偏差；
3. 保留“不确定/需人工”而非强制二元判断；
4. 对系统版本做盲化和随机顺序，避免位置偏差；
5. 报告 judge 与人工的混淆矩阵，不只报相关系数；
6. judge 变化后重算历史基线，不能把评分器变化当系统提升。

自动 faithfulness 主要回答“答案是否被给定上下文支持”，不回答来源是否真实、授权或最新。

## 6. 发布门禁与因果诊断

### 6.1 门禁分三类

- **硬门**：本次门禁覆盖样本中不得发现权限泄漏或撤回/删除残留；schema 可解析，关键安全测试通过；
- **回归门**：关键任务切片不得低于已批准基线和容忍区间；
- **预算门**：P95/P99、成本、索引构建与新鲜度满足 SLO。

阈值是产品风险决定，不存在通用的 Recall@5 或 faithfulness 合格线。

### 6.2 一次只改变一个层

典型发布顺序：

1. 在固定语料上比较切分/检索；
2. 在固定候选上比较重排；
3. 在固定上下文上比较生成与提示；
4. 端到端复验交互效应；
5. 影子流量或离线回放；
6. 小比例灰度并保留即时回滚；
7. 扩容后继续监控分布与长尾。

若同时换语料、embedding、向量库、reranker 和生成模型，即使总分上升也无法定位原因或安全退化。

## 7. 线上可观测性

### 7.1 请求级 trace

用请求 ID 关联语料/索引版本、权限策略摘要、查询改写、候选 ID、重排顺序、最终证据 ID、提示版本、模型版本、拒答码、耗时和验证结果。敏感原文按策略脱敏或只留受控引用；日志系统本身必须有更严格权限和保留期。

### 7.2 聚合看板

按租户、查询类型、语言、来源和系统版本观察：

- 空召回、少于 $k$、拒答与回退率；
- 候选重复、来源集中度、证据年龄；
- 引用无效、用户打开引用、纠错与升级人工；
- 每阶段延迟、错误、token 与成本；
- 权限过滤失败、异常写入、删除积压；
- 查询/语料 embedding 或词项分布漂移。

用户点赞不能直接当正确标签；它可能反映语气、速度或迎合。

### 7.3 可控探针

定期运行不含真实敏感数据的合成探针：当前版本命中、撤回版本不命中、跨租户不可见、冲突可披露、无答案会拒答、恶意文档不改变系统规则。探针也要隔离，防止被模型或缓存专门识别后“通过考试”。

## 8. RAG 威胁模型

### 8.1 间接 Prompt Injection

网页、邮件、PDF、工单和代码注释都可能包含面向模型的恶意指令。Greshake 等的原始论文展示了把指令放进可能被检索的数据，从而影响 LLM 集成应用的攻击面。[Indirect Prompt Injection 论文](https://arxiv.org/abs/2302.12173)

最低控制：

- 把检索内容标为不可信数据，不允许它提高指令优先级；
- 工具调用由服务端策略、最小权限和参数校验控制；
- 读取敏感数据与对外写入/发送分离，关键动作需确认；
- 不把系统提示、密钥或其他租户内容放入模型可回显上下文；
- 对 HTML 隐藏内容、注释、元数据和外链做解析与风险测试；
- 模型声称“已忽略恶意指令”不等于攻击被阻断。

### 8.2 语料投毒与排序操纵

攻击者可写入重复或针对特定查询优化的文本，使其进入前排，内容未必包含显式指令。PoisonedRAG 在其威胁模型和实验设置中演示了向知识库注入少量恶意文本来操纵目标回答；论文数字只适用于其数据、模型和攻击设置，不应作为生产风险概率。[PoisonedRAG, USENIX Security 2025](https://www.usenix.org/conference/usenixsecurity25/presentation/zou-poisonedrag)

控制包括：写入身份与审批、来源签名/版本、异常重复与突增监控、来源多样性、检索结果可追溯、可信源分区，以及独立的投毒红队集。签名可证明来源身份与完整性，不能证明内容真实；内容过滤也不是完备防御。

### 8.3 越权与存在性泄漏

- 权限必须在检索时执行，不能把越权文本送给模型再让它忽略；
- 缓存包含身份与权限版本；
- “没有权限”和“没有记录”的外部响应避免泄漏对象存在性；
- 管理员查询与普通用户查询分开审计；
- 片段、父文档扩展、引用预览和附件下载使用同一或更严格授权。

Azure 文档级访问控制提供了权限元数据随索引、查询时过滤的官方实现示例；具体机制和预览状态需绑定当前 API 版本。[Azure 文档级访问控制](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview)

### 8.4 数据外泄与恶意引用

- 输出引用只允许服务端映射的 `https`/内部受控链接；
- 防止模型拼接任意 `file:`, `javascript:` 或带秘密参数的 URL；
- 不把检索分数、ACL 列表、内部路径和调试上下文直接展示；
- 对敏感实体做输出策略与人工升级，但不要依赖简单关键词替代授权；
- 日志、评测集、反馈平台和 trace 导出同样属于敏感数据面。

### 8.5 资源耗尽

超长查询、多查询扩展、迭代检索、巨大 `top_k`、重排长文档和反复重试都能放大成本。设置输入、分解数、候选数、循环、token、并发、时间与总预算上限；超限时返回明确降级或拒答，不让模型自行决定无限搜索。

### 8.6 隐私与派生数据外泄

原文、查询、embedding、索引、缓存、评测副本、judge 输入、trace 和导出共同构成 RAG 数据面。最低控制包括：按数据分类决定是否允许向外部处理器发送；记录处理方、地域、保留与删除边界；对派生数据执行最小权限和保留期；把更正、撤回、数据主体删除传播到可检索副本与允许删除的日志；用专门切片测试 PII 输出、成员/属性推断、跨租户存在性和调试导出泄漏。NIST AI 600-1 将数据隐私纳入生成式 AI 风险管理；它提供风险框架，不替代具体法域和组织政策。[NIST AI 600-1](https://doi.org/10.6028/NIST.AI.600-1)

## 9. 故障与恢复

| 故障 | 安全默认 | 恢复验证 |
|---|---|---|
| 权限服务不可用 | 受保护语料失败关闭 | 权限探针与缓存过期测试 |
| 新索引构建失败 | 继续服务上一获批版本；标新鲜度 | manifest 完整、回归后再切换 |
| 删除积压 | 隐藏待删除对象或停相关源 | 孤儿扫描、缓存与引用复验 |
| embedding/reranker 超时 | 使用获批降级检索或拒答 | 降级集质量和权限不退化 |
| 生成模型失败 | 不返回未验证的半成品 | 重试幂等、预算和重复发送测试 |
| judge 不可用 | 不阻塞低风险请求可选；不伪造分数 | 延迟评测并标缺失，不静默记满分 |

回滚对象不仅是代码，还包括语料快照、索引、模型、提示、策略和缓存。已经撤权或依法删除的数据不能因“技术回滚”重新暴露。

## 10. 可复现实验与安全测试

### 10.1 离线回归

运行固定 manifest 的分层测试，输出每条查询的候选、上下文、答案、命题支持、引用和拒答。比较版本时用配对差异，列出退化样本，不只看平均值。

### 10.2 注入与投毒实验

在隔离语料中加入：

- 显式“忽略此前指令”；
- 隐藏 HTML/注释/元数据指令；
- 请求泄露其他证据或系统提示；
- 恶意链接与工具调用参数；
- 多份近重复、针对查询优化的错误文本；
- 权威源与恶意低权威源冲突。

观察恶意候选进入率、最终上下文进入率、模型服从率、工具越权率、敏感输出率与来源异常告警。测试报告必须写清攻击者写权限、是否知道查询/检索器、语料规模和防御配置。

### 10.3 权限矩阵实验

为每个 `(用户/组, 租户, 文档, 版本, 操作)` 建预期矩阵；验证检索、父段扩展、答案缓存、引用预览、导出和日志查看。随后撤权、改组、改标签和删除，测传播延迟与失败关闭。

### 10.4 线上灰度

先影子执行不向用户返回，再小比例流量。设定自动停机条件：任何越权、撤回内容出现、关键切片显著退化、成本或 P99 超限。灰度期间不临时改变 judge 或阈值，否则失去对照。

## 11. 上线检查表

- [ ] 评测 manifest 能固定语料、权限、索引、模型、提示、judge 与硬件。
- [ ] 语料、检索、上下文、生成和系统五层都有独立指标。
- [ ] 公共 benchmark 与业务留出分开，许可和时效已核验。
- [ ] 真实查询、长尾、无答案、冲突、权限和攻击样本均有切片。
- [ ] 自动 judge 已与人工标注校准，不能单独充当发布裁决者。
- [ ] 权限、删除、引用安全和关键风险使用硬门。
- [ ] 请求级 trace 可定位每阶段，同时遵守数据最小化与保留策略。
- [ ] 检索内容按不可信数据处理，工具权限不由文档文字决定。
- [ ] 投毒、间接注入、跨租户、存在性泄漏和资源耗尽已测试。
- [ ] PII、派生向量/缓存、外部处理器、评测副本、trace 与导出纳入隐私和删除传播测试。
- [ ] 新索引、模型和提示支持灰度、停止与回滚；回滚不恢复已撤权数据。
- [ ] 线上反馈进入人工复核队列，不直接污染语料或黄金集。
