# Hermes：模型、Agent 运行时与训练工具的边界

“Hermes”至少涉及四个不同层次的对象。它们由同一研究组织推进，也可以在一条研发链上衔接，但不能视为同一个产品，更不能据此推断部署中的 Agent 会自动训练或更新模型权重。

| 对象 | 所在层 | 有证据支持的职责 | 不应推断为 |
| :--- | :--- | :--- | :--- |
| Hermes 3 / Hermes 4 | 模型与权重 | 生成文本、推理内容和工具调用表示 | 工具执行器、权限系统、会话数据库 |
| Hermes Agent | Agent 运行时 | 组装提示、调用模型、分派工具、保存会话、加载技能、接入消息入口 | Hermes 模型的新版本、模型训练框架 |
| DataForge | 数据生成流水线 | 为 Hermes 4 生成和筛选合成训练数据 | Hermes Agent 的在线自动训练模块 |
| Atropos | RL 环境与轨迹基础设施 | 运行环境、评分并交换轨迹，支持训练与评测流程 | 内置训练器、推理服务器、线上 Agent 的自动参数更新器 |

Hermes Agent 的官方仓库明确支持切换模型与供应商，因此运行时并不要求使用 Hermes 模型；反过来，Hermes 模型也可以由其他兼容的 harness 调用。来源：[Hermes Agent 官方仓库](https://github.com/NousResearch/hermes-agent)。

## Hermes 3 与 Hermes 4 是模型，不是 Agent 运行时

Hermes 3 是基于 Llama 3.1 系列继续训练的通用指令与工具使用模型。报告中的 Hermes Function Calling 约定把工具定义表示为 JSON Schema，并用专用标签表达调用和返回；报告也把工具计算描述为模型之外的 out-of-band 操作。这意味着模型负责**提出调用**，真正的参数校验、执行、权限和副作用仍由外部系统承担。来源：[Hermes 3 Technical Report](https://arxiv.org/abs/2408.11857)。

Hermes 4 是后续的混合推理模型系列。其技术报告讨论合成数据、推理与非推理数据、训练方法、推理长度控制和评测；14B 模型从 Qwen3 14B 开始，70B 与 405B 模型从 Llama 3.1 对应规模开始。`<think>` / `</think>` 是报告所述推理轨迹的一部分，不等价于工具协议，也不自动规定应用是否展示或保存推理内容。来源：[Hermes 4 Technical Report](https://arxiv.org/abs/2508.18255)。

因此，模型侧结论应止于“在给定模板和评测设置下能生成某类输出”。从模型报告不能推出 Hermes Agent 的默认模型、权限策略、执行后端、延迟、成本或任务成功率。

## Hermes Agent 是可替换模型的运行时

官方架构把 CLI、消息网关、ACP、批处理、API Server 和 Python Library 视为入口；核心 `AIAgent` 负责供应商解析、提示构建、模型调用、工具执行、重试与 fallback、上下文压缩和持久化。工具通过中央注册表收集 schema、检查可用性并分派到实现。来源：[Hermes Agent Architecture](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/architecture.md)。

这比“每一步对所有动作求 argmax”的数学化描述更接近可审计实现。官方文档没有把 Agent loop 定义为旧稿中的概率公式，也没有把 `create_skill` 定义成扩张离散动作空间的特殊算法。应以实际模型响应、工具 schema、注册表和回调路径解释一次执行，而不是为实现补写理论公式。

### 工具与技能不是一回事

工具是运行时可分派的函数能力；具体可用项取决于平台、凭据和启用的 toolset。文件、终端、网页、委派、定时任务等能力及其参数应以当前的官方工具参考为准，不能把仓库某一时刻的工具数量或后端列表固化成性能承诺。来源：[Built-in Tools Reference](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md)。

技能则是按需加载的知识文档。主文件是 `SKILL.md`，可附带 `references/`、`templates/`、`scripts/`、`examples/` 和 `assets/`；运行时先看到索引信息，需要时再加载正文或引用文件。官方格式没有旧稿声称的必填 `parameters`、`implementation`、`dependencies` 字段，也没有“质量分、七天淘汰阈值、按代码行数惩罚”的机制。来源：[Skills System：格式与渐进披露](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md#progressive-disclosure)。

技能可以指导 Agent 调用已有工具或使用附带脚本，但技能本身不会创造底层权限。Agent 可以通过 `skill_manage` 创建、修改和删除技能；默认允许直接写入，开启 `skills.write_approval` 后才会暂存变更并等待批准。所谓“自改进”在这里首先是**外部知识与流程文件的可变更性**，不是模型权重更新，也不是质量自动提升。来源：[Skills System：技能写入审批](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md#gating-agent-skill-writes-skillswrite_approval)。

### 会话不是三层向量记忆

官方会话文档把 `~/.hermes/state.db` 中的 SQLite 数据库列为会话元数据和完整消息历史的存储，并使用 FTS5 做跨会话全文检索。文档没有支持旧稿中的“内存最近五步、SQLite 保存三十天、默认 MiniLM 向量、固定时间衰减公式”这套实现。来源：[Hermes Agent Sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md)。

会话库可能包含用户消息、工具调用、工具结果、系统提示快照和 token 计数。部署前应据此确定文件权限、备份、保留期和敏感数据清理方案；“可搜索”不等于“可无条件长期保存”。

### Docker 有两种不同用法

官方文档区分：

- **把 Hermes Agent 本身运行在 Docker 中**：配置、密钥、会话、技能和记忆通过宿主机目录挂载到 `/opt/data`。
- **把 Docker 选作 terminal backend**：Agent 仍运行在宿主机，命令进入持久化的 Docker 执行容器；技能目录和声明的凭据文件可以只读挂载到执行环境。

两者不能混写成“所有高风险动作默认进 Docker”。持久容器还意味着工具调用之间可能共享文件和已安装依赖；实际隔离边界取决于镜像、挂载、环境变量、网络和后端配置。来源：[Hermes Agent Docker](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/docker.md)。

## DataForge 与 Atropos 位于离线数据和训练侧

### DataForge：合成数据生成，不是运行时技能飞轮

Hermes 4 报告把 DataForge 描述为图式合成数据生成器：数据点通过有向无环图中的随机游走产生，节点执行 `struct → struct` 映射，并以类似 PDDL 的前置条件和后置条件决定可连接的数据流。报告还描述了按任务类型选择回答生成器、用专门的 LLM judge 审核以及失败后迭代或丢弃样本。来源：[Hermes 4 Technical Report，§2.1 DataForge](https://nousresearch.com/wp-content/uploads/2025/08/Hermes_4_Technical_Report.pdf)。

这些是**训练数据构造步骤**。报告没有定义 Hermes Agent 中可调用的 DataForge 运行时工具，也没有说明部署中的会话或技能会自动进入 DataForge、再自动微调当前模型。DataForge 的独立公共服务接口、部署成本和吞吐量在上述报告中未披露，不应补写默认实现或固定收益。

### Atropos：环境与轨迹 API，不包办训练

Atropos 官方仓库把它定义为面向异步 LLM 强化学习的环境微服务框架：环境产生并评分轨迹，trajectory API 接收数据并向训练侧提供批次。README 明确说明 trainer 与 inference engine 不包含在 Atropos 包中，仓库内的 trainer 只是集成示例。它支持多种环境与评分流程，但这不等于固定采用 PPO、中央参数服务器、梯度量化或异步权重广播。来源：[NousResearch/atropos](https://github.com/NousResearch/atropos)。

Hermes 4 报告说明 Atropos 被用于 rejection sampling，并利用“RL 环境也可作为评测实现”这一关系承载部分评测。这里的对象是模型训练/评测轨迹，而不是 Hermes Agent 生产会话的在线强化学习。来源：[Hermes 4 Technical Report，§2.2 与 §4.3](https://arxiv.org/abs/2508.18255)。

截至 `2026-09-01`，Atropos 官方 GitHub 仓库已被归档并标明不再维护；若继续采用，应固定提交、保存依赖锁并自行承担兼容性和安全维护。来源：[Atropos 官方仓库状态](https://github.com/NousResearch/atropos)。

## 一次运行真正发生了什么

在不绑定具体供应商和后端时，可以把运行路径概括为：

1. CLI、网关或其他入口把用户消息交给 Agent loop。
2. 运行时组装系统提示、会话上下文以及按需加载的技能内容。
3. 选定的模型服务返回普通文本或结构化工具调用。
4. 运行时按当前 toolset 与凭据检查工具是否可用，再把调用分派到对应实现和执行后端。
5. 工具结果回到模型上下文，直到运行时得到最终回复或停止执行。
6. 会话元数据与消息历史写入会话存储。

这条路径由 [Architecture](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/architecture.md)、[Tools Reference](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md) 和 [Sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md) 分别约束。技能是步骤 2 的按需知识，Hermes 模型是步骤 3 的可选模型之一；DataForge 与 Atropos 不在这条在线请求路径中。

## 成本与延迟：只报告可复现实测

官方资料没有给出可以外推到任意模型、供应商、地区、工具和硬件的固定单任务成本或延迟。下列模板用于替代“典型配置”估算；没有原始记录的单元格保持“未测”，不要填推测值。

### 固定实验条件

| 项目 | 必填记录 |
| :--- | :--- |
| Hermes Agent 版本 | release 或完整 commit SHA |
| 模型服务 | 模型精确 ID、供应商、API 模式、服务区域、测试日期 |
| 采样设置 | temperature、top_p、最大输出、推理模式；未显式设置则写“供应商默认，具体值未披露” |
| 运行环境 | OS、CPU、内存、Python、容器运行时及镜像 digest |
| 执行后端 | local / Docker / SSH / 其他；附相关配置与挂载清单 |
| 工具与技能 | 启用的 toolset、技能内容哈希、外部服务版本 |
| 工作负载 | 公开任务清单、输入文件哈希、成功判据、超时和最大步骤 |
| 试验设计 | 冷启动与热启动分开；预热次数、正式重复次数、并发度、随机种子 |

## 部署审计清单

- **模型边界**：模型只生成调用意图；运行时必须验证工具名、参数和权限。
- **工具边界**：按平台、凭据和 toolset 列出实际可用工具，不把文档全集当作当前实例的权限。
- **技能边界**：审查 `SKILL.md` 及附带脚本的来源；需要人工控制时开启技能写入审批，并保留 diff 与回滚路径。
- **执行边界**：明确 Agent 自身是否在容器中、terminal backend 是否为 Docker，以及每个挂载、网络和环境变量的暴露范围。
- **会话边界**：把 SQLite 会话库视为敏感数据，制定备份、访问控制、保留与删除策略。
- **训练边界**：任何 DataForge/Atropos 流水线都应作为独立、版本化的离线实验；模型权重变更必须经过数据审计、评测和显式发布。
- **证据边界**：性能、成本、默认值和安全保证只引用对应版本的官方文档或本地可复现实测；GitHub issue 只能作为问题线索，不能当作规范。
