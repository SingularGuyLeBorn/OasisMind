# 2 · 核心原理与架构

这一章讲的是一层 decoder-only Transformer 里有什么, 每一部分的成本从哪里来, 以及过去几年的架构改动分别改了哪一部分. 八个小节按这个思路排列: 2.1 和 2.2 定义组件和注意力; 2.3, 2.4, 2.5, 2.7 都在处理注意力的成本, 只是处理方式不同; 2.6 改的是 FFN; 2.8 改的是训练目标, 生成方式和参数组织.

读这一章时要分开三层. 第一层是数学语义: 模型计算了什么函数, 改动之后表达能力和归纳偏置怎样变. 第二层是张量与状态: 要保存哪些权重, 激活和 KV 状态, 形状怎样随序列长度变. 第三层是系统实现: kernel, 并行, 内存分配和服务调度怎样执行同一个或近似的计算. FlashAttention 属于第三层, 它是密集精确注意力的 IO 感知实现, 算术复杂度仍是平方的; MQA 和 MLA 属于第二层, 它们改变缓存的形状; 稀疏注意力和线性注意力改变了第一层, 计算的函数已经和密集 softmax 注意力不同.

## 1. 一层解码器与本章记号

### 1.1 层的骨架

一个典型的 Pre-Norm 解码器层可以写成两个带残差的子层:

$$
\tilde{X} = X + \operatorname{Attention}(\operatorname{Norm}(X)),\qquad
Y = \tilde{X} + \operatorname{FFN}(\operatorname{Norm}(\tilde{X})) \tag{1}
$$

注意力负责跨 token 混合, 单头的缩放点积注意力为 $\operatorname{softmax}(QK^{\mathsf T}/\sqrt{d_h}+M)V$, $M$ 是因果掩码, $d_h$ 是头维度. FFN 对每个 token 独立变换通道, 现行模型多用门控形式:

$$
\operatorname{FFN}(x) = W_{\mathrm{down}}\left[\phi(W_{\mathrm{gate}}x) \odot (W_{\mathrm{up}}x)\right] \tag{2}
$$

式 (1) 里的每个部件都有对应的小节. Norm 的形式和位置在 [2.1.2 归一化层](./2.1-深度学习基础组件/2.1.2-归一化层/2.1.2-归一化层.md), 两处 $X+\cdot$ 的残差和它的多流改法在 [2.1.3 残差连接](./2.1-深度学习基础组件/2.1.3-残差连接/2.1.3-残差连接.md), 式 (2) 的 $\phi$ 和门控在 [2.1.1 激活函数](./2.1-深度学习基础组件/2.1.1-激活函数/2.1.1-激活函数.md) 与 [2.1.5 前馈网络 FFN](./2.1-深度学习基础组件/2.1.5-前馈网络FFN/2.1.5-前馈网络FFN.md). 不加位置信息时, 自注意力对 token 排列是等变的, 因果掩码给出「谁能看见谁」, 但不直接编码两个可见位置的距离; RoPE 对 $Q, K$ 施加位置相关的旋转, 使 $(R_m q)^{\mathsf T}(R_n k)=q^{\mathsf T}R_{n-m}k$, 推导和外推问题在 [2.1.4 位置编码](./2.1-深度学习基础组件/2.1.4-位置编码/2.1.4-位置编码.md).

式 (1) 和式 (2) 是共同骨架, 各家模型在每个位置上都有变化: Norm 放在哪里, 残差是一条流还是多条, 位置编码用哪种, 注意力头怎样组织, FFN 是稠密的还是由路由器选专家. 本章记号统一如下: $L$ 为序列长度, $d$ 为隐藏维, $N$ 为层数, $H_q$ 为 Query 头数, $H_{kv}$ 为 KV 头数, $d_h$ 为头维度, 标准配置下 $H_qd_h\approx d$.

### 1.2 Prefill, Decode 与 KV 缓存

推理分两段. Prefill 并行处理整段输入, Q/K/V 和输出投影的计算量是 $O(Ld^2)$, 打分和加权求和是 $O(L^2d)$, 朴素实现若把注意力矩阵写进显存还要 $O(L^2)$ 的中间状态. Decode 每步只新增一个 token, 历史 token 的 K/V 存在缓存里不必重算, 但新 query 要读完整份缓存, 单步注意力成本随已缓存长度近似线性增长. 对显式保存头状 K/V 的 MHA, MQA, GQA, 单序列 KV 缓存的理想化字节数是

$$
\operatorname{KVBytes} = 2\,N L H_{kv} d_h b \tag{3}
$$

系数 2 对应 K 和 V, $b$ 是每元素字节数. MLA 缓存的是潜变量, 量化缓存还有元数据, 要对实际保存的张量逐项求和; 页块碎片, 前缀共享和运行时工作区也要另计. 下表把几种常被混在一起的成本分开:

| 对象 | 随长度的典型变化 | 不包含什么 |
|---|---|---|
| 模型参数 | 对固定模型不随输入长度变化 | 优化器状态, 分布式副本另计 |
| Prefill 密集注意力算术 | $O(L^2d)$ | 投影与 FFN 的 $O(Ld^2)$ 另计 |
| Decode 单步密集注意力 | 对缓存长度近似 $O(Ld)$ | kernel 启动, 批量与调度开销另计 |
| KV 缓存存储 | 对固定结构为 $O(L)$ | 碎片, 工作区和通信缓冲另计 |
| 训练激活 | 依实现, 重计算和并行策略而变 | 不能直接用推理 KV 公式代替 |

本章后半的大多数方法都对着这张表的某一行. FlashAttention 不动第二行的算术量, 只去掉 $O(L^2)$ 的中间状态和多余的显存搬运; MQA, GQA, MLA 缩小式 (3) 里的 $H_{kv}d_h$; 稀疏注意力减少第二, 三行实际计算的位置对; 线性注意力和状态空间模型把第四行换成与 $L$ 无关的固定状态. 读一篇新论文时先问它改的是哪一行, 能省掉很多混淆.

## 2. 八个小节的分工

### 2.1 组件与注意力: 2.1 和 2.2

[2.1 深度学习基础组件](./2.1-深度学习基础组件/2.1-深度学习基础组件.md) 是全章的词汇表. 首页补上感知机, 反向传播, 优化器, Dropout, Embedding, 损失函数和从 RNN/LSTM 到自注意力的过渡, 五个分节分别讲激活, 归一化, 残差, 位置编码和 FFN. 这五个组件在后面各节里几乎不再改动, 例外是残差 (2.1.3 讲到 Qwen3.8 的 Gated Residual 和 Kimi K3 的 Block AttnRes) 和 FFN (2.6 把它拆成专家).

[2.2 注意力机制](./2.2-注意力机制/2.2-注意力机制.md) 定义后面四节要改的对象. 2.2.1 讲单头的计算, 缩放的方差论证, 因果掩码和平方复杂度, 讲到数值稳定的在线 softmax 为止; 2.2.2 从 MHA 的缓存出发, 讲 MQA, GQA 减少份数, MLA 压缩每份的维度, 以及不碰缓存的 Gated Attention. 2.2.2 的方法改的是缓存里每个 token 存什么, 注意力计算的函数和密集 softmax 注意力相同.

### 2.2 沿注意力成本展开的四节

| 小节 | 改动对象 | 与密集 softmax 注意力的关系 | 训练要求 | 缓存随长度 |
|:----|:--------|:-------------------------|:--------|:---------|
| [2.3 注意力的高效实现](./2.3-注意力的高效实现/2.3-注意力的高效实现.md) | 分块, 融合, 片上调度 | 数学等价 | 直接替换 kernel | 不变, $O(L)$ |
| [2.4 稀疏注意力](./2.4-稀疏注意力/2.4-稀疏注意力.md) | 每个 query 读哪些 key | 保留 softmax, 只算部分位置对 | 多数从预训练就按稀疏模式学 | 仍为 $O(L)$, 每步只读一部分或沿序列压缩 |
| [2.5 线性注意力与状态空间模型](./2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md) | 用固定状态代替历史 | 函数不同, 去掉 softmax | 从头训练或混合架构 | 固定大小, 与 $L$ 无关 |
| [2.7 长上下文与外推技术](./2.7-长上下文与外推技术/2.7-长上下文与外推技术.md) | 位置外推, 推理期的缓存取舍与调度 | 外推与驱逐是近似, 分页是精确 | 外推多需少量微调, 驱逐免训练 | 驱逐后有上限, 分页不改大小 |

表的第三列是区分这四节的主要依据. 2.3 的五篇 (综述, Memory-Efficient Attention, FlashAttention v1/v2, FlashAttention-3/4, 几条实现路径对比) 都保证输出与朴素实现一致, 差别在 A100, H100, B200 各自的瓶颈: A100 上是 HBM 搬运和非矩阵乘运算, H100 上要让指数运算和矩阵乘并行. 2.4 和 2.5 都改变了计算的函数, 2.4 保留 softmax, 用块选择 (MoBA, NSA), 沿序列压缩 KV (DeepSeek-V4 的 CSA 与 HCA) 或压缩 indexer (Qwen 的 QSA) 决定读哪些位置; 2.5 去掉 softmax, 线性注意力, 状态空间模型和线性 RNN 三条来路最终都落到一个带衰减的矩阵递推上.

2.7 是这张表里唯一面向推理期, 不改模型结构的一节. 2.7.1 讲训练长度之外位置编码为什么失效, RoPE 之外的外推路线和外推的评测; 2.7.2 的八篇 (StreamingLLM 到 Quest) 在推理时决定哪些 KV 留在缓存里; 2.7.3 按 prefill 和 decode 两段瓶颈讲长上下文推理的整体优化, 并收了 PagedAttention 一篇. 第四列和第五列说明这几节可以叠加: 一个部署可以同时用 FlashAttention 内核, GQA 结构, 部分层的稀疏注意力和推理期的 KV 驱逐, 每一项对应 1.2 节表格的不同一行.

### 2.3 FFN 与训练目标: 2.6 和 2.8

[2.6 MoE](./2.6-MoE/2.6-MoE.md) 把式 (2) 的稠密 FFN 换成 $N$ 个专家, 每个 token 只经过其中 $K$ 个, 总参数随 $N$ 增长, 每 token 计算随 $K$ 增长. 六篇依次处理路由的离散选择, 负载偏斜与辅助损失, DeepSeekMoE 和 Kimi K3 的结构改进, 专家并行的通信, 以及专家权重的量化. 注意力一侧的 MLA 和 FFN 一侧的 MoE 在 DeepSeek-V2/V3 里同层出现, 但两个潜空间互不相干, 读者不要把 MLA 的潜变量和 LatentMoE 的潜空间路由当作同一件事.

[2.8 其他架构方向](./2.8-其他架构方向/2.8-其他架构方向.md) 的五个方向各自松开标准 decoder-only 模型的一处绑定. 2.8.1 MTP 让每个位置额外预测后面几个 token, 2.8.2 扩散语言模型换掉从左到右的分解, 2.8.3 Engram 把局部静态模式交给一张按 token ID 寻址的哈希表, 2.8.4 循环 Transformer 让同一套块转多轮, 2.8.5 LLM-JEPA 在嵌入空间加一项预测损失. 这些改动大多在训练目标和参数组织上, 注意力核与 FFN 基本不动, 所以和 2.3 到 2.7 的成本讨论基本正交.

## 3. 依赖关系与跨章边界

### 3.1 从注意力到长上下文的一条链

2.2 到 2.7 之间有一条阅读依赖. 2.2.1 第 4 节的在线 softmax 是 2.3 所有 FlashAttention 文章的前提, 分块计算让 $L\times L$ 矩阵不必写进显存. 分块之后计算量仍是平方的, 想再降就要少算位置对, 这是 2.4 的出发点: NSA 的内核按 GQA 组加载 KV 块, 必须先懂 2.2.2 的组共享和 2.3 的分块调度. 2.5 从另一侧接上: 线性注意力的推导从 2.2.1 的公式里拿掉 softmax 开始, 它的缓存优势要和 2.2.2 的式 (3) 对照才看得清.

2.7 处在链条末端, 同时依赖 2.1.4 和前面各节. 位置外推依赖 2.1.4 对 RoPE 低频平面越界的分析, 2.7.1 只讲 PI, NTK, YaRN 之外的路线; KV 驱逐依赖 2.2.2 的缓存结构和 2.2.2 第 5 篇对 attention sink 的讨论, 加了输出门之后, 首 token 的平均注意力占比从 46.7% 降到 4.8%, 依赖首 token 的保留策略要重新验证; 长上下文推理的 prefill 稀疏和 decode 带宽问题, 又要回到 2.3 和 2.4 的内核. 只关心长上下文的读者, 也至少要读 2.1.4 和 2.2.2.

### 3.2 MoE: 2.6 与 6.1.8 的分工

MoE 的机制和系统分在两章. 2.6 推导路由公式, Top-$K$ 的梯度, 负载均衡损失, 无辅助损失的偏置法, 共享专家和细粒度切分; 其中第 5 篇只写到理解这些机制所需的系统量级, 包括 All-to-All 的字节数, DualPipe 的气泡, 以及 prefill 与 decode 为什么切成不同的专家并行度. 第 6 篇讲专家权重的量化和专用硬件.

[6.1.8 MoE 系统与并行](../6-训练与推理优化/6.1-训练基础设施/6.1.8-MoE系统与并行/6.1.8-MoE系统与并行.md) 讲 token 怎样送到持有专家的卡, All-to-All 怎样和计算重叠, Grouped GEMM 的 Tile 怎样不被填充浪费, 三篇分别从场景清单, 数据流图和综述三个粒度展开. 判断一个问题该去哪一章, 看它能不能脱离具体集群回答: 负载为什么会偏斜, 偏置更新为什么不影响梯度, 这类问题在 2.6; 一次 dispatch 怎样拆包, 通信内核怎样和计算流水重叠, 这类问题在 6.1.8. MoE 模型的量化综述另在 [6.3.1 量化](../6-训练与推理优化/6.3-模型压缩/6.3.1-量化/05-MoE模型量化技术综述/05-MoE模型量化技术综述.md).

### 3.3 与其他章的边界

本章的内容止于机制, 张量形状和复杂度. 预训练目标, 数据配方和 MTP 的损失权重归 [3 预训练](../3-预训练/3-预训练.md), 对齐流程归 [4 后训练](../4-后训练/4-后训练.md). 并行训练, 量化, KV 缓存的系统管理和服务调度归 [6 训练与推理优化](../6-训练与推理优化/6-训练与推理优化.md), 例如 PagedAttention 在 2.7.3 有一篇讲它与 KV 张量形状的关系, 服务侧的完整讨论在 6.4 和 6.6; MTP 当作投机解码草稿模型的那一面也在 6.6.

多模态的位置编码和跨模态结构归 [8 多模态](../8-多模态/8-多模态.md), 本章只在 2.1.4 保留 M-RoPE 这种通用位置机制; 生产基础设施归 [9 AI 工程化与基础设施](../9-AI工程化与基础设施/9-AI工程化与基础设施.md). 具体模型的版本, 参数和发布细节在 [主流模型知识库](../../model-library/_garden.md), 本章只在解释机制来源时引用. 扩散语言模型的完整数学, 训练和采样在 [扩散语言模型知识库](../../diffusion-llm/_garden.md), 2.8.2 只讲它和自回归模型的架构边界.

## 4. 阅读路线

### 4.1 第一次系统学习

按编号顺序读是可行的, 但 2.1 篇幅很大, 不必读完再往下. 先读 2.1 首页的反向传播和损失函数, 再读 2.1.4 位置编码的第一篇和 2.2 两篇, 手算一遍 2.2.1 的因果注意力例子, 追踪 $Q, K, V$ 的形状. 然后用 1.2 节的式 (3) 和成本表, 分别算一个模型的 prefill 计算量, 单步 decode 读取量和 KV 存储, 2.2.2 的 01 第 4.2 节以 Llama-2-7B 代入, 给出了可以对照的数字.

这之后读 2.3 和 2.4, 比较「数学等价的实现优化」与「改变计算图的结构优化」; 再读 2.5 和 2.7, 区分固定状态, 位置外推和推理期缓存取舍各自的代价. 2.6 和 2.8 与注意力这条链关系较弱, 可以在任何时候插入, 读 2.6 之前最好先读 2.1.5, 那里讲了 FFN 在参数和访存上的分量.

### 4.2 推理部署与长上下文

做推理部署的读者从 2.2.2 读起, 重点是 MQA, GQA, MLA 的缓存结构和 MLA 矩阵吸收在 prefill 与 decode 上的不同算法, 再读 2.3 第 5 篇的几条实现路径, 然后进入 2.7.2, 2.7.3 和第 6 章的 KV 量化, PagedAttention 与调度. 这样可以分清缓存张量的结构优化, 内存分配和注意力 kernel 三件事.

做长上下文研究的读者从 2.1.4 读起, 先弄清 RoPE 哪些平面会越界, 再读 2.7.1 的其他外推路线和评测方法, 然后回到 2.4 和 2.5 选择稀疏, 递推或混合策略, 最终用 2.7.3 和第 6 章检查系统可行性. 名义最大窗口, 训练窗口和有效能力窗口要分开记录, 任何长上下文方法都应同时报告短上下文上的回退.
