# 核心原理与架构

大语言模型不是一张不断追加型号的清单,而是一组可以分别分析,组合和验证的机制.本章回答五类问题:一个 Transformer 层由什么组成,注意力如何建立 token 间的依赖,长序列的计算与存储成本从哪里产生,哪些架构通过稀疏或递推改变成本,以及"支持更长窗口"为什么不等于"能有效使用更长上下文".

本页是路线图,不代替各专题正文.阅读时始终区分三层:

1. **数学语义**:模型计算了什么函数,改变后表达能力与归纳偏置如何变化.
2. **张量与状态**:需要保存哪些权重,激活和 KV 状态,形状如何随序列长度变化.
3. **系统实现**:kernel,并行,内存分配和服务调度怎样执行同一个或近似的计算.

这三层经常被混写.例如,FlashAttention 是密集精确注意力的 IO-aware 实现,不把其算术复杂度改成线性;PagedAttention 主要解决服务侧 KV 内存管理,也不是新的注意力表达形式.

## 1. 一层解码器的最小机制

现代大语言模型存在许多变体,但一个典型的 Pre-Norm 解码器层可以抽象为:

$$
\begin{aligned}
\tilde{X} &= X + \operatorname{Attention}(\operatorname{Norm}(X)), \\
Y &= \tilde{X} + \operatorname{FFN}(\operatorname{Norm}(\tilde{X})).
\end{aligned}
$$

对单个注意力头,缩放点积注意力为:

$$
\operatorname{Attention}(Q,K,V)
= \operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_h}} + M\right)V,
$$

其中 $M$ 是因果或其他结构掩码,$d_h$ 是头维度.多头注意力让多个投影子空间并行建模依赖;MQA,GQA 和 MLA 则以不同方式减少或压缩推理时需要保留的 K/V 状态.

门控 FFN 常写为:

$$
\operatorname{FFN}(x)
= W_{\mathrm{down}}
\left[\phi(W_{\mathrm{gate}}x) \odot (W_{\mathrm{up}}x)\right].
$$

它对每个 token 独立变换通道表示,注意力负责跨 token 混合.[Geva 等人的分析](https://arxiv.org/abs/2012.14913)把 FFN 解释为键值记忆,有助于说明部分实验现象;这只是分析视角,不能推出模型知识只分布在 FFN 中.

没有位置编码,也没有固定位置相关 mask 的全自注意力,对输入 token 的同步排列是等变的.解码器的固定下三角因果 mask 已经通过"谁能看见谁"编码了顺序,因此不对任意 token 排列等变;但它本身不直接编码两个可见位置之间的距离.RoPE 进一步对 Q/K 成对维度施加位置相关旋转;在一致约定下有:

$$
(R_m q)^{\mathsf T}(R_n k)=q^{\mathsf T}R_{n-m}k,
$$

因此点积可以显式依赖相对位移.这个等式解释了 RoPE 的相对位置结构,但不保证模型会自动泛化到训练长度之外;频率分布,训练数据,优化过程和评测任务仍然重要.

这些公式给出的是共同骨架,而不是强制规范.Norm 的位置,残差拓扑,激活函数,位置机制,注意力头组织和 FFN 是否由专家路由,都可能变化.

## 2. Prefill,Decode 与 KV 缓存

设输入长度为 $L$,隐藏维度为 $d$.通常 query 头数 $H_q$,头维度 $d_h$ 与模型宽度满足 $H_qd_h\approx d$.下面讨论长度 $L$ 的渐近变化时固定层数,头组织和 $d_h$,并忽略 batch,精度,张量并行和 kernel 常数;若比较不同模型宽度,则不能再同时把 $H_q$,$d_h$ 和 $d$ 都视为独立固定量.

### 2.1 Prefill

Prefill 会并行处理整段输入.对密集注意力:

- Q/K/V 和输出投影的量级通常为 $O(Ld^2)$;
- 计算注意力分数并与 V 相乘的算术量级为 $O(L^2d)$;
- 朴素实现若显式物化注意力分数或概率矩阵,会产生 $O(L^2)$ 规模的中间状态.

FlashAttention 通过分块和在线 softmax 避免把完整的 $L\times L$ 注意力矩阵写入高带宽显存,并降低 HBM 与片上存储之间的数据搬运.它计算的是精确注意力,核心算术项仍随 $L^2d$ 增长;实际速度取决于形状,硬件,精度和 kernel 实现.

### 2.2 Decode

自回归解码每步只新增一个 token.启用 KV 缓存后,不必为历史 token 重算 K/V;新 query 仍需读取并关注已有缓存.对第 $t$ 个位置:

- 单层投影和 FFN 的每 token 成本主要由模型宽度决定;
- 密集注意力读取历史 K/V 并计算加权和,单步成本随已缓存长度 $t$ 近似线性增长,即 $O(td)$;
- 连续生成 $T$ 个 token 的注意力总成本还会累积前缀读取,不能把"单步近线性"误解为整段生成与长度无关.

对于显式保存头状 K/V 的 MHA,MQA 或 GQA,若有 $N$ 层,$H_{kv}$ 个 KV 头,头维度 $d_h$,每个元素占 $b$ 字节,则单序列 KV 缓存的理想化存储量为:

$$
\operatorname{KVBytes}
= 2N L H_{kv} d_h b,
$$

系数 2 分别对应 K 和 V.固定层数,头数,头维度和精度时,KV 存储随序列长度 $L$ **线性**增长.MLA 的潜变量缓存,K/V 非对称布局,混合精度或量化缓存应对实际保存的张量逐项求和,不能直接套用这个头状公式;页块碎片,批处理,前缀共享,量化元数据和运行时工作区也需要另计.

### 2.3 不要混为同一笔账

| 对象 | 随长度的典型变化 | 不包含什么 |
|---|---|---|
| 模型参数 | 对固定模型通常不随输入长度变化 | 优化器状态,分布式副本另计 |
| Prefill 密集注意力算术 | $O(L^2d)$ | 投影与 FFN 的 $O(Ld^2)$ 另计 |
| Decode 单步密集注意力 | 对缓存长度近似 $O(Ld)$ | kernel 启动,批量与调度开销另计 |
| KV 缓存存储 | 对固定结构为 $O(L)$ | 碎片,工作区和通信缓冲另计 |
| 训练激活 | 依实现,重计算和并行策略而变 | 不能直接用推理 KV 公式代替 |

### 3.1 Transformer 组件

这一节先建立后续章节共同使用的词汇:

- [激活函数](./2.1-深度学习基础组件/2.1.1-激活函数/2.1.1-激活函数.md):从 Sigmoid/Tanh 到 ReLU,GELU/SiLU,SwiGLU 门控与 SiTU/PowLU 稳定化改造.
- [归一化层](./2.1-深度学习基础组件/2.1.2-归一化层/2.1.2-归一化层.md):区分 LayerNorm,RMSNorm 与归一化放置位置,不把"内部协变量偏移"当成唯一机制解释.
- [残差连接](./2.1-深度学习基础组件/2.1.3-残差连接/2.1.3-残差连接.md):分析恒等路径,残差尺度和跨层聚合,而不只记住 $x+f(x)$.
- [位置编码](./2.1-深度学习基础组件/2.1.4-位置编码/2.1.4-位置编码.md):先理解绝对位置,相对位置和 RoPE 本体,再进入 2.5 的长度扩展.
- [前馈网络 FFN](./2.1-深度学习基础组件/2.1.5-前馈网络FFN/2.1.5-前馈网络FFN.md):区分普通两层 MLP,GLU/SwiGLU 门控 FFN,工程成本,量化/MoE 路线.

适用边界:这里讨论组件本身及其相互作用;优化器,数据配方,并行训练和特定模型版本不在本节建立第二份正本.

### 3.2 注意力基础

建议先手算一个很小的因果注意力例子,再比较头组织:

- MHA 为每个 query 头保留独立 K/V 头;
- MQA 让多个 query 头共享一组 K/V;
- GQA 让一组 query 头共享一组 K/V,是 MHA 与 MQA 之间的结构折中;
- MLA 把需要缓存的表示压缩到潜变量,并涉及解耦位置分量和矩阵吸收等实现条件.

统一入口是 [多头注意力变体](./2.2-基础注意力机制/2.2.2-多头注意力变体/2.2.2-多头注意力变体.md).比较这些方法时,至少同时报告 query 头数,KV 头数或潜变量维度,缓存张量形状,是否能从已有权重转换,以及质量结论所依赖的训练设置.仅凭"KV 少了多少"不能推出端到端吞吐提升.

适用边界:MHA/MQA/GQA/MLA 是表示与头组织问题;FlashAttention 是精确注意力实现问题;PagedAttention 是服务侧缓存分配问题.

### 3.3 高效注意力与 KV

"高效注意力"至少包含四条不同路线:

1. **精确但 IO-aware**:[Memory-Efficient Attention](https://arxiv.org/abs/2112.05682),FlashAttention;数学结果保持为密集注意力,改变计算调度与中间状态存取.
2. **结构稀疏或选择性注意力**:只计算部分 token 对,降低有效交互数,但需要说明稀疏模式,训练方式,以及覆盖误差,近似误差,质量变化或结构归纳偏置.
3. **核分解线性注意力**:用特征映射重排注意力计算,并以聚合统计量避免显式两两交互;成本更低不代表与 softmax 注意力等价.若固定大小递推状态成为模型主体,应转入 2.4.
4. **KV 缓存压缩,选择或驱逐**:减少保存或读取的历史状态;需要区分训练时架构改变,无需训练的推理策略和近似误差.

[硬件高效注意力](./2.3-高效与稀疏注意力/2.3.1-硬件高效注意力/2.3.1-硬件高效注意力.md) 解释精确实现,[稀疏与压缩注意力](./2.3-高效与稀疏注意力/2.3.2-稀疏与压缩注意力/2.3.2-稀疏与压缩注意力.md) 讨论结构稀疏和推理时 KV 策略,[线性注意力机制](./2.3-高效与稀疏注意力/2.3.3-线性注意力机制/2.3.3-线性注意力机制.md) 只把核分解线性注意力作为正本;RWKV,Griffin,DeltaNet,SSM/Mamba 等以递推状态转移定义模型主体的路线归 2.4,2.3 只保留比较链接.

服务侧 PagedAttention 的核心是按块分配,寻址并共享动态增长的 KV 缓存,以控制碎片和冗余复制;请求调度由上层服务系统负责.其唯一系统正本应放在 [第 6 章:训练与推理优化](../6-训练与推理优化/6-训练与推理优化.md);本章只保留它与注意力数学,KV 张量形状之间的边界.

### 3.4 替代架构与条件计算

- [MoE](./2.4-前沿架构与变体/2.4.1-混合专家模型MoE/2.4.1-混合专家模型MoE.md) 用路由器为每个 token 选择少量专家.它可以让总参数量增长快于每 token 激活计算,但会引入负载均衡,容量,跨设备通信和路由稳定性问题.
- [状态空间模型](./2.4-前沿架构与变体/2.4.2-状态空间模型SSM/2.4.2-状态空间模型SSM.md) 从隐状态递推研究长序列;[Mamba](./2.4-前沿架构与变体/2.4.3-Mamba系列/2.4.3-Mamba系列.md) 让部分状态空间参数依赖输入,并配套硬件感知扫描算法.
- RWKV,Griffin,DeltaNet,线性 RNN,循环 Transformer 和混合模型以递推状态转移定义模型主体,正本放在 2.4;需要分别说明状态大小,训练并行方式,信息保留机制和与注意力层的组合方式,不能只以"O(L)"归为同一种算法.SSM/Mamba 同样属于这里,而不是 2.3 的核分解线性注意力正本.
- MTP 横跨三层:第 2 章分析共享表示,附加预测头或模块等**架构机制**;第 3 章维护辅助损失,损失权重,数据与训练配方;第 6 章维护草稿生成,目标验证,接受率和服务调度.
- 扩散语言模型改变生成因式分解和采样过程.本章只解释它与自回归架构的边界,完整数学,训练,采样和评测进入 [扩散语言模型知识库](../../diffusion-llm/_garden.md).

适用边界:总参数量,激活参数量,训练 FLOPs,推理 FLOPs,通信量和运行时延迟是不同指标.MoE 或递推架构的单一复杂度标签不能替代实测.

### 3.5 长上下文与长度泛化

审计长上下文方案时至少分开检查四个维度;它们不是所有架构都必须以同一机制满足的"必要条件":

1. **位置机制**:RoPE 类模型要检查位置索引与频率缩放在目标长度上的数值和训练边界;相对偏置,递推状态等架构应检查各自的位置或状态机制,不能套用 RoPE 频率规则.
2. **计算与存储可承受**:prefill,decode 和 KV 缓存没有超过系统预算.
3. **训练分布**:记录模型是否见过足够的长程依赖和对应监督,而不只是较长的填充文本;训练覆盖是重要证据变量,但并非所有训练外推方法的逻辑前提.
4. **能力证据**:分别验证远处证据检索,多处信息整合与推理,不能只凭困惑度或单一"针"测试宣称有效上下文.

[长上下文与外推技术](./2.5-长上下文与外推技术/2.5-长上下文与外推技术.md) 负责位置插值,NTK-aware 方法,YaRN,LongRoPE,长度训练与有效上下文评测.2.3 负责注意力/KV 机制,第 6 章负责上下文并行,缓存量化,调度和服务实现.名义最大窗口,训练窗口和有效能力窗口必须分开记录.

## 4. 如何选择分析坐标

遇到一个新架构或新论文时,按以下问题拆解,而不是先判断它是否"取代 Transformer":

| 分析坐标 | 应核对的问题 |
|---|---|
| 计算语义 | 输出与标准密集注意力是否数学等价,还是近似或全新递推 |
| 状态形状 | 每层保存哪些张量,大小如何依赖长度,头数和维度 |
| 训练要求 | 能否直接替换 kernel,是否需要继续训练,微调或从头训练 |
| 复杂度口径 | 讨论的是算术,显存容量,HBM IO,通信还是端到端延迟 |
| 质量证据 | 对照模型,token 预算,上下文长度和评测任务是否一致 |
| 失效模式 | 极端长度,短上下文,分布外输入和小批量时会发生什么 |
| 可复现性 | 公式,代码,配置与论文表格能否互相对齐 |

任何"线性复杂度""缓存减少若干倍"或"无需训练"的结论,都应标注变量,固定条件和适用阶段.

## 5. 推荐学习路线

### 路线 A:第一次系统学习

1. 从 2.1 掌握 FFN,Norm,残差和 RoPE.
2. 在 2.2 手算因果自注意力,并追踪 Q/K/V 的形状.
3. 用第 2 节分别计算 prefill,单步 decode 和 KV 存储.
4. 在 2.3 比较"数学等价的实现优化"与"改变计算图的架构优化".
5. 在 2.5 区分位置外推,系统容量和有效长程能力.
6. 最后进入 2.4,比较 MoE,SSM,Mamba,线性 RNN 和其他生成机制.

### 路线 B:推理与服务

先读 2.2 的 MQA/GQA/MLA,再读 2.3 的 FlashAttention 与 KV 压缩,随后转入第 6 章的 KV 量化,PagedAttention,批处理和调度.这样可以避免把缓存张量优化,内存分配和注意力 kernel 当成同一技术.

### 路线 C:长上下文研究

先读 2.1 的 RoPE 本体,再读 2.5 的长度扩展与评测,然后回到 2.3 选择稀疏,递推或 KV 策略,最后在第 6 章验证系统可行性.任何方法都应同时报告短上下文回退与目标长度结果.

## 7. 学完后的验证问题

如果能独立回答以下问题,说明已经建立了本章所需的分析框架:

1. 为什么无位置编码,无固定位置相关 mask 的全自注意力具有排列等变性,而固定因果 mask 会破坏任意排列等变性?RoPE 又怎样让点积显式依赖相对位移?

6. PagedAttention 为什么属于服务侧内存管理,而不是新的注意力表达形式?
7. 稀疏注意力,KV 驱逐和线性递推状态各自牺牲或改变了什么?

9. SSM/Mamba 的递推状态与 softmax 注意力的显式历史访问有何不同?
