# Radial Attention: 视频 DiT 的 $O(n\log n)$ 静态稀疏掩码

本节其余各篇处理的是自回归 LLM 的注意力和 KV cache. Radial Attention 的对象是扩散模型里的双向注意力, 没有 KV cache, 也没有 decode. 它放在这里, 是因为它和 [MoBA](../01-MoBA架构深度解析/01-MoBA架构深度解析.md), [NSA](../02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md) 一样在回答「一张稀疏掩码怎样设计」, 只是数据的结构不同.

---

## 1. 视频 DiT 的 3D 稠密注意力和已有做法

### 1.1 3D 稠密注意力的开销

扩散模型从高斯噪声 $X_T$ 出发, 在隐空间里逐步去噪得到 $X_0$, 再用预训练的解码器还原成视频. 视频比图像多一个时间维, 隐空间 token 数成倍增加. 论文给的例子是 HunyuanVideo 生成 5 秒 720p 视频约需 110K 个 token. 隐空间压缩得更狠可以减少 token, 但会损失画质, 所以 token 数降不下去.

近两年的视频生成模型 (HunyuanVideo, Wan2.1, Mochi 1 等) 多用 3D 稠密注意力, 所有 token 两两交互. 设视频隐变量有 $f$ 帧, 每帧 $s$ 个 token, 共 $n=fs$ 个 token. 稀疏注意力的一般写法是在 logit 上加一个掩码 (论文式 (2)):

$$
\mathrm{SparseAttention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top+M}{\sqrt d}\right)V,\qquad M\in\{-\infty,0\}^{n\times n}. \tag{1}
$$

$M$ 中为 $-\infty$ 的位置在 softmax 里被忽略. 计算量正比于 $M$ 中 0 的个数. 稠密注意力的 0 有 $n^2=f^2s^2$ 个, 帧数翻倍, 注意力计算量变成 4 倍.

### 1.2 已有做法

论文把已有方法分成三类.

**静态窗口.** STA (Sliding Tile Attention) 用 3D 滑动窗口只看时空邻域. 掩码固定, 好实现, 但感受野有限, 远距离的帧之间没有直接联系, 生成长视频时容易丢掉长程依赖.

**动态选择.** Sparse VideoGen (SVG) 在推理时做在线 profiling, 把每个注意力头分类成「空间头」或「时间头」, 分别套用对应的掩码. 空间头主要看相邻帧里的邻近 token, 时间头主要看各帧里同一空间位置的 token. 这能加速推理, 但用到训练上有问题: 在没见过的数据分布上 (例如更长的视频) profiling 可能分错, 而训练会强化这个错误. 动态掩码的决策也有在线开销.

**换成线性注意力.** SANA 等工作把 softmax 注意力换成线性注意力, 复杂度 $O(n)$, 但架构改动大, 只做少量微调恢复不了原模型的画质. 论文在 Table 2 里也试了把 HunyuanVideo 的注意力换成 SANA 式线性注意力再做长度扩展, 2 倍长度时 Vision Reward 为 $-0.205$, 远低于其他方法.

另外还有来自 LLM 的稀疏模式. LongLoRA 的移位分组注意力 (见 [04-DCA 与 S2-Attn](../../2.7-长上下文与外推技术/2.7.1-长度外推/01-DCA与S2-Attn-长上下文分块注意力/01-DCA与S2-Attn-长上下文分块注意力.md)) 用两种局部模式加移位得到全局感受野; PowerAttention 只让 token 关注距离为 2 的幂的位置, 也是 $O(n\log n)$. 这些模式把视频当成一维序列, 不利用时空结构.

论文要回答的问题是: 能否设计一张静态掩码, 表达能力接近动态方法, 又能用于训练.

## 2. 时空能量衰减

### 2.1 观察

论文从 HunyuanVideo 抽取 softmax 之后的注意力图 (Figure 4). 沿用 SVG 的术语, 空间注意力图里每个 token 主要关注相邻帧中的邻近 token, 时间注意力图里每个 token 主要关注各帧同一空间位置的 token. 两种曲线:

- 同一空间位置, 时间距离增大时, 平均注意力分数下降;
- 同一帧内, 空间距离增大时, 平均注意力分数下降.

对多个头和多个扩散步取平均后, 两条曲线都呈衰减. 用 $y=\exp(-ax+b)$ 回归, $R^2$ 超过 0.985 (Figure 8(b)). 论文把这一现象称为时空能量衰减.

### 2.2 形式化

考虑第 $i_0$ 帧, 空间位置 $k_0$ 处的 query, 它的注意力分数 $p=\mathrm{softmax}(Q_{i_0s+k_0}K^\top)$. 论文假设存在常数 $\alpha,\beta>0$ 和 $C_{\text{rel}}>0$, 使第 $j$ 帧空间位置 $l$ 处的 key 满足 (论文式 (3)):

$$
p_{js+l}\le C_{\text{rel}}\,e^{-\alpha|j-i_0|-\beta|l-k_0|}\,p_{i_0s+k_0}. \tag{2}
$$

$\alpha$ 控制时间方向的衰减, $\beta$ 控制空间方向的衰减. $\beta$ 大, $\alpha$ 小, 对应时间注意力: 同一位置跨很多帧都有分数, 空间上稍一偏离就衰减. $\alpha$ 大, $\beta$ 小, 对应空间注意力: 只看邻近帧, 但帧内范围较宽. SVG 用两种掩码分别处理这两类头, 式 (2) 把它们放进同一个模型里, 用一张掩码同时覆盖.

这里的 $|l-k_0|$ 是把每帧 token 展平后的一维下标差, 不是二维图像上的欧氏距离. 论文没有讨论这种展平对空间距离的影响.

## 3. Radial Attention 的掩码

### 3.1 时间方向: 带宽倍增, 密度减半

帧 $i$ 和帧 $j$ 之间的计算密度定为

$$
\rho(i,j)=\Bigl(\tfrac12\Bigr)^{r(i,j)},\qquad r(i,j)=\bigl\lfloor\log_2\max(|i-j|,1)\bigr\rfloor. \tag{3}
$$

按 $r$ 把帧对分到以主对角线为中心的带里: 帧 $i$ 到帧 $j$ 落在第 $\mathrm{sign}(j-i)\cdot r(i,j)$ 号带, 共 $2\lceil\log_2\max(f,2)\rceil-1$ 条带. 第 0 号带 (帧距 0 和 1) 密度 100%, 往外每条带密度减半. 第 $\pm1$ 号带之外, 每条带覆盖的帧距范围是前一条的两倍: 第 2 号带是帧距 4–7, 第 3 号带是 8–15. 带宽翻倍, 密度减半, 所以每条带的总计算量有一个与带号无关的上界. 带的条数是 $\log_2 f$ 量级, 总量就是 $O(\log f)$ 乘以单条带的量.

### 3.2 空间方向: 对角带收窄

式 (2) 表明, 跨帧时注意力集中在空间位置相近的 token 上. 所以每个帧对块 ($s\times s$) 里保留的是一条以对角线为中心的带, 带宽随帧距收窄:

$$
w(i,j)=\Bigl\lfloor\frac{s}{2^{r(i,j)}}\Bigr\rfloor. \tag{4}
$$

当 $2^{r}>s$ 时 $w$ 小于 1, 不能再收窄. 这时改为降低对角线出现的频率: 只在 $|i-j|\bmod\lceil 2^{r}/s\rceil=0$ 的帧对块里保留主对角线 ($k=l$), 其余帧对块全部屏蔽. 这样平均密度仍按式 (3) 减半.

### 3.3 完整定义

论文构造一个 4D 掩码 $\tilde M\in\{-\infty,0\}^{f\times f\times s\times s}$, $\tilde M_{i,j,k,l}=0$ 表示第 $i$ 帧位置 $k$ 的 token 可以关注第 $j$ 帧位置 $l$ 的 token (论文式 (4)):

$$
\tilde M_{i,j,k,l}=
\begin{cases}
0, & 2^{r(i,j)}\le s\ \text{且}\ |k-l|+1\le \dfrac{s}{2^{r(i,j)}},\\[6pt]
0, & |i-j|\bmod\Bigl\lceil\dfrac{2^{r(i,j)}}{s}\Bigr\rceil=0\ \text{且}\ k=l,\\[6pt]
-\infty, & \text{otherwise}.
\end{cases} \tag{5}
$$

展平后 $M_{is+k,\,js+l}=\tilde M_{i,j,k,l}$, 代入式 (1). 另外加一个 attention sink: 所有 token 都可以关注第一帧的全部 token. 论文的理由是第一帧的注意力对画质很关键, 做法参考了 StreamingLLM 和 SVG. 这和 [StreamingLLM](../../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/01-StreamingLLM与Attention-Sink/01-StreamingLLM与Attention-Sink.md) 里保留开头几个 token 的 KV 是同类现象, 实现不同: 这里保留的是整整一帧, 而且是双向注意力里的一个掩码区域, 不涉及 cache 驱逐.

实际计算按 $128\times128$ 的块进行, 而不是逐 token. 推理用 FlashInfer, 训练用 Block-Sparse-Attention 库, 后端是 FlashAttention-2. 式 (5) 是 token 级定义, 落到 kernel 时以块为单位决定算或不算.

### 3.4 手算一例

取 $s=4$, 看帧距 $d=|i-j|$ 从 0 到 11 时一个 $4\times4$ 帧对块里保留多少个位置:

| 帧距 $d$ | $r$ | 密度 $\rho$ | 走式 (5) 哪一支 | 保留位置 | 保留数 / 16 |
|---|---:|---:|---|---|---:|
| 0, 1 | 0 | 1 | 第一支, $w=4$ | 全块 | 16 |
| 2, 3 | 1 | 1/2 | 第一支, $w=2$ | $\lvert k-l\rvert\le1$ | 10 |
| 4–7 | 2 | 1/4 | 第一支, $w=1$ | $k=l$ | 4 |
| 8, 10 | 3 | 1/8 | 第二支, $8\bmod2=0$, $10\bmod2=0$ | $k=l$ | 4 |
| 9, 11 | 3 | 1/8 | 第二支, 奇数帧距不满足 | 无 | 0 |

$r=1$ 时 $w=2$, 条件 $|k-l|+1\le2$ 即 $|k-l|\le1$, 4×4 块里这样的位置有 $4+3+3=10$ 个, 比名义密度 1/2 对应的 8 个多. 原因在式 (5) 第一支的形状: $|k-l|\le w-1$ 是一条宽 $2w-1$ 条对角线的带, 块内保留的位置数是

$$
N(w)=s(2w-1)-w(w-1), \tag{6}
$$

代入 $s=4,w=2$ 得 10, $w=1$ 得 4. 每帧 token 很多时, 把 $w=s/2^r$ 代入, 保留比例约为 $2/2^r-1/4^r$: $r=1$ 时约 3/4, $r=2$ 时约 7/16, $r$ 较大时约 $2/2^r$, 是名义密度 $\rho$ 的两倍. 所以式 (3) 的「密度」是名义上的减半规律, 每个块实际保留的比例并不等于它, 但随带号同样按 2 倍递减. 式 (7) 的复杂度上界按每块 $2s^2/2^r$ 个位置计, 用的正是这个实际比例.

$r=3$ 时 $2^3=8>s=4$, 走第二支, $\lceil 8/4\rceil=2$, 帧距为偶数的块保留对角线 4 个位置, 奇数的全部屏蔽, 两块平均 2 个, 是 $r=2$ 时 4 个的一半. 对角线已经不能再窄, 就改为隔一个块保留一次.

### 3.5 一个 query 看到的范围

换到单个 query 的视角. 第 $i_0$ 帧位置 $k_0$ 的 query 能看到:

- 第 $i_0-1$, $i_0$, $i_0+1$ 帧的全部 token, 以及第 0 帧的全部 token (sink);
- 帧距 2–3 的帧里, 空间下标满足 $|l-k_0|<s/2$ 的 token;
- 帧距 4–7 的帧里, $|l-k_0|<s/4$ 的 token;
- 依此类推, 帧距越大, 可见的空间范围越窄; 窄到只剩 $l=k_0$ 之后, 再往远处只在部分帧里保留同位置的那一个 token.

画在「时间距离 × 空间距离」的平面上, 可见区域从中心向外收缩, 掩码的名字由此而来. 粗略计数, 中心带和 sink 共 $4s$ 个 token, 之后每一条带在两侧合计覆盖约 $2\cdot2^r$ 帧, 每帧可见约 $2s/2^r$ 个 token, 每条带约 $4s$ 个, 共约 $\log_2 f$ 条带. 一个 query 看到的 token 数约为 $4s\log_2 f$, 稠密注意力是 $fs$, 两者之比约 $4\log_2 f/f$. $f=32$ 时这个比值是 $20/32\approx0.63$, $f=128$ 时是 $28/128\approx0.22$. 这是上界意义下的估计, 说明帧数少时节省有限, 帧数越多节省越大.

这里的 $f$ 和 $s$ 是隐空间里的帧数和每帧 token 数, 不是像素帧. HunyuanVideo 的因果 3D VAE 在时间上压 4 倍, 空间上压 8 倍, DiT 再按 $1\times2\times2$ 打 patch. 768×1280 分辨率下每个隐帧是 $48\times80=3840$ 个 token; 117 帧对应 $(117-1)/4+1=30$ 个隐帧, 共约 11.5 万个 token; 4 倍长度的 509 帧对应 128 个隐帧, 正是上面 $f=128$ 的情形. 由此还能看出式 (5) 第二支在这个设置下用不上: 720p 级别的 $s$ 在 3600 (720×1280) 到 3840 之间, $2^r>s$ 要求 $r\ge12$, 而 $f=128$ 时最大的 $r$ 是 $\lfloor\log_2 127\rfloor=6$, 每条带都还在收窄对角带宽. 规模上, 117 帧时稠密注意力每层每头要算 $115200^2\approx1.33\times10^{10}$ 个分数; 509 帧约 49 万 token, 分数个数是它的 18 倍左右. 长度变成约 4.3 倍, 稠密计算量按平方增长, 这也是论文把长视频生成当作主要场景的原因.

### 3.6 和 SVG 及一维稀疏模式的对照

第 0 号带对相邻帧保留稠密交互, 覆盖了 SVG 空间头的模式. 对时间方向, SVG 的时间头给所有帧的同位置 token 分配同样的计算, 不考虑时间衰减; Radial Attention 减少给远帧的计算, 把预算移到时间上更近的 token. 一张掩码对所有头通用, 不需要在线分类.

LLM 侧的一维稀疏模式在视频上吃亏, 原因在 token 的排列方式. 视频 token 展平成一维序列时按帧排列, 第 $i$ 帧位置 $k$ 的下标是 $is+k$. 在这个一维序列里, 相邻帧同一位置的 token 相距 $s$, 帧距为 $d$ 的同位置 token 相距 $ds$. 从掩码形状可以看出 LLM 侧几种模式的问题:

- **PowerAttention** 只关注距离为 $2^m$ 的位置. 同位置 token 的距离 $ds$ 只有在恰好是 2 的幂时才被覆盖; $s$ 不是 2 的幂时, 跨帧同位置这一最重要的交互大多落在掩码外.
- **LongLoRA 的移位分组注意力** 把序列切成长度为 $G$ 的连续组, 一半头再平移半组. 组长小于 $s$ 时, 一个组只覆盖一帧的一部分, 跨帧同位置的 token 不在同组; 组长覆盖若干帧时, 同组内又包含大量空间上相距很远的 token.
- **滑动窗口** 在一维上取最近 $W$ 个 token, 等价于本帧附近的一段加上前一帧末尾的一段, 和空间邻近不对应.

Radial Attention 的式 (5) 直接用帧号 $i,j$ 和帧内位置 $k,l$ 定义, 不经过一维距离, 所以能同时表达「相邻帧稠密」和「远帧同位置稀疏」. 论文的实验结论与此一致: LongLoRA 和 PA 虽然有全局感受野, 但没有捕捉时空相关性, 长视频上画质下降.

## 4. 复杂度, 误差与长度扩展

### 4.1 复杂度

计算量正比于 $\tilde M$ 中 0 的个数. 帧数 $f$ 较大时, 论文给出上界 (论文式 (5)(6)):

$$
\#\text{zeros}(\tilde M)\le\underbrace{4s^2f}_{\text{中心带与 sink}}+\underbrace{\sum_{r=1}^{\lfloor\log_2 s\rfloor}2^{r+1}f\cdot\frac{2s^2}{2^r}}_{w\ge1}+\underbrace{\sum_{r=\lfloor\log_2 s\rfloor+1}^{\lceil\log_2 f\rceil-1}2^{\lfloor\log_2 s\rfloor+1}fs}_{w<1}\le 4s^2f\log_2 f=4sn(\log_2 n-\log_2 s). \tag{7}
$$

三项分别对应: 中心带 (每帧最多 3 个相邻帧块) 加 sink (每帧 1 个块), 最多 $4f$ 个满块; 对角带宽至少为 1 的带, 第 $r$ 号带覆盖约 $2^{r+1}f$ 个帧对块, 每块保留约 $2s^2/2^r$ 个位置, 乘积是 $4s^2f$, 和 $r$ 无关; 对角带宽小于 1 的带, 只剩稀疏的对角线. 分辨率固定 ($s$ 不变) 时, 计算量是 $O(n\log n)$.

论文 Figure 2 用 HunyuanVideo 生成 509 帧 720p 视频, 注意力计算量是稠密注意力的 1/9.

Table 2 报告了各设置下实际掩码的稀疏度, 可以看到它随长度上升: HunyuanVideo 2 倍长度 80.8%, 4 倍长度 88.3%; Mochi 1 分别是 76.4% 和 85.5%; Wan2.1-14B 2 倍长度 73.6%. 稀疏度 88.3% 意味着注意力只算约 11.7% 的位置, 但 4 倍长度上的推理加速是 3.71×, 不是 8.5×. 差距来自三部分: 长视频推理时前 2 个去噪步仍是稠密注意力 (训练时前两个 DiT block 也保留稠密); 线性层, 归一化等非注意力计算不受影响; 按 $128\times128$ 块执行时, 部分保留位置不多的块也要整块计算. 训练加速 (4.37×) 和推理加速接近, 因为反向传播里注意力的梯度计算用的是同一张块稀疏掩码.

### 4.2 误差上界

基于式 (2), 用掩码后的注意力分数 $\tilde p$ 与原分数 $p$ 的 $\ell_1$ 误差满足 (论文式 (7)):

$$
\lVert\tilde p-p\rVert_1\le C_{\text{rel}}\left[\frac{8e^{-\beta(s/2+1)}}{(1-e^{-\alpha})(1-e^{-\beta})}+4\,\frac{1+e^{-\beta}}{1-e^{-\beta}}\cdot\frac{e^{-\alpha(s+1)}}{1-e^{-\alpha}}\right]=O\bigl(C_{\text{rel}}\,e^{-\min(\beta/2,\,\alpha)\,s}\bigr). \tag{8}
$$

衰减率 $\alpha,\beta$ 越大, 误差越小. 方括号里两项大致对应掩码丢掉的两部分: 第一项含 $e^{-\beta(s/2+1)}$, 来自空间方向上被截掉的 token, 第 1 号带的可见范围是 $|l-k_0|<s/2$, 再往外的分数按 $\beta$ 衰减; 第二项含 $e^{-\alpha(s+1)}$, 来自帧距超过 $s$, 对角线开始隔块保留之后被屏蔽的远帧, 这些帧的分数按 $\alpha$ 衰减. 两项都随 $s$ 指数下降, 每帧 token 越多, 带宽越宽, 上界越小. 举个数: 若 $\alpha=\beta=0.1$, $s=100$, 指数因子 $e^{-\min(0.05,0.1)\times100}=e^{-5}\approx0.0067$. 这里的 $\alpha,\beta$ 是为演示取的值, 论文没有报告实测的衰减率. 这个上界依赖式 (2) 的指数衰减假设, 论文在局限一节也写明, 这个假设简化了自然视频里复杂的时空依赖. 实测方面, 论文在 Wan2.1-14B 上比较注意力输出的平均 MSE: Radial Attention $3.9\times10^{-3}$, SVG $4.4\times10^{-3}$, STA $1.5\times10^{-2}$.

### 4.3 用 LoRA 扩展生成长度

预训练模型只见过短视频. 不训练的长度外推方法 (如调整 RoPE 频率的 RIFLEx) 受长度分布不匹配的限制; 直接在长视频上全参数训练又太贵. Radial Attention 只剪掉不重要的 token 对, softmax 注意力本身不变, 所以预训练权重大部分可以保留, 少量微调就能适应. 训练的时间复杂度也降到 $O(n\log n)$.

微调用 LoRA, 作用在注意力的 query, key, value 和输出投影上, rank 128. 训练细节 (论文 §5.1 与附录 B):

| 项 | 设置 |
|---|---|
| 数据 | OpenVid-1M 中按美学和运动分数选出的 2000 个视频, 每个扩展长度一组 |
| 硬件 | 8 张 H100 |
| HunyuanVideo | 60 个 DiT block, 2 倍长度训 2400 步, 4 倍长度训 1200 步, 约 16–21 小时 |
| Mochi 1 | 48 个 block, 2 倍和 4 倍都训 5000 步, 约 8–17 小时 |
| Wan2.1-14B | 40 个 block, 2 倍长度训 2500 步, 约 15 小时 |
| 稠密部分 | 训练时前两个 DiT block 保留稠密注意力 |

Figure 8(a) 比较全参数微调和 LoRA. 对稠密注意力, LoRA 在 4 倍长度之前都落后于全参数微调; 用 Radial Attention 时, LoRA 与全参数微调持平或更好. 论文的解释是 LoRA 只更新对时间连贯性和画质最关键的参数. 长度扩展 LoRA 还可以直接和已有的风格 LoRA 合并使用; 附录 C.3 提到合并后风格有轻微差异, 归因于长度扩展 LoRA 的训练数据较少.

PSNR, SSIM, LPIPS 衡量的是和原模型输出的数值相似度, 不是绝对画质; Vision Reward 是一个学出来的打分模型, 用来近似人类评分, 越高越好. 长视频部分另用 VBench-long 的三个维度, 因为原模型在这三项上退化明显. 计算预算相同时, Radial Attention 在相似度指标上优于 STA 和 PowerAttention (PA), 和 SVG 相当. STA 更快, 是因为用了 FlashAttention-3, 而 Radial Attention 的实现用 FlashAttention-2; 但 STA 的画质下降明显. PA 同样是 $O(n\log n)$, 但忽略了视频的时空局部性. 端到端加速 (1.88×, 1.77×) 和 PFLOPs 的减少 (612→339 约 1.8×, 560→323 约 1.7×) 一致. 由于前 12 步和第一个 block 仍是稠密的, 端到端加速远小于注意力本身的稀疏度.

附录 D 的消融说明了这些稠密部分的作用. Wan2.1-14B 上, 计算量对齐时, 不做预热 PSNR 只有 12.8, 预热 4, 8, 11, 12, 13 步分别是 18.5, 21.7, 23.2, 23.6, 23.5, 12 步最好. 附录 A 还把 Radial Attention 和另一种 $O(n\log n)$ 模式 Harmonic Series (对角带宽与到主对角线的距离成反比) 对比, HunyuanVideo 上 PSNR 27.3 对 27.0.

长视频推理时只用前 2 个去噪步做稠密预热. 附录 D 的 HunyuanVideo 消融里, 预热 0, 1, 2, 3 步的 Vision Reward 分别是 0.154, 0.160, 0.163, 0.157; 训练时保留 0, 1, 2, 3 个稠密 block 分别是 0.139, 0.156, 0.163, 0.157. 两项都取 2 最好.

## 6. 和 LLM 稀疏注意力的对照与边界

### 6.1 和 LLM 稀疏注意力的对照

| | Radial Attention | MoBA / NSA | StreamingLLM |
|---|---|---|---|
| 注意力方向 | 双向 (扩散去噪) | 因果 | 因果 |
| 掩码来源 | 静态, 由帧距决定 | 动态, 由 query 和块的打分决定 | 静态, 开头 + 窗口 |
| 结构先验 | 时空两维, 指数衰减 | 一维序列, 无先验 | 一维序列, sink + 局部 |
| 复杂度 | $O(n\log n)$ | 块 top-k, 与 $n$ 近似线性的核心注意力 | $O(n\cdot\text{窗口})$ |
| 训练 | 预训练后 LoRA 微调 | 预训练或续训 | 不训练 |
| 有无 KV cache | 无 | 有 | 有, 驱逐中间部分 |

Radial Attention 的掩码不看内容, 完全由 token 在时空网格里的位置决定. 这在视频上可行, 是因为式 (2) 的衰减规律在不同输入上足够稳定; 文本里两个 token 是否相关主要取决于内容, 一维距离只能给出很弱的先验, 所以 LLM 侧的块稀疏方法大多要按 query 动态打分. 论文在结论里也把 NSA 和 MoBA 这类可训练的稀疏注意力列为后续方向, 用来处理高分辨率长视频.

### 6.2 边界

**分辨率方向仍是平方.** 式 (7) 是 $4s^2f\log_2 f$, 对每帧 token 数 $s$ 是平方关系. 分辨率升高时成本增长没有改善, 论文在局限中写明了这一点.

**依赖指数衰减假设.** 掩码和误差上界都以式 (2) 为前提. 对时空结构不符合这一假设的内容 (例如镜头切换, 远帧之间有强关联), 静态掩码可能丢掉重要的交互; 论文没有给出这类情况的评测.

**默认长度的加速有限.** 前 12 步和第一个 DiT block 仍用稠密注意力, 端到端加速在 1.8× 左右; 注意力的稀疏度更高, 但加速被这些稠密部分摊薄. 长度越长, 稀疏部分占比越大, 4 倍长度时推理加速到 3.71×.

**长度扩展需要微调.** 4 倍长度上不训练直接用, 质量问题来自预训练只见过短视频, Radial Attention 本身不解决长度分布不匹配, 要配合 LoRA.

**空间距离按一维下标算.** 式 (5) 用 $|k-l|$ 判断空间远近, 而帧内 token 是二维网格按行展平的, 同一列上下相邻的两个 token 下标差等于一行的宽度. 对角带收窄到小于一行宽度后, 竖直方向的邻居会先于水平方向的远处 token 被屏蔽. 论文没有讨论这一点.

**只验证了双向的整段生成.** 实验对象都是一次生成整段视频的双向 DiT. 逐段自回归生成视频 (如论文相关工作里提到的 Framepack) 的注意力是因果的, 是否适用没有实验.

**画质结果并非全面领先.** Wan2.1-14B 的 2 倍长度上 Vision Reward 低于稠密全参数微调; 默认长度上 HunyuanVideo 的 SSIM 低于 SVG.
