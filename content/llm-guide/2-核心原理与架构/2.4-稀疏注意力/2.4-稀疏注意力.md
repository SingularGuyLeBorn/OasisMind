# 2.4 · 稀疏注意力

[2.3 注意力的高效实现](../2.3-注意力的高效实现/2.3-注意力的高效实现.md) 里的 FlashAttention 让 $n\times n$ 的分数矩阵不必落地, 但每个 query 仍要和全部历史 key 做点积, prefill 的计算量是 $O(n^2d)$. 到 1M 长度, 这一项和 decode 时读全部 KV 的带宽一起成为主要开销. NSA 论文引用的估计是, 解码 64K 上下文时 softmax 注意力约占总时延的 70% 到 80%.

softmax 的权重通常集中在少数 key 上, 所以一个自然的做法是只算这一部分. 这一节的五篇都保留 softmax 注意力, 并且让模型在预训练或续训中就按稀疏模式学习. 只在推理时对训好的稠密模型做裁剪或驱逐的方法 (StreamingLLM, H2O, SnapKV, Quest 等) 放在 [2.7.2 KV 缓存压缩与淘汰](../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/2.7.2-KV缓存压缩与淘汰.md), 把 softmax 换成递推状态的方法放在 [2.5 线性注意力与状态空间模型](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md).

## 1. 打分器加精确注意力

### 1.1 共用的记号

这一节的 LLM 方法都把一层注意力拆成两步. 第一步由一个便宜的打分器给 query $t$ 和每个候选单元打分; 第二步只对分数最高的 $k$ 个单元做精确 softmax 注意力. 记序列长 $N$ (或 $n$), 块大小 $B$, 选中块数 $k$, 则序列末尾的 query 看到约 $kB$ 个 token, 稀疏度为 $1-kB/N$. 位置小于 $kB$ 的 query 能选的块不超过 $k$ 个, 实际上在做全注意力, 所以短序列上这一类方法都没有加速.

各方法的区别落在三处: 打分器是什么 (块内 key 均值, 压缩分支的注意力, 独立的 lightning indexer), 选择单位是什么 (单个 token, 64 token 的块, 4 token 的微块, 压缩后的条目), 被选中的单位以什么精度参与注意力 (原始 token, 还是压缩后的条目本身). 第三处决定 KV cache 能不能变小. MoBA, NSA, DSA, QSA 的打分只决定加载哪些位置, 完整 KV 仍留在显存里; CSA 和 HCA 的压缩条目本身就是 key 和 value, cache 条目数变成原来的 $1/m$.

### 1.2 为什么按块选

MoBA 和 NSA 都按连续块选择, 理由有两条. 硬件上, GPU 读连续块比按下标随机读快得多, 块内计算能用上 Tensor Core; 数据上, NSA 论文对 27B 全注意力模型的注意力图做了可视化, 高分区域呈块状聚集. NSA 还指出另一个问题: GQA 模型里一组 KV 被组内所有 query 头共用, 如果每个头各自选 token, 实际读取量是各头选择的并集. 一组 16 个头各选 1024 个 token, 重叠很少时这组 KV 的读取量接近 16384 个 token, 计算降了, 访存没降多少. NSA 把组内各头的块分数求和, 只做一份选择.

按块选的代价在打分. MoBA 用 query 和块内 key 均值的内积打分, 等于块内各 token logit 的平均. [01 MoBA](01-MoBA架构深度解析/01-MoBA架构深度解析.md) 第 1.3 节的例子: $B=4$, 块 A 的 logit 是 $(10,0,0,0)$, 均值 2.5, 块 B 是 $(3,3,3,3)$, 均值 3, 门控选 B; 而 softmax 下 A 里那个 logit 为 10 的 token 权重是 B 中任一 token 的约 1100 倍. 块越小, 均值越接近块内最大值, MoBA 的块粒度实验也是越细越好. 但块越小, 打分项 $O(N^2/B)$ 越大. 后面几篇的改进, 大都是在「打分要准」和「打分要便宜」之间换一种做法.

## 2. 从 MoBA, NSA 到 CSA 与 QSA

### 2.1 两条同期的路

[MoBA](01-MoBA架构深度解析/01-MoBA架构深度解析.md) 的结构最简单: 只有一路选择, 打分没有参数, 当前块强制选中并加因果掩码 (论文把它对应到 MoE 的共享专家). 参数和全注意力完全一致, 每层可以随时切换. Llama 3.1 8B 续训到 1M 后打开 MoBA, 块大小 4096, top-12, 最终 3 层保留全注意力. 1M prefill 时注意力层快 6.5 倍. 01 第 3.3 节算了一笔: 29 个 MoBA 层合计约等于 2.7 个全注意力层的计算, 和保留的 3 层差不多, 只占 3/32 层数的全注意力贡献了约一半的注意力计算.

[NSA](02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md) 给每个 query 三路分支: 块长 32, 步长 16 的压缩摘要; 用压缩分支的 softmax 分数选出的 16 个 64 token 原始块; 最近 512 个 token 的滑动窗口. 三路各自做 softmax, 再用 sigmoid 门加权, 各有独立的 KV. 选择不可导, 但块分数来自参与主损失的压缩分支, 不需要辅助损失. 在 27B 激活 3B 的 MoE 上从预训练开始用 NSA, LongBench 平均 0.469, 全注意力 0.437; 64K 训练前向快 9.0 倍, 反向快 6.0 倍; 解码按读取量算的预期加速是 11.6 倍. 两者的分歧在于局部上下文怎么保证 (MoBA 的当前块, NSA 的独立窗口分支) 和打分器要不要参数.

### 2.2 indexer 自己的平方项

DeepSeek-V3.2 的 DSA 用一个低维, 多头, 带 ReLU 的 lightning indexer 给每个历史 token 打分, 核心注意力取 top-2048, 复杂度从 $O(n^2)$ 降到 $O(nk)$. indexer 本身仍是 $O(n^2)$, 1M 时每个 query 要扫 1048576 个 indexer key, KV cache 也仍是每 token 一条. 本节后两篇的 LLM 方法都从这里接着改, 方向不同.

[CSA 与 HCA](04-CSA-HCA-混合压缩注意力/04-CSA-HCA-混合压缩注意力.md) 是 DeepSeek-V4 的做法: 沿序列维压缩 KV 本身. CSA 每 4 个 token 压成一个条目 (每个条目看 8 个 token, 相邻重叠), 在条目上用 indexer 取 top-k (V4-Flash 512, V4-Pro 1024); HCA 每 128 个 token 压成一条, 不做选择, 对全部条目稠密注意力, 1M 压到 8192 条. 两种层都加 128 个未压缩 token 的窗口和每头一个可学习的 sink logit. 报告估算 1M 时 V4-Pro 的单 token FLOPs 是 V3.2 的 27%, 累计 KV cache 是 10%. [QSA](05-QSA-Qwen稀疏注意力/05-QSA-Qwen稀疏注意力.md) 只压缩 indexer 的 key: 每 4 个平均池化成一个微块, 先池化再按块起点加 partial RoPE, 在微块上打分后展开回原始 token, 核心注意力看的仍是原始 KV. 它装在每四层三层 GDN 一层全局注意力的混合骨架里, 48 层中 12 层是 QSA, indexer 只用 4 个 query 头. 1M 长度上注意力模块的 kernel 延迟相对 FlashInfer 稠密 GQA, prefill 快 7.6 倍, decode 快 4.9 倍. GLM-5.3-Flash 的 IndexPool 同样把 4 个 indexer key 压成一个, 用的是加权池化, 权重形式没有公开.

### 2.3 视频上的静态掩码

[Radial Attention](03-RadialAttention稀疏注意力/03-RadialAttention稀疏注意力.md) 处理的是另一类模型: 视频扩散 DiT 的双向 3D 注意力. HunyuanVideo 生成 5 秒 720p 视频约 110K 个 token, 帧数翻倍注意力计算变成 4 倍. 论文从注意力图里观察到分数随时间距离和空间距离都按指数衰减 (回归 $R^2$ 超过 0.985), 于是让帧对之间的计算密度随时间距离每翻倍减半, 得到一张 $O(n\log n)$ 的静态掩码, 不按内容打分.

这张掩码可以直接替换做推理加速, 也可以配 LoRA 把生成长度扩到 4 倍: HunyuanVideo 4 倍长度上 Vision Reward 与稠密全参数微调相当, 训练快 4.37 倍, 推理快 3.71 倍. 它能不看内容, 是因为视频里的衰减规律在不同输入上足够稳定; 文本里两个 token 是否相关主要由内容决定, 一维距离只给出很弱的先验, 所以 LLM 侧的方法都要按 query 动态打分. 对每帧 token 数 $s$, 它的成本仍是平方, 分辨率升高时没有改善.

## 3. 五种设计的对照

### 3.1 打分, 单位与 cache

| 方法 | 打分器 | 选择单位 | 核心注意力看到什么 | KV cache |
|---|---|---|---|---|
| MoBA | query 与块 key 均值, 无参数 | 块, top-$k$ 含当前块 | 选中块的原始 token | 不变 |
| NSA | 压缩分支的 softmax, GQA 组内求和 | 64 token 块 | 压缩摘要 + 选中块 + 512 窗口 | 不变, 另加压缩 KV |
| CSA | lightning indexer, 打在压缩条目上 | 压缩条目 | top-$k$ 条目 + 128 窗口 | 4 合 1 |
| HCA | 无 | 不选择 | 全部 128 合 1 条目 + 128 窗口 | 128 合 1 |
| QSA | 4 头 MQA indexer, 平均池化微块 | 4 token 微块 | 选中微块展开的原始 token + 尾部 | 不变 |
| Radial | 无, 由时空位置决定 | 静态掩码 | 掩码内的 token | 无 KV cache (双向) |

表的最终两列把方法分成两组. MoBA, NSA, QSA 的打分只决定读哪些位置, 被选中的部分以原始精度参与注意力, 远处的任何 token 只要被选中都能逐字取回, 代价是 KV cache 一个字节没省. NSA 第 4.2 节按论文配置推算, 64K 上下文选择分支的完整 KV 约 4.7 GiB; QSA 第 6.2 节估算 12 个 QSA 层在 1M 上的 BF16 KV 约 24 GiB. CSA 和 HCA 反过来, 远处 token 只以压缩形式存在, 原始精度只保留在 128 token 的窗口里. V4 的 MRCR 曲线 128K 以内很稳, 超过 128K 后可见下降, 报告没有做把下降归因到压缩的消融.

打分器一列反映训练方式. MoBA 没有独立打分参数, 只靠 $Q,K$ 在注意力训练中学到的表示; NSA 的打分来自本身参与语言模型损失的压缩分支; DSA, CSA, QSA 的 indexer 有独立参数, 训练分两阶段, 先冻结主干用 KL 散度让 indexer 对齐稠密注意力分布, 再打开稀疏选择联合训练. QSA 的老师分布要从 token 对齐到块, 块内取最大值而不是平均, 避免单个高分 token 被稀释成 $1/r$. NSA 论文第 6 节试过辅助损失打分和 Quest 式无参数启发式, 损失都比 NSA 差.

### 3.2 共同的边界

几篇的实验条件都要分开看. MoBA 的下游实验只在 prefill 用 MoBA, 生成阶段切回全注意力; NSA 的 11.6 倍是按读取量之比算的预期值, 论文没有给出解码的实际延迟; CSA 的 27% 与 10% 是报告 Figure 1 的估算; QSA 的 7.6 倍是 kernel 延迟, 官方博文的 8.6 倍是 90% 前缀缓存命中下相对上一代模型的端到端 prefill 吞吐, 两者不能换算.

结构上也有两条共同的约束. 第一, 都要训练: MoBA 至少续训, NSA 从预训练开始, CSA 先稠密预热 1T token 再在 64K 引入稀疏, QSA 在 256K 续预训练中替换, 只做阶段 1 蒸馏就直接稀疏推理, RULER 明显下降. 第二, 都保留了某种稠密成分: MoBA 的 1M 模型保留最终 3 层全注意力, QSA 本身就是全局层, 旁边 GDN 负责其余三层, HCA 对全部压缩条目稠密注意力, Radial 的前几个去噪步和前两个 DiT block 仍用稠密注意力. 纯稀疏的配置在尾部损失, SFT 或长距离检索上都不如全注意力.

## 4. 读的顺序

### 4.1 从块稀疏的基本形式进

先读 [01 MoBA](01-MoBA架构深度解析/01-MoBA架构深度解析.md). 它的门控只有式 (5) 和式 (6) 两行, 第 1.5 节在 $N=12, B=3, k=2$ 上把因果规则手算了一遍, 第 2.2 节把块选择和 MoE 的专家选择逐项对应. 接着读 [02 NSA](02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md), 重点是第 2.3 节压缩分数怎样按重叠长度累加到选择块上, 第 2.5 节每个 query 看多少 token 的表, 以及第 2.6 节按 GQA 组加载 query 的 kernel. 两篇读完, 「打分器, 选择单位, 局部上下文」三个变量就都出现过了.

关心 1M 上下文模型的读者接着读 [04 CSA 与 HCA](04-CSA-HCA-混合压缩注意力/04-CSA-HCA-混合压缩注意力.md) 和 [05 QSA](05-QSA-Qwen稀疏注意力/05-QSA-Qwen稀疏注意力.md). 两篇都从 DSA 的 indexer 平方项出发, 04 第 3.2 节在 $t=1000$ 和 $t=2^{20}$ 两个位置上追踪一个 query 实际算了什么, 05 第 4.3 节用模型卡的数字估算 indexer 的点积量. 两篇放在一起读, 能看出「压缩 KV 本身」和「只压缩 indexer」在 cache, 检索精度和推理框架支持上的不同后果.

### 4.2 从别的方向进

做视频生成的读者可以单独读 [03 Radial Attention](03-RadialAttention稀疏注意力/03-RadialAttention稀疏注意力.md), 它和其余四篇只共享掩码式 $\operatorname{softmax}((QK^\top+M)/\sqrt d)V$ 这一层记号. 第 6.1 节有它和 MoBA, NSA, StreamingLLM 的对照表.

已经有一个训好的稠密模型, 只想在推理时省显存或省带宽, 这一节的方法都需要训练, 应该去读 [2.7.2 KV 缓存压缩与淘汰](../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/2.7.2-KV缓存压缩与淘汰.md). 其中的 [Quest](../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/08-Quest-查询感知稀疏/08-Quest-查询感知稀疏.md) 也按页打分, 用每页 key 的逐通道最小值和最大值估计上界, MoBA 论文把它看作块更小, 用 min/max 作块表示的 MoBA. 想延长训练上下文本身, 去读 [2.7.1 长度外推](../2.7-长上下文与外推技术/2.7.1-长度外推/2.7.1-长度外推.md), 其中 [DCA 与 S²-Attn](../2.7-长上下文与外推技术/2.7.1-长度外推/01-DCA与S2-Attn-长上下文分块注意力/01-DCA与S2-Attn-长上下文分块注意力.md) 也是分块注意力, 用途是在原有位置范围内延长可用上下文.
