# DCA 与 S²-Attn: 长上下文扩展里的两种分块

把一个 4K 预训练的 Llama2 直接用在 32K 输入上, 坏的有两样东西. 第一样是位置: RoPE 让点积只依赖 query 与 key 的位置差, 超过 4K 的位置差模型从没见过, 困惑度会直接上到三位数. 第二样是算力: 想通过长序列微调让模型适应, 注意力的计算量随长度平方增长, 8192 长度的注意力 FLOPs 是 2048 的 16 倍. DCA 和 S²-Attn 都把序列切成块, 但切块解决的是不同的问题. **DCA** (Dual Chunk Attention, [An et al., 2024](https://arxiv.org/abs/2402.17463)) 不做任何训练, 切块是为了让所有相对位置都落回预训练见过的范围; **S²-Attn** (Shifted Sparse Attention, 出自 LongLoRA, [Chen et al., 2023](https://arxiv.org/abs/2309.12307)) 只在微调时切块, 为的是把注意力算力降到原来的约 $1/4$, 推理时模型照常做全注意力.

两者都不减少推理时的 KV cache, 也不改变推理阶段的注意力计算量. 它们和 [01 MoBA](../../../2.4-稀疏注意力/01-MoBA架构深度解析/01-MoBA架构深度解析.md), [02 NSA](../../../2.4-稀疏注意力/02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md) 那种推理时只读部分 KV 的稀疏方法不是一类, 放在本节是因为它们和块状注意力图有直接关系.

---

## 1. 预训练窗口之外坏在哪里

### 1.1 相对位置矩阵与未见过的距离

RoPE 给每个 query 和 key 一个位置号. 记 key 的位置号列表为 $P_{\mathbf{k}}$, query 的为 $P_{\mathbf{q}}$, 标准做法是 $P_{\mathbf{k}}=P_{\mathbf{q}}=[0,1,\ldots,l-1]$. 用 $f(\mathbf{q}, p)$ 表示对向量 $\mathbf{q}$ 按位置 $p$ 施加旋转, 第 $i$ 个 query 和第 $j$ 个 key 的内积只依赖位置差, DCA 论文把这个位置差排成矩阵:

$$
M[i][j]=P_{\mathbf{q}}[i]-P_{\mathbf{k}}[j], \qquad j\le i. \tag{1}
$$

标准 RoPE 下 $M[i][j]=i-j$, 是一个 Toeplitz 矩阵, 对角线是 0, 左下角是 $l-1$. 预训练长度 $c$ 的模型只见过 $0$ 到 $c-1$ 的位置差. DCA 论文 §2.2 把外推失败归到这里: 推理长度超过 $c$ 后, 矩阵左下角出现大于 $c-1$ 的位置差, 旋转角度落在训练分布之外.

Position Interpolation (PI) 和 NTK-aware RoPE 的做法是把 $M$ 的数值缩小. PI 在长度 12, 预训练长度 6 的例子里把所有位置号除以 2, $M[i][j]$ 跟着除以 2, 最大位置差回到 6 以内. 代价是相邻 token 的位置差变成 0.5, 位置分辨率减半. 这两种方法本来需要配合微调使用; 不训练直接用时, DCA 论文 Table 1 在 Llama2 7B, PG19 验证集上测出: PI 在 16K 困惑度 15.11, NTK 是 26.12, 加 YaRN 的 NTK 是 9.82, 而 4K 时三者都是 7.87. 输入超过预训练长度两倍以后, 不训练的缩放方法都明显变差.

### 1.2 长序列微调的算力

另一条路是用长序列继续训练. LongLoRA 论文开头给的比例是: 训练长度 8192 时自注意力的计算量是 2048 时的 16 倍. 它的 Table 11 用 torchprofile 统计 Llama2 7B 单条序列 prefill 的 FLOPs, 把注意力核, 投影, FFN 分开:

| 长度 | 注意力 (T) | 投影 (T) | FFN (T) | 合计 (T) | 注意力占比 |
|---|---:|---:|---:|---:|---:|
| 8192 | 35.2 | 35.2 | 70.9 | 143.5 | 24.5% |
| 16384 | 140.7 | 70.4 | 141.8 | 357.2 | 39.4% |
| 32768 | 562.9 | 140.7 | 283.7 | 996.0 | 56.5% |
| 65536 | 2251.8 | 281.5 | 567.4 | 3118.0 | 72.2% |

长度每翻一倍, 投影和 FFN 翻一倍, 注意力翻四倍. 到 65536 时注意力占了 72.2%. LoRA 只减少可训参数和优化器状态, 不减少这部分前向和反向计算, 所以 LongLoRA 论文 Figure 1 里普通 LoRA 的训练时长随长度增长的速度和全参微调差不多.

两个方法正好对应两个问题. DCA 处理 1.1, 前提是完全不训练; S²-Attn 处理 1.2, 前提是愿意微调, 只想让微调便宜.

## 2. DCA: 不训练, 重写相对位置矩阵

### 2.1 符号

DCA 论文的记号: 预训练长度 $c$, 块大小 $s$ ($s<c$), 局部窗口 $w$, 输入长度 $l$, 块数 $n=l/s$. Llama2 的 $c=4096$, 论文 §4.1 默认 $s=\frac{3}{4}c=3072$, $w$ 直接取 $c-s=1024$. 按这组默认值, 32K 输入有 $32768/3072\approx10.7$, 即 11 块. 后面三种位置编号里 query 的位置号最大是 $c-1=4095$, key 的位置号最小是 0, 所以不管输入多长, 任意一对 query 和 key 的相对位置差都不超过 4095, 落在预训练见过的范围里. 位置插值的做法是把所有位置差按比例缩小, 相邻 token 之间的位置差也跟着变小; DCA 在块内保留原来的位置差, 只改跨块的编号.

DCA 只改位置号, 不改 query, key, value 向量本身, 也不改模型权重. key 的位置号在块内循环:

$$
P_{\mathbf{k}}=[0,1,\ldots,l-1] \bmod s. \tag{2}
$$

key 的位置号只有这一套, 所以 KV cache 里的 key 只需要按 $P_{\mathbf{k}}$ 旋转一次存下, 后面不再改动. 论文 §3.2 明确说保留 $P_{\mathbf{k}}$ 不变是为了兼容 KV cache. query 的位置号有三套, 按 query 所在块和 key 所在块的距离选用.

### 2.2 块内: 等价于截断

同一块内, query 也用块内位置号:

$$
P^{\text{Intra}}_{\mathbf{q}}=P_{\mathbf{k}}, \qquad M[i][j]=P^{\text{Intra}}_{\mathbf{q}}[i]-P_{\mathbf{k}}[j]\quad \text{当}\ \lfloor i/s\rfloor=\lfloor j/s\rfloor. \tag{3}
$$

块内的位置差和标准 RoPE 相同, 都是 $i-j$, 最大 $s-1$. 如果只用块内注意力, 每个 query 只看自己所在块, 效果等于把输入从左边截断到不超过 $s$ 个 token. 截断的困惑度很低 (StreamingLLM 等工作已经观察到), 但前面块里的信息完全看不到. DCA 论文引言把 LM-Infinite 和 [StreamingLLM](../../2.7.2-KV缓存压缩与淘汰/01-StreamingLLM与Attention-Sink/01-StreamingLLM与Attention-Sink.md) 归为这一类: 只保留局部信息, 困惑度可以维持很低, 长距离依赖却没有了. 困惑度低不代表模型用上了长上下文, 这也是 DCA 论文除困惑度外还要测 passkey 和长文档问答的原因.

decode 时, 新 token 的 key 按 $P_{\mathbf{k}}$ 旋转后写入 cache, 和标准推理流程一样; 只有当前 query 需要按三套位置号各旋转一次. 因为 key 的位置号按块循环, 一个块内的 key 和下一个块同偏移的 key 旋转角度相同, 这对 cache 没有额外要求.

### 2.3 远块: 所有 query 用同一个大位置号

要让 query 看到前面的块, 直接用 $P^{\text{Intra}}_{\mathbf{q}}$ 会出问题. 例如第 $s$ 个 query (第二块第一个) 的块内位置是 0, 第 1 个 key 的位置是 1, 位置差是 $-1$, 违反了「query 位置号不小于前面 key」的因果习惯. DCA 的做法是给跨块的 query 一个比所有 key 位置号都大的常数, 取预训练时出现过的最大位置号:

$$
P^{\text{Inter}}_{\mathbf{q}}=[\underbrace{c-1,\;c-1,\;\ldots,\;c-1}_{l\ \text{个}}]. \tag{4}
$$

于是跨块时

$$
M[i][j]=c-1-P_{\mathbf{k}}[j]\ \ge\ c-s. \tag{5}
$$

式 (5) 说明了远块注意力丢掉的是什么: 位置差只取决于 key 在它自己块内的偏移, 和 query 在哪个块, key 在哪个块都无关. 隔 2 个块的 key 和隔 20 个块的 key, 只要块内偏移相同, 位置差就相同. 块与块之间的距离信息被完全抹掉, 远处 token 只剩「比所有近处 token 都远」这一层顺序.

### 2.4 相邻块: 恢复局部性

只用式 (4) 时, 相邻块之间也被当成远块处理. 论文 §3.3 的例子: $s=6$, $c=10$, 第一块最后一个 key $\mathbf{k}_5$ 的位置号是 5, 第二块第一个 query $\mathbf{q}_6$ 的位置号是 9, 两者实际相邻, 位置差却是 4. 语言模型预测下一个 token 时高度依赖紧邻的几个 token, 这一错位会直接抬高困惑度.

DCA 对相邻块单独定义一套 query 位置号, 让块内前 $w$ 个位置接着上一块的末尾往下数:

$$
P^{\text{Succ}}_{\mathbf{q}}=[\underbrace{\overbrace{s,\;s+1,\;\ldots,\;s+w-1}^{w\ \text{个}},\;c-1,\;\ldots,\;c-1}_{\text{每个块相同}}]. \tag{6}
$$

$w$ 取 $c-s$ 时, $s+w-1=c-1$, 前 $w$ 个位置号从 $s$ 递增到 $c-1$, 之后保持 $c-1$. 这样当前块前 $w$ 个 query 看上一块时, 位置差等于真实距离; 第 $w$ 个以后的 query 看上一块, 位置差回到式 (5) 的形式.

### 2.5 三段合起来

三套规则按块距离拼成完整的相对位置矩阵:

$$
M[i][j]=
\begin{cases}
P^{\text{Intra}}_{\mathbf{q}}[i]-P_{\mathbf{k}}[j], & \lfloor i/s\rfloor-\lfloor j/s\rfloor=0,\\
P^{\text{Succ}}_{\mathbf{q}}[i]-P_{\mathbf{k}}[j], & \lfloor i/s\rfloor-\lfloor j/s\rfloor=1,\\
P^{\text{Inter}}_{\mathbf{q}}[i]-P_{\mathbf{k}}[j], & \lfloor i/s\rfloor-\lfloor j/s\rfloor>1.
\end{cases} \tag{7}
$$

用论文 Figure 2 的设置手算几项: $s=6$, $c=10$, $w=4$. 为了让三段都出现, 取 $l=18$, 共 3 块. $P_{\mathbf{k}}=[0..5,\,0..5,\,0..5]$; $P^{\text{Succ}}_{\mathbf{q}}$ 在每块内是 $[6,7,8,9,9,9]$; $P^{\text{Inter}}_{\mathbf{q}}$ 全是 9.

| $(i,j)$ | 块距离 | 用哪套 | 计算 | $M[i][j]$ | 真实距离 $i-j$ |
|---|---|---|---|---:|---:|
| (8, 7) | 0 | Intra | $2-1$ | 1 | 1 |
| (6, 5) | 1 | Succ | $6-5$ | 1 | 1 |
| (7, 2) | 1 | Succ | $7-2$ | 5 | 5 |
| (11, 0) | 1 | Succ | $9-0$ | 9 | 11 |
| (12, 11) | 1 | Succ | $6-5$ | 1 | 1 |
| (12, 3) | 2 | Inter | $9-3$ | 6 | 9 |
| (17, 0) | 2 | Inter | $9-0$ | 9 | 17 |
| (17, 5) | 2 | Inter | $9-5$ | 4 | 12 |

表里每一项都在 $[0, 9]$ 之内, 也就是不超过 $c-1$. 块内项和真实距离完全一致; 相邻块的前 $w$ 个 query 一致, 之后被截到 9 以内; 远块项和真实距离不再单调对应, $(17,5)$ 真实距离 12, 位置差只有 4, 比 $(12,3)$ 还小. 这一项也说明了远块近似的另一个副作用: 同一个远块内部, 块内偏移越大的 key 位置差反而越小.

各段的值域可以直接从定义读出: 块内 $[0, s-1]$; 相邻块 $P^{\text{Succ}}_{\mathbf{q}}\in[s, c-1]$ 减去 $P_{\mathbf{k}}\in[0,s-1]$, 落在 $[1, c-1]$; 远块按式 (5) 落在 $[c-s, c-1]$. 三段的并集是 $[0, c-1]$, 这正是 DCA 的设计目标.

### 2.6 归一化与 FlashAttention

内积按式 (7) 选好位置号后, 每个 query 对它之前所有 key 做一次普通 softmax (论文式 (9)). 三段共享同一个 softmax 分母, 不是三个注意力输出各自归一化再相加.

实现上 query 要按三套位置号各旋转一次, 一次 FlashAttention 调用只能用一种旋转, 所以论文附录 A.3 的 Algorithm 1 对第 $i$ 个 query 调三次 FlashAttention:

1. 块内: query 用 $P^{\text{Intra}}_{\mathbf{q}}[i]$ 旋转, key 取当前块 $[s\lfloor i/s\rfloor, i]$, 带因果掩码.
2. 相邻块: query 用 $P^{\text{Succ}}_{\mathbf{q}}[i]$ 旋转, key 取上一块的 $s$ 个, 不需要因果掩码.
3. 远块: query 用 $P^{\text{Inter}}_{\mathbf{q}}[i]$ 旋转, key 取更早的 $s(n-1)$ 个, 不需要因果掩码.

每次调用返回该段的输出 $\mathbf{o}$ 和该段指数和 $Z$, 合并时按指数和加权:

$$
\mathbf{o}_i=\frac{Z_{\text{intra}}\,\mathbf{o}_{\text{intra}}+Z_{\text{succ}}\,\mathbf{o}_{\text{succ}}+Z_{\text{inter}}\,\mathbf{o}_{\text{inter}}}{Z_{\text{intra}}+Z_{\text{succ}}+Z_{\text{inter}}}. \tag{8}
$$

式 (8) 和 FlashAttention 分块计算时合并部分结果用的是同一个恒等式, 结果与一次性对全部 key 做 softmax 完全相同. 三段 key 加起来正好是全部历史, 复杂度分别是 $O(i-ns)$, $O(s)$, $O(s(n-1))$, 总和是 $O(i)$. 所以 DCA 的单步 decode 和稠密注意力一样读全部 KV, prefill 一样是 $O(l^2)$. 它解决的是位置外推, 不是计算量.

论文 Figure 3 在单张 A100 80G, Llama2 7B 上比较了原始 PyTorch 注意力, FlashAttention 和 DCA 的推理时间与显存: 不用 FlashAttention 时单卡最多处理约 12K 到 16K token; DCA 的时间和显存与 FlashAttention 基本一致. 正文脚注还给出两张 A100 80G 上不用 FlashAttention 的上限: 7B/13B 约 16K, 70B 约 5K.

### 2.7 实验

DCA 在论文里叫 ChunkLlama2 (Llama2 加 DCA). 它还被套在两个已经做过长上下文训练的模型上: Together-32k (PI 训练) 得到 ChunkTogether, CodeLlama (NTK) 得到 ChunkCodeLlama. 套到已训练模型上时只改块大小, 例如两者都用 24K 的块.

**语言建模.** PG19 验证集困惑度, 不训练 (Table 1, Table 2 节选):

| 模型 | 4K | 16K | 32K | 64K | 128K | 192K |
|---|---:|---:|---:|---:|---:|---:|
| Llama2 7B | 7.87 | > 100 | > 100 | > 100 | > 100 | > 100 |
| ChunkLlama2 7B | 7.87 | 7.64 | 7.89 | 15.87 | 96.21 | > 100 |
| ChunkLlama2 70B | 5.24 | 5.21 | 5.30 | 5.59 | 6.12 | 7.05 |
| ChunkLlama3 70B (8K 预训练) | 5.36 | 5.14 | 5.14 | 5.21 | 5.32 | 5.45 |
| Together 7B (PI, 32K 训练) | 8.21 | 7.76 | 7.64 | > 100 | > 100 | > 100 |
| ChunkTogether 7B | 8.21 | | 7.64 | 7.59 | 7.67 | 7.83 |

7B 能到 32K, 困惑度只比 4K 高 0.02; 到 64K 开始明显上升, 128K 就失效了. 70B 到 128K 困惑度只比 4K 高 0.88, 到 192K 高 1.81, 超过了论文标红用的「比 4K 高 1.0」阈值. 规模越大的模型越能承受远块位置信息的抹平. 已经训到 32K 的 Together 加 DCA 后撑到 192K, 说明 DCA 可以叠在 PI 或 NTK 上, 两者不冲突. Table 1 里训练过的 LongLoRA-32k 7B 在 65536 上困惑度 91.79, 超出训练长度后同样失效.

**少样本长文档问答** (Table 3, 输入截断到 16K, 四项平均): ChunkLlama2 70B 不训练得到 37.8; Llama2 70B 原始模型 29.5; 训练 1000 步, 支持 32K 的 LongLoRA 70B 37.2; 用 400B token, 100,000 步训练的 Llama2 Long 70B 40.7. DCA 在 70B 上比原模型平均高 8 分以上.

**零样本** (Table 4, L-Eval 四个闭卷任务, 输入 3K 到 27K): ChunkLlama2-Chat 70B 平均 63.20, GPT-3.5-16k-0613 是 67.03, 比值约 94%, 这是摘要里「94% of gpt-3.5-16k」的出处.

**消融** (Figure 4, 8K 到 32K): 只用块内注意力, 困惑度很低但检索不到其它块里的 passkey; 加上远块注意力, 12K 的 passkey 检索变好, 但相邻 token 的位置错乱让困惑度明显上升; 三段都用, 困惑度和检索都好. 这组消融是式 (6) 存在的直接理由.

**Passkey** (附录 A.1): Llama2 13B 加 DCA 在 18K 以内各个深度都是 100% 检索. 失败模式有一个规律: PI 的失败和 passkey 所在深度无关; NTK 在开头附近好, 放在中段时降到 40% 到 80%; DCA 随长度增加, 最先出错的位置是文档开头. 开头的 token 位于最远的块, 正是式 (5) 抹掉距离信息最多的地方.

**后续采用.** DCA 后来进了 Qwen 的长上下文方案. [Qwen2 技术报告](https://arxiv.org/abs/2407.10671) 写明在推理时把 YaRN 和 DCA 一起用, 让 32K 训练的模型处理到约 128K token. [Qwen2.5-1M 报告](https://arxiv.org/abs/2501.15383) 同样用 DCA 重映射相对位置, 把 256K 训练的模型推到 1M, 并配合 MInference 一类的稀疏注意力降低 prefill 成本. 这两处用法和论文一致: DCA 只负责位置外推, 计算量另由别的方法处理.

### 2.8 边界

**不省计算, 不省 KV.** 式 (8) 说明 DCA 仍是全注意力. 高并发加超长输入下 KV cache 照样放不下, 需要另配 KV 压缩或驱逐.

**远块之间没有距离.** 这是 DCA 不训练能工作的前提, 也是它的上限. 需要比较两个远处事件先后的任务, 模型只能依赖内容, 不能依赖位置.

**小模型在 $16c$ 附近失效.** 7B 在 64K (预训练长度 16 倍) 困惑度已到 15.87. 70B 在 32 倍 (128K) 时增幅仍在 1 以内, 但这是实验观察, 不是由式 (7) 推出的保证.

**块大小需要和 $c$ 配套.** $s$ 太接近 $c$ 时 $w=c-s$ 很小, 相邻块的局部窗口变窄; $s$ 太小时块数增多, 越来越多的 key 进入远块. 论文统一用 $3c/4$, 没有给块大小扫描.

**只适用于 RoPE 这类只看位置差的编码.** DCA 依赖「内积只依赖 $P_{\mathbf{q}}[i]-P_{\mathbf{k}}[j]$」, 绝对位置编码或 ALiBi 需要另行设计.

## 3. S²-Attn 及两种分块的对比

### 3.1 LoRA 单独不够

LongLoRA 先做了一个对照 (Table 2, Llama2 7B, 目标长度 32768, RedPajama 训练, PG19 验证): 全参微调困惑度 8.08; 标准 LoRA (只训注意力的四个投影) rank 8 是 11.44, rank 增加到 256 反而是 11.98. 把归一化层设为可训得到 10.49, 把 embedding 设为可训得到 8.29, 两者都训得到 8.12, 接近全参微调. 这两部分参数在 Llama2 7B 里很少: embedding 不到 2%, 归一化层不超过 0.004%. 论文把「LoRA + 可训 embedding 和归一化」称为 LoRA+.

LoRA+ 解决了质量, 没有解决算力. 算力问题由 S²-Attn 处理.

### 3.2 分组注意力缺跨组信息

最直接的省算力办法是分组: 长度 $n$ 切成 $n/G$ 组, 每组 $G$ 个 token 独立做因果注意力. 单组 $O(G^2)$, 总计 $O(nG)$, 和全注意力 $O(n^2)$ 相比比例是 $G/n$. 论文默认 $G=n/4$ (8192 长度用 2048 的组), 注意力计算量是原来的 $1/4$.

LongLoRA Table 1 用全参微调, PI 位置编码, PG19 验证集比较了三种训练注意力 (测试都用目标长度):

| 训练注意力 | 8192 | 16384 | 32768 |
|---|---:|---:|---:|
| 全注意力 | 8.02 | 8.05 | 8.04 |
| 分组 (不移位) | 8.29 | 8.83 | 9.47 |
| S²-Attn (分组 + 半数头移位) | 8.04 | 8.03 | 8.08 |

只分组时困惑度随长度增长而上升, 原因是组和组之间没有信息交换, 模型在训练里学不到跨越 $G$ 的依赖.

### 3.3 移位半组

S²-Attn 把注意力头分成两半. 前一半头按原样分组 (论文称 pattern 1); 后一半头先把 token 沿序列维平移 $G/2$, 再分组 (pattern 2). 以 $n=8192$, $G=2048$ 为例:

- pattern 1 的第一组是第 1 到第 2048 个 token.
- pattern 2 的分组边界平移 1024, 第一组是第 1025 到第 3072 个 token; 最前 1024 个和最后 1024 个 token 被平移到同一组.

pattern 2 的每组横跨 pattern 1 的两组, 所以第 1024 个 token 和第 1025 个 token 虽然在 pattern 1 里分属两组, 在 pattern 2 里同组. 一层之内信息只能跨一个组边界, 层数叠加之后可以传得更远. 两种 pattern 每组都是 $G$ 个 token, 移位不增加计算量.

论文 Algorithm 1 给出两行实现. 记 qkv 的形状为 $(B, N, 3, H, D)$, 沿头维切两半, 后一半沿序列维 roll $-G/2$, 再把序列维折进 batch 维:

```text
qkv = cat(qkv.chunk(2, 3)[0], qkv.chunk(2, 3)[1].roll(-G/2, 1)).view(B*N/G, G, 3, H, D)
out = self_attn(qkv)
out = cat(out.chunk(2, 2)[0], out.chunk(2, 2)[1].roll(G/2, 1))
```

折进 batch 维之后, 每组就是一条长度 $G$ 的独立序列, 可以直接调 FlashAttention-2. 第三行把后一半头的输出 roll 回原位置.

**移位造成的越界.** pattern 2 把序列末尾 1024 个 token 移到开头, 和最前 1024 个 token 同组. 因果掩码按组内顺序施加, 于是最前面的 token 会看到最后面的 token, 这是信息泄漏. 论文附录 B.3 的 Table 8 比较了三个变体 (8192 长度, PG19): 原方案 8.04; 改移位方向 8.04; 把移过来的 token 单独成组 8.03; 交换移位 token 和开头 token 8.05; 全注意力 8.02. 差异在 0.01 量级. 论文的解释是越界的 token 原本相距很远, 而且这种注意力只在微调时使用, 推理时用标准因果掩码.

### 3.4 为什么训练稀疏, 推理可以稠密

S²-Attn 训出的模型推理时用标准全注意力. 这依赖一个前提: 训练用的稀疏图和预训练时的全注意力足够接近, 模型权重适应了长度和位置分布, 而没有过拟合到某一种稀疏图. 论文 Table 6 用 Llama2 7B, LoRA+, 32768 长度, 在同等算力下比较了几种训练注意力, 每种分别用训练时的稀疏图和全注意力测试:

| 训练注意力 | 稀疏图测试 | 全注意力测试 |
|---|---:|---:|
| S²-Attn, 跨头混合 (默认) | 8.64 | 8.12 |
| S²-Attn, 跨层交替移位 | 8.63 | 9.70 |
| 只用 pattern 1 | 9.17 | 8.39 |
| 只用 pattern 2 | 9.64 | 9.81 |
| Dilated, 跨头 | 8.75 | 11.78 |
| Block sparse, 跨头 | 11.49 | 8.30 |
| Stride sparse, 跨头 | 32.81 | 24.03 |

默认方案在全注意力下最好, 而且全注意力测试比稀疏图测试还好 (8.12 比 8.64). 跨层交替移位用稀疏图测试与默认方案相当, 换成全注意力却变差到 9.70; dilated attention 也是同样的情况. 这两组说明, 一个注意力图训练时表现好, 不代表推理时能换成全注意力; 在同一层的不同头上混合两种 pattern, 让每层都覆盖一个组内的全连接和跨组边, 是能切回全注意力的关键. stride sparse 在两种测试下都差, 论文认为这类为从头训练设计的图和全注意力差距太大, 不适合微调已有模型.

### 3.5 组大小与训练步数

**组大小** (附录 Table 7, Llama2 7B, PG19):

| 目标长度 | 全注意力 | $n/2$ | $n/4$ | $n/6$ | $n/8$ |
|---|---:|---:|---:|---:|---:|
| 8192 | 8.02 | 8.04 | 8.04 | 8.10 | 8.16 |
| 16384 | 7.82 | 7.84 | 7.86 | 7.94 | 7.98 |

$n/2$ 和 $n/4$ 与全注意力差距很小, 小于 $n/4$ 开始变差. 论文默认 $n/4$, 这也决定了 S²-Attn 的注意力算力节省上限大约是 4 倍.

**训练步数** (Figure 5, 8192 长度): 不训练时 (第 0 步) 困惑度 15.82, 随后快速下降. 全参微调起初收敛更快, 200 步后 LoRA+ 追上, 最终差距很小. 论文所有实验训练 1000 步, 全局 batch 64, 7B/13B 学习率 $2\times10^{-5}$, 70B 为 $10^{-5}$, 位置编码统一用 PI.

### 3.6 实际省了多少

Table 11 的 S²-Attn 行给出注意力 FLOPs 精确变成 $1/4$: 8192 长度 35.2T 到 8.8T, 65536 长度 2251.8T 到 562.9T. 投影, FFN 不变, 所以整体 FLOPs 的节省随长度增大: 8192 是 143.5T 到 117.1T (约 18%), 65536 是 3118.0T 到 1429.1T (约 54%).

训练时长和显存 (Table 12, Llama2 7B, 1000 步, 8 张 A100, FlashAttention-2, DeepSpeed stage 2):

| 长度 | 全参微调 时长/显存 | LoRA 时长/显存 | LongLoRA 时长/显存 |
|---|---|---|---|
| 8192 | 7.4 h / 46.3 GB | 6.0 h / 25.7 GB | 5.2 h / 25.6 GB |
| 16384 | 16.3 h / 57.4 GB | 14.0 h / 34.7 GB | 11.3 h / 34.6 GB |
| 32768 | 39.8 h / 68.8 GB | 36.5 h / 46.5 GB | 24.6 h / 46.4 GB |
| 65536 | OOM | 92.5 h / 71.1 GB | 52.4 h / 69.8 GB |

LongLoRA 和 LoRA 的唯一差别是 S²-Attn. 显存几乎不变, 因为 FlashAttention-2 已经不物化注意力矩阵, 注意力的显存和长度成线性关系, 分组不改变这一点. 节省体现在时长上, 65536 长度是 LoRA 的 56.6%. 不用 FlashAttention-2 时 (Table 13, 8192 长度), S²-Attn 把训练时长从 17.5 h 降到 8.2 h (2.1 倍), 显存从 55.5 GB 降到 30.3 GB (1.8 倍); 16384 长度不用 S²-Attn 直接 OOM.

### 3.7 能扩到多长

单台 8×A100 上, LongLoRA 把 Llama2 7B 扩到 100K, 13B 扩到 65536, 70B 扩到 32768 (Table 4, FlashAttention-2 加 DeepSpeed stage 3). 在 proof-pile 测试集上, 7B 训练长度从 8192 增加到 32768, 32768 长度评测的困惑度从 2.72 降到 2.50 (§4.2).

Passkey (Figure 4): 训到 32768 的 7B 在 33K 到 34K 以内保持正确检索. 不再训练, 只把 PI 的最大位置改到 48K, 在 33K 到 45K 得到 60% 到 90% 的准确率; 原始 Llama2 7B 即使扩展 PI, 4K 之后也急剧下降. 话题检索 (Table 5, LongChat 任务, 13B 训到 18K): 16K 长度准确率 0.94, LongChat-13B 是 0.9.

论文还用自建的长指令数据 LongAlpaca 做了有监督微调 (附录 B.4, B.6). 7B 扩到 16384 后在 LongBench 上平均 36.8, 同为 Llama2 7B 底座的 LongChat-v1.5-7B 是 34.3, Vicuna-v1.5-7B 是 31.9, GPT-3.5-Turbo 是 44.0 (Table 9). 这次微调在单台 8×A100 上约 4 小时, 用了约 0.3B token. 和 GPT-3.5 的差距集中在单文档问答 (28.7 对 39.8), 多文档问答 (28.1 对 38.7) 和合成任务 (16.7 对 37.8) 三列; 摘要和代码两列 LongLoRA 7B 略高.

### 3.8 边界

**只省训练.** 推理时是标准全注意力, decode 读全部 KV, prefill 仍是 $O(n^2)$. 想降低推理成本需要别的方法.

**位置外推仍靠 PI.** S²-Attn 不处理位置问题, LongLoRA 所有实验都用 PI 缩放位置. PI 的已知副作用在 Table 4 里能看到: 扩展后的模型在短长度上困惑度比原模型高.

**节省有上限.** 组大小低于 $n/4$ 质量开始下降, 所以注意力 FLOPs 最多省到 $1/4$ 附近. 显存在有 FlashAttention-2 时几乎不变.

**只在同层跨头混合时有效.** Table 6 里换成跨层交替, 或全部头用同一种 pattern, 全注意力测试都会变差.

### 3.9 两种分块放在一起比

两种方法都把序列切块, 但块在其中的作用完全不同.

| | DCA | S²-Attn |
|---|---|---|
| 切块的目的 | 让相对位置不超过 $c-1$ | 让注意力 FLOPs 降到约 $1/4$ |
| 是否训练 | 否 | 是, 和 LoRA+ 一起微调约 1000 步 |
| 每个 query 看到的 key | 全部历史, 分三段用不同位置号 | 训练时只看组内 $G$ 个; 推理时全部历史 |
| 位置编码 | 原 RoPE, 位置号重映射 | PI 缩放 |
| 推理计算量与 KV | 与全注意力相同 | 与全注意力相同 |
| 丢了什么 | 远块之间的距离信息 | 训练时的跨组依赖 (由半数头移位部分补回) |

两条路线的差别可以收到一个问题上: 模型扩到长上下文之后, 不在预训练分布里的到底是什么. DCA 认为是位置差, 于是把位置差全部压回预训练范围, 换来的代价是远处位置分辨率归零; LongLoRA 认为位置可以由 PI 加微调解决, 难点在微调本身的算力, 于是只在训练图上做近似, 推理时不留任何痕迹. 两者可以叠加: DCA 论文 Table 2 里 ChunkTogether 就是把 DCA 套在 PI 训练过的模型上, 32K 训练加 DCA 到 192K 困惑度 7.83.
