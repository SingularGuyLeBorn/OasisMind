# 2.7 · 长上下文与外推技术

预训练的大部分算力花在短序列上, 因为注意力的计算量随长度平方增长. 推理时用户却会放进整本书, 整个代码仓库或者很长的对话历史. 这一节处理这个落差带来的两类问题. 第一类是模型本身: 位置编码在训练长度之外是否失效, 不失效时模型是否真的用上了远处的内容. 第二类是推理开销: 128k 上下文的 Llama 3 8B, KV Cache 已经和 bf16 权重一样大; 1M token 的 prefill 在单张 A100 上要 30 分钟.

RoPE 的推导和 PI, NTK-aware, YaRN 等频率缩放方法在 [2.1.4 位置编码](../2.1-深度学习基础组件/2.1.4-位置编码/2.1.4-位置编码.md), 下文默认读者已经读过. 长上下文继续训练的数据量, 长短配比和 SFT 配方属于训练问题, 在 [3.5.2 长上下文训练与数据](../../3-预训练/3.5-继续预训练与长上下文训练/3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md). 下文记训练长度为 $L$, 推理长度为 $n$, 每个 token 的 KV 字节数为 $M_{\text{token}}$.

## 1. 超过训练长度时坏的是什么

### 1.1 位置越界

模型在长度 $L$ 内训练, 推理时序列变长, 有两类东西落在训练分布之外. 一类是位置表示: 绝对位置编码在 $L$ 之后没有训练过的向量; RoPE 的低频平面在 $L$ 内连一圈都没转满, 超过 $L$ 后出现新的角度, LLaMA 7B 窗口拉到 4096, 困惑度超过 $10^3$. 另一类是注意力的分布: 即使每个位置都合法, softmax 分母里的项数变多, 注意力熵随之变大, YaRN 的温度因子针对的就是这一点.

[2.7.1 长度外推](./2.7.1-长度外推/2.7.1-长度外推.md) 按处理方式把路线分成三组. ALiBi 和 xPos 在 logits 或旋转上加随距离的衰减, 远处的 key 被压低, 新出现的长距离不会扰乱分数; NoPE 和 FIRE 让因果掩码或学到的归一化偏置承担位置信息; LongRoPE 逐维搜索 RoPE 的插值倍数, 并让开头的 token 不插值. 还有一组完全不训练, 只改每对 token 被赋予的相对位置: Self-Extend 把远处位置整除一个组大小, DCA 把序列切块, 块内, 块间, 相邻块分别给位置号.

### 1.2 不崩不等于会用

外推研究长期以困惑度为主要指标, 问题在于困惑度主要由局部上下文决定. ALiBi 在 $L$ 之后困惑度继续下降, 原文附录 B 用步长为 1 的滑动窗口重测, 下降几乎消失: 收益来自长窗口让更多 token 拿到了 $L$ 以内的完整上下文, 不是用上了 $L$ 之外的内容. Mistral 开滑动窗口时 16k 困惑度 9.29, 窗口外的 passkey 却一个都取不回. RoPE base 设成 500 后 128k 困惑度很低, 1k 以内的信息都检索不到.

base 的例子给出了第二层问题的一个下界. Men 等人把「距离 $m$ 处给相似 token 的分数比给随机 token 高多少」写成 $B_m=\sum_i\cos(m\theta_i)$, 要求它在 $m\le L$ 内不为负, 得到 base 的数值下界: 头维 128 时 32k 约 $6.4\times10^5$, 128k 约 $7.8\times10^6$, 1M 约 $5.1\times10^8$. PI 和 NTK 关心角度是否越界, base 下界关心角度都在范围内时远处的相似 token 是否还分得出来. 判断一个外推方法, 要分别看它解决的是哪一层.

## 2. 训练和不训练的扩展

### 2.1 搜索插值倍数, 再微调

LongRoPE 不微调时在 LLaMA2-7B 的 PG19 16k 上困惑度 11.34, PI 是 20.49, YaRN 是 87.89. 扩到 2048k 走了三步: 先在 128k 和 256k 上各微调几百步, 再在 256k 模型上搜一次倍数不再微调, 最后为 4k 和 8k 另搜一组倍数恢复短上下文. 256k 微调的 LLaMA2 在 4k 到 2048k 的 passkey 上准确率都在 90% 以上. 代价是短任务回退, MMLU 从 46.6 降到 39.6, 而且推理时按长度切换两套位置参数会让已算好的 KV Cache 作废, 因为 Key 存的是旋转后的值.

搜索的目标函数是困惑度, 原文只用 passkey 补了一部分验证, 没有报告 RULER 一类多任务基准. 2048k 的结果依赖前面两段长序列微调, 不是一次搜索得到的. 继续训练的另一面是数据: 要多少 token, 长数据从哪来, 长短怎么配, 这些在 3.5.2. ProLong 表 2 里 Llama-3-8B 只改 RoPE base, GSM8K 从 44.7 降到 40.1, 说明短任务回退不只出在 LongRoPE 上.

### 2.2 两种分块

[DCA 与 S²-Attn](./2.7.1-长度外推/01-DCA与S2-Attn-长上下文分块注意力/01-DCA与S2-Attn-长上下文分块注意力.md) 都把序列切块, 但块的作用不同. DCA 不训练, 块内用正常的相对位置, 远块之间所有 query 用同一个大位置号, 相邻块单独处理以恢复局部性, 这样相对位置不超过块长减一. 原文报告 Llama2 70B 不继续训练就能支持超过 100k 的窗口, 在实际长文本任务上达到 gpt-3.5-16k 的 94%. 代价是远块之间的距离信息归零.

S²-Attn 是 LongLoRA 的一部分, 只在微调时把注意力分组, 半数头移位半组以补回跨组信息, 推理时回到全注意力. 它省的是训练算力: 注意力 FLOPs 精确降到 $1/4$, 65536 长度整体 FLOPs 约省 54%, 训练时长是 LoRA 的 56.6%; 单台 8×A100 能把 Llama2 7B 扩到 100K. 两种分块的推理计算量和 KV 都与全注意力相同, 推理开销要靠下一节的方法降. DCA 论文还把 DCA 套在 PI 训练过的模型上, 32K 训练加 DCA 到 192K, 困惑度 7.83.

## 3. 推理的两段开销

### 3.1 prefill 的平方与 decode 的读取

每个 token 的 KV 是 $M_{\text{token}}=2\,n_{\text{layer}}\,n_{kv}\,d_h\,p$. Llama 3 8B ($n_{\text{layer}}=32$, $n_{kv}=8$, $d_h=128$, bf16) 每 token 128 KB, 128k 上下文 16 GB, 1M 上下文 128 GB, 单张 80 GB 显卡放不下. decode 每步要把权重和全部 KV 读一遍; batch 增大时权重读取被分摊, KV 读取不分摊, batch 8, 128k 时每步读 16 GB 权重加 128 GB KV, KV 占九成.

prefill 的注意力 FLOPs 约 $n_{\text{layer}}\cdot2d\cdot n^2$, 线性层约 $2N\cdot n$, 两者在 $n^\ast=N/(n_{\text{layer}}d)$ 处相等, Llama 3 8B 约 60k. 1M token 时注意力占约 94%. FlashAttention 不改变这个 FLOPs 量, 它解决的是显存读写. 所以长上下文推理有两个独立的瓶颈: prefill 要少算, decode 要少读. [2.7.3 长上下文推理优化](./2.7.3-长上下文推理优化/2.7.3-长上下文推理优化.md) 按这两段组织, prefill 一侧的代表是 MInference, 用三种动态稀疏模式把 LLaMA-3-8B 的 1M prefill 从 30 分钟降到 3 分钟.

### 3.2 少读 KV 的三种办法

第一种是让每条 KV 变小. GQA, MQA, MLA 在结构上减少 KV 头或做低秩压缩, 要在预训练时定下来; KIVI 不改结构, 把 Key 按通道, Value 按 token 量化到 2 bit, 最近 128 个 token 保持全精度. 第二种是让条数变少, 也就是驱逐: [2.7.2 KV 缓存压缩与淘汰](./2.7.2-KV缓存压缩与淘汰/2.7.2-KV缓存压缩与淘汰.md) 的八篇按位置, 按历史注意力, 按 prompt 末尾一次性挑选, 或按层按头分配预算来决定删哪些. 第三种是检索: InfLLM 和 Quest 不删任何 KV, 每步按当前 query 选一部分读.

驱逐和检索的分界在被挑剩的 KV 去了哪里. 驱逐把它们删掉, 显存随之封顶; 检索把它们留着, 显存不减. ∞-Bench 的键值检索上, StreamingLLM 和 H2O 只有 0.2 和 2.6, InfLLM 在 Mistral 上是 96.8, 在 Llama-3 上却只有 5.0. 单卡放不下时, Ring Attention 把 query 和 KV 切到多张卡上, 各卡沿环传 KV 块并在线合并 softmax, 是这些手段里唯一不做近似的, 只改变计算放在哪里. KV 在显存里怎么放, 由 [PagedAttention](./2.7.3-长上下文推理优化/01-PagedAttention/01-PagedAttention.md) 的块表管理, 它不改注意力数值, 和上面各种方法可以叠加.

## 4. 方法对照与评测

### 4.1 各方法解决哪一段

| 方法 | 位置越界 | 远处信息可用 | 是否训练 | 推理开销 |
|---|---|---|---|---|
| ALiBi, xPos | 解决 | 远处被衰减压低 | 预训练时定 | 不变 |
| LongRoPE | 解决 | 靠长序列微调 | 搜索加少量微调 | 不变 |
| Self-Extend, DCA | 解决 | 远处位置被合并 | 否 | 不变 |
| S²-Attn (LongLoRA) | 不处理, 靠 PI | 靠微调 | 是 | 不变 |
| KIVI, GQA, MLA | 不处理 | 不变 | KIVI 否, 其余是 | KV 变小 |
| 驱逐 (2.7.2) | StreamingLLM 重新编号 | 被删的找不回 | 否 | KV 条数封顶 |
| 检索 (InfLLM, Quest) | InfLLM 远处共用位置 | 取决于召回 | 否 | 读取量封顶, 显存不减 |

表的前四行改模型能读多长, 后三行改读一次的代价, 两组互不替代. 用 DCA 把窗口扩到 100k 之后, prefill 和 KV 仍按全长度算; 用驱逐把 KV 压到几千条, 也不会让模型认识训练长度之外的位置. StreamingLLM 能处理 400 万 token 的流, 是因为它在缓存内重新编号, 让相对距离始终不超过缓存大小, 它并不扩展模型能用的上下文.

第三列在两组里都是关键. 前四行里, 只保证不越界的方法 (滑动窗口, ALiBi 的陡斜率头, Self-Extend 分组后同组内的先后顺序) 都会丢掉一部分远处信息; 后三行里, 驱逐类方法默认过去重要的 token 以后也重要, 答案在前, 问题在后的检索任务上会失败. InfLLM 论文的对比说明, 位置外推类方法 (NTK, Self-Extend) 把窗口拉到 128k 后 passkey 能取回, 键值检索和问答却没有明显改善.

### 4.2 评测要看什么

困惑度只能排除位置越界导致的整体崩溃. passkey 和大海捞针更直接地测能否从远处取回信息, 但太简单: Xiong 等人的消融里除了原始 RoPE, 所有位置编码变体的 passkey 都是满分. RULER 把任务扩到 13 个, 分检索, 多跳追踪, 聚合, 问答四类, 以 Llama2-7B 在 4k 上的平均分 85.6 为及格线定义有效长度. 声称 128k 的 GPT-4 和 Llama3.1-70B 有效长度都是 64k, Mistral-v0.2 声称 32k, 有效长度 16k.

长度之外还要扫深度和回头测短任务. 相关文档放在输入中间时, GPT-3.5-Turbo 的多文档问答准确率低于闭卷设置的 56.1%. 外推方法改了位置编码或权重, 原窗口内的能力可能下降, LongRoPE 和 ProLong 都有这样的数字. 对推理期压缩, 2.7.2 和 2.7.3 的经验是看任务类型: 语言建模和摘要用很小的缓存就能接近完整模型, 检索类任务要一半以上, 或者干脆不删 KV.

## 5. 读的顺序

### 5.1 先读外推, 再读推理

第一次读这一节, 按 2.7.1, 2.7.2, 2.7.3 的顺序. [2.7.1](./2.7.1-长度外推/2.7.1-长度外推.md) 第 1 节先讲清两层问题, 后面每种方法都按这两层来评; 第 5 节的失效模式表把困惑度爆掉, 困惑度平稳但检索失败, base 过小几种症状对到原因. 它的 [01 篇](./2.7.1-长度外推/01-DCA与S2-Attn-长上下文分块注意力/01-DCA与S2-Attn-长上下文分块注意力.md) 把 DCA 和 S²-Attn 放在一张表里比较.

然后读 [2.7.2](./2.7.2-KV缓存压缩与淘汰/2.7.2-KV缓存压缩与淘汰.md), 其中 StreamingLLM 的 attention sink 是后面驱逐方法和 2.7.3 的位置编号都要用到的现象. 最后读 [2.7.3](./2.7.3-长上下文推理优化/2.7.3-长上下文推理优化.md), 它的第 1 节手算了 Llama 3 各规模的 KV 大小和 prefill FLOPs, 第 1.4 节的方法地图把量化, 稀疏 prefill, 驱逐, 检索和多卡切分对到三个瓶颈上.

### 5.2 只关心部署

只关心部署的读者可以从 2.7.3 开始, 它对 2.7.1 的依赖只有 StreamingLLM 和 InfLLM 的位置编号一处. 显存不够时读 2.7.2 和 [PagedAttention](./2.7.3-长上下文推理优化/01-PagedAttention/01-PagedAttention.md); 首 token 延迟太长时读 2.7.3 第 2 节的 MInference. 推理期的方法都不改模型, 如果可以重新训练, 另外两条路是训练期就稀疏的注意力和固定状态的线性层.

训练期稀疏 (MoBA, NSA, DeepSeek 的 CSA) 见 [2.4 稀疏注意力](../2.4-稀疏注意力/2.4-稀疏注意力.md), 它们让 prefill 和 decode 两段都少算; 线性注意力, 状态空间模型和混合架构见 [2.5 线性注意力与状态空间模型](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md), 每层只留固定大小的状态, 代价是逐字检索能力要靠少量全注意力层补. 不改公式只改执行方式的 FlashAttention 系列在 [2.3 注意力的高效实现](../2.3-注意力的高效实现/2.3-注意力的高效实现.md).
