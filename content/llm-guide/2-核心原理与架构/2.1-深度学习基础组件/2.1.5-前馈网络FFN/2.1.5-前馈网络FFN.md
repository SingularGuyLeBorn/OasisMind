# 2.1.5 前馈网络 FFN

在很多入门材料里, Transformer 的前馈网络 (Feed-Forward Network, FFN) 被介绍成「注意力后面跟着的两层 MLP」. 这种描述本身没有错误, 但不足以说明 FFN 在现代大语言模型中的实际作用. 对当前的大语言模型而言, FFN 是影响模型容量, 知识内化, 训练稳定性, 推理成本和压缩路线选择的核心模块之一. 注意力机制决定当前 token 从哪些位置获取信息, FFN 则决定获取后的信息在当前表示中如何被加工, 放大和筛选.

工程上, FFN 的宽度设计, 激活函数形态, 门控结构, 量化策略和稀疏化方案都会直接影响模型表现和成本. BERT, GPT-2 采用基于 GELU 的标准 FFN; PaLM, Llama, Qwen, Mistral, DeepSeek 等后续模型广泛采用 SwiGLU 一类的门控 FFN. 许多 MoE 架构也将专家化集中在 FFN 子层, 因为这里通常占据单层参数与逐 token 变换容量的主要部分.

本文从数学公式, 几何直觉, 工程成本, 训练诊断, 量化与 MoE 路线等角度展开讨论, 围绕以下五个核心问题组织:

1. FFN 在 Transformer 里究竟承担什么职责.
2. 为什么 FFN 的宽度设计是容量与成本的 trade-off.
3. 为什么现代模型从标准 FFN 走向 SwiGLU 门控 FFN.
4. 为什么 FFN 经常成为训练, 推理, 量化与稀疏化的重点领域.
5. 工程上诊断 FFN 时该看哪些指标.

## 1. FFN 在 Transformer 中到底是什么

Transformer 的一个标准块通常由两部分组成: 注意力子层和 FFN 子层. 注意力子层负责跨 token 交互; FFN 子层则对每个 token 的隐藏状态独立做高容量非线性变换. 这里的「独立」容易被误解: 它指的是 FFN 不直接比较不同 token, 并不意味着 FFN 与上下文无关; 它处理的输入已经是「吸收过上下文的 token 表示」. 因此, 注意力负责聚合来自其他位置的信息, FFN 决定这些信息在当前 token 的表示中最终如何转换.

若某个 token 原本只是一个粗糙表示, 经过注意力聚合后, 它可能同时携带事实知识, 语法约束, 任务指令, 风格提示, 长程依赖和局部模式. FFN 将这些混合信息投影到更大的特征空间, 通过非线性激活进行筛选和重组, 再压缩回模型维度. 这一过程可分解为特征投影, 非线性筛选与重组, 以及向模型维度的回投影. 因此, FFN 不是纯粹的后处理层, 它往往决定模型能否将注意力带来的上下文转化为可用的表示.

从参数规模上看, FFN 的重要性也超过直觉判断. 标准 Transformer 中, 注意力部分包含 $Q, K, V, O$ 四个投影矩阵, 共约 $4d^2$ 个参数; 标准 FFN 包含两个大矩阵 $W_1, W_2$. 当隐藏维度扩展到 $d_{ff}=4d$ 时, FFN 参数量约 $8d^2$, 占单层的三分之二. 若使用 SwiGLU 这类门控 FFN, 虽然宽度会做参数守恒调整, FFN 仍然是单层参数的主体. 也正因此, 模型压缩, 量化, 蒸馏, 专家化工作大多落在 FFN 上.

## 2. 数学形式: 标准 FFN 与门控 FFN

标准 FFN 与门控 FFN 共享相同的高层结构: 先将输入投影到高于模型维度的中间空间, 应用非线性激活或门控, 再将结果投影回模型维度. 两者的差异在于中间非线性是逐元素激活还是乘性门控, 以及是否引入第三条投影矩阵.

下面按标准 FFN, ReLU 与 GELU 实例, 以及 SwiGLU 门控结构逐步展开, 并说明升维-降维几何, 参数预算与实现复杂度之间的关系.

### 2.1 标准 FFN

最标准的 FFN 形式是:

$$
\text{FFN}_{std}(x)=\phi(xW_1+b_1)W_2+b_2
\tag{1}
$$

其中 $x\in\mathbb{R}^{1\times d}$ 是单个 token 的隐藏状态, $W_1\in\mathbb{R}^{d\times d_{ff}}$ 把输入投影到更高维度, $W_2\in\mathbb{R}^{d_{ff}\times d}$ 再把结果压缩回模型维度. $\phi$ 是激活函数, 常见取 ReLU 或 GELU. 现代大模型里偏置项常被省略, 因此也常见:

$$
\text{FFN}_{std}(x)=\phi(xW_1)W_2
\tag{2}
$$

若没有中间非线性 $\phi$, 两个矩阵乘法可合并为一个大矩阵, 整个网络退化成线性变换. 因此 FFN 的关键不在「有两个矩阵」, 而在「两个矩阵中间必须有非线性」. 有了非线性, 单隐层网络在隐藏单元足够多时可以任意逼近紧集上的连续函数 ([Cybenko, 1989](https://link.springer.com/article/10.1007/BF02551274); [Hornik, 1991](https://www.sciencedirect.com/science/article/pii/089360809190009T)).

### 2.2 为什么先升维再降维: 不是为了增加参数

结论先行: 升维是为了增加可供非线性选择和组合的中间特征数; 降维是为了把这些中间特征汇总成一个 $d$ 维更新, 写回固定宽度的残差流. 中间宽度比模型维度大是常用且有效的工程设计, 但不是数学上的硬性要求.

从 [Geva et al. (2021)](https://aclanthology.org/2021.emnlp-main.446/) 提出的键值记忆视角看, 式 (2) 可以按中间单元展开:

$$
\text{FFN}(x)=\sum_{i=1}^{d_{ff}}\phi(x\cdot k_i)\,v_i
\tag{3}
$$

其中 $k_i$ 是 $W_1$ 的第 $i$ 列, $v_i$ 是 $W_2$ 的第 $i$ 行. $k_i$ 可看成第 $i$ 个模式探测器: 它判断输入 $x$ 对某种特征的响应有多强; 激活函数 $\phi$ 决定这个响应如何通过; $v_i$ 则规定该特征命中后, 应沿哪个方向修改输出. 因此, $d_{ff}$ 不只是「向量变长了」, 它还决定这一层同时拥有多少组可学习的中间特征. 从 $d$ 扩到 $4d$, 相当于把这类探测器和对应的写回方向增加到原来的 4 倍, 再由 $W_2$ 将所有响应加权汇总.

这里真正起作用的是宽度与非线性的组合. 如果去掉中间激活函数, 两个矩阵可以合并为 $W_1W_2$, 无论中间升到多高都仍只是一次线性变换. 加入非线性后, 不同中间单元可以随输入选择性激活, FFN 才能实现输入相关的特征组合. 但这不意味着 $d\to d\to d$ 的同宽 FFN 只能做简单的线性变换或维度裁剪; 它同样具有非线性表达能力. 升维的优势是给同一层分配更多中间单元, 通常能以更多参数和计算换取更大的容量, 而不是保证语义因子一定会被分解到彼此独立的方向.

之所以再降回 $d$, 是因为 Transformer 通常维护一条固定宽度为 $d_{model}$ 的残差流. [Vaswani et al. (2017)](https://arxiv.org/abs/1706.03762) 在原始 Transformer 中明确让所有子层输出保持 $d_{model}$ 维, 以便 FFN 的结果与输入相加:

$$
x+\text{FFN}(x)
\tag{4}
$$

所以在标准结构中, $W_2$ 必须把 $d_{ff}$ 维的中间激活映射回 $d_{model}$. 这一步把许多被激活的中间特征混合成一个 $d$ 维更新; $d_{model}$ 维是层与层之间传递的统一接口. 如果另行改变残差支路的维度或增加投影, 输出并非绝对不能改变维度; 固定回到 $d_{model}$ 是标准 Transformer 的结构约定, 不是所有神经网络的数学定律.

至于为什么经典设置常取 $d_{ff}=4d$, 原因主要是经验折中. [原始 Transformer](https://arxiv.org/abs/1706.03762) 使用 $512\to2048\to512$, 由此形成了常见的 4 倍扩展惯例. 更宽通常意味着更多容量, 同时也会线性增加 FFN 的参数量, 计算量, 激活内存和权重搬运量, 因此不存在对所有模型都最优的固定比例. 现代门控 FFN 还会在相同参数预算下调整宽度; 例如 [Shazeer (2020)](https://arxiv.org/abs/2002.05202) 讨论的 SwiGLU 在对齐标准 $4d$ FFN 的参数与计算预算时, 中间宽度取约 $8d/3$, 以抵消第三个投影矩阵带来的额外开销: 标准 $4d$ FFN 有一条上投影与一条下投影, 参数量约 $8d^2$; SwiGLU 有两条上投影与一条下投影, 中间宽度取 $8d/3$ 时同样约为 $8d^2$. 这是参数量对齐, 实际吞吐还取决于融合内核和硬件. 近期的 Hourglass FFN 工作 ([Liao et al., 2026](https://arxiv.org/abs/2602.06471)) 也说明, narrow-wide-narrow 是有效惯例, 但不是不可替代的唯一结构.

综上, 先升维是用更多中间单元构造和筛选候选特征, 再降维是把候选特征汇总为固定宽度的残差更新. 升得多宽取决于容量收益与参数, 计算, 显存和带宽成本之间的折中.

### 2.3 ReLU 的分段线性形式

若取 $\phi=\text{ReLU}$, 则有:

$$
\text{FFN}_{\text{ReLU}}(x)=\text{ReLU}(xW_1+b_1)W_2+b_2
\tag{5}
$$

其中

$$
\text{ReLU}(x)=
\begin{cases}
x, & x>0 \\
0, & x\le 0
\end{cases}
\tag{6}
$$

ReLU 是典型的硬阈值函数: 负响应直接截断为零, 正响应保持不变. 它计算简单, 正半轴梯度恒为 1, 代价是负区间梯度完全为零.

### 2.4 GELU 的工程近似

[Hendrycks & Gimpel (2016)](https://arxiv.org/abs/1606.08415) 给出的 GELU 精确形式含误差函数, 工程实现常用 tanh 近似:

$$
\text{GELU}(x)\approx 0.5x\left(1+\tanh\left[\sqrt{\frac{2}{\pi}}\left(x+0.044715x^3\right)\right]\right)
\tag{7}
$$

这个近似的目的是在保留平滑门控特性的同时, 降低直接计算误差函数的成本. GELU 按输入大小连续调节保留程度, 而不是「正区间保留, 负区间截断」.

### 2.5 SwiGLU 的三矩阵结构

SwiGLU 不再是单一路径, 而是门, 上, 下三条投影:

$$
g=xW_g,\quad u=xW_u,\quad h=\text{SiLU}(g)\odot u,\quad y=hW_d
\tag{8}
$$

其中 $W_g$ 产生门控支路, $W_u$ 产生候选特征支路, $W_d$ 负责降维回到模型维度. SiLU 即 [Ramachandran et al. (2017)](https://arxiv.org/abs/1710.05941) 通过自动搜索得到的 Swish 在 $\beta=1$ 时的形式. 三矩阵相对两矩阵多一个上投影矩阵, 隐藏维乘 $2/3$ 才能保持参数量; 惯例 $d_{ff}=4d$ 时就是 $8d/3$. 详见 [02 GLU 家族](../2.1.1-激活函数/02-GLU家族-从GLU到SwiGLU/02-GLU家族-从GLU到SwiGLU.md).

若仅考虑大 O 记号, 标准 FFN 主计算量约为两次大矩阵乘法, 复杂度 $O(dd_{ff})$; SwiGLU 是三次投影加一次逐元素乘法, 主复杂度仍由投影矩阵主导. 理论上这是高效密集线性代数问题, 现实里却不总是算力瓶颈, 因为推理阶段尤其是单 token 解码时, 带宽和权重搬运常常更早成为限制. 下一节讲这一点.

## 3. 几何直觉: 升维, 分段, 门控与键值记忆

从几何视角看, $W_1$ 把输入表示投影到更高维空间. 原本在低维模型空间里纠缠的语义模式, 到了 $d_{ff}$ 空间后更有机会在不同方向上被分开, 方便后续非线性做选择和裁剪.

如果没有这个高维空间, 模型只能在原始维度里做有限混合, 很多本应被分离的特征会继续纠缠在一起. FFN 的「宽」本质上是用参数换表达能力: 给模型足够大的中间空间, 让它把不同语义因子, 风格因子和任务因子先分离, 再决定保留什么.

激活函数决定输入空间被怎样切分. ReLU 把每个中间单元的负半轴映射到零, 整个 FFN 因此是分段线性函数, 分段边界由 $x\cdot k_i=0$ 这些超平面决定; GELU 用平滑过渡代替这些硬边界; SwiGLU 则先算门, 再算值, 最后做乘性调制, 让不同方向之间发生条件耦合. 因此从表达能力看, SwiGLU 常被认为比简单逐元素激活更强: 它把「是否保留某个模式」实现为输入条件相关的函数, 而不是固定阈值.

Geva et al. (2021) 的工作就是式 (3) 的解释: $W_1$ 的列向量可视为很多「键」, 负责检测输入是否包含某种模式; $W_2$ 的行向量可视为对应的「值」, 负责把匹配到的模式映射为输出修正. 输入若与某些键高度匹配, 这些键对应的值就会被加权提取出来. 他们在语言模型上观察到, 键对应可被人理解的输入模式, 浅层多为表层模式, 深层更偏语义; 值则对应输出词表上的分布. 按这一解释, 事实, 风格, 局部变换规则有相当一部分以键值方式存储在 FFN 参数里.

## 4. FFN 为什么经常是工程成本中心

在工程层面, FFN 成为优化焦点的一个主要原因是其参数占比较高. 高参数占比直接转化为三类成本: 存储成本, 训练中的梯度与激活成本, 以及推理中的权重搬运成本.

由于这三类成本同时出现, FFN 自然成为模型压缩, 量化, 稀疏化和并行策略的核心落点. 理解这些成本的具体来源, 有助于在设计和部署时做出更合理的工程决策.

推理的解码阶段, FFN 常常受限于显存带宽而不是算力, 原因有三:

1. batch size 很小, 矩阵并不总能把硬件吞吐吃满.
2. FFN 权重很大, 每生成一个 token 都要反复读取.
3. 解码阶段复用度低, 算子调度空间也更窄.

因此常见现象是: GPU 利用率并不高, 但 HBM 带宽接近满载, 单 token 延迟仍然很高. 此时仅关注 FLOPs 做优化常常不够, 应优先处理 FFN 的量化, 分块, 融合和访存模式. 具体瓶颈仍要在目标硬件上测出来.

训练时的问题与推理不同. 推理更关心带宽, 训练还要关心反向传播. FFN 中间激活维度很大, 尤其是标准 $4d$ 或 SwiGLU 高宽度中间态, 会显著增加显存占用. 如果层数很多, 中间态的保存与回传代价并不低. 因此 activation checkpointing, 重计算, 混合精度和张量并行都涉及 FFN.

此外, FFN 的梯度链也更长. 标准 FFN 至少有两次大矩阵投影和一次非线性, SwiGLU 则多一条支路和一次乘法门控. 只要输入分布, 初始化或学习率设置不稳, FFN 层级统计就更容易首先出现异常.

## 5. 训练视角: FFN 怎样影响可训练性

从前向角度看, FFN 首先扩展表示空间, 其次通过激活或门控筛选特征, 最后把被筛选过的模式压缩回模型维度. 这一过程里, 决定效果的是哪些模式在高维空间里被显式分开, 哪些模式被放大, 哪些模式被抑制.

对于代码, 数学, 对话, 多语言, 结构化输出等复杂任务, 一个 token 往往携带多种纠缠语义. FFN 的宽度越充足, 门控越细致, 模型越有机会把这些模式分离并做差异化处理.

反向传播时, 激活函数的导数决定每个中间单元能回传多少梯度. ReLU 在负区间导数为零, 一个单元若对所有输入都落在负区间就不再更新; GELU 和 SiLU 在负区间保留细小但连续的梯度, 使模型更容易从不良状态中恢复. 门控结构还会让梯度同时依赖「内容支路」和「门控支路」的数值状态, 这使 SwiGLU 既更强也更复杂. 一个理论上更强的门控 FFN, 如果数值范围控制不好, 也可能成为训练不稳定的源头.

若你在训练一个大模型, FFN 相关指标很值得单独监控:

1. 激活稀疏率: 判断通道是否大面积沉默.
2. 中间态最大值与分位数: 快速定位异常尖峰层.
3. gate 输出均值和方差: 检查门控是否长期塌缩或饱和.
4. 每层 FFN 梯度范数: 识别哪些层学不动, 哪些层在振荡.
5. 权重范数漂移: 检查是否出现异常扩张或塌缩.
6. 量化前后输出余弦相似度: 评估部署阶段量化可承受度.

很多问题在全局 loss 上并不明显, 但在 FFN 层级统计上会很明显.

## 6. 失效模式: FFN 会在哪些地方出问题

若 $d_{ff}$ 太小, 模型在中间空间里可分离的模式不够, 表达能力下降; 若太大, 虽然表示能力上升, 但参数, 带宽, 显存和训练不稳定风险都增加, 而且边际收益递减. 因此 $4d, 8d/3$ 这些配置是大量工程折中后留下的经验配置, 可以按预算调整.

ReLU 的风险是死神经元, SwiGLU 的风险则更常表现为门控塌缩. 若某些 gate 长期接近零, 对应通道虽然参数存在, 但在实际前向中几乎失去作用. 门控饱和也会让梯度传播质量恶化. 因此训练时除了关心总体 loss, 也要观察门控统计.

FFN 中间态的动态范围常常比人们预期更大. 某些层会出现极端尖峰, 这在高位宽训练里未必立即造成训练崩溃, 但到了低比特量化阶段就会显现. 只要校准区间没覆盖好, 尖峰被截断, 输出就会发生系统性偏移. 这类问题在标准 ReLU/GELU FFN 和门控 FFN 中都可能出现, 门控乘法会让两路的误差相乘叠加. 针对 SwiGLU 的数值范围, 已有截断, softcap 和改写门控函数等做法, 见 [01 SiTU-GLU](../2.1.1-激活函数/01-SiTU-GLU/01-SiTU-GLU.md) 和 [03 PowLU](../2.1.1-激活函数/03-PowLU-Ling对SwiGLU的稳定化改写/03-PowLU-Ling对SwiGLU的稳定化改写.md).

## 7. FFN 与量化, 蒸馏, LoRA, MoE 的关系

FFN 不仅决定模型能学到什么, 也决定它怎么被压缩, 迁移和扩展. 量化, 蒸馏, LoRA 与 MoE 四个方向都涉及 FFN: 量化看它是否降低带宽, 蒸馏看它能否被小模型复现, LoRA 看它是否值得被微调, MoE 看它能不能被拆成稀疏专家.

**量化.** FFN 参数大且被频繁读取, 因此量化收益通常很直接. 把 FFN 权重从 FP16 压到 INT8, INT4, 本质上是降低每一步推理所需搬运的数据量. 很多时候, 量化 FFN 的收益不只是节省显存, 而是直接降低单 token 延迟. 但 FFN 量化也有自己的难点: 门控乘法误差放大, 以及不同矩阵对精度敏感度不一致. 门, 上, 下三类投影往往需要不同量化策略, 激活也可能需要按通道或按组做更精细校准.

**蒸馏.** 蒸馏常被理解为「学生模仿老师输出」或「学习注意力分布」, 但难以复制的部分往往是老师在 FFN 中完成的高容量变换. 小模型最困难的是在更小容量里复现老师的非线性加工能力. 无论蒸馏目标是隐藏状态还是 logits, FFN 仍然是学生能否学到老师行为的关键环节.

**LoRA 与参数高效微调.** 在很多领域适配任务里, 只给 Attention 应用 LoRA 并不总够. Attention 决定信息路由, 按第 3 节的键值记忆解释, 大量知识和风格变换发生在 FFN. 若任务差异主要体现在术语系统, 输出风格, 特定领域规则或结构化格式上, FFN 往往比 Attention 更值得纳入适配范围.

**MoE 与稀疏 FFN.** 稀疏 FFN MoE 的核心思想是把原 FFN 拆成多个专家, 让每个 token 只激活少量专家, 从而把总参数容量与单 token 激活参数量分开. 是否真的节省端到端成本, 还取决于路由, 负载, 通信, 容量溢出和硬件利用率. 注意力专家化与稀疏注意力也存在, 但解决的交互结构问题和工程权衡不同. [Dai et al. (2024)](https://arxiv.org/abs/2401.06066) 代表的 DeepSeekMoE 路线, 以及 Mixtral, MiniMax 等模型, 都把稀疏专家设计围绕 FFN 展开. 因为 FFN 是参数容量最大的子层, 稀疏化带来的收益最显著.

## 8. 极简实现: 标准 FFN 与 SwiGLU 的 PyTorch 映射

下面用最小 PyTorch 代码展示两种主流实现. 实际的大模型实现会加入并行, 融合, 混合精度和张量切分, 但核心结构就是这些.

StandardFFN 只包含 up 投影, 激活与 down 投影; SwiGLUFFN 则额外引入 gate 投影并在逐元素乘法后做 down 投影. 两者都省略偏置, 以匹配现代大模型的常见设置.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class StandardFFN(nn.Module):
    def __init__(self, dim: int, hidden_dim: int):
        super().__init__()
        self.up = nn.Linear(dim, hidden_dim, bias=False)
        self.down = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.down(F.gelu(self.up(x)))

class SwiGLUFFN(nn.Module):
    def __init__(self, dim: int, hidden_dim: int):
        super().__init__()
        self.gate = nn.Linear(dim, hidden_dim, bias=False)
        self.up = nn.Linear(dim, hidden_dim, bias=False)
        self.down = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        gated = F.silu(self.gate(x)) * self.up(x)
        return self.down(gated)
```

这段代码说明三件事. 第一, SwiGLU 的核心不是「更换激活函数」, 而是多出一条门控支路. 第二, SwiGLU 与标准 FFN 的主要开销差别来自额外投影和门控乘法. 第三, 后续所有工程问题, 包括量化, 融合, 稀疏化, 并行切分, 本质上都围绕这些矩阵和这次门控乘法展开.
