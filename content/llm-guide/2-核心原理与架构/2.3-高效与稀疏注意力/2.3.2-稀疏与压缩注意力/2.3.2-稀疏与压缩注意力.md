# 2.3.2 · 稀疏与压缩注意力

稠密注意力的 decode 每生成一个 token 都要把全部历史 KV 从显存读一遍, prefill 的计算量随长度平方增长. 本节收的方法都保留 softmax 注意力, 改的只是两件事之一: 每个 query 对哪些 key 做点积, 或者 KV cache 里留下哪些条目. 降低读写字节的 kernel 实现 (FlashAttention, PagedAttention) 和把 softmax 换成递推状态的线性注意力在 [2.3 高效与稀疏注意力](../2.3-高效与稀疏注意力.md) 的其它小节.

## 本节回答的问题

1. 稀疏单元为什么从 token 变成连续块, 块级路由的打分 (均值池化, 压缩 token, 微块 indexer) 各自丢了什么.
2. 稀疏模式在预训练或续训里学出来, 和在训好的稠密模型上推理时临时裁剪, 质量和成本差在哪.
3. indexer 自己的 $O(n^2)$ 扫描在 1M 长度上怎么处理.
4. 推理期只保留部分 KV 时, 按什么打分 (累积注意力, 观测窗, 当前步分数, 按头画像), 预算怎么在层和头之间分.
5. 哪些方法真的删掉了 KV, 哪些只是少读 (全量 KV 仍在显存), 删掉之后哪类任务先坏.

## 训练期稀疏注意力

这一组改的是模型本身的注意力图, 稀疏模式在预训练, 续训或微调中出现, 权重适应了它.

| 篇 | 一句话 |
|---|---|
| [01 MoBA](./01-MoBA架构深度解析/01-MoBA架构深度解析.md) | 历史切块, 块内 key 均值和 query 打分取 top-k, 当前块强制选中; 可以和全注意力逐层切换 |
| [02 NSA](./02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md) | 压缩, 选择, 滑动窗口三路门控融合, 选择分支复用压缩分支的分数, kernel 按 GQA 组加载 |
| [03 Radial Attention](./03-RadialAttention稀疏注意力/03-RadialAttention稀疏注意力.md) | 视频扩散模型里时空注意力随距离衰减, 用静态的 $O(n\log n)$ 掩码配 LoRA 延长视频 |
| [04 DCA 与 S²-Attn](./04-DCA与S2-Attn-长上下文分块注意力/04-DCA与S2-Attn-长上下文分块注意力.md) | 两种分块: DCA 不训练, 重映射块内/块间相对位置; S²-Attn 在 LongLoRA 微调时分组并移位半组 |
| [05 CSA 与 HCA](./05-CSA-HCA-混合压缩注意力/05-CSA-HCA-混合压缩注意力.md) | DeepSeek-V4 沿序列压缩 KV: CSA 4 合 1 再 top-k, HCA 128 合 1 稠密, 交错排布支撑 1M |
| [06 QSA 与 IndexPool](./06-QSA-Qwen稀疏注意力/06-QSA-Qwen稀疏注意力.md) | indexer 的 key 先收成微块再打分, 索引成本降到 $O(n^2/r)$; GLM-5.3-Flash 的 IndexPool 同属这一族 |

## 推理期 KV 压缩与驱逐

这一组不改训练, 在训好的稠密模型上决定 decode 时保留或读取哪些 KV. 前七篇都会把 KV 真的删掉, Quest 不删, 只少读.

| 篇 | 一句话 |
|---|---|
| [07 StreamingLLM](./07-StreamingLLM与Attention-Sink/07-StreamingLLM与Attention-Sink.md) | 开头几个 token 吸收大量注意力, 保留 4 个起始 KV 加滑动窗即可稳定流式生成 |
| [08 H2O](./08-H2O-Heavy-Hitter-Oracle/08-H2O-Heavy-Hitter-Oracle.md) | 累积注意力分数高的 heavy hitter 和最近 token 各占一半预算 |
| [09 SnapKV](./09-SnapKV-生成前观测窗/09-SnapKV-生成前观测窗.md) | prompt 末尾一小段观测窗投票, 每个头在 prefill 后一次性选出要留的 prompt KV |
| [10 PyramidKV](./10-PyramidKV-层间漏斗/10-PyramidKV-层间漏斗.md) | 浅层注意力分散, 深层集中, 按层递减分配预算, 层内沿用 SnapKV 选法 |
| [11 FastGen](./11-FastGen-按头自适应/11-FastGen-按头自适应.md) | prefill 时给每个头画像, 选特殊 token, 标点, 局部, 高频或全量中的一种保留策略 |
| [12 ScissorHands](./12-ScissorHands-重要性持久/12-ScissorHands-重要性持久.md) | 某一步重要的 token 之后仍重要, 按窗口内低分次数成批丢弃 |
| [13 TOVA](./13-TOVA-注意力省略/13-TOVA-注意力省略.md) | 每步丢掉当前 query 下注意力最低的那条 KV, 把多状态 RNN 的视角落到 Transformer |
| [14 Quest](./14-Quest-查询感知稀疏/14-Quest-查询感知稀疏.md) | KV 按页存 key 的逐维最小/最大值, 当前 query 估上界, 只读 top-k 页, 不删 KV |

## 读法

只关心新模型的架构, 读 01, 02, 05, 06; 01 和 02 是同期两条路, 05 和 06 是一年后把压缩和 indexer 做进 1M 模型的版本. 要在现成模型上省显存, 从 07 和 08 开始, 这两篇定义了后面几篇对照的基线 (sink 加窗口, 累积分数加窗口); 09 到 13 各改打分或预算分配中的一处, 14 是唯一不删 KV 的对照. 04 和 03 处理的是上下文扩展与视频生成, 和其它篇关系较远, 可以单独读.
