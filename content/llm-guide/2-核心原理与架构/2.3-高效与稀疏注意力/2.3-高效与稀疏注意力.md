## 3. 这一章真正研究的是成本结构

标准 Attention 已经成功；后续工作不是证明「attention 有问题」，而是：当规模、上下文、并发一起涨时，这笔账怎么继续付得起。

1. **IO / 访存**：典型答案是 FlashAttention（以及更早的 MEA）。
2. **KV Cache 存储与带宽**：典型答案是 MQA、GQA、MLA、PagedAttention。前三者公式在 2.2.2；分页在 2.3.1。
3. **全连接注意力图本身的计算**：典型答案是稀疏、线性、块级路由。

这三类不互斥。现代系统几乎总是组合技。

## 4. 为什么「更快」必须先问阶段

「更快」至少可能指三件完全不同的事：Prefill 更快、Decode 更快、长上下文更能撑。最优路线并不相同。

- FlashAttention 对 Prefill 极重要：重写稠密 attention 的执行顺序。
- PagedAttention 更偏 Decode：KV Cache 如何被组织与复用。
- 稀疏与压缩更偏「超长上下文下如何不做无意义计算」。
- 线性注意力更激进：从公式层面改成本结构。

读任何一篇之前先问：它优化的是哪个阶段、哪一笔账。

## 5. 统一阅读框架

### 第一问：它改的是哪一层

算子执行层 / 结构层 / 存储层 / 路由层。

### 第二问：它优化的是哪个阶段

训练前向 / 训练反向 / Prefill / Decode。

### 第三问：它付出的代价是什么

数学近似、表达力、实现复杂度、对硬件架构的依赖。

按这个框架看，`2.3.1` 到 `2.3.5` 不会散成名词表。

## 6. 互补，不是替代

- FlashAttention：对稠密注意力做 IO 优化
- 稀疏注意力：减少必须计算的连边
- 线性注意力：改变注意力公式
- MLA：压缩 KV 表示（公式在 2.2.2/04–05）

常见叠法：稠密路径跑 FlashAttention；超长层引入块级稀疏；解码用 GQA / MLA 压缩缓存；服务系统用 PagedAttention 管内存。

## 7. 和 2.4 / 2.5 的边界

- `2.3`：Transformer 注意力还在，把它做得更快、更省、更适合部署
- `2.4`：如果注意力本身不再是唯一主干
- `2.5`：上下文越来越长时，位置编码与外推如何继续撑住

## 10. 本章小结

你要能看出：哪些问题来自二次复杂度本身，哪些来自 IO 和中间矩阵 materialization，哪些来自 KV Cache 管理，哪些必须靠改公式、哪些只需重写执行路径。面对 FlashAttention、MoBA、NSA、MLA、PagedAttention、DeltaNet 时，先问它们分别在替你优化哪一笔账。
