# 01 高效注意力机制全景图：分类、对比与工程选择指南

> **定位说明**：本文是一篇全景综述(Survey),旨在为工程实践者提供一张系统性的"导航地图",帮助读者在纷繁复杂的高效注意力技术中快速定位最适合自身场景的方法. 对于每一种方法的核心数学原理,本文只做提纲挈领的刻画; 如需深度推导,请参阅知识库中对应的专题文章(如《MLA 专题》《FlashAttention 深度解析》等).

***

## 1. 引言：为什么需要一张"全景图"

自 2017 年 Transformer 诞生以来,注意力机制凭借其强大的序列建模能力,迅速成为自然语言处理、计算机视觉、语音识别乃至科学计算领域的核心构件. 然而,标准自注意力的计算复杂度和内存复杂度均与序列长度 $T$ 呈**二次关系**($O(T^2)$),这在长序列场景下成为了不可逾越的障碍.

当序列长度从 1K 扩展到 128K,甚至 1M 时：

* 计算量从 $10^6$ 级暴增到 $10^{10}$ 级
* 注意力矩阵的显存占用从 4 MB 膨胀到 400 GB(fp32)
* 推理阶段的 KV Cache 迅速淹没 GPU 显存

面对这一挑战,学术界和工业界在过去数年间催生了数十种高效注意力变体. 它们从不同的角度切入——有的革新内存访问模式,有的利用稀疏模式跳过计算,有的通过数学近似将复杂度降为线性,有的则直接在表示层面压缩状态. 这些方法之间的关系错综复杂,既有互补叠加的可能,也存在互斥替代的权衡.

\*\*本文的目标不是罗列所有论文,而是建立一套清晰的分类体系(Taxonomy),并基于工程实践的关键维度(序列长度、硬件条件、精度要求、实现复杂度)给出可落地的选择指南. \*\*

![高效注意力机制技术演进与分类全景图](images/attention_landscape_infographic.png)

> **图 1.1 高效注意力机制的技术演进与分类全景**
>
> * **硬件高效层(HCA / FlashAttention 等)**：不修改原始数学公式(即 Softmax 注意力无精度损失), 纯粹在硬件底层(SRAM 与 HBM 之间)重构内存存取和计算顺序.
> * **稀疏与窗口注意力(Sparse / Local Attention)**：限制 attention 作用范围, 舍弃远距离连接. 仅计算对角窗口或跨距块, 将计算复杂度从 $O(T^2)$ 降低到 $O(T \cdot w)$.
> * **线性与核函数近似(Linear Attention)**：利用核函数(Kernel Method)对 Softmax 进行泰勒展开或非线性投影, 改变计算顺序(左乘变右乘), 使复杂度与序列长度 $T$ 呈线性关系.
> * **状态与维度压缩层(MQA / GQA / MLA 等)**：在通道或头(Head)维度进行低秩分解或多头共享, 大幅降低自回归解码中的每 Token KV Cache 显存占用, 是目前极长上下文大模型(如 LLaMA-3、DeepSeek)的工程基石.

> 2026-08：图注里的「HCA」若当 **Hardware-efficient** 用，会和 DeepSeek-V4 的 **Heavily Compressed Attention** 撞名。本篇后文 HCA 一律按 V4。硬件高效层直接写 **Memory Efficient Attention（Rabe & Staats，2021）** / FlashAttention / PagedAttention。CSA 也不再展开成 Cross-Layer，见 §6.2。**不要**把 MEA 收进 FlashAttention 名下。

## 2. 分类体系：四条技术主线

我们将高效注意力机制划分为四大类：

| 大类                               | 核心思想                             | 代表方法                                          | 优化目标                  |
| -------------------------------- | -------------------------------- | --------------------------------------------- | --------------------- |
| **硬件高效 (Hardware-Efficient)**    | 不改变注意力的数学定义,通过优化计算图和内存访问模式提升实际吞吐 | **MEA**（Rabe & Staats 2021）, FlashAttention, PagedAttention, SageAttention | wall-clock time, 显存峰值 |
| **稀疏高效 (Sparse-Efficient)**      | 利用注意力矩阵的天然稀疏性,只计算"重要"的子集         | 局部窗口, 膨胀注意力, Longformer, BigBird；**Star-Transformer**（环+一个中继）；**NVIDIA Star Attention**（推理两阶段块稀疏）；另有 **Sparse Sinkhorn**（先排块再局部 $QK$） | FLOPs, 长距离依赖建模        |
| **线性近似 (Linear Approximation)**  | 通过核方法或特征映射,将二次复杂度降为线性            | 线性注意力, Performer, Linformer, RFA；另有 **AFT** / **Synthesizer**（无 $QK^\top$，时间仍可二次）；**LightConv/DynamicConv**（固定窗卷积，线性） | 渐近复杂度, 超长序列           |
| **压缩高效 (Compression-Efficient)** | 减少每个 token 的 KV 表示维度或共享表示        | MQA, GQA, MLA；V4 的 CSA/HCA；另有 CLA 跨层共享 | KV Cache 显存, 推理并发     |

以下各节将逐类展开.

## 3. 硬件高效：让标准注意力在硬件上跑得更快

这一类方法的核心特征是**计算结果与标准注意力完全等价**,但通过深度适配 GPU/TPU 的内存层次结构(memory hierarchy),显著降低 wall-clock time 和显存峰值.

### 3.0 Memory Efficient Attention（Rabe & Staats，2021）：先有显存算法，才有 FA 核

Rabe & Staats（Google Research，[arXiv:2112.05682](https://arxiv.org/abs/2112.05682)）的标题是 *Self-attention Does Not Need $O(n^2)$ Memory*。社区叫 **Memory Efficient Attention / MEA**。它是**精确**注意力：lazy softmax 把除法留到最后，再用 running max 做数值稳定；单 query 额外工作集 $O(1)$，self-attention 再多数一个下标 $O(\log n)$，TPU 实用实现 KV 块长 $\sqrt{n}$ 时 $O(\sqrt{n})$。时间仍 $O(n^2)$。评测在**单颗 TPUv3**、对照 Flax：Table 2 上 $n=2^{14}$ 额外显存 1GB→17MB；摘要写推理 **59×**、求导 **32×**。标准实现从 $2^{16}$ 起 OOM（$>16$ GB）。

**不是** FlashAttention。MEA 是 2021-12 的 JAX/TPU 分块；FA（2022-05）是 GPU 上 IO-aware 的 CUDA 融合核。FA 附录 B.5 写了三条机制差：MEA 打峰值占用、FA 打 HBM 访问次数；MEA 先留 $K$ 份块摘要再合并，FA 增量更新**一份** $O$；反向 MEA 用 checkpoint，FA 用解析公式。TPU 上这篇并不比标准注意力快（Table 2 相对速度 $-8\%$ 到 $-13\%$）。公式、表、五张自绘图在本体 [00-MEA](../2.3.1-硬件高效注意力/00-Memory-Efficient-Attention/01-MEA-显存高效注意力.md)。

### 3.1 FlashAttention 系列：IO 感知的精确注意力

#### 3.1.1 核心思想

FlashAttention(Dao et al., 2022)的洞察极为深刻：**注意力的性能瓶颈不在于 FLOPs,而在于 GPU HBM(高带宽内存)和 SRAM(高速缓存)之间的数据搬运**. 标准注意力实现中,注意力矩阵 $S = QK^T$ 和 $P = \text{softmax}(S)$ 被显式物化到 HBM 中,造成了巨大的内存读写开销.

FlashAttention 的核心创新是**分块计算(tiling)** 与**在线 softmax**. 它将 $Q, K, V$ 矩阵切分为足够小的块(block),使得每个块能完全放入 SRAM 中,然后在 SRAM 内完成完整的 softmax 和 attention 计算,最后只将最终的输出 $O$ 写回 HBM.

> **2026-08 修订（不删上文）。** 「分块 + 在线 softmax」不是 FA 在 2022 年才发明的。单卡精确、不物化 $n\times n$ 的算法先写在 MEA（[2112.05682](https://arxiv.org/abs/2112.05682)，§3.0 / [00-MEA](../2.3.1-硬件高效注意力/00-Memory-Efficient-Attention/01-MEA-显存高效注意力.md)）。FA 的新东西是 **IO-aware CUDA 核**：SRAM tile、增量一份 $O$、解析反向、把 HBM 访问从 $\Theta(N^2)$ 收到 $\Theta(N^2 d^2/M)$。不要在本小节把 MEA 写成 FlashAttention 的别名。

#### 3.1.2 关键公式

标准注意力的计算流程：

$$
S = QK^T \in \mathbb{R}^{N \times M}, \quad P = \text{softmax}(S), \quad O = PV \tag{1}
$$

此式将上述直觉形式化,各项分别对应输入变换、非线性激活与输出生成.
FlashAttention 的在线 softmax  trick 将这三个步骤融合为一个 kernel：

为建立定量关系,定义如下表达式：

$$
\tilde{m}_{ij} = \max(m_{i,j-1}, \max_k S_{ik}^{(j)}) \tag{2}
$$

此式描述了变量之间的定量关系,其中每一项对应特定的物理操作.

基于上述分析,建立如下数学关系：

$$
\tilde{\ell}_{ij} = e^{m_{i,j-1} - \tilde{m}_{ij}} \ell_{i,j-1} + \sum_k e^{S_{ik}^{(j)} - \tilde{m}_{ij}} \tag{3}
$$

将上述约束转化为数学表达：

$$
\tilde{O}_{ij} = e^{m_{i,j-1} - \tilde{m}_{ij}} O_{i,j-1} + \sum_k e^{S_{ik}^{(j)} - \tilde{m}_{ij}} V_k^{(j)} \tag{4}
$$

其中 $m$ 为逐行的最大值(用于数值稳定),$\ell$ 为归一化分母,$O$ 为累加的输出. 这三步在每块内迭代执行,最终得到与标准 attention **比特级精确一致**的结果.

#### 3.1.3 复杂度分析

| 维度                        | 标准 Attention | FlashAttention                       |
| ------------------------- | ------------ | ------------------------------------ |
| 计算复杂度                     | $O(N^2 d)$   | $O(N^2 d)$(FLOPs 不变)                 |
| HBM 访问量                   | $O(N^2)$     | $O(N^2 / M) + O(Nd)$($M$ 为 SRAM 块大小) |
| 显存峰值                      | $O(N^2)$     | $O(N)$(无需存储 $S, P$)                  |
| wall-clock (A100, 2K seq) | 100 ms       | \~15 ms(约 7.6× 加速)                   |

#### 3.1.4 FlashAttention-2 与 FlashAttention-3

* **FlashAttention-2**(2023)：减少了非矩阵乘法的运算量, 优化了 warp 级并行, seq\_parallel 策略使得不同注意力头可以并行处理.

* **FlashAttention-3**(2024)：针对 NVIDIA Hopper 架构(H100)的 Tensor Core 和异步拷贝做了深度定制, 支持 FP8 低精度计算, 在 H100 上实现了接近 roofline 的利用率.

> 2026-08：不要写成「接近 roofline」。[2407.08608v2](https://arxiv.org/html/2407.08608v2) 摘要：FA2 在 H100 约 **35%** 利用率；FA3 FP16 最高约 **740 TFLOPs/s（75%）**，相对 FA2 前向 1.5–2.0×；FP8 接近 1.2 PFLOPs/s。论文把 LLM inference 优化列为未做完。Decode 的 split-KV 在 [6.6.3](../../../6-训练与推理优化/6.6-推理框架与高级优化/6.6.3-Flash-Decoding原理与实现.md)；Hopper 核展开在 [04-FA3](../2.3.1-硬件高效注意力/01-FlashAttention/04-FlashAttention-v3.md)。

#### 3.1.5 适用场景

* **任何需要精确注意力结果且使用 GPU 的场景**. FlashAttention 已成为现代 LLM 训练的事实标准(PyTorch 2.0+ 原生集成 `scaled_dot_product_attention` 自动调度).
* 特别适合**中等长度序列(512 \~ 32K)** 的训练, 因为此时 $O(N^2)$ 计算尚可行, 但 $O(N^2)$ 显存会成为瓶颈.

> **2026-08 修订（不删上文）。** FlashAttention 与 Memory Efficient Attention 是**两篇**。两者都**只把注意力**收到 $O(s)$，一层 FFN 仍按 **$8bsh$** 记账。MEA 本体在 [00-MEA](../2.3.1-硬件高效注意力/00-Memory-Efficient-Attention/01-MEA-显存高效注意力.md)，不要写在 FA 名下。Blockwise Parallel Transformer（Liu & Abbeel，[2305.19370](https://arxiv.org/html/2305.19370)，NeurIPS 2023）在同一个 query 块上接着做 FFN，一层激活 **$2bsh$**。不是跨机 Ring，也不是序列并行。Table 2 同一行对 vanilla 是 **8×** 上下文，摘要「32×」没有落在同一行。BPT 本体在 [6.1.1 §4.7](../../../6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md)。

### 3.2 PagedAttention：为推理而生的 KV Cache 内存管理

#### 3.2.1 核心思想

PagedAttention(Kwon et al., 2023, vLLM 的核心贡献)解决的问题与 FlashAttention 不同：**推理阶段 KV Cache 的内存分配效率**. 在自回归生成中, 由于输出长度不确定, 系统往往为每个请求预先分配最大可能长度的连续显存块, 导致严重的内存碎片和浪费.

PagedAttention 借鉴操作系统虚拟内存的**分页(paging)** 机制：

* 将 KV Cache 分割为固定大小的 **block**(如每 block 16 个 token)
* 物理 block 可以非连续存放, 通过 block table 映射到逻辑上的连续序列
* 支持请求间的 block 共享(如并行采样时多个候选序列共享前缀 block)

#### 3.2.2 工程效果

在 LLM serving 场景下, PagedAttention 可以将 GPU 利用率从 40\~60% 提升到 90%+, 因为：

* 消除了内存碎片和过度预分配
* 支持动态的 batching 和抢占(preemption)
* 前缀共享使得 beam search 和 parallel sampling 的显存占用大幅下降

> **2026-08 修订（不删上文）。** 「GPU 利用率 40–60% → 90%+」**不是** [SOSP 2023 / arXiv:2309.06180](https://ar5iv.labs.arxiv.org/html/2309.06180) 里的数字。论文量的是 **吞吐** 和 **KV 这块显存有没有浪费**，不是 nsys 里的 SM busy%。摘要：相对 FasterTransformer / Orca，**同等延迟下吞吐 2–4×**；更长序列、更大模型、更复杂解码时差距更大。§6.2 ShareGPT：相对自实现的 Orca (Oracle) 能扛 **1.7–2.7×** 请求率，相对 Orca (Max) **2.7–8×**，相对 FasterTransformer 最高约 **22×**（FasterTransformer 没有 iteration-level 调度，内存管法接近 Orca Max）。Fig. 2：现有系统里 KV cache **只有 20.4%–38.2%** 真正存了 token 状态；vLLM 把浪费限制在 **每个请求最后一个未填满的 block**（near-zero waste）。A100 40GB、13B：约 **65% 权重、约 30% KV、激活很小**——所以 batch 上限绑在 KV 怎么切，不是「算子不够快」。OPT-13B：单 token KV **800 KB**（$2\times 5120\times 40\times 2$ byte FP16），2048 token 最多 **1.6 GB**。默认 block size **16**（§7.2：ShareGPT 上 16–128 都好用；Alpaca 短序列上 16/32 更好）。注意力 kernel 相对 FasterTransformer 慢 **20–26%**（块表、分支、变长），端到端仍然赢。共享不是「前缀省 50–90%」这种口头数：Alpaca 并行采样省 **6.1–9.8%** 块、beam 省 **37.6–55.2%**；ShareGPT 并行 **16.2–30.5%**、beam **44.3–66.3%**；few-shot 共享前缀相对 Orca (Oracle) 吞吐 **1.67× / 3.58×**（80 / 341 token 前缀）。本体展开在 [6.4.1](../../../6-训练与推理优化/6.4-KV缓存与内存优化/6.4.1-PagedAttention原理/6.4.1-PagedAttention原理.md) 与 [01-PagedAttention与vLLM](../2.3.1-硬件高效注意力/02-PagedAttention/01-PagedAttention与vLLM.md)。

#### 3.2.3 适用场景

* **高并发 LLM 服务部署**(batch size > 8)
* 动态长度生成任务(如对话、代码补全)
* 与 FlashAttention 正交叠加：PagedAttention 管理"在哪里存", FlashAttention 优化"怎么算"

### 3.3 SageAttention：量化感知的注意力加速

#### 3.3.1 核心思想

SageAttention(2024)探索了另一条硬件加速路径：**低精度量化**. 它观察到注意力计算中的 $QK^T$ 和 $PV$ 具有不同的数值敏感度：

* $QK^T$(score 计算)可以使用 INT8 甚至 FP8, 因为 softmax 对绝对尺度的敏感度较低
* $PV$(weighted sum)需要更高的精度, 但可以通过 per-channel 缩放来缓解误差

SageAttention 设计了混合精度的注意力 kernel, 在支持低精度 Tensor Core 的硬件(H100, RTX 4090)上实现了显著加速.

> **2026-08 修订（不删上文）。** 不要把 SageAttention 写成「H100 上的 FP8 FlashAttention 换皮」。[arXiv:2410.02367](https://arxiv.org/html/2410.02367) 是清华 THU-ML 的 **注意力核 INT8 量化**（plug-and-play，主要打线性层量化留下的注意力）。相对 FlashAttention2 / xformers，OPS 约 **2.1× / 2.7×**。作者强调 FA3 的 FP8 路径绑 Hopper；SageAttention 的对照场景是 **RTX 4090 / 3090** 上 INT8 Tensor Core（INT8 Matmul 在这些卡上常比 FP8 快一倍）。三件套：(1) **平滑 K**：减去 token 维均值，不改 softmax 结果，$\sigma(q(K-\mathrm{mean})^\top)=\sigma(qK^\top)$，开销 $<0.2\%$；否则 INT8 $QK$ 在文生图/视频上会糊。(2) $Q,K$ 用 INT8（per-token 或 per-block，不能 per-channel，因为 $QK^\top$ 的内轴 scale 没法反量化）。(3) $PV$ 用 **FP16 + FP16 accumulator**（4090/3090 上比 FP32 累加快约 2×，精度不掉）。在线 softmax 仍全精度。论文写端到端指标几乎不掉（语言 / 图 / 视频）。「优于 FlashAttention3」指的是 **精度对照**（直接上 FA3 FP8 会掉点，见表 1），不是 H100 上打赢 FA3 的 TFLOPs。SageAttention2（4-bit，arXiv:2411.10958）本篇不展开。

#### 3.3.2 适用场景

* **部署在支持 FP8/INT8 Tensor Core 的最新硬件上**
* 对精度损失容忍度较高的场景(如聊天机器人, 而非科学计算)
* 与模型权重量化(AWQ, GPTQ)叠加使用, 构建全链路低精度推理

## 4. 稀疏高效：利用注意力矩阵的天然稀疏性

与硬件高效类不同, 稀疏高效类方法**主动改变注意力的计算模式**, 假设注意力矩阵中只有少数位置需要被计算. 这一假设在大量实证中得到了验证：对于大多数自然语言序列, 注意力权重在经过 softmax 后往往呈现强烈的局部性和长尾分布.

### 4.1 局部窗口注意力(Local/Sliding Window Attention)

#### 4.1.1 核心思想

每个 token 只 attend 到其左右各 $w$ 个邻居. 这类似于卷积神经网络的感受野概念.

基于前述物理直觉, 给出数学形式：

$$
\alpha_{ij} = \begin{cases}
\text{softmax}(q_i^T k_j / \sqrt{d}) & \text{if } |i - j| \leq w \\
0 & \text{otherwise}
\end{cases} \tag{5}
$$

此式将上述直觉形式化, 各项分别对应输入变换、非线性激活与输出生成.

#### 4.1.2 复杂度

* 计算：$O(T \cdot w \cdot d)$, 当 $w \ll T$ 时接近线性
* 内存：$O(T \cdot w)$(注意力矩阵从稠密变为带状稀疏)

#### 4.1.3 代表模型

* **Longformer**(Beltagy et al., 2021)：滑动窗口 + 全局 token
* **Mistral-7B**：在底层使用滑动窗口注意力(window size = 4096), 配合滚动缓存(Rolling Buffer Cache)实现理论无限上下文

> **2026-08 修订（不删上文）。** 「理论无限上下文」**不是** Jiang 等人 *Mistral 7B*（[arXiv:2310.06825](https://ar5iv.labs.arxiv.org/html/2310.06825)）的句子。摘要写的是 SWA **以更低推理代价处理任意长度序列**——任意指 **cache 不再随 $n$ 涨**，不是把官方窗口改成无限。Table 1：`window_size = 4096`，**`context_len = 8192`**。

式 (5) 的 $|i-j|\le w$ 是 **双向** 局部窗（更接近 Longformer 的 local pattern）。Mistral 是 **因果左窗**：第 $k$ 层位置 $i$ 只 attend 上一层 $[i-W,i]$（Figure 1 示意 $W=3$）。递推后，输入层距离最多 $W\times k$ 的 token 仍能间接影响当前位置。$W=4096$、$k=32$ 时论文写 **理论注意跨度约 131K**——这是感受野上界，**不是** `context_len=131K`。Longformer 另加全局 token；7B 报告 **没有** 这条支路。

### 4.2 膨胀注意力(Dilated/Strided Attention)

#### 4.2.1 核心思想

在局部窗口的基础上, 以固定步长 $d$ 采样 attend 的位置, 类似于空洞卷积(dilated convolution).

基于前述物理直觉, 给出数学形式：

$$
\alpha_{ij} \neq 0 \iff |i - j| \leq w \text{ 且 } (i - j) \equiv 0 \pmod{d} \tag{6}
$$

此关系式描述了变量之间的定量映射, 为后续优化提供了数学基础.
此式给出了精确的数学定义, 为算法实现提供了理论基础.

#### 4.2.2 特点

* 在不增加计算量的情况下扩大感受野(effective receptive field = $w \times d$)
* 适合周期性或层次化结构的数据(如音乐、代码)
* 但稀疏模式是固定的, 无法适应数据驱动的内容重要性

> **2026-08 修订（不删上文）。** 式 (6) 写的是 $|i-j|\le w$ **并且** $(i-j)\equiv 0\pmod{d}$。按这个式子，一层的最远距离仍是 $w$，连接数大约是 $w/d$，感受野**不会**变成 $w\times d$。把「步长抽样」和「感受野乘 $d$」写在同一行，是 2025 笔记里两套图案叠在一起了。

Longformer（[arXiv:2004.05150](https://ar5iv.labs.arxiv.org/html/2004.05150)）§3 的 **dilated sliding window** 才是「算力不变、跨度变大」那条：窗上留宽为 $d$ 的空隙，类比空洞卷积。$d$ 与 $w$ 各层都固定时，顶层感受野写成 $\ell\times d\times w$。非膨胀滑窗：每边 $\frac{w}{2}$ 个邻居，复杂度 $O(n\cdot w)$，顶层感受野 $\ell\times w$。和式 (6) 对齐的写法是：**连接数仍约 $w$**，第 $k$ 步跳 $d$ 个位置：

$$
\alpha_{ij}\neq 0 \iff |i-j|=k\cdot d,\quad k\in\{0,1,\ldots,\lfloor w/2\rfloor\}
$$

一层跨度约 $(w/2)\cdot d$，不是把窗宽截在 $w$ 再抽稀。字符级 LM（text8 / enwik8）才用膨胀：下层**不用** dilation，好学近邻；上层只给 **2 个头**加一点点递增 dilation。从 RoBERTa 接着做下游时 window $=512$、**加 dilation 会掉点**（多半和预训练权重不兼容），所以「Longformer = 滑窗 + 全局 token」那句描述的是迁移设置，不是字符 LM。

Child 等人 Sparse Transformer（[arXiv:1904.10509](https://arxiv.org/abs/1904.10509)）是 **strided / 因子分解** 祖先，复杂度 $O(n\sqrt{n})$（BigBird 相关工作也这样引），**不是** $O(n)$，也不要和 Longformer 的空洞窗画成同一张掩码。BigBird **没有** dilated 这一支，图案见下一节。

### 4.3 随机稀疏与学习型稀疏

#### 4.3.1 随机稀疏(Random Sparse)

BigBird(Zaheer et al., 2021)证明：只要注意力图包含三种边——局部边(local)、全局边(global, 所有 token attend 到少数全局 token)和随机边(random), 则 Transformer 可以逼近任意图灵可计算函数.

BigBird 的复杂度为 $O(T)$, 同时保留了表达能力理论保证, 是稀疏注意力的里程碑.

> **2026-08 修订（不删上文）。** 上面把两条定理揉成了一句「三种边 ⇒ 任意图灵可计算函数」。Zaheer 等人 *Big Bird*（[arXiv:2007.14062](https://ar5iv.labs.arxiv.org/html/2007.14062)）分开写：

1. **通用逼近（Theorem 1）**：编码器侧，对紧集上连续的 seq-to-seq 函数 $f:[0,1]^{n\times d}\to\mathbb{R}^{n\times d}$，只要注意力图 **包含星图 $S$**（有全局节点），稀疏 Transformer 就能在 $\ell_p$ 距离上逼近到任意 $\varepsilon$。关键件是 **$O(1)$ 个全局 token**，不是随机边。证明里用额外全局位做 contextual mapping；随机边在这段不出现。
2. **图灵完备（§3.3）**：要 **稀疏编码器 + 稀疏解码器**，并且沿用 Pérez et al. 2019 的 **任意精度** 假设（有限精度下大家都是有限状态机）。这不是「BERT 式单编码器 + 三种边 ⇒ 任意可计算函数」。
3. **没有免费午餐（§3.4 / Proposition 1）**：找每个向量的最远邻居，满注意力 $O(1)$ 层能做；$\tilde{O}(n)$ 条边的稀疏注意力在正交向量猜想下需要 $\tilde{\Omega}(n)$ 层。稀疏省的是内积次数，不是层数上界。

三种积木仍是论文 Figure 1 的工程图案，只是理论分工不同：

| 积木 | 论文符号 | 干什么 |
| --- | --- | --- |
| 随机 | 每个 query 看 $r$ 个随机 key | Erdős–Rényi / 小世界：$\tilde{\Theta}(n)$ 边时平均路径对数；单独不够打 BERT |
| 滑窗 | 位置 $i$ 看 $[i-w/2,\,i+w/2]$ | 局部性 / 高聚类系数；§2 写明 **随机 + 窗口仍不够** 追上 BERT |
| 全局 | $g$ 个全局 token | 理论 UA 用的星图；经验上同样关键 |

全局有两种造法：**ITC** 把已有位置标成全局（$A(i,:)=A(:,i)=1$）；**ETC** 再加 $g$ 个额外位置（如 CLS），矩阵变成 $(n+g)\times(n+g)$。主实验 ETC 更好。实现不是逐 token 随机访存：Appendix / Figure 3 先 **切成 block**，再在 block 上做随机 / 窗 / 全局（示意 block size $=2$）。$w,r,g$ 当常数时内积次数 $O(n)$；每个 query 实际看约 $w+r+g$ 个（再乘 block 宽）。NLP 表用序列长度 **4096**；摘要「类似硬件上约 **8×**」是相对当时常见的 512，不是论文把主实验开到 1M。基因组任务另说。

##### Star-Transformer：一个中继 + 环，不是 BigBird，也不是 NVIDIA Star Attention

> **2026-08 修订（不删上文）。** Guo、Qiu、Liu、Shao、Xue、Zhang *Star-Transformer*（[arXiv:1902.09113](https://ar5iv.labs.arxiv.org/html/1902.09113)，**NAACL 2019**，[N19-1133](https://aclanthology.org/N19-1133/)，页 1315–1325）比 BigBird 早一年。拓扑是 **星**：$n$ 个卫星节点（每个 token 一个状态）+ **一个**共享中继 $\mathbf{s}$。边只有两类：径向（卫星 $\leftrightarrow$ 中继）和环形（相邻卫星，**首尾也连**）。连接数从 $n^{2}$ 写成 **$2n$**。不是学块置换（Sinkhorn），不是 LSH，也不是后来 NVIDIA 的 *Star Attention* 推理核（[2411.17116](https://arxiv.org/abs/2411.17116)）。BigBird Theorem 1 里的「星图」是 **$O(1)$ 个全局 token 当 UA gadget**；这篇是整层编码器都长这样，中继每层还要 **gather 一次**。

仍做缩放点积 + 多头，**没有去掉 $QK$**。式 (1)–(3) 就是 Vaswani 的 $\mathrm{Att}/\mathrm{MultiAtt}$。更新分两拍（Algorithm 1）：

1. **卫星**（式 4–6）：第 $i$ 个 query 只看长度为 **5** 的上下文 $\mathbf{C}_i=[\mathbf{h}_{i-1};\mathbf{h}_i;\mathbf{h}_{i+1};\mathbf{e}_i;\mathbf{s}]$，再 $\mathrm{LayerNorm}(\mathrm{ReLU}(\cdot))$。不是标准残差+LN 顺序。
2. **中继**（式 7–8）：$\mathbf{s}$ 对 $[\mathbf{s};\mathbf{H}]$ 做 MultiAtt，长度 $n+1$，这才是非局部通道。$\mathbf{s}^0=\mathrm{average}(\mathbf{E})$，$\mathbf{H}^0=\mathbf{E}$。可学习位置嵌入加在第一层。

复杂度他们写成一层 $O(6nd)$：环 $O(5nd)$ + 径向 $O(nd)$，对照满注意力 $O(n^2d)$。最长依赖路径经中继 **两跳**，写成 $O(1)$（常数 2），对照 RNN 的 $O(n)$。分类用 $\mathbf{s}^T+\max(\mathbf{H}^T)$；序列标注用 $\mathbf{H}^T$。

##### NVIDIA Star Attention：推理两阶段块稀疏，不是 2019 编码器

> **2026-08 修订（不删上文）。** Acharya、Jia、Ginsburg（NVIDIA）*Star Attention: Efficient LLM Inference over Long Sequences*（[arXiv:2411.17116](https://ar5iv.labs.arxiv.org/html/2411.17116)，关键词标 ICML；代码 [NVIDIA/Star-Attention](https://github.com/NVIDIA/Star-Attention)）和上一节 **不是同一件事**。2019 那篇改的是编码器拓扑；这篇 **不改权重、不微调**，只改 **长上下文推理** 怎么切块、怎么通信。对照基线是 **Ring Attention**（Liu、Zaharia、Abbeel，[arXiv:2310.01889](https://ar5iv.labs.arxiv.org/html/2310.01889)，ICLR 2024）：环上传递 KV、算的是 **精确** 全局注意力。Star Attention 在 context encoding 上长得像 Ring「把序列切到多机」，但 **Phase 1 主机之间不传 KV**。

前提：长任务常常是 **很长的 context + 短 query + 短答案**。作者的观察是 context token 多半只需要看邻近块，query / 生成 token 才需要看全部历史。于是两拍（Figure 1 / Algorithm 1–2）：

1. **Phase 1 局部编码。** 把 context $c$ 切成 $n$ 块，每块 $b$ 个 token。除第一块外，每块前面再拼一份 **锚块** $c_1$（序列开头那一块），得到 $c'_i=(c_1,c_i)$，长度 $2b$。$c_1$ 的位置编号 **仍是** $[0,\ldots,b-1]$，不改成当前块的下标。各 host 只在自己的 $2b$ 上做自注意力（可叠 Flash Attention）。**锚块的 KV 丢掉**，只留下 $c_i$ 的 KV。没有锚块时，每块开头各自长一个 attention sink（Xiao et al. StreamingLLM 那种），Phase 2 对不上全局分布（Figure 3b）；加上 $c_1$ 再丢掉锚 KV，sink 收到锚上，块内分布才接近全局（Figure 3c）。复杂度相对整段 $O(L^2)$ 写成对 context **线性**（块内仍是 $O(b^2)$，块数随 $L/b$ 涨）。
2. **Phase 2 查询 + 生成。** query 广播到所有 host。每台用本地 $K_h,V_h$ 算出局部注意力 $A_h$ 和 softmax 分母 $s_h$（式 1–2）。指定一台 **query-host** 收集 $\{A_h,s_h\}$，用 $s_{\mathrm{global}}=\sum s_h$ 做 $A_{\mathrm{global}}=\sum_h (s_h/s_{\mathrm{global}})A_h$（式 3–4）。每 token 只传 **一个标量 + 一个向量**，不搬整段 KV。生成时 **只有 query-host 更新 KV**。实现上用 Flash Attention + online softmax 的 log-sum-exp（Appendix Algorithm 2），不要按式 1 的朴素 $\exp$ 去实现。

#### 4.3.2 学习型稀疏

更激进的方向是让模型自己学习"该 attend 到哪里"：

* **Reformer**(Kitaev et al., 2020)：使用 LSH(Locality-Sensitive Hashing)将相似的 query/key 分到同一桶, 只在桶内计算注意力.

* **Routing Transformer**(Roy et al., 2021)：基于 k-means 聚类动态决定稀疏模式.

* **Sparse FlashAttention**：在 FlashAttention 的分块框架内, 通过 top-k 选择跳过不重要的块.

> **2026-08 修订（不删上文）。** Kitaev 等人 *Reformer*（[arXiv:2001.04451](https://ar5iv.labs.arxiv.org/html/2001.04451)，ICLR 2020）不是「学会该 attend 哪里」。LSH 用的是 **随机投影** 的角哈希：$h(x)=\operatorname{argmax}([xR;-xR])$，$R\in\mathbb{R}^{d_k\times b/2}$（Andoni et al. 2015）。相近向量大概率同桶，哈希函数 **不训练**。真正按内容学簇的是下一颗 Routing Transformer（k-means），不要和 LSH 揉成一类「学习型稀疏」。

三条一起才叫 Reformer，LSH 只是其中一条：

1. **LSH attention**：复杂度从 $O(L^2)$ 写成 $O(L\log L)$（摘要）。实现上 **Q=K**（同一线性层），再 $k_j=q_j/\|q_j\|$。softmax 由最大项主导，每个 query 只看近邻。按桶号排序后，切成宽 $m=2L/n_{\mathrm{buckets}}$ 的块，每块 attend **自己 + 前一块**（Figure 2d / 式 (5)）。多轮哈希取并（式 (6)），轮数可在 **评估时加多**（Table 2：用 4 轮训、8 轮评，复制任务能到 100%）。共享 QK 下 **禁止自己 attend 自己**（$q\cdot q$ 几乎总是最大），除非没有别的合法目标（句首）。Table 1 的时间项里有 $n_r(4L/n_c)^2$；Table 3 假定 $n_c=L/32$，于是 $4L/n_c=128$、$c=128^2$——这就是 Linformer 相关工作说的「常数很大、短序列不划算」。**不是** $O(L)$。
2. **可逆残差**（Gomez et al. 2017 RevNet）：$Y_1=X_1+\mathrm{Attention}(X_2)$，$Y_2=X_2+\mathrm{FeedForward}(Y_1)$，反传时用减残差还原，整网只存一份激活，消掉层数 $n_l$。
3. **FFN 分块**：按位置切开算，数值上等同，只省 $d_{ff}$ 那一截显存。

实验：合成复制 $0w0w$（整段 1024）；**enwik8-64K**；**imagenet64** 序列约 12K。3 层消融 $d_{\mathrm{model}}=1024$、$d_{ff}=4096$、8 头、batch 8 条、8 卡。共享 QK、可逆层对 enwik8 / imagenet64 的 bits/dim 曲线几乎贴上标准 Transformer。WMT14 En–De **不用 LSH**（测试句都短于 128，而 LSH 块大约 128）。可逆 base 100K step BLEU **27.6**（Vaswani base 27.3）；可逆 big 300K **29.1**（Ott big 29.3）。12 层 enwik8：20K step dropout 0.1 测集 **1.19 bits/dim**；再训再调到 **1.05**。$n_{\mathrm{rounds}}=8$ 时 LSH 已几乎贴满注意力（Figure 4）。

> **2026-08 修订（不删上文）。** Roy 等人 *Routing Transformer*（[arXiv:2003.05997](https://ar5iv.labs.arxiv.org/html/2003.05997)，**TACL 2021**）才是「按内容学簇」。不要写成 LSH，也不要写成 Mixtral 那种专家门控。

和 Reformer 的对照只钉三条：

| | Reformer LSH | Routing Transformer |
| --- | --- | --- |
| 空间怎么切 | 随机超平面，训练中 **固定** | 在线球面 $k$-means，质心 $\bm{\mu}$ **跟着学** |
| 复杂度 | 摘要 $O(L\log L)$ | $O(nkd+n^{2}d/k)$，取 $k=\sqrt{n}$ 变成 $O(n^{1.5}d)$ |
| ImageNet-64 | 相关工作引 Reformer Figure 3 约 **3.65** bits/dim | Table 4 **3.43**（正文 3.425；Sparse Transformer 3.44 / 3.437） |

两边都在近似 **MIPS**（query 只想看点积最大的那批 key）。单位球上 $\|Q_i-K_j\|^2=2-2Q_i^\top K_j$，最近邻就是最大点积。论文用 **关掉 scale/bias 的 LayerNorm** 把 $Q,K$ 投到 $d$-球上，不是手写 $\|x\|_2=1$。质心跨序列共享，Bottou–Bengio 那种在线更新；实现是指数滑动平均，衰减 $\lambda$ 通常 **0.999**，padding 不进质心。

式 (8)：query $i$ 只看与 $\mu(Q_i)$ **同簇、且** $j<i$ 的 key。Algorithm 1 里因果分支直接 **$K\leftarrow Q$**（和 Reformer 一样，避免「未来 key 进了这个簇」再加一张掩码）。非因果的编码器 / 交叉注意力不必共享 QK。

**平衡簇不是标准 k-means。** 每个质心按到 $\mu_i$ 的距离排序，取最近的 $w=n/k\sim\sqrt{n}$ 个 token（top-$k$）。再加 $O(n\log n)$ 排序，被 $O(n^{1.5}d)$ 盖住。好处是簇一样大，TPU/GPU 好切；代价是 **不保证** 每个点只属于一个簇。论文自己说将来想用平衡 k-means，当时没做。图里「assign to top-$k$ centroids」若理解成「每个 query 选 $k$ 个质心」就反了——是 **每个质心选 $w$ 个 token**。

这不是 Shazeer MoE，也不是 Correia 的 sparsemax/entmax：后两条要先物化整张 $n\times n$ 再变稀疏；Routing 从一开始只实例化同簇的块。和 XL / Compressive 的片段缓存也正交：Compressive 在 PG-19 上按 **512** 一块训，Routing **直接训 8192**。

主实验不是「所有头都 routing」。除 PG-19 外：**一半头局部窗，一半头按簇路由**。PG-19 更省：8 头里只留 **2** 个 routing，而且只放在 **最后两层**（长程只在顶层需要）。局部注意力本身已经很强：放大后的 ImageTransformer **3.48** bits/dim（Sparse Transformer 3.44）；WT103 局部相对位置 **19.8** vs XL **18.3**。CIFAR-10 消融（Table 1，12 层 8 头，$k=6$）：窗 512 时最好是 **4 routing 层 × 4 routing 头 → 2.971** bits/dim；纯 routing 无局部掉到 **3.400**；把路由换成随机下标（Random Transformer）**3.076**，比局部 **3.009** 还差。所以「学簇」有用，前提是底下先有局部表示。

##### Sparse Sinkhorn Attention：学块置换，不是去掉 $QK$

> **2026-08 修订（不删上文）。** Tay 等人 *Sparse Sinkhorn Attention*（[arXiv:2002.11296](https://ar5iv.labs.arxiv.org/html/2002.11296)，**ICML 2020**，PMLR 119:9438–9447）也是「学习型稀疏」，但不是 LSH，也不是 k-means。AFT 相关工作把它和 Synthesizer、LightConv 并列成「去掉点积」——**不对**：排完块之后仍做 **局部 $QK^\top$**。也不是 mHC 把残差混合投到双随机矩阵上的那套 Sinkhorn–Knopp（[2.1.3/02-xHC](../../2.1-深度学习基础组件/2.1.3-残差连接/02-xHC-Expanded-Hyper-Connections.md)）。

切法：长度 $\ell$ 分成 $N_B$ 块，每块 $B=\ell/N_B$ 个 token。普通局部注意力只看本块。SortNet 先把每块求和池化成 $X'\in\mathbb{R}^{N_B\times d}$（式 1–2），再用 $P$ 投到 $N_B$ 维得到 $R$（式 3–4；文里 $W_B$ 的形状写成 $d\times\ell_B$，和「输出 $N_B$ 维」对不上，按输出维理解）。对 $R$ 做 **Sinkhorn 迭代**（先 $\exp$，再交替行列归一，log 域实现），得到双随机矩阵，再左乘块序列，等于 **按块置换**。之后只在新邻域里算点积，并 **加上** 原来的局部项 $Q_i K_j^\top$（§3.2）。每头自己学一份 $R$，不共享。Gumbel 噪声 $+\tau$：温度越低越接近 0/1 置换矩阵。

复杂度他们写成 $O(B^2+N_B^2)$（§4 / 引言）。$\ell{=}1024$、$N_B{=}64$ 时相对 $O(\ell^2)$ 约 **240×** 显存。SortCut 编码再截成预算 $N_k$ 块，写成 $O(\ell N_k)$，宣称近线性。**Mixture** 再加一路满 $\mathrm{softmax}(QK^\top)V$，复杂度退回二次。

因果（§3.3）：块若被排到更早的位置就被掩掉，所以偏爱近邻块交换。$R$ 用 **前缀累加**（每块用块内第一个 token）生成，不能用全局求和。Sinkhorn 迭代里加掩码，避免用到未来。SortCut 只适合编码器，除非解码每步重算自注意力。

实验 Tensor2Tensor，16×TPU v2 训 LM；Sparse Transformer 是他们按 Child 固定模式 **手写掩码模拟**，没有原论文 CUDA kernel。数字只抄表：

## 5. 线性近似：将二次复杂度降为线性

线性近似类方法的目标最为宏大：**将自注意力的渐近复杂度从** $O(T^2)$ 彻底降为 $O(T)$. 它们通过数学变换, 将 softmax attention 近似为可以递推计算或矩阵乘法重排的形式.

> 2026-08：「近似 softmax」只覆盖 Performer 那条。Katharopoulos 是 **换核**；Linformer 是 **沿序列投影还留着 softmax**。不要三条揉成一句。

### 5.1 线性注意力(Linear Attention)

#### 5.1.1 核心思想

标准注意力可以写成：

为建立定量关系, 定义如下表达式：

$$
\text{Attn}(Q, K, V)_i = \frac{\sum_j \exp(q_i^T k_j) v_j}{\sum_j \exp(q_i^T k_j)} \tag{7}
$$

此式描述了变量之间的定量关系, 其中每一项对应特定的物理操作.
线性注意力的关键观察是：如果能将 $\exp(q^T k)$ 替换为某个核函数的内积 $\phi(q)^T \psi(k)$, 则分子和分母都可以通过矩阵乘法的结合律重排：

$$
\sum_j \phi(q_i)^T \psi(k_j) v_j = \phi(q_i)^T \underbrace{\left(\sum_j \psi(k_j) v_j^T\right)}_{\text{可增量维护的状态 } S_j} \tag{8}
$$

此式描述了变量之间的定量关系, 其中每一项对应特定的物理操作.
这意味着在自回归生成中, 我们可以维护一个固定大小的状态矩阵 $S_t = \sum_{j=1}^t \psi(k_j) v_j^T$, 每步只需要 $O(1)$ 更新时间和 $O(d^2)$ 内存, 与序列长度无关！

#### 5.1.2 代表方法

* **Linear Transformer**(Katharopoulos et al., 2020)：使用 $\phi(x) = \text{elu}(x) + 1$ 作为特征映射.

* **RWKV**(Peng et al., 2023)：将线性注意力与 RNN 的递推形式深度融合, 配合 channel mixing 和 time mixing, 实现了 Transformer 级别的语言建模能力的同时, 具备了 RNN 的 $O(1)$ 推理复杂度.

#### 5.1.3 局限

* **表达能力损失**：去掉 softmax 的 attention 不再是标准的注意力加权, 其动态范围(dynamic range)受限, 在需要精确定位少数关键 token 的任务上性能下降.

* **数值稳定性**：增量维护 $S_t$ 时, 数值累积误差可能随序列长度增长.

> **2026-08 修订（不删上文）。** Katharopoulos 等人 *Transformers are RNNs*（[arXiv:2006.16236](https://ar5iv.labs.arxiv.org/html/2006.16236)，**ICML 2020** 不是 ICLR）**没有**把 softmax 核分解成有限特征。§3.2.1 写明：指数核对应的特征映射是 **无限维**，精确线性化 softmax 做不到。他们换的是任意非负相似度 $\mathrm{sim}(q,k)$，再要求它写成 **同一个** $\phi$ 的内积 $\phi(q)^\top\phi(k)$，不是式 (8) 里两套 $\phi,\psi$。式 (7) 还漏了论文的 $1/\sqrt{D}$。论文式 (4)–(5)：

$$
V'_i=\frac{\phi(Q_i)^\top\sum_j\phi(K_j)V_j^\top}{\phi(Q_i)^\top\sum_j\phi(K_j)}.
$$

分子状态 $S=\sum\phi(K)V^\top$（外积，形状 $C\times M$），还要单独累加归一化向量 $Z=\sum\phi(K)$。只写 $S$、丢掉 $Z$，输出就不是加权平均。实验用的特征是式 (7) $\phi(x)=\mathrm{elu}(x)+1$（Clevert ELU），维度 $C=D$，复杂度 $\mathcal{O}(NDM)$；选 elu 而不是 relu，是避免 $x<0$ 时梯度被掐死。更长序列他们提过二次多项式核，精确有限维，代价 $\mathcal{O}(ND^2M)$，在 $N>D^2$ 时才划算；主实验没用它。

因果掩码是式 (9)–(12)：$S_i,Z_i$ 由 $S_{i-1},Z_{i-1}$ **对长度 $N$ 常数时间**更新。§3.3.1 还给出分子的常数显存反向（式 13–15，约 200 行 CUDA）。§3.4 把一层写成 RNN：两个隐状态 $s$（注意力记忆）和 $z$（归一化记忆），式 (18)–(20)。每步计算是 $\mathcal{O}(CM)=\mathcal{O}(d^2)$，**不是**对 FLOPs 写 $O(1)$；「常数」指 **不随已生成长度涨**。训练仍可层内并行（整段 ground truth 都在），推理才走 RNN 状态。

**4000× 接在语言模型上会漂。** 摘要「最高约 4000×」来自 **CIFAR-10 逐像素**（Table 2：17.85 vs 0.004 images/sec，**4462×**），序列约 $32\times32\times3$。MNIST Table 1：0.644 vs 0.621 bits/dim，**317×**（142.8 vs 0.45 images/sec）。复制符号任务（最长 128）上 linear 能收到和 softmax 一样的 loss。ASR 是另一回事：WSJ CTC，Linear **PER 8.08**、softmax **5.12**、每 epoch **824s vs 2711s**（约 3×）；线性更快但音素错误更高。合成测时：1080 Ti 11GB 上 softmax 最长 4096，linear 测到 $2^{16}$。没有「64K 吞吐量仍 85%」这张表。RWKV 的 time/channel mixing **不是**这篇论文，勿把 4000× 借过去。文末参考文献写 ICLR 的，改 ICML。

> **2026-08 修订（不删上文）。** Peng 等人 *RWKV: Reinventing RNNs for the Transformer Era*（[arXiv:2305.13048](https://ar5iv.labs.arxiv.org/html/2305.13048)，2023）不是 Katharopoulos 那套 $\phi(q)^\top\phi(k)$，也没有 $4000\times$。名字是 **Receptance Weighted Key Value**。灵感来自 AFT（Zhai et al. 2021）**原文式 (2)**；RWKV 论文自己把那条编号成式 (9)，不要写成「AFT 的式 (9)」。pairwise 的 $w_{t,i}$ 改成 **通道级时间衰减**，才能写成 RNN：

$$
w_{t,i}=-(t-i)w,\qquad w\in(\mathbb{R}_{\ge 0})^{d}.
$$

要求 $w$ 非负，是为了 $e^{w_{t,i}}\le 1$，每个通道往回衰减。Table 1 把推理写成 **时间 $O(Td)$、空间 $O(d)$**；对照 Linear Transformers 的 $O(Td^{2})$ / $O(Td+d^{2})$。摘要里「constant computational and memory complexity during inference」指 **不随已生成长度 $T$ 涨**，不是一步 FLOPs 写成 $O(1)$。§3.2：一层处理一个 batch 仍是 $O(BTd^{2})$，主项是 $W_r,W_k,W_v,W_o$ 那些矩阵乘；WKV 本身是串行扫描 **$O(BTd)$**。本体公式与工业数字在 [2.4.4](../../2.4-前沿架构与变体/2.4.4-线性RNN与Griffin/2.4.4-线性RNN与Griffin.md) / [2.3.3 §4.4](../2.3.3-线性注意力机制/2.3.3-线性注意力机制.md)。本篇只钉和线性注意力容易揉错的几条。

四元组：$R$ 收过去，$W$ 可学衰减，$K$/$V$ 类比注意力。time-mixing 的 $r,k,v$ 都来自 **token shift**（式 11–13）：$\mu\odot x_t+(1-\mu)\odot x_{t-1}$，实现是时间维 `ZeroPad2d((0,0,1,-1))`。WKV 是式 (16)，**逐通道**加权，不是 $r^\top k$：

$$
wkv_t=\frac{\sum_{i=1}^{t-1}e^{-(t-1-i)w+k_i}\odot v_i+e^{u+k_t}\odot v_t}{\sum_{i=1}^{t-1}e^{-(t-1-i)w+k_i}+e^{u+k_t}}.
$$

当前 token 用单独的 bonus $u$，避免把衰减 $W$ 学坏。输出再过 receptance 门和线性层（式 17）：$o_t=W_o\cdot(\sigma(r_t)\odot wkv_t)$。channel-mixing 替代 FFN：平方 ReLU（So et al. 2021 Primer），$o'_t=\sigma(r'_t)\odot(W'_v\cdot\max(k'_t,0)^2)$。

Appendix D 已经把 time-mixing 写成 RNN，**不是 RWKV-5/6 才变成 RNN**。状态是分子 $a$、分母 $b$：

$$
a_t=e^{-w}\odot a_{t-1}+e^{k_t}\odot v_t,\quad b_t=e^{-w}\odot b_{t-1}+e^{k_t},\quad wkv_t=\frac{a_{t-1}+e^{u+k_t}\odot v_t}{b_{t-1}+e^{u+k_t}}.
$$

官方实现再加共享指数 $p_t$ 防 $e^{k}$ 溢出。每层内部状态五段各 $D$ 维（time-mix 输入、channel-mix 输入、$a',b',p$），一共 **$5DL$**；无限精度可丢掉 $p$，剩 $4DL$。这篇论文对应后来叫 **RWKV-4** 的那一档；5/6 的矩阵值状态、7 的动态门控 **不在 2305.13048 里**，不要倒灌。

训练：Pile **330B** token 一 epoch；Adam 无 weight decay、bfloat16；预训练上下文 **1024**。再按 1024→2048（10B）→4096（100B）→8192（100B）加长微调，Fig. 6 上 Pile 测 loss 随上下文下降。六档：169M（12×768）到 **14B**（40×5120），作者写「当时训过最大的稠密 RNN」。对照 Pythia / OPT / BLOOM 的 FLOP 匹配，不跟 Chinchilla / 过训 LLaMA 比。§9：信息被漏斗进一条向量，很长上下文里细账会丢；prompt 顺序更敏感（Appendix L：同一任务 F1 **44.2% → 74.8%**）。未来工作提到对 $wkv$ 做 parallel scan，把那一段降到 $O(B\log T\, d)$，当时没做。

#### 5.1.4 AFT：没有 $QK^\top$，不是 RWKV，也不是核线性化

分类表把线性近似写成 Performer / Linformer / RFA；**AFT 不在那条核路上**。这篇是 Shuangfei Zhai、Walter Talbott、Nitish Srivastava、Chen Huang、Hanlin Goh、Ruixiang Zhang、Josh Susskind（Apple）的 *An Attention Free Transformer*（[arXiv:2105.14103](https://ar5iv.labs.arxiv.org/html/2105.14103)，2021）。不要写成 RWKV，也不要和 NLP 里另一个缩写 **Aggregation Fine-Tuning** 撞名。

§3.1 式 (2)（非因果示意；因果把求和上限改成 $t$）：

$$
Y_t=\sigma_q(Q_t)\odot\frac{\sum_{t'=1}^{T}\exp(K_{t'}+w_{t,t'})\odot V_{t'}}{\sum_{t'=1}^{T}\exp(K_{t'}+w_{t,t'})}.
$$

$Q,K,V$ 仍是线性投影。$\sigma_q$ 默认 **sigmoid**，不是对 $QK^\top$ 做 softmax。$K$ 与 $V$ **逐元素**结合，再和 $\sigma_q(Q)$ 逐元素相乘。$w\in\mathbb{R}^{T\times T}$ 是学出来的 pairwise 位置偏置。式 (3) 把它改写成「每个特征维一条隐式注意力」$a_t^i$，头数等于 $d$，但 **不物化** $n\times n$ 图。

Table 1（只对照他们写得出因果模式的那些）：

| 变体 | Time | Space |
| --- | --- | --- |
| Transformer | $O(T^{2}d)$ | $O(T^{2}+Td)$ |
| Linear Transformer | $O(Td^{2})$ | $O(Td+d^{2})$ |
| Performer（该表写法） | $O(Td^{2}\log d)$ | $O(Td\log d+d^{2}\log d)$ |
| **AFT-simple** | $O(Td)$ | $O(Td)$ |
| **AFT-full** | $O(T^{2}d)$ | $O(Td)$ |
| **AFT-local / AFT-conv** | $O(Tsd)$，$s<T$ | $O(Td)$ |

线性注意力那一档是矩阵点积，复杂度带 $d^{2}$。AFT 的 $K,V$ 是逐元素，AFT-simple 才能写成 $O(Td)$。AFT-full 时间仍二次，省的是 **不存注意力矩阵**。这不是推理状态 $O(d)$ 的 RNN：pairwise $w$ 绑死序列长 $T$，**AFT-full 不能直接当 RNN**。RWKV 把 $w_{t,i}$ 换成 $-(t-i)w$ 才行，见上一节。

四种变体（§3.2）：

- **AFT-full**：完整 $w_{t,t'}$。
- **AFT-local**：窗 $|t-t'|<s$ 里学偏置，窗外 **$w=0$ 不是 $-\infty$**。窗外 key 仍进加权，只是没有学到的偏置。全文强调这和硬切局部 Transformer 不同，**全局连通还在**。ImageNet 上把窗外改成 $-\infty$（指数后权重 0、kernel 7）Top-1 **79.9**，对照默认 AFT-conv **80.8**，掉 0.9。
- **AFT-simple**：$s=0$，无位置偏置。式 (5) 变成 $Y_t=\sigma_q(Q_t)\odot\sum(\mathrm{softmax}(K)\odot V)$，全局池化 + 逐元素，完全去掉点积。
- **AFT-conv**：相对位置 + 权共享。式 (6) 用 depthwise conv（核写成 $\exp(w)-1$）加上全局 $\sum\exp(K)\odot V$。可做成全卷积、可变输入尺寸；分类时去掉 class token 和位置嵌入，末层 GAP。

full/local 的 $w$ 用式 (7) 分解 $w_{t,t'}=u_t^\top v_{t'}$，$d'$ 小（CIFAR 64、ImageNet 128），参数 $2Td'$ 而不是 $T^{2}$。CIFAR Table 3：不分解 **9.6M**/层、训 2.82 测 2.84；分解 **0.6M**、训 2.75 测 **2.74**。AFT-conv 不能这么分解，改用式 (8) 对每个头做标准化再加 $\gamma,\beta$（都初始化为 0）。

实验都在 **8×V100**，插件替换注意力，超参从对照 Transformer 继承。数字只抄表：

#### 5.1.5 Synthesizer：合成对齐矩阵，不是线性复杂度

AFT 相关工作把 **Synthesizer** 和 LightConv、Sinkhorn 并列在「去掉点积」。Sinkhorn 见 §4.3.2：仍做局部 $QK$。这篇是 Yi Tay、Dara Bahri、Donald Metzler、Da-Cheng Juan、Zhe Zhao、Che Zheng（Google Research）的 *Synthesizer: Rethinking Self-Attention for Transformer Models*（[arXiv:2005.00743](https://ar5iv.labs.arxiv.org/html/2005.00743)，**ICML 2021**，PMLR 139:10183–10192）。不要写成 AFT，也不要写成 $O(n)$ 的 Linformer。

§3.1：仍输出 $Y=\mathrm{softmax}(B)\,G(X)$。$G$ 类比 $V$。换掉的是 $QK^\top$，换成合成函数 $S(X)$。点积注意力本身也落进这个框架：$S(X)=F_Q(X)F_K(X)^\top$。

四种合成方式（Table 1）：

| 变体 | $S(X)$ | 条件 | 样本级 | token–token | 每头参数 |
| --- | --- | --- | --- | --- | --- |
| Dot Product | $F_Q(X)F_K(X)^\top$ | 全体 $X_j$ | Local | 有 | $2d^{2}$ |
| Random | $R\in\mathbb{R}^{N\times N}$ | 无 | Global | 无 | $N^{2}$ |
| Fac. Random | $R_1 R_2^\top$，$k\ll N$ | 无 | Global | 无 | $2Nk$（主实验 $k{=}8$） |
| Dense | $W_2\sigma_R(W_1(X_i))$，再投到 $N$ | 只看 $X_i$ | Local | 无 | $d^{2}+dN$ |
| Fac. Dense | 两路投到 $a,b$（$a\times b=N$）再 tile 相乘 | 只看 $X_i$ | Local | 无 | $d^{2}+d(k_1+k_2)$ |

**Dense**（式 1–3）：每个位置独立用两层 ReLU FFN，从 $d$ 投到序列长 $N$，填对齐矩阵的一行。有 token 信息，**没有** pairwise 交互。

**Random**（式 4）：$Y=\mathrm{softmax}(R)G(X)$。$R$ 可训练或 **Fixed**（不训练）。全局一份对齐，所有样本共用。作者写没指望它能跑，结果是强基线。泛化 Raganato 等人 2020 的固定 encoder 图案。

**分解**：Dense 加 $dN$、Random 加 $N^{2}$，长序列难受。Fac. Random 把 $R$ 写成 $R_1 R_2^\top$。**softmax 仍作用在 $N\times N$ 上**，时间不是 $O(Nk)$。和 Linformer 的 $n\times k$ 注意力图不是一回事。长度相关参数按最大长定义、batch 里截断，文里类比可训练位置编码。

**混合**：$\sum\alpha_i S_i$，再 softmax。记号 R / D / V / Fix / FR / FD；`+` 表示混合。正文把 FD 误写成 Factorized random，Table 1 才是准的。

和 AFT / MLP-Mixer 不要揉：

- AFT 式 (2) 是逐元素 $K,V$ 再乘 sigmoid$(Q)$，**没有**对 token 维做 softmax 对齐图。Synthesizer 合成的就是那张图。
- 文内 2021 补记：Random Synthesizer 在长度维乘 $R$，转置之后等价 MLP-Mixer 的 token-mixer。差别是 **softmax 归一化核** + **多头**。MLP-Mixer 是 2021-04；本篇 preprint 2020-05。

#### 5.1.6 LightConv / DynamicConv：核只看当前步，不是 $n\times n$ 点积

Synthesizer 的 C4 对照轴是 **LightConv / DynamicConv**。这篇是 Felix Wu（Cornell，Facebook 实习）、Angela Fan、Alexei Baevski、Yann N. Dauphin、Michael Auli（FAIR）的 *Pay less attention with Lightweight and Dynamic Convolutions*（[arXiv:1901.10430](https://ar5iv.labs.arxiv.org/html/1901.10430)，**ICLR 2019**）。代码在 fairseq。不要写成 CVPR 2020 那篇「一组卷积核再加权」的 Dynamic Convolution，也不要把 Tay 2021 C4 上的 **60%** 接到这篇的 **20%**。

换的是 **自注意力**。解码器里的 **source–target 注意力仍在**（§5.1）。AAN（Zhang et al. 2018）对照：他们解码器用均匀平均，encoder **还留着**自注意力；这篇 encoder/decoder 的自注意力都换成卷积。

**LightConv**（§3）：depthwise 卷积 + 时间维 softmax 归一化 + 每 $d/H$ 个通道绑一组核。$d{=}1024,k{=}7$：普通卷积 $d^{2}k{=}7{,}340{,}032$ 个权重；depthwise $dk{=}7{,}168$；$H{=}16$ 共享后只剩 **$H\times k{=}112$**。同一套核用于所有时间步，窗口固定。模块：输入投 $d\to 2d$、GLU（Dauphin et al. 2017）、LightConv、输出投 $W^O\in\mathbb{R}^{d\times d}$。正则是 DropConnect：训练时按 $p$ 丢掉 $\mathrm{softmax}(W)$ 的项再除 $1-p$。

**DynamicConv**（§4）：在 LightConv 上把核换成 $f(X_i):\mathbb{R}^d\to\mathbb{R}^{H\times k}$，**只看当前步** $X_i$，不是整段上下文。$f$ 是线性层 $W^Q\in\mathbb{R}^{H\times k\times d}$。和自注意力一样会随时间改权重，但没有 $QK^\top$。操作数随长度 **线性**；自注意力二次。去掉 softmax 后训练 **发散**（Table 3 / Appendix A）。Appendix A：$\ell_2$ 归一化 26.8、sigmoid 26.6；无归一 / $\ell_1$ / 平方 / abs 会发散。

短序列实现：把 $W\in\mathbb{R}^{H\times k}$ 扩成带宽矩阵 $BH\times n\times n$ 再 batched GEMM。算法是 $O(nk)$ 的 depthwise，这份实现仍物化 $n\times n$ 带。作者写 dedicated CUDA 会更快。

架构：fairseq 的 Transformer Big（Ott et al. 2018）。每块参数更少，encoder 加到 **$N{=}7$** 对齐参数量。$H{=}16$。核宽按层 **3, 7, 15, 31×4**；解码器顶上三层才是 31。位置用正弦。

实验只抄表。三随机种子，测集用验证 BLEU 最高的那颗。WMT En-De / En-Fr 8×V100；IWSLT 单卡。

- **WMT'14 newstest2014** Table 1。LightConv 202M：En-De **28.9**、En-Fr **43.1**。DynamicConv 213M：**29.7 / 43.2**。Ott et al. 2018 自注意力：**29.3 / 43.2**。Vaswani：**28.4 / 41.0**。摘要「当时 SOTA 29.7」指 En-De。

### 5.2 核方法近似(Kernel Methods)

#### 5.2.1 Performer

Performer(Choromanski et al., 2021)使用随机特征映射(Random Fourier Features)来近似高斯核 $\exp(q^T k)$：

基于前述物理直觉, 给出数学形式：

$$
\exp(q^T k) \approx \mathbb{E}_{w \sim \mathcal{N}(0, I)} \left[ \exp(w^T q - \|q\|^2/2) \exp(w^T k - \|k\|^2/2) \right] \tag{9}
$$

此式将上述直觉形式化, 各项分别对应输入变换、非线性激活与输出生成.
通过采样 $m$ 个随机向量 $w$, 将注意力复杂度从 $O(T^2 d)$ 降为 $O(T m d)$. 当 $m$ 为常数时, 即为线性复杂度.

#### 5.2.2 特点

* 提供了无偏近似保证(unbiased approximation)
* 但随机特征的质量依赖于 $m$ 的大小, 实践中往往需要较大的 $m$ 才能逼近 softmax 的锐利分布

> **2026-08 修订（不删上文）。** 式 (9) 就是 Choromanski 等人 *Rethinking Attention with Performers*（[arXiv:2009.14794](https://ar5iv.labs.arxiv.org/html/2009.14794)，ICLR 2021）**Lemma 1**：softmax 核 $\mathrm{SM}(q,k)\overset{\mathrm{def}}{=}\exp(q^\top k)$ 的 **正随机特征** 无偏恒等式。导语里的「Random Fourier Features 近似高斯核 $\exp(q^T k)$」叠了三件事：高斯核 $\mathrm{K}_{\mathrm{gauss}}$、softmax 核 $\mathrm{SM}$、以及 Rahimi–Recht 的三角 RFF。三者不是同一个东西。$\mathrm{SM}(x,y)=\exp(\|x\|^2/2)\,\mathrm{K}_{\mathrm{gauss}}(x,y)\,\exp(\|y\|^2/2)$；三角特征用 $\sin/\cos$，论文明确说它 **不适合当注意力核**——分数接近 0 时方差爆炸，行归一化 $\mathbf{D}^{-1}$ 还可能出现负对角。FAVOR+ 的名字是 Fast Attention Via **positive Orthogonal Random features**：正特征 $\phi(x)\propto\exp(\omega^\top x-\|x\|^2/2)$，再把各 $\omega$ 正交化（ORF；实验约束 $m\le d$）。双曲版 $\widehat{\mathrm{SM}}^{\mathrm{hyp+}}$ 用 $\cosh$ 再降一点方差。无偏保证的是核/注意力矩阵估计，不是「$m$ 随便取都能复现 softmax 的尖峰」。正文还写过：注意力矩阵可在 $O(L d^2\log d)$ 时间内逼近到任意精度；实用实现仍是 $O(Lmd)$。文末参考文献 **2009.00094** 和副题「for Tabular Data」都是错号错题，以 2009.14794 为准。**同年 ICLR 还有 Hao Peng 等人的 RFA**（[2103.02143](https://ar5iv.labs.arxiv.org/html/2103.02143)）：走 Rahimi–Recht 三角特征 + 先把 $Q,K$ 单位化，不是 FAVOR+ 的正特征。不要把两条揉成「都是 RFF」。见下一节。

#### 5.2.3 RFA：目录表里有、正文一直空着

分类表把 **RFA** 和 Performer、Linformer 并列，上面却没有专节。这篇是 Hao Peng、Nikos Pappas、Dani Yogatama、Roy Schwartz、Noah Smith、Lingpeng Kong 的 *Random Feature Attention*（[arXiv:2103.02143](https://ar5iv.labs.arxiv.org/html/2103.02143)，**ICLR 2021**）。作者不是 RWKV 的 Bo Peng。**2006.11239 是 DDPM**，不要写成 RFA。

和 Performer 是 **并发**（§3.3 引 Choromanski et al. 2020）。两边都用随机特征把 $\exp(\langle\cdot,\cdot\rangle)$ 写成内积，好把注意力变成线性。分歧在特征怎么取：

| | RFA（2103.02143） | Performer FAVOR+（2009.14794） |
| --- | --- | --- |
| 随机特征 | Rahimi–Recht 三角 $\sin/\cos$（式 2），输出维 **$2D$** | **正**特征 $\exp(\omega^\top x-\|x\|^2/2)$，再正交化 |
| 方差对策 | 先把 $Q,K$ **$\ell_2$ 单位化**，再学温度 $\bm{\sigma}$（式 8，重参数化；$w_i$ 本身不训练） | 正特征避免分数接近 0 时方差爆炸；三角 RFF 被 Performer 明确说 **不适合当注意力核** |
| 额外件 | 可选 **RFA-Gate**：因果状态上乘 sigmoid 门，指数忘掉更旧的历史 | 无这套门 |
| 任务面 | LM / 翻译（编解码器）/ 长文本分类 | 蛋白质 MLM 等（RFA 自己的相关工作表述） |

Gaussian 核的恒等式是式 (4)：$\exp(x\cdot y/\sigma^2)=\exp(\|x\|^2/2\sigma^2+\|y\|^2/2\sigma^2)\,\exp(-\|x-y\|^2/2\sigma^2)$，后一项用 Theorem 1 的 $\phi(x)\cdot\phi(y)$ 无偏估计。单位化之后注意力变成式 (5)：

$$
\mathrm{RFA}(q_t,\{k_i\},\{v_i\})=\frac{\phi(q_t)^\top\sum_i\phi(k_i)\otimes v_i}{\phi(q_t)\cdot\sum_j\phi(k_j)}.
$$

因果时状态是 $(S_t\in\mathbb{R}^{2D\times d},\,z_t\in\mathbb{R}^{2D})$（式 6），和 Linear Transformer 的 $(S,Z)$ 同构，只是 $\phi$ 换成三角 RFF。RFA-Gate 把更新改成式 (7)：$S_t=g_t S_{t-1}+(1-g_t)\,\phi(k_t)\otimes v_t$，分母 $z$ 同样乘 $g_t$。这套门 **不好直接接到满 softmax 上**（没有「上一步隐状态」）。参数增量 **不到 0.1%**。另有一阶 arc-cosine 核：$\phi_{\arccos}$ 用 ReLU，同样 $D$ 时特征长度是 Gaussian 的一半。

实验数字只抄表，不把 12× 接到语言模型上：

- **WikiText-103**（块长 512，特征 64 维）：无门 RFA-Gaussian 仍略差于 Base（大模型测集 **27.5 vs 26.2**）；**RFA-Gate-Gaussian 测集 25.0**，小模型 **32.7 vs 34.5**。$\phi_{\mathrm{elu}}$（Katharopoulos）大模型 **30.2**。把 $(S,z)$ 传到下一个 minibatch 的 stateful 变体再降到 **23.5**。512 长度 **没有加速**，训练大约慢 15%（特征映射开销）。
- **翻译**：编码器仍用 softmax，解码器因果 + 交叉用 RFA（交叉 $D{=}128$、因果 $D{=}64$）。WMT14 EN–DE Base **28.1**、RFA-Gaussian **28.0**、$\phi_{\mathrm{elu}}$ **21.3**。单卡 TPU v2、batch 32，解码 **1.8–1.9×**（摘要「约 2×」）。门控在翻译上几乎不加分。
- **LRA 三条**（Table 3，数字来自 Tay et al. 2021 的对照）：RFA-Gaussian 平均 **53.0** vs Transformer **52.7** vs BigBird **53.1**；IMDb **66.0**。4K 上相对 Transformer 速度 **5.3×**、显存 **0.16**。Performer 那行平均只有 **45.7**（ListOps 18.0）。
- **12×**：§5 模拟条件生成，输入输出等长 **2048**，greedy、batch 16、TPU v2，相对缓存了 QKV 的 softmax 基线；显存不到 10%。不是 2006.16236 的 CIFAR 4000×。

§3.4：交叉注意力省显存的条件是 $2D\ll M$；$D$ 通常 **不小于头维 $d$**（约 64/128）。主实验 $D\in\{d,2d\}$，再加大边际很小。无门 RFA **不是** softmax 的逐点逼近：用一种注意力训、换另一种评，几乎掉到随机初始化（Appendix C.3）；从预训练 softmax 微调到 RFA 倒还能降 loss（C.4）。

### 5.3 低秩近似

#### 5.3.1 Linformer

Linformer(Wang et al., 2020)观察到注意力矩阵 $P = \text{softmax}(QK^T/\sqrt{d})$ 往往是低秩的. 因此可以引入投影矩阵 $E, F \in \mathbb{R}^{k \times T}$($k \ll T$), 将 $K, V$ 投影到低维：

$$
\text{Attn}(Q, K, V) = P \cdot V \approx \text{softmax}\left(\frac{Q (EK)^T}{\sqrt{d}}\right) (FV) \tag{10}
$$

此式将上述直觉形式化, 各项分别对应输入变换、非线性激活与输出生成.
复杂度降为 $O(T k d)$.

#### 5.3.2 局限

* 投影矩阵 $E, F$ 是全局共享的, 难以适应不同层、不同头对序列长度的不同需求
* 在低资源语言或长尾分布数据上, 低秩假设可能不成立

> **2026-08 修订（不删上文）。** Wang 等人 *Linformer*（[arXiv:2006.04768](https://ar5iv.labs.arxiv.org/html/2006.04768)）要压缩的是 **序列维**，不是头维。默认 **每个头一对** $E_i,F_i$，并不是一上来就全局共享。可选三级共享：层内头共享（12 层模型 24 个矩阵）、再加 KV 共用（12 个）、整网一层共用（**1** 个）。Figure 3(c)：单矩阵 layerwise 的 MLM PPL 几乎贴上不共享；Table 2 里 $n{=}512,k{=}256$ 再 layerwise 的下游平均 **92.30**，对照同语料 RoBERTa-base **92.25**。低秩观察针对的是 $n\times n$ 的 softmax 映射 $P$：RoBERTa 在 Wiki103/IMDB、$n{=}512$ 上奇异值长尾，高层更斜（Figure 1）。Theorem 1 说存在秩 $\Theta(\log n)$ 的逼近；他们 **不做每步 SVD**（太贵），改沿序列做线性投影。

## 6. 压缩高效：让 KV Cache 瘦身的艺术

压缩高效类方法不改变注意力的计算图, 而是减少**每个 token 的 KV 表示所占用的空间**. 这在推理阶段(尤其是自回归解码)具有决定性的工程价值, 因为此时计算量通常不是瓶颈, 显存才是.

### 6.1 MQA 与 GQA：头间共享的离散压缩

已在《MLA 专题》中详述, 此处总结其核心特征：

* **MQA**：所有头共享 1 组 K/V. 压缩比最高($H$ 倍), 但表达能力受损.

* **GQA**：头分为 $G$ 组, 组内共享. 压缩比为 $H/G$, 是主流大模型(Llama, Mixtral)的默认选择.

### 6.2 Cross-Layer Attention (CSA) / Hierarchical Cross-Attention (HCA)

更激进的压缩思路是**跨层共享 KV Cache**：

* **CSA**：每隔 $n$ 层才计算和缓存 K/V, 中间层直接复用邻近层的 KV.

* **HCA**：在层次化架构中, 底层使用高分辨率(完整序列)的注意力, 上层使用低分辨率(压缩序列)的注意力.

这些方法将 KV Cache 的层间冗余也挖掘出来, 但实现复杂度高, 且对模型架构有侵入性修改, 目前尚未被主流开源模型广泛采用.

> **2026-08 修订（不删上文）。** 上面两个英文展开在本花园里 **都不是** DeepSeek 报告里的词。V4 的 CSA / HCA 是 **Compressed Sparse Attention** 和 **Heavily Compressed Attention**，沿 **序列** 压缩 KV，不是隔几层复用。本体在 [07 CSA-HCA](../2.3.2-稀疏与压缩注意力/07-CSA-HCA-混合压缩注意力/07-CSA-HCA-混合压缩注意力.md)：CSA = 块压缩 + DSA top-k + 滑窗未压缩 KV；HCA = 更大压缩比后仍做 **稠密** 注意力。摘要：混合架构服务 1M 上下文。不要把 HCA 读成 Hierarchical Cross-Attention，也不要和 mHC / xHC 混名。

2025 段描述的「每隔几层才算 KV」更接近 **Cross-Layer Attention（CLA）** 这条独立积木。Hunyuan-Pro 公开材料 Table 2：CLA **每 2 层**共享 KV，和 GQA 叠在一起号称相对 MHA 的 KV 大约降 **95%**（D2：[01-01](../../../14-主流开源模型全景解析与技术报告精读/14.20-Hunyuan/01-Hunyuan-Pro/01-01-Hunyuan-Pro-架构精译.md)）。CLA ≠ CSA。分类表第 4 行的 CSA/HCA 按 V4 读；跨层共享请写 CLA。

### 6.3 MLA：特征维度的低秩压缩

MLA(Multi-Head Latent Attention)通过将 K/V 投影分解为低秩乘积, 将每 token 的 KV Cache 从 $O(H \cdot d_h)$ 压缩到 $O(d_c)$, 同时通过可学习的解压矩阵为每个头保留自适应的表示能力. 关于 MLA 的完整推导、数值走查和代码实现, 请参阅本知识库的《MLA 专题》.

![MHA, MQA, GQA, MLA 的每 Token KV Cache 显存占用与信息构成对比](images/kv_cache_compression_comparison.png)

> **图 6.1 MHA、MQA、GQA 与 MLA 架构的 KV Cache 显存占用与信息构成对比分析**
>
> * **MHA(Multi-Head Attention, 多头注意力)**：每个 Query 头 $Q^{(h)}$ 拥有各自独立的 Key 头 $K^{(h)}$ 和 Value 头 $V^{(h)}$. 对于 32 个头, 每一步解码生成都必须为 32 对 K/V 向量分配和读写 Cache.
> * **MQA(Multi-Query Attention, 多查询注意力)**：所有的 Query 头共享唯一的一对 Key 头 $K$ 和 Value 头 $V$. KV Cache 显存开销降为 MHA 的 $1/H$(如 32 倍压缩), 但注意力表达能力大幅缩水, 易损失长文精度.
> * **GQA(Grouped-Query Attention, 分组查询注意力)**：介于两者之间, 将 Query 分为 $G$ 个组(如 8 组), 每组内的 Query 头共享一对 K/V. KV Cache 显存开销为 GQA 组数比例, 兼顾了吞吐量与精度的帕累托最优.
> * **MLA(Multi-Head Latent Attention, 多头潜在注意力)**：通过引入低秩压缩空间, 将 K/V 投影解耦. 所有头通过低秩隐空间矩阵进行动态映射和解压. 它在物理上只存储低维的 Latent 向量(达到 8 倍以上的 Cache 压缩比), 但在计算时能通过解压矩阵为每个注意力头还原出独有的完整维度, 完美融合了 MQA 的高吞吐量与 MHA 的高表达能力.

## 8. 工程选择指南：如何为场景匹配合适的方法

高效注意力的选择不是单选题, 而是一道**多目标优化题**. 以下决策流程基于工业界部署 LLM 的实践经验总结.

### 8.1 决策树

```
开始
│
├─ 训练阶段？
│  └─ 是 → 序列长度 <= 8K？
│     ├─ 是 → 标准 MHA + FlashAttention-2/3(精确且高效)
│     └─ 否 → 序列长度 <= 128K？
│        ├─ 是 → GQA/MLA + FlashAttention-2(平衡精度与内存)
│        └─ 否 -> 局部窗口 + 全局 token / BigBird(必须牺牲部分全连接能力)
│
└─ 推理阶段？
   ├─ batch size 极小(在线服务, bs=1)？
   │  └─ 是 → 瓶颈在 prefill 计算 → FlashAttention + GQA
   │  └─ 否 → 瓶颈在 decode KV Cache → MLA + PagedAttention(最强组合)
│
   ├─ 精度要求极高(数学证明、科学计算)？
   │  └─ 是 → 避免线性近似和激进量化, 使用 FlashAttention + GQA
   │  └─ 否 → 可尝试 SageAttention(FP8)进一步压榨硬件
│
   ├─ 序列长度极度夸张(>200K, 如整本书、基因组)？
   │  └─ 是 → 线性注意力(RWKV)或 稀疏窗口(Longformer)
   │  └─ 否 → 优先考虑 MLA 或 GQA 的压缩方案
│
   └─ 硬件为最新代(H100/RTX 4090)？
      └─ 是 → FlashAttention-3；SageAttention 是 INT8 路径（见 §3.3），不要写成 FA3 FP8
      └─ 否(A100/V100)→ FlashAttention-2 + GQA/MLA
```

> **2026-08**：树上「线性注意力(RWKV)」把 2006.16236 和 2305.13048 揉在一起。AFT（[2105.14103](https://ar5iv.labs.arxiv.org/html/2105.14103)）是 RWKV 祖先，pairwise $w$ **不是** RNN；线性注意力逐步仍 $\mathcal{O}(d^2)$。见 §5.1 / §5.1.4。

### 8.2 典型场景配方

| 场景                      | 推荐组合                                  | 理由                                                           |
| ----------------------- | ------------------------------------- | ------------------------------------------------------------ |
| **通用 LLM 预训练**(<32K)    | FlashAttention-2 + GQA                | 精确、成熟、生态完善                                                   |
| **超长上下文 API 服务**(128K+) | MLA + PagedAttention + FlashAttention | MLA 压缩 Cache, PagedAttention 管理碎片, FlashAttention 加速 prefill |
| **边缘设备部署**(手机/NPU)      | 线性注意力 或 局部窗口 ($w=512$)                | 线性注意力省显存, 局部窗口易实现且兼容现有 kernel                                |
| **多轮对话系统**(动态长度)        | PagedAttention + GQA                  | 分页管理避免碎片, 动态长度支持好                                            |
| **金融/法律长文档分析**          | BigBird 或 局部窗口 + 全局 CLS token         | 需要在超长序列中保持对关键段落的精确定位                                         |
| **代码大模型**               | GQA + FlashAttention                  | 代码对位置精度敏感, 避免解耦 RoPE 和激进稀疏                                   |
| **推理模型(如 DeepSeek-R1)** | MLA + 定制 CUDA kernel                  | 思维链极长, KV Cache 是头号瓶颈, MLA 的压缩比不可替代                          |

### 8.3 组合使用的注意事项

多种高效注意力技术可以叠加, 但叠加时需注意兼容性问题：

1. **FlashAttention + PagedAttention**：天然正交. vLLM 已内置 FlashAttention kernel 作为后端.

2. **FlashAttention + MLA**：需要修改 FlashAttention 的 tile 计算逻辑, 因为 MLA 的 K/V 不是直接读取而是解压得到. DeepSeek 开源了适配 MLA 的定制 kernel.

3. **稀疏注意力 + PagedAttention**：困难. 稀疏模式破坏了序列的局部连续性, 导致分页的 block 利用率下降.

4. **线性注意力 + PagedAttention**：无意义. 线性注意力不需要 KV Cache, Paging 机制无用武之地.

5. **量化(SageAttention/GPTQ)+ MLA**：需谨慎. 低秩解压矩阵对量化误差可能比满秩矩阵更敏感, 需做充分的精度验证.

***

## 9. 未解之谜与未来方向

高效注意力领域仍有许多开放问题等待探索：

### 9.1 理论极限：注意力的压缩下界在哪里

MLA 将 KV Cache 压缩了约 8 倍, 线性注意力将其降为 $O(1)$. 但信息论告诉我们, 压缩极限取决于任务所需的最小充分统计量. 对于通用语言建模, 这个下界究竟是多少？是否存在一个不可逾越的"注意力熵"阈值？

### 9.2 硬件-算法的协同设计

当前的 FlashAttention 系列是针对 NVIDIA GPU 的 SRAM/HBM 层次手工调优的. 随着 Cerebras、Groq、SambaNova 等专用 AI 芯片的兴起, 注意力 kernel 的设计空间将被重新定义. 未来的高效注意力算法可能需要与芯片架构联合设计(co-design), 而非事后适配.

### 9.3 内容自适应的动态稀疏

现有稀疏注意力的模式(窗口、膨胀、随机)大多是静态的. 理想情况下, 模型应在推理时根据输入内容动态决定"该看哪里"——这需要极轻量的 routing 机制, 且不能引入过高的额外计算. 学习型稀疏(如 Reformer 的 LSH)是初步尝试, 但距离实用化尚有距离.

> 2026-08：LSH 的哈希是随机投影，**不是**学出来的 router。内容相关只体现在「相近 $q$ 进同一桶」。可学习路由见 Routing Transformer（球面 $k$-means、质心 EMA、复杂度 $O(n^{1.5}d)$），不要写「Reformer 的 LSH」。Routing 也不是 MoE 专家门控：query 被路由到 **同簇的 key**，不是路由到 FFN 专家。Sparse Sinkhorn（2002.11296）是第三条：学 **块级置换** $R$，排完仍做局部 $QK^\top$，**不是**去掉点积，也不是 mHC 把 $\mathcal{H}^{\mathrm{res}}$ 投到双随机矩阵。Star-Transformer（1902.09113）是 **固定**星拓扑（环 + 一个中继），不是学习路由，也不是 BigBird 后来用来证明 UA 的「$O(1)$ 个全局 token」。NVIDIA Star Attention（2411.17116）是 **推理期**两阶段块稀疏，相对 Ring 加速，**不是** 2019 那套编码器。

### 9.4 状态空间模型(SSM)与注意力的融合边界

Mamba 系列展示了线性复杂度序列建模的强大潜力, 但其在长程检索任务上的精度仍略逊于 Transformer. 未来的架构可能不是"注意力 vs SSM"的二选一, 而是两者的自适应混合：在需要精确定位的局部使用注意力, 在需要全局感知的层次使用 SSM. 如何设计这种混合的训练目标和推理效率, 是一个极具潜力的研究方向.

***

## 10. 总结

高效注意力机制不是单一的技术, 而是一个包含多条演进主线的庞大生态. 本文将其归纳为四大类：

* **硬件高效**：不改变数学定义, 通过 IO 优化和内存管理让标准注意力跑得更快(**MEA**、FlashAttention、PagedAttention)
* **稀疏高效**：利用注意力矩阵的稀疏性, 跳过不重要的计算(局部窗口、BigBird、Star-Transformer、NVIDIA Star Attention、Sparse Sinkhorn)
* **线性近似**：通过数学变换将二次复杂度降为线性(线性注意力、Performer)
* **压缩高效**：减少每个 token 的 KV 表示维度, 降低推理显存(MQA、GQA、MLA)

没有哪一种方法是银弹. **MEA** 是 2021 年「精确注意力不需要 $O(n^2)$ 显存」的算法；**FlashAttention** 是其后 GPU 训练/Prefill 的 IO 核, 不要把两篇写成一篇; **PagedAttention** 是推理服务的内存管理基石; **GQA** 是通用大模型压缩 KV Cache 的稳妥选择; **MLA** 是长上下文极限压缩的最优解; **线性注意力/SSM** 则是追求极致复杂度下界的前沿探索.

工程师在选择时, 应当回到三个根本问题：

1. **我的瓶颈是计算、显存, 还是带宽？**
2. **我的序列长度和 batch size 在什么量级？**
3. **我对精度损失的容忍度有多高？**

回答清楚这三个问题, 高效注意力的"全景图"就将自动坍缩为一张清晰的工程路线图.
