# 04.0 · MLA 作为 KV 表示压缩入口

MLA(Multi-Head Latent Attention)把推理时要缓存的 KV **从满秩头向量换成低维潜向量** $c^{KV}$(外加解耦 RoPE 键 $k^{R}$).它卡住的瓶颈是 **每 token 的 KV 字节**,不是 $N\times N$ 注意力核怎么在 SRAM 里跑.

公式,解耦 RoPE,坐标展开与数值走查在 [04-MLA 主文](../04-MLA-低秩潜变量与矩阵吸收.md).Prefill 非吸收 / Decode 吸收两套图是否代数等价,在 [04.1 矩阵吸收双版本](../04.1-矩阵吸收与非吸收双版本/04.1-矩阵吸收与非吸收双版本.md).本页只回答一件事:**MLA 为什么放在 2.2.2 而不是 2.3**--它改的是 KV **表示**,FlashAttention / 稀疏 / 线性改的是注意力 **算子**.

不是专栏转写,也不是把第 05 章 DeepSeek 型号正本再抄一遍.

## 1. 表示 vs 算子

| 子专题 | 改什么 | 不改什么 |
|--------|--------|----------|
| 2.3.1 FA / Paged | 核 IO,分页块表 | Q/K/V 仍是 MHA 形对象 |
| 2.3.2 稀疏 | 连哪些边 | 选中的边仍是 softmax 注意力 |
| 2.3.3 线性 | 核函数 / 递推状态 | 不是低秩 KV cache |
| **2.3.5 MLA** | **cache 里存什么** | 训练时仍是多头;核可以仍走 FA |

2.3 的前四块都在问「同样的 $QK^{\top}$,怎么少搬,少连,少平方」.MLA 问的是另一句:**推理时是否必须缓存与训练时同形的高维 $k_t,v_t$?** DeepSeek-V2 的答案是不必--联合压到 $c^{KV}$,只 cache $c^{KV}$ 与 $k^{R}$.

![MLA:只缓存潜向量 $c_{KV}$,注意力前再重建 K/V](./images/redrawn-fig-mla-kv-latent-cache.png)

> 图 1:缓存的是 $c_{KV}$,不是满秩 K/V.下投影 $W^{DKV}$,上投影 $W^{UK}/W^{UV}$ 的矩阵式见 [04 式与图 2](../04-MLA-低秩潜变量与矩阵吸收.md).

**图 1 解析**

- 左:$h_t$ 经 $W^{DKV}$ 进入虚线框 **Latent Cached**.
- 框内只有 $c_{KV}$:decode 持久化的是这一截,不是每头一份 $k,v$.
- 右:算分前再升维出 $K_t,V_t$,与 $Q_t$ 做 Attention.升维可以显式做(非吸收)或吸进 Q/O(吸收),分叉在 [04.1](../04.1-矩阵吸收与非吸收双版本/04.1-矩阵吸收与非吸收双版本.md).

### 1.1 复现时最容易踩的坑：为什么“MLA 怎么根本不省资源？”

很多人第一次复现 MLA 时都会遇到同一句话:「我靠,MLA 怎么根本不省资源？」我也犯过这个常见错误.这句话通常不是在否定 MLA,而是在提醒你**把缓存占用、临时工作区、权重占用、Prefill 峰值和 Decode 常驻 KV 混成了一个数字**.

社区里的复现反馈正好能把问题拆开:

- [ik_llama.cpp 的 MLA matrix absorption 讨论](https://github.com/ikawrakow/ik_llama.cpp/discussions/599)把三种实现放在一起比较:compressed cache 的字节数可以很小,但如果不做吸收、先把 latent 解压成完整 K/V,计算和中间张量会反过来拖慢运行;吸收后主要改善的是解压/搬运路径和计算量.
- [llama.cpp 的 MLA + FlashAttention 实现反馈](https://www.reddit.com/r/LocalLLaMA/comments/1kmrfoo/mla_optimization_with_flashattention_for/)展示了另一个容易忽略的事实:真正启用专用实现后,缓存可以只保留 K 一侧,实测长上下文占用会明显下降;这不是“画公式”自动发生的,而是后端真的没有把完整 V/K 展开后长期驻留.
- [sglang-jax 的 MLA backend 说明](https://github.com/sgl-project/sglang-jax/blob/main/docs/architecture/06-layers-and-attention.md)明确区分 absorbed MLA 与 non-absorbed fallback:前者缓存 latent + RoPE,后者会解压为完整 K/V,缓存规模可大很多.所以同一个 MLA 模型换后端,显存数字完全可能不一样.
- [LocalLLaMA 对 MLA/V4 KV 数字的讨论](https://www.reddit.com/r/LocalLLaMA/comments/1svzlog/the_exact_kv_cache_usage_of_deepseek_v4/)还提醒:DSA indexer、RoPE 侧的额外状态、FP16/FP8 精度、层数和批量都会改变总账.社区帖里的具体数字存在口径争议,只能用来定位变量,不能直接当通用常数.

**更本质的解释:**MLA 节省的根因是**改变每个历史 token 的持久化表示**.标准 MHA 要为每个 token、每个 head 长期保存完整 K/V;MLA 把它们联合压进共享的低维 $c^{KV}$,另存解耦的 $k^{R}$,因此 Decode 时每层每 token 的常驻状态从 $2n_hd_h$ 变成约 $d_c+d_h^{R}$.这是缓存字节下降的来源.

**矩阵吸收是什么:**它只是把上投影 $W^{UK},W^{UV}$ 的计算重新安排到 Q/O 两侧,从而减少显式解压、临时完整 K/V 和部分通信/带宽压力.把“因为矩阵可以吸收,所以 MLA 才省显存”当成根因是不准确的,甚至会把实现层和表示层倒置:即使不吸收,只要系统确实把 latent 作为持久 KV cache,常驻缓存仍然可以变小;反过来,如果 fallback 先解压并缓存完整 K/V,你就会看不到这项收益.而且吸收并非无条件更省:在训练或不合适的 fused/eager 路径里,吸收中间量可能变大,省下的是通信/解压路径,不一定是峰值显存.

因此复现 MLA 时要分三笔账:

1. **常驻 Decode KV**:只看真正写入 cache 的 $c^{KV}$ 与 $k^{R}$,这是 MLA 的核心收益.
2. **临时工作区与后端**:确认走 absorbed MLA 专用 kernel,还是 non-absorbed MHA/FlashAttention fallback;后者可能暂时展开完整 K/V.
3. **总 GPU memory**:另行扣除权重、激活、workspace、indexer、通信 buffer 和 allocator 预留.总显存没有按宣传比例下降,不等于 MLA 的 KV 表示没有压缩.

## 2. 不是 MQA

MQA 把 KV **份数**收到 1,cache 里仍是满维 $d_h$ 的 $k,v$.MLA 把 KV **维度**收到 $d_c$,cache 里是更短的 $c^{KV}$ 外加解耦的 $k^{R}$;多头还在,体现在 $W^{UQ}$ 与 per-head 打分.GQA 是份数插值($G$ 组),压缩比被组数锁死.

| 机制 | 压缩手段 | 每 token cache(量级) |
|------|----------|------------------------|
| MHA | 无 | $2 n_h d_h$ |
| MQA | 份数 → 1 | $2 d_h$ |
| GQA | 份数 → $G$ | $2 G d_h$ |
| MLA | 维度 → $d_c$ | $d_c + d_h^{R}$ |

![MHA、MQA、GQA 与 MLA 的直接结构对照](./images/redrawn-fig-mla-archive-analogy.png)

> 图 2:直接对照 MHA、MQA、GQA、MLA 的 Q/K/V 头共享关系、缓存内容与每 token 缓存规模.

**图 2 解析**

- MHA:每个 Query 头对应独立的 K/V 头,缓存规模最大.
- MQA:所有 Query 头共享一对 K/V;GQA:按组共享 K/V,两者都在图中单独列出.
- MLA:缓存低维 $c^{KV}$ 与解耦位置键,attention 前通过上投影还原各头 K/V,不把完整 K/V 写入 cache.

短序列上低秩变换的固定开销可能划不来;RoPE 必须解耦,否则位置旋转会挡住矩阵吸收.这些边界的公式仍在 04 / 05,这里不重推.
