# 2.2.2 · 多头注意力变体

[2.2.1 自注意力机制](../2.2.1-自注意力机制/2.2.1-自注意力机制.md) 算的是单个头. 把头数加到 $H$ 之后, 训练时的开销仍以序列长度的平方项为主, 自回归推理的开销却换了地方: Decode 每步只有一行 Query, 却要读出全部历史 token 在每一层, 每个头上的 Key 和 Value. 这一节五篇文章都围绕这份缓存展开. MHA 定下缓存的基准量; MQA, GQA 减少缓存的份数; MLA 保留份数, 把每份压成一个低维潜变量; Gated Attention 不动缓存, 改的是 SDPA 输出与输出投影之间那一段.

## 1. 参照系: MHA 的缓存与 Decode 的带宽

### 1.1 每 token 每层缓存多少

记层数 $N$, batch $B$, 序列长度 $T$, Query 头数 $H$, 每头维度 $d_h$, 每元素 $s$ 字节. MHA 每个 token 在每层每个头存一个 $d_h$ 维 Key 和一个 $d_h$ 维 Value, 每层每 token 缓存 $d_{kv}=2Hd_h$ 个元素, 全模型

$$
\text{KV Cache 字节数}=N\times B\times T\times d_{kv}\times s \tag{1}
$$

[01 MHA](./01-MHA-多头注意力的标准形式/01-MHA-多头注意力的标准形式.md) 第 4.2 节以 Llama-2-7B ($N=32$, $H=32$, $d_h=128$, FP16) 代入: 每 token 512 KiB, 一条 4096 token 的序列 2 GiB. 7B 模型的 FP16 权重约 13 GB, 只够放 6 条这样的序列的缓存. 后面四篇都用式 (1) 作对照, 区别只在 $d_{kv}$ 取什么.

式 (1) 对 $B$ 和 $T$ 都是线性的. 这一点和 Prefill 的平方项不同: Prefill 并行处理整段 prompt, 开销以 $T^2d$ 的打分乘加为主, 受算力限制; Decode 的开销以读缓存为主, 受显存容量和带宽限制. MQA, GQA, MLA 几乎不改变 Prefill 的计算量, 改的是每个 token 写进缓存多少, 每步读出多少.

### 1.2 为什么 Decode 卡在带宽

Shazeer (2019) §2.4.1 给出了 MHA 逐步解码的访存与计算之比 $\Theta(n/d+1/b)$, $n$ 是生成长度, $d$ 是隐藏维, $b$ 是 batch. $1/b$ 一项可以靠加大 batch 压下去, $n/d$ 一项来自每步重读形状为 $[b,H,n,d_h]$ 的 $K$ 和 $V$, 序列一长就接近 1. 换成单步看: 第 $t$ 步每层每个头读 $t\times d_h$ 的 $K$ 和 $V$, 每读一个缓存元素只做一次乘加, 而现代加速器的算力比显存带宽高约两个数量级.

加大 batch 能摊薄权重读取, 摊不薄缓存读取, 因为每条序列的缓存各读各的. 01 第 4.3 节算过, batch 开到 32 条 4096 长度的序列时, Llama-2-7B 每步要读 64 GiB 的 KV, 是权重读取量的约 5 倍. 所以减少 $d_{kv}$ 同时改善两件事: 同样显存能放下的序列数, 以及每步 Decode 要搬的字节数.

## 2. 两条压缩轴: 份数与每份的维度

### 2.1 MQA 与 GQA: 减少份数

[02 MQA 与 GQA](./02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md) 处理的是份数. MQA 让所有 Query 头共用一组 $K, V$, $d_{kv}$ 从 $2Hd_h$ 降到 $2d_h$, 每读一个缓存元素做 $H$ 次乘加. Shazeer 2019 的 WMT14 英德实验里, 解码器逐 token 生成从 46 μs 降到 3.8 μs, 训练和编码器几乎不变, 因为后两者是并行计算, 带宽本来不是瓶颈. GQA 把 $H$ 个 Query 头分成 $G$ 组, 每组共用一组 $K, V$, $d_{kv}=2Gd_h$. $G=H$ 时是 MHA, $G=1$ 时是 MQA, 组数是一条连续的轴; 张量并行度为 $P$ 时, $G$ 取 $P$ 的整数倍可以让每张卡分到整数个组, 不复制 K/V.

GQA 论文还给出了从 MHA 检查点转换的做法: 把同组的 Key/Value 投影矩阵平均池化, 再用原预训练配方 uptrain 约 5% 的步数. Llama 2 的 34B, 70B 和 DeepSeek LLM 67B 都用 GQA-8, Llama 2 70B 上 GQA-8 省下 MHA 缓存的 87.5%. GQA 和 MQA 只改份数, 每份仍是完整的 $d_h$ 维.

### 2.2 GQA 的质量损失取决于设置

GQA 论文的主实验是在编码器-解码器的 T5 上 uptrain, GQA-8 与 MHA 的平均分只差约 0.1. 换成从头训练的 decoder-only 模型, 差距明显变大. DeepSeek-V2 附录 D.1 的 7B 稠密模型各训练 1.33T token, MMLU 上 MHA 45.2, GQA-8 41.2, MQA 37.9; C-Eval 上 GQA-8 比 MHA 低 5.2 个点. Llama 2 附录 A.2.1 的 30B 对照 (各 150B token, 前馈层加宽以对齐参数量) 结论偏向 GQA: 多数评测与 MHA 相当, MQA 平均略低.

这三组实验的模型结构, 训练方式和评测集都不同, 放在一起只能说明「GQA 质量接近 MHA」依赖设置. DeepSeek-V2 正是以自己那组结果为理由, 去找一种缓存比 GQA 小而质量不低于 MHA 的结构. 02 第 4.3 节把三组数字和各自的范围并排列出. 速度一侧也要看具体配置, 02 第 3.2 节用 70B 规模的配置算过: $T=4096$, batch 为 1 时权重读取占大头, GQA-8 和 MQA 在总访存里只差 1% 左右; batch 加到 32, MHA 每步的缓存读取达到 320 GiB, 超过权重本身.

### 2.3 MLA: 压缩每份的维度

[03 MLA](./03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md) 走另一条轴. MHA 每个 token 的 $2Hd_h$ 个 Key/Value 元素都由同一个 $d$ 维隐藏状态线性算出, DeepSeek-V2 里 $2Hd_h=32768$ 而 $d=5120$, 本来就有冗余. MLA 引入一个 $d_c$ 维的瓶颈, 让每个头的 Key 和 Value 都由这个潜变量 $c^{KV}$ 上投影得到, 缓存只存 $c^{KV}$. 低秩压缩和 RoPE 冲突: 内容 Key 带位置旋转时, 上投影矩阵无法合并进 Query 一侧. 解法是另开一段 $d_h^R$ 维的通道专门承载 RoPE, 所有头共享一个 RoPE Key. DeepSeek-V2 取 $d_c=512$, $d_h^R=64$, 每层每 token 缓存 576 个元素, 同头数的 MHA 要 32768 个, 论文表 1 的说法是相当于 $G=2.25$ 的 GQA.

缓存小了, 注意力仍需要每个头的 Key 和 Value. [04 MLA 矩阵吸收与工程实现](./04-MLA-矩阵吸收与工程实现/04-MLA-矩阵吸收与工程实现.md) 推导两种算法: 不吸收时把全部历史潜变量上投影成 128 个头再做 MHA; 吸收时利用结合律把上投影挪到 Query 和输出一侧, 每个头读同一份 576 维的「Key」和 512 维的「Value」, 形态与 MQA 相同. 两者数学上等价, 计算量差别很大: Decode 每步只有 1 个新 token, 历史 4096 个时不吸收的乘加是吸收的 117 倍; 无历史的 Prefill 则是吸收更贵. vLLM 按 Prefill 和 Decode 切换算法, FlashMLA 的 Decode 内核走吸收路径.

### 2.4 缓存数字的口径

DeepSeek-V2 摘要里「KV Cache 减少 93.3%」是相对 DeepSeek 67B (GQA-8, 95 层) 算的, 并且 V2 部署时 KV 平均量化到 6 bit. 03 第 4.6 节按元素数重算, MLA 结构本身的贡献是 $34560/194560=17.8\%$, 也就是减少约 82%, 剩下的部分来自 KV 量化. 同理, 论文报告的生成吞吐 5.76 倍是 MLA, MoE, FP8 权重和 KV 量化共同作用的结果.

这条口径也适用于其他方法的比较. MLA 压缩的是每份的维度, 减少位置数的方法 (滑动窗口, 稀疏注意力) 和减少每个元素位数的方法 (KV 量化) 与它正交, 可以叠加, 但叠加后的总压缩率不能当作单一结构的效果. 已有的 MHA/GQA 检查点也不能直接换成 MLA, 结构变了就需要训练, 这一点和 GQA 的 uptrain 转换不同.

## 3. 变体对照与 SDPA 输出门

### 3.1 五种结构放在一张表里

| 变体 | 改动在哪一截 | 每层每 token 缓存 $d_{kv}$ | 从 MHA 检查点得到 | 文章 |
|:----|:------------|:------------------------|:-----------------|:-----|
| MHA | 每个头独立的 $K, V$ | $2Hd_h$ | — | [01](./01-MHA-多头注意力的标准形式/01-MHA-多头注意力的标准形式.md) |
| MQA | $K, V$ 投影去掉头下标 | $2d_h$ | 平均池化后 uptrain | [02](./02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md) |
| GQA | $G$ 组 $K, V$ | $2Gd_h$ | 平均池化后 uptrain 约 5% | [02](./02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md) |
| MLA | $K, V$ 由潜变量上投影, RoPE 走独立通道 | $d_c+d_h^R$ | 需要重新训练 | [03](./03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md), [04](./04-MLA-矩阵吸收与工程实现/04-MLA-矩阵吸收与工程实现.md) |
| Gated Attention | SDPA 输出逐头乘 sigmoid 门 | 与所用的 MHA/GQA 相同 | 新增门参数, 需要训练 | [05](./05-Gated-Attention-SDPA输出门控/05-Gated-Attention-SDPA输出门控.md) |

前四行沿 $d_{kv}$ 一列排开, MQA 和 GQA 是份数轴上的两个点, MLA 在维度轴上. 表的第四列说明了它们落地方式的差别: GQA 可以从已有 MHA 检查点转换, 用 5% 的预训练算力换一个推理更快的版本, 这是它在 2023 年后被大量开源模型采用的原因之一; MLA 的瓶颈结构没有这样的转换路径.

MLA 的位置通道是另一处代价. RoPE Key 所有头共享, 位置通道相当于一个 MQA, 位置信息的表达能力被压到 64 维的一个共享 Key 上. 这条通道的 Key 也要进缓存, 576 里的 64 就是它. 从位置编码一侧看 RoPE 为什么和低秩压缩冲突, 以及解耦后的点积怎样拆成内容项和位置项, 见 [2.1.4 的 RoPE 扩展](../../2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md) 第 4.4 和 4.5 节.

### 3.2 Gated Attention: 补上 $W_V$ 与 $W_O$ 之间的非线性

[05 Gated Attention](./05-Gated-Attention-SDPA输出门控/05-Gated-Attention-SDPA输出门控.md) 改的是表里唯一不碰缓存的一截. softmax 只作用在分数上, 对 Value 而言整个加权求和是线性的, 所以每个头的 $W_V^kW_O^k$ 可以合成一个秩不超过 $d_k$ 的矩阵, FFN 两次投影之间有激活, 注意力子层这两个矩阵之间没有. Qiu 等人在注意力子层上编号了五个可以加门的位置, 在 15B 总参, 2.54B 激活的 MoE 上比较, 放在 SDPA 输出之后的 $G_1$ 最好: PPL 从 6.026 降到 5.761, MMLU 从 58.79 升到 60.82. 放在 $W_O$ 之后的 $G_5$ 同样随 query 变, 却补不上这段非线性, 效果接近基线.

加门之后首 token 的平均注意力占比从 46.7% 降到 4.8%, 训练中的 loss spike 也明显减少, 模型能用更大的学习率. 这对依赖 attention sink 的 KV 保留策略 (保留开头几个 token 加滑动窗口) 是一个提醒: 在加门的模型上要重新验证. Qwen3-Next-80B-A3B 每 4 层里 3 层是线性注意力 Gated DeltaNet, 1 层是带输出门的全注意力, 05 第 3.5 节给出了这一整机布局.

## 4. 读法与相邻章节

### 4.1 阅读顺序

五篇按顺序写成, 后一篇沿用前一篇的记号. 01 定义多头的公式, 参数量, FLOPs 和式 (1) 的缓存基准, 第 4 节是后面所有对照的出发点, 只想看推理成本的读者可以从这一节读起. 02 的第 1 节和第 3 节分别是 MQA 与 GQA 的定义, 第 4 节是转换方法和三组质量实验. 03 和 04 是一对: 03 讲缓存什么, 04 讲怎样用缓存算注意力, 不打算实现推理内核的读者读完 03 第 4 节的缓存数字就可以停下.

05 与前四篇相对独立, 只依赖 01 第 1 节的多头写法. 对残差流做的同类改动, 即把深度方向的等权求和换成注意力加权的 [AttnRes](../../2.1-深度学习基础组件/2.1.3-残差连接/04-AttnRes-深度维注意力聚合/04-AttnRes-深度维注意力聚合.md), 以及四分支残差上的读门 [Gated Residual](../../2.1-深度学习基础组件/2.1.3-残差连接/03-Gated-Residual/03-Gated-Residual.md), 放在 2.1.3 残差连接, 它们不涉及 token 维的 KV.

### 4.2 相邻章节的分工

这一节的方法改的是缓存里每个 token 存什么. 不改公式, 只改计算顺序和片上调度的 FlashAttention 一类在 [2.3 注意力的高效实现](../../2.3-注意力的高效实现/2.3-注意力的高效实现.md), 05 篇对比了 SDPA 和 flash-attn 等路径对 GQA 的不同处理. 只让每个 query 读一部分 key 的训练期稀疏注意力在 [2.4 稀疏注意力](../../2.4-稀疏注意力/2.4-稀疏注意力.md), 其中 NSA 的内核按 GQA 组加载 KV. 用固定大小的状态代替随长度增长的缓存是 [2.5.1 线性注意力](../../2.5-线性注意力与状态空间模型/2.5.1-线性注意力机制/2.5.1-线性注意力机制.md) 的做法, Kimi Linear 用 3 层 KDA 配 1 层 MLA.

推理期在训好的模型上删掉或少读一部分 KV, 例如 [StreamingLLM](../../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/01-StreamingLLM与Attention-Sink/01-StreamingLLM与Attention-Sink.md) 和 H2O, 归 2.7.2; 缓存的分页分配是 [PagedAttention](../../2.7-长上下文与外推技术/2.7.3-长上下文推理优化/01-PagedAttention/01-PagedAttention.md) 的内容. 这些方法与 MQA/GQA/MLA 正交, 一个部署可以同时用 GQA, 分页缓存和 KV 驱逐, 计算缓存时按式 (1) 逐项乘上各自的压缩比.
