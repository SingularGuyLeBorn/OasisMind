# 2.4.8 条件记忆与 Engram

语言建模里有一类模式是**局部、静态、套话式**的：多 token 专名、成语、固定搭配。标准 Transformer 没有原生的「按局部上下文查一张表」算子，早期层只好用 Attention 和 FFN **把这张表现场重建一遍**。条件记忆把这件事改成 **O(1) 哈希查找**；条件计算（MoE）仍然负责动态推理。二者分的是稀疏预算，不是同一条数据流。

## 不是（家族内先分清）

条件记忆经常被顺口叫成「外挂记忆」或「另一种 MoE」。专文会展开，这里先钉四条，避免走错夹。

| 对象 | 它在干什么 | 和 Engram 差在哪 |
|------|------------|------------------|
| MoE | 按隐藏态激活少数专家，做矩阵乘 | 稀疏的是**计算**；路由要等当前层 $h_t$ |
| kNN-LM | 在训练语料的隐藏态库里做近邻，再插值 next-token 分布 | 非参数检索，复杂度随库长走，不是 O(1) 哈希行 |
| Hash Layers | 把 token ID 哈希到**某一个专家 FFN** | 哈希的落点是计算模块，不是静态嵌入行 |
| PEER / PKM | 用隐藏态当 query 去查海量小专家 | 地址依赖 $h_t$，不能在进层之前 prefetch |
| KV cache | 存本序列已经算过的 K/V | 随生成长度涨；不是一张可 offload 的参数表 |

DeepSeek-V4 把 Cheng et al. 2026 写在**未来路线**里的「更稀疏的嵌入模块」，不是出厂件。公开权重里把 51B 级 n-gram 表真正捆进百 B 档的，目前写在专文的 Qwen3.8-Flash-Next 节。
