# 2.4.1 混合专家模型 MoE:条件计算零点

MoE 把 Transformer 里那层稠密 FFN 换成 $N$ 个专家:每个 token 只激活 $k \ll N$ 路.卡住的不是「参数还能不能再堆」,而是**条件计算**:路由器怎么分活,负载怎么不塌,容量满了 token 走哪条残差.本页是 2.4.1 的地图和公式零点.容量,溢出,aux-loss,z-loss 写在下面第 4–5 节,不再另开工程实践单独成篇.机制主线 01→03→10.**不是** MLA(注意力 KV 的 $c^{KV}$ 在 [2.2.2/04](../../2.2-基础注意力机制/2.2.2-多头注意力变体/04-MLA-低秩潜变量与矩阵吸收/04-MLA-低秩潜变量与矩阵吸收.md)),也不是专家并行通信单独成篇(All-to-All / EP 正本在第 6 章),也不是条件记忆(n-gram 哈希表在 [2.4.8 Engram](../2.4.8-条件记忆与Engram/2.4.8-条件记忆与Engram.md)).LatentMoE 的 $\ell$ 是 FFN 专家空间的瘦维,不是 MLA 的 $c^{KV}$,公式在 [10](./10-Stable-LatentMoE与Quantile-Balancing/10-Stable-LatentMoE与Quantile-Balancing.md).

## 2. 条件计算:软混合 vs 稀疏门控

Dense FFN 对每个 token 执行同一套矩阵变换；稀疏 MoE 则根据该 token 的路由结果调用部分专家。这里讨论的是执行哪些矩阵计算，不是逐个激活值或参数梯度是否非零。

1991 年 Jacobs,Jordan,Nowlan,Hinton 的 Adaptive Mixtures of Local Experts 已经把「专家 + 门控」写清楚:门控给出权重,输出是全体专家的加权和,训练用 EM.那时所有 $g_i(x)>0$,没有算力折扣.现代 LLM 要的稀疏性,是 Shazeer 等人 2017 年的 noisy Top-K,GShard 的 Top-2 容量约束,Switch 的 Top-1 才钉进 Transformer 的.

![Dense与Sparse前馈接口、独立隐藏态和gate路径及矩阵预算对照](./images/redrawn-fig-moe-dense-vs-sparse-v2.png)

> 图 1：两种前馈映射均接收 $x\in\mathbb R^d$ 并输出 $d$ 维向量。示例 Dense 中间维为 $2H$；Sparse 有 8 个中间维为 $H$ 的专家，每 token 选择 2 个，假定容量充足。两者的输出分别记为 $y_D,y_M$，并不要求数值相同。

**图 1 解析**

- **Dense 路径**：外框 $F_D(x)$ 表示一次完整 FFN 调用，内部依次展开 $a=W_{\mathrm{up}}x$、$b=\varphi(a)$、$y_D=W_{\mathrm{down}}b$；矩阵维度为 $2H\times d$ 与 $d\times2H$。
- **Sparse 路径**：$x$ 独立进入 Router 和 Dispatch。Router 给出 $S=\{2,5\}$ 及 gate；两个 $(x,g_i)$ 数据包分别进入专家分支，FFN 结果经过对应 gate 后才相加。未选专家只列在名册中，没有执行连线。
- **门控口径**：本例与图 2 一致，保留全局 Softmax 后的 $g_2=0.31,g_5=0.28$，因此 $y_M=0.31E_2(x)+0.28E_5(x)$。不同门控归一化顺序见第 3.1 节。
- **预算边界**：固定输入/输出维和 FFN 形式，Dense 的中间宽度总量为 $2H$，Sparse 的专家总量为 $8H$，但本 token 只执行 $2H$。这说明总专家参数可以增长而激活矩阵预算保持对应；Router、派发、通信及硬件效率另计，不能直接当成相同实际时延。图示均为前馈映射，残差由外层子层处理。

记号:输入 token 隐状态 $x\in\mathbb{R}^{d}$,专家 $E_1,\ldots,E_N$ 各是一个 FFN,门控 $g_i(x)\in\mathbb{R}$.软混合(全体专家都算)是

$$
y=\sum_{i=1}^{N} g_i(x)\,E_i(x),\qquad
g(x)=\mathrm{Softmax}(W_g x). \tag{1}
$$

软混合里 $g_i(x)>0$,没有稀疏.稀疏门控把绝大多数 $g_i$ 强制为 0,只留 Top-$K$:

$$
y=\sum_{i\in\mathrm{TopK}(x)} g_i(x)\,E_i(x). \tag{2}
$$

![Top2路由中隐藏态x与选择索引及gate的独立路径](./images/redrawn-fig-moe-router-top2-v2.png)

> 图 2：单 token 的 Token-Choice 前馈映射，$k=2$，假定所选专家容量充足。本例先对全部专家做 Softmax，再保留 Top-2 的原始分数：Expert 2 与 Expert 5 分别使用 $g_2=0.31,g_5=0.28$。图示输出 $y$ 是专家前馈结果，Transformer 子层的残差另行相加。

**图 2 解析**

- **Router 与隐藏态副本**：$x\in\mathbb R^d$ 一路进入 Router 计算 $\ell=W_gx$ 与 $p=\operatorname{Softmax}(\ell)$，另一路直接进入 Dispatch。Router 提供选择信息，专家计算使用的仍是输入隐藏态 $x$。
- **选择与门控来源**：八个分数为 $(0.07,0.31,0.06,0.05,0.28,0.08,0.09,0.06)$，因此 $S=\{2,5\}$。第三高的是 Expert 7 的 $0.09$。Top-K 的虚线将 $S,g$ 送入 Dispatch；$g_2+g_5=0.59$，对应本例保留全局 Softmax 原值的规则。
- **所选分支**：Dispatch 的两个数据包分别为 $(x,g_2)$、$(x,g_5)$。分支内 $x$ 送入各自 FFN，$g_i$ 单独进入乘法；定义 $h_i=E_i(x)$、$z_i=g_ih_i$。灰框仅列出本次未选专家，没有执行数据流。
- **加权结果汇合**：两次乘法的结果 $z_2,z_5$ 进入求和，得到 $y=0.31E_2(x)+0.28E_5(x)$；乘法旁的卡片标明对应结果值。若采用选中集合重新归一化，门控数值会改变，应使用第 3.1 节对应公式。

## 3. 路由:Token-Choice vs Expert-Choice

路由是 token 与专家的匹配.三条路:

1. **Token-Choice**:每个 token 给全体专家打分,自己挑 Top-$K$ 个专家.Mixtral,DeepSeek,Qwen 这一路都是它.
2. **Expert-Choice**:每个专家给全体 token 打分,自己挑固定容量的 token(Zhou et al., 2022).
3. **全局分配**:把匹配写成运输问题.训练步里太贵,几乎不进主线.

哈希路由(Roller et al., 2021)是非学习的固定映射:零路由参数,天然均衡,但分数不能随数据改.Hash Layers 表明,即使哈希不含语义,单靠「多一套专家容量」也能降损失;它不是本库 LLM 的默认路由器,只说明**稀疏容量本身**有用.

### 3.1 Token-Choice:先 Top-K 再 Softmax,还是先 Softmax 再截断

对 $x$,路由器先出 logits

$$
h(x)=W_g x. \tag{3}
$$

Shazeer 2017 在训练早期加可学习噪声,避免过早锁死少数专家:

$$
h'(x)_i=h(x)_i+\mathrm{StandardNormal}()\cdot\mathrm{Softplus}\bigl((W_{\mathrm{noise}}x)_i\bigr). \tag{4}
$$

**实现分叉在 Softmax 和 Top-K 的顺序.**

**先 Top-K 再 Softmax**(KeepTopK,再把落选坐标置 $-\infty$):

$$
h_{\mathrm{TopK}}(x)_i=\begin{cases}
h'(x)_i & i\in\mathrm{TopK}(x)\\
-\infty & \text{otherwise}
\end{cases},\qquad
g(x)=\mathrm{Softmax}\bigl(h_{\mathrm{TopK}}(x)\bigr). \tag{5}
$$

选中的 $K$ 个门控之和为 1.Qwen 系常见这条;Shazeer 原文也是 KeepTopK 再 Softmax.

**先 Softmax 再截断**:先对全部 $N$ 个 logits 做 Softmax,再把非 Top-$K$ 的 $g_i$ 置 0.选中门控之和小于 1.DeepSeek V1–V2 走这条(见 [01](./01-DeepSeek-MoE/01-DeepSeek-MoE.md)).

两条都叫 Top-$K$,残差尺度不一样.不要混着用同一套学习率去对.

常规自动微分中，离散索引本身不求导；被选中的分数仍可通过 gather 等操作向原分数传递梯度。应区分索引路径和数值路径，具体计算图见 [03](./03-MoE-Top-K运算可导性分析/03-MoE-Top-K运算可导性分析.md)。

Switch Transformer 将 $K$ 设为 1，每个被接收的 token 只调用一个专家 FFN，派发与专家计算更简单。性能仍依赖模型、数据与训练配置，不能仅由 Top-1 或 Top-2 判断。

![SwitchTop1从logits到Softmaxgate的计算及独立隐藏态派发路径](./images/redrawn-fig-switch-top1-v2.png)

> 图 3：单 token、容量充足的 Switch 前馈示例。Router 对八个专家计算 logits，经全局 Softmax 选中 Expert 5。整数索引用于派发原始 $x$，所选概率用于缩放专家结果。图示输出 $y$ 是前馈映射，外层残差另计。

**图 3 解析**

- **logits 与概率分开**：图中 $\ell=(0.11,0.07,0.12,0.18,0.73,0.09,0.14,0.10)$ 是 logits 向量。计算 $p=\operatorname{Softmax}(\ell)$ 后，$p_5\approx0.2088$ 最大；$\ell_5=0.73$ 与 $p_5$ 是两个不同的量。
- **Dispatch 的两个参数**：原始向量 $x$ 通过独立实线进入 Dispatch，整数 $i^\star=5$ 通过虚线进入另一个端口。Dispatch 按索引选择专家，不对向量和整数作加法。
- **唯一专家与 gate**：Expert 5 计算 $h_5=E_5(x)$，再与 $g=p_5$ 相乘，输出 $y\approx0.2088E_5(x)$。其余七个专家本次没有 FFN 调用，其他 token 仍可能选择它们。
- **容量与归一化**：图中 $C=64$ 仅为容量设置示例，假定本次派遣被接收。gate 保留全局 Softmax 中的所选概率；若在选中的单个专家上再做 Softmax，gate 会变成 1，那将改变数值与梯度路径。溢出情况见图 8。

固定获胜索引的局部区域内，$\partial p_5/\partial\ell_j=p_5(\mathbf1[j=5]-p_j)$。主损失可以通过所选 gate 影响 Router 分数，这并不要求对 argmax 索引本身求导。该结构与门控定义见 [Switch 第 2.1 节](https://arxiv.org/html/2101.03961#S2.SS1)。

### 3.2 Expert-Choice：按专家列选择，按 token 位置回写

Token-Choice 固定每个 token 的选择数，却可能把大量选择集中到同一专家。Expert-Choice 则在一个路由组内，让每个专家取分数最高的 $C$ 个 token；当 $T\ge C$ 时，各专家恰好接收 $C$ 条派遣。这里均衡的是派遣数量，实际设备耗时还受通信和执行方式影响。

![Expert-Choice：评分矩阵、逐列选择、原始向量 Gather、专家计算与加权回写](./images/redrawn-fig-moe-expert-choice-v2.png)

> 图 4：自构的 $T=8,N=5,C=2$ 数值例子。评分与数据派遣是两条路径：Router 产生索引和 gate，Gather 按索引取得原始向量，专家结果再按 token 位置加权累加。图示输出 $Y$ 为 FFN 分支，残差另计。

**图 4 解析**

- **评分的归一化方向**：$S=\operatorname{Softmax}_{\mathrm{expert}}(XW_g)\in\mathbb R^{8\times5}$，每一行是一个 token 对五个专家的概率，总和为 1。随后给定 $S$，逐列沿 token 维取 Top-$C$；这些列选择分别执行，评分本身仍经过跨专家的行归一化。
- **索引与权重**：$I[e,r]$ 记录专家 $e$ 的第 $r$ 个入选 token，$G[e,r]=S[I[e,r],e]$ 记录对应概率。Expert 2 选 token 3、7，gate 分别为 $0.41,0.33$；其他四列也从同一张矩阵选择。
- **向量输入**：Gather 同时接收原始 $X$ 和索引 $I$，得到 $X_{\mathrm{in}}[e,r]=X[I[e,r]]$，形状为 $5\times2\times d$。每个专家对自己的两个向量分别计算 $V[e,r]=E_e(X_{\mathrm{in}}[e,r])$。
- **加权回写**：Scatter-Add 接收 $V$ 以及 $(I,G)$，计算 $Y_t=\sum_{e,r:I[e,r]=t}G[e,r]V[e,r]$，恢复 $8\times d$ 的 token 顺序。这里直接使用取出的 gate；没有在同一 token 的入选专家之间另做归一化。上述算子定义对应 [Expert-Choice 第 3.2 节](https://arxiv.org/html/2202.09368#S3.SS2)。

用图中的记录逐项回算，token 2 被 Expert 1、5 选中，所以 $Y_2=0.40E_1(x_2)+0.30E_5(x_2)$；token 6 被 Expert 4、5 选中，所以 $Y_6=0.40E_4(x_6)+0.32E_5(x_6)$。八个 token 的专家数依次为 $(1,2,1,1,1,2,1,1)$，总派遣数为 $NC=10$，平均每个 token 使用 $10/8=1.25$ 个专家。本例恰好覆盖所有 token；一般情况下，也可能有 token 未被任何专家选中。

Token-Choice 的槽数写成容量因子 $\gamma$(Switch 文里也叫 $\mathrm{CF}$).设本层一个 batch 有 $T$ 个 token,$N$ 个专家,每个 token 最多派给 $k$ 个专家.Switch 是 $k=1$;GShard 是 top-2,组内还要把容量按组切开.统一写法:

$$
C=\left\lceil\frac{T\cdot k}{N}\cdot\gamma\right\rceil. \tag{6}
$$

$\gamma=1$ 对应均匀分流的派遣预算，向上取整可能增加少量槽位。路由分布不均时，热门专家仍会先满；固定容量实现会跳过超出容量的 token–expert 派遣。在 Top-1 且无共享专家的例子中，这会使该 token 的专家分支为零，由残差保留输入；Top-K 则还需检查其他已接收分支。$\gamma>1$ 给负载波动留缓冲，空槽用 padding 填成静态形状，会增加计算与通信开销。Switch 实验里常用 $1.0$–$1.25$(Fedus et al., 2021)。评测时常把 $\gamma$ 临时加大(ST-MoE 微调评估 $\gamma=2.0$)：训练和评测应分别报告容量配置。

Expert-Choice 的 $c$ 不是这颗螺丝.Zhou et al. (2022) 式 (1) 把每个专家取多少 token 写成 $k=n\cdot c/e$($n$ 是 batch 内 token 数,$e$ 是专家数).$c=2$ 与 GShard top-2 的激活量对齐;$c=1$ 对齐 Switch top-1.桶大小按构造固定,不再需要下面的 $f_i P_i$.

## 4. 负载:aux-loss,z-loss,aux-loss-free

Token-Choice 可能把大量派遣集中到少数专家。一次 batch 的偏斜是负载快照；如果路由器长期重复这种选择，冷门专家获得的任务学习信号会减少，严重时形成**专家坍塌**。需要结合跨 batch 的调用统计判断这种长期退化。

![Top1索引的计数分支与原始向量分组派遣：16个token的完整负载与输出](./images/redrawn-fig-moe-load-imbalance-v2.png)

> 图 5：八个专家按 1–8 编号，负载为 $(1,1,10,1,1,1,1,0)$，总数恰好为 16。为单独观察派遣分布，本例设 $C\ge10$，所有选择均被接收；容量溢出见图 8。

**图 5 解析**

- **Router 输出索引**：原始 $X\in\mathbb R^{16\times d}$ 经 Router 得到 $P\in\mathbb R^{16\times8}$，逐行取 $z_t=\arg\max_e P[t,e]$。token 1、2 分别选 Expert 1、2；token 3–12 都选 Expert 3；token 13–16 依次选 Expert 4–7。
- **Count 只做统计**：$n_e=\sum_{t=1}^{16}\mathbf1[z_t=e]$ 使用整数索引 $z$ 计算柱高。$\sum_e n_e=16$，均匀参考线为 $T/N=2$；它与本例的容量 $C\ge10$ 是两个量。Expert 3 的比例为 $10/16=62.5\%$，均匀比例为 $1/8=12.5\%$。
- **GroupBy 派发向量**：它同时接收独立旁路的原始 $X$ 和索引 $z$，按 $X_e=\operatorname{stack}\{x_t\mid z_t=e\}$ 分组。七条非空数据包各有明确的专家终点；Expert 3 的一束线携带十个向量，并非把一条线当作一个 token。
- **专家的输入输出守恒**：Expert 3 分别计算 $h_t=E_3(x_t)$，$t=3,\ldots,12$，产生十个对应输出；其他六个非空专家各产生一个输出。Expert 8 本批没有调用，所以不画执行线。本图止于专家输出，后续还需按 gate 合并并处理残差。

这里 $f_e=n_e/T$ 是选择频率，而非 gate 值。负载统计分支中的 $n$ 不会被当成隐藏态送进 FFN。频率与概率均值如何共同构造辅助损失，见下面的定义；路由与容量机制可对照 [Switch 第 2 节](https://arxiv.org/html/2101.03961#S2)。

### 4.1 辅助损失(Switch 同族)

对一个 batch 中参与统计的 $T$ 个有效 token，令 $p_i(x)$ 为容量截断前、对全部专家计算的 Router Softmax 概率。Switch 的 Top-1 选择频率为

$$
f_i=\frac{1}{T}\sum_{x\in\mathrm{Batch}}\mathbb{1}\bigl\{\arg\max p(x)=i\bigr\}. \tag{7}
$$

此时 $\sum_i f_i=1$，均匀选择时 $f_i=1/N$。$f_i$ 统计选择结果，不能用容量截断后的存活数替代而仍声称总和为 1。对应的概率均值使用完整的 $p$，与实际乘到专家输出上的截断门控 $g$ 区分开：

$$
P_i=\frac{1}{T}\sum_{x\in\mathrm{Batch}} p_i(x). \tag{8}
$$

于是 $\sum_i P_i=1$。若每个 token 在截断前恰好选择 $K$ 个专家，选择比例可定义为 $\bar f_i=(TK)^{-1}\sum_t\mathbf1[i\in S_t]$，其总和为 1。DeepSeek 的对应记号为 $f_i^{\mathrm{DS}}=N\bar f_i$，总和为 $N$、均匀时各分量为 1；两种尺度应分别标注，并一起核对损失前的 $N$ 因子。具体公式见 [01 DeepSeek-MoE](./01-DeepSeek-MoE/01-DeepSeek-MoE.md)。

本节统一将**尚未乘系数**的负载项定义为两个向量的点积，再乘专家数：

$$
L_{\mathrm{balance}}=N\sum_{i=1}^{N} f_i P_i. \tag{9}
$$

当 $f_i=P_i=1/N$ 时，这个均匀基准值为 1。它是点积型负载代理项，不是均方误差。系数 $\alpha$ 控制它在总损失中的贡献：

$$
L_{\mathrm{total}}=L_{\mathrm{main}}+\alpha L_{\mathrm{balance}}. \tag{10}
$$

Switch 取 $\alpha=10^{-2}$,在 $10^{-1}$ 到 $10^{-5}$ 的十倍扫里,这个数量级既能很快拉平负载,又不压过交叉熵.$f_i$ 里的指示函数不可导,梯度只走 $P$,不走 $f$:路由器被拧的是「给热专家的概率」.$L_{\mathrm{balance}}$ 进训练图,**不进推理图**.关掉它,Switch / ST-MoE 表里的丢弃率会从 $<1\%$ 跳到两位数--不是容量公式变了,是 $f$ 更尖,局部 $C$ 更早打满.这和 [03](./03-MoE-Top-K运算可导性分析/03-MoE-Top-K运算可导性分析.md) 里 Top-K 的掩码恒等是两件事:aux-loss 不把选中集合变光滑.GShard 组级形式是 $\ell_{\mathrm{aux}}=\frac{1}{E}\sum_e (c_e/S)\,m_e$:想罚 $(c_e/S)^2$,但 $c_e$ 来自 top-2 计数,改用可微的组内平均门控 $m_e$ 去乘.

单独考察这个负载项，并将离散 $f$ 视为常量时，对第 $t$ 个 token 的 Router logit $\ell_{t,j}$ 有

$$
\frac{\partial L_{\mathrm{balance}}}{\partial\ell_{t,j}}
=\frac NT\,p_{t,j}\left(f_j-\sum_i f_i p_{t,i}\right).
$$

这条梯度经过概率均值 $P$ 和 Softmax 返回 Router，离散计数分支不参与求导。完整模型还同时受到主任务与其他正则的梯度影响，不能只凭这个局部方向预测最终负载。

DeepSeek V1–V2 还加过**逐设备**均衡:把同一 GPU 上的专家聚合成 $f'$,$P'$ 再点积,避免「专家数均分但卡间 token 数不均」.公式在 [01](./01-DeepSeek-MoE/01-DeepSeek-MoE.md).

### 4.2 Router z-loss

ST-MoE(Zoph et al., 2022)讨论了 Router 指数运算对数值舍入的敏感性。选择性 FP32 改变计算精度；router z-loss 则在训练目标中约束 logits 的 log-partition。两者的作用不同。令 $\ell_{t,i}$ 为第 $t$ 个有效 token 对专家 $i$ 的原始 logit，先对每个 token 计算 LogSumExp，再平方并对 token 取均值：

$$
L_z=\frac{1}{T}\sum_{t=1}^{T}\left(\log\sum_{i=1}^{N}e^{\ell_{t,i}}\right)^2. \tag{11}
$$

$$
L_{\mathrm{total}}=L_{\mathrm{main}}+\alpha L_{\mathrm{balance}}+c_z L_z. \tag{12}
$$

![MoE三项损失的预测标签输入、计数概率双分支与单次系数加权](./images/redrawn-fig-moe-eng-aux-zloss-v2.png)

> 图 6：同一次模型前向给出词表 logits 与某个路由层的 logits。交叉熵同时接收预测和监督标签；Router logits 分出概率统计与 LogSumExp 两条路径。原始 $L_{\mathrm{balance}}$、$L_z$ 各乘一次系数后，与主损失相加。示例系数为 $\alpha=0.01,c_z=0.001$。

**图 6 解析**

- **预测与标签**：词表 logits $A$ 和独立监督标签 $y_t$ 分别进入交叉熵，两者都是计算所需输入。
- **计数与概率**：图中路由矩阵 $L$ 的第 $t$ 行为 $\ell_t$。其 Softmax 概率 $p_t$ 分别产生离散选择频率 $f$ 和可微均值 $P$，两者共同进入点积。
- **z-loss 的来源**：LogSumExp 读取原始 $\ell_t$；平方后再取均值，得到式 (11) 的 $L_z$。
- **一次加权**：$L_{\mathrm{main}}$、$\alpha L_{\mathrm{balance}}$、$c_zL_z$ 独立进入总和。$0.01$ 与 $0.001$ 相差 10 倍，实际影响还由损失尺度与梯度决定。跨层聚合方式也应按实现说明。

一个数值检查：若四个 token 的路由概率依次为 $(0.6,0.3,0.1)$、$(0.5,0.4,0.1)$、$(0.2,0.3,0.5)$、$(0.4,0.35,0.25)$，则 Top-1 选择为 $(1,1,3,1)$，得到 $f=(0.75,0,0.25)$、$P=(0.425,0.3375,0.2375)$，原始负载项为 $1.134375$。乘 $\alpha=0.01$ 后贡献为 $0.01134375$，可用来检查实现是否重复乘系数。

图中为清晰起见按同一组有效 token 展开。若主损失监督位置与路由统计位置不同，需分别使用各自的 mask 与分母。公式来源见 [Switch 第 2.2 节](https://arxiv.org/html/2101.03961#S2.SS2) 和 [ST-MoE 第 3.3 节](https://arxiv.org/html/2202.08906#S3.SS3)。

ST-MoE 取 $c_z=0.001$(预训练扫参).z-loss 通过训练梯度作用于产生 logits 的参数；直接截断已计算的 logits 与收紧优化器 update clipping 是另外两类操作，应按作用位置分别比较。Switch Table 2:路由器整段 bfloat16 时负对数困惑度到 $-3.780$ 并发散;只把**路由器局部**升到 float32(dispatch / combine 仍 bfloat16)得到 $-1.716$,速度与纯 bfloat16 同为 1390 examples/s.$-3.780$ 是发散后的坏质量,不是「更负所以更好」.ST-MoE 写:到他们的最大规模,选择性精度仍不够.Table 4(各 3–6 次):基线 $4/6$ 稳定,质量 $-1.755\pm0.02$;把 Adafactor 的 update clip 收到 $0.1$ 则 $3/3$ 稳定,但质量崩到 $-4.206\pm0.17$;z-loss 则 $3/3$ 稳定且质量 $-1.741\pm0.02$.

![Router选择性FP32、原始隐藏态派发、整数索引与zloss训练分支](./images/redrawn-fig-moe-router-zloss-v2.png)

> 图 7：一种选择性精度实现，假定所选容量充足。原始 BF16 隐藏态直接进入 Dispatch；Router 的 FP32 路径只产生路由数值与索引。原始 logits 另行分支到 z-loss，得到标量正则。图示输出 $Y$ 是前馈映射，外层残差另计。

**图 7 解析**

- **独立的隐藏态路径**：$H$ 一路转成 FP32 供 Router 计算，另一路以 BF16 直接进入 Dispatch。Dispatch 接收选择集合 $S_t$ 后生成 $(h_t,i)$ 记录，只调用记录对应的 $E_i$。
- **元数据与浮点数据**：$S_t$ 保持整数索引，图示 gate 转回 BF16。Combine 同时接收专家结果 $v_{t,i}$ 与路由记录 $(S,g)$，计算 $Y_t=\sum_{i\in S_t}g_{t,i}v_{t,i}$。BF16 标签描述浮点数据，不适用于整数索引。
- **训练正则路径**：原始路由矩阵 $L=(\ell_{t,i})$ 在 Softmax 之前分支，先按专家维做 LogSumExp，再平方并按有效 token 取均值。$c_zL_z$ 与独立提供的其余损失 $L_{\mathrm{other}}$ 一起进入总损失；其他项的来源见图 6。
- **实现边界**：本例沿用全局 Softmax 后保留选中概率的门控。精度、输出缩放、门控归一化与跨层损失汇总都应按实际模型核对，图中不将一种 dtype 配置当成所有 MoE 的固定规定。

**z-loss 更直接观察的是 log-partition。** 对单个 token，记 $a=\log\sum_i e^{\ell_i}$。由定义可得：给所有 logits 同时加常数 $c$，Softmax 概率保持不变，但 $a$ 变成 $a+c$。取 $p=(0.5,0.3,0.2)$、$\ell=\log p$，可得到以下精确数学例子：

| logits | Softmax 概率 | LogSumExp | 单 token z-loss |
| --- | --- | --- | --- |
| $\log p$ | $p$ | $0$ | $0$ |
| $\log p+2\mathbf1$ | $p$ | $2$ | $4$ |
| $\log p-2\mathbf1$ | $p$ | $-2$ | $4$ |

这解释了为什么只观察路由概率不足以确定 z-loss。它也不同于逐 logit 的 L2：例如 $(0,-100,-100)$ 的 LogSumExp 和 z-loss 都接近零，尽管某些分量的绝对值很大。实现中应保持该损失读取原始 logits；若误接到 `log_softmax` 的输出，其 LogSumExp 在精确运算中恒为零，正则会失去作用。

对第 $t$ 个 token 的梯度为

$$
\frac{\partial L_z}{\partial\ell_{t,i}}
=\frac{2}{T}\log Z_t\,p_{t,i},\qquad
\log Z_t=\operatorname{LogSumExp}(\ell_t).
$$

因此各分量的梯度通常不同；共同平移的例子用来区分目标观察的量，并不表示实际更新只做共同平移。选择性 FP32 则影响路由算术的精度，不能恢复输入在转成 BF16 之前已经丢失的信息。稳定性的其他问题见 [6.1.7](../../../6-训练与推理优化/6.1-训练基础设施/6.1.7-训练稳定性与训推不一致.md)。

### 4.3 aux-loss-free

DeepSeek-V3 不再用逐专家 $f_i P_i$ 当主均衡,而是给每个路由专家一个偏置 $b_i$:过载就减小 $b_i$,空闲就增大,下一步用 $s_{i,t}+b_i$ 做 Top-K.这叫 aux-loss-free.单序列上仍可能极端不均,所以还留了一个**序列级**互补辅助损失.偏置的更新步长在 K3 规模上不够,改 Quantile Balancing,见 [10](./10-Stable-LatentMoE与Quantile-Balancing/10-Stable-LatentMoE与Quantile-Balancing.md).V3 的 Sigmoid 打分与 $b_i$ 公式在 [01](./01-DeepSeek-MoE/01-DeepSeek-MoE.md).

## 5. 容量,溢出,显存

固定容量的 Token-Choice 实现可以丢弃超额的 token–expert 派遣。下面限定为 **Top-1、无共享专家、overflow 时跳过专家分支** 的示例：若所选专家容量已满，该 token 在本 MoE 子层的专家输出为零，残差保留原输入，随后继续后续计算。对于有共享专家、多个已接收路由分支或 dropless 调度的实现，应分别分析其保留的计算路径。

在使用容量丢弃的配置中，同一 token 是否被接收可能取决于该批次的其他 token 与派发顺序；需要将这种容量相关变化与路由打分本身区分开。具体策略参见 [Switch 第 2.2 节与附录 B](https://arxiv.org/html/2101.03961)。

![固定容量Top1的五个token、三个gate与残差相加及两条直通路径](./images/redrawn-fig-moe-token-overflow-v2.png)

> 图 8：Router 对五个 token 都选 Expert 1，示例 gate 为 $0.8$，容量为 $C=3$，按输入顺序接收 Token 1–3。三个 $E_1(u_i)$ 是同一组 FFN 参数对不同 token 的计算；Token 4、5 的专家分支被跳过。五个输入与五个输出的位置保持对应。

**图 8 解析**

- **调度记录**：$m=(1,1,1,0,0)$ 表示哪些派遣被接收；上方控制流程与下方逐 token 路径使用相同编号。按顺序占槽是本图的示意规则，实际保留顺序应以实现为准。
- **容量内的三个 token**：$u_i$ 一路送入 Expert 1，得到 $E_1(u_i)$ 后乘 gate $0.8$；另一路保留原始 $u_i$，两路在加法节点汇合。每个 Expert 本身就是 FFN。
- **溢出的两个 token**：$m_4=m_5=0$，分别沿自己的残差路径得到 $h_4=u_4,h_5=u_5$，没有跨 token 混合。图中 Expert 2–4 虽然空闲，本例采用的策略也不额外改派。
- **输出与后续计算**：三个容量内输出为 $h_i=u_i+0.8E_1(u_i)$，两个溢出输出保留原输入。这里省略 Norm，只展示 MoE 子层；五个位置随后继续后续子层。

统一写为 $h_i=u_i+f_i$：接收时 $f_i=0.8E_1(u_i)$，丢弃专家分支时 $f_i=0$。例如容量内的 $u_i=(1,2)$、$E_1(u_i)=(0.5,-0.25)$，得到 $h_i=(1.4,1.8)$；若该派遣被丢弃，则保留 $(1,2)$。数值仅用于检查 gate 与残差的作用。

Switch Table 1(128 专家,隔层 MoE,同 32 核 TPUv3,100k step)把 $\gamma$ 当成速度–质量旋钮.负对数困惑度**越大越好**($-1.534$ 优于 $-1.731$):

| 模型 | $\gamma$ | 100k step 负对数困惑度 | 到 $-1.50$ 的小时 | examples/s |
|------|---------|------------------------|-------------------|------------|
| T5-Base | — | $-1.731$ | 未达到 | 1600 |
| MoE-Base(top-2) | 2.0 | $-1.547$ | 68.7 | 840 |
| Switch-Base | 2.0 | $-1.554$ | 72.8 | 860 |
| Switch-Base | 1.25 | $-1.553$ | 65.0 | 910 |
| Switch-Base | 1.0 | $-1.561$ | 62.8 | 1000 |
| Switch-Base+ | 1.0 | $-1.534$ | 67.6 | 780 |

低 $\gamma$(1.0 / 1.25)在这块 TPU 预算上反而更好:质量几乎一样,小时数和吞吐都占便宜.配合 aux-loss,系数够大时,丢弃率通常 $<1\%$,且与专家个数没有观察到的依赖.GShard 更严:一个 token 的两个候选专家**都**满了,才标 overflow.第二专家还带一层随机派遣:若 $g_2$ 已经很小,按与 $g_2$ 成比例的概率决定要不要派第二路.Switch 还试过 **No-Token-Left-Behind**:溢出 token 改派给第二高分专家,可迭代到几乎零丢弃,实验上没有质量收益--网络一旦学到 token–专家对应,改派会把对应关系打乱.

**Token drop** 是 GShard / Switch 默认:形状固定,溢出走残差.ST-MoE Table 5(SuperGLUE):训练 $\gamma=0.75$,评估 $\gamma=2.0$,开 aux-loss 时峰值丢弃 $10.6\%$,分数 $86.5\pm0.21$;训练 $\gamma=1.25$ 丢弃 $0.3\%$,分数 $86.7$.关掉 aux-loss,同样 $\gamma=0.75$,丢弃升到 $15.6\%$,分数掉到 $85.7$.微调阶段丢 $10$–$15\%$ 可以和丢 $<1\%$ 差不多;aux-loss 在微调里仍然有用.预训练另一端:MegaBlocks 在 The Pile,64 专家,top-1,对照 Transformer-Small 时,$\gamma=1$ 的 drop 模型验证损失只降 $0.15$,避免丢弃的配置降 $0.26$(约为前者收益的 $1.73\times$).

**Dropless** 不是把 $\gamma$ 调到无穷.MegaBlocks(Gale et al., [arXiv:2211.15841](https://arxiv.org/abs/2211.15841))把 MoE 写成 **block-sparse GEMM**:专家 batch 长度跟实际派遣走,只 pad 到 block 对齐,不再按全局 $C$ 填空槽.同验证损失下,相对 Tutel 的 padding 式 dropless,端到端加速 $1.38\times$(XS)/$2.0\times$(Small)/$4.35\times$(Medium).Tutel 把 $\gamma$ 动态调到「刚够不丢」时,有的 MoE 需要 $\gamma$ 高到 $11$,而且训练中途会尖刺--那是调度器在追负载,不是建议把 $\gamma$ 钉死在 11.核与通信形状的正本在 [6.1.8 / 08](../../../6-训练与推理优化/6.1-训练基础设施/6.1.8-MoE系统与并行/08-MoE系统优化综述/08-MoE系统优化综述.md).

稀疏激活应按 **token 和层** 统计：一个 token 在当前层调用 $K$ 个专家，同一个 batch 的不同 token 可以选择不同专家，合起来可能覆盖全部 $N$ 个。权重的存放位置是另一项部署配置；在全量 GPU 驻留配置下，未被当前 token 使用的权重仍占用显存。

![单层MoE的全部权重驻留、三条参数读取与完整隐藏态和gate计算路径](./images/redrawn-fig-moe-vram-sparse-vs-active-v2.png)

> 图 9：单个 MoE FFN 层，$N=8,K=2$，本层 Router 与全部专家权重驻留同一 GPU。存储块 $W_i$ 表示参数集合，$E_i$ 表示使用这些参数的计算；权重读取、隐藏态和路由记录使用不同连线。

**图 9 解析**

- **驻留与读取**：八组专家权重始终保留在存储区。本 token 的三条参数读取路径分别为 $W_g\to\mathrm{Router}$、$W_2\to E_2$、$W_5\to E_5$；其余六组本次没有专家计算路径。读取权重不会把它们从驻留区删除。
- **完整前向**：原始 $x$ 独立进入 Router 与 Dispatch。后者同时接收 $(S,g)$，按 $S=\{2,5\}$ 形成两个数据包 $(x,g_i)$。分支中，$x$ 与驻留权重 $W_i$ 用于计算 $h_i=E_i(x;W_i)$；标量 $g_i$ 绕过 FFN，进入输出乘法，得到 $z_i=g_i h_i$。最后 $y=z_2+z_5$。本图的 $y$ 是 FFN 分支输出，残差另计。

- **单层账目**：若每个专家有 $P_E$ 个参数、Router 有 $P_R$ 个参数，则驻留参数为 $P_R+8P_E$，本 token 激活参数为 $P_R+2P_E$。在每参数固定 $q$ 字节的存储格式下，权重张量载荷为 $q(P_R+8P_E)$。本图采用列向量 $x$；无 bias 的 SwiGLU 三块矩阵给出 $P_E=3dH$，Router 矩阵形状 $8\times d$ 给出 $P_R=8d$。

这份单层权重账不包含模型的其他层。KV cache、激活、工作区、分配开销以及训练时的梯度和优化器状态都需要另列；激活参数量也不能直接当作实测显存流量或端到端耗时。多卡部署可用 [Expert Parallelism](https://arxiv.org/html/2401.04088#S2.SS1) 分散权重并转发 token；采用 CPU／disk offload 时，权重还可以按需搬入执行设备，详见 [Accelerate 的加载与 offload 说明](https://huggingface.co/docs/accelerate/concept_guides/big_model_inference)。

完整模型的例子是 Mixtral 8×7B：[官方发布说明](https://mistral.ai/news/mixtral-of-experts/)给出约 $46.7\,\mathrm{B}$ 总参数、每 token 约 $12.9\,\mathrm{B}$ 激活参数。前者对应完整模型权重规模，后者描述每 token 使用的参数规模；实际部署的显存还取决于精度、分片、offload 与运行时开销。

## 6. LLM 主线里的架构分叉:DeepSeekMoE 与 Upcycling

DeepSeekMoE(Dai et al., 2024)在 Token-Choice 上加入细粒度与共享专家两项结构设计，具体机制见[论文第 3 节](https://arxiv.org/html/2401.06066#S3)：

1. **细粒度切分**：将 FFN 中间维从 $H$ 缩小到 $H/m$，专家数从 $N$ 增至 $mN$，激活数同步从 $K$ 增至 $mK$。在固定输入/输出维与 FFN 形式时，专家矩阵的总参数和激活计算预算保持对应。
2. **共享专家隔离**：在 $mN$ 个窄专家中划出 $N_s$ 个始终执行的共享专家，路由池剩下 $mN-N_s$ 个，每 token 激活其中 $mK-N_s$ 个。共享分支直接计算输入 $u$，与加权路由输出共同汇合，旨在减轻公共知识冗余。

![相同专家预算下宽专家、细粒度与共享专家的完整路由及残差对照](./images/redrawn-fig-deepseekmoe-panels-v2.png)

> 图 10：采用 $N=4,K=2,m=2,N_s=1$ 的示意配置。宽专家激活 2 路；中间维减半后激活 4 路；加入共享专家后保持 1 路共享＋3 路路由。三种配置的总专家中间宽度均为 $4H$，每 token 激活中间宽度均为 $2H$。

**图 10 解析**

- **数据与门控分开**：每行的输入 $u$ 分别送入 Router 与 Dispatch；Router 的虚线提供索引 $S$ 和 gate，Dispatch 的数据包标出 $(u,g_i)$。专家使用 $u$ 计算 $E_i(u)$，其输出再乘本行对应的 $g_i$。
- **宽专家**：4 个宽度 $H$ 的专家中选中 1、2，两项加权输出进入求和；3、4 只列在 IDLE 名册中。
- **细粒度**：8 个宽度 $H/2$ 的专家中选中 1、2、3、4，四项加权输出都进入求和；其余四个专家本次不执行。
- **细粒度加共享**：共享专家从原始 $u$ 单独接收输入，以系数 1 产生 $E_s(u)$；三个路由输出为 $z_i=g_iE_i(u)$，共同形成 $F(u)=E_s(u)+z_1+z_2+z_3$。
- **残差一致**：每行均在专家输出求和后计算 $h'=u+F(u)$，原始 $u$ 有独立旁路。预算表是说明信息，与计算节点之间没有数据线。

这是一组架构预算对照，选中编号只作示意，不表示不同架构中同名专家共享权重，也不表示将训练好的宽 FFN 直接切片就能保持原函数。表中比较专家 FFN 的矩阵部分；Router 参数、调度、通信和硬件效率另计，实际训练时长需测量。V1–V3 的真实 $N_s,N_r,K_r$ 配置见 [01 DeepSeek-MoE](./01-DeepSeek-MoE/01-DeepSeek-MoE.md)。

Upcycling 复用已训练的 Dense checkpoint 作为 MoE 的参数初值，再继续训练新模型。需要分开看两个阶段：初始化时哪些参数被复制，以及前向时隐藏态如何经过新专家层。

![Upcycling参数初始化：沿用部分复制、四份独立专家副本、随机Router与全模型继续训练](./images/redrawn-fig-moe-upcycling-init-v2.png)

> 图 11A：以一个选中层的两层 MLP 扩为四个专家为例，$d_{\mathrm{model}},d_{\mathrm{ff}}$ 对应后文的 $d,H$。箭头表示参数初值复制、随机初始化和训练流程；每个被改造的层使用自己对应的 Dense FFN 参数。具体模型的完整 FFN 参数组都要复制，包含 bias 或门控投影时也应一并处理。

**初始化与继续训练**

- **沿用部分**：Attention、LayerNorm、Embedding、输出层和未替换的 FFN 从 checkpoint 复制，记为 $\theta_{\mathrm{keep}}^{(0)}=\theta_{\mathrm{keep}}^*$。
- **专家副本**：本层四组参数满足 $\theta_i^{(0)}=\theta_F^*$，$i=1,2,3,4$；它们初值相同、存储独立，后续可以接收不同梯度。
- **新 Router**：$\theta_R^{(0)}$ 随机初始化。随后继续优化新模型的沿用部分、Router 和专家；Attention 结构与初值被保留，不代表它的参数被冻结。优化器状态是否继承需单独配置。[原论文第 3 节](https://arxiv.org/html/2212.05055#S3) 给出了这套初始化与继续训练过程。

![原Dense block完整前向：Attention全段上下文、X与u_t的两次残差及FFN输入](./images/redrawn-fig-moe-upcycling-dense-block-v2.png)

> 图 11B：原 Dense block 的完整主干。Attention 读取整段 $X\in\mathbb R^{T\times d}$；图中展开第 $t$ 行的 FFN 与输出。第一次残差取原始 $X$，第二次取该行归一化前的 $u_t$。

**前向与残差**

第一次残差使用原始 $X$，得到

$$
U=X+\operatorname{Attention}(\operatorname{LN}_1(X)).
$$

取第 $t$ 行 $u_t=U[t]$，再计算 $a_t=\operatorname{LN}_2(u_t)$。Dense FFN 接收 $a_t$，第二次残差保留 $u_t$，所以

$$
y_{D,t}=u_t+F(a_t;\theta_F^*).
$$

![Upcycling后MoE完整block主干与节点9的Router分发专家门控加权求和展开定义](./images/redrawn-fig-moe-upcycling-forward-v2.png)

> 图 11C：MoE block 保留两次残差，只将 FFN 位置替换成 $f_M=M(a_t)$。节点 9 的展开定义给出同一运算的完整内部路径，接口仍为 $a_t\in\mathbb R^d\mapsto f_M\in\mathbb R^d$；灰色关联线表示展开定义。四个专家、Top-2 是说明性配置。与图 11B 对照时使用同一输入和复制后的初值，两模型分别持有各自参数。

Router 与 Dispatch 都接收归一化后的 $a_t$；专家输出合并后，才在 block 主干中加回 $u_t$：

$$
y_{M,t}=u_t+M(a_t)
=u_t+\sum_{i\in S_t}g_{t,i}E_i(a_t;\theta_i^{(0)}).
$$

图中的 $p=(0.42,0.18,0.28,0.12)$ 选中 Expert 1、3；所选两项归一化后 $g_1=0.6,g_3=0.4$。Dispatch 从原始 $a_t$ 形成两个数据包，分支中将向量送进 FFN，将 gate 送到输出乘法；两个加权结果先相加，再加残差 $u_t$。Expert 2、4 的副本仍保留，只是本 token 没有调用它们。

**复制初值何时保持原函数？** 在专家参数一致、Dropout 关闭且输入相同的条件下，$E_i(a_t;\theta_i^{(0)})=F(a_t;\theta_F^*)$。于是

$$
\sum_{i\in S_t}g_{t,i}E_i(a_t;\theta_i^{(0)})
=\left(\sum_{i\in S_t}g_{t,i}\right)F(a_t;\theta_F^*).
$$

当至少一路派遣被接收、实际参与合并的 gate 和为 1 时，图中的 MoE 分支与 Dense 分支相等。如果直接保留 $0.42,0.28$，门控和为 $0.70$，FFN 贡献便缩放为原来的 $0.70$；如果没有分支被接收，FFN 贡献为零，由残差保留 $u_t$。这些条件说明，复制参数本身并不无条件保证整个模型函数保持不变。

在上述相同专家与归一化条件下，固定专家而只调整 Router 也不会改变该 FFN 对固定输入的输出；专家参与后续优化，才可能学成不同函数。原论文的路由与合并归一化配置随任务而异，相关讨论见 [原论文附录 B.7–B.8](https://arxiv.org/html/2212.05055)。图示关系用于理解初始化，实际收益与训练预算仍需依据相应实验。

## 7. 视觉与编码器中的 MoE 分支

V-MoE 的主要例子是视觉 Transformer 中的稀疏派发；Soft-MoE 的原论文研究视觉任务，也展示了对比学习文本编码器。二者的计算对象不同：前者将原始 token 派给所选专家，后者先构造一组加权混合的 slot，再由各专家处理自己的 slot。Soft-MoE 的工作量应按总 slot 数评估。

### 7.1 V-MoE：patch 表征与优先级派遣

ViT 把图像切成 patch，展平后用共享线性投影形成向量序列，再加入位置嵌入。V-MoE 将部分 Encoder block 内的 FFN 替换成稀疏 MoE。容量不足时，BPR 使用本层 Router 权重作为派遣优先级的代理；这不是人工提供的主体／背景标注。被跳过的是相应的专家计算，token 信息仍可经残差保留。[V-MoE 第 2、4 节](https://arxiv.org/html/2106.05974)说明了这些机制。

![ViT的16个patch行优先展平共享投影CLS拼接位置相加与17个Encoder输出位置](./images/redrawn-fig-vit-patches-v2.png)

> 图 12：以带 CLS 的 ViT 入口为例。$4\times4$ 共 16 个 patch，前置一个可学习 CLS 后，Encoder 的序列长度为 17；其中 16 个位置仍对应 patch。$P$ 表示 patch 边长，$C$ 表示通道数，$D$ 表示 embedding 维度。

**图 12 解析**

- **切块与编号**：示例图像为 $I\in\mathbb R^{4P\times4P\times C}$。行、列坐标 $r,c\in\{0,1,2,3\}$ 对应 patch 编号 $i=4r+c+1$，按 $1,2,\ldots,16$ 的行优先顺序排列。
- **展平的是像素**：每个 $P\times P\times C$ patch 形成 $x_i\in\mathbb R^{P^2C}$，堆叠为 $X_p\in\mathbb R^{16\times P^2C}$。格号用于追踪位置，投影的输入是该 patch 的像素向量。
- **共享投影**：所有 patch 使用同一个 $W_{\mathrm{emb}}\in\mathbb R^{P^2C\times D}$，得到 $Z_{\mathrm{patch}}=X_pW_{\mathrm{emb}}\in\mathbb R^{16\times D}$。图中采用线性无 bias 形式；带 bias 的实现还需按行广播相加。
- **CLS 与位置嵌入**：$c_{\mathrm{cls}}\in\mathbb R^{1\times D}$ 沿 token 轴前置，得到 $Q=[c_{\mathrm{cls}};Z_{\mathrm{patch}}]\in\mathbb R^{17\times D}$。随后 $Z_0=Q+E_{\mathrm{pos}}$，其中 $E_{\mathrm{pos}}\in\mathbb R^{17\times D}$；拼接新增一个位置，位置相加保持长度 17。
- **Encoder 与读出**：图中将 Encoder 及最终 LayerNorm 视为复合算子，输出 $Y\in\mathbb R^{17\times D}$。按从 0 开始的序列下标，$Y[0]$ 是 CLS 表征，$Y[1:17]$ 是 16 行 patch 表征。输出行顺序保留，但表征已通过 Attention 融合上下文。V-MoE 的改造位置在 Encoder 内部选中的 FFN，完整 block 结构见图 11。

上述 CLS、共享线性投影和位置嵌入的关系对应 [ViT 第 3.1 节式 (1)](https://arxiv.org/html/2010.11929#S3.SS1)。若采用不含 CLS 的 pooling 变体，本例的长度及位置嵌入表则按 16 行配置；应明确使用哪一种入口与读出设置。

![V-MoE BPR的16条Router记录、Top1与Top2两轮排序、容量状态及完整加权回写](./images/redrawn-fig-vmoe-priority-v2.png)

> 图 13：自构的完整 Top-2 数值例子。一个路由组含 $T=16$ 个 patch token、$E=4$ 个专家、$k=2$，容量比 $C=0.75$，所以每个专家的 buffer 容量为 6。绿色和红色分别表示该次派遣被接收或跳过，不表示 patch 的语义类别。

**图 13 解析**

- **Router 先产生专家选择**：对每个 patch 表征 $x_t$，计算 $g_t=\operatorname{Softmax}(Wx_t+\epsilon)$。表中只列 Top-1、Top-2 及其原始 Router 权重，没有在两个入选项之间重新归一化。优先级取 $s_t=\max_e g_{t,e}$；在本例中它就是 Top-1 权重。
- **BPR 改变尝试顺序**：先完成所有 token 的 rank-1 尝试，再开始 rank-2；同一个 rank 内按 $s_t$ 从高到低处理。本例已按 $t_1,\ldots,t_{16}$ 的顺序构造递减分数。BPR 不会替 token 改选另一个专家，它只决定何时尝试既定的 Top-$k$ 派遣。
- **容量按专家分别检查**：用路由组内 token 总数 $T$ 表示时，

  $$
  B_e=\operatorname{round}\!\left(\frac{kTC}{E}\right)
  =\operatorname{round}\!\left(\frac{2\times16\times0.75}{4}\right)=6.
  $$

  第一轮的 16 条 Top-1 派遣全部被接收，每个专家占用 $4/6$。第二轮仍按同一优先级顺序处理：$t_1$–$t_8$ 的第二选择填满剩余八个槽；$t_9$–$t_{16}$ 的第二选择因目标专家已满而跳过。
- **最终记录守恒**：四个 buffer 各有六条记录，总接收数为 $4\times6=24$。Expert 1 的 token 为 $(1,5,9,13;4,7)$，分号前后分别来自 rank-1、rank-2；另外三行同理。总尝试数为 $16\times2=32$，所以跳过数为 $32-24=8$，与图中红色列表一致。
- **记录如何驱动计算**：最终 buffer 保留索引 $I$ 和对应 gate $G$。原始 $X$ 与 $I$ 进入 Gather／Expert FFN，产生 $V[e,r]=E_e(X[I[e,r]])$；随后 $V$ 与 $(I,G)$ 进入按位置加权回写，得到

  $$
  F_t=\sum_{e,r:I[e,r]=t}G[e,r]V[e,r].
  $$

  图示 $F$ 是 MoE FFN 分支输出，block 的残差在外部相加。跳过一条派遣表示对应专家分支不执行；本例所有 Top-1 都被接收，因此每个 token 至少有一路专家结果。一般的不均衡分布可能使某个 token 的多路选择都失败，需结合残差路径理解最终输出。

“priority” 更准确地说是**派遣优先级**。论文使用 Router 输出作为分类重要性的代理，并明确指出 Router 权重主要编码 token–expert 匹配程度，并非现成的主体／背景分数。[V-MoE 第 4.1 节](https://arxiv.org/html/2106.05974#S4.SS1)给出 $s(x)=\max_i g(x)_i$，也报告过 Top-$k$ 权重和这一替代定义。不同图像的 patch 会在同一个 batch 路由组中共同竞争容量，因此计算量也可以按图像自适应变化。

### 7.2 Soft-MoE：token–slot 混合与两种归一化

Soft-MoE 的一个 **Expert Slot** 是交给某个专家处理的 $d$ 维输入向量，由多个 token 的加权混合形成。前文固定容量槽接收离散派遣的 token；这里每个 slot 的内容来自一个连续加权和。设单序列有 $T$ 个有效 token、$N$ 个专家、每专家 $p$ 个 slot，总数为 $M=Np$。

![SoftMoE同源打分的Dispatch列归一化、Combine行归一化与多slot专家路径](./images/redrawn-fig-soft-moe-v2.png)

> 图 14：$T=3,N=2,p=2,M=4$ 的非因果前馈示例。三个 token 汇聚为四个 slot，每个专家处理两个 slot，再按原 slot 顺序堆叠输出，并混合回三个 token。$D$ 与 $C$ 来自同一打分矩阵，归一化方向不同。

**先打分，再沿两个轴归一化。** 基础公式使用输入 $X\in\mathbb R^{T\times d}$ 与可学习参数 $\Phi\in\mathbb R^{d\times M}$ 计算 $L=X\Phi$。每一列 $\phi_s$ 对应一个 slot 的打分参数。Dispatch 权重为

$$
D_{t,s}=\frac{\exp L_{t,s}}{\sum_{t'=1}^{T}\exp L_{t',s}},\qquad
\sum_{t=1}^{T}D_{t,s}=1.
$$

这是**按 token 轴归一化，每列和为 1**。同一个 $L$ 还产生 Combine 权重：

$$
C_{t,s}=\frac{\exp L_{t,s}}{\sum_{s'=1}^{M}\exp L_{t,s'}},\qquad
\sum_{s=1}^{M}C_{t,s}=1.
$$

这是**按 slot 轴归一化，每行和为 1**。这两个方向属于算法定义；$D,C$ 都是由输入与 $\Phi$ 计算出来的权重矩阵，不能当成两套独立参数或任意替换其归一化轴。定义与实现见[原论文第 2.1 节、Algorithm 1](https://arxiv.org/html/2308.00951#S2.SS1)。

**Slot 的内容与归属。** 两个矩阵乘法都需要完整输入：

$$
U=D^\top X\in\mathbb R^{M\times d},\qquad
u_s=\sum_{t=1}^{T}D_{t,s}x_t.
$$

图中按 expert-major 顺序编号，从 1 开始：$u_1,u_2$ 交给 $F_1$，$u_3,u_4$ 交给 $F_2$。同一专家逐行处理自己的两个输入；不同专家使用各自参数。一般地，该编号下 slot $s$ 的所属专家为 $e(s)=1+\lfloor(s-1)/p\rfloor$，输出为 $v_s=F_{e(s)}(u_s)$。

将结果按 slot 顺序堆叠为 $V\in\mathbb R^{M\times d}$，再计算

$$
Y=CV\in\mathbb R^{T\times d},\qquad
y_t=\sum_{s=1}^{M}C_{t,s}v_s.
$$

所以 $X$ 必须旁路进入 $D^\top X$；$C$ 必须从原始打分路径旁路进入 $CV$。专家输出提供 $V$，不负责生成 $C$。图示 $Y$ 是前馈映射，外层残差按 Transformer 块的定义处理。

**归一化与形状检查。** 若 $L=0$，本图的 $D$ 每个元素为 $1/3$，$C$ 每个元素为 $1/4$：前者列和为 1，后者行和为 1。$U$、$V$ 均有四行，$Y$ 回到三行；slot 数可以与 token 数不同。padding 应在 token 方向的打分归一化与后续使用中正确屏蔽，分母跟有效位置一致。

**计算量与适用条件。** 若单个 slot 的专家函数成本为 $c_F$，基础运算规模为 $O(TdM+Mc_F)$。总 slot 数 $M$ 决定专家调用数，不能简单按“每个专家都对每个原始 token 跑一次”计算。固定 $M$、保持专家结构时，可以改变专家数与每专家 slot 数的分配；参数存储、通信和硬件利用率仍需另外评估。参考[论文第 2.3 节](https://arxiv.org/html/2308.00951#S2.SS3)。

图示使用基础打分式。论文实现还在打分路径对 $X$ 的行、$\Phi$ 的列做 L2 normalization，并加入可学习 scale；这与 $D,C$ 各自的 Softmax 归一化轴是不同层面的操作。全序列混合适用于本图的非因果场景；若直接用于自回归解码，会涉及未来信息，必须重新处理因果约束。原论文将此列为[尚待解决的限制](https://arxiv.org/html/2308.00951#S6)。

## 8. 失效模式

| 现象 | 原因 | 说明 |
|------|------|------|
| 专家坍塌 | Token-Choice 无均衡 | $f_i$ 集中;式 (9) 或 aux-loss-free 偏置就是在打这个 |
| $\gamma=1$ 仍大量 drop | 局部溢出 | 总槽数够也不够:热专家先满.先查 $f_i$,再加 $\gamma$ |
| token 溢出 | $\gamma$ 偏小 / 负载更偏 | 残差跳过本层专家;batch 内互相抢槽.不是从序列里删 token |
| 把 $\gamma$ 拉到 $11$ 仍不稳 | Tutel 动态容量尖刺 | MegaBlocks:与其堆 padding,不如变长 block-sparse |
| 微调丢 $10\%$ token 就慌 | 预训练直觉套用错阶段 | ST-MoE Table 5:微调对 drop 不敏感;aux-loss 仍建议开 |
| 路由翻转,损尖峰 | logits 过大,低精度 Softmax | 式 (11) + Router FP32.Switch Table 2:整网 bf16 会发散 |
| 混淆不同约束 | logits 截断、update clipping 与 z-loss 作用位置不同 | ST-MoE 对紧 update clipping 与 z-loss 分别做过实验，应区分解释 |
| 把式 (9) 写进推理 | 训练正则误当门控 | $L_{\mathrm{balance}}$ / $L_z$ 只加在训练损失 |
| 把 Expert-Choice 的 $c$ 当成 Switch 的 $\gamma$ | 记号撞车 | 前者是每 token 平均专家数,后者是均匀分流之上的缓冲倍数 |
| 小数据 SFT 过拟合 | 稀疏总容量大,激活路径多 | 不要指望几条样本把所有专家都训到位 |
| 把 $\ell$ 写成 MLA | 两个「潜空间」同名 | LatentMoE 的 $\ell$ 在 FFN;MLA 的 $c^{KV}$ 在注意力 |

MiniMax-M2 用 sigmoid 门,每 token 8/256 细粒度专家,对照 Softmax Top-$K$;产品捆在 [MiniMax-M2 正本](../../../../model-library/03-模型家族/18-minimax/minimax-m2/minimax-m2-bi.md),不在这页展开.
