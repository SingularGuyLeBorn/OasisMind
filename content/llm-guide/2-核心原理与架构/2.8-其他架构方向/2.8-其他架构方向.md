# 2.8 · 前沿架构与变体

## 1. 本章的问题

标准 decoder-only Transformer 有几处固定的成本结构, 本章每一节改动其中一处:

1. **参数量等于每 token 的激活量.** 稠密模型每个 token 都要经过全部 FFN 参数. 条件计算 (MoE) 让每个 token 只激活少数专家, 条件记忆 (Engram) 把一部分参数做成按 token ID 查的表.
2. **注意力随序列长度平方增长, KV 缓存随长度线性增长.** 状态空间模型、Mamba、线性 RNN 用固定大小的状态做递推; 混合模型只保留少量注意力层.
3. **每次前向只出一个 token.** MTP 在训练时让每个位置多预测几个 token, 推理时可以当投机解码的草稿; 扩散语言模型换成并行去噪的生成过程.
4. **深度和参数绑定.** 循环 Transformer 只存 $K$ 个块, 前向转 $R$ 轮, 展开深度 $N=KR$.
5. **训练目标只在 token 空间.** LLM-JEPA 在 next-token 损失上加一项嵌入空间的预测损失.

这些改动彼此独立, 可以组合. 例如 Jamba 同时用了 Mamba、注意力和 MoE, DeepSeek-V3 同时用了 MoE 和 MTP.

## 3. 阅读顺序

先读 2.4.1, 理解参数量和每次激活量为什么能分开. 之后按问题选:

- 长序列、KV 缓存太大: 2.4.2 → 2.4.3 → 2.4.4 → 2.4.5.
- 解码太慢或想要更密的训练信号: 2.4.6; 换成非自回归生成: 2.4.7.
- 静态局部模式、可放到 Host 内存的参数表: 2.4.8.
- 想在不加参数的情况下加深度: 2.4.9.
- 训练目标本身: 2.4.10.

注意力核与 KV 表示 (MHA、GQA、MLA、线性注意力) 在 2.3 章.
