# 2.8 · 其他架构方向

标准 decoder-only Transformer 把几件事绑在一起: 训练时每个位置只学下一个 token, 生成时从左到右一次出一个, 记事实和做多步组合共用同一批稠密参数, 深度增加参数就跟着增加. 注意力的平方代价和 KV 缓存由 [2.5 线性注意力与状态空间模型](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md) 处理, 稠密 FFN 的计算由 [2.6 MoE](../2.6-MoE/2.6-MoE.md) 处理. 这一章收的是剩下五个方向, 每个方向松开上面的一处绑定.

前两个方向改训练目标和生成方式: [2.8.1 多 token 预测](./2.8.1-多Token预测MTP/2.8.1-多Token预测MTP.md) 让每个位置多预测后面几个 token, [2.8.2 扩散语言模型](./2.8.2-扩散语言模型DLM/2.8.2-扩散语言模型DLM.md) 去掉从左到右的顺序. 中间两个方向改参数组织: [2.8.3 条件记忆与 Engram](./2.8.3-条件记忆与Engram/2.8.3-条件记忆与Engram.md) 把一部分参数做成按 token 查的表, [2.8.4 循环 Transformer](./2.8.4-循环Transformer/2.8.4-循环Transformer.md) 让同一组层反复执行. 最后一个 [2.8.5 LLM-JEPA](./2.8.5-LLM-JEPA/2.8.5-LLM-JEPA.md) 在嵌入空间里加一项损失.

## 1. 五处绑定

### 1.1 记号

全章沿用两组记号. 序列记为 $x_1,\dots,x_T$, 标准目标是逐位置的下一 token 交叉熵

$$
L_1=-\sum_t\log P_\theta(x_{t+1}\mid x_{t:1}). \tag{1}
$$

参数侧把总参数记为 $P_{\mathrm{tot}}$, 每 token 实际参与计算的记为 $P_{\mathrm{act}}$. 稠密模型两者相等; MoE 和 Engram 让 $P_{\mathrm{act}}<P_{\mathrm{tot}}$, 循环 Transformer 走另一个方向, 参数不变而每 token 计算按展开深度 $N=KR$ 增长, $K$ 是存下来的物理块数, $R$ 是轮数.

五个方向与式 (1) 的关系各不相同. MTP 在式 (1) 之外加几项更远位置的交叉熵, 主损失不变; 扩散语言模型把式 (1) 的从左到右分解整个换掉, 改成对随机遮住的位置做预测; LLM-JEPA 保留式 (1), 再加一项嵌入之间的余弦距离. Engram 和循环 Transformer 不碰式 (1), 改的是同一个式子背后参数怎么摆, 计算怎么走.

### 1.2 改动的位置

这些改动大多落在训练目标和参数组织上, 注意力核与 FFN 结构基本不动. MTP 加的是与主干同构的 Transformer 块, 推理时可以整个丢掉; LLM-JEPA 连新参数都不加, 预测器复用模型自身的权重; Engram 在第 2 层附近插一个查表模块, 骨干照常是注意力加 MoE; 循环 Transformer 的块就是标准层, 只是被访问 $R$ 次. 扩散语言模型改得最深, 去掉了因果掩码, LLaDA 因此也改用普通多头注意力.

改动位置决定了能不能叠在现有模型上. MTP 和 Engram 已经进入主流模型: DeepSeek-V3 和 V4 带深度为 1 的 MTP, Kimi K3 把 MTP 层微调成投机解码的草稿, Qwen3.8-Flash-Next 带 Engram. 循环 Transformer 和 LLM-JEPA 的公开结果仍在 1B 到 3.5B 的研究模型上, 扩散语言模型的代表 LLaDA 是 8B.

## 2. 改训练目标与生成方式

### 2.1 多预测几步

Gloeckle 等人 (2024) 用共享主干加 $n$ 个并行头, 让每个位置预测后面 $n$ 个 token. 7B 模型在 200B token 代码上, $n=4$ 把 MBPP pass@1 从 30.0 提到 33.8; 小模型上 MTP 反而更差, 自然语言选择题上 $n=4$ 略有退步. 额外的头可以直接当草稿做自投机解码, 代码上加速 3.0 倍. DeepSeek-V3 改成顺序模块: 第 $k$ 个模块把第 $i+k$ 个真实 token 的嵌入拼进输入, 保持因果链, 取深度 $D=1$, 小 MoE 上 HumanEval 从 20.7 升到 26.8, 推理时第二个 token 接受率 85% 到 90%, 解码提速 1.8 倍.

之后 MTP 的角色从训练辅助目标偏向内置草稿模型. MiniMax-M2 在退火阶段把 MTP 模块从 1 个扩到 3 个, 新模块复制主模型权重初始化. Kimi K3 冻结目标模型, 把 MTP 层按 EAGLE-3 协议微调, 直接最小化接受率的负对数. K3 报告也指出了一个冲突: KDA 层的递推状态每步原地更新, 验证拒绝部分草稿后无法直接回滚, 这是线性注意力与投机解码结合的共同问题.

### 2.2 去掉从左到右

掩码扩散语言模型的前向过程按比例 $t$ 随机把 token 换成掩码, 反向过程同时预测所有被遮位置. 采样从全掩码开始, 每步把置信度最低的一部分预测重新遮住; 回答长 8, 走 4 步时每步揭开 2 个 token. 步数等于长度时前向次数与自回归相同, 步数更少时同一步揭开的 token 互相看不到取值. 因为没有因果掩码, 每步都要对全序列重算, LLaDA 论文明确说它与 KV 缓存不兼容.

LLaDA 8B 在 2.3T token 上预训练, MMLU 65.9 与训练了 15T 的 LLaMA3 8B 相当, GSM8K 70.3 对 48.7, BBH 49.7 对 62.1 落后; 两者数据不同, 架构层面的比较要看同数据的规模曲线, 那里两者可比. 反转诗句补全上 LLaDA 正向 51.8, 反向 45.6, 反向超过 GPT-4o 的 34.3, 但正向低 30 多个点. MDLM 在 GPT-2 规模上与自回归的困惑度差距在 15% 到 25% 之间.

### 2.3 在嵌入空间加一项

LLM-JEPA 保留式 (1), 再加 $\lambda\cdot d(\mathrm{Pred}(\mathrm{Enc}(\mathrm{Text})),\mathrm{Enc}(\mathrm{Code}))$: 让同一内容的一个视图 (自然语言描述) 的表示去预测另一个视图 (正则, SQL, 代码) 的表示, 度量是余弦距离. 编码器取最后一层最后一个 token 的隐状态, 预测器靠在输入末尾追加 $k$ 个 `[PRED]` token 实现, 不增加参数. 防塌缩没有用视觉 JEPA 的 EMA 目标编码器, 靠的是生成项本身: 生成项权重为 0 时模型只输出空串.

Llama-3.2-1B-Instruct 在 NL-RX-SYNTH 上从 57.29 升到 71.46, OpenELM 翻了一倍多, OLMo 基线已有 87% 只多 0.43 个点; GSM8K 上推理模型的提升约 1 个百分点. 两个视图要分开编码, 训练计算约为两倍; 按批次随机丢弃 75% 的 JEPA 项, 成本降到 1.25 倍, 同预算下反而最好. 实验几乎都依赖天然成对的数据, 没有类似视觉数据增强的机制之前, 这个目标还用不到任意语料上.

## 3. 改参数组织

### 3.1 把一部分参数做成表

专名, 成语, 固定搭配这类局部静态模式, Transformer 只能在早期层用注意力和 FFN 逐层拼出来. Engram 用压缩后的后缀 $n$-gram 做多头哈希, 从大嵌入表里取向量, 经上下文门控加进残差. 地址只依赖 token ID, 进入网络前就能算出, 表可以放在 Host 内存里经 PCIe 预取; 100B 参数的表插在 8B 骨干第 2 层, H800 上吞吐只降 2.8%. 把 MoE 的稀疏参数按比例 $\rho$ 分给专家和表, 验证损失随 $\rho$ 呈 U 形, 最优大约把 20% 到 25% 给表.

同激活 3.8B, 同总参的对照里, Engram-27B 相对 MoE-27B 在 BBH 上 +5.0, MMLU +3.0, 事实问答 TriviaQA 只 +1.9; 推理和代码的增幅大于事实问答, 论文的解释是早期层不再重建套话, 有效深度让了出来. 推理时把表的输出置零, 事实类基准只剩原来的 29% 到 44%, 阅读理解还留 81% 到 93%, 表主要承担参数化事实.

### 3.2 让同一组层反复执行

循环 Transformer 走相反的方向: 参数少, 计算多. 只存 $K$ 个物理块, 同一套块转 $R$ 轮. Saunshi 等人的合成任务上, 一层转 12 次就能把 32 个数相加的准确率从 0.0 拉到 99.6; 但在 Pile 上预训练时, 24 层基线困惑度 7.40, $(12\otimes2)$ 循环模型是 7.90, 推理类分数更高, 闭卷问答补不回参数缺口. 循环的收益集中在多步组合, 记事实仍要靠参数, 这和 Engram 的分工结论正好互补.

Huginn 把轮数当作推理阶段的算力: 3.5B 参数, 轮数从 4 加到 32, ARC-E 从 49.07 升到 69.91, 16 圈之后收益饱和. 展开深度变大后残差容易爆炸, 12 圈的普通循环模型训练失败, Fully Looped 改接线, DeepLoop 改 DeepNorm 的缩放指数. Mixture-of-Recursions 和 Ouro 进一步按 token 分配轮数, 前者借用 MoE 的路由术语, 路由的对象是「这个 token 再进几轮」.

## 4. 对照与组合

### 4.1 五个方向的对照

| 方向 | 改动的环节 | 推理成本变化 | 代表工作的规模 | 收益最稳的领域 |
|---|---|---|---|---|
| MTP | 训练目标加远位置 token | 可丢弃; 当草稿时提速 1.8 倍起 | DeepSeek-V3, Kimi K3 | 代码, 数学 |
| 扩散语言模型 | 生成顺序 | 无 KV 缓存, 每步全序列重算 | LLaDA 8B | 数学, 反向补全 |
| Engram | 一部分稀疏参数改成表 | 每 token FLOPs 不增, 吞吐降约 2% 到 3% | Engram-27B, Qwen3.8-Flash-Next | 推理, 代码, 长上下文 |
| 循环 Transformer | 深度与参数解绑 | 每 token 计算随轮数增长 | Huginn 3.5B | 多步组合推理 |
| LLM-JEPA | 加嵌入空间损失 | 推理无额外开销, 训练约 2 倍 | 1B 到 8B 微调 | 成对数据上的生成 |

第三列把五个方向按部署代价分开. MTP 和 LLM-JEPA 的额外成本落在训练侧, 推理时可以完全不付; Engram 不加每 token 计算, 代价是要放得下大表和 PCIe 带宽; 循环 Transformer 和扩散语言模型的推理计算会增加, 前者随轮数, 后者随采样步数与序列长度. 扩散语言模型还换掉了 KV 缓存这套推理基础设施, 迁移成本最高.

最后一列是各自论文里提升最稳定的地方, 不是适用范围. MTP 在自然语言选择题上 $n=4$ 退步, 大 MoE 的 MMLU 也从 67.5 降到 66.6; 扩散语言模型的 BBH 落后; LLM-JEPA 在 OLMo 这类基线已很高的设置上提升很小. 读这些数字时要看清对照组: LLaDA 与 LLaMA3 训练数据不同, Huginn 的固定深度对照是同数据训到 180B token 的小模型, 只有 Engram-27B 和 DeepSeek-V3 的 MTP 消融是同课表, 同激活参数的对照.

### 4.2 组合与边界

这些改动彼此独立, 可以叠加. DeepSeek-V3 同时用了 MoE 和 MTP; Engram 本来就和 MoE 分摊同一笔稀疏参数, 骨干还用了 [mHC](../2.1-深度学习基础组件/2.1.3-残差连接/01-Hyper-Connections与mHC/01-Hyper-Connections与mHC.md) 的多分支残差; 扩散的生成过程也可以配 MoE 骨干. 叠加时要注意接口冲突: 线性注意力的原地状态和 MTP 草稿的回滚冲突, 循环 Transformer 按 token 早停会留下缺失深度的 KV, 扩散语言模型没有因果顺序, 也就用不上从左到右的投机解码.

几个方向在同一个问题上给出了一致的信号: 记事实靠参数, 多步组合靠深度或计算. Engram 的置零实验, Saunshi 的闭卷问答, Ouro 测得的约 2 bit 每参数都指向这一点. MTP 的选择点分析和 LLM-JEPA 的表示分析则说明, 只改训练目标也能改变隐状态里编码的内容, 但两篇都把机制解释写成推测, 没有单独检验因果.

## 5. 读的顺序

### 5.1 按想解决的问题读

解码太慢的读者从 [2.8.1](./2.8.1-多Token预测MTP/2.8.1-多Token预测MTP.md) 读起, 第 3 节 DeepSeek-V3 的顺序模块和第 4.2 节 Kimi K3 的草稿微调最直接; 投机解码本身的原理在 [6.6.2 投机解码](../../6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/6.6.2-投机解码.md). 想换掉自回归生成的读者读 [2.8.2](./2.8.2-扩散语言模型DLM/2.8.2-扩散语言模型DLM.md), 第 4 节的采样与 KV 缓存讨论决定了它的推理代价.

关心参数怎么摆的读者先读 [2.6 MoE](../2.6-MoE/2.6-MoE.md), 弄清总参数与激活参数为什么能分开, 再读 [2.8.3](./2.8.3-条件记忆与Engram/2.8.3-条件记忆与Engram.md) 的 U 形分配曲线和 [2.8.4](./2.8.4-循环Transformer/2.8.4-循环Transformer.md) 的 $(k\otimes L)$ 实验, 两者正好是同一问题的两个方向. 只想改训练目标, 不动架构的读者读 [2.8.5](./2.8.5-LLM-JEPA/2.8.5-LLM-JEPA.md), 它的训练代码只多一次前向.

### 5.2 与相邻章节

注意力核与 KV 表示 (MHA, GQA, MLA) 在 2.2, 高效实现与稀疏注意力在 [2.3](../2.3-注意力的高效实现/2.3-注意力的高效实现.md) 和 [2.4](../2.4-稀疏注意力/2.4-稀疏注意力.md), 线性注意力, SSM, Mamba 和混合模型在 [2.5](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md). 这一章的五个方向和它们正交: Kimi K3 同时有 KDA 线性注意力和 MTP, 两者的冲突正是 2.8.1 第 4.2 节讨论的回滚问题.

扩散语言模型有一个单独的兄弟花园, 后续模型, 块扩散, KV 缓存近似和强化学习都在那里, 2.8.2 第 5.4 节末尾给了入口. 循环 Transformer 与 CoT 的关系, 即沿深度思考和沿 token 思考的区别, 可以对照 [4.8 推理与 Agent 能力](../../4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).
