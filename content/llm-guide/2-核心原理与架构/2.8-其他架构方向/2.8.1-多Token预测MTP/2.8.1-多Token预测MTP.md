# 2.8.1 · 多 token 预测 (MTP)

材料是 Gloeckle 等人 ([2404.19737](https://arxiv.org/abs/2404.19737)) 的并行多头实验, DeepSeek-V3 报告 ([2412.19437](https://arxiv.org/abs/2412.19437)) 的顺序 MTP 模块, 以及 DeepSeek-V4, MiniMax-M2, Kimi K3 报告里沿用和改造 MTP 的部分. 问题是: 让每个位置额外预测后面几个 token, 训练能得到什么, 推理能省多少, 代价落在哪里.

## 1. 问题: 下一 token 预测只看一步

### 1.1 标准目标

给定语料 $x_1,\dots,x_T$, 标准语言模型最小化交叉熵 (Gloeckle 等人式 1):

$$
L_1=-\sum_t\log P_\theta(x_{t+1}\mid x_{t:1}). \tag{1}
$$

$$
\underbrace{x_{t:1}=x_t,\dots,x_1}_{\text{已观察到的前缀}},\qquad
\underbrace{P_\theta}_{\text{待训练的模型}}
$$

训练用 teacher forcing: 每个位置的输入都是真实前缀, 模型只需要做好「下一步」. Gloeckle 等人在引言中指出, 这种训练方式抓住的是局部模式, 容易忽略「难」的决策; 达到同样的语言流畅度, 当前的下一 token 模型所需的数据比儿童多出几个数量级.

### 1.2 改目标的两个动机

**训练信号.** 每个位置多预测几步, 相当于要求隐状态里提前编码后面几步需要的信息.

**推理速度.** 解码一步只出一个 token, 大模型解码受内存带宽限制. 如果模型本身就能猜后面几个 token, 就可以用投机解码一次验证多个, 不需要单独训练草稿模型. 投机解码本身的原理见 [6.6.2](../../../6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/6.6.2-投机解码.md).

## 2. Gloeckle 等人: 共享主干加并行头

### 2.1 目标, 结构与实现

把式 (1) 推广为每个位置预测后面 $n$ 个 token (原文式 2):

$$
L_n=-\sum_t\log P_\theta(x_{t+n:t+1}\mid x_{t:1}). \tag{2}
$$

为了可计算, 论文假设模型先用共享的 Transformer 主干 $f_s$ 把前缀编码成 $z_{t:1}$, 再由 $n$ 个独立的头分别预测:

$$
P_\theta(x_{t+i}\mid x_{t:1})=\mathrm{softmax}\Bigl(f_u\bigl(f_{h_i}(f_s(x_{t:1}))\bigr)\Bigr),\quad i=1,\dots,n. \tag{3}
$$

$$
\underbrace{f_s}_{\text{共享主干}},\quad
\underbrace{f_{h_i}}_{\text{第 }i\text{ 个头, 一层 Transformer}},\quad
\underbrace{f_u}_{\text{共享的反嵌入矩阵}}
$$

于是式 (2) 分解成 $n$ 项交叉熵之和, $i=1$ 那一项就是普通的下一 token 预测头. 这里的关键假设是: 给定 $z_{t:1}$ 后, 后面 $n$ 个 token 的预测互相独立. 第 2 个头预测 $x_{t+2}$ 时看不到 $x_{t+1}$ 是什么.

实现上有两处要处理. 一是显存: 词表大小 $V$ 远大于隐藏维度 $d$, logits 是显存瓶颈. 如果同时为 $n$ 个头生成 logits 和梯度, 形状都是 $(n,V)$, 批大小会被严重压缩. 论文的做法是: 主干前向之后, 依次对每个头做前向和反向, 把梯度累加到主干输出上, 每个头的 logits 用完立即释放. 峰值显存从 $O(nV+d)$ 降到 $O(V+d)$, 运行时间不变 (附录表 S5).

二是比较的公平性: 多出的 $n-1$ 个头各是一层 Transformer. 为了不让参数量增加, 论文在比较时把主干减少 $n-1$ 层, 总参数与基线相同.

### 2.2 其他头结构

论文附录 B 还试了几种替代结构, 都在 7B、200B token 代码、$n=4$ 的设置下与并行头比较 (表 S4):

| 头结构 | MBPP pass@1 | HumanEval pass@1 | HumanEval pass@100 |
|---|---|---|---|
| 基线 ($n=1$) | 30.0 | 22.8 | 62.0 |
| 线性头, 并行 | 33.6 | 21.9 | 63.7 |
| Transformer 头, 反因果 | 30.8 | 20.9 | 64.5 |
| Transformer 头, 因果 | 31.9 | 20.9 | 67.3 |
| Transformer 头, 并行 | 33.8 | 24.0 | 66.1 |

因果变体让第 $i$ 个头叠在前 $i-1$ 个头之上, $f_{h_i}\circ f_{h_{i-1}}\circ\cdots\circ f_{h_1}\circ f_s$; 反因果变体先预测最远的 token, 再逐步细化到下一个. 线性头相当于对主干表示做线性探测. 论文的结论是这些结构都优于基线, 但没有一种比并行头更稳定. 复制 $n$ 份反嵌入矩阵也是一种实现, 但需要 $(d,nV)$ 的矩阵, 大规模训练无法承受.

注意这里的「因果」变体只是把头串起来, 输入仍然只有 $z_{t:1}$, 不包含中间 token 的嵌入. 第 3 节 DeepSeek-V3 的做法在这一点上不同.

### 2.3 代码上的结果

**规模.** 在至少 91B token 代码上从头训练 300M 到 13B 的六档模型 (图 3). 小模型上 MTP 反而更差, 规模变大后反超. 论文认为「只在规模上有用」可能是 MTP 长期被忽视的原因. 摘要报告 13B 模型在 HumanEval 上多解出 12% 的题, MBPP 上多 17%.

**$n$ 的选择.** 7B 模型、200B token 代码数据 (表 1):

| $n$ | MBPP pass@1 | HumanEval pass@1 |
|---|---|---|
| 1 (基线) | 30.0 | 22.8 |
| 4 | 33.8 | 24.0 |

$n=4$ 在 HumanEval 和 MBPP 的 pass@1、10、100 上都最好; APPS/Intro 上 $n=6$ 最好. 论文认为最优窗口取决于数据分布.

**字节级.** 第 3.3 节把分词推到极端: 7B 字节级模型在 314B 字节 (约合 116B token) 上训练. 8-byte 预测模型的 MBPP pass@1 为 32.3, 下一字节基线只有 19.3, 多解出 67% 的题; HumanEval pass@1 多 20%. 字节级的最优 $n$ 在各评测上都稳定在 8. 论文认为这说明下一 token 预测确实偏向局部模式, 粒度越细, 这个问题越明显.

**多轮训练.** 1T token (4 个 epoch) 时优势缩小但仍在, MBPP pass@1 为 43.1 对 40.7.

**微调.** 在 CodeContests 上微调时, 4-token 预训练的模型无论用 4-token 还是普通下一 token 目标微调, 都优于基线; 去掉额外头、用下一 token 目标微调效果最好.

### 2.4 自投机解码

额外的头可以直接当草稿: 先用 $n$ 个头一次猜出 $n$ 个 token, 再用下一 token 头并行验证. 论文第 3.2 节在 7B 的 4-token 模型上用贪心自投机解码: 代码上平均每 3 个猜测接受 2.5 个, 加速 3.0 倍; 文本上 2.7 倍; 8-byte 模型加速 6.4 倍.

手算一下接受数与加速的关系. 每次前向产出 1 个由下一 token 头确定的 token, 加上被接受的猜测. 平均接受 2.5 个时, 每次前向约产出 3.5 个 token. 附录表 S2 给出了用不同数量的头时的实测 (代码模型训练 1T token, 文本模型训练 500B token, 批大小 42, 生成 512 个 token):

| 使用的头数 | Wikipedia 加速 | 每次前向 token 数 | 代码加速 | 每次前向 token 数 |
|---|---|---|---|---|
| 1 | 1.00 | 1.00 | 1.00 | 1.00 |
| 2 | 1.79 | 1.88 | 1.85 | 1.94 |
| 3 | 2.35 | 2.57 | 2.54 | 2.78 |
| 4 | 2.74 | 3.12 | 3.05 | 3.50 |

用 $k$ 个头时加速的上限是 $k$. 每多用一个头, 每次前向多产出的 token 数递减: 代码上依次多 0.94、0.84、0.72 个, 因为越远的猜测越难被接受. 实测加速始终低于每次前向的 token 数, 差值是同时做验证和预测带来的额外计算. 论文说明这个加速比在不同批大小下基本不变 (图 S10).

字节级模型的加速更大 (表 S3): $n=32$ 的字节模型用满 32 个头时, 每次前向产出 15.35 个字节, 加速 10.84 倍.

### 2.5 自然语言上的结果

论文第 3.7 节在 7B、200B token 的自然语言数据上训练 $n=1,2,4$ 三个模型.

- 6 个标准选择题评测: $n=2$ 与基线持平, $n=4$ 略有退步. 论文认为选择题和基于似然的评测不适合区分生成能力, 也可能需要更大的模型才能看到提升.
- 8 个摘要评测 (ROUGE-L): $n=2$ 和 $n=4$ 都优于基线, 训练数据从 200B 增到 500B 时差距缩小.
- GSM8K (8-shot): 200B token 时 $n=2$ 明显优于基线, 500B token 时反过来, $n=4$ 始终更差.

代码上的收益在自然语言上没有稳定复现. 这一点限定了 MTP 收益的适用范围.

### 2.6 为什么可能有用

论文第 5 节标题为「一些推测」, 给了两个解释.

**选择点.** 文本中有些 token 是关键决策 (选择点), 决定后续内容; 有些只是风格变化. 论文用图 9 的例子数损失项: $n$-token 预测给选择点的权重为 $n(n+1)/2$, 给无关紧要的点权重为 $n$. $n=4$ 时两者之比为 $10:4$, 选择点被加权了 2.5 倍. 具体数法放在本节末尾.

**信息论分解.** 记 $X$ 为下一个 token, $Y$ 为再下一个, 省略对前缀的条件. 下一 token 预测关心 $H(X)$, 2-token 预测关心 $H(X)+H(Y)$. 分解为

$$
H(X)=H(X\mid Y)+I(X;Y),\qquad
H(X)+H(Y)=H(X\mid Y)+2I(X;Y)+H(Y\mid X). \tag{4}
$$

$$
\underbrace{H(X\mid Y)}_{\text{不影响后文的局部变化}},\quad
\underbrace{I(X;Y)}_{\text{X 中约束后文的信息}},\quad
\underbrace{H(Y\mid X)}_{\text{下一位置的普通下一 token 熵}}
$$

$H(Y\mid X)$ 在下一个位置还会作为下一 token 损失出现, 去掉它后, 2-token 预测把互信息 $I(X;Y)$ 的权重提高了一倍. 也就是说, 对后文有影响的那部分 $X$ 被更重地训练.

**归纳能力.** 第 4.1 节在儿童故事数据上训练 1M 到 1B 非嵌入参数的小模型, 测两 token 名字中第二个 token 的预测准确率. 30M 及以下时, 2-token 预测明显帮助归纳头的形成; 到 100M 时优势消失. 论文的解释是 MTP 帮助模型学会跨位置传递信息, 一旦归纳能力形成, 这个任务就变成了可以在当前位置局部解决的下一 token 任务.

**算法推理.** 第 4.2 节用多项式环 $\mathbb F_7[X]/(X^5)$ 上的运算 (取负、加、乘、复合) 做任务, 训练时每个表达式含 1 到 5 个运算, 评估阶段用超过 5 个运算的表达式测分布外泛化. 30M 和 100M 非嵌入参数的模型上, MTP 在各难度上都提高准确率, 分布外的提升尤其明显, 尽管绝对值很低. 把模型从 30M 放大到 100M 带来的提升, 小于把下一 token 换成 MTP 带来的提升.

附录 L.3 给出了选择点权重的数法. 设 $x_t\to x_{t+1}$ 是选择点, 走错会得到 $\tilde x_{t+1}$, 之后的路径 $\tilde x_{t+2},\tilde x_{t+3},\dots$ 也全部不同. 看位置 $t-n+i$ ($i=1,\dots,n$) 上的 $n$-step 预测: 它要预测 $x_{t-n+i+1},\dots,x_{t+i}$, 其中越过选择点的 $i$ 个目标都会因为选错而出错. 把 $i=1$ 到 $n$ 加起来, 与这个选择点及其后果相关的损失项共 $1+2+\cdots+n=n(n+1)/2$ 个. 无关紧要的转移 (之后的路径马上汇合) 只在 $n$ 个位置上各被预测一次, 共 $n$ 项. 所以选择点在 $n$-step 预测中的相对权重平均是下一步预测的 $(n+1)/2$ 倍. $n=2$ 时为 3 项对 2 项, $n=4$ 时为 10 项对 4 项.

## 3. DeepSeek-V3: 顺序 MTP 模块

### 3.1 结构

DeepSeek-V3 报告第 2.2 节说明了引入 MTP 的两个理由: 一是让训练信号更密, 可能提高数据效率; 二是让模型提前规划表示, 以便更好地预测未来 token. 报告用 $D$ 个顺序模块预测后面 $D$ 个额外 token. 第 $k$ 个模块由共享嵌入层 $\mathrm{Emb}$、共享输出头 $\mathrm{OutHead}$、一个 Transformer 块 $\mathrm{TRM}_k$ 和投影矩阵 $M_k\in\mathbb R^{d\times2d}$ 组成. 对第 $i$ 个输入 token, 第 $k$ 个深度先把上一深度的表示与第 $i+k$ 个 token 的嵌入拼接 (原文式 21):

$$
h_i'^{\,k}=M_k\Bigl[\mathrm{RMSNorm}(h_i^{k-1});\ \mathrm{RMSNorm}\bigl(\mathrm{Emb}(t_{i+k})\bigr)\Bigr]. \tag{5}
$$

$$
\underbrace{h_i^{k-1}}_{\text{上一深度在位置 }i\text{ 的表示, }k=1\text{ 时为主模型输出}},\quad
\underbrace{t_{i+k}}_{\text{第 }i+k\text{ 个真实 token}},\quad
\underbrace{[\,\cdot\,;\,\cdot\,]}_{\text{拼接, 得到 }2d\text{ 维}}
$$

然后经过 Transformer 块和共享输出头 (式 22、23):

$$
h_{1:T-k}^{k}=\mathrm{TRM}_k\bigl(h_{1:T-k}'^{\,k}\bigr),\qquad
P_{i+k+1}^k=\mathrm{OutHead}(h_i^k). \tag{6}
$$

$P_{i+k+1}^k\in\mathbb R^V$ 是第 $k$ 个模块对第 $i+k+1$ 个 token 的预测分布. 序列长度 $T$ 内只有前 $T-k$ 个位置有可预测的目标, 所以 $\mathrm{TRM}_k$ 作用在 $1{:}T-k$ 上.

和第 2 节的并行头对比, 差别在输入. 第 2 节的第 $i$ 个头只看 $z_{t:1}$, 不知道前面几个 token 是什么. V3 的第 $k$ 个模块把第 $i+k$ 个 token 的嵌入拼进输入, 并接在第 $k-1$ 个模块的输出之后, 预测第 $i+k+1$ 个 token 时已经知道第 $i+1$ 到 $i+k$ 个 token. 报告说明这一点参考了 EAGLE, 目的是保持每个预测深度的完整因果链. 代价是 $D$ 个模块只能顺序计算.

### 3.2 损失

第 $k$ 个深度的损失 (式 24):

$$
\mathcal L_{\mathrm{MTP}}^k=-\frac1T\sum_{i=2+k}^{T+1}\log P_i^k[t_i]. \tag{7}
$$

$P_i^k[t_i]$ 是第 $k$ 个模块对第 $i$ 个位置真实 token 的预测概率. 所有深度取平均再乘权重 $\lambda$ (式 25):

$$
\mathcal L_{\mathrm{MTP}}=\frac{\lambda}{D}\sum_{k=1}^{D}\mathcal L_{\mathrm{MTP}}^k. \tag{8}
$$

总损失为主模型的下一 token 损失加上 $\mathcal L_{\mathrm{MTP}}$.

手算一个小例子看下标. 输入为 $t_1,\dots,t_T$, 训练目标一直到 $t_{T+1}$. 取 $T=6$, $D=1$:

- 主模型在位置 $i=1,\dots,6$ 预测 $t_{i+1}$, 目标为 $t_2,\dots,t_7$, 共 6 项.
- MTP 模块只作用在位置 $1{:}T-k=1{:}5$. 位置 $i$ 的输入是 $h_i^0$ 与 $\mathrm{Emb}(t_{i+1})$ 的拼接, 预测 $t_{i+2}$, 目标为 $t_3,\dots,t_7$, 共 5 项, 对应式 (7) 中 $i=3,\dots,7$.
- 位置 6 没有 MTP 输出, 因为它需要 $t_7$ 的嵌入作为输入, 而 $t_7$ 只是标签.

式 (7) 前面除以 $T$ 而不是 $T-k$, 序列很长时两者的差别可以忽略.

### 3.3 配置和训练布局

V3 取 $D=1$, 即只多预测一个 token. $\lambda$ 在前 10T token 为 0.3, 剩余 4.8T token 为 0.1.

按 V3 的配置估算 MTP 模块的规模. 主模型 61 层, 隐藏维度 $d=7168$; 除前 3 层外, FFN 都是 MoE (1 个共享专家加 256 个路由专家, 每个 token 激活 8 个). 投影矩阵 $M_1\in\mathbb R^{d\times2d}$ 的参数量为 $2d^2=2\times7168^2\approx1.03\times10^8$, 约 1 亿. $\mathrm{TRM}_1$ 是一个 Transformer 块, 规模与主模型的一个块相当. 所以一个 MTP 深度增加的计算大约是主模型的 $1/61$ 加一次输出头; 输出头和嵌入与主模型共享, 不增加参数. 嵌入层和输出头与主模型共享. 在 DualPipe 流水线并行中, 嵌入层和输出头被放在同一个流水线 rank 上, 这样 MTP 模块与主模型可以在物理上共享这两部分的参数和梯度.

### 3.4 消融

报告表 4 在两档 MoE 上比较加与不加 MTP. 评估阶段去掉 MTP 模块, 推理成本完全相同, 差别只来自训练信号.

| 评测 | 小 MoE 基线 | 小 MoE + MTP | 大 MoE 基线 | 大 MoE + MTP |
|---|---|---|---|---|
| HumanEval | 20.7 | 26.8 | 44.5 | 53.7 |
| GSM8K | 25.4 | 31.4 | 72.3 | 74.0 |
| MMLU | 50.0 | 53.3 | 67.5 | 66.6 |
| BBH | 39.0 | 41.4 | | |
| MATH | 10.7 | 12.6 | | |
| NQ | 22.7 | 22.3 | | |

小 MoE 为 15.7B 总参数、2.4B 激活, 训练 1.33T token; 大 MoE 为 228.7B 总参数、20.9B 激活, 训练 540B token. 代码和数学提升明显, 知识类评测 (MMLU、NQ) 有升有降. 按相对值算, HumanEval 在小 MoE 上提升 29%, 在大 MoE 上提升 21%; GSM8K 分别提升 24% 和 2%. 这两档模型的规模和训练 token 数都不同, 只能说在这两组设置里, 基线越强, 数学上的相对提升越小, 不能据此外推规模趋势.

### 3.5 推理

MTP 模块可以丢掉, 主模型照常工作; 也可以留下来做投机解码. 报告第 5.4.3 节给出: 第二个 token 的接受率在不同生成主题上为 85% 到 90%, 解码速度 (TPS) 提升到 1.8 倍.

接受率与加速的关系: 每一步主模型确定 1 个 token, MTP 猜的第 2 个 token 以概率 $p$ 被接受, 每步期望产出 $1+p$ 个 token. $p=0.85$ 到 $0.9$ 对应 1.85 到 1.9, 实测 1.8 倍略低, 差值是验证和调度的开销.

## 4. 后续模型与边界

### 4.1 DeepSeek-V4 与 MiniMax-M2

DeepSeek-V4 报告写明保留 MTP, 采用与 V3 相同的策略, 不做任何修改, 深度仍为 1. 损失权重在大部分训练中为 0.3, 学习率开始衰减后改为 0.1. 见 [DeepSeek-V4 模型库条目](../../../../model-library/03-模型家族/01-deepseek/deepseek-v4/deepseek-v4-bi.md).

MiniMax-M2 改动更多. 报告 (2605.26494) 第 2.3 节: 预训练时带 1 个 MTP 模块; 为了支持多步投机解码, 在继续预训练的退火阶段扩到 3 个 ($K=3$). 新模块不随机初始化, 而是复制主模型的权重. 报告给出两个理由: 复制初始化的模块收敛快得多, 随机初始化的模块起始 loss 很高, 会暂时拖累主模型; 复制初始化对主模型表示的扰动也最小. 扩展后先冻结主模型、只训 MTP 模块, 等 loss 稳定再联合训练. 报告还试过始终冻结主模型, 结果 MTP 模块的最终质量比联合训练差. 强化学习阶段, MTP 模块用 top-K KL 损失与策略持续共同训练, 防止策略变化后草稿接受率下降.

### 4.2 Kimi K3: 把 MTP 层微调成 EAGLE-3 草稿

先看 [EAGLE-3](https://arxiv.org/abs/2503.01840) 本身. EAGLE 和 EAGLE-2 的草稿在特征层做自回归: 预测目标模型下一个位置的顶层特征, 再送进目标模型的输出头得到 token 分布, 损失由特征预测损失和 token 预测损失两部分组成. 特征损失让只在第 1 步训练过的草稿也能接着往后起草, 但作者发现它限制了草稿的表达能力: 给 EAGLE 加训练数据, 加速比几乎不涨. EAGLE-3 去掉特征预测损失, 直接预测 token. 去掉之后第 2 步以后的输入不再像目标模型的顶层特征, 于是训练时就模拟多步起草 (training-time test), 让草稿在训练中见到自己前几步的输出. 输入也不再限于顶层特征, 改为融合低, 中, 高三层. 在 LLaMA-Instruct 3.1 8B 上, 草稿的训练数据增加时加速比随之上升, 原文称这是之前的 EAGLE 结构上没有观察到的. 用约为 EAGLE 8 倍的数据训练, EAGLE-3 最高加速 6.5 倍, 批大小 1 时延迟比 EAGLE-2 再快约 1.4 倍; 在 SGLang 里批大小 64 时吞吐提升 1.38 倍, 说明投机解码在大批量下也不一定掉吞吐.

Kimi K3 预训练时带一个 MTP 层, 结构与主干的一个块相同. EAGLE-3 的草稿模型恰好也是单个解码层, 所以 K3 在后训练阶段把这个 MTP 层微调成 EAGLE-3 风格的草稿: 目标模型冻结, 只更新草稿层和特征融合投影. 按 EAGLE-3 的 training-time test 协议, 训练时草稿展开 7 步; 第一步之后目标侧最新位置的特征不可用, 草稿使用自己前几步的输出, 与推理时的递推起草一致.

**特征融合.** 草稿的输入融合目标模型的低、中、高层特征, 分别取自第 1、第 4 和最后一个 AttnRes 块的输出. 三者拼接后经无偏置矩阵 $W_{E3}$ 投影到隐藏维度. $W_{E3}$ 初始化为 $[\,0\ 0\ I\,]$, 使融合表示在初始时等于高层特征, 也就是 MTP 层预训练时的输入; 微调过程中再逐步引入低层和中层特征.

**损失.** 无损投机采样下, 每个 token 的接受率为 $\sum_x\min(p(x),q(x))$, $p$ 和 $q$ 分别是目标模型和草稿模型的下一 token 分布. K3 报告指出, 对容量有限的草稿模型, 最小化常规的 KL 代理损失并不保证最大化这个接受率, 所以直接优化 LK 损失, 即接受率的负对数 (K3 报告式 16):

$$
\mathcal L_{\mathrm{LK}}=-\log\sum_{x\in\mathcal V}\min\bigl(p(x),q(x)\bigr). \tag{9}
$$

$p,q$ 都在温度 1 下计算, 不加真实标签的交叉熵项. 微调沿用后训练的量化感知配置: MoE 专家权重 MXFP4, 其输入激活 MXFP8, 非专家模块保持更高精度.

手算一个三词表的例子说明 KL 与接受率的差别. 目标分布 $p=(0.6,0.3,0.1)$.

- 草稿 $q_1=(0.6,0.2,0.2)$: $\sum\min=0.6+0.2+0.1=0.9$, 接受率 90%.
- 草稿 $q_2=(0.4,0.4,0.2)$: $\sum\min=0.4+0.3+0.1=0.8$, 接受率 80%.

再算两者对目标的 KL 散度 $D_{\mathrm{KL}}(p\Vert q)=\sum_xp(x)\log\frac{p(x)}{q(x)}$ (自然对数):

- $q_1$: $0.6\log1+0.3\log1.5+0.1\log0.5\approx0+0.122-0.069=0.052$.
- $q_2$: $0.6\log1.5+0.3\log0.75+0.1\log0.5\approx0.243-0.086-0.069=0.088$.

这个例子里两种度量给出相同的排序. $\sum_x\min(p,q)=1-D_{\mathrm{TV}}(p,q)$, 其中 $D_{\mathrm{TV}}$ 是总变差距离, 而 KL 只是它的一个上界代理 (Pinsker 不等式 $D_{\mathrm{TV}}\le\sqrt{D_{\mathrm{KL}}/2}$). 草稿容量足够时两者的最优点都是 $q=p$; 容量不足、只能在一族受限的 $q$ 中选时, 最小化 KL 的 $q$ 不一定是接受率最高的 $q$, 这就是 K3 报告改用式 (9) 的理由.

**与线性注意力的冲突.** K3 的主干含 KDA 层, 其递推状态在每个解码步原地更新. K3 报告的推理系统部分指出, 在基于 MTP 的投机解码中, 如果验证拒绝了部分草稿 token, 状态已经越过最后一个被接受的 token, 无法直接回滚; 为每个草稿位置保存状态快照可以回滚, 但会成倍增加状态的读写流量, 在线服务的大批量下这是主要成本. 这与 [2.4.5](../../2.5-线性注意力与状态空间模型/2.5.5-新兴架构与混合模型/2.5.5-新兴架构与混合模型.md) 中 MiniMax-M2 报告所说「线性注意力与投机解码的结合方式不明确」是同一个问题. K3 的条目见 [Kimi K3 模型库条目](../../../../model-library/03-模型家族/02-kimi/kimi-k3/kimi-k3-bi.md).

### 4.3 对照

| 方案 | 额外预测的结构 | 预训练深度 | 推理阶段的用法 | 草稿的后续训练 |
|---|---|---|---|---|
| Gloeckle 等人 | 并行独立头 | $n=4$ 为主 | 丢弃或自投机解码 | 无 |
| DeepSeek-V3 | 顺序模块, 拼接下一 token 嵌入 | $D=1$ | 丢弃或投机解码 | 无 |
| DeepSeek-V4 | 与 V3 相同 | 1 | 与 V3 相同 | 无 |
| MiniMax-M2 | MTP 模块 | 1, 退火阶段扩到 3 | 多步投机解码 | RL 阶段用 top-K KL 共同训练 |
| Kimi K3 | 与主干块同构的 MTP 层 | 1 | EAGLE-3 风格草稿 | 冻结目标模型, 用 LK 损失微调 |

从上到下, MTP 的角色逐渐从「训练辅助目标」偏向「内置草稿模型」. 前两行的消融关心的是去掉 MTP 后主模型变好了多少; 后两行关心的是草稿的接受率, 并为此在预训练之后单独训练草稿. 两种目标对 MTP 模块的要求不同: 前者只要它提供有用的梯度, 后者要它的分布尽量接近目标模型.

### 4.4 边界

**收益依赖规模和领域.** Gloeckle 等人的小模型上 MTP 更差; 自然语言选择题上 $n=4$ 退步; GSM8K 在 500B token 时结果反转. DeepSeek-V3 的消融中大 MoE 的 MMLU 从 67.5 降到 66.6. 在已有的消融里, MTP 对代码和数学的提升最稳定.

**并行头的独立性假设.** 并行头预测第 $i$ 个未来 token 时不知道前面几个的取值, 只能预测给定前缀下的边缘分布. 第 2.4 节中代码的加速比 (3.0 倍) 高于文本 (2.7 倍). 顺序模块解决了这个问题, 代价是只能串行.

**训练成本.** 额外模块需要额外的前向和反向. Gloeckle 等人用减少主干层数来保持参数量不变, 摘要称训练时间没有额外开销; V3 只加一个深度. MiniMax-M2 的经验表明, 扩到多个模块时初始化方式会影响主模型.

**推理阶段还要验证.** MTP 模块当草稿用时, 输出必须经主模型验证才能保证无损; 被拒绝的猜测白白消耗了计算, 接受率越低, 这部分浪费越大. 「一次前向输出 $k$ 个 token 就结束」不是 MTP 的推理方式.

**与其他非自回归方法的区别.** MTP 的因式分解仍然从左到右, 每个位置的主损失仍是下一 token 预测. 扩散语言模型 ([2.4.7](../2.8.2-扩散语言模型DLM/2.8.2-扩散语言模型DLM.md)) 去掉了从左到右的顺序; LLM-JEPA ([2.4.10](../2.8.5-LLM-JEPA/2.8.5-LLM-JEPA.md)) 预测的是表示而不是 token.
