# 系列专栏

系列专栏收录按主题持续积累的短文, 目前有两个子专栏: [大模型题目日积月累](./大模型面试题日积月累/大模型面试题日积月累.md) 和 [面经分享](./面经分享/面经分享.md). 前者一题一条, 每条从一个具体问题出发, 给出可以核对的推导和数字; 后者记录技术岗位的考察流程和题目分布. 它们和正文章节的区别在于组织方式: 正文按知识的依赖顺序展开, 专栏按问题展开, 一个问题可能同时用到第 2 章的注意力, 第 6 章的显存分析和第 9 章的硬件参数.

本页说明专栏里的题目怎样分类, 每一类对应正文的哪一章, 以及一条合格的答案应当包含什么. 第 3 节给出几道高频题的完整答案, 作为专栏条目的样式. 题目的整体格局和准备路线, 另见 [11.2 技术岗位问答集锦](../11-实践与资源/11.2-面试集锦/11.2-面试集锦.md).

## 1. 专栏的组织方式

### 1.1 两个子专栏的分工

技术问答专栏的条目是独立的: 每条只回答一个问题, 篇幅控制在读者十分钟内能看完并复算一遍. 条目的标题就是问题本身, 例如「注意力为什么要除以 $\sqrt{d_k}$」「70B 模型 decode 时 KV cache 占多少显存」. 正文中已经有完整推导的内容, 条目只给结论和关键一步, 然后链到对应小节, 不在专栏里重写一遍.

经历分享专栏关注题目以外的信息: 不同方向的岗位 (算法研究, 训练工程, 推理部署, 应用开发) 各自考察哪些维度, 追问一般从哪里展开, 系统设计题给出的约束是什么样的. 这些信息能帮助读者判断该在哪些章节上多花时间. 分享中出现的具体题目, 会被拆出来补进问答专栏, 两边互相链接.

### 1.2 和正文章节的关系

专栏不引入正文里没有的新机制. 一道题如果涉及正文尚未覆盖的内容, 先补正文, 再写专栏条目. 这样做的原因是答案的可信度来自推导, 而推导的位置应当只有一个; 如果专栏和正文各写一份, 两边迟早会出现不一致的数字.

反过来, 专栏对正文也有用处. 高频题集中暴露了读者最容易卡住的地方: 为什么 GQA 能省显存, DPO 的损失怎么从偏好模型推出来, 混合精度为什么需要主权重副本. 这些问题在正文里往往夹在长推导中间, 专栏把它们单独拎出来, 读者可以先从问题进入, 再回到正文看完整的上下文.

## 2. 题目按什么分类

### 2.1 五个维度与正文落点

| 维度 | 典型问题 | 正文落点 |
|---|---|---|
| Transformer 原理 | 缩放因子, 位置编码外推, MHA/GQA/MQA, RMSNorm, SwiGLU | 第 2 章 |
| 预训练与微调 | 数据配比, 并行策略, 混合精度, Loss Spike, LoRA | 第 3 章, 第 4 章, 6.1 |
| 对齐与后训练 | RLHF 三阶段, PPO 的 clip, DPO 推导, PRM 与 ORM | 第 4 章 |
| 推理部署 | KV cache 计算, PagedAttention, 量化, Continuous Batching | 第 6 章, 第 9 章 |
| RAG 与 Agent | 切分与重排, 检索对了但答错, ReAct, 多 Agent 设计 | 7.2, 第 13 章 |

五个维度的题目难度并不均匀. Transformer 原理是所有方向的公共基础, 题目短, 但追问会一直推到矩阵维数. 推理部署类的题目大多可以算出具体数字, 答案好不好一眼就能看出来. RAG 与 Agent 类的题目常以系统设计的形式出现, 没有唯一答案, 考察的是能否讲明白每个组件的职责和失败方式, 对应的正文是 [7.2 RAG](../7-LLM应用开发/7.2-RAG/7.2-RAG.md) 和 [第 13 章 Agent](../13-Agent/13-Agent.md).

### 2.2 一条答案的三层

合格的答案分三层. 第一层是定义和公式, 例如 LoRA 是在冻结权重 $W_0$ 旁加一个低秩增量 $BA$. 第二层是动机和对比: 它解决什么问题, 和相近的方法相比好在哪里, 代价是什么. 第三层是数字: 在一个具体配置下, 它省了多少参数, 多少显存, 慢了多少.

多数答案停在第一层, 少数能说到第二层, 第三层最能区分是否真正理解. 能算出数字, 说明知道公式里每个符号对应模型的哪个维度, 也知道这些维度在真实模型里的取值. 专栏的每个条目都要求写到第三层, 数字的配置 (模型, 精度, 序列长度) 写清楚, 让读者能自己复算.

## 3. 几道高频题的完整答案

### 3.1 注意力为什么除以 $\sqrt{d_k}$

设查询 $q$ 和键 $k$ 的各分量独立, 均值为 0, 方差为 1. 点积 $q\cdot k=\sum_{i=1}^{d_k}q_ik_i$ 是 $d_k$ 个方差为 1 的项之和, 方差为 $d_k$. 当 $d_k=128$ 时, 点积的标准差约为 11.3, softmax 的输入在几十的量级上波动, 输出会接近 one-hot, 大部分位置的梯度趋近于 0.

除以 $\sqrt{d_k}$ 把点积的方差拉回 1, softmax 工作在梯度正常的区间. 追问通常是「为什么不除以 $d_k$」: 那样方差变成 $1/d_k$, 注意力分布接近均匀, 模型很难把权重集中到相关位置. 完整推导和代码在 [2.2.1 自注意力机制](../2-核心原理与架构/2.2-注意力机制/2.2.1-自注意力机制/2.2.1-自注意力机制.md).

### 3.2 KV cache 的显存与 GQA

每个 token 的 KV cache 大小是 $2\times n_{\text{layer}}\times n_{kv}\times d_{\text{head}}\times b$ 字节, 其中 2 表示 K 和 V, $b$ 是每个元素的字节数. 以 32 层, 32 个 KV 头, $d_{\text{head}}=128$, FP16 的配置 (Llama-2-7B) 为例, 每个 token 占 $2\times32\times32\times128\times2=524{,}288$ 字节, 即 0.5 MiB; 一条 4096 token 的序列需要 2 GiB, batch 为 16 时就是 32 GiB, 超过权重本身的 13.5 GB.

GQA 让多个查询头共享一组 KV 头. 同样 32 层, 把 KV 头数降到 8 (Llama-3-8B 的配置), 每 token 降到 128 KiB, 4096 token 的序列只需 0.5 GiB, 同样的显存能放下 4 倍的 batch. decode 阶段每生成一个 token 都要把整个 KV cache 读一遍, 所以 KV 体积变小同时也降低了显存带宽压力. 推导见 [MQA 与 GQA](../2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md), 分页管理和前缀复用见 [6.4 KV 缓存与内存优化](../6-训练与推理优化/6.4-KV缓存与内存优化/6.4-KV缓存与内存优化.md).

### 3.3 LoRA 省下的是什么

用 Adam 和混合精度做全参数训练, 每个参数要存 FP16 权重和梯度各 2 字节, FP32 主权重 4 字节, 两个 Adam 动量各 4 字节, 共 16 字节. 7B 模型仅模型状态就要约 112 GB, 还没算激活. 对一个 $d\times k$ 的权重矩阵, LoRA 只训练 $r(d+k)$ 个参数; $d=k=4096$, $r=8$ 时是 65,536 个, 约为原矩阵 1678 万参数的 0.39%.

所以 LoRA 省下的主要是优化器状态和梯度, 冻结的底座只需要半精度权重 (7B 约 13.5 GB). 追问常问推理代价: 训练完可以把 $BA$ 合并进 $W_0$, 推理时没有额外计算; 不合并时每 token 多约 $r(d+k)$ 次乘加. 秩怎样选, QLoRA 怎样把底座量化到 4 bit, 见 [4.3.1 LoRA 低秩适应](../4-后训练/4.3-PEFT/4.3.1-LoRA低秩适应/4.3.1-LoRA低秩适应.md) 和 [6.2.1 显存占用分析](../6-训练与推理优化/6.2-显存与计算分析/6.2.1-显存占用分析/6.2.1-显存占用分析.md).

### 3.4 DPO 的损失从哪里来

RLHF 的目标是在 KL 约束下最大化奖励, 它的最优策略有闭式解 $\pi^*(y|x)\propto\pi_{\text{ref}}(y|x)\exp(r(x,y)/\beta)$. 反解出奖励 $r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)}+\beta\log Z(x)$, 代入 Bradley-Terry 偏好模型 $P(y_w\succ y_l)=\sigma(r(x,y_w)-r(x,y_l))$, 配分函数 $Z(x)$ 在相减时消掉.

于是偏好数据上的极大似然直接变成对策略的损失: $-\log\sigma\big(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}-\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\big)$, 不再需要单独训练奖励模型, 也不需要在线采样. 追问一般转向它的问题: 离线数据带来的分布偏移, 以及 IPO, KTO, SimPO 各改了什么. 完整推导见 [DPO](../4-后训练/4.6-偏好优化/4.6.1-离线偏好优化/01-DPO/01-DPO.md).

## 4. 使用方法

### 4.1 按方向挑题

准备训练工程方向的读者, 优先看第 2 节表格中的预训练与微调, 推理部署两行, 把 3.2 和 3.3 这类能算出数字的题目全部自己算一遍, 换一个模型配置再算一遍. 应用开发方向的读者, 重点在 RAG 与 Agent 一行, 同时要能答出 3.1 这样的原理题, 它是所有方向共用的基础.

算法研究方向的题目更依赖论文细节, 对齐与后训练一行的题目往往会追问到某个方法的具体假设, 例如 DPO 的推导依赖 Bradley-Terry 模型, 偏好不满足传递性时这个假设就不成立. 这类追问在专栏条目里只给出提示, 完整讨论在第 4 章的各篇里.

### 4.2 用正文核对答案

专栏条目里的每个数字都可以在正文里找到推导, 读者应当把核对当作阅读的一部分. 例如 3.2 的 KV cache 公式, 可以在 6.4 里看到它怎样扩展到 MLA 的压缩缓存; 3.3 的 16 字节, 可以在 6.2.1 里看到它和 ZeRO 各阶段的切分方式之间的关系.

如果发现专栏和正文的数字对不上, 以正文为准, 并回头检查专栏条目的配置假设. 常见的差异来源是精度 (FP16 与 BF16 字节数相同, FP8 减半), 是否计入激活, 以及模型的真实层数和头数. 具体模型的这些参数, 在 [主流模型知识库](../../model-library/_garden.md) 对应版本的分析笔记里可以查到.
