# Agent 应用与治理：能力、评测与安全保证

Agent 从演示进入生产后，核心问题从“能不能调用工具”转为：系统在什么任务、权限、预算和失败条件下可靠，出现事故时能否阻断、追溯和恢复。产品名称和排行榜会变，评测与治理责任更稳定。

## 2. 应用评审的六个维度

1. **任务**：输入、目标、约束、成功和失败怎样定义？
2. **能力**：模型和 harness 能读什么、做什么、验证什么？
3. **权限**：实际身份、资源作用域、副作用和审批是什么？
4. **可靠性**：错误、超时、重复、取消和恢复怎样处理？
5. **评测**：是否固定环境，是否包含成本、方差和安全？
6. **治理**：谁负责上线、变更、监控、事件和退役？

任何“全自动”描述都应转换成这六类可观察条件。

## 3. 自主级别按风险配置

| 级别 | 行为 | 适合 |
|---|---|---|
| 建议 | 只生成建议或差异 | 高影响、难验证任务 |
| 受控执行 | 只读自动，写操作逐次批准 | 开发、研究、办公 |
| 有限委派 | 在隔离环境和预算内完成任务 | 结果可验证的长任务 |
| 条件自治 | 低风险动作按政策自动，高风险升级 | 稳定、经过持续评测的流程 |

自主性不是单一产品标签。同一 Agent 对读取公开网页和删除生产数据应处于不同级别。

## 4. 上线证据包

- 任务与非目标范围；
- 模型、提示、工具、策略和环境版本；
- 正常、边界、依赖故障和恶意输入评测；
- 权限矩阵与高风险审批；
- 数据来源、保留、删除和供应商边界；
- 成功、回归、人工介入、延迟、费用和安全指标；
- 回滚、停用、事件响应和负责人。

上线后任何模型、工具、权限、提示或环境变更都可能破坏证据，应触发相应回归。

## 5. 不应使用的证据

- 没有任务和 harness 的单一排行榜分数；
- 没有实验方法的“节省 90% 时间”或固定成本；
- 厂商功能页推导出的市场排名；
- 一次成功演示推导出的长期可靠性；
- 模型自述“已完成”或“操作安全”；
- 把沙箱、MCP 或安全微调当作完整治理。

## 6. 验收清单

- [ ] 应用的自主级别按动作风险而非营销名称设置。
- [ ] 结果由外部状态、测试或人工量表验证。
- [ ] 模型、harness、环境和 evaluator 都有版本。
- [ ] 成本包含失败、重试和人工介入。
- [ ] 安全评测包含间接提示注入、越权和数据泄露。
- [ ] 运行中有监控、事件响应、回滚和停用机制。
