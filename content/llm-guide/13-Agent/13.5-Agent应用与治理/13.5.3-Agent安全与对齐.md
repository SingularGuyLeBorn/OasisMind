# Agent 安全：威胁模型、硬控制与持续保证

Agent 安全的核心不是要求模型“永远听话”，而是即使模型被诱导、误判或生成危险参数，系统仍能限制其可见数据和可执行动作。安全训练改善模型行为，硬权限、隔离、审批和验证限制最坏影响。

> **证据与时效边界**：本文截至 2026-09-01，依据 NIST、OWASP、MITRE ATLAS 和一手研究。攻击分类与产品会变化，实际控制应结合组织资产、法规和部署环境更新。

## 1. 先画信任边界

至少区分：用户输入、开发者指令、模型输出、外部网页/邮件/文档、工具服务器、业务 API、记忆库、运行时、凭据和最终用户。

以下内容默认不可信：

- 用户提供的文本、代码、URL 与附件；
- 网页、邮件、仓库文档和检索片段；
- 模型生成的工具名、参数、路径和“已获批准”声明；
- 第三方工具描述与返回；
- 外部依赖、镜像和脚本。

身份与授权必须来自宿主的认证上下文，不能由模型参数声明。

## 2. 资产与影响

| 资产 | 可能影响 |
|---|---|
| 用户/组织数据 | 越权读取、跨租户泄露、错误修改 |
| 凭据与令牌 | 账户接管、横向移动、外部泄露 |
| 文件与代码仓库 | 删除、后门、构建脚本投毒 |
| 网络与云资源 | SSRF、元数据访问、资源滥用 |
| 对外通信 | 错误发信、公开发布、社会工程 |
| 财务与权限 | 重复支付、错误授权、权限升级 |
| 记忆与知识库 | 持久投毒、过期信息、删除不完整 |
| 审计与评测 | 日志篡改、evaluator 利用、假成功 |

风险不是“Agent 自主性”的抽象函数；应按具体动作的可逆性、范围、可检测性和数据敏感度评估。

## 3. 提示注入与越狱

### 3.1 直接注入

用户试图改变系统目标、绕过限制或诱导泄露。内容过滤可以作为信号，但不能替权限边界。

### 3.2 间接注入

恶意指令藏在 Agent 读取的网页、邮件、文档、图片 OCR、代码注释或工具结果中。Agent 若把数据当成高优先级指令，可能调用敏感工具。

防御不是简单“清洗掉所有可疑句子”。攻击表达会变化，分类器会漏报。需要组合：

1. 数据与指令分区并标记来源；
2. 外部内容不能修改系统策略或授权；
3. 按任务最小化可用工具和可见数据；
4. 敏感动作执行前重新显示对象与影响并批准；
5. 限制跨域数据流，例如读取邮件的 Agent 不自动拥有外发任意 URL 的权限；
6. 记录注入测试和实际拦截点。

## 4. 模型提议与宿主执行

安全调用链是：

```text
模型提出动作
  -> 结构与类型校验
  -> 路径/URL/资源 ID 规范化
  -> 基于真实身份的业务授权
  -> 副作用分级和必要审批
  -> 隔离与资源限制下执行
  -> 结果/终局验证
  -> 审计与状态更新
```

JSON Schema 合规只证明结构。`account_id`、文件路径、收件人和支付金额仍需业务验证。MCP 只提供互操作协议，不自动解决认证、授权、恶意服务器或提示注入。

## 5. 最小权限与审批

### 5.1 能力拆分

把读取、创建、修改、删除、公开发布、支付和权限管理拆成不同工具与 scopes。不要给“文件工具”一个能读写整个主机的万能接口。

### 5.2 短期身份

使用按任务、按资源、短时有效的凭据；不把宿主长期密钥放进模型上下文、镜像或普通日志。工具服务端每次调用都重建租户和用户授权。

### 5.3 有意义的批准

批准界面应展示规范化后的真实对象、动作、差异、收件人、金额和不可逆影响。不要只问“是否允许工具 X”，也不要让恶意网页提供审批说明。

批量批准应限制作用域、期限和动作类别，并可撤销。

## 6. 沙箱与网络

不受信任代码、二进制和文档处理器应进入与风险匹配的隔离环境。容器、gVisor、MicroVM 或 Wasm 各有边界，不是线性安全排行。详见 [运行时环境与沙箱](../13.3-Agent系统工程/13.3.4-运行时环境与沙箱.md)。

最低控制包括：非 root、只读输入、独立输出、资源上限、受限系统调用、默认拒绝网络、短期凭据、每任务清理、禁止宿主 socket 和敏感挂载。

网络策略应阻断环回、私网、链路本地和云元数据地址，处理重定向与 DNS rebinding，并限制域名、端口、下载体积和请求数。

## 7. 副作用与重试

只读查询可以对明确瞬时错误有限重试。支付、发信、创建、删除和发布等非幂等动作需要幂等键或稳定操作 ID。超时后先查询状态，不能根据模型判断直接重复。

对高影响动作采用：只读侦察 → 预览差异 → 用户/策略批准 → 提交 → 回查状态。验证“工具返回成功”和“业务目标达成”是两步。

## 8. 记忆与数据安全

- 记忆写入前检查来源、稳定性、权限和敏感性；
- 模型猜测不能自动变成用户事实；
- 每条记录带租户、用户、用途、来源、时间和失效条件；
- 删除传播到主存储、索引、缓存和可控备份；
- 防止外部提示被持久化为高优先级指令；
- 用越权检索、删除残留和跨用户混淆测试系统。

## 9. 供应链

Agent 会安装包、运行构建脚本、连接 MCP server 或加载 Skill。需要：

- 固定依赖、镜像和工具服务器版本；
- 校验来源、签名/哈希与 SBOM；
- 审查安装期脚本、Skill 脚本和工具描述；
- 在隔离环境中安装和运行未知依赖；
- 对更新进行回归和权限差异审查；
- 准备禁用、回滚和撤销凭据。

“开源”“官方市场”或“通过 MCP”都不等于无供应链风险。

## 10. 安全评测

安全测试对象是联合系统，不只模型。至少覆盖：

- 直接/间接注入和跨工具数据外泄；
- 越权读写、跨租户、路径穿越、SSRF；
- 重复副作用、超时、取消和恢复；
- 记忆投毒、删除残留和过期事实；
- 恶意工具描述、结果投毒和依赖投毒；
- 资源耗尽、循环和费用放大；
- 审批疲劳、误导性预览和绕过路径。

报告攻击前提、可用权限、系统版本、每题多次运行、攻击成功率、误报/漏报、实际阻断层和残余影响。模型拒答率不是完整安全指标。

## 11. 红队与事故响应

红队结果应进入回归集，但自动攻击模型本身也可能偏置或漏报。高风险场景结合领域专家、软件安全测试和真实业务演练。

事故流程至少包含：检测与分级、暂停工具或模型、撤销令牌、保存受控证据、确定影响范围、恢复/补偿、通知、根因与控制修复、回归验证。日志最小化与证据保全需同时满足。

## 12. 对齐训练的边界

RLHF、RLAIF、Constitutional AI 或安全分类器可以影响模型生成与拒答，但不能承担以下硬责任：

- 判断当前用户是否拥有某数据库行；
- 限制进程读取宿主文件；
- 阻止网络访问云元数据；
- 保证转账只执行一次；
- 证明输出满足业务不变量。

分类器同样会分布漂移，需校准、监控和故障安全策略。把模型输出的“安全评分”作为唯一授权条件是不安全的。

## 13. 治理与持续保证

把模型、提示、工具、权限、MCP server、Skill、环境和 evaluator 都视为受控配置。每次重要变化触发相应安全回归。风险登记至少记录资产、威胁、控制、证据、负责人、残余风险和复审日期。

NIST AI RMF 的 Govern、Map、Measure、Manage 可用于组织治理活动；它不是自动合规认证。法律和标准要求应由合格人员按地区与日期核验。

## 14. 上线清单

- [ ] 资产、攻击者、入口、信任边界和最坏影响已明确。
- [ ] 模型提议与宿主执行严格分离。
- [ ] 工具按读、写、高影响动作拆分并最小授权。
- [ ] 外部内容不能提升权限，敏感动作会再授权。
- [ ] 代码、文件、网络、凭据和资源有隔离边界。
- [ ] 非幂等动作有预览、幂等/状态查询和回查。
- [ ] 记忆可查看、更正、失效和删除。
- [ ] 供应链版本固定，更新可回滚。
- [ ] 安全回归覆盖正常、异常和恶意场景。
- [ ] 有停用、撤权、事故响应和持续监控。
