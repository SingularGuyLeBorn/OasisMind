# 记忆系统：生命周期、边界与评估

Agent 记忆不是“把所有对话永久保存”，也不等于模型的 KV cache。更准确地说，记忆系统是在模型上下文之外或之内，对过去信息进行**选择性保留、检索、更新和删除**的一组机制。它的价值取决于取回的信息是否相关、是否仍然有效，以及是否在权限范围内。

## 一、先区分三个容易混淆的概念

| 概念 | 典型生命周期 | 主要用途 | 不能代表什么 |
|---|---|---|---|
| 当前上下文 | 单次请求或一次会话 | 给模型提供眼前任务、工具结果和最近交互 | 不等于跨会话持久记忆 |
| 推理缓存 | 一次或一组相关推理过程 | 减少重复计算或保存模型运行状态 | 不等于可解释、可编辑的用户记忆 |
| 外部记忆 | 可跨请求或跨会话 | 保存事件、事实、偏好、技能或任务状态 | 不保证被正确写入、取回或遗忘 |

公开论文通常研究外部存储与上下文管理。它们不能证明某个商业产品采用了特定的内部状态注入、检索管线或数据库结构。产品内部实现若没有官方证据，应标为 **unknown**。

## 二、按内容作用分类

下面的分类描述“记住什么”，与向量库、关系库、知识图谱等“存在哪里”是两个正交维度。

| 类型 | 内容示例 | 常见风险 |
|---|---|---|
| 工作记忆 | 当前目标、计划、最近观察、待处理工具结果 | 上下文溢出、旧状态覆盖新状态 |
| 情节记忆 | 某次任务发生了什么、采取了哪些动作、结果如何 | 把一次偶然事件误当成稳定规律 |
| 语义记忆 | 已确认事实、实体关系、项目约束 | 来源过期、同名实体混淆、事实冲突 |
| 程序性记忆 | 可复用步骤、工具使用方法、失败恢复策略 | 适用条件丢失、错误步骤被不断复用 |
| 用户或项目配置 | 明示偏好、权限、环境设置 | 未经同意推断敏感属性，删除边界不清 |

一个记录可以同时带有内容类型、来源、时间、置信度、适用范围和访问权限。不要把“存成向量”本身当作记忆分类。

## 三、完整生命周期

### 3.1 写入：先判断是否值得记

候选信息进入持久记忆前，至少经过以下检查：

1. **任务价值**：未来是否可能复用，而不是只对当前回答有用。
2. **来源与时间**：谁提供、何时产生、能否重新核验。
3. **权限与敏感性**：是否允许跨会话保存，是否包含凭据或敏感个人信息。
4. **稳定性**：是长期事实、临时状态，还是未经验证的猜测。
5. **冲突与重复**：是否覆盖旧记录，还是应保留多个带版本的说法。

推荐的最小记录结构是：`内容 + 来源 + 记录时间 + 适用范围 + 置信度 + 失效/删除条件`。这是一种工程模板，不是论文规定的统一格式。

### 3.2 存储：保留可追溯性

- 原始事件适合追加式日志，便于审计发生了什么。
- 结构化事实适合带实体、关系、版本和来源的记录。
- 文档片段适合关键词与语义索引并存，但索引必须能回指原文。
- 技能或流程应同时保存前置条件、成功标准和已知失败模式。

MemGPT 把有限上下文类比为主存，并用分层存储和显式的上下文管理扩展可访问历史。这是一个具体系统设计，不意味着模型获得了真正无限且无损的记忆。[MemGPT 论文](https://arxiv.org/abs/2310.08560)

### 3.3 读取：检索只是第一步

一次可靠读取通常包含：

1. 根据当前问题生成关键词、实体和时间约束；
2. 通过精确匹配、语义检索或结构化查询召回候选；
3. 结合相关性、时效性、来源可信度和权限排序；
4. 去重并解决冲突，必要时保留“不确定”而非强行合并；
5. 只将少量、带来源的结果放回当前上下文。

具体排序公式是实现选择。除非系统论文公开，否则不要声称某产品采用固定权重、特定内部状态注入或专有检索流程。

### 3.4 更新与遗忘：删除是核心能力

遗忘不只是容量优化，还涉及正确性与隐私：

- **失效**：用 `superseded` 标记旧事实并指向新版本，避免静默覆盖来源。
- **到期**：临时任务状态可设置 TTL，到期后不再参与检索。
- **摘要压缩**：保留原始出处，摘要不能成为无法追溯的新“事实”。
- **硬删除**：同时处理主存储、派生索引、缓存与可控备份，并记录删除结果。
- **用户控制**：让用户查看、纠正和删除与自己有关的持久记录。

## 四、如何评估记忆系统

LongMemEval 提供 500 个问题，用于考察五类长期交互能力：信息抽取、多会话推理、时间推理、知识更新和拒答。论文还把系统拆为 indexing、retrieval、reading 三个阶段，便于定位错误来自写入组织、召回还是最终作答。[LongMemEval 论文](https://arxiv.org/abs/2410.10813)

真实系统不应只报告最终答案准确率。至少同时测量：

| 维度 | 例子 |
|---|---|
| 任务效果 | 正确率、任务成功率、需要记忆与无需记忆样本的差异 |
| 检索质量 | 相关记录召回率、精确率、来源覆盖、时间约束命中率 |
| 更新能力 | 新事实替代旧事实时是否选择最新版，是否保留冲突证据 |
| 拒答能力 | 缺少记忆或权限不足时能否明确说不知道 |
| 删除与隐私 | 删除后主存储和索引是否仍可检索，越权访问是否被阻止 |
| 系统成本 | 写入与读取延迟、上下文占用、存储和模型调用成本 |

产品体验、召回或其他内部指标，只有在来源、样本、对照组和时间范围明确时才可引用；无法核验的营销数字不应进入技术结论。

## 五、常见失败模式

- **错误持久化**：把模型猜测写成用户事实，之后反复放大。
- **新旧冲突**：召回旧地址、旧依赖版本或已经撤销的偏好。
- **检索污染**：相似措辞压过真正相关且更可信的记录。
- **上下文挤占**：召回过多历史，反而让当前任务指令变得不清楚。
- **提示注入持久化**：把外部文档中的恶意指令写入长期记忆。
- **删除不完整**：正文已删，但向量索引、缓存或副本仍可命中。

防护重点是来源标记、写入审批、权限过滤、版本与时间、可审计删除，以及把外部内容当作数据而非系统指令。

## 六、设计检查表

- 记忆范围是一次任务、一个项目、一个用户，还是整个组织？
- 谁能写入、读取、纠正和删除？
- 每条事实能否回到原始来源和时间？
- 冲突事实如何并存、排序和失效？
- 记忆不可用时，系统是否仍能安全退化？
- 评测是否包含更新、拒答、删除、权限与提示注入，而不只测召回？
