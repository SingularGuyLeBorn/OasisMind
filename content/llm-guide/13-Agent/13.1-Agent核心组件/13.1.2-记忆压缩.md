# 记忆压缩：在 token 预算内保留事实、约束与证据

Agent 的“记忆压缩”不是把所有历史改写成更短的散文。它要在有限的模型输入预算内，保住当前任务仍然需要的**事实、约束、决定、证据位置、未完成事项与错误状态**。压缩可以有损，但原始事件和权威来源不应因此消失。

> **证据与时效边界**：本文截至 2026-09-01。论文中的压缩倍数只对其模型、数据集和评价设置成立；生产系统需要在自己的任务分布上重新测量，不能把“最多 20×”之类的实验结果当成默认能力。

## 1. 先区分三种“压缩”

| 对象 | 目的 | 常用办法 | 主要风险 |
|---|---|---|---|
| 当前上下文 | 让下一次模型调用装得下且聚焦 | 截断、窗口、摘要、查询感知筛选 | 遗漏当前任务需要的信息 |
| 长期记忆 | 减少重复、合并稳定事实、提高检索质量 | 去重、实体归并、版本化事实、分层索引 | 把暂时观察固化成长期真相 |
| 存储与传输 | 降低磁盘或网络字节数 | 通用无损压缩、列式存储 | 与模型语义记忆不是同一问题 |

这一页讨论前两类。普通 gzip 可以减少字节，但模型仍要看到解压后的 token；它不解决上下文选择问题。

## 2. 正确的数据分层

可靠系统通常同时保留以下层，而不是让一段摘要覆盖所有数据：

1. **原始事件层**：用户输入、工具调用、授权决定、工具结果和时间戳。尽量追加写入，承担审计与重建。
2. **权威工件层**：文件、数据库记录、测试报告和外部文档。摘要只保存引用，不替代原文。
3. **工作状态层**：当前目标、计划、已完成项、未完成项、错误和预算。
4. **摘要层**：面向某个任务或时间段的有损视图，必须带版本和来源范围。
5. **检索索引层**：向量、关键词、图关系或倒排索引，是查找入口，不是新的权威事实。

MemGPT 的核心思想是借鉴操作系统分层内存，在有限上下文与外部存储之间移动信息；论文并没有证明摘要可以无损替代原始历史。实际设计中，“上下文里没有”与“系统永久忘记”必须分开。

## 3. 压缩前先定义不可丢失项

通用摘要提示容易遗漏对后续执行至关重要、但在自然语言中不显眼的信息。建议把以下字段设为受保护内容：

- 用户明确要求、禁止项和验收标准；
- 文件路径、资源 ID、版本、哈希、URL 与证据定位；
- 数字、单位、日期、时区、范围和否定词；
- 已批准或被拒绝的高风险动作；
- 工具错误、重试次数、部分成功和副作用是否可能已经发生；
- 已完成工作、剩余工作、依赖关系和阻塞原因；
- 有冲突的事实及各自来源，而不是强行选一个；
- 用户可撤回的偏好、隐私边界和数据保留要求。

一个实用的摘要契约可以固定为：`goal`、`constraints`、`decisions`、`completed`、`open_items`、`evidence`、`errors`、`uncertainties`。没有内容的字段也明确为空，避免“摘要没写”被误读为“不存在”。

## 4. 六类压缩策略

### 4.1 截断与滑动窗口

只保留最近若干消息或 token，成本低、行为可预测。适合近期信息明显更重要的短会话；不适合早期约束仍控制后续步骤的任务。

改进方法是把稳定系统指令、任务契约和未完成状态固定在窗口之外，只滚动低价值对话与冗长工具输出。

### 4.2 确定性过滤与结构化提取

先去掉重复日志、无关调试信息、二进制块和可重新获取的大段输出，再用规则提取路径、错误码、测试失败、ID 与状态。对代码、JSON、数字和引用，结构化提取通常比自由摘要更可控。

过滤规则必须允许“保留原文指针”。例如测试日志可以只送入失败用例、错误栈和日志对象 URI，但不能只留下“测试失败”四个字。

### 4.3 抽象式滚动摘要

当窗口超过阈值时，让模型把较早事件总结为状态摘要。优点是可读、压缩灵活；风险是遗漏、把不确定信息写成事实，以及多次“摘要的摘要”造成误差累积。

降低风险的做法：

- 只摘要已经结束的时间段，活动中的操作保留原始记录；
- 摘要同时输出证据事件 ID；
- 新摘要从“上一摘要 + 新原始事件”生成，但定期从原始事件重新构建；
- 用模式校验字段完整性，再做事实一致性检查；
- 发生冲突时保留双方与来源，不让摘要器擅自裁决。

### 4.4 分块与分层摘要

长历史可以先按任务、主题或时间切块，生成局部摘要，再由上层摘要汇总。它适合离线归档和跨多会话回顾，但上层摘要必须保留指向局部摘要和原始事件的路径。

固定 token 长度切块简单，却可能切断一次工具调用与其结果。事件边界、事务边界和主题变化通常比纯 token 边界更适合作为切块依据。

### 4.5 查询感知筛选与提示压缩

当下一步查询已知时，可以按与查询的相关性选择段落、句子或 token。LLMLingua 采用粗到细预算控制和 token 级压缩；LongLLMLingua进一步面向长上下文与查询相关性。它们是特定论文方法，不等于所有 Agent 的默认记忆实现。

查询感知压缩能减少当前调用输入，却可能丢掉随后步骤需要的信息。因此它更适合生成**临时视图**，不应覆盖长期摘要或原始记录。

### 4.6 检索与分层分页

把较少的工作状态常驻上下文，其余事件和知识留在外部存储，需要时按关键词、向量、实体、时间或图关系检索。检索不是压缩的替代品：召回结果仍可能超预算，需要排序、去重和摘录；检索失败也不能被解释为事实不存在。

对于路径、ID、错误码和专有名词，混合关键词与向量检索通常比仅用语义相似度更稳。对时间敏感事实还要按版本与有效期过滤。

## 5. 预算分配而不只看“压缩率”

设模型允许的输入预算为 $B$，固定指令、当前请求、工具模式、工作状态与检索内容分别占用 $b_i$。必须满足：

$$
\sum_i b_i + b_{\text{output reserve}} \le B.
$$

这里的输出预留同样重要：把输入塞满窗口可能导致没有足够空间生成动作或解释。预算应按任务动态分配，例如代码修复可给当前差异和测试错误更多空间，长期闲聊可给用户偏好更多空间。

压缩率可以定义为：

$$
r = \frac{\text{compressed tokens}}{\text{source tokens}}.
$$

它只描述长度，不描述质量。较低的 $r$ 可能意味着更高效率，也可能意味着关键约束已被删除。

## 6. 如何评估压缩质量

### 6.1 建立成对评测

对同一批历史 $H$ 生成压缩视图 $C(H)$，再准备由原始历史可回答的查询集合 $Q$。分别让同一系统基于完整历史和压缩视图完成任务，比较：

- 任务成功率或答案正确率；
- 约束遵循率与关键事实召回率；
- 引用是否能回到正确原始事件；
- 冲突、否定、数字、日期和 ID 的错误率；
- 输入 token、端到端延迟和压缩本身的成本。

“信息保留率”若用压缩后分数除以完整历史分数，只是某个查询集上的实验指标，不是可直接观测的普适信息论常数。必须同时报告任务集、评分器、模型、压缩器和置信区间。

### 6.2 专门测试长尾风险

评测集要包含：

- 早期给出、很久后才使用的约束；
- 被后续信息修正的旧事实；
- 含否定、单位或小数点的关键条件；
- 工具超时但副作用状态未知；
- 多个相似实体和相似文件路径；
- 恶意内容要求摘要器忽略先前指令；
- 需要多个原始事件联合回答的问题。

Lost in the Middle 论文表明，相关信息在长上下文中的位置会影响模型使用效果。这提醒我们不仅要测“是否放入上下文”，还要测放置位置、排序和实际任务表现。

## 7. 版本、失效与重建

每个压缩工件至少记录：

- `summary_id` 与模式版本；
- 覆盖的原始事件 ID 范围；
- 生成模型或算法版本；
- 生成时间和适用任务；
- 受保护字段及其证据引用；
- 被后续事实替代或撤销的状态。

当原始事实更正、权限变化、摘要模式升级或检测到矛盾时，应使相关摘要失效并从原始事件重建。不要在旧摘要上反复补丁，最终却无法判断哪句话来自哪里。

## 8. 一个可实现的压缩流水线

```text
原始事件（追加保存）
  -> 规范化与去重
  -> 提取受保护字段和证据 ID
  -> 按任务/事务边界切块
  -> 对已结束块生成结构化摘要
  -> 模式校验 + 事实回查 + 冲突检查
  -> 写入带版本的摘要层
  -> 根据当前查询检索与排序
  -> 组装临时上下文，保留输出预算
```

失败策略应当保守：摘要校验失败时继续使用原始事件或较长摘录；不能为了满足 token 预算而悄悄删除强约束。实在装不下时，应缩小任务、请求澄清或暂停，而不是伪装成上下文完整。

## 9. 常见误区

1. **长上下文消灭了记忆工程**：窗口更大仍有成本、位置效应、噪声和跨会话持久化问题。
2. **摘要越短越好**：长度不是目标，任务充分性才是目标。
3. **向量库就是长期记忆**：向量只是索引；来源、版本、权限和删除仍要单独管理。
4. **摘要可替代审计日志**：有损文本不能承担完整审计。
5. **所有内容使用同一种压缩器**：代码、JSON、数字、对话和日志的失真容忍度不同。
6. **把论文最大压缩倍数当 SLA**：跨模型、语言和任务不具可迁移保证。

## 10. 验证清单

- [ ] 原始事件与权威工件仍可访问，摘要没有覆盖它们。
- [ ] 任务契约、否定项、数字、ID、来源和未完成状态被显式保护。
- [ ] 摘要带原始事件范围、版本、时间和用途。
- [ ] 工具调用与结果不会被切到无法配对的块。
- [ ] 定期从原始事件重建，避免递归摘要误差无限累积。
- [ ] 查询感知压缩只生成临时视图，不修改长期真值。
- [ ] 评测比较完整历史与压缩历史，并覆盖冲突和长尾约束。
- [ ] 报告 token、质量、延迟和压缩成本，而不是只报压缩倍数。
- [ ] 压缩失败时有保守降级和人工升级路径。
