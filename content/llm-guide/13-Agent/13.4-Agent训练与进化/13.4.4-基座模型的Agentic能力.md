# Agent 能力从哪里来：模型、数据、训练与 Harness

一个 Agent 完成任务的能力来自联合系统，不能全部归功于“基座模型注入了 Agentic 能力”。模型提供理解、生成和动作提议；harness 提供状态、工具、权限、执行、记忆和验证；环境决定反馈是否真实可重复。

## 1. 能力分解

| 能力 | 可能的模型侧来源 | 系统侧仍需负责 |
|---|---|---|
| 理解任务 | 预训练、指令微调 | 任务契约和消歧 |
| 生成合法调用 | 工具格式 SFT、约束解码 | schema 复验和错误处理 |
| 选择工具 | 工具轨迹、RL、上下文学习 | 缩小工具集合、授权 |
| 多步规划 | 推理/规划数据、RL | 状态、依赖、停止和重规划 |
| 使用环境反馈 | 多轮轨迹、交互训练 | 执行隔离和结果验证 |
| 失败恢复 | 失败—恢复轨迹、当前策略 rollout | 错误分类、幂等、检查点 |
| 长期记忆 | 通常不在单次模型权重更新中体现 | 存储、检索、权限、删除 |
| 安全行动 | 安全训练、拒答行为 | 硬权限、审批、沙箱、审计 |

模型“愿意拒绝”不能替代执行端拒绝，模型“记得路径”也不能替代文件作用域校验。

## 2. 预训练

预训练建立语言、代码、文档和世界知识，并可能让模型从文本中学习 API 形态或规划模式。它不能保证：

- 见过当前工具及其最新版本；
- 能严格满足调用 schema；
- 知道当前用户的真实权限；
- 在动态环境中恢复；
- 生成内容事实正确或动作安全。

没有模型报告时，不应猜测某个闭源模型使用了多少“Agent 数据”。

## 3. 持续预训练与中间训练

一些团队使用继续预训练或所谓 mid-training 强化代码、长上下文、特定领域和工具相关分布。`mid-training` 不是跨机构统一的标准阶段；其数据、目标和位置随报告定义而异。

可以核验的内容应来自模型技术报告：数据类别、token 规模、上下文长度、目标函数和消融。不能把某一模型公开的阶段顺序写成所有基座模型的固定流水线。

## 4. 工具与轨迹 SFT

监督数据可包含：

- 无需工具时直接回答；
- 正确工具选择与参数；
- 工具返回后的综合；
- 格式错误、权限拒绝、空结果和超时；
- 多步计划、重规划、停止与人工升级；
- 安全拒绝和高风险动作预览。

只保留成功轨迹会让模型缺少恢复经验；只训练工具调用又可能增加无工具任务上的误调用。训练集应包含负例和“不调用工具”的决策。

## 5. 强化学习

推理 RL 可以优化数学、代码等可验证结果，但未必包含外部环境。交互式 Agent RL 需要工具或环境状态，并对整条轨迹评分。两者不能混为一谈。

公开报告若只说“使用强化学习提升推理”，不能推出 PPO/GRPO、过程奖励、工具环境或 Agentic RL。详见 [Agentic RL 训练](./13.4.1-AgenticRL训练.md)。

## 6. 蒸馏与合成数据

强模型、规则或搜索可生成任务、示范和批评，但合成流水线必须验证：

1. 任务可执行、初始环境可重置；
2. 轨迹中的工具真实执行，而非模型编造结果；
3. 最终成功由独立 evaluator 确认；
4. 数据与测试集、仓库、答案去重；
5. 许可、隐私和敏感数据符合要求；
6. 失败轨迹、恢复和不确定性没有被全过滤掉。

教师正确率不是 100%，筛选器也可能奖励格式漂亮的错误轨迹。

## 7. Harness 是能力的一部分

同一模型因以下变化会得到不同 Agent 结果：

- 工具名称、描述和候选集合；
- 工具返回格式和错误信息；
- 上下文选择、压缩与记忆；
- 最大步骤、重试与计划策略；
- 文件、网络、浏览器或代码接口；
- evaluator、检查点和人工审批。

SWE-agent 研究强调 Agent-Computer Interface 对软件工程 Agent 的影响。这提醒我们：基准比较应报告完整 harness，而不是只报告模型名。

## 8. 外部记忆和测试时适应

把成功/失败案例写入外部记忆，再在相似任务检索，可以改变 Agent 行为而不更新模型权重。这是系统层学习或适应，不应描述成基础模型永久获得新参数能力。

记忆还会带来污染、过期、隐私、删除和跨租户泄漏风险，必须带来源、版本、作用域和失效条件。

## 9. 训练数据最小模式

```yaml
trajectory_id: "..."
task_version: "..."
environment_image: "sha256:..."
policy_snapshot: "..."
available_tools: "catalog-version"
events:
  - action_proposal: "..."
    authorization: "allowed|denied"
    tool_result_ref: "..."
reward:
  source: "tests|rule|model|human"
  value: "..."
final_verification: "..."
contains_privileged_information: false
```

该模式是工程模板，不是行业标准。关键是能追溯任务、环境、策略、工具和奖励。

## 10. 能力归因实验

要判断能力来源，可以依次固定其他变量，进行：

- base vs instruct/SFT；
- 无工具 vs 同模型有工具；
- 相同工具，不同工具描述/ACI；
- SFT vs RL；
- 无记忆 vs 受控记忆；
- 无验证 vs 外部验证；
- 单次调用 vs 同预算 Agent 循环。

报告最终成功、工具参数、恢复、安全、成本和方差。不同产品或不同基准的数字不能组成训练阶段的因果证据。

## 11. 常见误写

- 把 OpenAI o1、DeepSeek-R1 的推理 RL 自动称为交互式 Agent RL；
- 给闭源模型补写未披露的 PPO/GRPO/PRM；
- 把 `mid-training` 写成所有模型相同的正式阶段；
- 把 harness 改进全部算到模型权重；
- 把模型安全训练当成宿主权限控制；
- 把外部记忆适应称为基础模型持续学习。
