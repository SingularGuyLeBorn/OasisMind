# Agentic RL 训练：证据边界与方法谱系

Agentic RL 不是某个固定算法的别名。更稳妥的定义是：模型在多步决策中观察状态、选择文本或工具动作，并从可验证结果或环境反馈中学习策略。它至少包含两类不同问题：

- **推理强化学习**：主要在数学、代码等可验证任务上优化一段推理轨迹，未必与外部环境交互。
- **交互式 Agent 强化学习**：动作会改变网页、操作系统、代码仓库或其他环境状态，奖励依赖整条交互轨迹的结果。

因此，“某模型使用了 RL”不能自动推出它使用 PPO、PRM、在线环境训练，也不能自动把它归为交互式 Agent RL。

## 一、先记录公开披露到什么程度

截至 2026-09-01，下表只陈述论文或官方材料明确披露的信息。

| 系统或方法 | 公开证据支持的说法 | 不能据此推出的说法 |
|---|---|---|
| OpenAI o1 | 官方模型页说明 o1 使用强化学习来执行复杂推理 | PPO、GRPO、PRM、value model、奖励配方和在线工具环境均未在该模型页披露 |
| OpenAI o3 | 公开产品材料不足以建立一套可复现的训练算法 | 不能写成未经披露的确定算法组合 |
| DeepSeek-R1-Zero | 论文披露其从基础模型直接进行 GRPO，并在可验证任务上使用规则奖励 | 这不是所有 Agent 系统的通用训练配方，也不等同于网页或桌面环境训练 |
| DeepSeek-R1 | 论文披露冷启动数据、推理导向 RL、拒绝采样与监督微调等多阶段流程 | 不能把 R1-Zero 的每个细节无条件套到 R1 全流程 |
| Kimi k1.5 | 论文 v4 披露一种 online policy mirror descent 变体、长上下文和 partial rollouts；明确不依赖 MCTS、value function 或 PRM | Kimi k1.5 不是 DAPO；“没有 PRM”也不等于“没有任何奖励模型” |
| DAPO | 官方论文项目披露 Decoupled Clip、Dynamic Sampling、token-level policy-gradient loss 与 overlong reward shaping | DAPO 是独立方法，不能用来补写 Kimi k1.5 未披露的训练细节 |
| Claude computer use | Anthropic 官方材料说明模型被训练来理解截图并操作软件 | 官方说明没有给出策略优化算法，因此相关细节应标为 **unknown** |
| OSWorld | OSWorld 是用于评估计算机 Agent 的真实环境基准 | 基准本身不是训练配方，也不能证明被评模型使用了某种特定强化学习算法 |

来源：[OpenAI o1 模型页](https://developers.openai.com/api/docs/models/o1)、[OpenAI o3 模型页](https://developers.openai.com/api/docs/models/o3)、[DeepSeek-R1 论文](https://arxiv.org/abs/2501.12948)、[Kimi k1.5 论文 v4](https://arxiv.org/abs/2501.12599v4)、[DAPO 官方项目页](https://dapo-sia.github.io/)、[Anthropic computer use 研发说明](https://www.anthropic.com/research/developing-computer-use)、[OSWorld 论文](https://arxiv.org/abs/2404.07972v2)。

## 二、奖励来自哪里

训练页面最容易出错的地方，是把所有反馈都写成“过程奖励”。实际应区分：

1. **规则或执行结果**：测试是否通过、数学答案是否匹配、网页最终状态是否满足约束。
2. **学习得到的结果奖励**：奖励模型对完整输出或完整轨迹评分。
3. **过程奖励**：对中间步骤提供学习得到的监督。它是可选设计，不是推理 RL 的必备组件。
4. **环境代价与安全约束**：无效动作、超时、危险操作或资源消耗可作为约束或惩罚，但权重必须由具体实验说明。

Kimi k1.5 的论文同时讨论规则型正确性奖励与奖励模型，并明确声明不使用 PRM；这两个事实并不矛盾。写作时应保留“结果奖励模型”和“过程奖励模型”的区别。

## 三、方法不是可互换标签

### 3.1 PPO

PPO 是通用的策略优化算法族。只有在论文或官方报告明确披露时，才应把某个产品模型标为 PPO 训练；仅凭“使用 RL”不足以判断。

### 3.2 GRPO

DeepSeek-R1 论文将 GRPO 用于其推理强化学习流程。它以同一问题的一组采样输出形成相对优势估计，从而避免训练一个与策略同规模的 critic。这个结论属于 DeepSeek-R1 的公开方法，不应扩写成所有 Agent 的默认算法。

### 3.3 Kimi k1.5 的 online policy mirror descent 变体

Kimi k1.5 v4 将其优化方法描述为 online policy mirror descent 的变体，并披露长上下文 RL、partial rollouts 和长度相关的课程设计。论文还明确写明不依赖 MCTS、value function 或 PRM。未披露的优化器细节、线上数据来源和产品级训练配方应保持 **unknown**，不要用 DAPO 或 PPO 补全。

### 3.4 DAPO

DAPO 是另一项公开方法，其官方项目页列出四项关键设计：Decoupled Clip、Dynamic Sampling、token-level policy-gradient loss 和 overlong reward shaping。它可以作为大规模可验证奖励训练的案例，但不是 Kimi k1.5 的别名或已知组成部分。

## 四、交互式 Agent RL 还需要环境工程

当动作会改变外部状态时，训练结果同时依赖算法和环境：

- 初始状态是否可重置，任务是否能重复执行；
- 工具返回是否确定，外部网站或软件版本是否固定；
- 成功条件能否由程序化 evaluator 检查；
- 是否限制网络、凭据、文件系统和高风险动作；
- 超时、重试、无效动作和人工接管如何计入结果。

这也是为什么在 OSWorld 上报告成功率，不等同于披露模型的训练算法。基准结果只能说明某个系统在特定版本、任务集和执行配置下的表现。

## 五、最小披露模板

评审一项 Agent RL 工作时，至少记录：

| 维度 | 应披露内容 |
|---|---|
| 策略起点 | 基础模型、监督微调或冷启动数据 |
| 环境 | 任务来源、版本、初始状态与重置方式 |
| 动作空间 | 文本、函数调用、鼠标键盘或代码执行 |
| 反馈 | 规则结果、结果奖励模型、过程奖励或人工反馈 |
| 优化 | 明确算法及与基线的差异；未披露则写 unknown |
| 采样 | 每题轨迹数、长度限制、失败与截断处理 |
| 安全 | 沙箱、权限、网络和人工审批策略 |
| 评估 | 独立测试集、任务版本、成功判定、成本和方差 |

不要使用没有来源的统一奖励公式，也不要把不同论文中的组件拼成一个“行业标准流水线”。

## 六、常见误写

- **给 o1/o3 指定公开材料未披露的算法组合**：相关细节应写 unknown。
- **“Kimi k1.5 使用 DAPO”**：论文描述的是 online policy mirror descent 变体；DAPO 是独立工作。
- **给 Claude computer use 指定策略优化算法**：官方材料没有这样披露。
- **把 OSWorld 当作训练算法**：OSWorld 是评测环境，不是被评模型的训练配方。
- **“没有 PRM 就没有 reward model”**：过程奖励与结果奖励是不同概念。
