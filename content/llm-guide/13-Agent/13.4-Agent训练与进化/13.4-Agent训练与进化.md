# Agent 训练：轨迹、环境、反馈与分布

Agent 能力可以来自预训练知识、工具调用数据、监督轨迹、偏好或结果反馈、交互式强化学习，也可以来自不更新模型权重的检索与记忆。不同方法优化的对象不同，不能都叫作“Agentic RL”。

## 2. 训练对象先分层

| 层 | 可优化对象 | 例子 |
|---|---|---|
| 模型 | token 策略、工具格式、规划或恢复行为 | SFT、RL、蒸馏 |
| 记忆/检索 | 案例选择、经验写入和读取 | 外部 memory policy |
| Harness | 工具目录、状态、重试、上下文、验证 | 规则、搜索、提示优化 |
| 环境 | 任务、状态重置、反馈和 evaluator | 容器、网页、桌面、代码仓库 |

模型分数上升可能来自更好的环境或 harness，而不是模型权重。实验应固定并公开这些版本。

## 3. 训练流水线的最小披露

- 策略起点与模型快照；
- 任务与环境版本、重置方法；
- 动作和观察格式；
- 监督轨迹或 rollout 的来源；
- 结果奖励、过程奖励、规则与安全约束；
- 优化算法、采样、截断和无效轨迹处理；
- 训练/验证/测试切分与污染控制；
- evaluator、成本、方差和失败日志。

没有这些信息，就不应写出确定的“标准配方”。

## 4. 关键风险

- 稀疏奖励让模型难以定位哪一步有效；
- 工具结果不是模型生成 token，损失 mask 和归因边界容易出错；
- 环境不可重置、版本漂移或 evaluator 漏洞会产生虚假奖励；
- 长轨迹增加方差、截断和训练不稳定；
- 离策略示范可能落在当前策略难以到达的状态；
- 奖励塑形可能学会少调用工具，却牺牲正确性；
- 安全约束若只在训练奖励中出现，部署时仍需硬权限门。

## 5. 验收清单

- [ ] 推理 RL 没有被自动等同于交互式 Agent RL。
- [ ] 基准环境没有被写成训练算法。
- [ ] 公开披露与推断明确分开。
- [ ] 工具结果、模型 token 和奖励归因边界清楚。
- [ ] evaluator 独立测试，环境可重置并有版本。
- [ ] 训练增益与 harness 增益通过消融分开。
- [ ] 部署权限不依赖“模型已经对齐”。
