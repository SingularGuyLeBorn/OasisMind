# Agent 训练:轨迹,环境,反馈与分布

Agent 能力可以来自预训练知识, 工具调用数据, 监督轨迹, 偏好或结果反馈, 交互式强化学习, 也可以来自完全不更新权重的检索与记忆. 这些方法优化的对象不同, 不能统统叫作「Agentic RL」. 本节把它们分开, 说明每一类在公开研究中实际做了什么, 以及一次训练要披露哪些信息, 结果才可以复现和比较.

本节对闭源模型只写官方披露的内容. 未公开的优化器, 奖励, 数据和环境一律标为 unknown, 不用其他论文的方法去补全. 这条规则在 Agent 训练领域格外要紧, 因为最受关注的几个系统 (o1, o3, Claude computer use) 恰好披露得最少, 而 DeepSeek-R1, Kimi k1.5 和一批开源 TIR 工作披露得较多, 两者很容易被混在一起叙述.

## 1. 训练对象先分层

### 1.1 四个可优化的层

| 层 | 可优化对象 | 例子 |
|---|---|---|
| 模型 | token 策略, 工具格式, 规划或恢复行为 | SFT, RL, 蒸馏 |
| 记忆/检索 | 案例选择, 经验写入和读取 | 外部 memory policy |
| Harness | 工具目录, 状态, 重试, 上下文, 验证 | 规则, 搜索, 提示优化 |
| 环境 | 任务, 状态重置, 反馈和 evaluator | 容器, 网页, 桌面, 代码仓库 |

一个 Agent 在基准上的分数上升, 原因可能在任意一层. 换了更好的工具描述, 给 evaluator 修了一个漏洞, 或者把重试上限从三次调到五次, 都会让分数变化, 而模型权重一个字节都没动. 所以实验要固定并公开这四层的版本, 训练带来的增益和 harness 带来的增益要通过消融分开.

记忆/检索这一层容易被误归入「训练」. [Memento](https://arxiv.org/abs/2508.16153) 一类工作不微调基础模型, 它学习的是怎样选择和更新外部案例记忆. 这同样能让 Agent 在后续任务上表现更好, 但改变的是系统状态, 部署后可以直接查看, 删除和回滚, 和写进权重的能力在治理上完全不同.

### 1.2 推理 RL 与交互式 Agent RL

[13.4.1 Agentic RL 训练](./13.4.1-AgenticRL训练/13.4.1-AgenticRL训练.md) 把强化学习分成两类问题. 推理强化学习主要在数学, 代码等可验证任务上优化一段推理轨迹, 未必和外部环境交互; DeepSeek-R1-Zero 从基础模型直接做 GRPO, 用规则奖励, 就属于这一类. 交互式 Agent 强化学习的动作会改变网页, 操作系统或代码仓库的状态, 奖励依赖整条交互轨迹的结果.

两类问题的工程负担差别很大. 推理 RL 的环境就是一个判分函数, 可以无限并行, 天然可重置; 交互式 RL 需要可重置的容器或虚拟桌面, 要处理网页变化, 超时, 副作用和 evaluator 漏洞. 「某模型使用了 RL」这句话, 不能自动推出它用了 PPO, 用了过程奖励模型, 或者做过在线环境训练, 也不能自动把它归为交互式 Agent RL.

## 2. 四篇文章的分工

### 2.1 优化算法与奖励来源

13.4.1 的主体是一张披露对照表: 每个系统或方法, 公开证据支持什么说法, 不能据此推出什么. 在算法层面, 它分别说明 PPO, GRPO (来自 DeepSeek-R1, 组内相对优势, 不需要价值模型), Kimi k1.5 的 online policy mirror descent 变体 (论文明确不依赖 MCTS, 价值函数或过程奖励模型) 和 DAPO 的四项设计 (Decoupled Clip, Dynamic Sampling, token 级策略梯度损失, 过长奖励塑形). 这几种方法不能互换标签, Kimi k1.5 不是 DAPO, DAPO 也不能用来补写 k1.5 未披露的细节.

奖励来源决定了能训练什么任务. 规则奖励 (答案匹配, 单元测试) 便宜且难以作弊, 但只覆盖可验证任务; 学习得到的奖励模型覆盖面广, 却会被策略找到漏洞. 交互式任务的奖励来自环境的 evaluator, 它的正确性要像被测代码一样单独测试, 否则策略学到的是 evaluator 的缺陷.

### 2.2 工具进入训练环

[13.4.2 工具集成推理 RL](./13.4.2-Tool-integrated-Reasoning-RL/13.4.2-Tool-integrated-Reasoning-RL.md) 用一个轨迹记号划清边界: $\tau=(x,r_1,c_1,o_1,\ldots,r_T,c_T,o_T,y)$, 其中 $x$ 是任务, $r_t$ 是模型生成的内容, $c_t$ 是工具调用, $o_t$ 是环境返回, $y$ 是最终答案. 只有模型生成的 token 属于策略采样, 工具返回 $o_t$ 要从策略损失里屏蔽, 否则模型会被训练去「生成」它根本无法控制的搜索结果.

在这个框架下, 文章逐个说明公开工作的实际设计. Search-R1 把搜索当作环境, 屏蔽检索 token, 只用最终结果奖励; ToRL 从 Qwen2.5-Math 出发, 研究代码解释器的调用上限和规模; OTC 在正确性之外显式优化工具调用成本, 结果说明奖励能改变调用频率, 不说明调用越少越好. RAGEN 分析了多轮训练的不稳定和 echo trap. 这些结论都只在各自论文的模型, 任务和实现内成立.

### 2.3 数据来自哪个策略

[13.4.3 离策略数据与特权信息](./13.4.3-Off-policyness与Privileged-Information/13.4.3-Off-policyness与Privileged-Information.md) 先定义三个策略: 正在更新的当前策略 $\pi_\theta$, 产生训练轨迹的行为策略 $\mu$, 提供示范或分布的教师策略 $\pi_T$. 数据由 $\pi_\theta$ 采样即 on-policy, 由别的 $\mu$ 产生即 off-policy. 策略更新之后, 刚采样的数据也会逐渐变旧, 所以要写清采样和更新的节奏.

文章纠正了一个常见说法: 「SFT 不稳定, on-policy RL 最稳定」. SFT 的交叉熵优化通常稳定, 但部署时模型自己的早期错误会把它带到示范没覆盖的状态 (covariate shift); on-policy RL 贴近真实访问分布, 却受稀疏奖励, 高方差和长轨迹影响. 特权信息蒸馏 (OPSD 等) 让看得到标准答案或隐藏环境状态的教师指导看不到这些信息的学生, 前提是学生部署时只用合法输入.

### 2.4 能力归因

[13.4.4 Agent 能力来源](./13.4.4-基座模型的Agentic能力/13.4.4-基座模型的Agentic能力.md) 把「Agent 能力」拆成理解任务, 生成合法调用, 选择工具, 多步规划, 使用环境反馈, 失败恢复, 长期记忆和安全行动几项, 每一项分别列出可能的模型侧来源和系统侧仍需承担的责任. 模型「愿意拒绝」替代不了执行端的拒绝, 模型「记得路径」也替代不了文件作用域校验.

能力的来源依次是预训练, 持续预训练或中间训练, 工具与轨迹 SFT, 强化学习, 蒸馏与合成数据, harness 和外部记忆. 其中「mid-training」并没有跨机构统一的定义, 数据, 目标和位置随各家报告定义而异. 第 10 节的能力归因实验给出了把这些来源分开的消融设计, 没有模型报告时, 不猜测某个闭源模型用了多少「Agent 数据」.

## 3. 风险与披露

### 3.1 训练中的主要风险

第一组风险来自奖励和归因. 稀疏奖励让模型难以定位哪一步有效; 工具结果不是模型生成的 token, 损失 mask 和归因边界容易出错; 环境不可重置, 版本漂移或 evaluator 漏洞会产生虚假奖励; 奖励塑形可能让模型学会少调用工具, 代价是正确性下降. 这些问题在单轮推理 RL 里不明显, 到多轮工具环境里会叠加.

第二组风险来自分布和部署. 长轨迹增加方差, 截断和训练不稳定; 离策略示范可能落在当前策略很难到达的状态; 安全约束如果只出现在训练奖励里, 部署时仍然需要硬权限门. 最后这一条和 [13.5.3 安全与对齐](../13.5-Agent应用与治理/13.5.3-Agent安全与对齐/13.5.3-Agent安全与对齐.md) 的立场一致: 训练能降低危险行为的概率, 不能代替执行端的拒绝.

### 3.2 最小披露与验收

一份可复现的 Agent 训练报告要写清: 策略起点和模型快照; 任务与环境的版本及重置方法; 动作和观察的格式; 监督轨迹或 rollout 的来源; 结果奖励, 过程奖励, 规则与安全约束; 优化算法, 采样, 截断和无效轨迹的处理; 训练, 验证, 测试的切分和污染控制; evaluator, 成本, 方差和失败日志. 缺了这些信息, 就不应写出确定的「标准配方」.

读别人的结果时, 验收的问题对应上面几条. 推理 RL 有没有被自动等同于交互式 Agent RL; 基准环境有没有被写成训练算法 (OSWorld 是评测环境, 不是训练配方); 公开披露和推断是否分开; evaluator 是否独立测试过; 训练增益和 harness 增益是否通过消融分开; 部署权限是否依赖「模型已经对齐」这个假设.

## 4. 读法与边界

### 4.1 按背景进入

熟悉 RLHF 和 [第 4 章 后训练](../../4-后训练/4-后训练.md) 的读者, 从 13.4.1 开始, 它和 4.4 强化学习基础, 4.5 GRPO 家族与 RLVR 共用 PPO, GRPO 的推导, 本节只补交互环境带来的新问题. 做工具调用产品, 想知道要不要自己训练的读者, 先读 13.4.4, 再读 13.4.2 的环境工程部分, 多数情况下先改进 harness 和外部记忆, 收益更快, 风险也更容易控制.

研究分布偏移或蒸馏的读者, 13.4.3 是主线, 它的监控指标和实验设计两节给出了检测离策略问题的具体做法. 评测相关的读者把 3.2 节的披露清单和 [13.5.2 Benchmark 与 Eval](../13.5-Agent应用与治理/13.5.2-Benchmark与Eval/13.5.2-Benchmark与Eval.md) 一起读.

### 4.2 与相邻章节的分工

推理时怎样组织规划, 搜索和反思在 [13.2 决策架构](../13.2-Agent认知架构/13.2-Agent认知架构.md); 本节讨论把其中一部分行为训进权重. harness 的状态, 重试和沙箱在 [13.3 系统工程](../13.3-Agent系统工程/13.3-Agent系统工程.md), 本节在归因时把它们当成需要固定的变量.

通用的 RL 算法推导 (PPO 的裁剪目标, GRPO 的组内优势) 在第 4 章, 本节不重复. Agent 通过记忆和技能积累实现自改进, 不经过梯度更新的那条路线, 见 [RSI 花园](../../../rsi/_garden.md).
