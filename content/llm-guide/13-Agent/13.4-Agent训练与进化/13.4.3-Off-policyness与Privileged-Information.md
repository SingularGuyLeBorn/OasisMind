# 离策略数据与特权信息：定义、收益与分布偏移

“off-policyness”不是一个统一可观测分数。它描述训练数据由什么行为策略产生，以及这些状态—动作与当前策略访问分布的差异。示范、旧 checkpoint、经验回放、教师轨迹和当前策略 rollout 都可能形成不同程度的分布偏移。

## 1. 先定义三个策略

- **当前策略** $\pi_\theta$：正在更新的模型或 Agent。
- **行为策略** $\mu$：产生训练轨迹的策略，可能是旧模型、专家、人类或混合系统。
- **教师策略** $\pi_T$：提供分布、动作、批评或示范的更强/特权条件系统。

若数据由当前 $\pi_\theta$ 采样，通常称 on-policy；若由不同的 $\mu$ 产生，则是 off-policy。实际训练中策略更新后，刚采样的数据也会逐渐变“旧”，所以需要明确采样—更新节奏，而不是只给方法贴标签。

## 2. SFT 与 RL 不是稳定性的两端

“SFT 完全 off-policy 且不稳定、纯 on-policy RL 最稳定”是不准确的。SFT 的交叉熵优化通常稳定，但部署时会遇到 covariate shift：模型自己的早期错误把它带到示范数据未覆盖的状态。On-policy RL 更贴近当前访问分布，却可能因稀疏奖励、高方差、长轨迹和环境漂移而不稳定。

| 方法 | 优点 | 主要风险 |
|---|---|---|
| 专家 SFT | 信号密集、实现简单 | 只学示范状态；错误恢复覆盖不足 |
| 当前策略 RL | 覆盖模型真实行为 | rollout 昂贵、奖励稀疏和方差高 |
| 经验回放/旧轨迹 | 复用昂贵环境数据 | 策略漂移，需校正或限制 |
| 教师蒸馏 | 提供更丰富 token 级信号 | 教师偏差、支持集不匹配 |
| 混合训练 | 平衡覆盖、质量与遗忘 | 配比、权重和归因复杂 |

## 3. 特权信息是什么

特权信息只在训练或教师侧可见，部署时学生不能依赖。例如：

- 标准答案或完整证明；
- 隐藏环境状态和 evaluator 诊断；
- 专家成功轨迹；
- 更强模型或更多工具可见的输出；
- 未来信息、测试标签或人工批评。

它可以提高监督密度，但必须保证学生部署时只用合法输入。若把测试答案、未来网页状态或其他用户私有数据引入教师，就会产生泄漏而不是能力提升。

## 4. Privileged Information Distillation

[Privileged Information Distillation for Language Models](https://arxiv.org/abs/2602.04942)研究让教师在附加特权信息条件下指导不看到该信息的学生，并提出 On-Policy Self-Distillation（OPSD）等实例。应按论文定义使用名称：OPSD 是该工作中的具体方法，不是所有 Agent 自蒸馏的统称。

论文结果只支持其模型、数据和训练设置；不能从“教师看答案”直接推出生产 Agent 一定更可靠。还要测试：教师是否泄露答案格式、学生在分布外输入上是否退化、特权信息错误时会发生什么。

## 5. KL 方向的直觉与边界

给定教师 $p_T$ 与学生 $p_S$：

$$
D_{KL}(p_T\|p_S)=\sum_v p_T(v)\log\frac{p_T(v)}{p_S(v)},
$$

$$
D_{KL}(p_S\|p_T)=\sum_v p_S(v)\log\frac{p_S(v)}{p_T(v)}.
$$

Forward KL 对教师有质量的区域加权，倾向覆盖教师支持；Reverse KL 按学生样本区域加权，常表现得更偏向教师高概率模式。这个“mode-covering / mode-seeking”是常见直觉，不是对神经语言模型训练结果的充分证明。

实际还受温度、token mask、序列长度、零概率平滑、采样分布和其他损失影响。必须通过消融而不是凭 KL 名称预测 Agent 行为。

## 6. 长轨迹中的分布偏移

Agent 的状态包含模型先前动作和环境观察。早期动作不同，后续状态就不同。专家只展示成功轨迹时，学生在自己造成的失败状态里可能不知道怎样恢复。

缓解方向包括：

- 收集当前策略失败和恢复轨迹；
- 让专家/教师对学生实际访问的状态提供纠正；
- 混入专家数据防止能力退化，同时控制比例；
- 记录数据产生策略与版本，限制过旧经验；
- 为重要性采样、裁剪或其他校正说明适用条件；
- 在独立环境上测试 rollout 分布，而不只看离线 token loss。

DAgger 展示了让学习策略访问状态并由专家标注的经典思路；语言 Agent 的工具环境更复杂，但“在学生真实状态上获得监督”仍是有用原则。

## 7. 数据与奖励治理

每条训练轨迹建议记录：任务和环境版本、行为策略、采样参数、可见工具、权限、奖励来源、是否含特权信息、是否人工修改、去重和许可状态。

特权信息必须经过：

- 训练/测试与时间泄漏检查；
- 用户和租户权限检查；
- 敏感数据最小化与删除传播；
- 教师输出事实和安全审查；
- 部署输入可用性检查。

## 8. 监控指标

- 当前策略与行为策略的 token/序列概率比或可用代理；
- KL、熵、裁剪比例和梯度范数；
- 当前 rollout 与专家数据的状态/任务覆盖；
- 训练任务、近分布和远分布任务的成功率；
- 正确状态被改坏、错误状态恢复和循环率；
- 工具调用、成本、安全与 evaluator 利用行为。

`pass@k - pass@1` 的变化不能单独诊断 off-policyness；它同时受模型多样性、采样温度和任务难度影响。

## 9. 实验设计

至少比较：专家 SFT、当前策略 RL、两者混合、带/不带特权信息教师、不同 KL/损失方向。保持模型、任务、环境步数和总计算尽量可比，报告多随机种子。

还应专门构造：教师错误、特权信息缺失、环境漂移、学生进入专家未见失败状态、训练答案泄漏等压力测试。

## 10. 验收清单

- [ ] 当前策略、行为策略和教师策略分别定义。
- [ ] 没有把 SFT 写成天然不稳定，也没有把 on-policy RL 写成天然稳定。
- [ ] 特权信息在部署时确实不可用且没有泄漏测试答案。
- [ ] OPSD 等名称只用于其原论文定义的方法。
- [ ] KL 方向的直觉没有被写成性能定理。
- [ ] 评测覆盖学生自己造成的失败状态与恢复。
