# 上下文管理：选择、压缩、隔离与缓存

上下文窗口是一次模型调用可见的输入，不是 Agent 的完整状态或长期记忆。可靠系统保留权威工件和事件，再为每次调用组装一个受预算、权限和任务相关性约束的视图。

## 1. 五类数据不要混在一起

| 数据 | 例子 | 权威性与生命周期 |
|---|---|---|
| 稳定指令 | 角色、政策、输出契约 | 版本化；不能被工具文本覆盖 |
| 任务状态 | 目标、计划、待办、预算 | 单次运行，可持久化与恢复 |
| 原始事件 | 调用、授权、结果、错误 | 追加记录，用于审计与重建 |
| 权威工件 | 文件、数据库、测试报告 | 真实来源；上下文只放摘录与引用 |
| 记忆/摘要/索引 | 历史经验、摘要、向量 | 派生视图，可失效和重建 |

KV cache 或供应商 prompt cache 是计算优化，不等于用户记忆；向量索引是查找结构，也不是权威事实。

## 2. 组装上下文的预算

设输入预算为 $B$，系统指令、工具契约、当前请求、工作状态、观察和检索片段分别占用 $b_i$，还需给模型输出保留 $B_{out}$：

$$
\sum_i b_i + B_{out} \le B.
$$

预算是上限，不是“越满越好”。过多候选工具、重复历史和长日志会降低有效信息密度。不同任务应动态分配：代码修复重视差异与测试，研究任务重视来源与引用，审批任务重视对象与副作用。

## 3. 六种互补策略

### 3.1 选择

只装入当前步骤需要的信息。稳定约束、当前目标和未完成状态通常常驻；历史闲聊和可重新获取的大输出不必重复进入每次请求。

### 3.2 卸载

把代码、数据、长报告和日志保存为权威工件，上下文中只保留路径、版本、摘要和必要片段。卸载不是遗忘，读回时要验证对象版本没有变化。

### 3.3 检索

按关键词、实体、时间、结构和语义召回候选，再按权限、来源、时效和任务相关性排序。检索失败不证明事实不存在；召回文本也不能获得系统指令的信任级别。

### 3.4 压缩

对结束的事件块生成结构化摘要，保留目标、约束、决定、证据、错误和未完成项。摘要带源事件范围和版本，定期从原始事件重建。详见 [记忆压缩](../13.1-Agent核心组件/13.1.2-记忆压缩.md)。

### 3.5 隔离

为子任务或子 Agent 提供最小必要上下文，而不是复制主任务全部历史。交接消息应包含输入版本、目标、约束、输出契约、允许工具和完成证据。

### 3.6 缓存

对稳定前缀或模型计算复用供应商/推理引擎缓存。缓存键应包含模型、token 序列、工具和指令版本；内容更新、权限变化或模型升级时失效。缓存命中节省计算，不会自动刷新过期事实。

## 4. 工具结果的处理

工具结果常是上下文最大的来源，也可能包含提示注入或敏感信息。建议：

1. 保存原始结果或权威对象引用；
2. 校验调用 ID、来源、状态和模式；
3. 先过滤凭据与不必要个人数据；
4. 提取关键字段、错误和证据定位；
5. 把文本标为不可信数据；
6. 对敏感下一动作重新做授权。

不要把终端或网页最后一行直接拼成高优先级指令。

## 5. 多 Agent 交接契约

```yaml
task_id: audit-links
input_version: commit-or-snapshot
goal: "检查页面的一手来源链接"
constraints:
  - read_only
allowed_tools: [search, open]
deliverable_schema:
  findings: []
  checked_urls: []
success_evidence: "每项结论对应原始来源"
```

接收者不需要发送者的完整聊天历史。发送者也不应把未经核验的私有猜测包装成事实。交接内容必须能被主编排器验证和合并。

## 6. 上下文缓存的边界

- 缓存稳定前缀时，动态用户数据应位于前缀之后；
- 工具目录变化会改变模型决策空间，应参与缓存版本；
- 不同租户不得共享可能含私有数据的缓存条目；
- 已撤销权限、已删除记忆和过期事实要触发失效；
- 报告命中率时同时报告延迟、成本和内容新鲜度。

不要从“提供 prompt caching”推断产品保存策略，也不要把推理引擎内部 KV cache 当成可编辑记忆。

## 7. 典型失败

| 失败 | 原因 | 修复 |
|---|---|---|
| 早期约束丢失 | 滑动窗口只保留最近消息 | 契约与未完成状态常驻 |
| 摘要漂移 | 多次摘要的摘要 | 保留原始事件，周期性重建 |
| 版本错配 | 读到旧文件或旧分支 | 工件引用带版本/哈希 |
| 工具描述挤占 | 一次暴露过多工具 | 按任务缩小候选集合 |
| 跨角色泄露 | 子 Agent 收到全部用户数据 | 最小上下文、字段脱敏、作用域 |
| 缓存陈旧 | 权限或事实变化未失效 | 版本键与主动失效 |
| 持久注入 | 恶意网页进入长期记忆 | 写入审查、来源、可撤销 |

## 8. 评测

对同一任务比较完整上下文与管理后上下文：

- 任务成功、约束遵循、关键事实与证据召回；
- 冲突、否定、数字、日期和 ID 的错误率；
- 越权召回、删除后残留和提示注入成功率；
- 输入 token、缓存命中、首 token/端到端延迟和费用；
- 长任务在压缩前后能否从检查点恢复。

压缩率、命中率或上下文长度都不是最终质量指标。

## 9. 验收清单

- [ ] 权威工件与原始事件没有被摘要覆盖。
- [ ] 每次调用的上下文有明确任务、权限和 token 预算。
- [ ] 摘要、检索与缓存带来源、版本和失效条件。
- [ ] 工具结果作为不可信数据处理。
- [ ] 子 Agent 只收到完成子任务所需内容。
- [ ] 缓存失效覆盖模型、指令、工具、权限与数据版本。
- [ ] 评测包含长尾约束、冲突、删除和注入。
