# Agent 决策架构：反馈、规划与自我修正

Agent 的“认知架构”不是模型内部大脑结构的复刻，而是系统怎样组织目标、状态、候选动作、环境观察、验证和停止。它可以包含模型生成的计划，也可以包含规则、搜索、外部验证器和人工决策。

> **证据边界**：本文截至 2026-09-01。ReAct、Tree of Thoughts、Reflexion 等论文证明的是特定方法在特定任务与设置中的实验结果，不构成对任意模型、任意 Agent 的普遍增益保证。

## 2. 三种稳定架构形态

### 2.1 反应式循环

系统读取最新观察，选择下一动作，再把结果送回循环。它适合路径依赖中间结果、无法预先穷举的任务。ReAct 是公开研究中的代表性提示与轨迹组织方法，但生产系统可以只记录动作摘要和证据，不必暴露自由文本思维链。

### 2.2 计划—执行—重规划

系统先把目标拆成带依赖的步骤，执行器逐项推进；前提失效或结果不符合预期时，明确记录原因并重规划。它适合依赖清楚、可并行或需要里程碑的任务。计划必须可修订，不能把最初猜测当成事实。

### 2.3 候选—评估—选择

系统生成多个候选状态或动作，使用任务专用 evaluator、规则或有限的模型裁判筛选，再展开较优候选。Tree of Thoughts 是这一类搜索的研究实例。它增加测试时计算，不保证评估器能识别真实最优路径。

三者可组合：先生成粗粒度计划，在每个子任务里采用反应式循环；遇到关键不可逆决策时生成多个候选并由外部规则或人工选择。

## 3. 可观察接口比“像人脑”更重要

一个可审计的决策步应回答：

- 当前目标和不可违反的约束是什么？
- 哪些事实来自环境，哪些只是模型假设？
- 候选动作的参数、副作用和权限是什么？
- 动作执行后得到了什么新证据？
- 验证器是否确认进展，还是只得到“调用成功”？
- 什么条件会停止、回退、重规划或请求用户？

这些接口可以测试；“前额叶”“意识”“涌现”之类比喻无法直接构成验收条件。

## 4. 选择架构的依据

| 条件 | 更合适的起点 |
|---|---|
| 路径固定、步骤确定 | 普通工作流，不必使用动态 Agent |
| 每次观察都会改变下一步 | 反应式循环 |
| 依赖关系清楚、可并行 | 计划—执行 |
| 少数关键步骤值得额外计算 | 有限候选搜索 |
| 高风险且结果难验证 | 降低自治，增加预览与人工检查 |
| 反馈只能来自模型自评 | 谨慎使用修正循环，优先补外部验证器 |

“规划更多”并不总是更好。任务短、工具确定时，额外 Planner 可能只增加成本和失败面；任务长而前提多时，没有显式状态和重规划又容易积累错误。

## 5. 评估认知架构

在同一模型、工具和预算下做消融，分别移除规划、候选搜索或反思，报告：

- 外部验证的任务成功率；
- 首次成功率、重试后成功率和把正确结果改错的比例；
- 无效调用、重复动作、回退和人工介入；
- token、调用次数、端到端延迟和费用；
- 正常、异常、恶意输入和环境漂移下的结果；
- 随机种子或多次运行造成的方差。

不同论文中的百分比不能拼成一条“架构演进曲线”。如果任务、模型、工具或 evaluator 不同，结果就不具直接可比性。

## 6. 验证清单

- [ ] 架构描述落到了状态、动作、观察、验证和停止接口。
- [ ] 自由文本推理没有被当作必须公开的审计证据。
- [ ] 计划可以因新证据更新，且更新理由被记录。
- [ ] 反思循环以外部反馈为主，并有预算和无进展停止。
- [ ] 未将控制论公式、人体器官或物理概念直接当作 Agent 性能证明。
- [ ] 任何增益数字都能回到同一实验设置中的一手来源。
