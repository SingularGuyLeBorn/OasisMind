# 反思与自我修正：反馈、验证与停止条件

反思不是让模型无限重复“再想一遍”。可靠的自我修正需要三件事：可定位的失败证据、与失败类型匹配的下一步动作，以及明确的停止或升级条件。没有外部证据时，模型可能只是把原答案换一种说法，也可能把正确答案改错。

## 一、四类相关方法不要混为一谈

| 方法 | 反馈来自哪里 | 是否更新模型权重 | 公开工作中的核心边界 |
|---|---|---|---|
| Reflexion | 环境反馈、自生成反思和后续试验结果 | 否 | 把语言反馈写入 episodic memory，影响下一次轨迹；不是梯度式“在线训练” |
| Self-Refine | 同一基础模型承担生成、反馈和改写角色 | 否 | 不需要额外训练，但改进依赖模型能否识别自身错误 |
| CRITIC | 搜索、代码解释器等外部工具返回的证据 | 否 | 工具用于验证与纠错；工具选择和查询本身仍可能失败 |
| Self-RAG | 模型生成特殊 reflection tokens 来控制检索并评价证据与回答 | 是，论文训练了相应模型 | 它是带训练的检索与自评框架，不能等同于任意提示词式“自我反思” |

来源：[Reflexion](https://arxiv.org/abs/2303.11366)、[Self-Refine](https://arxiv.org/abs/2303.17651)、[CRITIC](https://arxiv.org/abs/2305.11738)、[Self-RAG](https://arxiv.org/abs/2310.11511)。

## 二、最小可验证循环

推荐把一次修正写成清晰的状态转换，而不是装饰性流程图：

> 任务与约束 → 生成候选 → 调用外部检查 → 读取证据 → 分类失败 → 选择不同的下一步 → 再检查

循环只有三种出口：

1. **成功**：外部检查满足预先定义的成功条件；
2. **升级**：需要新权限、关键信息或人工判断，交给用户或专家；
3. **停止**：达到预算、连续无进展或安全边界，保留当前证据并报告失败。

这里的“外部检查”应尽量是与任务匹配的可执行证据：

- 代码：目标测试、静态检查、编译器和精确差异；
- 数学：代入验证、符号计算或独立求解；
- 检索：原始论文、官方文档和逐条引文核对；
- 网页或桌面操作：页面/应用最终状态与任务专用 evaluator；
- 开放式文本：事实核验、约束清单和必要的人工评审。

“另一个模型觉得更好”可以是辅助信号，但通常不能替代真实任务结果。

## 三、把失败分型，而不是泛泛反思

| 失败类型 | 可观察证据 | 更合适的下一步 |
|---|---|---|
| 信息缺失 | 找不到所需文件、来源或参数 | 搜索、提问或请求权限 |
| 事实冲突 | 两个一手来源给出不同版本 | 标注版本与日期，保留不确定性 |
| 规划错误 | 工具结果显示前提不成立 | 回退到最近有效状态，重做计划 |
| 执行错误 | 命令、测试或工具返回明确错误 | 根据错误信息修正最小步骤 |
| 验证错误 | evaluator 不覆盖真实需求 | 补充判据，而不是只优化现有分数 |
| 权限或安全阻断 | 动作越权、涉及凭据或不可逆影响 | 停止并请求人工授权 |

一条有用的反思记录至少包含：`失败证据`、`原因假设`、`下一步变化`、`适用条件`。不要把未经验证的原因假设写入长期记忆成为“事实”。

## 四、停止条件与防循环

反思系统应显式维护：

- 最大轮数、时间、token、工具调用或费用预算；
- 最近一次成功检查的状态与可回滚点；
- 已尝试动作及其结果，避免原样重试；
- 当前失败类型是否变化，是否连续多轮没有新证据；
- 是否触碰权限、安全或数据完整性边界。

可以用任务状态的摘要作为重复检测线索，例如“目标 + 当前错误 + 最近动作 + 关键文件版本”。这只是工程做法，不应伪装成通用最优公式。

```text
while budget_remaining:
    candidate = act(task, evidence, memory)
    result = verify(candidate)
    if result.passed:
        return candidate
    if result.needs_permission or result.high_risk:
        return escalate(result.evidence)
    lesson = diagnose(result.evidence)
    if no_new_evidence_or_action(lesson):
        return stop_with_evidence(result)
    memory = record_bounded_lesson(memory, lesson)
return stop_with_evidence("budget exhausted")
```

## 五、为什么内部自评不够

论文《Large Language Models Cannot Self-Correct Reasoning Yet》指出，在缺少外部反馈时，提示模型反复自我修正并不稳定，某些设置下还会损害原本正确的答案。[DeepMind 论文页](https://deepmind.google/research/publications/48252/)

这不意味着所有反思机制都无效，而是说明需要区分：

- **内部批评**：便宜、通用，但批评者与生成者可能共享同一盲点；
- **工具验证**：证据更具体，但工具可能报错、被误用或覆盖不全；
- **环境反馈**：贴近真实任务，但可能昂贵、随机或不可逆；
- **人工反馈**：适合歧义、价值判断和高风险动作，但不能无限扩展。

可信顺序通常是：先用确定性检查，再用任务专用 evaluator；开放式判断才考虑模型评审或人工评审，并保留判据和原始证据。

## 六、记忆与反思的边界

Reflexion 把语言反思保存在情节记忆中，供后续尝试读取。工程实现时还要增加治理：

- 只保存与明确失败证据相连的短经验；
- 标注任务、工具版本、时间和适用条件；
- 新证据推翻旧经验时进行失效或版本化；
- 不保存凭据、敏感数据和外部提示中的指令；
- 定期测试记忆是否让新任务变好，而不是仅增加上下文。

详见 [13.1.1 · 记忆系统](../13.1-Agent核心组件/13.1.1-记忆系统.md)。

## 七、实施检查表

- 成功条件能否在执行前写清，而不是事后移动门槛？
- 每次失败是否有原始工具输出、测试或来源支撑？
- 下一轮是否真的改变动作，而不是只改措辞？
- 是否设置预算、无进展停止、人工升级和回滚点？
- 反思记录是否带来源、版本、适用范围和失效条件？
- 评估是否包含“把正确答案改错”的退化率？
