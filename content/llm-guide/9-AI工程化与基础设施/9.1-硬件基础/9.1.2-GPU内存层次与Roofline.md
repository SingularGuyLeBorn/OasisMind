# 9.1.2 GPU 内存层次与 Roofline

> 第 9 章索引：[9 AI工程化与基础设施](../9-AI工程化与基础设施.md) · 邻居 [9.1 硬件基础](./9.1-硬件基础.md)（代际与 Tensor Core）· 算法侧 [2.3.1 硬件高效注意力](../../2-核心原理与架构/2.3-高效与稀疏注意力/2.3.1-硬件高效注意力/2.3.1-硬件高效注意力.md)

标准注意力为什么「算得动、搬不动」？不是 Softmax 公式写错了，而是 **HBM 比片上 SRAM 慢一个数量级以上**，而朴素实现要把 $S\times S$ 的分数矩阵写进这条慢通路。FlashAttention 是对这条物理事实的软件回答。本节把层次、带宽公式和 Roofline 写全；规格数字只用来自下面「参考文献」的官方页。

第 6 章讲怎么减访存、怎么并行；本节只回答：**数据在哪一层、一层能撑多少、算力强度跨过哪条线才算用满 Tensor Core**。

## 1. 问题：一次注意力到底在搬什么

设序列长 $S$，头维度 $d$。一次因果注意力对每个头做

$$
\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V,
$$

其中 $Q,K,V\in\mathbb{R}^{S\times d}$。$QK^\top$ 是 $S\times S$ 的分数矩阵。若把整张分数矩阵物化到设备全局内存（HBM），读写量随 $S^2$ 涨。每个分数元素随后只参与很少几次运算（scale、mask、softmax、再乘 $V$），**运算次数跟不上搬运次数**。

这就是「内存墙」：GPU 的 Tensor Core 峰值很高，但峰值只有在数据已经躺在寄存器 / 共享内存里时才摸得到。注意力的痛不在乘法器不够，而在反复穿过 HBM。

后面用算力强度把这句话写成一条可以画在 Roofline 上的直线。

## 2. CUDA 规定的四级地址空间

NVIDIA CUDA C++ Programming Guide 把线程可见的存储画成固定层级，而不是「显存」一个词（[Memory Hierarchy](https://docs.nvidia.com/cuda/cuda-c-programming-guide/#memory-hierarchy)）：

| 空间 | 谁看见 | 生命周期 | 对应硬件直觉 |
|------|--------|----------|----------------|
| 每线程 private / local | 单线程 | 线程 | 寄存器；溢出才进 local memory（仍在 HBM 上，只是私有编址） |
| 每 block 的 shared memory | 同 block | block | 片上 SRAM scratchpad，程序员用 `__shared__` 显式管理 |
| 全局 global memory | 全 grid | 核函数之间仍在 | HBM（数据中心卡）或 GDDR（消费卡） |
| 另：L1 / L2 | 硬件缓存 | 对程序员半透明 | L1 常与 shared 争同一块 SM 上的 SRAM；L2 芯片共享 |

Guide 的关键句是：block 内线程靠 shared memory 合作，并用 `__syncthreads()` 对齐访存。FlashAttention 的 tiling 就是把 $Q,K,V$ 的一块搬进 shared，在块内做完 softmax 的在线归约，再把 $O$ 的一块写回 HBM——**中间的 $S\times S$ 不要落盘**。

Hopper 起还有 Distributed Shared Memory（cluster 内跨 block 看对方的 shared）。那是 9.2 的编程模型；本节只要记住：比 HBM 快的那一层，容量以 KB～MB 计，不是 GB。

## 3. 容量与延迟：金字塔为什么陡

同一张卡上，从寄存器走到 HBM，容量涨三个数量级以上，延迟也涨三个数量级以上。下面容量取官方调优指南能核对的数字，不把第三方「经验延迟」写成规格。

NVIDIA [Blackwell Tuning Guide](https://docs.nvidia.com/cuda/blackwell-tuning-guide/) 写明：B200 与 H100 一样，每个 SM 上 L1/texture/shared 的组合上限 256 KB；shared memory 可配置档位包含 0、8、16、32、64、100、132、164、196、**228 KB**。

HBM 容量与带宽用产品页，不用早期营销稿里互相打架的「192 GB」：

| 产品 | 每卡容量 | 带宽 | 来源 |
|------|----------|------|------|
| H100 SXM | 80 GB HBM3 | 3.35 TB/s | [NVIDIA H100](https://www.nvidia.com/en-us/data-center/h100/) |
| H200 SXM | 141 GB HBM3e | 4.80 TB/s | [HGX AI Factory Components](https://docs.nvidia.com/enterprise-reference-architectures/hgx-ai-factory/latest/components.html) |
| B200 SXM | **180 GB** HBM3e | 最高 8 TB/s | 同上；[DGX B200](https://www.nvidia.com/en-us/data-center/dgx-b200/) 为 8 卡共 1,440 GB |
| B300 SXM | 288 GB HBM3e | 最高 8 TB/s | HGX AI Factory Components |
| Rubin GPU | 最高 288 GB HBM4 | 最高 22 TB/s | [NVIDIA Technical Blog · Rubin](https://developer.nvidia.com/blog/inside-nvidia-rubin-gpu-architecture-powering-the-era-of-agentic-ai/) |

9.1 正文里曾写 B200「192 GB」。那是 2025 笔记里常见的宣传口径。2026-08 以 HGX/DGX 文档的 **180 GB** 为准；192 GB 只当作未出货/未写入该表的上限叙述。勘误记在 [9.1 文末修订](./9.1-硬件基础.md)。

HBM 快，是因为位宽极大（堆叠 DRAM + TSV），不是因为单 pin 比 GDDR 更快。容量涨得比算力慢：模型参数、Adam 态、激活、KV 都要住在这一层。ZeRO / 重计算 / PagedAttention 全是在跟这一层的 **GB 数** 谈判，不是跟 FLOPS 谈判。

![GPU 内存层次：寄存器、共享内存、L2、HBM](./images/fig-gpu-memory-hierarchy.png)

> 图 1：层次示意。越往上容量越小、越靠近 Tensor Core。FlashAttention 的目标是让 $QK^\top$ 的中间结果尽量停在 Shared Memory / 寄存器，而不是往 HBM 写一张 $S\times S$ 的表。

## 4. 算力强度：把「搬一次能算几次」写成数

定义 **operational intensity**（算力强度、运算强度）

$$
I \;=\; \frac{\text{该 kernel 执行的浮点运算次数}}{\text{从慢存储读入的字节数}}\qquad [\mathrm{FLOP/Byte}].
$$

慢存储对 LLM kernel 几乎总是 HBM。一次 FMA 计 2 FLOP。

**大 GEMM**（例如 $M{=}N{=}K{=}4096$ 的 FP16 乘）：算术量 $\sim 2MNK$，读写大约是三块矩阵各 $2MN$ 字节量级（还要算 tile 重复加载）。$I$ 可以到几百 FLOP/Byte，跨过下面的 ridge point，于是受峰值算力限制。

**逐元素算子**（LayerNorm、softmax 的逐行 exp）：每个元素几次 FLOP，却要完整读入再写出，$I$ 往往只有 $O(1)$ FLOP/Byte，必然受带宽限制。

**朴素注意力**：物化 $S\times S$ 分数矩阵时，HBM 流量含 $\Theta(S^2)$ 项，而每个分数只摊到常数次 FLOP，所以 $I$ 随 $S$ 变差。这就是 FlashAttention 论文把注意力重新表述成 **IO-aware** 算法的动机（Dao et al., 2022, [arXiv:2205.14135](https://arxiv.org/abs/2205.14135)）。

## 5. Roofline：一条横线、一条斜线

Williams、Waterman、Patterson 的 Roofline（*Communications of the ACM*, 2009）把峰值画成

$$
P_{\text{attainable}}(I) \;=\; \min\!\bigl(P_{\text{peak}},\; B_{\text{peak}}\cdot I\bigr).
$$

- $P_{\text{peak}}$：该精度下 Tensor Core（或 CUDA core）峰值，单位 FLOP/s。
- $B_{\text{peak}}$：该级存储的峰值带宽，单位 Byte/s。对「有没有吃满 GPU」通常先取 **HBM 带宽**。
- 两条线的交点称为 **ridge point**

$$
I_{\text{ridge}} \;=\; \frac{P_{\text{peak}}}{B_{\text{peak}}}.
$$

$I < I_{\text{ridge}}$：带宽墙，加 FLOPS 没用，要减访存、提高缓存复用、换更窄的数据类型。  
$I > I_{\text{ridge}}$：算力墙，要更大的 tile、更好的 MMA 流水、更高的占用率。

用 H100 SXM、**无稀疏** 的官方口径做一次算术（数据表脚注：标了星号的 Tensor Core 数含稀疏；无稀疏取一半）：

- 稠密 FP16 Tensor Core：1979 / 2 = **989 TFLOPS**
- HBM： **3.35 TB/s**

$$
I_{\text{ridge}}^{\text{H100, FP16 dense}} \;\approx\; \frac{989\times 10^{12}}{3.35\times 10^{12}} \;\approx\; 295\ \mathrm{FLOP/Byte}.
$$

含义：从 HBM 读 1 字节，硬件「希望」你做约 300 次 FLOP。注意力中间矩阵做不到这个强度，所以即使用满 Tensor Core 的宣传 TFLOPS，实测仍会贴在斜边上。

把同一公式套到 Rubin 官方博文给出的 **NVFP4 推理峰值 50 PFLOPS** 与 **HBM4 22 TB/s**（[Rubin 博文](https://developer.nvidia.com/blog/inside-nvidia-rubin-gpu-architecture-powering-the-era-of-agentic-ai/)）：

$$
I_{\text{ridge}}^{\text{Rubin, NVFP4}} \;\approx\; \frac{50\times 10^{15}}{22\times 10^{12}} \;\approx\; 2270\ \mathrm{FLOP/Byte}.
$$

[OM-FREEPLAY] 50 PFLOPS 是博文中的推理峰值口径，是否含稀疏、是否单卡可持续，以日后白皮书为准；这里只说明 **代际越往后，ridge 越高，越逼你做 IO-aware kernel 和更低比特**。不要把 2270 当成可以写进招标书的承诺。

## 6. 回到注意力：FlashAttention 在金字塔上做了哪一步

FlashAttention 不改数学上的 softmax 注意力，改的是 **数据摆放**：

1. 把 $Q$ 的一行 tile、对应的 $K,V$ tile 从 HBM 搬进 SRAM。
2. 在 SRAM 里做分块 $QK^\top$、在线 softmax（维护 $m_i$ 与 $\ell_i$ 两个统计量），累加输出 tile。
3. 只把最终 $O$ 写回 HBM。

SRAM 装不下整段 $S$ 时就按块循环。复杂度分析见原论文的 IO 下界，不在这里重推。要点只有一句：**它把 $I$ 从「带 $S^2$ 写 HBM」抬到「只流 $Q,K,V,O$」**，所以能从 Roofline 的斜边往上走。

工程上还要避开 shared memory 的 **bank conflict**（32 bank 对齐 warp）。那是 9.2 与 CUTLASS 的课；本节只要知道：层次存在，不等于随便 `__shared__` 就快。

与第 6 章的接口：量化、KV paging、投机解码，都是继续降低 HBM 上的字节数或重复加载。它们不替代 Roofline，只是改变 $I$ 和 $B$ 的有效值。

## 7. 失效条件

- **只看峰值 FLOPS 选型**：decode 阶段每步只吃一个 token 的 $Q$，强度极低，买再贵的卡也会坐在斜边上。PD 分离（prefill 偏算力、decode 偏带宽）就是这个图的运维版本，细节见 [9.4.1](../9.4-推理服务框架/9.4.1-SGLang与Prefill-Decode分离.md)。
- **把 L2 当免费 HBM**：L2 是缓存，容量是几十 MB 量级（9.1 记录 A100 40 MB、H100 50 MB；未在本篇数据表中的型号不要编）。长上下文 KV 仍然住在 HBM。
- **跨节点套用卡内带宽**：NVLink / IB 见 [9.1.3](./9.1.3-卡间互联与集群拓扑.md)。Roofline 的 $B$ 换成功带宽后，同一公式仍可用，数字会掉一到两个数量级。
- **非 NVIDIA**：TPU 的片上 SRAM 更大、HBM 叙事不同。对照表见 [9.1.4](./9.1.4-加速器全景.md)，不在本篇假装「全世界都是 SM + HBM」。
