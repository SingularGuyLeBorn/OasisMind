# 3.3 分词器：子词怎么把文本变成 ID

模型不读字符串，只读整数 ID。分词器是预训练管道的第一道工序：它决定词表大小 $V$、同样 8K 窗口里能装多少自然语言、以及未登录字符会不会把序列打成 `[UNK]`。算法细节、工业正则、Llama 3 的 128K 词表，写在 [3.3.1 训练 Tokenizer](./3.3.1-训练Tokenizer/3.3.1-训练Tokenizer.md)。本节只把三条路立住：**词级太碎、字符级太长、子词走中间**。

下面用 BPE 合并图。

## 1. 两极都不可用

**词级**：英语词形膨胀，词表可到 $10^5$–$10^6$；新词、拼写错误、代码标识符直接 OOV。`play` / `playing` / `played` 变成三个无关向量。

**字符级**：词表极小，OOV 消失，但序列长度大约按字符走。自注意力 $O(L^2)$，同样上下文窗口装下的语义更少。汉字若再拆成 UTF-8 字节，8K 窗口大约只够两千多字。

子词的折中：高频词保持整块，低频词拆成可组合的片段。训练目标是在语料上学习一份 **merge 表 + 词表**，推理时确定性（BPE / WordPiece）或按概率（Unigram）切开。

## 2. BPE：最高频相邻对，合并

BPE 源自压缩（Gage, 1994），Sennrich et al. (2016) 把它变成机器翻译的子词单元。流程：字符（或字节）初始化 → 统计相邻对频率 → 合并最高频对 → 重复直到 $|V|$ 达到目标。

![](./images/fig-bpe-merge-steps.png)

> 图 1：玩具语料上的两次贪心合并。`play_` 出现 5 次、`player_` 出现 3 次，对 $(p,l)$ 共现 8 次，先合并成 `pl`，再合并 $(pl,a)$。（示意，不是论文截图）

**图 1 解析**

- Step 0：词尾 `_` 当作普通符号，避免跨词合并（空白预分词的 BPE 需要这一步；SentencePiece 则把空格本身编进流）。
- Step 1：贪心只看计数，不看「语言学是否像词根」。
- Step 2：合并在**新序列**上重数，不是在原始字符上一次性想好全部词。
- 局限：中文等大字符集上「以字符为原子」会让初始词表膨胀；跨语言难共用一套字符。下一节的 BBPE 把原子改成 256 个字节。

WordPiece（BERT）同样贪心合并，但打分是

$$
\mathrm{score}(X,Y)=\frac{\mathrm{freq}(XY)}{\mathrm{freq}(X)\,\mathrm{freq}(Y)} \tag{1}
$$

偏向「强绑定」而不是纯高频。Unigram（Kudo, 2018）相反：从大词表做减法，用 EM 估 $P(t)$，推理走 Viterbi。SentencePiece（Kudo & Richardson, 2018）是**框架**：输入视为原始 Unicode，空格变成元符号 `▁`，底层可选 BPE 或 Unigram，分词可逆。

## 3. 怎么选（和怎么不要选）

| | BPE | WordPiece | Unigram | SentencePiece |
|--|-----|-----------|---------|----------------|
| 合并哲学 | 频率贪心 | 似然比贪心 | 概率剪枝 | 包装 BPE 或 Unigram |
| 预分词 | 通常要 | 通常要 | 通常要 | 不要 |
| 可逆 | 取决于空格处理 | 否 | 否 | 是（空格显式编码） |
| 常见绑定 | GPT 系、Llama 3 tiktoken 风格 | BERT | T5 / ALBERT（经 SP） | Llama 1/2、T5 |

开源权重必须配**同一份** tokenizer 文件。换词表等于换 embedding 行，属于 [3.2.7 CPT](../3.2-预训练全流程/3.2.7-继续预训练/3.2.7-继续预训练.md) 而不是「预处理开关」。

细节、正则预切、Llama 3 压缩率 3.17→3.94 字符/token：进 [3.3.1](./3.3.1-训练Tokenizer/3.3.1-训练Tokenizer.md)。
