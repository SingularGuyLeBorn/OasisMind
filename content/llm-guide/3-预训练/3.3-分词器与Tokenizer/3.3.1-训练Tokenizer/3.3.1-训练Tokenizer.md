# 3.3.1 训练 Tokenizer:语料到 merge 到词表

沿用 [3.3](../3.3-分词器与Tokenizer.md) 的问题:词级 OOV,字符级 $L$ 太长.本篇写**怎么从语料得到一份可复现的词表**,以及 $V$ 怎样咬进 embedding 矩阵和注意力长度.Llama 3 把词表从 Llama 2 的 32K 扩到 128K,官方给出的是压缩率,不是「中文 fertility < 1」这类未核对口号.

## 1. $V$ 同时拉 embedding 和序列长度

词表大小 $V$ 锁定两块矩阵:$V\times d_{\mathrm{model}}$ 的输入嵌入,以及 $d_{\mathrm{model}}\times V$ 的 LM head(若不绑权重).Llama 3 70B 的 $d_{\mathrm{model}}=8192$(Grattafiori et al., 2024, Table 1).按词表 128,256 计,单侧约 $128256\times 8192\approx 1.05\times 10^9$ 个参数;bf16 下约 2.1 GB,untied 再翻倍.这是显存账,不是「词表越大越聪明」.

另一头:切得越碎,$L$ 越长,注意力越贵,窗口里装下的自然语言越少.所以训练 tokenizer 是在 **$V$,压缩率,尾部 token 是否训到** 之间取点.

## 2. 训练循环:语料 → 计数 → 合并 → 词表

![](./images/fig-tokenizer-train-pipeline.png)

> 图 1:BPE / BBPE 训练是「数相邻对 → 合并最高频 → 改写序列」直到 $|V|$ 达标.示意图,不是 HuggingFace 界面.

**图 1 解析**

- 框 1:语料要能代表下游分布.代码,CJK,数学 LaTeX 若几乎不出现,merge 就不会为它们造整词.
- 框 2–4:每步 $O(\text{语料长度})$ 扫一遍的朴素实现太慢;工业实现用堆 + 链表把单次合并摊到对数时间(HuggingFace tokenizers 一类).
- 回边:停在预设 $|V|$,不是停在「语言学词根已经完整」.
- 框 5:词表 = 原子符号 ∪ 合并产生的子词 ∪ 特殊 token.Llama 3 名义 128K,实现里常见 128,256(含 special).

算法(字符或字节原子):

1. 初始化原子集合.
2. 统计所有相邻对 $(t_a,t_b)$ 的出现次数.
3. 合并计数最大的对,写入 merge 表第 $k$ 行.
4. 在流上替换,重复 2–4.

推理:按 merge 表从前往后(或等价的优先级)应用,得到确定性切分.

## 3. BBPE:原子改成 256 字节

字符 BPE 仍可能在生僻 Unicode 上 OOV.Byte-level BPE 把文本先编成 UTF-8 字节,原子永远是 $0x00$–$0xFF$.任意字符串可切,乱码也可以.代价:一个汉字常占 3 个字节,**在 merge 还没把常用字拼回来之前**序列会变长.GPT-2 起这条路成为 GPT 系默认.

Llama 2 用 SentencePiece BPE,词表 32K.Llama 3 **改成 tiktoken 风格的字节 BPE**:词表「128K tokens」,由 tiktoken 的约 100K 加上 **28K** 非英语 token 组成;英文样本压缩率从 Llama 2 的 **3.17 字符/token 提到 3.94**(Grattafiori et al., §2).这是一手数字.不要写成「Llama 3 仍用 SentencePiece」.

## 4. 正则预切:merge 不许跨缝

算法之前往往有一层 **pre-tokenization**.OpenAI `cl100k_base` 用正则把字母块,数字块,空白,标点切开,BPE **不能跨这些缝合并**.数字常被切成最多 3 位一块(`\p{N}{1,3}`),避免「一个 12 位发票号占一个几乎从未更新的 embedding 行」.

SentencePiece 不依赖空格预分词:空格变成 `▁`,整句是一条 Unicode 流,解码可逆.T5,Llama 1/2 走这条.和 tiktoken 的差别是工程包装,不是「另一种注意力」.

## 5. Unigram:减法 + EM

Unigram 假设切分 $s=(t_1,\ldots,t_m)$ 的概率 $\prod_i P(t_i)$.目标是词表与 $P(t)$ 使语料边际似然最大:

$$
\mathcal{L}=\sum_{x\in D}\log\sum_{s\in S(x)}\prod_{t\in s}P(t) \tag{1}
$$

从很大的种子词表出发:E 步用当前 $P$ 算期望切分(Viterbi 或 forward),M 步更新 $P$,再剪掉对似然贡献最小的一批子词.推理取最大概率切分.训练期可按 $P$ 采样非最优切分(subword regularization),等于在 token 粒度做数据增强.

## 6. 评估:压缩率,parity,不要用 PPL 比不同词表

| 量 | 含义 | 注意 |
|----|------|------|
| 字符/token 或 byte/token | 压缩率 | Llama 3 英文 3.94 vs Llama 2 的 3.17,来自官方报告 |
| Fertility | 每词多少 token | 跨语言比较时先定义「词」 |
| BPC / bits-per-byte | 跨 tokenizer 的语言建模 | Token 级 PPL 随 $V$ 变,不可比,见 [3.4.1](../../3.4-预训练评估/3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md) |

尾部 token 若在预训练里几乎不出现,embedding 接近随机,遇到冷门字就胡言.Upsampling 罕见语种或罕见字符是数据侧补丁,不是再跑一遍 BPE 能单独修好的.

**不是**:把 Magma / 像素 tokenizer 写进本篇当「已替代 BPE」.离散子词仍是 2026-08 稠密 LLM 的默认;连续或字节潜变量是另一条线.

失效模式:OOV(没做字节回退),数字幻觉(没预切长数字),代码缩进爆炸(空格组合未进词表),换 tokenizer 却继续用旧 checkpoint.
