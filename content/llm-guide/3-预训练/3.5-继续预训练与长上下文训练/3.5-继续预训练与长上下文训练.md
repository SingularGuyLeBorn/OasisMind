# 3.5 继续预训练与长上下文训练

前面四节讲的是从随机初始化开始的一次预训练. 这一节的起点不同: 手里已经有一个训好的模型, 学习率已经衰减到峰值的 1/10 或更小 (Llama 3 405B 是 1%), 现在要让它学会新东西. 需求有两类. 一类是领域适应, 把通用模型变成代码或数学模型, Code Llama 从 Llama 2 出发训练 500B token, Llemma 再从 Code Llama 出发, 这是 [3.5.1 继续预训练](./3.5.1-继续预训练/3.5.1-继续预训练.md) 的主题. 另一类是把 4K 或 8K 的窗口扩到 128K 以上, 这是 [3.5.2 长上下文训练与数据](./3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md) 的主题.

继续预训练与 SFT 的区别在数据和 loss: 它用无标注文本, 对全部 token 算 loss, 数据量在几十 B token 以上, 改变的是模型的知识分布; SFT 用指令和回答对, 只对回答部分算 loss, 见 [4.2](../../4-后训练/4.2-SFT/4.2-SFT.md). 位置编码层面不训练或少训练的外推方法 (PI, NTK, YaRN 等) 在 [2.7](../../2-核心原理与架构/2.7-长上下文与外推技术/2.7-长上下文与外推技术.md), 3.5.2 讲的是外推之后仍然需要的那一步训练.

## 1. 从训好的模型出发

### 1.1 两个目标和一条基线

设原预训练数据为 $\mathcal D_0$, 新数据为 $\mathcal D_1$. 继续预训练要同时做到两件事: 在 $\mathcal D_1$ 上的 loss 降下来 (适应), 在 $\mathcal D_0$ 上的 loss 不明显上升 (不遗忘). 最强的基线是在 $\mathcal D_0\cup\mathcal D_1$ 上从头训练, 两个目标都能满足, 但要重新花一次预训练的算力. 继续预训练的问题因此可以写成: 只花 $\mathcal D_1$ 那部分算力, 离这条基线能有多近.

Ibrahim 等人在 405M 模型上给出了答案的量级. Pile 上训练 300B token 之后, 在 SlimPajama 上继续训练 300B token 并混入 5% 到 10% 的旧数据, 两份验证 loss 的平均值是 2.36 到 2.37, 在 600B 并集上从头训练是 2.35; 换成分布差得更远的德语 Common Crawl, 25% 回放的平均 loss 与从头训练持平. 额外算力只有从头训练的一半或 40%. 长上下文训练的基线也一样: 从头用长序列预训练能做到最好, 但注意力的计算随长度平方增长, LongLoRA 举的例子是 8192 长度的自注意力计算量是 2048 的 16 倍.

### 1.2 放在流水线的哪一段

长上下文训练有两种放法. Llama 3 和 Qwen3 把它放进预训练的末段, 仍算预训练日程的一部分: Llama 3 405B 先用 8K 上下文完成 15.6T token 的标准预训练, 再分 6 个阶段扩到 128K, 共约 800B token, 学习率沿用主体训练的日程. Code Llama 则在领域训练之后单独设一个长上下文微调阶段, 序列从 4096 加到 16,384, 学习率 $2\times10^{-5}$, 比代码阶段的峰值小一个数量级以上, 7B 和 13B 只训约 20B token.

两种放法对应两种起点. 预训练内的长上下文阶段有完整的优化器状态和数据管线, 可以和退火合在一起做, Llama 3 最终 40M token 就在 128K 长度上把学习率降到 0. 开源基座之上的继续训练通常拿不到优化器状态, 也拿不到原预训练数据, Ibrahim 等人的实验因此每次都重置优化器状态, Llemma 只能用公开的 Pile 和 RedPajama 代替真实的 $\mathcal D_0$. 后一种情况下, 3.5.1 第 3.2 节回放表里的数字不能直接套用.

## 2. 学习率, 回放与起点

### 2.1 学习率要不要重新升温

预训练结束时学习率是 $\eta_{\min}$, 直接用它在新数据上训练, 参数更新太小, 模型学不动新分布. Gupta 等人用 Pythia 410M 做了对照: 把学习率重新升到峰值, 上游 (Pile) 和下游 (SlimPajama) 的 loss 都先上升, 训练足够长后下游效果超过从头训练; 峰值越高, 适应越好, 遗忘越多. 不换数据只重新升温, Pile 的 loss 同样先上升, 说明这段上升来自学习率本身. 3.5.1 第 2.1 节把它和 MiniCPM 的观察对照: 衰减阶段损失函数的曲率增大一个数量级, 参数停在一个窄区域里, 学习率重新升高就把参数推了出去.

工业配方的取值跟数据量走. Code Llama 训练 500B token, 相当于 Llama 2 预训练的 25%, 沿用基座的原学习率 ($3\times10^{-4}$ 和 $1.5\times10^{-4}$) 效果最好, 更接近第二次预训练. Llemma 7B 训练约 200B token, 峰值 $10^{-4}$, 是 Code Llama 对应尺寸的 1/3 左右. 长上下文阶段要改的只是位置编码的用法, 学习率更小: Code Llama 长上下文微调用 $2\times10^{-5}$, ProLong 用 $10^{-5}$, DeepSeek-V3 沿用末段的 $7.3\times10^{-6}$.

### 2.2 回放旧数据与混入短数据

只降学习率挡不住遗忘. 回放是在新数据里混入一部分旧数据, Ibrahim 等人按算力等价比较, 回放的 token 从新数据的预算里扣. 规律是少量回放收益最大: 弱偏移时 0.5% 回放就把 Pile loss 从 2.44 降到 2.27, 强偏移时 1% 回放从 3.56 降到 2.83; 新数据上的代价很小, 回放从 0 到 10%, SlimPajama loss 只从 2.50 变到 2.51. 工业配方的比例从几个百分点到六成都有: Code Llama 初始阶段混入 7% 一般自然语言和 8% 与代码相关的自然语言, DeepSeek 继续训练 DeepSeek-V2 时回放 30% 预训练数据.

长上下文训练里, 和回放起同样作用的是短数据. ProLong 在 Llama-3-8B 上消融发现, 长数据比例越高, 短任务越差, SFT 之后长数据过多连长任务也变差, 综合最优在 60% 长数据; 剩下 40% 的短数据用什么也有显著影响, 自配的 ShortMix 好于单用 SlimPajama, FineWeb-Edu 或 DCLM-Baseline. 只改 RoPE 底数, 或照搬 Fu 等人的 SlimPajama 长数据配方, Llama-3-8B 的 MMLU 从 66.5 降到 64.7 和 63.1, GSM8K 从 44.7 降到约 40.

### 2.3 从哪个 checkpoint 出发

重新升温的代价可以在预训练时就避开. Ibrahim 等人提出无限学习率日程: warmup 和一次冷却之后进入恒定段, 新数据到来时从恒定段的 checkpoint 接着训, 需要部署时再从恒定段分叉一段退火, 退火后的 checkpoint 不用作下一次继续训练的起点. 这和 [3.4.2](../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 2 节的 WSD 结构相同. MiniCPM 指出衰减之前的 checkpoint 可以继续训练, DeepSeek 继续训练 DeepSeek-V2 时也选了未衰减的 checkpoint.

基座只发布了余弦衰减到底的权重时, 就只能重新升温. Gupta 等人还比较了从预训练中途更早的 checkpoint 出发, 结果并不更好, 用最新的 checkpoint 最好, 他们据此认为预训练没有让模型失去可塑性. warmup 的长度影响很小: Gupta 等人比较 0% 到 2%, Ibrahim 等人比较 0.5% 到 2%, 都没有明显区别.

## 3. 领域训练与长上下文训练的对照

### 3.1 几份公开配方

下表并列 3.5.1 和 3.5.2 引用的主要配方:

| 配方 | 起点 | 目标 | 数据量 | 学习率 | 结果 |
|---|---|---|---|---|---|
| Code Llama | Llama 2 | 代码 | 500B token (70B 为 1T), 代码 85% | 沿用基座峰值 | 7B HumanEval 12.2% 到 33.5% |
| Llemma | Code Llama | 数学 | 7B 约 200B, 34B 约 50B | 7B 峰值 $10^{-4}$ | 7B MATH 4.5% 到 18.0% |
| Code Llama 长上下文微调 | Code Llama (4K) | 16K | 约 20B token | $2\times10^{-5}$ | HumanEval 降 0.52, MBPP 降 1.9 个百分点 |
| Llama 2 Long | Llama 2 | 32K | 400B token | $2\times10^{-5}$ 或 $10^{-5}$ | 70B 对话模型 10 个长文本任务中 7 个超过 gpt-3.5-turbo-16k |
| Fu 等人 | LLaMA-2 7B / 13B | 80K / 64K | 5B token 饱和 | 恒定 $2\times10^{-5}$ | 7B NIAH 88.0 |
| ProLong | Llama-3-8B-Instruct | 512K | 两阶段各 20B token | $10^{-5}$ | 长上下文数据为 Llama 3.1 的 5% |

领域训练和长上下文训练的数据量差了一个量级以上. 领域训练要改写知识分布, Code Llama 的 500B token 相当于基座预训练的 25%; 长上下文训练按 Fu 等人的假设, 在任意位置取用信息的能力在 4K 的预训练里基本已经学到, 继续训练只是把它延伸到更长的长度, 500M token 就能解锁大部分检索准确率, 5B token 饱和.

两类训练都在 Muennighoff 等人给出的 4 个 epoch 以内重复数据: Code Llama 的代码训练 2.03 个 epoch, Python 专项阶段 3.69 个 epoch. 长上下文训练的数据来源更窄, 长文档集中在书和代码仓库, 所以 3.5.2 第 3.1 节说「上采样长文档」和「改变领域配比」是同一个操作的两面: 上采样书, 书的 loss 降 0.175, 代码的 loss 升 0.029. Fu 等人推荐按来源上采样, 在每个领域内部上采样长文档, 保持领域比例不变.

### 3.2 几处尚未统一的结论

第一处是长上下文训练要多少 token. Fu 等人以 128K 的 NIAH 为目标, 5B token 就够; Llama 2 Long 和 Llama 3 还要求真实长文本任务提升, 短任务不退化, 分别训了 400B 和 800B. ProLong 的 40B token 落在中间, 作者报告它在大多数长上下文任务上超过 Llama-3.1-8B-Instruct. 分歧的来源是评测目标: NIAH 衡量的是检索, 长文档问答和摘要还要求理解.

第二处是质量和长度谁更重要. Llama 2 Long 的消融显示, 调整长度分布带来的收益不大, 新配比的提升主要来自数据质量; Fu 等人则认为必须上采样长文档. 3.5.2 第 3.4 节给出的解释是训练量不同: 400B token 里天然长文档的总量已经足够, 5B token 不上采样就见不到足够的长依赖. 第三处是 SFT 要不要长指令: Llama 3 混入 0.1% 的合成长数据综合最好, ProLong 混 0% 最好, 加到 10% 和 50% 平均分从 55.7 降到 53.9 和 43.3. ProLong 作者的假设是 Llama 3.1 的私有指令数据量大得多, 大量短指令 SFT 时需要合成长数据防止长上下文能力退化.

## 4. 共用的旋钮与读法

### 4.1 RoPE 底数

两类训练都会改 RoPE 底数 $\theta$. Llama 2 Long 发现不改位置编码, 7B 模型即使充分继续训练也看不到 4000 到 6000 token 之外, 于是把底数从 10,000 调到 500,000 (ABF), 让远处 token 的注意力衰减变慢; 32K 上的困惑度几种方法差别很小, 只有 RoPE ABF 能在完整的 32768 窗口上完成「复述第一句」任务. Llama 3 预训练时就用 500,000, Code Llama 长上下文微调从 $10^4$ 提到 $10^6$, Qwen3 在长上下文阶段从 $10^4$ 提到 $10^6$.

更长的窗口要更大的底数. Men 等人给出底数随目标长度的下界, 64K 约 $2.1\times10^6$, 512K 约 $6.4\times10^7$; ProLong 在 64K 阶段用 $8\times10^6$, 512K 阶段用 $1.28\times10^8$, 都在下界之上. 底数也可以往回改: Llemma 7B 训练前把 Code Llama 的 $10^6$ 收回 $10^4$, 为的是以后能在 Llemma 上重复一次长上下文微调, 34B 受算力限制没有验证, 保留了 $10^6$. 下界的推导在 [2.7.1 长度外推](../../2-核心原理与架构/2.7-长上下文与外推技术/2.7.1-长度外推/2.7.1-长度外推.md).

### 4.2 评估同时看两侧

继续训练的评估需要两组指标. 目标侧是 Code Llama 的 HumanEval, MBPP, Llemma 的 MATH, GSM8k, 长上下文训练的检索和长文档任务; 原有能力侧是旧数据上的验证 loss 和通用基准. 只看目标领域会把遗忘当成免费的, Code Llama 7B 在 MMLU-STEM 和 SAT 上低于随机猜测 (25%) 这类问题就会漏掉; 只看验证 loss 也不够, Fu 等人的「128K 截断」配方验证 loss 与上采样版本相近, 检索能力却明显更差.

长上下文训练的放行条件因此是双向的. Llama 3 每扩一个阶段, 都要求短上下文评测完全恢复, 大海捞针在当前长度上全部正确; ProLong 不用困惑度和 NIAH, 用 HELMET 的一组下游任务 (键值检索, RAG, 重排序, 多样本上下文学习, 长文档问答和摘要), 并且每个消融都先做 SFT 再评测, 因为有些差别只在 SFT 之后才显现. 长上下文评估的协议和 NIAH 的局限在 [3.6.3](../3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md).

### 4.3 读法

做领域模型的读者读 [3.5.1](./3.5.1-继续预训练/3.5.1-继续预训练.md) 第 2, 3 节的学习率和回放实验, 再看第 4 节 Code Llama 与 Llemma 的配比和 epoch, 第 4.3 节用 $C\approx6ND$ 估了几份配方的算力并从 GPU 时数反推硬件利用率. 第 6.4 节的表把继续预训练, 退火, 长上下文微调, SFT, 持续学习, 回放几个名字相近的做法放在一起区分, 持续学习的一般问题在 [4.10](../../4-后训练/4.10-持续学习/4.10-持续学习.md).

要把窗口扩到 128K 以上的读者读 [3.5.2](./3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md): 第 2 节是先短后长的 FLOPs 和两派数据量, 第 3 节是长短数据的配比, 训练长度要不要超过评测长度, 以及打包时的文档掩码, 第 5.4 节的表按训练流程列出常见失效现象和检查方法. 显存不够时, 第 5 节的 LongLoRA 用移位稀疏注意力加放开 embedding 和 norm, 能在单台 8 卡 A100 上把 Llama2 7B 训到 100K, 代价是 MMLU 和 NIAH 都低于全注意力继续训练.
