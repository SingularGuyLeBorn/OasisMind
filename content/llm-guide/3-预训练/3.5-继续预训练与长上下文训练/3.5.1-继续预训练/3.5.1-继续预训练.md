# 3.5.1 继续预训练

> 相关阅读: [3.4 预训练全流程](../../3.4-训练过程/3.4-训练过程.md) · [3.4.2 预训练策略](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) · [3.3.2 Scaling Laws](../../3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md) · [4.2 SFT](../../../4-后训练/4.2-SFT/4.2-SFT.md) · [4.10 持续学习](../../../4-后训练/4.10-持续学习/4.10-持续学习.md) · [3.6.3 大海捞针测试](../../3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md)

## 1. 问题

### 1.1 什么时候需要继续预训练

预训练结束时学习率已衰减到很小 (余弦衰减到峰值的 1/10 或更小, 见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 1.2 节). 之后有三类需求要在同一个模型上继续训练:

- **领域适应**: 把通用模型变成代码或数学模型. Code Llama 从 Llama 2 出发, Llemma 从 Code Llama 出发.
- **新数据**: 预训练后又收集到新数据, 不想从头训练.
- **长上下文**: 预训练用短序列, 末段扩展到长序列. Llama 3 和 Qwen3 都把这一步放在预训练的最后阶段 (见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4.3 节).

与 SFT 的区别: SFT 用指令-回答对, 数据量通常是百万条以内, 只对回答部分算 loss (见 [4.2](../../../4-后训练/4.2-SFT/4.2-SFT.md)); 继续预训练用无标注文本, 对全部 token 算 loss, 数据量在几十 B token 以上, 改变的是模型的知识分布.

### 1.2 两个矛盾的目标

继续预训练要同时满足:

1. **适应**: 在新数据 $\mathcal D_1$ 上的 loss 降下来.
2. **不遗忘**: 在旧数据 $\mathcal D_0$ 上的 loss 不明显上升.

最强的基线是在 $\mathcal D_0\cup\mathcal D_1$ 上从头训练. 它同时满足两个目标, 但要重新花一次预训练的算力. 继续预训练的问题可以表述为: 只花 $\mathcal D_1$ 那部分的算力, 能离这个基线多近.

## 2. 学习率

### 2.1 为什么要重新升温: Gupta 等人的实验

预训练结束时学习率是 $\eta_{\min}$. 如果直接用 $\eta_{\min}$ 在新数据上训练, 参数更新很小, 模型学不动新分布. 如果把学习率重新拉高 (re-warming), 模型能适应新数据, 但大步更新会破坏已有的知识. 学习率是适应和遗忘之间最直接的旋钮.

Gupta 等人 (2023) 用 Pythia 410M: 先在 Pile 上训练 300B token, 再在 SlimPajama 上继续训练 297B token. 学习率先线性 warmup, 再余弦衰减, 峰值取 $1.5\times10^{-4}$, $3\times10^{-4}$, $6\times10^{-4}$ 三档, 在 240B token 处衰减到峰值的 0.1. 主要发现:

- **重新升温的短期代价**: 升温期间, 上游 (Pile) 和下游 (SlimPajama) 的 loss 都先上升.
- **长期收益**: 训练足够长后, 下游效果超过在 SlimPajama 上从头训练的模型, 即使下游数据集本身很大.
- **与恒定小学习率的对比**: 一直用恒定学习率继续训练的基线在前 100B token 内表现最好, 因为它没有升温造成的 loss 上升; 训练到收敛时, 重新升温的模型超过了从头训练和恒定学习率两个基线.
- **峰值**: 峰值越高, 在下游数据上适应得越好, 在上游数据上遗忘得越多.
- **warmup 长度与起点**: 对 297B token 的日程比较 0%, 0.5%, 1%, 2% 四种 warmup, 在前 50B token 后测量, 对结果影响很小. 从预训练中途更早的 checkpoint 出发并不更好, 用最新的 checkpoint 最好. 作者据此认为预训练没有让模型失去可塑性.

升温为什么先让 loss 上升, 可以和 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 2 节 MiniCPM 的观察对照: 学习率衰减阶段, 损失函数的曲率增大一个数量级, 参数进入一个局部最优附近的窄区域. 小学习率能停在这个区域里; 学习率重新升高后, 每步更新的幅度超出这个区域的尺度, 参数被推出去, 上游和下游的 loss 同时上升. 之后新数据的梯度主导更新, 模型在新分布上找到另一个低点. 2.5 节的无限学习率日程从衰减前的 checkpoint 出发, 参数还没有进入窄区域, 就不需要经历这一段上升.

Gupta 等人还做了一个对照: 不换数据, 在 Pile 上接着训练, 只把学习率重新升温. Pile 验证 loss 同样先上升 (论文 §4.4, Figure 5). 数据分布没变, 所以这段上升来自学习率的变化本身, 与分布偏移无关. 而且在同一份数据上, 模型在升温再衰减之后也没有把这段损失补回来: 没有新分布可学时, 重新升温只有代价.

这一解释也给出了「峰值越高, 遗忘越多」的直观理由: 升温幅度决定了参数被推离原位置的距离. Gupta 等人在 Pile 上的 loss 曲线显示, 提高峰值学习率会一致地抬高上游数据的最终 loss.

### 2.2 Ibrahim 等人的升温与再衰减

Ibrahim 等人 (2024) 用 405M 和 10B 两个尺寸, 先在 Pile 上训练 300B token, 再分别在 SlimPajama (300B token, 弱偏移) 和德语 Common Crawl (200B token, 强偏移) 上继续训练. 每次继续训练都重置优化器状态, 因为开源模型通常不附带优化器状态. 学习率有三种升温目标: 预训练峰值 $3\times10^{-4}$ 的一半, 相同, 两倍; 升温后余弦衰减到 $\eta_{\min}=0.1\cdot\eta_{\max}$.

他们的经验规则:

- 预训练时从 $\eta_{\max}$ 余弦衰减到 $\eta_{\min}$ 的模型, 继续训练时把学习率重新升到 $\mathcal O(\eta_{\max})$, 再衰减到 $\mathcal O(\eta_{\min})$, 适应效果优于一直用小学习率.
- 降低峰值能减少遗忘, 提高峰值能增强适应.
- warmup 取 $\mathcal D_1$ 总步数的 0.5%, 1%, 2%, 结果没有区别.

### 2.3 Code Llama: 沿用原学习率

Code Llama 从 Llama 2 出发继续训练. 优化器 AdamW ($\beta_1=0.9$, $\beta_2=0.95$), 余弦日程, 1000 步 warmup, 最终学习率为峰值的 1/30, batch 4M token, 序列 4096. 报告说明, 尽管微调阶段的惯例是用比预训练更低的学习率, 他们沿用 Llama 2 基座的原学习率时效果最好: 7B 和 13B 为 $3\times10^{-4}$, 34B 和 70B 为 $1.5\times10^{-4}$. Python 专项阶段的初始学习率为 $10^{-4}$.

Code Llama 的初始阶段训练 500B token (70B 为 1T), 相对 Llama 2 的 2T 预训练是 25% 到 50% 的量级. 这一数据量下, 继续训练更接近第二次预训练, 而不是微调, 所以沿用预训练学习率合理.

### 2.4 Llemma: 较小的峰值

Llemma 从 Code Llama 出发, 用 256 张 A100 40GB 训练:

| 模型 | 步数 | batch | 峰值学习率 | warmup | 衰减终点 | 算力 |
|------|------|------|------|------|------|------|
| 7B | 42,000 | 4M token | $10^{-4}$ | 500 步 | 峰值的 1/30 | 约 23,000 A100 时 |
| 34B | 12,000 | 4M token | $5\times10^{-5}$ | 500 步 | 峰值的 1/30 | 约 47,000 A100 时 |

7B 训练约 200B token, 34B 约 50B token. 峰值是 Code Llama 对应尺寸的 1/3 左右, 数据量也小一个量级. 7B 原计划训练 48,000 步, 第 42,000 步之后出现 NaN loss, 最终停在 42,000 步, 余弦日程仍按 48,000 步设定 (见 [3.4.3](../../3.4-训练过程/3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md) 第 4 节).

### 2.5 避免重新升温: 无限学习率日程

重新升温的代价是 loss 先上升. 如果预计模型还要继续训练, 可以在预训练时就不把学习率衰减到底. Ibrahim 等人提出无限学习率日程, 分四段:

$$
\eta_t=\begin{cases}
\eta_{\max}\cdot t/T_{\mathrm{warmup}}, & t\in[0,t_{\mathrm{cd}}] & \text{(warmup)}\\
f_{\mathrm{cd}}(t), & t\in(t_{\mathrm{cd}},t_{\mathrm{const}}] & \text{(冷却到恒定值)}\\
\eta_{\mathrm{const}}, & t\in(t_{\mathrm{const}},t_{\mathrm{ann}}] & \text{(恒定)}\\
\eta_{\mathrm{const}}\cdot(\eta_{\min}/\eta_{\mathrm{const}})^{\frac{t-t_{\mathrm{ann}}}{t_{\mathrm{end}}-t_{\mathrm{ann}}}}, & t\in(t_{\mathrm{ann}},t_{\mathrm{end}}] & \text{(退火)}
\end{cases} \tag{1}
$$

- **warmup 和冷却只在第一个数据集上做一次**. 冷却把学习率从 $\eta_{\max}$ 降到恒定值 $\eta_{\mathrm{const}}$, 之后所有数据集都不再重新升温.
- **恒定段末尾的 checkpoint 是继续训练的起点**. 新数据到来时, 从这里接着用 $\eta_{\mathrm{const}}$ 训练.
- **退火段只为部署**: 需要一个收敛的模型时, 从恒定段的任意位置分叉, 按指数衰减到 $\eta_{\min}$. 退火后的 checkpoint 不用作下一次继续训练的起点.

冷却函数 $f_{\mathrm{cd}}$ 有两种: 余弦, 以及逆平方根

$$
f_{\mathrm{cd}}(t)=\eta_{\max}+\frac{\eta_{\mathrm{const}}-\eta_{\max}}{h(1)}\cdot h\left(\frac{t-t_{\mathrm{cd}}}{t_{\mathrm{const}}-t_{\mathrm{cd}}}\right),\quad h(x)=\frac{1}{\sqrt{1+\alpha x}}-1 \tag{2}
$$

$\alpha$ 控制下降的陡峭程度; $h(0)=0$, 所以起点是 $\eta_{\max}$, 终点 $x=1$ 时是 $\eta_{\mathrm{const}}$. 这一形式与 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 2 节的 WSD 结构相同, 区别在于把「恒定段」放在一次冷却之后, 而且明确规定从哪个 checkpoint 继续.

他们在 SlimPajama 的 3 个 100B token 同分布子集上依次训练 405M 模型 (模拟同一来源的新数据随时间到来, 例如最新抓取的网页), 跨子集时不保留优化器状态. 每个子集上各保留两个 checkpoint: 一直停在恒定段的, 和做过冷却的; 切换到下一个子集时选前者. 结果是各种日程的表现相近, 但无限日程可以在恒定段的任意时刻开始冷却, 反复余弦则必须事先知道 token 数. 跨子集时 loss 因为重置优化器状态先急剧上升, 无限日程的模型随即恢复, 跨数据集边界的遗忘可以忽略.

已有的预训练日程中, MiniCPM 的 WSD 和 DeepSeek LLM 的多阶段日程都有这一性质. MiniCPM 指出衰减之前的 checkpoint 可以继续训练; DeepSeek LLM 的多阶段日程允许复用第一阶段 (见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 2 节). Ibrahim 等人提到 DeepSeek 继续训练 DeepSeek-V2 时也选了未衰减的 checkpoint, 以保证学习率平滑过渡.

## 3. 回放旧数据

### 3.1 算力等价回放

只降学习率不能完全防止遗忘. 回放 (replay) 是在新数据中混入一部分旧数据. Ibrahim 等人用「算力等价回放」做公平比较: 回放的 token 从新数据的预算中扣除, 总 token 数不变.

例子: $\mathcal D_0$ 和 $\mathcal D_1$ 各 100B token. 模型 (a) 依次训练两者, 共 200B 唯一 token. 模型 (b) 用 5% 算力等价回放: 看 $\mathcal D_0$ 的 100B, 再看 $\mathcal D_1$ 的 95B 加从 $\mathcal D_0$ 回放的 5B, 共 200B token. 两者算力相同, 但 (b) 少看了 5B 新数据.

### 3.2 回放比例的效果, 以及放大到 10B

405M 模型, 300B Pile 之后继续训练, 最终验证 loss (论文 Table 2):

**弱偏移: 300B SlimPajama**

| 设置 | Pile loss | SlimPajama loss | 平均 |
|------|------|------|------|
| 无回放 | 2.44 | 2.50 | 2.47 |
| 0.5% 回放 | 2.27 | 2.50 | 2.39 |
| 1% 回放 | 2.26 | 2.50 | 2.38 |
| 5% 回放 | 2.23 | 2.51 | 2.37 |
| 10% 回放 | 2.21 | 2.51 | 2.36 |
| 50% 回放 | 2.16 | 2.54 | 2.35 |
| 并集从头训练 (600B) | 2.17 | 2.53 | 2.35 |

**强偏移: 200B 德语 Common Crawl**

| 设置 | Pile loss | 德语 loss | 平均 |
|------|------|------|------|
| 无回放 | 3.56 | 1.11 | 2.34 |
| 1% 回放 | 2.83 | 1.12 | 1.97 |
| 5% 回放 | 2.57 | 1.12 | 1.85 |
| 10% 回放 | 2.46 | 1.13 | 1.80 |
| 25% 回放 | 2.33 | 1.16 | 1.75 |
| 50% 回放 | 2.24 | 1.22 | 1.73 |
| 并集从头训练 (500B) | 2.26 | 1.25 | 1.75 |

两张表的规律:

- **少量回放收益最大**. 弱偏移时 0.5% 回放就把 Pile loss 从 2.44 降到 2.27 (并集从头训练为 2.17); 强偏移时 1% 回放把 Pile loss 从 3.56 降到 2.83.
- **新数据上的代价很小**. 弱偏移下回放从 0 到 10%, SlimPajama loss 只从 2.50 变到 2.51. 50% 回放时少看了 150B SlimPajama token, loss 也只升到 2.54.
- **强偏移需要更多回放**. 德语的遗忘更严重, 回放到 25% 时平均 loss 与从头训练持平, 50% 时略优.
- **继续训练可以追平从头训练**. 弱偏移 5% 到 10% 回放的平均 loss (2.36 到 2.37) 与并集从头训练 (2.35) 相差 0.01 到 0.02; 强偏移 25% 回放与之持平. 在已有 Pile 模型的基础上, 额外算力只有从头训练的一半 (弱偏移 300B 对 600B) 或 40% (强偏移 200B 对 500B).

论文据此选 5% 回放用于 SlimPajama, 25% 用于德语.

10B 模型 (含 embedding 9.6B 参数) 只做了弱偏移实验. 训练设置: batch 1104 条, 序列长度 2048, 一个 epoch 约 132,366 步; TP 跨一个节点内 6 张 GPU, PP 跨 4 个节点, 每个模型副本占 24 张 GPU, 共 276 个节点, 梯度累积 4 步, 使用 ZeRO-1, 激活重计算和 FP16/FP32 混合精度. 对比两个继续训练的模型 (只升温再衰减, 以及再加 5% 回放) 和三个从头训练的基线 (300B SlimPajama, 300B Pile, 600B 并集). 结论与 405M 一致: 升温, 再衰减加少量回放, 在遗忘和适应之间取得平衡, 达到并集从头训练的水平; 与 0% 回放相比, 5% 回放对下游表现的影响很小. 他们建议在有限的 token 预算上先比较几个回放比例, 因为不同比例的相对差异在训练早期就会显现.

### 3.3 工业实践中的回放

工业模型的回放比例从几个百分点到六成都有, 回放的也不一定是基座的原始数据:

- **Code Llama**: 初始阶段 7% 的数据是一般自然语言, 训练 0.01 个 epoch; 8% 是与代码相关的自然语言. Instruct 阶段混入 6% 代码数据和 2% 自然语言数据作为 rehearsal.
- **Llemma**: 混入 Pile (300B, 权重 0.15) 和 RedPajama 的通用代码 (59B, 权重 0.22).
- **Ibrahim 等人引用的两例**: Glorioso 等人 (2024) 在 50B token 高质量数据的衰减阶段用 60% 回放; DeepSeek 继续训练 DeepSeek-V2 共 6T token, 用 30% 预训练数据回放, 代码生成能力显著提高, 大部分自然语言能力得以保留.

## 4. 数据配比与 epoch

### 4.1 Code Llama

初始阶段的数据组成:

| 数据 | 比例 | epoch |
|------|------|------|
| 代码 | 85% | 2.03 |
| 与代码相关的自然语言 | 8% | 1.39 |
| 一般自然语言 | 7% | 0.01 |

Python 专项阶段再训练 100B token: Python 75%, 其他代码 10%, 与代码相关的自然语言 10%, 一般自然语言 5%; Python 数据训练了 3.69 个 epoch.

7B, 13B 和 70B 在初始阶段还同时学填空 (infilling): 每篇文档按字符切成前缀, 中间, 后缀三段, 以 0.9 的概率把中间段挪到末尾再做自回归预测, 一半按「前缀, 后缀, 中间」排列 (PSM), 一半按「后缀, 前缀, 中间」排列 (SPM); 词表为此加了 4 个标记前缀, 中间, 后缀和填空结尾的特殊 token. 代价是 HumanEval 和 MBPP 的 pass@1, pass@10, pass@100 平均下降 7B 0.6 个百分点, 13B 1.1 个百分点 (报告 Table 5). 34B 没有做这一项.

代码数据重复 2 个 epoch, Python 重复 3.7 个 epoch, 都在 Muennighoff 等人给出的 4 个 epoch 以内 (见 [3.3.2](../../3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md) 第 4.1 节), 重复几乎不损失数据价值.

### 4.2 Llemma 的配比与代理指标

Proof-Pile-2 共 55B token, 由三部分组成: 数学相关代码 AlgebraicStack 11B, 数学网页 OpenWebMath 15B, arXiv 论文 29B. 配比用 MATH 训练集的困惑度选: 比较 arXiv:网页:代码 的不同比例, 2:4:1 的总体困惑度最低 (1.478), 2:4:2 为 1.482, 4:2:1 为 1.487. 最终的混合权重是 AlgebraicStack 1.00, OpenWebMath 4.00, arXiv 2.00, 外加通用代码 0.22, Pile 0.15.

用 MATH 训练集选超参数, 再在 MATH 测试集上评测, 有一定的过拟合风险. 作者在论文中说明了这一点, 并认为效果与用其他高质量相关文本选择类似.

Llemma 没有用 Scaling Laws 去定配比, 用的是小规模代理指标: 目标任务训练集的困惑度. Llama 3 的退火实验 (见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4 节) 是另一种代理: 把 30% 的权重给候选数据, 在 40B token 上把学习率退火到 0, 比较下游评测. 两种方法都用远小于正式训练的成本在少数几个候选中挑选.

### 4.3 算力估算

用 $C\approx6ND$ (见 [3.3.1](../../3.3-模型配置与Scaling-Laws/3.3.1-确定模型结构与参数/3.3.1-确定模型结构与参数.md) 第 1.2 节) 估算继续训练的成本:

| 训练 | $N$ | $D$ | $C$ | 相对基座预训练 |
|------|------|------|------|------|
| Llama 2 7B 预训练 | 7B | 2T | $8.4\times10^{22}$ | 1 |
| Code Llama 7B 初始阶段 | 7B | 500B | $2.1\times10^{22}$ | 25% |
| Llemma 7B | 7B | 200B | $8.4\times10^{21}$ | 10% |
| Llemma 34B | 34B | 50B | $1.0\times10^{22}$ | - |

Llemma 报告了 GPU 时数, 可以反推硬件利用率. 7B 用约 23,000 A100 时, $8.4\times10^{21}/(23000\times3600)\approx1.0\times10^{14}$ FLOPs/s, 是 A100 BF16 峰值 312 TFLOPS 的约 32%; 34B 用约 47,000 A100 时, 约 60 TFLOPS, 约 19%. 34B 用 TP=8, 7B 用 TP=2, 张量并行的通信更多 (见 [3.4.1](../../3.4-训练过程/3.4.1-训练框架选择/3.4.1-训练框架选择.md) 第 3 节), 这与 34B 利用率更低一致.

7B 的 token 数有一处出入: 论文写训练 200B token, 但 42,000 步乘 4M token 的 batch 约为 168B 到 176B (取决于 4M 是 $4\times10^6$ 还是 $2^{22}$); 200B 更接近原计划的 48,000 步. 34B 的 12,000 步乘 4M 约 50B, 与论文一致. 作为对照, Llemma 论文列出 Minerva 8B 和 62B 的领域适应数据分别是 164B 和 109B token.

## 5. 长上下文继续训练

### 5.1 Code Llama 的长上下文微调

Code Llama 单独设一个长上下文微调 (LCFT) 阶段, 序列长度从 4096 提高到 16,384:

- **RoPE 底数**: $\theta$ 从 $10^4$ 提高到 $10^6$. 底数变大后, 注意力得分随距离衰减变慢, 远处的 token 对当前预测的贡献更大. 报告说明这一修改可以直接用在预训练好的模型上, 以较低学习率训练时 loss 曲线在几步内就稳定.
- **超参数**: 学习率 $2\times10^{-5}$, batch 2M token (7B, 13B) 或 1M token (34B), 训练 10,000 步; 34B 为 11,000 步, Code Llama - Python 7B 为 3,000 步.
- **成本**: 只在微调阶段处理长序列, 不显著增加总训练成本.
- **外推**: 训练长度是 16,384. 在不小于 50kB 的大源文件上, 各尺寸的困惑度越过 16,384 后仍稳定下降, 到 100K token 之后才略有上升.
- **代价**: 在短上下文任务上, LCFT 使 HumanEval pass@1 平均下降 0.52 个百分点, MBPP 下降 1.9 个百分点.

学习率 $2\times10^{-5}$ 比代码阶段的峰值小一个数量级以上. 与 2.3 节的领域继续训练不同, 长上下文阶段要改变的只是位置编码的使用方式, 不需要大幅改写知识.

### 5.2 RoPE 底数的反向修改

Llemma 7B 训练前把 Code Llama 7B 的 RoPE 底数从 $10^6$ 收缩回 $10^4$, 目的是以后可以在训练好的 Llemma 7B 上重复 Code Llama 那样的长上下文微调. 受算力限制, 他们无法验证收缩底数对 34B 没有性能损失, 所以 34B 保留了 $10^6$.

这个例子说明 RoPE 底数是继续训练时可以改的超参数, 改动后模型需要一段训练来适应. 长上下文的位置编码设计见 [3.5.2](../3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md).

### 5.3 与预训练内长上下文阶段的比较

| 做法 | 起点 | 长度 | 数据量 / 步数 | 学习率 |
|------|------|------|------|------|
| Code Llama LCFT | Code Llama (4K) | 16K | 10,000 步, 每步 2M token, 约 20B token (7B/13B) | $2\times10^{-5}$ |
| Llama 3 405B | 8K 预训练 | 128K, 6 个阶段 | 约 800B token | 预训练日程的一部分 |
| DeepSeek-V3 | 4K 预训练 | 32K, 128K | 两个阶段各 1000 步 | $7.3\times10^{-6}$ |

Code Llama 的 7B/13B 长上下文微调约 20B token ($10^4\times2\mathrm{M}$), 是 Llama 3 长上下文阶段的 1/40, 目标长度也短得多. 数据量的差别对应目标的差别: Code Llama 只要求 16K 内可用并能一定程度外推, Llama 3 要求 128K 内稳定. 这些设置的细节和来源见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4.3 节.

Llama 3 报告说明, 在一条序列内用注意力掩码阻止不同文档之间的注意力, 在标准预训练中影响有限, 但在很长序列上的继续预训练中很重要. 掩码让每个 token 只关注同一文档内的前文. Llama 3 405B 先用 8K 上下文完成 15.6T token 的标准预训练, 再用继续预训练把上下文扩展到 128K.

## 6. 结果与边界

### 6.1 Code Llama 的结果

HumanEval pass@1:

| 尺寸 | Llama 2 | Code Llama | Code Llama - Python |
|------|------|------|------|
| 7B | 12.2% | 33.5% | 38.4% |
| 13B | 20.1% | 36.0% | 43.3% |
| 34B | 22.6% | 48.8% | 53.7% |
| 70B | 30.5% | 53.0% | 57.3% |

- 500B token 的继续训练让 7B 的 HumanEval 从 12.2% 提高到 33.5%, 超过 Llama 2 70B 的 30.5%.
- Python 专项的 100B token 再提高 4.3 到 8.3 个百分点 (HumanEval), MBPP 提高 1.2 到 6.4 个百分点.
- 在 HumanEval 上, 7B 的领域继续训练比把通用模型放大到 70B 收益更大.

### 6.2 Llemma 的结果

贪心解码的准确率 (MATH 用 4 个示例, GSM8k 用 8 个示例):

| 模型 | MATH | GSM8k |
|------|------|------|
| Llama 2 7B | 3.2% | 11.8% |
| Code Llama 7B | 4.5% | 10.5% |
| Minerva 8B | 14.1% | 16.2% |
| Llemma 7B | 18.0% | 36.4% |
| Code Llama 34B | 12.2% | 29.6% |
| Llemma 34B | 25.0% | 51.5% |
| Minerva 62B | 27.6% | 52.4% |

Llemma 7B 在 200B token 的继续训练后, MATH 从起点的 4.5% 提高到 18.0%, 超过 Minerva 8B. Llemma 34B 在 50B token 后达到 25.0%, 与参数近两倍的 Minerva 62B (27.6%) 接近. 多数投票下 Llemma 34B 的 MATH 为 43.1%, Minerva 62B 为 43.4%.

Proof-Pile-2 里有约 1.5B token 的形式化数学 (Lean 和 Isabelle 的证明状态), 继续训练的收益也落在这里. 不做微调, few-shot 在 Lean 里逐步生成证明 (每步 32 个候选, best-first 搜索, 10 分钟超时), miniF2F-test 上 Llemma 7B 证出 26.23%, 起点 Code Llama 7B 是 20.49%.

数学网页里本来就有大量竞赛题, 所以论文检查了 MATH 测试集与训练数据的 30-gram 重叠: 约 7% 的题面和 0.6% 的标准解在 Proof-Pile-2 里有命中. Llemma 34B 在有命中和无命中的题上准确率没有明显差别, 例如 5 级难题上分别是 6.08% 和 6.39%.

### 6.3 评估要同时看两侧

继续训练的评估需要两组指标:

- **目标领域**: Code Llama 的 HumanEval, MBPP; Llemma 的 MATH, GSM8k. 长上下文继续训练还要看长距离检索 (见 [3.6.3](../../3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md)).
- **原有能力**: 旧数据上的验证 loss (Ibrahim 等人用 Pile loss), 通用基准. Code Llama 的长上下文微调在短上下文上的回退 (HumanEval 0.52, MBPP 1.9 个百分点) 就是这一侧的指标.

只看目标领域, 会把遗忘当成免费的; 只看验证 loss, 会漏掉 Code Llama 7B 在 MMLU-STEM 和 SAT 上低于随机猜测 (25%) 这类问题. Llemma 论文指出, 这主要是因为它没能以有效答案结束推理过程.

### 6.4 适用范围与名字相近的做法

前面学习率和回放的结论, 有以下几条适用条件:

- **规模**: Gupta 等人只用了 410M, Ibrahim 等人用了 405M 和 10B. Code Llama 和 Llemma 在 7B 到 70B 上验证了做法, 但没有做系统的回放比例消融.
- **优化器状态与数据量**: Ibrahim 等人的实验重置了优化器状态. 如果有原始的优化器状态, 升温的初期行为可能不同. 本文的例子都是几十 B 到 1T token. 数据量只有几 B token 时, 更接近微调, 学习率和回放的结论不一定适用.
- **起点 checkpoint 的选择**: 基座只发布了余弦衰减到底的权重时, 只能重新升温; 如果基座用 WSD 或多阶段日程且有衰减前的 checkpoint, 从后者出发可以省掉升温造成的 loss 上升 (2.5 节).
- **回放数据的来源**: Ibrahim 等人回放的是真实的 $\mathcal D_0$. 开源基座的预训练数据通常不公开, 回放只能用分布相近的公开语料, Llemma 混入的就是公开的 Pile 和 RedPajama. 替代数据与真实 $\mathcal D_0$ 有差距, 第 3.2 节表格里的回放效果不能直接套用到这种情况.
- **遗忘的度量**: 旧数据的验证 loss 上升与下游能力下降不完全一致. Ibrahim 等人同时报告了 loss 和多个评测基准的平均分.

继续预训练和几种做法名字相近, 区别在用什么数据, 学习率怎么设:

| 名字 | 数据 | 学习率 | 与本文的关系 |
|------|------|------|------|
| 继续预训练 | 无标注文本, 几十 B token 以上 | 重新升温到 $\mathcal O(\eta_{\max})$ | 本文主题 |
| 退火 (annealing) | 高质量数据, 预训练末段 | 衰减到 0 | 预训练的一部分, 见 [3.4.2](../../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4 节 |
| 长上下文微调 | 长序列文本 | 小学习率 (如 $2\times10^{-5}$) | 第 5 节 |
| SFT | 指令-回答对 | 小学习率 | 见 [4.2](../../../4-后训练/4.2-SFT/4.2-SFT.md) |
| 持续学习 | 多阶段任务序列 | 视方法而定 | 更一般的问题, 见 [4.10](../../../4-后训练/4.10-持续学习/4.10-持续学习.md) |
| 回放 (replay) | 新数据中混入旧数据 | 不变 | 第 3 节 |
| rehearsal (Code Llama) | 微调数据中混入预训练风格数据 | 不变 | 与回放同义, 用在 Instruct 阶段 |
