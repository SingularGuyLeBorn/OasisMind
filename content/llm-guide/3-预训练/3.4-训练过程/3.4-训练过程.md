# 3.4 训练过程

进入训练过程时, 配置表已经填好: 语料和配比来自 [3.1](../3.1-预训练数据/3.1-预训练数据.md), 词表来自 [3.2](../3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md), 参数量, token 数和形状来自 [3.3](../3.3-模型配置与Scaling-Laws/3.3-模型配置与Scaling-Laws.md). 剩下的问题是怎样把 $C\approx6ND$ 这么多计算在几千到上万张卡上跑完: 模型怎么切到卡上 ([3.4.1](./3.4.1-训练框架选择/3.4.1-训练框架选择.md)), 学习率, batch 和数据阶段怎么排 ([3.4.2](./3.4.2-预训练策略/3.4.2-预训练策略.md)), 故障和 loss spike 出现时怎样恢复 ([3.4.3](./3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md)).

这三篇的数字大多来自同一次训练: Llama 3 405B 在最多 16,384 张 H100 上训练 15.6T token. 下面先给出五个环节的位置, 再讲三篇之间互相牵制的几个量, 最后用这次训练的时间线把它们串起来.

## 1. 五个环节

### 1.1 从数据到 checkpoint

**图 1 解析**

图里的箭头只表示决定做出的顺序. 后面三个环节都在训练开始前定方案, 训练中持续调整: 并行配置会随序列长度切换, 学习率和数据配比会分阶段变化, checkpoint 间隔要随故障率调整. 所以 3.4 的三篇讲的是同一段时间里同时在跑的三件事.

### 1.2 前两个环节留下的约束

结构环节已经替训练框架做了一部分决定. 3.3.1 第 2.2 节说明, Llama 3 405B 的 126 层来自 16 段流水线每段 8 层, 首末两段各减一层; 128 个查询头和 8 个 KV 头都能被张量并行度 8 整除. 也就是说, 层数和头数是按预定的并行方式选的, 3.4.1 的并行配置在结构环节就已有雏形.

数据环节则决定了策略环节的数据阶段. 3.4.2 第 4 节里训练中途对配比的调整 (增加非英语, 上采样数学, 加入更新的网页, 下采样低质量子集), 前提是 3.1 已经把语料按来源和质量分好层; 末段上采样高质量数据, 依赖 3.1.3 的质量分类器打出的分数. 如果语料只是一个混合好的大池子, 这些调整就无从做起.

## 2. 三篇共享的约束

### 2.1 显存与通信

混合精度训练的模型状态约为每参数 16 字节: BF16 权重和梯度各 2 字节, FP32 主副本和 Adam 的两个矩各 4 字节. 405B 模型合计约 6.48 TB, 远超单卡显存, 必须切分. ZeRO / FSDP 切分模型状态, 张量并行切每层的矩阵乘, 流水线并行按层切段, 上下文并行切序列, 专家并行切 MoE 的专家. 每种切法都换来一种通信: 张量并行每层要做 all-reduce, 流水线并行有段间传输和气泡, 上下文并行要交换 K, V.

Megatron 的 PTD-P 给出两条组合规则: 张量并行放在单机 8 卡的 NVLink 内, 模型并行度取能放下模型的最小值, 其余卡全部用于数据并行. Llama 3 的三档配置符合这两条, 8192 张卡上是 TP 8, PP 16, DP 64, MFU 43%; 扩到 16,384 张卡, DP 翻倍到 128, MFU 降到 41%; 128K 序列阶段加上 CP 16, MFU 38%. 并行维度从内到外的顺序是 [TP, CP, PP, DP], 通信最频繁的放在带宽最高的一层.

### 2.2 batch 同时受优化和并行约束

3.4.2 从优化的角度讨论 batch. McCandlish 等人的梯度噪声尺度说明, batch 小于临界值时加倍 batch 几乎加倍进度, 超过临界值后只是多耗样本; 临界 batch 随 loss 下降而增大, Kaplan 的拟合给出 loss 从 3 降到 2.5 nats 时临界 batch 增大约 2.4 倍. 这是 Llama 3 把 batch 从 4M 加到 8M 再加到 16M token 的依据, 也让早期 18% 的 token 占了约 31% 的参数更新步数.

3.4.1 从并行的角度给 batch 设了下限. 全局 batch 等于数据并行组数乘以每组的 micro-batch 数和 micro-batch 大小, 流水线的气泡比例随每组 micro-batch 数增加而下降, 所以每个数据并行组的 batch 不能太小. MegaScale 在固定全局 batch 下扩卡, MFU 从 59.1% 降到 55.2%, 原因之一就是每组分到的 micro-batch 变少, 气泡占比变大. 优化想要的早期小 batch 和并行想要的大 batch 在这里相互冲突, 3.4.2 第 5.2 节把这一点列为 McCandlish 理论的边界.

### 2.3 checkpoint 把三篇连在一起

3.4.3 第 2 节推导了 checkpoint 间隔: 每次保存阻塞 $\delta$ 秒, 平均故障间隔 $M$, 最优间隔 $T^*=\sqrt{2\delta M}$, 最小损失约 $\sqrt{2\delta/M}+R/M$, $R$ 是每次重启的开销. Llama 3 的 54 天里有 419 次意外中断, $M\approx3.1$ 小时; 代入可知保存阻塞要压到几十秒以内, 重启要在十分钟量级, 有效训练时间才可能超过报告的 90%. 6.48 TB 的状态按存储系统的 2 TB/s 持续吞吐写一次约 3.2 秒, 这是带宽给出的下限.

checkpoint 的内容又由另外两篇决定. 它要保存的不只是权重, 还有优化器状态, 数据加载器的位置和随机数状态, 因为 3.4.3 第 4 节的 loss spike 处理要求精确重放: PaLM 遇到约 20 次 spike, 每次从 spike 前约 100 步的 checkpoint 重启, 跳过 200 到 500 个 batch, 这只有在训练逐位确定, 数据能按 batch 跳过时才能做. 学习率日程也影响 checkpoint 的用途: WSD 和恒定加冷却的恒定段 checkpoint 可以分叉出一段短衰减, 用来评估数据或延长训练, 余弦日程的中途 checkpoint 则做不到.

## 3. 三篇的对照

### 3.1 各自优化的量

把三篇放在一张表里, 每篇都在一个约束下优化一个量:

| | 3.4.1 训练框架 | 3.4.2 预训练策略 | 3.4.3 容灾与监控 |
|---|---|---|---|
| 优化的量 | 吞吐 (MFU) | 同样 token 数下的最终 loss | 有效训练时间 |
| 主要约束 | 单卡显存, 互连带宽 | 训练稳定性, 临界 batch | 故障率, 存储带宽 |
| 关键式 | 16 字节每参数; 训练时间 $\approx 8ND/(nX)$, $X$ 为每卡实际吞吐 (含重计算) | 余弦与 WSD 的形状; $B_{\mathrm{noise}}\approx\mathrm{tr}(\Sigma)/\lvert G\rvert^2$ | $T^*=\sqrt{2\delta M}$ |
| Llama 3 405B 的取值 | TP 8, PP 16, DP 64 到 128, MFU 38% 到 43% | 峰值 $8\times10^{-5}$, 8000 步 warmup, 余弦 120 万步降到 1% | 466 次中断, 有效时间 90% 以上 |

前两列都以工期计成本: 训练时间正比于 $1/X$, 也正比于有效训练时间比例的倒数, MFU 从 43% 降到 41% 与有效训练时间从 95% 降到约 90% 对工期的影响相当. Llama 3 报告把 batch 递增和学习率日程放在一起解释 loss spike 很少的原因, 训练中不需要干预来纠正发散, 这又减少了 3.4.3 意义上的回滚开销.

公开的 MFU 数字跨度很大: GPT-3 21.3%, Gopher 32.5%, MT-NLG 30.2%, PaLM 46.2%, Megatron 530B 54.2%, MegaScale 55.2%. 这些数字的计算口径不完全一致 (是否计入注意力 FLOPs, 是否计入重计算), 3.4.1 第 5.3 节给出了 MFU 的定义和 PaLM 附录 B 的计算方式, 比较前要先对齐口径.

### 3.2 公开配方的分歧

并行组合上, 公开配方并不收敛到同一种. PaLM 540B 在 6144 张 TPU v4 上不用流水线并行, 每个 pod 内 12 路模型并行乘 256 路 FSDP, 两个 pod 之间用 Pathways 做数据并行; DeepSeek-V3 反过来不用张量并行, 用 PP 16, EP 64 和 ZeRO-1, 理由是非专家参数只占总参的几个百分点, 专家由专家并行分摊. Llama 3 是稠密模型, 四维 [TP, CP, PP, DP] 全用. 选择取决于硬件的互连拓扑和模型是否 MoE.

学习率日程和 spike 处理也是两派. Llama 3 用一条余弦; DeepSeek-V3 前 10T token 恒定在 $2.2\times10^{-4}$, 之后 4.3T token 余弦降到 $2.2\times10^{-5}$, 末尾 500B token 两级阶梯, 继承了 WSD 可以从恒定段接着训的性质; MiniCPM 的 WSD 只在最后约 10% 衰减. spike 方面, PaLM 和 OPT 靠回滚 (OPT 还把梯度裁剪从 1.0 收紧到 0.3), Llama 3 和 DeepSeek-V3 报告全程不需要回滚, 稳定性来自训练配方本身.

## 4. 一次训练的时间线与读法

### 4.1 Llama 3 405B 的时间线

按 token 进度排, Llama 3 405B 的训练依次经过这些节点. 开始时序列长度 4096, batch 4M token, 8000 步 warmup 到峰值学习率 $8\times10^{-5}$. 训练到 252M token, 序列加到 8192, batch 加到 8M; 到 2.87T token, batch 再加到 16M. 主体训练期间配比逐步调整, 最终是通用知识 50%, 数学与推理 25%, 代码 17%, 多语言 8%. 整个过程中集群每天至少因自动维护中断一次, 54 天快照期内 GPU 相关问题占意外中断的 58.7%.

主体训练之后进入长上下文阶段, 从 8K 分 6 个阶段扩到 128K, 共约 800B token, 并行配置加入 CP 16, MFU 从 41% 到 43% 降到 38%. 最后 40M token 在 128K 长度上把学习率线性降到 0, 同时上调高质量来源, 对退火阶段的 checkpoint 做 Polyak 平均, 得到最终的预训练模型. 在 8B 上做同样的退火, GSM8k 提升 24.0%, MATH 提升 6.4%, 在 405B 上可以忽略. 长上下文阶段的数据与外推方法在 [3.5.2](../3.5-继续预训练与长上下文训练/3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md), 每一阶段的放行条件在 [3.6.3](../3.6-预训练评估/3.6.3-大海捞针测试/3.6.3-大海捞针测试.md).

### 4.2 读法

估算训练天数的读者先读 [3.4.1](./3.4.1-训练框架选择/3.4.1-训练框架选择.md) 第 1 节的显存公式和第 5 节的训练时间估算与 MFU, 第 5.6 节有一个 70B 模型在 8K 序列上的完整算例; 并行方式的通信原语和实现细节在 [6.1.1 分布式训练](../../6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md). 要选学习率日程的读者读 [3.4.2](./3.4.2-预训练策略/3.4.2-预训练策略.md) 第 2.5 节的日程对照表, 从余弦换到 WSD 时注意 Hägele 等人的结论: 恒定加冷却的最优学习率略低于余弦峰值的一半, 直接沿用余弦峰值会把全程平均学习率提高近一倍.

负责训练运维的读者读 [3.4.3](./3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md), 第 2.2 节把 Llama 3 的故障率代入 checkpoint 间隔公式, 第 4.4 节给出 spike 的处理顺序, 第 5 节列出训练数值和系统层面要监控的信号, 包括 Gemini 报告估计每一两周就会出现一次的静默数据损坏. 训练过程中评测进度用什么量, 见 [3.6](../3.6-预训练评估/3.6-预训练评估.md); 在已训好的基座上继续训练时日程怎样重新升温, 见 [3.5.1](../3.5-继续预训练与长上下文训练/3.5.1-继续预训练/3.5.1-继续预训练.md).
