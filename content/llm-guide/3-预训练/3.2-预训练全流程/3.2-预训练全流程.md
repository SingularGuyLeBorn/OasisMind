## 1. 分词器:本节只定接口

词表大小 $V$ 同时影响 embedding 矩阵和 LM head 的维度.词表太小,非英语会碎成字节,序列变长;词表太大,罕见词学习效率下降,embedding 层参数也膨胀.所以分词器不是「选一个开源词表」就行,而是要在压缩率,多语言覆盖和下游任务兼容性之间权衡.

合并规则文件通常随模型一起发布,代表性语料上训 BPE 或 SentencePiece,再对多语言,代码,特殊符号做编解码回归.算法步骤,byte-level 与 Unigram 对比全部去 3.3.

## 3. 框架与并行

单卡装不下 70B 的参数 + 梯度 + Adam 状态.3D 并行把矩阵切在节点内(TP),层切到不同机(PP),不同 batch 做数据并行(DP).ZeRO 再把优化器状态(以及更激进的梯度/参数)分片.细节与文档数字在 3.2.3.

并行策略不是越大越好.TP 通信太密,通常只在一个节点内;PP  Pipeline bubble 会浪费算力;DP 需要 batch 足够大才能摊平同步开销.框架选型时先看硬件拓扑:机内 NVLink 带宽,机间 IB 带宽,单节点显存,这些硬约束比任何并行公式都先决定可行性.序列并行与 Megatron-SP 的 MFU 数字见 [6.1.1](../../6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md).

## 4. 策略与容灾

优化器几乎都是 AdamW;学习率要么余弦衰减(Llama 3 405B 报告),要么 WSD 平台期(MiniCPM).精度默认 BF16,TP 内部偶尔用 FP8 进一步压通信和显存.这些选择在子文 3.2.4 里按报告列数字,不在首页画假 Loss 曲线.

容灾不是可选项.同步训练里一张 GPU 挂了整作业停,步间必须能从最近合法 snapshot 拉起来.异步 checkpoint 可以减轻停顿,但会引入一致性窗口;故障域设计要看哪些节点共享交换机,哪些共享存储.3.2.5 写 checkpoint 频率,监控量和常见挂法.

## 5. 和 3.2.6,3.2.7 的边界

给定 FLOPs,先问 $N$ 与 $D$ 配多少,这是 3.2.6 Scaling Law 的问题.它回答的是「同样算力,模型应该多大,数据应该多少",不是「具体某个架构怎么实现".Kaplan 和 Chinchilla 两条曲线给出了不同的最优偏向,但实际训练往往还会超配数据以换推理成本.

已经有通用基座,只想灌医学或法律,走 3.2.7 继续预训练.它不是把 3.2 整条链再跑一遍,而是冻结或低学习率更新部分层,用领域语料补基座没见过的术语和分布.重点在数据配比,灾难性遗忘和学习率恢复,而不是从头调超参.
