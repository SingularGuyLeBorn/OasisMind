# 3.4.3 大海捞针测试（Needle In A Haystack, NIAH）

NIAH 问的是：模型能不能从很长的无关文本里**找回一句与主题无关的事实**。它诊断检索，不诊断摘要、多跳推理或「真正读懂」。有效长度请用 RULER；U 型位置曲线的论文实验不是餐厅针演示——见下文链接，本篇不写第二套 Lost-in-the-Middle。旧路径 [3.3.3](./3.3.3-大海捞针测试.md) 为重定向。

厂商演示热力图的逐格准确率，本篇没有打开 Kamradt 仓库或原图读数，**不列 GPT-4 Turbo / Claude 3 / Gemini 1.5 的百分表**。

## 1. 协议：放针、提问、二分

| 概念 | 含义 |
|------|------|
| Haystack | 很长的干扰文本 |
| Needle | 与上下文无关的一句事实 |
| 检索 | 问与针直接相关的问题，看是否答出关键实体 |

步骤：把针插入开头 / 中部 / 结尾（或连续扫深度）→ 提问 → 输出是否包含针里的关键信息（通常通过 / 失败）。设计要点：针不能靠常识猜中；位置要扫全；长度从远小于窗口加到宣称上限。

**图 1 解析**

- 中：问题与针对齐，避免模型用参数知识抢答。
- 右：标准评分是二元。部分正确（专名对了但缺限定）会被判失败，粒度粗。
- Llama 3 在把窗口从 8K 接到 128K 的继续预训练里，用「该长度上 NIAH 是否全对」当适应判据之一（Grattafiori et al., 2024, §3.4）——那是**训练检查**，不是公开热力图读数。

## 2. 单针全绿之后：RULER

Hsieh et al. (2024) 把 vanilla NIAH 判成浅层检索：他们评的模型在单针上几乎满分，加长并换任务后大面积掉点。RULER 四类（论文 §1）：

1. **Retrieval**：扩展 NIAH（多种针、多根针）。
2. **Multi-hop Tracing**：变量追踪，代理指代链。
3. **Aggregation**：高频词抽取，代理摘要。
4. **Question Answering**：短上下文 QA 加上干扰文档。

配置：13 个代表任务；当时测 10 个长上下文模型（摘要亦写 17 个模型的更大扫描）。宣称上下文 ≥32K 的模型里，**只有四个**在 32K 仍过他们的满意线（GPT-4、Command-R、Yi-34B、Mixtral）。一句话：**宣称窗口 ≠ 有效窗口**；有效窗口不能用单针全绿定义。

## 3. Lost in the Middle：链专文，不在这里重画 U 型

Liu et al. (2023, TACL 2024) 的实验是 **多文档 QA + key-value 检索**，不是 Kamradt 餐厅针。结论：相关信息在上下文**开头或结尾**时更好，在**中间**显著变差；上下文再拉长，表现继续掉。不要把那篇的曲线标成「NIAH 热力图」。位置偏差在本库的应用层写法见 [7.6 上下文工程 §8.3](../../../7-LLM应用开发/7.6-上下文工程/7.6-上下文工程.md)；注意力压缩何时救不了「模型本来就不会长上下文」，见 SnapKV 专文里的失效节。

## 4. 失效

| 现象 | 原因 |
|------|------|
| 针换一种措辞分数崩 | 协议对字面匹配敏感 |
| 干草主题与针偶然相关 | 参数知识或主题幻觉顶替检索 |
| 位置编码外推失败 | 超过训练长度时 RoPE 局部性坏掉，未必是「忘了」 |
| 只报宣称 1M | 未跑 RULER 或等价多任务 |
