# 3.4.1 困惑度: 从交叉熵到每字节比特

> 相关阅读: [3.4 预训练评估](../3.4-预训练评估.md) · [3.4.2 通用基准](../3.4.2-通用基准/3.4.2-通用基准.md) · [3.4.3 大海捞针与长上下文](../3.4.3-大海捞针测试/3.4.3-大海捞针测试.md) · [3.2 预训练全流程](../../3.2-预训练全流程/3.2-预训练全流程.md) · [3.3 分词器](../../3.3-分词器与Tokenizer/3.3-分词器与Tokenizer.md)

## 1. 问题与定义

### 1.1 预训练中拿什么看进度

预训练一次要跑几周到几个月. 训练 loss 每一步都有, 但它是在训练分布上算的, 数据重复, 配比调整, 学习率阶段切换都会让它跳动. 下游基准 (MMLU, GSM8K, HumanEval) 能回答「会不会做题」, 但每跑一次要完整推理, 小模型和早期 checkpoint 上又常常停在随机水平附近 (见 [3.4.2](../3.4.2-通用基准/3.4.2-通用基准.md) 第 4 节). 于是在两者之间需要一个量: 在固定的留出语料上算, 每个 checkpoint 都能算, 对模型变好有连续的响应. 困惑度和由它换算出的每字节比特就是这个量.

常见的粗略说法是: PPL 越低, 模型越好. 这句话在一个模型的训练过程里大体成立, 换到模型之间就有三处不准. 第一, PPL 的单位是「每 token」, 不同 tokenizer 下 token 数不同, 数字不可比. 第二, 同一个模型在同一份语料上, 给的上下文长短不同, PPL 可以差 15%. 第三, PPL 和下游分数的关系取决于下游用什么度量, 有时近乎线性, 有时看起来脱钩.

本文按五个问题展开:

1. PPL 的定义是什么, 它和交叉熵, 几何平均, 码长是什么关系.
2. 跨 tokenizer 比较时换成什么单位, 怎么换算.
3. 窗口, 步长, 文档边界怎样改变 PPL.
4. 把语言模型当压缩器看, 能多看出什么.
5. PPL 降低何时对应下游变好, 何时看起来不对应.

### 1.2 PPL 的定义: 从链式法则到 PPL

测试序列 $x_{1:T}=(x_1,\dots,x_T)$ 是 tokenizer 切出来的 $T$ 个 token. 自回归模型 $p_\theta$ 按链式法则给整段序列打概率:

$$
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}) \tag{1}
$$

$x_{<t}$ 是第 $t$ 个位置之前的全部 token, 也就是模型在这一步看到的上下文. 每 token 平均负对数似然 (以 nat 为单位, 底数 $e$) 是

$$
\mathcal{L}_{CE}=-\frac{1}{T}\sum_{t=1}^{T}\ln p_\theta(x_t\mid x_{<t}) \tag{2}
$$

式 (2) 就是训练时 next-token prediction 的交叉熵, 只是换成在留出语料上算. 困惑度是它的指数:

$$
\mathrm{PPL}=\exp(\mathcal{L}_{CE})=p_\theta(x_{1:T})^{-1/T} \tag{3}
$$

式 (3) 的第二个等号把指数和对数抵消: $\exp\bigl(-\frac{1}{T}\sum\ln p_t\bigr)=\bigl(\prod p_t\bigr)^{-1/T}=\bigl(\prod 1/p_t\bigr)^{1/T}$. 也就是说, **PPL 是模型给每个真实 token 的概率倒数的几何平均**. Hugging Face 的 perplexity 文档用的是同一个定义, 并补了一句: 这一定义只适用于自回归模型, 对 BERT 这类掩码语言模型没有良好定义.

### 1.3 「等效候选数」从哪来

如果模型在每一步都把概率均匀摊在 $K$ 个 token 上, 并且真实 token 总在这 $K$ 个之中, 那么每一步 $p_t=1/K$, 式 (2) 给出 $\mathcal{L}_{CE}=\ln K$, 式 (3) 给出 $\mathrm{PPL}=K$. 这就是「PPL 等于每步等效的均匀候选数」的来源. 真实分布不均匀, 这个解释只说明量纲, 不说明模型每步真的在 $K$ 个词里犹豫.

手算一个四 token 的例子 (概率为示意, 非某个模型的输出). 设模型给四个真实 token 的条件概率依次是 $0.5, 0.25, 0.8, 0.1$:

| 步 | $p_t$ | $-\ln p_t$ | $1/p_t$ |
|---|---|---|---|
| 1 | 0.5 | 0.6931 | 2 |
| 2 | 0.25 | 1.3863 | 4 |
| 3 | 0.8 | 0.2231 | 1.25 |
| 4 | 0.1 | 2.3026 | 10 |
| 合计 | | 4.6051 | 乘积 100 |

式 (2): $\mathcal{L}_{CE}=4.6051/4=1.1513$ nat. 式 (3): $\mathrm{PPL}=e^{1.1513}=3.162$, 与 $100^{1/4}=3.162$ 相同. 第 4 步一个 token 贡献了总 loss 的一半. 这说明 PPL 对模型「完全没料到」的 token 敏感: 一个概率 0.001 的 token 贡献 6.9 nat, 抵得上十个概率 0.5 的 token. 低频专名, 数字, 代码里的随机标识符, 都是 PPL 里的大头.

### 1.4 loss 差和 PPL 比的换算

训练曲线通常画 loss, 报告里常写 PPL. 两者之间是指数关系. 若两个 checkpoint 的 loss 差 $\Delta=\mathcal{L}_1-\mathcal{L}_2$, 则

$$
\frac{\mathrm{PPL}_2}{\mathrm{PPL}_1}=e^{-\Delta} \tag{4}
$$

式 (4) 说明 PPL 的相对变化只取决于 loss 的绝对差, 与 loss 本身在哪个水平无关. loss 降 0.01 nat, PPL 降 $1-e^{-0.01}\approx 1.0\%$; 降 0.1 nat, PPL 降约 9.5%. 所以「PPL 从 20 降到 18」和「从 5 降到 4.5」是同样大小的进步, 都对应 loss 降约 0.105 nat. 指数不改变最优点, 只改变曲线看起来的陡峭程度.

| $\mathcal{L}_{CE}$ (nat) | PPL | $\mathcal{L}_{CE}$ (bit) |
|:---:|:---:|:---:|
| 0 | 1 | 0 |
| 1 | 2.72 | 1.443 |
| 2 | 7.39 | 2.885 |
| 3 | 20.1 | 4.328 |

最后一列是同一个量换成以 2 为底: $\mathcal{L}_{\text{bit}}=\mathcal{L}_{\text{nat}}/\ln 2$. 第 2 节和第 3 节都要用到 bit 单位.

### 1.5 PPL 的下界: 数据本身的熵

式 (2) 是模型分布 $p_\theta$ 相对真实分布 $p$ 的交叉熵的样本估计. 交叉熵可以拆成两项:

$$
H(p,p_\theta)=H(p)+D_{\mathrm{KL}}(p\,\|\,p_\theta) \tag{5}
$$

$H(p)$ 是数据的熵, $D_{\mathrm{KL}}\ge 0$ 是模型与真实分布的差距. 训练只能把第二项压向 0, 第一项不随模型变化. 所以自然文本上 PPL 有一个大于 1 的下界 $e^{H(p)}$. 这个下界不可直接测, 但它解释了 Scaling Laws 拟合式里的常数项 (不可约 loss), 拟合细节见 [3.2 预训练全流程](../../3.2-预训练全流程/3.2-预训练全流程.md) 的 Scaling Law 一篇. 换句话说, 两个模型的 PPL 差是它们的 KL 项之差, 熵项在同一份语料上相同, 被减掉了.

## 2. 单位与协议: 同一个模型为什么会得出不同的 PPL

### 2.1 token 数不同: 换成每字节比特

同一段文本, 词表小的 tokenizer 切得碎, $T$ 大, 每个 token 好猜一些 (很多 token 只是词的后半截); 词表大的切得粗, $T$ 小, 每个 token 难猜. 式 (2) 是按 $T$ 平均的, 两者的 $\mathcal{L}_{CE}$ 和 PPL 都不可比. 可比的是整段文本的总码长 $\sum_t -\log_2 p_\theta(x_t\mid x_{<t})$, 它不依赖怎么切, 只依赖模型给整段文本的概率. 把总码长除以一个与 tokenizer 无关的长度, 就得到可比的单位.

The Pile 论文 (Gao 等人 2020) 选的长度是 UTF-8 字节数. 记语料共 $L_T$ 个 token, $L_B$ 个 UTF-8 字节, $\ell$ 为式 (2) 的每 token 平均 loss (nat), 则

$$
\mathrm{BPB}=\frac{L_T}{L_B}\cdot\frac{\ell}{\ln 2} \tag{6}
$$

$\ell/\ln 2$ 把每 token 的 nat 换成 bit, 再乘每字节的 token 数 $L_T/L_B$, 得到每字节的 bit 数. 论文给出 GPT-2 tokenizer 在整个 Pile 上 $L_T/L_B=0.29335$ token/byte, 各子集的值在其 Table 7. 代入一个例子: 若 GPT-2 tokenizer 下 $\ell=2.0$ nat, 则 $\mathrm{BPB}=0.29335\times 2.0/0.6931=0.846$.

论文给出选字节而不选字符的理由有两条: 对 tokenizer 不变; Unicode 下「一个字符」怎么算有歧义 (组合字符, 代理对). Huang 等人 (2024) 用的是每字符比特, 定义为

$$
\mathrm{BPC}=\frac{\sum_{i=1}^{N}-\log_2 p_\theta(x_i\mid x_{<i})}{C} \tag{7}
$$

$N$ 是该模型 tokenizer 切出的 token 数, $C$ 是语料的字符数. 式 (6) 和式 (7) 只差分母. 对中文这一点要单独算: 常用汉字 (U+4E00 到 U+9FFF) 在 UTF-8 里占 3 个字节, 纯中文文本上 $\mathrm{BPC}\approx 3\,\mathrm{BPB}$, 英文 ASCII 文本上两者近似相等. 中英混合语料只报 BPC 或只报 BPB 都可以, 但不能拿中文的 BPC 和英文的 BPB 放在一起比.

Chinchilla 论文附录 Table A5 用 BPB 比较三个 tokenizer 不同的模型在 The Pile 各子集上的表现. 几行节选 (单位 bit/byte):

| 子集 | Chinchilla 70B | Gopher 280B | Jurassic-1 170B |
|---|---|---|---|
| `pile_cc` | 0.667 | 0.691 | 0.669 |
| github | 0.337 | 0.377 | 0.358 |
| arxiv | 0.627 | 0.662 | 0.680 |
| `dm_mathematics` | 1.111 | 1.142 | 1.037 |
| `ubuntu_irc` | 1.026 | 1.090 | 0.857 |
| `gutenberg_pg_19` | 0.548 | 0.656 | 0.890 |

Jurassic-1 和 Chinchilla 词表不同, 这张表仍然能比, 原因就是式 (6) 消掉了 tokenizer. 表里也能看出子集之间差得很远: 代码 0.337, 合成数学题 1.111. 一个「全语料平均 BPB」会被配比左右, 留出集的子集构成要固定.

### 2.2 上下文长短: 不重叠切块与滑动窗口

式 (1) 要求每一步都以全部前文为条件. 模型有最大长度 $K$, 序列一长就只能截断. Hugging Face 的 perplexity 文档对比了两种做法:

- **不重叠切块**: 把序列切成长 $K$ 的段, 各算一遍. 每段开头的 token 几乎没有上下文, 平均下来上下文偏短, PPL 偏高.
- **滑动窗口**: 每次把窗口右移步长 $S<K$, 只对窗口内最后 $S$ 个新 token 计 loss, 前面 $K-S$ 个 token 只当上下文 (代码里把它们的 label 设为 $-100$ 以忽略). 除了序列开头, 每个被计分的 token 至少有 $K-S$ 个 token 的上下文.

文档里的数字: GPT-2 large ($K=1024$) 在 WikiText-2 测试集上, $S=1024$ (即不重叠) 得 PPL 19.44, 与 GPT-2 论文报的 19.93 接近; $S=512$ 得 16.44. 同一个模型, 同一份数据, 只改切法, PPL 低了 15%.

代价按前向次数算. 长度 $N$ 的语料, 不重叠需要 $N/K$ 次长 $K$ 的前向; 步长 $S$ 需要约 $N/S$ 次, 计算量是前者的 $K/S$ 倍. $S=1$ 最接近式 (1), 但每个 token 都要一次前向. 文档推荐的折中就是取一个较大的步长. Huang 等人 (2024) 测 BPC 时用步长 512 的滑动窗口, 并把所有模型的上下文统一截到 1900 token, 理由是他们的下游基准输入都不超过 2048 token, 让压缩和做题看到同样多的上下文.

lm-evaluation-harness 维护者的论文 (Biderman 等人 2024) 引用 Press 等人 (2020) 指出, 对超过窗口的序列用不重叠窗口算 PPL, 会系统性地偏向训练窗口更长的模型. 原因与上面相同: 窗口长的模型每段开头的「冷启动」占比小. 比较不同窗口的模型时, 要么统一截断长度 (Huang 的做法), 要么用相同 $K-S$ 的滑动窗口.

### 2.3 文档边界

HF 文档的例子把 WikiText-2 全部测试文本用 `\n\n` 拼成一条长序列再滑窗, 前一篇文章的结尾会成为后一篇开头的上下文. The Pile 论文的做法相反: 每篇文档单独 tokenize, 按模型最大长度 (GPT-2 1024, GPT-3 2048) 切段, 每个 token 恰好计分一次, 文档之间不共享上下文. 两种做法在长文档上差别小, 在大量短文档 (网页, 对话) 上差别大, 因为短文档的开头 token 占比高, 而开头 token 最难猜.

把 3.1 到 3.3 合起来, 一个 PPL 数字要能复现, 至少要附上下面几项:

| 项 | 例子 | 不写会怎样 |
|---|---|---|
| 计分单位 | 每 token / 每字节 / 每字符; 对数底 | 跨 tokenizer 不可比, nat 与 bit 差 1.443 倍 |
| 语料与切分 | WikiText-2 test; Pile 各子集 | 子集 BPB 可差 3 倍 |
| 窗口 $K$, 步长 $S$ | 1024 / 512 | 同一模型差 15% |
| 文档处理 | 拼接 / 逐篇 | 短文档语料上差别明显 |
| 是否去污 | 与训练集的 n-gram 重叠 | PPL 虚低 (第 4.4 节) |

## 3. 压缩视角: log-loss 就是码长

### 3.1 算术编码把概率变成比特

Delétang 等人 (2023) 的论文 *Language Modeling Is Compression* 从信息论出发重新叙述 PPL. Shannon 信源编码定理给出: 对来自分布 $\rho$ 的序列, 任何无损编码的期望码长不小于熵 $H(\rho)$. 算术编码在给定一个概率模型后能逼近这个下界: 对序列 $x_{1:n}$, 无限精度算术编码的码长是 $-\lceil\log_2\rho(x_{1:n})\rceil+1$ bit, 最优码长是 $-\log_2\rho(x_{1:n})$ bit; $B$ bit 有限精度实现再多 $O(n2^{-B})$ bit, 32 位或 64 位运算下可以忽略.

用模型 $\hat\rho$ 代替未知的 $\rho$, 期望码长变成交叉熵 (论文式 (2)):

$$
H(\rho,\hat\rho)=\mathbb{E}_{x\sim\rho}\Bigl[\sum_{i=1}^{n}-\log_2\hat\rho(x_i\mid x_{<i})\Bigr] \tag{8}
$$

式 (8) 与式 (2) 是同一个量, 只差对数底和是否除以长度. 所以论文的说法是: 当前语言模型的训练目标就是最大压缩目标. 编码过程是逐 token 的: 第 $k$ 步把当前区间按 $\hat\rho(\cdot\mid x_{<k})$ 切成子区间, 选中真实 token 对应的那一段, 区间宽度乘以 $\hat\rho(x_k\mid x_{<k})$. 结束时区间宽度是 $\hat\rho(x_{1:n})$, 写出这个区间需要约 $-\log_2\hat\rho(x_{1:n})$ bit. 模型给真实 token 的概率越高, 区间缩得越慢, 码越短. 解码端用同一个模型重放这个过程, 所以解码方必须持有模型参数.

压缩率 (压缩后大小 / 原始大小) 和 BPB 只差一个常数: 原始数据每字节 8 bit, 所以压缩率 $=\mathrm{BPB}/8$. 上一节 Chinchilla 在 `pile_cc` 上的 0.667 BPB, 折算压缩率约 8.3%.

### 3.2 三种数据上的压缩率

论文把每份数据集都做成 1GB: enwik9 (2006 年英文维基 XML 的前 $10^9$ 字节), ImageNet (32×64 灰度图块, 每像素一个字节), LibriSpeech (16kHz 语音, 按 2048 字节切块). Transformer 类压缩器按 2048 字节分块, 每块独立压缩 (不带前一块的历史); 经典压缩器同时报不分块和分块两种. Table 1 节选 (原始压缩率, %, 越低越好):

| 压缩器 | 分块 | enwik9 | ImageNet | LibriSpeech |
|---|---|---|---|---|
| gzip | 不分块 | 32.3 | 70.7 | 36.4 |
| LZMA2 | 不分块 | 23.0 | 57.9 | 29.9 |
| PNG | 不分块 | 42.9 | 58.5 | 32.2 |
| FLAC | 不分块 | 89.5 | 61.9 | 30.9 |
| gzip | 2048 | 48.1 | 68.6 | 38.5 |
| Transformer 3.2M (enwik8 上训练) | 2048 | 17.0 | 215.8 | 228.2 |
| Llama 2 7B | 2048 | 8.9 | 53.4 | 23.1 |
| Chinchilla 70B | 2048 | 8.3 | 48.0 | 21.0 |

这张表有三处要读. 第一, Chinchilla 70B 主要在文本上训练, 在图像块上 48.0 低于 PNG 的 58.5, 在语音上 21.0 低于 FLAC 的 30.9. 论文的解释是模型在上下文内完成了对新模态的适应 (in-context learning). 第二, 只在 enwik8 上训练的小 Transformer 压文本很好 (17.0), 压图像和语音超过 100%, 即比原始数据还大, 说明它只学到了训练分布. 第三, 经典压缩器分块后变差 (gzip 32.3 到 48.1), 因为它们本来靠很长的上下文 (gzip 32KB, LZMA2 近乎无限) 吃序列依赖; 语言模型的优势在参数里的先验, 不在上下文长度.

### 3.3 把参数算进码长

解码方要有模型才能解码. 论文把每个参数按 float16 计 2 字节, 加进压缩后大小, 得到调整后压缩率 (adjusted compression rate). 同一张 Table 1 的右半: Chinchilla 70B 在 enwik9 上从 8.3% 变成 14008.3%, Llama 2 7B 变成 1408.9%, 而 3.2M 参数的 Transformer 只从 17.0% 变成 17.7%. 140GB 的参数无法被 1GB 数据摊薄.

在 enwik7, enwik8, enwik9 三种规模上训练不同大小的 Transformer, 调整后压缩率随模型变大先降后升 (论文 Figure 2): 每个数据集大小对应一个最优模型大小, 数据越大, 能负担的参数越多. 这给 Scaling Laws 加了一个限定: 只看 log-loss 时模型越大越好, 把模型本身的描述长度算进来, 模型大小受数据量约束. 这一结论对应两段式编码 (two-part code); 论文也提到另一种在线 (prequential) 编码只计训练脚本长度, 对过参数化网络更有利, 但要在编码和解码两端都在线训练.

### 3.4 tokenizer 是一次预压缩

| BPE 1K | 25.4 | 14.8 | 6.9 |
| BPE 2K | 25.6 | 15.7 | 7.4 |
| BPE 5K | 23.1 | 17.1 | 8.7 |
| BPE 10K | 21.3 | 17.0 | 8.9 |
| BPE 20K | 19.3 | 16.4 | 9.0 |

无损分词不改变文本的总信息量: 序列变短, 每个 token 的条件分布熵相应变大. 表中 38M 参数的模型用 ASCII 最好 (6.4), 词表越大越差, 到 BPE 20K 是 9.0; 200K 参数的模型则是 BPE 20K 最好 (19.3). 论文表注的解释是: Transformer 用更简单的 tokenizer 压得更好, 而更大的词表把序列缩得更短, 固定长度的上下文能装下更多信息, 这对容量小的模型更有用. 这一节和 2.1 节指向同一件事: token 级 loss 混合了模型能力和分词方式, 要把两者拆开, 只能回到字节或字符.

## 4. PPL 与下游能力

### 4.1 跨模型: BPC 与平均分近似线性

Huang 等人 (2024) *Compression Represents Intelligence Linearly* 测了 31 个公开基座模型 (Llama 1/2, Qwen, Mistral, Mixtral-8x7B, Jamba-52B, DeepSeek, Yi, Falcon, 以及代码和数学专用模型), 在 12 个基准上做题, 同时在三份语料上测 BPC: 最新的 Common Crawl 文本 (对应知识与常识), 最近的 GitHub Python 仓库 (对应代码), arXiv 数学类论文 (对应数学). 语料取实验当时能拿到的最新数据, 以避开各模型的预训练集.

结果: 三个领域的平均分与全部语料的平均 BPC 之间 Pearson 相关为 -0.93, 线性拟合 RMSE 为 3.1%; 每个领域内部约 -0.95. 单个基准上也成立: HellaSwag -0.881, TriviaQA -0.951, MMLU -0.890, 这三项的 RMSE 约 2 个绝对点, 论文指出改一下 prompt 就足以造成这么大的波动; 代码区 DS-1000 为 -0.946. 这些模型的 tokenizer, 上下文窗口, 架构 (含 MoE 和 Transformer-Mamba 混合) 和预训练数据都不同, 式 (7) 的 BPC 让它们落在同一条线上.

这组结果有几个前提, 论文都写明了:

- **只看基座模型**. 后训练模型只对 (问题, 回答) 结构建模, 不再是任意文本的通用压缩器.
- **上下文统一为 1900 token**, 用步长 512 的滑动窗口. 下游输入都短, 长上下文对压缩的好处在做题时用不上, 所以截平.
- **语料要和能力对口**. MMLU 与 Common Crawl 分布不一致, 相关只有 -0.890; 换成教科书语料, 升到 -0.930 (附录 E). HellaSwag 平均准确率已超过 0.8, 接近饱和, 模型间区分度变小.
- **离群点**. DeepSeek-coder 系列一直在拟合线上方, 论文推测它们在预训练中见过对 HumanEval, MBPP 有帮助的私有任务数据, 但承认没有可靠方法验证. 数学区用 Min-K% Prob 方法 ($k=20$, 取一条样本中概率最低的 20% token 的平均负对数似然, 异常低说明样本可能在预训练集里) 检出: Qwen 系列在 GSM8K 训练集, MATH 训练集甚至 MATH 测试集上的分数远低于其他模型, 被判为可能见过这些数据.
- **语料要多大**. 知识区把压缩语料从 5 万字符加到 1 亿字符, 相关在约 300 万字符处饱和 (Figure 7).

也就是说, 在「基座模型, 短上下文, 语料对口, 无泄漏」这四个条件下, BPC 可以当一个与 tokenizer 无关的能力代理. 四个条件任一不满足, 线性关系就要重新检验. 另外 MMLU 在这篇里用的是完形填空格式 (只给题干, 比较各选项的似然), 不是常见的「A/B/C/D」格式; 后者会引入第 [3.4.2](../3.4.2-通用基准/3.4.2-通用基准.md) 节讲的格式能力问题.

### 4.2 单模型训练中: loss 平滑, 准确率突变

「涌现」指小模型完全不会, 大模型突然会的能力 (Wei 等人 2022). Schaeffer, Miranda, Koyejo (2023) 给出另一种解释: 对一个模型族, 每 token 交叉熵随参数量 $N$ 平滑下降, 是度量把它变成了突变. 设

$$
\mathcal{L}_{CE}(N)=\Bigl(\frac{N}{c}\Bigr)^{\alpha},\qquad c>0,\ \alpha<0 \tag{9}
$$

用观测到的真实 token $v^*$ 代替未知分布, 单 token 预测正确的概率是

$$
p(\text{单 token 正确})=\exp\bigl(-\mathcal{L}_{CE}(N)\bigr) \tag{10}
$$

若任务要求 $L$ 个 token 全对 (例如 $L$ 位整数加法的精确匹配), 并假设各 token 是否正确相互独立, 则

$$
\mathrm{Accuracy}(N)\approx p(\text{单 token 正确})^{L}=\exp\bigl(-L\,\mathcal{L}_{CE}(N)\bigr) \tag{11}
$$

而按 token 编辑距离计分时, 错误数近似是

$$
\mathrm{TokenEditDistance}(N)\approx L\bigl(1-p(\text{单 token 正确})\bigr) \tag{12}
$$

式 (11) 对每 token 错误率是几何的, 式 (12) 是近似线性的. 代入数字 ($L=5$): 每 token loss 从 0.5 降到 0.1 nat, 单 token 正确率从 0.607 升到 0.905, 编辑距离从 1.97 降到 0.48, 平滑变化; 精确匹配准确率从 $0.607^5=0.082$ 升到 $0.905^5=0.607$, 在对数横轴上看就是一段陡升. 前面更小的模型 loss 在 1.0 以上时, 精确匹配约 $e^{-5}=0.007$, 测试集只有几百题时这个数被测成 0, 看起来「完全不会」. 论文把这第二个原因称为分辨率不足: 准确率的最小可测间隔是 $1/$ 测试集大小.

论文用三组证据检验这个解释:

1. **InstructGPT/GPT-3 的算术**. 两位数乘法和四位数加法 (2-shot) 上, 4 位或 5 位目标用准确率时呈现涌现, 同一批输出换成 token 编辑距离后平滑提升. 增加测试题数后, 小模型的准确率也测出高于随机.
2. **BIG-Bench 元分析**. 39 个优选度量里至多 5 个出现涌现; 人工标注的涌现案例只出现在 4 个度量下, 其中超过 92% 来自多选得分 (Multiple Choice Grade, 概率最高的选项正确记 1, 否则记 0) 和精确匹配. 前者不连续, 后者非线性. LaMDA 在多选得分下的涌现, 换成连续的 Brier 分数后消失.
3. **视觉任务上人为制造涌现**. 浅层自编码器重建 CIFAR100 的 MSE 平滑下降, 定义「重建误差低于阈值 $c$ 的比例」后出现突变.

这篇论文的结论有自己的边界. 式 (11) 的独立性假设不成立, 作者也写明这只是定性近似; 论文明确说不排除大模型存在真正的涌现, 只是已报道的那批案例可以由度量选择解释. 对预训练评估, 它给出一条可操作的规则: 想在早期 checkpoint 上看到连续信号, 用连续度量 (正确答案的对数概率, Brier 分数, token 编辑距离) 或加大测试集; 想看最终能力, 才用精确匹配或多选得分.

GPT-4 技术报告里有一个同方向的做法. 用小模型预测 HumanEval 通过率时, 拟合的不是通过率本身, 而是题目子集 $P$ 上的平均对数通过率:

$$
-\mathbb{E}_{P}\bigl[\log \mathrm{pass\_rate}(C)\bigr]=\alpha\,C^{-k} \tag{13}
$$

$C$ 是训练算力, $\alpha, k$ 为正常数. 报告把除最难 15 题以外的题目按小模型表现分成 6 个难度桶, 只保留在大采样预算下每个模型都至少做对一次的题, 用算力至多为 GPT-4 千分之一的模型拟合, 在训练完成前登记了预测; 图中展示的第 3 易的桶预测准确. 取对数让接近 0 的通过率也有可拟合的变化, 限定「至少做对一次」则是因为通过率为 0 时对数无定义.

### 4.3 loss 相同, 下游可以不同

跨模型线性 (5.1) 和单模型平滑 (5.2) 都有反例. The Pile 论文训练了三个结构相同的 1.3B 模型, 只换训练数据; 三份数据都按 13-gram 对评测集去污, 并下采样到约 40GB. Table 3:

| 训练数据 | Pile 验证 BPB | WikiText PPL | LAMBADA PPL | LAMBADA 准确率 |
|---|---|---|---|---|
| The Pile | 0.9281 | 5.59 | 12.78 | 50.1 |
| CC-100 (en) | 1.3143 | 8.27 | 11.78 | 49.7 |
| Raw CC | 1.1180 | 11.75 | 19.84 | 43.8 |

Raw CC 在 Pile 的 BPB 上优于 CC-100 (1.1180 对 1.3143), 在 WikiText 和 LAMBADA 上却明显落后. 论文推测 CC-100 用维基训出的语言模型按 PPL 过滤数据, 去掉了和维基太像或太不像的文本, 多样性受损; 这让它在维基类评测上占优, 在 Pile 的多领域文本上吃亏. 同一张表里, WikiText PPL 的排序 (Pile < CC-100 < Raw CC) 和 Pile BPB 的排序 (Pile < Raw CC < CC-100) 不一致. 换句话说, 「在哪份语料上测 PPL」决定了 PPL 衡量的是哪种能力, 拿 A 分布的 PPL 预测 B 分布的下游分数, 只在两者相近时成立.

另一种脱钩来自题目格式. OLMES (Gu 等人 2024) 画出 OLMo-7B-0424 训练过程中 MMLU 的两种分数: 完形填空格式从早期就有信号, 「A/B/C/D」多选格式在约 400B token 之前停在随机水平, 之后才开始上升. 这段时间里 loss 一直平滑下降, 多选格式的突变来自模型学会了「用字母作答」这一格式, 不是知识突然增加. 细节见 [3.4.2](../3.4.2-通用基准/3.4.2-通用基准.md) 第 4 节.

### 4.4 泄漏让 PPL 虚低

测试文本若出现在训练集中, 模型对它的 PPL 会远低于同分布的新文本. Chinchilla 论文报 WikiText-103 上 Chinchilla PPL 7.16, Gopher 7.75, 同时提醒 Chinchilla 训练数据是 Gopher 的 4 倍, 训练/测试泄漏可能人为改善了结果, 因此更看重其他任务. Huang 等人选最新语料, 也是为了绕开这个问题; 他们在 4.1 节用的 Min-K% Prob 就是利用「见过的文本 PPL 异常低」来反查泄漏.

泄漏检测的通用方法 (n-gram 重叠, 改写样本, Min-K% Prob) 在 [3.4.2](../3.4.2-通用基准/3.4.2-通用基准.md) 第 6 节.

## 5. 训练中怎么用, 以及边界

### 5.1 留出集, 单位与协议

把前几节落到训练监控上, 留出集的设计和读法如下.

**留出集怎么建.** 从训练配比的每个来源各留一份, 与训练集按文档级去重; 再加一两份训练截止日期之后的新语料 (新闻, 新代码仓库, 新论文), 用来估计泄漏和分布漂移. 每份固定下来, 整个训练过程不换. 按 Huang 等人的饱和曲线, 每份几百万字符已经够用; 按 Chinchilla 的 Table A5, 子集之间 BPB 可以差 3 倍, 所以要按子集分别画曲线, 不只画加权平均.

**单位怎么选.** 只在一个模型内部看进度, token 级 loss 即可, 用式 (4) 读相对变化. 要和别的模型, 别的 tokenizer, 或换过词表的自家模型比, 用式 (6) 的 BPB. 中英混合语料按语言分开报, 避开 2.1 节说的 BPC 与 BPB 三倍差.

**协议怎么固定.** 窗口长度, 步长, 文档是否拼接, 是否加 BOS token, 全部写进评测配置, 换模型时不变. 比较不同训练窗口的模型时, 统一截断到较短的那个窗口.

### 5.2 怎么读曲线

曲线出现异常时, 先按下表定位原因, 再去看对应的日志或指标:

| 现象 | 可能原因 | 去看什么 |
|---|---|---|
| 训练 loss 降, 留出 BPB 不降 | 过拟合重复数据, 或配比与留出集偏离 | 按来源拆开的 BPB |
| 某一子集 BPB 突然升 | 该来源数据在配比里被调低, 或数据出错 | 数据加载日志, 配比表 |
| 截止日期后的新语料 BPB 明显高于旧语料 | 旧语料有泄漏, 或时间漂移 | 与训练集的重叠率 |
| BPB 平滑降, 某基准停在随机 | 度量非线性或格式未习得 | 正确答案对数概率, 完形填空格式分数 |
| 两模型 BPB 相同, 下游差几分 | 评测语料与下游分布不一致; 题目格式; 噪声 | 换对口语料; 看 3.4.2 的协议 |

**连续代理.** 对早期 checkpoint, 下游分数用正确选项的对数概率或归一化概率代替 0/1 准确率 (4.2 节), 曲线噪声小, 也不会被测试集大小截成 0. 到训练后期, 再切回各基准的标准度量.

### 5.3 边界

PPL 能判断什么, 不能判断什么, 取决于前面几节的条件是否成立:

| 想知道的事 | 用 PPL 能否判断 | 原因 |
|---|---|---|
| 同一模型, 训练是否还在进步 | 能 | 固定协议下, 式 (4) 直接读 |
| 不同 tokenizer 的模型谁建模更好 | 用 BPB/BPC 能 | 式 (6)(7) 消掉 tokenizer |
| 基座模型的综合能力排序 | 条件成立时近似能 | 4.1 节的四个前提 |
| 某个具体基准的分数 | 不能直接给出 | 度量非线性, 格式, 分布差异 |
| 长上下文是否真的可用 | 不能 | 长文档 PPL 主要由局部上下文决定, 见 [3.4.3](../3.4.3-大海捞针测试/3.4.3-大海捞针测试.md) |
| 后训练模型的对话质量 | 不能 | 后训练模型不再对任意文本建模 |
| 测试集是否泄漏 | 只能提示 | PPL 异常低是信号, 确认要靠重叠检测 |

PPL 衡量的是模型给一份固定文本的概率. 这份文本选什么, 怎么切, 用什么单位, 决定了这个数在衡量什么. 下一篇 [3.4.2](../3.4.2-通用基准/3.4.2-通用基准.md) 讲把能力切成题目之后, 题目格式和打分方式又引入了哪些变量.
