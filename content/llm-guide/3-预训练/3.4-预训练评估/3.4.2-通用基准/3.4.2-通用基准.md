# 3.4.2 通用基准: 题目, 打分方式与评测协议

> 相关阅读: [3.4 预训练评估](../3.4-预训练评估.md) · [3.4.1 困惑度](../3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md) · [3.4.4 特定能力评估](../3.4.4-特定能力评估/3.4.4-特定能力评估.md) · [3.1 预训练数据](../../3.1-预训练数据/3.1-预训练数据.md)

## 1. 问题与六个常用基准

### 1.1 一个分数背后有多少选择

「模型 X 的 MMLU 是 64 分」这句话至少省略了五个选择: 给几个示例 (0-shot 还是 5-shot), 题目怎么排版 (有没有学科说明, 选项前有没有空格), 怎么判对 (看字母概率, 看选项文本概率, 还是让模型生成后解析), 概率怎么归一化 (按 token 数, 按字符数, 还是除以无条件概率), 57 个学科怎么平均 (按题数加权还是按学科等权). lm-evaluation-harness 的维护者把根源归结为他们所说的「核心问题」(Key Problem): 同一个意思有很多种写法, 而判断两句话是否等价的最好工具, 恰恰是我们要评的语言模型. 应对办法只有三类: 把开放问题改成能机械判对的封闭问题 (多选, 格式约束, 单测), 用模型打分, 用人打分. 预训练评估主要用第一类.

预训练阶段对基准还有两个额外要求. 一是要在训练过程中反复跑, 成本要低; 二是要在小模型, 早期 checkpoint 上就有区分度, 否则无法用来做数据和配比消融. 这两个要求和「最终能力排行」的要求不同, 后者更关心难度和天花板.

本文先介绍六个常用基准各自怎么构造 (第 1.2 到 1.7 节), 再讲三类打分方式和 pass@k (第 2 节), 然后讲格式敏感性 (第 3 节), 早期 checkpoint 用什么基准 (第 4 节), 污染 (第 5 节), 最后是评测框架和复现清单 (第 6.1 节).

### 1.2 MMLU

Hendrycks 等人 (2021) 收集了 57 个学科的四选一题目, 覆盖初等数学, 美国历史, 计算机科学, 法律等, 难度从小学到专业水平. 题目由研究生和本科生从网上免费资源手工收集, 包括 GRE 和美国医师执照考试 (USMLE) 的练习题, 本科课程习题等. 共 15908 题, 每个学科取 5 题作为少样本开发集, 验证集 1540 题, 测试集 14079 题, 每个学科至少 100 道测试题.

原论文给出的参照: Mechanical Turk 上的非专业人员 34.5%, 估计的专家水平 89.8%; GPT-3 175B 5-shot 43.9%, 小一些的 GPT-3 接近随机的 25%. 学科间差得很远: GPT-3 在美国外交政策上 69%, 大学化学上 26%. 原论文的提示以「The following are multiple choice questions (with answers) about [学科].」开头, 以「Answer:」结尾, 取 A, B, C, D 四个 token 中概率最高的作为预测. 也就是说, MMLU 原始协议就是第 2 节的 MCF.

### 1.3 HellaSwag 与 ARC

Zellers 等人 (2019) 给出一段情境描述, 让模型从四个结尾里选最合理的一个. 错误结尾由语言模型生成, 再用对抗过滤 (Adversarial Filtering) 筛选: 反复训练判别器 (BERT-Large), 把判别器能识破的生成结尾换掉, 留下判别器难以区分的. 情境来自 ActivityNet 视频描述和 WikiHow 文章, 共 7 万题. 发布时人类准确率 95.6%, 当时最好的模型不到 48%. 这个基准当时难, 是因为错误选项专门挑了让 BERT 困惑的. 判别器换成更强的模型后, 这种难度不再成立; GPT-4 技术报告里 10-shot 已到 95.3%, 与人类相当.

**ARC.** Clark 等人 (2018) 收集了 7787 道真实的中小学 (grade-school) 科学考试选择题, 绝大多数是四选一. Challenge 集 2590 题, 定义为检索方法 (IR solver) 和词共现方法 (PMI solver) 都答错的题; 其余 5197 题为 Easy 集. 论文同时发布了 1400 万句的科学语料 ARC Corpus. harness 论文提到 ARC 里有一道题有 5 个选项, 实现时若默认四选一会出错.

### 1.4 GSM8K

Cobbe 等人 (2021) 雇人写了 8.5K 道小学数学应用题, 训练集 7.5K, 测试集 1K, 每题需要 2 到 8 步基本运算. 答案是一个数, 解答以自然语言写出中间步骤. 这一设计让评测从选项打分变成生成: 模型写出推理过程, 最后抽取数值和标准答案比较.

论文的主要方法是训练验证器 (verifier) 给多个候选解打分, 再选最高分的. 两个与评测有关的结果: 去掉训练数据中的中间步骤直接学答案, 6B 模型的测试准确率从 20.6% 降到 5.2%; 验证器的收益在每题采 400 个候选时最高, 再多反而下降, 因为出现了骗过验证器的错误解. 这两个现象在 [3.4.4](../3.4.4-特定能力评估/3.4.4-特定能力评估.md) 讨论数学评估还会用到.

### 1.5 HumanEval

Chen 等人 (2021) 的 Codex 论文手写了 164 道 Python 编程题, 每题给函数签名, docstring 和函数体之前的内容, 模型补全函数体, 平均每题 7.7 个单元测试. 判对的标准是全部单测通过, 这称为功能正确性 (functional correctness). 论文选择手写, 是因为 GitHub 上已有的题解很可能出现在训练数据里.

这篇论文同时说明了 BLEU 这类文本重叠度量不能用于代码: 在 HumanEval 上, 正确解和错误解的 BLEU 分布大量重叠. 打分细节 (pass@k) 在 2.4 节.

### 1.6 BBH

Suzgun 等人 (2022) 从 BIG-Bench 中挑出 23 个具有挑战性的任务 (BIG-Bench Hard, BBH), 标准是当时已报告的模型都不如人类评分者的平均水平. 23 个任务含 27 个子任务, 多数每个子任务 250 题, 只有 Causal Judgement 187 题, Penguins in a Table 146 题, Snarks 178 题, 共 6511 题. 每个任务配 3 个手写的 CoT 示例.

结果: 加 CoT 后, PaLM 540B 在 23 个任务中的 10 个超过人类平均水平, Codex (code-davinci-002) 在 17 个上超过. BBH 的用途和前五个不同: 它衡量的是多步推理在 CoT 提示下能否展开, 对基座模型和 prompt 都更敏感.

### 1.7 六个基准汇总

| 基准 | 规模 | 格式 | 常用打分 | 常见示例数 (GPT-4 报告) |
|---|---|---|---|---|
| MMLU | 测试 14079 题, 57 学科 | 四选一 | MCF 字母概率 | 5-shot |
| HellaSwag | 7 万题 | 四选一续写 | CF, 长度归一化 | 10-shot |
| ARC-C | 2590 题 | 多为四选一 | CF 或 MCF | 25-shot |
| GSM8K | 测试 1K 题 | 自由生成数值 | 抽取后精确匹配 | 5-shot CoT |
| HumanEval | 164 题 | 生成函数体 | 单测 pass@k | 0-shot |
| BBH | 6511 题, 23 任务 | 生成 | 抽取后精确匹配 | 3-shot CoT |

最后一列取自 GPT-4 技术报告 Table 2 的设置 (MMLU 86.4, HellaSwag 95.3, ARC 96.3, GSM-8K 92.0, HumanEval 67.0). 同一张表里每个基准的示例数都不同, 这些设置不是基准自带的, 是报告方自选的. 另外 GPT-4 报告附录 E 说明训练混入了 GSM8K 和 MATH 的训练集, 建议把 GSM-8K 的 92.0 理解为介于少样本迁移和针对性微调之间.

## 2. 打分方式

### 2.1 完形填空式 (CF)

把题干 $q$ 作为上下文, 依次计算每个选项文本 $a_i$ 的对数似然, 选最大的:

$$
\hat{i}=\arg\max_{i}\ s(a_i),\qquad s(a_i)=\ln P(a_i\mid q)=\sum_{j=1}^{|a_i|}\ln P(a_{i,j}\mid q, a_{i,<j}) \tag{1}
$$

$a_{i,j}$ 是选项 $a_i$ 的第 $j$ 个 token. 式 (1) 的问题是长选项天然吃亏: 每多一个 token 就多乘一个小于 1 的概率. OLMES (Gu 等人 2024) 整理了四种归一化:

$$
s_{\text{none}}=\ln P(a_i\mid q),\qquad s_{\text{token}}=\frac{\ln P(a_i\mid q)}{\mathrm{num\_tokens}(a_i)} \tag{2}
$$

$$
s_{\text{char}}=\frac{\ln P(a_i\mid q)}{\mathrm{num\_chars}(a_i)},\qquad s_{\text{pmi}}=\ln\frac{P(a_i\mid q)}{P(a_i\mid u)} \tag{3}
$$

按 token 数归一化来自 GPT-3 论文; 按字符数归一化是 Llama 和 lm-evaluation-harness 的做法, 好处是与 tokenizer 无关; pmi 中 $u$ 是无条件提示「Answer:」, 分母是不看题干时模型给这个选项的概率, 用来扣除选项本身的先验. OLMES 为每个任务指定了一种: ARC-Challenge, CommonsenseQA, OpenbookQA 用 pmi, 理由是这些任务的选项常含模型不太会生成的词 (论文举的例子是「Whirlpool bath」对「Bathtub」); ARC-Easy, HellaSwag, PIQA, SIQA, MMLU 用 char; BoolQ, WinoGrande 用 none.

手算一个例子 (概率为示意). 题干问「浴缸叫什么」, 两个选项: A 为 1 个 token, $\ln P=-2.0$; B 为 4 个 token, 每个 token 的条件对数概率 $-0.6$, 合计 $-2.4$. 不归一化选 A; 按 token 归一化, A 为 $-2.0$, B 为 $-0.6$, 选 B. 同一个模型, 只换归一化就换了答案. 若再知道无条件下 $\ln P(A\mid u)=-1.0$, $\ln P(B\mid u)=-5.0$, pmi 分数 A 为 $-1.0$, B 为 $+2.6$, 也选 B: A 的高似然多半来自它本身就常见.

### 2.2 多选字母式 (MCF)

把选项连同字母一起放进提示, 末尾是「Answer:」, 只比较下一个 token 是 A, B, C, D 的概率:

$$
\hat{i}=\arg\max_{i\in\{A,B,C,D\}}\ \ln P(\ell_i\mid q, a_A,\dots,a_D) \tag{4}
$$

$\ell_i$ 是字母 token. 式 (4) 每题只要一次前向, 不受选项长度影响, 模型能同时看到所有选项并比较. 代价是模型必须先学会「看选项, 用字母作答」这一格式. OLMES 还发现一个 tokenizer 层面的细节: 选项写成 `"\n A. <选项>"` (字母前有空格) 才能让 Llama 等 tokenizer 下选项里的字母和答案处的字母是同一个 token (「_A」). 第 3 节会看到这个格式要求在小模型上有多大影响.

### 2.3 生成后抽取

GSM8K, BBH, MATH 这类题没有选项, 只能让模型生成, 再按规则抽答案:

1. 解码通常用 greedy, 或者固定温度采多个样本后投票;
2. 设定停止条件 (遇到下一个「Question:」或最大长度);
3. 从输出中抽取答案 (例如最后一个数字, 或「The answer is」后面的部分);
4. 归一化 (去逗号, 单位, 美元符号, 小数末尾的 0), 再与标准答案比较.

第 3, 4 步完全由评测代码决定. 模型答对了但格式不符合正则, 记为错. 这是生成式打分特有的误差源, 在数学题上尤其明显, 见 [3.4.4](../3.4.4-特定能力评估/3.4.4-特定能力评估.md) 第 2 节.

### 2.4 pass@k 与无偏估计

代码题可以执行, 「对不对」由单测判定, 但一次采样的结果有随机性. Kulal 等人 (2019) 定义 pass@k: 每题采 $k$ 个样本, 任一个通过全部单测就算解出, 报告解出题目的比例. 直接按定义估计方差大. Codex 论文的做法是每题采 $n\ge k$ 个样本, 数出其中通过的个数 $c$, 用下式估计:

$$
\text{pass@}k=\mathbb{E}_{\text{题目}}\left[1-\frac{\binom{n-c}{k}}{\binom{n}{k}}\right] \tag{5}
$$

推导: 从 $n$ 个样本中不放回地取 $k$ 个, 全部失败的概率是从 $n-c$ 个失败样本中取 $k$ 个的组合数除以总组合数. 1 减去它, 就是「至少一个通过」的概率. 对一道题, 这个量是 pass@k 的无偏估计. 论文中 $n=200$, $k\le 100$.

大组合数直接算会溢出. 把比值展开成连乘:

$$
\frac{\binom{n-c}{k}}{\binom{n}{k}}=\prod_{i=n-c+1}^{n}\left(1-\frac{k}{i}\right) \tag{6}
$$

论文给出的 numpy 实现就是式 (6):

```python
def pass_at_k(n, c, k):
    if n - c < k:
        return 1.0
    return 1.0 - np.prod(1.0 - k / np.arange(n - c + 1, n + 1))
```

$n-c<k$ 时, 任取 $k$ 个必然含一个通过的样本, 直接返回 1.

**手算.** $n=10$, $c=3$. pass@1 $=1-\binom{7}{1}/\binom{10}{1}=0.3$, 就是通过比例. pass@5: $\binom{7}{5}/\binom{10}{5}=21/252=0.0833$, 所以 pass@5 $=0.917$. 用式 (6) 验算: $i=8,9,10$ 时 $(1-5/8)(1-5/9)(1-5/10)=\frac{3}{8}\cdot\frac{4}{9}\cdot\frac{1}{2}=0.0833$, 一致.

**为什么不用 $1-(1-\hat p)^k$.** 一种直观做法是先估单样本通过率 $\hat p=c/n$, 再假设 $k$ 次独立: 上例给出 $1-0.7^5=0.832$, 比 0.917 低. 这个方向是确定的: $f(x)=(1-x)^k$ 是凸函数, 由 Jensen 不等式 $\mathbb{E}[(1-\hat p)^k]\ge(1-p)^k$, 所以 $\mathbb{E}[1-(1-\hat p)^k]\le 1-(1-p)^k$, 系统性低估. Codex 论文附录 A 讨论了这一偏差.

**温度.** pass@k 的 $k$ 越大, 越需要样本多样. Codex 论文在 679M 模型上扫温度, pass@1 的最优温度是 0.2, pass@100 是 0.8. 所以报 pass@1 和 pass@100 时, 两者通常来自不同温度的采样.

Codex 论文 Table 1 节选 (HumanEval, %):

| 模型 | pass@1 | pass@10 | pass@100 |
|---|---|---|---|
| GPT-Neo 2.7B | 6.41 | 11.27 | 21.37 |
| GPT-J 6B | 11.62 | 15.74 | 27.74 |
| TabNine | 2.58 | 4.35 | 7.59 |
| Codex-300M | 13.17 | 20.37 | 36.27 |
| Codex-12B | 28.81 | 46.81 | 72.31 |

pass@1 和 pass@100 之间的差距说明, 「采很多次总有一次对」和「第一次就对」是两种能力. 论文还比较了从 100 个样本中选一个提交的策略: 选平均 token 对数概率最高的, 效果好于随机选; 用单测选 (相当于 oracle) 则等于 pass@100. 测试用例有限时 pass@k 会高估, 这是 [3.4.4](../3.4.4-特定能力评估/3.4.4-特定能力评估.md) 讲 HumanEval+ 的出发点.

## 3. few-shot 与格式敏感性

### 3.1 同一个模型, 换提示格式

lm-evaluation-harness 论文 (Biderman 等人 2024) Table 1 用 0-shot 比较两种常见提示风格 (±后为论文报告的误差范围):

| 模型 | ARC-C, Cloze | ARC-C, MMLU 风格 | MMLU, Hybrid | MMLU, MMLU 风格 |
|---|---|---|---|---|
| GPT-NeoX-20B | 38.0 ± 2.78 | 26.6 ± 2.53 | 27.6 ± 0.74 | 24.5 ± 0.71 |
| Llama-2-7B | 43.5 ± 2.84 | 42.8 ± 2.83 | 39.8 ± 0.79 | 41.3 ± 0.80 |
| Falcon-7B | 40.2 ± 2.81 | 25.9 ± 2.51 | 29.1 ± 0.75 | 25.4 ± 0.72 |
| Mistral-7B | 50.1 ± 2.86 | 72.4 ± 2.56 | 48.3 ± 0.80 | 58.6 ± 0.77 |
| Mixtral-8x7B | 56.7 ± 2.84 | 81.3 ± 2.23 | 59.7 ± 0.77 | 67.1 ± 0.72 |

Cloze 即 2.1 节的 CF, MMLU 风格即 2.2 节的 MCF. 三点:

1. 差距可以超过 20 个点 (Mistral-7B 在 ARC-C 上 50.1 对 72.4).
2. 方向因模型而异: GPT-NeoX-20B 和 Falcon-7B 在 MCF 下接近随机 (25%), CF 下好得多; Mistral 和 Mixtral 相反.
3. 排名会变: CF 下 Falcon-7B (40.2) 低于 Llama-2-7B (43.5) 但差距不大, MCF 下 Falcon 掉到 25.9, 差距拉到 17 个点.

Sclar 等人 (2023) 把这个问题推到更细的粒度: 只改分隔符, 大小写, 空格这类不改语义的格式, 在 LLaMA-2-13B 上同一任务的少样本准确率最多相差 76 个点. 他们提出 FormatSpread, 在一组合理格式上采样, 报告准确率的区间, 而不是单一格式下的点估计; 并发现一个格式在某个模型上好, 换个模型不一定好, 格式效果在模型间只弱相关.

### 3.2 MCF 是一种要学的能力

OLMES 在 15 个 1B 到 70B 的模型上同时跑 MCF 和 CF. 能力强的模型在 MCF 下大幅领先: Llama-3 70B 的 ARC-C, MCF 93.7, CF 69.0, 错误率差约 5 倍. Llama-3 8B 在 25-shot 下 MCF 78.6, CF 60.2. 最弱的 8 个模型在 MCF 下接近随机.

论文 Figure 1 画的是 OLMo-7B-0424 训练过程中 MMLU 验证集的分数: 早期 CF 有信号, MCF 停在随机; 约 400B token 时模型开始学会 MCF, 之后 MCF 的信号超过 CF. 这条曲线说明, 在 400B token 之前用 MMLU 原始协议 (MCF) 评估, 得到的是一条平线, 数据和配比的差异在上面看不出来. [3.4.1](../3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md) 第 4.2 节从度量非线性的角度解释了类似现象.

OLMES 的处理是每个模型两种格式都跑, 每个任务取较高的那个. 其他规定: 统一用「Question: ... Answer:」格式; 有公开标签的用测试集, 否则用验证集; 多于 1500 条的数据集用 `Random(1234).sample(all_instances, 1000)` 抽 1000 条; 每个任务用手工挑选的固定 5-shot, 并让 5 个示例的答案在选项间分布均衡 (避免 4 个 A 1 个 B); 输入连同补全限制在 2048 token 内.

### 3.3 聚合方式

MMLU 有 57 个学科, 每个学科题数不同. 按题平均 (micro) 和按学科平均 (macro) 的结果不同. harness 论文说明官方 MMLU 评测脚本用的是 micro, 并称这一选择能让结果差几个百分点, 而且报告里很少写明. OLMES 选 macro (跟随 Llama 3), 但在附录 Table 8 的对比中称两者在实践中一般差别不大. 两篇的结论在幅度上不一致, 对报告者的要求是一致的: 写明用的是哪种.

harness 论文还提到 Fourrier 等人 (2023) 对比了 MMLU 的三个实现 (HELM, lm-eval, 原始 MMLU 代码), 同一批模型得到的分数差异很大, 连排名顺序都变了.

### 3.4 误差范围

准确率是 $n$ 道题上伯努利变量的均值, 标准误为

$$
\mathrm{SE}=\sqrt{\frac{p(1-p)}{n}} \tag{7}
$$

$p=0.5$ 时: HumanEval ($n=164$) 的标准误约 3.9 个点, 1000 题约 1.6 个点, MMLU 测试集 ($n=14079$) 约 0.42 个点. 所以 HumanEval 上 2 到 3 个点的差距在一个标准误以内, 不能据此排序. 题目之间难度不一, 式 (7) 只是量级估计; harness 默认用 bootstrap 估计标准误并随分数一起报告.

## 4. 预训练早期用什么基准

### 4.1 早期基准要满足的条件: DCLM 的 Core 指标

数据消融通常在小模型上做: 训一个 400M 或 1B 的模型, 比较不同数据方案的下游分数, 再把胜出的方案用到大模型上. 这要求基准满足两个条件: 小模型上不在随机水平 (有信号); 小模型上的排序与大模型一致 (信号可迁移). MMLU 的 MCF 在 400B token 以前不满足第一条.

DataComp-LM (DCLM, Li 等人 2024) 是一个数据集构建的基准: 提供 240T token 的 Common Crawl 候选池, 固定训练代码和各规模的超参数, 参与者只改数据, 最后在 53 个下游任务上评估. 为了在小规模上有稳定的信号, DCLM 定义了 Core 指标: 从 53 个任务中选出 22 个在小规模上方差也低的任务 (如 HellaSwag, ARC-E), 对每个任务做线性缩放, 再取平均:

$$
\mathrm{centered}=\frac{\mathrm{acc}-\mathrm{acc}_{\text{random}}}{1-\mathrm{acc}_{\text{random}}} \tag{8}
$$

$\mathrm{acc}_{\text{random}}$ 是随机猜的准确率 (四选一为 0.25). 式 (8) 让 0 对应随机, 1 对应全对, 不同选项数的任务可以直接平均. 例如四选一任务上准确率 0.40, 中心化后为 $(0.40-0.25)/0.75=0.20$; 二选一任务上准确率 0.60, 中心化后也是 0.20. 不做这一步, 二选一任务的 0.60 和四选一任务的 0.40 放在一起平均会被前者主导. 此外 DCLM 也报 MMLU 5-shot 和 53 个任务的 Extended 平均.

DCLM 规定了从 400M-1x 到 7B-2x 的几档规模, 训练 token 数为参数量 × 20 × 倍数 (1x 即 Chinchilla 最优配比). 10 种数据方案在 400M-1x, 1B-1x, 3B-1x 上的得分与在 7B-1x 上的得分, Pearson 相关分别为 0.838, 0.956, 0.982. 也就是说, 在 Core 这类指标上, 小规模消融的结论能迁移到 7B, 规模越接近迁移越好. 用这套流程选出的数据 (fastText 质量分类器取前 10%) 训出的 7B 模型, 2.6T token 下 MMLU 5-shot 达到 64%.

### 4.2 选基准的原则

把有没有信号, 信号能不能迁移这两个条件, 和各阶段的目的放在一起, 可以得到下表:

| 阶段 | 目的 | 合适的基准与格式 | 不合适 |
|---|---|---|---|
| 小模型数据消融 | 方案排序 | Core 类低方差任务, CF 格式, 中心化准确率 | MCF 格式的 MMLU, 高难度生成题 |
| 主训练过程监控 | 看趋势, 早发现问题 | 分领域 BPB ([3.4.1](../3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md)), CF 格式的常识题, 正确答案对数概率 | 单次 greedy 的 GSM8K (噪声大) |
| 训练后期与发布 | 最终能力 | MCF 与 CF 取高, 生成式数学与代码, 长上下文 | 已饱和的 HellaSwag 作为主要区分依据 |

## 5. 数据污染

### 5.1 定义, 检测与改写绕过

如果测试题 (或其答案) 出现在预训练数据中, 分数衡量的就有一部分是记忆. 常见检测方法按「怎么判断一道题出现过」区分:

| 方法 | 判定规则 | 来源 |
|---|---|---|
| 13-gram 重叠 | 测试样本与训练文档有长度 13 的 token 序列重合 | GPT-3 论文 |
| 50 字符子串 | 去掉空格和符号后, 从测试样本随机取 3 段 50 字符子串, 任一段在训练数据中出现即判为污染 | GPT-4 技术报告附录 C |
| 嵌入近邻 + LLM 判别 | 用嵌入检索每道测试题在训练集中的 top-k 近邻, 再让强模型判断是否为改写 | Yang 等人 2023 |
| Min-K% Prob | 样本中概率最低的 k% token 的平均负对数似然异常低 | Shi 等人 2024, 见 [3.4.1](../3.4.1-困惑度-PPL/3.4.1-困惑度-PPL.md) 第 4.1 节 |

GPT-4 技术报告 Table 11 用第二种方法估计了预训练数据对各基准的污染 (除 HumanEval 外, 每个基准随机抽 1000 题): MMLU 约 0.6%, GSM-8K 约 1%, AI2 (ARC) 约 3.4%, WinoGrande 约 0.9%, DROP 约 21%, HumanEval 25%. 在 HumanEval 未污染的子集上 GPT-4 (基座, 无 RLHF) 得 65.58%, 相对全集 67.0% 下降 2.12%. HellaSwag 用的是私有留出集, 没有做污染检查, 报告称留出集结果与训练时明确屏蔽的验证集 (95.6%) 接近.

Yang 等人 (2023) 的论文 *Rethinking Benchmark and Contamination for Language Models with Rephrased Samples* 说明前两种方法都可以被绕过: 用 LLM 把测试题改写或翻译成另一种语言后放进训练集, 13-gram 和 50 字符子串都匹配不上. 他们在改写过的 MMLU 测试题上微调 Llama-2-13B, MMLU 达到 85.9, 与 GPT-4 相当, 且 n-gram 检测查不出来. 他们用第三种方法 (嵌入检索 + GPT-4 判别) 在真实数据集中发现: RedPajama-Data-1T 和 StarCoder-Data 中有 8% 到 18% 的 HumanEval 题目的改写版本; 合成数据集 CodeAlpaca 中有 12.8% 是 HumanEval 的改写. 后者说明污染也会经由 LLM 生成的合成数据进入训练集.

### 5.2 应对

没有一种做法能单独解决污染, 每种做法都只挡住一部分来源:

| 做法 | 能解决什么 | 局限 |
|---|---|---|
| 训练前对评测集做 n-gram 去污 | 原文重复 | 改写, 翻译, 合成数据 |
| 发布污染率并报告未污染子集分数 | 让读者判断影响 | 依赖检测方法的召回率 |
| 私有留出集 (如 GPT-4 的 HellaSwag) | 题目不外泄 | 外部无法复现 |
| 按发布时间切分的动态基准 (如 LiveCodeBench) | 模型截止日期之后的题不可能被训练 | 题量有限, 需持续更新, 见 [3.4.4](../3.4.4-特定能力评估/3.4.4-特定能力评估.md) |
| 换用压缩率在新语料上评估 | 新语料不在训练集中 | 只评通用建模, 不评具体任务 |

## 6. 评测框架, 复现清单与边界

### 6.1 评测框架与复现清单

lm-evaluation-harness (EleutherAI) 把任务定义 (数据集, 提示模板, 打分方式, 归一化, 聚合) 写成配置文件, 同一份配置可以对接不同的模型后端. 它的论文附录 D 把经验归纳成一份清单: 公开确切的提示; 不要照搬其他实现得出的结果; 公开模型输出; 做定性分析; 做统计显著性检验. 论文列出的几个容易出错的细节都已在前文出现: ARC 中一道五选一题, MMLU 的 micro 与 macro, HumanEval 中 3 道题缺少其他题都有的示例测试, 超长序列 PPL 的不重叠窗口偏向长上下文模型.

把本文各节合起来, 报一个基准分数时要附上:

| 项 | 例子 |
|---|---|
| 数据划分与题数 | MMLU test 14079 题; 是否抽样 |
| 示例数与示例来源 | 5-shot, 固定示例或随机抽取 (种子) |
| 提示格式 | 有无学科说明, 选项排版, 「Answer:」 |
| 打分方式 | CF / MCF / 生成; CF 的归一化 |
| 解码与抽取 (生成任务) | greedy 或温度; 停止条件; 抽取正则; 归一化规则 |
| pass@k (代码) | $n$, $k$, 温度, 是否用式 (5) |
| 聚合 | micro / macro |
| 误差 | 标准误或 bootstrap 区间 |
| 污染 | 检测方法与污染率 |

### 6.2 边界

| 情况 | 基准分数的问题 | 应对 |
|---|---|---|
| 小模型或早期 checkpoint | MCF 停在随机, 生成题接近 0 | CF 格式, 中心化准确率, BPB |
| 跨论文比较 | 格式, 示例, 实现不同, 差距可超 20 个点 | 同一框架同一配置重跑 |
| 基准饱和 (HellaSwag 95%) | 区分度不足 | 换更难的基准, 不以它为主要依据 |
| 题量小 (HumanEval 164 题) | 标准误约 4 个点 | 报误差, 用扩充版本 |
| 测试集泄漏 | 分数含记忆成分 | 去污, 报未污染子集, 动态基准 |
| 训练混入了基准训练集 | 结果介于少样本和微调之间 (GPT-4 的 GSM8K) | 明确披露 |
| 多选题 | 只测识别, 不测生成 | 配合生成式基准 |

这些基准测的是知识, 常识和短推理. 长上下文检索和代码, 数学这类需要执行或专门判分的能力, 分别在 [3.4.3](../3.4.3-大海捞针测试/3.4.3-大海捞针测试.md) 和 [3.4.4](../3.4.4-特定能力评估/3.4.4-特定能力评估.md).
