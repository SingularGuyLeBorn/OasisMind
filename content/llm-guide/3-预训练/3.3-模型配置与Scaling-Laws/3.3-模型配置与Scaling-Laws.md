# 3.3 模型配置与 Scaling Laws

预训练开始前要交出一张配置表: 参数量, 训练 token 数, 层数, 宽度, 注意力头数, KV 头数, FFN 中间维, 词表, 上下文长度, 峰值学习率. 这张表分两步填. 第一步由算力预算 $C$ 定出参数量 $N$ 和 token 数 $D$, 依据是 [3.3.2 Scaling Laws](./3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md); 第二步把标量 $N$ 展开成一组形状参数, 并核算每个选择对参数量, FLOPs 和 KV cache 的影响, 这是 [3.3.1 确定模型结构与参数](./3.3.1-确定模型结构与参数/3.3.1-确定模型结构与参数.md).

两篇的编号和决策顺序相反. 3.3.1 排在前面, 因为参数与 FLOPs 的计数公式在它的第 1 节推导, 3.3.2 的 $C\approx6ND$ 直接引用这个结果; 实际定配置时先用 3.3.2 定规模, 再回 3.3.1 定形状. 块结构本身 (注意力, 位置编码, FFN 的推导) 在第 2 章, 这里只用它们的参数量和计算量.

## 1. 从算力到配置表

### 1.1 一个约束式

稠密 Transformer 每 token 前向的矩阵乘约 $2N$ FLOPs, 反向约是前向的 2 倍, 训练总计算量

$$
C\approx6ND
$$

这条式子略去了注意力打分 ($QK^\top$ 与加权求和) 的计算, 这部分不带参数, 随序列长度增长. DeepSeek LLM 指出 $6N$ 在小规模下最多偏差 50%, 改用每 token 非嵌入 FLOPs $M$ 衡量规模, 注意力项与矩阵乘项之比为 $l_{\mathrm{seq}}/(6d_{\mathrm{model}})$: $d_{\mathrm{model}}=4096$, 序列 4096 时是 $1/6$, 宽度 512 的小模型配同样的序列是 $4/3$. Scaling Laws 实验恰好从几千万参数的小模型做起, 计数口径不同, 小模型那端的拟合点就落在不同位置.

$C$ 由卡数和工期决定, 于是 $N$ 和 $D$ 此消彼长: 选大模型就只能少训练. Scaling Laws 要回答的是, 给定 $C$, loss 最低的 $(N,D)$ 在哪里. 这只能从实验拟合: 训练一批小模型, 拟合 loss 关于 $N$ 和 $D$ 的函数, 再外推到大几个数量级的目标算力. 外推是否可靠, 取决于函数形式对不对, 以及小实验的设置是否与正式训练一致.

### 1.2 第二步为什么能单独做

把 $N$ 展开成形状能单独成为一步, 前提是 loss 对形状不敏感. Kaplan 等人固定非嵌入参数量, 把宽深比 $d_{\mathrm{model}}/n_{\mathrm{layer}}$ 在 40 倍范围内变动, loss 相差在 3% 以内, 例如 6 层宽 4288 与 48 层宽 1600. 他们的结论是 loss 主要由 $N$ 决定, 形状是次要变量. 这条结论覆盖的是 1.5B 以下的非嵌入参数.

形状的取值因此交给 loss 拟合之外的约束: 层数要能被流水线段数整除, 头数要能被张量并行度整除, KV cache 要放得进推理显存, 深模型对学习率更敏感. 这些约束都不在 $L(N,D)$ 里, 3.3.1 第 2 节逐条核算. 词表大小 $V$ 介于两步之间: 它进入参数量和输出头 FLOPs, 又通过压缩率改变 $D$ 对应的文本量, 详见 [3.2](../3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md).

## 2. 最优分配的几次修正

### 2.1 Kaplan, Chinchilla 与之后的拟合

几组拟合给出的「算力增加时参数该涨多少」差别很大:

| 来源 | $N_{\mathrm{opt}}\propto C^a$ | 拟合方式 | 外推到的配置 |
|---|---|---|---|
| Kaplan 等人 (2020) | $a=0.73$ | 训练曲线 + 临界 batch, 余弦周期固定为 130B token 大参数少数据, 同期的 GPT-3 是 175B / 300B token |
| Chinchilla (2022) | 0.50 / 0.49 / 0.46 (三种方法) | 训练曲线下包络, IsoFLOP, 参数化拟合 | 约 20 token 每参数, Chinchilla 70B / 1.4T |
| DeepSeek LLM (2024) | 0.5243 (以 $M$ 计) | IsoFLOP, 改用 $M$ 计算量 | 数据质量越高, 越应把算力分给模型 |
| Llama 3 (2024) | 最优 token 数 $\propto C^{0.53}$ | IsoFLOP, $6\times10^{18}$ 到 $10^{22}$ FLOPs | 402B 参数, 16.55T token |

Kaplan 和 Chinchilla 的分歧主要来自学习率日程. Kaplan 对所有模型用同一个余弦周期 (130B token), 在 $D\ll130\mathrm{B}$ 处读出的 loss 学习率还没降下来, 是高估的, 于是小数据量的点显得更差, 拟合偏向「多给参数」. Chinchilla 让每个训练长度的余弦周期与之匹配, 并且分析用的模型大多超过 500M 参数. 按新拟合, 与 Gopher 同样的 $5.76\times10^{23}$ FLOPs 应训练约 70B 参数, 1.4T token; 由此训练的 Chinchilla 在 MMLU 上平均 67.5%, 比 280B 的 Gopher 高 7 个百分点以上.

几个指数不能直接拿来比. 它们来自不同的数据, 不同的 $N$ 口径 (Kaplan 不计嵌入, Chinchilla 计入, DeepSeek 用 $M$), 不同的学习率日程; DeepSeek LLM 还在数据集迭代的不同版本上分别拟合, 发现数据质量会改变指数. 有意义的比较是: 同一套设置下, 小实验的外推能不能命中大模型. DeepSeek LLM 外推了 1000 倍算力, Llama 3 在 ARC Challenge 上外推了 4 个数量级, 都只有小幅偏差.

### 2.2 拟合常数的精度

Chinchilla 方法 3 拟合 $\hat L(N,D)=E+A/N^\alpha+B/D^\beta$, 在 $C=6ND$ 约束下有闭式最优解 $N_{\mathrm{opt}}\propto C^{\beta/(\alpha+\beta)}$. Besiroglu 等人从原论文的图中提取 240 个数据点重新拟合, 得到 $\alpha=0.3478$, $\beta=0.3658$. 三组参数代入 Gopher 的算力, 结果相差两倍多: 正文四舍五入的 $\alpha=0.34$, $\beta=0.28$ 给出 32B; TeX 源文件里的精确值 $\beta=0.2849$ 给出原文报告的 40B; 重新拟合给出 72B, 约 18 token 每参数, 与 Chinchilla 实际采用的约 20 token 每参数和前两种方法一致.

Llama 3 的拟合碰到同样的问题. 报告给出 $N^\star(C)=AC^\alpha$, $(\alpha,A)=(0.53,0.29)$, 注意这里的 $N^\star(C)$ 是最优训练 token 数. 直接代入 $3.8\times10^{25}$ FLOPs 得到约 10.5T, 与报告的 16.55T 不符: $C$ 在 $10^{25}$ 量级时, $\alpha$ 变动 0.01 就让 $C^\alpha$ 变化约 1.8 倍. 外推几个数量级的结果对拟合常数的末位很敏感, 引用别人的拟合时, 应当直接用原文给出的预测值.

### 2.3 离开算力最优的三种情况

算力最优假设数据无限, 只计训练成本, 并且模型是稠密的. 三个假设各有人放开过. 数据受限时, Muennighoff 等人把重复数据折算成有效数据量, 拟合出 $R_D^*\approx15.4$: 重复 4 次 (5 个 epoch) 的有效比例约 90%, 15 次约 66%, 40 次只剩 37%; 混入最多 50% 的 Python 代码, 自然语言任务不下降. 这和 [3.1](../3.1-预训练数据/3.1-预训练数据.md) 的过滤阈值直接相关, 过滤越严, 唯一 token 越少, 重复遍数越多.

计入推理成本时, Sardana 等人把生命周期内的推理算力 $2ND_{\mathrm{inf}}$ 加进目标函数, 最优解偏向小模型多训练: 计划训练 13B 模型, 推理需求 2T token, 改训 7B 能省 17% 的总算力. 工业配置与此一致, Llama 3 8B 训了约 15T token, 每参数约 1900 个, 405B 每参数约 39 个, 接近 IsoFLOP 外推的比例. MoE 一侧, Clark 等人在固定 130B token 下发现专家数的收益随模型变大而减小; Krajewski 等人放开训练时长并引入粒度 $G=d_{\mathrm{ff}}/d_{\mathrm{expert}}$, 结论是 MoE 一致优于稠密模型, 最优粒度随预算增大, $G=1$ 几乎从不最优.

## 3. 形状由什么决定

### 3.1 公开配置的落点

形状的自由度在实践中被用得很窄. 3.3.1 第 2.2 节统计了公开配置的宽深比, 稠密模型集中在 80 到 156: Llama 3 三个尺寸是 128, 102.4, 130, PaLM 540B 是 156.2. 头维几乎都取 128 (Llama 3, DeepSeek LLM, Qwen3), 头数随宽度线性增长. 固定宽深比 $r$ 时宽度只随参数量的立方根增长, $d_{\mathrm{model}}=(rN/12)^{1/3}$, 参数翻 8 倍, 宽度和层数各翻 2 倍.

例外是 Qwen3-235B-A22B, 宽深比只有 43.6, 残差流宽 4096, 但注意力宽度 $n_hd_h=64\times128=8192$ 是 $d_{\mathrm{model}}$ 的 2 倍, 专家 FFN 的总宽度也远大于 $d_{\mathrm{model}}$. 这种配置下 Kaplan 的 $12n_{\mathrm{layer}}d_{\mathrm{model}}^2$ 不再成立, 参数量要逐项核算. 3.3.1 按 Qwen3 Table 2 和 HF 配置算出总参 235.0B, 激活 22.1B, 与命名一致.

### 3.2 系统与推理侧的约束

层数和头数的最终取值服从并行切分. Llama 3 405B 用 16 段流水线, 为平衡首段 (嵌入) 和末段 (输出头与 loss) 的负载, 首末两段各去掉一层, $16\times8-2=126$; 张量并行度 8, 三个尺寸的头数都是 8 的倍数, 8 个 KV 头让每个张量并行 rank 恰好持有一个. DeepSeek LLM 67B 选 95 层, 报告同样说明层数考虑了流水线切分. 这些并行方式本身在 [3.4.1](../3.4-训练过程/3.4.1-训练框架选择/3.4.1-训练框架选择.md).

推理侧的约束要在训练前定. KV 头数几乎不影响训练 loss, 但决定每 token 的 KV cache: Llama 3 70B 用 8 个 KV 头是 320 KiB, 改成 64 头 MHA 是 2.5 MiB, 128K 上下文从 40 GiB 变成 320 GiB. DeepSeek-V3 的 MLA 每层只缓存 512 维的压缩潜变量和 64 维的解耦 RoPE key, 每 token 约 68.6 KiB. MoE 的两个参数量分别对应两种成本: DeepSeek-V3 显存按 671B 总参准备, 计算按 37B 激活参数计费, 训练算力 $6N_{\mathrm{act}}D=3.29\times10^{24}$ FLOPs, 是 Llama 3 405B 的约 1/11.5; 若误用总参数计算, 会高估约 18 倍.

### 3.3 跟着形状变的超参数

峰值学习率随规模下降. Llama 3 的 8B, 70B, 405B 依次是 $3\times10^{-4}$, $1.5\times10^{-4}$, $8\times10^{-5}$, 宽度每翻一倍约减半. DeepSeek LLM 把最优学习率和 batch 也写成算力的幂律, $\eta_{\mathrm{opt}}=0.3118\,C^{-0.125}$, $B_{\mathrm{opt}}=0.2920\,C^{0.3271}$, 用正式的 7B 和 67B 配置核对, 实际取值与公式相差都在 10% 以内. 另一条路是 μP 一类参数化 (MiniCPM), 让小模型上调好的学习率直接迁移到更宽的模型.

形状也影响训练稳定性. Wortsman 等人用小模型代理大模型的不稳定性, 发现加深模型时学习率敏感度上升得比加宽更快, 所以 loss 相近的两种形状, 更深的那种要更仔细地调学习率和 warmup. 他们还发现梯度范数随规模增大而下降, AdamW 默认的 $\epsilon=10^{-8}$ 在最大规模上已与梯度均方根相当. Qwen3 加的 QK-Norm 对应的是他们复现的注意力 logit 增长. 学习率日程, batch 递增和其他稳定性设置见 [3.4.2](../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md).

## 4. 记号与读法

### 4.1 同名不同义的记号

两篇引用的论文各用自己的记号, 同一个字母常指不同的量:

| 记号 | 出处 | 含义 |
|---|---|---|
| $N$ | Kaplan 2020 | 非嵌入参数量 |
| $N$ | Chinchilla 2022 | 全部参数, 计入嵌入 |
| $M$ | DeepSeek LLM 2024 | 每 token 非嵌入 FLOPs, 含注意力项 |
| $N^\star(C)$ | Llama 3 2024 | 最优训练 token 数 |
| $N_{\mathrm{act}}$, $G$ | MoE 文献 | 每 token 激活参数; 粒度 $d_{\mathrm{ff}}/d_{\mathrm{expert}}$ |

最容易出错的是嵌入是否计入. Llama 3 8B 的嵌入加输出头占总参数的 13.1%, 70B 占 3.0%, 405B 占 1.0%, 小模型上两种口径相差一成以上, 用别人的系数前要先对齐. Kaplan 的报告还说明, 把嵌入参数算进去, 不同层数的模型落不到同一条曲线上, 这是他们选择不计嵌入的原因.

第二处是 Llama 3 的 $N^\star(C)$, 名字像参数量, 实际是 token 数. 第三处是 MoE 的扩展率 $E$ 与专家数: 细粒度时专家数为 $E\times G$, 两者不相等. 3.3.2 第 6.4 节另有一张表, 把算力最优, 推理最优, 过度训练, 训练不充分, 有效数据量几个「最优」并列.

### 4.2 读法

要估算一次训练成本, 先读 [3.3.1](./3.3.1-确定模型结构与参数/3.3.1-确定模型结构与参数.md) 第 1 节的参数与 FLOPs 计数, 第 1.4 节用 Llama 3 三个尺寸逐项核算到 8.028B, 70.548B, 405.841B; 再读 [3.3.2](./3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md) 第 2.3 节的闭式解和第 3.1 节的重新拟合, 自己代一遍 Gopher 的算力. 两篇的第 5.2 节和第 3.2 节分别从配置和规模两侧讲同一个 Llama 3 405B 的定配置过程, 可以对照着读.

关心 MoE 的读者读 3.3.1 第 4 节 Qwen3-235B-A22B 和 DeepSeek-V3 的逐项核算, 再读 3.3.2 第 5 节的粒度与显存约束, 路由与负载均衡在 [2.6 MoE](../../2-核心原理与架构/2.6-MoE/2.6-MoE.md). 想降低 Scaling Laws 实验成本的读者看 3.3.2 第 6.1 节: Hägele 等人用恒定学习率加冷却, 每个尺寸只跑一次, 在不同位置分叉冷却, Chinchilla 实验套件的算力从 $5.59\times10^{23}$ 降到 $2.36\times10^{23}$ FLOPs. 上下文长度怎样分阶段加长, 3.3.1 第 3.3 节给了三家的做法, 训练细节在 [3.5](../3.5-继续预训练与长上下文训练/3.5-继续预训练与长上下文训练.md).
