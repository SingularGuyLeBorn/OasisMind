# 数据处理: 过滤, 去重, 配比与去污染

> 相关阅读: [3.1 预训练数据](../3.1-预训练数据.md) · [3.1.1 预训练数据收集](../3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) · [3.1.2 合成与改写数据](../3.1.2-合成与改写数据/3.1.2-合成与改写数据.md) · [3.2 分词器](../../3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md)

## 1. 问题与启发式质量过滤

### 1.1 有了正文之后还差什么

[3.1.1](../3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) 把 Common Crawl 的原始 HTML 变成了带语言标签的正文. 这批文本还不能直接训练, 原因有四:

1. **大部分网页文本质量低.** Gopher 附录 A 的原话是, 网页上的大多数文本质量不足以用于语言模型训练: 自动生成的内容, 给搜索引擎看的关键词堆砌, 缺乏上下文的社交媒体片段.
2. **重复多.** 同一段免责声明, 同一篇转载文章, 同一个模板页会出现成千上万次. Common Crawl 的不同快照之间也会重复抓取同一页.
3. **来源比例要人为决定.** 网页, 书, 代码, 论文, 百科的数量差几个数量级, 按自然数量混合, 网页会占绝大多数.
4. **评测集可能已经在训练数据里.** 基准题目常被转载到论坛和博客, 不处理的话, 评测分数会混入记忆成分.

对应的四个处理步骤是质量过滤, 去重, 配比, 去污染. 它们删掉的数据量很大: RefinedWeb 在质量过滤后剩下原始文档的 23%, 去重后合计删掉近 90%; Dolma 的 CCNet 流水线把 175.1TB 处理成 27.7TB, 删掉 84.2%. 每一步的阈值都有人做过消融, 下面按原文给出.

本篇的数字大多来自小模型消融. FineWeb 的消融模型是 1.71B 参数, 训练 28B token; DCLM 的消融按「规模-倍数」命名, 例如 7B-1x 指 7B 参数, 按 Chinchilla 最优 token 数的 1 倍训练. 这些结论在更大规模上是否成立, 各论文只做了有限验证.

### 1.2 启发式过滤与 C4 的规则

启发式过滤是对每篇文档算几个统计量, 超过阈值就删掉. 规则简单, 能在 CPU 上逐文档并行, 不需要训练任何模型.

最早成体系的一套是 C4 的规则. C4 (Colossal Clean Crawled Corpus) 来自 T5 论文 (Raffel et al., §2.2). 作者取 2019 年 4 月的 Common Crawl WET 文本, 依次应用下表的规则, 有的删行, 有的删整页:

| 作用于 | 规则 |
|---|---|
| 行 | 只保留以句末标点 (句号, 感叹号, 问号, 结束引号) 结尾的行; 只保留至少含 5 个词的行 |
| 行 | 删除含「Javascript」一词的行 (这类行多是「请启用 Javascript」的提示) |
| 行 | 删除含「terms of use」「privacy policy」「cookie policy」「uses cookies」等字符串的行 |
| 行内 | 删除维基百科式的引用标记, 如 `[1]`, `[citation needed]` |
| 页 | 丢弃少于 3 个句子的页面 |
| 页 | 删除含「List of Dirty, Naughty, Obscene or Otherwise Bad Words」中任何一个词的页面 |
| 页 | 删除含「lorem ipsum」的页面 |
| 页 | 删除含花括号 `{` 的页面 (用来排除代码) |
| 片段 | 去重: 任何出现不止一次的三句话片段, 只留一份 |

另外用 langdetect 只保留英语概率至少 0.99 的页面. 结果约 750GB.

C4 规则的代价可以在 FineWeb 上看到. FineWeb 团队把 C4 的各条规则分别用在自己的数据上: 句末标点规则一条删掉约 30% 的 token; 花括号规则删 2.8%; 词长规则删 4.3%; lorem ipsum, javascript, policy 三条各删不到 0.5%. 除句末标点外的规则合起来删约 7%, 效果好于单用句末标点规则. 句末标点规则是单条提升最大的, 但删掉的数据太多, FineWeb 最终采用了除它以外的全部 C4 规则, 另设了一条更宽松的标点规则 (见 §1.4).

### 1.3 Gopher 的规则

Gopher 论文 (Rae et al., 附录 A.1.1) 把过滤分成质量过滤和重复去除两组, 都只用于 MassiveWeb (MassiveText 中的网页子集, 占训练数据的 48%).

质量过滤删除满足任一条件的文档:

| 统计量 | 保留条件 |
|---|---|
| 词数 | 50 到 100,000 |
| 平均词长 | 3 到 10 个字符 |
| `#` 或 `...` 与词数之比 | 不超过 0.1 |
| 以项目符号开头的行 | 不超过 90% |
| 以省略号结尾的行 | 不超过 30% |
| 至少含一个字母的词 | 至少 80% |
| 停用词 | the, be, to, of, and, that, have, with 中至少出现两个 |

停用词规则针对的是语言识别判为英语, 但实际没有连贯英语句子的页面, 例如纯关键词列表.

重复去除对行和段落分别算两个量: 重复行 (段) 占总行 (段) 数的比例, 以及重复行 (段) 中字符占全文字符的比例. 对 $n$-gram 再算两类量. 设文档 $d$ 共有 $|d|$ 个字符, 对 $n\in\{2,3,4\}$ 算出现次数最多的那个 $n$-gram 覆盖的字符比例; 对 $n\in\{5,\dots,10\}$ 算所有重复 $n$-gram 覆盖的字符比例, 重叠部分的字符只计一次:

$$
f_n(d)=\frac{\left|\bigcup_{g\in \mathrm{Dup}_n(d)} \mathrm{span}(g)\right|}{|d|} \tag{1}
$$

其中 $\mathrm{Dup}_n(d)$ 是 $d$ 中出现至少两次的 $n$-gram 的全部出现位置, $\mathrm{span}(g)$ 是一次出现覆盖的字符位置集合. 取并集就是为了让重叠字符不被重复计数. 阈值见 Table A1:

| 统计量 | 超过即删 |
|---|---|
| 重复行比例 / 重复段落比例 | 0.30 / 0.30 |
| 重复行字符比例 / 重复段落字符比例 | 0.20 / 0.20 |
| 最高频 2-gram / 3-gram / 4-gram 字符比例 | 0.20 / 0.18 / 0.16 |
| 重复 5-gram 到 10-gram 字符比例 | 0.15, 0.14, 0.13, 0.12, 0.11, 0.10 |

$n$ 越大阈值越低: 长 $n$-gram 偶然重复的概率小, 一旦重复多半是整段复制.

Gopher 在内容过滤上用 Google SafeSearch 而不是词表. 理由是词表过滤被发现会不成比例地删掉与少数群体相关的正常内容 (Dodge et al., 2021). C4 的脏词表规则正是这类词表.

### 1.4 规则怎么挑

Dolma 的消融把两套规则直接比较. 在 Dolma 的网页数据上, Gopher 全部规则标出 15.23% 的字符, C4 的句末标点规则单独标出 22.73%. 下游效果上, 单用 C4 句末标点规则好于 C4 全部规则, 也好于 Gopher 全部规则; Gopher 全部规则加 C4 句末标点规则组合最好.

FineWeb 给出了一种找新规则的方法. 他们注意到, 2013-48 这个快照做全局去重后保留的约 31B token, 训练效果比被删掉部分 (约 460B, 单独去重后 171B) 还差. 于是有了一对「高质量」和「低质量」数据, 作者在两者上算了 50 多个文档统计量, 挑出分布差异大的 16 个作为候选阈值, 再逐个做消融. 最后留下三条:

| 规则 | 删除的 token |
|---|---|
| 以标点结尾的行占比 $\le 0.12$ | 10.14% |
| 重复行的字符占比 $\ge 0.1$ | 12.47% |
| 短于 30 字符的行占比 $\ge 0.67$ | 3.73% |

第一条是 C4 句末标点规则的宽松版: 不再逐行删, 而是只删几乎没有标点结尾行的整篇. 第二条与 Gopher 的重复行字符比例同一统计量, 阈值从 0.2 收紧到 0.1. 三条合计删约 22% 的 token, 聚合分数提高约 1 个百分点.

规则的局限也在这里: 每条规则都只看表面统计量, 一篇格式正常的营销软文能通过全部检查. 要按内容判断质量, 需要 §3 的分类器.

## 2. 去重

### 2.1 重复的规模与后果

Lee et al. (2107.06499) 在四个英语语料上量化了重复:

| 语料 | 近重复样本比例 (NearDup) | 重复子串 token 比例 (ExactSubstr) | 验证集中在训练集有近重复的比例 |
|---|---|---|---|
| C4 | 3.04% | 7.18% | 4.60% |
| RealNews | 13.63% | 19.4% | 14.35% |
| LM1B | 4.86% | 0.76% | — |
| Wiki-40B | 0.39% | 2.76% | — |

前两列来自原文 Table 2 和 Table 3, 第三列只取 Table 2 中 C4 与 RealNews 两行. C4 里有 180 万个近重复簇只含一对样本, 但也有 280 个簇超过 5000 个样本, 最大的簇有 250,933 个样本. 一个 61 词的句子在 C4 训练集中出现 61,036 次, 在验证集中出现 61 次.

重复的直接后果是记忆. 作者在三份数据上各训练一个 1.5B 参数的 XL 模型 (50K BPE 词表, 序列长 512), 统计无提示生成中与训练集逐字匹配的 token 比例 (Table 4):

| 训练数据 | 1 epoch | 2 epochs |
|---|---|---|
| C4 原始 | 1.926% | 1.571% |
| NearDup 去重 | 0.189% | 0.264% |
| ExactSubstr 去重 | 0.138% | 0.168% |

去重最多让数据集缩小 19%, 困惑度不变差, 部分验证集上降低最多 10%. 另一个后果是评测偏高: C4 验证集里 4.6% 的样本在训练集中有近重复, 用这部分算困惑度, 测到的是记忆.

去重分三种粒度: 整篇完全相同 (精确去重), 整篇大部分相同 (近重复去重), 片段相同 (子串去重). 下面分别讲.

### 2.2 精确去重与 Bloom filter

精确去重对每篇文档 (或每个段落, 每个 URL) 算哈希, 相同哈希只留一份. 数据能放进一台机器的内存时用哈希表即可; 数据到 TB 级时, 常用 Bloom filter 代替哈希表. Dolma 的 URL, 文档, 段落三级精确去重都用 Bloom filter.

Bloom filter 用 $m$ 位的位数组和 $k$ 个哈希函数. 插入元素时把 $k$ 个哈希位置都置 1; 查询时 $k$ 个位置全为 1 就判为「见过」. 它不会漏报, 但会误报: 插入 $n$ 个元素后, 误报率约为

$$
\varepsilon \approx \left(1-e^{-kn/m}\right)^k \tag{2}
$$

给定 $n$ 和目标误报率 $\varepsilon$, 使 (2) 最小的位数和哈希数是

$$
m=-\frac{n\ln\varepsilon}{(\ln 2)^2},\qquad k=\frac{m}{n}\ln 2 \tag{3}
$$

DCLM 给出的例子: 在 $10^{12}$ 个 token 上要求误报率 $10^{-12}$, 需要约 6.5TB 内存. 按 (3) 验算, $-\ln 10^{-12}\approx27.63$, $(\ln2)^2\approx0.4805$, $m\approx10^{12}\times27.63/0.4805\approx5.75\times10^{13}$ 位, 即约 $7.2\times10^{12}$ 字节, 合 6.5TiB.

DCLM 的 BFF (big friendly filter) 把 Bloom filter 用在 $n$-gram 上做近似去重: 对文档的每个 $n$-gram ($n$ 取 5 到 13) 查 filter, 若某个段落或文档中被判为「见过」的 $n$-gram 超过 0.8, 就把它删掉, 否则把它的 $n$-gram 插入 filter. filter 的误报率设为 0.01. 单个 $n$-gram 的误报会不会让一篇新文档被误删? DCLM 用 Hoeffding 不等式给了一个例子: 一篇有 100 个 $n$-gram 的文档, 其中 60 个确实见过, 剩下 40 个各以 0.01 的概率误报, 要超过 0.8 的阈值至少需要 20 个误报, 这个概率小于 $10^{-8}$. 在 7B-2x 规模上, BFF 与 MinHash 的 Core 分数相差 0.2 以内.

### 2.3 MinHash-LSH: 近重复去重

两篇文档 $A$, $B$ 先各自切成 $n$-gram 集合 (称 shingle), 用 Jaccard 相似度衡量重合程度:

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|} \tag{4}
$$

两两计算 (4) 的代价是文档数的平方, 无法用于数十亿篇文档. MinHash 用哈希签名近似它. 取一个随机哈希函数 $h$, 定义 $\min_h(A)=\min_{x\in A}h(x)$. 两个集合的最小哈希相同, 当且仅当 $A\cup B$ 中哈希最小的元素同时属于 $A$ 和 $B$, 而在随机哈希下 $A\cup B$ 的每个元素成为最小者的概率相同, 所以

$$
\Pr\left[\min_h(A)=\min_h(B)\right]=J(A,B) \tag{5}
$$

用 $br$ 个独立哈希函数得到长为 $br$ 的签名. 局部敏感哈希 (LSH) 把签名切成 $r$ 段, 每段 $b$ 个值 (称一个桶). 两篇文档只要有一个桶的 $b$ 个值全相同, 就成为候选对. 设 $J(A,B)=s$, 一个桶全相同的概率是 $s^b$, $r$ 个桶都不全相同的概率是 $(1-s^b)^r$, 所以成为候选的概率是

$$
P(s)=1-\left(1-s^b\right)^r \tag{6}
$$

(6) 是一条 S 形曲线, 陡峭处大约在 $s^*\approx(1/r)^{1/b}$. 增大 $b$ 让曲线右移, 增大 $r$ 让曲线左移, 两者同时增大让曲线更陡, 代价是签名更长.

用 FineWeb 的参数手算一个点. FineWeb 取 5-gram, 112 个哈希, $r=14$ 个桶, 每桶 $b=8$ 个. $s=0.75$ 时, $0.75^8\approx0.1001$, $(1-0.1001)^{14}=e^{14\ln 0.8999}\approx e^{-1.477}\approx0.228$, 所以 $P(0.75)\approx 77\%$. 陡峭点 $s^*\approx(1/14)^{1/8}=e^{-\ln 14/8}\approx e^{-0.330}\approx0.72$. 各家参数对比:

| 来源 | shingle | 签名长 | 桶数 $r$ × 每桶 $b$ | $s^*$ | 后处理 |
|---|---|---|---|---|---|
| Lee et al. (C4) | 5-gram | 9000 | 450 × 20 | 约 0.74 | 候选对再要求编辑相似度 $>0.8$, 连通分量聚类 |
| RefinedWeb | 5-gram | 9000 | 450 × 20 | 约 0.74 | 0.75 时命中 76%, 0.8 时 99.4% |
| FineWeb | 5-gram | 112 | 14 × 8 | 约 0.72 | 传递聚类, 每簇随机留一篇 |
| Gopher (MassiveText) | 13-gram | 未给 | 未给 | 阈值 0.8 | 归一化空白, 忽略标点 |

FineWeb 报告的命中概率: $s=$ 0.7, 0.75, 0.8, 0.85 时分别为 56%, 77%, 92%, 98.8%. RefinedWeb 的 $s^*$ 按 $(1/450)^{1/20}=e^{-\ln 450/20}\approx e^{-0.305}\approx0.74$ 算出. 签名长度从 9000 降到 112, 存储和比较代价降到约 1/80, 曲线变缓, 0.7 附近的文档对有一半被判为候选.

近重复去重删多少, 各家差别很大. RefinedWeb 的 Table 1 列出: GPT-3 的 MinHash 删约 10%, The Pile 用 10 个哈希, 阈值 0.5, 删约 26%, RefinedWeb 删约 50%.

### 2.4 后缀数组: 子串去重

MinHash 处理整篇, 处理不了「一篇正常文章里夹着一段 200 词的转载段落」. Lee et al. 的 ExactSubstr 删掉所有长度至少 $k=50$ 个 token, 在语料中出现不止一次的子串.

做法是把整个语料拼接成一个 token 序列 $S$, 对 $S$ 构建后缀数组 $A$: $A$ 是 $S$ 所有后缀按字典序排序后的起始位置. 以字符串 banana 为例, 6 个后缀按位置是 banana(1), anana(2), nana(3), ana(4), na(5), a(6), 按字典序排列为 a, ana, anana, banana, na, nana, 所以 $A=(6,4,2,1,5,3)$. 任何重复子串都表现为排序后相邻两个后缀的公共前缀: ana(4) 与 anana(2) 相邻, 公共前缀 ana 长 3, 说明 ana 在位置 2 和 4 各出现一次. 在真实语料上, 扫一遍相邻后缀, 公共前缀长度 $\ge 50$ 的就标记为重复.

后缀数组可以线性时间构建, 每个 token 占 8 字节, 内存比后缀树省 10 到 100 倍. 内存仍然是瓶颈: RefinedWeb 为此用了最多 2TiB 内存的 x2iedn 实例, 并且先做 MinHash, 让 ExactSubstr 需要处理的数据减少近 40%.

标出重复片段后怎么处理, RefinedWeb 比较了四种: 直接切掉片段 (Cut), 片段 token 不计入损失 (Mask), 片段超过文档 20% 就删整篇 (DropPartial), 有任何重复片段就删整篇 (DropAny). 最终选了 Cut.

两种近似方法有大量重叠: NearDup 从 C4 删掉的样本中, 77% 至少含一处 50 token 的逐字匹配.

### 2.5 去重范围

去重通常在全语料上做, FineWeb 的实验显示这样做不一定好. 他们从最新快照开始, 按时间倒序对 96 个快照做全局 MinHash, 最老的快照被删掉 90%, 最后剩 4T token. 从中随机抽 350B token 训练, 模型比不去重的版本提升很小, 远低于 RefinedWeb. 前面 §1.4 提到的 2013-48 快照就是这个实验的副产品: 全局去重保留的 31B token (原数据的 10%), 比被删掉的 90% 更差. 人工查看发现, 保留下来的部分含更多广告, 无连贯的关键词列表和格式混乱的文本.

作者的假设是, 去重的主要收益来自删掉包含几十万篇文档, 在所有快照中都存在的大簇; 对重复次数少的簇 (少于约 100, 即快照数量级) 再去重, 反而可能有害. 最终 FineWeb 对每个快照内部单独做 MinHash, 合计 20T token, 效果追平 RefinedWeb. 附录 E.3 还试了几种更轻的全局去重 (URL 去重删 71.5%, 行去重删 77.8%, 带最少词数的行去重删 85%, 三行窗口去重删 80.9%), 都不如逐快照去重.

这个结论依赖数据: 快照之间的重复与快照内部的重复性质不同. 换成书或代码这种没有快照结构的数据, 全局去重仍是默认做法.

## 3. 质量分类器与安全过滤

### 3.1 模型质量分类器: 从困惑度到分类器

用模型判断质量有两类做法. 一类是参考模型困惑度: CCNet 在维基百科上训练 KenLM 5-gram 模型, 按困惑度把文档分成高, 中, 低三档. 在 Dolma 的统计里三档分别占 21.9%, 28.5%, 49.6%, 做完启发式过滤后这个比例基本不变, 即启发式规则在三档里删掉的比例相近, 两种信号挑出的不是同一批文档.

另一类是二分类器: 选一批「高质量」参考文本作正例, 网页作负例, 训练分类器后按分数筛网页. GPT-3 用 WebText, 维基百科和书作正例; LLaMA 用被维基百科引用的页面作正例. 这类方法的关键是正例选什么.

设分类器给文档 $d$ 打分 $q(d)$, 保留比例为 $\rho$, 规则是

$$
\text{keep}(d)=\mathbb{1}\left[q(d)\ge Q_{1-\rho}(q)\right] \tag{7}
$$

其中 $Q_{1-\rho}(q)$ 是整个候选池分数的 $1-\rho$ 分位数. 下面两个方法在「正例」和「$q$ 是什么模型」上不同.

### 3.2 DCLM 的 fastText 分类器

DCLM 在 1B-1x 规模上用同一个起点 (RefinedWeb 复现版) 比较了 8 种筛选方法 (Table 4, Core 分数):

| 方法 | Core |
|---|---|
| 不筛 (RefinedWeb 复现) | 27.5 |
| PageRank | 26.1 |
| SemDedup | 27.1 |
| BGE 嵌入分类器 | 27.2 |
| AskLLM | 28.6 |
| 困惑度过滤 | 29.0 |
| top-k 平均 logits | 29.2 |
| fastText 分类器 | 30.2 |

PageRank 比不筛还差. 最便宜的 fastText 最好. fastText 分类器用 unigram 加 bigram 特征 (`wordNgrams=2`), 训练集固定为 40 万篇: 正例 20 万篇 (OH-2.5 和 ELI5 各 10 万), 负例 20 万篇从 RefinedWeb 复现版中随机采. 正例的选择在 7B-1x 规模上消融 (Table 5, Core / MMLU):

| 正例 | Core | MMLU |
|---|---|---|
| OpenHermes-2.5 指令数据 + ELI5 高赞回答 | 41.0 | 29.2 |
| 维基百科 | 35.7 | 27.0 |
| OpenWebText2 | 34.7 | 25.0 |
| GPT-3 正例的近似复现 | 37.5 | 24.4 |

阈值上, 保留分数前 10% 最好; 放宽到前 15% 时 Core 是 39.8, 前 20% 时 38.7.

正例选的是指令数据和问答论坛, 结果明显好于传统上「高质量」的维基百科. DCLM 还请 16 名标注者对约 500 篇文档做了人工质量判断, 标注者之间的一致率 71%. AskLLM 与人工标签的 ROC-AUC 约 82%, 但 Core 只有约 28.5; fastText 的 ROC-AUC 约 73%, Core 超过 31. 与人工判断的相关 ($R^2$) 低于 0.3. 人觉得好的文本, 不一定是训练效果好的文本.

DCLM 还试了把高质量来源 (RedPajama 的维基, 书, arXiv 等) 混进筛选后的网页 (Table 6). 混进 C4 提升 2.2, 混进 RefinedWeb 提升 1.4, 混进 DCLM-baseline 反而下降 1.2. 网页筛得足够好以后, 再混入传统高质量来源不再有收益.

### 3.3 FineWeb-Edu

FineWeb-Edu 的分数 $q$ 来自大模型标注. 流程:

1. 用 Llama-3-70B-Instruct 给 46 万篇 FineWeb 文档打 0 到 5 分. prompt 采用累加式打分: 满足一条标准加 1 分, 标准围绕「对小学到中学教育是否有用」.
2. 在 Snowflake-arctic-embed-m 嵌入上训练一个线性回归头, 41 万篇训练 20 epoch, 学习率 $3\times10^{-4}$, 留 5 万篇验证.
3. 把回归输出四舍五入成整数分, 以 3 为阈值做二分类, 验证集 F1 为 82%.
4. 用这个分类器给 FineWeb 全部 15T token 打分, 耗 6000 H100 GPU 小时. 保留 $\ge 3$ 分的文档, 得到 1.3T token.

效果: MMLU 从 33 升到 37, ARC 从 46 升到 57. 在 38B token 时 MMLU 达到 33.6%, 另一个对比数据集 Matrix 需要约 300B token 才达到同样分数.

代价是分布偏移. 分类器偏好教育, 历史类主题, 商业, 娱乐类内容被压低. 分类器把标注 prompt 的偏好写进了数据分布, prompt 围绕「教育价值」写, 留下的数据就偏向知识类基准考察的内容.

### 3.4 毒性过滤

毒性过滤有三种做法: 词表 (C4), 外部服务 (Gopher 用 SafeSearch), 分类器 (Dolma). 词表误伤多, 前面提过 Dodge et al. 的结论. Dolma 用分类器, 并测了阈值的影响.

Dolma 在 Jigsaw 毒性评论数据集上训练两个 fastText 分类器, 一个识别仇恨言论, 一个识别色情内容, 按句子打分, 超过阈值 $\tau$ 的句子删掉. 两档阈值的对比:

| 阈值 $\tau$ | 删除比例 | 下游效果 |
|---|---|---|
| 0.4 | 5.5% 到 7.3% | 较差 |
| 0.0004 | 29.1% 到 34.9% | 较好 |

低阈值删得多, 效果更好. Dolma 最终用了 0.4, 原因是低阈值删掉的数据太多, 凑不够计划的 token 数. 这个取舍说明, 过滤阈值和总 token 预算要一起定.

### 3.5 个人信息 (PII)

各家的 PII 处理都比较保守, 只处理能用正则可靠识别的类型:

- **Dolma**: 只处理邮箱, IP 地址, 电话号码三类. 一篇文档里命中不超过 5 处, 就把命中处替换成特殊 token (影响 0.02% 的文档); 超过 5 处删整篇 (影响 0.001% 的文档). 消融显示替换和删除对下游效果没有差别.
- **FineWeb**: 用正则把邮箱和公网 IP 地址替换成占位符.
- **代码数据**: StarCoder 系列训练了专门的 NER 模型 StarPII, 识别代码里的密钥, 密码, 邮箱, IP 地址, 姓名, 用户名.

人名, 住址这类信息没有固定格式, 正则抓不全, 上面两个网页数据集都没有处理.

## 4. 数据配比

### 4.1 问题的形式

设有 $k$ 个数据域 (网页, 书, 代码, ...), 第 $i$ 个域的数据分布为 $P_i$. 配比是概率单纯形 $\Delta^k$ 上的一个向量 $\alpha=(\alpha_1,\dots,\alpha_k)$, $\alpha_i\ge0$, $\sum_i\alpha_i=1$. 训练分布是

$$
P_\alpha=\sum_{i=1}^{k}\alpha_i P_i \tag{8}
$$

$\alpha_i$ 按 token 计. 若域 $i$ 的 token 总数为 $N_i$, 总训练 token 为 $T$, 这个域被重复的遍数约为 $\alpha_i T/N_i$. 小域的 $\alpha_i$ 定高了, 就意味着多遍重复.

问题是找使目标 (验证损失或下游分数) 最好的 $\alpha$. 每个候选 $\alpha$ 都要训练一个模型来评估, 直接网格搜索不现实.

### 4.2 人工消融

Gopher 的做法是小规模扫描. 他们把维基百科固定在 2% (保证训练一整遍), GitHub 固定在 3%, 剩下 95% 在 MassiveWeb, News, Books, C4 之间分配, 试了 7 种组合 (附录 A.3.1). 书的比例高时 LAMBADA 损失低, C4 比例高时 C4 验证损失低. 最后选 C4 10%, MassiveWeb 50%, Books 30%, News 10% (再乘 95%), 这组在各任务上都不差, 在 Curation Corpus 上最好.

LLaMA 的配比表见 [3.1.1](../3.1.1-预训练数据收集/3.1.1-预训练数据收集.md). 这类人工配比的问题是只能试很少的组合, 且依赖选定的评测任务.

### 4.3 DoReMi

DoReMi (Xie et al., 2305.10429) 不依赖下游任务, 目标是让模型在每个域上的「超额损失」都小. 超额损失指代理模型与参考模型在同一样本上的损失差. 分三步:

1. 用初始配比 (如均匀, 或按 token 数) 训练一个 280M 参数的参考模型, 得到每个 token 的损失 $\ell_{\text{ref}}$.
2. 训练同样大小的代理模型 $\theta$, 求解极小极大问题:

$$
\min_\theta\max_{\alpha\in\Delta^k}\sum_{i=1}^{k}\alpha_i\left[\frac{1}{\sum_{x\in D_i}|x|}\sum_{x\in D_i}\left(\ell_\theta(x)-\ell_{\text{ref}}(x)\right)\right] \tag{9}
$$

内层的 max 会把权重全部压到超额损失最大的域上. 超额损失大说明参考模型能学会 (损失低) 而代理模型还没学会; 熵很高的域 (参考模型损失也高) 或很容易的域 (代理模型损失已经低) 超额损失都小, 不会被加权.

3. 用第 2 步得到的平均权重重新采样数据, 训练 8B 主模型.

第 2 步用 Group DRO 的在线算法交替更新. 每步按均匀权重采一个批次, 对域 $i$ 算 token 级超额损失并截断到 0 以上:

$$
\lambda_t[i]=\frac{1}{\sum_{x\in B\cap D_i}|x|}\sum_{x\in B\cap D_i}\sum_{j=1}^{|x|}\max\left\{\ell_{\theta_{t-1},j}(x)-\ell_{\text{ref},j}(x),0\right\} \tag{10}
$$

然后做指数梯度上升, 归一化并与均匀分布 $u=\frac{1}{k}\mathbf{1}$ 平滑:

$$
\alpha'_t=\alpha_{t-1}\odot\exp(\eta\lambda_t),\qquad \alpha_t=(1-c)\frac{\alpha'_t}{\sum_i\alpha'_t[i]}+cu \tag{11}
$$

再用 $\alpha_t$ 加权的损失更新代理模型. 原文取步长 $\eta=1$, 平滑系数 $c=10^{-3}$, 没有细调. 最终配比是整个训练过程的平均 $\bar\alpha=\frac1T\sum_t\alpha_t$. 截断到 0 是因为 Group DRO 要求损失非负. 平滑项 $cu$ 保证每个域的权重不低于 $c/k$, 避免某个域被完全丢弃.

DoReMi 可以迭代: 把上一轮的 $\bar\alpha$ 作为下一轮参考模型的配比, 直到权重的最大变化小于 $10^{-3}$. 在 GLaM 数据集上 3 轮收敛.

The Pile 上的结果 (Table 1, 部分域):

| 域 | 默认权重 | DoReMi (280M) |
|---|---|---|
| Pile-CC (网页) | 0.1121 | 0.6057 |
| OpenWebText2 | 0.1247 | 0.1019 |
| Wikipedia (en) | 0.0919 | 0.0699 |
| Books3 | 0.0676 | 0.0224 |
| Github | 0.0427 | 0.0179 |
| USPTO Backgrounds | 0.0420 | 0.0036 |
| FreeLaw | 0.0386 | 0.0043 |
| DM Mathematics | 0.0198 | 0.0018 |

网页的权重从 11% 升到 61%, 专利, 法律, 合成数学大幅降低. 用这个配比训练的 8B 模型, 每个域的困惑度都降低了, 包括被降权的域; 下游 one-shot 生成任务平均准确率比默认配比高 6.5 个点, 到达默认配比最终准确率所需的步数少 2.6 倍. 在 GLaM 数据集上, DoReMi 与按下游任务调出的配比表现相当.

### 4.4 RegMix

RegMix (Liu et al., 2407.01492) 把配比当成回归问题. 先训练大量小模型, 用它们的结果拟合「配比 → 目标」的回归器, 再在回归器上搜最优配比.

1. **采样配比.** 在 The Pile 可用的 17 个域上, 从 Dirichlet 分布采样配比. Dirichlet 的参数是各域的 token 占比乘以 0.1 到 5.0 之间的系数, 系数小时采出的配比稀疏, 系数大时接近 token 占比. 以 token 占比为基础, 是为了不让 token 少于 1% 的小域被采成大比例 (那样的配比在大规模训练时没有足够数据支撑).
2. **训练代理模型.** 512 个 1M 参数模型, 每个训练 1B token. 总计算量约为训练一个 1B 模型的 2%.
3. **拟合回归.** 特征是配比向量 $\alpha$, 目标 $y$ 取 Pile-CC 域的验证损失. 比较了岭回归

$$
y=\omega_0+\sum_{i=1}^{k}\omega_i\alpha_i+\epsilon \tag{12}
$$

和 LightGBM (梯度提升树).

4. **模拟与选择.** 在回归器上预测大量随机配比, 100 万个配比的预测不到 10 个 CPU 秒. 取预测最好的前 100 个配比求平均, 作为大模型的配比.

回归器的排序能否外推到大模型, 用 Spearman 秩相关 $\rho$ 检验 (Table 2):

| 回归器 | 1M 模型 $\rho$ | 60M 模型 $\rho$ | 1B 模型 (25B token) $\rho$ |
|---|---|---|---|
| 线性 | 90.08 | 89.26 | 88.01 |
| LightGBM | 98.45 | 98.64 | 97.12 |

LightGBM 明显好于线性, 说明域之间有交互, 配比的效果不能按域线性叠加. 用 1M 模型预测出的配比训练 1B 模型 25B token, 在 64 个不同配比的 1B 模型中表现最好. 在同样的小规模算力下, 增加代理模型个数比增加每个代理模型的 token 更有用: 代理模型 token 数超过约 0.25B 后收益饱和, 512 个各训 0.2B 的模型好于 128 个各训 0.8B 的.

RegMix 用约 10% 的计算量达到或超过 DoReMi, 在 7B 模型训练 100B token 的实验中持续好于人工配比. 它还发现, 与下游表现正相关最强的是网页数据 (Pile-CC), 而不是维基百科这类通常被认为高质量的数据. 这与 DoReMi 把 Pile-CC 权重提到 61%, 以及 DCLM 混入高质量来源无收益, 是同一个方向的观察.

把两种方法放在一起比较. DoReMi 的目标与下游任务无关, 只看各域损失; 代价是只训练两个小模型, 但得到的配比是「各域都不差」的折中. RegMix 可以对任意目标优化 (某个域的损失, 某个基准的分数), 但目标选错, 配比就会针对错误的目标. 两者都依赖一个假设: 小模型上配比的相对优劣在大模型上保持. RegMix 的 Spearman 相关支持这个假设到 1B, 更大规模上的证据只有 7B 一组.

## 5. 去污染

### 5.1 污染有多普遍, 怎么去

Lee et al. 的综述部分汇总了几个数字: GPT-3 用 13-gram 重叠检查评测集, 最多 90% 的任务被标为可能受污染; Dodge et al. 发现部分基准有最多 14.4% 的测试样本逐字出现在 C4 中. GPT-2 用 8-gram 重叠做了事后分析.

去污染与去重用的是同一套工具, 只是把评测集当作「已见过」的集合, 删训练数据中与它重合的部分.

- **Gopher**: 计算训练文档与测试文档 (Wikitext103, C4, Curation Corpus, LAMBADA) 的 13-gram Jaccard 相似度, 超过 0.8 的训练文档删掉. 另外从维基百科训练集中直接删除 Wikitext103 验证集和测试集用到的页面, 因为这些页面后来可能被编辑过, $n$-gram 匹配会漏掉. Gopher 原文也写明, The Pile 等部分测试集在 Gopher 训练之后才发布, 可能已经泄漏进训练集.
- **The Stack v2**: 对 HumanEval, MBPP, APPS, GSM8K, DS1000 去污染, 匹配前去掉空白, 避免缩进差异造成漏检.
- **DCLM**: 对 MMLU 和 Hellaswag, 标出同时含题干和至少一个选项的网页, 删掉匹配的题干和选项字符串. MMLU 有些题带长段落, 为提高召回只匹配题干最后一句, 这样误报较多. 删掉后重新训练 7B-2x 模型 (Table 7):

| 训练数据 | MMLU | Hellaswag |
|---|---|---|
| DCLM-baseline | 51.8 | 77.9 |
| DCLM-baseline (删除命中) | 52.7 | 78.4 |

分数没有下降, 说明这两项上的提升不是来自题目泄漏. 按同一规则, DCLM-baseline, Dolma-V1.7 (抽 1/10), FineWeb-Edu (10B 子集) 被标出的样本比例分别为 0.007%, 0.001%, 0.009%; 规则偏召回, 这些是上界估计.

### 5.2 从评测侧统计

另一种做法不删训练数据, 而是把评测集分成「干净」和「受污染」两部分分别报分. DCLM 附录 O 沿用 Llama 2 的标准: 找训练集与评测样本之间长度至少 10 的公共 token 序列, 样本中超过 80% 的 token 落在这类序列里记为「dirty」, 低于 20% 记为「clean」. 设评测样本 $e$ 有 $|e|$ 个 token, 其中被至少一个长度 $\ge 10$ 的公共序列覆盖的 token 集合为 $C(e)$, 污染率是

$$
\mathrm{cont}(e)=\frac{|C(e)|}{|e|} \tag{13}
$$

DCLM 比较了全集与「非 dirty」子集上的分数, 差别很小; BoolQ 和 SQuAD 被标为高度污染, 但模型在非 dirty 子集上的分数反而略高. 原文也指出 20% 和 80% 两个阈值都难以论证: 20% 误报多, 80% 可能漏掉不少污染样本.

$n$-gram 方法只能找到字面重合. 改写过的题目, 翻译成其他语言的题目, 以及由强模型生成, 内容接近基准的合成数据, 都检测不到.

## 6. 流水线顺序与边界

### 6.1 流水线顺序

把以上步骤串起来, 常见顺序是按单文档成本从低到高排:

```text
URL 过滤 → 正文抽取 → 语言识别        (3.1.1)
→ 启发式质量规则 (C4 / Gopher / 自定义)
→ 近重复去重 (MinHash-LSH, 按快照或全局)
→ 子串去重 (后缀数组, 可选)
→ 模型质量分类器 (fastText / 嵌入回归)
→ 毒性分类 与 PII 替换
→ 去污染 (n-gram 对评测集)
→ 按域配比采样 → tokenize
```

先做便宜的规则, 是为了减少后面昂贵步骤的输入量: RefinedWeb 先 MinHash 再 ExactSubstr, 子串去重的处理量少了近 40%. FineWeb-Edu 的分类器要 6000 GPU 小时, 是在已经过滤, 去重的 FineWeb 上跑的.

### 6.2 边界

**消融的规模.** 本篇绝大多数结论来自 1B 到 7B 模型, 训练几十到几百 B token. FineWeb 的消融模型是 1.71B / 28B token; DCLM 的分类器比较在 1B-1x. 更大模型对低质量数据的容忍度, 是否让某些过滤变得多余, 公开论文里没有系统结论.

**过滤与 token 预算的冲突.** Dolma 的毒性阈值说明, 效果最好的阈值可能删掉太多数据. 按 §4.1 的重复遍数 $\alpha_iT/N_i$, 过滤越严 $N_i$ 越小, 同样的训练 token 数 $T$ 下重复遍数越多, 两者需要一起权衡.

**分类器的偏好.** fastText 和 FineWeb-Edu 的分类器都把正例或标注 prompt 的偏好写进了数据分布. DCLM 的人工判断实验显示这种偏好与人的质量判断相关很弱. 换一个目标能力 (例如对话, 多语言), 分类器需要重新选正例.

**多语言.** C4, Gopher 的规则 (停用词, 词长, 句末标点) 都是为英语设计的. 中文没有空格分词, 平均词长和词数规则要改成按字符或按分词结果算, 句末标点集合也不同. 本篇引用的消融几乎都只在英语上做过.

**去重会改变分布.** FineWeb 的全局去重实验说明, 去重不只是删冗余, 也会改变剩下数据的质量构成. 高频重复的页面里也有高质量内容, 全部压到一份会降低它们的权重.

**去污染只覆盖已知基准.** 训练之后才发布的基准, 以及改写过的题目, 都不在去污染范围内. 这时只能在评测侧用 (13) 一类的统计报告污染率.
