# 合成与改写数据: 用模型生成预训练语料

> 相关阅读: [3.1 预训练数据](../3.1-预训练数据.md) · [3.1.1 预训练数据收集](../3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) · [3.1.3 数据处理](../3.1.3-数据处理/3.1.3-数据处理.md) · [4.6 OPD](../../../4-后训练/4.9-OPD/4.9-OPD.md)

## 1. 问题: 为什么预训练要用模型写的数据

### 1.1 高质量文本不够用

预训练需要的 token 数一直在涨. Llama 3.1 8B 训练了 15T token. 而可用的高质量文本有限: [3.1.3](../3.1.3-数据处理/3.1.3-数据处理.md) 讲到, DCLM 和 FineWeb-Edu 用模型分类器筛网页时都只保留约 10%. Nemotron-CC 的作者指出, 这样的数据量不够支撑 15T token 的训练.

数据不够时可以重复. Muennighoff et al. (2305.16264) 在最多 9B 参数, 900B token 的实验中发现, 计算预算固定, 数据重复不超过 4 遍时, 损失与用不重复数据几乎相同; 重复更多遍, 增加计算的收益最终降到零.

### 1.2 和知识蒸馏, 合成指令数据的区别

用模型生成文本给出了另一个选项: 用一个已有的指令模型, 按设计好的 prompt 生成新的文本, 加入预训练数据. 这里的「合成」有两层含义, 需要先区分清楚:

| | 生成什么 | 用在哪 | 学生学的信号 |
|---|---|---|---|
| 本篇: 合成与改写预训练数据 | 教科书, 文章, 改写后的网页 | 预训练 (或继续预训练) | 生成文本的下一个 token |
| 经典知识蒸馏 (Hinton et al., 2015) | 教师在同一输入上的输出分布 | 任意阶段 | 教师的软标签, 用 KL 散度对齐 |
| 合成指令数据 (Self-Instruct 等) | 指令-回答对 | SFT | 回答的下一个 token |
| [OPD](../../../4-后训练/4.9-OPD/4.9-OPD.md) | 学生自己采样的前缀 | 后训练 | 教师在学生前缀上的逐 token 监督 |

下文讨论的都是第一行. 学生按普通的因果语言模型目标训练, 生成模型只作为文本来源, 学生接触不到它的 logits 或中间层.

第一行内部又分两类做法:

- **从主题生成**: prompt 给出主题, 受众, 体裁, 让模型从头写. 文本里的知识来自生成模型.
- **改写已有文本**: prompt 给出一段真实网页, 让模型换一种风格重写, 或者从中抽出问答对. 文本里的知识来自原网页.

两类做法对生成模型的要求不同. 从主题生成需要生成模型本身知识多, 错误少; 改写只要求它能保持原意, WRAP 和 Nemotron-CC 用 7B 到 12B 的模型就够了.

## 2. Phi-1: 筛选数据加合成教科书

### 2.1 数据

Phi-1 (Gunasekar et al., 2306.11644) 是一个 1.3B 参数的代码模型. 它的训练数据有三部分:

| 数据 | 规模 | 来源 |
|---|---|---|
| 筛选后的代码数据 | 约 6B token | The Stack (Python, 已去重) 和 StackOverflow, 用分类器筛选 |
| 合成教科书 | 不到 1B token | GPT-3.5 生成的 Python 教科书 |
| CodeExercises | 约 180M token | GPT-3.5 生成的 Python 习题和解答 |

前两部分合称 CodeTextbook, 用于预训练得到 phi-1-base; 第三部分用于微调得到 phi-1. 三部分加起来不到 7B token.

筛选分类器的做法: 原始池子有 3500 多万个文件, 超过 35B token. 作者让 GPT-4 给其中约 10 万个样本标注「对于想学习基本编程概念的学生, 这段代码的教育价值」, 再用预训练 CodeGen 模型的输出嵌入作特征, 训练一个随机森林分类器, 给全部文件打分. GPT-4 只用于这部分标注, 合成内容全部由 GPT-3.5 生成.

筛选本身的作用可以单独看: 350M 模型在未筛选的 Stack 和 StackOverflow 上训练 96k 步 (约 200B token), HumanEval 停在 12.19%; 在筛选后的子集上训练 36k 步就到 17.68%; 再加入合成教科书, 提高到 20.12%.

### 2.2 多样性

合成数据最难的是多样性. 原文的描述是, 只是让模型写一本编程教科书, 即使改变指令里的一些参数, 得到的数据也会高度同质, 相同的概念和解法反复出现, 只有细微差别. 原因是语言模型倾向于沿训练数据里最常见的路径生成.

Phi-1 的做法沿用 TinyStories (Eldan & Li): 在 prompt 里注入随机性. 合成教科书通过限定主题和目标读者来产生差异; CodeExercises 通过限定函数名来产生差异. 每条习题是一个待补全函数的 docstring.

### 2.3 训练与结果

训练设置: 8 张 A100, 序列长 2048, 文件之间用 `<|endoftext|>` 分隔. 预训练有效批大小 1024, 最大学习率 $10^{-3}$, 共 36,000 步; 取第 24,000 步的检查点作为 phi-1-base, 约相当于在 CodeTextbook 上训练 8 遍, 合计 50B 多一点 token, 用时不到 4 天. 微调有效批大小 256, 学习率 $10^{-4}$, 6000 步, 用时 7 小时.

phi-1-base 的 HumanEval 为 29%. 微调后的 phi-1 在 HumanEval 上 pass@1 为 50.6%, MBPP 为 55.5%. 同一流程训练的 350M 模型 phi-1-small 在 HumanEval 上为 45%. CodeExercises 只有不到 200M token, 但带来的提升最大.

### 2.4 去污染

CodeExercises 的格式和 HumanEval 很像 (都是 docstring 加函数补全), 污染是最直接的质疑. Phi-1 做了两层检查.

第一层是 $n$-gram 重叠. 只有 4 道 HumanEval 题与 CodeExercises 中的条目有 13-gram 重叠, 人工检查后 4 例都是误报, 例如两段描述都含有「The frequency of an integer is the number of times it appears in the list」这句话, 但题目要求完全不同.

第二层针对语义相似但字面不同的情况. 作者用两种距离: 一是 CodeGen-Mono 350M 嵌入之间的 L2 距离, 能捕捉 docstring, 函数名和代码结构相近的代码对; 二是两段代码抽象语法树 (AST) 之间的字符串编辑距离, 对变量名, 注释, docstring 不敏感. 嵌入距离取固定阈值, AST 匹配率 $\tau$ 从 0.95 变到 0.8, 对应从 CodeExercises 的 879.5K 道题中删掉 42.5K 到 354K 道.

删完后重新训练 phi-1, 在 HumanEval 全部 164 题上的 pass@1 (原文 Table 3):

| $\tau$ | 删除题数 | phi-1 | 剪枝后重训的 phi-1 | StarCoder-Prompted |
|---|---|---|---|---|
| 0.95 | 42.5K | 50.6% | 50.6% | 41.5% |
| 0.9 | — | 50.6% | 45.1% | 41.5% |
| 0.85 | — | 50.6% | 46.3% | 41.5% |
| 0.8 | 354K | 50.6% | 45.1% | 41.5% |

$\tau=0.8$ 时删掉了 $354/879.5\approx40\%$ 的习题, 包括只是有点像 HumanEval 的题, 重训后的模型仍比 StarCoder 高 3.6 个点. 这个实验能排除逐字或近似泄漏, 排除不了「习题的整体风格接近 HumanEval」带来的收益.

## 3. Phi-1.5 与 Cosmopedia: 从主题生成通用文本

### 3.1 Phi-1.5

Phi-1.5 (Li et al., 2309.05463) 把同一方法用到自然语言. 训练数据是 phi-1 的数据 (7B token) 加约 20B token 新合成的「教科书式」数据, 内容是常识推理和世界知识 (科学, 日常活动, 心智理论等). 作者挑选了 2 万个主题作为种子, prompt 中加入网页样本以增加多样性. 除 phi-1 的 6B token 筛选代码外, 训练数据全是合成的.

模型训练 150B token, 其中 80% 来自新合成数据, 20% 来自 phi-1 的数据. 作者另训练了两个对照模型: phi-1.5-web-only 只用 95B token 的筛选网页 (88B 来自 Falcon RefinedWeb, 7B 来自代码); phi-1.5-web 把筛选网页, phi-1 代码数据, 新合成数据按约 40%, 20%, 40% 混合. 部分结果 (原文 Table 2 和 Table 4):

| 模型 (1.3B) | WinoGrande | ARC-C | GSM8K | HumanEval |
|---|---|---|---|---|
| Falcon-rw-1.3B | 0.607 | 0.282 | < 3 | 0 |
| phi-1.5-web-only | 0.604 | 0.329 | < 3 | 17.2 |
| phi-1.5 | 0.734 | 0.444 | 40.2 | 34.1 |
| phi-1.5-web | 0.740 | 0.449 | 44.6 | 41.4 |
| Llama2-7B (对照) | 0.691 | 0.434 | 14.6 | 12.8 |

phi-1.5 的 GSM8K 是「通过写代码」解题的结果. 加入网页数据后 (phi-1.5-web), 推理和代码类任务又有提升. Phi-1.5 的技术报告没有公开合成数据本身, 也没有给出 prompt 的具体构造方法.

### 3.2 Cosmopedia

Cosmopedia (Ben Allal et al., HuggingFace, 2024) 的目标是公开复现 Phi-1.5 的数据. 生成模型是开放权重的 Mixtral-8x7B-Instruct-v0.1, 产出教科书, 博客, 故事, 帖子, WikiHow 式文章, 共 3000 多万个文件, 25B token.

**需要多少 prompt.** Phi-1.5 用 2 万个主题生成 20B token. 按平均每个文件 1000 token 算,

$$
N_{\text{prompt}}\approx\frac{20\times10^{9}}{10^{3}}=2\times10^{7} \tag{1}
$$

也就是约 2000 万个互不相同的 prompt. 2 万个主题远远不够, 每个主题要派生出约 1000 个 prompt, 而且生成结果之间还不能雷同.

**来自整理过的教育资源的 prompt.** 从斯坦福课程, Khan Academy, OpenStax, WikiHow 抽取课程大纲, 每个单元写一个 prompt. 这类来源规模有限: OpenStax 只能抽出 16,000 个单元, 斯坦福 250,000 个. 一个主题可以按受众和体裁复用: 4 类受众 (幼儿, 高中生, 大学生, 研究者) 乘 3 种体裁 (教科书, 博客, WikiHow 文章), 最多扩到 12 倍:

$$
N_{\text{prompt}}=N_{\text{topic}}\times N_{\text{audience}}\times N_{\text{style}} \tag{2}
$$

作者发现只把 prompt 里的「为大学生写」改成「为幼儿写」, 重复率仍然很高, 必须在 prompt 里明确写出格式和内容应该怎样不同.

**来自网页的 prompt.** 这是规模最大的来源, 占全部 prompt 的 80% 以上. 做法是把数百万个网页样本 (来自 RefinedWeb 这类数据集) 聚成 145 个簇, 每簇随机取 10 个样本的摘录, 让 Mixtral 总结共同主题, 并给出 0 到 10 的教育价值分. 人工检查后删掉低教育价值的簇 (色情, 名人八卦, 讣告等), 保留 112 个主题. prompt 要求模型围绕某个网页样本, 在其所属主题范围内写一篇教科书. 只有 50% 的 prompt 带主题信息, 再叠加受众和体裁的变化. 这条路一共构造了 2300 万个 prompt. 数学内容另外以 AutoMathText 为种子.

**故事.** 早期评估发现模型缺少小学阶段的常识, 作者用 UltraChat 和 OpenHermes-2.5 中的样本为种子生成包含日常知识的故事, 排除了代码, 高等化学这类不适合写故事的类别.

最终 3000 多万个 prompt 的重复内容低于 1%. 生成在 H100 上用 TGI 部署 Mixtral, 总计超过 1 万 GPU 小时. 作者还提到, 模型习惯用相同的开头 (例如故事常以「Once upon a time」开头), 在 prompt 里明确要求避免后, 这类开头出现得少了.

**去污染.** 先用 10-gram 重叠找候选, 再用 `difflib.SequenceMatcher` 比较候选样本 $x$ 与评测样本 $e$, 若

$$
\frac{\mathrm{len}(\text{matched}(x,e))}{\mathrm{len}(e)}>0.5 \tag{3}
$$

就丢弃 $x$. 例如在「网页 + 斯坦福 + OpenStax」这部分里, 与 BoolQ 匹配被删的样本有 386 个, 对应 41 道不同的 BoolQ 题; 与 ARC 匹配的有 49 个, 对应 16 道题. MMLU, OpenBookQA, WinoGrande 的污染样本都少于 4 个.

**结果与问题.** 在 Cosmopedia 上训练的 1B 模型 cosmo-1b 在 ARC-Easy, ARC-Challenge, OpenBookQA, MMLU 上好于 TinyLlama 1.1B, 但与 Phi-1.5 仍有差距. 作者认为差距可能来自生成模型, 主题覆盖或 prompt. 他们也指出 Mixtral 会产生幻觉, 在 AutoMathText 和 Khan Academy 部分的历史事实和数学推理上出现错误.

## 4. WRAP: 把网页改写成另一种风格

### 4.1 方法

WRAP (Web Rephrase Augmented Pre-training, Maini et al., 2401.16380) 不让模型从头写, 而是改写. 生成模型是冻结的 Mistral-7B-Instruct, 输入是 C4 的一段文本, 输出四种风格之一:

- **Easy**: 连幼儿都能看懂的文本.
- **Medium**: 维基百科那样的高质量英语. prompt 原文是「For the following paragraph give me a paraphrase of the same in high-quality English language as in sentences on Wikipedia」, 通过对比中等规模模型与 GPT-4 的输出迭代调整得到.
- **Hard**: 简练, 晦涩的语言.
- **Q/A**: 对话式问答格式.

每段输入最多 300 token. 作者观察到让模型一次改写超过 300 token 时, 常会丢信息.

改写数据与原始 C4 按 1:1 混合. 原因是改写后的文本干净, 而模型还需要能理解有错别字和语法错误的真实网页. 设 $D_{\text{c4}}$ 为 C4 的分布, $D_{\text{syn}}$ 为改写数据的分布, 只用 C4 的训练目标是

$$
\theta_{\text{c4}}=\arg\min_\theta\ \mathbb{E}_{x\sim D_{\text{c4}}}\left[L(\theta;x)\right] \tag{4}
$$

WRAP 的目标是

$$
\theta_{\text{WRAP}}=\arg\min_\theta\ \mathbb{E}_{x\sim D_{\text{c4}}\cup D_{\text{syn}}}\left[L(\theta;x)\right] \tag{5}
$$

$L(\theta;x)$ 是样本 $x$ 上的语言模型负对数似然. (5) 不再只拟合 C4, 所以在 C4 验证集上比 (4) 的模型差不到 1 个困惑度单位. 作者因此改在 The Pile 的 21 个子域上评估困惑度.

### 4.2 结果

摘要中给出的结论: 在 C4 上使用 WRAP, 预训练提速约 3 倍; 相同计算预算下, Pile 各子集上的困惑度平均改善超过 10%, 13 个零样本问答任务的准确率提高超过 2 个点. 在 ArXiv 和 HackerNews 等子域上, 困惑度降到只用真实数据时的约 1/3.

通用理解任务的对比 (约 1.3B 模型, 原文 Table 1, 8 个任务平均):

| 训练数据 | 平均 | TruthfulQA |
|---|---|---|
| C4 一半 (85B) | 47.4 | 34.1 |
| C4 全量 (170B) | 47.3 | 33.5 |
| RefinedWeb (320B) | 47.5 | 36.0 |
| TinyLlama (1T) | 47.4 | 37.6 |
| 只用改写数据 (85B) | 49.4 | 44.0 |
| 改写 + C4 (85B) | 49.4 | 40.6 |

括号里是真实数据的 token 数. 真实数据从 85B 加到 320B 甚至 1T, 平均分几乎不变; 加入改写数据后高 2 个点. 单项提升最大的是 TruthfulQA (34.1 到 44.0). 作者把收益归于两点: 改写带来的风格多样性更接近下游评测的风格; 改写文本的质量高于抓取的网页.

收益从哪里来, 边界在哪里, 作者用一组消融 (原文 Table 2 到 Table 4 及附录) 逐条检查:

- **改写不增加知识.** 在需要专门知识的任务 (原文 Table 2) 上, 作者明确写道合成数据不能带来「新知识」, 只能让预训练更快. 用更多真实数据训练的 Pythia (300B) 平均 44.6, 高于 C4 (85B) 的 43.5.
- **真实数据仍然需要.** 在真实数据 35B token 的设置下 (Table 4), Q/A 改写加 C4 平均 45.0, 只用 Q/A 改写 43.8. 在 Philpapers 和 Gutenberg 等子域上, 去掉真实 C4 后困惑度明显上升. 作者的解释是合成数据里没有真实网页中常见的标签和格式.
- **改写模型不必很大.** 用 T5-base (微调过), Qwen-1.8B-chat, Mistral-7B-chat, Vicuna-13B-chat 分别生成, 训练 345M 模型 30B token. Qwen-1.8B 和 Mistral-7B 生成的数据得到的困惑度比 Vicuna-13B 更低; T5-base 明显更差. 所有改写模型都好于只用 C4.
- **改写不同于数据增强.** 在 1.5B token 的数据池上训练 350M 模型 15B token (数据需要重复约 10 遍), 同义词替换和随机删词两种增强方法都明显差于真实数据加改写数据.
- **风格要匹配评测域.** 用与评测域风格接近的改写数据训练效果更好, 但没有一种风格在所有域上都最好. 若每个域都能挑到最合适的风格, 困惑度能再降 16%.

改写会不会把原文以外的信息带进来, 作者也检查了: 用 SimCSE 句向量计算原文与改写之间的余弦相似度, 改写对的相似度高于随机 C4 样本对和同一样本前后两半, 说明改写保留了原意, 没有加入原文以外的信息.

## 5. Nemotron-CC: 按质量分层改写

### 5.1 动机与分类器集成

Nemotron-CC (Su et al., 2412.02595) 关心的是长训练. DCLM 和 FineWeb-Edu 的分类器只保留约 10% 的高质量 token, 召回率低; 启发式过滤还会误删: 用 FineWeb-Edu 分类器判为高质量的 token 中, 有 18.1% 被启发式规则删掉. 作者的做法是用三个分类器集成提高召回, 只对低质量部分用启发式规则, 再用合成数据补足高质量 token. 正文抽取改用 jusText 替代 trafilatura, 配合不对高质量部分做启发式过滤, 高质量 token 多出 57.4%.

集成里的三个分类器: 两个是 FineWeb-Edu 式的教育价值回归器, 训练数据是用 Mixtral 8x22B-Instruct 和 Nemotron-340B-Instruct 分别给 FineWeb-Edu 那 46 万篇文档打的 0 到 5 分, 模型同样是 Snowflake-arctic-embed-m 加线性回归; 第三个是 DCLM 的 fastText 分类器. 没有直接用 FineWeb-Edu 的分类器, 原因是它的标注来自 Llama 3, 有许可问题.

每个分类器先对全部文档打分, 再按排名把分数映射成 0 到 19 的整数, 使每个整数约占 5% 的文档. 设分类器 $j$ 给文档 $d$ 的原始分数为 $q_j(d)$, 其在全体文档上的经验分布函数为 $F_j$, 则整数分为

$$
b_j(d)=\min\left(\left\lfloor 20\,F_j\left(q_j(d)\right)\right\rfloor,\ 19\right) \tag{6}
$$

集成分数取三者的最大值:

$$
b(d)=\max_{j\in\{1,2,3\}} b_j(d) \tag{7}
$$

取最大值意味着只要有一个分类器认为文档好, 文档就进入高分桶. 这样做是因为不同分类器挑出的文档重合很少: 在 CC-MAIN-2021-21 快照上, 被 FineWeb-Edu 分类器或 DCLM 分类器判为高质量的文档共 11,359,655 篇, 两者都判为高质量的只有 10.1%, 只被 FineWeb-Edu 分类器选中的占 35.4%, 只被 DCLM 选中的占 54.4%.

20 个桶怎么合并成质量等级, 由下游实验决定. 作者取一个训练到 70% 的 8B 模型, 用 50B token 继续预训练 (66% 默认混合, 34% 待测桶), 比较 9 个任务的平均分, 把 20 个桶归为 5 档 (原文 Table 2):

| 等级 | 桶 | token (B) | 占比 |
|---|---|---|---|
| High | 19 | 553 | 12.63% |
| Medium-High | 18 | 504 | 11.52% |
| Medium | 12–17 | 2,023 | 46.24% |
| Medium-Low | 7–11 | 894 | 20.43% |
| Low | 0–6 | 402 | 9.18% |

在 8B 模型训练 1T token 的对比中 (Table 9), 单独用 FineWeb-Edu 分类器时高质量 token 占 8%, 平均分 59.0; DCLM 分类器 11%, 58.4; 集成后 25%, 59.4. 高质量 token 占比是单个分类器的 2 到 3 倍, 平均分持平略高.

### 5.2 两种合成策略

作者观察到低分文档噪声和错误多, 高分文档写得好, 格式规整, 于是分开处理:

- **低质量文档**: 用 WRAP 的维基风格 prompt 改写, 去掉错误和冗余, 改善格式.
- **高质量文档**: 目标是得到更多不重复的 token, 并把知识压缩出来. 用四个 prompt: 多样问答对 (是非题, 开放题, 选择题等, 问文中的事实并给答案), 精简改写 (Distill, 改写成简洁清楚的段落), 抽取知识 (重写文中的知识, 丢掉无信息内容), 知识列表 (把关键信息整理成列表). prompt 要求保留数字等具体细节.

输入越长, 模型越倾向于过度简化, 所以文档先切成若干段, 每段由完整的行组成, 长度不超过一个上限: 维基改写 512, Distill 2000, 抽取知识 1400, 问答对和知识列表 1000 (都含 prompt 和对话模板的 token). 超长的单行直接丢弃.

生成模型是 Mistral NeMo 12B Instruct, FP8 推理, top-p 0.9, 温度 0.5. 后处理包括: 去掉不完整的输出和 Markdown 加粗符号, 去掉「Here is a paraphrased version:」这类前缀, 去掉包住整个回答的引号, 丢弃短于 50 token 的输出. 问答对打乱顺序, 按原段落长度保留一定数量, 附在原段落之后. 合成数量 (原文 Table 3, 单位 B token):

| 来源 | 输入 | prompt | 输出 |
|---|---|---|---|
| Low | 403.0 | 维基改写 | 336.3 |
| High | 451.3 | 维基改写 | 372.9 |
| High | | 多样问答对 | 499.5 |
| High | | Distill | 157.6 |
| High | | 抽取知识 | 303.6 |
| High | | 知识列表 | 203.2 |

中等质量的文档因时间和资源限制没有用于合成. 最终在 99 个快照 (CC-MAIN-2013-20 到 CC-MAIN-2024-30) 上得到 6.3T token: 4.4T 全局去重后的原始 token 加 1.9T 合成 token. 只取最高分真实数据和多样问答对的子集 Nemotron-CC-HQ 为 1.1T. 作者指出 FineWeb-Edu 和 DCLM 只做了分片近似去重, 约 80% 是模糊重复, 因此 Nemotron-CC 的不重复真实 token 约为它们的 4 倍.

### 5.3 结果

8B 模型训练 1T token, 数据中 73% 是待测的英语 Common Crawl, 27% 是固定的代码, 论文, 书, 专利, 维基混合 (原文 Table 5):

| 数据集 | MMLU | 10 任务平均 |
|---|---|---|
| FineWeb-Edu | 42.9 | 53.2 |
| DCLM | 53.4 | 57.0 |
| Nemotron-CC (6.3T) | 53.0 | 57.8 |
| Nemotron-CC-HQ (1.1T) | 59.0 | 60.1 |

HQ 子集比 DCLM 的 MMLU 高 5.6, 平均高 3.1. 全量版与 DCLM 持平, 但不重复的 token 多得多, 适合更长的训练. 8B 模型训练 15T token, 其中 7.2T 来自 Nemotron-CC, MMLU 70.3, 10 任务平均 64.7; 同为 15T token 的 Llama 3.1 8B 在同一评测设置下为 65.3 和 64.2 (Table 6).

合成数据的单独作用 (Table 10, 8B 模型, 1T token):

| 混合 | 说明 | 平均 |
|---|---|---|
| LQ-Base | 含低质量文档的原始数据 | 52.5 |
| LQ-Synthetic | 低质量文档换成维基改写 | 54.0 |
| HQ-Base | 高质量文档重复 8 遍, 低中质量减少 | 55.8 |
| HQ-Synthetic | 8 遍中的 4 遍换成合成数据 | 56.7 |

改写低质量文档平均提高 1.5, ARC-Easy, ARC-Challenge, OpenbookQA, CommonsenseQA 提高 1.80 到 4.75 个点, 但也有个别任务略降. 作者认为下降可能来自合成时引入的错误信息. 把高质量文档的 4 遍重复换成合成数据, 多数任务提高.

## 6. 对比与边界

### 6.1 四种做法对比

| | Phi-1 / Phi-1.5 | Cosmopedia | WRAP | Nemotron-CC |
|---|---|---|---|---|
| 生成模型 | GPT-3.5 | Mixtral-8x7B-Instruct | Mistral-7B-Instruct | Mistral NeMo 12B Instruct |
| 种子 | 主题, 受众, 函数名, 网页样本 | 课程大纲, 网页聚类主题, 指令数据 | C4 段落 (≤300 token) | Common Crawl 分段 (512–2000 token) |
| 知识来源 | 生成模型 | 生成模型 | 原网页 | 原网页 |
| 合成规模 | <1B (phi-1), 约 20B (phi-1.5) | 25B | 与 C4 同量级 | 1.9T |
| 与真实数据的比例 | phi-1.5 训练中 80% 合成 | 只用合成数据训练 cosmo-1b | 1:1 | 1.9T 合成, 4.4T 真实 |
| 主要风险 | 风格贴近评测集 | 幻觉, 主题覆盖 | 不加新知识 | 合成误差, 生成成本 |

两条路线的区别可以用一个问题判断: 删掉原网页, 生成文本里的信息还在不在? 从主题生成的数据里, 信息来自生成模型, 所以生成模型越强越好, 但它的错误和偏好会直接进入数据. 改写数据里, 信息来自原网页, 生成模型只改变表达方式, 因此能用小模型大规模生成, 但模型能学到的知识上限仍由原网页决定.

### 6.2 边界

**模型坍塌.** Shumailov et al. (2305.17493) 指出, 用模型生成的数据训练模型会造成不可逆的缺陷: 原始分布的尾部先消失, 多代之后学到的行为收敛到方差很小的点估计. 他们在高斯混合模型, VAE 和语言模型上都观察到这一现象, 语言模型部分只做了微调设置, 只看到早期迹象. 本篇的方法都只用一代生成, 且与真实数据混合. 随着网上模型生成的文本越来越多, 以后从 Common Crawl 采到的「真实数据」里也会混入生成文本.

**事实错误.** Cosmopedia 报告了历史和数学上的幻觉; Nemotron-CC 改写低质量文档后有个别任务分数下降. 从主题生成的数据没有原文可对照, 错误更难检出.

**评测风格贴合.** WRAP 把部分收益归于改写风格接近下游评测的风格, 其消融也显示改写风格与评测域匹配时效果更好. Phi-1 的 CodeExercises 与 HumanEval 格式相同. 这类收益有一部分来自格式对齐, 不全是能力提升. $n$-gram 去污染和嵌入距离去污染都检测不到这种贴合.

**知识上限.** WRAP 明确写道改写不能带来新知识. 对需要大量事实的任务, 合成数据的作用是让模型更快学会已有数据里的知识, 不能代替更多的真实数据.

**成本与许可.** Cosmopedia 的 25B token 用了 1 万多 GPU 小时. 生成模型的许可会传递到数据和下游模型: Nemotron-CC 因为 Llama 3 标注的许可问题没有使用 FineWeb-Edu 分类器. 用闭源 API 生成的数据, 还要看服务条款是否允许用来训练其他模型.

**规模外推.** Phi 系列只在 1.3B 上报告; WRAP 最大 1.3B, 训练 300B token; Nemotron-CC 在 8B, 15T token 上验证. 合成数据在更大模型上的收益是否保持, 公开结果有限.
