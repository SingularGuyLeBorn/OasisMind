# 3.1 预训练数据: 来源, 合成, 处理

预训练语料的主体是网页. 公开数据集几乎都从 Common Crawl 出发, 它从 2007 年起定期抓取公开网页, 到 2024 年中已有 100 个快照, 总量在 PB 级. 从这些原始 HTML 到一份能送进分词器的文本, 中间要删掉绝大部分内容, 再把剩下的按来源重新配比. 三篇文章按数据流经的顺序分工: [3.1.1](./3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) 把抓取变成带语言标签的正文, [3.1.3](./3.1.3-数据处理/3.1.3-数据处理.md) 做质量过滤, 去重, 配比和去污染, [3.1.2](./3.1.2-数据蒸馏/3.1.2-数据蒸馏.md) 处理真实数据不够用时怎样用模型生成.

## 1. 数据在流水线上怎么变少

### 1.1 每一步删掉多少

各家公开的删除比例说明, 收集阶段和处理阶段都在大幅删数据. RefinedWeb 在文档准备阶段 (URL 过滤, 正文抽取, 语言识别) 结束时只剩原始文档的 48%, 主要是语言识别删掉的; 质量过滤后剩 23%; 去重后合计删掉近 90%. Dolma 的 CCNet 流水线把 175.1TB 处理成 27.7TB, 删掉 84.2%. 到模型分类器这一步, DCLM 只保留打分前 10% 的文档, FineWeb-Edu 从 FineWeb 的 15T token 里留下 1.3T.

删得最狠的步骤恰好排在最前面. 语言识别用 fastText 线性分类器, 只需查表, 求平均和一次小矩阵乘, 不用 GPU 就能扫完整个 Common Crawl; 越往后的步骤单文档越贵, FineWeb-Edu 的分类器打完 15T token 要 6000 H100 小时. 按单文档成本从低到高排列, 是为了让昂贵步骤的输入尽量小: RefinedWeb 先做 MinHash 近重复去重再做后缀数组子串去重, 后者的处理量少了近 40%.

### 1.2 删完之后不够用

预训练需要的 token 数一直在涨, Llama 3.1 8B 训了 15T token. 按上面的保留比例, 只用分类器筛出的前 10% 网页, 撑不起这个量级. 一条路是重复: Muennighoff 等人在最多 9B 参数, 900B token 的实验中发现, 计算预算固定时重复不超过 4 遍与新数据几乎等价. 另一条路是用模型生成, 这是 3.1.2 的主题.

两条路都和过滤阈值相互牵制. 设第 $i$ 个来源 (下文称「域」) 有 $N_i$ 个唯一 token, 采样比例为 $\alpha_i$, 总训练 token 为 $T$, 这个域被看的遍数约为 $\alpha_iT/N_i$. 过滤越严 $N_i$ 越小, 遍数越多; 遍数超过 4 以后重复的收益开始下降. Dolma 的毒性过滤就碰到过这一冲突: 阈值 0.0004 删掉 29.1% 到 34.9% 的数据, 下游效果更好, 但凑不够计划的 token 数, 最终用了只删 5.5% 到 7.3% 的阈值 0.4.

## 2. 三篇的分工与接口

### 2.1 收集: 从 WARC 到带语言标签的正文

[3.1.1](./3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) 从 Common Crawl 的三种文件讲起. WET 是现成的纯文本, 但它把整页 HTML 转成文本时不区分正文和导航, 菜单, 页脚; FineWeb 用 1.71B 模型训 28B token 做对照, 从 WARC 用 trafilatura 自己抽取的版本明显好于 WET, 此后的实验全部基于 WARC. DCLM 改用 resiliparse, 理由是快 8 倍而质量相当. 抽取之后依次是 URL 黑名单 (RefinedWeb 约 460 万个域名, 人工排查高频命中后去掉了误杀的正常站点), fastText 语言识别 (阈值 0.65 或 0.5), 以及跨快照的 URL 去重.

网页之外的来源各有自己的问题. 代码要判许可: The Stack v2 只有 3.07% 的仓库在元数据里带许可, 其余靠 ScanCode 在文件级检测, 最后收宽松许可和无许可的文件, 共 619 种编程语言. 数学网页的公式在抓取的 HTML 里多是未渲染的 MathJax 源码, 通用抽取器会把它们丢掉; OpenWebMath 识别出 LaTeX 在网页里的七种编码方式, 专门写了抽取流程, 得到 14.7B token. 书, 论文, 百科每个 token 的信息密度高, 常被上采样: LLaMA 第一代的配比里维基百科看了 2.45 遍, 书 2.23 遍, GitHub 只有 0.64 遍.

### 2.2 处理: 规则, 去重, 分类器, 配比, 去污染

[3.1.3](./3.1.3-数据处理/3.1.3-数据处理.md) 接在收集之后. 启发式规则 (C4, Gopher) 对每篇文档算几个统计量, 超阈值就删, 能在 CPU 上逐文档并行. 去重分精确, 近重复, 子串三种粒度, 近重复用 MinHash-LSH: 两篇文档切成 $n$-gram 集合 $A$, $B$, Jaccard 相似度 $J(A,B)=|A\cap B|/|A\cup B|$, 随机哈希下两者最小哈希相同的概率恰好等于 $J$. FineWeb 取 112 个哈希分 14 桶, 每桶 8 个, 相似度 0.75 的文档对有 77% 的概率成为候选.

去重之后是模型质量分类器和配比. DCLM 在同一起点上比较了 8 种筛选方法, 最便宜的 fastText 分类器 Core 分数最高 (30.2), PageRank 反而不如不筛. 配比问题是在概率单纯形上找各域的采样比例 $\alpha$: DoReMi 训练两个 280M 的小模型, 按各域超额损失调权重, 把 The Pile 的网页权重从 11% 提到 61%; RegMix 训练 512 个 1M 参数的代理模型, 拟合「配比到目标」的回归器, 总计算量约为训练一个 1B 模型的 2%. 最后用 $n$-gram 匹配把评测集从训练数据里删掉.

### 2.3 合成: 补上网页里缺的文本

[3.1.2](./3.1.2-数据蒸馏/3.1.2-数据蒸馏.md) 的方法分两条路线. 从主题生成: prompt 给出主题, 受众, 体裁, 让模型从头写, Phi-1 的合成教科书和 Cosmopedia 的 25B token 属于这一类, 文本里的知识来自生成模型. 改写已有文本: prompt 给出一段真实网页, 让模型换风格重写或抽出问答对, WRAP 和 Nemotron-CC 属于这一类, 知识来自原网页, 用 7B 到 12B 的指令模型就够.

判断一种合成数据属于哪条路线, 可以问: 删掉原网页, 生成文本里的信息还在不在. 两条路线的风险因此不同. 从主题生成的数据会继承生成模型的错误和偏好, 没有原文可对照, 幻觉更难检出; 改写数据只改变表达方式, 不能带来新知识, 模型能学到的知识上限仍由原网页决定. 两者都只用一代生成并与真实数据混合, 以避开 Shumailov 等人描述的多代递归训练造成的分布尾部消失.

## 3. 几个数据集与做法的对照

### 3.1 四个公开网页数据集

把收集和处理的选择放进同一张表 (各数据集原文, 3.1.1 第 6.1 节有完整版):

| | RefinedWeb | FineWeb | DCLM-baseline | Dolma v1.6 |
|---|---|---|---|---|
| 规模 | 约 5T token, 公开 600B | 15T (GPT-2 分词器) | 3.8T, 来自 240T 的候选池 | 约 3T (Llama 分词器) |
| 来源 | 网页 | 网页 | 网页 | 网页, 代码, Reddit, 论文, 书, 百科 |
| 抽取 | WARC + trafilatura | WARC + trafilatura | WARC + resiliparse | WET (经 CCNet) |
| 语言阈值 | 0.65 | 0.65 | 沿用 RefinedWeb | 0.5 |
| 质量过滤 | 规则 + 逐行修正 | 规则; Edu 子集加分类器 | 规则 + fastText 取前 10% | Gopher 规则 + C4 句末标点规则 |
| 去重 | MinHash + 子串 + 跨份 URL | 逐快照 MinHash | Bloom filter 近似去重 | Bloom filter 三级精确去重 |

DCLM 在 7B-1x 规模 (6.9B 参数, 138B token) 上比较了四个已有数据集, Core 分数依次是 C4 34.2, Dolma-V1 35.0, RedPajama 35.3, RefinedWeb 36.9. 只用网页的 RefinedWeb 排第一, 混了维基百科一类整理过的来源的 RedPajama 和 Dolma-V1 反而落后, DCLM 因此以 RefinedWeb 的规则为起点再加分类器.

去重范围的选择出人意料. FineWeb 对 96 个快照做全局 MinHash, 最老的快照被删掉 90%, 留下的部分广告和关键词列表更多, 训练效果远低于 RefinedWeb; 改成每个快照内部单独去重后才追平. 作者的解释是去重的收益主要来自删掉在所有快照里都出现的大簇, 重复次数少的簇再去重可能有害. 这个结论依赖快照结构, 书和代码没有快照, 全局去重仍是默认做法.

### 3.2 「高质量」由下游效果定义

几组实验都指向同一个方向: 传统上被认为高质量的文本, 不一定是训练效果最好的文本. DCLM 的 fastText 分类器换正例做消融, 用 OpenHermes-2.5 指令数据加 ELI5 高赞回答作正例, 7B-1x 的 Core 是 41.0; 用维基百科作正例只有 35.7. 网页筛得足够好之后, 再混入维基, 书, arXiv 这类来源, DCLM-baseline 的分数反而下降 1.2. RegMix 发现与下游表现正相关最强的是 Pile-CC 网页, DoReMi 也把网页的权重提到 61%.

人的质量判断与训练效果也对不上. DCLM 请 16 名标注者对约 500 篇文档打分, 标注者之间一致率 71%; AskLLM 与人工标签的 ROC-AUC 约 82%, Core 只有约 28.5, fastText 的 ROC-AUC 约 73%, Core 却超过 31. 分类器也会把正例或标注 prompt 的偏好写进数据分布: FineWeb-Edu 围绕「对中小学教育是否有用」打分, MMLU 从 33 升到 37, ARC 从 46 升到 57, 但商业和娱乐类内容被压低. 换一个目标能力, 分类器要重新选正例.

## 4. 读法与边界

### 4.1 按关心的问题读

搭数据流水线的读者按 3.1.1, 3.1.3 的顺序读, 3.1.3 第 6.1 节给出了全流程的步骤顺序, 可以当清单用. 只关心去重的读者直接看 [3.1.3](./3.1.3-数据处理/3.1.3-数据处理.md) 第 2 节, 那里有 Bloom filter 的误报率推导, MinHash-LSH 的候选概率 $P(s)=1-(1-s^b)^r$ 和各家参数的手算. 关心配比的读者看 3.1.3 第 4 节的 DoReMi 与 RegMix, 再到 [3.4.2](../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4 节看配比在训练中途怎样分阶段切换.

做代码或数学模型的读者, 收集部分读 3.1.1 第 4, 5 节 (The Stack v2 与 OpenWebMath), 再读 [3.5.1](../3.5-继续预训练与长上下文训练/3.5.1-继续预训练/3.5.1-继续预训练.md), Code Llama 和 Llemma 的继续训练配比就建在这些数据上. 考虑合成数据的读者读 3.1.2 第 6 节的四种做法对比和边界; 数据配比怎么评估, 小模型上用哪些基准才有信号, 见 [3.6.2](../3.6-预训练评估/3.6.2-通用基准/3.6.2-通用基准.md) 第 4 节.

### 4.2 结论的适用范围

本节的绝大多数结论来自小模型消融: FineWeb 的过滤消融是 1.71B 参数训 28B token, DCLM 用 412M 到 7B 的五档规模. DCLM 检查过排名能否外推, 10 种方法在 400M-1x, 1B-1x, 3B-1x 上的分数与 7B-1x 的 Pearson 相关依次为 0.838, 0.956, 0.982, 规模越接近外推越可靠. 更大模型对低质量数据的容忍度是否让某些过滤变得多余, 公开论文没有系统结论.

另外两条限制贯穿三篇. 一是语言: 四个网页数据集都只留英语, C4 和 Gopher 的停用词, 词长, 句末标点规则都为英语设计, 中文没有空格分词, 这些规则要改成按字符或按分词结果计算. 二是 token 计数: 各数据集用不同的分词器计 token, 跨数据集只能比量级; 分词器本身怎么训练, 词表大小怎样改变同一份语料的 token 数, 见 [3.2](../3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md). 固定算力下参数量和 token 数怎么分, 见 [3.3.2](../3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).
