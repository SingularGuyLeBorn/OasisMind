# 3 预训练

生成式大模型的预训练目标是因果语言建模: 只看上文, 预测下一个 token, 在海量未标注文本上最小化交叉熵. BERT 的掩码语言建模双向看上下文, 适合理解类任务, 但不能直接续写, Decoder-only 基座已不再用它做主目标. 注意力, 位置编码, FFN 这些结构本身的推导在 [第 2 章](../2-核心原理与架构/2-核心原理与架构.md); 预训练之后的 SFT, 偏好对齐和蒸馏在 [第 4 章 后训练](../4-后训练/4-后训练.md).

本章关心的是目标函数之外的全部决定: 训什么文本, 文本怎么切成 token, 模型多大, 形状怎样, 用几千张卡怎么并行, 学习率和 batch 怎么排, 故障了怎么续上, 窗口怎么加长, 训到一半怎么判断走没走偏. 这些决定在一次训练里只能做一回, 改错了往往要从头再来, 所以各节写的都是公开技术报告里的具体数字和对照实验.

## 1. 一次预训练要定下的东西

### 1.1 目标函数带来的两个约束

因果语言建模的 loss 按 token 平均. 设一段文本被分词器切成 $T$ 个 token $x_1,\dots,x_T$, 模型参数为 $\theta$, 每 token 的交叉熵是 $\frac{1}{T}\sum_{t}-\log p_\theta(x_t\mid x_{<t})$. 这个量直接依赖分词器: 同一段文本, 词表小的切得碎, $T$ 大, 每个 token 好猜; 词表大的切得粗, $T$ 小, 每个 token 难猜. 所以 token 级 loss 和困惑度只能在同一个分词器下比, 跨模型比较要换成每字节比特 (BPB), 这是 [3.2](./3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md) 和 [3.6](./3.6-预训练评估/3.6-预训练评估.md) 共用的结论.

第二个约束来自计算量. 训练一个参数量为 $N$ 的稠密模型看 $D$ 个 token, 矩阵乘的计算量约为 $C\approx6ND$: 前向每 token 每参数 2 次浮点运算, 反向对输入和对权重各算一次梯度, 再加 4 次. 预算 $C$ 由卡数和工期决定, 于是 $N$ 和 $D$ 此消彼长. 这条式子是 [3.3](./3.3-模型配置与Scaling-Laws/3.3-模型配置与Scaling-Laws.md) 所有估算的起点, 也决定了 [3.4](./3.4-训练过程/3.4-训练过程.md) 里训练要跑多少天.

### 1.2 六节的先后

按一次训练的时间顺序, 先有语料 ([3.1](./3.1-预训练数据/3.1-预训练数据.md)), 再在有代表性的语料子集上训练分词器 ([3.2](./3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md)). 分词器定下之后, 语料才有确定的 token 数, Scaling Laws 的实验和外推才有统一的口径 ([3.3](./3.3-模型配置与Scaling-Laws/3.3-模型配置与Scaling-Laws.md)). 规模和形状定下之后选并行方式, 排学习率, batch 和数据阶段, 准备故障恢复 ([3.4](./3.4-训练过程/3.4-训练过程.md)). 主体训练的末段加长窗口, 或者换成领域数据接着训 ([3.5](./3.5-继续预训练与长上下文训练/3.5-继续预训练与长上下文训练.md)). 评估贯穿全程 ([3.6](./3.6-预训练评估/3.6-预训练评估.md)): 小模型数据消融, 主训练的进度监控, 长上下文阶段的放行门槛, 用的是不同的量.

这个顺序只是决定做出的先后, 信息流是双向的. 形状要服从流水线的段数, 日程要考虑之后能不能从中间 checkpoint 接着训, 数据过滤阈值要和总 token 预算一起定. 第 2 节把这些反向约束逐条摊开.

### 1.3 全章共用的记号

下面几个记号在本章各篇里反复出现, 含义在这里定一次. 同一个字母在不同论文里口径不同, 最容易混的几处在 [3.3](./3.3-模型配置与Scaling-Laws/3.3-模型配置与Scaling-Laws.md) 再展开.

| 记号 | 含义 | 常见取值 (Llama 3 405B) |
|---|---|---|
| $N$ | 参数量 (Kaplan 不计嵌入, Chinchilla 计入) | 405B |
| $D$ | 训练 token 数 | 15.6T |
| $C$ | 训练算力, $C\approx6ND$ | $3.8\times10^{25}$ FLOPs |
| $V$, $d_{\mathrm{model}}$ | 词表大小, 残差流宽度 | 128,000, 16,384 |
| 压缩率 $r$ | 字符数除以 token 数 | 英语 3.94 字符/token |
| BPB | 总码长除以 UTF-8 字节数 | 与分词器无关 |

$D/N$ 常写成「每参数 token 数」. Chinchilla 的算力最优比例约为 20, Llama 3 405B 是 38.5, Llama 3 8B 训到约 15T token, 每参数约 1900 个 token. 同样的 $D$, 换一个分词器对应的文本量就变了, 所以比较两家的训练 token 数之前, 先看它们各用哪个分词器计数.

## 2. 前后节之间的约束

### 2.1 数据与分词器

分词器在数据之后训练, 又反过来改变数据的规模. Llama 3 把词表从 Llama 2 的 32K 扩到 128K, 英语样本上的压缩率从 3.17 升到 3.94 字符/token, 同样的英语文本 token 数少了约 19.5%. 训练语料里某种语言或某类文本 (代码, LaTeX) 占比低, 分词器学到的对应合并就少, 这部分文本切得更碎, 训练和推理都更贵. 所以训练分词器用的语料配比, 实际上也是一次多语言配比的决定.

数据集之间的比较也受分词器影响. FineWeb 的 15T 按 GPT-2 分词器计, DCLM 的 3.8T 按 GPT-NeoX 计, Dolma 的约 3T 按 Llama 分词器计, 三个数只能比量级. 这一点在 [3.1.1](./3.1-预训练数据/3.1.1-预训练数据收集/3.1.1-预训练数据收集.md) 的数据集对照表后面有专门说明.

### 2.2 规模与数据量

Scaling Laws 给出的 $D_{\mathrm{opt}}$ 假设数据无限, 每个 token 只看一次. 实际的高质量文本有限: DCLM 和 FineWeb-Edu 用分类器筛网页时都只留约 10%, Nemotron-CC 的作者指出这样的数据量撑不起 15T token 的训练. Muennighoff 等人的实验给出了重复的上限: 重复 4 个 epoch 以内与新数据几乎等价, 约 16 个 epoch 之后再重复几乎没有价值. 过滤越严, 每个来源的唯一 token 越少, 同样的训练 token 数下重复遍数越多, 所以 [3.1.3](./3.1-预训练数据/3.1.3-数据处理/3.1.3-数据处理.md) 的过滤阈值和 [3.3.2](./3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md) 的 $D$ 要一起定.

推理成本把最优点进一步推离 Chinchilla. 部署后每生成一个 token 约需 $2N$ FLOPs, 预期推理量越大, 越应该训练更小的模型并多给数据. 工业模型的做法与此一致: 小模型大幅过度训练, 旗舰模型接近算力最优. 合成数据 ([3.1.2](./3.1-预训练数据/3.1.2-合成与改写数据/3.1.2-合成与改写数据.md)) 是数据不够时的另一条路, Nemotron-CC 合成了 1.9T token, 与 4.4T 真实数据混用.

### 2.3 形状与训练系统

Scaling Laws 只给出一个标量 $N$. 把它展开成层数和宽度时, Kaplan 的实验显示宽深比在 40 倍范围内变动, loss 相差在 3% 以内, 形状的最终取值由系统决定. Llama 3 405B 的 126 层来自 16 段流水线每段 8 层, 再从首末两段各去掉一层以平衡嵌入和输出头的负载; 128 个查询头和 8 个 KV 头都能被张量并行度 8 整除, 每个张量并行 rank 恰好持有一个 KV 头.

推理侧的约束也要在训练前定. KV 头数几乎不影响训练 loss, 但决定 KV cache: Llama 3 70B 用 8 个 KV 头, 每 token 缓存 320 KiB, 换成 64 头 MHA 是 2.5 MiB. MoE 把参数量拆成两个: 总参数决定显存和卡数, 激活参数决定每 token 的计算. DeepSeek-V3 总参数 671B, 激活 37B, 训练算力按激活参数算是 $3.29\times10^{24}$ FLOPs, 但专家要分布到多机上, 引入专家并行和 all-to-all 通信.

### 2.4 日程, 继续训练与评估

学习率日程决定了训练能不能中途延长, 能不能分叉. 余弦日程的周期要和训练长度对齐, 周期设得比实际训练长 25% 以上性能明显下降; WSD (warmup, 恒定, 衰减三段) 把衰减推到最后 10% 到 20%, 恒定段的任一 checkpoint 都能接一段衰减得到可用的模型. 这一性质在三处派上用场: Scaling Laws 实验可以一次训练产出多个长度的结果; 数据评估可以从中途 checkpoint 分叉一段短退火来比较; 继续预训练如果有衰减之前的 checkpoint, 就不必重新把学习率升上去.

评估也跟着日程走. WSD 恒定段的 checkpoint loss 偏高, 衰减后才反映真实水平, 中途评测前要先做一次短衰减. Llama 3 用 40B token 的退火评估新数据; 长上下文阶段每加长一次, 都要求短上下文评测完全恢复, 大海捞针在当前长度上全部正确, 才进入下一阶段.

## 3. 公开配方

### 3.1 从预算到配置: Llama 3 405B

Llama 3 的技术报告给出了从预算到训练结束的一条完整链条, 本章各节的数字可以按这个顺序串起来:

| 决策 | 取值 | 所在节 |
|---|---|---|
| 预算与规模 | $3.8\times10^{25}$ FLOPs; IsoFLOP 外推建议 402B 参数, 16.55T token; 实际 405B, 15.6T | [3.3.2](./3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md) |
| 形状与词表 | 126 层, 宽度 16,384, 128 个查询头, 8 个 KV 头, 词表 128K | [3.3.1](./3.3-模型配置与Scaling-Laws/3.3.1-确定模型结构与参数/3.3.1-确定模型结构与参数.md) |
| 并行 | 8192 到 16,384 张 H100, TP 8, PP 16, 128K 阶段加 CP 16; MFU 38% 到 43% | [3.4.1](./3.4-训练过程/3.4.1-训练框架选择/3.4.1-训练框架选择.md) |
| 日程 | 峰值学习率 $8\times10^{-5}$, 8000 步 warmup, 余弦降到 1%; batch 4M, 8M, 16M token 三档 | [3.4.2](./3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) |
| 运行 | 54 天里 466 次中断, 419 次意外, 有效训练时间 90% 以上 | [3.4.3](./3.4-训练过程/3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md) |
| 长上下文 | 8K 到 128K 分 6 个阶段, 约 800B token | [3.5.2](./3.5-继续预训练与长上下文训练/3.5.2-长上下文训练与数据/3.5.2-长上下文训练与数据.md) |

表里有两处数字对不上直接相乘的结果. 一是 IsoFLOP 拟合的常数 $(\alpha,A)=(0.53,0.29)$ 只给了两位有效数字, 直接代入得到约 10.5T, 与报告的 16.55T 不符; $C$ 在 $10^{25}$ 量级时, $\alpha$ 变动 0.01 就让结果差 1.8 倍. 二是 402B 和 405B 的差别: 大预算下 IsoFLOP 曲线在谷底附近变平, 规模的小幅偏移对 loss 影响很小, 最终取值还要服从形状和并行的整除关系.

训练中途配比也在变: 增加非英语数据, 上采样数学, 后期加入更新的网页, 下采样被判为低质量的子集, 最终配比是通用知识 50%, 数学与推理 25%, 代码 17%, 多语言 8%. 最后 40M token 在 128K 长度上把学习率线性降到 0, 对退火期间的 checkpoint 做 Polyak 平均, 得到最终的预训练模型.

### 3.2 三家配方的分歧

把 DeepSeek-V3 和 Qwen3 放进同一张表, 能看出哪些选择已经趋同, 哪些仍在分化:

| | Llama 3 405B | DeepSeek-V3 | Qwen3-235B-A22B |
|---|---|---|---|
| 结构 | 稠密, GQA | MoE, MLA, 671B 总参 / 37B 激活 | MoE, GQA, 235B 总参 / 22B 激活 |
| 训练 token | 15.6T | 14.8T | 36T (整个 Qwen3 系列) |
| 词表 | 128,000 | 128K | 151,669 |
| 学习率日程 | 余弦 | 恒定到 10T, 余弦, 末段两级阶梯 | 分 S1, S2, S3 三阶段, S2 加快衰减 |
| 长上下文 | 8K 到 128K, 6 个阶段 | 4K 起, YaRN 扩到 32K 和 128K, 各 1000 步 | 4096 到 32768, ABF 把 RoPE 基频从 $10^4$ 提到 $10^6$ |

趋同的部分: 块结构都是 Pre-Norm, RoPE, SwiGLU 或 MoE FFN; 词表都在 12.8 万到 15.2 万之间; 长上下文都放在末段, 主体训练用 4K 到 8K 的短序列, 理由都是注意力的计算随长度增长. 分化的部分集中在日程和结构上. DeepSeek-V3 前 10T token 保持恒定学习率, 继承了 WSD 可以从恒定段接着训的性质; Llama 3 用一条 120 万步的余弦. DeepSeek-V3 的非专家参数只占总参的几个百分点, 专家由 64 路专家并行分摊, 因此可以不用张量并行; Llama 3 是稠密模型, 张量并行放在单机 8 卡的 NVLink 内.

Qwen3 的 36T token 远超前两者, 其中 S2 阶段约 5T 是更高质量的 STEM, 代码和推理数据. 高质量数据放在学习率低的末段, 是三家共同的做法, 也是 Llama 3 退火, MiniCPM 衰减段混入高质量数据的同一思路.

负责训练稳定性的读者读 [3.4.2](./3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 5 节和 [3.4.3](./3.4-训练过程/3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md), 一个讲防发散的设置, 一个讲 spike 之后的回滚流程和监控信号. 要在开源基座上学新领域或加长窗口的读者, 直接读 [3.5](./3.5-继续预训练与长上下文训练/3.5-继续预训练与长上下文训练.md), 需要的学习率日程背景都在 3.4.2 第 1, 2 节. 只想知道一个评测分数靠不靠得住, 读 [3.6](./3.6-预训练评估/3.6-预训练评估.md) 的首页和 3.6.2 第 3 节的格式敏感性.
