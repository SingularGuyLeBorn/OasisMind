# 4.3.2 PEFT 方法全景

> 相关阅读: [4.3 PEFT](../4.3-PEFT.md) · [4.3.1 LoRA 低秩适应](../4.3.1-LoRA低秩适应/4.3.1-LoRA低秩适应.md) · [4.2.1 SFT 原理与实践](../../4.2-SFT/4.2.1-SFT原理与实践/4.2.1-SFT原理与实践.md)

参数高效微调 (PEFT) 只训练少量参数. 材料是 BitFit, Adapter, Prefix-tuning, Prompt Tuning, P-Tuning 的原论文, He 等人的统一视角, 以及 Lialin 等人的综述.

[4.3.1](../4.3.1-LoRA低秩适应/4.3.1-LoRA低秩适应.md) 讲了 LoRA. 这一篇把其他主要 PEFT 方法放在一起: 先按「改什么参数」分类并算参数量, 再逐类看它们改了模型的哪一部分, 在什么基准上接近全参数微调, 差距多大; 然后用 He 等人的统一视角把 Adapter, Prefix, LoRA 写成同一个式子, 看由此得出的设计结论; 最后比较推理延迟, 多任务部署和序列长度上的代价.

## 1. 分类与参数量

### 1.1 三类加混合

Lialin 等人的综述 *Scaling Down to Scale Up* 按「改什么参数」分三类, 再加混合方法:

| 类别 | 改动 | 代表方法 | 推理时额外开销 |
|---|---|---|---|
| 选择式 (selective) | 只训练原有参数的一个子集 | BitFit, 只训上层 | 无 |
| 附加式 (additive) | 新增模块或输入向量, 原参数冻结 | Adapter, Prefix-tuning, Prompt Tuning | Adapter 增加串联计算; 软提示占用序列长度 |
| 重参数化式 (reparametrization) | 用低维参数表示权重更新 | LoRA, DoRA, 内在维度方法 | 合并后无 |
| 混合式 (hybrid) | 组合多类 | MAM Adapter, UniPELT | 取决于组合 |

综述在后续版本中覆盖了 2019 年到 2024 年中的五十多篇论文, 并在最大 11B 的模型上比较了 15 种方法. 下文按类别展开, 第 5 节讲 He 等人的统一视角.

### 1.2 参数量对照

取一个 Llama 2 7B 形状的模型: 32 层, $d=4096$, FFN 中间维 11008, 注意力投影都是 $4096\times4096$, 线性层无偏置. 各方法典型配置的参数量:

| 方法 | 配置 | 计算 | 参数量 |
|---|---|---|---|
| BitFit | 无偏置 | | 不适用 |
| Prompt Tuning | $l=100$ | $100\times4096$ | 0.41M |
| Prefix-tuning | $l=10$, 每层 K 和 V | $32\times2\times10\times4096$ | 2.62M |
| Adapter (Houlsby) | $m=64$, 每层 2 个 | $32\times2\times(2\cdot64\cdot4096+4096+64)$ | 33.82M |
| LoRA | $r=8$, $W_{q,k,v,o}$ | $32\times4\times8\times8192$ | 8.39M |
| LoRA | $r=8$, 全部 7 个线性层 | $32\times(4\times8\times8192+3\times8\times15104)$ | 19.99M |

Prefix 的参数按推理时保留的 $P$ 算, 不含训练时的重参数化 MLP. 底座约 6.74B, 表中最大的 Adapter 约 0.5%, 最小的 Prompt Tuning 约 0.006%.

参数量只是一个维度. Prompt Tuning 参数最少, 但会占 100 个位置的上下文; Adapter 参数最多, 还带推理延迟; LoRA 合并后没有推理开销.

## 2. 选择式: BitFit

### 2.1 改动

BitFit 冻结所有权重矩阵, 只训练偏置向量. 在 BERT 中, 偏置出现在注意力的 $Q, K, V$ 投影, 注意力输出投影, MLP 的两层线性变换和 LayerNorm 中. 以第 $\ell$ 层第 $m$ 个头为例:

$$
Q^{m,\ell}(x)=W_q^{m,\ell}x+b_q^{m,\ell},\quad K^{m,\ell}(x)=W_k^{m,\ell}x+b_k^{m,\ell},\quad V^{m,\ell}(x)=W_v^{m,\ell}x+b_v^{m,\ell} \tag{1}
$$

多头注意力把各头的 $Q, K, V$ 合成 $h_1^\ell$, 之后的 MLP 和 LayerNorm 按原文式 (1) 到 (5) 写成:

$$
\begin{aligned}
h_2^\ell&=\mathrm{Dropout}(W_{m_1}^\ell h_1^\ell+b_{m_1}^\ell), &
h_3^\ell&=g_{LN_1}^\ell\odot\frac{(h_2^\ell+x)-\mu}{\sigma}+b_{LN_1}^\ell,\\
h_4^\ell&=\mathrm{GELU}(W_{m_2}^\ell h_3^\ell+b_{m_2}^\ell), &
h_5^\ell&=\mathrm{Dropout}(W_{m_3}^\ell h_4^\ell+b_{m_3}^\ell),\\
\mathrm{out}^\ell&=g_{LN_2}^\ell\odot\frac{(h_5^\ell+h_3^\ell)-\mu}{\sigma}+b_{LN_2}^\ell
\end{aligned} \tag{2}
$$

$h_2^\ell$ 是注意力输出投影, $h_4^\ell$ 是 MLP 的升维层 (BERT-base 从 768 到 3072), $h_5^\ell$ 是降维层. 训练的是式 (1) 和式 (2) 里所有的 $b$, 再加任务分类头. BERT-base 和 BERT-large 的偏置分别占总参数的 0.09% 和 0.08% (原文 §2).

训练设置 (附录 A.2): AdamW, batch 16. 全参数的学习率在 $\{1\mathrm{e}{-5},2\mathrm{e}{-5},3\mathrm{e}{-5},5\mathrm{e}{-5}\}$ 中选, 只训偏置时在 $\{1\mathrm{e}{-4},4\mathrm{e}{-4},7\mathrm{e}{-4},1\mathrm{e}{-3}\}$ 中选, 原因是小学习率在部分任务上收敛太慢. 用大学习率后, 多数任务 8 个 epoch 以内收敛.

### 2.2 结果

BERT-base, GLUE 验证集 (原文 Table 3):

| 训练的参数 | 占比 | 平均 |
|---|---|---|
| 全参数 | 100% | 82.3 |
| 全部偏置 (BitFit) | 0.09% | 82.4 |
| $b_q$ + $b_{m2}$ | 0.04% | 81.1 |
| 只 $b_{m2}$ | 0.03% | 80.0 |
| 只 $b_q$ | 0.01% | 76.6 |
| 随机选同样数量的参数 | 0.09% | 78.5 |
| 全部冻结 | 0 | 62.1 |

$b_{m2}$ 是 MLP 中间层 (升维那一层) 的偏置. 两个结论. 一是参数选在哪里很重要: 同为 0.09%, 偏置 82.4, 随机参数 78.5. 二是偏置里贡献集中在 $b_q$ 和 $b_{m2}$, 二者合起来是全部偏置的一半, 平均只掉 1.3 分.

换到 BERT-large 测试集 (Table 2): 全参数 81.8 (Houlsby 报告的数字) 和 81.5, Adapter (3.6%) 81.1, Diff-Prune (0.5%) 81.5, BitFit (0.08%) 80.9. 在 GLUE 这类小数据分类任务上, BitFit 与其他方法的差距在 1 分以内.

### 2.3 哪些偏置在动

原文把偏置的变化量定义为 $\frac{1}{\dim(b)}\lVert b_0-b_F\rVert_1$, 即微调前后每一维的平均绝对变化. Figure 1 (RTE 任务, 其他任务的图形相近) 显示 $b_q$ 和 $b_{m2}$ 变化最大, 而 key 的偏置 $b_k$ 变化为零.

$b_k$ 不动可以直接推出来. 对一个查询 $q$, 第 $j$ 个位置的注意力 logit 是 $q^\top(W_kx_j+b_k)=q^\top W_kx_j+q^\top b_k$. 后一项 $q^\top b_k$ 与 $j$ 无关, 对同一个查询的所有位置都加了同一个常数, softmax 对整体平移不变, 所以注意力权重与 $b_k$ 无关, $b_k$ 的梯度为零. 原文引用 Cordonnier 等人 (2020) 的理论观察说明这一点.

两类偏置单独训练的结果说明二者缺一不可: 只训 $b_q$ 平均 76.6, 只训 $b_{m2}$ 80.0, 合起来 81.1, 全部偏置 82.4.

### 2.4 数据规模, 泛化与局限

- **泛化差距**: 全参数微调多数情况下训练准确率接近 100%, BitFit 的训练误差与测试误差之差明显更小 (原文 §4).
- **数据量**: 在 SQuAD v1.0 的递增子集上 (Figure 2), 数据少时 BitFit 好于全参数, 数据多时反过来. 原文的结论是 BitFit 适合小到中等规模的训练数据; 数据量大时, 它与其他稀疏微调方法相当.

原文据此提出一个解释: 微调主要是把语言模型预训练中已有的知识暴露出来, 而不是学习新的任务相关语言知识.

BitFit 依赖模型有偏置. LLaMA 系列的线性层不带偏置 (只有 RMSNorm 的缩放参数), 此时 BitFit 无从下手, LLaMA-Adapter V2 这类方法改为同时解锁 norm, bias 和 scale 参数 (见 6.1 节). 此外 BitFit 的证据集中在 BERT 规模的分类任务上; 在 GPT-3 175B 上 (LoRA 论文 Table 4), BitFit 用 14.2M 参数在 WikiSQL 上 71.3, 低于全参数 73.8 和 LoRA 73.4.

## 3. 附加式: Adapter

### 3.1 结构

Houlsby 等人在每个 Transformer 层里串联两个 Adapter, 一个在多头注意力之后, 一个在 FFN 之后. 每个 Adapter 是带残差的瓶颈:

$$
h\leftarrow h+f(hW_{\mathrm{down}})W_{\mathrm{up}},\qquad W_{\mathrm{down}}\in\mathbb R^{d\times m},\ W_{\mathrm{up}}\in\mathbb R^{m\times d},\ m\ll d \tag{3}
$$

$f$ 是非线性激活. 含偏置每个 Adapter 有 $2md+d+m$ 个参数. 原文用的规模大约是原模型参数的 0.5% 到 8%. 初始化让 Adapter 接近恒等映射, 训练开始时模型行为与底座一致. Pfeiffer 等人后来提出只在 FFN 之后插一个 Adapter 的更省的变体.

### 3.2 结果与代价

原文在 26 个文本分类任务上测试, GLUE 上用 3.6% 的每任务参数, 与全参数微调差 0.4 分以内. 每个新任务只加少量参数, 不影响已有任务.

BERT-large 的 GLUE 测试集 (原文 Table 1): 全参数平均 80.4, Adapter 尺寸在 $\{8,\dots,256\}$ 中按任务选取时 80.0 (每任务 3.6% 参数), 固定尺寸 64 时 79.6 (2.1%). 解完 9 个任务, 全参数需要 9 倍于 BERT 的总参数量, Adapter 是 1.3 倍. 最优尺寸因任务而异: MNLI 选 256, 最小的 RTE 选 8. 另外 17 个公开分类任务上, Adapter 同样落后全参数 0.4%, 而全参数需要 17 倍的总参数.

原文还有三组消融:

- **只训 LayerNorm**: BERT-base 的 LayerNorm 参数只有 4 万个, 只训它们时 CoLA 掉约 3.5%, MNLI 掉约 4%. Adapter 训练时也为每个任务训练新的 LayerNorm 参数, 但单靠这部分不够.
- **去掉部分层的 Adapter**: 训好后不重训, 直接移除连续若干层的 Adapter 再评估. 移除 0 到 4 层的 Adapter 对 MNLI 几乎没有影响, 高层的 Adapter 影响更大. 这与 AdapterDrop 去掉低层 Adapter 的做法一致.
- **结构变体**: 在 Adapter 内加 batch/layer norm, 增加 Adapter 层数, 换 tanh 激活, 只在注意力层内插, 以及与主干并联, 都没有带来明显提升. 5.3 节 He 等人的实验里并联好于串联, 两篇的并联设计与评测任务不同, 结论不能直接对照.

代价是推理延迟. Adapter 串联在主干上, 每层多两次小矩阵乘和一次非线性, 不能像 LoRA 那样合并进原权重. LoRA 论文 Table 1 测了 GPT-2 Medium 在一张 Quadro RTX8000 上的单次前向延迟 (100 次平均). batch 1, 序列长 128 时, 基线 19.8ms, Houlsby 结构 25.8ms (+30.3%), Lin 等人的单 Adapter 结构 23.9ms (+20.7%); batch 32, 序列长 512 时, 增幅降到 3.0% 和 2.2%. 在线服务通常 batch 小, 序列短, 这个代价最明显. 模型需要张量并行切分时, 多出来的层还会增加 AllReduce 等同步操作.

### 3.3 多 Adapter 组合

单个 Adapter 对应一个任务. 任务多了以后, 有两项工作分别研究怎样把多个 Adapter 的知识组合起来, 以及怎样在推理时裁掉一部分 Adapter 来省计算.

- **AdapterFusion (Pfeiffer 等人 2021)**: 两阶段. 先为每个任务单独训练 Adapter (知识抽取), 再学一个组合层把多个 Adapter 的输出融合 (知识组合). 两阶段分开避免了多任务学习的灾难性遗忘和数据配比问题. 在 16 个 NLU 任务上好于全参数微调和多任务学习.
- **AdapterDrop (Rücklé 等人 2021)**: 训练和推理时去掉低层的 Adapter. 同时推理多个任务时, 计算开销可以动态减少, 任务性能只有很小的下降; 对 AdapterFusion 剪枝后推理效率提升, 性能完全保持.

## 4. 附加式: 软提示

### 4.1 软提示与 Prefix-tuning

硬提示是离散的文本, 搜索它是组合优化. 软提示是若干个不对应任何词的连续向量, 直接在嵌入空间用梯度优化. 软提示的方法按「加在哪一层」和「怎么参数化」区分.

Li 与 Liang (2021) 在每一层注意力的 key 和 value 前拼一段可训练向量 $P_k, P_v\in\mathbb R^{l\times d}$, $l$ 是前缀长度. 对 GPT-2 这类仅解码器模型, 序列是 $[\text{PREFIX};x;y]$; 对 BART 这类编码器-解码器, 编码器和解码器各加一段前缀 $[\text{PREFIX};x;\text{PREFIX}';y]$.

直接优化 $P$ 会让训练不稳定, 性能也略差; 原文脚注说预实验中直接优化前缀对学习率和初始化很敏感. 所以原文用一个 MLP 重参数化: $P[i,:]=\mathrm{MLP}(P'[i,:])$, $P'$ 是更小的矩阵. 训练完只保留 $P$, MLP 丢掉. 默认训练 10 个 epoch, batch 5, 学习率 $5\times10^{-5}$.

存储上, Prefix-tuning 比全参数少存 1000 倍参数 (约 0.1%). 全量数据上, 表格转文本 (E2E, WebNLG, DART, GPT-2) 与全参数相当, XSum 摘要 (BART) 略差; 低数据设置下两类任务平均都好于全参数; WebNLG 测试集一半是训练中没见过的类别, 在这部分上 Prefix-tuning 外推更好.

### 4.2 Prompt Tuning

Lester 等人 (2021) 只在输入层拼 $l$ 个软 token, 不改中间层, 可以看作 Prefix-tuning 的简化. 实验在 T5 上, 默认配置: 先对 T5.1.1 做 10 万步 LM adaptation, 提示长度 100, 用类别标签的词嵌入初始化. 主要发现:

- **规模**: 模型越大, Prompt Tuning 和全参数微调的差距越小. T5-XXL (11B) 上它追平了多任务全参数微调, 而任务专属参数少 20,000 倍以上. 原文 Figure 2: 每个任务一份 11B 的模型拷贝, 对比每任务 20,480 个提示参数.
- **长度** ($\{1,5,20,100,150\}$, Figure 3(a)): 多数规模下长度超过 1 才能有好结果; 所有规模超过 20 后收益都很小, 超过 100 对较大模型略有损害. XXL 用 1 个 token 也表现很好, 模型越大, 需要的条件信号越少.
- **初始化** (Figure 3(b)): 在 $[-0.5,0.5]$ 均匀随机初始化最差, 从 5000 个高频词嵌入采样居中, 类别标签初始化最好. 规模到 XXL 时三者差别消失.
- **预训练目标** (Figure 3(c)(d)): T5 原始的 span corruption 目标不适合冻结模型加提示; 中等规模模型甚至学不会输出合法标签, 得 0 分. 改用 LM adaptation 继续训练后效果好, 训练越久越好, 到 10 万步 (原 T5 预训练步数的 10%).
- **领域迁移** (§5): 在 SQuAD 上训练, 在 MRQA 2019 的域外数据集上零样本评测, Prompt Tuning 在多数数据集上好于全参数, TextbookQA 上 F1 高 12.5. 领域差别小的 DROP (同为 Wikipedia) 上全参数更好. 从 QQP 迁移到 MRPC, 准确率高 3.2, F1 高 3.1.

原文 §6 还给了一个部署上的用法, 提示集成 (prompt ensembling). 同一任务训练 $N$ 个提示, 相当于得到 $N$ 个模型, 但底座共享. 一份 T5-XXL 拷贝占 42 GiB, 传统集成要存 $N$ 份并跑 $N$ 次前向; 提示集成只需把同一个样本复制成 batch 为 $N$ 的输入, 每条配不同提示, 一次前向完成. 多任务混合 batch 用的是同一机制.

用 20,480 这个数可以反推: T5-XXL 的隐藏维 $d=4096$, $20480/4096=5$, 对应长度 5 的提示. 与 Prefix-tuning 相比 (原文 §3), 默认的 100 个 token 比 Prefix-tuning 默认的 10 个前缀长, 但只改输入层, 不改每一层的激活, 所以参数仍更少.

### 4.3 P-Tuning 与软提示的共同代价

- **P-Tuning (Liu 等人 2021)**: 连续提示和离散提示拼接使用, 连续部分由一个双向 LSTM 加两层 MLP 组成的提示编码器生成, 只在输入层. 目标是减少离散提示措辞变化带来的性能波动. 在 LAMA 知识探测和 SuperGLUE 上提升了 GPT 类模型的 NLU 表现.
- **P-Tuning v2 (Liu 等人 2022)**: 在每一层都加独立的软提示 (deep prompt tuning), 可训练参数 0.1% 到 3%. 重参数化 MLP 改为可选, 分类任务用随机初始化的分类头代替 LM head 的词表映射. 结果是在 300M 到 10B 的模型上都能追平全参数微调, 包括 Prompt Tuning 表现差的小模型和序列标注任务.

v2 与 Prefix-tuning 的结构很接近, 区别主要在面向 NLU 任务的这些实现选择.

从 Prefix-tuning 到 P-Tuning v2, 软提示类方法有三个共同的代价:

- **占序列长度**: 每个软 token 占一个位置. LoRA 论文 §1 认为这会减少下游任务可用的序列长度, 可能是提示类方法表现不如其他方法的一个原因.
- **优化难**: LoRA 论文 Table 4 和 Figure 2 显示 Prefix 类方法性能随参数量不单调, prefix-embedding 超过 256 个 token, prefix-layer 超过 32 个 token 后明显下降.
- **规模依赖**: Prompt Tuning 在小模型上与全参数差距大, 这是 P-Tuning v2 改为每层加提示的动机.

## 5. 统一视角: He 等人 (2022)

### 5.1 Prefix-tuning 改写成加法

He 等人 *Towards a Unified View of Parameter-Efficient Transfer Learning* 先把 Prefix-tuning 的一个注意力头展开. 查询 $x$, 原上下文 $C$, 前缀 $P_k, P_v$:

$$
\mathrm{head}=\mathrm{softmax}\bigl(xW_q\,[P_k;CW_k]^\top\bigr)\begin{bmatrix}P_v\\CW_v\end{bmatrix}
=(1-\lambda(x))\,\mathrm{Attn}(xW_q,CW_k,CW_v)+\lambda(x)\,\mathrm{Attn}(xW_q,P_k,P_v) \tag{4}
$$

$\lambda(x)$ 是 softmax 归一化后落在前缀上的注意力权重之和 (原文式 (8)):

$$
\lambda(x)=\frac{\sum_i\exp(xW_qP_k^\top)_i}{\sum_i\exp(xW_qP_k^\top)_i+\sum_j\exp(xW_qW_k^\top C^\top)_j} \tag{5}
$$

式 (4) 可以逐步验证. 记前缀部分的 logit 为 $a_i=(xW_qP_k^\top)_i$, 原上下文部分为 $c_j=(xW_qW_k^\top C^\top)_j$, 两部分的指数和分别为 $S_P=\sum_i e^{a_i}$, $S_C=\sum_j e^{c_j}$. 拼接后的 softmax 在前缀位置 $i$ 上的权重是 $e^{a_i}/(S_P+S_C)$, 可以拆成 $\frac{S_P}{S_P+S_C}\cdot\frac{e^{a_i}}{S_P}$, 前一个因子就是 $\lambda(x)$, 后一个因子是只在前缀内部做的 softmax. 原上下文位置同理拆成 $(1-\lambda(x))\cdot e^{c_j}/S_C$. 对 value 加权求和后, 两部分各自是一个标准注意力, 式 (4) 成立. 这一步只用到 softmax 的定义, 没有近似.

由此还能看出前缀的作用强度不是常数. $\lambda(x)$ 随查询 $x$ 变化: 某个查询与前缀 key 的点积大, 它就更多地读前缀; 原上下文很长时 $S_C$ 变大, $\lambda(x)$ 随之变小. 同样长度的前缀, 在长输入上对每个位置的影响会被稀释.

于是 Prefix-tuning 等价于 (原文式 (9)):

$$
h\leftarrow(1-\lambda(x))\,h+\lambda(x)\,\Delta h,\qquad \Delta h=\mathrm{softmax}(xW_qP_k^\top)P_v \tag{6}
$$

把 $W_1=W_qP_k^\top$, $W_2=P_v$ 看成两个矩阵, $f=\mathrm{softmax}$, 这就是一个以 $x$ 为输入, 激活为 softmax 的瓶颈 Adapter, 再用 $\lambda(x)$ 做门控组合 (原文式 (10)). 瓶颈宽度是前缀长度 $l$.

### 5.2 四个设计维度

原文 Table 1 把各方法放进同一张表:

| 方法 | $\Delta h$ 形式 | 插入方式 | 修改的表示 | 组合函数 |
|---|---|---|---|---|
| Prefix-tuning | $\mathrm{softmax}(xW_qP_k^\top)P_v$ | 并联 | 注意力头 | $h\leftarrow(1-\lambda)h+\lambda\Delta h$ |
| Adapter | $\mathrm{ReLU}(hW_{\mathrm{down}})W_{\mathrm{up}}$ | 串联 | 注意力 / FFN 输出 | $h\leftarrow h+\Delta h$ |
| LoRA | $xW_{\mathrm{down}}W_{\mathrm{up}}$ | 并联 | 注意力的 key / value | $h\leftarrow h+s\cdot\Delta h$ |

「并联」指 $\Delta h$ 用模块的输入 $x$ 计算, 与原模块并行; 「串联」指用原模块的输出 $h$ 计算. 把三种组合函数放在一个参数化里: $h\leftarrow(1-\gamma)h+\beta\,\Delta h$. $\gamma=0,\beta=1$ 是 Adapter, $\gamma=0,\beta=s$ 是 LoRA, $\gamma=\beta=\lambda(x)$ 是 Prefix-tuning. 新方法可以在这四个维度上任意组合, 例如把 Adapter 改成并联, 或者给它加 LoRA 式的缩放.

### 5.3 实验结论

实验在 XSum 摘要, WMT16 En-Ro 翻译 (BART/mBART) 和 MNLI, SST-2 分类 (RoBERTa) 上做.

原文 §4.2 先比较了已有方法. MNLI 和 SST-2 上, 用不到 1% 的参数就能接近全参数 (全参数 87.6 / 94.6, BitFit 0.1% 为 84.7 / 93.7, Prefix 0.5% 为 86.3 / 94.0, LoRA 和 Adapter 0.5% 都是 87.2 / 94.2). XSum 和 En-Ro 上, 参数加到 5% 仍有明显差距, 加到 10% 以上差距依然显著. 原文据此提醒: 在仅编码器模型的 GLUE, 或 E2E 这类较简单的生成基准上「与全参数相当」的结论, 不一定能推广到其他标准基准, 原因可能涉及样本量, 任务难度和模型结构. 所以后面的设计维度分析主要在 XSum 和 En-Ro 上做.

串联与并联的对比 (原文 Table 3, BART, 瓶颈 $r=200$):

| 方法 | 参数 | XSum R-1/R-2/R-L | En-Ro BLEU |
|---|---|---|---|
| Prefix, $l=200$ | 3.6% | 43.40 / 20.46 / 35.51 | 35.6 |
| 串联 Adapter, 注意力 | 3.6% | 42.01 / 19.30 / 34.40 | 35.3 |
| 串联 Adapter, FFN | 2.4% | 43.21 / 19.98 / 35.08 | 35.6 |
| 并联 Adapter, 注意力 | 3.6% | 43.58 / 20.31 / 35.34 | 35.6 |
| 并联 Adapter, FFN | 2.4% | 43.93 / 20.66 / 35.63 | 36.4 |

0.1% 预算下的翻译结果 (原文 Table 4): Prefix $l=30$ 为 35.2, 去掉门控改成直接相加降到 34.9; 并联 Adapter 在 FFN 上 33.0, 在注意力上 33.7; 多头并联 Adapter (注意力) 35.3, 比单头版本高 1.6. 并联 Adapter (注意力) 的瓶颈从 200 降到 30 损失 1.9 BLEU, Prefix 只损失 0.4.

1. **并联好于串联**: 并联 Adapter 在 FFN 上比串联 Adapter 在 XSum 上高 1.7 ROUGE-2, 翻译上高 0.8 BLEU.
2. **修改 FFN 还是注意力看预算**: 参数较多时, 改 FFN 好于改注意力. 原文的解释是 FFN 学到的是任务相关的文本模式, 而注意力学的是位置间交互, 前者需要更大容量. 参数只有 0.1% 时, 改注意力的多头方法 (prefix, 多头并联 Adapter) 至少高 1.6 BLEU. Prefix 长度从 200 降到 30 只损失 0.4 BLEU.
3. **缩放组合好于直接加**: 并联 Adapter 加缩放后 ROUGE-2 高 0.56. LoRA 的缩放 $s=4$ 时 XSum 44.59/21.31, $s=1$ 时 44.17/20.83. 这组对比都改 FFN, 参数都是 6.1% (Adapter 瓶颈 512, LoRA 秩 102). 不缩放的并联 Adapter 为 44.35/20.98, 介于两档 LoRA 之间; 加 $s=4$ 后到 44.85/21.54. 把 $s$ 设成可训练标量没有更好, 为 44.56/21.31.

### 5.4 MAM Adapter 与 UniPELT

结合上面三条, 原文提出 Mix-And-Match Adapter: 注意力上用 prefix-tuning ($l=30$, 小预算就够), FFN 上用缩放的并联 Adapter (瓶颈 $r=512$, 大容量), 总共 6.7% 参数.

| 方法 | 参数 | XSum R-1/R-2/R-L | En-Ro BLEU |
|---|---|---|---|
| 全参数 (原文复现) | 100% | 44.81 / 21.94 / 36.83 | 37.3 |
| MAM Adapter | 6.7% | 45.06 / 21.90 / 36.87 | 37.5 |
| BitFit | 0.1% | 40.64 / 17.32 / 32.19 | 26.4 |
| Prompt Tuning | 0.1% | 38.91 / 15.98 / 30.83 | 21.0 |

分类任务上 MAM 用 0.5% 参数, MNLI 87.4, SST-2 94.2, 比同为 0.5% 的 LoRA 和 Adapter 在 MNLI 上高 0.2. 生成任务上 BitFit 和 Prompt Tuning 与全参数差 4 到 6 分 ROUGE-1, 差距比在 GLUE 分类任务上大得多.

Mao 等人 (2022) 的 UniPELT 是另一条路: 把 Adapter, Prefix-tuning, LoRA 都作为子模块装进模型, 每个子模块配一个门控, 让训练决定激活哪个. GLUE 上比它包含的最好单个方法高 1% 到 4%, 不同设置下好于全参数微调, 而且通常超过「每个任务分别取最好子模块」的上界. He 等人的统一视角和 UniPELT 发表时间相近, 前者从公式上统一, 后者在模型里并用.

## 6. 多模态, 选型与失效

### 6.1 视觉与多模态中的 PEFT

同样的思路已用到视觉和多模态模型上. 这里只列一手论文给出的数字:

| 方法 | 模型 | 做法 | 一手数字 |
|---|---|---|---|
| VPT (Jia 等人 2022) | ViT | 输入空间加可训练提示; Deep 版每层都加 | 不到 1% 参数, 多数情况好于全参数 |
| CoOp (Zhou 等人 2022) | CLIP | 用可学习向量代替提示模板的上下文词 | 11 个数据集, 1 到 2 shot 即超过手写提示, 16 shot 平均提升约 15% |
| Textual Inversion (Gal 等人 2022) | 文生图扩散模型 | 冻结模型, 为新概念学一个词嵌入 | 3 到 5 张图, 一个词嵌入就够 |
| ControlNet (Zhang 等人 2023) | Stable Diffusion | 锁定原模型, 复制编码层作可训练分支, 用零初始化卷积连接 | 小 (<5 万) 和大 (>100 万) 数据集上训练都稳定 |
| LLaMA-Adapter (Zhang 等人 2023) | LLaMA 7B | 高层拼可学习提示, 零初始化注意力门控 | 1.2M 参数, 5.2 万条指令, 8 张 A100 不到 1 小时 |
| LLaMA-Adapter V2 (Gao 等人 2023) | LLaMA | 额外解锁 norm, bias, scale; 视觉 token 只进早期层 | 14M 参数 |
| NExT-GPT (Wu 等人 2023) | LLM + 编码器 + 扩散解码器 | 只训部分投影层 | 约 1% 参数 |

ControlNet 的「零卷积」和 LLaMA-Adapter 的「零门控」与 LoRA 的 $B=0$ 是同一个约束: 新加的分支在训练开始时输出为零, 模型从底座出发. Houlsby Adapter 的近恒等初始化也属于这一类, 原文主实验用均值为零, 标准差 $10^{-2}$ 的截断高斯初始化; §3.6 在 $[10^{-7},1]$ 范围内扫标准差, 低于 $10^{-2}$ 时结果稳定, 初始化过大时性能下降.

### 6.2 怎么选

下表的每一格都对应前文的一手数字.

| 需求 | 倾向 | 依据 |
|---|---|---|
| 在线服务, 小 batch, 延迟敏感 | LoRA (合并) | Adapter 在 batch 1 时延迟增加 20.7% 到 30.3% (LoRA Table 1) |
| 同一服务内大量任务, 每次请求换任务 | 软提示或不合并的 LoRA | 软提示随输入走, 同 batch 可混任务 (Prompt Tuning Figure 2) |
| BERT 规模分类, 参数极少 | BitFit | GLUE 82.4 对 82.3 (BitFit Table 3) |
| 生成任务 (摘要, 翻译) | LoRA, MAM, 并联 Adapter | BitFit, Prompt Tuning 落后 4 到 6 ROUGE-1 (He 等人) |
| 十亿参数以上, 只想存极少参数 | Prompt Tuning | T5-XXL 追平全参数 (Prompt Tuning §3) |
| 小模型, 序列标注 | P-Tuning v2 | v2 在 300M 到 10B 都追平全参数 |
| 底座没有偏置 (LLaMA 系) | 不用 BitFit | 无偏置参数 |

### 6.3 评测与选型上的失效

前四类问题出在读证据和选方法上: 把某类任务或某个规模上的结论推到别处, 或者只比一个指标.

1. **把分类任务的结论搬到生成任务**: BitFit 和 Prompt Tuning 在 GLUE 上接近全参数, 在 XSum 上差 4 到 6 分. 方法的证据要看任务类型.
2. **软提示用在小模型上**: Prompt Tuning 的优势只在十亿参数以上成立; 小模型应改用每层提示 (P-Tuning v2) 或 LoRA.
3. **提示长度越长越好**: Prompt Tuning 超过 20 后收益很小, 超过 100 对大模型略有损害; Prefix 类方法超过一定长度 (prefix-layer 32, prefix-embedding 256, 见 LoRA 论文) 后性能下降.
4. **只看可训练参数量**: 软提示占序列长度, Adapter 有推理延迟, 全参数和 PEFT 的激活显存相同. 选型时要同时比较这三项.

### 6.4 训练配置上的失效

后三类问题出在训练配置上. 它们的共同表现是方法看上去无效, 而原因在预训练目标, 学习率或参数化方式没有按原文设置.

1. **Span corruption 预训练的模型直接做 Prompt Tuning**: 中等规模模型可能学不会输出合法标签 (Prompt Tuning §3.3), 需要先做 LM adaptation. 现在的仅解码器模型都是语言模型目标, 不受这一条影响.
2. **BitFit 套用全参数的学习率**: 原文全参数用 1e-5 到 5e-5, 只训偏置用 1e-4 到 1e-3. 用小学习率时部分任务收敛很慢, 容易误判为方法无效.
3. **直接优化 Prefix 参数**: 不做 MLP 重参数化时, 训练对学习率和初始化很敏感 (Prefix-tuning §4.3). 换实现或去掉重参数化后结果变差, 先检查这一项.
