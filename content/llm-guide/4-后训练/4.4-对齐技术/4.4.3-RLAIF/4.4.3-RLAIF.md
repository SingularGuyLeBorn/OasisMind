# 4.4.3 RLAIF：用现成 LLM 标偏好

RLAIF（Reinforcement Learning from AI Feedback）把偏好标签从人换成现成的大模型。卡的不是「还要不要奖励模型」，是人标太贵、太慢，规模一上去就跟不上。Lee 等 *RLAIF vs. RLHF*（[arXiv:2309.00267](https://arxiv.org/abs/2309.00267)）在摘要、有帮助对话、无害对话三件事上，把头对头做完：同一套带基线的 REINFORCE，标签换成 PaLM 2 生成的偏好，人评胜率和 RLHF 打平，无害率还更高。他们特意没用 PPO：附录 E 写带价值基线的 REINFORCE 更简单，这件事上够用。

词是 Bai 等 *Constitutional AI*（[arXiv:2212.08073](https://arxiv.org/abs/2212.08073)）先用的。那篇把人标和 AI 标混进奖励模型，再配上书面原则让模型自我批评、改写。Lee 这篇要回答的是另一句：标签全换成 AI，能不能替代人。**不是** [DPO](../4.4.2-无奖励模型的对齐DPO-KTO/01-DPO/01-DPO.md)：DPO 离线分类，不训独立 RM，也不在训练环里找裁判打分。**不是** 把 $\varepsilon$ 写成熵滑动的课设故事。邻居：PPO 的 clip 在 [04-PPO](../4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md)，本篇实验走的不是那条。

## 1. 人标是瓶颈，不是算法名词

RLHF 的流水线熟：SFT 之后采一对回答，人标 $y_w \succ y_l$，拟合 $r_\phi$，再策略梯度。InstructGPT 用 PPO；本篇对照实验用带基线的 REINFORCE。贵的是中间那一刀。现代对话模型一天能吐出的候选，远远超过人能排的对。附录 L 用当时 GPT-4 API 价估算 AI 标：详细 CoT 提示平均 830 个输入 token、理由 61 个输出 token，位置对调两次前向，大约 **$0.06 / 例**。人标按 Google Cloud 分类标注、每篇帖加两条摘要约 304 词，估 **$0.67 / 例**。比值写成 **超过 10 倍便宜**。这是 2023 年那一组价，不是 2026 年任何一家 API 的通用汇率。方向对：标签可以离人。训练员成本、专家标和搭标注基础设施，附录自己说没算进去。

Bai 2022b 已经证明「AI 标能训出比 SFT 更好的助手」，但奖励模型吃的是人标和 AI 标的混合物，也没有和「纯人标 RLHF」做同一套评测。Lee 把对照钉死：三条任务，策略都从 PaLM 2 Extra-Small 出发，奖励模型也是 PaLM 2 XS，标签一边是原数据集的人标，一边是 PaLM 2 Large 的 AI 标。裁判模型指令微调过，**没有**先做 RL。

## 2. 现成模型怎么给出一对偏好

标注器是 off-the-shelf：预训练或指令微调，不为这条下游任务再训一遍，也不先做 RL。规范路径默认 PaLM 2 Large；same-size 和 d-RLAIF 的打分模型才降到 XS。成本附录用当时 GPT-4 API 价估账单，实验骨干仍是 PaLM 2，不要把「现成」读成某家聊天接口。给它一段上下文和两条候选，提示由四截拼起来：导语（preamble）、可选的 few-shot、待标样本、收尾（例如 `Preferred Response=`）。然后取生成 token「1」和「2」的对数概率，做 softmax，得到软标签，例如 $[0.6,0.4]$。写成

$$
p_1=\frac{\exp(\ell_1)}{\exp(\ell_1)+\exp(\ell_2)},\qquad p_2=1-p_1,
$$

其中 $\ell_i$ 是编号 token 的对数概率。不是让模型自由写「左边更好」再正则抽答案。概率落在两个编号上，后面 RM 才能吃交叉熵。他们也提过从自由文本里抽偏好、或做成 one-hot，最后选 softmax，因为实现直接、比 one-hot 多一点分布信息。

CoT 解码用贪心 $T=0$，最长 512 token，上下文上限 4096。self-consistency 才把温度抬到 $0.3$–$1.0$。

位置会偏。同一对候选，左右一换，小模型更容易钉死同一个栏位。附录 Table 4，摘要任务、`Detailed + CoT 0-shot`：PaLM 2 L / S / XS 在对调之后仍偏好同一栏位的比例是 **18% / 21% / 56%**。他们的修法是每对做两次前向，第二次对调顺序，把两份偏好分布平均。这是实现手续，不是另一条损失。

Chain-of-thought 走两步。先把收尾换成「考虑连贯、准确、覆盖，解释哪条更好。Rationale:」，解码一段理由；再把原提示、理由、标准收尾拼回去，才取「1」「2」的概率。Figure 3 就是这件事。few-shot 时，示例里也可以带一段理由给它模仿。

![AI 标注器先写理由再对 1/2 做 softmax](./images/fig-rlaif-cot-softmax.png)

> 图 1：一对候选进导语，先解码 CoT，拼回提示后再取 token「1」「2」的对数概率做 softmax。虚线指向位置偏置：对调顺序会改分布。

**图 1 解析**

- 从左到右五框。黄框是上下文加两条候选。绿框是导语，few-shot 可有可无。
- 蓝框是第一次前向，只出理由。青框把提示、理由、收尾拼在一起。
- 橙框才是偏好：对 token「1」「2」的对数概率做 softmax，得到 $p_1,p_2$。页脚写 off-the-shelf，不是已经训好的 RM。
- 虚线注脚是位置偏置。修法在正文：对调再平均，不要指望 softmax 自己消掉栏位偏好。

Table 2 把提示扫了一遍。对齐率（AI 软标签二值化之后对人标的准确率）在摘要 / 有帮助 / 无害三列。`Base 0-shot` 是 76.1% / 67.8% / 69.4%。最好的一组相对它只高 **+1.9 / +1.3 / +1.7** 个点。CoT 在摘要上稳定有用；对话两条任务上，CoT 主要是配 `Base` 导语才涨。详细导语帮摘要，对话上好坏参半。few-shot 更刺：无害任务上 `Base 2-shot` 到 72.1%，摘要和有帮助却随着示例变多单调往下。摘要上他们随机换 10 个 `Base 1-shot` 示例，最高仍是 76.1%，没超过零样本。`Detailed 8-shot` 在摘要上掉到 69.8%。self-consistency（多条理由再平均）附录 M 写的是严格变差。

Stiennon 估计 OpenAI 摘要偏好的人与人一致率大约 73–77%。PaLM 2 L 最好一组 78.0%，和人打分的噪声带叠在一起。不要写成「AI 裁判已经超过人类」。

## 3. 蒸馏进 RM，或 RL 时当场打分

规范 RLAIF（canonical）把 AI 软标签当成训练集，另训一个 $r_\phi$。损失是交叉熵：RM 打出的标量先 softmax 成分布，再去拟合那份 $[p_1,p_2]$。论文把它写成蒸馏。RM 仍是 PaLM 2 XS，Adafactor，学习率 $10^{-5}$，训到损失和准确率平台，大约 2–3 个 epoch。摘要 RM 的 batch 128，对话 32，最长输入 1152（1024 上下文 + 128 回复）。摘要的 AI 标 RM 从 TL;DR SFT 初始化；人标 RM 从裸 PaLM 2 XS 初始化——他们试过也从 SFT 起，人标验证准确率更低（Table 6：79.3% vs 78.7%）。

策略梯度是带价值基线的 REINFORCE，不是 PPO 的 clip。价值网络和策略都从 SFT 初始化。奖励只打在最后一个 token 上，中间步为 0，$\gamma=1$，回报就是终局 $R_T$。附录 E 把损失写成

$$
\mathcal{L}_{\mathrm{PG}}(\theta)=-\sum_t\log\pi_\theta(A_t\mid X_t)\,\overline{(R_T-V_\psi(X_t))},
$$

横杠表示优势不反传。价值网络自己拟合

$$
\mathcal{L}_V(\psi)=\sum_t(R_T-V_\psi(X_t))^2.
$$

KL 扣进策略梯度，$\beta=0.05$。采样温度 $0.9$，batch 128，学习率 $10^{-5}$，8 个 epoch。终局 checkpoint 先在验证 prompt 上挑 4 个高奖励点，再用现成 LLM 对 SFT 估胜率，外加人工看十几条。训练期裁判模型不再出场，出场的是这份冻结的 RM。便宜、可复现。代价是 RM 会过时：策略已经走到新分布，标签还是旧策略附近采的那批对。迭代 RLAIF（隔一段时间用新策略再标、再训 RM）他们写了，但没做，因为耗时。

Williams (1992) 的基线在这里就是 $V_\psi$。没有 GAE 的 $\lambda$ 混合，没有 clip $\varepsilon$，没有四模型同时驻内存。价值网络只提供基线，不进 PPO 那种代理目标。策略和价值从同一份 SFT 起，损失分开写：策略走 REINFORCE，价值走平方误差。和 [04-PPO](../4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md) 对照时，差的是代理目标和四模型，不是「有没有奖励」。

d-RLAIF 把 RM 拿掉。RL 的每一步，现成 LLM 直接给当前这条 $y$ 打 1 到 10 分。取各数字 token 的似然，归一成分布，加权

$$
s(y\mid x)=\sum_{i=1}^{10} i\,P(i\mid y,x),
$$

再把 $s$ 线性映到 $[-1,1]$ 当奖励。没有成对比较，也没有第二份权重。策略一变，打分模型看到的就是新样本。附录把 RM 过时写成 staleness；d-RLAIF 冲的就是这一层。账单换到训练环里：每条 rollout 都要问一次大模型。他们实验里 d-RLAIF 的打分模型用的是指令微调的 PaLM 2 XS，为了省算力，不是再用 Large。

![三列：人标 RLHF、蒸馏 RLAIF、无 RM 的 d-RLAIF](./images/fig-rlaif-vs-rlhf-direct.png)

> 图 2：左列人标进 RM 再带基线的 REINFORCE；中列现成 LLM 给出 1/2 偏好，蒸馏进 RM 再同一套策略梯度；右列训练时当场 1–10 加权打分，没有独立 RM。

**图 2 解析**

- 三列都从上往下，列之间没有箭头。不要把右列读成「少画了一个橙框，公式还是成对 BT」。
- 左：黄框一对回答，桃框人标，橙框 $r_\phi$，粉框带基线的 REINFORCE。
- 中：蓝框是 softmax 过的 AI 标，橙框仍是 RM，粉框同一套策略梯度。页脚 distill then RL。
- 右：黄框是一条 $y$，青框加权分数，粉框直接策略梯度。页脚 no RM。粉框写的是带价值基线的 REINFORCE，不是 PPO 的 clip。

把人标和 AI 标拼进同一份 RM，附录 K 说他们试过，没有超过「只用人标」。这不是定理。换混合比例、换任务，仍可能有缝。正文只承诺：在他们试过的设定里，拼起来没有额外好处。

## 4. 一手数字：摘要、有帮助、无害

策略一律 PaLM 2 XS。摘要的 SFT 在 Reddit TL;DR 上跑：batch 128，1 个 epoch，Adafactor，学习率 $10^{-5}$，输入最长 1024、输出 128。有帮助和无害两条不再做任务 SFT，直接拿指令微调的 PaLM 2 XS 当起始策略。RM 一律 Adafactor、$10^{-5}$，训到损失和准确率走平，大约 2–3 个 epoch；摘要 RM 的 batch 128，对话 32，最长输入 1152（1024 上下文加 128 回复）。规范 RLAIF 的标注器默认 PaLM 2 L，提示用各任务 Table 2 最好的那档。评测是人：摘要和有帮助做无平局排序，再收成两两胜率；无害任务改成独立判断这条是否无害，因为大量回复同样安全，相对排序没意义。测试集不进训练。

Table 1（人评）：

| 对照 | 摘要 | 有帮助 | 无害率（模型） |
|------|-----:|-------:|----------------|
| RLAIF vs SFT | 71% | 63% | SFT 64% |
| RLHF vs SFT | 73% | 64% | RLHF 76% |
| RLAIF vs RLHF | 50% | 52% | RLAIF 88% |
| Same-size RLAIF vs SFT | 68% | — | — |
| d-RLAIF vs SFT | 74% | 66% | — |
| d-RLAIF vs Same-size | 60% | — | — |

摘要上 RLAIF 对 SFT 71%，RLHF 对 SFT 73%，两人评差没有统计显著。对头 RLAIF vs RLHF 是 50%，也就是说打平。有帮助是 63% / 64% / 52%，同一句话。无害率 RLAIF 88%，RLHF 76%，SFT 64%，这一条 RLAIF 显著高于 RLHF。脚注还写：相对 TL;DR 里的人类参考摘要，RLAIF / RLHF 分别 79% / 80%。长度会偏人评。摘要送到人评的平均字符长度：RLAIF 164、RLHF 161、SFT 132。附录 J 用逻辑回归，输入是长度比，输出是谁赢，再在长度比 $=1$ 处读出控制后的胜率。摘要：RLAIF vs SFT 从 71% 收到 **59%**，RLHF vs SFT 从 73% 收到 **61%**，对头从 50% 收到 47%。有帮助：63%→61%、64%→61%、52%→50%。两条仍高于 SFT，对头仍打平。无害任务没有相对胜率。长度控制把 SFT 的平均长度当参照：SFT 64% 不动，RLHF 76%→78%，RLAIF 88%→**91%**。same-size 对 SFT：68%→59%；d-RLAIF 对 SFT：74%→65%；d-RLAIF 对 same-size：60%→56%。控制后结论方向不变。论文自己写这套事后回归不完美，更干净的做法是训练时加长度辅助损失，他们没做。

HH 数据来自 Anthropic `helpful-base` / `harmless-base`，各约 40k 训练、2k 测试，测试再切成 2/3 验证、1/3 测试。对齐率实验为了迭代快，训练劈成 15% / 10% / 10%，摘要还只留高置信（分数 1、2、8、9），每条任务剩下 3–4k。端到端 RM 仍用**完整**训练劈。

d-RLAIF 的打分提示写死角色。摘要：「你是专家摘要评分员」，给 TEXT（含 subreddit 和标题）和 SUMMARY，要 1–10。有帮助：「你是有帮助且诚实回复的专家评分员」。分数 token 的似然加权之后再映到 $[-1,1]$。打分模型用指令微调的 PaLM 2 XS，Vertex AI 上的公开接口，论文自己写不能保证比特级复现。

Same-size：标注器改成 PaLM 2 XS，策略还是 XS。摘要上对 SFT 68%。和 Large 标注器的 71% 比，p=0.07，按 $\alpha=0.05$ 不显著。标注器是指令微调的 XS，策略是 TL;DR 上的 SFT，**不是**严格的自我改进。有帮助那条 d-RLAIF 才是：打分模型和起始策略同一份 checkpoint，对 SFT 胜率 66%。PaLM 2 XS 是他们能负担端到端 RL 的骨干。标注器可以大到 L，因为只在造数据集时跑一遍；策略做大，rollout 和价值网络一起涨，账单是另一档。Table 1 的打平不要外推成「任意规模 AI 标都等于人标」。

d-RLAIF 在摘要上对 SFT 74%，高于同尺寸蒸馏 RLAIF 的 68%；对头 60%，二项检验相对 50% 显著。论文的读法是：少一次蒸馏、少一次过时。有帮助 66% 是另一列，不要和 74% 并成「一律高 6 个点」。

Table 3，摘要对齐率随标注器变大：PaLM 2 L 78.0%，S 73.8%，XS 62.7%。从 L 换 S 掉约 4 个点，再换 XS 又掉约 11 个点。小模型位置偏置更重，是原因之一，不是全部。规范 RLAIF 的标注器只在造数据集时跑一遍，训练环里不再调用，所以把标注器做大，摊到每条策略更新上并不一定更贵。

附录 G Table 5，人标验证集上的成对准确率：摘要人标 RM 79.3% / AI 标 RM 74.2%；有帮助 76.0% / 67.8%；无害 72.1% / 69.7%。人标 RM 准过 AI 标 RM。这不奇怪，验证集就是人标。有意思的是，即便如此，RLAIF 的策略在两条任务上仍和 RLHF 打平，无害上更高。摘要上 `Base 0-shot` 的 RM 准确率 77.9%，`Detailed + CoT 0-shot` 是 74.2%，和 RL 之后的好坏是反的。附录 N：这两份标签只差对齐率 76.1% vs 78.0%，训出的策略对头人评 59% 偏向更对齐的那份（相对 50% 显著）。RM 准确率相关，但不是「准确率更高的 RM 一定训出更好的策略」；端到端还是要看人评。same-size 那份 XS 标注器训出来的 RM，摘要准确率掉到 66.4%（Table 7）。

人评规模：约 2k 条独特上下文，每条多个回复，约 6k 对 (上下文, 回复)，三人独立评，约 18k 条判断。Kendall $W$ 在 0.6–0.7。摘要的 RL 回复末尾常出现多余句点和空格，他们当成奖励黑客，评测前用规则剪掉，避免评委被版式带走。

self-consistency 在摘要上：贪心一条理由 78.0%；16 条、$T=0.3$ 到 $1.0$ 分别 76.2% / 75.1% / 74.0% / 72.8%。温度越高越差。4 条和 16 条几乎一样（$\pm 0.4\%$）。$T>0$ 把理由写坏了，平均帮不上忙。

## 5. 不是 Constitutional AI，不是 DPO，不是「70% 降本」

Constitutional AI 先让模型按书面原则批评、改写自己的回答（监督阶段），再用 AI 偏好训奖励模型做无害 RL，有帮助一侧往往仍留人标。Lee 这篇没有那套原则，也没有自我改写环。它问的是：成对偏好能不能整份交给现成 LLM，和纯人标 RLHF 对打。把 Claude 的无害训练写成「就是 2309.00267」，槽位错了。Bai 的混合 RM 是「人+AI 一起优化两个目标」；Lee 的规范 RLAIF 是「同一目标，标签来源对换」。d-RLAIF 更进一步，连 RM 都不要。

不要把 LMSYS 式 LLM-as-a-judge 榜和本篇的标注器混成一件事。本篇的 $p_1,p_2$ 是两个编号 token 的 softmax，进 RM 或进加权分数；Arena 的法官模型是另一套提示和另一套胜负。数字不能横抄。

DPO 吃已经标好的 $(x,y_w,y_l)$，损失写在 $\pi_\theta$ 和 $\pi_{\mathrm{ref}}$ 上，训练期不采样、不调用裁判。RLAIF 仍是在线 RL：有独立 RM 或当场打分。d-RLAIF 的 1–10 加权也不是 Bradley-Terry。ORPO / SimPO 更是另一侧。本篇实验没用 PPO 的 $\min$ clip，不要把图里的粉框自动读成 [04-PPO](../4.4.1-基于奖励模型的RL-RLHF-PPO/04-PPO/04-PPO.md) 那四份权重。

不要写「RLAIF 降低标注成本约 70%」或「AI 裁判与人一致率卡在 80%」。论文写的是 **超过 10 倍便宜**，摘要对齐最好 78.0%，人与人大约 73–77%。80% 不是他们的上限命题。2023 年那一组 API 价，不能当成 2026 年任意一家接口的通用汇率。

定性上他们看过摘要。有时 RLHF 会编一个原文没有的年龄，RLAIF 没有；有时 RLAIF 更不通顺，跑句、反复问「How do I get over this?」而原文没问。70 条小样本上，准确 / 覆盖 / 连贯的差异不显著。模式是否规模化，正文留给后续，不要拿 70 条当产品结论。

| | 标签从哪来 | 独立 RM | 训练期打分 | 典型论文 |
|--|------------|---------|------------|----------|
| RLHF | 人 | 要 | 否（用 RM） | InstructGPT / Stiennon |
| 规范 RLAIF | 现成 LLM 的 1/2 softmax | 要 | 否 | Lee 2309.00267 |
| d-RLAIF | 无离线对 | 不要 | 是，1–10 加权 | 同文 §2.2.2 |
| Constitutional AI | 原则 + 自我改写 + 混合偏好 | 要 | 否 | Bai 2212.08073 |
| DPO | 已有成对 | 不要 | 否 | Rafailov 2305.18290 |

## 6. 失效与边界

| 现象 | 机制 | 说明 |
|------|------|------|
| 位置钉死 | 小模型更严重 | XS 56% 同栏；必须对调平均 |
| 把 CoT 当万灵 | Table 2 对话两条上不总涨 | 配错导语会平或掉 |
| 堆 few-shot | 摘要 / 有帮助单调下降 | 8-shot 摘要 69.8% |
| self-consistency | 附录 M | 对齐率严格变差 |
| RM 过时 | 蒸馏标签来自旧分布 | d-RLAIF 换账单，不是免费 |
| 打分模型=策略 | 有帮助那条是严格自改进 | 摘要 same-size 不是 |
| 无害用胜率 | 大量同样安全 | 论文改用 harmless rate |
| 长度偏人评 | 附录 J | 控制后仍高于 SFT，不要忽略 |
| 写成 PPO | 附录 E 是 REINFORCE + 价值基线 | clip 不是本实验 |
| 混过人标没涨 | 附录 K：拼起来对 SFT 71% vs 人标 74% | 他们的设定；不是禁令 |
| 末尾句点刷分 | 附录 H | 评测前剪掉，内容没变 |
| 规模只到 PaLM 2 XS 策略 | 论文自己的骨干 | 不要写成已经验证到百 B |

RLAIF 把人从成对标注里请出去，策略梯度还在。规范路径省的是标注员；d-RLAIF 再省一份 RM，把查询丢进训练环。裁判弱、位置偏、提示堆不好，标签噪声会进 RM，再进策略。需要在线探索、可验证奖励的，仍然走 [02-GRPO](../4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md) 那侧，不要指望换一个 AI 裁判就变成组相对。
