# 4.1 后训练数据

后训练各阶段用的数据形态不同, 来源也不同. 这里的材料是 InstructGPT, Llama 2, Tülu 3 的数据章节, 几篇合成数据与 AI 反馈论文, 以及常用公开数据集的数据卡.

## 1. 问题

1. 后训练数据有哪几类, 各自的格式和用途是什么?
2. 示范数据从哪里来, 人工, 真实用户和合成三种来源各有什么取舍?
3. 偏好数据怎么标注, 标注协议里哪些细节会影响奖励模型?
4. AI 反馈能在多大程度上替代人工偏好?
5. 合成偏好数据时, prompt 数量, 回答来源, 打分模型怎么选?
6. 常用公开数据集的真实规模和构造方式是什么?

## 2. 三类数据

| 类别 | 一条数据的形态 | 用于 | 本章相关位置 |
|---|---|---|---|
| 示范 | $(x, y)$ | SFT | [4.2 SFT](../4.2-SFT/4.2-SFT.md) |
| 偏好 | $(x, y_w, y_l)$, 或一组带排序/打分的回答 | 奖励模型, DPO 及其变体 | [4.4 对齐技术](../4.4-对齐技术/4.4-对齐技术.md) |
| 可验证 prompt | $(x, v)$, $v$ 是判定函数 | RLVR, GRPO | [4.0 后训练概述](../4.0-后训练概述/4.0-后训练概述.md) §7 |

三类数据共享同一个 prompt 池. Tülu 3 (Lambert et al., 2024) §3 的说法是, prompt 代表用户与模型交互的各种方式, 是所有后训练阶段的核心组成. 他们先汇集约 2,333 万条 prompt (其中 OpenMathInstruct 2 一个来源就有 2,197 万条), 最终 SFT 用了 939,344 条, DPO 用了 425,145 条 (Table 7).

## 3. 示范数据

### 3.1 prompt 从哪来: InstructGPT 的做法

示范数据的第一步是 prompt. InstructGPT §3.2 的 prompt 主要来自 OpenAI API 的 Playground: 用户调用的是早期的 InstructGPT 模型 (只在部分示范数据上做过 SFT), 并且收到过「数据可能用于训练」的提示. 生产环境中 API 客户的数据不用. 处理规则:

1. 按长公共前缀启发式去重.
2. 每个用户 ID 最多取 200 条 prompt.
3. 按用户 ID 切分训练, 验证, 测试集, 保证验证集和测试集里没有训练集用户的数据.
4. 训练集里的 prompt 过滤个人身份信息.

第 2 条和第 3 条针对的是少数重度用户: 不限量的话, 他们的 prompt 会主导分布; 不按用户切分的话, 同一用户的相似 prompt 会同时出现在训练集和测试集.

附录 A 的 Table 6 给出了各数据集按来源的 prompt 数:

| 数据集 | 训练集: 标注员撰写 | 训练集: API 用户 | 验证集: 标注员撰写 | 验证集: API 用户 |
|---|---|---|---|---|
| SFT | 11,295 | 1,430 | 1,550 | 103 |
| RM | 6,623 | 26,584 | 3,488 | 14,399 |
| PPO | 0 | 31,144 | 0 | 16,185 |

SFT 数据里标注员撰写的 prompt 远多于用户 prompt. 原因是项目初期, 标注界面要求标注员写一条总的模板指令, 再配若干 few-shot 示例; 对同一条指令抽取不同的 few-shot 示例组合, 就能合成出多条 SFT 数据. 到了 RM 和 PPO 阶段, 用户 prompt 成为主体, PPO 数据则全部来自用户.

最早的 InstructGPT 模型没有现成的指令式 prompt 可用, 因为普通 GPT-3 用户很少这样提问. 于是让标注员自己写三类 prompt:

- **Plain**: 任意任务, 但要保证任务足够多样.
- **Few-shot**: 一条指令, 配多组问答示例.
- **User-based**: 根据 API 候补申请里填写的用例, 写对应的 prompt.

标注员对 RM 数据集中 API prompt 的用途分类 (Table 1):

| 用途 | 占比 |
|---|---|
| 生成 | 45.6% |
| 开放问答 | 12.4% |
| 头脑风暴 | 11.2% |
| 闲聊 | 8.4% |
| 改写 | 6.6% |
| 摘要 | 4.2% |
| 分类 | 3.5% |
| 其他 | 3.5% |
| 封闭问答 | 2.6% |
| 抽取 | 1.9% |

原文用这张表解释 InstructGPT 为什么好于在 FLAN 和 T0 上微调的 GPT-3: 公开 NLP 数据集偏向分类, 问答这类容易自动评测的任务, 而在 API 用户的实际用途里, 分类和问答只占约 18%, 开放式生成和头脑风暴约占 57%. 公开数据集的 prompt 分布与真实用户差得很远, 这是后训练数据要尽量取自真实使用场景的一个理由.

这份分布也有局限. 原文讨论部分指出, 项目大部分时间里 API 用户是从候补名单中选出的, 名单最初的种子是 OpenAI 员工, 用户群因此偏向他们自己的社交圈.

### 3.2 人工撰写

人工撰写的数据质量可控, 但贵, 规模小.

| 数据 | 规模 | 构造方式 |
|---|---|---|
| InstructGPT SFT | 约 13k 训练 prompt | 约 40 名经筛选的标注员撰写示范, prompt 来自 API 与标注员 |
| Llama 2 SFT | 27,540 条 | 供应商标注, 不含 Meta 用户数据 |
| LIMA | 1,000 条 | 社区问答精选 + 作者手写, 详见 [4.2.2](../4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md) §8.1 |
| databricks-dolly-15k | 15,000 余条 | 数千名 Databricks 员工撰写, 8 个类别 |
| OpenAssistant Conversations (OASST1) | 161,443 条消息 | 13,500 多名志愿者众包, 35 种语言 |
| No Robots | 9,500 条 (Tülu 3 使用的数量) | 专业标注员撰写, 覆盖多种开放式类别 |

几条补充:

- Dolly 的 8 个类别是 InstructGPT 论文列出的 7 类 (头脑风暴, 分类, 封闭问答, 生成, 信息抽取, 开放问答, 摘要) 加一个开放式自由类别. 部分类别要求撰写者从维基百科复制参考文本, 数据卡建议使用时去掉其中的方括号引用编号.
- OASST1 有 461,292 条质量评分, 构成 1 万多棵完整标注的对话树. 同一个用户提问下常有多个已排序的回答, 所以它也能拆出偏好对.
- Llama 2 先用了几千条高质量示范, 发现搁置数百万条第三方数据, 改用更少但更好的供应商数据后, 结果明显提升. 他们在 2.7 万条时停止标注 SFT. 原文还观察到, 不同标注平台和供应商产出的数据, 训出的模型差别显著. 他们人工检查了 180 条样本, 发现 SFT 模型的输出常常可以与人工撰写的示范相比, 于是把更多标注预算转向 RLHF 的偏好标注.

### 3.3 真实用户对话

真实用户的 prompt 分布最接近部署场景, 问题在于许可和隐私.

ShareGPT 是用户在网上分享的 ChatGPT 对话, 最早用于训练 Vicuna, 原始数据没有正式发布, 后来的工作大多用社区复刻版本. Tülu 3 §3.1.1 认为它的法律来源存疑: 用户分享时没有同意被用于训练或公开发布. 所以 Tülu 3 不用 ShareGPT, 改用 WildChat (用户与模型的真实交互记录), 并删掉了 UltraFeedback 中来自 ShareGPT 的子集. HelpSteer2 的 prompt 用到了 ShareGPT, 也一并弃用.

许多公开数据集是其他数据集的组合, Tülu 3 为此手动追踪每个子集的来源以核对许可, 最终只保留许可明确的数据.

### 3.4 模型合成

合成数据便宜, 可定制, 也能利用强模型的知识. 主要方法:

**Self-Instruct** (Wang et al., 2022). 从种子任务出发, 让模型生成指令, 输入和输出, 再过滤掉无效的和过于相似的样本, 用结果微调原模型. 在原版 GPT-3 上, Super-NaturalInstructions 上提升 33 个百分点 (绝对值), 与 InstructGPT-001 相当. 在专家撰写的新任务上做人工评测, 与 InstructGPT-001 的差距是 5 个百分点.

**Alpaca**. 按 Self-Instruct 的思路, 用 text-davinci-003 生成 52K 条指令数据, 微调 LLaMA.

**Evol-Instruct** (WizardLM, Xu et al., 2023). 从初始指令出发, 逐步把指令改写得更复杂, 混合各个复杂度的数据微调 LLaMA. 在 GPT-4 自动评测中, WizardLM 在 29 项技能中的 17 项上达到 ChatGPT 能力的 90% 以上.

**UltraChat** (Ding et al., 2023). 不使用人类提问, 用一套框架迭代生成多轮对话, 共 150 万条. 在其上微调 LLaMA 得到 UltraLLaMA.

**SlimOrca**. 从 OpenOrca (GPT-4 增强的 FLAN 推理轨迹) 中再筛一遍: 用 GPT-4 对照 FLAN 的人工标注, 去掉看起来答错的回答, 保留约 50 万条 (数据卡记为 517,982 条). 数据卡称能以约 2/3 的算力达到此前版本的质量.

**角色驱动合成** (Tülu 3 §3.1.2). 合成数据的一个难点是模型容易落入重复的模式, 即模式坍缩. Tülu 3 沿用 Persona Hub 的方法: 把不同的角色描述 (例如「一位专注神经网络的机器学习研究者」) 与合成指令 (例如「出一道编程题」) 拼在一起, 引导模型从不同视角生成数据. 他们使用约 25 万个角色:

- 精确指令遵循: 先为 IFEval 定义的 25 种约束各手写 1 到 2 条示例, 共 33 条种子, 再让 GPT-4o 按角色和种子生成新指令及回答, 共 29,980 条.
- 数学与代码: 零样本让 GPT-4o 按角色出题, 数学解答由 GPT-4o 生成, Python 程序由 claude-3-5-sonnet 生成. 数学约 22 万条, 代码 3.5 万条.

合成数据的质量筛选, 例如 AlpaGasus 打分, Deita 的复杂度与质量评分, 见 [4.2.2](../4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md).

### 3.5 一份实际的配比

Tülu 3 SFT 阶段的 939,344 条 prompt 按类别汇总 (由 Table 7 各行相加计算):

| 类别 | 主要来源 | SFT 条数 | 占比 |
|---|---|---|---|
| 数学推理 | Persona MATH / GSM / Algebra, OpenMathInstruct 2, NuminaMath-TIR | 334,252 | 35.6% |
| 代码 | Persona Python, Evol CodeAlpaca | 142,275 | 15.1% |
| 通用对话 | WildChat 10 万, No Robots, OASST, 硬编码身份问答 | 116,872 | 12.4% |
| 安全与拒答 | CoCoNot, WildJailbreak, WildGuardMix | 110,983 | 11.8% |
| 知识调用 | FLAN v2, SciRIFF, TableGPT | 104,982 | 11.2% |
| 多语言 | Aya | 100,000 | 10.6% |
| 精确指令遵循 | Persona IF | 29,980 | 3.2% |

这份配比是 Tülu 3 针对自己的评测集反复消融得到的 (过程见 [4.2.2](../4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md) §10), 只对它的目标技能和评测集成立. 例如数学占三分之一以上, 是因为他们的评测里有 GSM8K 和 MATH. 换一组目标就要重新消融. 表中的「硬编码」是 24 条关于模型身份的问答, 上采样到 240 条.

每类数据的作用可以从 Tülu 3 Table 10 的去除实验看出 (8B SFT, 每次只去掉一类):

| 设置 | 平均 | GSM8K | MATH | IFEval | AlpacaEval 2 | 安全 |
|---|---|---|---|---|---|---|
| 完整 SFT 混合 | 60.1 | 76.2 | 31.5 | 72.8 | 12.4 | 93.1 |
| 去掉 WildChat | 58.9 | 75.8 | 31.8 | 70.1 | 7.5 | 95.2 |
| 去掉安全数据 | 58.0 | 76.9 | 32.6 | 71.0 | 12.4 | 74.7 |
| 去掉 Persona 数据 | 58.6 | 76.8 | 30.1 | 53.6 | 13.5 | 93.9 |
| 去掉数学数据 | 58.2 | 64.1 | 23.5 | 70.6 | 12.0 | 93.5 |

原文的四条结论:

1. 多样的真实对话数据对多数技能有益, 去掉 WildChat 后 AlpacaEval 2 从 12.4 降到 7.5, 降幅最明显.
2. 安全数据与其他能力基本正交: 去掉它, 其他各项大致不变, 只有安全分从 93.1 降到 74.7. 他们还发现, 加入 CoCoNot 这类对比 prompt (看上去敏感, 实际无害) 能防止模型拒答安全的请求.
3. Persona 数据提升了它针对的技能, 去掉后 IFEval 从 72.8 降到 53.6.
4. 针对技能的高质量数据能大幅提升该技能: 去掉数学数据, GSM8K 从 76.2 降到 64.1, MATH 从 31.5 降到 23.5.

Llama 2 的安全 RLHF 一节有一个方向相同的实验. 有用性数据固定在约 90 万条, 安全数据从 0% 逐步加到 100% (约 10 万条), 共训练 0%, 1%, 10%, 25%, 50%, 100% 六个变体. 随着安全数据增加, 模型处理风险和对抗 prompt 的安全奖励分明显上升, 低分长尾变轻, 有用性奖励的均值基本不变. 原文推测这是因为有用性数据已经足够多.

第 2 条对配比有直接意义: 安全数据的比例可以按安全目标单独调, 不必担心拖累其他能力. 第 4 条说明, 某项技能不达标时, 最直接的办法是补这项技能的专门数据.

## 4. 偏好数据

### 4.1 三种标注格式

| 格式 | 做法 | 代表 |
|---|---|---|
| 二元比较 | 两个回答选一个, 可附偏好程度 | Llama 2, Anthropic HH-RLHF |
| 排序 | 一次给 $K$ 个回答排序, 拆成 $\binom{K}{2}$ 对 | InstructGPT ($K=4$ 到 9), Nectar (7 个) |
| 逐条打分 | 每个回答按若干维度打分, 再二值化成偏好对 | UltraFeedback, Tülu 3 (1 到 5 分, 4 个维度) |

Llama 2 选择二元比较, 理由是这样能最大化收集到的 prompt 的多样性. 排序格式的一个训练细节: 同一 prompt 拆出的比较对高度相关, InstructGPT 发现把它们打散训练一遍就会过拟合, 改为把同一 prompt 的全部比较放在一个 batch 元素里.

### 4.2 Llama 2 的人工标注协议

Llama 2 §3.2.1 的流程:

1. 标注员先自己写一个 prompt.
2. 从**两个不同的模型变体**采样两个回答, 并改变采样温度, 以增加多样性.
3. 标注员强制二选一, 并标注偏好程度: 显著更好, 更好, 略好, 几乎一样/不确定.
4. 有用性和安全性分开标注, 各有一套准则. 安全标注要求重点针对对抗性 prompt.
5. 安全阶段额外打一个安全标签, 把样本分进三档: 选中的安全而另一个不安全 (18%), 两个都安全 (47%), 两个都不安全 (35%). 不收录「选中的不安全而另一个安全」的样本, 理由是更安全的回答也应该更受人偏好.

标注按周分批进行. 原文强调, 策略模型每改进一轮, 输出分布就会移动. 奖励模型如果见不到新分布的样本, 准确率会很快下降. 所以每次开始新一轮微调之前, 都要先用最新的 Llama 2-Chat 采集新的偏好数据, 让奖励模型保持在分布内.

Llama 2 奖励模型训练用到的数据 (Table 6):

| 数据集 | 比较对数 | 平均轮数 | 平均每条 token |
|---|---|---|---|
| Anthropic Helpful | 122,387 | 3.0 | 251.5 |
| Anthropic Harmless | 43,966 | 3.0 | 152.5 |
| OpenAI Summarize | 176,625 | 1.0 | 371.1 |
| OpenAI WebGPT | 13,333 | 1.0 | 237.2 |
| StackExchange | 1,038,480 | 1.0 | 440.2 |
| Stanford SHP | 74,882 | 1.0 | 338.3 |
| Synthetic GPT-J | 33,139 | 1.0 | 123.3 |
| Meta (安全与有用性) | 1,418,091 | 3.9 | 798.5 |
| 合计 | 2,919,326 | 1.6 | 595.7 |

与公开数据集相比, Meta 自己收集的数据轮数更多, 平均更长. 两个公开偏好集的完整规模可以对照数据卡: Anthropic HH-RLHF 训练与测试合计 169,352 条; OpenAI 的 `webgpt_comparisons` 共 19,578 条, 是 WebGPT 项目结束时被标为适合训练奖励模型的全部比较. 两者都比 Llama 2 实际使用的数量多, 差别来自各自的取舍和过滤.

人工标注的天花板: InstructGPT 的训练标注员彼此一致率为 72.6±1.5%, Llama 2 奖励模型在「几乎一样」档的样本对上准确率只有 54.5% 到 55.0% (Table 28). 偏好程度标签可以帮助识别这类难以区分的样本对.

### 4.3 AI 反馈

**Constitutional AI** (Bai et al., 2022 年 12 月). 训练无害助手, 不用任何人工标注的有害输出标签, 人的监督只体现在一组规则或原则上. 分两个阶段: 监督阶段让模型对自己的回答做自我批评和修改, 在修改后的回答上微调; RL 阶段让模型判断两个样本哪个更好, 用这些 AI 偏好训练偏好模型, 再以它为奖励做 RL, 即 RLAIF. 结果是一个无害而不回避的助手: 面对有害请求时解释反对理由, 而不是简单拒绝. 详见 [01-Constitutional-AI](../4.4-对齐技术/4.4.3-RLAIF/01-Constitutional-AI-宪法对齐/01-Constitutional-AI-宪法对齐.md).

**RLAIF vs. RLHF** (Lee et al., 2023). 用现成的大模型生成偏好标签训练奖励模型. 在摘要, 有用对话和无害对话三项任务上, RLAIF 与 RLHF 表现相当. 即使 AI 标注器与策略模型同样大, 甚至就是策略的初始 checkpoint, RLAIF 也能超过 SFT 基线. 他们还提出 d-RLAIF: 不训练奖励模型, RL 中直接让大模型打分, 效果好于标准 RLAIF. 见 [4.4.3 RLAIF](../4.4-对齐技术/4.4.3-RLAIF/4.4.3-RLAIF.md).

**Nectar**. 182,954 个 prompt, 每个 7 个回答. 回答按优先级从多个模型中挑选 (GPT-4 系列, Anthropic HH, GPT-3.5-Turbo-Instruct 优先, 其次是其他模型, 最后才是重复模型的回答). 排序由 GPT-4 按有用性和无害性两套准则给出: 首先要求所有回答都无害, 在请求本身无害时最大化有用性. 数据卡称采取了若干措施缓解位置偏差.

### 4.4 Tülu 3 的合成偏好流水线

Tülu 3 §5.2.1 在 UltraFeedback 流水线的基础上做了三步:

1. **选 prompt**: 包括 SFT 用过的 prompt, 从相同来源采样但 SFT 没用到的 prompt, 去掉 TruthfulQA 的 UltraFeedback, 以及给已有 prompt 加上新的指令约束.
2. **生成回答**: 每个 prompt 从模型池随机抽 4 个模型各生成一个回答. 模型池覆盖不同参数规模和模型家族的开源与闭源模型. 另取一部分 prompt 加入 on-policy 数据: 一个回答来自 Tülu SFT 模型自己, 另一个来自其他模型.
3. **打分**: GPT-4o-2024-08-06 对每个回答在有用性, 指令遵循, 诚实, 真实性四个维度上打 1 到 5 分. 二值化时取各维度均分, 均分最高的作为 chosen, 从均分较低的回答中随机抽一个作为 rejected.

一个手算例子. 某 prompt 的 4 个回答四维平均分为 A 4.50, B 3.75, C 3.75, D 2.00. chosen 是 A, rejected 从 B, C, D 中随机抽一个. 这种做法让 rejected 不总是最差的那个, 偏好对的难度有高有低.

最终 8B 的偏好数据 271,409 条, 70B 334,302 条 (Table 15). 主要组成: SFT prompt 的 off-policy 偏好 96,911 条, on-policy 偏好 19,444 条, 加约束的指令遵循 65,530 条, 清洗后的 UltraFeedback 41,635 条, 以及 WildChat 的几个子集.

§5.3 的消融结论 (均在 8B 上):

| 实验 | 结论 |
|---|---|
| 增加不重复 prompt 数 (Figure 8) | 多项指标随规模提升 |
| 同一 prompt 复制更多回答对, 64k → 180k → 383k (Figure 9) | 383k 与 64k 平均相当, DROP, GSM8K, AlpacaEval 略降 |
| 新 prompt 对比复用 SFT prompt, 各 10 万 (Figure 10) | 新 prompt 略好, 两者混合最好 |
| 加入 on-policy 回答 (Figure 11) | 优于完全 off-policy |
| 换打分模型 (Table 17) | GPT-4o, Llama 3.1 405B, GPT-4 Turbo 表现接近, GPT-4o 平均略高 |

打分模型的比较是在同一批 1 万条随机抽取的 UltraFeedback prompt 和回答上做的, 参与比较的有 GPT-4-turbo-2024-04-09, GPT-4o-2024-08-06, gpt-4o-mini-2024-07-18, 以及 Llama 3.1 70B 和 405B. 开源的 405B 与 GPT-4 Turbo 接近, 说明这条流水线并不依赖某一个闭源打分模型. 模型池方面, Tülu 3 在 UltraFeedback 原有模型池上换用了新版本 (例如 Llama 2 换成 Llama 3.1), 加入了表现最好的模型, 已无法访问的模型 (例如 WizardLM) 换成开源替代.

偏好数据的来源组合也做了消融 (Table 16). 只用 SFT 阶段的 prompt 生成偏好数据时, DPO 后的平均分是 60.54. 在此基础上加入 WildChat 的指令遵循子集, SFT 中的指令遵循 prompt, 复用的 WildChat prompt 和重新生成回答的 UltraFeedback, 平均分最高, 为 62.27, 高出 1.73 分. 加入更多来源并不总是更好: 同一组合再加上 Persona IF, 平均分反而降到 61.99. 最终的 8B 混合是在这类实验的基础上, 兼顾平均分和目标技能 (精确指令遵循, 数学, AlpacaEval) 选出的.

原文由此得出: 扩充偏好数据时, 收集不重复的 prompt 并做好混合, 比在同一 prompt 上复制更多回答对更重要. 打分模型选 GPT-4o, 理由是好用, 单价低, 可以走 Batch API 批量推理.

### 4.5 自我对弈

SPIN (Chen et al., 2024) 从 SFT 模型出发, 不需要额外的人工标注: 模型用上一轮自己的生成作为负样本, 人工示范作为正样本, 训练自己区分两者. 原文证明训练目标的全局最优只在策略分布与目标数据分布一致时达到, 实验中 SPIN 超过了用额外 GPT-4 偏好数据训练的 DPO. 详见 [05-SPIN](../4.4-对齐技术/4.4.2-无奖励模型的对齐DPO-KTO/05-SPIN-自对弈微调/05-SPIN-自对弈微调.md).

## 5. 可验证 prompt

可验证 prompt 是 prompt 加一个判定函数. Tülu 3 的 RLVR 数据共 29,946 条: GSM8K 训练集 7,473 条和 MATH 训练集 7,500 条按最终答案精确匹配, 14,973 条指令遵循 prompt 各配一个约束检查函数. DeepSeek-R1 的准确性奖励要求数学题在指定格式里给出最终答案, 代码题用编译器跑预设测试用例. 这类数据的构造重点是判定函数要可靠: 答案抽取规则过松会被模型利用, 过严则会把正确答案判错. 训练细节见 [4.0](../4.0-后训练概述/4.0-后训练概述.md) §7.

## 6. 失效模式

1. **许可与隐私**. ShareGPT 这类用户分享数据来源存疑, 组合数据集里还可能嵌套着它. Tülu 3 逐个子集追踪来源.
2. **供应商差异**. Llama 2 发现不同标注平台和供应商的数据训出的模型差别显著, 即使外包也要做数据检查.
3. **奖励模型脱离分布**. 策略更新后输出分布移动, 用旧分布的偏好数据训练的奖励模型准确率会下降. Llama 2 每轮用最新模型重新采集.
4. **合成数据的模式坍缩**. 模型合成容易重复同样的模式. Tülu 3 用 25 万个角色做条件, 提高多样性.
5. **用复制回答对扩充偏好数据**. Tülu 3 中, 同一 prompt 的回答对从 64k 扩到 383k 没有收益, 部分任务还略降.
6. **偏好难以区分的样本对**. 回答差距很小时, 标注员和奖励模型都难以判断. Llama 2 记录偏好程度, 可以据此给 margin 或过滤.
7. **安全数据的标签冲突**. 如果收录「选中的不安全」样本, 偏好与安全目标相互矛盾. Llama 2 直接排除这类样本.
8. **过度拒答**. 安全数据只有「该拒绝」的样本时, 模型容易把看起来敏感但实际无害的请求也拒掉. Tülu 3 在安全数据里加入 CoCoNot 这类对比 prompt, 让模型同时见到应当正常回答的边界样本.
9. **公开基准分布与真实用途不符**. InstructGPT 的 API prompt 中分类和问答只占约 18%, 只在公开 NLP 任务上做指令微调的模型, 在真实用户的开放式请求上表现不如 InstructGPT.
10. **评测污染**. prompt 池越大, 混入评测题的可能性越大. Tülu 3 对 prompt 做 n-gram 去污染, 方法和发现的污染见 [4.2.2](../4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md) §9.
