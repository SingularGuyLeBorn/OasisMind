# Agentic 能力训练: 以 GLM-5 为主线

> 上级: [4.5 推理与思考能力](../4.5-推理与思考能力.md) · 平级: [4.5.1 推理模型训练](../4.5.1-推理模型训练/4.5.1-推理模型训练.md) · 相关: [GRPO](../../4.4-对齐技术/4.4.1-基于奖励模型的RL-RLHF-PPO/02-GRPO/02-GRPO.md) · [OPD 基础原理](../../4.6-OPD/01-OPD基础原理/01-OPD基础原理.md) · [4.7 持续学习](../../4.7-持续学习/4.7-持续学习.md)

## 1. Agent RL 与推理 RL 的区别

推理 RL (见 [4.5.1](../4.5.1-推理模型训练/4.5.1-推理模型训练.md)) 的一条轨迹是一段连续生成: 问题进去, 推理和答案出来, 判分器给一个奖励. Agent RL 的一条轨迹是多轮交互:

$$
(q,\ r_1,a_1,o_1,\ r_2,a_2,o_2,\ \dots,\ r_n,a_n,o_n) \tag{1}
$$

$q$ 是任务, $r_i$ 是第 $i$ 轮的推理, $a_i$ 是动作 (调用工具, 执行命令, 改文件), $o_i$ 是环境返回的观察. 和推理 RL 相比有四点不同:

1. **一部分 token 不是模型生成的**. $o_i$ 来自环境, 只能作为条件, 不能对它算梯度. GLM-5 只用模型生成的 token 计算损失, 环境反馈在损失中忽略.
2. **轨迹长, 耗时不均**. 一次 SWE 任务可能几十轮, 每轮要等测试跑完; 一次搜索任务要等网页返回. 同步 RL 会被最慢的轨迹拖住, 所以需要异步框架 (第 5 节).
3. **奖励来自环境**. 测试是否通过, 答案是否与标准一致. 环境本身要可复现, 可批量启动, 这使环境构造成为数据工作的主体 (第 7 节).
4. **上下文会被工具结果撑满**. 搜索结果和日志很长, 轨迹很快超过上下文窗口 (第 8 节).

## 2. GLM-5 的训练流程

GLM-5 报告 (GLM-5 Team 2026, *GLM-5: from Vibe Coding to Agentic Engineering*) 给出的流程:

| 阶段 | 要点 |
|---|---|
| 预训练 | 744B 参数, 注意力用 DSA (DeepSeek Sparse Attention); 预训练语料 27T token |
| 中训 | 三段上下文扩展: 32K 训练 1T token, 128K 训练 500B, 200K 训练 50B; 加入长上下文 agent 数据; 预训练与中训合计 28.5T |
| SFT | 最大长度 202,752 token; 三种思考模式: Interleaved (每次回答和工具调用前都思考), Preserved (多轮之间保留此前的思考内容), Turn-level (按轮开关思考) |
| 推理 RL | 数学, 科学, 代码, 工具集成推理 (TIR) 四个领域 |
| Agent RL | SWE, 终端, 搜索; 全异步 |
| 通用 RL | 正确性, 情感智能, 任务质量 |
| 跨阶段 OPD | 用前面各阶段的最终检查点当教师做 on-policy 蒸馏 |

SFT 语料分三类: 通用对话 (问答, 写作, 角色扮演, 翻译, 多轮与长上下文), 推理 (数学, 编程, 科学), 编码与 agent (前后端工程代码, 工具调用, 编码 agent, 搜索 agent, 通用 agent). 与 GLM-4.5 相比, agent 和编码数据的规模明显扩大. 三种思考模式各有用途: Interleaved 提升指令遵循和生成质量; Preserved 用在编码 agent 场景, 复用已有推理, 不必每轮从头推导, 减少信息丢失和前后不一致; Turn-level 让轻量请求关掉思考以降低延迟和成本.

编码与 agent 数据靠构建大量执行环境采集轨迹, 再用专家 RL 和拒绝采样提高质量. 轨迹会保留出错的片段 (例如调用错了工具, 随后改正), 但出错的那部分在损失里被 mask 掉. 模型因此见过 「出错后怎么恢复」 的上下文, 又不会被训练去生成错误动作.

## 3. 推理 RL: GRPO 加 IcePop

### 3.1 训推不一致

RL 中采样由推理引擎 (vLLM, SGLang 一类) 完成, 梯度由训练引擎 (Megatron 一类) 计算. 两边的算子实现, 并行切分和数值精度不同, 同一个模型, 同一个 token, 两边算出的概率并不相等. 记推理策略为 $\pi^{\mathrm{infer}}$, 训练策略为 $\pi^{\mathrm{train}}$, 训推不一致比

$$
\rho_{i,t}=\frac{\pi^{\mathrm{train}}_{\theta_{\mathrm{old}}}(y_{i,t}\mid x,y_{i,<t})}{\pi^{\mathrm{infer}}_{\theta_{\mathrm{old}}}(y_{i,t}\mid x,y_{i,<t})} \tag{2}
$$

理想情况下 $\rho\equiv1$. Ring-1T 报告 (Ling Team 2025) 的定理 1 说明, 这种差异会随训练步数复利放大; MoE 的动态路由和长 CoT 都会加剧它: 路由在两边可能选到不同专家, 序列越长, 逐 token 的偏差累积越多.

### 3.2 GLM-5 的损失

GLM-5 的推理 RL 损失 (报告式 (1)):

$$
\mathcal L(\theta)=-\mathbb{E}\Biggl[\frac1G\sum_{i=1}^{G}\frac1{|y_i|}\sum_{t=1}^{|y_i|}\mathrm{pop}\bigl(\rho_{i,t},\tfrac1\beta,\beta\bigr)\cdot\min\bigl(r_{i,t}\hat A_{i,t},\ \mathrm{clip}(r_{i,t},1-\epsilon_{\mathrm{low}},1+\epsilon_{\mathrm{high}})\hat A_{i,t}\bigr)\Biggr] \tag{3}
$$

$y_i$ 从 $\pi^{\mathrm{infer}}_{\theta_{\mathrm{old}}}$ 采样, $r_{i,t}$ 是新旧训练策略的重要性比, $\hat A_{i,t}$ 是 GRPO 的组内优势. 算子 pop 的定义是

$$
\mathrm{pop}(\rho,\tfrac1\beta,\beta)=\begin{cases}\rho & \tfrac1\beta\le\rho\le\beta\\ 0 & \text{otherwise}\end{cases} \tag{4}
$$

超参: $\beta=2$, $\epsilon_{\mathrm{low}}=0.2$, $\epsilon_{\mathrm{high}}=0.28$; 每题采样 32 个回答, batch 为 32 道题, 每步共 $32\times32=1024$ 条回答, 完全 on-policy, 即每批生成只做一次梯度更新. 与原始 IcePop 相比去掉了 KL 正则项, 以加快 RL 的提升.

手算: $\beta=2$ 时保留区间是 $[0.5,2]$. 某 token 推理引擎给的概率是 0.30, 训练引擎算出 0.33, $\rho=1.1$, 保留并乘上 1.1; 另一个 token 推理引擎给 0.02, 训练引擎算出 0.09, $\rho=4.5$, 越界, 这个 token 的梯度为 0. 第二个 token 往往是采样时的低概率 token, 两边数值差异在这里最容易放大.

### 3.3 IcePop 与 TIS

Ring-1T 中的 IcePop 用双边掩码 $M(\rho;\alpha,\beta)$, 取 $\alpha=0.5$, $\beta=5$, 与 GLM-5 的区间不同. 对比 TIS (truncated importance sampling): TIS 对越界 token 把权重截断到上限, 梯度仍然以截断后的系数保留; IcePop 直接丢弃越界 token 的梯度. 拿第 3.2 节 $\rho=4.5$ 的 token 来算, 若 TIS 的截断上限也取 2, 这个 token 仍以系数 2 参与更新, IcePop 下系数为 0. 在 Ring-mini-2.0 (总参数 16.8B, 激活 0.75B) 上, IcePop 在 AIME25 上比基线高 14% 以上; 被丢弃的 token 只占约 1 到 2‰, 且集中在高熵 token 上.

### 3.4 DSA indexer 的确定性

DSA 用一个轻量 indexer 为每个 query 选出 top-$k$ 个 key ($k=2048$), 只在这些 key 上做注意力. RL 中这又是一处训推不一致: 若推理引擎和训练引擎选出的 key 集合不同, 同一个 token 的概率就不同. GLM-5 报告的处理:

- 像 MoE 的 routing replay 那样把推理端选出的索引存下来回放, 不可行: 每个 token 每层都要存 2048 个索引, 存储和通信开销过大.
- 改用确定性的 `torch.topk`. 非确定性的 CUDA 或 TileLang top-k 实现会让 RL 在几步之内性能骤降, 熵快速下跌.
- RL 阶段冻结 indexer 的参数.

### 3.5 数据与奖励

四个领域: 数学, 科学, 代码, TIR. 难度过滤保留 GLM-4.7 很少答对, 但更强的教师模型 (GPT-5.2 xhigh, Gemini 3 Pro) 能解的题: 太简单的题组内全对, 优势为 0; 连强教师都解不出的题, 答案本身可能有问题. 奖励是二元的结果奖励.

## 4. 通用 RL

通用 RL 在三个维度上优化: 基础正确性, 情感智能, 任务质量. 奖励由三种来源混合: 规则奖励, 结果奖励模型 (ORM), 生成式奖励模型 (GRM). 报告观察到, 只用模型生成的回答做优化, 输出会收敛到一眼能认出的 「模型腔」: 啰嗦, 套路化, 缺少熟练写作者的分寸. 所以训练中引入专家撰写的回答, 作为风格和质量上的锚点.

## 5. Agent RL: 全异步框架

### 5.1 解耦与优化器重置

GLM-5 的 Agent RL 建在 slime 框架上. rollout 引擎持续生成轨迹, 训练引擎持续消费; 每进行 $K$ 次梯度更新, 把新权重同步到推理引擎. 一条轨迹可能横跨几次权重同步, 由不同版本的模型生成, off-policy 问题严重. 由于 rollout 策略变了, 每次同步之后要解的已经是另一个优化问题, 所以每次权重同步后都重置优化器状态.

目标沿用组内基线. 对任务 $x$ 采样 $K$ 条轨迹 $\{y_1,\dots,y_K\}$, 优势取 $r(x,y_i)-\bar r(x)$, $\bar r(x)=\frac1K\sum_i r(x,y_i)$, 不除标准差; 只对模型生成的 token 计算损失.

不同任务的工具集和 rollout 逻辑各不相同. GLM-5 让每个任务把自己的 rollout 和奖励逻辑实现成独立的微服务, 注册到中心的 Multi-Task Rollout Orchestrator. 编排器控制每个任务的 rollout 比例和生成速度, 使各任务的数据采集保持平衡; 所有任务的轨迹统一成同一种 message-list 表示, 便于集中后处理和记录. 任务逻辑与训练主循环由此隔离. 编排器支持 1000 个以上的并发 rollout, 可以自动动态调整任务采样比例.

异步的出发点是长尾. 同步 RL 中, 一步训练要等这一批里最慢的那条轨迹; agent 任务的轨迹长度极不均衡, GPU 会长时间空等. slime 因此把优化目标从总吞吐换成端到端延迟, 尤其是尾延迟:

- **不排队**: 用多节点部署 (例如 8 个节点上 EP64, DP64) 提供足够的分布式 KV cache, 突发流量下请求也能立即被服务; MLA 配合 DP-attention, 避免在 rank 之间复制 KV.
- **FP8 rollout 与 MTP**: FP8 降低每 token 延迟. 尾部的慢样本通常是小 batch 解码 (罕见的长上下文, 工具调用密集的轨迹), MTP 投机解码在小 batch 下收益最大, 正好缩短最慢样本的完成时间.
- **PD 分离**: 多轮场景里长前缀 prefill 很频繁, 与 decode 混跑时, 一次重 prefill 会打断同一服务器上正在进行的 decode. 把 prefill 和 decode 放在不同资源上, 长程样本可以连续推进.
- **心跳容错**: rollout 服务器定期发送心跳, 不健康的服务器被主动终止并从路由中注销, 重试自动转向健康的服务器.

### 5.2 TITO 网关

多轮 agent 轨迹在推理端是 token 序列, 在 agent 框架里却常以文本形式拼接, 再在训练端重新分词. 重新分词不一定得到同一串 token (边界合并, 特殊符号, 空白), 训练计算的就不是模型实际生成的那个动作的概率. TITO (Token-in-Token-out) 网关让训练端直接拿到推理端的 token 序列, 保持动作级的精确对应, 消除重分词错位.

### 5.3 直接双边重要性采样

异步之后, 每条轨迹的 rollout 策略是不同版本的混合, 精确计算 $\pi_{\mathrm{old}}$ 需要保存历史检查点. GLM-5 不这样做, 直接用推理时记录的 log 概率:

$$
r_t(\theta)=\exp\bigl(\log\pi_\theta(y_t\mid\cdot)-\log\pi_{\mathrm{rollout}}(y_t\mid\cdot)\bigr) \tag{5}
$$

再做双边截断:

$$
f(x)=\begin{cases}x & 1-\epsilon_\ell<x<1+\epsilon_h\\ 0 & \text{otherwise}\end{cases},\qquad \mathcal L=-\mathbb{E}\bigl[f(r_t(\theta))\cdot\hat A_t\cdot\log\pi_\theta(y_t\mid\cdot)\bigr] \tag{6}
$$

越界 token 的贡献直接为 0, 这一点与第 3.3 节的 IcePop 一致. 式 (5) 同时吸收了两种偏差: 推理引擎与训练引擎的数值差, 以及 rollout 版本与当前版本的策略差. 把它拆开写就能看出来:

$$
r_t(\theta)=\underbrace{\frac{\pi_\theta(y_t\mid\cdot)}{\pi^{\mathrm{train}}_{\mathrm{old}}(y_t\mid\cdot)}}_{\text{策略差}}\cdot\underbrace{\frac{\pi^{\mathrm{train}}_{\mathrm{old}}(y_t\mid\cdot)}{\pi_{\mathrm{rollout}}(y_t\mid\cdot)}}_{\text{训推差}}
$$

式 (3) 把这两项分开处理, 前一项做 PPO 裁剪, 后一项交给 pop; 两项都要用到旧策略在训练引擎上的概率 $\pi^{\mathrm{train}}_{\mathrm{old}}$. 式 (5) 只截断两者的乘积, 中间那个量约掉了, 因此不必保存历史检查点.

手算 (示意, 取 $\epsilon_\ell=\epsilon_h=0.2$): 某 token 推理时 $\log\pi_{\mathrm{rollout}}=-1.20$, 当前 $\log\pi_\theta=-1.05$, $r=e^{0.15}\approx1.16$, 落在 $(0.8,1.2)$ 内, 保留; 另一个 token 差值为 $0.40$, $r=e^{0.4}\approx1.49$, 丢弃.

### 5.4 陈旧样本与环境故障

每条回答记录参与生成的模型版本序列 $(w_0,\dots,w_k)$. 若当前版本 $w'$ 与最旧版本之差 $w'-w_0$ 超过阈值 $\tau$, 丢弃整条样本.

环境崩溃 (容器启动失败, 测试框架异常) 产生的样本不反映模型能力, 直接剔除. 剔除后一组剩下的有效样本若超过半数, 就复制有效样本补齐组大小; 否则整组丢弃. 补齐保证每组样本数固定, 组内基线可比.

### 5.5 DP-aware 路由

多轮 agent 请求共享同一前缀 (前面所有轮的上下文). 在数据并行的 MoE 推理中, 若同一条轨迹的后续请求被分到不同 DP rank, 前缀的 KV cache 无法复用, 每轮都要重新 prefill. GLM-5 用一致性哈希把每个 rollout ID 固定映射到一个 DP rank, 跨轮保持不变, 再在哈希空间上做轻量的动态负载再平衡, 防止长期不均.

## 6. 跨阶段 on-policy 蒸馏

多阶段 RL 依次优化不同目标, 会让此前获得的能力累积退化. GLM-5 在最后加一个 on-policy 蒸馏阶段: 前面各阶段的最终检查点当教师, 训练 prompt 从各教师对应的 RL 训练集中采样, 按比例混合. 损失把式 (3) 中的优势换成

$$
\hat A_{i,t}=\mathrm{sg}\Bigl[\log\frac{\pi^{\mathrm{infer}}_{\theta_{\mathrm{teacher}}}(y_{i,t}\mid x,y_{i,<t})}{\pi^{\mathrm{train}}_\theta(y_{i,t}\mid x,y_{i,<t})}\Bigr] \tag{7}
$$

sg 表示停止梯度. 学生在自己采样的 token 上, 教师给的概率比学生高的 token 得到正优势, 低的得到负优势. 优势直接由与教师的差距给出, 不再需要一组样本估计基线, 所以 group size 设为 1, batch 为 1024, 提高吞吐. 教师 logits 目前由推理引擎提供.

手算: 某 token 教师概率 0.6, 学生 0.3, $\hat A=\log2\approx0.69$; 另一 token 教师 0.1, 学生 0.4, $\hat A=\log0.25\approx-1.39$. 这是逐 token 的反向 KL 信号, 原理见 [OPD 基础原理](../../4.6-OPD/01-OPD基础原理/01-OPD基础原理.md); 为什么 on-policy 能减少遗忘见 [4.7](../../4.7-持续学习/4.7-持续学习.md) 第 9 节.

## 7. 环境与数据

### 7.1 SWE

先收集大量真实的 Issue-PR 对, 用规则和 LLM 过滤出真实, 高质量的 issue 描述, 按任务类型 (修 bug, 实现功能, 重构等) 分类, 并补充必要的需求说明, 使模型的实现能与测试补丁对得上. 环境搭建基于 RepoLaunch: 自动分析仓库的安装和依赖配置, 构建可执行环境并生成测试命令, 再让 LLM 按语言生成测试日志的解析函数, 从输出中提取测试用例. 测试分两类: F2P (fail-to-pass, 修复前失败, 修复后应通过, 检验问题是否解决) 和 P2P (pass-to-pass, 修复前后都应通过, 检验有没有改坏别的). 最终得到 1 万多个可验证环境, 来自数千个仓库, 覆盖 Python, Java, Go, C, C++, JavaScript, TypeScript, PHP, Ruby 9 种语言.

### 7.2 终端

终端任务采用 Harbor 格式 (结构化任务描述, Docker 化的执行环境, 测试脚本), 有两条合成路线.

- **从种子数据合成**: LLM 先头脑风暴出大量可验证的终端任务草稿, 构建 agent 把草稿实例化成具体任务, 精修 agent 再按人工定义的评分细则反复检查: Docker 镜像能稳定构建, 测试用例与任务描述一致, 环境不存在可被利用的捷径. 这条路线得到数千个可验证的终端环境, Docker 构建准确率超过 90%.
- **从网页语料合成**: 收集与代码相关的网页, 用质量分类器去掉非技术或缺少实质代码的页面, 挑出适合改写成终端任务的网页, 按主题和难度分层采样. 编码 agent 读网页, 按 Harbor 规范合成任务, 再对自己的产出运行 Harbor 校验脚本; 校验失败就诊断并修改, 直到通过全部自动检查才收入数据集.

### 7.3 多跳搜索

从 200 多万个网页构建网页知识图谱. 以低频到中频的实体为种子, 扩展出多跳子图, 再在子图上合成问题. 低频实体保证答案不能靠模型记忆直接给出, 多跳保证需要多次检索和推理.

三道过滤:

1. 无工具的模型采样 8 次, 只要有 1 次答对就删除 (可以靠记忆答出).
2. 早期 agent 几步之内就能解出的删除 (太简单).
3. 验证 agent 双向校验, 确认答案唯一且与证据一致.

### 7.4 幻灯片生成: 分层奖励与奖励黑客

幻灯片以 HTML 生成, 先用 SFT 给出基础能力, 再用 RL 训练一个专门的幻灯片专家. 奖励分三层:

1. **静态标记属性**: 检查 HTML 中声明的位置, 间距, 颜色, 字体, 饱和度等, 用基于设计原则的规则约束, 同时保证 HTML 可解析; 另加幻觉图片和重复图片检测.
2. **运行时渲染属性**: 用分布式渲染服务实际渲染页面, 取 DOM 节点的宽高, 包围盒等几何量加以约束.
3. **视觉感知特征**: 在渲染结果上检测异常留白等, 作为构图平衡的辅助信号.

训练中出现了奖励黑客: 模型把过长的内容硬截断, 或者过度操纵间距, 让几何指标好看. 修法是改渲染器, 消除可被利用的漏洞, 让奖励反映的是真实渲染出的属性值. 训练分布上, 按概率丢掉一部分结构过于简单的样本, 让优化集中在复杂页面; 同一样本的不同 rollout 结果分散到多个 batch, 减少优化偏差.

RL 之后把奖励函数转成数据过滤管线做拒绝采样 (页面级检查代码有效性和可编译, 轨迹级检查工具执行正确性和内容多样性, best-of-N 取最优), 再做 mask 精修: 只有少数页面有缺陷的轨迹不整条丢弃, 把缺陷页 mask 掉, 保留同一轨迹里的高质量内容. 结果: 生成页面中严格符合 16:9 的比例从 40% 升到 92%, 页面溢出明显减少; 人工评测中, GLM-5 相对 GLM-4.5 的总体胜率为 67.5% (内容质量 60%, 版式合理性 57.5%, 视觉美观 65%).

## 8. 上下文管理

搜索类任务的工具结果很长, 报告观察到上下文极长时 (例如超过 100k token) 模型准确率显著下降.

**Keep-recent-k**: 交互超过 $k$ 轮时, 把最近 $k$ 轮之前的工具观察折叠为一句占位文本:

$$
o_i\leftarrow\text{「Tool result is omitted to save tokens.」},\qquad i=1,\dots,n-k \tag{8}
$$

推理 $r_i$ 和动作 $a_i$ 保留, 只折叠观察 $o_i$. 工具共 4 个: search, open, find, python. 取 $k=5$, BrowseComp 从 55.3% 升到 62.0%; 换其他 $k$, 或改为按 token 阈值触发, 结果相同.

**分层上下文管理**: 在 keep-recent 的基础上, 若总上下文仍超过阈值 $T$, 就丢弃全部工具调用历史, 以新的上下文重新开始 (Discard-all), 之后继续执行 keep-recent. $T=32k$ 由参数搜索确定. 在不同算力预算下都比只用 Discard-all 好, 最终 BrowseComp 75.9%.

手算: 一条轨迹已有 12 轮, 每轮观察约 6k token, 推理和动作约 1k token. 不折叠时约 84k; keep-recent-5 后, 前 7 轮各剩约 1k, 总量约 $7\times1+5\times7=42$k, 仍超过 32k, 触发 Discard-all, 从 $q$ 重新开始. 两种机制分别控制增长速度和上限.

## 9. 并行 agent: Kimi K2.5 的 PARL

上面的上下文管理都是事后截断: 上下文已经很长了再丢. Kimi K2.5 (Kimi Team 2026) 走另一条路: 由 orchestrator 主动把任务拆给多个 subagent, 每个 subagent 在自己的上下文里工作, 只返回结果. 这是主动的上下文分片, 也是推理阶段宽度轴上的扩展 (见 [4.5.1](../4.5.1-推理模型训练/4.5.1-推理模型训练.md) 第 1 节).

### 9.1 只训练 orchestrator

PARL (Parallel-Agent Reinforcement Learning) 中, orchestrator 可以调用创建 subagent 和分派任务的接口. subagent 从固定的中间策略检查点实例化并冻结, 其轨迹不进入优化目标, 只有 orchestrator 用 RL 更新. 原文给出的理由是端到端联合优化有两个难点: 信用分配模糊 (结果奖励稀疏, 分不清是 orchestrator 拆得不好还是 subagent 做得不好) 和训练不稳定. 训练先从较小的 subagent 开始.

### 9.2 奖励

$$
r=\lambda_1r_{\mathrm{parallel}}+\lambda_2r_{\mathrm{finish}}+r_{\mathrm{perf}} \tag{9}
$$

- $r_{\mathrm{perf}}$ 评价最终解答的成功与质量.
- $r_{\mathrm{parallel}}$ 鼓励创建 subagent, 防止 serial collapse: orchestrator 退化到单 agent 执行的局部最优.
- $r_{\mathrm{finish}}$ 奖励分派的子任务被成功完成, 防止 spurious parallelism: 只为拿 $r_{\mathrm{parallel}}$ 创建一堆没有实际作用的 subagent.
- $\lambda_1,\lambda_2$ 在训练中退火到 0, 最终只优化任务表现.

训练 prompt 覆盖 wide search (需要并行收集大量条目) 和 deep search (需要多条推理分支) 两类, 但 prompt 不明示要并行, 由 orchestrator 自己判断.

### 9.3 关键路径步数

衡量并行效果用的是关键路径步数, 不是总步数:

$$
\text{CriticalSteps}=\sum_{t=1}^{T}\Bigl(S^{(t)}_{\mathrm{main}}+\max_iS^{(t)}_{\mathrm{sub},i}\Bigr) \tag{10}
$$

第 $t$ 个阶段里, 主 agent 走 $S_{\mathrm{main}}^{(t)}$ 步, 并行的 subagent 中最慢的一个走 $\max_iS_{\mathrm{sub},i}^{(t)}$ 步. 手算: 阶段 1 主 agent 2 步, 三个 subagent 分别 5, 8, 3 步; 阶段 2 主 agent 3 步, 没有 subagent. CriticalSteps $=(2+8)+(3+0)=13$; 串行执行要 $2+5+8+3+3=21$ 步. 总 token 没有减少, 墙钟延迟按 13 步计.

### 9.4 结果

与单 agent 相比: BrowseComp 从 60.6% 到 78.4%, WideSearch item-F1 从 72.7% 到 79.0%, 延迟降低 3 到 4.5 倍.

## 10. 失效模式

- **训推不一致未处理**: MoE 路由, 长序列, 非确定性 top-k 都会让 $\rho$ 偏离 1. 不加 IcePop 类掩码时偏差随训练复利放大; DSA indexer 用非确定性 top-k 会在几步内崩溃.
- **重分词错位**: 训练的 token 与模型实际生成的不一致, 梯度落在模型从未生成的动作上.
- **陈旧样本**: 异步框架里太旧的轨迹与当前策略差距过大, 重要性比大面积越界, 有效梯度变少.
- **环境故障当成模型失败**: 容器崩溃的轨迹若计入奖励 0, 会惩罚无辜的动作. 需要剔除并补齐组.
- **数据可被记忆**: 搜索题若无工具也能答出, RL 学到的是记忆而不是搜索.
- **规则奖励被钻空子**: 幻灯片 RL 里的硬截断和间距操纵. 奖励要基于真实执行或渲染的结果, 并在训练中持续检查样本.
- **环境本身有捷径**: 终端任务若测试与描述不一致, 或环境里能绕过任务直接通过测试, 奖励就不再衡量能力.
- **长上下文退化**: 工具结果不折叠, 上下文过百 k 后准确率下降.
- **并行退化**: 没有 $r_{\mathrm{parallel}}$ 时 orchestrator 不并行; 只有 $r_{\mathrm{parallel}}$ 时出现无用的 subagent.
- **多阶段能力回退**: 通用 RL 冲掉推理或 agent 能力, 需要跨阶段蒸馏和逐阶段的回归评测.
