# 4.0 后训练概述

后训练从预训练得到的基座模型出发, 用人工示范, 成对偏好和可验证奖励继续训练. 这里依据的材料是 InstructGPT, Llama 2, Tülu 3, DeepSeekMath 和 DeepSeek-R1 的原文, 关心的是这些信号怎样进入训练, 各阶段带来多少收益, 以及训练在哪些地方出问题.

## 1. 后训练补什么, 用什么信号

### 1.1 预训练模型缺什么

InstructGPT (Ouyang et al., 2022) 开篇的判断是: 模型变大不等于更会按用户的意图办事. 大模型会输出不真实, 有毒或者没用的内容, 也就是和用户「没有对齐」. 预训练目标是预测网页上的下一个 token, 与「有用且安全地执行指令」之间存在差距.

后训练能弥补多少差距, InstructGPT 给出了几组数字:

- 在 API 提示分布的测试集上, 1.3B 的 InstructGPT 输出被标注员偏好于 175B 的 GPT-3, 前者参数少 100 多倍, 两者架构相同, 区别只在于 InstructGPT 用人工数据微调过. 给 GPT-3 加上 few-shot 提示后, 结论不变.
- 175B InstructGPT 对 175B GPT-3 的胜率是 85±3%, 对加了 few-shot 提示的 GPT-3 是 71±4%.
- 在 TruthfulQA 上, InstructGPT 给出真实且有信息量的回答的频率约为 GPT-3 的两倍. 在摘要, 封闭域问答这类「输出不应包含输入以外信息」的任务上, 编造率从 41% 降到 21%.
- 作为对照, InstructGPT 还在 175B GPT-3 上分别用 FLAN 和 T0++ 两个公开 NLP 任务合集微调. 在 API 提示分布上, 这两个模型略差于 SFT 基线. 以 175B SFT 为基线比较胜率, InstructGPT 是 73.4±2%, T0 版本 26.8±2%, FLAN 版本 29.8±2%. 原文的解释是公开数据集的任务分布与 API 用户的实际用途相差很大, 用途分布见 [4.1 后训练数据](../4.1-后训练数据/4.1-后训练数据.md) §2.1.
- 在 RealToxicityPrompts 上, 提示模型「保持尊重」时, 有毒输出约少 25%. 在 Winogender 和 CrowS-Pairs 偏见基准上没有显著改善.

成本方面, 训练 175B 的 SFT 模型用了 4.9 petaflops/s-days, 175B 的 PPO-ptx 模型用了 60 petaflops/s-days, GPT-3 预训练是 3,640 petaflops/s-days (InstructGPT 讨论部分). 作者据此认为, 就他们客户的任务分布而言, 投入对齐比训练更大的模型更划算.

这些数字说明后训练改变的主要是行为: 按指令作答的格式, 拒绝编造, 语气和安全边界. 知识本身主要来自预训练. 后训练的数据量远小于预训练, 能做的是把预训练学到的能力调出来, 并约束在用户想要的方向上.

### 1.2 示范, 偏好, 可验证奖励

| 信号 | 数据形态 | 典型方法 | 代价 |
|---|---|---|---|
| 示范 | (prompt, 标准回答) | SFT | 需要人或强模型写完整回答 |
| 偏好 | (prompt, 较好回答, 较差回答) | 奖励模型 + PPO, DPO | 比写回答便宜, 但标注一致率有上限 |
| 可验证奖励 | (prompt, 判定函数) | RLVR, GRPO | 只适用于答案能被程序检查的任务 |

示范直接告诉模型「该输出什么」. 偏好只告诉模型「两者之中哪个更好」, 标注员不必自己写出最好的答案. 可验证奖励则完全不需要人工逐条标注: 数学题比对最终答案, 代码题跑测试用例, 格式约束用规则检查.

### 1.3 统一的梯度形式

DeepSeekMath (Shao et al., 2024) §5.2.1 把 SFT, 拒绝采样微调 (RFT), DPO, PPO, GRPO 写成同一种梯度:

$$
\nabla_\theta \mathcal{J}_{\mathcal{A}}(\theta) = \mathbb{E}_{(q,o)\sim\mathcal{D}}\left[\frac{1}{|o|}\sum_{t=1}^{|o|} GC_{\mathcal{A}}(q,o,t,\pi_{rf})\,\nabla_\theta\log\pi_\theta(o_t\mid q,o_{<t})\right]
\tag{1}
$$

式 (1) 里有三个组成部分:

1. **数据源** $\mathcal{D}$: 训练用的 (问题, 回答) 从哪来.
2. **奖励函数** $\pi_{rf}$: 训练信号的来源, 规则或模型.
3. **算法** $\mathcal{A}$: 把数据和奖励变成梯度系数 $GC$, 决定每个 token 被加强或惩罚多少.

按这三项归类 (DeepSeekMath Table 10):

| 方法 | 数据源 | 奖励 | 梯度系数 |
|---|---|---|---|
| SFT | 人工挑选的 SFT 数据 | 无 | 恒为 1 |
| RFT | SFT 问题, 由 SFT 模型采样回答 | 规则 | 答对为 1, 答错为 0 |
| DPO | SFT 问题, 由 SFT 模型采样一对回答 | 规则 | 由 DPO 损失决定 |
| Online RFT | SFT 问题, 由当前策略采样 | 规则 | 答对为 1, 答错为 0 |
| PPO | SFT 问题, 由当前策略采样 | 模型 | 由优势函数决定 |
| GRPO | SFT 问题, 由当前策略每题采样一组 | 模型 | 由组内标准化奖励决定 |

在这个框架下, SFT 是系数恒为 1 的特例: 每个示范 token 都被同等加强. RFT 和 Online RFT 只加强答对的样本, 不惩罚答错的. GRPO 按奖励大小区分强弱, 答错的样本系数为负.

DeepSeekMath 在 1.3B 模型上比较了这些方法 (Figure 5), 得到两条结论:

- **在线优于离线**: Online RFT 在训练前期与 RFT 相当, 后期明显领先. 原文的解释是前期策略和 SFT 模型很接近, 采样差别小, 后期差别变大, 实时采样的优势就显出来了.
- **有正负系数优于只有正系数**: GRPO 好于 Online RFT. 用过程奖励 (每步打分) 的 GRPO 又好于只用结果奖励的 GRPO.

## 2. InstructGPT: SFT → 奖励模型 → PPO

### 2.1 数据

InstructGPT 从 Upwork 和 ScaleAI 雇了约 40 名标注员, 招募时做过筛选测试, 考察他们识别潜在有害输出的能力. 三份数据集:

| 数据集 | 训练 prompt 数 | 来源 | 用途 |
|---|---|---|---|
| SFT | 约 13k | API 与标注员撰写 | 标注员写示范回答 |
| RM | 33k | API 与标注员撰写 | 标注员给模型输出排序 |
| PPO | 31k | 只来自 API | 无人工标签, 作为 RL 的输入 |

数据 96% 以上是英文. 标注员之间的一致率: 参与训练数据标注的标注员两两一致 72.6±1.5%, 另一组不参与训练数据的标注员是 77.3±1.3%. 作为对照, Stiennon et al. (2020) 摘要任务中研究者之间的一致率是 73±4%. 这个数字给偏好学习设了一个天花板: 奖励模型预测人类偏好的准确率很难超过标注员彼此之间的一致率.

为检验是否过拟合到特定标注员, 原文把标注员分成 5 组做交叉验证: 在 4 组上训练, 在留出的 1 组上测. 奖励模型对留出组的预测准确率是 69.6±0.9%, 对训练组是 72.4±0.4%.

### 2.2 SFT

SFT 训练集共 12,725 条 prompt, 其中标注员自写 11,295 条, 来自 API 用户 1,430 条; 验证集 1,653 条 (InstructGPT 表 6). 标注员自写的部分占约 89%, 附录 A.3 说明其中不少是从同一条模板指令出发, 换不同的 few-shot 例子生成的多条数据点, 所以真正不同的任务数比 13k 少.

在这些示范上微调 GPT-3, 训练 16 个 epoch, 残差 dropout 0.2. 附录 C.1 给出其余超参数: 学习率用余弦调度降到初始值的 10%, 不做预热; 1.3B 和 6B 的学习率 9.65e-6, batch size 32; 175B 的学习率 5.03e-6, batch size 8. 学习率在 1.3B 和 6B 上做了 7 档几何搜索, 175B 上 5 档, epoch 数也做了几何搜索. 验证集损失在 1 个 epoch 后就开始过拟合, 但继续训练对奖励模型打分和人类偏好都有帮助, 所以最终按验证集上的 RM 分数选模型, 原文认为 RM 分数比验证损失更能预测人类偏好. SFT 的细节见 [4.2.1 SFT 原理与实践](../4.2-SFT/4.2.1-SFT原理与实践/4.2.1-SFT原理与实践.md).

### 2.3 奖励模型

从 SFT 模型出发, 去掉最终的 unembedding 层, 输出一个标量奖励. 全文只用 6B 的奖励模型: 175B 的奖励模型验证损失更低, 但训练不稳定, 不适合作为 PPO 价值函数的初始化, 计算量也大得多.

标注时一次给标注员 $K=4$ 到 $K=9$ 个回答排序, 每个 prompt 产生 $\binom{K}{2}$ 个比较对. 损失函数是:

$$
\operatorname{loss}(\theta) = -\frac{1}{\binom{K}{2}}\,\mathbb{E}_{(x,y_w,y_l)\sim D}\left[\log\sigma\big(r_\theta(x,y_w) - r_\theta(x,y_l)\big)\right]
\tag{2}
$$

其中 $r_\theta(x,y)$ 是奖励模型对 prompt $x$ 和回答 $y$ 的打分, $y_w$ 是一对中较好的那个. 式 (2) 只依赖奖励之差, 所以 RL 之前要加一个偏置, 把标注员示范的平均分归一到 0.

这里有一个工程细节. 同一个 prompt 的 $\binom{K}{2}$ 个比较高度相关, 如果把它们打散混进整个数据集, 每个回答会参与 $K-1$ 次梯度更新, 模型过一遍数据就过拟合. InstructGPT 的做法是把同一 prompt 的全部比较放进同一个 batch 元素: 每个回答只需前向一次 (而不是 $\binom{K}{2}$ 次), 也不再过拟合, 验证准确率和对数损失都明显改善.

### 2.4 PPO 与 PPO-ptx

RL 环境是一个 bandit: 随机给一个用户 prompt, 模型生成回答, 奖励模型打分, episode 结束. 每个 token 上加一项对 SFT 模型的 KL 惩罚, 防止奖励模型被过度优化. 价值函数从奖励模型初始化.

只用 PPO 时, 模型在 SQuAD, DROP, HellaSwag, WMT 2015 法译英等公开数据集上出现退化, 原文称之为「对齐税」. 修正办法是在 PPO 梯度里混入预训练梯度, 称为 PPO-ptx, 目标函数是:

$$
\operatorname{objective}(\phi) = \mathbb{E}_{(x,y)\sim D_{\pi_\phi^{\mathrm{RL}}}}\left[r_\theta(x,y) - \beta\log\frac{\pi_\phi^{\mathrm{RL}}(y\mid x)}{\pi^{\mathrm{SFT}}(y\mid x)}\right] + \gamma\,\mathbb{E}_{x\sim D_{\mathrm{pretrain}}}\left[\log\pi_\phi^{\mathrm{RL}}(x)\right]
\tag{3}
$$

$\beta$ 控制 KL 惩罚强度, $\gamma$ 控制预训练梯度强度. $\gamma=0$ 时就是普通 PPO. 文中所说的 InstructGPT 默认指 PPO-ptx 模型.

附录 C 给出的超参数:

| 项目 | 取值 |
|---|---|
| KL 系数 $\beta$ | 0.02 |
| 预训练梯度系数 $\gamma$ | 27.8 |
| 训练 episode 数 | 256k, 约 31k 个不重复 prompt |
| batch / minibatch | 512 / 64, 每个 batch 只训 1 个内层 epoch |
| PPO clip | 0.2 |
| 采样温度 | 1 |
| 价值函数学习率 | 1.3B 与 6B 策略用 9e-6, 175B 用 5e-6 |
| 权重 EMA 衰减 | 0.992 |
| 预训练样本数 | RL episode 数的 8 倍 |

附录中的几个扫描结果:

- 在 1.3B 模型上, $\gamma \ge 20$ 时公开数据集上的退化可以恢复.
- KL 系数取 0 和 2 时人类评分都很差, 最优值在 0.01 到 0.02 之间. 即使混入了预训练梯度, KL 系数仍然要调.
- 把训练从 256k episode 延长到 512k, DROP 和 SQuADv2 上的成绩随训练推进逐步下降. 在 1.3B 模型上, 训练超过 256k episode 没有帮助.

PPO 的推导与实现见 [4.4 基于奖励模型的 RL](../4.4-强化学习基础/4.4-强化学习基础.md) 与 [04-PPO](../4.4-强化学习基础/04-PPO/04-PPO.md).

## 3. 偏好信号: 从迭代 RLHF 到 DPO

### 3.1 Llama 2 的两个奖励模型与 margin 损失

Llama 2 (Touvron et al., 2023) 自己收集了 1,418,091 条二元偏好数据, 平均每条 3.9 轮对话. 偏好按「有用性」和「安全性」分开标注. 原文认为两者有时冲突, 单个奖励模型很难在两项上都好, 因此训练了 Helpfulness RM 和 Safety RM 两个模型. Helpfulness RM 用全部 Meta Helpfulness 数据, 再加等量从 Meta Safety 和开源数据集里均匀采样的数据; Safety RM 用全部 Meta Safety 和 Anthropic Harmless 数据, 按 90/10 混入有用性数据. 原文发现这 10% 的有用性数据对「两个回答都安全」的样本对的准确率特别有帮助. 两个奖励模型都只训 1 个 epoch (更长会过拟合), 最大学习率 70B 为 5e-6, 其余为 1e-5, 余弦降到 10%, batch 固定为 512 对.

每一对数据里, 标注员除了选出较好的回答, 还给出差距档位 (显著更好, 更好, 略好, 几乎一样). Llama 2 把档位作为 margin 加进二元排序损失:

$$
\mathcal{L}_{\text{ranking}} = -\log\sigma\big(r_\theta(x,y_c) - r_\theta(x,y_r) - m(r)\big)
\tag{4}
$$

$y_c$ 是被选中的回答, $y_r$ 是被拒绝的回答, $m(r)$ 是档位的离散函数: 差距越大, margin 越大. 附录 Table 27 给了两组取值, 「小 margin」按档位依次为 1, 2/3, 1/3, 0, 「大 margin」为 3, 2, 1, 0.

Table 28 的有用性测试集准确率 (按档位: 显著更好 / 更好 / 略好 / 几乎一样 / 平均):

| 设置 | 显著更好 | 更好 | 略好 | 几乎一样 | 平均 |
|---|---|---|---|---|---|
| 无 margin | 79.1 | 66.9 | 59.8 | 54.5 | 62.5 |
| 小 margin | 80.4 | 67.3 | 60.4 | 55.0 | 63.0 |
| 大 margin | 80.7 | 67.5 | 60.5 | 54.3 | 62.9 |

margin 主要提升差距明显的样本对. 对「几乎一样」的样本对, 准确率只比随机高几个点, 与 InstructGPT 的标注一致率上限是同一个现象. 原文还观察到, margin 会让奖励分布呈两极分化, margin 越大越明显 (Figure 27), 因此建议今后在奖励校准上多下功夫.

### 3.2 Llama 2 的拒绝采样微调与 PPO

随着标注数据一批批到来, Llama 2 训练了 RLHF-V1 到 V5 五个版本. 用到两种 RL 算法:

- **拒绝采样微调**: 对每个 prompt 从模型采样 $K$ 个回答, 用奖励模型选出最高分的作为新的标准答案, 再像 SFT 一样微调.
- **PPO**: 与 InstructGPT 相同.

原文把两者的区别归为两点. 广度: 拒绝采样每个 prompt 探索 $K$ 个样本, PPO 只生成一个. 深度: PPO 第 $t$ 步的样本来自第 $t-1$ 步更新后的策略, 拒绝采样则先用初始策略采完全部样本再微调. 由于做了多轮迭代, 两者的差异没有那么大.

V4 之前只用拒绝采样微调. 之后两者串联: 先在拒绝采样的 checkpoint 上跑 PPO, 再进行下一轮采样. 拒绝采样只用最大的 70B 模型做, 更小的模型在 70B 采出的数据上微调, 相当于把大模型的能力蒸馏给小模型.

两条经验:

1. **只用上一轮的样本会遗忘**. V3 之前, 每轮只从上一轮的样本里挑最佳答案, 例如 V3 只用 V2 的样本. 结果 V3 写押韵诗的能力比早期版本差. 之后改为纳入所有历史轮次的最佳样本, 问题得到解决.
2. **最佳采样温度会漂移**. 对 RLHF 后的模型, 采样 10 到 100 个回答时最佳温度在 1.2 到 1.3 之间. RLHF 会改变模型的输出分布, 所以每一轮都要重新调温度 (Figure 8).

Llama 2 还提出了 Ghost Attention (GAtt), 通过改造微调数据, 让模型在多轮对话中持续遵守第一轮给出的系统指令.

### 3.3 DPO: 去掉显式奖励模型

DPO (Rafailov et al., 2023) 证明 KL 约束下的奖励最大化问题有闭式最优解, 从而可以把奖励模型写成策略与参考模型的对数概率比, 直接在偏好对上优化策略:

$$
\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\right)\right]
\tag{5}
$$

与 PPO 相比, DPO 不需要训练奖励模型, 不需要在训练中采样, 可以直接用从各种来源收集的离线偏好对训练. 按式 (1) 的分类, DPO 的数据源是离线的.

Tülu 3 (Lambert et al., 2024) 的偏好阶段选择了 DPO 的长度归一化变体. 在早期 SFT checkpoint 和 UltraFeedback 数据上, 他们比较了 DPO, SimPO 和长度归一化 DPO, 只有长度归一化 DPO 超过了基线 checkpoint (Table 18). 他们也试了 PPO, 认为加大算力和调参后 PPO 可能更好, 但考虑到资源有限, 以及奖励模型评估本身不好做, 选择了更省事的 DPO, PPO 则留给 RLVR 阶段. 最终 DPO 的学习率 8B 为 5e-7, 70B 为 2e-7 (Table 20).

DPO 的推导见 [01-DPO](../4.6-偏好优化/4.6.1-离线偏好优化/01-DPO/01-DPO.md), 其他无奖励模型方法见 [4.6.1](../4.6-偏好优化/4.6.1-离线偏好优化/4.6.1-离线偏好优化.md).

## 4. 可验证奖励

### 4.1 Tülu 3 的 RLVR

RLVR 沿用 KL 约束的 RLHF 目标, 把奖励模型换成判定函数 $v$:

$$
\max_{\pi_\theta}\ \mathbb{E}_{y\sim\pi_\theta(x)}\Big[v(x,y) - \beta\,\mathrm{KL}\big[\pi_\theta(y\mid x)\,\|\,\pi_{\text{ref}}(y\mid x)\big]\Big]
\tag{6}
$$

$$
v(x,y) = \begin{cases}\alpha & \text{答案正确}\\ 0 & \text{否则}\end{cases}
\tag{7}
$$

Tülu 3 取 $\alpha = 10$, 这是根据预实验定的, 没有再调. 优化算法是 PPO. 训练数据约 3 万条 (Table 22):

| 来源 | 数量 | 判定方式 |
|---|---|---|
| GSM8K 训练集 | 7,473 | 抽取最终答案精确匹配 |
| MATH 训练集 | 7,500 | 抽取答案精确匹配 |
| 可验证指令遵循 | 14,973 | 每条 prompt 对应一个约束检查函数 |
| 合计 | 29,946 | |

指令遵循部分从 Tülu 2 SFT 数据里抽取指令, 再拼上 IFEval 分类体系里的约束 (例如「回答恰好包含 3 段」), 每种约束模板都有对应的检查函数. 最终 8B RLVR 模型的 KL 系数 $\beta = 0.05$, 70B 为 0.07.

### 4.2 GRPO

GRPO 是 DeepSeekMath 提出的 PPO 变体. PPO 的价值模型通常与策略模型同样大, GRPO 去掉价值模型, 改用同一问题下一组样本的奖励估计基线. 对问题 $q$, 从旧策略采样 $G$ 个输出, 得到奖励 $\mathbf{r} = \{r_1, \dots, r_G\}$. 在结果监督下, 输出 $o_i$ 中每个 token 的优势都等于标准化后的奖励:

$$
\hat{A}_{i,t} = \frac{r_i - \operatorname{mean}(\mathbf{r})}{\operatorname{std}(\mathbf{r})}
\tag{8}
$$

DeepSeekMath 的 RL 设置: 从 DeepSeekMath-Instruct 7B 出发, 训练数据是 SFT 数据中与 GSM8K 和 MATH 相关的约 144K 道链式推理题. 策略学习率 1e-6, KL 系数 0.04, 每题采样 64 个输出, 最大长度 1024, batch 1024, 每次探索后策略只更新一次. 结果 GSM8K 从 82.9% 涨到 88.2%, MATH 从 46.8% 涨到 51.7%, 域外的 CMATH 从 84.6% 涨到 88.8%.

DeepSeekMath §5.2.2 还比较了 RL 前后的 Maj@K 与 Pass@K: RL 提升了 Maj@K, 没有提升 Pass@K. 原文的解读是, RL 让输出分布更稳健, 把 Top-K 里本来就有的正确答案的概率提了上去, 并没有增强基础能力. 这个观察是 [RLVR 的局限性](../4.5-GRPO家族与RLVR/09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md) 一节讨论的起点.

之后的改进多在 GRPO 上做. 例如 DAPO (Yu et al., 2025) 把裁剪的上下界解耦 ($\varepsilon_{\text{low}} = 0.2$, $\varepsilon_{\text{high}} = 0.28$), 并做了若干其他修改, 在 Qwen2.5-32B 上把 AIME 2024 从朴素 GRPO 的 30 分提到 50 分.

GRPO 的完整计算见 [01-GRPO](../4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

### 4.3 DeepSeek-R1-Zero 与 DeepSeek-R1

DeepSeek-R1-Zero (DeepSeek-AI, 2025) 直接在 DeepSeek-V3-Base 上用 GRPO 训练, 不做 SFT. 奖励全部基于规则:

- **准确性奖励**: 数学题要求在指定格式 (如方框) 里给出最终答案, 用规则判对错. LeetCode 题用编译器跑预设测试用例.
- **格式奖励**: 要求把思考过程放在指定的思考标签之间.

原文明确不用结果或过程神经奖励模型, 理由有两个: 大规模 RL 中神经奖励模型可能被奖励黑客利用, 重训奖励模型又需要额外资源, 使流程复杂化.

R1-Zero 的 AIME 2024 平均 pass@1 从 15.6% 涨到 71.0%, 多数投票后达到 86.7%. 思考长度在训练中持续增加. 问题是可读性差, 语言混杂.

DeepSeek-R1 用四个阶段解决这些问题:

1. **冷启动**: 收集数千条长推理过程数据, 微调 DeepSeek-V3-Base.
2. **面向推理的 RL**: 与 R1-Zero 相同的大规模 RL. 训练中发现推理过程常有语言混杂, 尤其当 RL prompt 涉及多种语言时. 于是加入语言一致性奖励, 即推理过程中目标语言词的比例, 与准确性奖励直接相加. 消融显示这会让性能略降, 但输出更可读.
3. **拒绝采样与 SFT**: RL 收敛后, 用该 checkpoint 拒绝采样. 推理数据约 60 万条: 每个 prompt 采多个回答只留正确的, 部分题用 DeepSeek-V3 作为生成式奖励模型判对错, 并过滤掉语言混杂, 段落过长和带代码块的推理过程. 非推理数据 (写作, 事实问答, 自我认知, 翻译) 约 20 万条, 复用 DeepSeek-V3 的 SFT 数据. 合计约 80 万条, 在 DeepSeek-V3-Base 上训练 2 个 epoch.
4. **全场景 RL**: 推理题继续用规则奖励, 通用数据用奖励模型. 有用性只评最终总结, 无害性评整个回答 (含推理过程).

最终 DeepSeek-R1 的 AIME 2024 pass@1 为 79.8%, MATH-500 为 97.3%, Codeforces 评分 2,029. 用同一批 80 万条数据直接微调 Qwen 和 Llama 系列的小模型, 推理能力显著提升, 其中 DeepSeek-R1-Distill-Qwen-1.5B 的 AIME 为 28.9%, MATH 为 83.9%.

推理模型训练的细节见 [4.8.1 推理模型训练](../4.8-推理与Agent能力/4.8.1-推理模型训练/4.8.1-推理模型训练.md).

## 5. 收益, 失效与后续各节

### 5.1 各阶段的收益

Tülu 3 8B 在其开发评测集上的平均分 (Tülu 3 Table 1 的 8B 部分):

| 阶段 | 平均分 |
|---|---|
| Tülu 3 8B SFT | 60.6 |
| Tülu 3 8B DPO | 64.7 |
| Tülu 3 8B (RLVR 后) | 65.1 |

SFT 到 DPO 涨 4.1 分, DPO 到 RLVR 涨 0.4 分. RLVR 只针对 GSM8K, MATH 和 IFEval 三个可验证任务, 原文报告的提升也在这三项上, 摊到十几项评测的平均分里就很小. 训练成本方面, 8B SFT 用 32 张 GPU 跑 6 小时, 70B SFT 用 64 张 GPU 跑 50 小时.

把几条流水线放在一起:

| 模型 | 阶段顺序 | 偏好或奖励来源 |
|---|---|---|
| InstructGPT | SFT → RM → PPO-ptx | 人工排序训练的 6B RM |
| Llama 2-Chat | SFT → 5 轮 (拒绝采样微调, V4 后加 PPO) | 有用性与安全性两个 RM |
| Tülu 3 | SFT → 长度归一化 DPO → RLVR | 合成与人工偏好对, 规则判定 |
| DeepSeek-R1-Zero | GRPO | 规则 (准确性, 格式) |
| DeepSeek-R1 | 冷启动 SFT → 推理 RL → 拒绝采样 SFT → 全场景 RL | 规则, 语言一致性, 生成式 RM, 偏好 RM |

除 R1-Zero 外, 几条流水线都把 SFT 放在最前面. R1-Zero 证明了不做 SFT 也能靠 RL 学出推理能力, 但可读性问题又迫使 R1 把 SFT 加了回来. SFT 与 RL 怎样组合, 见 [4.8.3 SFT 与 RL 的融合策略](../4.8-推理与Agent能力/4.8.3-SFT与RL的融合策略/4.8.3-SFT与RL的融合策略.md).

### 5.2 常见失效模式

后训练常见的失效有八种, 按来源可以分成三组. 第 1 到 3 条出在奖励信号上: 奖励模型和规则都只是「人类想要什么」的近似, 优化压力一大, 策略就去找近似与真实目标之间的缝隙, 所以 InstructGPT 要保留 KL 惩罚和预训练梯度, DeepSeek-R1-Zero 干脆不用神经奖励模型. 第 4 和 5 条出在偏好数据上: 标注一致率给奖励模型准确率设了上限, 比较对的组织方式又决定了奖励模型会不会过拟合. 第 6 到 8 条出在训练流程和评估上: 多轮迭代的数据怎么累积, 可读性约束和性能怎么取舍, 以及用什么指标判断 RL 到底学到了什么.

这八种在前文都已有对应的数字和处理办法, 下表集中对照:

| # | 失效 | 现象与数字 | 原文的处理 |
|---|---|---|---|
| 1 | 对齐税 | InstructGPT 只用 PPO 时在 SQuAD, DROP, HellaSwag, WMT 上退化 | 混入预训练梯度 ($\gamma = 27.8$) 恢复大部分; 原文承认没有完全消除, 且预训练数据里的不良行为可能随之变多 |
| 2 | 奖励模型被过度优化 | 奖励模型只是人类偏好的近似; $\beta = 0$ 时人类评分很差, 训练过长也伤害公开基准 | 保留 KL 惩罚, $\beta$ 取 0.01 到 0.02; 不超过 256k episode |
| 3 | 奖励黑客 | 神经奖励模型在大规模 RL 中可能被利用; 规则奖励也有格式漏洞, 例如答案提取过松 | DeepSeek-R1-Zero 只用规则奖励 |
| 4 | 偏好标注的天花板 | InstructGPT 标注员一致率 72.6% 到 77.3%; Llama 2 对「几乎一样」的样本对准确率约 55% | 记录偏好程度, 用 margin 区分差距大小 |
| 5 | 比较对打散导致过拟合 | 同一 prompt 的比较对彼此相关, 打散训练一遍就过拟合 | 同一 prompt 的全部比较放进一个 batch 元素 |
| 6 | 迭代中的遗忘 | Llama 2 V3 只用上一轮样本, 押韵诗能力退化 | 纳入全部历史轮次的最佳样本 |
| 7 | 语言混杂与可读性 | R1-Zero 的推理过程可读性差 | 语言一致性奖励和过滤规则, 代价是性能略降 |
| 8 | 对 RL 收益的误读 | DeepSeekMath 中 RL 提升 Maj@K 而不提升 Pass@K | 同时报告 Pass@K, 不只看单次准确率, 以免高估 RL 对基础能力的作用 |
