# 4.5 GRPO 家族与 RLVR

4.4 节的方法大多在 RLHF 设定下验证, 奖励来自学到的奖励模型. 数学和代码给了另一种奖励: 答案对不对, 测试过不过, 程序可以直接判定. 这种奖励不会被策略钻空子去讨好打分器 (只要判定函数本身没有漏洞), 可以长时间, 大规模地优化, 这类训练叫 RLVR (reinforcement learning with verifiable rewards). DeepSeekMath 提出的 GRPO 和 DeepSeek-R1 的成功让它成了推理模型后训练的主流算法, 随后一年里出现了一长串改法.

这一节的十篇分三部分. 01 到 07 讲 GRPO 本身和对它的改动; 08 JustRL 讲在这些改动中取舍后的一份极简配方; 09 和 10 不再改算法, 而是问 RLVR 本身的边界: 它让模型学会了新东西, 还是只让已会的东西更容易被采样到, 以及加算力能涨到哪里.

## 1. GRPO 和它留下的旋钮

### 1.1 组内相对优势

GRPO 对同一道题 $q$ 采 $G$ 条回答 $o_1,\dots,o_G$, 判定函数给出奖励 $r_1,\dots,r_G$, 第 $i$ 条回答所有 token 共享同一个优势

$$
\hat A_{i}=\frac{r_i-\mathrm{mean}(r_1,\dots,r_G)}{\mathrm{std}(r_1,\dots,r_G)}. \tag{1}
$$

然后代入 PPO 的裁剪目标, 并把 KL 从奖励里移到损失里. [01 GRPO](01-GRPO/01-GRPO.md) 讲这个目标和 DeepSeekMath 的配置: $G=64$, 学习率 1e-6, KL 系数 0.04. DeepSeekMath-Instruct 7B 经 GRPO 后 GSM8K 从 82.9% 到 88.2%, MATH 从 46.8% 到 51.7%. 论文还注意到 Maj@K 上升而 Pass@K 不变, 这个观察后来在 09 篇被系统地展开.

式 (1) 留下了几个旋钮: 分母要不要除标准差, 损失按回答长度还是按 token 总数平均, 重要性比率在 token 级还是序列级算, 越界的 token 是丢掉梯度还是缩小权重, 全对或全错的组怎么办. 组内奖励全相同时式 (1) 是 $0/0$, 这道题不贡献梯度; 若单条回答的通过率是 $p$, 这种情况的概率是 $p^G+(1-p)^G$, 在很容易和很难的题上都会频繁出现.

### 1.2 轨迹侧与奖励侧

[07 GxPO 结构扩展](07-GxPO结构扩展/07-GxPO结构扩展.md) 借 Shen 等人对策略梯度方法的分类, 给这些改法一个统一的位置. 期望回报 $J(\theta)=\mathbb E_{\tau\sim p_\theta}[R(\tau)]$ 有两部分: 轨迹从什么分布采出, 以及每条轨迹的奖励标量怎样算. GRPO 本身是奖励侧的替换, 用组内标准化后的奖励代替原始奖励; DAPO, GSPO, GMPO, GHPO 相对 GRPO 改的是轨迹侧的 clip, 采样, 比率聚合或 prompt.

这个分法的用处是判断两个改法能否叠加. 改同一侧同一项的方法互相替代, 例如 GSPO 的序列级比率和 GMPO 的几何平均都在处理 token 比率的离群值; 改不同项的方法通常可以组合, 例如 DAPO 的动态采样可以和任何一种比率形式一起用. 07 篇也把 DPO 和散度形式的 OPD 放在 $J$ 之外, 它们优化的已经不是期望回报.

## 2. 七种改法各改哪一项

### 2.1 归一化与长度

[02 Dr.GRPO](02-DrGRPO-去标准差/02-DrGRPO-去标准差.md) 指出式 (1) 和 GRPO 的损失里有两处偏差. 损失按每条回答的长度 $1/|o_i|$ 平均, 错误回答越长受罚越轻, 模型会把错的回答写长; 除以组内标准差, 让通过率接近 0 或 1 的题获得更大权重, 引入难度偏差. 去掉这两项后回到带无偏基线的蒙特卡洛策略梯度. 用 Qwen2.5-Math-7B 和 MATH level 3-5, 7B 模型在 AIME 2024 上到 43.3%, 8 张 A100 约 27 小时.

DAPO 在 07 篇里有完整讨论, 它对 GRPO 做了四处修改: clip 上下界拆开为 0.2 和 0.28, 让低概率 token 有上升空间; 动态采样丢掉全对和全错的组, 补采到 batch 填满; 损失按组内 token 总数平均; 对超长回答做软惩罚. 在 Qwen2.5-32B 上 AIME 2024 从朴素 GRPO 的 30 分升到 50 分. 07 篇也讲了 GHPO: 对模型全答错的难题, 把标准解的前 25%, 50% 或 75% 作为提示接在题目后面, 让这类题重新产生梯度.

### 2.2 比率与裁剪

GRPO 沿用 PPO 的 token 级比率和硬裁剪. [04 GSPO](04-GSPO/04-GSPO.md) 把比率收成长度归一化的序列级比率, clip 也作用在序列上, 裁剪范围小到 3e-4 和 4e-4. 它对 MoE 的好处最明显: Qwen3-30B-A3B 每次更新后同一条回答约 10% 的激活专家会变, token 级比率被路由变化打乱, GRPO 要缓存旧路由做 Routing Replay 才能收敛, GSPO 不需要. 同一篇也讲了 DCPO, 它留在 token 级, 让裁剪界随旧概率变化.

[05 GMPO](05-GMPO/05-GMPO.md) 把 token 级加权奖励的算术平均换成几何平均, 单个离群比率对整体的影响被压小, clip 窗口因此能放宽到 $(e^{-0.4},e^{0.4})$; R1-Distill-Qwen-7B 五份数学卷均分 63.4 对 GRPO 的 59.3. [03 CISPO](03-CISPO-裁剪重要性权重/03-CISPO-裁剪重要性权重.md) 来自 MiniMax-M1, 不裁 token 的更新, 而是裁重要性权重本身并做 stop-gradient, 越界 token 仍有梯度; Qwen2.5-32B 上用 DAPO 一半的步数达到 DAPO 的 AIME 成绩. [06 SAPO](06-SAPO-温度软门/06-SAPO-温度软门.md) 把硬裁剪换成温度控制的 sigmoid 软门, 负优势用更高的温度; Qwen3-30B-A3B-Base 冷启动时 GSPO 和 GRPO-R2 早期崩溃, SAPO 保持稳定.

## 3. 改法对照与一份极简配方

### 3.1 对照表

| 方法 | 改动位置 | 比率粒度 | 越界处理 | 代表结果 |
|---|---|---|---|---|
| GRPO | 奖励侧: 组内标准化 | token | 硬裁剪, 丢梯度 | MATH 46.8% 到 51.7% |
| Dr.GRPO | 去掉长度与标准差归一 | token | 同 GRPO | AIME24 43.3%, 27 小时 |
| DAPO | 拆 clip 界, 动态采样, token 级聚合 | token | 非对称硬裁剪 | AIME24 30 到 50 |
| GSPO | 序列级比率 | 序列 | 序列级硬裁剪 | MoE 不需要 Routing Replay |
| GMPO | 几何平均 | token, 几何聚合 | 放宽窗口 | 63.4 对 59.3 |
| CISPO | 裁重要性权重 | token | 权重封顶, 梯度保留 | 一半步数追平 DAPO |
| SAPO | 软门代替硬裁剪 | token 或序列 | 平滑衰减 | 冷启动不崩 |

前四行和后三行关心的是不同的事. Dr.GRPO 和 DAPO 处理的是梯度往哪个方向偏: 长回答, 难题, 全对全错组各自得到多少权重. GSPO 往下的四种处理的是更新会不会失控: 一条回答里个别 token 的比率离群时, 是整条回答一起看 (GSPO), 用几何平均压住 (GMPO), 保留方向只限幅度 (CISPO), 还是平滑地减小权重 (SAPO).

表里的数字来自各自的论文, 底座, 数据和评测都不同, 只能看方向. 10 篇 ScaleRL 是少有的在同一设置下比较损失类型的工作: 8B 稠密模型上 GSPO 和 CISPO 的渐近通过率都明显高于 DAPO, CISPO 后期略好且对上界参数不敏感, 被选进最终配方.

### 3.2 JustRL: 少改也能到

[08 JustRL](./08-JustRL-极简配方/08-JustRL-极简配方.md) 反过来做: 用 veRL 默认的 GRPO, 每题 8 条, DAPO 的规则验证器, clip 上界放到 1.28, 不加 KL 和熵正则, 单阶段, 超参全程固定, 上下文 16k. 两个蒸馏过的 1.5B 模型上, 九项数学平均分别到 54.87% 和 64.32%, 略高于多阶段的 ProRL-V2 和 QuestA, token 预算约为对方的 1/2 和 1/2.4.

前面的改法仍然有用. JustRL 的起点是已经蒸馏过的推理模型, clip 上界和 DAPO 验证器本身也来自前面的工作. 它说明的是: 在一个好的起点上, 多阶段课程, 动态长度调度和各种正则带来的收益, 可能小于它们增加的调参成本. 先跑通一份简单配方再逐项加改动, 比一次堆满所有技巧更容易判断哪一项真的有用.

## 4. RLVR 的边界与算力曲线

### 4.1 采样效率还是新能力

[09 RLVR 的局限性与探索边界](./09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md) 的主要证据来自 Yue 等人. RLVR 训练后 pass@1 普遍上升, 但 $k$ 取大时基座的 pass@k 会追上甚至反超. 在 AIME24 上取 $k=1024$, 只有 RL 模型能解的题占 0.0%, 只有基座能解的占 13.3%, RL 模型能解的题几乎是基座能解的子集. 困惑度分析也指向同一结论: RL 模型的回答在基座下概率并不低. 蒸馏则在所有 $k$ 上都有提升, 因为教师带来了基座没有的推理模式.

ProRL 给出了反例的条件. 加 KL 并定期重置参考模型, 在 136K 道跨领域题目上训 2000 多步, 8 个阶段, 约 1.6 万 H100 小时, 数学平均从 44.45 到 60.14, 基座完全解不了的 boxnet 任务被解出. 它按任务把 RL 的效果分成三类: 增益随训练消失, 停在平台, 持续上升. 09 篇的建议是评估 RL 效果要画完整的 pass@k 曲线, 看通过率直方图和集合差, 单看 pass@1 区分不了这几种情况.

### 4.2 能否提前预测回报

[10 ScaleRL](./10-ScaleRL-尺度定律的再发现/10-ScaleRL-尺度定律的再发现.md) 用超过 40 万 GB200 GPU 小时做消融, 把验证集通过率随算力 $C$ 的变化拟合成 sigmoid:

$$
R_C-R_0=\frac{A-R_0}{1+(C_{\mathrm{mid}}/C)^{B}}, \tag{2}
$$

$A$ 是渐近上限, $B$ 和 $C_{\mathrm{mid}}$ 决定多快接近上限. 它的发现是改动分两类: 损失类型, LM head 用 FP32 和异步方式能移动 $A$; 损失聚合, 优势归一化, 课程和长度控制主要改效率. 合成的 ScaleRL 配方在 8B 稠密模型上跑到 10 万 GPU 小时, 用前 5 万小时拟合的曲线外推到了终点.

这条曲线和 09 篇的结论可以对照着读. ScaleRL 的上限 $A$ 是在固定底座, 固定数据上的上限, 它告诉你继续加算力还能涨多少, 不告诉你上限是否超出了基座的覆盖. 两篇放在一起的含义是: 小规模实验应该比较拟合出的 $A$, 只看早期斜率会误判, 早期跑得快的配方不一定涨得高; 而 $A$ 本身受底座和数据限制, 要扩大它, 换底座, 加蒸馏或换任务比调损失更直接.

## 5. 从哪里读起

### 5.1 按目标

只想跑通一次 RLVR 的读者, 先读 [01 GRPO](01-GRPO/01-GRPO.md), 它的后半篇讲一轮 GRPO 在推理引擎和训练引擎之间怎么走, 然后直接看 [08 JustRL](./08-JustRL-极简配方/08-JustRL-极简配方.md) 的配置. 训练不稳定, 回答越写越长或在 MoE 上不收敛时, 读 [07](07-GxPO结构扩展/07-GxPO结构扩展.md) 的失效表, 再按症状去 [02](02-DrGRPO-去标准差/02-DrGRPO-去标准差.md), [04](04-GSPO/04-GSPO.md), [03](03-CISPO-裁剪重要性权重/03-CISPO-裁剪重要性权重.md), [05](05-GMPO/05-GMPO.md) 或 [06](06-SAPO-温度软门/06-SAPO-温度软门.md).

要判断 RL 值不值得继续投入的读者, 读 [09](./09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md) 的评测建议和 [10](./10-ScaleRL-尺度定律的再发现/10-ScaleRL-尺度定律的再发现.md) 的拟合方法. 策略梯度, 基线和 PPO 裁剪的推导不在这一节重复, 需要时回到 [4.4 强化学习基础](../4.4-强化学习基础/4.4-强化学习基础.md).

### 5.2 与后续各节的接口

GRPO 一族在完整训练流程里怎样用, 看 [4.8 推理与 Agent 能力](../4.8-推理与Agent能力/4.8-推理与Agent能力.md): 4.8.1 讲 DeepSeek-R1 的可验证奖励 RL, 4.8.2 讲 GLM-5 用 GRPO 加 IcePop 处理训推不一致, 4.8.3 讲示范怎样接进 GRPO 的组内或前缀. 09 篇提到的蒸馏能扩大覆盖, 在 [4.9 OPD](../4.9-OPD/4.9-OPD.md) 里有更细的展开.

可验证奖励之外, 只有偏好数据时看 [4.6 偏好优化](../4.6-偏好优化/4.6-偏好优化.md); 奖励来自学到的奖励模型而担心被优化过头时看 [4.7](../4.7-AI反馈与奖励过优化/4.7-AI反馈与奖励过优化.md).
