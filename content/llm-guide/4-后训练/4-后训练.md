# 4 后训练:SFT, 对齐, 蒸馏与持续学习

预训练只教会模型「接话";后训练才决定它接什么样的话.本章覆盖预训练之后的一整条流水线:SFT 把指令格式和领域知识灌进去, RL 类方法把输出对齐到人类偏好, OPD 和蒸馏把大模型的能力迁到小模型, 持续学习让模型在不冲刷旧知识的前提下更新.

注意力 / MoE / 推理优化公式在 [第 2 章](../2-核心原理与架构/2-核心原理与架构.md); 预训练流程在 [第 3 章](../3-预训练/3-预训练.md); 具体模型如何组合这些方法及其一手报告统一见 [主流模型知识库](../../model-library/_garden.md); Agent 训练见 [Agent 正本](../13-Agent/13-Agent.md).

## 2. 后训练到底在调什么

预训练损失是 next-token, 目标单一但数据杂.后训练的目标正好相反: 数据经过精心构造, 损失函数却要同时承担格式,知识,风格,安全和可用性.同一份 SFT 数据里, 既要让模型学会「按指令回答」, 又不能让它过度拟合训练集中的语气; 同一趟 RLHF 里, 既要让回答更有帮助, 又不能让它学会讨好或说谎.

因此后训练不是「在预训练后面再加一个步骤", 而是一组相互牵制的目标. SFT 负责能力和格式, RL 负责偏好和边界, 蒸馏负责压缩和迁移, 持续学习负责稳定性. 它们共享同一个基座, 但各有各的失败模式.

## 3. 三条主线

**对齐.** 从 PPO + 奖励模型, 到 DPO 跳过奖励模型, 再到 GRPO 省去 Critic, 对齐方法一直在简化流程.核心矛盾没变: 奖励信号来自人类或 AI 裁判, 模型很容易找到奖励函数的捷径. 解决奖励黑客,长度偏见,模式坍塌, 比设计损失函数本身更难.

**蒸馏.** 大模型生成数据或 logits, 小模型跟着学. OPD 让学生自己采样前缀, 教师只在学生已经展开的路径上给监督, 这是后训练阶段才成立的设定. 它和预训练阶段的语料蒸馏不同, 也和 SFT 阶段的「模仿教师输出」不同.

**推理时缩放.** 不一定每次都要改模型. 让模型在回答前多生成几个候选,多验证几步,多轮自洽投票, 可以在不增加参数的情况下提高困难任务的准确率. 代价是延迟和计算量.

## 4. 读完本章应能回答

1. SFT 数据质量比数量更重要, 但「质量」具体指什么.
2. DPO 为什么能省掉奖励模型, 代价是什么.
3. GRPO 去掉 Critic 后, 基线从哪来.
4. OPD 和 SFT 蒸馏在采样方式上的本质差别.
5. 持续学习里, 灾难性遗忘为什么比预训练阶段的分布偏移更难处理.
