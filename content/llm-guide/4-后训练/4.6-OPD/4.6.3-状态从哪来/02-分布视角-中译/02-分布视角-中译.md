# 从分布透镜看 SFT、RL 与 On-Policy Distillation

> 作者：nrehiew（站名 wh.）  
> 副题：On forgetting, generalization, and what connects RL to on-policy distillation  
> 原文：[https://nrehiew.github.io/blog/sft_rl_opd/](https://nrehiew.github.io/blog/sft_rl_opd/) · [01 英文誊录](../01-分布视角-英文/01-分布视角-英文.md)  
> 结构保真中译。公式、表内数字、URL 未改。

我一直在用分布来想后训练方法。语言模型是序列上的一个分布。后训练、教它一项任务，就是在重塑这个分布。不同方法差在怎么塑形、把什么当目标、目标定义得有多直接。

这句话并不精确，也不是要写成严格定理。我只觉得它是一把好用的心智模型，而且能解释 SFT、RL 和 On-Policy Distillation 之间不少定性差别。下面要展开的就是这套直觉。

## 后训练的分布视角

从这个角度看，最该先问的是：我们在朝哪个目标分布优化？

### SFT：固定的外部目标分布

SFT 是最简单的情形。

你有一份标注数据。也许是人写的，也许是更强模型生成的。总之数据在训练之前就存在。然后对起始模型做交叉熵。用分布的话说：当前模型是一个分布，数据集定义另一个分布。SFT 把模型往数据集分布上拉。

负对数似然的性质决定了，你从哪个分布出发其实不太重要。所以我觉得 SFT 天然容易灾难性遗忘。如果数据集分布离模型原来的分布很远，模型没有内建理由去偏好一个近的解，只会被拉向示范 token。

这不是说 SFT 不好。SFT 极其有用。但从几何上看，它是对外部目标的一次很直接的牵引，几乎不顾起始策略。所以它适合「冷启动」类任务：期望的输出格式必须大改。

SFT 的梯度压力均匀作用在整个模型分布上，不只作用在和新任务相关的区域。箭头表示参数更新方向；它们从峰（高概率的既有能力）、谷、以及起始分布的其他区域一齐出发。青色箭头是把模型推向目标行为的更新；橙色箭头是会侵蚀既有能力的附带压力。灾难性遗忘会出现，是因为交叉熵没有内建机制去区分任务关键 token 和数据集里偶然带上的东西。

### RL：期望奖励最大的方向

在线强化学习看起来不一样。模型从自己身上采样；这些样本被某个奖励函数打分；再用策略梯度把期望奖励往上推。

这里「目标分布」更难定义。后面还会回来，但高层上，并没有一个任意的外部分布在把模型往外拉。

RL 的梯度压力只通过当前策略采样到的行为起作用。绿点是 on-policy rollout，带橙圈的点是主导更新的高奖励样本。虚线轮廓是概率质量移向受奖轨迹之后的更新策略。SFT 在外部数据集上施加 token 级压力；RL 主要重塑模型已经在访问的高概率区域。这种局部性有助于解释：RL 可以提高任务表现，却不必对无关能力施加同样宽的压力。

当然，这只有奖励有意义时才成立。RLVR 里奖励可验证，奖励方向常常是质量的不错代理，沿这个方向走应当能得到更好的模型。RLHF 里奖励模型不完美，情况更乱。后面再谈。

### On-Policy Distillation：伪 RL

On-policy distillation（OPD）夹在 SFT 和 RL 之间。像 SFT，它有教师信号。学生被训练去匹配另一个分布；但像 RL，数据来自学生。每一步算法都在做 on-policy 采样，梯度却通过 reverse KL 把模型往教师分布上拉。松散地说，OPD 可以想成一种 RL：不是用优势给 completion 加权，而是用学生和教师的对数比加权。

OPD 的一个新变体是 On-Policy Self Distillation（OPSD）。教师和学生是同一个模型，但算「教师」对数概率时，教师会拿到参考解当前缀。想法是：这份特权信息会提供学习信号。

问题在于学生和教师是同一套模型，大多数 token 上输出会非常接近。作者做了逐 token KL 分析，发现风格或枢纽 token，比如 “wait” 或 “alright”，KL 可以高于数学 token，比如 “power”、“exponent”、“logarithm”。因此如果在这些不重要 token 上更新太猛，模型可能坍缩。解决办法是引入逐 token 裁剪，防止过更新。

在所有 thinking 配置里，风格 token 的逐 token KL 显著更高，数学 token 的 KL 最低。

这就是为什么 OPSD 感觉更接近 RLHF 而不是 RLVR。RLHF 里奖励模型信号偏差更高，所以要用 KL 惩罚和置信域式裁剪，避免把错的东西优化过头。OPSD 里教师信号也并不与任务重要性完美相关，因为高 KL 的 token 可能只是风格。可验证奖励偏差更低。这也是（以及其他原因）人们在 RLVR 里更愿意去掉显式 KL 惩罚、或放松置信域约束（用 GRPO 而不是 PPO）的原因。

常见论点是：带 outcome reward 的 RLVR 在逐 token 信用分配上很吃力，优势函数每个 episode 只提供 $O(1)$ 比特信息（Schulman et al., 2025）。OPSD 好像走到另一极端：每个 token 都有自己的「奖励」，但算法每次更新引入的噪声和偏差也更大。

## 用不同教师做 On-Policy Distillation

这组实验用的是我的 Minimal Code Editing 任务。强烈建议先读我上一篇，再往下看。快速摘要：模型拿到一个被破坏的有 bug 函数，只要求修这个 bug。我们检查解是否能跑，以及函数其余部分有没有相对未破坏原函数被改写。我喜欢这个环境，因为它能测两件事：

1. **泛化**：可以在一类破坏上训练，在另一类破坏上评估。这样能问模型学到的是「最小编辑」这种一般行为，还是只会还原特定破坏。
2. **灾难性遗忘**：和标准代码生成不同，最小编辑是一种很窄的编码行为。因此可以把微调后的模型放到 LiveCodeBench 上，看通用代码生成有没有掉。

实验里我先分别用 SFT 和 RL 训练了两个教师。两个教师的表现复现了上一篇的结果。两者都学会了最小编辑，但 RL 泛化更好、没有明显遗忘，SFT 则在通用代码生成上掉了。做 OPD 之前，我预期从 RL 教师蒸馏出的学生会更好。

| Model | Pass@1 ↑ | Norm. Levenshtein ↓ | Added CC ↓ | LiveCodeBench v6 ↑ |
| --- | --- | --- | --- | --- |
| Teachers | | | | |
| SFT | 0.775 | 0.450 | 0.450 | 0.286 |
| RL | 0.792 | 0.063 | 0.206 | 0.320 |
| Students (OPD) | | | | |
| OPD SFT teacher | 0.800 | 0.059 | 0.206 | 0.297 |

教师 vs on-policy distillation 学生，在最小编辑任务（域外破坏）和 LiveCodeBench v6 上。

实际不是这样。

从 SFT 教师训出的 OPD 学生，和从 RL 教师训出的 OPD 学生，看起来极度相似。更意外的是，两个 OPD 学生都略超过 RL 教师，并显著超过 SFT 教师。即便 RL 教师在自己的训练 run 里最终奖励更高，也还是这样。

再者，尽管 SFT 教师在通用代码生成上掉了、RL 教师没有，从两个教师训出的 OPD 学生都只有轻微遗忘。OPD 学生忘得比 SFT 教师少，哪怕教师本身就是那个退化了的 SFT 模型。这很意外：如果教师分布才是主因，从 SFT 教师训出的学生应当继承更多 SFT 教师的遗忘。但它没有。

这说明数据从哪来（也就是 via on-policy 采样）很重要，教师也许没我预期的那么重要。这是个让人放心的结果：我们可以把一个专项模型「训过头」——哪怕用蛮力 SFT——再做 OPD 把这项能力学过来，同时保住大量其他我们在乎的能力。

## 为什么 RL 忘得更少？

常见解释有几条。我觉得它们都有一点真，但大多数我并不觉得完全够。

### SFT 是 Forward KL，RL 是 Reverse KL

第一条解释常常和两种算法优化的 KL 方向有关。在固定数据集上的交叉熵，等价于最小化 forward KL，差一个常数。

$$
\begin{align}
D_{KL}(p \| q_\theta) &= \sum_x p(x) \log \frac{p(x)}{q_\theta(x)} \\
&= \sum_x p(x) \log p(x) - \sum_x p(x) \log q_\theta(x) \\
&= -H(p) + H(p, q_\theta)
\end{align}
$$

Forward KL 的 mode-covering 行为因此可能牺牲旧模态（代表既有能力）去学新任务。Chen et al., 2025 表明，RL 可以看成 reverse KL 最小化。

在一个玩具多模态设定里，作者显示 reverse KL 比 forward KL 忘得少。

我觉得这类论证有用，但不完整。问题在于它严重依赖对参考模型的显式 KL 正则。但经验上，即使去掉或大幅削弱这条 KL 惩罚，RL 仍然可以抗遗忘。RLVR 里人们常用比 RLHF 弱得多的 KL 约束，抗遗忘往往还在。

### SFT 有均匀、猛烈的 token 级梯度

#### 数据依赖的正则

首先，SFT 对每个 token 给稠密、均匀的监督。SFT 里每个示范 token 都被当成模型应当提高概率的东西。这个 token 可能是任务关键的，比如一个数学算符；也可能是风格 token，比如 “therefore” 或 “we can see that”。损失不知道差别，只是把示范 token 的概率往上推，造成宽更新。Diao et al. 发现 SFT 里有许多低概率、低熵的 token。这意味着模型对自己的预测高度自信，却被迫拟合一个分叉的真值标签，会伤到既有表征。

相比之下，RL 有某种数据依赖的正则（Lai et al., 2025）。例如优势估计时在组内归一化奖励，多样性更高、奖励方差更大的组，更新会小于低方差的组。模型不确定时，更新幅度会自然变小。反过来，模型持续给出高奖励回复的样本上，更新更猛。

#### RL 的参数更新更稀疏

于是 Mukherjee et al. 发现，RL 只通过稀疏但满秩的更新改模型的一小块子网络，而 SFT 诱发稠密更新。类似地，Yuan et al. 发现 SFT 的参数更新更冗余。他们裁掉 SFT 和 RL 各自更新的参数数量后，发现 RL 的性能掉得快得多，这确认了 SFT 更新更冗余，而 RL 更新对最终任务表现更关键。

就 SFT vs RL 的比较而言，这两部分论证经验上都站得住。我稍微怀疑它们是否一般到足以拿来做算法分析，还是只对作者测过的领域成立。再者，OPD 怎么嵌进这幅图？

### 我更偏好的解释：On-Policy 数据

我最认同的是 Shenfeld et al. 那条。有兴趣的读者建议读原文，但直觉用一个非常简单的 RL 版本最容易看清。假设我们用带二元 0/1 奖励的 REINFORCE。奖励是 1，贡献正训练信号；奖励是 0，贡献为零。这时奖励像过滤器，看起来很像拒绝采样。

回到一开始的目标分布，RL 现在有一个了。我们可以把最优策略定义成：该策略下所有 completion 的奖励都是 1。当然最优策略有多个，但因为我们在当前策略生成的 on-policy 样本上训练，这个最优分布是所有最优策略里离当前策略最近的那个。做一步策略梯度时，我们是在把当前策略拟合到这个新的最优策略上，而它隐含地对当前策略有低 KL。因此 RL 学到的是最近的任务求解策略。

这给了遗忘一种很不同的几何。On-policy 数据把训练程序约束到每一步都靠近起始策略的分布。相比之下，SFT 的目标分布可以任意远。

这就是为什么我觉得 OPD 继承了 RL 的一部分抗遗忘，以及为什么从 SFT 教师蒸馏出的 OPD 学生可以比 SFT 教师自己忘得更少。教师是在外部数据上训的，学生是在自己的数据上训的。即便信号来自教师，状态分布仍是学生的。

这也回答了 on-policy distillation 为什么对遗忘更鲁棒。必须承认，on-policy distillation 的信号方差可能更高，因为 logits 分布并不完美；但因为 on-policy，设定里已经内建了隐式 KL 正则。

On-policy 训练隐式选择离当前模型最近的任务求解策略。它不是把模型拉向任意外部目标，而是通过从当前策略采样，把更新约束在模型已经访问的区域。在最优策略集合 $P^{*}$ 里，训练因此趋向最近可达最优点 $\pi^{*}$。这有助于解释 on-policy 方法为何能提高任务表现，同时保留更多原始策略。（图受 Shenfeld et al. Fig 5 启发。）

### 学生为什么能超过教师？

这是实验里另一件意外的事，但并不新。事实上 Agarwal et al. 的原作就已经显示，蒸馏学生在 GSM8K 上超过教师。我没有一个板结的解释，但有几条说得通的假说。

和传统蒸馏不同，OPD 的监督可以更定向，因为它用学生生成的状态。这很重要：学生的错误不必是教师的错误。如果只在教师生成的轨迹上训练，学生可能在自己很少访问的分布区域收到监督。但在 OPD 里，教师是在学生自己的前缀上给建议。

第二，KL 匹配不等于奖励最大化。文首我把 OPD 说成有点像带 token 级教师监督的 RL，这个类比并不完美。最小化 KL 的训练信号，偏差显著高于标准 RLVR 奖励。教师分布可能包含风格、不确定性、备选续写和推理结构等信息。匹配它可以重塑学生分布、改善采样行为，而不必精确复现教师的贪心行为。

所以即便教师自己采样出的输出并不更好，学生仍可以变好。如果只按单个 token 想，这很难讲通。按分布塑形来想，更说得过去。

把训练想成改变模型分布的形状，这种视角可以反直觉。一个例子是 Zhang et al.。作者报告：每个 prompt 只用 1 条模型生成的 completion、而且不做正确性过滤，训练仍能提升编码。更意外的是，他们用高温做自蒸馏——训练数据变成乱码——在这种差数据上训练仍然提升表现。作者试图用某些 token 上的概率输出来解释，但要点是：在这些高维对象上建立直觉极其困难。

我目前最好的解释是：模型在新能力周围经历了 mode collapse。看 OPD 和 RL 训练中的熵统计，OPD 的熵坍缩剧烈得多。这和 reverse KL 训练的 mode-seeking 行为相符，mode-collapse 可能导致多样性下降（Gu et al., 2023）。我不想把这一节说满，因为它仍属推测；但我确实觉得分布视角是正确的起点。

OPD vs RL 的奖励与熵训练曲线。RL 的奖励是逐渐升高的；OPD 的奖励升高突然得多，并对应一次剧烈的熵坍缩。

## 为什么 RL 和 OPD 泛化更好？

上面几节的分析已经覆盖了大部分。首先，SFT 里模型会因为没有把概率分给某个特定答案而受罚。另一方面，RL 从构造上就不那么像模仿，因为监督贴在任务成功上，而不是贴在某一串特定 token 上。

关键处可以借用 Ross et al.。SFT 里模型只看到教师访问的状态。测试时因为自回归，学生的一次错误可能把它带到教师从未访问过的状态。当学生的前缀（或当前状态）和教师会做的不一样，这种错配会造成复合误差。因此 on-policy 数据聚合可以减小这种错配。

## 完整管线

多数（开源）模型用 Pretrain-SFT-RL-OPD 管线。预训练之后需要 SFT，既为了格式遵守，也为了灌入基本指令跟随；没有这些，RL 无法高效进行（Chu et al., 2025）。但之后呢？

最近 GLM 5 和 DeepSeek v4 都用 OPD 把专家能力并进最终模型，最终检查点不再走 RL。这引出一个问题：这些专家该怎么训？跨方法比较的一个有用参照是 MiMo-V2 Flash 技术报告。

数学和代码任务倾向 RL。这不意外，我们知道 RLVR 在这些域上能工作。创意写作和一些偏知识的基准似乎更受益于自蒸馏或蒸馏类方法。这也说得通：这些域里奖励噪声大得多。如果依赖 LLM judge，我们是在优化一个有偏的质量代理。

表还比较了最终合并模型相对各教师的表现。学生真正比教师差的域，只出现在教师也是自蒸馏的域，以及 SFT 域的 BrowseComp。在 RL 域，最终合并模型几乎总是超过教师，幅度各异。原因仍待观察，但考虑到多数后训练管线正在收敛到某种专家合并作为最后一站，这一点值得标出来。

## 最好的算法

这篇受 Brown, 2026 启发。他把每种后训练方法写成：在相对先验的 KL 的不同权衡下最大化能力。文章结尾暗示存在某种比 RL 更算力最优、仍能保住能力 vs KL 移动这条帕累托前沿的算法。

我希望这篇能说服你的是：任何这种算法都必须靠 on-policy 数据。不是 RL 这种算法特别特殊，也不是显式 KL 惩罚在扛重活。能把能力往上推、又不把 KL 预算冲爆的，是 on-policy 训练。洞察并不新（Lu et al., 2025），但我没找到一个地方把研究收拢在一起，而且文献大多仍把 RL 写成扁平的「更优越」。

On-Policy Distillation 越来越流行，其实让这件事更容易看见。把它和 RL、SFT 放在一起，OPD 和 RL 落到相近的地方，这才让我确信 on-policy 数据是承重构件。另一只旋钮，也是我认为这种假想算法必须做对的，仍是老的信用分配问题。Outcome reward 太稀，所以 RL 这么贵。Lightman et al. 那种 Process Reward Model 在规模上训不高效。从教师做 logit 蒸馏，每个 token 信号更密，但代价是偏差，然后又被迫上各种裁剪。

所以问题的形状比解更清楚：你想要蒸馏的密度、RL 的无偏、以及两者都有的 on-policy 性质。作为具体算法它长什么样，我不知道。
