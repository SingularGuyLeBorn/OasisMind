# 4.6 · On-Policy Distillation

本库 OPD = **On-Policy Distillation**：学生按当前策略自己采样，教师在这些**学生前缀**上给逐 token 密集监督。卡住的是 off-policy 蒸馏只在教师 / 数据前缀上教、推理却走学生自己的前缀（暴露偏差），而 RL 虽 on-policy，监督却常稀到整条轨迹一个标量。本节是后训练里这块的地图；数字与公式以 01–10 专文为准。**不是** Online Preference Distillation，不是 DPO 换名。MiniLLM（reverse KL + policy gradient）与 GKD（学生前缀上的 KL，不对采样反传）是两条梯度，不要合成「OPD = Reverse KL」。

## 怎么读

`01`–`10` 是这一节的专文，夹名就是文章名。先看 [01](./01-OPD-学生前缀蒸馏/01-OPD-学生前缀蒸馏.md) 钉定义和 Qwen3 Table 21 分母；各家报告各写各的损失见 [10](./10-OPD-各家报告对照/10-OPD-各家报告对照.md)；$f$-散度综述在 [4.6.2](./4.6.2-OPD综述/4.6.2-OPD综述.md)；「监督打在哪些前缀上」在 [4.6.3](./4.6.3-状态从哪来/4.6.3-状态从哪来.md)。节根还有一篇旧的 [Self-Distillation-条件增强](./Self-Distillation-条件增强.md)，当历史入口，不是 01 的替代。

## 1. 钩子：SFT 抄前缀，RL 只给一个标量

LLM 做完 SFT 之后，常见下一步是 PPO / GRPO。三条路各自卡在不同位置：

1. **PPO 的复杂度**：Actor、Critic、Reward Model、Reference 常要同时占显存。
2. **奖励稀疏**：生成几百个 token 后只拿到一个标量（+1 / −1）。Credit assignment 难：不知道哪一句对、哪一句错。
3. **Off-policy 蒸馏的暴露偏差**：用强模型轨迹做 SFT，学生只在教师 / 数据前缀上挨打。推理时一旦写出自己的前缀，就离开了训练状态。

On-Policy Distillation 换的是**状态从哪来**：让学生自己采样（on-policy，对上推理时的前缀），再让教师在这些前缀上给 token 级密集监督（dense，对上 RL 的稀疏）。教师可以是更强的外部模型（[01](./01-OPD-学生前缀蒸馏/01-OPD-学生前缀蒸馏.md) / Qwen3 Strong-to-Weak），也可以是同一套权重加上特权上下文（[02](./02-OPSD-参考解自蒸馏/02-OPSD-参考解自蒸馏.md) 起）。没有可查询的教师时，01 这套不成立，不要把「自己当自己的老师」写进 OPD 的定义。

Qwen3 Table 21 的对照只在很窄的格子上成立：**Qwen3-8B、同一个 off-policy distilled 8B checkpoint、只比 math+code**；括号是 pass@64。同一检查点上 RL 用 **17,920** GPU hours 把 AIME'24 推到 **67.6**，on-policy distillation 用 **1,800** GPU hours 推到 **74.4**。1,800 / 17,920 ≈ 1/10 是这一行的算术，不是「所有后训练任务都用 1/10 算力超过 RL」，也不要安到 V4。分母与表行见 [01](./01-OPD-学生前缀蒸馏/01-OPD-学生前缀蒸馏.md) 与 [10](./10-OPD-各家报告对照/10-OPD-各家报告对照.md)。

## 2. 三种后训练：抄卷、打分、在学生前缀上教

- **SFT / Off-policy 蒸馏**：学生照着学霸试卷抄。考场上遇到学霸没写过的前缀，当场懵（暴露偏差）。
- **RL**：学生自己做卷，老师只在卷末给总分。要猜哪一步对了（奖励稀疏）。
- **OPD（On-Policy Distillation）**：学生自己写（前缀来自 $\pi_\theta$）。教师不再重写一条满分轨迹，而是对**已经写出的每个前缀**给分布 / logits。01 需要一名可查询的教师；[02-OPSD](./02-OPSD-参考解自蒸馏/02-OPSD-参考解自蒸馏.md) 把教师换成「同一套权重 + 参考解 $y^{\star}$」——**需要 $y^{\star}$**，不是「全靠自己探索、没有满分答案」。没有 $y^{\star}$ 时教师退化成学生，散度为 0。

## 3. On-policy 钉在采样；散度不是定义

综述把 OPD 写成：外层期望在学生当前策略上，

$$
\min_{\theta}\mathbb{E}_{x\sim\mathcal{D}}\,\mathbb{E}_{y\sim p_{\theta}(\cdot \mid x)}\bigl[\mathcal{L}(y,x;\theta,T)\bigr]. \tag{1}
$$

$\mathcal{L}$ 可以是散度、奖励或混合。关键是 $y\sim p_\theta$，不是固定语料或教师生成分布。这和 DPO 不是一条路：DPO 优化成对偏好，不必在学生前缀上查教师全词表 logits。

传统监督蒸馏常用 **Forward KL**：

$$
 D_{\mathrm{KL}}(\pi_T \Vert \pi_\theta) = \mathbb{E}_{x \sim \pi_T} [\log \pi_T(x) - \log \pi_\theta(x)] \tag{2}
$$

它是 mean-seeking：老师觉得两个答案都行，学生容易往中间挤。它也强迫学生覆盖老师的长尾，能力不够时容易幻觉。

**Reverse KL** 把期望换到学生自己的轨迹上：

$$
 D_{\mathrm{KL}}(\pi_\theta \Vert \pi_T) = \mathbb{E}_{x \sim \pi_\theta} [\log \pi_\theta(x) - \log \pi_T(x)] \tag{3}
$$

它是 mode-seeking：老师给出多个可行解时，学生可以贴其中一个。这是 **MiniLLM** 的目标，再对 $y\sim q_\theta$ 做 policy gradient。**GKD** 的 on-policy 钉在**状态分布**：先让学生生成前缀，再在这些前缀上做全词表 KL，**不对采样路径反传**；论文默认写出的是 forward KL，散度本身可选 reverse / JSD，哪一种更好写成 task-dependent。Qwen3 只写 “aligning its logits … to minimize the KL divergence”，**未点名**正反向。两条梯度不要合成一句「OPD = Reverse KL」。推导见 [01](./01-OPD-学生前缀蒸馏/01-OPD-学生前缀蒸馏.md)。

## 4. 教师从哪来

| 槽 | 教师是谁 | 专文 |
|----|----------|------|
| Strong-to-Weak | 同系列更大的指令模型（Qwen3-32B / 235B-A22B 压 8B） | [01](./01-OPD-学生前缀蒸馏/01-OPD-学生前缀蒸馏.md)、[10](./10-OPD-各家报告对照/10-OPD-各家报告对照.md) |
| 参考解特权上下文 | 同一套权重，$p_\theta(\cdot\mid x,y^{\star})$ 只做 prefill | [02-OPSD](./02-OPSD-参考解自蒸馏/02-OPSD-参考解自蒸馏.md) |
| 示范特权上下文 | 教师多看 $d$，学生仍 $\pi_\theta(\cdot\mid x)$；教师 EMA | [03-SDFT](./03-SDFT-示范持续学习/03-SDFT-示范持续学习.md) |
| 环境 rich feedback | 堆栈 / 失败单测 / 同组成功解条件化同一套权重，对已生成 $y$ 重算 log-prob | [04-SDPO](./04-SDPO-环境反馈蒸馏/04-SDPO-环境反馈蒸馏.md) |
| 多教师合版 | 分域 RL 专家并进一份学生权重 | [09-MOPD](./09-MOPD-多教师蒸馏/09-MOPD-多教师蒸馏.md) |

双路 prompt（高信息量上下文 vs 低信息量上下文、同一套权重）是自教师的一种实现，属于 02 / 03 这一格，不是 01 的定义。示意损失（学生在前、教师在后）：

$$
 \mathcal{L} = \sum_{i=1}^T P_S(y_i \mid x_{\mathrm{low}}, y_{<i}) \left[ \log P_S(y_i \mid x_{\mathrm{low}}, y_{<i}) - \log P_T(y_i \mid x_{\mathrm{high}}, y_{<i}) \right] \tag{4}
$$

工程上常用单样本近似，或改 JSD 避免数值炸掉。这只是示意，不要当成 MiniLLM 实现。

## 5. 50 行 PyTorch 示意

下面这段展示「同一套权重、两条上下文、教师切断梯度」。`F.kl_div(input=log S, target=T)` 在 PyTorch 里是 $\mathrm{KL}(T \Vert S)$，即 **forward KL**，不要把它读成 MiniLLM 的 reverse KL + policy gradient。

```python
import torch
import torch.nn.functional as F

def opd_self_distillation_step(model, inputs_student, inputs_teacher, temperature=1.0):
    """
    自教师示意：同一套权重，两条上下文。
    inputs_student: shape (B, L) 学生上下文
    inputs_teacher: shape (B, L) 教师上下文（例如带 detailed system prompt）
    """

    # [1] On-Policy 采样：学生自己生成轨迹（这里省略自回归，假设输入已含 y）
    model.train()

    # [2] 学生分布 — 开梯度
    logits_S = model(inputs_student).logits

    # [3] 教师分布 — 不传导梯度
    with torch.no_grad():
        logits_T = model(inputs_teacher).logits

    log_probs_S = F.log_softmax(logits_S / temperature, dim=-1)
    probs_T = F.softmax(logits_T / temperature, dim=-1)

    # [4] PyTorch kl_div(input=log S, target=T) = KL(T || S) = forward KL
    loss_kl = F.kl_div(
        input=log_probs_S,
        target=probs_T,
        reduction='batchmean'
    ) * (temperature ** 2)

    # 实务里常再加 NLL，避免分布崩溃
    # labels = ...  # 从轨迹取 token
    # loss_nll = F.cross_entropy(logits_S.transpose(1, 2), labels)
    # total_loss = loss_nll + alpha * loss_kl

    return loss_kl
```

这段没有第二个模型：区别只在上下文。`torch.no_grad()` 切断教师梯度。要做 MiniLLM 那种 reverse KL，需要对 $y\sim q_\theta$ 走 policy gradient，不是这一条 `kl_div`。

## 6. OPD vs SFT vs RL

下表是机制对照，不是算力保证。Qwen3 Table 21 的 **17,920 vs 1,800 GPU hours** 只属于 **8B、同一 off-policy 检查点、math+code**，见 §1。

| 维度 | SFT / Off-Policy | RL (PPO/GRPO) | OPD（On-Policy Distillation） |
|------|------------------|---------------|------------------------------|
| **采样策略** | 静态外部数据集 | 动态 **On-Policy** | 动态 **On-Policy** |
| **监督粒度** | Token-level（硬标签） | Sequence-level（稀疏标量） | **Token-level（密集分布）** |
| **探索能力** | 无（纯模仿） | 强（但容易 Reward Hacking） | 中等（在学生自己会走到的前缀上） |
| **显存占用** | 低（1× Model） | 极高（3×–4× Models） | 中（常需师生双路前向） |
| **收敛速度** | 快 | 慢（稀疏信号） | 快（稠密梯度；分母见 Table 21） |
| **典型失效** | 暴露偏差 | 模式坍缩 / advantage 塌缩 | MiniLLM：高熵处捏尖峰、短句 hacking；GKD：学生还不会说话时前缀是垃圾 |

「相对稳定靠 Reverse KL 兜底」只覆盖 MiniLLM 那条目标，不要写进 OPD 定义。

## 7. 家族与厂商捆法

1. **SDPO（Self-Distillation Policy Optimization）**：[04](./04-SDPO-环境反馈蒸馏/04-SDPO-环境反馈蒸馏.md) 换的是 GRPO 的 token 级优势。环境 rich feedback 条件化同一套权重当自教师，对已生成 $y$ 重算 log-prob，KL(学生 ∥ stopgrad(教师))。**不是**把 OPD 的 reverse KL 塞进 DPO，也不是 02 的标准答案特权上下文。LCBv6 / Qwen3-8B：**48.8 vs GRPO 41.2**（Table 5/9）。Claude Opus 4 **39.7%** 是公开榜，不是训练格。

2. **G-OPD / SCOPE**：05 把蒸馏目标写成 f-散度 / $\lambda$ 光谱；06 在信号进损失前做置信度门控。本波不升格成节的现行定义，专文可当背景读。

3. **多教师 OPD（DeepSeek-V4）**：混合 RL 合并阶段换成多教师 On-Policy Distillation。领域专家先各自 SFT+GRPO，再蒸馏进一个学生。V4 mineru 式 (29)：

$$
\mathcal{L}_{\mathrm{OPD}}(\boldsymbol{\theta}) = \sum_{i=1}^{N} w_i \cdot \mathrm{D}_{\mathrm{KL}}\bigl(\pi_{\boldsymbol{\theta}} \parallel \pi_{E_i}\bigr) \tag{5}
$$

轨迹从学生 $\pi_\theta$ 采样。先前工作常把全词表 KL 收成 token 级 $\mathrm{sg}[\log \pi_E/\pi_\theta]$ 当 advantage，方差大；V4 改用 **全词表 logit 蒸馏**。十余个教师。QAT/MXFP4 仍在 [6.1.7](../../6-训练与推理优化/6.1-训练基础设施/6.1.7-训练稳定性与训推不一致.md)，**禁止为 V4-Flash / 后训练刷新 mkdir**。入口：[V4 mineru §5.1.2](../../14-主流开源模型全景解析与技术报告精读/14.1-DeepSeek/10-DeepSeek-V4/04-DeepSeek-V4-mineru-zh.md)。

4. **MOPD（Kimi K3）**：三个域 × 三档 reasoning effort 共九个 RL 专家，再用 Multi-Teacher On-Policy Distillation 合成一个权重。逐 token 奖励是 $\mathrm{clip}(\mathrm{sg}(\log\pi_{\mathrm{teacher}}/\pi_\theta),-R_{\max},R_{\max})$（K3 式 (15)）。试过更细的 top-$k$ 蒸馏，报告写没有明显好处。公式以 K3 为准，不要和 V4 合成一套超参。入口：[K3 D2 §8](../../14-主流开源模型全景解析与技术报告精读/14.5-Kimi/05-Kimi-K3/01-Kimi-K3-架构精译.md)。

三家损失分叉见 [09-MOPD](./09-MOPD-多教师蒸馏/09-MOPD-多教师蒸馏.md)（V4 仍叫 OPD、全词表 reverse KL；K3 clip 对数比；MiMo 裁训推比并叠 ORM，**不要**用 $R_{\max}$ 填 Flash）。各家官方名 / 教师槽 / 数字分母见 [10](./10-OPD-各家报告对照/10-OPD-各家报告对照.md)。**17,920 vs 1,800 GPU hours 只属于 Qwen3 Table 21**，不要安到 V4。

## 8. 总结

1. OPD 的定义是 **On-Policy Distillation**：学生自己采样，教师在学生前缀上密集监督。不是对齐成对人类偏好，不是 DPO 换名。
2. **On-policy** 钉在状态从哪来，用来对暴露偏差；**dense supervision** 用来对 RL 的稀疏标量。
3. Reverse KL 是 MiniLLM 的目标，不是 OPD 的定义；GKD 的梯度不对采样反传。Qwen3 Table 21 的 1/10 GPU hours 只在 8B、math+code、同一 off-policy 检查点上成立。
4. 没有外部教师 → 02（需要 $y^{\star}$）；持续学习 → 03（70.6/65.4 是单任务 Tool Use）；换 GRPO 优势 → 04（不是塞进 DPO）；多教师合版 → 09 / 10。
