# 从分布的角度看 SFT, RL 与 OPD

> 相关阅读: [02 状态轴: 监督落在哪些前缀上](../02-状态轴/02-状态轴.md) · [01 OPD 基础原理](../../4.9.1-OPD方法与落地/01-OPD基础原理/01-OPD基础原理.md) · [07 OPD 失败模式](../../4.9.1-OPD方法与落地/07-OPD-失败模式/07-OPD-失败模式.md) · [09 MOPD 多教师蒸馏](../../4.9.1-OPD方法与落地/09-MOPD-多教师蒸馏/09-MOPD-多教师蒸馏.md)

本文的材料是 nrehiew 的博客 *SFT, RL, and On-Policy Distillation Through a Distributional Lens*, 以及它引用的几篇论文. 要回答的问题是: SFT, RL 和 OPD 在改模型分布时各自以什么为目标, 这个差别能不能解释遗忘程度和泛化能力的不同.

博客作者自己说这套说法既不精确也不严格, 只是一个好用的思考框架. 下文凡是博客的推测都按推测写, 能在被引论文里找到的结论注明出处. 记号: 当前策略 $\pi_\theta$, 教师 $\pi_T$, 数据分布 $p$, 奖励 $r$.

## 1. 三种方法朝哪个目标拉

### 1.1 SFT: 固定的外部目标

语言模型是序列上的分布. 后训练教一个任务, 就是改这个分布的形状. 博客提出的核心问题是: 优化过程朝向的目标分布是什么, 这个目标是怎么定义的. 先看目标最明确的 SFT.

SFT 的数据集在训练开始前就已经存在, 可能由人写, 也可能由更强的模型生成. 在这份数据上做交叉熵训练, 等价于最小化数据分布到模型分布的 forward KL, 只差一个常数:

$$
D_{\mathrm{KL}}(p\,\|\,\pi_\theta)=\sum_y p(y)\log p(y)-\sum_y p(y)\log \pi_\theta(y)=-H(p)+H(p,\pi_\theta). \tag{1}
$$

式 (1) 里 $H(p)$ 与参数无关, 能优化的只有交叉熵项. 这一项对起点没有任何偏好: 不管 $\pi_\theta$ 原来长什么样, 梯度都把它拉向 $p$. 如果 $p$ 离原模型很远, 模型没有理由选一个离自己近的解, 只会被拉向示范 token. 博客认为这就是 SFT 天然带有灾难性遗忘风险的原因.

博客也强调 SFT 很有用. 从几何上看它是对外部目标的直接拉拽, 很少顾及起点, 这正适合冷启动: 需要大幅改变输出格式时, SFT 是最直接的手段.

压力分布是另一个问题. 交叉熵对数据里每个 token 一视同仁, 区分不了任务关键的 token 和数据里的偶然痕迹. 梯度压力因此遍布整个分布, 既作用在和新任务相关的区域, 也作用在原有能力所在的高概率区域.

### 1.2 RL: 没有外部目标

在线 RL 的样本来自模型自己. 奖励函数给样本打分, 策略梯度提高期望奖励. 这里找不到一个外部分布当目标, 梯度压力只能经由当前策略采到的样本传过去. 高奖励样本主导更新, 概率质量向它们移动, 改动集中在模型本来就会访问的高概率区域. 这种局部性是 RL 能提升任务表现又不大面积波及其他能力的一个解释.

前提是奖励有意义. RLVR 的奖励可验证, 沿奖励方向走通常确实得到更好的模型. RLHF 的奖励模型不完美, 情况就复杂得多.

### 1.3 OPD 与自蒸馏的信号偏差

OPD 介于两者之间. 它和 SFT 一样有教师信号, 学生要去匹配另一个分布; 它又和 RL 一样, 数据由学生自己采. 每一步都在 on-policy 采样, 梯度则通过 reverse KL 把学生拉向教师. 博客把 OPD 称为「伪 RL」: RL 用优势给样本加权, OPD 换成学生和教师的对数概率比. 这个对应并不严格, 第 3 节会回到这一点.

教师换成学生自己, 就是自蒸馏. 博客顺带讨论了 OPSD (On-Policy Self Distillation, arXiv 2601.18734). 教师和学生是同一个模型, 区别只在计算教师对数概率时给它看参考解作前缀, 指望这份特权信息提供学习信号.

问题在于两者是同一个模型, 绝大多数 token 上的输出几乎一样. OPSD 作者逐 token 统计 KL, 发现 "wait", "alright" 这类风格词或转折词的 KL 可以比 "power", "exponent", "logarithm" 这类数学词更高. 在这些不重要的 token 上更新过猛, 模型可能崩掉, 所以 OPSD 引入了逐 token 截断来限制更新幅度.

博客由此把几种信号按偏差排了个序:

| 训练方式 | 信号偏差 | 常见约束 |
|---|---|---|
| RLHF | 奖励模型偏差高 | KL 惩罚 + 信任域截断 |
| OPSD | 高 KL token 未必是任务关键 token | 逐 token 截断 |
| RLVR | 可验证奖励, 偏差低 | 常放松或去掉 KL, 用 GRPO 代替 PPO |

所以博客认为 OPSD 更接近 RLHF, 离 RLVR 远. RLVR 也有自己的短板: 结果奖励很难把功劳分到具体 token, 博客引 Schulman 等 (Thinking Machines, *LoRA Without Regret*) 的说法, 优势函数每条轨迹只提供 $O(1)$ 比特信息. OPSD 在另一个极端, 每个 token 都有自己的「奖励」, 代价是每次更新带进更多噪声和偏差.

## 2. 换教师做 OPD 与学生超过教师

### 2.1 换教师做 OPD: 学生长得差不多

博客的实验用作者此前设计的「最小代码编辑」任务. 给模型一个被注入 bug 的函数, 要求只修 bug, 别的不动. 评测有两项: 修好的函数能否通过, 以及和原始未损坏函数相比有没有改写别的地方. 这个环境能同时看两件事:

1. 泛化: 在一组损坏类型上训练, 在另一组上评测, 看模型学会的是「最小改动」这种行为, 还是只学会了逆转特定的损坏.
2. 遗忘: 最小编辑是小众的代码行为, 训练后可以拿 LiveCodeBench 检查通用代码生成有没有退化.

作者先分别用 SFT 和 RL 训了两个教师, 结果复现了上一篇博客: 两者都学会了最小编辑, RL 泛化更好且没有明显遗忘, SFT 在通用代码生成上退化. 然后从两个教师各做一次 OPD. 表中前三列是域外损坏上的最小编辑指标, 最终一列是 LiveCodeBench v6:

| 模型 | Pass@1 ↑ | 归一化 Levenshtein ↓ | 新增圈复杂度 ↓ | LCB v6 ↑ |
|---|---|---|---|---|
| SFT 教师 | 0.775 | 0.450 | 0.450 | 0.286 |
| RL 教师 | 0.792 | 0.063 | 0.206 | 0.320 |
| OPD 学生 (SFT 教师) | 0.800 | 0.059 | 0.206 | 0.297 |
| OPD 学生 (RL 教师) | 0.787 | 0.055 | 0.228 | 0.314 |

作者原本预期 RL 教师蒸出来的学生更好. 实际有三点出乎意料:

- 两个学生的指标几乎一样, 尽管 RL 教师自己训练时的最终奖励更高.
- 两个学生的编辑指标都略好于 RL 教师, 远好于 SFT 教师. SFT 教师的归一化 Levenshtein 是 0.450, 它的学生降到 0.059.
- SFT 教师在 LCB 上退化到 0.286, 它的学生是 0.297, 忘得比教师少. 如果教师分布是决定性因素, 这个学生应该继承更多遗忘.

博客的结论是: 数据从哪来 (on-policy 采样) 影响很大, 教师是谁的影响比预想的小. 作者认为这是个好消息, 意味着可以先把一个专精模型「过度训练」, 哪怕是粗暴的 SFT, 再用 OPD 把这项能力转给学生, 同时保住其他能力. 这个实验是单任务, 单作者的小规模结果; [02](../02-状态轴/02-状态轴.md) 介绍的 Nie 论文在 GSM8K 上做了受控对照, 方向一致.

### 2.2 学生为什么能超过教师

2.1 节的表里, 从 SFT 教师蒸出的学生在编辑指标和 LCB 上都好于教师. 学生超过教师这一现象并不新, Agarwal 等的 GKD (arXiv 2306.13649) 已经报告过 GSM8K 上蒸馏学生超过教师. 博客没有确定的解释, 给了两个假设.

第一, 监督更有针对性. 学生犯的错不一定是教师会犯的错. 只在教师轨迹上训练, 学生拿到的监督可能落在自己很少到达的区域; OPD 让教师对学生自己的前缀给意见.

第二, KL 匹配和奖励最大化不是一回事. 第 1.3 节把 OPD 看成带 token 级教师监督的 RL, 但 KL 信号的偏差比 RLVR 奖励高得多. 教师分布里包含风格, 不确定性, 备选续写, 推理结构等信息. 匹配它可能改善学生的采样行为, 却不复现教师的贪心输出. 所以即使教师自己采出来的回答不更好, 学生也可能变好. 只盯单个 token 很难理解这件事, 从整体分布形状去想更自然.

博客承认分布层面的直觉在高维里很难建立, 举了 Zhang 等 (arXiv 2604.01193) 的例子: 每个提示只用一条模型生成, 不做正确性过滤, 训练后代码能力有提升; 用高温自蒸馏得到几乎是乱码的数据, 训练后性能仍然提升.

博客自己的猜测是, 模型在新能力附近发生了模式坍缩. 作者对比 OPD 和 RL 训练中的熵曲线, RL 奖励逐步上升, OPD 奖励上升得突然, 同时伴随剧烈的熵坍缩. reverse KL 的寻模性质会降低多样性, 这在 MiniLLM (Gu 等, arXiv 2306.08543) 里已有讨论. 作者明确说这一段是推测.

## 3. RL 为什么忘得少

### 3.1 Forward KL 对 Reverse KL

博客列了三类常见解释. 作者认为每类都有一部分道理, 但前两类都不够. 第一类解释看 KL 方向. 式 (1) 说明 SFT 在最小化 forward KL. forward KL 要求覆盖数据分布的所有模式, 为了学新任务可能牺牲原有模式, 也就是原有能力. Chen 等的 *Retaining by Doing* (arXiv 2510.18874) 把 RL 看作 reverse KL 最小化, 在一个多模态玩具设定里显示 reverse KL 忘得比 forward KL 少.

这篇论文本身的结论比「KL 方向」更具体. 常见直觉是: forward KL 覆盖所有模式, 应该更能保住旧模式; reverse KL 寻模 (mode-seeking), 学得快但会丢掉旧模式. 论文在玩具设定里把目标分布建成两个一维高斯的混合, 「旧」模式代表已有知识, 「新」模式代表目标任务, 权重 0.75 对 0.25. 结论取决于初始策略的形状:

- 初始策略是单峰时, 符合常见直觉, forward KL 忘得更少.
- 初始策略本身是多峰时 (论文认为实际的语言模型属于这种), forward KL 先拉伸新模式, 再从旧模式挪走概率质量去覆盖目标, 造成遗忘; reverse KL 保持旧模式的形状, 只平移新模式去对准目标.

实际模型上的实验用 Llama-3.2-1B, Llama-3.1-8B, Qwen-2.5-1.5B, Qwen-2.5-7B 的 Instruct 版本, 目标任务是 IFEval (指令遵循), MMLU (通用知识), Countdown (算术推理), 另外用 MATH 和两个安全数据集测遗忘. 对比三种方法: 用 Llama-3.3-70B-Instruct 生成数据的 SFT, 用初始模型自己生成并按奖励过滤的 Self-SFT, 以及 GRPO. 结果在各数据集, 模型家族和规模上一致: RL 遗忘更少, 目标任务表现持平或更高.

GRPO 和 SFT 有三处区别: on-policy 数据, 对初始策略的 KL 正则, 优势估计. 论文逐一排除后两项. 去掉 KL 正则的 GRPO, 在增益和遗忘之间的取舍与带 KL 的版本相近, 只有 Llama 在 IFEval 上例外. 不用优势估计的 REINFORCE 目标任务涨得少, 遗忘同样低. 以 Llama-3.1-8B 为例 (单位 %, 增益 / 非目标任务平均下降):

| 方法 | IFEval | MMLU | Countdown |
|---|---|---|---|
| SFT | 25.2 / 27.8 | 11.1 / 38.5 | 25.5 / 36.4 |
| REINFORCE | 17.8 / 7.7 | 8.6 / −0.1 | 7.5 / −0.8 |
| GRPO | 18.4 / 3.4 | 14.6 / −0.2 | 60.4 / −0.5 |

论文的解读是, 优势估计这类算法差别主要影响增益大小, 抗遗忘主要归因于 on-policy 数据. 它也由此指出, 这与 Lai 等「某种优势估计形式减轻遗忘」的假设相左.

最终一个结果偏实用: Self-SFT 只用初始策略的数据, 仍然遗忘严重; 而 Iterative-SFT 在每个 epoch 开始时用当前模型重新生成一次数据, 目标准确率达到或超过 SFT, 遗忘轻微甚至没有. 用 RL 训练过程中产生的轨迹做 SFT, 遗忘也会减少. 近似 on-policy 的数据就够用, 成本比每步采样低得多.

博客对 KL 方向论的异议是: 这套论证很依赖对参考模型的显式 KL 正则, 而 RLVR 里常把 KL 惩罚去掉或调得很弱, 抗遗忘性往往还在. 这和 Retaining by Doing 的消融结论吻合.

### 3.2 SFT 的 token 梯度均匀而激进

第二类解释看梯度形状. SFT 把每个示范 token 都当作要提高概率的对象, 不管它是数学运算符还是 "therefore" 这样的套话. 博客引 Diao 等 (arXiv 2601.02151): SFT 数据里有大量低概率, 低熵的 token, 模型对自己的预测很有把握, 却被迫去拟合一个不同的标签, 这会冲击已有表示.

RL 则带有数据相关的正则 (Lai 等, arXiv 2507.05386). 以组内归一化为例, 奖励方差大的组, 归一化后单个样本的更新反而小; 模型稳定拿高分的样本更新更激进. 模型拿不准的地方, 更新幅度自动变小.

参数层面也有证据. Mukherjee 等 (arXiv 2505.11711) 发现 RL 只更新一个小子网络, 更新稀疏但满秩, SFT 的更新是稠密的. Yuan 等 (arXiv 2510.04454) 发现 SFT 的参数更新冗余更多: 剪掉同样比例的更新参数, RL 的性能掉得快得多, 说明 RL 的每一处更新对最终任务更关键.

博客认为这两条在 SFT 和 RL 的对比上站得住, 但怀疑它们能否推广到其他领域, 也没说明 OPD 处在什么位置. 稀疏性这一条另有反证: Shenfeld 等专门检验了它, 发现他们观察到的稀疏更新来自 bfloat16 训练. bfloat16 尾数位有限, RL 产生的小幅参数更新可能跨不过表示精度的门槛, 等于没更新; 改用 float32 训练, 模型性能相同, 更新不再稀疏. 他们还检查了权重变化的秩, 各算法的更新都是满秩.

### 3.3 on-policy 数据与最近的最优策略

博客最认同的是 Shenfeld 等 *RL's Razor* (arXiv 2509.04259) 的解释. 这篇论文发现, 在新任务表现相近时, 遗忘程度由分布偏移决定, 偏移用微调后策略与基座策略在新任务输入上的 KL 衡量; on-policy RL 在众多能解新任务的解里隐式偏向 KL 最小的那个, SFT 则可能收敛到离基座任意远的分布. 论文在大语言模型和机器人基础模型上都做了验证, 并把这条规律命名为 RL's Razor.

具体做法如下. LLM 实验用 Qwen 2.5 3B-Instruct, 分别训数学推理, 科学问答 (SciKnowEval 化学 L-3 子集), 工具使用 (ToolAlpaca); 机器人实验用 OpenVLA 7B 做抓取放置. 为了能训到收敛并做大量消融, 作者另造了玩具任务 ParityMNIST: 只要求预测数字的奇偶, 任何同奇偶的标签都算对, 所以存在许多同样正确的输出分布. 遗忘的预测量是新任务输入上的 $\mathbb{E}_{x\sim\tau}[D_{\mathrm{KL}}(\pi_0\|\pi)]$, $\pi_0$ 为基座. 把 RL 和 SFT 的遗忘都画在这个 KL 上, 落在同一条曲线上, 二次拟合 $R^2$ 在 ParityMNIST 上为 0.96, 在 LLM 实验上为 0.71. 权重变化幅度, 更新稀疏度, 梯度秩等候选变量都对不上. 两个验证实验把因果方向坐实: 在 ParityMNIST 上解析构造出满准确率且到基座 KL 最小的「oracle」标注, 用它做 SFT, 遗忘比 RL 还少; 用 RL 模型生成的数据做 SFT, 取舍曲线与 RL 一致. 另一组对比里, 1-0 REINFORCE 表现接近 GRPO, 离线的 SimPO 接近 SFT, 说明关键在 on-policy 数据, 负梯度的有无影响不大.

博客的论证用的是其中最简单的情形. 取 0/1 奖励的 REINFORCE, 奖励就成了过滤器: 当前策略采样, 只有 $r=1$ 的样本贡献正向梯度, 等价于在自己的样本上做拒绝采样再拟合.

回到「目标分布」的问题, 这时 RL 有了目标. 定义最优策略为: 在它下面所有回答的奖励都是 1. 记 $\mathcal{R}=\{y: r(y)=1\}$, 最优策略集合是

$$
\mathcal{P}^\ast=\{q:\ \mathrm{supp}(q)\subseteq\mathcal{R}\}. \tag{2}
$$

最优策略不止一个. 博客的论点是, 训练样本来自当前策略, 拟合的那个最优分布在所有最优策略里离当前策略最近. 这一点可以直接验证. 对任意 $q\in\mathcal{P}^\ast$, 令 $\pi(\mathcal{R})=\sum_{y\in\mathcal{R}}\pi(y)$:

$$
D_{\mathrm{KL}}(q\,\|\,\pi)=\sum_{y\in\mathcal{R}}q(y)\log\frac{q(y)}{\pi(y)/\pi(\mathcal{R})}-\log \pi(\mathcal{R})\ \ge\ -\log \pi(\mathcal{R}), \tag{3}
$$

第一项是 $q$ 到 $\pi$ 在 $\mathcal{R}$ 上归一化后的分布的 KL, 非负, 当且仅当

$$
q^\ast(y)=\frac{\pi(y)\,\mathbf{1}[r(y)=1]}{\pi(\mathcal{R})} \tag{4}
$$

时取零. 式 (4) 正是「从 $\pi$ 采样, 只留 $r=1$」得到的分布, Shenfeld 等把这一刻画写成拒绝采样的引理, 并在可行策略族为凸集等正则条件下证明策略梯度收敛到 $\mathcal{P}^\ast$ 中 $D_{\mathrm{KL}}(\pi\|\pi_0)$ 最小的策略. 所以过滤后的 on-policy 样本代表的目标, 是 $\mathcal{P}^\ast$ 中按 $D_{\mathrm{KL}}(q\|\pi)$ 离当前策略最近的那一个, 距离是 $-\log\pi(\mathcal{R})$. 当前策略答对的概率越高, 这个目标离得越近, 拉动越小.

![图 1: on-policy 训练隐式选中离当前策略最近的最优策略](images/fig-nearest-optimal-policy.png)

*图 1: 从当前策略采样, 留下 $r=1$ 的样本, 拟合目标是离当前策略最近的 $\pi^\ast$, 而非 $\mathcal{P}^\ast$ 中任意一个远处的最优解. 博客原图参考 Shenfeld 等的 Fig 5.*

SFT 的目标 $p$ 由数据集给定, 和当前策略无关, 可以落在 $\mathcal{P}^\ast$ 里离 $\pi$ 很远的位置. 这就是同样「学会任务」, 两者对原分布改动幅度不同的原因. 博客说策略梯度每一步都在把当前策略拟合到一个隐式地与它 KL 很小的最优策略上, 所以 RL 学到的是「最近的能解任务的策略」.

OPD 的样本同样来自学生, 区别在于目标换成了教师在学生前缀上的条件分布. 第 2.1 节两个学生长得差不多, 也符合这个解释: 决定改动幅度的主要是采样来源.

## 4. 泛化, 流水线与理想算法

### 4.1 泛化与完整流水线

为什么 RL 和 OPD 泛化更好, 博客的解释沿用前文. SFT 惩罚的是「没给某个特定答案分配概率」, RL 的监督挂在任务成功上, 不绑定具体 token 序列. 更关键的是 Ross 等 (arXiv 1011.0686) 的分析: SFT 只见过教师访问的状态, 推理阶段一旦犯错, 自回归会把学生带到教师从未到过的状态, 误差逐步累积. on-policy 数据聚合能减小这种错配. [02](../02-状态轴/02-状态轴.md) 第 1.1 节把这个问题写成状态分布的形式.

流水线方面, 多数开放模型用 Pretrain-SFT-RL-OPD. 预训练后的 SFT 负责格式遵循和基本指令能力, 没有它 RL 很难高效进行 (Chu 等, arXiv 2501.17161). GLM-5 和 DeepSeek-V4 都用 OPD 把多个专家的能力并进最终模型, 最终 checkpoint 不再经过 RL. 接下来的问题是专家该怎么训.

博客拿 MiMo-V2-Flash 报告 (arXiv 2601.02780) 的 Table 7 作参照, 表里列出各领域最佳教师用了哪种后训练方法. 数学和代码偏向 RL, 这符合 RLVR 在这两个领域的已知效果. 创意写作和部分知识密集的评测更适合自蒸馏或蒸馏式方法, 因为这些领域的奖励噪声大, 用 LLM 评审等于优化一个有偏的质量代理. 同一张表还对比了合并后的学生和各教师: 学生只在教师本身就是自蒸馏的领域, 以及 SFT 领域的 BrowseComp 上不如教师; 在 RL 领域, 学生几乎总超过教师. 博客没有给出原因. 各家怎么合并专家, 见 [09](../../4.9.1-OPD方法与落地/09-MOPD-多教师蒸馏/09-MOPD-多教师蒸馏.md) 和 [10](../../4.9.1-OPD方法与落地/10-OPD-报告落地对照/10-OPD-报告落地对照.md).

### 4.2 理想算法缺什么

博客的出发点是 Brown (2026) 的一段讨论: 每种后训练方法都在「能力」与「到先验的 KL」之间做不同的取舍, 也许存在比 RL 更省算力, 又不劣化这条帕累托前沿的算法.

博客的立场是, 这样的算法必须依赖 on-policy 数据. RL 并不特殊, 显式 KL 惩罚也不是主力; 让能力上升又不超出 KL 预算的, 是 on-policy 训练. 这个观点 Thinking Machines 的 OPD 博客 (Lu 等, 2025) 已经提过, 博客的贡献是把相关研究放在一起. OPD 和 RL 最终落在相近的位置, 这让作者更确信 on-policy 数据是承重的那一部分.

另一个旋钮是老问题: 功劳分配. 三条现有路线各有缺陷:

| 信号 | 密度 | 偏差 | 问题 |
|---|---|---|---|
| 结果奖励 | 每条轨迹约 $O(1)$ 比特 | 低 (可验证时) | 太稀疏, RL 因此昂贵 |
| 过程奖励模型 (Lightman 等, arXiv 2305.20050) | 逐步 | 取决于 PRM | 难以在大规模下高效训练 |
| 教师 logit 蒸馏 | 逐 token | 高 | 需要繁琐的截断方案 |

博客把目标概括为: 蒸馏的信号密度, RL 的无偏性, 加上两者共有的 on-policy 性质. 具体算法是什么样, 作者说不知道.
