# 监督微调：数据契约、损失掩码与训练验证

监督微调（Supervised Fine-Tuning，SFT）在预训练模型上继续做 next-token prediction，但训练序列由任务输入和期望输出构成。它可以教会模型对话格式、指令遵循、工具调用、输出结构、领域任务和拒答行为；它不会自动保证事实正确、安全完整或覆盖所有用户分布。

> **证据边界**：本文截至 2026-09-01。学习率、epoch、样本量、可训练显存和最优 loss mask 都依赖模型、序列长度、数据、优化器、并行/量化实现与硬件。正文给出决策与验证方法，不提供脱离条件的“固定配方”。

## 1. SFT 的目标与边界

序列经模型专属 chat template 转成 token $x_1,\dots,x_T$。令 $m_t\in\{0,1\}$ 表示 token $x_t$ 是否参与监督，则常见 token 平均负对数似然为：

$$
\mathcal{L}_{\text{SFT}}
=
-\frac{1}{\sum_{t=1}^{T}m_t}
\sum_{t=1}^{T}
m_t\log p_\theta(x_t\mid x_{<t}).
$$

这个统一写法覆盖：

- **assistant-only loss**：只监督 assistant 响应及模板定义的相关结束 token；
- **completion-only loss**：prompt 作为条件，只监督 completion；
- **全序列 loss**：prompt、角色标记和回答均参与语言建模；
- **多轮选择性 loss**：只监督部分 assistant 轮次或工具调用段。

SFT 优化的是给定训练前缀时目标 token 的似然。它不会直接优化引用是否支持主张、工具是否真的执行成功、拒答是否校准或开放式答案是否受人偏好；这些需要数据设计、执行器约束和独立评测。

## 2. 先定义样本 schema

### 2.1 对话样本

最小逻辑表示是按顺序排列的 message：

- role：system、user、assistant、tool 等；允许角色取决于模型模板；
- content：文本或模型支持的多模态内容；
- tool_calls：结构化工具名与参数，而不是随意嵌在自然语言中；
- tool_call_id：把调用与结果关联；
- metadata：不一定发给模型，但用于来源、许可、切分和审计。

训练集还应保留：

| 字段 | 用途 |
|---|---|
| sample_id / conversation_id | 去重、追踪和回滚 |
| source / source_version | 证明来源与重新生成 |
| license / consent | 使用边界 |
| language / domain / capability | 分层采样和评测 |
| created_at / valid_at | 时效性 |
| synthetic / teacher_id | 识别合成数据与教师偏差 |
| quality_flags | 正确性、安全、格式、引用等检查 |
| split_group | 防止同源样本跨 train/eval 泄漏 |

### 2.2 Prompt-completion 样本

分类、抽取、翻译、代码补全等任务可使用 prompt/completion。进入训练器前仍要明确：

- prompt 是否包含系统规则和输出 schema；
- completion 是否包含终止 token；
- 空答案、拒答和无解如何表示；
- 多个有效答案是展开为多样本还是使用采样；
- loss 是只覆盖 completion，还是覆盖完整序列。

不要根据字段名猜 loss。最终应检查序列化 token 与 labels。

## 3. Chat template 是模型接口，不是排版

两个模型都接受 messages，不代表它们使用相同的控制 token。Hugging Face 官方文档展示了同一基座的不同 chat 模型可分别使用 [INST] 或 <|user|> 等格式，并提醒模板已包含的特殊 token 不应重复添加。[Transformers Chat Templates](https://huggingface.co/docs/transformers/chat_templating)

以 Llama 3 系列为例，Meta 官方格式使用 begin-of-text、role header 和 end-of-turn 等专用 token；这只是 Llama 的契约，不能复制给 Qwen、Gemma、Mistral 或 DeepSeek。[Meta Llama prompt format](https://github.com/meta-llama/llama-models/blob/main/models/llama3_3/prompt_format.md)

训练与推理必须固定：

1. checkpoint 与 tokenizer revision；
2. chat template 原文和哈希；
3. system/user/assistant/tool 角色映射；
4. BOS、EOS、end-of-turn、end-of-message 与 padding token；
5. 训练时是否加入 generation prompt；
6. 推理时停止 token 和解析器；
7. 工具调用模板与普通对话模板是否不同。

### 3.1 模板金样本

每个模型至少保留几条人工审阅的 golden cases，并保存：

- 原始 message；
- 渲染后的字符串；
- token ID 与 special token 位置；
- labels 和 loss mask；
- 推理前缀；
- 应命中的停止条件；
- 工具调用和工具结果的解析结果。

升级 Transformers/TRL、tokenizer 或模型 revision 后逐字节回归。loss 能下降不能证明模板正确。

## 4. Assistant-only 还是全序列 loss

| 选择 | 适合的目标 | 优点 | 风险 |
|---|---|---|---|
| Assistant-only | 对话、指令回答、工具调用 | 不要求模型模仿用户文本；监督集中在行为输出 | 有效目标 token 少；模板必须能给出可靠 mask |
| Completion-only | 明确 prompt→completion 任务 | 边界清楚、易于控制 | 多轮或复杂模板需额外处理 |
| 全序列 | 领域语言建模、统一序列建模、特定模板训练 | 所有 token 提供梯度 | 用户/检索文本也成为学习目标，长 prompt 可能压低回答权重 |
| 选择性轮次 | 多轮课程或只训练末轮 | 可控制每轮权重 | mask 构造和评测更复杂 |

TRL 官方 SFTTrainer 同时提供 completion-only 与 assistant-only 选择；assistant-only 需要 conversational template 能返回 assistant token mask，当前文档要求模板支持 generation 标记。[TRL SFTTrainer](https://huggingface.co/docs/trl/sft_trainer)

必须直接验证：

- system/user/tool-result token 的 label 是否为 ignore index；
- assistant role header、正文和结束 token 哪些被监督；
- 多轮中是所有 assistant 轮，还是只有末轮；
- 截断是否切掉回答却留下大量 prompt；
- 空 target 是否被悄悄计入批次；
- loss 分母是目标 token、样本还是微批平均。

不同归一化会改变长短样本和梯度累积的权重。报告训练损失时要写清 reduction 口径。

## 5. Packing 与跨样本 attention

Packing 把多个短样本装入固定长度块，可减少 padding，但“放在同一张量”不自动意味着样本边界安全。

### 5.1 两种不同实现

- **边界隔离 packing**：使用 block-diagonal/varlen attention 元数据，使每个样本只看自己的历史；
- **朴素拼接**：样本之间只插 EOS，再使用一张普通 causal mask。此时后一个样本仍可能注意前一个样本；EOS 是一个 token，不是 attention 防火墙。

两种实现都可能产生可训练 loss，但学习分布不同。还要确认 position IDs 是每样本重置还是连续，以及跨边界 special token 是否参与监督。

TRL 提供 packing=true 及多种 packing strategy，具体 padding-free、截断和 FlashAttention 支持会随版本变化。[TRL Packing 文档](https://huggingface.co/docs/trl/sft_trainer) 不要只看配置名；应对一个已知小批次打印 sequence IDs、position IDs、attention metadata 和 labels，并测试后一样本 logits 是否受前一样本内容影响。

### 5.2 Packing 验证清单

- 同一 conversation 的轮次不能被错误打散；
- 不同租户或敏感样本不应形成意外跨样本条件；
- 截断不能只保留 user 而删除监督回答；
- 训练与 eval 的 packing 策略要明确；
- 实际非 padding token 利用率、目标 token 利用率要分别记录；
- 边界隔离实现需与所用 attention kernel 兼容。

## 6. 数据质量：正确、必要、可追溯

### 6.1 先去污染，再谈分数

去重至少覆盖精确重复、规范化文本、近重复、同一来源的改写和多轮切片。train/eval 污染检查要在切分前按 source/conversation 分组，并对公开基准题面、答案、翻译和合成改写做匹配。

Tülu 3 公开了多阶段后训练配方，其 Open Instruct 仓库同时发布了面向评测套件的 decontamination 工具；这说明“公开混合数据”仍需要显式污染检查，而不是默认干净。[Tülu 3](https://arxiv.org/abs/2411.15124) · [Open Instruct 去污染说明](https://github.com/allenai/open-instruct/blob/main/decontamination/README.md)

### 6.2 质量不是单一教师分数

逐样本检查：

- 输入是否可解、约束是否完整；
- 回答是否事实正确、引用可核验；
- 是否真正遵循格式、长度和语言；
- 代码/数学是否能执行或验证；
- 拒答是否与风险和信息不足匹配；
- 工具名、参数、调用顺序和结果是否一致；
- 回答是否泄露系统规则、隐私或内部标注；
- 是否含教师模型口癖、免责声明和错误自信。

训练故障恢复时，应把“检索返回错误/空结果”作为条件，并把澄清、重试、换工具或据实拒答作为目标；不能把错误结果本身复制成期望答案。

### 6.3 小而精不是普遍规模定律

LIMA 在 LLaMA-65B、1000 个精心选择样本和其人工评测协议下展示了少量数据可显著改变回答行为；它没有证明 1000 条足以覆盖代码、多语言、工具、安全和领域事实。[LIMA](https://arxiv.org/abs/2305.11206)

Llama 2 报告使用 27,540 条高质量 SFT 标注，之后仍进行了偏好数据与 RLHF；这个数字描述其具体流程，不是所有模型的推荐数据量。[Llama 2 论文](https://arxiv.org/abs/2307.09288)

合理规模取决于基座已有能力、目标覆盖、样本多样性和允许的回退。应画能力覆盖矩阵，并用增量数据消融判断边际收益。

## 7. 多轮与工具调用数据

### 7.1 多轮对话

多轮样本应呈现真实状态变化，而不是把多个无关单轮串接。检查：

- 代词、实体和约束在各轮一致；
- 用户纠正后，旧事实不再被当作当前事实；
- assistant 不重复询问已确认信息；
- 被截断的历史不会让目标回答变成无条件猜测；
- 每轮目标与最终任务成功都可评测。

若只监督末轮，前面 assistant 内容是条件；若监督所有 assistant 轮，早期低质量回答也会产生梯度。两种目标要显式区分。

### 7.2 工具调用

一个可执行轨迹通常包含：

1. 用户目标；
2. assistant 的结构化工具调用；
3. 与调用 ID 匹配的 tool result；
4. assistant 基于结果的最终回答或下一次调用。

工具 result 通常作为条件而不是模型应模仿的输出；工具 call 和最终 assistant 内容是否都监督，取决于目标。schema、枚举、参数类型和错误返回必须与部署执行器一致。外部工具结果属于不可信数据，样本还应覆盖注入文本、超时、权限不足、空结果和部分成功。

工具模板追加新消息时应保持既有前缀稳定，否则训练时与多轮 prefix cache/推理解析可能不一致。Hugging Face 当前模板文档明确把 prefix-preserving 作为工具训练模板的重要要求。[TRL Chat Templates](https://huggingface.co/docs/trl/chat_templates)

## 8. 全参数微调与 PEFT

| 路线 | 可更新参数 | 适用情形 | 主要风险 |
|---|---|---|---|
| 全参数 SFT | 全模型 | 数据和算力充分、需要广泛行为改变 | 优化状态与通信大，通用能力回退 |
| LoRA/Adapter | 注入的低秩或适配参数 | 多租户、快速迭代、有限资源 | rank/target modules 限制表达，部署需管理 adapter |
| 冻结部分层 | 指定上层、embedding 或 head | 受控适配和消融 | 选择依模型，未必优于 LoRA |
| 量化基座 + PEFT | 量化权重、可训练 adapter | 单机或显存受限实验 | kernel、量化误差、优化稳定性和可复现性 |

“一张消费级显卡可以训练某个超大模型”缺少序列长度、batch、量化、offload、优化器、checkpointing 和速度口径，不能作为容量结论。训练显存至少包含权重、梯度、优化器状态、激活、临时缓冲和通信开销；应根据具体框架做内存估算与最小 smoke test。

PEFT 原理与部署见 [PEFT](../4.3-PEFT/4.3-PEFT.md)。

## 9. 训练配方从可验证基线开始

### 9.1 先做数据与模板 smoke test

在大规模训练前：

1. 人工检查随机样本和高风险切片；
2. 渲染模板并反解 token；
3. 可视化 labels/mask；
4. 用极小数据过拟合，确认 loss 和停止行为可学；
5. 从 checkpoint 生成固定 golden prompts；
6. 验证保存、恢复、adapter 合并和推理服务加载。

### 9.2 超参数没有跨模型固定答案

学习率、warmup、epoch、batch、weight decay、dropout 和 max length 应由小规模 sweep 与保留集选择。记录的核心训练量包括：

- 看过的总 token 和受监督 target token；
- 每个能力/来源的采样 token；
- effective batch 的序列数与 target token 数；
- 截断率、空 target 率和 packing 利用率；
- 模型、优化器、精度、并行和 kernel 版本。

同样的 epoch 在不同去重、长度和 packing 设置下代表不同 token 曝光量，因此不能照搬“训练 3 epoch”等经验值。

### 9.3 训练诊断

同时监控：

- train/eval 的总 loss 与按能力、语言、来源、长度切片的 loss；
- target token 数、梯度范数、学习率和溢出/跳步；
- tokens/s、显存、通信等待和数据加载；
- 回答长度、重复、EOS/turn-end 率、格式合法率；
- 固定生成集上的任务质量、文本能力和安全回归。

loss 下降但生成变差，常见原因包括模板错位、错误 mask、回答被截断、训练/推理停止 token 不一致、数据重复、学习率过高或教师风格过拟合。先定位数据和接口，再增加 epoch。

## 10. 评测、发布与回滚

### 10.1 评测矩阵

| 维度 | 必测内容 |
|---|---|
| 目标能力 | 任务正确率、格式、工具参数、领域标准 |
| 通用回归 | 问答、写作、代码、数学、多语言 |
| 对话 | 多轮一致性、纠错、澄清、停止 |
| 事实性 | 闭卷事实、给定证据忠实度、引用支持 |
| 安全 | 有害请求、过度拒答、隐私、提示注入 |
| 鲁棒性 | 长短输入、拼写、空输入、冲突指令 |
| 校准 | 无答案时拒答、置信与错误类型 |
| 运行 | 延迟、吞吐、显存、结构化输出解析率 |

LLM-as-judge 可作为一个信号，但需固定 judge 版本、提示、顺序随机化，并用人工/可执行评测校准长度偏好和自家族偏差。

### 10.2 发布单元

一次 SFT 发布应绑定：

- base checkpoint revision；
- tokenizer 与 chat template；
- 数据清单、哈希、许可和过滤版本；
- loss mask、packing 与截断策略；
- 训练代码、依赖、随机种子和超参数；
- checkpoint/adapter、评测结果和已知限制；
- 推理停止 token、采样和工具解析器；
- 回滚目标与触发阈值。

先灰度到可观测流量，比较目标能力与保留能力。回滚不能只恢复权重，还要恢复匹配的 tokenizer、template、parser 和 adapter 路由。

## 11. 上线前检查清单

- [ ] 样本 schema、来源、许可、时间与 split_group 可追溯。
- [ ] checkpoint、tokenizer 和 chat template revision 完全匹配。
- [ ] Golden cases 已核对渲染文本、token、labels、mask 和停止条件。
- [ ] Assistant-only/full-sequence 的选择与业务目标一致。
- [ ] Packing 的跨样本 attention、position IDs 和截断行为已实测。
- [ ] 去重、train/eval 污染和合成教师偏差已检查。
- [ ] 多轮纠错、工具失败、无答案与高风险请求有专门数据。
- [ ] 全参/PEFT 的显存与吞吐来自当前配置实测，不引用无条件硬件口号。
- [ ] 训练同时记录总 token、target token、切片 loss 与生成回归。
- [ ] 发布包包含模型、tokenizer、template、parser、数据与评测版本。
- [ ] 有明确灰度、监控和整体回滚方案。
