# 安全与对抗评测

安全评测的对象不是一句模型回答，而是一条可能跨越用户输入、检索、模型、工具、身份和外部系统的攻击路径。模型拒答可以降低部分风险，却不能替代授权、隔离、输出校验、资源限制和恢复机制。

## 先区分安全、可靠性与内容政策

| 维度 | 典型问题 | 主要控制 |
|---|---|---|
| 可靠性 | 正常输入下是否出错、超时或漂移？ | 测试、冗余、降级、回滚、SLO |
| 安全性 | 攻击者能否破坏机密性、完整性或可用性？ | 身份、授权、隔离、验证、监控、响应 |
| 安全/社会风险 | 系统是否放大危险能力、偏见、操纵或现实伤害？ | 用途限制、能力评测、政策、人工治理、访问控制 |
| 内容政策 | 哪些内容允许、限制或拒绝？ | 分类、规则、模型行为和申诉流程 |

它们会重叠，但不能混为一个“安全分”。例如，拒绝危险请求属于行为控制；工具是否能删除生产数据属于授权与系统安全。

## 威胁模型

### 资产

- 用户和组织的敏感数据、提示、密钥和凭据；
- 模型权重、系统提示、训练数据和专有检索语料；
- 工具可访问的邮件、代码、数据库、支付、发布和基础设施；
- 决策完整性、审计记录、服务容量、预算与声誉；
- 受系统输出或动作影响的人与环境。

### 信任边界

用户输入、上传文件、网页、邮件、RAG 文档、工具返回、其他 Agent 消息和模型输出都可能是不可信数据。即使来源通过身份验证，其内容也可能被攻陷、过时或超出当前授权。

### 攻击者能力

记录攻击者能否：反复查询、观察分数或错误、上传文档、控制网页/邮件、影响训练或反馈数据、调用工具、访问模型权重、窃取凭据或控制供应链组件。攻击预算、知识和访问级别决定测试代表什么。

### 影响

把攻击成功转成具体结果：读取跨租户数据、执行未授权命令、修改记录、发送邮件、支付、发布内容、消耗预算、破坏索引或诱导高风险决策。没有影响定义的“越狱成功率”难以支持工程优先级。

## 攻击分类

NIST AI 100-2e2025 将生成式 AI 风险组织为 evasion、poisoning、privacy 和 misuse 等攻击家族，并强调缓解措施存在局限。[NIST AI 100-2e2025](https://doi.org/10.6028/NIST.AI.100-2e2025) 提供共同术语；具体系统仍要按资产和攻击路径展开。

| 攻击面 | 示例 | 需要验证的系统属性 |
|---|---|---|
| 输入规避 | 越狱、编码/多语言变体、对抗图像或音频 | 行为边界、跨模态一致性、升级与记录 |
| 提示注入 | 用户直接注入、网页/文档/邮件间接注入 | 指令与数据分离、工具授权、输出处理 |
| 投毒 | 预训练、微调、反馈、RAG、记忆和工具描述投毒 | 来源、写权限、异常检测、版本与恢复 |
| 隐私 | 训练数据抽取、成员/属性推断、日志与向量泄漏 | 最小数据、访问控制、保留、隐私评测 |
| 滥用 | 网络攻击、欺诈、危险知识或规模化操纵 | 能力门槛、访问分级、监测、速率与人员流程 |
| 供应链 | 恶意权重、远程代码、依赖、连接器、模型替换 | provenance、签名/hash、隔离、固定版本 |
| 资源攻击 | 超长输入、循环工具、并发放大、成本收割 | 配额、步数、超时、预算、队列和熔断 |

## 提示注入与越狱

### 概念边界

- **直接提示注入**：攻击者在当前用户输入中加入改变系统行为的指令。
- **间接提示注入**：恶意指令藏在模型读取的网页、文档、邮件、图像或工具结果中。
- **越狱**：通过变形、角色扮演、多轮或对抗提示绕过模型行为限制；按 OWASP 2026 的用法，它属于提示注入的一类，不是与提示注入完全独立的攻击家族。
- **系统提示泄漏**：模型披露隐藏指令；真正秘密不应只靠系统提示保密。

提示注入的根本难点是模型在同一上下文中处理“指令”和“数据”，而自然语言分隔符不是强制访问控制。[Indirect Prompt Injection](https://arxiv.org/abs/2302.12173) 展示了外部内容改变应用行为的攻击面；它不意味着所有实现都以同样方式受影响。

### 不能依赖的单点防御

- “忽略之前指令”或更强硬的系统提示；
- 关键词黑名单或单一分类器；
- RAG、微调或对齐模型本身；
- 隐藏工具名称、schema 或系统提示；
- 要求模型自我检查后直接执行高影响动作。

这些措施可作为纵深的一层，但不构成权限边界。OWASP 的当前 LLM 风险指南也把提示注入、敏感信息、投毒、输出处理、过度代理能力和资源消耗分开处理。[OWASP GenAI LLM Top 10 2026](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/)

### 分层控制

1. 外部内容默认作为不可信数据，不允许自行提升指令优先级。
2. 工具由服务端基于用户身份、对象、动作和上下文授权。
3. 模型只能提出结构化意图；参数做 schema、范围和业务规则验证。
4. 读写、低风险与高风险工具分离；默认最小功能、权限和自治。
5. 删除、支付、发送、发布、权限变更等动作需要预览、明确确认或双人审批。
6. 浏览、代码和文件处理运行在隔离环境，限制网络、文件、凭据与资源。
7. 模型输出进入 HTML、SQL、shell、模板或日志前按目标语境编码/校验。
8. 保存来源、调用、授权、结果与确认轨迹，并提供停止、撤销和转人工。

## Agent 与工具安全

### 三种“过度”

Agent 高影响失败常来自：

- **功能过度**：拥有任务不需要的工具；
- **权限过度**：工具身份能访问不需要的对象或动作；
- **自治过度**：没有确认、预算、步数、停止或人工接管。

模型能力提升不能解决这三类设计错误。授权主体应是最终用户或受控服务身份，不能因为模型“认为需要”就扩权。

### 工具契约

每个工具至少定义：

- 允许主体、对象、动作和环境；
- 参数 schema、业务前置条件与最大范围；
- 读/写性质、幂等性、可逆性和影响等级；
- 超时、重试、重复调用、部分成功与补偿；
- 输出可信等级、敏感字段和保留方式；
- 是否需确认、谁可批准、确认绑定哪组参数；
- 审计事件和告警字段。

确认必须绑定即将执行的具体动作和参数，不能用一次笼统同意授权后续任意步骤。

### 代理测试矩阵

- 无需工具时是否不调用；相似工具是否正确消歧；
- 低权限用户能否诱导高权限工具或跨租户对象；
- 工具返回恶意指令、错误、空结果或部分成功时如何处理；
- 多步计划是否出现循环、目标漂移、递归委派或预算放大；
- 重试是否造成重复支付、重复发送或重复修改；
- 确认后参数是否被替换；取消/停止是否真正阻止后续动作；
- 记忆或上下文投毒是否跨会话持续；
- 多 Agent 消息能否伪造身份、权限或任务来源；
- 日志是否能重建每一步的模型、输入、工具、授权与结果。

MITRE [ATLAS](https://atlas.mitre.org/) 提供包括 prompt injection、RAG/上下文投毒、Agent 工具调用和数据外泄在内的攻击技术矩阵，可用于覆盖检查；它不是风险排序或自动控制清单。

## 数据与模型投毒

### 入口

- 预训练、继续预训练、SFT、偏好、奖励和合成数据；
- 用户反馈、在线学习、长期记忆和成功轨迹回放；
- RAG 文档、元数据、embedding、重排训练集；
- 工具描述、插件清单、MCP/协议元数据和外部 API 返回；
- benchmark 与安全集本身。

### 控制与测试

- 限制写入身份，保留来源、许可、时间、审核和版本；
- 分离数据准入、索引/训练构建和发布权限；
- 做近重复、异常集中、触发词、来源多样性与标签一致性检查；
- 用可信金丝雀查询和独立红队集监控目标行为；
- 能从版本化快照重建、回滚和撤回；
- 假设少量恶意内容可能通过过滤，验证最终影响而非只测过滤准确率。

数字签名或 hash 能证明所取 artifact 与某个发布身份/内容一致，不能证明其无后门、真实或适合当前用途。

## 供应链

需要盘点的不只是模型权重：tokenizer、聊天模板、数据、评测代码、推理框架、自定义算子、容器、驱动、SDK、远程代码、工具服务器、浏览器、解析器和模型路由都可能改变安全边界。

最低控制包括：

- 从正式来源获取并固定版本、hash、签名或发布 provenance；
- 禁止未经审查的可执行序列化和 `trust_remote_code`；
- 首次加载、转换、量化和自定义代码在隔离环境进行；
- 生成组件清单，监控漏洞、撤回、许可证和供应商变更；
- API 别名与模型路由建立行为漂移检测；
- 连接器和工具服务器采用独立身份、最小网络与短期凭据；
- 预先验证替代模型和故障降级，不在事故中临时换未知版本。

可把 NIST [SP 800-218A：Secure Software Development Practices for Generative AI and Dual-Use Foundation Models](https://csrc.nist.gov/pubs/sp/800/218/a/final) 作为生成式 AI 的 SSDF 1.1 Community Profile；应与 SP 800-218 及组织现有安全开发生命周期结合，而不是当作独立认证清单。

## 红队与对抗评测

### 测试层级

1. **组件**：模型行为、分类器、检索、解析器和单个工具。
2. **集成**：提示加 RAG、工具、权限和输出处理。
3. **端到端**：真实身份、网络、数据、人工确认和恢复流程。
4. **运行**：灰度流量、持续监控、蜜罐/金丝雀和事件演练。

### 记录攻击条件

- 黑盒、灰盒或白盒；
- 查询次数、并发、时间、成本与人工技能；
- 攻击者是否控制用户、文档、网页、工具或供应链；
- 模型/系统版本、温度、工具和防御；
- 成功标准、影响等级和是否需要用户交互；
- 首次成功时间、成功率、稳定性和可检测性。

“发现一个攻击”可证明存在脆弱性；“在预算内未发现”只能提供有限反证。自动红队扩大覆盖，但生成器和评分器也会漏报、误报或偏向已知攻击模板。

### 修复验证

修复后同时测试：原攻击、语义变体、相邻攻击面、正常任务回归、性能与拒答副作用。只封一个字符串不算修复；控制必须在攻击者可变部分之外生效。

## 安全门禁与事件

上线前至少有：

- 覆盖当前威胁模型的风险集与端到端攻击链；
- 权限、确认、输出校验、资源限制和隔离的确定性测试；
- 已知剩余风险、负责人、例外期限和补偿控制；
- 安全日志、异常检测、紧急停用、密钥轮换和回滚演练；
- 外部报告、漏洞接收、分级响应和受影响用户通知流程。

事件发生后保全版本、输入、上下文、工具调用、身份、授权、输出和外部副作用。先控制影响与恢复，再做根因、检测缺口、测试补充和跨系统复盘；不能只把事故样本加入拒答集。

## 提交前检查

- [ ] 资产、信任边界、攻击者能力、预算和影响已定义。
- [ ] 模型行为与授权、隔离、输出处理没有混为一层。
- [ ] 直接/间接注入、投毒、隐私、滥用、供应链和资源攻击均有覆盖。
- [ ] 高影响工具最小权限、参数校验、确认、可逆与审计齐全。
- [ ] 红队结果记录版本、攻击条件、原始轨迹和覆盖限制。
- [ ] 修复验证包含变体、相邻攻击面和正常任务回归。
- [ ] 有紧急停止、密钥轮换、回滚、事件响应与外部报告通道。
- [ ] 结论没有把“未发现”写成“不可攻击”。

与数据来源、派生数据、保留和删除相关的控制，继续见[隐私、数据与内容治理](./10.3-隐私数据与内容治理.md)。
