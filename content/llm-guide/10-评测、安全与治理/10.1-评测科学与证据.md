# 评测科学与证据

评测不是“找一个数据集跑分”，而是用有限观察支持一个有范围的决策声明。最重要的问题不是分数是多少，而是：测了谁、代表谁、改变了哪些变量、误差有多大，以及这个结果足不足以承担当前决策。

## 从声明开始，而不是从 benchmark 开始

一个可检验声明至少包含：

- **对象**：精确 checkpoint、API snapshot、产品模式或完整系统；
- **任务**：输入、允许动作、输出和完成判据；
- **人群与分布**：语言、领域、长度、模态、用户、地区和风险等级；
- **设置**：prompt、工具、检索、推理预算、采样和超时；
- **指标**：成功、严重失败、延迟、成本与安全；
- **时间**：评测日期、知识或数据截止和结论有效期；
- **阈值**：通过、限制、转人工或停止的预先规则。

例如，“模型 A 更好”不可检验；“在客服验收集 v4、统一检索与中等推理预算下，API snapshot X 的任务成功率不低于 92%，且风险集覆盖样本中未发现跨租户泄漏”才接近可审查声明。后半句仍不能证明部署中绝无泄漏，只说明当前覆盖内的观察。

## 固定评测对象

### 记录最小身份

- 家族、模型 ID、checkpoint/revision、量化、tokenizer 和哈希；
- Base/Instruct/Chat/Thinking/领域微调身份；
- API 区域、接口版本、dated snapshot 或别名、评测日期；
- 系统提示、对话模板、路由、RAG、工具、安全策略和后处理版本；
- 运行框架、硬件、精度、批量、缓存和并发。

如果只能使用会漂移的 API 别名，结果卡应明确“这是对某日期服务行为的观察”，并用金丝雀集检测后续漂移。

### 区分三种比较

| 比较 | 固定什么 | 回答什么 |
|---|---|---|
| 模型隔离比较 | 工具、prompt、预算、数据和评分器 | 在统一条件下模型差异多大？ |
| 最佳系统比较 | 每个候选使用允许的最佳系统配置 | 哪个完整方案最适合任务？ |
| 版本回归比较 | 生产基线与候选只改变一个受控变量 | 这次变更是否可上线？ |

三种结果都重要，但不能放在同一列冒充同口径排名。

## 数据设计

### 五类样本

1. **代表集**：按真实流量的语言、任务、长度、模态与用户分层抽样。
2. **困难集**：低频格式、长尾语言、长上下文、多工具、冲突证据和边界输入。
3. **风险集**：应拒/不应拒、敏感数据、越权、提示注入和高影响动作。
4. **时效集**：价格、政策、软件版本、新闻和内部知识等会变化的任务。
5. **回归集**：历史事故、已修缺陷和关键能力的最小稳定集合。

代表集估计常见表现，困难集和风险集发现尾部失败；它们不应按真实流量权重简单混成一个平均分。严重度、频率和检测目的要分开报告。

### 划分与版本

- 训练、开发、prompt 调整、阈值校准和最终盲测分离；
- 冻结最终集后，不用其错误反复调 prompt；需要迭代时升版本；
- 保存样本 ID、来源、创建时间、变换、去重和敏感等级；
- 记录哪些样本可能公开、进入训练语料或被供应商看到；
- 多语言翻译版记录译者、模型和人工复核，不能默认等价。

## 指标与估计量

### 封闭式任务

准确率适合单标签且错误代价近似相同的任务：

$$
\operatorname{Accuracy}=\frac{\text{正确样本数}}{\text{纳入评测的全部样本数}}.
$$

分母 $N>0$ 应在看结果前冻结。解析失败、超时和格式不合规不能事后静默剔除；除非协议预先把某类样本判定为数据无效，否则应按预登记规则计为失败、拒答或单独错误类型。确需排除时，同时报告原始总数、排除数、原因和剩余 $N$。类别不平衡或错误代价不同，应报告每类 precision、recall、F1、混淆矩阵和严重度。宏平均先对类别求指标再平均，微平均先合并计数；二者回答不同问题，不能只保留较好看的一个。

### 生成与代码任务

开放生成要先决定评分单位：事实声明、引用、结构字段、可执行测试、人工偏好还是任务最终成功。ROUGE、BLEU、embedding 相似度只能度量特定表面或语义接近性，不等于事实正确、可用或安全。

代码生成常见的 pass@$k$ 估计，针对一个问题已从固定采样策略生成 $n$ 个候选、其中 $c$ 个通过测试，再从这 $n$ 个候选中均匀无放回选择 $k$ 个时写为：

$$
\widehat{\operatorname{pass@}k}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}}.
$$

其定义域为 $n\ge k\ge1$、$0\le c\le n$；当 $n-c<k$ 时约定 $\binom{n-c}{k}=0$。若 benchmark 有 $m\ge1$ 个问题，第 $j$ 题的计数为 $(n_j,c_j)$，则报告外层问题平均：

$$
\widehat{\operatorname{Pass@}k}
=\frac{1}{m}\sum_{j=1}^{m}
\left(1-\frac{\binom{n_j-c_j}{k}}{\binom{n_j}{k}}\right).
$$

它依赖采样分布、测试完备性、$n_j$、$k$、温度和预算。不同候选若采样或测试不同，不能只比较 pass@$k$。[Evaluating Large Language Models Trained on Code](https://arxiv.org/abs/2107.03374)

### 校准与选择性回答

概率或置信表达要同时看正确性和校准。Brier score 可用于二元事件：

$$
\operatorname{Brier}=\frac{1}{N}\sum_{i=1}^{N}(p_i-y_i)^2.
$$

$N>0$、$p_i\in[0,1]$、$y_i\in\{0,1\}$，且所有 $p_i$ 必须对应同一类定义明确的二元事件。在这一归一化下，Brier score 位于 $[0,1]$，越低越好；多类别 Brier 使用概率向量，存在不同归一化约定，报告时要写明。让模型自由生成“80% 可信”未必是可校准概率。Expected Calibration Error 依赖分箱选择，不应作为唯一结论。

对允许拒答的系统，令 $a_i\in\{0,1\}$ 表示第 $i$ 个样本是否回答，$\ell_i$ 表示回答损失，则：

$$
\operatorname{Coverage}=\frac{1}{N}\sum_{i=1}^{N}a_i,
\qquad
\operatorname{SelectiveRisk}=
\frac{\sum_{i=1}^{N}a_i\ell_i}{\sum_{i=1}^{N}a_i},
$$

其中选择性风险只在 $\sum_i a_i>0$ 时定义。risk–coverage 曲线检查覆盖率下降时，已回答样本的错误风险是否下降。拒答不是免费正确答案；错误拒答、用户转人工和延迟要另计任务损失，不能把未回答样本当正确。

### 端到端任务

Agent、RAG 和工具系统优先测：

- 最终任务是否完成；
- 是否使用允许的证据和工具；
- 是否越权、重复执行或遗漏确认；
- 工具失败后是否安全恢复；
- 端到端延迟、调用数、token、外部费用和人工介入；
- 结果是否可追溯到工具返回或证据。

只给最终文本打分会丢失高影响的中间动作。

## 不确定性与统计设计

### 配对优先

同一批样本上比较两个候选，应保存逐样本结果并采用配对分析。二元正确性可用 McNemar 检验关注“A 对 B 错”和“A 错 B 对”的不对称；连续或复杂指标可用按样本配对 bootstrap 估计差异区间。

置信区间描述在抽样与模型假设下的估计不确定性，不覆盖数据污染、评分器偏差、未来分布漂移等系统误差。

### 独立抽样单位与聚类

先定义真正独立的抽样单位：用户、会话、任务、文档或组织。同一用户的多轮对话、同一题的多个候选、同一输入的多个 seed 通常相关，不能把每一行都当独立样本来缩窄区间。存在相关组时，比较仍要保持候选配对，并按真实独立单位做 cluster bootstrap、分层 bootstrap 或层级模型；报告组数、组内样本数和重采样单位。

重复运行估计的是给定任务和环境下的条件方差，不会自动增加独立任务样本量。若同时筛选很多模型、指标、切片或阈值，应预声明主比较，并对探索性多重比较做校正或清楚标注，避免从大量结果中只挑显著项。

### 多次运行

非确定生成、工具网络和并发环境会引入方差。记录 seed 并不能保证所有 API 可复现；应按风险选择重复次数，报告均值、分位数、方差和最坏失败，而不是挑一次最好结果。

### 阈值在看结果前冻结

验收阈值应来自业务损失、法规/政策要求和基线能力，并在正式盲测前登记。看到结果后移动阈值属于新的决策版本，必须保留变更理由并用新盲测验证。

## LLM-as-a-Judge

LLM 裁判适合扩展开放式评测，但它是一个需要校准的测量工具，不是客观真值。

### 常见偏差

- **位置偏差**：偏好先出现或后出现的候选；
- **冗长偏差**：把更长、更自信的答案当成更好；
- **自家族偏差**：偏好与裁判相同或相似的模型风格；
- **风格替代事实**：流畅、分段和礼貌掩盖事实错误；
- **知识与权限不足**：裁判无可靠来源却被要求判时效或私有事实；
- **提示敏感**：rubric、示例、输出顺序和温度改变结论。
- **评分操纵**：候选答案把面向裁判的指令、伪造 rubric 或外部链接藏进正文，诱导裁判改变评分。

[Judging LLM-as-a-Judge](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html) 的实验展示了位置、冗长和自增强等限制；这些结果提示要校准，而不是证明所有裁判在所有任务中同样偏置。

### 最低控制

1. 在有代表性的人评金标准上校准裁判，报告一致性和分歧类型。
2. 成对比较时交换答案顺序；模型身份匿名化。
3. rubric 拆成可观察项，要求引用具体证据，不用一个模糊总分。
4. 事实、代码、schema 和引用尽量先用规则、执行或来源校验。
5. 把候选答案作为不可信数据做结构化封装；自然语言分隔符不是硬边界。裁判默认不接工具、不访问候选给出的链接，并加入 judge-injection 对抗集。
6. 高风险样本保留人工复核与仲裁，不把裁判输出直接当上线门禁。
7. 保存裁判 model ID/snapshot、prompt、采样和原始理由；裁判变更后重新校准。

## 污染、饱和与动态评测

### 污染不只有答案泄漏

测试题、答案、解析、代码仓库、翻译、排行榜讨论和合成变体都可能进入训练或后训练。模型训练集不透明时，字符串去重未命中不能证明无污染。

缓解包括：私有滚动集、首次公开日期台账、近重复检测、实体/数字/表述的受控变体、保留真正新题，以及对原题与变体的性能差异分析。[NLP Evaluation in Trouble](https://arxiv.org/abs/2310.18018) 提供污染层次的讨论；它是方法参考，不是某个模型的污染判决。

### 饱和与题目质量

接近满分时，小差异可能来自错题、答案提取和随机性。定期审查：

- 题目是否有唯一可判答案；
- 答案键、单位、版本和翻译是否正确；
- 模型是否通过真正能力而非格式线索作答；
- 分数差是否大于评分和抽样噪声；
- 新任务是否覆盖真实失败，而非只追求更难。

### 动态评测

对时效知识、软件、法规和真实攻击，使用版本化滚动窗口。动态集也要防止“永远换题导致不可比较”：保留稳定锚点集、记录题目退役原因，并同时报告锚点趋势与新鲜窗口表现。

## 结果卡

| 字段 | 必须记录 |
|---|---|
| 声明 | 决策问题、适用范围、阈值和结论有效期 |
| 对象 | 模型/API/产品/系统精确身份与所有组件版本 |
| 数据 | 来源、版本、样本量、分层、污染与敏感性 |
| 设置 | prompt、采样、推理预算、工具、网络、超时和硬件 |
| 评分 | 规则、测试、裁判、人工指南、无效输出处理 |
| 统计 | 原始计数、分层结果、区间、重复与配对方法 |
| 失败 | 严重错误、代表性案例、未知项和未覆盖区域 |
| 运行 | TTFT、TPOT、吞吐、资源、调用、成本和失败率 |
| 决策 | 通过、限制、补测、停止、负责人和复查触发器 |

评测实现可以参考 [HELM](https://arxiv.org/abs/2211.09110) 的场景与多指标组织、UK AI Security Institute 的 [Inspect](https://inspect.aisi.org.uk/) 任务/数据/solver/scorer 分层；使用工具并不自动满足上述证据要求。

## 提交前检查

- [ ] 声明、对象、目标分布和结论范围明确。
- [ ] 模型与完整系统结果没有混写。
- [ ] 数据版本、污染风险、敏感性和切分可追溯。
- [ ] prompt、工具、预算、裁判和运行环境已固定。
- [ ] 同时报告平均结果、严重失败、分层结果和不确定性。
- [ ] LLM 裁判已用人评校准并做顺序交换。
- [ ] 通过阈值在看盲测结果前冻结。
- [ ] 原始输出、工具轨迹、评分和裁决记录可复查。
- [ ] 结论写成覆盖范围内的证据，不宣称绝对安全或永久领先。

完成质量证据后，继续用[安全与对抗评测](./10.2-安全与对抗评测.md)检查攻击路径与控制失效。
