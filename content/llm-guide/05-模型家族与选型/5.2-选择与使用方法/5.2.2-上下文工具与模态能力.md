# 上下文、工具与模态能力

“支持 1M 上下文”“支持函数调用”“原生多模态”都是接口入口，不是任务完成保证。评测需要把容量、有效性能、系统编排和每种模态的输入输出逐项拆开。

## 标称上下文不是有效长上下文

### 先确认窗口口径

上下文窗口可能同时容纳：

- 系统、开发者和用户消息；
- few-shot 示例与对话历史；
- 文档、图像或音频编码后的 token；
- 工具定义、工具调用和工具返回；
- 模型隐藏或可见的推理预算；
- 最终输出 token。

接口最大值不一定全部可供用户输入。还要核对最大输出、单文件限制、模态预处理、批量限制、区域和具体 model ID。

### 有效性能需要分层测试

| 测试 | 要回答的问题 |
|---|---|
| 容量 | 是否接受目标长度，截断、报错和计费如何发生？ |
| 检索 | 目标信息位于开头、中间、末尾时能否找到？ |
| 多证据 | 能否合并分散证据，并拒绝上下文外推断？ |
| 干扰鲁棒性 | 面对相似、冲突和无关片段是否稳定？ |
| 全局理解 | 是否能跨章节比较、追踪实体和遵循文档级约束？ |
| 输出预算 | 长输入后是否仍有足够输出，能否完整结束？ |
| 运行代价 | 长度增加时 TTFT、吞吐、显存和成本如何变化？ |

测试长度应来自生产分布，例如 p50、p95、最大允许值，而不是只测极限窗口。每个长度再改变证据位置和干扰量，避免把“大海捞针一次命中”当成完整长上下文能力。

[Lost in the Middle](https://arxiv.org/abs/2307.03172)、[LongBench](https://arxiv.org/abs/2308.14508) 和 [RULER](https://arxiv.org/abs/2404.06654) 提供了不同测试思路；使用时仍需固定其数据版本、任务和模型设置。

### Tokenizer 和压缩的影响

相同文本在不同 tokenizer 下 token 数不同，不能用字符数直接比较窗口。文件解析、OCR、图像切块、音频帧和上下文压缩也可能丢失信息。记录原始输入大小、处理后 token、被截断或压缩内容，以及压缩器版本。

## 工具调用是完整系统能力

工具使用至少包含五层：

1. **选择**：模型判断是否调用哪个工具。
2. **参数**：生成满足 schema 的名称、类型、枚举和依赖字段。
3. **执行**：编排器校验权限并调用真实系统。
4. **观察**：模型正确读取成功、空结果、错误和部分结果。
5. **恢复**：重试、换工具、请求澄清、停止或转人工。

模型只生成函数参数时，并没有亲自执行工具。搜索质量、代码沙箱、检索库、权限和重试策略都属于系统变量。

### 工具测试矩阵

- 单工具选择、相似工具消歧和无需工具时不调用；
- 必填、可选、嵌套、枚举、数组、日期和长参数；
- 非法参数、未知工具、schema 变化和返回类型变化；
- 超时、限流、空结果、部分成功、重复执行和幂等；
- 多步依赖、并行调用、循环检测和最大步数；
- 工具输出中的提示注入、恶意链接和不可信数据；
- 读操作与写操作的权限隔离、高风险动作二次确认；
- 最终答案是否忠实于工具结果并标明失败。

比较模型时固定工具定义、排序、描述、权限、超时和返回内容。比较产品时则把编排器作为系统的一部分，报告端到端成功率和越权率。

## 多模态需要 I/O 矩阵

“多模态”不能说明方向和质量。为每个精确版本填写：

| 模态 | 输入 | 输出 | 还需记录 |
|---|---|---|---|
| 文本 | 语言、编码、结构化输入 | 文本、JSON、代码 | tokenizer、最大输入输出、schema |
| 图像 | 格式、尺寸、张数、透明度 | 描述、坐标、图像 | 缩放、切块、OCR、空间定位 |
| 音频 | 格式、时长、采样率、声道 | 文本、音频 | 转写、说话人、时间戳、流式延迟 |
| 视频 | 格式、时长、帧率、音轨 | 文本、视频 | 采帧、时间定位、音画对齐 |
| 文件 | PDF、表格、幻灯片、压缩包 | 摘要、结构化结果 | 解析器、页数、图表、宏和嵌入文件 |

### 多模态评测原则

- 分别测感知、定位、跨模态推理和输出生成，不用一个总分概括。
- 保存原始文件及预处理参数；产品自动 OCR 与裸 API 结果分开。
- 检查低清、旋转、遮挡、口音、噪声、长静音、长视频和多页文档。
- 涉及时间时测事件顺序、时间戳和跨片段一致性。
- 涉及空间时测坐标、计数、图表和细粒度文字，不只问总体描述。
- 输出音频或图像时另审安全、版权、水印、时长和编码约束。

## 能力验证记录

每项实验至少保存：

- model ID/checkpoint、API 区域、日期和接口版本；
- 输入原件、预处理、token/帧数和截断；
- 系统提示、工具 schema、权限和返回；
- 推理预算、采样、最大输出和重试；
- 任务成功、严重错误、延迟、资源和成本；
- 产品能力、API 能力、权重能力和完整系统能力的归属。

通过能力检查后，还需在目标负载下审查[部署成本与风险](./5.2.3-部署成本与风险.md)。
