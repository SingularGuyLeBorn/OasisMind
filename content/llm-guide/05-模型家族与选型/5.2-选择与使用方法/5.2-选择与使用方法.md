# 选择与使用方法

型号名称不是能力合同。“支持长上下文”“原生多模态”“支持工具”“开放模型”都需要拆成可核对的字段，并落到精确 checkpoint、API snapshot、区域、许可和系统配置。

## 三次审查

### 身份与权利

先确认使用的究竟是模型家族、产品、API、权重还是完整系统，再分别核对模型卡、权重、代码、数据和许可。见[模型卡与许可](./5.2.1-模型卡与许可.md)。

### 能力与接口

分别验证输入和输出模态、有效长上下文、工具契约、输出预算、错误恢复和安全边界。见[上下文、工具与模态能力](./5.2.2-上下文工具与模态能力.md)。

### 运行与治理

在目标长度和并发下测 TTFT、TPOT、吞吐、显存与 TCO，并审查区域、数据保留、回滚和供应链。见[部署成本与风险](./5.2.3-部署成本与风险.md)。

## 一张候选审查卡

| 类别 | 至少记录 |
|---|---|
| 身份 | 家族、模型 ID/checkpoint、修订、日期、Base/Instruct/Thinking、量化 |
| 获取 | API/权重/产品、区域、接口版本、别名或 dated snapshot |
| 开放性 | 模型卡、权重、代码、数据、日志/配方及各自许可 |
| 能力 | 语言、模态 I/O、上下文、输出上限、结构化输出、工具 |
| 运行 | TTFT、TPOT、吞吐、并发、显存、缓存和失败率 |
| 成本 | 输入、输出、缓存、工具、存储、网络、硬件、运维和人工复核 |
| 治理 | 数据驻留、保留、训练使用、删除、许可、供应链和下线政策 |
| 恢复 | 版本固定、变更检测、回滚、降级和替代候选 |

## 结论的表达方式

- 写“官方文档披露了什么”和“内部测试观察到什么”，不混成一句。
- 写明 `as_of`、区域、版本和测试设置，不承诺永久有效。
- 未公开的参数、训练数据、路由和系统实现保持未知，不用传闻补空白。
- 开放性、能力、价格和服务可用性分别核验；其中一项优秀不代表其余项优秀。

本节给出审查方法；最终选择仍应回到[模型比较与选型](../5.1-模型比较与选型/5.1-模型比较与选型.md)的冻结任务和上线闸门。
