# Kimi 智能助手：产品身份与长文本边界

> 核验日期：2026-09-01。早期 Kimi 是产品身份，不是一个随技术报告和权重完整公开的检查点；本页只陈述官方产品信息，未披露架构保持未知。

## 它是什么

Kimi 智能助手由 Moonshot AI（月之暗面）在 2023 年 10 月面向公众推出，早期核心卖点是处理长文本。官方客户端下载页以“约 20 万汉字”的方式描述长文本能力，产品后来继续加入联网搜索、文件阅读、办公与 Agent 功能。

这里的“约 20 万汉字”是**面向用户的字符口径**，不是模型卡里的固定 token 上下文。汉字、英文、代码、表格和文档解析中间产物的分词率不同，产品还可能做检索、压缩、分块或路由，因此不能把字符数按一个固定比例换算后写成模型架构上限。

## 三个容易混淆的身份

| 名称 | 层级 | 能确认什么 | 不能据此确认什么 |
|---|---|---|---|
| Kimi 智能助手 | 面向用户的持续更新产品 | 产品入口、产品公开功能和页面当时的容量口径 | 内部模型参数、注意力实现、训练数据、是否固定为单一检查点 |
| `moonshot-v1-8k/32k/128k` | 开放平台 API 路由 | 当前官方文档给出的 API 上下文与接口能力 | 它们等同于 2023 年 Kimi Chat 内部权重 |
| Kimi K2/K3 等 | 有独立模型卡或技术报告的版本 | 指定仓库披露的架构、窗口、权重与许可 | Kimi 产品线上始终只运行该公开权重 |

产品名可以保持不变而后端持续升级；API 路由也可以有独立生命周期。因此知识库应按日期保存产品事实，按精确仓库和 revision 保存模型事实。

## 已公开与未公开

官方产品页足以支持这些结论：Kimi 是长文本智能助手；能处理多类文档和用户任务；其产品能力持续演进。但 Moonshot AI 没有为最初的 Kimi Chat 发布一份可与 K2 报告同等核验的架构说明，也没有公开一个名为“Kimi Chat 初代”的完整权重检查点。

因此，下列未经一手材料支持的说法不能视为事实：

- “使用 RoPE 扩展、稀疏/局部注意力或 Ring Attention”——这些都是可能的长上下文技术路线，但没有足够一手证据证明用于该产品当时的内部模型。
- “2M 上下文”等把汉字数直接写成 token 的换算。
- 从后来的 K2.6 官网快照反向说明 2023 年 Kimi Chat 的技术结构。
- 用当前 `moonshot-v1` API 型号解释最初产品后端。

## 正确评估长文能力

产品是否能“放进”长文只是第一层。实际评估至少应覆盖：

1. 不同位置的事实召回，特别是中间位置的信息丢失；
2. 多文档冲突、时间顺序与来源归因；
3. 跨章节推理，而不只是关键词复制；
4. 表格、扫描 PDF、公式和版式解析质量；
5. 引用是否能回到原文，是否产生无依据概括；
6. 超长输入下的延迟、费用和失败重试。

如果任务必须复现，应记录日期、产品版本提示、输入文件、输出、引用和失败案例。网页产品会更新，单次截图不是永久模型规格。
