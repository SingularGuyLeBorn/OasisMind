# Kimi K2 Thinking：推理与连续工具调用

> 核验日期：2026-09-01。K2 Thinking 于 2025-11-06 发布，是 K2 主线的推理检查点；它不是 K2.5，也不具备后者的原生视觉编码器。

## 定位

Kimi K2 Thinking 把“模型作为 Agent”置于核心：模型在推理过程中选择工具、读取观察结果，再继续推理，而不是先生成一整段不可修正的计划。官方称这种模式为交错式思考与工具调用，并用长达数百次的连续工具调用场景展示其长轨迹能力。

模型卡给出 256K 上下文，并发布原生 INT4 权重。这里的“原生 INT4”表示官方提供的权重形态，不应被扩写为所有算子、KV 缓存或通信都以 4 bit 运行，也不等于单卡可部署一万亿总参数。

## 与普通 Instruct 的差异

| 维度 | K2-Instruct-0905 | K2 Thinking |
|---|---|---|
| 优先目标 | 通用指令、代码与 Agent 执行 | 显式推理、复杂任务与长工具轨迹 |
| 上下文 | 256K | 256K |
| 推理形态 | 通用 Instruct | 官方要求保留 thinking 行为，不能随意当作无思考模型 |
| 公开权重 | 常规开放权重 | 官方原生 INT4 开放权重 |
| 视觉编码器 | 无 | 无 |

两者不能只按 benchmark 高低替换。Thinking 通常会产生更多推理 token，延迟和费用不同；简单提取、改写或固定格式任务未必值得使用长推理。

## 交错式工具使用

一个工具轨迹可以抽象为：模型推理 → 发出结构化调用 → 环境执行 → 返回观察 → 模型更新判断。它的优势是能利用新证据纠正计划；风险则会随轨迹长度累积：

- 某次错误参数可能污染后续状态；
- 工具输出可能包含提示注入或不可信指令；
- 重复调用和无效探索消耗大量 token；
- 模型可能在没有验证的情况下过早宣布完成；
- 外部系统的写操作可能不可逆。

因此“可连续调用 200–300 次”是官方披露的能力口径，不是生产系统应默认放开同样预算。执行层仍需权限隔离、参数校验、幂等、预算、超时、人工确认与最终验证。

## 评测设计

推理 Agent 不能只看最终正确率。建议记录：

1. 首次工具选择与参数正确率；
2. 观察到错误后的恢复率；
3. 完成任务所需调用次数和生成 token；
4. 是否引用了实际工具结果，而非臆造结果；
5. 遇到提示注入、敏感数据和高风险写操作时的行为；
6. 相同初始条件下的方差。

官方 benchmark 只支持“在其协议下取得该结果”。业务选型应与 0905、K2.5 或其他模型在同一工具环境、同一预算和同一停止规则下比较。

## 部署注意

- 使用模型卡推荐的推理模板与采样设置；不要任意剥离 thinking token 后假定能力不变。
- 256K 是输入与输出共享的总预算约束之一，还要为工具结果和后续生成留空间。
- 原生 INT4 降低权重占用，但完整模型仍是约 1T 总参数的 MoE，需要匹配的多卡/多机推理栈。
- 许可为 Modified MIT；对外分发衍生权重或服务前保存并核对仓库许可证。
