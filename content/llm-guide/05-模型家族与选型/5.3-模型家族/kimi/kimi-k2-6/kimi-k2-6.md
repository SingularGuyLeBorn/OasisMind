# Kimi K2.6：多模态 Agent 能力升级

> 核验日期：2026-09-01。K2.6 于 2026-04-20 发布。它的官方模型卡继续列出 K2.5 的 1T/32B、MoonViT 与 256K 架构，因此主要应理解为检查点与 Agent 后训练升级，而不是新的参数代际。

## 定位

Kimi K2.6 面向更长的软件工程任务、视觉设计、主动任务推进和并行 Agent 编排。它保留 K2.5 的原生多模态输入，可以直接处理图像和视频；旧稿中“API 不暴露图像能力”的绝对表述不能用来否定公开模型卡。

托管 API 的具体请求格式、可用模态和路由仍可能随日期或套餐变化。模型卡能证明权重具备视觉结构，不代表任何同名 API endpoint 在任意时间都开放完全相同的媒体接口。

## 身份卡

| 字段 | 官方模型卡口径 |
|---|---|
| 发布日期 | 2026-04-20 |
| 总参数 / 激活参数 | 约 1T / 32B |
| Transformer 层数 | 61 |
| 注意力 | MLA，64 个注意力头 |
| MoE | 384 个专家、选择 8 个，另有 1 个共享专家 |
| 视觉编码器 | MoonViT，约 400M 参数 |
| 上下文 | 256K |
| 模态 | 文本、图像、视频输入；文本与工具调用输出 |
| 许可 | Modified MIT License |

与 K2.5 相同的架构表不意味着权重相同。继续训练数据、后训练轨迹、奖励设计与模板都能显著改变 Agent 行为。

## 重点能力

### 长周期编码

K2.6 官方材料强调在大型仓库中理解、修改、测试并继续修复。评估这种能力不能只看一次补丁是否“看起来合理”，而要把仓库检索、依赖理解、测试执行、失败恢复和最终 diff 审查都纳入成功条件。

### 视觉与设计任务

视觉编码器使模型可以基于截图、界面稿或视频进行分析和代码生成。生产验收仍需覆盖像素还原之外的可访问性、响应式布局、交互状态、浏览器兼容和安全性。

### 主动 Agent

“主动”通常表示模型能根据目标补充步骤、选择工具并持续推进，不等于可以跳过权限与确认。对发布、支付、删除、外发消息等高风险动作，应由执行系统强制审批；不能只依赖模型自我判断。

### 更大规模的 Agent Swarm

官方 Agent Swarm 支持页在 K2.6 版本给出最多 300 个子 Agent、4,000 个步骤的系统上限，并报告部分任务最高约 4.5 倍提速。这是官方产品编排口径，不是模型内部的 MoE 专家数，也不保证任意任务获得线性加速。

## 与相邻版本的边界

| 版本 | 主要增量 | 不应误写成 |
|---|---|---|
| K2.5 | K2 主线原生多模态、Agent Swarm | K2.6 的旧名称 |
| K2.6 | Agent、编码、视觉设计和更大 Swarm 的后训练升级 | 新的参数架构代际 |
| K2.7 Code | 基于 K2.6 的编码专项、thinking-only | K2.6 通用版本别名 |
| K3 | 新 2.8T/104B 架构和 1M 上下文 | K2.6 的小版本 |

## 部署与评测

- 固定 K2.6 模型仓库 revision；不要让无版本 API 别名替代可复现实验记录。
- 使用官方媒体处理器和聊天模板，分别记录文本、图像和视频 token 消耗。
- Agent 评测报告工具预算、执行环境、权限和最终验证方法，避免只摘录自报 benchmark。
- 自托管仍要保存约 1T 权重；32B 激活规模不等于 32B 模型的显存需求。
- 多 Agent 并发会放大推理费用、外部工具限流和冲突写入，先从少量可独立子任务压测。
