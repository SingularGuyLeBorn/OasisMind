# Kimi K3：2.8T 原生多模态 Agent 基座

> 核验日期：2026-09-01。Kimi K3 于 2026-07-16 发布，权重与技术报告于 07-27 公开。它是新的基础架构代际，不是 K2.6/K2.7 的后训练别名。

## 定位

Kimi K3 是 Moonshot AI 的超大规模原生多模态 MoE 模型，面向推理、编码、视觉和 Agent 任务。技术报告表格给出的精确规模是 2.78T 总参数、104.2B 激活参数；官方介绍常四舍五入为 2.8T/104B。它将大部分 Kimi Delta Attention（KDA）层与一部分 Gated MLA 层组合，在扩到 1M 上下文的同时保留全注意力式的信息交互锚点。

K3 的权重可下载，但使用自定义 Kimi K3 License。它的“开放”必须同时描述权重可得性和许可证条件，不能简写成 Apache-2.0、MIT 或无条件开源。

激活参数决定单 token 的部分计算量，完整的 2.78T 权重仍决定存储、加载和专家并行的基本规模。

## 混合注意力

### Kimi Delta Attention

KDA 属于受 delta rule 启发的线性/递归注意力路线：它把过去信息压缩进可更新状态，而不是为每个查询显式读取全部历史键值。高层目标是让长序列计算和缓存随长度更可控，同时通过选择性更新减少旧信息干扰。

线性注意力的压缩状态也可能丢失精确细节，因此 K3 没有只堆叠 KDA。知识库不应把“线性复杂度”写成“对任意 1M 内容无损记忆”。

### Gated MLA

24 个 Gated MLA 层提供内容相关的全注意力交互，并用门控调节信息流。KDA 与 MLA 混合的意义是折中：多数层承担高效的长序列状态更新，部分层提供更直接的全局 token 交互。实际首 token 延迟、KV 缓存和有效召回仍取决于推理实现与输入结构。

## 更大规模 MoE

K3 将路由专家数扩到 896，每 token 选择 16 个路由专家，并使用 2 个共享专家。相比 K2 主线的 384/8/1，容量和激活计算都明显增加。共享专家承担跨 token 的通用变换，路由专家提供条件化容量。

部署挑战随之增加：

- 完整权重必须分布在大量设备或以更低精度存储；
- 专家路由会产生跨卡 all-to-all 通信；
- 热门专家可能造成负载不均与尾延迟；
- 1M 上下文进一步放大预填充、缓存和请求调度压力；
- 框架“能加载”不等于在业务并发下有可用吞吐。

## 三条结构轴

K3 报告把扩展分成互相配合的三条轴，而不是只增加参数：序列轴用 KDA/Gated MLA 混合，深度轴用 Block Attention Residuals，宽度轴用 Stable LatentMoE。

### 序列轴：KDA 的稳定化

K3 对前代 KDA 的衰减与输出门做了具体调整。log-decay 改为有下界的 sigmoid 形式，报告给出 `g_min = -5`，避免小块内累计衰减落入 BF16 难以表达的范围；输出门改为满秩形式，提高通道间表达。它们是 K3 对 KDA 的版本化实现细节，不能反写为所有线性注意力的通用公式。

### 深度轴：Block Attention Residuals

普通残差连接只把相邻层输出相加；Attention Residuals 则让当前层对 embedding 与历史层输出做深度方向的加权读取。完整保留所有层输出会增加显存和流水线通信，因此 K3 使用 Block 版本：先将层分块、块内汇总，再在块之间做注意力。报告中的 K3 划为 8 个约 12 层的块，最后一块较短，加上 embedding 一共形成 9 个可查询来源。

AttnRes 改的是**深度维信息聚合**，不是增加残差流数量，也不是替换 KDA/MLA 的序列注意力。它与 mHC、超连接或 MLA 不能当作同一技术名词互换。

### 宽度轴：Stable LatentMoE

K3 的路由专家不全部在模型宽度 `d` 上计算，而是在 `d/2 = 3584` 的潜在宽度中运行；两个共享专家仍保留完整宽度。这样可以在 Top-16 路由下控制专家计算与通信，但连续的降维、门控和升维也带来训练稳定性问题。

报告把三项稳定化组合称为 Stable LatentMoE：聚合后的 RMSNorm、SiTU-GLU 激活，以及 Quantile Balancing 路由平衡。Quantile Balancing 针对超大专家数下负载平衡步长难以统一的问题，不应被简化成传统 auxiliary loss 的新名字。

## 原生多模态

MoonViT-V2 把图像与视频转换为视觉 token，再与文本共同进入 K3。与 K2.5 的视觉塔相比，K3 报告强调 MoonViT-V2 不再从 SigLIP 初始化，而是从头用 next-token prediction 训练，以避免接入预训练视觉编码器时出现的尖锐梯度。模型卡给出约 401M 参数，报告描述其为 27 层；图像和视频共享参数，并在投影前用 `2×2` pixel shuffle 减少视觉 token。

原生联合训练有利于视觉推理、界面理解和视觉 Agent，但必须分开评估视觉感知、OCR/空间定位、逻辑推理和工具执行。视频任务还应披露帧采样与时间信息，不能只写“支持视频”。

## 预训练公开边界

官方报告列出 Web、代码、数学、知识等文本域，以及 caption、图文交错、OCR、感知、视频和视觉编码等视觉域，并说明长文数据经过清洗、上采样和打散拼接。但报告**没有公开总训练 token、各域精确配比、峰值学习率、最终 batch size 等关键数值**。这些空白不能从图表横轴、K2 配方或第三方报道补造。

报告称重新联合搜索架构、数据和训练配方后，held-out OOD 验证损失所体现的 scaling efficiency 相对 K2 约提高 2.5 倍。这里的指标是其拟合与验证口径，不是公开 benchmark 提高 2.5 倍，也不是训练墙钟缩短到 1/2.5。

优化侧披露了矩阵参数的 Muon、注意力投影的 Per-Head Muon、来自 K2 的 weight clipping、Quantile Balancing、1% 线性 warmup、余弦学习率和 0.1 weight decay。它们是一套配方，不能把 K2 的 MuonClip 单独当作 K3 全部稳定性来源。

## 后训练：九个专家蒸回一个模型

K3 后训练可以概括为三阶段：SFT 冷启动；按三个任务域和三档 reasoning effort 训练 9 个 RL 专家；再通过 Multi-Teacher On-Policy Distillation（MOPD）合成单一检查点。三个域是通用任务、通用 Agent 和编码 Agent，effort 为 `low`、`high`、`max`。

### RL 与 partial rollout

长轨迹的执行时间差异很大。K3 用 partial rollout 在一部分轨迹完成后先开始优化，暂停的轨迹后续优先续跑；它提升资源利用率，但也使完成轨迹与当前策略之间产生时间差。报告用逐 token 正则约束局部策略更新，并按每题初始预算构造 reasoning-effort 课程。产品中的 effort 档位因此不是简单固定 token 上限。

Agent 训练还依赖可组合的环境 harness 和可恢复 sandbox。权重本身不会自动提供网页、终端、文件系统权限或断点恢复；部署者要重建工具协议、隔离和状态管理。

### MOPD

MOPD 按任务域和 effort 选择对应老师，用停梯度的老师/学生 token 概率 log 比构造并截断奖励，再对学生做 on-policy 更新。官方还试过提供更细的 top-k 蒸馏信息，但报告称没有明显收益。这里的“9 个专家”是**后训练教师策略**，与模型每层的 896 个 MoE 路由专家完全不同。

### 从 SFT 开始的 QAT

K3 的量化感知训练不是训练完成后的离线压缩：它从 SFT 开始贯穿 RL，rollout 与训练使用相同量化方案，以减少训推精度不一致。报告只将占主要参数量的路由专家设为 MXFP4 权重/MXFP8 激活；注意力、潜在投影、共享专家和路由器等保持更高精度。

官方没有给出完整的“量化 vs 全精度”公开榜消融，因此不能仅凭格式推断无精度损失。

## MTP 微调为投机解码 draft

K3 将预训练的单层 multi-token prediction（MTP）模块微调为 EAGLE-3 风格的 draft，而不是从头训练另一套独立模型。目标模型冻结，draft 融合 AttnRes 第 1、第 4 和最后一块的低、中、高层特征；融合投影初始化为 `[0, 0, I]`，让微调起点先等于 MTP 已见过的高层特征。

训练按 EAGLE-3 的 training-time test 展开 7 步，但这不承诺线上每次固定接受 7 个 token。目标函数直接优化与无损投机接受率相关的分布重叠，而不是 KL，也不额外加入真值交叉熵。官方未公开线上平均接受率整数，部署效果仍要由目标后端和请求分布实测。

## 长上下文基础设施

- **FlashKDA**：分块实现 KDA，让块内并行与块间状态传播重叠，并服务训练和 prefill。
- **KDA Context Parallelism（KCP）**：各段交换累计转移和局部生成状态，再做 prefix scan；不能像普通求和那样合并“从零计算”的局部递归状态。
- **MoonEP**：为专家并行规划 token 分配，使每个 rank 获得固定形状的负载并缩小通信缓冲；它解决系统负载，不是新的模型路由公式。
- **混合前缀缓存**：KDA 固定状态与 MLA 随 token 增长的 KV 要在同一前缀边界恢复，才能视为缓存命中。
- **可恢复 Agent sandbox**：支持跨多轮 partial rollout 继续长达 1M 上下文的工具轨迹，同时隔离外部执行环境。

这些系统优化是 K3 可训练、可服务的一部分。只复刻模型配置而没有相应 kernel、并行和缓存策略，不能据官方吞吐或上下文结论估算自己的系统。

## 量化感知训练

K3 在训练中引入量化感知，使模型适应 MXFP4 权重与 MXFP8 激活的低精度计算。它的目标是在超大模型上降低内存与计算成本，并减少训练后再量化造成的精度损失。

但 QAT 口径不意味着任何下载文件天然适用于所有 GPU，也不意味着 KV 缓存、路由、通信和全部算子同为 4 bit。部署前需确认仓库权重格式、推理后端、硬件支持、累加精度和业务精度回归。

## K2.x 与 K3 的断点

| 维度 | K2.5 / K2.6 / K2.7 Code | K3 |
|---|---|---|
| 主体规模 | 约 1T / 32B 激活 | 2.78T / 104.2B 激活 |
| 层数 | 61 | 93 |
| 注意力 | MLA | 69 KDA + 24 Gated MLA |
| 路由专家 | 384，选 8；1 共享 | 896，选 16；2 共享 |
| 视觉 | MoonViT，约 400M | MoonViT-V2，约 401M |
| 上下文 | 256K | 1M |
| 许可 | Modified MIT | Kimi K3 License |

这张表说明 K3 是新基座。K2.7 Code 虽然发布时间接近，也仍是 K2.6 架构的代码专项模型。

## 许可核验

Kimi K3 License 允许复制、修改、分发和使用模型，但包含不能被“开放权重”四个字省略的商业条款。官方许可证对达到特定收入的商业 MaaS 使用设置单独许可要求；对月活超过 1 亿或月收入超过 2,000 万美元的某些商业产品/服务设置显著展示“Kimi K3”的要求，并列有内部使用及官方/认证合作伙伴等例外。

这些条件需要结合实际业务和许可证原文判断。采用前应保存当时 revision 的许可证，由法务核对适用范围；本页不是法律意见。

## 评测与选型

1. 把官方 benchmark 标为作者自报结果，并核对提示、工具、采样、预算和是否使用并行 Agent。
2. 对 1M 上下文分别测针式召回、多跳推理、长代码依赖、首 token 延迟、峰值显存和并发吞吐。
3. 对多模态任务报告图像分辨率、视频帧采样和视觉 token 数。
4. 对 Agent 任务同时统计最终成功、工具错误、恢复、调用数、token、费用和高风险动作拦截。
5. 若 256K 足够且资源有限，K2.6/K2.7 Code 可能更容易部署；更大并非所有任务自动更优。

## 已知披露缺口

- 没有总预训练 token 与各数据域精确比例；
- 没有完整公开 peak learning rate、最终 batch 和 tokens-per-parameter；
- 没有 QAT 对全精度权重的完整公开榜消融；
- 没有线上投机 draft 的平均接受率整数；
- 官方 benchmark 与案例仍受提示、工具、预算和环境影响。

这些“未公开”本身也是版本事实。后续若模型卡或报告修订补充，应记录来源日期，不从图像或第三方摘要估算。
