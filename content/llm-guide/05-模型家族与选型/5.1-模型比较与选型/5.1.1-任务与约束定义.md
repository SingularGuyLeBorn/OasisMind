# 任务与约束定义

“做一个客服”“选一个代码模型”不是可评测需求。选型的第一步，是把任务写成可观察的输入、动作、输出和损失，并把不能妥协的边界从偏好中分离出来。

## 先定义比较层级

同一个名称可能指向不同对象。需求文档应先声明本次决策落在哪一层：

| 层级 | 例子 | 需要固定的身份 |
|---|---|---|
| 模型家族 | 某机构的一代模型 | 家族范围和版本边界，仅用于发现候选 |
| 精确模型 | checkpoint、开放权重或 dated snapshot | 模型 ID、修订、量化、Base/Instruct/Thinking 身份 |
| API 服务 | 托管推理端点 | API 模型 ID、区域、接口版本、推理参数和服务日期 |
| 产品模式 | 聊天、研究、代码或代理产品 | 产品版本、可用工具、系统行为和账户权限 |
| 完整系统 | 模型加 prompt、RAG、工具、策略和人工流程 | 所有组件版本、权限、路由和失败恢复 |

家族比较只能生成候选，不能直接产生生产结论。产品或完整系统的成绩也不能反推裸模型权重具备相同能力。

## 写清任务单位

每条样本至少包含：

- **触发条件**：用户请求、队列事件、文档上传或系统告警。
- **输入分布**：语言、模态、长度分位数、格式、噪声、领域和敏感等级。
- **允许动作**：只生成文本，还是可以检索、调用函数、运行代码或修改外部状态。
- **期望输出**：内容、结构、引用、置信表达、工具轨迹和最大输出长度。
- **完成判据**：一次回答正确、工作流最终成功，还是经人工确认后完成。
- **时间范围**：知识截止、数据新鲜度、响应期限和结论有效期。

对于代理任务，评测单位应优先是“任务是否完成且没有越权”，而不是某一步生成文本是否流畅。

## 建立失败与损失分类

先列失败，再选指标。建议至少区分：

| 失败类型 | 示例 | 需要记录的损失 |
|---|---|---|
| 内容错误 | 事实、计算、代码或引用错误 | 纠错时间、业务损失、人工复核成本 |
| 指令错误 | 漏约束、格式错、语言错 | 下游解析失败、重试和用户流失 |
| 安全错误 | 泄密、有害内容、越权工具调用 | 事件等级、暴露范围、恢复和合规成本 |
| 拒答错误 | 应答却拒答，或应拒却执行 | 任务失败率与风险暴露 |
| 时效错误 | 使用过期知识或旧版本规则 | 决策延迟、错误传播范围 |
| 服务错误 | 超时、限流、队列拥塞、输出中断 | SLO 违约、降级和重试成本 |
| 成本错误 | 长思考、循环调用、缓存失效 | 单任务成本尾部和预算超支 |

平均准确率无法表达严重事故。高风险任务可采用硬门槛、分级损失，或要求“在预先定义的门禁样本与风险覆盖范围内不得发现严重错误、一般错误再优化”；这不等于测试能证明现实世界绝对零风险。

## 约束清单

### 内容与能力

- 目标语言、方言、代码语言和术语覆盖；
- 文本、图像、音频、视频、文件等输入输出模态；
- 上下文长度分布、单文件大小、输出预算和多轮状态；
- JSON/schema、引用、函数参数或代码可执行性；
- 是否需要搜索、私有检索、代码执行、浏览器或企业工具；
- 知识时效、引用可追溯性和允许的不确定性。

### 服务目标

- TTFT、TPOT 或端到端延迟的目标分位数；
- 峰值与持续吞吐、并发、突发流量和队列上限；
- 可用性、超时、重试、幂等和降级路径；
- 单任务、单用户和月度预算；
- 可接受的人工升级比例和处理时限。

### 部署与治理

- API、自托管、托管专实例或端侧部署；
- 可用硬件、显存、机房、网络和运维能力；
- 数据驻留、跨境、日志、训练使用、保留和删除要求；
- 权重、代码、数据和输出的许可要求；
- 区域、供应商锁定、下线通知和替代模型；
- 外部工具权限、密钥隔离和高风险动作审批。

## 硬约束与优化目标

把条件分成两类：

- **硬约束**：违反即淘汰，例如区域不可用、许可不允许、无法处理必需模态、显存装不下或严重错误超过阈值。
- **优化目标**：在合格候选中权衡，例如更低 TPOT、更低成本、更好的长尾质量或更成熟的生态。

不要让加权总分把硬约束“平均掉”。权重应来自失败代价和业务优先级，而不是沿用通用模板。

## 构造验收样本

### 四类数据集

1. **代表集**：按真实语言、长度、模态、用户和任务占比分层抽样。
2. **困难集**：长尾格式、模糊指令、长上下文、多工具和低资源语言。
3. **风险集**：越权、提示注入、敏感数据、危险动作、应拒与不应拒样本。
4. **时效集**：规则、价格、版本、新闻等会变化的任务，记录答案有效日期与允许来源。

训练、prompt 调整集、开发集与最终盲测集应分开。最终集冻结后，不再用其错误案例反复调 prompt；需要迭代时建立新版本并保留历史结果。

### 每条样本的最小字段

- 输入与上下文；
- 允许工具和权限；
- 可接受答案或判分规则；
- 严重错误标签；
- 数据来源、创建日期和敏感等级；
- 是否可能进入公开训练语料；
- 人工裁决标准和分歧处理方式。

## 需求评审完成条件

进入候选评测前，应能回答：

- 比较的是哪一层对象？
- 哪些条件是一票否决？
- 一次严重失败会造成什么损失？
- 真实数据的语言、长度、模态和时效分布是什么？
- 工具、延迟、吞吐、预算和部署边界是什么？
- 验收集如何防止泄漏和反复调参？
- 谁能批准例外，谁负责事故与回滚？
