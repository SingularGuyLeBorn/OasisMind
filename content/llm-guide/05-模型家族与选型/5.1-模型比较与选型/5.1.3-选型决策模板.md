# 选型决策模板

本模板既是决策记录，也是上线检查单。填写时链接到实验、模型卡、许可文本、威胁模型和运行手册，不只填写结论。

## 决策信息

- 任务、系统和负责人：
- 决策日期、证据截止日期、复查日期：
- 目标用户、地区和数据等级：
- 比较层级：权重 / checkpoint / API / 产品 / 完整系统：
- 允许工具与外部动作：
- 质量、延迟、吞吐和预算目标：
- 关键失败与最高可接受损失：

## 硬约束

| 门槛 | 要求 | 证据 | 结果 |
|---|---|---|---|
| 身份 | 可固定精确版本或检测漂移 | 模型 ID、snapshot、哈希、日期 | 通过/不通过 |
| 模态与语言 | 覆盖必需 I/O、格式和语言 | 官方文档加内部样本 | 通过/不通过 |
| 工具 | 支持所需 schema、权限和恢复 | 工具契约测试 | 通过/不通过 |
| 部署 | 区域、硬件、容量和运维可行 | 容量评估 | 通过/不通过 |
| 数据治理 | 驻留、保留、训练使用和删除符合要求 | 合同、设置、审查记录 | 通过/不通过 |
| 许可 | 权重、代码、数据和使用条款可接受 | 原始许可文本 | 通过/不通过 |
| 安全 | 严重风险低于阈值且可阻断 | 风险集、红队、控制措施 | 通过/不通过 |

任一硬约束不通过时，候选退出或缩小用途。例外必须记录批准人、期限和补偿控制。

## 候选漏斗

### 发现池

从正式模型目录、模型卡、技术报告和已有基础设施发现候选。家族名只用于搜索，不用于记录最终结果。

### 纸面筛选

核对精确身份、可用区域、模态、上下文、许可、硬件和下线政策。删除信息缺失且无法补证的候选。

### 快速基线

用小型代表集验证接口、格式、语言、工具和明显质量问题，同时测量大致延迟和资源。不在此阶段精调到某个模型的极限。

### 正式短名单

一般保留少量真正可部署的候选，以统一设置完成盲测、压力测试和风险测试。候选过多会挤压每个候选的证据深度。

## 候选与证据

| 精确版本 | 获取方式与区域 | 开放性/许可 | 质量与严重错误 | TTFT/TPOT/吞吐 | 每有效任务成本 | 主要风险 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

如需加权决策，权重应由失败损失和业务目标推导，并在看结果前冻结。原始分层指标和硬门槛必须保留，不能只存一个综合分。

## 离线评测结论

- 数据版本、样本量和真实流量覆盖：
- prompt、推理预算、工具和 judge 是否统一：
- 主指标及置信区间：
- 严重错误、拒答、无效输出和工具失败：
- 各语言、长度、模态、风险等级的短板：
- 负载、并发、上下文长度变化下的性能：
- 未解决的不确定性与需要补做的实验：

结论使用限定语，例如：“在冻结数据 v3、统一工具和中等推理预算下，候选 A 的任务成功率较高；在超长输入和高并发下候选 B 更稳定。”

## 受控试点

### 试点方式

- 影子流量：不影响用户，只比较输出和运行指标；
- 人工确认：模型提出结果，人员批准后执行；
- 小比例灰度：限定用户、地区、任务和权限；
- Champion/Challenger：稳定版本提供服务，新版本只接收受控流量。

### 必须记录

- 流量比例、样本选择和排除规则；
- 模型、prompt、RAG、工具和安全策略版本；
- 用户成功、人工改写、升级、取消和投诉；
- p95/p99 延迟、限流、工具错误、重试和成本尾部；
- 数据、日志和反馈的保留方式；
- 自动停止阈值和人工值班人。

## 上线闸门

| 闸门 | 最小问题 | 负责人 | 证据与状态 |
|---|---|---|---|
| 质量 | 代表集、困难集和真实试点是否达标？ | 产品/评测 |  |
| 安全 | 越权、注入、泄密、有害输出能否阻断？ | 安全 |  |
| 隐私与合规 | 数据流、区域、保留和删除是否批准？ | 隐私/法务 |  |
| 可靠性 | 峰值、超时、限流、降级和依赖故障是否演练？ | SRE |  |
| 成本 | 峰值预算、循环调用和异常账单能否限制？ | 工程/财务 |  |
| 可观测性 | 能否追踪版本、请求、工具、质量和成本？ | 平台 |  |
| 回滚 | 是否能在目标时间恢复已验证版本？ | 发布负责人 |  |
| 供应链 | 权重、代码、容器、SDK 和供应商变更是否受控？ | 平台/安全 |  |

“有监控”不是通过条件；每个闸门都需要阈值、告警、负责人和操作手册。

## 回滚与降级

至少准备两种恢复路径：

1. **版本回滚**：恢复已验证的 snapshot/checkpoint、prompt、索引和工具配置。
2. **能力降级**：关闭高风险工具、缩短任务链、转为只读、切人工或暂停服务。

回滚手册应包含触发阈值、权限、配置位置、数据兼容性、缓存清理、验证查询和恢复后的复盘流程。仅写“可切回旧模型”不足以证明可恢复。

## 持续监控与复查触发器

- 任务成功率、严重错误、应拒/不应拒和人工改写；
- 输入语言、长度、模态和用户分布漂移；
- TTFT、TPOT、队列、超时、工具错误和单位任务成本；
- API 别名、模型 snapshot、权重哈希、SDK 或系统提示变化；
- 价格、限流、区域、数据保留或许可条款变化；
- 新攻击、新法规、供应商事件或关键依赖漏洞。

定期复查不能替代事件触发复查。任何可能改变输出分布、权限或成本的组件更新，都应按影响范围重新跑对应验收集。
