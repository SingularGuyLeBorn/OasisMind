# 经典论文阅读指南

这个知识库不是"所有经典论文"的穷举,也不把网络流传书目当作不可质疑的权威原件.它做两件事:整理一份与 Sutskever–Carmack 轶事相关的社区重建书目,并补入能够连接现代架构的少量经典工作.

## 先分清三种顺序

1. **私人原始清单**:John Carmack 在采访中回忆,Ilya Sutskever 曾给他一份大约 40 项的阅读材料,并说学懂后可掌握当时约 90% 的重要知识.

原始私人清单没有完整公开,因此其逐项内容和顺序不可核验.
2. **社区重建书目**:网络社区整理出的 27 项版本.它可用于追踪流传版本,但只能证明"该重建版本收录了什么",不能证明私人原始清单的精确内容.
3. **本站学习路线**:本站按知识依赖把 27 项重排为六个主题,编号采用 `1.1.1`,`1.2.1` 等继承式结构.编号只表示本站阅读路径,不代表 Ilya 的排序或作者意图.

### 三条可选阅读路径

### 从理论到工程

依次阅读复杂度与信息论,CNN,RNN,Attention,结构化推理,规模化训练.

这是本站默认路线,适合第一次系统补课.

### 从现代模型反向追根

先从 Transformer,Scaling Laws 或 MoE 进入,再沿每篇文章的"前置阅读"和"相关工作"回溯.适合已经做过大模型训练或部署的读者.

**单篇怎么读**

1. 先读摘要,问题定义和结论,确认论文到底解决什么.
2. 再看核心机制与关键公式,不把后人的解释误写成原论文结论.
3. 对实验数字检查数据集,指标,模型规模和比较对象.
4. 最终读局限与后续影响;"首次""唯一""直接催生"等强断言必须能追到一手来源.

**来源等级**

正文优先链接论文,作者博客,课程官网,会议页面和官方代码.社区书目只用于说明重建版本本身;二手文章只作扩展阅读.找不到一手证据时,会明确写成"尚无法核验",而不是补全传闻.

## 把论文放回问题链

经典论文通常把一个含混的问题改写成可计算对象.复杂度与 MDL 讨论怎样度量结构和模型选择;CNN 论文讨论局部连接,深度与残差路径;RNN,LSTM 和 Attention 处理序列状态与可变长度依赖;显式记忆,关系网络和图网络把推理对象从单一向量扩展到地址,集合与边;GPipe,Deep Speech 2 和 Scaling Laws 则把算法放进数据规模,硬件与训练预算.阅读时先找问题定义,再看作者允许哪些输入,保存什么状态,优化什么目标.

历史顺序与概念依赖并不重合.AlexNet 早于 ResNet,但理解残差退化问题不需要重读全部视觉史;Bahdanau Attention 早于 Transformer,前者的动态对齐能解释后者为何不再把源序列压成定长状态;HiPPO 和稀疏 MoE 不在 27 项社区重建版中,却分别连接现代状态空间模型与条件计算.因此本站保留书目来源,同时另建学习顺序.**来源坐标回答“这项材料从哪里来”,教学坐标回答“为了理解下一项应先读什么”.**

### 读公式与实验

公式要展开到参与者和状态.一个递归式至少要说明当前输入,历史状态和参数;一个损失要说明样本来自哪里,对哪些变量求梯度;一个并行算法要说明各设备持有什么,何时通信.符号若只在公式里出现而正文没有定义,先回原文寻找定义,不要用后来的通行含义替换作者当年的用法.

实验数字必须绑定数据集,划分,指标,模型规模和基线.同一工作常同时包含机制验证,消融和最终系统结果,三类证据支持的结论强度不同.消融能说明在指定设置中去掉组件发生什么,不能证明该组件在所有架构中必要;规模曲线能描述观测区间,外推部分仍依赖拟合假设;可视化可以帮助解释行为,不能单独证明模型内部形成了人类概念.

### 三种读法

第一次系统阅读适合走本站六段路线.每个主题先读首页,确认该段的共同问题与条目顺序,然后按论文的“问题—方法—实验—局限”推进.已经熟悉现代 LLM 的读者可从 Attention,Scaling Laws,GPipe 或 MoE 逆向回溯,但遇到术语重名时仍要回到原始定义.

按项目查阅时,从当前故障选择入口.训练深网络不稳,可回到残差连接与规范化的历史;长序列状态成本过高,可比较 Attention,外部记忆与状态空间模型;总参数需要增长而每 token 计算受限,可进入稀疏 MoE;模型跨设备放置困难,则阅读 GPipe 的切分,微批和重计算.这种读法要求在项目笔记中写出论文条件与当前条件的差异.

时间有限时,每篇至少保留四项记录:作者解决的问题,核心状态或公式,最有说服力的一项实验,以及作者明确承认的边界.四项能够阻止摘要退化成结论口号.有余力再补前置工作与后续演进,并区分“论文提出”“后续采用”和“今天常见”三个事实层级.

跨主题阅读还要记录术语迁移.“Attention”在早期神经机器翻译中指解码器对编码器状态的动态加权,Transformer 将同一类匹配运算扩展为 self-attention 并移除循环主干;“memory”在 LSTM 中是循环状态,在 Neural Turing Machine 中还包含外部可寻址矩阵,在 KV Cache 中则是推理时保存的历史投影.名称相同不表示状态,训练目标或计算成本相同.把输入,状态,更新规则与输出列成表,比背诵名词谱系可靠.

最终,复现与理解也应分开.复现论文结果需要版本一致的数据,预处理,初始化,训练预算与硬件;理解机制则可用缩小的手算或代码实验验证形状,梯度和边界.小实验能够证明实现符合某个公式,不能代替原论文的大规模效果.反过来,论文报告的最终数字也不能证明读者写出的实现正确.本站文章同时保留公式,实验条件和后续关系,正是为了让这两类证据互相校验.

### 先把论文拆成六个对象

一篇机器学习论文通常同时包含问题,数据,模型,目标函数,优化过程和评测协议.标题里的方法名只覆盖其中一部分.先用六行笔记把对象分开,能避免把数据扩充带来的收益归给架构,也能避免把推理阶段技巧误写成训练方法.

**问题**要写清输入,输出和约束.「长上下文」可能指长度外推,长文问答,缓存容量或训练序列长度,四种问题的成功标准不同.**数据**要记录来源,规模,去重与划分.同名 benchmark 若版本或 prompt 模板不同,数字也可能不可比.**模型**记录状态和数据流,特别是每个张量由谁产生,会被谁读取.**目标函数**记录每一项的采样分布,权重和求梯度变量.**优化**包括初始化,学习率,batch,精度与训练步数.**评测**则写明指标,解码配置,基线和置信区间.

摘要可以帮助定位这六项,但通常会压缩条件.方法部分给出作者希望实现的机制,实验部分才说明机制在什么设置中得到支持.附录常包含超参数,证明和额外消融,复现时不能跳过.相关工作负责说明作者如何划分领域,其中的比较未必经过同一实验协议.

## 公式阅读从 shape 开始

遇到矩阵公式,先在每个符号旁写 shape.例如 $Q,K\in\mathbb{R}^{n\times d}$ 时,$QK^T\in\mathbb{R}^{n\times n}$;softmax 沿最终一维归一化,每一行表示一个 query 对全部 key 的权重.若再乘 $V\in\mathbb{R}^{n\times d_v}$,输出回到 $n\times d_v$.shape 能直接检验转置,广播和求和轴,也能估算中间激活的内存.

概率公式还要写随机变量来自哪个分布.同样是 $\mathbb E$,对训练数据取期望,对模型采样取期望和对变分后验取期望具有不同含义.KL 的方向也不能省略:$D_{KL}(q\|p)$ 在 $q$ 覆盖而 $p$ 概率接近零的位置惩罚很大,换成 $D_{KL}(p\|q)$ 会产生不同偏好.如果论文用 Monte Carlo 估计期望,还要看样本数和梯度估计器.

递推式从最小时间轴展开.写出 $t=1,2,3$ 三步,标明参数是否共享,状态怎样传递,损失在哪些步产生.这样能直接看见梯度需要经过多少次乘法,dropout 掩码是否随时间变化,以及推理能否并行.图网络同理:展开两轮消息传递,就能判断一个节点最远读取到几跳邻居.

论文中的等号有三类.定义等号规定符号,代数等号可以逐步推导,近似或估计关系则依赖假设.作者若从连续系统离散化,要找步长与离散方案;若从总体目标改成 minibatch,要找无偏性或方差;若把复杂模型化成上界,要找等号何时成立.把三类关系混写,会让经验近似看起来像数学定理.

### 数字必须连着条件抄

记录实验数字时至少附上数据集与划分,指标方向,模型规模,训练预算和基线.例如 perplexity 依赖 tokenizer 与词表,不能跨分词方案直接比较;BLEU 依赖 tokenization,casing 和脚本版本;图像 top-1 还受裁剪和增强影响.数字脱离协议以后只剩小数点,无法支撑方法比较.

表格中最醒目的数字通常是最终系统结果,机制判断却更多依赖消融.消融要检查是否一次只改一个变量,训练预算是否相同,误差是否超过随机种子波动.删掉模块后变差能说明该模块在当前组合中有贡献,仍不能证明它在所有架构中必要.若模块同时改变参数量或 FLOPs,还要增加匹配容量的基线.

规模曲线需要记录观测范围.在 $10^7$ 到 $10^9$ 参数之间拟合的幂律,外推到万亿参数时可能受到数据不足,优化变化和架构切换影响.论文若报告拟合指数,查看拟合变量用的是总参数还是非 embedding 参数,计算量是理论 FLOPs 还是实际设备时间.横轴定义改变会直接改变配方.

速度数字先区分 latency,throughput 和总训练时间.latency 还要区分平均值与尾延迟,throughput 要说明 batch 和序列长度.训练加速可能来自更多设备,低精度或不同收敛标准.模型达到相同 loss 的时间与跑完相同步数的时间是两个指标.系统论文中,硬件型号,互联拓扑和软件版本属于结果的一部分.

### 证据怎样支撑不同强度的结论

一条训练曲线证明该配置在一次运行中能够优化;多个随机种子给出波动范围;跨数据集实验说明效果不局限于单一分布;受控消融帮助定位组件;理论证明则只在假设成立时给出结论.证据层级可以叠加,无法互相替代.定理证明复杂度上界,并不保证现有 kernel 更快;benchmark 提升,也不证明作者给出的机制解释唯一正确.

可视化适合发现模式.注意力图能显示权重集中位置,路由图能显示 token 分配,隐藏状态探针能显示线性可分信息.它们都可能受选择样例和绘图尺度影响.更强的检查包括干预:遮掉高权重位置,交换对象,打乱顺序,控制参数量或构造反例,再观察输出如何变化.

历史影响同样需要具体对象.后续论文引用某项工作,只说明存在文献联系;后续系统沿用相同公式或模块,才说明技术继承.「首次」要求检查更早工作,「催生」需要时间与机制证据,「成为标准」至少要指出哪些代表系统采用.无法建立这些联系时,写清论文当时解决的问题已经足够.

### 复现分为三个层次

第一层是**公式复算**.选最小张量或几条样本,手算一遍输出,再用代码对照.这一步能发现转置,归一化轴,mask 和常数项错误.第二层是**机制复现**.构造缩小任务,验证关键现象,例如残差网络的优化差异,注意力能否对齐,MoE 是否出现负载集中.第三层才是**结果复现**,需要匹配数据,预算,硬件和评测.

公式复算通过,只证明局部实现与推导一致;缩小实验成功,只证明机制在玩具设置中可发生;最终数字接近,还可能存在多个错误彼此抵消.可靠复现会同时保留单元测试,shape 断言,训练日志,配置和数据版本.无法获得原数据或算力时,应明确停在哪一层.

复现失败也要分类.损失完全不降通常先查数据与梯度;小模型正常,大模型发散,再查精度,初始化和并行;质量接近但速度差,重点看 kernel,batch 和通信;训练指标一致而评测不同,优先核对预处理与解码.把所有差异归结为「超参数没调好」不会产生可用结论.

## 建立自己的论文笔记

一篇读完后,用一页记录问题定义,参照系统,核心公式,shape,关键实验,失败模式和后续连接.核心公式旁放一个手算例子,关键数字旁附表号与条件.如果某个结论来自自己的推断,直接写出推断链和前提,不要混入作者原结论.

多篇论文比较时固定同一组坐标.架构类可以比较状态,连接图,复杂度和归纳偏置;训练类比较目标,采样,优化与稳定性;系统类比较分片对象,通信,内存和容错;评测类比较数据,指标,污染和统计功效.统一坐标让差异自然出现,无需用大量形容词制造重要性.

最终做一次反向复述:不给方法名,只描述它改变了哪个张量,减少了哪项成本,增加了什么约束,由哪组实验支持.如果仍只能背论文标题和排行榜,说明机制尚未进入可迁移的知识结构.能够从公式推到实现,从实现推到指标,再从指标退回适用条件,才算完成一篇论文的阅读闭环.

### 常见的四类比较错误

第一类是**预算错位**.新方法使用更多参数,更多 token 或更长训练,却只和较小基线比较.解决办法是同时给固定参数,固定 FLOPs 或固定时间中的至少一种对齐结果.第二类是**数据错位**.训练集来源,去重,污染或提示模板不同,benchmark 分数便混入数据优势.模型能力比较必须先说明数据条件.

第三类是**阶段错位**.训练优化,prefill 加速和 decode 加速作用于不同数据流.一种 kernel 降低训练激活内存,未必减少逐 token 推理读取;量化降低权重带宽,也可能增加解码或校准误差.第四类是**指标错位**.平均准确率掩盖长尾类别,平均延迟掩盖尾延迟,总体 loss 掩盖特定长度退化.先确认指标能否看见论文声称解决的问题.

### 反例比总结更能检验理解

为每个机制构造一个它会失败的输入.卷积面对需要远距离精确配对的任务,固定状态面对无界精确回忆,全注意力面对极长序列显存,MoE 面对高度相关 token 的瞬时拥塞,经验规模律面对训练分布和架构突变.这些反例会暴露方法依赖的假设和资源边界.

如果一个解释无法预测失败条件,它通常还停留在描述层.例如「残差让网络更深」不如「恒等加法路径缩短梯度必须经过的非线性变换」具体,后者能预测破坏 shortcut 或在加法后截断信号会发生什么.同样,「attention 能看全局」还要补上连接矩阵与平方成本,才形成可检验机制.

### 引用链怎样使用

第一次出现术语时优先回到提出该公式或问题的原始材料,实现细节则查官方代码和维护文档.综述适合建立地图,不适合替代关键数字的出处.后续论文如果修正早期结论,应并列写出实验条件变化,而不是简单宣布旧论文错误.

引用也要贴着具体陈述.一个链接不能同时证明作者身份,公式来源,benchmark 数字和历史影响.数字最好附表号或章节,代码行为附具体版本,会议奖项查会议官方页面.链接能够打开只是最低要求,页面内容必须直接支持附近那句话.

## 阅读顺序服务于问题

按历史顺序能看见研究者当时掌握的工具,按概念依赖更适合教学,按当前故障逆向查阅更适合工程.三种顺序没有统一优先级.本库保留来源书目的坐标,再单独组织主题,正是为了让「材料来自哪里」与「现在怎样学」同时成立.

进入陌生方向时,先读主题首页建立变量表,再选一篇奠基工作和一篇现代代表作对照.前者提供问题原型,后者暴露规模变化后的新约束.中间论文按具体疑问补齐.这样既能避免只读最新工作而缺少参照,也不会退化成按年份逐篇罗列.
