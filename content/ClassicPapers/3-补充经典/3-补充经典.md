# 补充经典

这一章不追求补齐所有深度学习史,而是补入对现代架构仍有直接解释力,且能用原始论文核验的关键工作.

## 收录原则

- 能回答一个长期存在的基础问题,而不仅是刷新一次榜单.
- 对后续方法存在可追踪的机制关系.
- 有可访问的论文,作者资料或官方实现.
- 新增前先说明与现有条目的边界,避免把同一背景反复写成多篇.

### 当前专题

- [`2.1` 状态空间模型](3.1-状态空间模型/3.1-状态空间模型.md):HiPPO 与连续时间记忆.
- [`2.2` 混合专家模型](3.2-混合专家模型/3.2-混合专家模型.md):稀疏门控与 Switch Transformer.

后续若扩充优化器,归一化,生成模型或训练系统,应先建立主题首页和入选标准,再补充相应的论文解析.

### 为什么从这两个主题开始

社区重建书目覆盖了从复杂度到 Transformer 与 Scaling Laws 的多条主线,但现代 LLM Atlas 还需要两条无法由原清单完整承接的架构路线.第一条是状态空间模型:模型怎样把不断到来的序列压入有限状态,同时保留对过去的可控记忆.第二条是混合专家模型:模型怎样扩大总参数容量,又让单个 token 只激活少量参数.两条路线分别处理“时间状态怎样压缩”和“参数计算怎样稀疏化”,都直接影响长序列与大规模训练.

补充章节不把后来的热门论文倒推成历史必然.每个主题从一个定义清楚的机制起点进入,再沿可核验的后续工作连接到现代模型.当前状态空间路线收录 HiPPO,因为它把记忆写成对历史函数的在线投影问题,给出连续时间状态更新与离散化方法;当前 MoE 路线收录 Sparsely-Gated MoE 与 Switch Transformer,因为前者系统处理稀疏门控,负载均衡和分布式效率,后者把路由简化为 top-1 并研究容量与稳定性.

## 状态空间模型:先定义记忆

[状态空间模型](3.1-状态空间模型/3.1-状态空间模型.md)当前以 HiPPO 为入口.普通 RNN 的 hidden state 由训练自行形成,但“它应保存历史中的什么”通常没有显式目标.HiPPO 选择一组基函数,让有限维状态持续逼近截至当前时刻的历史函数.不同时间测度决定近期与远期信息怎样加权,连续动力系统离散化后才能进入实际网络.

这条路线分为三层.第一层是 HiPPO 的投影问题与状态矩阵;第二层是 S4 等工作怎样参数化并高效计算长卷积;第三层是 Mamba 等选择性状态空间模型怎样让状态更新依赖输入.HiPPO 只完成第一层,后两层由后续工作发展出来.从 HiPPO 起步可以保留状态空间模型的数学源头,也方便比较后续方法究竟改了状态表示,计算方式还是输入依赖性.

判断状态空间方法时,不能只看序列复杂度.还要检查训练时能否并行,Decode 时状态大小,长程任务的实际效果,离散化稳定性与硬件 kernel.线性时间并不自动等于墙钟更快,固定状态也不保证所有历史细节都能恢复.

### 混合专家模型:容量与计算分离

[混合专家模型](3.2-混合专家模型/3.2-混合专家模型.md)先读 Sparsely-Gated MoE,再读 Switch Transformer.前者用 noisy top-k Router 为每个样本选择少数专家,并通过重要性与负载辅助损失减少路由集中;它还讨论专家批次过小,跨设备通信和条件计算的工程障碍.Switch Transformer 把选择简化为 top-1,引入专家容量和 token overflow 处理,在更简单的路由下扩展模型规模.

两篇论文不是“MoE 从复杂到简单”的线性胜负关系.Top-1 降低 dispatch 与组合复杂度,也减少同时参与的专家;top-k 提供多专家组合,通信与负载控制更复杂.后续模型继续采用共享专家,细粒度专家,设备受限路由或无辅助损失均衡,说明设计空间仍未收束.理解现代 MoE 时应分别核算总参数,激活参数,Router 计算,专家容量,All-to-All 字节与 token 丢弃策略.

### 与主清单怎样衔接

状态空间路线可接在 RNN 与序列建模之后.读者已经理解循环状态,门控和长依赖困难,再读 HiPPO 会看到“记忆”从经验 hidden state 变成函数逼近对象.也可在 Transformer 之后进入,用固定状态递推与全历史 Attention 对照训练并行,推理状态和内容选择能力.

MoE 路线适合接在 Transformer FFN 与 Scaling Laws 之后.稠密 Scaling 把更多参数与更多每 token 计算绑定,稀疏专家尝试放松这种绑定;GPipe 与分布式训练又为专家跨设备放置提供系统背景.这种衔接能解释 MoE 为什么既是模型结构问题,也是通信与负载调度问题.

## 继续扩充的边界

新增主题需要满足三项条件.第一步,它补足主清单中确实缺失的机制链,而不是因为近期流行.第二步,至少存在可作为起点的一手论文,其问题,公式和实验能够独立讲完整.最终,新增条目之间要有明确依赖,主题首页能够解释为何按该顺序阅读.

优化器,归一化,量化,检索与后训练都可能成为后续方向,但不能把相关论文简单排成“神作榜单”.LLM Atlas 的作用是展示问题之间的来路与分叉:一篇论文改变了什么状态,补上前一方法的哪个缺口,又留下什么工程代价.只有关系能够被原文和实现核验时,它才进入这部分路线.

两条现有路线也提供了统一的比较方法.先写出稠密或全历史参照,再说明新方法压缩了什么:HiPPO 把历史函数投影到有限系数,MoE 把全部专家计算压成稀疏激活集合.随后追踪被省下的状态或 FLOPs 转移成了什么代价.状态空间模型要承担信息压缩,离散化和专用 kernel 的约束;MoE 要承担 Router 学习,负载均衡,专家容量和跨设备 dispatch.任何“线性复杂度”或“参数大而计算不变”的结论,都必须带上这些条件.

### 实验阅读同样按这一参照进行

实验阅读同样按这一参照进行.HiPPO 的记忆任务说明特定投影能保留哪些历史结构,不能单独推出所有语言任务优势;Sparsely-Gated MoE 的大规模语言模型结果依赖当时的专家布局和通信实现;Switch Transformer 的速度与质量结果要绑定其硬件,基线,训练步数和专家容量.后续模型采用相关思想能说明影响延续,不能把后续改进的效果倒记到早期论文.

两类方法都可以落到状态图上.状态空间图标出输入,有限状态,连续更新,离散化和输出;MoE 图标出 token,Router,Top-K,专家批次,合并输出与设备通信.每条边再标出 shape,保存周期和训练信号,论文机制便能与现代实现逐项对应.这种表示也为新增主题提供统一的比较坐标:它改变哪段状态,增加哪种通信,又把哪项成本转移到训练或推理阶段.

这种验收方式也保留了章节的工程用途:读者可以据此检查代码实现,估算资源,并识别论文结论不能覆盖的部署条件.
