# 2.2.1 · Sparsely-Gated MoE: 稀疏门控让容量涨 1000 倍, 计算几乎不涨

> 原始论文: Noam Shazeer, Azalia Mirhoseini, Krzysztof Maziarz, Andy Davis, Quoc Le, Geoffrey Hinton, Jeff Dean, "Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer", ICLR 2017. [arXiv:1701.06538](https://arxiv.org/abs/1701.06538).
> 路线 `2.2.1`. 这项工作把 MoE 从 1991 年的集成学习概念改造成可插入深度网络的通用层. 接着阅读 `2.2.2` [Switch Transformer](3.2.2-switch-transformer.md),可以看到 top-1 路由怎样进一步简化训练并进入 Transformer 预训练.

**全文符号表**

论文公式不多, 但门控和负载均衡的记号容易混, 先一次登记.

| 符号 | 含义 |
|------|------|
| $x$ | MoE 层的输入, 一个位置 (时间步) 上的隐状态向量, 论文里维度是 512 或 1024 |
| $n$ | 专家总数, 从 4 到 131072 |
| $k$ | 每个输入实际激活的专家数, 论文取 2 或 4 |
| $E_i(x)$ | 第 $i$ 个专家的输出. 专家是一层隐层的 ReLU 前馈网络, 各有独立参数 |
| $G(x)$ | 门控网络输出, 一个 $n$ 维向量, 只有 $k$ 个分量非零 |
| $W_g$ | 门控权重, 把 $x$ 映成 $n$ 个专家的打分 |
| $W_{noise}$ | 噪声权重, 决定每个专家打分上加多大的高斯噪声 |
| $H(x)$ | 加噪之后, 截断之前的门控打分 |
| $\text{KeepTopK}(v, k)$ | 保留 $v$ 里最大的 $k$ 个分量, 其余置为 $-\infty$ |
| $\text{Softplus}(z)$ | $\log(1 + e^z)$, 一个恒正的平滑函数, 这里用来保证噪声标准差为正 |
| $X$ | 一个训练 batch 的输入集合 |
| $CV(\cdot)$ | 变异系数 (coefficient of variation), 标准差除以均值, 衡量一组数有多不均匀 |
| $\Phi$ | 标准正态分布的累积分布函数 |
| $w_{importance}$, $w_{load}$ | 两个辅助损失的手调系数 |

**读公式的方法.** 全文公式分两组. 第一组回答「每个位置交给谁算」: 打分, 加噪, 截断到 top-k, 再 softmax, 顺着 $H(x) \to \text{KeepTopK} \to G(x)$ 读. 第二组回答「怎么防止大家都交给同一个人」: 先把每个专家在 batch 里分到的量加总, 再用 $CV^2$ 惩罚不均匀. 读第二组时盯住一件事: 被选中的次数是离散的, 不可导, 论文所有的绕路都是为了造一个可导的替身.

## 背景: 容量和计算被绑在一起

模型容量受参数量限制, 这句话在 2016 年已经是常识. 语言模型和翻译模型越大越好, 数据集 (互联网语料) 又远远没被吃干净. 真正的约束来自计算成本.

稠密模型里每个样本都要过一遍全部参数. 模型变大, 训练数据也跟着变多, 论文的说法是训练成本大约按平方膨胀. 算力增长追不上这个速度.

条件计算 (conditional computation) 是早就提出的解法: 每个样本只激活网络的一部分, 容量可以涨, 单样本计算不跟着涨. Bengio 组 2013 和 2015 年, Davis 和 Arel 2013 年, Cho 和 Bengio 2014 年都做过. 门控可以是二值的或连续稀疏的, 可以用 REINFORCE 训, 也可以用反向传播训. 理论上都很漂亮.

论文第一节的判断很不客气: 到 2016 年为止, 没有任何一篇工作在模型容量, 训练时间或模型质量上展示出大幅提升. 条件计算停在「理论上可行」快四年了.

MoE 本身更老. Jacobs, Jordan, Nowlan 和 Hinton 1991 年的 Adaptive Mixtures of Local Experts, 一个门控网络加若干专家, 门控决定每个样本听谁的. 那时候 MoE 是整个模型. Eigen, Ranzato 和 Sutskever 2013 年第一次把多个 MoE 叠进深度网络当中间层, 并在结论里提了一句稀疏化的潜力. Hinton 同时出现在 1991 年那篇和这篇的作者名单里, 中间隔了 26 年.

这篇论文做的事, 是把「中间层 MoE」和「稀疏门控」两个想法接起来, 然后把挡路的工程问题一个一个拆掉.

### 条件计算为什么一直没成: 五个工程障碍

论文把失败原因列得很具体, 这份清单比方法本身更值得看.

第一, GPU 擅长算术, 不擅长分支. 条件计算天然是分支, 所以只能整块整块地开关网络, 粒度越粗越浪费.

第二, 大 batch 是性能的命根子, 用来摊薄参数搬运和更新的开销. 条件计算让每个被激活的子网络只分到一小部分样本, batch 被切碎了.

第三, 网络带宽. 一个 GPU 集群的算力可以是设备间总带宽的几千倍. 算法的「计算量/通信量」比必须高过这个比值, 否则 GPU 在等网络. 论文顺手点了 embedding 层: 它也是一种条件计算, 但因为要跨网络传, 交互数被带宽卡死.

第四, 可能需要额外的损失项来控制稀疏度和负载, Bengio 等人 2015 年用了三个. 这些项同时影响模型质量和负载均衡.

第五, 容量只在超大数据集上才关键. 之前的条件计算工作用的是最多 60 万张图的图像分类数据, 这些标签不可能喂饱几十亿参数.

这五条里, 前三条是硬件问题, 第四条是优化问题, 第五条是实验设计问题. 论文的方案逐条对应, 所以它读起来更像一份系统论文, 不像一篇算法论文.

### MoE 层的结构

一个 MoE 层由 $n$ 个专家和一个门控网络组成. 输出是专家输出的加权和:

$$y = \sum_{i=1}^{n} G(x)_i E_i(x)$$

求和遍历全部 $n$ 个专家, 但只要 $G(x)_i = 0$, 对应的 $E_i(x)$ 就根本不用算. 省计算的全部来源就是 $G(x)$ 的稀疏性. 论文里专家多达数千个, 每个样本只算其中几个.

专家本身很朴素: 一层隐层的 ReLU 前馈网络, 结构相同, 参数独立. 语言模型实验里每个专家是 512 → 1024 → 512, 约 100 万参数.

专家数很大时还有一个层次化版本: 一级门控先挑几组, 每组内部再有二级门控挑专家. 这相当于把一个 $n$ 路分支拆成两个 $\sqrt{n}$ 量级的分支, 后面 4096 个以上专家的模型都是这种结构.

## Noisy Top-K 门控

最朴素的门控是 softmax: $G_\sigma(x) = \text{Softmax}(x \cdot W_g)$. 它不稀疏, 每个专家都有非零权重, 等于每个专家都要算.

论文在 softmax 之前加了两样东西: 噪声和截断.

$$H(x)_i = (x \cdot W_g)_i + \text{StandardNormal}() \cdot \text{Softplus}\big((x \cdot W_{noise})_i\big)$$

第一项是正常的门控打分. 第二项是噪声: 标准正态采样乘上一个由输入决定的幅度, $\text{Softplus}$ 保证幅度恒正. 噪声幅度也是可学习的, 由 $W_{noise}$ 控制, 每个专家, 每个输入各不相同.

$$G(x) = \text{Softmax}\big(\text{KeepTopK}(H(x), k)\big)$$

$\text{KeepTopK}$ 只留最大的 $k$ 个打分, 其余置为 $-\infty$, 过 softmax 之后恰好变成 0. 被留下的 $k$ 个分量重新归一化, 权重和为 1.

代入一组数. $n = 4$, $k = 2$, 推理时不加噪声, 打分 $x \cdot W_g = (2.0, 1.0, 0.5, -1.0)$. 截断后是 $(2.0, 1.0, -\infty, -\infty)$. softmax: $e^{2} = 7.389$, $e^{1} = 2.718$, 和为 10.107, 门控值 $(0.731, 0.269, 0, 0)$. 输出 $y = 0.731 E_1(x) + 0.269 E_2(x)$, 专家 3 和 4 一次都不用算.

训练时噪声打开, 第 3 个专家的 0.5 分就有机会挤进前二. 这就是噪声的第一个作用: 让门控偶尔尝试别的专家, 避免选择过早固定. 第二个作用在第 7 节, 它让「被选中的概率」变成了一个可导的量.

还有一个细节决定了 $k$ 的取值. $k > 1$ 时, 被选中的 $k$ 个门控值对 $W_g$ 有非零梯度, 因为 softmax 在它们之间分配权重, 改动打分会改变分配比例. 论文据此认为至少要比较两个专家, 路由才学得动. 这个判断四年后被 Switch Transformer 推翻.

门控整体用反向传播训练, 和 Bengio 2015 用布尔门加 REINFORCE 的做法不同. top-k 截断在数学上是不连续的, 论文原话是「理论上吓人的不连续」, 但实践中没观察到问题.

### Batch 缩水问题: 数据并行和模型并行混着用

第二个工程障碍在这里变成一行算式. batch 大小为 $b$, 每个样本挑 $n$ 个专家里的 $k$ 个, 每个专家平均只分到

$$\frac{kb}{n} \ll b$$

个样本. 专家越多, 每个专家的 batch 越小, GPU 越空.

论文的解法是让数据并行和模型并行共用同一批设备. 普通层和门控网络按数据并行复制到 $d$ 台设备上, 每台处理自己的 batch; 专家只存一份, 分散在这些设备上, 每个专家收集所有设备上路由给它的样本. 这样每个专家的 batch 变成

$$\frac{kbd}{n}$$

多了一个 $d$ 倍. 设备数和专家数一起涨, 每个专家的 batch 就保持不变, 每台设备的显存, 带宽和步长也保持不变. 论文在这里写了一句野心: 目标是在万亿词语料上训练万亿参数模型, 写论文时还没做到, 但加硬件应该可以.

第二个技巧是利用卷积性. MoE 在每个时间步上用的是同一套专家, 所以可以等下面那层 LSTM 把所有时间步算完, 再把全部时间步拼成一个大 batch 送进 MoE. batch 又放大了一个「展开步数」倍.

代入语言模型实验的数字. 16 张 K40, 每个 batch 约 30 万个词. MoE-256 有 256 个专家, 每个位置挑 4 个, 每个专家每步分到约 $4 \times 300000 / 256 \approx 4700$ 个样本. 对一个 512 → 1024 → 512 的小网络, 这个 batch 已经足够把 GPU 喂饱.

论文也承认一个做不到的方向: 把 MoE 用在循环内部, 比如替换 LSTM 的权重矩阵. 那样每一步的输入依赖上一步的输出, 卷积性技巧失效. 它只在展望里提了一句.

### 带宽: 让专家的计算量压过通信量

专家是固定在设备上的, 门控参数又很少, 所以主要通信是把专家的输入和输出在网络上搬来搬去. 为了让 GPU 不等网络, 专家的「计算量 / 输入输出大小」要高于设备的「算力 / 带宽」比, 对 GPU 来说是上千比一.

一个一层隐层的专家, 两个权重矩阵是 $d_{in} \times d_{hidden}$ 和 $d_{hidden} \times d_{out}$. 计算量和输入输出大小之比, 恰好等于隐层宽度. 512 → 1024 → 512 的专家, 每个 token 做约 100 万次乘加, 只搬 1024 个数, 比值 1024.

这意味着提高通信效率的方法简单到有点滑稽: 把专家的隐层做宽, 或者多加几层. 论文实验里专家隐层都是上千维, 翻译模型用 2048, 高预算语言模型用到 8192.

## 负载均衡: 两个 CV² 辅助损失

门控网络有一个自我强化的坏习惯: 某几个专家早期被选得多, 训练得快, 于是被选得更多. 最终门控收敛到永远只给同几个专家大权重. Eigen 2013 年见过同样的现象, 用训练初期的硬约束压; Bengio 2015 年对每个门的 batch 平均值加了软约束.

论文走软约束, 但拆成了两个损失.

第一个管「重要性」. 专家的 importance 定义为它在一个 batch 里拿到的门控值之和:

$$\text{Importance}(X) = \sum_{x \in X} G(x)$$

$$L_{importance}(X) = w_{importance} \cdot CV\big(\text{Importance}(X)\big)^2$$

$\text{Importance}(X)$ 是一个 $n$ 维向量, 每个分量是一个专家的总权重. $CV$ 是标准差除以均值, 平方之后乘上手调系数. 所有专家总权重相等时 $CV = 0$, 损失为零.

算一个极端情况. 4 个专家, batch 里 4 个样本全部权重给了专家 1, importance 是 $(4, 0, 0, 0)$. 均值 1, 总体标准差 $\sqrt{(9 + 1 + 1 + 1)/4} = \sqrt{3} = 1.732$, $CV^2 = 3$. 完全均匀时是 $(1, 1, 1, 1)$, $CV^2 = 0$. 损失在这两端之间平滑变化, 可以直接求梯度.

但 importance 均衡不等于负载均衡. 一个专家可能收到少数几个大权重样本, 另一个收到大量小权重样本, 两者 importance 相同, 实际处理的样本数差很多. 分布式硬件上这会导致显存溢出和掉速.

第二个损失管「负载」, 也就是每个专家实际收到多少样本. 样本数是离散的, 不能反向传播. 论文在这里用上了噪声: 定义 $P(x, i)$ 为「重新采样专家 $i$ 的噪声, 其余分量的噪声保持不变时, $G(x)_i$ 非零的概率」.

$$P(x, i) = \Phi\left(\frac{(x \cdot W_g)_i - \text{kth\_excluding}(H(x), k, i)}{\text{Softplus}\big((x \cdot W_{noise})_i\big)}\right)$$

分子是专家 $i$ 的干净打分, 减去「除它之外第 $k$ 大的加噪打分」, 也就是它要挤进前 $k$ 名必须越过的门槛. 分母是它自己的噪声标准差. 整个比值是「差多少个标准差才能入选」, 过一遍 $\Phi$ 就变成概率.

接着第 4 节的数字. 假设其余专家的噪声已经采样好, 打分恰好还是 $(2.0, 1.0, \cdot, -1.0)$, 专家 3 的噪声标准差是 1. 除专家 3 之外第 2 大的打分是 1.0, 于是 $P(x, 3) = \Phi((0.5 - 1.0)/1) = \Phi(-0.5) = 0.309$. 专家 3 有约 31% 的概率被选中, 这个数对 $W_g$ 和 $W_{noise}$ 都可导.

$$\text{Load}(X)_i = \sum_{x \in X} P(x, i), \qquad L_{load}(X) = w_{load} \cdot CV\big(\text{Load}(X)\big)^2$$

把每个样本的入选概率加起来, 就是专家 $i$ 的期望负载, 再套一次 $CV^2$. 不可导的计数被换成了可导的期望, 这是全文最巧的一步.

为了避免训练一开始就显存溢出, 论文把 $W_g$ 和 $W_{noise}$ 都初始化为全零: 没有信号, 只有噪声, 起点就是近似均匀.

附录 A 的消融把两个损失的作用摆得很清楚. 固定 MoE-256 训 10 个 epoch:

| $w_{importance}$ | $w_{load}$ | 测试困惑度 | $CV(\text{Importance})$ | $CV(\text{Load})$ | 最忙专家 / 平均负载 |
|---|---|---|---|---|---|
| 0.0 | 0.0 | 39.8 | 3.04 | 3.01 | 17.80 |
| 0.2 | 0.0 | 35.6 | 0.06 | 0.17 | 1.47 |
| 0.0 | 0.2 | 35.7 | 0.22 | 0.04 | 1.15 |
| 0.1 | 0.1 | 35.6 | 0.06 | 0.05 | 1.14 |
| 1.0 | 1.0 | 35.7 | 0.03 | 0.02 | 1.07 |

不加任何辅助损失, 最忙的专家扛了平均负载的 17.8 倍, 困惑度 39.8. 只要加上任意一个, 困惑度就回到 35.6 左右. 两个损失对质量的影响几乎一样, 区别在负载: 加了 $w_{load}$ 的配置, 最忙专家的超载倍数明显更低. 语言模型实验最终用 0.1 和 0.1, 翻译实验用 0.01 和 0.01.

### 实验一: 10 亿词语言模型

数据是 1B Word Benchmark: 约 8.29 亿词, 词表 793471. 模型是两层 LSTM 中间夹一个 MoE 层, 残差连接, MoE 输出过 sigmoid 再 dropout.

第一组实验固定计算量, 只加容量. 所有模型每个时间步前向约 800 万次乘加 (不算 softmax): 两层 LSTM 各 200 万, MoE 层 4 个激活专家各 100 万. 专家数从 4 到 4096 变化.

| 模型 | 10 epoch 测试困惑度 | 每步计算 (百万乘加) | 参数 (不含 embedding 与 softmax, 百万) |
|---|---|---|---|
| MoE-4 (4 个专家全开, 不稀疏) | 45.0 | 8.4 | 8.4 |
| MoE-32 | 39.7 | 8.4 | 37.8 |
| MoE-256 | 35.7 | 8.6 | 272.9 |
| MoE-1024-h | 34.6 | 8.5 | 1079.0 |
| MoE-4096-h | 34.1 | 8.9 | 4303.4 |

计算量几乎不动, 参数涨了 500 倍, 困惑度从 45.0 降到 34.1, 低 24%. 专家全开的 MoE-4 和同计算量的稠密基线打平, 这说明收益全部来自稀疏带来的容量, 不是 MoE 结构本身.

第二组实验和此前最好的结果比. Jozefowicz 等人 2016 年的 2xLSTM-8192-1024, 1.51 亿参数, 每步 1.51 亿次乘加, 32 张 K40 训 59 小时, 10 epoch 困惑度 34.7.

低预算 MoE 模型 (就是上面的 MoE-4096-h) 每步 890 万次乘加, 16 张 K40 训 15 小时, 困惑度 34.1. 同样 10 个 epoch, 计算量只有对手的 6%, 结果略好.

高预算 MoE 模型每步 1.427 亿次乘加, 和对手的计算量相当, 32 张 K40 训 47 小时, 困惑度 28.0, 比 34.7 低 18%. 大 MoE 在场的情况下, 多给计算仍然有用.

硬件效率也要看. K40 标称峰值 4.29 TFLOPS. 稠密基线跑到 1.07 到 1.29 TFLOPS/GPU, 低计算 MoE 模型 0.74 到 0.90, 最高预算的 MoE 因为矩阵更大反而跑到 1.56. 稀疏门控确实损失了一些效率, 但远不到「白给容量却跑不动」的程度. 摘要里「只有少量计算效率损失」这句话, 说的就是这组数.

### 实验二: 1000 亿词和 137B 参数

1B Word 上有一个现象: MoE 层参数超过 10 亿之后收益开始递减. 论文的假设是数据不够大. 于是换成 Google 内部新闻语料, 去重打乱后约 1000 亿词, 同样固定每步约 800 万次乘加, 专家数从 32 一路加到 131072.

| 模型 | 1 epoch 测试困惑度 | MoE 层参数 (百万) | 总参数 (十亿) | TFLOPS/GPU |
|---|---|---|---|---|
| 4xLSTM-512 (稠密基线) | 47.0 | 8.4 | 0.1 | 1.23 |
| MoE-32 | 40.4 | 37.8 | 0.1 | 0.83 |
| MoE-4096-h | 30.9 | 4303.4 | 4.4 | 1.07 |
| MoE-16384-h | 29.7 | 17201.0 | 17.3 | 0.96 |
| MoE-65536-h | 28.9 | 68791.0 | 68.9 | 0.72 |
| MoE-131072-h | 29.2 | 137577.6 | 137.7 | 0.30 |

65536 个专家, 680 亿参数时效果最好, 困惑度比同计算量的稠密基线低 39%. 此时层稀疏度 99.994%, 每个位置只用万分之一不到的专家, 效率仍有 0.72 TFLOPS/GPU.

131072 个专家, 1377 亿参数时反而退步到 29.2, 效率掉到 0.30. 论文给了两个解释: 稀疏过头; 以及为了和其他模型对齐, 没有随 GPU 数等比加大 batch. 标题里「outrageously large」的 137B 就是这个模型, 它是规模的上限演示, 不是最好的模型.

训练 10 亿参数一张卡, 论文用了两个省显存的办法. 一是专家隐层的激活不存, 反向时重算. 二是改优化器: Adam 的一阶矩直接关掉 ($\beta_1 = 0$), 二阶矩不存完整矩阵, 只存行均值和列均值, 用外积近似还原. 这个分解二阶矩的做法, 一年后被 Shazeer 和 Stern 写成了 Adafactor.

10 亿词和 1000 亿词两条曲线的差距随容量拉大. 容量在大数据上更值钱, 这和第 2 节第五条障碍对上了.

### 实验三: 机器翻译

翻译模型基于 GNMT, 为了省计算把编码器 LSTM 从 9 层减到 3 层, 解码器从 8 层减到 2 层. MoE 层插在编码器第 2, 3 层之间和解码器第 1, 2 层之间, 最多 2048 个专家, 每个约 200 万参数, 共增加约 80 亿参数. 单语言对模型用的是附录 F 的严格均衡门控, 原因是当时基础设施上每个专家 batch 完全相等时跑得更快.

WMT'14 newstest2014 的结果:

| 任务 | MoE (2048 专家) | GNMT | GNMT+RL | MoE 每步计算 | GNMT 每步计算 |
|---|---|---|---|---|---|
| 英 → 法 BLEU | 40.56 | 39.22 | 39.92 | 8500 万 | 2.14 亿 |
| 英 → 德 BLEU | 26.03 | 24.91 | 24.66 | 8500 万 | 2.14 亿 |

MoE 没用强化学习微调, 相对不带 RL 的 GNMT 分别高 1.34 和 1.12 BLEU, 每步计算不到对方的一半. 英法那组 MoE 用 64 张 K40 训 6 天, GNMT 用 96 张 K80 训 6 天. Google 内部英法生产数据上, MoE 只训了 GNMT 六分之一的时间, 测试 BLEU 仍高 1.01.

多语言实验更有意思. Johnson 等人 2016 年用一个 GNMT 同时训 12 个语言对, 效果比 12 个单独模型差, 这很正常: 12 个模型合计有 12 倍容量. 论文用同样数据, 同样约 30 亿句对的训练量, 换成一个 87 亿参数的 MoE 模型.

结果是开发集困惑度从多语言 GNMT 的 4.14 降到 3.35, 低 19%. BLEU 上 12 个语言对赢了 11 个, 最多高 5.84 (韩 → 英), 还在 8 个语言对上超过了单语言对的 GNMT. 唯一输的是英 → 韩, 低 1.79, 论文归因于稀有语言对的少量真实样本被过度过采样, 训过头了. MoE 模型每步计算 1.02 亿次乘加, 多语言 GNMT 是 2.12 亿.

专家确实分了工. 编码器里第 752 号专家专门处理动词短语中引出宾语的不定冠词 a, 上下文是「plays a core」「plays a critical」「play a leading」「assume a leadership」这类表示重要性或领导角色的搭配. 第 2004 号专家则集中在「rapidly growing」「swiftly」「the fastest」这类表示速度的词. 没有任何人告诉它们该管什么.

## 局限: 这套配方仍未解决的问题

MoE 不是万能的. 这篇论文的局限大多写在它自己的实验里.

第一, 稀疏度有上限. 131072 个专家时质量和效率同时下滑, 专家越多不一定越好, 边界在哪由数据量和 batch 大小共同决定.

第二,负载均衡依赖任务级调参.$w_{importance}$ 和 $w_{load}$ 在语言模型和翻译上相差 10 倍,可见同一组系数无法直接跨任务复用.附录 F 的严格均衡门控在推理时还要额外学习一组阈值,近似训练时的 batch 级掩码,因此训练和推理的路由行为并不完全一致.

第三, 显存不省. 计算和容量解耦了, 但所有专家的参数都得驻留在某台设备上. 1377 亿参数要 128 张 GPU 才装得下.

第四, 通信模式重. 专家分布在不同设备上, 每个 MoE 层都要把 token 发出去再收回来, 后来叫 all-to-all. 论文在 LSTM 时代靠「专家做宽」勉强压住了通信比, 换到 Transformer 这种层数多, 每层都想放 MoE 的架构, 通信会成为主瓶颈.

第五, 只做了层间 MoE. MoE 夹在 LSTM 层之间, 卷积式地作用于每个时间步. 放进循环内部的版本论文只提了设想.

第六, $k > 1$ 是个没被检验的假设. 论文认为至少比较两个专家才能学会路由, 所以取 $k = 4$ 或 $k = 2$. Switch Transformer 四年后证明 $k = 1$ 也行, 而且更快.

### 后续: 从 LSTM 夹层到 LLM 标配

这篇论文之后, MoE 沉寂了三年. 2020 年的 GShard 把 top-2 MoE 放进 Transformer 的每隔一层 FFN, 做到 6000 亿参数的多语言翻译模型, 同时解决了自动分片的工程问题.

2021 年路线 `2.2.2` Switch Transformer 把路由简化成 top-1, 把两个辅助损失合并成一个, 用选择性精度解决 bf16 下的不稳定, 做到 1.6 万亿参数. 同年 GLaM 用 64 专家 top-2 做到 1.2 万亿参数.

2023 年底的 Mixtral 8x7B 是开源社区第一个被广泛使用的 MoE 模型, 8 个专家选 2 个, 总参数约 470 亿, 每个 token 激活约 130 亿. 2024 年 DeepSeekMoE 把专家切得更细, 再加共享专家; DeepSeek-V3 进一步把负载均衡主要交给每个专家一个可调的偏置项, 辅助损失只留一个很小的序列级兜底.

十年过去, 门控从 noisy top-k 变成了各种变体, 辅助损失从两个变成一个再压到几乎为零, 但骨架没变: 一个路由器决定每个 token 交给谁, 一个机制防止大家都交给同一个人. 这两件事第一次被同时写清楚, 就在这篇论文里.

### 从稀疏门控到预训练 MoE

这项工作第一步证明稀疏激活可以在大规模语言模型中稳定训练.路线 `2.2.2` [Switch Transformer](3.2.2-switch-transformer.md) 随后把问题推进到更简单的路由和 Transformer 预训练.两篇连读,可以看到条件计算从 LSTM 层间模块演化为万亿参数模型的主干组件.

往前看, 它的底座是路线 `1.3.2` [LSTM](../../2-sutskever阅读清单/2.3-rnn与序列建模/2.3.2-understanding-lstm.md): MoE 层就夹在两层 LSTM 中间. 它的并行思路和路线 `1.6.2` [GPipe](../../2-sutskever阅读清单/2.6-训练规模与生成/2.6.2-gpipe/2.6.2-gpipe.md) 是两条互补的路: GPipe 把模型按层切开, MoE 把一层按专家切开. 路线 `1.6.4` [Scaling Laws](../../2-sutskever阅读清单/2.6-训练规模与生成/2.6.4-scaling-laws/2.6.4-scaling-laws.md) 说参数量是性能的主轴, 这篇论文提前三年给出了另一个答案: 参数量可以不跟着计算量一起涨.

这篇论文示范了一种做法. 它没有发明新的数学, noisy gating, CV 损失, 混合并行, 每一项单看都不复杂. 它的贡献是先把失败原因列成清单, 再一条一条对着拆, 最终用 1000 亿词的数据证明拆完之后真的有收益. 条件计算喊了四年的口号, 最终是被工程兑现的.
