# 临界批量：样本效率、并行效率与梯度噪声

把数据并行卡数翻倍，再把全局 batch 一起翻倍，训练时间会不会减半？在 batch 较小时，答案往往接近「会」：每一步看更多样本以后，随机梯度更稳定，达到同一损失所需的更新步数随之下降。可 batch 增大到某个区域后，继续增加样本只能让本来已经足够准确的梯度估计再精确一点，更新步数却不再等比例减少。设备仍在做更多计算，优化进度没有同步增长。

这个转折区域通常称为**临界批量**（critical batch size）。它连接了两个常被分开讨论的问题：优化器每次更新需要多少统计信息，以及训练系统能否用更多设备缩短墙钟时间。临界批量并非模型配置表里一个固定常数，也不等于「显存能装下的最大 batch」。它取决于参数所在位置、数据分布、损失函数、优化器和我们采用的效率口径，训练过程中还会移动。

## 1. 先把三个 batch 分开

训练日志中的 batch 至少有三种口径。**micro batch** 是一次前向、反向真正送入单张设备的样本或 token；**gradient accumulation steps** 表示累积多少次梯度后才更新参数；**global batch** 是所有数据并行副本在一次优化器更新中共同处理的总量。若有 $R$ 个数据并行副本，每个副本的 micro batch 为 $b$，累积 $A$ 次，则

$$
B=RAb.
$$

语言模型样本长度不同时，用序列条数描述 batch 容易失真。两批各有 1024 条序列，一批长度 256，另一批长度 4096，计算量和参与损失的 token 数差了十六倍。因此预训练更常用 **tokens per update**。若采用 packing，还要说明填充 token 是否计入，loss mask 后的有效 token 才决定梯度统计量。

增大 micro batch 可能提升矩阵乘的尺寸和设备利用率；增大累积次数不会增加数据并行通信量，却会延长两次参数更新之间的计算；增加数据并行副本可以缩短一次更新的墙钟时间，但会引入梯度同步。这三种做法都能得到同一个 $B$，系统表现却不同。临界批量讨论的是优化层面的全局统计规模，具体怎样拼出这个规模属于系统设计。

## 2. 随机梯度里有什么

设单个训练样本 $z$ 对参数 $\theta$ 的梯度为

$$
g(z)=\nabla_\theta \ell(\theta;z).
$$

从当前数据分布取期望，得到总体梯度

$$
G=\mathbb E_z[g(z)].
$$

实际训练无法在每一步遍历全部数据，只能抽取 $B$ 个样本求平均：

$$
\hat G_B=\frac{1}{B}\sum_{i=1}^{B}g(z_i).
$$

在独立同分布这一简化条件下，$\hat G_B$ 是 $G$ 的无偏估计。若单样本梯度协方差为

$$
\Sigma=\mathbb E[(g-G)(g-G)^\top],
$$

那么批梯度的协方差为

$$
\operatorname{Cov}(\hat G_B)=\frac{\Sigma}{B}.
$$

这条式子给出了增大 batch 最直接的收益：batch 翻倍，估计方差减半，标准差按 $1/\sqrt B$ 缩小。可是方差变小并不自动等于训练速度按相同比例提高。参数更新还受曲率、学习率、动量和不同方向上的噪声影响。临界批量正是从「多看样本可以改善梯度」走向「改善已经不值额外样本」的转折。

一个常用的标量概括是简单噪声尺度

$$
\mathcal B_{\text{simple}}=\frac{\operatorname{tr}(\Sigma)}{\lVert G\rVert_2^2}.
$$

分子汇总单样本梯度在各方向上的方差，分母表示平均梯度信号的平方。当 $B\ll \mathcal B_{\text{simple}}$ 时，采样噪声相对强；增加 batch 能明显改善方向估计。当 $B\gg \mathcal B_{\text{simple}}$ 时，均值梯度已经主导，再多取样本的边际收益较小。

这个比值很有直觉，但它忽略了损失面的各向异性。在陡峭方向上，同样大小的误差可能比平坦方向危险得多。二阶近似下，更贴近优化进展的噪声尺度会把 Hessian $H$ 纳入：

$$
\mathcal B_{\text{noise}}
=\frac{\operatorname{tr}(H\Sigma)}{G^\top HG}.
$$

这里的分子衡量噪声在曲率加权后的代价，分母衡量真实梯度在相同局部几何下产生的变化。实际大模型无法显式构造完整 Hessian，因此工程分析常使用可估计的代理量，或者直接从不同 batch 的训练曲线拟合临界区域。噪声尺度提供解释，最终决策仍需实验验证。

## 3. 一条可跟算的效率曲线

为了看清拐点，可以采用一个近似模型。设使用无限大 batch 时，达到目标损失至少需要 $S_\infty$ 次更新；有限 batch 带来的额外随机性使所需步数变为

$$
S(B)\approx S_\infty\left(1+\frac{B_{\text{crit}}}{B}\right).
$$

当 $B\ll B_{\text{crit}}$，有

$$
S(B)\approx S_\infty\frac{B_{\text{crit}}}{B}.
$$

此时 batch 翻倍，步数近似减半。达到目标损失所处理的样本数为

$$
E(B)=B S(B)\approx S_\infty(B+B_{\text{crit}}).
$$

在小 batch 区间，$E(B)$ 接近常数 $S_\infty B_{\text{crit}}$，所以可以用更大的并行批量换取更少更新，而样本效率损失不大。当 $B\gg B_{\text{crit}}$，$S(B)$ 逐渐逼近 $S_\infty$，但 $E(B)$ 近似随 $B$ 线性增长。每一步多处理的数据不能再换来足够的步数减少。

假设 $S_\infty=10{,}000$，$B_{\text{crit}}=1024$。取 $B=128$ 时，模型预测需要 $90{,}000$ 步，共处理约 $11.52$M 个样本；取 $B=1024$ 时需要 $20{,}000$ 步，共处理约 $20.48$M 个样本；取 $B=8192$ 时仍需 $11{,}250$ 步，却要处理约 $92.16$M 个样本。第三种配置的更新次数已接近下限，样本开销却大幅增加。

这只是帮助理解的经验形式，不能拿来代替真实曲线。不同优化器和学习率规则会改变函数形状，目标损失选得不同也会给出不同的拐点。它揭示的核心关系是：小 batch 区间受随机梯度统计限制，大 batch 区间受可取得的优化更新次数限制。

## 4. 样本效率、计算效率与时间效率

「效率」若不注明口径，很容易把相反结论写到一起。

**样本效率**关注达到目标损失需要处理多少 token。越过临界批量后，处理的 token 增长更快，样本效率下降。**计算效率**还要考虑每个 token 的 FLOPs、重计算、padding 和通信。如果两个方案处理 token 数相同，但一个因张量形状更整齐而更容易命中高效 kernel，它的实际计算成本仍可能更低。**墙钟效率**关注总训练时间，取决于每一步耗时与步数的乘积：

$$
T(B)=S(B)t_{\text{step}}(B).
$$

若增加数据并行设备后每步时间几乎不变，而所需步数下降，那么墙钟时间会缩短。实际通信、负载不均、输入流水线和小矩阵利用率会让 $t_{\text{step}}$ 改变。即使 $B$ 略高于临界值，只要额外设备能够显著提高吞吐，训练时间仍可能下降；代价是消耗更多总计算。反过来，若设备数量固定，仅靠梯度累积增大全局 batch，每步时间大致随累积次数增长，通常无法获得同样的时间收益。

训练团队还会受到最长运行窗口、集群稳定性和学习率日程的约束。一次更新越久，单次故障损失的工作越多；更新总数太少，warmup、衰减和 checkpoint 频率的离散粒度也会变粗。因此「最大化 tokens/s」并不是完整目标。合理配置需要同时报告 tokens/s、模型 FLOPs 利用率、达到某一验证损失的 token 数以及墙钟时间。

## 5. 临界批量为什么会变化

噪声尺度包含 $G$ 和 $\Sigma$，参数一更新，两者都会变。训练早期平均梯度通常较强，较小 batch 已能提供有用方向；训练后期平均梯度减弱，样本之间的差异相对突出，估计同样精度的方向可能需要更多样本。许多任务中会观察到临界批量随损失下降而增长，但这是一种经验趋势，不能把它写成对所有阶段都成立的定律。

数据混合也会改变梯度方差。若一个 batch 同时包含代码、数学和多语言文本，不同域的梯度方向可能差异很大；调整采样比例以后，即使模型和损失相同，噪声尺度也会改变。序列 packing 会在一个序列容器中放入多个文档，token 虽然更多，却未必等同于同样数量的独立样本。重复样本、相邻切片和同源文档会提高相关性，使方差不再严格按 $1/B$ 下降。

优化器同样重要。动量会跨步平滑噪声，Adam 类方法按坐标缩放更新，梯度裁剪会改变大梯度样本的贡献。用原始梯度估计出的噪声尺度，未必直接对应预条件化更新的有效噪声。学习率也必须随 batch 一起调节：若只放大 batch 而保持原学习率，观察到的步数变化同时混入了超参数失配。

模型扩展后，梯度范数、曲率和数据难度都会变化。小模型测出的临界批量不能只按参数量线性外推到大模型。更稳妥的办法是在几个规模和训练阶段上做局部扫描，记录拐点如何随验证损失或训练进度移动，再为目标规模留出保守区间。

## 6. 如何从两种 batch 估计噪声

完整单样本梯度代价很高，但可以用两个独立子批量得到近似统计。设两个大小均为 $b$ 的子批量梯度为 $g_1,g_2$。它们的平均

$$
\bar g=\frac{g_1+g_2}{2}
$$

近似总体梯度；差值则反映采样噪声。因为两个估计独立且各自协方差约为 $\Sigma/b$，所以

$$
\mathbb E\lVert g_1-g_2\rVert^2
=\frac{2\operatorname{tr}(\Sigma)}{b}.
$$

于是可以用

$$
\widehat{\operatorname{tr}(\Sigma)}
=\frac{b}{2}\lVert g_1-g_2\rVert^2
$$

估计总方差，再除以 $\lVert\bar g\rVert^2$ 得到简单噪声尺度的近似值。单步估计波动很大，通常需要跨若干更新取平滑值；两个子批量还应使用相同参数状态，不能先用 $g_1$ 更新参数再计算 $g_2$。

另一种更直接的办法是固定模型、数据版本与目标损失，扫描若干全局 batch。每个 batch 都重新搜索合理学习率，在训练曲线上读取达到目标损失需要的步数和 token 数。若 batch 翻倍时步数接近减半，仍处在线性扩展区；若步数几乎不变，则已进入饱和区。用多个目标损失重复读取，还能看到临界批量怎样随训练进展变化。

实验至少要控制四件事。第一，所有配置处理相同的数据分布，避免数据顺序差异冒充 batch 效应。第二，比较验证损失而非只看训练损失，因为大 batch 可能改变泛化。第三，给不同 batch 足够的学习率调参空间。第四，报告随机种子方差；临界区域本来就是平滑转折，单次训练很难精确定位一个整数。

## 7. 学习率怎样随 batch 调整

小 batch 区间常见线性缩放规则：batch 放大 $k$ 倍，学习率也放大约 $k$ 倍。直觉是把原来 $k$ 次小批量更新合并成一次大批量更新，使参数位移尺度接近。这个近似要求相邻小步期间梯度场变化不大，并且常与更长 warmup 配合。batch 很大后，线性放大学习率容易碰到稳定性边界。

平方根缩放把学习率按 $\sqrt{k}$ 增长，强调保持随机更新方差的尺度。Adam 等自适应优化器还会受到二阶矩估计和偏置修正影响，没有一条规则可以跨模型直接套用。实际扫描可以从原学习率、平方根缩放和线性缩放三个锚点开始，观察早期 loss、梯度范数、更新范数以及溢出事件。

batch 改变以后，学习率日程的横轴也要明确。按 optimizer step 设置 warmup 时，batch 翻倍而 warmup 步数不变，warmup 期间处理的 token 也翻倍；按 token 设置则保持数据量一致。预训练报告若只写「warmup 2000 steps」而省去全局 batch，配置无法复现。

可以用更新比例辅助诊断：

$$
r=\frac{\lVert\Delta\theta\rVert_2}{\lVert\theta\rVert_2}.
$$

batch 放大后若 $r$ 急剧增大并伴随 loss 尖峰，学习率可能过高；若梯度方差已经明显降低而 $r$ 很小，训练可能受步长限制。这个指标应按层观察，总范数可能掩盖 embedding、归一化参数和主干矩阵之间的差别。

## 8. 动态增大 batch 的条件

既然临界批量可能随训练推进而增大，一个自然策略是从较小全局 batch 开始，随后分阶段提高。早期保留更多参数更新，后期利用更大的批量降低噪声并扩大数据并行。动态 batch 还可以减少早期为巨大批量准备的设备需求。

切换时需要共同调整学习率与日程。若 batch 从 4M token 跳到 8M token，每个 optimizer step 对应的数据量翻倍；继续按原 step 数衰减学习率，会改变整个 token 视角下的训练计划。比较稳妥的做法是以累计 token 为主时间轴，切换点前后检查 loss 是否连续，并监控梯度范数、更新范数和吞吐。

动态增长也有上限。全局 batch 已接近剩余训练 token 的显著比例时，更新次数会太少；数据并行组扩大还可能让通信占比上升。训练系统若主要受网络限制，增加副本带来的吞吐收益会先于优化拐点耗尽。此时应把设备用于张量并行、流水线并行或更多独立实验，而非继续扩大数据并行 batch。

## 9. 常见误判

第一种误判是把显存上限当作临界批量。显存决定 micro batch 能放多大，梯度累积却能把全局 batch 推得更高；优化拐点由梯度统计和训练目标决定。

第二种误判是只测单步吞吐。更大的 batch 常让 tokens/s 更漂亮，但达到同一损失可能处理更多 token。吞吐基准回答机器跑得多快，收敛曲线回答这些计算是否有效，两者必须放在一起。

第三种误判是固定学习率比较所有 batch。大 batch 的潜在优势可能被过小步长压住，也可能被过大的线性缩放破坏。每个候选 batch 至少要在合理范围内重新调学习率和 warmup。

第四种误判是把梯度累积与同步大 batch 视为完全相同。若中间没有参数更新且算子确定，两者产生的平均梯度可以很接近；BatchNorm 一类依赖批内统计的算子、随机层、数值累加顺序以及梯度裁剪位置都会造成差别。语言模型常用 LayerNorm 或 RMSNorm，减少了一项差异，但低精度累加和按 micro batch 裁剪仍需核查。

第五种误判是寻找唯一精确的 $B_{\text{crit}}$。真实曲线是缓慢弯折的，选择临界点需要阈值，例如并行效率降到理想线性的 80%，或者样本开销比小 batch 基线高出 20%。阈值不同，报告的数字自然不同。比一个孤立整数更有用的是给出拐点区间、训练阶段和测量口径。

## 10. 一份可执行的选择流程

先在单机或小集群上确定能高效运行的 micro batch，记录不同序列长度下的显存、tokens/s 和 kernel 利用率。随后用梯度累积构造若干全局 batch，例如按两倍递增；每档搜索学习率，并以累计 token 绘制训练与验证 loss。

接着选取多个损失水平，读取每档配置达到这些水平所需的 optimizer steps、token 数和墙钟时间。把步数相对最小 batch 的下降比例与 batch 增长比例对照，就能判断线性扩展还能维持到哪里。若有条件，再估计梯度噪声尺度，检查统计量给出的趋势是否与曲线一致。

确定候选区间后，把通信效率加入决策。测量 all-reduce 时间、输入流水线空闲、故障恢复成本和 checkpoint 周期，据此选择满足训练期限且总计算可接受的点。训练期间持续记录有效 token、全局 batch、学习率、梯度范数、更新范数、吞吐与非有限值事件；数据混合、序列长度或并行拓扑变化时重新评估。

## 11. Token 相关性会怎样改变有效批量

前面的 $1/B$ 方差缩减依赖样本近似独立。语言模型训练里的 token 显然存在相关性：同一句话中的相邻 token 共享上下文，同一文档的多个切片包含相似主题，从同一站点抓取的页面还可能重复模板。全局 batch 即使包含一百万 token，提供的独立信息也可能少得多。

用一个简单模型可以看出影响。设 $B$ 个标量梯度贡献具有相同方差 $\sigma^2$，任意两项的相关系数为 $\rho$，则均值的方差为

$$
\operatorname{Var}(\bar g)
=\frac{\sigma^2}{B}\bigl[1+(B-1)\rho\bigr].
$$

若 $\rho=0$，便恢复 $\sigma^2/B$。若 $\rho>0$，$B$ 增大后方差会趋近 $\rho\sigma^2$，无法继续按 $1/B$ 降低。把它写成独立样本数，可定义

$$
B_{\text{eff}}=\frac{B}{1+(B-1)\rho}.
$$

例如 $B=1024$ 且 $\rho=0.01$ 时，$B_{\text{eff}}\approx91$。这个等相关假设很粗糙，却清楚说明了去重、打散和跨域采样为何会影响临界批量：它们改变的除了数据质量，还有每次更新真正获得的独立梯度信息。

长序列训练尤其要谨慎。把序列长度从 2K 提到 8K，同时保持序列条数不变，token batch 增加四倍，但同一序列内 token 的相关结构也变了。若目标是比较优化统计，应同时报告序列数、有效 token 数、平均文档数与 packing 方式。只留下一个 global tokens 数字，后续很难解释拐点移动究竟来自 batch、上下文长度还是数据组成。

## 12. 目标损失决定你看到哪个拐点

临界批量总是相对于一段训练轨迹和一个观测目标定义。假设大 batch 在前一万步下降很快，却在后期泛化稍差；若目标损失设得较高，它看起来极具优势，目标设在训练末尾则可能结论相反。报告实验时可以选取早、中、晚三个验证损失水平，分别计算达到目标所需的 step、token 和时间，而不是只比较训练结束时的单点。

不同任务也可能给出不同临界区域。总体语言建模损失平滑下降时，代码或数学子集的损失可能具有更高方差；某个 batch 对总体 loss 已经饱和，对稀有领域却仍能从更多样本中受益。若训练目标明确包含多个能力域，应分别画出域内曲线，并检查数据采样是否让每个 batch 都包含足够的稀有样本。

训练预算还会改变选择。只训练很少 token 时，大 batch 导致 optimizer step 太少，优化器状态和学习率日程尚未进入稳定区；超长训练则允许逐步扩大 batch，并用更多阶段估计噪声。临界批量因此更适合写成随训练状态变化的函数 $B_{\text{crit}}(L)$ 或 $B_{\text{crit}}(t)$，而非贴在模型名称旁的一项永久属性。

## 13. 从实验记录还原一次决策

假设四档 token batch 为 1M、2M、4M、8M，达到指定验证损失分别需要 8000、4500、2800、2300 步。对应处理量为 8B、9B、11.2B、18.4B token。1M 增至 2M 时，步数下降接近一半，样本开销只增加 12.5%；4M 墧至 8M 时，步数仅下降约 18%，样本开销却增加约 64%。优化拐点大致落在 2M 到 4M 之间。

若系统测得四档每步时间分别为 2.0、2.1、2.2、2.3 秒，墙钟时间约为 4.44、2.63、1.71、1.47 小时。8M 仍是最快方案，但它用更多计算只换来约 14% 的额外时间缩短。集群紧张时可以选 4M，把设备让给数据消融或超参数实验；交付期限很紧时则可能接受 8M 的计算浪费。这类表格把价值判断显式留给预算和期限，避免用单一的「最优 batch」掩盖取舍。

临界批量描述的是**额外样本、额外设备和额外更新各自还能换来多少损失下降**。理解这层交换关系以后，大 batch 便成为连接优化动力学与训练系统的预算选择。
