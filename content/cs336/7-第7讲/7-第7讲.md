# 第7讲: 并行训练的状态分片与通信

单卡训练受显存容量和计算吞吐限制, 增加 GPU 后问题会转化为状态放在哪里、何时通信以及哪些计算能够重叠. 数据并行复制模型并切分 batch, 张量并行切分层内矩阵, 流水线并行切分层, 序列并行切分激活的 sequence 维. 每种策略减少的状态不同, 引入的 collective 与同步点也不同. 并行方案不能只用“用了多少卡”描述, 必须给出参数、梯度、优化器状态与激活的分布.

[主讲义](./7.1-主讲义/7.1-主讲义.md)从硬件连接层级、collective 到 3D parallelism 建立完整坐标。[Collective Communication](./7.2-Collective-Communication/7.2-Collective-Communication.md)给出 broadcast、reduce、all-gather、reduce-scatter 和 all-reduce 的语义与环形带宽成本。[Tensor Parallelism](./7.3-Tensor-Parallelism/7.3-Tensor-Parallelism.md)推导列并行、行并行、Attention/MLP 分片与序列并行。[ZeRO-3/FSDP](./7.4-ZeRO3-FSDP/7.4-ZeRO3-FSDP.md)跟踪分片参数的生命周期；[流水线并行](./7.6-流水线并行/7.6-流水线并行.md)与[Zero-Bubble PP](./7.5-Zero-Bubble-PP/7.5-Zero-Bubble-PP.md)研究 stage 划分和调度气泡。

## 1. Collective 是并行策略的基本操作

### 1.1 数据怎样在 rank 之间变化

broadcast 把一个 rank 的张量复制给所有 rank; reduce 把各 rank 数据聚合到一个目标; all-gather 收集各 rank 分片并在所有 rank 重建完整张量; reduce-scatter 先聚合再让各 rank 仅保留一片; all-reduce 让每个 rank 得到完整聚合结果. [Collective Communication](./7.2-Collective-Communication/7.2-Collective-Communication.md)给出关键恒等式: all-reduce 可由 reduce-scatter 加 all-gather 组成.

通信成本取决于消息字节、参与 rank 数、链路拓扑和算法. ring 算法把大消息分块传递, 总发送量可估算, 但真实系统还受节点内 NVLink、节点间网络、延迟与拥塞影响. 小消息更易受启动延迟限制, 大消息更接近带宽上限. 因而应按实际拓扑建立通信组, 让频繁通信尽量发生在更快链路上.

### 1.2 重叠依赖数据就绪时间

communication overlap 不是简单地异步调用 collective. 某个梯度 bucket 只有在反向计算完成后才能 reduce-scatter, 下一层参数必须在使用前 all-gather. 要产生重叠, 通信流与计算流之间需要正确事件依赖, bucket 大小也要兼顾带宽效率与尽早启动.

过大的 bucket 延迟通信开始, 过小则增加 collective 启动与调度成本. profile 应观察通信是否落在计算窗口内, 以及训练步尾部是否仍有无法隐藏的 exposed communication. **并行效率取决于关键路径上的未隐藏通信, 不取决于通信总字节一个数字.**

## 2. 数据并行与 ZeRO/FSDP

### 2.1 DDP 的复制成本

Distributed Data Parallel 让每个 rank 保存完整参数和优化器状态, 处理不同 microbatch, 反向时 all-reduce 梯度. 在理想情况下, global batch 随数据并行度扩大, 每 rank 计算独立; 但参数、梯度和 Adam 状态全部复制, 单卡容量不会因增加 rank 而改善.

global batch、microbatch 与 gradient accumulation 必须区分. 扩大数据并行度而保持每 rank batch 不变会改变 global batch, 进而影响优化超参数和收敛. 若固定 global batch, 每 rank 工作过少又可能降低 GPU 利用率. 数据并行度因此受有效 batch 上限约束.

### 2.2 ZeRO 的逐级分片

ZeRO Stage 1 分片优化器状态, Stage 2 继续分片梯度, Stage 3/FSDP 再分片参数. [ZeRO-3/FSDP](./7.4-ZeRO3-FSDP/7.4-ZeRO3-FSDP.md)描述参数生命周期: 某层前向前 all-gather 完整参数, 计算后释放非本地分片; 反向需要时再次收集, 梯度通过 reduce-scatter 归还各参数所有者.

FSDP 用通信换常驻显存. 参数收集形成临时峰值, prefetch 太早会同时驻留多层参数, 太晚则计算等待通信. backward 中参数 all-gather、梯度计算和 reduce-scatter 的顺序决定重叠空间. activation checkpointing 还能减少激活, 但增加重计算并改变通信窗口.

## 3. 层内与层间模型并行

### 3.1 张量并行

张量并行切分单层权重矩阵. Column parallel 可把输出特征分片, Row parallel 可把输入特征分片并在局部乘法后归约. Attention 的 head 天然可按 rank 切分, 但残差流或后续层在特定位置需要 all-reduce、reduce-scatter 或 all-gather. 每层多次通信使 TP 通常优先放在节点内高速互联上.

TP 降低单 rank 参数和部分激活, 但每 token 都参与层内 collective. batch 或 sequence 较短时, 局部矩阵变小, 计算效率也可能下降. 切分维度必须能被 TP degree 整除或有明确 padding. 比较方案时要写出每个线性层输入、局部权重、局部输出和 collective 后 shape.

### 3.2 流水线并行与气泡

[流水线并行](./7.6-流水线并行/7.6-流水线并行.md)把连续层分到多个 stage, stage 之间只传激活与梯度. 朴素调度中, 后续 stage 等待首批激活, 前面 stage 又会在尾部提前空闲, 形成 bubble. 把 batch 切成多个 microbatch 并采用 1F1B 调度可以让前向与反向交错, bubble 比例随 microbatch 数增加而下降.

microbatch 更多会增加调度复杂度, 还可能改变 kernel shape、通信频率和激活驻留. stage 划分应按实测时间而非层数平均, 否则最慢 stage 决定流水线周期. [Zero-Bubble PP](./7.5-Zero-Bubble-PP/7.5-Zero-Bubble-PP.md)进一步把反向拆成输入梯度与权重梯度计算, 利用依赖差异填充空闲窗口, 代价是更复杂调度、缓存和严格的时间匹配.

## 4. 激活与 3D 并行

参数分片后, 长序列和大 batch 的激活可能成为主要显存. sequence parallel 把某些逐 token 操作沿序列维分片, 在需要完整 hidden 或归约统计的位置通信. 它常与 TP 组合, 让 LayerNorm、dropout 和残差等部分不必在每个 TP rank 保存完整 sequence 激活.

大规模训练通常组合 DP/FSDP、TP 与 PP. TP 组放在高速节点内链路, PP 沿 stage 传相对较少的边界激活, DP 跨副本同步分片梯度. 并行度乘积等于总 rank 数, 但选择顺序受模型能否装入、global batch 上限、链路拓扑和 bubble 约束.

3D 配置由模型 shape、显存和网络拓扑共同决定。可以先用 FSDP 或 TP 满足容量，再用 PP 降低单 stage 层数，并以 DP 扩大吞吐；每一步都要用实测 step time、通信占比和峰值显存校正。checkpoint 格式、随机数状态和容错也必须与分片布局对应。

## 5. 阅读路线

先读[主讲义](./7.1-主讲义/7.1-主讲义.md)和[Collective Communication](./7.2-Collective-Communication/7.2-Collective-Communication.md), 熟悉各操作输入输出和 ring 成本. 然后阅读[ZeRO-3/FSDP](./7.4-ZeRO3-FSDP/7.4-ZeRO3-FSDP.md), 按前向与反向画出参数状态; 再进入[流水线并行](./7.6-流水线并行/7.6-流水线并行.md)和[Zero-Bubble PP](./7.5-Zero-Bubble-PP/7.5-Zero-Bubble-PP.md), 比较调度表与激活数量.

[Tensor Parallelism](./7.3-Tensor-Parallelism/7.3-Tensor-Parallelism.md)把单层矩阵拆到多个 rank，并逐项标出局部 shape 与 collective；第八讲再把 collective、数据并行、张量并行和流水线并行落到 PyTorch 代码。阅读本讲时，可以为每种方案列一张状态表：每个阶段、每个 rank 持有什么张量，发送什么，以及等待哪项依赖。

制定配置时先做容量预算. 对 $P$ 个参数, 列出参数 dtype、梯度、Adam 一阶与二阶状态、可能的 FP32 主权重;再按 batch、sequence、hidden size 和层数估计激活. 若完整参数能装入但优化器状态不能装入, ZeRO-1 已可能解决主要问题;若梯度也超限, 进入 ZeRO-2;若单 rank 无法保存参数, 才需要 FSDP/ZeRO-3 或模型并行.

随后做通信预算. DDP 每步主要同步约参数规模的梯度, FSDP 还为各层参数执行 all-gather, TP 在多层内部反复 collective, PP 则传输 stage 边界激活. 把消息 shape 乘 dtype 字节数, 再映射到 NVLink、PCIe 或节点间网络. 仅比较总字节仍不够, 还要检查消息数量和数据就绪时刻, 因为小消息延迟与关键路径上的 exposed communication 无法由带宽峰值隐藏.

流水线的 microbatch 数同时改变 bubble 和激活生命周期. 增加 microbatch 能提高 stage 利用率, 但每个 microbatch 太小会降低矩阵效率, 调度元数据和通信次数也会上升. Zero-Bubble 调度把输入梯度和权重梯度计算分开安排, 只有在 stage 时间接近且依赖满足时才能填充空槽, 不能把“零气泡”理解为任意模型和网络下都没有空闲.

checkpoint 与恢复也必须服从分片布局.FSDP 分片 checkpoint、TP 切分维度和 PP 层归属都需要元数据;改变 world size 时要重新分片. 随机数状态则要兼顾数据并行副本的样本差异和模型并行分片的语义一致. 这些约束不会出现在理想 FLOPs 公式中, 却决定长时间训练是否可恢复.
