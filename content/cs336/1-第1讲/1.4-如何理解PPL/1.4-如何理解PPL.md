# 困惑度: 定义、计算与比较口径

## 1. 定义

给定 token 序列 $w_1,\ldots,w_N$,自回归语言模型在每个位置给实际出现的 token 分配条件概率 $p(w_i\mid w_{<i})$.平均负对数似然为

$$
H=-\frac{1}{N}\sum_{i=1}^{N}\log p(w_i\mid w_{<i}).
$$

困惑度定义为

$$
\operatorname{PPL}=\exp(H).
$$

$H$ 与 PPL 单调对应,训练 loss 下降时,用同一口径计算的 PPL 也下降.例如 $H=2$ 时,PPL 为 $e^2\approx7.39$.这项变换没有增加信息,只是把对数尺度换成较容易解释的概率尺度.

## 2. 有效分支数的直觉

若模型在每个位置都把概率均匀分给 $K$ 个 token,正确 token 概率为 $1/K$,交叉熵为 $\log K$,PPL 恰好为 $K$.因此 PPL 常被解释成「与当前不确定性等价的均匀分支数」.PPL 为 20,表示平均不确定性与在 20 个等概率选项中选择相当.

真实模型的分布并不均匀,有效分支数也不是候选 token 的实际个数.一个位置可能高度确定,另一个位置可能分散;PPL 把所有位置的正确 token 概率用几何平均聚合.它适合比较整体概率分配,不能还原每个位置的分布形状.

理论下界是 1,对应所有实际 token 都获得概率 1.自然语言存在多种合理后续,有限模型通常达不到该下界.高 PPL 也不必然意味着生成文本杂乱;领域错配、罕见术语或不同切分都会提高数值.

## 3. 可比条件

PPL 的分母是 token 数,Tokenizer 改变后,同一文本的 token 数与条件概率项都会改变.字符级模型、BPE 模型和 WordPiece 模型的 token PPL 不能直接排序.同一 tokenizer 下比较时,还要固定验证文本、归一化、BOS/EOS、文档边界、上下文长度与滑动窗口策略.

验证集分布同样决定结果.新闻模型在医学文本上 PPL 升高,说明模型给该领域文本的概率更低,不能单凭这个数字判断模型在原训练域退化.可靠报告同时给总体值和语言、领域、长度切片.

## 4. 能力边界

PPL 衡量参考文本的似然,不验证陈述是否真实.训练语料中的常见错误也可能获得高概率,罕见但正确的专业表达可能获得低概率.它也不直接测量指令遵循、安全拒答、代码执行和开放式创作;这些能力需要相应任务数据、verifier 或人工协议.

预训练阶段,PPL 仍适合监控概率建模进展.进入指令微调与偏好训练后,优化目标和使用目标发生变化,评估需要加入任务成功率与偏好指标.PPL 保留为概率诊断项,但不能替代这些指标.

## 5. 从联合概率重新推导

自回归模型把序列概率分解为 $p(w_{1:N})=\prod_i p(w_i\mid w_{<i})$.直接连乘容易下溢,实际计算先累加负对数似然:

$$
H=-\frac{1}{N}\sum_{i=1}^{N}\log p(w_i\mid w_{<i}),\qquad \operatorname{PPL}=e^H.
$$

等价地,PPL 是正确 token 概率倒数的几何平均.若每一步正确 token 概率均为 $1/4$,PPL 为 4;两步概率分别为 $1/2$ 与 $1/8$ 时,PPL 仍为 $\sqrt{2\times8}=4$.「有效选项数」只描述与该熵相当的等概率分支数,不表示模型真的在四个候选中均匀抽签.

批量评估要先累加各 batch 的 NLL 总和 $S_b$ 与有效标签数 $N_b$,最后计算 $H=\sum_bS_b/\sum_bN_b$.先求每个 batch 的平均 loss 再无权平均会让短 batch 或 padding 较多的 batch 获得过大权重.EOS 是合法标签,PAD 应由 loss mask 排除.

使用自然对数时交叉熵单位为 nat;使用以 2 为底的对数时得到 bits per token(BPT),对应 $\operatorname{PPL}=2^{\operatorname{BPT}}$.日志中的 loss 只有在对数底数、reduction、标签 mask 和 label shift 相同时才能换算比较.

## 6. 有限上下文上的长文评估

上下文上限为 $L$ 时,非重叠分块会让每块开头失去原本存在的前文,预测条件变短,PPL 因而偏高.滑动窗口评估会保留最多 $L$ 个历史 token,每次只给窗口中新加入的后缀计分.设步长 $s<L$,后续窗口的前 $L-s$ 个位置仅提供上下文,loss mask 设为忽略;最后 $s$ 个新标签才进入累计值.

步长越小,重复计算越多,但每个被评分 token 获得的历史越完整.报告必须给出 $L$ 与 $s$,否则同一模型在同一文档上也可能产生不同 PPL.使用 KV Cache 可以减少逐 token 重算,其数学结果应与相同条件下的完整 causal forward 一致;量化缓存或近似 Attention 则可能引入额外误差.

文档边界也会改变条件概率.若把多篇文档直接串接,后一篇开头会读取前一篇正文;若逐篇重置,开头只看到 BOS.训练与评估宜采用一致的 EOS、BOS 和边界策略.跨文档内容本来无关时,让前文进入上下文还会使结果依赖文档排列顺序.

## 7. 跨 Tokenizer 的统一分母

对同一原始 UTF-8 字节串,设总 NLL 为 $S$ nats,字节数为 $M$,则 bits per byte 为

$$
\operatorname{BPB}=\frac{S}{M\log2}.
$$

BPB 把概率代价分摊到统一的字节分母,可用于不同子词切分之间的粗略比较.字符级口径也可定义,但必须统一 Unicode 归一化、换行和组合字符计数.统一分母仍不能消除 BOS/EOS、上下文长度和文本清洗差异,这些配置需要随数字一起提供.

一个反例可以说明 token PPL 为什么会误导.字符串 `abab` 被 tokenizer A 切成 `[ab,ab]`,每步正确概率为 $0.25$,token PPL 是 4;tokenizer B 切成 `[a,b,a,b]`,每步概率为 $0.5$,token PPL 是 2.两个模型给整串的联合概率都是 $1/16$.按相同四个字符或字节归一化后,两者才落在同一口径.

固定 token 预算也不等于固定文本量.平均每 token 覆盖字节越多,相同 token 数读过的原始文本越多.跨模型报告训练数据和验证损失时,应同时给 tokenizer 版本、原始字节量和主要语言的压缩率.

## 8. 用 PPL 诊断训练

训练 PPL 下降而验证 PPL 上升,可能是过拟合,也可能是训练与验证预处理不一致.两者同时突然上升时,优先检查学习率、梯度溢出、数据 batch 和 checkpoint.只有某个领域切片上升时,更可能是数据配比变化或领域遗忘.

代码、中文、网页与书籍应分别累计 NLL 和有效 token 数.总体 PPL 是按 token 占比加权的结果;数据配比改变后,即使各域能力不变,总体值也会移动.切片统计还能发现平均值掩盖的局部退化.

loss 从 2.0 降到 1.9 对应 PPL 从约 7.39 降到 6.69,但差异是否稳定取决于验证集规模与文档相关性.可以按文档 bootstrap 估计区间,不能把相邻 token 当作完全独立样本.Scaling law 常直接拟合交叉熵,因为对数空间更稳定且接近加性;指数变换只改善解释,不会产生新的证据.

## 9. PPL 没有回答的问题

PPL 检查模型给参考文本的概率,不检查文本是否真实.常见但错误的说法可能得到高概率,罕见的正确结论可能得到低概率.开放式任务还有多个合理回答,单一参考序列的概率无法覆盖所有有效输出.事实核验、推理、代码执行、指令遵循和安全拒答需要各自的 verifier、任务基准或人工协议.

评估文本若出现在训练数据中,PPL 会因记忆而虚低.近重复、模板复用和同源网页也会泄漏,不能只查文件哈希.验证集应在训练前隔离,训练语料同时做精确与模糊去重;评估后还可检查异常低 loss 的文档,定位潜在污染.

一份可复算报告至少包含 checkpoint、tokenizer、数据集版本与文件哈希、有效 token 数、上下文窗口、stride、文档边界、BOS/EOS/PAD 处理、loss 聚合方式和计算精度.口径齐全时,PPL 能稳定衡量模型对指定分布的压缩能力;缺少这些信息,孤立数字不能支持模型优劣结论.

## 10. 从 logits 手算到代码实现

### 10.1 三分类例子

设某位置词表只有 `甲、乙、丙`,模型 logits 为 $[2,1,0]$,正确标签是「乙」.softmax 分母为 $e^2+e^1+e^0$,正确概率

$$
p(\text{乙})=\frac{e}{e^2+e+1}\approx0.245.
$$

该位置 NLL 为 $-\log0.245\approx1.408$.另一位置正确 token 概率若为 $0.8$,两位置平均 NLL 为 $(1.408-\log0.8)/2\approx0.816$,PPL 为 $e^{0.816}\approx2.26$.不能先把两个概率做算术平均再取倒数;PPL 对应几何平均,低概率错误会受到更强惩罚.

数值实现无需显式算 softmax 再取 log.使用 `log_softmax` 或 fused cross entropy 可以通过减去最大 logit 避免指数上溢.若 logits shape 为 $[B,T,V]$,标准 next-token 评估使用 `logits[:, :-1]` 对 `tokens[:, 1:]`;两边都结合 attention mask 裁成同一组有效标签.

### 10.2 一次可靠聚合

每个 batch 返回 `nll_sum` 和 `token_count`,分布式环境对两者分别做 all-reduce,最后由全局总和计算一次指数.各 rank 直接平均 PPL 是错误的:指数是非线性变换,而且每张卡的有效 token 数可能不同.正确顺序始终是「汇总 NLL→除以 token 数→取指数」.

FP16 中累加大量 NLL 可能损失精度,统计量宜用 FP64 或至少 FP32.超长语料的 PPL 可能数值很大,日志可同时保存平均 NLL;模型极差时先比较 NLL,避免指数溢出.评估代码还应输出实际计分 token 数,防止 mask 错误后得到看似正常的 PPL.

## 11. 条件 PPL 与生成任务

### 11.1 Prompt 不一定进入分母

评估问答或摘要时,输入由 prompt 和目标 answer 拼接.若任务关心回答的条件概率,attention 允许 answer 读取 prompt,但 loss mask 应遮掉 prompt,只累计 answer token.这得到 $p(\text{answer}\mid\text{prompt})$ 的条件 PPL.若把 prompt 也计分,问题模板的易预测程度会稀释答案差异.

不同答案长度仍会影响平均值.按 token 平均适合比较模型对整个答案分布的压缩能力;若做候选排序,还要考虑长度归一化是否与任务目标一致.短答案可能因少犯错而获得较高联合概率,长答案则提供更多细节.这些问题不能靠 PPL 一个数字解决.

聊天模板同样属于条件的一部分.system、role delimiter 与结束 token 必须与模型训练格式一致.漏掉模板或换用另一套特殊 token,测到的是格式失配.报告条件 PPL 时应保存渲染后的实际 token 序列和 loss mask,仅提供可见对话文本不足以复现.

### 11.2 蒸馏与知识迁移中的 PPL

硬标签 PPL 只看数据中实际出现的 token.蒸馏还会最小化学生分布与教师分布的 KL 散度,教师给其他 token 的概率也参与目标.学生的验证 PPL 改善说明对真实文本的似然提高,却不能单独说明它复现了教师的完整分布;需要另报 KL、任务指标或生成一致性.

温度会改变教师分布的平滑程度,因此蒸馏 loss 与普通 NLL 数值不能直接比较.同样,带 label smoothing 的训练 loss 包含对非目标类别的项,不能简单做 `exp(loss)` 当作标准 PPL.评估阶段应关闭 smoothing,用原始 one-hot 标签重新计算 NLL.

## 12. 常见实现故障

### 12.1 Off-by-one 与重复计分

最危险的错误是 logits 与同位置 token 对齐,让模型预测已经看见的输入.这种泄漏会产生异常低 PPL.最小测试可用递增 ID 序列,打印每个 logit 对应标签,确认位置 $i$ 的输出预测 $i+1$.加入 BOS 后也要重新核对,不能凭张量长度猜测.

滑动窗口若对重叠区域重复累计,中间 token 会获得比文档两端更大权重.每个窗口应明确 `target_start`,重叠前缀全部设为 ignore index.完成后断言累计有效 token 数等于按边界规则可预测的总 token 数.

### 12.2 评估模式与随机性

评估前调用 `model.eval()` 关闭 dropout,同时禁止梯度以降低显存.若模型含随机路由、采样层或数据增强,还要固定或关闭这些路径.PPL 计算使用教师强制,每一步条件是真实前缀,不应调用随机生成 API;采样温度、top-k 与 top-p 不参与标准 PPL.

MoE 模型还应确认评估时路由容量和 token 丢弃策略.容量不足导致 token 被丢弃会改变 logits;不同 batch size 可能得到不同 PPL.概率指标理应尽量独立于评估 batch,若 batch 改变结果,需要检查 padding、路由容量、归约与数值精度.

## 13. 如何阅读一个 PPL 数字

先看数据:评估集属于哪个语言和领域,是否与训练集去重.再看单位:token PPL、BPT 还是 BPB,采用哪个 tokenizer.随后看条件:上下文长度、stride、文档边界和模板.最后才比较模型,并结合有效 token 数和统计区间判断差异是否稳定.

同一模型的训练 checkpoint 在固定口径下,PPL 是敏感且便宜的进度指标;同一 tokenizer、同一验证集上的架构消融也适合用它筛选.一旦跨 tokenizer、跨领域或跨后训练目标,必须补充统一分母和任务指标.**PPL 准确回答的是「模型给这批 token 序列分配了多大平均概率」,其余结论都需要额外证据.**

还可以用一个均匀模型校验评估程序.若词表大小为 $V$,每个位置 logits 全为 0,softmax 后每个 token 概率是 $1/V$,理论 NLL 为 $\log V$,PPL 必须等于 $V$.若实际结果不同,优先检查 shift、mask、reduction 和词表维.再构造一个把正确 token logit 提高固定常数的模型,手算概率并与程序对照,可以同时覆盖 softmax 与聚合路径.

比较 checkpoint 时应使用完全相同的评估容器.数据加载顺序本身不应影响结果;若改变 batch size 或样本顺序后 PPL 明显变化,通常意味着 padding mask、MoE 容量、状态缓存或浮点累加存在问题.把这些不变量写成自动测试,比在训练结束后凭曲线排查可靠.

PPL 也能用于数据检查.单篇文档 loss 极高可能包含乱码、语言错配或模板破损;异常低则可能是重复、泄漏或大段固定样板.这里使用的是排序后的样本诊断,不是按 PPL 自动删除数据.高 loss 的专业文本可能恰好最有价值,仍需结合来源和内容判断.

还要区分「验证集 PPL」与「模型生成文本的 PPL」.前者用真实文本作标签,衡量模型对外部数据的概率;后者若让同一个模型给自己采样的文本打分,结果会受到采样温度和截断策略控制,低温生成天然偏向高概率 token,因而得到更低 PPL.这不能证明生成质量更高.若用另一个模型评分,数字又混入评分模型的偏好与 tokenizer 差异.生成质量评估应直接针对任务目标设计,不要把自评分数包装成验证集似然.

PPL 类似训练监控中的温度计:它对概率分布变化敏感,却不会自动指出病因.数据切片、优化日志和任务评测负责定位变化来源.测量对象与口径稳定固定后,PPL 的升降才具有可解释性.

## 14. 熵、交叉熵与校准

设真实数据分布为 $q$,模型分布为 $p$.在无限样本下,平均 NLL 是交叉熵

$$
H(q,p)=H(q)+D_{\mathrm{KL}}(q\Vert p).
$$

$H(q)$ 是数据分布自身的不确定性,对固定验证分布而言不可由模型改变;$D_{\mathrm{KL}}$ 衡量模型分布偏离真实分布的程度.模型改进能够降低第二项,却不能把自然语言中固有的多种合理后续消除.不同数据域的 $H(q)$ 本来就可能不同,所以跨数据集比较 PPL 时,数值差异同时混合了任务难度与模型能力.

有限验证集只提供 $q$ 的样本,每个位置通常只有一个实际 token.交叉熵奖励模型给该 token 更高概率,但无法直接观察其他合理 token 应占多少概率.这也是 PPL 与开放式生成质量之间存在距离的原因:它对观测序列是严格的概率评分,对未观测但合理的替代续写没有正向标签.

PPL 降低也不保证概率已经校准.校准关注「模型声称 80% 的事件是否约有 80% 发生」,而 NLL 同时受排序和置信度影响.可以按正确 token 概率或 top-1 置信度分桶,比较预测置信与经验命中率;但语言建模词表巨大、每位置只有一个结果,校准图的解释要结合 token 频率与上下文类型.

温度缩放会改变 logits 的尖锐程度.令 $z$ 为 logits,温度 $\tau$ 后分布为 $\operatorname{softmax}(z/\tau)$.在固定验证集上选择 $\tau$ 可以降低 NLL,说明原模型过度或不足自信;这不等于模型学到新知识,也不应把调温后的 PPL 与未调温模型混为一次架构能力比较.

## 15. 数据加权与混合分布

预训练验证集常由多个来源混合.若第 $j$ 个域有 $N_j$ 个有效 token,NLL 总和为 $S_j$,自然 token 加权结果是 $\sum_jS_j/\sum_jN_j$.它回答「从当前混合分布随机抽一个 token,平均代价是多少」.若每个领域同等重要,可先求各域平均 NLL 再按预设权重组合;两种口径回答的问题不同.

领域权重应在看结果前确定.根据模型强弱临时调整权重会让总体 PPL 失去可比性.报告既给固定权重总体值,也给逐域值和 $N_j$,读者才能分辨提升来自哪个来源.多语言评估尤其要防止英语 token 数占比压过低资源语言.

重复文本会改变有效权重.某个样板重复一百次,token 加权 PPL 会把它当一百份证据,即使信息量几乎没有增加.验证集也需要去重,并避免同一文档的不同抓取版本横跨训练与验证.按文档聚合再 bootstrap 时,近重复文档仍会低估不确定性.

序列长度分布同样值得切片.短段落的开头 token 占比高,可用上下文少;长文中段可以利用更多历史.两个验证集即使主题相同,长度分布不同也会得到不同 PPL.报告按上下文可用长度分桶的 NLL,可以观察模型收益主要发生在局部预测还是长程条件利用.

## 16. 从 PPL 到实验决策

训练过程中可以用验证 NLL 选择 checkpoint,因为它与 PPL 单调等价且数值更便于比较.早停规则需要容忍评估噪声,例如要求连续若干次无改善,同时保持评估间隔和验证样本固定.若学习率调度以验证指标触发,还要避免频繁试探验证集造成间接过拟合.

架构消融中,先比较固定计算预算下的 NLL,再检查逐域与逐长度切片.差异很小时,运行多个随机种子或扩大验证集;单次末位小数变化可能来自初始化和数据顺序.同时记录训练 FLOPs、墙钟和峰值显存,才能判断较低 PPL 是否值得额外成本.

后训练模型可能为了更好地遵循指令而降低某些普通文本续写概率.若只看预训练 PPL,这种变化会被记录为退步,但任务成功率可能提高.合理做法是同时保留基础语言建模集与目标任务集,分别测概率保持和行为收益,而不是强求一个指标承担两种目标.

数据、公式、代码路径和聚合口径能够完整复算时,PPL 才适合进入实验表格.它提供的是模型对指定序列分布的压缩结果;事实性、推理正确率和人类偏好继续由各自指标回答.

这条边界在阅读论文和训练日志时始终适用.
