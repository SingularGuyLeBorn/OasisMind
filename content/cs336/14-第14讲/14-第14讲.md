# 第14讲: 数据过滤、去重与数据管线

Common Crawl 网页经过解析和筛选后才能成为预训练数据.网页正文旁边有导航栏、版权声明、广告和模板文本;抓取结果里有乱码、截断页面、重复镜像站与机器批量生成内容;同一篇文章还可能以打印版、转载版和不同 URL 出现.这些 token 一旦进入训练流,都会参与参数更新.数据管线需要给出明确的文档表示、保留规则和版本记录, 使最终训练分布能够复查.

第13讲讨论「应该从哪些来源取数据」,第14讲继续追问每个来源内部怎样处理.这里的顺序很重要:抽取改变文档边界,语言识别和规则过滤改变保留集合,去重依赖前两步得到的文本表示,最终混合又决定每类文档被模型看到多少次.把其中任何一步单独拿出来调到很激进,都可能让局部指标变好,同时删除罕见语言、短文本或特定领域里真正有用的材料.

## 从网页记录到训练文档

原始抓取通常以 WARC 记录保存 HTTP 响应.数据管线先解析编码与 MIME 类型,再从 HTML 中抽取可见正文,并给每条文档保留来源、抓取时间、URL、语言分数和过滤原因.元数据不是附属品:当某个训练现象需要回查时,研究者必须能够定位原始文档,以及它经历过哪些变换.只保存最终纯文本,会让误删、污染和许可证问题很难追踪.

正文抽取没有唯一方案.保留太多 DOM 节点会留下站点模板;过滤过强又会损失代码块、表格、公式和列表结构.抽取器由此定义了后续算法实际观察到的「文档」.两个团队即使使用同一份 Common Crawl,只要正文抽取、文档切分与 Unicode 归一化不同,最终 token 分布就可能相差很大.

语言识别一般输出一个语言标签和置信度,而不是绝对正确的真值.短文本、代码混排、专名和相近语言尤其容易误判.实践中更稳妥的做法是保留分数,按来源与目标语言分别选阈值,并抽样检查阈值附近的文档.**过滤器需要输出可审计的分数与原因,不能只输出一个不可逆的保留位.**这样才能比较不同阈值造成的规模变化,也能为后续实验重新采样.

## 质量过滤实际在估计什么

质量过滤常见两条路线.规则法计算字符比例、重复行、平均词长、标点密度、URL 数量和敏感内容命中等特征;分类器法用高质量参考数据与随机网页构造正负样本,学习一个文档分数.两种方法都在估计「这篇文档是否适合当前训练目标」,而这个目标由参考集和规则共同定义.参考集偏向百科或学术文本,分类器便会系统性压低论坛、对话和非标准书写.

[主讲义](./14.1-主讲义/14.1-主讲义.md)先给出完整管线,再把规则阈值、模型过滤和数据规模放在同一条流程中理解.[KenLM](./14.2-KenLM/14.2-KenLM.md)进一步解释一种常见质量信号:用 $n$-gram 语言模型计算文档在参考分布下的困惑度.KenLM 分数低,表示局部字符或词序列更接近参考语料;这个分数无法直接证明事实正确,也无法判断文档是否提供了稀有知识.它适合作为一个特征,不能替代内容与来源分析.

设一篇文档的 token 为 $w_1,\ldots,w_T$,$n$-gram 模型给出的平均负对数似然为

$$
H(d)=-\frac{1}{T}\sum_{t=1}^{T}\log p(w_t\mid w_{t-n+1:t-1}).
$$

困惑度是 $\operatorname{PPL}(d)=\exp(H(d))$.当参考模型来自 Wikipedia 时,低 PPL 更接近「写法像 Wikipedia」,而不是普遍意义上的高质量.工程上应同时观察被过滤文档的来源、长度、语言与主题分布,避免一个标量阈值悄悄改变整个数据集的覆盖范围.

## 精确重复与近似重复

精确去重可以对归一化后的全文计算 hash.两个文档字节序列相同时,只保留一份即可;困难在于网页重复往往带有少量编辑、模板差异或段落重排.近似去重因此把文档表示成 shingles 集合.若使用连续 $k$ 个 token 的 shingle,文档 $A$ 与 $B$ 的 Jaccard 相似度为

$$
J(A,B)=\frac{|S_A\cap S_B|}{|S_A\cup S_B|}.
$$

直接比较所有文档需要二次复杂度.[MinHash 与 LSH](./14.3-MinHash-LSH/14.3-MinHash-LSH.md)说明怎样先用多组哈希近似 Jaccard,再用 locality-sensitive hashing 只召回可能相似的候选对.单个 MinHash 分量相等的概率等于 Jaccard 相似度;用 $m$ 个独立分量后,相等比例就是一个方差随 $m$ 降低的估计量.LSH 再把签名切成 band,让至少一个 band 完全相同的文档进入候选集.

去重阈值会改变数据分布.阈值过低会把共享常用段落的不同文档合并,技术文档、法规文本和代码许可证尤其容易受影响;阈值过高则保留大量轻微改写的镜像.随机保留、保留最早抓取、保留质量分最高或许可证信息最完整的副本,也会产生不同结果.去重规则实际决定了哪些样本共享一次统计权重.

## 顺序、泄漏与最终混合

过滤与去重的顺序决定结果.先做严格质量过滤,可能把某个重复簇中唯一保留元数据完整的页面删掉;先做全局去重,又可能让低质量镜像成为代表文档.合理流程通常会保留簇信息,先计算多个质量与来源特征,再按明确规则选择代表.段落级去重和文档级去重也解决不同问题:前者能删除跨站点模板,后者更容易保持文档语义完整.

评测污染需要单独处理.对 benchmark 题目做精确字符串匹配只能找到直接复制;规范化、$n$-gram overlap、语义召回各自覆盖不同改写程度,也各自带来误报.去污染报告应写清 benchmark 版本、匹配单元、阈值以及删除的是整篇文档还是命中窗口.缺少这些口径,「已经去污染」无法说明训练集与评测集还剩多少联系.

管线最后输出若干来源池,训练时还要决定混合权重与重复次数.某个高质量来源规模小,增加采样权重会让模型更常看到它,同时提高记忆风险;大规模网页权重高,覆盖更广,却可能稀释稀有领域.本讲把抽取、过滤、去重和混合串成一条可追溯记录, 每个阈值都应对应到实际保留或删除的样本集合.

数据管线还需要用小规模训练实验校准.保留率更高不等于模型一定更好,过滤分数更高也不等于下游任务稳定提升.可以固定模型、token budget 与训练配置,只替换某一个数据版本,比较 held-out loss、分领域评测和记忆指标.这样的对照才能把「过滤器看起来合理」推进到「过滤器确实改变了模型行为」,也能发现某个阈值只优化了与分类器参考集相近的领域.

一条训练样本还应能追溯到管线版本.记录中至少保存原始对象标识、正文抽取器版本、语言与质量分数、重复簇标识、去污染规则版本以及最终采样权重.当规则更新时,这些字段允许只重算受影响的阶段,也能解释两个语料版本为何拥有相同 token 数却产生不同训练曲线.**数据版本不是一个文件名,而是一组输入对象、变换代码、参数和输出清单的共同快照.**
