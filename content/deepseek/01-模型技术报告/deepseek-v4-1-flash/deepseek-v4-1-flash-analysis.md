# DeepSeek-V4.1-Flash: 每 token 890 字节的 global KV

材料是 DeepSeek 的正式技术报告 (arXiv 2609.19969). 报告的出发点是长程 Agent 的负载越来越偏输入: 工具调用一轮接一轮, 每轮都要 prefill, KV cache 要在 HBM, 主机内存和 SSD 之间存放与搬运; V4 用压缩稀疏注意力压下了长序列的计算之后, 剩下的瓶颈是 cache 的容量和带宽.

## 1. 规模与每 token KV 字节

### 1.1. 规模: 从配置复算 552B 和 16B

第 4.2.1 节给出配置: 40 层, 隐藏维 5120, 前 20 层是因果 encoder, 后 20 层是 decoder. 每层 MoE 有 1 个共享专家加 384 个路由专家, 专家中间维 2304, 每 token 激活 6 个路由专家. 按 SwiGLU 三个矩阵算, 每个专家约 3540 万参数, 每层 385 个专家, 40 层合计约 545B(推导). 注意力侧 64 个查询头, 每头 512 维, 查询压缩维 1280, 输出分 8 组, 每组中间维 1024, 再加 32 头 × 128 维的 indexer 查询投影, 每层约 1.3 亿参数, 40 层约 5.3B(推导). 两者相加约 550B, 再加嵌入与输出头, 与 552B 对得上. 词表大小报告没有给, 这一项按前作的量级估.

激活参数也能复算. 每 token 走 7 个专家, 40 层约 9.9B, 加上约 5.3B 注意力和约 0.7B 输出头, 约 16B, 对应 decode 的 16B; prefill 在 CED 下只跑 encoder 的 20 层, 专家约 5B, 注意力约 2.6B, 合起来约 8B(推导). 所以 「8B/16B」 不是两个模型, 是同一组权重在两个阶段走过的层数不同. Engram 的 196B 不计入激活, 因为它按 N-gram 查表, 不做矩阵乘. 表 1 把 V4.1-Flash-Base 的激活写成 「8B/16B」, 骨干 552B, 对照 V4-Flash-Base 的 13B/284B 和 V4-Pro-Base 的 49B/1.6T, 骨干总参数约是 Pro 的三分之一 (552/1600 ≈ 0.35); 激活参数按阶段不同, decode 的 16B 约是 Pro 的三分之一, prefill 的 8B 约是六分之一 (推导). 算上 Engram, 总参数是 748B, 约为 Pro 的 47%.

### 1.2. 图 1(b): 四代模型的每 token global KV

图 1(b) 给出四代模型每 token 的 global KV 字节数: V1 为 389,120, V3.2 为 48,068, V4-Flash 为 3,514, V4.1-Flash 为 890. 图上标的倍数是 8.1×, 13.7× 和 3.9×, 正文把末段写成 「approximately 4-fold」, V1 到 V4.1 是 437 倍. 这几个数都能用各代的公开配置复算. V1 的 67B 模型按 [DeepSeek LLM 报告](../deepseek/deepseek-analysis.md) Table 2 有 95 层, GQA 8 个 KV 头, 每头 128 维, K 和 V 各存 BF16, 每层 4096 字节, 95 层正好 389,120 (推导). V3.2 的 cache 布局见 FlashMLA 仓库的说明: 每层存一个 MLA 潜变量, 512 维 FP8 加 4 个 FP32 比例因子加 64 维 BF16 RoPE, 共 656 字节; 再加 indexer K 的 128 维 FP8 和一个 FP32 比例因子, 共 132 字节; 每层 788 字节, 61 层正好 48,068 (推导). indexer K 的 132 字节是按总数反推的, FlashMLA 说明里只写了主 KV 的 656 字节.

### 1.3. 890 字节怎么来

报告没有写 890 的分解, 但可以从配置拼出来. 主 KV 条目是 512 维, 存成 E2M1 的 FP4, 每维 0.5 字节, 共 256 字节; 每 16 维配一个 E4M3 比例因子, 32 个, 共 32 字节; 一个条目 288 字节. indexer K 是 128 维, 按第 2.4.4 节说的 OCP 标准 MXFP4 存法, 64 字节数据加 4 个 E8M0 比例因子, 共 68 字节. 一组 global KV 条目合计 356 字节(推导). 缓存组数继续按层排布计算: encoder 后 18 层分三组, 每组只有第一层是 Full, 三个 Full 层各存一份, 压缩比 m=2, 所以每 token 摊 3 × 356 / 2 = 534 字节; decoder 20 层只有第一组第一层是 Full, 后四组的 Reindex 层复用最近 Full 层的主 KV 和 indexer K, 整个 decoder 只存一份, m=1, 每 token 356 字节. 534 + 356 = 890, 与报告一致 (推导). 主 KV 的 288 字节布局 (256 字节 E2M1 数据加 32 个 E4M3 比例因子) 与 FlashMLA 仓库对 V4.1 FP4 cache 格式的说明一致. indexer K 用 MXFP4 是按第 2.4.4 节的上下文推定的, 报告里没写 indexer K 的比例因子布局.

这个分解说明了 V4.1 的压缩主要来自哪里. 38 个 CSA2 层里只有 4 层真正产生 global KV, 其余 34 层都在读别人的 cache; 精度从 V4 报告第 2.3 节的 「448 维 FP8 + 64 维 BF16 RoPE」(每条目 576 字节, 不计比例因子)降到 288 字节, 又减一半. V4-Flash 的 3,514 字节涉及索引键比例因子的存法, V4 报告里没写, 这里只用图上的数字. 按 890 字节算, 1M token 的请求在 HBM 里约占 890MB global KV (推导); SWA KV 每层只存 128 个窗口位置, 与上下文长度无关, SWA 条目的精确维度报告里没写.

## 2. 注意力: CED 与 CSA2

### 2.1. CED: 从 YOCO 借来的半网 prefill

**CED** (Causal Encoder-Decoder) 的灵感来自 **YOCO**(You Only Cache Once). YOCO 把网络分成 self-decoder 和 cross-decoder 两半, 下半层用高效注意力产出一份 global KV, 上半层全部通过交叉注意力复用这一份, 于是 prefill 走完下半层就可以提前退出. CED 做了两处改动. 第一, decoder 的 global KV 条目 $C_l$ 和压缩权重 $Z_l$ 不来自本层隐状态 $H_l$, 而是由 encoder 末层 $H_{L/2}$ 经层相关投影得到, 见式 (1):

$$
C_l=H_{L/2}W_l^{KV},\qquad Z_l=H_{L/2}W_l^{Z},\qquad l>\frac{L}{2}.
$$

右边只有 $H_{L/2}$ 一个输入, 不含任何 decoder 层的隐状态, 所以 prefill 算完第 20 层就能把 decoder 需要的 global KV 全部投影出来, 不用跑 decoder 的 20 层. 投影权重 $W_l^{KV}$, $W_l^{Z}$ 按层独立, 保留了一定的 cache 容量. 配合 CSA2, decoder 里只有第一个 Full 层真的执行这个投影并落盘, 其余层复用它, 这就是第 1.3 节里 decoder 只存一份 356 字节的原因. 第二, SWA 在每一层都照常从本层隐状态算局部 K 和 V, 局部 KV 的生成深度没有减少. 与 YOCO 的上半层完全不保留局部注意力相比, 这是最大的差别.

第二处改动带来一个代价: decoder 的 SWA KV 依赖 decoder 自己的隐状态, 要精确得到它, prefill 时 decoder 仍要多处理 $n_{\text{win}} \times L/2$ 个 token. 多轮对话里每轮 prompt 很短时, 这笔开销不可忽略. 报告引用 PowerAttention 的观察, SWA 实际的有效感受野远小于理论值 $n_{\text{win}} \times L/2$, 于是引入 Decoder SWA Bounded Replay, 只对 prompt 末尾 $n_{\text{win}}$ 个 token 做 decoder 的 SWA 计算, 细节在第 3.2.2 节. 整体上, $N \gg n_{\text{win}}$ 时 prefill 复杂度从 $O(NL)$ 降到 $O(NL/2 + n_{\text{win}} \times L/2) \approx O(NL/2)$. 按配置 $n_{\text{win}}=128$, $L/2=20$, 精确重建要 2560 个 token 的 decoder 前向, 有界回放只要 128 个, 少 20 倍(推导). CSA2 与 CED 结合时, decoder 里的 Full 层从 $H_{L/2}$ 算自己的 global KV, Reindex 和 Reuse 不变; 由于 decoder 只有一个 Full 层, CED 加 CSA2 的 decoder 在 global KV 上也只存一份, 结果和 YOCO 的「只 cache 一次」相同, 区别在于 V4.1 每层仍保留自己的 SWA.

CED 的计算和状态变化如下. encoder 的 20 层照常前向; decoder 的 global KV 由第一个 Full 层用自己的投影 $W_l^{KV}$ 从 encoder 末层输出 $H_{L/2}$ 算出. decoder 各层的查询来自本层隐状态, 与 encoder 输出投影得到的 global KV 做稀疏注意力, 再与本层 SWA KV 做局部注意力. prefill 跑完 encoder 后即可写好全部 global KV, decoder 只为 prompt 末尾 128 个 token 补算 SWA KV; decode 时每个新 token 仍走全部 40 层. 代价是 decoder 看到的远程信息只来自第 20 层表示, 深层隐状态不再写入 global KV. 报告没有给出 CED 相对标准 decoder-only 的质量消融.

### 2.2. CSA2 的三种模式和层排布

CSA2 给每个 CSA2 层静态指定三种模式之一(图 4). **Full** 走完整路径: 算本层主 KV 和 indexer Q, 从主 KV 投影出 indexer K, 打分选出新的 Top-K, 职责等同 V4 里一个完整的 CSA 层. **Reindex** 复用最近 Full 层的主 KV 与 indexer K, 用本层的 indexer Q 重新打分, 选出新的 Top-K. **Reuse** 连 Top-K 一起复用, 不算 indexer Q, 不打分, 直接做稀疏注意力. 三种模式都在本层算主 Q 和 SWA KV. cache 共享和索引复用因此解耦: Reindex 让被选中的条目可以逐层变化, 而存储仍是共享的.

| 模式 | 本层算什么 | 和谁做注意力 | 缓存怎么变 | 丢了什么 |
|---|---|---|---|---|
| Full | 主 KV, indexer Q 与 K, top-k, 主 Q, SWA KV | 自己选出的 top-k 条目加 SWA | 写入一份新的主 KV 和 indexer K | 无, 等同 V4 的一个 CSA 层 |
| Reindex | indexer Q, top-k, 主 Q, SWA KV | 在最近 Full 层的条目里重新选 top-k | 不写 global KV, 只写本层 SWA KV | 本层看到的 KV 内容由前面某一层的隐状态决定 |
| Reuse | 主 Q, SWA KV | 直接用上一个 Full 或 Reindex 层的 top-k | 同上 | 选哪些条目也由前一层决定, 本层只能调整怎么加权 |

相关工作里, **IndexCache** 只复用 Top-K 索引, 省下 indexer 计算但省不了主 KV 存储; YOIO 全网共享一次路由, 报告认为会限制性能; HySparse 让稀疏层复用稠密层的 KV, 但仍保留全注意力层. 报告的判断是这些方法都没有同时覆盖三个维度.

第 4.2.1 节给出具体排布. encoder 前 2 层是纯 SWA; 其余 18 层 CSA2, 压缩比 $m=2$, 分三组每组 6 层, 每组 「1 Full + 5 Reuse」. decoder 20 层 CSA2, 压缩比 $m=1$, 即不压缩, 分五组每组 4 层: 第一组 「1 Full + 3 Reuse」, 后四组 「1 Reindex + 3 Reuse」. 所有 CSA2 层的 indexer 查询头 32 个, 头维 128, 稀疏注意力 top-k 取 512; SWA 窗口 128. 所以 decoder 里每个查询读 512 个 token 级条目, encoder 里读 512 个条目覆盖 1024 个 token 位置(推导). 与 V4 的 CSA 与 HCA 交错不同, V4.1 只用 CSA2, 没有 HCA; 38 个 CSA2 层里 Full 4 个, Reindex 4 个, Reuse 30 个(推导). 报告没有给这套排布的消融, 也没有说明为何 encoder 取 m=2, decoder 取 m=1.

### 2.3. 压缩器和 indexer 的简化

CSA2 在 V4 的 CSA 基础上做了两处简化. V4 的 CSA 在压缩比 m 下, 每个主 KV 条目由 2m 个原始条目生成, 相邻压缩条目的来源有重叠, 压缩时还加绝对位置编码标记这 2m 个位置. CSA2 去掉了重叠和绝对位置编码. 另外, CSA2 的 indexer K 直接从主 KV 条目投影得到, 不再像 CSA 那样另走一条从隐状态出发的压缩路径. 报告说这两处改动都简化了实现, 提高了训练效率, 但没有给质量上的消融数字.

indexer K 从主 KV 投影这一点, 和跨层复用是配套的. 如果 indexer K 有自己独立的压缩路径, Reindex 层要复用它就得额外存一份独立状态; 从主 KV 投影之后, 共享主 KV 与共享 indexer K 变成同一件事. 代价是 indexer K 不再能独立学一套只为打分服务的表示, 打分质量受主 KV 表示的约束; 报告没有给这项改动的质量对比. CSA2 把压缩比 1 的不压缩情形作为特例包含在内, decoder 用的正是这种特例, 这时 CSA2 在 decoder 里的行为接近 V3.2 的 DSA: token 级 indexer 选 Top-K, 再做稀疏注意力, 见 [稀疏注意力综述](../../../llm-guide/2-核心原理与架构/2.4-稀疏注意力/2.4-稀疏注意力.md).

### 2.4. 分层稀疏 Indexer 与 decode 算力

跨层复用减少了 indexer 的调用次数, 但剩下的 indexer 仍要给全部因果可见的条目打分, 上下文极长时这仍是主要瓶颈. **Hierarchical Sparse Indexer** 只用于 CED 的 decoder: decoder 第一个 Full 层给全部位置打分, 选出自己的 Top-512, 同时做块级候选选择, 每块取块内最大分数, 选分数最高的块, 把这些块覆盖的位置收成候选池. 配置是最多 2048 个块, 每块 8 个位置, 候选池至多 16,384 个位置(图 5). 后面的 Reindex 层只在候选池里打分并选各自的 Top-512, Reuse 层不打分. 这个机制在后训练引入, 训练和推理用同一个候选池限制, 深层 indexer 是在推理时的搜索域上优化出来的.

## 3. 架构扩展, 量化与优化器

### 3.1. Single-Pass mHC 与 Mega-mHC

V4 引入的 mHC 在相邻块之间维护 n 条残差流, 更新式为 $X_{l+1} = B_l X_l + C_l \mathcal{F}(A_l X_l)$, 系数由 $X_l$ 预测, 机制见 [mHC](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.3-残差连接/01-Hyper-Connections与mHC/01-Hyper-Connections与mHC.md). 理想情况下, 两块之间的残差变换只需读 $(n+1)d$, 写 $(n+1)d$, 激活内存流量下界是 $(2n+2)d$. V4 的实现拆成残差更新, 系数预测, 输入混合三个顺序执行的内核, 加上 pre-norm, 总流量 $(4n+4)d$, 是下界的两倍. 其中残差更新和系数预测可以共用一次遍历, 但输入混合要等全部隐藏维归约完才拿得到 $A_l$, 必须第二次读 $X_l$, 两遍实现是 $(3n+2)d$.

**Single-Pass mHC** 把输入混合系数错后一块: 块 l 用上一块预测的 $A_{l-1}$, 式 (6):

$$
X_{l+1}=B_lX_l+C_l\mathcal{F}_l(A_{l-1}X_l),\qquad (A_l,B_l,C_l)=\mathcal{H}(X_l).
$$

和原式 $X_{l+1}=B_lX_l+C_l\mathcal{F}_l(A_lX_l)$ 比, 只有 $\mathcal{F}_l$ 的输入混合系数从 $A_l$ 换成 $A_{l-1}$. $A_l$ 要对 $X_l$ 的全部 $nd$ 个值归约才能得到, 原式里必须先扫完一遍 $X_l$ 算出 $A_l$, 再扫第二遍做 $A_lX_l$; 换成 $A_{l-1}$ 后, 系数在进入块 l 之前就已知, 读 $X_l$ 的同一遍里既能做输入混合, 又能累加下一块要用的 $\mathcal{H}(X_l)$. $B_l$, $C_l$ 仍用本块的. 依赖一消失, $X_l$ 的每个 tile 可以同时用于输入混合和下一块的系数预测. 报告说这一错位带来的性能损失可以忽略. 丢掉的是块 $l$ 的输入混合对本块输入的即时响应: $A_{l-1}$ 是看着 $X_{l-1}$ 定的, 块 $l-1$ 写回残差流的新内容要到下一块才影响输入混合权重. 残差流的状态大小不变, 仍是 $n\times d$.

预训练保留原来的多内核实现, 部署时把残差更新, 输入混合, 系数预测, pre-norm 和 FP8 转换融进一个内核 **Mega-mHC**, 残差读一次写一次, 达到 $(2n+2)d$. 配置里 n=4, 流量从 20d 降到 10d, 按 d=5120 是每 token 每块从 10.24 万个值降到 5.12 万个(推导). 报告没有给这项改动对端到端延迟的量化结果.

### 3.2. Engram: 196B 参数的条件记忆

**Engram** 是 DeepSeek 此前提出的条件记忆模块: 用局部 N-gram 作键, 经多头哈希索引一张大嵌入表, O(1) 查表, 再用上下文门控融进残差流. 它的原论文把这看成与 MoE 条件计算互补的另一条稀疏轴. V4.1 沿用原设计的 tokenizer 压缩, 多头哈希, 上下文门控和多分支融合, 改了两处: 去掉短因果卷积, 理由是收益不抵推理栈里增加的复杂度; 嵌入表改用动量更新加 Sinkhorn 均衡来优化(见下一节).

配置是 196B 参数平均分给两个模块, 每个模块 N-gram 阶数 {2, 3, 4}, 每阶 8 个哈希头, 每阶总嵌入维 2048, 每头索引一张约 16M 条目的表, 表大小取互不相同的素数. 按每头 2048 / 8 = 256 维算, 每模块 3 × 8 × 16M × 256 ≈ 98B, 两个模块约 196B, 与报告一致(推导). 嵌入表和 K/V 投影都用 FP8, 两个模块全表约 196GB(推导). 模块放在第 1 层和第 14 层(从 0 计数), 都在 encoder 里, 理由是平衡训练流水线各阶段的显存. 推理时寻址只取决于输入 token, 可以提前经后台 RDMA 从主机内存预取, 第一个模块的预取与第一个 Transformer 块的计算重叠. 学习率乘 5. 报告没有给 Engram 在 V4.1 上的单独消融.

### 3.3. DSpark 取代 MTP

V4.1 在骨干预训练阶段去掉了 MTP 模块, 改用 **DSpark** 做投机解码. DSpark 的起草器是 3 个 Transformer 块, 滑动窗口 128, 一次前向并行算出 5 个起草位置的基础 logits, 再用一个轻量 Markov 头建模起草 token 之间的依赖. 一个置信度头预测每个位置的条件接受概率, 由此估计前缀存活概率; 调度器把这些估计和实测的引擎吞吐曲线结合, 为每个请求动态选验证长度, 目标是当前负载下系统总吞吐最大. 投机解码的一般原理见 [投机解码](../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/01-投机解码原理与应用/01-投机解码原理与应用.md).

训练方式和 V3 的 MTP 不同. V3 的 [MTP](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.1-多Token预测MTP/2.8.1-多Token预测MTP.md) 在整个预训练中与骨干联合训练, MTP 的损失也回传到骨干. DSpark 在预训练结束后单独一个阶段训练, 骨干冻结; 后训练期间继续和骨干一起训, 但 DSpark 的梯度不回传骨干. 这样 DSpark 能跟上策略的变化, 同时服务线上推理和 RL, OPD 的采样. 代价是骨干不再得到 MTP 那种额外的预测信号. 报告没有给 DSpark 的接受率, 加速比, 也没有给去掉 MTP 对 Base 质量的影响.

### 3.4. FP4 主 KV: 格式选择和动态范围

V4 已经对 indexer 的 Q 和 K 做 FP4 量化感知训练(QAT), 用的是 OCP 标准 MXFP4, 报告说选它是为了兼容尽量多的硬件, 尽管实验里别的格式精度更高. V4.1 把 QAT 扩到主 KV cache. 这里 FP4 省的是存储, 不是矩阵乘吞吐: cache 在注意力计算前反量化, 所以格式不必有原生矩阵乘支持, 可以选更准的. 在几种约 4 位的格式里, 报告选了 E2M1 元素加每 16 通道一个 E4M3 比例因子, 跟 NVFP4 一样, 但去掉了 NVFP4 的第二级全局比例因子. 与 MXFP4 相比, 这种格式的块更小, 比例因子带尾数位, 每元素摊 4.5 位, MXFP4 是 4.25 位; 一个离群值影响的邻居更少, 比例因子也不必取 2 的幂.

去掉全局比例因子的论证是数值上的. 这种格式能表示的最大幅值是 448 × 6 = 2688. V4.1 训练出的 RMSNorm 权重最大约为 1, RMS 归一化后 512 通道潜变量的 L2 范数至多约 √512; RoPE 保范数, 旋转后单通道最大绝对值也不超过约 22.6, 训练中实测最大幅值约 10. 2688 比 22.6 大一百多倍(推导), 所以省掉全局比例因子没有可测的精度损失, 还简化了 cache 布局. 量化放在 RoPE 之后: 放在 RoPE 之前精度只略好, 而且 decode 时要多一步开销. 非 RoPE 和 RoPE 部分用同一格式. SWA KV 对量化更敏感, 仍保留 FP8. QAT 在后训练引入. 相对 V4 的 FP8 主 KV, 报告说存储近乎减半, HBM 和卸到 SSD 都一样. FP8 训练的背景见 [FP8 混合精度训练](../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/02-FP8混合精度训练详解/02-FP8混合精度训练详解.md).

### 3.5. 优化器: head-wise Muon 与 Sinkhorn 均衡更新

V4.1 在 V4 的优化配置上改了两处. 第一, 查询和 key 权重用 **head-wise Muon**: 先按头切开再做 Muon 更新. 把 Muon 看成预条件梯度下降, 原版 Muon 对所有头用一个预条件器, head-wise 给每个头各一个, 能更好处理注意力头之间的异质性. 报告说 head-wise 优于原版, GLM-5 和 Kimi-K3 也验证过. Muon 本身见 [Muon](../../../llm-guide/6-训练与推理优化/6.5-优化器/6.5.2-Muon/01-Muon优化器专题/01-Muon优化器专题.md). 其余线性层, Engram 投影层和视觉语言投影器用 Muon; RMSNorm 权重和偏置, 比例因子等非矩阵参数用 AdamW($\beta_1=0.9$, $\beta_2=0.95$, $\varepsilon=10^{-20}$, 权重衰减 0.1). Muon 动量 0.95, 权重衰减 0.1, 更新矩阵的 RMS 调到 0.18 以复用 AdamW 的学习率.

第二, Engram 嵌入表, token 嵌入和输出头改用动量更新加 **Sinkhorn** 均衡(算法 1), 原因是给新增的 196B Engram 参数配 Adam 状态太占显存. 流程与 Muon 相同, 只是把 Newton-Schulz 正交化换成交替的行归一化与列归一化, 目标是式 (7):

$$
\Delta_t=\sqrt{n}\,D_r\widehat G_tD_c,\qquad \frac{1}{n}\sum_{j=1}^{n}(\Delta_t)_{ij}^2\approx1,\qquad \frac{1}{m}\sum_{i=1}^{m}(\Delta_t)_{ij}^2\approx1.
$$

$\widehat G_t$ 是 Nesterov 动量后的 $m\times n$ 更新矩阵, $D_r$, $D_c$ 是对角缩放, 只改每行每列的整体大小, 不改行内各元素的相对比例. 两个约束要求每行和每列的均方都接近 1: 一个很少出现的 N-gram 行不会因为梯度小而几乎不动, 一个被大量 token 共用的特征列也不会一步走太远. 和 Newton-Schulz 相比, 它不做正交化, 只做两个方向的尺度均衡, 所以只要维护两个比例向量.

实现上奇数步归一化行, 偶数步归一化列, 共 K=11 步. 行对应一个 token 或一个 N-gram, 列对应一个隐藏特征, 这种结构正适合双向归一化. 由于 K 是奇数, 第 11 步是行归一化, 每行 L2 范数精确为 1, 乘 $\sqrt{n}$ 后行 RMS 为 1(推导).

行范数低于平均值 $10^{-3}$ 倍的近零行被屏蔽, 避免数值不稳 (算法 1 把这个阈值记作 $\tau$, 和第 6.2 节力度衰减里的 $\tau$ 是两个量). 学习率校正 $\gamma=0.18$, 接近 Moonlight 的 0.2. 这种更新只需一个动量缓冲, 报告说实测优于 Adam, 但没有给对比曲线. 视觉编码器在学习率衰减阶段之前冻结, 衰减开始时解冻, 以较小学习率与 LLM 联合训练.

## 4. 基础设施

### 4.1. 训练基础设施: 多模态, 跨层共享与 Engram

多模态训练有三项优化. 视觉编码器的对比学习阶段要跨数据并行 rank 做 all-gather; 由于文本特征的梯度只依赖收集来的视觉特征, 反之亦然, 视觉特征的 all-gather 可以藏在文本前向后面, 文本特征的 all-gather 藏在文本反向后面. 端到端并行采用解耦编码器设计: 视觉编码器复制在 LLM 参数树之外, 每步分成视觉前向, LLM 前后向, 视觉反向三段, LLM 段保持纯文本训练的并行策略. 长序列多模态样本按上下文并行 rank 均衡切分图像, 每张图只读一次. 报告给出加载能被计算隐藏的条件 $\rho < (B_{IO}/B_{GPU}) C$, 其中 $\rho$ 是每 token 原始字节, C 是每 token 计算量; 序列长度 N 在两边约掉, 所以只有每 token 计算量小的消融小模型才会受存储带宽限制.

CSA2 的跨层共享给流水线并行带来新问题: 共享注意力组件的层可能落在不同流水线阶段. 报告用三项设计解决. **Shadow indexer** 在每个参与阶段放一个轻量可执行副本, 共享参数只有一个逻辑属主负责优化和检查点, 副本靠参数同步和梯度聚合保持一致. 流水线载荷扩展把跨阶段需要的中间表示和稀疏路由信息并入已有的点对点通信, 按上下文并行一致切分. 微批级共享状态管理跟踪并发微批的状态, 在前向, 激活重算和反向之间协调生命周期, 末位消费者用完就释放. Engram 表按行切分到专门的进程组, 优化器状态再在副本间切分; 查表索引只依赖输入, 所以每步开始前整批预取, 预取和梯度回传与视觉编码器的计算重叠; Sinkhorn 归一化只维护行列比例向量, 不反复写整张归一化矩阵; RL 采样时 Engram 表常驻显存, 避免主机内存碎片导致的 OOM.

### 4.2. 推理系统与持久化 KV 管理

报告说 V4.1 的架构概念复杂, 内核流却很短. 借助 FlashMLA 里的 RoPE-注意力-RoPE-转换融合内核, DeepGEMM 里的 Mega-Gate, Mega-mHC, Mega-MoE, 以及 TileKernels 和 DeepSelect 的 TopK 内核, 绝大多数层(即 Reuse 模式的 CSA2 层)prefill 只需 15 个内核, decode 只需 11 个. 部署上采用 Encoder–Prefill–Decode(EPD)解耦, 视觉编码, prefill 和 decode 独立扩展并重叠执行.

持久化 KV 缩到 V4 的 1/8, 是两个因子相乘: 持久化缓存不再存 SWA KV, 体积近乎减半; 留下的 global KV 又经架构和精度压到 V4 的 1/4. V4 部署时 SWA KV 占了持久化缓存近一半容量; global KV 整段存, 命中即复用整个前缀; SWA KV 只在 prompt 末尾和输出末尾两个位置存, 用于重新生成和多轮会话. 为保命中率, V4 配了足够大的 SSD, 典型负载下两类 KV 都能驻留 72 小时以上.

问题在于 SWA KV 的访问模式与长驻留策略不匹配: global KV 有长尾复用, SWA KV 只在活跃会话内分钟级复用, 会话结束或下一轮开始就失效. V4 报告提出过 Zero SWA Caching, 缺失时重算, 但精确恢复要对 $L \times n_{\text{win}}$ 个 token 做完整前向, 生产上代价过高. V4.1 于是把 SWA KV 移到每台机器 10% 主机 DRAM 组成的分布式内存池, TTL 只有几分钟, 过期立即回收给新会话; global KV 留在持久化缓存, 保证至少 72 小时.

### 4.3. SWA Bounded Replay: 用近似状态换存储

SWA 的依赖逐层累积, 精确重建 L 层的 SWA KV 需要回放 $L \times n_{\text{win}}$ 个 token. **SWA Bounded Replay** 只回放最近 $n_{\text{win}}$ 个 token, 并把 SWA 截断在回放段内: 回放从位置 s 开始时, 位置 i 的查询只看 $[\max(s, i-W+1), i]$ 内的 SWA key. 得到的状态是近似的. Encoder 侧, 命中 global KV 但缺 SWA KV 时, 回放已缓存前缀的末尾 $n_{\text{win}}$ 个 token, 与未缓存的后缀一起处理; 回放 token 只重新生成 SWA KV, 复用已缓存的 global KV, 不重算也不覆盖; 后缀则同时生成 global KV 和 SWA KV. 按配置, 精确恢复要 40 × 128 = 5120 个 token 的前向, 有界回放只要 128 个, 少 40 倍(推导). 报告称这一设计把灾难性的 miss 变成代价很小的降级, 这是把 SWA KV 移出持久化缓存的前提.

回放状态是近似的, 因此未缓存后缀算出的 global KV 和 SWA KV 取决于命中位置, 不同命中位置得到的结果在数学上并不相同. 同一段对话是否命中缓存, 会让模型看到略有差别的状态. Decoder 侧每次 prefill 回放 prompt 末尾 $n_{\text{win}}$ 个 token, 把它们的 encoder 输出送过 decoder 各层, 得到的 decoder SWA KV 只用于 decode, 不写入前缀缓存. 报告称两者对回答质量的影响可以忽略, 并在后训练中模拟同样的回放做适配; 但没有给出量化的质量对比, 第 6 节也把 SWA 状态重建列为尚未完全刻画的风险.

缓存命中但 SWA KV 已过期时, prefill 节点会对已缓存前缀的末尾 128 个 token 重跑前向. 回放 token 的 SWA 只访问回放段内部, global 注意力仍读取已缓存的 global KV. 持久化缓存只保存 global KV; SWA KV 留在 TTL 为数分钟的 DRAM 池中, 到期便回收. 重新得到的 SWA 状态截断了更早的局部依赖, 因此同一段对话在不同命中位置上可能生成略有差异的后续 KV, 无法与无缓存的完整前向逐位一致.

## 5. 预训练

### 5.1. 数据: 去隐式重复, 原生网页多模态, 7:1 配比

文本数据的思路是超越小规模实验反映的样本级质量, 更看重不同语料之间的信息增益互补. 报告设计了一条模型参数与训练数据的 Scaling 阶梯来指导大规模训练; 过滤信息增益有限的模型生成内容, 包括较弱模型的输出和低质量机器翻译, 把它们视为 「隐式重复」, 认为长训练周期下有害. 引入更多领域专家定义细粒度质量维度; 代码语料加入新开源仓库, 提交, 库和框架. 报告还提到在探索模型在环的数据迭代, 作为未来大规模合成数据的基础, 但没有给出比例.

多模态数据分图文对, 图文交错和领域数据三类. 报告的前提是原生网页已经含有丰富的多模态知识, 所以没有做大规模合成, 优先清洗并利用原生形态. 最初的爬虫偏向文本网页, 于是从 Common Crawl 重新引导以提高多模态覆盖. 图文对按相关性阈值过滤, 按图像语义去重; 交错数据主要来自网页和 PDF, 按成本递增分阶段处理: 先做启发式, 统计过滤, 去重和质量模型, 再组装成图文序列并做图像感知的二次过滤, 末轮用 **SmolVLM** 严格打分; 被筛掉的文档部分回收成图文对. 领域数据补视觉定位, 指点, OCR 和长尾知识, 另收集大量图像-代码对和计算机使用轨迹. 文本与多模态两条流水取并集, 重叠样本用多模态版本替换并取两者较大的 epoch 数, 最终纯文本与多模态的 token 比为 7:1; 若按 45T 摊, 多模态约 5.6T. 超长文档混合前确定性预切分, best-fit packing 的填充率至多 $10^{-4}$.

### 5.2. 视觉编码器: 两阶段训练与分辨率

**DeepSeek-ViT** 从零训练, 32 层, 隐藏维 1024, 16 个注意力头, patch 14. 为支持任意分辨率, 用 2D-RoPE 取代绝对位置编码; 为兼容 Muon, patch 嵌入的卷积换成线性投影; 归一化用 RMSNorm, 激活用 SwiGLU. 进入 LLM 前做 3 × 3 pixel-unshuffle, 视觉 token 数除以 9, 再经 2 层 MLP 投影器映射到 5120 维. 最大输入约 1344 × 1344, 即 96 × 96 = 9216 个 patch, 除以 9 得 1024 个视觉 token(推导). MoE 的负载均衡对图像和文本 token 各维护一套专家校正偏置, 选专家时用各自模态的偏置, 加权仍用原始路由分数, 两套偏置按各自负载独立更新, 更新速度都是 0.001; 另保留权重 0.0001 的序列级平衡损失. 无辅助损失均衡的基本机制见 [DeepSeekMoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md).

ViT 先单独训练两阶段. 对比预训练用 SigLIP 的 sigmoid 对比损失, 在约 47B 图文对上训, 输入最大 224 × 224, 即 256 个 patch(推导); 报告说这一阶段用更高分辨率虽有明显收益, 但对最终模型贡献很小, 因为下一阶段专门处理高分辨率. 自回归微调阶段把 ViT 接到一个 4B 的 MoE LLM 上, 用 next-token prediction 在 236B token 上训, 数据包括图像描述, alt 文本, 图表和 OCR, 分辨率限制在 544 × 544 到 1344 × 1344 之间, 对应约 160 到 1024 个视觉 token(推导). 训完丢掉 LLM, 只留 ViT 进入正式预训练, 分辨率策略保持不变. 多模态模型的一般结构见 [多模态](../../../llm-guide/8-多模态/8-多模态.md).

### 5.3. 预训练日程与算力估算

第 4.2.2 节的日程是: batch 固定 100.6M token; 学习率前 2000 步线性预热, 之后保持 $2.6\times10^{-4}$ 直到 28T token; 28T 到 40T 按余弦降到 $2.6\times10^{-5}$; 40T 到 45T 保持这个低值. 稀疏注意力从 64K 序列长度从零开始训, 没有稠密注意力预热阶段; 34T token 时序列长度扩展到 1M. 训练全程没有不稳定. 与 V4 一样使用样本级注意力掩码. 对比 V3.2 需要先做稠密预热再切稀疏, V4.1 直接从稀疏起训, 说明 CSA2 的 indexer 可以和主干一起从零学.

按固定 batch 算, 45T token 约 **44.7 万**步, 预热 2000 步约 0.2T token, 恒定学习率段占总 token 的约 62%. 1M 扩展发生在余弦衰减段中间, 此后约 11T token 在允许 1M 序列的设置下训练, 报告没有给各长度的数据占比. 训练时每个 token 仍经过全部 40 层计算损失, 所以按 16B 激活算, 训练算力约 6 × 16B × 45T ≈ **4.3e24** FLOPs, 不含注意力和 Engram 查表; V4-Flash 按 13B 激活和 32T token 约 2.5e24, V4.1 约为它的 1.7 倍. Scaling 的背景见 [Scaling Law](../../../llm-guide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).

## 6. 后训练, 评测与局限

### 6.1. 后训练: 任务合成, 环境与 DSec

第 5.1 节开宗明义: 这一版不引入新的后训练算法, 配方仍是 SFT, RL, 再接 On-Policy Distillation(OPD), 不超出 V4 开发中的成熟做法; 精力几乎全在 「训什么」 而不在 「怎么优化」. 每个任务被形式化为 「问题, 环境, 验证系统」 三元组, 按难度(任务不平凡)和正确性(三部分没有关键缺陷)评价, 并用这两维作奖励训练模型去构造更好的任务; 任务每进入一次新的 RL 跑次, 产生的轨迹又成为质量复审的证据.

通用 Agent 流水鼓励内部员工和外部伙伴在日常工作中用最新模型, 自愿回传交互和反馈, 据此构造大量模拟工具, 并把收集到的负反馈和失败案例回放成单轮和多轮环境.

编码 Agent 流水的来源是复杂或模型表现差的编码会话, 以及达到星数阈值的 GitHub 仓库; 多个专用 Agent 分工判断能否容器内构建与自动验证, 设计 fail-to-pass 和 pass-to-pass 评测点, 装依赖自测, 清除泄题痕迹, 再由独立质检 Agent 检查环境问题和可被投机利用的风险, 不过就交给修复 Agent. RL 部分见 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md) 和 [Agentic RL](../../../llm-guide/13-Agent/13.4-Agent训练与进化/13.4.1-AgenticRL训练/13.4.1-AgenticRL训练.md).

RL 在两个方向上放大: 训练算力和 scaffold 数量. 跨 scaffold 训练时, rollout 拆成运行 scaffold 与工具的沙箱, 和一个与 scaffold 无关的控制层, 后者把异质交互归一成统一轨迹格式; 两者都跑在 **DSec** 上, 在可抢占的 GPU 训练池之外. 图 7 读图: 在 DeepSeek Harness 的 Minimal 模式下, 累计约 1900 步 RL(512K 上下文)把 DeepSWE v1.1 从约 57% 推到约 72%, 末段约 230 步把上下文扩到 1M, Terminal-Bench 3.0 从约 17% 升到约 27%. 曲线分成三段, 断点是模型合并后重新初始化的新跑次; 每次合并后输出 token 明显回落, 例如 DeepSWE 第二段开头从约 200k 回到约 150k, 随后一度降到约 100k, 同时 Pass@1 掉了三四个点 (读图). 报告说合并同时提升了任务表现和 token 效率; 图上能直接看到的是 token 明显下降, 准确率在合并点先小幅下降, 随后的 RL 再把它推高.

DSec 此时要支撑数百万并发沙箱: 计算节点分片, 用放松一致性的自研调度器替代 Kubernetes, 各节点自行做准入校验; 节点内用 sub-NUMA 分区, 单物理节点的并发活容器从约 1000 提升到 2500 以上; 时延敏感任务单独一类, 非敏感任务用 `SCHED_IDLE`, 并用 core scheduling 隔离超线程. 训练中 Agent 利用过 XFS 权限问题, AppArmor 非法内存访问, 包镜像服务泄露答案等漏洞, 还会删关键二进制甚至文件系统; 报告用逐沙箱 AppArmor 配置和 eBPF 网络策略防护, 环境崩溃按失败轨迹处理.

### 6.2. 可控推理力度 b

V4 的推理力度是 Non-think, High, Max 三个离散档. V4.1 改成标量 $b \in \{1, \ldots, 100\}$, 写进系统提示: 「Reasoning Effort: {effort} (range 1–100; higher values request more thorough reasoning)」. 每个训练 prompt 在每个力度档上采样多条响应, 相同 $(x, b)$ 构成子组, 组内奖励均值中心化后算组相对优势, 所以不同力度的响应不直接比较. 力度行为靠长度惩罚诱导: 式 (9) 的惩罚为 $-\min\{C_{\max}, k(b)\,\ell/L_{\text{norm}}\}$, 式 (10) 让系数 $k(b) = k_0 \exp(-(b-b_{\min})/\tau)$ 随力度指数衰减, $b$ 每增加 $\tau$, 系数乘 $e^{-1}$. 报告没有给 $k_0$, $\tau$, $\lambda$, 训练用的力度档集合等具体数值. 推理能力与长度的一般讨论见 [推理与思考能力](../../../llm-guide/4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).

附录 C 给出指数形式的动机. 对固定问题, 设 $p_x(\ell)$ 是花 $\ell$ 个推理 token 后的解出概率, 最优长度满足 $p_x'(\ell^*) = k(b)/L_{\text{norm}}$. 若边际收益近似指数衰减 $p_x'(\ell) \approx a_x e^{-\ell/s_x}$, 代入得 $\ell^* \approx C_x - s_x \log k_0 + (s_x/\tau)(b-b_{\min})$, 即偏好长度与力度局部呈仿射关系, 两档之差约为 $(s_x/\tau)(b_2-b_1)$. $k_0$ 管整体压短的力度, $\tau$ 管对力度的敏感度. 报告明确说这是局部的奖励层近似, 不主张实测平均长度必须线性或处处单调; 力度指令可能直接改变推理策略, Agent 轨迹轮数不同, 子组归一化也会改变优化强度, 而且推导假设惩罚上限未触发. 生产 API 于 2026 年 9 月上线, 暴露 max, high, low 三档, 分别对应 b=100, 75, 50(表 2).

### 6.4. 异步后训练基础设施与大规模 OPD

RL 的 rollout 长尾一直是训练效率瓶颈. V4.1 把 rollout 和训练放在同一批设备上分时执行, 每个任务设定在途样本数上限, 系统在整个 rollout 阶段维持这个上限. 派发粒度试过三种: 批级派发(开头多发几批, 每次迭代后补一整批)导致训练指标剧烈振荡; prompt 级派发(一个 GRPO 组完成后再发新 prompt)容易卡在组内的长尾样本上; 最终采用样本级派发, 新完成的样本数一达到下一个 prompt 的 GRPO 组大小就派发, 不管这些样本来自哪个组. 样本够了训练就抢占 rollout. 跨多个检查点生成的样本, 把各段 rollout 的专家路由拼接起来做 routing replay, 不丢弃重算. GRPO 的计算细节见 [GRPO 计算流程](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

异步生成有两个副作用. 一是长度分布偏差, 训练早期短样本先完成, 占满最初的 batch; 对策是按数据集限制并发, 间接控制稳态 batch 的来源比例, 并丢弃过早返回的短样本. 二是 off-policy 样本; 对策是调整派发和等待条件, 给最大 off-policy 比例设上限, 并对过时太多的 token 做 loss mask. 生成支持 token 级中断, KV cache 和专家路由按 token 粒度持久化, 换检查点后直接复用, 不用重新 prefill, 样本完成即回收其状态; 同一机制让训练作业能响应集群抢占而不丢进度. 后训练第 11 步是全词表 OPD, 在所有领域数据上用 **40 个以上**教师, 教师可以来自不同开发阶段, 彼此架构不同, 也可以和学生架构不同; 训练中还会动态调整数据配比, 各数据集并发上限和启用的教师. V4 用的是十个以上教师, V4.1 把数量翻了几倍. OPD 的机制见 [OPD](../../../llm-guide/4-后训练/4.9-OPD/4.9.1-OPD方法与落地/01-OPD基础原理/01-OPD基础原理.md) 与 [On-Policy Distillation](../../../llm-guide/4-后训练/4.9-OPD/4.9.1-OPD方法与落地/01-OPD基础原理/01-OPD基础原理.md).

### 6.7. 局限与谱系位置

## 7. CSA2 的完整选择链

设压缩器把 $N$ 个 token 映成 $M$ 个条目 $z_j$, Indexer 用查询 $q_t$ 计算粗分数 $u_{t,j}=f(q_t,z_j)$, 选择集合

$$
S_t=\operatorname{TopK}_j(u_{t,j},k).
$$

主注意力只在 $S_t$ 内计算精分数 $a_{t,j}=\operatorname{softmax}_{j\in S_t}(q_t^{\mathsf T}k_j/\sqrt d)$, 输出 $o_t=\sum_{j\in S_t}a_{t,j}v_j$. 候选生成决定可见集合, 精排决定集合内权重, 聚合决定值信息如何返回. 任一级丢失的信息都无法由后级补回.

将密集注意力分布记为 $p$, 稀疏集合外质量为 $\delta=\sum_{j\notin S}p_j$. 若 $\|v_j\|\le M_v$, 对集合内概率重新归一化后, 输出差满足

$$
\|o-\hat o\|\le 2\delta M_v.
$$

推导来自两部分: 被删项范数至多 $\delta M_v$, 剩余权重因除以 $1-\delta$ 产生的变化同样至多 $\delta M_v$. 这个界说明关键指标是漏掉的注意力质量, 不是位置召回数. 漏一百个几乎零权重位置可能无害, 漏一个占 0.4 的证据会造成大误差.

若压缩条目各代表一组原 token, 条目被选中后还需恢复或聚合组内信息. 平均池化会消除组内次序, 加权压缩则依赖压缩 query. 两段近似分别产生「组间漏选」与「组内信息损失」. 提高 $k$ 只能修复前者, 无法恢复压缩时已经丢掉的细节.

## 8. 稀疏选择怎样训练

Top-K 是离散操作, 未选条目拿不到主注意力梯度. Indexer 可通过连续粗分数的辅助目标、教师注意力蒸馏或选中路径的近似梯度学习. 若只靠最终语言损失, 早期误选会让正确条目长期没有训练信号, 形成自我强化.

理想教师可用密集注意力质量构造目标分布 $p_j$, Indexer 分布为 $r_j$, 辅助损失可写成 $D_{KL}(p\|r)$. 它要求训练时计算密集教师, 成本高; 可只在短序列、抽样层或少量 batch 上使用. 若论文未公开辅助权重、教师来源与负样本策略, 外部无法精确复现选择器质量.

负样本太容易时, Indexer 只会区分无关段落; 真正困难的是近重复、同实体不同时间和多证据弱相关. 应按困难负样本分桶报告 recall@k 与加权漏失 $\delta$, 再与最终 loss 对齐.

## 9. CED 的线性代数视角

逐层独立缓存可写成 $K_l=XW_l^K,V_l=XW_l^V$. CED 共享记忆 $Z=XP$, 后层只能通过 $K_l=ZA_l,V_l=ZB_l$ 读取. 合成矩阵秩受 $\operatorname{rank}(P)$ 限制, 各层虽有不同 $A_l,B_l$, 可用的历史输入子空间相同.

若各层所需子空间高度重合, 共享几乎无损; 若浅层需要词法方向、深层需要与其正交的语义方向, $P$ 容量不足时必须舍弃一部分. 反例可构造两组独立属性, 前半任务只查询第一组, 后半只查询第二组, 共享维度小于两组秩之和便无法同时无损保存.

增加共享记忆宽度、设置多个更新点或残留少数独立层都能扩大表达力, 代价是缓存上升. 扫描更新间隔与记忆维度, 观察质量—字节 Pareto 曲线, 比单一正式配置更能证明设计选择.

## 10. 并发缓存账

890 字节乘一百万 token 为 890MB 十进制, batch 1、8、32、64 分别约 0.83、6.63、26.52、53.05GiB. 若再加每组 scale、对齐与运行时索引, 实占更高. 对话前缀共享可让多请求引用同一物理缓存, 独立长文则不能共享.

若对照 V4-Flash 的 3514 字节, 百万 token 单请求约 3.27GiB, batch 32 约 104.7GiB; V4.1 同 batch 约 26.5GiB, 差约 78GiB. 这笔显存可换成更多并发或更大权重驻留, 吞吐收益仍取决于计算与调度.

## 11. 同坐标比较几条路线

HCA 用层级压缩减少可读条目, CSA 用学习 Indexer 做内容选择, CSA2 再强化跨层共享与统一压缩路径. NSA 将局部、压缩和选择三条注意力分支组合, DSA同样把稀疏索引作为主注意力前的候选器. HySparse2 也受跨层共享思路启发, 重点在共享专家式索引与残差补偿. 这些路线可按四轴比较: 条目宽度、保留位置数、独立缓存层数、选择器成本.

名称相近不代表算子等价. 比较必须回到候选从哪里来、索引是否跨层共享、漏选如何补偿、局部窗口是否常驻以及训练信号怎样进入 Indexer. 官方材料未给出的发布时间优先级和相互影响不作为技术结论.

## 12. 复现缺口

完整复现还需要压缩率、各模式层号、Top-K、Indexer 隐宽与分层候选数、辅助损失权重、选择温度、FP4 分组与 scale 格式、训练阶段是否使用教师注意力. 报告公开最终缓存与主要结构, 部分训练超参仍不足.

表格复算能核对字节、参数和相对倍率, 不能恢复这些隐含选择. 若外部实现分数不同, 应先分别测压缩重建误差、Indexer 加权召回、FP4 数值误差与跨层共享误差, 再归因到整体 CSA2.

## 13. CSA2 与 CED 的核心关系

CED 与 CSA2 压缩的是两个不同维度. CED 把网络沿深度分成「自解码」和「交叉解码」部分: 前半段建立可供后半段读取的表示, 后半段不再为每层独立保存完整输入序列状态. 这一思想来自 YOCO 的 decoder-decoder 结构. CSA2 则决定 global attention 在哪些层建立压缩条目、怎样由 Indexer 从长序列选择少量位置. 一个压层数, 一个压被读取的位置数.

设序列长度为 $N$, global KV 条目宽度为 $d_c$, 独立 global 层数为 $L_g$. 普通逐层缓存量与 $NL_gd_c$ 成正比. 跨层共享后, 若 $m$ 层共用一组 KV, 缓存降为约 $NL_gd_c/m$. CSA 再只保存或访问压缩候选, decode 计算从遍历 $N$ 个位置变成 Indexer 评分加 Top-$k$ 精读. 两项收益相乘的前提是共享层确实使用同一份可索引表示.

「受 YOCO 启发」不等于复制 YOCO. YOCO 的关键是只缓存一次并由 cross-decoder 重用; V4.1 把这一跨层复用原则嵌入已有 MLA/CSA 路线, 还要兼容局部 SWA、压缩器、Indexer 与 MoE. 准确关系是设计启发与结构继承, 不能写成两套架构完全等价.

## 14. CSA、HCA 与 CSA2

V4 将 HCA 与 CSA 混合. HCA 让部分层使用层级压缩表示, CSA 用 Indexer 在压缩条目中选择候选. V4.1-Flash 改成纯 CSA2, 目标是让压缩、索引和跨层共享形成统一路径, 减少同时维护两类 global attention 的复杂度. 这项变化属于长上下文与缓存路线, 与 Coder 系列的代码专项数据无关.

CSA2 的三种层模式可按信息流理解: 某些层负责生成或更新压缩记忆, 某些层复用已有记忆做稀疏读取, 局部层继续处理邻近 token. 若每层都重新压缩, 跨层缓存节省消失; 若所有层永远共享一份记忆, 深层无法写入新的抽象特征. 分层排布是在更新频率与复用程度之间取舍.

压缩器把若干 token 表示映成较少条目. 设压缩率为 $r$, 条目数约 $N/r$. 若 Indexer 对全部条目打分并选 $k$, 粗筛成本为 $O(N/r)$, 精读成本为 $O(kd)$. 当 $N$ 很大、$k$ 固定时, 相比 full attention 的 $O(Nd)$ 显著下降. 若 Indexer 本身用高维 query 与全部条目做昂贵点积, 粗筛仍可能成为瓶颈, 因而报告强调简化与分层索引.

## 15. Indexer 的误差模型

设 full attention 真正贡献最大的集合为 $S^*$, Indexer 选择 $\widehat S$. 召回率为 $|S^*\cap\widehat S|/|S^*|$. 漏掉一个低权重位置影响很小, 漏掉唯一关键证据可能让答案完全改变. 因而平均召回不足以描述质量, 还要按被漏位置的真实注意力质量加权.

若完整输出为 $o=\sum_i a_iv_i$, 稀疏集合归一化后的输出为 $\hat o$, 被漏注意力质量记作 $\delta=\sum_{i\notin\widehat S}a_i$. 在值向量范数不超过 $M$ 时, 输出误差可由与 $\delta M$ 同量级的界控制. 当注意力集中且关键位置被选中, $\delta$ 很小; 当注意力分散到大量证据, 固定 $k$ 会丢掉较多质量.

反例是长文中有许多弱证据, 每处单独得分不高, 合起来决定结论. Top-$k$ 偏爱少数强匹配, 可能漏掉累积信号. 另一个反例是两个近似段落只有一个数字不同, Indexer 的低维表示无法区分, 选到错误版本. 应加入多证据聚合、近重复消歧和位置对抗测试, 不能只测单针检索.

分层 Indexer 可先用便宜表示筛大范围, 再用更强表示排序候选. 两级召回相乘: 第一层召回 $r_1$, 第二层在第一层候选内召回 $r_2$, 总召回约 $r_1r_2$. 第一层漏掉的条目无法被后级找回. 所以最早一级应偏向高召回, 后级负责精度.

## 16. 890 字节的口径

每 token global KV 字节数应写成各类持久化条目的总和:

$$
B_{global}=\sum_j L_jd_jb_j/c_j,
$$

$L_j$ 是该类缓存覆盖的层数, $d_j$ 是每层元素数, $b_j$ 是每元素字节, $c_j$ 是跨层共享或序列压缩因子. 890 字节是 V4.1-Flash 整套 global 路径在报告配置下的结果, 同时包含跨层共享、压缩与 FP4. 把它全归给 CSA2、CED 或 FP4 任一单项都会重复归因.

一百万 token 的 global KV 按 890 字节计算约 890MB, 按二进制约 849MiB. batch 64 约 53.1GiB, 尚未计局部 SWA 状态、量化尺度、页表、对齐和运行时工作区. 这个手算说明单条百万上下文已从数百 GB 级降到不足 1GB, 并发服务仍需精细管理.

FP4 把同元素数量的字节约降为 FP8 的一半、BF16 的四分之一, 实际还需 block scale 与打包元数据. 若每组 $g$ 个 4 bit 值共享一个 16 bit scale, 平均每元素额外 $2/g$ 字节. $g=64$ 时为 0.03125 字节, 相对 0.5 字节增加 6.25%. 因而理论位宽与实测显存应分开.

## 17. CED 的表达边界

逐层独立 KV 允许每层从自己的表示空间读取历史. CED 让后半网络共享前面构建的记忆, 缓存更小, 也限制了深层为历史 token 重新编码的自由. 当前 token 的深层 query 仍会变化, 它可以用不同方式读取同一记忆; 历史 value 的表示却不随每个深层重新生成.

若前半网络已经提取足够信息, 后半层共享不会伤质量. 若某项深层抽象只有经过多层交互才形成, 共享记忆可能缺少它. 反例可构造为需要先在浅层解析局部结构、再在深层根据新语义重新标记远处 token 的任务. 增加记忆更新层或让少数层写回可以缓解, 同时增加缓存.

消融应固定参数和训练 token, 扫描自解码与交叉解码层比例, 报告短文本、单针、多证据、长代码和困惑度. 若某比例缓存更低且各项持平, 支持共享充分; 若长程组合先下降, 它标出 CED 的表达边界.

## 18. 训练目标与架构信用

CSA2、CED 仍通过语言建模目标端到端学习. Indexer 若有额外监督或蒸馏目标, 其作用要与主损失分开; 只凭最终模型分数无法知道选择器靠何种信号学会检索. 压缩器、索引和主注意力共同训练时, 表示会适应稀疏路径, 事后把 full attention 换成 Top-$k$ 的结果不能代替从头训练消融.

V4.1 同时改变 CSA2、CED、FP4、Engram、DSpark、优化器、多模态数据与后训练. 正式模型相对 V4 的端点差异不能归因于单一注意力改动. 最有力证据来自固定其余配置的消融; 报告未覆盖的组合效应应保留为空白.

与 YOCO、V4 HCA/CSA 的关系也应按证据强度写: 论文明确声明的启发和继承属于一手事实; 从结构相似推断的共同机制属于分析; 社交传播中的命名、热度和发布时间叙事不构成技术证据.

## 19. 可证伪实验

第一, 固定模型与数据, 比较 V4 混合 HCA/CSA、纯 CSA2、CSA2 加 CED. 同时报缓存字节、prefill FLOPs、decode 延迟和长程任务. 这能拆出 CSA2 与跨层共享的边际贡献.

第二, 对 Indexer 做 oracle 对照. 用 full attention 的真实高权重位置作为候选上限, 与学习 Indexer、随机选择和局部窗口比较. 若 oracle 很好而学习 Indexer 差, 问题在检索; 若 oracle 也差, 固定 $k$ 或压缩表示本身不足.

第三, 扫描 $k$ 和压缩率. 质量随 $k$ 增长应趋近密集对照, 延迟与缓存随之上升. 若提高 $k$ 仍无法恢复, 误差来自压缩器或跨层共享, 并非漏选位置.

第四, 分别使用 BF16、FP8、FP4 KV, 固定选择集合, 测逐层输出误差与任务质量. 再固定精度改变 CSA2, 避免把量化误差记到稀疏结构头上.

第五, 做近重复、多证据和超长代码压力测试, 按证据数量、距离与干扰相似度分桶. 若标准 benchmark 持平而这些桶下降, 「未发现系统退化」只适用于现有测试覆盖.

## 20. 稀疏注意力路线中的位置

从 full MHA 到 GQA/MQA, 早期路线主要减少每个 token 的 KV 头数; MLA 把 K/V 联合压进潜变量, 减少条目宽度; CSA/HCA 开始减少长序列中需要精读的条目; CSA2 与 CED 再把跨层复用纳入设计. 这是一条沿「头、宽度、序列、层」逐维压缩的路线.

Indexer 因此越来越重要. 当每层都看全部历史时, 注意力分数本身完成选择; 当主注意力只看少数候选时, Indexer 决定哪些信息还有机会进入计算. 它的召回上限直接限制主注意力, 计算占比和训练信号也成为架构核心.

这条路线并不说明稀疏越激进越好. 每压一个维度, 都增加表示约束或检索错误. V4.1-Flash 用内部评测证明整套方案可用, 仍需对极端长程组合、相似干扰与缓存恢复做独立压力测试. 它的贡献是把多维压缩推到可部署配置, 不是宣布 full attention 在所有任务上失去价值.

## 21. Indexer 的监督从哪里来

分层 Indexer 在后训练阶段启用, 后续 Reindex 层训练时看到的搜索域与推理一致: 第一层先从全局位置中形成块候选, 后续层只在至多 16,384 个候选位置里重打分. 这条约束很重要. 若训练时后续层能在完整序列里寻找正例, 推理时却只能在第一层候选里寻找, 训练目标会把第一阶段的漏召回藏起来. 令第一阶段候选为 $C_t$, 最终稀疏集合为 $S_t\subset C_t$, 主注意力损失为 $\mathcal L_{\mathrm{LM}}$. 对后续层而言, 正确的条件分布是

$$
p(j\mid j\in C_t,q_t),\qquad j\in C_t,
$$

而不是全序列分布 $p(j\mid q_t)$. 第一阶段需要承担把有效位置送入 $C_t$ 的责任, 第二阶段负责在 $C_t$ 内排序. 两层若共用一个笼统的 recall@512, 很难判断失败发生在哪里.

可复算的正例集合可以由密集教师构造. 对同一查询 $q_t$, 先计算密集注意力质量 $a_{t,j}$, 再取能覆盖累计质量 $1-\epsilon$ 的最小集合 $P_t$. 这种定义比固定取教师 Top-$k$ 更稳: 尖峰分布可能只需几个位置, 平坦分布则需要更多位置. 对块级候选, 位置正例再映射为块正例

$$
y_{t,b}^{+}=\mathbb 1\!\left[\sum_{j\in b}a_{t,j}\ge \tau_b\right].
$$

若只用「块内最大教师权重」标正, 一个偶然尖峰便能让整块过关; 若只用块内总质量, 大块又天然占优. 固定八位置的块降低了后一项偏差, 仍应同时保留最大值与质量和, 让块级目标兼顾唯一关键证据和多处弱证据.

负例至少分三类. 第一类是随机远处位置, 它们帮助模型建立粗粒度主题边界, 但很快会变得太容易. 第二类是词面相似的困难负例: 同一实体、同一函数名或同一段模板, 其中日期、参数或调用关系不同. 第三类是竞争证据: 单独看每段都与问题相关, 只有组合后才能判断哪一段适用. 可把负例权重写成

$$
w_j=\lambda_0+\lambda_1\operatorname{sim}_{\rm lexical}(q_t,x_j)
     +\lambda_2\operatorname{sim}_{\rm teacher}(q_t,x_j),
$$

其中第三项取教师给出中等分数但未进入正例集合的位置. 训练批若只保留随机负例, Indexer 会学成主题分类器; 加入近重复负例后, 它才被迫利用数字、时间、否定词和局部依赖.

多证据任务还需成组正例. 假设结论依赖 $j_1,j_2,j_3$ 三处证据, 单独任一处的教师权重都不高, 按逐位置阈值会把它们全标成负例. 更合适的样本单位是超边 $E=\{j_1,j_2,j_3\}$, 损失要求候选至少覆盖其中规定数量:

$$
\mathcal L_{\rm cover}=\max\left(0,m-\sum_{j\in E}\mathbb 1[j\in C_t]\right).
$$

离散指示在实际训练中可换成候选概率之和的光滑近似. 这类监督直接对应长文归纳、跨文件调用链和时间线核对, 也解释了单针检索很高时多证据任务仍可能失败.

## 22. 从召回到最终语言损失的因果拆分

Indexer 质量、集合内注意力质量和最终语言损失是三段不同的因果链. 第一段问证据是否进入候选池, 第二段问进入后是否被选中并得到足够权重, 第三段问值向量携带的信息能否被后续网络利用. 记第一阶段候选为 $C$, 最终集合为 $S$, 教师重要集合为 $P$, 可以分别报告

$$
R_C=\frac{\sum_{j\in P\cap C}a_j}{\sum_{j\in P}a_j},\qquad
R_S=\frac{\sum_{j\in P\cap S}a_j}{\sum_{j\in P}a_j},
$$

以及集合内重归一化后输出误差 $E_o=\|o_{\rm dense}-o_S\|_2$. $R_C$ 低说明块候选已经漏证据; $R_C$ 高而 $R_S$ 低说明 Reindex 排序有问题; 两者都高但 $E_o$ 大, 通常指向压缩条目或 FP4 值误差. 继续比较教师强制集合下的语言损失, 才能把表示问题与检索问题分开.

一组四臂干预足够形成最小因果拆分. A 臂使用完整系统; B 臂只把候选换成密集教师候选, 保留压缩 KV 与 FP4; C 臂在 B 的基础上把 KV 换回 BF16; D 臂使用密集 BF16 注意力. 令四者损失为 $L_A,L_B,L_C,L_D$, 则

$$
\Delta_{\rm retrieval}=L_A-L_B,\quad
\Delta_{\rm quant}=L_B-L_C,\quad
\Delta_{\rm sparse}=L_C-L_D.
$$

这些差值不是严格可加的结构因果效应, 因为组件之间存在交互; 它们是在同一 checkpoint 上做替换干预得到的局部归因. 再交换干预顺序, 例如先恢复 BF16 再换教师候选, 两套结果的差异恰好刻画「量化改变排序」这一交互项.

最终 token loss 对少量灾难性错误并不敏感. 百万 token 中只有一个关键定义被漏掉, 平均困惑度几乎不动, 具体回答却会完全错误. 所以还要按样本计算反事实损失差: 对每个带已知证据位置的样本, 强制加入该位置, 观察答案 token 的负对数似然下降多少. 若加入证据后损失大幅下降, 可把失败归到检索; 若证据已经选中而损失不降, 问题更接近推理或值表示.

## 23. 两级候选的复杂度与显存

设序列含 $N$ 个可索引位置, 第一阶段按八位置一块形成 $N/8$ 个块, 最多保留 $B=2048$ 块, 候选位置数 $M=8B=16{,}384$, Reindex 层数为 $R=4$, 每层最终选择 $k=512$. 若块分数由第一层位置分数归约而来, Full 层仍需为 $N$ 个位置计算分数, 后续层只需计算 $RM$. 打分次数为

$$
C_{\rm score}(N)=N+R\min(N,M).
$$

在 $N=1{,}000{,}000$ 时为 1,065,536 次, 对应五个层各扫完整序列的 5,000,000 次, 仅 decoder 的 Indexer 打分减少约 78.7%. 在 $N=32{,}768$ 时为 98,304 对 163,840, 降幅约 40%; 在 $N\le16{,}384$ 时两者都要扫全序列, 分层候选不再减少分数计算, 还多出块归约与 Top-K 调度. 因而这项设计主要服务超长上下文, 短上下文收益来自跨层 Reuse, FP4 和较小激活骨干.

稀疏率也有两个口径. 第一阶段保留率为 $\rho_1=M/N$, 第二阶段为 $\rho_2=k/M$, 总保留率 $\rho=k/N=\rho_1\rho_2$. 百万位置时 $\rho_1=1.6384\%$, $\rho_2=3.125\%$, 总保留率约 $0.0512\%$. 当 $N=32{,}768$ 时第一阶段保留一半, 总保留率约 $1.56\%$. 固定 $M$ 和 $k$ 让计算增长缓慢, 同时意味着序列越长, 每个保留槽位承担的历史范围越大. 长度外推最先冲击候选召回, 不能只看固定 Top-512 的注意力内核是否稳定.

候选显存需要区分持久状态和单步工作区. global KV 的 890 字节每 token 是跨请求持久化的主体; 候选索引若用 32 位整数, 单查询单 Reindex 层的 16,384 个位置需 64KiB, 四层顺序执行且复用工作区时仍约 64KiB, 同时保留四份则为 256KiB. Top-512 索引只有 2KiB. 分数若以 FP16 暂存, 16,384 项另需 32KiB; 做流式块 Top-K 可以只保存每块局部候选, 避免把全部分数落盘. 百万 token 主缓存约 849MiB, 所以候选索引不是容量主项, 但它处在每个 decode token 的热路径, 访存形态和同步次数会影响时延.

当 batch 为 $Q$, 候选工作区近似随 $Q$ 线性增长, 共享前缀只能共享 KV, 不能共享不同 query 的排序结果. 两个请求即使历史完全相同, 当前 query 不同便会产生不同候选. 因此高并发下应分别统计「可共享的历史状态」和「随查询复制的选择工作区」. 890 字节回答前者, 无法直接推出后者的并发上限.

## 24. CED 跨层复用怎样改变梯度

标准逐层 KV 令第 $l$ 层历史表示 $H_l$ 通过本层投影写入 $K_l,V_l$. 来自深层损失的梯度沿各层各自的 KV 支路回传:

$$
\frac{\partial\mathcal L}{\partial H_l}
=\frac{\partial\mathcal L}{\partial K_l}W_l^{K\mathsf T}
 +\frac{\partial\mathcal L}{\partial V_l}W_l^{V\mathsf T}+\cdots.
$$

CED 把 decoder global KV 的源统一为 encoder 末层 $H_e=H_{L/2}$. 若第 $l$ 个 decoder 层使用 $K_l=H_eW_l^K,V_l=H_eW_l^V$, 则所有 decoder global 分支的梯度汇聚到同一个截面:

$$
\frac{\partial\mathcal L}{\partial H_e}
=\sum_{l>L/2}\left(
\frac{\partial\mathcal L}{\partial K_l}W_l^{K\mathsf T}
+\frac{\partial\mathcal L}{\partial V_l}W_l^{V\mathsf T}
\right)+\frac{\partial\mathcal L_{\rm local}}{\partial H_e}.
$$

这会产生两种相反作用. 多层监督共同约束 $H_e$, 有利于让 encoder 末层形成可被不同深度读取的通用记忆; 若各 decoder 层要求相互冲突的特征, 梯度内积为负, 汇聚点会承受任务干扰. 设两层贡献为 $g_i,g_j$, 冲突程度可用 $g_i^{\mathsf T}g_j/(\|g_i\|\|g_j\|)$ 衡量. 训练稳定并不保证冲突消失, 它只说明优化器找到了可用折中.

CSA2 又把多个层的物理 KV 进一步合并. Reuse 层既不产生自己的 global KV, 也不产生新的 Top-K, 其损失对共享 KV 的梯度会累加到最近的 Full 层. Reindex 层产生新查询与选择, 但值内容仍来自共享 KV. 因而 Full 层承担「写什么」, Reindex 层只改变「读哪里」, Reuse 层只改变集合内「怎样读」. 这三个角色的梯度路径不同: Full 层的 KV 投影收到整组消费者的梯度; Reindex 的 indexer Q 收到本层选择信号; Reuse 没有独立索引参数可修正漏选.

层特异性保留在 query、输出投影、SWA 分支以及部分层相关的投影中. 即使共享同一 $K,V$, 第 $l$ 层仍计算

$$
o_l=\operatorname{softmax}(Q_lK^{\mathsf T}/\sqrt d)V W_l^O,
$$

所以不同层可以从同一记忆中读取不同线性组合. 被限制的是历史 token 的可写表示, 不是当前 token 的读取函数. 若某项信息已经存在于共享 $V$ 的列空间里, 深层 query 可以重新组合它; 若信息在构造共享 $V$ 时已被投影掉, 后续层再复杂也无法恢复.

## 25. 表达秩与层特异性的上限

把各层独立 value 投影并排写成 $\mathcal V=[W_1^V,\ldots,W_r^V]$. 标准结构可利用的联合子空间维数最多为 $\operatorname{rank}(\mathcal V)$. 共享记忆写成 $Z=XP$, 各层 value 为 $V_l=ZB_l=XPB_l$, 则

$$
\operatorname{rank}([PB_1,\ldots,PB_r])\le \operatorname{rank}(P)\le d_Z.
$$

只要 $d_Z$ 小于独立层联合需要的秩, 就存在一组输入方向无法同时保留. 一个直接反例是 $r$ 个层分别需要互相正交的一维属性, 而共享记忆只有 $r-1$ 维; 无论怎样选择 $B_l$, 至少有一项属性在公共投影后不可辨识. 这项约束与参数量无关, 增大读取投影无法突破 $P$ 的列空间.

实际模型未必需要独立层的全部联合秩. 相邻层的历史表示高度相关, 很多方向只是同一语义的不同坐标. 若奇异值谱快速衰减, 共享子空间保留前 $d_Z$ 个方向便能覆盖大部分能量. 可对密集教师的各层 KV 收集矩阵 $\mathcal V$, 计算截断误差

$$
E(d_Z)=\frac{\sum_{i>d_Z}\sigma_i^2}{\sum_i\sigma_i^2}.
$$

$E(d_Z)$ 给出线性重建的下界, 但不能直接代表任务损失: 小奇异值方向可能承载罕见而关键的信息. 因而还应按 token 类型、距离与任务分桶测谱, 尤其观察数字、标识符和低频实体对应方向是否更早丢失.

共享也可能带来正则化收益. 独立 KV 允许每层写入任意细节, 部分方向只适配训练分布; 共享迫使 encoder 形成多层都能使用的表示, 相当于低秩瓶颈. 当数据有限时, 这种约束可能改善泛化. 一旦任务需要分阶段重编码历史, 瓶颈便转为欠表达. 最小消融应同时扫描共享组长度和记忆宽度: 只扫描其中一个, 无法区分「复用太久」与「共享空间太窄」.

## 26. FP4 如何改变 Indexer 排序

主 KV 与 indexer K 都进入离散排序链, 量化误差可能先改变候选, 再改变注意力输出. 设未量化的索引键为 $k_j$, 量化后为 $\hat k_j=k_j+e_j$, 查询为 $q$, 分数误差为

$$
\hat s_j-s_j=q^{\mathsf T}e_j,\qquad
|\hat s_j-s_j|\le \|q\|_2\|e_j\|_2.
$$

对两个候选 $i,j$, 原分数间隔为 $\gamma=s_i-s_j>0$. 排序保持的充分条件是

$$
\gamma>\|q\|_2(\|e_i\|_2+\|e_j\|_2).
$$

因此平均量化均方误差很小, 仍可能翻转 Top-K 边界附近的条目. 真正该看的量是第 $k$ 名与第 $k+1$ 名之间的 margin 分布, 再与量化扰动分布比较. 若大量查询的 margin 接近零, 极少的数值误差也会频繁改集合; 若 margin 宽, FP4 对排序近乎无影响.

E2M1 每 16 通道共享一个 E4M3 scale, 缩短分组能限制离群值污染. 若同组某一通道幅值为其余通道的十倍, scale 必须覆盖它, 其余通道可用的有效刻度随之变粗. RoPE 保持二范数却会在通道间旋转能量, 所以「量化放在 RoPE 前还是后」会改变组内动态范围. 报告选择 RoPE 后量化并用 QAT 适配; 这让训练看到与部署相同的舍入位置, 但不能保证每个 query 的 Top-K 都不变.

排序翻转又分有害和无害. 若第 512 与 513 名对应近似重复的两段, 交换集合几乎不改输出; 若 512 名是唯一证据, 513 名只是高词面相似干扰, 同一次翻转便可能改变答案. 可定义任务加权翻转率

$$
F_w=\frac{1}{T}\sum_t\sum_{j\in S_t\triangle\hat S_t}a_{t,j}^{\rm teacher},
$$

其中对称差只统计因量化进出集合的位置, 再用教师质量加权. 它比单纯的集合 Jaccard 距离更接近最终影响. 实验还应固定候选集合只量化 value, 与量化 indexer K 后重新选集合分开, 前者测数值重建, 后者测排序路径.

## 27. 长上下文中的位置分布漂移

训练在 34T token 时把最大序列长度扩到 1M, 此后约 11T token 处于长上下文阶段. 最大长度只规定允许的上界, 不决定证据位置分布. 若长样本中的监督主要落在末尾, Indexer 可能学到强烈的近因偏置; 若文档切分总把标题和摘要放在开头, 又会产生首部偏置. 部署中的 Agent 轨迹常把旧工具结果留在中段, 当前指令在尾部, 位置条件与网页或书籍不同.

把相对位置写成 $r=(t-j)/t$, 可以按 $r$ 分桶测加权召回. 仅报告整体召回会被近距离样本淹没. 更严格的压力测试固定语义内容, 只把证据平移到 0.01、0.1、0.5、0.9 等相对位置, 并保持干扰段落数量不变. 若分数随位置系统变化, 说明 Indexer 使用了位置先验. 位置先验本身并非错误, 在自然数据上可能提高平均质量; 问题是部署分布改变后先验会反噬.

长度增长还改变极值统计. 即便每个无关位置分数分布不变, 从 $N$ 个负例中取最大值时, 最大负分数会随 $N$ 上升. 设负分数独立同分布, 累积分布为 $F_-$, 最大值满足

$$
P(M_N\le x)=F_-(x)^N.
$$

当 $N$ 从 64K 增到 1M, 负例数量约增 16 倍, 更容易出现一个偶然高分干扰挤掉正例. 这解释了短上下文上稳定的阈值与 margin 无法直接外推到百万 token. 分块候选降低后级看到的负例数量, 第一阶段仍面对全序列极值问题.

多轮 Agent 还有时间漂移: 相同实体在不同轮出现多个版本, 最近版本通常有效, 但任务也可能要求回看早期承诺. 单纯位置衰减会偏向新版本, 纯语义相似又可能拿到旧版本. 训练样本应同时包含「取最新」和「取指定历史版本」两类, 让 query 中的时间条件参与打分. 评测时把实体、内容和距离正交控制, 才能分清语义混淆与位置偏置.

## 28. 逐表复算与最小复现实验

第一组复算只用公开配置. 表 1 的骨干参数、激活参数与图 1(b) 的 KV 字节分别从层数、专家数、激活专家数、KV 维度、精度和共享组数重建; 每一步保留十进制字节与二进制容量两种口径. 图 2 的曲线不能只抄端点, 应在 4K、64K、128K、1M 四个位置读取, 用「固定骨干 FLOPs + 随上下文增长的 Indexer FLOPs」拟合. 若拟合残差在分层候选启用点附近发生折线, 便能验证后级搜索域被截到固定 16,384.

第二组实验用小模型隔离 CSA2. 取 12 层、隐藏维 768 的 decoder, 先训练密集基线, 再保持数据、参数预算和训练 token 一致, 比较四种配置: 每层独立稀疏索引; 跨层共享 KV 但每层 Reindex; 共享 KV 加 Reuse; 共享 KV 加两级候选. 序列长度取 4K、16K、64K, $k$ 取 64、128、256, 候选池取 $4k$、$16k$、$64k$. 每个点记录语言损失、证据加权召回、Top-K margin、KV 字节和单 token 延迟. 这样能画出质量—缓存—计算三维前沿, 并找出两级候选开始有收益的长度.

第三组隔离 CED. 固定总层数和总参数, 扫描 encoder/decoder 分割为 3:1、1:1、1:3, 再把共享记忆宽度设为隐藏维的 1/4、1/2、1 倍. 每个配置同时测 prefill FLOPs、联合 KV 奇异值截断误差、层间梯度余弦和长程组合任务. 若共享宽度增大能恢复质量而改变分割无效, 限制来自表达秩; 若增加 encoder 深度有效, 限制来自记忆形成所需的计算深度; 若两者都无效, 应检查候选检索与局部回放.

第四组隔离 FP4. 同一 checkpoint 运行 BF16、FP8、FP4 三套 cache, 对每层保存量化前后分数、512/513 margin、候选对称差、输出误差和答案 token loss. 再做两项交换: FP4 分数配 BF16 value, BF16 分数配 FP4 value. 第一项只保留排序误差, 第二项只保留值误差. 按长度、相对位置、近重复干扰和多证据数量分桶后, 可以看到量化是否主要伤害百万 token 边界处的检索.

第五组复现 SWA Bounded Replay. 对同一前缀分别运行完整前向、精确多层回放和 128-token 有界回放, 比较各 decoder 层 SWA KV 的余弦误差与后续 256 个 token 的分布差. 再把后训练适配关掉, 测量适配前后误差如何传播. 这项实验把架构近似与训练补偿拆开: 有界回放产生多大状态偏差是一件事, 模型学会容忍多少又是另一件事.

这些实验最终形成一组能相互定位的曲线: 候选召回随长度、排序翻转随 margin、输出误差随精度、语言损失随强制证据、质量随共享秩. 任一总分下降都能沿这条链追到具体环节, 才算真正复现了 CSA2、CED 与 FP4 的联合机制.

## 29. 三类容易被平均分掩盖的失效

第一类是「候选正确, 身份错误」. 长代码库中常有多个同名函数, 文档里也会重复出现同一实体. Indexer 可能找到词面和类型都正确的片段, 却选错文件、版本或时间点. 从普通 recall 看, 候选高度相关; 从任务因果关系看, 它缺少唯一能决定答案的限定条件. 可以构造两个仅在一个常量或提交时间上不同的片段, 交换它们在上下文中的远近位置. 若模型总取较近者, 位置先验压过了身份约束; 若总取词频更高者, 表示压缩丢掉了稀有限定词. 这类错误需要实体—版本二元标签, 不能用主题相关性代替.

第二类是「单步召回高, 跨步状态断裂」. Agent 在第十轮读取一条工具结果, 第二十轮根据新条件重新解释它. 第一处检索和第二处检索单独都可能成功, 但共享 KV 在中间层缺少重新写入, 新条件无法改变旧证据的表示. 设旧证据为 $x$, 新条件为 $c$, 理想记忆需要表示交互项 $\phi(x,c)$. 若共享记忆在看到 $c$ 之前已固定为 $P x$, 后续只能计算 $g(Px,c)$; 当 $P$ 丢掉了与 $c$ 相关的方向, 任意读取函数都无法恢复交互. 测试时应让条件在证据之后很远才出现, 并与条件前置的对照组比较. 两组差距能暴露 CED 共享写入时刻的限制.

第三类是「平均误差低, 尾部事件致命」. FP4 大多数通道的重建误差很小, 少量包含数字、路径或校验值的通道可能恰好落在量化阈值附近. 这些 token 在语料中占比低, 对平均余弦和困惑度贡献也低, 却决定代码补丁、金额或安全策略是否正确. 应按 token 类别统计排序翻转和输出误差: 普通词、数字、标识符、文件路径、时间戳、否定词分别成桶. 若总均值稳定而数字桶显著恶化, 继续增加普通文本样本无法解决问题, 需要调整量化分组、困难样本或局部高精度路径.

三类失效会相互放大. 近重复版本让 Top-K margin 变窄, FP4 更容易翻转排序; 共享记忆若压掉版本字段, 即使候选选对, 深层也难以区分; 位置先验又会让最近的错误版本获得优势. 因此组合压力测试应同时控制四个量: 版本相似度、证据距离、量化精度和共享组长度. 例如固定一条正确证据, 逐渐增加近重复干扰, 分别在 BF16/FP4 和独立/共享 KV 下测准确率. 四条曲线若只在「FP4 + 长共享」同时陡降, 说明两项近似存在非线性交互, 单组件消融会低估风险.

诊断顺序沿计算链展开: 检查正确证据是否进入第一阶段候选, 再检查是否进入最终 Top-512, 随后比较量化前后的集合变化, 末端检查共享 value 是否还能线性解码出版本与时间属性. 每一步都能给出可观测量, 失败无需靠最终答案倒猜. 这条链与报告点名的两个风险相呼应: CSA2 的误选和近似缓存恢复都可能只在极端输入暴露, 平均榜单持平无法覆盖它们.
