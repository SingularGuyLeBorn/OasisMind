# JanusFlow 技术解析: 在同一 LLM 中协调自回归理解与 Rectified Flow 生成

JanusFlow 由 DeepSeek-AI, 北京大学, 香港大学和清华大学共同完成, 论文 arXiv:2411.07975v2 于 2025 年 3 月更新, 代码与模型位于 [DeepSeek Janus 仓库](https://github.com/deepseek-ai/Janus). 它以增强版 DeepSeek-LLM 1.3B 为共享主干, 将视觉理解写成 next-token prediction, 将图像生成写成 rectified flow 的速度预测. 两种任务共享 LLM, 但不强迫视觉输入共用编码器. 论文的主要贡献落在接口设计: 连续图像潜变量怎样进入因果 Transformer, 两项视觉任务怎样隔离输入表征, 生成特征又怎样借用理解编码器的语义空间.

## 1. 统一发生在 LLM 主干, 不发生在视觉入口

JanusFlow 统一的是 **LLM 主干**, 视觉理解与图像生成仍使用不同入口.

### 1.1. 两项任务共用序列计算接口

视觉理解沿用多模态 LLM 的常见路径. 文本先变成离散 token 嵌入, 图像 $x_{im}$ 由理解编码器 $f_{enc}$ 转成 $H_{im}\times W_{im}\times D_{enc}$ 的特征图, 展平并线性投影到 $D_{emb}$ 维. 图像嵌入放在 |BOI| 与 |EOI| 之间, 与文本嵌入拼成一个序列. LLM 使用因果注意力读取这段序列, 只在响应文本 $x^{res}$ 上计算自回归损失 $\mathcal{L}_{AR}$.

图像生成也进入同一个因果 Transformer, 但输入不是理解特征. SDXL-VAE 先将目标图像压到连续潜在空间. 训练时把真实潜变量 $x^{res}$ 与高斯噪声 $z_0$ 线性插值得到 $z_t=tx^{res}+(1-t)z_0$, 生成编码器 $g_{enc}$ 将 $z_t$ 转成 LLM 嵌入, 并追加时刻 $t$ 的嵌入. LLM 输出再经过生成解码器 $g_{dec}$ 还原成潜在空间速度. 因此共享主干处理的都是 embedding 序列, 任务差异由序列来源, 输出头与损失函数表达.

> 图 1: JanusFlow 的理解与生成路径. 理解路径预测文本 token, 生成路径迭代预测潜变量速度, 对应原文 Figure 2.

图 1 中生成状态不是一次自回归产生的离散图像 token. 每个采样时刻都把当前潜变量 $z_t$ 送入同一个 LLM, 得到速度 $\nu(z_t,t)$, 再用 Euler 更新 $z_{t+dt}=z_t+\nu(z_t,t)dt$. 到 $t=1$ 后, SDXL-VAE 解码器把最终潜变量还原成图像. 论文使用 30 个采样步计算主要 FID, 这意味着一次图像生成需要多次运行 LLM. 统一模型节省了独立生成主干, 却没有把图像生成变成单次前向.

### 1.2. 因果注意力为何能够承担速度预测

扩散或 flow Transformer 常让图像 token 双向交互, JanusFlow 却报告替代掩码没有带来收益, 因而保留 LLM 原有的因果注意力. 图像潜变量经 $g_{enc}$ 变成固定顺序的二维网格序列, 后一位置只能看到文本条件, 时间 token 与之前的图像位置. 这在对称性上弱于全注意力, 但减少了对预训练 LLM 注意力结构的改造, 也允许理解和生成走同一套主干实现.

论文没有给出不同掩码方案的定量表, 只说明初步实验未观察到收益. 因此不能从现有实验推出因果掩码普遍优于双向掩码. 更稳妥的结论是: 在 1.3B LLM, 384 分辨率, 当前 $g_{enc}$ 与 $g_{dec}$ 配置下, 因果注意力足以支持论文报告的生成质量. 当分辨率, 主干规模或采样器改变后, 掩码是否仍无影响需要单独验证.

### 1.3. 解耦编码器解决目标冲突

理解编码器需要形成对类别, 关系和文字稳定的语义表征. JanusFlow 使用约 300M 参数的预训练 SigLIP-Large-Patch/16. 生成路径则需要从带噪潜变量中保留局部结构, 并输出与 SDXL-VAE 潜在空间同形状的速度. 它使用从头训练的 ConvNeXt 编码器和解码器, 两者合计约 70M 参数, 中间还有长跳跃连接. 两项任务对空间细节和不变性的要求不同, 共用一个视觉编码器会让输入接口同时接受相互牵制的梯度.

表 6 将这种冲突量化. 实验 B 让理解与生成共享 VAE 潜在空间中的 ConvNeXt, POPE, VQAv2 和 GQA 分别只有 78.13, 53.94 与 44.04. 实验 F 改用 SigLIP 理解编码器与独立生成模块后, 三项指标升至 84.73, 69.20 与 54.83. 实验 C 虽然分开编码器, 但理解侧仍从 VAE 与 ConvNeXt 起步, 对应结果为 75.30, 55.41 与 44.44. 差异表明“分开”与“使用预训练语义编码器”都是关键变量, 单独复制相同结构并不足以获得理解能力.

## 2. Rectified Flow 在 LLM 内部怎样训练

### 2.1. 速度目标与采样路径

Rectified flow 从简单分布 $\pi_0$, 通常为标准高斯噪声, 连接到数据分布 $\pi_1$. 训练从两端各取一点 $z_0$ 与 $x$, 再在 $t\in[0,1]$ 上取插值点 $z_t=tx+(1-t)z_0$. 直线路径的目标速度为 $x-z_0$. 神经网络以 $z_t$ 和 $t$ 为输入, 最小化预测速度与 $x-z_0$ 的平方距离. JanusFlow 将图像 $x^{res}$ 换成 SDXL-VAE 潜变量, 得到论文式 (7) 的 $\mathcal{L}_{RF}$.

时间 $t$ 沿用 Stable Diffusion 3 的 logit-normal 分布采样. 时间分布决定训练更频繁覆盖哪些噪声强度, 会改变模型在采样轨迹不同区段的误差. 论文没有在 JanusFlow 上单独消融时间分布, 因而主要实验支持的是整套配置. 推理使用一阶 Euler 求解器. 附录图 1(b) 显示, CFG 固定为 2 时, 在论文考察范围内改变步数对结果影响较小, 正文选择 30 步作为质量与成本的折中.

生成过程还使用 classifier-free guidance. 训练时随机丢弃 10% 文本提示, 让同一网络同时学习条件速度 $\nu(z_t,t\mid x^{con})$ 与无条件速度 $\nu(z_t,t\mid\emptyset)$. 推理按 $w\nu(z_t,t\mid x^{con})+(1-w)\nu(z_t,t\mid\emptyset)$ 合成速度. 当 $w>1$ 时, 条件方向被外推. 附录图 1(a) 显示 CLIP 相似度随 CFG 增大继续上升, FID 却存在最优点, 说明更强提示对齐与整体图像分布质量不是同一个目标.

### 2.2. REPA 将生成特征拉向语义空间

解耦编码器避免任务入口相互干扰, 也使理解编码器能够充当固定语义教师. 对生成样本, SigLIP 编码器 $f_{enc}$ 读取干净目标图像 $x^{res}$, LLM 则读取带噪状态 $z_t$. 论文取 LLM 第 6 个 Transformer 模块后的中间特征 $q_\theta(z_t)$, 通过三层 MLP $h_\varphi$ 投影到 $D_{enc}$ 维, 再按空间位置与 SigLIP 特征计算逐元素余弦相似度均值. 负相似度形成 $\mathcal{L}_{REPA}$.

理解编码器一侧使用 `stop_grad`, 所以 REPA 不会为了适配生成特征而改变 SigLIP. 梯度只更新 LLM 生成路径和投影 MLP. 作者还调整 $g_{enc}$ 与 $g_{dec}$ 的配置, 使 $H_{gen}=H_{im}$ 且 $W_{gen}=W_{im}$, 两张特征图能够按位置对齐. 这项限制简化了损失实现, 也把 REPA 与当前空间分辨率和 patch 布局绑定. 如果更换理解编码器或生成网格, 需要重新设计位置对应关系.

表 6 的实验 A 与 F 只在 REPA 上不同. 加入 REPA 后, FID 从 19.84 降至 17.61, CLIP 从 24.94 升至 26.40; POPE 从 82.40 升至 84.73, VQAv2 从 69.62 略降至 69.20, GQA 从 54.43 升至 54.83. 生成侧收益清楚, 理解侧并非每项都单调改善. 论文附录还给出预训练前 50,000 次迭代的 FID 与 CLIP 曲线, 表征对齐在训练早期已经拉开差距.

### 2.3. 三项损失没有强行合成一个响应空间

多模态理解样本使用 $\mathcal{L}_{AR}$, 图像生成样本使用 $\mathcal{L}_{RF}+\mathcal{L}_{REPA}$. 两类响应不需要共同的离散词表. 文本响应由语言头给出概率, 图像响应由生成解码器给出连续速度. “统一”体现在共享 LLM 参数和训练批次, 并不要求对文本和图像采用同一种概率分解.

这种设计避免了向量量化图像 token 的重建上限, 但训练调度必须管理不同损失的尺度和收敛速度. 论文没有报告三项损失之间的显式权重, 式 (7) 和式 (8) 直接相加. 预训练初期提高理解数据比例, 随后提高生成比例, 原因是扩散类生成收敛更慢. 任务平衡主要通过数据比例与训练阶段控制, 而不是把所有样本混入一个完全同构的目标.

## 3. 三阶段训练如何保护预训练能力

### 3.1. 先适配接口, 再更新共享主干

阶段 1 只训练随机初始化的线性层, $g_{enc}$ 和 $g_{dec}$, 冻结预训练 LLM 与 SigLIP. 新模块先学习把潜变量映射到 LLM 可处理的数值范围, 再将输出还原为速度. 表 1 给出的阶段 1 配置为学习率 $1.0\times10^{-4}$, 10,000 步, batch size 512, 数据比例 50:50:0. 此处没有纯文本数据.

阶段 2 解冻除视觉编码器外的整个模型, 训练 390,000 步, batch size 512. 数据比例为 14:80:6, 图像生成占主要部分, 同时保留理解与纯文本数据. SigLIP 继续冻结, 因而理解入口保持稳定语义空间; LLM 则同时适应自回归理解与速度预测. 所有序列被打包到长度 4,096, 提高训练利用率.

### 3.2. SFT 才解冻理解编码器

阶段 3 使用对话, 任务专项会话和高质量文生图样本进行 SFT, 并解冻 SigLIP. 学习率降到 $2.0\times10^{-5}$, 训练 26,000 步, batch size 256, 数据比例为 21:70:9. 直到此时才更新理解编码器, 减少大规模生成数据在预训练阶段改写语义视觉特征的风险.

三个阶段均使用 AdamW, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 为 0, 梯度裁剪为 1.0. 前两个阶段 warm-up 2,000 步, 第三阶段 1,000 步. 整个训练在 NVIDIA A100 上完成, 每个模型约消耗 1,600 A100 GPU-days. 论文没有说明 GPU 数量与墙钟时间, 因而该数字表达总计算投入, 不能直接换算训练时长.

### 3.3. 数据预处理保留不同任务需要的信息

理解任务把图像长边缩放到目标尺寸后填充成正方形, 因为裁剪可能移除回答问题所需的对象或文字. 生成任务则把短边缩放到目标尺寸后随机方形裁剪, 避免 padding 区域进入目标图像. 同一张原始图像在两项任务中可能因此产生不同视图. 这进一步说明共享视觉编码器会面对冲突输入分布.

预训练理解数据包括描述, 图表, 问答和图文交错数据. 生成数据来自多个公开图像集与 200 万条内部数据, 经过机器重新描述, 宽高比和美学分过滤; LAION-Aesthetics 与 PixelProse 仅保留约 20%. 其中 25% 使用单句描述, 用于维持短提示处理能力. 内部数据未公开细节, 这限制了完整训练复现, 也使模型表现无法完全归因于架构.

## 4. 实验结果能支持哪些判断

### 4.1. 统一模型与专项模型的差距

JanusFlow 在 GenEval 得到 0.63, 高于 Show-o 的 0.53 和 Janus 的 0.61, 与论文表中 Transfusion 的 0.63 相同. 分项上, JanusFlow 的位置关系 0.53 较强, 两对象 0.59 与计数 0.45 并非表中最佳. DPG-Bench 总分为 80.09, 接近 PixArt-$\Sigma$ 的 80.54 与 Emu3-Gen 的 80.60. MJHQ FID-30k 为 9.51, 优于同为 1.3B 的 Show-o 15.18 与 Janus 10.10, 但表中 7B VILA-U 384 达到 7.69.

视觉理解方面, 384 分辨率模型取得 POPE 88.0, MME-P 1333.1, MMBench 74.9, SEED 70.5, VQAv2 79.8, GQA 60.3, MMMU 29.3, MM-Vet 30.9, ChartQA 64.6 与 TextVQA 55.5. 不同基准的领先对象并不一致. 例如更大模型在 MMMU 与 MM-Vet 上仍有明显优势. 论文能够支持的判断是: 在 1.3B LLM 规模下, 统一训练没有造成明显的全面能力塌缩, 且在若干通用基准上具有竞争力.

表 6 提供了更严格的专项对照. 统一实验 F 与相同数据, 基础设施和超参数下的理解专项实验 D 相比, POPE 为 84.73 对 85.03, VQAv2 为 69.20 对 69.10, GQA 为 54.83 对 54.23. 与生成专项实验 E 相比, FID 为 17.61 对 16.69, CLIP 为 26.40 对 26.89. 差距较小, 但统一生成仍略弱于专项生成. 这比跨论文榜单更能隔离统一训练本身的成本.

### 4.2. 分辨率结果暴露指标之间的张力

附录比较 256 与 384 分辨率. 384 模型在全部列出的理解指标上更好, 例如 MMBench 从 71.9 升到 74.9, VQAv2 从 76.3 升到 79.8, MM-Vet 从 27.4 升到 30.9. 更高分辨率保留更多文字和小物体信息, 这一趋势与理解任务相符.

生成指标呈现两个方向. 384 模型的 MJHQ FID 从 12.70 改善到 9.51, 视觉分布质量更好; 256 模型的 GenEval 总分为 0.70, 高于 384 模型的 0.63, DPG-Bench 总分也从 80.09 升到 81.23. 论文将其归因于低分辨率下视觉复杂度较低, 语义控制更容易. FID、CLIP 与指令遵循衡量的是不同属性, 单一汇总指标覆盖不了生成质量的全部维度.

### 4.3. 比较口径仍有边界

跨模型表格汇集了不同训练数据, 分辨率, 参数规模和评测实现. JanusFlow 的主要结果使用 384 分辨率与增强版 DeepSeek-LLM 1.3B, 生成数据还包含 200 万条内部样本. 表中某些统一模型参数更多, 某些专项模型使用不同文本编码器或生成分辨率. 因而榜单适合说明竞争位置, 不能独立证明所有收益都来自 rectified flow.

消融实验统一使用 256 分辨率, 只训练 50,000 次迭代, 与主模型 384 分辨率和完整三阶段训练不同. 它能验证早期训练阶段的方向, 不能保证各差距在完全收敛后保持相同幅度. 尤其表征对齐与编码器解耦可能影响收敛速度, 固定训练步数同时测到了最终质量与优化速度.

## 5. 设计边界与后续复用

共享主干允许两项任务复用序列计算, 同时保留 **不同的模态表征**.

### 5.1. 共享参数不等于共享表示

JanusFlow 的经验表明, 统一模型可以共享最昂贵的 Transformer 主干, 同时保留任务专项入口和出口. 视觉理解依赖 SigLIP 的语义不变性, 图像生成依赖连续潜变量的局部结构, 强制二者共用编码器会降低理解表现. 解耦以后, REPA 再以单向正则化把生成中间特征拉向固定语义空间, 实现“接口分开, 语义关联”.

该结构也限定了扩展方式. 增加视频, 音频或更高分辨率时, 可以继续共享 LLM, 但每种模态是否需要独立编码器取决于输入目标. REPA 要求教师特征与生成网格具备空间对应, 不能直接假定任意编码器都能逐位置对齐. 生成解码器和 VAE 还决定最终分辨率与细节上限.

### 5.2. 推理成本仍受迭代生成支配

Rectified flow 避免离散图像 tokenizer 的重建误差, 但 30 步 Euler 采样意味着 LLM 对整段图像嵌入重复前向. CFG 通常还需要条件与无条件预测, 进一步增加计算. 论文强调架构精简和模型统一, 并未给出与 Janus 离散自回归生成之间的端到端延迟, 显存或吞吐对比. 因而不能将参数共享直接解释成服务成本更低.

实际部署需要同时优化图像序列长度, 采样步数, CFG 实现和 KV cache 策略. 因果注意力允许缓存文本前缀, 但每个时间步的图像潜变量整体变化, 图像部分的状态难以像普通语言解码那样只追加一个 token. 附录显示增加采样步数影响较小, 为减少步数提供了实验依据, 但更激进的少步采样仍需重新评估 FID 与语义指标.

### 5.3. 论文自身留下的复现缺口

训练数据包含 200 万条内部图文数据, 增强版 DeepSeek-LLM 的扩展文本语料也未公开组成. 论文给出总 GPU-days, 没有给出硬件数量, 数据 token 或样本总量以及各阶段墙钟时间. 这些信息不足以完整复现训练预算与数据混合.

方法侧也有若干未展开变量. 因果注意力与其他掩码的比较没有定量结果; $\mathcal{L}_{RF}$ 与 $\mathcal{L}_{REPA}$ 的相对尺度缺少曲线或权重消融; REPA 选择第 6 层以及三层 MLP 的依据未消融; Euler 求解器没有与更高阶求解器比较. 这些缺口不影响论文证明当前配置可行, 但限制了结论向更大模型与更高分辨率外推.

表 6 的编码器消融还混入了预训练来源差异. 实验 B 使用共享 VAE 与 ConvNeXt, 实验 C 使用彼此独立但结构相同的 VAE 与 ConvNeXt, 实验 F 则把理解侧换成预训练 SigLIP. B 到 C 可以观察参数解耦, C 到 F 同时改变理解架构和预训练语义质量. 表中没有“共享 SigLIP”或“独立且从头训练的 SigLIP”配置, 因而无法从一个对比精确分解架构解耦与视觉预训练各自贡献多少.

专项基线同样只覆盖短程消融口径. 理解专项实验 D 训练 13,000 步, 生成专项实验 E 训练 37,000 步, 数量按统一预训练的数据比例从 50,000 步折算. 这种匹配控制了样本量, 但不同任务的最佳学习率, batch 组成和收敛曲线未必一致. 表 6 能说明统一模型在共同训练配方下接近专项基线, 不能证明每个专项模型充分调优后仍只有相同差距.

评测层面缺少人类偏好与安全维度. GenEval 和 DPG-Bench 主要检查对象, 属性与关系, MJHQ FID 衡量生成分布, CLIP 相似度衡量图文接近程度. 这些指标没有覆盖文字渲染, 手部结构, 真实感偏好, 文化偏差与不安全内容. 图 4 的定性样例能够展示输出范围, 但经过挑选的少量图像不能替代盲评或大规模错误分类.

附录的分辨率解释也仍是相关性判断. 256 模型在语义基准更好, 作者将其归因于低分辨率图像更容易控制; 论文没有保持其他变量不变后进一步测量训练动态, 潜变量信噪比或空间 token 难度. 另一种可能是两种分辨率在固定模型容量, 训练步数和采样参数下处于不同优化状态. 现有数字确认了现象, 没有唯一确定成因.

论文正文第 4.5 节还存在一处残句: “Impact of Decoupling Visual Encoders” 后紧接 “e efficacy of using powerful pre-trained visual encoders”, 句首明显缺失. 结合后文可以判断作者要讨论预训练视觉编码器的有效性, 但缺失文字无法从当前 PDF 恢复. 对照译稿保留了英文原貌, 中文按后续完整论述表达可确认的含义.

原文的表格抽取也暴露版面限制. 表 5 将多个模型压在单个单元格内, 文本化以后模型名, 参数量和各列数字失去逐行对齐; 复核具体模型成绩应查看 PDF 表格版面, 不能依赖 Markdown 抽取后的行. 这属于源文排版转文本时的信息损失, 不改变论文报告的数字, 但会影响自动解析与逐项引用.

JanusFlow 最稳定的可复用结论有两点. 第一, 连续生成目标可以通过轻量输入输出模块接入预训练因果 LLM, 无需另建完整扩散主干. 第二, 统一主干时应按任务目标保留视觉编码器差异, 再用表征正则项建立语义联系. 表 6 与附录结果共同说明, 统一能力来自接口分工, 数据调度和训练目标的组合, 不能归结为单一模块替换.

与 Janus 的离散自回归路线相比, JanusFlow 改变了质量上限所在的位置. Janus 受视觉 tokenizer 的离散码本和重建质量约束, JanusFlow 继承 SDXL-VAE 的连续潜在空间, 再由速度场与数值积分决定采样误差. 表 4 中 JanusFlow 的 FID 9.51 优于 Janus 的 10.10, 但实验同时更换了生成目标与部分训练设计, 不能把 0.59 的差值全部归给 rectified flow.

统一主干的长期价值更接近参数复用和跨任务表征迁移. 当前结果证明 1.3B 规模可行, 尚未证明规模扩大后收益会保持. 更大的 LLM 会提高每个 flow 采样步的成本, 也可能增强文本条件理解和生成特征容量. 后续工作需要同时报告质量, 端到端延迟和单位样本训练成本, 才能判断统一方案在更大尺度上的实际优势.

## 6. 从线性插值到速度回归

### 6.1. 训练样本给出的速度为何不是随意指定的

设 $Z_0\sim\pi_0$ 是高斯噪声, $Z_1\sim\pi_1$ 是图像经过 SDXL-VAE 编码后的潜变量. JanusFlow 采用独立耦合, 即先各自采样 $Z_0$ 与 $Z_1$, 再令

$$
Z_t=(1-t)Z_0+tZ_1,\qquad \dot Z_t=Z_1-Z_0.
$$

一条具体配对轨迹的速度恒定, 但网络只观察 $Z_t$, 时间 $t$ 与文本条件 $c$, 看不到这次配对的两个端点. 平方损失的最优预测因此是条件均值

$$
v^*(z,t,c)=\mathbb E[Z_1-Z_0\mid Z_t=z,C=c].
$$

这个等式可以直接由条件平方损失得到. 固定 $(z,t,c)$, 将随机目标记作 $U=Z_1-Z_0$, 任意预测 $a$ 的风险为

$$
\mathbb E[\|U-a\|_2^2\mid z,t,c]
=\mathbb E[\|U-\mathbb E[U\mid z,t,c]\|_2^2\mid z,t,c]
+\|a-\mathbb E[U\mid z,t,c]\|_2^2.
$$

第一项与 $a$ 无关, 第二项在 $a=v^*$ 时最小. 网络学习的是同一个中间位置上许多配对速度的平均, 而非复现某一对噪声与图像之间的连线. 这也解释了为什么训练目标看起来是简单的端点差, 采样时却能形成随位置和时间变化的向量场: 条件集合随 $(z,t)$ 改变, 条件均值自然随之改变.

对一个一维双峰分布可以看得更直观. 假设数据端点集中在 $-m$ 与 $+m$, 中间状态 $z_t$ 接近零. 当 $t$ 很小时, 当前位置主要由噪声决定, 两个数据峰都可能产生该位置, 最优速度会平均两种去向. 当 $t$ 接近 1 时, $z_t$ 已透露它属于哪个数据峰, 条件均值才会明确指向相应模态. 所以时间不是装饰性的附加 token, 它改变了当前位置能够透露多少目标信息. 若丢掉 $t$, 相同数值 $z$ 在不同噪声阶段对应不同条件分布, 回归器只能再次平均, 生成轨迹会失去正确的时间方向.

### 6.2. 回归出的场为何能够保持边缘分布

速度场驱动常微分方程

$$
\frac{dX_t}{dt}=v^*(X_t,t,c),\qquad X_0\sim\pi_0.
$$

要说明它能把噪声边缘分布送往数据边缘分布, 需要比较概率密度的连续性方程. 插值随机变量 $Z_t$ 的密度记作 $p_t(z\mid c)$. 对任意光滑测试函数 $\phi$, 链式法则给出

$$
\frac{d}{dt}\mathbb E[\phi(Z_t)\mid c]
=\mathbb E[\nabla\phi(Z_t)^\top(Z_1-Z_0)\mid c].
$$

再对 $Z_t$ 条件化,

$$
\frac{d}{dt}\mathbb E[\phi(Z_t)\mid c]
=\mathbb E[\nabla\phi(Z_t)^\top v^*(Z_t,t,c)\mid c].
$$

这正是密度满足 $\partial_t p_t=-\nabla\cdot(p_t v^*)$ 的弱形式. 由同一速度场驱动的 ODE 也满足这条连续性方程, 在适当的存在唯一性条件下便拥有与插值过程相同的逐时刻边缘分布. 这里保留的是每个时刻的边缘分布, 并不要求 ODE 的单条轨迹复现训练时那条随机直线. 训练配对会相交, 条件均值会把交叉处的速度合并成确定向量, 采样轨迹因此可以比原始随机配对更平滑.

直线插值也不意味着学习后的轨迹必然是直线. 只有当 $Z_t$ 几乎处处唯一确定两端点时, 条件均值才等于该配对的常速度. 高维数据的许多配对会经过相近区域, $v^*$ 在这些区域发生平均, ODE 积分曲线可能弯曲. Rectified flow 的优势来自回归目标简单且运输路径通常较直, 不是对有限步 Euler 零误差的保证.

### 6.3. 条件生成改变的是哪一个分布

文本条件 $c$ 固定以后, 数据端分布变成 $\pi_1(\cdot\mid c)$. 噪声端仍可取与 $c$ 独立的标准高斯. 条件速度为

$$
v^*(z,t,c)=\mathbb E[Z_1-Z_0\mid Z_t=z,C=c].
$$

语言模型的文本前缀承担 $c$ 的表示. 生成图像位置通过因果注意力读取该前缀, 于是速度场可以随提示改变. 这与理解任务的 next-token 条件概率存在一层共同结构: 两者都先把条件编码进共享隐状态, 再由任务出口读取. 区别在响应分解方式. 文本响应使用离散条件分布 $p(y_i\mid y_{<i},c)$; 图像响应在每个时间点预测连续场 $v(z_t,t,c)$. 共享 Transformer 提供条件计算, 并没有把两种统计目标变成同一个似然函数.

从这个角度也能看出 JanusFlow 的极简边界. 它没有为生成再造一套完整的 DiT 主干, 但仍需 VAE, 生成编码器, 生成解码器, 时间嵌入和独立损失. 如果把统一理解成所有模态共享每一个参数, JanusFlow 显然不符合; 若把它理解为最主要的序列建模参数可被两项任务共同更新, 其结构才成立.

## 7. Euler 采样误差怎样进入最终图像

### 7.1. 三类误差会沿积分过程叠加

把模型场写作 $v_\theta=v^*+\varepsilon_\theta$, 步长记作 $h=1/N$. 一阶 Euler 更新为

$$
\hat z_{k+1}=\hat z_k+h\,v_\theta(\hat z_k,t_k,c),\qquad t_k=kh.
$$

最终误差至少有三部分. 第一部分是统计误差: 有限数据与有限模型容量使 $\varepsilon_\theta$ 不为零. 第二部分是数值误差: 即使已知精确场, 用区间左端斜率代替连续积分也会留下 $O(h)$ 的全局误差. 第三部分来自潜在编码: ODE 最多把噪声送到 VAE 潜在数据分布, VAE 解码本身仍有重建误差. FID 变化无法单独识别这三部分.

若 $v^*$ 对空间满足 Lipschitz 条件 $\|v^*(x,t)-v^*(y,t)\|\le L\|x-y\|$, 并把单步截断误差界记作 $Mh^2/2$, 离散误差 $e_k=\|\hat z_k-z(t_k)\|$ 大致满足

$$
e_{k+1}\le (1+hL)e_k+h\|\varepsilon_\theta(\hat z_k,t_k,c)\|+\frac{M}{2}h^2.
$$

迭代后会出现类似 Grönwall 因子 $e^L$. 这说明某一时刻的小速度误差若把状态推入错误区域, 后续场可能继续放大偏离. 训练均方误差相同的两个模型, 若误差分别集中在轨迹敏感区和稳定区, 最终图像质量可以很不一样. 因此平均 flow-matching loss 不是采样质量的充分统计量.

论文附录观察到其测试范围内增加采样步数收益不大, 可有两种相容解释: 30 步附近数值误差已低于模型误差; 或当前 FID 与 CLIP 指标对更小积分误差不敏感. 该观察没有证明任意提示和任意分辨率都能少步生成. 分辨率升高会增加潜变量维度, 主干和生成编解码器也会改变场的光滑性, 原步数结论不能直接外推.

### 7.2. 为什么潜变量每一步都需要重新计算

语言自回归解码在第 $i$ 个 token 后只追加一个位置, 先前 token 的键值不再改变, 所以 KV cache 能避免重复计算历史前缀. Flow 采样每一步都会把整张潜变量网格从 $z_{t_k}$ 更新为 $z_{t_{k+1}}$. 图像位置对应的输入嵌入全部变化, 先前缓存的图像键值已不再代表新状态. 文本前缀可以缓存, 图像部分仍需整段重算.

设生成网格有 $S$ 个位置, 文本前缀有 $T$ 个位置, 层数为 $L_b$, 隐藏维度为 $d$. 忽略常数后, 每个采样步的注意力开销约为 $L_b(S+T)^2d$, 30 步则乘以 30. 因果掩码将矩阵上三角置零, 在普通稠密内核中未必把 FLOPs 精确减半; 真正收益取决于是否使用能跳过遮蔽区域的实现. 参数量只保存一份不能推导出生成延迟也接近理解任务.

长跳跃连接也值得从信息路径理解. $g_{enc}$ 把带噪潜变量逐级压缩成 LLM token, $g_{dec}$ 再恢复到速度场. 若所有局部信息都必须经过较窄的 Transformer 表示, 高频位置细节容易在瓶颈处丢失. 编解码器之间的长连接给局部结构提供短路径, 共享 LLM 更集中地修正受文本和全局语义控制的部分. 这与 U-Net 的动机相近, 但 JanusFlow 的中间主干仍是因果 LLM, 不能把它等同于标准扩散 U-Net.

### 7.3. CFG 是两个场的外推

训练以概率 $p_{drop}=0.1$ 丢弃文本条件, 得到条件场 $v_c$ 和无条件场 $v_u$. 论文写出的引导场可整理为

$$
v_{cfg}=v_u+w(v_c-v_u)=w v_c+(1-w)v_u.
$$

当 $w=1$ 时就是条件场; $w=0$ 时是无条件场; $w>1$ 时沿着加入文本后速度如何变化的方向继续外推. 它提高提示相关性并没有免费的概率解释: 外推场未必对应训练数据中的某个真实条件分布, 过大的 $w$ 可能把轨迹推离自然图像的高密度区域. 附录里 CLIP 继续提高而 FID 先改善后恶化, 正符合这种张力.

一个简单反例是提示要求红色物体, 而自然数据中红色常与某种饱和度范围共同出现. 条件场会把样本朝红色区域移动; 过强外推可能继续增加饱和度, 虽更容易被 CLIP 判断为红, 却偏离真实图像颜色分布. 这不是 CLIP 或 FID 谁对谁错, 两个指标分别观察文本一致性与分布距离. JanusFlow 选择 $w=2$ 报告 MJHQ FID, 是该模型和评测配方下的工作点.

## 8. 因果注意力在二维生成中的信息结构

### 8.1. 展平顺序引入了人为方向

假设生成编码器输出 $H\times W$ 个位置, 按行展平成 $S=HW$ 个 token. 标准因果掩码下, 第 $i$ 个图像 token 只能读取文本前缀与图像位置 $1,\ldots,i$. 左上位置看不到右下位置, 右下位置却能汇总此前全图. 二维图像原本没有天然的阅读方向, 展平顺序于是成为模型结构的一部分.

速度解码器的卷积与长连接能在 LLM 前后交换局部信息, 因而第一个 LLM token 看不到后续 token 不等于最终第一个像素完全不知道右侧图像. $g_{enc}$ 的卷积感受野可先把邻域混入每个 token, $g_{dec}$ 也能在输出侧传播信息. 但远距离全局依赖仍受到因果方向限制. 如果把扫描顺序反转, 理论上会改变哪些区域享有更丰富上下文; 论文没有报告顺序消融.

这种限制仍能工作的原因来自三条信息路径. 文本前缀对所有图像位置可见, 提供全局语义锚点;每个位置的输入来自当前整图潜变量的卷积特征, 已包含邻域信息;多层因果 Transformer 又让后部 token 建立更广的上下文. 速度场预测由生成解码器联合变换整段隐藏状态, 输出无须逐 token 自回归采样. 因果掩码削弱了对称性, 但没有把任务退化成从左到右逐像素生成.

### 8.2. 共享掩码减少了结构切换

若理解任务用因果掩码, 生成任务用双向掩码, 同一注意力参数会在两种邻接关系下训练. 这未必不可行, 但共享参数需要同时适应不同的可见域. JanusFlow 保留因果掩码, 让两项任务的注意力算子形式一致, 差异集中在输入接口和损失. 对一个从语言预训练初始化的 1.3B 主干, 这种选择减少了结构分布变化.

论文只说其他掩码在初步实验中没有明显收益, 没给出双向, 分块或前缀双向掩码的完整数字. 因果注意力源于共享预训练 LLM 时的结构折中, rectified flow 的数学定义并不要求使用这种掩码. 独立训练的生成 Transformer 可以采用全注意力; 更大规模统一模型也可能从混合掩码受益.

可以构造一个暴露限制的任务: 提示要求画一条跨越图像左右两端且宽度严格恒定的水平线. 若左端 token 无法读取右端当前状态, 全局一致性更多依赖卷积感受野和后续解码器. 双向注意力能在中间层直接比较两端. JanusFlow 的指标中包含关系与属性, 但没有专门隔离这种扫描方向敏感任务, 所以现有评测不能排除因果方向造成的特定失败.

### 8.3. 理解路径的因果掩码承担不同职责

理解任务中, 图像 token 位于回答文本之前. 回答位置可以读取全部图像位置, 所以图像 token 内部是否彼此双向并不直接限制回答读取整张图. 约束发生在视觉 token 经 LLM 再编码的过程中: 靠前图像位置的隐藏状态看不到后部位置, 但回答 token 聚合了所有位置各自携带的 SigLIP 特征. SigLIP 在进入 LLM 前已用视觉 Transformer 建立全局上下文, 进一步减轻了因果限制.

这恰好体现两个入口的分工. 理解侧把二维全局建模主要交给预训练 SigLIP, LLM 负责把视觉语义与语言序列结合; 生成侧由卷积编解码器提供局部空间交换, LLM 负责文本条件与较长程的序列交互. 相同因果主干并不意味着两条路径获得相同的空间归纳偏置.

## 9. REPA 对齐的梯度与几何

### 9.1. 余弦损失约束方向而非范数

设理解教师在位置 $j$ 的特征为 $y_j=f_{enc}(x)_j$, 生成路径第 6 层特征经过 MLP 后为 $r_j=h_\varphi(q_\theta(z_t)_j)$. REPA 损失可写为

$$
\mathcal L_{REPA}=-\frac{1}{S}\sum_{j=1}^{S}
\frac{r_j^\top\operatorname{sg}(y_j)}{\|r_j\|_2\,\|\operatorname{sg}(y_j)\|_2},
$$

其中 $\operatorname{sg}$ 表示停止梯度. 对 $r_j$ 求导得到

$$
\nabla_{r_j}\mathcal L_j
=-\frac{y_j}{\|r_j\|\|y_j\|}
+\frac{(r_j^\top y_j)r_j}{\|r_j\|^3\|y_j\|}.
$$

第二项去掉沿 $r_j$ 自身方向的分量, 梯度主要旋转表示方向, 不直接要求生成特征复制 SigLIP 的范数. 三层 MLP 还允许两套特征先经过非线性坐标变换再对齐. 所以 REPA 约束的是生成中间层能够表达语义方向, 并未要求它与理解特征逐通道相等.

停止梯度决定了教师与学生关系. 如果两侧同时更新, 最容易下降的路径可能是 SigLIP 特征朝生成路径移动, 视觉理解所依赖的语义空间会漂移. 冻结教师后, 生成路径必须承担适配. 阶段 3 虽解冻理解编码器用于 SFT, REPA 的 `stop_grad` 仍阻止生成样本通过这项损失直接拉动教师; 理解侧可以由理解样本自己的目标更新.

### 9.2. 为什么选择中间层而非最终层

靠近输出头的 LLM 隐状态更强地服务于具体响应形式. 理解路径要预测词表 logits, 生成路径要恢复潜在速度, 两者在末端层的局部需求不同. 过早层主要承接输入模态与局部纹理, 语义抽象可能不足. 在中间层施加对齐, 给后续层留下将共享语义重新变成任务输出的空间.

论文选择第 6 个 Transformer block, 没有提供逐层消融, 因此不能断言第 6 层具有普遍最优性. 若主干层数改变, 第 6 层对应的相对深度也改变. 更可迁移的假设是选择已形成语义而尚未被输出头强烈专门化的层, 具体位置需要用线性探针, 表征相似度或生成消融确定.

一个可能的失败例子是细粒度纹理生成. SigLIP 训练目标强调图文语义匹配, 对准确复原草叶纹理或微小噪声可以保持不变. 若 REPA 权重过强, 生成中间层可能过早丢弃对语义无关却影响真实感的细节. JanusFlow 用独立编解码器和长连接为局部信息保留旁路, 同时没有报告 REPA 权重扫描. 表 6 只能说明当前配置提升 FID 与 CLIP, 不能推出对齐越强越好.

### 9.3. 逐位置对齐隐含空间对应假设

损失把第 $j$ 个生成位置与第 $j$ 个 SigLIP 位置配对, 前提是两张网格覆盖近似相同的图像区域. 为此作者调整生成编解码器, 使 $H_{gen}=H_{im}$, $W_{gen}=W_{im}$. 尺寸相同只是必要条件. 若两侧卷积步幅, padding, patch 切分或裁剪坐标不同, 相同索引仍可能指向不同感受野.

对齐的另一个隐含变量是时间 $t$. 教师读取干净图像, 学生读取带噪 $z_t$. 当 $t$ 接近 1, 学生输入保留大量图像结构; 当 $t$ 接近 0, 它几乎只有噪声和文本条件. 后一种情况下要求逐位置贴近干净教师更困难, 学生可能主要依靠文本猜测全局语义. logit-normal 时间采样会改变不同难度的 REPA 样本权重. 论文没有按时间区间报告对齐误差, 这使我们无法判断收益主要来自中低噪声还是高噪声阶段.

REPA 还可能把教师偏差传给生成器. SigLIP 对某些文字, 空间关系或长尾实体表征较弱时, 将其视为固定语义目标不会自动纠正这些弱点. 表征教师的优势是稳定且经过大规模视觉语言预训练; 代价是生成语义空间的上限会部分受教师决定. 这也是为何 REPA 应与 flow 目标共同使用: flow 目标直接监督每个潜变量速度, 防止语义对齐取代图像重建方向.

## 10. 多任务优化的共享梯度

### 10.1. 参数共享使任务关系进入梯度内积

将共享 LLM 参数记作 $\theta_s$, 两项主损失分别为 $L_U$ 与 $L_G$. 一次混合更新的期望梯度可以写为

$$
g=\rho_U\nabla_{\theta_s}L_U+\rho_G\nabla_{\theta_s}(L_{RF}+L_{REPA})+\rho_T\nabla_{\theta_s}L_{text},
$$

其中 $\rho$ 由样本比例, token 数, 损失归一化和批次调度共同决定. 判断生成更新会不会伤害理解, 不能只看两个损失的数值, 还要看共享参数上的梯度内积 $\langle g_U,g_G\rangle$. 内积为正时, 某个小步长下两项任务倾向于共同下降; 内积为负时存在局部冲突; 接近零表示共享参数上近似独立. 解耦视觉编码器直接消除了入口参数上的梯度相加, 但 LLM 内部仍会同时收到两类梯度. 表 6 显示最终性能接近专项模型, 说明当前规模和配方下冲突可控, 论文没有测量逐层梯度夹角.

损失量纲也不同. 自回归交叉熵按响应 token 聚合, flow MSE 按潜变量位置和通道聚合, REPA 按空间位置计算余弦. 即使训练式中没有显式系数, reduction 方式与样本比例已经形成隐式权重. 把三项标成简单相加不代表它们对共享参数贡献相等. 若改动分辨率, 图像位置数变化会改变聚合尺度; 若改动回答长度, AR token 数也变化. 复用配方时需要先确认实现究竟按 token 平均, 按样本平均还是按整个 batch 平均.

### 10.2. 数据比例是动态权重

阶段 1 的 50:50 只训练接口, 共享 LLM 冻结, 此时比例主要决定两个新入口各见多少样本. 阶段 2 的 14:80:6 明显偏向生成, 作者给出的理由是生成收敛更慢. 假设 batch size 512 且比例按样本抽取, 一个期望 batch 约有 72 个理解样本, 410 个生成样本与 31 个纯文本样本; 实际实现会受取整与打包影响. 生成占比高也不等于其梯度必然占 80%, 因为不同样本的序列长度和损失范数不同.

保留 6% 纯文本数据具有抗遗忘作用. 视觉任务中的回答分布通常较短且模板化, 若只训练视觉数据, LLM 的一般语言分布会被狭窄响应覆盖. 纯文本 next-token loss 提供原有语言行为的锚. 它无法保证所有语言能力不退化, 但为共享主干持续提供无视觉条件下的梯度.

阶段 3 将比例调为 21:70:9, 理解与文本比例上升, 同时学习率从 $10^{-4}$ 降到 $2\times10^{-5}$. SFT 数据更接近交互格式, 解冻 SigLIP 又增加了可训练参数, 较小学习率可以降低入口语义空间快速漂移. 从优化角度看, 三阶段方案把随机接口对齐, 大规模共同表征学习, 面向任务格式校准分开, 每阶段允许的参数集合和数据分布都不同.

### 10.3. 打包长度会改变有效样本权重

论文将序列打包到 4096. 若一个理解样本只占数百 token, 一个 packed sequence 可以容纳多条样本; 生成样本的图像网格和文本条件也占用序列位置. 训练算力按 token 消耗, 数据表里的比例却可能按样本定义. 当两类样本平均长度差异明显时, 样本比例与计算比例并不相等.

因果掩码还要求打包样本之间建立隔离, 否则后一条样本可能读取前一条无关样本. 通常需要 block-diagonal attention 或正确的 position id 与 loss mask. 论文给出 packed sequence length, 没展开隔离实现. 这属于实现正确性条件: 若跨样本泄漏, 训练损失可能更低, 推理时却没有那些前序内容.

## 11. 解耦视觉编码器到底隔离了什么

### 11.1. 理解追求不变性, 生成追求可逆信息

视觉理解希望同一对象在轻微颜色变化, 裁剪或纹理扰动下仍有相近语义表示. 这种不变性有助于分类和问答. 图像生成的逆过程却要恢复颜色, 边缘与局部纹理; 若入口已经把这些差异压掉, 后续速度场无法凭空找回与当前状态对应的细节. 两项任务对充分统计量的要求不一样.

用信息论语言表示, 理解特征 $F_U$ 希望保留与语义标签 $Y$ 相关的信息 $I(F_U;Y)$, 同时可以降低与无关纹理 $N$ 的互信息. 生成特征 $F_G$ 需要对潜变量速度 $V$ 足够充分, 很多对分类无关的 $N$ 恰好影响 $V$. 强迫 $F_U=F_G$ 会让同一瓶颈同时满足不看纹理和精确保存纹理. 参数容量足够大时也许能分子空间编码, 但优化梯度仍可能互相牵制.

JanusFlow 让 SigLIP 负责 $F_U$, ConvNeXt 编解码器负责 $F_G$, 再由共享 LLM 学习较高层的条件关系. REPA 只要求生成中间特征具有与教师相似的语义方向, 没有让原始输入表示相同. 这是一种底层信息分工, 中层语义联系的结构.

### 11.2. 表 6 如何逐步隔离变量

实验 B 让理解与生成共享 VAE 加 ConvNeXt, 理解指标明显较低. 实验 C 将两侧参数分开, 但理解侧仍采用相同类型的 VAE 与 ConvNeXt. B 到 C 的变化较能反映参数解耦: POPE 从 78.13 降至 75.30, VQAv2 从 53.94 升至 55.41, GQA 从 44.04 升至 44.44, 三项并未一致上升. 这意味着仅分开两份随机或生成取向编码器不足以稳定改善理解.

实验 F 使用预训练 SigLIP 理解编码器, 并保留独立生成路径和 REPA, 理解成绩大幅提高. C 到 F 同时改变预训练来源, 架构与对齐项, 无法将提升单独归给某一个因素. A 与 F 更接近 REPA 消融: A 不用 REPA, F 使用 REPA, 生成 FID 从 19.84 改善至 17.61. 理解侧三项有升有降, 说明 REPA 的最直接收益落在生成路径.

严格的全因子实验需要至少控制四个轴: 参数是否共享, 理解编码器是否预训练, 生成编码器类型, 是否使用 REPA. 论文没有覆盖所有组合. 因而结论可以支持作者整套解耦加预训练语义编码器的方案有效, 以及当前配置中 REPA 改善生成; 不能把每个差值都解释成纯粹的解耦收益.

### 11.3. 预处理也是一种任务解耦

理解图像按长边缩放后 padding, 最大限度保留完整画面; 生成图像按短边缩放后随机裁剪, 保证目标区域被像素填满. 假设原图宽高比为 2:1, 目标为正方形. 理解预处理缩放后会有一半面积是 padding, 但左右两端对象都保留. 生成预处理会裁掉约一半横向范围, 却不要求模型生成大块空白边框.

若共用同一预处理, 代价会落在不同位置. 全部使用裁剪会损害需要读取边缘对象的问答; 全部使用 padding 会让生成模型学习人为边框和长宽比相关空区. JanusFlow 的任务分工不只在网络模块, 也发生在数据变换. 因此研究共享编码器是否冲突时必须控制预处理, 否则输入分布差异会与参数共享混在一起.

## 12. 评测数字怎样连接到机制

### 12.1. GenEval 分项比总分透露更多

GenEval 将单对象, 两对象, 计数, 颜色, 位置和颜色归因分开. JanusFlow 384 的对应成绩为 0.97, 0.59, 0.45, 0.83, 0.53, 0.42, 总分 0.63. 单对象与颜色较强, 计数和颜色归因较弱. 后两项需要把属性绑定到正确实体或维持多个离散实例, 对空间关系和组合表示要求更高.

这一形态与因果网格可能有关, 也可能来自训练数据的描述分布, 模型容量或评测检测器. 仅凭分项不能识别因果. 若要验证掩码假设, 需要在相同数据和初始化下只替换注意力掩码, 再观察计数与归因是否定向改善. 论文没有这组消融, 所以分项适合定位错误类型, 不足以确认结构原因.

256 模型总分 0.70 高于 384 的 0.63, 其中两对象从 0.59 升到 0.73, 计数从 0.45 升到 0.54, 位置从 0.53 升到 0.63. 同时 384 的 MJHQ FID 9.51 优于 256 的 12.70. 固定 1.3B 主干时, 384 网格让每张图需要处理更多空间状态, 有助于纹理和分布质量, 却可能让有限容量更难完成组合控制. 这是一种合理解释, 仍需控制训练预算和网格长度后验证.

### 12.2. FID 不能定位生成链条的误差来源

FID 比较 Inception 特征的均值和协方差,

$$
\operatorname{FID}=\|\mu_r-\mu_g\|_2^2+
\operatorname{Tr}(\Sigma_r+\Sigma_g-2(\Sigma_r\Sigma_g)^{1/2}).
$$

它把真实图像与生成图像各自近似为特征空间高斯分布. 较低 FID 表明前两阶统计更接近, 不保证每条提示都被正确遵循, 也不直接衡量单图美感. JanusFlow 的 FID 改善可能来自 VAE 连续表示, flow 场, REPA, 数据过滤或采样参数的组合.

FID 还依赖样本数, 图像预处理和特征实现. 论文报告 MJHQ FID-30k, 跨论文比较时需要相同 30k 提示与实现. 表 4 给出竞争位置, 但各模型训练数据与分辨率仍不同. 同表的 1.3B JanusFlow 9.51 和 Janus 10.10 很接近, 这组结果支持新路线有竞争力; 若要证明 rectified flow 本身贡献 0.59, 应在 JanusFlow 框架内只替换连续与离散生成目标.

### 12.3. 专项对照回答的是配方内问题

统一实验 F 的理解结果与专项 D 接近, 生成结果与专项 E 接近. 这一对照比跨论文榜单更有意义, 因为训练基础设施与数据口径更接近. 但 D 训练 13,000 步, E 训练 37,000 步, 是按统一模型 50,000 步的数据比例拆分. 它控制了各任务看见的样本数, 没保证专项模型达到自己的最佳超参数和收敛点.

假设生成任务需要更长 warm-up, 专项 E 的 37,000 步可能尚未充分收敛; 反过来, 若统一模型的共享语言表示为生成提供迁移, 相同步数下接近专项模型正是统一训练的收益. 要区分这两种情况, 需要给出完整学习曲线, 等计算量对照与各自调优结果. 当前实验最可靠的表述是: 在作者采用的共同训练配方和样本预算下, 统一模型接近拆分后的专项对照.

## 13. 从 Janus 到 JanusFlow 的路线变化

### 13.1. 离散图像 token 把误差集中在码本

Janus 的生成路径先由视觉 tokenizer 将图像量化成离散码序列, LLM 再自回归预测这些码. 若码本大小为 $K$, 每个位置使用交叉熵学习 $K$ 类分布. 优点是文本和图像都可写成离散 next-token prediction, 推理只需沿序列逐步采样. 代价是量化器必须先把连续图像压到有限码字, 码本重建误差构成生成质量上限的一部分.

JanusFlow 保留 SDXL-VAE 的连续潜变量, 取消生成码本上的离散分类. 误差重心转为 VAE 压缩误差, 速度回归误差和 ODE 离散误差. 两条路线都不是无损: 离散路线受码本与自回归曝光偏差影响; 连续路线受迭代场估计和数值积分影响. 选择哪条路线要同时看图像质量, 指令遵循, 延迟和训练稳定性.

### 13.2. 两种因子分解带来不同依赖结构

离散自回归把图像概率写作

$$
p(s_{1:S}\mid c)=\prod_{i=1}^{S}p(s_i\mid s_{<i},c).
$$

每个位置在一次生成中只决定一次, 前面采错的 token 会成为后续条件. Flow 则从全局噪声状态出发, 每一步同时修正整张潜变量网格. 某个局部在早期偏离后仍可能在后续时间被改正, 但每一步都需处理全部位置. 自回归的序列步数随 $S$ 增长, flow 的积分步数通常固定在几十, 每步计算却覆盖 $S$ 个位置.

若只数网络前向次数, flow 的 30 次小于数百个图像 token 的自回归次数; 若考虑每次前向的序列长度和 KV cache, 两者的实际吞吐关系不再简单. 离散自回归每步可复用历史 KV, flow 图像状态整体改变. 论文未提供同硬件端到端比较, 所以无法从步数直接判定哪条路线更快.

### 13.3. 连续目标更自然地接入表征对齐

REPA 使用每个空间位置的连续中间特征与 SigLIP 对齐. 离散码路线也能加入语义损失, 但量化索引本身只表示码字编号, 其几何距离没有天然连续含义. Flow 路径从带噪连续潜变量到连续速度, 中间表示更容易接受余弦对齐而不改动输出词表.

这不等于连续生成天然拥有更强语义. 文本条件是否被利用仍取决于数据, 主干和引导. JanusFlow 的贡献在于证明预训练因果 LLM 可以承接连续场预测, 并借助解耦入口与 REPA 达到有竞争力的结果. 论文没有建立所有统一模型都应放弃离散 token 的一般结论.

## 14. 可以从现有证据推出的设计准则

### 14.1. 先区分共享计算与共享输入统计

两个任务都能使用 Transformer, 只说明它们可共享序列计算形式. 是否共用编码器取决于输入表示需要保留什么信息. 理解希望压缩与问答无关的变化, 生成需要保留许多局部差异. JanusFlow 将最昂贵的 LLM 主干共享, 将目标冲突最直接的视觉入口拆开, 这是表 6 支持最充分的结构方向.

复用到视频时, 还需问时间编码器是否同时适合理解和生成. 视频理解可能只需抓住关键事件, 视频生成则要保持逐帧运动与纹理. 直接复制同一个视频编码器会重现视觉冲突; 保留专项入口, 在共享主干中交换语义, 更接近 JanusFlow 的实际经验.

### 14.2. 表征对齐要保留任务私有通道

REPA 的有效组合包含三个条件: 教师冻结, 对齐发生在中间层, 生成编解码器有自己的局部路径. 如果删掉私有路径并强迫全部特征与教师一致, 语义不变性可能吞掉生成细节. 如果教师也随生成损失漂移, 对齐目标可能失去稳定参照. 如果只在最终输出层对齐, 又会直接干扰两种不同响应形式.

因此对齐不是越多层越好. 更合理的实验轴包括层位置, 对齐权重, 时间区间与空间粒度. 可以分别测量高噪声和低噪声的余弦相似度, 检查 REPA 是否主要帮助语义布局还是局部去噪; 也可以只对全局 pooled token 对齐, 与逐位置对齐比较空间约束的贡献.

### 14.3. 统一模型必须报告两侧代价

只报告参数总量会遗漏迭代生成成本, 只报告 FID 会遗漏理解退化. 完整对照至少需要四类量: 理解任务成绩, 生成语义与分布指标, 每任务推理延迟和显存, 以及相同样本或相同计算预算下的专项模型. JanusFlow 已给出两侧能力和短程专项消融, 但没有延迟吞吐与充分调优的等计算对照.

在当前证据范围内, JanusFlow 最有分量的结论是可行性: 一个预训练因果 LLM 可以在保留文本自回归能力的同时学习连续图像速度场; 输入解耦和单向语义对齐让两种目标在 1.3B 规模上共存. 至于更大模型是否更省总成本, 因果掩码是否仍是最佳选择, 以及 REPA 在何种时间区间起主要作用, 都需要新的受控实验回答.

## 15. 复核 JanusFlow 时的计算链

### 15.1. 从图像到训练目标

以一张目标图像 $I$ 和文本 $c$ 为例, 生成训练可以按以下依赖顺序复核. VAE 编码得到 $Z_1=E_{vae}(I)$. 采样 $Z_0\sim\mathcal N(0,I)$ 和时间 $t$, 构造 $Z_t=(1-t)Z_0+tZ_1$, 监督速度 $U=Z_1-Z_0$. $g_{enc}$ 把 $Z_t$ 变成与 LLM 隐藏宽度相同的网格 token, 时间嵌入与文本 token 一同进入因果主干. $g_{dec}$ 将主干输出还原为 $\hat U$. 主损失比较 $\hat U$ 与 $U$.

与此同时, 干净图像经过 SigLIP 得到 $Y=f_{enc}(I)$. 第 6 层 LLM 特征 $Q$ 经三层 MLP 得到 $R$, 按位置计算 $R$ 与停止梯度后的 $Y$ 的余弦损失. 生成批次更新 $g_{enc}$, 共享 LLM, $g_{dec}$ 与投影 MLP, 不通过 REPA 更新 SigLIP. 理解批次则让 SigLIP 图像特征投影到 LLM 序列, 只在回答 token 上计算交叉熵.

这条链中任何一处 shape 不一致都会改变方法. VAE 潜变量的通道数决定生成入口; $g_{enc}$ 输出位置数必须与 LLM 序列和 REPA 网格相容; $g_{dec}$ 输出必须与 $U$ 同形; 理解图像 token 的隐藏宽度必须等于语言嵌入宽度. 论文强调无需复杂架构改造, 指的是 LLM 主干可以保持原形式, 不是外围张量接口可以省去.

### 15.2. 从噪声到图像

推理从 $z_0\sim\mathcal N(0,I)$ 开始. 对 $k=0,\ldots,N-1$, 分别用条件文本和空条件得到 $v_c,v_u$, 合成 $v_{cfg}$, 再更新

$$
z_{k+1}=z_k+\frac{1}{N}v_{cfg}(z_k,k/N).
$$

得到 $z_N$ 后, VAE 解码器输出图像 $\hat I=D_{vae}(z_N)$. 如果条件与无条件通过 batch 拼接一次前向计算, 单步仍需近似双倍 batch; 如果顺序调用, 就是两次主干前向. 文本前缀可以预计算, 图像 token 每一步重新生成. 这些细节共同决定真实延迟.

数值复核时还要注意潜变量缩放. SDXL-VAE 常在编码和解码之间使用固定 scaling factor, 若训练目标与解码端缩放不一致, ODE 即使准确拟合也会落到错误幅值. 官方仓库提示 VAE 使用 bfloat16 而非 fp16, 说明数值精度也是复现条件. 这类实现信息能解释模型是否正常运行, 但不应替代对速度场机制的分析.

### 15.3. 一个最小的反事实实验矩阵

若要继续验证论文机制, 可以保持数据, 初始化和计算预算一致, 只改变一个轴. 第一组比较因果与双向掩码, 并按扫描方向敏感任务报告结果. 第二组比较无 REPA, 全局 pooled 对齐和逐位置对齐, 同时按时间区间记录损失. 第三组固定 SigLIP, 比较共享与独立生成入口, 排除视觉预训练差异. 第四组比较 Euler 步数和二阶求解器, 把模型误差与数值误差分开.

每组都应同时观察理解与生成. 例如双向掩码可能改善图像一致性, 却改变预训练 LLM 的注意力分布并伤害理解; 更强 REPA 可能提高 CLIP, 却损害纹理 FID; 高阶求解器可能减少步数, 单步成本又更高. 单个最终分数无法覆盖这些交换关系.

JanusFlow 已完成关键的第一步: 它把两个看似不同的目标放进同一主干, 并用受控消融证明整套接口能工作. 更深入的研究问题集中在共享到哪一层, 在哪个时间和空间尺度对齐, 以及有限计算应分给模型容量还是积分精度. 这些问题都能从现有结构自然提出, 同时也划定了论文实验尚未覆盖的范围.

## 16. 时间采样决定模型把容量用在哪里

### 16.1. 均匀采样并不等于均匀难度

Flow matching 的总体风险可以写成

$$
\mathcal L=\int_0^1 q(t)\,
\mathbb E[\|v_\theta(Z_t,t,c)-(Z_1-Z_0)\|_2^2\mid t]dt,
$$

其中 $q(t)$ 是时间采样密度. 改变 $q(t)$ 等价于改变不同噪声阶段在训练中的权重. 即使使用均匀时间, 各阶段也没有相同难度. $t\approx0$ 时 $Z_t$ 几乎是高斯噪声, 单个状态对具体 $Z_1$ 提供的信息很少, 条件速度目标方差较大; $t\approx1$ 时图像结构清晰, 去噪方向较容易从局部内容判断. 中间区间则常决定全局布局怎样从噪声中形成.

JanusFlow 沿用 Stable Diffusion 3 的 logit-normal 时间采样. 可以先采 $u\sim\mathcal N(\mu,\sigma^2)$, 再令 $t=\operatorname{sigmoid}(u)$. 当 $\mu=0$ 时分布关于 $0.5$ 对称, 密度会按 $\sigma$ 改变对中间或端点的关注. 论文没有列出单独的时间分布消融, 所以不能把性能提升归因于该选择;它属于完整训练配方的一部分.

时间采样还会同时作用于 REPA. 在高噪声端, 学生只能借助文本与很弱的图像线索靠近干净 SigLIP 特征;在低噪声端, 逐位置匹配更容易. 若 $q(t)$ 大量覆盖中间区域, REPA 主要教生成主干在结构开始显现时建立语义. 若改成端点加权, 同一个对齐系数对应的有效难度就会变化. 因而时间分布与 REPA 权重不宜独立调节后直接拼接结论.

### 16.2. 目标方差揭示高噪声端的学习压力

固定 $(z,t,c)$ 后, MSE 无法消除的风险是条件方差

$$
\operatorname{Var}(Z_1-Z_0\mid Z_t=z,C=c).
$$

它刻画同一个中间状态可能对应多少不同端点速度. 当目标分布多模态且 $t$ 很小时, 该方差通常较大. 网络预测条件均值以后, 单样本监督仍围绕它剧烈波动, 梯度噪声也更强. 文本越具体, 条件分布越窄, 方差可能越小;模糊提示允许多种图像, 高噪声端便更难确定方向.

这解释了 CFG 为何在采样早期特别有影响. 条件场与无条件场的差异携带提示对多模态分布的收缩方向, 外推会更早推动全局布局靠近文本. 过强外推也会过早排除合理模态, 形成构图单一或细节失真. 若只在所有时间使用同一个 $w$, 默认假设各阶段适合同等引导强度;论文没有探索随时间变化的 CFG.

### 16.3. 时间参数化影响速度尺度

线性插值下目标速度是 $Z_1-Z_0$, 与 $t$ 无关;网络输出仍随 $t$ 变化, 因为条件均值随可观察状态改变. 若改用非线性路径 $Z_t=\alpha(t)Z_1+\sigma(t)Z_0$, 目标速度会变成

$$
\dot Z_t=\dot\alpha(t)Z_1+\dot\sigma(t)Z_0.
$$

时间重参数化会直接改变不同阶段的目标幅值和 ODE 刚性. JanusFlow 的 30 步经验依赖线性路径, 时间分布和 Euler 求解器的组合. 将同一模型思想移到另一种噪声日程时, 需要重新检查输出参数化与采样步长, 不能仅替换 $t$ 的取值范围.

一个常见误解是直线路径必然让数值求解简单. 训练样本的路径是直线, 条件平均场的积分线可能弯曲;模型误差还会让实际场出现高曲率. 真正决定 Euler 难度的是学习场沿采样轨迹的导数, 而非训练插值公式表面上是否线性.

## 17. 自回归理解目标的掩码与归一化

### 17.1. 为什么损失只落在回答 token

理解序列包含系统或用户文本, 图像嵌入以及回答文本. 若条件部分也计算语言建模损失, 模型会被要求复述用户提示或预测图像占位符, 这些目标与回答质量没有直接关系. JanusFlow 只对 $x^{res}$ 的 token 求负对数似然,

$$
\mathcal L_{AR}=-\sum_{i=1}^{\ell_{res}}
\log p_\theta(x_i^{res}\mid x^{con},x_{<i}^{res}).
$$

图像嵌入虽然没有离散标签, 仍通过回答损失接收梯度. 回答位置读取图像表示, 链式法则把误差信号传回投影层, SigLIP 以及共享 LLM. 阶段 2 冻结 SigLIP 时, 梯度止于视觉入口;阶段 3 解冻后, SFT 可以调整视觉特征以适应问答目标.

若按 token 平均损失, 长回答贡献更多独立监督项, 但每项经总 token 数归一化;若按样本先平均再聚合, 短回答和长回答可能获得相近样本权重. 论文给出最大序列与打包策略, 没详细说明该归一化. 它会影响理解梯度相对 flow 梯度的尺度, 也是复现实验时需要从代码或训练配置确认的细节.

### 17.2. 图像位置是条件, 不是要预测的词

理解路径先由 SigLIP 产生二维特征, 再线性投影到语言隐藏维度并放入 |BOI| 和 |EOI| 之间. 这些连续向量占据序列位置, 注意力可以读写其隐藏状态, 但语言头不必把它们还原成词表 token. 这种接口绕开了视觉离散化, 代价是图像位置数量固定受编码器 patch 网格控制.

若输入分辨率从 256 提到 384, patch 数随面积增长. 在 patch 大小保持不变时, 边长扩大 1.5 倍会令位置数约扩大 2.25 倍. 注意力矩阵面积进一步平方增长, 共享 4096 长度预算中留给文本的空间也会减少. 论文的分辨率提升既增加视觉信息, 也改变计算和序列竞争;理解指标上升说明额外细节在当前配方下有用, 却不能视为没有成本的分辨率收益.

### 17.3. 纯文本数据维护的是条件计算底座

共享 LLM 在视觉任务中会频繁看见特殊图像 token, 较短回答和生成速度目标. 纯文本批次让它继续训练一般 next-token 分布, 维持语法, 世界知识与长文本条件能力. 这种维护会间接帮助两条视觉路径:理解需要用语言表达答案,生成需要把提示词转成条件隐状态.

纯文本比例 6% 或 9% 不能保证原始语言基准完全保持. 遗忘取决于视觉梯度强度, 学习率, 数据覆盖和参数规模. 论文的视觉理解基准包含问答与推理, 但未系统报告纯语言基准的前后变化. 因而可以确认训练混入了纯文本锚点, 尚不能量化它保护了多少通用语言能力.

## 18. 潜变量接口决定哪些细节可被恢复

### 18.1. VAE 是生成分布的一部分

生成模型学习的是潜变量分布 $p_Z$, 最终图像分布由固定解码器的映射 $D_{vae}$ 推前得到. 即便 $p_Z$ 被精确学习, 输出质量仍受 $D_{vae}(E_{vae}(I))$ 的重建能力限制. 细小文字, 规则线条和高频纹理可能在 VAE 压缩阶段损失, 速度场无法恢复编码中已消失的具体信息.

相比离散 tokenizer, 连续 VAE 没有最近邻码本量化, 但仍有空间下采样和概率编码瓶颈. “连续”只表示潜变量取值不被限制为有限编号, 不表示映射可逆. JanusFlow 使用成熟的 SDXL-VAE, 借用了其图像先验与重建质量, 也继承其已知边界.

训练目标在潜在空间使用欧氏 MSE. 两个潜变量方向具有相同平方距离, 不保证它们对解码图像造成相同感知变化. VAE 某些通道或空间区域可能对输出更敏感. 因而 flow loss 对潜变量误差的均匀权重, 经过解码后会形成非均匀视觉误差. FID 与人类视觉指标正是在输出端重新观察这些差异.

### 18.2. 生成编解码器承担坐标变换

$g_{enc}$ 需要把 VAE 潜变量的局部连续场映射成 LLM 的 token 表示, $g_{dec}$ 再把隐藏状态映射回潜变量速度. 这两个模块不仅调整维度, 还连接卷积空间与因果序列空间. 若仅使用逐位置线性层, 每个 token 在进入 LLM 前无法获得邻域结构;ConvNeXt 让局部边缘和纹理先形成稳定特征.

长连接使 $g_{dec}$ 同时读取编码侧不同尺度的信息. 可以把最终速度分成概念上的两部分

$$
\hat v=\hat v_{local}(z_t)+\hat v_{semantic}(z_t,t,c),
$$

其中局部项可沿卷积旁路保留当前状态细节, 语义项主要经 LLM 受文本与全局上下文调节. 实际网络没有显式按该式相加, 这是一种理解信息路径的分解. 它解释了为什么共享主干不必承载所有像素级信息.

若生成编码器过强, 它可能在进入 LLM 前完成大量去噪, 共享主干对生成的贡献会减弱;若过弱, LLM 需要用语言结构处理低层纹理, 容量利用不经济. 论文报告编解码器合计约 70M 参数, 相对 1.3B LLM 较小, 但未给出宽度和深度规模消融.

### 18.3. 空间分辨率同时改变统计问题与计算问题

384 分辨率包含更多局部自由度. 在相同数据量下, 模型需要估计更高维速度场;在相同主干宽度下, 每个位置能获得的全局容量相对减少. 另一方面, 更细网格降低了 VAE 与缩放预处理丢失小物体的概率. 所以理解提升和生成指标分化都可以由“信息更多但优化更难”来解释.

要隔离分辨率效应, 理想对照应让 256 与 384 模型看到相同数量的图像和近似相同总计算, 再分别报告随训练步数和 FLOPs 的曲线. 若只固定步数, 384 模型已经消耗更多计算;若只固定 FLOPs, 它能看到的样本又更少. 论文附录给出了最终结果, 没有展开这两种预算口径.

## 19. 失败模式可以从机制中提前推断

### 19.1. 多对象绑定容易同时受数据与结构影响

提示“红色立方体在蓝色球体左边”要求模型同时生成两个对象, 赋予正确颜色并维持位置关系. 文本侧需要形成实体槽位, 图像侧需要让相隔较远的位置共享同一关系约束. GenEval 中颜色归因与计数弱于单对象, 表明组合绑定仍是短板.

错误可能来自三处. 训练描述若常省略精确关系, 条件场缺少监督;因果网格使前部位置难以读取后部当前状态, 全局协调压力增加;CFG 外推也可能强化最显著名词而弱化关系词. 区分三者需要数据分层, 掩码消融和按词类改变引导强度, 单看生成样例无法定位.

### 19.2. 文字生成跨越两套视觉目标

视觉理解中的 OCR 受益于 SigLIP 和高分辨率输入, 任务是把已有字形映射成文本 token. 文生图中的文字渲染则要求从文本 token 产生精确笔画, 经过 flow 场, VAE 解码和图像采样后仍保持字符结构. 前者优秀不推出后者优秀, 因为信息方向和瓶颈完全不同.

VAE 对高频笔画的压缩, 生成网格的空间分辨率以及训练数据中带字图像的标注质量都会影响文字渲染. REPA 强调语义相似, SigLIP 可能判断一张招牌语义正确, 即使具体拼写错误. 因而 REPA 也无法单独解决生成文字的逐字符约束.

### 19.3. 罕见概念可能在共享主干中出现非对称迁移

理解数据里出现过某个罕见物体, 不保证生成数据也包含足够图像示例. 共享 LLM 可能已经知道名称和语义关系, 生成编解码器与 flow 场却没学到相应视觉分布. 此时模型能在问答中识别或描述概念, 生成时只给出近邻类别. 反方向也可能发生:生成数据含大量无精确问答标注的视觉风格, 模型会画却难以用语言区分.

统一训练为跨任务迁移提供参数通道, 没有创造缺失的监督. REPA 可将生成表示拉向理解语义, 前提是 SigLIP 对该概念已有稳定方向, 且生成数据提供足够视觉细节. 长尾概念的真实收益需要按训练频次分桶评估.

### 19.4. 迭代误差会表现为结构逐步漂移

若速度场在某个时间区间系统性高估边缘移动, Euler 每一步都会把轮廓推得更远. 早期误差常影响布局, 后期误差更容易表现为纹理和局部伪影, 但二者并非严格分离. 记录每个时间点的预测误差并把中间潜变量解码, 可以观察对象数量何时确定, 关系何时破坏以及细节何时形成.

只比较最终图像会把路径信息压缩掉. 对 JanusFlow 这类迭代模型, 时间分段诊断能直接连接到训练采样:若错误集中在高噪声段, 可以调整时间密度或条件表达;若低噪声段纹理受损, 需要检查 VAE, 局部旁路或求解步长. 论文展示了最终指标与采样超参数曲线, 尚未给出这类逐时刻错误分解.

## 20. 结论的证据层级

论文直接证明了三件事. 第一, 在增强版 DeepSeek-LLM 1.3B, 指定数据和三阶段训练下, 因果 LLM 可以承担 rectified flow 速度预测. 第二, 采用独立 SigLIP 理解入口, ConvNeXt 生成入口和 REPA 的完整配置, 在作者报告的理解与生成基准上具有竞争力. 第三, 短程消融中 REPA 改善生成指标, 完整统一模型接近按样本比例拆分的专项对照.

机制分析还能支持若干受条件限制的推论. 解耦入口减少了两类视觉目标在底层参数上的直接冲突;REPA 用固定语义教师约束生成中间表示方向;flow 的迭代成本不会因共享参数自动消失;因果掩码引入扫描方向, 其影响被卷积入口, 视觉教师和生成解码器部分缓冲. 这些推论由结构与公式给出, 具体效应大小仍需额外消融.

现有结果没有证明 rectified flow 在所有统一模型上优于离散 token, 没有证明第 6 层或 30 步是普遍最优, 也没有证明扩大 LLM 后两项任务仍保持当前平衡. 训练数据包含未公开部分, 端到端延迟和纯语言遗忘也未完整报告. 这些边界不会削弱 JanusFlow 的核心贡献, 反而把它放在准确位置:它提供了一套简洁而有效的统一接口, 并留下足够清晰的变量供后续研究继续拆解.

## 21. 用一个低维例子核对速度回归

### 21.1. 高斯到高斯时可以算出条件速度

取一维情形 $Z_0\sim\mathcal N(0,1)$, $Z_1\sim\mathcal N(m,s^2)$, 两者独立. 线性插值

$$
Z_t=(1-t)Z_0+tZ_1
$$

仍是高斯, 均值为 $tm$, 方差为

$$
D_t=(1-t)^2+t^2s^2.
$$

目标速度 $U=Z_1-Z_0$ 与 $Z_t$ 联合高斯. 它们的均值分别是 $m$ 与 $tm$, 协方差为

$$
\operatorname{Cov}(U,Z_t)
=\operatorname{Cov}(Z_1-Z_0,(1-t)Z_0+tZ_1)
=ts^2-(1-t).
$$

联合高斯的条件均值给出最优场

$$
v^*(z,t)=m+\frac{ts^2-(1-t)}{D_t}(z-tm).
$$

即使每条训练连线的速度 $Z_1-Z_0$ 是常数, 最优场仍随 $z$ 和 $t$ 变化. 当目标也是标准高斯, 即 $m=0,s=1$, 两端分布相同, 训练中的独立配对仍产生非零随机速度;条件平均场为

$$
v^*(z,t)=\frac{2t-1}{(1-t)^2+t^2}z.
$$

它在 $t=1/2$ 时为零, 前半程收缩, 后半程扩张, 最终将标准高斯边缘送回标准高斯. 这个例子很重要:端点分布相同也不意味着训练目标逐样本为零. Rectified flow 匹配的是边缘演化, 训练采用的独立耦合会让中间分布先改变再恢复.

### 21.2. 文本条件可以改变均值和方差

再假设不同提示 $c$ 对应不同的 $m_c,s_c$. 条件场变为

$$
v^*(z,t,c)=m_c+
\frac{t s_c^2-(1-t)}{(1-t)^2+t^2s_c^2}(z-tm_c).
$$

提示通过 $m_c$ 改变样本向哪个中心移动, 也通过 $s_c$ 改变收缩与扩张强度. 对图像而言, 文本条件对应一整族符合描述的图像分布, 并非单个目标图. 「一只猫」的条件方差远大于指定姿态, 背景和风格的长提示. 共享 LLM 要把这种条件信息注入每个图像位置的速度预测.

CFG 可以在这个例子里理解为条件场与边缘场的线性外推. 当条件均值与无条件均值相差很大时, $w>1$ 会把终点均值推得更远;若真实条件分布并没有对应的外推均值, 最终样本就会偏离数据. 这给前文的 FID 与 CLIP 张力提供了一个可计算的低维对应.

### 21.3. Euler 步数可以手算误差

若某段场近似线性 $v(z,t)=a(t)z+b(t)$, Euler 更新为

$$
z_{k+1}=(1+h a_k)z_k+h b_k.
$$

最终状态包含乘积 $\prod_k(1+h a_k)$. 连续解的对应因子为 $\exp(\int a(t)dt)$. 当 $a_k$ 较大或快速变化时, 两者差异明显;当场较平滑且 $h=1/30$ 足够小, 乘积逼近指数, 增加步数收益就会减弱. 这说明附录中的步数曲线实际在测模型场与求解器的组合, 并非单独测 rectified flow 理论.

该手算也揭示稳定性条件. 若某一步 $1+h a_k$ 绝对值过大, 离散轨迹可能放大误差甚至振荡, 连续 ODE 本身仍可能稳定. 更高阶求解器能够减小截断误差, 但无法纠正 $v_\theta$ 的系统偏差. 在模型误差占主导时继续增加求解阶数, 计算增长却未必改善图像.

## 22. 训练阶段之间的参数状态转换

### 22.1. 第一阶段校准随机接口的数值范围

预训练 LLM 已适应某种嵌入分布:每层输入的范数, 均值和方向具有相对稳定的统计. 随机初始化的 $g_{enc}$ 若直接与 LLM 一起高学习率训练, 可能向主干送入幅值异常的图像 token, 共享参数会为了适应随机接口而大幅漂移. 第一阶段冻结 LLM, 让接口先学会产生主干可处理的特征, 同时让 $g_{dec}$ 建立到速度空间的基本映射.

这个过程类似在固定坐标系两端学习适配器. 理解侧的预训练 SigLIP 已有语义表示, 主要需要线性投影到 $D_{emb}$;生成侧从头训练的模块还要学会处理不同 $t$ 下的带噪潜变量. 10,000 步不能保证生成质量收敛, 其职责是避免随机外围模块把后续联合训练起点变成严重失配状态.

阶段 1 没有纯文本数据, 因为 LLM 冻结后不存在语言遗忘. 50:50 的理解与生成比例保证两种接口都获得适配机会. 一旦阶段 2 解冻主干, 纯文本数据才开始对共享参数提供锚定.

### 22.2. 第二阶段建立共同计算空间

390,000 步是训练主体. SigLIP 冻结让理解输入语义保持稳定, 共享 LLM 同时学习问答条件与 flow 场, 生成编解码器继续更新. 此时 REPA 的教师也稳定,生成学生面对的是固定目标空间. 若同步大幅更新 SigLIP, 教师特征和理解入口都会移动,共享主干必须追踪两个变化源.

学习率 $10^{-4}$ 对随机接口与共享主干是否使用完全相同参数组, 论文表格没有进一步区分. 即使全局学习率相同, AdamW 的自适应二阶矩会令不同参数得到不同有效步长. 权重衰减为 0 表示没有显式 $L_2$ 收缩, 更新主要由三类训练损失和梯度裁剪控制.

梯度裁剪阈值 1.0 对多任务训练尤其重要. 某类 batch 若因图像位置多或 flow 目标异常产生大梯度, 全局裁剪会限制单步破坏. 但裁剪也会改变任务的相对权重:若生成梯度更常超过阈值, 它的有效幅值会被压缩. 论文未报告各任务裁剪频率, 数据比例不能完整代表实际优化占比.

### 22.3. 第三阶段允许视觉教师适应对话任务

SFT 解冻 SigLIP 后, 理解损失可以改变视觉特征, 使它更适合任务专项会话,图表或文字问题. 学习率降低到 $2\times10^{-5}$, 并把理解与纯文本比例提高. 这降低了生成占主导的数据继续改写共享主干的速度, 也为模型输出格式和对话行为提供更多监督.

SigLIP 的更新来自理解路径;REPA 教师分支停止梯度, 所以生成样本不会直接推动它. 不过教师在不同训练步仍会因理解更新而缓慢变化, 生成路径下一次看到的对齐目标也随之变化. 较小学习率让这种目标漂移更平缓. 这是“停止单次反向梯度”与“整个训练期间教师完全固定”的区别.

三阶段总计 426,000 步, 但每阶段 batch size 和数据混合不同,不能简单把步数相加后按统一比例估算每类样本. 阶段 1 与 2 batch size 512, 阶段 3 为 256;若每步都满 batch, 三阶段处理的样本数量和计算负担需要分别计算. packed sequence 又使实际 token 数取决于样本长度.

## 23. 与扩散模型的联系停留在哪一层

### 23.1. 二者都学习随时间变化的去噪方向

扩散概率流 ODE, score matching 与 rectified flow 都从简单噪声分布连接到数据分布. 它们可以共享时间条件网络, CFG 和数值求解器等组件. 差别落在路径与监督参数化:经典扩散常由预设噪声日程构造 $x_t$, 预测噪声, score 或 velocity;rectified flow 直接在线性插值上回归端点差.

把 JanusFlow 称为 flow 路线有助于强调其目标, 但工程接口仍借用了扩散生成的成熟部件, 包括 SDXL-VAE, logit-normal 时间采样, CFG 与 Euler 积分. 这些部件能复用, 因为它们处理的是连续潜变量和时间条件, 并不要求主干必须是标准 DiT.

### 23.2. 速度预测没有给出显式归一化似然

自回归文本头可直接计算观察 token 的条件对数概率. Flow 模型通过 ODE 定义连续变换, 理论上若计算速度场散度可追踪密度变化, 但 JanusFlow 的训练与评测没有把显式图像似然作为目标. MSE 较低表示速度回归更好, 不等价于可直接比较的每像素负对数似然.

因此两项任务虽共享主干, 训练信号的统计意义不同. AR 损失是离散条件最大似然;RF 损失是生成正确边缘流的回归目标;REPA 是表征正则. 把它们相加是多目标优化, 不是一个统一概率模型的严格联合负对数似然. 这一点解释了为何任务比例和损失尺度必须通过实验调节.

### 23.3. 简单目标不等于简单分布

$Z_1-Z_0$ 的监督只需一次端点采样和减法, 不要求模拟前向随机微分方程. 但数据分布的复杂性被放进条件期望 $v^*(z,t,c)$ 中. 当许多图像与噪声配对在中间区域重叠时, 网络仍需表示高度非线性的多模态向量场.

所以 JanusFlow 的简洁主要体现在训练目标和主干接口, 并未消除生成建模难度. 1.3B LLM, 70M 生成模块, 大规模图文数据和 426,000 步训练共同承担了这种复杂性. 公式短是方法的优点, 但模型能力和数据覆盖仍决定最终场的精度.

## 24. 相关工作与公开实现

[JanusFlow 论文](https://arxiv.org/abs/2411.07975) 给出共享主干, 三阶段训练, 数据比例, 主表和消融实验. [Rectified Flow](https://arxiv.org/abs/2209.14577) 从速度回归与常微分方程出发, 建立逐时刻边缘分布保持的理论关系. 前者把这一生成目标接入因果 LLM, 后者解释条件速度为何能够驱动从噪声到数据的连续变换.

[DeepSeek Janus 官方仓库](https://github.com/deepseek-ai/Janus) 发布模型权重和推理入口, 并明确 JanusFlow 加载 SDXL-VAE 时采用 bfloat16. 论文描述训练方法与实验, 仓库呈现发布模型的执行路径, 两者合在一起才能连接公式中的 $z_t$, 条件与无条件速度以及最终 VAE 解码. 梯度内积, Euler 误差界和高斯例子则沿论文公开公式展开, 它们说明假设如何影响结果, 不属于原文报告的新增实验数字.
