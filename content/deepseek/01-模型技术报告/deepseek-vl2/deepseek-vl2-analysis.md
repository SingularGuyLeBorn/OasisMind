# DeepSeek-VL2: 动态切图与稀疏语言模型怎样协同

DeepSeek-AI 于 2024 年 12 月发布 DeepSeek-VL2 技术报告. 系列包含 Tiny, Small 与标准版三个变体, 语言模型总参数分别为 3B, 16B 与 27B, 每个 token 实际激活约 0.57B, 2.4B 与 4.1B 参数; 三者共同使用约 0.4B 参数的 SigLIP-SO400M-384 视觉编码器. 模型沿用 LLaVA 式 decoder-only 路径, 但把上一代固定双分辨率视觉编码改成动态切图, 同时把语言侧升级为 DeepSeekMoE 与 MLA.

这种组合针对两个不同成本. 动态切图让高分辨率和极端长宽比图像不必整体压到固定方形画布; MoE 降低每个语言 token 的激活参数, MLA 压缩推理时的 KV cache. 视觉 token 仍会随 tile 数增长, 因此 VL adaptor 还要把每个 tile 的 $27\times27$ 特征压到 $14\times14$. DeepSeek-VL2 的效率来自三处压缩叠加, 不能只归给 MoE.

## 1. 动态切图怎样形成视觉序列

动态切图先选择**候选网格**,再把局部 tile 与整图缩略图共同送入视觉编码器.

### 1.1. 候选分辨率与 tile 选择

SigLIP 的原生输入是 384×384. DeepSeek-VL2 定义候选集合

$$
C_R=\{(384m,384n)\mid m,n\in\mathbb{N},\ 1\leq m,n,\ mn\leq9\}.
$$

对高为 $H$, 宽为 $W$ 的输入, 系统先保持长宽比缩放, 再计算补到每个候选分辨率所需的 padding 面积, 选择空白面积最小的 $(384m_i,384n_i)$. 缩放后的图像被切成 $m_i\times n_i$ 个 384×384 局部 tile, 另生成一个全局缩略图. 因而单图最多有 9 个局部 tile 加 1 个全局 tile.

上一代 DeepSeek-VL 同时使用 384×384 的 SigLIP 与 1024×1024 的 SAM-B, 两条固定分辨率路径分别提供粗粒度和细粒度特征. 固定 1024×1024 对超长网页, 高密度文档和极端长宽比图像不够灵活. VL2 只保留一个共享 SigLIP, 通过 tile 数改变覆盖范围, 避免整幅大图压缩后小字不可读.

动态切图的代价是视觉序列长度随面积离散增长. 候选集合还会使相近尺寸的图像落到不同网格, 产生 tile 数跳变. 报告为多图输入设置边界: 当输入图片超过 2 张时关闭动态切图. 这项限制表明单图高分辨率能力与多图上下文容量共用同一序列预算.

### 1.2. 全局视图与局部视图各自保留什么

局部 tile 保留字符, 小物体与细节, 但每块只观察图像的一部分. 全局缩略图保留页面结构与远距离关系, 分辨率却不足以读取细小内容. 两类视图由同一个 SigLIP 编码器处理, 后续通过特殊 token 拼成一个视觉序列. 语言模型可以同时利用整体布局和局部纹理, 但必须从序列位置判断局部 tile 在整图中的位置.

该设计没有让 tile 之间在视觉编码器内部直接做全局注意力. 跨 tile 关系要到语言模型层面通过自注意力建立. 这降低视觉编码成本, 却把一部分空间整合压力转给语言模型. 如果任务依赖跨越多个 tile 的细线, 表格行列或网页组件, 局部边界与二维排列编码都会影响结果.

全局缩略图也承担去重作用. 相邻局部 tile 可能分别包含同一大对象的不同部分, 语言模型若只看局部序列, 容易把它们当成多个对象. 全局视图提供整体数量和布局参照. 反过来, 全局图中的小字可能不可读, 必须回到局部 tile. 两类视图的互补需要语言模型在注意力层中学会匹配同一对象的不同尺度表示.

候选分辨率以 padding 面积最小为选择准则, 没有直接使用任务内容. 同样长宽比的低密度照片与密集网页会选择相同网格, 尽管所需细节不同. 内容自适应切图可能进一步节省 token, 但会引入区域选择器和漏检风险. VL2 选择几何规则, 优点是确定, 易复现且不依赖额外模型.

报告的定性样例覆盖自然图像, 文档, 网页 UI, meme 与 anime, 说明同一切图策略可以支持多类输入. 但报告没有按 tile 数给出准确率和延迟曲线, 也没有比较相同视觉 token 预算下的固定分辨率与动态切图. 因而可以确认动态策略提升了高分辨率适应性, 不能仅凭最终总分量化每个局部视图的独立贡献.

### 1.3. pixel shuffle 与序列排布

SigLIP 为每个 tile 输出 $27\times27=729$ 个 1152 维视觉 embedding. VL adaptor 使用 $2\times2$ pixel shuffle, 把空间网格压到 $14\times14=196$ 个 token. pixel shuffle 把邻近位置的特征重排并合并到通道维, 随后的两层 MLP 再投影到语言模型 embedding 空间. 这一步把单 tile 的语言侧序列长度缩短约 3.72 倍.

全局缩略图的 14 行各追加一个 `<tile_newline>`, 因而占 $14\times15=210$ 个 token. 局部 tile 按二维网格重排为 $(14m_i,14n_i)$, 每行末尾也加换行 token, 共 $14m_i(14n_i+1)$ 个 token. 全局视图与局部视图之间再插入一个 `<view_separator>`. 完整视觉序列长度为

$$
L_v=210+1+14m_i(14n_i+1).
$$

当 $m_i=n_i=1$ 时, 视觉序列为 421 个 token; 当 $m_in_i=9$ 且采用 3×3 网格时, 长度为 201? 这里直接代入可得 $210+1+42\times43=2017$. 也就是说, 动态切图虽然限制在 9 个局部 tile, 视觉前缀仍可超过两千 token. 特殊换行和分隔 token 没有携带图像 patch 特征, 但为语言模型提供二维行边界和视图边界.

pixel shuffle 并未把 729 恰好除以 4 得到整数. 原始网格是 27×27, 实现需要处理奇数边界后形成 14×14 输出. 报告直接给出最终 token 数, 没有逐项说明边界 padding. 因而复现时应以仓库 adaptor 实现为准, 不能只按理想 $2\times2$ 网格重排推测 shape.

视觉序列的换行 token 让一维自回归模型获得二维行结构, 但没有显式列分隔 token. 同一行内的位置由序列顺序与位置编码表达, tile 网格边界则依赖拼接规则. 如果下游实现改变局部 tile 排列顺序, 即使每块图像特征相同, 语言模型接收到的空间关系也会变化.

## 2. 语言侧的稀疏计算与缓存压缩

共享专家承担公共模式,路由专家提供**条件容量**;视觉 token 与文本 token 共用这套稀疏计算.

### 2.1. 三个 MoE 变体的共同路由

Tiny 使用 12 层, 64 个路由专家与 2 个共享专家, 每个 token 选择 6 个路由专家; Small 使用 27 层, 64 个路由专家; 标准版使用 30 层, 72 个路由专家. 三者都保留 2 个共享专家与 top-6 路由. 共享专家持续处理所有 token, 用于容纳跨领域的共同模式; 路由专家只处理被选中的 token, 将额外参数容量分配给不同输入分布.

Tiny 的语言模型总参数为 3B, 激活约 0.57B; Small 为 16B 与 2.4B; 标准版为 27B 与 4.1B. 视觉编码器约 0.4B 参数也在推理中运行, 因而系列最终激活规模约为 1.0B, 2.8B 与 4.5B. Figure 1 以这个合计值比较开源模型, 不是用语言模型总参数比较.

Tiny 与 Small 的路由函数为 softmax, 标准版改用 sigmoid 并加入专家校正 bias. sigmoid 路由允许各专家分数独立变化, 校正 bias 用于负载均衡. 报告没有给路由分布, 专家利用率和去掉 bias 的消融, 所以无法从表格判断标准版增量中有多少来自新路由方式.

### 2.2. MLA 解决 Decode 阶段的 KV cache

Small 与标准版采用 MLA, rank 为 512; Tiny 仍使用标准 MHA. MLA 把各注意力头的 Key 与 Value 表示压到共享低维潜变量, 推理时缓存潜变量而非每层每头的完整 KV. 详细推导应参见 [MLA 相关章节](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2-注意力机制.md), DeepSeek-VL2 报告主要说明它在多模态模型中的工程用途.

视觉前缀会在 Prefill 阶段一次进入语言模型, 随后生成回答. 动态切图让视觉前缀可能超过两千 token, 如果继续使用完整 KV cache, 每层缓存会随视觉 token 数, 头数和维度增长. MLA 不减少视觉前缀自身的 Prefill 计算, 但会降低这些视觉 token 在后续 Decode 阶段占据的缓存空间和读取带宽.

这一区分解释了动态切图与 MLA 的互补关系. tile 增加改善细节感知, 同时拉长视觉序列; MLA 缓解长前缀造成的推理缓存压力. MoE 又降低每个 token 的前馈计算. 三者分别作用于视觉输入分辨率, 注意力状态和参数激活, 不能互相替代.

### 2.3. 多模态 token 的路由边界

视觉 embedding 经 MLP 投影后与文本 token 进入同一个语言模型. MoE 路由器因而会同时看到视觉位置, 特殊 tile token, 用户 prompt 与回答 token. 论文没有规定视觉 token 固定进入特定专家, 也没有报告专家是否按模态分化. 从公开结构看, 路由由每个位置的隐藏状态动态决定.

这种统一路由允许视觉与语言知识共享专家容量, 也带来负载波动. 高分辨率单图会集中产生大量视觉 token, 纯文本 batch 则完全没有视觉 token. 标准版使用全局专家 bias 调节负载; 训练系统还必须在数据并行 rank 之间平衡 tile 数. 路由层与系统调度共同决定实际吞吐.

MoE 的「激活参数较少」也不等于权重显存只需保存激活部分. 部署仍要存储全部路由专家, 并在设备间安排专家并行通信. Figure 1 的横轴适合比较每 token 计算规模, 不代表总模型存储或跨卡通信成本.

视觉任务还会改变专家负载的时间分布. Prefill 时连续处理大量视觉 token, Decode 时每步只增加一个文本 token. 如果视觉与文本隐藏状态偏向不同专家, 两个阶段的通信热点可能不同. 报告只给全局负载均衡机制, 没有分别报告 Prefill 与 Decode 的专家命中率和吞吐.

Tiny 保留 MHA, 因此 KV cache 不享受 MLA 压缩, 但层数和 hidden size 更小. Small 与标准版使用 MLA 后, cache 优势会随序列和生成长度增长. 对短问答, 视觉编码与 Prefill 可能主导延迟; 对长回答和并发服务, cache 带宽与容量更重要. 报告没有给分阶段 latency, 不能用激活参数直接预测所有请求形态.

## 3. 三阶段数据与训练管线

### 3.1. 从对齐到全参数预训练

Stage 1 使用约 1.2M 条 ShareGPT4V caption 与对话样本, 训练视觉编码器和 VL adaptor, 冻结语言模型. 与常见固定视觉编码器的对齐阶段不同, VL2 还要让 SigLIP 适应动态高分辨率 tile, 因而视觉编码器并未冻结. 三个变体在该阶段都训练约 2.0B token, batch size 为 256, sequence length 为 4096.

Stage 2 解冻视觉编码器, adaptor 与语言模型全部参数, 使用约 796.5B–808.9B token 做视觉语言预训练. VL 数据约占 70%, 纯文本约占 30%. 纯文本数据用于维持基础语言能力, 视觉语言数据覆盖交错图文, caption, OCR, VQA, 图表文档, web-to-code, visual prompt, grounding 与 grounded conversation.

三个模型 Stage 2 token 数接近, 并没有随参数规模成比例增加. Tiny, Small 和标准版分别约为 798.5B, 808.9B 与 796.5B token. 因而系列比较更接近固定数据规模下扩大模型容量, 而非同时扩大数据. batch size 对 Tiny 与 Small 为 2304, 标准版为 3360; sequence length 都是 4096 并开启 sequence packing.

视觉编码器学习率是主学习率的 0.1 倍, 说明联合训练时仍限制预训练视觉权重的更新幅度. Stage 2 使用 step 调度, Stage 3 改为 constant. 报告没有公布 warmup step, step 衰减节点和各数据源采样温度, 完整训练日程不能仅凭 Table 2 复原.

next-token prediction loss 只在文本 token 上计算. 视觉 token 作为条件输入, 梯度通过语言损失回传到 adaptor 与视觉编码器. 这意味着视觉表示的学习目标由文本生成任务间接定义, 并没有额外的图像重建损失. 任务分布和回答质量会直接决定视觉编码器保留哪些信息.

### 3.2. 数据清洗比简单扩量更关键

caption 数据来源质量差异较大, 包括过短描述, 图文错配和幻觉. 团队把 OCR hint, 地点和相机等元信息, 以及原 caption 一起交给内部 captioner 重写, 再用 DeepSeek Chat 按写作质量评分过滤. 该流程提高文本质量, 但评分器是否验证视觉忠实度没有单独说明; 写得流畅的错误 caption 仍可能通过纯文本质量评分.

重写流程还会改变数据风格. 多个来源经同一 captioner 生成后, 语句结构和关注点可能趋同, 原数据的人类表达差异被削弱. 团队使用多种指令引导 caption 生成来减少重复, 又以写作质量过滤明显模板化结果. 报告没有公开过滤阈值和保留率, 无法判断质量提升与多样性损失的取舍.

文本数据占预训练的 30%, SFT 也加入 DeepSeek-V2 纯文本对话, 用于减轻多模态训练造成的语言能力退化. 视觉 batch 与纯文本 batch 的计算路径不同, 训练系统因此准备两种流水线策略并按需切换. 报告没有给出加入纯文本数据前后的语言榜单消融, 这部分作用无法从现有结果中单独量化.

OCR 数据包含 LaTeX OCR, 12M RenderedText 和内部中英文文档数据. 图表与文档理解加入 PubTabNet, FinTabNet 和 Docmatix; web-to-code 使用 Websight, 部分样本由 DeepSeek V2.5 重建; visual prompt 数据在图像上叠加箭头, 框, 圆和涂画. 不同来源被统一成自回归回答格式, 使模型在同一输出空间学习识别, 定位和代码生成.

grounding 坐标归一化到 0–999, 用 `<ref>` 与 `<det>` 特殊 token 包裹对象描述和 bounding box. 训练集还加入目标不存在的负样本, 避免模型无论提问什么都输出一个框. 这种离散坐标格式便于文本解码, 精度上限受 1000 个坐标 bin 与图像缩放影响.

### 3.3. SFT 的回答长度与模型容量

Stage 3 使用约 19.5B–20.0B token 做 SFT, 所有参数继续训练, 但只监督回答和特殊 token, mask 掉 system 与用户 prompt. 数据混合多模态指令与 DeepSeek-V2 的纯文本对话, 覆盖通用 VQA, OCR, 文档, 图表, visual-to-code, 推理, grounding 和语言理解.

公开数据常见三个问题是回答过短, OCR 质量差与幻觉. 团队结合原问题, 图像和 OCR 信息重写回答. Tiny 早期版本还会在中文回答中错误插入英文词, 报告把原因指向模型容量有限与视觉语言预训练阶段中英文失衡, 因而额外构建中文图像描述和单轮, 多轮对话数据.

报告还观察到详细推理回答对 Tiny 效果较差, 简洁回答反而更合适. 这说明同一 SFT 目标不能不加区分地用于三个容量档位. 标准化长推理过程可能超过小模型稳定表示和生成的能力, 也会挤占 4096 token 序列中的图像与问题空间. 论文没有给回答长度的定量消融, 但明确记录了容量相关的数据选择.

## 4. 训练系统与评测口径

### 4.1. 学习率与并行配置

三个阶段都使用 AdamW, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 0.1, gradient clip 1.0. 视觉编码器学习率乘数固定为 0.1. Stage 1 和 Stage 2 的主学习率按模型不同约为 $4.2\times10^{-4}$ 到 $5.4\times10^{-4}$, Stage 3 降到 $1.4\times10^{-5}$ 到 $3.0\times10^{-5}$. 调度器分别为 cosine, step 与 constant.

视觉编码器位于流水线首段, 计算形态与均匀堆叠的 LLM block 不同. 动态切图还使每条样本 tile 数不同, 如果直接分配到数据并行 rank, 某些 rank 会等待 tile 更多的样本. HAI-LLM 对视觉编码器做细粒度层切分, 并在 forward 与 backward 中跨数据并行 rank 平衡 image tile 数, 以减少 pipeline bubble.

训练同时使用流水线并行, tensor parallel 与 expert parallel. Tiny, Small 和标准版分别用 16, 33 与 42 个节点, 每节点 8 张 A100, 用时约 7, 10 与 14 天. 报告给出节点和时间, 没有给实际 GPU 利用率与故障重启成本, 因而只能得到名义卡时, 不能复原有效训练 FLOPs.

### 4.2. 文档与 OCR 结果怎样读取

在文档评测表中, Tiny 的 DocVQA 为 88.9, ChartQA 81.0, InfoVQA 66.1, TextVQA 80.7, OCRBench 809. Small 分别为 92.3, 84.5, 75.8, 83.4, 834. 标准版为 93.3, 86.0, 78.1, 84.2, 811. 模型变大时大多数项目提高, OCRBench 却由 Small 的 834 降到标准版的 811.

这个反例说明综合能力与单一 OCR 榜单不必单调一致. 标准版改变了语言模型层数, 路由专家数, 路由函数与训练系统, 不能把 OCRBench 回落归因于某一个部件. MiniCPM-V2.6 的 OCRBench 852 标注使用 CoT, 评测协议也与普通直接生成可能不同.

Figure 1 平均 MMBench v1.1, MMStar, MMMU, MathVista, AI2D 与 OCRBench, 其中 OCRBench 除以 10 映射到 0–100. 简单平均默认六项同等重要, 也会掩盖单项回退. 它适合展示激活参数与综合分数的整体位置, 不能替代逐任务表格.

参数比较还要区分视觉编码器与语言模型. DeepSeek-VL2-Tiny 的语言侧激活 0.57B, 加上 0.4B 视觉编码器后按约 1.0B 标示; 其他基线有的只报告语言参数, 有的报告总激活参数. 表格脚注用匕首标明 MoE 激活值, 但闭源模型没有可比参数. Figure 1 主要用于开源模型内部的效率位置, 不能据此比较闭源服务的真实计算量.

标准版 DocVQA 93.3 低于 Claude 3.5 Sonnet 的 95.2 与 Qwen2-VL-7B 的 94.5, ChartQA 86.0 低于 Claude 的 90.8, InfoVQA 78.1 接近但低于 Gemini-1.5-Pro 的 80.1. 报告用 competitive 或 state-of-the-art 描述不同任务, 具体读取仍应逐列比较, 不能把平均图理解为每个项目都领先.

### 4.3. 已公开结果不能回答什么

动态切图, pixel shuffle, MLA, MoE 与数据扩充在同一版本同时出现, 报告没有完整组件消融. 因而 VL2 相对 VL 的提升不能被拆成「多少来自切图, 多少来自语言架构, 多少来自数据」. 三个变体也不是只改变规模: Tiny 使用 MHA 和 softmax 路由, Small 使用 MLA, 标准版进一步改为 sigmoid 路由与校正 bias.

多图超过两张时关闭动态切图, 是实际能力边界. 28 页报告中的定性样例以单图为主, 没有系统测量多图数量, tile 数和回答长度共同增长时的效果. 4096 token 训练长度也限制视觉前缀, prompt 和回答的总预算, 不能由动态高分辨率推导出任意长视觉上下文.

视觉序列在最大 3×3 tile 下约占 2017 token, 已接近 4096 训练长度的一半. 再加 prompt 与回答后, 长文档转写或多轮对话会很快触及预算. 超过两图时关闭切图能控制长度, 代价是每张图只能使用较低细节. 论文没有给超出训练长度的外推测试.

grounding 坐标被离散到 0–999, 在高分辨率原图上一个 bin 对应多个像素. 视觉 tile 可以保留更细局部信息, 输出协议却限制坐标精度. 同时, bounding box 生成是自回归文本任务, 数字 token 的局部错误会造成框位置突变. 报告展示定性定位样例, 没有按物体尺寸分析误差.

数据构建大量使用内部 captioner, DeepSeek Chat 和 DeepSeek V2.5 重写或筛选, 但没有公开内部数据规模的完整分项, 人工抽检率与污染检查. 第三方可以复现架构和部分公开数据, 无法严格复现训练集. DeepSeek-VL2 的公开价值主要在架构, 训练配比和结果边界, 不是一份完全可复现的数据配方.

对部署者而言, 三个变体的选择应同时考虑图像 tile 数, 回答长度, 并发量与总权重存储. Tiny 的 cache 路径较传统, Small 在较低激活参数下获得 MLA, 标准版提供更强综合能力但 OCRBench 并未最高. 应用侧需要按自身文档, 网页和自然图像分布复测, 不能只按平均分选择最大模型.

### 4.4. 动态分辨率的工程边界

动态切图并不等于可以无成本提高输入分辨率. 候选网格以 384×384 为步长, 图像只要跨过候选边界, 局部 tile 数和视觉 token 数就可能阶跃增加; 即使原图像素只增加少量, prefill 延迟与显存占用也可能明显变化. 工程侧因此不能只按原图文件大小分桶, 还应按实际选中的 $(m_i,n_i)$ 网格统计请求成本. 对版式相近的文档先统一缩放或裁边, 也可能减少无信息 padding 和不必要的 tile.

报告只在单图动态切片时允许最多 9 个局部 tile, 多于两张图时直接关闭该策略, 没有给出服务端批处理的吞吐曲线. 不同请求的 tile 数不一还会造成 batch 内计算不齐, 训练阶段可以跨数据并行 rank 做负载均衡, 在线推理却需要调度器另行处理. 部署验收可以分别测量 1 tile、常见多 tile、9 tile 以及多图降级四类输入, 同时记录首 token 延迟、峰值显存和回答截断率。论文给出的序列构造与 4096 token 训练长度足以确定这些测试场景，具体性能仍需在目标服务环境中测量.

## 5. 动态视觉 token 的信息论与几何结构

### 5.1. 切图是在分辨率与上下文预算之间做离散优化

一张宽为 $W$、高为 $H$ 的图像若直接缩放到固定正方形,比例变换会让细字变小,填充又浪费像素. VL2 从候选网格 $(m,n)$ 中选择局部 tile 布局,目标同时考虑宽高比匹配和 tile 数. 可把选择写成

$$
(m^*,n^*)=\arg\min_{(m,n)\in\mathcal G}
\left|\log\frac{W/H}{m/n}\right|+\lambda mn,
$$

其中第一项惩罚比例失真,第二项代表视觉 token 与计算成本. 官方实现有明确的候选集合和 tie-break 规则,上式用于呈现其中的取舍,不是逐行复刻代码.

单独最小化比例误差时,一张极宽长图会倾向很多横向 tile,很快耗尽 4096 序列预算;单独最小化 tile 数时,所有图又会退化成单个缩略图,OCR 与细节识别随之下降. 动态 tiling 要解决的是有限候选中的视觉预算分配:图像几何决定该花多少 token 保留细节.

这个离散选择也会产生阈值效应. 两张尺寸几乎相同的图可能落入不同网格,视觉 token 数突然跳变;图像轻微裁边后,模型输入结构就改变. 测试时可连续改变宽高比,画出 tile 数和准确率曲线. 若阈值附近性能剧烈波动,说明网格选择比视觉内容更支配结果.

### 5.2. 全局缩略图承担的是坐标系角色

局部 tile 保存小字和纹理,却会切断跨块关系. 一张表格被分成四块后,每块都能看清单元格,模型仍可能不知道它们属于哪一行;街景中的路牌与车辆分落两块,局部内容无法表达相对位置. 全局缩略图提供页面或场景的整体坐标系,让语言模型有机会把局部细节放回全局布局.

设全局特征为 $G=E(I_{global})$,局部特征为 $L_k=E(I_k)$. 最终视觉序列并非简单增加分辨率,而是提供两类互补变量:

$$
Z=[P(G),P(L_1),\ldots,P(L_K)],
$$

$P$ 包含 pixel shuffle 与 adaptor. $G$ 的单个 token 覆盖面积大,适合表达布局;每个 $L_k$ 覆盖面积小,适合表达字符. decoder 必须学习同一物体在两个尺度上的对应关系.

重复也是代价. 标题会同时出现在全局图和局部 tile,若模型没有跨尺度去重,可能生成两次. 全局图识别成“8”、局部图识别成“3”时,还需要选择更可信的尺度. 这类冲突不能由增加 tile 自动解决,应单独统计重复率和尺度冲突错误.

### 5.3. Tile 边界会制造人为的不连续

视觉世界连续,切图后的 token 序列却在边界处跳转. 文字行跨过两个 tile 时,前半句位于一个局部序列末尾,后半句可能隔着分隔 token 出现在另一个序列. 若 tile 没有重叠,边界字符还可能被裁断;若增加重叠,重复区域又会扩大.

对宽度为 $w$ 的 tile 和重叠量 $o$,相邻 tile 的唯一覆盖宽度是 $w-o$,额外计算比例近似为

$$
\rho=\frac{w}{w-o}.
$$

$o$ 越大,跨边界目标更完整,$\rho$ 也越高. VL2 的公开策略主要围绕网格切分和全局视图组织,没有把任意大重叠作为核心机制. 因而跨 tile 表格线、长公式和倾斜文字仍是值得单测的边界.

一个干净的反事实实验是把同一段文字在图中水平平移,让它依次位于 tile 中央与边界. 字体、内容和总分辨率保持不变,准确率差就反映切片敏感性. 再加入全局图消融,可以看到全局上下文能否修复局部断裂.

### 5.4. Pixel shuffle 本质上是空间到通道的重排

假设视觉 encoder 输出特征网格 $X\in\mathbb R^{H\times W\times C}$,以 $r\times r$ 邻域做 pixel shuffle 下采样后,空间尺寸变成 $H/r\times W/r$,通道变成 $r^2C$. 元素没有在重排步骤中丢失:

$$
Y_{i,j,:}=\operatorname{concat}\{X_{ri+a,rj+b,:}\mid0\le a,b<r\}.
$$

随后 adaptor 把高维通道投影到 LLM hidden size. token 数减少 $r^2$ 倍,每个 token 携带更大局部邻域. 与平均池化相比,pixel shuffle 在重排时保留邻域内各位置的独立通道;真正的信息瓶颈出现在后续线性/MLP 投影与有限 hidden dimension.

它的优势是降低语言模型序列长度. 如果 ViT 输出 576 个 patch token,$r=2$ 后只剩 144 个视觉 token,LLM self-attention 和 KV cache 随之下降. 风险是四个 patch 被压进一个 token 后,LLM 无法再把它们当四个独立序列位置处理,精细坐标主要依赖通道编码.

对 OCR 而言,一个字符若小于压缩邻域,其笔画信号可能与背景混在同一投影中. 对自然图像分类,这种压缩影响较小. 所以相同 token 压缩率在不同任务上没有统一最优值. VL2 的文档/OCR 成绩说明整套配置具有竞争力,没有证明更激进的 shuffle 仍然安全.

### 5.5. 视觉序列需要显式表达 tile 的二维身份

把所有 tile token 串联后,一维位置只告诉模型谁先谁后,无法直接说明 token 属于第几行第几列. 实现通常加入分隔标记、换行标记或 tile 顺序约定,让模型从序列结构恢复二维布局. 如果这些标记在训练和推理时不一致,内容仍能被识别,定位和阅读顺序会先退化.

将第 $k$ 个 tile 的网格坐标记为 $(u_k,v_k)$,内部 patch 坐标为 $(a,b)$,它在原图中的近似坐标为

$$
(x,y)=((u_k+a/r_t)w_t,(v_k+b/r_t)h_t),
$$

其中 $w_t,h_t$ 是 tile 尺寸,$r_t$ 是内部 patch 网格分辨率. 模型没有必要显式计算这个公式,但序列编码必须保留足够信息,否则两个相同局部图案在不同 tile 中不可区分.

视觉 grounding 对这一点最敏感. 模型既要识别目标,又要把位置输出为坐标. 训练中若坐标归一化到整图,局部 tile 的预测必须经过逆映射;若归一化到 tile,还要输出 tile 身份. 代码与数据格式决定具体路径,不能只从最终 bounding box 文本猜测.

### 5.6. 动态 token 数让 batch 内计算出现长尾

不同图像选择不同 tile 数,对应视觉序列长度 $N_v$ 不同. batch 通常 pad 到其中最大长度,实际 attention 计算若未使用变长 kernel,短样本也会为 padding 付费. 当大多数图片只有一个 tile、少数图片有九个 tile,随机混批会被长尾样本拖慢.

按 tile 数分桶能减少浪费. 设 batch 内长度为 $n_1,ldots,n_B$,padding 利用率为

$$
\eta=\frac{\sum_i n_i}{B\max_i n_i}.
$$

$\eta$ 越低,无效计算越多. 训练数据打乱、任务混合和数据并行负载均衡都要考虑这一分布. 单看平均 tile 数无法预测吞吐,分位数和同批极差更关键.

在线服务又有首 token 延迟目标,不能无限等待相同长度请求凑批. 调度器要在利用率与排队时间之间取舍. 仓库的基础推理实现强调功能正确,README 也说明未做生产优化;从开源 demo 的速度不能直接推断模型架构的最优吞吐.

### 5.7. 多图输入为何关闭高成本动态切片

若每张图最多产生 $V$ 个视觉 token,$M$ 张图就需要约 $MV$ token. 训练总序列长度只有 4096,还要容纳问题与答案. 多图继续对每张图使用九 tile,很快让文本空间归零,attention 成本也急剧增加. 官方策略在多于两张图片时关闭动态切片,本质上是给多图数量与单图细节做预算交换.

这会形成能力边界. 两张高分辨率票据可以精读,十张票据只能以较低细节比较;多帧视频抽帧后,每帧的小字更难识别. 如果 benchmark 的多图任务分辨率较低,这种退化未必明显;真实长截图或相册对比会更敏感.

一种扩展方案是先低分辨率浏览全部图片,再由模型或外部检索器选少数关键图片做高分辨率切片. 预算可写为

$$
V_{total}=M V_{global}+\sum_{i\in S}V_{local,i},
$$

$S$ 是被选中精读的图片集合. 这需要两阶段推理或可微选择,VL2 没有实现为论文核心. 它说明动态分辨率下一步不仅是“切得更多”,还要学会把 tile 花在最相关的图上.

### 5.8. 视觉 token 与文本 token 在 LLM 中共享注意力预算

LLaVA 式结构把投影后的视觉 embedding 插入文本序列,语言模型对它们做统一 causal attention. 对回答 token $y_t$,它能读取此前全部视觉 token 与问题 token. 当视觉 token 数增加,每层 attention 的前缀长度增大,预填充成本上升,后续每个生成 token 的 KV 读取也变多.

如果视觉 token 为 $N_v$,文本提示为 $N_p$,输出为 $N_o$,粗略 attention 成本包含前缀预填充与解码:

$$
C\propto (N_v+N_p)^2+N_o(N_v+N_p)+\frac{N_o(N_o+1)}{2}.
$$

MLA 降低 KV cache 常数,MoE 降低每 token FFN 激活参数,但动态切图带来的 $N_v$ 仍然影响计算. 三项技术是互补关系,不能用“稀疏 LLM”推导视觉 token 免费.

视觉前缀过长还会稀释语言指令. 4096 token 窗口里若大量位置被图片占用,复杂问题和详细回答可用空间减少. 训练样本的截断策略于是很关键:截掉答案会教模型过早停止,截掉视觉 tile 会改变图像完整性,截掉问题则破坏任务. 论文公开总序列长度和 packing 配置,没有逐类披露截断比例.

### 5.9. 动态切图是否有效需要三类消融

第一类固定像素预算. 比较单张高分辨率图、全局加局部 tile、固定多 crop,让输入总像素接近. 这样可判断收益来自动态布局还是单纯看了更多像素. 第二类固定视觉 token,比较不同 shuffle 率和 tile 数,观察空间覆盖与局部精度怎样交换.

第三类按任务和宽高比分层. OCR、图表、自然图 VQA、grounding 对细节和布局需求不同;方图、长图、极宽图的候选网格也不同. 如果只看所有 benchmark 平均分,容易让 OCR 的大收益遮住自然图推理无变化,或让大量常规比例遮住极端长图退化.

还应记录选择稳定性. 同一图像缩放几个像素、添加白边、旋转一度,正确答案理应不变. tile 网格若随扰动改变,模型输出是否仍一致? 这组反事实比再加一个常规 VQA 分数更能检验动态策略的边界.

### 5.10. 动态分辨率并不等同于任意尺度理解

模型只在有限 tile 尺寸、网格数量与训练分布上学习. 超大工程图缩成候选网格后,最小文字仍可能低于 ViT patch 分辨率;显微图像里的对象尺度也可能远离自然图训练分布. “动态”指预处理从候选中变化,不意味着连续尺度不变性.

同样,图像尺寸大不代表信息量大. 一张 8K 纯色背景只需少量 token,一张 1K 密集表格可能需要更多. 仅靠宽高比和分辨率选择 tile,无法感知内容密度. 内容自适应切片可根据边缘、文字检测或视觉熵分配预算,但会增加检测误差与流水线复杂度.

VL2 的设计优点是规则明确、易复现,不依赖额外区域提议模型. 代价是预算对内容难度不敏感. 评价时既要承认它相对固定 384/1024 双编码器的进步,也要保留“候选网格内的动态”这一准确范围.

## 6. 从视觉对齐到多模态 MoE 的完整学习链

### 6.1. VL adaptor 要解决的不是简单维度匹配

SigLIP 视觉特征和语言模型 token embedding 来自不同训练目标. 前者擅长图文判别与语义聚合,后者位于自回归语言空间. adaptor 即使只是若干线性层与非线性层,也要把视觉局部变成 LLM 能在 next-token prediction 中使用的表示.

设视觉 encoder 输出 $z_i\in\mathbb R^{d_v}$,语言 hidden size 为 $d_l$,adaptor 给出

$$
h_i=W_2\sigma(W_1z_i+b_1)+b_2.
$$

维度从 $d_v$ 变到 $d_l$ 只是表面要求. 更深的要求是 $h_i$ 与文本 token 的尺度、方向和统计分布兼容. 若范数远大于文本 embedding,视觉 token 会压过指令;若太小,LLM 几乎忽略图片. 第一阶段冻结语言模型,正是迫使视觉 encoder 与 adaptor 适应既有语言空间.

冻结也形成瓶颈. 语言模型原先没见过连续视觉前缀,adaptor 必须用有限容量把所有视觉关系翻译成它能理解的模式. 第二阶段全参数解冻后,语言侧可以共同适应,视觉表示不再单方面承担对齐. 这解释了三阶段顺序中的功能分工,但每阶段独立贡献仍需消融确认.

### 6.2. 第一阶段 2B token 学到的是基础对齐

论文三种规模的第一阶段都使用约 2B token,冻结 language model,训练视觉 encoder 和 adaptor. 数据主要让模型把图片区域与词语、短描述或已有语言概念对齐. 这一阶段若一开始就更新 LLM,随机初始化的 adaptor 会向语言层传入不稳定信号,可能破坏已有文本能力.

冻结语言侧时,损失对视觉参数的梯度仍经过 LLM 反传:

$$
\nabla_{\theta_v}L=
\frac{\partial L}{\partial h}
\frac{\partial h}{\partial z}
\frac{\partial z}{\partial\theta_v},
$$

只是 $\theta_l$ 不执行更新. 因此 LLM 相当于固定的语义判别空间,并非完全不参与训练. 视觉 encoder 学习哪些特征能让固定语言模型更容易预测目标文本.

2B token 不能直接换算成图像数,因为 caption 长度、packing 与图像 token 是否计入统计都会影响口径. 论文表格报告的是训练 token 量,没有为每类 alignment 数据给完整样本数. 可靠描述应停留在公开量级和阶段目标,不补造图像数量.

### 6.3. 第二阶段近 800B token 才是能力主体

Tiny、Small 和 VL2 在第二阶段分别使用约 798.5B、808.9B、796.5B token,解冻全模型进行多模态预训练. 这一数量远大于第一与第三阶段,决定模型能否在自然图、OCR、文档、图表、grounding 和纯文本之间建立共同能力.

第二阶段仍包含语言数据很重要. 如果所有 batch 都带图,LLM 的文本推理和知识可能遗忘;保留纯文本任务能维持底座能力,也让 MoE 专家继续接触足够多的语言分布. 视觉数据与文本数据的精确比例会影响专家分工,论文描述了数据构建类别,没有发布全部混合权重.

全参数训练时视觉 encoder 学习率乘 0.1. 假设主学习率为 $\eta$,视觉更新使用 $0.1\eta$. SigLIP 已有成熟视觉表示,较小步幅防止它被噪声 caption 快速改坏;adaptor 与 LLM 需要更大适应. 同一个 multiplier 用于三阶段,说明团队持续控制视觉侧漂移.

规模不同的主学习率并不一致:Tiny 约 $5.4\times10^{-4}$,Small 约 $4.2\times10^{-4}$,VL2 约 $4.5\times10^{-4}$;第三阶段再明显降低. 这些数值与 batch、优化器和 scheduler 配套,不能抽出一个学习率直接迁移到不同规模模型.

### 6.4. 第三阶段 SFT 把能力变成可调用行为

第三阶段约 19.5B—20B token,序列仍为 4096,采用 constant learning rate,全模型可训练. SFT 数据把预训练中隐含的视觉知识组织成问答、多轮对话、坐标输出、文档转写和指令遵循. 它的 token 量远小于第二阶段,但对输出格式和用户体验影响很大.

视觉 grounding 是典型例子. 预训练模型可能知道“红色汽车在哪里”,却不会按指定格式输出坐标. SFT 同时教目标识别、坐标量化方式、特殊 token 与答案模板. 如果格式变了,底层视觉能力仍在,评测 parser 却可能判零分.

SFT 也可能让回答更长或更短. 长描述数据提高细节覆盖,却容易在简单 VQA 上啰嗦;短答案数据有利于 exact match,可能损伤开放描述. 三个模型容量不同,同一数据模板会产生不同吸收效果. 论文给最终结果,没有展示回答长度与任务比例的系统消融.

### 6.5. 数据清洗为何比增加弱 caption 更有效

图文训练的监督来自文本. caption 若漏掉关键对象,模型会把“没有描述”误当成“不重要”;caption 若幻觉出不存在物体,模型会被训练去相信语言先验. OCR 数据中一个字符错误会直接污染精确识别,grounding 数据中 box 偏移则教错坐标.

可以把观测标签 $\tilde y$ 看成真实标签 $y$ 经噪声过程 $Q(\tilde y\mid y,x)$ 产生. 数据量增加降低采样方差,却不会自动消除系统偏差. 如果某类网页截图总把导航栏漏标,模型会稳定忽略导航栏. 清洗和重标的作用是改变噪声矩阵,不只是删掉低质量图片.

多模态数据还会重复. 同一网络图片配上多个近似 caption,会让 benchmark 图像或其变体进入训练. 去重应同时考虑图像感知哈希、文本相似度和来源. 论文描述了改进的数据构建流程,但没有公开全量数据,外部无法完全审计 benchmark contamination.

### 6.6. MoE 路由在视觉 token 上会形成什么分工

VL2 的语言底座使用 DeepSeekMoE. 对每个 token hidden state $h_t$,router 选择少数专家:

$$
y_t=E_s(h_t)+\sum_{i\in S_t}\alpha_{t,i}E_i(h_t).
$$

视觉 token 经 adaptor 后也进入这一网络,因此它们同样参与路由. 视觉 token、问题 token 与回答 token 的分布不同,可能形成不同专家偏好. 某些专家更常处理 OCR 特征,另一些专家更常处理自然语言,但论文没有给专家语义标签,不能把这种可能性写成已证事实.

可以统计条件路由概率 $P(i\mid c)$,$c$ 表示视觉、中文、英文、坐标或公式 token. 用互信息

$$
I(E;C)=\sum_{e,c}P(e,c)\log\frac{P(e,c)}{P(e)P(c)}
$$

衡量专家与 token 类型的关联. $I$ 高说明路由专门化明显,仍不证明某专家具有人类可命名功能;干预时屏蔽专家并观察特定任务下降,证据才更接近因果.

视觉序列长且局部 token 相似,可能集中路由到少数专家,造成负载不均. 论文训练表报告 auxiliary loss weight,最大模型还使用 expert bias correction. 这些机制帮助设备负载稳定,其目标是计算均衡,不保证专家语义均衡.

### 6.7. 三个模型的“激活参数”存在两种口径

论文摘要给 Tiny、Small、VL2 的整体 activated parameters 为 1.0B、2.8B、4.5B;训练表中语言模型 activated parameters 为 0.57B、2.4B、4.1B. 两者相差约 0.4B,对应共同使用的 SigLIP-SO400M 视觉 encoder 及 adaptor 量级. 因而引用数字时要说明是 LLM 还是整个多模态系统.

总 LLM 参数分别为 3B、16B、27B,开源 README 的近似数字可能因统计范围或舍入出现 3.37B、16.1B、27.5B 等表达. “总参数”决定模型文件与显存,“激活参数”近似单 token FFN 计算,视觉 encoder 又是每张图都要运行的 dense 模块. 只拿 4.5B activated 与一个 4B dense 语言模型比较,仍要核对视觉成本与总权重驻留.

性能—参数图把 OCRBench 除以 10 后与其他百分制指标取平均. 这个平均能展示总体趋势,却隐含每项 benchmark 等权. 若模型在 OCRBench 特别强,缩放方式会影响图中位置;不同应用的真实权重也不同. 散点图适合概览,不能替代逐任务表.

### 6.8. MLA 的收益主要落在自回归解码

MLA 把每个 token 的 key/value 压缩成低维潜向量,减少生成阶段的 KV cache. 对含大量视觉 token 的提示,每生成一个答案 token 都要读取视觉前缀缓存,所以压缩很有价值. 动态切图增加视觉 token,MLA 在语言侧抵消一部分内存压力.

设普通 MHA 每层每 token 缓存 $2hd$ 个元素,MLA 缓存 latent dimension $r$ 加位置相关部分 $d_r$,压缩比近似

$$
\kappa\approx\frac{2hd}{r+d_r}.
$$

精确比值取决于实现和 dtype. MLA 不会降低 SigLIP 编码图片的成本,也不会消除前缀 attention;它主要减小 cache 和相关带宽. 因此高分辨率图的首 token 延迟可能仍然很高,后续长回答吞吐改善更明显.

Tiny、Small、VL2 使用的语言底座规模不同,MLA 配置也需从各自公开 config 核对. 把 DeepSeek-V2 大模型的 93.3% KV 降幅直接套到 VL2 不严谨,因为层数、head 维度和潜空间不同. 本文只沿机制解释,具体内存应按模型配置计算.

### 6.9. 4096 序列长度限制了多模态能力的组合

论文所有训练阶段 sequence length 都是 4096. 单图视觉 token、问题和答案必须共享这一窗口. 当九个局部 tile 加全局图占据大量位置时,开放式长回答、文档全文转写和多轮对话容易触顶. 模型能看清局部,不代表能把整份超长文档无损输出.

设每 tile 压缩后为 $v$ 个 token,局部数量为 $K$,全局为 $g$,文本输入输出合计为 $t$,需要满足

$$
Kv+g+t\le4096.
$$

增加 $K$ 会线性压缩文本预算. 若答案被截断,benchmark 可能把后半段缺失记为 OCR 错误,实际瓶颈是序列长度. 对表格与文档任务,报告页级准确率时应同时统计截断比例.

仓库后来提供 incremental prefilling 以节省显存,它把长前缀分块送入模型,并没有扩大训练窗口或改变 token 总数. chunk size 影响峰值显存与速度,不会让模型突然支持更长语义上下文. README 对这点给的是推理用法,不能误写成训练方法.

### 6.10. Grounding 坐标是一种离散语言

视觉 grounding 将二维连续坐标转为可生成 token. 若坐标归一化到 $[0,M]$,真实位置 $x/W$ 量化为

$$
q_x=\operatorname{round}\left(M\frac{x}{W}\right).
$$

反量化误差最多约为 $W/(2M)$. $M$ 越大,位置精度越高,坐标词表和生成难度也可能增加. 最终 IoU 还会受四个边界共同误差影响,小物体对同样像素偏差更敏感.

动态 tile 让局部物体拥有更多像素,有利于识别和边界定位;输出坐标必须回到原图尺度. 若预处理包含 resize 与 padding,逆变换要扣除 padding 并按缩放比恢复. 一个坐标 parser 的 off-by-one 或宽高顺序错误,会让模型看似 grounding 很差,实际上是部署后处理错误.

测试可用人工几何图:在固定画布上放置已知矩形,覆盖四角、边缘、tile 交界和极小目标. 先验证 processor 与反量化,再评模型语义. 这比直接在自然图上猜错误来源更高效.

### 6.11. OCR、图表与普通 VQA 的错误链不同

OCR 错误从像素采样、patch 编码、shuffle 压缩、语言识别一路传播. 图表理解还增加图形元素绑定与数值比较;普通 VQA 常依赖对象识别和常识. 一个平均多模态分数无法说明模型在哪一层进步.

对 OCR 可将字符按尺寸、对比度、旋转和语言分桶. 对图表可分成读取单点、比较两点、聚合多点和解释趋势. 对 VQA 可区分答案直接可见、需要关系推理、依赖外部知识. 动态 tiling 应主要改善小字与高分辨率细节;MoE 容量和数据则可能改善推理与知识. 若所有提升都归给切图,就忽略了同时发生的语言底座和数据变化.

一个交叉消融矩阵应包含旧视觉方案加新 LLM、新视觉方案加旧 LLM、新视觉加新 LLM,并尽量固定训练数据. 论文比较最终系统与前代,没有提供完整二维矩阵. 所以可以确认 VL2 整体显著增强,两项结构各自贡献的精确比例仍未知.

### 6.12. Benchmark 平均数如何掩盖任务差异

论文覆盖 MMBench、MMStar、MMMU、MathVista、AI2D、OCRBench、DocVQA、ChartQA、TextVQA、grounding 等多类测试. 它们的指标不同:有 exact match、模型判分、ANLS、IoU 或任务自定义分数. 把它们归一到一张平均图方便比较激活参数,却不能进行严格的跨指标加减.

例如 OCRBench 原始上限 1000,图中除以 10 映射到 0—100. 这等价于给 OCRBench 与其他六项之一相同权重,不等于给每道题相同权重. 一个模型 OCR 提升 100 原始分,平均图上约贡献 $100/10/6$ 或相应分母的变化. 应用若主要处理票据,真正权重会完全不同.

还要看评测分辨率是否允许动态切图. 若框架在送入 processor 前已缩小图片,模型无法发挥高分辨率策略;若不同模型使用各自原生 processor,输入像素和 token 预算又不相同. 公平比较要同时报告原图处理、最大 tile 和视觉 token 数.

### 6.13. 定性样例能展示能力,不能估计失败率

论文展示 grounding、多图、GUI、OCR 和复杂图像对话样例,能确认接口支持这些输出形态,也帮助理解模型如何组织答案. 但展示样例经过选择,没有分母,不能用来估计随机页面的成功率. 一张漂亮的长图识别不代表所有长宽比都稳定.

定性分析仍有独特价值. 自动指标可能把语义等价表达判错,也可能忽略答案中额外幻觉;看样例能发现重复、语言混杂、坐标格式和不确定性表达. 最好的做法是先按预定义规则随机抽样,再标注错误类型,避免只挑最成功或最失败的页面.

反例库应该包含遮挡、低对比、小目标、跨 tile 文字、密集表格、相似物体、多图指代和页面旋转. 每次改 processor 或推理框架都跑同一批,比只追榜单总分更能防止工程回归.

### 6.14. 视觉幻觉来自语言先验与证据不足的竞争

给定视觉表示 $V$ 与问题 $Q$,模型预测 $p(y\mid V,Q)$. 当图片模糊或关键区域在压缩中丢失,$V$ 提供的信息减少,语言先验 $p(y\mid Q)$ 占比上升. 模型会生成场景中常见但图里没有的对象,或根据表格标题猜数值.

可以用遮挡差分检查视觉依赖. 将关键区域 $R$ 遮掉,比较答案 token 的对数概率:

$$
\Delta=\log p(y\mid V,Q)-\log p(y\mid V_{\setminus R},Q).
$$

若答案声称读取了该区域,$\Delta$ 却接近零,输出很可能主要依靠语言先验. 再把局部 tile 分辨率提高,观察 $\Delta$ 是否增加,能检查动态切图是否真正提供证据.

拒答与不确定性也是能力. 图片无法辨认时,编造一个流畅答案在普通语言指标上可能不受重罚,实际 OCR 场景风险很高. VL2 的训练目标以生成正确答案为主,论文没有建立完整的视觉置信度校准体系. 高风险应用仍需字符级置信、规则校验或人工复核.

### 6.15. 多图理解需要解决指代与顺序

多张图片进入同一序列时,模型要知道“第一张”“左图”“上一张截图”对应哪段视觉 token. processor 通常插入图像边界与编号,问题文本再引用它们. 如果调用层改变图片顺序但文字编号不变,模型会稳定回答错对象.

多图比较还要求跨图绑定. 识别每张图里都有红车只是局部能力,回答哪张车更靠近路口需要把属性、对象和图编号组成关系. 当动态切片关闭后,小目标信息更弱,跨图任务同时承受分辨率与关系推理压力.

可以设计交换测试:将两张图次序互换,同步或不同步修改问题中的编号. 同步修改时答案语义应保持,不同步时答案应跟随编号改变. 若模型总偏向首图或末图,说明位置偏置强于内容关系. 多图 benchmark 若不做这种反事实,可能被数据中的固定答案位置利用.

### 6.16. GUI 理解是视觉、文字与动作语义的交叉点

GUI 页面包含小字、图标、层级布局和可点击区域. 模型回答“设置按钮在哪里”需要 OCR 与 grounding;回答“怎样关闭通知”还要推断动作序列. 动态 tiling 对小控件有利,全局图对页面层级有利,坐标输出把理解连接到动作.

静态截图无法告诉模型按钮是否可点击、点击后状态如何变化. 因而 GUI benchmark 上的定位分数不能直接等同于可执行 Agent 能力. 真正交互还需要观察—动作循环,处理弹窗、滚动和页面变化. VL2 论文展示 GUI perception 扩展,主要证明静态视觉基础,没有声称完成完整电脑操作系统.

坐标误差在 GUI 中具有非线性后果. box 中心偏十像素可能仍点中大按钮,对小图标则点到相邻控件. 评测应同时报告 IoU 和实际点击成功率,后者还依赖屏幕缩放、设备像素比与浏览器坐标变换.

### 6.17. 训练稳定性同时受 MoE 与多模态长度影响

不同 batch 的视觉 token 数、文本长度和任务损失差异很大. 长 OCR 样本产生更多 token loss,若按 token 平均,它们对梯度贡献可能高于短 VQA;若按样本平均,短答案任务权重上升. MoE router 又会把不同 token 分给不同专家,某些任务可能集中更新少数参数.

论文统一使用 gradient clip 1.0 和 AdamW $(\beta_1=0.9,\beta_2=0.95)$,有助于控制突发大梯度. auxiliary loss weight 在 Tiny/Small 为 0.001,最大模型为 0.0001,并配合 expert bias correction. 这些细节说明规模放大后负载均衡策略有调整,不能假定三种模型只有层数和专家数不同.

数据并行 rank 间的专家负载也会波动. 一批文档图可能产生大量相似视觉 token,另一批纯文本路由分布不同. 训练系统需要 all-to-all 通信与并行切分,论文表格报告 pipeline、tensor、expert 与 data parallel 配置. 它们保证该训练规模可运行,不是模型推理时必须逐项照搬的结构参数.

### 6.18. Sequence packing 提高利用率也引入边界风险

第二、三阶段开启 sequence packing,把多个短样本拼到 4096 token 序列. 若 attention mask 正确隔离,样本之间不会互读;若只用普通 causal mask,后一个问题可能看到前一个样本的答案,形成训练泄漏. 多模态 packing 还要让每张图只替换属于自己的 image placeholder.

一个最小单测可把两个完全不同样本 A、B 打包,只改变 A 的图片,检查 B 对应位置 hidden state 是否变化. 正确 block mask 下应不变;若变化,跨样本存在信息通道. 再检查 label mask,确保图像 token、padding 和用户提示不被当成 assistant 目标错误计损失.

packing 率越高,每步有效 token 越多,却使位置分布更复杂. 每个新样本的位置是否重置、RoPE position ID 是否连续,会影响训练—推理一致性. 论文报告使用 packing,代码或内部管线的完整训练实现并未全部公开,复现者需要自行验证这些细节.

### 6.19. 增量预填充只改变内存峰值

仓库为 VL2-Small 在 40GB GPU 上提供 `chunk_size 512` 的 incremental prefilling. 普通预填充一次处理全部视觉与文本前缀,中间激活峰值高;分块预填充逐段更新 KV cache,释放前段临时激活,降低峰值.

若前缀长度为 $N$,chunk 为 $c$,需要约 $\lceil N/c\rceil$ 次前向调度. 计算的 token 总量没有消失,小 chunk 还增加 kernel launch 与调度开销,所以 README 提醒可能变慢. 它解决“能否在显存内跑起来”,并非让模型本身更高效.

分块实现必须保持 attention 语义一致. 后一 chunk 可读取此前 KV,前一 chunk 不能看到未来 token. 视觉 embedding 替换位置、position ID 与 causal mask 任何一项错位,都会让分块结果偏离完整预填充. 验证可固定输入与 greedy decoding,比较两种路径的首步 logits 与生成 token.

### 6.20. 官方论文和仓库划定了可复现范围

[DeepSeek-VL2 论文](https://arxiv.org/abs/2412.10302)直接给出架构、三种模型规模、动态切图、数据类别、三阶段训练、超参数和完整评测表. [官方仓库](https://github.com/deepseek-ai/DeepSeek-VL2)提供 processor、视觉 encoder、VL adaptor、语言模型实现、配置、推理脚本和权重入口. 这些材料足以复现前向处理和检查模型结构.

全量训练数据、清洗规则的所有阈值、训练系统内部实现与完整随机种子没有开放,从零训练到论文结果仍需要自行构建数据和分布式管线. 开放权重让最终系统可测试,不等于训练过程每一步都可原样重放. 这两种开放程度应分开描述.

论文的最强结论是动态 tiling、DeepSeekMoE/MLA 与改进数据组成的 VL2 系统,以较少激活参数在多项多模态任务上取得竞争力. 单项技术的独立贡献、专家是否形成视觉专门化、极端宽高比和多图高分辨率的稳定性,仍需要额外消融. 把系统效果与机制推断分开,才能继续研究而不把合理解释写成已证事实.

### 6.21. SigLIP 特征为什么适合作为视觉起点

SigLIP 在大规模图文对上学习图像与文本的语义对应,输出已经包含对象、属性和场景信息. VL2 统一使用 SigLIP-SO400M,避免为三种语言模型分别训练视觉 backbone. 共享 encoder 也让规模比较更集中到 LLM 容量和 MoE 配置.

但对比式预训练倾向全局语义,OCR 和精确定位需要局部细节. 动态 tiling 用更高有效分辨率弥补这一张力,全参数阶段再让 SigLIP 以 0.1 学习率适应文档与 grounding. 如果完全冻结视觉 encoder,adaptor 只能重组既有特征,无法让 backbone 更关注小字和边界.

微调又会破坏原有泛化. 文档数据比例过高时,视觉特征可能偏向文字区域,自然图像的材质或细粒度类别反而下降. 一套有解释力的消融是比较冻结、0.1 倍学习率与主学习率三种设置,同时测 OCR、自然图 VQA 与 zero-shot 图像检索. 论文给出最终 0.1 倍方案,没有完整学习率曲线.

### 6.22. 图像 resize 与 padding 会改变坐标和字符尺度

候选网格确定后,原图需要缩放并填充到 tile 画布. 保持宽高比的 letterbox 会留下空白,padding 颜色若与训练分布不同,模型可能把边界当成内容. 直接非等比 resize 没有空白,却会拉伸文字和物体. processor 的选择是模型输入定义的一部分.

设原图按比例 $s$ 缩放,水平与垂直 padding 为 $(p_x,p_y)$,原坐标 $(x,y)$ 映射为

$$
(x',y')=(sx+p_x,sy+p_y).
$$

grounding 输出反变换时要减 padding 再除以 $s$. 若动态网格先切分再缩放,还要加 tile 原点;若先拼画布再切分,边界计算又不同. 坐标实现中的一像素误差在小 box 上会明显影响 IoU.

OCR 也受缩放策略影响. 插值核会平滑细笔画,二值扫描件用双线性缩小可能丢掉小数点. benchmark 通常只给模型最终图片,处理器应保持官方实现;自行更换 resize 库后出现分数变化,不能直接归因于权重.

### 6.23. 视觉位置与语言位置混用会遇到长度外推

视觉 token 插入语言序列后使用同一套自回归位置编号. 九 tile 让回答 token 的绝对位置大幅后移. 如果训练中大多数图片 tile 较少,高 tile 样本的答案位置分布较稀,模型可能在接近 4096 末端时更容易退化.

位置编号还编码了 tile 顺序,却没有天然二维含义. 相邻的一维 token 可能是同一 tile 的相邻 patch,也可能跨过 tile 边界;两个二维相邻 patch 若分属不同 tile,序列距离可能很远. 分隔 token 和全局图帮助模型学习这种非均匀几何.

可按答案起始位置分桶评测,将同一问题前面填入不同数量的无关视觉或文本 token,观察准确率. 若内容不变而位置后移导致下降,瓶颈更接近位置分布和上下文竞争. 这种实验能避免把所有九 tile 失败都解释成视觉 encoder 看不清.

### 6.24. 纯文本能力是多模态模型的隐性基线

图像问题最终仍由语言模型理解指令、推理和生成. 如果多模态训练损害纯文本数学与常识,视觉 benchmark 中需要语言推理的部分也会受影响. 保留文本数据不只是为了让模型还能聊天,也是维持多模态推理上限.

可以把任务误差粗分为视觉提取误差 $e_v$ 与语言条件推理误差 $e_l$. 二者并不独立,但若给模型完美的图像文字描述后仍答错,主要瓶颈在语言侧;若同一问题在人工描述下答对、看图时答错,瓶颈更接近视觉链路.

这种 oracle caption 实验适合图表和科学示意图. 人工把所有相关元素转成结构化文本,比较模型直接看图与读描述的差距. 差距小,继续提高视觉分辨率收益有限;差距大,需要改善 encoder、tiling 或 adaptor. 论文的端到端表格没有提供该上限测试.

### 6.25. 文档理解不能只看字符编辑距离

文档包含标题层级、段落、表格、脚注与阅读顺序. 两个输出字符完全相同,结构标记不同,下游检索效果可能差很多;字符有少量差异,结构正确,人仍能使用. 因而 OCR 和文档理解要拆开评价.

文本层可用 normalized edit distance,布局层可比较区域匹配与顺序,表格层可比较树结构或单元格关系. 对答案问答还要检查模型是否从正确区域取证. 只用 VQA accuracy,模型可能凭模板和常识答对,并未完整解析页面.

动态 tiling 主要增加局部像素,全局视图与 LLM 负责结构组合. 若 OCR 字符分上涨而表格结构不变,说明细节通道改善;若阅读顺序提升,才说明跨 tile 组织也变好. VL2 的多项 benchmark 给出系统覆盖,更细机制仍需按层指标.

### 6.26. 图表推理需要从像素恢复数据关系

柱状图问答看似读数字,实际包含轴刻度识别、柱子与类别绑定、高度映射、再执行比较或运算. 任何一步出错都能产生流畅但错误的答案. 动态切图若把图例、坐标轴和柱体分到不同 tile,局部细节增加,绑定难度也会上升.

设纵轴像素坐标 $y$ 对应数值 $v=a y+b$,模型需从刻度文本估计 $a,b$,再将柱顶坐标代入. 非零起点、对数轴和断轴都会破坏简单线性假设. 训练数据若大多是零起点规则图,模型容易形成错误捷径.

反例可以固定数据,改变颜色、图例顺序、轴范围与图表类型. 正确答案保持时,模型输出也应保持. 再把标签替换成无意义字符串,检查它是否真正读取绑定,而非依靠常见类别先验. 这些测试比单一 ChartQA 总分更能揭示推理链.

### 6.27. 小模型的激活参数优势有适用范围

Tiny 约 1.0B 整体激活参数,能以较低计算完成许多 OCR 与 VQA;复杂数学、多图关系和长描述仍受语言容量限制. MoE 增加总参数知识容量,单 token 只激活少数专家,并不保证所有任务都等价于同规模 dense 模型.

对一个任务,性能由可用专家容量、路由质量、attention 宽度和训练数据共同决定. activated parameter 只覆盖 FFN 计算的一部分,attention 与视觉 encoder 是 dense 成本. 因而“同激活参数更强”是有价值的效率观察,不能推成相同硬件延迟或相同显存.

比较三个 VL2 变体时,应画准确率—延迟、准确率—显存和准确率—总权重三条曲线. 若只画准确率—激活参数,会忽略大模型专家驻留和通信. 论文图的目标是展示稀疏计算下的能力密度,部署选型还要补系统指标.

### 6.28. MoE 路由错误会以内容相关方式出现

Dense FFN 的所有 token 经过同一参数,MoE token 若被路由到不合适专家,误差会随输入类别变化. 低资源语言、罕见符号或 adaptor 输出分布偏离训练区间时,router 更可能给出不稳定选择. 这类错误不一定在常规英文 VQA 中暴露.

可对同一视觉 token 加小扰动,比较 top-k expert 集合的 Jaccard 相似度. 如果极小噪声让专家集合完全改变,但输出仍稳定,专家存在冗余;若输出同步剧变,路由边界脆弱. 还可比较纯文本与视觉 token 的 router entropy,观察视觉分布是否更不确定.

负载均衡约束鼓励专家使用均匀,却可能把一部分 token 分给次优专家. 过强辅助损失牺牲语义路由换计算平衡,过弱又导致热点. 最大模型降低 aux loss 并用 bias correction,体现这一权衡. 论文没有给视觉任务上的路由消融,不能把规模收益全部归于专家数量.

### 6.29. 训练 token 统计不等于有效视觉监督量

一条带图长 caption 可能贡献数百文本 token,一条短 VQA 只有几个答案 token;若统计包含输入和输出,两者的训练 token 量与有效监督不同. 图片本身经过 encoder 产生视觉 token,是否计入论文表格的 training tokens 也要按原定义理解. 单一 token 总量无法说明图片多样性.

有效视觉覆盖还取决于独立图片数、每图问答数、分辨率与任务标签. 对同一图片生成十条相似问题会增加 token,新增视觉内容有限;一张密集文档虽只有一个样本,包含大量字符监督. 数据比较至少需要图像数、文本 token、视觉 token 和任务分布四个维度.

论文公开约 800B 的阶段量级与数据构建方法,没有开放全量明细. 因而可确认训练规模巨大且多样,不能由 token 数反推出某个 benchmark 领域用了多少独立图片. 这也是外部复现最难补齐的部分.

### 6.30. 坐标、OCR 与自然语言的损失权重并不天然公平

标准 next-token loss 对每个目标 token 求交叉熵. 一段长 OCR 转写贡献很多 token,一个 bounding box 只贡献少数坐标 token,短 VQA 可能只有一个词. 若全部混合后按 token 平均,长文本任务天然权重大;若按样本平均,短任务权重提高.

可为任务 $k$ 设置权重 $w_k$:

$$
L=\sum_k w_k\frac{1}{|T_k|}\sum_{t\in T_k}-\log p(y_t\mid y_{<t},x).
$$

不同归一方式会改变 grounding 与 OCR 的平衡. 论文没有完整公布任务 loss 权重,最终多任务成绩说明配方有效,但无法从表格还原采样与归一化细节.

模型可能有很强的 OCR 能力,却很少输出合法 box. 此时应检查坐标样本在 loss 中的权重,不能直接归因于视觉定位能力. 另一端也有风险:过多格式化 grounding 数据会让模型在普通问答中倾向输出坐标. 分任务训练曲线与梯度范数能帮助诊断.

### 6.31. 为什么视觉输入不适合盲目增加 tile

增加 tile 提升局部分辨率,也增加重复、边界、序列长度和推理延迟. 当原图信息已经被一两个 tile 充分采样,继续切分只是在更高分辨率观察噪声. JPEG 压缩块、扫描颗粒和屏幕摩尔纹都可能被模型当成细节.

可用边际收益描述预算选择. 令质量为 $Q(K)$,成本为 $C(K)$,选择满足

$$
\frac{Q(K+1)-Q(K)}{C(K+1)-C(K)}>\lambda
$$

的 tile 增量. 当前规则主要根据几何而非实际质量预测,无法知道下一 tile 的边际收益. 内容自适应方案需要额外估计器,也可能漏掉肉眼不起眼但问题相关的区域.

稳健系统可以结合问题条件. 问“图片整体是什么场景”时全局图足够;问“右下角序列号”时局部高分辨率必要. VL2 在编码前通常已知文本问题,理论上可以据此选择 tile,论文策略没有把问题条件作为主要切片信号. 这是清晰的后续方向,不是现有能力描述.

### 6.32. 一套最小复现实验如何拆开变量

第一步固定官方权重与 processor,复现若干论文 benchmark 子集,确保模板、图片占位符、坐标 parser 和 generation config 正确. 第二步保持权重不变,只改 tile 上限、全局图开关和 pixel shuffle,观察 OCR、grounding、普通 VQA 的差异. 这能测推理时预处理敏感性,但不等于训练消融.

第三步在小规模数据上训练 adaptor 或轻量模型,构造固定视觉/新 LLM、新视觉/固定 LLM 的交叉矩阵. 第四步统计视觉与文本 token 的专家路由、负载和干预结果. 第五步按 tile 数、宽高比、字符大小和答案位置分桶,而非只报平均分.

所有实验记录原图尺寸、选中网格、视觉 token 数、序列截断、输出长度、显存和时间. 发现错误时沿 processor、encoder、adaptor、LLM、parser 顺序定位. 如果坐标反变换错了,重新训练模型没有意义;如果视觉 token 已丢字,只调 decoder prompt 也不会稳定恢复.

这套复现不会复制近 800B token 的官方训练,却能验证核心机制是否按论文和代码运行. 大规模结果由官方权重承担,小规模受控实验负责回答因果问题,两者分工明确.

### 6.33. 这篇工作的技术主线

DeepSeek-VL2 解决的核心矛盾是高分辨率视觉需要更多 token,大语言模型又必须控制每 token 的计算和缓存. 动态 tiling 按图像几何分配视觉预算,pixel shuffle 压缩空间 token,MoE 控制 FFN 激活参数,MLA 压缩解码 cache. 四个部件分别处理像素覆盖、序列长度、参数计算和历史存储.

它们也引入四类新边界:tile 选择有阈值,shuffle 会压缩局部位置,MoE 有路由和通信成本,MLA 不消除长视觉前缀的预填充. 三阶段训练再把视觉对齐、全参数能力学习和指令行为分开,数据质量贯穿其中.

所以评价 VL2 不应停在“用了 MoE 的多模态模型”. 更准确的理解是一套预算系统:图像端决定看多少、切在哪里,adaptor 决定怎样进入语言空间,稀疏 LLM 决定每个 token 调用多少参数,训练数据决定这些部件是否学会合作. 论文与代码已经把这套系统的主要接口开放,仍未回答的因果问题可以由消融、反事实和逐层诊断继续补齐.

### 6.34. 分辨率提升只在采样定理允许时有效

原始图片若已经模糊,放大和多切 tile 不会创造真实笔画. 一个字符在原图里只有两三个像素宽,resize 到 384 像素或 768 像素只是插值复制;模型可能利用语言先验猜对,却没有增加可辨识信息. 动态 tiling 的收益前提是原图含有被固定缩放压掉的高频细节.

可以用同一高分辨率文档构造两条路径. 路径 A 直接交给动态切片;路径 B 先缩小到低分辨率,再放大回原尺寸. 两者输入画布相同,B 已永久丢失细节. 若模型在 A 上明显更好,说明策略利用了真实高分辨率信息;若两者接近,瓶颈可能在 encoder、shuffle 或语言解码.

扫描噪声还会混叠. 细线与 patch 网格接近时,轻微缩放可让线条出现或消失. 对工程图、乐谱和小数点,应测试不同缩放核与相位偏移. 这属于视觉采样边界,不能靠增加语言参数完全修复.

### 6.35. 图像旋转会同时挑战局部识别和全局顺序

动态网格按图像宽高比选择,旋转 90 度会交换候选布局. 文本方向也改变,SigLIP 是否见过足够旋转文字决定局部识别;tile 顺序从横向变纵向,LLM 又要重新组织阅读流. 因而旋转退化不只有 OCR 一个原因.

测试应区分三种情况:只旋转内容但保持画布,旋转整张图片并交换宽高,旋转后再自动纠正方向. 第一种隔离文字方向,第二种同时改变 tiling,第三种测外部预处理能否恢复. 如果方向纠正后完全恢复,使用专门 orientation detector 可能比扩大模型更划算.

自然图像对小角度旋转通常应稳定,表格和文档却有明确方向. 数据增强若过强,会让模型对方向不敏感,反而损害阅读顺序;若完全没有旋转增强,手机拍照稍倾斜就退化. 训练配方需要在不变性与方向语义之间取舍,论文未给完整增强参数.

### 6.36. 特殊字符与多语言 OCR 检验 tokenizer 边界

视觉 encoder 看清字符后,LLM 仍要用 tokenizer 表达它. 常见汉字或英文可能单 token 表示,罕见字、组合音标、数学符号和少数语言会拆成多个 token. 一个视觉字符对应更长输出链,任一 token 错误都会破坏转写.

若字符 $c$ 被编码成 $k$ 个 token,粗略正确概率为各步条件概率乘积. 即使每步准确率相同,$k$ 越大,整体正确率越低. 这让 tokenizer 覆盖与视觉能力耦合. OCR benchmark 若语言分布偏向高频字符,无法代表古籍、化学式或带重音文本.

可按字符的 tokenizer 长度和训练频率分桶,检查错误率. 再使用同字体渲染常见与罕见字符,保持像素难度相近. 若差距随 token 长度显著增加,瓶颈在语言输出链;若视觉相似字符普遍混淆,瓶颈更接近图像编码.

### 6.37. 多模态提示注入来自图像里的文字

模型会读取截图和文档中的文字,其中可能包含“忽略用户要求”“调用某工具”等指令. 对纯视觉问答,这些只是图片内容;接入 Agent 后,模型可能把它们误当系统命令. 高 OCR 能力同时提高了读取恶意文本的能力.

权限层级不能只靠自然语言位置区分. 系统与用户指令由 chat template 提供可信边界,图像 OCR 文本应标记为不可信数据. 若任务确实要求执行图片中的步骤,也应先让用户确认或由策略层判断允许动作. 模型本身无法知道一张网页截图由可信管理员还是攻击者提供.

可以构造图像注入集:正常任务要求总结页面,页面里隐藏工具调用、数据外传和角色伪造文字. 评价既看摘要是否正确,也看模型是否拒绝越权动作. VL2 论文关注理解能力,没有把 Agent 安全作为核心评测,开源权重部署时需要外部防线.

### 6.38. 校准需要区分“没看清”和“不会推理”

模型最终 token 概率混合了视觉与语言不确定性. 一张模糊票据上数字不清,模型仍可能以高概率输出常见金额;一张清楚的几何题中,视觉读取正确,推理步骤却不确定. 两者需要不同处理:前者请求更高清图片,后者增加推理或验证.

可以训练两个辅助信号. 视觉质量头根据局部特征预测可读性,答案验证头根据问题与候选答案预测推理置信. 如果视觉质量低,优先重新裁剪或放大;如果视觉质量高而答案分歧大,进行多样采样或调用计算工具.

不依赖新训练也能做有限诊断. 对同一图片改变 tile 预算,答案随分辨率剧烈变化说明视觉证据不稳;固定视觉输入多次采样仍分歧,更可能是语言推理不稳. 这不是完美分解,但比把 softmax 最大值直接当可靠置信度更有信息.

### 6.39. 版本复现必须锁定 processor 与模型权重

多模态 checkpoint 不只是一组 safetensors. processor 配置决定候选分辨率、归一化、图像占位符与 tile 顺序;tokenizer 决定特殊 token ID;模型配置决定 adaptor 和语言结构. 混用另一个版本的任一文件,有时不会报错,输出却明显退化.

验收可以保存一张固定图片经过 processor 后的网格选择、pixel values shape、image token mask 和首批 embedding checksum. 框架升级后逐项比较. 如果预处理输出已不同,无需等到 benchmark 下降才发现问题.

仓库与模型卡提供官方入口,第三方框架可能重新实现 processor 以提高速度. 优化实现应先在固定样例上达到 token 与 logits 等价,再测吞吐. 只看最终自然语言大致相似,会漏掉 grounding 坐标和小字识别的细微回归.

### 6.40. 最终结论应落到可证伪的变量

VL2 的系统成绩可以拆成四个可测变量:原图被保留多少有效像素,压缩后产生多少视觉 token,每个 token 激活多少语言参数,生成时缓存多少状态. 动态 tiling、pixel shuffle、MoE 和 MLA 分别控制它们. 数据与三阶段训练让这些部件形成协作.

如果固定像素与 token 后动态网格不再领先,收益主要来自预算增加;如果屏蔽视觉专门路由不影响任务,专家分工假设不成立;如果高分辨率只改善 OCR、不改善结构推理,跨 tile 组织仍是瓶颈;如果增量预填充改变输出,实现没有保持等价. 这些结果都能反驳过强解释.

论文已经充分证明最终系统在发布时的一组公开 benchmark 上具有竞争力. 它没有必要同时证明每个设计都是唯一方案. 把未解问题转成上述实验,既保留工作本身的贡献,也为后续动态视觉预算、稀疏多模态路由和长文档理解留下清晰入口.

### 6.41. 视觉 token 的注意力图不能直接当作解释

观察回答 token 对各 tile 的 attention,可以看到模型读取了哪些区域,但权重高不等于该区域因果重要. 多层 attention 会混合信息,某个低权重 token 可能早已把内容写入其他位置;softmax 权重还受 value 向量范数影响. 单张热力图适合发现明显错位,不适合单独证明模型推理路径.

更接近因果的方法是区域遮挡与表示替换. 遮掉被认为关键的 tile,观察正确答案概率和输出是否变化;把该 tile 换成内容相似但数值不同的反事实图,看答案是否跟随. 如果 attention 很亮而干预无影响,热力图可能只是相关;如果注意力分散但遮挡导致答案崩溃,信息已经通过复杂路径传播.

跨尺度还要分别干预全局图和局部图. 删除全局图后顺序错但字符仍对,说明它主要提供布局;删除局部图后字符错而整体描述还对,说明尺度分工符合设计. 这比凭可视化颜色解释各模块职责更稳健.

### 6.42. 多模态生成的停止条件会影响评测

文档转写和长描述常接近最大输出长度. 模型若生成 EOS 太早,结果表现为漏页;若 EOS 学得太弱,会重复段落直到截断. 两种错误的字符编辑距离都很差,处理方式却不同. 前者需要改善完整性监督,后者涉及重复控制和结束标记.

generation config 中的 max new tokens、EOS ID、temperature 和 repetition penalty 会改变结果. benchmark 应使用论文或官方仓库对应设置,并报告因 EOS 正常结束与因长度上限截断的比例. 一个模型输出更多文字可能覆盖更多真值,也可能增加幻觉,长度本身不是质量.

多图对话里每张图还有局部结束边界. processor 用图像占位符划分视觉段,decoder 的 EOS 只结束整条回答. 如果训练样本常在固定模板后结束,模型可能依赖格式而非内容判断完成. 改变提问措辞和要求的输出顺序,可以检查停止行为是否稳健.

### 6.43. 训练规模与开放复现之间的现实落差

第二阶段约 800B token,即便平均每步处理巨大 batch,仍需要可观的算力、存储与数据流水线. 开源代码能重现前向结构,普通研究者很难从零复制训练. 可行路线是使用公开 checkpoint 做受控推理干预,或在 Tiny 规模和小数据上验证趋势.

小规模结果也有外推限制. Tiny 的专家数、宽度和优化动力学不同,某个 tile 策略在 Tiny 有效,到 27B 总参数模型未必同幅度提升;反过来,大模型能用语言先验补偿视觉缺失,Tiny 更依赖清楚像素. 复现报告应明确验证的是机制趋势,不声称重建官方绝对分数.

知识库里最合适的结论因此分三层. 论文表格与开源配置属于可直接核对的事实;由公式和代码得到的成本、坐标与信息流关系属于结构推导;专家语义分工、数据配比贡献和极端场景泛化属于待实验假设. 三层写在一起没有问题,前提是语气清楚,不让读者把推导误认成团队已经报告的消融.

DeepSeek-VL2 给出的并非一个神奇模块,而是高分辨率多模态系统怎样分配有限预算的一套完整答案. 它让更多像素进入模型,又用空间压缩、稀疏专家和潜 KV 控制代价;它用大规模多任务训练获得广度,也把 tile 边界、序列竞争和路由稳定性带进新的研究空间. 沿这些变量分析,模型的优点与限制都会变得具体.

### 6.44. 阅读代码时最值得核对的四个接口

第一处是 processor 如何由原图尺寸选网格,并生成全局图、局部 tile 与占位符. 第二处是 pixel shuffle 前后的 tensor shape,它决定视觉 token 数是否与论文推导一致. 第三处是 adaptor 输出怎样替换语言序列中的 image token,任何数量不匹配都会造成位置错位. 第四处是 grounding 坐标怎样归一化和反变换.

这四处形成一条闭环:网格决定像素覆盖,shape 决定序列预算,embedding 替换决定视觉信息进入 LLM 的位置,坐标变换决定输出回到原图的含义. OCR 回答错误时可保存各层中间量逐项排查;若只看最终文本,预处理错误、模型错误和后处理错误会混在一起.

官方仓库还公开 Tiny、Small 和 VL2 的配置. 对比配置时要区分通用接口与规模差异:processor 主流程相同,语言层数、专家和 hidden size 不同;视觉 encoder 共同采用 SigLIP-SO400M. 这让同一张图片可以用三种模型做控制实验,检查错误随语言容量变化还是始终停留在视觉侧.

代码核对的价值不在于罗列类名,而在于把论文概念落到可测 shape 和坐标. 动态切图是否选择预期网格、压缩后是否产生预期 token、不同 chunk 的 logits 是否一致,都能写成单元测试. 这些测试通过后,benchmark 差异才更有资格被解释为模型能力差异.
