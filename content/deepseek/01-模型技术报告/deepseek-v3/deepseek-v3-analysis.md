# DeepSeek-V3: 671B 总参, 37B 激活, 14.8T token

来源: [DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437) (arXiv: 2412.19437v2, 2025-02-18). 仓库: https://github.com/deepseek-ai/DeepSeek-V3

DeepSeek-V3 延续 V2 的 MLA 与细粒度 MoE，同时把路由均衡、低精度训练、辅助预测目标和流水并行连成了一套完整系统。下面的推导以[原技术报告](https://arxiv.org/abs/2412.19437)为依据；同目录的 bi 稿可用于逐段核对原文。

DeepSeek-V3 是一个 671B 总参, 每 token 激活 37B 的 MoE 语言模型, 在 14.8T token 上预训练, 全部训练用了 2.788M H800 GPU 小时. 注意力和 FFN 的主体沿用 V2 的 MLA 与 DeepSeekMoE, 新增无辅助损失的负载均衡 (auxiliary-loss-free load balancing)和 MTP 训练目标; 工程侧采用 FP8 混合精度, DualPipe 流水并行和自写的跨节点 all-to-all 内核; 后训练把 DeepSeek-R1 的长 CoT 蒸馏进一个不输出长思考的普通对话模型. 这些改动互相牵连: 路由限制决定通信能否被计算覆盖, 通信开销降下来后才有条件取消张量并行, FP8 节省的显存和带宽又为大规模专家并行留出空间.

## 1. 模型结构

### 1.1. 从 V2 到 V3: 哪些没变, 哪些变了

从模型架构上看, V3 有 61 层, 隐藏层宽度 7168, MLA 用 128 个头, 每个头 128 维, KV 压缩维度 $d_c=512$, query 压缩维度 1536, 解耦 RoPE 每个头有 64 维. 除前三层保留稠密 FFN, 其余 58 层都是 MoE: 1 个共享专家加 256 个路由专家, 每个专家中间维 2048, 每 token 激活 8 个路由专家, 且最多发往 4 个节点. MTP 深度 D = 1. V2 是 60 层, 隐宽 5120, 2 个共享加 160 个路由专家, 激活 6 个. 层数几乎不变, 宽度和专家数都放大, 激活参数从 21B 涨到 37B, 总参数从 236B 涨到 671B, 激活率从 8.9% 降到约 5.5%.

37B 可以按这些宽度自己加出来. 每个专家是 SwiGLU 结构, 三个矩阵共 3×7168×2048 ≈ 44.0M 参数, 每个 MoE 层激活 9 个专家约 396M, 58 层约 23.0B. MLA 每层的 query 下投影, query 上投影(含 RoPE 部分), KV 下投影, K 与 V 上投影, 输出投影加起来约 187M, 61 层约 11.4B. 词嵌入和输出头各约 0.93B. 前三层稠密 FFN 的中间维报告正文没写, 公开权重的 config.json 里是 18432, 三层共 3×3×7168×18432 ≈ 1.19B. 四项合计约 37.4B, 与报告的 37B 对上. 总参同样可以加出来: 256 个路由专家乘 58 层约 654B, 加上共享专家, 注意力, 嵌入和稠密层, 约 671B. 报告的 671B 不含 MTP 模块; Hugging Face 上的权重合计 685B, 其中主模型 671B, MTP 模块 14B. MTP 模块由一个与主干同构的 MoE Transformer 块和一个 7168×14336 的投影组成, MoE 块约 11.6B, 权重文件里它还另存了一份嵌入和输出头, 约 1.9B, 合起来约 13.5B, 与 14B 相符.

### 1.2. MLA: 推理时每 token 只缓存 576 个数

MLA 的式 (1)–(11) 与 V2 完全一样: 键和值先由 $W^{DKV}$ 压成 512 维的潜向量 $c_t^{KV}$, 再分别上投影成 128 个头的 K 和 V; 另有一个 64 维的解耦键 $k_t^R$ 单独加 RoPE, 所有头共享. 推理时只需缓存这两个向量, 每 token 每层 576 个元素. 61 层合计 35,136 个元素, BF16 下约 70KB; 同样配置的标准 MHA 每层要存 2×128×128 = 32,768 个元素, MLA 只有它的约 1.76%. 按此计算, 一条 128K 的序列 KV cache 约 9.2GB. 这是 V3 能把上下文开到 128K 并在 decode 阶段用大 batch 的前提, 矩阵吸收与缓存推导见 [MLA 低秩潜变量与矩阵吸收](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md).

query 侧的低秩压缩(式 6–9)不影响推理缓存, 报告的说法是为了降低训练时的激活显存. 注意力打分的分母是 $\sqrt{d_h + d_h^R} = \sqrt{192}$, 因为每个头的 query 和 key 都由 128 维内容部分和 64 维位置部分拼成. 报告还写了两处 V2 就有的细节: 压缩潜向量后面各加一个 RMSNorm, 在宽度瓶颈处乘额外的比例因子. 这两处都是为了训练稳定, 很可能也与第 2.2 节的 FP8 有关: 低秩瓶颈的激活值范围如果不受控, 量化误差会被上投影放大. 报告没有对 MLA 做新的消融, 它在 V3 里被当作 V2 已经验证过的组件直接沿用.

### 1.3. DeepSeekMoE: sigmoid 门控和节点受限路由

MoE 层的输出是残差, 共享专家输出, 各路由专家输出按门控加权之和(式 12). V3 相对 V2 有一处小改动: 亲和度 $s_{i,t}$ 用 **sigmoid** 而不是 softmax 计算(式 15), 选出 top-8 以后, 再在这 8 个分数之间归一化得到门控值(式 13). 写成一步:

$$
s_{i,t}=\mathrm{Sigmoid}(\mathbf{u}_t^\top\mathbf{e}_i),\qquad g'_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}\in\mathrm{Topk}(\{s_{j,t}\},K_r)\\ 0, & \text{otherwise}\end{cases},\qquad g_{i,t}=\frac{g'_{i,t}}{\sum_{j}g'_{j,t}}.

$$

V2 每层 160 个路由专家, 每个 token 选 6 个; V3 是 256 个选 8 个。门控值是路由器给选中的每个专家的权重, 决定该专家的输出按多大比例混进这一路的结果。

softmax 和 sigmoid 的区别在权重怎么定。V2 用 softmax: 全体 160 个专家抢一块和为 1 的蛋糕, 单个分数在 160 个里分, 选中的 6 个加起来仍小于 1, 剩下那份谁也没拿到——路由这一路的输出幅度随路由集中程度浮动。V3 用 sigmoid: 每个专家独立打分, 各自落在 0 到 1, 再只在选中的 8 个内部归一化, 8 个权重相加恒等于 1——这一路幅度固定, 跟共享专家那一路的相对比例不再随 token 变化。Table 5 的两个基线都已采用 sigmoid 门控和 top-K 归一化, 因而没有分离出这项改动的贡献。

从路由上看, 专家被限制在少数节点上. 训练时每层的 256 个路由专家均匀分布在 8 个节点的 64 张卡上, 每卡 4 个. 每个 token 先按「每个节点上最高的 $K_r/M=2$ 个亲和度之和」给 8 个节点排序, 选出前 4 个节点, 再只在这 4 个节点的专家里选 top-8. 这一步的目的是限制跨节点流量: 节点内 NVLink 约 160 GB/s, 跨节点 IB 约 50 GB/s, 相差约 3.2 倍. 报告据此算出, 每个 token 平均在每个目标节点上可以选 3.2 个专家而不增加 NVLink 开销, 4 个节点最多 13 个专家, 通信成本和现在选 8 个一样. 也就是说, 激活专家数还有余量, 通信预算不是当前配置的瓶颈. V3 训练和推理都不丢 token, 这依赖下一节的负载均衡和第 5.1 节的冗余专家部署. DeepSeekMoE 细粒度专家与共享专家的来由见 [DeepSeek-MoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md).

### 1.4. 无辅助损失的负载均衡

常规 MoE 在训练损失里加一项辅助损失, 惩罚负载不均; 系数太小管不住, 太大又会干扰主任务的梯度. V3 采用 Wang 等人 2024 年提出的 **Loss-Free Balancing**(式 16): 给每个专家一个偏置 $b_i$——一个由训练循环维护的标量, 初值全 0, 与梯度无关: 每个训练步结束, 这一步里超载的专家 $b_i$ 减 $\gamma$, 欠载的加 $\gamma$; 推理时冻结——把上式的选择条件换成

$$
g'_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}+b_i\in\mathrm{Topk}(\{s_{j,t}+b_j\},K_r)\\ 0, & \text{otherwise}\end{cases}

$$

选 top-K 时用 $s_{i,t} + b_i$ 排序, 但乘到专家输出上的门控仍用原始的 $s_{i,t}$. 每个训练步结束时统计整个 batch 上各专家的负载, 超载的专家偏置减 $\gamma$, 欠载的加 $\gamma$. 偏置不参与反向传播, 也就没有辅助损失那样的干扰梯度; 它只改变「谁被选中」, 不改变「选中后权重多大」. Loss-Free Balancing 原文特别指出, 偏置要用之前 batch 的负载来更新, 如果用当前序列的负载, 路由就会泄露未来 token 的信息. V3 在步末更新, 下一步才生效, 符合这个约束.

超参数在 §4.2: 前 14.3T token 的 $\gamma=0.001$, 最后 500B token 设为 0, 即偏置冻结. 按符号更新时, 偏置每步最多变 0.001, 而 sigmoid 分数在 0 到 1 之间, 要把一个专家的选中率明显压下去大概需要上百步的累积. 最后 500B 冻结偏置, 恰好与学习率的最后两段恒定期重合, 路由在收尾阶段不再变动. 另外保留了一个极小的序列级均衡损失(式 17–20), $\alpha=0.0001$, 报告的说法是只为防止单条序列内极端不均. 这条损失里, $f_i$ 是专家 $i$ 在这条序列上实际被选中的频率(乘 $N_r/K_r$ 后以 1 为均值), $P_i$ 是它的平均门控权重, 两者乘积对所有专家求和再乘 $\alpha$——又热门又权重大的专家把乘积顶上去, 损失负责把它压下去:

$$
\mathcal{L}_{\mathrm{Bal}}=\alpha\sum_{i=1}^{N_r}f_iP_i,\qquad f_i=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb{1}\big(s_{i,t}\in\mathrm{Topk}(\{s_{j,t}\},K_r)\big),\qquad P_i=\frac{1}{T}\sum_{t=1}^{T}\frac{s_{i,t}}{\sum_{j}s_{j,t}}.

$$

形式和 V2 的专家级损失相同, $T$ 是一条序列的 token 数, 所以约束的是序列内部. 两处和 V2 不同. 一是 $P_i$ 里先把 256 个 sigmoid 分数除以它们的和: sigmoid 分数之和不是 1, 不归一的话 $\sum_iP_i$ 随路由器输出整体漂移, 损失的尺度就不固定. 二是 $f_i$ 的指示函数按原始 $s_{i,t}$ 的 Top-K 计数, 不含偏置 $b_i$, 而实际路由用的是 $s_{i,t}+b_i$; 偏置一旦把某个专家挤出或挤进 Top-8, 这一项看到的负载和真实负载就不一致. 报告没讨论这点, $\alpha$ 取得这么小, 影响大概有限. 这个系数比 V2 专家级均衡损失的 0.003 小 30 倍, 基本只在出现塌缩时起作用.

Table 5 在两个规模上比较纯辅助损失和无辅助损失. 小档 15.7B 总参, 2.4B 激活, 训 1.33T token; 大档 228.7B 总参, 20.9B 激活, 训 578B token. 大档的 HumanEval 从 40.2 升到 46.3, GSM8K 从 70.7 升到 74.5, MATH 从 37.2 升到 39.6, Pile-test BPB 从 0.656 降到 0.652. 但并非全部上升: 大档 MMLU 从 68.3 降到 67.2, 小档 MBPP 从 36.6 降到 35.8. 两个基线的辅助损失强度分别沿用 V2-Lite 和 V2 的设置, 没有针对新配置调参, 所以这组对比比较的是「V2 的做法」和「新做法」, 不是「最优辅助损失」和「新做法」.

§4.5.3 追问了优势从哪来. 无辅助损失和序列级辅助损失的根本区别在均衡的范围: 一个在整个 batch 上均衡, 一个要求每条序列内部均衡. batch 级约束更宽松, 允许一条代码序列集中用擅长代码的专家. Figure 9 和附录 C 在 Pile 的三个领域上画出 16B 模型的专家相对负载, 无辅助损失模型的专家特化更明显(读图). 他们又设计了一个 batch 级辅助损失作对照: 1B 模型上, 序列级辅助损失验证损失 2.258, 无辅助损失 2.253, batch 级辅助损失也是 2.253; 3B 模型上分别是 2.085, 2.080, 2.080. 结论是关键在均衡范围, 而不在是否用损失函数. batch 级均衡的代价是小 batch 或单条序列内可能严重不均, 以及推理时领域变化带来的不均; 前者靠大规模专家并行和数据并行保证每个 micro-batch 足够大, 后者靠部署时的冗余专家.

### 1.5. MTP: 训练时多预测一个 token

**MTP**: 训练时让每个位置不只预测下一个 token, 再多预测一个。思路来自 Gloeckle 等人 2024 年的工作, 但实现不同: 他们用 D 个独立输出头并行预测后面 D 个; 而 V3 直接就是串行——D 个模块一层层往后推, 每层保留完整的因果链(Figure 3)。

![报告 Figure 3: MTP 模块结构——每深度一个模块, 串行往后推, 嵌入层与输出头与主模型共享](images/p10-figure-3-illustration-of-our-multi-token-prediction-mtp.png)

图注: 报告 Figure 3: MTP 模块结构——每深度一个模块, 串行往后推, 嵌入层与输出头与主模型共享。
*报告 Figure 3: MTP 模块结构——每深度一个模块, 串行往后推, 嵌入层与输出头与主模型共享*

拿 V3 实际用的 D = 1 走一遍. 主模型在「爱」这个位置算出一个 hidden state——由「我」「爱」两个 token 算出。MTP 模块收到两样输入: 这个 hidden state, 和「北」的嵌入——嵌入就是输入层那张查表矩阵, 把 token 查成向量, 宽度和 hidden state 一样是 7168:

全模型只有一个宽度 d, embedding、hidden state、注意力内部都共用。预测「京」既需要「我爱」的上下文, 也需要紧跟其前的「北」; 而「爱」的 hidden state 里还没有「北」, 所以「北」的嵌入要单独喂进来。两样各做 RMSNorm 统一尺度, 首尾拼接成一个 14336 维的长向量(式子里的 $[\,;\,]$), 乘投影矩阵 $M_k$(7168×14336)压回 7168 维, 过一个小 Transformer 块, 最后用主模型共享的输出头预测「京」。嵌入层和输出头都与主模型共享, 模块自己要训的只有投影矩阵和那个小 Transformer 块。这是训练时的辅助任务, 推理时模块整个摘掉(也可以改作投机解码的草稿头, 见下文)。写成三步(式 21–23):

$$
\mathbf{h}_i'^{\,k}=M_k\big[\mathrm{RMSNorm}(\mathbf{h}_i^{k-1});\mathrm{RMSNorm}(\mathrm{Emb}(t_{i+k}))\big],\quad \mathbf{h}_{1:T-k}^{k}=\mathrm{TRM}_k(\mathbf{h}_{1:T-k}'^{\,k}),\quad P_{i+k+1}^{k}=\mathrm{OutHead}(\mathbf{h}_i^k),

$$

$$
\mathcal{L}_{\mathrm{MTP}}^{k}=-\frac{1}{T}\sum_{i=2+k}^{T+1}\log P_i^k[t_i],\qquad \mathcal{L}_{\mathrm{MTP}}=\frac{\lambda}{D}\sum_{k=1}^{D}\mathcal{L}_{\mathrm{MTP}}^{k}.

$$

$k=1$ 时 $\mathbf{h}_i^{0}$ 就是主模型最后一层在位置 $i$ 的表示. 第 $k$ 个模块在位置 $i$ 手里有两样东西: 上一深度对前缀 $t_{\le i+k-1}$ 的理解, 和真实的第 $i+k$ 个 token 的嵌入, 要预测的是第 $i+k+1$ 个. 这就是「保持因果链」的含义: 它不像 Gloeckle 的并行头那样从同一个 $\mathbf{h}_i$ 猜两步之后, 而是先把中间那个真实 token 喂进去再猜下一个. 因为要用到 $t_{i+k}$, 第 $k$ 个模块只能处理前 $T-k$ 个位置, 所以式 22 切片到 $1{:}T-k$. 两处 RMSNorm 让主模型表示和词嵌入在拼接前尺度一致, $M_k$ 把 $2d$ 维拼接压回 $d$ 维, 也就是上一节说的那个 7168×14336 投影. 总损失是主模型的 next-token 交叉熵加 $\mathcal{L}_{\mathrm{MTP}}$, $\lambda$ 前 10T token 取 0.3, 剩余 4.8T 取 0.1. MTP 的梯度经 $\mathbf{h}_i^{0}$ 回到主干, 另外还经共享的嵌入层和输出头回流; 推理时丢掉模块, 留下的就是被这几路梯度塑形过的主模型. 报告给的动机有两条: 训练信号更密, 可能提高数据效率; 模型可能会提前为未来 token 规划表示. 两条都是动机不是理论——没有分析证明 MTP 必然有效, 证据就是 Table 4 的消融; 「可能」出现了两次, 报告自己也没把话说死. 这类先有效、后补理论的设计在深度学习里是常态, 按实验行为对待即可. MTP 的一般机制见 [多 Token 预测 MTP](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.1-多Token预测MTP/2.8.1-多Token预测MTP.md).

Table 4 的消融在推理时丢掉 MTP 模块, 两边推理成本完全相同, 比的只是训练目标. 小档 15.7B 训 1.33T token, 大档 228.7B 训 540B token. 大档 HumanEval 从 44.5 升到 53.7, 小档从 20.7 升到 26.8; 小档 GSM8K 从 25.4 升到 31.4, MMLU 从 50.0 升到 53.3. 反例同样存在: 大档 MMLU 从 67.5 降到 66.6, 小档 NaturalQuestions 从 22.7 降到 22.3. Pile-test BPB 几乎不变(0.729 对 0.729, 0.658 对 0.657), 说明 MTP 没有让下一个 token 的预测变好多少, 提升集中在代码和数学这类需要多步规划的生成任务上. 两组消融的大档训练量不同(MTP 540B, 均衡 578B), 基线也不是同一个, 所以不能把两张表的提升直接相加当作 V3 相对 V2 的增益.

推理时 MTP 模块可以丢掉, 也可以改作投机解码的草稿头。接受的含义: MTP 猜出第二个 token, 主模型的下一个前向顺手验证。判据是标准的接受采样。$q$ 是投机解码头自己的 softmax——它前向一遍, 输出头在词表上给出对猜测 token 的信心, 比如 $q(\text{「京」})=0.7$; $p$ 是主模型验证前向的 softmax——主模型把草稿 token 当输入, 做它本来就要做的那个前向, 输出头给出权威判分, 比如 $p(\text{「京」})=0.4$。两者是同一个东西(词表上的 softmax), 只是一个出自解码头、一个出自主模型。

$$
P(\text{接受 } x)=\min\left(1,\\ \frac{p(x)}{q(x)}\right)

$$

这个公式的意义是**校正**: 草稿的 proposal 来自 $q$, 长期看输出会偏向 $q$; 让每个 proposal 以 $p/q$ 的概率存活, 存活频率恰好抵消 $q$ 的偏移, 净效果等于主模型自己采样——所以投机解码只加速、不换分布, 这是它能无脑上线的原因。$\min$ 封顶在 1, 因为概率不能超过 100%。草稿夸大了($q>p$)必收; 越心虚($q$ 小)按比值打折; **自信地猜错最容易被拒**。

被拒时从残余分布 $(p(x)-q(x))_{+}$ 归一化后重采样——把草稿多算的那部分扣掉再补样, 分布依旧与主模型严格一致。

走一遍完整的。已生成「我爱北京」, 第 6 个 token 待定:

1. 主模型前向, 采出第 5 个 token「天」(常规步骤, 没有投机)。
2. 草稿头拿到「京」的 hidden state(上下文摘要, 即训练时说的深度 0 输出, 主模型这步前向顺手就有)和「天」的嵌入(预测目标前一位的 token), 猜第 6 个是「安」, 给出 $q$:{安: 0.7, 门: 0.15, …}。
3. 主模型把「天」接进输入做验证前向, 给出第 6 个位置的 $p$:{安: 0.4, 门: 0.3, …}。
4. 只对草稿猜的那个词「安」做判定: $q(\text{安})=0.7$, $p(\text{安})=0.4$, 接受概率 $\min(1, 0.4/0.7)\approx 0.57$。接受, 这一步吐「天 安」两个 token; 拒绝, 从残余分布重采样(比如「门」), 输出「天 门」。

判定是抽签不是过线: 从 $[0,1]$ 抽均匀随机数 $u$, $u$ 小于接受概率就过——同一句草稿每次跑结果都可能不同。且必须随机: 只有按 $p/q$ 的概率随机接受, 长期频率才精确抵消 $q$ 的偏移, 任何确定性阈值都保不住分布不变。判定全程只用两个数——草稿分布和主模型分布在同一词上的概率, 与任何训练超参无关。

§5.4.3 报告第二个 token 的接受率在 85% 到 90% 之间(接受次数÷草稿次数, 各类生成主题上的统计), 解码速度达到 1.8 倍 TPS。按 D = 1, 每步期望产出 $1+p$ 个 token, $p$ 取 0.85 到 0.9 时为 1.85 到 1.9, 实测 1.8 倍, 差额应是草稿模块和验证的额外开销。报告没有给出按任务分开的接受率, 代码这类确定性高的文本接受率可能更高。投机解码的一般原理见 [投机解码原理与应用](../../../llm-guide/6-训练与推理优化/6.6-推理框架与高级优化/6.6.2-投机解码/01-投机解码原理与应用/01-投机解码原理与应用.md).

## 2. 训练基础设施

### 2.1. DualPipe 与跨节点通信

训练集群是 2048 张 H800, 每节点 8 卡. 并行方式为 16 路流水并行, 跨 8 节点的 64 路专家并行, 加 ZeRO-1 数据并行, 没有张量并行(§3.2). 跨节点专家并行的代价是 all-to-all 通信: 报告说计算与通信时间比约为 1 : 1, 不重叠的话一半时间在等通信. **DualPipe** 的做法是把每个 chunk 拆成注意力, all-to-all dispatch, MLP, all-to-all combine 四段, 反向 chunk 的注意力和 MLP 再按 ZeroBubble 的方式拆成「对输入求梯度」和「对权重求梯度」两部分; 然后把一对前向和反向 chunk 的各段交错排列, 并手工调整分给通信和计算的 SM 数, 使 all-to-all 和流水线通信都被计算完全掩盖(Figure 4). 调度上从流水线两端同时送入 micro-batch(Figure 5), 前向流和反向流在每张卡上交替.

Table 2 给出三种调度的气泡与显存. 1F1B 的气泡是 (PP−1)(F+B), ZB1P 是 (PP−1)(F+B−2W), DualPipe 是 (PP/2−1)(F&B+B−3W), 其中 F&B 是一对互相重叠的前向与反向 chunk 的执行时间. V3 的 PP = 16, 1F1B 的系数是 15, DualPipe 是 7, 而且括号里的项更小. 代价是每张卡保存两份模型参数, 峰值激活增加 1/PP. 专家并行已把 MoE 参数切到 64 张卡上, 每卡参数量较小, 报告认为这一开销可以接受. DualPipe 只要求流水级数和 micro-batch 数能被 2 整除, 气泡和激活显存都不随 micro-batch 数增长. 报告只给出公式比较, 没有提供 DualPipe 与 1F1B 的实测吞吐对照.

跨节点通信内核与路由一起设计(§3.2.2). token 先经 IB 发到目标节点上卡号相同的 GPU, 再经 NVLink 立即转发到存放目标专家的卡上, IB 和 NVLink 两段流量完全重叠. 只用 20 个 SM 就能跑满 IB 和 NVLink 的带宽, 这 20 个 SM 分成 10 个通信通道, 用 warp specialization 把 IB 发送, IB 到 NVLink 转发, NVLink 接收分给不同的 warp, warp 数按负载动态调整. 内核用定制 PTX 指令并自动调节通信块大小, 减少对 L2 缓存和其他计算 SM 的干扰. H800 一共 132 个 SM, 20 个用于通信意味着约 15% 的算力单元不做矩阵乘, 这也是 §3.5 希望硬件把通信从 SM 上卸下来的原因.

显存方面有三项措施(§3.2.3). 反向传播时重算所有 RMSNorm 和 MLA 的上投影, 不保存它们的输出激活. 参数的指数滑动平均放在 CPU 内存里, 每步之后异步更新, 用来提前估计学习率衰减后的模型效果, 不占显存也不占时间. DualPipe 把最浅层(含嵌入层)和最深层(含输出头)放在同一个流水级上, MTP 模块与主模型共享的嵌入和输出头因此在物理上共用参数和梯度. 这三项加上 FP8 的激活缓存, 使 V3 可以不用张量并行; 张量并行每层都要做 all-reduce, 在跨节点带宽有限的 H800 集群上开销很大.

### 2.2. FP8 混合精度训练

报告称这是首次在超大规模模型上验证 FP8 训练的可行性(§3.3). 线性层的三个 GEMM 都用 FP8: 前向 Fprop, 对激活求梯度的 Dgrad, 对权重求梯度的 Wgrad, 理论上速度是 BF16 的两倍; Wgrad 用 FP8 还意味着前向的激活可以按 FP8 缓存给反向用. 嵌入层, 输出头, MoE 门控, 归一化和注意力算子保持 BF16 或 FP32. 主权重, 权重梯度和优化器状态保持高精度, 其中 AdamW 的一阶, 二阶矩改用 BF16, 报告说没有观察到效果下降; 这些高精度部分的显存开销由数据并行分片摊掉. 混合精度的一般做法见 [FP8 混合精度训练详解](../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/02-FP8混合精度训练详解/02-FP8混合精度训练详解.md).

FP8 的难点是动态范围小, 常规做法按整个张量的最大绝对值定比例因子, 一个离群值就会把其他元素压到下溢. V3 改用**细粒度量化**: 激活按 1×128 的 tile(每个 token 每 128 个通道)分组, 权重按 128×128 的 block 分组, 每组各有比例因子, 并在线计算每组的最大绝对值, 不用延迟量化那样依赖历史最大值. 分组小了以后, 组内元素相当于共享指数位, 所以 V3 所有张量都用 E4M3 格式(4 位指数, 3 位尾数), 而不像以往在反向用范围更大, 精度更低的 E5M2. 这套做法与 microscaling 格式思路一致, Blackwell 的 Tensor Core 已宣布原生支持更小粒度的 microscaling.

另一个问题是累加精度. 报告实测 H800 的 FP8 GEMM 在 Tensor Core 里只保留约 14 位进行累加: 32 个尾数乘积按最大指数右移对齐后, 只取最高 14 位相加. 两个 K = 4096 的随机矩阵相乘, 最大相对误差接近 2%. V3 的办法是每累加 $N_C=128$ 个元素(相当于 4 条 WGMMA 指令), 就把部分和拷到 CUDA Core 的 FP32 寄存器里做全精度累加, 顺便乘上沿 K 维分组的比例因子完成反量化. 这会降低单个 warpgroup 的 WGMMA 发射率, 但 H800 上通常有两个 warpgroup 并发, 一个做提升累加时另一个做矩阵乘, Tensor Core 利用率仍然较高. 后来开源的 DeepGEMM 把这一过程描述为 FP8 GEMM 先得到每 128 个元素的部分和, 再在 FP32 中累加.

存储和通信也压到低精度(§3.3.3). 注意力之后那个线性层的输入同时被注意力的反向用到, 对精度敏感, 用定制的 E5M6 格式; 它在反向要从 1×128 tile 转成 128×1 tile, 比例因子取 2 的整数次幂, 避免转换时引入额外量化误差. MoE 中 SwiGLU 的输入按 FP8 缓存, 反向时重算输出. dispatch 前的激活量化成 FP8 再发送, down-projection 前的激活梯度同样处理; 前向和反向的 combine 保持 BF16. 附录 B.1 在约 16B(训 1.33T token)和约 230B(训约 0.9T token)两个规模上对比 BF16, 相对损失误差始终低于 0.25%. 附录 B.2 是一个反例: 把 Dgrad 相关张量都按 128×128 block 量化, 16B 模型训到约 300B token 时发散. 报告的解释是激活梯度在 token 之间极不均衡, 存在与 token 相关的离群值, block 量化无法按 token 隔离它们, 这也说明了激活为什么要按 1×128 的 token 方向分组.

## 3. 预训练

### 3.1. 预训练数据, 分词器与日程

数据上, 数学和代码样本的比例相比于 V2 提高了, 并把多语覆盖扩展到中英文以外(§4.1), 处理流程在减少冗余的同时保持多样性. 具体配比, 各语言占比, 去重规则, 报告都没有给. 文档打包沿用 Ding 等人的做法保证数据完整性, 但训练时不做跨样本注意力掩码, 同一条 4K 序列里的不同文档可以互相看到. FIM 按文档级 0.1 的比例施加, 格式是 Prefix-Suffix-Middle, 与 DeepSeekCoder-V2 一致; 报告称它不损害 next-token prediction, 又让模型学会根据前后文补中间. 分词器是 128K 词表的 byte-level BPE, 预分词器和训练数据为多语压缩率做了调整.

新的预分词器会引入一项边界效应. 它包含标点与换行合并的 token, 当多行提示最后没有换行时, 模型看到的 token 边界与训练中常见的不同, 这就是 token boundary bias, few-shot 评测的提示最容易触发. V3 的处理是训练时随机拆开一部分这类合并 token, 让模型见过更多边界情形. 拆开的比例报告没有给. 这一细节会影响第 3.3 节的 Base 评测: few-shot 提示的格式稍有变化, 分数就可能漂移, 而报告只说所有模型用同一套内部框架评测.

训练超参: AdamW, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 0.1, 梯度裁剪 1.0, 序列长度 4K. 学习率前 2K 步线性升到 2.2e-4, 恒定到 10T token, 再在 4.3T token 内按余弦降到 2.2e-5; 最后 500B token 中, 前 333B 保持 2.2e-5, 后 167B 降到 7.3e-6. batch 在前 469B token 内从 3072 条升到 15360 条, 之后保持. 满 batch 每步约 62.9M token, 剩余约 14.3T token 约需 22.8 万步, 加上 batch 爬升期约 1.2 万步, 总共约 24 万步. MTP 权重在 10T 处从 0.3 降到 0.1, 与学习率开始衰减是同一时刻; 偏置更新速度在 14.3T 处归零, 与最后 500B 的恒定学习率同步. 整个日程由三个切换点组成: 10T, 14.3T 和 14.633T.

预训练用了 2664K GPU 小时, 每万亿 token 约 180K GPU 小时, 在 2048 卡上约 3.7 天(§1). 按每 token 6 倍激活参数的前向加反向计算量, 14.8T token 约需 3.3e24 FLOPs; 2664K GPU 小时按 H800 稠密 BF16 峰值约 989 TFLOPS 算, 可用算力约 9.5e24 FLOPs, 折合 BF16 口径的算力利用率约 35%, 若按 FP8 峰值算则约 17%(未计注意力打分和 MTP 模块的计算量). 报告说全程没有出现不可恢复的损失尖峰, 也没有回滚; 这一点对成本很重要, 因为 Table 1 的小时数假设每一步都只跑一次. Scaling 的一般讨论见 [Scaling Law](../../../llm-guide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).

### 3.3. Base 模型评测

Base 评测用内部框架, 所有对比模型用同一套设置, 分差不超过 0.3 视为同一水平(Table 3). 评测协议分三类: HellaSwag, PIQA, WinoGrande, RACE, MMLU 系列, ARC, C-Eval, CMMLU, C3, CCPM 按困惑度打分, 即比较各选项的似然; TriviaQA, NaturalQuestions, DROP, 数学, 代码, BBH, AGIEval, CLUEWSC, CMRC, CMath 按生成打分; Pile-test 用 bits-per-byte, 以消除不同分词器的影响. 报告也承认内部框架近几个月有改动, V2-Base 的分数与之前公布的略有不同.

V3-Base 的优势集中在数学, 代码和多科选择题. MATH 61.6(Qwen2.5 72B 54.4, LLaMA-3.1 405B 49.0), HumanEval 65.2(53.0, 54.9), BBH 87.5, MMLU-Pro 64.4, CMath 90.7, MMMLU 非英语部分 79.4. 它输给 LLaMA-3.1 405B 的项目也不少: Pile-test BPB 0.548 对 0.542, HellaSwag 88.9 对 89.2, PIQA 84.7 对 85.9, WinoGrande 84.9 对 85.2, RACE-Middle 67.1 对 74.2, RACE-High 51.3 对 56.8, NaturalQuestions 40.0 对 41.5. 在 RACE 两项和 WinoGrande 上它甚至低于自家的 V2-Base. 中文方面 CMMLU 88.8 低于 Qwen2.5 的 89.5, CCPM 92.0 低于 V2 的 93.0.

这组输赢与第 3.1 节的数据改动对得上. 数学和代码比例提高, 相应的生成类评测大幅领先; 阅读理解和常识类题目几乎没有进步, 部分还倒退, 说明数据配比向数学代码倾斜, 挤占了一部分通用文本(报告没有给配比无法核实). Pile-test BPB 是最接近纯语言建模能力的指标, V3 用 37B 激活参数略输 405B 稠密模型, 这符合激活参数少 11 倍的预期. 报告「激活参数只有十一分之一却在多数项上更好」的说法成立, 但要加一句: 更好的主要是数学, 代码, 多科选择和多语, 语言建模和阅读理解并没有更好.

## 4. 后训练

### 4.1. 后训练数据: 从 R1 蒸馏推理能力

SFT 数据约 1.5M 条, 按领域用不同方法构造(§5.1). 推理类(数学, 竞赛编程, 逻辑题)用内部的 DeepSeek-R1 生成. R1 的输出准确率高, 但有过度思考, 格式差, 过长的问题, 目标是在 R1 的准确率与普通推理数据的简洁之间取平衡. 做法分三步. 先针对代码, 数学或通用推理某一领域, 用 SFT 加 RL 训一个**专家模型**. 专家模型的 SFT 阶段, 每道题生成两种样本: 一种是「问题, 原始回答」, 另一种是「系统提示, 问题, R1 回答」, 系统提示专门引导模型写出反思和验证. 专家模型的 RL 阶段用高温采样, 即使没有系统提示, 模型也会把 R1 的模式和原始回答的模式融合起来; 经过几百步 RL, 中间模型学会了 R1 的模式. 最后用专家模型做拒绝采样, 为 V3 筛出最终的 SFT 数据.

非推理类(创意写作, 角色扮演, 简单问答)用 DeepSeek-V2.5 生成回答, 再由人工核验准确性. SFT 训 2 个 epoch, 学习率按余弦从 5e-6 降到 1e-6; 多个样本打包进一条序列, 但用样本掩码让它们互相不可见. 这与预训练的做法相反, 预训练打包时不做跨样本掩码. 各领域的样本数量, 专家模型的规模, 拒绝采样的判据, 报告都没有给. SFT 的一般做法见 [SFT](../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md).

§5.4.1 用 V2.5 做了蒸馏消融(Table 9): 基线用短 CoT 数据训练, 对照组用上述专家模型生成的数据. LiveCodeBench-CoT 的 Pass@1 从 31.1 升到 37.4, 平均长度从 718 到 783, 只多约 9%; MATH-500 从 74.6 升到 83.2, 平均长度从 769 到 1510, 几乎翻倍. 数学的提升是用长度换来的, 代码的提升却几乎不增加长度, 说明两个领域从 R1 学到的东西不同: 数学学到的是多写验证步骤, 代码学到的更可能是解题思路本身. 报告说为 V3 「仔细选择了蒸馏的最优设置」来平衡准确率与长度, 但具体设置和 V3 最终的平均输出长度没有公布. 这组消融的对象是 V2.5 而不是 V3, 数学和代码以外领域的蒸馏效果也没有测. 蒸馏的一般讨论见 [知识蒸馏](../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.3-知识蒸馏/6.3.3-知识蒸馏.md).

### 4.2. RL: 两类奖励和 GRPO

奖励分两类(§5.2.1).

- **规则奖励**用于能按规则验证的题: 数学题要求把最终答案写在指定格式里(如方框中)再比对, LeetCode 题用编译器跑测试用例. 报告强调规则奖励不容易被模型利用漏洞, 所以能用就用.
- **模型奖励**用于其余情况: 有自由形式标准答案的题, 由奖励模型判断回答是否与标准答案一致; 没有标准答案的题(如创意写作), 奖励模型根据问题和回答给出反馈. 奖励模型从 V3 的 SFT checkpoint 训练而来, 偏好数据除了最终奖励, 还包含得出奖励的 CoT, 报告说这能降低特定任务上的 reward hacking.

策略优化用 GRPO(式 26–28), 与 V2 相同. 每道题从旧策略采样一组 G 个回答, 用组内奖励的均值和标准差把每个回答的奖励标准化成优势, 省掉与策略同规模的 critic 模型. 目标函数是 PPO 式的截断比率项减去 KL 惩罚, 式 26 里的比率写成整个回答的概率比 $\pi_\theta(o_i|q)/\pi_{\theta_{old}}(o_i|q)$, 是序列级写法; KL 用式 27 的无偏估计 $\pi_{ref}/\pi_\theta - \log(\pi_{ref}/\pi_\theta) - 1$. 组大小 G, 截断系数 $\varepsilon$, KL 系数 $\beta$, RL 步数和提示集规模都没有给. 后训练总共只用了 5K GPU 小时, 与预训练的 2664K 相比几乎可以忽略, 说明这一轮 RL 的规模很小, 和随后 R1 的大规模 RL 不是一个量级. GRPO 的推导见 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

§5.4.2 描述了自奖励: 在难以写硬规则的通用场景, 用 constitutional AI 的思路, 以 V3 自己投票评判的结果作为反馈. Table 8 在 RewardBench 上评了 V3 的判断能力: 平均 87.0, 用 6 次投票(maj@6)后 89.6; Claude-3.5-Sonnet-1022 是 88.7, GPT-4o-0806 是 86.7. 报告说单次判断与最好的 GPT-4o 和 Claude 版本「相当」, 按表 V3 单次比 Claude-1022 低 1.7, 投票后才反超. 自奖励让主观评测明显提升, 但没有给出提升多少的对比数字; 用模型自己当裁判, 也有把自身偏好放大的风险, 报告没有讨论.

## 5. 部署, 成本与谱系

### 5.1. 部署和对硬件的建议

推理把 prefill 和 decode 分开部署(§3.4). prefill 的最小单元是 4 节点 32 卡: 注意力用 4 路张量并行加序列并行, 配 8 路数据并行; MoE 用 32 路专家并行, 让每个专家拿到足够大的 batch. 为了均衡负载, 按在线统计复制高负载专家, 设 32 个冗余专家, 每卡在原有 8 个专家外多放 1 个, 冗余集合定期调整(如每 10 分钟). 同时处理两个计算量相近的 micro-batch, 一个做注意力和 MoE 计算时, 另一个做 dispatch 和 combine. 报告还在试验动态冗余: 每卡放 16 个专家, 每步只激活 9 个, 每层 all-to-all 之前实时算出全局最优路由.

decode 的最小单元是 40 节点 320 卡. 注意力仍是 4 路张量并行加序列并行, 配 80 路数据并行; MoE 用 320 路专家并行, 每卡只放 1 个专家, 其中 64 张卡放冗余专家和共享专家, 256 + 64 = 320 正好对上. decode 时把共享专家当成一个必选的路由专家, 每个 token 相当于选 9 个专家. 每个专家的 batch 通常不超过 256 个 token, 瓶颈是访存而不是计算, 所以 MoE 部分只分少量 SM, 把算力留给注意力. dispatch 和 combine 走 IB 点对点传输, 用 IBGDA 降低延迟. 结论节承认推荐部署单元偏大, 对小团队是负担, 端到端生成速度比 V2 快两倍多, 但仍有提升空间.

§3.5 的硬件建议是把 V3 在软件里绕过的限制列出来. 通信方面: 用 SM 做通信会占掉 132 个中的 20 个, 而且这些 SM 上的 Tensor Core 完全闲置; 希望把 IB 与 NVLink 之间的转发, RDMA 缓冲区搬运, combine 的归约交给协处理器, 并把 IB 和 NVLink 统一成计算单元可直接调用的读, 写, 组播, 归约原语. 计算方面: 提高 Tensor Core 的 FP8 累加精度; 原生支持 tile 和 block 级量化, 让部分和的累加与反量化在 Tensor Core 内完成; 把 FP8 转换和 TMA 访存融合, 在数据从全局内存搬到共享内存的途中完成量化, 报告估计近存计算方案可减少约 50% 的片外访存; 支持从共享内存直接转置读取, 省掉反向时反量化, 转置, 再量化的往返.

### 5.2. 成本, 局限和谱系位置

Table 1 按 H800 每小时 2 美元租价计算: 预训练 2664K GPU 小时, 上下文扩展 119K, 后训练 5K, 合计 2788K, 约 557.6 万美元. 报告明确说这只包括 V3 的正式训练, 不包括此前在架构, 算法, 数据上的研究和消融. 第 1.4, 1.5 节的消融模型(15.7B 训 1.33T token, 228.7B 训 540B 或 578B token)和附录 B 的 FP8 对比实验本身就要花不少算力, 都不在这个数字里. 部署侧 decode 最少 320 卡, 训练便宜并不意味着服务便宜.

从方法看, V3 的每项改动都有消融或实测支撑: 无辅助损失均衡有 Table 5 和 batch 级对照, MTP 有 Table 4 和接受率, FP8 有附录 B, 蒸馏有 Table 9. 缺的是它们之间的组合效应和规模外推: 消融最大只做到 228.7B 总参, 不到 V3 的三分之一, 训练量不到 V3 的二十分之一. sigmoid 门控, 节点受限路由, 分词器改动, 数据配比变化都没有单独消融. 报告的结论节列出了后续方向: 改进架构以支持无限长上下文并尝试突破 Transformer, 扩大数据的规模和信号来源, 加长推理的长度和深度, 以及建立不易被针对性优化的评测.

谱系上, V3 继承 V2 的 MLA 和 DeepSeekMoE, 把均衡方式换成无辅助损失, 加上 MTP, 用 FP8 和 DualPipe 训完 14.8T token. 后训练阶段它是 R1 的学生: SFT 数据里的推理部分来自 R1 系列专家模型. 反过来, V3-Base 又是 R1 的起点, R1 在它之上做大规模 RL. 之后的 V3.1, V3.2 继续沿用这个 671B 的 MoE 底座, 在注意力稀疏化和混合推理模式上改进. 推理与思考能力的整体脉络见 [推理与思考能力](../../../llm-guide/4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).

## 6. 无辅助损失均衡的完整推导

### 6.1. 从路由分数到选择分数

V3 的路由先计算 token $t$ 与专家 $i$ 的亲和度

$$
s_{i,t}=\operatorname{Sigmoid}(u_t^{\mathsf T}e_i),
$$

其中 $u_t$ 是进入 MoE 的隐藏状态, $e_i$ 是专家中心. 选择专家时不直接按 $s_{i,t}$ 排序, 而是加入每个专家的动态偏置 $b_i$:

$$
g'_{i,t}=s_{i,t}+b_i.
$$

节点受限筛选与 Top-$K$ 都看 $g'_{i,t}$; 真正加权专家输出时仍用原始 $s_{i,t}$, 即

$$
y_t=\sum_{i\in\mathcal T_t}s_{i,t}E_i(u_t).
$$

偏置只改变「谁被选中」, 不直接改变「被选中后占多少权重」. 这一区分正是 auxiliary-loss-free 的含义. V2 把负载目标作为可微损失加进总目标, 均衡梯度会穿过门控概率并与语言建模梯度相加; V3 把均衡变成训练控制器, 主损失只优化预测质量.

每个训练步结束后统计专家负载. 若专家 $i$ 的负载高于目标, 将 $b_i$ 减去更新速度 $\gamma$; 低于目标则加上 $\gamma$. 可以把它写成离散反馈:

$$
b_i^{(n+1)}=b_i^{(n)}+\gamma\,\operatorname{sign}(\bar f-f_i^{(n)}),
$$

$f_i^{(n)}$ 是本步接收的 token 数, $\bar f$ 是平均目标. 报告给出正式训练的偏置更新速度先取 $0.001$, 后降到 $0$, 但没有公布完整衰减曲线. 这个控制器像一个只看误差方向的积分调节: 热门专家的选择门槛逐步升高, 冷门专家逐步降低. 它不要求对离散 Top-K 求导.

拿四个专家、Top-1 做手算. 原始分数为 $(0.80,0.76,0.55,0.30)$, 偏置初始为零, 第一个专家被选. 若它连续过载, 偏置变成 $(-0.06,0.02,0.02,0.02)$, 选择分数成为 $(0.74,0.78,0.57,0.32)$, 第二个专家接手; 输出权重使用第二个专家原始的 0.76, 而非加偏置后的 0.78. 如果偏置也进入输出权重, 负载控制会直接缩放主网络激活, 专家输出分布随控制器漂移, 训练更难解释.

### 6.2. sigmoid 与 softmax 的差别

V2 在全部路由专家上做 softmax, 一个专家分数升高会压低其余专家概率, 各门控值之和为 1. V3 用逐专家 sigmoid, 每个 $s_i$ 独立落在 0 到 1. 两个 token 即使专家排名相同, 也可以分别呈现「所有专家都很匹配」与「所有专家都不太匹配」. Top-K 决定计算稀疏度, sigmoid 数值决定专家输出强度.

独立门控也改变了均衡控制的几何形状. softmax 对所有 logit 加同一常数毫无影响, 偏置必须改变相对差; sigmoid 后加选择偏置同样按相对排名工作, 但输出强度没有归一化约束. V3 对选中专家的亲和度再做缩放, 让路由专家权重和保持在合适范围. 若多个 sigmoid 同时接近 1, 未缩放的专家和会随 Top-K 增大而放大残差; 若都很小, MoE 路径又会变弱.

一个可证伪问题是 sigmoid 是否独立贡献质量. 应固定专家数量、Top-K、负载控制和训练数据, 只比较 softmax 与 sigmoid, 同时报告主损失、门控和、专家熵与负载. V3 报告把 sigmoid、节点限制和偏置均衡一起用于正式模型, 没有独立给出这张消融表, 因而不能把均衡改进全部记在 sigmoid 上.

### 6.3. sequence-wise 辅助损失为什么还保留

「无辅助损失」指不再使用 V2 那种全局专家级、设备级、通信级损失作为主要均衡手段. V3 仍保留一个很小的 sequence-wise balance loss. 对单条序列, 统计各专家获得的分派比例 $f_i$, 再与平均亲和度 $P_i$ 相乘:

$$
\mathcal L_{Bal}=\alpha\sum_i f_iP_i,
$$

其中 $\alpha=0.0001$. 它约束的是每条序列内部的极端路由. 全局 batch 完全均衡仍可能掩盖单序列塌缩: 一条中文长文全去第一组专家, 一条代码长文全去第二组专家, batch 统计很漂亮, 每条序列却只有少量专家得到训练. sequence-wise 项给这种现象轻微惩罚.

它的系数比 V2 的专家级 0.003 小三十倍, 也远小于 V2 的设备级 0.05. 因而主均衡动力来自偏置反馈, 序列损失更像防止局部极端状态的护栏. 如果把它删掉后全局负载仍均匀, 但长序列的专家覆盖数显著下降、验证损失升高, 就证明它捕获了偏置控制遗漏的尺度; 若各项都不变, 这项可以删去.

### 6.4. 控制器的振荡与滞后

偏置更新速度过大时, 某专家本步略热便被大幅压低, 下步转为过冷, 偏置又反向跳动, 负载在专家间振荡. 速度过小时, 数据分布突然从代码切到中文, 热点要很多步才消退, 中间会发生容量溢出. 合适的 $\gamma$ 取决于 batch token 数、专家数、数据混合与路由分数间隔.

sign 更新只看方向, 不看超载多少. 超载一个 token 与超载一千个 token 得到同样步长, 鲁棒但响应慢. 可替代方案是按归一化负载误差更新, 代价是容易被异常 batch 推得过远. V3 选择固定小步并在训练后期降到零, 相当于先让专家分工与负载共同成形, 收尾时冻结选择边界, 避免 checkpoint 附近仍有控制振荡.

要验证稳定性, 至少应画出专家负载最大值、最小值、变异系数、偏置范数和 token 丢弃率随训练步变化的曲线. Table 5 的最终分数证明方案可用, 却无法展示控制过程是否经历过振荡. 后来的部署仍要复制热门专家, 说明训练均衡不等于任意在线流量都均衡: 线上输入分布会偏离训练混合, 专家热度也会改变.

## 7. MLA 与 V2 的继承账

V3 保留 $d_c=512$ 的 KV 潜向量和 64 维解耦 RoPE 键, 每层每 token 缓存 576 个元素. 61 层中首层是 Dense FFN, 注意力层数仍按 61 计算, 则每 token 缓存 35136 个元素. BF16 下约 68.6 KiB; 128K 单序列约 8.58 GiB. 若部署把缓存量化, 实占取决于位宽、尺度和对齐. 这条路线与 V2 几乎相同, V3 的主要结构创新落在路由与 MTP, 并未重新设计长上下文状态.

V3 的隐藏宽 7168, 128 个注意力头, 每头内容维 128, 位置维 64. 普通 MHA 若为每头缓存 128 维 K 与 128 维 V, 每层每 token 是 32768 个元素; MLA 的 576 是其 1.76%. 61 层、128K、BF16 的 MHA 缓存约 488 GiB, MLA 约 8.58 GiB. 这是假想同配置 MHA 对照, 不是论文实测部署差值.

MLA 的矩阵吸收仍要求内容 K/V 上投影为固定线性映射. 解耦位置键独立缓存, 避免 RoPE 旋转夹在可吸收矩阵之间. V3 使用更大隐藏宽度, 512 维公共潜变量相对隐藏状态的压缩比例从 V2 的 $512/5120=10\%$ 降到 $512/7168\approx7.14\%$. 若模型规模扩大需要保存更多独立历史特征, 固定 512 可能成为更强瓶颈; 正式结果说明它至少在 V3 数据和任务上仍可用, 报告未扫描 512、768、1024 的质量与缓存曲线.

MLA 与路由存在潜在交互. 注意力输出的微小变化可能让 token 跨过 Top-K 专家边界, 离散路由会放大表示差异. 可做四格实验: MHA 配 V2 路由、MLA 配 V2 路由、MHA 配无辅助损失路由、MLA 配无辅助损失路由. 若 MLA 在两套路由下的分数差相近, 两项改动近似独立; 若只在新路由下稳定, 说明偏置控制补偿了低秩表示对路由的扰动. 公开消融没有覆盖四格, 正式模型的总增益不能拆成简单加法.

## 8. FP8 混合精度到底混在哪里

### 8.1. 动态范围与量化误差

FP8 用 8 个比特表示符号、指数和尾数. E4M3 提供更多尾数精度、较小动态范围, 常用于前向激活与权重; E5M2 指数更多、范围更大, 常用于梯度. V3 不是把全部状态粗暴改成 8 bit. 参数主副本、优化器状态、部分累加与敏感算子保留更高精度, 大矩阵乘的输入使用 FP8, 输出和归约按指定精度处理.

将张量 $x$ 量化前选尺度 $a$, 得到 $Q(x/a)$, 计算后再乘回尺度. 若整张矩阵共享尺度, 一个离群值会把 $a$ 拉大, 大部分普通元素挤在很少的离散档位上. V3 对激活采用 $1\times128$ tile-wise 量化, 对权重采用 $128\times128$ block-wise 量化. 每个小块拥有自己的尺度, 离群值只污染所在块.

举个简化例子. 一组 128 个激活中 127 个绝对值约 0.1, 一个值为 100. 若整层共享最大值尺度, 0.1 可能量化为零或极粗档位; tile 分组至少把影响限制在这 128 个值. 如果离群值分散到每个 tile, 局部量化也无能为力. 因而 FP8 成功依赖激活统计, 分组只能缩小离群影响范围, 无法消除所有误差.

### 8.2. 累加精度与分块求和

两个长度为 $K$ 的向量做点积, 每项乘积有量化误差, 累加又会产生舍入误差. 若一直在低精度累加, 小项可能被大部分和吞掉. V3 在 Tensor Core 上以有限精度累加, 每隔 128 个乘积把部分和提升到 CUDA Core 的 FP32 寄存器, 再继续下一块. 可写为

$$
y=\sum_{j=1}^{K/128}\operatorname{FP32}\left(\sum_{k=128(j-1)+1}^{128j}\widehat x_k\widehat w_k\right).
$$

块内仍有低精度累加误差, 块间使用 FP32 避免误差随完整 $K$ 长度持续堆积. 代价是把部分和搬出 Tensor Core, 引入额外指令与数据移动. 报告的硬件建议希望未来 Tensor Core 原生支持更高精度累加, 正是为了去掉这段软件补偿.

### 8.3. 哪些部件保持高精度

嵌入、输出头、MoE 门控、归一化和注意力相关的敏感操作并非全部采用同一种 FP8 路径. 优化器状态需要累积很小的更新, 仍保留 FP32; 权重主副本承担长期参数记忆, 不能只剩每步量化后的 8 bit 值. 通信中的部分张量也根据数值风险选 BF16 或 FP8. 所以「FP8 训练」描述的是主要 GEMM 数据路径, 不是模型文件和每个中间量都只有八位.

附录 B 用两个 16B 级模型训练 2T token 对比 BF16 与 FP8, 验证损失曲线高度接近, 下游分数也接近. 该证据支持方案在这一路径和规模上的数值稳定性. 正式 671B 模型没有一份从头到尾的 BF16 平行训练作对照, 成本太高. 若 FP8 误差只在训练很后期或更大规模累积, 小模型实验可能看不见; 正式训练无不可恢复尖峰则提供另一种稳定性证据, 但不等价于质量零损失.

### 8.4. 可证伪的数值检查

最直接的检查是同一 checkpoint、同一 batch 同时跑 BF16 参考路径与 FP8 路径, 比较每层输出余弦相似度、最大绝对误差、梯度方向与最终 loss. 再按层深、专家、token 类型分桶. 若误差只在少数专家放大, 可能是那些专家权重存在离群块; 若随层数单调积累, 残差路径没有完全吸收量化噪声; 若训练开始稳定、学习率下降后反而恶化, 小更新可能低于量化分辨率.

另一个实验是固定训练 token, 分别采用全 BF16、仅权重 FP8、权重加激活 FP8、再加入 FP8 通信. 每步记录吞吐、显存和最终质量. 这样才能分清速度来自矩阵乘、通信带宽还是更大 batch. 报告给了整体方案与局部对照, 尚未公开这条完整阶梯.

## 9. Multi-Token Prediction 的目标函数

### 9.1. 从下一个 token 到下两个 token

标准语言模型在位置 $t$ 用隐藏状态预测 $x_{t+1}$. V3 加一个 MTP 模块, 让主干表示同时学习更远一步的目标. 第一个额外模块把当前位置主干表示与下一个真实 token 的嵌入结合:

$$
h_t' = M_1[\operatorname{RMSNorm}(h_t);\operatorname{RMSNorm}(E(x_{t+1}))],
$$

再经过一个 Transformer block 与共享输出头预测 $x_{t+2}$. 训练损失为

$$
\mathcal L=\mathcal L_{Next}+\lambda\mathcal L_{MTP},
$$

正式模型只保留一个额外预测深度, 权重 $\lambda$ 在训练中逐步衰减. MTP 模块训练后可丢弃, 主模型仍按普通自回归方式生成; 也可在推理时拿来做 speculative decoding 的草稿预测.

为什么输入里要含真实的 $x_{t+1}$? 预测 $x_{t+2}$ 本来就应以 $x_{t+1}$ 为条件, 否则任务变成从同一状态并行猜两个未来 token, 条件分布更模糊. 训练时 teacher forcing 提供真实嵌入; 推理验收时只能使用主模型刚采样的 $x_{t+1}$, 若第一步猜错, 第二步候选也会偏离. 因而训练损失改善不自动等于推测解码接受率高.

### 9.2. MTP 怎样改变主干表示

额外损失的梯度会通过 MTP 模块流回主干 $h_t$. 标准目标只要求 $h_t$ 足以区分下一个 token; MTP 还要求它与下一 token 结合后能判断再下一个 token. 对短语「北京是中国的」, 下一词「首都」较确定, 再下一词可能是标点或补语; 对代码中的括号结构, 更远 token 受到语法约束, MTP 会鼓励主干提前编码结构信息.

它也可能伤害局部建模. 如果 $\lambda$ 过大, 主干为远期可预测性牺牲下一 token 的细节; 对高熵文本, $x_{t+2}$ 的噪声梯度会干扰主目标. 权重衰减让训练早期多用额外监督塑造表示, 收尾时回到下一 token 目标. 报告的消融显示 MTP 模型在多项基准略优, 没有观察到主要任务损失, 但只测试了给定深度和权重日程.

### 9.3. 接受率与加速上限

推测解码中, 主模型提出 $x_{t+1}$, MTP 头提出 $x_{t+2}$, 再由主模型一次验证多个候选. 报告称第二 token 接受率在 85% 到 90%. 若每轮必验第一个 token, 第二个以概率 $p$ 被接受, 每轮平均前进 $1+p$, 当 $p=0.85$ 时是 1.85 token. 这只是理想步数收益; 验证额外 token 会增加一次前向的计算, 调度与缓存写入也有成本, 实际加速低于 1.85 倍.

若扩成两个额外头, 第二、第三候选接受概率分别为 $p_2,p_3$, 第三个只有前两个都通过才能采用, 平均前进约 $1+p_2+p_2p_3$. 错误相关性很关键. 两头若常在同一难点同时失败, 增加深度收益迅速递减. V3 正式模型选择单层 MTP, 可以看作训练收益、接受率与额外模块成本之间的保守点.

### 9.4. MTP 的对照实验怎样做

公平对照应固定主干参数、训练 token 和总 FLOPs. 加 MTP 会增加少量计算; 若直接按相同步数比较, MTP 模型花了更多 FLOPs. 一套对照固定 token, 测额外监督是否值得额外计算;另一套固定 FLOPs, 让基线多训练一些 token, 测预算下净收益. 还应报告主损失、MTP 损失、各领域接受率和文本熵. 若代码接受率高、创意写作低, 说明收益来自局部结构可预测性, 不宜用单个平均接受率概括所有流量.

## 10. DualPipe 的调度逻辑

### 10.1. 流水线气泡从哪里来

模型切成 $P$ 个流水线阶段, 普通 1F1B 调度需要先填满流水线, 尾部再排空. 每个 micro-batch 的前向和反向还夹着 MoE all-to-all. V3 跨节点专家并行让通信量很大, 若计算与通信串行, GPU 会频繁等待网络.

DualPipe 从流水线两端同时注入 micro-batch, 将前向、输入梯度反向和参数梯度反向拆开排程. 一条 micro-batch 做矩阵计算时, 另一条可以进行专家 dispatch 或 combine. 关键资源约束是计算核、通信 SM、显存缓冲和依赖关系; 「重叠」要求两类工作使用的瓶颈不同. 若通信已经占满内存带宽, 同时跑 GEMM 未必免费; 若网络等待为主, 计算就能遮住大部分延迟.

报告给出训练时最多让 20 个 SM 处理通信, 其余用于计算. 以 H800 的 132 个 SM 计, 通信保留约 15.2% SM. 这些 SM 上的 Tensor Core 在通信核运行时闲置, 所以硬件建议提出专门通信协处理器. DualPipe 把等待藏到计算背后, 却没有让通信字节消失; 网络或转发一旦超过可遮蔽窗口, 气泡仍会露出来.

### 10.2. 节点受限路由的通信上界

V3 每 token 选 8 个路由专家, 但限制在最多 4 个节点. 每节点 8 卡, 专家并行铺在大量 GPU 上. 不限制节点时, 8 个专家最坏落在 8 个节点, 隐状态需发往 8 处; 节点限制把跨节点目的地减半, 节点内再由高速 NVLink 分发. 选择候选节点时取该节点专家分数之和的前若干项, 再在候选节点内选专家.

这会产生质量与通信的交换. 全局排名第八的专家若位于第五个节点, 会被候选外某个较低分专家替代. 当高分专家集中在少数节点, 交换几乎没有代价; 当它们均匀散开, 限制更强. 可按 token 记录受限与无限制 Top-8 的重合数及被替换分数差, 再与 loss 增量关联. 报告给出最终效果, 没有公开这组分布.

### 10.3. 训练稳定性不是只有 loss spike

报告称完整训练没有不可恢复的 loss spike, 也没有回滚. 这是大规模训练稳定性的强证据, 但稳定包含多个层面: 数值是否溢出, 路由是否坍缩, 数据 batch 是否异常, 流水线是否死锁, checkpoint 是否可恢复. FP8 可能造成非有限值, MoE 可能出现专家热点, DualPipe 的复杂依赖可能暴露通信竞态. 最终 loss 平滑只覆盖其中一部分.

可复核日志应包含全局 loss、梯度范数、各 FP8 缩放因子、溢出计数、专家负载、偏置范围、丢弃率、流水线气泡与网络吞吐. 若 loss 正常但少数专家长期不被选择, 容量已经浪费; 若负载正常但 FP8 尺度频繁触顶, 数值裕度不足. V3 正式训练走完 14.8T token 说明整套防护有效, 仍不能据此定位每项防护的独立贡献.

## 11. 参数量与 FLOPs 手算

### 11.1. 专家参数

V3 有 256 个路由专家与 1 个共享专家, 每 token 选择 8 个路由专家. 专家中间宽 2048, 隐藏宽 7168, SwiGLU 每个专家含门投影、上投影、下投影三块, 参数约

$$
3\times7168\times2048=44{,}040{,}192.
$$

每个 MoE 层的专家总参数约 $257\times44.04M=11.32B$. 60 个 MoE 层约 679B, 与整模 671B 略有出入, 原因包括报告配置中专家实现维度、共享方式、参数统计口径以及此处忽略或近似的细节. 这笔粗算的价值在数量级: 绝大多数总参数位于专家 FFN.

单 token 每层激活 8 个路由加 1 个共享专家, 专家参数约 $9\times44.04M=396M$. 60 层约 23.8B, 再加注意力、首层 Dense FFN、嵌入和输出头, 得到论文所说约 37B 激活参数. 这也说明 37B 不能简单由 $671B\times9/257$ 精确得到, 因为全量部件不随路由稀疏.

### 11.2. 训练 FLOPs 的近似

Dense Transformer 常用每 token 约 $6P$ FLOPs 粗估训练, 其中前向约 $2P$, 反向约前向两倍. 对 MoE 应以激活参数为主, 但路由、注意力、共享嵌入、MTP、重计算和通信都让简单公式偏差. 用 $P_{act}=37B$ 与 14.8T token 粗算:

$$
6\times37\times10^9\times14.8\times10^{12}\approx3.29\times10^{24}\ \text{FLOPs}.
$$

除以 2664K GPU 小时, 平均每 GPU 约 $3.43\times10^{14}$ FLOP/s, 即 343 TFLOP/s. H800 的理论低精度峰值取决于稀疏口径和数据类型, 不能用单一标称数直接算 MFU; 粗算至少表明数量级合理. 论文的 MFU 统计使用更精细的模型 FLOPs 定义, 将通信时间也计入墙钟.

如果错误地用 671B 总参数套 $6PD$, FLOPs 会放大约 18 倍, 完全忽略条件计算. 反过来只算九个专家又会漏掉全量注意力. MoE 成本核算必须明确「总参数」「激活参数」和「实际算子 FLOPs」三种口径.

### 11.3. token 吞吐与训练天数

预训练 14.8T token 使用 2664K H800 GPU 小时, 平均单 GPU 吞吐约

$$
\frac{14.8\times10^{12}}{2.664\times10^6\times3600}\approx1543\ \text{token/s/GPU}.
$$

若持续使用 2048 张卡, 2664K GPU 小时相当于约 54.2 天; 4096 张卡约 27.1 天. 这是理想满载换算, 不包含研究消融与中断. 上下文扩展另用 119K GPU 小时, 约为主预训练的 4.47%; 后训练 5K 约为 0.19%.

按每卡每小时 2 美元计, 三段分别约 532.8 万、23.8 万和 1 万美元, 合计 557.6 万. 价格是假定租价乘 GPU 小时, 没有包含集群网络、CPU、存储、电力、人员以及失败实验. 它适合比较正式 run 的计算量, 不适合代表研发总投入.

## 12. 后训练边界与 R1 的双向关系

V3 Technical Report 的后训练使用 R1 系列专家模型生成部分推理数据, 但 V3-Base 又是正式 DeepSeek-R1 的底座. 时间与模型角色需要拆开: 内部已有推理专家为 V3 Chat 蒸馏数据; V3-Base 完成后, 更完整的大规模 RL 路线在其上产出 R1. 因此 V3 Chat 的强数学能力包含蒸馏所得的推理轨迹, 却不等于它经历了 R1 报告中的完整 RL 过程.

1.5M SFT 样本里推理与非推理数据的比例未公开. 样本条数也不等于 token 权重: 一条长数学推导可能抵得上多条短问答. 两个 epoch 意味着每条样本大约被看两次, 打包掩码阻止样本之间互相注意, 避免前一条回答泄露给后一条. 若只按 1.5M 条判断训练规模, 会忽略长度分布.

规则奖励在数学和代码上更可靠, 仍可能被格式与测试覆盖限制. 数学答案匹配只验证最终结果, 中间推理可以碰巧正确; 代码测试无法覆盖的边界条件可能被钻空子. 模型奖励覆盖开放任务, 又会继承裁判偏好. 带 CoT 的奖励模型训练希望它学会判分依据, 但生成一段看似合理的评语不保证判断正确. 应在对抗样本、长度偏差和风格变体上单测奖励模型.

GRPO 的组内标准化使奖励只在同题候选间比较. 若一组答案全对或全错, 标准差接近零, 有效策略梯度很弱; 高温采样提高候选差异, 也会制造更多低质量长回答. 推理专家经过几百步 RL 学会融合 R1 风格, 这个描述没有给组大小、温度、奖励权重和长度惩罚, 外部无法精确复现. 可确认的是蒸馏消融的端点收益, 训练配方仍有空白.

## 13. 联合消融矩阵

V3 的五项核心变化——偏置均衡、节点受限路由、MTP、FP8、DualPipe——分别作用于质量、通信、监督信号、数值格式和调度. 单项消融不能揭示交互. 一套最小矩阵可以先固定 BF16 与普通流水线, 比较 V2 路由和新路由, 再分别加入 MTP; 质量侧得到四格. 系统侧固定同一 checkpoint, 比较 BF16/FP8 与普通流水线/DualPipe, 得到另一组四格.

路由与 MTP 可能通过隐藏状态发生交互. MTP 改变主干表示, 进而改变专家选择分布; 新路由的偏置控制也许使这种变化更稳定. 应同时报告验证损失、专家负载与 MTP 接受率. 若 MTP 在 V2 路由下造成热点, 在偏置路由下消失, 两项组合收益就不能简单相加.

FP8 与 DualPipe 的交互来自算通比. FP8 加快 GEMM并减少通信字节后, 原先被计算遮蔽的通信可能暴露, 或原先的网络瓶颈得到缓解; 方向取决于具体张量. DualPipe 在 BF16 下的提升比例不必等于 FP8 下的提升比例. 固定模型和 batch 分别测四种组合, 才能计算调度在两种精度下的边际贡献.

节点限制与偏置均衡同样耦合. 偏置按专家负载更新, 节点筛选却先决定专家有没有参选资格. 某专家本身偏置很高, 所在节点得分仍可能不够进入候选. 理想控制器应同时观察专家级和节点级负载. 若只追专家均衡, 可能出现每个专家长期平均相近、某些节点在短窗口仍过热. 报告的节点受限策略与部署冗余共同处理这一问题, 缺少逐项对照.

## 14. 一组反例和适用边界

无辅助损失路由的反例是数据分布快速交替. 连续若干 batch 全是代码, 偏置把代码专家压低; 紧接着回到均匀数据, 控制器尚未恢复, 普通 token 被迫绕路. 随机混合数据可缓解这种滞后, 在线微调或课程学习更容易触发. 观察切换后的 loss、偏置恢复时间与专家选择重合率即可验证.

sequence-wise 均衡的反例是本来就应高度专门化的长序列. 一份纯 Python 文件让大多数 token 选择代码专家十分合理, 强迫它覆盖很多专家可能伤害质量. 极小系数意在只处罚极端塌缩. 扫描系数并按领域测 loss, 能找到均衡与专门化的转折点.

FP8 的反例是大量离群值均匀散布到每个量化块. 分块尺度失去隔离作用, 普通值精度普遍下降. 人工构造不同离群密度的激活, 测 GEMM 相对误差和后续层放大倍数, 可以判断块大小 128 的安全范围.

MTP 的反例是下一 token 与更远 token 都接近随机的高熵数据. 额外目标只增加噪声, 接受率低, 推测解码还要支付验证成本. 对代码、数学、对话、随机字节分别测 MTP loss 与接受率, 应出现明显领域差异. 若所有领域接受率几乎相同, 反而要检查统计是否混入 teacher forcing.

DualPipe 的反例是计算与通信争夺同一内存带宽, 或 micro-batch 太小导致核启动开销占主导. 此时重叠可能降低单项效率. 对 batch、序列长度和节点数做二维扫描, 画出吞吐而非只报一个最大点, 才能界定适用区间.

## 15. 如何读 V3 的「经济」

V3 的训练成本低来自多层组合. MoE 让 671B 容量只激活约 37B; FP8 提高矩阵乘吞吐并降低通信量; DualPipe 隐藏专家通信与流水线气泡; 无辅助损失均衡减少热点和 token 丢弃; MTP 用少量额外计算改善表示, 还可能加速推理. 其中任何一项都无法独自推出 557.6 万美元这个端点.

这个数字还有明确分母: 14.8T 预训练 token、119K GPU 小时上下文扩展、5K GPU 小时后训练, 硬件按 H800、单价按每小时 2 美元. 更换租价只改变美元数, 不改变 GPU 小时; 更换硬件则连 GPU 小时也会变化. 比较另一模型时, 最稳妥的是先比 token、激活参数、精度、GPU 类型与利用率, 再看名义金额.

推理成本也不能由训练成本推出. 671B 权重即使用低精度仍需大量设备, decode 推荐单元达到 320 卡. MLA 显著降低每请求缓存, MoE 权重却分散在众多专家上, 小并发时每个专家 GEMM 很薄, 访存占主导. V3 适合用大规模并发摊薄权重与通信; 单用户、本地部署和低流量服务面对的是另一条成本曲线.

## 16. 可复核结论

第一, V3 对 V2 最关键的继承是 MLA 与细粒度共享专家 MoE. 模型总容量升到 671B, 单 token 激活约 37B, KV 缓存仍是每层每 token 576 个元素. 架构规模改变很大, 长上下文缓存公式却保持稳定.

第二, 负载均衡的实质变化是把主控制信号从损失梯度移到专家选择偏置. 偏置参与排名、不参与输出权重; sequence-wise 小损失仍在. 「无辅助损失」若理解成训练目标里完全没有任何均衡项, 会读错论文.

第三, FP8 是按 tile 和 block 缩放的大矩阵乘路径, 配合高精度部分和、主权重与优化器状态. 小模型长程对照与正式训练稳定性共同支持其可行, 仍缺一条同规模 BF16 平行 run, 这在成本上也很难实现.

第四, MTP 同时是训练辅助目标和推测解码草稿头. 训练收益来自额外未来监督, 推理收益取决于连续候选接受率. 85% 到 90% 的第二 token 接受率不能直接等同于相同比例的端到端加速.

第五, DualPipe 通过双向流水线和计算通信重叠减少等待, 节点受限路由缩小跨节点扇出. 它们改变调度, 没有消除通信数据. 当网络延迟超过可遮蔽窗口, 气泡仍会出现.

第六, V3 Chat 的推理能力包含来自 R1 系列专家的蒸馏, 正式 R1 又从 V3-Base 开始大规模强化学习. 这是一段双向谱系, 不能用一句「V3 在 R1 之前」或「V3 来自 R1」概括全部训练关系.

V3 把一组看似分散的改动压到同一个目标上: 让超大 MoE 在既定硬件上稳定吃完 14.8T token. 路由偏置管专家负载, 节点限制管通信扇出, FP8 管矩阵乘与带宽, DualPipe 管时间轴, MTP 管每个训练 token 提供多少监督. 它最值得细读的地方正是这些约束如何咬合, 而不是某一个榜单分数.

## 17. 路由负载的进一步手算

V3 每个 token 选择 8 个路由专家. 假设一个全局 batch 含 $T$ 个 token, 总分派次数为 $8T$, 256 个专家的平均负载为 $T/32$. 当 $T=16384$ 时, 平均每专家得到 512 次分派. 某专家收到 640 次, 过载率为 25%; 若容量严格按平均值配置, 多出的 128 次必须等待、转移或丢弃. 无辅助损失偏置的目标是让这种差距在容量约束生效前收敛.

随机均匀路由本身也不会让每个专家恰好收到 512 次. 若把每次选择近似看成独立伯努利事件, 单专家负载方差约为 $8T\cdot(1/256)(255/256)$, 标准差约 22.6. 640 次比均值高出约 5.7 个标准差, 很难由随机波动解释; 540 次却可能只是正常起伏. 控制器若对每一点微小偏差都用同样步长修正, 会追逐采样噪声, 因而实际负载统计通常需要在较大 token 集合或滑动窗口上观察.

节点层面也可复算. 若 256 个专家均匀放在 32 个节点, 每节点 8 个专家. 每 token 最多访问 4 个节点, 跨节点发送副本上限为 4, 节点内再分给若干专家. 若 Top-8 恰好在四个节点中各有两个, 没有替换; 若分散在八个节点, 至少四个全局高分专家会失去资格. 受限路由的真实代价取决于专家分数在节点上的聚集程度, 只报节点上限不足以推导质量损失.

共享专家始终激活, 不参与路由均衡. 它的流量等于整个 batch, 比任一路由专家的平均流量高约 32 倍. 训练系统可以专门放置或复制共享专家, 否则它会成为固定热点. decode 部署把共享专家视作必选路由专家并放到冗余卡上, 正是因为训练中的「逻辑共享」最终要落实为物理数据流.

## 18. FP8 误差怎样穿过残差网络

设某层理想输出为 $F(h)$, FP8 路径多出误差 $e$, 残差更新为 $h'=h+F(h)+e$. 下一层归一化会削弱整体尺度误差, 却不会自动消除方向误差. 若误差在各层近似独立、均值为零, 累积范数可能按层数平方根增长; 若量化偏差在某些通道方向一致, 则可能近似线性累积. 这也是逐层余弦相似度比只看最终 loss 更敏感的原因.

MoE 让误差传播多了一道离散门槛. FP8 扰动路由 logit 后, 排名第八与第九的专家可能交换. 专家函数差异较大时, 很小的 logit 误差会变成较大的输出变化. V3 将门控相关计算保留较高精度, 可以避免量化直接作用于这道边界; 专家内部 GEMM 使用 FP8, 其误差仍会进入残差. 一套针对性测试应分别量化门控、专家和注意力, 比较专家选择重合率.

缩放因子的估计也有时间维度. 当前 batch 的最大值若直接决定尺度, 偶发离群会让尺度剧烈跳动; 使用历史窗口或延迟缩放更平滑, 又可能跟不上分布突变. V3 的细粒度分组减少每个尺度覆盖的元素数, 让局部统计更贴近当前块. 若数据突然切换领域, 各专家激活分布变化, 缩放策略仍需及时响应.

训练稳定还要区分「不溢出」与「精度足够」. 一个 FP8 run 可以全程没有 NaN, 最终损失却稳定地比 BF16 高一点. 附录对照用于测后一种差异, 溢出日志用于测前一种故障. 二者缺一不可. 正式训练顺利完成证明数值范围受到控制, 小模型 BF16 对照则说明质量差在报告精度内很小.

## 19. MTP 的信息量视角

标准下一 token 损失估计条件熵 $H(X_{t+1}\mid X_{\le t})$. MTP 模块在拿到真实 $X_{t+1}$ 后估计 $H(X_{t+2}\mid X_{\le t+1})$. 从数据标签看, 每个位置多提供一个监督项; 从条件信息看, 第二项与把序列平移一位后的标准目标相似. 它的特殊之处在于额外目标通过独立模块回传到同一个较早的主干表示 $h_t$, 迫使 $h_t$ 对更远预测仍有用.

如果 MTP 模块容量过大, 它可能主要依靠真实 $x_{t+1}$ 的嵌入和自己的 Transformer block 完成预测, 回到主干的有效信号很弱. 模块太小又无法利用额外条件, MTP loss 居高不下. 消融不仅要比较最终基准, 还应测冻结主干后 MTP 头能学到多少, 以及切断 MTP 到主干的梯度后收益是否消失. 后者若仍有同样收益, 说明提升可能来自更多参数或训练扰动, 而非多 token 表示学习.

推测解码的接受概率还受采样设置影响. 贪心解码时, MTP 候选只要与主模型验证分布的最大概率 token 一致即可; 温度采样需要保持目标分布, 验收规则更复杂. 报告的 85% 到 90% 应连同任务分布、温度和验收算法理解. 长代码中局部语法强, 接受率可能较高; 开放写作的下一句分支多, 接受率可能下降.

若每轮验证两个位置的计算成本为普通一步的 $c$ 倍, 平均前进 $1+p$ 个 token, 理想加速是 $(1+p)/c$. 取 $p=0.85$, 若批量验证使 $c=1.2$, 上限约 1.54 倍; 若实现开销令 $c=1.6$, 只剩约 1.16 倍. 接受率是必要指标, 验证成本才决定最终速度.

## 20. 成本表还能推出什么

上下文扩展 119K GPU 小时若仍使用同样数量的 H800, 相当于预训练成本的 4.47%. 它处理的 token 量远少于 14.8T, 单 token 成本却更高, 原因是序列从 4K 拉长后注意力计算和激活显存增加. MLA 缓解解码缓存, 训练注意力仍需处理更大的序列矩阵; 长上下文训练不会按 token 数与 4K 阶段等价计价.

后训练 5K GPU 小时只占正式训练的 0.18%, 但这不包含生成 SFT 数据、训练专家模型、奖励模型推理与拒绝采样的全部外部成本, 报告表格统计的是 V3 正式阶段. 若将数据生成调用也折成 GPU 小时, 后训练链条会更大. 因此「5K」能说明策略更新本身很短, 无法说明后训练数据便宜.

按 14.8T token 与 1.5M SFT 样本比较也会产生错觉. 预训练以 token 计, 后训练以样本计; 一条样本可能含数千 token 并训练两个 epoch. 缺少总 SFT token 时, 不能直接求两阶段数据量比例. 5K GPU 小时给出计算比例, 仍混合了序列长度、采样和模型并行差异.

成本的另一面是失败风险. 一次 14.8T run 若在末期因数值或路由问题回滚 1%, 就是约 26.6K GPU 小时, 已超过后训练五倍. 无辅助损失均衡、FP8 稳定策略和 checkpoint 机制的价值不只体现在峰值吞吐, 也体现在减少重跑. 报告没有把「避免的失败成本」单独量化, 全程无需回滚仍是很重要的工程结果.

## 21. 从预训练到部署的一条数值链

把正式训练配置串起来, 每个 batch 有 15360 条 4K 序列, 即约 62.9M token. 14.8T token 若全部使用该 batch, 约需 235240 步; 前 469B token 处于 batch warmup, 实际总步数更高. 偏置更新速度为 0.001 时, 一百步累计变化上限为 0.1, 相当于约 6.29B token 的观测窗口. 路由控制响应的是数十亿 token 尺度的稳定偏差, 不适合追逐单个小 batch 的偶然热点.

每一步的 62.9M token 会产生约 503M 次路由专家分派. 均匀情况下, 每个专家约接收 1.97M 次. 如此大的样本数让全局负载估计很稳定, sequence-wise 损失则照看单条 4K 序列内部的偏斜. 二者恰好工作在不同统计尺度: 偏置根据大批量吞吐调节物理负载, 小辅助项防止某条序列把表示集中到极少专家.

4K 预训练完成后, 上下文扩展用更长序列继续优化 RoPE 位置路. MLA 每 token 缓存维度不随窗口增加, 总缓存仍与长度线性增长; 注意力训练的计算却会随序列长度更快增长. 119K GPU 小时看似只占主训练一小部分, 每个长序列 token 的计算代价已经不同. 这也是成本表将上下文扩展单列的原因.

进入 SFT 后, 1.5M 样本训练两个 epoch. 推理样本携带更长的解答轨迹, token 占比可能显著高于样本占比. MTP 辅助头在推理部署时可以保留作草稿, 主干权重则已经吸收额外预测目标. RL 只花 5K GPU 小时, 主要重排已有行为, 无法替代 14.8T token 预训练形成的知识和表示.

部署时, 权重容量决定需要多少设备, MLA 决定每条长请求追加多少状态, MoE 路由决定每步跨多少节点, MTP 接受率决定一次验证能前进几个 token. 训练期五项设计到了服务期各自对应不同资源. 只看 37B 激活参数会低估权重驻留与通信, 只看 671B 总参数又会高估每 token 矩阵乘, 只看 576 维缓存则会漏掉专家权重的物理分布.

## 22. 哪些实验会直接推翻当前解释

若在固定数据、固定计算下, 新路由的主任务损失与 V2 辅助损失路由相同, 但负载方差更大、丢弃更多, 「偏置控制改善均衡」就不成立. 若负载更均匀而质量下降, 则它实现了系统目标, 代价是专家选择受扰; 需要重新选择偏置速度或节点限制.

若 FP8 与 BF16 在短跑中接近, 训练长度增加后差距持续扩大, 小模型附录不足以支持长程稳定. 若误差集中在路由边界, 保留门控高精度仍不够; 还要检查进入门控的隐藏状态是否已受前层量化影响. 若逐层误差不累积而最终任务下降, 问题更可能出在少数决策敏感样本.

若切断 MTP loss 到主干的梯度后, 基准提升依旧存在, 「额外未来监督改善主干表示」需要重审. 若接受率很高而端到端速度没有提升, 瓶颈位于验证、调度或缓存写入. MTP 的训练价值与推理价值应分别测量, 任一失败都不会自动否定另一项.

若关闭 DualPipe 后通信字节相同、GPU 利用率和吞吐也相同, 原调度没有遮住有效等待; 若小规模有收益、大规模消失, 网络或内存带宽已越过可重叠区间. 调度收益必须用时间线和墙钟吞吐证明, 仅凭理论气泡公式不够.

若 MHA 与 MLA 在新路由下差距明显大于旧路由, 两项架构存在交互, V3 的消融便不能逐项相加. 若四格交互接近零, 可以分别优化缓存与路由. 这类结果决定后续模型该联合搜索参数, 还是独立替换组件.

这些反证条件把 V3 的结论落到可观测量: loss、专家负载、路由重合率、逐层数值误差、MTP 接受率、流水线气泡与墙钟吞吐. 任何一个总榜单都无法替代它们. V3 报告已经公开了许多端点和小规模消融, 剩余问题集中在组件交互与规模外推, 这也是复现时最值得保留日志的部分.

还有一个贯穿各项实验的控制变量: 数据顺序. 路由偏置会记住近期负载, FP8 缩放会适应近期数值范围, 学习率与 MTP 权重又按 token 位置变化. 即使两次训练使用同一份数据, 打乱顺序也可能改变专家形成、量化误差和辅助目标所处的学习率区间. 严格消融应复用样本顺序与随机种子, 或至少运行多个种子并报告离散程度. 否则零点几分的差距可能来自训练轨迹, 很难归因于被替换的组件.

检查 checkpoint 也应覆盖训练中段与收尾阶段. 某项设计可能早期加快收敛, 终点被基线追平; 也可能前期相同, 到低学习率阶段才显出稳定性. 只比较终点无法区分「提高数据效率」和「改变最终上限」. 对 MTP、FP8 与路由控制分别画出同 token、同 GPU 小时的验证曲线, 才能回答它们究竟省了什么.
