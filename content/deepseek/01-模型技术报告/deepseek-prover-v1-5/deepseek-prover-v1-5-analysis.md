# DeepSeek-Prover-V1.5: 证明助手反馈, 截断续写和好奇心搜索

来源: [DeepSeek-Prover-V1.5: Harnessing Proof Assistant Feedback for Reinforcement Learning and Monte-Carlo Tree Search](https://arxiv.org/abs/2408.08152)(arXiv: 2408.08152v1, 2024-08-15, 后收入 ICLR 2025). 仓库: https://github.com/deepseek-ai/DeepSeek-Prover-V1.5.

V1 用 **800 万**条合成语句把 7B 模型在 Lean 4 miniF2F-test 上推到 50.0%, 靠的是一遍写完整段证明. V1.5 没有换骨架, 参数仍是 7B, 改动落在四个地方: 继续预训练时加入形式语言, SFT 数据里插入自然语言 CoT 注释和 tactic 状态注释, 用 Lean 的 0/1 验证结果做 **GRPO**(报告叫 **RLPAF**), 推理时把整证生成接进蒙特卡洛树搜索并配上内在奖励(**RMaxTS**). 这四处互相依赖: 状态注释是树搜索续写的前提, 中等难度的提示筛选是 GRPO 能学到梯度的前提, 大规模 CPU 验证集群是一切大预算数字的前提. miniF2F 上的结果同时依赖这条训练与搜索链, 不能单独归因给其中一个环节.

## 1. 训练流水: 预训练, SFT 与 RLPAF

### 1.1. 问题: 整证生成看不见中间状态

形式证明模型大致分两类. 逐步生成每次只写一条 tactic, 交给 Lean 执行, 拿回新的证明状态再写下一条, 通常配树搜索, GPT-f, ReProver, HTPS, InternLM2-StepProver 都属于这一类. 整证生成一次写完整段证明代码再交给 Lean 验证, 失败就重采样, DSP, LEGO-Prover 和 V1 属于这一类. 前者每步都能看到真状态, 但模型和验证器之间来回通信很多; 后者通信少, 却要在看不到中间状态的情况下预测一长串 tactic.

报告把后者的毛病归结为误差累积(compounding errors): Lean 的 tactic 模式是一步步改写证明状态, 模型对某个中间状态「脑补」错了, 后面每一行都建立在错的状态上. V1 的证明普遍很短, 主要靠 `nlinarith`, `simp_all` 这类高层 tactic 收尾, 一旦题目需要多层中间结论, 这个毛病就暴露出来. V1.5 想要的是: 保留整证生成的低通信成本, 同时在出错时能拿到真状态, 从出错的地方接着写, 而不是从定理陈述重开.

### 1.2. 起点: 继续预训练, 骨架不变

V1.5-Base 从 DeepSeekMath-Base 7B 继续预训练, 语料是高质量数学和代码, 重点放在 Lean, Isabelle, Metamath 这些证明助手用的形式语言(源文 §2.1). 报告没有给出这轮预训练的 token 数、学习率、数据配比以及各形式语言的占比. 可见的效果只有一个数: Base 用 3-shot 提示在 miniF2F-test 上 Pass@128 为 29.7%, 6400 次采样到 42.2%. V1 报告表 1 里 DeepSeekMath-Base 同样 128 次采样是 27.5%, 两者预算相同, 续训只带来约 2 个点. 两边的 few-shot 示例来源可能不同, V1.5 用的是 Yang(2023) 的人写证明, 所以这 2 个点也不全是权重的功劳. 相比之下 SFT 一步把 Pass@128 抬到 50% 上下, 形式证明能力主要是 SFT 数据给的, 继续预训练更像是把形式语法的底子打平.

报告也没有通过消融说明 Isabelle 和 Metamath 语料能否改善 Lean 证明. 三种语言的语法和 tactic 体系差别很大, 可能迁移的是「目标-假设-变形」这类证明结构, 具体贡献无法从现有实验中分离.

骨架方面, 这仍是 DeepSeekMath 那套 7B Dense decoder-only 结构, 报告没有提任何架构改动. 这点决定了整条技术路线的形状: 参数不变, 所以增益只能来自数据格式, RL 信号和推理时的搜索. 也因为模型小, 单卡 A100-40G 加 vLLM 就能跑采样, 真正的瓶颈落在 Lean 验证上, 后面树搜索那一节会看到, 验证要数千个 CPU 核.

### 1.3. 训练数据: CoT 注释和 tactic 状态注释

SFT 数据的定理来自 Mathlib4, V1 和 Lean Workbook 的合成语句, 以及 miniF2F 和 ProofNet 的**验证集**, 再用 expert iteration 滚出证明: 生成, 验证, 拿通过的回训, 再生成(源文 §2.2). 每轮之间让 **DeepSeek-Coder-V2 236B** 给证明补自然语言注释, 最后得到 9,645k 条序列. SFT 训 9B token, batch 2,048, 恒定学习率 1e-4, 上下文 4,096. 用 9B 除以 9,645k, 平均每条约 930 token, 这是带注释之后的长度. 数据质量怎么筛, 可以对照 [SFT 数据质量筛选](../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md); 这里 Lean 编译器本身就是最硬的过滤器, 不需要另训质量模型.

注释分两种. 第一种是 CoT: 在证明块开头插一段完整的自然语言解法, 再在每条 tactic 前插对应步骤的说明, 和 Lean-STaR 每步前单独做 CoT 的思路接近, 区别是 V1.5 把推理直接写进代码注释. 训练时用两套引导提示区分 CoT 模式和 non-CoT 模式, 推理时可以任选. 第二种是 tactic 状态: 作者给 Lean REPL 接上 LeanDojo 的抽取工具, 拿到每条 tactic 的位置和执行前后的状态, 然后在合法证明里插入 `tactic state:` 注释. 训练时注释之后的 token 算 loss, 之前的当提示, 相当于一个「读懂当前状态再往下写」的辅助目标. 第二种注释是截断续写的地基, 没有它, 后面树搜索喂进去的状态注释模型根本不认识.

两种模式在输入上的区别只在第一行引导语. 附录 A 里 non-CoT 的提示是 「Complete the following Lean 4 code」, CoT 的提示是 「Complete the following Lean 4 code with explanatory comments preceding each line of code」, 后面跟相同的文件头: `import Mathlib`, `import Aesop`, `set_option maxHeartbeats 0`, 以及一串 `open`. `maxHeartbeats 0` 关掉了 Lean 的单步计算上限, 真正的时间约束只剩 300 秒的外部时限. 同一道 `aime_1983_p9`, non-CoT 输出两行 tactic 就结束; CoT 输出先写一段整体思路, 再在每条 tactic 前写一句说明, 长度是前者的好几倍. 这个长度差直接影响 2,048 token 上限下能写多长的证明, 也影响相同采样数下的推理成本, 报告的预算记号按「生成次数」计, 把这两种长度不同的生成当作等价.

有一点报告没有讨论: CoT 注释是 Coder-V2 写的, Lean 只检查代码, 不检查注释. 附录 B.2 的 `amc12_2000_p12` 就是例子, 注释里说「用一个引理: 三数之和有界则乘积有界」, 代码里并没有这样的引理, 真正干活的是 `interval_cases a <;> interval_cases m <;> interval_cases c` 把 13³ 种取值全部枚举一遍. 同一附录里 `numbertheory_x5neqy2p4` 的模 11 注释和代码是对得上的. 所以 CoT 注释有时是真规划, 有时只是事后的叙述, 报告把 CoT 模式的增益归因于「更系统的数学思维」, 这个归因没有做注释与代码一致性的检查.

### 1.4. RLPAF: 用 Lean 当奖励的 GRPO

RL 阶段的提示来自 SFT 数据, 只挑 SFT 模型多次尝试后成功率中等的定理, 最后留下约 4.5k 条, 每条同时配 CoT 和 non-CoT 两种引导(源文 §2.3). **奖励就是 Lean 验证的 0/1**, 不训练奖励模型. 算法采用 DeepSeekMath 提出的 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md): 每题采 32 条候选, 用组内相对得分当优势, 不需要 critic. 参考模型是 SFT 模型, KL 系数 0.02, 学习率 5e-6, 最大长度 2,048, batch 512. 报告未给训练步数和总 GPU 时间, 因而无法计算这一阶段的总训练成本.

中等难度筛选和 GRPO 的组内比较是配套的. 全对或全错的组, 组内优势全为零, 这一步什么也学不到; 只有一组 32 条里有对有错, 梯度才非零. 这比 DeepSeekMath 的处境简单得多: 那边用的是神经网络奖励模型, 要担心奖励被钻空子, 这边 Lean 验证几乎没有假阳性. 不过报告没有说明验证脚本如何拒绝 `sorry` 或其他绕过检查的写法. 按今天的叫法, 这就是 RLVR(可验证奖励的 RL), 比 R1 用规则奖励做大规模 RL 早了近半年.

奖励粒度覆盖整条证明. 一段证明包含十几条 tactic 时, 最后一条出错也会使整条序列得到 0 分, 正确前缀无法在训练中获得单独信用. GRPO 没有逐步信用分配; 推理阶段的截断续写保留成功前缀作为搜索节点, 部分弥补了这个缺口. CoT 模式还包含大段注释, 2,048 的最大长度对它更紧. 报告未给出截断比例以及 RL 前后的平均证明长度, 无法量化长度限制的影响.

### 1.5. RL 到底改变了什么

图 3 在 Pass@128 上比较各阶段: Base 29.7%, SFT non-CoT 49.8%, SFT CoT 50.4%, RL non-CoT 50.5%, RL CoT 51.6%. SFT 这一步涨了约 20 个点, RL 只再涨 1.2 个点(CoT 模式). 报告的论点是: 和 DeepSeekMath 里「RL 只是把 TopK 里的正确答案抬上来」不同, 形式证明上 RL 带来的是基础能力提升, 证据是采样预算加大后差距不消失. 表 3 支持这一点, 单遍 CoT 在 16×6400 预算下 SFT 57.4%, RL 60.2%, 差 2.8 个点, 反而比 128 次时更大.

表 1 把这个趋势摊得更开. 单遍 CoT 下 SFT 和 RL 在各预算的成绩: 32 次 48.2% 对 50.0%, 64 次 49.6% 对 50.7%, 128 次 50.4% 对 51.6%, 3200 次 53.3% 对 54.9%, 4×6400 次 55.8% 对 58.4%, 16×6400 次 57.4% 对 60.2%. 差距从 1 到 2 个点逐步拉到 2.8 个点, 采样越多 RL 领先越多. 这和 DeepSeekMath 的 Figure 7 方向相反, 那边 RL 只抬 Maj@K, Pass@K 不动. 一个可能的解释是奖励的性质不同: DeepSeekMath 用的是有噪声的神经奖励模型, 这里是几乎零噪声的 Lean 验证. Base 的曲线则更平: 128 次 29.7%, 3200 次 39.2%, 6400 次 42.2%, 多采样能涨, 但和 SFT 之间始终隔着十几个点.

这个论点有两处需要打折扣. 第一, 对照对象是 SFT, 不是 Base. 2025 年那篇讨论 RLVR 边界的论文(Yue 等)发现, 在自然语言数学上, 采样数足够大时 Base 的 Pass@k 会反超 RL 模型, V1.5 的 Base 只测到 6400 次, 42.2%, 离 RL 的 60.2% 还很远, 所以这里无法检验同样的现象, 相关讨论见 [RLVR 的局限与探索边界](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md). 第二, 「RL 在所有设定下都胜过 SFT」只在 miniF2F 上成立. 表 2 的 ProofNet 里, 单遍 4×6400 时 RL 在验证集 21.6% 低于 SFT 22.2%, 全集 22.6% 低于 SFT 22.9%; RMaxTS 1×3200 时 RL 全集 21.8%, SFT 21.9%. 仓库 README 的汇总表也把 ProofNet 上 SFT 列为 22.9%, RL 列为 22.6%. 4.5k 条 RL 提示来自 SFT 数据, 偏高中竞赛代数, 对本科级的实分析, 抽象代数题帮助有限, 这是一个合理的解释, 报告没有讨论.

后来的开源工作给了一个更直接的对照. 2025 年 2 月的 Goedel-Prover 把 Numina 的自然语言题目形式化成 **164 万**条 Lean 语句, 用 expert iteration 证出其中 80 万条以上, 然后只在 V1.5-Base 上做 SFT, 不做 RL, miniF2F-test Pass@32 就到 57.6%, 比 V1.5-RL 的 50.0% 高 7.6 个点, 3200 次采样时 62.7% 对 54.9%. 这说明在这个规模上, 语句覆盖面比 RL 那一两个点重要得多, V1.5 的 RL 增益是真的, 但在整条流水线里分量不大.

### 1.6. expert iteration 怎样扩大可证明数据

初始模型面对一批 theorem 采样证明, Lean 只保留通过者, 再把这些新 theorem-proof 对加入 SFT. 更新后的模型能证明更多题, 下一轮继续收集. 设第 $j$ 轮策略为 $\pi_j$, 数据池为 $D_j$, 则循环近似为:

$$
P_j=\{(x,y):x\in X,\ y\sim\pi_j(\cdot\mid x),\ \operatorname{Lean}(x,y)=1\},
\qquad D_{j+1}=D_j\cup P_j.
$$

这套循环把模型当前能力边界变成数据生成器. 容易题先得到证明, 模型从中学会 tactic 组合后再覆盖更难题. Lean 验证消除语法正确但逻辑错误的标签, 数据仍会偏向模型容易采样到的证明风格. 若模型偏爱 `nlinarith`, 数据池会继续放大这种风格.

去重也很重要. 同一定理可以有许多等价证明, 大量自动化变体可能占据训练 token, 却不增加新数学结构. 论文给出最终序列数, 没说明按 theorem、证明文本或状态轨迹怎样去重. 数据规模 964.5 万不能直接等同于 964.5 万种独立证明思路.

验证集 theorem 被用于 expert iteration 后, 对应 validation 分数不再是泛化指标. 论文对 ProofNet 明确标注, miniF2F 也只应看 test. 这种使用对训练数据扩展有价值, 但要求报告中把调参与最终测试分开.

### 1.7. CoT 注释的监督信号到底落在哪里

CoT 注释放在 Lean comment 中, tokenizer 仍把它们当普通文本. 若整条输出都计算 next-token loss, 模型同时学习自然语言解释与 tactic; 状态注释之前作为 prompt、之后 token 算 loss的辅助构造又形成条件续写数据. 不同样本格式会训练模型在看到特定引导时切换模式.

解释可能提供高层规划 token. 在生成 tactic 前先写「证明该式等价于平方非负」, 后续代码可以关注 `sq_nonneg`. 自回归模型把注释作为工作记忆, 将远处 theorem 压成局部计划. 即使注释不进入 kernel, 它仍改变后续 tactic 的条件概率.

错误注释也会成为噪声. Lean 只筛 proof, Coder-V2 生成的解释没有形式校验. 一段错误解释配正确代码, 模型可能学会语言与行动脱节. 论文没有对注释忠实率抽样, CoT 增益可能同时来自规划、长度、随机扰动和更多文本监督.

non-CoT 与 CoT 用不同提示, 形成两个条件分布. 混合推理覆盖更多题, 说明两种分布有互补支持集. 要证明自然语言推理本身贡献, 可做更严格对照: 保持 token 长度相近, 用空白或随机注释替换 CoT; 或只保留正确状态说明. 论文没有这些对照.

### 1.8. 二值奖励为什么既强又稀疏

Lean 通过是几乎无歧义的终局奖励. 相比神经 verifier, 它不会因文风或表面合理给错分, 也很难被普通语言 reward hacking. 只要 theorem 没有漏洞、环境禁用 `sorry` 等逃逸, reward 直接对应形式正确.

稀疏性来自长证明只有终局信号. 一组 32 条全失败时, 组内优势为零; 全成功也没有相对差异. 假设单次成功率为 $p$, 一组同时含正负样本的概率是:

$$
1-p^{32}-(1-p)^{32}.
$$

当 $p=0.5$ 时几乎为 1; 当 $p=0.001$ 时约 3.15%; 当 $p=0.999$ 时也约 3.15%. 中等难度筛选就是把训练提示放到有效区间.

这种筛选改变训练分布. 极难题因没有正样本被排除, 极易题因没有负样本也被排除. RL 学到的是边界题上哪些证明更容易通过, 不直接覆盖超出模型探索支持的难题. 后续更强数据或子目标分解能把新题移入中等区间, 再使用 RL.

KL 系数 0.02 防止策略过快收缩. 二值奖励可能让模型集中到少数高成功 tactic, 多样性下降会伤害 pass@大 $k$. 表中 RL 在大预算仍领先 SFT, 说明至少在该实验里没有简单塌缩; 缺少 entropy、unique proof 与长度统计, 无法观察分布具体怎样变化.

### 1.9. 继续预训练、SFT 与 RL 的职责分界

继续预训练让模型熟悉 Lean、Isabelle、Metamath 语法和数学代码分布, 目标仍是 next-token prediction, 不要求证明通过. SFT 用经过 Lean 验证的 theorem-proof 对告诉模型可行轨迹. RL 再用在线 sample 的通过结果调整概率, 强化当前策略偶尔发现的正确证明.

三阶段的增益尺度不同. Base 到 SFT 约 20 点, SFT 到 RL 约 1–3 点, 搜索再按预算增加数点. 这说明能力主体来自大规模验证 SFT, RL 与搜索在其上挖掘尾部. 若缺少 SFT, 稀疏 RL 很难从几乎全错的组获得信号; 若缺少预训练, SFT 要先纠正大量形式语法.

这条分工也解释后续工作为什么能只用 SFT 超过 V1.5. 更广 theorem 和更强 expert iteration直接扩大可证明支持集, 其收益可能大于在原 4.5k 边界题上继续优化. RL 仍有价值, 但它不是替代数据覆盖的捷径.

## 2. Lean 证明状态与整证生成

### 2.1. 定理证明在 Lean 中是什么状态转移

Lean 中的定理声明给出目标命题, tactic 执行后把当前目标改写为零个或多个子目标. 一个证明状态可抽象为:

$$
s_t=(\Gamma_t\vdash g_{t,1},\ldots,\Gamma_t\vdash g_{t,m}),
$$

$\Gamma_t$ 是局部变量、假设与可用定义, $g_{t,i}$ 是尚未完成的目标. tactic $a_t$ 交给 kernel 与 tactic engine 后, 得到 $s_{t+1}=T(s_t,a_t)$. 若 tactic 不适用、类型不匹配或超时, 转移失败; 当目标列表为空时, Lean 接受证明项.

这个状态与普通自然语言推理不同. 一句解释可以大致正确, tactic 必须在精确类型与上下文中合法. `nlinarith` 可能一次关闭目标, `constructor` 会把合取拆成两个目标, `have h : P := ...` 会增加局部事实. 模型要跟踪的不只是结论, 还有变量类型、命名、可见假设和当前焦点.

Lean 的 kernel 检查最终证明项, tactic 是构造证明项的程序. 验证通过意味着在当前 Lean 版本、导入库与选项下类型检查成功. 它保证形式语句被证明, 不保证形式语句忠实表达原始自然语言题目. miniF2F 已经提供形式化 theorem, V1.5 主要解决 proof synthesis, 没有评估自动形式化正确性.

### 2.2. 整证生成为什么缺少真实状态

整证模型看到初始 theorem, 一次生成完整 `by ...` 代码. 在生成第 $t$ 条 tactic 时, 它没有实际运行前 $t-1$ 条, 只能从 token 前缀推测 Lean 会得到什么状态. 若前面 tactic 产生了意外子目标、名称不同或类型化简方式不同, 后续代码建立在错误心智状态上.

设模型内部预测状态为 $\hat s_t$, 真实执行状态为 $s_t$. 即使 $a_t$ 对 $\hat s_t$ 合法, 也可能不属于真实合法动作集 $\mathcal{A}(s_t)$. 一旦失败, 后续 token 仍以文本中的错误动作作条件, 整段通常无法恢复. 这就是 compounding error 在形式证明中的具体形态.

逐步 prover 每次只生成一个 tactic, 立即得到 $s_{t+1}$. 它不需要长期脑补状态, 代价是模型—Lean 往返频繁, 每一步都要调度与验证. 整证生成用较少交互换取更长开环控制. 截断续写把两者组合: 先开环走多步, 出错后从最后真实状态闭环纠正.

整证模式还有搜索粒度优势. 一次 sample 可以包含一个完整数学思路, 高层 tactic 会在内部完成大量推理. 逐 tactic 搜索更容易组合局部动作, 也可能在浅层分支迅速膨胀. 哪种方式更好取决于模型能否生成长合法前缀、tactic 自动化强度与 Lean 验证成本.

### 2.3. tactic state 注释提供了什么

状态注释把 Lean 返回的目标以文本形式插入 prompt, 使模型直接条件化真实 $s_t$. 例如当前上下文包含 $h:0<x$、目标为 $12(x\sin x)\le 9(x^2\sin^2x)+4$, 模型可识别右减左等于平方, 再生成 `nlinarith [sq_nonneg ...]`. 状态文本连接了形式 kernel 与语言模型.

状态序列也构成训练监督. 在合法证明的每条 tactic 前后抽取状态, 模型学习「给定 theorem、已验证前缀和当前目标, 下一段代码是什么」. 截断续写时输入格式与 SFT 中的状态注释接近, 减少训练—推理分布差异. 若只在推理时突然加入状态文本, 模型可能把它当普通注释而不会利用.

状态注释不是完美的 Markov 状态. tactic 行为还依赖环境中的导入、namespace、attribute、局部 notation、options 与 elaborator 状态. 论文给每题固定文件头, 在 miniF2F 范围内文本状态足够实用. 扩展到大型 Lean 文件时, 当前目标之外的环境依赖会更复杂.

状态文本还可能很长. 多个子目标、复杂类型和大量局部假设会占用 2048 token 生成预算. 截断前缀、CoT 注释与状态一起增长, 留给新证明的空间缩小. 论文没有报告 prompt 长度分布和上下文截断策略, 长证明外推边界不明.

### 2.4. 合法状态、等价状态与重复搜索

不同 tactic 序列可以到达相同目标集合. `simp [h]` 与若干 `rw` 可能得到等价状态, 变量名和表达式正规形又可能不同. RMaxTS 需要判断「新状态」, 若只按原始字符串去重, alpha-renaming 或 pretty printer 差异会被当成新奇; 若做过强正规化, 可能合并仍有不同局部环境的状态.

论文说明同一状态节点可以存多条等价 tactic 代码, 表明实现做了状态合并. 官方代码负责从 LeanDojo/REPL 抽取状态并维护树. 公开报告没有完整形式化状态等价关系. 因而内在奖励的有效性也依赖工程中的状态键: 键太细会奖励伪新奇, 太粗会丢失真实分支.

失败状态同样有信息. 语法错误、unknown identifier、tactic failed 和 timeout 指向不同问题. 截断续写主要保留第一条错误之前的成功前缀, 把最新合法状态作为恢复点, 并没有把错误类型作为显式奖励或 critic. 模型可能从代码与状态推断, 搜索器本身只看是否加入新节点和是否完成证明.

### 2.5. 证明正确、证明短与证明可读是三件事

Lean 0/1 奖励只关心是否通过. `interval_cases` 穷举、强自动化 tactic 与结构清晰的引理链都可能同得 1. 这使 RL 信号客观且难被自然语言奖励模型误判, 同时不奖励简洁、可维护和数学解释一致.

CoT 注释不进入 kernel, 错误解释不会阻止代码通过. 注释可能帮助模型规划, 也可能是事后包装. 若评估目标是机器可验证证明, 通过率足够; 若目标还包括人类教学与库维护, 需要额外检查注释忠实、证明长度、依赖与 tactic 鲁棒性.

`set_option maxHeartbeats 0` 允许高成本自动化一直运行到外部 300 秒超时. 一段短代码可能消耗大量 Lean 搜索, token 短不等于验证便宜. 证明效率应同时报告生成 token、Lean 时间和 kernel term 大小. 论文主要按生成次数与成功率比较, 没有给这些维度.

### 2.6. 用一个小例子走过状态变化

考虑 theorem: 对实数 $x$, 若 $h:x=3$, 证明 $x^2=9$. 初始状态可写为:

$$
x:\mathbb{R},\ h:x=3\ \vdash\ x^2=9.
$$

执行 `rw [h]` 后, Lean 用等式重写目标, 得到 $\vdash 3^2=9$. 再执行 `norm_num`, 目标关闭. 逐步 prover 在第一步后直接看到新状态; 整证模型要生成 `rw [h]` 时预想重写结果, 再决定 `norm_num` 可用.

如果模型误写 `rw [← h]`, Lean 可能把目标中的常数 3 反向改成 $x$, 产生与预期不同的式子或找不到匹配. 整证后面的 `norm_num` 仍会被生成, 最终验证失败. 截断续写定位到错误行, 保留此前合法前缀, 把真实目标插回 prompt, 新 rollout 可以改用 `norm_num [h]` 或正确重写.

再看会分叉的 `constructor`. 目标 $P\land Q$ 执行后变成两个 goals. 模型若只记住第一个, 写完 $P$ 就提前结束, Lean 仍显示 $Q$. tactic state 注释把全部未完成目标列出来, 比自然语言 CoT 更可靠. 这也是状态监督对多目标证明尤其有价值的原因.

### 2.7. 高层 tactic 把搜索藏到了哪里

`simp`, `aesop`, `linarith`, `nlinarith` 和 `omega` 内部会做重写、规则搜索或决策过程. 模型输出一个 token 序列动作, Lean 内部可能探索大量候选. V1.5 的外层树只看 tactic 前后状态, 看不见内部搜索树.

高层 tactic 降低模型动作长度, 也把算力转移到 CPU verifier. `nlinarith` 处理算术题很强, 对不适用目标会失败或耗时. 模型学习何时调用哪个 tactic, 相当于学习搜索算法的调度. 这部分能力可以通过 SFT 大量成功 proof 获得.

pass@k 因此不只衡量数学规划. 它还衡量模型记忆 tactic 语法、选择自动化、提供必要引理和避免超时. 一个证明用一行自动化通过, 可能比十行人工式 proof 更容易采样, 也更依赖 Mathlib 与 tactic 实现版本.

### 2.8. Lean 版本与库版本为什么进入实验定义

Lean elaborator、tactic 和 Mathlib lemma 会随版本变化. 同一代码在 4.7 与 4.9 可能因名称、类型推断或 tactic 行为不同而通过或失败. V1 与 V1.5 使用的环境不同, 直接把分数差全归模型不严谨.

benchmark 转换从 Lean 3 到 Lean 4 也可能改变语句与可用证明. 手工转换能修复语法, 仍需检查 theorem 语义等价. 报告没有发布逐题转换审计. 公开代码使后来者可以固定文件与 commit 重跑, 这是复现的必要条件.

few-shot 示例也属于环境. Base 在 ProofNet 使用 RL 生成的正确 proof, 相当于从后续模型获得 prompt 资产; SFT/RL 则零样本使用专用引导. 表格比较最终设置, 不是严格相同 prompt 条件的 checkpoint 对照.

## 3. 树搜索: 截断续写与 RMaxTS

### 3.1. 截断续写: 把整证拆成搜索树

**截断续写**(truncate-and-resume)的流程是: 模型照常写完整段证明, 交给 Lean; 全对就结束; 有错就在第一条错误处截断, 丢掉后面的代码, 把成功的前缀加上 Lean 返回的最新 tactic 状态注释, 作为下一轮的提示(源文 §1, §3.1). 截断出来的前缀按 tactic 切开, 每条 tactic 连同它前面的 CoT 注释构成搜索树的一条边, 代表一次状态转移. 这样整证生成就有了一个状态-动作接口, 树搜索可以挑任何一个节点续写, 不必只从最后一条成功的 tactic 往下接.

几个细节是为 Lean 的特点定制的. 不同 tactic 写法可以到达同一个状态, 所以每个节点存一组等价的 tactic 代码, 续写时随机抽一条当前缀. 一次扩展模型会写出多条 tactic, 所以一次扩展可能往树里插入一整条节点路径, 这和 AlphaZero 那类棋类 MCTS 每轮只扩一层不同. 选择阶段用了 virtual node: 每个节点带一个虚拟子节点, 选中它就表示「就在这里扩展」, 于是非叶节点也能被反复扩展. 这对生成模型是必要的, 因为同一个节点能续写出的内容没有上限, 不能像棋盘那样把合法着法列全. 附录 A 的 `aime_1983_p9` 展示了续写时模型看到的东西: 提示末尾的注释写着当前目标 `12 * (x * x.sin) ≤ 9 * (x ^ 2 * x.sin ^ 2) + 4`, 模型在 CoT 里把它整理成 $(3x\sin x-2)^2\ge0$, 最后一行 `nlinarith [sq_nonneg (3 * x * Real.sin x - 2)]` 收尾.

和纯逐步搜索相比, 这套接口每次扩展只调一次模型, 一次 Lean 验证, 却可能推进多步, 通信密度低得多. 代价是每次验证都要把整段前缀连同新代码一起交给 Lean 重新检查, 前缀越长, 单次验证越贵, 报告没有给单次验证的平均耗时. 和纯整证重采样相比, 它保住了已经验证过的前缀, 同一道题的第二百次尝试不必再从头写 `have h1 : 0 < x * Real.sin x`. 同一套训练目标既能单遍采样又能进树搜索, 报告把这当作方法的主要结构贡献(源文 §3.5), 部署时可以按算力在两者之间切换, 不用维护两套模型.

MCTS 的四步里, 模拟被并进了扩展: 整证生成模型从被选节点往下写到底, 本身就是一次 rollout. 回传时沿本轮的选择路径, 对每个 $(s,a)$ 更新两项统计: 经过它的轨迹数 $N(s,a)$ 和这些轨迹的奖励和 $W(s,a)$, 利用项取 $W/N$, 探索项是随访问次数衰减的 UCB 奖励. 式 4–6 是 UCB1 的原始写法, 实际采用的是式 7–9 的折扣版, 越早的轨迹权重越低. 外在奖励只有证完时的 1, 所以在找到证明之前, $W$ 全部来自下一节的内在奖励. 这里的「动作」包括虚拟节点代表的「就地扩展」, 所以一个节点被反复选中扩展, 统计也会累积在它的虚拟子节点上.

### 3.2. RMaxTS: 没有外在奖励时靠新状态指路

树搜索的外在奖励只有一种: 整题证完给 1, 否则 0. 证完之前所有节点的价值估计都是 0, 标准 UCT 此时只按访问次数挑节点, 和盲目展开差不多. **RMaxTS** 借用 RMax 的想法: 一次扩展只要往树里加了至少一个新节点(也就是看到了新的 tactic 状态), 内在奖励就是 1, 否则是 0(式 3). 证完之前轨迹奖励完全由内在奖励决定, 流程接近 ZeroRMax. 同一状态可以由多种代码到达, 奖励「新状态」而不是「新代码」, 能减少写法不同但状态相同的重复生成.

内在奖励有一个特点: 树越大, 越难碰到新状态, 奖励的期望随搜索进行不断下降, 是非平稳信号. 标准 UCB1 假设奖励分布不变, 靠大量访问逐渐收敛, 有限预算下, 早期积累的高奖励记录会一直压着估计值. 所以报告改用折扣 UCB(DUCB, 式 7–9), 每来一条新反馈, 旧记录按 $\gamma=0.99$ 衰减. 内在奖励和两种 UCB 分别写成:

$$
R_{\mathrm{intrinsic}}(\tau)=\mathbb{I}[\text{本次扩展至少向树中加入一个新节点}],
$$

$$
Q_{\mathrm{UCB1}}(s,a)=\frac{W(s,a)}{N(s,a)}+\sqrt{\frac{2\ln\sum_{a'}N(s,a')}{N(s,a)}},\qquad W=\sum_{\tau\in\Gamma(s,a)}R(\tau),\ N=|\Gamma(s,a)|,
$$

$$
Q_{\mathrm{DUCB}}(s,a)=\frac{W_\gamma(s,a)}{N_\gamma(s,a)}+\sqrt{\frac{2\ln\sum_{a'}N_\gamma(s,a')}{N_\gamma(s,a)}},\qquad W_\gamma=\sum_{t=1}^{N(s,a)}\gamma^{N(s,a)-t}R(\tau_t),\ N_\gamma=\sum_{t=0}^{N(s,a)-1}\gamma^t.
$$

$\Gamma(s,a)$ 是经过 $(s,a)$ 的所有轨迹. UCB1 的利用项是历史奖励的算术平均, 前一百次扩展都拿到新节点, 后一百次都没拿到, 均值仍是 0.5. DUCB 的 $W_\gamma$ 给第 $t$ 条轨迹乘 $\gamma^{N-t}$, 最近一条权重 1, 一百条之前约 0.37, 利用项变成近期奖励的加权平均, 上例会掉到约 0.27. $N_\gamma$ 是同一组权重之和, 上界是 $1/(1-\gamma)=100$, 访问再多也不超过 100, 所以探索项不会像 UCB1 那样随 $N\to\infty$ 趋于 0, 被冷落的分支总保有一份被重新选中的机会. 这两处合起来, 就是「新状态挖空的节点价值很快降下来, 让位给别处」的具体实现. 这里的折扣作用在搜索迭代轮次上, 不是单条轨迹内部的时间步, 和 MDP 里的折扣因子含义不同, 报告专门提醒了这一点.

这套内在奖励属于强化学习里基于计数和新奇度的探索家族, 报告引用了 Bellemare 等的伪计数和 Burda 等的 RND. 这类方法有一个老问题: 新奇不等于进展. 在证明搜索里, 一条 tactic 把目标改写成更复杂的形式, 或者引入一个无关的中间结论, 同样会产生新状态, 同样拿到奖励 1, 搜索会被引向这些方向. RMaxTS 没有任何机制区分「离证完更近的新状态」和「只是不一样的新状态」, 这正是结论节说缺一个 critic 的原因. 在 miniF2F 这种短证明为主的集合上, 这个问题不严重, 因为证明树本来就浅; 证明一旦变长, 无差别的新奇奖励可能会让树横向铺得很宽.

并行化决定了这套方法能不能跑起来(源文 §3.4). 每个计算节点起 256 个 MCTS runner, 每张 GPU 一个模型, 生成 batch 512; Lean 通过 REPL 调用, 跑在数千核的 CPU 集群上, 每次验证一个沙箱进程, 生成和验证都是异步的. 每棵树 32 个线程并发做选择-扩展-验证-回传, 进行中的迭代先回传虚拟奖励 0(virtual loss), 避免多个线程挤到同一节点. 报告没有给出总 CPU 核时和 GPU 时.

### 3.3. 截断点怎样决定可复用前缀

生成结果交给 Lean 后, 系统定位第一条失败 tactic. 失败前所有 tactic 已被验证, 可以作为树中的合法路径; 失败行及其后续全部丢弃. 若一条复合 tactic 内部部分成功后失败, 对外仍通常表现为该命令失败, 复用粒度受语法命令边界限制.

粒度太粗会丢掉复合 tactic 内部进展, 太细会增加状态数与验证交互. V1.5 以 tactic 位置切分, 借 LeanDojo 获取前后状态, 是源码结构与搜索成本之间的折中. 宏、`all_goals` 和组合符可能让一行改变多个目标, 文本行数也不等于一步逻辑推理.

前缀复用需要保证环境确定. 同一文件头、Lean 版本、Mathlib commit 和 options 下, 重放前缀应得到相同状态. 若 tactic 依赖超时、外部 oracle 或不同库版本, 缓存状态可能失效. 论文固定 Lean 4.9.0 与导入, 使 benchmark 内重放可控.

截断也能把超长失败证明压回最近合法点. 但 prompt 会包含前缀代码、注释和状态, 多次续写后仍可能接近上下文上限. 搜索器没有压缩形式证明语义的独立模块, 长文件需要更长上下文或结构化状态存储.

### 3.4. virtual node 为何允许反复扩展同一状态

开放文本动作空间不能预先枚举. 第一次从状态 $s$ 采样得到 `nlinarith`, 没有理由认为其他可行 tactic 已经穷尽. virtual node 相当于保留一个永远存在的「再问模型一次」动作, 被选择时生成新的候选.

真实子节点代表已发现状态转移, virtual child 代表尚未采样的潜在转移. UCB 统计决定是沿已有分支深入, 还是从某个旧状态再开新分支. 如果没有 virtual child, 一个节点首次展开后就封闭, 语言模型的随机性无法被持续利用.

virtual loss 用于并行. 某线程选择节点后先临时降低其吸引力, 其他线程倾向别处, 等验证返回再用真实奖励覆盖. 它提高树的并行多样性, 也可能让本应集中探索的强分支暂时被冷落. 论文给出 32 线程设置, 没有并发数消融.

### 3.5. 状态合并与路径依赖的张力

从 Lean 看, 两条代码前缀到达同一 proof state 后, 未来合法 tactic 集大体相同. 从语言模型看, prompt 中前缀文字、CoT 和命名不同, 后续分布可能不同. RMaxTS 将等价代码存到同一节点, 续写时随机选择一条前缀, 在状态合并与文本多样性之间折中.

如果只保留一条最短前缀, prompt 更省 token, 可能丢掉有用的自然语言计划. 如果所有前缀都建独立节点, 树会被同状态重复占满, 新奇奖励失真. 多前缀单状态让 Lean 语义去重, 同时保留若干模型上下文.

这种设计也说明搜索不是纯 MDP. 理论状态 $s$ 若只取 Lean goal, policy 还依赖达到它的文本历史 $h$. 更完整状态应是 $(s,h)$, 合并时忽略了部分 $h$. 实验显示这种近似有效, 没有证明对长证明同样成立.

### 3.6. DUCB 的有效记忆长度

$\gamma=0.99$ 时, 距当前 $k$ 轮的权重为 $0.99^k$. 约 69 轮后降到一半, 229 轮后约 0.1. 有效样本数上限 100, 意味着选择器主要反映最近数百次扩展, 不让早期容易获得的新奇永久支配.

探索项中的折扣计数也有上界, 已访问很多次的分支仍保留非零探索奖励. 对非平稳新奇信号合理, 对稳定外在成功概率则可能过度探索. 任务一旦找到证明立即停止, 没有长期利用已知成功分支的问题.

$\gamma$ 控制适应速度. 更小值更快忘记, 对噪声更敏感; 更大值更稳定, 节点挖空后转移慢. 论文固定 0.99, 没有 sensitivity study. 完整 RMaxTS 的优势可能依赖 benchmark 证明树尺度与这个有效窗口匹配.

### 3.7. 新状态奖励可能出现哪些反例

第一类是循环改写. tactic 在两个等价表达式间来回转换, 若状态正规化不足, 每次都可能被当新节点. 第二类是无关 `have`, 不推进主目标却扩充上下文. 第三类是目标爆炸, 一个 tactic 把一个目标拆成很多更难子目标, 仍因新状态得分.

Lean 会阻止非法动作, 不能判断数学进展. 计数新奇类似探索未知房间, 房间多不代表接近出口. miniF2F 中高层自动化常能从一个有用中间状态直接收尾, 新奇是尚可接受的代理; 大型库证明可能需要长时间沿一条看似不新奇的路径积累引理.

引入 learned critic 可估计从状态完成的概率, 但训练标签昂贵且可能偏差. 可用搜索回报训练 value, 又形成自举误差. V1.5 选择零 critic 的 RMax, 保持验证信号纯净, 用更大搜索宽度换方向性.

### 3.8. 为什么小预算看不到树搜索收益

建树初期要重复发现合法前缀、抽取状态并估计分支新奇. 独立整证 sample 则从第一份预算起就有机会直接命中. 若题目短、模型单遍成功概率不低, 初期树管理成本难以回收.

只有当多次 sample 反复共享某些正确前缀, 且失败点之后存在多种续写, 前缀复用才优于重开. 大预算提高遇到这类题的机会. 表中 3200 次差不到一题, 4×6400 与 16×6400 才逐渐拉开, 与这个门槛一致.

这也限制个人复现. 单题数千 sample 时, 使用 RL checkpoint 做 independent sampling更简单; 若 CPU 验证远慢于 GPU 生成, 树搜索的反复前缀验证还会受瓶颈. 论文的异步数千核环境把这些延迟隐藏在并行中.

### 3.9. 异步执行会怎样改变树

32 个线程从同一棵树并发选择节点, GPU 批量生成, CPU Lean worker 的完成顺序取决于证明长度与 tactic 耗时. 快速失败可能先回传, 慢而正确的证明稍后到达. 树在等待期间已经被其他结果更新, 选择策略是异步近似.

virtual loss 防止重复选择, 其数值会临时影响其他线程. 并发越高, 临时统计越多, 树与串行 UCB 的路径差异越大. 高并发换吞吐, 同时增加调度随机性. 论文报告系统设置, 没有串行/并行质量对照.

批量生成要求把来自不同 theorem 和状态的 prompt 拼 batch. 长度差导致 padding, CoT prompt 更长. GPU 利用率与生成延迟受 batch composition 影响. 数千 CPU 核负责验证, 整体吞吐取决于 GPU proposal 与 Lean 消费是否平衡.

若 Lean 成为瓶颈, 新候选在队列等待, 搜索统计滞后; 若 GPU 慢, CPU 闲置. 论文没有队列、吞吐和利用率, 所以算法预算无法直接转换为墙钟.

### 3.10. 搜索树中的证明多样性

同一 theorem 可以有代数、几何或自动化等不同 proof. 独立采样通过随机 token 获得多样性, 树搜索还通过状态选择分散分支. 新奇奖励倾向覆盖更多 state, 理论上能提高结构多样性.

状态多样不等于 proof 多样. 两个不同中间状态可能最终都调用同一自动化 tactic, 两段不同代码也可能 kernel term 接近. 论文只统计是否至少一证, 没报告 unique proof、state coverage 或 tactic entropy.

多样性对 pass@k 有直接价值. 如果 sample 完全重复, 增加 $k$ 没有收益; 如果不同 proof 失败独立, 覆盖更快上涨. RL 的 KL 与 CoT/non-CoT 混合可能保持多样性, RMaxTS 新奇则显式扩展状态. 大预算曲线继续上涨说明系统没有完全塌缩.

### 3.11. 搜索终止与证明发布

任何 rollout 得到 Lean 通过后, 当前 theorem 搜索可以立即结束. 最终 proof 是从根到成功节点的某条前缀加新生成后缀. 搜索中的其他分支和错误注释不会进入发布证明.

若多个线程同时成功, 可以选择先返回者、最短 proof 或验证成本更低者. 论文以 solved/unsolved 计分, 没说明多个成功 proof 的选择标准. 这不影响 pass, 会影响可读性与复现输出.

验证通过还应在干净进程重放, 防止 REPL 状态泄漏. 沙箱进程与固定导入有助于隔离. 官方系统以 Lean 为最终裁判, 具体发布 pipeline 在论文中不详细.

### 3.12. 没有 critic 时的理论直觉

标准 UCT 用平均终局回报估计动作价值. 在稀疏证明任务中, 找到第一条 proof 前所有外在回报为零, exploitation 无信息. RMaxTS 把「发现未见状态」当乐观回报, 类似 RMax 对未知状态赋最大值, 使搜索优先完成状态空间覆盖.

一旦某区域被反复扩展, 新状态率下降, DUCB 利用项随近期零奖励降低, 搜索便转向别处. 这个分数表达未知性耗尽前的乐观程度, 不估计当前状态离完成证明还有多远. 对有限浅树有合理效果.

开放动作与无限状态意味着无法真正覆盖完. 状态字符串细微变化也会持续产生新奇, 所以方法依赖模型 proposal 集中在有意义 tactic 和状态合并去重. 理论 RMax 的有限 MDP 保证不能直接搬到这里.

## 4. 奖励、搜索与证明生成的关系

### 4.1. RLPAF 优化的是生成分布

对定理 $x$, 模型生成证明 $y$, Lean 奖励 $r(y)\in\{0,1\}$. GRPO 每组采 32 条, 用组内均值与标准差构造相对优势. 忽略裁剪细节, 优势可写成:

$$
A_i=\frac{r_i-\bar r}{\operatorname{std}(r_1,\ldots,r_G)+\epsilon}.
$$

正确证明的 token 概率被提高, 错误证明被降低, KL 项约束模型不要离 SFT 参考过远. 奖励在序列末端给出, 每个 token 共享整条证明优势. 算法不知道哪一条 tactic 起了决定作用, 信用通过策略梯度粗粒度传播.

RL 改变的是采样分布, 不直接修改 Lean 搜索器. 若正确证明已经在 SFT 分布尾部, RL 可把它移到更高概率区域; 若定理所需思路从未出现在模型支持集, 0/1 奖励难以创造新动作. 中等难度筛选保证每组有机会出现正负样本, 也让训练集中在现有能力边界附近.

4.5k 提示很少, 每题 32 sample 仍能产生大量在线序列. 题目来自 SFT 数据并按成功率筛选, 分布偏向模型偶尔可解的竞赛式 Lean 题. ProofNet 回退说明这种局部优化没有自动迁移到所有本科数学领域.

### 4.2. 树搜索优化的是测试时资源分配

给定固定 checkpoint, RMaxTS 决定下一次 sample 从哪个已验证状态开始. 它不更新模型参数, 而是在一题内部把更多预算分给能产生新状态的分支. RL 与 MCTS 的作用层不同: RL 跨题改变策略先验, MCTS 在单题中利用 Lean 反馈重排探索.

可以把模型看成 proposal policy $\pi_\theta(a\mid s)$, 搜索器根据统计选择状态 $s$, 再让模型生成动作或整段 rollout. 若模型 proposal 很差, 搜索反复得到非法 tactic; 若模型已经很强, 单遍大量采样也能覆盖正确证明, 搜索边际收益小. 表中低预算几乎无增益, 正是后一种与启动成本共同作用的结果.

截断续写使一次 rollout 的有效前缀能进入树. 普通 best-of-$k$ 每个 sample 独立, 失败证明中的正确前缀全部丢弃. 树搜索复用前缀, 但也要支付状态抽取、去重和反复验证. 收益只有在正确证明需要跨多个尝试组合前缀时超过开销.

### 4.3. MCTS 在这里与棋类 MCTS 有何不同

棋类动作空间有限, transition 便宜且确定, value network 可以估计局面. Lean tactic 是开放文本, 合法动作无法枚举; transition 需要 elaboration 与 tactic 执行; 未完成状态没有现成价值. virtual child 表示从同一节点再次调用生成器, 动作集合随 sample 不断展开.

一次生成还可能跨越多条 tactic, 因而树边不是固定一步. 验证后会把成功前缀切成若干节点, 一次 expansion 增长多层. rollout 与 expansion 融合, 没有单独从叶子随机模拟到终局的阶段. 这更接近语言模型引导的异步 best-first tree search, 但选择统计沿用 MCTS/UCB 框架.

Lean transition 确定, 模型 proposal 随采样随机. 相同状态多次扩展可以得到不同证明片段. 状态节点保存多条前缀代码, 因为 reaching path 会影响语言模型看到的文本与 CoT, 即使 Lean 状态相同, 后续生成分布也可能不同. 这使「状态价值」与「文本前缀价值」没有完全分离.

### 4.4. 新奇奖励与证明进展的差别

RMaxTS 给新状态奖励 1, 相当于鼓励扩大已知可达状态集合. 它不测目标数量是否减少、表达式是否简化或关键引理是否建立. 一条 `have` 引入无关命题也可能产生新状态. 在短证明上, 新状态往往意味着至少有 tactic 合法, 对探索有用; 在深证明上, 横向发散会浪费预算.

可以设想更有方向的进展量, 例如目标数变化、表达式复杂度、模型 value、到已知 lemma 的距离或后续成功率. 这些启发式容易被 tactic 操纵, 也可能错误惩罚必要的中间复杂化. 0/1 新奇的优势是简单、无需训练 critic, 缺点是没有数学方向感.

DUCB 解决的是奖励非平稳, 没有解决奖励含义. 一个分支早期容易产生新状态, 后期已经挖空, 折扣让旧成功快速失效; 另一分支若持续产生无用新状态, 仍会长期受偏好. 完整证明的外在奖励一旦出现, 任务已经成功, 没必要继续估计中间价值.

### 4.5. 搜索预算怎样分解

论文用 $N\times T$ 或 $N\times S\times T$ 表示并行 runner、sample 与轮数, 不同方法的一次「生成」长度不同. 更公平的成本至少包括模型生成 token 数、prefill token、Lean 调用数、Lean CPU 时间和墙钟延迟. CoT 样本更长, 整证验证也比单 tactic 更贵.

设第 $i$ 次扩展生成 $l_i$ token, Lean 验证耗时 $v_i$, 总成本可写成:

$$
C=\alpha\sum_i l_i+\beta\sum_i v_i+\delta C_{\text{orchestration}}.
$$

$\alpha$ 与 $\beta$ 由 GPU/CPU 价格和并行度决定. 单写 sample 数隐含每次成本相等, 在 CoT/non-CoT、整证/逐步之间不成立. V1.5 的结论主要是成功率随给定官方预算变化, 不是等 FLOPs 或等成本最优.

大预算下每题十万级生成, pass 率继续上涨说明尾部分布中仍有新证明. 实际部署若只有几百到几千 sample, 树搜索收益接近零, 应优先使用更强 checkpoint 或更多独立 sample. 只有验证集群与长时间预算充足时, RMaxTS 的前缀复用才显示优势.

### 4.6. 一个 GRPO 组怎样产生梯度

设某题采 8 条而非论文的 32 条以便手算, 奖励为 $[1,0,0,0,0,0,0,0]$. 均值为 $1/8$, 成功样本优势为正, 七条失败样本优势为负. 策略更新提高成功 proof 中所有 token 的概率, 降低失败 proof token. 如果奖励全为 0 或全为 1, 去均值后优势全部为 0.

这会产生粗信用问题. 成功 proof 中可能有冗余注释和无用 tactic, 它们与关键步骤一起被提高; 失败 proof 可能有很长正确前缀, 也整体被压低. 大量样本与共同 token 会在期望上缓和噪声, 没有逐状态奖励仍会浪费信息.

组大小影响获得混合奖励的概率与优势方差. $G$ 大时, 低成功率题更可能至少采到一条正确 proof, 生成成本同步增加. 论文用 32 是探索与 batch 成本的选择, 没有组大小消融.

GRPO 的裁剪和 KL 还限制单次更新. 若成功 proof 极罕见, 不受约束地提高它可能让策略过拟合单一路径; 参考策略让更新保持在 SFT 邻域. 这有助于保留语言和证明多样性, 也限制从少数奖励中快速跳到新分布.

### 4.7. 训练时 RL 与推理时搜索为何不能互换

增加 RL 训练计算产生一个可重复使用的 checkpoint, 每道新题的单次成功率可能提高. 增加搜索只为当前题花 TestingTime, 不改变下一题. 若要服务很多题, 训练投入可摊销; 若只有少量高价值难题, 大搜索更灵活.

RL 依赖训练 theorem 分布, 域外可能退化. 搜索使用当前 theorem 的 Lean 反馈, 即使域外仍能验证合法状态, proposal policy 太弱时也无从探索. 两者组合让先验与在线反馈互补, 没有谁能完全替代另一方.

表中 RL 单遍大预算领先 SFT, 说明 checkpoint 改善不只在 top-1 排序; RMaxTS 在 RL 上再加数点, 说明同一 policy 仍有可由状态反馈挖出的尾部. 这两种增益口径应分开报告.

### 4.8. 奖励 hacking 在形式系统里仍有哪些入口

kernel 验证比神经 reward 可靠, 环境与 statement 仍可能被利用. 如果允许 `sorry`, 声明不安全 axiom, 修改 theorem 或使用有漏洞的 tactic/编译接口, 模型可以获得 1 而没有预期证明. 防护需要静态扫描、只读题目、可信 kernel 和固定依赖.

资源型 hacking 也存在. `maxHeartbeats 0` 下, 模型可生成非常昂贵 tactic, 只要 300 秒内通过就得同样奖励. 它可能学会 brute-force 而非简洁推理. 若线上资源不同, 这种 proof 不可用.

形式语句若前提矛盾, `exfalso` 后轻易证明任意结论仍是逻辑合法. 这属于题目问题, 不属于模型作弊. benchmark 审计要区分 theorem 漏洞、环境漏洞与正常自动化.

V1.5 论文没有报告发现 reward hacking, 也没有列完整过滤器. 可靠奖励的正确表述是「在受控 Lean 环境中通过验证的二值信号」, 不是无条件不可能被利用.

### 4.9. 一个更有方向的 critic 要学什么

critic 可以估计 $V(s)=P(\text{最终可证}\mid s,\pi,\text{budget})$. 训练标签可来自搜索树: 某状态的后代是否找到 proof、用了多少扩展. 有了 value, 选择器可优先成功概率高的状态, 而非只奖励新奇.

标签有选择偏差. 未找到 proof 可能是预算不足, 不能断言状态不可证; 已找到 proof 的状态又更常被强 policy 访问. value 会继承当前搜索器盲点. 过度相信 critic 可能剪掉新颖但暂时低分的分支.

另一种方法预测 progress, 如目标数、表达式复杂度或到已知 lemma 的匹配. 这些手工指标易被欺骗. RMaxTS 避免训练 critic, 把方向性让给模型 proposal, 用新奇保证宽度. 这是稳健与效率之间的选择.

### 4.10. 正确前缀为什么是稀疏奖励中的宝贵资产

一条失败 proof 可能前 20 条 tactic 全部合法, 第 21 条出错. 序列奖励给整条 0, 训练时没有直接复用前 20 条; 截断搜索把它们保存为节点, 推理时立刻获得价值. 这显示 RLPAF 与 RMaxTS 在信用分配上的互补.

如果将每个合法前缀也用于训练, 可以构造状态—后续 tactic 数据, 甚至给 progress reward. V1.5 的 tactic state SFT 已经做了一部分: 从成功 proof 抽取中间状态. 失败 rollout 中的合法前缀是否回流训练, 论文没有说明.

失败前缀不一定通向最终 proof. 一条合法 tactic 可以把目标带进死路, 仍被树保存. 新奇奖励鼓励探索这些状态, 没有 critic 识别可恢复性. 大预算通过尝试弥补, 训练层面则可用后代成功标签筛选.

### 4.11. 模型先验与搜索后验

模型给出 $\pi_\theta(a\mid s,h)$, 是从训练数据学到的 tactic 先验. 搜索统计根据当前 theorem 的验证结果更新分支偏好, 可看成测试时后验. 强先验减少无效动作, verifier 反馈纠正题目特定错误.

RMaxTS 的 selection score 没直接乘 policy probability, proposal 阶段仍由模型控制动作. 高频 tactic 更常被提出, 稀有有用 tactic 可能始终不出现. 搜索能重分配状态, 无法在一个状态内枚举模型几乎不给概率的动作.

温度 1、top-$p$ 0.95 保留相当随机性, 为大预算提供探索. 降温会提高常见正确 proof 命中, 也可能降低尾部覆盖. 论文固定采样设置, 没给温度—搜索曲线.

### 4.12. 自动化 tactic 与模型能力的归因

当模型生成 `nlinarith`, 后续代数消元由 Lean tactic 完成. 成功来自模型识别问题类型、准备必要假设和调用工具, 以及 tactic 本身的算法. 这与 Agent 调用工具相似, 不能把所有内部计算算作语言模型参数完成.

不同 prover 若可用导入与 tactic 集不同, 成绩不可直接比较. V1.5 固定 `Mathlib` 和 `Aesop`, `maxHeartbeats 0`, 给自动化充分空间. 某些系统限制 tactic 或 CPU, pass 会下降. 评测环境是系统能力的一部分.

自动化并不削弱结果价值. 形式证明的目标就是正确组合库与 tactic. 归因时应说模型学会生成可验证 proof, 避免把一行 tactic 描述成模型自行完成了其内部所有推理.

### 4.13. 训练与搜索的数据闭环

V1.5 的 expert iteration先用模型生成、Lean 验证、正确 proof 回训; RL 再在线采样并根据验证更新; RMaxTS 测试时继续用验证探索. 三处都把 Lean 放在反馈环, 区别是数据写回参数还是只写入当前搜索树.

SFT 回路离线积累可复用 proof, RL 回路改变全局策略, 搜索回路只解决单题. 若将 RMaxTS 新找到的 proof 再加入 SFT, 可以继续 expert iteration. 论文没有报告搜索结果回训, 方法结构允许这种扩展.

闭环容易自我强化当前风格. 模型更会某类 tactic, 就更容易生成通过 proof, 数据池继续增加同类 proof. 扩展 theorem 来源、控制 proof 多样性和引入检索可以打破偏置. Goedel-Prover 用更广形式化数据获得大幅提升, 正是覆盖面的证据.

### 4.14. 从单题成功到训练目标的错位

benchmark 计每题是否至少有一证, 训练最大化 sample 级预期奖励. 对容易题从 0.8 提到 0.9 与难题从 0 提到 0.1, 训练收益可能相似, pass@大 $k$ 的价值不同: 难题获得非零支持会带来新覆盖, 容易题只是更快命中.

中等难度筛选偏向第二种有学习信号的题, 但没有显式最大化 theorem coverage. 可以按题目成功率重权, 鼓励把近零题拉起来; 过难题仍没有正 sample. curriculum 与搜索生成正例能逐步移动边界.

证明长度也未进入奖励. 短 proof 和长 proof 同得 1, 长 proof 产生更多 token 梯度, 其序列概率更低. 长度归一、每题归一与 GRPO token reduction 会影响实际更新, 论文没有细到这个层面.

## 5. 实验与统计口径

### 5.1. 消融能证明多少

图 5 在 RL 模型 CoT 模式下拆 RMaxTS 的组件. 4×6400 预算时: 单遍 58.4%±0.5%, UCT 无内在奖励 58.2%±0.3%, 内在奖励配 UCB1 58.6%±0.3%, 去掉 tactic 状态 58.4%±0.3%, 完整 RMaxTS **59.6%±0.6%**. 16×6400 时依次是 60.2%, 61.1%, 60.7%, 61.1%, 62.7%. 报告据此得出三点: 没有内在奖励, 树搜索退化到接近不搜索; 内在奖励必须配 DUCB; tactic 状态注释是树搜索有效的必要条件.

方向上这三点和数据一致, 但幅度要换算成题数看. miniF2F-test 共 244 题, 1 题约 0.41 个点. 16×6400 下完整 RMaxTS 约证出 153 题, 三个消融版本约 148–149 题, 单遍约 147 题. 也就是说, 在十万级采样上, 内在奖励, DUCB, 状态注释各自的贡献都在 4–5 题左右, 而 16×6400 这一档没有给标准差. 结论可能是对的, 但证据比正文的措辞弱. 表 3 里还有一处值得核对: SFT 模型的 non-CoT & CoT 混合 (2+2)×6400, 单遍和 RMaxTS 两行都是 **56.1%±0.8%**, 连标准差都相同, 可能是巧合, 也可能是抄录错误, 报告没有说明.

小预算下树搜索几乎不起作用, 这一点正文没有强调. 表 1 里 RL 单遍 3200 次 54.9%, RL + RMaxTS 1×3200 55.0%; SFT 单遍 3200 次 53.3%, SFT + RMaxTS 53.5%. 两处都只差 0.1–0.2 个点, 不到一题. 树搜索的收益主要出现在 4×6400 以上, 这和「内在奖励要积累足够多的新状态才开始有区分度」的机制是一致的. 对只能跑几千次采样的使用者, 单遍整证生成基本就是全部收益.

### 5.2. 主结果和预算口径

miniF2F-test(表 1): RL 单遍 128 次 51.6%, 3200 次 54.9%, 16×6400 次 60.2%, 比 V1 的 50.0% 高 10.2 个点; RL + RMaxTS 16×6400 62.7%; 用 CoT 和 non-CoT 各一半预算的混合策略, 32×6400 到 63.5%. 对照组里 InternLM2-StepProver 54.5%, Lean-STaR 46.3%, HTPS 41.0%, GPT-f 36.6%, COPRA + GPT-4 26.6%. 摘要里的 63.5% 同时用了 RL, RMaxTS 和混合提示三样东西; 只看模型本身, 应该看单遍的 60.2%. ICLR 2025 版正文把主结果写成 62.7%, 没有把混合策略的数字当标题.

评测协议写在源文 §2.4. 每个模型单卡 A100-40G, 用 vLLM 采样, 温度 1, top-p 0.95, 最多 2,048 token; 验证时导入 Mathlib4 和 Aesop, 单题时限 300 秒. miniF2F 和 ProofNet 原本都是 Lean 3, 作者手工转成 Lean 4.9.0, 比 V1 用的 v4.7.0-rc2 新. 这意味着 V1 的 50.0% 和 V1.5 的数字不是在完全相同的语句文件和工具链上测的, 表 1 里 V1 那一行是在哪个版本上重跑的, 报告没有说明. Base 模型用 3-shot, 示例从验证集随机抽: miniF2F 用 Yang(2023) 的人写证明, ProofNet 则用 **V1.5-RL 生成的正确证明**当示例. 用最终模型的输出去给 Base 做示例, Base 在 ProofNet 上的 9.7% 就不完全是 Base 自己的水平, 报告没有讨论这一点. SFT 和 RL 模型不用 few-shot, 改用 CoT 或 non-CoT 两种引导提示.

预算怎么比是这一节最容易读错的地方(源文 §4.1). 单遍方法按总生成数记, best-first 按 $N\times S\times T$ 记, 树搜索按 $N\times T$ 记. 报告称 3200 次整证就超过 InternLM2-StepProver 的 64×32×100 次, 后者折合 204,800 次生成. 但一次整证生成最长 2,048 token, 一次逐步生成只写一条 tactic, 按 token 或按验证调用次数算, 两边的差距会小得多, 报告没有给 token 口径的对比. 另一个量级: 32×6400 即每题 204,800 次整证生成, 244 题合计约 5000 万次, 每次都要 Lean 验证, 这就是 §2.2 那套数千核集群存在的原因.

ProofNet(表 2): RL 单遍 4×6400 全集 22.6%, RL + RMaxTS 全集 25.3%, 测试集 25.3%, 验证集 25.4%, 对照 ReProver 13.8%, InternLM2-StepProver 18.1%. 表注写明 ProofNet 验证集参与了 SFT 的 expert iteration, 所以验证集那一列不能当泛化证据, 只有测试集 186 题是干净的. 测试集上单遍 23.7% 到 RMaxTS 25.3%, 约多证出 3 题. miniF2F 验证集同样进了 SFT 数据, 所以 miniF2F 也只能看测试集. 和 V1 相比, V1.5 把「哪些评测集进了训练」写清楚了, 这是评测口径上的进步.

### 5.3. CoT 和 non-CoT 各擅长什么

表 3 显示 CoT 相对 non-CoT 的优势随预算放大: 单遍 RL 模型 4×6400 时 CoT 58.4%, non-CoT 56.5%, 16×6400 时 60.2% 对 57.4%. 报告的解释是自然语言注释让规划路径更多样, 大预算时能覆盖更多不同的证明思路. 这个解释和数据方向一致, 但和 §1.3 提到的问题连在一起看: 注释不受 Lean 检查, 多样性可能部分来自注释本身带来的随机扰动, 而不全是「更好的规划」, 报告没有做区分这两者的实验.

两种模式确实互补. 附录 B.1 里 non-CoT 赢的题, 比如 `induction_pord1p1on2powklt5on2` 和 `imo_1960_p2`, 证明是一串 `field_simp`, `nlinarith`, `norm_num`, 靠 Lean 自动化硬算过去; B.2 里 CoT 赢的题, 比如 `mathd_algebra_459` 先在注释里把四元方程组解出 $d=13/15$, 再逐个 `have` 落到代码. 混合策略把预算对半分, RL + RMaxTS 在 (16+16)×6400 时 63.5%, 比纯 CoT 的 16×6400 62.7% 多约 2 题, 而总预算是后者的两倍. 所以混合策略的增益里, 一部分来自多花了一倍的 TestingTime 算力, 一部分来自两种模式覆盖不同题目, 表 3 没有给等预算下纯 CoT 32×6400 的数字, 两者分不开. 推理模式如何影响思考能力, 更一般的讨论见 [推理与思考能力](../../../llm-guide/4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).

### 5.4. pass@k 到底估计什么

若单次独立成功概率为 $p$, 理想 pass@$k$ 为:

$$
1-(1-p)^k.
$$

真实评测通常从 $n$ 个 sample 中估计 pass@$k$, 常用无偏估计器根据失败数 $c$ 计算组合比例. 当所有候选同分布且独立时, $k$ 增大单调接近至少一次成功概率. 模型样本高度相关, 有效多样性低于 $k$.

V1.5 的大预算写成多组 $6400$, 可能通过不同随机运行聚合 theorem 是否至少成功. 表中百分比是 244 个 theorem 的通过比例, 并非单题平均 $p$. 有些题在前几十次就成功, 有些题十万次仍失败, 总曲线反映难度混合.

pass@k 奖励覆盖面, 不关心正确证明概率质量. 一个模型每题只有万分之一概率成功, 给足预算也可能有高 pass; 线上单次使用却很差. Pass@128 更接近有限部署, 16×6400 展示支持集与搜索上限. 两种口径都重要.

树搜索样本不独立, 不能直接套 $1-(1-p)^k$. 后续扩展依赖先前发现状态, $k$ 代表自适应查询次数. 把 RMaxTS 与独立采样按相同生成数比较有直观意义, 统计模型不同.

### 5.5. 题目数如何限制小差值解释

miniF2F-test 有 244 题, 单题约 0.41 个百分点. 0.1 或 0.2 点差小于一题, 来自多次运行平均或四舍五入, 不应写成实质提升. 1 点约 2–3 题, 2.8 点约 7 题. 把百分点换成题数能恢复直觉.

同一模型不同 seed 会改变哪些题被证明. 论文对部分设置报告标准差约 0.3–0.8 点, 与一到两题相当. 完整大预算缺少所有对应方差, 63.5 与 62.7 的 0.8 点差未必稳健, 而且预算不同.

题目不是同质 Bernoulli. 多道题可能共享 `nlinarith` 模式, 一项能力变化会成组影响, 简单二项置信区间低估相关性. 更有信息的报告应列配对翻转: SFT 未证而 RL 证出的题, RL 退化的题, RMaxTS 独有题及证明长度.

ProofNet test 186 题, 单题约 0.54 点. RMaxTS 从 23.7 到 25.3 约多 3 题. 这是正向信号, 规模远小于 miniF2F 的主标题增益, 也说明搜索收益随领域与证明深度变化.

### 5.6. miniF2F 与 ProofNet 的分布差异

miniF2F 主要是中学竞赛题, 大量代数、数论与不等式可由 `linarith`、`nlinarith`、`norm_num`、`ring` 等自动化收尾. 自然语言 CoT 容易提出中间等式, Lean tactic 生态也与数据中常见模式吻合.

ProofNet 来自本科数学陈述, 涉及更广定义、分析与抽象结构. 证明需要选择库 lemma、处理类型类和拓扑/代数环境, 单靠算术 tactic 不够. V1.5 的 RL 提示只有 4.5k, 来自 SFT 中等难度题, 领域覆盖可能偏 miniF2F 风格.

这解释 RL 在 miniF2F 稳定优于 SFT、ProofNet 某些预算却持平或回退的可能原因. 它是分布假设, 论文没有按领域列训练题和错误类型. 不能把 miniF2F 上「RL 增强基础能力」直接外推到全部 Lean 数学.

ProofNet validation 进入 SFT expert iteration, test 才能用于泛化. Base few-shot 又用了 V1.5-RL 生成的证明当示例, 不同模型行的上下文信息不完全对齐. 这使表格适合比较最终系统, 不适合纯 checkpoint 归因.

### 5.7. CoT 模式的成本口径

CoT 在每条 tactic 前写解释, 输出 token 明显多于 non-CoT. 相同 sample 数下, GPU 解码时间、KV cache 和截断概率不同. CoT 分数高不能直接称为免费提升, 应报告每个成功证明的平均 token 与时间.

2048 token 上限对两模式影响不同. non-CoT 能容纳更多 tactic, CoT 可能在代码完成前被解释耗尽. 短 miniF2F 中规划收益超过长度代价; 长证明可能反转. 论文没有按证明长度分桶.

混合模式的互补还可能只是增加多样性. 用两个 prompt 形成两个采样分布, 类似 prompt ensemble. 若换成多种 non-CoT 提示也可能覆盖更多证明. 要隔离自然语言推理, 需要等 token、等 prompt 数与等总预算比较.

### 5.8. 消融缺少哪些轴

RMaxTS 消融覆盖内在奖励、UCB/DUCB 与状态注释, 没有扫描 $\gamma$、线程数、每次 rollout 长度、状态合并规则和模型温度. 搜索组件相互作用, 固定一个配置的移除实验只能说明该点附近贡献.

训练侧缺少纯 tactic state、纯 CoT、两者同时和无注释的完整矩阵. SFT 数据、预训练与 expert iteration也没有规模曲线. 因而 CoT 与状态监督各自对单遍和搜索的贡献难以拆分.

RL 侧缺少提示数量、组大小、KL 与训练步数消融, 也没有训练 reward、entropy 和验证曲线. 1–3 点增益可以确认, 为什么产生以及是否已经饱和仍未知.

最后缺少等成本对照. 增加独立 sample、RMaxTS、best-first 与逐步 prover 应按 GPU token、Lean CPU 与墙钟比较. 论文使用生成次数作为统一轴, 有利于展示算法, 不能回答真实集群的性价比.

### 5.9. 从 pass 曲线反推题目分层

若所有题拥有相同单次成功率, pass 曲线会由一个 $p$ 决定. 实际从 128 到十万 sample 仍增长, 说明题集至少包含三层: 高概率题早早通过, 低概率题需大预算, 零支持题始终失败. 曲线尾部上涨来自第二层.

RL 若只重排已有 proof, 可能让高概率题更早通过, 大 $k$ 最终与 SFT 汇合. 表中大预算差距没有消失, 支持 RL 让部分题从近零概率进入可采样尾部, 或扩大了正确证明多样性. 它仍未达到证明「创造全新推理算法」的强度.

RMaxTS 的目标是把第二层题的合法前缀组合起来. 对高概率短题, 独立 sample 足够; 对零支持题, 树也无合法 proposal. 所以搜索增益集中在中间层, 与 RL 的中等难度训练筛选形成相似结构.

若报告按题目单遍成功率分桶展示搜索增益, 可以直接验证这一解释. 论文没有该图, 只能从预算曲线间接判断.

### 5.10. 混合策略怎样区分互补与额外预算

设 CoT 在题集上成功集合为 $A$, non-CoT 为 $B$. 混合覆盖率由 $|A\cup B|$ 决定, 互补部分是 $|A\triangle B|$. 只给两种单独总分与混合总分, 无法求出交集, 因为采样预算和随机性也变化.

等预算实验应把总 sample 固定为 $K$, 在 CoT/non-CoT 间分配 $\lambda K$ 与 $(1-\lambda)K$, 扫描 $\lambda$. 论文的 (16+16)×6400 比纯 CoT 16×6400 多一倍总预算, 混合上涨 0.8 点可能来自额外 sample.

不过附件案例确实显示模式偏好不同. non-CoT 更常简短调用自动化, CoT 更常显式建立中间 `have`. 这种结构差异给互补提供定性证据. 要量化仍需相同预算和题级翻转表.

### 5.11. 标准差与重复运行怎样读

部分结果写成均值±标准差, 表明多个随机运行或批次. 标准差描述运行间波动, 不等于均值置信区间; 还需要重复次数才能计算标准误. 论文没有在每个大预算格都给完整重复信息.

0.5 点标准差约一题多. 两个设置均值差 0.4 点且区间重叠时, 不应强调排名. 完整 RMaxTS 对某些消融高 1–1.5 点, 方向更可信, 题数仍只有数题.

benchmark 题数固定, 重复随机性来自模型采样与搜索调度. 32 线程异步还会因返回顺序改变树, 即使随机 seed 相同也可能不完全确定. 复现应报告多 seed 与调度设置.

### 5.12. 与后续强基线比较时的时间顺序

Goedel-Prover 用更大形式化数据在 V1.5-Base 上 SFT, 说明数据覆盖可以超过 V1.5 的 RL 增益. 它发布时间更晚, 使用 V1.5 作为基础, 不能反过来否定 V1.5 当时的方法贡献.

Prover-V2 使用更强通用模型分解和 671B RL, 模型规模、数据与任务构造都不同. 它表明路线演进到显式子目标与大模型, 不是 RMaxTS 的受控替代实验.

正确比较方式是把后续结果作为上限与机制启示: V1.5 找到 verifier RL 和状态搜索接口, 后续扩大 theorem 数据与规划能力. 每代主结果的预算也不同, 不能只排一个 pass 百分比排行榜.

### 5.13. 用数值理解采样收益递减

若某题单次成功率 $p=1\%$, 独立采样 128 次的成功率约为 $1-0.99^{128}\approx72.4\%$; 3200 次几乎必过. 若 $p=0.01\%$, 128 次约 1.27%, 3200 次约 27.4%, 十万次才接近必过. 大预算主要从第二类极低概率题中继续挖答案.

如果 $p=0$, 任何独立采样都无效. 树搜索可能把多个非零概率正确前缀拼起来, 将整证零支持变成可达; 前提是每个关键局部动作都能由模型提出. 这就是 RMaxTS 相对 best-of-$k$ 的潜在优势.

题集曲线是不同 $p_i$ 的平均. 从表格总 pass 无法反推出单题分布, 同一总分可能由「多数题中等概率」或「一半很易、一半为零」形成. 后者增加 sample 很快饱和, 前者持续上涨. 论文的大预算曲线提供部分形状信息, 没发布题级 $p_i$.

采样收益递减还决定资源分配. 与其给已高概率题继续上万 sample, 可以根据早期失败动态把预算移给边界题; 但早期没成功也可能是极难零支持题. 一个 value 或难度估计器能改善分配, RMaxTS 用状态新奇作为局部代理.

### 5.14. 最低可复现实验应报告什么

模型侧需要 checkpoint、prompt 模式、temperature、top-$p$、最大 token 与 sample 数. Lean 侧需要版本、Mathlib commit、导入、heartbeat、墙钟超时和禁用 escape 规则. 数据侧需要 test 文件摘要以及 validation 是否进训练.

搜索侧还要记录 runner、线程、virtual loss、$\gamma$、状态去重和每次 expansion 的生成数量. 成本侧记录 GPU token、Lean calls、CPU 秒与墙钟. 只报告 `N×T` 无法让不同硬件与方法公平比较.

结果侧除 pass@k, 还应给题级成功、证明长度、Lean 时间、CoT token、unique states 与多 seed 方差. 这些指标能区分 checkpoint 更强、搜索更广、自动化更重和预算更多.

V1.5 已公开论文、模型与仓库, 为复现提供了主体. 未公开预训练数据配比、完整训练日志和集群成本, 所以最容易复现的是 checkpoint 推理与小预算 pass, 最难复现的是从 Base 到 RL 的整条训练和十万级 RMaxTS.

## 6. 局限与谱系位置

报告的结论节把整条流水线比作 AlphaZero: expert iteration 和合成数据是试错循环, Lean 编译器是世界模型, 树搜索负责探索. 作者自己承认只做了探索这一半, 利用这一半没做: 没有 critic 给不完整的证明打分, 也就没有逐步信用分配和剪枝, 搜索靠的是好奇心和访问统计. 另一个方向是从单个定理走向多定理的 Lean 文件级证明, 报告说模型已有一定文件级上下文理解, 但没有给评测.

谱系上, V1.5 夹在两代之间. 往前看, 它继承了 V1 的合成数据和整证生成范式, 以及 DeepSeekMath 的基座和 GRPO. 往后看, 2025 年 4 月的 Prover-V2 换了思路: 用 DeepSeek-V3 把难题拆成一串 `have` 子目标, 由一个 7B prover 递归证每个子目标, 拼起来的完整证明加上 V3 的 CoT 做冷启动数据, 再用 GRPO 训 671B 模型, miniF2F-test Pass@32 82.4%, Pass@8192 88.9%. V1.5 的 CoT 注释由外部大模型写, V2 的 CoT 由通用大模型负责拆题, 形式化那一侧交给专用 prover, 分工更明确. RMaxTS 在 V2 的公开材料里没有再作为主推方法出现, 子目标分解接替了「把长证明拆短」这个角色. V1.5 留下来的是两样东西: 用 Lean 0/1 做 GRPO 奖励的做法, 以及截断续写这种让整证模型读到编译器状态的接口.

还有一样常被忽略: V1.5-Base 本身成了开源形式证明的底座. Goedel-Prover 就是在 V1.5-Base 上做的 SFT, 并且用 V1.5-RL 为 expert iteration 的第一轮生成证明. 这说明继续预训练那一步虽然在报告里只占一段, 数字也只涨了约 2 个点, 却是后来者最愿意复用的部分. 对只有单机的读者, 最有参考价值的数字是单遍 128 次的 51.6% 和 3200 次的 54.9%; 树搜索那几档依赖数千核验证集群, 在个人环境里很难复现.

### 6.1. 验证器可靠不等于 benchmark 没有漏洞

Lean kernel 能保证给定环境中的 theorem 有证明项, 前提是语句、导入与允许的公理符合预期. 如果形式化语句比原题弱、前提矛盾或允许不受信任的声明, 编译通过仍不代表解决了原问题. V1.5 从已经形式化的 miniF2F/ProofNet 开始, 没承担 statement 忠实性验证.

代码还要禁用逃逸方式. `sorry`、`admit` 或自定义不安全公理能让 theorem 表面通过. 论文把 Lean 奖励视为可靠, 官方评测脚本理应过滤这些结构; 报告没有逐项列安全规则. 后续 Prover-V2 的 benchmark 曾出现 statement 错构与工具漏洞, 说明形式评测仍要审计语句和环境.

超时也是语义外的系统边界. 一个证明理论上合法, 300 秒内没有完成会记失败; 更强 CPU 或缓存可能改变结果. `maxHeartbeats 0` 把限制移到外部时钟, benchmark 同时测 tactic 可证明性与运行资源.

### 6.2. 从短 theorem 外推到大型 Lean 文件

miniF2F theorem 通常自包含, 文件头统一, 证明短. 大型 Mathlib 开发需要跨 namespace 查 lemma、维护局部实例、处理依赖与前面定义, 当前 goal 只是环境的一小部分. tactic state 注释可能不足以表达所有相关上下文.

文件级任务还会产生长期依赖. 早先 lemma 的命名和形式决定后续证明, 修改一处可能让很多 theorem 失效. 整证生成对单 theorem 的低通信优势, 在文件级增量编译中未必保持. 搜索树若跨 theorem, 状态空间与缓存策略都要重做.

检索是另一缺口. V1.5 依赖模型参数与导入库知识, 没有专门 premise retrieval. ProofNet 抽象领域常需要精确 lemma, 搜索 tactic 状态却不能自动发现库中远处定义. 后续系统常把检索、分解与生成结合, 这不是单纯增大 RMaxTS 预算能替代的.

### 6.3. 自然语言 CoT 的外推边界

miniF2F 的数学思路容易用短自然语言描述, 再由 `nlinarith` 等 tactic 完成细节. 高阶代数、拓扑与范畴论证明需要精确类型和库结构, 自然语言计划可能过于粗糙. CoT 模式在 ProofNet 未呈现同等优势, 提醒这种监督有领域依赖.

注释由 Coder-V2 236B生成, 小 prover 学习的是大模型对正确证明的解释. 这属于离线蒸馏, 解释质量上限受教师约束. 如果教师不熟悉 Lean 语义, 注释会把形式动作包装成似是而非的数学话. Lean 不能检查 comment.

CoT 还可能泄露答案结构. 训练注释是在已知正确 proof 后生成, 属于 hindsight explanation; 推理时模型要在未知 proof 前规划. 事后解释分布与在线计划不同. 真正检验规划作用需要看注释先预测的中间结论是否被后续代码使用.

### 6.4. RL 增益为何不能外推成通用数学推理增益

奖励只对 Lean proof 通过负责. 它会提高生成可编译 tactic 的概率、熟悉库用法并选择更成功的自动化, 不直接训练自然语言答案、形式化语句或新数学概念. miniF2F 上大预算 gap 支持形式证明策略改善, 不等于所有数学推理都提高.

训练提示来自约 4.5k 个中等难度 theorem, 规模和领域有限. ProofNet 的回退提供反例. 若将「RL 带来基础能力」理解为当前 Lean 分布上的 policy 改善是合理的, 扩大成领域无关 reasoning breakthrough 就超过证据.

pass@大 $k$ 领先说明 RL 分布仍包含更多可用正确证明, 但可能来自更好的 tactic syntax 或库 lemma 选择. 要证明数学思路新颖, 需要按证明结构、lemma 与题型分析, 论文没有这类语义审计.

### 6.5. RMaxTS 与子目标分解的关系

RMaxTS 在执行失败后从真实状态继续, 是反应式分解: Lean 已经通过 tactic 把目标变成子目标, 搜索再沿状态推进. Prover-V2 用强模型先写 `have` 链, 是规划式分解: 在生成完整 proof 前显式设计子目标.

两者可以互补. 规划提供方向性, Lean 状态保证每步真实, 树搜索在某个子目标失败时探索替代证明. V1.5 没有 learned critic 与显式分解器, 所以依赖新奇扩大树. V2 更依赖冷启动数据和大模型规划, 减少把大预算花在无方向状态上.

RMaxTS 未在 V2 主结果中延续, 不说明截断续写无价值. 它提供了整证模型接入 verifier 状态的通用接口. 当模型已经能写高质量子目标, 搜索的边际位置会从全局探索转向局部恢复.

### 6.6. 与逐步 prover 的公平比较

逐步 prover 每个动作短, Lean 调用多; 整证 prover 每次输出长, Lean 调用少. 按 model calls, 整证占优; 按生成 token, 差距缩小; 按 Lean CPU, 要看前缀重放与 tactic 复杂度. 表中把不同方法的预算换成生成次数, 只是一种口径.

逐步方法还可能使用检索、value network 与 best-first queue, 参数和训练数据不同. V1.5 在 miniF2F 上超过旧基线, 同时发布时间、Lean 版本和基础模型也更晚. 横向表展示当时系统水平, 不能把全部差距归到整证范式.

最严格比较应固定同一个 checkpoint 与 verifier, 分别运行独立整证、截断续写、逐 tactic 和混合搜索, 报告等 GPU token、等 Lean 秒与等墙钟曲线. V1.5 主要比较自身搜索组件, 没完成这套范式级实验.

### 6.7. 一手来源与代码边界

[DeepSeek-Prover-V1.5 论文](https://arxiv.org/abs/2408.08152)提供数据构造、RLPAF、truncate-and-resume、RMaxTS 公式、并行设置和主表. [官方仓库](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5)提供模型、benchmark 与运行入口. DeepSeekMath 论文是 GRPO 与 7B 基座来源, V1 论文是 800 万合成数据与整证范式前身.

论文能直接支持训练规模、超参、分数与算法定义. 不能支持的包括预训练 token 构成、训练总步数/GPU 时、CoT 忠实率、状态等价实现细节、搜索总成本和安全过滤完整规则. 代码可以补接口行为, 不能补未发布的训练数据与实验日志.

后续 Goedel-Prover 与 Prover-V2 适合作为外部对照, 用来限定 V1.5 的数据与谱系位置, 不能反写成 V1.5 当时已经采用的方法. 技术文章应把原论文事实、源码行为和后续解释分层.

### 6.8. 最终可以保留的结论

第一, tactic state 注释与截断续写成功把整证生成接入 Lean 中间反馈, 在保持长 rollout 的同时复用合法前缀. 第二, 可靠 0/1 verifier 奖励让 GRPO 在形式证明上得到小而可测的增益, 其量级远小于 SFT 数据贡献.

第三, RMaxTS 用新状态解决无 critic 时的冷启动探索, DUCB 适应新奇奖励衰减. 它在十万级测试预算上多证出若干题, 小预算收益很小. 第四, CoT 与 non-CoT 有互补, 但自然语言注释未被形式验证, 等预算归因不完整.

第五, 63.5% 是 RL、树搜索、双提示和约 20 万次每题生成共同组成的系统结果. 单遍 128 与 3200 更接近普通部署. ProofNet 和后续 SFT 强基线说明结论不能越过数据分布与算力边界.

V1.5 最持久的贡献因此是接口和训练信号: 用证明助手状态把开环生成变成可恢复搜索, 用 kernel 结果替代神经奖励, 再让同一模型同时支持单遍与树搜索. 这套思路后来可以与更广数据、子目标分解和检索结合, 并不依赖 RMaxTS 成为唯一搜索算法.

### 6.9. 一条完整的阅读路线

先把 Lean proof 看成状态转移. theorem 给出 $s_0$, tactic 产生 $s_1,s_2,\ldots$, 空目标是成功. 整证模型一次预测整条动作序列, 逐步模型每次观察真实状态. tactic state 注释与截断续写的意义, 都从这组状态差异出发.

再看训练数据. 继续预训练提供形式语言先验, expert iteration提供大量通过证明, Coder-V2 注释增加自然语言计划, 状态注释训练恢复接口. SFT 建立主要能力后, RLPAF 只在中等难度题上用 0/1 verifier 微调分布. 这解释了为何 SFT 增益约 20 点, RL 只有数点.

随后看搜索. RMaxTS 不是替模型证明, 它选择从哪个真实状态再次调用模型. 外在奖励在证完前全零, 新状态提供临时方向; 新奇衰减后, DUCB 忘掉旧奖励并转向其他分支. 大预算下合法前缀复用逐渐抵消建树成本, 小预算仍接近独立采样.

最后看数字. pass@128 反映较现实多采样, 十万级 pass 展示尾部和搜索上限; 63.5% 还叠加双提示与翻倍预算. miniF2F 强项不能覆盖 ProofNet 反例, Lean 通过也不能覆盖 statement 忠实、证明可读与计算成本. 沿这四步阅读, 每个提升都能落到明确机制与适用条件.

### 6.10. 从 V1.5 继续向前需要补什么

数据层需要更广 theorem、去重后的多样 proof 和可信自然语言—代码对齐. 状态层需要适合大型文件的环境表示、premise retrieval 与上下文压缩. 训练层需要前缀级信用、更清楚的 RL 曲线和跨领域提示. 搜索层需要能估计进展又不过早剪枝的 critic.

评测层则要固定 Lean/Mathlib, 审计 statement, 报告等成本曲线与题级翻转. 证明通过之外, 还应观察验证时间、依赖、长度和注释忠实. 这些指标会告诉读者新方法是在增加数学覆盖、调用更强自动化, 还是单纯花了更多 TestingTime.

V1.5 已经把关键接口打开: 语言模型生成候选, Lean 提供状态与奖励, 训练和搜索分别利用反馈. 后续方法可以替换 proposal、value、分解或检索, 仍沿用这个闭环. 它的价值不只在 63.5%, 更在于把整证生成从盲目重采样推进到可观察、可恢复的证明过程.

这套闭环还有一个容易忽略的判断标准: 每增加一层智能, 都要保留 kernel 的最终否决权. 自然语言 CoT 可以错, critic 可以偏, 检索可以召回无关 lemma, 搜索也可以走入新奇却无用的状态; 只要最终 proof 在固定环境中重新验证, 逻辑正确性仍有硬边界. 反过来, kernel 只能否决非法 proof, 不会告诉系统怎样高效找到 proof、语句是否忠实或解释是否可信. V1.5 的方法价值正来自把软策略与硬验证接在一起, 而不是让其中一方替代另一方.

因此复现结果至少要同时保存 theorem 文件、环境版本、最终 proof 与运行口径. 只有百分比而没有可重放证明, 很难区分模型退化、库变化和评测脚本变化. 形式证明相比自然语言评测的一大优势, 正是成功样本可以在未来环境中重新编译; V1.5 的搜索与 RL 都应围绕这种可重放性理解.

重新编译还应在空白工作目录与固定依赖中进行, 并记录每份 proof 的验证时间和超时状态. 这样既能确认逻辑结果仍成立, 也能发现某次库升级让自动化 tactic 变慢或失效. 对大预算搜索而言, 保存成功 proof 比保存临时搜索树更重要, 因为前者是可长期复核的研究产物.
