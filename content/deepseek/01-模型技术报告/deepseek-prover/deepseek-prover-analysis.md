# DeepSeek-Prover: 用 Lean 核验器当过滤器, 合成 800 万条形式证明

来源: [DeepSeek-Prover: Advancing Theorem Proving in LLMs through Large-Scale Synthetic Data](https://arxiv.org/abs/2405.14333) (arXiv: 2405.14333v1, 2024-05-23). DeepSeekMath 在结论里承认几何和定理证明是短板, 三个月后的 DeepSeek-Prover 就对准了其中一块: 用 Lean 4 写出能被机器核验的证明. 模型和底座都没变, 仍是 DeepSeekMath-Base 7B, 训练方法也只是普通的监督微调. 这篇报告的全部分量都在数据上: 把网上爬来的约 87 万道竞赛题自动翻成 Lean 语句, 过滤, 证明, 用 Lean 核验器判对错, 通过的样本回流训练, 滚四轮得到约 **800 万**条带证明的形式语句. 读它要换一个视角: 这里的「数据流水」本身就是算法, Lean 核验器同时扮演标注员和质检员.

## 1. 数据合成流水

### 1.1. 问题: 形式证明缺的是平行语料

Lean, Isabelle, Coq 这类证明助手把命题和证明都写成代码, 内核按形式规则逐步检查, 通过才算证完. 可靠性远高于自然语言证明, 代价是写起来慢, 资深数学家也要花大量时间. 神经定理证明此前有两条路. 一条是模型引导的树搜索: 模型逐步给出 tactic, 和证明器交互, 按搜索算法扩展, 代表是 GPT-f, ReProver, Hypertree Proof Search, 搜索空间大, 算力贵. 另一条是整证生成: 模型一次写完整个证明脚本, 交给证明器判对错, 代表是 Baldur, Draft-Sketch-Prove, 省掉交互, 但一次写对很难.

更早的一阶定理证明器, 比如 E 和 Vampire, 在简单逻辑框架里很高效, 但处理不了证明助手里常见的高阶, 带大量库定义的命题. 神经方法把这个领域重新激活, 不过树搜索那条线多用 RL 提升准度, 搜索本身耗时耗算力; 整证生成那条线跳过了逐步交互, 效率更高, 却更依赖模型一次写对的能力, 也就更依赖训练数据.

两条路都卡在同一个地方: 形式语料太少. Python 这种语言在 GitHub 上有海量代码可学, Lean 的 mathlib 虽然是最大的形式数学库, 规模和自然语言数学相比仍然小几个数量级. 自动形式化(把自然语言题目翻成形式语句)能补一些, 但此前的工作规模都不大. 报告的判断是: 模型架构和搜索算法不是主要瓶颈, 训练数据是. 所以他们不改模型, 不改搜索, 只造数据. 此前造形式数据的办法有两类: 一类对已有定理做基于规则的变换, 能批量生成, 但受限于预先写好的规则, 变不出新的题型; 另一类用大模型把自然语言题翻成形式语句, 灵活, 但已有数据集规模小, 只覆盖几个小基准, 训练收益有限. DeepSeek-Prover 选的是第二类, 目标是把规模做大两个数量级以上. 表 2 的对照直接说明了语料的差距: 同样用 expert iteration, 只用 mathlib 的人写定理, 训练 token 只有 0.238B; 用自动形式化的语句, 训练 token 到 3.108B, 多了一个数量级.

### 1.2. 起点: 冷启动一个会翻译的模型

整个流水需要一个会「把题目翻成 Lean」的模型, 但 DeepSeekMath-Base 一开始几乎不会. 冷启动用 MMA 数据集: 它把 mathlib 里的 Lean 4 语句用 GPT-4 反向翻成自然语言题目, 于是得到「自然语言到 Lean」的平行样本, 在上面微调一下, 模型就能按固定模板把题目翻成 Lean 4 声明. 模板要求只输出核心声明, 包在代码块里, mathlib 固定到某个 commit, Lean 固定在 v4.7.0-rc2. 版本固定这件事看似琐碎, 实际很关键: mathlib 引理的名字和签名会随版本变, 同一段证明在新版本上可能就过不了.

题源的选择也有讲究. 报告观察到, 条件明确, 目标清楚的竞赛题比需要复杂定义和构造的高等数学容易形式化, 所以主攻高中和本科竞赛题, 以代数和数论为主, 组合, 几何, 统计为辅. 这类题陈述简单, 解法可能不浅, 适合做证明训练数据. 自然语言题目从网上的习题, 考试, 竞赛资源爬取清洗, 得到 869,659 道. 爬了哪些网站, 怎么清洗, 报告没有细节. 这也埋下一个问题: 竞赛题来源和 miniF2F 的题源(AMC, AIME, IMO, MATH)高度重合, 报告通篇没有提到去污染, 后面读 miniF2F 分数时要把这一点记在心里.

### 1.3. 质量过滤: 打分和假设否决

自动形式化的产物有两类典型问题. 一类是太简单, 翻出来的语句平凡到没有训练价值. 处理办法是让模型**自己打分**: 标准包括与当前研究的相关性, 复杂度与深度, 跨学科潜力, 社区缺口, 创新性; 用 miniF2F-valid 的例子做 few-shot, 让模型用 CoT 把语句评成 excellent, good, above average, fair, poor 五档, fair 和 poor 丢弃. 人工抽查认为打分接近人的直觉. 表 3 用等量的高分档和低分档数据分别微调底座, pass@128 下 miniF2F-test 从 38.1% 到 42.6%, valid 从 41.4% 到 48.8%, 差约 4.5 个点. 这个设计有一个副作用: miniF2F-valid 进了打分提示, 它作为评测集的干净程度就打了折扣, 读 valid 分数时比 test 更要谨慎.

打分提示的输出格式在附录 A.1: 模型先把 Lean 代码翻回自然语言, 写出背景, 假设和定义, 再逐条给五个维度写理由, 最后给出总评. 先回译再打分, 实际上又做了一次语义检查, 翻不回通顺题意的语句多半会被打低分. 「与当前研究的相关性」「社区缺口」「创新性」更接近论文评审维度, 对一道练习题未必容易稳定判断; 「复杂度与深度」则能直接排除 `1 + 1 = 2` 一类平凡语句. 报告只说人工抽查结果符合直觉, 没有给出抽查规模、一致率、五档比例以及 fair、poor 的淘汰占比. 表 3 说明整套过滤有效, 但没有比较五维标准与单独使用难度评分的差异.

另一类问题更隐蔽: 语句可以被证明, 但前提自相矛盾, 结论是空虚真. 报告的例子是假设「对所有复数 $z$, $z^2=-1$ 且 $z^3=-1$ 且 $z^6=1$」, 前提本身就假, 推出什么都没有意义. 处理办法是**假设否决**: 把结论换成 `False`, 让模型试证, 证出来就说明前提矛盾, 整条丢弃. §5.2 的行列式案例把这种错误的样子展示得很清楚: 模型把「存在 a, b, c 使行列式为 D」写成「对所有非零 a, b, c, 行列式都等于同一个 D」, 然后代入两组具体值算出不同的行列式, 用 `linarith` 推出矛盾. 这类量词错误在人眼里很像一个正常定理, 靠核验器反证才能稳定抓出来. 两道过滤之后, 87 万道题剩 712,073 条语句.

假设否决有一个结构上的盲区: 它只把冒号后面的结论换成 `False`, 检查的是冒号前面那些假设. 如果矛盾藏在结论内部的蕴含前件里, 或者藏在量词结构里, 这一步就看不见. 附录 A.2 被当作成功样例的两条语句正好说明了这一点. 例 a 要证「若对所有 $x$, $f(x)\le0$ 蕴含 $x<-1$ 或 $x>1$, 则 $a=3$」, 其中 $f(x)=x^3-ax-1$. 但 $f(0)=-1\le0$ 而 $0$ 不在那两个区间里, 所以这个前件对任何 $a$ 都不成立, 整条命题是空虚真. 模型给的证明正是把 $x=0,1,-1$ 代进前件, 再用 `linarith` 收尾. 前件写在冒号之后, 假设否决根本不会去检查它. 例 b 的形式是 `∃ k, f k = … → (∃ m, F m = … → m = k)`, 取 $m=k$ 内层就直接成立, 同样平凡, 证明也只是一行 `simp` 加 `aesop`. 报告对这两例的分析只评价了算子翻译得对不对(区间并, `Nat.choose`), 没有指出语义上已经空了(以上为读附录代码的判断). 这说明 20% 错误率只是下限, 通过核验的语句里仍有一部分在教模型「找平凡出口」.

自动形式化的提示也影响语句形态. 模板里的输入是 `informal_statement_with_answers`, 即题目连同答案一起给模型. 求值题因此被改写成「证明答案是某个数」的形式, 这是把计算题变成可证命题的关键一步; 代价是答案若本身有误, 翻出来的语句就是假命题, 要靠后面的否定并行兜底.

### 1.4. 扩大证明池: 同时证原命题和它的否定

过了过滤, 语句仍然不保证为真. 报告估计即使过滤后, 也至少有 20% 的自动形式化语句是错的. 这在大规模合成里是算力黑洞: 人写的定理基本都成立, 可以放心一直搜; 机器翻出来的假命题, 模型会一直试到超时. 对策利用**命题和否定的对称性**: 对 $\Gamma\vdash P$ 和 $\Gamma\vdash\neg P$ 并行搜索, 各试最多 $k$ 次, 任何一边先找到能通过核验的证明就停. 按尝试次数算一下代价. 只搜 $P$ 时, 真命题在第 $j$ 次证出花 $j$ 次, 假命题一定烧满 $k$ 次. 双路并行时, 真命题在第 $j$ 次证出花 $2j$ 次, 多付一倍; 假命题若否定在第 $j'$ 次证出, 只花 $2j'$ 次, 只要 $j'<k/2$ 就比单路省; 两边都证不出的语句, 代价从 $k$ 变成 $2k$. 所以这套做法划不划算, 取决于假命题占比和否定证明来得多快. 报告没给 $k$ 的取值, 也没给这几类语句各占多少.

这一步同时解决了两件事. 算力上, 假命题通过证出否定被提前判死, 不再烧满超时预算. 数据上, 两边的证明都能进训练池: 证出原命题得到正样本, 证出否定也是一条合法的 Lean 证明, 形式化写错的语句反而变成了训练数据. 和 expert iteration 的原始做法相比, 这是最关键的改动. Expert iteration 默认待证命题都是真的, 只需要不断采样直到证出来; 自动形式化打破了这个前提, 必须给不可证的命题一个出口. 从社区对这篇的讨论看, 「否定并行」也是被引用最多的工程细节, 因为它几乎不增加复杂度, 却把合成流水的效率提高了一截.

否定并行和假设否决分工不同. 假设否决在证明之前把结论换成 `False`, 检查前提是否自洽; 否定并行在证明阶段检查结论本身是否成立. 一条语句可能前提自洽但结论错误, 比如题目要求证明某个方程的解是 3, 模型翻译时把答案写成了 4, 这种错误只能由否定并行发现. 两道关口分别覆盖前提错误和结论错误. 报告没有给出否定一侧的证明比例以及训练池中的否定证明占比. 错误语句超过 20% 也不代表否定证明达到同一比例, 因为不少错误语句可能两侧都搜索失败. 这部分样本训练模型反驳错误命题, 它对只含真命题的 miniF2F 是否有帮助, 报告没有单独消融.

### 1.5. 迭代: 弱模型滚成强模型

四个环节串成闭环: 形式化, 过滤, 证明, 用核验通过的样本微调, 更强的模型再回去做下一轮形式化和证明, 直到收益变薄. 每一轮的变化是双向的: 模型证得更多, 能进训练池的样本就更多, 而且更难的语句也开始有证明; 模型翻译得更准, 下一轮语句的质量也更高. 表 4 给出 pass@128 的台阶: iteration 0 到 4, miniF2F-test 从 34.0% 升到 39.3%, 41.4%, 45.1%, 46.3%, valid 从 38.1% 升到 59.4%. 涨幅逐轮收窄, test 在第 3 到第 4 轮只涨 1.2 个点.

这个闭环本质上是一种没有梯度信号的 RL. 核验器给出 0/1 奖励, 只保留奖励为 1 的样本做监督学习, 相当于 rejection sampling 加迭代. V1.5 的报告后来明确把这层关系说破: expert iteration 和合成数据对应 RL 的试错循环, 编译器是提供环境反馈的世界模型. 和 DeepSeekMath 的 GRPO 相比, 这里没有负样本的梯度, 也没有组内相对优势, 失败的证明被直接丢弃. 这种做法的好处是稳定, 坏处是浪费了失败样本里的信息, V1.5 用 RLPAF 补的就是这一块. 训练设定只给出底座 DeepSeekMath-Base 7B、全局 batch 512、恒定学习率 $1\times10^{-4}$ 和 6000 步 warmup. 每轮训练步数、新增样本数及轮次间的数据混合比例均未公开. 因此表 4 的逐轮提升无法分解为数据规模增加和数据难度提高各自的贡献.

几个数字放在一起能粗看训练量级. 光 warmup 就是 6000 步 × 512 条, 约 307 万条样本, 相当于 800 万条数据的四成, 说明每轮微调不是轻量的几百步. 表 2 里自动形式化那一行写的训练量是 3.108B token, 如果它对应的是全部证明样本, 平均每条约 390 token, 这和附录里那些十行以内的短证明在量级上吻合. 和 DeepSeekMath 500B token 的续训相比, 形式证明这一步的训练量小了两个数量级, 模型能力的底子仍在数学预训练里.

过滤后的语句是 712,073 条, 最终数据集却有 8,066,621 条, 贡献列表还写着「800 万条形式语句, 每条都带一个形式证明」. 两个数相差十多倍, 报告没有分解其来源. 可能因素包括跨轮累积、同题多种形式化、同一语句的多个证明以及否定侧证明. 即使按 5 轮、每轮 71 万条粗算, 总量也只有约 350 万, 因而数据集中必然还存在一题多译或一句多证. 这里的「800 万」更适合按证明样本数理解, 不能直接当作 800 万道不同题目.

## 2. 从自然语言到 Lean：翻译的对象究竟是什么

### 2.1. 形式化不是逐句翻译

一道竞赛题交给人时，许多约束藏在常识里：分母默认不为零，三角形边长默认取正，所谓“根”通常落在实数域，题目给出的数值答案还暗含“要求证明它恰好等于这个数”。Lean 不接受这些省略。自动形式化模型真正要完成的，是把自然语言问题还原成一个类型正确、量词范围明确、库中对象可用的命题。若自然语言题面记为 $x$，Lean 声明记为 $s$，训练数据需要的映射是

$$
p_\theta(s\mid x),
$$

但“能够编译”只约束 $s$ 的语法与类型，“与题意相同”还要求语义保持。前者能由 Lean 精确判断，后者没有现成的自动判定器。这正是整条流水线最难的一处：证明一条 Lean 命题与证明它正确表达原题，是两个不同任务。 以求值题为例，“$120\%$ 的 $30$ 与 $130\%$ 的 $20$ 的正差是多少”可以写成实数上的绝对值等式，也可能被写成自然数除法。两段代码都可能通过类型检查，含义却完全不同，因为自然数除法会截断。类似问题还出现在幂、区间、有限集合与矩阵维数上。模型必须选定数域，补齐类型转换，再从 mathlib 中找到相符的定义。于是自动形式化能力至少包含四层：识别数学对象、恢复隐含条件、选择库表示、生成能够通过 elaboration 的 Lean 代码。

DeepSeek-Prover 的冷启动数据 MMA 走了一条反向路线：先从 mathlib 中取已经形式化的声明，再让 GPT-4 写出自然语言版本，由此获得配对数据。这种配对天然保证 Lean 一侧可编译，却不能保证自然语言侧完整保留了量词、类型与边界条件。用它训练出的模型再去翻译真实竞赛题，会继承这种“形式端可靠、语义对应关系较弱”的偏差。因此论文后续同时使用模型评分、假设否决与证明搜索；三者分别过滤低价值命题、前提矛盾和无法找到证明的命题，但仍没有一个步骤直接证明 $x$ 与 $s$ 等价。

### 2.2. 量词、前提与答案如何改变命题

自然语言中的“存在”“任意”“唯一”对应不同的 Lean 类型结构。把“存在某个 $x$ 使 $P(x)$”写成 `∀ x, P x` 会把弱命题变成强命题；反过来则会把原题削弱到容易成立。蕴含的方向同样危险，$P\to Q$ 与 $Q\to P$ 都能编译，甚至都可能恰好可证。验证器只能回答生成的命题是否被给出的证明建立，无法依据原题判定箭头方向。

带答案的题目又多一层转换。流水线输入字段包含题面与答案，模型常把“求 $a$”改写成“证明 $a=c$”。这使开放式计算任务变成闭合命题，也让验证器可以工作。代价是答案成了声明的一部分：若抓取答案错误，模型可能生成一个假命题；若形式化时无意中把答案写入前提，命题又会退化成循环论证。一个看似漂亮的证明可能只是 `exact h`，因为目标早已作为假设出现。

论文展示的错误案例说明，语义退化往往比语法错误更隐蔽。前提矛盾时，由爆炸原理可以推出任意结论；存在量词的见证若能从结论结构中机械选取，也可能让原题的数学内容消失。因而数据质量不能只看验证通过率。更有解释力的分层应当是：代码能否 elaboration、命题是否自洽、形式命题是否忠实于原题、证明是否利用了题目的关键结构。DeepSeek-Prover 对前两层做了大规模自动检查，对第三层主要依赖模型评分和少量人工观察，对第四层没有系统指标。

### 2.3. mathlib 既是词典，也是归纳偏置

Lean 代码从来不在真空里运行。`import Mathlib` 提供定义、定理和自动化 tactic；`import Aesop` 又扩大了自动搜索能力。模型看到的目标虽只有几行，背后可以调用的是一个庞大的人工知识库。于是模型生成 `nlinarith`、`ring_nf` 或 `norm_num`，并不表示它逐步重建了人类证明；它可能只识别出目标属于某类可判定片段，然后把剩余工作交给 tactic。

这并非缺陷。形式证明的价值本来就包括复用可信库，只是评价“推理能力”时要分清模型贡献与库贡献。若换一个 mathlib 提交版本，引理名称、类型签名和简化规则发生变化，同一段生成结果可能失败。若改变导入前缀，自动化 tactic 的搜索空间也会变化。论文固定 Lean 4 与 mathlib 版本，实际上固定了任务环境；模型学到的不只是数学，还包括该环境中的 API、惯用证明风格和 tactic 可达性。

这种依赖解释了为何大规模合成数据有效。七十多万条声明覆盖了大量类型组合和库调用，八百多万条证明又为同类目标提供多种短程序。模型反复见到“目标形状—tactic 组合”的对应关系，逐渐形成形式语言里的操作先验。它在 miniF2F 上的提升既来自数学底座，也来自对 Lean 生态的熟悉程度。

## 3. 验证器反馈：拒绝采样、SFT 与隐含目标

### 3.1. 二值验证提供了罕见的硬标签

自然语言数学答案通常需要另一个模型评判，形式证明则可以交给小型可信内核。对声明 $s$ 和候选证明 $y$，验证器给出

$$
r(s,y)=\mathbf{1}[\operatorname{Lean}(s,y)=\text{accepted}].
$$

这里的 $1$ 意味着证明项在给定环境中类型正确，所有证明义务已经闭合。它不依赖人类偏好，也不需要奖励模型猜测文字答案。这种精确反馈使大规模拒绝采样成为可能：从当前模型采样许多候选，只保存 $r=1$ 的序列，再用普通交叉熵训练下一轮模型。 若第 $t$ 轮模型为 $p_{\theta_t}$，通过验证的集合为 $D_t^+$，下一轮近似优化

$$
\mathcal L_{t+1}=-\sum_{(s,y)\in D_t^+}\log p_{\theta}(y\mid s).
$$

失败样本没有直接进入损失，反馈通过“能否留在训练集”发挥作用。把它称作 expert iteration 更准确：当前策略负责寻找新证明，验证器挑出成功轨迹，监督学习再模仿这些轨迹。它与策略梯度共享“采样—奖励—更新”的闭环，但 V1 没有对失败轨迹计算负优势，也没有在线优化期望奖励。

### 3.2. 拒绝采样会偏向短证明与熟悉题型

验证器的标签精确，采样过程仍然带来选择偏差。假设某命题在一次采样中成功的概率是 $q$，尝试 $k$ 次后至少得到一个证明的概率为

$$
1-(1-q)^k.
$$

当 $q$ 较大时，少量尝试便能稳定收集样本；当 $q$ 极小时，把预算扩大几十倍也未必得到一条证明。新数据因此集中在当前模型已经接近会做的题上。迭代能沿能力边界向外推进，却很难跨过需要全新表示或长链规划的空白区。 证明长度进一步放大这一偏差。整证生成要求一次输出从 `by` 到结尾的完整程序，只要中间一个标识符、类型转换或 tactic 参数错误，整条轨迹就被丢弃。若每个局部片段正确的条件概率约为 $p$，包含 $L$ 个关键决策的证明，其粗略成功率会随 $p^L$ 下降。短证明、强自动化 tactic 能处理的证明更容易进入数据集，长证明则更难获得第一批正样本。

这解释了训练集为何会形成自增强：模型先在代数化简、线性算术等区域取得较高成功率，这些区域生成更多验证通过的样本，下一轮又进一步强化相同技能。若不控制题型和难度分布，八百万条证明并不等价于八百万份彼此独立的数学知识，许多样本可能围绕相近的声明形状和 tactic 套路聚集。

### 3.3. 验证正确不等于训练目标完整

Lean 内核能排除语法错误、未闭合目标和类型不一致，却无法判断证明是否有教学价值，也不会惩罚命题本身的语义退化。一个从矛盾假设推出结论的证明完全合法；一个依靠强自动化一行结束的证明也完全合法。对生成模型来说，它们同样得到 $r=1$。 因此流水线实际上同时优化三个目标：证明可验证、样本容易被当前模型找到、形式命题通过质量筛选。第一个目标严格，后两个由采样分布和评分模型间接决定。若评分模型偏爱表面复杂的声明，或漏掉藏在内层蕴含中的矛盾，验证器不会替它修正语义判断。V1 的关键贡献是证明了硬验证可以把合成规模推到百万级；它也清楚暴露出“可验证性”与“题意忠实度”之间仍有一道缺口。

## 4. 整证生成、搜索预算与 pass@k

### 4.1. 一次生成完整证明意味着什么

V1 采用 whole-proof generation：给定完整声明，模型一次写出整段 Lean 证明，随后统一编译。它避免了每生成一个 tactic 都与 Lean 往返交互，适合把大量候选放进批处理流水线。对短小竞赛题，这种方法很直接；模型常先用 `intro` 或 `induction` 建立结构，再由 `norm_num`、`ring`、`linarith`、`nlinarith`、`aesop` 收尾。 它失去的是中途纠错。若第三步产生的局部状态已经偏离目标，模型在后续 token 中看不到 Lean 的报错，也不知道当前还剩哪些子目标。整证生成只能依靠训练时学到的隐式状态估计。树搜索方法则在每一步执行 tactic，拿到新 proof state 后再扩展节点。两条路线的差别可以写成：整证模型近似 $p(y\mid s)$，交互式模型分解为

$$
p(a_{1:T}\mid s)=\prod_{t=1}^{T}p(a_t\mid z_t),
$$

其中 $z_t$ 是 Lean 执行前 $t-1$ 步后的真实状态。后者反馈更密，代价是每条路径都需要多次调用证明器，并维护分支与回溯。

### 4.2. pass@k 衡量覆盖率，不直接衡量单次可靠性

对 $N$ 道题，每题生成 $k$ 个候选，最朴素的经验 pass@k 为

$$
\operatorname{pass@}k=\frac1N\sum_{i=1}^{N}\mathbf 1\!\left[\sum_{j=1}^{k}r_{ij}>0\right].
$$

它回答“给足 $k$ 次机会后能覆盖多少题”。随着 $k$ 增大，这个数单调不降；它混合了模型单次成功率与样本多样性。若模型总生成同一个高概率错误，增加预算没有帮助；若成功证明概率很低但候选差异较大，大采样预算可能不断找到新题。 论文从 $64$ 次增到 $65{,}536$ 次时，测试集只从 $46.3\%$ 提升到 $50.0\%$。这说明剩余题目里相当一部分并非“再抽几次就能碰中”，而是模型分布几乎不给正确证明概率。单纯扩大采样在这里已经接近饱和。累计 $52.0\%$ 又汇总了多组实验找到的证明，其预算口径与固定 $k$ 不同，适合表示曾经覆盖过的题集，不宜当成一次部署的 pass@k。

### 4.3. 双向证明搜索的收益与边界

对自动形式化命题同时尝试 $P$ 和 $\neg P$，把真假判断转化为两个证明搜索任务。若任一侧产生可验证证明，流水线便得到确定标签和一条训练轨迹。这种做法利用了经典竞赛命题通常有明确真值，也减少了把算力长期耗在错误翻译上的情况。 但“双向都找不到”没有确定含义。它可能表示命题独立于当前环境，更多时候只表示模型能力或采样预算不足。双向都找到在一致的 Lean 环境中原则上不应发生；一旦发生，应先检查是否两边的声明预处理不同、是否引入了不安全公理，或数据拼装是否出错。论文没有公开各类结果的比例，使读者无法估算这项设计究竟节省了多少预算，也无法判断否定证明在最终训练集中的权重。

### 4.4. V1.5 如何补上 V1 看不到的中间状态

V1 的整证生成把 Lean 当作终点裁判，V1.5 则把证明状态引入训练与搜索。下面沿着状态转移、截断续写、RLPAF 与 RMaxTS 四层展开；这些机制属于后续版本，用来解释 V1 的能力边界，不能倒算成 V1 已经采用的训练方法。

### 2. Lean 证明状态与整证生成

#### 2.1. 定理证明在 Lean 中是什么状态转移

Lean 中的定理声明给出目标命题, tactic 执行后把当前目标改写为零个或多个子目标. 一个证明状态可抽象为:

$$
s_t=(\Gamma_t\vdash g_{t,1},\ldots,\Gamma_t\vdash g_{t,m}),
$$

$\Gamma_t$ 是局部变量、假设与可用定义, $g_{t,i}$ 是尚未完成的目标. tactic $a_t$ 交给 kernel 与 tactic engine 后, 得到 $s_{t+1}=T(s_t,a_t)$. 若 tactic 不适用、类型不匹配或超时, 转移失败; 当目标列表为空时, Lean 接受证明项. 这个状态与普通自然语言推理不同. 一句解释可以大致正确, tactic 必须在精确类型与上下文中合法. `nlinarith` 可能一次关闭目标, `constructor` 会把合取拆成两个目标, `have h : P := ...` 会增加局部事实. 模型要跟踪的不只是结论, 还有变量类型、命名、可见假设和当前焦点. Lean 的 kernel 检查最终证明项, tactic 是构造证明项的程序. 验证通过意味着在当前 Lean 版本、导入库与选项下类型检查成功. 它保证形式语句被证明, 不保证形式语句忠实表达原始自然语言题目. miniF2F 已经提供形式化 theorem, V1.5 主要解决 proof synthesis, 没有评估自动形式化正确性.

#### 2.2. 整证生成为什么缺少真实状态

整证模型看到初始 theorem, 一次生成完整 `by ...` 代码. 在生成第 $t$ 条 tactic 时, 它没有实际运行前 $t-1$ 条, 只能从 token 前缀推测 Lean 会得到什么状态. 若前面 tactic 产生了意外子目标、名称不同或类型化简方式不同, 后续代码建立在错误心智状态上. 设模型内部预测状态为 $\hat s_t$, 真实执行状态为 $s_t$. 即使 $a_t$ 对 $\hat s_t$ 合法, 也可能不属于真实合法动作集 $\mathcal{A}(s_t)$. 一旦失败, 后续 token 仍以文本中的错误动作作条件, 整段通常无法恢复. 这就是 compounding error 在形式证明中的具体形态. 逐步 prover 每次只生成一个 tactic, 立即得到 $s_{t+1}$. 它不需要长期脑补状态, 代价是模型—Lean 往返频繁, 每一步都要调度与验证. 整证生成用较少交互换取更长开环控制. 截断续写把两者组合: 先开环走多步, 出错后从最后真实状态闭环纠正.

整证模式还有搜索粒度优势. 一次 sample 可以包含一个完整数学思路, 高层 tactic 会在内部完成大量推理. 逐 tactic 搜索更容易组合局部动作, 也可能在浅层分支迅速膨胀. 哪种方式更好取决于模型能否生成长合法前缀、tactic 自动化强度与 Lean 验证成本.

#### 2.3. tactic state 注释提供了什么

状态注释把 Lean 返回的目标以文本形式插入 prompt, 使模型直接条件化真实 $s_t$. 例如当前上下文包含 $h:0<x$、目标为 $12(x\sin x)\le 9(x^2\sin^2x)+4$, 模型可识别右减左等于平方, 再生成 `nlinarith [sq_nonneg ...]`. 状态文本连接了形式 kernel 与语言模型. 状态序列也构成训练监督. 在合法证明的每条 tactic 前后抽取状态, 模型学习「给定 theorem、已验证前缀和当前目标, 下一段代码是什么」. 截断续写时输入格式与 SFT 中的状态注释接近, 减少训练—推理分布差异. 若只在推理时突然加入状态文本, 模型可能把它当普通注释而不会利用. 状态注释不是完美的 Markov 状态. tactic 行为还依赖环境中的导入、namespace、attribute、局部 notation、options 与 elaborator 状态. 论文给每题固定文件头, 在 miniF2F 范围内文本状态足够实用. 扩展到大型 Lean 文件时, 当前目标之外的环境依赖会更复杂.

状态文本还可能很长. 多个子目标、复杂类型和大量局部假设会占用 2048 token 生成预算. 截断前缀、CoT 注释与状态一起增长, 留给新证明的空间缩小. 论文没有报告 prompt 长度分布和上下文截断策略, 长证明外推边界不明.

#### 2.4. 合法状态、等价状态与重复搜索

不同 tactic 序列可以到达相同目标集合. `simp [h]` 与若干 `rw` 可能得到等价状态, 变量名和表达式正规形又可能不同. RMaxTS 需要判断「新状态」, 若只按原始字符串去重, alpha-renaming 或 pretty printer 差异会被当成新奇; 若做过强正规化, 可能合并仍有不同局部环境的状态. 论文说明同一状态节点可以存多条等价 tactic 代码, 表明实现做了状态合并. 官方代码负责从 LeanDojo/REPL 抽取状态并维护树. 公开报告没有完整形式化状态等价关系. 因而内在奖励的有效性也依赖工程中的状态键: 键太细会奖励伪新奇, 太粗会丢失真实分支.

失败状态同样有信息. 语法错误、unknown identifier、tactic failed 和 timeout 指向不同问题. 截断续写主要保留第一条错误之前的成功前缀, 把最新合法状态作为恢复点, 并没有把错误类型作为显式奖励或 critic. 模型可能从代码与状态推断, 搜索器本身只看是否加入新节点和是否完成证明.

#### 2.5. 证明正确、证明短与证明可读是三件事

Lean 0/1 奖励只关心是否通过. `interval_cases` 穷举、强自动化 tactic 与结构清晰的引理链都可能同得 1. 这使 RL 信号客观且难被自然语言奖励模型误判, 同时不奖励简洁、可维护和数学解释一致. CoT 注释不进入 kernel, 错误解释不会阻止代码通过. 注释可能帮助模型规划, 也可能是事后包装. 若评估目标是机器可验证证明, 通过率足够; 若目标还包括人类教学与库维护, 需要额外检查注释忠实、证明长度、依赖与 tactic 鲁棒性. `set_option maxHeartbeats 0` 允许高成本自动化一直运行到外部 300 秒超时. 一段短代码可能消耗大量 Lean 搜索, token 短不等于验证便宜. 证明效率应同时报告生成 token、Lean 时间和 kernel term 大小. 论文主要按生成次数与成功率比较, 没有给这些维度.

#### 2.6. 用一个小例子走过状态变化

考虑 theorem: 对实数 $x$, 若 $h:x=3$, 证明 $x^2=9$. 初始状态可写为:

$$
x:\mathbb{R},\ h:x=3\ \vdash\ x^2=9.
$$

执行 `rw [h]` 后, Lean 用等式重写目标, 得到 $\vdash 3^2=9$. 再执行 `norm_num`, 目标关闭. 逐步 prover 在第一步后直接看到新状态; 整证模型要生成 `rw [h]` 时预想重写结果, 再决定 `norm_num` 可用. 如果模型误写 `rw [← h]`, Lean 可能把目标中的常数 3 反向改成 $x$, 产生与预期不同的式子或找不到匹配. 整证后面的 `norm_num` 仍会被生成, 最终验证失败. 截断续写定位到错误行, 保留此前合法前缀, 把真实目标插回 prompt, 新 rollout 可以改用 `norm_num [h]` 或正确重写. 再看会分叉的 `constructor`. 目标 $P\land Q$ 执行后变成两个 goals. 模型若只记住第一个, 写完 $P$ 就提前结束, Lean 仍显示 $Q$. tactic state 注释把全部未完成目标列出来, 比自然语言 CoT 更可靠. 这也是状态监督对多目标证明尤其有价值的原因.

#### 2.7. 高层 tactic 把搜索藏到了哪里

`simp`, `aesop`, `linarith`, `nlinarith` 和 `omega` 内部会做重写、规则搜索或决策过程. 模型输出一个 token 序列动作, Lean 内部可能探索大量候选. V1.5 的外层树只看 tactic 前后状态, 看不见内部搜索树. 高层 tactic 降低模型动作长度, 也把算力转移到 CPU verifier. `nlinarith` 处理算术题很强, 对不适用目标会失败或耗时. 模型学习何时调用哪个 tactic, 相当于学习搜索算法的调度. 这部分能力可以通过 SFT 大量成功 proof 获得. pass@k 因此不只衡量数学规划. 它还衡量模型记忆 tactic 语法、选择自动化、提供必要引理和避免超时. 一个证明用一行自动化通过, 可能比十行人工式 proof 更容易采样, 也更依赖 Mathlib 与 tactic 实现版本.

#### 2.8. Lean 版本与库版本为什么进入实验定义

Lean elaborator、tactic 和 Mathlib lemma 会随版本变化. 同一代码在 4.7 与 4.9 可能因名称、类型推断或 tactic 行为不同而通过或失败. V1 与 V1.5 使用的环境不同, 直接把分数差全归模型不严谨. benchmark 转换从 Lean 3 到 Lean 4 也可能改变语句与可用证明. 手工转换能修复语法, 仍需检查 theorem 语义等价. 报告没有发布逐题转换审计. 公开代码使后来者可以固定文件与 commit 重跑, 这是复现的必要条件. few-shot 示例也属于环境. Base 在 ProofNet 使用 RL 生成的正确 proof, 相当于从后续模型获得 prompt 资产; SFT/RL 则零样本使用专用引导. 表格比较最终设置, 不是严格相同 prompt 条件的 checkpoint 对照.

### 3. 树搜索: 截断续写与 RMaxTS

#### 3.1. 截断续写: 把整证拆成搜索树

**截断续写**(truncate-and-resume)的流程是: 模型照常写完整段证明, 交给 Lean; 全对就结束; 有错就在第一条错误处截断, 丢掉后面的代码, 把成功的前缀加上 Lean 返回的最新 tactic 状态注释, 作为下一轮的提示(源文 §1, §3.1). 截断出来的前缀按 tactic 切开, 每条 tactic 连同它前面的 CoT 注释构成搜索树的一条边, 代表一次状态转移. 这样整证生成就有了一个状态-动作接口, 树搜索可以挑任何一个节点续写, 不必只从最后一条成功的 tactic 往下接.

几个细节是为 Lean 的特点定制的. 不同 tactic 写法可以到达同一个状态, 所以每个节点存一组等价的 tactic 代码, 续写时随机抽一条当前缀. 一次扩展模型会写出多条 tactic, 所以一次扩展可能往树里插入一整条节点路径, 这和 AlphaZero 那类棋类 MCTS 每轮只扩一层不同. 选择阶段用了 virtual node: 每个节点带一个虚拟子节点, 选中它就表示「就在这里扩展」, 于是非叶节点也能被反复扩展. 这对生成模型是必要的, 因为同一个节点能续写出的内容没有上限, 不能像棋盘那样把合法着法列全. 附录 A 的 `aime_1983_p9` 展示了续写时模型看到的东西: 提示末尾的注释写着当前目标 `12 * (x * x.sin) ≤ 9 * (x ^ 2 * x.sin ^ 2) + 4`, 模型在 CoT 里把它整理成 $(3x\sin x-2)^2\ge0$, 最后一行 `nlinarith [sq_nonneg (3 * x * Real.sin x - 2)]` 收尾.

和纯逐步搜索相比, 这套接口每次扩展只调一次模型, 一次 Lean 验证, 却可能推进多步, 通信密度低得多. 代价是每次验证都要把整段前缀连同新代码一起交给 Lean 重新检查, 前缀越长, 单次验证越贵, 报告没有给单次验证的平均耗时. 和纯整证重采样相比, 它保住了已经验证过的前缀, 同一道题的第二百次尝试不必再从头写 `have h1 : 0 < x * Real.sin x`. 同一套训练目标既能单遍采样又能进树搜索, 报告把这当作方法的主要结构贡献(源文 §3.5), 部署时可以按算力在两者之间切换, 不用维护两套模型.

MCTS 的四步里, 模拟被并进了扩展: 整证生成模型从被选节点往下写到底, 本身就是一次 rollout. 回传时沿本轮的选择路径, 对每个 $(s,a)$ 更新两项统计: 经过它的轨迹数 $N(s,a)$ 和这些轨迹的奖励和 $W(s,a)$, 利用项取 $W/N$, 探索项是随访问次数衰减的 UCB 奖励. 式 4–6 是 UCB1 的原始写法, 实际采用的是式 7–9 的折扣版, 越早的轨迹权重越低. 外在奖励只有证完时的 1, 所以在找到证明之前, $W$ 全部来自下一节的内在奖励. 这里的「动作」包括虚拟节点代表的「就地扩展」, 所以一个节点被反复选中扩展, 统计也会累积在它的虚拟子节点上.

#### 3.2. RMaxTS: 没有外在奖励时靠新状态指路

树搜索的外在奖励只有一种: 整题证完给 1, 否则 0. 证完之前所有节点的价值估计都是 0, 标准 UCT 此时只按访问次数挑节点, 和盲目展开差不多. **RMaxTS** 借用 RMax 的想法: 一次扩展只要往树里加了至少一个新节点(也就是看到了新的 tactic 状态), 内在奖励就是 1, 否则是 0(式 3). 证完之前轨迹奖励完全由内在奖励决定, 流程接近 ZeroRMax. 同一状态可以由多种代码到达, 奖励「新状态」而不是「新代码」, 能减少写法不同但状态相同的重复生成.

内在奖励有一个特点: 树越大, 越难碰到新状态, 奖励的期望随搜索进行不断下降, 是非平稳信号. 标准 UCB1 假设奖励分布不变, 靠大量访问逐渐收敛, 有限预算下, 早期积累的高奖励记录会一直压着估计值. 所以报告改用折扣 UCB(DUCB, 式 7–9), 每来一条新反馈, 旧记录按 $\gamma=0.99$ 衰减. 内在奖励和两种 UCB 分别写成:

$$
R_{\mathrm{intrinsic}}(\tau)=\mathbb{I}[\text{本次扩展至少向树中加入一个新节点}],
$$

$$
Q_{\mathrm{UCB1}}(s,a)=\frac{W(s,a)}{N(s,a)}+\sqrt{\frac{2\ln\sum_{a'}N(s,a')}{N(s,a)}},\qquad W=\sum_{\tau\in\Gamma(s,a)}R(\tau),\ N=|\Gamma(s,a)|,
$$

$$
Q_{\mathrm{DUCB}}(s,a)=\frac{W_\gamma(s,a)}{N_\gamma(s,a)}+\sqrt{\frac{2\ln\sum_{a'}N_\gamma(s,a')}{N_\gamma(s,a)}},\qquad W_\gamma=\sum_{t=1}^{N(s,a)}\gamma^{N(s,a)-t}R(\tau_t),\ N_\gamma=\sum_{t=0}^{N(s,a)-1}\gamma^t.
$$

$\Gamma(s,a)$ 是经过 $(s,a)$ 的所有轨迹. UCB1 的利用项是历史奖励的算术平均, 前一百次扩展都拿到新节点, 后一百次都没拿到, 均值仍是 0.5. DUCB 的 $W_\gamma$ 给第 $t$ 条轨迹乘 $\gamma^{N-t}$, 最近一条权重 1, 一百条之前约 0.37, 利用项变成近期奖励的加权平均, 上例会掉到约 0.27. $N_\gamma$ 是同一组权重之和, 上界是 $1/(1-\gamma)=100$, 访问再多也不超过 100, 所以探索项不会像 UCB1 那样随 $N\to\infty$ 趋于 0, 被冷落的分支总保有一份被重新选中的机会. 这两处合起来, 就是「新状态挖空的节点价值很快降下来, 让位给别处」的具体实现. 这里的折扣作用在搜索迭代轮次上, 不是单条轨迹内部的时间步, 和 MDP 里的折扣因子含义不同, 报告专门提醒了这一点.

这套内在奖励属于强化学习里基于计数和新奇度的探索家族, 报告引用了 Bellemare 等的伪计数和 Burda 等的 RND. 这类方法有一个老问题: 新奇不等于进展. 在证明搜索里, 一条 tactic 把目标改写成更复杂的形式, 或者引入一个无关的中间结论, 同样会产生新状态, 同样拿到奖励 1, 搜索会被引向这些方向. RMaxTS 没有任何机制区分「离证完更近的新状态」和「只是不一样的新状态」, 这正是结论节说缺一个 critic 的原因. 在 miniF2F 这种短证明为主的集合上, 这个问题不严重, 因为证明树本来就浅; 证明一旦变长, 无差别的新奇奖励可能会让树横向铺得很宽.

并行化决定了这套方法能不能跑起来(源文 §3.4). 每个计算节点起 256 个 MCTS runner, 每张 GPU 一个模型, 生成 batch 512; Lean 通过 REPL 调用, 跑在数千核的 CPU 集群上, 每次验证一个沙箱进程, 生成和验证都是异步的. 每棵树 32 个线程并发做选择-扩展-验证-回传, 进行中的迭代先回传虚拟奖励 0(virtual loss), 避免多个线程挤到同一节点. 报告没有给出总 CPU 核时和 GPU 时.

#### 3.3. 截断点怎样决定可复用前缀

生成结果交给 Lean 后, 系统定位第一条失败 tactic. 失败前所有 tactic 已被验证, 可以作为树中的合法路径; 失败行及其后续全部丢弃. 若一条复合 tactic 内部部分成功后失败, 对外仍通常表现为该命令失败, 复用粒度受语法命令边界限制. 粒度太粗会丢掉复合 tactic 内部进展, 太细会增加状态数与验证交互. V1.5 以 tactic 位置切分, 借 LeanDojo 获取前后状态, 是源码结构与搜索成本之间的折中. 宏、`all_goals` 和组合符可能让一行改变多个目标, 文本行数也不等于一步逻辑推理. 前缀复用需要保证环境确定. 同一文件头、Lean 版本、Mathlib commit 和 options 下, 重放前缀应得到相同状态. 若 tactic 依赖超时、外部 oracle 或不同库版本, 缓存状态可能失效. 论文固定 Lean 4.9.0 与导入, 使 benchmark 内重放可控.

截断也能把超长失败证明压回最近合法点. 但 prompt 会包含前缀代码、注释和状态, 多次续写后仍可能接近上下文上限. 搜索器没有压缩形式证明语义的独立模块, 长文件需要更长上下文或结构化状态存储.

#### 3.4. virtual node 为何允许反复扩展同一状态

开放文本动作空间不能预先枚举. 第一次从状态 $s$ 采样得到 `nlinarith`, 没有理由认为其他可行 tactic 已经穷尽. virtual node 相当于保留一个永远存在的「再问模型一次」动作, 被选择时生成新的候选. 真实子节点代表已发现状态转移, virtual child 代表尚未采样的潜在转移. UCB 统计决定是沿已有分支深入, 还是从某个旧状态再开新分支. 如果没有 virtual child, 一个节点首次展开后就封闭, 语言模型的随机性无法被持续利用. virtual loss 用于并行. 某线程选择节点后先临时降低其吸引力, 其他线程倾向别处, 等验证返回再用真实奖励覆盖. 它提高树的并行多样性, 也可能让本应集中探索的强分支暂时被冷落. 论文给出 32 线程设置, 没有并发数消融.

#### 3.5. 状态合并与路径依赖的张力

从 Lean 看, 两条代码前缀到达同一 proof state 后, 未来合法 tactic 集大体相同. 从语言模型看, prompt 中前缀文字、CoT 和命名不同, 后续分布可能不同. RMaxTS 将等价代码存到同一节点, 续写时随机选择一条前缀, 在状态合并与文本多样性之间折中. 如果只保留一条最短前缀, prompt 更省 token, 可能丢掉有用的自然语言计划. 如果所有前缀都建独立节点, 树会被同状态重复占满, 新奇奖励失真. 多前缀单状态让 Lean 语义去重, 同时保留若干模型上下文. 这种设计也说明搜索不是纯 MDP. 理论状态 $s$ 若只取 Lean goal, policy 还依赖达到它的文本历史 $h$. 更完整状态应是 $(s,h)$, 合并时忽略了部分 $h$. 实验显示这种近似有效, 没有证明对长证明同样成立.

#### 3.6. DUCB 的有效记忆长度

$\gamma=0.99$ 时, 距当前 $k$ 轮的权重为 $0.99^k$. 约 69 轮后降到一半, 229 轮后约 0.1. 有效样本数上限 100, 意味着选择器主要反映最近数百次扩展, 不让早期容易获得的新奇永久支配. 探索项中的折扣计数也有上界, 已访问很多次的分支仍保留非零探索奖励. 对非平稳新奇信号合理, 对稳定外在成功概率则可能过度探索. 任务一旦找到证明立即停止, 没有长期利用已知成功分支的问题. $\gamma$ 控制适应速度. 更小值更快忘记, 对噪声更敏感; 更大值更稳定, 节点挖空后转移慢. 论文固定 0.99, 没有 sensitivity study. 完整 RMaxTS 的优势可能依赖 benchmark 证明树尺度与这个有效窗口匹配.

#### 3.7. 新状态奖励可能出现哪些反例

第一类是循环改写. tactic 在两个等价表达式间来回转换, 若状态正规化不足, 每次都可能被当新节点. 第二类是无关 `have`, 不推进主目标却扩充上下文. 第三类是目标爆炸, 一个 tactic 把一个目标拆成很多更难子目标, 仍因新状态得分. Lean 会阻止非法动作, 不能判断数学进展. 计数新奇类似探索未知房间, 房间多不代表接近出口. miniF2F 中高层自动化常能从一个有用中间状态直接收尾, 新奇是尚可接受的代理; 大型库证明可能需要长时间沿一条看似不新奇的路径积累引理. 引入 learned critic 可估计从状态完成的概率, 但训练标签昂贵且可能偏差. 可用搜索回报训练 value, 又形成自举误差. V1.5 选择零 critic 的 RMax, 保持验证信号纯净, 用更大搜索宽度换方向性.

#### 3.8. 为什么小预算看不到树搜索收益

建树初期要重复发现合法前缀、抽取状态并估计分支新奇. 独立整证 sample 则从第一份预算起就有机会直接命中. 若题目短、模型单遍成功概率不低, 初期树管理成本难以回收. 只有当多次 sample 反复共享某些正确前缀, 且失败点之后存在多种续写, 前缀复用才优于重开. 大预算提高遇到这类题的机会. 表中 3200 次差不到一题, 4×6400 与 16×6400 才逐渐拉开, 与这个门槛一致. 这也限制个人复现. 单题数千 sample 时, 使用 RL checkpoint 做 independent sampling更简单; 若 CPU 验证远慢于 GPU 生成, 树搜索的反复前缀验证还会受瓶颈. 论文的异步数千核环境把这些延迟隐藏在并行中.

#### 3.9. 异步执行会怎样改变树

32 个线程从同一棵树并发选择节点, GPU 批量生成, CPU Lean worker 的完成顺序取决于证明长度与 tactic 耗时. 快速失败可能先回传, 慢而正确的证明稍后到达. 树在等待期间已经被其他结果更新, 选择策略是异步近似. virtual loss 防止重复选择, 其数值会临时影响其他线程. 并发越高, 临时统计越多, 树与串行 UCB 的路径差异越大. 高并发换吞吐, 同时增加调度随机性. 论文报告系统设置, 没有串行/并行质量对照. 批量生成要求把来自不同 theorem 和状态的 prompt 拼 batch. 长度差导致 padding, CoT prompt 更长. GPU 利用率与生成延迟受 batch composition 影响. 数千 CPU 核负责验证, 整体吞吐取决于 GPU proposal 与 Lean 消费是否平衡. 若 Lean 成为瓶颈, 新候选在队列等待, 搜索统计滞后; 若 GPU 慢, CPU 闲置. 论文没有队列、吞吐和利用率, 所以算法预算无法直接转换为墙钟.

#### 3.10. 搜索树中的证明多样性

同一 theorem 可以有代数、几何或自动化等不同 proof. 独立采样通过随机 token 获得多样性, 树搜索还通过状态选择分散分支. 新奇奖励倾向覆盖更多 state, 理论上能提高结构多样性. 状态多样不等于 proof 多样. 两个不同中间状态可能最终都调用同一自动化 tactic, 两段不同代码也可能 kernel term 接近. 论文只统计是否至少一证, 没报告 unique proof、state coverage 或 tactic entropy. 多样性对 pass@k 有直接价值. 如果 sample 完全重复, 增加 $k$ 没有收益; 如果不同 proof 失败独立, 覆盖更快上涨. RL 的 KL 与 CoT/non-CoT 混合可能保持多样性, RMaxTS 新奇则显式扩展状态. 大预算曲线继续上涨说明系统没有完全塌缩.

#### 3.11. 搜索终止与证明发布

任何 rollout 得到 Lean 通过后, 当前 theorem 搜索可以立即结束. 最终 proof 是从根到成功节点的某条前缀加新生成后缀. 搜索中的其他分支和错误注释不会进入发布证明. 若多个线程同时成功, 可以选择先返回者、最短 proof 或验证成本更低者. 论文以 solved/unsolved 计分, 没说明多个成功 proof 的选择标准. 这不影响 pass, 会影响可读性与复现输出. 验证通过还应在干净进程重放, 防止 REPL 状态泄漏. 沙箱进程与固定导入有助于隔离. 官方系统以 Lean 为最终裁判, 具体发布 pipeline 在论文中不详细.

#### 3.12. 没有 critic 时的理论直觉

标准 UCT 用平均终局回报估计动作价值. 在稀疏证明任务中, 找到第一条 proof 前所有外在回报为零, exploitation 无信息. RMaxTS 把「发现未见状态」当乐观回报, 类似 RMax 对未知状态赋最大值, 使搜索优先完成状态空间覆盖. 一旦某区域被反复扩展, 新状态率下降, DUCB 利用项随近期零奖励降低, 搜索便转向别处. 这个分数表达未知性耗尽前的乐观程度, 不估计当前状态离完成证明还有多远. 对有限浅树有合理效果. 开放动作与无限状态意味着无法真正覆盖完. 状态字符串细微变化也会持续产生新奇, 所以方法依赖模型 proposal 集中在有意义 tactic 和状态合并去重. 理论 RMax 的有限 MDP 保证不能直接搬到这里.

### 4. 奖励、搜索与证明生成的关系

#### 4.1. RLPAF 优化的是生成分布

对定理 $x$, 模型生成证明 $y$, Lean 奖励 $r(y)\in\{0,1\}$. GRPO 每组采 32 条, 用组内均值与标准差构造相对优势. 忽略裁剪细节, 优势可写成:

$$
A_i=\frac{r_i-\bar r}{\operatorname{std}(r_1,\ldots,r_G)+\epsilon}.
$$

正确证明的 token 概率被提高, 错误证明被降低, KL 项约束模型不要离 SFT 参考过远. 奖励在序列末端给出, 每个 token 共享整条证明优势. 算法不知道哪一条 tactic 起了决定作用, 信用通过策略梯度粗粒度传播. RL 改变的是采样分布, 不直接修改 Lean 搜索器. 若正确证明已经在 SFT 分布尾部, RL 可把它移到更高概率区域; 若定理所需思路从未出现在模型支持集, 0/1 奖励难以创造新动作. 中等难度筛选保证每组有机会出现正负样本, 也让训练集中在现有能力边界附近. 4.5k 提示很少, 每题 32 sample 仍能产生大量在线序列. 题目来自 SFT 数据并按成功率筛选, 分布偏向模型偶尔可解的竞赛式 Lean 题. ProofNet 回退说明这种局部优化没有自动迁移到所有本科数学领域.

#### 4.2. 树搜索优化的是测试时资源分配

给定固定 checkpoint, RMaxTS 决定下一次 sample 从哪个已验证状态开始. 它不更新模型参数, 而是在一题内部把更多预算分给能产生新状态的分支. RL 与 MCTS 的作用层不同: RL 跨题改变策略先验, MCTS 在单题中利用 Lean 反馈重排探索. 可以把模型看成 proposal policy $\pi_\theta(a\mid s)$, 搜索器根据统计选择状态 $s$, 再让模型生成动作或整段 rollout. 若模型 proposal 很差, 搜索反复得到非法 tactic; 若模型已经很强, 单遍大量采样也能覆盖正确证明, 搜索边际收益小. 表中低预算几乎无增益, 正是后一种与启动成本共同作用的结果. 截断续写使一次 rollout 的有效前缀能进入树. 普通 best-of-$k$ 每个 sample 独立, 失败证明中的正确前缀全部丢弃. 树搜索复用前缀, 但也要支付状态抽取、去重和反复验证. 收益只有在正确证明需要跨多个尝试组合前缀时超过开销.

#### 4.3. MCTS 在这里与棋类 MCTS 有何不同

棋类动作空间有限, transition 便宜且确定, value network 可以估计局面. Lean tactic 是开放文本, 合法动作无法枚举; transition 需要 elaboration 与 tactic 执行; 未完成状态没有现成价值. virtual child 表示从同一节点再次调用生成器, 动作集合随 sample 不断展开. 一次生成还可能跨越多条 tactic, 因而树边不是固定一步. 验证后会把成功前缀切成若干节点, 一次 expansion 增长多层. rollout 与 expansion 融合, 没有单独从叶子随机模拟到终局的阶段. 这更接近语言模型引导的异步 best-first tree search, 但选择统计沿用 MCTS/UCB 框架. Lean transition 确定, 模型 proposal 随采样随机. 相同状态多次扩展可以得到不同证明片段. 状态节点保存多条前缀代码, 因为 reaching path 会影响语言模型看到的文本与 CoT, 即使 Lean 状态相同, 后续生成分布也可能不同. 这使「状态价值」与「文本前缀价值」没有完全分离.

#### 4.4. 新奇奖励与证明进展的差别

RMaxTS 给新状态奖励 1, 相当于鼓励扩大已知可达状态集合. 它不测目标数量是否减少、表达式是否简化或关键引理是否建立. 一条 `have` 引入无关命题也可能产生新状态. 在短证明上, 新状态往往意味着至少有 tactic 合法, 对探索有用; 在深证明上, 横向发散会浪费预算. 可以设想更有方向的进展量, 例如目标数变化、表达式复杂度、模型 value、到已知 lemma 的距离或后续成功率. 这些启发式容易被 tactic 操纵, 也可能错误惩罚必要的中间复杂化. 0/1 新奇的优势是简单、无需训练 critic, 缺点是没有数学方向感.

DUCB 解决的是奖励非平稳, 没有解决奖励含义. 一个分支早期容易产生新状态, 后期已经挖空, 折扣让旧成功快速失效; 另一分支若持续产生无用新状态, 仍会长期受偏好. 完整证明的外在奖励一旦出现, 任务已经成功, 没必要继续估计中间价值.

#### 4.5. 搜索预算怎样分解

论文用 $N\times T$ 或 $N\times S\times T$ 表示并行 runner、sample 与轮数, 不同方法的一次「生成」长度不同. 更公平的成本至少包括模型生成 token 数、prefill token、Lean 调用数、Lean CPU 时间和墙钟延迟. CoT 样本更长, 整证验证也比单 tactic 更贵. 设第 $i$ 次扩展生成 $l_i$ token, Lean 验证耗时 $v_i$, 总成本可写成:

$$
C=\alpha\sum_i l_i+\beta\sum_i v_i+\delta C_{\text{orchestration}}.
$$

$\alpha$ 与 $\beta$ 由 GPU/CPU 价格和并行度决定. 单写 sample 数隐含每次成本相等, 在 CoT/non-CoT、整证/逐步之间不成立. V1.5 的结论主要是成功率随给定官方预算变化, 不是等 FLOPs 或等成本最优. 大预算下每题十万级生成, pass 率继续上涨说明尾部分布中仍有新证明. 实际部署若只有几百到几千 sample, 树搜索收益接近零, 应优先使用更强 checkpoint 或更多独立 sample. 只有验证集群与长时间预算充足时, RMaxTS 的前缀复用才显示优势.

#### 4.6. 一个 GRPO 组怎样产生梯度

设某题采 8 条而非论文的 32 条以便手算, 奖励为 $[1,0,0,0,0,0,0,0]$. 均值为 $1/8$, 成功样本优势为正, 七条失败样本优势为负. 策略更新提高成功 proof 中所有 token 的概率, 降低失败 proof token. 如果奖励全为 0 或全为 1, 去均值后优势全部为 0. 这会产生粗信用问题. 成功 proof 中可能有冗余注释和无用 tactic, 它们与关键步骤一起被提高; 失败 proof 可能有很长正确前缀, 也整体被压低. 大量样本与共同 token 会在期望上缓和噪声, 没有逐状态奖励仍会浪费信息. 组大小影响获得混合奖励的概率与优势方差. $G$ 大时, 低成功率题更可能至少采到一条正确 proof, 生成成本同步增加. 论文用 32 是探索与 batch 成本的选择, 没有组大小消融.

GRPO 的裁剪和 KL 还限制单次更新. 若成功 proof 极罕见, 不受约束地提高它可能让策略过拟合单一路径; 参考策略让更新保持在 SFT 邻域. 这有助于保留语言和证明多样性, 也限制从少数奖励中快速跳到新分布.

#### 4.7. 训练时 RL 与推理时搜索为何不能互换

增加 RL 训练计算产生一个可重复使用的 checkpoint, 每道新题的单次成功率可能提高. 增加搜索只为当前题花 TestingTime, 不改变下一题. 若要服务很多题, 训练投入可摊销; 若只有少量高价值难题, 大搜索更灵活. RL 依赖训练 theorem 分布, 域外可能退化. 搜索使用当前 theorem 的 Lean 反馈, 即使域外仍能验证合法状态, proposal policy 太弱时也无从探索. 两者组合让先验与在线反馈互补, 没有谁能完全替代另一方. 表中 RL 单遍大预算领先 SFT, 说明 checkpoint 改善不只在 top-1 排序; RMaxTS 在 RL 上再加数点, 说明同一 policy 仍有可由状态反馈挖出的尾部. 这两种增益口径应分开报告.

#### 4.8. 奖励 hacking 在形式系统里仍有哪些入口

kernel 验证比神经 reward 可靠, 环境与 statement 仍可能被利用. 如果允许 `sorry`, 声明不安全 axiom, 修改 theorem 或使用有漏洞的 tactic/编译接口, 模型可以获得 1 而没有预期证明. 防护需要静态扫描、只读题目、可信 kernel 和固定依赖. 资源型 hacking 也存在. `maxHeartbeats 0` 下, 模型可生成非常昂贵 tactic, 只要 300 秒内通过就得同样奖励. 它可能学会 brute-force 而非简洁推理. 若线上资源不同, 这种 proof 不可用. 形式语句若前提矛盾, `exfalso` 后轻易证明任意结论仍是逻辑合法. 这属于题目问题, 不属于模型作弊. benchmark 审计要区分 theorem 漏洞、环境漏洞与正常自动化. V1.5 论文没有报告发现 reward hacking, 也没有列完整过滤器. 可靠奖励的正确表述是「在受控 Lean 环境中通过验证的二值信号」, 不是无条件不可能被利用.

#### 4.9. 一个更有方向的 critic 要学什么

critic 可以估计 $V(s)=P(\text{最终可证}\mid s,\pi,\text{budget})$. 训练标签可来自搜索树: 某状态的后代是否找到 proof、用了多少扩展. 有了 value, 选择器可优先成功概率高的状态, 而非只奖励新奇. 标签有选择偏差. 未找到 proof 可能是预算不足, 不能断言状态不可证; 已找到 proof 的状态又更常被强 policy 访问. value 会继承当前搜索器盲点. 过度相信 critic 可能剪掉新颖但暂时低分的分支. 另一种方法预测 progress, 如目标数、表达式复杂度或到已知 lemma 的匹配. 这些手工指标易被欺骗. RMaxTS 避免训练 critic, 把方向性让给模型 proposal, 用新奇保证宽度. 这是稳健与效率之间的选择.

#### 4.10. 正确前缀为什么是稀疏奖励中的宝贵资产

一条失败 proof 可能前 20 条 tactic 全部合法, 第 21 条出错. 序列奖励给整条 0, 训练时没有直接复用前 20 条; 截断搜索把它们保存为节点, 推理时立刻获得价值. 这显示 RLPAF 与 RMaxTS 在信用分配上的互补. 如果将每个合法前缀也用于训练, 可以构造状态—后续 tactic 数据, 甚至给 progress reward. V1.5 的 tactic state SFT 已经做了一部分: 从成功 proof 抽取中间状态. 失败 rollout 中的合法前缀是否回流训练, 论文没有说明. 失败前缀不一定通向最终 proof. 一条合法 tactic 可以把目标带进死路, 仍被树保存. 新奇奖励鼓励探索这些状态, 没有 critic 识别可恢复性. 大预算通过尝试弥补, 训练层面则可用后代成功标签筛选.

#### 4.11. 模型先验与搜索后验

模型给出 $\pi_\theta(a\mid s,h)$, 是从训练数据学到的 tactic 先验. 搜索统计根据当前 theorem 的验证结果更新分支偏好, 可看成测试时后验. 强先验减少无效动作, verifier 反馈纠正题目特定错误. RMaxTS 的 selection score 没直接乘 policy probability, proposal 阶段仍由模型控制动作. 高频 tactic 更常被提出, 稀有有用 tactic 可能始终不出现. 搜索能重分配状态, 无法在一个状态内枚举模型几乎不给概率的动作. 温度 1、top-$p$ 0.95 保留相当随机性, 为大预算提供探索. 降温会提高常见正确 proof 命中, 也可能降低尾部覆盖. 论文固定采样设置, 没给温度—搜索曲线.

#### 4.12. 自动化 tactic 与模型能力的归因

当模型生成 `nlinarith`, 后续代数消元由 Lean tactic 完成. 成功来自模型识别问题类型、准备必要假设和调用工具, 以及 tactic 本身的算法. 这与 Agent 调用工具相似, 不能把所有内部计算算作语言模型参数完成. 不同 prover 若可用导入与 tactic 集不同, 成绩不可直接比较. V1.5 固定 `Mathlib` 和 `Aesop`, `maxHeartbeats 0`, 给自动化充分空间. 某些系统限制 tactic 或 CPU, pass 会下降. 评测环境是系统能力的一部分. 自动化并不削弱结果价值. 形式证明的目标就是正确组合库与 tactic. 归因时应说模型学会生成可验证 proof, 避免把一行 tactic 描述成模型自行完成了其内部所有推理.

#### 4.13. 训练与搜索的数据闭环

V1.5 的 expert iteration先用模型生成、Lean 验证、正确 proof 回训; RL 再在线采样并根据验证更新; RMaxTS 测试时继续用验证探索. 三处都把 Lean 放在反馈环, 区别是数据写回参数还是只写入当前搜索树. SFT 回路离线积累可复用 proof, RL 回路改变全局策略, 搜索回路只解决单题. 若将 RMaxTS 新找到的 proof 再加入 SFT, 可以继续 expert iteration. 论文没有报告搜索结果回训, 方法结构允许这种扩展. 闭环容易自我强化当前风格. 模型更会某类 tactic, 就更容易生成通过 proof, 数据池继续增加同类 proof. 扩展 theorem 来源、控制 proof 多样性和引入检索可以打破偏置. Goedel-Prover 用更广形式化数据获得大幅提升, 正是覆盖面的证据.

#### 4.14. 从单题成功到训练目标的错位

benchmark 计每题是否至少有一证, 训练最大化 sample 级预期奖励. 对容易题从 0.8 提到 0.9 与难题从 0 提到 0.1, 训练收益可能相似, pass@大 $k$ 的价值不同: 难题获得非零支持会带来新覆盖, 容易题只是更快命中. 中等难度筛选偏向第二种有学习信号的题, 但没有显式最大化 theorem coverage. 可以按题目成功率重权, 鼓励把近零题拉起来; 过难题仍没有正 sample. curriculum 与搜索生成正例能逐步移动边界. 证明长度也未进入奖励. 短 proof 和长 proof 同得 1, 长 proof 产生更多 token 梯度, 其序列概率更低. 长度归一、每题归一与 GRPO token reduction 会影响实际更新, 论文没有细到这个层面.

## 5. 实验与评测

### 2.1. 数据规模和数据来源各自贡献多少

表 2 比较数据来源, 设定都是 pass@128. 底座不做任何形式证明训练时, miniF2F-test 27.5%; 用 mathlib 定理做 expert iteration, 31.2%; 用自动形式化语句, 42.6%. 人写的形式库只能带来不到 4 个点, 自动形式化带来 15 个点. 结论很明确: **mathlib 喂不饱一个 7B 证明器, 大规模自动形式化才是主要增益**. 表 3 的高分档和表 2 的自动形式化行数字完全相同(48.8%, 42.6%), 大概率是同一次训练.

表 5 比较数据规模: 从 800 万条里取 1,000, 10,000, 100,000, 1,000,000 和全部 8,066,621 条, test 分别是 24.18%, 31.97%, 37.7%, 38.11%, 40.16%. 规模每涨一个数量级, 分数都涨, 但 10 万到 100 万只涨 0.4 个点, 到 800 万又涨 2 个点, 曲线不是平滑的. 这张表还有两处和别的表对不上. 一是只用 1000 条时 test 24.18%, 比完全不训的底座 27.5% 还低, 小数据微调反而伤了多样本采样. 二是全量 800 万条只有 40.16%, 低于表 4 第 4 轮的 46.3%. 报告没解释, 合理的猜测是表 5 是一次性微调的对照, 表 4 是逐轮迭代的模型, 训练过程不同. 这说明「数据量」和「迭代过程」是两个独立的变量, 800 万条数据一次喂进去, 抵不上边造边训.

### 2.2. 主结果: miniF2F 与 FIMO

miniF2F 有验证集和测试集各 244 题, 覆盖基础算术到 AMC, AIME, IMO 级竞赛题, 用 LeanDojo 发布的 Lean 4 版. 表 1 是报告最常被引用的一张表. DeepSeek-Prover 整证生成: 贪心约 30.0%, 64 次 46.3%, 128 次 46.3%, 8192 次 48.8%, 65536 次 50.0%. 累计(把所有实验中找到的证明合起来算)valid 60.2%, test 52.0%. 对照组: GPT-4-turbo 0409 在 64 次采样下 valid 25.4%, test 23.0%; 树搜索里最强的 Hypertree Proof Search(600M)累计 valid 58.6%, test 41.0%. 采样从 64 次加到 65536 次, 算力多了 1000 倍, test 只涨 3.7 个点, 说明整证生成在难题上很快碰到上限. pass@k 的定义是「模型生成的前 $k$ 次尝试里至少有一次通过核验」, 按一次实际采样的前 $k$ 条直接计数, 不是 Codex 那种从 $n>k$ 个样本里算 $1-\binom{n-c}{k}/\binom{n}{k}$ 的无偏估计. 如果 64 次和 128 次取自同一串采样, 两者同为 46.3% 就意味着第 65 到 128 条没有为任何新题找到证明; 报告也没给多次运行的方差.

表 1 的上下两部分采用不同预算. 上半部分的树搜索方法以「交互步数乘分支」计量, 下半部分的整证生成方法记录独立采样次数, 两者无法直接换算成同一种算力. 「累计」也不是固定预算下的结果, 它取所有实验找到的证明并集, 与 pass@k 的含义不同. 报告给出的结论限于整证设定: 7B 模型经过合成数据训练后, 64 次采样的分数达到 GPT-4 的两倍, 累计指标超过当时最强树搜索方法的 test 分数. 这组数字没有比较两类方法的等算力表现.

GPT-4 这条基线的设定也要看清. 报告说 GPT-4-turbo 0409 和 DeepSeekMath 都「用和本文类似的方法」生成完整证明, 但没有给 few-shot 示例数量, 导入前缀和温度. GPT-4 没有在 Lean 4 数据上微调, 而当时 Lean 4 和 mathlib 4 的写法相对 Lean 3 变化很大, 通用模型很容易写出旧语法或已改名的引理. 所以 23.0% 对 46.3% 的差距里, 有一部分是「见没见过当前版本的 Lean 4」, 不全是推理能力. 这不影响结论的方向, 但「两倍于 GPT-4」这个说法应当放在这个前提下理解.

FIMO 把 IMO shortlist 翻成 Lean 4, 正文写 149 题, 摘要写 148, 两处不一致. 每题 100 次尝试证出 4 题, GPT-4 为 0; 加到每题 4096 次再多证出 1 题, 共 5 题. 附录里的 FIMO 证例能看到模型会组合 induction, `linarith`, `nlinarith`, `field_simp`, `aesop` 等 tactic. 从 100 次加到 4096 次只多一题, 说明 IMO 级题目基本在这条路径的能力之外; 能证出的几题, 更像是训练分布边缘恰好覆盖到的题型. miniF2F 上的成功集中在训练数据最密的代数和数论中等难度题, 与 FIMO 的稀疏成功形成对照.

### 2.3. 评测缺口

评测还留下三处缺口. 训练题面爬自竞赛资源, miniF2F 同样来自 AMC、AIME、IMO, 报告没有检查二者重合度, 也没有给出合成语句与评测语句的相似度. miniF2F-valid 既出现在打分提示的 few-shot 示例中, 又被用来报告 60.2% 的验证分数. 主结果的采样预算从贪心横跨到 65,536 次, 累计指标还是多次实验的并集, 各行消耗的算力差异很大. 表 2 到表 5 的内部对照仍能支持过滤与迭代的收益, 但这些缺口会降低它与外部方法直接比较时的可信度.

附录 A.3.1 列出的 miniF2F-test 证例可以把这个担心说得更具体. 其中一题是 `amc12b_2021_p4`, 也就是 2021 年 AMC 12B 第 4 题, 另一题 `induction_1pxpownlt1pnx` 是伯努利不等式的一个归纳证明. AMC 真题及其解答在网上随处可见, 正是「高中与本科习题, 考试, 竞赛资源」会收录的内容. 这不证明它进了训练集, 但说明报告至少应当做一次题面级的重合检查. DeepSeekMath 在自然语言数学上做了 10-gram 去污染, 到了 Prover 这一步反而没有提, 算是这篇报告评测部分最明显的缺口. V1.5 的 SFT 数据甚至直接收入了 miniF2F 的验证集, 只保留测试集做评测, 口径比 V1 清楚.

模型大小也值得一提. 表 1 的树搜索对照里, Hypertree 是 600M, ReProver 是 229M, Proof Artifact Co-Training 是 837M, 多数比 7B 小一个数量级; Llemma 7B 和 34B 是同量级, test 分别 26.2% 和 25.8% 到 29.6%. 所以 DeepSeek-Prover 相对小模型搜索方法的优势, 有一部分来自参数量和数学预训练底座. 表 1 里 DeepSeekMath-Base 在 128 次采样下已有 27.5%, 高于 ReProver 的 25.0%, 就是底座本身的贡献. 在同一个底座上, 合成数据把 27.5% 推到 46.3%, 这 19 个点才是本文方法的净增量.

### 2.4. 案例里能看到的形式化难点

§5.1 的成功案例把一道余弦矩阵行列式为 0 的题, 翻成依赖实数 $a, b$ 的 `Matrix.det ![![...]] = 0`. 附录 A.2 的成功样本还有: 把「小于 -1 或大于 1」写成区间并 `Set.Iio (-1) ∪ Set.Ioi 1`, 二项式系数用 `Nat.choose`, 三维向量拆成 $\mathbb{R}\times\mathbb{R}\times\mathbb{R}$ 的分量. 这些都是形式化里的常见陷阱, 模型在标准代数和分析句式上已经能翻对. 条件和目标都是显式代数等式时, 自动形式化最可靠, 这也是题型选择偏向代数和数论的原因.

失败案例更能说明流水设计的道理. 量词写错, 前提矛盾, 这类错误让语句「形式上可证但数学上无意义」, 证明搜索再强也救不回来; 如果不做假设否决, 这类空虚真的证明会大量进入训练集, 模型学到的是「从矛盾前提推出任何结论」的技巧. 附录 A.4 还给了生成证明前固定的一长串 `import Mathlib...` 和 `import Aesop`, 以及 `maxHeartbeats 0` 等选项. 这套前缀决定了模型默认能用哪些引理和 tactic, 评测和合成时前缀不一致, 通过率就会漂移. 复现这篇报告需要同时拿到权重, 导入前缀, Lean 和 mathlib 的确切版本, 缺一样都可能对不上表 1.

附录 A.3.1 的成功证明也有一个共同风格: 很短, 主要靠 Lean 自带的自动化 tactic 收尾. 伯努利不等式那题只有一行 `induction'`, 接一串 `simp_all` 化简规则, 再用 `nlinarith` 喂一个平方非负的提示就结束了. 这说明整证明生成学到的更多是「选对 tactic 组合, 给对提示项」, 而不是一步步写出人类式推导. 这种风格和 miniF2F 里大量短代数题正好匹配, 碰到需要多层引理拼接的 IMO 级题目就吃力, FIMO 上 100 次采样只证出 4 题, 和这个观察一致. V1.5 后来引入自然语言 CoT 注释和 RMaxTS 搜索, 目标之一就是补这块长证明的短板.

### 5.5. 用后续版本看懂评测统计

V1.5 延续了 miniF2F，却增加了 ProofNet、CoT 与树搜索，因而把 V1 已经存在的统计问题放大了：pass@k、混合策略和累计成功率都依赖预算口径。以下比较只用于解释指标，不把后续成绩计入 V1 的实验结论。

### 5. 实验与统计口径

#### 5.1. 消融能证明多少

图 5 在 RL 模型 CoT 模式下拆 RMaxTS 的组件. 4×6400 预算时: 单遍 58.4%±0.5%, UCT 无内在奖励 58.2%±0.3%, 内在奖励配 UCB1 58.6%±0.3%, 去掉 tactic 状态 58.4%±0.3%, 完整 RMaxTS **59.6%±0.6%**. 16×6400 时依次是 60.2%, 61.1%, 60.7%, 61.1%, 62.7%. 报告据此得出三点: 没有内在奖励, 树搜索退化到接近不搜索; 内在奖励必须配 DUCB; tactic 状态注释是树搜索有效的必要条件. 方向上这三点和数据一致, 但幅度要换算成题数看. miniF2F-test 共 244 题, 1 题约 0.41 个点. 16×6400 下完整 RMaxTS 约证出 153 题, 三个消融版本约 148–149 题, 单遍约 147 题. 也就是说, 在十万级采样上, 内在奖励, DUCB, 状态注释各自的贡献都在 4–5 题左右, 而 16×6400 这一档没有给标准差. 结论可能是对的, 但证据比正文的措辞弱. 表 3 里还有一处值得核对: SFT 模型的 non-CoT & CoT 混合 (2+2)×6400, 单遍和 RMaxTS 两行都是 **56.1%±0.8%**, 连标准差都相同, 可能是巧合, 也可能是抄录错误, 报告没有说明.

小预算下树搜索几乎不起作用, 这一点正文没有强调. 表 1 里 RL 单遍 3200 次 54.9%, RL + RMaxTS 1×3200 55.0%; SFT 单遍 3200 次 53.3%, SFT + RMaxTS 53.5%. 两处都只差 0.1–0.2 个点, 不到一题. 树搜索的收益主要出现在 4×6400 以上, 这和「内在奖励要积累足够多的新状态才开始有区分度」的机制是一致的. 对只能跑几千次采样的使用者, 单遍整证生成基本就是全部收益.

#### 5.2. 主结果和预算口径

miniF2F-test(表 1): RL 单遍 128 次 51.6%, 3200 次 54.9%, 16×6400 次 60.2%, 比 V1 的 50.0% 高 10.2 个点; RL + RMaxTS 16×6400 62.7%; 用 CoT 和 non-CoT 各一半预算的混合策略, 32×6400 到 63.5%. 对照组里 InternLM2-StepProver 54.5%, Lean-STaR 46.3%, HTPS 41.0%, GPT-f 36.6%, COPRA + GPT-4 26.6%. 摘要里的 63.5% 同时用了 RL, RMaxTS 和混合提示三样东西; 只看模型本身, 应该看单遍的 60.2%. ICLR 2025 版正文把主结果写成 62.7%, 没有把混合策略的数字当标题. 评测协议写在源文 §2.4. 每个模型单卡 A100-40G, 用 vLLM 采样, 温度 1, top-p 0.95, 最多 2,048 token; 验证时导入 Mathlib4 和 Aesop, 单题时限 300 秒. miniF2F 和 ProofNet 原本都是 Lean 3, 作者手工转成 Lean 4.9.0, 比 V1 用的 v4.7.0-rc2 新. 这意味着 V1 的 50.0% 和 V1.5 的数字不是在完全相同的语句文件和工具链上测的, 表 1 里 V1 那一行是在哪个版本上重跑的, 报告没有说明. Base 模型用 3-shot, 示例从验证集随机抽: miniF2F 用 Yang(2023) 的人写证明, ProofNet 则用 **V1.5-RL 生成的正确证明**当示例. 用最终模型的输出去给 Base 做示例, Base 在 ProofNet 上的 9.7% 就不完全是 Base 自己的水平, 报告没有讨论这一点. SFT 和 RL 模型不用 few-shot, 改用 CoT 或 non-CoT 两种引导提示.

预算怎么比是这一节最容易读错的地方(源文 §4.1). 单遍方法按总生成数记, best-first 按 $N\times S\times T$ 记, 树搜索按 $N\times T$ 记. 报告称 3200 次整证就超过 InternLM2-StepProver 的 64×32×100 次, 后者折合 204,800 次生成. 但一次整证生成最长 2,048 token, 一次逐步生成只写一条 tactic, 按 token 或按验证调用次数算, 两边的差距会小得多, 报告没有给 token 口径的对比. 另一个量级: 32×6400 即每题 204,800 次整证生成, 244 题合计约 5000 万次, 每次都要 Lean 验证, 这就是 §2.2 那套数千核集群存在的原因.

ProofNet(表 2): RL 单遍 4×6400 全集 22.6%, RL + RMaxTS 全集 25.3%, 测试集 25.3%, 验证集 25.4%, 对照 ReProver 13.8%, InternLM2-StepProver 18.1%. 表注写明 ProofNet 验证集参与了 SFT 的 expert iteration, 所以验证集那一列不能当泛化证据, 只有测试集 186 题是干净的. 测试集上单遍 23.7% 到 RMaxTS 25.3%, 约多证出 3 题. miniF2F 验证集同样进了 SFT 数据, 所以 miniF2F 也只能看测试集. 和 V1 相比, V1.5 把「哪些评测集进了训练」写清楚了, 这是评测口径上的进步.

#### 5.3. CoT 和 non-CoT 各擅长什么

表 3 显示 CoT 相对 non-CoT 的优势随预算放大: 单遍 RL 模型 4×6400 时 CoT 58.4%, non-CoT 56.5%, 16×6400 时 60.2% 对 57.4%. 报告的解释是自然语言注释让规划路径更多样, 大预算时能覆盖更多不同的证明思路. 这个解释和数据方向一致, 但和 §1.3 提到的问题连在一起看: 注释不受 Lean 检查, 多样性可能部分来自注释本身带来的随机扰动, 而不全是「更好的规划」, 报告没有做区分这两者的实验.

两种模式确实互补. 附录 B.1 里 non-CoT 赢的题, 比如 `induction_pord1p1on2powklt5on2` 和 `imo_1960_p2`, 证明是一串 `field_simp`, `nlinarith`, `norm_num`, 靠 Lean 自动化硬算过去; B.2 里 CoT 赢的题, 比如 `mathd_algebra_459` 先在注释里把四元方程组解出 $d=13/15$, 再逐个 `have` 落到代码. 混合策略把预算对半分, RL + RMaxTS 在 (16+16)×6400 时 63.5%, 比纯 CoT 的 16×6400 62.7% 多约 2 题, 而总预算是后者的两倍. 所以混合策略的增益里, 一部分来自多花了一倍的 TestingTime 算力, 一部分来自两种模式覆盖不同题目, 表 3 没有给等预算下纯 CoT 32×6400 的数字, 两者分不开. 推理模式如何影响思考能力, 更一般的讨论见 [推理与思考能力](../../../llm-guide/4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).

#### 5.4. pass@k 到底估计什么

若单次独立成功概率为 $p$, 理想 pass@$k$ 为:

$$
1-(1-p)^k.
$$

真实评测通常从 $n$ 个 sample 中估计 pass@$k$, 常用无偏估计器根据失败数 $c$ 计算组合比例. 当所有候选同分布且独立时, $k$ 增大单调接近至少一次成功概率. 模型样本高度相关, 有效多样性低于 $k$. V1.5 的大预算写成多组 $6400$, 可能通过不同随机运行聚合 theorem 是否至少成功. 表中百分比是 244 个 theorem 的通过比例, 并非单题平均 $p$. 有些题在前几十次就成功, 有些题十万次仍失败, 总曲线反映难度混合. pass@k 奖励覆盖面, 不关心正确证明概率质量. 一个模型每题只有万分之一概率成功, 给足预算也可能有高 pass; 线上单次使用却很差. Pass@128 更接近有限部署, 16×6400 展示支持集与搜索上限. 两种口径都重要.

树搜索样本不独立, 不能直接套 $1-(1-p)^k$. 后续扩展依赖先前发现状态, $k$ 代表自适应查询次数. 把 RMaxTS 与独立采样按相同生成数比较有直观意义, 统计模型不同.

#### 5.5. 题目数如何限制小差值解释

miniF2F-test 有 244 题, 单题约 0.41 个百分点. 0.1 或 0.2 点差小于一题, 来自多次运行平均或四舍五入, 不应写成实质提升. 1 点约 2–3 题, 2.8 点约 7 题. 把百分点换成题数能恢复直觉. 同一模型不同 seed 会改变哪些题被证明. 论文对部分设置报告标准差约 0.3–0.8 点, 与一到两题相当. 完整大预算缺少所有对应方差, 63.5 与 62.7 的 0.8 点差未必稳健, 而且预算不同. 题目不是同质 Bernoulli. 多道题可能共享 `nlinarith` 模式, 一项能力变化会成组影响, 简单二项置信区间低估相关性. 更有信息的报告应列配对翻转: SFT 未证而 RL 证出的题, RL 退化的题, RMaxTS 独有题及证明长度. ProofNet test 186 题, 单题约 0.54 点. RMaxTS 从 23.7 到 25.3 约多 3 题. 这是正向信号, 规模远小于 miniF2F 的主标题增益, 也说明搜索收益随领域与证明深度变化.

#### 5.6. miniF2F 与 ProofNet 的分布差异

miniF2F 主要是中学竞赛题, 大量代数、数论与不等式可由 `linarith`、`nlinarith`、`norm_num`、`ring` 等自动化收尾. 自然语言 CoT 容易提出中间等式, Lean tactic 生态也与数据中常见模式吻合. ProofNet 来自本科数学陈述, 涉及更广定义、分析与抽象结构. 证明需要选择库 lemma、处理类型类和拓扑/代数环境, 单靠算术 tactic 不够. V1.5 的 RL 提示只有 4.5k, 来自 SFT 中等难度题, 领域覆盖可能偏 miniF2F 风格. 这解释 RL 在 miniF2F 稳定优于 SFT、ProofNet 某些预算却持平或回退的可能原因. 它是分布假设, 论文没有按领域列训练题和错误类型. 不能把 miniF2F 上「RL 增强基础能力」直接外推到全部 Lean 数学. ProofNet validation 进入 SFT expert iteration, test 才能用于泛化. Base few-shot 又用了 V1.5-RL 生成的证明当示例, 不同模型行的上下文信息不完全对齐. 这使表格适合比较最终系统, 不适合纯 checkpoint 归因.

#### 5.7. CoT 模式的成本口径

CoT 在每条 tactic 前写解释, 输出 token 明显多于 non-CoT. 相同 sample 数下, GPU 解码时间、KV cache 和截断概率不同. CoT 分数高不能直接称为免费提升, 应报告每个成功证明的平均 token 与时间. 2048 token 上限对两模式影响不同. non-CoT 能容纳更多 tactic, CoT 可能在代码完成前被解释耗尽. 短 miniF2F 中规划收益超过长度代价; 长证明可能反转. 论文没有按证明长度分桶. 混合模式的互补还可能只是增加多样性. 用两个 prompt 形成两个采样分布, 类似 prompt ensemble. 若换成多种 non-CoT 提示也可能覆盖更多证明. 要隔离自然语言推理, 需要等 token、等 prompt 数与等总预算比较.

#### 5.8. 消融缺少哪些轴

RMaxTS 消融覆盖内在奖励、UCB/DUCB 与状态注释, 没有扫描 $\gamma$、线程数、每次 rollout 长度、状态合并规则和模型温度. 搜索组件相互作用, 固定一个配置的移除实验只能说明该点附近贡献. 训练侧缺少纯 tactic state、纯 CoT、两者同时和无注释的完整矩阵. SFT 数据、预训练与 expert iteration也没有规模曲线. 因而 CoT 与状态监督各自对单遍和搜索的贡献难以拆分. RL 侧缺少提示数量、组大小、KL 与训练步数消融, 也没有训练 reward、entropy 和验证曲线. 1–3 点增益可以确认, 为什么产生以及是否已经饱和仍未知. 最后缺少等成本对照. 增加独立 sample、RMaxTS、best-first 与逐步 prover 应按 GPU token、Lean CPU 与墙钟比较. 论文使用生成次数作为统一轴, 有利于展示算法, 不能回答真实集群的性价比.

#### 5.9. 从 pass 曲线反推题目分层

若所有题拥有相同单次成功率, pass 曲线会由一个 $p$ 决定. 实际从 128 到十万 sample 仍增长, 说明题集至少包含三层: 高概率题早早通过, 低概率题需大预算, 零支持题始终失败. 曲线尾部上涨来自第二层. RL 若只重排已有 proof, 可能让高概率题更早通过, 大 $k$ 最终与 SFT 汇合. 表中大预算差距没有消失, 支持 RL 让部分题从近零概率进入可采样尾部, 或扩大了正确证明多样性. 它仍未达到证明「创造全新推理算法」的强度. RMaxTS 的目标是把第二层题的合法前缀组合起来. 对高概率短题, 独立 sample 足够; 对零支持题, 树也无合法 proposal. 所以搜索增益集中在中间层, 与 RL 的中等难度训练筛选形成相似结构.

若报告按题目单遍成功率分桶展示搜索增益, 可以直接验证这一解释. 论文没有该图, 只能从预算曲线间接判断.

#### 5.10. 混合策略怎样区分互补与额外预算

设 CoT 在题集上成功集合为 $A$, non-CoT 为 $B$. 混合覆盖率由 $|A\cup B|$ 决定, 互补部分是 $|A\triangle B|$. 只给两种单独总分与混合总分, 无法求出交集, 因为采样预算和随机性也变化. 等预算实验应把总 sample 固定为 $K$, 在 CoT/non-CoT 间分配 $\lambda K$ 与 $(1-\lambda)K$, 扫描 $\lambda$. 论文的 (16+16)×6400 比纯 CoT 16×6400 多一倍总预算, 混合上涨 0.8 点可能来自额外 sample. 不过附件案例确实显示模式偏好不同. non-CoT 更常简短调用自动化, CoT 更常显式建立中间 `have`. 这种结构差异给互补提供定性证据. 要量化仍需相同预算和题级翻转表.

#### 5.11. 标准差与重复运行怎样读

部分结果写成均值±标准差, 表明多个随机运行或批次. 标准差描述运行间波动, 不等于均值置信区间; 还需要重复次数才能计算标准误. 论文没有在每个大预算格都给完整重复信息. 0.5 点标准差约一题多. 两个设置均值差 0.4 点且区间重叠时, 不应强调排名. 完整 RMaxTS 对某些消融高 1–1.5 点, 方向更可信, 题数仍只有数题. benchmark 题数固定, 重复随机性来自模型采样与搜索调度. 32 线程异步还会因返回顺序改变树, 即使随机 seed 相同也可能不完全确定. 复现应报告多 seed 与调度设置.

#### 5.12. 与后续强基线比较时的时间顺序

Goedel-Prover 用更大形式化数据在 V1.5-Base 上 SFT, 说明数据覆盖可以超过 V1.5 的 RL 增益. 它发布时间更晚, 使用 V1.5 作为基础, 不能反过来否定 V1.5 当时的方法贡献. Prover-V2 使用更强通用模型分解和 671B RL, 模型规模、数据与任务构造都不同. 它表明路线演进到显式子目标与大模型, 不是 RMaxTS 的受控替代实验. 正确比较方式是把后续结果作为上限与机制启示: V1.5 找到 verifier RL 和状态搜索接口, 后续扩大 theorem 数据与规划能力. 每代主结果的预算也不同, 不能只排一个 pass 百分比排行榜.

#### 5.13. 用数值理解采样收益递减

若某题单次成功率 $p=1\%$, 独立采样 128 次的成功率约为 $1-0.99^{128}\approx72.4\%$; 3200 次几乎必过. 若 $p=0.01\%$, 128 次约 1.27%, 3200 次约 27.4%, 十万次才接近必过. 大预算主要从第二类极低概率题中继续挖答案. 如果 $p=0$, 任何独立采样都无效. 树搜索可能把多个非零概率正确前缀拼起来, 将整证零支持变成可达; 前提是每个关键局部动作都能由模型提出. 这就是 RMaxTS 相对 best-of-$k$ 的潜在优势. 题集曲线是不同 $p_i$ 的平均. 从表格总 pass 无法反推出单题分布, 同一总分可能由「多数题中等概率」或「一半很易、一半为零」形成. 后者增加 sample 很快饱和, 前者持续上涨. 论文的大预算曲线提供部分形状信息, 没发布题级 $p_i$.

采样收益递减还决定资源分配. 与其给已高概率题继续上万 sample, 可以根据早期失败动态把预算移给边界题; 但早期没成功也可能是极难零支持题. 一个 value 或难度估计器能改善分配, RMaxTS 用状态新奇作为局部代理.

#### 5.14. 最低可复现实验应报告什么

模型侧需要 checkpoint、prompt 模式、temperature、top-$p$、最大 token 与 sample 数. Lean 侧需要版本、Mathlib commit、导入、heartbeat、墙钟超时和禁用 escape 规则. 数据侧需要 test 文件摘要以及 validation 是否进训练. 搜索侧还要记录 runner、线程、virtual loss、$\gamma$、状态去重和每次 expansion 的生成数量. 成本侧记录 GPU token、Lean calls、CPU 秒与墙钟. 只报告 `N×T` 无法让不同硬件与方法公平比较. 结果侧除 pass@k, 还应给题级成功、证明长度、Lean 时间、CoT token、unique states 与多 seed 方差. 这些指标能区分 checkpoint 更强、搜索更广、自动化更重和预算更多. V1.5 已公开论文、模型与仓库, 为复现提供了主体. 未公开预训练数据配比、完整训练日志和集群成本, 所以最容易复现的是 checkpoint 推理与小预算 pass, 最难复现的是从 Base 到 RL 的整条训练和十万级 RMaxTS.

## 6. 局限与谱系位置

结论写明的边界: 主战场是高中到本科的代数和数论, 几何, 高等定义, 更广的题型是下一步. 整证生成依赖 Lean 工具链和固定导入, 换证明助手或大改 mathlib 版本都要重建核验流水. 合成数据和模型的开源写在贡献和 Broader Impact 里. FIMO 的 5 题也标出了能力上限: 在极难基准上破零, 离系统性解决竞赛级形式证明还远.

谱系上, Prover 是 DeepSeekMath 的直接延伸. 底座是 DeepSeekMath-Base 7B, 继承了 120B 数学 token 的先验; 训练方法从 SFT 加 GRPO 退回到纯 SFT 加 expert iteration, 因为形式证明有了一个比奖励模型可靠得多的裁判, 也就是 Lean 核验器. 这里第一次出现了家族后来反复使用的一个结构: 能被程序自动判对错的任务, 就用判定器生成和过滤训练数据, 让模型自己滚大数据集. V1.5 在这个基础上补了三样东西: 用 Lean 反馈做真正的 RL(RLPAF), 在证明中写自然语言推理, 以及 MCTS 搜索. 再往后, R1 在数学和代码上只用规则奖励, 思路和这里用 Lean 判对错一脉相承. 形式证明的 SFT 数据选取可对照 [4.2.2-SFT数据质量筛选与训练技巧](../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md), 这篇的打分过滤就是其中「模型打分筛数据」的一个具体实例.
