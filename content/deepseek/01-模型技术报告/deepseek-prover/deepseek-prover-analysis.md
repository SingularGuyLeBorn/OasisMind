# DeepSeek-Prover: 用 Lean 核验器当过滤器, 合成 800 万条形式证明

来源: [DeepSeek-Prover: Advancing Theorem Proving in LLMs through Large-Scale Synthetic Data](https://arxiv.org/abs/2405.14333) (arXiv: 2405.14333v1, 2024-05-23).

对照译稿: `deepseek-prover-bi.md`. 表内数字回源文 `deepseek-prover.md`.

DeepSeekMath 在结论里承认几何和定理证明是短板, 三个月后的 DeepSeek-Prover 就对准了其中一块: 用 Lean 4 写出能被机器核验的证明. 模型和底座都没变, 仍是 DeepSeekMath-Base 7B, 训练方法也只是普通的监督微调. 这篇报告的全部分量都在数据上: 把网上爬来的约 87 万道竞赛题自动翻成 Lean 语句, 过滤, 证明, 用 Lean 核验器判对错, 通过的样本回流训练, 滚四轮得到约 **800 万**条带证明的形式语句. 读它要换一个视角: 这里的「数据流水」本身就是算法, Lean 核验器同时扮演标注员和质检员.

## 1. 数据合成流水

### 1.1. 问题: 形式证明缺的是平行语料

Lean, Isabelle, Coq 这类证明助手把命题和证明都写成代码, 内核按形式规则逐步检查, 通过才算证完. 可靠性远高于自然语言证明, 代价是写起来慢, 资深数学家也要花大量时间. 神经定理证明此前有两条路. 一条是模型引导的树搜索: 模型逐步给出 tactic, 和证明器交互, 按搜索算法扩展, 代表是 GPT-f, ReProver, Hypertree Proof Search, 搜索空间大, 算力贵. 另一条是整证生成: 模型一次写完整个证明脚本, 交给证明器判对错, 代表是 Baldur, Draft-Sketch-Prove, 省掉交互, 但一次写对很难.

更早的一阶定理证明器, 比如 E 和 Vampire, 在简单逻辑框架里很高效, 但处理不了证明助手里常见的高阶, 带大量库定义的命题. 神经方法把这个领域重新激活, 不过树搜索那条线多用 RL 提升准度, 搜索本身耗时耗算力; 整证生成那条线跳过了逐步交互, 效率更高, 却更依赖模型一次写对的能力, 也就更依赖训练数据.

两条路都卡在同一个地方: 形式语料太少. Python 这种语言在 GitHub 上有海量代码可学, Lean 的 mathlib 虽然是最大的形式数学库, 规模和自然语言数学相比仍然小几个数量级. 自动形式化(把自然语言题目翻成形式语句)能补一些, 但此前的工作规模都不大. 报告的判断是: 模型架构和搜索算法不是主要瓶颈, 训练数据是. 所以他们不改模型, 不改搜索, 只造数据. 此前造形式数据的办法有两类: 一类对已有定理做基于规则的变换, 能批量生成, 但受限于预先写好的规则, 变不出新的题型; 另一类用大模型把自然语言题翻成形式语句, 灵活, 但已有数据集规模小, 只覆盖几个小基准, 训练收益有限. DeepSeek-Prover 选的是第二类, 目标是把规模做大两个数量级以上. 表 2 的对照直接说明了语料的差距: 同样用 expert iteration, 只用 mathlib 的人写定理, 训练 token 只有 0.238B; 用自动形式化的语句, 训练 token 到 3.108B, 多了一个数量级.

### 1.2. 起点: 冷启动一个会翻译的模型

整个流水需要一个会「把题目翻成 Lean」的模型, 但 DeepSeekMath-Base 一开始几乎不会. 冷启动用 MMA 数据集: 它把 mathlib 里的 Lean 4 语句用 GPT-4 反向翻成自然语言题目, 于是得到「自然语言到 Lean」的平行样本, 在上面微调一下, 模型就能按固定模板把题目翻成 Lean 4 声明. 模板要求只输出核心声明, 包在代码块里, mathlib 固定到某个 commit, Lean 固定在 v4.7.0-rc2. 版本固定这件事看似琐碎, 实际很关键: mathlib 引理的名字和签名会随版本变, 同一段证明在新版本上可能就过不了.

题源的选择也有讲究. 报告观察到, 条件明确, 目标清楚的竞赛题比需要复杂定义和构造的高等数学容易形式化, 所以主攻高中和本科竞赛题, 以代数和数论为主, 组合, 几何, 统计为辅. 这类题陈述简单, 解法可能不浅, 适合做证明训练数据. 自然语言题目从网上的习题, 考试, 竞赛资源爬取清洗, 得到 869,659 道. 爬了哪些网站, 怎么清洗, 报告没有细节. 这也埋下一个问题: 竞赛题来源和 miniF2F 的题源(AMC, AIME, IMO, MATH)高度重合, 报告通篇没有提到去污染, 后面读 miniF2F 分数时要把这一点记在心里.

### 1.3. 质量这一面: 打分和假设否决

自动形式化的产物有两类典型问题. 一类是太简单, 翻出来的语句平凡到没有训练价值. 处理办法是让模型**自己打分**: 标准包括与当前研究的相关性, 复杂度与深度, 跨学科潜力, 社区缺口, 创新性; 用 miniF2F-valid 的例子做 few-shot, 让模型用 CoT 把语句评成 excellent, good, above average, fair, poor 五档, fair 和 poor 丢弃. 人工抽查认为打分接近人的直觉. 表 3 用等量的高分档和低分档数据分别微调底座, pass@128 下 miniF2F-test 从 38.1% 到 42.6%, valid 从 41.4% 到 48.8%, 差约 4.5 个点. 这个设计有一个副作用: miniF2F-valid 进了打分提示, 它作为评测集的干净程度就打了折扣, 读 valid 分数时比 test 更要谨慎.

打分提示的输出格式在附录 A.1: 模型先把 Lean 代码翻回自然语言, 写出背景, 假设和定义, 再逐条给五个维度写理由, 最后给出总评. 先回译再打分, 相当于顺带做了一次语义检查, 翻不回通顺题意的语句多半会被打低分.

打分标准本身也值得多看一眼. 「与当前研究的相关性」「社区缺口」「创新性」这些维度, 更像是评审论文而不是评判一道练习题, 对一个 7B 模型来说判断起来并不容易. 真正起作用的大概是「复杂度与深度」这一项, 它把 `1 + 1 = 2` 式的平凡语句挡在门外. 报告只说人工抽查和直觉一致, 没有给抽查规模和一致率, 也没有给五档各自的比例, 被丢掉的 fair 和 poor 占多少, 本页无从得知. 表 3 证明了过滤有用, 但没证明这套五维标准比一个简单的「难度」打分更好.

另一类问题更隐蔽: 语句可以被证明, 但前提自相矛盾, 结论是空虚真. 报告的例子是假设「对所有复数 $z$, $z^2=-1$ 且 $z^3=-1$ 且 $z^6=1$」, 前提本身就假, 推出什么都没有意义. 处理办法是**假设否决**: 把结论换成 `False`, 让模型试证, 证出来就说明前提矛盾, 整条丢弃. §5.2 的行列式案例把这种错误的样子展示得很清楚: 模型把「存在 a, b, c 使行列式为 D」写成「对所有非零 a, b, c, 行列式都等于同一个 D」, 然后代入两组具体值算出不同的行列式, 用 `linarith` 推出矛盾. 这类量词错误在人眼里很像一个正常定理, 靠核验器反证才能稳定抓出来. 两道过滤之后, 87 万道题剩 712,073 条语句.

假设否决有一个结构上的盲区: 它只把冒号后面的结论换成 `False`, 检查的是冒号前面那些假设. 如果矛盾藏在结论内部的蕴含前件里, 或者藏在量词结构里, 这一步就看不见. 附录 A.2 被当作成功样例的两条语句正好说明了这一点. 例 a 要证「若对所有 $x$, $f(x)\le0$ 蕴含 $x<-1$ 或 $x>1$, 则 $a=3$」, 其中 $f(x)=x^3-ax-1$. 但 $f(0)=-1\le0$ 而 $0$ 不在那两个区间里, 所以这个前件对任何 $a$ 都不成立, 整条命题是空虚真. 模型给的证明正是把 $x=0,1,-1$ 代进前件, 再用 `linarith` 收尾. 前件写在冒号之后, 假设否决根本不会去检查它. 例 b 的形式是 `∃ k, f k = … → (∃ m, F m = … → m = k)`, 取 $m=k$ 内层就直接成立, 同样平凡, 证明也只是一行 `simp` 加 `aesop`. 报告对这两例的分析只评价了算子翻译得对不对(区间并, `Nat.choose`), 没有指出语义上已经空了(以上为读附录代码的判断). 这说明 20% 错误率只是下限, 通过核验的语句里仍有一部分在教模型「找平凡出口」.

自动形式化的提示也影响语句形态. 模板里的输入是 `informal_statement_with_answers`, 即题目连同答案一起给模型. 求值题因此被改写成「证明答案是某个数」的形式, 这是把计算题变成可证命题的关键一步; 代价是答案若本身有误, 翻出来的语句就是假命题, 要靠后面的否定并行兜底.

### 1.4. 规模这一面: 同时证原命题和它的否定

过了过滤, 语句仍然不保证为真. 报告估计即使过滤后, 也至少有 20% 的自动形式化语句是错的. 这在大规模合成里是算力黑洞: 人写的定理基本都成立, 可以放心一直搜; 机器翻出来的假命题, 模型会一直试到超时. 对策利用**命题和否定的对称性**: 对 $\Gamma\vdash P$ 和 $\Gamma\vdash\neg P$ 并行搜索, 各试最多 $k$ 次, 任何一边先找到能通过核验的证明就停. 按尝试次数算一下代价. 只搜 $P$ 时, 真命题在第 $j$ 次证出花 $j$ 次, 假命题一定烧满 $k$ 次. 双路并行时, 真命题在第 $j$ 次证出花 $2j$ 次, 多付一倍; 假命题若否定在第 $j'$ 次证出, 只花 $2j'$ 次, 只要 $j'<k/2$ 就比单路省; 两边都证不出的语句, 代价从 $k$ 变成 $2k$. 所以这套做法划不划算, 取决于假命题占比和否定证明来得多快. 报告没给 $k$ 的取值, 也没给这几类语句各占多少.

这一步同时解决了两件事. 算力上, 假命题通过证出否定被提前判死, 不再烧满超时预算. 数据上, 两边的证明都能进训练池: 证出原命题得到正样本, 证出否定也是一条合法的 Lean 证明, 形式化写错的语句反而变成了训练数据. 和 expert iteration 的原始做法相比, 这是最关键的改动. Expert iteration 默认待证命题都是真的, 只需要不断采样直到证出来; 自动形式化打破了这个前提, 必须给不可证的命题一个出口. 从社区对这篇的讨论看, 「否定并行」也是被引用最多的工程细节, 因为它几乎不增加复杂度, 却把合成流水的效率提高了一截.

否定并行和假设否决看起来相似, 其实分工不同. 假设否决在证明之前做, 把结论换成 `False`, 检查的是前提是否自洽; 否定并行在证明阶段做, 检查的是结论本身是否成立. 一条语句可能前提自洽但结论错了, 比如题目要求证明某个方程的解是 3, 模型翻译时把答案写成了 4, 这种错误假设否决抓不到, 只有否定并行能发现. 两道关口加起来, 覆盖了「前提坏」和「结论坏」两种情况. 报告没有给出否定一侧证出的比例, 训练池里否定证明占多少, 本页无从得知. 错误语句占 20% 以上, 不等于否定证明也占这么多, 因为很多错误语句可能两边都证不出. 这部分样本教模型的是「反驳」而不是「证明」, 对 miniF2F 这种全是真命题的评测是否有帮助, 报告也没有做单独消融.

### 1.5. 迭代: 弱模型滚成强模型

四个环节串成闭环: 形式化, 过滤, 证明, 用核验通过的样本微调, 更强的模型再回去做下一轮形式化和证明, 直到收益变薄. 每一轮的变化是双向的: 模型证得更多, 能进训练池的样本就更多, 而且更难的语句也开始有证明; 模型翻译得更准, 下一轮语句的质量也更高. 表 4 给出 pass@128 的台阶: iteration 0 到 4, miniF2F-test 从 34.0% 升到 39.3%, 41.4%, 45.1%, 46.3%, valid 从 38.1% 升到 59.4%. 涨幅逐轮收窄, test 在第 3 到第 4 轮只涨 1.2 个点.

这个闭环本质上是一种没有梯度信号的 RL. 核验器给出 0/1 奖励, 只保留奖励为 1 的样本做监督学习, 相当于 rejection sampling 加迭代. V1.5 的报告后来明确把这层关系说破: expert iteration 和合成数据对应 RL 的试错循环, 编译器是提供环境反馈的世界模型. 和 DeepSeekMath 的 GRPO 相比, 这里没有负样本的梯度, 也没有组内相对优势, 失败的证明被直接丢弃. 这种做法的好处是稳定, 坏处是浪费了失败样本里的信息, V1.5 用 RLPAF 补的就是这一块.

训练设定写得很短: 底座 DeepSeekMath-Base 7B, 全局 batch 512, 恒定学习率 $1\times10^{-4}$, 6000 步 warmup. 每轮训几步, 每轮新增多少样本, 各轮数据怎么混, 本页都没有给. 所以表 4 的逐轮提升里, 有多少来自「数据更多」, 有多少来自「数据更难」, 无法从本页拆开.

几个数字放在一起能粗看训练量级. 光 warmup 就是 6000 步 × 512 条, 约 307 万条样本, 相当于 800 万条数据的四成, 说明每轮微调不是轻量的几百步. 表 2 里自动形式化那一行写的训练量是 3.108B token, 如果它对应的是全部证明样本, 平均每条约 390 token, 这和附录里那些十行以内的短证明在量级上吻合. 和 DeepSeekMath 500B token 的续训相比, 形式证明这一步的训练量小了两个数量级, 模型能力的底子仍在数学预训练里.

数量关系上也有一处本页没解释清楚. 过滤后的语句是 712,073 条, 最终数据集是 8,066,621 条, 贡献列表写的是「800 万条形式语句, 每条都带一个形式证明」. 两个数差了十多倍. 可能的来源有几种: 每一轮用更强的模型重新形式化 87 万道题, 语句在各轮之间累积; 同一道题被翻成多个不同版本; 同一条语句保留了多个不同证明; 否定一侧的证明也计入. 即使按 5 轮, 每轮 71 万条算, 也只有约 350 万条, 仍不到 800 万, 所以至少还有一题多译或一句多证的情况. 报告没有给各部分占比, 读「800 万」时应理解为证明样本数, 不等于 800 万道不同的题.

## 2. 实验与评测

### 2.1. 数据规模和数据来源各自贡献多少

表 2 比较数据来源, 设定都是 pass@128. 底座不做任何形式证明训练时, miniF2F-test 27.5%; 用 mathlib 定理做 expert iteration, 31.2%; 用自动形式化语句, 42.6%. 人写的形式库只能带来不到 4 个点, 自动形式化带来 15 个点. 结论很明确: **mathlib 喂不饱一个 7B 证明器, 大规模自动形式化才是主要增益**. 顺带一提, 表 3 的高分档和表 2 的自动形式化行数字完全相同(48.8%, 42.6%), 大概率是同一次训练.

表 5 比较数据规模: 从 800 万条里取 1,000, 10,000, 100,000, 1,000,000 和全部 8,066,621 条, test 分别是 24.18%, 31.97%, 37.7%, 38.11%, 40.16%. 规模每涨一个数量级, 分数都涨, 但 10 万到 100 万只涨 0.4 个点, 到 800 万又涨 2 个点, 曲线不是平滑的. 这张表还有两处和别的表对不上. 一是只用 1000 条时 test 24.18%, 比完全不训的底座 27.5% 还低, 小数据微调反而伤了多样本采样. 二是全量 800 万条只有 40.16%, 低于表 4 第 4 轮的 46.3%. 报告没解释, 合理的猜测是表 5 是一次性微调的对照, 表 4 是逐轮迭代的模型, 训练过程不同. 这说明「数据量」和「迭代过程」是两个独立的变量, 800 万条数据一次喂进去, 抵不上边造边训.

### 2.2. 主结果: miniF2F 与 FIMO

miniF2F 有验证集和测试集各 244 题, 覆盖基础算术到 AMC, AIME, IMO 级竞赛题, 用 LeanDojo 发布的 Lean 4 版. 表 1 是报告最常被引用的一张表. DeepSeek-Prover 整证生成: 贪心约 30.0%, 64 次 46.3%, 128 次 46.3%, 8192 次 48.8%, 65536 次 50.0%. 累计(把所有实验中找到的证明合起来算)valid 60.2%, test 52.0%. 对照组: GPT-4-turbo 0409 在 64 次采样下 valid 25.4%, test 23.0%; 树搜索里最强的 Hypertree Proof Search(600M)累计 valid 58.6%, test 41.0%. 采样从 64 次加到 65536 次, 算力多了 1000 倍, test 只涨 3.7 个点, 说明整证生成在难题上很快碰到上限. pass@k 的定义是「模型生成的前 $k$ 次尝试里至少有一次通过核验」, 按一次实际采样的前 $k$ 条直接计数, 不是 Codex 那种从 $n>k$ 个样本里算 $1-\binom{n-c}{k}/\binom{n}{k}$ 的无偏估计. 如果 64 次和 128 次取自同一串采样, 两者同为 46.3% 就意味着第 65 到 128 条没有为任何新题找到证明; 报告也没给多次运行的方差.

读表 1 有两处要分清. 第一, 表格上半是树搜索方法, 下半是整证生成方法, 横轴一个是「交互步数乘分支」, 一个是「独立采样次数」, 不能直接当成同一种算力比. 第二, 「累计」不是一个固定预算下的数字, 而是所有实验找到的证明的并集, 和 pass@k 不可直接比较. 报告对这两点的表述是克制的: 在整证设定下, 7B 靠合成数据把 64 次采样的分数推到 GPT-4 的两倍, 累计指标超过当时最强树搜索的 test 分数, 没有声称用更少算力打败所有交互式证明器.

GPT-4 这条基线的设定也要看清. 报告说 GPT-4-turbo 0409 和 DeepSeekMath 都「用和本文类似的方法」生成完整证明, 但没有给 few-shot 示例数量, 导入前缀和温度. GPT-4 没有在 Lean 4 数据上微调, 而当时 Lean 4 和 mathlib 4 的写法相对 Lean 3 变化很大, 通用模型很容易写出旧语法或已改名的引理. 所以 23.0% 对 46.3% 的差距里, 有一部分是「见没见过当前版本的 Lean 4」, 不全是推理能力. 这不影响结论的方向, 但「两倍于 GPT-4」这个说法应当放在这个前提下理解.

FIMO 把 IMO shortlist 翻成 Lean 4, 正文写 149 题, 摘要写 148, 两处不一致. 每题 100 次尝试证出 4 题, GPT-4 为 0; 加到每题 4096 次再多证出 1 题, 共 5 题. 附录里的 FIMO 证例能看到模型会组合 induction, `linarith`, `nlinarith`, `field_simp`, `aesop` 等 tactic. 从 100 次加到 4096 次只多一题, 说明 IMO 级题目基本在这条路径的能力之外; 能证出的几题, 更像是训练分布边缘恰好覆盖到的题型. miniF2F 上的成功集中在训练数据最密的代数和数论中等难度题, 与 FIMO 的稀疏成功形成对照.

### 2.3. 评测这一面还缺什么

把前面几处放在一起看, 这篇报告的评测有几个本页没有处理的问题. 去污染: 训练题面爬自竞赛资源, miniF2F 同样来自 AMC, AIME, IMO, 两者可能重合, 报告没有做任何重合检查, 也没有报告合成语句和评测语句的相似度. 验证集使用: miniF2F-valid 被用作打分提示的 few-shot 示例, 又被当作评测集报告 60.2%. 采样预算: 主结果横跨贪心到 65536 次, 累计指标又是多次实验的并集, 不同行之间的算力差异很大. 这些问题不否定方法的有效性, 表 2 到表 5 的内部对照仍然成立, 但会影响和外部方法比较时的可信度.

附录 A.3.1 列出的 miniF2F-test 证例可以把这个担心说得更具体. 其中一题是 `amc12b_2021_p4`, 也就是 2021 年 AMC 12B 第 4 题, 另一题 `induction_1pxpownlt1pnx` 是伯努利不等式的一个归纳证明. AMC 真题及其解答在网上随处可见, 正是「高中与本科习题, 考试, 竞赛资源」会收录的内容. 这不证明它进了训练集, 但说明报告至少应当做一次题面级的重合检查. DeepSeekMath 在自然语言数学上做了 10-gram 去污染, 到了 Prover 这一步反而没有提, 算是这篇报告评测部分最明显的缺口. V1.5 的 SFT 数据甚至直接收入了 miniF2F 的验证集, 只保留测试集做评测, 口径比 V1 清楚.

模型大小也值得一提. 表 1 的树搜索对照里, Hypertree 是 600M, ReProver 是 229M, Proof Artifact Co-Training 是 837M, 多数比 7B 小一个数量级; Llemma 7B 和 34B 是同量级, test 分别 26.2% 和 25.8% 到 29.6%. 所以 DeepSeek-Prover 相对小模型搜索方法的优势, 有一部分来自参数量和数学预训练底座. 表 1 里 DeepSeekMath-Base 在 128 次采样下已有 27.5%, 高于 ReProver 的 25.0%, 就是底座本身的贡献. 在同一个底座上, 合成数据把 27.5% 推到 46.3%, 这 19 个点才是本文方法的净增量.

### 2.4. 案例里能看到的形式化难点

§5.1 的成功案例把一道余弦矩阵行列式为 0 的题, 翻成依赖实数 $a, b$ 的 `Matrix.det ![![...]] = 0`. 附录 A.2 的成功样本还有: 把「小于 -1 或大于 1」写成区间并 `Set.Iio (-1) ∪ Set.Ioi 1`, 二项式系数用 `Nat.choose`, 三维向量拆成 $\mathbb{R}\times\mathbb{R}\times\mathbb{R}$ 的分量. 这些都是形式化里的常见陷阱, 模型在标准代数和分析句式上已经能翻对. 条件和目标都是显式代数等式时, 自动形式化最可靠, 这也是题型选择偏向代数和数论的原因.

失败案例更能说明流水设计的道理. 量词写错, 前提矛盾, 这类错误让语句「形式上可证但数学上无意义」, 证明搜索再强也救不回来; 如果不做假设否决, 这类空虚真的证明会大量进入训练集, 模型学到的是「从矛盾前提推出任何结论」的技巧. 附录 A.4 还给了生成证明前固定的一长串 `import Mathlib...` 和 `import Aesop`, 以及 `maxHeartbeats 0` 等选项. 这套前缀决定了模型默认能用哪些引理和 tactic, 评测和合成时前缀不一致, 通过率就会漂移. 复现这篇报告需要同时拿到权重, 导入前缀, Lean 和 mathlib 的确切版本, 缺一样都可能对不上表 1.

附录 A.3.1 的成功证明也有一个共同风格: 很短, 主要靠 Lean 自带的自动化 tactic 收尾. 伯努利不等式那题只有一行 `induction'`, 接一串 `simp_all` 化简规则, 再用 `nlinarith` 喂一个平方非负的提示就结束了. 这说明整证明生成学到的更多是「选对 tactic 组合, 给对提示项」, 而不是一步步写出人类式推导. 这种风格和 miniF2F 里大量短代数题正好匹配, 碰到需要多层引理拼接的 IMO 级题目就吃力, FIMO 上 100 次采样只证出 4 题, 和这个观察一致. V1.5 后来引入自然语言 CoT 注释和 RMaxTS 搜索, 目标之一就是补这块长证明的短板.

## 3. 局限与谱系位置

结论写明的边界: 主战场是高中到本科的代数和数论, 几何, 高等定义, 更广的题型是下一步. 整证生成依赖 Lean 工具链和固定导入, 换证明助手或大改 mathlib 版本都要重建核验流水. 合成数据和模型的开源写在贡献和 Broader Impact 里. FIMO 的 5 题也标出了能力上限: 在极难基准上破零, 离系统性解决竞赛级形式证明还远.

谱系上, Prover 是 DeepSeekMath 的直接延伸. 底座是 DeepSeekMath-Base 7B, 继承了 120B 数学 token 的先验; 训练方法从 SFT 加 GRPO 退回到纯 SFT 加 expert iteration, 因为形式证明有了一个比奖励模型可靠得多的裁判, 也就是 Lean 核验器. 这里第一次出现了家族后来反复使用的一个结构: 能被程序自动判对错的任务, 就用判定器生成和过滤训练数据, 让模型自己滚大数据集. V1.5 在这个基础上补了三样东西: 用 Lean 反馈做真正的 RL(RLPAF), 在证明中写自然语言推理, 以及 MCTS 搜索. 再往后, R1 在数学和代码上只用规则奖励, 思路和这里用 Lean 判对错一脉相承. 形式证明的 SFT 数据选取可对照 [4.2.2-SFT数据质量筛选与训练技巧](../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md), 这篇的打分过滤就是其中「模型打分筛数据」的一个具体实例.
