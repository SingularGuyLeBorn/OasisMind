# Janus: 看图和画图各用一套视觉编码

来源: [Janus: Decoupling Visual Encoding for Unified Multimodal Understanding and Generation](https://arxiv.org/abs/2410.13848) (arXiv: 2410.13848v1, 2024-10-17). 仓库: https://github.com/deepseek-ai/Janus

Janus 是一个 1.3B 的统一多模态模型: 同一个自回归 Transformer 既回答关于图片的问题, 也按文字生成图片. 它的主张只有一条, 理解和生成对视觉表征的要求不同, 不该共用一个视觉编码器. 于是理解走 SigLIP, 生成走 VQ tokenizer, 两条通路在进入语言模型之前分开, 之后共用同一套 Transformer 和 next-token prediction 目标. 这篇报告的证据集中在 Table 5 的六组消融上, 主结果表更多是在说明「1.3B 的统一模型能做到什么程度」. 下面把架构, 数据配比, 三阶段训练, 评测协议和消融放在一起读, 看这条主张被证明到了哪一步.

## 1. 问题与架构

### 1.1. 问题: 共用一个视觉编码器, 理解先吃亏

2024 年的统一多模态模型大致分两路. 一路是工具式组合: 多模态 LLM 负责理解和给条件, 真正出图交给外挂的扩散模型, 如 Emu, NExT-GPT. 报告认为这不算真正统一, 因为 LLM 本身不会生成图像, 整体效果常被外挂扩散模型卡住, 甚至不如直接用那个扩散模型. 另一路是单个 Transformer 同时做理解和生成, 如 Chameleon, Show-o, LWM, VILA-U. 这一路的共同点是视觉输入只经过一套编码: Chameleon 用同一个 VQ tokenizer 处理输入和输出图片, VILA-U 用一个兼顾语义和重建的离散 tokenizer.

报告指出这种共用有代价. 理解任务要的是高层语义, 比如物体类别, 属性和关系, 编码器的输出要能支撑推理; 生成任务要的是局部纹理和全局结构, 编码必须保留细粒度的空间信息. 两种需求放在同一个表征空间里, 编码器只能折中. 从 Table 2 看, 此前的统一模型在理解上普遍明显落后于同规模的专用理解模型, 例如 Show-o 1.3B 的 MME-P 只有 948.4, 同样 1.3B 语言底座的 LLaVA-v1.5-Phi-1.5 是 1128.0. Janus 要验证的是: 把编码器拆开, 理解能不能追上来, 生成会不会因此变差.

### 1.2. 两条视觉通路

理解通路用 **SigLIP-Large-Patch16-384**. 384×384 的图按 16×16 切块, 得到 24×24 共 576 个 patch 特征, 从二维网格展平成一维序列, 再经一个两层 MLP 的理解 adaptor 映射到 LLM 的输入空间. SigLIP 用逐对的 sigmoid 损失替代 CLIP 那种需要全 batch softmax 归一化的对比损失, 训练对 batch 大小更不敏感, 它的特征偏向图文语义对齐, 当代 VLM 多用它当视觉塔. 视觉编码器的选型讨论见 [CLIP 与视觉编码器](../../../llm-guide/8-多模态/8.8-CLIP与视觉编码器/01-CLIP与视觉编码器/01-CLIP与视觉编码器.md), LLaVA 式「编码器加 adaptor 接 LLM」的结构见 [LLaVA 架构深度解析](../../../llm-guide/8-多模态/8.2-视觉语言模型/02-LLaVA架构深度解析/02-LLaVA架构深度解析.md).

生成通路用 LlamaGen 的 **VQ tokenizer**, 码本 16,384 项, 下采样 16 倍, 所以 384×384 的图同样变成 576 个离散 ID. 每个 ID 对应的码本向量经生成 adaptor(也是两层 MLP)映射进 LLM. 输出端另起一个随机初始化的图像预测头, 在 16,384 个码本 ID 上做分类; 文本仍用 LLM 自带的预测头. 生成出的 ID 序列交给 VQ 的 CNN 解码器还原成像素. 报告只写了码本大小和下采样率; 按 LlamaGen 报告, 这个 tokenizer 的码本向量只有 8 维并做 L2 归一化, 在 384 分辨率下的重建 rFID 是 0.94. 码本向量维度这么低, 说明它就是为「重建像素」设计的, 几乎不带语义, 这也是 Exp-A 里拿它做理解会崩的原因.

两条通路的形状差别很大: 一边是 1024 维的连续特征, 一边是离散 ID 查表得到的低维向量, 所以各配一个 adaptor. 语言底座是 DeepSeek-LLM 1.3B, 最大序列长 4096. 一张图在两条通路里都占 576 个位置, 所以一条 4096 的序列最多放六七张图. 整个模型只用标准的因果注意力, 不需要为图像设计特殊的注意力掩码; 这一点和 Show-o 在图像部分用双向注意力不同, 实现上更简单, 代价是生成时只能逐个 token 解码.

### 1.3. 一个 Transformer 怎么同时做两件事

训练目标就是式 (1) 的交叉熵 $\mathcal{L}=-\sum_i\log P_\theta(x_i\mid x_{<i})$. 求和只覆盖被监督的位置: 纯文本和多模态理解样本只在文本 token 上算损失, $x_i$ 取自 LLM 词表, 由文本头预测; 视觉生成样本只在图像 token 上算损失, $x_i$ 是 16,384 个码本 ID 之一, 由图像头预测. 同一个 $x_{<i}$ 前缀里, 图片在理解样本中以 SigLIP 特征的形式出现, 在生成样本中以 VQ 码本向量的形式出现, 两条通路只在输入端分叉, 损失形式完全一样. 三类任务不设损失权重. 数据格式也很直接: 理解样本是 `<image><text>`, 生成样本是 `<caption><image>`, 指令微调阶段套上 `User: <Input Message>\nAssistant: <Response>` 的模板, 只监督回答, 系统提示和用户提示做 mask. 模型靠输入里图片出现在前还是在后来区分「看图」还是「画图」, 没有额外的任务标记.

不设损失权重不等于三类任务的梯度份额按样本比例分配. 交叉熵是按 token 求和的, 一个生成样本要监督 576 个图像 token; 一个理解样本只监督回答里的文本, 图像描述一般几十到一两百个 token, 选择题式的问答更短. 阶段 II 里生成样本占一半, 按监督 token 数算, 生成在总损失里的份额很可能远超一半. 报告没有给各类样本的平均长度, 也没有讨论这个失衡. 如果它存在, Exp-D 对 Exp-E 在 MMBench, SEED 上那 1 个点左右的下降, 可能就和生成 token 占了大部分梯度有关.

三类数据在同一步里混合, 也有工程上的考虑. 如果按任务轮流训练, 每一段都会把模型往一个方向推, 容易出现遗忘; 同一步里混合, 每次更新都同时照顾三类任务. 纯文本数据在阶段 II 占 3/10, 阶段 III 占 3/20, 它的作用是让 1.3B 的语言底座在大量图像 token 的冲击下不丢掉语言能力. 报告没有给 Janus 在纯文本基准上的成绩, 所以这部分数据是否足够, 仅凭报告无从判断.

生成时用 **classifier-free guidance**(CFG). 每个图像 token 都算两次 logit, 一次带文本条件得到 $l_c$, 一次不带条件得到 $l_u$, 最终 $l_g=l_u+s(l_c-l_u)$, 评测默认 $s=5$. 无条件分支来自训练时的条件丢弃: 以 10% 概率把文生图数据里的文本换成 pad token. CFG 放大了条件和无条件预测的差, 让图像更贴合提示, 代价是每步前向算两遍, 576 个 token 就要约 1152 次前向(可以把两路拼成一个 batch). 报告没有给不同 $s$ 下的 FID 和 GenEval 曲线, 所以不清楚 $s=5$ 是怎么选的, 也不清楚它在「贴提示」和「画质多样性」之间落在哪里.

这种设计里, 理解和生成共享的是 Transformer 的全部权重和同一个目标. 视觉编码器分开以后, 两类任务在 LLM 内部仍然要争用同一套参数. Table 5 的 Exp-D, E, F 就是在测这一层有没有冲突, 见第 4.1 节.

## 2. 训练与评测设置

### 2.1. 三阶段训练和数据配比

阶段 I 只训理解 adaptor, 生成 adaptor 和图像头, 两个视觉编码器和 LLM 都冻住. 数据是 ShareGPT4V 的 1.25M 条图文描述加 ImageNet-1k 约 1.2M 张图, ImageNet 按类名做成 `<category_name><image>` 的文生图格式. 学习率 1e-3, cosine, warmup 300 步, 共 10K 步, batch 256, 三类数据比例(理解 : 纯文本 : 生成)为 1 : 0 : 1. 按每条序列一个样本粗算, 10K×256 约 2.56M 条, 两类各一半, 恰好把 ShareGPT4V 和 ImageNet 各过一遍. 这一阶段的目标是让新加的三个小模块先对齐到冻结的 LLM, 避免随机初始化的 adaptor 一上来就把 LLM 的权重冲乱. 学习率 1e-3 比后两个阶段高一到两个数量级, 因为只训几个小模块, 不用担心破坏大模型; 纯文本比例为 0, 也是因为 LLM 冻结, 不存在遗忘问题. 图像头在这一阶段只见过 ImageNet 的类名条件, 所以阶段 I 结束时的「初步生成能力」其实是类别条件生成, 开放域文生图要到阶段 II 后段才开始学.

阶段 II 解冻 LLM 做统一预训练, 学习率 1e-4 恒定, warmup 5K 步, 共 180K 步, batch 512, 比例 2 : 3 : 5. 数据有五类: DeepSeek-LLM 的纯文本预训练语料; WikiHow 和 WIT 的图文交错数据; 多个来源的图像描述, 其中一部分用开源多模态模型重写, 格式化成「详细描述这张图」的问答; DeepSeek-VL 的表格和图表数据; 以及多来源的文生图数据加 2M 内部数据, 其中两个数据集按美学分和尺寸过滤后只留 20%. 生成部分分两段: 前 120K 步只用 ImageNet, 后 60K 步换成开放域文生图, 这个顺序借鉴 PixArt, 先学基本的像素依赖, 再学复杂场景. 训练时还以 25% 概率只保留描述的第一句, 让模型也能处理短提示.

按同样粗算, 阶段 II 共约 92M 条序列, 生成占一半约 46M; 前 120K 步里 ImageNet 约 30.7M 次, 相当于把 1.2M 张图反复过了约 25 遍, 后 60K 步开放域生成约 15.4M 次(实际用了 sequence packing, 一条序列可能包含多个样本). 也就是说, 生成通路三分之二的预训练预算花在了 ImageNet 的类别条件生成上, 真正的开放域文生图只占三分之一. 这个配比对 Janus 的生成能力影响有多大, 报告没有做对照; 后来的 Janus-Pro 调整了这一段的数据安排.

阶段 III 做指令微调, 除生成编码器外全部参数都训练, 学习率恒定为 2e-5, weight decay 0.1, 无 warmup, 共 24K 步, batch 256, 数据比例为 7 : 3 : 10. 纯文本对话使用一个开源对话集, 多模态理解使用六个开源指令数据集, 生成数据来自阶段 II 的一个子集和 4M 内部数据. 理解与生成样本混合训练, 一个 checkpoint 同时保留两种能力. 冻结范围也随阶段改变: 阶段 II 只解冻 LLM, 两个视觉编码器保持冻结; 阶段 III 除生成编码器外全部更新, 因而 SigLIP 直到指令微调阶段才参与训练. 生成端 VQ 编码器始终冻结, 它的码本决定图像头预测的 ID, 改动码本会破坏与像素解码器的对应关系. 粗略计算, 阶段 III 约有 6.1M 条序列, 其中生成约 3.1M, 理解约 2.2M, 纯文本约 0.9M; 生成部分的 4M 内部数据加开源子集, 训练轮数不到一遍. 全部训练在 16 个节点上运行 7 天, 每节点 8 张 A100 40GB, 约 2.15 万 GPU 小时, 框架为 HAI-LLM. 三个阶段都使用 AdamW, $\beta_1=0.9$, $\beta_2=0.95$, 梯度裁剪 1.0.

### 2.2. 预处理和评测协议

图像统一到 384×384, 但两类任务的预处理不同. 理解数据把长边缩到 384, 短边用 RGB(127, 127, 127) 的灰色补齐, 保证整张图的内容都在; 生成数据把短边缩到 384, 长边裁到 384, 目标图像不带灰边. 这个分叉和编码器的分叉是同一个道理: 理解不能丢信息, 生成不能学出灰边. 训练用 sequence packing, 每一步都按上面的比例混合三类数据.

理解评测用 VQAv2, GQA, POPE, MME, SEED, MMBench, MM-Vet, MMMU 八项. 其中 POPE 专门测物体幻觉, MME-P 是感知部分的总分(满分 2000), MM-Vet 用 GPT-4 给开放回答打分, MMMU 是大学水平的多学科题. 生成评测用 MSCOCO-30K 和 MJHQ-30K 的 FID, 以及 GenEval. FID 衡量生成图和 3 万张真实图在 Inception 特征空间的分布距离, 看的是整体画质和多样性; GenEval 用目标检测器去检查生成图里有没有提示要求的物体, 数量, 颜色和位置, 看的是组合式的指令跟随. 理解评测用的解码设置(贪心还是采样, 最大长度多少)报告没有写; 生成评测的采样温度, top-k 也没有写, 只给了 CFG 尺度. 报告没有说明对照模型的数字是自测还是引用, 从 Table 2 大量空格看, 应当主要是引用各自论文, 这意味着不同行之间的提示模板和解码设置未必一致.

## 3. 评测结果

### 3.1. 理解评测: 同规模里领先, 但不是全面领先

Janus 在 Table 2 的成绩: POPE 87.0, MME-P 1338.0, MMBench 69.4, SEED 63.7, VQAv2 77.3, GQA 59.1, MMMU 30.5, MM-Vet 34.3. 相对此前最好的同规模统一模型 Show-o, 报告说 MME 提升 41%(949 到 1338), GQA 提升 30%(48.7 到 59.1). 前一个数核算无误, 后一个按表内数字算是 $59.1/48.7-1\approx$ 21%, 报告的 30% 算错了. 提升本身仍然很大, 只是幅度要按 21% 理解.

和同规模的专用理解模型比, 优势就没有那么大. LLaVA-v1.5-Phi-1.5 同样是 1.3B 语言底座, Janus 在 POPE(87.0 对 84.1), MME-P(1338 对 1128), GQA(59.1 对 56.5)上领先, 但 MMMU 反而低 0.2(30.5 对 30.7). MobileVLM-V2 1.4B 的 GQA 是 59.3, 也略高于 Janus. 所以更准确的说法是: 解耦以后, 统一模型的理解能力追平了同规模专用模型, 部分项目小幅领先. 这恰好是报告摘要里「匹配或超过专用模型」的意思.

各项的性质不同, 领先的位置也有规律. POPE 用「图里有没有某物体」的是非题测幻觉, Janus 的 87.0 是全表最高, 连 7B 模型都没超过; MM-Vet 用 GPT-4 给开放回答打分, Janus 的 34.3 高于 LLaVA-v1.5 7B 的 31.1. 这两项主要考「看得准不准, 说得全不全」, 依赖视觉特征的质量, SigLIP 在这里起了主要作用. 落后的 MMMU, GQA, VQAv2 更依赖知识和多步推理, 或者依赖大量同分布的训练数据, 语言底座的规模可能更关键.

报告强调 Janus 在 POPE, MMBench, SEED, MM-Vet 上超过 7B 的 LLaVA-v1.5, 这四项确实都赢. 但 LLaVA-v1.5 在 MME-P(1510.7), VQAv2(78.5), GQA(62.0), MMMU(35.4)上仍领先. 7B 的统一模型 VILA-U 在 MME-P(1401.8), VQAv2(79.4), GQA(60.8)上也高于 Janus. 考虑到 Janus 只有 1.3B, 这些差距多半反映的是语言底座的大小, MMMU 这类需要知识和推理的题尤其依赖底座.

表里还有一组可以和消融互相印证的数字. 同样共用 VQ 编码的 Chameleon 7B, MMMU 22.4, MM-Vet 8.3; LWM 7B 的 MM-Vet 只有 9.6. 这些 7B 模型的理解成绩, 和 Exp-A 里 1.3B 共用 VQ 的 MMMU 24.7 处在同一水平, 远低于同规模的 LLaVA 类模型. 也就是说, 「用重建型 VQ 做理解就会很差」不只是 Janus 自己消融里的现象, 在别人的模型上也看得到, 把语言底座做到 7B 也补不回来. 带 † 的工具式模型(DreamLLM, LaVIT, Emu, NExT-GPT)理解端用的是连续视觉特征, VQAv2 在 52.0 到 72.9 之间, DreamLLM 的 MM-Vet 36.6 甚至高于 Janus, 这也和「理解要用语义特征」的判断一致.

Figure 5 的表情包例子是定性证据: Janus 读出了图里的文字并理解了笑点, Show-o 把狗的颜色认错, Chameleon 连物体都没认出来, 两者都读错了图中文字. 读图中文字依赖编码器保留的细节, SigLIP 在 384 分辨率下 16×16 的 patch 对小字仍然吃力, 报告在扩展方向里提到动态高分辨率, 应当也是为此.

### 3.2. 生成评测: 贴提示强, 计数和画质仍有差距

GenEval 总分 Janus 0.61, 高于 Show-o 的 0.53, SDXL 的 0.55, DALL-E 2 的 0.52 和 Emu3-Gen 的 0.54. 拉开差距的是两项: 位置关系 0.46, 对 SDXL 0.15, Emu3-Gen 0.17; 颜色属性绑定 0.42, 对 SDXL 0.23, Show-o 0.28. 这两项考的是「把红色给对物体, 把左边放对位置」, 正好是语言模型理解长提示的强项, 统一模型把文本理解和图像生成放在同一个 Transformer 里, 这里受益应该最明显. 但计数只有 0.30, 低于 Show-o 的 0.49, SDXL 的 0.39, 甚至低于 SDv1.5 的 0.35; 两物体 0.68 也低于 SDXL 的 0.74. 总分 0.61 的领先主要来自位置和颜色属性两项.

FID 方面, COCO-30K 8.53, MJHQ-30K 10.10, 都好于 Show-o(9.24, 15.18)和 LWM(12.68, 17.77). 但同在 384 分辨率的 VILA-U 在 MJHQ-30K 上是 7.69, 比 Janus 好; COCO-30K 上 PixArt-α 7.32, Imagen 7.27, RAPHAEL 6.61, 纯生成模型仍领先一截. Figure 4 把 Janus 和 SDXL, LlamaGen 做定性对比, 三者分辨率分别是 384, 1024 和 512, 所以 Figure 4 只能用来比较谁更贴提示, 不能用来比细节.

Table 4 里带 † 的工具式模型提供了另一个角度. Emu 的 COCO FID 11.66, NExT-GPT 11.28, SEED-X 14.99, 都比它们所依赖的 Stable Diffusion 系列(SDv1.5 是 9.62)差. 这和报告在引言里的判断一致: 把 LLM 的输出当条件喂给外挂扩散模型, 整体生成质量会被接口拖累, 不如直接用扩散模型. Janus 的 8.53 好于 SDv1.5, 说明统一自回归路线在 1.3B 规模上已经能在分布质量上超过这些外挂方案. 另一方面, 共用 VQ 的 Chameleon 做到 34B, GenEval 也只有 0.39, 共用编码器的问题在生成端同样存在, 只是没有理解端那么严重.

LlamaGen 本身也在 GenEval 表里: 0.8B, 总分只有 0.32, 位置 0.07, 颜色属性 0.04. Janus 的生成端用的是同一个 VQ tokenizer, 同样是逐 token 自回归, 总分却接近翻倍, 位置和颜色属性提升了一个数量级. 差别可能主要在于条件端: LlamaGen 的文本条件来自 FLAN-T5 编码器, Janus 的文本和图像在同一个 1.3B 语言模型里交互, 语言理解更强, 训练数据也不同. 这个对比比 Janus 和扩散模型的对比更能说明「统一」带来的好处, 因为图像表征相同, 差异主要落在语言侧.

## 4. 消融

### 4.1. 消融: 哪一步证明了解耦有效

Table 5 的六组实验要按顺序读. Exp-A 按 Chameleon 的做法, 理解和生成都用同一个 VQ tokenizer: 生成的 COCO FID 8.72, 还不错; 理解却很差, POPE 60.1, MMBench 35.0, SEED 34.9, MMMU 24.7. Exp-B 换一个更强的共享编码器, 即用 SigLIP 蒸馏出的语义 tokenizer(见第 4.2 节): 理解明显回升, POPE 82.4, MMBench 52.7, SEED 54.9, MMMU 26.6, 生成 FID 还降到 7.11, 比 Janus 主模型的 8.53 更好. Exp-C 用同一个语义 tokenizer 只训理解: MMBench 从 52.7 升到 62.1, SEED 从 54.9 升到 60.8. B 和 C 的差距说明, 即使共享编码器已经带了语义, **同时承担生成仍会拖累理解**. 这是整篇报告最直接的一条证据.

Exp-D 是 Janus 本身: SigLIP 加 VQ, 理解和生成一起训, POPE 87.0, MMBench 69.4, SEED 63.7, MMMU 30.5, FID 8.53, 与主结果表完全相同, 说明 D 就是正式模型. Exp-E 只用 SigLIP 训理解, Exp-F 只用 VQ 训生成, 两者在各自任务上的训练步数与 D 相同. 结果 E 的 MMBench 70.6, SEED 64.8, 略高于 D; POPE 85.9, MMMU 28.8, 略低于 D. F 的 FID 8.92, 反而比 D 差. 报告据此认为统一训练基本不伤理解. 更细地看, 统一训练在 MMBench 和 SEED 上各掉约 1 个点, 在 POPE 和 MMMU 上涨了 1 到 2 个点, 生成还略有改善; 这些差距都在 2 个点以内, 每组只训一次, 没有误差条, 方向不能当成确定结论.

把 Exp-A 和 Exp-F 放在一起看还能得到一个报告没有明说的结论. 两者生成端都是普通 VQ, A 同时训理解, F 只训生成, 结果 A 的 FID 8.72 反而略好于 F 的 8.92. 也就是说, 共用 VQ 编码器时, 加入理解任务并没有伤害生成; 受伤的只有理解. **冲突是单向的**: 生成需要的细粒度表征塞给理解会导致理解很差, 反过来理解数据并不妨碍生成. 这和第 1.1 节「统一模型在理解上普遍落后」的观察对得上, 也解释了为什么此前的统一模型大多选择以生成为准的编码器.

报告没有说明 A, B, C, E, F 是否与 D 一样完成了 180K 加 24K 步的三阶段训练. 每组完整训练约需 2 万 GPU 小时; 如果其它组缩短了日程, 它们与 D 就不是等算力比较. Exp-B 的生成 FID 比 D 好 1.4, 报告给出两个可能原因: 语义 tokenizer 的离散 ID 更连贯, 更容易被 LLM 预测; B 的视觉编码器参数量也明显更大. 这两个因素没有分开实验. 按公开数据粗算, LlamaGen 的 16 倍下采样 tokenizer 约 72M 参数, 语义 tokenizer 在此基础上增加一个 12 层、隐宽 768 的 ViT, 规模接近 ViT-B, 约 86M, 合计约为普通 VQ 的两倍多. 因此现有实验无法分别计算参数规模和语义表征对 FID 改善的贡献. 「生成端采用语义更强的离散表征」仍值得继续验证, 解耦方案所用的普通 VQ 未必是最优选择.

### 4.2. 消融里的语义 tokenizer

附录 A 描述了 Exp-B, C 用到的**语义 tokenizer**. 它以 LlamaGen 的 tokenizer 为骨架, 下采样 16 倍; 在向量量化之后, 除了原来还原像素的 CNN 解码器, 再加一条 12 层 ViT 的语义解码分支, 12 个头, 隐宽 768, 用因果注意力掩码, 方便后面接 LLM. 训练从零开始分两段: 先在 ImageNet-1k 上训 40 个 epoch, 再在 Janus 预训练用的约 **5000 万**张生成数据图上训 1 个 epoch, 学习率恒定 1e-4, batch 128. 损失由两部分组成: 沿用 LlamaGen 的 RGB 重建损失, 以及按 BEiT-v2 的做法, 让语义解码器的输出和 SigLIP-Large-Patch16-384 的特征做余弦相似度最大化, 权重 0.25. 写成一个式子是 $\mathcal{L}=\mathcal{L}_{\mathrm{rec}}+0.25\,\mathcal{L}_{\mathrm{sem}}$, 其中 $\mathcal{L}_{\mathrm{sem}}$ 按 BEiT-v2 的写法是逐 patch 的 $-\cos(\hat{\mathbf f}_j,\mathbf f_j^{\mathrm{SigLIP}})$ 取平均($\hat{\mathbf f}_j$ 是语义解码器在第 $j$ 个位置的输出). $\mathcal{L}_{\mathrm{rec}}$ 按 LlamaGen 报告是一组损失(像素重建, 量化承诺, 感知与对抗项), Janus 报告没有逐项列出. 两个解码器读的是同一份量化结果: 余弦项的梯度经语义解码器回到编码器, 把量化前的特征往「能解码出 SigLIP 特征」的方向拉, 重建项往「能还原像素」的方向拉, 码本跟着编码器特征移动, 最后大概落在两者之间.

接入 LLM 时, 图像先经 CNN 编码器, 向量量化和语义解码器变成连续的语义特征, 经 adaptor 送进 LLM 当输入; LLM 预测的仍是离散 ID, 最后由像素解码器还原成图. 也就是说, 语义 tokenizer 在输入端给 LLM 语义特征, 在输出端让 LLM 预测离散 ID, 思路和 VILA-U 相近. 它的语义来自 SigLIP 蒸馏, 上限不会超过 SigLIP 本身, Exp-C 的理解成绩(MMBench 62.1)低于直接用 SigLIP 的 Exp-E(70.6), 也符合这个预期. 蒸馏损失权重只有 0.25, 重建仍是主目标, 语义保留得不够完整可能是差距的一部分原因. 报告明确说这个 tokenizer 只用于消融, 主实验为了简单用普通 VQ.

## 5. 局限与谱系位置

解耦视觉编码还留下一个可检验的边界：理解分支看到的连续语义特征与生成分支看到的离散码并未被要求逐位置一致。同一张图经过两条路径后，Transformer 接收的是两种不同坐标系中的表示。共享语言模型可以在任务标记和上下文帮助下学习两套条件分布，却不保证理解得到的属性能够原样约束生成，也不保证生成码中的细节能被理解分支读出。检验这种跨路径一致性，需要图像重建、属性问答与条件再生成组成闭环，仅看两组独立基准还不够。

局限有几处. 分辨率只有 384, 生成图的细节上限明显; 计数能力弱; 生成端的离散 VQ 码本几乎不带语义, Exp-B 已经暗示换成更好的生成表征能提升画质; 生成需要逐 token 解码 576 步再加 CFG 的双倍前向, 速度不占优势, 报告没有给生成耗时. 附录 B 的 Figure 8 展示了一个意外现象: 训练里的文生图数据只有英文, 但中文、法语、日语甚至带 emoji 的提示也能生成对应的图, 作者归因于语言底座先把各种语言映射到了共同的语义空间. 这些样例属于定性展示, 报告未提供多语言生成的定量评测.

生成速度值得单独算一下. 一张 384×384 的图要逐个解码 576 个 token, 每个 token 在 CFG 下要算条件和无条件两路; 扩散模型通常是 20 到 50 步去噪, 每步对整张图的潜变量并行计算. 自回归路线可以借用 LLM 的 KV cache 和 vLLM 这类推理框架加速, LlamaGen 就报告过用 vLLM 提速 3 到 4 倍. 但分辨率一旦提高, token 数按平方增长, 768×768 就是 2304 个 token, 这是自回归图像生成在高分辨率上的主要障碍, 报告提到的「因果和双向注意力混合」就是为了缓解它.

报告还列了几个扩展方向: 理解端换 EVA-CLIP, InternViT 等更强的编码器, 或用动态高分辨率和 pixel shuffle 压缩 token; 生成端换 MoVQGAN 这类更细的编码器, 改用 diffusion loss, 或者混合因果和双向注意力来减少逐 token 生成的误差累积; 再往外可以接点云, 触觉, 脑电等新模态, 每种模态配自己的编码器. 这些都是解耦带来的灵活性, 两条通路可以各自升级而互不影响. 统一多模态的整体图景见 [多模态](../../../llm-guide/8-多模态/8-多模态.md).

在 DeepSeek 谱系里, Janus 的语言底座来自 DeepSeek-LLM, 表格图表数据来自 DeepSeek-VL, 训练框架是 HAI-LLM, 生成端直接用了开源的 LlamaGen tokenizer. 它之后有两条延续: 同年 11 月的 JanusFlow 把生成端换成 rectified flow, 仍保留理解端的 SigLIP; 2025 年 1 月的 Janus-Pro 保持架构不变, 把模型扩到 7B, 扩充数据并调整三阶段的训练安排. 两者都保留了「理解和生成各用一套视觉编码」这个前提. Janus 这篇报告留下的主要是 Table 5 的 B 对 C 对比: 共享编码器即使带了语义, 同时做生成也会拖累理解.


## 6. 信息表示、统一序列与 Janus-Pro 演进

前五节给出 Janus 的直接证据，这一节从表示目标重新推导两条视觉路径：SigLIP 提供适合语义判别的连续特征，VQ tokenizer 提供可由自回归模型预测并还原图像的离散索引。两者共享 Transformer，不意味着它们共享视觉信息瓶颈。






本文提出 **Janus**: 用自回归框架把多模态理解与生成放进同一套系统. 既往工作(如 Chameleon)常让理解, 生成共用一个视觉编码器; 但两类任务对信息粒度的要求差得很远, 硬绑在一起往往两头不讨好, 理解侧尤其吃亏. Janus 把视觉编码拆成两条通路, 后面仍由同一个统一 Transformer 处理. 解耦一方面缓和编码器在「理解 / 生成」角色上的冲突, 另一方面提高可扩展性: 理解支路与生成支路可以各自挑最合适的编码方式. 实验显示 Janus 超过先前统一模型, 并在若干任务上追平或超过专用模型. 结构简单, 灵活, 有效, 适合作为下一代统一多模态模型的候选骨架.

「信息粒度」这里指: 理解侧更在意高层语义(类别, 属性, 推理), 生成侧更在意局部纹理与空间结构. 同一编码器既要抽语义又要保细节, 表征空间容易互相拉扯.





近年多模态大模型在理解与生成两端都推进很快 [20, 51]. 理解侧多沿 LLaVA [51]: 用视觉编码器当桥梁, 让 LLM 读图. 生成侧扩散方法 [9, 20, 67] 成绩突出; 也有人用自回归做视觉生成 [73, 79], 质量已能逼近扩散. 为了做更强的通才模型, 社区开始把理解与生成拼进同一系统 [75, 77, 94]. 一类做法是把理解模型接到预训练扩散模型上 [27, 28, 75]: 例如 Emu [75] 用 LLM 输出当条件, 真正出图仍靠外部扩散. 严格说这还不算「真统一」-- 生成能力在外挂扩散里, 多模态 LLM 自己并不会直接画图.

另一类工作 [77, 85, 86, 94] 用单个 Transformer 同时扛理解与生成: 指令跟随更好, 可能出现涌现能力, 也少一套冗余模块. 这类方法通常仍用**同一个**视觉编码器喂两类任务. 但所需表征差得很远. 理解时, 编码器要抽高层语义(物体类别, 视觉属性等), 输出还要支撑复杂语义推理, 表征粒度偏高维语义. 生成时, 重点是局部细节与全局一致性, 更需要能表达细粒度空间结构与纹理的低维编码. 把两套需求塞进同一表征空间, 就会冲突, 折中. 于是现有统一模型常在理解侧让步, 明显落后于专用理解模型. 消融实验里会再展开这一点.





为解决上述问题, 我们提出 **Janus**<sup>1</sup>: 统一多模态框架, 把理解与生成的视觉编码解耦. 具体做法是两条独立视觉编码通路-- 理解一条, 生成一条-- 再由同一 Transformer 架构统一处理. 好处主要有两点: (1) 缓和两类任务对粒度需求不同带来的冲突, 选编码器时不必再在理解与生成之间硬折中; (2) 更灵活, 更好扩展. 解耦之后, 理解与生成可以各自采用本领域更强的编码技术.

<small><span class=「docvortex-page-footnote」 data-block-type=「page_footnote」 style=「color: #6b7280」><sup>1</sup>罗马神话里 Janus(雅努斯)是双面神, 象征对立力量并存. 模型名取此意: 理解要抽象高层语义, 生成要具体细节; 用专用编码器拆开两条路, 再在统一架构里化解张力. </span></small>





并且将来还可以接更多输入类型, 如点云, 脑电(EEG), 音频等: 各自独立编码器抽特征, 再交给统一 Transformer.




据我们所知, 这是首次在「统一理解 + 生成」框架里强调**解耦视觉编码**的重要性. 实验上, 同等参数量级下 Janus 在理解与生成基准都超过既有统一模型, 达到当时领先水平; 甚至超过部分参数量大得多的专用模型(图 1). 具体地, 理解基准 MMBench [54], SEED-Bench [42], POPE [48] 上, Janus(1.3B)分别得到 69.4, 63.7, 87.0, 超过 LLaVA-v1.5(7B)[50] 与 Qwen-VL-Chat(7B)[3]. 生成基准 MSCOCO-30K [11], GenEval [30] 上, FID 为 8.53, 准确率 61%, 超过 DALL-E 2 [66], SDXL [62] 等文生图模型. 性能加上灵活可扩展, 使 Janus 成为下一代统一多模态模型的有力候选.

FID(Fréchet Inception Distance)越低通常表示生成分布越接近真实图像分布; GenEval 则按物体组合, 计数, 颜色, 位置等细项看「指令跟得紧不紧」.


#### 2.1. Visual Generation 视觉生成




视觉生成发展很快, 把 NLP 思路与 Transformer 进展揉在一起. 自回归模型受语言建模启发, 用 Transformer 预测离散视觉 token(码本 ID)序列 [24, 65, 75]: 先把图像 token 化, 再按 GPT 式 [64] next-token prediction. 另有掩码预测一类 [7, 8], 借鉴 BERT 式 [19] 掩码, 预测被遮住的视觉片段以提高合成效率, 并已扩展到视频 [89]. 与此同时, 连续扩散模型在视觉生成上表现突出 [33, 67, 71], 从概率路径补足离散方法.

「离散视觉 token / 码本 ID」: VQ 一类编码器把图像块映射到有限码本里的编号, 生成就变成「按顺序预测这些编号」, 和语言模型预测词 ID 同构.

#### 2.2. Multimodal Understanding 多模态理解




多模态大语言模型(MLLM)同时吃文本与图像 [6, 80, 81]. 借助预训练 LLM, 一批 MLLM [1, 2, 12, 51, 55, 82, 95] 已能较强地处理多模态信息. 近期也有人给 MLLM 外挂预训练扩散模型来出图 [27, 29, 36, 75, 76]. 这属于「工具调用」: 扩散模型按 MLLM 给出的条件生成图像, MLLM 本身不会直接做视觉生成; 整系统的生成上限常被外挂扩散卡住, 甚至不如单独用同一扩散模型 [27, 75].

图 2｜Janus 架构. 与先前工作 [77, 85] 默认理解与生成共用同一视觉编码器不同, Janus 把理解编码与生成编码拆开.「Und. Encoder」「Gen. Encoder」分别是理解编码器, 生成编码器. 建议彩色查看.




无论自回归(AR)[77, 85] 还是扩散 [86, 94], 传统统一模型多半仍共用一套视觉表征. 例如 Chameleon [77] 用同一个 VQ Tokenizer 同时服务理解与生成; 编码器不得不在两类需求间折中, 效果容易次优. Janus 则显式拆开理解与生成的视觉表征, 承认不同任务可能需要不同信息层次.

### 3. Janus: A Simple, Unified and Flexible Multimodal Framework Janus: 简单, 统一, 灵活的多模态框架

#### 3.1. Architecture 架构







图 3｜Janus 采用三阶段训练. 图中火焰表示该模块更新参数, 雪花表示冻结.




对纯文本理解, 多模态理解, 视觉生成, 各自用独立编码把原始输入变成特征, 再交给统一的自回归 Transformer. 文本: 用 LLM 自带 tokenizer 变成离散 ID, 取对应嵌入. 多模态理解: 用 SigLIP [92] 抽高维语义特征, 把 2-D 网格展成 1-D, 再经**理解 adaptor**映射进 LLM 输入空间. 视觉生成: 用 [73] 的 VQ tokenizer 把图像变成离散 ID, 展成 1-D 后经**生成 adaptor**把各 ID 对应的码本嵌入映射进 LLM 输入空间. 各特征序列拼接成多模态序列送入 LLM. 纯文本与多模态理解用 LLM 自带预测头做文本预测; 视觉生成另用随机初始化的图像预测头. 整模型走自回归, 不需要特制注意力掩码.

Adaptor(适配器)这里就是两层 MLP: 把视觉侧特征维度对齐到 LLM 的词嵌入维度, 类似 LLaVA 里的 projector. 理解支路输出连续特征, 生成支路先离散成码本 ID 再取嵌入-- 两条路进 LLM 之前的「接口形状」不同, 所以各有一个 adaptor.

#### 3.2. Training Procedure 训练流程




Janus 训练分三阶段, 见图 3. 细节如下.




**阶段 I: 训练 adaptor 与图像头.** 目标是在嵌入空间里建立视觉与语言的概念连接, 让 LLM 能认图中实体, 并具备初步视觉生成能力. 此阶段冻结视觉编码器与 LLM, 只更新理解 adaptor, 生成 adaptor 与图像头.




**阶段 II: 统一预训练.** 用多模态语料做统一预训练, 同时学理解与生成. 解冻 LLM, 混用纯文本, 多模态理解, 视觉生成三类数据. 受 PixArt [9] 启发: 先在 ImageNet-1k 上做简单视觉生成, 摸清基本像素依赖; 再用通用文生图数据拉高开放域生成能力.




**阶段 III: 监督微调.** 用指令数据微调, 加强指令跟随与对话. 除生成编码器外全部参数可训. 损失只盯答案, 系统提示与用户提示做 mask. 不为单一任务单独微调, 而是混纯文本对话, 多模态理解与视觉生成数据, 保证两边都能用.

#### 3.3. Training Objective 训练目标




Janus 是自回归模型, 训练时直接用交叉熵:

$$
\mathcal {L} = - \sum_ {i = 1} \log P _ {\theta} (x _ {i} | x _ {<   i})\tag{1}
$$






$P(\cdot\mid\cdot)$ 是 Janus 参数 $\theta$ 建模的条件概率. 纯文本与多模态理解只在文本序列上算损失; 视觉生成只在图像序列上算损失. 为保持简单, 未给不同任务设不同损失权重.

#### 3.4. Inference 推理




推理仍是下一 token 预测. 纯文本与多模态理解按常规从预测分布依次采样. 图像生成使用 classifier-free guidance(CFG)<sup>2</sup>, 做法与 [8, 26, 73] 类似. 每个 token 的 logit 为 $l_g = l_u + s(l_c - l_u)$, 其中 $l_c$ 为条件 logit, $l_u$ 为无条件 logit, $s$ 为 CFG 尺度; 下文评测默认 $s=5$.




<small><span class=「docvortex-page-footnote」 data-block-type=「page_footnote」 style=「color: #6b7280」><sup>2</sup>训练时以 10% 概率把文生图数据里的文本条件换成 pad token, 从而学会无条件视觉生成. </span></small>

CFG 的直观含义: 同一位置既算「有提示」的分布, 也算「无提示」的分布, 再往「有提示相对无提示多出来的方向」推一把; $s$ 越大越贴提示, 但过大可能伤多样性或稳定性.

#### 3.5. Possible Extensions 可能的扩展




理解与生成分编码器的设计直白, 也好扩展.




**多模态理解.** (1) 理解支路可换更强视觉编码器(EVA-CLIP [74], InternViT [13] 等), 不必再担心它能不能兼做生成. (2) 高分辨率可用动态高分辨率技术 [50], 任意分辨率扩展且无需对 ViT 做位置嵌入插值; 也可用 pixel shuffle [12] 等压缩 token 省算力.




**视觉生成.** (1) 可换更细粒度编码器以保留更多细节, 如 MoVQGan [93]. (2) 可用专为视觉生成设计的损失, 如 diffusion loss [46]. (3) 可把 AR(因果注意力)与并行(双向注意力)结合, 减轻自回归累积误差 [79].




**更多模态.** 架构简单, 易接额外编码器: 3D 点云 [53], 触觉 [88], 脑电 [4] 等, 有望做成更强的多模态通才.

图 6(b) 展示与 LLM 的集成: 图像经 CNN 编码器, 向量量化, 语义解码器变成连续特征; LLM 处理这些特征并预测图像 ID; 最后像素解码器把离散 ID 还原成 RGB.

### 6.18. Janus-Pro 改变了哪些变量

Janus-Pro 保留双视觉路径和统一自回归接口，主要扩展数据、训练日程与模型规模。以下比较用于区分架构继承和训练配方变化。



来源: [Janus-Pro: Unified Multimodal Understanding and Generation with Data and Model Scaling](https://arxiv.org/abs/2501.17811) (arXiv: 2501.17811v1, 2025-01-29). 仓库: https://github.com/deepseek-ai/Janus

Janus-Pro 是 Janus 的升级版, 架构完全沿用: 理解走 SigLIP, 生成走 VQ tokenizer, 两条视觉通路接同一个自回归 Transformer. 改动在三处: 训练日程重排, 理解和生成数据都大幅扩充, 语言底座从 1.5B 扩到 7B. 结果是 7B 版 MMBench 79.2, GenEval 0.80, DPG-Bench 84.19, 后两项超过 DALL-E 3 和 SD3-Medium. 报告只有 13 页, 没有消融表, 三处改动各贡献多少只能从 1B 和 7B 两个版本, 以及它们和 Janus 的对比里推算. 下面把训练日程, 数据, 模型配置和评测放在一起读, 看这些分数分别能归到哪一步.

### 1. 从 Janus 到 Janus-Pro

#### 1.1. Janus 留下的问题

Janus 在 1.3B 规模上证明了解耦视觉编码可行, 但生成端有两个明显的弱点. 一是短提示下生成质量差, 二是文生图不稳定, 同一个提示多次生成, 质量波动大. 报告把原因归到两处: 训练数据量有限, 模型容量偏小. 从 Janus 的配置看还有第三个原因, 这篇报告自己也点出来了: 阶段 II 里生成部分 66.67% 的步数花在 ImageNet 的类别名条件生成上, 真正的开放域文生图只占三分之一.

Janus 用类别名当提示, 本意是借鉴 PixArt, 先让模型学会像素之间的依赖, 再学复杂场景. 但类别名是一两个词的短提示, 和真实用户写的长描述差别很大; 在 LLM 已解冻的阶段 II 里花 120K 步学这个, 报告的评价是「次优, 而且计算效率很低」. Janus-Pro 的日程改动就是冲着这一点去的.

架构本身报告只用一段话复述(源文 §2.1), 细节要回 Janus 原文. 理解通路: SigLIP-Large 把 384×384 的图按 16×16 切 patch, 得到 24×24 = 576 个高维语义特征, 从二维网格展平成一维序列, 再经理解 adaptor 映射到 LLM 的输入空间. 生成通路: VQ tokenizer 把图编码成 576 个离散 ID, 每个 ID 查码本取出嵌入, 经生成 adaptor 映射进去. LLM 自带的文本预测头只管文字, 另加一个随机初始化的图像头, 在 16,384 个码字上做 next-token prediction. 两条通路在输入端分开, 在 Transformer 里共享全部参数, 到输出端再分开; 所谓「解耦」只发生在两头, 中间的语言模型始终是同一个 decoder-only 网络.

报告没有复述的是推理设置. Janus 原文生成时用 **classifier-free guidance**: 训练时以 10% 的概率把文本条件换成 pad token, 让模型学会无条件生成; 推理时每个 token 的 logit 取 $l_g=l_u+s(l_c-l_u)$, $l_c$ 带文本条件, $l_u$ 是 pad 条件下的无条件 logit, 默认 $s=5$. $s=1$ 时就是普通的条件采样; $s=5$ 把「文本让哪些码字变得更可能」这部分差值放大 5 倍, softmax 之后的采样分布正比于 $p_c^{\,s}/p_u^{\,s-1}$, 那些无论什么提示都常见的码字被压低. Janus-Pro 对 guidance 系数, 采样温度, 每条提示生成几张都没有写, 这些数字只能推测沿用了 Janus 的设置. 这会影响第 2.2 节的读法: GenEval 和 DPG-Bench 对 guidance 强度相当敏感, 系数调高, 物体更「听话」, 画面也更容易过饱和, 表里各家模型用的是什么采样设置无从得知.

#### 1.2. 训练日程: 把 ImageNet 挪到冻结阶段

第一处改动是延长阶段 I. 阶段 I 只训两个 adaptor 和图像头, LLM 冻结. Janus 在这一阶段训 10K 步, 比例(理解 : 纯文本 : 生成)1 : 0 : 1; Janus-Pro 训 20K 步, 比例改成 1 : 0 : 3, warmup 从 300 步增到 600 步. 按每条序列一个样本粗算, 生成样本从约 1.28M 增到约 3.84M, ImageNet 相当于过了三遍多. 报告的发现是: **即使 LLM 参数完全冻结, 只靠 adaptor 和图像头, 模型也能学会像素依赖**, 按类别名生成像样的图. 这说明 ImageNet 那一段不需要动 LLM, 放在冻结阶段做更便宜.

冻结阶段能学会像素依赖, 说明的问题比报告写的更多. 阶段 I 里可训练的只有两个两层 MLP adaptor 和图像头. 图像头是从隐宽到 16,384 个码字的线性层, 1B 版约 33.5M 参数, 7B 版约 67M(按隐宽乘码本大小估算); 加上 adaptor, 可训练参数只占全模型的几个百分点. 也就是说, 一个只见过文字的 LLM, 冻住全部权重, 只在输入和输出两端各接一层薄薄的映射, 就能把「下一个图像块该是什么」建模到能画出像样的类别图. 语言预训练学到的序列建模能力在相当程度上与模态无关, 真正需要解冻 LLM 去学的, 可能是长描述和图像内容之间的细粒度对应. 阶段 I 的学习率调度也从 Janus 的 cosine 改成了恒定, 三个阶段全部恒定学习率, 这让「延长阶段 I」变成简单地多跑步数, 不必重设衰减终点.

第二处改动是阶段 II 去掉 ImageNet, 直接用正常的文生图数据, 让模型从一开始就学按稠密描述生成. 阶段 II 计划 360K 步, 实际在 270K 步提前停止, 学习率 1e-4 恒定, batch 512, 比例仍是 2 : 3 : 5. 生成部分约 270K×512×0.5, 约 69M 条样本, 全部是开放域文生图; Janus 的开放域部分只有 60K 步, 约 15M 条. 开放域文生图的训练量因此多了约 4.5 倍. 为什么在 270K 步停止, 报告只说用了早停, 没有给判据和损失曲线.

第三处改动在阶段 III. 比例从 Janus 的 7 : 3 : 10 改成 5 : 1 : 4, 生成占比从 50% 降到 40%, 纯文本从 15% 降到 10%, 理解从 35% 升到 50%. 报告的说法是: 略微降低生成数据比例后, 生成能力保持住了, 理解能力提高了. 超参也变了: 学习率从 2e-5 升到 4e-5, batch 从 256 降到 128, weight decay 从 0.1 改成 0, 1B 训 80K 步, 7B 训 40K 步. 1B 的阶段 III 约 10.2M 条样本, 7B 约 5.1M, Janus 约 6.1M. 7B 的微调步数只有 1B 的一半, 报告没有解释, 可能是大模型收敛更快, 也可能是算力限制.

阶段 III 的超参组合值得多看一眼. 学习率翻倍, batch 减半, 按每个样本摊到的更新幅度算, 相当于放大了约 4 倍(按 AdamW 下学习率与 batch 的常见比例关系粗看). Janus 在阶段 III 用 weight decay 0.1, Janus-Pro 三个阶段全部为 0. 阶段 III 还沿用 Janus 的做法, 在阶段 II 的基础上解冻 SigLIP 理解编码器, VQ 编码器始终冻结. 理解数据占比从 35% 升到 50%, 意味着解冻后的 SigLIP 拿到的梯度比 Janus 多; 1B 版阶段 III 的理解样本约 5.1M, Janus 约 2.2M, 多了一倍多. 理解分数的提升有一部分可能来自这里, 但报告没有把 SigLIP 冻结与否单独拆开.

还有一处实现细节决定了「比例」的含义: 报告写明每个训练步内按比例混合所有数据类型, 并用 sequence packing 把多条短样本拼进 4096 长的序列(源文 §3.1). 所以 2 : 3 : 5 是每一步 batch 内部的构成, 不是按阶段轮换任务; 理解, 纯文本, 生成三种损失在同一次反向传播里一起更新共享的 Transformer. 这也让上面「每条序列一个样本」的估算只是下限. 一条生成样本大约是几十个文本 token 加 576 个图像 token, 一条描述类理解样本也是 576 个图像特征加一段文字, 一条 4096 长的序列理论上能装进 5 到 6 条. 本节所有样本量估算都应理解为下限, 实际样本数可能再乘几倍, 但 Janus 与 Janus-Pro 之间的相对倍数不受影响, 因为两者用的是同一套打包方式.

#### 1.3. 数据: 理解加 9000 万条, 生成加 7200 万条合成图

理解数据参考 DeepSeek-VL2 扩充. 阶段 II 加了约 **9000 万**条样本, 包括 YFCC 这类图像描述数据, 以及表格, 图表, 文档理解数据(如 Docmatix). 阶段 III 加了 DeepSeek-VL2 的表情包理解, 中文对话和改善对话体验的数据. 文档和图表数据主要提升读图中文字和结构的能力, 但 384 的分辨率限制了能读多小的字, 报告在局限里专门提到 OCR 受分辨率影响. Figure 4 的定性例子里有中文地标识别(西湖三潭印月)和黑板读字, 对应的正是这两类新增数据.

把数据量和步数放在一起算, 会发现阶段 II 其实看不完新数据. 阶段 II 理解占 20%, 270K 步乘 512 再乘 0.2, 约 27.6M 条序列; 新增的理解样本就有约 9000 万条, 还不算 Janus 原有的数据. 按每条序列一个样本, 新增理解数据只过了约三成; 算上 sequence packing, 实际样本数可能是这个数的几倍, 大致在一遍上下. 生成那边, 合成 7200 万条加真实数据按 1 : 1 约 7200 万条, 池子约 **1.44 亿**条, 阶段 II 生成部分约 69M 条序列, 同样按一条算只过了约一半. 这说明 Janus-Pro 的阶段 II 处在数据充足, 算力受限的区间, 270K 步早停并不是因为数据用完了. 多数样本只见一两遍, 这种设置下数据质量比重复次数更要紧, 这也和报告强调合成数据「质量高, 收敛快」的叙述一致.

预处理上理解和生成用了两套不同的规则(源文 §3.1). 理解数据按长边缩到 384, 短边用 RGB(127, 127, 127) 的灰色补齐成正方形, 保住整张图的内容, 文档和图表的边角文字不会被裁掉. 生成数据按短边缩到 384, 长边直接裁掉多余部分, 目标图因此永远是铺满画面的正方形, 模型不会学到在图上画灰边. 两种做法各有代价: 理解端把一部分 token 花在灰色填充上, 细长图表的有效分辨率进一步降低; 生成端裁掉了宽幅图的两侧, 模型对全景构图可能见得少.

生成数据的改动更关键. 报告认为 Janus 用的真实图文数据质量不高, 噪声大, 是文生图不稳定, 美感差的主要原因. Janus-Pro 在阶段 II 加了约 **7200 万**条合成美学数据, 让真实数据和合成数据的比例达到 1 : 1. 合成数据的提示词来自公开数据集, 参考文献 [43] 是 Hugging Face 上的 Midjourney 提示词数据集. 报告说用合成数据训练收敛更快, 生成的图更稳定, 美感明显更好.

这段描述留下了一个关键空白: **合成图是用哪个模型生成的, 报告没有说**. 提示词来自 Midjourney 用户, 图像大概率来自某个现有的文生图模型. 如果是这样, Janus-Pro 的生成能力有相当一部分是从那个模型蒸馏来的: 合成图的构图, 光影和美学风格, 连同它在「按提示摆放物体」上的能力, 都会被学进来. 这不影响 Janus-Pro 作为开源模型的价值, 但会影响对「统一自回归架构能做到什么」的判断, GenEval 和 DPG-Bench 上的领先不能全部归功于架构. 另外, 合成数据的提示词分布和评测提示词的重合程度, 报告也没有检查. 知识蒸馏的一般讨论见 [知识蒸馏](../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.3-知识蒸馏/6.3.3-知识蒸馏.md).

#### 1.4. 模型规模和训练算力

两个版本的语言底座都是 DeepSeek-LLM, 词表 100K, 上下文 4096. 1B 版隐宽 2048, 16 头, 24 层; 7B 版隐宽 4096, 32 头, 30 层. 视觉部分两者相同: SigLIP-Large-Patch16-384, 码本 16,384, 下采样 16 倍的 VQ tokenizer, 两层 MLP 的 adaptor. 命名上有一处不一致: 模型叫 Janus-Pro-1B, 表里写的是 1.5B 的 LLM, 而 Janus 论文把同一个底座写成 1.3B. 按词表 100K, 隐宽 2048 算, 输入词嵌入约 0.2B, 1.3B 和 1.5B 的差距大致就是算不算词嵌入.

训练在 A100 40GB 集群上完成: 1.5B 用 16 个节点跑约 9 天, 7B 用 32 个节点跑约 14 天, 每节点 8 卡. 折算约 2.8 万和 8.6 万 GPU 小时; Janus 是 16 个节点 7 天, 约 2.2 万 GPU 小时. 1B 的算力只比 Janus 多约三成, 但阶段 II 的开放域生成训练量多了数倍, 这是因为去掉了 ImageNet, 同样的步数用在了更有价值的数据上. 报告还说更大的 LLM 在理解和生成两边的损失都收敛得更快, 但没有给出曲线. 用配置反推一下两个版本的计算量. 按每层约 12d² 个参数粗算, 1B 版非嵌入参数约 1.21B, 7B 版约 6.04B, 相差约 5 倍. 两个版本阶段 I 和阶段 II 的步数相同, 只有阶段 III 不同, 按 batch 乘步数, 1B 共约 1.54 亿条序列, 7B 约 1.49 亿条. 于是 7B 的训练计算量约是 1B 的 4.8 倍, GPU 小时却只多约 3.1 倍. 差出来的部分只能由硬件利用率解释: 按 6 乘参数量乘 token 数, 序列全部打满 4096 计算, 1B 的算力利用率上限约 15%, 7B 约 23%(实际打包率低于满额, 真实利用率更低). 小模型在 A100 上矩阵太窄, 吃不满算力, 这是常见现象; 另外 SigLIP 前向和 VQ 编码的开销与语言底座大小无关, 在小模型上占比更高.

这组估算也说明, 「更大的 LLM 损失收敛更快」这句话要按步数理解. 同样的步数下, 7B 每一步花的算力约是 1B 的 5 倍, 按算力对齐比较, 大模型是否仍然更划算, 报告没有给出数据. Scaling 的一般规律见 [Scaling Law](../../../llm-guide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).

### 2. 理解与生成为何要解耦视觉编码

#### 2.1. 两个任务需要的视觉信息粒度不同

图像理解把图片压成一组供语言模型读取的语义特征. 对「图里是什么」「物体之间有什么关系」这类问题, 编码器应对光照、纹理微扰和局部像素噪声保持一定不变性. 两张像素略有差异的猫图, 理解特征仍应靠近. SigLIP 通过大规模图文对比目标学习这种语义组织, 每个 patch 输出连续向量, 向量的方向与距离承载概念和上下文信息.

图像生成的编码目标不同. decoder 要从 latent 重建颜色、纹理、轮廓和局部位置, 过强语义不变性会把重建所需细节丢掉. VQ tokenizer 把局部图像映射到离散码字, 再由像素 decoder 复原. 两块都属于「猫」的 patch 可能因毛色与边缘方向落入不同码字, 因为生成端必须知道画面具体长什么样. 用同一个 token 同时追求语义不变与像素可逆, 两个目标会在有限码本和有限网络容量上竞争.

设理解编码器为 $f_u$, 生成 tokenizer 为 $f_g$, 输入图像为 $I$. Janus-Pro 得到两种表示:

$$
U=f_u(I)\in\mathbb{R}^{N_u\times d_u},
\qquad
Z=f_g(I)\in\{1,\ldots,K}^{N_g}.
$$

$U$ 是连续特征, 供问题回答和描述; $Z$ 是离散 ID, 供自回归预测和图像重建. 两者都在 $384\times384$ 输入上形成 576 个位置, 数量相同不代表含义相同. $U_i$ 是有上下文的语义向量, $Z_i$ 是码本索引, 其距离没有自然的连续语义.

解耦的收益来自允许两条通路分别选择训练目标和预训练来源. SigLIP 已经在图文对齐上学习, VQ tokenizer 已经在重建上学习. Janus-Pro 不要求一个新视觉前端从零同时满足两种需求, 只让 adaptor 把它们映射进共享 Transformer. 代价是参数、显存和接口更多, 同一张图在理解与生成任务中经过不同前端, 两种表示不会自动对齐到同一视觉坐标系.

#### 2.2. 连续理解特征怎样进入语言模型

SigLIP-Large-Patch16-384 把边长 384 的图像分为 $24\times24$ 个 patch. 经过视觉 Transformer 后得到 576 个连续向量. 理解 adaptor 是两层 MLP, 将每个向量从视觉维度投影到语言模型隐宽 $d$. 记 adaptor 为 $A_u$, 送入语言模型的视觉嵌入是:

$$
X_u=A_u(U)\in\mathbb{R}^{576\times d}.
$$

这些向量直接占据 decoder-only Transformer 的输入位置, 与文本 token embedding 拼成一条序列. 它们不需要先变成词表 ID, 也不经过文本 embedding 查表. Transformer 只接收 $d$ 维向量, 因而可以在同一注意力层里让问题 token 读取视觉 token.

连续特征保留了码本之外的细微语义差异. 若两个 patch 都被 VQ 分到同一码字, 生成表示完全相同; SigLIP 向量仍可能在连续空间中区分对象、背景和上下文. 这有利于分类与关系判断. 但连续表示没有可直接解码成像素的有限词表, 语言模型也无法通过预测一个 SigLIP 向量 ID 来逐步生成图片.

理解序列的因果注意力还需要明确方向. 图像特征通常先放在问题文本之前, 后续文本 token 可以关注全部视觉位置. 视觉 token 自身经过语言模型时也会相互作用, 但最终监督来自答案文本的 next-token loss. 如果只在答案位置计算损失, 图像特征通过注意力影响答案, 梯度再回到 adaptor, 解冻阶段还会回到 SigLIP. Janus-Pro 阶段 I、II 冻结 SigLIP, 阶段 III 才让理解编码器随任务调整.

384 分辨率和 576 个 patch 是明确瓶颈. 一个 patch 覆盖 $16\times16$ 像素, 细小文字可能跨 patch 且在缩放时已经模糊. 灰色 padding 保留完整画面, 对细长文档却会让有效内容缩得更小. 增加 OCR 数据能教模型利用现有信号, 无法恢复预处理已经抹掉的笔画.

#### 2.3. 离散图像 token 为什么适合生成

VQ tokenizer 先用 encoder 将图像压成空间 latent, 再把每个 latent 向量替换为最近码字. 设码本为 $E=\{e_1,\ldots,e_K\}$, 连续 latent 为 $v_i$, 量化 ID 是:

$$
z_i=\arg\min_{k\in\{1,\ldots,K\}}\|v_i-e_k\|_2^2.
$$

Janus-Pro 的 $K=16384$, 一张图对应 576 个 ID. 这些 ID 像文字 token 一样形成有限分类问题. 生成 adaptor $A_g$ 将码字 embedding 投影到语言模型隐宽, 图像输出头再把隐藏状态映射回 $K$ 个 logits. 训练目标可以直接使用交叉熵.

离散化使图像和文本共享同一种自回归接口: 给定前缀预测下一个类别. 文本头在约 10 万词表上分类, 图像头在 16384 码字上分类. 两个头分开避免图像 ID 与文字 ID 占用同一词表含义, 共享 Transformer 则让提示文本影响图像位置的隐藏状态. 统一发生在序列建模层, 没有要求底层表示类型相同.

量化一定会丢信息. 码本越小、空间下采样越强, 重建越模糊; 码本越大, 分类更难且输出头更大. 16 倍下采样把 $384\times384$ 压成 $24\times24$, 每个 token 最终负责约 $16\times16$ 像素区域. decoder 能借相邻 token 补细节, 无法恢复量化时彻底丢失的高频信息. 小脸、文字和细线最容易受损.

离散 token 还带来暴露偏差. 训练时第 $i$ 个位置看到真实前缀 $z_{<i}$, 推理时看到自己采样的 $\hat z_{<i}$. 早期错误会改变后续条件, 可能扩散成结构畸变. 扩散模型在连续噪声去除中逐步修正整幅图, 自回归光栅生成则更依赖前缀. CFG、数据质量和大模型容量可以降低错误率, 没有消除这种生成方式的路径依赖.

#### 2.4. 解耦到哪里为止

两条视觉编码通路在输入端分开, 进入 adaptor 后都变成 $d$ 维向量, 共享语言 Transformer 的每一层. 理解任务更新共享参数时, 会改变生成 token 的条件建模; 生成任务同样会改变理解答案. 所以 Janus 所说的 decoupling 是视觉表征职责解耦, 共享主干仍存在多任务干扰.

输出端也分开. 文本答案使用语言模型原有词表头, 图像生成使用独立 image head. 若把两个输出空间合并, 文本与图像类别会在一个超大 softmax 中竞争, 还要设计特殊 ID 区间. 分头后, 模态控制决定当前用哪个 head, 分类规模更小. 代价是同一隐藏状态不能在一个位置自由输出文字或图像 token, 序列格式必须先决定区段模态.

共享 Transformer 带来的正迁移是文本知识能直接条件化图像生成, 视觉理解训练也可能改善对象与关系表示. 负迁移则来自梯度竞争和容量分配. Janus-Pro 阶段 III 把理解比例提高到 50%、生成降到 40%, 生成分数仍保持, 说明在该训练点附近共享主干还有余量. 没有更细比例消融, 不能推出任意降低生成数据都不会伤害生成.

真正完全解耦的方案会为理解与生成各用一套 Transformer, 再在高层交换信息. 这种方案减少梯度冲突, 参数与推理成本翻倍, 文本知识共享也变弱. Janus-Pro 选择的是中间点: 专用视觉前端解决表示粒度冲突, 共享强语言主干承担跨模态序列规律.

#### 2.5. 一个小图例看两种表示的差别

设图像只有 $2\times2$ 个区域: 左上是红球, 右上是蓝盒, 下方是桌面. 理解任务问「球在盒子哪边」, SigLIP 特征需要让语言模型读出对象类别、颜色和相对位置. 红球表面的一点反光不应改变答案, 因而编码器可以忽略部分像素差异. 四个连续向量经过 adaptor 后, 注意力把「球」对应问题 token 与左上区域关联, 输出「左边」.

生成任务的提示是「红球在蓝盒左边」. 图像 tokenizer 要为四块选择能让 decoder 重建红色圆形边缘、蓝色直角和桌面纹理的码字. 若把所有红球区域都压成同一个语义 token, decoder 不知道球的大小、阴影和边缘落在哪. 离散 ID 必须保留更多局部外观, 自回归主干还要确保左侧先出现与红球相容的 token, 右侧再出现蓝盒 token.

两种表示可以共享「红球—蓝盒—左边」这层关系, 没必要共享底层编码. 共享 Transformer 从文本和视觉任务中学习关系模式, adaptor 负责把连续语义向量或离散码字 embedding 放到可用隐藏空间. 这就是 Janus 的双面含义: 输入视觉表示不同, 中央序列模型相同.

这个例子也揭示了解耦的边界. 如果生成训练只强调像素重建而缺少文本绑定, VQ token 很精细仍会画错关系; 如果理解 encoder 很强而共享主干容量不足, 答案仍可能错. 解耦消除一处表示冲突, 没有自动解决跨模态对齐、组合推理和图像规划.

#### 2.6. 连续特征与离散 token 的信息瓶颈

连续表示的瓶颈来自维度、patch 数和预训练目标. 576 个向量每个有许多浮点分量, 名义容量很大, 但 SigLIP 训练鼓励保留有助于图文对齐的信息. 纹理噪声、精确像素和局部排列可能被压缩. 这种有选择的遗忘有利于语义理解, 对逐像素重建不够.

离散表示的瓶颈更容易量化. 每个 token 最多承载 $\log_2 16384=14$ bit 的码字身份, 576 个位置的离散索引上界约 8064 bit, 还要依赖 decoder 与码本共享的先验来还原图像. 这不是实际压缩率的完整计算, 因为码本、decoder 参数和 token 相关性也携带信息, 但它说明单图索引是强压缩表示.

码本使用不均会进一步降低有效容量. 若训练只频繁使用一小部分码字, 名义 16384 类没有全部贡献. 自回归模型也更容易预测高频码字, 罕见纹理与小对象可能被常见模式替代. 论文引用 tokenizer 的重建能力, 没有报告 Janus-Pro 训练图上的码本利用率、perplexity 或按对象尺度的重建误差.

理解与生成用 576 个位置还会造成表面错觉: 读者可能以为两套 token 可以逐位置对齐. SigLIP 每个输出已经混合全局上下文, VQ 码字更接近局部 latent; 同一索引的感受野与语义并不相同. Janus-Pro 没有显式约束 $U_i$ 和 $Z_i$ 对齐, 它们只在共享主干的任务梯度中间接关联.

### 3. 统一自回归建模

#### 3.1. 三种序列共用一个因果目标

纯文本、图文理解与文生图都可以写成条件序列概率. 纯文本预测 $y$:

$$
p(y)=\prod_t p(y_t\mid y_{<t}).
$$

理解任务把视觉连续嵌入 $X_u$ 与问题 $q$ 放在前缀, 只对答案 $a$ 计算文本损失:

$$
p(a\mid I,q)=\prod_t p(a_t\mid X_u,q,a_{<t}).
$$

生成任务把提示 $c$ 放在前缀, 预测离散图像序列 $z$:

$$
p(z\mid c)=\prod_{i=1}^{576}p(z_i\mid c,z_{<i}).
$$

三个式子共享「前缀条件下预测下一位置」这一计算骨架. 差别在输入 embedding 来源、监督位置和输出 head. 统一自回归因此是训练接口与 Transformer 主干统一, 并不表示所有模态都经过相同 tokenizer.

这种统一让预训练语言模型的序列能力得到复用. 注意力已经学会从长前缀选择相关信息, 残差网络已经学会逐步变换上下文. adaptor 只要把视觉表示投到主干可利用的区域, 图像任务就能借用这些能力. 阶段 I 冻结 LLM 仍能学会类别条件生成, 正是这种可迁移性的实验证据.

统一目标也简化混合训练. 一个 batch 中可以放三种序列, 分别构造 loss mask 和 head, 汇总损失后对共享参数反向传播. 无需在扩散噪声损失、对比损失和语言损失之间切换完全不同的训练循环. 简洁不等于不存在权重问题: 不同序列长度、token 数和损失尺度会改变每类任务的有效梯度.

#### 3.2. 图像光栅顺序带来了什么归纳偏置

$24\times24$ 图像 token 要展平成一维. 常见做法按行从左到右、从上到下排列. 第 $i$ 个 token 只能看见光栅前缀, 左侧和上方信息更早可用, 右侧和下方要在之后生成. 这种方向性与二维图像没有天然对称, 但让标准 causal mask 可以直接使用.

光栅顺序有利于局部连续性. 相邻水平 token 在序列中相邻, 换行处的上下文也能通过注意力访问. 垂直相邻 token 的序列距离为 24, 对 4096 上下文的 Transformer 并不长. 全局构图则要求早期 token 根据文本提前规划尚未出现的区域, 因为后面不能返回修改前缀.

GenEval 位置分数可能受顺序偏置影响. 「A 在 B 左边」的文本先提 A, 光栅生成也先覆盖左侧, 两种顺序有机会对齐; 反向关系是否同样好, 需要按关系方向拆分. 官方只给 position 总分, 没有足够证据确认优势来自空间推理、训练分布还是生成顺序.

其他序列化方式可以改变偏置, 例如列优先、蛇形、Hilbert 曲线或多尺度 token. 改顺序需要重新训练位置规律, 还可能影响局部邻接. Janus-Pro 延续 Janus 架构, 没有比较这些选择. 它证明光栅顺序在当前数据与规模下可行, 没有证明这是二维生成的最优顺序.

#### 3.3. 两个输出头如何共享隐藏状态

设 Transformer 输出隐藏状态 $h_t\in\mathbb{R}^d$. 文本 logits 与图像 logits 分别是:

$$
\ell_t^{\text{text}}=W_{\text{text}}h_t,
\qquad
\ell_t^{\text{image}}=W_{\text{image}}h_t.
$$

$W_{\text{text}}$ 继承语言模型词表头, $W_{\text{image}}$ 随机初始化. 模态区段决定采用哪个矩阵. 阶段 I 冻结 LLM 时, $W_{\text{image}}$ 与生成 adaptor 要学习如何把固定隐藏空间变成码字分类器; 阶段 II 解冻主干后, 隐藏表示可以进一步适应视觉生成.

共享 $h_t$ 使文本属性、对象和关系能进入图像预测. 对提示「红色汽车在蓝色房子左边」, 文本 token 先形成条件表示, 每个图像位置再根据这个条件选择码字. 模型没有显式场景图, 属性绑定和位置关系都隐含在注意力与隐藏状态里. DPG-Bench 和 GenEval 测到的是这种隐式绑定最终是否落到像素.

理解方向相反. 连续视觉 token 进入主干后, 文本头把隐藏状态解码成答案. 图像 head 在理解任务中不参与监督. 两个任务的输入和输出方向不同, 共享参数通过批次交替接收梯度. 如果生成梯度让主干更关注局部纹理, 理解可能受益也可能被干扰; 解耦 encoder 只能减少输入表示冲突.

#### 3.4. CFG 在离散自回归里怎样工作

训练时以一定概率丢弃文本条件, 模型同时学习 $p(z\mid c)$ 与 $p(z)$。推理时对条件 logits $\ell_c$ 和无条件 logits $\ell_u$ 做线性外推:

$$
\ell_{\text{cfg}}=\ell_u+s(\ell_c-\ell_u).
$$

$s>1$ 放大提示带来的方向. 对 softmax 概率忽略归一化常数后, 有 $p_{\text{cfg}}(z)\propto p(z\mid c)^s/p(z)^{s-1}$. 常见而与提示无关的图像模式被压低, 更能区分提示的码字被提升.

CFG 并非免费. $s$ 太低时图像自然但可能漏属性, 太高时提示跟随增强, 多样性下降, 颜色和边缘可能过强. 每个图像 token 都要分别做条件与无条件前向, 生成计算近似翻倍, KV cache 也要维护两条条件. Janus 官方 demo 暴露默认 CFG 权重 5, Janus-Pro 论文没有报告评测逐项采用的采样参数.

生成 benchmark 对 $s$ 很敏感. GenEval 奖励物体、颜色、数量和位置符合提示, 较强 guidance 往往有利; 人类审美与真实感未必随之单调上升. 没有统一采样协议时, 跨模型比较混入 CFG、温度、top-$p$ 和每提示候选数差异. Janus-Pro 的高分是真实系统结果, 不能全部归到训练 checkpoint.

#### 3.5. 自回归图像生成的计算边界

576 个图像 token 逐步解码, 每一步都要经过语言主干. 有 KV cache 时, 第 $i$ 步只计算新 token 的 query 与全部前缀 key/value, 总注意力代价仍随序列长度近似二次增长, 主干 MLP 则按 token 数线性增长. 7B 比 1B 生成每张图明显更贵, 论文只报告训练资源, 没有生成延迟与吞吐.

提高分辨率到 768 会让每边 token 数从 24 增至 48, 总 token 从 576 增至 2304. 生成步数变四倍, 注意力交互的上界约增十六倍, KV cache 四倍. 这使论文提出的「提高分辨率」不只是改预处理, 还要求更高效 tokenizer、分层生成或更强推理优化.

扩散模型可并行处理整张 latent, 每个去噪步更新所有位置; 自回归模型每步只确定一个位置, 但能直接使用成熟 LLM 与离散交叉熵. 两者的步数不能简单比较: 扩散一次前向覆盖全图, 自回归 576 次前向可借 KV cache. Janus-Pro 没有报告等硬件延迟, GenEval 高分不代表推理效率优于扩散模型.

#### 3.6. 训练时 teacher forcing 与推理时采样

生成训练使用真实前缀, 损失为 576 个位置交叉熵之和或平均:

$$
\mathcal{L}_{\text{img}}=-\sum_{i=1}^{576}\log p_\theta(z_i\mid c,z_{<i}).
$$

每个位置都在正确历史上学习, 梯度稳定且可以并行计算全部位置 logits. 推理时必须顺序采样, 若第 50 个 token 错了, 第 51 个以后看到错误前缀. 训练目标优化局部 next-token likelihood, 最终图像评分关注对象、关系与美感, 两者并不完全一致.

温度控制采样分布尖锐度, top-$p$ 截断尾部. 贪心解码稳定但容易重复高频视觉模式, 高温增加多样性也增加结构错误. 每个提示生成多张再挑最好的一张, 能显著提高 benchmark 命中率, 代价是成倍计算. GenEval 的评测协议通常每提示生成四张用于统计, 模型侧是否还做内部候选筛选必须由具体实现说明.

CFG 与温度相互作用. $s$ 放大条件 logit 差, 低温再把分布变尖, 两者同时很强会使输出收缩到少量码字路径. 这可能提高短模板的属性命中, 也可能损失构图多样性. 论文没有采样消融, 所以生成表反映的是某个完整推理配方, 不能视为 checkpoint 的唯一固有分数.

#### 3.7. 理解和生成能否在一轮对话中交替

架构具备文本 head 与图像 head, 但开放仓库示例把理解和生成作为两条入口. 一轮中先看图、回答文字, 再根据回答生成新图, 需要定义序列中的模态切换 token、保留哪些视觉表示以及如何把生成图片重新编码. 论文评测没有测试任意交错输出.

统一主干给交替任务提供潜力: 理解得到的语义状态与生成使用同一 Transformer 参数, 文本中间表示可以条件化 image head. 但输入端的两套 encoder 和输出端的两套 head 仍需外部控制. 「统一多模态」在 Janus-Pro 中主要表示一个模型支持理解与生成两类任务, 不等于像普通词表一样在任意位置自由混排所有模态.

这一区分对能力宣传很重要. 文生图分数与 VQA 分数同时很高, 说明两个接口各自有效; 它们没有直接测「看图后局部编辑」「生成后自我检查」或多图连续创作. 后续若要实现闭环视觉推理, 还需要任务数据和推理协议, 不能只依靠共享参数自动涌现.

#### 3.8. 为什么理解端不把连续特征当输出目标

连续视觉向量没有天然唯一答案. 同一语义可以经过旋转、缩放或不同 adaptor 映射到等价隐藏空间, 直接用均方误差预测 SigLIP 向量会把模型绑在某个表示坐标系. 文本答案和离散码字都有明确分类目标, 更适合自回归交叉熵. Janus-Pro 让连续特征只作条件, 避免定义连续视觉输出分布.

如果要让模型生成连续 latent, 通常需要回归、混合密度、扩散或 flow 目标. JanusFlow 正是把生成端改为连续流匹配, 它与语言交叉熵在损失和采样过程中不再完全同构. Janus-Pro 选择 VQ token, 换取统一 next-token 训练和复用 LLM head 范式, 接受量化损失与逐 token 解码.

理解 adaptor 的目标也不是重建 SigLIP 输入. 它只需让答案 loss 能从语言模型反传, 找到对问答有用的投影. 因此 adaptor 可能丢掉暂时未被理解数据监督的信息. 阶段 III 解冻 SigLIP 后, 整条理解通路更会向现有问答分布适应. 这能提高 benchmark, 也可能降低未覆盖视觉任务的通用性, 论文没有冻结对照.

两种通路若要加强对齐, 可以加入同图表示一致、互预测或共享语义 code 等辅助目标. 这样可能改善生成后理解与视觉规划, 也会重新引入解耦试图避免的约束. Janus-Pro 保持简单: 只在共享 Transformer 参数处间接交流, 实验结果证明这条基线已经很强.

### 4. 训练目标、数据配比与缩放归因

#### 4.1. 数据比例要按 token 和梯度读取

论文给出的 2:3:5 或 5:1:4 是样本类别比例, 每类样本的有效监督 token 不同. 文生图样本固定有 576 个图像目标, 纯文本样本可能含数百到数千文字 token, 理解样本通常只在答案文字上计算 loss. 若每类 loss 对 token 求平均后再汇总, 样本比例与梯度贡献仍受序列长度和实现 reduction 影响.

设一批中三类有效监督 token 数为 $n_u,n_t,n_g$, 对应平均 token loss 为 $L_u,L_t,L_g$, 最简单总损失为:

$$
L=\frac{n_uL_u+n_tL_t+n_gL_g}{n_u+n_t+n_g}.
$$
