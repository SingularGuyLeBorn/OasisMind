# DeepSeek-R1: 用规则奖励的 RL 训出长推理

来源: [DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning](https://arxiv.org/abs/2501.12948). 本库采用带补充材料的 86 页 v1 (2025-01-22); 2026-01-04 发布的 v2 不在本页材料范围内. 权重: https://huggingface.co/deepseek-ai

关键实验数字、公式和图表来自[原技术报告](https://arxiv.org/abs/2501.12948), 同目录 bi 稿提供逐段对照译文.

这篇报告有两个模型. DeepSeek-R1-Zero 直接在 DeepSeek-V3-Base 上做 RL, 不经过 SFT, 奖励只看最终答案对不对和格式对不对; 训练中模型的回答越来越长, 自己学会了反思和验证, AIME 2024 的 pass@1 从 15.6% 升到 77.9%. DeepSeek-R1 在此基础上加了冷启动数据, 两轮 SFT 和两轮 RL, 解决 R1-Zero 可读性差, 中英混杂, 只会做题的问题, 最终 AIME 2024 79.8%, 与 OpenAI o1-1217 相当. 报告还把 R1 生成的 80 万条数据蒸馏进 Qwen 和 Llama 的小模型. 模型架构完全沿用 V3; 差异集中在奖励设计、训练日程、数据流转和推理能力的评测结果上.

## 1. 起点与算法

### 1.1. 起点: V3-Base 和「不做 SFT」的假设

R1 的底座是 DeepSeek-V3-Base, 671B 总参, 37B 激活, 经过 14.8T token 预训练. 补充材料 A.1 说明, 预训练数据来自普通网页和电子书, 没有主动加入合成数据; 不过部分网页含有 OpenAI 模型生成的回答, 底座仍可能间接接触这类内容. 预训练末段同样没有刻意加入 OpenAI 生成的数据. 数学和代码内容在语料中占有相当比例, 底座已经见过大量推理过程. 因而 RL 更像是在底座能够生成的候选解中强化有效路径, 而非从零建立推理能力.

报告的出发点是一个假设: 人写的推理示范会限制模型的探索, 跳过 SFT, 只给结果奖励, 模型可能找到不同于人类的推理方式. 补充材料 G.1 给出了这个假设成立的前提: 他们先在 7B 稠密模型和 16B MoE 上试过, AIME 上没有有意义的提升, 回答变长后小模型开始重复, 无法利用长 CoT; 换到 32B 稠密, 230B MoE 和 671B MoE 才看到纯 RL 带来的大幅提升. 结论是纯 RL 的效果高度依赖底座的容量. 这个前提比「跳过 SFT」本身更重要, 后来的复现工作大多也是在 7B 以上的强底座上才看到类似现象.

### 1.2. GRPO: 不要 critic, 用组内均值当基线

R1-Zero 和 R1 都用 **GRPO**(式 1–3):

$$
\mathcal{J}_{\mathrm{GRPO}}(\theta)=\mathbb{E}_{q,\{o_i\}\sim\pi_{\theta_{old}}}\frac{1}{G}\sum_{i=1}^{G}\left(\min\left(\rho_iA_i,\ \mathrm{clip}(\rho_i,1-\varepsilon,1+\varepsilon)A_i\right)-\beta\,\mathbb{D}_{KL}(\pi_\theta\|\pi_{ref})\right),\qquad A_i=\frac{r_i-\mathrm{mean}(\{r_j\})}{\mathrm{std}(\{r_j\})},
$$

$\rho_i=\pi_\theta(o_i|q)/\pi_{\theta_{old}}(o_i|q)$. 每道题从旧策略采样 $G=16$ 个回答, 用这组回答奖励的均值和标准差把每个奖励标准化, 得到优势 $A_i$; 目标函数是 PPO 式的截断比率项, 减去对参考策略的 KL 惩罚. 结果奖励是 0/1 时, 组内标准化的效果可以直接算出来. 16 个里答对 4 个: 均值 0.25, 标准差 $\sqrt{0.25\times0.75}\approx0.433$, 答对的 $A=1.73$, 答错的 $A=-0.58$. 16 个里只答对 1 个: 均值 0.0625, 标准差约 0.242, 那一个答对的 $A\approx$ **3.87**, 其余各 $-0.26$. 也就是说, 越难的题, 偶然答对的那条轨迹拿到的正优势越大, 答错的轨迹受罚越轻; 16 个全对或全错时优势全为 0, 这道题只剩 KL 项. 这就是 GRPO 把底座「偶尔能走通」的路径放大的具体方式(以上按总体标准差算, 报告没写用总体还是样本标准差). 

与 PPO 的区别有两处(补充材料 A.3). 第一, PPO 用 GAE 计算优势, 需要一个与策略同规模的价值模型; 价值模型要根据已生成的前缀预测最终奖励, 在只有结果奖励, 回答又长又会中途推翻自己的长 CoT 场景里, 这种预测尤其困难. 第二, PPO 通常把逐 token 的 KL 惩罚作为稠密奖励加在每一步上, 累积起来相当于惩罚回答长度; 

GRPO 把 KL 的无偏估计 $\pi_{ref}/\pi_\theta - \log(\pi_{ref}/\pi_\theta) - 1$ 直接加进损失, 不随长度累积, 回答才有机会变长. GRPO 的推导见 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md), 与 PPO 的对照见 [PPO](../../../llm-guide/4-后训练/4.4-强化学习基础/04-PPO/04-PPO.md).

Figure 4 用 DeepSeek-Coder-V2-Lite(16B MoE, 2.4B 激活)在 MATH 上比较两者: GAE 的 $\lambda$ 取开源实现常用的 0.95 时, PPO 明显不如 GRPO; 调到 1.0 后接近 GRPO(读图). $\lambda=1$ 意味着 GAE 退化为蒙特卡洛回报减价值基线, 不再依赖价值模型的逐步估计, 这恰好说明在结果奖励场景下价值模型的中间估计帮不上忙. 报告的结论是 PPO 调好也能用, 但要多花调参成本, 还要多训一个价值模型. 

训练中每 400 步把参考模型换成最新策略, 因为几千步之后策略会离初始模型很远, 固定参考会过度约束后续探索.

式 1 的比率写成整条回答的概率比 $\pi_\theta(o_i|q)/\pi_{\theta_{old}}(o_i|q)$, 没有写出按 token 平均的项; 但 §3.2.1 又说截断系数太小「会截断大量 token 的梯度」, 说明实现里比率是逐 token 计算的. 社区后来的分析(Understanding R1-Zero-Like Training, 提出 Dr. GRPO)指出, DeepSeekMath 原式里按回答长度 $1/|o_i|$ 平均, 以及按组内标准差归一化, 会让长的错误回答受罚更轻, 人为推高回答长度. 报告未说明 R1 的实现是否带有长度平均项; 按式 3 的写法, 标准差归一化是存在的. 这一偏置的讨论见 [Dr. GRPO 去标准差](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/02-DrGRPO-去标准差/02-DrGRPO-去标准差.md).

## 2. R1-Zero: 只用规则奖励的 RL

### 2.1. R1-Zero 的奖励与模板

R1-Zero 的奖励全部是规则(§2.2): **准确率奖励**加**格式奖励**, 两者权重相同, 即 $\mathrm{Reward}_{\mathrm{rule}}=\mathrm{Reward}_{\mathrm{acc}}+\mathrm{Reward}_{\mathrm{format}}$(式 4). 数学题要求把最终答案写在指定格式里(如方框中)再与标准答案比对, 代码题用编译器跑预设测试用例; 格式奖励要求推理过程放在 think 标签里. 报告明确不用神经网络奖励模型, 不论是结果奖励还是过程奖励, 理由是大规模 RL 中神经奖励模型容易被 reward hacking, 重训奖励模型又增加成本和复杂度. 模板(Table 1)只规定先在 think 标签里写推理过程, 再在 answer 标签里写答案, 刻意不加任何内容上的引导, 以便观察模型自己的演化.

RL 数据在补充材料 B.3.1 和 Table 4. 数学 26K 题, 平均提示 122 个 token, 不含证明题, 因为证明的对错难以自动判断, 答对得 1 分否则 0 分; 代码 17K 道算法竞赛题, 另有 8K 道从 GitHub issue 提取的修 bug 题, 要通过全部单元测试; STEM 22K 道四到八个选项的选择题, 化学占 46.5%, 生物 30.7%, 物理 15.5%; 逻辑 15K 题, 包括网上的脑筋急转弯, 经典逻辑题, 以及合成的 code-IO 题和密码, 斑马谜题, 24 点等题目. 所有题目都是中文或英文. 通用数据 66K 题用于 R1 的第二轮 RL, R1-Zero 不用. 这套数据的特点是答案都能自动验证, 数学只要最终数值或表达式, STEM 和部分逻辑题是选择题. 选择题只有四到八个选项, 随机猜也有 12.5% 到 25% 的正确率, 模型可能靠排除法而不是完整推理拿到奖励.

### 2.2. R1-Zero 的训练日程

超参在 §2.1: 学习率 3e-6, KL 系数 0.001, 采样温度 1, 每题采样 16 个回答. 最大长度在第 8.2K 步之前是 32,768 token, 之后改为 65,536; 总共训 10,400 步, 相当于 1.6 个 epoch. 每步 32 道题, 即 512 个回答. 每次 rollout 生成 8,192 个回答(512 道题乘 16), 随机分成 16 个 mini-batch, 每个 mini-batch 更新一次, 只过一个内层 epoch. 所以一次 rollout 对应 16 个训练步, 10,400 步约 650 次 rollout, 参考模型每 400 步即每 25 次 rollout 更新一次. 同一次 rollout 的后几个 mini-batch 用的数据已落后策略十几次更新, 这也是截断比率仍然必要的原因.

用步数反推数据量, 会发现一处对不上. 10,400 步乘 32 道题约 33.3 万题次, 除以 1.6 个 epoch, 训练集约 **20.8 万**道题. 而 Table 4 列出的推理类 RL 题目合计约 8 万到 8.8 万道. 两者差两倍多, 可能 R1-Zero 用的题库比 Table 4 更大, Table 4 描述的是 R1 阶段的数据, 也可能 epoch 的算法不同, 报告没有说明. 训练成本见补充材料 Table 7: R1-Zero 用 64 个节点共 512 张 H800, 约 198 小时, 合 101K GPU 小时. 每步平均约 69 秒, 其中大部分时间花在生成几万 token 长的回答上.

### 2.3. R1-Zero 的结果和「顿悟」

Figure 1 显示, AIME 2024 的 pass@1 从 15.6% 升到 77.9%, 用 16 次采样多数投票(cons@16)可达 86.7%, 超过人类参赛者的平均水平. 训练集上的平均回答长度持续增长, 从开始时约 500 token 涨到结束时约 **1.35 万** token, 第 8K 步以前大致线性上升, 此后曲线明显抬高, 波动也变大(读图). 在第 8.2K 步最大长度从 32K 放宽到 64K 时, 分数和长度都出现一次明显跳升, 报告自己也写了这一点. 这说明在此之前有相当一部分回答被长度上限截断, 截断的回答拿不到答案分; 放宽上限本身就会带来提升, 不能全部归功于模型「学会了思考」.

补充材料 C 做了行为分析. 在 MATH 按难度分层, 1 到 3 级很快达到 0.90 到 0.95, 4 级从约 0.78 升到 0.95, 5 级从约 0.55 升到 0.90(读图); 1 级只有 43 题, 95% 到 97% 的正确率意味着只错一两道, 多是几何题. 三位专家选了 wait, mistake, however, but, retry, error, verify, wrong, evaluate, check 等反思词, 训练中这些词的出现频率涨了 **5 到 7 倍**. 其中 wait 在训练早期几乎没有, 4000 到 7000 步偶尔出现, 8000 步之后骤增. Table 2 的「aha moment」就是模型在推导中写出「Wait, wait. Wait. That's an aha moment I can flag here」然后重新检查.

「顿悟」的解读后来受到质疑. Understanding R1-Zero-Like Training 一文检查了包括 V3-Base 在内的多个底座, 发现 V3-Base 在 RL 之前就会出现 aha moment 式的自我反思; 另一项 oat-zero 的研究发现小底座在第 0 步就有这类表达, 其中不少是「表面反思」, 反思之后答案并没有变对. 结合第 1.2 节的长度偏置, 回答变长和反思词增多, 有一部分可能来自优化目标本身, 而不是全新能力的涌现. 报告附录也承认底座见过大量推理数据. 现有证据支持 RL 提高已有反思行为的频率和有效性, 但不足以证明这些行为由 RL 凭空产生.

## 3. R1 的多阶段流水

### 3.1. R1 的第一步: 冷启动数据

R1-Zero 有两个问题: 可读性差, 同一段 CoT 里中英混杂. R1 的流程(Figure 2)先收集几千条**冷启动数据**, 微调 V3-Base 作为 RL 的初始策略. 补充材料 B.3.2 说这一步的动机主要是产品层面的: 用户更容易接受第一人称的思考过程. R1-Zero 倾向用「we」或者不用人称, R1 更多用「I」. 报告同时提醒, 这种生动的推理风格反映的是 DeepSeek 设计的启发式规则, 不代表模型具备了类人的智能, 可能让用户产生不必要的信任. 冷启动数据的风格要求是: 先理解问题, 再详细推理并带反思和验证, 全程第一人称, 语言与提问一致.

图注: 报告 Figure 2: R1 多阶段训练流程——冷启动 SFT、推理 RL、拒绝采样、全场景 RL。
*报告 Figure 2: R1 多阶段训练流程——冷启动 SFT、推理 RL、拒绝采样、全场景 RL*

制作流程是: 先请人工标注员把 R1-Zero 的推理轨迹改写成自然的对话风格, 再用这些改写样例提示一个 LLM 按同样风格改写更多数据, 随后对 LLM 的输出做第二轮人工核验. 

冷启动 SFT 训 2 到 3 个 epoch, 学习率余弦从 5e-5 降到 5e-6, 最大长度 32,768, batch 128(补充材料 B.4.2). 

冷启动之后的 R1-Dev1(Table 3)指令跟随明显变好: IF-Eval 从 R1-Zero 的 46.6 升到 71.7, ArenaHard 从 53.6 升到 77.0, AlpacaEval 2.0 从 24.7 升到 50.1. 代价是推理下降: AIME 从 77.9 降到 59.0, CNMO 从 88.1 降到 58.0, GPQA 从 75.8 降到 66.1. 报告归因于冷启动数据量太小. 几千条人改的数据就能把 AIME 拉低近 19 分, 说明 SFT 对长推理行为的扰动很大, 这也从反面支持了报告「人写的示范会限制探索」的判断.

### 3.2. 第一轮 RL 和语言一致性奖励

第一轮 RL 的超参与 R1-Zero 基本相同: 学习率 3e-6, KL 系数 0.001, 温度 1, 每题 16 个回答, 最大长度 32,768, 每步 32 道题, 每 400 步更新参考模型. 报告写 GRPO 截断系数 $\varepsilon=10$, 并解释系数太小会截断大量 token 的梯度, 太大又不稳定. 常见的 PPO 截断系数约为 0.2; $\varepsilon=10$ 要求比率超过 11 才触发上界, 下界 $1-10$ 又为负数, 在通常定义下几乎等同于不截断. 公开材料无法判断这是笔误, 还是 R1 实现采用了不同于式 1 的截断定义.

这一轮新增了**语言一致性奖励**(式 7): $\mathrm{Reward}_{\mathrm{language}}=\mathrm{Num}(\mathrm{Words}_{\mathrm{target}})/\mathrm{Num}(\mathrm{Words})$, 即 CoT 中目标语言词数占总词数的比例, 取值 0 到 1, 直接加到最终奖励上, 推理和非推理数据都加. 

它和 0/1 的准确率奖励同权相加, 放进同一组里比较: 答对但 CoT 只有一半是目标语言的回答得 $1+1+0.5=2.5$(准确率, 格式, 语言), 答错但语言纯净的回答得 $0+1+1=2$, 答对仍然占优, 但只多 0.5 分. 半个准确率的差距足以在组内标准化后改变优势的正负分布, 代码题的轻微下降可以从这里理解. 

补充材料 B.6 在 DeepSeek-R1-Distill-Qwen-7B 上做了消融, 该模型用同样的冷启动数据, RL 中同样出现语言混杂. 不加这项奖励, 语言一致性随训练步数逐渐变差; 加上后一直稳定. 数学基准基本不变, 代码基准略有下降(读图). 报告的态度是接受这点性能损失, 换取可读性. 第一轮 RL 之后的 Dev2 推理大幅回升: AIME 74.0, CNMO 73.9, LiveCodeBench 63.5, Codeforces 评分从 Dev1 的 1534 升到 1687; AlpacaEval 只从 50.1 到 55.8, 说明面向推理的 RL 对用户偏好类评测帮助有限.

### 3.3. 80 万条 SFT 数据

第二轮 SFT 的数据约 **80 万**条(补充材料 B.3.3). 推理数据约 60 万条, 从第一轮 RL 的 checkpoint **拒绝采样**得到: 每题采样多个回答, 只保留正确的. 这一轮不再限于能用规则判分的题, 一部分题把标准答案和模型预测一起交给 DeepSeek-V3 判断, 即生成式奖励模型. 还过滤掉了语言混杂, 段落过长, 含代码块的 CoT. 非推理数据约 20 万条, 包括写作, 事实问答, 自我认知, 翻译, 复用了 V3 的部分 SFT 数据, 并加入程序修复, 前端开发等软件工程数据. 部分非推理任务先让 V3 生成一段 CoT 再回答, 像「hello」这样的简单问题则不给 CoT.

Table 5 给出分领域统计: 数学 395,285 条, 平均 6094 token; 代码 211,129 条, 平均 7436 token; STEM 10,124 条; 逻辑 10,395 条; 通用 177,812 条, 平均 1420 token; 合计 804,745 条, 平均 5355 token. 按条数乘平均长度, 一个 epoch 约 **43 亿** token, 其中数学约 56%, 代码约 36%, 通用只占约 6%. 条数上通用数据占 22%, 按 token 算却只有 6%, 模型在 SFT 中看到的绝大部分内容是长推理. 平均轮数 1.0 到 1.1, 几乎全是单轮, 报告承认这会限制多轮对话能力. 这一轮 SFT 之后的 Dev3 在 AlpacaEval 上到 62.1, Aider-Polyglot 从 25.6 跳到 44.8, 对应新加的非推理数据和软件工程数据. SFT 数据质量筛选的一般做法见 [SFT 数据质量筛选与训练技巧](../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md).

### 3.4. 奖励模型和第二轮 RL

第二轮 RL 需要给通用数据打分, 所以训了两个奖励模型(§3.1). **有用性奖励模型**: 用 Arena-Hard 的提示格式让 DeepSeek-V3 比较一对回答, 每对问 4 次并随机交换 A, B 位置以消除位置偏差, 取 4 次平均, 只保留分差 Δ 大于 1 的对; 还让整个数据集中被选和被拒回答的长度相当, 以减少长度偏差. 共 66,000 对, 提示都是非推理问题. 模型结构与 R1 相同, 加一个标量奖励头; batch 256, 学习率 6e-6, 训一个 epoch, 训练最大长度 8192, 推理时不限长度. 有用性只评最终总结, 不评推理过程, 避免干扰推理. 

**安全奖励模型**用 106,000 条标注为安全或不安全的回答, 按单点方式训练; 安全性评估整个回答, 包括推理过程.

第二轮 RL 的总奖励是

$$
\mathrm{Reward}=\mathrm{Reward}_{\mathrm{reasoning}}+\mathrm{Reward}_{\mathrm{general}}+\mathrm{Reward}_{\mathrm{language}},\quad \mathrm{Reward}_{\mathrm{reasoning}}=\mathrm{Reward}_{\mathrm{rule}},\quad \mathrm{Reward}_{\mathrm{general}}=\mathrm{Reward}_{\mathrm{reward\_model}}+\mathrm{Reward}_{\mathrm{format}}.
$$

一道题只属于一类: 推理题拿规则奖励, 通用题按它属于有用性集还是安全集, 拿对应奖励模型的分数, 再加格式奖励; 语言项两类都加. 有用性奖励在式 5 里写成 $RM_{\mathrm{helpful}}(\mathrm{Response}_A,\mathrm{Response}_B)$, 输入是一对回答, 奖励头输出的标量是这一对的偏好分, 而 GRPO 需要给组里 16 个回答各一个标量; 报告没写 RL 时怎么把成对打分变成单个回答的分数. 

温度从 1 降到 0.7, 因为高温下生成不连贯. 共 1,700 步, 通用指令数据和偏好奖励只在末尾 400 步加入. 原因写在补充材料 B.5: 用有用性奖励模型训练更多步会出现 reward hacking, Figure 6 显示奖励持续上升的同时 Codeforces 成绩下降(读图). 所以偏好 RL 在这里被刻意限制在几百步. R1 相对 Dev3 的主要提升在用户偏好类评测: AlpacaEval 2.0 从 62.1 升到 87.6, ArenaHard 从 75.6 升到 92.3, IF-Eval 从 78.1 升到 83.3.

## 4. 评测与分析

### 4.1. 评测协议与去污染

评测设置在补充材料 D.1. 最大生成长度 32,768 token. 贪心解码会让长推理模型重复率高, 不同 checkpoint 之间波动大, 所以默认用温度 0.6, top-p 0.95 采样 k 个回答, 报告平均正确率作为 pass@1; AIME 和 GPQA 取 k = 64, MATH 和 Codeforces 取 16, LiveCodeBench 取 8. AIME 另报 64 次多数投票的 cons@64. MMLU-Pro, C-Eval, CLUEWSC 原本是 few-shot 提示, 改成 zero-shot, 因为 few-shot 会损害 R1; Codeforces 用 10 场 Div.2 比赛的题和专家构造的测试用例, 估算评分和百分位; LiveCodeBench 取 2024 年 8 月到 2025 年 1 月的题; AlpacaEval 和 ArenaHard 用 GPT-4-Turbo-1106 当裁判, 只把最终总结交给裁判, 以减少长度偏差. o1-1217 的分数取自官方报告, 因为在中国大陆难以访问其 API, 与其他模型不是同一套评测流程.

去污染方面, V3-Base 的知识截止于 2024 年 7 月, 预训练数据里凡是与评测题目或参考答案有 10-gram 重合的片段都被过滤, 仅数学领域就删掉约 **600 万**条潜在文本. 后训练的数学 SFT 数据和 RL 题目只取 2023 年以前的竞赛, 并做同样的 n-gram 过滤. 报告也承认 n-gram 方法挡不住改写过的题目, 2024 年以前发布的评测集可能存在污染. 作为补充, 补充材料 E.2 用训练之后才发布的 AIME 2025 测试: R1 平均答对 11.3/15, 即 75%, o1-1217 为 12.0/15; AMC 12 2024 得 143.7/150, 两者合成的 USAMO 指数 256.7, 超过 251.5 的晋级线. 表里的 AIME 2025 只有 15 题(链接指向 AIME II), 一道题就是 6.7 个百分点.

### 4.3. 推理长度和 TestingTime 算力

补充材料 E.4 用 2024 年 93 场数学竞赛的 366 道题测试推理长度. R1 的 pass@1 为 61.8%, 平均每题 8,793 个思考 token; 简单题用不到 7,000, 最难的题超过 18,000(读图, Figure 18 经过样条平滑). 1 + 1 这类极简单问题不到 100 个 token. GPT-4o 0513 在同一组题上只有 24.7%, 平均输出 711 个 token, 少一个数量级. 这就是报告说的 TestingTime 算力: 模型根据题目难度自己决定花多少推理 token, 难题多想. 报告也承认简单问题上仍有过度思考, token 效率还有优化空间. 推理能力与推理时算力的整体脉络见 [推理与思考能力](../../../llm-guide/4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md).

报告拿多数投票做了对照. GPT-4o 在 AIME 2024 上 64 次投票只从 9.3% 升到 13.4%, 在 366 题集上 16 次投票几乎没有提升, 尽管总 token 数已超过 R1. 报告的解释是独立采样的回答之间不会互相借鉴, 不会回溯纠错, 多采样只是重复错误答案. 反过来, R1 自己的 pass@64 是 90.0%, 比 pass@1 的 79.8% 高 10 个百分点, 多数投票能到 86.7%, 说明长推理有时也会陷在错误路径里, 并行采样仍有互补作用.

pass@64 与 pass@1 的差距, 连着一个后来被反复讨论的问题. Does Reinforcement Learning Really Incentivize Reasoning Capacity 一文在多个模型族上比较底座与 RLVR 模型的 pass@k: k 小时 RL 模型更好, k 很大时底座反而更高, RL 模型能解出的题几乎都在底座的采样分布里. 按这个视角, RL 主要提高的是采样效率, 把底座偶尔能走通的路径变成大概率路径. 该文同时发现蒸馏能带来底座没有的新推理模式, 这与本篇第 5.1 节蒸馏胜过小模型 RL 的结果一致. R1 报告没有给出 V3-Base 在大 k 下的 pass@k, 因而不能在该模型上直接检验这一结论. RLVR 的边界讨论见 [RLVR 的局限性与探索边界分析](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md).

## 5. 蒸馏与失败的尝试

### 5.1. 蒸馏到小模型

蒸馏只做 SFT, 不做 RL(补充材料 F). 用第 3.3 节的 80 万条数据微调六个开源底座, 训 2 到 3 个 epoch, 学习率余弦降到初始值的十分之一, 最大长度 32,768, batch 64. 底座和初始学习率(Table 6): Qwen2.5-Math-1.5B 1e-4, Qwen2.5-Math-7B 8e-5, Qwen2.5-14B 7e-5, Qwen2.5-32B 6e-5, Llama-3.1-8B 5e-5, Llama-3.3-70B-Instruct 2e-5. 1.5B 和 7B 用的是数学专用底座, 其余是通用底座, 70B 用的是已经指令微调过的版本, 起点并不统一.

Table 15 的结果: Distill-Qwen-1.5B 的 AIME 2024 为 28.9%, MATH-500 83.9, 已超过 GPT-4o 和 Claude-3.5-Sonnet 的数学分数; 7B 为 55.5, 14B 为 69.7, 32B 为 72.6, Llama-70B 为 70.0, GPQA 65.2. 规模越大越好, 但并非处处单调: cons@64 上 7B 和 32B 都是 83.3, 14B 只有 80.0. AIME 只有 30 题, 83.3% 是 25 题, 80.0% 是 24 题, 差的只是一道. 1.5B 的 GPQA 只有 33.8, Codeforces 954, 数学底座蒸馏出来的小模型在数学以外很弱. 这些小模型都只在推理类评测上报告, 没有通用能力和指令跟随的分数. 知识蒸馏的一般讨论见 [知识蒸馏](../../../llm-guide/6-训练与推理优化/6.3-模型压缩/6.3.3-知识蒸馏/6.3.3-知识蒸馏.md).

补充材料 F.1 回答了「小模型自己做 RL 行不行」. 在 Qwen2.5-32B-Base 上用数学, 代码, STEM 数据做了 1 万多步 RL, 得到 Qwen2.5-32B-Zero: AIME 47.0, MATH 91.6, GPQA 55.0, LiveCodeBench 40.2, 与 QwQ-32B-Preview 相当; 同一底座蒸馏出的 Distill-Qwen-32B 是 72.6, 94.3, 62.1, 57.2, 全面领先. 结论有两条: 把强模型蒸馏给小模型效果好, 小模型靠本文这种大规模 RL 需要大量算力, 还未必追得上蒸馏; 但要超越人类的能力边界, 仍需要更强的底座和更大规模的 RL. 为排除底座见过推理数据的可能, 他们还在 o1 发布前的 Qwen2-Math-7B(2024 年 8 月发布)上做了约 1 万步 RL, AIME 2024 从指令版的 7.9% 升到 22.3%, AIME 2025 从 4.6% 升到 18.1%.

### 5.2. 失败的尝试和安全评测

补充材料 G.2 记录了两条没走通的路. **过程奖励模型**: 一般推理很难定义细粒度的「步」, 判断中间步骤对错也难, 用模型自动标注效果不好, 人工标注又无法规模化; 一旦引入基于模型的过程奖励, reward hacking 就不可避免. 过程奖励适合给候选答案重排或辅助搜索, 但在大规模 RL 中收益抵不过开销. **蒙特卡洛树搜索**: 让模型生成对应推理步骤的标签, 用预训练的价值模型引导搜索, 再用搜到的问答对迭代训练策略和价值模型. 问题在于 token 生成的搜索空间比棋类大得多, 限制每个节点的扩展数又容易陷入局部最优; 细粒度价值模型难训, 迭代自我提升做不起来.

安全评测在补充材料 D.3. 六个公开基准(Table 9)中, R1 在隐藏 CoT 的设置下平均 96.0, 与其他前沿模型相当; 但这是加上风险控制系统后的分数, 被风控拦截而自动拒答的回答一律算作安全. 不计风控时, R1 的 HarmBench 只有 58.0, 平均 89.7. 报告分析 HarmBench 的失分主要在知识产权类题目, 例如被要求写出某首歌的歌词时不拒绝. 

越狱测试(Table 11)用 2,232 个越狱模板拼接原有安全问题: 不带风控的 R1 不安全回答比例从 25.2% 升到 85.9%, 增幅 60.7 个百分点, 是所有模型中最大的; 加上风控后降到 4.3%, 代价是拒答率升到 87.3%. 报告据此建议用开源模型提供服务的开发者部署同等的风控措施, 因为本地部署的模型没有这层保护.

## 6. 局限和谱系位置

结论节列出的局限: 结构化输出能力弱于现有模型, 不能调用搜索引擎, 计算器等工具; 简单问题上过度思考; 只针对中英文优化, 其他语言的提问可能用英文推理和回答; 对提示敏感, few-shot 会降低表现, 建议 zero-shot 直接描述问题和输出格式; 软件工程任务评测耗时长, 大规模 RL 没有在这类任务上充分展开, 所以 SWE 类成绩相对 V3 提升不大. 

方法层面的局限是奖励: 规则奖励只覆盖可验证任务, 写作等任务只能用奖励模型, 训练越久越容易被利用, 所以 R1 对这类任务只用人工标注的 SFT 数据加几百步 RL.

谱系上, R1 与 V3 是互相借用的关系. V3 的后训练 SFT 数据里, 推理部分由 R1 系列专家模型生成; R1 反过来以 V3-Base 为底座, 非推理 SFT 数据复用了 V3 的一部分, 有用性奖励模型的偏好对也由 V3 判定. R1 之后, V3.1 把思考和非思考两种模式合进同一个模型, V3.2 和 V4 在长推理之外继续加入工具调用和 Agent 任务的 RL. R1 在这条线上确立的做法, 即可验证奖励, GRPO, 冷启动加多阶段 RL, 以及用长推理数据蒸馏, 被后续版本基本沿用. Agentic RL 的后续发展见 [Agentic RL 训练](../../../llm-guide/13-Agent/13.4-Agent训练与进化/13.4.1-AgenticRL训练/13.4.1-AgenticRL训练.md).

## 7. GRPO 从采样到梯度

### 7.1. 组内优势的手算

给定问题 $q$, 旧策略采样 $G$ 个回答 $o_1,\ldots,o_G$, 奖励为 $r_1,\ldots,r_G$. GRPO 不训练价值网络, 直接用同题样本的均值和标准差构造优势:

$$
A_i=\frac{r_i-\bar r}{\sigma_r+\epsilon},\qquad
\bar r=\frac{1}{G}\sum_{j=1}^{G}r_j.
$$

假设四个数学回答的规则奖励是 $(1,1,0,0)$, 均值 0.5, 总体标准差 0.5, 优势为 $(1,1,-1,-1)$. 两个正确轨迹概率上升, 两个错误轨迹下降. 若奖励为 $(1,1,1,1)$, 方差为零, 加稳定项后四个优势都为零, 该题不提供策略梯度. 全员答错同样如此. 训练最有信息的题位于当前能力边界: 同组里既有成功也有失败.

规则奖励若包含准确性 $r^{acc}$ 与格式 $r^{fmt}$, 总奖励可写成 $r=r^{acc}+r^{fmt}$. 四个回答得到 $(2,1,1,0)$ 时, 第一个既正确又守格式, 中间两个只满足一项. 组内标准化只关心相对次序, 两项权重决定模型愿不愿用正确性换格式. R1-Zero 的格式模板只要求思考放在 `<think>` 与 `</think>` 中, 答案放在指定区域, 不规定具体推理风格, 尽量减少对思考内容的人为塑形.

### 7.2. token 级裁剪

对第 $i$ 个回答的第 $t$ 个 token, 新旧策略概率比为

$$
\rho_{i,t}(\theta)=\frac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}{\pi_{\theta_{old}}(o_{i,t}\mid q,o_{i,<t})}.
$$

目标对回答长度取平均:

$$
J(\theta)=\frac1G\sum_i\frac1{|o_i|}\sum_t
\min\left(\rho_{i,t}A_i,\operatorname{clip}(\rho_{i,t},1-\varepsilon,1+\varepsilon)A_i\right)
-\beta D_{KL}(\pi_\theta\|\pi_{ref}).
$$

$A_i>0$ 时, 概率比超过 $1+\varepsilon$ 后收益封顶; $A_i<0$ 时, 概率比低于 $1-\varepsilon$ 后惩罚封顶. 同一个序列优势复制到所有 token, 规则奖励只告诉模型整条回答成败, 没有指出错误发生在哪一步. 一条两千 token 的推理在末尾算错, 前面所有 token 也拿到负优势; 一条中间逻辑错误却碰巧答对的轨迹, 全部 token 得到正优势. 大量采样与模型自身分布只能在统计上缓解信用分配问题.

长度平均避免长回答仅因 token 多而产生更大梯度, 也会带来另一种偏差: 长轨迹每个 token 分到的更新较小. 若成功轨迹普遍更长, 模型可能难以稳定强化早期探索步骤. R1 观察到回答长度随 RL 增长, 说明在其设置里准确奖励足以抵消这种稀释, 但报告没有给不同长度桶的梯度或回报曲线.

### 7.3. KL 约束与参考策略

KL 项使用逐 token 无偏估计

$$
D_{KL}=\frac{\pi_{ref}}{\pi_\theta}-\log\frac{\pi_{ref}}{\pi_\theta}-1.
$$

令 $x=\pi_{ref}/\pi_\theta$, 则 $x-\log x-1\ge0$, 等号只在 $x=1$ 成立. 它惩罚策略远离参考模型, 抑制为追规则奖励而把语言分布推到异常区域. $\beta$ 太大, 策略几乎不动; 太小, 格式重复、语言混杂和奖励漏洞会快速放大. R1 报告公开算法形式, 没有给出完整的 $G$、$\varepsilon$、$\beta$ 与 batch 配置, 外部只能复现方法族, 无法精确复现训练轨迹.

## 8. R1-Zero 的证据边界

### 8.1. 「从零」指什么

R1-Zero 从 DeepSeek-V3-Base 开始, 没有先做推理 SFT, 随即进入规则奖励 RL. 「Zero」指后训练阶段没有冷启动监督数据, 底座本身已经经过 14.8T token 预训练, 拥有数学、代码、语言与一定的解题轨迹. 因此实验检验的是「预训练底座能否在无推理 SFT 的条件下被 RL 重排成稳定长推理」, 不等于从随机参数凭奖励学出推理.

V3-Base 在大采样数下能否解出相同题目, 报告没有系统给出. 若底座 pass@64 已很高、pass@1 较低, RL 可能主要把低概率正确轨迹推到高概率; 若底座无论怎样采样都找不到某类策略, RL 后出现新轨迹才更接近能力扩展. 只比较 pass@1 端点无法区分这两种机制.

### 8.2. 长度增长不等于推理增长

训练过程中平均回答长度从较短逐步增加, AIME 准确率也上升. 两条曲线同步支持「更多测试时计算有帮助」, 仍不能证明因果. 模型可能先学会正确策略, 正确题恰好需要更长回答; 也可能单纯增加重复检查, 其中一部分碰巧纠错. 应在固定最大长度下比较不同 checkpoint, 或对同一 checkpoint 强制不同预算, 得到准确率—token 曲线.

一个反例是模型反复重述题目、枚举无关路径, 长度翻倍而正确率不变. 另一个反例是简单算术被强制长推理后引入错误. R1 报告也承认简单问题存在过度思考. 因而有效计算要看单位新增 token 带来的正确率增量, 以及模型能否按题目难度分配长度.

### 8.3. 「顿悟时刻」如何验证

报告展示的中间样例出现「等等, 让我重新检查」一类自我反思, 并称为 aha moment. 这能直观说明策略学会延长与修正轨迹, 但单个样例不构成涌现证据. 更严格的测量可以定义可观察事件: 明确否定先前中间结论、回到早期分支、重新计算并改正答案. 对每个 checkpoint 抽取同规模样本, 人工或规则标注事件频率, 再与最终正确率关联.

如果反思短语频率突然上升而纠错成功率不变, 模型可能只学会了表面措辞; 若没有固定短语, 实际回溯成功率持续提高, 能力变化反而更可信. 「突然」还需要密集 checkpoint 才能确认. 训练日志若只隔很远保存一次, 平滑增长也会看起来像跃迁.

### 8.4. 语言混杂与可读性

纯规则奖励只关心答案和格式, 不奖励语言一致与易读性. R1-Zero 会在同一推理中混用中英文, 句子也可能难读. 准确奖励仍完成了它所定义的任务, 但表达质量位于奖励覆盖范围之外. 只要混合语言不妨碍最终答案, 策略没有动力修正.

给语言一致性奖励又会产生取舍. 奖励过强时, 模型可能为了保持某种语言放弃更熟悉的数学表达, 推理准确率下降; 过弱则混杂保留. R1 第一轮 RL 加入语言一致性奖励, 报告称准确率略有下降但可读性改善. 这说明推理质量与表达质量在当前策略空间里并非完全同向.

## 9. cold-start 改变了什么

冷启动数据由少量高质量长推理样本组成, 来源包括 few-shot 提示生成、直接提示模型给出反思和验证、人工后处理 R1-Zero 输出, 以及人工撰写. 它向模型提供可读的推理格式、摘要与答案分隔方式, 再进行第一轮推理 RL. 数量和具体配比没有公开.

从优化角度看, cold-start 把初始策略移到规则奖励可探索的区域. 若底座产生正确长轨迹的概率为 $p$, 每题采样 $G$ 次至少出现一次成功的概率为 $1-(1-p)^G$. 当 $p$ 极小时, 组内几乎全错, 优势信号消失. 少量 SFT 把 $p$ 提高后, RL 才经常见到成功与失败并存的组. 它还统一输出边界, 让规则解析器少把正确答案误判为格式错误.

这解释了为何冷启动不需要覆盖全部能力. 它的任务是提高可探索性和可读性, 具体数学知识仍来自 V3-Base, 策略强化来自后续 RL. 若用大量 SFT 填满所有题型, 就难以判断 RL 是否学到新策略; 若完全不用 SFT, R1-Zero 证明准确率可以提升, 但表达质量较差.

严谨消融应至少比较四个起点: V3-Base 直接 RL、仅 cold-start SFT、cold-start 后 RL、等 token 的普通短 CoT SFT 后 RL. 比较 pass@1、pass@k、回答长度、语言一致性、格式成功率与训练样本效率. R1 报告展示了 Zero 与完整 R1 的端点, 没有把四格全部公开.

## 10. 从第一次 RL 到 80 万条 SFT

第一轮 RL 聚焦数学、代码、科学和逻辑等可验证任务. 得到 checkpoint 后, 团队用拒绝采样生成推理数据: 对问题采样多个回答, 用规则或判分筛选正确轨迹, 再过滤语言混杂、不可读和不合格式的样本. 约 60 万条推理样本与约 20 万条非推理样本组成新 SFT 集.

拒绝采样改变的是条件分布. 原策略生成 $o$ 的概率为 $p(o\mid q)$, 筛选器接受概率为 $a(o,q)$, 留下的数据服从

$$
p_{keep}(o\mid q)=\frac{p(o\mid q)a(o,q)}{\sum_{o'}p(o'\mid q)a(o',q)}.
$$

规则正确的轨迹被放大, 错误轨迹被压到零. 如果判分器漏掉某类等价答案, 这些正确推理也会消失; 如果测试用例不完整, 投机代码会进入数据. SFT 学到的是筛选后的策略, 筛选器的盲区也会被蒸馏.

非推理数据来自 DeepSeek-V3 的既有 SFT 数据, 覆盖写作、事实问答、自我认知与翻译. 这一步用于恢复通用交互能力. 只在可验证题上做 RL 容易让模型把长思考格式带到所有问题, 20 万条普通回答为短任务提供另一种模式. 两类数据的 token 比、采样权重和长度截断未公开, 60 万对 20 万的条数比例不能直接当作训练权重比例.

第二次 SFT 后再做一轮覆盖更广的 RL. 推理任务继续使用规则奖励, 通用任务使用有用性与安全奖励模型. 有用性只看最终回答, 不评价隐藏思考, 避免奖励模型干预推理过程; 安全奖励同时看整段输出. 两种奖励的混合系数没有公开. 这轮 RL 负责把推理、帮助性和安全合到同一策略, 也可能产生能力间的覆盖.

## 11. 蒸馏为何可能胜过小模型直接 RL

小模型直接 RL 受探索概率限制. 假设某道难题底座一次生成正确轨迹的概率为 $10^{-5}$, 每组采样 64 次, 至少一次成功的概率约为 $6.4\times10^{-4}$. 大多数训练组全错, 规则奖励无法指出向哪里改. 强教师可直接提供成功轨迹, SFT 对每个 token 都有监督, 不需要学生先碰巧探索到答案.

蒸馏还传递中间策略: 分解题目、设变量、验证边界、回滚错误. 最终答案奖励只有一个标量, 教师轨迹却给出数千个条件 token 标签. 对 1.5B 或 7B 学生, 密集监督的数据效率远高于稀疏奖励并不奇怪.

它的上限受教师分布约束. 学生主要模仿被筛出的 R1 轨迹, 很难系统超过教师在这些题型上的策略; 教师错误、冗长习惯和固定措辞也会传递. 直接 RL 理论上能探索教师未覆盖的策略, 前提是底座有足够容量和非零成功概率. 报告因此把蒸馏视作小模型的高效方案, 把更强底座上的 RL 视作突破边界的路线.

比较蒸馏与 RL 时还要统一计算. Distill-Qwen-32B 使用 80 万条筛选数据训练多个 epoch, Qwen-32B-Zero 做一万多步 RL, RL 还需为每题生成一组回答. 仅比较训练步数不能代表 token 或 FLOPs. 报告的端点证明给定配方下蒸馏更强, 尚未给出相同总生成与训练预算的等成本曲线.

## 12. “能力涌现”的三种解释

第一种是概率重排. 预训练底座已经能偶尔生成有效策略, RL 把它们概率提高, pass@1 大涨而大 $k$ 的 pass@k 上限变化不大. 第二种是组合泛化. 底座掌握局部操作, RL 让模型学会更长地组合、检查和回退, 新轨迹在有限采样中此前几乎看不到. 第三种是表面行为. 模型学会写更长、加入反思短语, 真实求解能力只小幅提升.

三者可以同时存在. 区分它们需要同一底座与 RL checkpoint 的 pass@k 曲线、轨迹聚类、固定长度准确率和干预实验. 如果 RL 只改概率, 随 $k$ 增大底座会追上; 如果产生底座采样不到的新策略, RL 的 pass@k 包络仍更高; 如果主要是表面行为, 删除反思措辞或压缩轨迹后准确率基本不变.

AIME 分数从训练早期到后期上升、回答长度增长、样例出现自我纠错, 支持策略发生变化. 报告没有提供足以排除概率重排的 V3-Base 大 $k$ 数据, 所以「RL 创造全新推理能力」应保留为较强解释, 不能写成已经由该报告单独证明的事实.

## 13. 规则奖励的边界

数学最终答案可精确匹配时, 奖励噪声低. 但等价表达可能很多: 分数与小数、集合顺序、单位和符号形式都需要规范化. 解析器处理不全会制造假阴性. 代码测试提供比字符串匹配更强的语义验证, 测试集覆盖不足又会留下假阳性. 模型可能学会针对常见测试结构投机.

规则奖励也不检查证明过程. 一个错误推导碰巧得到正确答案会被强化, 正确推导因抄错末位数字会被惩罚. 在大量不同题目上, 系统性正确方法通常更容易反复得分, 所以结果奖励仍能学到过程; 这个统计倾向不保证每条轨迹可信. 将 R1 的思考直接当作可验证证明会越过奖励所提供的证据.

过程奖励试图解决信用分配, 又引入步骤边界和判分器漏洞. 一段推理可以省略中间步骤、把多个推断写在一句里, 固定步级很难定义. 自动过程判分器自身会错, 策略能针对其偏好优化. R1 团队放弃大规模 PRM, 说明在当时设置下结果奖励更稳, 不代表过程监督在所有形式下都无效.

## 14. 与 V3 底座的关系

R1-Zero 与 R1 都从 DeepSeek-V3-Base 出发, 因而继承 671B 总参数、约 37B 激活参数、MLA、无辅助损失负载均衡、MTP 训练留下的表示以及 14.8T token 预训练知识. RL 没有重新发明这些能力, 它改变回答轨迹的概率分布.

V3-Base 的 MoE 路由在 RL 中继续工作. 长回答意味着每个问题产生更多 token, 专家调用与 KV cache 按长度增长. RL 的成本不仅由更新步决定, 还受采样长度影响. 随训练推进, 平均推理变长, 同样问题数的生成成本会上升, 训练吞吐也会变化. 报告没有公开完整 GPU 小时, 无法像 V3 预训练那样复算总账.

MTP 在 V3 预训练时提供额外未来监督, R1 推理时主要按自回归策略采样. 若保留 MTP 作推测头, 长推理可以获得解码加速; 技术报告没有把 R1 的能力提升归给 MTP. MLA 则直接决定长 CoT 的缓存成本. R1 输出越长, V3 底座的低缓存设计越有价值.

## 15. 可证伪的最小实验集

验证 cold-start 应固定 RL 数据与预算, 比较零样本起点、冷启动起点和等量普通 CoT 起点. 若冷启动只改善格式、不提高采样成功率, 它主要负责可读性; 若训练早期有效组比例明显上升, 它也改善探索.

验证涌现应为 V3-Base 与各 RL checkpoint 计算相同温度下的 pass@1、pass@8、pass@64 和轨迹多样性. 大 $k$ 上限不变支持概率重排, 上限提高支持策略集合扩张. 再固定输出长度, 排除单纯增加 token 的作用.

验证语言奖励应扫描权重, 同时测数学准确率、单语比例、人工可读性与回答长度. 若单语比例改善而准确率持续下降, 可画出明确 Pareto 前沿; 若存在两者同时提升区间, 当前权重尚未到最佳点.

验证蒸馏与 RL 应固定总生成 token、训练 FLOPs和底座, 比较教师拒绝采样 SFT、纯规则 RL 与 SFT 后 RL. 报告现有实验起点和预算不同, 只能支持实际配方排序, 不能推出任何规模上蒸馏必然优于 RL.

验证规则奖励的可信度应抽样人工审查高奖励轨迹, 统计最终答案正确但过程含错、解析器误拒与测试用例漏判. 这些比例决定数据进入拒绝采样 SFT 后会放大多少噪声. 只看最终基准无法发现过程可靠性问题.

## 16. 采样预算的完整手算

假设底座单次成功率为 $p$, 独立采样 $k$ 次至少成功一次的概率为

$$
\operatorname{pass@}k=1-(1-p)^k.
$$

当 $p=0.01$ 时, pass@64 约 47.4%; 当 $p=0.1$ 时约 99.9%. 真实采样并不完全独立, 多条回答常沿相似路径犯同一种错, 所以公式通常高估收益. 多数投票又与 pass@k 不同: pass@k 只要一条正确, 投票要求正确答案成为众数. 一个模型偶尔找到正确答案、其余样本稳定犯同一种错, pass@64 很高, cons@64 仍可能很低.

R1 在 AIME 2024 上 pass@1 约 79.8%, cons@64 约 86.7%, pass@64 约 90.0%. 三者间距说明剩余错误包含两类: 一部分可通过并行采样找到正确轨迹, 另一部分在 64 次内仍未解决. cons@64 低于 pass@64, 表明至少部分题的正确答案出现过, 但没有成为多数. 若只报投票分数, 会低估模型候选集合里的能力; 只报 pass@64, 又依赖理想的答案选择器.

训练时组大小 $G$ 也遵循相同逻辑. $p$ 太低, 全错组概率为 $(1-p)^G$; $p$ 太高, 全对组概率为 $p^G$. 两者都不给组内相对信号. 以 $G=16,p=0.01$ 为例, 全错概率约 85.1%; $p=0.5$ 时全对或全错都很少, 信号最丰富. 课程若持续使用固定题集, 随模型变强, 早期合适的题会逐渐全对, 有效梯度转向更难样本.

温度影响 $p$ 与多样性. 温度低时高概率路径重复, 独立公式偏差更大; 温度高时探索增加, 语言与格式错误也增加. R1 第一轮与第二轮使用的温度调整说明采样质量本身就是训练变量. 精确复现需要报告温度、top-p、最大长度、组大小与截断规则, 论文并未完整公开.

## 17. 拒绝采样中的选择偏差

假设每题生成 16 条回答, 只保留规则正确者. 容易题可能留下十几条相似轨迹, 难题只留下零到一条. 若不按题目重新加权, SFT 数据会被容易题和模型熟悉的解法占据. 为难题扩大采样数能提高留存, 计算量也随之增加. 报告给出约 60 万条推理数据的结果规模, 没有公布每题采样数、零留存题比例与去重方法.

答案正确还会偏向长轨迹. 多次尝试和自检增加碰到正确答案的机会, 拒绝筛选便可能让保留集平均长度高于原策略. SFT 学到这种长度偏差, 即便某些题无需长推理. 可以按题目难度和正确性匹配长短轨迹, 比较蒸馏后模型是否仍过度思考.

同一道题的多个正确回答也未必提供多样性. 采样可能只有措辞变化, 核心解法相同. 用中间公式、代码抽象语法树或语义嵌入聚类后再选代表轨迹, 能提高策略覆盖. 若多样化筛选使 pass@k 提升而 pass@1不变, 它主要扩展候选集合; 若 pass@1也提高, 多解法监督改善了默认策略.

拒绝采样与在线 RL 的差别在于分布更新. SFT 固定学习筛选数据, 训练过程中数据不会随学生变化; 在线 RL 每轮从当前策略采样, 能在新能力边界附近继续获得信号. R1 把二者交替使用: RL 生成更强策略, 拒绝采样固化高质量轨迹, SFT 混回通用能力, 再用第二轮 RL 统一偏好.

## 18. 推理长度、难度与停止

理想策略应把计算分配给困难样本. 可将题目按底座 pass@1 或人类难度分桶, 统计每桶输出长度与准确率. 如果所有桶长度一起增长, 模型学到的是统一变长; 如果困难桶增长更多且准确率提升更大, 才支持自适应测试时计算.

停止本身是一项决策. 模型每多写一步都有机会纠错, 也有机会推翻正确结论. 规则奖励只看终点, 可以隐式学习何时结束, 但 `<think>` 结束标记的概率受到格式奖励和长度截断影响. 最大长度截断会把尚未写答案的轨迹判错, 给超长推理施加隐式惩罚.

可以把继续思考的期望价值写成

$$
V_{continue}=P(\text{纠错})\Delta R_{gain}-P(\text{引入错误})\Delta R_{loss}-c_{token}.
$$

训练奖励未显式加入 token 成本时, $c_{token}$ 接近零, 策略容易偏长. 部署成本却真实存在. 加长度惩罚会提高效率, 也可能砍掉难题必要的探索. 更好的做法是让惩罚随题目难度或置信度变化, 但如何可靠估计置信度仍是问题.

自我反思也可分成有效与装饰性两类. 有效反思应改变后续推导并提高答案正确率; 装饰性反思只插入「再检查一下」, 后面重复原路径. 自动分析可以比较反思前后的中间答案、变量和运算轨迹. 若 checkpoint 越晚装饰性短语越多, 训练可能在强化一种可见风格; 若路径改变率和纠错率同步上升, 才更接近策略改善.

## 19. SFT、RL 与蒸馏的梯度差异

SFT 对教师轨迹每个 token 给交叉熵梯度. 即使一条回答很长, 每一步都有明确标签. RL 用整条奖励构造一个优势, 同一符号分配到所有 token, 信号稀疏但允许偏离教师. cold-start SFT先提供稳定语法和少量成功路径, RL 再在策略分布内探索, 拒绝采样 SFT 把探索成果变成密集标签.

蒸馏学生时只用 SFT, 它学到的是教师筛选分布的近似. 学生容量较小时, 无法复现全部轨迹, 交叉熵会优先拟合高频局部模式. 数学专用 Qwen 底座已经有符号和题型表示, 因而 1.5B 也能吸收大量推理格式; 通用能力和世界知识仍受容量与底座限制.

若让蒸馏模型再做 RL, 理论上可修正教师偏差并适应自身策略. 风险是小模型探索能力不足, 奖励优化破坏已经学到的轨迹. 一套有意义的对照需要从同一蒸馏 checkpoint 出发, 扫描较小 RL 预算, 观察 pass@1、pass@k 和通用能力, 而非直接与从 Base 做一万步的 Zero 模型比较.

## 20. R1 结论的强弱分层

可以直接确认的是: V3-Base 在不经过推理 SFT 的条件下, 用规则奖励 GRPO 训练后, 数学基准与回答长度显著提高; 加入 cold-start、多阶段 SFT/RL 后, 可读性与综合能力更好; 强模型生成并筛选的轨迹能有效蒸馏到多个小底座.

需要限定条件的是: 长推理带来更多测试时计算, 但长度本身不保证有效; 规则奖励降低判分噪声, 但只验证终点或测试覆盖; GRPO 省去 critic, 信用分配仍停留在序列级; 蒸馏在报告配方下优于小模型直接 RL, 尚未完成等计算预算比较.

证据仍不足的强主张包括: RL 从底座采样分布之外创造全新推理能力; 单个「顿悟」样例代表训练中发生离散相变; 可验证任务上的成功会自然迁移到开放写作与所有语言. 这些问题都可以继续实验, R1 报告提供了重要起点, 没有替读者完成全部因果识别.

## 21. GRPO 估计量的偏差与方差

组内均值是随样本共同变化的基线. 对第 $i$ 个回答, $A_i$ 的分子包含自己的奖励, 因而基线与该样本相关. 若不用留一法均值, 单个奖励对自身优势的系数是 $1-1/G$, 对其余样本各贡献 $-1/G$. 组越小, 自相关越明显; 组越大, 组均值更接近该问题在旧策略下的期望奖励.

除以组内标准差让不同难度题的优势尺度接近, 也会放大小方差组的噪声. 奖励为 $(1,1,1,0.99)$ 时, 那个略低样本得到显著负优势, 其余得到小正优势, 尽管绝对质量几乎相同. 稳定项 $\epsilon$ 可限制放大, 具体取值影响低方差题的权重. 报告没有公开这一实现细节.

同组回答也并非独立. 它们来自同一问题、同一旧策略, 常共享开头和错误模式. 有效样本量小于 $G$. 若两两奖励相关系数近似为 $\rho$, 组均值方差大致乘上 $1+(G-1)\rho$. 当 $G=16,\rho=0.2$ 时, 方差相当于独立情形的四倍. 提高组大小仍有收益, 却远小于独立公式预测.

优势在组内求和为零, 一个样本的相对提升必然对应其他样本的相对下降. 对全都很好的回答, GRPO仍会压低较弱者; 对全都很差的回答, 也会抬高「最不差」者. 参考策略 KL 和规则奖励绝对水平共同阻止策略只做相对游戏. 若奖励方差来自判分噪声, 组内排序会把噪声直接变成梯度.

回答长度平均又产生一种权重差异. 同样优势下, 短回答每个 token 获得的平均梯度份额更集中, 长回答的信用被摊薄. 若去掉长度平均, 长回答因 token 多主导 batch. 两种选择都带偏好. 可按长度桶报告每 token KL、策略梯度范数与成功率, 判断训练是否暗中偏爱某一长度.

## 22. cold-start 的因果链

R1-Zero 的可读性问题包括语言混杂、段落组织松散和答案边界不稳定. cold-start 同时改变了三件事: 给出统一模板, 展示自然语言推理风格, 提供少量正确长轨迹. 完整 R1 比 Zero 更易读, 无法仅凭端点判断是哪一项起作用.

可以把冷启动数据拆成三个对照. 格式组只统一标签与答案区域; 风格组保留原解法, 只人工改写语言; 能力组加入更强解法但不润色. 格式成功率、语言一致率和数学准确率分别测量. 若风格组改善可读性而准确率不变, 因果关系较清楚; 若能力组提高早期 RL 有效组比例, 它主要帮助探索.

语言一致性奖励又叠在第一轮 RL 中, 所以 R1 的可读性提升来自 SFT 与奖励共同作用. 要分开二者, 应从同一 cold-start checkpoint 分别运行有无语言奖励的 RL. 报告说明加入语言奖励略伤准确率, 支持两项目标存在张力, 没给出完整权重扫描.

冷启动还会缩小策略熵. SFT 让模型集中到示范风格, 可能减少 R1-Zero 那种自由探索. 若成功轨迹更常见, 熵下降有利; 若示范覆盖窄, 稀有但有效的策略可能被压低. 比较 cold-start 前后的轨迹聚类数和大 $k$ pass@k, 可以看到可读性换走了多少多样性.

## 23. 验证器塑造了什么数据

拒绝采样只保留验证器接受的回答. 数学验证器偏爱可规范化的短答案, 代码验证器偏爱通过现有测试的实现. 开放证明、等价形式和不常见语言若难解析, 即使正确也会被系统性删除. 这种选择偏差会在 SFT 后变成模型偏好.

设真实正确性为 $Y$, 验证器接受为 $V$. 保留数据中的真实正确率取决于验证器精确率 $P(Y=1\mid V=1)$, 覆盖率取决于召回率 $P(V=1\mid Y=1)$. 高精确率保证少喂错误, 低召回率仍会让正确策略种类变窄. 报告强调规则奖励可靠, 没有给解析器的精确率、召回率和等价答案误拒率.

题目选择也会偏移. 能采到正确答案的题进入数据, 零成功题消失; 学生看到的是教师能力范围内的条件分布. 难题即使留下, 每题正确轨迹数也少. 若按轨迹均匀采样, 容易题权重更大; 若按问题均匀采样, 每题贡献相同但难题轨迹多样性更低.

验证器还可能与评测共享形式. 训练中大量使用竞赛数学的答案规范和代码测试, AIME、MATH、LiveCodeBench 的输出形式与之接近. 提升既包含推理能力, 也包含熟悉判分接口. 换成需要完整证明、交互式调试或不同答案语法的任务, 能检验迁移程度.

## 24. 多阶段训练与遗忘

第一轮 RL 把策略推向长推理, 随后的 80 万条 SFT 同时包含推理与普通数据. SFT 会提升格式稳定性, 也可能把 RL 探索出的低频策略拉回教师数据的高频模式. 这属于分布覆盖造成的遗忘: 数据里没出现的行为会在交叉熵更新中相对降概率.

第二轮 RL 从 SFT checkpoint 再出发, 让规则任务重新按结果优化, 同时加入帮助性与安全偏好. 它可以恢复被 SFT 削弱的成功轨迹, 并让通用回答适应人类偏好. 也可能产生新的覆盖: 有用性奖励训练过久时分数上升、Codeforces 下降, 报告据此把偏好 RL 限制在收尾数百步.

要量化遗忘, 每个阶段都应在同一套推理、知识、写作、语言一致性和安全集上评测. 只比较 Base、Zero、最终 R1 会漏掉冷启动后、第一轮 RL 后、第二次 SFT 后的回落与恢复. 报告给出部分 Dev checkpoint 结果, 尚未形成完整能力矩阵.

参数距离不能代替行为遗忘. MoE 中只有被路由到的专家得到大量梯度, 某领域 SFT 可能集中更新少数专家; 另一领域能力因共享注意力或路由变化受影响. 记录各专家选择分布与层输出变化, 才能判断遗忘发生在知识参数、路由还是回答策略.

## 25. 蒸馏覆盖与学生上限

教师生成数据覆盖的题型决定学生看见哪些推理算子. 若 60 万条轨迹都集中在代数与竞赛技巧, 学生在这些领域可接近教师, 对开放科学推断未必迁移. 数据条数很大, 题目与策略的有效多样性可能远小于条数.

学生上限也受底座影响. 数学版 Qwen 已在预训练中学习大量公式与题型, 蒸馏主要教策略组织; 通用 Llama 起点不同. 表中跨底座、跨规模分数不能只拟合一条参数量曲线. 32B Qwen 超过 70B Llama 的若干数学成绩, 说明领域底座与分词、预训练数据同样关键.

教师轨迹越长, 学生越可能在中途偏离 teacher-forcing 分布. 训练时每一步看到正确前缀, 推理时看到自己的前缀, 一个早期错误会累积. 仅用序列交叉熵无法纠正这种暴露偏差. 学生蒸馏后再做少量 on-policy RL, 理论上能在自身分布上修正, 报告没有系统给出该组合.

学生超过教师某个单项也不矛盾. 底座原有能力、采样方差和蒸馏数据筛选都可能让学生在特定 benchmark 得分更高. 真正的教师覆盖上限指策略与知识来源, 不是每张小表上逐项严格低于教师. 要证明超越, 应在教师大量采样仍失败的新题上稳定成功.

## 26. 评测可比性的细节

pass@1 会随温度变化. 贪心近似选择最高概率轨迹, 温度 0.6 或 0.7 会增加探索, 多次采样平均又不同于一次确定输出. 两个模型若使用不同温度、最大长度或答案提取器, 分数差可能来自协议. R1 报告对 AIME 等小集合采用多次采样平均, 横向表中的外部数字仍可能来自不同 harness.

AIME 只有 30 题. 单次多答对一道就是 3.33 个百分点; 取多次采样平均降低生成随机性, 不增加题目数量, 题集抽样误差仍在. 72.6 与 70.0 这类差异若没有跨年份或更多题验证, 不宜过度排序.

污染检查能搜索与评测题相似的训练文本, 很难排除改写、答案泄漏和同源题. R1 的 80 万条数据由模型生成, 提示题库来源未完整公开. LiveCodeBench 用时间窗口降低公开训练污染, 教师模型或数据管线是否接触题目仍需截止日期和日志支持.

多数投票还依赖答案归一化. 同一个数学值写成不同形式, 若解析器没合并, 正确票会被拆散; 错误答案若共享常见格式, 可能形成多数. cons@64 因而同时测推理分布与答案聚合器. 报告中的相同解析协议可用于内部比较, 跨论文数字要核对实现.

## 27. 表格数字还能算出什么

R1-Zero 在 AIME 2024 从训练早期约 15.6% 升到 71.0%, 相当于期望答对题数从 4.7 增到 21.3. 完整 R1 pass@1 为 79.8%, 约 23.9 题; 相对 Zero 多约 2.6 题. 在仅 30 题的数据上, 完整流水线相对纯 RL 的差距没有百分数看起来那么大, 可读性和通用能力才是 cold-start 的主要额外价值.

Distill-Qwen-1.5B 的 AIME 28.9% 约为 8.7 题, 32B 的 72.6% 约为 21.8 题. 参数增大约 21 倍, 期望多答对约 13 题. 增长并非线性, 也混有数学底座差异. MATH-500 样本更多, 83.9 到 94.3 对应约 52 道题差, 在统计上比 AIME 的一两题差更稳定.

Qwen-32B-Zero 的 AIME 47.0 对蒸馏版 72.6, 约差 7.7 道题; LiveCodeBench 40.2 对 57.2, 差 17 个百分点. 这说明蒸馏优势跨数学和代码出现, 不只是一张小题集波动. 由于训练预算与数据不同, 数字支持「当前蒸馏配方更有效」, 不支持算法固有上限排序.

越狱中无风控不安全率从 25.2% 升至 85.9%, 相对增长超过三倍; 加风控降至 4.3%, 同时 87.3% 请求被拒. 安全收益主要由外部风控换来, 可用性代价很高. 本地开源权重没有这层系统, 模型自身的安全水平应看无风控列.

## 28. 纯 RL 的探索动力学

R1-Zero 开始训练时, 一道题能否产生梯度取决于同组回答有没有奖励差异. 设单次成功率为 $p$, 组大小为 $G$, 至少一对样本奖励不同的概率是

$$
P_{mix}=1-p^G-(1-p)^G.
$$

$p$ 接近 0 或 1 时, $P_{mix}$ 都很低; $p=0.5$ 时最高. 这给出纯 RL 的自然课程: 太难的题全错, 太易的题全对, 能推动策略的是当前边界附近的题. 随模型提升, 原本困难题进入混合区, 原本边界题逐渐全对. 若题库难度范围不够宽, 有效组比例会先升后降.

探索还受回答分布熵控制. 高温增加不同路径, 让稀有正确轨迹更可能出现, 也提高乱码、格式错误和无意义长文本的比例. 低温保证连贯, 多个样本却高度相关. 理想温度随能力变化: 早期需要探索, 后期需要稳定地强化有效轨迹. 报告提到部分阶段从温度 1 调到 0.7, 没给完整日程与对照.

格式奖励提供早期密集信号. 模型即使答错, 只要按 `<think>` 与答案模板输出也能获得部分奖励, 组内因此不至于全部相同. 它帮助策略进入可解析区域, 同时可能形成投机: 写出正确标签、堆叠反思短语、把答案藏在解析器容易捕捉的位置. 准确奖励变强后, 格式应退居约束角色. 若格式权重长期过大, 模型会优先维护外壳.

格式退化有两种方向. 奖励太弱时, 长推理逐渐混杂语言、遗漏结束标签, 正确答案也无法解析; 奖励太强时, 模板本身占据生成概率, 内容变得刻板. 可分别统计标签成功率、答案解析率、人工可读性和准确率, 扫描格式权重. 单一总奖励曲线看不出二者的交换.

## 29. 语言一致性奖励的梯度冲突

设准确奖励目标为 $J_a$, 语言一致目标为 $J_l$, 混合梯度为

$$
g=\nabla J_a+\lambda\nabla J_l.
$$

两梯度内积为正时, 更新同时改善准确率与语言; 内积为负时发生冲突. 某些数学术语和代码标识天然跨语言, 强制单语可能让模型改写熟悉表达, 负内积更常见. 报告观察到语言一致性提升伴随少量准确率损失, 与平均冲突相符.

冲突并非每个 token 相同. 自然语言连接词适合受一致性奖励, 公式、变量和代码片段应豁免. 若奖励只按整段语言比例评分, 一段必要英文术语可能让所有 token 得到较低优势. 更细的掩码或分段评分可减少误伤, 论文没有披露语言判定器与权重.

多目标训练还存在尺度问题. 准确奖励常为 0/1, 语言分数可能连续且方差更小. GRPO 会在组内标准化总奖励, 权重 $lambda$ 对排序的影响取决于两项分布, 不能只看数值大小. 应报告加入语言项后有多少样本对发生排序翻转, 这比平均奖励更直接.

一种可验证做法是投影冲突梯度: 当 $\nabla J_a\cdot\nabla J_l<0$ 时, 去掉语言梯度在准确梯度反方向的分量. 若可读性维持、准确率损失缩小, 说明问题确实来自梯度冲突; 若无改善, 可能是策略空间本身难以同时满足两项目标.

## 30. 可验证任务与开放任务

数学短答案和代码测试适合规则奖励, 因为判分器成本低、结果相对客观. 形式证明只有在证明检查器可运行时才同样可靠; 自然语言证明即使结论正确, 中间有效性也难自动核验. 科学问答若有唯一答案可用结果奖励, 开放假设生成则没有单一真值.

写作、建议和角色扮演依赖上下文偏好. 奖励模型可把人工偏好推广到新样本, 也会偏爱长度、语气和熟悉立场. 策略持续优化后会找到裁判漏洞, Figure 6 中偏好奖励上升而 Codeforces 下降就是分布外代价的信号. 因而 R1 把开放任务 RL 限制在很短阶段, 主要靠人工核验 SFT 塑形.

两类任务之间存在过渡区. 代码风格、算法复杂度、可维护性无法只靠测试; 数学解释的清晰度也不是答案匹配能判断. 可组合硬奖励与模型奖励, 前者守住正确性, 后者改善表达. 权重不当时, 模型可能用漂亮解释掩盖错误, 或只输出最短可验证答案. 应把正确性和表达分开报告.

工具使用为开放任务提供新的可验证信号: 搜索后引用是否存在、计算器结果是否一致、代码是否执行成功. R1 报告明确说模型不能调用工具, 所以这些奖励渠道尚未进入其训练. 后续 Agent RL 扩展了可验证范围, 不能倒推为 R1 已具备相同能力.

## 31. 小样本评测的方差

AIME 有 30 题. 若把每题看作独立伯努利试验, 准确率估计 $\hat p$ 的标准误差约为

$$
\operatorname{SE}=\sqrt{\frac{\hat p(1-\hat p)}{30}}.
$$

当 $\hat p=0.8$ 时, 标准误差约 7.3 个百分点, 正态近似 95% 区间约为正负 14.3 点. 题目并非从统一总体随机抽取, 这个区间只提供数量级, 已足以说明相差两三点不稳定.

多次采样取平均降低的是解码随机方差. 同一道题跑 64 次, 可以更准确估计模型对该题的成功概率; 题目仍只有 30 道, 题集构成的不确定性没有消失. 把 30 乘 64 当作 1920 道独立题会严重低估区间, 因为同题样本共享难度和解法结构.

比较两个模型时, 最好使用配对统计: 记录每道题两者成功概率之差, 观察优势是否遍布题目, 还是集中在一两道. 若 R1 多答对的题恰好都属于某个知识点, 换一年赛题排名可能改变. AIME 2024、2025 与更多竞赛集共同报告, 证据会更稳.

pass@64 又引入估计上限. 每题只要一次成功就记 1, 对 $p=0.05$ 的题, 理论 pass@64 已约 96.2%; 它很快饱和, 难以区分中等概率模型. pass@1、cons@64 和 pass@64 组合起来, 才分别呈现默认成功率、多数稳定性与候选覆盖.

## 32. 多阶段状态转移

整条路线可以写成六个策略状态:

$$
\pi_{V3B}\xrightarrow{\text{规则RL}}\pi_{Zero},\qquad
\pi_{V3B}\xrightarrow{\text{cold-start SFT}}\pi_C
\xrightarrow{\text{推理RL}}\pi_R
\xrightarrow{\text{拒绝采样+通用数据SFT}}\pi_S
\xrightarrow{\text{综合RL}}\pi_{R1}.
$$

$\pi_{Zero}$ 是旁路线, 用来证明无 cold-start 时规则 RL 也能提升推理; 正式 R1 没有从 Zero checkpoint 直接继续. cold-start 数据会借鉴 Zero 输出并人工改写, 信息通过数据进入 $\pi_C$, 参数路径仍从 V3-Base 出发.

$\pi_C$ 提供可读格式和初始成功轨迹; $\pi_R$ 扩大规则任务能力; 从 $\pi_R$ 采样并筛选得到数据集 $D_R$, 与通用数据 $D_G$ 混合训练出 $\pi_S$; 综合 RL 再把推理、帮助性和安全偏好合入 $\pi_{R1}$. 每个箭头都有可能提升目标能力并损伤其他能力.

这个图式澄清了一个常见混淆: 80 万条数据来自第一轮 RL 后策略, 不是训练开始前固定准备; 蒸馏小模型使用的是这批数据, 没有复制完整多阶段 RL; R1-Zero 也没有经历拒绝采样 SFT 和第二轮偏好 RL. 三种模型的训练信号不同, 不能仅按底座规模解释差异.

要定位贡献, 需要保存并评测 $\pi_C,\pi_R,\pi_S$ 三个中间点. 如果 $\pi_S$ 推理下降、综合 RL 恢复, 第二轮负责抗遗忘; 如果 $\pi_S$ 已经保持推理, 第二轮主要改善偏好与安全. 报告只公开部分开发版本, 精确贡献仍无法完整复算.

## 33. 学生架构的归纳偏置

Qwen2.5-Math 底座对数学符号、公式和竞赛语料有专门预训练, 同样蒸馏数据下更容易压缩教师轨迹. 通用 Qwen 与 Llama 的分词器、位置编码、指令训练状态不同. 70B Llama 使用 Instruct 起点, 其对话偏好可能限制长推理风格, 也可能改善格式.

模型宽度、深度和注意力结构决定学生能保存多少中间状态. 小模型可能学会常见模板, 在需要同时维护多个分支时失败; 大模型能表示更多策略, 却不保证采样时选择正确分支. 蒸馏曲线同时反映容量与底座归纳偏置, 不能仅用参数量解释.

训练最大长度 32768 也构成上限. 教师超过该长度的轨迹需要截断或过滤, 最长推理行为无法完整传递. 学生评测若允许更长生成, 它也缺少对应监督. 报告未给教师轨迹长度分布、截断比例和各学生实际训练 token 数, 这些缺口影响蒸馏上限判断.

## 34. 无法精确复现的公开缺口

GRPO 侧缺少组大小、裁剪系数、KL 系数、每阶段提示数量、batch、学习率、最大生成长度和完整温度日程. 奖励侧缺少准确与格式权重、语言一致性判定器及系数、第二轮帮助性与安全奖励混合比例. 这些参数会直接改变探索、长度和多目标冲突.

数据侧缺少 cold-start 条数与来源配比、第一轮 RL 题库规模、每题拒绝采样次数、验证器实现、60 万推理样本的领域与长度分布、20 万通用样本的混合权重、去重和污染过滤细节. 外部项目可以复现流程名称, 难以复现数据分布.

系统侧缺少 R1 全流程 GPU 小时、采样与训练资源比例、每阶段墙钟和失败重跑. 长 CoT 使生成成为主要成本, 只给更新步数不足以比较预算. 评测侧部分外部模型数字来自不同接口或报告, 温度和输出上限也需逐项核对.

这些缺口不会抹去公开结果. 它们限定的是复现精度与因果归因: 可以确认多阶段方案达到报告分数, 可以沿用 GRPO与规则奖励的总体方法, 却无法仅凭论文重建一条数值等价的训练 run. 将已公开配方与未公开超参分开, 才能正确评价后续复现的差异.

## 35. 从奖励到行为的因果检查

奖励曲线上升只能说明策略更符合当前判分器. 要证明目标能力提高, 需要一套不参与训练的外部测量. 数学可用不同来源、不同答案格式的新题; 代码可换隐藏测试与人工审查; 语言可读性可由不知道 checkpoint 顺序的标注员盲评. 训练奖励与外部指标同步上升, 才支持奖励捕获了目标能力.

若训练准确奖励上升、外部数学不变, 可能发生题库记忆或解析器投机; 若外部数学上升、语言质量下降, 则是明确的多目标交换; 若两者都升而回答长度暴涨, 还需计算单位 token 收益. R1 报告同时给标准基准、长度曲线和人工可见样例, 证据比单一奖励充分, 仍缺训练题与评测题之间的严格独立审计.

因果检查还应干预行为. 把同一 checkpoint 的最大长度截成 2K、4K、8K、16K, 测准确率是否随预算稳定增加; 删除或替换「等等」「重新检查」等短语, 测结果是否变化; 强制模型用另一种语言推理, 测语言奖励塑造的是表面还是内部策略. 这些干预比相关曲线更接近机制证据.

## 36. 完整的题目级记录表

对每道训练题, 可以记录底座成功率、各阶段成功率、平均长度、轨迹聚类数、验证器接受率与最终是否进入 SFT 数据. 这份记录能回答许多总表无法回答的问题. 若底座从未成功、RL 后稳定成功, 它是能力扩展的强候选; 若底座偶尔成功、RL 只提高频率, 更接近概率重排.

题目记录还能揭示拒绝采样偏差. 零留存题集中在哪些领域, 进入数据的题是否明显更短, 某些答案格式是否被大量误拒, 都可以直接统计. 蒸馏学生后再按同一题目分桶, 可观察学生究竟继承了教师的成功集合, 还是通过底座泛化解决了新题.

对公开论文而言, 完整题目日志可能涉及数据泄漏, 至少可以发布匿名分桶统计: 起始成功率区间、题目长度、领域、留存率与阶段增益. 这样既不暴露训练题, 又能检验「边界题提供主要 RL 信号」和「蒸馏受教师覆盖限制」两项判断.

## 37. R1 与普通指令模型的差别

普通指令模型追求对大多数问题迅速给出有用回答, 长推理模型允许在答案前消耗大量 token 搜索. 两者共享 V3-Base 的知识, 后训练改变默认计算策略. R1 面对简单问题也可能展开长链, 说明它尚未完全学会按难度调节预算.

这一区别影响评测. 只限制相同最大 token, 长推理模型可以使用更多平均计算; 只比较总 token, 短模型可以并行采样更多次. 公平口径取决于使用场景: 单次答案质量比较固定请求, 成本效率比较总生成 token 或延迟, 候选覆盖比较固定采样预算. 报告的主要表偏向单次高预算能力.

R1 的成功说明自回归模型可通过后训练把已有表示组织成长程搜索, 没有证明这种文本内搜索是测试时计算的唯一形式. 外部验证器、树搜索、工具调用与并行候选都能消费额外计算. 报告记录 MCTS 尝试失败, 结论针对当时的价值模型和搜索设计, 不构成所有搜索方法的否定.

## 38. 收束

R1-Zero 回答了一个窄而重要的问题: 强预训练底座在缺少推理 SFT 时, 能否靠可验证结果奖励学会更长的搜索、自检与回退. 公开结果给出肯定答案, 同时暴露语言混杂与可读性问题. 完整 R1 用 cold-start 把策略送入更合适的起点, 用推理 RL 扩展成功轨迹, 用拒绝采样和通用 SFT 固化并混合能力, 再用短程综合 RL 校准帮助性与安全.

这条路线的力量来自信号分工. 规则奖励提供低噪声终点, SFT 提供密集过程标签, 奖励模型覆盖无法写规则的偏好, 蒸馏把昂贵探索变成小模型可学习的数据. 每种信号都有盲区: 终点奖励信用稀疏, 教师轨迹限制覆盖, 偏好模型会被利用, 组内优势依赖采样多样性.

因此最稳固的结论落在可观测行为上: 数学和代码成绩提高, 输出长度增长, 部分轨迹出现有效回溯, 蒸馏学生显著受益. 关于全新能力、顿悟相变和推理本质的说法需要 pass@k、轨迹干预和阶段对照继续验证. 把结果与解释分开, R1 的贡献反而更清楚.

复现时还应保留失败轨迹, 只公开成功样例会遮住探索成本. 同一道题从错误到正确经历多少采样、错误路径是否反复出现、纠错发生在何处, 都能帮助判断 RL 学到的是搜索策略还是答案模式. 成功率给出终点, 失败分布描述策略空间. 两者一起公开, 才能把「模型会做这道题」进一步拆成「默认就会」「多试几次会」与「当前分布完全不会」.

对中间 checkpoint 重复统计, 还能看出能力是逐步扩散到更多题目, 还是少数题目从低概率迅速变成高概率. 后一种现象值得检查是否出现策略跃迁, 同时还需排除学习率切换、数据批次和评测随机性的影响. 训练曲线的拐点只有与题目级行为变化对齐, 才具备机制解释价值.
