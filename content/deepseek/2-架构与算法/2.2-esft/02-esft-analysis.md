# ESFT: 在细粒度 MoE 上只训与任务相关的路由专家

材料是 DeepSeek-AI 与西北大学 2024 年 7 月的论文 *Let the Expert Stick to His Last: Expert-Specialized Fine-Tuning for Sparse Architectural Large Language Models* (arXiv 2407.01906, 18 页, 发表于 EMNLP 2024 主会), 一作王子涵当时在 DeepSeek 实习. 官方代码与 adapter 在 [deepseek-ai/ESFT](https://github.com/deepseek-ai/ESFT). 论文要解决的问题是: MoE 模型做下游定制时, 全参微调 (FFT) 要动 15.7B 参数, LoRA 省参数但效果差一截, 能不能利用 MoE 本身「不同 token 走不同专家」的结构, 只训和任务相关的那几个专家. ESFT 的做法可以压成三步: 用原模型在少量任务数据上前向一遍, 记下每层每个路由专家拿到的门控分数或被选中的次数; 每层按分数从高到低累加, 加到阈值 $p$ 为止, 这些专家设为可训练; 其余专家, 共享专家, 注意力, 门控和 embedding 全部冻结, 然后照常做 SFT. 全文只在 DeepSeek-V2-Lite 一个底座上做实验, 所以下面的数字都要带着这个前提读.

## 1. 从路由访问分布定位待训练专家

**前提: 底座结构与两条路由观察**

**稠密 PEFT 搬到 MoE 上少了什么**

稠密模型的 PEFT 大致分三类: 新增参数 (Adapter, Prompt Tuning), 选择已有参数的一部分来训, 以及低秩更新 (LoRA). 三类方法的显存构成和设计空间见 [4.3 参数高效微调](../../../llm-guide/4-后训练/4.3-PEFT/4.3-PEFT.md). 这些方法在 MoE 上照样能用, 论文的 LoRA 基线就是给除 embedding 和输出头以外的所有矩阵 (包括每个专家的三个投影) 都挂 rank 8 的低秩项. 问题在于它们看不到 MoE 独有的一个维度: 同一层里有几十个专家, 一个任务的 token 只会落到其中一部分专家上. **ESFT 属于「选择已有参数」中的结构化选择, 选择单位是整个路由专家.** 它和稠密模型上按敏感度挑参数的做法区别在于, 选择依据直接取自预训练路由器的输出, 不需要算梯度或 Fisher 信息, 只要一次前向. 代价也由此而来: 选择完全依赖冻结的预训练路由器, 路由器本身对任务的判断不准, ESFT 就选不准. 这一点在第 5.3 节再谈.

**DeepSeek-V2-Lite 的专家配置**

实验底座是 DeepSeek-V2-Lite. 按 [V2 解析](../../1-%E6%A8%A1%E5%9E%8B%E6%8A%80%E6%9C%AF%E6%8A%A5%E5%91%8A/1.3-deepseek-v2/02-deepseek-v2-analysis.md) 附录 B 的配置: 27 层, 隐宽 2048, 第 1 层是稠密 FFN, 其余 26 层是 MoE; 每个 MoE 层有 2 个共享专家和 64 个路由专家, 专家中间宽 1408, 每个 token 选 6 个路由专家, 总参数 15.7B, 激活 2.4B. 论文说「每层 66 个专家」, 是把 2 个共享专家也算进去了, 可供 ESFT 挑选的只有 64 个路由专家. 共享专家加细粒度路由专家这套结构的来历见 [DeepSeek MoE: 共享专家与细粒度路由](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md), MoE 的一般机制见 [2.6 MoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/2.6-MoE.md). 论文式 (4)(5) 写出这一层的输出: $\mathbf h_t^l=\sum_{i=1}^{K_s}\mathrm{FFN}_i^s(\mathbf u_t^l)+\sum_{i=1}^{N}g_{i,t}\,\mathrm{FFN}_i^n(\mathbf u_t^l)+\mathbf u_t^l$. 第一项是 $K_s=2$ 个共享专家, 每个 token 都过; 第二项是 $N=64$ 个路由专家, 门控 $g_{i,t}$ 只在亲和度 $s_{i,t}$ 落进 Top-$(K-K_s)$ 时取 $s_{i,t}$, 否则为 0. 论文里 $K=8$ 包含共享专家, 所以路由部分是 Top-6. 亲和度 $s_{i,t}=\mathrm{Softmax}_i(\mathbf u_t^{l\top}\mathbf e_i^l)$ 是对 64 个路由专家做 softmax, 取 Top-6 后不再归一化 (仓库 `modeling_deepseek.py` 里 `norm_topk_prob` 为假, 缩放系数为 1), 所以一个 token 在一层的 6 个门控值之和小于 1. 这个细节决定了第 2.2 节里两种分数的阈值口径不同.

按 SwiGLU 三个矩阵算, 一个路由专家有 $3\times2048\times1408\approx 8.65$M 参数, 26 层 $\times$ 64 个是 14.4B, 占总参数的 92%; 共享专家 $26\times2\times8.65$M $\approx 0.45$B; 剩下约 0.85B 是注意力, 门控, embedding, 输出头和第 1 层稠密 FFN. 这个拆分和表 3 的可训练参数列逐行对得上: 只训共享专家是 450M, 共享专家加非专家参数是 1.3B, ESFT 选中的路由专家平均 1.4B, 合起来 2.7B. 1.4B 除以 8.65M 约 162 个专家, 摊到 26 层是每层约 6.2 个, 占 64 个路由专家的 10% 左右. 实验用的「原始模型」(vanilla) 并非开源的 V2-Lite-Chat, 是作者在剔除数学和代码数据的对齐集上重新训的 checkpoint, 目的是把数学和代码能力压在初级水平, 让后续提升看得清楚. 这个 checkpoint 以 `ESFT-vanilla-lite` 的名字放在 Hugging Face 上. 所有方法训练时都按 1:1 混入这份对齐数据.

**平均门控分数与 token 选择比例**

ESFT 给每层每个路由专家算一个与任务的相关性分数, 有两种定义. 平均门控分数 (ESFT-Gate) 是式 (6):

$$
g_i^l=\frac{1}{N_s}\sum_{j=1}^{N_s}\frac{1}{L_j}\sum_{k=1}^{L_j}g_{i,k}^l,
$$

$N_s$ 是采样序列条数, $L_j$ 是第 $j$ 条的长度, $g_{i,k}^l$ 是第 $l$ 层专家 $i$ 在第 $k$ 个 token 上的门控值 (未被选中时为 0). 它回答的问题是: 这个任务的 token 平均分给专家 $i$ 多大权重. Token 选择比例 (ESFT-Token) 是式 (7):

$$
r_i^l=\frac{1}{N_s}\sum_{j=1}^{N_s}\frac{1}{L_j}\sum_{k=1}^{L_j}\frac{\mathbb 1(g_{i,k}^l>0)}{K},
$$

只看专家 $i$ 有没有进某个 token 的 Top-$K$, 进了就记 $1/K$ ($K=6$). 它回答的是: 这个任务的路由选择里有多大比例落在专家 $i$ 上. 由于每个 token 恰好给出 $K$ 次选择, 一层 64 个专家的 $r_i^l$ 之和严格等于 1. 两种分数的差别在于是否看门控大小. 用一个小例子手算: 一层 4 个专家 A, B, C, D, 每个 token 选 2 个 ($K=2$), 省略共享专家, 3 个 token 的门控如下 (数值仅示意): token 1 选 A (0.30) 和 B (0.05); token 2 选 A (0.28) 和 C (0.06); token 3 选 B (0.10) 和 D (0.09). 按式 (6), A 的平均门控是 $(0.30+0.28)/3\approx0.193$, B 是 $(0.05+0.10)/3=0.05$, C 是 $0.02$, D 是 $0.03$, 四者之和只有 0.293. 按式 (7), A 和 B 各被选 2 次, $r=2\times\frac12/3\approx0.333$; C 和 D 各 1 次, $r\approx0.167$, 合计 1. Token 选择比例下 A 和 B 并列第一; 平均门控分数下 A 远高于 B, 因为 B 每次被选中时都排在第二位, 权重很小. 也就是说, ESFT-Gate 偏向「被选中时权重高」的专家, ESFT-Token 偏向「被选中次数多」的专家.

论文没有从理论上说明该用哪一种, 只说按任务实验效果选. 从结果看, ESFT-Gate 专项平均略高 (50.2 对 49.4), ESFT-Token 通用能力保持略好 (61.5 对 60.6), 后者每层选的专家通常也更少 (图 4). 仓库的实现在序列长度上与公式稍有出入: 脚本把所有 token 的门控直接加总, 再除以 token 总数, 是按 token 平均; 式 (6)(7) 先在每条序列内平均再跨序列平均. 采样序列等长时两者相同, 不等长时长序列权重更大. 这一点有人在 GitHub issue #17 提过, 没有得到回复.

### 1.2. 累计阈值 p: 每层选几个由分布决定

有了分数, 每层单独选专家. 式 (8) 要求选出的集合 $E_s^l$ 满足 $\sum_{i\in E_s^l}R_i^l\geqslant p$, 其中 $R_i^l$ 取 $g_i^l$ 或 $r_i^l$. 仓库 `generate_expert_config.py` 的实际做法是按分数降序逐个加入, 每加一个累加一次, 累计值第一次达到 $p$ 就停. 所以 $E_s^l$ 是满足式 (8) 的最小前缀集合, 一层选几个专家由这一层分数分布的陡峭程度决定: 分布越集中, 少数几个专家就能凑够 $p$. 阈值的口径在两种分数上不同. Token 选择比例每层和为 1, $p=0.2$ 就是「覆盖本层 20% 的路由选择」. 门控分数每层的和小于 1, 用仓库公开的 `summary.json` 算, 意图, 法律, 摘要三个任务各层 $g_i^l$ 之和在 0.26 到 0.48 之间. 论文默认 ESFT-Gate 取 $p=0.1$, 相当于本层门控总量的 20% 到 40%, 不同层的实际覆盖比例并不一样. 论文 §3.3 把 $p$ 描述成「总相关性分数的比例」, 对门控分数不成立. 一作在 GitHub issue #8 里解释过这是有意不做层内归一化: $p$ 在所有层共用, 不归一化能让各层按同一个绝对尺度比较. 这个口径带来的直接后果在图 6 里看得到: ESFT-Gate 取 $p=0.4$ 时平均每层选了约 64 个专家, 已经是全部路由专家, 因为多数层的门控总量本身就不到 0.4.

**冻结了什么, 训练时梯度怎么流**

选好专家后, 仓库用 `esft.py` 里的 `to_esft` 改造模型: 把所有不训练的参数从 `nn.Parameter` 改注册成非持久化的 buffer (`persistent=False`), 只把选中路由专家的权重留作参数. 默认配置下, 门控向量 $\mathbf e_i^l$, 注意力, 共享专家, embedding 和输出头都变成 buffer. 这样做有两个直接效果: 优化器只看得到选中的专家, 梯度和优化器状态只为这部分参数分配; 保存 checkpoint 时 buffer 不写盘, 存下来的就只有被训练的专家, 这是「adapter」体积小的来源. 推理时 `add_adapter` 把这些专家的权重加载回原模型对应位置.

**门控冻结意味着路由在整个微调过程中不变: 同一个 token 训练前后进入同一组专家, 只有部分专家的权重发生更新.** 被选中的专家只能从路由到它的那些 token 拿到梯度, 没路由到它的 token 对它没有贡献; 没被选中的专家照常做前向, 也照常把梯度往下传给更早的层, 只是自己的权重不更新. 附录 E 的图 9 用 $p=0.2$ 的 ESFT-Token 做了统计: 所有 (token, 专家) 选择中约 20% 落在可训练专家上, 颜色最深的 token 是意图任务里的「意图」, 法律任务里的「原告」「被告」, 数学任务里的数字, 代码任务里的关键字和注释. 也就是说, 训练信号集中在任务特有的那部分 token 上, 通用 token 主要走冻结的专家, 这是通用能力掉得少的直接原因.

训练配置按论文 §4.3 和仓库 `configs/base.yaml`: batch 32 (8 卡, 每卡 1 条, 梯度累积 4), 序列长 4096, 最多 500 步, 每任务约 $500\times32\times4096\approx6.6\times10^7$ 个 token; ESFT 学习率 1e-5 常数, 无 warmup, weight decay 0.1, Adam 的 $\beta_2=0.95$. FFT 和 LoRA 的学习率分别是 3e-5 和 1e-4, 三者都在 {1e-5, 3e-5, 1e-4, 3e-4} 上搜过. ESFT 的学习率最小, 和它只动少数专家, 每个专家只见到一部分 token 的设定相符. 训练数据里提示词部分的 label 被置为 -100, 只在回答上算损失; 但打分阶段的前向用的是完整对话, 提示词 token 也参与了专家打分.

**结果: 专项能力与通用能力**

**任务, 基线与评测口径**

任务分两组. 能力增强组是数学和代码: 数学用 MetaMathQA 训练, 在 GSM8K 和 MATH 上评测; 代码用 evol-codealpaca 的 Python 子集训练, 在 HumanEval 和 MBPP 上评测. 原始模型在这两个领域本来有一定水平, 看的是提升幅度. 能力适配组是四个模型原本不会的窄任务: 家电控制指令转 JSON 的意图识别, 客服通话摘要, 婚姻案件判决预测 (三者来自 BDCI-21 赛题, 都是中文), 以及切罗基语到英语的低资源翻译 (ChrEn). 意图识别按精确匹配算分, 其余三个用 gpt-4-1106-preview 对照参考答案打 0 到 10 分, 评分指令见附录 G. 通用能力用 MMLU, TriviaQA, HellaSwag, ARC-Challenge, IFEval, CEval, CLUEWSC 七个基准. 基线是 FFT 和 LoRA (rank 8, scaling 2, 挂在除 embedding 与输出头以外的全部矩阵上). 三种方法都混 1:1 对齐数据, 每 100 步评测一次. 论文没有写上报的是第几步的结果; 仓库 `train.py` 用 `load_best_model_at_end` 按 2% 验证集的 loss 选 checkpoint, 若论文也按这个规则, 选出的是验证 loss 最低的那一步, 未必是评测分最高的那一步. 表 2 的通用能力带 $\pm$, 应是同一方法在六个任务上分别训出的六个模型之间的离散程度, 论文没有写明是标准差还是别的统计量; 附录表 6 中同一行的 $\pm$ 恰好约为表 2 的 2 倍 (FFT 平均 $\pm1.3$ 对 $\pm2.5$, ESFT-Token $\pm1.1$ 对 $\pm2.3$), 两张表的口径也没有交代.

## 2. 专项能力: 接近 FFT, 明显高于 LoRA

表 1 的平均分: 原始模型 33.6, FFT 51.0, LoRA 44.9, ESFT-Token 49.4, ESFT-Gate 50.2. 提升主要来自适配组. 意图识别从 16.8 涨到 FFT 78.8, ESFT-Gate 78.6, ESFT-Token 75.6, LoRA 67.8; 翻译从 14.5 涨到 FFT 38.4, ESFT-Token 36.2, ESFT-Gate 35.2, LoRA 23.1; 法律从 17.1 涨到 ESFT-Gate 49.1, 高于 FFT 的 47.0. 摘要上 FFT 69.4 领先, 两种 ESFT 在 65.4 到 65.8, 与 LoRA 的 64.7 接近. 翻译和意图识别是 ESFT 与 LoRA 差距最大的两项 (13.1 和 10.8 个点), 前者恰好是图 4 里选专家最少的任务. 增强组的情况不同. 数学上 FFT 是 23.4 和 66.4, ESFT-Gate 23.2 和 64.9, ESFT-Token 22.6 和 66.0, LoRA 20.6 和 58.9, ESFT 与 FFT 差距在 1.5 个点以内. 代码上四种方法几乎都没有提升: HumanEval 原始模型 42.1, FFT 仍是 42.1, ESFT-Gate 43.3 是表中最高; MBPP 原始 44.6, 训完后三种方法反而略降 (FFT 42.2, ESFT 41.8 到 42.6), 只有 LoRA 持平. 附录表 9 给出不混对齐数据时的结果: FFT 的 HumanEval 是 51.2, 混入数据后下降 9.1 回到 42.1; 两种 ESFT 不混数据时 HumanEval 都是 42.1, 和原始模型一样. 所以在代码任务上, ESFT 不论混不混对齐数据都没有带来提升, FFT 只在不混数据时有提升. 论文对代码结果没有单独讨论. 摘要和结论里「追平甚至超过 FFT」的说法要看口径. 按表 1 平均分, ESFT-Gate 比 FFT 低 0.8; 不混对齐数据时 (表 9) FFT 是 52.7, 两种 ESFT 是 50.0 和 49.7, 差距扩大到 2.7 以上. 「超过」只在单项上成立 (HumanEval, 法律). 如果把通用能力一起算, 表 3 的「专项与通用平均」一列里 ESFT (55.4) 确实高于 FFT (54.9).

**通用能力: 掉得少, 而且不需要混对齐数据**

表 2 的通用平均: 原始模型 62.4, FFT 58.8, LoRA 59.1, ESFT-Token 61.5, ESFT-Gate 60.6. FFT 掉得最多的是 IFEval (42.5 到 34.2) 和 HellaSwag (74.0 到 67.9); LoRA 掉得最多的是 CLUEWSC (81.5 到 74.3, 且 $\pm7.7$). ESFT-Token 七项里六项与原始模型的差距在 1.8 以内, 只有 HellaSwag 掉 1.7 且离散较大 ($\pm3.6$); ESFT-Gate 的 HellaSwag 是 $68.2\pm9.9$, 是表中最不稳的一格, 说明 ESFT-Gate 在某几个任务上训完后 HellaSwag 掉得很多, 论文没有给出是哪几个. 附录 H 换了一种看法: 在四个适配任务上只用任务数据训练 (不混对齐数据), 再测没训过的数学和代码. 表 8 中原始模型四项平均 40.5, FFT 降到 31.5, LoRA 降到 28.1, ESFT-Token 39.7, ESFT-Gate 39.8, 下降都不到 1 个点. 附录 F 进一步说明混对齐数据对各方法的作用不同, 把表 9 和表 10 的数字整理如下:

| 方法 | 专项 (不混) | 专项 (混 1:1) | 通用 (不混) | 通用 (混 1:1) |
| --- | --- | --- | --- | --- |
| FFT | 52.7 | 51.0 | 58.5 | 58.8 |
| LoRA | 47.1 | 44.9 | 55.0 | 59.1 |
| ESFT-Token | 50.0 | 49.4 | 62.3 | 61.5 |
| ESFT-Gate | 49.7 | 50.2 | 62.2 | 60.6 |

LoRA 靠混数据把通用能力从 55.0 拉回 59.1, 代价是专项掉 2.2; FFT 混数据后通用只涨 0.3, 专项掉 1.7. 两种 ESFT 不混数据时通用能力是 62.3 和 62.2, 与原始模型的 62.4 基本持平, 混了反而降到 61.5 和 60.6. 因此 ESFT 的最好配置是不混对齐数据, 而正文表 1, 表 2 为了统一设置, 给 ESFT 用的是对它不利的混合配置. 对使用者来说这一点有实际意义: ESFT 不需要保留一份对齐数据去做混训, 也不用为每个任务调混合比例. 为什么冻结共享部分就能保住通用能力, 论文的解释在 §6.3: 共享专家和注意力处理每一个 token, 改了它们会影响所有输入; 选中的路由专家只处理被路由过去的 token, 而路由器冻结, 通用 token 不会突然被送进这些专家. 前面图 9 的统计 (可训练专家只占约 20% 的选择, 且集中在任务关键词上) 支持这个解释. 不过路由隔离并不完全, 第 4.2 节表 3 显示只训共享专家 (450M) 时通用能力是 61.2, 只训相关路由专家 (1.4B) 时是 61.5, 参数多 3 倍而通用能力反而更好.

**随机专家与专家粒度**

§6.4 的随机专家消融把相关性分数选出的专家换成随机专家, 每层数量不变. 表 4 给出各任务相对原 ESFT 的变化: ESFT-Token 平均下降 2.8, ESFT-Gate 平均下降 4.4. 翻译降幅最大(-13.5和-20.4),ESFT-Gate的意图与HumanEval分别下降5.0和4.3. 也有几项随机反而略好: MBPP (+0.2 和 +1.6), ESFT-Token 的法律 (+1.3), ESFT-Gate 的摘要 (+0.3). 翻译是路由最集中的任务 (图 2 中头号专家拿 17%), 随机换掉损失最大, 和集中度越高, 选对专家越重要的推论一致. 这个消融只比较了「相关」与「随机」, 没有比较「最不相关的专家」, 也没有和「按全局负载选专家」这类不看任务的启发式比较. 第二个消融回答细粒度为什么是前提. V2-Lite 没有同参数量的粗粒度版本, 论文用模拟: 在对齐数据上统计每对专家同时进入某个 token Top-6 的次数, 得到共现矩阵, 两专家的相似度取各自行向量的余弦; 然后贪心地每次取平均组内相似度最高的 $K$ 个专家成组 ($K=2$ 或 4), 直到分完 64 个. 同组专家共享组内平均亲和度, 整组一起被选中或一起不选, 每个 token 选 1/8 的专家. 组大小为 4 时, 一层相当于 16 个粗专家选 2 个, 与 Mixtral 的 8 选 2 比例接近.

![](./images/p09-chart.jpg)

图注: 横轴是组大小 1, 2, 4, 左轴是 MATH, 右轴是 GSM8K, 深色是 FFT, 浅色是两种 ESFT. 组大小从 1 到 4, FFT 的 MATH 约从 24.8 降到 18.9, GSM8K 约从 68.5 降到 59.5; ESFT-Token 的 MATH 约从 23.6 降到 14.8, GSM8K 约从 67 降到 52.5, 降幅都比 FFT 大. 图 7 解析: 横轴是组大小 1, 2, 4, 左轴是 MATH, 右轴是 GSM8K, 深色是 FFT, 浅色是两种 ESFT. 组大小从 1 到 4, FFT 的 MATH 约从 24.8 降到 18.9, GSM8K 约从 68.5 降到 59.5; ESFT-Token 的 MATH 约从 23.6 降到 14.8, GSM8K 约从 67 降到 52.5, 降幅都比 FFT 大. 原图另一张子图显示可训练专家数 (按原 64 个专家计) 随组大小上升, ESFT-Gate 约从 6.5 升到 11. 图中组大小为 1 的 FFT 点 (约 24.8, 68.5) 与表 1 的 FFT (23.4, 66.4) 不一致, 论文没有说明这组实验的设置.

这个实验有两个解读上的限制. 一是 FFT 自身也随组大小下降约 6 到 9 个点, 说明分组改变了一个已经训好的模型的路由, 分组后的模型本身就变差了, 并不等同于一个从头按粗粒度训练的 MoE. 二是「每 token 选 1/8」与原模型对不上: 原模型 64 选 6 是 $1/10.7$, 组大小 2 和 4 都是选 8 个专家, 激活量比原模型多两个. 论文结论「ESFT 乃至有效的 LLM 定制高度依赖细粒度架构」在方向上可以接受: 粒度越粗, 最小选择单位越大, 凑够 $p$ 需要的参数越多, 一个专家里混杂的任务也越多. 但定量上它是事后分组的模拟, Limitations 一节也承认了这一点.

### 2.2. 训练时间与存储

§5.2 给出六个任务的平均: 训练时间 FFT 28.5 分钟, ESFT-Token 19.8, ESFT-Gate 20.9, LoRA 16.5; 存储 FFT 28.6 GB, ESFT-Token 2.57 GB, ESFT-Gate 3.20 GB, LoRA 在图 5 上接近 0. 时间省 30% 是 $19.8/28.5\approx0.69$ 算出来的平均值, 并非「最多」; 存储省 90% 是 $2.57/28.6\approx0.09$. 存储能从参数量直接推回: 1.4B 参数按 bf16 是 2.8 GB, 约 2.6 GiB; 15.7B 是 31.4 GB, 约 29.2 GiB, 与 28.6 GB 有约 2% 的出入. LoRA rank 8 按前面估算约 0.15B, bf16 约 0.3 GB.

![](./images/p07-figure-5-computational-efficiency-results-blue-bars-show-the.jpg)

图注: 柱是平均训练时间 (左轴, 分钟), 绿线是平均存储 (右轴, GB), 四种方法从左到右按存储递增排列. 时间的差距远小于存储的差距: 存储差了 11 倍, 时间只差 1.4 倍. 图 5 解析: 柱是平均训练时间 (左轴, 分钟), 绿线是平均存储 (右轴, GB), 四种方法从左到右按存储递增排列. 时间的差距远小于存储的差距: 存储差了 11 倍, 时间只差 1.4 倍. 图里没有给显存峰值, 也没有给多卡通信时间的拆分. 时间为什么只省 30%, 可以按前向和反向的计算量估一下 (文中没有给出时间分解, 以下只是从计算结构推出的数量级). 设一次前向的计算量为 $F$, 反向要算对激活的梯度和对权重的梯度, 各约 $F$, 合计 $3F$. ESFT 冻结的层仍要把激活梯度往前传 (更早的层里还有可训练专家), 所以省掉的只是冻结参数的权重梯度; 可训练专家只占约 20% 的路由选择, 权重梯度的计算几乎全部省掉, 总量从 $3F$ 降到约 $2F$, 少三分之一. 仓库开了梯度检查点, 反向时还要重算一次前向, FFT 是约 $4F$, ESFT 约 $3F$, 少四分之一. 实测 30% 落在这两个估计之间. 再往下省就要靠不做前向, 而 MoE 的前向本来就只激活 2.4B 参数, 没有可省的空间. 显存方面, 梯度和优化器状态按可训练参数线性缩放, 从 15.7B 降到 1.4B, 约降到 1/11; 冻结的 14B 参数仍要全量常驻显存, 这一点 ESFT 和 LoRA 一样.

**部署: adapter 是整块专家**

ESFT 的产物是若干个专家的整块新权重, 没有加性的低秩增量. 好处是推理时不增加任何计算: 换进新专家后, 模型结构和激活量与原模型完全相同, 也不需要像 LoRA 那样 merge. 代价在多任务部署上. LoRA 有 S-LoRA, Punica 一类系统, 可以在同一个底座上并发服务上百个 adapter, 因为每个 adapter 只是一个小的加性项; ESFT 的 adapter 是替换专家, 不同任务选中的专家部分重叠 (图 3 里 Code 与 Law 共用约 2 个), 两个任务同时上线时同一个专家位置有两份权重, 路由也要按请求改写. 后续的 [ExpertWeave](https://arxiv.org/abs/2508.17624) (华为, 2025) 专门做了这件事, 在 Ascend NPU 上动态加载各 adapter 的专家并改写路由, 让多个 ESFT adapter 共享一个底座. 存储上的「90%」也要放到规模上看. 在 V2-Lite 上 ESFT adapter 是 2.6 GB, 比 rank 8 的 LoRA (约 0.3 GB) 大一个量级. 若在 671B 的 V3 上按同样比例选 10% 的路由专家, adapter 会有几十 GB, 这是论文没有讨论的方向. 另一个没有讨论的是多任务合并: 两个任务各自训出的 adapter 若有重叠专家, 直接合并会互相覆盖, 论文和仓库都只处理单任务.

**适用边界与可疑之处**

第一个边界是底座. 全部实验只在 V2-Lite 上做, Limitations 里也写明了. V2-Lite 的门控是 softmax 后取 Top-6 不再归一化, 门控值本身带着「路由器有多确定」的信息, ESFT-Gate 正是用这个信息. 之后的 [DeepSeek-V3](../../1-%E6%A8%A1%E5%9E%8B%E6%8A%80%E6%9C%AF%E6%8A%A5%E5%91%8A/1.4-deepseek-v3/02-deepseek-v3-analysis.md) 把亲和度改成 sigmoid, 并在选中的专家之间归一化, 每个 token 的门控和固定; 负载均衡也改成无辅助损失的偏置法, 均衡压力不再进入梯度. 在这类底座上门控分数的含义变了, $p$ 的取值和两种分数的优劣都需要重新确定, 论文没有给出数据. 第二个边界是专家选择完全依赖冻结的预训练路由器. 负载均衡损失会把路由往均匀方向推, 门控分数被拉平后, 集中度判据就弱. 2025 年的 CEFT 工作 (arXiv 2508.19594) 以 ESFT 为基线, 先只训路由器, 看哪些专家在任务上被频繁选中, 再只训这些专家, 在上下文依赖的问答任务和 OLMoE, MiniCPM-MoE 等非 DeepSeek 底座上报告了与 ESFT 持平或更好的结果. 另一面, 路由器冻结也意味着 ESFT 处理不了需要改变路由的情况: 一个任务的 token 如果在原模型里被送到了「错的」专家, ESFT 只能去训那个错的专家.

几处 claim 需要打折扣. 结论说 ESFT「增强了专家系统的专精程度」, 但门控在训练中冻结, 路由分布不会变, 论文也没有测训练后专家的分工有什么变化, 能直接支持的只是「没有破坏原有分工」. §3.2 说图 3 非对角线「接近 0」, 实际有接近 2 的格子. 「追平甚至超过 FFT」只在单项或把通用能力一起平均时成立, 专项平均始终是 FFT 领先. 复现方面, 仓库 issue #22 有人报告直接评测官方 adapter 能对上论文, 从打分到训练整条流水线重跑则差很多; issue #19 里作者说明论文用 2 节点 16 张 A100, 不提供 LoRA 训练脚本. 仓库公开的 translation 任务 `summary.json` 里 token 分数每层之和约为 2.5, 而脚本应当产出 1, 和公开的 `translation.json` 专家配置也对不上, 按公开分数用 =0.2$ 重新选, 第 1 层得到专家 35, 44, 而配置里是 35, 22, 13, 43, 说明打分文件与配置文件出自不同的运行.

## 3. 专家子集选择的优化视角

**把专家选择写成优化问题**

第$l$层有$E$个路由专家,任务数据集为$D$. 冻结底座得到每个token对专家的路由权重$g_{l,e}(x_t)$与Top-k集合$A_l(x_t)$. ESFT先计算任务相关性$r_{l,e}$,再选择子集$S_l$,仅更新$e\in S_l$的专家参数. Gate分数可写为

$$
r^{gate}_{l,e}=\frac{1}{\sum_{x\in D}|x|}\sum_{x\in D}\sum_t g_{l,e}(x_t)\mathbf 1[e\in A_l(x_t)],
$$

Token分数则统计被选比例

$$
r^{tok}_{l,e}=\frac{1}{\sum_{x\in D}|x|}\sum_{x\in D}\sum_t\mathbf 1[e\in A_l(x_t)].
$$

按$r$降序排列后,取最小前缀$S_l$使累计归一化分数达到$p$. 这相当于每层独立求一个覆盖问题:用尽量少的专家覆盖任务路由质量的$p$比例. 专家分布尖锐时集合小,分布平坦时集合大,所以可训练参数量由任务与层共同决定. 选择过程没有用标签梯度,只观察底座路由. 它默认“经常接收任务token”与“最值得为任务改变”正相关. 两者并不等价:某专家可能高频处理通用语法,真正决定标签的低频专家反而排在后面. 梯度敏感度或反事实删除可以检验该假设. MoE层输出写成

$$
h' = h+\sum_{e\in A(h)}g_e(h)E_e(h)+E_s(h),
$$

$E_s$是共享专家. ESFT冻结路由器、注意力、embedding、输出头和未选专家,只让$E_e,e\in S_l$获得权重梯度. 前向仍执行原Top-k专家,包括冻结专家;反向也必须把激活梯度穿过它们传给更早层中被选择的专家. 若当前token没有路由到$S_l$,该层无可训练专家参与,对该层参数的梯度为零. 因此实际更新频率由$S_l$与$A_l(x_t)$交集决定. 选择了十个专家不代表每个batch都更新十个,稀有专家可能长期没有样本. 对选中专家$e$,梯度是

$$
\nabla_{\theta_e}L=\sum_{x,t}\mathbf1[e\in A_l(x_t)]g_e(x_t)J_{E_e}^{T}\nabla_{h'}L.
$$

门控权重同时缩放前向贡献与梯度. 高频但低权重专家在Token分数中显得重要,实际更新幅度较小;Gate分数部分修正这一点,却仍没有考虑$J^T\nabla L$的任务方向. 参数隔离是位置级的. 被选择专家的全部矩阵都更新,其中原有通用能力也可能改变;未选专家保持逐位不变. 只要通用token仍路由到被改专家,遗忘仍会发生. ESFT降低受影响参数范围,没有提供严格功能隔离. 训练目标仍是标准因果语言模型损失

$$
L_{task}(\theta_S)=-\sum_{(x,y)\in D}\sum_{t\in y}\log p_{\theta_0,\theta_S}(y_t\mid x,y_{<t}),
$$

其中$\theta_0$表示冻结参数,$\theta_S$表示选中专家. 冻结本身形成硬约束正则:优化只能在专家子空间内寻找解. 全量微调的可行更新空间维数约等于全部参数,LoRA把每个目标矩阵限制在低秩增量,ESFT则保留少数专家的完整矩阵自由度. 它的归纳偏置是“任务能力已经落在某些专家中,需要沿这些专家的高维方向调整”. 对需要细致改变少数专家的任务,这比给全模型铺低秩增量更合适. 可加入保持底座行为的蒸馏项

$$
L=L_{task}+\lambda E_{z\sim D_{retain}}D_{KL}(p_{0}(\cdot|z)\|p_{S}(\cdot|z)),
$$

但论文强调ESFT不混通用对齐数据,实验也未使用该项. 因而通用能力保持来自冻结范围与路由稀疏性,不能归因于显式抗遗忘目标.

### 3.1. 路由稳定与训练后行为

路由器冻结意味着同一隐藏状态下Top-k规则不变,隐藏状态却会因前层专家更新而变化. 后层路由输入因此可能漂移,后层实际专家频率并非严格固定. 论文用训练前分数选专家,没有在训练中重新选择. 设第$l$层路由logit间隔为$m_l=z_{(k)}-z_{(k+1)}$,前层更新导致logit扰动$\delta z$. 当$\|\delta z\|_\infty<m_l/2$时Top-k集合稳定;margin小的token容易换路由. 可按层测训练前后的Top-k Jaccard与margin分桶,判断“冻结router”到底保留了多少路径. 路由漂移可能带来正迁移:更新后的表示更容易进入适合任务的专家. 也可能让预选专家失去流量,可训练参数后期收不到梯度. 训练中记录选中专家覆盖率$P(A_l(x)\cap S_l\ne\varnothing)$即可观察. 推理时模型结构和Top-k数量不变,单请求FLOPs与底座相同. 若部署按任务替换专家权重,路由器仍可能把通用请求送进任务专家. 多租户服务必须按请求绑定adapter版本,否则同一专家槽位无法同时代表多个任务.

通用任务性能变化可分为直接参数漂移、隐藏状态传播和路由切换. 直接项来自通用token激活被更新专家;传播项来自早层输出改变后影响所有后层;路由项来自后层Top-k集合改变. 三者能用逐层替换实验拆分. 若通用数据上专家$e$的激活概率为$q_e$,任务更新幅度为$\|\Delta\theta_e\|$,粗略风险量可写为

$$
R_{forget}=\sum_{l,e\in S_l}q_{l,e}\|\Delta\theta_{l,e}\|_F.
$$

ESFT选择任务相关专家$r$高,若这些专家在通用数据上的$q$也高,遗忘风险仍大. 更稳健的选择分数可以使用$r/(q+\epsilon)$或$r-\alpha q$,偏好任务专用而非全局热门专家. 只看通用benchmark平均分会掩盖局部损伤. 应按领域、语言、长度和路由簇分组,尤其检查与目标任务共享专家最多的通用样本. 共享度越高而跌幅越大,才支持参数重叠导致遗忘的机制解释. 被选专家往往承载相近token或计算模式. 数学微调可能提高使用同一专家的代码和逻辑任务,形成正迁移. 迁移强度取决于输入路由重叠与梯度方向一致性. 两任务$a,b$在层$l$的加权专家重叠可定义为

$$
O_l(a,b)=\frac{\sum_e\min(r^a_{l,e},r^b_{l,e})}{\sum_e\max(r^a_{l,e},r^b_{l,e})}.
$$

再测选中专家梯度余弦$C_l=\langle g_a,g_b\rangle/(\|g_a\|\|g_b\|)$. 高重叠、高正余弦预示迁移;高重叠、负余弦预示冲突;低重叠则接近隔离. 只用专家集合交集无法区分合作与竞争. 迁移实验应在未参与训练的相关任务上测零样本变化,并与随机专家、同参数量LoRA和FFT对照. 若相关任务提升而无关任务稳定,专家专门化解释更可信. 多任务数据混合$D=\cup_jD_j$时,直接对全部token平均会让大数据任务主导$r$. 若各任务token数$n_j$,混合分数是$\sum_jn_jr^j/\sum_jn_j$. 小任务即使路由集中也可能被淹没. 任务均衡分数可用$\bar r_e=\sum_jw_jr^j_e$,令$w_j$按目标重要性而非样本数设定. 也可先为每个任务选$S^j_l$,再取并集. 并集保证覆盖,参数量会随任务数增长;共同阈值更省参数,可能牺牲小任务.

数据采样还影响更新频率. 选择阶段按原始数据统计,训练阶段若重采样类别,实际路由分布会不同. 两阶段应使用同一目标分布或对相关性做重要性加权. 输入模板、system prompt与语言都会改变路由. 用裸任务文本打分、再用长指令模板训练可能选错专家. 选择数据应包含实际部署格式,并报告不同模板下集合稳定度.

**阈值 p 的含义**

$p$控制覆盖的路由质量,不是固定参数比例. 分布熵低时少数专家达到$p$,熵高时接近全选. 可用有效专家数$N_{eff}=\exp(-\sum_e\tilde r_e\log\tilde r_e)$描述集中度. 若相关性近均匀,$\tilde r_e=1/E$,达到$p$需约$pE$个专家;若头部一个专家占0.4,$p=0.5$只需再选少量. 所以跨任务比较$p$必须同时给出每层选中数和参数量. 提高$p$扩大可优化空间,专项性能通常先升后平台,遗忘与存储则单调增加的可能性更大. 最优点应由专项—通用—成本三维Pareto决定,不能只取专项最高. 层级统一$p$也未必最优. 早层路由可能按词形语言分工,后层按语义任务分工;用相同覆盖阈值会在不同层产生不同含义. 可为每层选择$p_l$,在总参数预算$B$下最大化验证收益.

V2-Lite总参数15.7B,每token激活2.4B. ESFT约训练1.4B参数,存bf16权重约2.8GB. Adam若为每个可训练参数保留FP32一阶、二阶与主权重,优化器及主权重约16.8GB,再加bf16梯度2.8GB,仅训练状态约22.4GB;FFT对应约251GB,未计分片. 冻结权重仍需前向并参与激活梯度,所以计算不会按1.4/15.7缩小. 把前向、激活反向、权重梯度各近似为$F$,FFT约$3F$,ESFT约$2F+\rho F$,$\rho$为可训练激活专家占比. $\rho\approx0.2$时理论约2.2F,相对FFT省27%,接近实测. 通信方面,数据并行只需同步可训练参数梯度,字节约按参数比例下降;MoE前向与激活反向的all-to-all不变. 当专家通信占主导,训练加速小于计算估计;当梯度all-reduce占比高,收益更大. adapter磁盘保存完整专家矩阵,无低秩分解. 多任务$M$个adapter且集合无重叠时容量约$M P_S$;重叠槽位虽可共享底座原权重,各任务更新不同,仍需各存一份. 大规模服务的存储与加载成为主要成本.

细粒度专家让选择单位小,能用少量参数逼近任务子空间. 把$K$个细专家绑成组后,选中任一能力都必须更新整组,引入无关参数. 若组内任务相关性方差大,污染更明显. 理想分组应让共同路由且梯度方向相近的专家放在一起. 论文只按路由共现模拟分组,没有利用梯度,并改变了原模型激活结构. 它说明粒度缩粗会损害既有模型,不足以预测从头训练粗粒度MoE的ESFT效果. 共享专家每token都激活,更新它们覆盖面最大,专项收益可能高,遗忘风险也高. 消融中冻结共享参数仍保持较好结果,支持把任务更新限制在路由专家. 对需要改变普通知识表达的任务,共享专家可能不可绕开.

### 3.2. 训练动态

选中专家的batch有效样本数不均. 高频专家每步都有梯度,低频专家隔多步才更新;统一学习率会让后者估计方差更大. 可按激活token数归一化梯度或为专家维护独立学习率,但论文沿用统一训练配置. 负载不均还影响并行效率. 少数被训练专家集中在特定GPU时,权重梯度计算与优化器更新倾斜,其他rank只做前向. 专家并行放置应把被选专家均匀分散,或在训练阶段复制热点专家. 早层更新改变后续输入分布,静态$S_l$可能逐渐失配. 周期性重新打分能适应漂移,集合切换又会让新专家突然加入、旧专家停止. 可用滞回阈值和集合并集控制震荡. 训练日志应记录每层覆盖率、各专家激活token、梯度范数、路由Jaccard和验证损失. 只有总loss无法判断性能来自少数热点专家还是广泛微调.

单adapter部署可直接替换选中专家权重,不增加矩阵乘次数. 若权重常驻,延迟与底座近似相同;从存储按请求加载会产生几十GB级搬运,必须缓存热门adapter. 多adapter同时服务时,同一专家槽位可能有多个版本. 按请求分组后为每组加载对应版本,或将版本分散到不同设备. 路由动态决定实际访问哪些专家,预加载全部选中专家最稳,按需加载会在首次命中产生尾延迟. adapter组合困难来自重叠参数. 两个任务更新同一专家,直接相加权重差没有理论保证;按请求选择其中一份只能实现切换,无法同时获得两种能力. 可在联合数据上重训冲突专家,或保留多个版本并由上层任务路由选择.

底座升级会使专家权重、router与隐藏表示改变,旧adapter通常不能直接迁移. 即使形状相同,旧更新对应的功能子空间也可能消失. 版本元数据必须绑定基础checkpoint和专家编号. 路由不具任务专门化时,$r$接近均匀,达到$p$需选择大量专家,ESFT退化为大范围微调. 负载均衡过强、专家粒度过粗或底座训练不足都可能造成这种情况. 任务需要新路由时,冻结router限制明显. 输入原本被送往不合适专家,训练只能改造这些专家,可能破坏其旧功能. 先训练router再选专家或联合少量router参数能缓解,也扩大遗忘面. 低频关键token会被平均分数忽略. 代码中的稀有运算符、法律任务的特定条款可能决定答案,token占比很低. 按loss梯度或样本级最大贡献打分可以补充频率指标.

跨领域生成需要多种能力协同,固定小集合可能只覆盖主要模式. 翻译兼具语言、知识与格式,数学解释还需自然语言组织. 阈值过低会在复杂请求上出现能力缺口. 数据很少时相关性估计方差大. 不同抽样可能选出不同专家,后续性能波动来自选择而非训练. 应bootstrap数据,报告专家入选频率与结果置信区间. 实验一保持每层专家数相同,比较相关性选择、随机选择、最低相关性选择与全局热门专家. 若任务路由确有因果作用,相关性应稳定胜过后三者,低相关性应最差. 实验二对每个入选专家做单独冻结,测验证loss增量;再对未选专家逐个开放. 相关性排名若有效,前者边际贡献应更大. 用Shapley近似还能测专家交互,避免把冗余专家误判为无用.

实验三扫描$p$,同时画专项、通用、可训练参数、训练时间和adapter大小. 若专项提升来自更大参数量,同参数量随机或LoRA会接近;若来自专家匹配,ESFT应保持优势. 实验四固定训练结果,在通用数据上按是否激活更新专家分组. 遗忘应集中在高重叠组. 若低重叠组同样下降,隐藏传播或评测噪声比直接参数污染更重要. 实验五记录训练前后路由Top-k与margin. 若router冻结足以保持路径,Jaccard应很高;若深层变化明显,静态专家选择需要重新审视. 实验六改变选择数据模板、大小与随机种子. 稳健方法应在合理变化下得到相近集合和性能. 集合极不稳定却分数相近,说明存在多个冗余专家组合.

实验七联合训练两个高重叠任务与两个低重叠任务. 高重叠且梯度冲突的组合应更易负迁移;按任务保留专家版本或梯度投影后若恢复,冲突机制得到支持. 实验八在V2-Lite之外使用sigmoid路由或不同Top-k的MoE,重新校准$r$与$p$. 若原阈值直接迁移失败而归一化排名仍有效,方法的核心是相对专家相关性,具体分数口径依赖路由器.

## 4. 适用边界、训练动态与系统成本

**应怎样读 ESFT**

ESFT利用底座已经形成的专家分工,把任务数据经过router后的访问分布当作参数定位器. 它节省的是权重梯度、优化器状态和adapter存储,前向激活与专家通信仍然存在. 通用能力保持来自有限参数暴露与稀疏路由重叠. 路由冻结降低结构变化,前层表示漂移仍可能改变后层路径. 因而“专家保持本职”是一种有实验支持的倾向,没有形成严格隔离保证. 方法最适合路由集中、专家细粒度、目标任务与底座已有能力对齐的场景. 分布平坦、需要新路由、稀有token关键或多任务冲突时,频率式选择会暴露边界. 评估应把选择质量、优化空间、遗忘位置与部署版本一起看. 只比较最终专项分数,会漏掉ESFT真正提供的参数定位能力以及它对底座专家结构的依赖.

Token分数是Bernoulli均值. 若专家真实激活率为$r_e$,观察$N$个token,标准误差约$\sqrt{r_e(1-r_e)/N}$. 当两个专家分数差小于数倍标准误差时,排名不稳定,阈值边缘集合会随抽样变化. token并非独立. 同一序列中的语言与主题连续,有效样本量小于token数. 应以样本或文档为bootstrap单位,避免把长序列内重复路由当成大量独立证据. 报告每个专家分数区间比只给点估计更可靠. Gate分数还受softmax温度与Top-k截断影响. 所有logit同时缩放会改变权重集中度,即使专家排序不变,$p$阈值选择数也会变化. 使用层内rank或归一化熵能提高跨模型可比性,仍需重新校准阈值. 估计预算有限时,可逐批更新排名,当前缀累计集合连续多轮不变便停止. 分布平坦任务会需要更多数据,这与其选择本身更困难相符. 更直接的任务相关性是冻结底座下专家参数梯度范数

$$
r^{grad}_{l,e}=E_{(x,y)\sim D}\|\nabla_{\theta_{l,e}}L(x,y)\|_F.
$$

它同时考虑激活、门控和标签误差,计算与存储代价远高于路由计数. 可用输出梯度与专家激活的低维近似,或只在少量batch上估计. 梯度范数偏好大矩阵与尺度大的层,需要按参数数或Fisher对角归一化. 另一个指标是一步更新后的loss下降近似$\eta\|g_e\|^2$,但专家间交互会让单独贡献不可加. 反事实分数把专家输出置零或替换为均值,观察$\Delta L_e$. 它测前向因果贡献,不会说明该专家是否容易通过微调改善. 频率、梯度和反事实分别回答“常用”“想改”“当前有用”,三者组合能定位差异. 可证伪比较应给三种方法相同参数预算. 若梯度选择明显优于频率,ESFT的廉价router信号牺牲了选择质量;若接近,路由已经提供足够任务结构.

### 4.1. 预算约束下的层间分配

原方法每层独立用相同$p$,没有显式总参数预算. 设选专家$e$的参数成本$c_{l,e}$,价值估计$v_{l,e}$,可写成背包问题

$$
\max_{S}\sum_{l,e\in S}v_{l,e}\quad\text{s.t.}\quad\sum_{l,e\in S}c_{l,e}\le B.
$$

专家尺寸相同时按价值排序即可;不同层或结构尺寸不同,应按$v/c$权衡. 还需每层最低覆盖,避免预算全部集中在少数层. 早层改变词法表示,影响范围大;后层更贴近输出目标,专项性可能强. 在固定专家数下逐层开放能画出层敏感度. 若后半层贡献集中,统一$p$会浪费早层预算. 层间还存在互补:只训后层可能无法修正输入表示,只训早层又缺少输出映射. 双层或分段组合消融可测非加性交互. 最优集合不一定等于单专家价值最高项的并集. 即使选中参数相同,学习率、步数与正则决定遗忘. 对专家输出的一阶变化

$$
\Delta E_e(h)\approx J_{\theta_e}(h)\Delta\theta_e.
$$

参数范数小不保证功能变化小,Jacobian大的输入更敏感. 在保留集上测输出余弦或KL能直接约束功能漂移. 可加入L2-SP惩罚$\lambda\|\theta_e-\theta_{e,0}\|^2$,使选中专家围绕底座权重更新. 它比普通weight decay更符合防遗忘目标. 论文未使用,可以作为边界实验而非归入原方法. 分层学习率可按通用激活率$q_e$缩放:$\eta_e=\eta/(1+\alpha q_e)$. 全局热门专家更新更保守,任务专用专家允许更大步长. 若通用保持改善且专项不降,说明遗忘风险确与共享使用有关. 冻结router保持原分工并降低不稳定,也锁住错误路径. 只训练router时,参数很少,却可能把任务token导向已有合适专家;随后固定新路由再选专家,形成两阶段方法. router训练容易塌缩到少数专家. 需要负载约束、熵正则或容量限制,这些目标可能与任务loss冲突. 路由改变还会让通用请求路径变化,遗忘从参数漂移扩展为计算路径漂移.

比较应包含冻结router、router-only、先router后专家、router与专家联合四组,保持训练token与参数预算. 记录专项分数、通用分数、负载熵、Top-k变化和溢出率. 若router-only已解决任务,更新专家并非必要. 对V3式无辅助损失偏置路由,选择偏置与训练logit分开. 微调哪个量会产生不同作用:改偏置主要调负载,改logit权重改变内容路由. 不能把V2-Lite结论直接套用. 两个adapter的专家集合$S_a,S_b$不重叠时,理论上可同时装入,但前层表示变化仍可能影响另一任务的后层路由. **参数不重叠不等于功能完全独立.** 集合重叠时,联合目标$L_a+\lambda L_b$对共享专家产生梯度和$g_a+\lambda g_b$. 余弦为负会互相抵消. PCGrad一类投影可缓解,代价是需要同时看到多任务batch. 模块化部署可以为冲突槽位保存多个版本,请求级任务ID选择版本. 这要求专家调度器同时考虑router结果与adapter映射. 一个batch混合多任务时,同一专家编号可能对应多份权重,难以合并为一次GEMM.

可先聚类任务,簇内联合训练一组专家版本,簇间保持独立. 聚类特征应包含路由重叠与梯度相似,单用任务标签可能错过实际共享结构.

### 4.2. 专家并行下的训练成本

专家分布在不同rank,token通过all-to-all送往目标专家. ESFT不改变前向路由,发送token数量与底座相同. 选中专家的权重梯度只在所在rank计算,导致rank间反向工作不均. 设rank$j$承载的可训练激活token为$n_j$,反向阶段完成时间近似$\max_j(a n_j+c_j)$,平均值低无法消除最慢rank. 专家集合若恰好集中在一个rank,训练加速会小于参数比例预测. 重放置专家可均衡训练,却改变部署拓扑与checkpoint映射. 复制热点可训练专家并做梯度同步,增加通信. 对短微调任务,搬运权重的启动成本可能超过收益. 论文给训练总时间,没有拆计算、all-to-all、优化器与数据. profiler消融可确认30%节省来自权重梯度还是通信/实现差异. 错误标签会把梯度写入最常访问专家,污染底座已有能力. 参数范围虽小,影响可能集中且持久. 清洗重要性不因PEFT而消失,甚至选中专家的单位参数梯度更密集.

重复样本会同时扭曲相关性与训练. 某模板重复万次,其路由专家更易入选,后续更新又被同模板主导. 打分前按样本去重或给模板簇等权,能减少格式专家冒充任务专家. 答案token与prompt token是否都用于打分也会改变集合. prompt包含任务说明和示例,答案更接近目标生成. 分别统计prompt、response与loss mask内token,可判断专家选择由输入格式还是输出能力驱动. 长文档任务中背景token占多数,关键问答token很少. 按token平均会偏向阅读通用专家. 可按样本归一化,再让每个样本贡献相同总质量,或对loss位置附近token提高权重. 专项评测需覆盖训练分布内、模板变化、长度外推和相关领域. 只在同模板测试可能奖励格式记忆. 通用评测应包含与目标高重叠领域,才能暴露局部遗忘.

每个配置多随机种子,随机性包括数据顺序、专家选择样本与训练初始化. ESFT选择本身是离散步骤,边界专家变化可能带来比优化随机更大的方差. 参数效率比较保持可训练参数或adapter字节相同. LoRA rank 8远小于ESFT 1.4B时,ESFT胜出不能完全归因于结构选择. 应提高LoRA rank或降低$p$画完整Pareto曲线. 计算效率比较保持实现优化相近. 冻结参数如果框架仍构造梯度缓冲,内存收益会被低估;LoRA若未使用融合kernel,时间会被高估. FLOPs、峰值显存、通信字节与墙钟时间一起报告. 反例一是router与任务标签无关. 随机置换专家编号不影响功能,但若每个token均匀路由,ESFT需要大集合. 在合成MoE中控制路由互信息,可以观察方法收益是否随互信息上升.

反例二是关键能力位于共享专家. 路由专家只处理表面格式,真正推理由共享路径完成. 冻结共享专家会让ESFT上限低于FFT,开放共享专家后专项提升同时遗忘增加. 反例三是任务需要底座从未学到的新符号系统. 原路由没有合适专门化,频率只能找到“被迫接收”token的专家. router与embedding都可能需要改变,ESFT硬约束过强. 反例四是多语言混合. 语言专家和任务专家交叉,目标小语种样本先按语言路由,选中的专家承载大量该语种通用能力. 微调专项任务可能伤害整个语种,英文通用榜却看不出来.

**手算一个选择过程**

某层八个专家归一化Gate分数为$[0.30,0.22,0.16,0.10,0.08,0.06,0.05,0.03]$. $p=0.5$时选前两名,累计0.52;$p=0.8$时需前四名,累计0.78仍不足,还要第五名达到0.86. 阈值从0.5到0.8让专家数从2增到5,并非增加60%. 若另一个任务分布为$[0.15,0.14,0.13,0.13,0.12,0.12,0.11,0.10]$,$p=0.5$需四个,$p=0.8$需七个. 同阈值下平坦任务成本更高,有效专家数也更大. 假设每专家100M参数、20层,前一任务平均每层2个,可训练4B;后一任务平均每层4个,可训练8B. adapter大小和优化器状态相差一倍,所以论文报告平均1.4B不能代表任意任务. 若两个专家分数0.101与0.099,样本误差0.005,排序没有统计把握. 阈值恰好切在两者之间时应把两者同时纳入候选,再用验证集或梯度贡献决胜. 固定底座checkpoint、tokenizer、router实现与打分模板,保存每层原始分数、归一化方式、排序规则和阈值. 分数相同的tie-break也会改变集合,需要确定性定义.

根据集合生成训练掩码后,逐名打印可训练参数并核对总数. 用一次反向检查冻结参数梯度为空,选中但未激活专家梯度也应为空. 优化器只能接收可训练参数,否则仍会分配无用状态. 训练中保存底座哈希、专家集合、超参数和每专家激活统计. adapter checkpoint应只含变化专家及映射,加载时校验专家形状和底座版本. 评测先加载底座建立基线,再逐adapter加载与卸载,确认卸载后输出恢复. 多adapter进程尤其需要这个检查,避免上一个任务的专家残留. ESFT专项平均略低于FFT,通用保持更好,说明限制更新空间形成有效折中. 它在若干任务超过FFT可能来自正则、优化噪声或单次评测波动,不能据此宣布小子空间普遍优于全参数.

随机专家消融明显下降支持选择信号有效,个别任务随机持平说明专家冗余或估计噪声存在. 加入最低相关性与同参数全局热门基线后,因果证据会更完整. 粗粒度模拟同时损伤FFT,说明底座本身依赖细粒度结构. ESFT下降更多符合最小选择单位变大,具体幅度混入了事后改路由的影响. 通用能力没有显著下降是结果亮点,仍需结合评测覆盖与误差条. 未测试领域、语言或共享专家高重叠样本可能存在局部遗忘. ESFT把预训练router当成任务参数地图. 相关性统计负责定位,冻结掩码负责隔离,标准SFT损失负责更新. 方法没有新增推理分支,代价集中在adapter版本管理.

选择质量由路由专门化、数据代表性和阈值决定;优化效果由更新专家的激活频率、梯度方向与层间传播决定;遗忘由通用路由重叠和更新幅度决定. 三部分应分别测量. 与LoRA相比,ESFT沿参数位置稀疏、矩阵内部保持全秩;与FFT相比,它牺牲更新覆盖换取隔离和成本. 这两条轴解释了它为什么能在细粒度MoE上形成独特折中. 方法边界也由同一机制推出:router没有信息时无法定位,任务需要新路径时冻结成为阻碍,多任务重叠时完整专家版本发生冲突. 这些问题需要路由适配、梯度选择或服务层版本化,无法仅调$p$解决.

## 5. Gate、Token 分数与有效证据

**Gate 与 Token 分数何时分歧**

Token分数把每次Top-k命中记为1,Gate分数保留权重. 某专家在90% token上以0.02权重入选,另一个在20% token上以0.3权重入选,Token偏好前者,Gate总质量分别0.018与0.06,会偏好后者. V2-Lite的选中权重没有重新归一化,Gate总和还反映router确定性. 不同样本Top-k权重和变化时,高置信样本对分数贡献更大. Token分数对温度较稳健,但忽略贡献幅度. 若门控权重校准差,高logit不代表专家输出更关键,Gate优势会消失. 可以把某专家输出乘零测loss增量,计算分数与反事实贡献的Spearman相关. 相关更高的方法应更适合选择. 两分数选集的差集尤其有信息. 只被Token选中的专家代表高频弱贡献,只被Gate选中的代表低频强贡献. 分别训练差集并测领域子集,能解释不同任务为何偏好不同方案.

同一数据既选专家又训练参数,会产生选择偏差:偶然高相关的专家被选中,随后在同数据上更容易显示收益. 将数据拆为selection、train、validation三份可避免信息重复使用. selection过小导致集合噪声,train过小降低更新质量. 总数据固定时存在分配权衡. 可在10%、20%、40%选择比例上扫描,若集合很快稳定,剩余数据应留给训练. 交叉选择能充分利用数据:每折用其他折估计集合,对本折训练并合并结果很复杂,因为各折集合不同. 更实际的是多折只用于评估集合稳定,再用全selection确定最终集合. 验证集调$p$也会过拟合. 任务少、候选阈值多时,最优点可能是噪声. 报告完整曲线和误差条比只报最佳$p$可靠.

“专家专门化”不能只由路由频率推出. 可收集每个专家接收token的主题、语言、词性与上下文,训练轻量probe预测属性;probe可分离说明路由包含该信息,仍不证明专家计算不可替代. 替换实验更直接:把专家$e$输出换成同层另一专家、均值输出或零,测各任务loss. 专家专门化应表现为在相关任务上替换损失大,无关任务上小. 微调后再次做替换,若选中专家在目标任务上的不可替代性增加,才支持“专精增强”. router冻结而替换损失增加,说明功能变化发生在专家内部;只看路由分布无法观察这一点. 表示相似度也可追踪. 对相同输入计算训练前后专家输出CKA或余弦,选中专家应在任务token上变化更大,通用token上变化受限. 未选专家理论上参数不变,输入漂移仍会让输出值变化.

MoE训练常给每专家容量限制,路由过载时token被丢弃或转去备选专家. ESFT选择集中专家后,router虽冻结,数据分布专门化可能让若干专家持续过载. 打分若统计路由意图,训练实际执行的专家可能不同. 应区分pre-capacity Top-k与post-capacity dispatch. 相关性最好按实际dispatch统计,否则会选择收到大量意图却因容量没有计算的专家. 论文设置是否发生丢弃需要结合实现检查. 容量因子提高可减少丢弃,增加显存与通信. 训练与推理容量策略不同还会造成分布偏移. 每层报告溢出率、备选路由率和选中集合覆盖,才能判断专家是否真正获得梯度. 热点专家复制能扩容量,多个副本参数需同步. 若副本独立更新,同一逻辑专家会分叉;平均梯度保持一致,增加通信. 短微调中通常先提高容量因子更简单.

### 5.1. 学习率与有效batch

专家$e$每个全局batch只接收$n_e$个token,有效batch随路由频率变化. Adam的二阶矩估计在低频专家上更新稀疏,相邻两次梯度间隔大,偏置校正按全局step可能不匹配有效更新次数. 可为每专家维护激活step计数,只在有梯度时推进优化器状态. 这改变与常规框架的等价性,需实验验证. 更简单的方法是确保每batch包含足够多路由到低频入选专家的样本. 按路由分层采样能提高覆盖,会改变目标数据分布. 对采样概率做重要性权重可以保持无偏,权重方差又可能增大. 低频专家是否值得训练,应结合其边际贡献决定. 梯度裁剪若全局计算,一个热点专家的大梯度会缩小所有专家更新. 按专家裁剪提高独立性,可能破坏层级整体尺度. 两者对稳定与迁移的影响应单独消融.

ESFT选择参数位置,LoRA限制更新秩,两者可以组合:只在相关专家内部训练LoRA. 这样adapter更小,同时保留路由定位;表达能力低于完整专家更新. BitFit或norm微调选择参数类型,也能叠加专家集合. 比较方法时应明确稀疏轴:位置稀疏、低秩稀疏、元素稀疏与激活稀疏解决不同问题. 在相同adapter字节下,专家LoRA可以覆盖更多专家,完整ESFT覆盖更少专家. 前者适合能力分散、每专家只需小修;后者适合少数专家需要高秩改变. 扫描“专家数×rank”二维网格可找边界. 稀疏权重增量也可在选中专家内训练,部署需要稀疏kernel或合并. ESFT完整权重替换推理简单,这是其服务优势的一部分. 相关性通常在单轮任务数据上统计. 多轮对话中历史token与当前任务token混合,路由分布可能被长历史主导. 按全部token平均会选到对话格式或语言专家,忽略当前答案能力.

可仅统计loss mask内答案token,或给靠近生成端的层/位置更高权重. 对需要从历史检索证据的任务,只看答案又会漏掉阅读路径. prompt与response分开选择再取预算化并集更稳妥. 上下文长度改变专家负载,早期短样本打分集合未必覆盖长文本中的位置与主题. 在4K、16K、64K分桶统计集合Jaccard,能测长度稳定性. 多轮部署还会在同一KV cache中跨任务切换adapter. KV由旧专家权重产生,中途替换专家后继续decode会混合两套模型状态. adapter必须在会话开始固定,切换时重新prefill. 安全对齐数据可能路由到广泛通用专家. 只改少数专家可以减少能力损伤,也可能使安全行为只在某些表达下生效. 攻击者换语言、格式或主题后绕到未更新专家,出现路由依赖的安全缺口.

评测应按选中专家覆盖率分桶做越狱与拒答测试. 低覆盖样本若安全率显著下降,说明局部更新不足. 开放共享专家或加入路由训练可能提高覆盖,同时增加通用行为改变. 权限隔离类adapter若按请求加载,服务层必须防止用户选择未授权版本. 专家权重本身可能编码敏感领域信息,卸载后还需清理显存缓存与批处理队列.

**失败后的诊断顺序**

专项不升时先查选中集合覆盖与专家实际梯度. 覆盖低说明选择或路由失配;覆盖高而梯度近零说明门控权重、loss mask或实现有问题;梯度正常仍不升再考虑优化空间不足. 专项上升但通用大跌时,按通用样本路由重叠分桶. 跌幅随重叠增加说明直接污染;各桶都跌说明早层传播、路由漂移或评测实现变化. 训练时间没有下降时,用profiler区分权重梯度、激活反向、all-to-all与优化器. 若通信占主导,减少可训练参数只省状态,不会显著缩短墙钟. adapter加载后结果不符时,核对底座哈希、专家编号、层偏移与router版本. 整块权重形状往往相同,错位加载可能不报错却完全破坏功能.

假设每层64个路由专家,Top-6激活,共27层. 若$p$选择平均6个专家,每层约9.4%,与单token激活比例相同,但集合与每tokenTop-6并不相同. 整个任务可能选择6个固定专家,单token只命中其中一部分. 若单专家约8M参数,27层各选6个得到1.296B,加少量其他参数接近论文1.4B. bf16 adapter约2.6GiB,与报告吻合. $p$使平均专家数翻倍时,adapter和优化器状态近似翻倍. 100个任务各2.6GB需要260GB adapter存储. 若每任务在GPU常驻,不可行;按热度缓存10个约26GB,其余从本地NVMe加载. PCIe 25GB/s理论加载一个约0.1秒,实际还需分发到专家并行rank,冷启动尾延迟明显. 训练侧若ZeRO把22GB左右ESFT状态分到16卡,每卡约1.4GB;FFT约251GB分片后每卡约15.7GB. 权重与激活之外的节省足以扩大batch,这部分可能间接提高吞吐.

### 5.2. 最小充分证据

要证明路由相关性有效,至少需要同参数随机、最低相关与热门专家对照. 要证明抗遗忘来自隔离,需要通用路由重叠分桶与更新幅度控制. 要证明效率,需要参数、状态、FLOPs、通信和墙钟拆分. 要证明细粒度是关键,最好比较从头训练的不同粒度MoE,保持总参数、激活参数和训练数据一致. 事后分组只能提供提示. 要证明可迁移到其他底座,需覆盖softmax、sigmoid、不同Top-k与共享专家比例. 每个底座重新校准分数,同时报告集合熵与成本. 要证明服务优势,应测多adapter并发、冷加载、专家重叠冲突和会话固定版本. 单adapter无额外FLOPs只是部署问题的一部分. 框架中设置`requires_grad=false`仍可能因权重绑定、共享buffer或自定义kernel出现意外更新. 最直接的验收是训练前后逐张量做哈希,未选专家、router、attention与共享参数若配置冻结,哈希必须一致.

混合精度master weight也要检查. 模型bf16张量未变,优化器中的FP32副本若被更新,保存或合并时仍可能覆盖. 优化器参数组应由白名单生成,不能先加入全模型再依赖零梯度. 梯度检查点重算前向时使用相同router决定性设置. 若存在随机路由或dropout,重算路径变化会产生错误梯度. 固定随机状态并比较关闭checkpoint的小batch结果. 分布式训练保存adapter时,每个专家可能分片在多个rank. 汇总必须按专家ID与层号重建,不能依赖当前rank顺序. 重载后用固定输入逐层比较选中专家输出,比只看最终文本更容易发现错位.

**选择集合的几何解释**

每个任务可表示为跨层专家相关性向量$r^a$. 任务间距离$\|r^a-r^b\|$描述router视角下的访问差异. 距离小的任务更可能共享adapter槽位,仍需梯度方向确认是否兼容. 对多个任务相关性矩阵做低秩分解,可以发现语言、代码、数学等公共轴. 专家与任务没有一一对应关系,其功能可以视为多个潜在能力轴的组合. ESFT按单任务阈值切集合,等价于在该向量上做稀疏截断. 截断误差为$1-\sum_{e\in S}\tilde r_e$,正好被$p$控制. 该误差是路由质量遗漏,不等于功能误差. 被遗漏专家可能高度冗余,也可能包含低频关键能力. 因而$p$提供可计算覆盖,最终性能仍需验证. 若相关性向量随层呈现不同簇,统一把所有层专家拼成一个全局排序会偏向权重大或分布尖锐的层. 每层阈值保证层覆盖,代价是无法把预算从无关层转移到关键层. 定义样本$x$在第$l$层的覆盖

$$
c_l(x)=\frac{\sum_t\sum_{e\in A_l(x_t)\cap S_l}g_{l,e}(x_t)}{\sum_t\sum_{e\in A_l(x_t)}g_{l,e}(x_t)}.
$$

总体$p$高不保证每个样本$c_l$高. 大类样本可以贡献大部分质量,小类样本覆盖接近零. 应报告覆盖分位数与最低类别均值. 训练时低覆盖样本主要通过少数层更新,能力上限可能较低. 将低覆盖样本单独加入选择阶段,或约束每个类别最低覆盖,能改善长尾,会扩大集合. 覆盖也可用于动态batch. 把高低覆盖样本混合,确保每步有足够token命中选中专家. 只采低覆盖样本无法凭空产生梯度,需要先调整集合. 推理错误按覆盖分桶后,若低覆盖组显著更差,说明选择遗漏;若所有桶相同,问题更可能来自优化或底座能力.

### 5.3. 更新后的专家是否仍可解释

微调前专家可能表现出领域集中,更新后其输入路由近似不变,功能却可能偏向目标任务. 对同一批探针任务比较前后专家替换损失,能看到专门化方向. 若一个原本负责代码的专家被法律任务选中并更新,代码性能下降、法律上升,说明router相关性可能捕捉到表面符号而非稳定能力. 这种交换在平均通用榜中可能被其他专家补偿. 专家功能标签不应由少量示例命名. 更可靠的是用多任务贡献向量表示,保留连续变化. ESFT之后向量在目标维度上的增量及其他维度的损失构成功能迁移图. 未选专家也可能因输入表示变化而贡献改变,即便权重哈希不变. 功能分析需在固定输入与实际网络输入两种条件下做:固定输入隔离参数变化,实际输入包含层间传播.

假设一台服务节点可留40GB用于adapter,单个ESFT adapter 2.6GB,最多常驻15个,还需预留碎片与加载buffer. 100个任务的长尾请求会频繁换入,命中率取决于热度分布. 若adapter请求服从Zipf分布,前15个任务可能覆盖大多数流量,缓存有效;若任务均匀,命中仅15%,冷加载成为主要延迟. 多adapter可服务性不能只由单adapter推理FLOPs判断. 两个adapter各修改平均1.4B参数,重叠一半时,底座加两份增量需存2.1B独特槽位版本,但同一槽位仍有两个值,无法按参数去重. 只有完全相同的权重块或一个任务沿用底座时可共享. 按请求batch时,不同adapter的同一专家不能合并为普通大GEMM,需要分组GEMM或分批执行. adapter多样性越高,每组token越少,硬件利用率下降. ExpertWeave一类系统工作的核心就在这一服务层矛盾.

专家选择是否稳定,要看bootstrap集合、阈值曲线和模板变化. 参数隔离是否成立,要看逐张量哈希与路由重叠分桶. 专项收益是否来自定位,要看同预算随机和低相关对照. 遗忘是否可控,要看高共享领域、语言和长尾样本,并跟踪专家输出与后层路由. 训练是否省成本,要拆优化器状态、权重梯度、all-to-all与墙钟. 推理是否无成本,要区分单adapter常驻与多adapter动态服务. 这些问题形成一条完整因果链:底座路由提供信号,信号决定参数集合,集合限制梯度,梯度改变专家功能,功能变化经原路由影响任务与通用样本,服务层再负责把正确版本交给请求. 任一环缺少测量,都可能把偶然相关误读成方法优势.

**一个联合诊断例子**

设数学任务在某层选择专家$\{3,7,11,18\}$,累计Gate质量0.82. 训练后专项提高6点,通用数学提高1点,代码下降2点. 路由统计发现代码token有35%质量也落在这四个专家,其他领域不足5%,参数重叠与局部遗忘方向一致. 进一步比较梯度,数学与代码在专家7上的余弦为-0.4,其余三个接近零. 冻结专家7重新训练后,数学只少0.5点,代码跌幅从2点缩到0.3点. 这说明专家7虽路由相关,更新收益有限且冲突显著,频率选择可由梯度冲突修正. 若冻结专家7后数学损失仍大,可为该专家加入保留集KL或较小学习率. 两种处理分别验证“必须更新但要约束”与“可以排除”. 仅把$p$整体调低会同时移除其他无冲突专家,无法精确定位.

部署时数学adapter保留四个专家版本,代码请求仍使用底座版本. 请求级映射能避免代码下降,数学会话中混入代码问题仍走数学版本,局部冲突依然存在. 这说明服务隔离解决租户切换,无法解决单请求内部多能力组合. 该例把相关性、路由重叠、梯度冲突、消融与部署连在一起. 每一步都有可观察量,也给出结果相反时的替代解释,比单看任务平均分更容易判断方法边界.

**与全量微调的上限差距**

令FFT最优更新为$\Delta\theta^*$,ESFT允许的参数子空间投影为$P_S\Delta\theta^*$. 一阶二次近似下,被丢弃方向造成的损失差与

$$
(\Delta\theta^*-P_S\Delta\theta^*)^TH(\Delta\theta^*-P_S\Delta\theta^*)
$$

有关,$H$是局部曲率. 参数范数遗漏很小不保证损失差小,高曲率方向即使幅度小也重要. 随着$p$提高,子空间扩大,理论上更接近FFT可行域;优化噪声与正则效应会让验证分数不单调. ESFT偶尔超过FFT可理解为受限子空间抑制过拟合,训练loss通常仍应不低于充分优化的FFT. 对同一初始化记录训练loss与验证loss. FFT训练loss更低而验证更差支持正则解释;两者训练loss也接近则可能是优化未充分或任务本来只需少数专家. 再比较更新向量投影到选中专家后的残差,可以估计上限差距来自集合遗漏还是训练过程.
