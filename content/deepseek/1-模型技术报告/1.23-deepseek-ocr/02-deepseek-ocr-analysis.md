# DeepSeek-OCR: 用视觉 token 压缩文档上下文

DeepSeek-AI 在 2025 年发布 DeepSeek-OCR 技术报告与代码. 模型由约 380M 参数的 DeepEncoder 和 DeepSeek-3B-MoE-A570M 解码器组成. 报告以视觉文本压缩为核心问题: 含有 $N$ 个文本 token 的页面至少需要多少视觉 token 才能恢复. OCR 同时承担实际文档解析任务和压缩实验的解码器.

报告给出两组核心结果. Fox 的 100 个英文文档页面上, 压缩比低于约 $10\times$ 时解码精度接近 97%, 到约 $20\times$ 时仍约为 60%. OmniDocBench 上, Small 模式只用 100 个视觉 token 就超过使用 256 token 的 GOT-OCR2.0; Gundam 模式少于 800 token, 综合结果优于平均使用约 6790 token 的 MinerU2.0. 两组实验分别回答信息容量边界与实际解析质量, 不能互相替代.

## 1. 光学压缩的计算对象

这里的「压缩比」比较 **文本 token 与视觉 token 的序列长度**, 不代表文件字节压缩率.

**压缩比怎样定义**

报告把压缩比定义为 ground truth 经 DeepSeek-OCR tokenizer 编码后的文本 token 数, 除以 DeepEncoder 输出的视觉 token 数. 若页面有 $N$ 个文本 token, 编码后得到 $n$ 个视觉 token, 则压缩比为 $r=N/n$. 这个比值比较序列长度, 不等同于文件字节压缩率, 也没有计入视觉编码器的计算量.

Fox 实验只选英文部分中 600–1300 文本 token 的文档, 共 100 页. Tiny 模式固定 64 个视觉 token, Small 模式固定 100 个. 600–700 token 区间里, Tiny 的压缩比约 $10.5\times$, 精度 96.5%; Small 为 $6.7\times$, 精度 98.5%. 到 1200–1300 token 区间, Tiny 达到 $19.7\times$ 后精度降至 59.1%, Small 为 $12.6\times$ 与 87.1%.

精度在相邻区间也不完全单调. Tiny 从 800–900 token 的 83.8% 到 900–1000 token 的 85.9% 略有回升, 说明页面布局和字符清晰度会覆盖纯 token 数趋势. Small 在 800–900 与 900–1000 两档同为 96.8%, 到 1000–1100 才降至 91.5%. 因此压缩比是主要解释变量之一, 但不是单页难度的充分统计量.

如果把实验用于自动档位选择, 系统还要先估计页面信息密度. 原始 PDF 若有文本层, 可以直接得到字符或 token 数; 扫描件则必须通过轻量 OCR 或版面特征估计. 估计过低会选到 token 不足的档位, 估计过高则失去压缩收益. 论文按已知 ground truth 分桶, 没有提供线上档位路由器.

这些数字形成一条容量曲线: 视觉 token 数固定时, 页面文字越多, 每个视觉 token 必须承载的信息越多. 曲线同时混入布局复杂度与缩放后的字符清晰度. 较长文档可能有更多栏、表格和公式, 在固定 512×512 或 640×640 画布上还会产生更小的字符. 因此 10 倍是该数据集、tokenizer、分辨率和评价方式下的经验区间, 不能直接当成普适的信息论阈值.

### 1.1. 为什么 OCR 能测视觉表示容量

页面图像先经过 DeepEncoder 映射为潜变量序列, 解码器再生成文本. 若输出能逐 token 恢复 ground truth, 视觉序列就保留了相应文字信息. 与只做分类相比, OCR 要恢复内容, 阅读顺序和部分结构, 对压缩表示的要求更严格. Fox 实验使用 `Free OCR` 提示, 尽量减少布局格式差异对文字恢复的干扰.

报告也指出输出格式无法与 Fox ground truth 完全一致, 所以字符或 token 精度会把格式差异计入错误. 这使结果更适合比较不同压缩档位, 不宜直接解释为纯字符识别上限. 论文没有给语义等价评分, 错误类型或重复采样方差; 60% 精度也不意味着剩余 40% 恰好是可控制的低价值信息.

Fox 表中每个 token 区间的页数并不均衡. 600–700 token 只有 7 页, 700–900 token 各有 28 页, 1200–1300 token 只有 4 页. 越靠近 $20\times$ 压缩的区间样本越少, 59.1% 这一端点的统计稳定性因此弱于中间区间. 报告没有给逐页分数或置信区间, 也没有按布局类型分层. 曲线足以展示精度随压缩比下降的趋势, 不能精确确定一个跨数据集的拐点.

文本 token 数还依赖约 129K 词表的 tokenizer. 同一页内容换用字符级 tokenizer 或另一套子词词表, 分母不变而分子会变化, 压缩比也随之变化. 英文中常见词可能合成一个 token, 数学公式, 生僻字符与多语言文本往往需要更多 token. 因而报告的 $7$–$20\times$ 是 DeepSeek-OCR tokenizer 下的比值, 不是语言无关的固定倍率.

光学表示还有一个额外成本: 文本必须先渲染成图像, 再由视觉编码器处理. 如果原始文本已经以 token 形式存在, 这条路径增加预处理和视觉编码计算. 报告讨论的收益位于后续 LLM 上下文长度和 KV cache, 不能据序列压缩比宣称端到端计算也等比例下降.

**DeepEncoder 怎样控制激活与 token 数**

DeepEncoder 同时控制 **视觉 token 数** 与高分辨率输入产生的激活开销.

**窗口注意力先处理高分辨率输入**

常见视觉编码器有三类限制. 双塔结构需要两套图像预处理并增加流水线复杂度; tile 方法能控制单块显存, 却会把大图切成许多块并产生大量 token; 直接自适应分辨率的方法保留整图, 但高分辨率下全局注意力激活迅速增长. DeepEncoder 的目标是同时支持高分辨率, 较低激活, 少量输出 token 与多分辨率输入.

DeepEncoder 先使用约 80M 参数的 SAM-base 部件. 这一阶段以窗口注意力处理密集 patch, 让大多数注意力计算局限在局部窗口. 若输入网格含 $H\times W$ 个 patch, 全局注意力需要在全部 $HW$ 个位置间计算, 窗口注意力则把计算限制在各窗口内部. 它仍保留高分辨率局部感知, 但不会在最密集的序列上立即执行全局两两交互.

SAM 部件承担字符笔画, 线段和局部布局的感知. 局部窗口也会丢失跨页远距离联系, 因而 DeepEncoder 没有到此结束. 后面的 CLIP-large 部件补充全局交互与视觉知识. 两者不是并行双塔, 图像只走一条串联路径.

**倍卷积压缩后再做全局注意力**

SAM 与约 300M 参数的 CLIP-large 之间放置两层 stride-2 卷积. 空间高宽各缩小 4 倍, token 总数缩小 $4\times4=16$ 倍. 卷积同时聚合相邻特征, 压缩后的 token 再进入 CLIP 的 dense global attention. 全局注意力面对的是缩短后的序列, 激活与计算成本随之下降.

这一步的代价是局部细节被合并. 若字符在输入中已经过小, 卷积下采样会让相邻笔画更难区分; 若压缩前特征充分编码局部结构, 后续 CLIP 又能在页面范围交换信息, 则少量 token 仍可支持解码. Fox 曲线展示的正是这种取舍随压缩比变化的结果.

DeepEncoder 输出还经过投影, 作为视觉前缀送入 MoE 解码器. 解码器总参数约 3B, 每个 token 激活约 570M 参数. MoE 减少单 token 激活计算, 但视觉信息容量主要受 DeepEncoder 输出长度与表示质量限制. 报告没有给移除 SAM, 移除 CLIP 或改变 16 倍压缩器的逐项消融, 因而无法从最终表格拆出三个部件各自贡献.

串联结构还改变了两个预训练视觉模型的分工. SAM-base 擅长密集局部边界与区域感知, CLIP-large 的预训练则把视觉特征与语义空间联系起来. DeepEncoder 让 SAM 先接触高分辨率网格, CLIP 只接收压缩后的序列. 这样既复用两类初始化, 又避免让 CLIP 的全局注意力直接面对全部高分辨率 patch. 论文把两者称为 perception 与 knowledge 部件, 但没有用冻结实验验证这种语义分工.

16 倍压缩发生在进入 CLIP 之前, 所以 CLIP 无法恢复卷积压缩器已经丢失的局部变化. 解码器能够补全常见词形和文档结构, 但补全可能产生看似流畅却不忠于页面的字符. 对数据生产而言, 这类错误比明显乱码更难过滤. 报告主要用 edit distance 衡量输出, 没有单列数字, 专名与公式中的高风险替换.

### 1.2. 多分辨率档位不是同一输入的免费切换

模型提供 Tiny, Small, Base, Large, Gundam 与 Gundam-M 等档位. Tiny 对应 512×512 输入和 64 个视觉 token, Small 对应 640×640 与 100 token; 更高档位增加分辨率与 token 数. 位置编码插值让同一编码器接受不同网格, 但更高分辨率会增加 SAM 阶段的密集 patch 和计算.

Base 与 Large 对输入做 padding 以保留长宽比. 若实际内容区域的长边对齐方形画布, 短边方向会出现空白 token. 报告用式 (1) 估算有效 token: $N_{valid}=\lceil N_{actual}\min(w,h)/\max(w,h)\rceil$. 例如 1024×512 页面进入 Base 的 256 个槽位, 有效数约为 128. 该公式按面积比例估算, 不会判断页面边缘是否本来就是空白.

Tiny 与 Small 直接 resize, 没有 padding 浪费, 但会扭曲长宽比. 对普通段落, 形变可能仍可识别; 对几何图形, 图表比例与细小公式, 形变会改变视觉结构. 这也是高档位保留长宽比的原因. 论文没有在相同有效 token 下比较 resize 与 padding, 两种预处理的独立影响仍不清楚.

有效视觉 token 数还可能小于张量中的填充长度. OmniDocBench 表中 Base 为 256 个槽位, 平均有效 token 182; Large 为 400 与 285. 比较模型时应区分上限和有效平均数. 报告以平均每页 token 衡量推理序列, 没有把视觉编码器 FLOPs 与峰值显存放进同一张表.

多分辨率输入依赖位置编码插值. 预训练位置网格被调整到新的空间尺寸, 使相同参数能够处理不同宽高. 插值解决位置参数尺寸不匹配, 并不保证任意极端长宽比都有相同性能. 文档页面, 幻灯片与报纸的空间分布差异较大, 模型还要依靠训练中的分辨率和长宽比分布来适应. 报告没有给固定 token 数下不同长宽比的消融.

Gundam-M 还会把大图拆为若干局部视图并保留全局视图, 因而 token 数高于单幅 Gundam. 局部视图提高小字可读性, 全局视图保留页面布局. 这种组合与简单提高单图分辨率的计算路径不同. OmniDocBench 中 Gundam-M 的平均 1853 token 换来更低 edit distance, 但不再属于「少于 800 token」的档位.

**数据与训练把压缩器变成文档模型**

**OCR 数据不只包含纯文本页面**

预训练数据包含 OCR 1.0, OCR 2.0, 一般视觉与纯文本数据. OCR 1.0 侧重文字和布局恢复, OCR 2.0 扩展到图表, 化学结构与几何图形. 一般视觉数据保持图像描述, 检测和 grounding 能力, 纯文本数据用于保留解码器语言能力. 不同任务通过 prompt 区分输出形式.

数据比例为 OCR 70%, 通用视觉 20%, 纯文本 10%. OCR 文档主体包括从互联网收集的 3000 万页 PDF, 中文和英文约 2500 万页, 其他近 100 种语言共约 500 万页. 中文与英文各有 200 万页细标注, 其余数据可使用 fitz 提取的粗标注. 自然场景 OCR 另从 LAION 与 Wukong 获取图像, 用 PaddleOCR 标注, 中英文各 1000 万条.

细标注由版面模型和已有 OCR 系统生成, 因此教师模型错误会进入训练集. 对低资源语言, 流水线先用 fitz 构建 patch 训练 GOT-OCR2.0, 再标注布局切分后的 patch, 形成 60 万条飞轮数据. 这种方法扩大语言覆盖, 也可能把字体或版面偏差循环放大. 论文没有报告人工抽检比例与各语言标签准确率.

PDF 页面来自真实文档与合成数据, 覆盖中英文及近 100 种语言. 合成页面可以控制字体, 布局与文字密度, 真实页面补充扫描噪声和复杂结构. 报告没有公布各类数据的精确比例与去重细节, 因而无法复原训练分布. 多语言能力也只给可视化样例, 没有逐语言基准表.

训练分两阶段. 第一阶段固定解码器, 主要训练 DeepEncoder, 使视觉特征对齐已有语言空间; 第二阶段联合训练编码器与解码器. 报告明确没有 SFT 阶段, 模型不是按聊天助手行为训练, 部分能力需要 completion prompt 激活. 这一点解释了开源权重的调用方式, 也限制把通用视觉样例当成对话能力证明.

第一阶段冻结语言模型可以避免尚未对齐的视觉特征立即扰动解码器, 训练压力集中在编码器和投影层. 视觉前缀逐渐学会触发已有词表中的正确文本. 第二阶段再联合更新, 让解码器适应文档布局, 公式与结构化输出. 两阶段分别处理模态对齐和端到端任务适配, 但论文没有报告第一阶段结束时的 OCR 成绩, 无法量化联合训练的增量.

数据引擎还通过 prompt 控制带布局与不带布局的输出. 同一页面可以训练纯文本 OCR, Markdown 布局恢复或特定图像区域的深度解析. 这种统一生成接口减少传统 OCR 中检测, 识别与版面重建的独立模块, 代价是所有错误集中到自回归序列中. 一处早期格式错误可能改变后续阅读顺序, 表格闭合与公式边界.

OCR 2.0 数据进一步扩展输出空间. 图表部分用 pyecharts 与 matplotlib 合成 1000 万幅折线图, 柱状图, 饼图和组合图, 目标输出改为 HTML table; 化学结构从 PubChem 获取 SMILES, 用 RDKit 渲染 500 万个图文对; 平面几何按 Slow Perception 构建 100 万条数据. 三类任务都要求模型从像素恢复结构, 不只是识别可见字符串.

合成数据的优势是 ground truth 可精确生成, 样式和坐标也容易控制. 局限在于渲染器分布比真实文档窄. 真实图表可能有遮挡, 扫描噪声和不规则图例; 化学式可能跨行或带手写标记; 几何图形的标注习惯也会变化. 报告提供定性样例, 没有分别给三类 OCR 2.0 任务的独立基准分数.

**生产吞吐与训练吞吐是不同指标**

报告称 20 个节点, 每节点 8 张 A100-40G, 每天可处理 3300 万页, 折合单卡每天约 20 万页. 该数字描述数据生产管线的页面吞吐, 会受分辨率档位, 输出长度, batch 和后处理影响. 它不是训练速度, 也不能直接外推到任意硬件.

训练部分另给出纯文本约 100B token/天, 多模态约 70B token/天的速度. 文本 token 与页面数的单位不同. OCR 生产还要保存 Markdown 或结构化结果, 运行质量过滤并处理失败页面. 发布的吞吐证明模型适合大规模数据构建, 但没有给能耗, 错误重试和质量过滤后的净留存率.

训练采用 20 个节点, 每节点 8 张 A100-40G, 流水线并行分为四段, 数据并行度为 40, global batch size 为 640. SAM 与压缩器放在 PP0 并冻结, CLIP 放在 PP1 继续训练, 12 层 MoE 解码器均分到 PP2 与 PP3. 这种划分公开了计算组织方式, 但没有给总训练 step 与实际训练 token 数, 因而不能由每日吞吐还原总训练算力.

## 2. 实验结果与上下文遗忘边界

**OmniDocBench 的优势来自 token 效率**

OmniDocBench 使用 edit distance, 数值越低越好, 并分别评估文本, 公式, 表格和阅读顺序. DeepSeek-OCR Small 只用 100 token, 英文 overall 为 0.221, 优于 GOT-OCR2.0 的 0.287; Gundam 使用 795 token, 英文 0.127, 优于 MinerU2.0 的 0.133, 中文 0.181 也优于 MinerU2.0 的 0.238. Gundam-M 在 200dpi 下用 1853 token, 英文与中文 overall 分别为 0.123 和 0.157.

类别表显示文档结构决定所需档位. Slides 在 Tiny 下已为 0.116, Book 从 Tiny 的 0.147 降到 Small 的 0.085; Newspaper 则从 Tiny 的 0.94, Small 的 0.744, 一直到 Gundam 的 0.122 才明显可用. 报告解释报纸页面通常含 4000–5000 文本 token, 远高于书页和报告, 因而固定视觉 token 下压缩比更高.

比较仍有口径限制. pipeline 模型的 token 数没有统一列出, 不同端到端模型使用的图像分辨率和预处理也不同. OmniDocBench 结果证明 DeepSeek-OCR 在该协议下取得良好的质量与视觉 token 折中, 不能推出其视觉编码 FLOPs 最低. 公式项在中文和英文上仍明显难于普通文本, 也说明压缩没有消除细粒度符号识别问题.

表格还揭示 Base 与 Large 并非所有列都随 token 数单调改善. 英文 overall 从 Base 的 0.137 到 Large 的 0.138 略微变差, 英文 formula 从 0.267 到 0.277, order 从 0.064 到 0.067. 中文 overall 则从 0.240 改善到 0.208. 这些小幅反向变化可能来自样本差异, 解码波动或分辨率对不同结构的影响. 因而分辨率档位应按文档类型选择, 不能默认 token 越多每项必然越好.

Gundam 模式在中文公式上为 0.432, 仍明显高于中文文本的 0.097. Gundam-M 把公式降到 0.377, 改善有限. 公式包含二维结构, 上下标和相似符号, 既需要局部清晰度, 也需要严格序列化. 这项结果限制了把普通文本的近无损压缩结论直接推广到 STEM 文档.

### 2.1. 渐进遗忘仍是研究设想

报告提出把较早的对话文本渲染为图像, 随时间继续降低图像分辨率, 让旧上下文占用更少视觉 token. 最近信息保留高分辨率, 较远信息逐步丢失细节. Fox 的不同压缩比为这种设想提供 OCR 解码曲线, 但实验没有把图像压缩后的历史重新送入长对话任务.

真正的上下文压缩需要验证问答保持, 跨轮指代, needle-in-a-haystack 和数字精确回忆. OCR edit distance 只测文本恢复, 没有测模型能否利用被压缩信息完成推理. 报告结论也把数字与光学文本交错预训练, 长上下文检索列为后续工作. 因而「理论上无限上下文」不是已有实验结论.

遗忘机制还需要定义丢失优先级. 降低分辨率最先损害小字符和密集区域, 这种视觉顺序与语义重要性没有稳定对应. 日期, 数字或代码中的一个字符可能对后续任务很关键. 如果系统只按时间降低清晰度, 信息价值与视觉可读性并不一致. DeepSeek-OCR 建立了视觉 token 容量的经验基线, 尚未解决长期记忆的选择与恢复策略.

压缩后的历史还引入可验证性问题. 原始文本若被图像表示替换, 后续回答引用旧信息时需要重新 OCR, 每次解码都可能产生不同局部错误. 系统若同时保留原文用于核对, 存储并没有真正消失; 若只保留图像, 又失去精确恢复保证. 实际长期记忆可能需要原文冷存储, 压缩表示用于常规推理, 在关键事实不确定时再检索原文.

因此 DeepSeek-OCR 已证明的是文档视觉 token 可以形成高压缩的可解码表示, 以及这种表示可服务实际 OCR 数据生产. 它尚未证明视觉上下文能替代文本上下文完成同等推理, 也未证明渐进降分辨率能按语义价值遗忘. 两者之间需要数字与光学文本交错预训练, 长上下文任务和端到端成本评测补足.

工程上可以先按页面信息密度选择 Tiny 到 Gundam-M, 把不同分辨率档位用于文档解析. 若用于对话记忆, 还必须保留原文回退路径与事实级校验, 避免压缩误差进入后续推理后持续传播.

这一区分决定了 OCR 产品能力与长期记忆研究不能共用同一套验收指标.

**序列长度比并不等于信息压缩率**

**一个视觉 token 能承载多少比特**

报告用 $r=N/n$ 衡量压缩, 其中 $N$ 是文本 tokenizer 产生的 token 数, $n$ 是视觉 token 数. 这个定义适合比较 LLM 接收的序列长度, 但没有限定单个 token 的状态空间. 文本 token 是约 129K 词表中的离散编号, 若粗略按均匀编码估计, 每个编号需要

$$
\log_2 129000\approx16.98
$$

比特. 视觉 token 则是 $d$ 维连续向量. 若以 bfloat16 存储, 原始数值宽度为 $16d$ 比特. 即便 $d$ 只有 1024, 一个向量的存储位数也远高于一个离散文本编号. 网络当然不会均匀使用所有浮点状态, 有效信息量受数据流形, 噪声和模型可解码性限制;这仍足以说明 $10\times$ 的序列长度比不能读成 $10\times$ 的无损字节压缩.

DeepSeek-OCR 关心的是 Transformer 上下文槽位. 对解码器而言, 100 个视觉向量占据约 100 个序列位置, 而原文可能需要 1000 个文本位置. 注意力和 KV cache 的主维度确实随位置数变化. 因此该指标对推理上下文预算有直接意义, 对磁盘体积, 网络传输或 Shannon 码长则没有直接等价关系.

若要比较比特率, 至少要定义视觉向量的量化精度, 隐藏维度与熵编码方式. 还应计入图像本身或视觉编码器输出是否需要持久化. 当前实验在运行时生成视觉 token, 没有将它们设计成可跨模型传输的压缩文件格式.

### 2.2. 文本 tokenizer 改变分子

同一句英文在不同 tokenizer 下会产生不同 $N$. 高频单词可能对应一个 token, 罕见专名可能被拆成多个子词;中文单字, 数学符号和代码的分割规律又不同. 假设页面字符数固定为 $C$, 平均每个文本 token 覆盖 $a=C/N$ 个字符, 则报告的比值可以改写为

$$
r=\frac{C}{a n}.
$$

当词表更擅长当前语言时, $a$ 增大, $N$ 减少, 即使视觉表示完全不变, $r$ 也会下降. 因而跨语言或跨模型比较压缩比时, 必须同时给出 tokenizer. Fox 只取英文页面, 避免了一部分语言差异, 却没有建立多语言共享阈值.

一个包含大量随机身份证号的页面与普通散文可能拥有相近文本 token 数. 散文中有强语言冗余, 解码器可凭上下文补全词语;随机号码几乎没有这种冗余, 每个字符都必须从图像准确读取. 两页的 $r$ 相同, 可恢复难度会显著不同. 因此更完整的容量曲线应按字符熵, 版面和字体大小分层, 而非只按文本 token 桶聚合.

**OCR 解码混合了视觉信息与语言先验**

设页面文本为 $Y$, 视觉 token 为 $Z$, 解码器输出为 $\hat Y$. 高恢复率说明 $Z$ 与语言先验共同足以预测 $Y$. 它没有单独测出互信息 $I(Y;Z)$. 当 $Y$ 符合常见语言模式时, 解码器可以根据局部可见字符补全后续内容. 若将同一字符集合随机打乱, 语言先验失效, 相同视觉 token 数可能得到更低准确率.

从条件熵看, 理想解码误差受 $H(Y\mid Z)$ 影响. 强语言模型能够利用 $p(Y)$, 但只有在 $Z$ 缩小候选集合后才能恢复具体页面. 对常见句子, $H(Y)$ 本来较低;对密码, 哈希值或随机表格, $H(Y)$ 更高. Fox 结果证实视觉编码加语言解码在真实英文文档上的联合容量, 没有证明视觉 token 单独保存了同等数量的独立字符信息.

可以设计三种受控实验拆开二者. 第一种把词序随机打乱但保留字体和字符频率;第二种将实体名和数字替换成随机串;第三种让解码器面对语法正确但事实不同的成对页面. 如果精度在这些实验中快速下降, 表明原结果依赖语言冗余. 这不会否定光学压缩的实用性, 却能划清它对精确记忆和自然语言摘要各自适用的范围.

**二维排版为什么可能节约上下文位置**

**一维 token 序列显式展开全部字符**

文本 tokenizer 把阅读顺序展开成一维位置. 标题, 两栏正文和脚注即使在页面上并行分布, 最终也需要逐 token 排列. 图像把二维邻域放进同一 patch, 一个视觉位置可以同时编码多行局部笔画, 字体, 间距和边框. 卷积与视觉注意力将这些像素压成连续向量, 后续解码器再按阅读顺序展开.

这种节约利用了文档的空间规律. 字符按基线排列, 行距与列间隔重复, 字体字形共享结构. 视觉编码器无须为每个像素保留独立符号, 可以把常见局部模式映射到低维特征. 语言解码器又利用词法和句法冗余. 视觉压缩的效果来自空间先验与语言先验叠加, 并非二维坐标本身自动增加信息容量.

反例是将每个字符随机旋转, 改变字体并散布到页面. 二维局部规律被破坏, 阅读顺序也不再由版面轻易推断. 相同像素数和字符数下, DeepEncoder 必须保留更多局部差异, 压缩曲线可能提前下降. 论文数据以常规文档为主, 结论适用于具有文档结构的视觉文本.

**页面布局本身也占用容量**

Free OCR 主要恢复纯文本, Markdown 提示还要求标题层级, 表格边界, 公式和阅读顺序. 若视觉 token 总数固定, 保存布局就会与保存字符细节竞争容量. 一张纯段落页可以把大部分表示用于字形;一张报纸需要编码多栏区域, 图片位置和跨栏标题, 同样 $n$ 下更难恢复.

可以将页面信息概念性分为

$$
I_{page}=I_{glyph}+I_{layout}+I_{nontext}+I_{noise}.
$$

$I_{glyph}$ 是字形与字符,$I_{layout}$ 是阅读顺序和结构,$I_{nontext}$ 包含图表与插图,$I_{noise}$ 是扫描污点等无关变化. DeepEncoder 希望保留字形,布局与非文本内容,同时抑制扫描噪声. 纯文本 OCR 可以忽略精确坐标,文档转 Markdown 必须保留结构,通用描述又可能关注插图内容,三类任务对信息分量的权重各不相同.

同一个视觉表示要通过 prompt 支持多种输出,意味着编码器不能只保存某一种任务的最小充分统计量. 这会牺牲理论上的极限压缩,换来任务复用. Fox 的 Free OCR 曲线因此更接近纯文本恢复上限,不能直接预测 Markdown 解析在相同 $r$ 下的质量.

### 2.3. 阅读顺序是隐变量

端到端模型输入整页图像,输出一维序列. 在多栏文档中,模型必须同时推断区域集合和它们的遍历顺序. 可以把生成概率写成

$$
p(Y\mid X)=\sum_R p(R\mid X)p(Y\mid R,X),
$$

其中 $R$ 表示阅读顺序和区域划分. 传统流水线显式预测 $R$,端到端模型把它隐含在视觉 token 与解码隐藏状态中. 一旦早期选择了错误栏,自回归输出会沿错误上下文继续生成,表现为段落交叉或表格行错位.

OmniDocBench 单列 order edit distance 正是因为字符正确还不够. Gundam 提供局部裁块和全局页视图,局部块保留小字,全局视图帮助恢复 $R$. 若只保留局部块而缺少全局图,模型可能识别每块内容却不知道拼接顺序;若只保留全局低分辨率图,布局清楚而字符模糊. 多视图结构在两个目标之间分配 token.

**DeepEncoder 的计算与信号路径**

**全局注意力为何要放在压缩之后**

设初始 patch 数为 $P=HW$. 全局自注意力的分数矩阵含 $P^2$ 个元素. 两层 stride-2 卷积令高宽各缩小 4 倍,压缩后位置数 $P'=P/16$. 若直接比较注意力矩阵规模,

$$
\frac{(P')^2}{P^2}=\frac{1}{256}.
$$

这只是 CLIP 全局注意力部分的理论位置比例,不包含通道宽度,层数,SAM 窗口注意力和卷积成本. 它仍说明顺序的重要性:先压缩再全局交互,比在完整高分辨率网格上运行 CLIP 更容易控制激活.

窗口注意力把每个窗口大小记作 $M\times M$. 若忽略边界,窗口总计算随 $P M^2$ 增长,相对全局的 $P^2$ 在大图上更接近线性. 代价是窗口间缺少直接联系. SAM 部件可以通过多层和可能的窗口布局积累局部感受野,真正的页面级关系仍由压缩后的 CLIP 处理.

**Stride 卷积是一种有学习参数的采样器**

每次 stride-2 卷积把相邻位置映射到更稀疏网格. 若输入信号含有超过新 Nyquist 频率的变化,下采样会产生混叠. 对文档而言,细笔画,小数点,上下标和相邻竖线都属于高频结构. 可学习卷积需要在降采样前形成近似低通与语义聚合,把关键细节转移到通道维度.

一维例子足以说明风险. 若像素序列交替为 $1,-1,1,-1$,直接每隔一个位置采样会得到全 1 或全 -1,完全失去原频率. 卷积若先对相邻值平均,结果变成 0,避免伪造低频模式,却仍丢失原信号. 若网络知道这种交替对应字符边缘,可以用不同通道保存幅值与相位. 能否做到取决于训练覆盖和通道容量.

这也是字符越小越难压缩的原因. 同一汉字在 20 像素高度下,关键笔画跨多个 patch;缩到 5 像素时,一次 stride 已可能合并不同部件. 提高视觉 token 数只有在输入分辨率也保留了笔画时才有用. 对低清扫描件,Large 档位无法恢复原图不存在的信息.

**串联预训练模块存在分布接口**

SAM-base 原本为分割相关感知训练,CLIP-large 原本接收自己的 patch 嵌入与图像分布. DeepEncoder 在二者之间插入卷积压缩器,让 CLIP 接收经过 SAM 与压缩的特征,并非原生 RGB patch. 训练需要让接口输出落入 CLIP 可利用的表示范围,同时调整 CLIP 适应新输入.

论文训练划分中,SAM 与压缩器位于 PP0 并冻结,CLIP 位于 PP1 继续训练. 这意味着某一阶段后局部前端成为固定变换,全局视觉模块承担分布适配. 固定前端降低训练激活与参数更新成本,也使前端遗漏的信息无法由后续梯度修正. 报告没有给冻结与全量训练的对照,目前只能评价完整配方.

**输出 token 数由空间尺度确定**

Tiny 512×512 对应 64 token,可理解为最终 $8\times8$ 网格;Small 640×640 对应 100 token,对应 $10\times10$;Base 和 Large 分别是 $16\times16$ 与 $20\times20$. 这组数字呈现一致的边长比例:输入边长每 64 像素大致对应一个最终视觉位置.

这个观察帮助理解容量. Tiny 的一个最终 token 覆盖约 $64\times64$ 输入像素区域,但其通道已经汇集 SAM 局部特征. 若该区域含多行小字,一个向量要同时保存许多字符线索;若只含页边空白,该槽位几乎浪费. Base 的 padding 会产生空白区域,所以论文用有效 token 估算排除一部分浪费.

动态裁块的 Gundam 把高密度区域重新映射到多个 Small 视图,相当于为同一页面增加局部网格. 全局 Base 视图继续提供布局. 这种 token 分配仍以规则裁块为主,并非根据字符密度学习的自适应采样. 真正的内容感知压缩还可以把更多槽位分给小字与公式,更少槽位分给空白和大图,论文没有实现这类路由.

## 3. 视觉 token 怎样进入 MoE 解码器

**视觉前缀改变的是条件状态**

DeepEncoder 输出经投影后成为解码器前缀. 对输出 token $y_i$,自回归概率为

$$
p(y_i\mid Z,y_{<i},q),
$$

其中 $Z$ 是视觉序列,$q$ 是任务 prompt. 视觉 token 无须逐个对应文字 token. 一个视觉位置可以影响很多输出字符,一个字符也可以同时读取多个视觉位置. 这使 $N/n>1$ 成为可能.

因果解码时,视觉前缀的 KV 可以缓存,每个新文本 token 只追加自身状态. 视觉序列越短,每层 KV cache 的固定前缀越小,后续每步注意力读取的历史也更短. 对长输出,节约会重复作用于每个解码步. 但 DeepEncoder 的一次性编码成本不会随 $n$ 的减少自动消失.

### 3.1. MoE 降低每个输出位置的激活参数

解码器总参数约 3B,每个 token 激活约 570M. MoE 路由让不同 token 使用部分专家,把参数容量与单 token 计算解耦. OCR 输出里普通文字,公式,HTML 标签和 SMILES 具有不同分布,专家可能形成分工,但论文没有公开路由统计或专家专门化结果.

MoE 无法增加视觉前缀中已经丢失的信息. 当小数点在编码阶段消失,更大的语言容量只能根据上下文猜测. 强解码器会把模糊视觉证据变成语法流畅输出,提高常规文本精度,也可能让专名和数字错误更隐蔽. 因此高压缩场景要同时报告拒答或置信度,不能只看可读性.

**Prompt 定义输出协议**

官方仓库提供 `Free OCR.`, `Convert the document to markdown.`, `Parse the figure.` 等提示. 相同图像在不同 prompt 下需要不同输出空间. Free OCR 忽略大部分版面标记,Markdown 模式要生成结构符号,figure 模式可能把图表转成表格. Prompt 因而充当任务选择器.

如果训练数据中某种 prompt 与固定数据源高度绑定,模型可能利用提示猜测输出风格,而非完全由视觉决定. 更严格的泛化测试应让同一页面接受多种协议,并检查内容是否一致. 例如 Free OCR 与 Markdown 去掉标记后的文本应该大致相同;若二者事实内容不同,说明协议控制与视觉恢复发生冲突.

官方推理示例还加入 n-gram logits processor,抑制长输出中的重复循环,并对白名单表格标签放行. 这表明自回归文档生成存在退化重复风险. 该处理器改变解码分布,评测复现需要保持相同设置. 它改善生成稳定性,没有提高视觉编码的信息容量.

**从 token 预算推导页面选择**

**固定档位隐含固定空间采样密度**

设页面有 $N$ 个文本 token,选择档位得到 $n$ 个视觉 token. 若希望压缩比不超过经验阈值 $r_{max}$,至少需要

$$
n\ge\left\lceil\frac{N}{r_{max}}\right\rceil.
$$

例如估计一页有 1200 个文本 token,若希望控制在 $10\times$,至少需要 120 个视觉 token. Small 的 100 不足,Base 的有效 token 若受长宽比影响仍可能超过 120. 这只是基于 Fox 英文曲线的粗路由,公式和报纸应采用更保守阈值.

档位集合是离散的. 需求为 120 时从 Small 跳到 Base 256 槽位,会产生额外预算. Gundam 的局部块数量又随页面尺寸变化. 更细的动态网格能减少这种量化浪费,但也会让 batch 内序列长度不齐,增加训练和推理调度复杂度.

**长宽比修正只估计几何空白**

Base 和 Large 的有效 token 公式可写为

$$
n_{eff}=\left\lceil n\frac{\min(w,h)}{\max(w,h)}\right\rceil.
$$

若页面宽高比为 $1:2$,256 个槽位估成 128 个有效位置. 该估计假设内容均匀铺满实际页面矩形,而 padding 占剩余一半. 若原页面本身有宽页边距,真正含字位置更少;若内容只集中在局部表格,几何有效位置又会高估信息利用率.

更准确的预算需要内容掩码或文字密度图. 假设前端检测到每个区域的字符密度 $d_j$ 和任务难度权重 $w_j$,可按 $d_jw_j$ 分配局部 token. 公式,小字体和随机数字权重更高,插图空白更低. DeepSeek-OCR 的规则档位没有提供这套学习路由,但其压缩曲线为设计路由器提供了经验约束.

**批处理受最长视觉序列影响**

同一 batch 若混合 Tiny 与 Gundam-M,为了张量对齐可能 padding 到最长序列,空槽位仍消耗部分内存或调度开销. 按档位分桶可以减少浪费,却可能降低请求合批率. 生产吞吐 20 万页每卡每天取决于输入分布和 batch 策略,不能从单页 token 数直接计算.

对于文档库,可以先用页面尺寸,字符密度估计和文档类型进行粗分桶. 书页多用 Small 或 Base,报纸和密集公式进入 Gundam,极端页面使用 Gundam-M. 这是一种资源分配策略,质量保障仍要依靠抽样评测和错误检测.

**编辑距离怎样衡量恢复质量**

### 3.2. 归一化编辑距离观察序列变换

Levenshtein 距离计算把预测变成真值所需的插入,删除与替换次数. 归一化后常写为

$$
d_{norm}(\hat y,y)=\frac{D_{lev}(\hat y,y)}{\max(|\hat y|,|y|)}.
$$

数值越低,序列越接近. 它能同时惩罚漏字,多字和错字,适合 OCR. 但所有操作通常权重相同:漏掉一个逗号与把药物剂量的 1 改成 9 都计一次错误. 对安全敏感文档,还需数字,实体和关键字段的加权指标.

版面输出会放大格式差异. Markdown 表格的一处竖线缺失可能导致后续对齐变化,字符串距离增加,即使人仍能理解;反过来,语法完整但单元格错位可能只改变少量字符,实际结构错误更严重. OmniDocBench 分文本,公式,表格和阅读顺序报告,正是为了避免 overall 隐藏不同失败.

**平均值会隐藏长尾页面**

设大多数普通页距离很低,少量密集报纸完全失败,平均 overall 可能仍显得可用. 生产系统更关心分位数和失败率:第 95 百分位距离,空输出比例,重复循环比例,以及关键字段精度. 论文表格给数据集平均值,没有提供逐页分布.

Fox 每个文本长度桶的页数也不均衡. 若先按桶求均值再观察曲线,小样本端点方差较大. 对 4 页的 1200–1300 桶,一页异常就会明显改变 59.1%. 容量拐点需要更多页面与置信区间验证.

**解码温度与重复抑制影响指标**

官方示例使用 temperature 0,使相同输入趋向确定性输出. 文档 OCR 要求忠实恢复,随机采样通常没有收益. n-gram processor 阻止长片段循环,可降低因生成退化造成的大量插入. 如果不同模型使用不同解码约束,编辑距离比较会同时测模型与解码器.

贪心解码也可能在局部模糊处选择错误字符后继续传播. Beam search 或字段约束能提高某些序列准确率,计算成本则更高. DeepSeek-OCR 的主要结果应按论文协议理解,不能把一个解码配置视为模型唯一能力上限.

**数据引擎中的标签噪声**

**教师 OCR 会产生结构化误差**

粗标注来自 fitz 或已有 OCR 系统. 文本层完整的数字 PDF 可以提供高质量字符串,扫描件,乱码字体和错误嵌入文本则会污染标签. 版面模型还可能把两栏顺序合并错误,把公式拆成普通文本. 这些误差具有系统性,不会像独立随机噪声那样简单平均掉.

设真实标签为 $Y$,教师标签为 $\tilde Y$. 训练最小化 $-log p_\theta(\tilde Y\mid X)$,实际关心 $Y$. 若噪声转移 $p(\tilde Y\mid Y,X)$ 与字体,语言和版面相关,模型会学到特定场景的偏差. 例如教师经常漏掉上标,学生会把漏上标当成正确输出格式.

**飞轮能扩大覆盖也能放大偏差**

低资源语言流程先构造 patch 训练已有模型,再让模型标注更多数据. 每一轮增加样本量,但伪标签来自上一轮能力. 若罕见字符从种子阶段就识别错误,后续标注会重复同一映射. 只有人工真值,独立教师或高置信过滤能打断偏差循环.

飞轮收益取决于选择机制. 高置信样本易于加入,会让模型在已会区域更强;困难字体和模糊扫描被过滤,长尾仍没有覆盖. 若为了覆盖保留低置信样本,标签噪声又上升. 论文报告近 100 种语言与 60 万飞轮数据,没有逐语言真值评测,多语言样例只能证明部分可用性.

**合成数据提供精确标签但缩窄视觉分布**

图表,化学结构和几何合成数据的标签可由生成程序直接获得. HTML table,SMILES 或几何描述与图像共享同一源结构,避免教师 OCR 错误. 训练因而可以学习严格输出语法.

渲染器决定字体,颜色,线宽和布局组合. 现实文档中的扫描阴影,遮挡,手写批注和软件导出差异若未进入渲染分布,模型会在合成基准上优秀而真实页面退化. 域随机化能扩大样式,却仍难覆盖所有排版工具与历史文档噪声.

**数据去重关系到容量实验**

如果评测页面或近似模板出现在训练集,语言与版面记忆会抬高恢复率. 3000 万 PDF 页可能包含重复版本,公开书籍或网页镜像. 论文没有给出与 Fox 和 OmniDocBench 的去重细节. 这不等于存在泄漏,但容量结论的外推强度受该信息缺失限制.

更严格的容量实验可以用程序生成从未出现的随机文本与新布局,同时保留真实字体噪声. 这样能降低语言记忆和页面模板记忆,直接测视觉通道. 再与自然文档结果并列,便能量化语言先验带来的增益.

### 3.3. OCR 2.0 把字符概念扩展到结构

**公式需要恢复二维语法**

普通文本可以按行展开,数学公式包含上下标,分式,根号和矩阵. 两个符号像素相同但相对位置不同,LaTeX 序列就不同. 视觉编码器必须保存几何关系,解码器再按语法顺序输出.

设公式解析树为 $T$,渲染图像为 $X=R(T)$. OCR 要近似求逆 $T\approx R^{-1}(X)$. 渲染并非一一映射:不同 LaTeX 可得到近似相同外观,宏命令也可能语义等价. 纯字符串 edit distance 会惩罚等价表达,同时也可能漏掉结构语义差异. 公式评测最好增加编译成功率,渲染相似度和符号树距离.

**图表解析需要从连续几何恢复数据**

图表转 HTML table 不只是 OCR 标签文字. 模型要识别坐标轴,图例,曲线或柱形,再把像素位置映射回数值. 若纵轴范围为 $[a,b]$,绘图区高度为 $H$,某点像素纵坐标 $p$ 对应数值近似

$$
y=a+(b-a)\frac{H-p}{H}.
$$

像素定位误差 $\Delta p$ 会产生 $(b-a)\Delta p/H$ 的数值误差. 图像缩放与视觉 token 压缩会降低有效 $H$,所以图表数值恢复比读取大标题更敏感. 对数坐标,断轴和三维图又需要先识别坐标规则.

合成 pyecharts 与 matplotlib 数据让模型看到坐标与真值配对,但真实图表的风格更广. 报告以定性样例展示 deep parsing,没有独立数值误差表,不能由普通 OCR overall 推出图表数据完全可靠.

**SMILES 要求拓扑一致性**

化学结构图中的原子标签,键类型和环闭合共同决定分子图. SMILES 是对该图的一种序列化,同一分子可有多个合法字符串. 字符 edit distance 对非规范但等价的 SMILES 不友好;更合理的评测会先解析字符串,比较分子图或 canonical SMILES.

视觉压缩对细双键,楔形键和小原子标签敏感. 少一个键字符可能产生完全不同分子,却只算很小编辑距离. 这再次说明 OCR 2.0 的结构任务需要领域语义指标.

**渐进遗忘必须定义保存目标**

**从文本到图像是有损记忆编码**

设历史文本为 $H$,渲染器产生图像 $X=R(H)$,DeepEncoder 得到 $Z=E(X)$. 后续任务为 $Q$,希望由 $Z$ 回答 $A$. 如果目标是逐字恢复,要求 $I(H;Z)$ 足够大;如果只需回答某类问题,真正需要保留的是关于 $A$ 的充分信息.

降低图像分辨率会形成一串表示 $Z_1,Z_2,\ldots$,直观上容量逐步下降. 只有当转换构成 Markov 链

$$
H\rightarrow Z_1\rightarrow Z_2\rightarrow\cdots
$$

时,数据处理不等式才保证后续表示不会增加关于原文的信息. 实际系统若每次从原始文本重新渲染不同分辨率,各档位并非由前一档生成;它们共享源 $H$,信息关系未必严格嵌套.

**时间远近与信息价值并不一致**

简单策略让旧消息分辨率更低,相当于令预算只依赖年龄 $a$. 更合理的预算应依赖未来任务价值 $v$ 与恢复风险 $u$,例如

$$
n_i=f(a_i,v_i,u_i).
$$

一年前的身份证号可能仍需逐字保存,刚刚产生的寒暄则很快失去价值. OCR 压缩按视觉可读性丢失小字,不会自动识别哪些事实重要. 若要成为记忆系统,还需事实抽取,重要性估计与原文回查.

**错误会在再次生成时累积**

如果系统将 OCR 输出重新渲染并继续压缩,每轮都可能引入替换与删除. 假设单轮字符正确率为 $p$,且错误近似独立,经过 $k$ 轮后原字符仍正确的概率粗略为 $p^k$. $p=0.97$ 时十轮约为 0.737. 实际错误不独立,语言模型可能纠正常见词,也可能把一次错误稳定地复制下去.

因此渐进遗忘更适合从同一可信原文生成不同分辨率表示,而非反复 OCR 后再编码. 原文可以放在冷存储,视觉表示服务常规上下文;当回答涉及数字,专名或低置信区域时,回源检索. 这种系统节省热上下文,没有消除持久存储.

**OCR 精度不等于任务保持率**

一段历史有 1000 个 token,其中只有一句决定后续答案. 即使总体字符精度 60%,关键句若清楚,任务仍可能成功;反过来,总体 97% 但恰好改错关键数字,任务就失败. 长上下文压缩应测

$$
P(\hat A=A\mid Q,Z),
$$

而不只测 $P(\hat H=H\mid Z)$. 两者相关但不等价. 报告把交错预训练和长上下文检索列作后续方向,表明现有结果处在表示可解码阶段.

## 4. 端到端成本需要分四段计算

**渲染与编码是前置成本**

若源内容原本是文本,光学压缩先把文本排版成像素. 渲染成本通常低于大模型推理,但会增加图像存储,字体选择和分页规则. 页面分辨率越高,DeepEncoder 的 SAM 窗口计算越多. 对已经是扫描 PDF 的任务,渲染步骤不存在,视觉路径则是自然入口.

编码成本每页支付一次. 如果视觉 token 被多轮复用,一次编码可摊薄;若每次上下文都重新编码,收益会减少. 报告的生产吞吐说明批量页面处理可行,没有与直接文本 tokenization 的端到端延迟比较.

### 4.1. Prefill 从缩短序列中受益

设原文本长度 $N$,视觉长度 $n$,后续共同上下文长度 $L$. 稠密注意力 prefill 的粗略二次项从 $(L+N)^2$ 变为 $(L+n)^2$. 当 $N\gg n$ 时差异明显. 视觉编码成本记作 $C_E$,压缩有利的粗略条件为

$$
C_E+C_{prefill}(L+n)<C_{prefill}(L+N).
$$

实际 LLM 使用 FlashAttention,MoE 和硬件优化,常数不能忽略. 若只需要一次短回答,编码成本可能占较大比例;若历史被许多后续 token 反复读取,缩短 KV 的收益持续累积.

**Decode 受 KV 长度与输出长度共同影响**

自回归生成每一步查询全部前缀 KV. 把历史从 $N$ 降到 $n$ 后,每个输出 token 的注意力读取减少约 $N-n$. 若输出长度为 $M$,累计节约近似与 $M(N-n)$ 成正比. OCR 自身输出长度接近原文本 $N$,所以用视觉 token 重新恢复全文时仍要生成大量文本 token;若后续任务只输出短答案,压缩更可能节省总解码.

这揭示两种用途的差别. 文档转 Markdown 必须生成全文,视觉 token 少并不消除长输出;上下文问答只读取压缩历史并产生短回答,更能利用前缀缩短. 但后者尚缺任务实验.

**存储与热缓存是不同层级**

KV cache 存储每层键值,随层数,头维和序列长度增长. 视觉 token 将热上下文位置减少,可以直接降低 KV. 原始 PDF 或文本是否保留在磁盘属于冷存储问题,体积和访问延迟的量级不同. DeepSeek-OCR 的光学压缩主要针对前者.

因此不能用 10 倍视觉序列比宣称整个系统存储降低 10 倍. 模型权重,视觉编码激活,原图,输出文本和冷存储仍存在. 正确评价应分别列编码 FLOPs,prefill 延迟,decode 吞吐,KV 峰值与持久化字节.

**现有实验能够支撑的结论**

**光学映射在真实文档上具有高序列压缩潜力**

Fox 曲线表明,在限定英文页面,DeepSeek-OCR tokenizer 和 Free OCR 协议下,少量视觉 token 能恢复远多于自身位置数的文本 token. 低于约 $10\times$ 的区间精度接近 97%,压缩继续增加后逐渐下降. 这证明连续视觉前缀结合语言解码器可以利用二维与语言冗余.

该结果没有给出最小充分视觉 token 数的理论下界. 样本只有 100 页,高压缩桶更少,文本类型和 tokenizer 也固定. 它是一条经验率失真曲线,而非语言无关常数.

**DeepEncoder 在文档解析中实现了质量与序列长度折中**

OmniDocBench 显示 Small, Gundam 与 Gundam-M 在不同 token 预算下取得有竞争力的 edit distance. 串联窗口感知,卷积压缩与全局视觉模块能够处理从普通书页到密集报纸的不同负载. 多档位允许系统按页面难度增加视觉槽位.

表格没有统一所有模型的视觉编码计算,训练数据和解码约束. 因而优势应表述为该评测协议中的质量与视觉序列长度折中,不能扩展为所有端到端资源都更低.

**OCR 数据生产能力已经落到公开实现**

[DeepSeek-OCR 官方仓库](https://github.com/deepseek-ai/DeepSeek-OCR) 发布权重,多分辨率模式,prompt 和 vLLM/Transformers 推理入口. 论文报告单 A100-40G 每天 20 万页以上的生产规模,官方示例还展示并发 PDF 解析和重复抑制配置. 这些材料支撑它作为文档解析器的实用性.

吞吐依赖页面类型,档位,batch 与输出长度. 公开数字不包含过滤后的净合格页数,也没有逐语言生产质量. 部署时仍需在自身文档分布上测量.

**长期记忆仍停留在待验证假设**

将旧文本渲染为低分辨率图像,确实能缩短送入 LLM 的序列. 要成为记忆机制,还需要证明压缩历史能保持问答与推理,并建立关键事实回源,置信度和语义重要性路由. [DeepSeek-OCR 论文](https://arxiv.org/abs/2510.18234) 将交错预训练,长上下文检索和遗忘机制放在讨论与后续方向,没有把它们当成已完成系统.

最稳固的认识是:DeepSeek-OCR 提供了一种可训练的视觉信道,把文档页面变成短连续前缀,并用 OCR 展示其可解码容量. 从可解码页面到可用记忆之间,还隔着任务充分性,精确事实保护,端到端成本和多轮误差控制四道验证.

**用率失真视角重看压缩曲线**

**压缩必须和允许误差一起讨论**

信息压缩没有脱离失真定义的单一最优比率. 将原页面文本记为随机变量 $Y$,视觉表示记为 $Z$,失真函数记为 $d(Y,\hat Y)$. 率失真函数写作

$$
R(D)=\min_{p(z\mid y):\mathbb E[d(Y,\hat Y)]\le D}I(Y;Z).
$$

它表示平均失真不超过 $D$ 时至少需要多少信息率. DeepSeek-OCR 没有直接估计 $I(Y;Z)$,而是以视觉 token 数作为率的代理,以 OCR 精度或 edit distance 作为失真代理. Fox 表格由此形成经验曲线:视觉位置减少时,恢复误差上升.

不同任务对应不同 $d$. 普通字符错误率把每个字符近似等权;合同解析应对金额与日期赋更大权重;文档检索只关心能否回答查询;摘要任务甚至允许大量原句无法重建. 因此同一个 DeepEncoder 输出可能对摘要已足够,对逐字归档却不可接受. 把约 $10\times$ 当成统一安全线会忽略失真目标.

### 4.2. Fano 不等式说明分类误差与信息量的联系

将一个文本 token 看作 $K$ 类离散变量 $Y$,由视觉表示预测 $\hat Y$,错误概率为 $P_e$. Fano 不等式给出

$$
H(Y\mid Z)\le h(P_e)+P_e\log(K-1),
$$

其中 $h$ 是二元熵. 低错误率意味着视觉表示与语言先验合在一起大幅降低了条件不确定性. 但公式中的 $Z$ 若只包含视觉 token,最优解码还隐含已知的数据分布;实际 LLM 的参数正保存这种先验.

对整页序列,token 之间高度相关,不能简单把单 token 信息量乘以 $N$. 常见句子的联合熵远低于独立均匀词表的 $N\log K$. OCR 能以少量连续向量恢复长文本,部分原因正是自然语言和版面具有冗余. 随机串实验会提高联合熵,更接近视觉信道的苛刻压力测试.

**精度拐点可能来自多种瓶颈**

曲线在高压缩区下降,至少可能由三类因素触发. 第一,输入 resize 后字符不足以分辨,信息在进入网络前已经丢失. 第二,卷积与固定视觉网格容量不足,多个字符映射到相似表示. 第三,解码器在长输出中累积自回归错误. 三类瓶颈都会降低最终精度,只看输出无法区分.

可以用分阶段探针定位. 在 SAM 输出上训练局部字符分类器,观察输入感知是否仍清楚;在 DeepEncoder token 上用轻量解码器测局部可分性,观察压缩损失;用教师强制给定正确前缀再测下一 token,观察自回归传播. 论文没有这些分层实验,所以 20 倍附近的下降应理解为整个系统的联合上限.

**多视图模式如何合并局部与全局**

**局部裁块提高每个字符的采样密度**

假设原页宽高为 $W\times H$,整页缩到 1024 方形后,小字高度从 $s$ 变成约 $1024s/\max(W,H)$. 若先将页面切成 $k$ 个局部块,每块再缩到 640,同一字符可占更多像素. 局部视图因此改善笔画分辨率.

局部块会切断跨块结构. 表格可能横跨边界,一行文字可能在两块重复或断开. 全局 Base 视图提供页面布局,让解码器知道各块的相对位置. 模型需要把多个视觉前缀中的重复内容对齐,避免生成两遍.

**多视图 token 具有冗余**

全局图和局部块观察同一页面,它们不是独立信息. 设全局表示为 $Z_g$,局部表示为 $Z_l$,联合信息量为

$$
I(Y;Z_g,Z_l)=I(Y;Z_g)+I(Y;Z_l\mid Z_g).
$$

第二项才是局部块在已知全局图后增加的信息. 大标题在全局图中已清楚,局部块对其增益很小;小字和公式的条件增益较大. Gundam 规则地加入局部视图,无法只为高增益区域付费,所以 token 数中包含重复.

内容感知裁块可以先在低分辨率全局图上估计文字密度与不确定性,再选择局部区域. 这会形成两阶段策略:全局图路由,局部图精读. 风险在于路由器可能漏掉肉眼很小却重要的脚注或数字,因此仍需覆盖保证.

**位置标识决定块间拼接**

多个局部块进入解码器时,模型必须知道每块来自页面哪里. 位置可以由裁块顺序,二维坐标 token 或视觉内容隐式推断. 若两个表格块外观相似且缺少坐标,模型可能交换顺序. 论文架构图与公开模式说明存在动态分辨率输入,但没有系统消融块坐标编码.

拼接还要处理重叠区域. 无重叠切块易在边界截断字符;带重叠切块会重复观察内容. 理想解码器要将重复证据融合成一次输出. 生产错误中出现重复段落时,原因可能是自回归循环,也可能是重叠块去重失败,两者需要分别诊断.

**训练流水线中的并行与冻结**

**四段流水线反映模块负载不均**

论文把 SAM 与压缩器放在 PP0,CLIP 放在 PP1,12 层 MoE 解码器分到 PP2 和 PP3. 流水线并行的吞吐由最慢阶段决定. 若各阶段时间分别为 $c_0,c_1,c_2,c_3$,稳态微批次间隔至少为

$$
\max(c_0,c_1,c_2,c_3).
$$

视觉前端只占两个 stage,解码器占两个 stage,说明训练组织同时考虑高分辨率激活与 MoE 参数. 冻结 SAM 与压缩器减少反向激活保存,PP0 的内存压力得以下降.

**Global batch 不能直接换算页面总数**

global batch size 640 表示一次优化更新聚合的样本数,但每个样本可能是页面,自然图像或纯文本. 数据比例 70:20:10 若按样本抽取,一个期望 batch 约含 448 个 OCR,128 个通用视觉和 64 个纯文本样本. 若不同样本长度差异大,实际 token 与计算比例会偏离这一比例.

论文给每日训练 token 吞吐,没有给总 step. 因而总训练样本,总 epoch 与每类数据重复次数无法由公开表格精确恢复. 3000 万 PDF 页是数据池规模,不表示每页只看一次或全部进入同一阶段.

### 4.3. 冻结参数改变优化问题

第一阶段固定解码器,令视觉编码器寻找能被既有语言空间读取的表示. 若解码器也从一开始更新,两侧可以共同移动,短期损失可能下降更快,却容易形成只有当前配对能理解的私有编码,破坏原有语言能力. 固定一侧提供坐标参照.

第二阶段联合训练允许解码器适应结构化输出和视觉歧义. 这时纯文本样本继续约束语言分布. 10% 比例是一种经验平衡,没有配套语言基准就无法判断遗忘程度. 训练中无 SFT 还意味着基础能力与调用格式都来自预训练任务混合,不能假定它具备经过偏好对齐的拒答或对话风格.

**MoE 路由负载也可能受文档类型影响**

如果公式 token 更常路由到少数专家,密集 STEM 页面可能造成专家负载不均. 分布式 MoE 需要在设备间发送 token,热点专家会拖慢整批. 论文给 active 参数量和流水线方案,未报告专家负载或通信量.

从能力角度,专家分工能让同一模型容纳普通文字,代码,公式和 SMILES 模式. 从训练稳定性看,仍需负载均衡损失与容量管理. 这些属于解码器底座的性质,不能由 OCR 表格反推出专家已经按任务理想分工.

**错误类型比单一分数更能指导档位**

**替换错误常来自局部混淆**

形近字符如 `0/O`, `1/l`,中文同部件字以及数学 `-` 与分数线,在下采样后容易混淆. 这类错误通常保持序列长度,编辑距离计一次替换. 提高局部分辨率或加入字符级对比训练可能改善.

语言模型也会把不常见拼写替换为高频词. 若图像证据模糊,后验满足

$$
p(y\mid z)\propto p(z\mid y)p(y),
$$

高频先验 $p(y)$ 会压过相近的视觉似然. 对自然句子这能纠错,对专名和编号则造成幻觉式规范化.

**删除错误常来自密度过高或区域遗漏**

小字行被卷积压缩后与背景混合,模型可能整段跳过. 多栏阅读顺序错误也会漏掉一个区域. 删除比单字符替换更可能随页面密度增长,是档位不足的重要信号.

若输出长度显著短于由页面密度估计的范围,系统可以自动升级分辨率重试. 这种检测不需要知道 ground truth,但对本来就有大图少字的页面会误报. 结合文字检测框数量会更稳妥.

**插入与重复常来自自回归退化**

模型可能重复一行,表格标签或段落. 官方 n-gram processor 正是为限制长重复. 重复不一定表示视觉容量不足:视觉前缀足够,解码器仍可能进入循环. 增加视觉 token 未必解决,更适合调整解码约束或训练长序列终止行为.

**结构错误需要树或图指标**

表格行列交换,公式括号层级错误,SMILES 环编号错误都可能只有少数字符差异,语义后果却很大. 将输出解析成抽象结构后比较,能区分语法有效性与表面字符串接近度. 若解析失败,应单独计为结构失败,而非只并入平均 edit distance.

按错误类型选择档位更合理. 局部替换和删除随分辨率改善,重复主要由解码控制,阅读顺序需要全局视图. 把所有错误合成一个 overall 后简单增加 token,可能对真正瓶颈无效.

**与文本摘要和向量检索的关系**

**三种压缩保留的信息不同**

文本摘要把长文生成较短自然语言,保留模型判断的重要语义,通常无法逐字恢复. 向量检索把文档切块并存储嵌入,查询时只取相关片段,不要求所有历史同时进入上下文. 光学压缩把整页映射成连续视觉前缀,目标可以是全文可解码.

摘要的优势是输出仍是文本 token,无需视觉编码器;代价是生成摘要时已经作出语义选择. 检索保留原文,但依赖查询与索引召回. 光学表示保留页面全局结构,却受视觉分辨率与解码误差影响. 三者可以组合,没有必要互相替代.

**光学压缩适合保留未知未来查询的页面**

当未来问题未知,摘要可能删掉后来需要的细节. 视觉前缀若仍能解码全文,理论上保留更广信息. 但高压缩下精度下降,未知查询恰好命中错误字符的风险仍在. 对关键事实,检索原文更可靠.

一种分层系统可以让视觉前缀常驻热上下文,原文块进入外部检索. 模型先用视觉表示回答或判断相关页,再在低置信时加载原文. 这样利用视觉 token 的页面级压缩,同时避免把有损表示当作唯一真相.

**二维渲染对本来就有版面的内容更自然**

PDF,幻灯片,表格和图表原生具有二维结构,文本线性化会丢失坐标或生成大量标记. 光学表示直接接受现有页面,无需先决定阅读顺序. 对纯聊天记录,二维渲染主要是人为编码,收益更依赖字体排版与 OCR 先验.

所以文档解析结果不能无条件外推到所有长文本. 代码依赖精确缩进与符号,日志含大量随机标识符,它们的语言冗余低;普通叙事文本冗余更高. 各类型需要独立率失真曲线.

## 5. 一组能够区分机制的消融

**控制字符熵**

保持字体,字号,页数和文本 token 数不变,分别渲染自然语言,词序打乱文本和随机字符. 三者视觉复杂度接近,语言熵逐步升高. 若自然语言远好于随机字符,说明解码器先验承担了重要压缩. 再按压缩比绘制曲线,可以估计视觉信道与语言冗余各自贡献.

**控制空间密度**

将同一文本渲染为单栏大字,双栏小字和稀疏分散布局,保证内容完全相同. 若错误随字符像素高度变化,主要瓶颈在感知与下采样;若大字多栏仍有顺序错误,主要瓶颈在全局布局. 这组实验还能检验 16 倍压缩器对小字的敏感性.

### 5.1. 控制解码器容量

固定 DeepEncoder,分别使用较弱与较强语言解码器,或在正确前缀教师强制下测试. 强解码器若只提升自然文本而不提升随机串,收益主要来自语言建模;两者都提升则说明视觉表示中有信息但小解码器读不出.

**控制视觉 token 数与输入分辨率**

当前档位同时改变分辨率和 token 数,两个变量耦合. 可以将高分辨率输入压到 64 token,也将低分辨率输入映射到 256 token. 前者测瓶颈容量,后者测原始像素上限. 若高分辨率 64 token 优于低分辨率 256 token,说明输入笔画清晰度更关键;反之则表示表示槽位不足.

**测试下游任务而非全文恢复**

为每页生成精确问答,关系推理,数字查找和摘要任务. 在不同压缩档位下同时测 OCR 与任务正确率. 两条曲线可能不平行:摘要在高压缩下保持,数字查找快速下降. 这才直接回答渐进遗忘能否服务 LLM 上下文.

**复用 DeepSeek-OCR 时的原则边界**

视觉 token 数适合作为 **解码器上下文预算**,不适合作为文件压缩比. 其收益应在相同隐藏维度,视觉编码成本和输出任务下比较. 当源内容已经是图像文档时,这条路径省去传统多模块流水线;当源内容本来是文本时,还要计入渲染与编码.

Fox 曲线适合说明自然英文文档的经验容量,高风险字段需要单独评测. 随机数字,代码,公式与低资源语言的熵和视觉结构不同,不能套用同一安全倍率. 页面越密集,越应增加局部视图或保留原文回退.

DeepEncoder 的核心结构关系可以压缩成一条信号路径:高分辨率局部感知先提取笔画,学习型卷积把空间信息转移到通道并将位置数降 16 倍,全局视觉模块再建立页面关系,投影后的短前缀由 MoE 解码器展开成文本或结构. 每一步都对应明确代价:窗口限制远程交互,下采样可能混叠,全局模块看不到已丢细节,语言解码可能用先验补错.

长期记忆设想需要把时间衰减改造成价值感知的预算分配. 旧信息可以更模糊,关键数字与身份字段仍应保真;热上下文可以保存视觉表示,冷存储保留原文;模型可在低置信时回源. 没有这些机制时,降分辨率只是按字形大小遗忘,尚未实现按语义价值遗忘.

DeepSeek-OCR 最重要的研究价值由此变得具体:它把视觉编码器从辅助感知模块提升为上下文信道,并给出第一条可测的序列长度—恢复误差曲线. 这条曲线开启了新的设计空间,同时要求后续工作用信息率,任务保持率和端到端成本补齐评价坐标.

**压缩倍率的手算揭示什么**

**同一档位随页面长度改变工作点**

Tiny 固定 64 个视觉 token. 页面分别含 640,960 和 1280 个文本 token 时,压缩比分别为

$$
640/64=10,\qquad 960/64=15,\qquad 1280/64=20.
$$

模型和图像分辨率没有改变,仅页面文字增加就从较可靠区间移动到明显失真区间. 因而「Tiny 模式准确率」不是单一常数,必须附带页面密度. Small 的 100 token 对同三页分别是 6.4,9.6 和 12.8 倍,拥有更大余量.

若一个 1280 token 页面采用 Base 的 256 个槽位,理论比值为 5 倍;若长宽比 1:2 使有效 token 约 128,有效比值又回到 10 倍. 这里暴露了两个口径:张量序列仍占 256 槽位,内容区域只覆盖约 128 个位置. 前者决定实际 KV 与计算,后者更接近信息密度. 报告比较平均有效 token 时强调后者,部署核算显存时还要看前者.

**页面数吞吐可换算平均时间但不能外推延迟**

单卡每天 20 万页对应平均

$$
\frac{86400}{200000}\approx0.432
$$

秒/页. 这是高并发生产吞吐的摊销值,不等于单请求延迟. batch 会并行处理多页,视觉编码与解码也可能流水重叠. 一页输出很短的幻灯片和数千 token 的报纸耗时不同,平均数还依赖页面分布.

20 节点共 160 张卡,若线性按 20 万页/卡估算,理论上约 3200 万页/天,与报告的 3300 万页规模接近. 这种一致性说明单卡与集群数字采用相近口径,仍没有给出质量过滤后的保留页数. 数据生产的有效吞吐应为

$$
T_{valid}=T_{raw}(1-p_{fail})(1-p_{reject}),
$$

其中 $p_{fail}$ 是推理或解析失败率,$p_{reject}$ 是质量过滤淘汰率.

### 5.2. 视觉前缀越短,长输出中的收益越大

假设原文历史为 1000 token,视觉压缩为 100 token,后续生成 500 token. 忽略层宽和常数,decode 注意力读取的历史位置总量可粗略比较为

$$
\sum_{i=1}^{500}(1000+i)
\quad\text{与}\quad
\sum_{i=1}^{500}(100+i).
$$

两者相差 $500\times900=450000$ 次位置读取. 但若任务本身是 OCR 全文恢复,视觉方案还要生成原来的 1000 token;若任务只回答一句话,输出可能几十 token. 所以光学上下文的计算收益取决于使用方式,不只取决于 $N/n$.

**不确定性怎样变成可操作信号**

**token 概率只覆盖解码器不确定性**

自回归解码器在每一步给出词表分布. 最大概率低或熵

$$
H_i=-\sum_v p(v\mid Z,y_{<i})\log p(v\mid Z,y_{<i})
$$

较高,说明当前字符或子词有多个候选. 可以按区域聚合熵,触发更高分辨率重试. 但神经网络可能高置信地产生语言上常见、视觉上错误的词,因此概率没有天然校准.

解码温度为 0 时无法用采样方差估计不确定性. 可以比较不同档位输出:Small 与 Base 在某字段一致时提高信心,不一致时升级 Gundam 或回源. 也可以让独立 OCR 系统再次识别数字与实体. 这种一致性仍是启发式,共享训练数据的模型可能犯相同错误.

**局部重读比整页升级节省 token**

若模型能输出文本区域坐标,低置信字段可以裁成局部图重新识别. 设整页 Gundam 需要 800 token,一个局部块为 100 token;只重读两个区域会增加 200,低于整页升级. 这把固定档位变成渐进计算:先用 Small 扫描,再为疑难区域追加视觉证据.

局部重读需要将输出字符映射回页面坐标. 若初次阅读顺序错误,坐标关联可能失效. Grounding prompt 与版面标注为这一机制提供接口,论文没有报告基于置信度的自适应重读实验.

**关键字段应采用规则校验**

日期,金额,身份证号和化学式常有格式约束. 校验和,正则或领域解析器可以发现部分错误. 例如表格金额合计与明细不一致时,系统可定位相关单元格重读. 这些约束提升可靠性,但属于任务外部知识,不能用来宣称视觉编码本身无损.

**与传统 OCR 流水线的机制差异**

**显式中间结果换成隐式序列状态**

传统系统依次做文字检测,行框排序,字符识别和版面重建. 每一阶段有可观察中间结果,方便定位错误,但上游框偏移会传播到下游. DeepSeek-OCR 直接从视觉前缀生成最终序列,区域与阅读顺序隐含在模型状态中.

端到端训练允许最终文本损失共同调整特征,避免各模块目标错位. 代价是可解释性下降:漏掉一段时很难直接判断检测,排序还是解码出了问题. Deep parsing 的 prompt 将多任务统一,没有消除这些潜在子问题.

**流水线可以保留高分辨率局部证据**

检测器先找出文字框后,识别器可逐框放大,所以小字不必与整页共享固定视觉 token. DeepSeek-OCR 的 Gundam 局部块在一定程度上恢复这一能力,但裁块粒度比文字框粗. 规则档位换来统一结构,在极端密集页上可能需要更多冗余 token.

传统系统还可为每个字符输出坐标与置信度,便于人工校对. 端到端 Markdown 更自然,字符级对齐则需要额外 grounding. 两条路线的优劣取决于输出任务,不能只用总体 token 数比较.

**错误传播方向不同**

流水线的检测遗漏会让后续永远看不到区域,但已检测区域之间较独立. 自回归端到端模型读取整页,理论上能利用全局上下文纠错;一次早期生成错误又会成为后续条件,可能扰乱长段结构. n-gram processor缓解重复,无法纠正阅读顺序选择.

实际系统可以保留混合诊断:端到端模型生成 Markdown,轻量检测器检查文字区域覆盖,结构解析器验证表格与公式. 这些模块给黑盒序列输出增加可观测约束,又无须接管主识别路径.

**多语言压缩的特殊变量**

### 5.3. 字符集与字体改变视觉难度

拉丁字母的基本笔画较少,中文字符在相同字号中包含更多局部结构,阿拉伯文还有连写与上下文形变. 输入像素高度相同不代表可辨信息相同. 压缩器的 16 倍空间下采样可能更早损害复杂字形.

文本 tokenizer 对各语言的分词效率也不同. 某语言平均每字符需要更多 token,报告比值 $N/n$ 会显得更高,其中一部分来自 tokenizer,一部分来自视觉难度. 多语言容量比较应同时报告字符错误率,每字符文本 token 数和视觉 token 数.

**低资源语言面对双重稀缺**

训练页数少意味着字体与版面覆盖不足,教师 OCR 也可能更弱. 飞轮扩大样本时,伪标签错误更难被独立监督纠正. 通用视觉和语言解码器可以迁移笔画与文档结构,无法替代罕见字符真值.

逐语言测试还应控制脚本重叠. 使用拉丁字母的低资源语言可能从英语迁移,独特文字系统的难度更高. 论文的近 100 种语言样例展示覆盖范围,尚未形成每种语言的可靠压缩阈值.

**混合语言页面增加路由压力**

科研文档可能同时包含中文正文,英文术语,LaTeX 公式和代码. 解码器要在词表与专家间快速切换,视觉编码器还要保存不同尺度的字形. 按整页指定单一语言无法解决局部切换.

混合页面的错误应按片段语言统计. 如果 overall 由大量中文正文主导,少量公式或英文专名失败会被平均掩盖. 这也是领域文档需要字段级验收的原因.

**论文与公开实现的证据接口**

[DeepSeek-OCR 技术报告](https://arxiv.org/abs/2510.18234)定义光学压缩比,DeepEncoder,训练数据与 Fox、OmniDocBench 实验. [DeepSeek-OCR 官方仓库](https://github.com/deepseek-ai/DeepSeek-OCR)给出 Tiny 到 Gundam 的公开模式,prompt,权重和 vLLM/Transformers 推理设置. [General OCR Theory](https://arxiv.org/abs/2409.01704)把普通文字,公式,表格,图表,乐谱与几何形状统一到 OCR 2.0 的「人工光学字符」范围,解释了 DeepSeek-OCR 数据引擎为何超出传统文字识别.

三者连成一条清楚的技术路线:GOT 先把端到端 OCR 的输出范围扩展到结构化人工符号,DeepSeek-OCR 再把视觉编码器的输出长度提升为核心研究变量,官方仓库则把多分辨率与结构化提示变成可运行接口. 信息论推导,成本手算和失效分类沿这些公开定义展开,目的是标出实验数字适用的条件.

截至原始技术报告,视觉 token 高压缩已经在文档恢复和实际基准上得到验证;视觉记忆替代文本上下文仍需下游长程任务. 这两层结论同时保留,才能既看到 DeepEncoder 的新意,也避免把一条 OCR 率失真曲线提前写成通用长期记忆方案.

**从页面压缩推广到上下文压缩的必要条件**

第一项条件是 **任务接口能读取视觉前缀**. DeepSeek-OCR 的解码器在训练中学过图像到文本和结构化输出;普通纯文本 LLM 没有视觉入口,不能直接消费 DeepEncoder token. 即使另接投影层,共享隐藏维度也不保证模型理解其含义,仍需要视觉—语言对齐训练.

第二项条件是视觉表示与后续文本能够交错. 长对话可能由旧页面,最近文本,工具结果和新图像组成. 模型要区分各段边界,建立跨模态位置关系,并在回答时同时引用. 仅训练单页 OCR 时,视觉前缀后面紧跟该页转写;它没有覆盖隔了许多轮之后再查询页面细节的分布.

第三项条件是压缩误差可以被发现. 若模型把视觉前缀中的模糊数字自信地补成常见值,后续推理会在错误事实上保持逻辑一致. 系统至少要保存字段置信度,页面来源和原文定位,让答案能够触发回源. 没有来源指针的连续视觉 token 很难单独承担可审计记忆.

第四项条件是节约大于新增成本. 对原生 PDF,视觉入口本来就需要;对纯文本历史,渲染,DeepEncoder 和更复杂的多模态 prefill 都是新增项. 只有在历史较长,复用次数较多或 KV 预算紧张时,短视觉前缀才更可能获得端到端收益. 对几百 token 的短对话,直接保留文本通常更简单也更精确.

第五项条件是遗忘策略与任务风险匹配. 普通闲聊允许语义级恢复,代码补丁,财务数字与医疗剂量要求逐字符保真. 同一个时间衰减规则不能同时服务这些内容. 视觉压缩应成为多层记忆中的一种表示,由风险和价值路由,而非覆盖所有历史的唯一格式.

这五项条件把压缩曲线连接到上下文系统:曲线帮助选择每页视觉预算,估计恢复风险,并决定何时加载原文. 当前实验已充分支撑高 token 效率的文档视觉编码与解码;用于长期上下文时,还要逐项验证上述接口,交错训练,回源,成本和风险条件.
