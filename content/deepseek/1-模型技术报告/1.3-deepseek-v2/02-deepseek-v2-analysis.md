# DeepSeek-V2: 用 MLA 压推理显存, 用 MoE 压训练算力

来源: [DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model](https://arxiv.org/abs/2405.04434) (arXiv: 2405.04434v5, 2024-06-19). 仓库: https://github.com/deepseek-ai/DeepSeek-V2

DeepSeek-V2 总参 236B, 每个 token 激活 21B, 上下文 128K, 在 8.1T token 上预训练, 再经 1.5M 条 SFT 和两阶段 GRPO 得到 Chat 版. 摘要里的三组数字最常被引用: 相对 DeepSeek 67B 训练成本省 42.5%, KV cache 减 93.3%, 最大生成吞吐 5.76 倍. 这三组数字分别来自不同的环节: 42.5% 主要来自 MoE 的稀疏计算, 93.3% 是 MLA 和部署期 KV 量化叠在一起的结果, 5.76 倍则是显存省下来以后 batch 能开大的连锁效应. 读这份报告, 要把架构, 数据, 训练日程, 对齐和评测放在一起看, 才能分清哪一部分收益来自哪一步.

## 1. 起点与注意力: MLA

**起点: 67B 卡在哪里**

前一代 DeepSeek LLM 67B 是 Dense 模型, 95 层, 隐宽 8192, 64 个 query 头, 8 组 KV 的 GQA, 在 2T token 上训练. 它有两个瓶颈. 训练侧, 每个 token 都要走完全部 67B 参数, 算力随参数线性涨. 推理侧, 每个 token 在每层要缓存 $2\times 8\times 128=2048$ 个 KV 元素, 95 层合计 194,560 个(按 67B 配置推算), BF16 下约 380 KB; 128K 上下文单条请求就要约 47 GB, 一张 80 GB 的卡放不下几条长请求.

V2 同时处理这两个瓶颈. 注意力换成 Multi-head Latent Attention(MLA), 解决推理缓存; FFN 换成 DeepSeekMoE, 解决训练算力. 其余小设定(RMSNorm, SwiGLU 激活, 分词器)沿用 67B, 数据流水线也沿用 67B 的阶段划分. 这意味着 V2 相对 67B 的提升混合了架构, 数据量和数据配比三个因素, 报告没有做「只换架构, 数据不变」的对照, 这一点在看后面的 Base 分数时要记着.

### 1.1. MLA: 把 K, V 压进一个共享的低维向量

标准 MHA 每个 token 每层缓存 $2n_hd_h$ 个元素. GQA 和 MQA 让多个 query 头共用一组 K, V 来减缓存, 代价是表达能力. 附录 D.1 的对照说明了这个代价: 三个约 7B 的 Dense 模型同训 1.33T token, 只改注意力并调层数对齐参数, MHA 的 MMLU 45.2, GQA(8 组) 41.2, MQA 37.9; C-Eval 分别是 42.9, 37.7, 30.0. 在这个规模上, 省缓存的老办法要付出 4 到 13 个点.

**MLA** 换了一个思路: 不减头数, 而是把 K 和 V 先联合压成一个低维潜向量 $\mathbf{c}_t^{KV}=W^{DKV}\mathbf{h}_t$(式 9), 再用 $W^{UK}$, $W^{UV}$ 上投影回每个头的 K 和 V(式 10–11). 推理时只缓存 $\mathbf{c}_t^{KV}$, 每层 $d_c$ 个元素. V2 取 $d_c=512$, 而 MHA 在同样 128 头, 每头 128 维下要存 32,768 个. 更关键的是**矩阵吸收**: 注意力分数 $\mathbf{q}^T\mathbf{k}=\mathbf{h}^TW^{Q\,T}W^{UK}\mathbf{c}$, 中间两个矩阵可以预先乘成一个, 推理时 query 直接和缓存的潜向量做内积, 不用把每个历史 token 的 K 展开出来; $W^{UV}$ 同理吸进输出投影 $W^O$. 中文技术社区的实现笔记指出, 吸收后 128 个头共享同一份 $\mathbf{c}^{KV}$, 计算形态接近 MQA, 算术强度正比于头数, 这对显存带宽受限的解码阶段很有利.

矩阵吸收也有代价. 吸收之后, 每个头的 query 要先映射到 512 维的潜空间, 再和每个历史 token 的潜向量做内积, 单头单 token 的点积长度从 128 变成 512 加 64. 解码阶段每步只有一个新 token, 瓶颈是读缓存的显存带宽, 多算一点不要紧; 预填充阶段一次处理整段 prompt, 算力才是瓶颈, 这时把 K, V 显式展开反而更省. 所以公开的推理实现通常在预填充时展开, 解码时吸收. 报告附录 C 只说「推理时可以吸收」, 没有区分这两个阶段.

Query 也做了低秩压缩, $d_c'=1536$(式 12–13), 但目的只是省训练期的激活显存, 与 KV cache 无关. 低秩压缩会改变层输出的尺度, 所以报告在压缩潜向量之后加了 RMSNorm, 并在宽度瓶颈处(潜向量和路由专家的中间态)乘额外的缩放系数来稳住训练. 缩放系数取多少, 报告没有给. 机制推导见 [MLA: 低秩潜变量与矩阵吸收](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md), GQA 的折中思路见 [GQA: 在性能与缓存之间折中](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md).

**解耦 RoPE, 以及 93.3% 是怎么算出来的**

RoPE 和矩阵吸收不兼容. 如果对上投影后的 $\mathbf{k}_t^C$ 施加 RoPE, 与当前位置相关的旋转矩阵就会夹在 $W^Q$ 和 $W^{UK}$ 中间, 矩阵乘法不满足交换律, 两者不能预先合并, 推理时又得为所有前缀 token 重算 K. 报告的办法是**把位置信息单独拿出来**: 另开每头 $d_h^R$ 维的 $\mathbf{q}_{t,i}^R$ 和一个所有头共享的 $\mathbf{k}_t^R$ 专门承载 RoPE(式 14–15), 内容部分 $\mathbf{q}^C$, $\mathbf{k}^C$ 不加位置编码, 继续走吸收路径; 两部分拼接后算注意力, 分母改成 $\sqrt{d_h+d_h^R}$(式 18). 共享的 $\mathbf{k}_t^R$ 直接从 $\mathbf{h}_t$ 投影, 不经过潜向量, 也要进缓存. 社区里常把 $\mathbf{k}^R$ 描述成「MQA 版的 RoPE」: 位置这一路只有一个头, 内容这一路有 128 个头.

V2 取 $d_h^R=64$, 每层缓存 $512+64=576$ 个元素, 等于 $4.5d_h$. Table 1 说这相当于「只有 2.25 组的 GQA」, 就是由 $2n_gd_h=4.5d_h$ 解出来的. 这个数可以和附录交叉验证: 60 层乘 576 是 34,560, 正好是表 9 里大号 MoE 带 MLA 那一行的 34.6K; Lite 的 27 层乘 576 是 15,552, 对上表 9 小号 MoE 带 MLA 的 15.6K. 相对同配置 MHA 的 32,768, 缩到约 1/57.

再算相对 67B 的缩减. 67B 每 token 194,560 个元素, V2 是 34,560 个, 只按元素数算, 缩减为 82.2%. 报告在 §3.2.3 还写了部署时把 KV 平均量化到 **6 bit**; 如果拿 V2 的 6 bit 对比 67B 的 16 bit, $34{,}560\times 6\,/\,(194{,}560\times 16)\approx 6.7\%$, 缩减正好是 93.3%. 摘要里的 93.3% 很可能合并计算了 MLA 与 KV 量化, 而 Table 1 的脚注又明确说缓存量「按元素数计, 不论存储精度」. 两处口径不一致, 报告没有说明. 按元素数归因时, MLA 对应 82.2% 的缩减, 其余差距来自量化精度.

换成实际显存更直观. V2 每 token 34,560 个元素, BF16 下约 67.5 KB, 128K 上下文单条请求约 8.4 GB; 67B 同长度约 47 GB. 同一台 8×H800 能并发的长请求数因此多出好几倍, 这就是 5.76 倍生成吞吐的主要来源. 吞吐测试用的 prompt 和生成长度分布取自线上 67B 服务的真实流量, 并且叠加了 FP8 权重和 6 bit KV 量化, 所以 5.76 倍衡量的是整套部署方案, 不是 MLA 单独的贡献. 生成吞吐超过 50K token/s, prompt 吞吐超过 100K token/s, 这两个数都是单节点 8 卡的结果.

**注意力消融能证明多少**

附录 D.2 用两档 MoE 比较 MLA 和 MHA. 小档总参约 16B, 训 1.33T token: MHA 激活 2.5B, 缓存 110.6K; MLA 激活 2.4B, 缓存 15.6K, 约为前者的 14%; 四项硬基准里 MLA 赢三项(BBH 39.0 对 37.9, MMLU 50.0 对 48.7, CMMLU 53.4 对 52.3), C-Eval 输 0.7(50.9 对 51.6). 大档总参约 250B, 只训 420B token: MHA 激活 25.0B, 缓存 860.2K; MLA 激活 21.5B, 缓存 34.6K, 约为 4%; 四项全赢, BBH 50.7 对 46.6, MMLU 59.0 对 57.5, C-Eval 59.2 对 57.9, CMMLU 62.5 对 60.7.

这组结果支持「MLA 不比 MHA 差」, 证据仍有三项限制. 其一, 大档只训练了 420B token, 约为正式训练量的 5%, 早期优势能否保持到 8.1T 尚无数据. 其二, 从缓存量反推, 小档 MHA 每层 4,096 个元素, 即 16 头乘 128 维, 与 Lite 一致; 大档 MHA 每层约 14,336 个元素, 若每头 128 维则只有 56 个头, 而 MLA 设定使用 128 头. 报告称两者「除注意力外架构相同」, 却未列出 MHA 的头数和维度, 因此一部分差异可能来自头数. 其三, 每档每个设置只训练一次且没有误差条, 1 个点以内的差距缺少统计稳定性证据.

表 8 和表 9 合起来看, 报告想说明的是一条链: GQA, MQA 比 MHA 差, MLA 又不比 MHA 差, 所以 MLA 同时拿到了省缓存和保质量. 前半条链在 7B Dense 上测, 后半条在 MoE 上测, 两者不在同一个模型族里. 表 8 为了对齐参数量调整了层数, MQA 版本 7.1B, 另外两个 6.9B, MQA 省下的 KV 投影参数被换成了更多的层, 所以它和 MHA 的差距不是「同样深度下少了 KV 头」那么单纯. MLA 和 GQA 的直接对比, 报告没有给.

### 1.2. DeepSeekMoE

**DeepSeekMoE: 细专家, 共享专家和设备受限路由**

FFN 侧沿用 DeepSeekMoE 的两个做法(式 20–22). 一是把**专家切细**: 在总专家参数不变时, 专家越小, 数量越多, 激活组合就越多, 每个专家更容易学到专门的知识. 二是**隔离共享专家**: 每个 token 都经过的共享专家负责通用知识, 减少路由专家之间的重复. V2 除第一层外全部换成 MoE, 每层 2 个共享专家加 160 个路由专家, 专家中间宽 1536, 每 token 激活 6 个路由专家. 一层 MoE 的输出是

$$
\mathbf{h}_t'=\mathbf{u}_t+\sum_{i=1}^{N_s}\mathrm{FFN}_i^{(s)}(\mathbf{u}_t)+\sum_{i=1}^{N_r}g_{i,t}\,\mathrm{FFN}_i^{(r)}(\mathbf{u}_t),\qquad s_{i,t}=\mathrm{Softmax}_i(\mathbf{u}_t^\top\mathbf{e}_i),
$$

$g_{i,t}=s_{i,t}$ 当 $s_{i,t}$ 在 $N_r$ 个亲和度的 Top-$K_r$ 内, 否则为 0. 第一项是残差; 第二项 $N_s=2$ 个共享专家不经门控, 权重恒为 1, 每个 token 都走; 第三项 $N_r=160$ 个路由专家里只有 $K_r=6$ 个非零. $\mathbf{e}_i$ 是专家 $i$ 的中心向量, 亲和度就是 token 和它的内积. Softmax 是在全部 160 个专家上做的, 取 Top-6 之后不再归一化, 所以 6 个门控之和小于 1, 路由越分散, 路由专家这一路的输出就越小, 共享专家那一路的相对分量越大. 这套结构的机制讨论见 [DeepSeek-MoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md).

细粒度带来一个副作用: 激活专家多, 如果它们散在很多张卡上, 专家并行的 all-to-all 通信就会变贵. 每层 160 个路由专家均匀铺在 8 张卡上($D=8$), 每卡 20 个, 不加限制时一个 token 的 6 个专家最多可能落在 6 张卡上. **设备受限路由**(device-limited routing)先按每张卡上最高的亲和度挑出 $M$ 张卡, 再只在这些卡的专家里做 Top-6. V2 取 $M=3$, 报告称 $M\ge 3$ 时效果与不受限的 Top-K 大致持平, 但没有附表, 也没有给出 $M=1$ 或 $M=2$ 的数字.

用配置可以反推 236B 和 21B 是怎么构成的. 一个 SwiGLU 专家有三个 5120×1536 的矩阵, 约 23.6M 参数; 每层 162 个专家约 3.8B, 59 个 MoE 层合计约 225B. 每 token 激活 2 个共享加 6 个路由, 共 8 个专家, 59 层约 11.1B. 注意力一层的投影矩阵加起来约 149M(其中输出投影 $W^O$ 就有 128×128×5120, 约 84M), 60 层约 9B. 再加约 1B 的输入输出词嵌入和第一层的 Dense FFN, 激活参数约 21B, 总参约 235B, 与报告的 21B 和 236B 对得上. 这笔推算说明, V2 激活的 21B 里注意力占了四成以上, 专家只占一半左右; MLA 省的是缓存, 不是参数.

这个限制还给了发送端一个硬上界: 每张卡最多向外发送 $MT$ 个隐状态, $T$ 是序列 token 数. 共享专家不需要跨卡, 所以 V2 把共享专家的计算和专家并行的 all-to-all 通信重叠起来, 让等通信的时间也在算东西. 这一步是训练效率的关键之一, 但重叠带来的具体提速比例, 报告没有给.

**三级均衡损失和 token-dropping**

路由不均衡有两个后果: 一部分专家训不到, 出现路由塌缩; 专家并行时, 忙的卡拖慢整层. V2 叠了**三级辅助损失**. 专家级一项写全是

$$
\mathcal{L}_{\mathrm{ExpBal}}=\alpha_1\sum_{i=1}^{N_r}f_iP_i,\qquad f_i=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb{1}(\text{token }t\text{ 选中专家 }i),\qquad P_i=\frac{1}{T}\sum_{t=1}^{T}s_{i,t},
$$

$\alpha_1=0.003$. 一个序列 $T$ 个 token 各选 $K_r$ 个专家, 共 $K_rT$ 次选择, 均匀时每个专家分到 $K_rT/N_r$ 次, 前面的系数 $N_r/(K_rT)$ 就是把这个值归一到 $f_i=1$. $P_i$ 是专家 $i$ 在这段序列上的平均 Softmax 亲和度, $\sum_iP_i=1$. 均匀路由时 $\sum_if_iP_i=N_r\cdot1\cdot\frac{1}{N_r}=1$. $f_i$ 来自 Top-K 的指示函数, 不可导, 梯度只经 $P_i$ 流回路由器, 而 $P_i$ 前面的权重正是 $f_i$: 被选得越多的专家, 它的亲和度被往下压得越重, 冷门专家几乎不受压. 这就是乘积形式的作用, 用不可导的计数给可导的概率加权. 设备级 $\mathcal{L}_{\mathrm{DevBal}}$(式 26–28)把同卡专家的 $f$ 取平均, $P$ 求和, $\alpha_2=0.05$. 通信级 $\mathcal{L}_{\mathrm{CommBal}}$(式 29–31)的 $f''$ 统计的是 token 被发往某卡的频率, 用 $D/(MT)$ 归一化, $\alpha_3=0.02$; 归一化的道理和专家级相同: 每个 token 最多发往 $M$ 张卡, 共 $MT$ 次发送, 均匀时每卡 $MT/D$ 次, 归一后 $f''_i=1$; 设备受限路由限住了发送端, 这一项鼓励每张卡接收的量也在 $MT$ 左右.

读公式时会发现, 设备级和通信级两项的 $P$ 完全相同(都是同卡专家亲和度之和), 区别只在 $f$: 一个是同卡专家被选频率的均值, 一个是「被发送到该卡」的频率. 仓库的 GitHub issue 里有人提过这两项几乎等价, 讨论者后来认为差别在于「发送」只计跨卡的 token. 报告正文没有这个解释, 也没有三级损失各自的消融. 三个系数里设备级最大, 专家级最小, 说明作者更在意卡间的均衡, 对专家间的轻微不均更宽容, 这和细粒度专家本来就希望专业化分工的设计一致.

辅助损失保证不了严格均衡, 所以训练时还加了**设备级 token-dropping**: 每卡的算力预算按平均值算(容量因子 1.0), 超出预算时丢掉该卡上亲和度最低的 token, 被丢的 token 在这一层只走残差. 约 10% 的训练序列永远不丢, 这样推理时可以按效率需要选择丢或不丢, 训练里两种情况都见过. 评测时一个 token 都不丢. 这个设计把「训练吞吐」和「评测分数」分开, 但也意味着训练时约 90% 的序列里有一部分 token 在某些层没有经过专家; 报告没有给出实际丢弃率.

**预训练**

### 1.3. 数据与训练日程

67B 的数据流水线分去重, 过滤, 再混合三步, 去重跨 91 个 Common Crawl dump 一起做. V2 沿用这三步, 但做了四处改动: 改进清洗流程, 找回大量此前被误删的网页数据; 显著增加中文; 改进基于质量的过滤算法, 并补充多来源的高质量数据; 过滤争议内容, 减少特定地域文化带来的偏见. 分词器仍是 67B 的 100K 词表 BBPE. 8.1T token 里中文比英文多约 12%. 如果只算中英两种, 英文最多约 3.8T, 这和 §3.2.2 里「英文 token 不到 LLaMA3 70B 的四分之一」的说法一致. 代码, 数学的占比和各来源配比, 报告没有给.

训练超参: 60 层, 隐宽 5120, 128 头, 每头 128 维, 参数初始化标准差 0.006. AdamW, $\beta_1=0.9$, $\beta_2=0.95$, weight decay 0.1, 梯度裁剪 1.0. 学习率前 2K 步线性升到峰值 2.4e-4, 训到约 60% 和 90% token 时各乘 0.316, 这个系数约为 $1/\sqrt{10}$, 两次之后学习率是峰值的 1/10. Batch 在前 225B token 内从 2304 条增到 9216 条, 之后固定. 序列长 4K, 所以稳定期每步约 37.7M token, 剩余约 7.9T token 大约对应 21 万步. 和 67B 比, 峰值学习率从 3.2e-4 降到 2.4e-4, batch 从固定 4608 条变成最终 9216 条. 67B 报告里拟合过超参的 Scaling 规律: 算力预算越大, 最优 batch 越大, 最优学习率越小. V2 的训练算力比 67B 大, 两个超参的调整方向与这条规律一致, 但报告没有说是否按那套公式算出来的. Batch 先小后大, 让早期 loss 下降快的阶段多走几步更新, 等梯度噪声变大再换大 batch, 这是 batch size warmup 的常见理由, 报告只写了做法, 没写理由. 这套分段下降的日程来自 67B 的 Scaling 实验, 好处是可以从中间 checkpoint 续训, 后来 Coder-V2 就是从 V2 的中间 checkpoint 出发继续训练的.

训练框架是自研 HAI-LLM: 16 路 zero-bubble 流水线并行, 8 路专家并行, ZeRO-1 数据并行. 激活参数少, 再对部分算子做重算节省激活显存, 所以完全不用张量并行. 通信, 路由和跨专家的融合线性层都写了专门的 CUDA kernel, MLA 基于改进版 FlashAttention-2. 集群是 H800, 节点内 NVLink/NVSwitch, 节点间 InfiniBand. 实测每训 1T token, 67B 要 300.6K GPU 小时, V2 要 172.8K, 这就是 42.5% 的来源. 按此推算, V2 预训练约 **140 万** GPU 小时, 67B 的 2T 约 60 万. 如果只看激活参数, V2 每 token 的 FFN 计算量约是 67B 的 31%, 实际成本却是 57.5%, 说明 MoE 的通信和负载不均吃掉了接近一半的理论收益(未计注意力计算量差异). 报告只说「MFU 相对较高」, 没有给具体数值.

预训练阶段没有混入 SFT 数据. 报告以 MiniCPM 在预训练中加入 SFT 数据的做法作对照, 并声明 Table 2 的 Base 分数未受指令数据影响. 这是报告给出的数据口径, 公开材料没有提供独立核查方法.

**YaRN 把 4K 扩到 128K**

预训练结束后用 YaRN 把窗口从 4K 扩到 128K. 在 MLA 里只有解耦的 $\mathbf{k}_t^R$ 和 $\mathbf{q}^R$ 带 RoPE, 所以 YaRN 只作用在这 64 维上. 参数: 扩展倍数 $s=40$, $\alpha=1$, $\beta=32$, 目标上限 160K(4K 乘 40), 期望 128K 可用. YaRN 原版用一个随 $s$ 变化的注意力温度调节 softmax 的熵, 原式是 $\sqrt{1/t}=0.1\ln s+1$; V2 把系数改成 0.0707, 报告写作 $\sqrt{t}=0.0707\ln s+1$, 目标是让困惑度最低. 频率插值的机制见 [长度外推: 从 PI 到 YaRN 的频率扩展](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md).

这里有一个实现层面的细节. 原版 YaRN 通常把温度乘到 RoPE 的 cos/sin 上, 让 q 和 k 各自放大 $\sqrt{1/t}$, 点积就放大 $1/t$. 这个做法要求整个 q, k 向量都经过 RoPE; MLA 里只有 64 维带 RoPE, 另外 128 维不带, 乘在 cos/sin 上只会放大一部分. llama.cpp 社区在移植时讨论过这个问题, 公开推理代码的做法是把温度移到 softmax 的缩放系数上. 按 $s=40$ 算, V2 的系数约 1.26, 原版约 1.37. 另外社区指出报告里的 $\sqrt{t}$ 应为 $\sqrt{1/t}$, 属于笔误.

长上下文训练只有 1000 步, 序列 32K, batch 576 条, 合计约 18.9B token, 不到预训练量的 0.3%. 训练只在 32K 上做, 评测却到 128K, Figure 4 的 Needle-In-A-Haystack 在全部长度和深度上都表现良好. 但大海捞针只测「能不能找到一句插入的话」, 不测多跳推理和长文摘要. 报告没有提供 LongBench, RULER 一类的长上下文评测, 因而「128K 可用」只有这一张检索测试图支持.

## 2. 对齐

**SFT 和两阶段 GRPO**

SFT 数据扩到 1.5M 条, 其中有用性约 1.2M, 安全约 0.3M, 覆盖数学, 代码, 写作, 推理, 安全等领域, 相对 67B Chat 的版本主要改进是减少幻觉, 提升写作. 训练 2 个 epoch, 学习率 5e-6. 数学和代码数据占比不小, 所以 SFT 后 GSM8K 从 79.2 到 90.8, MATH 从 43.6 到 52.7, HumanEval 从 48.8 到 76.8, 而 MMLU 基本不变(78.5 到 78.4). SFT 的 token 总量, 各领域配比和数据来源, 报告没有给. 讨论节还记了一条: SFT 少于 10K 条时 IFEval 明显下降, 和 LIMA 一类「少量数据就够」的结论相反, 作者的解释是特定技能需要一定数据量, 模型变大可以降低门槛, 但消除不了. SFT 的数据质量问题见 [SFT 数据质量筛选与训练技巧](../../../llm-guide/4-后训练/4.2-SFT/4.2.2-SFT数据质量筛选与训练技巧/4.2.2-SFT数据质量筛选与训练技巧.md).

RL 用 DeepSeekMath 提出的 GRPO. 报告的写法是

$$
\mathcal{J}_{\mathrm{GRPO}}(\theta)=\mathbb{E}_{q,\{o_i\}_{i=1}^G\sim\pi_{\theta_{old}}}\frac{1}{G}\sum_{i=1}^{G}\left(\min\left(\rho_iA_i,\ \mathrm{clip}(\rho_i,1-\varepsilon,1+\varepsilon)A_i\right)-\beta\,\mathbb{D}_{KL}(\pi_\theta\|\pi_{ref})\right),\qquad \rho_i=\frac{\pi_\theta(o_i\mid q)}{\pi_{\theta_{old}}(o_i\mid q)},
$$

$$
A_i=\frac{r_i-\mathrm{mean}(\{r_1,\dots,r_G\})}{\mathrm{std}(\{r_1,\dots,r_G\})}.
$$

每个问题 $q$ 从旧策略采 $G$ 个回答, 各自拿到奖励 $r_i$. 优势 $A_i$ 只和同组其他回答比: 高于组均值为正, 低于为负, 再除以组内标准差, 让难题和易题的优势尺度一致. 这一步替掉了 PPO 里的价值网络, 基线不再是 critic 对 $q$ 的估值, 而是同题 $G$ 个样本的平均奖励. $\rho_i$ 是新旧策略对同一回答的概率比, $\min$ 和 clip 限制一次更新里 $\rho_i$ 最多偏离 1 到 $\varepsilon$ 为止, 超出部分不再给梯度. $\beta$ 项把策略拉向参考模型 $\pi_{ref}$, 防止为了追奖励模型的分数跑到分布外. 对 236B 的模型来说, 省掉一个同规模的价值网络是很实际的考虑. 同组 $G$ 个回答奖励完全相同时, 分子分母都是 0, 这组除了 KL 项拿不到任何梯度; 报告没写怎么处理这种组. 组大小 $G$, 裁剪系数 $\varepsilon$, KL 系数 $\beta$ 和训练步数也没有公开. 式 32 的写法和 DeepSeekMath 有一处不同: DeepSeekMath 按 token 写比率并对输出长度取平均, 这里直接写成整条输出的概率比 $\pi_\theta(o_i|q)/\pi_{\theta_{old}}(o_i|q)$. 这可能只是记号上的简写, 报告没有说明实际实现按 token 还是按序列裁剪. KL 项(式 33)用的是 $\frac{\pi_{ref}}{\pi_\theta}-\log\frac{\pi_{ref}}{\pi_\theta}-1$ 这个无偏且恒为非负的估计量, 与 DeepSeekMath 相同, 它不放进奖励, 而是直接加在损失上. 算法细节见 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

训练分两段. 预实验发现代码, 数学这类推理数据上的 RL 和通用数据不一样: 能力可以在更长的训练步数里持续提升. 所以先做推理对齐, 奖励来自一个训出来的 $RM_{\mathrm{reasoning}}$(式 35); 再做人类偏好对齐, 奖励是 $c_1RM_{\mathrm{helpful}}+c_2RM_{\mathrm{safety}}+c_3RM_{\mathrm{rule}}$(式 36), 三个系数没有给. 奖励模型都从 Chat(SFT) 初始化, 用 point-wise 或 pair-wise 损失训练; 代码偏好数据来自编译器反馈, 数学偏好数据来自标准答案. 注意这里的编译器和标准答案只用来造奖励模型的训练数据, RL 时打分的仍是神经网络奖励模型. 到 R1 才把规则判分直接当奖励. 工程上有三项: 训练和推理用不同并行策略的混合引擎, 大 batch 的 vLLM 做采样, 以及模型在 CPU 和 GPU 之间卸载, 回载的调度. 讨论节还说在线 RL 在偏好对齐里明显好于离线, 所以专门搭了在线框架, 但同时说明这个结论可能随场景变化.

**从普通注意力推到 MLA**

**缓存究竟保存了什么**

先把自回归解码写成最朴素的形式. 第 $t$ 步生成新 token 时, 第 $i$ 个注意力头拿到查询 $q_{t,i}$, 与此前 $1$ 到 $t$ 位的键做内积, 再用得到的权重加权值向量:

$$
a_{t,s,i}=\operatorname{softmax}_s\left(\frac{q_{t,i}^{\mathsf T}k_{s,i}}{\sqrt{d_h}}\right),\qquad
o_{t,i}=\sum_{s=1}^{t}a_{t,s,i}v_{s,i}.
$$

过去位置的隐藏状态已经不会改变, 每步重新计算它们的键和值纯属浪费, 于是部署系统保存全部 $k_{s,i}$ 与 $v_{s,i}$. 这就是 KV cache. 若层数为 $L$, KV 头数为 $n_{kv}$, 单头宽度为 $d_h$, 上下文长度为 $S$, 每个数占 $b$ 字节, 单条序列需要

$$
M_{KV}=2L S n_{kv}d_hb.
$$

这里的 2 分别对应 K 与 V. 它解释了一个容易混淆的现象: 模型权重只随 batch 装载一次, KV cache 却随「并发数乘上下文长度」增长. 236B 权重很大, 但它可以切到多张卡并被整个 batch 共用; 某位用户多塞进一段历史, 新增的缓存只服务于这位用户. 长上下文在线服务最终经常先撞到缓存容量, 而非权重容量.

MHA 令 $n_{kv}=n_h$, MQA 令 $n_{kv}=1$, GQA 则取介于两者之间的组数. 这三种结构都直接缓存投影完成的 K 和 V. MLA 改的是「缓存对象」: 保存能够重建二者的公共潜向量. 设当前层输入为 $h_t\in\mathbb R^d$, 联合下投影为

$$
c_t^{KV}=W^{DKV}h_t,\qquad W^{DKV}\in\mathbb R^{d_c\times d},\quad c_t^{KV}\in\mathbb R^{d_c}.
$$

然后分别上投影:

$$
k_t^C=W^{UK}c_t^{KV},\qquad v_t^C=W^{UV}c_t^{KV}.
$$

$W^{UK}$ 的输出可以按头切成 $k_{t,i}^C$, $W^{UV}$ 同理. 「联合」非常重要. 若 K 与 V 各存一份 512 维潜向量, 缓存是 1024 维; V2 只存一份 512 维向量, 两种重建共享同一组坐标. 共享会施加结构约束: 所有头的键和值都必须由同一个低维状态线性生成. 这也说明 $d_c$ 并非越小越好. 当它小到无法容纳各头共同需要的信息时, 上投影只能把已经丢掉的信息编造为不同形状, 表面上仍有 128 个头, 实际可用的自由度却受 $d_c$ 限制.

### 2.2. 矩阵吸收为什么成立

忽略 RoPE, 第 $i$ 个头的内容查询可写为 $q_{t,i}^C=W_i^{Q}h_t$. 它与历史位置 $s$ 的内容键内积:

$$
(q_{t,i}^C)^{\mathsf T}k_{s,i}^C
=(W_i^Qh_t)^{\mathsf T}W_i^{UK}c_s^{KV}
=h_t^{\mathsf T}(W_i^Q)^{\mathsf T}W_i^{UK}c_s^{KV}.
$$

模型参数在一次推理期间固定, 因而可预先构造 $\widetilde W_i^Q=(W_i^{UK})^{\mathsf T}W_i^Q$, 运行时直接得到 $\widetilde q_{t,i}=\widetilde W_i^Qh_t\in\mathbb R^{d_c}$. 分数变成 $\widetilde q_{t,i}^{\mathsf T}c_s^{KV}$. 历史位置无需恢复完整键. 值路径也可把上投影和注意力输出投影合并. 若拼接各头结果后乘 $W^O$, 则

$$
W^O\operatorname{Concat}_i\left(\sum_s a_{t,s,i}W_i^{UV}c_s^{KV}\right)
=\sum_i\sum_s a_{t,s,i}\widetilde W_i^{OV}c_s^{KV},
$$

其中 $\widetilde W_i^{OV}$ 是 $W^O$ 对应分块与 $W_i^{UV}$ 的乘积. 因而缓存中始终只需 $c_s^{KV}$. 这里并不存在无条件的免费午餐: 点积从 $d_h$ 维变成 $d_c$ 维, V2 中是从 128 维增至 512 维. 每读一个历史 token, 每个查询头做的乘加更多了. 解码阶段通常受显存带宽限制, 少读几十倍数据换来四倍点积宽度依然划算; 预填充会一次处理许多 query, 更容易受计算量限制, 此时显式重建 K/V 并调用高效注意力核可能更好.

拿 60 层、128 头、头宽 128 做一次手算. MHA 每层每 token 保存 $2\times128\times128=32768$ 个数. MLA 保存 512 维潜向量与 64 维位置键, 共 576 个数, 元素数之比为 $576/32768=1.758\%$. 若二者都是 BF16, 仅缓存结构便缩小约 56.9 倍. 对 128K 序列, MLA 的 BF16 缓存是

$$
60\times131072\times576\times2\approx 9.06\times10^9\ \text{bytes},
$$

也就是约 8.44 GiB. MHA 则约 480 GiB. 前文拿 67B 的 8 个 KV 头作基线得到约 47 GiB, 属于另一种比较口径. 一个是「V2 若使用同头数 MHA」, 一个是「V2 对上一代 GQA 模型」. 两者都能回答问题, 却不能混成同一个缩减比例.

**RoPE 为何必须拆开**

RoPE 对位置 $t$ 施加旋转矩阵 $R_t$. 标准形式的分数含有

$$
(R_tW_i^Qh_t)^{\mathsf T}(R_sW_i^Kh_s)
=h_t^{\mathsf T}(W_i^Q)^{\mathsf T}R_{s-t}W_i^Kh_s.
$$

相对位置来自 $R_t^{\mathsf T}R_s=R_{s-t}$. 若令 $W_i^K=W_i^{UK}W^{DKV}$, 旋转夹在 query 投影和键上投影之间. $R_sW_i^{UK}$ 随历史位置变化, 无法提前吸收到固定查询矩阵. 强行吸收会要求每个位置使用不同的参数矩阵, 也就失去了只缓存潜向量的意义.

V2 把查询和键各拆成内容路与位置路:

$$
q_{t,i}=[q_{t,i}^C;R_tq_{t,i}^R],\qquad
k_{s,i}=[k_{s,i}^C;R_sk_s^R].
$$

于是总分数为

$$
q_{t,i}^{\mathsf T}k_{s,i}
=(q_{t,i}^C)^{\mathsf T}k_{s,i}^C
+(q_{t,i}^R)^{\mathsf T}R_{s-t}k_s^R.
$$

第一项不带旋转, 可以走矩阵吸收; 第二项保留相对位置信息, 只缓存共享的 64 维 $R_sk_s^R$. 这是一种明确的容量分工: 512 维潜状态承担「这里写了什么」, 64 维位置键帮助判断「它离当前 token 多远」. 位置路在所有头之间共享键, 各头仍有自己的位置查询, 因而不同头可以用不同方式读取同一套位置坐标.

一个反例能说明为何不能把位置路删掉. 假设序列里出现两次完全相同的短语, 两处内容表示接近. 当前 token 需要引用最近一次. 只有内容点积时, 两处键可能给出近似分数; 相对旋转提供距离与次序线索, 才能系统地区分两次出现. 反过来, 若任务是一袋词分类, 位置本来无关, 64 维位置路的收益可能很小. 所以解耦 RoPE 的价值应在顺序、复制、指代与长距离检索任务上更明显, 这是可以单独做消融验证的预期.

**查询压缩省的是训练激活**

V2 还先把查询下投影到 1536 维潜表示, 经过 RMSNorm 后再生成各头查询. 查询只属于当前计算步骤, 不会为历史位置长期留在 KV cache 中, 因而它不参与前面的 576 维缓存公式. 它主要减少训练反向传播需要保留的中间激活, 并给 128 个查询头施加共享低秩约束.

可以用秩来理解: 若完整查询投影直接从 $d=5120$ 映到 $128\times128=16384$ 维, 其线性变换秩上限为 5120; 插入 1536 维瓶颈后, 合成矩阵秩上限降为 1536. 约束很强, 但每头仍能通过上投影选择潜空间的不同组合. 若把 $d_c'$ 继续降到几十维, 所有头会被迫围绕少数方向工作, 多头分工可能坍缩. 论文给出最终设置, 没有公布一条完整的 $d_c'$ 扫描曲线, 因而 1536 更适合看作在该规模上验证过的设计点, 还谈不上跨规模定律.

## 3. MoE 的容量、计算与路由

**总参数多不等于每步都贵**

Dense FFN 对每个 token 使用全部参数. MoE 则把参数容量与单 token 计算解耦. 设路由专家共 $N_r$, 每次选 $K_r$, 共享专家共 $N_s$, 每个专家参数量近似为 $P_e$, 其总专家参数约 $(N_r+N_s)P_e$, 激活专家参数约 $(K_r+N_s)P_e$. V2 中二者分别对应 162 与 8 个专家, 专家部分单 token 只走约 $8/162=4.94\%$ 的容量. 注意力、嵌入、归一化和路由器依然全量运行, 所以整模的 236B 与 21B 不能直接用 8/162 推出.

细粒度专家带来的组合数也可量化. 从 160 个路由专家选 6 个, 无序组合数为 $\binom{160}{6}$, 远大于把同样总参数切成少数大专家后选一两个. 组合数大不代表模型真的使用所有组合; 路由器可能只偏爱少数专家簇. 它提供的是潜在分工空间. 是否形成分工, 要看实际专家负载、token 类型与专家选择的互信息, 以及屏蔽某个专家后哪些任务受损. 单看路由热力图很容易把频率差异误认成语义专门化.

共享专家处理另一种浪费. 若某种通用变换对几乎所有 token 都有用, 纯路由 MoE 会让多个专家各自学一遍. 把这部分容量抽成始终激活的共享专家, 路由专家可把容量留给条件性模式. 代价也很直接: 两个共享专家每个 token 必走, 它们会抬高计算下限. 若通用知识其实很少, 或路由专家本来就能高效共享, 固定共享路径反而浪费算力. 因此共享专家是否值得, 可用「固定激活参数相同」的纯路由对照检验, 不能只比较总参数相同的模型.

### 3.1. 负载均衡在优化什么

专家级均衡损失中的 $f_i$ 是离散选择频率, $P_i$ 是连续路由概率. 设四个专家、Top-1 路由, 一个 batch 内选择频率归一化后为 $(2,1,1,0)$, 平均概率为 $(0.5,0.2,0.2,0.1)$. 乘积和为 $1.4$, 高于均匀状态的 1. 梯度会压低第一个专家的平均概率. 若选择频率与概率错位, 例如 $f=(2,1,1,0)$ 而 $P=(0.1,0.3,0.3,0.3)$, 乘积和只有 0.8. 这揭示了该代理目标的局限: 它依赖当前 Top-K 结果与软概率共同变化, 单个 batch 上并不等价于负载方差, 更不保证每次更新都向均匀状态移动.

均衡也不应追求到每个专家逐 token 完全相等. 如果代码 batch 与中文 batch 的统计结构不同, 合理路由本就会偏向不同专家. 过强的辅助损失会让路由器为了凑人数, 把 token 送给次优专家, 主任务损失上升. 过弱则出现热点专家, 容量溢出与等待时间增加. V2 把专家级系数设得最小, 设备级和通信级更大, 表明约束重点是硬件负载, 而非抹平语义分工. 后来的 V3 用动态偏置调节负载, 恰好说明把均衡压力直接写进训练目标会干扰模型质量.

设备受限路由把候选专家限制在最多三张卡上, 它缩小的是通信扇出. 假设 Top-6 专家原本散在六张卡, token 隐状态需要发六份; 限到三张卡后最多发三份, 每张卡内仍可选多个专家. 代价是全局第六高的专家可能被候选设备筛掉, 改选同卡上分数稍低的专家. 当专家分数头部很平时, 这一步容易换错; 当前三张设备已经覆盖明显高分专家时, 损失很小. 因而论文关于 $M\ge3$ 基本持平的结论与「路由分数通常有明显头部」相容, 但缺少不同领域、不同训练阶段的分布数据.

**token-dropping 的真实含义**

容量因子 1.0 表示按平均负载准备槽位. 例如一层共处理 8192 个 token, 每个 token 选 6 个路由专家, 160 个专家平均收到 $8192\times6/160\approx307$ 次分派. 若某专家收到 420 次, 多出的低分分派会被丢掉. 该 token 并未从网络中消失, 它仍沿残差支路传播, 也可能经过共享专家与其他已选路由专家; 被删的是某一条专家贡献.

永远不丢的那部分序列给训练加入一个锚点, 防止模型只适应带缺口的 MoE. 它也形成轻微的分布混合: 大部分样本见到容量噪声, 少部分样本见到完整计算. 若实际丢弃率很低, 这种噪声近似正则化; 若热点严重, 特定语言或题型的 token 经常被丢, 就会变成有方向的数据损伤. 需要按领域报告丢弃率才能排除后一种情况, 论文只给策略, 没给这组统计.

一个可证伪判断是: 若均衡损失有效, 训练后期各设备负载的高分位差距应下降, token-dropping 率也应随之下降; 若主损失改善只是因为丢弃带来正则化, 关掉丢弃但保持均衡后验证损失反而可能变差. 两种解释可通过日志区分. 论文没有公开这些曲线, 读者不应把「设计目标」直接当成「已经测得的机制」.

**数据和训练日程怎样共同塑造结果**

**T token 比架构更难剥离**

V2 相对 67B 同时改变训练 token、中文比例、清洗策略、模型结构与计算预算. 因此 MATH、中文基准的提升无法只归因于 MLA 或 MoE. 最干净的架构证据来自附录的同数据消融, 而正式模型间比较回答的是「整套方案是否更强」. 两类证据的力度不同.

设验证误差可粗略写成 $E=f(P_{active},P_{total},D,Q,A)$, 分别代表激活参数、总容量、数据量、数据质量和架构. 从 67B 到 V2, 五项几乎全变. 只观测两个端点不能解出 $A$ 的边际贡献. 附录固定数据量并比较 MHA/MLA, 才接近控制变量; 可它又只覆盖 420B 或 1.33T token, 尚未验证优势在 8.1T 末端是否保持. 合理结论是「现有消融没有发现 MLA 的质量代价, 并在若干基准上略优」, 更强的因果说法需要多随机种子和完整训练曲线.

中文 token 比英文多约 12% 容易被误读为中文超过总数据一半. 数据还包含代码、数学与其他语言, 论文只报告中英相对差, 无法反推中文占全部 token 的比例. 同理, 「英文少于 LLaMA3 70B 的四分之一」比较的是英文 token, 不等于总数据只有四分之一. V2 用较少英文数据接近其英文能力, 可能来自数据质量、跨语言迁移、MoE 容量或评测饱和, 报告没有逐项拆解.

### 3.2. 分段学习率和 batch warmup

峰值学习率 $2.4\times10^{-4}$ 在 2000 步内线性升高并保持到 60% token, 此处乘约 0.316, 到 90% 再乘一次, 训练末段因而降至峰值的约十分之一. 60% token 以前保存的 checkpoint 仍有较强可塑性. Coder-V2 从这一区间的 checkpoint 继续做代码与数学预训练, 继承了权重以及尚未完全退火的优化状态位置.

batch 从 2304 增到 9216 条, 每条 4096 token. 起始批约 9.44M token, 最终约 37.75M token. 225B token 的 warmup 区间若把增长细节忽略, 大约经历数千到两万余步, 取决于 batch 变化曲线. 论文只说逐步增加, 无法精确恢复步数. 大 batch 降低梯度噪声并提高吞吐, 也减少同样 token 数下的参数更新次数. 早期小 batch 给模型更多更新机会, 后期大 batch 让已经较稳定的方向被更准确估计. 若把最终 batch 从开头用到底, 训练可能更稳却少了早期更新; 若始终用小 batch, 优化步更多但通信与流水线效率较差.

**长上下文外推能证明什么**

32K 训练后在 128K 的大海捞针图上成功, 说明模型能够把一个明显目标从远处取回. 这项测试未覆盖多处证据整合、跨章节约束、长代码修改与中间信息干扰. 例如在 120K 文本里放入二十个互相相似的人名, 最终要求比较其中三人的事件顺序, 会同时考验检索、消歧和组合; 单针任务只需找一个高显著字符串.

MLA 的缓存优势与长上下文能力也要分开. 前者回答「是否装得下、吞吐是否可接受」, 后者回答「装进去后是否会用」. 缓存压缩可能让 128K 推理成为现实, 但不会自动创造长程推理能力. YaRN 和短暂的长序列继续训练负责位置外推, 预训练数据里是否存在长依赖又决定模型学到多少使用方式. 若将窗口扩到 128K 后只测检索, 最稳妥的表述就是支持 128K 检索场景.

**从 SFT 到 GRPO 的能力迁移**

**组内标准化的手算**

假设同一道数学题采样四个答案, 奖励为 $(1,1,0,0)$. 均值 0.5, 若用总体标准差 0.5, 优势为 $(1,1,-1,-1)$. 两个正确答案都被推动, 两个错误答案都被压低. 若奖励为 $(1,1,1,1)$, 标准差为零, 该组无法提供相对信号; 实现通常需要加一个很小的稳定项, 论文公式没有展开. 若奖励为 $(1,0.9,0.9,0.9)$, 最优答案得到较大正优势, 其余三个得到较小负优势. GRPO 学的是同题候选间的相对排序, 奖励绝对值会被组内归一化削弱.

这既是优点也是风险. 难题四个答案都很差, 其中「稍微没那么差」的一个仍会得到正优势; 易题四个都对则没有梯度. 奖励模型必须能在低质量候选中给出有意义的细微排序, 否则策略会强化偶然差异. 数学与代码有较明确的正确性反馈, 组内排序可靠一些; 开放写作依赖神经奖励模型, 更容易把风格偏好当成质量.

裁剪项处理策略更新幅度. 当 $A_i>0$ 时, 概率比高于 $1+\varepsilon$ 后收益封顶, 防止一次把幸运样本概率推得过高; 当 $A_i<0$ 时, 概率比低于 $1-\varepsilon$ 后惩罚封顶, 防止把某种回答一步清空. KL 项把分布拉回参考模型. 二者分别限制局部更新与全局漂移. 若奖励模型存在漏洞, 裁剪只能减慢利用漏洞, KL 只能要求新模型别离旧模型太远, 都无法判断奖励本身是否正确.

**两阶段 RL 为什么会出现取舍**

推理阶段先强化数学与代码, 通用阶段再混合有用、安全和规则奖励. 后一阶段的梯度可能覆盖前一阶段部分行为, 尤其当奖励模型偏爱简洁、稳妥回答时, 多步推理会因长度与形式受到间接惩罚. 表格里数学代码继续增长, 若干选择题回落, 说明覆盖并非全面, 但存在任务间拉扯.

将 Base、SFT、RL 三点连起来更有信息. MATH 为 43.6、52.7、53.9, 最大跃升发生在 SFT; HumanEval 为 48.8、76.8、81.1, 同样如此. RL 的贡献真实却小于监督阶段. 开放生成评分上 RL 增益更大, 与偏好优化目标匹配. V2 的后训练过程可以概括为: 预训练形成解题基础, SFT 教会稳定的回答轨迹, RL 再对候选进行偏好重排.

一个反事实实验可检验阶段顺序: 从同一 Base 分别训练「只做 SFT」「SFT 后推理 RL」「SFT 后通用 RL」「SFT 后两段 RL」, 固定采样预算和最终 token 数. 若两段方案只在开放生成上好, 数学收益与推理单段相同, 第二阶段主要负责表达与安全; 若两段方案数学也更高, 通用奖励可能产生协同. 论文只提供 SFT 与完整 RL 两列, 无法拆开两段各自贡献.

**成本数字的口径**

### 3.3. % 节省不等于总项目少花 42.5%

每 1T token 的训练 GPU 小时从 300.6K 降到 172.8K, 比值为 0.575, 因而同 token 计算成本下降 42.5%. V2 实际训练 8.1T token, 67B 只训练 2T. 将单位成本乘实际 token 后, V2 的预训练总 GPU 小时约 1.40M, 仍高于 67B 的约 0.60M. 「更经济」指在更大数据和容量下单位训练量便宜, 这次完整训练使用的 GPU 小时反而更多.

GPU 小时也不是纯算法 FLOPs. 它包含通信、负载不均、重计算、流水线气泡以及内核效率. 若换一套集群拓扑, 设备受限路由的收益会变化. 论文在 H800 集群上测得的数字可用于该系统配置附近的估算, 不能直接当成所有硬件上的常数. 理论激活参数比例比实测成本比例更低, 差额正好提醒我们 MoE 的参数稀疏不会一比一变成墙钟时间节省.

**倍吞吐依赖并发场景**

解码单步只生成一个 token, 读取权重的代价很大. batch 太小时, 权重带宽无法摊薄; KV cache 变小后可塞进更多并发序列, 同一遍权重读取服务更多 token, 吞吐随之提升. 因此 5.76 倍是缓存、量化、批处理和专用内核共同作用的系统结果.

若请求全是短提示、短回答, KV cache 原本就不占主要显存, MLA 释放的空间未必能转化为更大 batch, 提升会低于长请求场景. 若服务强调单用户最低延迟, 增大 batch 反而需要等待聚合, 吞吐收益也不能直接换成延迟收益. 若并发足够高且上下文很长, 缓存才成为决定性约束. 因而「最大生成吞吐」中的最大二字不能就不写了.

**三组数字对应三条因果链**

42.5% 主要来自稀疏激活降低训练计算, 同时受 MoE 通信拖累; 93.3% 来自 MLA 缩小缓存元素数再叠加 6 bit 存储; 5.76 倍来自省下显存后提高并发, 并加入权重量化与内核优化. 三者首尾相接, 却并非同一个消融实验. 若要把贡献拆开, 至少需要 BF16 MHA、BF16 MLA、低比特 MLA 三档缓存, 以及相同 batch 与各自最大 batch 两套吞吐. 公开报告没有给完整矩阵, 因而只能确认整套部署方案的端到端结果.

**与前后模型的连接**

DeepSeekMoE 提供细粒度专家、共享专家与多级均衡, V2 把它放进 236B 规模并加上设备受限路由. 这条继承关系说明 MLA 和 MoE 解决的是正交瓶颈: MLA 面向每条长序列持续增长的状态, MoE 面向每个 token 需要经过多少参数. 只用 MLA 的 Dense 模型仍会付出全量 FFN 计算; 只用 MoE 的普通注意力仍会被长上下文缓存卡住.

Coder-V2 从 V2 中间 checkpoint 继续预训练代码和数学, 架构仍是 MLA 加 DeepSeekMoE. 因而它在代码任务上的提升不能解释成新注意力结构带来的突变, 主要变量是继续训练的数据与长度扩展. 这也提供了一个自然实验: 同一架构经领域续训后能力明显偏移, 说明 V2 正式模型的基准分布同样不能脱离数据讨论.

V3 延续 MLA, 说明这一压缩路线经受了更大规模训练; 路由均衡却改成辅助损失自由的偏置控制, 说明 V2 的三层损失更像过渡方案. V3 还引入多 token 预测与 FP8 训练, 因而 V3 的效率不可回溯归功于 V2 单项设计. V2 真正稳定留下来的核心是「缓存潜状态、解耦位置路」和「细粒度路由加共享专家」两组结构.

**可复核结论与尚缺证据**

第一, MLA 的缓存公式、矩阵吸收与解耦 RoPE 能从公开维度逐项复算, 这是最扎实的部分. 它确实把每层每 token 的缓存从大量分头 K/V 压到 512 加 64 维. 对照实验显示质量没有出现明显下降, 但训练长度、随机种子和部分配置披露不足, 尚不能推出所有规模都优于 MHA.

第二, DeepSeekMoE 把总容量与激活计算分开, 训练单位 token 成本显著下降. 专家路由的语义分工没有被完整验证, 设备级均衡与 token-dropping 的日志也未公开. 能确认的是端到端 GPU 小时, 以及最终模型效果; 中间机制仍有若干待测环节.

第三, 8.1T 数据、SFT 与 GRPO 共同决定最终分数. Base 到 SFT 的跃升在数学代码上大于 SFT 到 RL, RL 对开放生成偏好更有效. 把 V2 概括成一篇注意力论文会漏掉大半结果, 把所有能力提升都归给 MLA 又会越过现有证据.

第四, 128K 的公开依据主要是大海捞针. 若后续复现出现「检索成功而多证据推理失败」, 并不与论文图冲突; 若在相同位置缩放和训练设置下连单针检索也明显失败, 才会直接挑战该结果. 同样, 5.76 倍吞吐应在论文的请求分布、量化与并发条件附近复核, 短上下文单请求测不到这个倍率也不构成反证.

V2 最值得带走的思考方式是把效率问题拆开: 长上下文状态用低秩表示, 大参数容量用条件计算, 路由通信用拓扑约束, 对齐计算用组内相对优势. 每个办法都把一种昂贵对象换成另一种约束. 低秩缓存换来表示秩与额外点积, 稀疏专家换来通信和负载问题, GRPO 省去价值网络却依赖同题采样与奖励排序. 读懂这些交换关系, 才算读懂「economical and efficient」究竟成立在哪些条件下.

## 4. 一组贯穿全篇的手算

假设服务端同时处理 16 条 128K 请求. 按 BF16 计算, V2 单条 KV cache 约 8.44 GiB, 16 条约 135 GiB; 若使用同层数、同头数 MHA, 单条约 480 GiB, 连一条都难以放进常见的八卡节点剩余显存. 换成上一代 8 KV 头的 GQA, 单条约 60 GiB 左右, 仍只能维持很小并发. 这组数解释了 MLA 的价值来自哪里: 它没有让单次点积消失, 而是让服务端可以在同一批权重旁边保留更多用户状态.

进一步看每一步解码. 16 条序列各生成一个 token, MLA 每层需读取约 $16\times128K\times576$ 个缓存元素, MHA 要读 $16\times128K\times32768$ 个. 前者约 1.2B, 后者约 68.7B. 即使 MLA 的每头点积宽度增至 512, 读缓存总量仍大幅降低. 真实内核还要考虑缓存层级、并行切分与量化解码, 但数量级差异足以说明它为什么适合带宽受限的生成阶段.

每个 token 激活 8 个小专家, 总容量则有 162 个专家. 假设各专家耗时完全相同且通信开销为零, 专家部分的理论计算比例约 4.94%. 实际总模型还包含全量注意力, all-to-all 也要发送隐藏状态. 因而 GPU 小时降到 Dense 基线的 57.5%, 远高于 4.94%; 专家 FFN 只占整条训练流水线的一部分.

单位 1T token 省 127.8K GPU 小时; 多训练 6.1T token 又增加约 1.05M GPU 小时. V2 用更高的总成本换来了更大的数据量、容量和中英文覆盖, 同时让「训练这样一个规模」比 Dense 路线便宜. 若预算固定为 67B 的约 0.60M GPU 小时, 按 V2 单位成本最多训练约 3.47T token, 达不到正式版 8.1T. 效率提高往往会被兑换为更多训练, 最终账单未必下降.

### 4.1. MLA 的表示能力再往前一步

**联合低秩约束如何作用于所有头**

把所有头的内容键拼起来, 有 $k_t^C=W^{UK}W^{DKV}h_t$. 合成矩阵的秩至多为 $d_c=512$. 若普通 MHA 的完整键输出宽度为 16384, MLA 把所有可能键限制在一个至多 512 维的线性子空间. 值同样由这份潜变量生成, 但有自己的上投影. K 与 V 并非落在同一个输出子空间, 它们共享的是产生二者的坐标.

这种限制为何可能不伤质量? 相邻注意力头往往含有大量冗余, 16384 个输出坐标不代表真有同等数量的独立信息方向. 输入隐藏状态本身也只有 5120 维, 普通投影的秩上限已经小于输出宽度. MLA 再降到 512, 押注的是历史 token 中需要长期保存的信息远少于即时隐藏状态的全部细节. 如果这个押注成立, 低秩瓶颈会滤掉冗余; 如果任务要求许多互不相关的精细属性长期并存, 它会成为上限.

可以设计一类压力测试: 给每个 token 附加多个独立随机属性, 在很远处随机查询其中某个属性, 并逐渐增加属性数. 内容不可通过语言相关性压缩, 所以当信息量逼近潜向量容量时, MLA 应比大宽度 MHA 更早下降. 自然语言通常有强结构与冗余, 因此实际任务可能离这条上限很远. 这类合成测试比通用基准更能直接检验低秩假设.

**为什么 K 与 V 可以共用潜变量**

键负责匹配, 值负责取回. 表面看两种功能差异很大, 共享潜表示似乎过强. 但二者都源于同一个历史隐藏状态 $h_t$, 共同包含该 token 的语义、句法和上下文信息. 下投影先保留一组公共因素, 两个上投影再分别组织为检索坐标和返回内容. 这与先压缩一张图片、再用两个解码头分别做分类和重建相似: 共享编码可行的前提是潜变量保留两项任务的联合充分信息.

若分别使用 $c_t^K$ 与 $c_t^V$, 表达能力会提高, 缓存也翻倍. 可做的消融包括固定总缓存: 联合使用 512 维, 分离后各用 256 维; 或固定单路维度: 联合 512 对分离的 512+512. 前者检验共享是否提升信息利用率, 后者检验额外容量能换回多少质量. V2 报告没有给这张表, 所以联合压缩是经正式模型验证的有效方案, 尚未证明是同缓存预算下的最优方案.

**解耦位置路的容量边界**

位置键只有 64 维且跨头共享. 每个二维 RoPE 子空间对应一个旋转频率, 64 维意味着 32 组频率. YaRN 对这些频率做插值与外推, 内容路则完全不旋转. 如果位置路过窄, 不同距离模式会互相干扰; 如果过宽, 每 token 缓存增加, 同时更多表示被强制带上旋转结构.

共享位置键还有一个细节: 头与头之间的差异主要来自各自的位置查询. 同一个历史位置向所有头提供相同的基础位置编码, 各头决定如何读取它. 这减少了缓存, 也排除了「每个头存一套完全不同的位置键」. 若某些任务确实需要各头对位置进行不同的内容依赖变换, 内容路只能通过不带 RoPE 的分数间接补偿. 目前消融结果说明 64 维共享路足以支撑所测基准, 其极限仍需专门的位置推理测试.

**路由器的学习动力学**

训练初期专家参数近似随机, 某个专家若偶然收到更多 token, 更新次数会增加, 更容易适配这些 token, 路由器继而更愿意选择它, 形成正反馈. 均衡损失试图打断这条反馈. 共享专家则提供稳定底座, 即使路由专家选择尚不成熟, token 也能经过固定的非线性变换.

Top-K 带来一道离散边界. 排名第六与第七的专家分数只差很小, 只有第六个收到主任务梯度; 下一步两者名次可能交换. 这种跳变能促进探索, 也会增加梯度噪声. Softmax 概率参与辅助损失, 让未入选专家仍可能从均衡项得到梯度, 但它们拿不到该 token 的任务损失. 专家专业化就在这两股力量之间形成: 任务损失鼓励选对, 均衡项鼓励别总选同一批.

设备限制又在 Top-K 前加入一层筛选. 某专家单独看分数很高, 所在设备若未进入前三, 仍会失去资格. 因而训练出的路由并非纯语义最近邻, 它会适应硬件拓扑, 倾向把常共同出现的专家集中在少数设备候选中. 更换专家到设备的映射可能改变有效路由, 这也是 MoE checkpoint 移植到不同并行布局时需要谨慎的原因.

论文的三级损失分别看专家、设备与通信, 实际优化信号存在重叠. 一个 token 选择某专家, 同时增加该专家计数、所在设备负载以及跨设备发送. 三个系数不是三个互不相关的旋钮. 增大设备级系数可能已经改善通信, 再增大通信级系数的边际收益取决于本地 token 是否计入发送. 完整消融应逐项开关并报告任务损失、负载方差、丢弃率和墙钟吞吐, V2 只公开最终组合.

### 4.2. 评测里容易看错的地方

**选择题概率与生成答案**

Base 模型没有经过指令格式训练, 用选项困惑度可绕开「会不会按格式回答」的影响. 但它也可能利用选项长度、措辞等统计特征. 生成式评测更接近实际使用, 却把能力与格式服从混在一起. 同一模型在两种协议下的分数变化, 不应直接解释为知识增减.

few-shot 示例还会占用上下文并改变任务分布. 25-shot ARC 与 0-shot HumanEval 对模型的要求相差很大. 横向表格的价值在于同协议下比较各模型, 纵向比较不同基准分数则没有统一尺度. 78 分的 MMLU 与 78 分的 HumanEval 表达的是两种完全不同的成功率.

**小于一个点的差异**

附录消融中多项差异只有零点几到一点多. 没有随机种子重复和置信区间时, 这些差异既可能来自结构, 也可能来自训练随机性、样本顺序或评测波动. MLA 大幅节省缓存是确定的代数事实; MLA 比 MHA 高 0.7 分则是弱得多的经验信号. 把两者放在同一句「又快又强」里会掩盖证据等级.

更合适的判断标准是非劣性: 在预先设定的容忍区间内, MLA 质量没有系统下降, 同时缓存显著降低. 若目标是证明质量更强, 就需要重复实验与统计区间. 工程架构往往只需通过前一种门槛, 因为几十倍资源收益足以补偿极小且不确定的分数波动.

**模型裁判的偏差**

MT-Bench、AlignBench 一类开放生成评测把回答交给另一个模型打分. 裁判可能偏爱熟悉的表达风格、长度或答案结构. 当被评模型与裁判模型训练风格接近时, 分数还可能出现额外偏好. 长度控制版 AlpacaEval 专门减轻「写得长就得分高」的问题, 但不会消除事实判断与风格偏差.

所以开放评测适合观察大幅变化, 并与人工评价、可验证任务相互印证. V2 从 SFT 到 RL 的多项开放分数同时提升, 支持偏好对齐有效; 单个中文分项超过 GPT-4 则不足以推出总体中文能力领先. 表格中的任务定义、裁判版本和提示模板都是结论的一部分.

**如果重新做一轮消融**

第一组围绕 MLA. 固定模型规模、数据顺序和训练 token, 比较 MHA、相同缓存预算的 GQA、联合潜变量 MLA、K/V 分离潜变量 MLA; 对 $d_c$ 取 256、512、1024, 对位置维度取 32、64、128. 除通用基准外, 加入随机属性检索、相对位置判断、多证据组合与 4K 到 128K 的长度扫描. 同时报预填充 FLOPs、解码带宽和实际延迟.

第二组围绕 MoE. 固定激活参数与总参数, 分别去掉共享专家、改变专家粒度、关闭三类均衡项, 再扫描设备候选数 $M$. 每个设置记录专家负载分布、设备负载分布、跨卡字节数、token 丢弃率和验证损失. 只有这样才能知道质量来自更大组合空间、共享知识隔离, 还是单纯总参数增加.

第三组围绕后训练. 从同一 Base 产生 SFT checkpoint, 再分别接推理 RL、通用 RL 与两段 RL. 对每阶段固定采样 token 和更新步数, 报数学、代码、知识、格式服从、安全与开放写作. 还要报告回答长度, 防止裁判分数被长度变化推动. 奖励模型在留出的人类偏好集上单独测准确率, 才能判断策略提升受不受奖励误差限制.

第四组围绕系统. 在 BF16 权重与缓存下先比较结构, 再逐步加入 FP8 权重、6 bit KV 和最大 batch, 每一步记录吞吐与延迟. 短、中、长三种请求分布分别测量. 这会把 MLA 自身收益、量化收益与并发收益拆开, 也能说明 5.76 倍适用的流量条件.

这些实验的共同原则是一次只改变一条因果链. 正式 V2 的目标是交付一套强而经济的模型, 它可以同时改变许多部件; 理解机制时则要把它们重新拆开. 论文附录已经做了重要开端, 仍留下足够多可继续验证的问题.

### 4.3. 低秩近似的误差从哪里进入

**把 MLA 看成两组受约束的线性映射**

普通注意力直接学习键矩阵 $W^K$ 与值矩阵 $W^V$. MLA 要求它们能分解为

$$
W^K=W^{UK}W^{DKV},\qquad W^V=W^{UV}W^{DKV}.
$$

两者右侧共享同一个 $W^{DKV}$. 若先拿一个训练好的 MHA 层再做事后压缩, 可以把纵向拼接矩阵 $[W^K;W^V]$ 做截断奇异值分解. 保留前 $d_c$ 个右奇异向量, 就得到在 Frobenius 范数下最好的共享线性子空间. 被舍弃奇异值的平方和给出该矩阵的最小重建误差. V2 从头采用分解参数化优化, 网络前后层可以共同适应瓶颈, 因而事后 SVD 的误差只能作为理解工具, 不能直接预测最终损失.

共享下投影比「K 和 V 各自秩 512」更严格. 即便 $W^K$ 与 $W^V$ 各自都容易低秩近似, 它们最重要的输入方向也可能不同. 假设 K 只需要隐藏状态前 512 个正交方向, V 只需要另外 512 个方向, 两者各用 512 维可以无损, 共享 512 维却至少要舍弃一部分. 若两者重要方向高度重合, 共享几乎没有额外代价. MLA 成功隐含地说明自然语言模型中的检索依据和返回内容拥有大量共同因素.

为了把误差写清楚, 设理想键和值为 $k_s^*,v_s^*$, MLA 重建为 $k_s^*+e_s^K$ 与 $v_s^*+e_s^V$. 对查询 $q_t$, 分数误差为

$$
\delta z_{t,s}=\frac{q_t^{\mathsf T}e_s^K}{\sqrt d}.
$$

由柯西不等式, $|\delta z_{t,s}|\le \|q_t\|_2\|e_s^K\|_2/\sqrt d$. 键的重建误差若与查询方向正交, 即使范数较大也不会改变该次注意力; 很小的误差若恰好沿查询方向, 则可能改变排名. 因而只测 K 的均方重建误差不够, 更直接的量是注意力 logit 误差及 Top-$k$ 历史位置的翻转率.

Softmax 会继续放大或吸收误差. 记原分布为 $a=\operatorname{softmax}(z)$, 一阶变化近似为

$$
\delta a\approx (\operatorname{Diag}(a)-aa^{\mathsf T})\delta z.
$$

当一个位置的概率已经接近 1, 小分数扰动通常不会改变输出; 当两个候选分数接近, 很小扰动就能交换二者次序. 长上下文里候选位置更多, 最大分数之间的间隔可能缩小, 所以低秩误差应按上下文长度分桶检查. 只在 4K 上验证质量, 无法完全代表 128K 时的检索稳定性.

值误差走另一条路径. 在注意力权重暂时不变时, 输出误差为

$$
\delta o_t=\sum_s a_{t,s}e_s^V,\qquad
\|\delta o_t\|_2\le\sum_s a_{t,s}\|e_s^V\|_2.
$$

它是被注意力概率加权的误差平均. 低权重位置的值即使重建较差, 影响也有限; 高频被读取的位置更重要. 真正的总误差还包含键误差引起的权重变化:

$$
\widehat o_t-o_t=\sum_s(a_{t,s}+\delta a_{t,s})e_s^V+\sum_s\delta a_{t,s}v_s^*.
$$

第一项是值重建, 第二项是注意力改道. 两者可能同向累积, 也可能互相抵消. 这说明 MLA 的表达边界无法只用「512 维比 16384 维小多少」判断, 最终要看训练后误差与模型实际查询分布怎样对齐.

**一个会失败的构造**

设历史 token 隐状态包含 1024 个相互独立的二值属性, 后续查询会均匀随机索引其中任意一个, 并要求精确返回. 若查询与返回都必须通过同一份 512 维连续潜变量, 在有限精度和噪声下不可能稳定保留全部独立属性. 模型可以把多个比特编码进实数, 但有限精度、线性上投影与训练扰动会让这种编码脆弱. 增加属性数量后, 错误率应在某个容量区间快速上升.

自然语言不满足「独立随机属性」假设. 词义、句法、实体与上下文有强相关性, 大量维度可以共享. 因而这个构造用于指出边界, 不用于否定 MLA. 它还提示应加入两类测试: 一类测可压缩的自然语言长文, 一类测刻意去除冗余的合成记忆. 前者回答实用效果, 后者测结构极限.

将 $d_c$ 从 512 提到 1024, 缓存由每 token 每层 576 个元素变成 1088 个元素, 仍远小于 MHA 的 32768; 若合成长记忆任务显著改善而通用损失变化很小, 说明 512 主要受极端信息密度限制. 若两类任务都几乎不变, 512 可能仍有冗余. 若通用任务明显改善, 则原设置是在质量与缓存之间主动取舍. 论文缺少这一维度扫描, 所以无法确定 512 离饱和点多远.

## 5. 矩阵吸收的代数条件

**线性、固定与位置无关**

矩阵吸收成立需要三个条件. 第一, 被合并的两步必须是线性映射. $W^{UK}c$ 与 query 做双线性内积, 可以利用结合律重排; 若两者之间插入逐元素激活、归一化或依赖 token 的门控, 就无法用一个固定矩阵替代. 例如键若写成 $\operatorname{SiLU}(W^{UK}c)$, 一般不存在矩阵 $A$ 使 $q^{\mathsf T}\operatorname{SiLU}(W^{UK}c)=(Aq)^{\mathsf T}c$ 对所有 $q,c$ 成立.

第二, 上投影参数在处理整段缓存时固定. 常规推理满足这一点. 若使用根据输入动态生成权重的超网络, 每个历史 token 的 $W_s^{UK}$ 不同, query 端无法预先吸收成同一个矩阵. 量化不会必然破坏吸收, 但「先量化两矩阵再相乘」与「先相乘再量化」会产生不同舍入误差, 部署时必须明确使用哪条路径.

第三, 上投影不能夹带无法移到 query 侧的位置操作. RoPE 正是违反这条条件的因素. 旋转矩阵依赖历史位置 $s$, 合成结果也依赖 $s$. 解耦之后, 内容路恢复位置无关, 位置路则直接缓存已经旋转的共享键. ALiBi 一类把位置偏置直接加在 logit 上的方法不会夹在 K 上投影中, 理论上更容易与吸收共存; 代价与长程性质属于另一问题.

### 5.1. 多头输出吸收的索引展开

设第 $i$ 个头值上投影为 $U_i^V\in\mathbb R^{d_h\times d_c}$, 输出投影按头分块为 $O_i\in\mathbb R^{d\times d_h}$. 层输出为

$$
y_t=\sum_i O_i\sum_s a_{t,s,i}U_i^Vc_s
=\sum_i\sum_s a_{t,s,i}(O_iU_i^V)c_s.
$$

预计算 $B_i=O_iU_i^V\in\mathbb R^{d\times d_c}$ 后, 历史值无需展开. 但权重 $a_{t,s,i}$ 仍按头不同, 所以不能把所有 $B_i$ 简单加成一个矩阵后只做一次加权和. 正确顺序是每头先依据自己的注意力权重汇聚潜向量, 再乘相应的 $B_i$, 或使用等价的融合核.

这条限制给出了计算账. 每头先形成 $u_{t,i}=\sum_s a_{t,s,i}c_s\in\mathbb R^{d_c}$, 需要约 $S d_c$ 次乘加; 再做 $B_i u_{t,i}$, 需要 $d d_c$ 量级计算. 标准注意力的值汇聚为 $S d_h$, 随后所有头拼接后做 $d\times d$ 输出投影. 两种路径谁更省取决于 $S$、batch、内核和张量并行. MLA 的核心保证是少读缓存, 并未保证每个阶段 FLOPs 都更少.

**训练时为何仍可用展开形式**

训练和长 prompt 预填充同时拥有许多 query. 若完全采用吸收形式, 每个 query 头与 512 维潜键相乘; 展开形式先生成 128 维键, 再使用成熟的矩阵乘法和 FlashAttention. 展开 K/V 会产生临时张量, 但它们只活在当前计算块中, 无需像解码缓存那样跨步保存. 因此训练时可选择计算更友好的形式, 解码时选择带宽更友好的形式, 两者在精确算术下表示同一函数.

这种等价性也提供了实现校验: 对同一批输入分别运行展开与吸收路径, 在 FP32 下输出应只差浮点误差; BF16、量化和融合核会扩大差异, 仍应落在预设容差内. 如果差异随序列长度系统增长, 常见原因包括 RoPE 路处理错误、softmax 缩放维度不一致, 或量化尺度在合并前后使用了不同轴.

**解耦 RoPE 的缓存账与反例**

V2 每层每 token 缓存 $c^{KV}$ 的 512 个元素和 $k^R$ 的 64 个元素. 60 层合计 34560 个元素. BF16 为 69120 字节, 约 67.5 KiB; 128K token 按 $131072$ 计算得到 8.44 GiB. 若把 64 维位置键也按 128 个头分别缓存, 每层会新增 $128\times64=8192$ 个元素, 总缓存变成每层 8704, 单条 128K 请求约 127.5 GiB. 「位置键跨头共享」本身就贡献了约 15 倍差距.

若取消位置路, 每层只剩 512 个元素, 单条 128K 缓存约 7.5 GiB, 比正式方案只少约 0.94 GiB. 这笔账说明 64 维位置键占 MLA 缓存的 $64/576=11.1\%$, 用约一成缓存换取显式相对位置信息. 它的成本远低于按头保存 RoPE 键.

若把位置维度从 64 加到 128, 每层缓存为 640 个元素, 128K 单条约 9.38 GiB; 降到 32 维则为 544 个元素, 约 7.97 GiB. 在 32、64、128 间移动只改变一 GiB 左右, 所以维度选择更可能由质量决定, 而非容量发生数量级变化. 真正昂贵的是是否跨头复制.

再看一个位置混淆反例. 输入为「甲给乙一本书……甲又给丙一本书」, 末尾问「最近一次甲把书给了谁」. 两个事件的内容键都含有甲、给、书, 区别主要在位置和受事. 内容路能够通过「乙/丙」区分, 但 query 在问最近一次, 需要相对位置偏好. 若训练数据总把答案放在最近位置, 无位置路的模型也可能借残差状态中的间接位置信息猜测; 把两个事件替换为高度对称、受事随机的合成样本, 才能更纯粹地检验 RoPE 路.

另一个反例来自绝对位置无关任务. 将同一组事实随机打乱, 问其中某个实体的属性. 正确答案不应随顺序变化. 如果位置分数过强, 模型可能偏向开头或结尾. 所以位置路既要能表达距离, 又要允许 query 把其权重压低. 拼接后相加的两路分数提供了这种自由: 内容项可主导无序检索, 位置项可主导顺序任务.

**MLA 与 MoE 必须联合观察**

**四格消融**

最直接的联合实验是四个模型: MHA+Dense、MLA+Dense、MHA+MoE、MLA+MoE. 固定训练 FLOPs很难, 因为 MoE 改变激活计算, MLA 又改变注意力计算; 更可行的是同时报告固定 token、固定 GPU 小时两套结果. 固定 token 比较同样数据摄入后的质量和成本, 固定 GPU 小时比较现实预算下谁能学到更多数据.

从四格可计算 MLA 的主效应:

$$
\Delta_{MLA}^{Dense}=S(MLA,Dense)-S(MHA,Dense),
$$

$$
\Delta_{MLA}^{MoE}=S(MLA,MoE)-S(MHA,MoE).
$$

若两者接近, MLA 质量影响与 FFN 类型基本独立; 若差异很大, 说明低秩注意力与专家容量存在交互. MoE 的主效应也可同理计算. 交互项为

$$
I=S(MLA,MoE)-S(MHA,MoE)-S(MLA,Dense)+S(MHA,Dense).
$$

$I>0$ 表示组合收益超过两项简单相加, $I<0$ 表示两者一起使用出现额外损失. V2 附录比较 MLA 与 MHA 时使用 MoE 模型, 能估计 $\Delta_{MLA}^{MoE}$, 但缺少 Dense 对应项, 无法计算交互.

### 5.2. 为什么可能产生交互

MLA 压缩注意力可长期保存的信息, MoE 扩大 FFN 的条件容量. 一种可能是互补: 注意力负责从上下文找出少量相关信息, 专家再按 token 类型做复杂变换; FFN 容量更大可以弥补注意力压缩造成的细节损失. 另一种可能是冲突: 路由器依据被 MLA 改写后的隐藏状态选择专家, 小的表示误差若让 token 跨过路由边界, 后续会进入完全不同的专家, 误差被离散选择放大.

可以记录同一批样本在 MHA 与 MLA 模型中的专家选择一致率. 若注意力输出很接近而专家选择频繁翻转, 说明路由边界敏感; 若翻转主要发生在分数接近的专家间且最终输出稳定, 则多个专家功能可能冗余. 还可固定路由选择, 单独替换注意力输出, 将路由放大效应与专家函数差异拆开.

联合系统上也有互补. MLA 减少张量并行中的缓存压力, MoE 增加专家并行通信. 省下的显存可以扩大 micro-batch, 更大的 token 批量提高 all-to-all 消息尺寸, 往往更容易利用网络带宽; 同时并发增大也可能加剧专家负载波动. 最终 GPU 小时包含这两种方向相反的作用. 仅凭参数量无法推导墙钟收益.

**固定什么才算公平**

固定总参数会让 MoE 的激活参数远小于 Dense; 固定激活参数则 MoE 总容量更大; 固定训练 FLOPs又会使各模型见到的 token 数不同. 公平口径取决于所问的问题. 比较「同请求成本的准确率」可固定激活 FLOPs和数据; 比较「同存储容量的准确率」可固定总参数; 比较「同预算最终能力」则固定 GPU 小时. 报告中的正式模型比较偏向第三种现实问题, 附录消融更接近固定数据和规模.

**训练与成本数字的复算表**

**预训练 token 与步数**

最终 batch 为 9216 条, 序列长 4096, 每步 token 数为

$$
9216\times4096=37{,}748{,}736.
$$

如果 8.1T token 全部按最终 batch 训练, 约需 214578 步. 实际前 225B token 使用较小且逐渐增加的 batch, 所以总步数会更多. 最小 batch 2304 时每步 9437184 token; 前 225B token 的步数因此位于 5961 到 23842 之间. 剩余 7.875T token 按最终 batch 约 208617 步. 总步数可限定在约 214578 到 232459 之间, 精确值取决于 batch 增长曲线.

2000 步学习率 warmup 至少覆盖约 18.9B token, 至多约 75.5B token, 同样取决于当时 batch. 它明显短于 225B token 的 batch warmup. 学习率已到峰值时, batch 可能仍在增长. 两种 warmup 调节的是不同噪声来源, 时间范围不必一致.

**GPU 小时与平均吞吐**

论文给出每 1T token 172.8K H800 GPU 小时. 换算为单 GPU 平均 token 吞吐:

$$
\frac{10^{12}}{172800\times3600}\approx1607\ \text{token/s/GPU}.
$$

67B 对应

$$
\frac{10^{12}}{300600\times3600}\approx924\ \text{token/s/GPU}.
$$

二者比值约 1.74, 与 GPU 小时比值的倒数一致. 这是把整个集群工作量平均到每张 GPU 的统计吞吐, 包含流水线气泡与通信, 不能当作单卡独立运行 236B 模型的速度.

8.1T 乘 172.8K 得 1.39968M GPU 小时. 若集群有效使用 2048 张 GPU 且持续满载, 墙钟约 683 小时, 即 28.5 天; 4096 张则约 14.2 天. 论文数字可用来做这种量级换算, 实际卡数、维护中断与利用率会改变日历时间. GPU 小时也没有包含数据处理、失败重跑、消融和后训练的全部项目成本.

**KV cache 的十进制与二进制单位**

前文 8.44 GiB 使用 $2^{30}$ 字节作一 GiB. 若云服务页面按十进制 GB 展示, 同一缓存是 9.06 GB. 两个数字描述相同对象. 再加入 batch、张量并行与缓存量化时尤其容易因单位混乱得出看似矛盾的结果.

6 bit KV 若紧密打包, 理论上单条 128K 缓存为 $8.44\times6/16\approx3.17$ GiB. 实现通常还需要分组尺度、零点、对齐与元数据, 实占会稍高. 若简单用 8 bit 容器存每个 6 bit 值而不打包, 则为约 4.22 GiB. 摘要的 93.3% 缩减更像理论有效位宽口径, 复现实测显存时应把量化元数据算进去.

对 67B GQA 的 BF16 基线, 95 层、8 个 KV 头、头宽 128, 每 token 为 $95\times2\times8\times128=194560$ 个元素. 128K 时约 47.5 GiB. V2 的 6 bit 理论缓存约 3.17 GiB, 比值约 6.67%, 即减少 93.33%. 这次复算把层数、头数、精度与长度全部列出, 也验证了摘要数字为何不能只归给 MLA 结构.

### 5.3. 结论的强弱分层

可以由公式直接确认的结论有三条: V2 的缓存元素数是每层每 token 576; 不含位置操作的线性 K/V 上投影可以吸收到 query 和输出投影; MoE 每 token 只激活 2 个共享与 6 个路由专家. 这些结论不依赖基准波动.

由一次公开实验支持的结论包括: 附录规模下 MLA 相对 MHA 没有表现出质量损失; 正式训练中 V2 每 1T token 的 GPU 小时低于 67B; 给定部署方案下最大生成吞吐达到对照的 5.76 倍. 它们成立于报告的模型、数据和系统配置, 外推到其他规模需要继续测量.

仍属于待验证解释的部分包括: 共享潜变量主要滤掉了头间冗余; 共享专家确实承接通用知识; 三层均衡损失各自改善了哪种瓶颈; 128K 检索能力能否转化为复杂长程推理. 这些解释与结果相容, 论文提供的消融不足以逐条确认.

把三层分开有一个实际好处: 后续模型即使改掉路由损失, 也不会推翻 MLA 的代数节省; 某个新长上下文基准表现不佳, 也不会改变缓存确实缩小的事实. 相反, 若吸收与展开路径在高精度下无法给出一致输出, 就直接触及实现正确性; 若同配置复现实测缓存远超公式, 则应检查额外张量、量化元数据与并行副本. 结论越贴近可计算对象, 复核路径就越短, 争议也越少.

**从一枚 token 走完整条路径**

把前面的部件串起来看一遍. 第 $t$ 个 token 进入某层后, 隐状态先经 RMSNorm. 查询下投影生成 1536 维潜表示, 再上投影为各头的内容查询与位置查询; KV 下投影生成 512 维 $c_t^{KV}$, 另一路生成 64 维位置键. 当前 token 的这 576 个元素加入缓存. 内容查询在吸收后的潜空间里与所有历史 $c_s^{KV}$ 点积, 位置查询与旋转后的位置键点积, 两项相加并缩放, softmax 得到每头的历史权重. 各头用该权重汇聚潜值, 经过吸收后的值输出矩阵回到隐藏宽度.

注意力结果加回残差后进入 MoE. 路由器为 160 个路由专家打分, 设备限制先保留至多三张卡的候选, 再选 6 个专家; 两个共享专家始终参与. 八路输出加权汇总并走下一次残差. 训练时, 主语言建模损失更新全部被选路径, 三类均衡损失额外更新路由概率; 超过设备容量的低分分派可能被丢弃. 解码时不再保留这一 token 的完整 K 与 V, 下一步只读取刚写入的潜向量和位置键.

这条路径说明两个稀疏发生在不同坐标上. MLA 对历史状态做表示压缩, 每个历史 token 仍参加注意力; MoE 对参数执行做条件选择, 每个当前 token 只访问部分专家. 一个没有丢掉历史位置, 一个没有删掉未激活专家的参数. 把二者都简称为「稀疏」会掩盖它们各自的误差来源: MLA 的风险是低秩信息损失, MoE 的风险是路由错误与负载拥塞.

也可以据此定位故障. 长文中找不到近处的精确事实, 先查位置路、缓存量化和 MLA 容量; 某类 token 表现突然变差且伴随专家热点, 先查路由与丢弃; 所有领域随上下文增长一起退化, 再查 YaRN 外推和训练长度. 这些现象会互相影响, 但从 token 的数据流出发, 至少能把检查顺序排清.

还有一项容易漏掉的检查: 同一 token 在预填充路径和逐 token 解码路径中, 层输出应在数值容差内一致. 前者可能展开 K/V, 后者使用吸收矩阵; 两条路径若在短序列上已经分叉, 长上下文评测就失去解释基础. 先用 FP32 排除代数和索引问题, 再依次加入 BF16、权重量化与 KV 量化, 可以判断误差从哪一步进入. 对 RoPE 路还应分别测试位置 0、训练长度边缘与外推区间, 因为旋转频率错误往往在短输入上不明显, 到远距离才迅速积累. 这种逐层对照比只看最终生成文本更敏感, 也更容易复现.
