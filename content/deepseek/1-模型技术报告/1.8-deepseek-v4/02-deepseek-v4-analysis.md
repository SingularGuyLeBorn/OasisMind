# DeepSeek-V4: 压缩注意力撑起 1M 上下文

材料是 DeepSeek 的正式技术报告 (arXiv 2606.19348, 58 页), 发布的是 V4 预览版的两个 MoE 模型: V4-Pro 总参数 1.6T, 激活 49B; V4-Flash 总参数 284B, 激活 13B, 都原生支持 1M token 上下文. 报告要解决的问题是让 1M 长度的预训练, RL 采样和线上推理在单 token 算力和 KV cache 上都撑得住.

## 1. 模型结构、混合注意力与训练组件

**模型结构: 规模, MoE 与 mHC**

V4 相对 V3 保留了 DeepSeekMoE 与 MTP, 改了四处: 注意力从 MLA 换成 CSA 与 HCA 交错的混合结构, 残差连接换成 mHC, 优化器换成 Muon, 后训练的收尾从混合 RL 换成多教师 On-Policy Distillation (OPD). 这几处改动互相依赖. 没有注意力压缩, 1M 序列的预训练和 RL 采样都撑不下来; 报告把 Muon 的作用写成「更快收敛, 更稳的训练」, 把 mHC 写成「增强常规残差」, 训练稳定还要靠第 4.2 节的两种经验手段; FP4 量化感知训练和批不变内核则保证 RL 采样, 训练和线上部署看到的是同一套数值. 报告第 4.2.1 节给出完整配置. Pro 有 61 层, 隐藏维 7168, 每层 1 个共享专家加 384 个路由专家, 专家中间维 3072, 每 token 激活 6 个路由专家. Flash 有 43 层, 隐藏维 4096, 1 个共享专家加 256 个路由专家, 专家中间维 2048, 同样激活 6 个. 按 SwiGLU 三个矩阵算, Pro 每个专家约 6600 万参数, 每层 385 个专家约 254 亿, 61 层合计约 1.55T, 加上注意力和嵌入, 与 1.6T 吻合; Flash 每层 257 个专家约 65 亿, 43 层约 2780 亿, 与 284B 吻合.

激活参数也能按同样的办法拆开. Pro 每 token 激活 7 个专家 (1 个共享加 6 个路由), 61 层约 28B; 注意力部分按第 2.2 节的维度估算每层约 3.1 亿参数 (查询上投影 $1536\times128\times512\approx1.0$ 亿, 分组输出投影约 1.8 亿, 其余是查询下投影, KV 与压缩权重投影和索引器), 61 层约 19B; 再加嵌入和输出头约 2B, 合计约 49B, 与报告一致 (推导). 注意力约占激活参数的 40%. 作为对照, V3 的 MLA 按其配置 ($n_h=128$, $d_h=128$, $d_c=512$, $d_c'=1536$) 每层约 1.9 亿参数, 61 层约 11B, 占 37B 激活的约 30% (推导). V4 的注意力参数多出来的部分, 主要来自 128 个查询头每头 512 维带来的查询上投影和输出投影. 报告第 4.2.1 节末尾把 Pro 的参数写成 「DeepSeek-V4-Flash comprises 1.6T total parameters」, 这是笔误, 同段开头和 Table 1 都是 Pro.

### 1.1. MoE 的小改动与 MTP

MoE 仍是 DeepSeekMoE 的细粒度加共享专家结构, 见 [DeepSeek-MoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md). 相对 V3 有四处改动.

- 计算亲和度的激活从 Sigmoid 换成 $\sqrt{\mathrm{Softplus}(\cdot)}$, 后者没有上界, 在大输入时按平方根增长, 报告没有解释为什么换.
- 继续用无辅助损失均衡, 另加一个很小的序列级均衡损失防止单条序列内极端不均.
- 去掉了 V3 的「每个 token 最多发往 $M$ 个节点」约束, 报告说为此重新设计了并行策略.
- 前几层的稠密 FFN 换成 **Hash 路由**的 MoE: 按输入 token ID 的预设哈希函数决定去哪个专家, 不经过门控网络, 两个模型都是前 3 个 MoE 层用 Hash 路由.

去掉节点约束后, 一个 token 发往的 6 个路由专家可以散在任意多个节点上, 跨节点通信量不再有 V3 那样的 4 节点上限, 所以第 3.1 节的通算融合就变得必要. Hash 路由为什么只用在前 3 层, 报告没有解释. Hash 路由的代价也很直接: 同一个 token ID 在任何上下文里都去同一个专家, 浅层专家没法按语境分工. MTP 按 V3 的配置不变, 深度为 1, 机制见 [MTP 深度解析](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.1-多Token预测MTP/2.8.1-多Token预测MTP.md). 均衡超参沿用 V3: 偏置更新速度 0.001, 序列均衡损失权重 0.0001; MTP 损失权重大部分时间是 0.3, 学习率开始衰减时改为 0.1.

**mHC: 把残差流加宽并约束**

Hyper-Connections 把残差流从 $d$ 维扩成 $n_{\mathrm{hc}}\times d$, 每层通过三个小矩阵混合: 输入映射 $A_l$ 从多路残差里组合出这一层的输入, 残差变换 $B_l$ 在多路之间重新混合, 输出映射 $C_l$ 把层输出写回多路, 即式 (1) $X_{l+1}=B_lX_l+C_l\mathcal F_l(A_lX_l)$. 层内部的计算仍是 $d$ 维, 所以加宽残差几乎不增加计算. 报告说朴素 HC 在多层堆叠时经常数值不稳. **mHC** 的做法是把 $B_l$ 约束到**双随机矩阵**上(非负, 每行每列和为 1), 这样 $B_l$ 的谱范数不超过 1, 残差变换不会放大信号; 双随机矩阵相乘仍是双随机矩阵, 所以堆多少层都成立. $A_l$ 和 $C_l$ 用 Sigmoid 约束为非负有界, 避免信号相互抵消. 三个矩阵都由输入动态生成, 见式 (3)–(8):

$$
\tilde A_l=\alpha_l^{\mathrm{pre}}(\hat X_lW_l^{\mathrm{pre}})+S_l^{\mathrm{pre}},\quad \tilde B_l=\alpha_l^{\mathrm{res}}\,\mathrm{Mat}(\hat X_lW_l^{\mathrm{res}})+S_l^{\mathrm{res}},\quad \tilde C_l=\alpha_l^{\mathrm{post}}(\hat X_lW_l^{\mathrm{post}})^\top+S_l^{\mathrm{post}},
$$

$$
A_l=\sigma(\tilde A_l),\qquad C_l=2\sigma(\tilde C_l),\qquad B_l=\text{Sinkhorn}(\tilde B_l).
$$

$\hat X_l$ 是把 $n_{\mathrm{hc}}\times d$ 的残差流展平后做 RMSNorm 的结果. 每个矩阵都是「动态项乘门控 $\alpha$, 加静态偏置 $S$」; $\alpha$ 初始化很小, 所以训练初期三个矩阵几乎就是静态偏置, 连接方式固定, 随训练才逐步变成依赖输入. $A_l$ 过 sigmoid 落在 $(0,1)$; $C_l$ 是 $2\sigma$, 落在 $(0,2)$, 动态项为 0 且偏置为 0 时恰好等于 1, 即写回权重从 1 起步. $B_l$ 的投影用 Sinkhorn-Knopp 算法: 先取指数保证为正, 再交替做行归一化 $\mathcal T_r$ 和列归一化 $\mathcal T_c$, $M^{(t)}=\mathcal T_r(\mathcal T_c(M^{(t-1)}))$, 迭代 20 次. 20 次后只是近似双随机, 行和列和不严格等于 1, 报告没给残差误差. 两个模型都取 $n_{\mathrm{hc}}=4$. mHC 的一般原理见 [Hyper-Connections 与 mHC](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.3-残差连接/01-Hyper-Connections与mHC/01-Hyper-Connections与mHC.md).

mHC 在每个 Transformer 块之前, 由展平归一化后的残差流 $\hat X_l$ 经三组小线性投影算出 $A_l, B_l, C_l$, 每 token 每层计算一次. $A_l$ 把 4 路残差加权合成该层的 $d$ 维输入, $B_l$ 在 4 路之间做 $4\times4$ 混合, $C_l$ 把层输出按权重写回 4 路. 层间状态从一个 $d$ 维向量变为 $4\times d$ 矩阵, 激活显存和流水线阶段间传递的张量约增至 4 倍; 注意力仍在 $d$ 维输入上计算, 因而不增加推理时的 KV cache. $B_l$ 被限制为双随机矩阵, 不能放大信号或给某一路赋负权, 以朴素 HC 的这部分自由度换取数值稳定. Sinkhorn 只迭代 20 次, 所以约束也是近似满足. 代价在激活显存和流水线通信上, 第 3.5.2 节用融合内核, 选择性重算和调整 DualPipe, 把墙钟开销压到重叠 1F1B 流水阶段的 6.7%. 报告没有给 mHC 对损失或评测的消融, 也没有和普通残差做对照. 后续的 V4.1-Flash 保留 mHC, 把系数预测错后一块, 让部署时一个内核读一遍残差流就能完成输入混合和下一块的系数预测, 激活访存从 V4 实现的 $(4n+4)d$ 降到 $(2n+2)d$, 见 [V4.1-Flash 解析](../1.9-deepseek-v4-1-flash/02-deepseek-v4-1-flash-analysis.md).

**CSA 第一步: 沿序列维压缩 KV**

V4 的注意力有两种. **Compressed Sparse Attention**(CSA)先把每 $m$ 个 token 的 KV 压成一条, 再在压缩后的条目上做 DSA 式的稀疏选择. 压缩方式见式 (9)–(12): 对每个 token 算两组 KV 向量 $C^a, C^b$ 和两组压缩权重 $Z^a, Z^b$; 第 $i$ 个压缩条目由当前块的 $m$ 个 $C^a$ 和前一块的 $m$ 个 $C^b$ 加权求和得到, 权重是 $Z$ 加上可学习位置偏置后在这 $2m$ 个位置上做 softmax. 写成式子:

$$
C^a=HW^{aKV},\ C^b=HW^{bKV},\ Z^a=HW^{aZ},\ Z^b=HW^{bZ},
$$

$$
[S^a_{mi:m(i+1)-1};S^b_{m(i-1):mi-1}]=\mathrm{Softmax}_{\mathrm{row}}\big([Z^a_{mi:m(i+1)-1}+B^a;\ Z^b_{m(i-1):mi-1}+B^b]\big),
$$

$$
C_i^{\mathrm{Comp}}=\sum_{j=mi}^{m(i+1)-1}S_j^a\odot C_j^a+\sum_{j=m(i-1)}^{mi-1}S_j^b\odot C_j^b.
$$

以 $m=4$ 算第 $i$ 个条目: 它取 token $4i$ 到 $4i+3$ 的 $C^a$ 和 token $4i-4$ 到 $4i-1$ 的 $C^b$, 共 8 个向量; softmax 沿这 8 个位置做, 且每个特征维各做一次, 所以 $S$ 和 $C$ 同形, 用 $\odot$ 相乘. $B^a$, $B^b$ 是块内位置的可学习偏置, 让「块内第几个 token」本身带权重. 每个 token 因此出现在两个条目里: 以 $C^a$ 身份进自己所在块的条目, 以 $C^b$ 身份进下一块的条目. 相邻压缩条目的窗口有重叠, 但每 $m$ 个 token 只产生一个条目, 所以序列长度压到 $1/m$. 两个模型都取 $m=4$. HCA 的式 (20)–(23) 是去掉 $b$ 那一路的同一结构, 块长 $m'=128$, 每个条目只对自己块内 128 个 token 做逐维 softmax 加权, 块与块不重叠.

这种压缩和 MLA 的低秩压缩方向不同. MLA 把每个 token 的 KV 压到低维潜变量, token 数不变, 见 [MLA](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md); CSA 让每个条目仍是 512 维的完整向量, 但条目数减到四分之一. 压缩权重逐维度独立(Hadamard 积), 等于每个特征维可以选择从块内哪几个 token 取信息. 与 NSA 的块压缩相比, CSA 用重叠窗口和两组 KV 让块边界处的信息不被切断, NSA 的做法见 [NSA](../../../llm-guide/2-核心原理与架构/2.4-稀疏注意力/02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md). 报告没有给 $m$ 取 2, 4, 8 的对比.

**CSA 第二步: 索引器选块, MQA 计算**

压缩后, CSA 沿用 V3.2 的 lightning indexer 选 top-k. 索引器的键也按同样方式压缩, 查询由低秩方式生成: 先把 $\mathbf h_t$ 降到 $d_c$ 维的潜变量 $\mathbf c^Q_t$, 再上投影成 $n^I_h$ 个索引头, 分数仍是 $\sum_h w_{t,h}\mathrm{ReLU}(\mathbf q^I_{t,h}\cdot K^{\mathrm{IComp}}_s)$, 见式 (13)–(17). 两个模型的索引器都是 64 头, 每头 128 维; top-k 在 Flash 上是 512, Pro 上是 1024. 每个被选中的条目代表 4 个 token, 所以 Pro 每个查询实际覆盖约 4096 个 token 位置, 比 V3.2 的 2048 多, 但选出的条目数只有一半. 报告第 2.3.4 节说 V4 选了比 V3.2 更小的 top-k, 以提高短文本和中等长度文本上的效率: 序列不长时, 压缩条目总数和 top-k 相差不多, 注意力计算量主要由 top-k 决定. 核心注意力用 MQA: 每个压缩条目同时当键和值, 所有查询头共享. 查询头由同一个 $\mathbf c^Q_t$ 上投影得到, 与索引器共用潜变量. Pro 有 128 个查询头, Flash 有 64 个, 每头 $c=512$ 维. 这样 $c\cdot n_h$ 很大, Pro 达到 65536 维, 直接投影回 7168 维代价太高, 所以用分组输出投影: 把头分成 $g$ 组, 每组先投到 $d_g=1024$ 维, 再拼起来投回 $d$. Pro 取 $g=16$, Flash 取 $g=8$. 按 Pro 的配置, 分组后输出投影约 1.8 亿参数, 不分组直接投需要约 4.7 亿.

### 1.2. HCA 与层的排布

**Heavily Compressed Attention**(HCA)用更大的压缩率 $m'=128$, 窗口不重叠, 只有一组 KV, 见式 (20)–(23); 压缩后不做稀疏选择, 查询对所有压缩条目做稠密注意力, 也用共享 KV 的 MQA 和分组输出投影. 1M 上下文下, HCA 每层只有约 8192 个条目, 稠密计算也不贵; CSA 每层有约 26 万个条目, 所以需要索引器再挑. 两者的分工是: HCA 给出全局的粗粒度视图, CSA 在细一些的粒度上按内容挑远处的块. 层排布上, Flash 前两层是纯滑动窗口注意力, Pro 前两层是 HCA, 之后 CSA 与 HCA 交错. 按 Pro 的 61 层算, 前两层 HCA 之后 59 层交错, 约 30 层 CSA, 31 层 HCA (推导). 报告没有解释为什么 Flash 前两层只用滑动窗口而 Pro 用 HCA, 也没有给交错比例的消融. 两种注意力的计算、交互状态与代价如下:

| | CSA | HCA |
|---|---|---|
| 谁算 | 每个 token 算两组 KV 向量 $C^a, C^b$ 和两组压缩权重, 每满 4 个 token 产出一个 512 维条目; 索引器另算一份压缩键 | 每个 token 算一组 KV 向量和压缩权重, 每满 128 个 token 产出一个 512 维条目 |
| 和谁算 | 查询先经索引器给全部压缩条目打分, 只和 top-k 个条目加最近 128 个原始 token 做注意力 | 查询和全部压缩条目加最近 128 个原始 token 做稠密注意力 |
| 缓存怎么变 | 每 4 个 token 追加一个主 KV 条目和一个索引键; 不满 4 个的尾巴放在状态缓存里 | 每 128 个 token 追加一个条目; 尾巴同样暂存 |
| 丢了什么 | 块内 4 个 token 的逐 token 细节只剩加权和; 没被 top-k 选中的条目这一层完全看不到 | 128 个 token 的细节压成一条, 远处只剩粗粒度信息, 精确定位靠交错的 CSA 层和滑动窗口 |

两种层交错, 是让每一层都只付一种代价: CSA 层的远程信息是细的但不全, HCA 层的远程信息是全的但粗. 1M 长度下 HCA 每层只有约 8192 个条目, 稠密计算不贵; CSA 每层约 26 万个条目, 打分开销落在索引器上. CSA 与 HCA 的对比和更多背景见 [CSA-HCA 混合压缩注意力](../../../llm-guide/2-核心原理与架构/2.4-稀疏注意力/04-CSA-HCA-混合压缩注意力/04-CSA-HCA-混合压缩注意力.md).

**注意力的四项补充设计**

第 2.3.3 节补了四项. 一是对每个查询头和唯一的 KV 头在核心注意力前做 RMSNorm, 防止注意力 logit 爆炸. 二是部分 RoPE: 查询和 KV 条目只在末尾 64 维加 RoPE. 因为 KV 条目同时当键和值, 注意力输出是 KV 的加权和, 会带上被注意位置的绝对位置编码; 报告的对策是对输出的末尾 64 维再施加位置为 $-i$ 的 RoPE, 抵消查询自身位置, 使输出只带相对位置信息. 这个细节在 MLA 里不存在, 因为 MLA 的值向量不加 RoPE. 三是滑动窗口支路. 为保证因果性, 查询只能看之前的压缩块, 看不到自己所在块内的其他 token; 而语言建模里最近的 token 通常最相关. 所以每个查询另外取最近 $n_{\mathrm{win}}=128$ 个未压缩 token 的 KV, 与压缩条目一起参加注意力. 四是 attention sink: 每个头有一个可学习的 sink logit $z'_h$, 加进 softmax 分母, 见式 (27):

$$
s_{h,i,j}=\frac{\exp(z_{h,i,j})}{\sum_k\exp(z_{h,i,k})+\exp(z'_h)}.
$$

分母多出的 $\exp(z'_h)$ 不对应任何位置, 也没有 value, 所以 $\sum_js_{h,i,j}=\frac{\sum_k e^{z_{h,i,k}}}{\sum_k e^{z_{h,i,k}}+e^{z'_h}}<1$, 缺的那部分权重被「吸走」, 输出向量的模随之变小. 当所有真实位置的 logit 都远小于 $z'_h$ 时, 权重总和接近 0. $z'_h$ 按头学习, 与查询无关, 所以它相当于每个头一条固定的「输出多少」门槛. 压缩条目数随长度变化很大, 有了 sink, 一个头在没有相关内容时可以选择几乎不输出, 而不是被迫把权重分给无关条目.

图 1 右侧的单 token FLOPs 曲线上, 1M 位置处 V3.2 约 1.19T, Pro 约 0.32T (图上标「低 3.7 倍」), Flash 约 0.12T (标「低 9.8 倍」)(读图). 1/3.7 约 27%, 对应引言里 Pro 的 FLOPs 比例; 1/9.8 约 10%, 是 Flash 的 FLOPs 比例, 和 Pro 的 KV cache 比例 10% 恰好同数, 不是一回事. 引言给出的 Flash KV cache 比例是 7%. 报告的 FLOPs 按「等效 FP8 FLOPs」计. V3.2 的曲线从约 0.1T 线性涨到 1.2T, 主要是索引器随长度线性增长的开销; V4 的斜率小得多, 因为 CSA 的索引器只对四分之一的条目打分, HCA 没有索引器. 第 2.3.4 节把效率来源分成存储和计算两类. 存储上, KV 条目的 RoPE 维用 BF16, 其余维用 FP8, 比纯 BF16 省近一半, 这一项直接缩小 KV cache. 计算上, 索引器内部的注意力打分用 FP4, top-k 比 V3.2 小, 这两项减的是 FLOPs, 不改变每 token 存多少字节. 报告说最主要的一项仍是压缩注意力和混合注意力本身, 它同时减小 FLOPs 和 KV cache.

**Muon 优化器**

除嵌入, 输出头, mHC 的静态偏置与门控系数, 以及所有 RMSNorm 权重仍用 AdamW 外, 其余参数都用 **Muon**, 见 [Muon 优化器专题](../../../llm-guide/6-训练与推理优化/6.5-优化器/6.5.2-Muon/01-Muon优化器专题/01-Muon优化器专题.md). Algorithm 1 依次执行: 动量累积, 用 Nesterov 技巧组合动量和当前梯度, 做 Newton-Schulz 正交化, 把更新矩阵乘以 $\sqrt{\max(n,m)}\cdot\gamma$ 调整 RMS, 随后做权重衰减并更新. Newton-Schulz 迭代的目标是把矩阵 $M=U\Sigma V^T$ 近似成 $UV^T$, 即所有奇异值变成 1, 相当于让更新在各个方向上步长相同. V4 的改动是混合 Newton-Schulz: 共 10 步, 前 8 步用系数 (3.4445, −4.7750, 2.0315) 快速把奇异值推近 1, 后 2 步用 (2, −1.5, 0.5) 精确稳定在 1. 把系数代入迭代多项式 $f(x)=ax+bx^3+cx^5$: 前一组在 $x=1$ 处 $f(1)\approx0.70$, 1 不是它的不动点, 小奇异值被快速放大, 但最终只落在 1 附近的一个区间; 后一组 $f(1)=1$ 且 $f'(1)=0$, 能把奇异值稳定收敛到 1(推导). 两者组合兼顾速度和精度. 超参: 动量 0.95, 权重衰减 0.1, 更新矩阵的 RMS 调到 0.18 以复用 AdamW 的学习率. 报告引用的 Liu et al. (2025) 在 Muon 上用 QK-Clip 防止注意力 logit 爆炸; V4 因为已对查询和 KV 条目做 RMSNorm, 不再需要 QK-Clip. 报告没有给 Muon 与 AdamW 的收敛速度对比.

## 2. 预训练

第 3.1 节的细粒度专家并行把 Dispatch, Linear-1, Linear-2, Combine 四个阶段融进一个流水化内核, 专家按 wave 调度: 一组专家的数据一到就开始计算, 同时传下一组的 token, 发回已完成专家的结果. 相对非融合基线, 一般推理负载快 1.50–1.73 倍, RL rollout 等延迟敏感场景最高 1.96 倍, 内核以 MegaMoE 名义开源. 报告给出通信完全被隐藏的条件: 每个 token-专家对需要 $6hd$ FLOPs 和 $3h$ 字节通信(FP8 发送加 BF16 回收), 所以只要峰值算力与带宽之比 $C/B\le 2d$, Pro 的专家中间维 $d=3072$ 对应 6144 FLOPs/Byte, 即每 GB/s 带宽可以隐藏 6.1 TFLOP/s 的计算. 第 3.3 节做了端到端的批不变与确定性内核. 批不变指同一个 token 的输出与它在 batch 中的位置无关, 按位一致: 注意力放弃 split-KV, 用单 SM 内核加多 SM 内核两套实现并保证累加顺序相同; 矩阵乘全部换成 DeepGEMM, 多数场景放弃 split-k. 确定性针对反向传播: 稀疏注意力反向不用 atomicAdd, 每个 SM 用独立缓冲再确定性求和; MoE 反向做 token 顺序预处理和缓冲隔离; mHC 里输出维只有 24 的小矩阵乘, 分开输出各段再确定性归约. 这些保证了预训练, 后训练和推理三条路径按位对齐, 训练出现损失尖峰时可以精确复现.

**FP4 量化训练与 KV 缓存管理**

第 3.4 节在后训练阶段引入 FP4(MXFP4)量化感知训练, 覆盖两处: MoE 专家权重, 以及 CSA 索引器的 QK 路径. 索引分数也从 FP32 降到 BF16, top-k 选择器快 2 倍, KV 召回率保持 99.7%. 专家权重的做法是: FP32 主权重先量化到 FP4, 再反量化到 FP8 参与计算. 报告说这一步无损, 因为 FP8(E4M3)比 FP4(E2M1)多 2 位指数, 只要一个 128×128 的 FP8 块内, 各个 1×32 FP4 子块比例因子的最大最小比不超过阈值, 细粒度比例信息就能被 FP8 的动态范围吸收. 反向时梯度直接传回 FP32 主权重, 等价于直通估计器. RL rollout 和推理直接用真实 FP4 权重, 保证采样行为与线上部署一致. FP8 训练的背景见 [FP8 混合精度训练详解](../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/02-FP8混合精度训练详解/02-FP8混合精度训练详解.md).

推理侧, 混合注意力打破了 PagedAttention 的前提: 各层 KV 大小不同, 滑动窗口有自己的缓存与淘汰策略, 压缩分支还有凑不满 $m$ 个 token 的尾巴要暂存. 第 3.6 节把 KV 分成两部分: 经典 KV cache 存 CSA/HCA 的压缩条目, 每块覆盖 $\mathrm{lcm}(m,m')=128$ 个原始 token; 状态缓存存滑动窗口 KV 和未压缩的尾巴, 每个请求一个固定大小的块, 当作状态空间模型的状态来管理. 共享前缀复用放在磁盘上: 压缩条目全部落盘; 滑动窗口 KV 约是压缩条目的 8 倍, 提供三种策略, 全量存, 每 $p$ 个 token 存一次检查点, 或者完全不存, 靠已缓存的压缩条目重算最近 $n_{\mathrm{win}}\cdot L$ 个 token 恢复.

**数据与预训练日程**

**训练不稳: 两种有效但机理不明的手段**

第 4.2.3 节记录了万亿参数 MoE 训练中的明显损失尖峰: 回滚后训练可以暂时恢复, 尖峰仍会再次出现. 实验将尖峰与 MoE 层的离群值联系起来, 路由机制还会放大这类离群值. 第一种处理手段是 **Anticipatory Routing**: 第 $t$ 步用当前参数 $\theta_t$ 计算特征, 路由索引则由历史参数 $\theta_{t-\Delta t}$ 计算. 实现上在第 $t-\Delta t$ 步提前取第 $t$ 步的数据, 预先算好路由并缓存. 该机制会增加约 20% 的墙钟开销; 系统只在检测到尖峰时自动短回滚并临时开启, 运行一段时间后切回正常训练, 因此对完整训练的影响很小. 第二种手段是 **SwiGLU Clamping**: 把 SwiGLU 的线性分支夹在 $[-10, 10]$, 门控分支上界设为 10, 两个模型全程使用. 路由和主干解耦为什么有效, 一个可能的解释是: 路由和专家权重同步更新时, 专家变强会吸引更多 token, 更多 token 又让它更新更多, 形成正反馈, 延迟路由能打断这个循环. 报告自己说两种手段的理论机理仍不清楚, 是作为经验公开给社区. 报告没有给出尖峰的频率, 开启 Anticipatory Routing 的总时长, 也没有给出 clamp 触发的比例.

### 2.2. 专家训练: 三档推理, 生成式奖励与工具格式

后训练先按领域训专家, 每个专家先 SFT 再用 GRPO 做 RL, 超参沿用前作, 见 [GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md). 领域包括数学, 代码, Agent, 指令跟随等. 推理投入分三档: Non-think 直接给摘要; Think High 先写思考 token 再给摘要; Think Max 在系统提示开头加一句 「Reasoning Effort: Absolute maximum with no shortcuts permitted.」 三档对应 RL 时不同的长度惩罚和上下文窗口, 评测中上下文分别是 8K, 128K, 384K. 报告没有给三档各自的长度惩罚系数. 难验证任务不再用标量奖励模型, 改用带 rubric 的 RL 数据和生成式奖励模型(GRM), 并且直接对 GRM 本身做 RL: actor 网络同时充当 GRM, 评判能力和生成能力一起优化, 报告说这样只需要少量多样的人工标注. 工具调用改用 XML 格式, 加一个特殊 token `|DSML|`, 报告说 XML 能减少转义失败和工具调用错误. 交错思考比 V3.2 更进一步: 工具调用场景下所有推理内容在整段对话中保留, 包括跨用户消息; 普通对话仍在新用户消息到来时丢弃旧推理. Quick Instruction 在输入序列后追加专用特殊 token, 直接复用已算好的 KV cache 完成是否搜索, 生成搜索词, 判断权威性和领域等辅助任务, 省掉单独小模型的重复预填充, 降低首 token 延迟.

**OPD: 十多个教师合成一个学生**

专家训完后, 用多教师 **On-Policy Distillation** 合成最终模型, 完全取代了 V3.2 的混合 RL 阶段. 目标是式 (29) $\mathcal L_{\mathrm{OPD}}=\sum_i w_i\,\mathrm{KL}(\pi_\theta\|\pi_{E_i})$, 样本由学生自己生成, 权重 $w_i$ 按专家的相对重要性设定, 这一阶段用了**十个以上**教师. 反向 KL 让学生在自己会走到的状态上贴近教师, 并倾向于集中在教师的高概率区域, 这对「数学题听数学专家, 代码题听代码专家」的选择性学习是合适的, OPD 的基本原理见 [OPD 基础原理](../../../llm-guide/4-后训练/4.9-OPD/4.9.1-OPD方法与落地/01-OPD基础原理/01-OPD基础原理.md) 与 [On-Policy Distillation 深度解析](../../../llm-guide/4-后训练/4.9-OPD/4.9.1-OPD方法与落地/01-OPD基础原理/01-OPD基础原理.md).

常见做法是把全词表 KL 简化成采样 token 处的单点估计, 用 $\log(\pi_{E_i}/\pi_\theta)$ 当逐 token 优势塞进 RL 框架. 报告说这样方差大, 训练不稳, 所以改用全词表 logit 蒸馏. 词表超过 10 万, 为所有教师物化 logits 不可行, 第 5.2.2 节的办法是: 教师权重放在集中式分布存储里按需加载; 只缓存教师输出层前的隐藏状态, 训练时再过对应的输出头重建 logits; 样本按教师编号排序, 保证每个 mini-batch 中每个教师头只加载一次, 显存里最多驻留一个教师头; KL 用专门的 TileLang 内核计算. 报告没有给 OPD 的步数, 学生生成长度, 各教师权重, 也没有给 OPD 与混合 RL 的对比实验.

**RL 与 OPD 的系统设计**

第 5.2.3 节处理集群抢占和硬件故障. 每个生成请求有一个 token 粒度的预写日志: 每生成一个 token 立即追加; 抢占时暂停推理引擎并保存未完成请求的 KV cache, 恢复时继续解码; 硬件致命错误时用日志里的 token 重新预填充. 报告特别指出, 被中断的请求从头重新生成在数学上是错的, 会引入长度偏差: 短回答更容易在中断前完成, 从头重来会让模型更倾向短序列. 如果推理栈批不变且确定, 也可以用固定随机种子重新生成, 但要重跑解码, 效率不如预写日志. 第 5.2.4 节为百万 token 的 RL 把 rollout 数据拆成轻量元数据和重量级逐 token 字段, 元数据全局加载做打乱和打包, 逐 token 字段按 mini-batch 用完即释放. 第 5.2.5 节的沙箱平台 DSec 用 Rust 写成, 单集群管理数十万个并发沙箱; 一套 Python SDK 背后有四种执行底座: 函数调用, Docker 兼容容器, Firecracker microVM, QEMU 全虚拟机. 每个沙箱有全局有序的轨迹日志, 训练任务被抢占后可以回放已完成命令的缓存结果, 避免重复执行非幂等操作. Agent RL 的一般流程见 [Agentic RL 训练](../../../llm-guide/13-Agent/13.4-Agent训练与进化/13.4.1-AgenticRL训练/13.4.1-AgenticRL训练.md).

**评测协议与主结果**

## 3. CSA、HCA 与 Indexer 的计算链

**统一符号下的 CSA 计算链**

设输入序列为 $H\in\mathbb R^{N\times d}$, 压缩步长为 $m$, 压缩条目数 $M=\lceil N/m\rceil$. 第 $j$ 个压缩条目从局部窗口 $G_j$ 聚合原 token:

$$
c_j=\sum_{i\in G_j}\alpha_{j,i}W_Vh_i,
\qquad
\alpha_{j,i}=\frac{\exp z_{j,i}}{\sum_{u\in G_j}\exp z_{j,u}}.
$$

V4 的窗口覆盖 $2m$ 个 token, 相邻条目有重叠, 并用块内绝对位置偏置区分同一窗口中的槽位. 重叠让边界附近 token 至少进入相邻一个条目, 代价是每个原 token 参与约两次压缩. 当 $m=4$ 时, 条目数约降到 $N/4$, 压缩器实际读取仍约 $2N$ 个 token 表示. Indexer 对查询位置 $t$ 产生分数 $u_{t,j}=f(q_t^{I},k_j^{I})$, 取

$$
S_t=\operatorname{TopK}_j(u_{t,j},k).
$$

主注意力随后只在 $S_t$ 中计算

$$
o_t=\sum_{j\in S_t}
\operatorname{softmax}_{j\in S_t}
\left(\frac{q_t^\mathsf Tk_j}{\sqrt{d_h}}+b_{t,j}\right)v_j.
$$

压缩、候选选择与集合内注意力是三个独立误差源. 压缩决定条目里还剩什么信息; Indexer 决定哪些条目有资格进入主注意力; softmax 决定集合内怎样混合. 提高 top-k 只能缓解漏选, 无法恢复压缩阶段丢掉的块内次序. V4 的主分支使用 MQA 形式读取压缩 KV, 多个查询头共享同一组 K/V. 共享减少 KV 宽度, 但查询头仍可有不同 $q_h$ 与输出投影. 因而每个头能从同一压缩记忆读取不同组合, 写入记忆的子空间却共同受限. 因果性要求压缩条目不能混入查询位置未来 token. 靠近序列尾部的未满窗口需要掩码; 重叠窗口若跨越 $t$, 只能使用其中 $i\le t$ 的部分. 训练和推理若对尾块处理不同, 会出现隐蔽泄漏或分布偏差.

CSA 用学习 Indexer 做内容选择, 擅长跨很远距离寻找少量相关条目; HCA 用更激进的层级压缩扩大覆盖, 更像固定结构的低分辨率全局视野. 两者交错相当于在「内容寻址」和「覆盖保证」之间分摊风险. Indexer 漏掉证据时, HCA 仍可能通过粗粒度摘要保留主题; HCA 抹掉细节时, CSA 可直接选中更细条目. 设 HCA 第一级压缩率 $m_1$, 第二级 $m_2$, 最终条目约 $N/(m_1m_2)$. 若两级聚合均为凸组合, 最终 value 是原 token value 的线性组合; 表达能力受聚合权重与层级瓶颈限制. CSA 保留 $N/m$ 个细条目再取 top-k, 计算依赖 $k$, 存储仍依赖 $N/m$. HCA 同时压存储与读取条目, 代价是无法按 query 恢复细节. 混合排布还能周期性刷新表示. 某层 CSA 选择的条目进入后续非线性变换, HCA 层再把更新后的表示汇总; 下一组 CSA 的 Indexer面对更深语义. 若所有稀疏层共享同一索引, 深层无法改变检索目标; 若每层都独立全局索引, 计算与缓存开销升高. V4 在两端之间取了复杂折中.

反例一是精确复制任务. 长上下文中某处只有一个 20 位数字, HCA 平均聚合容易抹掉, CSA 只要 Indexer 命中就能保留. 反例二是分散证据计数. 数百段各贡献一个弱信号, 固定 top-k 的 CSA 会漏掉多数, HCA 的全局摘要反而可能保留总量. 两类任务解释了单一稀疏模式难以覆盖所有长程依赖. 交错架构也让归因变难. 最终输出经过多层 CSA/HCA, 某个 benchmark 提升无法归给单层. 最小消融应固定参数与训练 token, 比较全 CSA、全 HCA、交错三种排布, 再扫压缩率与 top-k. 报告公开最终配置, 没有给这张完整网格. 把密集注意力概率记为 $p_j$, 候选集合为 $S$, 集合外质量

$$
\delta=\sum_{j\notin S}p_j.
$$

稀疏注意力在 $S$ 内重新归一化, $\hat p_j=p_j/(1-\delta)$. 若 $\|v_j\|\le V$, 则

$$
\|o-\hat o\|
\le \left\|\sum_{j\notin S}p_jv_j\right\|
+\left\|\sum_{j\in S}(p_j-\hat p_j)v_j\right\|
\le2\delta V.
$$

界依赖漏掉的概率质量, 不依赖漏掉的位置个数. 位置 recall@k 很高仍可能漏掉唯一高权重条目; 位置 recall 较低但漏项权重接近零, 输出仍稳定. Indexer 评测应报告质量加权召回. 压缩再引入重建误差. 设原 value $v_i$ 被所属条目近似为 $\tilde v_i$, 且 $\|v_i-\tilde v_i\|\le\epsilon_i$. 即使候选覆盖全部相关块, 输出误差还含

$$
E_c\le\sum_i p_i\epsilon_i.
$$

总误差可粗分为 $E\le2\delta V+E_c$. 增加 top-k 只减第一项, 缩小压缩率或改善聚合才能减第二项. 实验中若质量随 top-k 增长后很快平台化, 平台高度反映压缩与表示误差. 这个界是单层、固定 query 的局部界. 多层网络中误差经残差与非线性传播, 若后续块 Lipschitz 常数为 $L_l$, 最坏会乘 $\prod_lL_l$. 实际残差和归一化通常抑制爆炸, 不能把单层小误差直接等同端到端无损. softmax 分布平坦时, 固定 top-k 的 $\delta$ 很大; 分布尖锐时很小. 因此稀疏注意力依赖「相关性可集中」这一数据假设. 多证据归纳、全局计数和均匀匹配构成天然压力测试.

### 3.1. Indexer 怎样获得训练信号

Top-K 是离散选择, 未选条目没有主注意力梯度. 若只依赖最终语言损失, 早期误选会让正确条目长期看不到梯度, 形成自我强化. V4 先用稠密注意力预热, 再短暂训练 Indexer, 随后切到稀疏路径, 目的就是让选择器在承担主任务前获得可用排序. 密集教师可为每个 query 产生目标重要性 $a_j$. Indexer 分数经 softmax 得 $r_j$, 蒸馏损失可写为

$$
\mathcal L_I=\sum_j a_j\log\frac{a_j}{r_j}.
$$

若教师注意力有多头, 可以取头间最大值保住任一头的关键证据, 或取加权和反映平均贡献. 最大值偏向高召回, 和固定 top-k 更匹配;平均会压低只服务少数头的条目. 正负样本需要覆盖困难情况. 随机远处负例只教会主题匹配; 同实体不同时间、同函数名不同文件、相似段落中一个数字不同, 才能检验细粒度索引. 多证据任务应把一组位置作为联合正例, 防止每处权重不高而全部落出 top-k. 切换稀疏后, 主干表示会适应 Indexer 的选择偏差. 因此「稠密 checkpoint 直接替换稀疏注意力」低估联合训练效果; 同时也可能掩盖检索缺陷, 因为上游会把信息搬到更容易被选中的位置. 可用 oracle 候选、学习候选、随机候选三臂拆分表示上限与索引质量.

训练长度分布影响 Indexer. 4K 预热中负例少, 到 1M 时极值负例增加 256 倍. 即使每个负例分数分布不变, 最大负分数也随 $N$ 上升. 长度扩展阶段必须让选择器见到百万规模的困难干扰, 不能只依赖短序列排序精度. V3.2 MLA 每层每 token 主 KV 含 512 维潜变量与64维 RoPE 部分, BF16 口径为1152字节;再加 Indexer K. V4 把序列按压缩率 $m$ 变为约 $N/m$ 条, 每 token 摊销缓存近似

$$
B_{CSA}=\frac{L_C}{m}B_c+\frac{L_H}{m_H}B_h+B_{local},
$$

$L_C,L_H$ 是 CSA/HCA 层数, $B_c,B_h$ 是条目宽度, $B_{local}$ 是固定窗口缓存. 图1给V4-Flash每token global KV 3514字节,与V3.2的48068字节相差约13.7倍. 这个倍率同时包含序列压缩、层排布与条目格式,不能全归因于一个$m$. decode时,压缩器不再重算历史,主要成本是Indexer扫描$M=N/m$条目与主注意力读取$k$条. 若Indexer头数$h_I$、维度$d_I$,粗略乘加量

$$
C_I\approx2Mh_Id_I,
\qquad C_A\approx2kh_Ad_A.
$$

$k$固定时主注意力与$N$脱钩,Indexer仍线性增长. V4在百万上下文下的decode曲线继续上升,正来自这条扫描路径. V4.1用分层候选进一步压后续Reindex扫描,这是后续改进,不应倒写成V4已有机制. prefill不同. 所有query都要建立压缩条目并索引,若朴素每个query扫描此前$M$条,复杂度仍近二次. 实现可按块批处理、利用因果结构与矩阵乘提高硬件效率,算术量不会自动变成线性. 报告效率图需区分prefill吞吐与单token decode. 百万token按3514字节约3.514GB十进制、3.27GiB global KV/请求. batch8约26.2GiB,batch32约104.7GiB,还未计SWA、页表、量化scale与工作区. 稀疏把单请求变得可行,高并发仍需要前缀共享、分层存储和调度. V4 从4K逐步扩到16K、64K、1M. 每次扩展改变三件事: RoPE位置分布、Indexer负例数量、样本内部依赖跨度. 若训练数据只是把无关短文拼成1M, 模型学到的是边界与局部统计; 真正跨文档推理需要证据、问题与干扰在长范围内共同出现.

位置漂移可用相对距离$r=(t-j)/t$分桶. 同一证据内容平移到序列前部、中部、尾部,保持干扰不变,若召回随$r$系统下降,说明Indexer或位置编码存在距离偏置. 整体MRCR平均会被短长度掩盖,图9在1M端明显衰减正说明要看长度曲线. 多needle测试仍偏检索. needle通常词面独特、答案局部明确;真实Agent轨迹有重复工具输出、版本更新和跨轮条件. 更困难的样本应包含同实体多个版本,要求按时间或调用链选对;还要包含多个弱证据共同决定答案. 上下文容量也不等于有效记忆. 固定top-k=512时,从64K扩到1M,保留率下降16倍. 如果任务所需证据数随文档长度增长,固定k会形成硬上限. 适应办法包括动态k、层间累积、HCA全局摘要或先分层候选,各自增加计算或压缩误差. 训练目标仍是next-token prediction. 它能从自然长文获得远程监督,但许多token只依赖局部上下文,模型可在不使用远处证据时得到低loss. 长上下文阶段需要提高真正远依赖样本比例,或加入明确检索与多证据任务,否则「训练过1M」不能证明有效利用1M.

### 3.2. mHC、Muon 与稀疏注意力的耦合

mHC维持多条残差流,混合矩阵受流形约束,目标是在超深网络里保留信息与梯度. CSA/HCA会周期性压缩和选择信息,残差多流给局部层提供更多旁路,可能缓解稀疏分支遗漏;这只是机制上的可能联系,报告没有两者交叉消融. 设多流状态$X_l\in\mathbb R^{n\times d}$,更新

$$
X_{l+1}=B_lX_l+C_lF_l(A_lX_l).
$$

若$A,B,C$保持受约束的谱性质,梯度不会被任意放大或压扁. 稀疏注意力误差$e_l$进入$F_l$后,残差传播近似

$$
\Delta X_{l+1}=B_l\Delta X_l+C_le_l.
$$

多流能把误差分散到不同通道,不能恢复已丢证据. Indexer漏掉唯一事实时,稳定残差只会稳定地传播错误表示. Muon对矩阵梯度做近似正交化/预条件,与AdamW的逐元素尺度不同. 注意力投影、专家矩阵和mHC混合矩阵形状差异大,统一Muon超参未必最优. V4公开整体配置和端点结果,缺少「只换Muon」消融,所以Base提升不能单独归因优化器. Anticipatory Routing延迟路由参数,打断专家能力—负载正反馈;SwiGLU Clamping限制专家激活离群. 两者都针对MoE稳定性,与稀疏注意力Indexer是两套不同路由. 文章中提到routing时必须说明是专家路由还是注意力索引,否则容易把机制混在一起. Flash总参284B、激活13B,Pro总参1.6T、激活49B. 激活参数主要决定每token计算,总参数包含大量路由专家容量,更影响知识存储与条件计算. Pro在SimpleQA、FACTS上的大幅领先与总容量同时变化,无法只归给注意力.

数据侧V4加入新的代码、知识与长文策展,训练token也不同. Flash训练32T、Pro33T,V3.2的累计训练历史与数据分布又不同. Table1比较的是完整系统端点,结构、数据、优化器、规模一起变化. 事实性提升可由更多高质量知识数据、总参数容量或训练配方共同产生. 训练目标仍以next-token为主,后训练再通过专家SFT/RL与OPD塑造行为. Base表反映预训练底座,Max表还混入推理长度、工具、奖励与教师. 用Max的Agent分数反推HCA/CSA能力会跨越太多变量. 一个可辨识实验需要固定数据与算力,只换注意力;再固定结构,只换数据;再固定二者,只换优化器. 大模型成本使完整网格难以执行,可在小模型上筛机制,大模型只做关键点. 没有消融时,合理写法是列出共同变化并限制因果结论.

V3到V4并非单线升级. V3的MLA压KV宽度,V3.2的DSA引入Indexer,V4把序列压缩与HCA/CSA混合,V4.1再做跨层复用和FP4. 每一步压缩不同轴:头/宽度、序列、层、精度. 把V4称为「更强DSA」会漏掉压缩条目与HCA. 表1先按激活参数、总参数、训练token三轴排列,不要只按模型代际. 计算粗估用$6P_{act}D$:Flash约$2.5\times10^{24}$,Pro约$9.7\times10^{24}$ FLOPs. 再对每项分数计算相对V3.2差值,即可看到Flash低算力仍提升与BigCodeBench、MATH等反例并存. 注意力消融用四臂:密集、只压缩不Top-k、压缩+oracle候选、完整Indexer. 密集到压缩差值衡量条目损失;压缩到oracle衡量固定k上限;oracle到Indexer衡量检索误差. 再分别加入HCA层,才能判断混合收益. Indexer实验扫长度$N$、压缩率$m$、候选$k$. 每点报告加权召回$1-\delta$、输出误差、语言loss、prefill/decode FLOPs与KV字节. 若提高$k$只能降低$\delta$而loss不恢复,瓶颈位于压缩表示或后续推理.

长上下文实验固定内容,改变证据位置、证据数和近重复干扰. 单needle、多needle、全局聚合、版本消歧分开报告. MRCR表格值还要与各长度曲线同时给出,避免「1M」标签被理解成1M端点分数. 稳定性实验记录MoE激活峰度、专家负载、路由margin与loss spike. 分别关闭clamp、开启anticipatory routing、同时开启,比较尖峰频率与训练速度. 只报告回滚后恢复无法解释机制. 谱系对照固定四列:V3.2的MLA+DSA,V4的CSA/HCA,V4.1的CSA2+CED,每列写缓存条目来源、序列压缩、索引是否跨层复用、KV精度. 这样能看清V4.1继承V4的内容选择思想,同时替换了混合层与缓存组织,不会把后来的设计倒灌进V4.

**压缩窗口的频率响应**

压缩条目可以看成沿序列轴的降采样. 若聚合近似平均池化, 长度$m$窗口相当于低通滤波后每$m$点采样. 平滑主题被保留, token级突变、数字和标点属于高频分量, 容易衰减或混叠. 重叠$2m$窗口降低边界突变,不能取消降采样的信息上限. 设一维特征$x_i$,平均压缩$c_j=m^{-1}\sum_{i=jm}^{(j+1)m-1}x_i$. 对交替序列$x_i=(-1)^i$,偶数$m$时$c_j=0$,全部信息消失;对常数序列则完全保留. 学习权重能根据内容偏离平均,但一个固定维度条目仍无法无损编码任意$m$个向量. 块内绝对位置偏置给聚合器标出槽位,使「A在B前」和「B在A前」可产生不同条目. 若只用内容softmax而没有位置,交换同窗口token会保持相同加权集合. 位置偏置解决置换不变性,不保证所有次序可逆.

重叠窗口还改变缓存相关性. 相邻$c_j,c_{j+1}$共享约$m$个原token,误差和内容高度相关. Indexer选中多个相邻条目时,实际覆盖的信息小于条目数乘窗口大小. 评测候选覆盖应按原token并集计算,不能把重复覆盖算多次召回. 一个改进方向是根据内容边界动态分块,但动态边界会让缓存地址、并行打包与因果更新复杂. V4选择规则窗口与学习聚合,是在硬件友好和表达力之间取舍. Indexer最终只关心Top-k边界. 第$k$名与$k+1$名分数间隔

$$
\gamma_t=u_{t,(k)}-u_{t,(k+1)}
$$

决定选择稳定性. 查询或键扰动$e_q,e_j$使分数误差近似$e_q^Tk_j+q^Te_j$. 若两项误差差超过$\gamma_t$,候选翻转. 平均分数误差很小仍可能在大量小margin查询上改变集合. V4对Indexer Q/K使用低精度与专门训练,主KV也涉及FP8缓存. 应同时报告分数MSE、Top-k重合和教师质量加权翻转. 两集合Jaccard低不一定有害,若交换的是等价近重复条目;一个唯一证据被换出则影响巨大. 压缩会缩小margin. 多个原片段映成相似条目后,它们的键距离变近;长上下文又增加极值负例. 因而$m$、$N$与量化精度存在交互,分别做单因素实验会低估百万长度的翻转率. 可构造可控测试:保持正确条目分数不变,逐渐增加相似负例数,分别用BF16、FP8和模拟噪声排序. 绘制正确条目保留概率对$gamma$与$N$的曲线,再与任务准确率对应.

稀疏主注意力对已选条目的K/V与query可正常反传,集合外条目梯度为零. Indexer若用独立监督,其Q/K从蒸馏损失得到连续梯度;若依赖主loss,Top-K不可导需要straight-through、软近似或其他估计. 报告没有公开全部细节时,不能假定某一种实现. 对已选集合$S$,主注意力损失对value梯度为

$$
\frac{\partial\mathcal L}{\partial v_j}=a_jg_o,
\quad j\in S,
$$

集合外为零. 这会让压缩器优先优化常被选中的条目,罕见证据更新更少. 教师监督能给Indexer罕见正例信号,压缩value仍需通过被选择路径学习. 预热阶段的意义还包括避免dead region. 稀疏从随机初始化开始时,少数条目偶然得高分并持续获得梯度,其他条目停滞. 稠密主干先形成语义表示,再训练Indexer,能让初始排序与任务相关. 切换时若突然从dense变Top-k,loss会跳变. 可逐步减k或混合dense/sparse输出:

$$
o=(1-\lambda)o_{dense}+\lambda o_{sparse},
$$

让$\lambda$从0升到1. 是否采用这一路径应以报告为准;它说明可检验的切换稳定性机制.

## 4. 推理缓存、OPD 与多证据任务

**HCA/CSA 的缓存更新与 decode**

自回归decode每来一个token,只产生与当前位置相关的新局部状态. 当累积满一个压缩窗口,生成新条目;未满窗口需要维护暂存状态. 重叠窗口意味着同一token可能参与两个条目,实现需保存足够历史以完成下一条. 若压缩权重依赖窗口内全部token,新token到来前条目未定稿. 已定稿条目可持久缓存,尾部条目可能随每步变化. 这部分工作与固定SWA窗口类似,对百万历史不增长,但会增加每token固定成本. Indexer扫描历史键时,键缓存按压缩条目增长. 主KV与Indexer K可能有不同宽度和精度,缓存字节需分别计算. 只统计主KV会低估;V4图中的global KV总数应视为整条全局路径口径. 分页缓存还面临条目与原token映射. 前缀命中若停在窗口中间,复用已完成条目之外,还要恢复尾部压缩器状态. 若只保存定稿条目,命中点可能回退到上一个窗口边界;保存尾状态可提高命中精度,增加元数据.

跨请求共享要求相同前缀产生完全相同条目. 动态随机量化、不同batch形状或非确定核若造成差异,缓存复用会破坏逐位一致. 工程验证应比较独立prefill与前缀复用的logit误差. 长度课程不仅控制显存,也控制优化难度. 早期4K阶段每样本包含更多独立序列,梯度多样性高;1M阶段一个样本占大量token,global batch中独立文档数下降. 若batch按token固定,长度增长会减少序列数,梯度相关性上升. 设global batch为$B$ token、平均序列长$L$,每步独立序列约$B/L$. $B=75.5M$时,4K约18432条,1M只有约75条. 即使长序列内部包含多文档,样本级随机性仍不同. 数据packing与跨文档mask决定模型看到的是连续长文还是许多隔离片段. attention计算随长度增长,同token batch无法保持step时间不变. 稀疏降低增长率,Indexer扫描和压缩仍有额外成本. 训练系统可能减少micro-batch、增加梯度累积,改变归一化与流水效率.

长度扩展还需要位置频率适配. V4没有单独YaRN阶段,不表示位置问题消失;渐进长度与持续预训练本身承担适配. 端点结果只能说明整套课程有效,不能推断直接从4K跳1M同样稳定. 测试应按训练后期实际长度分布解释. 最大长度1M不等于大量token都来自1M样本. 若报告未给各桶比例,不能从总11T或总33T推算模型看过多少完整百万序列.

### 4.1. OPD 与底座能力的边界

OPD样本由学生策略生成,教师只在学生访问的状态上提供全词表分布. 这避免离线教师轨迹与学生状态错位,也意味着学生从不访问的策略区域没有监督. 初始底座若不会展开某类长程行为,教师难以凭KL把它凭空带入. 多教师目标

$$
\mathcal L=\sum_iw_i\operatorname{KL}(\pi_\theta\|\pi_i)
$$

若教师意见冲突,反向KL倾向选择某个高概率模态,权重决定领域折中. 全词表计算降低采样方差,不消除教师冲突和数据配比问题. 长上下文Agent能力同时依赖底座检索、后训练轨迹和推理预算. OPD可以教会何时搜索、怎样调用工具和如何组织答案,无法恢复CSA/HCA已丢掉的上下文证据. 分析Max模型时,架构上限与策略训练应分开. 教师隐藏状态缓存与输出头重建logits节省存储,前提是输出头和隐藏状态版本严格匹配. 多教师按编号排序减少头加载次数,会改变mini-batch样本顺序;训练系统需在全局shuffle与局部教师聚类之间平衡. OPD没有公开与混合RL的同算力消融,所以V4后训练提升属于整套专家+OPD结果. 十多个教师的数量也不能代表有效多样性,关键在领域覆盖、质量与权重.

V3使用MLA,每层历史token保存低秩潜变量与RoPE键,仍对全序列做注意力. V3.2加入DSA Indexer,主注意力只看少量token,但历史表示仍按token级MLA缓存. V4把历史token先压成条目,再用CSA选择,并插入HCA层;压缩从计算扩展到缓存序列维. V4.1保留「压缩记忆+内容索引」核心,用CSA2统一原CSA/HCA混合,去掉重叠与块内绝对位置路径,并让层间复用global KV与索引. CED让decoder global KV来自encoder末层,FP4再压精度. 这些改动在V4报告中不存在. 用四个轴比较最清楚:

| 版本 | 条目宽度 | 序列条目数 | 独立缓存层数 | 精度 |
|---|---:|---:|---:|---:|
| V3 | MLA低秩 | $N$ | 多层 | BF16/FP8路径 |
| V3.2 | MLA低秩+Indexer K | $N$ | 多层 | FP8部署 |
| V4 | 压缩KV | 约$N/m$ | CSA/HCA各层 | FP8主路径 |
| V4.1 | 压缩KV | 约$N/m$ | 跨层共享 | FP4主KV |

这个表只写结构轴,不代表能力排序. V4.1 Flash总规模、数据、多模态、Engram与训练日程都变了,不能用端点分数证明CSA2必然优于V4混合架构. 同理,V4相对V3.2的提升混有mHC、Muon、MoE规模、数据和后训练. 架构谱系回答「改了什么」,消融才回答「贡献多少」. 长文答错时先做oracle候选干预. 把正确证据条目强制加入Top-k,若答案恢复,失败位于Indexer;若不恢复,再换未压缩value,恢复则是压缩误差;仍不恢复则检查后续推理与训练目标. 如果短长度正确、长长度错误,同时测margin与最大负分数. margin随$N$下降且oracle恢复,属于极值干扰;oracle不恢复可能是位置外推或多证据容量. 如果数字、代码标识符错误而主题问答正常,检查块内压缩和量化. 将$m$减小、保留BF16、固定候选分别测试,能区分降采样与数值误差.

如果训练出现loss spike,同时记录专家路由负载、SwiGLU离群、Indexer熵和Muon更新范数. 专家路由与注意力索引是不同系统,不要看到「routing异常」就混为同一原因. 如果KV字节下降但decode不快,检查Indexer扫描、内存访问与kernel启动. 稀疏主注意力省下的计算可能被全历史粗排吃掉,尤其在1M长度. V4.1分层Indexer正针对这条剩余瓶颈. 这些定位步骤对应可干预组件,比用最终benchmark猜原因可靠. 每次只替换一条路径,保留同一checkpoint和输入,结果才有可比性.

### 4.2. 多证据任务为什么难

单证据检索只要求至少一个关键条目进入$S$. 多证据任务要求集合$E=\{e_1,\ldots,e_r\}$同时覆盖. 若每个证据独立召回概率为$p$,全部召回概率约$p^r$. 即使$p=0.95$,十处证据全覆盖也只有约60%. 实际召回相关,固定top-k又产生竞争,结果可能更低. 证据还可能分散在同一压缩窗口. 聚合器若偏向局部最显著token,多项弱证据会被强片段遮住. 先对每个原token构造贡献标签,再测压缩条目能否线性恢复证据属性,可以把聚合损失从Indexer漏选中分离. 全局计数是更极端反例. 答案依赖所有出现位置,任何固定k都只能取样. HCA摘要可能学习近似计数,误差随层级聚合累积. 这类任务不应期待稀疏注意力逐项精确,需要专门状态或算法结构.

多跳推理还有顺序:先找到A才能知道下一步应检索B. 一层Indexer的query尚未包含A,可能无法直接选B;深层重新索引能逐步完成. 因而只复用同一Top-k会限制多跳,V4多层独立索引保留这项能力,代价是计算更高. V4保留局部滑动窗口,处理邻近语法、短程状态和压缩前细节;全局CSA/HCA负责远程信息. 两分支输出融合后进入残差. 若局部窗口$w$,每层局部计算$O(Nw)$,与百万长度线性;全局分支按压缩与top-k控制. 局部分支还能补偿压缩边界. 一个短语跨两个窗口时,局部注意力先形成组合表示,后续压缩看到的已不是孤立token. 这要求压缩发生在足够深层;过早压缩会在局部结构形成前丢信息.

反例是距离略大于窗口但语义局部的依赖,例如长代码中的变量定义. 它只能走全局Indexer,若分数不足便断裂. 扫描证据距离从$w-1$到$w+1$,常能看到架构边界造成的突变. 局部与全局也会重复读取同一位置,增加计算. 可对全局候选排除局部窗口,但这改变softmax归一化与鲁棒性. V4具体实现应按报告,分析时不能自动假定去重. MoE总参数$P_{tot}$与激活参数$P_{act}$相差巨大. 每token只走少量专家,计算接近$P_{act}$,知识容量可利用更大$P_{tot}$. 但某个token只访问被路由专家,总容量不是统一可读内存. 若256个专家、top-8,单token访问路由专家比例约3.125%,再加共享专家. 领域知识需被路由到合适专家;负载均衡偏置又会改变选择. Pro总参1.6T带来事实记忆提升,仍可能受到路由可达性限制.

专家细分提高条件容量,每专家token减少,小batch下GEMM利用率下降. 训练大batch能聚合专家token,decode时每专家样本稀疏. Flash与Pro的服务成本不能只按激活参数比较,还要考虑专家并行通信和权重驻留. 底座评测中的知识、数学、代码分别受专家容量、数据与共享注意力影响. 某项提升不能直接证明总参数越大越好;BigCodeBench反例说明数据或专项能力可能退化.

**推理档位与结构成本**

三档推理改变生成token数与上下文上限. 总成本近似

$$
C_{total}=C_{prefill}(N)+T_{out}C_{decode}(N+\bar t).
$$

稀疏注意力降低长$N$的decode增长,Max档输出更长,仍会线性累积单token成本. Flash每token便宜但用更多token时,任务总成本可能接近或超过Pro. 评测分数随档位提升不能归因底座结构变化,checkpoint相同,主要变化是策略条件与预算. Non-think到High的大跃升说明许多任务受测试时计算限制;High到Max边际变小,呈现收益递减. 长输出还把自己的推理token加入上下文,Indexer需要在原问题、工具轨迹与自身历史中选择. 输出越长,干扰也越多. 推理预算提高并非永远有益,错误链可能自我强化. 比较模型时应画分数—token—延迟Pareto,而非只比Max分数. 同一档位名称在不同模型上token数不同,不能视为同计算预算. 原token有明确位置$i$,压缩条目覆盖一个窗口,需要定义代表位置. 若取窗口末端,因果关系自然,距离偏向较近;取中心可能更符合语义,却需确保不引用未来. V4用块内位置偏置与部分RoPE共同编码.

KV条目同时作key/value时,RoPE旋转会进入value聚合. 输出再施加逆位置旋转用于消除query自身绝对位置,保留相对关系. 这个操作依赖RoPE的群性质$R(a)^TR(b)=R(b-a)$. 若一个条目混合多个位置,单个代表旋转无法同时精确表示所有原位置. 块内位置偏置承担细节,主RoPE表示条目尺度位置. 压缩率越大,代表位置误差范围越大. 长度外推时低频RoPE维决定远距分辨率,只在64维加位置减少缓存/计算,也缩小位置子空间. 端点MRCR下降可能来自Indexer、压缩或位置编码,需用oracle候选与未压缩对照拆分. Full attention为$O(N^2d)$,CSA常写$O(NMd_I+Nkd_A)$. 当$M=N/m$,第一项仍是$O(N^2/m)$;实际硬件通过分块、层数减少和低维Indexer降低常数. 仅用「稀疏所以线性」会错误描述prefill. decode单query才是$O(Md_I+kd_A)$,随$N$线性粗排、固定k精读. 在短上下文,骨干GEMM主导;长上下文,Indexer扫描逐渐主导. 图1曲线交点由常数决定.

KV存储$O(N/m)$,但压缩器尾状态、SWA缓存和索引键增加固定/线性项. 实际字节应从布局相加,不能只用元素位宽乘主KV维度. 带宽也可能比FLOPs更关键.Indexer点积算术强度低,每token读取大量历史键;即使FLOPs不高,HBM带宽决定延迟. 低精度键同时减容量与带宽,排序误差成为代价. 报告明确给出的包括最终层排布、压缩与索引公式、训练日程、模型规模、端点评测和部分稳定措施. 它没有给完整注意力消融网格、Indexer监督全部超参、各长度数据比例、尖峰频率与OPD权重. 这些缺项限制因果结论. 推导可验证配置是否自洽,例如KV倍率、步数与FLOPs数量级;不能替代未公开的训练曲线. 理论误差界描述充分条件,不代表真实误差达到上界.

结构相似可说明谱系,不能证明直接代码继承. V3.2 DSA、V4 CSA与V4.1 CSA2都有Indexer,候选来源、缓存条目与跨层复用不同. 名称连续不等于算子等价. 内部评测与公开benchmark回答不同问题. 内部写作、搜索和研发任务更贴近产品,样本与评判由团队控制;公开表更可复核,也可能饱和. 两者并列可看覆盖,不能混成统一排名. V4最坚实的结论是:团队在1M上下文下把global KV与主注意力计算显著压低,并训练出强底座与后训练模型. 各单项技术贡献、极端输入稳健性和跨硬件复现仍需消融与实现证据.

## 5. 候选预算、训练稳定性与算力口径

**候选容量怎样随任务变化**

固定$k$把每层可读取条目数设成硬预算. 对单针任务,k远大于所需证据数;对全局归纳,k可能不足. 动态k可根据Indexer熵或margin调整:分布尖锐用小k,平坦用大k. 若分数概率为$r_j$,熵$H=-\sum r_j\log r_j$. 可选择覆盖累计质量$1-\epsilon$的最小集合,而非固定数量. 这让计算随样本难度变化,批处理形状与延迟更不稳定. 另一方案是各头不同候选. 多头关注不同关系,共享集合可能让主导头占满预算;独立集合提高覆盖,候选并集最多乘头数,KV读取与重排上升. V4的Indexer头与主注意力头设计需要按报告配置,不能默认共享程度. 层间候选也可累积. 第$l$层保留前层候选并加入新条目,多跳能力增强,集合逐层增长;每层截断则控制成本,可能忘掉早期证据. 这类选择解释了后续为何研究索引复用和跨层候选.

动态策略的验收应报告P50/P99 k与延迟,平均k会隐藏少数超大集合. 在线服务通常更看尾延迟,训练则更容易容忍可变计算. 判断压缩保留了什么,可以冻结模型后从$c_j$线性解码窗口属性:bag-of-words、token位置、数字、实体与顺序. 若简单探针无法恢复某属性,后续注意力更难利用;探针能恢复只说明信息存在,不保证模型会读. 重建误差应按频率分桶. 高频词与主题容易保留,罕见标识符、长数字和否定词更可能丢失. 平均MSE被常见token主导,需要任务加权指标. 窗口重叠可通过消融验证. 固定条目数,比较不重叠$m$窗口与重叠$2m$窗口,测边界短语与计算. 若收益只在跨边界任务出现,说明重叠确实用于边界鲁棒;若所有任务提升,可能来自额外计算容量. 位置偏置测试将同一token集合随机换序,观察条目变化与下游顺序判断. 无位置时理论上更接近置换不变,加偏置后应能区分. 这直接验证设计目标,比总榜更有解释力.

### 5.1. 训练稳定性的因果假设

MoE正反馈可写成负载$c_i$影响专家更新幅度,更新又影响下一步路由分数$s_i$. 线性化后

$$
\Delta c_{t+1}\approx A\Delta c_t,
$$

若最大特征值超过1,偏差增长成尖峰. Anticipatory Routing用旧参数算路由,相当于给反馈环加延迟;延迟通常也可能引发振荡,其有效性依赖具体耦合,所以报告把机理留作开放问题. Clamping直接限制专家输出与梯度的极值,降低$A$中的增益. 它可能同时削弱少数需要大激活的特征. 需要报告clamp命中率与命中token类型,才能判断代价. 短回滚后临时开启anticipatory routing说明它是恢复控制,不是全程配方. 若回滚到尖峰前却复用相同数据顺序,恢复与路由延迟共同变化,无法仅凭成功续训确定哪个因素起作用. 可做小规模干预:固定checkpoint与后续数据,多随机种子运行正常、clamp、延迟路由与二者组合,比较尖峰概率. 单条训练轨迹没有统计力.

公开benchmark的分数受采样次数、温度、提示与scaffold影响. Codeforces每题32候选再抽10个提交序列,最终rating是复杂随机变量;报告期望值比单次更稳,仍依赖内部题集与罚分实现. 长上下文图由读图获得的数应标近似. 曲线像素、平滑与长度桶都会带误差,不能用0.01差异下强结论. 表格MRCR 1M与端点曲线不同,应按各自协议理解. 内部胜率可给二项近似区间. 例如3170条中胜1986,单纯胜率标准误约$\sqrt{p(1-p)/n}\approx0.86$个百分点;但提示相关、评审偏差和平局处理使独立二项假设偏乐观. 30个白领任务中一题约3.3个百分点,67%与70%只差一题左右. 这适合发现大方向,不足以排精细名次. 第一步只实现压缩器,在短序列对齐dense输出与因果mask;第二步加入oracle候选,验证稀疏主注意力;第三步训练Indexer;第四步插入HCA层;第五步再做长上下文课程. 一次加入全部组件,失败时无法定位.

每步保留同一批合成测试:边界短语、唯一数字、近重复版本、多证据、全局计数. 输出压缩重建、候选召回、注意力误差和token loss四层指标. 性能测试把prefill与decode分开. prefill扫长度和batch,decode固定batch扫历史长度;同时记录HBM字节、Indexer FLOPs、主注意力FLOPs与KV容量. 只看tokens/s无法知道瓶颈迁移. 训练对照固定token预算与数据顺序,稠密baseline参数量需匹配. 稀疏模型若把省下算力用于更多参数或更多token,端点提升属于系统收益,不能当纯算子质量. 最终再接MoE、mHC、Muon和后训练. 这样形成从注意力机制到完整V4配方的证据梯度,每个结论都有对应干预.

**稀疏注意力的检索视角哪里不准**

把Indexer叫检索器很直观:query找候选,key像索引,value像文档. 但它与外部RAG有三处差别. 第一,条目由模型联合训练的压缩器生成,不是固定文本块;第二,候选进入可微注意力并逐层变化;第三,遗漏会直接改变隐藏状态,没有独立生成器兜底. 检索指标因此只能作诊断. 一个条目可能包含多token混合,无法给唯一文档相关标签;密集教师注意力也不等于因果贡献,高权重位置可能被其他位置替代. 删除/加入条目的反事实loss比静态相关性更接近真实作用. Indexer分数负责粗排,主注意力分数负责精排. 两者表示与维度不同,粗排高召回比精确排序重要. 训练若过度优化Top-1准确,可能损害Top-k覆盖.

外部检索可返回任意数量与原文,CSA固定在模型内部缓存和预算. 二者可叠加:外部RAG缩小输入语料,内部CSA再管理长上下文. 不能用外部检索成功证明内部索引无损. 单请求global KV约$3.27$GiB/1M token,batch并发$q$时若前缀完全独立,容量近似$q$倍. 80GB HBM扣除权重、激活与工作区后,能留给KV的空间有限;大模型通常跨卡张量/专家并行,每卡KV分片方式又影响上限. 前缀共享可让多个请求引用同一物理页. 共享比例$s$时,总KV约一个共享前缀加$q$份后缀,而不是$q$份全量. Agent多分支搜索从同一轨迹fork时收益大,独立百万文档没有收益. KV卸到主机或SSD降低HBM占用,带来恢复带宽. 每轮需要载入3.5GB,400Gbps理想约70ms,还未计协议和并发. 对交互延迟不可忽略. 稀疏注意力降低字节,同时让长前缀持久化更实际. V4.1的890字节进一步改善并发,不能用该数字回填V4部署. 两者主KV精度、跨层共享和持久化SWA策略均不同.

**数据污染与长上下文评测**

公开benchmark可能进入预训练数据,长上下文任务还常使用固定模板与needle. 高分既可能来自真实检索,也可能来自模板熟悉. 使用新生成内容、随机实体和程序化验证可降低污染. 随机needle太独特会让Indexer轻易命中. 困难版本应加入语义相似干扰、相同实体不同值和多处冲突,并随机化位置. 答案验证需检查引用的是哪个版本,不能只匹配最终字符串. CorpusQA类任务更接近多文档阅读,仍可能通过局部线索或问题先验回答. 删除证据、替换证据与交换位置的反事实测试能确认模型是否使用上下文. 训练数据中若包含评测格式,结构优势与数据记忆难分. 报告未公开全部数据,外部应把污染作为不确定性,不据此否定所有结果,也不把单榜视为机制证明.

令$m\to1$,CSA退化为token级稀疏选择,压缩误差趋近零,缓存和Indexer扫描增大. 令$m\to N$,全序列只有一个条目,计算最省,所有query共享同一全局摘要,细节基本消失. 这两端给出连续的质量—成本轴. 令$k=M$,Indexer不再稀疏,主注意力读取全部压缩条目;可隔离纯压缩质量. 令$k=1$,每层只读一个条目,适合唯一证据,多证据任务上限明显. 消融应包含这些退化点,帮助验证实现. HCA层级数增加也形成类似轴. 一层压缩保留更多局部细节,多层覆盖更广、误差累积. 最优点依赖任务分布,不存在脱离数据的固定答案. V4选择一组能支撑百万上下文的配置,证明该点可训练并有强端点表现. 它没有证明所有压缩率、层排布与数据上都最优. 后续V4.1主动精简,本身也说明V4是探索性复杂架构.

若Indexer选错条目,主注意力完全看不到正确value;若候选正确但压缩value失真,仍可能答错. 两者并非简单相加:量化和压缩也会改变Indexer key,先影响集合,再影响集合内输出. 四臂干预可拆交互:A为完整系统,B强制oracle集合,C在B上换未压缩value,D为dense. $L_A-L_B$近似检索项,$L_B-L_C$近似压缩项,$L_C-L_D$近似固定k与结构项. 再交换恢复顺序,两套差异就是交互. 对近重复片段,压缩可能抹掉唯一差异,Indexer即使语义正确也只能随机选;这时归因给Indexer不完整. 应检查压缩键是否还能区分版本. 多层网络还可能自我修复:某层漏选,后层query变化后重新找到证据. 单层召回低不必然导致答案错;反过来,各层平均召回高也可能在关键层同时漏同一证据. 需要跟踪证据跨层可见轨迹.

### 5.2. 训练算力与系统成本

**训练算力的另一种口径**

$6P_{act}D$适合估稠密前后向主干,MoE路由、注意力、压缩器、Indexer和mHC另有开销. 长序列注意力即便稀疏,其比例会随长度课程变化. 因而Flash与Pro的粗算只能比较数量级. 总参数不进入每token六倍公式,却影响权重加载、专家通信、优化器状态与checkpoint. 训练成本受激活参数和系统并行共同决定. Pro总参1.6T即使激活49B,权重驻留与EP规模仍比普通49B稠密模型复杂. batch逐步增大意味着用最大batch反推步数只给下界. 前期小batch增加optimizer step数,学习率按step还是token调度也影响预热比例. 报告给出token节点后,最可靠的是按token进度理解. FP8或低精度硬件使实际指令FLOPs与等价BF16模型FLOPs不同.MFU需说明分母峰值和精度权重,否则跨系统比较会混乱.

V4的技术中心是沿序列维压缩:先把历史变成少量条目,再用Indexer做内容寻址,HCA提供更粗全局覆盖. 它与MLA压条目宽度、V4.1压层与精度属于不同轴. Indexer的重要性随稀疏程度上升. 主注意力再强也无法读取候选外信息,所以召回、margin、困难负例和长长度极值分布应与最终loss一起评估. 百万上下文是一套训练课程、数据和系统结果,不等于把位置上限改成1M. MRCR端点衰减、多证据容量和固定top-k都给出明确边界. Pro与Flash的能力差来自结构、总参数、激活参数、数据、优化器与训练算力共同变化. 表格支持整套模型比较,不足以分配单项功劳. V4.1的精简说明V4更像一次大规模架构探索. 理解V4应抓住压缩—索引—精读三段链,而非把后续CSA2、CED与FP4提前写进来.

**一组手算例子**

取$N=1{,}048{,}576$、压缩率$m=4$,得到$M=262{,}144$条. 若top-k=512,主注意力只读取约0.195%的压缩条目,相对原token约0.049%. 这解释计算节省,也说明多证据覆盖预算极紧. 假设密集教师对候选外质量$\delta=0.02$,value范数上界$V=10$,单层输出误差界为$0.4$. 若漏质量升到0.1,界变2.0. 同样漏掉100个位置,影响取决于它们合计权重,位置数本身不能判断. 若Indexer每条键128维、32个查询头,单query扫描$M$条的乘加约$M\times128\times32\approx1.07$B,按乘加2 FLOPs约2.15GFLOPs. 主注意力若64头、头维128、512条,约8.4M乘加,粗排比精读大两个数量级. 具体配置与融合会改变数字,趋势说明百万decode为何受Indexer支配. 若每压缩条目主KV共512维FP8,数据本体512字节,$M$条单层约128MiB;多层相加很快达到GiB. scale、Indexer K与RoPE部分还会增加. 图1的每token字节是比凭单一维度更可靠的整机口径.

训练时global batch75.5M token,若全部为1M序列,每步只有约75条;若64K,约1180条. 独立样本数变化近16倍. 长度课程同时改变统计效率与系统形状. 假设证据数$r=8$,单证据召回0.95,独立近似下全覆盖$0.95^8\approx66.3\%$;召回0.98时约85.1%. 多证据准确率对单证据召回的小变化非常敏感,所以只报平均recall不足. 这些手算不是模型实测,作用是检查数量级与指标选择. 实际验收应用报告配置替换假设值,并以profiler、缓存布局和消融结果校正. 设一个查询面对$N$个无关条目,负例分数服从累积分布$F_-(x)$,最大负例分数$M_N$满足

$$
\Pr(M_N\le x)=F_-(x)^N.
$$

$N$增大时,$M_N$会向分布右尾移动. 正例分数分布即使保持不变,它被至少一个偶然高分负例超过的概率也会提高. 这解释了一个容易被忽略的现象:在8K上下文训练出的Indexer,放到1M时可能没有发生表示漂移,召回率仍然显著下降. 问题来自候选池扩大后的极值统计,不能只靠位置编码外推解决. 若正例分数固定为$s^+$,它胜过全部负例的概率是$F_-(s^+)^N$. 假设单个负例超过正例的概率只有$10^{-5}$,在一万个条目下无负例越界的概率约为$e^{-0.1}=90.5\%$;在二十五万个条目下则约为$e^{-2.5}=8.2\%$. 数值是独立近似,但数量级足以说明困难负例、分数校准与候选容量为何必须随长度一起训练. Top-k把条件放宽为正例只需超过第$k+1$高的负例,因此增大$k$可以换回召回,代价是主注意力计算与KV读取同步上涨. 更可取的评测是同时报告不同长度下的recall@k、正负margin分位数和每个查询的读取字节,画出质量—成本曲线. 只在固定长度报一个Top-k准确率,无法判断Indexer是否真正具备长度外推能力.

多正例任务还要看联合覆盖. 若八处证据散在不同主题,某一类高频干扰可能同时压过多处正例,独立假设会过于乐观. 可按查询类型、证据距离和干扰簇分组统计,再用整题答案验证索引指标与端到端损失是否一致. 这样才能把“候选没找全”与“候选齐了但模型不会组合”分开.
