# Engram: 用哈希 N-gram 查表给 MoE 加一条记忆轴

论文 *Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models* 由北京大学与 DeepSeek-AI 合作完成, arXiv 编号 2601.07372, v1 发布于 2026 年 1 月, 当前 v2 日期为 2026-07-12, 正文加附录共 35 页. 官方代码在 [deepseek-ai/Engram](https://github.com/deepseek-ai/Engram), 只有一个约 400 行的演示脚本 `engram_demo_v1.py`, 骨干的注意力和 MoE 用恒等函数占位, 没有训练代码, 也没有发布权重. Engram 的机制推导 (N-gram 嵌入的历史, 门控公式的来由, U 形曲线的直观解释) 已在 llm-guide 的 [条件记忆与 Engram](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.3-条件记忆与Engram/2.8.3-条件记忆与Engram.md) 和 [Engram: 从 N-gram 到可扩展查找](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.3-条件记忆与Engram/01-Engram-从Ngram到可扩展查找/01-Engram-从Ngram到可扩展查找.md) 中写过, 这里不再重推, 只讨论论文在具体设置下做了什么选择, 测了哪些数, 演示代码和公式有哪些出入, 以及证据链在哪几处偏弱.

论文的主张分三层. 结构层: 给 Transformer 加一个按局部 token 序列查表的模块, 查表的地址只由输入 token 决定. 预算层: 在总参数和激活参数都固定时, 把 MoE 专家的一部分参数挪给查表模块, 验证损失随分配比例呈 U 形, 最优点在专家占 75% 到 80% 附近. 系统层: 因为地址在前向之前就能算出, 嵌入表可以放在主机内存里异步预取, 100B 参数的表只让吞吐下降不到 3%. 下面按寻址, 预算, 主实验, 机制分析, 系统代价的顺序逐层核对.

## 1. 寻址与融合: 一个 token 怎样拿到 16 行嵌入

### 1.1. 分词压缩, 后缀 N-gram 与乘法异或哈希

Engram 的输入只有 token ID, 不看隐状态. 第一步是分词压缩: 用一个满射 $P: V \to V'$ 把 DeepSeek-V3 的 129280 个 token 合并成更少的类. 演示代码把每个 token 解码成字符串, 依次做 NFKC, NFD, 去重音, 小写化, 把连续空白合成一个空格, 再去掉首尾空白, 规范化后字符串相同的 token 映射到同一个新 ID. 附录 C 的 Table 6 给出的效果是词表缩小 23.43%. 这一步让「Apple」「apple」「 apple」共享同一组表项, 减少的是表中同义重复项的数量, 相当于提高了表容量的利用率.

第二步取后缀 N-gram. 对位置 $t$, 2-gram 是 $(x'_{t-1}, x'_t)$, 3-gram 是 $(x'_{t-2}, x'_{t-1}, x'_t)$, 序列开头不足的位置用压缩后的 pad ID 补齐. 哈希按演示代码写开是

$$
\mathrm{mix}^{(\ell)}_{t,n} = \bigoplus_{i=0}^{n-1} \left( x'_{t-i} \cdot m^{(\ell)}_i \right), \qquad z^{(\ell)}_{t,n,k} = \mathrm{mix}^{(\ell)}_{t,n} \bmod p^{(\ell)}_{n,k},
$$

其中 $\oplus$ 是按位异或, 乘法在 int64 上回绕; $m^{(\ell)}_i$ 是每个插入层各自的随机奇数乘子, 随机种子为 $\mathrm{seed} + 10007 \cdot \ell$; $p^{(\ell)}_{n,k}$ 是第 $\ell$ 层, 第 $n$ 阶, 第 $k$ 个头的表大小, 取素数. 代码从配置给定的表大小开始逐个向上找素数, 并要求所有层, 所有阶, 所有头的素数两两不同, 所以 16 张子表的大小都略有差异. 3-gram 的 mix 等于 2-gram 的 mix 再异或 $x'_{t-2} m^{(\ell)}_2$, 两阶共享前两项.

### 1.2. 多头哈希并不独立: 冲突上界

论文 2.2 节把多头哈希表述为「每个 N-gram 阶用 $K$ 个不同的哈希头, 以减少冲突」. 读代码后要修正一个直觉: 同一阶的 8 个头共用同一个 $\mathrm{mix}$, 只在模数上不同. 两个 N-gram 的 mix 一旦相等 (64 位值相等), 8 个头全部冲突; mix 不相等时, 它们在头 $k$ 上冲突等价于 $p_k$ 整除两者的差 $\Delta = \mathrm{mix}_a - \mathrm{mix}_b$. 因为各头的素数互不相同, 若在 $r$ 个头上同时冲突, $\Delta$ 必须被这 $r$ 个素数之积整除, 而 $|\Delta| < 2^{64} \approx 1.84 \times 10^{19}$.

用具体的数推一下. 演示代码每阶从 $5 \times 129280 = 646400$ 起找素数, 3 个约 $6.46 \times 10^5$ 的素数之积约为 $2.7 \times 10^{17}$, 只有 $2^{64}$ 的 1.5%, 可以整除某个差值; 4 个之积约 $1.7 \times 10^{23}$, 是 $2^{64}$ 的约 9000 倍, 不可能整除任何非零差值. Engram-27B 的 Appendix A 给出 Engram Vocab Size 为 2262400 (等于 $17.5 \times 129280$), 按 1.4 节的参数核对这是每个子表的行数, 4 个约 $2.26 \times 10^6$ 的素数之积约 $2.6 \times 10^{25}$, 同样远超 $2^{64}$. 所以 mix 不同的两个 N-gram 在同一阶最多冲突 3 个头, 至少 5 个头的表项是各自独占或与别的 N-gram 冲突. 若头真的独立, 8 个头全撞的概率随表大小指数下降; 实际情况是 mix 本身相等时 8 头全撞, 而 mix 相等的概率由乘法异或在 $2^{64}$ 空间上的分布决定, 远小于表大小的倒数. 结论方向和论文一致 (多头能压冲突), 但起作用的是素数模互不相同带来的「中国剩余定理式」约束, 与独立重复抽样无关.

一次冲突影响多大可以按拼接结构算. 每 token 每层拼接 2 阶 $\times$ 8 头 = 16 段, 每段 $d_{\mathrm{mem}}/16 = 80$ 维, 一个头冲突只污染 1/16 的维度, 后面的 $W_K$, $W_V$ 投影和门控还可以学会压低它. 论文没有测冲突率与损失的关系, 也没有和无冲突的完美哈希做对照; 按上面的上界, 冲突对一个 N-gram 的影响被限制在 3/16 以内. Table 6 的压缩率与表大小之间的关系文中也没有给出: 压缩后的 3-gram 组合数远大于每头约 $2.3 \times 10^6$ 行, 冲突必然大量存在, 只是被分散到多个头.

### 1.3. 门控与短卷积: 查到的向量用多少

拼接后的 $e_t \in \mathbb{R}^{d_{\mathrm{mem}}}$ ($d_{\mathrm{mem}} = 1280$) 经两组投影得到键 $k_t = W_K e_t$ 和值 $v_t = W_V e_t$, 维度都回到骨干的 $d = 2560$. 门控按式 (4) 是

$$
\alpha_t = \sigma\left( \frac{\mathrm{RMSNorm}(h_t)^\top \mathrm{RMSNorm}(k_t)}{\sqrt{d}} \right), \qquad \tilde v_t = \alpha_t \cdot v_t ,
$$

$h_t$ 是该层的输入隐状态. 门是一个标量, 作用在整个值向量上: 隐状态和查到的键方向一致时接近 1, 方向相反时接近 0. 这一步承担去噪职责: 哈希冲突或多义 N-gram 查到的向量与当前上下文不符时, 门控把它压下去. 演示代码在 sigmoid 之前多了一步带符号开方, 即 $s \mapsto \mathrm{sign}(s)\sqrt{|s|}$, 公式 (4) 里没有. 它压缩点积的动态范围: $s = 4$ 时 $\sigma(4) = 0.982$, 开方后 $\sigma(2) = 0.881$; $s = 0.25$ 时 $\sigma(0.25) = 0.562$, 开方后 $\sigma(0.5) = 0.622$. 大点积不易把门推到饱和, 小点积的梯度也更大. 论文训练的模型是否用了这一步, 文中没有给出.

门控之后是因果深度卷积: $Y = \mathrm{SiLU}(\mathrm{Conv1D}(\mathrm{RMSNorm}(\tilde V))) + \tilde V$, 核宽 $w = 4$, 膨胀 $\delta$ 等于最大 N-gram 阶 3. 感受野为 $(w-1)\delta + 1 = 10$ 个位置, 实际读取 $t, t-3, t-6, t-9$ 四个位置的门控输出, 每个通道独立. 论文说卷积权重零初始化, 训练开始时 Engram 只是门控后的值直接加回残差; 演示代码用 `nn.Conv1d` 默认初始化, 没有置零. 最终输出加到该层的残差流, 位置在注意力和 MoE 之前. 门控如何在 mHC 多分支上展开, 以及门控公式的推导, 见 llm-guide 的 [Engram 子文章](../../../llm-guide/2-核心原理与架构/2.8-其他架构方向/2.8.3-条件记忆与Engram/01-Engram-从Ngram到可扩展查找/01-Engram-从Ngram到可扩展查找.md) 与 [mHC 文章](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.3-残差连接/01-Hyper-Connections与mHC/01-Hyper-Connections与mHC.md).

![](images/p03-figure-1-the-engram-architecture-the-module-augments-the.jpg)

图 1 解析: 原文 Figure 1 画的是单个 Engram 模块. 左边是 token 序列, 每个位置抽取 2-gram 和 3-gram, 经哈希落到多个嵌入子表, 取出的行拼接后进入门控; 门控的另一路输入是该层隐状态. 右侧短卷积和残差加法把结果写回主干. 图中只画了单分支, 实际实验都接在 $M = 4$ 的 mHC 上: 4 个分支共享嵌入表和 $W_V$, 各有一个 $W_K^{(m)}$, 因此每个分支的门值不同, 写回的强度也不同.

### 1.4. 每 token 的计算与访存

按四件事收一下 Engram. 谁算: 插入层在注意力之前算一次, 每 token 每层查 16 行, 再做 5 个 $1280 \to 2560$ 的投影 (1 个 $W_V$ 加 4 个分支的 $W_K$), 论文把它们融合成一次 FP8 矩阵乘. 和谁算: 查表只依赖当前及前两个 token 的 ID; 门控用当前隐状态; 卷积读前 9 个位置的门控输出. 状态怎么变: 不引入跨步状态, 推理时不需要额外的 cache, 只需保留最近 9 个位置的值向量用于卷积. 丢了什么: N-gram 只看到最多 3 个 token, 对超过这个长度的模式只能靠卷积和注意力补; 门控是标量, 没法只保留值向量的一部分维度.

计算量可以从投影规模推出. 5 个投影共 $1280 \times 2560 \times 5 \approx 1.64 \times 10^7$ 个参数, 每 token 约 $3.3 \times 10^7$ FLOPs; Engram-27B 激活参数 3.8B, 每 token 前向约 $7.6 \times 10^9$ FLOPs, 一个 Engram 层的投影只占约 0.4%, 两层合计不到 1%. 访存方面, 16 行 $\times$ 80 维在 BF16 下是 2560 字节, 两层合计每 token 5 KB. 嵌入参数量则是 $2262400 \times 1280 \times 2 = 5.79 \times 10^9$, 正好对上 Table 1 的 5.7B; Engram-40B 是 $7239680 \times 1280 \times 2 = 1.85 \times 10^{10}$, 对上 18.5B. 每层 16 个子表各 80 维, 拼起来正好 1280 维, 所以这两个乘法说明 Appendix A 的 Engram Vocab Size 是单个子表的行数, 每层 16 个子表合计 $2262400 \times 1280 \approx 2.9 \times 10^9$ 个参数, 两个插入层各一份, 层间不共享. 演示代码同样是每个头一张约 $5 \times$ 词表大小的子表.

## 2. 稀疏分配: U 形曲线的口径

### 2.1. 分配比例 $\rho$ 与专家数的复算

式 (7) 把不激活的参数预算 $P_{\mathrm{sparse}} = P_{\mathrm{tot}} - P_{\mathrm{act}}$ 拆成两份: 专家占 $\rho P_{\mathrm{sparse}}$, Engram 占 $(1-\rho) P_{\mathrm{sparse}}$. 实验固定两档计算量: $C = 2 \times 10^{20}$ FLOPs 时 $P_{\mathrm{tot}} \approx 5.7\mathrm{B}$, $P_{\mathrm{act}} = 568\mathrm{M}$, 纯 MoE 基线 106 个专家; $C = 6 \times 10^{20}$ 时 $P_{\mathrm{tot}} \approx 9.9\mathrm{B}$, $P_{\mathrm{act}} = 993\mathrm{M}$, 基线 99 个专家. 两档的 $P_{\mathrm{tot}}/P_{\mathrm{act}}$ 都约为 10. 改变 $\rho$ 时只调整路由专家数和 Engram 表的行数, 训练流程和超参不变.

论文说 $\rho \approx 40\%$ 对应 46 个和 43 个专家. 这个数可以复算: 激活的 top-6 专家属于 $P_{\mathrm{act}}$, 不进入 $P_{\mathrm{sparse}}$, 所以可分配的是基线中未激活的 $106 - 6 = 100$ 和 $99 - 6 = 93$ 个专家. 保留 46 个专家时, 未激活的专家是 40 个, $40/100 = 0.400$; 保留 43 个时是 37 个, $37/93 = 0.398$. 两者都对上 40%, 说明论文把 Engram 表全部算作不激活参数, 每 token 实际读出的 16 行 (每层 1280 个参数) 被忽略. 这部分很小, 在 $P_{\mathrm{act}}$ 中占不到万分之一, 忽略是合理的.

Engram-27B 的 $\rho = 74.3\%$ 也能复算, 但需要一个文中没有给出的量: 专家的中间维度. 若取 1536 (DeepSeek 同规模 MoE 常用值, 论文和附录都没写), 每个专家参数为 $3 \times 2560 \times 1536 \approx 1.18 \times 10^7$, 每层少 17 个专家, 29 个 MoE 层 (30 层减去 1 个稠密层) 共少 $17 \times 29 \times 1.18 \times 10^7 \approx 5.82 \times 10^9$, 与 Engram 的 5.79B 吻合. 此时 MoE-27B 的不激活专家为 $66 \times 29 \times 1.18 \times 10^7 \approx 22.6 \times 10^9$, $\rho = 1 - 5.79/22.58 \approx 0.743$, 对上 74.3%. 这组数相互一致, 反过来支持中间维度是 1536.

### 2.2. Figure 3 左图: 读数, 噪声与最优点

![](images/p07-chart.jpg)

图 2 解析: 原文 Figure 3 左图, 横轴是 $\rho$, 纵轴是验证损失, 上下两条曲线分别是 $2 \times 10^{20}$ 和 $6 \times 10^{20}$ FLOPs 两档. 每条曲线由十个左右的点组成, 右端 $\rho = 100\%$ 是纯 MoE. 两条曲线都在 $\rho$ 降到 40% 附近时回到纯 MoE 的水平, 再往左上升更快. 上档曲线最低点在 85% 附近, 正文写的是 80%.

正文给出 $6 \times 10^{20}$ 档从 1.7248 ($\rho = 100\%$) 降到 1.7109 (约 80%), $\Delta = 0.0139$. 从图上读, 85% 处的点约为 1.7095, 比 1.7109 更低; 相邻点之间有 0.001 到 0.002 的起伏, 曲线带有明显锯齿. 正文称最优点在两档都位于 75% 到 80%, 结合图上的点密度, 更稳妥的读法是最优区间在 75% 到 85% 之间, 具体位置分辨不出. $2 \times 10^{20}$ 档纯 MoE 约 1.829, 最低约 1.8155, 降幅约 0.0135, 与上档接近. 两档的降幅都只有损失的 0.8% 左右, U 形很浅.

U 形结论有三处口径限制. 第一, 只有两档计算量, 且都固定 $P_{\mathrm{tot}}/P_{\mathrm{act}} \approx 10$; 27B 实验的比值是 $26.7/3.8 \approx 7.0$, 已经不在这个设置里, 最优 $\rho$ 是否随稀疏比移动, 文中没有测. 第二, 每个点只训一次, 没有给出种子方差, 0.001 量级的差异无法判断显著性. 第三, 左端 $\rho \to 0$ 时模型几乎没有专家, 损失上升是预期内的; 有信息量的是右半段, 也就是「把 15% 到 25% 的专家参数换成表, 损失会降」这一条.

### 2.3. 无限记忆: 对数线性的口径

3.2 节换了一个设置: 骨干固定为总参数约 3B, 激活 568M 的 MoE, 训练 100B token (Figure 3 右图标注的基线损失 1.808), 只增加 Engram 表的槽位数. 图中横轴是嵌入槽位数 (对数刻度), 从 $2.58 \times 10^5$ 到 $10^7$. 最小值 $2.58 \times 10^5$ 约等于 $2 \times 129280$, 即槽位数与词表同量级. 按 1280 维一行算, $10^7$ 个槽位对应约 12.8B 参数, 是骨干的 4 倍.

从图上读, $2.58 \times 10^5$ 时损失约 1.788, $10^7$ 时约 1.743, 跨 1.59 个数量级下降 0.045, 每增加 10 倍槽位约降 0.028. 对照组 OverEncoding (把哈希 N-gram 嵌入与词嵌入取平均后送入骨干, 没有门控和卷积) 的曲线与 Engram 近似平行, 高出约 0.01 到 0.015. 这条曲线的一个点还能与第 6.2 节的消融对上: 6.2 节的参考配置用 1.6B 参数的 Engram, 损失 1.768, 基线同为 1.808; 图中约 $1.3 \times 10^6$ 个槽位处损失也在 1.768 附近, 而 $1.3 \times 10^6 \times 1280 \approx 1.66 \times 10^9$. 正文对 $10^7$ 个槽位给的是「约 13B 参数」, 也就是 $10^7 \times 1280$. 两处对照说明这里的一个槽位指 1280 维的一整行 (16 个子表各取一行, 每行 80 维), 槽位数乘 1280 就是表的总参数. Appendix A 的 Engram Vocab Size 按单层计, Engram-27B 两层合计约 $4.5 \times 10^6$ 个槽位, 落在右图横轴 $1.3 \times 10^6$ 与 $10^7$ 之间.

论文把这条线称为严格的幂律. 图上只有约 6 个点, 横跨不到两个数量级, 在半对数坐标上近似直线, 能支持的只是这个范围内的对数线性; 损失有不可约下界, 继续外推到 $10^8$ 以上必然弯折. 所有点都只训 100B token, 表越大, 每行被访问的次数越少, 大表一端的增益可能被欠训练压低, 曲线斜率是这一训练量下的斜率. Engram-40B 在第 4 节被描述为「仍处于欠训练状态」, 和这一点方向一致, 但论文没有给出 40B 的单独损失曲线来支撑.

## 3. 27B 主实验与长上下文: 数字的口径

### 3.1. 四个模型的对齐方式

第 4 节训了四个模型, 共用 30 层, 隐藏维 2560, MLA 32 头, mHC 扩展率 4, 序列长 4096, batch 1280, 50000 步, 合计 $4096 \times 1280 \times 50000 \approx 2.62 \times 10^{11}$ token, 与 Table 1 的 262B 一致. 骨干优化器是 Muon, 学习率 4e-4, 阶梯衰减. Dense-4B 是 4.1B 稠密模型; MoE-27B 为 2 个共享专家加 72 个路由专家, top-6; Engram-27B 把路由专家减到 55, 省出的参数给两层 Engram; Engram-40B 骨干与 Engram-27B 相同, 只把表加大到 18.5B. 四个模型的激活参数都是 3.8B (不含词嵌入), 所以 MoE-27B 与 Engram-27B 在总参数和每 token 计算量上同时对齐.

嵌入表的训练设置与骨干不同: Adam 优化, 学习率乘 5, 不做权重衰减, 卷积零初始化. 5 倍学习率的理由文中没有给出. 一个可以从结构推出的解释是, 每个表项只在其 N-gram 出现时收到梯度, 更新频率远低于稠密参数, 放大学习率是在补偿稀疏更新. 不做权重衰减也与此相关: 长期不被访问的行若被衰减, 会慢慢丢失已学到的内容. 这些设置让 Engram 的优化条件和 MoE 专家不同, U 形曲线与 27B 的增益里有多少来自优化设置而非结构, 论文没有拆开.

### 3.2. Table 1 的增益与噪声

Engram-27B 相对 MoE-27B, Pile 损失从 1.960 降到 1.950, 验证损失从 1.634 降到 1.622. 下表列出部分评测的差值, 数字全部取自 Table 1.

| 类别 | 评测 | MoE-27B | Engram-27B | 差值 |
| --- | --- | --- | --- | --- |
| 知识 | MMLU / MMLU-Redux | 57.4 / 60.6 | 60.4 / 64.0 | +3.0 / +3.4 |
| 知识 | CMMLU / C-Eval | 57.9 / 58.0 | 61.9 / 62.7 | +4.0 / +4.7 |
| 事实问答 | TriviaQA / PopQA | 48.8 / 19.2 | 50.7 / 19.4 | +1.9 / +0.2 |
| 推理 | BBH / ARC-C / CCPM | 50.9 / 70.1 / 79.6 | 55.9 / 73.8 / 87.1 | +5.0 / +3.7 / +7.5 |

表里有一处和摘要对不上. 摘要与引言写「MMLU +3.4」, Table 1 的 MMLU 是 57.4 对 60.4, 差 3.0; 差 3.4 的是 MMLU-Redux. 摘要列出的其余五个数 (CMMLU +4.0, BBH +5.0, ARC-C +3.7, HumanEval +3.0, MATH +2.4) 都与表一致. 另一处值得对照的是增益分布: 论文强调记忆模块在推理和代码上的增益「更大」, 但最直接测记忆的两项事实问答 TriviaQA 和 PopQA 只涨了 1.9 和 0.2, 在全表里属于最小的一档; 最大的 CCPM +7.5 是中文成语填空, 本身就是固定搭配的识别, 与 N-gram 查表的对应关系最直接.

单次评测的噪声可以用附录 Figure 8 估计. 图中给出最后 10k 步的评测曲线, HumanEval 在相邻检查点之间起伏约 5 个点, MoE 与 Engram 两条线多次交叉; WinoGrande, PopQA, CruxEval 也有交叉. MMLU, CMMLU, CCPM, BBH, DROP, ARC 的差距在整个区间内保持同号, 这些项的增益可以认为是稳定的. HumanEval +3.0 小于它自身的波动, 不能单独作为代码能力提升的证据. Engram-40B 相对 Engram-27B 在 HumanEval, MBPP, C3, MATH 上反而下降, 也落在这一噪声范围内.

### 3.3. 长上下文: Iso-Loss 对照与例外项

5.2 节在 32k 上下文上比较四个检查点. 所有模型用同一套上下文扩展流程 (YaRN, 5000 步, 30B token, 32768 长度), 区别只在起点: MoE-27B 和 Engram-27B 的 50k 步终点, 以及 Engram-27B 的 41k 和 46k 中间检查点. 46k 检查点的预训练损失与 MoE-27B 终点相同 (都是 1.63), 构成 Iso-Loss 对照; 41k 检查点损失更高 (1.66), 只用了 82% 的训练计算. 这一设计让比较的对象从「同样训练量」换成「同样语言建模水平」, 能排除「Engram 只是预训练损失更低」这一解释.

Table 2 中 Iso-Loss 一组 (46k 对 MoE 50k) 的主要差距在多查询检索: Multi-Query NIAH 从 84.2 升到 97.0, Variable Tracking 从 77.0 升到 87.2, 四项 LongPPL 全部更低. 但表里有几处例外, 论文正文的「全面领先」不成立: 单针检索 S-NIAH 三个 Engram 检查点都低于 MoE 的 100.0 (99.6, 97.6, 99.3); 41k 检查点的 CWE 3.8 低于 MoE 的 4.5, L-CoT 困惑度 14.26 高于 14.16. 另一个异常是频繁词抽取 FWE, MoE 只有 73.0, 三个 Engram 检查点都在 98.6 以上, 差距 25 个点以上, 远大于其他列, 文中没有解释. Multi-Query 在 46k 和 50k 都是 97.0, 说明这一项在 46k 后已饱和.

论文对长上下文增益的解释是: Engram 接管了局部依赖, 注意力就有更多容量处理全局上下文. 这条解释与第 4 节的机制分析一致, 但 Table 2 本身不能区分它和另一种可能: Engram 改变了骨干的训练动态, 使 YaRN 扩展更容易收敛. 要区分两者, 需要在长上下文评测阶段关掉 Engram 或对比注意力头的距离分布, 文中没有做.

## 4. 机制分析: 证据链逐环核对

### 4.1. LogitLens 与 CKA: 测到的是什么

论文的核心解释是: Engram 让骨干不必在浅层重建静态知识, 等效于加深了网络. 证据来自 6.1 节的两组可解释性测量. LogitLens 把每一层的隐状态直接接最终的 LM Head, 得到一个中间输出分布, 再计算它与该模型最终输出分布的 KL 散度; 值越小, 说明这一层已经越接近「可以直接给出预测」. Figure 4(a) 中 Engram 的曲线在前中段整体低于 MoE, 差距最大处约 0.5 到 0.7; 第 0 层 Engram-27B 反而略高 (约 10.4 对 10.0), 到第 17, 18 层附近三条曲线一起骤降, 之后基本重合.

这个指标有一处口径要留意: 每个模型都和自己的最终分布比较, 两个模型的终点不同. Engram 的 KL 更低, 可以解释为浅层更早形成预测, 也可以解释为 Engram 在第 2 层和第 15 层把 N-gram 查表结果 (本身就接近下一 token 的统计预测) 直接写进残差流, 让中间层的 LM Head 投影「看起来」更接近终点. 后一种情况下, 浅层并没有多做组合运算, 只是被注入了一份现成的预测. 论文没有区分这两种读法, 例如对比插入层前后单层的 KL 跳变, 或者关掉 Engram 再测.

![](images/p13-chart-2.jpg)

图 3 解析: 原文 Figure 4(b), 横轴是 MoE-27B 的层号, 纵轴是 Engram-27B 的层号, 颜色表示两层隐状态的 CKA 相似度. 对每个 MoE 层, 图上标出与之最相似的 Engram 层, 连成一条软对齐曲线. 曲线整体落在对角线上方, 即 Engram 的较浅层与 MoE 的较深层最相似. 曲线在 Engram 插入的第 2 层和第 15 层之后出现台阶式的跳升, 其余层段较平.

CKA 的台阶形状正好对应上面的第二种读法: 若浅层真的「更快完成组合」, 对齐曲线应在各层平滑偏移; 台阶集中在插入层之后, 说明偏移的主体来自 Engram 输出写入残差的那一刻, 而不是之后的层算得更快. CKA 的样本取自 Few-NERD 实体数据集, 抽取的是实体最后一个 token 的隐状态, 这恰好是多 token 实体识别完成的位置, 也是 N-gram 查表最可能命中的位置. 在这个子集上测出的对齐偏移, 不能直接推广到推理或代码 token. 「有效深度增加」作为假说与数据相容, 但这两组测量都没能排除更简单的解释.

### 4.2. 插入层与组件消融

6.2 节在 3B MoE 骨干 (基线损失 1.808) 上做结构消融, Engram 预算固定为 1.6B 参数. 参考配置是 {2, 3}-gram, 插入第 2 层和第 6 层, 损失 1.768, 降 0.04. 单层扫描把同样 1.6B 放在一层上: 第 2 层最好 (1.770), 第 1 层约 1.7735, 往深处逐渐变差, 但不单调, 第 5 层约 1.7788 比第 6 层约 1.7779 还差. 最差的第 11, 12 层也在 1.783 左右, 仍比基线低约 0.025. 换句话说, 0.04 的总增益里约 60% 与插入位置无关, 位置只决定剩下的约 0.015.

![](images/p15-figure-5-architecture-ablation-results-we-compare-the-3b.jpg)

图 4 解析: 原文 Figure 5, 左侧深蓝曲线是单层插入的层号扫描, 横轴层号 1 到 12, 纵轴验证损失; 顶部虚线是 MoE 基线 1.808. 右侧的散点是在参考配置上去掉或加上单个部件后的损失. 所有散点和曲线都位于基线下方很远处, 部件之间的差距在 0.001 到 0.006 之间, 与 Figure 3 左图里相邻点的起伏同一量级.

从图上读各部件的贡献: 去掉多分支融合约 1.7745 (比参考高 0.006), 去掉分词压缩约 1.7739 (高 0.0055), 去掉门控约 1.7728 (高 0.0044), 加 4-gram 约 1.7695 (高 0.001), 去掉短卷积约 1.7688 (只高 0.0004). 论文据此把多分支, 门控, 分词压缩列为三项关键部件, 结论方向可以接受, 但每个点只有一次训练, 0.001 级的差距无法区分; 单层第 2 层的 1.770 与双层的 1.768 只差 0.002, 「双层更好」也落在这一范围内. 短卷积的贡献最小, V4.1-Flash 采用 Engram 时正是去掉了短卷积, 并把阶数扩到 {2, 3, 4}, 见 [V4.1-Flash 解析](../../01-模型技术报告/deepseek-v4-1-flash/deepseek-v4-1-flash-analysis.md) 的 3.2 节.

### 4.3. 关表实验: 依赖程度与知识存储

6.3 节在推理时把 Engram 输出整个置零, 骨干不变, 测各评测保留的比例. Figure 6 的读数是: 阅读理解保留得最多 (C3 93%, RACE-Middle 89%, RACE-High 84%, DROP 81%), 事实问答保留得最少 (TriviaQA 29%, PopQA 44%, TriviaQA-ZH 44%). 论文由此得出 Engram 是参数化知识的主要存储处, 阅读理解主要依赖注意力.

![](images/p17-figure-6-retained-performance-under-engram-ablation-factual-knowledge.jpg)

图 5 解析: 原文 Figure 6, 横向条形图, 每条是一个评测在关掉 Engram 后保留的分数比例, 按类别着色. 正文只讨论了两端, 中间部分同样跌得很深: MATH 只剩 36%, MGSM 44%, GSM8K 62%, HumanEval 58%, BBH 67%, MMLU 75%. 数学推理的保留比例与事实问答处在同一档.

这组结果有两处读法问题. 第一, 置零测的是骨干对 Engram 输出的依赖程度, 不是 Engram 存了多少知识. 训练时骨干一直能拿到这份输入, 置零后浅层残差流的分布整体偏移, 任何下游任务都会受影响; 论文自己也说这会造成训练与推理不一致. TriviaQA 保留 29%, 即 $50.7 \times 0.29 \approx 14.7$, 低于完全没有 Engram 的 Dense-4B 的 33.0, 说明掉下去的部分远超 Engram 带来的那 1.9 个点增益, 骨干在训练中已经把一部分本该自己承担的功能交给了查表. 第二, MATH 36% 与「知识在 Engram, 推理在骨干」的二分不符, 正文只挑了两端讨论. 更直接的证据应该是带着 Engram 重新训练的对照, 或者只置零某些 N-gram 的表项.

## 5. 系统代价: 确定性寻址的收益与边界

### 5.1. 训练: 分片, All-to-All 与优化器状态

训练时嵌入表按行切分到各 GPU, 前向用 All-to-All 收集每个 token 需要的行, 反向用同样的通信把梯度发回. 每 token 每层的通信量是 16 行, 与表的总大小无关, 这是 Engram 能把表做到 GPU 显存之外的基础. 论文没有给出训练吞吐相对 MoE-27B 的变化, 也没有说明 All-to-All 是否与前一层的计算重叠.

优化器状态是另一项成本. 嵌入表用 Adam, 每个参数要两份状态, Engram-27B 的 5.79B 参数需要额外约 11.6B 个状态值, Engram-40B 的 18.5B 需要约 37B. 论文对这一项只字未提. 后续的 V4.1-Flash 把 Engram 做到 196B, 就把嵌入表的优化器换成了动量加 Sinkhorn 行列均衡, 理由正是 Adam 状态太占显存, 同时保留了 5 倍学习率, 见 [V4.1-Flash 解析](../../01-模型技术报告/deepseek-v4-1-flash/deepseek-v4-1-flash-analysis.md) 的 3.2 节与第 3 节的优化器部分. 这说明 Engram 论文的训练设置在百 B 级表上不能原样沿用.

### 5.2. 推理: 预取窗口与 Table 4

推理时表放在主机内存, 地址在前向开始前就能由 token ID 算出, 系统可以异步经 PCIe 把需要的行拷到 GPU, 用前几层的计算掩盖传输. Table 4 在 H800 上用 nano-vLLM 测: 512 条序列, 长度在 100 到 1024 之间均匀采样, 在 Dense-4B 和 Dense-8B 的第 2 个块插入一个 100B 参数的 Engram 层, 预取与第 1 个块的计算重叠. 吞吐从 9031.62 降到 8858.28 tok/s (降 1.92%), 从 6315.52 降到 6140.02 tok/s (降 2.78%).

带宽本身不是瓶颈, 可以推算出来. 按 Engram-27B 的 $d_{\mathrm{mem}} = 1280$ 和 BF16, 每 token 每层取 2560 字节; 9000 tok/s 时只有约 23 MB/s, 远低于 PCIe 5.0 x16 的数十 GB/s. 难点在延迟和突发: prefill 一次处理的 token 数大, 例如 512 条平均 562 token 的序列一次性进 prefill, 约 $2.9 \times 10^5$ 个 token, 需要取约 740 MB, 按 50 GB/s 算约 15 ms, 只靠 1 个块的计算未必掩盖得住. Table 4 没有给出 100B 表的 $d_{\mathrm{mem}}$, 头数和阶数, 没有分开 prefill 与 decode, 也没有报告延迟分布, 所以 1.9% 到 2.8% 只能说明「在这组负载下吞吐损失小」, 不能外推到长 prompt 或低延迟场景. 演示代码里哈希在 CPU 上用 numpy 计算, 这部分开销在 Table 4 里是否计入, 文中没有给出.

### 5.3. 实验没有覆盖的部分

Table 4 刻意选了稠密骨干, 理由是避开 MoE 专家并行的通信. 但 Engram 论文的主张恰恰是与 MoE 搭配, 实际部署时 Engram 的 PCIe 传输要和专家并行的 All-to-All, KV cache 的主机内存交换同时争抢带宽与拷贝引擎, 这些交互都没有测. 2.5 节提出的多级缓存 (热门 N-gram 放 HBM, 长尾放 SSD) 依据是 N-gram 访问服从 Zipf 分布, Table 4 只测了「全部走 PCIe」这一档, 论文把它称为保守基线; 缓存命中率, SSD 一档的延迟都没有实测.

插入层的选择也受系统约束. 预取窗口等于插入层之前的计算时间, 插得越深窗口越大, 但 4.2 节显示插得越浅损失越低. 论文在 27B 上选第 2 和第 15 层 (演示代码写 [1, 15], 按从 0 计数应是同一组), 第一层 Engram 只有 1 到 2 个块可用来掩盖传输. V4.1-Flash 把两个模块放在第 1 和第 14 层 (从 0 计数), 理由写的是平衡训练流水线各阶段的显存, 推理时的预取则改走后台 RDMA. 两份材料都说明, 插入层位置在实践中由建模收益, 预取窗口和流水线显存三者共同决定, 论文的消融只覆盖了第一项.
