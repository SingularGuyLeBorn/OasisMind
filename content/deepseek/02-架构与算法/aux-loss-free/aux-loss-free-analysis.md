# Loss-Free Balancing: 只管选择的专家偏置如何替代 MoE 辅助损失

论文是 *Auxiliary-Loss-Free Load Balancing Strategy for Mixture-of-Experts* ([arXiv 2408.15664](https://arxiv.org/abs/2408.15664)), 2024 年 8 月 28 日挂出, 14 页, 作者 Lean Wang, Huazuo Gao, Chenggang Zhao, Xu Sun, Damai Dai, 来自 DeepSeek-AI 和北京大学多媒体信息处理国家重点实验室, 第一作者在 DeepSeek 实习期间完成. 论文没有配套代码仓库; 方法后来进了 DeepSeek-V3, 推理侧的偏置可以在 [DeepSeek-V3 的 `inference/model.py`](https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py) 里看到, 训练侧的更新规则在 [Megatron-LM 的 `moe_utils.py`](https://github.com/NVIDIA/Megatron-LM/blob/main/megatron/core/transformer/moe/moe_utils.py) 有一份独立实现. 逐段译文见 [对照译稿](aux-loss-free-bi.md). 方法本身三行就能写完: 每个路由专家配一个标量偏置, 选 Top-K 时把它加在路由分数上, 乘到专家输出上的门控仍用原始分数; 每步训练结束后, 超载专家的偏置减 $u$, 欠载专家的加 $u$. 篇幅主要花在三件事上: 这个改动为什么能同时改善困惑度和均衡, 实验数字在什么口径下成立, 以及 V3 实际用法和论文设定之间差了哪些东西. 辅助损失的一般形式, 容量与 token drop, Expert Choice 泄露量的推导, 在 llm-guide 的 [MoE 负载均衡与容量](../../../llm-guide/2-核心原理与架构/2.6-MoE/03-MoE负载均衡与容量/03-MoE负载均衡与容量.md) 和 [MoE 路由与 Top-K 可导性](../../../llm-guide/2-核心原理与架构/2.6-MoE/02-MoE路由与Top-K可导性/02-MoE路由与Top-K可导性.md) 已有, 下文只在需要时引结论.

## 1. 辅助损失的矛盾与无损失控制

### 辅助损失的两难

#### 1.1. 式 (2) 的梯度落在谁身上

论文的 MoE 层按式 (1) 计算: 第 $t$ 个 token 的输入 $\mathbf{u}_t$ 与第 $i$ 个专家的中心向量 $\mathbf{e}_i$ 做内积, 过门控函数 $G$ 得到路由分数 $s_{i,t}$, 取分数最高的 $K$ 个专家, 用 $g_{i,t}=s_{i,t}$ 加权它们的 FFN 输出. 主实验的 $G$ 是 sigmoid, 每个 $s_{i,t}$ 独立落在 $(0,1)$, 不在专家之间归一. 基线的辅助损失是式 (2), 按一条长度为 $T$ 的序列计算:

$$
\mathcal{L}_{\mathrm{Balance}}=\alpha\sum_{i=1}^{N}f_iP_i,\qquad f_i=\frac{N}{KT}\sum_{t=1}^{T}\mathbb{1}(\text{token } t \text{ 选中专家 } i),\qquad P_i=\frac{1}{T}\sum_{t=1}^{T}s_{i,t}
$$

$f_i$ 是专家 $i$ 在这条序列上的实际负载, 乘了 $N/K$ 之后完全均衡时等于 1; 它由指示函数构成, 不可导, 梯度只经过 $P_i$ 流回路由分数. 对单个分数求导, 得到

$$
\frac{\partial\mathcal{L}_{\mathrm{Balance}}}{\partial s_{i,t}}=\frac{\alpha f_i}{T}
$$

这一项与 token $t$ 是否选中专家 $i$ 无关: 序列里每个 token 对专家 $i$ 的分数都会被同一个力度往下压, 专家越热 ($f_i$ 越大) 压得越狠. 再往前一层, sigmoid 的导数是 $s_{i,t}(1-s_{i,t})$, 于是输入 $\mathbf{u}_t$ 收到的辅助梯度是 $\frac{\alpha}{T}\sum_i f_i\,s_{i,t}(1-s_{i,t})\,\mathbf{e}_i$. 这条梯度进的是残差流, 会一路传回前面的注意力层和 FFN 层. 也就是说, 为了让路由均衡, 辅助损失改动的不止路由器的 $\mathbf{e}_i$, 还有所有上游层的表示. 论文说的「干扰梯度」, 具体就是这一项: 它的方向由负载统计决定, 和 next-token prediction 的损失无关, 系数 $\alpha$ 越大, 它在总梯度里占比越高. 式 (2) 还有一个容易被忽略的设定: 它在单条序列内统计. 一条代码序列天然会偏向擅长代码的专家, 序列级损失要求它在 2048 个 token 内部也摊平到 64 个专家上, 这比「整个 batch 摊平」严格得多. 这一点到第 5 节会变得重要, 因为 V3 的消融后来把 Loss-Free 的收益很大一部分归到了统计范围上. Switch 形式的点积损失为什么能推动均衡, 推导见 [MoE 负载均衡与容量](../../../llm-guide/2-核心原理与架构/2.6-MoE/03-MoE负载均衡与容量/03-MoE负载均衡与容量.md) 第 2 节.

#### 2.1. 式 (3): 偏置决定集合, 不决定权重

Loss-Free 只改式 (1) 的选择条件. 每个 MoE 层的每个路由专家有一个标量 $b_i$, 选专家时比较的是 $s_{i,t}+b_i$:

$$
g_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}+b_i\in\operatorname{Topk}\left(\{s_{j,t}+b_j\mid 1\le j\le N\},K\right)\\ 0, & \text{otherwise}\end{cases}
$$

被选中之后, 乘到 $\mathrm{FFN}_i(\mathbf{u}_t)$ 上的仍是不带偏置的 $s_{i,t}$. 这个设计有两层含义. 第一, $b_i$ 只出现在 Top-K 的比较里, Top-K 输出的是索引, 对 $b_i$ 没有导数, 主损失不会去更新 $b_i$, $b_i$ 也不会通过梯度去改动 $\mathbf{e}_i$ 或上游表示. 第二, 固定选中集合时, MoE 层的输出函数和不加偏置的模型完全相同, 偏置的全部作用是「换掉哪几个专家参与计算」. 如果把 $b_i$ 也加进 $g_{i,t}$, 输出会被偏置直接放大或缩小, 偏置就变成了影响前向数值的参数, 要么它接收梯度 (于是又和主损失耦合), 要么它的变化让同一个 token 的输出幅度随训练步漂移. 两种情况都破坏了「均衡和建模各管各的」这条分工.

偏置有一个冗余自由度: 所有 $b_i$ 同时加一个常数, 每个 token 的 Top-K 结果不变. 所以偏置的绝对值没有意义, 只有专家之间的差有意义, 也不需要约束 $s_{i,t}+b_i$ 非负. 这个性质在实现上留下一个坑: V3 的推理代码先按组筛选专家, 再把未选中组的分数填成某个值后取 Top-K. 偏置为负时 $s_{i,t}+b_i$ 可以小于 0, 如果填充值是 0, 被屏蔽的专家会排到合法专家前面, 必须填 $-\infty$. 官方 `Gate.forward` 用的正是 `masked_fill_(mask, float("-inf"))`, 自己重写路由时这一处最容易抄错.

#### 2.3. Algorithm 1 的时序与因果

Algorithm 1 的一步分四件事: 用当前偏置做前向和反向, 更新模型参数; 统计这个 batch 里每个专家被分到的 token 数 $c_i$ 及其均值 $\overline{c_i}$; 算违背误差 $e_i=\overline{c_i}-c_i$; 按 $b_i\leftarrow b_i+u\cdot\mathrm{sign}(e_i)$ 更新. 偏置在 batch 内不变, 第 $n$ 步用的偏置只由前 $n-1$ 个 batch 的负载决定. 所以在一个 batch 内部, 某个 token 选哪个专家只取决于它自己的分数和这组固定的偏置, 不取决于同 batch 里别的 token, 更不取决于同一序列里它后面的 token. 推理时偏置冻结, 路由退化成逐 token 的确定函数, 训练和推理的路由形式一致. 论文特意强调「用历史负载而不是当前序列的负载」, 原因就在这里: 如果先看当前序列的负载再定偏置, 前面 token 的选择就依赖后面 token 的分数, 这正是第 4 节 Expert Choice 的问题.

统计范围是整个训练 batch. 1B 模型一步 1152 条序列, 每条 2048 token, 共约 2.36M token, 每层 64 个专家的平均负载约 $2.36\text{M}\times6/64\approx2.2\times10^5$ 个 token. 偏置是逐层的, 每个 MoE 层各有一组 64 个 $b_i$, 论文报告的 MaxVio 是各层平均. 有梯度累积和数据并行时, $c_i$ 要在所有 micro-batch 和所有数据并行副本上加总后再更新, 否则每张卡会按自己看到的局部负载各改各的偏置. Megatron 的实现正是这样: 偏置注册成 fp32 的 buffer 而非可训练参数, 前向时只在开着梯度的情况下累加计数 (评测和激活重算不重复计), 优化器步结束时在张量, 数据, 上下文并行组上 all-reduce, 再用 $\mathrm{sign}(\text{total}-c_i\cdot N)$ 定方向, 用整数比较避开均值的浮点误差. V3 官方推理代码里偏置是 fp32 的 `nn.Parameter`, 推理时没有问题; 但它默认 `requires_grad=True`, 直接拿去训练时要先关掉, 否则它会进入优化器. 偏置在前向里只出现在 Top-K 的输入中, 本来就拿不到梯度, 可一旦开了 weight decay, 优化器仍会把它往 0 拉, 与 Algorithm 1 的更新互相抵消.

#### 2.4. sign 更新的性质与代价

sign 规则可以从两个角度理解. 一是把它看成对偏置做符号梯度下降: 对目标 $\frac12\|F-Q\|^2$ ($F$ 是带偏置的负载分布, $Q$ 是均匀分布), 用直通估计把 $F$ 对 $b$ 的导数取成单位阵, 梯度就是 $F-Q$, 普通 SGD 给出 $b\leftarrow b-u(F-Q)$, 取符号就是 Algorithm 1; 表 3 的 $b_i+u\cdot e_i$ 变体对应普通 SGD. 二是把偏置看成「每个专家负载等于 $KT/N$」这条约束的对偶变量, Top-K 选择是原始步, 偏置更新是一步对偶上升: 过载专家的偏置下调, 等价于提高它的「价格」, 只有分数高出价格的 token 才继续选它. 按这种写法, sign 规则相当于逐专家取步长 $u/|e_i|$ 的对偶梯度步, 离均衡越近步长相对越大, 这也解释了第 2.4 节说的末段抖动. 两种看法给出同一个结论: Loss-Free 并没有「去掉损失」, 它把均衡目标的优化变量从全部模型参数缩到了 $N$ 个偏置上. 这正是它不干扰主任务的原因, 也是它和辅助损失最本质的区别.

sign 更新的代价是步长不衰减. 不论 $|e_i|$ 多大, 偏置每步都动 $u$, 已经均衡的专家也被推着来回抖, 最终只能收进一个宽度与 $u$ 成正比的带里, 不会精确收敛. 另一个代价是新增了超参 $u$, 而 $u$ 的取值和门控分数的量程绑定: sigmoid 分数在 $(0,1)$ 内且彼此独立, $u=0.001$ 相当于每步移动千分之一的分数量程; 换成 softmax, 分数的量程随 token 变化 (一个确定的 token 最高概率可能是 0.9, 一个犹豫的 token 64 个专家都在 0.016 附近), 固定加性偏置对不同 token 的作用差别很大, 论文附录 C 也因此改用了 $u\cdot e_i$. 「Loss-Free 不用调 $\alpha$」的说法要补半句: 它要调 $u$, 只是 $u$ 在 sigmoid 门控下比 $\alpha$ 好调, 论文在 1B 上搜出的 0.001 被直接用到了 3B, 后来又原样用进了 V3 和 V4.

#### 3.1. 模型与训练设置

两个模型都是 DeepSeekMoE 结构 (细粒度专家加共享专家, 见 [DeepSeek-MoE](../../../llm-guide/2-核心原理与架构/2.6-MoE/01-DeepSeek-MoE/01-DeepSeek-MoE.md)), 门控从 DeepSeekMoE 原文的 softmax 换成 sigmoid. 按表 5, 1B 模型隐藏维 1024, 8 个注意力头, 9 个 MoE 层 (另有紧接嵌入层的一层稠密 FFN), 每层 2 个共享专家加 64 个路由专家, 每 token 激活 6 个路由专家, 细粒度系数 $d_{ff}/d_{expert}=16/3$; 3B 模型隐藏维 1280, 10 个头, 11 个 MoE 层, 专家配置相同, 细粒度系数 4. 词表 32064, 是用 HuggingFace tokenizers 训的 32K BPE. 训练设置按附录 B 可以逐项复算. 1B 用带预热的余弦学习率, 峰值 1e-3, 最低 1e-4, 预热 1000 步, batch 1152 条 × 2048 token, 40000 步, 合计 $1152\times2048\times40000\approx9.44\times10^{10}$, 即约 94B token, 正文写的 100B 是取整. 3B 用多阶段学习率, 在 45211, 50862, 56514 步切换, 三段学习率 7.8e-4, 2.47e-4, 7.8e-5, 预热 2000 步, batch 1728 条, 56514 步合计 $2.00\times10^{11}$ token, 与 200B 吻合; 两个切换点分别落在总步数的 80% 和 90%. 结论节写的「3B 训 300B token」与这里对不上, 是笔误. 验证集约 70.8M token, 等于 1B 的 30 个 batch, 也等于 3B 的 20 个 batch. 更新速率只在 1B 上调, 3B 直接沿用.

#### 3.2. MaxVio 的定义与 Table 2

式 (4) 定义一个 MoE 层的最大违背度:

$$
\mathrm{MaxVio}=\frac{\max_i\mathrm{Load}_i-\overline{\mathrm{Load}_i}}{\overline{\mathrm{Load}_i}}
$$

$\mathrm{Load}_i$ 是分到专家 $i$ 的 token 数, $\overline{\mathrm{Load}_i}$ 是完全均衡时的期望负载. 它只看最热的那一个专家, 原因是专家并行下一层的完成时间由最慢的那张卡决定, 平均偏离再小, 只要有一个专家超载 70%, 这一层就要多等 70% 的计算. 两个变体的差别在统计范围: $\mathrm{MaxVio}_{\mathrm{global}}$ 在整个验证集上数, 对应 batch 无穷大时的效率上限; $\mathrm{MaxVio}_{\mathrm{batch}}$ 在每个训练 batch 上数, 对应训练时每一步的实际效率. 全文报告的值都是各层平均, 单层的最差值文中没有给出. Table 2 的结果: 1B 上辅助损失困惑度 9.56, $\mathrm{MaxVio}_{\mathrm{global}}$ 0.72, Loss-Free 为 9.50 和 0.04; 3B 上辅助损失 7.97 和 0.52, Loss-Free 7.92 和 0.04. 换成交叉熵, 两个规模的差都约为 $\ln 9.56-\ln 9.50\approx\ln 7.97-\ln 7.92\approx0.006$ nat. 负载的改善是一个数量级, 困惑度的改善约 0.6%. 论文只报告困惑度, 没有下游评测, 没有多随机种子, 0.006 nat 的差在单次训练里能否与噪声区分, 文中没有给出依据. 负载上的结论则可靠得多: 0.72 到 0.04 的差远超训练噪声.

![](images/p06-figure-3-loss-free-balancing-maintains-a-better-load.jpg)

图注: 两个子图是 1B 和 3B 训练全程的 $\mathrm{MaxVio}_{\mathrm{batch}}$, 每个点是相邻 100 步的平均. 两种方法在前约 1k 步都从很高的值迅速下降; 之后辅助损失停在 1B 约 0.72, 3B 约 0.52 的水平, Loss-Free 降到约 0.1 并缓慢下行. 图 3 解析: 两个子图是 1B 和 3B 训练全程的 $\mathrm{MaxVio}_{\mathrm{batch}}$, 每个点是相邻 100 步的平均. 两种方法在前约 1k 步都从很高的值迅速下降; 之后辅助损失停在 1B 约 0.72, 3B 约 0.52 的水平, Loss-Free 降到约 0.1 并缓慢下行. 3B 的辅助损失曲线在约 45k 步有一个小台阶, 正是学习率第一次下调的位置. 图里看不出困惑度, 也看不出单层的情况. $\mathrm{MaxVio}_{\mathrm{batch}}$ 后期约 0.1, 比 $\mathrm{MaxVio}_{\mathrm{global}}$ 的 0.04 高一倍多, 差额来自 batch 之间的内容差异. 如果 2.2M 次派遣是独立抽样, 每个专家计数的相对波动约 $1/\sqrt{2.2\times10^5}\approx0.2\%$, 远小于 0.1; 实际的 0.1 说明 batch 之间的数据配比在变, 偏置按上一 batch 的负载更新, 跟不上下一 batch 的内容变化. 这是 Loss-Free 的结构性下限: 它只能纠正持续的偏斜, 纠正不了单个 batch 的偶然偏斜.

V3 补一个序列级损失, 防的正是这一段.

#### 4.1. 泄露从哪来, 式 (7) 的界有多紧

Expert Choice (EC, [Zhou et al., 2022](https://arxiv.org/abs/2202.09368)) 把选择方向倒过来, 改由每个专家在一个分块的 $T$ 个 token 里挑分数最高的 $RT$ 个, $R=K/N$ 是稀疏比. 每个专家恰好收 $RT$ 个 token, 负载按构造完全均衡, 不需要任何辅助损失或偏置. 代价在因果性: token $t$ 能不能被专家 $i$ 选中, 取决于它的分数在整个分块里排第几, 而分块里包括 $t$ 之后的 token. 图 6 给了一个两 token 的例子: 「the cat」和「the dog」里, 后一个 token 的门控分数不同, 迫使前面的「the」选到不同的专家, 于是「the」的路由结果本身就编码了下一个词是什么. 这条信息经过 MoE 输出写进「the」的表示, 预测下一个 token 时就可以读出来, 训练损失因此虚低.

![](images/p09-figure-6-an-example-of-future-token-leakage-in.jpg)

图注: 两个专家, 每个专家在两 token 的分块里选 1 个 token. 方框里的数字是门控分数. 图 6 解析: 两个专家, 每个专家在两 token 的分块里选 1 个 token. 方框里的数字是门控分数. 左边「cat」对专家 2 的分数是 2, 抢走了专家 2, 「the」只能去专家 1; 右边「dog」对专家 1 的分数是 2, 「the」只能去专家 2. 红圈标的是「the」的选择暴露了后继 token. 这只是构造出的极端例子, 分数是示意值, 图里没有说明真实模型多大比例的 token 处在这种情况. 附录 D.1 估计泄露量. 一层里每个专家从 $T$ 个 token 选 $RT$ 个, 共 $\binom{T}{RT}^N$ 种分配, 平均每个 token 能携带 $I=\frac1T\log_2\binom{T}{RT}^N$ bit. 用 $\binom{T}{m}\ge\left(\frac{T}{m}\right)^m>\left(\frac{T-m}{m}\right)^m$ 放缩, 得到式 (7) 的下界 $I>K\log_2\frac{1-R}{R}$. 代入 $N=16$, $K=2$: 每层 $2\log_2 7\approx5.61$ bit, 9 层约 50.5 bit; 词表 32064 的一个 token 需要 $\log_2 32064\approx15$ bit, 所以论文说 50 bit 足够确定后继 token. 这个界并不紧, 用 Stirling 近似, $\frac1T\log_2\binom{T}{RT}\to H(R)$ ($H$ 是二元熵), 每层的容量趋于 $N\cdot H(R)$, $R=0.125$ 时为 $16\times0.544\approx8.7$ bit, 比下界大 55%. 换成论文自己的 1B 配置 ($N=64$, $K=6$, $R\approx0.094$), 下界是每层 $6\log_2(58/6)\approx19.6$ bit, 熵近似是 $64\times0.449\approx28.7$ bit, 9 层合计 177 到 258 bit.

这些数要正确理解. 它们是路由分配这条通道的容量, 不是模型实际泄露的量: 分配编码的是整个分块的信息, 前面 token 和后面 token 都在里面, 模型能不能学会把它解码成「下一个 token 是谁」, 容量估计回答不了. 所以式 (7) 证明的是「EC 有足够大的泄露通道」, 真正的证据在 D.2 的实验.

D.2 训了一个 2B 的 EC 模型, 100B token, 比较分块 512, 2048, 8192 和「512 加打乱」四种设置. 脚注说明 2048 个 token 是一条序列, 512 是四分之一条, 8192 是四条. 正文 §5.2 和附录 D.2 都说结果在「Table 9」, 实际是图 9; 2B 这个规模在正文其他地方没出现过, 架构细节文中没有给出.

![](images/p14-figure-9-comparison-of-expert-choice-with-different-chunk.jpg)

图注: 5k 到 25k 步的训练损失. 2048, 8192 和「512 加打乱」三条曲线几乎重合, 25k 步时约 1.96; chunk=512 从约 8k 步开始低于其他曲线, 20k 步附近陡降一段, 25k 步约 1.80. 图 9 解析: 5k 到 25k 步的训练损失. 2048, 8192 和「512 加打乱」三条曲线几乎重合, 25k 步时约 1.96; chunk=512 从约 8k 步开始低于其他曲线, 20k 步附近陡降一段, 25k 步约 1.80. 四条曲线在 20k 步都有一次下降, 位置一致, 应是学习率调度的切换点 (文中没有给出 2B 的调度). 图里只有训练损失, 没有验证损失.

按图上读数, 512 的损失比其余低约 $(1.96-1.80)/1.96\approx8\%$, 与正文「约 10%」接近. 打乱实验是关键对照: 分块大小同为 512, 只是选择前在 batch 内打乱 token, 块内的 token 不再来自同一段上下文, 损失就回到正常水平. 这排除了「小分块只是让优化更容易」的解释, 支持损失下降来自读取了未来信息. 但图 9 也留下两点要补. 第一, chunk=2048 已经是在单条序列内部做选择, 按式 (7) 泄露通道照样存在, 它没有掉下来, 只能说明 25k 步内模型没学会利用, 不能说明 2048 安全; chunk=512 的陡降发生在训练中段, 说明利用泄露是训练中途学会的, 训得更久的大分块会不会出现同样的现象, 图里看不出. 第二, 损失虚低本身不等于评测失效, 论文说泄露「破坏泛化」, 但没有报告 EC 模型在自回归生成时的表现. 自回归解码每步只有一个新 token, 组内竞争根本无法按训练时的方式进行, 这一点 Zhou 等人自己在局限一节也承认, 推导与案例见 [MoE 路由与 Top-K 可导性](../../../llm-guide/2-核心原理与架构/2.6-MoE/02-MoE路由与Top-K可导性/02-MoE路由与Top-K可导性.md) 第 1.3 节.

Table 1 把辅助损失也标成「无泄露」, 这里有一个细节. 式 (2) 的 $f_i$ 在整条序列上计数, 它对 $s_{i,t}$ 的梯度 $\alpha f_i/T$ 里含有 $t$ 之后的 token 的路由结果. 但这只进训练信号, 前向里读不到: 和语言建模损失本身一样, 损失可以看整条序列, 只要 token $t$ 的前向计算不读后面的 token, 就不构成泄露. Loss-Free 的偏置来自之前的 batch, 前向更是只读固定值. 两者都满足因果约束, EC 不满足, 区别就在选择这一步本身是否跨 token 竞争.

#### 5.1. V3 沿用了什么, 改了什么

V3 ([DeepSeek-V3 解析](../../01-模型技术报告/deepseek-v3/deepseek-v3-analysis.md) 第 1.4 节) 沿用了论文的核心: sigmoid 亲和度, 加性偏置只进排序, 每步在整个 batch 上统计负载, 按符号更新, 步长 (V3 叫偏置更新速度 $\gamma$) 也是 0.001. 改动有五处, 每一处都对应论文没覆盖到的情形. 规模和门控形式不同. V3 每个 MoE 层 256 个路由专家选 8 个, 外加 1 个共享专家, 前 3 层是稠密 FFN; 门控在选中的 8 个专家上把 sigmoid 分数归一到和为 1, 再乘一个缩放系数 (官方推理代码里的 `route_scale`). 论文的式 (3) 不做这一步. 归一化只改权重, 不改选择, 偏置仍然只影响集合. 偏置还参与了节点选择. V3 限制每个 token 最多发往 4 个节点, 实现上把 256 个专家分成 8 组, 每组的得分是组内最高两个分数之和, 先选 4 组, 再在这 4 组里选 Top-8. 官方推理代码 `Gate.forward` 里, 组得分用的是加了偏置之后的分数, 门控权重才用 `original_scores`. 所以 V3 的偏置同时调节「去哪几个节点」和「选哪几个专家」, 论文只有单层 Top-K, 没有测过偏置在两级选择下的行为. 另外这份代码只在隐藏维 7168 (671B 配置) 时创建偏置.

训练末期冻结. V3 在前 14.3T token 用 $\gamma=0.001$, 末段500B token 设为 0, 与学习率的末尾两段恒定期重合. 论文的 1B, 3B 实验从头到尾都在更新. 冻结的作用可以从第 2.4 节推出: sign 更新的步长不衰减, 偏置在均衡带里一直抖, 抖动意味着贴近边界的 token 在相邻两步换专家; 学习率降到很低之后, 这种抖动相对于参数更新不再可以忽略, 冻结让收尾阶段的路由固定下来. 冻结后的偏置随权重一起发布, 推理时继续参与选择. 补了序列级均衡损失. V3 保留一个 $\alpha=0.0001$ 的序列级损失, 形式和式 (2) 相同, 只是 $P_i$ 先把分数在专家间归一, 指示函数按不带偏置的 Top-K 计数. 系数比论文的基线小 10 倍, 用途是防单条序列内的极端偏斜. 第 3.4 节的图 5 已经给出这样做的理由: 计算 batch 小于十几二十条序列时, 纯 Loss-Free 的局部负载比序列级辅助损失还差. V3还在训练中 训练不丢 token, 推理侧再用冗余专家处理领域变化带来的负载漂移, 这两项都在论文范围之外.

#### 5.2. V3 的消融如何改写了论文的解释

V3 报告在两个更大的规模上重做了对比: 15.7B 总参训 1.33T token, 228.7B 总参训 578B token, 大档的 HumanEval 从 40.2 升到 46.3, MATH 从 37.2 升到 39.6, 但 MMLU 从 68.3 降到 67.2. 这是论文缺的下游评测, 结论大体同向, 也有反例. 更有分量的是 V3 §4.5.3 的一组对照: 在 1B 和 3B 上同时比较序列级辅助损失, Loss-Free 和 batch 级辅助损失 (统计范围从一条序列换成整个 batch). 验证损失 1B 上是 2.258, 2.253, 2.253, 3B 上是 2.085, 2.080, 2.080. batch 级辅助损失和 Loss-Free 打平. 这组数字修正了论文的叙述. 论文把 Loss-Free 的优势归于「没有干扰梯度」, 而它的基线式 (2) 同时具备两个特征: 有梯度, 并且按序列统计. V3 的对照把两者拆开后显示, 只要把辅助损失的统计范围放宽到 batch, 带梯度的方法也能达到同样的验证损失. 收益的主要来源是均衡范围: batch 级约束允许一条代码序列集中使用擅长代码的专家, 专家的领域分工更明显 (V3 报告的 Figure 9 在 Pile 三个领域上画了专家负载). 「干扰梯度」在第 1.1 节的推导里确实存在, 但在 $\alpha=0.001$ 这个量级上, 它对质量的影响小到被统计范围的效应盖住. Loss-Free 相对 batch 级辅助损失的实际好处在工程上: 不用为每个模型重新扫 $\alpha$, 不往残差流注入额外梯度, 均衡程度 (0.04) 比任何能接受的 $\alpha$ 都好. 偏置分数与统计范围的关系, 在 [MoE 负载均衡与容量](../../../llm-guide/2-核心原理与架构/2.6-MoE/03-MoE负载均衡与容量/03-MoE负载均衡与容量.md) 第 4.3 节有整理.

#### 5.3. 之后的演进

DeepSeek-V4 继续用无辅助损失均衡, 偏置更新速度 0.001, 序列级损失权重 0.0001, 亲和度函数从 sigmoid 换成了 $\sqrt{\mathrm{Softplus}(\cdot)}$, 并在前 3 个 MoE 层改用按 token ID 哈希的路由, 见 [DeepSeek-V4 解析](../../01-模型技术报告/deepseek-v4/deepseek-v4-analysis.md) 第 1.1 节. 亲和度函数换掉以后分数不再有 $(0,1)$ 的上界, 第 2.4 节说的 $u$ 与分数量程的绑定关系也随之改变, V4 报告没有讨论这一点. 框架层面, Megatron-LM 把偏置均衡做成了开关 (`moe_router_enable_expert_bias`, `moe_router_bias_update_rate`), 并允许与序列级辅助损失同时开启, 即 V3 的组合. 方法层面有两条改进路线. 一条改步长: 论文的消融只比了固定 $u$ 下的 sign 与线性两种形式, 没有试过随训练衰减的 $u$, 也没有试过把 $e_i$ 先按整体幅度归一再更新. 从第 2.4 节的分析看, 前者能收窄末段的均衡带, 后者能让接近均衡的专家少动, 两者针对的都是固定步长 sign 规则的抖动, V3 末段直接冻结是其中最简单的做法. 另一条改求解方式: Kimi K3 在 896 个路由专家的规模上不再逐步试探, 而是按分数分位数直接解出让负载均衡的偏置 (Quantile Balancing), 见 [Stable-LatentMoE 与 Quantile Balancing](../../../llm-guide/2-核心原理与架构/2.6-MoE/04-Stable-LatentMoE与Quantile-Balancing/04-Stable-LatentMoE与Quantile-Balancing.md). 两条路线保留的都是论文最核心的那一步: 均衡由一组只进排序的偏置负责, 不经过主损失的梯度.

## 2. 反馈控制、选择偏置与稳定性

### 把偏置更新写成反馈控制

第$i$个专家在batch中的实际负载为$f_i$,目标负载为$\bar f=K/N$. 路由偏置$b_i$只进入排序分数$z_i=s_i+b_i$. 更新

$$
b_i^{(t+1)}=b_i^{(t)}+u\,\operatorname{sign}(\bar f-f_i^{(t)})
$$

构成离散反馈控制:过载专家降低偏置,欠载专家提高偏置. 控制器不通过反向传播,其“梯度”来自下一batch的计数响应. 路由负载是偏置向量的非光滑函数. Top-k集合只在分数穿过边界时变化,小偏置更新可能暂时无效,越过边界后负载离散跳变. sign规则用固定步长穿越这些平台,也会在均衡点附近来回震荡. 若局部近似$f-\bar f\approx J(b-b^*)+\epsilon$,线性控制$b\leftarrow b-u(f-\bar f)$类似积分控制;sign控制只保留方向,对异常幅度稳健,无法随接近目标自动减小步长. MoE输出

$$
y_t=\sum_{i\in A_t}\frac{s_{i,t}}{\sum_{j\in A_t}s_{j,t}}E_i(h_t),\qquad A_t=\operatorname{TopK}_i(s_{i,t}+b_i).
$$

$b_i$改变集合$A_t$,选中后的混合权重仍由原始亲和度$s_i$决定. 这样偏置只决定“给谁机会”,不会让欠载专家因人为大偏置获得过高输出权重. 若偏置同时进入权重,控制器会直接改变前向函数,模型可能依赖偏置数值编码内容;偏置每步更新又使标尺非平稳. 只进排序把影响限制在集合边界. 集合变化仍会改变前向,因此方法并非对模型函数无影响. 区别在于没有连续辅助loss梯度推着router牺牲任务亲和度,负载干预集中在边界token. 经典损失$L_{bal}=\alpha N\sum_if_iP_i$,其中$f_i$是硬路由频率,$P_i$是平均soft概率. 训练通常对$f_i$停梯度,router收到

$$
\frac{\partial L_{bal}}{\partial z_{i,t}}\propto\alpha f_i\frac{\partial P_i}{\partial z_{i,t}}.
$$

过载专家$f_i$大,其概率被压低;欠载专家概率被抬高. 这条梯度作用于所有token,包括本来高度适合某专家的token,会削弱专门化. 干扰大小由$\alpha$与主损失梯度相对尺度决定. $\alpha$很小可能几乎无伤,均衡又不足;很大时负载好、语言loss变差. Loss-Free把该超参数换成控制步长$u$与统计窗口. V3的batch级辅助损失结果表明,干扰梯度并非全部质量差距来源. 统计范围从序列扩大到batch,允许领域样本间互补,即使保留梯度也能接近Loss-Free. 负载估计可按单序列、microbatch、global batch或滑动窗口. 窗口越小响应快、噪声大;窗口越大稳定,对分布变化反应慢. 单序列强制均衡会让每篇代码或数学文本都使用全部专家,直接反对领域专门化. Batch均衡只要求不同序列合计平衡,每条序列可集中使用相关专家.

分布式训练中各data-parallel rank看到不同样本. 若偏置按本地负载更新,rank间$b$分叉,同一token路由不同;需要all-reduce计数或周期同步. 全局batch很大时通信计数成本小,更新延迟至少一个step. 数据非IID或课程切换时,滑动估计可减小突变. batch含$T$个token,每token选$K$专家,理想每专家期望$TK/N$. 即使真实概率均匀,计数标准差约$\sqrt{TK(1/N)(1-1/N)}$. 相对噪声约$\sqrt{(N-1)/(TK)}$. $N=64,K=6,T=8192$时约3.6%;T只有512时约14.3%. 小batch下sign更新经常追逐抽样噪声. 可设置死区$|f_i-\bar f|<\tau$不更新,或用EMA平滑. 死区降低抖动,允许更大瞬时不均. V3末期冻结等价于训练时间维度上的最大死区.

$u$相对原始分数量程决定每步能翻转多少边界token. sigmoid分数在0到1,$u=0.001$看似小;若Top-k margin集中在$10^{-4}$,仍会翻转很多. 定义margin$m_t=z_{(K)}-z_{(K+1)}$. 更新后只有$m_t$不大于相关专家偏置差变化的token可能换路由. 统计margin分布可预测控制增益. 大$u$响应快、震荡大;小$u$稳定、恢复慢. 数据分布突变后的整定时间约与所需偏置位移/$u$成正比. 步长衰减$u_t$可在早期快速均衡、末期收敛. 满足随机逼近条件$\sum u_t=\infty,\sum u_t^2<\infty$有理论收敛直觉,Top-k非光滑与非平稳权重使严格证明更复杂. 理想MoE希望专家功能不同,硬件又希望负载接近. 二者不矛盾:不同数据域占比若均衡,各专家可专门化且总负载相等. 域分布偏斜时,完全均衡要求部分token去次优专家.

令token对首选与次选专家主loss差为$\Delta_t$. 为均衡翻转低$\Delta_t$边界token代价小,翻转高margin token代价大. 偏置排序天然先影响margin小的token,是一种近似最小代价流量调节. 辅助loss连续压缩所有概率,可能改变高margin token表示;偏置法主要换边界集合. 这是其质量优势更精确的机制假设. 每专家容量$C=\lceil cTK/N\rceil$,容量因子$c$. 过载时token丢弃、绕到备选或all-to-all缓冲溢出. 均衡降低所需$c$,节省显存和通信. 论文与V3强调不丢token,意味着系统要容纳实际最大负载. MaxVio低能缩小最坏峰值,但瞬时microbatch与节点聚合仍可能不均. 平均专家均衡不保证节点均衡. 多个热门专家若落在同一节点,节点all-to-all过载. V3加入group/node限制与冗余专家处理这一层.

若专家负载$f_i$,平均$\bar f$,MaxVio通常衡量$\max_i f_i/\bar f-1$. 它关心最坏过载,与系统容量直接相关. MaxVio小不代表整体均匀. 一个专家略过载,多个专家接近零,最大比可能受定义掩盖;还应报告CV、熵、Gini与最小负载. 时间平均MaxVio也会掩盖尖峰. 通信buffer按step峰值配置,应报告P95/P99与连续过载时长. 模型参数持续学习,原始亲和度分布$s_i$变化. 控制器追踪移动目标$b^*(t)$. 若模型变化速度快于偏置响应,负载滞后;后期模型稳定,偏置震荡成为主要变化. 偏置存在平移不变性:给所有$b_i$加常数不改变Top-k. 数值可整体漂移而路由不变. 定期减均值保持数值稳定.

长期偏置幅度很大说明原始router强烈不均. 这可能遮住训练问题;仅靠控制仍能均衡,专家亲和度与选择集合长期错位. 模型权重以学习率$\eta_t$更新,偏置以$u$更新. 当$u\gg\eta$,偏置快速均衡当前router;当$u\ll\eta$,router分布先变化,负载长期偏. 理想双时间尺度让控制器相对快,又不对batch噪声过敏. 训练末期$\eta$下降而$u$固定,相对关系反转,偏置抖动占主导,解释V3冻结. 联合扫描$u/\eta$比单扫$u$更可迁移到不同batch与模型规模. 论文固定设置在V3沿用成功,不保证普遍最优. sign更新每个不平衡专家移动同样幅度,避免极端batch造成巨大跳变. 线性更新$b_i\leftarrow b_i+u(\bar f-f_i)$按误差幅度加速恢复,对噪声敏感.

归一化线性更新用误差除以$\bar f$提高跨batch可比性. clipped更新$\operatorname{clip}(e,-c,c)$连接两者. 带动量或PI控制可减少稳态误差,可能产生过冲. 非光滑Top-k让经典控制直觉需实验验证.

## 3. 数据漂移、路由结构与可证伪实验

### 数据域变化

预训练语料按阶段混合代码、数学、多语言,最优专家负载随域比例变化. 全局均衡控制会把新增域流量分给多个专家,可能阻碍形成新专门化. 按域维护偏置能保护专门化,部署时需要知道域标签. 单一偏置更简单,允许专家功能随整体分布重排. 微调或RL数据窄,继续更新偏置可能大幅改变路由;冻结预训练偏置保留底座结构,负载可能偏. 两种选择需根据硬件容量与适应目标权衡. 共享专家每token激活,不参与路由均衡. 它们吸收通用能力,路由专家更容易专门化. 共享计算固定,提高总激活成本. 若共享专家过强,router专家梯度弱,负载控制仍均匀分配无关token,专门化不足. 若共享太弱,每个路由专家都需承担通用模式.

Loss-Free只控制路由专家计数,不能保证共享与路由贡献比例. 应同时测输出norm和消融. V3先选节点组再选专家,偏置影响两级分数. 专家级均衡可能与节点级冲突:某节点内专家都略欠载,组分数上升后节点突然过载. 可分别维护节点偏置与专家偏置,形成层级控制. 单一专家偏置通过组Top-2间接调节点,响应非线性. 节点约束减少跨机通信,可能迫使token放弃全局最佳专家. 质量—通信权衡需独立消融. 推理流量分布与训练不同,固定偏置可能造成热点. V3部署冗余热门专家,把同一逻辑专家复制到多个设备,调度分流.

冗余解决物理负载,不改变模型路由语义. 训练均衡解决逻辑专家计数. 两者不能混为同一机制. 复制数量按线上profile决定,分布变化后需重新映射. 权重相同无需额外训练,占显存与同步加载. 负载熵高表示专家使用均匀,不代表每token选择多样. 每tokenTop-k固定,重要的是跨token分布与专家功能. router概率熵太高表示亲和度平坦,选择由小偏置主导,专门化弱;概率熵低而总体负载均匀说明不同token明确选择不同专家,更理想. 同时报告token级熵和batch负载熵,可区分“所有token随机均分”与“分工明确后的总体均衡”.

Top-k margin决定偏置敏感度. 小margin token是控制器的调节储备,大margin token稳定留在擅长专家. 训练中若margin整体增大,固定$u$翻转token变少,控制响应减慢. 偏置可能累积更大幅度才生效. 按margin分桶测被重新路由token的主loss变化,可以验证“低代价边界调节”假设. 验证loss平均差很小,下游领域可能不同. 专家分工改善应在代码、数学、多语言呈现不同负载模式与能力变化. V3大模型消融有正有负,说明均衡策略没有逐项单调优势. 多seed与任务置信区间仍重要.

系统吞吐收益也可转化为更大batch或更多token,间接影响最终质量. 固定算力与固定token是两种不同对比口径. 实验一固定batch统计范围,比较辅助loss、Loss-Free与无均衡,隔离梯度影响. 再固定方法改变序列/batch范围,隔离统计范围. 实验二按router margin分桶,观察偏置更新翻转率与loss代价. 若高margin同样大量翻转,最小代价解释不成立. 实验三扫$u$、batch token与EMA窗口,用归一化噪声$\sqrt{N/(TK)}$对齐曲线. 若最优$u$随噪声可预测,控制解释成立. 实验四训练末期分别固定$u$、衰减$u$、冻结偏置,比较路由Jaccard、loss与MaxVio. 验证V3冻结动机.

实验五做域切换,测恢复时间、偏置幅度与专家功能变化. sign、线性与分位数法比较动态响应. 实验六专家均匀但节点放置不均,测节点all-to-all峰值. 加层级控制后若改善,说明专家指标不足. 实验七保留相同MaxVio,构造不同负载分布,测吞吐与buffer. 验证单指标边界. 实验八冻结router只更新偏置,与联合训练比较. 区分控制本身和router适应. batch太小,计数噪声主导,偏置随机游走. EMA或序列级小辅助loss更稳.

数据极度单域,所有token真实偏好少数专家. 强均衡必然把token送往次优专家,质量与均衡无法同时最优. 专家容量或节点拓扑约束未进入控制目标,专家计数均衡仍可能通信热点. router margin过大,小$u$长期无效;突然累积到阈值后大量token切换,产生震荡. 推理分布漂移且偏置冻结,训练均衡不保证线上均衡. 动态改偏置会改变模型行为,需谨慎校准. 1B配置$N=64,K=6,T=8192$,总路由分配49152,理想每专家768. MaxVio 0.1允许最忙约845,额外77 token.

若每token专家FFN通信4KB,额外77约0.3MB/层/step/热点专家. 多层多rank累积后影响buffer与尾延迟. 计数all-reduce只需64个整数/层,相对激活通信很小. 控制器工程成本主要在同步时序而非字节. $u=0.001$,欠载专家连续100步增加0.1偏置,已是sigmoid全量程10%. 长期大偏置应触发诊断. token-choice每个token只依据自身历史表示选专家,满足因果. Expert Choice让专家在一组token中挑Top-C,某token是否入选取决于组内未来token分数. 因此当前token输出隐含了未来token竞争结果,形成侧信道. chunk越短且与同一序列对齐,泄漏越容易被模型利用.

打乱token破坏未来序列关联,损失恢复,是有力因果对照. 更长chunk未明显泄漏不能证明安全,学习解码通道可能更难. Loss-Free使用前一batch统计更新固定偏置,当前前向不读同batch未来路由,保持因果. 组合数计算给路由分配可编码bit上限,没有说明模型实际互信息. 分配还承载正常专家选择,可供泄漏的剩余容量更小. 要测实际泄漏,可训练probe从当前token专家分配预测未来token,与打乱和token-choice对照. 互信息估计比理论容量更直接. 自回归推理组大小改变时,训练利用的信道消失,产生严重train-test gap. 应报告生成困惑度与下游,论文只给训练loss曲线.

sign控制逐步试探偏置,分位数法根据分数分布直接求使目标计数达成的阈值. 专家数大时收敛更快. Top-k多专家选择使各专家阈值耦合,独立分位数只近似. 需要迭代或全局约束. 分位数对当前batch拟合精确,也可能追逐噪声. 使用历史分布与正则能稳定. 两者是反馈控制与直接求解的取舍. 论文直接支持1B/3B预训练loss、MaxVio、更新形式消融与EC泄漏实验. V3报告补充大规模下游、batch辅助loss和生产配置. 控制论、margin、噪声和层级路由分析是由公式推出的验证框架,不应写成已测事实. V4亲和函数变化后的最优$u$也没有官方消融.

后续Quantile Balancing属于不同团队/模型路线,可比较求解思想,不能算原论文结果. Loss-Free把负载均衡从主损失梯度中拿出来,交给只参与排序的偏置反馈. 控制器用上一批负载调下一批选择,输出权重仍由原始亲和度决定. 质量优势来自两个可能因素:减少辅助梯度干扰,扩大统计范围以允许序列专门化.V3消融说明后者贡献很大,前者仍提供免调$\alpha$和更低MaxVio的工程价值. 稳定性由batch噪声、Top-k margin、步长和模型学习速度共同决定. 专家计数均衡还需延伸到节点、容量与推理漂移. 方法最适合大batch、细粒度专家、分布混合且不丢token的训练. 小batch、单域或强拓扑约束需要EMA、小辅助loss或层级控制补充.

## 4. 平衡目标、专家塌缩与路由正则

### 平衡目标的选择

目标$\bar f=K/N$默认所有专家同容量、同速度、同通信成本. 异构设备或专家尺寸不同,最优负载应按服务率$\mu_i$分配:

$$
f_i^*=\frac{\mu_i}{\sum_j\mu_j}K.
$$

慢专家目标更低,快专家更高. 追求计数均匀反而增加step尾延迟. 控制器可直接把$\bar f_i$换成容量加权目标. 专家所在节点链路不同也可进入成本. 目标不再是单个固定向量,而是最小化最大节点完成时间. 需要在线profile服务率. token数相同不等于计算量相同. 不同序列长度、padding、专家实现或条件计算会改变成本. 标准FFN专家结构一致时计数是良好代理. 若专家采用不同宽度或量化,应按预计FLOPs/字节加权. 控制信号从$f_i$改为工作量$c_if_i$. 通信量还与token来源rank相关. 本地token与远端token计数相同,网络成本不同. 专家负载均衡只能控制第一层代理.

设节点$m$承载专家集合$G_m$,节点负载$F_m=\sum_{i\in G_m}f_i$. 即使所有$f_i$接近均值,每节点专家数不同或冗余映射也会造成$F_m$差异. 层级偏置可写$b_i=b_i^{expert}+b_{g(i)}^{node}$,节点偏置按$F_m$更新,专家偏置按节点内相对负载更新. 两个控制环步长需分离,避免互相振荡. V3组选择用组内Top-2分数,节点偏置无法简单等价于所有专家加常数,因为组排序与最终专家排序耦合. 仿真应使用真实路由函数. 定义不均衡势能$V=\frac12\sum_i(f_i-\bar f)^2$. 理想更新若使过载专家选择概率下降、欠载上升,期望$V$减小. Top-k跳变、模型参数更新与batch噪声会让单步$V$上升. 评估应看窗口平均下降和稳态分布,不要求每步单调.

若连续多步$V$发散,可能步长过大、符号方向实现错误、偏置未同步或节点约束冲突. 该势能是简单诊断量. 某专家初始亲和度极低,即使持续增加偏置也长时间选不到token,形成dead expert. sign更新最终能把$b_i$推过边界,恢复时间取决于分数差/$u$. 一旦突然获得大量token,未训练专家输出差,主loss上升,随后梯度才开始适应. 热启动可在初期限制偏置幅度或给专家少量强制流量. dead expert率、首次激活step和恢复后loss应单独监控. 平均MaxVio可能只显示其他专家过载,不说明欠载专家能力. router与专家存在正反馈:某专家表现稍好,获得更多token,训练更多,进一步变好. 均衡控制打断流量正反馈,给其他专家学习机会.

完全均衡也可能把差专家长期保留,降低总体质量. 专家初始化、共享专家和容量共同决定是否需要强控制. 可在训练早期强均衡、后期放宽目标,让成熟专家按能力获得略多流量. 这与固定均匀目标不同. 偏置只靠反馈可能累积很大. 加泄漏项$b_i\leftarrow(1-\lambda)b_i+u\operatorname{sign}(e_i)$让无持续误差时回到零. 泄漏减小长期对原始router的遮蔽,会产生稳态负载误差. 控制论对应leaky integrator. 限制$|b_i|\le b_{max}$防数值失控,达到上限且仍欠载说明专家或router存在结构问题,不应继续靠偏置补偿.

sigmoid分数量程固定,加性偏置含义明确. Softplus平方根无上界,分数尺度随参数变化,固定$u$相对强度会漂移. 可把偏置按层内分数标准差归一:$z_i=s_i+\sigma_s\tilde b_i$,控制无量纲$\tilde b$. 这样跨层和训练阶段更可比. 乘性偏置$s_i(1+b_i)$在$s_i$接近零时调节无力,对高分专家作用大;加性偏置能救活低分专家. 论文消融支持加性,机制与此一致. z-loss约束router logits尺度,防止softmax过大,不直接均衡负载. logits尺度稳定后,固定偏置步长的相对意义也更稳定. 若亲和度用sigmoid而非softmax,仍可能需要logit正则控制饱和. 饱和区梯度小,router难适应,偏置只能换集合.

均衡控制、z-loss与router学习率共同影响margin,消融应保持其余设置一致. V3选中后对原始sigmoid分数归一. 偏置把一个低原始分专家推进集合时,其混合权重可能很小,主loss代价有限,但专家收到的梯度也小. 这形成柔和探索:计数上获得token,功能贡献逐步增长. 若不归一且直接用sigmoid,总权重变化可能更大. 负载计数只看入选,不看混合权重. 专家计算成本与入选相关,学习有效样本则还受权重影响. 应同时报告token数与门控质量. 欠载专家被偏置选中却原始权重低,其参数梯度乘门控权重,学习慢. 控制器可能持续送更多token,负载均衡但能力追不上.

可给新选专家最低训练权重,会直接改变前向;或只在反向重标度,产生straight-through偏差. 原方法没有这类补偿. 观察专家loss、梯度norm与原始门控质量能识别“有流量但学不到”. V3保留$10^{-4}$序列级辅助loss,给局部极端偏斜提供快速梯度. Bias控制全batch均衡,两者处理不同尺度. 小batch或单序列推理模拟中,序列loss能防一条样本把所有token送少数专家. 系数很小以减少专门化干扰. 两机制同时开启时可能冲突:batch层希望不同序列互补,序列loss希望每条均匀. 扫系数可看质量与局部MaxVio.

冻结偏置固定选择边界,router与专家仍可在该分配附近收敛. 若router继续变化很大,负载会重新偏斜;V3末段学习率低,变化有限. 冻结时刻过早,后续数据域改变无法适应;过晚,路由抖动影响收尾. 可依据偏置更新率、MaxVio稳定与学习率共同触发. 保存checkpoint需要包含$b$. 恢复训练若丢偏置,路由瞬间变化,负载和loss跳跃. 训练得到的$b$编码训练分布下的均衡补偿. 推理batch内容、序列数与领域不同,直接使用保证模型行为一致,不保证硬件均衡. 在线更新$b$会改变输出,尤其margin小token. A/B请求在不同负载下可能得到不同专家与文本,不利于可复现.

生产更倾向固定模型偏置,用冗余专家与调度解决物理热点. 若确需动态偏置,需离线校准质量边界.

## 5. 微调、强化学习与分布式时序

### 微调阶段

窄域SFT可能集中少数专家. 继续Loss-Free会强制均衡到其他专家,扩大被修改参数范围;冻结偏置保留预训练路由,节点热点增加. 可降低$u$或把目标设为预训练负载分布而非均匀. 这样保持专家专门化比例,只防进一步塌缩. PEFT只训练部分专家时,均衡到冻结专家会减少有效梯度. 路由控制必须知道可训练集合. RL rollout分布随策略变化,router负载也变化. 在线控制能追踪,奖励噪声与小batch使计数更抖. 不同答案长度导致token权重不均,长rollout主导负载统计. 可按序列等权或token等权,对应不同系统目标.

策略更新与偏置更新双重非平稳,需要更慢$u$或独立EMA. 下游官方报告具体设置不足时不应臆测. 全局batch恰好按领域均匀时,专家专门化与负载均衡兼容. 若batch按数据源成块,连续多个step单域,控制器来回追踪,偏置震荡. 数据shuffle改善控制稳定,也改变训练随机性. 按域分层组batch能让每step接近全局分布. 若硬件只能小microbatch,梯度累积期间汇总路由计数再更新偏置,统计窗口增大;偏置在累积步内固定. step$t$前向使用$b_t$,统计$f_t$,all-reduce后得到$b_{t+1}$. 所有rank必须在下一前向前同步,否则模型函数不同.

异步更新减少等待,rank间偏置陈旧会导致不同路由,专家并行通信难以匹配. 同步计数通常必要. 流水并行有多个microbatch在途,立即更新会让同一step不同microbatch用不同$b$. 应在pipeline flush或全局step边界更新. Loss-Free仍是token-choice:每个token用自己的隐藏状态和全局固定$b$选专家. $b$来自历史batch,不包含当前序列未来token. 若实现错误地在当前batch先统计再重路由同一batch,偏置会读到未来token分布,重新引入跨token依赖. Algorithm 1时序必须严格遵守. 单元测试可改变当前token之后内容,确认该token路由不变. 这是因果路由的直接验收.

均衡后的专家是否更专门化,可用领域负载向量、token属性probe与专家替换损失测量. 仅看路由热图会把偏置强制分配误当功能. 若专家在某领域负载高,删除它应显著损伤该领域而较少影响其他领域. 负载与因果贡献一致才说明专门化. 辅助loss与Loss-Free在相同batch范围下比较功能指标,能直接测试干扰梯度假设. 每step均衡可能过严. 系统只需在通信buffer窗口内不过载,长期平均可允许领域step集中. 放宽为多step窗口能保护专门化. 窗口$W$内累计负载$F_i=\sum_{t-W+1}^tf_i$作为控制信号,响应慢、噪声低. 突发过载仍需容量缓冲.

最优$W$由硬件队列可吸收时长与数据域相关长度决定. $b_i>0$表示原始router低估该专家相对目标的流量,$b_i<0$表示高估. 跨层比较前需除以分数尺度. 领域切换时观察$b$变化可识别哪些专家受新数据偏好. 这是一种系统诊断,不等于专家语义标签. 偏置长期单调增长、负载仍低,说明专家输出差、分数饱和或路由mask不可达. 给定一批token亲和度矩阵,可以离线求容量约束下最大总亲和度分配,作为oracle. 它回答在完全均衡下最小质量代价.

Loss-Free分配与oracle亲和度差距衡量控制效率;无均衡Top-k与oracle质量差距衡量均衡必需代价. 这是一个带每token选K、每专家容量的b-matching问题,小规模可精确求解,大规模用最小费用流近似.

## 6. 对偶视角、容量约束与消融设计

### 偏置法与对偶变量

容量约束优化

$$
\max_x\sum_{t,i}s_{ti}x_{ti},\quad \sum_ix_{ti}=K,\quad \sum_tx_{ti}=C_i
$$

的拉格朗日乘子正对应专家偏置. 对固定对偶变量,每token选择$s_{ti}+b_i$最高专家;负载误差用于对偶上升. 这给出Loss-Free更深的解释:它在近似求解容量约束的最大亲和度分配.sign更新是对偶次梯度只保留方向的版本. 有限batch、非凸模型和动态$s$让问题持续变化,对偶解释仍能说明为何偏置只进排序. 标准对偶上升应按约束违反幅度更新,线性规则更接近. sign规则归一化幅度,在不同负载误差下等速. sign对量纲和离群稳健,远离最优时收敛可能慢. 混合策略在大误差用线性clip,小误差用衰减步长.

对偶目标可离线画出$b$与负载响应,选择稳定增益. 论文经验$0.001$是有效点,未给系统整定方法. 反例一:数据99%为代码,仅少数代码专家真正优. 均匀目标迫使大量token进非代码专家,质量必降. 反例二:一个专家硬件变慢,计数均匀仍拖尾. 目标应按服务率调整. 反例三:小batch每step只有少量token,许多专家计数为零,sign同时抬高大量偏置,下一步群体过载. 反例四:router margin极大,偏置积累很久后突然翻转大量token,产生周期震荡.

反例五:专家均匀散布但节点映射把热点专家集中,系统仍不均. 二维扫描统计范围{序列,microbatch,global,EMA}与控制方式{辅助loss,sign,linear,quantile}. 每点保持token与模型一致. 报告验证loss、下游、MaxVio P99、CV、节点负载、all-to-all时间、偏置norm、路由Jaccard与专家功能probe. 再扫batch token与专家数,验证参数是否按噪声尺度迁移. 单一1B/3B配置不足以得到普遍规律. V3每层256专家选8. 全局batch若含8M token,每层总分配64M,理想每专家25万,相对抽样噪声约$\sqrt{255/(64M)}\approx0.2\%$,计数极稳定.

若本地microbatch仅4096 token,总分配32768,每专家128,相对噪声约8.8%. 这说明必须汇总global batch后更新. 偏置计数all-reduce每层256个32位数约1KB,数十层仍很小. 同步延迟可与其他梯度通信融合. 某逻辑专家承担平均2倍负载,复制成两份并按请求分流可恢复物理均衡,模型输出相同. 显存增加一份专家权重. 若热点随领域变化,固定复制可能失效. 维护多个候选冗余槽,按profile换入权重,产生加载成本. 训练偏置若把逻辑负载压平,冗余需求下降;极致均衡换来的质量损失与显存节省需要联合计算.

确认偏置只加入Top-k排序,混合权重使用原始分数. 这是最容易实现错的核心. 确认更新使用前一batch统计,所有DP rank同步,gradient accumulation期间时序一致. 偏置无梯度且保存进checkpoint. 小矩阵手算专家计数与一步更新,再构造未来token变化测试因果. 用固定router验证控制器能从偏斜收敛到均衡带. 方法级验收看相同统计范围下是否减少质量干扰;控制级验收看响应、过冲、稳态抖动与域切换;系统级验收看节点P99和无丢token. 专家功能需在均衡之外单测,推理漂移需用线上分布回放. MaxVio一项无法覆盖完整行为.

偏置法的最大价值是把模型目标与系统约束解耦成两个可观察回路. 解耦不意味着互不影响,Top-k集合仍是两者交点.

## 7. 质量代价、分层控制与路由漂移

### Batch 辅助损失为何能追平

序列级$f_i$要求每条序列内部均匀,代码序列也要分给非代码专家.Batch级$f_i$允许一条代码集中、另一条自然语言集中,合计均衡. 统计范围改变了约束可行域. 当batch足够多样,batch辅助loss的梯度只需修正跨序列总偏差,对单token亲和度干扰较小. 因此V3消融中可追平Loss-Free. 若batch同质或很小,该优势消失. 比较两法必须报告batch组成,不能把结果只归因于有没有辅助梯度. 固定容量$C_i$的路由优化中,偏置是容量约束的影子价格. 专家过载时价格降低其吸引力,欠载时提高. 单位偏置代表放宽一单位容量对目标的边际价值. 若某专家持续需要大负偏置,原始亲和度对它需求高,增加该专家物理容量或复制可能比强行改路由更合理.

偏置因此也能指导系统扩容:结合服务率与质量代价,识别应该复制的逻辑专家. 把目标MaxVio从宽松逐步收紧,记录主loss与下游,得到质量—均衡曲线. Loss-Free的$u$主要影响收敛速度和稳态带,目标本身默认完全均匀. 引入死区或非均匀目标能直接移动曲线. 对硬件而言,只要P99不超过buffer,继续追求更低MaxVio没有收益. 最优点应由系统容量约束决定,不是把MaxVio降到最小. 论文展示0.04的强结果,部署仍需衡量质量边际. 各MoE层router分布、margin和通信不同,统一$u$可能让某些层震荡、另一些响应慢. 可按层分数标准差或负载灵敏度设置$u_l$.

早层token功能较通用,均衡容易;后层领域分工强,完全均衡代价更高. 目标容差也可分层. 逐层报告MaxVio与偏置norm,避免平均掩盖单层热点. 系统step往往被最慢层决定. 不同专家的负载对偏置灵敏度$\partial f_i/\partial b_i$不同. margin密集的专家小偏置就改大量token,应使用更小步长. 可用历史$\Delta f_i/\Delta b_i$估计灵敏度,设置$u_i\propto1/(|J_i|+\epsilon)$. 噪声会让估计不稳,需要平滑与上限. 固定sign简单鲁棒,自适应控制若没有显著减少抖动不值得复杂度. 这是可证伪对照.

一个token选K专家,负载可按硬计数、门控权重和、FLOPs或通信字节定义. 论文用硬计数匹配专家计算量. 门控权重和更接近功能贡献,不能代表FFN是否执行. 用它均衡可能让大量低权重token挤满专家容量. 节点网络按发送字节,若token表示维相同仍与硬计数成正比. 异构压缩时需改指标. padding、被mask token或重复数据是否计入负载会影响控制. 只对实际执行专家的有效token统计最合理. 长序列在batch中贡献更多token,系统计算也确实更多;若想保护每序列领域分工,可另设序列级监控,不应改变硬件计数.

RL中不同rollout长度使长回答主导偏置,这与计算成本一致,与任务公平可能不同. 专家输出改变残差,后层router输入随之漂移. 即使偏置稳定,层间负载会联动. 前层均衡干预可改变后层域分布. 逐层独立控制把这些联动视为外部扰动. 更新足够慢时能追踪,同时大步更新可能产生跨层振荡. 交错更新层偏置或降低全层同步步长可测试联动. 论文所有层同时更新,实验证明其配置可用. router与专家对称初始化时,随机噪声决定早期分工. 均衡控制防单个专家抢占,为对称破缺保留空间.

偏置初始为零最自然. 根据预采样负载初始化可减少热身过载,预采样分布与训练不一致会引入先验. 专家权重完全相同会导致router梯度对称,需要随机初始化或噪声. Bias控制本身不创造功能差异.

## 8. 训练动态、数值细节与并行交互

### Warmup

训练最初router分数无意义,强均衡可避免容量爆炸,也把随机token均分给未成熟专家. $u$过大使偏置在噪声中积累. 可在短warmup用较大容量与小$u$,待margin和专家能力形成后增强控制. 或使用辅助loss提供平滑早期梯度,再切Loss-Free. 比较warmup策略应看后期专家功能,不仅早期MaxVio. 训练相邻step同类token换专家会增加专家参数访问不稳定,对训练cache影响有限,对推理可复现更重要. 路由Jaccard在固定探针集上测量. 末期学习率低而偏置仍变时,Jaccard下降主要来自控制器,冻结应恢复.

功能等价专家间切换可能不伤质量,仍改变通信热点. 质量与系统稳定需分开测. 推理模型可能量化router分数,偏置保持FP32或BF16. 若分数量化步长大于$u$,训练积累的细小bias差异被吞掉,路由改变. 偏置应与分数在同一精度域比较,或在量化前相加. 按margin测量路由一致率. 训练checkpoint到部署kernel的排序稳定是验收项,尤其Top-k并列与tie-break. 专家分数相同时,Top-k实现可能按索引、线程顺序或不确定规约选择. 偏置sign更新会让接近相等情况频繁.

不确定tie-break造成跨设备路由差异. 使用稳定排序或极小确定性扰动保证复现. 固定索引tie-break长期偏好低编号专家,控制器会用偏置补偿,形成无意义偏置差. 随机均匀tie-break则增加噪声. 某专家设备暂时变慢,计数控制看不到服务时间,继续分配相同token. Step尾部恶化但MaxVio正常. 把完成时间或队列长度反馈加入目标可绕开straggler,会让模型路由随硬件状态变化,训练函数非确定. 生产训练更常修复硬件或重映射专家,保持逻辑路由稳定. 短时限流需评估质量.

不同pipeline stage含不同MoE层,最慢stage决定吞吐. 每层专家均衡后,stage间计算仍可能不均. Loss-Free只处理层内专家,不能解决stage划分. 端到端profile需同时调整层分配或virtual pipeline. 控制收益应看step time,不是单层all-to-all. 某非MoE stage已是瓶颈时,进一步均衡无吞吐收益. 专家内部若用TP,每个token还触发TP通信. 硬计数均衡专家计算,节点拓扑决定TP链路. EP与TP组合时,同一专家的token来源分布影响all-to-all,计数相同但跨机比例不同. 放置和dispatch优化仍必要.

Bias法保持路由语义简单,便于系统层独立优化,这是解耦优势. 均衡让每专家每step获得较稳定token数,降低专家参数梯度batch大小波动. 这可能改善优化,是除系统吞吐外的收益. 强制送入不匹配token又增加梯度异质性. 方差下降与样本质量下降并存. 按专家测梯度norm方差、样本loss和领域纯度,可判断哪项主导. 辅助loss若压平router表示,专家分工弱,可能损害跨域泛化.Loss-Free保持原始亲和度学习更自由,只在选择边界施加容量约束.

Batch辅助loss追平说明小系数与宽统计范围也能保留分工. 泛化优势不能简单归给“零辅助梯度”. 最有力证据是相同负载下专家功能分离与下游变化,而非训练loss单点. 四专家目标各25%,当前负载$[40,30,20,10]\%$,$u=0.01$. sign更新后偏置变化$[-.01,-.01,+.01,+.01]$. 若大量token的第2与第3名margin在0.015内,下一步会从前两专家切到后两;负载可能变为$[28,22,27,23]\%$. 控制继续对1、3降偏置,2、4升偏置,形成小幅摆动. 若margin全大于0.1,上述更新几乎无效,需连续多步积累. 相同$u$的响应由margin分布决定.

四专家服务率$[1,1,2,2]$,总选择量100,吞吐最优目标约$[16.7,16.7,33.3,33.3]$. 强制各25会让慢专家每个承担25,完成时间25;加权目标完成时间约16.7,理论step缩短三分之一. 模型质量可能偏好另一个分配. 将亲和度代价加入最小费用流,目标在吞吐与质量间折中. 真实DeepSeek专家同构,均匀计数合理;这个例子界定方法迁移到异构MoE的边界. 预测一:增大全局batch、保持$u$时,MaxVio波动下降. 若不下降,主要噪声来自数据域或控制振荡. 预测二:冻结偏置后固定探针路由Jaccard上升,负载可能缓慢漂移. 若Jaccard不变,末期抖动本来很小.

预测三:相同batch统计下,Loss-Free与小辅助loss质量接近时,专家功能仍可能不同. Probe可区分. 预测四:低margin token承担绝大多数路由切换. 若切换遍布高margin,实现或分数尺度有问题. 预测五:节点热点无法由专家MaxVio预测时,层级控制或重放置会改善通信而不改专家计数. 原论文证明偏置反馈能把负载压到很低违约,并避免强序列级辅助loss的质量代价.V3验证方法可扩展到256专家与大模型. V3的batch辅助loss对照说明统计范围是关键混杂因素,使“全部收益来自无干扰梯度”不再成立. Loss-Free仍在均衡精度、免调$\alpha$和控制解耦上有优势.

序列级微小loss、末期冻结、节点限制与推理冗余说明生产系统没有把单一算法当万能解. 每项补丁对应不同时间或拓扑尺度. Auxiliary-Loss-Free路由可以视为容量约束分配的对偶控制. 偏置是影子价格,负载误差更新价格,每token仍按任务亲和度加价格选择Top-k. 它减少主梯度对router的持续拉扯,允许batch内不同序列形成领域分工. Top-k集合仍受系统约束改变,质量与均衡的张力没有消失. 稳定使用需要足够大的统计窗口、合适步长、同步时序、末期处理以及节点/容量监控. 小batch、异构专家和窄域微调需要修改目标或补充机制. 最可靠的评估同时包含主loss、下游、路由margin、专家功能、负载P99、节点通信和推理漂移. 只看MaxVio无法判断方法是否真正更好.

## 9. 质量上界、校准与恢复训练

### 路由变化的质量上界

设无偏置Top-k集合$A_t^0$,加偏置集合$A_t^b$. 只有对称差$A_t^0\triangle A_t^b$中的专家改变. 若专家输出范数不超过$V$,被替换总门控质量为$\delta_t$,输出变化可粗界为$2V\delta_t$. 硬计数翻转很多不一定输出变化大,因为新旧边界专家原始权重都低. 这解释偏置可显著调负载而主loss代价有限的区域. 应测计数翻转率与被替换门控质量,后者更接近功能扰动. 高翻转、低质量可能系统收益大且模型影响小. 边界专家若功能相似,替换代价小;功能差异大,同样margin也可能伤质量. Router分数近似表达适配度,不是完整功能距离. 计算专家输出CKA或在公共输入上的差异,分析控制器是否主要在相似专家间搬运token. 若偏置经常跨功能簇调流,专门化受损更大.

可在每个功能簇内均衡、簇间按数据需求分配,形成分层目标. 需要可靠簇与额外系统支持. 原始亲和度$s_i$排序决定任务匹配,其数值未必跨专家校准. 某专家logit尺度系统偏高会过载,偏置长期补偿相当于校准截距. 若尺度差异还包括温度,单一加性偏置不能完全修正. 每专家仿射校准$a_is_i+b_i$表达更强,会直接改变margin与学习动态. 长期$b$可作为router校准诊断. 重训router消除系统偏差后,控制偏置幅度应下降. 均衡关注专家资源,公平还可关注数据域:少数语言token是否总被迫进入拥塞或低质量专家. 全局硬件最优不保证各域质量相近.

按域报告路由margin、替换率与loss变化. 若少数域承担主要均衡代价,可以设置域保护或增加相关专家容量. 域标签不完备时,用表示聚类近似. 保护过多群体会缩小均衡可行域,需要明确优先级. 从checkpoint恢复必须同时加载模型、优化器、偏置、控制EMA与全局step. 只加载$b$而丢EMA会在首步产生跳变. 数据并行规模改变后global batch不同,计数噪声与目标绝对值变化. 负载使用比例归一时目标不变,$u$可能需要按噪声重调. 专家并行映射改变时,逻辑专家ID保持,偏置按ID迁移. 不能按物理rank顺序加载.

每层记录专家计数直方图、MaxVio、CV、熵、偏置均值/方差/极值、更新方向翻转率和探针路由Jaccard. 系统侧记录每rank收发token、all-to-all时间、buffer峰值与丢弃. 将逻辑均衡和物理性能对齐. 模型侧记录主loss、辅助loss、router梯度、专家梯度与领域负载. 这样才能判断质量变化来自控制还是数据. 用8到16专家的小MoE,合成两域数据,人为设定域—专家匹配. 扫序列混合比例与batch大小,能直接观察专门化和均衡张力. 比较无均衡、序列辅助、batch辅助、sign偏置、线性偏置. 保持专家容量足够,避免丢token混杂.

随后加入节点分组、专家异构速度和域切换,验证层级控制与非均匀目标. 小模型可多seed给置信区间. 四token各选一专家,两专家容量各2. 亲和度为$[(10,9),(10,0),(9,8),(9,0)]$. 独立Top-1全部选专家1,总分38但违反容量. 容量最优把第二个或第四个token分给专家2. 改第二个损失10,改第四个损失9,所以应分配第四个到专家2;还需再改一个,第一损失1、第三损失1,任选其一. 最优总分28. 偏置降低专家1后,margin为1的第一或第三token先翻转,符合最小代价;随后仍需翻转margin9的第四token. 当真实需求超出容量,高代价改派无法避免. 若质量对均衡极敏感,优先增加容量、复制热点或改善放置;若大量低margin token可调,偏置控制性价比高.

若小batch导致噪声,汇总更大窗口或保留微小序列loss;若末期抖动,衰减或冻结;若节点热点,增加层级目标. 每种症状对应不同修复,不能只调$u$. 先定位统计、控制、拓扑还是模型亲和度问题. 若Loss-Free主要保护专门化,在相同batch负载下其领域probe应强于序列辅助loss;若差异消失,收益主要来自统计范围. 若偏置近似对偶价格,提高某专家容量目标后,其$b_i$应上升并吸收更多低机会成本token,总亲和度损失下降. 若末期冻结减少控制抖动,固定探针路由稳定度应提高,主loss不应突然变坏;若负载迅速恶化,冻结时机过早.

若专家计数是系统好代理,MaxVio下降应伴随all-to-all尾延迟下降;若两者脱钩,节点映射或异构成本占主导. 无辅助损失均衡最重要的变化是把“学什么”和“每台设备算多少”拆成主梯度与反馈偏置两个回路. Router学习任务亲和度,偏置以影子价格执行容量约束. 两个回路仍在Top-k集合处耦合. 偏置会改模型前向,router变化会改控制对象,batch噪声与硬件拓扑会改反馈质量. 解耦让问题更容易测量,没有让权衡消失. 从原论文到V3,方法逐步补上batch统计、微小序列约束、末期冻结、节点选择和推理冗余. 这套组合说明生产MoE需要同时处理模型、控制与系统三个尺度.

## 10. 故障诊断、容量计算与验收

### 一次完整故障诊断

假设训练中MaxVio从0.05突然升到0.4,主loss基本不变,all-to-all时间增加30%. 先检查global计数是否同步:若不同rank的专家直方图不一致,问题在偏置或计数all-reduce;若一致,再看数据域是否切换. 域切换时原始router负载与偏置norm会同时变化. 偏置方向正确但恢复慢,说明$u$相对margin过小;偏置每步反转且负载摆动,说明$u$过大或batch噪声高. EMA曲线能区分持续偏斜和单步尖峰. 若专家MaxVio已经恢复,all-to-all仍慢,查看节点负载与token来源. 热门专家可能集中在一个节点,或跨机比例上升. 此时继续调专家偏置无法解决,应重放置、加节点级控制或复制专家. 若负载改善但主loss开始上升,按margin统计被改派token. 大量高margin token切换说明均匀目标与数据专门化冲突;放宽目标、增加容量或使用非均匀目标比减小$u$更直接. 减小$u$只会延迟同一冲突.

恢复后固定探针集比较路由与专家输出. 若路由回稳而loss未恢复,错误token已经更新了不合适专家,需要回滚checkpoint或继续修复训练. 控制状态恢复不保证模型参数自动恢复. 设128专家选8,global batch 2M token,理想每专家12.5万token. 每token隐藏激活14KB,单专家理想接收约1.63GiB/层/step的逻辑激活字节. MaxVio 0.2让热点增加约0.33GiB. 若8个专家位于同节点且同时达到1.2倍,节点额外流量约2.6GiB,远大于单专家数字. 专家负载相关性决定节点峰值,均匀随机放置只能降低预期,不能消除最坏组合. 把热点逻辑专家复制两份可把其物理流量近似减半,显存增加一份权重;把目标负载降到0.8倍会把token转给次优专家. 两种方案分别用硬件和质量支付成本.

这类计算应使用真实dispatch字节、双向all-to-all与网络拓扑修正. 简化数字的作用是说明MaxVio、放置与复制必须联合评估. 偏置冻结前连续观察若干窗口. MaxVio与节点P99应进入稳定区,偏置更新方向翻转率不能持续上升,固定探针的路由Jaccard应接近平台. 只看平均负载达到目标就冻结,可能把周期振荡恰好截在一个偏置极端. 冻结后继续训练一段,检查负载缓慢漂移速度. 若很快越过容量,说明router仍在显著变化,应延后冻结或同步衰减router学习率. 若负载稳定而主loss更平滑,冻结发挥了预期作用. 最终checkpoint需要保存偏置、专家逻辑ID、两级分组方式与路由尺度. 部署实现用同一批探针逐token比对Top-k与混合权重,防止归一化、tie-break或量化顺序差异. 上线回放再按真实领域混合测逻辑专家、物理节点和冗余副本负载. 训练MaxVio只是第一层验收,推理分布与拓扑共同决定最终容量. 若逻辑负载平稳而节点尾延迟仍超标,结论应明确指向放置与通信,避免继续修改已经收敛的模型路由.
