# NSA: 从预训练起就稀疏的注意力

材料是 DeepSeek-AI, 北京大学和华盛顿大学的论文 *Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention* (arXiv 2502.11089, 2025 年 2 月, 25 页), 后来获 ACL 2025 最佳论文, 正式版对部分表格题注做了修改. 论文没有放出训练代码, 下文涉及实现细节的地方对照两个社区实现: [fla-org/native-sparse-attention](https://github.com/fla-org/native-sparse-attention) 和 [XunhaoLai/native-sparse-attention-triton](https://github.com/XunhaoLai/native-sparse-attention-triton). 逐段译文见 [NSA 对照译稿](nsa-bi.md).

NSA 的完整机制推导见 [原生稀疏注意力机制 NSA](../../../llm-guide/2-核心原理与架构/2.4-稀疏注意力/02-原生稀疏注意力机制NSA/02-原生稀疏注意力机制NSA.md), 稀疏注意力各路线总览见 [稀疏注意力](../../../llm-guide/2-核心原理与架构/2.4-稀疏注意力/2.4-稀疏注意力.md). 本文进一步检查三路分支的公式、选择分数来源、GQA 组共享与 kernel 的关系、加速数字口径和实验条件, 并与后续 DeepSeek-V3.2 采用的 DSA 路线比较.

## 1. 问题设定: 理论加速和可训练性两头落空

### 1.1. 已有稀疏方法的两个缺口

论文第 2 节把已有稀疏注意力的问题归成两类. 第一类是推理加速打折扣. H2O 一类 KV cache 驱逐方法只在解码阶段稀疏, MInference 一类只在 prefill 阶段稀疏, 而真实负载两者都有: 书籍摘要, 代码补全以 prefill 为主, 长推理链以解码为主, 只优化一个阶段, 另一阶段仍是全注意力的开销. 另一个更隐蔽的问题出在 GQA 上. Quest 让每个注意力头独立选 KV 块, 在 MHA 模型里计算量和访存量都随之下降; 但 GQA 中同一组的多个查询头共享一份 KV cache, 解码时从 HBM 读出来的是组内各头选择结果的并集, 计算省了, 访存没省多少. 解码恰好是访存受限的阶段, 所以这类方法在 GQA 模型上拿不到预期加速.

第二类是训练. 多数方法只在推理时把一个稠密训练出来的模型改成稀疏, 论文认为这会让模型偏离预训练时的最优轨迹, 并引用了 Chen et al. (2024) 的结论: 稠密模型中注意力最高的 20% 只覆盖约 70% 的注意力质量, 剩下的长尾一旦被丢掉, 误差随层数累积. 想在训练时就用稀疏, 又会遇到两个障碍: ClusterKV 的 k-means 聚类, MagicPIG 的 SimHash 这类离散选择操作没有梯度; HashAttention 这类 token 粒度的选择在反向时要从 KV cache 中做非连续的读取, 用不上 FlashAttention 那种连续块加载, 训练效率反而低于稠密.

### 1.2. 算术强度决定每个阶段该省什么

第 2.2 节用算术强度 (计算量与访存量之比) 区分两个阶段. 训练和 prefill 时, 一批查询同时计算, 矩阵乘法规模大, 算术强度高于 GPU 的计算访存比, 瓶颈在算力; 解码时每步只有一个 token 的查询, 却要读完整个 KV cache, 瓶颈在访存带宽. 稀疏注意力因此要同时满足两个目标: prefill 和训练阶段减少实际执行的 FLOPs, 解码阶段减少从 HBM 读出的 KV 字节数. 前一个目标要求选中的 KV 能以连续块的形式被 Tensor Core 消化, 后一个目标要求同组的查询头读同一批 KV.

这两个目标直接决定了 NSA 的三个选择: 用块而不是单个 token 作为选择单位, 让同一 GQA 组的所有头共享选择结果, 让选择分数直接来自一个本身就要算的分支, 不另设打分网络. 后两节分别看这三点在公式和 kernel 里怎样落地. 论文给出的整体结构见图 2.

## 2. 三路分支, 门控与选择分数

### 2.1. 压缩分支与门控的形式

NSA 把注意力输出写成式 (5): $\mathbf o_t^*=\sum_{c\in\mathcal C}g_t^c\,\mathrm{Attn}(\mathbf q_t,\tilde K_t^c,\tilde V_t^c)$, 其中 $\mathcal C=\{\mathrm{cmp},\mathrm{slc},\mathrm{win}\}$. 门控 $g_t^c\in[0,1]$ 由输入特征经 MLP 加 sigmoid 得到. 三个门控各自独立地过 sigmoid, 没有归一化到和为 1, 所以输出的幅度可以在 0 到三路之和之间变化; 论文没有讨论这一点, 也没有给门控值在训练后的分布. XunhaoLai 的实现把门控写成一个 `Linear(hidden, 3 * num_q_heads)` 加 sigmoid, 每个查询头每个分支一个标量, 与论文描述一致.

压缩分支见式 (7): $\tilde K_t^{\mathrm{cmp}}=\{\varphi(\mathbf k_{id+1:id+l})\mid 0\le i\le\lfloor\frac{t-l}{d}\rfloor\}$. 块长 $l=32$, 步长 $d=16$, 相邻块有一半重叠. $\varphi$ 是带块内位置编码的可学习 MLP, 把 32 个 key 映射成一个压缩 key, value 侧同理. 论文没有给 $\varphi$ 的层数和宽度. 社区实现在这里分歧很大: fla-org 的实现用均值池化, 块长与步长都取 64, 不做重叠; XunhaoLai 的实现提供线性, 均值池化, 加权池化三种压缩, 线性方式是每个 KV 头一个把 $l$ 个 key 拼接后映射回单个 key 维度的矩阵, 块内位置编码只加在 key 上, 压缩之后才对压缩 key 施加 RoPE. 位置 $t$ 的查询能看到的压缩 token 只能是完全位于 $t$ 之前的块, XunhaoLai 的代码用「查询位置 $\ge id+l-1$」作为因果条件.

### 2.2. 选择分支: 分数从压缩分支导出

选择分支是 NSA 的核心. 如果为每个块单独打分, 就要额外算一遍查询与所有块代表向量的点积. NSA 的做法是直接复用压缩分支的注意力分数. 式 (8) 是压缩分支本身的 softmax: $\mathbf p_t^{\mathrm{cmp}}=\mathrm{Softmax}(\mathbf q_t^\top\tilde K_t^{\mathrm{cmp}})$. 选择块长 $l'=64$, 与压缩块 $l=32$ 和步长 $d=16$ 不对齐, 所以式 (9) 把压缩块的分数按空间关系加权汇总到选择块上; 当 $l=l'=d$ 时两者一一对应, 可以直接取 $\mathbf p^{\mathrm{slc}}_t=\mathbf p^{\mathrm{cmp}}_t$.

式 (10) 再在 GQA 组内求和: $\mathbf p_t^{\mathrm{slc}\prime}=\sum_{h=1}^{H}\mathbf p_t^{\mathrm{slc},(h)}$, 组内所有查询头得到同一个块分数向量, 然后按式 (11) 取 top-n, 选中块内的原始 key 和 value 拼起来送进注意力, 即式 (12). 论文设置 $n=16$, 其中固定包含开头 1 块和最近 2 块, 剩下 13 块按分数选出. 这一设计的成本很低: 压缩分支本来就要算 softmax, 选择只多出一个加权求和和一个 top-n. 但它也有一个前提, 就是压缩 key 的注意力分布要能代表块内细粒度 token 的重要性, 论文第 6.2 节用图 8 的注意力图来支持这个前提.

### 2.3. 滑动窗口分支与三路独立的 KV

滑动窗口分支只看最近 $w=512$ 个 token. 论文第 3.3.3 节的理由是: 局部 token 的注意力分数天然较高, 如果和远程分支混在一起, 梯度会集中流向局部模式, 压缩和选择分支学不到远程依赖. 把局部信息单独放到一个分支, 并给三路分支各自独立的 key 和 value, 可以避免三路之间的梯度互相干扰. 这就是三路 KV 不共享的原因, 代价是 KV cache 的写入量变成三份: 压缩 KV, 原始 KV 和窗口 KV. 其中原始 KV 必须保存完整, 选择分支要从中取块; 窗口 KV 只需保留最近 512 个; 压缩 KV 按 $1/d$ 增长.

社区实现在这里也和论文不同. XunhaoLai 的实现用一套共享的 q, k, v 投影, 三路分支从同一份 key 和 value 出发, 压缩分支再经过自己的压缩层. fla-org 的实现同样共享 key 和 value. 论文的消融里没有「三路共享 KV」这一组, 所以独立 KV 带来的收益有多大, 文中没有给出. 第 6.1 节的图 7 比较的只有选择策略.

### 2.4. 式 (9) 的下标与块对齐

式 (9) 写作 $\mathbf p_t^{\mathrm{slc}}[j]=\sum_{m=0}^{\frac{l'}{d}-1}\sum_{n=0}^{\frac{l}{d}-1}\mathbf p_t^{\mathrm{cmp}}\left[\frac{l'}{d}j-m-n\right]$. 代入 $l=32, d=16, l'=64$, 下标取遍 $4j-4$ 到 $4j$, 权重分别是 1, 2, 2, 2, 1. 按式 (7) 的定义, 第 $i$ 个压缩 token 覆盖位置 $16i+1$ 到 $16i+32$; 按式 (12), 第 $j$ 个选择块覆盖 $64j+1$ 到 $64j+64$. 与这个选择块有重叠的压缩 token 是 $i=4j-1$ 到 $4j+3$: $4j$ 到 $4j+2$ 完全落在块内, $4j-1$ 和 $4j+3$ 各有一半在块内. 权重 1, 2, 2, 2, 1 正好对应重叠长度, 但起点应是 $4j-1$, 式 (9) 写成了 $4j-4$, 往前错了 3 个压缩 token, 大半落在第 $j-1$ 个选择块上.

这处差异不影响论文的结论, 但照式 (9) 实现会得到错位一块的选择结果. XunhaoLai 的实现在汇总前把压缩分数左侧补 $l/d-1$ 个零, 再用一个长度 $l'/d+l/d-1$ 的窗口做加权求和, 实际起点是 $4j-1$, 与式 (7)(12) 一致. 文中没有给出式 (9) 采用的编号约定, 能确定的是式 (9) 与式 (7)(12) 的下标定义不统一. 另外, XunhaoLai 的实现在汇总前用 log-sum-exp 在 `no_grad` 下重算压缩分数, 选择分支因此不向压缩分支回传梯度; top-n 本身不可导, 这与论文的设定一致, 选择分支对压缩 key 的影响只经过压缩分支自己的语言模型损失.

## 3. GQA 组内共享与 Triton kernel

### 3.1. 为什么组内共享是 kernel 高效的前提

FlashAttention 的前向把连续的一段查询 (比如 64 或 128 个) 加载进 SRAM, 再沿 key 方向循环, 每次加载一块连续的 key 和 value. 这个循环之所以高效, 是因为同一块查询要看的 key 范围相同 (因果掩码下只差一个三角). 换成 NSA 的选择分支, 相邻位置的查询各自选出 16 个块, 选择结果一般不同. 如果仍按连续查询块加载, 一块查询要用到的 KV 块就是各自选择的并集, 要么把并集都读进来做大量被掩码浪费的计算, 要么逐个查询单独读取, 失去矩阵乘的规模. 论文第 3.4 节说的「queries within a block may require disjoint KV blocks」就是这个问题.

NSA 的办法是换一个维度凑出矩阵乘: 不在序列方向上凑查询, 而在头方向上凑. 同一 GQA 组内的查询头在同一位置看的是同一份 KV, 只要它们的选择也相同, 一次加载的 KV 块就能同时服务组内所有头. 式 (10) 的组内求和正是为此设置的: 它让选择结果在组内一致, 牺牲的是每个头独立挑块的自由. 这与第 1.1 节提到的 Quest 问题是同一件事的两面: Quest 每头独立选择, 在 GQA 下解码访存是并集; NSA 强制组内共享, 访存量就是 $n$ 个块, 不随组内头数增加. 所以组内共享同时服务于两个阶段: 训练和 prefill 时它让 kernel 能以「组内头数 × 块长」的规模做矩阵乘, 解码时它让读出的 KV 字节数与选择数量严格成正比.

这个数据流成立依赖两个条件. 第一个条件是每个程序实例的内层循环长度几乎相同: 每个查询都选 $n$ 个块, 所以循环次数固定, 不同程序之间负载均衡, 论文因此把外层循环直接放进网格. 第二个条件是 $h$ 足够大. 每次矩阵乘的规模是 $[h,d_k]\times[d_k,B_k]$, $h$ 就是 Tensor Core 指令的 M 维. 效率实验里 $g=4$ 个组, 每组 $h=16$ 个头, 正好是 Triton 在 Ampere 上 `tl.dot` 要求的最小 16. fla-org 的实现在入口处直接断言组内头数是 16 的倍数, 组内头数更少时只能补零到 16, 浪费的算力按比例增加. 论文的 27B 模型配置是 64 个头分 4 组, 也是每组 16 个头, 这一配置与 kernel 的要求一致, 但论文没有讨论更小的组 (比如每组 8 个头的常见 GQA 配置) 时 kernel 的表现.

### 3.3. 反向 kernel 与小组规模问题

论文只描述了前向 kernel, 反向的设计一句没有. 反向的难点在 dK 和 dV: 前向是「每个查询找自己的块」, 反向要反过来「每个 KV 块汇总所有选了它的查询的梯度」. 直接按前向的网格做反向, 不同程序会同时写同一个 KV 块的梯度, 需要原子加. fla-org 的实现换成 KV 驻留的做法: 先由块索引构造一个 `block_mask`, 标出每个 KV 块被哪些查询选中, 网格按 KV 块划分, 每个程序遍历选中它的查询累加梯度, 不用原子操作. dQ 则仍按前向的网格计算, 每个查询只写自己的梯度. 于是反向至少要两个 kernel, 外加一次从「查询到块」到「块到查询」的映射构造, 这些都是前向没有的开销.

这一差别能解释论文图 6 里反向加速明显低于前向. 前向 64k 加速 9.0 倍, 基本等于计算量之比 (见 4.1 节); 反向 64k 只有 6.0 倍. 反向需要额外构造反向映射, 而且每个 KV 块被选中的次数不一, KV 驻留的程序之间负载不均. 社区工作 FSA (arXiv 2508.18224) 针对的正是小组规模: 它把选择 kernel 的循环顺序反过来, 外层遍历 KV 块, 内层遍历选中该块的查询, 这样矩阵乘的 M 维由查询个数凑出, 不再依赖组内头数, 报告相对 NSA kernel 最多 3.5 倍, 平均 1.6 倍的 kernel 加速, 端到端训练最多 1.25 倍. 这从侧面说明 NSA kernel 的高效依赖「每组 16 个头」这一配置.

### 4.2. 解码: 表 4 是访存量之比

表 4 列的是解码时每步需要读取的 token 数: 全注意力是 8192, 16384, 32768, 65536; NSA 是 2048, 2560, 3584, 5632; 期望加速 4.0, 6.4, 9.1, 11.6 倍. 这四个 NSA 数字等于 $s/d+nl'+w$, 即每个压缩 token, 选中 token 和窗口 token 都按一个 token 计. 正文写的压缩 token 数是 $\lfloor\frac{s-l}{d}\rfloor$, 按它算会比表里少 2, 差别可以忽略. 需要分清的是, 加速比一行是两个读取量相除, 并没有实际测出解码时延. ACL 正式版把表 4 的题注改成「expected speedup is approximately linear with the volume of memory access」, 口径更明确. 图 1 右侧的「解码 11.6 倍」来自这张表, 而前向 9.0 倍和反向 6.0 倍来自图 6 的计时, 三个数的性质并不相同.

按读取量估计解码加速, 至少有三件事没有反映出来. 一是选择必须串在压缩之后: 每步先对全部压缩 token 算注意力, 再汇总分数做 top-n, 然后才能去读选中块, 64k 下压缩 token 有 4096 个, 这两步是串行的, 读取量相加看不出这层依赖. 二是显存占用不降: 原始 KV 必须完整保存, 压缩 KV 再多出约 $1/16$, 加上独立的窗口 KV, NSA 只省每步读取量, KV cache 的容量反而略增, 能同时服务的长请求数量不会因此增加. 三是解码 batch 较大时, 每个请求的选中块各不相同, 读取的随机性高于全注意力的顺序读. 文中没有给出这三项的大小, 也没有给出任何端到端的解码吞吐或时延.

### 4.3. 基线与硬件的选择

图 6 的基线是 Triton 实现的 FlashAttention-2, 不是官方 CUDA 版. 两者的绝对速度有差距, 用同一编程框架做对比可以排除实现语言的影响, 但读者不能把 9.0 倍理解成相对生产环境里最快的注意力实现. ACL 正式版的局限一节也承认 Triton 带来抽象开销, 用 CUDA 重写可能更快. 硬件是 A100, 没有 Hopper 上的数字; Hopper 上 FlashAttention-3 用了 TMA 和 warp 特化, 全注意力基线更快, NSA 的相对加速会被压缩.

序列长度方面, 加速比随长度单调上升, 因为 NSA 的开销里 $nl'+w=1536$ 是常数, 只有压缩部分随长度线性增长. 由此可以算出盈亏点: 前向在 $T/2$ 约等于 $T/32+1536$ 时打平, 即 $T$ 约 3.3k, 实际 kernel 还有额外开销, 所以 8k 时前向才 2.1 倍. 论文第 4.3 节自己也承认, 通用基准的样本大多短于稀疏方法的局部窗口, 「NSA may not fully leverage its efficiency advantages on shorter sequences」. 对 8k 以下的短上下文场景, NSA 带来的变化主要在模型质量上, 速度收益有限.

## 6. NSA 与 DSA 的取舍

### 6.1. DeepSeek-V3.2 的 DSA 走了另一条路

NSA 之后, DeepSeek 在 V3.2 里上线的稀疏注意力是 DSA, 详见 [DeepSeek-V3.2 解析](../../01-模型技术报告/deepseek-v3-2/deepseek-v3-2-analysis.md). DSA 只有一路: 一个轻量的 lightning indexer 对每个查询和每个历史 token 算一个 ReLU 加权的索引分, 选出 top-2048 个 token, 主注意力在 MLA 的 MQA 模式下只对这 2048 个潜变量做注意力. 它和 NSA 的共同点是选择结果在所有查询头之间共享: NSA 在 GQA 组内共享, DSA 在 MQA 模式下全部 128 个头共享. 两篇论文在「KV 要被多个查询头共用才能跑满硬件」这一点上结论相同.

区别集中在四处. 选择粒度上, NSA 按 64 个 token 的块选, DSA 按单个 token 选, 后者不受块边界影响, 但需要每个 token 都有一个索引分. 打分来源上, NSA 复用压缩分支的 softmax 分数, 打分网络就是模型本身的一个分支, 受语言模型损失直接训练; DSA 的索引器是独立的小网络, 输入被 detach, 只靠与主注意力分布的 KL 散度训练. 训练方式上, NSA 从头预训练, DSA 从 V3.1-Terminus 的稠密检查点出发, 先做 1000 步, 2.1B token 的稠密预热让索引器对齐主注意力, 再用 943.7B token 的稀疏训练适应. 分支结构上, NSA 有三路和门控, DSA 只有一路, 没有压缩分支也没有单独的滑窗.

### 6.2. 为什么生产模型选了 DSA

DSA 的选择可以从第 4 节的分析里找到理由. NSA 的三路独立 KV 增加了 KV cache 的写入量, 解码时选择要串在压缩之后; DSA 只在 MLA 原有的潜变量 cache 上加一个很小的索引键, cache 结构几乎不变, 可以在已有的 V3 系列检查点上继续训练, 不必从头预训练一个新架构. 对一个已经有成熟稠密模型的团队, 后一条的成本差距最大. 另一方面, DSA 的索引器仍是 $O(L^2)$, 只是常数比主注意力小一个数量级, prefill 曲线仍有明显斜率; NSA 的压缩分支也是 $O(L^2/d)$, 两者在 prefill 上都没有摆脱平方项.

后续的 V4 又把两条路线合在了一起. V4 的 CSA 先沿序列维把每 4 个 token 的 KV 压成一条, 再用 DSA 式的索引器在压缩条目上选 top-k, 另有 HCA 用 128 倍压缩做稠密注意力, 详见 [DeepSeek-V4 解析](../../01-模型技术报告/deepseek-v4/deepseek-v4-analysis.md). 压缩加选择的两级结构来自 NSA, 独立索引器和 MQA 共享来自 DSA. 社区的讨论里也有一种看法认为 NSA 的质量收益更多来自门控而不是稀疏本身, 这个问题论文没有做对应的消融 (比如「全注意力加三路门控」), 文中的数据无法区分两者.

## 7. 三分支的统一数学形式

对查询$q_t$,NSA输出

$$
o_t=g_t^c o_t^c+g_t^s o_t^s+g_t^w o_t^w,
$$

其中$c,s,w$分别表示压缩、选择与滑窗分支,$g_t=\operatorname{softmax}(W_gh_t)$保证三路权重非负且和为1. 每一路使用独立的$K,V$投影,因此门控混合的是三个不同表示子空间.

压缩分支把长度$L$的历史按步长$d$聚成约$L/d$个块表示. 对第$j$块

$$
\tilde k_j=\sum_{r=0}^{l-1}a_r k_{jd+r},\qquad \tilde v_j=\sum_{r=0}^{l-1}b_r v_{jd+r},
$$

$a_r,b_r$由可学习压缩器产生,窗口$l$可大于步长$d$形成重叠. 查询对$\tilde k_j$做稠密注意力,得到全局低分辨率视图.

选择分支把压缩注意力质量聚合为原始块重要性,选$n$个块,再对块内$l'$个原始token做精细注意力. 滑窗分支读取最近$w$个token,保证局部连续性与新近信息.

## 8. 压缩并非简单池化

均值池化保留低频趋势,会抹掉块内稀有token. 可学习压缩根据内容分配权重,仍受单个向量容量限制. 若一个块同时包含两条互相独立的事实,一个压缩key难以让所有查询都准确寻址.

压缩误差可写为原始块输出与摘要输出之差. 对块$B_j$,原始注意力贡献

$$
u_j(q)=\sum_{i\in B_j}\alpha_i(q)v_i,
$$

摘要近似为$\tilde\alpha_j(q)\tilde v_j$. 若块内value方差大、查询相关权重尖锐,单摘要误差上升. 重叠窗口让边界token进入多个摘要,降低硬切分损失,增加压缩计算.

摘要承担两项职责:向压缩分支提供近似value,同时给选择分支提供块分数. 对前者需要内容可重建,对后者需要相关性可排序,两项目标可能冲突. 语言模型损失通过两路共同训练压缩器,没有显式分离.

## 9. 选择分数为何能获得训练信号

选择Top-n是离散操作,集合外块无法从选择分支得到直接梯度. NSA复用压缩分支的注意力分数,压缩分支本身对全部摘要做可微softmax,每个块都从语言模型loss获得梯度.

设压缩logit$z_j=q^T\tilde k_j$,概率$p_j=\exp z_j/\sum_r\exp z_r$. 选块分数由覆盖该原始块的$p_j$聚合. 即使块未入Top-n,$p_j$仍影响$o^c$,梯度为

$$
\frac{\partial L}{\partial z_j}=p_j\left\langle\frac{\partial L}{\partial o^c},\tilde v_j-o^c\right\rangle.
$$

这条梯度让压缩注意力学习语言建模相关性,避免单独定义检索标签. 假设是“适合低分辨率全局注意的块,也适合高分辨率精读”. 当摘要丢失关键细节时,该假设会失败.

## 10. Top-n 的近似误差

令全注意力输出$o=\sum_i\alpha_iv_i$,选中集合$S$的归一化稀疏输出$o_S=\sum_{i\in S}\alpha_iv_i/(1-\delta)$,$\delta=\sum_{i\notin S}\alpha_i$. 若$\|v_i\|\le V$,则

$$
\|o-o_S\|\le2V\delta.
$$

因此关键是候选外注意力质量,不是漏掉多少token. 一个权重0.2的关键token比漏掉一千个微小权重token更严重.

NSA按块选择. 只要块内一个token重要,整个块$l'$个token都进入精读,召回高而精度低. 预算$n l'$固定时,块越大越浪费;块越小选择索引与随机访问更多.

压缩分支与滑窗分支为漏选提供旁路. 远程块没进$S$时仍可能通过摘要影响输出,近程token由窗口覆盖. 三路门控能根据query降低选择误差的影响.

## 11. 门控的作用

门控可视为query相关的混合专家. 局部语法query提高$g^w$,全局主题提高$g^c$,精确远程引用提高$g^s$. 这种解释需由实测门控分布支持,仅凭结构无法保证.

门控若塌缩到一路,其他分支训练信号减弱. 设$g^c\approx0$,压缩器虽可能仍参与选块,其value路径梯度很小;若$g^s\approx0$,Top-n质量无法从选择输出体现. 可监控门控熵与各路梯度范数.

三路输出尺度不同会影响门控. 若某路向量范数更大,门控可能偏向它而非信息更好. 独立归一化、温度或输出norm能控制,论文结构应结合具体实现解读.

缺少“全注意力加三路门控”消融时,短任务上的收益无法完全归给稀疏. 门控提供额外参数和多尺度归纳偏置,本身可能改善质量.

## 12. GQA 组内共享

GQA一组查询头共享KV头. 若每个查询头独立选块,同组最终需要读取各头集合并集,稀疏度随头数迅速下降. 组内共享集合让一次KV加载服务多个头,提高算术强度.

设组内$h$个头,每头独立选$n$块,随机重叠很低时并集接近$hn$;共享只读$n$块,带宽最多降$h$倍. 代价是不同头的偏好被聚合,专门化头可能失去最佳候选.

可将组分数取和、最大或加权和. 求和偏好多个头共同相关的块,最大保留任一头强信号,更易被异常头主导. NSA的具体聚合决定质量—带宽权衡.

共享粒度越大,kernel越高效,选择自由度越小. DSA在MQA模式下全头共享,走到更激进端点;两者差异不能只看Top-k数.

## 13. 复杂度

全注意力prefill的score与value计算为$O(L^2d_h)$. NSA压缩分支约$O(L^2d_h/d)$,选择分支每query读$n l'$个token为$O(Lnl'd_h)$,滑窗为$O(Lwd_h)$.

总主项

$$
O\left(d_h\left(\frac{L^2}{d}+Lnl'+Lw\right)\right).
$$

只要$d$固定,仍有平方项,渐近复杂度不是线性. 相对全注意力平方系数缩小$d$倍,长序列仍显著加速.

解码每步压缩摘要数量约$L/d$,另读$nl'+w$原token,复杂度$O((L/d+nl'+w)d_h)$. KV写入还包含三路独立投影,不能只按读取token数估容量.

## 14. 算术强度

GPU效率由FLOPs/读取字节决定. 每个选中KV块被同组多个query头复用,矩阵块足够大时Tensor Core利用率高. token级随机选择会形成碎片访存.

压缩分支是规则稠密矩阵,适合高吞吐kernel;选择分支不规则,通过固定块长把gather转成块矩阵乘. 滑窗同样规则.

块数$n$太小,每个kernel工作不足,启动与索引开销占比高;太大则稀疏收益下降. 硬件最优点与模型质量共同决定配置.

论文A100 Triton结果说明设计可实现,不能直接外推Hopper或不同head维. FlashAttention基线和稀疏kernel都会随硬件演进.

## 15. KV cache 容量

三路独立KV意味着每token需要压缩输入投影、选择KV与窗口KV相关状态. 压缩摘要每$d$步产生,原始分支仍保存历史token供未来选块.

设选择KV每token字节$b_s$,窗口KV$b_w$,压缩摘要$b_c$,长度$L$,单层容量近似

$$
M=L(b_s+b_w)+\frac{L}{d}b_c.
$$

若选择与窗口无法共享投影,容量可能高于普通GQA. 论文强调计算效率,部署还需看cache字节与写带宽.

仅保存最近窗口KV无法支持远程选块,选择分支的原始KV必须长期驻留或分层到主机/SSD. 解码随机读取远端块会增加地址与分页管理.

## 16. 长上下文训练

原生稀疏训练让模型从预训练起适应信息瓶颈. 推理时才剪枝的稠密模型没有学会把关键信息写入可检索摘要,因此同预算基线较弱.

训练长度8K再扩32K,只证明该课程下可收敛. 64K needle外推成功说明单一显眼证据可定位,多证据与相似干扰更困难.

长度增长时压缩候选数$L/d$增加,负例最大分数随极值统计上升. 正例分数不变也会被更多偶然高分块挤出Top-n. 长度课程需同时校准选择margin.

若负例分布$F_-$,最大负例$M_N$满足$P(M_N\le x)=F_-(x)^N$. $N$扩大使右尾上移,这是长度外推的检索难点.

## 17. 多证据容量

回答需要$r$处分散证据,单证据召回率$u$,独立近似下全覆盖$u^r$. $u=0.95,r=8$时只有66.3%. 平均单针高分不能代表多跳推理.

固定$n$限制可同时精读的块数. 若证据超过$n$,选择分支无法一次覆盖,压缩分支可能保留粗信息,多层网络也可分步检索.

应评测证据数、距离、块边界与干扰相似度四轴. 只随机放一根needle主要测位置编码与显著性.

跨层候选可以变化. 前层找到部分证据改变query,后层再找其余证据. 单层recall低不必然导致答案错,需要跟踪证据跨层可见轨迹.

## 18. 块边界

关键短语跨两个块时,任一摘要只看到一部分,相关分数下降. 压缩重叠与选择块扩展能缓解,增加冗余读取.

固定语义段落与固定token边界不对齐. 内容自适应分块可能提高质量,产生变长块和不规则kernel. NSA选择固定块体现硬件优先.

边界实验可平移同一证据相对块起点,画召回周期曲线. 若每$l'$token出现低谷,说明块切分泄漏明显.

局部窗口与选中块重叠时应去重. 不去重浪费预算,去重后每query实际token数变化,kernel形状更复杂.

## 19. 训练梯度细节

Top-n索引本身无梯度,选中块内部attention可训练选择KV投影. 集合变化发生在分数越过边界时,loss对分数呈分段结构.

压缩分支提供平滑替代,但优化目标未直接最大化Top-n召回. 可加入教师全注意力KL或候选覆盖辅助损失,论文消融中独立辅助方法效果较弱,不代表所有蒸馏目标无效.

门控给三路分配梯度. 若某一路早期稍优,正反馈可能让它占据更多门控,其他路欠训练. 初始化和负载正则会影响最终分工.

压缩器与选择共享分数形成多任务梯度:摘要value质量与排名质量可能方向冲突. 记录两路梯度余弦可以验证.

## 20. 稳定性

softmax分数在长序列可能尖锐,Top-n边界对小扰动敏感. 分数第$n$与$n+1$名间隔$m$是集合稳定指标. $m$小的query在量化或不同kernel下容易换块.

候选切换并不必然导致输出跳变,两个块内容可能冗余. 可同时测集合Jaccard与输出差异,区分索引不稳和功能不稳.

训练混合精度、解码KV量化都会扰动分数. 在margin分桶下测召回,比平均准确更能预测量化风险.

## 21. 反例

反例一是块内稀有事实. 摘要由大量普通token主导,关键数字无法提高块分数,选择漏掉. 增加显著干扰块会进一步挤出.

反例二是大量近重复版本. query要找最新或某一日期,压缩摘要相似,Top-n选错版本. token级索引更有优势.

反例三是全局均匀依赖,例如统计整篇某模式次数. 固定$n$精读无法覆盖全部,压缩分支必须承担统计,摘要容量可能不足.

反例四是局部精确复制跨窗口边界. 滑窗漏掉,块摘要模糊,选择分数又不强. 边界平移实验能复现.

反例五是短序列. 所有分支开销与门控参数存在,全注意力本来便宜,稀疏kernel未到盈亏点.

## 22. NSA 与全注意力的公平比较

两模型结构参数量不同,NSA有三套投影、压缩器与门控. 短任务提升可能来自参数与归纳偏置. 公平消融应给全注意力增加相近参数或多尺度分支.

训练token、batch、优化器与长上下文课程需一致. kernel速度比较则保持head维、dtype、框架与编译设置一致.

质量比较多随机种子. 0.01量级基准差异可能落在训练方差. 预训练loss曲线需给置信或至少重复末端评测.

推理时稀疏基线预算应按实际读取字节与FLOPs匹配,不能把一个压缩token简单等同一个原token而忽略摘要生成.

## 23. NSA 与 DSA 的统一视角

两者都先估计相关性再限制主attention. NSA相关性来自低分辨率attention,DSA来自独立indexer. 前者梯度天然、附带全局摘要;后者选择粒度细、架构简单.

NSA候选单位为块,DSA为token. 块选择提高硬件复用,token选择提高精度. V4 CSA先压缩再索引,在两者之间取组合.

NSA压缩扫描$L/d$摘要,DSA扫描$L$轻量key. 哪个更快取决于维度、压缩率、kernel与内存,不能只比较渐近符号.

已有稠密checkpoint更适合DSA式适配;从头预训练可以让NSA多分支共同形成表示. 生产选择包含迁移成本,不等于论文架构质量排序.

## 24. 可证伪实验

实验一固定实际KV读取字节,扫描块长与块数. 若块复用是关键,中等块长应在质量—吞吐前沿优于token随机选择.

实验二对同一证据做块内位置平移,测选择召回与答案. 周期低谷验证边界效应,增加重叠后应减弱.

实验三构造1、2、4、8处证据,报告单证据recall、全覆盖与答案准确. 若答案下降快于覆盖,模型组合能力也有限.

实验四冻结门控为等权、只开单路、全注意力加门控. 这能分离稀疏、三路表示和动态混合的贡献.

实验五用oracle块替换选择结果. NSA与oracle差距是检索损失,oracle与全注意力差距是固定预算与块结构损失.

实验六分别停止压缩value梯度与选择分数梯度,测共享训练是否必要. 再比较独立indexer与压缩分数.

实验七在8K训练后直接测32K、64K、128K,按负例数报告margin与recall,验证极值外推.

实验八加入量化噪声,按margin分桶测集合变化与输出误差,判断部署精度要求.

## 25. 复杂度手算

取$L=32768,d=32,nl'=1024,w=512$. 每query等效注意条目约$1024+1024+512=2560$,是全注意力的7.8%. 该比例只代表score/value条目,三路投影与选择开销另计.

$L=8192$时压缩256条,总1792,比例21.9%;短序列优势明显缩小. $L=4096$时1664,已达40.6%,额外kernel开销可能抹平收益.

若每块64token,$n=16$得到1024直选token. 多证据分布在17个块时,至少一块无法进入选择分支,只能依赖摘要.

## 26. 证据边界

论文直接支持从头训练可收敛、27B实验质量、A100 Triton速度、32K LongBench与64K单针. 它没有证明Hopper生产速度、多证据极限、KV总容量或门控独立贡献.

DSA与V4关系来自后续官方报告,可以比较机制,不能把后续配置视为NSA消融. 社区kernel结果也需注明硬件与实现.

数学误差界、极值分析与反例属于机制推导,用于设计验证,不应写成论文实测结论.

## 27. 最终判断

NSA的核心是三层保险:压缩分支保持低分辨率全局视野,选择分支恢复少量高分辨率远程内容,滑窗守住局部连续性. 门控按query混合三种尺度.

它的可训练性来自压缩attention为全部块提供连续梯度,选择直接复用该分数. 硬件效率来自块选择与GQA组内共享,让稀疏读取仍形成可复用矩阵块.

代价是三路投影、KV容量、块边界和仍然存在的平方压缩项. 长度越长计算优势越大,选择极值与多证据覆盖也越难.

最值得保留的思想是“全局摘要负责可微定位,局部精读负责细节”. 后续DSA与CSA改变索引器和粒度,仍围绕如何让相关性估计、KV布局与硬件复用同时成立.

## 28. 压缩窗口的频率响应

把压缩器局部线性化为滤波器$a_r$,其频率响应$H(\omega)=\sum_ra_re^{-i\omega r}$. 平滑权重偏低通,能保留主题与慢变化,削弱交替符号、精确位置和高频细节.

语言中的数字、括号匹配、代码标识符可能是高频信号. 选择分支若依赖同一摘要打分,高频信息既无法进入压缩value,也可能无法触发精读,形成双重损失.

多通道摘要可让不同通道学习不同频带,摘要数与KV增加. NSA每压缩块的表示维度固定,是否形成多频分工需分析权重或探针.

构造块内交替pattern、低频主题与单点脉冲三类信号,比较摘要重建与选块召回,可以验证频率解释.

## 29. 重叠压缩的代价

窗口$l$大于步长$d$时,每个token进入约$l/d$个摘要. 边界信息更平滑,压缩计算与写入放大同样乘该比例.

相邻摘要高度相关,有效候选数低于$L/d$. softmax质量会分散到覆盖同一事实的多个摘要,聚合回原始块时需要避免重复或正确相加.

重叠还改变因果边界. 自回归位置$t$的摘要只能使用$t$之前token,靠近当前端的窗口不完整. kernel需处理尾部,训练长度变化会改变不完整窗口比例.

扫描$l/d$从1到4,同时测边界召回、摘要相关、FLOPs与吞吐,能找出重叠的真实收益.

## 30. 因果掩码

压缩token代表一段历史,其时间位置应保证不会包含query未来信息. 对query$t$,只允许窗口末端不超过$t$. 重叠窗口使可用摘要数量随$t$阶梯增长.

选择分支取出的原始块也必须裁剪当前块内未来token. 滑窗分支采用标准因果mask. 三路mask若边界不一致,训练可能泄漏.

单元测试可令未来token携带唯一答案,逐位置检查输出是否变化. 仅验证最终loss不足以发现少量mask偏移.

## 31. 位置编码

压缩摘要需要一个代表位置. 取窗口末端、中心或学习位置会改变相对距离. RoPE下聚合已经旋转的key与先聚合再旋转不等价.

若先对token应用RoPE再线性压缩,不同位置相位混合,高频维可能抵消. 若摘要在统一位置旋转,丢失块内相对位置. NSA实现的顺序决定表示能力.

选择分支读取原始KV,保留精确位置;压缩分支主要承担粗全局信息,可容忍位置模糊. 对需要远程精确顺序的任务,必须成功选块.

YaRN扩展到32K改变旋转尺度,摘要分数也会变化. 长度外推测试应分离位置编码与稀疏选择失败.

## 32. 压缩与信息瓶颈

每$d$个token压为一个固定维向量,通道容量不会随块内信息量增加. 从信息论看,若任务需要恢复的变量熵超过摘要容量,无损压缩不可能.

NSA无需恢复全部token,只需保留对未来query有用的信息. 训练分布决定“有用”的定义,罕见未来任务可能被丢弃. 这解释为何长尾检索比平均语言建模loss更脆弱.

选择分支相当于外部细节存储,摘要只需提供地址线索. 理想摘要保存“块里有什么”,原始KV保存“具体内容”. 一个向量同时做内容近似与地址索引会共享容量.

## 33. Query 依赖的预算

论文使用固定$n$与$w$. 实际query难度不同:局部续写只需窗口,多跳检索需要更多块. 固定预算在容易query上浪费,困难query不足.

可根据压缩分数熵或Top-n累计质量动态选择$n_t$. 当累计概率超过阈值停止,分布尖锐时少选,平坦时多选.

动态$n$破坏固定kernel形状,可量化到几个bucket并批处理. 质量收益需抵消调度与padding开销.

预算控制还可由门控决定:$g^s$高时扩大$n$,低时缩小. 需要防止门控因训练偏差在真正困难query上低估选择需求.

## 34. Oracle 分解

用全注意力权重选择质量最高的$n$块,得到oracle selector. 用oracle集合配NSA value,可测压缩打分损失;用学习集合配原始全注意力权重,测集合损失.

进一步把压缩分支替换为无损块统计,测摘要value误差. 三组差值分别对应摘要表示、候选选择与固定预算.

oracle依赖全注意力,只用于分析. 若学习selector接近oracle而模型仍落后,继续改索引器意义小,应增加预算或改多分支融合.

## 35. 与局部注意力的关系

仅滑窗注意力复杂度$O(Lw)$,局部建模强,跨窗信息需层层传播. $H$层最多通过残差逐步扩大感受野,精确信息经过多次变换会衰减.

NSA选择分支提供跨越任意距离的直接边,压缩分支提供全局低分辨率连接. 图结构上,滑窗形成链,选块增加稀疏长边,摘要形成到块代表的二部连接.

连通不等于可用. 每层虽能接触全局摘要,摘要信息瓶颈仍在. 图直径小只能说明路径短.

## 36. 层间分工

早层可能依赖局部词法,后层需要远程语义. 使用所有层同一$n,w,d$简化实现,未必最优. 门控可部分适应,资源仍固定分配.

逐层测平均$g^c,g^s,g^w$、选块距离与熵,能观察分工. 若早层选择门控接近零,其选择kernel可能可以省去.

层级预算在总FLOPs固定下重新分配:早层大窗口小选择,后层多选择. 这会改变训练和kernel调度,属于可验证扩展.

## 37. Head 间冲突

同一GQA组的查询头可能分别关注实体、位置、语法与代码结构. 共享块集合时,聚合分数偏向多数头,少数专门化头召回下降.

定义每头oracle集合$S_h$,共享集合$S$,测$|S_h\cap S|/|S_h|$. 按头功能分桶可识别受损类型.

可给少数头保留私有块,其余共享. 带宽为共享$n_s$加私有集合并集,介于两端. kernel复杂度增加.

头分组应按相关性而非固定GQA物理组,但重新分组会改变KV共享结构. NSA选择硬件现有组是一种系统约束.

## 38. Value 误差与路由误差交互

候选正确但value投影表达差会答错;摘要表示差还会先让候选错误. 两种误差通过共享压缩器耦合.

四臂实验可拆解:A完整NSA,B用oracle块,C在B上换全注意力value,D全注意力. $L_A-L_B$近似选择损失,$L_B-L_C$近似稀疏value与预算损失,$L_C-L_D$是结构差.

交换恢复顺序可估交互. 若先修value后选择收益不同,两类误差不可加.

## 39. Soft selection 训练

训练时可对所有块使用soft权重,推理Top-n,梯度充分但有train-test gap. NSA压缩分支已经提供soft路径,选择value仍是hard集合.

Gumbel-Top-k或straight-through可近似离散梯度,方差与偏差较大. 论文选择复用压缩分数,实现更稳定.

anneal策略从大$n$逐步减到目标预算,让早期更多块获梯度. 最终质量是否提高需对照固定$n$,也会增加训练计算.

## 40. 负例训练

相似干扰块比随机块更能训练选择边界. 普通语言模型数据中困难负例自然出现频率未知. 可构造实体相同、数值不同、版本不同的上下文.

显式排序损失$\max(0,m-z^++z^-)$能扩大margin,需要知道正块. 通过答案引用、合成needle或全注意力教师获得伪标签.

辅助损失可能与语言模型目标冲突. 权重过高让摘要只适合检索,压缩value质量下降. 应测两路梯度余弦.

## 41. 长度课程的统计变化

从8K到32K,每query负例摘要数增4倍,固定Top-n召回压力增大. batch token固定时,序列数降4倍,独立样本减少.

学习率与batch策略若不调整,长度阶段的梯度噪声变化. 质量提升不能只归给长上下文数据,训练统计也改变.

位置分布应覆盖证据靠前、中、后. 若长阶段总从短文拼接,跨文档边界可能让选择学到格式捷径.

## 42. 推理分页

选择块在历史KV页中离散分布. PagedAttention可按页映射,块长若与页大小对齐,gather简单;不对齐会读多页与碎片.

固定块ID到物理页映射需要处理prefix sharing. 多请求共享前缀时,选同一块可复用缓存,批内query选择不同块则难合并.

NSA论文kernel主要验证计算核,完整服务还包含调度、页表、KV写入和batch动态. kernel倍数不等于端到端倍数.

## 43. Prefill 与 decode 的不同瓶颈

prefill包含大量query,矩阵计算占主导,压缩的平方项仍重要. decode每步一个query,KV读取带宽主导,选择索引与随机gather比例更高.

同一配置可能prefill最优而decode非最优. 增大块长提高decode顺序读取,也增加无关token;减小块长提高选择精度,metadata更多.

应分别报告TTFT、TPOT、吞吐、HBM字节和kernel时间. 论文训练与解码数字口径不同,不能直接相加.

## 44. 量化

KV量化误差改变压缩摘要、选择分数与最终value. 分数排序对误差敏感,尤其margin小的query. 主attention输出误差则连续累积.

Indexer key可用更高精度、value低精度,在字节与召回间折中. NSA压缩分数由attention key产生,分离精度需额外布局.

按margin分桶注入FP8/INT8/INT4量化,测集合Jaccard、候选外质量与任务分数,能确定最低安全精度.

## 45. RoPE 外推与选择

长距离RoPE相位变化影响压缩logit排序. 即使value表示足够,远程块分数可能系统性衰减,selection出现位置偏差.

按相同内容放在不同距离测分数,理想selector只在任务需要位置时变化. 若无关距离导致召回下降,应校准位置编码或分数.

YaRN修正全模型频率,压缩摘要代表位置仍需一致处理. 训练32K测64K满分单针是积极证据,多样内容和距离仍需覆盖.

## 46. 数据类型差异

代码有长程标识符与括号依赖,块内局部结构强,选择远程定义重要.NSA在LCC提升符合这一特性,单项结果不足以归因.

报告摘要需要跨段主题整合,压缩分支有利,精确事实又依赖选择. GovRpt低于全注意力提示摘要容量或训练差异.

多语言token密度不同,同一64-token块对应字符长度不同. 中文块覆盖语义更长或更短取决于tokenizer,固定块预算跨语言不公平.

数学推理生成中近期推导适合窗口,早期条件需选择. 错误中间步骤也会被检索并强化,稀疏结构不保证推理正确.

## 47. 训练损失更低的解释

NSA预训练loss略低于全注意力可能来自多尺度归纳偏置、额外参数、正则效应或随机波动. 稀疏本身也能抑制无关token干扰.

要区分,需全注意力加相同参数、多分支但不稀疏、固定随机稀疏和NSA四组. 单次曲线无法完成因果归因.

训练loss低不保证长任务好,因为平均token预测由局部模式主导. 专门的远程依赖loss或合成数据更敏感.

## 48. 统计显著性

AIME 30题、16采样产生480回答,同一道题的样本相关,有效单位更接近30题. 不能把480当独立样本计算极小误差.

可对题目bootstrap,每次保留题内16次平均,得到准确率差区间. LongBench也应按样本bootstrap,多子集平均需说明权重.

预训练只跑一个seed时,微小通用榜差异应谨慎. 大模型重复昂贵,至少可对checkpoint邻域与下游评测做bootstrap.

## 49. 安全边界

稀疏选择可能漏掉上下文中的安全指令或否定条件,模型只看到诱导内容. 将关键系统约束固定放入窗口或始终可见区能降低风险.

攻击者可填充大量相似块,挤出真正指令,属于selection flooding. 固定保留系统prompt与高优先级块,不要完全依赖内容分数.

压缩摘要可能把恶意指令混进看似普通主题,精读未选中却仍通过压缩分支影响. 安全评测需同时检查漏读与摘要污染.

## 50. 与外部检索的区别

NSA在模型内部对已进入上下文的KV做选择,候选范围固定为prompt历史. 外部RAG从语料库找文档,可扩展知识范围,也有独立索引误差.

两者可串联:RAG缩小语料,NSA管理长prompt. 外部检索成功不能证明NSA无损,内部选择成功也不解决语料缺失.

摘要分数类似学习检索,但每层query与表示变化,比一次性向量检索更动态. 成本也在每层重复.

## 51. 更严格的消融表

结构行应含全注意力、窗口、压缩+窗口、选择+窗口、三路等权、三路门控. 这能定位各分支边际贡献.

选择行应含随机、Quest、辅助indexer、压缩分数、oracle. 固定真实读取token和块尺寸.

系统行扫描GQA共享粒度、块长、n、w与压缩步长,报告质量、FLOPs、HBM字节、TTFT和TPOT.

训练行比较从头稀疏、稠密转稀疏、长度课程和蒸馏. 不同路线解决不同部署约束.

## 52. 复现检查

核对压缩窗口$l$、步长$d$、选择块$l'$、块数$n$、窗口$w$及因果对齐. 一个off-by-one会导致未来泄漏或预算差异.

随机小张量上用PyTorch稠密参考实现比对Triton前向与反向. 分别检查三路输出、门控、分数聚合和Top-n索引.

用有限差分验证可微路径,Top-n边界处避开分数相等. 冻结集合后选择分支内部梯度应与参考一致.

性能测试预热、固定频率、报告shape与dtype. 同一Triton框架比较可控,仍需注明非生产CUDA基线.

## 53. 一组容量例子

假设32层、每token选择KV 512字节、窗口独立KV 256字节、压缩摘要512字节,$d=32,L=32768$. 单层约$32768\times768+1024\times512\approx24.5$MiB,全模型约784MiB/请求.

若普通共享KV每token512字节,全模型约512MiB. 此假设下NSA cache高约53%,计算下降没有自动带来容量下降. 实际维度需按论文投影替换.

batch 32时差额约8.5GiB,足以影响并发. 若窗口KV可与选择共享,容量显著下降,实现细节十分关键.

## 54. 一个检索手算

候选摘要2048个,正块分数3.0,负例分数标准正态. 负例最大值典型约$\sqrt{2\log2048}\approx3.9$,正块容易被极端负例超过. Top-16阈值较低,仍需足够margin.

长度扩大4倍,极值约$\sqrt{2\log8192}\approx4.24$,只增加0.34却可能跨过正例. 困难负例训练要提升分数分离,不能只保持短长度排序.

若正块因边界压缩损失0.5,从3.0降2.5,召回进一步恶化. 长度与压缩误差会共同作用.

## 55. 最小结论

NSA的质量依赖摘要能定位、块内精读能恢复、窗口能覆盖局部、门控能按query选择尺度. 四个条件分别有可测指标.

其速度依赖规则压缩、固定块、组内共享和足够长序列. 理论稀疏比例只有在kernel与KV布局兑现后才成为端到端收益.

论文给出了从头训练与A100实现的强证据,生产迁移、缓存容量、复杂多证据和独立门控贡献仍需额外实验.

## 56. 压缩摘要的可逆性探针

冻结模型后,用线性probe从摘要预测块内token属性:实体、数字、位置、词袋与局部顺序. probe准确率衡量摘要保留了什么,不会直接等于下游能力.

再用query条件probe预测某个事实是否在块中,更贴近选择用途. 若无条件重建差但条件检索好,摘要成功充当索引而非存档.

逐层比较可看早层摘要偏表面、后层偏语义. 训练长度变化后probe下降可提示外推损失.

## 57. 候选覆盖与最终答案

给每个任务标注证据token,计算每层选中块覆盖率$R_l$. 最终答案正确率按$\min_lR_l$、平均覆盖与关键层覆盖分桶,能定位哪些层最重要.

证据进入压缩摘要但未进入选择时,仍可能答对. 因此还需屏蔽压缩分支做反事实,区分摘要旁路与精读贡献.

答案错且证据覆盖高,问题在组合或生成;答案对但覆盖低,可能依赖参数记忆或数据泄漏. 只报告答案无法验证检索机制.

## 58. 选择分数的校准

把块是否含证据视为二元标签,按分数分桶测precision与recall. softmax概率是相对质量,候选数变化后绝对值漂移,跨长度不能直接比较.

温度缩放可校准固定长度,长度变化还需加入$\log N$修正或按rank评估. Top-n只关心排序,动态预算需要累计概率可信.

分数校准差时,用entropy决定$n$会误判. 应先在不同长度与任务上验证coverage-risk曲线.

## 59. 选择集合的多样性

Top-n可能选中多个近重复块,浪费预算. 在分数之外加入内容去重或最大边际相关性,能覆盖更多主题.

设相似度$sim(B_i,B_j)$,贪心目标$r_i-\lambda\max_{j\in S}sim(i,j)$. $\lambda$过大可能排除重复但必要的版本比较.

多证据任务上多样选择应提高全覆盖,单一needle上收益小. 额外相似度计算也影响kernel效率.

## 60. 块内注意力预算

选择$n$块后通常读取每块全部$l'$token. 可在块内再做token筛选,形成两级稀疏,进一步省带宽,增加索引与随机访问.

块内注意力权重往往只集中少数token,理论有压缩空间. 但整块加载已经完成,计算省下而HBM字节未必省,硬件收益有限.

V4 CSA先压条目再索引体现另一种两级结构,减少候选数据宽度. NSA保持原token精读,质量更直接.

## 61. 门控熵正则

给门控加入$-\lambda H(g_t)$可鼓励多路使用,防塌缩;加入$+\lambda H$则鼓励单路决策,推理可跳过低权重分支. 两种目标不同.

NSA实际若始终计算三路,稀疏门控不会省计算. 让门控控制执行需提前决定分支,门控自身只看当前隐藏状态,可能错误跳过远程检索.

门控权重与分支输出贡献可用梯度×输入或分支消融验证. 权重大不一定代表因果贡献大,分支输出可能相互抵消.

## 62. 分支冗余

最近窗口token也落入选择块,压缩摘要也覆盖它们,三路信息重叠. 冗余提高鲁棒,减少有效信息预算.

测三路输出CKA或余弦,以及移除一路后的loss. 高相似且移除无损说明可简化;相似但移除有损可能是尺度或优化依赖.

训练中随机drop branch可促使各路独立承担功能,推理更鲁棒,也可能损害协同.

## 63. 短序列退化路径

当$L\le w$,滑窗已覆盖全部历史,选择与压缩在信息上冗余. 理想实现可退化为全注意力或只用窗口,避免三路开销.

动态切换会让训练与推理路径不同. 训练中应包含短序列退化,或在部署接受小幅数值差异.

通用benchmark多为短输入,若仍启用三路,结果反映结构而非稀疏效率. 论文对此已有提醒.

## 64. 跨文档上下文

长上下文常由多文档拼接. 文档边界提供天然块先验,固定token块可能把两个文档混在同一摘要. 对齐文档能提高语义纯度,产生变长块.

位置与来源元数据可加入压缩key,帮助query区分文档. 这改变模型输入结构,不属于原NSA配置.

评测应包含同主题多文档、互相矛盾版本与来源优先级,比随机needle更接近RAG场景.

## 65. 流式输入

压缩摘要可随新token增量生成,每$d$步封闭一个窗口. 重叠窗口需保留最近$l-d$个token状态.

选择分支原始KV持续增长,内存仍线性. 若把旧KV卸载,query选中后需要异步取回,延迟可能高于attention计算.

滑窗KV可环形buffer,压缩摘要常驻,选择KV分层. 三类生命周期不同,天然适合分级存储,论文未展开系统设计.

## 66. 训练通信

序列并行下,压缩窗口跨rank边界需要交换halo token. 选择块可能位于远端rank,需all-to-all或复制KV. kernel单卡速度不包含这些通信.

按序列块分片时,每queryTop-n位置分布不均,某rank成为热点. 组内共享减少请求数,无法保证目标均衡.

可先按rank聚合块请求再批量传输,通信字节与候选远程比例相关. 长上下文训练端到端扩展需单独测.

## 67. MoE 交互

论文模型同时使用DeepSeekMoE. 稀疏attention改变隐藏表示,可能改变专家路由与负载;性能差异包含attention—MoE交互.

三路门控与专家router都是输入相关离散/软选择,可能共同形成专门化. 测NSA与全注意力的专家负载熵、重叠和通信,能判断是否改变MoE效率.

固定MoE或使用稠密FFN的小模型消融可隔离attention本身,论文3B选择消融仍需看骨干配置.

## 68. 优化器与尺度

三套KV投影使参数梯度尺度不同. 压缩分支每query看更多摘要,选择与窗口看固定项,更新频率与方差不同.

统一学习率可能让某路收敛慢. 分支级梯度norm和参数norm曲线可诊断,必要时用分组学习率.

门控初始偏置若偏窗口,压缩和选择早期欠训练. 初始化等权或按预算比例设置会影响最终解.

## 69. 上下文污染

长prompt中大量无关或恶意文本会占候选. 压缩softmax质量总和固定,污染越多,相关块质量被稀释. Top-n固定使攻击可通过数量放大.

分层选择先按文档再按块,或给可信来源先验,能抵抗. 纯内容分数无法识别权限优先级.

系统指令应放入始终可见区域,不能与普通历史共同竞争Top-n. 这是稀疏attention部署的安全约束.

## 70. 反事实删除

静态注意力权重不等于因果贡献. 删除选中块再算loss,得到$\Delta L_j$,更接近真实重要性. 高分低贡献块说明selector存在代理偏差.

逐块删除成本高,可抽样或使用梯度近似. 多块交互使单独删除贡献不相加,Shapley近似可测冗余.

用$\Delta L$监督selector可能提高因果性,训练代价巨大. 作为评估即可验证压缩分数假设.

## 71. Attention sink

开头token常获得异常注意力,可能让压缩分数偏向首块. NSA基线预算也固定保留开头128token,反映这一经验.

若首块被选择分支重复选中,浪费预算. 可将固定sink与Top-n分开,选择时屏蔽已保证可见区.

sink具有稳定softmax作用,删除可能损害质量. 应区分功能sink与实际语义证据.

## 72. 稀疏模式的可解释性

块选择可以可视化,但分数只代表模型内部相关,不能直接解释答案. 压缩分支还可能使用未选块,只看Top-n会遗漏因果路径.

完整解释需同时展示门控、压缩质量、选择块、窗口覆盖与跨层变化. 信息过多时可聚合到文档或语义段.

解释稳定性也重要:同义改写query后选择完全变化而答案相同,说明存在冗余路径;答案变化则暴露脆弱性.

## 73. 蒸馏稠密模型

已有全注意力teacher可提供每query块质量$P^T_j$. selector最小化$D_{KL}(P^T\|P^S)$,压缩value再匹配teacher输出.

teacher注意力不等于因果贡献,但比无标签频率细. DSA采用类似对齐独立indexer,NSA原生训练没有依赖teacher.

蒸馏适合从稠密checkpoint迁移,能否达到从头NSA质量取决于表示是否能适应三路结构.

## 74. 预算Pareto

对$n,w,d,l'$做网格,每点记录质量、训练FLOPs、decode字节、KV容量和kernel吞吐. 单一“2560 token预算”不足以描述成本.

增大$w$优先改善局部,增大$n$改善远程细节,减小$d$改善全局摘要. 不同任务沿不同方向获益.

可按目标部署加权成本,选择Pareto点. 训练最优配置未必推理最优,需要联合约束.

## 75. 更多手算

32K长度、压缩步长32得到1024摘要. 若每摘要key/value合计512字节,单层压缩cache0.5MiB;原始选择KV若每token512字节则16MiB. 压缩cache小,原始远程KV占主导.

Top-16块、每块64token读取1024token,每token512字节约0.5MiB/层/query组. 窗口512再读0.25MiB. 若64头独立选择且无重叠,最坏读取会放大数十倍,组共享是决定性条件.

压缩attention每query读0.5MiB,三部分约1.25MiB/层. 全注意力读16MiB,理论字节降约12.8倍,实际还受投影、写入和cache复用影响.

## 76. 端到端验收

正确性先用小shape参考实现、因果泄漏与梯度检查. 机制用oracle、边界平移、多证据和困难负例. 质量用通用、长文、代码、数学与安全污染.

性能分别测kernel、整层、整模型TTFT/TPOT,报告KV容量、HBM字节与通信. A100结果与目标硬件分开.

稳健性覆盖长度外推、量化、不同语言、块边界、prefix sharing和batch动态. 每项都应对应前文假设.

只有质量、速度和缓存三者同时进入Pareto前沿,NSA才在具体部署中成立. 单一论文分数或kernel倍数无法替代端到端判断.

## 77. 候选数的概率下界

设每个相关块独立进入Top-n概率为$u(n)$,任务需$r$块,目标全覆盖概率至少$1-\epsilon$,则需

$$
u(n)\ge(1-\epsilon)^{1/r}.
$$

$r=8,\epsilon=0.1$时单块召回需98.7%. 这远高于“平均召回95%”看似不错的水平. 多证据任务会迫使$n$增大或改用分步检索.

独立假设通常乐观. 相似干扰会同时压低多个正块,联合覆盖更差. 按问题统计全覆盖比把所有块混在一起算recall更可靠.

动态$n$可以直到累计质量或预测覆盖达标. 校准错误会让理论下界失效,需在验证集直接估$P(cover\mid n)$.

## 78. 层级错误传播

第$l$层漏掉证据,残差流仍保留前层表示,后层可能重新选中. 若前层错误改变query方向,后层会持续搜索错误区域,形成路径依赖.

把某层集合替换为oracle,观察最终loss改善,可定位关键层. 逐层单独替换的收益不相加,多层共同oracle揭示累积交互.

早层选择更影响表示形成,后层选择更接近输出. 同一漏选在不同层的代价不同,统一recall指标会掩盖.

## 79. 压缩分支的全局平均风险

压缩attention对全部摘要做softmax,大量普通块各获微小质量,总和仍可能显著. value若存在共同偏置,微小权重累积成全局漂移.

归一化使长度增加后单块平均权重下降,摘要输出尺度保持,内容分布改变. 训练长度外推时,模型看到的是更多摘要的混合,不只位置变长.

可以截断低质量摘要或使用稀疏softmax,进一步降计算,会削弱为选择提供全覆盖梯度的优点.

## 80. 共享KV投影的替代

三路独立KV提升表达,也增加参数与cache. 共享底层投影、每路用小adapter变换可降低容量. 共享过强会让摘要、精读和局部需求互相牵制.

消融可比较完全独立、共享K、共享V、低秩分支adapter. 报告参数、cache与质量,判断额外表示是否值得.

若窗口与选择读取相同原始token,共享V尤其自然;两路attention权重不同,同一value仍可复用. 具体head维与位置编码可能阻止直接共享.

## 81. Query 压缩

当前每个query都扫描所有摘要. 相邻query表示相似,可按query块共享粗候选,再在块内细化,减少选择计算.

共享过长会漏掉query快速变化,代码与多主题切换尤其明显. 可用query相似度触发候选刷新.

decode逐token时,上一步Top-n可作为下一步候选先验,只搜索部分新摘要. 这属于时间局部性优化,错误候选可能持续锁定,需周期全扫.

## 82. 非均匀块长

固定64token块硬件友好,信息密度不均. 代码行、表格行、段落与对话轮次是自然边界. 变长块能减少语义切割,使读取量不可预测.

可先用固定物理页,在逻辑上把相邻页组成语义段,选择仍以页执行. 分数聚合到段后再展开页,保持kernel规整.

长段会垄断预算,应按读取token成本归一化分数,形成价值/字节选择问题.

## 83. 价值/成本选择

当块大小或存储层不同,选择目标应最大化收益且满足字节预算:

$$
\max_S\sum_{j\in S}r_j,\quad \sum_{j\in S}c_j\le B.
$$

固定块时$c_j$相同,退化为Top-n. 分层KV中主机块成本高于HBM块,单纯相关性Top-n可能造成延迟尖峰.

按$r_j/c_j$贪心是分数背包近似,会偏好小块;真正收益有块间冗余,需要边际价值. 这是部署层对NSA选择的扩展.

## 84. Cache 命中与批处理

batch内多个query选相同块时,KV可留在L2或shared memory复用. 选择集合相似度因此影响实际带宽. 理论按每query独立读取会高估.

按候选集合聚类query可提高复用,重排计算会增加调度延迟. 生成batch中不同请求语义无关,共享较少;同一prefill连续query共享较多.

性能基准应区分单序列prefill、多请求decode和prefix共享场景,同一kernel数字不能代表全部.

## 85. 与线性注意力的边界

线性attention把历史压进固定状态,成本$O(L)$,精确内容寻址较弱.NSA保留原始KV并按query选块,存储$O(L)$且能恢复细节.

压缩分支类似多状态线性记忆,选择分支像内容寻址外存. 两者结合避免只依赖固定容量状态,代价是索引扫描与随机读取.

当任务只需全局统计,线性状态可能更便宜;需要任意复制与稀有事实时,NSA外存更合适. 混合模型可按层或头组合.

## 86. 质量退化定位表

短文本也退化时,优先查三路投影、门控与训练差异;只在长文本退化,查位置外推与负例极值;只在多证据退化,查固定预算与联合覆盖;只在块边界退化,查压缩重叠.

量化后退化且集中在低margin,查selector精度;吞吐未达理论而HBM满,查gather与KV布局;GPU利用率低,查块数、kernel启动和batch.

这种映射把任务分数落到可观察机制,避免笼统归因“稀疏损失信息”.

## 87. 论文数字的再计算

32K平均激活量的$t/16$来自因果序列中压缩条目随位置增长:终点$L/32=1024$,全位置平均约512,若计论文具体重叠与分支定义需按其公式复核. 原文给出的1024口径与“终点/平均”容易混淆,比较基线时应遵循论文预算定义.

前向打平粗式$L/2\approx L/32+1536$得到约3277,只计attention主项. 8K实测2.1倍说明固定开销、投影与硬件效率显著. 长度增加后主项占比上升,倍数才接近理论.

9倍训练反向峰值需结合具体长度与kernel. 端到端模型还包含MoE、norm与通信,整体训练不会达到attention kernel倍数.

## 88. 新硬件上的预测

HBM带宽与Tensor Core增长比例改变最优块长. 计算更强、带宽相对更慢时,减少KV字节更重要;TMA等异步搬运也能改善规则块加载.

全注意力kernel若获得更大提升,NSA相对倍数下降,绝对时间仍可能更低. 应比较同代最佳实现.

更大片上缓存可提高选中块复用,更快互联改善序列并行. 这些变化不会消除选择质量边界.

## 89. 最终可证伪命题

命题一:压缩分数是有效selector. 以同预算随机、启发式、独立indexer和oracle排序检验.

命题二:块选择带来硬件效率. 以相同读取token但不同块连续性的kernel检验.

命题三:三路互补. 以单路、双路、等权和门控组合检验,并观察任务分桶.

命题四:原生训练优于推理剪枝. 以同底座从头稀疏、稠密转稀疏和推理剪枝检验.

命题五:长推理收益来自远程信息利用. 以证据覆盖、输出长度匹配和oracle候选检验,排除只因更短生成或训练随机.

## 90. 收束

NSA把算法与硬件约束同时写进结构:摘要提供连续训练信号,块选择提供远程细节,滑窗提供局部稳定,GQA共享把不规则访问重新变成可复用计算.

它没有消灭长上下文代价. 压缩扫描保留缩小后的平方项,原始KV继续线性增长,Top-n面对更多负例,多证据受固定预算限制.

理解NSA应同时跟踪四个量:候选外注意力质量、块内信息损失、门控分配和实际HBM字节. 任何一个都能成为质量或性能瓶颈.

后续DSA与CSA更换了索引与压缩方式,共同问题仍是如何在可训练相关性、精确细节、缓存容量和矩阵硬件之间取得可验证平衡.

## 91. 一次端到端误差追踪

设问题需要远程块$B^*$中的一个数字. 压缩器先把$B^*$映成摘要$\tilde k^*,\tilde v^*$;query与$\tilde k^*$的分数排在第$n+1$,选择分支漏块. 若压缩门控$g^c=0.4$,摘要value仍可能携带模糊数字,窗口门控无法帮助.

将$B^*$强制放入候选后答案恢复,证明主要错误在选择. 若仍错误,把该块原始value换成全注意力投影;恢复则说明NSA分支value不足. 再把门控固定到选择分支,可测混合是否稀释正确信号.

若强制候选只在部分层恢复,逐层oracle可找到必须读取证据的层. 早层oracle让后续自然重新选中,说明错误会经隐藏状态传播;每层都需oracle则selector持续失配.

这个诊断需要记录分数rank、margin、三路门控、块内attention与最终logit变化. 单看Top-n可视化只能看到漏块,无法判断摘要旁路是否已经补偿.

## 92. 一次性能追踪

同一32K请求记录压缩GEMM、Top-n、gather、选择attention、窗口attention与门控融合时间. 若gather占比高,增加块连续性或重排比减少FLOPs更有效;若压缩GEMM主导,提高$d$或优化稠密kernel更重要.

同时记录HBM读写、L2命中、Tensor Core利用率和kernel启动数. 理论条目下降而HBM字节未同比下降,说明KV布局或重复读取抵消稀疏.

prefill按query块执行时,选块索引可批量;decode只有单query,Top-n和地址生成固定成本占比更高. 两阶段分别profile,避免用prefill加速推断TPOT.

端到端再加入MoE通信与采样调度. Attention kernel快9倍,若attention只占模型时间30%,Amdahl上限为$1/(0.7+0.3/9)\approx1.36$倍. 这解释为何kernel峰值不能直接成为模型吞吐倍数.

## 93. 验收结论的写法

若oracle差距大,结论指向selector;若oracle也差,固定预算或value结构是主因. 若质量达标而速度不足,检查硬件映射;若速度达标而KV过大,三路投影需要共享或分层.

每个结论都应附可反驳观测:候选外质量、边界曲线、门控熵、读取字节、margin分布或oracle差值. 这样可以区分论文已证、公式推导和待验证假设.

## 94. 长度、证据与干扰的联合边界

长度、证据数和干扰相似度应联合扫描. 只拉长上下文而保持唯一显眼needle,增加的是负例数量;增加证据数考验容量;加入近重复干扰考验分辨率. 三轴同时提高时,错误可能远大于各轴单独下降之和.

设单证据在32K随机干扰下召回0.98,近重复干扰降到0.94,扩到128K再降到0.90. 八证据全覆盖在独立近似下仅$0.9^8\approx43\%$. 即使单项看起来仍有九成,端到端多跳任务已经过半失败.

提高$n$可恢复覆盖,读取字节与attention计算同步增长;减小块长提高区分,降低矩阵复用;增加压缩通道改善索引,扩大cache和平方项. 这三个旋钮分别交换预算、硬件效率与摘要容量,没有免费修复.

真正的极限测试应画三维质量—成本曲线,并给oracle集合上限. 若oracle在相同预算下仍无法完成,继续训练selector无益;若oracle很高而学习集合很低,困难负例与摘要目标才是正确方向.

这组实验还能检验NSA与DSA、CSA的差异究竟来自粒度、索引器还是压缩. 保持读取字节和底座一致,再比较联合边界,比在单针满分任务上排序更有解释力.
