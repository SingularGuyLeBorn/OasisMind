# 数据与存储：让样本持续抵达计算设备

训练和推理都依赖数据移动。样本从对象存储经过清单、分片、解码、shuffle、主机内存与设备预取；checkpoint 则沿相反方向写回持久介质。任何一级吞吐、并发或小文件开销不足，都可能让昂贵计算设备等待。仅比较存储标称带宽，无法解释端到端时间。

本章用数据生命周期组织格式与系统。后续讨论语料分片、随机性与确定性、压缩和解码、分层缓存、预取、对象存储、并行文件系统、checkpoint 写入及恢复。每条路径都记录有效字节、放大系数、请求次数、队列深度和进入关键路径的时段。

## 数据为什么会让 GPU 停下来

训练样本管线、checkpoint、模型制品与推理缓存共享三项约束：数据正确、顺序语义明确，并能持续提供目标吞吐。某个 batch 未按时到达、保存阻塞 step 或故障后状态无法重建，都可以沿对象的生产者、存储位置和消费者定位。

- [预处理与背压](4.2-预处理与背压/4.2-预处理与背压.md)：从原始语料到不可变训练分片，展开预处理 DAG、资源预算、背压、幂等提交与增量重跑。

### 数据管线是一条带反压的流水线

训练样本通常经历清单读取、对象下载、解压、解析、过滤/拼接、tokenize、组 batch、固定内存与 H2D 拷贝。每一级都有服务率与缓冲区。若 GPU 每秒消耗 $r_t$ 个 token，平均编码后每 token 占 $b$ byte，进入设备前的最低有效吞吐是 $r_tb$. 压缩存储会降低网络字节，却把压力转给 CPU 解压；预先 tokenization 减少在线计算，却增加存储容量并绑定 tokenizer 版本。

流水线的吞吐由最慢稳态级决定，尾延迟则会由抖动和队列传播。对象存储一次请求偶尔慢 2 s，如果预取队列可覆盖，GPU 不一定看见；队列过浅就出现空档。队列过深也有代价：占用内存、扩大随机顺序窗口，任务取消时丢弃更多已读数据。合适深度应从消费速率和 I/O 延迟分布估算，再用 GPU idle 时间验证。

### 小文件把一次顺序读取放大成大量请求

读取 1 TB 数据可以是 1024 个 1 GiB 对象，也可以是一亿个 10 KiB 对象。有效字节相同，后者却产生大量元数据查询、连接、鉴权与 seek。吞吐模型应写成 $T\approx n\alpha+Q/B$, 其中 $n$ 是请求数、$\alpha$ 是每次固定延迟、$Q$ 是有效字节。当 $n\alpha$ 主导时，增加链路带宽几乎无效。

分片文件将许多样本顺序打包，并配套索引记录 offset 与长度。分片不能无限大：单对象损坏或重试的代价会增加，分布式 worker 可并行的 shard 数也减少。通常根据单 worker 顺序读取带宽、训练时长、故障重试粒度和 shuffle 要求选择，使每个 epoch 有足够多 shard 分配给 worker。

## 随机性、确定性与断点恢复

大模型数据混合往往来自多个语料源，每个源有权重、过滤版本和采样策略。可恢复训练不能只保存模型参数，还要保存全局 step、数据游标、随机数状态以及混合调度状态。否则重启后可能重复或跳过大段样本。严格逐样本不重复未必总是训练目标，但行为必须可描述、可复现。

分布式 shuffle 常分层完成：先打乱 shard 顺序，再在 worker 内用有限缓冲打乱样本。缓冲越大越接近全局随机，内存和恢复状态也越大。worker 数变化会改变分片映射；若恢复允许改变 world size，需要基于全局样本编号或确定性哈希重新分配，而不是简单恢复每个旧 rank 的本地 offset。

数据版本由清单、对象校验和、预处理代码与 tokenizer 共同定义。只给 bucket 路径不够，因为路径内容可以被覆盖。训练记录应指向不可变 manifest，包含每个 shard 的大小、校验和和样本统计。发现污染样本时，可以从 manifest 追溯影响哪些 run，也能生成新版本而不悄悄修改旧实验。

### 缓存要回答命中了什么

缓存可以位于对象存储网关、节点本地 SSD、主机内存或 GPU 内存。越靠近计算，容量越小、单次访问越快。命中率本身不足以判断价值：命中大量小对象可能只省少量字节，未命中的几个大 shard 仍决定等待。更有用的指标是 byte hit rate、请求 hit rate、节省的后端时间与因缓存填充产生的额外流量。

训练按 epoch 重读数据时，本地 SSD cache 很有效；一次性流式语料则可能把热数据不断驱逐。淘汰策略应了解 shard 的下次使用距离和多个作业共享情况。缓存键必须包含内容版本，避免同名对象更新后读取旧副本。校验不应只发生在首次下载，磁盘损坏与不完整写入同样需要原子落盘和 checksum。

多个 worker 同时 miss 同一对象会产生 cache stampede。单飞锁可让一个下载者填充、其他等待，但锁持有者失败时需要超时与接管。跨节点共享 cache 可以减少后端流量，却又成为新的网络和故障域。选择层级时要比较回源带宽、局部复用和缓存服务自身的扩展能力。

### Checkpoint 是一致性协议

训练 checkpoint 至少包含参数、优化器状态、学习率调度、随机数与数据进度。张量并行、ZeRO/FSDP 会让状态分散在 rank 上。一次保存只有在所需分片都完整并且元数据可见时才算成功。常见做法先写临时版本，每个 shard 校验完成后再原子发布 manifest；恢复端只读取已提交 manifest，忽略半成品。

同步保存让各 rank 停下来写盘，语义简单但直接进入 step 关键路径。异步保存先把状态复制到主机或独立缓冲，训练继续，后台写持久存储。它缩短停顿，却增加峰值内存和一致性难度：下一次参数更新不能覆盖尚未复制完成的页，失败时要知道末个真正持久化的版本。

保存频率在正常开销与故障重算之间折中。间隔为 $C$、恢复耗时为 $R$、平均故障间隔为 $I$, 粗略损失包含每次故障平均 $C/2$ 的重算与 $R$ 的恢复；同时每 $C$ 时间还支付一次保存开销。模型规模、存储带宽和集群故障率变化后，旧间隔未必合理。

## 恢复必须演练

「文件写成功」不等于能够恢复。恢复要验证分片数、shape、dtype、模型/优化器版本与 world size 兼容性；随后重建通信组、数据游标和随机状态。若支持弹性 world size，需要重新切分参数和优化器状态，不能假定 rank 编号不变。

演练应从真实持久介质下载, 在隔离作业中加载并执行至少一个训练 step，比较 loss 与关键状态。只做文件存在性检查发现不了损坏 tensor、缺少 scheduler 或数据重放。对关键长期训练，定期恢复演练本身就是数据管线的一部分。

### 推理与模型制品

推理副本启动时要加载权重、量化 scale、tokenizer、kernel cache 与服务配置。数百 GB 权重若每个副本都从远端独立下载，会在扩容时形成惊群。节点级缓存、分层分发或点对点传播可以降低后端压力，但必须校验模型版本，确保所有 rank 加载同一 manifest。

启动时间应拆为调度等待、镜像/代码准备、权重下载、反序列化、GPU 拷贝、通信初始化与 warmup。权重下载变快后，反序列化和 H2D 可能接管瓶颈。mmap、并行读取和 safetensors 一类可定位格式能减少不必要复制，但最终效果取决于文件布局与并行度。

在线系统还会持久化 prefix、adapter 或远端 KV。它们的有效期与模型/adapter/tokenizer 版本绑定，并携带隐私与租户隔离要求。把推理缓存视作普通无状态对象会引出串租户与陈旧结果。缓存键、加密、删除和审计必须与性能设计一起完成。

### 数据路径的共同约束

[《训练数据流水线》](4.1-训练数据流水线/4.1-训练数据流水线.md)从 manifest 到 GPU 逐段计算吞吐与反压，并把分片、洗牌、packing 和恢复位置纳入同一状态定义；后续的数据格式可继续比较顺序分片、列式存储和索引开销，checkpoint 存储处理分布式一致性与弹性恢复，I/O 路径则沿对象存储、网络、page cache、pinned memory 到 DMA 解释一次字节移动。

各篇使用相同验收方式：验证样本和状态正确，确认设备能持续获得数据，再优化成本。带宽数字必须绑定对象大小、并发、缓存状态和读取模式。数据系统的改动不能以牺牲随机性、可恢复性或版本一致性为代价。
