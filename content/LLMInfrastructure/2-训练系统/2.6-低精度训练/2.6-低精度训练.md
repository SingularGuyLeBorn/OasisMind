# 低精度训练

低精度训练同时处理三个问题：数值能否表示、硬件能否高效计算、训练状态能否稳定更新。把参数从 FP32 改成 BF16 只回答了第一个问题的一部分。一次训练 step 里，权重副本、前向 activation、反向梯度、归约结果、优化器状态和矩阵乘累加器可以使用不同格式；FP8 与 FP4 还要携带 scale，数值的真实含义由低精度编码和 scale 共同决定。

训练系统因此需要保存两类状态。模型状态包括参数、梯度和优化器矩；数值控制状态包括 loss scale、amax 历史、量化 scale、格式配方和溢出判定。前者遗漏会改变优化轨迹，后者遗漏也可能让恢复后的若干步突然饱和或下溢。只比较模型文件大小，无法判断训练显存和恢复语义。

## 格式决定范围与分辨率

FP16 使用 5 位指数和 10 位尾数，有限最大值为 65504，1 附近的间隔约为 $2^{-10}$。BF16 使用 8 位指数和 7 位尾数，动态范围接近 FP32，1 附近的间隔则增大到 $2^{-7}$。因此 BF16 更能容纳大梯度，FP16 在同一数量级内保留更多有效位。训练是否稳定，取决于张量分布落在哪个范围，而非格式名字里的位数。

FP8 把范围与精度的矛盾继续推向两端。NVIDIA Transformer Engine 常用 E4M3 处理前向张量，其最大有限值为 448；E5M2 的指数更多、最大有限值为 57344，常用于梯度。FP4 E2M1 只有极少离散值，离开分块缩放几乎没有实用训练空间。FP8/FP4 的问题已经从“选哪个 dtype”变成“每多少个值共享一个 scale，以及 scale 何时更新”。

### 哪些状态可以降精度

矩阵乘输入降精度能减少 HBM 读取并使用低精度 Tensor Core，累加通常保留更高精度。优化器更新需要把很小的增量加到较大的参数上；若直接在 BF16 参数中累加，更新可能小于当前 ULP 而消失。因此许多混合精度方案保留 FP32 master weight，以及 Adam 的 FP32 一阶矩和二阶矩，再生成 BF16、FP16、FP8 或 FP4 计算副本。

这种设计的显存收益并非“位宽减半”这么简单。以 70 亿参数为例，BF16 计算参数约 14 GB，BF16 梯度约 14 GB，FP32 master weight 约 28 GB，Adam 的 $m,v$ 各约 28 GB，总计约 112 GB，尚未计入 activation、通信 buffer 和临时 workspace。把计算权重换成 FP8 只能先省约 7 GB，其余约 105 GB 仍由梯度、master weight 和 Adam 状态占用。

### 缩放是数据流的一部分

FP16 常用 loss scaling：前向把 loss 乘 $s_L$，反向得到的梯度也乘 $s_L$，在裁剪、归约或优化器更新前按约定除回去。动态 loss scale 发现任一 rank 出现 Inf/NaN 时跳过整次更新并降低 scale；连续若干步有限时再提高。所有数据并行 rank 必须形成同一个溢出结论，否则参数会从下一步开始分叉。

FP8/FP4 的张量缩放更接近量化。若格式最大有限值为 $M$，张量绝对最大值为 $a$，留出 $m$ 位指数余量时可取

$$
s=\frac{2^{-m}M}{a},\qquad q=\operatorname{cast}(sx),\qquad \hat{x}=q/s.
$$

Scale 可以按整个张量、通道或 block 共享。粒度越细，离群值污染的元素越少，metadata、布局约束和 kernel 复杂度越高。Delayed scaling 使用历史 amax 计算下一次 scale，省去当前值对当前计算的依赖，却会在分布突变时暂时饱和；current scaling 与 block scaling反应更快，也要付出更紧的融合要求。

## 算子、通信与缩放顺序

典型路径是高精度权重生成低精度计算副本，activation 统计 amax 后缩放并 cast，低精度 GEMM 用较高精度累加，再把输出交给下一算子。反向梯度经过 loss unscale、有限性检查和必要的 FP8/FP4 cast；数据并行 collective 使用何种 dtype、在 unscale 前还是后执行，都必须固定。

FSDP 参数 all-gather、TP activation collective 与 MoE token dispatch 都可能传低精度 payload。通信字节可以下降，但接收端必须拿到匹配的 scale。只传编码而漏传 scale，shape、通信量和 kernel 状态看起来都正常，恢复出的数值却完全错误。Scale 所有权应像参数 shard 一样写进并行布局。

### FP16、BF16、FP8 与 FP4 的选择边界

BF16 通常是支持 BF16 Tensor Core 硬件上的稳健基线，动态范围接近 FP32，很多模型无需 loss scaling。FP16 在旧硬件或特定 kernel 上仍有价值，但要认真处理 loss scaling。FP8 适合已经有 BF16 稳定基线、主要算子获得成熟 kernel 支持，并且可以记录 amax、饱和率和 scale 的训练。FP4 对 scale 粒度、异常值和累加路径更敏感，当前实践通常绑定 Blackwell 级硬件与具体配方，例如 NVFP4，而非把所有张量直接改成四位格式。

首尾层、归一化、softmax、router score 和部分归约常保留 BF16/FP32。原因不神秘：这些位置可能输入动态范围大、输出对舍入敏感，或计算量占比太小，降精度没有足够吞吐收益。精度配置应落实到算子和张量角色，不能只写“模型使用 FP8”。

### 与并行训练共同验收

数据并行要同步溢出标志和更新决定；FSDP 要明确低精度参数何时聚合、何时释放；张量并行要确定局部 amax 是否在 TP 组内归约；流水线并行要让 scale 状态与 microbatch 对齐；MoE 还要处理不同 expert 的分布差异。一个全局 scale 容易被热点 expert 的离群值主导，细粒度 scale 又增加分布式 metadata。

性能验收至少记录有效 token/s、GEMM dtype、累加 dtype、cast 时间、amax/scale 时间、collective dtype、饱和率、零值比例和跳步次数。若 FP8 GEMM 更快，却新增大量 unfused cast 或 amax 归约，端到端 step 未必缩短。数值验收则比较 loss 曲线、梯度范数、参数更新范数、溢出次数和恢复后的第一步。

## 位宽选择怎样进入数值闭环

[《数值格式与缩放》](2.6.1-数值格式与缩放/2.6.1-数值格式与缩放.md)从指数与尾数开始，逐项展开 FP16、BF16、FP8、FP4 的表示范围，解释 master weight、optimizer state、loss scaling、amax 粒度、delayed scaling、cast/collective/GEMM 数据流，并给出下溢、饱和、checkpoint 恢复和手算案例。

后续可沿两条线继续扩展：一条研究低精度优化器与状态压缩，另一条研究通信量化和不同并行维度中的 scale 所有权。无论格式怎样变化，稳定训练都要回答同一组问题：谁保存高精度真值，谁生成低精度副本，scale 属于哪个张量，溢出如何形成全局决定，恢复时哪些数值控制状态必须回到原位。

### 一张配置表应该写到什么程度

可复现的精度配置应按张量角色列出格式，而非只给模型贴一个标签。线性层权重、前向 activation、反向梯度、GEMM 累加器、残差、归一化、softmax、loss、梯度归约和 optimizer state 各有一行；使用 FP8/FP4 的行还要写 scale 粒度、amax 算法、margin 与 history 长度。这样才能判断两次实验到底改变了计算格式，还是顺手改变了通信和更新路径。

以 FP8 训练为例，权重与 activation 可能使用 E4M3，梯度使用 E5M2，累加器为 FP32，层间输出回到 BF16，Adam 状态仍为 FP32。参数 all-gather 可以传 BF16，也可以按配方传 FP8。两种配置都能简称“FP8 训练”，显存、网络字节和数值行为却不同。实验表格必须把这些差异展开。

### 收益上限先看字节落在哪里

低精度加速主要来自 GEMM Tensor Core 与 HBM/网络字节减少。若 step 大部分时间耗在数据读取、CPU 调度、小 kernel、同步长尾或 checkpoint 写盘，降低矩阵 dtype 的收益会被 Amdahl 定律限制。反过来，大矩阵乘占主导且 cast 可以融合时，FP8 才容易接近硬件宣传的提升。

显存也要按生命周期估算。低精度计算副本常与 master weight 同时存在，activation 只在特定区间驻留，amax 与 scale metadata 很小但不能丢，通信 buffer 可能按最坏 shape 预留。峰值出现在 backward、参数聚合或 optimizer step，需要时间线而非静态文件大小来判断。

## 上线前的最低验收线

短跑先覆盖极小梯度、极大梯度、离群 activation、全零张量和分布突变，确认不会静默饱和。多卡测试刻意让一个 rank 产生 Inf，检查所有 rank 是否一起跳步。重算测试比较第一次前向与 recompute 的 scale 和输出；恢复测试比较 checkpoint 前后同一 batch 的下一次更新。

长跑至少保留 BF16 对照，观察 loss、梯度范数、更新范数、跳步率、饱和率和最终任务指标。某套配置只有吞吐更高而训练预算内质量下降，它仍然是速度与质量的交换，不能把减少的每步时间直接当作训练时间收益。
