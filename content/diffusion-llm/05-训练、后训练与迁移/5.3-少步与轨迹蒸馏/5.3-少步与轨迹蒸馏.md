# 少步与轨迹蒸馏

蒸馏的共同目标是把教师的多步修订压到更少网络调用，但“少了多少步”不等于“快了多少倍”。学生模型大小、并行硬件利用率、缓存、验证和输出长度都会改变端到端结果。

## 三条路线

- [`5.3.1` SDTT 少步蒸馏](5.3.1-sdtt少步蒸馏.md)：压缩连续或离散去噪时间网格。
- [`5.3.2` dParallel 确定性蒸馏](5.3.2-dparallel确定性蒸馏.md)：通过 certainty-forcing 降低正确 token 的不确定性。
- [`5.3.3` d3LLM 伪轨迹与 AUP](5.3.3-d3llm伪轨迹与aup.md)：用教师揭开顺序构造学生轨迹，并明确作者提出的新指标。

## 必报字段

教师/学生检查点、原始/蒸馏步数、网络调用定义、长度、batch、硬件、精度、是否含 prefill、质量指标与检查点可得性。论文中的“32×/64×”若指步数压缩，就只写成步数压缩。
