# CRoCoDiL:连续草稿,掩码解码

[五条性质](4.2-联合依赖建模.md) 把 L2 写成:按格边际对了,乘积仍可抽出假句.[CoDD](4.2.3-codd可算联合层.md) 在冻住的 logits 上接可算联合.[离散 copula](4.2.1-离散copula.md) 用 GPT-2 当 copula.Uziel,Belhasin,Levy,Bercovich,El-Yaniv,Zilberstein,Elad 的 [CRoCoDiL](https://arxiv.org/abs/2603.20210) 走第三条:长程结构先在连续句级空间里扩散成一份草稿 $\mathbf{z}_0$,再让掩码去噪器条件在这份草稿上把词揭开.解码器仍是 MDM,一步之内各格仍按边际抽.这份草稿先编码整段级语义,并行揭开共享同一个全局条件,因而较少落入彼此无关的局部最优. > **实验范围**:arXiv:2603.20210v3 首次提交于 2026-03-02,当前版修订于 2026-04-17,仍是预印本.生成实验覆盖 StarCoder Python 子集上适配后的 LLaDA-8B 无条件代码生成;13×/14× 来自长度 512/1024 的 NFE 比,不对应墙钟,tok/s 或 HumanEval 加速.带提示的条件生成尚无实验结果.

实验范围限于无条件代码生成.骨干是 LLaDA-8B,在 StarCoder 的 Python 子集上用 1200 万条,长度 $[0,4096]$ 的程序微调 demasker,从开源 Base 初始化.编码器 $h_\phi$ 从 Qwen embedding 0.6B 初始化,和 demasker 一起再训.潜变量尺寸 $1024\times K$,$K$ 是寄存器个数,训练里 $1\le K\le 128$,dropout 偏好前面的寄存器,好让推理用更短的 $K$.Nie Table 1 那份通用 Base 的 GSM8K / MMLU 不在这套实验里.作者把带提示的条件生成列为未来工作,见附录 H.文中的加速倍数全部来自无条件 Python,整段当一块的 Figure 6. 摘要写「超过 $10\times$ 更快」.正文例子两档:长度 512,基础 LLaDA NFE $=512$(MAUVE $0.62$,Gen-PPL $19.4$)对 ConWithinDisc NFE $=40$(MAUVE $0.6$,Gen-PPL $14.3$),约 $13\times$;长度 1024,基础 NFE $=1024$(MAUVE $0.76$,Gen-PPL $23.5$)对 ConWithinDisc NFE $=72$(MAUVE $0.8$,Gen-PPL $12.5$),约 $14\times$.NFE 把连续去噪器也折算进去了:400M 的连续 demasker 跑 128 步,约等于 6 次 8B 前向;条件连续扩散 32 步,少于 2 次 NFE.报 $13\times$ 时分母是这套折算后的 NFE,不是墙钟,并非 GSM8K 时延.

## 边际 demasker 缺的是整段草稿

从边际预测到共享全局条件? 掩码扩散的 demasker 输出各格 logits,训练目标是按格交叉熵.并行揭开等于从乘积里抽,提交得越激进,跨位置联合误差越大.MDM 揭开 token 后直接写入最终序列,后续步骤只有部分完成的离散文本可用,缺少一份覆盖整段语义的全局草稿.局部片段可以自洽,整段主题与结构仍可能漂移.

CRoCoDiL 把「整段在干什么」放到连续空间.编码器 $h_\phi$ 把干净序列映成 $\mathbf{z}_0$.demasker 变成 $f_\theta(\mathbf{x}_t,t,\mathbf{z}_0)$,每格仍独立抽 $\hat x_0^i$,但条件多了这份草稿.长程结构由轻量连续扩散在潜空间里长出来,MDM 负责把草稿译成词.作者的类比是:潜变量是素描,MDM 是按素描上色.素描可以不完整,MDM 的迭代还能补.COSMOS 的解码器没有生成能力,潜变量必须自己带齐所有信息.E2D2 把提示编成连续向量去导离散回答,回答侧仍是普通 MDM,跨 token 依赖仍缺.CRoCoDiL 的 $\mathbf{z}_0$ 表示无条件整段程序,不承担从提示到答案的条件映射. 相关工作里点名的 DCD copula,能量模型,高斯隐变量,作者写成小尺度上补联合.CRoCoDiL 的尺度是 8B demasker 加 0.6B 编码器再训,任务是无条件 Python.DCD 的 32× NFE 对照 SEDD 多步,尺度 GPT-2.CoDD 的 +5.00 是 LLaDA 低置信 MATH500 256 步.三套分母不能减.

COSMOS 也在连续潜空间扩散.差别在解码器:COSMOS 的解码没有生成能力,潜变量必须自己带齐所有信息,少一点就译不回来.CRoCoDiL 的 MDM 会迭代揭开,素描可以残缺.E2D2 在有提示的设定里把提示编成连续向量,用普通 MDM 写回答;跨 token 依赖仍在回答侧的因子化里.CRoCoDiL 做无条件整段生成,demasker 从第一步就条件在 $\mathbf{z}_0$ 上.推理期只改揭开顺序的算法(条件独立性检验,膨胀日程)被写成:它们在找「不太相关的格一起揭」,相关格若处处都在,加速就停.CRoCoDiL 不找独立格,它先把相关写进草稿.

高斯隐变量那条(Xie 等人 VADD)也是给离散扩散加连续相关.作者把它和 copula,能量模型放在小尺度一栏.8B 实验没有提供与 VADD 的同协议对照.能量模型 Xu 等人 ICLR 2025 用能量给文本扩散补依赖,配分一般不可精确求;CoDD 后来走可算回路,是另一篇.CRoCoDiL 连续侧是高斯扩散,离散侧仍因子化,依赖靠 $\mathbf{z}_0$ 这个条件,不靠能量.

连续草稿怎样诱导离散联合? 给定草稿 $z$,demasker 的一步输出仍可按位置分解:

$$
p_\theta(x_M\mid x_t,z)
=\prod_{i\in M}p_\theta(x_i\mid x_t,z).
$$

如果 $z$ 本身是随机变量,对它边缘化后得到

$$
p(x_M\mid x_t)
=\int p_\psi(z\mid x_t)
\prod_{i\in M}p_\theta(x_i\mid x_t,z)\,dz.
$$

条件在固定 $z$ 上的位置独立,混合之后一般相关.两个位置都读取同一草稿样本,其输出会随 $z$ 共同变化.这是连续草稿承载离散联合的概率来源:相关性位于潜变量混合,不在单次 demasker 的输出头. 可以用二元例子手算.令 $z\in\{-1,+1\}$ 等概率,给定 $z$ 时两个 token 都以 0.9 概率取 $\mathbb 1[z=+1]$.边缘上每个 token 仍接近均匀,两个位置相等的概率却为 $0.9^2+0.1^2=0.82$.若忽略共享 $z$、从边缘独立采样,相等概率只有 0.5. CRoCoDiL 推理时通常先采一份 $z_0$,再让整段离散解码共享它.这对应从混合分布中先选一个成分,随后条件生成.如果每个位置各自采独立 $z_i$,相关性会消失;如果每个去噪步无条件重采 $z$,草稿语义可能在步骤间漂移.

**连续草稿提供的是潜变量诱导联合,固定草稿后的 token 输出仍为因子化分布.** 它减少联合误差的能力取决于 $z$ 是否携带相关结构,以及 demasker 是否真正使用这份条件.

联合分布的表达上限? 潜变量混合理论上能表示复杂联合.若 $z$ 有足够容量,每种离散序列都可对应一个潜区域,条件解码器近似确定性.这时边缘化能恢复任意分布.有限寄存器、有限网络和连续扩散训练使实际模型远离这个极限. 表达能力可以按互信息约束理解.离散序列与草稿之间的信息满足

$$
I(X;Z)\le H(Z),
$$

连续变量的微分熵不直接等于可用比特,噪声、有限精度和解码器容量共同限制通道.寄存器数 $K$ 增大提供更多维度,也让无条件连续扩散更难生成正确分布. 若两个序列共享同一全局主题、局部细节不同,$z$ 可以只编码主题,MDM 负责细节.若任务要求逐字符精确重建,$z$ 需承载更多信息或依赖已揭开的离散 token.自编码器 Table 1 的 CER 与 CodeBERTScore 差异正体现语义草稿和字符还原的不同目标. 潜变量还可能被 demasker 忽略.强大的 8B 模型在低掩码率下可从 $x_t$ 自己恢复 token,梯度不必经过 $z$.高掩码率和少步重建更能检验草稿是否有信息.扫 $K$ 与掩码率的交叉熵曲线比单一最终分数更直接.

连续松弛和 token 嵌入扩散不同?

token 嵌入扩散把每个离散 token 映射到连续向量,对每个位置加噪,最终用 rounding 或 softmax 回词表.连续变量与 token 位置一一对应,量化边界直接影响每个词. CRoCoDiL 的 $K$ 个寄存器不与 $n$ 个 token 一一对应.编码器把整段压进 $z_0\in\mathbb R^{1024\times K}$,连续扩散建模的是句级表示分布.离散 token 仍由 MDM 输出词表概率,没有把潜向量最近邻量化成 token. 因此量化发生在解码器输出,不是潜空间 rounding.草稿误差先改变 demasker logits,再通过离散采样变成 token 差异.两个相近 $z$ 可能落入同一离散程序,也可能跨过某个高敏感决策边界产生完全不同的标识符.

连续松弛的好处是梯度可穿过编码器与 demasker,可以联合训练.代价是潜空间几何由任务损失间接塑造,欧氏距离未必对应代码语义距离.连续扩散使用高斯噪声隐含局部平滑假设,需要实验证明潜表示满足它.

量化误差如何传播到离散序列? 设理想草稿为 $z^*$,连续生成得到 $\widetilde z=z^*+\delta$.某位置 logits 为 $l_i(z)$.一阶展开

$$
l_i(\widetilde z)
\approx l_i(z^*)+J_i(z^*)\delta,
$$

$J_i$ 是 logits 对草稿的 Jacobian.若正确 token 与次优 token 的 margin 为 $m_i$,当扰动投影超过 $m_i$ 时,argmax 可能翻转.草稿 L2 误差小,不保证离散输出稳定;关键是 Jacobian 与 margin. 首个 token 翻转后会进入后续 $x_t$,demasker 再把它作为条件,误差从潜扰动转为离散上下文扰动.后续步骤可能纠正,也可能强化错误.标识符首次出现被改名后,全局一致地沿用新名字会造成 CER 高、语义仍接近;这与 Table 1 的观察一致. 可以按潜扰动大小画三条曲线:重建交叉熵、token flip rate、执行或语义分数.若语义曲线比 CER 平缓,潜空间确实优先保留高层结构.若极小扰动导致执行结果骤降,连续草稿存在脆弱方向.

固定草稿与中途修正? ConThenDisc 先采 $z_0$,整条离散轨迹固定条件.优点是全局意图稳定,缺点是早期草稿错误无法利用已生成 token 修正.其联合分布为

$$
p(x)=\int p_\psi(z)
p_\theta(x\mid z)dz.
$$

ConWithinDisc 在中途根据部分离散状态更新草稿.若更新核为 $p_\psi(z'\mid z,x_t)$,生成变成耦合链:

$$
z^{(s+1)}\sim p_\psi(z\mid z^{(s)},x_{t_s}),
\qquad
x_{t_{s+1}}\sim p_\theta(x\mid x_{t_s},z^{(s+1)}).
$$

离散文本给草稿提供证据,草稿再约束下一轮 token.这能修正初始潜样本,也可能产生反馈错误:早期错误 token 让草稿向错误语义移动,更新后的草稿又使错误更稳定. 正文只做一次中途更新,减少连续侧计算和反馈次数.更新时机决定可用证据:太早时 $x_t$ 大多是 mask,编码器输入分布外;太晚时大部分 token 已提交,草稿没有足够纠错空间.

连续草稿不能自动消除因子化? 若真实依赖在给定 $z$ 后仍存在,条件乘积仍有缺口.例如 $z$ 只编码「生成一段括号串」,具体成对位置没有进入草稿,同时提交括号仍可能不匹配.潜变量要成为足够统计量:

$$
X_i\perp X_j\mid Z,x_t
$$

才会消除相应条件依赖.有限草稿通常只降低总相关量,不会归零. 这给出直接测量:比较原条件总相关量与给定真实编码 $z_0=h(x_0)$ 后的剩余总相关量.小词表可枚举,真实代码可用成对互信息或约束违例作 proxy.若真实草稿条件下仍有大缺口,连续生成再准确也无法完全解决. CoDD 与连续草稿可以组合,因为二者作用层不同:草稿解释全局混合成分,PC 修固定草稿后的局部相关.现有论文没有组合实验,因此这里只能从分布分解看到兼容性,不能声称性能会叠加.

## 编码器和解码器一起训

寄存器编码与两阶段训练? 损失仍是掩码扩散那一项,只是 demasker 看见 $\mathbf{z}_0=h_\phi(\mathbf{x}_0)$.抽干净 $\mathbf{x}_0$,抽 $t\sim U[0,1]$,按吸收态掩出 $\mathbf{x}_t$,网络吃 $(\mathbf{x}_t,t,h_\phi(\mathbf{x}_0))$,对被掩位置做交叉熵.权重沿用 LLaDA 的 $1/\alpha_t$.$\phi$ 和 $\theta$ 一起更新.没有这份条件时,式子退回普通 MDM.

变长靠 BOS / EOS.微调后的 demasker 会写不同长度的程序,开头结尾用这两个特殊词标出来.潜变量不是「一个 1024 维向量」,是 $K$ 个 1024 维寄存器排成的矩阵.训练对后面的寄存器做 dropout,推理时长度 512 用 $K=8$,长度 1024 用 $K=16$,自编码器 Table 1 用满 $K=128$.$K$ 并非 Transformer 层数.寄存器越多,草稿越细,Figure 4 上有条件 demasker 的交叉熵缝越大.生成 Figure 6 没有用满 128,因为无条件连续扩散还要先把这些寄存器从噪声里长出来,$K$ 太大,连续侧更难.dropout 偏好前面的寄存器,意思是短 $K$ 时仍然用矩阵的前几列,而并非随机抽子集.这样 $K=8$ 的推理和 $K=128$ 的训练共享同一套列对齐.附录 C 写 FlexTok 一类工作把图压成变长 1D token,这里是把程序压成变长寄存器.FlexTok 的图像结果不参与程序生成比较.

1200 万条 Python 相对 LLaDA 原文的 2.3T 通用 token,属于领域适配.开源 Base 用作初始化,损失仍是带 $1/\alpha_t$ 的掩码交叉熵,demasker 额外接收 $\mathbf{z}_0$.论文没有报告适配后的通用 MMLU / GSM8K,所以 $13\times$ 只代表 Python 无条件生成,不代表聊天任务.Qwen embedding 0.6B 的论文是 Qwen3 Embedding;初始化之后 $\phi$ 和 demasker 会联合更新,权重未必还对应公开检索模型,检索分数也不能代表联合训练后的编码器. ConThenDisc 的循环按 Algorithm 2.从 $\epsilon\sim\mathcal{N}(0,I)$ 用 $G_\psi$ 得到 $\mathbf{z}_0$.$\mathbf{x}$ 从全掩出发.每一步 demasker 条件在这份冻住的 $\mathbf{z}_0$ 上预测 $\hat{\mathbf{x}}_0$,再按前向核把下一步该掩的位置盖回去,$t$ 减 $1/T$.$T$ 小则每步揭得多.草稿不变,等于整段生成共用一张素描.

ConWithinDisc 每步(或选定的子集步)先抽新的 $\mathbf{z}_0\sim G_\psi(\epsilon,h_\phi(\mathbf{x}_t))$,再揭开.正文为了省,只在 MDM 中途加一次连续更新,NFE 额外少于 2.作者列出三条未做完的改进:更新可以更勤;条件可以直接打在 $\mathbf{x}_t$ 上而不经 $h_\phi$;给掩码输入另训编码器 $h_\mu$.主表没有这三档的数字. 自编码器评测把这件事反过来用:已知 $\mathbf{z}_0=h_\phi(\mathbf{x}_0)$,从全掩出发跑少步 MDM,看能不能把程序找回来.Figure 4 在 1000 条验证程序上画交叉熵和 top-1:掩码率升高,所有曲线都差;条件在 $K=8/64/128$ 上优于无条件基线,$K$ 越大缝越大.曲线点没有进入主表,因此只报告趋势,不引用阴影区域的读数.

联合训练目标怎样分解? 自编码阶段最基本的损失是条件掩码交叉熵:

$$
\mathcal L_{\mathrm{disc}}
=\mathbb E_{x_0,t,x_t}
\left[
w(t)\sum_{i:x_{t,i}=\mathtt{MASK}}
-\log p_\theta(x_{0,i}\mid x_t,t,h_\phi(x_0))
\right].
$$

梯度同时更新编码器 $\phi$ 与 demasker $\theta$.编码器被鼓励输出能降低各掩码位置 loss 的草稿,没有单独要求潜空间服从高斯或欧氏平滑.如果只优化这项,编码器可能形成不规则、离散化很强的潜簇,后续高斯扩散难以学习. 连续生成阶段固定或使用训练后的编码器,收集 $z_0=h_\phi(x_0)$,训练连续去噪器 $G_\psi$.标准噪声过程写成

$$
z_t=\alpha_t z_0+\sigma_t\epsilon,
\qquad \epsilon\sim\mathcal N(0,I),
$$

去噪目标可预测 $z_0$、噪声 $\epsilon$ 或 velocity,具体参数化以论文附录为准.这一步让模型从高斯噪声生成编码器潜分布. 两阶段目标存在错配.自编码器希望 $z_0$ 尽量利于离散重建,连续扩散希望 $z_0$ 分布平滑易生成.寄存器 dropout 与有限 $K$ 提供瓶颈,没有显式保证两目标最优一致.生成质量取决于折中.

寄存器 dropout 在优化什么? 训练时优先保留前几个寄存器、随机丢弃后部,使前缀寄存器承担核心信息.设最大寄存器数 $K_{\max}$,随机有效长度 $K\sim\pi(K)$.编码器目标变为

$$
\mathbb E_{K\sim\pi}
\mathcal L_{\mathrm{disc}}
(h_\phi(x_0)_{1:K}).
$$

较小 $K$ 出现频繁时,前几个寄存器必须支持粗略重建;较大 $K$ 再补细节.这形成渐进式表示,推理可以按序列长度选择 $K=8$ 或 $16$,无需为每个 $K$ 训练独立编码器. 该机制没有保证寄存器严格按语义层次排序.后部寄存器可能与前部协同编码,截断后 demasker 通过鲁棒性补偿.可以测新增第 $k$ 个寄存器带来的条件 NLL 降幅

$$
\Delta_k=\mathcal L(K=k-1)-\mathcal L(K=k).
$$

若 $\Delta_k$ 递减,渐进信息假设较合理;若某些后部寄存器突然贡献很大,固定短 $K$ 会遗漏特定模式. dropout 分布也影响连续扩散训练.连续模型若只看满 $K=128$ 潜矩阵,推理截成 $K=8$ 属于形状变化;论文对变长潜序列另有训练处理.报告 $K$ 时要区分自编码上限与生成工作点.

编码器为何可能泄漏答案? 自编码器训练中 $h_\phi$ 读取完整 $x_0$,demasker 当然可从草稿恢复被掩 token.这证明表示容量与可解码性,没有证明无条件生成时能从噪声采到同样正确的 $z_0$.Table 1 是上界诊断. 若编码器近乎逐 token 搬运答案,重建会很好,连续潜分布却复杂.寄存器数 $128$、每个 1024 维,容量很大;瓶颈来自共享寄存器、dropout 和训练,不能只按维数断言压缩程度.

可用线性 probe 或最近邻检查潜变量是否记住具体 token.将 $z_0$ 的小扰动输入 demasker,观察字符级重建稳定性.高度脆弱且近邻对应完全不同程序,说明潜几何不利于连续扩散. 还可比较真实编码草稿与连续生成草稿的统计:均值、协方差、范数、寄存器间相关、demasker 条件 NLL.两者分布接近,生成阶段才有可能复现自编码能力.

连续扩散训练的分布对象? 连续模型学习的是编码器推送分布

$$
p_\phi(z)=\int \delta(z-h_\phi(x))p_{\mathrm{data}}(x)dx.
$$

它不是标准高斯,也不保证满维.若编码器输出落在低维流形,前向高斯噪声会把流形扩散开,反向模型需恢复复杂几何.400M demasker 的容量与 2M 潜样本决定拟合程度. 序列长度与 $K$ 改变潜分布.长度 512 用 $K=8$,1024 用 $K=16$,连续模型要么支持不同形状,要么分别设置条件.两档 NFE 同时变化,无法只归因于长度. 训练潜变量若来自联合更新期间不断变化的编码器,连续数据分布也会漂移.常见做法先完成自编码训练、冻结编码器、再抽取潜数据.若交替训练,旧缓存潜变量会过期.论文阶段划分需要按附录复现.

中途修正为何是后验问题? 生成到部分状态 $x_t$ 后,理想草稿分布应为

$$
p(z\mid x_t)
\propto p(z)p_\theta(x_t\mid z).
$$

ConWithinDisc 的条件连续扩散试图近似这个后验.已揭开的 token 作为观测更新全局意图,新草稿同时继承初始潜状态与当前离散证据. 正文用 $h_\phi(x_t)$ 作为条件,但编码器训练主要读取干净程序.包含大量 `[MASK]` 的输入属于分布变化.若编码器把 mask 当普通 token,条件表示可能偏离理想后验统计.作者提出单独训练 $h_\mu$ 正是针对这一点. 后验可能多峰.部分前缀兼容多种程序结构,连续扩散若取单一均值会产生两种模式的混合草稿,demasker 难以解释.随机条件扩散保留多样性,代价是一次更新可能跳到另一语义模式. 修正频率越高,潜–离散耦合越强,也越贵.每一步更新草稿并不保证单调提高离散 likelihood.可以记录更新前后真值条件 NLL或结构约束,检验修正是否朝正确方向.

草稿冻结后的误差传播? ConThenDisc 初始草稿若缺少某个全局结构,离散解码只能依靠自身 $x_t$ 补充.少步时每轮提交多,错误更容易被固定.草稿误差会同时影响多个位置,产生相关错误,与普通因子化的独立错位不同. 设草稿误差为 $e_z$,第 $s$ 步离散状态误差为 $e_s$.局部线性分析可写

$$
e_{s+1}\approx A_s e_s+B_s e_z+\xi_s,
$$

$A_s$ 描述离散上下文误差传播,$B_s$ 描述共享草稿影响,$\xi_s$ 是采样噪声.固定草稿使 $e_z$ 在每一步重复注入;中途修正相当于替换 $e_z$. 如果 $B_s e_z$ 让所有标识符一致改名,局部一致性反而高,字符参考不一致.如果草稿在控制流结构上错误,多个块会共同偏离,MDM 很难局部修补.按错误类型分析比平均 CER 更有意义.

离散与连续步数怎样共同构成预算? 令连续去噪步数为 $T_c$,连续模型单步成本为 $C_c$;离散步数为 $T_d$,8B demasker 单步成本为 $C_d$.总计算近似

$$
C_{\mathrm{total}}
=T_cC_c+T_dC_d+C_{\mathrm{update}}.
$$

作者把 $T_cC_c/C_d$ 折算成等效 NFE,便于和基础 LLaDA 比.400M 与 8B 参数比约 1:20,单步成本还受序列形状、attention 与硬件利用率影响,参数比不是精确 FLOPs 比. 中途条件扩散增加少于 2 个等效 NFE,说明连续模型较小.墙钟加速还受两个网络交替、kernel 启动、内存读写和 batch 影响.因此 NFE 是算法预算,并非时延实测. 优化预算可在 $T_c$ 与 $T_d$ 间分配.更多连续步改善草稿,更多离散步允许 token 自纠.等总 NFE 网格能回答哪侧更值得投入.只比较基础 $T_d=n$ 与一个混合工作点,无法得到完整 Pareto 前沿.

## 与连续嵌入扩散,联合层和推理加速的关系

相邻路线的接口差异? [从图像到离散](../../2-数学与生成机制/2.1-状态空间与前向过程/2.1.1-从ddpm到离散token.md) 里的连续路线把噪声加在 token 嵌入上,最终 rounding.CRoCoDiL 的连续扩散加在句级寄存器上,词仍由离散 MDM 揭开,没有 rounding 成词这一步.Diffusion-LM 的 80M 句法树结果对应 token 嵌入连续扩散,与句级寄存器实验协议不同. [CoDD](4.2.3-codd可算联合层.md) 冻结 8B 骨干并训练 HMM,实验指标是 MATH500 / GSM8K 准确率.CRoCoDiL 继续训练 8B demasker 和编码器,实验指标是无条件 Python 的 MAUVE / Gen-PPL / NFE.前者补充因子化输出缺失的联合项,后者提供全局草稿.两种模块在结构上可以组合,现有实验未评估该组合. [代码向扩散](../../5-训练-后训练与迁移/5.3-后训练与任务评测/5.3.2-代码模型的训练与评测.md)中的 DiffuCoder 7B 使用约 130B token 专用语料和 coupled-GRPO.CRoCoDiL 的 1200 万条 StarCoder Python 用于适配 demasker,没有重新训练代码基座.DiffuCoder 用 HumanEval 衡量带题目条件的函数正确率;CRoCoDiL 用 MAUVE 和 NFE 衡量无条件程序分布与生成成本.标识符命名误差会降低 CER,即使 CodeBERTScore 仍然较高,因此 Table 1 同时报出两列.无条件生成没有一一对应的参考程序,相应实验改用 MAUVE.

## 怎样检验连续草稿机制

### 三个层次必须分开.** 第一层是自编码上限:给真实 $z_0=h(x_0)$,测少步 MDM 能否重建.它回答表示是否携带信息、demasker 是否会读取.第二层是连续生成:从高斯噪声得到 $\widetilde z_0$,测其分布是否接近编码潜变量.第三层是离散生成:给生成草稿后,少步 MDM 是否产生高质量程序. 三个层次的误差可串联.真实草稿重建差,瓶颈在编码或解码;真实草稿好、生成草稿条件 NLL 差,瓶颈在连续模型;两者都好、最终采样差,瓶颈在离散日程与量化决策.只看 Figure 6 最终 MAUVE 无法定位. 一个完整结果表应同时列 oracle $z_0$、生成 $z_0$、中途修正 $z$ 三档.每档固定离散 NFE,报告 token NLL、CER、CodeBERTScore、执行率和分布指标.这样能看到连续生成距离自编码上限还有多远.

合成联合任务能证明什么

构造长度 $n$ 的二元序列,全局潜类 $c\in\{0,1}$.给定 $c$,每位以 0.9 概率等于 $c$.真实单点边际均匀,位置之间强相关.一维草稿只需编码 $c$,条件 demasker 即可并行生成一致序列. 再加入局部异或规则,让全局类决定主题、相邻 token 决定细节.草稿应承担 $c$,MDM 迭代承担局部依赖.扫草稿维度和离散步数,可以看到二者分工.如果增加 $K$ 只改善全局一致,增加 $T_d$ 只改善局部规则,机制解释得到支持. 反例任务让每条序列由独立 token 构成.共享草稿没有联合结构可学,理想结果应接近基线.若仍大幅提升,收益可能来自额外容量或边际校准,并非补联合. 另一个反例要求精确复制随机长串.压缩草稿容量不足时,真实 $z_0$ 重建也会失败.这能测信息瓶颈,避免把所有错误归给连续扩散?5.3. 潜空间插值不是充分证据.** 常见可视化在两个程序草稿间线性插值

$$
z(\lambda)=(1-\lambda)z_A+\lambda z_B.
$$

若解码程序平滑变化,说明某条路径可用;它没有证明整个高斯噪声区域落在数据流形附近.高维空间中随机生成路径与两点直线分布不同. 更严格的检查包括随机方向扰动、球面插值、编码样本最近邻距离和生成潜变量的 density ratio.还要运行生成代码或解析 AST,仅看文本相似可能错过语义断裂. 插值中途若输出两个程序的拼接,可能看起来平滑,执行却失败.连续草稿需要由离散约束评估,不能只展示潜图或 PCA.

量化边界的可证伪实验? 对真实 $z_0$ 加不同范数的高斯扰动,固定离散随机种子,测首个 token flip.按位置 margin 分桶,验证低 margin 位置更敏感.若 flip 与 $\|J_i\delta\|$ 相关,一阶传播解释成立.

随后比较一次性 argmax、低温采样和多步 remask.多步能修复部分量化翻转时,CER 随 NFE 下降;无法修复的错误更可能来自草稿结构.记录错误首次出现与是否被重掩. 还可沿 Jacobian 最大奇异向量扰动.相同 L2 范数下,最坏方向比随机方向造成更多离散变化,说明平均重建掩盖对抗性脆弱方向.这不必解释成安全攻击,它是潜几何诊断.

草稿修正应该在什么时候发生? 设离散过程完成比例为 $u\in[0,1]$,在 $u$ 处执行一次连续后验更新.扫描 $u=0.1,0.25,0.5,0.75,0.9$.太早时证据少,太晚时可改位置少,中间可能存在最优点. 每个 $u$ 记录更新前后草稿与真实编码的距离、demasker 条件 NLL、最终质量和额外 NFE.如果距离下降但质量不升,欧氏潜距离与解码语义不一致.如果 NLL 改善而最终不升,离散提交已锁定错误.

再扫描更新次数,保持连续总步数固定.多次短更新与一次长更新比较,能区分频繁反馈和连续去噪精度.若多次更新更差,早期离散错误可能污染后验.

掩码编码器的分布变化? 干净编码器 $h_\phi(x_0)$ 在训练中几乎不见 `[MASK]`.直接用于 $x_t$ 时,表示可能主要反映 mask 数量,不是已知 token 语义.按掩码率训练 probe 预测原程序主题,可测信息保留. 单独训练 $h_\mu(x_t,t)$ 应让其输出接近后验需要的条件,目标可以是匹配干净潜变量、改善连续去噪或直接降低最终离散 loss.三种目标不等价.简单 MSE 会把多峰后验压成均值. 对照包括干净编码器、mask 增强编码器、专用编码器和只用可见 token pooling.固定连续模型与更新步数,才能把收益归到条件表示.
