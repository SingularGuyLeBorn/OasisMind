# 后训练与任务评测

「后训练与任务评测」关注的是一组彼此牵连的选择：状态如何表示，破坏过程怎样丢失信息，模型又凭什么把信息找回来。下面的文章分别落到这些选择的不同分支，比较时以共同概率对象和计算条件为坐标。

## 1. 共同起点

LLaDA 8B Instruct 的论文主表只有 SFT,没有 RL.和 LLaMA3 Instruct 比 GSM8K 69.4 对 78.3,HumanEval 49.4 对 59.8 时,作者自己写了对照侧有 RL.后面两篇工作把后训练补上.LLaDA 1.5 做偏好对齐,算法叫 VRPO,是 DPO 在 ELBO 上的降方差版.d1 做推理强化,算法叫 diffu-GRPO,是 GRPO 在掩码模型上的策略梯度.两者都先撞上同一堵墙:序列的 $\log\pi(y\mid x)$ 写不出来,只能估.

掩码扩散的模型分布由反向过程定义,精确似然要对整条掩码轨迹积分.训练用的 $1/t$ 交叉熵是变分下界的一项,用来更新预测器够了.偏好优化要的是两条完整回答的对数概率差

四个对数似然,每个都换成一次 ELBO 估计 $\widehat{\mathcal{B}}$,四个蒙特卡洛误差会加进 $s$ 里.LLaDA 1.5 证明:DPO 损失和梯度相对真值的偏差,方差,都能被这个分数估计量的方差界住.分数一吵,梯度符号都能反,模型会学成「讨厌本来更好的回答」.

直观上,同一个 $y$,抽一次 $t$,再抽一次掩码位置,ELBO 可以差很多.$t$ 接近 0 时几乎没掩码,这项接近 0;$t$ 接近 1 时几乎全掩,交叉熵很大.随机抽到哪一段,决定了今天这条偏好对的梯度有多大.AR 没有这个 $t$.

加大预算 $n$.每条 ELBO 多抽几次再平均.默认 $n=8$,相对 $n=1$ 大约 8 倍前向.相对预训练,作者写这项开销仍低于 0.5%.

最优分配:固定 $n$ 时,应避免在同一个 $t$ 上重复抽取多份掩码,并把预算铺到不同时间步,每个 $t$ 只抽一份掩码.定理说,ELBO 的方差主要来自 $t$ 的积分,不来自同一 $t$ 下掩码的条件方差.Table 2:$n=8$ 且 $n_t/n_{y_t}=8/1$ 时,$\mathbb{V}\hat s_\theta=1.0$;同样 $n=4$ 但挤在一个 $t$ 上抽 4 份掩码,方差 7.3.

对偶抽样:$\pi$ 与 ref 共享随机源.关掉它,Table 2 里 $\mathbb{V}\hat s_\theta$ 从大约 1–4 跳到 2183.7,损失的偏好方差从 $10^{-3}$ 跳到 62.下游分数掉得没这么夸张,作者解释:VRPO 直接优化的是损失估计,不是测试集泛化;关掉对偶有时等于多看了一些不同掩码模式.即便如此,训练稳定性已经足够让人必须打开它.

数据:内部 35 万偏好对,覆盖写作,对话,知识,推理,数学,代码,过滤,去重,奖励模型排序,部分回答被更强模型替换.训一个 epoch,得到 LLaDA 1.5.评测时每个任务仍可选纯扩散,半自回归 remask,低置信 remask 里最好的那种,和原版 Instruct 公平比较时要记住采样器仍是超参.

Table 1(相对 LLaDA 8B Instruct):GSM8K 78.6→83.3(+4.7),Math 42.2→42.6,GPQA 33.3→36.9,HumanEval 49.4→52.4,MBPP 41.0→42.8,IFEval 62.2→66.2,Arena-Hard 10.0→14.3,AlignBench 5.4→5.9,MTBench 7.2→7.3.数学和指令跟随的抬升比开放对话打分大.Arena-Hard 仍在 14 附近,和同期强 AR 对话模型不是一个量级.VRPO 证明 MDM 能吃 DPO,没有证明对齐已经打平 Claude.

离线偏好和在线可验证奖励采用不同数据与优化过程,不能统称为一种「扩散 RL」.VRPO使用已经排好的赢输对,每个偏好对需要运行多次 ELBO;d1使用对错标签,每个梯度步需要在线生成一组回答.非二元风格偏好适合VRPO,具有可验证答案的数学、代码和数独适合d1.原版 Instruct 两头都没做,所以和 LLaMA3 Instruct 比缺口时,缺的是后训练深度,不一定是扩散结构.把 1.5 的 GSM8K 83.3 和 d1 的 82.1 不能直接比较:采样器,shot,生成长度都并未固定为同一协议.

Instruct 原文 Table 2 的 GSM8K 78.6 用了块采样;1.5 的 78.6 基线写的是同一栏「LLaDA Instruct」.两篇没有固定同一采样器;1.5 正文写明采用各任务上表现最好的扩散采样方式.横比 83.3 和 LLaMA3 的 78.3 时,把采样器写上.

GRPO 用一组回答的奖励标准化当优势,不训 critic.搬到掩码模型,缺的是 $\pi(o_k\mid q)$.d1 的估法:对提示随机再掩一层($p_{\mathrm{mask}}=0.15$),只跑一步预测器,用这一步的 token 对数概率当序列概率的代理.完整反向轨迹太贵,在线 RL 每步要生成一组回答,再估概率,套多层去噪会炸算力.一步估计有偏,但够拿来算概率比.

SFT 阶段用 s1K 的 1000 条带反思的推理轨迹,长度 4096,随机时间掩码,LoRA $r=8$.RL 阶段按任务分开训,在线生成长度固定为256,LoRA $r=128$,8×A100.GSM8K 7700 步,MATH500 6600 步,Countdown 5000,Sudoku 3800.奖励是格式加正确性,Countdown / Sudoku 用合成数据.

SFT 单独做,GRPO 单独做,都不如先 SFT 再 GRPO.12 个设定里 d1 有 11 个超过纯 GRPO.长度 512 时,SFT 和 d1 的轨迹里开始出现自检,回退,作者称为 aha moment,来自 s1K 里那种「算完再验」的写法.RL 之后没有出现 DeepSeek-R1 那种思维链越写越长:在线生成固定为256,预训练本身最长 4096,再拉长目前算不起.它证明策略梯度能打在掩码模型上,并且长度 128 和 512 也能沾 256 训练的光,说明学到的不全是「只在训练长度上有效的格式」.

## 2. 分岔来自哪里

代码和数学不一样.GSM8K 上全局 AR-ness 更稳,更偏左;HumanEval 上均值更低,方差更大.作者的解释是:数学文本几乎必须按演算顺序写,代码可以先写函数体再补签名,也可以先写返回值再填循环.这是观察,不是「代码任务上扩散一定更强」的证明.Table 1 上 DiffuCoder Base 的 HumanEval 确实高于同表 Dream,也高于同表 LLaDA,但分母里有 130B 代码 token,Dream 并非代码专料.

Stage 1 训到 65B 时 AR-ness 已经偏低;继续训练到 700B 后,AR-ness 回升且验证变差,因此作者选择早停.中训和 SFT 的第一个 epoch 会抬高因果偏差,随后任务性能改善,AR-ness 再次下降.GRPO 之后全局 AR-ness 继续降低,并且步数减半时掉点比 Instruct 更小.作者据此认为,模型可以自行学习需要多强的因果顺序,无需依靠固定的小块半自回归解码.

掩码扩散没有精确的 $\log\pi(y\mid x)$,GRPO 的重要性比只能估.d1 的办法是把整段 completion 全掩,一步前向,用 $t=1$ 的边际当序列概率.省,但偏:熵汇会让左边的 token 梯度更猛;代码任务上再去掩 15% 提示,作者发现奖励曲线不稳,于是退回「提示不掩,completion 全掩」当基线.即便如此,每个 token 总在「完全看不见兄弟」的上下文里被打分,和生成时逐步揭开对不上.

## 4. 后训练信号落在哪个动作上

扩散模型的一次回答包含噪声状态、位置选择、token 采样和可能的重掩码。序列级偏好只评价最终文本，却没有直接说明中间哪一步值得奖励；若把同一个终局分数平均贴到所有去噪动作，信用分配方差会很大。逐步价值、成对轨迹比较和耦合采样分别试图减少这类方差，但它们依赖的行为策略与反向链定义不同，不能只因为都用了「GRPO」或「DPO」名字就视为同一目标。

代码任务尤其容易暴露差别。编译通过、测试通过和字符串相似度分别约束语法、行为与表面形式；并行提交多个相关 token 时，局部概率都高也可能组合成不可执行程序。训练若只奖励最终 pass，模型可能学会更保守的短答案或模板；若加入 token 级 shaping，又要检查 shaping 是否改变原目标的最优策略。

公平评测至少固定基座、输出预算、采样步数、温度与测试执行环境。扩散模型还要报告每步提交多少 token、是否允许重掩以及失败样本的实际网络调用数。相同 wall-clock 下比较通过率，和相同前向次数下比较通过率，回答的是两个问题。后训练文章负责概率目标，代码评测文章负责把目标放回可执行协议。
