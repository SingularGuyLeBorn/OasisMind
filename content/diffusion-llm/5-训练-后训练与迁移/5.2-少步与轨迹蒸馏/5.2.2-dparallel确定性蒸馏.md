# dParallel:把确定性逼成并行

缓存与调度方法减少每步注意力,SlowFast 少的是揭开策略的静态.两边都不改「确定性从哪边先尖」.Chen,Fang,Ma,Yu,Wang 的 dParallel(arXiv:2509.26488)认为开源 LLaDA / Dream 之所以还要接近长度那么多步,是因为掩码格的置信度仍按邻居顺序爬到峰值.一步里网络已经给出全部边际,真正敢落盘的往往只有紧挨着明文的那一小撮.仓库 [czg1225/dParallel](https://github.com/czg1225/dParallel).

主表硬件是 NVIDIA RTX 6000 Ada.长度 256,半自回归块长 32.摘要 8.5× 是 LLaDA-8B-Instruct 在 GSM8K-CoT 零样本上的**时延**比:原版 256 步,18.6 秒到 30 步,2.2 秒,准确率 75.7% 到 76.1%.MBPP 3-shot:256 步,50.1 秒到 24 步,4.8 秒,10.5×,准确率 42.4% 到 40.8%.步数从 256 收到 30 是 88% 少步,时延倍数还含 DualCache 那种「步数不变但每步更便宜」对照不上的部分.报 8.5× 写任务,长度,卡,是秒不是 TPF.

d3LLM 的同一份蒸馏数据上,Qian 的表把 dParallel-LLaDA 写成 TPF 5.14,AUP 358.那是单卡 H100,另一套评测脚本.dParallel实验中8.5× 的分母是 18.6 秒.两套减不出「dParallel 到底 5 倍还是 8 倍」.

## 1. 能并行预测,不等于能并行确定

掩码扩散每步对所有 `[MASK]` 出边际,式 (2) 仍是乘积.其因子化误差来自因子分解误差来自「提交前互相看不见最终取值」.dParallel 补的观察更窄:就算你用阈值只揭尖的,尖的集合仍沿着已揭开的上下文**顺序**长大.Figure 2 在 LLaDA-Instruct,GSM8K 上画过三件事.平均置信度和对错正相关.位置上的平均置信度随步数从左往右推.单格轨迹也是错开着进平台,不是一排同时竖起来.

于是阈值并行有天花板.原文写:置信度阈值平均每步只能揭 3–4 个 token,质量能保住;再强迫多揭,低置信承诺会引发后续错误.SlowFast 的快阶段也在等一段地图先收敛.两边都表明「尖」是稀缺资源.dParallel 要把稀缺变成训练目标:让更多格在同一步里同时尖.

Teacher forcing 和 Diffusion Forcing 对齐的是轨迹 $Y$,不直接管熵.D2F 的不对称 KL 对齐的是块条件,学生看见脏前缀.dParallel 的老师和学生同骨架,老师先用半自回归采样写出一条回答,学生在这条回答的中间态上既要预测正确 token,又要把已经预测正确的那些格的熵压下去.轨迹可以几乎不变,确定性的时间表被改掉.

置信度地图为啥像从左往右扫,作者没有写成定理.半自回归块本身就是左到右;块内低置信 remask 也倾向先揭已经被上下文确定的格.双向注意力看得见右边的掩码,但右边全是 `[MASK]` 时,提供不了「下一个该是什么」的尖峰值.于是尖的集合跟着明文前缘走.块扩散的块间因果是结构上的前缘;这里连块内都有一层软前缘.certainty-forcing 要做的是:当前块里被掩的一半位置,只要字已经对,就强迫它们一起尖,不要等邻居先落盘.

## 2. Certainty-forcing:只对猜对的格加压

老师 $M_{\theta_T}$ 是冻结的预训练 dLLM.学生拷同一份权重.提示来自公开训练集,回答由老师自己生成,滤掉答错的.LLaDA-Instruct 用 GSM8K,PRM12K,部分 Numina-Math,半自回归长度 256,块长 32,约 92k 条.Dream-Instruct 同样生成轨迹,再加约 10k 条 AceCode 提示.目标 token 全部是自己模型写的,没有外挂标准答.这和 d3LLM 的「顺序来自老师,字来自标准答」不是同一份监督.d3LLM 的写过两家共用提示源,差别在标签怎么造.

训练时模仿半自回归中间态.抽块下标 $n$,前 $n$ 块保持明文当上下文;当前块以固定比例 $q$ 随机掩;后面的块全掩.$q=50\%$ 是消融里最好的一档.当前块叫 active,$\mathcal{M}_a$ 是其中被掩的位置.损失只加在 $\mathcal{M}_a$ 上,不是整句所有掩码格.传统 $1/t$ 会监督未来块里那些「还不该写」的位置;这里未来块只当上下文形状,不当监督.

一致性损失是交叉熵,监督老师轨迹上的字 $y_i$:

$$
\mathcal{L}_{\mathrm{Consistency}}=-\frac{1}{|\mathcal{M}_a|}\sum_{i\in\mathcal{M}_a}\log p_{\theta}(y_i\mid\tilde Y).
\tag{5}
$$

CE 一旦 argmax 对了,梯度很快变小,没有动力把 0.51 推到 0.95.确定性损失只加在学生**已经猜对**的掩码格 $\mathcal{M}_c$ 上.$\mathcal{M}_c=\{i\in\mathcal{M}_a\mid\arg\max_v p_\theta(v\mid\tilde Y)=y_i\}$.猜错的位置继续只吃交叉熵,等下一次预测正确了再进 $\mathcal{M}_c$.这和「对全部掩码格压熵」不是一句.全部压熵会奖励尖而错的峰值.

$$
\mathcal{L}_{\mathrm{Certainty}}=\frac{1}{|\mathcal{M}_c|}\sum_{i\in\mathcal{M}_c} H\bigl(p_{\theta}(\cdot\mid\tilde Y;T)\bigr),\qquad T=0.5.
\tag{7}
$$

总损失 $\mathcal{L}_{\mathrm{CFD}}=\mathcal{L}_{\mathrm{Consistency}}+\beta\mathcal{L}_{\mathrm{Certainty}}$,$\beta=2$.温度 $T$ 写在熵项的 softmax 里,推理熵阈值是另一把尺.

实现上 Complementary mask 把当前块的掩码图案取反再算一次损失,同一条 $\tilde Y$ 上两套 $\mathcal{M}_a$.附录一笔带过,没有消融表.主结果仍按 50% 单图案报.

![dParallel 以 certainty-forcing 压低正确 token 熵并减少并行采样步数](images/fig-dparallel-certainty-forcing.png)

> 图 1:左列是确定性仍按邻居爬.右列老师半自回归出轨迹,学生在当前块 50% 掩码上拟合 token,只对已经对的格压熵.底栏标出 GSM8K 时延提升 8.5×,MBPP 步数减少 10.5×,硬件是 RTX 6000 Ada.

图 1 解析:

- **L1–L2**:每步只有邻居尖.提前多揭等于提交平的边际.
- **L3**:只对齐 $Y$ 改不了爬升顺序.
- **R1**:老师半自回归,$L_b=32$.Dream 训练改成整句随机掩,见第 4 节.
- **R2**:上下文明文,当前块一半掩,未来全掩.
- **R3–R4**:式 (5) 拟合 token,式 (7) 压对的格.$\beta=2$.
- **F0**:8.5× $=18.6/2.2$.10.5× 是 MBPP 时延 50.1/4.8.不是 SlowFast Table 4,并非 d3LLM TPF.

附录还写 complementary mask,同一条样本把互补的掩码图案再训一次,提高 token 利用率.细节没有单独开表.主设定仍是当前块 50% 随机掩.

推理改成熵阈值半自回归 remask,和训练的「压熵」对齐.阈值 0.45 或 0.5,按任务选.这和 Fast-dLLM 的 max Softmax 0.9 使用不同统计量:一个看熵,一个看最大概率.尖的分布熵低,max $p$ 也高,实践上常选中同一批位置,具体门槛仍需分别校准.

原版逐步揭开把 $T$ 设成 256,等于一步大约揭一格.阈值把平均揭开数抬到 3–4.dParallel 把工作点推到 8 以上,靠的是训练时已经见过「当前块一半仍掩,但这些格必须尖」.推理阈值才能找到足够多的合格格.没有蒸馏,把阈值从 0.9 降到 0.5 只是多揭平的格,Table 1 的少步 64 已经把这条路的掉分写出来了.

## 5. 和 SlowFast,SDTT,d3LLM,CAP 各比一刀

SlowFast 训练免费,改 $S$.dParallel 改权重,让同一套阈值/熵规则每步能揭更多.15.63× 在 GPQA 长度 1024,4090,Base;8.5× 在 GSM8K 长度 256,6000 Ada,Instruct.分母,任务,是否改权重三套都不一样.可以叠:先蒸确定性,再动态 span.主表没有叠 SlowFast.

SDTT 蒸的是老师多步之后的分布,骨架停在 863M.dParallel 蒸的是「沿自己的半自回归轨迹,对的格更尖」,8B Instruct.SDTT 与dParallel使用不同模型和硬件.dParallel的8.5× 对照原版 256 步时延,不是对照带 KV 的 GPT-2.

d3LLM 伪轨迹把揭开顺序和标准答捆在一起,再叠 certainty-forcing(LLaDA 权重 2.0).Qian Table 1 里 dParallel TPF 5.14 低于 d3LLM 的 9.11,AUP 358 低于 637.那是「同数据,另一套测速」.dParallel Table 1 没有 TPF 列.报 dParallel 用 8.5× / 10.5×;报和 d3LLM 的相对位置用 Qian 的 TPF,并写 H100.

CAP 在已经对的位置压熵,提高 TPF,对照是 LLaDA 2.0 flash-CAP 535 TPS 对文内 AR 约 2.1×.dParallel 是 8B LoRA,不是 100B MoE 编译栈.压熵这一刀同族,尺度和对照物不同.

Fast-dLLM 原文 A100 上 GSM8K 长度 256 能到 54.4 tok/s,约 8.1×,对照物是逐步揭开的 Instruct.该实验的 Dual-Cache 基线同一任务只有 1.9×,因为步数固定为256,卡换成 6000 Ada,实现未必是 Wu 的 DualCache 主设定.1.9× 不能直接比较 8.1×.dParallel 的 8.5× 分母是「256 步 Python 循环的 18.6 秒」,和 54.4 tok/s 没有同一单位.要绝对吞吐,论文只给了秒,没给 TPS.18.6 秒生成多长,平均 TPS 等于长度除以秒,长度按 256 画布算是上限,真实写出的 token 更短.不能把 256/2.2≈116 TPS 写成产品规格,EOS 截断会改分子.

ReFusion 槽内 AR,A100 上 GSM8K 81.24 TPS.dParallel 不改注意力.Eso-LM 65× 对照无缓存 MDLM.分母三套.产品若能 LoRA 十小时量级,dParallel 是改确定性时间表;若不能改权重,回 SlowFast / DualCache.主表没有「dParallel + DualCache」.缓存与少步正交,叠了应再报一列.工程上可以叠,倍数不能用 8.5× 乘 1.9×.

SDTT 把老师 1024 步蒸成学生 32 步,目标是生成分布.dParallel 的老师轨迹长度就是 256 步半自回归,学生推理收到 30 步,靠的是每步揭得更多,不是把反向过程的时间网格减半.时间网格对齐那种 $k$ 整除 $m$,这里没有.两种少步机制不能合并.

### 5.1. 失效:长度 256,自蒸馏天花板,联合仍缺

主表画布 256.Instruct 块长 8,Nie GSM8K 78.6,长度 1024 的 SlowFast / Fast-dLLM 长前缀,都不是这张表.将 8.5× 外推到 1024 画布,步数分母会变,时延更会变.

自蒸馏滤掉老师答错的题.老师不会的题,学生没有可用教师轨迹.附录承认:基座弱,并行救不了分.92k 数学提示能把代码列的并行带起来,作者当成迁移;HumanEval 38.4 到 40.2 是小涨,不是从零学会写代码.Dream 加了 AceCode 才在代码列站稳.

熵阈值把「尖」写成可提交.校准差时,尖的错格会整批落盘,比 max-$p$ 阈值更松或更紧取决于温度 $T=0.5$.主表没有把熵阈值和 0.9 概率阈值做同一权重的逐列扫描.

确定性并行不是联合.一步 8 个 token 仍是 8 个边际.MBPP 掉到 40.8,代码搭配比 GSM8K 更疼,和 ParallelBench 的方向一致.主表没有 Shuffle.

训练 50% 固定掩,推理熵阈值.若产品把推理改回逐步揭开,蒸过的尖边际可能用不满,只剩 CE 微调过的质量.主表没有「蒸完再用 256 步原版采样器」那一行.

### 5.2. 为什么普通交叉熵不会主动把正确答案推到低熵

设某个被掩位置的目标 token 为 $y$,学生 logits 为 $z_v$,温度为一时的概率为 $p_v=\exp z_v/\sum_u\exp z_u$.一致性交叉熵是

$$
\ell_{\mathrm{CE}}=-\log p_y,
\qquad
\frac{\partial\ell_{\mathrm{CE}}}{\partial z_v}=p_v-\mathbf 1[v=y].
\tag{9}
$$

严格说,只要 $p_y<1$,交叉熵仍会继续推高正确 token,不会在 argmax 刚刚正确时突然停止.现稿前文所说「梯度很快变小」指的是相对现象:当 $p_y$ 已经高于其他类别,梯度范数随 $1-p_y$ 缩小;同一批样本里大量仍然猜错的困难位置贡献更大,优化器会优先修正错误,而不会专门把已正确位置从可用的 $0.6$ 推向适合阈值解码的 $0.95$.

这一区别很重要.分类准确率只看 $p_y$ 是否最大,并行提交却关心分布是否足够尖.假设三个候选的概率分别是 $(0.51,0.48,0.01)$ 与 $(0.95,0.04,0.01)$,两者 top-1 都正确,对后续推理的价值完全不同.第一组若与另一个同样摇摆的位置同时落盘,联合正确率在独立近似下只有 $0.51^2\approx0.26$;第二组则约为 $0.90$.dParallel 针对的就是从「已经答对」到「可以成批提交」之间的间隙.

熵项使用温度 $T=0.5$.令

$$
q_v(T)=\frac{\exp(z_v/T)}{\sum_u\exp(z_u/T)},
\qquad
H_T(z)=-\sum_v q_v(T)\log q_v(T).
\tag{10}
$$

较低温度会放大 logit 差.若正确 token 已是 argmax,最小化 $H_T$ 往往继续拉开它和次大候选;若 argmax 错误,同样操作会把错误峰值压得更尖.这就是集合 $\mathcal M_c$ 必须存在的原因.过滤条件把熵最小化限制在当前预测正确的位置,其余位置仍由交叉熵负责改方向.

熵对 logit 的梯度可以写成

$$
\frac{\partial H_T}{\partial z_k}
=-\frac{q_k}{T}\left(\log q_k+H_T\right).
\tag{11}
$$

概率高于几何平均水平的类别通常收到继续增大的方向,低概率类别继续降低.梯度含 $1/T$,低温不仅改变分布,也放大梯度.因此 $\beta=2$ 和 $T=0.5$ 是耦合超参数:只比较 $\beta$ 而不写温度,无法判断熵项的实际强度.

$\mathcal M_c$ 由学生当前 argmax 动态决定,目标不是一个固定光滑函数.某个位置从猜错变为猜对时,它突然获得熵梯度;若下一步又翻回错误,熵项再次消失.在决策边界附近会出现门控抖动.实现中 argmax 集合通常停止梯度,不会对「进入集合」这个离散事件求导.训练依靠连续的 CE 梯度把位置推过边界,再由熵项拉开间隔.

这种门控也产生选择偏差.容易位置更早进入 $\mathcal M_c$,接受更多轮低熵训练;困难位置长期只有 CE.最终模型的确定性提升会优先集中在已有上下文就能确定的 token,例如常见标点、固定短语或算术模板.这有利于增加每步可提交数量,却不保证语义关键的长程决策同样提前收敛.

可以把 certainty-forcing 理解成一种带正确性门控的 margin 增强.它没有显式写出 top-1 与 top-2 的间隔,但降低熵会把概率质量从尾部收回主峰.若分布有两个接近峰值,熵梯度会根据当前微小优势放大其中一个;CE 用目标 token 确保被放大的方向正确.两项缺一时,Table 3 的现象便有了数学解释:只有 CE 能保方向但不够尖,只有熵能变尖却可能沿错误方向自我强化.

### 5.3. 从单格置信度到一批 token 的提交风险

推理时设当前 active block 的被掩位置集合为 $M$.模型给每个位置一个边际分布 $p_i$.阈值解码选择集合

$$
A_\tau=\{i\in M:H(p_i)\leq\tau\},
\tag{12}
$$

并同时写入各自 argmax.如果 $A_\tau$ 为空,实现还需要至少选一个最确定位置,否则过程会停住.这条保底规则意味着步数不会无限增加,也意味着再平的分布最终仍会被强制提交.报告阈值时还应说明空集合如何处理.

熵与最大概率相关,但不存在与词表无关的一一映射.二分类下,给定 $p_{\max}$ 基本确定熵;五万词表下,剩余质量可以集中在一个竞争者,也可以摊在数万个尾部 token 上.两种分布具有相同 $p_{\max}$,熵差别很大.因此熵阈值 $0.5$ 不能机械换算成 Fast-dLLM 的最大概率阈值 $0.9$.

对一个 $K$ 类分布,给定最大概率 $m$,最低熵出现在剩余质量集中于一个类别,最高熵出现在剩余质量均匀铺给 $K-1$ 个类别:

$$
h_2(m)\leq H(p)\leq h_2(m)+(1-m)\log(K-1),
\tag{13}
$$

其中 $h_2$ 是二元熵.词表越大,上界越宽.熵门槛更偏爱尾部质量集中的分布,最大概率门槛只看主峰.二者可能选出不同位置,即使平均揭示数相同.

若每个位置的 top-1 校准概率为 $c_i$,同时提交一组 token 全部正确的概率在独立假设下为 $\prod_{i\in A}c_i$.八个位置即使各自有 $0.95$ 置信度,全部正确也只有 $0.95^8\approx0.66$.真实错误还会相关,例如同一个错误中间结论使后续数字一起错,乘积只能当粗略参照.

并行解码需要衡量错误落盘后对后续条件分布的影响，平均单格错误率不足以表达这种风险.一个标点错了可能下一步自行修复或几乎无影响;一个变量名、函数名或推导符号错了会改变多个位置.只按熵排序默认每个 token 的错误代价相同,dParallel 没有额外学习语义风险权重.

把一次提交写成集合决策,理想目标可表示为

$$
\max_{A\subseteq M}\ |A|
\quad\text{s.t.}\quad
\Pr(\hat y_A=y_A\mid \tilde Y)\geq1-\delta.
\tag{14}
$$

模型只有因子化边际,无法直接计算联合正确概率.熵阈值用逐位置条件替代联合约束,计算简单,但忽略相关性.ParallelBench 所测的联合依赖正落在这个缺口里.确定性蒸馏能提高边际尖锐度,没有为式 (14) 提供准确的联合概率.

一个反例是复制任务:两个被掩位置必须输出同一个随机 bit.每个位置边际都是 $(0.5,0.5)$,联合分布只在 `00` 和 `11` 上有质量.边际熵很高,阈值解码不敢提交,但若能联合抽样,两个位置可一步生成且永远满足约束.另一个反例是两个位置边际都达到 $0.99$,却因共享的少数错误模式而高度相关;批量提交的失败概率接近 $0.01$,而非独立估计的 $0.0199$.只看熵既可能低估并行性,也可能误估风险.

dParallel 选择了一条现实路线:不改输出头,不显式建联合,而是让更多边际在老师轨迹上提前变尖.它改善现有阈值采样器能利用的信号,没有声称解决所有并行依赖.代码任务掉分与数学长推导掉分可以从这里理解:结构约束越强,边际尖锐越不能代替联合协调.

阈值还决定停止时间.当当前块所有位置都揭开,解码进入下一块;若每步平均揭示 $r$ 个 token,块长 $B$ 的理想步数约为 $B/r$.但 $r$ 随状态变化:最开始上下文少,合格位置少;中段确定性扩散后上升;末尾只剩难点,又可能下降.用总长度除以步数得到的 8.5 token/步只是全程平均,不代表每一步固定揭八个.

### 5.4. 训练掩码为何必须贴近推理访问到的状态

学生训练输入不是任意 MLM 掩码.半自回归生成把回答切成长度 $B$ 的块,先前块已经确定,当前块部分掩码,未来块全掩.设块下标为 $n$,当前块掩码率为 $q$,可写成

$$
\tilde Y_i=
\begin{cases}
y_i,&i<nB,\\
m_i y_i+(1-m_i)[\mathrm{MASK}],&nB\leq i<(n+1)B,\\
[\mathrm{MASK}],&i\geq(n+1)B,
\end{cases}
\tag{15}
$$

其中当前块的 $m_i\sim\mathrm{Bernoulli}(1-q)$.这个分布同时保留已完成前缀、当前局部明文和未开始的未来.普通全句随机掩码会让未来块偶尔泄漏 token,而实际半自回归推理中这些位置必然全掩;训练条件比推理更容易,确定性可能建立在不存在的右侧明文上.

固定 $q=0.5$ 的意义不仅是一半监督、一半上下文.若 $q$ 太小,当前块大部分已知,每个被掩位置很容易,但训练状态接近块尾,模型很少学习块刚开始时的高掩码情形.若 $q$ 太大,上下文不足,许多位置猜错,进入 $\mathcal M_c$ 的样本少,熵项几乎没有作用.中间掩码率同时提供可预测位置和足够数量的监督位置.

Table 4 中全掩 $q=1$ 步数仍少,准确率却下降,正符合这一机制.熵项可以把少数已猜对位置变尖,但缺少块内明文时,被选中的正确位置更偏向容易模板;困难位置的方向没有学好.速度指标只看有多少位置越过阈值,不会检查越过阈值的位置是否覆盖了真正关键的依赖.

随机 $q$ 理论上覆盖更多推理阶段,实验却不如固定 50%.一种可能解释是有限训练预算下,随机掩码把样本分散到大量条件难度,每种状态得到的熵门控次数减少.固定 $q$ 则集中强化一个能向相邻掩码率泛化的工作点.论文消融给出结果,没有把这一解释证明为唯一原因.

Complementary mask 让同一当前块的两套掩码互补.若第一套掩住集合 $A$,第二套掩住 $B\setminus A$,每个位置至少在一套视图里成为监督目标,也至少在另一套视图里可能充当明文上下文.它提高 token 利用率,但两次前向的条件不同,不能把损失简单理解为把 batch 翻倍.

互补视图还形成一种局部双向训练.位置 $i$ 在第一视图预测时可能看到 $j$,第二视图则由 $j$ 预测时看到 $i$.这种对称覆盖有助于减少固定掩码图案带来的方向偏差.附录没有单独消融,所以不能把主表收益定量分配给 complementary mask;它更适合作为训练分布构造的一部分说明.

推理访问的是学生自己的状态,训练输入来自老师生成的正确轨迹,两者仍有 exposure gap.学生一旦提交错误 token,后续会条件于错误前缀;训练数据滤掉老师答错题,也没有系统注入学生错误.确定性越高、并行提交越多,一次错误改变的后续状态越远,这项分布偏移可能更严重.

可以设想把学生在线采样状态混入训练,类似 DAgger:让学生生成中间轨迹,再用老师或标准答案标注应恢复的 token.这样能覆盖错误上下文,代价是生成数据昂贵,且老师在错误状态上的条件分布未必可靠.dParallel 选择离线自蒸馏,保持方法简单和训练成本可控.

Dream 的 AR 初始化让掩码分布更敏感.原模型权重带有强左到右归纳偏置,若继续使用清晰的块间因果训练,优化可能强化 next-token 路线,削弱全句双向去噪.改用整句随机掩码可以保住扩散式条件建模,推理再用块长 32.这项训练–推理不一致是为了避免更强的模型退化,也解释了 Dream 并行收益较低的一部分可能来源.

### 5.5. 自蒸馏保留了什么,又改变了什么

老师先按原始采样器生成回答 $Y=(y_1,\ldots,y_L)$,学生在 $Y$ 的腐蚀版本上训练.一致性损失把老师最终写下的 token 当硬标签,没有逐步匹配老师每一时刻的完整概率分布.因此「跟随原轨迹」主要指输出内容与半自回归块结构,不意味着学生的每步转移核与老师相同.

若老师在某位置给 $(0.55,0.45)$ 并采样或 argmax 得到第一个 token,硬标签 CE 会把学生推向 $(1,0)$;certainty loss 又加强这种趋势.学生保留老师选择,同时丢掉老师对第二候选的不确定性.这正是少步所需的确定性压缩,也意味着教师分布中的多样性可能收缩.

训练集过滤掉最终答案错误的轨迹,得到条件分布

$$
p_{\mathrm{train}}(Y\mid X)
=p_T(Y\mid X,\mathrm{correct}(Y)=1).
\tag{16}
$$

它和老师无条件生成分布不同.学生看到的是老师成功模式,不会模仿失败轨迹.这可能解释 GSM8K 准确率略升:蒸馏数据本身经过正确性选择.同时,老师容易答对的题和推导风格被过度代表,难题及多样解法被筛掉.

若正确性验证只看最终答案,中间推导可能包含偶然抵消的错误.学生仍会把整条轨迹当标签,并把其中已经猜对的局部 token 压到低熵.最终过滤不能保证每一步推理可靠.数学任务中 MATH 比 GSM8K 更复杂,长链条的这种噪声更可能积累.

自蒸馏与标准知识蒸馏的温度目标不同.经典 KD 常最小化教师与学生软分布的 KL,保留类别相似性;dParallel 的核心是硬 token 一致性加学生自身熵.教师提供「写什么」,学生熵项规定「多快确定」.因此老师无需额外前向输出全词表概率,数据生成后可离线训练.

设学生在某位置已经正确,熵项不关心其主峰是否等于老师当时的概率,只要求更尖.从路径角度看,学生改变了到达相同离散答案的时间参数化.原来第 20 步才越过阈值的位置可能第 5 步就越过,多个位置于是并行落盘.终点轨迹近似保留,中间置信度轨迹被压缩.

这种时间压缩没有显式单调约束.某位置在早期变尖后,加入新 token 作为上下文仍可能改变预测甚至翻转.推理一旦提交就通常不再 mask,早期高置信错误难以撤回.训练热图显示平均确定性提前,不能保证每个样本、每个位置的置信度随步数单调.

LoRA 限制了可改变的参数子空间.它有助于保留基座知识,训练成本低,也可能限制确定性地图的重塑幅度.rank 32、16、128 在三类模型上不同,结果不能只归因于底座.更高 rank 是否继续提高并行度、是否加重能力遗忘,论文没有系统曲线.

从信息论看,最小化条件熵倾向于减少同一腐蚀输入下输出多样性.如果任务本来有多个等价答案,老师轨迹只选其中一个,学生会更坚决地复现该模式.代码题按单元测试允许多种实现,硬轨迹蒸馏可能牺牲风格覆盖,而 pass@1 不一定反映这种变化.

蒸馏数据来自数学和部分代码提示,模型在未覆盖领域上的并行性取决于迁移.确定性是词法模板、句法结构和任务推理共同作用的结果.常见语言结构可能迁移,专业知识决策未必迁移.没有 MMLU、长文写作和开放对话数据时,不能把 GSM8K 的 30 步直接视为通用服务步数.

### 5.6. 步数、延迟和真正并行度之间的换算

原版长度 256、步数 256,容易让人以为每步只生成一个 token.实际每步模型对当前掩码位置全部输出分布,采样器只提交少数位置.步数是网络前向次数附近的量,token 数是画布上限,二者的比值给出平均提交宽度.

若总生成 token 数为 $L$,前向次数为 $S$,平均表面并行度可定义为

$$
r_{\mathrm{avg}}=\frac{L}{S}.
\tag{17}
$$

GSM8K 用画布 256 近似计算得到 $256/30\approx8.5$.若样本提前遇到 EOS,真实 $L<256$,实际每步新增 token 少于 8.5.论文的步数由采样循环报告,画布长度不能自动当成有效输出长度.

端到端延迟可粗分为

$$
T_{\mathrm{total}}
=S\,(T_{\mathrm{model}}+T_{\mathrm{select}}+T_{\mathrm{sync}})
+T_{\mathrm{fixed}}.
\tag{18}
$$

少步主要降低乘在 $S$ 上的部分.提示编码、tokenizer、数据搬运和固定启动成本不会同比下降.因此步数从 256 到 30 的 8.53 倍与实测 18.6/2.2 的 8.45 倍恰好接近,只说明该实验固定成本较小;换到短回答、高并发服务或不同实现后,两者可能分开.

Dual-Cache 不减 $S$,而是降低 $T_{\mathrm{model}}$;dParallel 降低 $S$,每步计算图大致不变.两者理论上可叠加,总收益受剩余固定成本限制.若缓存使模型前向便宜两倍,dParallel 再把步数减八倍,端到端不一定达到十六倍,因为选择、同步和内存访问占比会上升.

与 AR 比较更复杂.AR 每步只为下一个位置产生有效 token,但 KV cache 让每步只处理一个新 query;掩码扩散每步对整段活跃画布运行双向网络.即使 dParallel 每步提交八个 token,单步 FLOPs 仍可能高于 AR 的单 token decode.少步倍率只相对同一 dLLM 原版,不能直接当成相对 AR 的吞吐倍率.

块长 $B$ 给并行度设置上限.半自回归要求完成当前块后才能进入下一块,长度 $L$ 至少需要 $L/B$ 个块阶段.若一个块能一步完成,理论最少步数约为块数;实际还要在块内迭代.长度 256、块长 32 有 8 个块,dParallel 用 30 步,平均每块约 3.75 步,已经远少于原版每块约 32 步,但离一步一块仍有空间.

提示越长,每步注意力成本越高;生成长度增加时,块数和步骤也增加.论文四个任务的秒数差异不只来自步数,还来自 prompt 长度、实际 EOS 和评测模板.MBPP 原版 256 步却用 50.1 秒,GSM8K 同为 256 步只用 18.6 秒,说明每步成本并不固定.10.5 倍与 8.5 倍不能仅由揭示宽度解释.

硬件也改变瓶颈.大矩阵乘更适合 GPU,小 batch 的 Python 循环和同步可能占较多时间;减少步骤会同时减少 kernel launch,所以实测加速可能接近步数比.编译、CUDA graph 或更大 batch 降低循环开销后,同样少步比例对应的延迟收益可能变化.

报告吞吐还要区分单请求与服务吞吐.阈值解码使不同样本需要不同步数,batch 内若等待最慢样本,平均步数优势被尾部拖累;若动态移出已完成样本,会产生不规则 batch 和调度开销.论文单卡任务评测的秒数不等于多用户 continuous batching 的 TPS.

并行度也可用每步新确定 token 的分布描述,而不只给平均值.均值相同的两个模型,一个稳定每步八个,另一个多数步一个、少数步几十个,对 batch 同步、内存峰值和错误传播的影响不同.Figure 5/6 的热图给出形状,主表没有报告方差或尾部步数.

### 5.7. 熵降低不等于概率校准改善

模型校准要求置信度与经验正确率匹配.若所有置信度约 0.9 的预测中有 90% 正确,可称这一档校准良好.熵最小化追求更尖,可能把原来 0.7 且 70% 正确的预测推到 0.95,正确率没有同步提高时,模型会变得过度自信.

dParallel 用 $\mathcal M_c$ 只在训练样本当前预测正确时压熵,降低了把已知错误峰值变尖的风险.但训练正确不代表测试正确,也不保证分布外输入上的校准.学生可以在训练轨迹上学会「这些形状通常正确」,遇到陌生任务时仍以同样低熵输出错误答案.

熵阈值解码依赖排序和绝对尺度.若蒸馏让所有位置的熵整体下降,固定阈值会一次选更多位置;若下降幅度在任务间不同,同一个 0.45 不再对应相同错误风险.论文按任务选择 0.45 或 0.5,本身说明阈值需要校准,并非模型训练后存在一个普适常数.

温度缩放可以在验证集上重新校准概率,但推理门槛也随之变化.将 logits 除以更高温度会提高熵、减少提交数,可能恢复准确率却损失速度.训练中的 $T=0.5$ 只用于 certainty loss 的分布,推理是否使用同一温度必须按实现核对,两者不能视作同一个旋钮.

可用可靠性图检查风险:把位置按预测熵或 $p_{\max}$ 分桶,统计每桶 token 正确率,再按解码步和任务拆分.更关键的是统计「提交后最终仍正确」,因为当下 argmax 正确也可能在允许 remask 的采样器里发生变化.论文主要报告最终任务准确率与热图,没有完整校准曲线.

Expected Calibration Error 仍不够.阈值只使用低熵尾部,全分布平均 ECE 可能很好,而尾部恰好过度自信.更合适的是选择性预测风险:

$$
R(\tau)=\Pr(\hat y_i\neq y_i\mid H(p_i)\leq\tau),
\qquad
C(\tau)=\Pr(H(p_i)\leq\tau),
\tag{19}
$$

$R$ 是被提交位置的错误率,$C$ 是覆盖率.理想模型在提高覆盖率时风险缓慢上升.dParallel 的目标可理解为把风险–覆盖曲线向右推,主表的步数与准确率只是这条曲线上的一个工作点.

序列级任务准确率放大选择风险.一条推导中任意关键 token 错误都可能使最终答案失败,因此 token 风险的小变化会造成更大的 exact-match 变化.相反,HumanEval 的单元测试对空格、变量名等多种 token 序列等价,token 级偏差不一定降低 pass@1.不同任务的风险函数不同,同一熵阈值不能保证同等质量.
