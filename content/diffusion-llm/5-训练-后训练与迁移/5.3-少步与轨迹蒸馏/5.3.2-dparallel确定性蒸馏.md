# dParallel:把确定性逼成并行

缓存与调度方法减少每步注意力,SlowFast 少的是揭开策略的静态.两边都不改「确定性从哪边先尖」.Chen,Fang,Ma,Yu,Wang 的 dParallel(arXiv:2509.26488)认为开源 LLaDA / Dream 之所以还要接近长度那么多步,是因为掩码格的置信度仍按邻居顺序爬到峰值.一步里网络已经给出全部边际,真正敢落盘的往往只有紧挨着明文的那一小撮.仓库 [czg1225/dParallel](https://github.com/czg1225/dParallel).

主表硬件是 NVIDIA RTX 6000 Ada.长度 256,半自回归块长 32.摘要 8.5× 是 LLaDA-8B-Instruct 在 GSM8K-CoT 零样本上的**时延**比:原版 256 步,18.6 秒到 30 步,2.2 秒,准确率 75.7% 到 76.1%.MBPP 3-shot:256 步,50.1 秒到 24 步,4.8 秒,10.5×,准确率 42.4% 到 40.8%.步数从 256 收到 30 是 88% 少步,时延倍数还含 DualCache 那种「步数不变但每步更便宜」对照不上的部分.报 8.5× 写任务,长度,卡,是秒不是 TPF.

d3LLM 的同一份蒸馏数据上,Qian 的表把 dParallel-LLaDA 写成 TPF 5.14,AUP 358.那是单卡 H100,另一套评测脚本.dParallel实验中8.5× 的分母是 18.6 秒.两套减不出「dParallel 到底 5 倍还是 8 倍」.

## 1. 能并行预测,不等于能并行确定

掩码扩散每步对所有 `[MASK]` 出边际,式 (2) 仍是乘积.其因子化误差来自因子分解误差来自「提交前互相看不见最终取值」.dParallel 补的观察更窄:就算你用阈值只揭尖的,尖的集合仍沿着已揭开的上下文**顺序**长大.Figure 2 在 LLaDA-Instruct,GSM8K 上画过三件事.平均置信度和对错正相关.位置上的平均置信度随步数从左往右推.单格轨迹也是错开着进平台,不是一排同时竖起来.

于是阈值并行有天花板.原文写:置信度阈值平均每步只能揭 3–4 个 token,质量能保住;再强迫多揭,低置信承诺会引发后续错误.SlowFast 的快阶段也在等一段地图先收敛.两边都表明「尖」是稀缺资源.dParallel 要把稀缺变成训练目标:让更多格在同一步里同时尖.

Teacher forcing 和 Diffusion Forcing 对齐的是轨迹 $Y$,不直接管熵.D2F 的不对称 KL 对齐的是块条件,学生看见脏前缀.dParallel 的老师和学生同骨架,老师先用半自回归采样写出一条回答,学生在这条回答的中间态上既要预测正确 token,又要把已经预测正确的那些格的熵压下去.轨迹可以几乎不变,确定性的时间表被改掉.

置信度地图为啥像从左往右扫,作者没有写成定理.半自回归块本身就是左到右;块内低置信 remask 也倾向先揭已经被上下文确定的格.双向注意力看得见右边的掩码,但右边全是 `[MASK]` 时,提供不了「下一个该是什么」的尖峰值.于是尖的集合跟着明文前缘走.块扩散的块间因果是结构上的前缘;这里连块内都有一层软前缘.certainty-forcing 要做的是:当前块里被掩的一半位置,只要字已经对,就强迫它们一起尖,不要等邻居先落盘.

## 2. Certainty-forcing:只对猜对的格加压

老师 $M_{\theta_T}$ 是冻结的预训练 dLLM.学生拷同一份权重.提示来自公开训练集,回答由老师自己生成,滤掉答错的.LLaDA-Instruct 用 GSM8K,PRM12K,部分 Numina-Math,半自回归长度 256,块长 32,约 92k 条.Dream-Instruct 同样生成轨迹,再加约 10k 条 AceCode 提示.目标 token 全部是自己模型写的,没有外挂标准答.这和 d3LLM 的「顺序来自老师,字来自标准答」不是同一份监督.d3LLM 的写过两家共用提示源,差别在标签怎么造.

训练时模仿半自回归中间态.抽块下标 $n$,前 $n$ 块保持明文当上下文;当前块以固定比例 $q$ 随机掩;后面的块全掩.$q=50\%$ 是消融里最好的一档.当前块叫 active,$\mathcal{M}_a$ 是其中被掩的位置.损失只加在 $\mathcal{M}_a$ 上,不是整句所有掩码格.传统 $1/t$ 会监督未来块里那些「还不该写」的位置;这里未来块只当上下文形状,不当监督.

一致性损失是交叉熵,监督老师轨迹上的字 $y_i$:

$$
\mathcal{L}_{\mathrm{Consistency}}=-\frac{1}{|\mathcal{M}_a|}\sum_{i\in\mathcal{M}_a}\log p_{\theta}(y_i\mid\tilde Y).
\tag{5}
$$

CE 一旦 argmax 对了,梯度很快变小,没有动力把 0.51 推到 0.95.确定性损失只加在学生**已经猜对**的掩码格 $\mathcal{M}_c$ 上.$\mathcal{M}_c=\{i\in\mathcal{M}_a\mid\arg\max_v p_\theta(v\mid\tilde Y)=y_i\}$.猜错的位置继续只吃交叉熵,等下一次预测正确了再进 $\mathcal{M}_c$.这和「对全部掩码格压熵」不是一句.全部压熵会奖励尖而错的峰值.

$$
\mathcal{L}_{\mathrm{Certainty}}=\frac{1}{|\mathcal{M}_c|}\sum_{i\in\mathcal{M}_c} H\bigl(p_{\theta}(\cdot\mid\tilde Y;T)\bigr),\qquad T=0.5.
\tag{7}
$$

总损失 $\mathcal{L}_{\mathrm{CFD}}=\mathcal{L}_{\mathrm{Consistency}}+\beta\mathcal{L}_{\mathrm{Certainty}}$,$\beta=2$.温度 $T$ 写在熵项的 softmax 里,推理熵阈值是另一把尺.

实现上 Complementary mask 把当前块的掩码图案取反再算一次损失,同一条 $\tilde Y$ 上两套 $\mathcal{M}_a$.附录一笔带过,没有消融表.主结果仍按 50% 单图案报.

![dParallel 以 certainty-forcing 压低正确 token 熵并减少并行采样步数](images/fig-dparallel-certainty-forcing.png)

> 图 1:左列是确定性仍按邻居爬.右列老师半自回归出轨迹,学生在当前块 50% 掩码上拟合 token,只对已经对的格压熵.底栏标出 GSM8K 时延提升 8.5×,MBPP 步数减少 10.5×,硬件是 RTX 6000 Ada.

图 1 解析:

- **L1–L2**:每步只有邻居尖.提前多揭等于提交平的边际.
- **L3**:只对齐 $Y$ 改不了爬升顺序.
- **R1**:老师半自回归,$L_b=32$.Dream 训练改成整句随机掩,见第 4 节.
- **R2**:上下文明文,当前块一半掩,未来全掩.
- **R3–R4**:式 (5) 拟合 token,式 (7) 压对的格.$\beta=2$.
- **F0**:8.5× $=18.6/2.2$.10.5× 是 MBPP 时延 50.1/4.8.不是 SlowFast Table 4,并非 d3LLM TPF.

附录还写 complementary mask,同一条样本把互补的掩码图案再训一次,提高 token 利用率.细节没有单独开表.主设定仍是当前块 50% 随机掩.

推理改成熵阈值半自回归 remask,和训练的「压熵」对齐.阈值 0.45 或 0.5,按任务选.这和 Fast-dLLM 的 max Softmax 0.9 使用不同统计量:一个看熵,一个看最大概率.尖的分布熵低,max $p$ 也高,实践上常选中同一批位置,具体门槛仍需分别校准.

原版逐步揭开把 $T$ 设成 256,等于一步大约揭一格.阈值把平均揭开数抬到 3–4.dParallel 把工作点推到 8 以上,靠的是训练时已经见过「当前块一半仍掩,但这些格必须尖」.推理阈值才能找到足够多的合格格.没有蒸馏,把阈值从 0.9 降到 0.5 只是多揭平的格,Table 1 的少步 64 已经把这条路的掉分写出来了.

## 5. 和 SlowFast,SDTT,d3LLM,CAP 各比一刀

SlowFast 训练免费,改 $S$.dParallel 改权重,让同一套阈值/熵规则每步能揭更多.15.63× 在 GPQA 长度 1024,4090,Base;8.5× 在 GSM8K 长度 256,6000 Ada,Instruct.分母,任务,是否改权重三套都不一样.可以叠:先蒸确定性,再动态 span.主表没有叠 SlowFast.

SDTT 蒸的是老师多步之后的分布,骨架停在 863M.dParallel 蒸的是「沿自己的半自回归轨迹,对的格更尖」,8B Instruct.SDTT 与dParallel使用不同模型和硬件.dParallel的8.5× 对照原版 256 步时延,不是对照带 KV 的 GPT-2.

d3LLM 伪轨迹把揭开顺序和标准答捆在一起,再叠 certainty-forcing(LLaDA 权重 2.0).Qian Table 1 里 dParallel TPF 5.14 低于 d3LLM 的 9.11,AUP 358 低于 637.那是「同数据,另一套测速」.dParallel Table 1 没有 TPF 列.报 dParallel 用 8.5× / 10.5×;报和 d3LLM 的相对位置用 Qian 的 TPF,并写 H100.

CAP 在已经对的位置压熵,提高 TPF,对照是 LLaDA 2.0 flash-CAP 535 TPS 对文内 AR 约 2.1×.dParallel 是 8B LoRA,不是 100B MoE 编译栈.压熵这一刀同族,尺度和对照物不同.

Fast-dLLM 原文 A100 上 GSM8K 长度 256 能到 54.4 tok/s,约 8.1×,对照物是逐步揭开的 Instruct.该实验的 Dual-Cache 基线同一任务只有 1.9×,因为步数固定为256,卡换成 6000 Ada,实现未必是 Wu 的 DualCache 主设定.1.9× 不能直接比较 8.1×.dParallel 的 8.5× 分母是「256 步 Python 循环的 18.6 秒」,和 54.4 tok/s 没有同一单位.要绝对吞吐,论文只给了秒,没给 TPS.18.6 秒生成多长,平均 TPS 等于长度除以秒,长度按 256 画布算是上限,真实写出的 token 更短.不能把 256/2.2≈116 TPS 写成产品规格,EOS 截断会改分子.

ReFusion 槽内 AR,A100 上 GSM8K 81.24 TPS.dParallel 不改注意力.Eso-LM 65× 对照无缓存 MDLM.分母三套.产品若能 LoRA 十小时量级,dParallel 是改确定性时间表;若不能改权重,回 SlowFast / DualCache.主表没有「dParallel + DualCache」.缓存与少步正交,叠了应再报一列.工程上可以叠,倍数不能用 8.5× 乘 1.9×.

SDTT 把老师 1024 步蒸成学生 32 步,目标是生成分布.dParallel 的老师轨迹长度就是 256 步半自回归,学生推理收到 30 步,靠的是每步揭得更多,不是把反向过程的时间网格减半.时间网格对齐那种 $k$ 整除 $m$,这里没有.两种少步机制不能合并.

### 6. 失效:长度 256,自蒸馏天花板,联合仍缺

主表画布 256.Instruct 块长 8,Nie GSM8K 78.6,长度 1024 的 SlowFast / Fast-dLLM 长前缀,都不是这张表.将 8.5× 外推到 1024 画布,步数分母会变,时延更会变.

自蒸馏滤掉老师答错的题.老师不会的题,学生没有可用教师轨迹.附录承认:基座弱,并行救不了分.92k 数学提示能把代码列的并行带起来,作者当成迁移;HumanEval 38.4 到 40.2 是小涨,不是从零学会写代码.Dream 加了 AceCode 才在代码列站稳.

熵阈值把「尖」写成可提交.校准差时,尖的错格会整批落盘,比 max-$p$ 阈值更松或更紧取决于温度 $T=0.5$.主表没有把熵阈值和 0.9 概率阈值做同一权重的逐列扫描.

确定性并行不是联合.一步 8 个 token 仍是 8 个边际.MBPP 掉到 40.8,代码搭配比 GSM8K 更疼,和 ParallelBench 的方向一致.主表没有 Shuffle.

训练 50% 固定掩,推理熵阈值.若产品把推理改回逐步揭开,蒸过的尖边际可能用不满,只剩 CE 微调过的质量.主表没有「蒸完再用 256 步原版采样器」那一行.

### 6.1. 为什么普通交叉熵不会主动把正确答案推到低熵

设某个被掩位置的目标 token 为 $y$,学生 logits 为 $z_v$,温度为一时的概率为 $p_v=\exp z_v/\sum_u\exp z_u$.一致性交叉熵是

$$
\ell_{\mathrm{CE}}=-\log p_y,
\qquad
\frac{\partial\ell_{\mathrm{CE}}}{\partial z_v}=p_v-\mathbf 1[v=y].
\tag{9}
$$

严格说,只要 $p_y<1$,交叉熵仍会继续推高正确 token,不会在 argmax 刚刚正确时突然停止.现稿前文所说「梯度很快变小」指的是相对现象:当 $p_y$ 已经高于其他类别,梯度范数随 $1-p_y$ 缩小;同一批样本里大量仍然猜错的困难位置贡献更大,优化器会优先修正错误,而不会专门把已正确位置从可用的 $0.6$ 推向适合阈值解码的 $0.95$.

这一区别很重要.分类准确率只看 $p_y$ 是否最大,并行提交却关心分布是否足够尖.假设三个候选的概率分别是 $(0.51,0.48,0.01)$ 与 $(0.95,0.04,0.01)$,两者 top-1 都正确,对后续推理的价值完全不同.第一组若与另一个同样摇摆的位置同时落盘,联合正确率在独立近似下只有 $0.51^2\approx0.26$;第二组则约为 $0.90$.dParallel 针对的就是从「已经答对」到「可以成批提交」之间的间隙.

熵项使用温度 $T=0.5$.令

$$
q_v(T)=\frac{\exp(z_v/T)}{\sum_u\exp(z_u/T)},
\qquad
H_T(z)=-\sum_v q_v(T)\log q_v(T).
\tag{10}
$$

较低温度会放大 logit 差.若正确 token 已是 argmax,最小化 $H_T$ 往往继续拉开它和次大候选;若 argmax 错误,同样操作会把错误峰值压得更尖.这就是集合 $\mathcal M_c$ 必须存在的原因.过滤条件把熵最小化限制在当前预测正确的位置,其余位置仍由交叉熵负责改方向.

熵对 logit 的梯度可以写成

$$
\frac{\partial H_T}{\partial z_k}
=-\frac{q_k}{T}\left(\log q_k+H_T\right).
\tag{11}
$$

概率高于几何平均水平的类别通常收到继续增大的方向,低概率类别继续降低.梯度含 $1/T$,低温不仅改变分布,也放大梯度.因此 $\beta=2$ 和 $T=0.5$ 是耦合超参数:只比较 $\beta$ 而不写温度,无法判断熵项的实际强度.

$\mathcal M_c$ 由学生当前 argmax 动态决定,目标不是一个固定光滑函数.某个位置从猜错变为猜对时,它突然获得熵梯度;若下一步又翻回错误,熵项再次消失.在决策边界附近会出现门控抖动.实现中 argmax 集合通常停止梯度,不会对「进入集合」这个离散事件求导.训练依靠连续的 CE 梯度把位置推过边界,再由熵项拉开间隔.

这种门控也产生选择偏差.容易位置更早进入 $\mathcal M_c$,接受更多轮低熵训练;困难位置长期只有 CE.最终模型的确定性提升会优先集中在已有上下文就能确定的 token,例如常见标点、固定短语或算术模板.这有利于增加每步可提交数量,却不保证语义关键的长程决策同样提前收敛.

可以把 certainty-forcing 理解成一种带正确性门控的 margin 增强.它没有显式写出 top-1 与 top-2 的间隔,但降低熵会把概率质量从尾部收回主峰.若分布有两个接近峰值,熵梯度会根据当前微小优势放大其中一个;CE 用目标 token 确保被放大的方向正确.两项缺一时,Table 3 的现象便有了数学解释:只有 CE 能保方向但不够尖,只有熵能变尖却可能沿错误方向自我强化.

### 6.2. 从单格置信度到一批 token 的提交风险

推理时设当前 active block 的被掩位置集合为 $M$.模型给每个位置一个边际分布 $p_i$.阈值解码选择集合

$$
A_\tau=\{i\in M:H(p_i)\leq\tau\},
\tag{12}
$$

并同时写入各自 argmax.如果 $A_\tau$ 为空,实现还需要至少选一个最确定位置,否则过程会停住.这条保底规则意味着步数不会无限增加,也意味着再平的分布最终仍会被强制提交.报告阈值时还应说明空集合如何处理.

熵与最大概率相关,但不存在与词表无关的一一映射.二分类下,给定 $p_{\max}$ 基本确定熵;五万词表下,剩余质量可以集中在一个竞争者,也可以摊在数万个尾部 token 上.两种分布具有相同 $p_{\max}$,熵差别很大.因此熵阈值 $0.5$ 不能机械换算成 Fast-dLLM 的最大概率阈值 $0.9$.

对一个 $K$ 类分布,给定最大概率 $m$,最低熵出现在剩余质量集中于一个类别,最高熵出现在剩余质量均匀铺给 $K-1$ 个类别:

$$
h_2(m)\leq H(p)\leq h_2(m)+(1-m)\log(K-1),
\tag{13}
$$

其中 $h_2$ 是二元熵.词表越大,上界越宽.熵门槛更偏爱尾部质量集中的分布,最大概率门槛只看主峰.二者可能选出不同位置,即使平均揭示数相同.

若每个位置的 top-1 校准概率为 $c_i$,同时提交一组 token 全部正确的概率在独立假设下为 $\prod_{i\in A}c_i$.八个位置即使各自有 $0.95$ 置信度,全部正确也只有 $0.95^8\approx0.66$.真实错误还会相关,例如同一个错误中间结论使后续数字一起错,乘积只能当粗略参照.

并行解码需要衡量错误落盘后对后续条件分布的影响，平均单格错误率不足以表达这种风险.一个标点错了可能下一步自行修复或几乎无影响;一个变量名、函数名或推导符号错了会改变多个位置.只按熵排序默认每个 token 的错误代价相同,dParallel 没有额外学习语义风险权重.

把一次提交写成集合决策,理想目标可表示为

$$
\max_{A\subseteq M}\ |A|
\quad\text{s.t.}\quad
\Pr(\hat y_A=y_A\mid \tilde Y)\geq1-\delta.
\tag{14}
$$

模型只有因子化边际,无法直接计算联合正确概率.熵阈值用逐位置条件替代联合约束,计算简单,但忽略相关性.ParallelBench 所测的联合依赖正落在这个缺口里.确定性蒸馏能提高边际尖锐度,没有为式 (14) 提供准确的联合概率.

一个反例是复制任务:两个被掩位置必须输出同一个随机 bit.每个位置边际都是 $(0.5,0.5)$,联合分布只在 `00` 和 `11` 上有质量.边际熵很高,阈值解码不敢提交,但若能联合抽样,两个位置可一步生成且永远满足约束.另一个反例是两个位置边际都达到 $0.99$,却因共享的少数错误模式而高度相关;批量提交的失败概率接近 $0.01$,而非独立估计的 $0.0199$.只看熵既可能低估并行性,也可能误估风险.

dParallel 选择了一条现实路线:不改输出头,不显式建联合,而是让更多边际在老师轨迹上提前变尖.它改善现有阈值采样器能利用的信号,没有声称解决所有并行依赖.代码任务掉分与数学长推导掉分可以从这里理解:结构约束越强,边际尖锐越不能代替联合协调.

阈值还决定停止时间.当当前块所有位置都揭开,解码进入下一块;若每步平均揭示 $r$ 个 token,块长 $B$ 的理想步数约为 $B/r$.但 $r$ 随状态变化:最开始上下文少,合格位置少;中段确定性扩散后上升;末尾只剩难点,又可能下降.用总长度除以步数得到的 8.5 token/步只是全程平均,不代表每一步固定揭八个.

### 6.3. 训练掩码为何必须贴近推理访问到的状态

学生训练输入不是任意 MLM 掩码.半自回归生成把回答切成长度 $B$ 的块,先前块已经确定,当前块部分掩码,未来块全掩.设块下标为 $n$,当前块掩码率为 $q$,可写成

$$
\tilde Y_i=
\begin{cases}
y_i,&i<nB,\\
m_i y_i+(1-m_i)[\mathrm{MASK}],&nB\leq i<(n+1)B,\\
[\mathrm{MASK}],&i\geq(n+1)B,
\end{cases}
\tag{15}
$$

其中当前块的 $m_i\sim\mathrm{Bernoulli}(1-q)$.这个分布同时保留已完成前缀、当前局部明文和未开始的未来.普通全句随机掩码会让未来块偶尔泄漏 token,而实际半自回归推理中这些位置必然全掩;训练条件比推理更容易,确定性可能建立在不存在的右侧明文上.

固定 $q=0.5$ 的意义不仅是一半监督、一半上下文.若 $q$ 太小,当前块大部分已知,每个被掩位置很容易,但训练状态接近块尾,模型很少学习块刚开始时的高掩码情形.若 $q$ 太大,上下文不足,许多位置猜错,进入 $\mathcal M_c$ 的样本少,熵项几乎没有作用.中间掩码率同时提供可预测位置和足够数量的监督位置.

Table 4 中全掩 $q=1$ 步数仍少,准确率却下降,正符合这一机制.熵项可以把少数已猜对位置变尖,但缺少块内明文时,被选中的正确位置更偏向容易模板;困难位置的方向没有学好.速度指标只看有多少位置越过阈值,不会检查越过阈值的位置是否覆盖了真正关键的依赖.

随机 $q$ 理论上覆盖更多推理阶段,实验却不如固定 50%.一种可能解释是有限训练预算下,随机掩码把样本分散到大量条件难度,每种状态得到的熵门控次数减少.固定 $q$ 则集中强化一个能向相邻掩码率泛化的工作点.论文消融给出结果,没有把这一解释证明为唯一原因.

Complementary mask 让同一当前块的两套掩码互补.若第一套掩住集合 $A$,第二套掩住 $B\setminus A$,每个位置至少在一套视图里成为监督目标,也至少在另一套视图里可能充当明文上下文.它提高 token 利用率,但两次前向的条件不同,不能把损失简单理解为把 batch 翻倍.

互补视图还形成一种局部双向训练.位置 $i$ 在第一视图预测时可能看到 $j$,第二视图则由 $j$ 预测时看到 $i$.这种对称覆盖有助于减少固定掩码图案带来的方向偏差.附录没有单独消融,所以不能把主表收益定量分配给 complementary mask;它更适合作为训练分布构造的一部分说明.

推理访问的是学生自己的状态,训练输入来自老师生成的正确轨迹,两者仍有 exposure gap.学生一旦提交错误 token,后续会条件于错误前缀;训练数据滤掉老师答错题,也没有系统注入学生错误.确定性越高、并行提交越多,一次错误改变的后续状态越远,这项分布偏移可能更严重.

可以设想把学生在线采样状态混入训练,类似 DAgger:让学生生成中间轨迹,再用老师或标准答案标注应恢复的 token.这样能覆盖错误上下文,代价是生成数据昂贵,且老师在错误状态上的条件分布未必可靠.dParallel 选择离线自蒸馏,保持方法简单和训练成本可控.

Dream 的 AR 初始化让掩码分布更敏感.原模型权重带有强左到右归纳偏置,若继续使用清晰的块间因果训练,优化可能强化 next-token 路线,削弱全句双向去噪.改用整句随机掩码可以保住扩散式条件建模,推理再用块长 32.这项训练–推理不一致是为了避免更强的模型退化,也解释了 Dream 并行收益较低的一部分可能来源.

### 6.4. 自蒸馏保留了什么,又改变了什么

老师先按原始采样器生成回答 $Y=(y_1,\ldots,y_L)$,学生在 $Y$ 的腐蚀版本上训练.一致性损失把老师最终写下的 token 当硬标签,没有逐步匹配老师每一时刻的完整概率分布.因此「跟随原轨迹」主要指输出内容与半自回归块结构,不意味着学生的每步转移核与老师相同.

若老师在某位置给 $(0.55,0.45)$ 并采样或 argmax 得到第一个 token,硬标签 CE 会把学生推向 $(1,0)$;certainty loss 又加强这种趋势.学生保留老师选择,同时丢掉老师对第二候选的不确定性.这正是少步所需的确定性压缩,也意味着教师分布中的多样性可能收缩.

训练集过滤掉最终答案错误的轨迹,得到条件分布

$$
p_{\mathrm{train}}(Y\mid X)
=p_T(Y\mid X,\mathrm{correct}(Y)=1).
\tag{16}
$$

它和老师无条件生成分布不同.学生看到的是老师成功模式,不会模仿失败轨迹.这可能解释 GSM8K 准确率略升:蒸馏数据本身经过正确性选择.同时,老师容易答对的题和推导风格被过度代表,难题及多样解法被筛掉.

若正确性验证只看最终答案,中间推导可能包含偶然抵消的错误.学生仍会把整条轨迹当标签,并把其中已经猜对的局部 token 压到低熵.最终过滤不能保证每一步推理可靠.数学任务中 MATH 比 GSM8K 更复杂,长链条的这种噪声更可能积累.

自蒸馏与标准知识蒸馏的温度目标不同.经典 KD 常最小化教师与学生软分布的 KL,保留类别相似性;dParallel 的核心是硬 token 一致性加学生自身熵.教师提供「写什么」,学生熵项规定「多快确定」.因此老师无需额外前向输出全词表概率,数据生成后可离线训练.

设学生在某位置已经正确,熵项不关心其主峰是否等于老师当时的概率,只要求更尖.从路径角度看,学生改变了到达相同离散答案的时间参数化.原来第 20 步才越过阈值的位置可能第 5 步就越过,多个位置于是并行落盘.终点轨迹近似保留,中间置信度轨迹被压缩.

这种时间压缩没有显式单调约束.某位置在早期变尖后,加入新 token 作为上下文仍可能改变预测甚至翻转.推理一旦提交就通常不再 mask,早期高置信错误难以撤回.训练热图显示平均确定性提前,不能保证每个样本、每个位置的置信度随步数单调.

LoRA 限制了可改变的参数子空间.它有助于保留基座知识,训练成本低,也可能限制确定性地图的重塑幅度.rank 32、16、128 在三类模型上不同,结果不能只归因于底座.更高 rank 是否继续提高并行度、是否加重能力遗忘,论文没有系统曲线.

从信息论看,最小化条件熵倾向于减少同一腐蚀输入下输出多样性.如果任务本来有多个等价答案,老师轨迹只选其中一个,学生会更坚决地复现该模式.代码题按单元测试允许多种实现,硬轨迹蒸馏可能牺牲风格覆盖,而 pass@1 不一定反映这种变化.

蒸馏数据来自数学和部分代码提示,模型在未覆盖领域上的并行性取决于迁移.确定性是词法模板、句法结构和任务推理共同作用的结果.常见语言结构可能迁移,专业知识决策未必迁移.没有 MMLU、长文写作和开放对话数据时,不能把 GSM8K 的 30 步直接视为通用服务步数.

**6.5. 步数、延迟和真正并行度之间的换算**

原版长度 256、步数 256,容易让人以为每步只生成一个 token.实际每步模型对当前掩码位置全部输出分布,采样器只提交少数位置.步数是网络前向次数附近的量,token 数是画布上限,二者的比值给出平均提交宽度.

若总生成 token 数为 $L$,前向次数为 $S$,平均表面并行度可定义为

$$
r_{\mathrm{avg}}=\frac{L}{S}.
\tag{17}
$$

GSM8K 用画布 256 近似计算得到 $256/30\approx8.5$.若样本提前遇到 EOS,真实 $L<256$,实际每步新增 token 少于 8.5.论文的步数由采样循环报告,画布长度不能自动当成有效输出长度.

端到端延迟可粗分为

$$
T_{\mathrm{total}}
=S\,(T_{\mathrm{model}}+T_{\mathrm{select}}+T_{\mathrm{sync}})
+T_{\mathrm{fixed}}.
\tag{18}
$$

少步主要降低乘在 $S$ 上的部分.提示编码、tokenizer、数据搬运和固定启动成本不会同比下降.因此步数从 256 到 30 的 8.53 倍与实测 18.6/2.2 的 8.45 倍恰好接近,只说明该实验固定成本较小;换到短回答、高并发服务或不同实现后,两者可能分开.

Dual-Cache 不减 $S$,而是降低 $T_{\mathrm{model}}$;dParallel 降低 $S$,每步计算图大致不变.两者理论上可叠加,总收益受剩余固定成本限制.若缓存使模型前向便宜两倍,dParallel 再把步数减八倍,端到端不一定达到十六倍,因为选择、同步和内存访问占比会上升.

与 AR 比较更复杂.AR 每步只为下一个位置产生有效 token,但 KV cache 让每步只处理一个新 query;掩码扩散每步对整段活跃画布运行双向网络.即使 dParallel 每步提交八个 token,单步 FLOPs 仍可能高于 AR 的单 token decode.少步倍率只相对同一 dLLM 原版,不能直接当成相对 AR 的吞吐倍率.

块长 $B$ 给并行度设置上限.半自回归要求完成当前块后才能进入下一块,长度 $L$ 至少需要 $L/B$ 个块阶段.若一个块能一步完成,理论最少步数约为块数;实际还要在块内迭代.长度 256、块长 32 有 8 个块,dParallel 用 30 步,平均每块约 3.75 步,已经远少于原版每块约 32 步,但离一步一块仍有空间.

提示越长,每步注意力成本越高;生成长度增加时,块数和步骤也增加.论文四个任务的秒数差异不只来自步数,还来自 prompt 长度、实际 EOS 和评测模板.MBPP 原版 256 步却用 50.1 秒,GSM8K 同为 256 步只用 18.6 秒,说明每步成本并不固定.10.5 倍与 8.5 倍不能仅由揭示宽度解释.

硬件也改变瓶颈.大矩阵乘更适合 GPU,小 batch 的 Python 循环和同步可能占较多时间;减少步骤会同时减少 kernel launch,所以实测加速可能接近步数比.编译、CUDA graph 或更大 batch 降低循环开销后,同样少步比例对应的延迟收益可能变化.

报告吞吐还要区分单请求与服务吞吐.阈值解码使不同样本需要不同步数,batch 内若等待最慢样本,平均步数优势被尾部拖累;若动态移出已完成样本,会产生不规则 batch 和调度开销.论文单卡任务评测的秒数不等于多用户 continuous batching 的 TPS.

并行度也可用每步新确定 token 的分布描述,而不只给平均值.均值相同的两个模型,一个稳定每步八个,另一个多数步一个、少数步几十个,对 batch 同步、内存峰值和错误传播的影响不同.Figure 5/6 的热图给出形状,主表没有报告方差或尾部步数.

**6.6. 熵降低不等于概率校准改善**

模型校准要求置信度与经验正确率匹配.若所有置信度约 0.9 的预测中有 90% 正确,可称这一档校准良好.熵最小化追求更尖,可能把原来 0.7 且 70% 正确的预测推到 0.95,正确率没有同步提高时,模型会变得过度自信.

dParallel 用 $\mathcal M_c$ 只在训练样本当前预测正确时压熵,降低了把已知错误峰值变尖的风险.但训练正确不代表测试正确,也不保证分布外输入上的校准.学生可以在训练轨迹上学会「这些形状通常正确」,遇到陌生任务时仍以同样低熵输出错误答案.

熵阈值解码依赖排序和绝对尺度.若蒸馏让所有位置的熵整体下降,固定阈值会一次选更多位置;若下降幅度在任务间不同,同一个 0.45 不再对应相同错误风险.论文按任务选择 0.45 或 0.5,本身说明阈值需要校准,并非模型训练后存在一个普适常数.

温度缩放可以在验证集上重新校准概率,但推理门槛也随之变化.将 logits 除以更高温度会提高熵、减少提交数,可能恢复准确率却损失速度.训练中的 $T=0.5$ 只用于 certainty loss 的分布,推理是否使用同一温度必须按实现核对,两者不能视作同一个旋钮.

可用可靠性图检查风险:把位置按预测熵或 $p_{\max}$ 分桶,统计每桶 token 正确率,再按解码步和任务拆分.更关键的是统计「提交后最终仍正确」,因为当下 argmax 正确也可能在允许 remask 的采样器里发生变化.论文主要报告最终任务准确率与热图,没有完整校准曲线.

Expected Calibration Error 仍不够.阈值只使用低熵尾部,全分布平均 ECE 可能很好,而尾部恰好过度自信.更合适的是选择性预测风险:

$$
R(\tau)=\Pr(\hat y_i\neq y_i\mid H(p_i)\leq\tau),
\qquad
C(\tau)=\Pr(H(p_i)\leq\tau),
\tag{19}
$$

$R$ 是被提交位置的错误率,$C$ 是覆盖率.理想模型在提高覆盖率时风险缓慢上升.dParallel 的目标可理解为把风险–覆盖曲线向右推,主表的步数与准确率只是这条曲线上的一个工作点.

序列级任务准确率放大选择风险.一条推导中任意关键 token 错误都可能使最终答案失败,因此 token 风险的小变化会造成更大的 exact-match 变化.相反,HumanEval 的单元测试对空格、变量名等多种 token 序列等价,token 级偏差不一定降低 pass@1.不同任务的风险函数不同,同一熵阈值不能保证同等质量.

过度自信还会削弱搜索.高熵位置保留多个候选,后续上下文可能帮助消歧;提前压成单峰并提交后,采样器失去回头机会.这在自然语言同义表达上可能只减少多样性,在代码作用域和数学符号上可能造成结构错误.允许 remask 或 corrector 可以缓解,但会增加步数并改变论文的速度点.

### 6.7. 因子化误差为什么在代码和长推导里更明显

掩码模型一次输出常写为

$$
p_\theta(y_A\mid\tilde Y)
\approx\prod_{i\in A}p_\theta(y_i\mid\tilde Y).
\tag{20}
$$

右侧所有位置都条件于提交前的同一状态,看不到同批其他位置最终选了什么.如果目标联合分布不能分解,各边际的 argmax 拼在一起甚至可能得到联合概率为零的组合.

设两个位置只允许 `ab` 和 `ba`,概率各半.两个边际在 `a`,`b` 上都各半.独立 argmax 若按固定 tie-break,可能输出 `aa`,而真实联合从不出现.降低单位置熵若没有额外信息,只会任意选定一个峰,不能恢复反相关结构.这是「边际更尖」存在根本上限的最小反例.

上下文能逐步打破对称.先提交一个位置后,下一步另一个位置看到它,条件分布变成确定.顺序采样用更多步换联合正确.dParallel 希望训练让原本需要先后消歧的位置在同一步就能由已有上下文确定,对于真正依赖同批未知变量的情况则无能为力.

代码中的括号、缩进、变量引用和类型约束形成大量远距离耦合.例如函数参数名与后续多次引用应一致,当参数位置和引用位置同时被掩时,每个边际可能在多个名字间摇摆.同时揭示会各自选择不同名字.数学推导中的中间数值与最终答案也有相同问题.

自然语言冗余较高,多个局部选择即使不完全协调,句子仍可能通顺;单元测试和 exact match 对结构错误更敏感.因此 GSM8K 的最终短答案可以在局部模板确定后快速并行,MBPP 的可执行一致性更难.这一机制与主表方向一致,但不能仅凭四个 benchmark 建立普遍排序.

块长控制耦合范围.较小块让同批未知位置少,因子化近似更可靠,块数与步骤增加;较大块提高潜在并行度,也把更多相互依赖位置放入同一次提交.最优块长取决于任务依赖跨度,论文固定 32,没有给出完整块长扫描.

可用总相关量描述联合偏差:

$$
\mathrm{TC}(Y_A\mid\tilde Y)
=\mathrm{KL}\left(p(Y_A\mid\tilde Y)\middle\|\prod_{i\in A}p(Y_i\mid\tilde Y)\right).
\tag{21}
$$

当条件总相关量高时,边际乘积偏离真实联合.确定性蒸馏可能通过改变表示降低部分 $\mathrm{TC}$,让已有上下文更早解释各位置;它的损失没有直接估计式 (21),也不能保证总相关量下降.

联合头、离散 copula、块内 AR 或验证器都能处理一部分相关性.联合头表达力强但词表组合爆炸;块内 AR 保结构却牺牲并行;验证器先并行起草再检查,增加额外前向.这些路线与 dParallel 的边际确定性可以组合,但组合后的收益必须重新测量.

**6.8. 一个四位置例子走完训练与推理**

设当前块有四个被掩位置,教师答案为 `x = 12`.为简化,只看四个 token `x`,`=`,`1`,`2`.学生第一次前向对目标 token 的概率分别为 $(0.92,0.88,0.54,0.40)$,第四位 argmax 是错误的 `3`,前三位 argmax 正确.

一致性 CE 对四个位置都计算,分别为 $-\log0.92,-\log0.88,-\log0.54,-\log0.40$.确定性集合 $\mathcal M_c$ 只有前三位,熵项不会压第四位的错误 `3`.更新后,前三位可能变为 $(0.97,0.95,0.72)$,第四位在 CE 作用下由目标概率 $0.40$ 升到 $0.48$,仍未成为 argmax.

下一次训练遇到相近状态时,第四位目标概率超过竞争者,它才进入 $\mathcal M_c$.熵项开始拉开 `2` 与 `3`.这种先纠正方向、再强化确定性的两阶段并非显式排程,却是由集合门控自动产生.

推理时若熵阈值选中前两位,模型同时提交 `x =`,剩余 `12` 下一步能看到等号和变量.若蒸馏后第三位也越过阈值,第一步提交 `x = 1`,第二步只写 `2`,步骤减少.若第四位错误地以低熵预测 `3`,它也会同时提交,得到 `x = 13`;门控训练降低这种概率,不能在测试时检测它.

现在把答案改成两个相互依赖 token,例如十位与个位必须满足某个算式.两位边际各自正确概率都为 $0.8$,同时提交全部正确的上限并非由两个数单独确定.若错误高度相关,可能是 $0.8$;若近似独立,约为 $0.64$;若两位错误互斥,甚至可能更低.熵阈值看不到这种相关结构.

该例还说明「每步揭更多」和「减少时间网格」不同.模型没有从 $t_k$ 直接跳到远处 $t_{k-m}$ 的教师分布,只是同一个当前块里有更多位置满足提交规则.因此 dParallel 的少步来自扩大集合 $A_\tau$,不是学习一个显式多步转移算子.

若配合 Dual-Cache,第一次前向算完整注意力,后续只更新受变化 token 影响的部分表示,每步更便宜;certainty-forcing 则使后续步数更少.四位置例里,前者降低两次前向成本,后者可能把两次变成一次.它们作用在不同乘数上.

**6.9. 对主表数字做一次因果拆解**

原版与 dParallel 同时改变了权重和采样规则.主表中的收益不能全部归给熵损失,Table 3 才是部件对照.只留 CE 时 53 步、73.5 分,说明轨迹微调本身减少了一些步数,也损失准确率;只留熵项时 23 步、57.8 分,说明低熵极易制造速度,方向错误会摧毁任务表现.

两项同时存在却不用半自回归掩码时是 44 步、73.3 分.这表明训练状态分布与推理状态对齐同样关键.三项齐全得到 30 步、76.1 分,不能把 30 对 44 的差简单称为掩码单独贡献,因为各部件之间存在交互,消融不是可加线性模型.

主表 dParallel 与原版的准确率差只有 0.4 点,GSM8K 测试集约 1319 题,二项分布标准误在 75% 附近约为 $\sqrt{0.75\times0.25/1319}\approx1.2$ 个百分点.不考虑样本相关与解码随机性,0.4 点也小于这一粗略标准误.它支持「没有观察到明显下降」,不足以证明蒸馏提高了真实准确率.

HumanEval 只有 164 道题,40.2% 与 38.4% 相差约三题.采样随机种子、代码执行环境和 pass@1 估计都可能影响结果.将这列写成「提高代码能力」证据太强,更合适的含义是主设定下加速没有显示出大幅退化.

MBPP 从 42.4 到 40.8,MATH 从 33.5 到 31.5,方向相反但幅度也需结合样本数和重复运行方差.论文表格主要展示速度–质量工作点,没有置信区间.比较 1–2 个点时应保留统计不确定性,尤其不能把不同论文单次表格的小数位排序成稳定结论.

延迟差异很大,统计不确定性不是主要问题,系统测量口径才是.是否预热、同步 CUDA、计入 prompt 编码、batch size 和 EOS 策略都会影响秒数.同表同脚本内的相对值最可信,跨表和跨硬件应退回步数、模型调用与任务设置逐项核对.

Figure 4 在固定更高加速点比较 dParallel 与普通阈值,说明训练改变了风险–覆盖曲线,不只选择了更激进阈值.如果只是把阈值放宽,两者在相同速度下应有相近质量;实际差距表明 certainty-forcing 使被选位置更可靠.这仍是特定任务上的经验结果,不能推出任意阈值和长度都维持相同优势.

**6.10. 能外推到哪里,哪里必须停住**

长度从 256 增到 1024 时,块数由 8 增到 32,最低步骤数至少随块数增长.若每块仍约 3.75 步,总步数接近 120,相对逐 token 1024 步仍约 8.5 倍;但长上下文注意力成本、依赖跨度和尾部难点都会改变每块步数,线性外推只是计算参照.

输出越长,早期错误影响的后缀越长.训练只在长度 256 的轨迹上强化确定性,未证明 1024 或更长文本仍保持校准.尤其块间因果意味着前块一旦错误,后续所有块都条件于错误明文,不会像全局 remask 那样回看.

开放式对话没有唯一正确答案,自蒸馏过滤也缺少 GSM8K 那样可靠的最终答案判定.用奖励模型筛选会引入评价器偏好,用教师自评会放大教师偏差.方法本身可训练,「正确位置集合」的标签和轨迹质量却更难定义.

预训练阶段加入 certainty loss 还会面对另一目标冲突.扩散预训练希望拟合各种噪声水平的条件分布,保留真实不确定性;熵最小化鼓励单峰.若对本来多模态的条件强行压熵,likelihood 可能变差.后训练针对确定任务轨迹使用门控熵,范围更窄,风险也更可控.

采样若允许随机性,低熵蒸馏会减少候选多样性.创意写作、开放问答和多样代码生成可能更依赖温度或 top-p.重新升温能恢复部分多样性,却可能让更多位置无法通过熵阈值,速度收益随之下降.速度、校准与多样性构成三方权衡.

不同语言和 tokenizer 也会改变并行机会.中文 token 可能对应完整汉字或词片,英文代码含大量短符号;同样 256 token 承载的信息量不同.固定块长 32 和熵阈值在另一 tokenizer 上未必对应相同依赖范围.

模型规模增大通常改善单格预测,可能天然产生更多低熵位置,也可能让错误更自信.小模型上需要强 certainty-forcing 才越过阈值,大模型上边际收益可能缩小;100B MoE 的 CAP 结果不能直接替 8B dParallel 回答这条缩放曲线.

领域迁移的判断应分两层.词法和句法确定性可跨任务迁移,例如标点、代码括号、常见推导连接词;任务答案和长程逻辑依赖领域数据.只要主表没有目标领域结果,最多说模型具备可迁移机制,不能给出固定加速倍率.

### 6.11. 复现时最值得逐项核对的公式与状态

第一步记录教师数据.每条样本应保存提示、教师完整回答、正确性判定、实际长度和生成配置.若只保存通过筛选的答案而不保存失败率,无法知道条件筛选有多强.教师使用贪心还是采样也会改变轨迹多样性.

第二步核对 active block.损失只能落在当前块的掩码位置 $\mathcal M_a$,未来全掩块不应被当作监督目标.把所有 mask 都加入 CE 会让模型提前预测尚未开始的块,训练目标退回普通全句 MLM,与半自回归推理状态错位.

第三步核对正确集合.条件应比较学生当前 argmax 与教师 token,并对集合选择停止梯度.空集合时 certainty loss 应为零,不能除以零或用整块替代.批量实现还要按样本归一化,否则拥有更多正确位置的样本获得更大权重.

第四步核对温度.式 (10) 的 $T=0.5$ 只进入熵项分布,一致性 CE 使用何种温度应跟论文实现一致.若先对 logits 除温度,又在熵函数内部除一次,有效温度变成 $T^2$,梯度会过强.

第五步核对 complementary mask.互补集合只针对当前 active block,已完成前缀继续保持明文,未来块继续全掩.若整句取反,会把前缀重新掩掉、未来泄漏出来,生成完全不同的训练分布.

第六步记录训练动态.每个 batch 至少统计 $|\mathcal M_a|$、$|\mathcal M_c|/|\mathcal M_a|$、CE、熵项、正确位置平均熵和错误位置平均熵.若 $\mathcal M_c$ 很小,熵项几乎没训练;若很快接近一而验证准确率下降,模型可能过拟合教师轨迹.

第七步复现解码.记录每步阈值、被提交 token 数、空集合保底次数、每块步数和最终 EOS.只给总步数无法判断收益来自普遍并行,还是少数步骤一次提交大量简单 token.保存熵热图可直接对照 Figure 5/6.

第八步测延迟.预热若干次,每次测量前后同步设备,分别报告 prompt 编码、去噪循环和后处理.同时写 GPU、精度、batch、长度、块长及实际输出 token 数.这样才能解释相同步数为何在不同任务上秒数差两倍以上.

第九步测质量.数学 exact match 应固定答案抽取,代码应固定执行沙箱和超时,并报告随机种子或重复运行.阈值是按测试任务调出的还是用验证集选择的,也要说明;直接在测试集挑最快且不掉分的阈值会高估泛化.

第十步做最小反例.准备复制、反相关二 token、括号配对和长距离变量引用四类合成样本.它们不替代 benchmark,却能区分低熵、校准和联合依赖.若平均熵下降而反相关任务更差,说明模型提高了边际确定性,没有学会联合并行.

**6.12. 温度、熵权重与词表规模怎样共同作用**

式 (11) 表明熵梯度同时受 $T$ 和 $\beta$ 控制.如果只把温度从 1 降到 0.5,logit 差先被放大两倍,梯度外面又多出 $1/T$.但 $q_k$ 也会趋向 0 或 1,极端位置的 $q_k(1-q_k)$ 反而变小.实际强度不是简单的四倍,取决于当前分布处在平坦区、决策边界还是已经饱和.

考虑二分类 logit 差 $d=z_1-z_2$,低温概率为 $q=\sigma(d/T)$,熵对 $d$ 的导数为

$$
\frac{\mathrm dH}{\mathrm dd}
=-\frac{d}{T^2}q(1-q).
\tag{22}
$$

$d=0$ 时导数为零,因为完全对称的最大熵点是一阶驻点;微小随机扰动决定往哪边走.门控集合保证训练样本上正确类别已经略占优势,CE 再提供明确方向.当 $|d|$ 很大时,$q(1-q)$ 接近零,熵项也会饱和.它主要放大中等间隔,而非无限推高已极端确定的 token.

多分类下,词表尾部会贡献熵.主峰概率相同,五万词表均匀尾部比二分类竞争产生更高熵.低温会迅速压小远低于主峰的尾部,所以熵下降可能主要来自清理无关 token,未必显著扩大主峰与第二候选的间隔.对于提交风险,第二候选通常比尾部总量更重要.

可以补充 top-two margin 指标 $m_i=z_{(1)}-z_{(2)}$.若熵下降而 margin 几乎不变,优化主要清理长尾;若 margin 同时上升,最强竞争者被压低.论文热图画平均置信度,没有把这两种变化拆开.复现时同时记录熵、$p_{\max}$ 和 margin,更容易解释阈值为何有效.

$\beta$ 过小,熵项被困难位置的 CE 淹没,模型继续维持顺序确定;过大时,容易位置迅速饱和,共享参数也可能让错误位置变得更尖,即使它们没有直接熵损失.门控只能控制直接梯度,不能隔离 Transformer 参数在不同 token 间的间接影响.

不同 batch 的 $|\mathcal M_c|$ 差异会改变有效权重.若熵损失按正确位置均值归一化,只要集合非空,一个正确位置与二十个正确位置都产生相近标量规模;若按 $|\mathcal M_a|$ 归一化,正确率越低,熵项越弱.两种实现对应不同课程效应,复现必须以代码为准.

当 $\mathcal M_c$ 为空时直接置零,会使最困难样本完全没有 certainty 信号;当只有一个偶然猜对位置时,该位置获得完整平均权重,梯度方差较大.可用跨 batch 的总正确位置数归一化稳定训练,但这会改变论文目标.原设定的优势是每条样本权重相对均衡.

温度还影响混合精度.除以 0.5 后 logits 范围翻倍,Softmax 的指数更容易上溢或下溢.稳定实现先减去最大 logit,熵中的 $q\log q$ 对零概率使用安全约定.若尾部在 FP16 下全部变成零,测得熵会偏低,模型看起来比实际更确定.

**6.13. 错误在半自回归块之间怎样传播**

设第 $n$ 块生成状态为 $B_n$,后续块的条件分布是 $p(B_{n+1}\mid B_{\leq n},X)$.当前块发生错误后,它作为明文前缀永久进入后续条件.若没有全局 remask,后面的正确性满足链式关系

$$
p(B_{1:N}\mid X)=\prod_{n=1}^N p(B_n\mid B_{<n},X).
\tag{23}
$$

块内并行错误影响当前因子,也会改变所有后续因子.因此前块的提交门槛理论上应更谨慎,末块错误影响范围较小.固定熵阈值没有区分块位置,除非模型自身在前块表现出更高不确定性.

可以定义扰动敏感度:把某个已提交 token 换成次优候选,观察后续 logits 或最终答案变化.敏感度高的位置应晚提交或要求更低熵.这需要额外前向,不适合直接用于每一步解码,但可离线训练一个风险头.原始 dParallel 没有这层机制.

数学 CoT 中,前面算错一个中间值,后面可能基于错误值进行内部一致的推导,模型置信度依然很高.熵反映模型对当前条件的犹豫程度,不反映条件本身是否正确.一旦错误进入明文上下文,后续低熵不能作为全局正确性的证据.

代码里同样存在「一致但错误」.错误函数名被提交后,后续调用位置会高置信复制它,局部 token 彼此一致,程序仍因未定义符号失败.低熵和自洽不能替代外部执行约束.这解释了为什么代码任务可考虑在块间加入编译或语法验证,而不是继续单纯压熵.

错误传播并非总是单向恶化.双向块内注意力让同一块剩余 mask 看见已经提交的 token,一个正确锚点可以迅速确定多个位置;这正是顺序确定性产生的来源.dParallel 试图让模型在锚点较少时也提前形成多个正确峰值.它扩大正向连锁,也可能扩大错误锚点的影响.

若允许在当前块完成前 remask 已提交 token,可把高置信错误重新打开.判断标准可以是新上下文到来后该 token 概率显著下降.这种非单调采样增加纠错,也使「确定 token 数」不再单调,步数和缓存实现更复杂.论文主设定追求简单少步,没有采用完整回溯.

块级验证是另一折中.先并行完成一个块,再用同一模型或外部 verifier 对整块打分;不通过则提高步数重采.容易样本保持高速,困难样本付出额外成本.平均速度可能很好,尾部延迟取决于失败率.它与 certainty-forcing 正交,但需要新的服务和评测协议.

**6.14. 正确性筛选造成的课程学习与盲区**

教师先生成再筛选,相当于自动构造课程:简单题更容易留下,困难题更容易被删除.学生反复学习教师最稳定的轨迹,这些轨迹本来就具有较早的确定性.观察到并行度提升时,一部分可能来自训练分布偏向容易确定的模式,而非所有问题的确定性都被同等改变.

设提示分布为 $p(X)$,教师成功概率为 $a(X)$.筛选后提示分布变成

$$
p_{\mathrm{keep}}(X)=\frac{p(X)a(X)}{\mathbb E_{p(X)}[a(X)]}.
\tag{24}
$$

$a(X)$ 越高的题权重越大.若想恢复原始提示分布,可按 $1/a(X)$ 重要性加权,但教师在低成功率题上几乎没有正确轨迹,权重会爆炸.自蒸馏的能力天花板不是简单增加样本数就能消除.

PRM12K、Numina-Math 与 GSM8K 的混合提供了难度和形式变化,但正确轨迹的筛选规则可能不同.最终答案可自动验证的数学题适合这条流程;开放解释、事实问答和安全拒答难以得到同样干净的二元标签.扩展领域时,数据验证往往比熵公式更难.

教师可能通过多次采样提高保留率.对单次成功率 $a$,采样 $k$ 次至少得到一条正确轨迹的概率为 $1-(1-a)^k$.这能覆盖更多困难提示,计算成本随 $k$ 增加,并且保留下来的可能是低概率侥幸轨迹.学生将偶然成功模式压到低熵,未必能稳定复现其推理.

可用过程奖励筛掉中间错误,但奖励模型自身会误判,并引入新的信息源.若只验证最终答案,方法仍是纯自蒸馏;加入人工解答或过程标注后,学生可能获得教师原本没有的能力,实验就不再只测确定性时间表.

数据重复也影响结果.同一数学模板换数字出现多次,LoRA 容易记住局部形式,验证集若共享模板,确定性提前看起来很强.严格评估应按题型或来源去重,再观察并行度是否保持.论文公开数据组合为复现提供起点,没有穷尽模板泄漏分析.

一个有用的分桶是按教师原版所需步数划分样本.本来 20 步就完成的题和需要 150 步的题分别比较蒸馏后步数,才能判断收益是压缩所有轨迹,还是主要改善容易样本.只报告平均 30 步会掩盖长尾.

另一个分桶是按答案正确性边际.教师多次采样都正确的稳定题、偶尔正确的脆弱题、从不正确的盲区应分开.学生在第一类上可安全学低熵,第二类需要更多验证,第三类没有监督.这比单一训练集准确率更接近自蒸馏的真实边界.

**6.15. 并行解码的理论下限与实际尾部**

块长 $B$ 时,若每一步至少提交一个 token,单块最坏需要 $B$ 步;若所有 token 一步都可确定,最好只需一步.长度 $L$、块数 $N=\lceil L/B\rceil$ 时,总步数满足

$$
N\leq S\leq NB,
\tag{25}
$$

忽略 EOS 和额外 corrector.长度 256、块长 32 给出 $8\leq S\leq256$.dParallel 的 30 步处在下限的 3.75 倍,原版接近上限.

设第 $n$ 块每步平均提交率为剩余位置的比例 $\rho$.若每步独立揭示 $\rho$ 比例,剩余数近似 $B(1-\rho)^s$,达到一个 token 所需步数约为

$$
s\approx\frac{\log B}{-\log(1-\rho)}.
\tag{26}
$$

这只是理想几何衰减.真实采样末尾常有几个顽固位置,形成 coupon-collector 式尾部.平均每步揭很多,总步数仍由最终的难 token 决定.

certainty-forcing 若主要让容易位置更早越阈值,前几步会非常宽,末尾不变,总步数收益有限.主表从 256 降到 30 说明尾部也明显缩短,但每块是否仍有固定难点需要逐步曲线确认.热图比单一平均更能看出尾部.

熵阈值过严时,$\rho$ 小,步骤多但错误少;阈值放宽时,$\rho$ 大,步骤少而风险上升.蒸馏目标是让同一风险下的 $\rho$ 增大.因此最公平对比是在相同任务准确率下比较步数,或画完整 Pareto 曲线,而非各方法各挑一个阈值只比最快行.

动态阈值可以按剩余 token 数和时间预算调整.块初期阈值严格,先提交最可靠锚点;后期逐渐放宽,避免少数位置拖尾.这种日程可能无需改权重就改善速度,也可能与 dParallel 叠加.论文使用固定任务阈值,没有证明固定阈值最优.

如果剩余位置长期高熵,强制 top-1 是必要的终止机制.强制发生次数越多,说明训练并没有真正提供足够确定性.把这些位置单独收集再蒸馏,可形成 hard-state curriculum.但它们可能正是不可因子化的依赖,继续压熵会增加错误而非解决结构问题.

理论下限还受信息传播限制.Transformer 一次前向具有全局注意力,计算图上任意位置都能读取全部已知 token,看似没有局部传播距离;未知 token 的取值却不能在同一次因子化输出中相互条件.每一轮提交能增加新的公共信息,需要几轮取决于依赖图的分层深度,而非物理 token 距离.

若答案可按依赖 DAG 分层,同一层节点在父节点已知后可并行生成,最少轮数接近 DAG 深度.左到右 AR 用节点数轮,dParallel 试图让模型靠已有上下文识别同层节点.存在环或对称选择时,仍需随机破缺、联合采样或额外约束.

### 6.16. 哪些实验能真正区分几种解释

第一个实验固定学生权重,只扫描熵阈值,得到基线风险–覆盖曲线;再对 dParallel 权重做同样扫描.若两条曲线只是横向平移,主要变化是全局温度;若 dParallel 在相同覆盖率下错误率更低,说明表示和排序也改善了.

第二个实验给 dParallel logits 做后处理温度缩放,把平均熵重新校准到原模型.若速度优势完全消失,训练主要学到 logit 尺度;若相同熵下仍能同时提交更多正确 token,模型学到了更有结构的确定性.

第三个实验把熵项替换为显式 margin loss,只要求正确 token 高于第二候选一个阈值.它不必清理整个词表尾部.若 margin loss 获得相同少步效果,长尾熵不是关键;若明显较差,全分布形状确实参与了阈值选择.

第四个实验按块位置统计错误率和步数.前块收益大、后块收益小,说明蒸馏主要改变了确定性传播;后块同样改善,可能是一般 logit 锐化.同时观察错误是否在后续块放大,能检验第 6.13 节的传播机制.

第五个实验构造相同边际、不同联合的合成数据.复制、互斥和括号任务都能控制边际熵.若 dParallel 只在独立任务上加速,边际确定性解释成立;若在联合任务也加速且保持约束,模型可能通过已有上下文或隐式顺序学到了更深结构.

第六个实验保留教师失败轨迹,只在正确 token 位置计算 CE,与整题过滤比较.如果整题过滤明显更好,数据课程与全局轨迹质量是关键;若差异小,局部标签足以支撑 certainty-forcing.这也能衡量 92k 数据中筛选偏差的贡献.

第七个实验在 256、512、1024 长度上固定块长,分别画步数与质量,再固定块数让块长随长度增大.前者测块间累积,后者测块内联合误差.只给单一长度无法区分这两种缩放瓶颈.

第八个实验报告多随机种子和置信区间.小幅准确率变化若不稳定,结论应集中在巨大且稳定的步数下降;若每个种子都维持质量,才能更强地声称无损.这对 HumanEval 等小样本集合尤其重要.

这些实验不要求改变 dParallel 的核心方法,却能把「只是温度变尖」「排序更好」「训练状态对齐」「筛选课程」「联合依赖仍在」几种解释拆开.原论文的消融已经回答其中一部分,剩余问题构成清晰的后续研究边界.

**6.17. 与概率扩散目标的关系**

原始掩码扩散训练常从变分界或加权 MLM 推出,不同噪声率对应不同损失权重.它的目标是拟合数据分布的条件概率.dParallel 在指令模型上加入 certainty loss,目标转向快速产生一条可靠轨迹,不再单纯优化 likelihood.

熵项会改变最优分布.假设真实条件分布在两个等价答案上各半,纯 CE 的最优预测也是各半;加入熵最小化后,对称点可能不稳定,模型偏向任一答案.在确定答案的数学题上这通常无害,在开放生成上会造成模式选择.

从决策角度看,后训练优化的是特定采样器效用:

$$
\max_\theta\ \mathbb E[mathrm{quality}(Y)]-\lambda\,\mathbb E[S(Y)],
\tag{27}
$$

certainty-forcing 没有直接写式 (27),而是用正确 token 熵作为步数的代理.熵低的位置更容易越过阈值,所以代理与 $S$ 相关;阈值、任务和校准变化时,代理关系也会变化.

把熵直接加入预训练 NELBO 会破坏原概率解释,除非将其视作新的正则目标并重新评价 likelihood.后训练 LoRA 的范围较小,论文关心任务准确率和速度,因此接受这种偏移.讨论「扩散模型是否更好建模概率」时,不能用 dParallel 后训练结果替代基座 likelihood.

蒸馏后的模型仍可用原 256 步采样器,但概率转移已经改变,长步数未必恢复原分布.更多步骤只能减少数值或提交误差,不能撤销权重中学到的低熵偏置.论文没有给这条对照,所以不能假设慢采样一定等同教师.

若目标是保持多样性,可以只在任务关键或可验证 token 上加熵,其余位置维持 CE;也可让 $\beta$ 随噪声率变化,只在接近提交阶段加强确定性.这些变体需要明确哪些位置和时间进入正则,否则「低熵」会成为笼统口号.

Rao-Blackwell 化、score entropy 等概率目标减少的是估计方差或速率误差;dParallel 的 entropy minimization 增加的是输出确定性.二者都出现 entropy 一词,数学作用相反,不能混在一起.前者尽量还原真实分布,后者有意把正确轨迹压尖以换取少步.

**6.18. 确定性地图可以怎样定量描述**

热图把位置放在横轴、解码步放在纵轴,颜色表示平均置信度.它直观展示红色高置信区域是否沿左到右前缘移动,但跨样本平均会抹掉不同答案长度和块边界.短答案后半段可能全是 padding 或 mask,与长答案同位置平均时含义不同.

更稳定的做法是按每个 token 的首次确定时间定义

$$
\tau_i=\min\{s:H(p_i^{(s)})\leq\tau\ \text{且位置 }i\text{ 被提交}\}.
\tag{28}
$$

对每个相对块位置统计 $\tau_i$,可看到确定时间是否随位置线性增加.原版若近似 $\tau_i\propto i$,说明存在顺序前缘;dParallel 若同一批位置的 $\tau_i$ 聚集,说明并行化真正发生.

只看首次低熵仍可能被瞬时尖峰欺骗.可以定义稳定确定时间:从某一步开始,该位置的 argmax 在后续所有观测中不再改变,且熵持续低于阈值.由于提交后模型通常不再重新预测该位置,离线分析需要保持它为 mask 或运行反事实轨迹.稳定时间更接近模型内部何时真正确定,计算也更贵.

位置之间的确定时间相关矩阵能揭示成组提交.若括号、变量引用或算式片段总在相近步骤变尖,可能存在语义组;如果只是相邻位置相关,收益更像前缘加宽.聚类结果还可指导自适应块或联合头设计.

确定时间的熵也有意义.所有样本同一位置都在固定步骤确定,调度可预测;分布长尾则会拖慢 batch.平均步数相同,低方差模型更适合服务.论文给平均速度,未报告样本级 P95/P99,因此无法判断尾部是否同步改善.

另一指标是每一步新增确定 token 数 $r_s$.累计曲线 $R_s=\sum_{j\leq s}r_j$ 若近似直线,并行度稳定;若前期陡、后期平,存在难点尾部.曲线下面积反映 token 等待时间,与总步数互补.两个方法最终步数相同,更早确定多数 token 的方法可为流式展示提供更低感知延迟.

然而块扩散通常不能把未完成块直接稳定流给用户,因为后续 remask 或块内修改可能发生.若 dParallel 采用单调提交,已落盘 token 可以流式输出;若加入 corrector,流式接口需要处理撤回.确定性地图与产品可见延迟之间还有这一层协议差异.

**6.19. 为什么「猜对后压熵」仍需要明确边界**

训练时的「猜对」是相对教师 token,教师 token 只是众多合法表达中的一个.开放题里学生预测同义答案,会被标成错误并接受 CE 拉回教师措辞;学生复现教师措辞后才获得熵奖励.方法把序列级多解问题转成单轨迹模仿,便利来自标签明确,代价是表达空间收缩.

数学题也不总是单轨迹.同一个答案可用代数、几何或枚举推导,教师选中的路线决定哪些 token 被视为正确.最终答案筛选保证结果,不保证路线唯一.模型原本偏好另一条正确路线时,硬标签会制造无谓冲突.

可把多个正确教师轨迹组成集合,训练时选择与学生当前分布最接近的一条,或对轨迹做最小风险学习.这样能保留多样性,数据生成和匹配成本更高,不同长度轨迹也难对齐.dParallel 使用单轨迹,符合轻量 LoRA 的定位.

「正确集合」依赖 tokenization.一个字符串若有多种 token 切分,教师 token 序列与学生输出空间由同一 tokenizer 固定,通常没有歧义;跨模型蒸馏若 tokenizer 不同,逐 token $\mathcal M_c$ 无法直接定义.方法采用同骨架教师与学生,绕开了这项问题.

教师与学生同权重初始化还让训练早期 $\mathcal M_c$ 较大.若学生更小或架构不同,大量位置初始猜错,certainty loss 很少激活,方法可能退化成普通 CE.要做异构压缩,可先用 CE 预热,再逐渐增加 $\beta$,或者用教师置信度而非学生正确性门控.

用教师正确性门控也有风险:教师在某位置自信但最终轨迹错误时,若整题过滤失效,学生会强化错误.学生门控至少要求当前预测与标签一致,仍依赖标签质量.任何自动验证漏洞都会被低熵目标放大.

安全与拒答场景中,高确定性并非总是优点.模型面对模糊或冲突指令时应保留不确定性、请求澄清或选择安全动作.无差别压熵可能让拒答或错误执行都更坚决.领域扩展应限制训练数据和评价目标,不能把「更敢提交」等同于「更可信」.

### 6.20. 一套不依赖宣传倍率的选型方法

先判断是否允许改权重.不能训练时,dParallel 不适用,应在阈值、动态 remask、缓存和编译中选择.允许 LoRA 且有可验证任务轨迹时,certainty-forcing 才具有低成本优势.它依赖教师生成和正确性筛选,训练权限本身还不够.

再判断输出约束是否主要由局部上下文决定.短算术、格式化抽取和模板代码更可能让多个位置同时确定;长程规划、严格变量一致性和开放创作存在更强联合依赖.后者可把 dParallel 当作边际加速层,仍需验证器、块内 AR 或回溯.

第三步确认质量预算.如果允许 1–2 点任务下降,可在 Pareto 曲线上取更低阈值;要求严格不降时,阈值应由独立验证集选定,并报告置信区间.「维持准确率」不能只依据一次运行的小幅升降.

第四步看延迟组成.模型前向占绝大多数时,少步收益接近步数比;固定开销、长 prompt 或多用户调度占比高时,收益会缩水.先测原版的分项 profile,再估算减少 $S$ 的价值,比直接套 8.5 倍可靠.

第五步看数据闭环.有执行器、答案验证器或规则检查的任务容易筛正确轨迹;没有验证器的开放域依赖教师自评,低熵可能放大错误.数据闭环越弱,certainty loss 的权重越应保守.

第六步保留回退路径.同一权重应能调高阈值换质量,或在困难样本上增加步数.若部署只支持固定 30 步,长尾题会被迫提交不确定 token.动态预算更符合方法本身的熵信号.

第七步在目标硬件重测.论文的 RTX 6000 Ada、长度 256、batch 和实现构成一个完整口径.模型编译、量化、不同 GPU 和服务 batch 都会改变每步成本.可迁移的是减少前向次数的机制,不是固定秒数.

按这套顺序,dParallel 的价值可以落到明确条件:有一条质量可靠的教师轨迹,学生大部分位置方向已经正确,瓶颈是正确位置变尖太慢,并且端到端延迟由反复全序列前向主导.四项同时成立时,certainty-forcing 很对症;缺任一项,都需要额外方法补位.

**6.21. 几个容易被平均数掩盖的反例**

第一个反例是答案长度混合.一半样本只需 32 token,另一半需要 256 token.若统一画布为 256,短样本在早期 EOS 后仍可能经历固定循环或被 padding 掩盖.平均步数下降可能主要来自短样本,长样本几乎不变.报告按实际输出长度分桶的步数,才能判断长度扩展能力.

第二个反例是模板 token 占多数.一段代码有 80% 的括号、关键字和常见标点可一次高置信生成,剩余 20% 的变量关系仍逐个确定.平均 token/步大幅上升,总步骤却由那 20% 决定;若任务分数恰好由变量关系决定,速度与质量会出现明显分叉.

第三个反例是错误校准恰好不影响验证集.模型把熟悉题型从 0.8 推到 0.99,验证集准确率保持;分布外题上同样把错误答案推到 0.99.同域主表会显示无损加速,上线输入却更难用阈值区分风险.因此需要跨域或难度外推测试.

第四个反例是教师答案泄漏结构.若自蒸馏提示与测试题共享强模板,学生可在当前块一半明文时快速补齐固定格式;换一种提示格式,确定性地图重新变成顺序前缘.模板鲁棒性需要改写 prompt、交换 CoT 格式或隐藏固定连接词来检验.

第五个反例是 EOS 提前.低熵模型过早预测 EOS,会显著减少延迟,任务评分若答案抽取仍能读到前面的正确数字,看起来速度与准确率双赢;开放生成却产生截断.应单独统计输出长度分布和 EOS 首次提交步,避免把少写内容当成并行提升.

第六个反例是 batch 尾部.单样本平均从 256 降到 30 步,但 1% 难题仍需 200 步.在线 batch 若等待全部完成,P99 决定批次延迟,均值优势无法充分兑现.动态 batching 能移出已完成请求,需要内存重排与调度支持.论文单样本秒数没有回答这一服务问题.

第七个反例是熵低但 token 不可执行.代码模型可能对语法正确的 API 名称极有把握,该 API 在目标库版本不存在.局部概率和语言先验都很尖,外部环境才知道错误.执行反馈、检索或编译器约束属于另一信息源,certainty-forcing 无法从纯轨迹中创造它.

第八个反例是多答案评价过窄.模型生成语义正确但字符串不同的答案,自动 exact match 判错,该轨迹被过滤;教师常用表述被反复保留.最终模型变得更确定,同时更单一.换用语义评价后,所谓准确率损失可能只是表达变化,也可能暴露真正覆盖下降.

这些反例共同说明,并行度不是模型的单一常数.它由长度、模板比例、任务分布、EOS、batch 调度、外部约束和评价函数共同决定.8.5 倍是论文协议下的强结果,最可靠的迁移方式是复用方法并重新测量,而非复用倍率.

真正需要保留的是因果链:训练让正确位置更早形成低熵分布,阈值采样因此能在一次前向后提交更大的集合,网络调用次数随之下降.链条中的任一环换了口径,最终倍率都要重新测量.这个判断比记住单个任务上的秒数更能迁移到新模型.

也就是说,方法迁移看机制是否成立,部署结论看目标环境中的实测曲线,两者缺一不可.
