# CRoCoDiL:连续草稿,掩码解码

[五条性质](../4.3-因子化障碍与联合建模.md) 把 L2 写成:按格边际对了,乘积仍可抽出假句.[CoDD](../4.3.3-codd可算联合层/4.3.3-codd可算联合层.md) 在冻住的 logits 上接可算联合.[离散 copula](../4.3.1-离散copula/4.3.1-离散copula.md) 用 GPT-2 当 copula.Uziel,Belhasin,Levy,Bercovich,El-Yaniv,Zilberstein,Elad 的 [CRoCoDiL](https://arxiv.org/abs/2603.20210) 走第三条:长程结构先在连续句级空间里扩散成一份草稿 $\mathbf{z}_0$,再让掩码去噪器条件在这份草稿上把词揭开.解码器仍是 MDM,一步之内各格仍按边际抽.这份草稿先编码整段级语义,并行揭开共享同一个全局条件,因而较少落入彼此无关的局部最优. > **实验范围**:arXiv:2603.20210v3 首次提交于 2026-03-02,当前版修订于 2026-04-17,仍是预印本.生成实验覆盖 StarCoder Python 子集上适配后的 LLaDA-8B 无条件代码生成;13×/14× 来自长度 512/1024 的 NFE 比,不对应墙钟,tok/s 或 HumanEval 加速.带提示的条件生成尚无实验结果.

实验范围限于无条件代码生成.骨干是 LLaDA-8B,在 StarCoder 的 Python 子集上用 1200 万条,长度 $[0,4096]$ 的程序微调 demasker,从开源 Base 初始化.编码器 $h_\phi$ 从 Qwen embedding 0.6B 初始化,和 demasker 一起再训.潜变量尺寸 $1024\times K$,$K$ 是寄存器个数,训练里 $1\le K\le 128$,dropout 偏好前面的寄存器,好让推理用更短的 $K$.Nie Table 1 那份通用 Base 的 GSM8K / MMLU 不在这套实验里.作者把带提示的条件生成列为未来工作,见附录 H.文中的加速倍数全部来自无条件 Python,整段当一块的 Figure 6. 摘要写「超过 $10\times$ 更快」.正文例子两档:长度 512,基础 LLaDA NFE $=512$(MAUVE $0.62$,Gen-PPL $19.4$)对 ConWithinDisc NFE $=40$(MAUVE $0.6$,Gen-PPL $14.3$),约 $13\times$;长度 1024,基础 NFE $=1024$(MAUVE $0.76$,Gen-PPL $23.5$)对 ConWithinDisc NFE $=72$(MAUVE $0.8$,Gen-PPL $12.5$),约 $14\times$.NFE 把连续去噪器也折算进去了:400M 的连续 demasker 跑 128 步,约等于 6 次 8B 前向;条件连续扩散 32 步,少于 2 次 NFE.报 $13\times$ 时分母是这套折算后的 NFE,不是墙钟,不是 GSM8K 时延.

## 1. 边际 demasker 缺的是整段草稿

**1.1. 从边际预测到共享全局条件.** 掩码扩散的 demasker 输出各格 logits,训练目标是按格交叉熵.并行揭开等于从乘积里抽,提交得越激进,跨位置联合误差越大.MDM 揭开 token 后直接写入最终序列,后续步骤只有部分完成的离散文本可用,缺少一份覆盖整段语义的全局草稿.局部片段可以自洽,整段主题与结构仍可能漂移.

CRoCoDiL 把「整段在干什么」放到连续空间.编码器 $h_\phi$ 把干净序列映成 $\mathbf{z}_0$.demasker 变成 $f_\theta(\mathbf{x}_t,t,\mathbf{z}_0)$,每格仍独立抽 $\hat x_0^i$,但条件多了这份草稿.长程结构由轻量连续扩散在潜空间里长出来,MDM 负责把草稿译成词.作者的类比是:潜变量是素描,MDM 是按素描上色.素描可以不完整,MDM 的迭代还能补.COSMOS 的解码器没有生成能力,潜变量必须自己带齐所有信息.E2D2 把提示编成连续向量去导离散回答,回答侧仍是普通 MDM,跨 token 依赖仍缺.CRoCoDiL 的 $\mathbf{z}_0$ 表示无条件整段程序,不承担从提示到答案的条件映射. 相关工作里点名的 DCD copula,能量模型,高斯隐变量,作者写成小尺度上补联合.CRoCoDiL 的尺度是 8B demasker 加 0.6B 编码器再训,任务是无条件 Python.DCD 的 32× NFE 对照 SEDD 多步,尺度 GPT-2.CoDD 的 +5.00 是 LLaDA 低置信 MATH500 256 步.三套分母不能减.

COSMOS 也在连续潜空间扩散.差别在解码器:COSMOS 的解码没有生成能力,潜变量必须自己带齐所有信息,少一点就译不回来.CRoCoDiL 的 MDM 会迭代揭开,素描可以残缺.E2D2 在有提示的设定里把提示编成连续向量,用普通 MDM 写回答;跨 token 依赖仍在回答侧的因子化里.CRoCoDiL 做无条件整段生成,demasker 从第一步就条件在 $\mathbf{z}_0$ 上.推理期只改揭开顺序的算法(条件独立性检验,膨胀日程)被写成:它们在找「不太相关的格一起揭」,相关格若处处都在,加速就停.CRoCoDiL 不找独立格,它先把相关写进草稿.

高斯隐变量那条(Xie 等人 VADD)也是给离散扩散加连续相关.作者把它和 copula,能量模型放在小尺度一栏.8B 实验没有提供与 VADD 的同协议对照.能量模型 Xu 等人 ICLR 2025 用能量给文本扩散补依赖,配分一般不可精确求;CoDD 后来走可算回路,是另一篇.CRoCoDiL 连续侧是高斯扩散,离散侧仍因子化,依赖靠 $\mathbf{z}_0$ 这个条件,不靠能量. **1.2. 连续草稿怎样诱导离散联合.** 给定草稿 $z$,demasker 的一步输出仍可按位置分解:

$$
p_\theta(x_M\mid x_t,z)
=\prod_{i\in M}p_\theta(x_i\mid x_t,z).
$$

如果 $z$ 本身是随机变量,对它边缘化后得到

$$
p(x_M\mid x_t)
=\int p_\psi(z\mid x_t)
\prod_{i\in M}p_\theta(x_i\mid x_t,z)\,dz.
$$

条件在固定 $z$ 上的位置独立,混合之后一般相关.两个位置都读取同一草稿样本,其输出会随 $z$ 共同变化.这是连续草稿承载离散联合的概率来源:相关性位于潜变量混合,不在单次 demasker 的输出头. 可以用二元例子手算.令 $z\in\{-1,+1\}$ 等概率,给定 $z$ 时两个 token 都以 0.9 概率取 $\mathbb 1[z=+1]$.边缘上每个 token 仍接近均匀,两个位置相等的概率却为 $0.9^2+0.1^2=0.82$.若忽略共享 $z$、从边缘独立采样,相等概率只有 0.5. CRoCoDiL 推理时通常先采一份 $z_0$,再让整段离散解码共享它.这对应从混合分布中先选一个成分,随后条件生成.如果每个位置各自采独立 $z_i$,相关性会消失;如果每个去噪步无条件重采 $z$,草稿语义可能在步骤间漂移.

**连续草稿提供的是潜变量诱导联合,固定草稿后的 token 输出仍为因子化分布.** 它减少联合误差的能力取决于 $z$ 是否携带相关结构,以及 demasker 是否真正使用这份条件. **1.3. 联合分布的表达上限.** 潜变量混合理论上能表示复杂联合.若 $z$ 有足够容量,每种离散序列都可对应一个潜区域,条件解码器近似确定性.这时边缘化能恢复任意分布.有限寄存器、有限网络和连续扩散训练使实际模型远离这个极限. 表达能力可以按互信息约束理解.离散序列与草稿之间的信息满足

$$
I(X;Z)\le H(Z),
$$

连续变量的微分熵不直接等于可用比特,噪声、有限精度和解码器容量共同限制通道.寄存器数 $K$ 增大提供更多维度,也让无条件连续扩散更难生成正确分布. 若两个序列共享同一全局主题、局部细节不同,$z$ 可以只编码主题,MDM 负责细节.若任务要求逐字符精确重建,$z$ 需承载更多信息或依赖已揭开的离散 token.自编码器 Table 1 的 CER 与 CodeBERTScore 差异正体现语义草稿和字符还原的不同目标. 潜变量还可能被 demasker 忽略.强大的 8B 模型在低掩码率下可从 $x_t$ 自己恢复 token,梯度不必经过 $z$.高掩码率和少步重建更能检验草稿是否有信息.扫 $K$ 与掩码率的交叉熵曲线比单一最终分数更直接. **1.4. 连续松弛和 token 嵌入扩散不同.**

token 嵌入扩散把每个离散 token 映射到连续向量,对每个位置加噪,最后用 rounding 或 softmax 回词表.连续变量与 token 位置一一对应,量化边界直接影响每个词. CRoCoDiL 的 $K$ 个寄存器不与 $n$ 个 token 一一对应.编码器把整段压进 $z_0\in\mathbb R^{1024\times K}$,连续扩散建模的是句级表示分布.离散 token 仍由 MDM 输出词表概率,没有把潜向量最近邻量化成 token. 因此量化发生在解码器输出,不是潜空间 rounding.草稿误差先改变 demasker logits,再通过离散采样变成 token 差异.两个相近 $z$ 可能落入同一离散程序,也可能跨过某个高敏感决策边界产生完全不同的标识符.

连续松弛的好处是梯度可穿过编码器与 demasker,可以联合训练.代价是潜空间几何由任务损失间接塑造,欧氏距离未必对应代码语义距离.连续扩散使用高斯噪声隐含局部平滑假设,需要实验证明潜表示满足它. **1.5. 量化误差如何传播到离散序列.** 设理想草稿为 $z^*$,连续生成得到 $\widetilde z=z^*+\delta$.某位置 logits 为 $l_i(z)$.一阶展开

$$
l_i(\widetilde z)
\approx l_i(z^*)+J_i(z^*)\delta,
$$

$J_i$ 是 logits 对草稿的 Jacobian.若正确 token 与次优 token 的 margin 为 $m_i$,当扰动投影超过 $m_i$ 时,argmax 可能翻转.草稿 L2 误差小,不保证离散输出稳定;关键是 Jacobian 与 margin. 首个 token 翻转后会进入后续 $x_t$,demasker 再把它作为条件,误差从潜扰动转为离散上下文扰动.后续步骤可能纠正,也可能强化错误.标识符首次出现被改名后,全局一致地沿用新名字会造成 CER 高、语义仍接近;这与 Table 1 的观察一致. 可以按潜扰动大小画三条曲线:重建交叉熵、token flip rate、执行或语义分数.若语义曲线比 CER 平缓,潜空间确实优先保留高层结构.若极小扰动导致执行结果骤降,连续草稿存在脆弱方向. **1.6. 固定草稿与中途修正.** ConThenDisc 先采 $z_0$,整条离散轨迹固定条件.优点是全局意图稳定,缺点是早期草稿错误无法利用已生成 token 修正.其联合分布为

$$
p(x)=\int p_\psi(z)
p_\theta(x\mid z)dz.
$$

ConWithinDisc 在中途根据部分离散状态更新草稿.若更新核为 $p_\psi(z'\mid z,x_t)$,生成变成耦合链:

$$
z^{(s+1)}\sim p_\psi(z\mid z^{(s)},x_{t_s}),
\qquad
x_{t_{s+1}}\sim p_\theta(x\mid x_{t_s},z^{(s+1)}).
$$

离散文本给草稿提供证据,草稿再约束下一轮 token.这能修正初始潜样本,也可能产生反馈错误:早期错误 token 让草稿向错误语义移动,更新后的草稿又使错误更稳定. 正文只做一次中途更新,减少连续侧计算和反馈次数.更新时机决定可用证据:太早时 $x_t$ 大多是 mask,编码器输入分布外;太晚时大部分 token 已提交,草稿没有足够纠错空间. **1.7. 连续草稿不能自动消除因子化.** 若真实依赖在给定 $z$ 后仍存在,条件乘积仍有缺口.例如 $z$ 只编码「生成一段括号串」,具体成对位置没有进入草稿,同时提交括号仍可能不匹配.潜变量要成为足够统计量:

$$
X_i\perp X_j\mid Z,x_t
$$

才会消除相应条件依赖.有限草稿通常只降低总相关量,不会归零. 这给出直接测量:比较原条件总相关量与给定真实编码 $z_0=h(x_0)$ 后的剩余总相关量.小词表可枚举,真实代码可用成对互信息或约束违例作 proxy.若真实草稿条件下仍有大缺口,连续生成再准确也无法完全解决. CoDD 与连续草稿可以组合,因为二者作用层不同:草稿解释全局混合成分,PC 修固定草稿后的局部相关.现有论文没有组合实验,因此这里只能从分布分解看到兼容性,不能声称性能会叠加.

## 2. 编码器和解码器一起训

**2.1. 寄存器编码与两阶段训练.** 损失仍是掩码扩散那一项,只是 demasker 看见 $\mathbf{z}_0=h_\phi(\mathbf{x}_0)$.抽干净 $\mathbf{x}_0$,抽 $t\sim U[0,1]$,按吸收态掩出 $\mathbf{x}_t$,网络吃 $(\mathbf{x}_t,t,h_\phi(\mathbf{x}_0))$,对被掩位置做交叉熵.权重沿用 LLaDA 的 $1/\alpha_t$.$\phi$ 和 $\theta$ 一起更新.没有这份条件时,式子退回普通 MDM.

变长靠 BOS / EOS.微调后的 demasker 会写不同长度的程序,开头结尾用这两个特殊词标出来.潜变量不是「一个 1024 维向量」,是 $K$ 个 1024 维寄存器排成的矩阵.训练对后面的寄存器做 dropout,推理时长度 512 用 $K=8$,长度 1024 用 $K=16$,自编码器 Table 1 用满 $K=128$.$K$ 不是 Transformer 层数.寄存器越多,草稿越细,Figure 4 上有条件 demasker 的交叉熵缝越大.生成 Figure 6 没有用满 128,因为无条件连续扩散还要先把这些寄存器从噪声里长出来,$K$ 太大,连续侧更难.dropout 偏好前面的寄存器,意思是短 $K$ 时仍然用矩阵的前几列,而不是随机抽子集.这样 $K=8$ 的推理和 $K=128$ 的训练共享同一套列对齐.附录 C 写 FlexTok 一类工作把图压成变长 1D token,这里是把程序压成变长寄存器.FlexTok 的图像结果不参与程序生成比较.

1200 万条 Python 相对 LLaDA 原文的 2.3T 通用 token,属于领域适配.开源 Base 用作初始化,损失仍是带 $1/\alpha_t$ 的掩码交叉熵,demasker 额外接收 $\mathbf{z}_0$.论文没有报告适配后的通用 MMLU / GSM8K,所以 $13\times$ 只代表 Python 无条件生成,不代表聊天任务.Qwen embedding 0.6B 的论文是 Qwen3 Embedding;初始化之后 $\phi$ 和 demasker 会联合更新,权重未必还对应公开检索模型,检索分数也不能代表联合训练后的编码器. ConThenDisc 的循环按 Algorithm 2.从 $\epsilon\sim\mathcal{N}(0,I)$ 用 $G_\psi$ 得到 $\mathbf{z}_0$.$\mathbf{x}$ 从全掩出发.每一步 demasker 条件在这份冻住的 $\mathbf{z}_0$ 上预测 $\hat{\mathbf{x}}_0$,再按前向核把下一步该掩的位置盖回去,$t$ 减 $1/T$.$T$ 小则每步揭得多.草稿不变,等于整段生成共用一张素描.

ConWithinDisc 每步(或选定的子集步)先抽新的 $\mathbf{z}_0\sim G_\psi(\epsilon,h_\phi(\mathbf{x}_t))$,再揭开.正文为了省,只在 MDM 中途加一次连续更新,NFE 额外少于 2.作者列出三条未做完的改进:更新可以更勤;条件可以直接打在 $\mathbf{x}_t$ 上而不经 $h_\phi$;给掩码输入另训编码器 $h_\mu$.主表没有这三档的数字. 自编码器评测把这件事反过来用:已知 $\mathbf{z}_0=h_\phi(\mathbf{x}_0)$,从全掩出发跑少步 MDM,看能不能把程序找回来.Figure 4 在 1000 条验证程序上画交叉熵和 top-1:掩码率升高,所有曲线都差;条件在 $K=8/64/128$ 上优于无条件基线,$K$ 越大缝越大.曲线点没有进入主表,因此只报告趋势,不引用阴影区域的读数.

**2.2. 联合训练目标怎样分解.** 自编码阶段最基本的损失是条件掩码交叉熵:

$$
\mathcal L_{\mathrm{disc}}
=\mathbb E_{x_0,t,x_t}
\left[
w(t)\sum_{i:x_{t,i}=\mathtt{MASK}}
-\log p_\theta(x_{0,i}\mid x_t,t,h_\phi(x_0))
\right].
$$

梯度同时更新编码器 $\phi$ 与 demasker $\theta$.编码器被鼓励输出能降低各掩码位置 loss 的草稿,没有单独要求潜空间服从高斯或欧氏平滑.如果只优化这项,编码器可能形成不规则、离散化很强的潜簇,后续高斯扩散难以学习. 连续生成阶段固定或使用训练后的编码器,收集 $z_0=h_\phi(x_0)$,训练连续去噪器 $G_\psi$.标准噪声过程写成

$$
z_t=\alpha_t z_0+\sigma_t\epsilon,
\qquad \epsilon\sim\mathcal N(0,I),
$$

去噪目标可预测 $z_0$、噪声 $\epsilon$ 或 velocity,具体参数化以论文附录为准.这一步让模型从高斯噪声生成编码器潜分布. 两阶段目标存在错配.自编码器希望 $z_0$ 尽量利于离散重建,连续扩散希望 $z_0$ 分布平滑易生成.寄存器 dropout 与有限 $K$ 提供瓶颈,没有显式保证两目标最优一致.生成质量取决于折中. **2.3. 寄存器 dropout 在优化什么.** 训练时优先保留前几个寄存器、随机丢弃后部,使前缀寄存器承担核心信息.设最大寄存器数 $K_{\max}$,随机有效长度 $K\sim\pi(K)$.编码器目标变为

$$
\mathbb E_{K\sim\pi}
\mathcal L_{\mathrm{disc}}
(h_\phi(x_0)_{1:K}).
$$

较小 $K$ 出现频繁时,前几个寄存器必须支持粗略重建;较大 $K$ 再补细节.这形成渐进式表示,推理可以按序列长度选择 $K=8$ 或 $16$,无需为每个 $K$ 训练独立编码器. 该机制没有保证寄存器严格按语义层次排序.后部寄存器可能与前部协同编码,截断后 demasker 通过鲁棒性补偿.可以测新增第 $k$ 个寄存器带来的条件 NLL 降幅

$$
\Delta_k=\mathcal L(K=k-1)-\mathcal L(K=k).
$$

若 $\Delta_k$ 递减,渐进信息假设较合理;若某些后部寄存器突然贡献很大,固定短 $K$ 会遗漏特定模式. dropout 分布也影响连续扩散训练.连续模型若只看满 $K=128$ 潜矩阵,推理截成 $K=8$ 属于形状变化;论文对变长潜序列另有训练处理.报告 $K$ 时要区分自编码上限与生成工作点. **2.4. 编码器为何可能泄漏答案.** 自编码器训练中 $h_\phi$ 读取完整 $x_0$,demasker 当然可从草稿恢复被掩 token.这证明表示容量与可解码性,没有证明无条件生成时能从噪声采到同样正确的 $z_0$.Table 1 是上界诊断. 若编码器近乎逐 token 搬运答案,重建会很好,连续潜分布却复杂.寄存器数 $128$、每个 1024 维,容量很大;瓶颈来自共享寄存器、dropout 和训练,不能只按维数断言压缩程度.

可用线性 probe 或最近邻检查潜变量是否记住具体 token.将 $z_0$ 的小扰动输入 demasker,观察字符级重建稳定性.高度脆弱且近邻对应完全不同程序,说明潜几何不利于连续扩散. 还可比较真实编码草稿与连续生成草稿的统计:均值、协方差、范数、寄存器间相关、demasker 条件 NLL.两者分布接近,生成阶段才有可能复现自编码能力. **2.5. 连续扩散训练的分布对象.** 连续模型学习的是编码器推送分布

$$
p_\phi(z)=\int \delta(z-h_\phi(x))p_{\mathrm{data}}(x)dx.
$$

它不是标准高斯,也不保证满维.若编码器输出落在低维流形,前向高斯噪声会把流形扩散开,反向模型需恢复复杂几何.400M demasker 的容量与 2M 潜样本决定拟合程度. 序列长度与 $K$ 改变潜分布.长度 512 用 $K=8$,1024 用 $K=16$,连续模型要么支持不同形状,要么分别设置条件.两档 NFE 同时变化,无法只归因于长度. 训练潜变量若来自联合更新期间不断变化的编码器,连续数据分布也会漂移.常见做法先完成自编码训练、冻结编码器、再抽取潜数据.若交替训练,旧缓存潜变量会过期.论文阶段划分需要按附录复现. **2.6. 中途修正为何是后验问题.** 生成到部分状态 $x_t$ 后,理想草稿分布应为

$$
p(z\mid x_t)
\propto p(z)p_\theta(x_t\mid z).
$$

ConWithinDisc 的条件连续扩散试图近似这个后验.已揭开的 token 作为观测更新全局意图,新草稿同时继承初始潜状态与当前离散证据. 正文用 $h_\phi(x_t)$ 作为条件,但编码器训练主要读取干净程序.包含大量 `[MASK]` 的输入属于分布变化.若编码器把 mask 当普通 token,条件表示可能偏离理想后验统计.作者提出单独训练 $h_\mu$ 正是针对这一点. 后验可能多峰.部分前缀兼容多种程序结构,连续扩散若取单一均值会产生两种模式的混合草稿,demasker 难以解释.随机条件扩散保留多样性,代价是一次更新可能跳到另一语义模式. 修正频率越高,潜–离散耦合越强,也越贵.每一步更新草稿并不保证单调提高离散 likelihood.可以记录更新前后真值条件 NLL或结构约束,检验修正是否朝正确方向.

**2.7. 草稿冻结后的误差传播.** ConThenDisc 初始草稿若缺少某个全局结构,离散解码只能依靠自身 $x_t$ 补充.少步时每轮提交多,错误更容易被固定.草稿误差会同时影响多个位置,产生相关错误,与普通因子化的独立错位不同. 设草稿误差为 $e_z$,第 $s$ 步离散状态误差为 $e_s$.局部线性分析可写

$$
e_{s+1}\approx A_s e_s+B_s e_z+\xi_s,
$$

$A_s$ 描述离散上下文误差传播,$B_s$ 描述共享草稿影响,$\xi_s$ 是采样噪声.固定草稿使 $e_z$ 在每一步重复注入;中途修正相当于替换 $e_z$. 如果 $B_s e_z$ 让所有标识符一致改名,局部一致性反而高,字符参考不一致.如果草稿在控制流结构上错误,多个块会共同偏离,MDM 很难局部修补.按错误类型分析比平均 CER 更有意义. **2.8. 离散与连续步数怎样共同构成预算.** 令连续去噪步数为 $T_c$,连续模型单步成本为 $C_c$;离散步数为 $T_d$,8B demasker 单步成本为 $C_d$.总计算近似

$$
C_{\mathrm{total}}
=T_cC_c+T_dC_d+C_{\mathrm{update}}.
$$

作者把 $T_cC_c/C_d$ 折算成等效 NFE,便于和基础 LLaDA 比.400M 与 8B 参数比约 1:20,单步成本还受序列形状、attention 与硬件利用率影响,参数比不是精确 FLOPs 比. 中途条件扩散增加少于 2 个等效 NFE,说明连续模型较小.墙钟加速还受两个网络交替、kernel 启动、内存读写和 batch 影响.因此 NFE 是算法预算,不是时延实测. 优化预算可在 $T_c$ 与 $T_d$ 间分配.更多连续步改善草稿,更多离散步允许 token 自纠.等总 NFE 网格能回答哪侧更值得投入.只比较基础 $T_d=n$ 与一个混合工作点,无法得到完整 Pareto 前沿.

## 4. 与连续嵌入扩散,联合层和推理加速的关系

**4.1. 相邻路线的接口差异.** [从图像到离散](../../../02-数学与生成机制/2.1-从ddpm到离散token/2.1-从ddpm到离散token.md) 里的连续路线把噪声加在 token 嵌入上,最后 rounding.CRoCoDiL 的连续扩散加在句级寄存器上,词仍由离散 MDM 揭开,没有 rounding 成词这一步.Diffusion-LM 的 80M 句法树结果对应 token 嵌入连续扩散,与句级寄存器实验协议不同. [CoDD](../4.3.3-codd可算联合层/4.3.3-codd可算联合层.md) 冻结 8B 骨干并训练 HMM,实验指标是 MATH500 / GSM8K 准确率.CRoCoDiL 继续训练 8B demasker 和编码器,实验指标是无条件 Python 的 MAUVE / Gen-PPL / NFE.前者补充因子化输出缺失的联合项,后者提供全局草稿.两种模块在结构上可以组合,现有实验未评估该组合. [离散 copula](../4.3.1-离散copula/4.3.1-离散copula.md) 推理期 I-投影,尺度 GPT-2.CRoCoDiL 把 copula 写成相关工作里的小尺度联合补丁.8B 上他们选的是连续草稿,不是 I-投影.

## 5. 怎样检验连续草稿机制

**5.1. 三个层次必须分开.** 第一层是自编码上限:给真实 $z_0=h(x_0)$,测少步 MDM 能否重建.它回答表示是否携带信息、demasker 是否会读取.第二层是连续生成:从高斯噪声得到 $\widetilde z_0$,测其分布是否接近编码潜变量.第三层是离散生成:给生成草稿后,少步 MDM 是否产生高质量程序. 三个层次的误差可串联.真实草稿重建差,瓶颈在编码或解码;真实草稿好、生成草稿条件 NLL 差,瓶颈在连续模型;两者都好、最终采样差,瓶颈在离散日程与量化决策.只看 Figure 6 最终 MAUVE 无法定位. 一个完整结果表应同时列 oracle $z_0$、生成 $z_0$、中途修正 $z$ 三档.每档固定离散 NFE,报告 token NLL、CER、CodeBERTScore、执行率和分布指标.这样能看到连续生成距离自编码上限还有多远. **5.2. 合成联合任务能证明什么.**

构造长度 $n$ 的二元序列,全局潜类 $c\in\{0,1}$.给定 $c$,每位以 0.9 概率等于 $c$.真实单点边际均匀,位置之间强相关.一维草稿只需编码 $c$,条件 demasker 即可并行生成一致序列. 再加入局部异或规则,让全局类决定主题、相邻 token 决定细节.草稿应承担 $c$,MDM 迭代承担局部依赖.扫草稿维度和离散步数,可以看到二者分工.如果增加 $K$ 只改善全局一致,增加 $T_d$ 只改善局部规则,机制解释得到支持. 反例任务让每条序列由独立 token 构成.共享草稿没有联合结构可学,理想结果应接近基线.若仍大幅提升,收益可能来自额外容量或边际校准,并非补联合. 另一个反例要求精确复制随机长串.压缩草稿容量不足时,真实 $z_0$ 重建也会失败.这能测信息瓶颈,避免把所有错误归给连续扩散.

**5.3. 潜空间插值不是充分证据.** 常见可视化在两个程序草稿间线性插值

$$
z(\lambda)=(1-\lambda)z_A+\lambda z_B.
$$

若解码程序平滑变化,说明某条路径可用;它没有证明整个高斯噪声区域落在数据流形附近.高维空间中随机生成路径与两点直线分布不同. 更严格的检查包括随机方向扰动、球面插值、编码样本最近邻距离和生成潜变量的 density ratio.还要运行生成代码或解析 AST,仅看文本相似可能错过语义断裂. 插值中途若输出两个程序的拼接,可能看起来平滑,执行却失败.连续草稿需要由离散约束评估,不能只展示潜图或 PCA. **5.4. 量化边界的可证伪实验.** 对真实 $z_0$ 加不同范数的高斯扰动,固定离散随机种子,测首个 token flip.按位置 margin 分桶,验证低 margin 位置更敏感.若 flip 与 $\|J_i\delta\|$ 相关,一阶传播解释成立.

随后比较一次性 argmax、低温采样和多步 remask.多步能修复部分量化翻转时,CER 随 NFE 下降;无法修复的错误更可能来自草稿结构.记录错误首次出现与是否被重掩. 还可沿 Jacobian 最大奇异向量扰动.相同 L2 范数下,最坏方向比随机方向造成更多离散变化,说明平均重建掩盖对抗性脆弱方向.这不必解释成安全攻击,它是潜几何诊断. **5.5. 草稿修正应该在什么时候发生.** 设离散过程完成比例为 $u\in[0,1]$,在 $u$ 处执行一次连续后验更新.扫描 $u=0.1,0.25,0.5,0.75,0.9$.太早时证据少,太晚时可改位置少,中间可能存在最优点. 每个 $u$ 记录更新前后草稿与真实编码的距离、demasker 条件 NLL、最终质量和额外 NFE.如果距离下降但质量不升,欧氏潜距离与解码语义不一致.如果 NLL 改善而最终不升,离散提交已锁定错误.

再扫描更新次数,保持连续总步数固定.多次短更新与一次长更新比较,能区分频繁反馈和连续去噪精度.若多次更新更差,早期离散错误可能污染后验. **5.6. 掩码编码器的分布变化.** 干净编码器 $h_\phi(x_0)$ 在训练中几乎不见 `[MASK]`.直接用于 $x_t$ 时,表示可能主要反映 mask 数量,不是已知 token 语义.按掩码率训练 probe 预测原程序主题,可测信息保留. 单独训练 $h_\mu(x_t,t)$ 应让其输出接近后验需要的条件,目标可以是匹配干净潜变量、改善连续去噪或直接降低最终离散 loss.三种目标不等价.简单 MSE 会把多峰后验压成均值. 对照包括干净编码器、mask 增强编码器、专用编码器和只用可见 token pooling.固定连续模型与更新步数,才能把收益归到条件表示. **5.7. 寄存器数量的公平扫描.**

$K$ 增大时,自编码信息、连续模型输入维度和计算量同时增加.公平扫描应固定连续总 FLOPs或分别报告质量–成本曲线.直接比较 $K=8$ 与 $128$ 的重建,只能说明容量上限. 对每个 $K$ 记录真实草稿重建、生成草稿重建和无条件生成.如果真实草稿持续改善、生成草稿先升后降,连续生成难度成为瓶颈.最佳 $K$ 位于两条曲线交点附近. 还应比较相同总维数下的形状,例如 $K=8,d=1024$ 与 $K=16,d=512$.前者寄存器少而宽,后者多而窄.差异能揭示模型需要多个槽位还是纯容量. **5.8. 连续草稿是否只学到长度.** 无条件程序的长度、缩进和 EOS 位置对 MAUVE 与 Gen-PPL 都有影响.草稿可能先学会长度分布,少步 MDM 因而减少提前结束,但未必改善代码逻辑.

固定生成长度或向模型显式提供长度条件,再比较有无草稿.收益若大幅缩小,长度先验贡献较大.也可训练一个只编码长度的弱草稿作为基线. 从 $z$ 预测 token 数、AST 深度、函数数和标识符数,能量化潜变量承载哪些全局属性.长度 probe 很强、语义 probe 很弱时,「整段语义草稿」需要收窄为结构尺寸草稿. **5.9. NFE 与墙钟的换算边界.** 等效 NFE 用模型参数规模近似连续与离散前向成本.Transformer FLOPs 还取决于层数、隐藏维、序列长度、attention 形状与 batch.400M 连续模型处理 $K$ 个寄存器,8B demasker 处理 512 或 1024 token,两者单步成本比未必等于参数比. 实际墙钟还包含网络切换、潜变量搬运和同步.连续模型小但运行 128 次,可能受 kernel 启动限制;大 batch 下吞吐关系又不同.13×/14× 只能写成 NFE 减少.

公平系统测量应给单请求延迟、batch 吞吐、峰值显存和能耗.同时记录连续与离散各自耗时.如果墙钟加速小于 NFE 比,差额来自这些执行成本;如果更大,小模型可能有更高硬件利用率. **5.10. 误差怎样跨连续和离散阶段传播.** 把最终任务损失记为 $L(x)$.草稿采样误差、条件解码误差和离散采样误差可以通过耦合实验分离.使用同一真实 $z$ 比较不同离散种子估计第三项;使用真实与生成 $z$、固定离散随机数估计草稿贡献;使用不同编码器看表示贡献. 误差未必相加.较差草稿有时被更多离散步修复,较好草稿在激进提交下也会量化错.需要二维网格 $T_c\times T_d$,不能只做单轴消融.

中途修正进一步形成反馈.保存每次 $z$ 更新与 token 状态,计算更新前后结构约束.若错误在一次潜更新后同时扩散到多个位置,共享草稿是传播通道;若更新纠正多处相关错误,同一通道带来收益. **5.11. 反例:共享草稿可能放大错误.** 若草稿误判程序要实现排序,demasker 可能在函数名、循环结构和返回值多处一致地产生排序代码.局部 token 彼此协调,整体任务仍错.共享条件把错误从独立噪声变成相关偏差. 无条件生成中没有题目真值,这种全局偏差可能仍像真实代码,MAUVE 不一定惩罚.条件生成才会暴露草稿是否服从 prompt,而论文尚无对应主表.

另一个反例是多模态程序分布.部分前缀同时兼容递归与迭代实现,中途后验更新若在两模式间取平均,草稿可能同时推动两种结构,产生不完整混合.保持随机多峰比均值回归更重要. **5.12. 反例:更好的 Gen-PPL 不等于更好的程序.** 外部语言模型偏好常见、流畅的 Python.生成模板化程序可以得到较低 Gen-PPL,不保证执行正确或功能多样.无条件任务又没有测试用例,无法测 Pass@1. MAUVE 比较生成与真实分布,也依赖特征模型和样本量.它对细粒度语法错误、死代码和安全漏洞未必敏感.两指标同时改善支持分布匹配,没有证明代码功能. 可以补充 parse rate、静态检查、执行无异常比例、圈复杂度和去重率.条件代码任务还需 HumanEval/MBPP,但那属于论文未来范围,不能由现有数字推断.

**5.13. 草稿更新会不会降低多样性.** 连续先验 $p(z)$ 决定高层模式多样性,条件 demasker 决定给定模式内的细节.如果连续扩散 mode collapse,不同噪声生成相似 $z$,离散采样再随机也只在局部变化. 测量潜空间 pairwise distance、聚类占用和生成代码 AST 多样性,能区分高层与表面多样性.固定 $z$ 多次解码估计模式内多样性,换 $z$ 固定离散种子估计模式间多样性. ConWithinDisc 中途修正可能把不同初始 $z$ 拉向相同高概率模式,提高质量同时降低模式覆盖.比较修正前后潜簇熵与 MAUVE,可以看到折中. **5.14. 条件生成需要新增哪条概率链.** 有提示 $c$ 时,理想模型是

$$
p(x\mid c)
=\int p_\psi(z\mid c)
p_\theta(x\mid z,c)dz.
$$

提示要同时约束草稿与离散解码.只让 demasker 读提示、连续先验仍无条件,草稿可能与任务冲突;只让连续模型读提示、demasker 依赖 $z$,又要求草稿完整传递条件. 训练需要成对 prompt–answer 数据,编码器应编码答案或联合上下文,连续模型学习 $p(z\mid c)$.无条件 StarCoder 程序没有这条映射.附录算法接口说明可扩展,不构成实验证据. 条件生成还引入 prompt 长度与 KV cache.8B demasker 每步读 prompt,连续模型是否也读全文影响成本.因此无条件 NFE 比不能直接迁移到聊天延迟. **5.15. 与 CoDD 组合时会发生什么.** 给定草稿后的 demasker 仍按位置输出边际,可以再乘概率回路:

$$
p(x_M\mid x_t,z)
\propto p_\omega(x_M)
\prod_{i\in M}p_\theta(x_i\mid x_t,z).
$$

草稿承担全局模式,PC 承担固定草稿后的局部结构.如果两者学习相同依赖,乘积可能过度尖锐;如果结构互补,联合缺口进一步缩小. 组合训练可先冻结各模块,只验证推理;也可联合优化.前者容易定位,后者成本高且可能让 demasker重新分工.现有论文没有组合结果. 公平对照应含基线、仅草稿、仅 PC、两者组合四格,固定总 NFE 与训练数据.只有组合超过两条单路线,才能说明互补. **5.16. 连续草稿的有效信息量.** 潜维数不能直接换算成模型实际使用的信息.可以用 variational probe 估计 $I(X;Z)$ 下界,或训练不同容量解码器测可恢复属性.更简单的方法是逐寄存器置零、打乱和交换,观察重建变化.

若打乱寄存器顺序几乎无影响,寄存器更像可交换集合;若交换后质量下降,位置承担专门角色.前缀 dropout 倾向形成有序重要性,但 Transformer 对寄存器的位置编码也可能制造顺序依赖. 跨样本交换后部寄存器可以测它们编码全局还是细节.若主结构来自前部、变量名与格式随后部变化,渐进草稿解释更可信.若任何一个后部寄存器都会改写主题,短 $K$ 推理可能不稳定. **5.17. 潜变量的尺度与归一化.** 连续扩散通常假设各维尺度相近.编码器输出若某些寄存器范数特别大,高斯噪声的相对强度不同.归一化、whitening 或 learned scale 会改变前向 SNR.

对每个寄存器统计均值、方差和协方差谱.强各向异性表示标准 isotropic noise 在不同方向破坏信息程度不同.低方差但语义敏感方向可能很早被噪声淹没. whitening 能让连续训练更容易,也会改变 demasker 条件接口.若在编码后变换 $z'=A(z-mu)$,解码时必须逆变换或让 demasker读新坐标.线性处理保持信息,数值与优化会变化. 不同 $K$ 下的尺度也应一致.截断后若 LayerNorm 统计改变,质量差可能来自分布尺度,不全是信息减少.按有效寄存器重新归一化与保持训练统计需要分别消融. **5.18. 连续采样复杂度不只看参数量.** 连续去噪器处理 $K$ 个 1024 维寄存器,attention 成本约随 $K^2$ 增长,MLP 随 $K$ 线性.从 $K=8$ 到 $16$,单步成本未必只翻两倍,但仍远小于处理 1024 token 的 8B demasker.

总连续成本还取决于 128 步能否批量、是否使用 ODE/SDE solver 和 classifier-free guidance.若每步包含两次条件/无条件前向,等效 NFE 要加倍.论文折算以其具体实现为准. 中途更新的条件连续扩散 32 步,输入还包括 $h(x_t)$.编码器前向本身有成本;若 NFE 折算只计 $G_\psi$,会低估.复现应逐模块计时. **5.19. 少步离散解码为什么会依赖草稿质量.** 设序列长度 $n$,离散步数 $T_d$,平均每步提交 $n/T_d$ 个位置.步数减少时,同一轮提交集合增大,位置之间无法互相看到本轮结果.共享草稿必须解释更多联合结构. 若草稿足够,给定 $z$ 后条件总相关量小,大集合并行安全.定义

$$
G(z,x_t)=\operatorname{TC}(X_M\mid z,x_t).
$$

理想编码器降低 $G$.可在小任务上枚举,真实代码用约束违例与成对互信息近似.随着 $K$ 增大,$G$ 应下降;若不下降,额外寄存器只改善边际. Figure 6 说明生成草稿在 40/72 NFE 下维持分布指标,支持这种可能.它没有直接测 $G$,所以联合解释仍属于机制推断,需要受控实验补强. **5.20. 基础 NFE 等于长度意味着什么.** 长度 512 用 512 次 demasker,近似每步提交一个 token.这把同步因子化误差压到最低,作为高质量慢基线.它没有使用 AR 因果 cache,每步仍是全序列 MDM 前向. 因此 512→40 的比值混合两项:草稿让每步可提交更多位置,基础实现每次全长重算.若加入 KV 近似、块扩散或更强调度,基础墙钟会改变.论文比较的是同骨干采样族中的 NFE.

如果基础在较低 NFE 也能用更好规划器保持 MAUVE,草稿相对优势会缩小.应画相同 NFE 下基线、ConThenDisc、ConWithinDisc 的完整 Pareto 曲线,而非只看两个端点. **5.21. 自编码指标怎样读.** CER 精确比较字符,变量重命名与空格都会计错.CodeBERTScore 用语义表示匹配,可能对执行错误不敏感.Gen-PPL 偏好常见代码.三者共同给出重建侧面,没有一项等于功能等价. Table 1 已知真实草稿,所以指标反映 demasker 从潜表示恢复信息的能力.块长变大、NFE 很低时表现更好,可能因为更大双向区域利用草稿,也可能因为提交策略不同.需要固定每步提交数进一步区分. 执行等价可通过生成测试或程序规范化测量.无输入程序难以自动验证功能,可用 AST 编辑距离、编译率和静态数据流作为补充.论文已有指标范围应如实保留.

**5.22. 随机种子与配对评测.** 无条件生成指标对样本集合敏感.MAUVE 受生成数、参考数和特征模型影响;Gen-PPL 受外部 LM 与长度影响.比较方法时应使用相同潜噪声或配对 seed,降低采样方差. ConThenDisc 与 ConWithinDisc 的连续轨迹不同,无法逐 token 完全配对,仍可共享初始高斯噪声.多个 seed 报均值和置信区间,避免一组样本决定 0.62 对 0.60 的小差异. 13×/14× 来自确定的 NFE 比,质量「不差」依赖指标误差范围.若 MAUVE 0.02 差异落在采样方差内,应称接近;没有区间时避免强调微小高低. **5.23. 训练数据规模的证据边界.** demasker 用 1200 万条 Python 适配,连续模型用 200 万条潜序列.两者数据量不同,功能也不同.前者让 8B 模型熟悉领域与草稿条件,后者学习潜先验.

数据曲线应分别缩放.固定自编码器,增加潜数据可测连续生成瓶颈;固定潜模型,改变 8B 适配数据可测 demasker.只给最终两点无法判断哪阶段数据不足. StarCoder Python 的重复与模板可能让潜分布较简单.跨语言、自然语言或多域代码是否保持同样压缩效率没有证据.条件生成更需 prompt–response 数据. **5.24. 领域迁移会在哪一层失败.** 新领域输入首先经过编码器.若 Qwen 初始化提供通用语义,联合训练后的编码器仍可能因 Python 适配遗忘.接着连续先验只学 Python 潜分布,即使编码器能表示新语言,先验也不会生成其区域. 最后 demasker 在 Python 数据上适配,词法和结构偏向该域.三层都可能限制迁移.用真实 $z$ 重建新域可检查编码–解码;用生成 $z$ 检查先验;分层实验能定位.

冻结部分模块进行域适配也可检验.只重训连续先验若成功,潜表示通用;必须重训编码器与 demasker则草稿接口域特定.现有主表不覆盖. **5.25. 条件后验更新的稳定性.** 中途更新可定义草稿变化量

$$
D_s=\|z^{(s+1)}-z^{(s)}\|_2.
$$

大变化可能是纠错,也可能是模式跳转.同步记录已提交 token 的条件 likelihood,若变化后下降,新草稿与不可修改历史冲突. 可以对更新加信赖域,限制 $D_s$,或插值

$$
z'=(1-\eta)z+\eta\widetilde z.
$$

$\eta$ 小提高稳定性,可能阻止必要的大修正.扫描 $\eta$ 与更新时间,得到质量–稳定曲线. 若更新后草稿要求修改已提交 token,标准 MDM 无法回滚.允许 remask 已提交位置会增加纠错,也改变采样过程.正文一次更新的具体可修改范围需按算法复现. **5.26. 结构错误和表面错误应分开.** 结构错误包括 AST 不闭合、控制流缺分支、函数签名与返回不一致.表面错误包括空格、注释、变量名和格式.连续草稿目标是全局结构,理论上应优先减少前者. 把 CER 分解到 token 类型与 AST 层级.如果草稿只改善标识符一致性,也属于联合收益,范围比「长程程序结构」窄.若控制流和长引用明显改善,全局草稿解释更强. Figure 5 的定性样本不能替代分桶统计.大量生成上做 parser 与静态分析,才能知道提升来自哪里.

**5.27. 连续草稿与块边界.** Figure 6 整段一块,所有 token 同时读取草稿.若改成块扩散,块间已有干净因果前缀,草稿还提供未来全局结构.这可能降低跨块漂移,也可能让草稿与已提交前缀冲突. 固定草稿时,后块可以同时条件于前缀和 $z$.若两者矛盾,demasker如何权衡取决于训练.训练只见真实前缀与真实草稿,推理错误前缀组合是分布外. 中途更新草稿可适配前缀错误,但会把错误合理化.跨块回滚则使 KV 失效.块扩散组合需要新的误差传播实验,不能从整段结果直接推出. **5.28. 一个完整的预算网格.** 设 $K\in\{4,8,16,32}$,$T_c\in\{16,32,64,128}$,$T_d\in\{16,32,64,128}$,更新时间 $u\in\{\varnothing,0.25,0.5,0.75\}$.全网格昂贵,可先用小模型筛选,再在 8B 验证 Pareto 点. 每点报告等效 NFE、实测毫秒、MAUVE、Gen-PPL、parse rate、长度与多样性.自编码 oracle 另表,避免把生成草稿误差混入.

固定等效 NFE 比较不同分配,能回答连续与离散算力替代关系.若增加 $T_c$ 的边际收益在低值最大、增加 $T_d$ 在后期更有效,可以形成自适应预算策略. **5.29. 草稿先验和自编码后验的错配.** 自编码器确定性地给出 $z_0=h(x_0)$,相当于退化后验 $q(z\mid x)=\delta(z-h(x))$.连续先验 $p_\psi(z)$ 要覆盖所有这些点.若聚合后验有多个细薄流形,有限步扩散可能在流形之间生成低密度草稿. 可用两样本分类器区分真实编码潜变量与生成潜变量.分类准确率高说明分布错配;分类器特征还可定位哪些寄存器差异最大.这比只比较均值协方差更敏感. 再把生成潜变量投影到最近真实 $z$ 或运行少量潜优化,看离散质量是否恢复.恢复说明先验采样偏离流形;不恢复则编码–解码本身或指标有问题.

**5.30. 为什么没有显式 KL 也能训练.** VAE 用 KL 把每样本后验推向简单先验,便于采样,但可能损失信息.CRoCoDiL 可以先学高信息确定编码,再用强连续扩散拟合复杂聚合分布,无需把每个编码压向高斯. 好处是重建上限高,代价是潜先验训练更难.连续扩散承担 VAE KL 原本简化的工作.2M 潜样本和 400M 模型是否足够由生成结果判断,没有解析保证. 如果给编码器加入过强高斯正则,潜空间更平滑,Table 1 重建可能下降.扫正则强度可画重建–可生成性前沿.现有寄存器 dropout 是信息瓶颈,作用不同于分布匹配 KL. **5.31. 连续扩散的目标误差怎样影响草稿.**

若连续模型预测噪声,每步误差在反向积分中累积.早期高噪声阶段决定粗模式,后期低噪声阶段修细节.草稿要承载全局结构,早期误差可能特别重要. 按噪声时间替换为 oracle 预测可以做因果消融.只在早期使用 oracle 若大幅改善最终代码,模式选择是瓶颈;只在后期改善 CER,说明细节还原更重要. 减少 $T_c$ 时 solver 离散误差增加.比较同模型不同 solver 和步数,固定函数评估数,可区分训练模型误差与数值积分误差.论文 128 步工作点没有给出全部 solver 前沿. **5.32. 草稿条件注入在哪些层.** demasker 可通过 cross-attention、前缀寄存器或调制层读取 $z$.不同接口决定每个 token 如何共享草稿.若把寄存器作为前缀,所有位置通过 self-attention访问;若单独 cross-attention,可控制层与头.

测每层屏蔽草稿连接后的 loss,能定位信息进入深度.早层作用大可能影响词法与局部表示,晚层作用大可能直接改 logits.注意力权重只是相关信号,屏蔽或 activation patching 更有因果性. 不同寄存器可能被不同位置读取.画 token–register attention 并按 AST 节点聚合,检查某些寄存器是否负责函数级结构.若所有位置只看同一寄存器,大 $K$ 的有效利用有限. **5.33. 连续草稿是否改善反转与 infill.** 共享草稿包含整段编码时,理论上左右两侧信息都能进入缺口,因此自编码 infill 可能受益.无条件生成草稿没有已知后缀,不能凭空提供未来事实.反转与 infill 需要单独条件实验. 给定前后缀时,可编码可见上下文生成后验草稿,再填中间.若编码器只在完整程序训练,部分输入仍有分布变化.专用 mask 编码器更适合.

比较 AR FIM、普通 MDM 与草稿 MDM,固定可见 token 与预算.如果草稿只在长缺口改善,它可能承担全局规划;短缺口都提升可能是额外容量. **5.34. 多样本草稿与 best-of-N.** 同一初始任务可以采多个 $z^{(1)},ldots,z^{(N)}$,每个再少步离散解码.这扩大高层模式搜索,计算成本为多次连续加离散生成.如果 verifier 能选正确程序,best-of-N 可能提升. 与直接对离散轨迹采样 $N$ 次相比,潜样本更侧重全局多样性.固定总 NFE 比较两种分配:多草稿少离散种子,或单草稿多离散种子.任务需要高层方案探索时前者可能更好. 无条件 MAUVE 不需要 verifier,多样本只是生成更多集合.条件代码任务才可用测试执行选择,尚无论文结果. **5.35. 提交策略与草稿置信度.**

demasker 的 token 置信度条件在 $z$.如果草稿错误但模型过度相信它,多个相关位置都会高置信提交,后续难纠.校准应按草稿质量分桶. 可以训练一个草稿置信度 $u(z)$,由连续去噪残差、潜 density 或重建一致性估计.低质量草稿使用更多离散步或触发中途更新;高质量草稿激进并行.这种自适应策略需要验证 $u$ 与最终错误相关. 简单指标是两份独立草稿下 logits 一致性.差异大表示高层不确定,应减少提交.代价是额外连续采样,是否划算取决于减少的 8B NFE. **5.36. 训练时怎样避免 demasker 过度依赖真草稿.** 训练总给精确编码 $z_0$,推理给近似生成 $\widetilde z_0$,形成 teacher forcing 式落差.向训练草稿加噪或混入连续模型样本,可提高鲁棒性.

设扰动级别 $s$,训练条件为 $z_s=\alpha_s z_0+\sigma_s\epsilon$.小噪声提高局部稳定,大噪声可能让模型忽略草稿.随机 $s$ 需要平衡.寄存器 dropout 已提供信息缺失,与连续高斯扰动作用不同. scheduled sampling 可逐步把真实草稿换成生成草稿.连续模型早期质量差时会污染 demasker;分阶段训练更稳.对照应测 oracle 与生成草稿差距是否缩小. **5.37. 结构一致性指标.** Python 可以从 AST 提取成对或全局约束:括号闭合、定义–引用、return 与函数体、循环变量作用域、缩进块.按这些约束统计违例率,比字符指标更贴近联合依赖. 比较基线与草稿模型在相同 NFE 下的违例率.若草稿显著减少长距离定义–引用错误,支持全局条件作用;只减少括号错误可能是局部语法改善.

再按依赖距离分桶.草稿收益随距离增长,说明它补长程;收益只在近距离,可能由额外条件容量或训练适配造成. **5.38. 连续草稿的隐私与记忆边界.** 高容量确定编码器可能记住训练程序细节.潜先验生成接近训练编码时,输出可能出现近重复.无条件分布指标不会直接检测记忆. 可做最近邻与去重检查:生成代码对训练语料的 token/AST 相似度,潜变量对训练 $z$ 最近邻距离.异常近的样本再人工或程序核查. 寄存器数越多、自编码越精确,记忆风险可能增加.这不是 CRoCoDiL 特有问题,但压缩草稿的容量–泛化权衡需要证据. **5.39. 一个严格的消融矩阵.**

模型轴包含无草稿、真实草稿、生成草稿、固定生成草稿、中途更新草稿.真实草稿给上限,生成草稿测先验,两种更新方式测反馈. 容量轴扫描 $K$ 与寄存器宽度.计算轴扫描 $T_c,T_d$ 和更新次数.数据轴扫描潜训练量与 demasker 适配量.每次保持其他轴固定或给等 FLOPs 对照. 结构轴包含独立数据、全局潜类、局部约束、长程复制与真实 Python.指标轴包含条件总相关 proxy、CER、语义、AST、MAUVE、PPL 与时延. 如果收益只出现在真实草稿,连续生成是瓶颈;只在 Python 出现,域模板可能主导;合成全局任务也出现,潜联合机制更可信;墙钟没有 NFE 比,系统成本限制部署结论. **5.40. 证据支持到哪里.**

现有证据支持编码器草稿能帮助 8B demasker 少步重建 Python,连续潜模型能生成足够有用的草稿,ConWithinDisc 在两个无条件长度工作点以 40/72 等效 NFE 达到接近或更好的分布指标. 证据尚未覆盖条件提示、HumanEval、数学、聊天、多语言、墙钟加速、KV cache 与跨硬件吞吐.寄存器数、更新次数和条件编码器也没有系统完成所有组合. 因此最准确的定位是无条件 Python 上的混合连续–离散生成原型.它证明共享连续草稿可以换取更少离散前向,没有证明任意文本生成都能获得同倍率. **5.41. 潜变量重建与联合似然.** 自编码器的按位置交叉熵仍是条件因子化目标.给定真实 $z$,它优化

$$
\sum_i\log p_\theta(x_i\mid x_t,z),
$$

没有直接最大化边缘化后的

$$
\log\int p_\psi(z)
p_\theta(x\mid z)dz.
$$

两阶段训练因此不像标准 latent variable maximum likelihood 那样包含联合 ELBO.编码器草稿学可重建表示,连续模型再拟合其聚合分布.生成结果证明这条近似流程可用,没有给出数据 likelihood 下界. 若要写成 VAE 式目标,需有 $q_\phi(z\mid x)$ 与先验 $p_\psi(z)$,并计算或估计 KL.扩散先验的 KL 处理更复杂.现有确定编码器避免这项计算,也失去明确边缘似然. 因此 Gen-PPL 是外部评测器分数,不等于 CRoCoDiL 自身 likelihood.不能用它证明潜模型概率校准,只能比较生成样本在外部模型下的流畅性. **5.42. 潜草稿的条件独立假设怎样检验.** 给定 $z$ 后,demasker每步仍输出位置乘积.可训练一个判别器,输入两位置的预测残差,判断是否存在条件相关.若判别器在知道 $z,x_t$ 后仍能预测联合违例,草稿不是充分统计量. 小规模任务可直接算

$$
I(X_i;X_j\mid Z,x_t).
$$

随 $K$ 和训练进度下降说明草稿吸收相关.对真实代码,可用匹配约束或 pairwise classifier 估计下界. 还可打乱 batch 内的 $z$.若条件相关性与质量迅速恶化,模型确实使用样本特定草稿;若变化小,草稿可能只提供全局域标签. **5.43. 寄存器之间是否需要自回归.** 连续潜模型同时生成全部寄存器,依赖由连续网络捕捉.如果寄存器按重要性排序,也可以先生成前部粗草稿,再条件生成后部细节.这形成潜空间自回归或块扩散. 分阶段潜生成允许先检查高层方案,不满意时重采前部;后部只补细节.代价是潜关键路径增长,13× NFE 口径需要重算. 比较并行潜扩散与分层潜生成,固定连续 FLOPs.若分层显著改善长程序,寄存器间联合是当前瓶颈;差异小则并行连续模型已足够.

论文的前缀 dropout 提供有序表示线索,没有实现寄存器自回归.这属于后续结构选择. **5.44. 草稿更新与已提交 token 的相容性.** 中途更新后,新 $z'$ 可能降低已提交 token $x_A$ 的概率.定义相容分数

$$
C(z';x_A)=\sum_{i\in A}log p_\theta(x_i\mid x_t,z').
$$

更新时加入该项约束,可以避免草稿否定历史.强约束又会把早期错误固化.需要在保持历史和允许纠错间选择. 若允许重掩已提交 token,可根据相容分数找冲突位置.固定提交 MDM 会由此变成可回退的采样链,计算与分布都变化.回滚一个位置后,所有把该位置当作干净条件的后续预测都要重新计算;若实现缓存了中间状态,对应缓存也随之失效.回滚范围越大,纠错机会越多,重复前向成本也越高.翻转率需要拆成正确到错误、错误到正确和错误到另一错误三类,三者对应的纠错效果不同.一次潜更新保持已提交 token 不变;加入跨阶段回滚后,采样核、状态空间与成本都要重新定义.

记录更新前后 $C$ 与未来 token NLL,能判断修正是否以牺牲历史为代价.最终质量提高但 $C$ 降低,说明模型可能重解释历史而非一致后验. **5.45. 长度扩展为什么仍需验证.** 长度 512 用 $K=8$,1024 用 $K=16$,近似保持每 64 token 一个寄存器.这提示容量随长度线性增加,不是固定潜瓶颈外推.更长序列还需增加 $K$ 或提高每寄存器负担. 连续 attention 随 $K^2$ 增长,离散 demasker 随 token 长度增长.当长度扩大到 4096,连续侧相对成本和潜建模难度都会变化.512/1024 的 NFE 比不能直接外推. 依赖长度也增长.程序跨函数引用、文件级结构可能超过草稿训练范围.按长度画 oracle 重建与生成重建差距,可区分容量和先验外推. **5.46. 训练目标的权重与掩码分布.**

掩码时间 $t$ 的采样决定草稿在什么条件下被需要.低掩码率时 $x_t$ 已含大量真 token,demasker 可忽略 $z$;高掩码率时草稿最关键.均匀采样 $t$ 不代表有效梯度均匀,权重 $1/\alpha_t$ 会再调整. 可以测草稿梯度范数

$$
g(t)=\left\|
\frac{\partial\mathcal L_t}{\partial z}
\right\|_2.
$$

若梯度集中在高噪声,编码器主要服务全局重建;若低噪声也大,草稿参与细节.按 $t$ 重新加权可改变分工. 推理少步会访问特定掩码轨迹,训练随机掩码分布与之不同.把推理状态回放进训练或做 trajectory fine-tuning,可能减少落差,需额外数据与实验. **5.47. 推断随机性来自两层.** 连续初始噪声 $\epsilon_z$ 决定高层草稿,离散采样噪声 $\epsilon_x$ 决定给定草稿的实现.总方差可用 ANOVA 式分解:

$$
\operatorname{Var}(S)
=\operatorname{Var}_{z}
[\mathbb E(S\mid z)]
+\mathbb E_z[\operatorname{Var}(S\mid z)],
$$

$S$ 是质量或结构统计.第一项是草稿间差异,第二项是草稿内离散差异. 固定多个 $z$,每个采多条 $x$,即可估计.若第一项主导,提高连续先验或多草稿搜索更重要;第二项主导,增加离散步或改提交策略更有效. ConWithinDisc 会让两层随机性耦合,因为 $x_t$ 反馈到 $z$.仍可共享初始噪声做配对,但简单方差分解不再完全独立. **5.48. 哪些结果会推翻当前解释.** 若打乱草稿样本后少步生成质量不变,demasker没有使用样本级全局条件;13×收益应寻找训练或调度解释.若只保留长度标量就能复现,草稿主要是长度控制. 若 oracle 草稿在大提交数下仍大量违反全局约束,给定 $z$ 后因子化缺口很大,连续草稿不足以解释联合.需要局部联合层或更多离散步.

若生成草稿与真实草稿统计接近,条件 NLL却差,潜欧氏匹配没有捕捉解码敏感方向.若统计差很大而生成质量好,简单分布距离也不是充分指标. 若等 FLOPs 下基础 MDM 的强调度器达到相同 Pareto 前沿,草稿额外训练不带来算法优势.若墙钟加速远小于 NFE,部署结论必须收窄到函数评估数. 若条件代码任务中草稿经常违背 prompt,无条件结果不能迁移.若跨语言与自然语言都需重训全部模块,表示接口高度领域化. 这些对照使机制声明可被实验否定:共享连续潜变量应该携带样本级结构,降低给定草稿后的依赖,并在等计算下帮助多位置提交.缺少其中任何一项,解释都要相应收窄. **5.49. 从执行轨迹看草稿是否真的在规划.**

程序草稿若承载规划,相同 $z$ 的多次离散解码应共享高层 AST,即使变量名和格式不同.可以把生成结果解析成函数、循环、分支和调用图,计算同草稿组内与跨草稿组间距离. 若同草稿组内 AST 距离显著更小,潜变量控制结构;若只有 token 风格相似,草稿更像表面模板.固定离散 seed、改变 $z$ 的对照进一步隔离高层影响. 还可在生成中途 probe 未来结构.用当前 $z$ 预测最终 AST 节点数、最大嵌套深度和是否递归.早期即可预测且中途更新后更准确,支持「草稿先规划」. 计划不等于正确.无条件生成只要求像训练分布,条件任务还需与 prompt 对齐.所以这些指标验证结构控制,不补上论文未做的功能评测. **5.50. 潜空间碰撞与一对多解码.**

有限草稿可能把多个程序映到相近区域.如果这些程序语义相近,碰撞是有益压缩;若功能不同,demasker 给定同一 $z$ 只能靠离散随机性选择,条件分布多峰. 找潜最近邻对,比较 token、AST 与执行特征.距离近且结构差异大的对是碰撞.随着 $K$ 减小,碰撞率应上升;重建 CER 与多样性变化可以对应. 一对多并非错误.无条件生成需要同一高层草稿允许多种实现.问题在于 demasker 的因子化输出能否协调多峰细节.若不同模式的 token 被并行拼接,需要更多离散步或局部联合模型. **5.51. 草稿条件的校准.** 给定生成 $z$,demasker 置信度可能高于给定真实 $z$ 的实际准确率,因为训练只见编码草稿.按草稿来源分别画 token reliability diagram,可以量化落差.

潜 density 低的草稿可能校准更差.把 $z$ 按连续模型 score 或去噪残差分桶,观察错误率.若相关,推理可对低密度草稿增加 $T_d$ 或重采. 温度校准只改边际尖锐度,无法修正草稿语义错误.校准后约束仍错,需要更新或替换 $z$.将 token ECE 与 AST 违例同时报告,避免把边际校准当联合正确. **5.52. 动态寄存器数如何定义停止.** 前缀 dropout 允许从少量寄存器开始.可以逐个生成或启用寄存器,直到新增寄存器对 demasker预测影响很小.定义

$$
R_k=D_{\mathrm{KL}}
(p_\theta(x\mid z_{1:k})
\|p_\theta(x\mid z_{1:k+1})).
$$

$R_k$ 小表示第 $k+1$ 个寄存器贡献有限.对困难样本可能需要更大 $K$,简单样本提前停止. 计算 $R_k$ 需要额外 demasker 前向,成本很高.可训练轻量预测器根据前部寄存器估计后续收益.预测错误会给困难样本不足容量. 等平均 $K$ 下与固定策略比较,才能判断动态分配是否有效.如果收益只来自平均使用更多寄存器,没有自适应价值. **5.53. 自回归基线应该怎样加入.** 无条件 Python 也可由标准 AR 生成.比较 CRoCoDiL 与基础 LLaDA 说明草稿对 MDM 的加速,没有说明相对 AR 的墙钟、质量或似然位置. 公平 AR 基线应使用相近领域适配数据、参数量和长度,报告同样的 MAUVE、Gen-PPL、parse rate 与实测时延.AR 天然逐 token NFE,但 KV Cache 使单步远小于全序列 8B MDM 前向,不能按 512 次等价.

混合模型若最终墙钟仍慢于 AR,其价值可能在可控性、并行 batch 或 infill;若更快且质量相近,才支持部署加速.论文的 NFE 结果尚未完成这项系统比较. **5.54. 一份可复现的最小报告.** 模型栏列 LLaDA checkpoint、Python 适配数据 1200 万条、编码器初始化、连续模型 400M、潜训练数据 200 万条.潜栏列 $K$、维度、dropout 分布和归一化. 采样栏列长度、块长、$T_c$、$T_d$、草稿更新次数和时机、离散提交日程、温度与 seed.成本栏分开写连续前向、编码器、8B demasker 和等效 NFE. 质量栏区分自编码与生成.自编码列 CER、CodeBERTScore;无条件生成列 MAUVE、Gen-PPL、长度与 parse rate;条件任务若新增,另列执行准确率.不同任务指标不交叉换算. 证据栏标出 Figure 6 两档明确数字、Table 1 重建数字和未报告项.13×/14× 后始终跟「等效 NFE」与长度.墙钟、tok/s、HumanEval 和条件生成没有数据时不补数字.

轨迹栏保存初始与更新草稿、每步 mask、提交 token、置信度和随机状态.失败样本才能回放到连续先验、草稿更新或离散量化中的具体一层. **5.55. 最终机制链.** 干净程序先被编码为少量连续寄存器.寄存器共享给所有 token 位置,使位置在边缘化潜变量后相关.连续扩散学习寄存器分布,把无条件高斯噪声变成程序级草稿. 离散 demasker 条件在草稿与当前 $x_t$ 上预测 token.草稿若已解释大部分全局依赖,每步可以同时提交更多位置,离散 NFE 随之下降.它仍需要多步处理潜变量遗漏的局部依赖和量化错误. ConThenDisc 保持高层意图稳定,也保留初始草稿错误.ConWithinDisc 用部分离散文本近似潜后验,获得纠错机会,同时引入 mask 编码分布变化与反馈风险.

现有两档无条件 Python 结果与这条链一致:较少离散 NFE 下分布指标保持.它们没有逐环节证明所有因果关系,因此受控联合任务、oracle 草稿、更新时机和墙钟对照仍是必要验证. **5.56. 潜变量的因果干预.** 观察 $z$ 与结构相关不足以证明控制.可先训练属性 probe 找到预测循环数量、函数数或长度的方向 $v$,再做

$$
z'=z+\lambda v.
$$

若对应属性随 $\lambda$ 单调变化、其他属性相对稳定,草稿具有可干预方向.若所有属性一起变化,probe 只读到相关簇. 更严格的方法交换两个样本的单个寄存器.若某寄存器负责控制流,交换后应转移对应结构.需要对大量样本统计,避免挑定性案例. 干预生成仍受 demasker支持约束.潜方向把草稿推到训练流形外时,输出可能崩坏.同时报告潜 density 与 parse rate,防止把失真解释成可控性. 论文主结果没有做这些干预,因此「寄存器承载整段结构」主要由架构和重建趋势支持,细粒度语义分工仍待验证. **5.57. 连续草稿与检索式记忆.** 编码潜变量可能靠近训练样本簇,连续先验生成后 demasker近似检索并改写常见程序.这也能提高流畅度和一致性,机制与抽象规划不同.

对生成 $z$ 找训练潜最近邻,再比较生成代码与最近邻 token/AST.高度一致说明检索成分强;距离较远仍能产生有效新结构,组合泛化更可信. 把最近邻草稿直接作为条件基线,与连续生成草稿比较.若检索基线同样好,400M 潜扩散的主要价值可能是平滑检索分布;若生成草稿更好,连续插值或新组合有贡献. 无条件生成允许一定记忆,条件任务更关心是否按提示组合.这也是未来条件实验不能省的原因. **5.58. 何时应停止草稿修正.** 多次更新可以根据连续后验残差、草稿变化 $D_s$ 与离散约束决定停止.仅看 $D_s$ 小可能落入错误固定点;仅看 token 置信度又可能被错误草稿共同抬高.

组合停止规则可要求草稿变化小、已提交相容分数稳定、结构违例不再下降.验证集上校准阈值,报告平均更新数与尾部分布. 若更新次数动态化,等效 NFE变成样本相关.平均 NFE 相同的两方法尾延迟可能不同.墙钟与 P95 更新数要一起给. 正文一次中途更新避免了复杂停止问题.更频繁更新属于潜在改进,不能把理论可能性算进 40/72 NFE 结果. **5.59. 最终验收中的数字边界.** 长度 512 的明确对照是基础 NFE 512、MAUVE 0.62、Gen-PPL 19.4;ConWithinDisc NFE 40、MAUVE 0.60、Gen-PPL 14.3.NFE 比约 12.8,写成约 13×. 长度 1024 的明确对照是基础 NFE 1024、MAUVE 0.76、Gen-PPL 23.5;ConWithinDisc NFE 72、MAUVE 0.80、Gen-PPL 12.5.NFE 比约 14.2,写成约 14×. 两档的 $K$ 分别为 8 和 16,序列长度与潜容量同时变化.连续 128 步约折算 6 次 8B NFE,条件连续 32 步少于 2 次,采用论文自己的折算.这些数字不替代实测时延.

Table 1 长度 256、真实草稿 $K=128$,属于自编码重建.它和 Figure 6 的无条件生成在潜来源、$K$、长度与指标上均不同.任何跨表比较都应保留这些条件. 实验范围止于经过 Python 适配的 LLaDA-8B 无条件生成.条件提示、HumanEval、GSM8K、聊天和通用 LLaDA 能力没有对应主表.把边界写完整,13×/14× 才是可复现结论. **5.60. 草稿质量的在线判别.** 部署时没有真实 $x_0$,无法直接知道生成 $z$ 是否落在可靠区域.可用连续模型 score 范数、不同 solver 的草稿差异、潜最近邻距离和 demasker首轮熵作为代理. 代理必须在验证集上与最终质量校准.潜最近邻近可能表示流形内,也可能表示训练记忆;首轮熵低可能是好草稿,也可能是错误过度自信.单一指标容易失效.

可以训练轻量判别器预测「当前草稿用 $T_d=32$ 是否达到目标质量」.高风险样本增加离散步、触发中途更新或重采草稿.固定平均 NFE 下与随机加算力比较,才能证明自适应有效. 判别器输入若包含 prompt 或已生成 token,条件任务下还要防止分布变化.无条件 Python 上校准的阈值不能直接用于聊天. **5.61. 失败模式的分层处理.** 连续先验失败时,多采一个 $z$ 或增加 $T_c$ 更直接;编码草稿容量不足时,增加 $K$ 或改编码目标;demasker 忽略草稿时,调整条件注入与高噪声训练;离散联合残差大时,增加 $T_d$ 或加入局部联合层. 中途更新失败又分两类:mask 编码器不懂部分序列,以及反馈把早期错误写入草稿.前者可训练 $h_\mu$,后者需信赖域、延迟更新或允许回滚.两类处理不能互换.

指标失败也要单列.Gen-PPL 改善而 parse rate 不升,优化方向偏流畅;CER 高而 CodeBERTScore 好,可能只是命名与格式;MAUVE 好而最近邻过近,可能有记忆.一项平均数无法决定模型是否成功. 分层诊断避免把所有问题交给更大连续模型.草稿、后验更新、离散解码与评测各有独立可证伪信号,应先定位再增加计算. **5.62. 连续与离散两种不确定性如何对齐.** 连续模型对 $z$ 的不确定性表示高层方案多样性,demasker logits 表示给定方案后的 token 不确定性.如果连续后验很宽而离散 logits 很尖,单草稿会过早选定方案;如果潜后验很窄而 token 熵高,瓶颈在细节解码. 可估计多个草稿下的平均 token 分布

$$
\bar p_i(v)=\frac{1}{S}\sum_{s=1}^{S}
p_\theta(x_i=v\mid z^{(s)},x_t).
$$

总预测熵与草稿内平均熵之差近似表示潜层 epistemic variation.差值大时多草稿搜索更有价值,差值小时增加离散步更合理. 中途条件扩散应随可见 token 增多缩小潜不确定性.若后验样本仍分散,部分程序支持多种高层解释;强行取单草稿会丢模式.若错误地迅速坍缩,mask 编码器可能过度自信. 这套分解给动态预算一个概率依据,但需要多次潜采样,自身增加成本.小型 proxy 能否近似是后续实验问题. **5.63. 结论应该落在哪一层.** 概率层面的结论是共享连续潜变量能让条件独立输出在边缘化后相关.这一点由混合分布公式成立,不依赖具体代码任务.有限寄存器能吸收多少真实依赖,属于模型容量与训练问题.

算法层面的结论是先生成草稿、再少步离散解码,并允许一次潜后验更新.草稿固定与更新对应不同耦合链,更新增加纠错也增加反馈风险. 实验层面的结论限于 Python 无条件生成.真实草稿自编码显示表示可解码,Figure 6 两档显示生成草稿能支持更少等效 NFE.指标覆盖分布相似与外部 PPL,没有覆盖功能正确率. 系统层面的结论目前只有函数评估折算.连续 400M 与离散 8B 的实际 kernel、网络切换、batch 和内存决定墙钟.13×/14× 后必须保留 NFE 口径. 边界层面的结论包括条件生成未验证、潜容量随长度变化、给定草稿后仍有因子化残差、mask 编码器存在分布变化、潜更新可能固化早期错误.这些条件决定方法能否迁移.

把五层分开后,CRoCoDiL 的贡献很清楚:它提供了一种在大规模 MDM 前面建立连续全局随机变量的可行结构,并在特定无条件代码协议中展示少步优势.更广的任务与部署结论仍需对应实验.
