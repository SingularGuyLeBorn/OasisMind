# 吸收态模型家族

「吸收态模型家族」关注的是一组彼此牵连的选择：状态如何表示，破坏过程怎样丢失信息，模型又凭什么把信息找回来。下面的文章分别落到这些选择的不同分支，比较时以共同概率对象和计算条件为坐标。

## 共同起点

LLaDA 要回答的问题很硬:LLM 的规模化,上下文学习,指令跟随,是不是必须绑在自回归连乘上.作者的答案是:这些能力来自「用似然(或其下界)拟合语言分布」,不来自「必须从左到右」.8B 从头训是把这句话做到和 LLaMA3 8B 同一张表上;2.0 是承认从头训 100B 太贵,改成继承 AR 权重.

机制公式见掩码扩散章节;这里比较架构选择,原表数字,采样器影响与 2.0 的转换课程.后训练(VRPO,diffu-GRPO)不在 8B 原论文主表里,文末只给指针和对照口径.

预训练 2.3T token,0.13 百万 H800 GPU 小时,序列长 4096.损失即掩码扩散篇式 (1):抽 $t\sim U[0,1]$,每个位置独立以概率 $t$ 变成 `[MASK]`,交叉熵只落在被掩位置上,再乘 $1/t$.SFT 用 450 万对,只掩回答,提示保持干净.没有 RL.

和 LLaMA3 8B 的对照写在附录 Table 5:都是 32 层,隐维 4096,32 个注意力头.LLaDA 用 32 个 KV 头(vanilla MHA),LLaMA3 用 8 个(GQA).作者写明原因:当时这套全双向公式和 KV Cache 不兼容,GQA 省 KV 的前提不成立.多出来的注意力参数靠减小 FFN(12288 对 14336)对齐到 8.02B / 8.03B.词表 126464 对 128000,分词器按他们的数据改编.

换掉的是 mask 和训练目标.RoPE,SwiGLU,RMSNorm 仍在.BERT 的 15% 固定掩码,NSP,10% 随机替换都不在.$t$ 要从 0 积到 1,生成要从全掩码走回来,这两件事才把编码器接上生成模型.

1% 的预训练样本会把长度在 $[1,4096]$ 里另抽一次,避免模型只会处理垫满 4096 的块.生成长度在纯扩散里仍是超参:一开始垫多少个 `[MASK]`.Instruct 数据若用 `[EOS]` 垫到固定长,纯扩散会学会到处写结束符,采样时要把 `[EOS]` 置信度置零.这不是 $Q_t$ 的问题,是定长垫片和结束符抢置信度.

训练一步长什么样.抽一条 4096 的文档,抽一个 $t$,抛硬币决定哪些位置变成 `[MASK]`.网络做一次全双向前向,词表 softmax 只在被掩位置上对原 token 算交叉熵,乘 $1/t$ 再反传.未掩位置的答案已经写在输入里,再预测一次没有信息,还会让模型学抄输入.这和 BERT 的差别不在「用了双向 Transformer」,而在 $t$ 覆盖 $[0,1]$ 全体:有的 batch 几乎没掩码,有的 batch 几乎全掩.似然下界是对这条日程求期望,所以可以从全掩码反向采样.固定 15% 的 MLM 没有这条反向过程.

SFT 把同一套损失收窄到回答段.提示位置永远可见,当作条件;回答位置按 $t$ 掩.模型学的是「在这段已经写好的指令旁边,把回答从噪声里擦出来」,不是「从左到右续写指令」.这解释了为什么同一组 Instruct 权重,用自回归采样(每步只揭最左边一个掩码)会和 `[EOS]` 垫片打架,而纯扩散,块扩散还能出分数.

同数据 ARM baseline 是作者用来挡「2.3T 对 15T」的那条曲线.语料配比,分词器,优化器尽量对齐,只换因式分解.下游在他们走到的 FLOPs 区间没有塌.这张图回答的是「扩散目标能不能 scale」,不是「LLaDA 的数据比 LLaMA3 更省」.跨公司主表上的 GSM8K 21 个点,混了数据,目标和双向,不能单独记在扩散名下.

MMLU 与 HumanEval 和 LLaMA3 持平量级;GSM8K / MATH 高出一截;BBH,Hellaswag 落后.作者把优劣同时归因于闭源数据不可比,并另外训了同数据的 ARM baseline,在 $10^{20}$–$10^{23}$ FLOPs 上显示下游曲线可以跟上,MMLU 与 GSM8K 甚至更陡.讨论「扩散样例效率」用那条同数据曲线,不要用 2.3T 除以 15T.

Base 的 MMLU 类任务走条件似然蒙特卡洛,HumanEval 走生成.两列不是同一种解码.HumanEval-FIM 在 Table 1 上是 73.8 对 LLaMA3 的 73.3:填空并非扩散独有的魔法,FIM 训过的 AR 也能做;扩散这边不必另开一条 FIM 目标.

附录 Table 10 把生成长度扫过 256 / 512 / 1024.Base 上 GSM8K 在 70.0–70.8 之间晃,MATH 30.3–31.4,HumanEval 32.9–35.4.定长超参不是分数的主因;采样器类别才是.本表 MATH 31.4,HumanEval 35.4 与 Table 10 在 length=1024 那一行对齐.

整体略落后有 RL 的 LLaMA3 Instruct,缺口在代码和 GSM8K 更明显.ARC-C 反而更高.作者把若干指标相对 Base 下降(如 MMLU)归因于 SFT 数据质量,并明确把 RL 对齐留到后续.

Table 2 的 69.4 / 31.9 / 49.4 是纯扩散.GSM8K 若改用块长 8 的块扩散 LLaDA,可到 78.6.报「LLaDA Instruct 的 GSM8K」而不写采样器,数字没有意义.自回归采样在 Instruct 上崩掉,和 `[EOS]` padding 有关,见采样篇.

## 分岔来自哪里

骨架仍是 decoder-only Transformer,注意力全双向.Table 2:16 层,隐维 2048,16 头,64 个专家,每次激活 8 个,专家隐维 1024,RoPE base 50,000.非嵌入参数 7B,激活 1.4B.主表表头把激活写成 1B,和 7B-A1B 的产品名对齐;规格以 Table 2 的 1.4B 为准.RMSNorm,SwiGLU,RoPE 都在,注意力里加了 QK-LayerNorm.论文 Figure 2 为了好看画过 Top-2 示意,规格是 Top-8,不要按示意图记路由宽度.

路由公式就是 AR MoE 那一套.隐状态 $h_t$ 进线性路由器得到 64 维 logits,Softmax 之后取 Top-$k$,被选中的专家输出按门控权重相加:

一层里数据怎么走,可以写成和 AR MoE 几乎相同的句子.Token 先做双向注意力,得到 $h_t$,再进路由器.被掩位置和干净位置共用同一套专家,没有「掩码专家」这种额外模块.AR 里 $h_t$ 的邻居集合随解码单调变长,路由的输入分布相对稳.掩码扩散里同一步内,有的格子是明文,有的是 $\mathbf{M}$,下一步明文集合又变,路由器看见的统计会跳.辅助损失要压的就是这种跳会不会把流量砸到两三个专家上.论文只证明前 1T 能稳住,没有证明专家学到了可命名的学科分工.

16 层对 8B 的 32 层,是故意把深度换成专家宽度.注意力头数也从 32 收到 16.读过 llm-guide 里 MoE 章节的人会问:这是不是 Switch Transformer 那种「层数少,专家多」.精神上接近,规格对不上 Switch 的万专家.这里 64 选 8,激活比例 12.5%,比 Mixtral 的 8 选 2 更「每步多用几个专家,专家库不那么夸张」.没有共享专家(shared expert)写进 Table 2.抄 DeepSeek 的共享专家设定过来,是另一篇论文的事.

前向:抽 $t\sim U[0,1]$,每个位置独立以概率 $t$ 变成掩码 $\mathbf{M}$.网络输出 $p_\theta(\cdot\mid y_t)$,交叉熵只落在被掩位置,再乘 $1/t$:

预训练本身也怕「只会处理满 4k 块」.他们把 8B 那招搬过来:1% 的步把长度在 $[8,4096]$ 里另抽并截断,其余 99% 仍用默认 4k.这不是新理论,是同一类训测缺口.生成评测统一用半自回归:长度 1024,块长 64,再叠低置信 remask.报「LLaDA-MoE 的 GSM8K」而不写这块采样器,数字没有锚.

训练一步可以按 8B 的剧本走,只在 FFN 处分叉.抽一条文档,抽一个 $t$,按 $t$ 抛硬币盖格子.全双向前向算出每个位置的隐状态.每个位置独立做一次式 (1) 的 Top-8.词表 softmax 仍只在掩码位上对原 token 算交叉熵,乘 $1/t$,再加上那两项很小的辅助损失.未掩位置不要再预测一遍:答案已经写在输入里,再预测是教模型抄输入.MoE 不会改变这条纪律.有人以为稀疏路由等于「让专家去猜哪些位置该揭开」.揭开顺序是采样器的事,路由器不输出「这一格还脏吗」.下一位置由采样器或规划器决定,不由 MoE 路由器决定.

## 家族内部真正连续的部分

LLaDA 家族的共同底座是吸收态掩码、双向条件建模和对随机掩码率加权的重构目标。版本变化主要发生在规模、块化方式、训练数据、后训练协议与推理调度上。读模型表时应先确认它是从头预训练还是由自回归权重改编，再看报告的是全序列扩散、块扩散还是带因果边界的混合形式；这些差异会直接改变可用上下文、缓存方式和并行度。

MoE 并没有改变扩散的概率对象。路由器仍在每个 token 的隐藏状态上选择专家，噪声时间与可见集合却会改变隐藏状态分布：同一个语义位置在高掩码率和低掩码率下可能被送往不同专家。于是专家负载、路由稳定性与去噪难度发生耦合。只比较总参数量会漏掉激活参数、每步前向成本以及扩散多次调用主模型产生的总成本。

模型能力也要和采样协议绑定。某个基础模型在高步数、低并行提交下得到的数学或代码成绩，不能直接与同一家族在少步高速配置下的吞吐拼成一项结论。家族页负责说明共同训练范式；具体文章分别保留基础模型与 MoE 的配置、实验口径和失败条件。
