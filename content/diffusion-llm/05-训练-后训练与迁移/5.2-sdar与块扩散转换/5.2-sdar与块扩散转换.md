# SDAR:先把 AR 训满,再改成块扩散

[从自回归权重改编](../5.1-从自回归权重改编/5.1-从自回归权重改编.md)比较了四条转换路线:DiffuLLaMA 验证 7B 改编可行,Dream 细化移位与噪声日程,LLaDA 2.0 用块课程扩展到 100B,Fast-dLLM v2 把转换预算降到约 1B token.Cheng 等人的 SDAR(arXiv:2510.06303,上海 AI Lab)进一步控制架构、1T 语料和优化器,分别从零训练 AR 与掩码扩散;AR 在该协议下具有更高的计算效率.因此 SDAR 先用精确 NLL 完成大规模预训练,再把推理转换为块内并行.从零训练块扩散还需同时处理干净前缀与含噪块,训练上下文接近翻倍.

SDAR转换的关键条件是转换可以不做移位,不做掩码退火.Dream 和 DiffuLLaMA 把移位当成保住几何的开关.SDAR 改注意力图案和损失,logits 头仍按原位置.这是另一条连续路径,不是把那两篇作废.仓库在 [JetAstra/SDAR](https://github.com/JetAstra/SDAR),检查点在 Hugging Face 的 JetLM.

## 1. 同一 1T,AR 的 MATH 是 29.9

SDAR 沿用吸收态掩码扩散的 $1/t$ 损失.前向过程把每个位置独立腐蚀成 `[MASK]`,线性日程为 $\alpha_t=1-t$:

$$
q(x_t^\ell\mid x_0^\ell)=\mathrm{Cat}\bigl(x_t^\ell;\ \alpha_t\mathbf{x}_0^\ell+(1-\alpha_t)\mathbf{m}\bigr).
\tag{1}
$$

反向最小化 NELBO.吸收态下它收成只在掩码格上的加权交叉熵,$1/t$ 来自这条线性日程,不是另设的超参:

$$
\mathcal{L}(\theta)=\mathbb{E}\Bigl[-\frac1t\sum_{\ell=1}^{L}\mathbf{1}[x_t^\ell=\texttt{[MASK]}]\log p_\theta(x_0^\ell\mid x_t)\Bigr].
\tag{2}
$$

AR 优化精确连乘 $\sum_\ell\log p_\theta(x^\ell\mid x^{<\ell})$,每个位置都参与梯度.掩码扩散只在被腐蚀的位置计算损失,其余 token 作为上下文.因此在相同 FLOPs 下,两者的有效监督密度不同.从任意顺序视角看,$1/t$ 损失对排列求期望,这里体现的是该等价关系在训练效率上的差异.

块扩散把序列切成不重叠的块.块间因式分解是精确连乘,块内仍是条件 NELBO:

$$
\log p_\theta(x)=\sum_{b=1}^{B}\log p_\theta(x^b\mid x^{<b}),
\tag{3}
$$

$$
\mathcal{L}_{\mathrm{blockwise}}(\theta)=\mathbb{E}\Bigl[-\frac1t\sum_{\ell=1}^{L'}\mathbf{1}[x_t^{b,\ell}=\texttt{[MASK]}]\log p_\theta(x_0^{b,\ell}\mid x_t^b,x^{<b})\Bigr].
\tag{4}
$$

从零训 (4),前向要把干净前缀和当前脏块拼进同一张图.作者把这件事写成禁止从零堆块扩散的理由:算力接近再付一份上下文.BD3-LM 那条从零训的河还在,SDAR 只是拒绝付这笔训练成本.

更硬的证据在 2B 对照.两个 2B 模型,同一 1T(网页,STEM,代码),上下文 4096,packed.AR 用变长因果;MDLM 用全双向.再各用 100B 退火,得到四份 Base:继续当 AR,AR 转块扩散(块长 16,即 SDAR),继续当 MDLM,MDLM 转块扩散.同一 4B token SFT 之后评 Chat.解码:AR 贪心;两份块扩散用最低置信静态,块长 16,16 步;纯 MDLM 跟 LLaDA 协议.评测是 BBH 3-shot,MMLU 5-shot,MATH 4-shot CoT,GSM8K 4-shot CoT,HumanEval 0-shot,MBPP 3-shot,GPQA-diamond 0-shot.

MATH 29.9 对 12.6,HumanEval 42.1 对 21.3:同等预算下掩码扩散的界明显松.转成块扩散之后,AR 起点仍压过 MDLM 起点.SDAR 相对原 AR,MATH 掉 3.1,HumanEval 掉 2.1,MMLU 反加 2.2,GPQA 加 1.9.转换不是免费,掉的是个位数,不是腰斩.MDLM 转块扩散能把 MATH 从 12.6 抬到 23.3,仍低于 AR 的 29.9.GSM8K 上 MDLM-BD 的 64.7 反而高于 AR 的 61.8,不能写成「AR 起点处处赢」;主缺口在竞赛数学和代码.骨干选 AR,是这张表的多数列,不是口号.

## 2. 转换:不移位,不退火

AR 检查点 $\theta_{\mathrm{AR}}$ 已经付过万亿级 NLL.转换阶段把序列切成块 $b_k$,前缀块保持干净,因果可见;当前块按 MDLM 随机掩,双向看见块内和全部前缀.实现上把干净序列和扰动序列拼成一次前向,改注意力掩码.这和 BD3-LM 的拼图同构:一次前向里既有「当 AR 读前缀」的半边,也有「当扩散填当前块」的半边.预训练阶段整句可扰动;SFT 只扰动回答,提示保持干净.目标从 NLL 换成块条件 ELBO.作者写明:不做 logits 移位,不做注意力掩码退火.

[从自回归权重改编](../5.1-从自回归权重改编/5.1-从自回归权重改编.md)说明移位可以保留保住 $h_i\to x_{i+1}$ 的开关.SDAR 赌的是:块间仍是因果,预测头不必搬家;块内双向是局部的,不必从因果慢慢放宽到全句.连续路径换成「先当 AR,再突然打开块内双向」,缓冲靠的是 30B 到 50B token,不是退火日程.2.0 的 WSD 把块大小当课程:warmup 加大块,stable 全序列,decay 收到部署块.SDAR 没有这门课,转换时块长一次定下来,后面靠 SFT 再拉.v2 用约 1B token 加互补掩码,卖点是接上现有 AR 和 KV,不是把 NLL 先训满再转.三条河都接到块扩散,训练成本和双向半径不同.Dream 那种全双向填空,SDAR 买不到.块外未来仍然不可见.诗歌反向,任意跨块 infill,结构上弱于 Dream.产品主打续写,代码,长 CoT,块扩散通常够.

受控 2B 实验使用 100B 退火;接到开源 Qwen3 时,CPT 是从 1T 语料里随机抽 50B,上下文仍 4096.作者强调:不必拿到基座的原始预训练数据,任意 decoder-only 都能转.这是配方,不是定理.他们扫过 20B,30B,40B,能转,下游略差,后续把块长做大也更死.Dream 约 580B,DiffuLLaMA 原文写不到 200B,SDAR 文写成 65B.两套口径必须分别引用,不能据此计算「SDAR 比 DiffuLLaMA 便宜三倍」.SDAR 的 50B 还是相对低质量的开源子集,不是 Qwen3 末期那 6T 合成料.预算小,不表示数据可以更脏.作者自己写:数据更好,分布更齐,转换预算还能再收.那是展望,主表仍是 50B.

推理分层.已完成块当因果前缀,KV 是真缓存.当前块从 $B$ 个 `[MASK]` 起步,逐步去噪,完成前不写入 KV.第 $t$ 步的 logits 条件是当前脏块加前缀:

$$
\mathrm{logits}(b_k^{t-1})\sim P(\cdot\mid b_k^t,\,b_{<k},\,\mathrm{prompt};\theta).
\tag{5}
$$

从得到的分布里挑一个位置子集落盘,其余继续当 `[MASK]`.静态策略设块长 $B$ 和总步数 $T$,每步揭 $\lceil B/T\rceil$ 个最高置信的掩码格.动态策略提交置信度超过 $\tau$ 的位置;若没有位置过阈值,至少揭 1 个或 $\lceil B/T\rceil$ 个,保证循环继续.一块填满后才写 KV 并进入下一块.块间因果允许模型遇到结束符才停止,无需预先指定整句长度;结束符出现后,后续块可以整块填 EOS.这与 dInfer 的早停属于同一类设计,但 SDAR 主文没有报告早停带来的 TPS 增益,serving 篇的 15% 到 40% 来自另一套引擎.低熵同时影响生成质量和每次前向可提交的 token 数,后面的 TPF 曲线会显示这层关系.

![SDAR 从充分训练的自回归模型切换到块扩散目标的阶段流程](../images/fig-sdar-ar-to-block.png)

> 图 1:左列先付 AR 的 NLL,再短转换;右列块间真 KV,块内从全掩码去噪.底栏 ChemBench 和 6600 TGS 的分母分开写.

**图 1 解析**

- **L1 到 L2**:每个 token 都更新,是 AR 更省算力的来源.转换改损失和掩码,不改移位.
- **L3**:块间精确连乘,块内吸收态.$Q_t$ 没有新定义.
- **L4**:同等 1T 的 2B 对照,MATH 差一倍还多.
- **R1 到 R2**:已完成块的 KV 是真缓存.当前块未完成前不写入.接错会读过期 Key.
- **R3 到 R4**:静态每步揭 $\lceil B/T\rceil$ 个最尖的;动态用阈值 $\tau$.大模型更能忍大块.
- **F0**:6600 是 H200 上 LMDeploy 扫大 batch 的峰值,不是 Mercury 那种单卡 batch 1.

## 3. 接到 Qwen3:1.7B 到 30B-A3B

开放权重转换实验采用 Qwen3-1.7B,4B,8B,30B-A3B.同一 50B CPT 加同一套 4B SFT,得到 SDAR-Chat 和 AR-Chat.评测时 SDAR 用贪心静态解码,块长和去噪步都取 4.这和 2B 表的块长 16,16 步不是同一工作点.外部基线 Qwen3-Base 来自技术报告;LLaDA 和 Dream 来自各自论文并列于 Table 3,协议不同,只能当量级.减「SDAR-8B 比 LLaDA 高 12 个 MMLU」当同场比赛,表不支持.

Table 2 里 30B 档,SDAR 在 18 项里 11 项持平或超过同流程 AR-Chat.MMLU 82.8 对 82.2.HumanEval 87.2 对 84.8(+2.4).HumanEval-X 66.3 对 63.5(+2.8).IFEval 60.6 对 57.7(+2.9).Math500 77.8 对 76.8.MathBench 79.3 对 78.4.GSM8K 91.4 对 92.7(-1.3).GPQA-diamond 36.7 对 37.3(-0.6).MBPP 71.6 对 75.1(-3.5;HTML 着色写成 +3.5,按两列相减).TriviaQA 75.9 对 66.5(+9.4).LMB-Hard 各档都偏低:1.7B 从 9.2 到 6.6(-2.6),8B 从 15.7 到 8.9(-6.8),30B 从 15.5 到 13.7(-1.8).平均「不掉点」盖不住这一列.1.7B 对块长更敏感:HumanEval 61.6 对 AR 的 65.9(-4.3),AIME-25 从 3.3 掉到 2.1.作者后文写小模型 $B>4$ 就掉,大模型能把块开到 16 甚至 32.主表用 $B=4$ 评质量上限,吞吐另扫.

Table 3 还把 Qwen3-Base 和 AR-Chat 并排放.1.7B 上 Base 的 Math500 是 43.5,同一套 CPT 加 SFT 之后 AR-Chat 到 62.0,SDAR-Chat 到 63.2.30B 上 Base 的 Math500 59.0,AR-Chat 76.8,SDAR 77.8.转换保住的是已经付过 CPT 和 SFT 的那一截,不是裸 Base.LLaDA 8B 的 Math500 在这张表里是 37.3,Dream 38.7,和 Qwen3 转出来的 8B(78.6)不在一个数量级.差距主要来自基座和后训练,扩散还是自回归排在后面.

Table 3 把 SDAR-8B 的 MMLU 78.6 写在 LLaDA 65.9,Dream 69.5 旁边.LLaDA 那格 65.9 对得上 Nie Table 1 Base;GSM8K 78.6 对得上 Instruct 块长 8,不是 Base 的 70.3.Dream 的 MMLU 69.5 是 Base Table 1;GSM8K 81.0,HumanEval 55.5,IFEval 62.5 是 Instruct Table 2.一张表混了 Base 和 Instruct.能说的是:Qwen3 转出来的 8B Chat,绝对分数已经离开 2025 年初那张开源扩散表.不能说块扩散改编已经全面超过从头训的 8B.数据,后训练,基座都不是对照.

块长和阈值是同一张风景的两根轴.静态把一块用满 $B$ 步揭完,质量天花板.动态 $\tau\in\{0.80,0.85,0.90,0.95\}$,$k$ 随置信变,步数仍等于当前选用的块长.小模型(1.7B,4B)对 $B>4$ 脆;8B 和 30B-A3B 更能扛.中间块长 8 或 16 在 GSM8K,MathBench,HumanEval 上有时反超更小的块,作者写成「中等生成上下文偶尔有用」,不是单调越块越好.$\tau$ 往 1 靠,分数往静态靠.30B-A3B 在 $\tau\ge 0.90$ 上多数任务接近饱和.MBPP 对 $\tau$ 更敏感,作者归因于 SFT 之后不适合当 Base 评测.SFT 还可以把块长从基座再拉大,作者说成本可忽略,细表在附录;主文当配方,不当免费午餐.

算法加速用 TPF:生成 token 总数除以前向次数.AR 的 TPF 恒为 1.SDAR 的 TPF 随 $B$ 单调涨,同一 $B$ 下大模型更高,因为更尖,更容易过阈值.$\tau$ 调低并不总是更快.解码是马尔可夫的:这一块若收下高熵内容,下一块更不敢揭,TPF 反而掉.质量和速度在这里不是两根独立轴.作者把「更大,更尖」写成加速的引擎,而不是跟速度做交换的代价.蒸馏或 RL 若把熵压下去,并行也会跟着涨.那是展望;主表没有 RL 列.d3LLM 用伪轨迹教揭开顺序,走的是另一条压熵的路,基座不是 SDAR,数字不要横减.

## 4. H200 上的 6600 不是聊天延迟

算法 TPF 相对 AR 恒为 1.墙上的 tokens/s 要另测.作者用 LMDeploy,单卡 H200,SDAR-Chat-8B,块长 4 到 64,动态 $\tau=0.9$,Math-500,batch 从 4 扫到 512.峰值 TGS:块长 4 为 6600,8 为 5510,16 为 4236,32 为 2520,64 为 1509.块越小,batch 越大,绝对吞吐越高.相对 AR 的优势出现在小 batch:每步算一块,前向更重,更早进入算力墙;batch 拉大之后 AR 的连续解码把 GPU 喂饱,扩散的相对倍数收窄.交互式,低并发,块扩散更值钱;吞吐型大 batch,要重测.

实现里块完成后还要多一次前向写 KV.记 $t_f$ 为一次前向时间,$\alpha$ 为 batch,$\beta$ 为块长,$\gamma$ 为动态解码下每块平均前向次数.AR 的吞吐是 $\mathrm{TGS}_{\mathrm{AR}}=\alpha/t_f$.静态 SDAR 因额外那一次 KV 前向变成

$$
\mathrm{TGS}_{\mathrm{static}}=\frac{\alpha\beta}{(\beta+1)\,t_f}.
\tag{6}
$$

动态解码将式中的 $\beta$ 替换为平均前向次数 $\gamma$.论文 Figure 8 左图:$t_f$ 随 batch 先缓增,越过算力墙之后变成近似线性,斜率在不同块长之间接近.右图从实测 TGS 反推 TPF,和算法曲线对得上.算法倍数能落到引擎上,绝对吞吐仍取决于是否已经算力饱和.大块在低 batch 加速更明显,也更早撞墙.部署时按并发选 $B$.分母里的 $+1$ 是当前引擎的税,不是块扩散的定理.作者自己写:把 KV 写进下一步解码,给这块图案写专用 kernel,小 batch 优势还能再拉长.报 6600 时,硬件是 H200,引擎是 LMDeploy,模型是 8B Chat,任务是 Math-500,batch 很大.dInfer 的 680 是 8 张 H800,MoE,batch 1,长度 1024.Mercury 1109 是 H100 单卡第三方.三套不能减.这些吞吐结果必须连同各自的硬件与并发协议报告.

开源实现包含两套引擎:研究实验使用 JetEngine,生产吞吐使用 LMDeploy,与 vLLM 默认 `generate()` 的执行路径不同.当前实现会在块完成后额外执行一次 KV 前向.四块 serving 调度没有进入 SDAR 主表,680 TPS 也采用不同的硬件与 batch,因此不能作为 SDAR-8B 的聊天延迟.引用吞吐时需要同时给出硬件、batch、模型和任务.

## 5. 科学推理:ChemBench +12.3

30B-A3B-Sci 不是 Chat 那条 50B 流水线.先从 Qwen3-30B-A3B 用 AR 目标继续预训练 1T 科学语料(500B 通识科学加 500B 退火),再把其中 50B 拿来做块扩散转换,再 0.5B 长 CoT SFT.对照的 AR-Sci 从同一份 1T 中间检查点出发,同一 50B 继续当 AR,同一套 SFT.差的是转换阶段的目标,不是数据.

## 6. 失效:移位,块长,协议

Dream 的全双向几何依赖移位对齐.dKV-Cache 把 Dream 推理移位搞反,GSM8K 掉到 32.68.SDAR 能这么做,是因为块间仍因果,头仍对准下一词位置,块内双向范围等于 $B$.将同一套「不移位」直接用于全双向改编上,没有这张表.

1.7B 把块开到 16,质量掉.主表用 4 评质量,扫 64 评吞吐,两套工作点.部署若把 1.7B 配成块长 64 再引用 30B 的「可忍耐」,表不支持.动态阈值过低会收下高熵块,下一块更不敢揭,TPF 和质量一起坏.

Table 3 的 LLaDA / Dream 与 Nie / Ye 的 Base 主表横减.78.6 是 Instruct 块采样;65.9 是 Base MMLU.SDAR-8B 的 78.6 MMLU 是 Qwen3 转出来的 Chat,后训练不同.2B 表是块长 16,Qwen3 主表是块长 4,Sci 表又是块长 4 静态.三套工作点需要分别报告协议.

SDAR 选择先训练 AR,主要因为从零训练块扩散需要更多计算、优化较松的 ELBO,训练阶段也无法利用推理 KV 缓存.BD3-LM 与 LLaDA 2.0 的 WSD 表明块扩散仍可从训练侧构建,但成本结构不同.另一方面,SDAR 的块间因果约束使全双向填空、跨块 infill 和反向诗歌任务弱于 Dream.选型时需要明确任务是否依赖块外未来上下文.

Table 2 的 18 项中,LMB-Hard 和 1.7B 的 HumanEval 提醒:平均持平会把难样本藏起来.竞赛数学硬集,小模型代码,对块长和转换都更敏感.报「30B 上 11 项不掉」时,也需要同时报告下降的项目.Sci 流水线多付了 1T 科学 AR,再转 50B,ChemBench 的红利不能记到 Chat 那条 50B 头上.两条管线,两张表.

## 7. 读完应留下的判断

要不要从零训扩散,先看同等预算的 MATH 和 HumanEval,不要只看 ELBO 能不能当生成模型.要改编,先问要不要全双向:要填空走 Dream;要 KV 和可变长走 SDAR,v2,2.0.要报快,先问 batch:H200 上 6600 是大 batch 峰值;聊天延迟看小 batch 那一截.要报科学,ChemBench +12.3 有同数据 AR 对照,GPQA +5.5 同样;LCB-v5 贪心 -10.8 必须一起报.多数投票能再抬一截,pass@k 是上界.

图 1 左列表示训练阶段先优化 NLL;NLL 先付.右列是推理纪律:块间真缓存,块内还在去噪.底栏两句分母,两组分母必须分别记录.开源检查点按尺寸和块长成套放出,1.7B 到 30B,块 4 到 64.选权重时看文件名上的块长,不能默认主表那个 4.研究代码走 JetEngine,生产数字走 lmdeploy 那张 H200 表,两套不能混合引用延迟.Sci 检查点是另一条 1T 科学管线,与 Chat 的 50B 转换属于不同检查点.长 CoT 样例在附录 11,主表仍是静态块长 4,没有 RL 列.
