# 采样与调度:揭开,重掩,步数

训练只保证 $p_\theta(x_0^i\mid x_t)$ 在掩码位置上校准得像样.生成还要决定:当前这一步提交哪些位置,提交之后下一步的 $x_s$ 长什么样,一共走多少步.这三件事是推理超参,同一组权重换调度,GSM8K 可以差几十个点.LLaDA 附录 Table 9:随机 remask 21.3,低置信 remask 70.0,生成长度设定相同. 以下采样方法沿用掩码扩散式 (1).动画中的 MaskedDiffusion 每一步优先揭开高置信位置.

## 1. 图 1：掩码状态的反向更新

- **两行同一份 $x_t$**:差别只在「盖回去哪两格」,网络权重没变.
- **上行 random remask**:按日程随机选择继续保持掩码的位置,不利用置信度.只有候选 token 和保留/重掩事件都按解析后验抽样时,才是严格的祖先采样;图中的 argmax 版本仍是近似实现.LLaDA Table 9 里随机策略的 GSM8K 为 21.3.
- **下行 low-conf remask**:盖 0.55 与 0.31,提交 0.92 与 0.88.同一设定下 GSM8K 70.0.
- **红叉不是实现细节**:它标记的是「已经尖的格子被随机策略埋掉」.下一步双向注意力就少两个可靠条件.
- **图里的 0.5 比例**对应 $\frac{s}{t}=0.5$ 时期望盖回一半掩码.真实日程按时间网格变,不是永远一半.
## 2. 反向一步在干什么

记当前掩码率为 $t$,下一步更干净的水平为 $s\in[0,t)$.网络看见 $x_t$(含提示),对仍是 `[MASK]` 的位置给出 $x_0$ 分布.严格的吸收态祖先采样先按该分布抽候选 token,再按解析反向后验独立决定每个位置在 $x_s$ 中继续掩码还是揭开;线性日程下,继续掩码的边际比例是 $s/t$.这个后验不按"谁更有信心"挑位置. 实践中的低置信,top-k,阈值和 argmax 解码使用同一日程控制数量,却根据模型置信度选择具体位置或用众数替代抽样.它们是经验启发式,不是精确反向后验;质量可能更好,但不能把所得样本当作严格祖先采样的无偏输出.

均匀时间网格把 $[0,1]$ 切成 $T$ 段,$t=1,1-1/T,\ldots$.$T$ 就是「网络前向次数」.$T=L$ 且每步只揭开一个位置时,步数退回和 AR 相同,只是揭开顺序不必从左到右.$T\ll L$ 时每步必须同时提交多个位置,这是吞吐来源,也是因子分解误差来源:一步里两个位置的预测只通过当前 $x_t$ 耦合,提交之后才变成彼此的上下文. 生成长度在纯扩散里是超参:一开始垫多少个 `[MASK]`.LLaDA 预训练和 SFT 都见过变长,附录说结果对这个超参不敏感.Instruct 版仍会因为 `[EOS]` 训练信号过强而提前结束,需要把 `[EOS]` 置信度置零.这不是日程的问题,是数据里垫结束符的问题.

五 token 的例子.当前 $x_t=(\mathrm{M},\mathrm{M},\text{明},\mathrm{M},\mathrm{M})$,$t=0.8$,下一步 $s=0.4$,则 $\frac{s}{t}=0.5$,四个掩码位置里期望盖回两个.网络对四个掩码位给出最大概率,比如 $0.92,0.55,0.88,0.31$.低置信策略盖回 $0.31$ 与 $0.55$ 那两格,提交 $0.92$ 与 $0.88$.随机策略可能盖回两个已经很尖的格.下一步 $x_s$ 里,「明」和两个新揭开的字成为双向上下文,继续猜剩下的掩码.动画里「逐步露出」就是这个循环,不是训练时的随机掩码.

## 3. 低置信 remask 为什么比随机强

按解析概率随机抽样是理论反向过程;常见的"先 argmax,再随机盖回固定数量"已经是它的近似.低置信策略进一步偏离后验:它把计算预算留给分布仍平的位置,避免随机埋掉尖锐预测.LLaDA 写明该策略借鉴 MaskGIT 的退火,不是由 ELBO 推导出来的.它在该评测上质量更高,说明实用解码器可以优于朴素近似,不说明启发式等于真实后验.

top-k / top-p 揭开是同一件事的另一种切法:每步固定提交 $k$ 个最尖的位置,或提交累积概率超过 $p$ 的集合.MDLM 的项目页和实现里有 top-p 掩码调度.阈值解码(LLaDA 2.0 主评测用 0.95)则是:概率超过阈值的位置本步提交,否则继续掩.阈值高则每步少提交,质量稳,TPF 低.2.0 在 mini 上扫过阈值和块大小,0.95 与块长 32 被选成主设定. EB-Sampler 一类方法试图给「何时可以同时揭开多个位置」一个联合熵上界,避免只看边际置信度.这是在修因子分解误差,不是换模型.

## 4. 纯扩散,自回归,块扩散三种采样

LLaDA 的权重在预训练之后就可以用三种方式采样,不必再训.附录 Table 7–8 把这件事做了消融. **纯扩散**:整段回答同时处于同一掩码日程,双向看见整句已揭开部分.Base 模型上 Humaneval 35.4,整体最好. **自回归采样**:每步只揭开最左边的一个 `[MASK]`,等价于用双向模型做从左到右的生成.Base 上 Humaneval 掉到 18.3.Instruct 上若干生成任务直接崩到 0,因为 `[EOS]` 与定长垫片和「一次一个」冲突. **块扩散采样**:把回答切成块.块与块之间从左到右;块内仍做掩码扩散.块长 $L'$ 是旋钮.$L'=32$ 时 Instruct 的 GSM8K 到 77.5,再把块长收到 8 可以到 78.6,高于纯扩散的 69.4.作者解释是 SFT 里大量 `[EOS]` padding 让纯扩散过早结束,块结构限制了结束符的传播.

同一组 8B 权重,采样器可以把它变成三种不同的模型.报数字必须写采样器.旧笔记把「扩散比 AR 快 2–8 倍」写在 LLaDA 名下,论文里没有这张速度表;速度要看 Mercury,LLaDA 2.0-CAP,Fast-dLLM 那些专门测吞吐的工作.

## 5. 步数–质量,以及「并行诅咒」

步数加多,反向更接近连续时间极限,质量通常上升,成本线性加.LLaDA Base 把生成长度和步数都设成 1024 去做 Humaneval 一类生成题,等于一步揭开约一个 token,放弃吞吐去换质量.产品侧的 Mercury 走另一端:粗到细并行改很多位置,用 H100 上四位数的 tokens/s 说话. 并行诅咒指的是:一步提交的位置越多,这些位置在提交前互相看不见对方的最终取值,搭配错误上升.缓解手段分三类.

解码侧:只提交高置信位置(Fast-dLLM,阈值解码);用小 AR 或自身做验证(APD,自投机 SSD);允许把已经落盘的字再变成 `[MASK]`(ReMDM).后一件和本步低置信 remask 不是同一层,见[提交之后还能不能改](../../6-推理加速与系统/6.1-采样调度与纠错/6.1.2-纠错重掩与动态调度.md).静态阈值之外还有动态 $S$:[SlowFast](../../6-推理加速与系统/6.2-验证投机与流水线/6.2.2-规划与快慢动态采样.md) 用终点方差决定何时从慢探切到快揭,15.63× 在 GPQA 长度 1024. 训练侧:dParallel 的 certainty-forcing 蒸馏让边际更快变尖;LLaDA 2.0 的 CAP 在已经预测对的位置上再压熵,提高 TPF. 结构侧:块扩散把并行范围限制在块内,块间有因果前缀,KV 可以缓存.这是下一篇知识点的主题.

## 6. 缓存:双向注意力默认没有 KV Cache

AR 的 KV Cache 成立,是因为位置 $i$ 的 Key/Value 在后续步骤里不再改变.全双向掩码扩散每揭开一些字,所有位置的注意力都可能变,严格 KV Cache 不成立.LLaDA 8B 因此不用 GQA.后来的 dKV-Cache,Fast-dLLM 做的是**近似**:延迟缓存,分块缓存,或只在已提交且不再改的位置上缓存.报「扩散也能 KV Cache」时,问的是近似还是块间因果.块扩散的块间部分是真缓存;块内仍要反复算.

### 6.1. 失效

$T$ 太小:一步揭开太多,出现前后矛盾,代码括号不配.$T$ 太大:吞吐掉回 AR,扩散的卖点消失. 阈值过低时,低置信分布也会被提交;若不允许 remask,这些错误无法回退.Seed Diffusion 后 20% 的编辑腐蚀走另一条路:训练时就让已写的字再变脏,采样时才能改已经揭开的 token.那是改前向的一部分,不是把 Table 9 的低置信策略再拧紧一档.

生成长度短于答案:后面被截断.长度长于答案:靠 `[EOS]` 或后处理切.Instruct 数据若用 `[EOS]` 垫到固定长,纯扩散会学会「到处写结束符」.LLaDA 附录在 Humaneval,GSM8K 上把 `[EOS]` 置信度置零,就是在堵这条捷径.块采样用块边界拦住结束符往尚未生成的块传播,所以 Instruct 的 GSM8K 可以从纯扩散 69.4 走到块长 8 的 78.6.同一检查点,解码器比再训一遍更便宜.

把 AR 的温度,top-p 直接套在每步边际上:可以,但温度现在同时影响「揭开谁」和「揭成什么」,两个旋钮缠在一起.调采样先固定 remask 策略,再动温度.温度升高会让更多位置的 max probability 掉到阈值以下,于是阈值解码每步少提交,表面上变慢,质量未必变好.这和 AR 里「升温更随机,长度不变」不是同一件事. 下面伪代码展示低置信,argmax 启发式的完整循环.严格反向后验的祖先采样器另有一步随机抽样,具体仓库也会调整提交和重掩细节.

```text
x ← [MASK] * L
for t in (1, 1-1/T, ..., 1/T):
    s ← t - 1/T
    logits ← f_θ(prompt, x)          # 双向,未掩位置可见
    conf ← max(softmax(logits), dim=-1)
    n_keep ← round((1 - s/t) * n_mask(x))
    submit ← topk(conf among MASK, n_keep)
    x[submit] ← argmax(logits[submit])
    # 其余 MASK 保持;本步低置信只盖尚未提交的预测,不是改已落盘明文
return strip_after_eos(x)
```

`n_keep` 随 $t$ 下降而增加,前面几步只敢提交很少位置,后面才大面积揭开.阈值解码把 `topk` 换成 `conf > τ`.块扩散在这块循环外再套一层:写完一块,把这块写入 KV,再初始化下一块的全掩码.

### 6.2. 读完检查

应能区分:训练的 $t$ 是掩码率随机变量;推理的 $T$ 是反向步数;$\frac{s}{t}$ 是本步要盖回去的比例.应能说出低置信 remask 在 LLaDA Table 9 上的差距,以及为什么 Instruct 的 GSM8K 在块采样下更高.下一篇用 BD3-LM 把「块」从采样技巧升级成模型定义. 开源模型和商业模型报速度时,分母经常不一样.有的 tokens/s 含 prefill,有的只算 decode;有的 batch=1 延迟优化,有的 batch=4 吞吐优化.Mercury Mini 的 1109 tokens/s 来自 Artificial Analysis 在 H100 上的第三方评测;LLaDA 2.0-flash-CAP 的 535 TPS 来自作者用 dInfer 对 SGLang 上 AR 基线的对照.两套数字不能减出「谁快一倍」.速度比较必须同时报告 $T$,阈值与块长,否则无法判断加速来自哪项设置.

步数 $T$ 和序列长度 $n$ 解耦之后,产品上会出现一种新的调参习惯:同一句回答,可以先用很小的 $T$ 出草稿,再加步数打磨.Dream 在 Countdown 上把步数扫到 5–20 仍能优于同尺寸 AR,靠的是规划题短,约束密.写长文档时,少步意味着一步揭开太多格子,括号和指代更容易对不齐.并行诅咒不是口号,是「提交前互相看不见最终取值」这句话的直接推论.缓解手段里,低置信 remask 最便宜,因为它不改权重;dParallel 那种 certainty-forcing 要蒸馏;块扩散则是改结构,把并行范围关进块内.选型时先问能不能改解码器,再问能不能再训.

阈值解码把「每步揭开多少」从比例改成绝对值.0.95 意味着只有高置信位置在本步提交,其余保持掩码.TPF(tokens per forward)随之下降,质量通常更稳.LLaDA 2.0 主评测采用 0.95 与块长 32,这是参数扫描后的折中.阈值过高时每步接近只揭一个位置,吞吐退回 AR;阈值过低时低置信位置也会被提交,错误会保留到后续步骤.因此阈值需要按任务调节.

伪代码里的 `argmax` 还可以换成按分布抽样.argmax 让同一种子更稳,抽样让多样性回来,也让低置信策略看到的「尖」变成随机尖.评 Humaneval 这类要过测试的题,主表常用 argmax 或很低的温度.写故事时可以抽样.温度,是否 argmax,remask 策略三者会缠在一起,调参一次只动一个.LLaDA Table 9 已经证明 remask 单独就能把 GSM8K 从 21.3 拉到 70.0;先锁这一项,再动温度,否则你不知道是哪一个旋钮救了分数.

生成长度在纯扩散里是画布,不是「写到 EOS 停」.画布太短,答案被截断,看起来像模型不会做;画布太长,模型在空白处堆结束符或胡写.LLaDA 说 Base 对长度不敏感,Table 10 支持这句;Instruct 不支持这句,因为 SFT 把 EOS 垫进固定长.产品若用 Instruct 权重,长度和 EOS 置零要一起调.块扩散把画布改成「再开一块」,可变长回来,EOS 传播被块边界拦住.这是 Instruct 的 GSM8K 从 69.4 走到 78.6 的机制解释,并非模型突然更会算术.

并行揭开与投机解码的回退机制不同.投机解码有草稿和验证器,拒绝可以回滚.扩散的阈值揭开没有验证器,错误位置只能通过 remask 回退.Fast-dLLM 的并行提交同样是边际启发式.真正带验证的 APD,SSD 要单独算进延迟,不能算进「训练免费加速」的倍数里.比较加速结果时需要核对错误能否回退,以及回退开销是否计入吞吐.

低置信 remask 从 MaskGIT 来,不是从 ELBO 来.严格祖先采样按解析后验抽样;argmax 后随机盖回是近似;按置信度盖回则是更强的启发式.三者必须分名.EB-Sampler 一类方法尝试给"何时可以同时揭开"增加联合熵保证.实践上仍常先用低置信或阈值,失败后再上更贵的验证;图 1 只解释这项启发式为什么可能有效. 块采样在 Instruct 上提高 GSM8K,但 Table 7 的 Base 模型使用纯扩散整体更好.SFT 的 EOS 填充改变了解码器与训练分布的匹配关系,所以 Base 与 Instruct 的最优采样器不同.部署经过 SFT 的模型时,应在目标 Instruct 检查点上比较 Table 8 的四类设置,再固定采样器.

伪代码末尾的 `strip_after_eos` 假设结束符出现之后的内容无意义.Instruct 若把 EOS 垫到画布末尾当普通 token 训过,模型可能在中间就写出结束符,后面仍是掩码.置零 EOS 置信度是补丁,块边界是结构补丁.两个补丁都在堵同一件事:结束符抢了还没写完的格子.调采样时若只动温度不动这两项,Instruct 生成任务会反复提前结束.

图 2 把「分数是采样器的」画成三条路,调参时可以按这张图排优先级.先锁 remask:Table 9 已经证明随机盖回能把 GSM8K 从 70.0 打到 21.3,这一刀比温度更狠.再锁解码器身份:Instruct 权重不要默认走 AR 采样,图 2 中间那列会归零.然后才扫 $T$,阈值,温度.一次动三个旋钮,你不知道是哪一个救了分数.Base 和 Instruct 的最优解码器还可能相反:Table 7 里 Base 纯扩散整体最好,Instruct 却吃块结构.换检查点等于换图 2 该走哪一列.

步数 $T$ 与长度 $n$ 解耦之后,少步不是免费的.$T=8$ 且 $n=256$ 意味着每步大约提交几十个位置,这些位置在提交前只通过当前 $x_t$ 耦合.括号,指代,数独盘上的重复数字,都会在这一步里按边际各自做决定.低置信 remask 把还平的格子留到下一步,等于用更多前向去买联合信息.阈值 0.95 更狠:不够尖就不提交.两种策略都在承认同一句话:一步多 token 的联合并非网络直接输出的对象,输出的是边际.采样器的工作是决定哪些边际现在可信.

投机解码包含草稿和验证器,拒绝后可以回滚,报告的延迟需要包括验证开销.扩散的阈值揭开没有验证器,错误位置只能通过 remask 修改.Fast-dLLM 的并行提交同样依赖边际置信度.带验证的 APD 与 SSD 需要单独计入验证延迟,不能并入无需训练的采样器加速倍数.图 2 的三条路径均没有验证器.

### 6.3. 从两时刻联合分布推反向后验

吸收态掩码的好处是后验可以直接算.令 $\alpha_t$ 表示时刻 $t$ 仍保留原 token 的概率,噪声越强时 $\alpha_t$ 越小.单个位置的前向边缘为

$$
q(x_t\mid x_0)
=\alpha_t\delta_{x_0}(x_t)
+(1-\alpha_t)\delta_m(x_t).
$$

取 $0\le s<t\le1$,从较干净的 $x_s$ 走向较脏的 $x_t$.若 $x_s=x_0$,它在 $t$ 仍保留的条件概率为 $\alpha_t/\alpha_s$;其余概率转入吸收态 $m$.若 $x_s=m$,之后一直是 $m$.于是

$$
q(x_t=m\mid x_s=x_0)
=1-\frac{\alpha_t}{\alpha_s}.
$$

反向时已知 $x_t$.当 $x_t$ 是可见 token,吸收态性质保证此前也是同一个 token,所以 $x_s=x_t$.真正需要采样的是 $x_t=m$ 的位置.给定干净 token $x_0$,它在较早时刻已经揭开的概率为

$$
q(x_s=x_0\mid x_t=m,x_0)
=\frac{\alpha_s-\alpha_t}{1-\alpha_t},
$$

继续保持掩码的概率为

$$
q(x_s=m\mid x_t=m,x_0)
=\frac{1-\alpha_s}{1-\alpha_t}.
$$

若使用常见线性保留率 $\alpha_t=1-t$,第二项化为 $s/t$,这就是正文中「期望盖回比例」的来源.它由前向马尔可夫链决定,不是随手规定每步留多少掩码.网络的角色是替代未知的 $x_0$:先从 $p_\theta(x_0\mid x_t,t)$ 得到候选,再把候选代入上面的后验. 对单个位置,模型反向核可以写成

$$
p_\theta(x_s\mid x_t)
=\sum_{\hat x_0}
q(x_s\mid x_t,\hat x_0)
p_\theta(\hat x_0\mid x_t,t).
$$

若按这条分布逐位置抽样,并使用训练定义对应的时间网格,才接近祖先采样的语义.argmax、top-k 提交与低置信重掩会主动改变这条核.它们通常追求任务正确率,不再追求严格复现模型定义的生成分布. 解析后验里的「继续掩码」事件并不根据候选 token 的置信度变化.给定 $s,t$,每个当前掩码位置共享相同的揭开概率.低置信策略把原本随机的揭开位置改成排序选择,等于给状态转移加入依赖模型输出的控制器.控制器能显著提高答案正确率,也会改变样本多样性和概率解释.

### 6.4. 时间离散化不等于平均切开区间

训练可以把 $t$ 当连续随机变量,推理只能选择有限网格

$$
1=t_K>t_{K-1}>\cdots>t_1>t_0=0.
$$

均匀网格令 $t_k=k/K$,实现最简单.真正决定每步揭开比例的是 $\alpha_{t_k}$,而非时间坐标本身.若 $\alpha_t$ 非线性,均匀 $t$ 会在某些区间大量揭开,另一些区间变化很小.更自然的选择可能是让相邻时刻的保留率差、对数信噪比差或期望揭开 token 数接近. 在吸收态下,当前还有 $M_k$ 个掩码,从 $t_k$ 到 $t_{k-1}$ 期望继续掩码的数量为

$$
\mathbb E[M_{k-1}\mid M_k]
=M_k\frac{1-\alpha_{t_{k-1}}}{1-\alpha_{t_k}}.
$$

线性日程下变成 $M_k t_{k-1}/t_k$.若网格均匀,接近终点时比例变化越来越大:最终一步必须清空所有剩余掩码.前期若只提交最容易位置,最终留下的恰好是最耦合、最含糊的部分,末步强制填满可能产生集中错误. 一种改法是按剩余掩码数设计网格,让每轮提交近似固定数量.另一种是前期保守、后期仍预留多轮处理难点,例如余弦形状或幂律形状.最优形状取决于置信度随上下文增长的速度.模板化文本早期就有大量高置信位置,可以快揭;数学证明的关键符号互相依赖,更适合保留更多末期步骤.

非均匀网格还改变离散化误差.连续时间反向过程假设无穷小转移,大步长把多个本应串行吸收的信息更新合并为一次独立边际预测.当 $t_k-t_{k-1}$ 很大,模型在提交一组 token 时看不到组内最终选择.步长误差与并行因子分解误差是同一现象的两个视角:时间上跨得越远,空间上同时提交得越多.

步数 $K$ 增加并不保证单调变好.模型只在某种训练时间分布上校准,极密网格可能反复把自身微小误差作为上下文;确定性 argmax 还可能早早进入错误不动点,多走几步也不改变.若调度器允许重掩,更多步才有机会撤回;若所有已揭开位置永久固定,额外步骤只服务剩余掩码.

### 6.5. 置信度、熵与边际之间的区别

常用置信度是最大类别概率

$$
c_i=\max_v p_\theta(x_0^i=v\mid x_t,t).
$$

它回答「最可能 token 有多突出」.熵

$$
H_i=-\sum_v p_i(v)\log p_i(v)
$$

则衡量整条分布的分散程度.两者相关却不等价.一个位置可能头部概率相同,尾部质量却分布在一个备选或几千个备选上;最大概率一样,熵不同.当采样器只需要决定是否接受 argmax,$c_i$ 很直接;当它想评估不确定性结构,熵信息更多. 边际置信度还受词表大小与 token 频率影响.标点和常见功能词容易形成尖分布,事实实体、数字和罕见代码标识符更平.纯 top-k 调度会优先填满标点骨架,这通常有帮助,却可能把真正决定答案的数字拖到最终.末步被迫提交一组相互关联的数字时,错误反而集中.

概率校准是另一层问题.若模型输出 0.9 的位置只有 70% 正确,阈值 0.9 并不代表预想的风险.校准还随 $t$、任务、位置类型和上下文长度变化.统一阈值 $\tau$ 隐含假设这些条件下的概率可比较.更细的调度可以使用温度校准 $\tau(t)$、按 token 类别校准,或按每轮分位数选择. 低熵也不代表联合安全.两个位置各自分布都很尖,却可能尖在互相冲突的组合上.设两个二元变量满足只能一真一假,当前边际都给「真」0.9.逐点 argmax 会选择不可能的真真,而联合分布应在真假与假真之间分配质量.逐点熵看起来都很低,条件总相关却很高.规则密集任务里,这类冲突正是并行提交的主要风险.

跨轮变化可以补一部分信息.若 $p_i^{(k)}$ 在加入新上下文后剧烈变化,即使当前最大概率高,它也尚未稳定.可定义

$$
d_i^{(k)}
=D_{\mathrm{KL}}\!\left(
p_i^{(k)}\Vert p_i^{(k-1)}
\right).
$$

把高置信、低熵与低跨轮变化结合,能筛出更可靠的位置.代价是保存前一轮分布,而且错误自洽状态仍可能稳定.

### 6.6. remask 在马尔可夫链里改了什么

remask 常指两种动作.第一种发生在当前仍为掩码的位置:网络为它提出候选,调度器只接受一部分,其余继续保持掩码.状态从未真正离开 $m$,更准确的名字是延迟揭开.第二种动作把已经成为可见 token 的位置重新变为 $m$,这才是撤回. 标准吸收态反向链具有单调性.定义可见集合

$$
V_k=\{i:x_{t_k}^i\ne m\},
$$

从噪声走向数据时应满足

$$
V_K\subseteq V_{K-1}\subseteq\cdots\subseteq V_0.
$$

一旦位置进入 $V_k$,后续保持同一 token.真正重掩会让 $V$ 缩小,打破这条单调路径.它依然可以定义成新的马尔可夫转移核

$$
\tilde p_\theta(x_{t_{k-1}}\mid x_{t_k}),
$$

但不再是原吸收态前向过程的精确时间反演.此时评价标准从「是否忠实采样训练定义的分布」转向「是否提高最终样本质量或任务奖励」. 撤回动作至少要回答三个问题.何时触发:固定比例、置信度下降、规则冲突或验证失败;撤回多少:单点、关联集合或整块;撤回后走到哪个噪声水平:只把 token 换成掩码,还是连同时间条件一起回退.若状态改了而时间仍只向前,模型会在训练中少见的组合上预测,例如极低 $t$ 却突然出现大量掩码. 只把几个位置重掩而保持全局 $t$ 不变,对应一种位置相关噪声水平.位置 $i$ 可拥有自己的有效时间 $t_i$.状态成为

$$
(x,\mathbf t),\qquad \mathbf t=(t_1,\ldots,t_L),
$$

转移器针对不同位置执行不同程度的去噪.许多实现没有显式传入 $\mathbf t$,而让模型从掩码图样自己推断.训练若覆盖随机掩码率与多种图样,这种近似可能工作;大规模回退仍会偏离训练分布. 撤回还会破坏缓存.一个已提交 token 若参与后续隐藏状态并被缓存,重掩它意味着依赖该 token 的表示可能全部失效.全双向模型本来就难以严格缓存,块模型则把已完成块当稳定前缀.跨块重掩会撤销这项结构保证.这说明「允许改多久以前的内容」本身就是模型概率分解的一部分.

### 6.7. 吸收态与非吸收态的采样差异

吸收态的状态空间很简单:每个位置要么是真值 token,要么是 $m$.前向一旦进入 $m$ 就不返回,反向一旦正确揭开也可保持.解析后验稀疏、训练目标接近加权 MLM,适合从成熟语言模型改编. 非吸收态离散扩散允许 token 之间随机替换.转移矩阵 $Q_t$ 不只把概率送到掩码列,还会在词表内传播:

$$
q(x_t\mid x_{t-1})
=\operatorname{Cat}(x_t;x_{t-1}Q_t).
$$

若 $Q_t$ 是均匀替换,带噪序列中的可见 token 未必正确;若矩阵利用词频或嵌入邻近关系,错误可能更像真实混淆.网络从训练开始就要判断每个可见 token 是否可信.反向后验通过矩阵乘积 $\bar Q_t=Q_1\cdots Q_t$ 计算,不再只有「保留或揭开」两种分支. 非吸收态天然允许某个可见 token 在反向过程中变成另一个可见 token,因此修订属于合法状态转移.代价是每个位置都可能需要更新,状态变化密集;大词表矩阵也要利用结构才能高效计算.模型看到的上下文长期含有伪词或错误词,训练难度高于掩码提供的明确未知标记.

掩码具有「我不知道」的显式语义.模型能把注意力集中在已知位置,采样器也能清楚统计剩余工作.随机替换没有这个标记,某个流畅词可能其实是噪声.它更接近真实草稿纠错,却削弱了状态可解释性.吸收态加编辑腐蚀位于两者之间:主体过程仍有清晰掩码,部分训练样本再加入可见错误.

不同前向过程决定 remask 的含义.吸收态模型把已揭 token 重新盖住,属于偏离原反向链的控制动作;替换扩散把 token 改成另一个状态,可能本就在合法反向转移中;插删改过程还允许长度变化.它们都能表现为「模型会反复改字」,接受的训练监督与后验公式却不同.

### 6.8. 误差怎样沿着去噪轨迹传播

一次错误提交会产生两种后果.局部后果是该位置最终错误;条件后果是后续所有掩码位置都把错误 token 当上下文.吸收态单调采样若不撤回,第二种后果可能扩大.设第 $k$ 轮错误集合为 $E_k$,后续预测分布实际变成

$$
p_\theta(x_0^i\mid x_{t_k},E_k),
$$

而训练中可见位置通常来自真值,对应 $E_k=\varnothing$.错误越早提交,影响轮次越多. 低置信调度降低早期错误率,相当于控制误差注入时间.容易位置先成为可靠条件,困难位置等待更多上下文.它没有处理高置信错误:模型若对错误实体给出 0.99,调度器会最早提交,污染尤其严重.这类错误需要重掩、外部验证或训练中的可见错误腐蚀.

误差并非只会放大.双向上下文也能形成纠正压力:错误 token 与后来揭开的多数位置不一致时,若允许撤回,其置信度会下降.关键在于采样器是否重新计算已提交位置的分布.许多只对掩码位置筛选 logits 的实现看不到这种信号;允许全位置复评估才可能发现早期错误. 可以定义位置的后验反悔分数

$$
r_i^{(k)}
=1-p_\theta(x_i^{(k)}\mid x_{t_k},t_k),
$$

即模型在新上下文下对当前 token 的不认可程度.选择最高 $r_i$ 的位置重掩,比只查看剩余掩码置信度更接近纠错.但若模型倾向迎合已有上下文,错误 token 可能继续得到高概率.编辑腐蚀训练能让模型学会怀疑可见输入,从而使 $r_i$ 更有辨别力. 成组错误需要成组撤回.代码里函数名和多处调用一起错时,每个位置互相支持,单点反悔分数可能都不高.随机重掩一个位置后,其余错误仍把它拉回原答案.按依赖结构重掩整组,更可能跳出错误吸引子,代价是丢失其中可能正确的部分.这与局部搜索里的邻域大小相似:邻域太小困在局部最优,邻域太大又接近重新生成.

### 6.9. 步数、稳定性与不动点

确定性采样可以看成反复应用映射

$$
x^{(k-1)}=F_{\theta,k}(x^{(k)}).
$$

如果调度与 argmax 固定,某些状态会成为不动点:再跑一轮,候选和保留集合都不变.正确答案可以是不动点,语法流畅的错误答案也可以.增加步数只有在 $F_{\theta,k}$ 随时间、噪声图样或随机性发生有效变化时才可能跳出错误状态. 稳定性至少有三种.位置稳定指 token 多轮不变;分布稳定指完整概率向量变化很小;约束稳定指输出持续满足任务规则.位置稳定最容易测,却可能稳定地错.分布稳定比 argmax 更细,仍无法识别共同错误.约束稳定需要任务特定检查器,适用于代码、数独、格式与方程,开放文本较难.

随机采样能帮助离开不动点,也会损害已经正确的结构.温度高时,候选变化增多,低置信调度又会减少每轮提交量;两个效应同时改变轨迹.比较温度时应固定实际前向次数与最终完成条件,否则高温版本可能只是多花了步骤. 早停条件也不能只看「没有掩码」.若允许撤回,画布填满后仍可能需要校正.可以要求连续若干轮 token 不变、平均反悔分数低于阈值,或外部约束通过.每多一种条件,最终分布便进一步离开原祖先采样,但任务正确率可能上升.

步数过大还会发生过度修订.已经正确的低频词可能因为模型偏好常见表达而被改平,创作文本的多样性下降;代码里一个新颖但正确的实现可能被拉回训练集常见模板.扩散过程的「越来越干净」只对理想反向核成立,经验控制器没有数学保证每一步都提高语义质量.

### 6.10. 一个八位置例子:边际都对,组合仍错

考虑输出「若 A 成立,则 B;若 A 不成立,则 C」,其中两个位置要分别填入 B 与 C 的条件分支.当前上下文不足时,模型对两个分支各自给出高概率候选,但候选组合可能把 B、C 对调.逐点置信度都是 0.9,top-k 会一起提交;下一轮句子语法完整,模型可能顺着错误组合继续补充理由.

若每轮只提交一个位置,第二个位置能读取第一个最终选择,组合错误概率下降,前向次数却增加.若提交两个位置后允许规则检查,发现两个分支与前提冲突再共同重掩,可以保留并行度.若只重掩其中一个,另一个错误分支仍可能把它诱导回去. 把例子换成代码更直观:

```text
if ascending:
    return min(values)
else:
    return max(values)
```

min 与 max 的边际都可能很高,括号和语法也完全正确,组合语义却颠倒.词级熵无法发现,测试能发现.这说明并行采样的质量上限不只由模型词表概率决定,还由是否存在组合级验证信号决定. 数独同一行的两个空格也一样.每格根据列与宫都偏向数字 7,逐点选择产生重复.等一个格先提交后,另一个格的条件分布会排除 7.低置信策略在两者置信度同高时仍无法决定正确顺序;联合熵、规则验证或随机打破对称才有帮助.

### 6.11. 解析采样、任务解码与搜索

三类目标应分清.解析采样试图忠实实现训练模型对应的反向链,关心样本分布是否正确.任务解码关心 pass@1、准确率或奖励,可以使用 argmax、阈值和低置信选择.搜索则保留多个中间状态,比较不同去噪轨迹,例如 beam、粒子或 SMC. 解析采样最适合研究似然与生成分布.它会保留模型自身的不确定性,某些位置随机揭开,单个答案未必最高分.任务解码牺牲概率忠实性换确定性表现,LLaDA Table 9 正是这种取舍的强例子.搜索能显式处理多峰组合,代价随候选数增长.

若保留 $P$ 个粒子,每个粒子拥有自己的掩码图样和候选序列,可以按外部奖励或模型分数重采样.这比单轨迹 remask 更可能摆脱错误吸引子,却需要 $P$ 倍左右计算,还要处理粒子退化.嵌套 SMC 等方法把序列级奖励接入扩散路径,目标已经从普通采样变成受控生成. 报告结果时只写「使用扩散采样」信息不足.至少要注明时间网格、步数、候选抽样或 argmax、揭开策略、是否重掩已提交位置、长度处理和验证器.这些选项足以让同一权重表现成完全不同的生成器.
