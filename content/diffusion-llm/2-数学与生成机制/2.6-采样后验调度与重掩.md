# 采样与调度:揭开,重掩,步数

训练只保证 $p_\theta(x_0^i\mid x_t)$ 在掩码位置上校准得像样.生成还要决定:当前这一步提交哪些位置,提交之后下一步的 $x_s$ 长什么样,一共走多少步.这三件事是推理超参,同一组权重换调度,GSM8K 可以差几十个点.LLaDA 附录 Table 9:随机 remask 21.3,低置信 remask 70.0,生成长度设定相同. 以下采样方法沿用掩码扩散式 (1).动画中的 MaskedDiffusion 每一步优先揭开高置信位置.

## 1. 反向一步在干什么

记当前掩码率为 $t$,下一步更干净的水平为 $s\in[0,t)$.网络看见 $x_t$(含提示),对仍是 `[MASK]` 的位置给出 $x_0$ 分布.严格的吸收态祖先采样先按该分布抽候选 token,再按解析反向后验独立决定每个位置在 $x_s$ 中继续掩码还是揭开;线性日程下,继续掩码的边际比例是 $s/t$.这个后验不按"谁更有信心"挑位置. 实践中的低置信,top-k,阈值和 argmax 解码使用同一日程控制数量,却根据模型置信度选择具体位置或用众数替代抽样.它们是经验启发式,不是精确反向后验;质量可能更好,但不能把所得样本当作严格祖先采样的无偏输出.

均匀时间网格把 $[0,1]$ 切成 $T$ 段,$t=1,1-1/T,\ldots$.$T$ 就是「网络前向次数」.$T=L$ 且每步只揭开一个位置时,步数退回和 AR 相同,只是揭开顺序不必从左到右.$T\ll L$ 时每步必须同时提交多个位置,这是吞吐来源,也是因子分解误差来源:一步里两个位置的预测只通过当前 $x_t$ 耦合,提交之后才变成彼此的上下文. 生成长度在纯扩散里是超参:一开始垫多少个 `[MASK]`.LLaDA 预训练和 SFT 都见过变长,附录说结果对这个超参不敏感.Instruct 版仍会因为 `[EOS]` 训练信号过强而提前结束,需要把 `[EOS]` 置信度置零.这不是日程的问题,是数据里垫结束符的问题.

五 token 的例子.当前 $x_t=(\mathrm{M},\mathrm{M},\text{明},\mathrm{M},\mathrm{M})$,$t=0.8$,下一步 $s=0.4$,则 $\frac{s}{t}=0.5$,四个掩码位置里期望盖回两个.网络对四个掩码位给出最大概率,比如 $0.92,0.55,0.88,0.31$.低置信策略盖回 $0.31$ 与 $0.55$ 那两格,提交 $0.92$ 与 $0.88$.随机策略可能盖回两个已经很尖的格.下一步 $x_s$ 里,「明」和两个新揭开的字成为双向上下文,继续猜剩下的掩码.动画里「逐步露出」就是这个循环,不是训练时的随机掩码.

## 2. 低置信 remask 为什么比随机强

按解析概率随机抽样是理论反向过程;常见的"先 argmax,再随机盖回固定数量"已经是它的近似.低置信策略进一步偏离后验:它把计算预算留给分布仍平的位置,避免随机埋掉尖锐预测.LLaDA 写明该策略借鉴 MaskGIT 的退火,不是由 ELBO 推导出来的.它在该评测上质量更高,说明实用解码器可以优于朴素近似,不说明启发式等于真实后验.

top-k / top-p 揭开是同一件事的另一种切法:每步固定提交 $k$ 个最尖的位置,或提交累积概率超过 $p$ 的集合.MDLM 的项目页和实现里有 top-p 掩码调度.阈值解码(LLaDA 2.0 主评测用 0.95)则是:概率超过阈值的位置本步提交,否则继续掩.阈值高则每步少提交,质量稳,TPF 低.2.0 在 mini 上扫过阈值和块大小,0.95 与块长 32 被选成主设定. EB-Sampler 一类方法试图给「何时可以同时揭开多个位置」一个联合熵上界,避免只看边际置信度.这是在修因子分解误差,不是换模型.

## 3. 纯扩散,自回归,块扩散三种采样

LLaDA 的权重在预训练之后就可以用三种方式采样,不必再训.附录 Table 7–8 把这件事做了消融. **纯扩散**:整段回答同时处于同一掩码日程,双向看见整句已揭开部分.Base 模型上 Humaneval 35.4,整体最好. **自回归采样**:每步只揭开最左边的一个 `[MASK]`,等价于用双向模型做从左到右的生成.Base 上 Humaneval 掉到 18.3.Instruct 上若干生成任务直接崩到 0,因为 `[EOS]` 与定长垫片和「一次一个」冲突. **块扩散采样**:把回答切成块.块与块之间从左到右;块内仍做掩码扩散.块长 $L'$ 是旋钮.$L'=32$ 时 Instruct 的 GSM8K 到 77.5,再把块长收到 8 可以到 78.6,高于纯扩散的 69.4.作者解释是 SFT 里大量 `[EOS]` padding 让纯扩散过早结束,块结构限制了结束符的传播.

同一组 8B 权重,采样器可以把它变成三种不同的模型.报数字必须写采样器.旧笔记把「扩散比 AR 快 2–8 倍」写在 LLaDA 名下,论文里没有这张速度表;速度要看 Mercury,LLaDA 2.0-CAP,Fast-dLLM 那些专门测吞吐的工作.

## 4. 步数–质量,以及「并行诅咒」

步数加多,反向更接近连续时间极限,质量通常上升,成本线性加.LLaDA Base 把生成长度和步数都设成 1024 去做 Humaneval 一类生成题,等于一步揭开约一个 token,放弃吞吐去换质量.产品侧的 Mercury 走另一端:粗到细并行改很多位置,用 H100 上四位数的 tokens/s 说话. 并行诅咒指的是:一步提交的位置越多,这些位置在提交前互相看不见对方的最终取值,搭配错误上升.缓解手段分三类.

解码侧:只提交高置信位置(Fast-dLLM,阈值解码);用小 AR 或自身做验证(APD,自投机 SSD);允许把已经落盘的字再变成 `[MASK]`(ReMDM).后一件和本步低置信 remask 不是同一层,见[提交之后还能不能改](../6-推理加速与系统/6.2-纠错重掩与动态调度.md).静态阈值之外还有动态 $S$:[SlowFast](../6-推理加速与系统/6.3-验证投机与流水线解码/6.3.4-slowfast动态采样.md) 用终点方差决定何时从慢探切到快揭,15.63× 在 GPQA 长度 1024. 训练侧:dParallel 的 certainty-forcing 蒸馏让边际更快变尖;LLaDA 2.0 的 CAP 在已经预测对的位置上再压熵,提高 TPF. 结构侧:块扩散把并行范围限制在块内,块间有因果前缀,KV 可以缓存.这是下一篇知识点的主题.

## 5. 缓存:双向注意力默认没有 KV Cache

AR 的 KV Cache 成立,是因为位置 $i$ 的 Key/Value 在后续步骤里不再改变.全双向掩码扩散每揭开一些字,所有位置的注意力都可能变,严格 KV Cache 不成立.LLaDA 8B 因此不用 GQA.后来的 dKV-Cache,Fast-dLLM 做的是**近似**:延迟缓存,分块缓存,或只在已提交且不再改的位置上缓存.报「扩散也能 KV Cache」时,问的是近似还是块间因果.块扩散的块间部分是真缓存;块内仍要反复算.

### 6. 失效

$T$ 太小:一步揭开太多,出现前后矛盾,代码括号不配.$T$ 太大:吞吐掉回 AR,扩散的卖点消失. 阈值过低时,低置信分布也会被提交;若不允许 remask,这些错误无法回退.Seed Diffusion 后 20% 的编辑腐蚀走另一条路:训练时就让已写的字再变脏,采样时才能改已经揭开的 token.那是改前向的一部分,不是把 Table 9 的低置信策略再拧紧一档.

生成长度短于答案:后面被截断.长度长于答案:靠 `[EOS]` 或后处理切.Instruct 数据若用 `[EOS]` 垫到固定长,纯扩散会学会「到处写结束符」.LLaDA 附录在 Humaneval,GSM8K 上把 `[EOS]` 置信度置零,就是在堵这条捷径.块采样用块边界拦住结束符往尚未生成的块传播,所以 Instruct 的 GSM8K 可以从纯扩散 69.4 走到块长 8 的 78.6.同一检查点,解码器比再训一遍更便宜.

把 AR 的温度,top-p 直接套在每步边际上:可以,但温度现在同时影响「揭开谁」和「揭成什么」,两个旋钮缠在一起.调采样先固定 remask 策略,再动温度.温度升高会让更多位置的 max probability 掉到阈值以下,于是阈值解码每步少提交,表面上变慢,质量未必变好.这和 AR 里「升温更随机,长度不变」不是同一件事. 下面伪代码展示低置信,argmax 启发式的完整循环.严格反向后验的祖先采样器另有一步随机抽样,具体仓库也会调整提交和重掩细节.

```text
x ← [MASK] * L
for t in (1, 1-1/T, ..., 1/T):
    s ← t - 1/T
    logits ← f_θ(prompt, x)          # 双向,未掩位置可见
    conf ← max(softmax(logits), dim=-1)
    n_keep ← round((1 - s/t) * n_mask(x))
    submit ← topk(conf among MASK, n_keep)
    x[submit] ← argmax(logits[submit])
    # 其余 MASK 保持;本步低置信只盖尚未提交的预测,不是改已落盘明文
return strip_after_eos(x)
```

`n_keep` 随 $t$ 下降而增加,前面几步只敢提交很少位置,后面才大面积揭开.阈值解码把 `topk` 换成 `conf > τ`.块扩散在这块循环外再套一层:写完一块,把这块写入 KV,再初始化下一块的全掩码.

### 7. 读完检查

应能区分:训练的 $t$ 是掩码率随机变量;推理的 $T$ 是反向步数;$\frac{s}{t}$ 是本步要盖回去的比例.应能说出低置信 remask 在 LLaDA Table 9 上的差距,以及为什么 Instruct 的 GSM8K 在块采样下更高.下一篇用 BD3-LM 把「块」从采样技巧升级成模型定义. 开源模型和商业模型报速度时,分母经常不一样.有的 tokens/s 含 prefill,有的只算 decode;有的 batch=1 延迟优化,有的 batch=4 吞吐优化.Mercury Mini 的 1109 tokens/s 来自 Artificial Analysis 在 H100 上的第三方评测;LLaDA 2.0-flash-CAP 的 535 TPS 来自作者用 dInfer 对 SGLang 上 AR 基线的对照.两套数字不能减出「谁快一倍」.速度比较必须同时报告 $T$,阈值与块长,否则无法判断加速来自哪项设置.

步数 $T$ 和序列长度 $n$ 解耦之后,产品上会出现一种新的调参习惯:同一句回答,可以先用很小的 $T$ 出草稿,再加步数打磨.Dream 在 Countdown 上把步数扫到 5–20 仍能优于同尺寸 AR,靠的是规划题短,约束密.写长文档时,少步意味着一步揭开太多格子,括号和指代更容易对不齐.并行诅咒不是口号,是「提交前互相看不见最终取值」这句话的直接推论.缓解手段里,低置信 remask 最便宜,因为它不改权重;dParallel 那种 certainty-forcing 要蒸馏;块扩散则是改结构,把并行范围关进块内.选型时先问能不能改解码器,再问能不能再训.

阈值解码把「每步揭开多少」从比例改成绝对值.0.95 意味着只有高置信位置在本步提交,其余保持掩码.TPF(tokens per forward)随之下降,质量通常更稳.LLaDA 2.0 主评测采用 0.95 与块长 32,这是参数扫描后的折中.阈值过高时每步接近只揭一个位置,吞吐退回 AR;阈值过低时低置信位置也会被提交,错误会保留到后续步骤.因此阈值需要按任务调节.

伪代码里的 `argmax` 还可以换成按分布抽样.argmax 让同一种子更稳,抽样让多样性回来,也让低置信策略看到的「尖」变成随机尖.评 Humaneval 这类要过测试的题,主表常用 argmax 或很低的温度.写故事时可以抽样.温度,是否 argmax,remask 策略三者会缠在一起,调参一次只动一个.LLaDA Table 9 已经证明 remask 单独就能把 GSM8K 从 21.3 拉到 70.0;先锁这一项,再动温度,否则你不知道是哪一个旋钮救了分数.

生成长度在纯扩散里是画布,不是「写到 EOS 停」.画布太短,答案被截断,看起来像模型不会做;画布太长,模型在空白处堆结束符或胡写.LLaDA 说 Base 对长度不敏感,Table 10 支持这句;Instruct 不支持这句,因为 SFT 把 EOS 垫进固定长.产品若用 Instruct 权重,长度和 EOS 置零要一起调.块扩散把画布改成「再开一块」,可变长回来,EOS 传播被块边界拦住.这是 Instruct 的 GSM8K 从 69.4 走到 78.6 的机制解释,并非模型突然更会算术.

并行揭开与投机解码的回退机制不同.投机解码有草稿和验证器,拒绝可以回滚.扩散的阈值揭开没有验证器,错误位置只能通过 remask 回退.Fast-dLLM 的并行提交同样是边际启发式.真正带验证的 APD,SSD 要单独算进延迟,不能算进「训练免费加速」的倍数里.比较加速结果时需要核对错误能否回退,以及回退开销是否计入吞吐.

低置信 remask 从 MaskGIT 来,不是从 ELBO 来.严格祖先采样按解析后验抽样;argmax 后随机盖回是近似;按置信度盖回则是更强的启发式.三者必须分名.EB-Sampler 一类方法尝试给"何时可以同时揭开"增加联合熵保证.实践上仍常先用低置信或阈值,失败后再上更贵的验证;图 1 只解释这项启发式为什么可能有效. 块采样在 Instruct 上提高 GSM8K,但 Table 7 的 Base 模型使用纯扩散整体更好.SFT 的 EOS 填充改变了解码器与训练分布的匹配关系,所以 Base 与 Instruct 的最优采样器不同.部署经过 SFT 的模型时,应在目标 Instruct 检查点上比较 Table 8 的四类设置,再固定采样器.

伪代码末尾的 `strip_after_eos` 假设结束符出现之后的内容无意义.Instruct 若把 EOS 垫到画布末尾当普通 token 训过,模型可能在中间就写出结束符,后面仍是掩码.置零 EOS 置信度是补丁,块边界是结构补丁.两个补丁都在堵同一件事:结束符抢了还没写完的格子.调采样时若只动温度不动这两项,Instruct 生成任务会反复提前结束.

图 2 把「分数是采样器的」画成三条路,调参时可以按这张图排优先级.先锁 remask:Table 9 已经证明随机盖回能把 GSM8K 从 70.0 打到 21.3,这一刀比温度更狠.再锁解码器身份:Instruct 权重不要默认走 AR 采样,图 2 中间那列会归零.然后才扫 $T$,阈值,温度.一次动三个旋钮,你不知道是哪一个救了分数.Base 和 Instruct 的最优解码器还可能相反:Table 7 里 Base 纯扩散整体最好,Instruct 却吃块结构.换检查点等于换图 2 该走哪一列.

步数 $T$ 与长度 $n$ 解耦之后,少步不是免费的.$T=8$ 且 $n=256$ 意味着每步大约提交几十个位置,这些位置在提交前只通过当前 $x_t$ 耦合.括号,指代,数独盘上的重复数字,都会在这一步里按边际各自做决定.低置信 remask 把还平的格子留到下一步,等于用更多前向去买联合信息.阈值 0.95 更狠:不够尖就不提交.两种策略都在承认同一句话:一步多 token 的联合并非网络直接输出的对象,输出的是边际.采样器的工作是决定哪些边际现在可信.

投机解码包含草稿和验证器,拒绝后可以回滚,报告的延迟需要包括验证开销.扩散的阈值揭开没有验证器,错误位置只能通过 remask 修改.Fast-dLLM 的并行提交同样依赖边际置信度.带验证的 APD 与 SSD 需要单独计入验证延迟,不能并入无需训练的采样器加速倍数.图 2 的三条路径均没有验证器.

### 7.1 从两时刻联合分布推反向后验

吸收态掩码的好处是后验可以直接算.令 $\alpha_t$ 表示时刻 $t$ 仍保留原 token 的概率,噪声越强时 $\alpha_t$ 越小.单个位置的前向边缘为

$$
q(x_t\mid x_0)
=\alpha_t\delta_{x_0}(x_t)
+(1-\alpha_t)\delta_m(x_t).
$$

取 $0\le s<t\le1$,从较干净的 $x_s$ 走向较脏的 $x_t$.若 $x_s=x_0$,它在 $t$ 仍保留的条件概率为 $\alpha_t/\alpha_s$;其余概率转入吸收态 $m$.若 $x_s=m$,之后一直是 $m$.于是

$$
q(x_t=m\mid x_s=x_0)
=1-\frac{\alpha_t}{\alpha_s}.
$$

反向时已知 $x_t$.当 $x_t$ 是可见 token,吸收态性质保证此前也是同一个 token,所以 $x_s=x_t$.真正需要采样的是 $x_t=m$ 的位置.给定干净 token $x_0$,它在较早时刻已经揭开的概率为

$$
q(x_s=x_0\mid x_t=m,x_0)
=\frac{\alpha_s-\alpha_t}{1-\alpha_t},
$$

继续保持掩码的概率为

$$
q(x_s=m\mid x_t=m,x_0)
=\frac{1-\alpha_s}{1-\alpha_t}.
$$

若使用常见线性保留率 $\alpha_t=1-t$,第二项化为 $s/t$,这就是正文中「期望盖回比例」的来源.它由前向马尔可夫链决定,不是随手规定每步留多少掩码.网络的角色是替代未知的 $x_0$:先从 $p_\theta(x_0\mid x_t,t)$ 得到候选,再把候选代入上面的后验. 对单个位置,模型反向核可以写成

$$
p_\theta(x_s\mid x_t)
=\sum_{\hat x_0}
q(x_s\mid x_t,\hat x_0)
p_\theta(\hat x_0\mid x_t,t).
$$

若按这条分布逐位置抽样,并使用训练定义对应的时间网格,才接近祖先采样的语义.argmax、top-k 提交与低置信重掩会主动改变这条核.它们通常追求任务正确率,不再追求严格复现模型定义的生成分布. 解析后验里的「继续掩码」事件并不根据候选 token 的置信度变化.给定 $s,t$,每个当前掩码位置共享相同的揭开概率.低置信策略把原本随机的揭开位置改成排序选择,等于给状态转移加入依赖模型输出的控制器.控制器能显著提高答案正确率,也会改变样本多样性和概率解释.

### 7.2 时间离散化不等于平均切开区间

训练可以把 $t$ 当连续随机变量,推理只能选择有限网格

$$
1=t_K>t_{K-1}>\cdots>t_1>t_0=0.
$$

均匀网格令 $t_k=k/K$,实现最简单.真正决定每步揭开比例的是 $\alpha_{t_k}$,而非时间坐标本身.若 $\alpha_t$ 非线性,均匀 $t$ 会在某些区间大量揭开,另一些区间变化很小.更自然的选择可能是让相邻时刻的保留率差、对数信噪比差或期望揭开 token 数接近. 在吸收态下,当前还有 $M_k$ 个掩码,从 $t_k$ 到 $t_{k-1}$ 期望继续掩码的数量为

$$
\mathbb E[M_{k-1}\mid M_k]
=M_k\frac{1-\alpha_{t_{k-1}}}{1-\alpha_{t_k}}.
$$

线性日程下变成 $M_k t_{k-1}/t_k$.若网格均匀,接近终点时比例变化越来越大:最终一步必须清空所有剩余掩码.前期若只提交最容易位置,最终留下的恰好是最耦合、最含糊的部分,末步强制填满可能产生集中错误. 一种改法是按剩余掩码数设计网格,让每轮提交近似固定数量.另一种是前期保守、后期仍预留多轮处理难点,例如余弦形状或幂律形状.最优形状取决于置信度随上下文增长的速度.模板化文本早期就有大量高置信位置,可以快揭;数学证明的关键符号互相依赖,更适合保留更多末期步骤.

非均匀网格还改变离散化误差.连续时间反向过程假设无穷小转移,大步长把多个本应串行吸收的信息更新合并为一次独立边际预测.当 $t_k-t_{k-1}$ 很大,模型在提交一组 token 时看不到组内最终选择.步长误差与并行因子分解误差是同一现象的两个视角:时间上跨得越远,空间上同时提交得越多.

步数 $K$ 增加并不保证单调变好.模型只在某种训练时间分布上校准,极密网格可能反复把自身微小误差作为上下文;确定性 argmax 还可能早早进入错误不动点,多走几步也不改变.若调度器允许重掩,更多步才有机会撤回;若所有已揭开位置永久固定,额外步骤只服务剩余掩码.

**7.3 置信度、熵与边际之间的区别**

常用置信度是最大类别概率

$$
c_i=\max_v p_\theta(x_0^i=v\mid x_t,t).
$$

它回答「最可能 token 有多突出」.熵

$$
H_i=-\sum_v p_i(v)\log p_i(v)
$$

则衡量整条分布的分散程度.两者相关却不等价.一个位置可能头部概率相同,尾部质量却分布在一个备选或几千个备选上;最大概率一样,熵不同.当采样器只需要决定是否接受 argmax,$c_i$ 很直接;当它想评估不确定性结构,熵信息更多. 边际置信度还受词表大小与 token 频率影响.标点和常见功能词容易形成尖分布,事实实体、数字和罕见代码标识符更平.纯 top-k 调度会优先填满标点骨架,这通常有帮助,却可能把真正决定答案的数字拖到最终.末步被迫提交一组相互关联的数字时,错误反而集中.

概率校准是另一层问题.若模型输出 0.9 的位置只有 70% 正确,阈值 0.9 并不代表预想的风险.校准还随 $t$、任务、位置类型和上下文长度变化.统一阈值 $\tau$ 隐含假设这些条件下的概率可比较.更细的调度可以使用温度校准 $\tau(t)$、按 token 类别校准,或按每轮分位数选择. 低熵也不代表联合安全.两个位置各自分布都很尖,却可能尖在互相冲突的组合上.设两个二元变量满足只能一真一假,当前边际都给「真」0.9.逐点 argmax 会选择不可能的真真,而联合分布应在真假与假真之间分配质量.逐点熵看起来都很低,条件总相关却很高.规则密集任务里,这类冲突正是并行提交的主要风险.

跨轮变化可以补一部分信息.若 $p_i^{(k)}$ 在加入新上下文后剧烈变化,即使当前最大概率高,它也尚未稳定.可定义

$$
d_i^{(k)}
=D_{\mathrm{KL}}\!\left(
p_i^{(k)}\Vert p_i^{(k-1)}
\right).
$$

把高置信、低熵与低跨轮变化结合,能筛出更可靠的位置.代价是保存前一轮分布,而且错误自洽状态仍可能稳定.

**7.4 remask 在马尔可夫链里改了什么**

remask 常指两种动作.第一种发生在当前仍为掩码的位置:网络为它提出候选,调度器只接受一部分,其余继续保持掩码.状态从未真正离开 $m$,更准确的名字是延迟揭开.第二种动作把已经成为可见 token 的位置重新变为 $m$,这才是撤回. 标准吸收态反向链具有单调性.定义可见集合

$$
V_k=\{i:x_{t_k}^i\ne m\},
$$

从噪声走向数据时应满足

$$
V_K\subseteq V_{K-1}\subseteq\cdots\subseteq V_0.
$$

一旦位置进入 $V_k$,后续保持同一 token.真正重掩会让 $V$ 缩小,打破这条单调路径.它依然可以定义成新的马尔可夫转移核

$$
\tilde p_\theta(x_{t_{k-1}}\mid x_{t_k}),
$$

但不再是原吸收态前向过程的精确时间反演.此时评价标准从「是否忠实采样训练定义的分布」转向「是否提高最终样本质量或任务奖励」. 撤回动作至少要回答三个问题.何时触发:固定比例、置信度下降、规则冲突或验证失败;撤回多少:单点、关联集合或整块;撤回后走到哪个噪声水平:只把 token 换成掩码,还是连同时间条件一起回退.若状态改了而时间仍只向前,模型会在训练中少见的组合上预测,例如极低 $t$ 却突然出现大量掩码. 只把几个位置重掩而保持全局 $t$ 不变,对应一种位置相关噪声水平.位置 $i$ 可拥有自己的有效时间 $t_i$.状态成为

$$
(x,\mathbf t),\qquad \mathbf t=(t_1,\ldots,t_L),
$$

转移器针对不同位置执行不同程度的去噪.许多实现没有显式传入 $\mathbf t$,而让模型从掩码图样自己推断.训练若覆盖随机掩码率与多种图样,这种近似可能工作;大规模回退仍会偏离训练分布. 撤回还会破坏缓存.一个已提交 token 若参与后续隐藏状态并被缓存,重掩它意味着依赖该 token 的表示可能全部失效.全双向模型本来就难以严格缓存,块模型则把已完成块当稳定前缀.跨块重掩会撤销这项结构保证.这说明「允许改多久以前的内容」本身就是模型概率分解的一部分.

**7.5 吸收态与非吸收态的采样差异**

吸收态的状态空间很简单:每个位置要么是真值 token,要么是 $m$.前向一旦进入 $m$ 就不返回,反向一旦正确揭开也可保持.解析后验稀疏、训练目标接近加权 MLM,适合从成熟语言模型改编. 非吸收态离散扩散允许 token 之间随机替换.转移矩阵 $Q_t$ 不只把概率送到掩码列,还会在词表内传播:

$$
q(x_t\mid x_{t-1})
=\operatorname{Cat}(x_t;x_{t-1}Q_t).
$$

若 $Q_t$ 是均匀替换,带噪序列中的可见 token 未必正确;若矩阵利用词频或嵌入邻近关系,错误可能更像真实混淆.网络从训练开始就要判断每个可见 token 是否可信.反向后验通过矩阵乘积 $\bar Q_t=Q_1\cdots Q_t$ 计算,不再只有「保留或揭开」两种分支. 非吸收态天然允许某个可见 token 在反向过程中变成另一个可见 token,因此修订属于合法状态转移.代价是每个位置都可能需要更新,状态变化密集;大词表矩阵也要利用结构才能高效计算.模型看到的上下文长期含有伪词或错误词,训练难度高于掩码提供的明确未知标记.

掩码具有「我不知道」的显式语义.模型能把注意力集中在已知位置,采样器也能清楚统计剩余工作.随机替换没有这个标记,某个流畅词可能其实是噪声.它更接近真实草稿纠错,却削弱了状态可解释性.吸收态加编辑腐蚀位于两者之间:主体过程仍有清晰掩码,部分训练样本再加入可见错误.

不同前向过程决定 remask 的含义.吸收态模型把已揭 token 重新盖住,属于偏离原反向链的控制动作;替换扩散把 token 改成另一个状态,可能本就在合法反向转移中;插删改过程还允许长度变化.它们都能表现为「模型会反复改字」,接受的训练监督与后验公式却不同.

**7.6 误差怎样沿着去噪轨迹传播**

一次错误提交会产生两种后果.局部后果是该位置最终错误;条件后果是后续所有掩码位置都把错误 token 当上下文.吸收态单调采样若不撤回,第二种后果可能扩大.设第 $k$ 轮错误集合为 $E_k$,后续预测分布实际变成

$$
p_\theta(x_0^i\mid x_{t_k},E_k),
$$

而训练中可见位置通常来自真值,对应 $E_k=\varnothing$.错误越早提交,影响轮次越多. 低置信调度降低早期错误率,相当于控制误差注入时间.容易位置先成为可靠条件,困难位置等待更多上下文.它没有处理高置信错误:模型若对错误实体给出 0.99,调度器会最早提交,污染尤其严重.这类错误需要重掩、外部验证或训练中的可见错误腐蚀.

误差并非只会放大.双向上下文也能形成纠正压力:错误 token 与后来揭开的多数位置不一致时,若允许撤回,其置信度会下降.关键在于采样器是否重新计算已提交位置的分布.许多只对掩码位置筛选 logits 的实现看不到这种信号;允许全位置复评估才可能发现早期错误. 可以定义位置的后验反悔分数

$$
r_i^{(k)}
=1-p_\theta(x_i^{(k)}\mid x_{t_k},t_k),
$$

即模型在新上下文下对当前 token 的不认可程度.选择最高 $r_i$ 的位置重掩,比只查看剩余掩码置信度更接近纠错.但若模型倾向迎合已有上下文,错误 token 可能继续得到高概率.编辑腐蚀训练能让模型学会怀疑可见输入,从而使 $r_i$ 更有辨别力. 成组错误需要成组撤回.代码里函数名和多处调用一起错时,每个位置互相支持,单点反悔分数可能都不高.随机重掩一个位置后,其余错误仍把它拉回原答案.按依赖结构重掩整组,更可能跳出错误吸引子,代价是丢失其中可能正确的部分.这与局部搜索里的邻域大小相似:邻域太小困在局部最优,邻域太大又接近重新生成.

**7.7 步数、稳定性与不动点**

确定性采样可以看成反复应用映射

$$
x^{(k-1)}=F_{\theta,k}(x^{(k)}).
$$

如果调度与 argmax 固定,某些状态会成为不动点:再跑一轮,候选和保留集合都不变.正确答案可以是不动点,语法流畅的错误答案也可以.增加步数只有在 $F_{\theta,k}$ 随时间、噪声图样或随机性发生有效变化时才可能跳出错误状态. 稳定性至少有三种.位置稳定指 token 多轮不变;分布稳定指完整概率向量变化很小;约束稳定指输出持续满足任务规则.位置稳定最容易测,却可能稳定地错.分布稳定比 argmax 更细,仍无法识别共同错误.约束稳定需要任务特定检查器,适用于代码、数独、格式与方程,开放文本较难.

随机采样能帮助离开不动点,也会损害已经正确的结构.温度高时,候选变化增多,低置信调度又会减少每轮提交量;两个效应同时改变轨迹.比较温度时应固定实际前向次数与最终完成条件,否则高温版本可能只是多花了步骤. 早停条件也不能只看「没有掩码」.若允许撤回,画布填满后仍可能需要校正.可以要求连续若干轮 token 不变、平均反悔分数低于阈值,或外部约束通过.每多一种条件,最终分布便进一步离开原祖先采样,但任务正确率可能上升.

步数过大还会发生过度修订.已经正确的低频词可能因为模型偏好常见表达而被改平,创作文本的多样性下降;代码里一个新颖但正确的实现可能被拉回训练集常见模板.扩散过程的「越来越干净」只对理想反向核成立,经验控制器没有数学保证每一步都提高语义质量.

**7.8 一个八位置例子:边际都对,组合仍错**

考虑输出「若 A 成立,则 B;若 A 不成立,则 C」,其中两个位置要分别填入 B 与 C 的条件分支.当前上下文不足时,模型对两个分支各自给出高概率候选,但候选组合可能把 B、C 对调.逐点置信度都是 0.9,top-k 会一起提交;下一轮句子语法完整,模型可能顺着错误组合继续补充理由.

若每轮只提交一个位置,第二个位置能读取第一个最终选择,组合错误概率下降,前向次数却增加.若提交两个位置后允许规则检查,发现两个分支与前提冲突再共同重掩,可以保留并行度.若只重掩其中一个,另一个错误分支仍可能把它诱导回去. 把例子换成代码更直观:

```text
if ascending:
    return min(values)
else:
    return max(values)
```

min 与 max 的边际都可能很高,括号和语法也完全正确,组合语义却颠倒.词级熵无法发现,测试能发现.这说明并行采样的质量上限不只由模型词表概率决定,还由是否存在组合级验证信号决定. 数独同一行的两个空格也一样.每格根据列与宫都偏向数字 7,逐点选择产生重复.等一个格先提交后,另一个格的条件分布会排除 7.低置信策略在两者置信度同高时仍无法决定正确顺序;联合熵、规则验证或随机打破对称才有帮助.

**7.9 解析采样、任务解码与搜索**

三类目标应分清.解析采样试图忠实实现训练模型对应的反向链,关心样本分布是否正确.任务解码关心 pass@1、准确率或奖励,可以使用 argmax、阈值和低置信选择.搜索则保留多个中间状态,比较不同去噪轨迹,例如 beam、粒子或 SMC. 解析采样最适合研究似然与生成分布.它会保留模型自身的不确定性,某些位置随机揭开,单个答案未必最高分.任务解码牺牲概率忠实性换确定性表现,LLaDA Table 9 正是这种取舍的强例子.搜索能显式处理多峰组合,代价随候选数增长.

若保留 $P$ 个粒子,每个粒子拥有自己的掩码图样和候选序列,可以按外部奖励或模型分数重采样.这比单轨迹 remask 更可能摆脱错误吸引子,却需要 $P$ 倍左右计算,还要处理粒子退化.嵌套 SMC 等方法把序列级奖励接入扩散路径,目标已经从普通采样变成受控生成. 报告结果时只写「使用扩散采样」信息不足.至少要注明时间网格、步数、候选抽样或 argmax、揭开策略、是否重掩已提交位置、长度处理和验证器.这些选项足以让同一权重表现成完全不同的生成器.

**7.10 调度中的反例**

高置信优先在常识问答里可能先提交错误实体.模型对常见但不相关的人名极其自信,其余解释随后围绕人名自洽.随机延迟反而有机会让后文线索先出现,降低实体概率.因此置信度与正确率必须在目标分布上校准. 低熵优先在复制任务里可能先提交大量重复 token,真正决定对齐的分隔符被拖后.一旦重复片段错位,后续每个位置仍有尖锐的局部预测,整段却偏移一格.位置熵很低,序列编辑距离很高. 固定每轮提交数量在难度不均的数据上失衡.简单样本被迫走满步骤,浪费计算;困难样本最终一轮仍堆着大量不确定位置,被迫一次填完.阈值调度能自适应数量,又会因概率校准不同产生停滞或过早提交.

真正重掩也可能降低质量.某个罕见专有名词概率较低,但提示明确要求保留;按最低置信重掩会反复擦掉它,最终换成常见词.加入「提示拷贝保护」或位置约束能避免,同时改变转移核. 更多步数在带位置偏置的模型上可能加深偏置.每轮都把常见前缀当高置信先提交,剩余位置只能围绕它补全;少步随机并行反而产生更多样的全局结构.质量指标若只看确定性基准,会漏掉这种多样性损失.

**7.11 后验公式里的位置独立从哪里来**

吸收态前向过程通常假设给定 $x_0$ 后各位置独立腐蚀:

$$
q(x_t\mid x_0)=\prod_{i=1}^{L}q(x_t^i\mid x_0^i).
$$

解析后验也因此按位置分解.语言本身当然不独立,依赖由网络预测的 $p_\theta(x_0^i\mid x_t)$ 注入.每个边际都读取同一段带噪上下文,所以它们共享信息;一次采样时却常把这些边际独立抽取.同轮候选之间缺少显式联合项,并行诅咒由此产生. 假设两个掩码位置的真实联合分布只有 $(a,b)$ 与 $(c,d)$ 两种模式,概率各半.两个位置的边际各有两个等概率候选,独立抽样会额外产生 $(a,d)$ 与 $(c,b)$,这些组合在数据中概率为零.增加上下文可能让一种模式先被别处线索选中,边际随后变尖;在此之前同时揭开两个位置就会创造假组合.

低置信策略把平坦边际推迟,能够等待消歧线索.可若两个边际都因为模型校准错误而很尖,它仍会同时接受.联合模型、能量修正或验证器直接对组合打分,理论上更合适,计算也更贵.采样调度本质上在用额外前向次数近似缺失的联合决策. 前向独立并不要求反向真实分布独立.给定带噪状态后,被遮 token 通过数据分布强烈相关.精确反向核若能边缘化真实 $x_0$,会保留这种相关;神经网络常输出逐位置 logits,实现又把它们独立采样,近似发生在这里.所以「前向每格独立掩码」与「语言位置互相独立」完全不是一回事.

**7.12 从连续时间速率看揭开事件**

把离散网格取得很密,吸收态可以写成连续时间跳跃过程.尚未掩码的 token 以速率 $\lambda(t)$ 跳入 $m$,保留率满足

$$
\alpha_t=\exp\left(-\int_0^t\lambda(u)\,du\right).
$$

反向过程则让掩码位置以数据相关速率跳回 token.在很短区间 $[t-\Delta t,t]$ 内,揭开概率与 $\Delta t$ 近似成正比.网络提供各 token 的相对质量,噪声日程提供总跳跃强度. 有限步采样把一段连续跳跃压缩为一次批量更新.若 $\Delta t$ 很小,同一位置多次事件概率可忽略,局部近似较准;若步长很大,期间本应先揭开的 token 会影响稍后事件,批量更新却看不到这个顺序.这给「少步为何更难」一个直接解释. 非均匀时间网格可以根据总速率分配步数.当 $\lambda(t)$ 很大或模型预测变化剧烈时多放节点,平缓区间少放节点.实际困难在于模型误差未必与前向噪声速率同步.靠解析日程分配只处理数值离散化,置信度自适应还要观察当前样本.

连续时间视角也说明真正重掩相当于加入反方向跳跃.原反向生成只从 $m$ 跳向词表,重掩又允许词表跳回 $m$.新的过程可保持马尔可夫性,但生成分布要重新分析;若跳回速率由神经网络置信度决定,它是一条受控跳跃链.

**7.13 调度器可以看成一个策略**

在每轮状态 $x_t$ 上,调度器选择动作 $a_t$:揭开哪些位置、是否撤回、走到哪个下一时刻.最终获得质量奖励,同时支付网络前向成本.因此可写成受预算约束的决策问题

$$
\max_\pi
\mathbb E_\pi[R(x_0)-\lambda C(\tau)],
$$

$\pi(a_t\mid x_t)$ 是调度策略,$\tau$ 是停止时间.固定网格加随机揭开是一条手工策略;top-k、阈值和动态步数只是更依赖状态的策略. 这个视角解释了为什么同一权重可被不同采样器大幅改变.模型提供转移候选,策略决定计算分配.低置信位置多获得几轮,高置信位置早提交;困难样本自动延长,简单样本提前停止.若奖励只看最终正确率,策略可能偏向确定性输出;若还要求多样性,就要保留抽样. 策略训练也有风险.若用某个 benchmark 奖励学习调度,它可能记住答案长度、格式或常见位置,跨任务失效.一个在 GSM8K 上学会优先揭开数字周围符号的策略,未必适合开放写作.通用调度最好依赖可迁移信号,如校准置信度、跨轮稳定与局部约束.

调度器与生成模型还会共同适应.固定模型上优化出的策略只利用现有概率;若进一步训练模型迎合策略,边际会在预期揭开顺序下变尖.dParallel 的 certainty-forcing 与 CAP 可以放在这个框架中理解:它们改变模型,使并行策略每轮能可靠接受更多 token.

**7.14 随机 remask 为何在严格采样中仍有位置**

任务准确率上低置信 remask 远胜随机,并不表示随机策略毫无意义.解析后验要求按规定概率选择哪些位置仍为掩码,随机性是生成分布的一部分.它不会系统偏向模型最自信的常见表达,因此更能保留分布尾部与多样性. 低置信选择产生一种确定的 easy-first 顺序.高频词、标点和模板片段先出现,稀有词后出现.训练前向掩码没有这种选择偏差,所以后期状态分布发生变化:剩余掩码集中在模型最不会的位置.最终几步的难度高于同掩码率随机训练样本.低置信虽然提升常见基准,也可能制造末步难题.

随机后验不会把所有难点留到末尾,但可能浪费已获得的可靠预测.LLaDA Table 9 的巨大差距说明在数学问答上,保持可靠中间结果比忠实随机性更重要.生成建模若关心样本覆盖,则需同时测多样性、重复率与分布校准,不能只看 GSM8K. 混合策略可以在高置信集合中随机选择,或用置信度作为抽样权重而非硬排序.温度控制排序偏好:温度低时接近 top-k,温度高时接近随机.这样在效率与分布覆盖之间连续调节,仍然不等同于原解析后验.

**7.15 EOS 是一个具有全局含义的普通 token**

在词表层面 EOS 只是一个类别,语义上却宣告后续位置全部无效.并行模型若在多个位置同时预测 EOS,每一个都试图决定全局长度.最靠前的 EOS 通常截断输出,后面已经生成的正确 token 全被丢弃.这使 EOS 错误的代价远高于普通词错一格. 纯扩散对固定画布所有位置同时给分布,训练数据若在答案后反复填 EOS,模型会在许多位置学到高 EOS 概率.推理早期上下文稀少,中间位置也可能抢先预测 EOS.把 EOS 置信度置零相当于禁止它参与常规揭开,最终再由长度规则处理;这能救评测,也改变了模型原分布.

块生成把全局长度决策变成块级决策.当前块生成 EOS 后停止开新块,未来块尚未初始化,EOS 不会跨越整张预分配画布传播.这解释了块采样为何能改善 Instruct 模型,同时说明收益可能来自长度处理,不全是更好的数学推理. 开放长度还可用独立长度头、停止分类器或编辑式插删解决.每种方案都把 EOS 的职责拆开一部分.比较采样器时若一个使用已知答案长度,另一个必须自己预测长度,质量与速度都不公平.

**7.16 温度同时作用于内容与日程**

对 logits 除以温度 $T_{\text{temp}}$ 后再 softmax,最大概率随温度变化.在 AR 解码里,温度主要改变下一个 token 的随机性;在阈值扩散里,它还决定多少位置超过 $\tau$.升温让分布变平,本轮提交位置减少,实际步数可能增加. 若使用固定 top-k 位置提交,温度通常不改变置信度排序,但会改变候选抽样.若候选用 argmax,正温度缩放甚至不改变 token 选择,此时温度对 top-k 排序也可能没有作用.不同代码路径下「温度」不是同一个旋钮. 可以把内容温度与调度温度分开.内容温度用于从每个位置的词表分布采样;调度温度用于把位置置信度转成揭开概率.前者控制表达多样性,后者控制揭开顺序的随机性.共用一个温度会让调参难以归因.

置信度校准也常借助温度缩放,但校准温度与生成温度目标不同.校准希望概率与正确率对应,生成温度希望改变样本多样性.把校准后的概率再用于阈值,然后为了创作升温,会同时破坏提交速度.实现与报告应区分这三种用途.

**7.17 局部重掩与成块重掩**

逐位置重掩适合孤立拼写错误.若错误横跨短语、公式或代码表达式,单点修改会暂时制造更坏的上下文.例如把变量定义改名而调用处不动,中间状态不一致,模型可能把新名字改回旧名字.成块重掩能让相关位置共同重建. 块的选择可以依据固定窗口、注意力关系、语法结构或错误传播图.固定窗口便宜,却可能切断依赖;语法结构更符合代码,需要解析器;注意力权重可由模型提供,但注意力不等于因果依赖.错误传播图若来自测试或约束,精确却只适合特定任务.

重掩范围越大,探索能力越强,保留成果越少.设错误集合真实大小为 $r$,重掩 $b<r$ 时残留错误可能把新候选拉回;取 $b\gg r$ 又会擦掉大量正确 token.动态扩张可从单点开始,若若干轮仍未改善便扩大邻域,类似局部搜索中的重启. 吸收态模型没有在训练中专门见过「低噪声时突然整块掩掉」,大块回退的分布偏移尤其强.把全局时间一并回调,或在训练加入多尺度掩码块,可以减轻错配.这些改动会从采样技巧走向训练方法.

**7.18 时间条件与实际掩码率不一致**

网络通常同时读取 $x_t$ 与标量 $t$.随机前向训练时,实际掩码数围绕期望值波动,因此模型能容忍一定不一致.启发式调度、阈值停滞和重掩可能让实际掩码率远离 $t$,时间嵌入便给出错误难度信号. 一种办法把实际掩码比例

$$
\hat t=\frac{1}{L}\sum_i\mathbf 1[x_i=m]
$$

作为时间条件.纯吸收态线性日程下很自然.可在低置信 easy-first 轨迹里,同样的掩码比例对应更难的剩余位置,仅用 $\hat t$ 仍低估难度.还可加入剩余位置平均熵、最大熵或位置级时间. 另一种办法保持预定 $t_k$,严格按数量揭开,避免状态与时间严重错位.它牺牲样本自适应:简单样本不能提前结束,困难样本不能多留位置.动态调度需要模型能处理更宽的状态—时间组合. 真正重掩尤其容易造成矛盾.全局 $t$ 已接近零,却重新出现一大片掩码.若网络把低 $t$ 理解为「只剩精修」,它可能过度自信地一次填回.回退时间或提供位置级噪声标签更合理,实现也更复杂.

**7.19 步数曲线应该怎样画**

只报告一个 $K$ 无法判断模型是稳定提升、早早饱和还是先升后降.至少应在对数尺度选取多个步数,例如 4、8、16、32、64、128,同时记录质量、完成率与端到端时间.固定输出长度和候选策略,曲线才解释步数本身. 任务准确率之外,还应记录每轮实际提交 token 数、错误提交后是否被撤回、剩余位置平均熵.这些轨迹能解释曲线转折.若 16 步后质量不再提高,可能是所有位置已固定;若仍有频繁重掩,则可能进入振荡. 不同长度要分别画.同样 $K=32$,长度 64 时平均每轮两个 token,长度 1024 时平均每轮三十二个 token,联合误差完全不同.更公平的横轴可以是每 token 获得的网络前向次数 $K/L$,或 TPF 与质量的帕累托曲线.

固定计算预算下还可比较多轨迹与单轨迹.64 次前向既可给一个样本走 64 步,也可生成四个 16 步样本再验证.数学题有可靠验证器时,后者可能更强;开放写作没有明确选择器,长轨迹可能更连贯.

**7.20 采样器为何会改变模型的能力画像**

知识问答多由少数事实 token 决定,高置信错误风险大;数学推理包含长链依赖,先出现的中间结果影响后文;代码兼有局部低熵语法与全局测试约束;规划任务则要求多个槽位同时满足条件.同一调度在四类任务上分配计算的方式不同. 低置信优先很擅长先搭语法骨架,数学里的关键数字却可能留到最终.块采样限制 EOS 传播,也限制未来块修正过去推导.真正重掩适合编辑与纠错,可能反复擦掉罕见事实.采样器因此不仅是速度层,它决定模型把有限计算花在哪里. LLaDA Base 与 Instruct 的最优采样路径不同,正是能力画像改变的实例.Base 权重与 SFT 权重对 EOS、格式和输出长度的分布不同,解码器匹配程度随之改变.部署时沿用 Base 的采样设置并不稳妥.

比较模型架构时若各自使用不同调度,结果同时衡量权重与解码器.这在产品评测中合理,因为用户关心最佳系统;在科学归因中则应补充统一采样预算与各自最佳采样两组结果.

**7.21 可逆性与详细平衡**

标准扩散的反向链由已知前向过程和数据分布定义,一般不要求采样器满足某个简单的平稳详细平衡式.加入启发式重掩后,有人会把它类比为 MCMC 的拒绝或回退,两者仍有差别.MCMC 转移通常设计成保持目标分布不变,低置信重掩若没有接受率校正,并无这项保证. 若希望重掩同时保持目标分布,需要为提议与逆提议计算概率,再用类似 Metropolis-Hastings 的接受规则.语言序列状态巨大,模型概率又经逐位置近似,精确比率很难得到.实用方法往往直接优化最终质量,放弃分布保证. 非吸收态过程具有双向 token 转移,也不自动等于可逆 MCMC.时间非齐次反向链每一步目标边缘不同,从噪声逐渐走向数据;MCMC 常在固定目标分布上混合.二者都能「改已写 token」,数学对象仍不同.

这个区分影响似然与样本解释.用启发式采样得到高分答案,不能直接声称它们是模型似然下的无偏样本;用精确祖先采样得到的多样样本,也未必有最高任务奖励.研究目标决定采用哪一种.

**7.22 何时应该停止重掩**

允许无限回退会产生振荡.位置 A 依赖 B,B 又依赖 A,两种组合概率接近时,采样器可能在它们之间来回切换.若每轮都重掩最低置信集合,同一批位置长期得不到提交,延迟没有上界. 最简单的停止条件是最大步数.更细的条件包括连续 $r$ 轮没有质量改善、重掩集合重复、分布变化低于阈值,或外部检查通过.外部奖励有噪声时,一次下降未必表示轨迹变坏,可用滑动平均. 还可以给每个位置设置回退预算.一个 token 最多重掩若干次,超出后固定.这样保证完成时间,也可能固定错误.预算应与位置影响力相关:标点错误影响小,函数签名和数学前提影响大,值得更多机会.

停止策略与速度报告紧密相关.动态步数若只汇报成功样本平均,会漏掉困难样本的长尾.应同时给步数均值、分位数和超时率.扩散生成的平均吞吐很高,少数振荡样本仍可能决定线上尾延迟.

**7.23 置信度要在轨迹上校准**

普通分类校准把所有样本按预测概率分桶,比较平均概率与正确率.扩散采样里,同一位置会在多个时间被反复预测,而且进入后期的样本经过调度器筛选.前期未被接受的低置信位置集中到后期,形成选择偏差.把所有时间混在一起画可靠性图,会掩盖这种变化. 更合适的校准对象是

$$
\Pr(\hat x_i=x_{0,i}\mid c_i\in B,\ t,\ \text{position selected}),
$$

其中 $B$ 是置信度区间.应分别统计不同 $t$、不同剩余掩码率与不同 token 类别.只有对「本轮将被提交的位置」校准,阈值 $\tau$ 才能对应实际错误风险. 调度会反过来改变校准数据.若只提交高置信位置,后期剩余集合的概率系统性偏低;若训练校准器时使用随机掩码样本,它没有见过这种 hard-tail 分布.可用真实采样轨迹收集数据再做后验校准,但校准器又会改变后续轨迹,必要时迭代更新.

Expected Calibration Error 只给平均偏差,对高风险尾部不敏感.生成中更关心阈值以上位置的错误率、一次提交多个位置时至少一处错误的概率,以及高置信错误是否集中在实体和数字上.若每格错误率为 $\epsilon$,一次提交 $b$ 格时,即使独立近似成立,至少一错的概率也是 $1-(1-\epsilon)^b$.小的逐点失准会被大批量提交放大. 校准还应区分候选正确与序列有用.某 token 与参考答案不同,可能是等价表达;代码标识符局部不同,整体仍可运行.基于单一参考的 token 正确率会低估语义有效性.规则任务可以用执行或约束判断,开放文本则难以获得完美校准标签.

**7.24 熵调度怎样处理尾部概率**

最大概率只看分布最高点,熵会累加整个词表.大词表中大量极小概率项的总质量可能显著,熵因此对尾部敏感.一个位置的 top-1 为 0.8,剩余 0.2 集中在一个同义词时,风险与 0.2 分散在上万词时不同;熵能区分,却也可能把无害同义分支当高不确定. Rényi 熵提供可调视角:

$$
H_\alpha(p)
=\frac{1}{1-\alpha}\log\sum_v p(v)^\alpha.
$$

$\alpha>1$ 更强调头部,$\alpha<1$ 更关注尾部.调度若主要担心 argmax 是否可靠,较大的 $\alpha$ 可能比 Shannon 熵合适;若希望保留多样性,尾部质量更重要.不存在脱离任务的唯一熵指标. 还可用 top-1 与 top-2 的 margin

$$
\Delta_i=p_i^{(1)}-p_i^{(2)}
$$

判断两个主要候选是否接近.它忽略更长尾部,计算和解释简单.数字、括号和真假选择常由两个候选竞争,margin 很有效;开放词汇位置可能有许多近义候选,完整熵更合理. 熵随温度与词表切分变化.同一句文本换 tokenizer 后,某个词可能由一个 token 变成三个,每个位置的熵不可直接比较.跨模型调度若固定熵阈值,要先处理词表差异.模型内部按分位数选择通常更稳,但分位数只控制数量,不保证绝对风险.

**7.25 约束验证如何进入反向链**

若任务有约束函数 $C(x)\in\{0,1\}$,最直接的做法是在完整样本生成后拒绝不满足者.这不会指导中间轨迹,失败时整条重来.更有效的方法把部分约束用于每轮提交:候选若立即造成括号不平衡、数独重复或类型冲突,就暂缓或重掩相关位置. 局部约束容易接入.例如右括号出现时检查左侧是否有匹配项,非法候选概率置零后重新归一化.全局约束可能要等更多位置确定,过早应用会误杀可修复状态.数独某格候选在当前局部合法,与未来唯一解仍可能冲突;完整验证接近求解器.

引入约束后,采样分布成为条件分布或受控近似.若每一步都严格按可行集合归一化,理论目标接近 $p_\theta(x\mid C(x)=1)$;若只用启发式冲突分数选择 remask,没有精确保证.任务正确率通常受益,模型自身能力与外部求解器贡献必须分开报告. 验证成本也应进入步数预算.一次网络前向后运行轻量语法检查几乎免费,编译整个仓库或执行测试可能比生成更慢.高吞吐模型在 agent 循环中未必降低总延迟.原理分析仍要把验证器视为额外信息源:它能发现边际置信度看不见的联合错误. 软约束可写成能量 $E(x)$,对候选概率做

$$
\tilde p(x)\propto p_\theta(x)\exp(-\beta E(x)).
$$

$\beta$ 控制模型流畅度与约束强度.逐位置近似能量梯度时仍可能漏掉组合,粒子或局部搜索可保留多个方案.这已经从普通 remask 进入受控采样.

**7.26 长度与时间日程相互影响**

固定步数下,画布越长,每轮平均提交越多.因此同一个 $K$ 并不代表同一离散精度.若希望每轮平均提交量保持 $b$,步数应随长度近似增长为 $K\approx L/b$.这会削弱扩散对长输出的固定步数优势. 块扩散把活动长度限制为块长 $B$,每块使用 $K_B$ 步,总前向次数约为 $(L/B)K_B$.与 token 级 AR 的 $L$ 步相比,理论并行因子约为 $B/K_B$,还要乘上单次块前向与 AR 增量前向的成本比.块长和块内步数共同决定速度.

长度预测错误还会改变调度难度.画布过长时,多余位置需要产生 EOS 或 PAD,这些位置往往高置信、会被优先提交,给模型制造虚假的可靠上下文.画布过短时,最终位置承担截断压力,即使置信度高也无法容纳完整答案.长度头的误差与 token 采样误差不能分开评价.

若允许插入新槽位,时间网格要定义新位置从哪个噪声水平开始.直接插入掩码相当于在后期轨迹加入高噪声坐标;给它较早的局部时间更合理.删除位置又改变索引与位置编码,后续 token 表示可能整体移动.编辑式扩散的长度自由来自更复杂的状态空间,并非免费附赠. EOS 与长度头可以组合:长度头给初始画布,EOS 允许提前结束,插入操作处理不足.组合越灵活,可到达路径越多,训练与采样的一致性也越难保证.固定格式 benchmark 往往绕开这些问题,开放长文才会暴露.

**7.27 振荡、坍缩与错误吸引子**

允许反复修改后,轨迹可能出现三类坏状态.振荡是在两个或多个候选间周期切换;坍缩是不同初始随机性最终都落到同一常见模板;错误吸引子则是一组内部自洽但任务错误的 token 稳定存在. 振荡常来自相互依赖位置的同步更新.两个位置在看到旧对方时都选择翻转,下一轮又一起翻回.异步更新或一次只接受其中一个可以打破周期,相当于数值迭代里的 Jacobi 与 Gauss-Seidel 差别.随机选择更新顺序也能破坏同步对称.

坍缩与置信度优先有关.常见短语早期概率尖,很快成为上下文,后续内容围绕它收敛.提高候选抽样温度、在高置信集合内随机揭开,或保留多粒子能恢复多样性.若任务只看单一正确答案,坍缩可能不影响分数;创作与开放问答会明显受损. 错误吸引子最难处理.模型对整套错误解释都很自信,位置与分布稳定指标一起失效.只有外部事实、规则验证、独立轨迹比较或大范围随机重启可能逃离.增加原轨迹步数通常无效,因为它已处在稳定状态.

检测周期可哈希最近若干状态,重复出现时触发异步更新或扩大重掩范围.检测坍缩需跨多个随机种子比较,单轨迹看不出来.检测错误吸引子则需要与任务目标有关的信号.三者不能靠一个通用「稳定阈值」解决.

**7.28 自适应步数的统计停止**

动态采样希望简单样本早停、困难样本多算.设第 $k$ 轮平均分布变化为

$$
\Delta_k=\frac{1}{L}\sum_i
D(p_i^{(k)}\Vert p_i^{(k-1)}).
$$

当 $\Delta_k$ 连续多轮低于阈值,可以认为模型趋于稳定.若只计算未提交位置,会漏掉已提交错误的变化;全位置计算更适合允许回退的采样器. 另一指标是本轮新增可靠 token 数 $g_k$.当 $g_k$ 很小,可能接近收敛,也可能陷入困难尾部.立即停止会留下掩码,强制填满会制造错误.可切换到更保守的小批量模式,或触发一次结构化重掩. 统计停止需要防止随机波动.单轮 $\Delta_k$ 小可能是偶然,连续 $r$ 轮更稳;但每多等一轮都增加延迟.序贯检验可以在错误停止概率与计算成本间取舍,实际实现常用简单耐心参数.

不同样本的步数分布应与正确率联合报告.若高质量只来自少数超长轨迹,平均步数会掩盖尾部;若超时样本直接丢弃,准确率也会虚高.固定上限、停止规则和失败处理都属于采样协议.

**7.29 从预测正确率估算批量提交风险**

假设候选位置经过校准,每个被提交 token 正确率至少为 $1-\epsilon$.一次提交 $b$ 个位置,在独立近似下全部正确概率为 $(1-\epsilon)^b$.当 $\epsilon=0.05,b=20$ 时,全部正确只有约 0.36.这说明 0.95 阈值看似严格,大批量提交仍很可能含错. 实际错误往往正相关:某个错误理解会同时影响多个位置,全部正确概率可能更低.也可能负相关,约束让候选互相排斥.逐点校准不足以给出批量安全保证.联合熵上界与验证器正是为了估计这层风险. 可以控制每轮总风险预算 $\delta$,选择最大集合 $S$ 满足

$$
\sum_{i\in S}(1-c_i)\le\delta,
$$

这是 union bound 下的保守规则.它没有考虑相关性,优点是简单.高置信位置多时自动多提交,困难时少提交,比固定 top-k 更接近风险控制. 若要求整条序列零错误,随着长度增加风险预算必须更严,吞吐会下降.代码 pass@1 和数学 exact match 都具有这种全序列性质;开放文本允许局部措辞差异,不必追求每 token 与参考一致.同一阈值在不同指标下含义不同.

**7.30 训练时间分布与推理网格的错配**

训练若均匀采样 $t$,模型在每个时间区间获得近似相同样本数.推理网格若大量集中在低噪声区域,会反复调用一个训练占比并不高的区域.反之,少步采样跨过大片时间,模型虽在端点训练过,却要承担大跨度后验近似. 训练损失权重还会让某些时间贡献更大.即使 $t$ 均匀,高噪声位置多、梯度尺度大,模型性能可能偏向某段.选择网格应依据实测误差,不能只依据前向日程的几何形状. 可按时间测量去噪交叉熵、校准误差与一步后验误差,在误差高或变化快的区间加密网格.这类似数值 ODE 的自适应步长,只是误差估计来自离散模型.每个样本还可动态调整,代价是额外探测.

少步蒸馏直接让模型学习大跨度转移,减少网格错配.它改变了权重,与训练免费的调度优化不同.比较少步结果时,要区分原模型跳步采样与专门蒸馏后的少步模型.

**7.31 一份足够复现的采样协议**

模型名称和 checkpoint 只是起点.协议应写明提示模板、目标画布长度或长度预测方式、时间日程 $\alpha_t$、离散网格、网络前向次数,以及块长.这些变量确定基本轨迹. 候选层要写温度、argmax 或抽样、词表截断规则.位置层要写随机、top-k、top-p、阈值或熵策略,每轮最少与最多提交量.两层常被一个「top-p」混写,复现时必须区分是在词表内截断还是在位置间选择. 纠错层要写是否复评估可见 token、真正重掩的触发条件、范围和预算,以及时间是否回退.停止层要写 EOS 处理、最大步数、动态早停和未完成掩码怎样收尾.使用验证器时还要写验证频率与成本.

速度侧报告硬件、精度、batch、输入与输出长度,说明是否含预填充、固定 overhead、验证和后处理.质量侧至少给随机种子数,因为抽样与随机 remask 方差可能很大.只提供最终脚本默认值,版本变化后也难复现,关键参数应进入表格. LLaDA 的随机与低置信 Table 9 已经说明,遗漏一个采样字段足以造成几十点差距.采样协议构成模型交付给使用者的另一半,重要性与正文中的模型定义相当.

**7.32 最终把几类 remask 分开**

解析后验保留掩码:当前为 $m$ 的位置按 $q(x_s=m\mid x_t=m,x_0)$ 继续留在 $m$.它属于原反向过程. 低置信延迟揭开:先为所有掩码位产生候选,只接受高置信部分,其余仍是 $m$.它改变具体位置选择,可提高任务分数,仍保持可见集合单调增长. 已提交位置撤回:把可见 token 重新设为 $m$,可见集合缩小.它打破吸收态反向路径的单调性,用于修正早期错误. 可见 token 替换:位置不经过显式 $m$,直接由一个 token 变成另一个.在非吸收态或编辑模型中可能属于合法转移;在纯掩码模型上则是额外解码动作. 整块回退:一组相关位置共同变脏,用于逃离成组错误吸引子.它消耗更多计算,还可能使时间条件与实际噪声严重错位.

五种动作在界面上都可能表现成文字闪动或被改写,数学含义完全不同.阅读论文或代码时,先看状态是否真的写回模型输入,随后检查该位置此前是否已经被承诺,最终看训练前向过程有没有覆盖这种状态.这三步足以拆开大多数含混的「remask」表述.

**7.33 采样误差可以拆成四层**

第一层是模型误差.即使给定完全符合训练分布的 $x_t$,网络预测的 $p_\theta(x_0^i\mid x_t,t)$ 也与真实条件分布有差距.增加推理步数无法消除这一层;更多轮只是反复调用同一近似模型.继续训练、更好的参数化与更丰富数据才直接作用于它. 第二层是时间离散误差.连续反向过程被有限网格替代,一次大跨度更新错过中间上下文.增加步数、调整网格或少步蒸馏可以处理.若模型本身在中间时间校准很差,单纯加密也可能收益有限.

第三层是并行分解误差.同一轮多个位置按边际独立选取,组合不符合联合分布.减少每轮提交量、按依赖分组、使用联合能量或验证器可以处理.它与时间离散相关,却不完全相同:即使时间步很密,一次仍可能提交一组强相关位置. 第四层是控制器偏差.低置信、阈值、argmax、EOS 抑制与重掩都把采样分布推离解析后验.这些动作可能大幅提高 benchmark,也可能损害多样性或制造 hard-tail.控制器应按最终任务评价,不应借用精确后验的概率保证. 四层误差会互相遮挡.增加步数后质量不升,可能是模型误差占主导;阈值提高后变慢却不变好,可能是高置信错误;允许重掩后振荡,可能是控制器和时间条件错配.逐层做消融比一次同时改五个旋钮更容易定位.

**7.34 一个最小消融矩阵**

固定 checkpoint、提示、画布和候选温度,先比较解析随机揭开、随机数量加 argmax、低置信 top-k 与绝对阈值.这一组分离位置策略.每项同时测 exact match、序列多样性、实际步数和高置信错误率. 再固定最佳位置策略,扫描均匀时间、按保留率均匀、余弦和自适应网格.这一组分离时间离散.记录每轮剩余掩码数与平均熵,可看出困难位置是否堆到终点. 第三组加入可见位置复评估,分别允许单点重掩、固定窗口重掩与整块重掩.需要统计真实纠正次数:多少被撤回 token 原本错误,多少原本正确.只看最终分数会掩盖无效擦写. 第四组改变长度和块长.同一答案长度下比较纯全画布与块采样,再改变长度预测误差.这样能分清块结构的收益来自 KV、并行范围,还是 EOS 被限制在当前块.

最终才加入验证器与少步蒸馏.验证器提供外部信息,蒸馏改变模型权重,若过早混入,无法判断基础调度本身贡献.完整矩阵成本很高,至少应保证关键结论有一条只改变单因素的对照.

**7.35 为什么「越来越干净」不是逐步正确的保证**

前向噪声的干净程度由掩码数或转移时间定义.反向状态掩码越来越少,只说明形式上更完整,不说明语义错误越来越少.一个错误 token 取代掩码后,噪声指标下降,任务损失却可能上升. 理想精确反向过程保证最终边缘回到数据分布,并不要求单条随机轨迹的每一步都更接近特定参考答案.中间状态甚至没有唯一的「正确文本」解释.经验 argmax 轨迹更不能继承单调质量保证. 因此监控只画 mask ratio 会制造乐观印象.还要画参考可得时的 token 正确率、约束违反数、可见位置反悔分数和跨轮变化.开放生成没有参考时,至少可监控内部一致性与外部验证.

用户界面把中间状态展示成不断完善的句子,会强化「每轮都更好」的直觉.实际上某轮可能为了修正全局结构而暂时擦掉正确局部,也可能填满掩码后进入错误自洽状态.是否展示中间候选是交互选择,不是数学证明.

**7.36 与坐标下降的关系**

低置信揭开可以类比坐标更新:每轮选择一组位置,根据其余坐标更新取值.逐位置异步更新类似坐标下降,批量同步更新类似块坐标法.强耦合坐标同时更新时容易振荡或选出不一致组合. 这个类比只到算法直觉为止.普通坐标下降有明确目标函数,每次更新可保证目标不升;神经扩散采样通常没有可计算的全序列能量,边际 argmax 也不保证提高联合概率.若额外训练能量模型或残差评分器,才更接近有目标函数的局部优化.

坐标选择规则仍提供启发.最大残差优先对应重掩最不一致位置;随机坐标保留理论覆盖;按依赖分块对应块坐标更新;周期检测后改用异步顺序可抑制振荡.这些技巧是否有效要在生成任务上验证,不能直接搬用优化定理. 与 Gibbs 采样也类似:给定其余位置重采一个 token.真正 Gibbs 需要精确条件分布并持续更新,其平稳分布才有保证.扩散模型的条件分布带时间、训练近似与掩码状态,一次批量更新更不是标准 Gibbs.类比帮助理解,不提供无偏保证.

**7.37 证据能够支撑到哪里**

LLaDA Table 9 直接支撑同一设置下低置信 remask 的 GSM8K 明显优于随机策略.它说明位置选择极其重要,没有证明所有任务、所有模型都保持相同比例.规划和数学任务的中间 token 依赖强,差距可能格外大. Table 7–8 直接支撑同一权重换纯扩散、AR 或块采样会大幅改变结果,并显示 Base 与 Instruct 的最佳路径不同.关于 EOS padding 的解释来自论文设置与消融,仍应与模型突然获得新知识区分. MaskGIT 支撑置信度揭开的来源,MDLM 等工作支撑半自回归或 top-p 调度的具体实现.这些图像或语言模型共享 easy-first 思想,前向过程与任务分布并不完全相同.引用思想可以,数字不能跨论文移植.

Fast-dLLM、LLaDA 2.0 与后续推理工作支撑阈值、缓存近似和并行提交能提高有效吞吐.每个速度数字绑定硬件、块长、阈值、batch 与是否计入额外开销.它们证明存在可用配置,没有给出脱离条件的统一倍数. 关于高置信错误、联合冲突、振荡和校准的讨论来自概率结构与通用采样分析.除非论文提供相应消融,这些内容用于解释风险与设计实验,不能冒充某个模型已经观察到的定量结论.

**7.38 把一次生成轨迹完整记下来**

最终答案只显示采样终点,许多错误在中间已经暴露.调试时应保存每轮的时间、掩码图样、候选 token、置信度、被接受与被撤回的位置,以及外部约束结果.不必保存完整词表 logits,top-2 概率、熵与当前 token 概率通常足够定位调度问题. 若答案错在某个数字,沿轨迹回看可以区分三种情况:数字从第一次出现就高置信错误;早期正确,后来被重掩改错;一直低置信,末步被强制填入.第一种偏向模型或事实问题,第二种偏向回退规则,第三种偏向时间网格与停止预算.终点分数相同,修法完全不同. 轨迹还可以统计有效进展率

$$
g_k=\frac{\text{本轮新增且终点保留的正确 token 数}}
{\text{本轮网络前向成本}}.
$$

前期 $g_k$ 高、后期接近零,说明继续迭代收益很低;后期仍有大量撤回,说明轨迹尚未稳定.参考答案不可得时,可把「正确」替换为通过约束且最终保留,它仍是近似指标. 多随机种子的轨迹对比能发现路径依赖.若不同早期揭开顺序最终都到同一答案,采样较稳定;若一个早期 token 决定完全不同结局,调度器应对该位置更保守,或保留多个粒子.这类分析比只调一个全局阈值更能说明问题. 轨迹日志也让速度数字可解释.网络前向次数相同,一个策略可能反复生成又擦除大量 token,另一个策略每轮提交较少却几乎不返工.最终 tokens/s 只数保留下来的 token,返工率则揭示计算浪费在何处.对于真正允许重掩的系统,两项应一起报告.
