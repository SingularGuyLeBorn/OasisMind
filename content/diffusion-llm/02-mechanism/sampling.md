# 采样与调度：揭开、重掩、步数

训练只保证 $p_\theta(x_0^i\mid x_t)$ 在掩码位置上校准得像样。生成还要决定：当前这一步提交哪些位置、提交之后下一步的 $x_s$ 长什么样、一共走多少步。这三件事是推理超参，同一组权重换调度，GSM8K 可以差几十个点。LLaDA 附录 Table 9：随机 remask 21.3，低置信 remask 70.0，生成长度设定相同。

**图 1 解析**

- **两行同一份 $x_t$**：差别只在「盖回去哪两格」，网络权重没变。
- **上行 random remask**：按日程随机选择继续保持掩码的位置，不利用置信度。只有候选 token 和保留/重掩事件都按解析后验抽样时，才是严格的祖先采样；图中的 argmax 版本仍是近似实现。LLaDA Table 9 里随机策略的 GSM8K 为 21.3。
- **下行 low-conf remask**：盖 0.55 与 0.31，提交 0.92 与 0.88。同一设定下 GSM8K 70.0。
- **红叉不是实现细节**：它标记的是「已经尖的格子被随机策略埋掉」。下一步双向注意力就少两个可靠条件。
- **图里的 0.5 比例**对应 $\frac{s}{t}=0.5$ 时期望盖回一半掩码。真实日程按时间网格变，不是永远一半。
## 1. 反向一步在干什么

记当前掩码率为 $t$，下一步更干净的水平为 $s\in[0,t)$。网络看见 $x_t$（含提示），对仍是 `[MASK]` 的位置给出 $x_0$ 分布。严格的吸收态祖先采样先按该分布抽候选 token，再按解析反向后验独立决定每个位置在 $x_s$ 中继续掩码还是揭开；线性日程下，继续掩码的边际比例是 $s/t$。这个后验不按“谁更有信心”挑位置。

实践中的低置信、top-k、阈值和 argmax 解码使用同一日程控制数量，却根据模型置信度选择具体位置或用众数替代抽样。它们是经验启发式，不是精确反向后验；质量可能更好，但不能把所得样本当作严格祖先采样的无偏输出。

均匀时间网格把 $[0,1]$ 切成 $T$ 段，$t=1,1-1/T,\ldots$。$T$ 就是「网络前向次数」。$T=L$ 且每步只揭开一个位置时，步数退回和 AR 相同，只是揭开顺序不必从左到右。$T\ll L$ 时每步必须同时提交多个位置，这是吞吐来源，也是因子分解误差来源：一步里两个位置的预测只通过当前 $x_t$ 耦合，提交之后才变成彼此的上下文。

生成长度在纯扩散里是超参：一开始垫多少个 `[MASK]`。LLaDA 预训练和 SFT 都见过变长，附录说结果对这个超参不敏感。Instruct 版仍会因为 `[EOS]` 训练信号过强而提前结束，需要把 `[EOS]` 置信度置零。这不是日程的问题，是数据里垫结束符的问题。

五 token 的例子。当前 $x_t=(\mathrm{M},\mathrm{M},\text{明},\mathrm{M},\mathrm{M})$，$t=0.8$，下一步 $s=0.4$，则 $\frac{s}{t}=0.5$，四个掩码位置里期望盖回两个。网络对四个掩码位给出最大概率，比如 $0.92,0.55,0.88,0.31$。低置信策略盖回 $0.31$ 与 $0.55$ 那两格，提交 $0.92$ 与 $0.88$。随机策略可能盖回两个已经很尖的格。下一步 $x_s$ 里，「明」和两个新揭开的字成为双向上下文，继续猜剩下的掩码。动画里「逐步露出」就是这个循环，不是训练时的随机掩码。

## 2. 低置信 remask 为什么比随机强

按解析概率随机抽样是理论反向过程；常见的“先 argmax、再随机盖回固定数量”已经是它的近似。低置信策略进一步偏离后验：它把计算预算留给分布仍平的位置，避免随机埋掉尖锐预测。LLaDA 写明该策略借鉴 MaskGIT 的退火，不是由 ELBO 推导出来的。它在该评测上质量更高，说明实用解码器可以优于朴素近似，不说明启发式等于真实后验。

top-k / top-p 揭开是同一件事的另一种切法：每步固定提交 $k$ 个最尖的位置，或提交累积概率超过 $p$ 的集合。MDLM 的项目页和实现里有 top-p 掩码调度。阈值解码（LLaDA 2.0 主评测用 0.95）则是：概率超过阈值的位置本步提交，否则继续掩。阈值高则每步少提交、质量稳、TPF 低。2.0 在 mini 上扫过阈值和块大小，0.95 与块长 32 被选成主设定。

EB-Sampler 一类方法试图给「何时可以同时揭开多个位置」一个联合熵上界，避免只看边际置信度。这是在修因子分解误差，不是换模型。

## 3. 纯扩散、自回归、块扩散三种采样

LLaDA 的权重在预训练之后就可以用三种方式采样，不必再训。附录 Table 7–8 把这件事做了消融。

**纯扩散**：整段回答同时处于同一掩码日程，双向看见整句已揭开部分。Base 模型上 Humaneval 35.4，整体最好。

**自回归采样**：每步只揭开最左边的一个 `[MASK]`，等价于用双向模型做从左到右的生成。Base 上 Humaneval 掉到 18.3。Instruct 上若干生成任务直接崩到 0，因为 `[EOS]` 与定长垫片和「一次一个」冲突。

**块扩散采样**：把回答切成块。块与块之间从左到右；块内仍做掩码扩散。块长 $L'$ 是旋钮。$L'=32$ 时 Instruct 的 GSM8K 到 77.5，再把块长收到 8 可以到 78.6，高于纯扩散的 69.4。作者解释是 SFT 里大量 `[EOS]` padding 让纯扩散过早结束，块结构限制了结束符的传播。

同一组 8B 权重，采样器可以把它变成三种不同的模型。报数字必须写采样器。旧笔记把「扩散比 AR 快 2–8 倍」写在 LLaDA 名下，论文里没有这张速度表；速度要看 Mercury、LLaDA 2.0-CAP、Fast-dLLM 那些专门测吞吐的工作。

![同一组 LLaDA 权重采用纯扩散、自回归和块扩散三种采样路径](./images/fig-three-samplers.png)

> 图 2：同一组 8B 权重分出三条解码路径。纯扩散整段一个 $t$；AR 采样每次只揭最左边一个掩码；块采样块间因果、块内仍去噪。Instruct 的 GSM8K 分别落到 69.4、0、以及块长 32 / 8 的 77.5 / 78.6。

**图 2 解析**

- **same 8B weights**：检查点没变，变的是揭开顺序和结束符能不能跨格传播。
- **pure diffusion**：全画布同一掩码率，双向看见已揭开的左右。Instruct 纯扩散 GSM8K 69.4。
- **AR sampling**：每步只揭最左一个 `[MASK]`。SFT 垫进去的结束符和「一次一个」打架，若干生成任务掉到 0。
- **block remask**：块间从左到右，结束符停在块边界。块长 32 到 77.5，收到 8 到 78.6。
- **表是采样器的表**：附录 Table 8 证明分数跟着解码器走。报 Instruct 数字必须写这一列走的是哪条路径。

## 4. 步数–质量，以及「并行诅咒」

步数加多，反向更接近连续时间极限，质量通常上升，成本线性加。LLaDA Base 把生成长度和步数都设成 1024 去做 Humaneval 一类生成题，等于一步揭开约一个 token，放弃吞吐去换质量。产品侧的 Mercury 走另一端：粗到细并行改很多位置，用 H100 上四位数的 tokens/s 说话。

并行诅咒指的是：一步提交的位置越多，这些位置在提交前互相看不见对方的最终取值，搭配错误上升。缓解手段分三类。

解码侧：只提交高置信位置（Fast-dLLM、阈值解码）；用小 AR 或自身做验证（APD、自投机 SSD）；允许把已经落盘的字再变成 `[MASK]`（ReMDM）。后一件和本步低置信 remask 不是同一层，见[提交之后还能不能改](../03-points/remask-revise.md)。静态阈值之外还有动态 $S$：[SlowFast](../03-points/slowfast.md) 用终点方差决定何时从慢探切到快揭，15.63× 在 GPQA 长度 1024。

训练侧：dParallel 的 certainty-forcing 蒸馏让边际更快变尖；LLaDA 2.0 的 CAP 在已经预测对的位置上再压熵，提高 TPF。

结构侧：块扩散把并行范围限制在块内，块间有因果前缀，KV 可以缓存。这是下一篇知识点的主题。

## 5. 缓存：双向注意力默认没有 KV Cache

AR 的 KV Cache 成立，是因为位置 $i$ 的 Key/Value 在后续步骤里不再改变。全双向掩码扩散每揭开一些字，所有位置的注意力都可能变，严格 KV Cache 不成立。LLaDA 8B 因此不用 GQA。后来的 dKV-Cache、Fast-dLLM 做的是**近似**：延迟缓存、分块缓存、或只在已提交且不再改的位置上缓存。报「扩散也能 KV Cache」时，问的是近似还是块间因果。块扩散的块间部分是真缓存；块内仍要反复算。

## 6. 失效

$T$ 太小：一步揭开太多，出现前后矛盾、代码括号不配。$T$ 太大：吞吐掉回 AR，扩散的卖点消失。

阈值过低：平的分布也被提交，错误锁死。若不允许 remask，锁死无法挽回。Seed Diffusion 后 20% 的编辑腐蚀走另一条路：训练时就让已写的字再变脏，采样时才能改已经揭开的 token。那是改前向的一部分，不是把 Table 9 的低置信策略再拧紧一档。

生成长度短于答案：后面被截断。长度长于答案：靠 `[EOS]` 或后处理切。Instruct 数据若用 `[EOS]` 垫到固定长，纯扩散会学会「到处写结束符」。LLaDA 附录在 Humaneval、GSM8K 上把 `[EOS]` 置信度置零，就是在堵这条捷径。块采样用块边界拦住结束符往尚未生成的块传播，所以 Instruct 的 GSM8K 可以从纯扩散 69.4 走到块长 8 的 78.6。同一检查点，解码器比再训一遍更便宜。

把 AR 的温度、top-p 直接套在每步边际上：可以，但温度现在同时影响「揭开谁」和「揭成什么」，两个旋钮缠在一起。调采样先固定 remask 策略，再动温度。温度升高会让更多位置的 max probability 掉到阈值以下，于是阈值解码每步少提交，表面上变慢，质量未必变好。这和 AR 里「升温更随机、长度不变」不是同一件事。

下面伪代码是低置信、argmax 的启发式实现，只帮助把循环钉死；它不是严格反向后验的祖先采样器，也不是某个仓库的逐行实现。

```text
x ← [MASK] * L
for t in (1, 1-1/T, ..., 1/T):
    s ← t - 1/T
    logits ← f_θ(prompt, x)          # 双向，未掩位置可见
    conf ← max(softmax(logits), dim=-1)
    n_keep ← round((1 - s/t) * n_mask(x))
    submit ← topk(conf among MASK, n_keep)
    x[submit] ← argmax(logits[submit])
    # 其余 MASK 保持；本步低置信只盖尚未提交的预测，不是改已落盘明文
return strip_after_eos(x)
```

`n_keep` 随 $t$ 下降而增加，前面几步只敢提交很少位置，后面才大面积揭开。阈值解码把 `topk` 换成 `conf > τ`。块扩散在这块循环外再套一层：写完一块，把这块写入 KV，再初始化下一块的全掩码。

## 7. 读完检查

应能区分：训练的 $t$ 是掩码率随机变量；推理的 $T$ 是反向步数；$\frac{s}{t}$ 是本步要盖回去的比例。应能说出低置信 remask 在 LLaDA Table 9 上的差距，以及为什么 Instruct 的 GSM8K 在块采样下更高。下一篇用 BD3-LM 把「块」从采样技巧升级成模型定义。

开源模型和商业模型报速度时，分母经常不一样。有的 tokens/s 含 prefill，有的只算 decode；有的 batch=1 延迟优化，有的 batch=4 吞吐优化。Mercury Mini 的 1109 tokens/s 来自 Artificial Analysis 在 H100 上的第三方评测；LLaDA 2.0-flash-CAP 的 535 TPS 来自作者用 dInfer 对 SGLang 上 AR 基线的对照。两套数字不能减出「谁快一倍」。本篇只负责把 $T$、阈值、块长这些旋钮讲清楚，让后面读速度表时知道作者拧过哪些。

步数 $T$ 和序列长度 $n$ 解耦之后，产品上会出现一种新的调参习惯：同一句回答，可以先用很小的 $T$ 出草稿，再加步数打磨。Dream 在 Countdown 上把步数扫到 5–20 仍能优于同尺寸 AR，靠的是规划题短、约束密。写长文档时，少步意味着一步揭开太多格子，括号和指代更容易对不齐。并行诅咒不是口号，是「提交前互相看不见最终取值」这句话的直接推论。缓解手段里，低置信 remask 最便宜，因为它不改权重；dParallel 那种 certainty-forcing 要蒸馏；块扩散则是改结构，把并行范围关进块内。选型时先问能不能改解码器，再问能不能再训。

阈值解码把「每步揭开多少」从比例改成绝对值。0.95 意味着只有非常尖的格子本步提交，其余继续掩。TPF（tokens per forward）随之下降，质量通常更稳。LLaDA 2.0 主评测钉在 0.95 与块长 32，是他们扫过之后的折中，不是定理。阈值再高，模型每步几乎只敢揭一个格子，吞吐退回 AR，扩散卖点消失。阈值再低，平的分布也被提交，错误锁死。两条边界都见过事故，所以阈值是要跟任务一起拧的旋钮，不是设一次永远正确。

伪代码里的 `argmax` 还可以换成按分布抽样。argmax 让同一种子更稳，抽样让多样性回来，也让低置信策略看到的「尖」变成随机尖。评 Humaneval 这类要过测试的题，主表常用 argmax 或很低的温度。写故事时可以抽样。温度、是否 argmax、remask 策略三者会缠在一起，调参一次只动一个。LLaDA Table 9 已经证明 remask 单独就能把 GSM8K 从 21.3 拉到 70.0；先锁这一项，再动温度，否则你不知道是哪一个旋钮救了分数。

生成长度在纯扩散里是画布，不是「写到 EOS 停」。画布太短，答案被截断，看起来像模型不会做；画布太长，模型在空白处堆结束符或胡写。LLaDA 说 Base 对长度不敏感，Table 10 支持这句；Instruct 不支持这句，因为 SFT 把 EOS 垫进固定长。产品若用 Instruct 权重，长度和 EOS 置零要一起调。块扩散把画布改成「再开一块」，可变长回来，EOS 传播被块边界拦住。这是 Instruct 的 GSM8K 从 69.4 走到 78.6 的机制解释，不是模型突然更会算术。

并行揭开和投机解码不要混名。投机解码有草稿和验证器，拒绝可以回滚。扩散的阈值揭开没有验证器，错了除非 remask 否则锁死。Fast-dLLM 的并行提交同样是边际启发式。真正带验证的 APD、SSD 要单独算进延迟，不能算进「训练免费加速」的倍数里。读加速论文的第一问是：错了能不能改，改的代价算不算进吞吐。

低置信 remask 从 MaskGIT 来，不是从 ELBO 来。严格祖先采样按解析后验抽样；argmax 后随机盖回是近似；按置信度盖回则是更强的启发式。三者必须分名。EB-Sampler 一类方法尝试给“何时可以同时揭开”增加联合熵保证。实践上仍常先用低置信或阈值，失败后再上更贵的验证；图 1 只解释这项启发式为什么可能有效。

块采样在 Instruct 上救 GSM8K，在 Base 上却不是最强。Table 7 里 Base 纯扩散整体最好。SFT 的 EOS 垫片改变了哪种解码器匹配训练分布。同一套揭开逻辑，权重从 Base 换成 Instruct，最优采样器跟着变。产品若先 SFT 再部署，不要抄 Base 附录的「纯扩散最好」当默认。先在自己的 Instruct 检查点上扫 Table 8 那四行，再锁采样器。

伪代码末尾的 `strip_after_eos` 假设结束符出现之后的内容无意义。Instruct 若把 EOS 垫到画布末尾当普通 token 训过，模型可能在中间就写出结束符，后面仍是掩码。置零 EOS 置信度是补丁，块边界是结构补丁。两个补丁都在堵同一件事：结束符抢了还没写完的格子。调采样时若只动温度不动这两项，Instruct 生成任务会反复提前结束。

图 2 把「分数是采样器的」画成三条路，调参时可以按这张图排优先级。先锁 remask：Table 9 已经证明随机盖回能把 GSM8K 从 70.0 打到 21.3，这一刀比温度更狠。再锁解码器身份：Instruct 权重不要默认走 AR 采样，图 2 中间那列会归零。然后才扫 $T$、阈值、温度。一次动三个旋钮，你不知道是哪一个救了分数。Base 和 Instruct 的最优解码器还可能相反：Table 7 里 Base 纯扩散整体最好，Instruct 却吃块结构。换检查点等于换图 2 该走哪一列。

步数 $T$ 与长度 $n$ 解耦之后，少步不是免费的。$T=8$ 且 $n=256$ 意味着每步大约提交几十个位置，这些位置在提交前只通过当前 $x_t$ 耦合。括号、指代、数独盘上的重复数字，都会在这一步里按边际各自做决定。低置信 remask 把还平的格子留到下一步，等于用更多前向去买联合信息。阈值 0.95 更狠：不够尖就不提交。两种策略都在承认同一句话：一步多 token 的联合不是网络直接输出的对象，输出的是边际。采样器的工作是决定哪些边际现在可信。

和投机解码的差别再钉一次。投机有草稿和验证器，拒绝可以回滚，延迟账单含验证。扩散的阈值揭开没有验证器，错了除非 remask 否则锁死。Fast-dLLM 的并行提交同样是边际启发式。真正带验证的 APD、SSD 要单独算进延迟，不能算进「训练免费加速」的倍数里。读加速论文的第一问是：错了能不能改，改的代价算不算进吞吐。图 2 三条路都没有验证器；验证是另一张图。
