# 采样与调度：揭开、重掩、步数

训练只保证 $p_\theta(x_0^i\mid x_t)$ 在掩码位置上校准得像样。生成还要决定：当前这一步提交哪些位置、提交之后下一步的 $x_s$ 长什么样、一共走多少步。这三件事是推理超参，同一组权重换调度，GSM8K 可以差几十个点。LLaDA 附录 Table 9：随机 remask 21.3，低置信 remask 70.0，生成长度设定相同。

本篇假定已经读过掩码扩散的式 (1)。动画仍用同一则 MaskedDiffusion，只是现在可以对照文字看「每步揭开的是高置信位置」。

## 1. 反向一步在干什么

记当前掩码率为 $t$，下一步更干净的水平为 $s\in[0,t)$。网络看见 $x_t$（含提示），对所有仍是 `[MASK]` 的位置给出词表分布。理论上，吸收态的反向后验要求：期望意义上把 $\frac{s}{t}$ 比例的预测再掩回去，使得 $x_s$ 的掩码率和前向在时间 $s$ 时一致。其余位置写入 $\arg\max$ 或按分布抽样的 token。

均匀时间网格把 $[0,1]$ 切成 $T$ 段，$t=1,1-1/T,\ldots$。$T$ 就是「网络前向次数」。$T=L$ 且每步只揭开一个位置时，步数退回和 AR 相同，只是揭开顺序不必从左到右。$T\ll L$ 时每步必须同时提交多个位置，这是吞吐来源，也是因子分解误差来源：一步里两个位置的预测只通过当前 $x_t$ 耦合，提交之后才变成彼此的上下文。

生成长度在纯扩散里是超参：一开始垫多少个 `[MASK]`。LLaDA 预训练和 SFT 都见过变长，附录说结果对这个超参不敏感。Instruct 版仍会因为 `[EOS]` 训练信号过强而提前结束，需要把 `[EOS]` 置信度置零。这不是日程的问题，是数据里垫结束符的问题。

五 token 的例子。当前 $x_t=(\mathrm{M},\mathrm{M},\text{明},\mathrm{M},\mathrm{M})$，$t=0.8$，下一步 $s=0.4$，则 $\frac{s}{t}=0.5$，四个掩码位置里期望盖回两个。网络对四个掩码位给出最大概率，比如 $0.92,0.55,0.88,0.31$。低置信策略盖回 $0.31$ 与 $0.55$ 那两格，提交 $0.92$ 与 $0.88$。随机策略可能盖回两个已经很尖的格。下一步 $x_s$ 里，「明」和两个新揭开的字成为双向上下文，继续猜剩下的掩码。动画里「逐步露出」就是这个循环，不是训练时的随机掩码。

## 2. 低置信 remask 为什么比随机强

随机 remask 忠实于前向后验，理论上更「对」。生成质量却差。原因是 $p_\theta$ 在不同位置上的校准不一样：有的位置上下文已经足够、分布很尖；有的位置还在几个近义词之间平。随机盖回去会把已经尖的位置浪费掉，同时放过仍然平的位置。低置信策略把概率质量最低的那些预测盖回去，等于把计算预算留给还没想清楚的格子。LLaDA 写明这是借鉴 MaskGIT 的退火，不是 ELBO 推导出来的。

top-k / top-p 揭开是同一件事的另一种切法：每步固定提交 $k$ 个最尖的位置，或提交累积概率超过 $p$ 的集合。MDLM 的项目页和实现里有 top-p 掩码调度。阈值解码（LLaDA 2.0 主评测用 0.95）则是：概率超过阈值的位置本步提交，否则继续掩。阈值高则每步少提交、质量稳、TPF 低。2.0 在 mini 上扫过阈值和块大小，0.95 与块长 32 被选成主设定。

EB-Sampler 一类方法试图给「何时可以同时揭开多个位置」一个联合熵上界，避免只看边际置信度。这是在修因子分解误差，不是换模型。

## 3. 纯扩散、自回归、块扩散三种采样

LLaDA 的权重在预训练之后就可以用三种方式采样，不必再训。附录 Table 7–8 把这件事做了消融。

**纯扩散**：整段回答同时处于同一掩码日程，双向看见整句已揭开部分。Base 模型上 Humaneval 35.4，整体最好。

**自回归采样**：每步只揭开最左边的一个 `[MASK]`，等价于用双向模型做从左到右的生成。Base 上 Humaneval 掉到 18.3。Instruct 上若干生成任务直接崩到 0，因为 `[EOS]` 与定长垫片和「一次一个」冲突。

**块扩散采样**：把回答切成块。块与块之间从左到右；块内仍做掩码扩散。块长 $L'$ 是旋钮。$L'=32$ 时 Instruct 的 GSM8K 到 77.5，再把块长收到 8 可以到 78.6，高于纯扩散的 69.4。作者解释是 SFT 里大量 `[EOS]` padding 让纯扩散过早结束，块结构限制了结束符的传播。

同一组 8B 权重，采样器可以把它变成三种不同的模型。报数字必须写采样器。旧笔记把「扩散比 AR 快 2–8 倍」写在 LLaDA 名下，论文里没有这张速度表；速度要看 Mercury、LLaDA 2.0-CAP、Fast-dLLM 那些专门测吞吐的工作。

## 4. 步数–质量，以及「并行诅咒」

步数加多，反向更接近连续时间极限，质量通常上升，成本线性加。LLaDA Base 把生成长度和步数都设成 1024 去做 Humaneval 一类生成题，等于一步揭开约一个 token，放弃吞吐去换质量。产品侧的 Mercury 走另一端：粗到细并行改很多位置，用 H100 上四位数的 tokens/s 说话。

并行诅咒指的是：一步提交的位置越多，这些位置在提交前互相看不见对方的最终取值，搭配错误上升。缓解手段分三类。

解码侧：只提交高置信位置（Fast-dLLM、阈值解码）；用小 AR 或自身做验证（APD、自投机 SSD）；允许下一步把错字掩回去（ReMDM）。

训练侧：dParallel 的 certainty-forcing 蒸馏让边际更快变尖；LLaDA 2.0 的 CAP 在已经预测对的位置上再压熵，提高 TPF。

结构侧：块扩散把并行范围限制在块内，块间有因果前缀，KV 可以缓存。这是下一篇知识点的主题。

## 5. 缓存：双向注意力默认没有 KV Cache

AR 的 KV Cache 成立，是因为位置 $i$ 的 Key/Value 在后续步骤里不再改变。全双向掩码扩散每揭开一些字，所有位置的注意力都可能变，严格 KV Cache 不成立。LLaDA 8B 因此不用 GQA。后来的 dKV-Cache、Fast-dLLM 做的是**近似**：延迟缓存、分块缓存、或只在已提交且不再改的位置上缓存。报「扩散也能 KV Cache」时，问的是近似还是块间因果。块扩散的块间部分是真缓存；块内仍要反复算。

## 6. 失效

$T$ 太小：一步揭开太多，出现前后矛盾、代码括号不配。$T$ 太大：吞吐掉回 AR，扩散的卖点消失。

阈值过低：平的分布也被提交，错误锁死。若不允许 remask，锁死无法挽回。

生成长度短于答案：后面被截断。长度长于答案：靠 `[EOS]` 或后处理切。Instruct 数据若用 `[EOS]` 垫到固定长，纯扩散会学会「到处写结束符」。

把 AR 的温度、top-p 直接套在每步边际上：可以，但温度现在同时影响「揭开谁」和「揭成什么」，两个旋钮缠在一起。调采样先固定 remask 策略，再动温度。

伪代码只帮助把循环钉死，不是某个仓库的实现。

```text
x ← [MASK] * L
for t in (1, 1-1/T, ..., 1/T):
    s ← t - 1/T
    logits ← f_θ(prompt, x)          # 双向，未掩位置可见
    conf ← max(softmax(logits), dim=-1)
    n_keep ← round((1 - s/t) * n_mask(x))
    submit ← topk(conf among MASK, n_keep)
    x[submit] ← argmax(logits[submit])
    # 其余 MASK 保持；可选：低置信已揭开位置再掩回去
return strip_after_eos(x)
```

`n_keep` 随 $t$ 下降而增加，前面几步只敢提交很少位置，后面才大面积揭开。阈值解码把 `topk` 换成 `conf > τ`。块扩散在这块循环外再套一层：写完一块，把这块写入 KV，再初始化下一块的全掩码。

## 7. 读完检查

应能区分：训练的 $t$ 是掩码率随机变量；推理的 $T$ 是反向步数；$\frac{s}{t}$ 是本步要盖回去的比例。应能说出低置信 remask 在 LLaDA Table 9 上的差距，以及为什么 Instruct 的 GSM8K 在块采样下更高。下一篇用 BD3-LM 把「块」从采样技巧升级成模型定义。

开源模型和商业模型报速度时，分母经常不一样。有的 tokens/s 含 prefill，有的只算 decode；有的 batch=1 延迟优化，有的 batch=4 吞吐优化。Mercury Mini 的 1109 tokens/s 来自 Artificial Analysis 在 H100 上的第三方评测；LLaDA 2.0-flash-CAP 的 535 TPS 来自作者用 dInfer 对 SGLang 上 AR 基线的对照。两套数字不能减出「谁快一倍」。本篇只负责把 $T$、阈值、块长这些旋钮讲清楚，让后面读速度表时知道作者拧过哪些。
