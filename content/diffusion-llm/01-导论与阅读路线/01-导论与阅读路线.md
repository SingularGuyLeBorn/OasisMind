# 扩散语言模型:导论与阅读路线

语言生成长期由自回归条件链主导，因为 next-token prediction 的训练目标直接、似然可计算，因果注意力又能配合 KV Cache 增量解码。扩散语言模型保留 Transformer 的表示能力，却把生成改写为多轮去噪：多个未知位置可以在一次前向中同时得到候选，后续步骤继续修订。这个变化首先是概率与状态定义的变化，速度、可控性和双向推理是需要分别验证的结果。

本章建立进入该领域所需的坐标。读者先比较自回归与扩散各自提交答案的方式，再区分连续嵌入扩散、离散词表扩散和掩码吸收态。随后把机制承诺、论文实验和当前工程实现分开。这样阅读模型报告时，吞吐不会被误写成数学性质，某个采样器的失败也不会被扩大成整个范式的失败。

## 先建立三条边界

1. **机制边界**:自回归模型固定按条件链逐步提交;扩散语言模型在一条噪声—数据路径上反复修订多个位置.两者都能使用 Transformer,但概率因式分解,训练目标和缓存条件不同.
2. **证据边界**:论文表格只证明指定模型,采样器,长度,批量,硬件和实现下的结果.NFE,token/s,首 token 延迟和端到端延迟不是同一指标.
3. **版本边界**:2025–2026 年许多工作仍是预印本或单一代码库结果.正文会给出版本与核验日期,不把作者主张写成领域共识.

## 自回归参照系

自回归模型把联合概率分解为从左到右的条件概率乘积。第 $i$ 个 token 依赖前面已经提交的 $i-1$ 个 token，因此生成长度为 $L$ 的序列至少经历 $L$ 次顺序决策。KV Cache 避免重复计算旧位置的 key 和 value，使每一步只处理新增 token；成熟的 continuous batching、量化与投机解码又继续降低服务成本。这些能力构成扩散系统必须面对的工程基线。

顺序提交也带来明确边界。后面的证据无法修改前面已经输出的 token；固定全局约束往往要通过搜索、拒绝采样或外部校验实现；训练时常见的 teacher forcing 与推理时使用自身历史之间存在分布差异。这些边界并不说明自回归模型不能处理对应任务，而是说明额外能力通过何种机制获得。

## 去噪生成改变的状态

掩码扩散把序列状态写成干净 token 与未知标记的组合。前向过程按时间 $t$ 增加掩码比例，反向模型在给定 $x_t$ 与时间条件下预测原始 token。一次前向可以为多个掩码位置给出分布；采样器决定哪些预测在本步提交、哪些继续保持未知，以及是否把低置信位置重新掩码。生成顺序因此成为调度结果，而不是固定的从左到右规则。

并行位置通常由因子化输出头分别预测。若两个位置存在强联合约束，各自边缘概率很高的 token 组合起来仍可能冲突，这就是联合依赖问题。增加去噪步数可以逐步传递信息，块扩散可以限制同时生成的范围，能量修正或规划器可以直接建模位置间耦合。第 04 章集中处理这些结构选择。

## 三类结论分别核验

机制结论来自模型定义，例如吸收态把被腐蚀位置变成可观察事件，双向注意力允许同一步中的未知位置共享上下文。实验结论来自具体检查点和协议，例如某个 7B 模型在指定基准上的准确率。系统结论则依赖采样步数、内核、缓存、batch 与硬件。三类结论使用不同证据，不能从其中一类直接推出另外两类。

比较速度时至少记录 NFE、单次前向处理的序列长度、每步提交 token 数和端到端延迟。扩散模型即使每步提交多个 token，也可能因全序列重复计算而失去优势；自回归模型即使顺序生成，也可能凭借缓存和优化内核取得更高吞吐。比较质量时还要固定提示、解码预算与模型阶段，避免把训练数据差异解释为生成机制差异。

另一个必要区分是“可修订”与“已经修正”。扩散轨迹允许位置在后续步骤改变，这只提供纠错通道；模型是否识别错误、调度器是否愿意重掩、剩余步数是否足够，仍由训练与采样共同决定。相同道理，双向注意力提供左右文可见性，却不自动消除反转任务或长程推理错误。机制给出可用的信息通路，实验才说明模型是否学会利用。

版本记录也属于阅读方法。同一家族可能从全双向扩散改为块扩散，从头训练改为自回归权重迁移，或替换采样器而保留检查点。名称相近不代表概率模型相同。页面引用模型时会同时写版本、训练起点与解码方式；若论文只公开接口或演示，正文会把未知参数留空，不从吞吐或基准分数反推隐藏结构。

这种记录方式也便于后续复现和更新。
