# 分层评测与自动评审

## 1. 数据集先固定任务口径

样本包含问题、用户与时间条件、参考证据、可接受答案和预期失败状态. 多份等价证据应全部允许, 否则检索到正确替代来源会被误判. 数据按文档族或时间切分, 防止相邻片段泄漏.

### 1.1. 样本覆盖

问题集覆盖精确实体、数字、否定、多跳、时间、表格、无答案、冲突和权限边界. 真实查询分布决定权重, 风险样本另设门槛.

### 1.2. 数据集版本

参考证据随语料更新, 因而评测集记录语料快照. 过期样本可以迁移到历史任务, 不能静默替换答案后继续与旧分数比较.

## 2. 分层指标

### 2.1. 检索和排序

recall@k 判断至少一份目标证据是否进入候选, MRR 关注首个目标位置, nDCG 允许多级相关标签. 多跳任务还需测证据集合覆盖, 单篇命中不足以完成问题.

### 2.2. 生成和引用

答案正确性与忠实性分开. 忠实性判断命题能否由给定证据支持. 引用再分为可解析、对应正确和重要命题覆盖. 拒答使用精确率、召回率或风险加权成本校准.

**端到端分数只能概括结果, 分层指标才负责定位原因.**

## 3. 自动评审

### 3.1. 评审提示与输出

评审器接收明确标准、问题、证据和答案, 输出结构化标签及理由. 不让评审器使用自身知识补全证据, 忠实性判断只依据提供材料.

### 3.2. 人工校准

抽取各问题类型和分数边界样本由人工双标, 计算评审器的一致性、偏差和稳定性. 更换评审模型或提示后重新校准.

自动评审适合回归与大规模筛查, 不能取代高风险样本和新错误类型的人工检查. 评审分歧本身可成为误差分析样本.

## 4. 实验解释

### 4.1. 置信区间

对样本重采样估计指标区间, 避免把小幅随机波动当成提升. 生成具有随机性时, 对关键样本多次运行或固定解码设置.

### 4.2. 切片与回归

总体指标按问题属性、来源、语言和风险切片. 每次线上错误加入回归集, 并标明责任层. 新版本必须同时通过总体与关键切片门槛.

评测最终服务于决策: 是否发布、哪一层继续优化以及增加的质量是否值得延迟和成本.


检索器已经找到正确文档, 回答仍可能错. 模型可能忽略限定条件, 混合两个版本, 使用参数记忆补出证据中没有的数字, 或者给一条相关但不支持结论的引用. 因此生成阶段不能只要求「根据上下文回答」. 输入需要成为可定位的证据包, 输出需要拆成可核验命题, 无法得到充分支持时还要进入拒答或澄清分支.

设最终证据集合为 $E$, 回答为 $y$, 将回答拆成原子命题 $a_1,\ldots,a_m$. 引用映射 $A(a_i)$ 指向支持该命题的证据. 生成质量至少包含三层: 回答是否完成用户任务, 每个事实命题是否被证据蕴含, 重要命题是否都有引用. **「有引用」只说明输出包含链接, 不能推出引用正确或覆盖完整.**

### 证据化生成

证据包包含请求内 ID、来源身份、版本、位置、有效时间和正文. 请求内 ID 让模型输出稳定引用标记, 服务端再将标记解析为真实链接. 由服务端提供位置可以避免模型编造页码和 URL. 输入前还应做确定性检查: 权限是否有效, 文档是否仍在当前快照, 内容是否超过长度限制, 同一来源是否重复.

上下文顺序和格式会影响模型使用证据. 对长文档, 可以先抽取与查询有关的最小支持区间, 再保留邻接条件;对表格与结构化查询, 要保留字段、单位、时间和查询快照. 自动摘要只能作为派生表示, 关键结论仍应回到原始证据. 若多个当前来源冲突, 输入应保留来源差异, 输出说明冲突并降低确定性.

### 引用与拒答

引用有效性检查标记能否解析到当前证据;引用正确性检查证据是否支持相邻命题;引用覆盖检查重要外部事实是否都有支持. 可以构造命题—证据矩阵 $M$, 其中 $M_{ij}=1$ 表示证据 $e_j$ 支持命题 $a_i$. 加权覆盖率为:

$$
\operatorname{Coverage}=\frac{\sum_iw_i\mathbf 1[\sum_jM_{ij}>0]}{\sum_iw_i}.
$$

$w_i$ 表示命题重要性. 数字、结论和行动建议可以赋更高权重. 支持关系可以由人工、NLI 或 LLM judge 判断, 自动评估器自身也要在人工样本上校准.

拒答至少区分证据不存在、证据不足、来源冲突、权限不足和请求不清. 单一相似度阈值无法承担这些原因, 因为稠密相似度不是正确概率. 评测集同时包含可答与不可答问题, 阈值通过风险—覆盖曲线选择. 只在不可答集提高拒答率, 可能让系统对正常问题也过度保守.

### 自适应检索与训练

固定检索每次都取相同数量片段, 对纯写作和简单常识浪费成本, 对多跳问题又可能不够. Self-RAG 训练模型生成 reflection tokens, 控制是否检索并评价证据相关性、回答支持度和效用. 推理时这些信号参与路径选择. 它把检索调用变成模型决策, 同时增加训练数据构造和特殊 token 监督.

RAFT 在训练样本中提供问题、oracle 文档和干扰文档, 让模型学习识别有用证据并生成带依据的回答. 训练时见过检索噪声, 可以改善模型面对候选集合时的使用方式. 它不替代线上召回: oracle 从未进入候选时, 生成器没有依据可用. 训练集还要避免答案直接泄漏在模板位置.

检索器训练常用对比目标. 对查询 $q$, 正文档 $d^+$ 与负样本集合 $D^-$, 一种损失为:

$$
L_{\text{ret}}=-\log\frac{\exp s(q,d^+)}{\exp s(q,d^+)+\sum_{d^-\in D^-}\exp s(q,d^-)}.
$$

难负样本来自当前检索器高排但不支持答案的文档. 同实体不同版本、数值接近和否定相反比随机负样本更能训练决策边界. 在线反馈不能把点击直接当相关性, 位置偏差、界面和既有排序都会影响点击.

### 分层评测

语料层测解析成功率、索引新鲜度、删除残留和权限;检索层测 Recall@k、MRR、nDCG 与集合覆盖;上下文层测证据覆盖、冗余和 token;生成层测答案正确、命题支持、引用正确与拒答;系统层测延迟、成本、错误率和可用性. 每次变更先确定作用层, 再选择主指标和保护指标.

RAGAS 等框架提出 context relevance、faithfulness 和 answer relevance 等自动指标, 可以缩短迭代周期. 自动 judge 对提示、模型和领域敏感, 不能替代人工校准集. BEIR 适合测试检索器跨数据集泛化, 私有业务仍需自己的查询分布、权限和时效样本. KILT 把知识密集任务与来源 provenance 联合评测, 提供了答案与证据共同验收的思路.

### 线上运行

请求 trace 应保存查询及改写、语料与索引版本、各路候选、融合重排、最终上下文、模型与提示版本、输出、引用和拒答原因. 敏感正文可以保存受控快照引用而非明文. 一次错误发生后, trace 要能回答证据在哪一层消失或被误用.

发布采用硬门、回归门与预算门. 权限泄漏和删除残留是硬门;检索、引用与拒答不能低于回归阈值;P95/P99 延迟、token 和调用成本不能超过预算. 回滚对象包括语料快照、索引、embedding、重排器、生成模型、提示和缓存. 只回滚一个组件可能无法恢复旧行为.

间接提示注入是 RAG 特有的重要风险之一: 检索文档可能包含要求模型泄露信息或调用工具的指令. 外部文档作为数据处理, 不获得系统指令权限;生成与工具执行分离, 动作继续经过 schema、权限和审批. 语料投毒、排序操纵与恶意引用也需要独立测试.

### 阅读落点

证据化生成、自适应训练与评测 将命题支持、Self-RAG、RAFT 和分层发布连成完整闭环. 后续扩展时, 引用验证、拒答校准可以形成生成路线下的叶子;Self-RAG、CRAG、RAFT 等方法进入训练与控制路线;评测与运维保留独立路线. 三者共享证据身份和请求 trace, 但目标函数不同.

判断新方法位置时, 看它主要改变哪一个变量. 改检索时机属于控制策略, 改检索器损失属于检索训练, 改证据判别属于选择或 verifier, 改引用解码属于生成约束, 改线上反馈闭环属于自适应. 这种归类能容纳新论文, 不需要按新缩写继续增加顶级章节.

### 三条路线怎样衔接

生成与引用路线接收已经选好的证据包, 输出回答、命题与引用映射. 训练与自适应路线可以改变生成器怎样使用证据, 也可以让控制器决定是否继续检索. 评测与运维路线保存每一步状态, 为训练数据和发布判断提供反馈. 三条路线共享语料、索引和请求 trace 这些线上权威状态.

一次失败若来自证据缺失, 训练生成器并不能补回文档;若证据完整而回答误读, 扩大 top-k 反而可能增加噪声;若离线指标正常但线上长尾超时, 应检查调用路径与容量. 按层归因让反馈进入正确数据集, 避免所有错误都被送进一次微调.

自适应控制增加分支后, 每条路径都要可回放. 系统记录触发检索的信号、候选评价、继续或停止原因以及预算. 固定候选可比较控制器, 固定控制动作可比较检索器, 固定证据可比较生成器. 这种实验分解与静态 RAG 使用同一套对象.

#### 2. 评测清单必须可重建

每次评测保存一份 manifest:

```text
evaluation_id
corpus_snapshot + permission_snapshot
query_set_version + split_policy

```

只保存 notebook 中的一张平均分表,无法判断分数变化来自模型,语料,标注,judge 还是缓存.


#### 3. 五层评测

#### 3.1 语料与索引层

| 指标/检查 | 回答的问题 |
|---|---|
| 摄取成功,隔离与解析错误率 | 哪些来源没有进入可用语料 |
| 片段可逆定位率 | 引用能否回到固定源位置 |
| 当前版本覆盖,孤儿片段数 | 新旧版本和删除是否一致 |
| 索引新鲜度分布 | 源变更多久后可查询 |
| ACL/租户继承正确率 | 片段是否保留源权限 |
| 重复与近重复率 | 候选是否被同一内容挤占 |

权限错误,依法删除后仍可检索,跨租户泄漏应作为零容忍发布门,而不是与回答质量求加权平均.

#### 3.2 检索与排序层

若黄金相关集合为 $G_q$,前 $k$ 个结果为 $R_k(q)$:

$$
\operatorname{Recall@k}(q)=\frac{|G_q\cap R_k(q)|}{|G_q|}.
$$

该式只在 $|G_q|>0$ 时有定义.对黄金证据集合为空的无证据查询,不计算普通 Recall;应单独测错误召回,错误作答,正确拒答和空结果行为.汇总报告必须说明是否跳过无相关项,采用何种宏/微平均,并按可回答性分组,不能静默除零或丢样本.

"前 $k$ 至少命中一条"的比例是 hit rate / success@k,不要与多相关文档的 Recall 混用.MRR 关注第一个相关结果;nDCG@k 适合多等级相关性;多跳和比较还要测必需证据集合 coverage.指标选择见检索,重排与索引.

BEIR 提供多领域检索数据和统一评测代码,适合外部分布压力测试;官方仓库也明确不为每个数据集的质量,公平性或许可背书,使用者仍要核对来源.公共 benchmark 不能替代生产查询,私有语言,ACL 和时间分布.[BEIR 官方仓库](https://github.com/beir-cellar/beir)

#### 3.3 上下文层

测最终送给模型的序列,而不只测重排列表:

- 必需证据覆盖率;
- 无关 token 比例与重复证据率;
- 关键证据被截断/位置变化率;
- 来源,版本,日期,单位和实体消歧保留率;
- 被拒绝或无权候选是否完全不在上下文;
- 序列化后 token,构造耗时和压缩信息损失.

#### 3.4 生成,引用与拒答层

至少分开报告:

- 任务答案指标:exact match,F1,数值误差,结构化字段正确率或人工 rubric;
- 命题支持:答案中的原子命题是否被证据蕴含;
- 引用有效,正确,完整;
- 冲突是否披露;
- 可回答/不可回答的拒答混淆矩阵;
- 敏感信息,越权存在性和不安全输出率.

ALCE 提出了端到端自动引用评测基准;RAGAS 提供自动化的上下文与 faithfulness 类指标.两者都不是生产系统的统一总分标准.[ALCE](https://arxiv.org/abs/2305.14627);[RAGAS](https://arxiv.org/abs/2309.15217)

#### 3.5 系统层

- 端到端成功率,P50/P95/P99 延迟和超时;
- 每阶段耗时,token,模型调用,缓存命中,索引扫描和成本;
- 降级,重试,熔断,失败关闭与回滚成功率;
- 并发下的吞吐,队列,内存和索引构建影响;
- 新鲜度,可用性与质量目标之间的联合表现.

只报告平均延迟会掩盖重排长文档,过滤高选择性和依赖超时造成的长尾.


#### 4. 数据集与标注设计

#### 4.1 查询来源

组合:匿名化真实分布,专家构造的关键业务用例,历史失败,长尾与对抗样本.真实日志不能直接当黄金答案;它可能包含隐私,错误反馈和旧版本语料.

#### 4.2 必备切片

- 高频/低频,短/长,单跳/多跳;
- 实体,错误码,数字,否定,时间范围与多语言;
- 可回答,部分证据,无证据,冲突,过期与撤回;
- 每个租户/角色与权限变更;
- 解析弱项:扫描 PDF,表格,代码,网页噪声;
- 检索内容含恶意指令,隐藏文字,恶意链接和重复投毒;
- PII/敏感字段输出,跨租户存在性,日志/trace/评测集/导出泄漏与删除传播;
- 分布外问题与系统依赖失败.

#### 4.3 防止泄漏

- 调参集与最终测试集分离;
- 时间切分避免同一文档版本跨集合;
- 近重复查询和片段按逻辑来源分组;
- prompt,reranker 或 judge 不得根据测试答案持续手工优化;
- 保留独立安全集,写入/检索管线不能读取预期攻击答案.

#### 4.4 标注质量

关键样本至少双人标注并记录分歧.相关性,证据支持,来源权威,答案正确与风险等级是不同标签,不能由一个"好/坏"代替.新语料版本可能让旧黄金答案失效,需要保留 `valid_as_of` 并重新裁决.


#### 5. 自动 judge 的使用边界

LLM judge 能扩展命题拆分,支持判定和风格检查,但会受提示,模型版本,答案长度,措辞和位置影响.使用时:

1. 固定 judge 模型快照,提示与解码;
2. 用人工黄金集测准确率和分组偏差;
3. 保留"不确定/需人工"而非强制二元判断;
4. 对系统版本做盲化和随机顺序,避免位置偏差;
5. 报告 judge 与人工的混淆矩阵,不只报相关系数;
6. judge 变化后重算历史基线,不能把评分器变化当系统提升.

自动 faithfulness 主要回答"答案是否被给定上下文支持",不回答来源是否真实,授权或最新.

#### 13. 指标切片与置信区间

#### 13.1. 总平均会隐藏哪些问题

查询按实体、数字、否定、时间、多语言、多跳、长文档和无答案切片. 若新 embedding 提高释义问题却降低型号检索, 总 Recall 可能仍上升. 发布判定要保护关键切片, 尤其是权限、时效和高风险业务. 切片定义进入评测版本, 不能每次实验临时改变.

同一查询在两个版本上运行, 可以用配对 bootstrap 估计指标差值区间. 端到端正确率、引用支持和拒答都保留逐样本结果, 再做重采样. 只报告平均提升而没有样本差异, 无法判断收益是否来自少量容易样本.

#### 13.2. 线上样本怎样回流

线上抽样覆盖高频与长尾, 并对失败、拒答和低置信请求适度过采样. 人工标注记录错误层级. 语料缺失进入内容队列, 召回遗漏进入检索集, 引用错误进入命题支持集, 表达问题进入生成偏好数据.

用户反馈不能直接当事实标签. 点赞受语气和速度影响, 点击来源受位置影响, 未投诉也不表示答案正确. 行为信号适合发现样本和估计体验, 高风险结论仍由证据标注与专业审查确认.
#### 一组可复算的分层结果

五个查询的首个相关证据名次为 1、2、4、未命中、3, 则 recall@3 为 $3/5=0.6$, recall@5 为 $4/5=0.8$, MRR 为 $(1+1/2+1/4+0+1/3)/5\approx0.417$. 若相关等级为 2、1、0, nDCG 还会奖励把高度相关证据放在前面; 使用 nDCG 前必须固定等级标注, 不能把“主题相关”和“充分支持”混成同一级.

假设其中四个问题取得完整证据, 上下文选择保住三个, 生成器对这三个都给出正确答案, 但只有两个回答的全部核心命题受证据支持. 系统报告语料条件 recall 0.8、context recall 0.75、条件答案准确率 1.0、faithfulness 0.667. 只看最终三个答案全对会隐藏一条依赖参数记忆或错误引用的回答.

Ragas 等框架把 context precision、context recall、faithfulness 和 answer relevance 组织成可运行评测, 价值在于统一实验接口; 具体 judge、提示和参考答案仍需在任务数据上校准. 自动 judge 与人工金标比较混淆矩阵, 分别观察把不忠实判为忠实的风险错误和反向误报.

数据切片同时报告样本数和区间. 某时间问题切片 20 个样本得 90%, 只代表 18 个成功; 与一千个简单事实问题的 90% 不具有相同不确定性. bootstrap 以问题为单位重采样, 配对比较新旧系统差值, 避免各抽一组样本造成额外方差.

BEIR 的跨领域结果提醒评测保留来源、体裁和任务切片. 同域平均提升可能伴随法规、科学文献或论证检索退化. 发布门槛除总体指标外, 为高风险切片设置最低 recall、faithfulness 和拒答 precision, 样本不足时保留人工验收.

每个汇总分数都能回到问题、候选、上下文、命题与 judge 判定, 评测结果才具有可复算的错误归因路径.

版本变化后仍按相同路径重放.
