# RAG · Retrieval-Augmented Generation · 检索增强生成

大模型知道很多, 但参数里的知识有三个麻烦: 更新时间取决于训练周期, 回答很难指出原始出处, 某条知识需要撤回时也不能定点删除. RAG (Retrieval-Augmented Generation) 把一部分知识留在模型外部, 每次回答前先取得与当前问题有关的证据, 再让生成模型依据证据作答. 这条路线看上去只多了一次搜索, 实际上把一个模型问题改造成了一条可以逐段测量的数据流. 文档怎样进入语料, 查询怎样变成检索请求, 候选怎样排序, 哪些片段真正送入上下文, 回答中的命题由哪一段支持, 证据不够时何时拒答, 都需要单独设计.

**RAG 把知识的获取、使用和核验从参数中拆出来.** 这也解释了为什么「接一个向量库」远远不够. 向量相似只能提供候选, 不能判断来源是否仍然有效, 不能保证数字和否定条件被保留, 更不能证明生成模型确实使用了候选中的证据. 一个完整系统至少有语料快照、检索运行、上下文选择和生成验证四种状态. 任何一段发生变化, 都可能让最终回答改变.

Lewis 等人在 2020 年提出的 RAG 模型把参数记忆与可检索的非参数记忆联合起来, 训练时对检索文档这一潜变量求和或近似. 今天工程中所说的 RAG 范围更宽: 稀疏搜索、稠密向量、数据库查询、重排模型、LLM 查询改写、引用验证和线上索引治理都可能进入同一条链. 名称扩大以后, 最容易出现的问题是把各种组件堆在一起, 却没有统一任务定义. 因此这里按照系统中信息状态的变化组织内容, 不按向量数据库、框架或论文年份排列.

```text
用户问题
  -> 任务判定与查询表示
  -> 受权限约束的候选召回
  -> 融合、重排与证据集合选择
  -> 带来源位置的上下文
  -> 回答、引用或拒答
  -> 分层评测与线上反馈
```

第一部分从[问题与基线](01-问题与基线/01-问题与基线.md)进入. 它先判断一个任务是否真的适合 RAG, 随后建立最小可复现基线. 纯创作不需要外部证据; 精确聚合、联接和事务查询通常应由数据库或业务 API 完成; 需要频繁更新、授权隔离和原文追溯的知识问答才是 RAG 的典型场景. 同一章也处理语料身份、版本、切分和删除传播, 因为错误或越权文档进入索引后, 后面的排序与提示无法补救.

第二部分沿[检索与上下文](02-检索与上下文/02-检索与上下文.md)展开. BM25 保留罕见词、编号和字面匹配, 双编码器处理释义和语义近邻, late interaction 与 cross-encoder 增加更细的查询—文档交互. 这些方法输出的分数含义不同, 需要融合、校准或按排名组合. 检索到候选之后还要处理重复片段、冲突版本、多跳证据和上下文预算. **召回解决「证据有没有进候选」, 重排解决「有限位置先放谁」, 上下文构造解决「模型最终看见什么」.** 三者不能拿一个最终回答分数混在一起调.

第三部分讨论[生成、自适应与评测](03-生成自适应与评测/03-生成自适应与评测.md). 生成器需要把回答拆成可以被证据支持的命题, 引用则要同时满足链接有效、证据确实支持命题、重要命题覆盖充分. 无答案问题需要校准拒答, 不能靠一个相似度阈值代替置信度. 当静态流程不够时, 系统可以学习何时检索、如何改写查询、如何从自身回答触发再次检索; Self-RAG、RAFT 一类工作分别从自反思控制和训练数据构造切入. 这些方法改变了检索与生成之间的控制关系, 但没有取消语料版本、权限和分层评测.

## 一套贯穿全库的对象

全库统一使用查询 $q$, 语料快照 $\mathcal C_t$, 候选集合 $D_K$, 最终证据集合 $E$, 回答 $y$ 与引用映射 $A$.$\mathcal C_t$ 中每个片段不只有正文, 还要带稳定文档身份、版本身份、来源位置、权限和有效时间. 检索器给出候选 $D_K=R(q,\mathcal C_t)$, 重排与上下文选择器再得到 $E=S(q,D_K,B)$, 其中 $B$ 是 token、延迟或成本预算. 生成器计算 $p(y\mid q,E)$, 引用映射 $A$ 把回答命题连接到 $E$ 中的具体位置.

这套记号把几个经常混用的判断分开. 候选相关不等于证据充分; 证据充分不等于回答忠实; 回答忠实于文档也不等于文档内容真实. 来源质量属于语料治理, 相关性属于检索与排序, 支持关系属于生成验证. 权限正确性和删除传播则是硬约束, 不能与相关性或答案流畅度做加权平均后抵消.

| 层 | 输入与输出 | 主要问题 | 典型指标 |
|---|---|---|---|
| 语料 | 源对象到 $\mathcal C_t$ | 版本、权限、切分是否正确 | 新鲜度、删除残留、解析成功率 |
| 检索 | $q,\mathcal C_t\to D_K$ | 所需证据是否进入候选 | Recall@k、MRR、nDCG |
| 选择 | $q,D_K,B\to E$ | 预算内证据是否完整且少重复 | 证据集合覆盖、冗余率、token 数 |
| 生成 | $q,E\to y,A$ | 回答是否被证据支持 | 正确率、命题支持率、引用覆盖 |
| 系统 | 请求到完整 trace | 延迟、成本、安全是否达标 | P95/P99、失败率、越权率 |

表中的层可以分别失败. 如果正确文档没有进入 $D_K$, 调重排模型不会找回它; 如果正确文档已在 $D_K$ 却没有进入 $E$, 问题在预算和选择; 如果 $E$ 已包含完整证据而 $y$ 仍写错, 应检查生成契约、长上下文位置效应和验证. 这种定位方式比反复改 prompt 更有效, 因为每次改动都能落到明确的输入、输出与指标上.

## 怎样读这座知识库

第一次建设 RAG, 可以依次读三部分. 任务损失、语料快照和无答案集合确定后, 比较稀疏、稠密和混合召回, 随后加入生成、引用和自适应控制. 已有系统遇到故障时则按症状进入: 旧文档或越权片段出现在回答中, 从语料版本与权限查起; 专有名词和编号找不到, 先看稀疏检索与分词; 候选已有正确证据却被排在后面, 检查融合与重排; 引用存在但不支持结论, 检查命题—证据映射; 换模型后整体分数上升但拒答变差, 回到分层评测和切片数据.

读论文时也要保持同一参照系. 新方法究竟改了语料表示、查询表示、候选打分、上下文选择、生成目标还是反馈闭环? 它增加了哪些训练或推理成本? 实验只测了开放域 QA, 还是包含长文档、多跳、时效、权限和无答案查询? 只要把工作放回这几个问题, 新缩写就不会把知识树重新打散.

## 从静态检索到学习型 RAG

最早的 RAG 训练把检索文档视作潜变量, 检索器与生成器可以联合优化. 随着通用 LLM 成为生成器, 很多系统改用冻结 embedding 和提示编排, 训练成本降低, 检索策略也退化成每次固定取若干段. Self-RAG 重新把「是否检索、证据是否相关、回答是否被支持」放入模型控制过程;RAFT 则通过带干扰文档的训练样本, 让模型学习从一组候选中识别并使用支持证据. 两条路线分别改变推理时控制和训练时监督, 不能都概括成「高级 RAG」.

学习型 RAG 仍要回到本库的共同对象. 自适应检索改变 $R(q,\mathcal C_t)$ 的调用时机, 不改变语料快照与权限要求;证据判别改变选择 $S(q,D_K,B)$, 不代表候选覆盖已经足够;基于引用或 verifier 的反馈改变生成与选择策略, 仍需独立测试反馈模型的偏差. 训练方法提高了组件之间的协作能力, 没有把各层合并成一个不可观察黑箱.

## 与 Agent、搜索和长期记忆的边界

RAG 可以成为 Agent 的一个工具, Agent 也可以规划多轮查询、调用网页搜索或数据库. 区别在控制范围: RAG 关注外部证据怎样进入一次生成并接受核验;Agent 还管理目标分解、工具选择、执行状态与长期任务. 如果每一次工具调用都被叫作 RAG, 检索质量、动作正确性和工作流成功率会失去边界.

搜索引擎输出排序文档, RAG 进一步把文档放入生成上下文并产生回答. 长期记忆记录用户经历、任务状态或可复用经验, 其中一部分可以通过检索读取, 但写入策略、遗忘与跨会话一致性属于记忆系统. 本库会引用这些相邻领域, 不把它们收进同一目录. 这种分工使 RAG 的评价对象始终是「外部证据怎样支持当前回答」.
