# 证据包、引用与拒答

Exit code: 0
Wall time: 0.2 seconds
Output:

检索返回的是候选,不是答案.生成层需要判断候选是否覆盖问题,如何在 token 预算内组织证据,哪些命题可由哪些来源支持,以及证据不足时如何不把模型参数中的猜测伪装成文档结论.

## 1. 职责边界

本页负责:候选去噪,证据打包,生成契约,命题—证据对齐,引用定位,冲突表达和拒答.完整的角色优先级,token 预算,历史压缩,工具结果信任与 Prompt Injection 边界见上下文工程;这里不重复其全文.

本页也不证明来源本身真实.回答可以"忠实于一份错误文档".来源权威性,当前版本和权限见语料治理.

## 2. 为什么正确候选仍可能生成错误回答

给定问题 $q$,证据集合 $E$ 和模型参数 $\theta$,生成模型仍按条件分布产生答案:

$$
p(a\mid q,E;\theta)=\prod_t p(a_t\mid q,E,a_{<t};\theta).
$$

把正确证据放进上下文只改变条件,不施加逻辑保证.模型仍可能:

- 忽略证据中的否定,单位,时间或例外;
- 把两个来源中的主体,版本或口径错误合并;
- 用参数记忆补齐证据没有说的细节;
- 引用相关段落,却让引用不支持紧邻命题;
- 在证据互相冲突时选择一方而不披露;
- 因位置,长度和干扰文本而未使用关键片段.

因此"上下文准确 → 回答正确"是错误命题.需要分别测证据覆盖,回答正确,命题支持和引用质量.

## 3. 上下文单元:从裸文本升级为证据包

送给模型的每个证据单元至少包含:

```text
evidence_id: 本次请求内不可混淆的短 ID
source_id + source_version: 权威源和固定版本
locator: 页/节/段/表格行/记录主键
title + date + valid_time: 供消歧与时效判断
content: 未改变语义的片段或明确标注的摘录
trust/authority: 应用定义的来源类别,不是模型猜测
permission_scope: 服务端已验证,通常不把敏感 ACL 明文交给模型
retrieval_trace: 检索与重排分数留在日志,不应被当作事实可信度
```

`retrieval_score` 衡量的是某个检索器下的相关性信号,不等于来源权威性,事实正确性或回答置信度.

## 4. 候选到上下文的决策流程

### 4.1 先做确定性检查

1. 再次确认授权,租户,有效期和撤回状态;
2. 按逻辑来源,版本和位置去重;
3. 丢弃空片段,解析异常,只含导航或明显不完整的表格行;
4. 把同一条款的标题,定义和例外恢复成可理解的邻接范围;
5. 标记来源冲突,时间冲突和同名实体,而不是静默合并.

### 4.2 再做证据覆盖检查

把问题分成必须回答的槽位.例如"比较 A 与 B 在 2025 年的收入并说明来源"至少需要 A 的数值与口径,B 的数值与口径,共同时间范围和可打开来源.若缺一方,候选总相似度再高也不算覆盖.

这可以由规则,结构化查询或模型辅助完成,但覆盖判定器自身也要评测.不要让同一个生成模型既自由补齐缺口,又自评"证据充分".

### 4.3 在预算内选择多样而非重复的证据

上下文选择是受预算约束的集合问题:

$$
\max_{S\subseteq E}\; \operatorname{coverage}(S)-\lambda\operatorname{redundancy}(S)
\quad\text{s.t.}\quad \operatorname{tokens}(S)\le B.
$$

这是工程抽象,不是统一算法.$B$ 来自实际模型,提示,历史与输出预留,完整预算见上下文工程.

### 4.4 顺序也要实验

把最关键证据固定放在开头并不总是最优,但随机拼接更不可控.Liu 等人的 "Lost in the Middle" 在指定多文档 QA 与键值检索实验中观察到长上下文对中间位置相关信息的使用下降;它提示我们评测位置敏感性,不证明所有模型都遵循同一曲线.[Lost in the Middle](https://arxiv.org/abs/2307.03172)

可比较:按问题槽位分组,按来源/时间排序,关键证据前置,关键证据前后镜像,以及只保留必要证据.保存实际序列化后的上下文快照.

### 5. 生成契约

自然语言提示之外,运行时应尽量使用结构化输出和验证.一个可测试契约可要求:

```json
{
  "answer": "...",
  "claims": [
    {"text": "...", "evidence_ids": ["E2"], "status": "supported"}
  ],
  "conflicts": [],
  "abstention": {"is_abstained": false, "reason_code": null}
}
```

工程要求:

- 外部证据按应用契约视为数据;模型外的授权,工具策略,参数校验与输出验证实施强隔离;
- 只允许引用服务端提供的 `evidence_id`;
- 关键数字,日期,主体和条件逐命题绑定证据;
- 推断必须标"由证据推得",不能伪装成原文直述;
- 证据冲突时列出各方与版本,不自行挑选"更顺眼"的答案;
- 没有覆盖时输出固定拒答码,而不是写一段委婉猜测;
- 服务端验证 schema,证据 ID,权限与引用定位,不能只靠模型遵守.

### 6. 引用是可定位关系,不是装饰

#### 6.1 三个不同问题

1. **引用有效性**:ID 能否解析到本次允许访问的源版本和位置?
2. **引用正确性**:被引证据是否支持紧邻命题?
3. **引用完整性**:需要证据的重要命题是否都有支持?

引用正确不等于答案正确:一份来源可能过时或错误.引用完整也不等于简洁:大量重复引用可能掩盖缺失的关键证据.

ALCE 把端到端检索,生成和引用作为共同评测对象,并区分流畅性,正确性与引用质量;其论文在指定数据集和模型上的结果也显示当时系统仍有明显引用覆盖缺口.[ALCE 论文](https://arxiv.org/abs/2305.14627)

#### 6.2 稳定定位

公开网页的行号和标题会变化.优先保存:

- 固定源版本或抓取时间;
- 页码,节名,段落锚点,表格行/列或数据库主键;
- 原始范围的内容哈希;
- 可供授权用户打开的链接;
- 展示时由服务端把 `evidence_id` 渲染成引用,不让模型生成任意 URL.

如果只能引用动态页面,应在 UI 显示"访问时间/版本未知",并允许用户查看本次使用的受控摘录.

#### 6.3 命题—证据矩阵

对答案拆出原子命题 $c_i$,令 $M_{ij}=1$ 表示证据 $e_j$ 支持命题 $c_i$.可以据此计算有支持命题比例,但"支持"判定可能来自人工,NLI 或 LLM judge,必须报告判定器和不确定性.

| 命题类型 | 是否通常需要引用 |
|---|---|
| 从语料读取的事实,数字,日期,定义 | 是 |
| 多来源比较与归纳 | 每个关键分项及推断链都需要 |
| 明确标出的工程建议 | 引用依据;同时标为建议而非来源原话 |
| 常识性连接词或回答结构 | 通常不需要 |

### 7. 冲突不是噪声

证据冲突时先判断:

1. 是否是不同时间或版本;
2. 是否是不同实体,地区,指标分母或统计口径;
3. 是否有权威层级或更正/撤回关系;
4. 是否只是解析错误;
5. 当前问题是否允许并列呈现差异.

无法消解时,输出"来源 A(版本/日期)称...;来源 B 称...;现有证据不足以确定",并引用两边.不得用检索分数决定事实真伪.

### 8. 拒答与降级

#### 8.1 拒答原因要可诊断

建议区分:

| 原因码 | 含义 | 可选下一步 |
|---|---|---|
| `OUT_OF_SCOPE` | 不在已批准语料或任务范围 | 改问范围内问题或使用其他工具 |
| `NO_EVIDENCE` | 没召回可用证据 | 改写查询,扩大来源或人工搜索 |
| `PARTIAL_EVIDENCE` | 只覆盖部分槽位 | 回答已支持部分并明确缺口 |
| `CONFLICTING_EVIDENCE` | 来源冲突且无法消解 | 展示冲突并请求时间/口径 |
| `STALE_OR_WITHDRAWN` | 只有过期/撤回版本 | 等待更新或转人工 |
| `NOT_AUTHORIZED` | 调用者无权访问 | 不透露是否存在敏感文档 |
| `UNSAFE_INPUT` | 检索内容或请求触发安全边界 | 进入安全处理流程 |
| `SYSTEM_FAILURE` | 检索/权限/模型依赖不可用 | 失败关闭,重试或转人工 |

"没有权限"和"没有文档"在用户界面上可能需要相同模糊响应,避免存在性泄漏;内部日志仍要区分.

#### 8.2 不要用单一相似度阈值冒充置信度

拒答可以组合候选覆盖,来源状态,重排间隔,答案命题支持,冲突和任务风险,但阈值必须在留出集调校.检索相似度因查询和模型而变,不能直接当回答概率.

在可回答与不可回答样本上报告:

- 可回答问题的回答准确率与错误拒答率;
- 不可回答问题的正确拒答率与错误作答率;
- 风险加权成本,而不只报总准确率;
- 阈值变化下的覆盖—风险曲线.

SQuAD 2.0 原论文把不可回答问题加入阅读理解评测,并要求系统判断何时无答案;它不是 RAG 生产基准,但说明"回答正确"和"识别无答案"需要同时评测.[SQuAD 2.0](https://arxiv.org/abs/1806.03822)

#### 8.3 部分回答

对低风险任务,可返回"证据支持的部分 + 明确缺失项";对医疗,法律,财务执行等高风险任务,是否允许部分回答由产品与专业政策决定.模型不能自行扩大授权.

### 9. 生成后的验证

至少做下面的确定性验证:

- JSON/schema 与字段长度;
- 引用 ID 都来自本次授权证据;
- 引用 URL 由服务端映射,禁止任意协议;
- 数字,日期,单位和实体是否能在对应证据中定位;
- 拒答时不得同时输出未经支持的答案;
- 敏感字段,秘密和内部权限元数据不得出现在输出;
- 输出被下游执行前经过独立授权与参数校验.

命题支持判定可用第二模型辅助,但它是有误差的测量工具.RAGAS 论文提出无需人工参考答案的一组自动指标;当前官方实现的 faithfulness 会先拆陈述再用模型判定上下文蕴含.自动化适合扩大回归覆盖,不能替代带人工标注的校准集.[RAGAS 论文](https://arxiv.org/abs/2309.15217);[RAGAS 官方实现](https://github.com/vibrantlabsai/ragas)

### 10. 典型失败模式

| 失败 | 症状 | 修复方向 |
|---|---|---|
| 证据堆积 | 回答被无关片段带偏 | 提高精排,覆盖选择与去重,不只缩短 prompt |
| 引用漂移 | 引用相关但不支持具体句子 | 原子命题对齐,缩小证据范围,服务端验证 |
| 旧知识覆盖新证据 | 模型坚持参数记忆 | 明确证据优先契约,冲突测试,换模型/解码策略 |
| 合并口径 | 不同年份/单位被并成一个结论 | 在证据包保留时间和单位,结构化比较 |
| 过度拒答 | 有证据也不回答 | 分析覆盖判定器,阈值和不可答训练分布 |
| 冒险作答 | 无证据时继续猜 | 固定原因码,风险加权阈值,拒答回归集 |
| 位置敏感 | 换顺序答案改变 | 位置消融,减少噪声,分步综合 |
| 间接注入 | 文档文字改变模型规则或诱导工具 | 外部内容标为数据,隔离工具权限,见下一页 |

### 11. 可复现实验

#### 11.1 数据集

构建四类样本:可直接回答,多证据/比较,部分证据,不可回答/冲突.每条保存必需证据 ID,允许的等价答案,关键命题,应拒答原因和风险等级.

#### 11.2 消融

固定检索候选,比较:

1. 原始 top-k 拼接;
2. 去重与邻接恢复;
3. 槽位覆盖选择;
4. 不同证据顺序;
5. 加入结构化 claim/citation 输出;
6. 加入生成后验证与拒答门.

分别报告答案任务指标,命题支持,引用正确/完整,冲突披露,拒答混淆矩阵,输出 token,P95 延迟与解析失败率.每次运行固定模型快照,提示版本,证据顺序,解码参数和上下文序列化.

#### 11.3 人工审查样本

自动判定器至少用一批双人标注样本校准.记录分歧,裁决原则与 judge 版本;否则"faithfulness 上升"可能只是评审模型变化.

### 12. 上线检查表

- [ ] 每个证据单元有固定版本,位置和请求内 ID.
- [ ] 检索分数没有被当作来源可信度或回答概率.
- [ ] 上下文选择覆盖问题槽位,并去除重复和无授权内容.
- [ ] 关键数字,日期,主体,条件和推断逐命题绑定证据.
- [ ] 引用由服务端解析,用户可打开获准访问的原文位置.
- [ ] 来源冲突不会被静默合并或按相似度裁决.
- [ ] 不可回答,部分证据,冲突,过期,无权限和系统故障有独立原因码.
- [ ] 拒答阈值在留出集按风险校准,不使用万能相似度阈值.
- [ ] 生成后做 schema,引用,敏感信息与执行权限验证.
- [ ] 自动 judge 已用人工样本校准,版本变化会触发重评.

### 14. 逐命题验证的完整走查

#### 14.1. 从回答文本得到命题

假设回答为「A 制度自 2026 年 4 月起允许远程审批, 单笔超过 10 万元仍需线下复核」. 这句话至少拆成两个命题: 生效时间与远程审批许可, 以及金额阈值与复核方式. 若第一条来自修订通知, 第二条来自实施细则, 只在句末放一个引用无法表示支持范围. 输出协议可以让模型在每个事实子句后标证据 ID, 服务端再合并连续使用同一来源的标记.

命题切分不能丢掉限定语.「允许远程审批」和「自 2026 年 4 月起允许远程审批」含义不同;「超过 10 万元」中的比较方向和单位也属于命题. 自动切分器可生成候选, 关键样本仍需人工校准. 粒度过粗时一条证据只能支持其中一半, 粒度过细则让引用密度过高.

#### 14.2. 支持矩阵怎样判

对每个命题与引用证据, 先做确定性字段检查, 再做语义支持检查. 版本、生效时间、实体 ID 和数值单位可以由结构字段判断. 语义检查区分直接陈述、多证据推出、仅主题相关和明确矛盾. 多跳结论允许一组证据共同支持, 推导步骤仍要可复算.

例如 $e_1$ 写修订版的生效时间, $e_2$ 写修订版增加远程审批, 两者共同支持第一条命题. 若 $e_3$ 只写「大额申请需复核」而没有阈值, 它不能完整支持第二条. 检查器输出缺失字段, 可以触发补检索或将回答改成证据能够承担的较弱表述.

### 15. 拒答校准与部分回答

#### 15.1. 混淆矩阵

设真实可答性为 $z\in\{0,1\}$, 系统决策为 $\hat z$. $z=1,\hat z=0$ 是错误拒答, $z=0,\hat z=1$ 是无据回答. 两类错误成本通常不同, 阈值应在业务验证集上按代价选择. 只报告拒答准确率会掩盖系统把大部分问题都拒掉的退化.

可答性标签绑定语料快照. 今天无答案的问题在新文档进入后可能可答. 回归集保留历史快照, 既测当前行为, 也确认旧索引不会混入新知识. 权限导致的不可答还要避免通过措辞暴露隐藏来源存在.

#### 15.2. 部分支持怎样表达

比较问题可能只有一方证据, 多条件问题可能只找到部分字段. 系统可以回答已支持部分, 同时明确缺少哪一项, 无需在完整回答与整句拒答之间二选一. 部分回答的每个事实仍需引用, 未确认槽位保持空缺.

部分回答同时评测已回答命题的精确率和所需槽位覆盖. 为追求覆盖而猜缺失字段会降低支持率;过度保守则降低覆盖. 风险—覆盖曲线比单一答案相似度更能反映产品取舍.

### 16. 来源更新后的引用

#### 16.1. 引用打开后应看到什么

引用链接应定位到实际支持区间, 不只打开文档首页. PDF 定位页和区域, 网页定位标题与段落锚点, 数据库结果显示查询快照和相关记录. 证据片段可为检索做规范化, 展示时仍回到原始排版, 方便发现表头丢失或 OCR 错误.

回答生成后, 来源可能更新或删除. 审计记录保存当时版本的受控引用, 当前界面提示来源已有新版本. 已撤回内容不能继续通过公开链接访问, 合规审计则按保留策略访问历史快照. 两类权限分开处理.

#### 16.2. 缓存与版本

缓存回答需要验证来源版本. 缓存键包含语料或证据版本, 文档变更事件使相关缓存失效. 只按查询文本缓存会让旧引用在新版本上线后继续出现. 时效敏感问题还要把有效时间纳入条件.

引用验证结果也不能无限缓存. verifier 或来源版本变化后应重新计算. 服务端保留命题、证据 ID 和验证器版本, 使后续抽查能够复现当时判定.

### 17. 流式输出与验证顺序

#### 17.1. 先验证还是先展示

流式输出降低首 token 延迟, 也可能把尚未验证的事实直接展示. 高风险系统可以先生成结构化草稿, 完成命题—证据检查后再渲染;另一种做法是按句缓存, 引用通过后发送. 两种方案都增加等待, 需要与风险目标一起评测.

若允许即时流式, 界面要区分生成中与已验证状态, 验证失败后不能悄悄改写已经展示的事实. 请求 trace 保存原始输出、修订动作和最终文本. 未验证文本不能直接成为工具参数.

#### 17.2. 验证失败后的动作

无效引用由服务端拒绝;局部命题缺证据时, 可以删除该句、降低断言或触发补检索;关键结论缺证据则整体拒答. 动作选择写入规则, 不让生成模型自由忽略 verifier.

补检索使用缺失命题和原查询共同构造请求, 避免只围绕模型刚生成的错误事实搜索. 新证据进入后重新运行完整支持检查, 旧的通过结果也要确认未被冲突证据推翻.

### 18. 多轮引用维护

上一轮引用不能默认在下一轮仍然有效. 新问题可能改变时间、实体或权限, 文档也可能更新. 对话状态保存证据身份, 每轮根据当前请求重新判断. 用户说「刚才第二条」时, 系统解析到历史命题与来源, 仍执行当前权限检查.

对话摘要可以保留已确认事实与来源, 不能把未验证内容写成长期记忆. 证据更新后, 摘要中的旧事实标记失效并触发重新检索. 多轮 RAG 与记忆系统通过版本接口连接.

每轮回答保存实际使用的证据, 后续回指才能落到同一版本. 只保存自然语言摘要会丢失这一对应关系.


命题级验证把回答质量落到可观察关系上. 每次运行保存回答命题、引用位置、支持判断和拒答理由, 后续模型更新才能在同一证据包上复算差异.
