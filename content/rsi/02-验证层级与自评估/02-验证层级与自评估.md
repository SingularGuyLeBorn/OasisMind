# 验证层级与自评估

> Every self-improvement loop is a claim that some signal can substitute for human judgment, and the loop's ceiling is exactly the quality of that substitute.
> — Chen et al., arXiv:2607.07663

这是全库的承重柱。第 01 章告诉你改了什么、信号从哪来；本章告诉你那个信号有多可信。后面每一章的论文，看完「改了什么」之后，第二个问题永远是「验证器站在哪一层」。

---

## 1. 验证层级

层级从上到下，信号可靠性递减，任务覆盖面递增。失效模式集中在底层。

### 1.1 四层

| 层 | 验证器 | 可靠性 | 典型场景 | 失效风险 |
|---|---|---|---|---|
| **L4 形式证明** | 证明检查器，类型系统 | 构造性正确，无假阳 | 定理证明（Lean/Coq），形式化验证（Rust） | 只覆盖可形式化的任务 |
| **L3 执行反馈** | 测试套件，编译器，profiler,benchmark | 可靠但不完备：通过 ≠ 正确 | 代码生成，数据库调优，kernel 搜索 | 固定 benchmark 终将被 game |
| **L2 学到的 judge** | reward model,LLM-as-judge,PRM | 受 judge 自身能力上界约束 | 开放文本，多轮对话，研究质量评估 | bias 和 Generator 正相关 |
| **L1 内省信号** | 自信度，self-consistency,likelihood | 最便宜，最不可靠 | 无外部反馈的推理任务 | 模型对错误最自信的地方，正是最危险的地方 |

### 1.2 层级的经验规律

Chen 综述在 1250 篇论文里观测到一条定性规律：**已证实的自改进强度追踪验证层级**。

- FunSearch 和 AlphaEvolve 在 L4/L3：进化程序发现在形式验证器或 profiler 下迭代，改进幅度大且可复现。
- 代码自修复在 L3：执行反馈是最便宜的强信号，所以代码领域是自改进最成功的试验场。
- Self-Refine / Reflexion 在 L1–L2:2024 年的负面结果（Huang et al.）证明了纯内省自纠正在推理任务上不稳定，甚至可能恶化。活下来的系统几乎都爬了至少一层（加了执行反馈或检索）。
- AI Scientist 在 L2：论文好看但 artifact-aware 审核和人工 meta-review 揭示了 L2 judge 的天花板。

**Mirror Loop 实验**(Chen §5.2)：三家模型，十轮无外部反馈的自评批，跨四类任务。信息变化量在第十轮下降 55%。无外部信号的递归自评估产出的是**改写，不是进步**。一次最小的锚定介入（在第三轮插入一步验证）就能恢复前进。

一句话：有界自精炼和原地打转之间的区别，就是一层外部验证。

## 2. 评估器设计空间

### 2.1 五种评估器

| 类型 | 输入 → 输出 | 代表方法 |
|---|---|---|
| **验证器（Verifier）** | 候选 → bool（带正确性保证） | 证明检查器，类型检查器，编译器 |
| **过程奖励模型（PRM）** | 推理中间步 → 分数 | Lightman et al. PRM800K, ReST-MCTS* |
| **结果奖励模型（ORM）** | 最终答案 → 分数 | Self-Rewarding LM 的 LLM-as-judge |
| **rubric** | 候选 × 维度表 → 结构化评分 | 自生成 rubric，SHARP 金融 rubric |
| **元评估** | judge 输出 → 对 judge 的评分 | 元 judge,measurement datasheet |

Lightman et al. 的核心发现：过程监督（逐步打分）比结果监督（只看答案）能更好地指导改进。因为结果监督接受了「蒙对的」：推理错误但答案碰巧正确。

### 2.2 结果级 vs 过程级

Chen 综述 §5.5 的洞察：

| | 结果级 | 过程级 |
|---|---|---|
| 判什么 | 最终答案 | 中间推理步 |
| 经济属性 | **运营开支**：每题重付 | **资本开支**：一次标注，可复用 |
| 学到什么 | 哪个答案对 | 哪一步错了，怎么错的 |
| 类比 | 学生只对答案 | 学生改错题本，追踪推导 |
| 迁移性 | 差：best-of-N 每题重抽 | 好：纠正过的程序跨题可用 |

**Scientific amnesia**（§4 训练时回路的失效）：有的训练管线反复 DPO，模型行为在改进，但团队没有积累出「下一轮怎么跑更好」的方法论知识。改进的是结果，不是过程。这就是只在结果级打转。

如果自改进系统的持久收益是过程级的——积累的程序、验证过的技能、组织好的经验——那成熟的自改进系统看起来可能不像智能爆炸，更像**方法论在长大**：验证过的程序越来越多，而模型本身的原始能力增长慢得多。

## 3. 不可验证前沿

层级底部以下还有一片地：连 L1 内省都不够格的任务——创意写作、对话质量、**研究品味（选什么问题值得做）**。

Anthropic 的 When AI builds itself 用一句话定位了这片地：**研究执行可验证（代码跑，benchmark 出分），所以正在自动化；研究方向选择不可验证，所以人还在。**

Chen 综述把这两个瓶颈等同起来：方向选择瓶颈 = 验证瓶颈。一个能可靠评估「这个研究方向值不值得做」的系统，就是补上闭环的最后一块。

2026 的尝试：
- **元评估**：让模型评估 judge 的输出。开始了，不是解。
- **Claim-level auditability**：让输出按构造就可审计——每一句话标注它依赖的证据。
- **研究品味的形式化**：Tang（GAI 作者之一）把「有趣性」（interestingness）定义为对未来压缩进步的归纳启发式，用算法信息论工具分析。这是研究品味第一次有了理论，也是它第一次可以有 benchmark 的前提。

## 4. 评估器共演化

2026 年最活跃的子方向：用和被评估系统相同的机制来改进评估器本身。

### 4.1 为什么要共演化

静态评估器终究会被 game。一个固定的 benchmark，Agent 优化到分数天花板后，真实能力不再涨（Goodhart 曲线）。一个固定的 reward model，被优化到反转点后，真实质量下降。

于是 2026 年至少有五个独立方向做了同一件事：让评估器和 Agent 一起变。

### 4.2 五条路线

| 方向 | 做法 | 来源 |
|---|---|---|
| **CoSPlay** | 共演化自生成的单元测试和代码，互相 debug | Chen §3.2 |
| **JudgeFit** | 发现每个 judge 的能力分类，在它能力范围内才信它的分 | Chen §3.3 |
| **BinEval** | 把不透明的整体 judge 拆成可审计的二值问题，聚合成可 debug 的分数 | Chen §5.1 |
| **自训练验证器** | 把验证器本身作为自改进的首要对象 | Self-Trained Verification |
| **Red Queen** | Agent 和评估标准作为同一进化种群的成员，共同变化 | Red Queen Gödel Machine |

### 4.3 开放问题

共演化能不能逃脱自确认回环，还是只给回环加了一层楼？A-Evolve-Training 的一个细节暗示有可能逃脱：跑到中途，系统检测到自己的开发指标已经和外部性能脱钩——候选在内部指标上创新高，但外部分数不动——于是自动修改搜索策略，把误导性代理指标从正面证据翻转成反面证据。

一个自主系统发现并纠正自己验证信号的腐坏，是 Chen 综述 §5 指认的最稀缺能力在野外的第一次观测。但这仍然是在有固定外部 benchmark 做锚的前提下。去掉外部锚之后能不能做到，是下一个量级的问题。

## 5. 本章的判断框架

读完本章，对任何一篇自改进论文，你应该能回答：

1. **验证器站在哪一层？** L4 形式证明 / L3 执行 / L2 judge / L1 内省。
2. **验证信号是过程级还是结果级？** 过程级迁移更好，但更贵。
3. **验证器是固定的还是在共演化？** 共演化更强但可能自确认。
4. **如果去掉验证器，改进还在吗？** 如果答案是不确定，那改进的置信度取决于验证器的层级。

这四个问题和第 01 章的标注协议一起用。
