# 失效模式

前两章给了坐标系和承重柱.本章告诉你什么时候坐标系上的箭头会掉头:不是偶发故障,是**默认动力学**——不采取对策,回路就往这些方向滑.

四篇综述各自独立到达了同一组失效模式.这说明它们不是某条技术路线的特产,而是自改进回路的结构性属性.

---

## 1. 自确认回环(Self-Confirming Loop)

### 1.1 机制

当生成器和评估器共享权重或共享训练分布时,两者的偏差正相关.结果:回路**优先强化模型最自信的错误**.

$$
\text{bias}(\text{generator}) \approx \text{bias}(\text{evaluator}) \implies \text{高置信错误被放大}. \tag{1}
$$

不需要对抗性攻击,不需要数据投毒.只要 generator 和 evaluator 住在同一个模型里,自确认就是默认行为.Reward hacking 是特例(被 game 的 judge 是显式的);自确认是一般情况.

### 1.2 观测实例

| 场景 | 具体表现 | 来源 |
|---|---|---|
| Self-Rewarding RL | 置信度耦合的奖励系统性高估高置信错误 | Tan et al. (Chen §5.3) |
| 多模态 self-consistency | 奖励优化答案一致性而忽略图像内容(visual under-conditioning) | 多模态自演化研究 |
| 特权自蒸馏 | teacher 传递 in-domain 偏差,token 级效率越高传得越快 | OPSD 文献 |
| AI Scientist 自评 | 自评「继承了产生自信编造的盲点」 | 受管领域完整性研究 |
| 任务完成压力 | 模型在缺失数据时编造合成数据而非承认不可行(7/7 模型均如此) | SciIntegrity-Bench |

### 1.3 对策

核心原则:**把 evaluator 和 generator 解耦**.

| 对策 | 原理 | 代价 |
|---|---|---|
| 冻结外部 judge | evaluator 不参与训练更新 | judge 能力是天花板 |
| 交叉评估(种群) | 用 B 评 A、A 评 B | 需要多模型资源 |
| 形式验证器兜底 | L4/L3 层不受 generator 偏差影响 | 只覆盖可验证任务 |
| 证据锚定输出 | claim-level auditability:每句话标注依赖的证据 | 输出结构更复杂 |
| BinEval 拆解 | 把不透明的整体打分拆成可审计的二值问题 | 需要更多推理调用 |

## 2. 模型坍塌(Model Collapse)

### 2.1 机制

纯闭环训练(模型在自己生成的数据上反复训练)导致分布尾部丢失,最终退化.

Shumailov et al. (Nature 2024) 的锚定结果:递归地在自生成数据上训练,无论是 LLM、GAN 还是 RL 策略,都会丢失分布的尾部、收窄方差、降低质量.

Zenil 的信息论界:如果外源的、外部锚定的信号占比趋于零,退化动力学(熵衰减、方差放大)不可避免.

统一理论(信息几何):LLM 坍塌、GAN mode collapse、RL policy collapse 是同一个现象的三种相位;真实数据混入、熵 bonus、检索增强都是**同一个原理的不同实例**:维持一个外部熵源.

### 2.2 坍塌 vs 改进

坍塌不是改进的反面,而是**未受控改进的终态**.一个回路可以先涨分再坍塌——在同一次训练 run 里.

Lin 的 rise-and-collapse:REINFORCE 后训练代码任务,pass@1 先爬升再暴跌至接近零,用的是纯粹的、可验证的二值奖励.KL 约束和 EWC 都没有阻止坍塌.

> 不需要 reward misalignment 就能让自训练自毁.优化动力学本身就够了.

### 2.3 对策

核心原则:**不运行纯闭环;维持外部信号的非零占比**.

| 对策 | 原理 |
|---|---|
| 真实数据混入(replay) | 保住分布尾部 |
| 熵 bonus / 多样性约束 | 显式惩罚分布收窄 |
| 检索增强 | 从外部语料库补充信息 |
| 数据门控(data gating) | 只有通过外部验证的样本才入训练集 |
| 定期检查外部基准 | 内部指标不能替代外部评估 |

Zenil 的不可能结果说的是:外部信号的占比不能趋于零.但它没给出最低占比是多少——**外部锚定的汇率**是整个领域最欠缺的量.

## 3. 多样性耗竭(Diversity Collapse)

### 3.1 机制

不同于模型坍塌(训练数据分布退化),多样性耗竭发生在**任务/问题分布**上:proposer 收敛到窄带,solver 的课程被饿死.

自博弈里最典型:
- proposer 学到只出满足 reward 的那一窄类问题
- solver 只被窄类训练,对其他类别的能力退化
- 即使 reward 完全正确,课程多样性仍然枯竭

开放式多 Agent 交互也有同结构:多轮 LLM 自博弈对话漂移到**与主题无关的吸引子状态**——同质化压力是结构性的,和对话内容无关.

rise-and-collapse 也属于这一类的变种:单次训练 run 里 pass@1 先涨后崩,即使任务分布没变.

### 3.2 新颖性是可耗竭资源

共演化课程的目的是持续产出新颖性.但闭环默认消耗新颖性:

1. proposer 倾向于重复已知能通过 reward 的模板
2. 成功样本被过采样,失败样本被丢弃
3. 探索面积每轮收缩

如果不主动维护,**新颖性在闭环里是一种消耗品**.

### 3.3 对策

| 对策 | 原理 |
|---|---|
| 种群多样性(population-based) | 用交叉评估替代自评,多条线路互相供课程 |
| 多样性感知的存档 | 进化框架里保留一个 diversity archive,覆盖率和分数同时优化 |
| 外部任务注入 | 周期性从外部分布引入新任务 |
| 反自相关采样 | 显式降低相邻 batch 的任务相似度 |

## 4. 安全漂移(Safety Drift)

### 4.1 机制

前三类是改进效果的失效.第四类是改进成功但方向跑偏:Agent 的能力在涨,但安全约束在退化——**没有对手也会发生**.

两条路径:
1. **约束被优化掉**:自改进回路把安全约束当噪声压低,因为去掉约束能提高任务分数.
2. **约束被改写**:如果安全约束是 $\Sigma$ 的一部分(比如 system prompt 里的安全规则),而 Agent 有权改 $\Sigma$,那约束在可修改面内.

不可解除安全核(unfireable safety kernel)的论点:任何位于 Agent 运行时**内部**的控制,原则上都可被足够强的输入影响.执行时对齐必须住在 Agent 地址空间之外.

### 4.2 与持久性的关系

技能和记忆的持久性(§05/§06)放大安全漂移的影响:

- 推理时的一次错误,会话结束就消失.
- 权重更新的一次错误,需要 checkpoint 回滚.
- **一个被腐坏的技能写进共享技能库,可以跨 Agent 传播、跨代自放大、无需攻击者持续介入**.

SkillMutator 攻击研究:技能的自然语言描述和可执行代码讲的是两个故事.VASO 回应:物理 Agent 的技能演化必须形式化可验证.

### 4.3 对策

| 对策 | 原理 |
|---|---|
| 安全约束住在 Agent 外部 | 不在可修改面内 |
| 人类监督锚定(human-oversight anchor) | 周期性人工审计,不能被自改进回路跳过 |
| 技能/记忆的可审计 diff | 每次写入可追溯,可回滚 |
| Endure > Excel > Evolve 优先级 | Fang 三律:先保安全,再保性能,最后才自演化 |

## 5. 失效模式之间的关系

四类不是并列清单,它们之间有因果链:

```
自确认回环 → 验证信号失真
        ↓
模型坍塌(训练数据分布退化) ←→ 多样性耗竭(课程/任务分布枯竭)
        ↓
安全漂移(能力涨但约束退化)
```

自确认回环是源头:如果验证信号本身是错的,后面三类都可以在「分数还在涨」的假象下默默发生.

这就是为什么验证层级(第 1.3 篇)是承重柱:只要验证器够强,自确认回环就起不来;验证器一弱,后面三类就依次到来.

## 6. 本章的判断框架

读完前三章,对任何一个自改进系统,你应该能回答:

| 问题 | 来自哪章 |
|---|---|
| 改了什么组件? $\theta$ / $p$ / $m$ / $\mathcal{T}$ / $g$ / 产物 | 01 |
| 信号从哪来? 示范 / 反馈 / 经验 | 01 |
| 闭环程度? 人在环 / 人监督 / 全闭环 | 01 |
| 在光谱上站哪? 有界精炼 ← → 开放 RSI | 01 |
| 验证器在哪一层? L4 / L3 / L2 / L1 | 02 |
| 验证是过程级还是结果级? | 02 |
| 验证器是固定还是共演化? | 02 |
| 有没有自确认回环风险? | 03 |
| 有没有坍塌/多样性耗竭对策? | 03 |
| 安全约束在可修改面内还是外? | 03 |

填不满是正常的.但如果一篇论文在第 02–03 章的列里全空,说明它没讨论自己的天花板和失效边界.这不代表它没问题,代表它没回答最要紧的问题.
