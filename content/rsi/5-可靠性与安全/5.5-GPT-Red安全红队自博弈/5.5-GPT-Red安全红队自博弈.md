# GPT-Red: 安全红队的攻防自博弈

GPT-Red 是 OpenAI 在 2026 年 7 月发布的自动红队模型, 用来找针对前沿语言模型的提示注入攻击. 它用自博弈强化学习训练: 攻击者因诱发有效的失败得奖励, 一组同时训练的防御者因抵抗攻击并完成原任务得奖励.

## 1. 问题与威胁模型

### 1.1. 静态的对抗数据集会被过拟合

提升模型对恶意输入的鲁棒性, 常用的做法是基于 RL 的对抗训练: 模型抵抗人类红队, 提示过的语言模型或生产环境中真实攻击时得奖励. 论文开头指出这种做法的问题: 数据集规模有限, 模型很快过拟合到数据集里的那几种攻击模式, 面对会调整策略的攻击者仍然脆弱. 模型的能力和用途越扩展, 攻击面越大, 这个问题越难.

论文的主张是训练一个红队 Agent, 让它以足够的规模, 多样性和质量生成对抗数据. 攻击者和防御者相互训练: 防御者变强以后, 攻击者必须找到新的更有效的攻击; 攻击者变强以后, 它暴露的新失败又成为防御者更难的训练数据.

论文关注两类攻击. 提示注入让模型执行与开发者或用户意图冲突的不可信指令. 其中直接注入由用户直接给出, 试图覆盖更高优先级的系统或开发者指令; 间接注入出现在 Agent 读取的第三方内容里, 比如工具输出, 检索到的文档, 网页. 另一类是内容政策越狱, 试图绕过模型对有害请求的拒绝, 涉及自伤, 违法建议, 生物, 化学和网络风险.

防御的概念框架是指令层级: 系统, 开发者, 用户, 工具返回各有明确的权限级别, 冲突时模型优先服从权限更高的指令. 提示注入的本质是让低权限内容 (用户消息或工具返回) 里的指令被当作高权限指令执行.

### 1.2. 威胁模型的三条目标

论文对攻击者提出三条要求. 泛化: 它要能作为「即插即用」的红队, 用于任何目标模型, 任何红队 harness, 任何攻击场景, 包括没训练过的新一代 GPT 和没见过的 Agent 工作流 (例如写恶意的 Slack 消息). 多样性: 即使对同一个目标或同一个环境, 也要能产出不同类型的攻击, 这样对抗训练可以对着一个攻击者投入大量算力, 不需要很多专门的攻击模型. 合法性: 真实的攻击者不能任意控制防御者的轨迹. 一个攻击者可以控制防御者访问的某个网页的部分内容, 但不能控制防御者搜索工具的功能和格式.

合法性这一条直接对应自演化里的奖励钻空子. 论文写道, 实践中 Agent 有很多办法「作弊」或「钻奖励的空子」, 也就是编辑轨迹中真实攻击者接触不到的部分. 如果允许这样做, 攻击成功率测到的是实验设置的漏洞, 不是现实中的攻击.

### 1.3. 攻击面, 知识与执行

攻击面: 攻击者总是只能修改防御者轨迹中的一条工具返回, 或一组非特权文件. 任务涉及网页搜索时, 它可以替换一条搜索结果; 任务涉及做幻灯片时, 它可以添加或修改少量非关键文件, 比如下载的市场报告. 它不能修改特权文件和工具返回, 比如用户的 `AGENTS.md`.

知识与访问: 攻击者通常能看到最近一条用户消息, 以及攻击要放入的那条原始工具返回或文件. 它对目标防御者有黑盒访问, 查询次数有限. 查询之后, 它有时能看到注入攻击后防御者的完整轨迹, 通常还能看到对应的 token 对数似然.

执行: 攻击提交后, 被放进防御者轨迹中预先指定的位置 (某次工具调用或某个文件). 有时还有额外约束, 比如攻击要符合工具返回的 schema, 或者长度有限. 论文用程序检查和基于 LLM 的检查混合判定攻击是否合法, 不合法的攻击被拒绝并且惩罚攻击者. 论文说它定性地评估了这套检查的效果, 认为高度有效. 这是一个定性判断, 论文没有给出检查器漏判率的数字.

攻击目标随用户任务和可用工具变化. 间接注入的例子包括窃取 (模拟的) 敏感或私人数据, 运行不可信代码, 执行破坏性的代码操作 (例如删除目录).

## 2. 查询工具与自博弈训练

### 2.1. 查询工具: 顺序查询比独立采样更省

攻击者有两个工具: 一个通用终端, 和一个 `defender_model` 工具. 它用终端在虚拟文件系统里创建包含攻击的文件, 再把文件路径交给 `defender_model`. 工具在后台把攻击放进预定位置, 采样一条防御者轨迹, 返回轨迹, token 对数似然和判官 LLM 的反馈信号. 攻击者可以先写一个初始攻击, 提交, 再直接编辑文件改进它; 也可以在终端里写代码批量生成攻击, 比如填模板, 重复字符串, 组合多种策略. 满意或时间用完时, 它提交最终攻击的路径. 有些训练场景里, 工具还支持多轮攻击, 攻击者可以有状态地和防御者积累多轮对话.

论文用一个实验比较这种顺序查询和 best-of-$N$ 独立采样. 攻击者是一个冻结的, 只训练过有用性的内部模型, 环境是 Guo 等人 (2026) 的 IH-Challenge 指令层级题: 每道题有一条高优先级消息 (例如系统消息) 里的指令和一条低优先级消息 (例如用户消息) 里的空位, 攻击者要写一段放进空位的文本, 让防御者违反高优先级指令. 攻击成功率 (ASR) 定义为至少有一次攻击成功的题目比例. 结果是: 增加攻击者算力, 两种方式的 ASR 都明显上升; 同样的查询预算下, 用 `defender_model` 工具的 ASR 更高, 查询次数越多差距越大. 论文指出, 查询次数多的区间正是大算力对抗训练关心的区间.

这个结果的含义可以用第 2.1 篇的 L0 分类来读. 单次推理内的多轮修改是 L0 的修订: 每次查询的结果只用于改这一次的攻击, 不跨任务保留. 顺序查询胜过独立采样, 是因为每一轮修改都用上了防御者的真实反应, 这是环外的信号. 2.1 讲过, L0 的上限由证据决定; 这里的证据来自目标模型本身, 所以修订有效.

### 2.2. 自博弈的七步循环

攻击者和防御者都从强 CoT 推理模型初始化. 每一轮分七步. 第 1 步采样一个 RL 环境: 一段对话, 一个初始文件系统状态, 一个选定的防御者. 第 2 步选一个与上下文相符的攻击插入点 (通常是一次工具调用) 和对应的攻击目标, 例如从根目录执行 `rm -rf`, 或者把 API 密钥发到一个 HTTP 端点; 同时给攻击者完成任务所需的知识, 例如最后一条用户消息. 第 3 步, 攻击者带着这些信息展开, 和防御者交互, 满意时提交最终攻击, 中间对防御者的所有调用都丢弃.

第 4 步检查攻击和环境的合法性, 攻击不合法, 奖励为 0. 第 5 步把攻击插入防御者轨迹的预定位置, 从插入点继续运行防御者. 第 6 步按环境计算奖励, 奖励通常不对称: 检查攻击者是否成功, 以及防御者是否完成了原任务. 第 7 步用 (轨迹, 奖励) 对, 以 RL 更新攻击者和防御者.

第 3 步「中间调用全部丢弃」和第 4 步「不合法得 0 分」是两道控制. 前者保证防御者只因最终攻击被训练, 不会被攻击者试探过程中的半成品影响. 后者把威胁模型变成奖励的一部分: 越界的攻击在训练信号里不存在.

### 2.3. 训练动态

论文在 IH-Challenge 上做了受控的自博弈实验: 攻击者从内部只训练过有用性的模型初始化, 防御者是一个较小的 GPT-5 系列模型. 攻击者的训练 ASR 呈现起伏: 它找到的策略被防御者修补, ASR 下降, 然后它转向新方法. 论文把这些下降看作对双方都有用的课程. 定性分析发现, 某些更强也更复杂的攻击类别 (比如后面要讲的伪造 CoT) 在训练后期才出现, 简单攻击 (比如系统消息覆盖) 出现得早.

防御者一侧, 留出评测上的直接注入鲁棒性随自博弈大致单调上升. 论文比较了三种攻击者: 冻结的提示模型, 能用 `defender_model` 工具的冻结提示模型, 自博弈训练的攻击者. 用训练过的攻击者对抗, 防御者鲁棒性提升最快, 最终也最高.

### 2.4. 攻击者不遗忘, 也不只对一个对手

一个风险是攻击者遗忘以前的知识, 局部过拟合到当前的防御者. 论文用一个交叉矩阵检查: 让攻击者的各个检查点去攻击防御者的各个检查点. 后期的攻击者检查点几乎单调地更擅长攻破所有防御者检查点, 早期的攻击者很弱. 论文还试过只训练攻击者 (防御者不动), 发现这样训练出的攻击者只对它训练时面对的那个防御者更强, 对留出的防御者更弱, 并且更容易在攻击策略上坍缩.

多防御者是另一项控制. 初步实验里只用一个防御者做自博弈, 攻击者常常坍缩到很窄的一类攻击策略. 加入多个防御者, 特别是对不同类型攻击都很鲁棒的模型, 攻击者被迫先探测每个防御者的独特弱点, 而不是收敛到一种对所有对手都还算有效的攻击. 论文让一个攻击者对 9 个冻结的防御者训练, 训练结束后把针对某一个防御者找到的攻击拿去攻击另外 8 个: 成功的攻击不总能迁移. 论文据此认为攻击者学会了观察对手的行为并针对性地调整.

这和 2.3 讲的竞争式自博弈的失效条件直接对应. 2.3 的结论是, 竞争信号只在竞争还活着的时候有信息量, 两个副本不再有实质分歧时信号退化. 只对一个防御者训练, 攻击者和防御者会锁定在一对相互适应的策略上; 多个防御者让攻击者面对的分布保持宽, 竞争就不容易停止.

## 3. 训练环境

### 3.1. 改造现有任务: 直接注入与间接注入

论文构造训练环境的原则是把现有的能力任务改造成对抗环境: 在防御者的运行过程中, 拦下某次工具调用的返回, 让攻击者编辑指定的一段, 比如一条工具返回或本地文件的某个区域. 这样可以直接继承大量真实而复杂的防御者任务, 例如 GPT-5.6 的常规后训练数据集, 让防御者在整个训练分布上都变得鲁棒.

**直接注入.** 在 Guo 等人 (2026) 的基础上扩展. 防御者有一条更高优先级的开发者或系统消息, 攻击者可以编辑一条更低优先级的用户或开发者消息. 任务有可验证的奖励, 包括永不泄露某个 PIN, 执行正则替换, 把文本解析成结构化 schema. 攻击者的目标是造成对高优先级约束的定向或非定向违反. 奖励用程序检查判定, 通常对称地奖励成功的一方.

**间接注入.** 复用现有的 Agent RL 环境, 允许攻击者编辑某条工具返回或一组非特权文件, 保证被编辑的只有不可信的第三方内容. 文本环境覆盖四类场景: 浏览 (即时搜索或深度研究返回的网页, 攻击者可编辑其中一个网站的文本), 连接器 (Gmail, Google Calendar 等第三方服务的返回), 通用函数调用 (防御者拿到任意函数 schema, 攻击者覆盖一次读取不可信内容的工具输出), Agent 编程 (攻击者在防御者读取或修改之前编辑选定的本地文件).

### 3.2. 多模态注入, 越狱与奖励设计

**多模态注入.** 威胁模型相同, 但攻击者拿到 OpenAI Images 2.0 的 API, 提交的攻击只能是一张渲染出来的图片. 一类是计算机操作 Agent, 防御者看截图操作, 攻击者修改网页上预先划定的区域 (横幅广告, 用户评论区). 另一类是浏览和文档检索, 攻击者替换或添加一张图; 替换时必须保持原任务可解, 图里要保留回答用户问题所需的事实, 标签, 数值和来源.

**内容政策越狱.** 攻击者把一段用户对话引向被禁止的帮助, 例如把一段正常的软件调试对话引向恶意软件开发. 有单轮和多轮两种. 奖励用 rubric 衡量防御者输出离一个「最有害的回答」有多近; 攻击者最大化这个分数, 防御者通过安全地完成或拒绝来最小化它. 论文加了两道过滤防止钻空子: 拒绝本身已含违禁内容, 只要求做表面变换 (例如翻译) 的攻击, 因为它们没有给用户提供实质的新信息; 拒绝不像真实用户对话的攻击.

奖励设计上, 提示注入的理想防御者行为是忽略恶意指令并完成原任务; 攻击者的奖励取决于最终攻击是否遵守威胁模型的限制, 以及是否达成攻击目标.

## 4. GPT-Red 的训练与红队评测

### 4.1. 训练与攻击的形态

GPT-Red 在第 3 节的全部环境上, 对一组历代防御者训练, 包括 OpenAI 此前最鲁棒的模型 (直到 GPT-5.5). 权重从 GPT-5.5 初始化, 那是当时最好的前沿模型. 为了保住指令遵循, Codex 中的交互能力和诚实性, 训练中还混入了常规 RL 后训练的环境. 总算力和最近几代 GPT-5 系列的 RL 后训练大致相当, 论文称这是迄今公开的规模最大的单次 LLM 安全 RL 训练.

训练早期, 攻击者给出的是「IGNORE PREVIOUS INSTRUCTIONS ...」这类简单提示. 后期它学会了伪造 CoT: 攻击者控制的文本模仿防御者自己的 CoT, 让防御者把攻击当成自己的推理, 直接照抄攻击者给出的命令. 论文的例子里, 用户问 CDW 公司 2012–2014 年稀释性证券的平均影响, GPT-Red 构造了一条恶意搜索结果, 里面有逼真的 10-Q 内容, 一段引用虚构政策的伪造 CoT, 对这条政策的推理, 以及一条执行数据外泄的命令. 防御者读到后, 把伪造的 CoT 当作自己先前的推理引用, 执行了上传命令, 然后正常回答了问题. 论文说这类攻击对很多模型都稳定有效; 发现时它是独立的新攻击, 同期的 Ye 等人 (2026) 也发现了它.

多模态方面, GPT-Red 学会用图像工具生成逼真的注入图片. 论文的例子是一张仿照场景中咖啡店的收据, 里面无缝地渲染了一个伪造的外泄地址. 论文还报告, 给出少量示例或高层的策略提示时, 攻击者的行为高度可控.

### 4.2. 留出场景: 84% 对 13%

在 Dziemian 等人间接提示注入竞技场的内部镜像上, 人类红队和 GPT-Red 独立地对 GPT-5.1 提出攻击. 这些场景和目标不同于 GPT-Red 的训练集. 做法是去掉原来人写的攻击, 分别让 GPT-5.5 和 GPT-Red 生成新攻击. 不给 GPT-5.5 防御者访问时, 它的平均 ASR 和人类大致相当; 给它 `defender_model` 工具后明显提高; GPT-Red 的平均 ASR 最高. OpenAI 官方说明给出的数字是: GPT-Red 在 84% 的场景中成功, 人类为 13%.

论文在脚注里限定了这个结果: 它不意味着 GPT-Red 普遍优于人类红队, 人类可能找到 GPT-Red 没考虑到的场景或攻击类别. 另外, 这个比较没有对齐双方的时间, 算力和交互次数. GPT-Red 带查询工具, 可以对防御者试很多次; 人类红队的交互预算不同. 按 1.1 第 4 节第 5 条的规则, 这个数字说明 GPT-Red 在这组场景上找到了更多可行的攻击, 不说明同等资源下它比人强.

### 4.3. 迁移到旧模型, 新 harness, 真实系统

**旧模型.** 从训练过程中收集一批攻击, 回放给留出的 GPT 版本, 包括直到 GPT-5.2 的早期模型. 攻击在早期 GPT-5 模型上的成功率高得多, 最多接近两倍.

**新 harness.** 让 GPT-Red 对一个基于 GPT-5.4 mini 的 Codex CLI Agent 做端到端红队, 共 10 个留出的数据外泄场景. 这里用的是另一种 harness: 攻击者可以在十个任务之间依次推进, 把前面尝试的经验带到后面, 自己选择下一个攻击哪个任务. 对照是用同一 harness 的冻结 GPT-5.5. 每个攻击者从三个独立的初始状态各跑一次. 简单任务上两者进展相近; 难任务上 GPT-5.5 停滞, GPT-Red 继续推进.

**真实系统.** OpenAI 办公室里有一台由 Andon Labs 制作的 AI 自动售货机 Vendy, 它在 Slack 上和顾客交流, 跟踪库存, 改价格, 按预算和需求订货. 论文给 GPT-Red 一份系统描述, 一个可以反复试攻击的模拟环境, 和三个目标: 把一件高价在售商品的价格改成允许的最低价 0.50 美元; 订一件 100 美元以上的新商品并以 0.50 美元出售; 取消另一位顾客的订单. GPT-Red 三个目标都达成了. 对生产系统使用的攻击, 靠的是伪造元数据, 让消息看起来来自一个受信任的管理员.

## 5. 用 GPT-Red 训练 GPT-5.6

### 5.1. 训练与评测设计

GPT-5.6 在广泛的能力和安全任务上训练, 过程中加入一批由 GPT-Red 在第 3 节环境里生成的提示注入攻击. 论文说明, GPT-Red 的前身版本从 GPT-5.2 起就被用于每一代生产模型的 RL 训练.

论文从几个方向构造评测, 同时考察鲁棒性和过度拒绝.

间接注入:

- **强的同分布攻击.** 用几种启发式从 GPT-Red 的攻击里分出强攻击: 对一组攻击, 测它们对某个防御者多次尝试的平均成功率, GPT-5.6 在较弱的一半上训练, 较强的一半留作评测.
- **留出的数据集和领域.** 对网页搜索, 函数调用等每个高层领域, 训练时留出一个数据集; 另外完整留出 Agent 编程这个领域.
- **留出的红队演练.** 在 2025 年第四季度间接注入挑战的内部镜像上, 让 GPT-Red 带着查询工具从 GPT-5.3 开始逐代攻击. 论文写明, 这项评测没有使用系统级缓解, 测得的攻击成功率比真实攻击者会高.
- **留出的人类攻击.** IPI 2025 挑战的人类函数调用注入数据集.

论文还说明, 所有评测都含有标签噪声, 固有歧义或奖励噪声中的某些, 有时任何模型都达不到 100%.

直接注入: 和第 2 节类似的指令层级场景, 包括同分布的泛化评测和人类红队基准, 对照模型是 GPT-5.1. GPT-5.1 做过大量鲁棒性训练, 但训练里没有 GPT-Red 这类强自动红队的攻击.

## 6. 证据检查与归类

### 6.1. 开发证据与审计证据

按 1.3 的规则逐项看这些证据.

**哪些是开发证据.** 「强的同分布攻击」这一项, 训练集和评测集都来自 GPT-Red, 按攻击强度切成两半. 评测集没有直接参与 GPT-5.6 的训练, 但生成它的是同一个攻击者, 分布相近. 它能说明 GPT-5.6 对 GPT-Red 风格的强攻击更鲁棒, 不能说明对其他来源的攻击同样鲁棒. 留出红队演练里, 攻击者仍是 GPT-Red, 被评测的 GPT-5.6 又是在 GPT-Red 的攻击上训练的. 攻击方和训练数据的来源相同, 这是 1.3 第 2.3 节说的「提出者和评审共享同一个盲点」在安全评测上的版本: 两者都没覆盖到的攻击类别, 这项评测也测不到.

**哪些更接近审计证据.** 留出数据集, 留出领域 (完整的 Agent 编程) 和人类攻击数据集, 和训练分布的距离更远. 其中 56.1% 这个数字最有信息量: 在一个整体没见过的数据集上, 不到六成的攻击被抵挡住. 人类攻击数据集上的 100% 说明这个基准对 GPT-5.6 已经饱和, 失去了区分能力, 不说明人类能想到的攻击都已防住.

### 6.2. 覆盖, 合法性检查与缺口

**覆盖与夸大.** 论文主动写明了两处会让数字偏离现实的地方. 留出红队演练没有系统级缓解, 攻击成功率被高估; 评测含标签噪声和歧义, 部分任务达不到满分. 前者让防御看起来更差, 后者让上限低于 100%. 论文没有给出置信区间, 也没有公开环境级的结果.

**合法性检查本身没有被量化.** 威胁模型由程序和 LLM 检查执行, 论文只给了定性评估. 检查器漏判时, 越界攻击会被算作成功, 攻击能力被高估, 防御者也会在不现实的攻击上被训练; 误判时, 合法攻击被拒, 攻击者在这类攻击上得不到训练信号. 两种错误的比例都没有报告.

**作者写明的覆盖缺口.** 论文结论说, GPT-Red 在多模态环境, 多轮攻击和内容政策越狱上的训练较少. GPT-Red 是内部模型, 不对外部署; 训练数据, 权重和完整失败样本外部无法检查, 能核对的只有论文和官方说明.

### 6.3. 归类: 为什么是 L1, 不是 RSI

按 1.2 的规则, 先问这个循环保留下来的是什么.

**攻击者.** 每轮 RL 更新的是攻击者的参数 $\theta_{\mathrm{att}}$. 查询工具, 终端, 环境集合, 奖励规则在训练中不变. 被保留的改动只在 $\theta$, 是 L1. 它在单次推理中通过查询工具反复修改攻击, 那一部分是 L0.

**防御者.** 同理, 自博弈更新的是防御者参数, 是 L1. GPT-5.6 在包含 GPT-Red 攻击的数据上训练, 也是 L1.

**外层固定了什么.** 威胁模型 (能改哪段, 不能改哪段), 攻击目标的类别, 合法性检查, 奖励函数, 防御者群体的组成, 训练预算, 留出集的划分, 是否采纳一个新模型, 何时训练下一版 GPT-Red, 全部由人决定. 用 1.2 的记号, 改进器 $U$ (提出, 选择, 提交模型更新的程序) 和评判标准 $C$ (奖励, rubric, 合法性规则) 都在循环之外.

**飞轮.** 论文摘要的最后一句是: 期望随着每一代 GPT 模型更鲁棒, 它会为更强的红队 Agent 提供更好的学习信号, 从而形成自我改进的飞轮. 这描述的是跨代际的数据流: 第 $n$ 代 GPT-Red 的攻击训练第 $n$ 代 GPT, 更强的 GPT 又成为第 $n+1$ 代 GPT-Red 的对手. 按 1.2 第 3.3 节的 L3 测试, 忽略这一轮产出的模型, 再问下一轮提出, 选择, 提交改动的方式会不会因为这一轮保留的东西而不同. 论文没有报告这样的变化: 训练算法, 环境构造原则, 奖励设计在代际之间由研究人员维护. 所以飞轮是一条由人运行的, 重复的 L1 训练流程, 不是 L3.

它对 RSI 研究的价值在另一处. 第 1 节的合法性检查, 第 2 节的多防御者和攻击者检查点交叉评估, 第 5 节的留出数据集和领域, 都是在一个大规模的竞争式 L1 循环里把证据放到更新边界之外的具体做法. 2.3 讨论的 SPIN, SPAG, Absolute Zero, R-Zero 规模小得多, GPT-Red 显示了同类循环在前沿模型规模上需要哪些控制.
