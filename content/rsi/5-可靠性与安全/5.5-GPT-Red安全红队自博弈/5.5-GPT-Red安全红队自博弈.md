# GPT-Red: 安全红队的攻防自博弈

GPT-Red 是 OpenAI 在 2026 年 7 月发布的自动红队模型, 用来找针对前沿语言模型的提示注入攻击. 它用自博弈强化学习训练: 攻击者因诱发有效的失败得奖励, 一组同时训练的防御者因抵抗攻击并完成原任务得奖励.

## 1. 问题与威胁模型

### 1.1. 静态的对抗数据集会被过拟合

提升模型对恶意输入的鲁棒性, 常用的做法是基于 RL 的对抗训练: 模型抵抗人类红队, 提示过的语言模型或生产环境中真实攻击时得奖励. 论文开头指出这种做法的问题: 数据集规模有限, 模型很快过拟合到数据集里的那几种攻击模式, 面对会调整策略的攻击者仍然脆弱. 模型的能力和用途越扩展, 攻击面越大, 这个问题越难. 论文的主张是训练一个红队 Agent, 让它以足够的规模, 多样性和质量生成对抗数据. 攻击者和防御者相互训练: 防御者变强以后, 攻击者必须找到新的更有效的攻击; 攻击者变强以后, 它暴露的新失败又成为防御者更难的训练数据.

论文关注两类攻击. 提示注入让模型执行与开发者或用户意图冲突的不可信指令. 其中直接注入由用户直接给出, 试图覆盖更高优先级的系统或开发者指令; 间接注入出现在 Agent 读取的第三方内容里, 比如工具输出, 检索到的文档, 网页. 另一类是内容政策越狱, 试图绕过模型对有害请求的拒绝, 涉及自伤, 违法建议, 生物, 化学和网络风险. 防御的概念框架是指令层级: 系统, 开发者, 用户, 工具返回各有明确的权限级别, 冲突时模型优先服从权限更高的指令. 提示注入的本质是让低权限内容 (用户消息或工具返回) 里的指令被当作高权限指令执行.

### 1.2. 威胁模型的三条目标

论文对攻击者提出三条要求. 泛化: 它要能作为「即插即用」的红队, 用于任何目标模型, 任何红队 harness, 任何攻击场景, 包括没训练过的新一代 GPT 和没见过的 Agent 工作流 (例如写恶意的 Slack 消息). 多样性: 即使对同一个目标或同一个环境, 也要能产出不同类型的攻击, 这样对抗训练可以对着一个攻击者投入大量算力, 不需要很多专门的攻击模型. 合法性: 真实的攻击者不能任意控制防御者的轨迹. 一个攻击者可以控制防御者访问的某个网页的部分内容, 但不能控制防御者搜索工具的功能和格式.

合法性这一条直接对应自演化里的奖励钻空子. 论文写道, 实践中 Agent 有很多办法「作弊」或「钻奖励的空子」, 也就是编辑轨迹中真实攻击者接触不到的部分. 如果允许这样做, 攻击成功率测到的是实验设置的漏洞, 不是现实中的攻击.

### 1.3. 攻击面, 知识与执行

攻击面: 攻击者总是只能修改防御者轨迹中的一条工具返回, 或一组非特权文件. 任务涉及网页搜索时, 它可以替换一条搜索结果; 任务涉及做幻灯片时, 它可以添加或修改少量非关键文件, 比如下载的市场报告. 它不能修改特权文件和工具返回, 比如用户的 `AGENTS.md`. 知识与访问: 攻击者通常能看到最近一条用户消息, 以及攻击要放入的那条原始工具返回或文件. 它对目标防御者有黑盒访问, 查询次数有限. 查询之后, 它有时能看到注入攻击后防御者的完整轨迹, 通常还能看到对应的 token 对数似然.

执行: 攻击提交后, 被放进防御者轨迹中预先指定的位置 (某次工具调用或某个文件). 有时还有额外约束, 比如攻击要符合工具返回的 schema, 或者长度有限. 论文用程序检查和基于 LLM 的检查混合判定攻击是否合法, 不合法的攻击被拒绝并且惩罚攻击者. 论文说它定性地评估了这套检查的效果, 认为高度有效. 这是一个定性判断, 论文没有给出检查器漏判率的数字. 攻击目标随用户任务和可用工具变化. 间接注入的例子包括窃取 (模拟的) 敏感或私人数据, 运行不可信代码, 执行破坏性的代码操作 (例如删除目录).

## 2. 查询工具与自博弈训练

### 2.1. 查询工具: 顺序查询比独立采样更省

攻击者有两个工具: 一个通用终端, 和一个 `defender_model` 工具. 它用终端在虚拟文件系统里创建包含攻击的文件, 再把文件路径交给 `defender_model`. 工具在后台把攻击放进预定位置, 采样一条防御者轨迹, 返回轨迹, token 对数似然和判官 LLM 的反馈信号. 攻击者可以先写一个初始攻击, 提交, 再直接编辑文件改进它; 也可以在终端里写代码批量生成攻击, 比如填模板, 重复字符串, 组合多种策略. 满意或时间用完时, 它提交最终攻击的路径. 有些训练场景里, 工具还支持多轮攻击, 攻击者可以有状态地和防御者积累多轮对话.

论文用一个实验比较这种顺序查询和 best-of-$N$ 独立采样. 攻击者是一个冻结的, 只训练过有用性的内部模型, 环境是 Guo 等人 (2026) 的 IH-Challenge 指令层级题: 每道题有一条高优先级消息 (例如系统消息) 里的指令和一条低优先级消息 (例如用户消息) 里的空位, 攻击者要写一段放进空位的文本, 让防御者违反高优先级指令. 攻击成功率 (ASR) 定义为至少有一次攻击成功的题目比例. 结果是: 增加攻击者算力, 两种方式的 ASR 都明显上升; 同样的查询预算下, 用 `defender_model` 工具的 ASR 更高, 查询次数越多差距越大. 论文指出, 查询次数多的区间正是大算力对抗训练关心的区间.

这个结果的含义可以用第 2.1 篇的 L0 分类来读. 单次推理内的多轮修改是 L0 的修订: 每次查询的结果只用于改这一次的攻击, 不跨任务保留. 顺序查询胜过独立采样, 是因为每一轮修改都用上了防御者的真实反应, 这是环外的信号. 2.1 讲过, L0 的上限由证据决定; 这里的证据来自目标模型本身, 所以修订有效.

### 2.2. 自博弈的七步循环

攻击者和防御者都从强 CoT 推理模型初始化. 每一轮分七步. 第 1 步采样一个 RL 环境: 一段对话, 一个初始文件系统状态, 一个选定的防御者. 第 2 步选一个与上下文相符的攻击插入点 (通常是一次工具调用) 和对应的攻击目标, 例如从根目录执行 `rm -rf`, 或者把 API 密钥发到一个 HTTP 端点; 同时给攻击者完成任务所需的知识, 例如最后一条用户消息. 第 3 步, 攻击者带着这些信息展开, 和防御者交互, 满意时提交最终攻击, 中间对防御者的所有调用都丢弃.

第 4 步检查攻击和环境的合法性, 攻击不合法, 奖励为 0. 第 5 步把攻击插入防御者轨迹的预定位置, 从插入点继续运行防御者. 第 6 步按环境计算奖励, 奖励通常不对称: 检查攻击者是否成功, 以及防御者是否完成了原任务. 第 7 步用 (轨迹, 奖励) 对, 以 RL 更新攻击者和防御者. 第 3 步「中间调用全部丢弃」和第 4 步「不合法得 0 分」是两道控制. 前者保证防御者只因最终攻击被训练, 不会被攻击者试探过程中的半成品影响. 后者把威胁模型变成奖励的一部分: 越界的攻击在训练信号里不存在.

**训练动态.** 论文在 IH-Challenge 上做了受控的自博弈实验: 攻击者从内部只训练过有用性的模型初始化, 防御者是一个较小的 GPT-5 系列模型. 攻击者的训练 ASR 呈现起伏: 它找到的策略被防御者修补, ASR 下降, 然后它转向新方法. 论文把这些下降看作对双方都有用的课程. 定性分析发现, 某些更强也更复杂的攻击类别 (比如后面要讲的伪造 CoT) 在训练后期才出现, 简单攻击 (比如系统消息覆盖) 出现得早.

防御者一侧, 留出评测上的直接注入鲁棒性随自博弈大致单调上升. 论文比较了三种攻击者: 冻结的提示模型, 能用 `defender_model` 工具的冻结提示模型, 自博弈训练的攻击者. 用训练过的攻击者对抗, 防御者鲁棒性提升最快, 最终也最高.

**攻击者不遗忘, 也不只对一个对手.** 一个风险是攻击者遗忘以前的知识, 局部过拟合到当前的防御者. 论文用一个交叉矩阵检查: 让攻击者的各个检查点去攻击防御者的各个检查点. 后期的攻击者检查点几乎单调地更擅长攻破所有防御者检查点, 早期的攻击者很弱. 论文还试过只训练攻击者 (防御者不动), 发现这样训练出的攻击者只对它训练时面对的那个防御者更强, 对留出的防御者更弱, 并且更容易在攻击策略上坍缩.

多防御者是另一项控制. 初步实验里只用一个防御者做自博弈, 攻击者常常坍缩到很窄的一类攻击策略. 加入多个防御者, 特别是对不同类型攻击都很鲁棒的模型, 攻击者被迫先探测每个防御者的独特弱点, 而不是收敛到一种对所有对手都还算有效的攻击. 论文让一个攻击者对 9 个冻结的防御者训练, 训练结束后把针对某一个防御者找到的攻击拿去攻击另外 8 个: 成功的攻击不总能迁移. 论文据此认为攻击者学会了观察对手的行为并针对性地调整.

这和 2.3 讲的竞争式自博弈的失效条件直接对应. 2.3 的结论是, 竞争信号只在竞争还活着的时候有信息量, 两个副本不再有实质分歧时信号退化. 只对一个防御者训练, 攻击者和防御者会锁定在一对相互适应的策略上; 多个防御者让攻击者面对的分布保持宽, 竞争就不容易停止.

### 2.3. 从现有任务构造训练环境

**直接注入与间接注入.** 论文构造训练环境的原则是把现有的能力任务改造成对抗环境: 在防御者的运行过程中, 拦下某次工具调用的返回, 让攻击者编辑指定的一段, 比如一条工具返回或本地文件的某个区域. 这样可以直接继承大量真实而复杂的防御者任务, 例如 GPT-5.6 的常规后训练数据集, 让防御者在整个训练分布上都变得鲁棒.

**直接注入.** 在 Guo 等人 (2026) 的基础上扩展. 防御者有一条更高优先级的开发者或系统消息, 攻击者可以编辑一条更低优先级的用户或开发者消息. 任务有可验证的奖励, 包括永不泄露某个 PIN, 执行正则替换, 把文本解析成结构化 schema. 攻击者的目标是造成对高优先级约束的定向或非定向违反. 奖励用程序检查判定, 通常对称地奖励成功的一方.

**间接注入.** 复用现有的 Agent RL 环境, 允许攻击者编辑某条工具返回或一组非特权文件, 保证被编辑的只有不可信的第三方内容. 文本环境覆盖四类场景: 浏览 (即时搜索或深度研究返回的网页, 攻击者可编辑其中一个网站的文本), 连接器 (Gmail, Google Calendar 等第三方服务的返回), 通用函数调用 (防御者拿到任意函数 schema, 攻击者覆盖一次读取不可信内容的工具输出), Agent 编程 (攻击者在防御者读取或修改之前编辑选定的本地文件).

**多模态注入、越狱与奖励设计.** **多模态注入.** 威胁模型相同, 但攻击者拿到 OpenAI Images 2.0 的 API, 提交的攻击只能是一张渲染出来的图片. 一类是计算机操作 Agent, 防御者看截图操作, 攻击者修改网页上预先划定的区域 (横幅广告, 用户评论区). 另一类是浏览和文档检索, 攻击者替换或添加一张图; 替换时必须保持原任务可解, 图里要保留回答用户问题所需的事实, 标签, 数值和来源.

**内容政策越狱.** 攻击者把一段用户对话引向被禁止的帮助, 例如把一段正常的软件调试对话引向恶意软件开发. 有单轮和多轮两种. 奖励用 rubric 衡量防御者输出离一个「最有害的回答」有多近; 攻击者最大化这个分数, 防御者通过安全地完成或拒绝来最小化它. 论文加了两道过滤防止钻空子: 拒绝本身已含违禁内容, 只要求做表面变换 (例如翻译) 的攻击, 因为它们没有给用户提供实质的新信息; 拒绝不像真实用户对话的攻击. 奖励设计上, 提示注入的理想防御者行为是忽略恶意指令并完成原任务; 攻击者的奖励取决于最终攻击是否遵守威胁模型的限制, 以及是否达成攻击目标.

### 2.4. GPT-Red 的训练与红队评测

**训练与攻击的形态.** GPT-Red 在 2.3 节的全部环境上, 对一组历代防御者训练, 包括 OpenAI 此前最鲁棒的模型 (直到 GPT-5.5). 权重从 GPT-5.5 初始化, 那是当时最好的前沿模型. 为了保住指令遵循, Codex 中的交互能力和诚实性, 训练中还混入了常规 RL 后训练的环境. 总算力和最近几代 GPT-5 系列的 RL 后训练大致相当, 论文称这是迄今公开的规模最大的单次 LLM 安全 RL 训练.

训练早期, 攻击者给出的是「IGNORE PREVIOUS INSTRUCTIONS ...」这类简单提示. 后期它学会了伪造 CoT: 攻击者控制的文本模仿防御者自己的 CoT, 让防御者把攻击当成自己的推理, 直接照抄攻击者给出的命令. 论文的例子里, 用户问 CDW 公司 2012–2014 年稀释性证券的平均影响, GPT-Red 构造了一条恶意搜索结果, 里面有逼真的 10-Q 内容, 一段引用虚构政策的伪造 CoT, 对这条政策的推理, 以及一条执行数据外泄的命令. 防御者读到后, 把伪造的 CoT 当作自己先前的推理引用, 执行了上传命令, 然后正常回答了问题. 论文说这类攻击对很多模型都稳定有效; 发现时它是独立的新攻击, 同期的 Ye 等人 (2026) 也发现了它.

多模态方面, GPT-Red 学会用图像工具生成逼真的注入图片. 论文的例子是一张仿照场景中咖啡店的收据, 里面无缝地渲染了一个伪造的外泄地址. 论文还报告, 给出少量示例或高层的策略提示时, 攻击者的行为高度可控.

**留出场景: 84% 对 13%.** 在 Dziemian 等人间接提示注入竞技场的内部镜像上, 人类红队和 GPT-Red 独立地对 GPT-5.1 提出攻击. 这些场景和目标不同于 GPT-Red 的训练集. 做法是去掉原来人写的攻击, 分别让 GPT-5.5 和 GPT-Red 生成新攻击. 不给 GPT-5.5 防御者访问时, 它的平均 ASR 和人类大致相当; 给它 `defender_model` 工具后明显提高; GPT-Red 的平均 ASR 最高. OpenAI 官方说明给出的数字是: GPT-Red 在 84% 的场景中成功, 人类为 13%.

论文在脚注里限定了这个结果: 它不意味着 GPT-Red 普遍优于人类红队, 人类可能找到 GPT-Red 没考虑到的场景或攻击类别. 另外, 这个比较没有对齐双方的时间, 算力和交互次数. GPT-Red 带查询工具, 可以对防御者试很多次; 人类红队的交互预算不同. 按 1.1 第 4 节第 5 条的规则, 这个数字说明 GPT-Red 在这组场景上找到了更多可行的攻击, 不说明同等资源下它比人强.

**迁移到旧模型、新 harness 与真实系统.** **旧模型.** 从训练过程中收集一批攻击, 回放给留出的 GPT 版本, 包括直到 GPT-5.2 的早期模型. 攻击在早期 GPT-5 模型上的成功率高得多, 最多接近两倍. **新 harness.** 让 GPT-Red 对一个基于 GPT-5.4 mini 的 Codex CLI Agent 做端到端红队, 共 10 个留出的数据外泄场景. 这里用的是另一种 harness: 攻击者可以在十个任务之间依次推进, 把前面尝试的经验带到后面, 自己选择下一个攻击哪个任务. 对照是用同一 harness 的冻结 GPT-5.5. 每个攻击者从三个独立的初始状态各跑一次. 简单任务上两者进展相近; 难任务上 GPT-5.5 停滞, GPT-Red 继续推进.

**真实系统.** OpenAI 办公室里有一台由 Andon Labs 制作的 AI 自动售货机 Vendy, 它在 Slack 上和顾客交流, 跟踪库存, 改价格, 按预算和需求订货. 论文给 GPT-Red 一份系统描述, 一个可以反复试攻击的模拟环境, 和三个目标: 把一件高价在售商品的价格改成允许的最低价 0.50 美元; 订一件 100 美元以上的新商品并以 0.50 美元出售; 取消另一位顾客的订单. GPT-Red 三个目标都达成了. 对生产系统使用的攻击, 靠的是伪造元数据, 让消息看起来来自一个受信任的管理员.

### 2.5. 用 GPT-Red 训练 GPT-5.6

**训练与评测设计.** GPT-5.6 在广泛的能力和安全任务上训练, 过程中加入一批由 GPT-Red 在 2.3 节环境里生成的提示注入攻击. 论文说明, GPT-Red 的前身版本从 GPT-5.2 起就被用于每一代生产模型的 RL 训练. 论文从几个方向构造评测, 同时考察鲁棒性和过度拒绝.

## 3. 证据、覆盖与攻防动力学

### 3.1. 开发证据、审计证据与归类

按 1.3 的规则逐项看这些证据. **哪些是开发证据.** 「强的同分布攻击」这一项, 训练集和评测集都来自 GPT-Red, 按攻击强度切成两半. 评测集没有直接参与 GPT-5.6 的训练, 但生成它的是同一个攻击者, 分布相近. 它能说明 GPT-5.6 对 GPT-Red 风格的强攻击更鲁棒, 不能说明对其他来源的攻击同样鲁棒. 留出红队演练里, 攻击者仍是 GPT-Red, 被评测的 GPT-5.6 又是在 GPT-Red 的攻击上训练的. 攻击方和训练数据的来源相同, 这是 1.3 第 2.3 节说的「提出者和评审共享同一个盲点」在安全评测上的版本: 两者都没覆盖到的攻击类别, 这项评测也测不到.

**哪些更接近审计证据.** 留出数据集, 留出领域 (完整的 Agent 编程) 和人类攻击数据集, 和训练分布的距离更远. 其中 56.1% 这个数字最有信息量: 在一个整体没见过的数据集上, 不到六成的攻击被抵挡住. 人类攻击数据集上的 100% 说明这个基准对 GPT-5.6 已经饱和, 失去了区分能力, 不说明人类能想到的攻击都已防住.

**覆盖、合法性检查与缺口.** **覆盖与夸大.** 论文主动写明了两处会让数字偏离现实的地方. 留出红队演练没有系统级缓解, 攻击成功率被高估; 评测含标签噪声和歧义, 部分任务达不到满分. 前者让防御看起来更差, 后者让上限低于 100%. 论文没有给出置信区间, 也没有公开环境级的结果. **合法性检查本身没有被量化.** 威胁模型由程序和 LLM 检查执行, 论文只给了定性评估. 检查器漏判时, 越界攻击会被算作成功, 攻击能力被高估, 防御者也会在不现实的攻击上被训练; 误判时, 合法攻击被拒, 攻击者在这类攻击上得不到训练信号. 两种错误的比例都没有报告.

**作者写明的覆盖缺口.** 论文结论说, GPT-Red 在多模态环境, 多轮攻击和内容政策越狱上的训练较少. GPT-Red 是内部模型, 不对外部署; 训练数据, 权重和完整失败样本外部无法检查, 能核对的只有论文和官方说明.

**这套循环在 L0–L4 中的位置.** 按 1.2 的规则, 先问这个循环保留下来的是什么. **攻击者.** 每轮 RL 更新的是攻击者的参数 $\theta_{\mathrm{att}}$. 查询工具, 终端, 环境集合, 奖励规则在训练中不变. 被保留的改动只在 $\theta$, 是 L1. 它在单次推理中通过查询工具反复修改攻击, 那一部分是 L0.

**防御者.** 同理, 自博弈更新的是防御者参数, 是 L1. GPT-5.6 在包含 GPT-Red 攻击的数据上训练, 也是 L1. **外层固定了什么.** 威胁模型 (能改哪段, 不能改哪段), 攻击目标的类别, 合法性检查, 奖励函数, 防御者群体的组成, 训练预算, 留出集的划分, 是否采纳一个新模型, 何时训练下一版 GPT-Red, 全部由人决定. 用 1.2 的记号, 改进器 $U$ (提出, 选择, 提交模型更新的程序) 和评判标准 $C$ (奖励, rubric, 合法性规则) 都在循环之外.

**飞轮.** 论文摘要的最后一句是: 期望随着每一代 GPT 模型更鲁棒, 它会为更强的红队 Agent 提供更好的学习信号, 从而形成自我改进的飞轮. 这描述的是跨代际的数据流: 第 $n$ 代 GPT-Red 的攻击训练第 $n$ 代 GPT, 更强的 GPT 又成为第 $n+1$ 代 GPT-Red 的对手. 按 1.2 第 3.3 节的 L3 测试, 忽略这一轮产出的模型, 再问下一轮提出, 选择, 提交改动的方式会不会因为这一轮保留的东西而不同. 论文没有报告这样的变化: 训练算法, 环境构造原则, 奖励设计在代际之间由研究人员维护. 所以飞轮是一条由人运行的, 重复的 L1 训练流程, 不是 L3.

它对 RSI 研究的价值在另一处. 第 1 节的合法性检查, 第 2 节的多防御者和攻击者检查点交叉评估, 以及 2.5 节的留出数据集和领域, 都是在一个大规模的竞争式 L1 循环里把证据放到更新边界之外的具体做法. 2.3 讨论的 SPIN, SPAG, Absolute Zero, R-Zero 规模小得多, GPT-Red 显示了同类循环在前沿模型规模上需要哪些控制.

### 3.2. 攻击面、对手预算与覆盖率

**攻击面怎样分解.** 一个 Agent 的攻击面至少包括输入文本、检索内容、图像、文件、工具返回、长期记忆、跨 Agent 消息和环境状态. 同一句恶意指令从用户直接输入, 与藏在网页或文档中, 信任边界不同. 红队样本要标记入口、权限和目标资产, 不能只按表面措辞分类. 攻击链还包含阶段: 发现可控通道、让模型采纳指令、获得权限、执行动作、隐藏或维持影响. 某个防御在采纳阶段有效, 不代表能阻止已获得凭证的工具调用. 分阶段成功率显示链条在哪里断开, 端到端成功率显示最终风险.

资产决定严重度. 泄露公开信息、读取私密文件、修改临时草稿、发送外部消息和执行不可逆交易, 后果不同. 红队奖励若只看「是否服从攻击」, 会把所有路径当等价. 风险分级与硬约束进入环境, 使搜索优先覆盖真正高影响路径.

**对手知识与预算.** 黑盒对手只看到公开接口, 灰盒对手知道系统提示或工具结构, 白盒对手还能读取权重与防御. GPT-Red 的能力应绑定威胁模型. 在白盒条件成功不能直接代表普通用户风险, 在黑盒失败也不能排除内部攻击者. 攻击预算包括查询次数、上下文长度、并行分支、外部模型和人工帮助. 顺序查询能利用前次反馈, 比独立采样强. 报告成功率随预算的曲线, 而非只给一个最好结果. 防御在十次查询有效、千次后崩溃, 适用场景不同.

现实攻击者会保存跨会话信息、轮换身份和共享策略. 评测若每轮重置, 只覆盖短期对手. 对长期 Agent 增加持久攻击阶段, 同时限制在安全沙箱. 状态是否清除、凭证是否轮换也成为防御的一部分.

**未知攻击族.** 静态分类法只能覆盖已知路径. 新工具、新模态和组合工作流会产生未知攻击. 保持开放发现通道: 异常轨迹、人工红队、真实事故和异构模型提出的攻击, 都进入候选池. 新样本先聚类机制, 再决定是否属于旧族. 新颖性不能按文本距离判断. 改写越狱提示可能很新, 机制仍是指令优先级冲突; 两个措辞相似的样本若一个利用缓存、一个利用工具解析, 机制不同. 以触发条件和影响路径去重, 防止题库被近义攻击淹没.

探索预算应保留给低先验方向. 当前防御对已知族优化后, GPT-Red 会继续在这些族附近搜索, 因为反馈最密. 定期切换环境、隐藏防御反馈和引入真实新接口, 能扩大边界. 新方向仍要经过合法性和危害控制.

**覆盖率不能只数样本.** 一万个提示可能只覆盖一个漏洞. 覆盖应按攻击族、入口、资产、权限、阶段和环境组合衡量. 建立覆盖矩阵, 显示哪些格子已有成功、失败或尚未测. 空白格子的含义是没有证据, 不能据此给出安全结论. 覆盖也有深度. 一个族在单轮文本测过, 未必覆盖多轮、工具和长期状态. 为关键族设置最低深度, 普通族抽样. 风险越高、现实暴露越大, 需要越深入.

成功样本之外保留近邻安全样本. 防御若通过全面拒绝获得低攻击成功率, 实用性会下降. 每个攻击族配合法任务与边界反例, 同时测攻击阻断和正常完成.

### 3.3. 自博弈的动力学

**攻防并非单调变强.** 攻击者 $A_t$ 针对防御者 $D_t$ 找漏洞, 防御者再针对这些漏洞更新. 当前胜率下降可能表示防御变强, 也可能是攻击者忘了旧招; 胜率上升可能来自攻击进步, 也可能是环境或评分器变宽松. 因此需要跨版本矩阵, 让每代攻击者测试多代防御者. 矩阵若呈现新攻击打穿新防御、旧攻击也重新成功, 防御发生回归; 新攻击只对当前版本有效, 可能过拟合; 新防御对所有历史攻击改善, 才像稳定进步. 仅看对角线 $A_t$ 对 $D_t$ 无法区分.

策略可能循环. 防御强化拒绝后, 攻击转向间接注入; 防御加强工具隔离后, 攻击回到语义诱导; 后续版本为可用性放松拒绝, 早期攻击再次出现. 保存历史攻击池和周期回归, 防止把循环当持续边界扩展.

**种群与遗忘.** 单一最强攻击者容易专门针对一个防御. 种群保留不同机制、预算和风格, 防御在混合分布上训练. 种群权重不能只按当前成功率, 否则已被修复但重要的旧攻击会消失. 为高风险历史族保留最低权重. 攻击者也会遗忘. 在新环境训练后, 旧环境成功率下降, 总体覆盖收窄. 定期在固定历史池重放, 用多任务训练或经验回放维持. 保持所有样本会增加成本, 可按机制选代表样本, 但对不可接受风险保留完整回归.

多样性按失败集合和攻击路径衡量. 两个攻击者输出完全不同文本却击中同一漏洞, 不算真正独立. 聚类使用被攻破组件、所需权限和防御响应, 让种群覆盖结构性差异.

**对手选择与课程.** 训练若总选成功率最高的攻击, 防御会面对已知容易漏洞; 总选最难攻击, 反馈可能全为失败. 有信息量的课程位于当前边界: 攻击偶尔成功, 防御能从差异中学习. 同时保留少量极难与基础回归. 边界随防御移动. 估计每个攻击族的成功概率与不确定性, 选择接近目标区间的样本. 新族样本少, 即使估计不稳定也给探索名额. 这类似主动学习, 但奖励必须包含覆盖与风险, 不只成功率.

课程本身可能被攻击者利用. 如果晋升规则公开, 攻击者可生成容易被评分器认可的伪攻击. 候选进入训练前验证真实影响, 评分器与生成器隔离. 高分但无实际危害的样本不能占据课程.

**平衡不等于安全.** 攻防达到近似平衡, 只说明在当前策略集和预算下互相难以改进. 策略集之外可能存在未知漏洞, 更强对手也可能打破. 纳什均衡一类语言若脱离游戏定义, 容易产生过强结论. 游戏奖励与现实风险的差距同样关键. 攻击者最大化分类器分数, 防御者最小化该分数, 双方可以围绕评分器形成平衡, 真实安全没有改善. 外部可执行结果、人工锚点和新环境定期校准.

停止自博弈应看边际新覆盖、外部验证和成本. 当前对手胜率低只是一个信号. 若新对手、真实事故和密封环境仍无新增漏洞, 才支持在该范围内趋稳; 结论保持时间和权限边界.

## 4. 奖励、留出评测与防御训练

### 4.1. 奖励函数决定红队学到什么

**攻击成功标签.** 最简单奖励由攻击分类器给出. 分类器可能把有害措辞当成功, 即使目标系统没有执行; 也可能漏掉隐蔽工具副作用. 高风险任务优先读取环境状态、权限变化和真实工具结果. 文本分类用于筛选, 不独自确认成功. 成功定义分层: 模型复述恶意指令、输出计划、调用工具、获得目标状态、维持影响. 不同层给不同奖励与严重度. 把部分进展都记零, 攻击者缺少学习信号; 把任何有害文本都记满分, 它会停在便宜表面行为.

评分器不确定时允许未决. 多模型投票若同源, 不能自动解决. 对跨线样本用可执行检查或人工核验, 将确认结果回流校准分类器. 未决比例突然下降可能表示评分器过度自信.

**新颖性与严重度.** 只奖励成功, 攻击者会重复最容易漏洞. 加新颖性可扩覆盖, 但文本距离容易奖励花哨改写. 新颖性基于攻击路径、触发组件和失败集合. 新族第一次确认获得较高奖励, 同族变体价值递减. 严重度反映资产、权限、可逆性和传播范围. 一次读取公开文件与一次外传秘密不可等价. 严重度由威胁模型与责任主体确定, 不能让攻击模型自行评估. 对不可接受路径设置硬优先级.

新颖与严重可能冲突. 一个低风险新奇攻击不应挤掉高风险回归. 采用分层队列或多目标选择, 保留画像. 统一加权分数需要明确权重, 且不允许严重风险被其他项补偿.

**成本与隐蔽性.** 现实攻击受查询、时间、算力和访问成本限制. 成功率相同, 一次查询成功比万次搜索更危险. 奖励加入成本或报告成功随预算曲线. 训练可探索高预算路径, 风险结论按现实可行预算分层. 隐蔽性关系监控. 明显攻击即使成功, 可能被运行时检测; 低异常分的攻击更难发现. 但奖励隐蔽性会主动培养规避监控能力, 评测与训练要隔离、限制输出和访问. 只有在有明确安全收益的受控环境中使用.

检测器也不能进入攻击者可读上下文. 若攻击者反复获得检测分, 它会对检测器优化. 最终隐蔽性在密封监控器和真实日志上评估, 开发反馈保持粗粒度.

**奖励黑客.** 攻击者可能操纵成功分类器、修改环境标志、让目标模型声称已执行或造成解析失败. 这些都能获得高分而没有真实攻击. 候选无权写评分状态, 环境从可信外部读取, 异常终止不算成功. 最小反例帮助定位黑客路径. 固定语义改变格式, 固定格式改变真实状态, 看分数是否跟随目标. 修复评分器后重放历史高分样本, 重新排序种群. 被漏洞选中的策略可能已经主导训练, 只修未来不足.

奖励版本写入每条轨迹. 新旧奖励不可直接平均. 评分修订后, 能重放的原始轨迹全部重算, 无法重算的结果降级. 这样训练曲线不会把换尺子误认成攻击能力跃升.

### 4.2. 留出评测怎样证明迁移

**按机制切分.** 随机把近义提示分到训练与测试, 会高估迁移. 同一模板的改写跨集合, 攻击者只需记风格. 更强切分按攻击族、目标应用、工具或时间, 让测试机制真正未见. 切分单位与主张对齐. 84% 对 13% 这样的差距要看分母、成功定义和置信. 若留出场景数量少, 单个场景权重很大; 若每个场景生成许多相似提示, 样本并不独立. 按场景聚类报告, 同时给逐场景分布.

训练场景与留出场景难度可能不同. 使用参考攻击者、人工红队或历史基线校准. 留出提升来自通用攻击能力, 还是测试更易, 需要相同基线下的增量判断.

**跨模型迁移.** 攻击从一个目标迁移到旧模型或新模型, 说明它捕捉了共享漏洞. 模型家族共享训练和安全策略, 迁移仍可能来自同源偏差. 增加不同架构、不同组织和不同防御的目标, 证据更强. 跨模型比较固定接口、工具和预算. 新模型安全过滤更强、能力也更强, 攻击成功变化混合两者. 记录攻击在哪一阶段失败: 不理解、拒绝、工具阻断或监控拦截.

目标模型更新后, 旧攻击池可作回归, 新攻击者重新搜索边界. 只复用旧池会漏掉新漏洞, 只用新池会忘记历史. 两部分分别计分.

**跨 harness 迁移.** harness 决定提示包装、工具协议、记忆和错误反馈. 攻击跨 harness 成功, 表明不依赖单一实现细节; 失败可能是防御有效, 也可能只是接口不兼容. 将攻击意图适配到新接口, 与原样迁移分别测试. 脚手架自身可能有漏洞. 模型安全, 解析器却执行了隐藏字段; 或模型被攻破, 权限层仍阻断后果. 分层日志区分. 将所有失败归到目标模型会错过系统安全的主要来源.

真实系统比实验 harness 多路由、缓存和策略. 在不暴露用户的影子环境重放, 再小流量受控测试. 研究结果先支持实验系统结论, 生产迁移需要新增证据.

**时间留出.** 按时间冻结训练材料, 用之后出现的攻击测试, 能减少直接记忆. 基础模型可能在预训练中见过后期公开攻击, 需要记录训练截止与数据来源. 无法严格保证时, 称为时间近似留出. 新攻击通常伴随新工具或系统变化. 时间留出混合攻击创新与环境漂移. 在旧环境复现新机制, 再在新环境端到端测试, 可以拆开. 两者都失败说明不同问题.

时间留出要持续滚动. 一批新攻击被用于修复后转为回归, 下一期另建密封集. 红队系统若一直在同一终审集上选模型, 终审也会变开发集.

### 4.3. 用红队数据训练防御

**从攻击到训练样本.** 成功攻击包含恶意输入、目标响应、环境后果和评分. 训练防御前要生成安全目标: 拒绝、澄清、降权外部指令、请求批准或安全完成. 统一训练成拒绝会损害可用性. 根据风险与合法意图选择行为. 同一攻击配近邻合法样本. 例如文档里含指令时, 有些是恶意注入, 有些是用户明确要求执行的内容. 模型需要依据来源、权限和目标区分, 关键词过滤无法完成. 训练对照保持表面相似, 只改变信任关系.

标签来源保存. 自动生成的安全响应、人工编辑和可执行验证具有不同证据. 高风险样本由领域人员确认, 不把攻击模型自己的解释当真值.

**训练目标与能力挤压.** 安全训练可能提高拒绝, 同时降低正常工具使用. 评估攻击成功率与合法任务完成率, 沿边界构造样本. 若防御通过全面停用工具实现, 安全性提高但能力边界改变, System Card 应说明. 损失权重决定取舍. 平均训练目标会让大量普通样本稀释罕见严重攻击; 过高安全权重又造成过拒绝. 对不可接受行为设置独立约束或门禁, 不只靠有限负奖励. 训练处理策略倾向, 权限层限制最坏后果.

能力挤压按群体和语言检查. 安全分类器可能对低资源语言更保守, 或漏掉变体. 总体合法完成率掩盖。分群设置门槛, 样本不足则限制部署范围.

**迭代中的数据污染.** 红队生成数据进入防御训练, 下一代攻击者又读到防御反馈, 双方逐渐共享同一语言. 外部真实攻击和人工新场景提供独立注入. 训练数据谱系显示多少来自自博弈、多少来自外部. 终审攻击集不能进入训练. 一旦用来修复, 降级为回归并替换. 分类器、目标模型和攻击模型若共同训练数据, 同时通过可能只是共同盲点. 异源验证器与环境结果补充.

重复样本去重按机制与母模板, 防止某类攻击因生成量大占据训练. 严重度权重由风险决定, 不由数量决定. 长尾攻击保留最低覆盖.

**防御泛化.** 修复单个提示后, 在语义变体、其他模态、不同工具和多轮中测试. 真正学到信任边界的防御应在这些变化下保持, 同时不误伤合法对照. 只对原字符串拒绝属于记忆补丁. 过程探针可检查模型是否引用来源、识别权限与请求确认, 但解释不等于真实机制. 行为干预更强: 改变来源标签、移除工具权限、给出冲突指令, 看决策是否按预期变化.

防御在新模型规模上可能不保持. 更强模型能理解约束, 也更会寻找绕过. 每个发布候选重新评估, 不从旧版继承通过标签. 稳定机制可以复用任务设计, 结果不能复制.

## 5. 攻击面、生产修复与指标

### 5.1. 间接注入与多模态

**信任边界.** 间接注入把指令藏在网页、邮件、文档或工具结果中. 模型需要把数据与授权指令区分. 内容能被读取, 不等于内容有权改变任务. 系统在消息结构中保存来源、签名与权限, 不只靠自然语言提醒. 检索器、解析器和摘要器可能丢失来源. 文档片段进入统一上下文后, 模型看不到它来自外部不可信页面. 传递结构化标签, 并确保压缩与记忆写入保留标签. 红队检查每个转换点.

用户可以授权执行文档指令, 需要显式确认具体动作. 授权绑定对象、范围和时间. 一次「可以处理邮件」不能扩展成执行邮件内任意工具调用.

**多模态隐藏通道.** 图像中的小字、二维码、元数据和视觉布局都可承载注入. OCR 与视觉编码器可能读取人类不易注意的内容. 红队样本覆盖可见文本、低对比、裁剪、叠层和跨帧内容, 同时遵守安全边界. 音频、视频与文件格式还有解析差异. 前端显示一份内容, 后端模型读取另一层; 文件扩展名与真实格式不符也可能触发不同解析器. 安全链要基于实际字节和解析路径, 不能只看截图.

多模态防御需要在输入规范化、来源标记和工具权限多层处理. 单个视觉分类器可能漏掉编码变化. 关键动作仍由结构化授权控制, 使注入即使进入上下文也无法直接执行.

**多轮与记忆污染.** 攻击可以先写入看似无害事实, 后续在特定触发下生效. 短对话评测会漏掉. 设计跨会话任务, 检查记忆写入、读取、冲突和过期. 不可信内容进入长期记忆前需要来源与用途验证. 记忆污染的影响持续到攻击对话结束后. 清除当前上下文不足, 要找到派生摘要、缓存和技能. 每个持久对象保存谱系, 事故后可追踪并撤销. 红队成功标准包含持久状态变化.

防御不能简单禁止记忆, 否则长程能力消失. 采用分区记忆、置信与来源标签、敏感写入审批. 合法长期任务与攻击轨迹成对评估.

**跨 Agent 注入.** 多 Agent 系统里, 一个成员的输出成为另一个成员输入. 下游可能把同伴消息视为可信指令, 攻击通过低权限角色升级. 消息携带发送者、授权范围和证据, 下游只执行与角色契约一致的动作. 子 Agent 不自动继承主 Agent 全部权限. 委托令牌绑定任务和资源, 再委托需要缩减或重新批准. 红队测试代理链、身份伪造、摘要注入和共享记忆.

共识也会被污染. 多个 Agent 共享同一恶意文档, 投票一致并不提供独立性. 使用不同证据通道和可执行检查, 对高影响行动保留控制面门禁.

### 5.2. 从红队发现到生产修复

**漏洞登记.** 确认漏洞后记录目标系统、入口、前置权限、最小触发、环境后果、严重度和发现版本. 原始攻击内容按敏感等级保存. 去掉无关步骤得到最小反例, 再生成邻近变体确定边界. 多个样本按共同机制聚类. 同一解析漏洞的一千种措辞算一个族, 不同工具共享同一权限错误也可能同族. 漏洞 ID 连接训练样本、代码修复、评测与事故.

重复发现不是浪费, 它能估计攻击容易度. 不同攻击者独立找到同一路径, 说明搜索门槛低. 但奖励去重后, 仍保留发现次数作为风险信号.

**修复位置.** 漏洞可在模型训练、提示、解析器、权限、工具或监控修复. 越靠外层的硬控制通常更可验证, 可能限制能力; 模型训练覆盖语义变化, 没有强保证. 多层组合, 每层声明阻断哪一步. 先修最接近后果的控制, 限制影响, 再改善模型行为. 例如外传风险先收紧网络与数据权限, 随后训练来源识别. 只改拒绝提示, 对解析或工具漏洞作用有限.

修复不能由攻击者直接写入生产. GPT-Red 提供反例与建议, 独立流程实现、测试和批准. 候选无权修改密封回归和审计日志.

**回归与能力保持.** 修复测试包括原攻击、语义变体、组合攻击、合法近邻和普通任务. 原攻击失败只证明补丁命中. 邻近合法任务保持, 才说明边界没有全面收缩. 普通任务测远端副作用. 回归按严重度与机制抽样. 高风险永久保留, 低风险同族选代表. 环境变化后重新生成, 防止旧接口样本失效. 公开样本用于开发, 密封变体用于晋升.

修复后的防御加入跨版本矩阵. 新模型可能重新出现旧漏洞. 每个版本报告历史池、新发现池和外部池, 不用一个总攻击率掩盖遗忘.

**分阶段上线.** 防御先在影子流量观察误报, 再小流量启用. 对高风险漏洞, 在修复完成前临时关闭功能或限权. 扩量监控攻击事件、合法拒绝、工具失败和用户申诉. 回滚防御也有风险. 新过滤器误伤严重时需要撤回, 撤回会重新暴露漏洞. 准备替代控制, 如权限收紧或人工确认. 决策在安全与可用性两条指标上完成.

上线后真实变体回到研究池, 先做隐私与合法性处理. 生产数据不是自动真值, 用户意图和环境结果仍需确认. 事故样本公开后转为回归, 下一批密封样本继续提供独立证据.

### 5.3. 红队指标怎样读

**攻击成功率.** 攻击成功率的分母可以是提示、会话、攻击族或目标系统. 大量同族提示会主导提示级平均. 同时报告按样本与按攻击族结果, 后者更接近覆盖. 每个族样本少时给置信区间. 成功由最少一次、平均或固定查询预算定义, 含义不同. 最少一次适合潜在风险, 平均适合典型可靠性, 固定预算支持公平比较. 原始成功随查询曲线最完整.

环境故障、目标拒绝、评分未决和攻击无效分开. 删除未决会改变分母, 把环境故障算防御成功也会高估. 流转表保持完整.

**防御成功与过拒绝.** 低攻击成功率可能来自安全理解, 也可能是系统拒绝所有任务. 与攻击样本配套合法任务, 报告安全效用前沿. 同一阈值下比较, 或在相同合法完成率比较攻击成功. 合法任务覆盖多样: 相同关键词、相同工具、相同领域, 只改变意图与授权. 普通无关任务无法发现局部过拒绝. 申诉样本和真实误报补充.

拒绝本身也可能泄露信息或被绕过. 检查响应是否暴露系统提示、攻击检测规则和可重试线索. 安全响应应简洁、可行动, 对合法用户提供受控替代.

**新颖性与覆盖增量.** 每轮新增样本数不等于新覆盖. 以新攻击族、覆盖矩阵新格子和新影响路径计增量. 一个新族经独立确认后才计入, 评分器异常不算发现. 覆盖增量随预算通常递减. 画累计确认漏洞与查询成本曲线, 比最终数量更能比较攻击者效率. 不同系统的可见攻击面不同, 曲线需在相同环境和权限下比较.

未发现新漏洞不能证明没有. 报告搜索预算、策略多样性和未覆盖矩阵. 当边际发现低、外部池稳定和真实事件下降, 只能支持给定范围内趋稳.

**跨版本净改进.** 新防御在新攻击上表现好, 旧攻击回归可能恶化. 净改进同时看历史池、当前池和未来留出. 三者权重按风险, 不用当前池一个数字决定. 攻击者也更新, 所以对角胜率不可跨时间直接比较. 用固定参考攻击者测防御趋势, 固定参考防御者测攻击趋势, 再看共同演化. 三条曲线区分双方贡献.

成本与延迟进入净改进. 防御增加大量模型调用, 即使安全提升也可能不可部署. 报告相同成本下的安全、相同安全下的成本, 再选择点.

## 6. 红队系统的安全、边界与长期能力

### 6.1. 红队系统本身的安全

**危险能力扩散.** 训练攻击模型会积累越狱、工具利用和隐蔽策略. 权重、轨迹和提示库需要访问控制. 开发环境限制网络与真实凭证, 只连接模拟目标. 研究产物按可操作性分级, 公开内容去除能直接复现伤害的细节. 攻击模型的部署范围小于普通助手. 仅授权人员、指定任务和期限使用, 所有调用记录. 不把高能力红队模型作为通用服务, 防止原安全目标变成新的攻击工具.

模型退役时撤销凭证、清理缓存并保留受控档案. 仅删除端点不足, 副本、检查点和导出数据仍可能存在. 资产清单与访问日志支持追踪.

**实验环境隔离.** 攻击只能作用于测试租户、虚拟数据和无副作用工具. 高保真环境用仿真或受控靶场. 任何连接生产的评测使用只读影子或明确审批, 最坏动作由外部控制器阻断. 隔离不仅是容器. 网络、云元数据、共享存储、日志和凭证都是逃逸路径. 使用临时最小权限身份, 禁止访问控制面. 资源上限防止递归进程和拒绝服务.

定期故障注入验证沙箱: 工具超时、返回畸形、日志中断、凭证撤销. 安全假设若只在正常环境成立, 红队运行本身可能制造事故.

**人员与流程.** 红队人员会接触敏感漏洞和有害内容, 需要最小访问、培训和心理支持. 关键操作双人确认, 漏洞披露有负责人. Agent 自动化减少机械工作, 责任仍由组织承担. 发现影响外部系统的漏洞时遵循协调披露, 不直接扩大测试. 证明最小影响后停止, 给维护方修复时间. 自动 Agent 无权自行决定继续攻击现实目标.

内部激励避免按漏洞数量单一考核, 否则会重复计数、夸大严重度或忽略修复. 奖励覆盖、可复现性、修复质量和长期回归.

**双重用途的发布.** 论文需要可核查, 细节可能降低攻击门槛. 分层材料: 公开方法、聚合结果和防御经验; 受控附录提供精确轨迹; 必要时延迟漏洞细节. 可信第三方可访问原始证据. 隐藏细节也不能成为夸大结论的借口. 公开样本量、系统配置、评估边界和独立核查方式. 对无法公开复现的主张标注证据等级.

防御代码与攻击代码分开发布. 即使防御公开, 测试漏洞的脚本可能直接武器化. 发布前做滥用评估, 选择最小必要信息.

### 6.2. 一轮可复核的红队闭环

**威胁登记.** 开始前登记目标系统、资产、入口、对手知识、预算和禁止动作. 指定成功的环境状态, 不只给文本标签. 对真实外部系统的测试需要授权, 超出范围立即停止. 历史漏洞与当前覆盖矩阵进入状态. 新候选说明覆盖哪个空白或怎样挑战已知防御. 没有明确增量的近义样本降低优先级, 高风险回归仍固定保留.

**候选生成.** GPT-Red 在沙箱生成攻击计划、预期路径和成本. 生成内容先过合法性与范围检查, 再送目标. 超出权限的候选可在纯模拟环境分析, 不实际执行. 候选保留谱系: 来自哪个攻击族、用了哪些反馈、如何变异. 相同母模板按组切分训练与测试. 多样性按机制选择, 不按句子表面.

**执行与验证.** 执行环境记录输入、目标版本、工具调用、状态变化、资源和异常. 评分器在候选进程之外读取可信状态. 解析失败、超时和环境故障单列, 不默认成功或失败. 自动评分只负责高吞吐初筛, 关键成功由可执行条件或人工确认. 评分分歧进入未决队列. 异常高分样本检查奖励黑客, 修复后重放历史.

**防御更新.** 确认漏洞先限制后果, 再选择训练、提示、解析、权限或监控层修复. 修复计划写预期机制和能力代价. 独立实现与批准, 攻击模型无权写生产控制. 验证覆盖原攻击、邻近变体、合法对照、历史池和新留出. 防御通过后分阶段上线, 监控误报与绕过. 生产异常回到漏洞档案.

**结论与停止.** 一轮结论包括新增覆盖、修复效果、成本、不确定与空白. 「未发现」绑定搜索预算和威胁模型. 不能把低当前胜率写成总体安全. 停止条件看边际新覆盖、外部留出与验证成本. 若攻击者只生成近义样本, 转向新环境或人工探索; 若评分不可靠, 暂停训练并修测量; 若发现高危路径, 冻结相关部署.

### 6.3. 这条路线的边界

**红队强不代表防御完整.** 强攻击者能发现更多漏洞, 没找到仍受策略集限制. 防御对 GPT-Red 鲁棒, 可能对人类专家、另一模型或新工具失败. 外部池、异构攻击者和真实事故持续补充. 攻击成功率下降还可能因目标拒绝更多、环境更难或评分器变化. 跨版本固定参考、合法效用和环境检查共同解释. 只看一条下降曲线不足以定位.

**自博弈在 RSI 分层中的位置.** GPT-Red 更新的是攻击策略, 防御模型通过训练吸收样本, 属于 L1 闭环. 改进器、训练规则和评判标准若保持固定, 循环再长也没有进入 L3/L4. 自博弈描述数据生成关系, 不自动表示系统在改造自身改进机制. 如果未来系统能发现评分器漏洞并提议新评测, 这仍只是 L4 候选. 新标准需要外部锚点与授权才能晋升. 把攻击者改尺子当进步, 会让它通过改变成功定义获胜.

**训练安全与部署安全.** 红队训练改善模型行为,部署安全还依赖权限、隔离、监控和响应. 模型会拒绝注入, 权限层仍要阻断越权; 权限层可靠, 行为训练仍减少误用与告警负担. 多层防护的失效机制尽量不同. 部署环境变化后重新测试. 新工具、新记忆和新路由都增加攻击面. 旧模型卡片与红队结果不能自动覆盖. 发布流程把红队回归绑定配置版本.

**统计证据的上限.** 有限测试只能对给定分布估计成功率. 对手主动寻找尾部, 自然频率不代表攻击频率. 低概率漏洞一旦公开可被重复利用. 因此严重路径更看机制与是否存在, 普通稳健性才看平均率. 零成功给出上界需要独立试验假设. 相似提示和共享模型错误降低有效样本. 按攻击族聚类, 报告有效覆盖, 不用巨大近义样本数制造虚假信心.

**能够从现有结果推出什么.** GPT-Red 证明自动攻击者能通过顺序查询、自博弈和跨环境训练发现可迁移漏洞, 论文数字支持其设定内的效果. 它同时暴露评分、覆盖和双重用途问题. 最强主张保持在实验系统与已测威胁模型. 真正决定价值的是发现能否转成修复, 修复能否在新攻击和合法任务上保持, 生产控制能否限制漏检后果. 攻击数量只是中间量, 风险下降才是终点.

后续最值得报告的是攻击族覆盖、跨版本矩阵、密封留出、合法效用、修复时延、生产绕过与总成本. 这些量一起描述闭环, 比一项成功率更接近真实安全.

### 6.4. 把红队证据变成长期能力

**研究档案.** 长期档案以漏洞族为中心, 连接攻击轨迹、目标版本、评分器、修复、回归和生产事件. 每条边有版本和证据等级. 新模型上线后, 系统能找到所有相关历史漏洞, 不依赖研究者记忆. 攻击轨迹保存原始输入、工具、环境状态和随机性. 敏感细节加密并限制访问, 聚合元数据用于统计. 只保存最终提示会丢掉顺序查询与中间反馈, 无法复现.

评分器版本同样进入档案. 标签更正后, 找出所有受影响训练与结论. 若无法重放, 标记证据失效. 新旧奖励分数不直接拼接. 漏洞状态包括开放、临时缓解、已修复、接受风险和无法复现. 「已修复」需要指定系统版本和回归证据, 不是永久属性. 工具或权限变化后自动重开相关状态. 档案还保存被否决的攻击假设. 否决说明测试范围与重启条件. 新环境满足条件时重新评估, 避免反复做旧实验, 也避免把一次零结果当永远无效.

人工判断记录理由与分歧. 严重度、合法性和披露范围含价值判断, 不能只存最终标签. 后续政策变化时可以重算, 不必猜当时为何决定.

**能力与控制共同演化.** 攻击能力提升时, 验证、沙箱和权限控制要同步. GPT-Red 能生成更长攻击链, 日志只记录最终文本就跟不上; 它能跨模态, 纯文本过滤就失效; 它能持久化, 会话重置也不足. 每项新攻击能力对应控制升级. 控制升级又改变攻击游戏. 权限层阻断后, 攻击者可能转向社会工程或信息泄露; 监控增强后, 隐蔽路径更有选择优势. 威胁模型随之更新, 不能继续用旧奖励解释新风险.

评测能力也要提高. 当攻击成功越来越少, 分类器难以校准, 未决比例上升. 增加高质量边界样本和真实环境检查, 而不是放宽成功定义保持训练信号. 没有可信测量时暂停共同演化. 防御者变强可能把攻击推向更高风险路径. 早期只生成有害文本, 后期尝试工具链与持久状态. 沙箱和审批在扩展任务前准备好. 研究价值不能以现实安全为代价. 共同演化需要外部坐标. 固定历史池测遗忘, 新密封池测迁移, 生产监控测现实暴露, 合法任务测能力保持. 四条曲线分别报告. 对角胜率只描述当前对手关系.

版本发布时, 把攻击模型、防御模型、评分器、环境和控制视为组合. 任一组件变化都可能改变结论. 兼容矩阵说明哪些组合经过测试, 未测组合不自动继承. 红队算力扩大也增加选择偏差. 生成百万候选后发现一次成功, 对潜在风险有意义; 若比较两个攻击模型效率, 必须固定预算. 报告发现概率与成本, 不用最高样本同时支持所有主张. 真实攻击者可能拥有不同目标. GPT-Red 奖励关注指定资产, 会忽略意外可利用后果. 定期开放式探索, 让评估者检查异常状态, 为新目标类别建立入口. 开放探索的结果经过合法性审查再训练.

模型安全更新不能只依靠红队. 形式权限、代码审计、数据治理和事故响应各覆盖不同层. 红队擅长找反例, 无法证明没有漏洞. 系统安全来自多种证据和限制的组合. 当某个漏洞持续无法从模型层修复, 可以缩小功能、权限或自动化深度. 这同样是有效结论. 安全目标落在损失控制上, 无须让模型在所有开放环境自主运行. 红队团队的产出也应按修复效果评价. 一个高危发现若没有责任人和上线修复, 只是风险库存. 追踪从发现、确认、缓解到验证的时间, 找出组织瓶颈. 生成速度超过修复速度时, 降低探索或增加控制资源.

同一漏洞在多个产品存在时, 建立共同根因而非逐个补丁. 共享解析器、提示模板或权限库可能是传播点. 修复共享组件后, 各产品仍做端到端回归, 因为集成不同. 攻击数据的生命周期也受隐私和安全约束. 设定保留期限、访问审计和销毁流程. 训练所需样本可脱敏或转换为结构等价任务, 但要验证转换仍保留机制. 无法安全保存的细节用受控摘要和哈希证明存在. 公开结果时, 将事实、解释和治理选择分开. 「在某预算下成功率为 X」是观测, 「暴露了某类共享漏洞」是解释, 「因此限制工具」是决策. 这种分层便于外部复核, 也防止论文数字被直接当成普遍风险率.

如果后续版本出现更低攻击成功率, 先检查攻击者、评分器和环境是否同样强. 防御改善只是可能解释之一. 跨版本重放和固定参考消除部分混杂, 未能对齐的部分保留不确定. 长期目标包括让已知严重路径被阻断、新路径尽早发现、漏检后影响可控、修复可快速验证. 这四项分别对应防御、发现、隔离和恢复. 攻击成功率压成零无法由有限测试证实, 不适合作为唯一目标. 红队闭环成熟后, 仍要允许人工提出违反当前分类法的问题. 自动系统会沿现有奖励高效搜索, 人类与现实事故提供新坐标. 两者结合, 才能避免覆盖矩阵越来越满, 实际攻击面却已经移动.

最终, GPT-Red 是安全研究的一个强生成与搜索组件. 它让攻击覆盖更快扩张, 也把评分器、环境和双重用途推到核心位置. 系统能否把搜索结果转成独立证据与可验证控制, 决定这条路线提高了真实安全, 还是只提高了红队基准分. 为了判断真实安全是否改善, 可以维护漏洞生存曲线. 从首次确认开始, 记录临时缓解、正式修复、首次复发和跨产品迁移. 修复数量相同, 生命周期短且少复发的体系更有效. 这条曲线也能暴露积压: 大量漏洞长期停在已确认状态, 问题位于修复能力而非发现能力.

修复时延按严重度拆分. 高危路径应立即限权, 正式模型更新可以稍后; 普通缺陷进入计划队列. 如果所有漏洞都按同一流程, 紧急项可能等待, 低风险项又浪费昂贵审查. 服务级目标写明每阶段时限与升级负责人. 还应记录红队触发的误报成本. 自动系统可能生成大量看似危险但无实际后果的样本, 人工确认成为瓶颈. 通过主动学习选择最不确定、影响最大的候选, 同时随机抽样低分样本估计漏检. 只审高分会无法知道分类器遗漏多少.

确认队列的排序不能完全由同一评分器决定. 高严重度先验、覆盖空白和外部事故提供独立优先级. 评分器失准时, 随机审计与规则触发仍能发现. 多通道减少红队通过操纵分数占满审阅预算. 模型生成的攻击解释也可能诱导确认者. 人工先看环境状态与最小轨迹, 再读模型理由, 降低锚定. 对复杂链由两名审阅者独立判断, 分歧交给领域专家. 确认结论与原理由分别保存, 便于研究解释是否可靠.

跨语言红队需要本地语境. 直接翻译英语攻击会漏掉礼貌、身份和语法中的信任线索, 也可能制造不自然样本. 本地专家与模型共同生成, 在同语言合法任务校准误报. 低资源语言样本少时, 结论保持有限, 部署采取更保守权限. 多模态任务还需保持渲染链一致. 图像压缩、OCR、缩放和前端预处理会改变攻击是否可见. 保存原始文件与每步派生物, 对比模型实际输入. 只保留截图无法复现后端解析, 也无法判断漏洞在模型还是管道.

工具调用红队要验证幂等性. 攻击可能诱导重复发送、重复扣费或重复删除. 环境使用幂等键与事务日志, 测试部分失败和重试. 即使模型策略错误, 工具接口也应限制重复副作用. 这一层控制通常比训练模型记住每个异常更稳定. 长程红队关注状态漂移. 攻击者可在早期建立信任, 中期扩大权限, 后期执行目标. 评测改变会话长度与阶段顺序, 隐藏终点. 只看单轮拒绝率无法覆盖. 同时设置最大权限与持续监控, 防止评测本身越界.

社会工程类攻击涉及人类操作者. 模型可能生成说服文本, 真正执行需要人. 安全评估可以在模拟参与者或经过审批的研究中测量, 不向真实无知情人员发送. 人因风险属于系统边界, 仍需伦理与隐私控制. 防御训练之后, 检查模型是否学会识别评测而非攻击. 改变模板、在自然任务嵌入注入、隐藏安全词, 看行为是否保持. 若只在标准格式拒绝, 训练产生了表面适配. 生产监控仍需覆盖非标准输入.

攻击者的评估觉察也会影响. 它知道自己在沙箱时可能尝试更激进行为, 知道输出会审查时可能伪装. 改变环境线索并比较策略. 结果只说明条件行为, 不能直接赋予意图; 控制依然基于可观察动作. 版本升级时先运行 A/A 控制. 同一攻击与防御配置重复执行, 估计环境和评分噪声. 若 A/A 差异已经很大, A/B 的小改进无法解释. 固定响应测试评分链, 固定工具轨迹测试环境检查, 将测量故障从模型变化中分离. 对极低成功率, 大量零结果仍可能掩盖族间差异. 使用分层模型共享信息, 同时保留每族原始计数. 统计平滑不能让未测试族获得安全结论. 决策时高风险空白按未知处理.

当攻击成功依赖罕见连锁条件, 平均率很低, 但条件一旦满足就稳定成功. 识别前置条件并估计现实暴露, 比继续随机采样更有效. 权限与环境控制可直接切断链, 不必等待模型层完全修复. 真实事故若没有被 GPT-Red 发现, 做遗漏分析: 攻击族不在目标里、环境不够真实、预算不足、评分器漏检, 还是候选生成没找到. 每次遗漏对应一项系统改进. 若只把事故加入回归, 下一个机制相似但表面不同的路径仍会漏掉. 反过来, GPT-Red 发现的高危路径长期未在现实出现, 也要分析. 可能是生产权限阻断、攻击成本过高或场景极不现实. 这不会让发现无效, 会调整风险优先级. 保留底层能力证据, 把现实暴露单列.

红队结果进入模型卡或 System Card 时, 说明测试对手、预算、环境、成功定义和缓解. 「通过红队」没有稳定含义. 更准确的是哪些攻击族在什么条件下未见成功、哪些成功已由什么控制阻断、哪些仍未决. 对外比较不同模型, 使用相同攻击池只能测固定威胁, 各自最强攻击者又有不同搜索预算. 两种设置都报告. 固定池比较防御, 自适应池比较在现实对抗中的脆弱性. 混在一起会把攻击者强弱算进目标模型排名.

随着红队模型变强, 训练它所需的目标访问本身成为风险. 采用分阶段权限: 早期只访问模拟器, 通过合法性与安全检查后才能测试更高保真环境. 每级输出受控, 防止生成内容扩散. 研究效率不能成为越过范围的理由. 最终治理动作必须可执行. 某类攻击超过门槛后, 是冻结功能、限制工具、增加确认还是延迟发布, 在测试前写明. 没有行动映射的红队分数容易停留在报告中. 行动完成后验证有效, 残余风险决定下一轮覆盖.

对攻击链的每一步还可以计算条件成功率. 若入口注入成功率高, 权限提升几乎为零, 资源应优先放在保持权限边界; 若权限一旦获得就稳定造成后果, 则恢复与监控同样关键. 端到端低成功率可能由单一强门控贡献, 也可能由多层弱门控相乘, 两者对共同故障的脆弱性不同. 条件成功率需要完整记录中间状态. 模型声称完成某步不算, 由可信环境验证. 对不可直接观察的阶段, 使用代理并标注不确定. 若代理误差大, 不强行做精细分解. 这张链条用于定位控制, 总体风险仍由端到端结果和现实暴露判断.

多层防护要做相关失效测试. 同一个编码变体是否同时绕过输入过滤、模型训练和输出监控; 同一次日志故障是否让检测与响应一起失效. 若防护共享表示、数据或服务, 冗余比数量看起来少. 引入机制不同的控制, 如权限类型和事务约束. 红队模型升级前后也要桥接. 固定一组目标与环境双跑, 看新模型多发现哪些族、成本如何变化、旧族是否遗忘. 若新模型只产生更长文本却没有覆盖增量, 生成规模不等于攻击能力. 新发现由独立验证确认后再计入.

对人工红队与 GPT-Red 的互补, 保存彼此独有发现. 人类擅长利用业务语境和社会工程, 模型擅长规模化变异和长时间搜索. 让模型扩展人工种子, 人工审查模型异常, 比简单比较谁发现更多更有价值. 重叠部分可估计两个通道的覆盖相关性. 真实用户报告也是一条通道, 需要防滥报与保护举报者. 提供可复现模板、敏感附件通道和状态反馈. 经确认的外部漏洞进入同一档案, 但发现者权限和披露约束分别记录. 外部来源不自动代表高严重度, 也不因无法公开而被忽略.

另留一组完全不参与训练的周期挑战. 它由独立人员根据新系统和真实事件构造, 在阶段性发布前开启. 结果用于判断闭环是否仍泛化, 不逐轮返回详细答案. 开启后若用于修复, 整组退役并建立下一组, 避免终审逐渐变成公开课程. 这套设计无法证明系统没有未知漏洞, 它能让证据范围、发现速度、修复质量和控制后果都可追踪. GPT-Red 的价值由此落在更具体的位置: 扩大搜索并缩短发现时间, 同时接受独立验证与外部权限边界.

每次阶段性复盘还应抽查若干低分攻击, 确认评分器没有系统性漏掉隐蔽路径. 如果低分样本里出现真实成功, 先修测量并重算历史, 再继续训练. 搜索速度建立在评分可信之上, 评分失效时生成更多候选只会更快积累错误信号. 低分抽查的比例、随机种子和确认结果同样进入档案, 让漏检估计能够跨版本比较, 也让后续团队知道哪些区域仍缺少可靠标签.
