# 3.2 · L2: 技能, 记忆与 Harness

3.1 讲了 L2 最内的两层: 提示与程序, 架构与工作流. 外面还有三层: 带显式调用接口的技能, 没有调用接口, 在之后某次检索时被静默注入上下文的记忆, 以及构造上下文, 调用工具, 观察轨迹, 提交改动的 harness 循环.

## 1. 三层的区别

### 1.1 三层各保留什么

3.1 讲的提示和架构, 改的是组件说什么和组件怎么组织. 结构稳定之后, 下一个问题是这些结构产生的能力里, 哪些要保留下来, 在之后的独立任务上再调用.

| 层 | 保留的是什么 | 怎么影响之后的行为 | 本地检查 | 典型失败 |
|---|---|---|---|---|
| 技能 | 命名的, 可检索的能力单元: 策略, 规则, 代码, 工具 | 通过显式接口被调用, 带一个声明的有效范围 | 留出探针, 被调用条目的回归预算 | 静默回归: 新条目修好目标任务, 弄坏原来对的行为 |
| 记忆 | 交互历史, 经验摘要, 用户画像等 | 被检索后静默注入上下文, 没有调用动作 | 用保留的原始轨迹做长时回放 | 累积噪声, 过期条目, 相互矛盾 |
| Harness | 构造上下文, 调工具, 观察, 归因, 提交的循环本身 | 决定前面所有层怎么被调用和提交 | 执行整个循环并记录回滚路径 | 循环可以反复查询的验收门不再是留出证据 |

### 1.2 排序与层级

技能排在记忆前面, 是因为技能有调用接口和有效范围, 能做局部检查; 记忆去掉了调用接口, 也就去掉了这个局部检查. Harness 排最后, 是因为它执行和观察其他所有层, 把它变成可写, 就把提示, 架构, 技能, 记忆都放进了一个可编辑的循环.

三层都在 L2, 前提和 3.1 一样: 保留下来的是 $\Sigma$ 里的非参数结构. 记忆的整理器如果是训练过并保留的参数, 那部分是 L1; harness 里如果有教师重新打标签再训练模型的环节, 那部分也是 L1.

三层的边界由行为接口决定, 不由文件名决定. 一段 Markdown 若只能被检索后拼进上下文, 它是记忆; 若带参数、前置条件和返回契约, 由控制器显式调用, 它承担技能角色; 若它规定检索、调用、验证和提交的顺序, 就成为 harness 的一部分. 同一段内容经过接口升级会跨层移动, 认证要求也随之改变.

可以把三层写成嵌套映射. 技能集合 $K$ 把输入和状态变成局部动作, 记忆 $M$ 改变技能与模型看到的上下文, harness $H$ 决定何时读取 $M$、选择哪个 $k\in K$ 以及如何处理结果:

$$
y=H\big(x,M;\{k(x,M)}_{k\in K}\big). \tag{1}
$$

修改外层会改变内层的实际分布. 一个技能本身没有变化, 路由器更新后被调用到新的任务上, 行为仍会退化; 一条记忆没有改写, 注入位置变化后影响会变强. 因此外层升级的回归集必须覆盖内层资产, 不能把每层测试完全隔离.

这也解释了为什么越外层越难做局部归因. 技能有明确调用事件, 可以比较调用前后; 记忆可能通过措辞轻微改变多个决定; harness 能改变整条轨迹, 包括哪些证据会被观察. 观察边界扩大后, 「组件没变」不再等于「组件作用没变」. 版本清单既要记录内容哈希, 也要记录路由、注入和控制关系.

三层还有不同的失败半径. 坏技能通常只伤害调用它的任务, 坏记忆会影响所有召回到它的任务, 坏 harness 可能让每条任务都绕过验证. 准入强度应随失败半径提高: 技能可先在窄作用域金丝雀, 记忆要检查邻接任务与长期干扰, harness 则需要全链路影子运行和真实回滚演练.

失败半径还决定观察周期. 技能调用后通常能立刻验收, 记忆的干扰可能隔几次任务才出现, harness 的状态迁移问题则可能只在版本升级或并发恢复时暴露. 局部单测、长期回放与故障注入分别覆盖这三种时间尺度, 不能互相替代.

## 2. 技能

### 2.1 从轨迹到技能

这一层的基本动作是把成功和失败的轨迹蒸馏成命名的, 可检索的条目. 条目和原始轨迹的区别在于: 它要在独立任务上被调用, 并且带着一个隐含的有效范围, 比如一类输入或一类任务.

**Voyager** (Wang 等, 2023, NVIDIA 与 Caltech 等) 是这一路的早期代表. 在 Minecraft 里, GPT-4 自动出课程, Agent 为每个任务写 JavaScript 动作程序, 根据环境反馈, 执行报错和自检反复修改. 只有自检确认任务完成, 程序才写进技能库, 用描述的嵌入向量做索引, 之后按相似度检索, 组合. 160 次提示迭代里发现 63 种物品, 是对比方法的 3.3 倍. 科技树解锁所需的迭代次数, 木制工具 6±2, 石制 11±2, 铁制 21±7, 三次运行都成功; 钻石工具 102 次, 三次里成功一次. ReAct 和 Reflexion 三次都没解锁任何一级. 换到新世界零样本做新任务, Voyager 带着技能库四个任务都成功, 对比方法全部失败. 把 GPT-4 换成 GPT-3.5 写代码, 发现的物品数少到 1/5.7.

Voyager 的技能库只增不删. 在 Minecraft 里这没出问题, 原因之一是任务空间有清晰的成功信号, 自检的可靠性高.

**SkillWeaver** (Zheng 等, 2025, 俄亥俄州立) 把同样的思路用在网页上. Agent 在网站上自己提出要练的技能, 执行后由一个 LLM 奖励模型判成败, 成功的轨迹被合成为 Playwright 的 Python API, 再经自动生成的测试用例调试后加入 API 库. WebArena 上 GPT-4o 从 22.6 到 29.8, GPT-4o-mini 从 9.2 到 14.1; 真实网站 Online-Mind2Web 上从 40.2 到 56.2. 强模型合成的 API 给弱模型用, WebArena 上最多相对提升 54.3%.

### 2.2 自己写的技能有没有用

SkillsBench (Li 等, 2026, BenchFlow) 直接测这个问题. 86 个任务, 11 个领域, 每个任务在三种条件下各跑一遍: 不给技能, 给人工整理的技能, 让模型先自己写技能再做题, 用确定性验证器判对错. 7 种 Agent 与模型的配置, 共 7308 条轨迹.

- 人工整理的技能平均提高 16.2 个百分点, 不同领域差别很大: 软件工程 +4.5, 医疗 +51.9. 84 个任务里有 16 个变差.
- 自己写的技能平均 −1.3 个百分点. 只有 Opus 4.6 有小幅提升 (+1.4), Codex 加 GPT-5.2 掉了 5.6.
- 只含 2–3 个模块的聚焦技能好于大而全的文档; 小模型带技能能追平不带技能的大模型.

这组结果给技能层定了基调: 让 Agent 往技能库里写东西本身没有价值, 价值取决于写进去之前有没有经过验证. 后面的系统都在回答「用什么门」.

### 2.3 技能作为可验证的程序

把技能写成程序, 工具或形式化的契约, 调用接口就收窄了, 升级前的本地证据也更强: 候选可以编译, 可以模型检验, 可以被验证器拒掉. 综述举了两类做法: 把反例轨迹转成对技能契约的文本修改 (VASO), 在没有真实测试用例的情况下让代理验证器和技能包一起演化 (CoEvoSkills). 这类系统基座权重不动, 也没有改自己的改进器, 演化的是技能或规格产物, 综述把它们归在 L2.

**Alita** (Qiu 等, 2025, 普林斯顿等) 走得更远: 只预置一个网页 Agent 和少量通用模块, 遇到任务时从开源代码现场生成, 修正 MCP 工具, 生成的工具留给以后的任务和别的 Agent 用. GAIA 验证集上, Claude-Sonnet-4 加 GPT-4o 的配置 pass@1 75.15%, pass@3 87.27%; OpenAI Deep Research 是 67.36%. 论文里没有看到显式的准入或删除门.

形式检查和执行检查证明的, 仍然只是覆盖到的执行上的语法和行为. 要证明技能能迁移, 还得做留出的端到端评测.

### 2.4 治理技能库与共享技能

技能库变大以后, 问题不再是单个技能对不对, 而是整个库会不会越来越差. 综述把这叫做静默回归: 新加的技能改善了它针对的样本, 同时悄悄弄坏了原来对的行为. 准入门和回滚就是为了抓这个.

**GRASP** (Moll 等, 2026, 慕尼黑工大) 的门写得最明确. 技能库有容量上限, 带版本, 可回滚. 每批任务跑完, 把失败按具体机制分组, 由写手模型提出 $K$ 个修改, 每个只增, 改或删一个技能. 每个修改 $c$ 都在一组留出的平衡探针上重跑, 探针由原先失败和原先成功的样本组成. 记 $F(c)$ 为修改后原先失败的探针里被修好的数量, $R(c)$ 为原先成功的探针里被弄坏的数量; $F_0, R_0$ 是用当前技能库重新跑一遍得到的同样两个数, 用来扣除重跑本身的波动. 接受条件是:

$$
\big(F(c)-F_0\big)-\big(R(c)-R_0\big)>0 \quad\text{且}\quad R(c)\le R_0. \tag{2}
$$

第一项要求修好的减去弄坏的, 比基准多; 第二项要求弄坏的不比基准多. 两项同时满足才收. 结果:

| 设置 | 起点 | GRASP | 最强基线 |
|---|---|---|---|
| MedAgentBench, gpt-oss-120b | 40.6% | 88.8% | 67.8% (Evo-MedAgent) |
| MedAgentBench 分布外, gpt-oss-120b | | 56.3% | 31.3% |
| MedAgentBench-v2, gpt-oss-120b | 61.1% | 76.9% | 67.8% (ExpeL) |
| MedAgentBench-v2 分布外, gpt-oss-120b | | 86.0% | 87.1% (SkillX) |

其他四个基座模型提升 17.2 到 40.3 个点. 在 v2 的分布外设置上 GRASP 不如最强基线, 作者明确不对这一项声称更好. 非医疗环境里, ALFWorld +28.4, WebShop +20.6, DBBench +5.0, OS Interaction +0.9, 最后一项在种子噪声范围内. 同一篇论文还报告, 去掉验证环节, 只让写手模型写技能, 效果和不用技能一样.

**SkillsVote** (Liu, Yang 等, 2026, MemTensor 等) 处理的是百万级的开源技能库. 执行前用 Agent 搜索给任务推荐技能; 执行后把轨迹拆成和技能挂钩的子任务, 把成败归因到四类: 技能引导, Agent 自己探索, 环境, 结果信号. 只有归因为成功且可复用的发现, 才能改写已有技能或新建技能; 失败和不确定的归因一律跳过. 用 Codex 跑 Terminal-Bench 2.0, GPT-5.2 从 51.1 到 53.7, GPT-5.5 从 79.8 到 80.7. 对照很有用: 同一张表里, 人工整理的技能在 GPT-5.5 上 78.1, 低于不用技能的 79.8; ReasoningBank 77.7, 也更低. 模型越强, 外加技能的空间越小, 门不严时更容易帮倒忙.

**SkillBrew** (Hu, Chu 等, 2026, 港城大等) 在整库层面做多目标整理: 效用是硬约束, 多样性和覆盖度是正则项. 对每个技能做留一反事实回放, 判断保留, 改写还是删除; 在支持集上提出修改, 在留出的查询集上做 Pareto 选择. Qwen2.5-7B 上 ALFWorld 平均 59.0, Voyager 47.0, ExpeL 46.3. GPT-4o 上 ALFWorld 从 46.4 到 88.1. 只允许添加, 不允许改写和删除时, ALFWorld 成功率只有 47.0%.

三个系统的共同点: 准入看留出样本上的净效果, 不看写入时的自评; 删除是正式的操作, 和添加同等对待.

技能变成跨 Agent, 跨模型, 跨用户的共享资产时, 多了一条兼容性要求: 接口和语义版本要在不同模型, 工具和用户之间保持有效, 迁移的成功率要和单个 Agent 内的复用分开测. 准入的代价也更高: 一个坏条目在共享库里会传播到创建它的 Agent 之外. 综述提到的组织层面的防护, 包括审计分离, 契约协议和组织记忆, 都是为了这一点.

### 2.5 技能选择, 组合与作用域

技能条目可以写成五元组

$$
k=(d_k,I_k,O_k,P_k,E_k), \tag{3}
$$

$d_k$ 是用于检索的描述, $I_k$ 与 $O_k$ 是输入输出契约, $P_k$ 是前置条件和权限, $E_k$ 是经过验证的适用证据. 只有描述而没有后四项的条目更像一段建议; Agent 可以读它, 却无法判断何时调用、调用后怎样验收. 技能库的能力来自条目本身与选择策略的组合, 同一个好技能被错配到不适用任务上仍会降低结果.

设任务上下文为 $x$, 候选技能集合为 $K(x)$, 选择器给出 $\pi(k\mid x)$. 调用技能 $k$ 后的净效用为

$$
u(x,k)=r(x,k)-\lambda c(x,k)-\rho q(x,k), \tag{4}
$$

$r$ 是任务收益, $c$ 是调用成本, $q$ 是权限或失败风险. 选择问题是最大化 $\mathbb E_{k\sim\pi(\cdot\mid x)}u(x,k)$. 语义相似检索只近似了「描述像不像」, 没有估计收益、成本和风险. MemRL 的效用重排、GRASP 的回归探针与 SkillsVote 的轨迹归因, 分别补了这个目标的不同部分.

选择器看到的反馈具有选择偏差. 被召回的技能有结果, 没被召回的技能没有反事实结果. 若某个早期技能偶然成功, 选择器会更常调用它, 数据里它也会继续占优; 其他技能得不到试用机会. 这与上下文 bandit 相同. 适度探索可以估计冷门技能, 但高风险任务不适合随机试错. 可把任务按风险分层: 低风险沙箱允许探索, 中风险任务只在验证器可覆盖时探索, 外部副作用任务使用已经通过对应权限探针的技能.

离线评估选择器时, 仅用历史日志重放会遇到支持集问题. 若旧策略在上下文 $x$ 下从未选择技能 $k$, 日志不能直接估计新策略选择 $k$ 的结果. 有记录的行为概率 $\mu(k\mid x)$ 时, 可以用逆倾向加权估计新策略 $\pi$ 的效用:

$$
\hat V(\pi)=\frac{1}{n}\sum_{i=1}^n
\frac{\pi(k_i\mid x_i)}{\mu(k_i\mid x_i)}u_i. \tag{5}
$$

当 $\mu$ 很小时权重爆炸, 方差很大. 截断权重或双重稳健估计能缓和, 不能凭空创造未覆盖动作的证据. 因而技能系统若打算长期自我学习, 从一开始就要记录候选集合、实际选择与选择概率; 只保存成功轨迹会失去评估新路由策略所需的信息.

技能的作用域可以理解为一个集合 $S_k\subseteq\mathcal X$, 表示已经有证据支持调用的任务区域. 新条目刚加入时 $S_k$ 很窄, 只能覆盖与验证探针相邻的任务. 每次在新任务族上通过独立验证, 才扩大作用域. 仅凭自然语言描述声称「适用于所有网页任务」不会扩大证据范围. 反过来, 某一类任务稳定失败时应缩小作用域, 而非立刻删除整个技能. 这让更新从二元的保留/删除变成作用域的收缩与扩张.

作用域还要区分能力前提与环境前提. 一个代码修复技能可能要求模型能稳定编辑多文件, 这是能力前提; 要求仓库有可执行测试、依赖版本兼容, 是环境前提. 换底座模型或工具版本后, 旧证据只覆盖旧前提. 技能条目携带验证时的模型、工具、权限和数据版本, 运行时发现前提不满足便降级为候选建议, 不能继续当已认证程序调用.

技能组合引入交互效应. 顺序组合 $k_2\circ k_1$ 要求 $O_{k_1}$ 满足 $I_{k_2}$, 并行组合要求副作用不冲突, 条件组合要求路由谓词有可测边界. 即使单个技能都通过测试, 组合也未必安全. 设单技能作用为算子 $T_k$, 一般有

$$
T_{k_2}(T_{k_1}(x))\ne T_{k_1}(T_{k_2}(x)), \tag{6}
$$

说明顺序属于组合语义. 一个先格式化后校验的流程可能通过, 先校验再格式化则拒绝同一输入. 技能库需要保存经过验证的组合模体, 或在组合时重新做接口和副作用检查.

重复技能会制造选择不稳定. 两个描述相似的条目可能实际上覆盖不同边界, 盲目去重会删掉差异; 两个措辞不同的条目可能行为等价, 全部保留又稀释检索概率. 去重应比较三层: 描述用于初筛, 契约判断接口是否相容, 行为探针判断在代表性输入上的输出与副作用是否等价. 行为接近但证据来源不同的条目可以合并实现、保留独立证据, 不必把审计链一起删掉.

冲突技能不能靠检索分数裁决. 若一个条目要求遇到缺失证据时停止, 另一个要求继续尝试替代来源, 两者可能分别适用于高风险事实回答和低风险探索. 解决办法是把条件写入作用域并规定优先级. 无法区分条件时, 系统应暴露冲突并进入复核, 而非让向量距离的小数差决定行为. 对权限和安全规则, 优先级属于不可由普通技能覆盖的外层策略.

技能贡献不能只按被调用后的成功计数. 容易任务更常成功, 会让处理容易任务的技能看起来最有价值. 可以比较同一任务在有无技能时的配对差值

$$
\Delta_k(x)=Y(x;K)-Y(x;K\setminus\{k\}), \tag{7}
$$

再按部署任务分布聚合. SkillBrew 的留一回放接近这个思想. 完整重跑每个技能成本很高, 可先用调用日志筛出可能有贡献的条目, 对高影响和高风险条目做精确消融; 长期未触发的技能不能直接判为无用, 还要确认对应任务是否仍会出现.

容量上限既是成本约束, 也是统计正则. 库越大, 检索器越容易从许多相似条目中选到偶然匹配, 每个条目获得的验证样本也越少. 设技能数为 $m$, 每个任务只检查前 $r$ 个候选, 增加 $m$ 会提高覆盖的可能性, 也提高误召回与多重比较偏差. 最优容量由任务多样性、检索分辨率和每条技能可获得的证据量共同决定. Ratchet 的上限 $C$ 把这个问题变成显式约束, 但淘汰依据仍必须校准; 容量满了时机械删最旧条目, 可能恰好删掉低频灾难场景的保护技能.

技能版本之间需要可替换关系. 补丁版本保持接口和作用域, 只修正实现; 次版本可以扩大作用域或增加可选输出; 主版本改变契约, 调用方必须重新验证. 自动改写若改变了输入字段、权限或失败状态, 即使自然语言描述相近也属于破坏性升级. 共享库中旧调用方不会同时更新, 因此要保留兼容层或并行版本, 直到依赖图上的消费者全部迁移.

迁移检验至少有三种. 同模型跨任务检验条目是否超出原始轨迹; 同任务跨模型检验技能是否依赖某个底座的特殊表达习惯; 同模型同任务跨环境检验工具与接口是否绑定特定实现. 三者失败的含义不同. 跨任务失败说明规则过拟合, 跨模型失败说明调用协议缺乏可移植性, 跨环境失败说明实现与外部依赖耦合. 把三种结果压成一个平均分, 无法指导是改描述、改程序还是缩小作用域.

一个成熟技能库因此不是提示片段仓库. 它包含候选发现、契约检查、选择策略、行为验证、作用域维护、组合测试、版本迁移与回滚. Agent 能生成一条看似有用的规则, 只完成了最前面的候选发现. SkillsBench 里自写技能平均无增益, 恰好说明后面的治理环节才决定条目会不会转化为持续能力.

## 3. 记忆

### 3.1 写入什么

技能有显式的调用接口, 记忆没有. 一条记忆不需要被有意调用, 就能影响之后的某个决定. 这让记忆成为 L2 里影响范围最广, 最难看见的一层.

**Reflexion** (Shinn 等, 2023, 东北大学) 在失败后写一段语言反思, 放进情景记忆, 下一次尝试同一任务时带上. HumanEval 上 pass@1 91.0, GPT-4 是 80.1; MBPP 上 77.1, 低于 GPT-4 的 80.1. Reflexion 的记忆主要用于同一任务内的重试, 只保留最近几条. 按 1.2 的持久性条件, 同一任务内的重试是 L0; 反思被保留下来, 用到之后的独立任务上, 才是 L2.

**ExpeL** (Zhao 等, 2023, 清华) 跨任务. 先在训练任务上用 Reflexion 收集成功和失败轨迹, 再从成败对比中提炼一份洞见列表, 列表用增加, 赞成, 反对, 编辑四种操作维护, 票数降到零的条目被删除. 推理时把洞见和检索到的相似成功轨迹一起放进上下文. HotpotQA 从 ReAct 的 28.0 到 39.0, ALFWorld 从 40.0 到 59.0; 迁移到 FEVER, 从 63 到 70. ExpeL 有删除, 但删除依据是写入模型自己的投票, 不是留出样本上的效果.

**ACE** (Zhang 等, 2025, 斯坦福等) 把上下文当成一份不断演化的操作手册. 生成器执行任务, 反思器提炼经验, 整理器按条目做增量更新, 并做语义去重和剪枝. 它针对的问题是上下文坍缩: 反复整篇重写上下文, 细节会逐渐丢失. AppWorld 上, DeepSeek-V3.1 的 ReAct 平均 42.4, 加 ACE 离线学习 59.4, 和排行榜第一的 IBM CUGA (60.3) 相当; 不用真实标签也有 57.2. 金融任务上有一个反例: 在线, 无标签的设置下, FiNER 一项从 70.7 降到 67.3. 没有可靠反馈时, 增量更新也会把错误写进去.

**ReasoningBank** (Ouyang 等, 2025, Google Cloud AI Research 等) 用 LLM 判官判定每条轨迹的成败, 从成功和失败中各自提炼可泛化的推理策略, 推理时检索使用. 它的扩展 MaTTS 给每个任务多跑几条轨迹, 用轨迹之间的对比提炼更好的记忆. WebArena 上, Gemini-2.5-flash 从无记忆的 40.5 到 48.8, 加 MaTTS 51.8, 平均步数从 9.7 降到 7.9. SWE-Bench-Verified 上, Gemini-2.5-flash 从 34.2 到 38.8.

**MemRL** (Zhang 等, 2026, 上海交大等) 把每条经验存成「意图, 经验, 效用」三元组. 检索分两步: 先按语义召回, 再按学到的期望效用值重排; 效用值用环境反馈做蒙特卡洛更新. 名字里有强化学习, 但模型权重不更新, 学的是存储里每条经验的效用, 所以仍是 L2. 五个设置的平均, 无记忆 0.631, MemRL 0.772, 另一个记忆方法 MemP 0.736.

### 3.2 怎么组织, 怎么注入

**MemGPT** (Packer 等, 2023, 伯克利) 借用操作系统的分层内存: 上下文窗口是主存, 外部的召回存储和归档存储是外存, 模型通过函数调用自己决定换入换出. 在多会话对话的深层记忆检索任务上, GPT-4 Turbo 从 35.3% 到 93.4%.

**A-Mem** (Xu 等, 2025, 罗格斯) 按卡片盒方法组织记忆: 每条新记忆生成一张带描述, 关键词, 标签的笔记, 和已有笔记建立链接, 还会反过来更新旧笔记的描述. LoCoMo 上 GPT-4o-mini 的 F1, 时间类问题 45.85, MemGPT 25.52; 多跳问题 27.02, MemGPT 26.65. 正文说多跳任务上「至少两倍」, 和表对不上, 翻倍的其实是时间类一列. 每次记忆操作约 1200 个 token, 对比方法约 16900.

**Dynamic Cheatsheet** (Suzgun 等, 2025, 斯坦福) 让模型在推理阶段自己维护一份小抄, 记下解题策略和代码片段, 每答一题整理一次, 不需要标签. GPT-4o 在 24 点游戏上从 10.0 到 99.0, Claude 3.5 Sonnet 在 AIME 2024 上从 23.3 到 50.0. 但 GPT-4o 在 MMLU-Pro 工程类上从 53.2 降到 44.0 (累积版) 或 51.2 (检索综合版). 小抄的内容由模型自己筛, 没有外部验证门, 有的任务上它记下的东西帮倒忙.

结构决定了哪些内容还能被检索到, 以及之后的回归能不能定位. 综述的提醒是: 每一步压缩和整合, 都可能丢掉审计之后某次失败所需的来源信息.

经验经由检索或运行时钩子注入时, 记忆层的风险最具体: 它影响行为, 却没有局部的有效性检查. 综述举的 WebCoach 把跨会话的导航日志浓缩成建议, 通过运行时钩子注入, 不需要重训, 对模型无关; OS-Copilot 的 FRIDAY 在冻结的模型上, 把成功完成后的工具和技能累积成自我改进的程序性记忆. 这类存储持续地, 静默地影响工具使用和规划, 它们的效果要在长时间跨度上测, 只看写入它们的那个会话不够.

### 3.3 删除, 以及一个反例

存储只增不删, 迟早会积累过期和相互矛盾的条目. 综述把删除和降级看作学习规则的一部分, 不只是容量管理.

CTIM-Rover (Lindenbauer 等, 2025, 慕尼黑工大与 LMU) 是这一节的反例. 它在 AutoCodeRover 上照搬 ExpeL, 从过去的成功轨迹里蒸馏出通用级和仓库级两层跨任务记忆, 外加示例轨迹, 全部直接放进初始上下文, 不做过滤. SWE-bench Verified 的 45 题子集上:

| 配置 | 成功率 |
|---|---|
| AutoCodeRover (无记忆) | 42 |
| CTIM-Rover (全部) | 40 |
| 只用示例轨迹 | 40 |
| 只用通用级记忆 | 36 |
| 只用跨任务记忆 | 31 |
| 只用仓库级记忆 | 31 |

没有任何配置超过无记忆基线. 作者的分析把退化归于保留下来的干扰条目产生的噪声. 这是直接的证据: 跨任务持久, 不加过滤的存储会积累噪声, 不一定积累能力.

综述由此给出这一层的结论: 持续重写的记忆即使起初有用, 也可能变差; 一次删除要用保留的原始轨迹回放验证, 确认它修好一处失败时没有悄悄带回另一处. 这是 L1 模型坍塌在 L2 的对应: 权重没变, 之后的行为却受早先可能出错的行为所产生的状态支配. 记忆的影响比技能更广也更难看见, 升级和淘汰都应该在更长的时间跨度上判断, 探针要同时覆盖检索, 工具使用和下游决策.

### 3.4 写入, 召回与遗忘是一条决策链

记忆系统常被画成向量库加相似度检索, 这只覆盖了召回的一步. 一条经历 $e_t$ 先经过写入策略 $w$, 变成记忆项 $m$; 存储结构 $S$ 决定它和其他条目的关系; 查询 $x$ 经召回策略 $r$ 得到集合 $R(x,S)$; 注入策略 $g$ 决定以何种形式进入上下文; 最终行为产生反馈, 遗忘策略 $f$ 再更新存储. 整体可以写成

$$
S_{t+1}=f\big(S_t,w(e_t),Y_t\big),\qquad
a_t=\pi\big(x_t,g(R(x_t,S_t))\big). \tag{8}
$$

任何一环都可能让有用经历失效. 写入器漏掉关键条件, 检索器召回错误条目, 注入器把来源压缩掉, 模型忽略了正确记忆, 淘汰器又依据这次失败删掉条目. 只比较「有记忆」和「无记忆」只能测整条链的总效应, 无法定位该修哪一环.

写入的起点是信息选择. 原始轨迹 $E$ 包含大量偶然细节, 记忆 $M$ 希望保留对未来任务 $X'$ 有用的信息. 理想目标可以写成带容量约束的信息瓶颈:

$$
\max_{p(m\mid e)} I(M;Y'\mid X')-\beta I(M;E), \tag{9}
$$

第一项奖励记忆对未来结果的预测或决策价值, 第二项惩罚把整段轨迹原封不动存下. 实际系统无法直接计算互信息, 但这个形式揭示压缩的矛盾: 摘要太短会丢掉适用条件和反例, 太长又挤占上下文并带入噪声. ACE 的增量条目试图减少整篇重写造成的信息损失, A-Mem 的链接试图保留关联, 两者都没有自动解决「哪些细节对未来有用」.

一条可审计记忆至少包含命题、作用域、来源、时间、置信和反证. 命题是准备复用的内容; 作用域说明在哪些任务和环境下成立; 来源指回原始轨迹或外部证据; 时间用于判断过期; 置信记录证据强度而非生成模型的语气; 反证保存已知失败条件. 若只存一句「遇到测试失败先重装依赖」, 后续无法知道它来自哪个仓库、是否只适用于锁文件损坏、有没有导致环境被破坏的反例.

来源不能在压缩时丢失. 记忆文本 $m$ 可以是多个轨迹的归纳, 仍应维护来源集合 $L(m)=\{e_{i_1},\ldots,e_{i_k}\}$. 新证据支持或反驳条目时, 更新的是来源图和条目置信, 而非直接覆盖原句. 若发现某条原始轨迹标签错误, 可以沿来源边撤销其贡献. 没有来源图, 一条错误经验被合并进十次摘要后几乎无法清除.

召回的目标超出语义近邻, 它要选择对当前决策有正边际价值的证据. 设不注入记忆时行为效用为 $V(x)$, 注入集合 $A$ 后为 $V(x,A)$, 记忆集合的价值为

$$
\Delta(A\mid x)=V(x,A)-V(x)-\lambda C(A), \tag{10}
$$

$C(A)$ 包含 token、延迟与干扰. 两条单独有用的记忆一起注入可能冲突, 所以 $\Delta$ 不一定可加. 单纯取相似度最高的前 $k$ 条假定每条贡献独立且与长度无关, 在存在冲突、重复和顺序效应时不成立.

召回可以分成候选生成、证据过滤和集合选择. 候选生成追求高召回率, 允许混入无关项; 过滤器检查时间、权限、作用域和来源强度; 集合选择在预算内覆盖互补信息并减少冲突. 条目间交互集中在集合选择阶段. 把三步压成一次向量排序速度快, 代价是无法说明漏召回、错召回和组合干扰分别贡献了多少错误.

检索质量要在行为层测. 常见的 Recall@k 只问目标条目是否出现在前 $k$, 可目标条目未必真的帮助模型, 也可能存在多个等价条目. 更直接的指标是干预后的任务差值: 固定任务与随机种子, 分别运行无记忆、召回集合、人工最小充分集合和随机同长度集合. 无记忆对照测总收益, 人工集合测检索还有多少上限, 随机集合测仅增加上下文的影响. 若召回集合与随机集合相近, 向量指标再高也没有转化为决策价值.

注入位置改变记忆的作用. 系统指令附近的条目更像高优先级规则, 工具结果旁边的条目更像局部证据, 末尾附录可能被忽略. 同一条记忆放在不同位置取得不同结果, 不应归因为条目本身. 评测记忆库时应冻结模板与位置; 要优化注入策略, 则固定条目集合单独比较. MemGPT 让模型主动换入换出, 相当于把注入决策交给执行策略, 它的收益同时包含存储和控制能力.

记忆会形成反馈环. 条目影响行为, 行为产生新轨迹, 新轨迹又支持原条目. 若系统把自己的成功判断当独立证据, 一个早期误判会被反复强化. 设条目置信为 $c_t$, 每次被采用后按照自评结果 $y_t$ 更新 $c_{t+1}=c_t+\eta y_t$, 当 $y_t$ 受条目本身影响且判官偏宽松时, 更新并非独立观测. 防止自证需要外部结果、可执行验证或与条目无关的审计样本. 同一模型的反思可以提出修改, 不足以确认修改.

矛盾记忆需要保留条件, 不能简单投票. 「先运行完整测试」与「先运行最小失败测试」在不同时间预算下都可能正确. 将两条合并成「视情况选择测试」丢掉了可执行边界; 只保留票数高者又抹掉少数场景. 更好的表示是带条件的规则图: 节点存命题, 边表示支持、反驳和限定, 查询时根据当前上下文激活条件. 条件未知时返回冲突状态, 让控制器补充信息.

时间衰减只适用于会自然过期的事实, 不适合作为统一遗忘规则. API 版本、用户偏好和环境状态随时间变化, 旧条目应降权; 数学恒等式、验证过的故障机制不会因时间自动失效. 记忆项需要声明变化过程. 对易变事实可以设生存概率 $P(v_t=1\mid\Delta t)$, 超过阈值后要求重新验证; 对稳定规则按新反证更新, 不做机械衰减.

删除是一种有风险的干预. 条目长期未被召回, 可能是任务分布暂时没有覆盖; 条目被频繁召回但看不出收益, 可能是它与其他条目冗余. 直接删除后若未来任务失败, 很难知道是否与删除相关. 因此先降级为冷存储, 在线不主动召回, 回归与审计仍可访问. 观察一段任务窗口后没有负面变化, 再做物理删除. 高风险保护条目即使低频, 也应按事件损失而非触发次数决定保留.

反事实回放能估计删除影响. 对历史任务 $x_i$, 固定其他记忆与执行条件, 比较含条目 $m$ 和移除 $m$ 的结果. 记贡献

$$
C(m)=\sum_i w_i\big[Y(x_i;S)-Y(x_i;S\setminus\{m\})\big]. \tag{11}
$$

权重 $w_i$ 应接近未来部署分布并提高高风险任务比重. $C(m)\approx0$ 不一定表示条目无用, 它可能被另一条冗余记忆替代. 可以进一步成组移除相似条目, 检查共同贡献. SkillBrew 的留一思想同样适用于记忆, 只是记忆的静默注入让调用边界更难确认.

记忆容量还受上下文读取能力限制. 存储可以无限增长, 每次能注入的 token 有限. 当候选条目数增加, 检索阈值不变会带来更多假阳性; 提高阈值又会漏掉罕见表达. 这类似开放集分类, 新任务可能不属于任何已有记忆的作用域. 选择器应允许「不用记忆」这个动作, 并校准拒绝阈值. CTIM-Rover 的结果说明无条件注入全部记忆会低于无记忆基线, 拒绝能力本身就是记忆系统的重要能力.

多用户系统还要处理记忆所有权与信息流. 用户画像、私有轨迹和组织经验不能因语义相似被另一个用户召回. 权限过滤必须发生在候选进入模型上下文之前, 不能先把敏感文本交给模型再要求它忽略. 删除请求需要沿来源图移除原文、摘要、派生条目和缓存; 只删向量库的一条索引, 派生总结仍可能泄露信息.

评测长期记忆不能随机打散会话. 若同一用户、仓库或事件的近重复信息跨训练和测试, 系统可以靠表面相似召回, 看不出能否处理真正的时间变化. 更严格的划分按实体和时间切割: 早期轨迹用于写入, 后期任务测试复用; 再加入事实反转和工具升级, 检查旧记忆能否被纠正. 指标同时报告收益、误注入、过期条目使用率、冲突发现率与删除后的回归.

记忆层的核心由此落在治理, 不在存储介质. 向量、图、层级摘要分别提供不同索引结构, 它们都无法自行判断一条经验是否真实、是否仍有效、是否值得影响当前决策. 写入门、来源链、作用域、拒绝选项、冲突处理和可逆遗忘共同决定存储会积累能力还是积累噪声.

## 4. Harness

### 4.1 当作外围对象

技能和记忆决定哪些经验保留下来, harness 决定每个持久组件怎么被调用, 观察和提交. 它构造上下文, 调用工具, 观察轨迹, 归因失败, 执行内部检查; 提出, 内部筛选, 提交和回滚由固定的改进器控制. 综述认为这是 L2 里最薄的一层: 很多看起来是改循环的工作, 保留下来的其实是训练过的权重, 属于 L1.

第一类从外部对待 harness, 本身不保留演化后的 harness.

综述举的 CUDAnalyst 冻结 CUDA 核生成的轨迹, 选择性地注入单个反馈组件, 用联盟式归因找出哪些信号真正驱动了规划决策. 它的贡献是可观测性: 之后的增益可以追溯到某一处反馈与推理的交互. 这是诊断分析, 本身不构成持久的脚手架更新. AutonomyLens 把场景规格, 仿真执行, 遥测分析, 反事实测试生成合成一个测试循环, 从观察到的失败合成新测试. 它产生的是端到端的行为证据, 但一个可写的测试 harness 可以提供开发证据, 不能充当自己那次更新的外部审计.

**AutoHarness** (Lou 等, 2026, Google DeepMind) 把对象收窄到防护代码. 起因是一个统计: Gemini-2.5-Flash 在 TextArena 游戏里的失败, 78% 来自非法动作. 它让 Gemini-2.5-Flash 为每个游戏写一个 Python 的合法动作校验器, 根据环境报错反复修改, 用 Thompson 采样做树搜索, 合法率到 100% 停止. 生成的 harness 在 145 个游戏里拦下了全部非法动作, Flash 带上它, 在 16 个单人游戏上平均奖励 0.745, Gemini-2.5-Pro 0.707. 另一个变体把整个策略写成代码, 推理时不再调用模型, 平均奖励 0.870, GPT-5.2-High 0.844. 拦截发生在动作执行之前.

### 4.2 当作保留的程序

第二类把 harness 本身当作持久的, 可演化的程序.

**Meta-Harness** (Lee 等, 2026, 斯坦福等) 把整个 harness 当优化目标. 提议者是一个编程 Agent, 可以通过文件系统读到以往所有候选的源码, 分数和完整执行轨迹, 而不只是一段压缩过的摘要. 在线文本分类上, 比 ACE 平均高 7.7 个点 (48.6 对 40.9), 上下文 token 少到约 1/4. 检索增强的数学推理上, 一个搜出的 harness 在五个没参与搜索的模型上, 200 道 IMO 级题目平均提高 4.7 个点. TerminalBench-2 上, Opus 4.6 用搜出的 harness 达到 76.4%, 手工设计的 Terminus-KIRA 74.7%. 论文自己说明, TerminalBench-2 的搜索和最终评测用的是同一套 89 题, 这一项是开发证据.

**Self-Harness** (Zhang 等, 2026, 上海人工智能实验室) 不借助更强的外部模型, 让同一个模型改进自己的 harness: 从执行轨迹里挖掘这个模型特有的失败模式, 针对它提出最小修改, 修改通过回归测试才采纳. 三个模型乘三个基准的九种组合, 最终 harness 在留入和留出样本上都提升. 部分结果:

| 模型 | 基准 | 初始 | 最终 |
|---|---|---|---|
| Qwen3.5-35B-A3B | Terminal-Bench 2.0 | 18.0 | 36.7 |
| Qwen3.5-35B-A3B | SWE-bench Verified | 19.5 | 41.5 |
| Qwen3.5-35B-A3B | AppWorld | 22.5 | 52.2 |
| GLM-5 | SWE-bench Verified | 52.0 | 55.5 |
| GLM-5 | AppWorld | 44.4 | 85.0 |

起点低的模型相对提升大, 起点高的在 SWE-bench 上只提高 3.5 个点.

**M★** (Pan 等, 2026, 港城大与微软) 把记忆 harness 写成可执行的 Python 程序, 包含 schema, 逻辑, 指令三部分, 一起做反思式代码演化, 每个配置 20 轮, 按验证集选最好的程序, 在测试集上报告. 八个指标里七个最好, 相对最强基线最多高 31%. ALFWorld 已见任务上 0.700, 低于 GEPA 加向量检索的 0.820. 它的做法是给每个任务配一个专门的记忆循环.

**MemoHarness** (Huang 等, 2026, 圣母大学等) 把 harness 拆成六个可编辑的控制维度: 上下文, 工具, 编排, 记忆, 解码, 输出处理. 经验库分两层, 逐例诊断和蒸馏出的全局模式; 推理阶段按检索到的经验为每个用例调整 harness. Terminal-Bench 上 GPT-5.3-Codex 达到 0.806, 比最强基线 Codex 高 0.084. 摘要自己写明, 统计稳健性和组件归因留给以后的工作.

**Continual Harness** (Karten 等, 2026, 普林斯顿等) 是综述的收尾案例: 不重置环境, 在同一次运行里一边行动一边改自己的提示, 子 Agent, 技能和记忆. 论文报告, 用它的 Agent 是第一个在不输一场战斗的条件下通关宝可梦蓝, 困难模式的黄和水晶的 AI 系统. 从零开始时, 它相对极简基线大幅减少按键成本, 补回了和人工专家 harness 之间的大部分差距. 它还包含一个在线协同学习环节: 开源模型的轨迹由前沿教师模型重新打标签, 再用来更新开源模型, 这部分是 L1. 综述引用它是为了保留下来的 harness 改动, 那是更深的 L2 目标.

### 4.3 更新能力和获益能力

Lin, Wu 等 (2026, 宾州州立等) 把两种常被混为一谈的能力拆开: 从执行证据写出持久的 harness 更新的能力, 和在解题时真正从更新中获益的能力.

- 更新能力和基座能力关系不大: Qwen3.5-9B 写出的更新, 带来的增益和 Claude Opus 4.6 写的相当.
- 获益能力随基座能力先升后降: 弱模型从更新后的 harness 获益很少, 中等模型获益最多, 强模型比中等模型获益少.

SWE 任务上的数据:

| 模型 | 基线 | 用更新后 harness 的增益 |
|---|---|---|
| Qwen3-32B | 3.6 | 4.4 |
| Qwen3-235B | 20.7 | 19.3 |
| GPT-OSS-120B | 26.2 | 15.8 |
| Haiku 4.5 | 66.0 | 2.4 |
| Sonnet 4.6 | 73.2 | 2.8 |
| Opus 4.6 | 74.2 | 2.6 |

弱模型获益少的一个原因是根本没用上: SkillsBench 上, Opus 4.6, Sonnet 4.6, Qwen3-235B 加载技能的比率在 0.957–0.961, GPT-OSS-120B 0.446, Qwen3-32B 0.251.

综述把这篇当作 L2 外部审计的主要依据, 并强调它是特定模型上的经验结果, 不是规律. 它说明了一件事: 一次成功的更新加上一个更高的分数, 本身不能证明在声明的外部目标下变好了. 写出更新的是一方, 从中获益的是另一方, 两者要分开评.

### 4.4 Harness 是闭环控制器

Harness 容易被误解为把提示、工具和重试粘在一起的工程外壳. 从行为上看, 它是一个闭环控制器. 环境状态 $s_t$ 经观察函数产生 $o_t$, harness 根据内部状态 $h_t$ 与观察选择模型调用、工具动作或提交:

$$
a_t=\pi_H(o_t,h_t),\qquad
h_{t+1}=F_H(h_t,o_t,a_t),\qquad
s_{t+1}\sim T(s_{t+1}\mid s_t,a_t). \tag{12}
$$

提示决定一次模型调用怎样响应, harness 决定什么时候调用、观察什么、把什么写回状态以及何时停止. 只改 $F_H$ 或 $\pi_H$ 而不改模型权重, 仍可能彻底改变 Agent 的能力边界. AutoHarness 的合法动作校验器在动作进入环境之前截断非法分支, 就是在转移函数外加了一个可执行守卫.

控制器面对的是部分可观测环境. 工具返回空结果可能表示对象不存在、权限不足、查询错误或服务暂时故障. 若 harness 把四种观察映射成同一状态, 后续只能盲目重试或放弃. 接口应保留可辨识的错误码、来源和可重试属性; 无法区分时安排诊断动作. 诊断本身有成本, 只有它可能改变后续决策时才值得执行.

闭环的稳定性比单步正确更难. 一次反思可能提高当前答案, 反复反思却会在两个版本之间振荡; 一个失败触发器可能不断生成相同修复, 状态没有进展. 可以给状态定义势函数 $\Phi(h_t)$, 表示未解决约束、失败测试和剩余不确定性. 合理更新应在成功路径上使势函数下降, 或至少在有限步内进入不同策略. 若连续更新不降低 $\Phi$, harness 应停止、回滚或升级, 不能只增加轮数.

最简单的终止证明来自有限状态与单调量. 假设待处理义务集合 $U_t$ 有限, 每次循环要么验证并删除一个义务, 要么以明确失败结束, 且不允许无证据地重新加入已删除义务, 则循环至多执行 $|U_0|$ 次有效步骤. 真实 Agent 会发现新义务, 可以给新增设置总预算并要求来源. 没有单调量的「直到模型认为完成」只是一条经验停止规则, 在环境反馈异常时可能无限循环.

Harness 的正确性可以拆成安全性与活性. 安全性是任何前缀都不能违反的约束, 如未经授权不得写外部系统、没有证据不得声明验证通过. 活性是满足前提后最终应发生的事件, 如可用工具正常时任务最终完成或返回明确失败. 过度防守的 harness 可能安全但没有活性, 对所有请求都拒绝; 过度激进的 harness 可能有活性但不安全, 总能给出结果却绕过验证. 两类性质要分别验收.

自修改使控制器同时成为被控对象. 当前版本 $H_t$ 产生轨迹, 提议器根据轨迹生成候选 $H'$, 验收器决定是否升级. 这个过程可写成

$$
H_{t+1}=\begin{cases}
H',&A(H',H_t;D_t)=1,\\
H_t,&\text{其他}.
\end{cases} \tag{13}
$$

若 $D_t$ 同时用于生成候选和接受候选, 验收器已经暴露给搜索. Meta-Harness 在同一 TerminalBench-2 题集上搜索并最终报告, 因而那组分数描述的是 $D_t$ 上的开发结果. 要获得外部证据, 接受函数至少要访问提议器没有反复查询的探针, 最终还要在冻结后测试.

接受函数需要偏向在任版本. 新旧表现接近时保留旧版, 能减少噪声造成的版本抖动. 设任务损失差为 $d_i=L_i(H')-L_i(H_t)$, 成本差为 $c_i$, 安全违规为 $v_i$. 一种有界接受规则是: 所有硬约束 $v_i=0$, 配对损失的置信上界小于 $-\delta$, 且成本不超过预算. $\delta$ 是最小有意义改进, 防止为统计可见但实际无价值的小差异承担迁移风险.

单一平均分会允许尾部退化. Harness 控制外部动作时, 少数严重失败的损失远大于许多普通成功. 可以约束条件风险价值

$$
\operatorname{CVaR}_{\alpha}(L)=
\mathbb E[L\mid L\ge q_{\alpha}], \tag{14}
$$

它关注最差 $1-\alpha$ 比例的任务. 候选即使平均损失下降, 若 CVaR 上升或新增不可逆副作用, 仍不升级. 对样本很少的灾难事件, 不能只依赖统计估计, 还要写成确定性权限和事务守卫.

事务边界决定回滚是否真实. 代码与提示可以切回旧版本, 已发送的消息、删除的数据和外部付款不能自动撤销. 候选 harness 在影子模式下只读运行, 或把写动作替换成模拟器, 能在放量前观察决策. 必须在线测试写操作时, 使用可撤销事务、幂等键和人工确认. 把「保留旧代码」叫回滚, 却无法补偿外部副作用, 只是版本切换.

状态迁移也属于升级. $H'$ 可能改变记忆 schema、技能标识或未完成任务的阶段枚举. 若继续读取旧状态, 默认值会让新控制流走入未经测试路径. 每个持久状态携带版本, 迁移函数满足幂等性, 同一状态重复迁移不会继续变化. 无法证明兼容时, 应冻结旧任务让旧版完成, 新任务使用新版, 而非在线强行转换.

Harness 搜索空间越自由, 越容易通过扩大权限或计算预算取巧. 候选差异审查应列出新增工具、网络域、文件范围、模型调用、最大循环次数和上下文来源. 一个候选因为能访问答案文件而提高分数, 与一个候选因为改进规划提高分数, 在端到端指标上可能相同. 权限差异和资源差异必须先于任务得分检查.

测试 harness 不能由候选随意改写. 若候选可以同时修改实现与验收脚本, 最短路径是放宽断言. 测试生成可以作为候选提出, 接受权归外部验证链; 新测试先证明能抓住已知错误或人工构造的变异, 再进入正式门. AutonomyLens 一类系统生成新场景很有价值, 这些场景在被独立确认前仍是开发资产, 不能单独证明生成它们的 harness 更可靠.

可观测性决定能否把失败变成有效候选. 每个控制步骤记录输入引用、状态版本、选择动作、工具副作用、预算和结构化错误, 形成可回放轨迹. 完整思维文本既不稳定又可能含敏感信息, 并非必要日志. 归因需要的是因果相关的外部状态和决策接口. 若日志只留最终答案, Self-Harness 所说的模型特定失败模式就无法从证据中分离出来.

回放分为确定性控制回放和在线交互复测. 保存模型输出与工具结果后, 新旧 harness 在同一轨迹材料上运行, 能隔离控制逻辑差异; 新结构可能选择旧轨迹里不存在的新动作, 回放无法继续. 在线复测允许新的调用, 但重新引入模型和环境噪声. 两者结合: 回放快速覆盖大量历史状态, 在线任务确认新分支与真实副作用.

Harness 的通用性需要跨底座验证. 一个为弱模型加入多层复核的流程, 对强模型可能只增加上下文噪声; 一个依赖强模型稳定输出 JSON 的控制器, 弱模型根本无法进入正确状态. Lin 与 Wu 等观察到获益能力随底座先升后降, 说明更新产物和消费者之间有匹配函数 $B(H,M)$. 不能脱离模型 $M$ 给 harness 一个绝对质量分, 应报告不同模型能力区间内的收益和失败方式.

同样, 专用 harness 与通用 harness 的目标不同. M★ 为每个任务演化一套记忆程序, 搜索可以利用任务结构; 共享 harness 要在更多任务上折中. 专用程序分数高不代表可迁移, 通用程序平均稳定也可能放弃某些领域上限. 评价时要明确产物准备复用到哪个任务分布, 再按该分布构造留出证据.

把 harness 视为闭环控制器以后, 「提示改了几句」「多加一个 Agent」都只是表面 diff. 真正要审查的是观察是否更可辨识、状态转移是否满足不变量、停止是否有界、权限是否收缩、接受证据是否独立以及消费者能否利用更新. 这些性质共同决定外围程序能否把一次修复变成持续能力.

### 4.5 更新的信用与消费者的依从

一次 harness 更新通常同时改变多处行为. 新版多检索一轮、换了错误分类、增加复核并延长预算, 总分上升后无法知道哪一处必要. 设更新由二元组件向量 $z=(z_1,\ldots,z_m)$ 表示, 任务效用为 $J(z)$. 单组件贡献可用干预差

$$
\Delta_i=J(z_i=1,z_{-i})-J(z_i=0,z_{-i}), \tag{15}
$$

但它依赖其他组件的取值. 某个复核器只有在检索器提供来源时才有用, 单独关闭任一项都会丢掉全部收益. 因而还要看交互

$$
\Delta_{ij}=J(1,1,z_{-ij})-J(1,0,z_{-ij})-J(0,1,z_{-ij})+J(0,0,z_{-ij}). \tag{16}
$$

交互很强时, 把成绩平均分给两个组件没有机制含义; 应把它们视为组合模体, 一起版本化和回归.

组件多时全因子实验成本指数增长. 可以先用轨迹定位可能相关的部件, 再做局部随机消融. 轨迹只负责提出因果假设, 随机开关或配对回放负责检验. 「某节点在成功轨迹里经常出现」只是相关性, 困难任务可能更常触发它, 让有益节点表面上与失败相关. 反过来, 一个无用节点也可能因只在容易任务触发而显得有效.

模型是否遵从 harness 也要单独测. 一个技能被放入上下文, 不代表模型读取并执行. 可以设计可观察标记: 技能规定特定中间字段或工具次序, 从轨迹判断是否采用; 再把采用率 $A$ 与采用后的条件收益 $G$ 分开:

$$
\mathbb E[\Delta Y]=P(A=1)\mathbb E[\Delta Y\mid A=1]
+P(A=0)\mathbb E[\Delta Y\mid A=0]. \tag{17}
$$

若采用率低而条件收益高, 应改路由、接口或提示显著性; 若采用率高而收益低, 说明更新内容本身有问题. SkillsBench 报告的加载率差异正说明弱模型可能连使用阶段都没有进入.

显式采用仍不等于因果使用. 模型可能复述技能名称, 实际答案来自自身能力. 对照可以把技能正文替换成长度和格式相似的空内容, 或打乱与当前任务无关的字段. 真技能优于安慰剂技能, 才说明语义内容有贡献. 另一个对照是给出正确技能但故意改变描述使检索失败, 用来分离条目质量与召回质量.

获益能力还受上下文竞争影响. 更新后的 harness 注入更多规则, 可能让强模型忽略原本足够的任务证据; 弱模型则可能没有能力综合新规则. 设模型可有效利用的上下文容量为 $B_M$, 注入内容的信息负载为 $L_H(x)$. 当 $L_H(x)>B_M$ 时, 新增条目会挤出其他证据. 这里的 $B_M$ 指模型对特定任务可稳定整合的信息量, 通常远小于标称上下文窗口. 因而压缩、路由与拒绝注入常比继续扩充技能库更重要.

更新器与消费者可能是同一个模型, 也可能不同. 同模型更新有适配优势: 它熟悉自身输出与失败模式; 也有共同盲点: 生成更新时漏掉的错误, 使用更新时可能继续漏掉. 强教师写给弱模型的技能可能逻辑正确但超出消费者执行能力. 验收要在真正消费者上做, 不能用写手模型的表现代替.

跨模型共享时, 可以把技能契约分成语义层和实现层. 语义层描述目标、前置条件和可观察结果; 实现层给某类模型具体提示、示例或代码. 新模型先通过语义探针, 再选择或生成适配实现. 这样共享的是稳定意图, 不把某个底座的提示习惯误当通用知识. 若语义探针不过, 系统应阻止复用, 而非通过更长提示强行补偿.

信用还会跨时间延迟. 一个记忆写入今天没有立即改变结果, 一周后在相似任务中减少了错误; 一个压缩策略今天节省 token, 数月后让来源无法追溯. 只把当前任务奖励分给当前更新, 会低估延迟收益与延迟损害. 存储条目和 harness 版本需要可追踪标识, 后续任务记录实际依赖, 才能把长期结果回连到历史决策.

延迟信用不宜无限回溯. 影响链越长, 混杂越多. 可以设时间窗和依赖图: 只有被检索、被解析或改变路由的组件进入候选归因集合; 没有行为路径的旧条目不因一次成功自动加分. 这比按时间接近分配奖励更符合因果结构. 对影响无法观察的静默记忆, 应先改善日志和干预接口, 再谈自动贡献估计.

最终的决策不必把所有贡献压成精确数值. 当证据只能确认「这个组合在某类任务有益, 单组件作用不明」时, 保留组合并标注适用范围已经足够. 伪精确的信用分会让下一轮搜索过度相信噪声. 信用分配的目标是支持安全的添加、路由、缩小作用域和删除, 不是给每段文本生成一个看似科学的排名.

## 5. 可靠性与固定改进器的上限

### 5.1 外部审计

综述对 L2 改动的认证证据是: 在改动没有参与挑选的任务上, 修改后的 Agent 和在任脚手架做受控的端到端对比. 一个汇总的基准分数不够, 因为它把改动的贡献和样本运气, 多出来的工具调用, 更多的检索上下文, 更宽松的判官混在一起.

可靠性条件包括: 有代表性的新任务; 对齐模型, 工具, token 预算和停止规则; 提议方不能无限查询的验收门; 测试过的回滚路径.

外部审计的「外部」指信息边界, 不一定指另一个组织. 只要候选生成过程没有访问审核样本、审核规则不能被候选改写、结果由独立执行路径复核, 同一团队也能建立外部门. 反过来, 换一个判官模型却把完整测试反馈逐轮交给提议器, 仍然是内部开发循环.

审计对象应是从输入到副作用的完整行为. 对任务 $x_i$, 记录质量 $q_i$、成本 $c_i$、延迟 $l_i$、违规 $v_i$ 与是否可恢复 $r_i$. 候选相对在任版本的差值向量为

$$
d_i=(\Delta q_i,\Delta c_i,\Delta l_i,\Delta v_i,\Delta r_i). \tag{18}
$$

先检查违规和不可恢复失败这类硬门, 再比较质量—成本前沿. 若一开始就把五项加权成总分, 一个严重违规可以被大量普通任务的小幅提分抵消. 权重也容易在看到候选结果后调整, 形成新的选择偏差.

配对运行能显著提高审计效率. 新旧版本处理同一任务、相同工具快照与相同随机种子, 比较逐任务差值, 可以抵消任务难度. 模型 API 无法固定随机性时, 每个版本运行多个交错种子, 避免时间段和服务负载只影响一方. 对工具会修改环境的任务, 从同一快照复制两个隔离环境, 不能让先运行的一方改变后运行的一方.

样本应按改动声称的作用域分层. 一次只修网页表单的技能, 主效应集覆盖不同网站和表单类型, 邻接集覆盖相近但不应触发的浏览任务, 全局回归集保护其他能力. 只在全库平均上测, 局部改进可能被稀释; 只测目标失败, 又看不到静默回归. GRASP 把原失败与原成功组成平衡探针, 正是在同时估计修复与破坏.

接受条件应在试验前冻结. 例如硬违规为零, 目标作用域的配对改善下界大于零, 邻接集不劣于预设容忍度, 全局成本不超过上限. 容忍度不能等看到结果后再选. 若数据不足以区分两版, 结论是证据不足, 保留在任版本; 不能把「没有显著变差」解释成「已经证明等价」.

等价验收需要单独设计. 对重构或成本优化, 目标可能是质量不下降而资源更少. 传统差异检验不显著无法证明不劣, 应预先给出可接受损失 $\delta$, 检验候选质量差的下界是否高于 $-\delta$. $\delta$ 由业务风险决定, 不是由样本量倒推. 高风险动作的容忍度可以为零, 普通语言风格允许更宽.

多项指标和许多任务组会产生多重比较. 若候选只要在几十个切片中找到一个亮点就宣传提升, 偶然结果几乎必然出现. 审计应指定主要终点, 次要切片用于解释机制; 对探索性发现明确标记并在新样本复现. 搜索过的候选数同样属于多重比较的一部分, 最终冠军需要独立复测.

判官模型适合补充难以自动评估的质量, 不适合独占接受权. 判官应先在带人工或执行结果的校准集上测假阳性、假阴性和分组偏差. 两个版本措辞差异很大时, 盲化版本标识和随机交换顺序, 减少位置与风格偏好. 对判官最不确定或彼此分歧的样本做人工复核, 比均匀抽样更能发现门的漏洞.

外部审计还要防数据污染. 技能条目、记忆和日志可能直接包含基准答案; harness 可能依据任务编号走专用分支. 发布前扫描评测标识、答案片段和数据路径, 运行格式扰动与同能力新题. 若轻微改写题面后成绩骤降, 原提升更像模板记忆. 对代码任务, 密封测试与公开测试必须由不同来源维护.

回滚演练是验收的一部分, 不是事故后的临时动作. 在隔离环境中升级候选、制造失败、恢复旧版, 检查代码、状态、缓存和权限能否一起回到一致版本. 若只能回滚程序但不能回滚被改写的技能库, 旧程序可能读取新 schema 继续失败. 演练还应确认审计日志没有因回滚丢失, 否则无法解释事故.

审计报告应保留失败而非只留冠军. 哪些任务退化、哪些约束触发、候选看过多少开发样本、为何接受或拒绝, 都会影响后续改进器的候选分布. 但被拒候选不能因为进入档案就改变正式运行行为; 档案服务于研究与避免重复, 正式 $Σ$ 只包含通过门的版本. 这条隔离防止「虽然没升级, 但模型看见失败补丁后已经受影响」.

外部审计证明的是在声明分布和权限边界内的相对改进. 它不证明所有未来任务都更好, 也不证明更新机制会持续产生改进. 结论的范围应与任务覆盖、时间跨度和消费者模型一致. 超出范围时重新认证, 比给一次通过的版本贴永久「可靠」标签更诚实.

### 5.2 有界的生命周期

对会累积的存储, 这个条件变得更具体: 生命周期要有界, 不能只增不删.

**Ratchet** (Zhang 等, 2026, AWS 生成式 AI 创新中心) 在冻结模型外面做了一个最小方案: 每个技能维护一个贡献值; 至少试过 $N_{\min}$ 次之后贡献低于 $-\tau$ 就淘汰; 活跃技能数上限为 $C$, 溢出时淘汰最弱的; 用一个写作先验约束新技能的合成. 论文证明了一个命题: 如果 LLM 判官把失败判成通过的比率 $\epsilon$ 满足

$$
\epsilon \ge \frac{1-\tau}{2}, \tag{19}
$$

那么不管样本多大, 这条规则一个技能也淘汰不掉. 淘汰规则的可靠性受判官可靠性约束, 判官太宽松, 按贡献淘汰这一步就不起作用. 在 MBPP+ 的难题切片上, 留出 pass@1 从 0.258 升到峰值 0.658, 滚动增益 +0.328. 论文还发现, 最终任务分数是一个很差的警报, 它的变化最多只有受治理部分增益的五分之一. 综述提醒, 它的「不跌破无技能基线」是一个在其假设下成立的命题, 这个基线就是让回滚有意义的外部锚点.

同一组作者的 **Library Drift** 定义了技能库漂移: 技能无界累积又不按结果淘汰时, 检索质量下降, 误注入增多, 性能停滞. 消融里, 关掉技能注入, 增益只有 +0.002; 淘汰过于严苛, 增益变成 −0.019, 有害; 去掉写作先验, 增益从 +0.328 降到 +0.187. 他们用一个可复现的漂移触发消融, 加上每个技能的贡献分和路由参与日志, 定位了这个问题.

### 5.3 脚手架过拟合

L2 的典型失败是脚手架过拟合: 贴合了基准, 判官, 记忆或路由器的特性, 没有学到可迁移的流程. 综述分出三种可以诊断的形态.

第一种是留出集被侵蚀和长时漂移. 一个名义上的留出集被反复查询, 就变成了自适应的开发证据. 综述引用的一项 391 个连续会话的研究报告了这种模式: 为了可靠性加入越来越多形式化, 符号化的约束, 结果适得其反, 系统退化成在符号层面自我指涉, 丢掉了任务语义. 综述也说明这只是单个项目的案例研究.

第二种是组件交互造成的混杂. 长的多 Agent 轨迹里错误出现得晚, 依赖相互缠绕, 一个候选看起来更好, 可能只是工作转移了或上下文变长了. 失败要定位到具体的 Agent, 步骤和 harness 产物. 综述举了两个做法: 从症状往回追溯, 只在证据确认后才更新情景记忆; 把基于轨迹的归因映射到有作用范围的修复操作, 在回归感知的验证下才接受.

第三种是存储的静默漂移. 一个局部有益的改动, 在检索策略或相邻技能变化之后让行为变差. Library Drift 是这一种的例子.

三种形态的共同点: 本地检查抓不到只在组件交互, 反复使用或之后检索中才出现的失败. 所以外部审计必须是一个受控的程序, 不能只是一个分数.

### 5.4 下一个上限

脚手架改得再全面, 也去不掉最后一个上限: 优化它的改进器是固定的, 人写的. 改进器决定能提出哪些改动, 候选怎么在内部筛选, 探索预算怎么分配; 固定的评判标准提供内部判断规则.

评估预算紧张时, 改进器的选择本身就有分量. **RoboPhD** (Borthwick, 2026) 在同样 1500 次评估的预算下比较三种优化算法: Elo 锦标赛选择 (RoboPhD), Pareto 选择 (GEPA), 贪心爬山 (Autoresearch). 四个基准里 RoboPhD 赢了三个, 只在最简单的一个上输了. ARC-AGI 上, 它把一个 22 行的种子 Agent 演化成 1013 行的多策略系统, 用 Gemini 3.1 Flash Lite 作求解器, 准确率从 27.8% 到 65.8%, GEPA 58.5%, Autoresearch 54.2%. RoboPhD 不单独留验证集, 用训练数据上的 Elo 对战同时完成评估和选择.

这组对比说明, 生成和内部选择哪些候选, 是由改进器决定的, 脚手架本身决定不了. 候选该不该被接受和升级, 仍是外部接受策略用匹配目标的证据来回答的问题. RoboPhD 的对象是优化范式本身, 综述把它归为 L3 的边界案例, 不应读作 L2 的能力结果. 让提出, 筛选, 提交, 回滚脚手架改动的过程本身成为演化目标, 就是第 4 部分的 L3.

### 5.5 长时验收与漂移定位

技能、记忆和 harness 的收益都具有时间结构. 新条目写入后, 短期任务与生成它的失败相似, 成绩容易上升; 随着任务分布变化、其他条目加入和工具升级, 原作用可能减弱或反转. 一次冻结测试只能证明某个时间切片, 长期可靠性要持续比较版本与环境.

设第 $t$ 个时间窗口的任务分布为 $D_t$, 脚手架版本为 $H_t$, 观测效用为

$$
J_{t}(H)=\mathbb E_{x\sim D_t}[U(H,x)]. \tag{20}
$$

从 $J_t(H_t)$ 下降无法直接推出脚手架退化, 因为 $D_t$ 也变了. 至少需要两个锚点: 当前版本在冻结探针 $D_0$ 上的 $J_0(H_t)$, 与在当前流量上的 $J_t(H_t)$; 有条件时再让旧版本 $H_0$ 在当前流量影子运行, 得到 $J_t(H_0)$. 四格比较能区分版本回归、任务漂移和共同环境故障.

若 $J_0(H_t)<J_0(H_0)$, 冻结能力出现回归; 若两版在当前分布都下降, 更像环境或任务变难; 若 $H_t$ 在冻结探针稳定却在当前分布落后 $H_0$, 新版本可能改变了对新任务的路由. 这些仍是诊断线索, 还需按错误类型和组件依赖定位. 只监控在线总分会把不同原因混成一句「系统变差了」.

冻结探针本身也会老化. API 被弃用后, 旧任务失败不一定说明能力下降; 基准答案被公开后, 成绩稳定也不再代表泛化. 探针分成三类更稳妥: 永久不变量检查安全和接口契约, 版本化任务检查当前环境, 密封滚动样本检查未见分布. 更新探针时保留旧版本与变更理由, 避免通过删掉失败任务让曲线看起来恢复.

滚动验收不能让改进器无限查询同一批密封样本. 可以建立分级门. 第一层是公开开发探针, 供候选快速淘汰; 第二层是周期轮换的审核探针, 只给有限入围候选; 第三层是延迟揭示的线上结果, 只用于确认已经部署的版本. 每次查询都消耗审计预算并记录, 预算耗尽便更换任务族. 这近似限制自适应数据分析中的信息泄漏.

序贯监控若每个窗口都做一次显著性检验, 偶然报警概率会不断累积. 可以预先设累计和或 e-value 一类序贯规则, 也可以使用简单但保守的连续失败门槛. 关键是规则在看结果之前确定. 看到某周下降后临时改变窗口、指标或分组, 会把普通波动包装成漂移证据.

平均收益之外要监控检索与调用过程. 技能层记录候选召回率、实际采用率、调用后净收益和回退率; 记忆层记录误注入、过期命中、冲突与拒绝率; harness 层记录路径分布、重试、异常、预算耗尽与权限拒绝. 最终分数尚未明显下降时, 过程指标常先暴露 Library Drift: 候选越来越多, 有效条目排名下降, 上下文变长, Agent 开始忽略正确技能.

过程指标也可能产生假警报. 例如模型升级后一次调用能解决过去三步的问题, 技能调用率下降是能力增强, 并非技能库失效. 因此报警后要运行反事实: 强制启用被怀疑技能与完全禁用技能, 比较配对结果; 把旧版本放在同一模型和工具环境中复测. 没有干预的相关曲线只能决定调查优先级, 不能自动触发删除.

定位漂移可以沿依赖图做二分. 最终失败先固定模型输出, 回放新旧 harness, 判断控制逻辑; 控制一致时固定召回集合, 比较新旧记忆或技能内容; 内容一致时比较检索排序与环境接口. 每一步只替换一层, 把搜索空间从整套系统缩到具体组件. 若新结构产生旧回放没有的新动作, 再对该分支做在线复测.

回滚粒度应与变更粒度一致. 一次发布同时添加十条技能、压缩记忆并改路由, 出现回归只能整包撤销, 好改动也一起丢失. 原子版本允许分别回滚条目、索引、选择器和控制程序; 发布清单记录兼容关系, 防止回滚某一层后剩余层无法读取旧 schema. 若多个改动只有组合才成立, 把组合声明成一个事务版本.

线上金丝雀要覆盖代表性路径, 不能只随机抽极少流量. 低频高风险任务在随机样本中可能一次也不出现. 可按权限、工具、任务难度和用户群分层, 每层设置最小样本与硬错误门. 新版先在无副作用或可撤销任务上运行, 再逐步开放写权限. 影子结果与正式结果的差异也要记录: 影子模式没有真实副作用反馈, 可能高估可执行性.

长期保留的证据应可重建. 每个版本关联源代码或提示哈希、依赖版本、数据切片标识、随机种子、候选搜索次数和接受报告. 只保存一个排行榜数字, 将来无法判断下降来自模型接口变化还是当时选择偏差. 原始用户数据可因隐私期限删除, 至少保留经过授权的聚合统计和可重放合成探针.

达到回滚阈值后也不应自动把失败轨迹直接写成新规则. 先回到已知安全版本, 再从故障样本提出候选; 候选重新走开发、审核与金丝雀. 否则漂移监控和在线改写形成高增益反馈环, 一次噪声报警便触发修改, 修改又改变指标, 系统可能持续振荡.

长时验收最终回答的是三个不同问题: 产物在生成后是否立即有效, 与其他产物共存一段时间后是否仍有效, 环境变化后是否还能识别自己已经失效. 前两个依赖回归和交互测试, 第三个依赖拒绝、过期和重新认证机制. 只有第一项通过的系统, 仍然只是会积累内容, 还不能称为会维护能力.

### 5.6 固定改进器看不见什么

L2 的改进器决定候选分布. 设所有可能的脚手架为 $\mathcal H$, 固定改进器在历史 $D$ 下能提出的候选支持集为

$$
\mathcal S_U(D)=\{H:P_U(H\mid D)>0\}. \tag{21}
$$

即使验收器完美, 它也只能从 $\mathcal S_U(D)$ 中选择. 真正更好的结构 $H^*$ 若不在支持集里, 增加评估预算只能更仔细地比较已有候选, 无法发现 $H^*$. 这就是固定改进器的表达上限.

支持集由表示和操作共同决定. 只允许改提示的改进器看不到新增工具; 只会增删节点的图搜索看不到状态机语义; 只做局部补丁的爬山法跨不过必须同时改变接口与调用方的低谷. AFlow 每轮只改一处便于归因, 也会限制必须组合改变的候选. 搜索偏置既带来效率, 也制造盲区.

局部最优不是抽象担忧. 假设旧 harness 的解析器与提示使用同一旧格式, 单独改提示会让解析失败, 单独改解析器也无法读取旧输出, 两处同时改才提高. 严格要求每个单补丁立即提升的接受门会拒绝两条路径. 可以把接口迁移声明为原子组合, 或允许在沙箱分支积累若干中间补丁后整体验收. 允许组合会扩大搜索与风险, 需要更强契约检查.

改进器还受观察限制. 日志没有记录被召回但未采用的技能, 它就无法提出改善依从性的候选; 工具只返回空字符串不返回错误类别, 它无法区分查询失败与目标不存在; 只看最终奖励, 它无法知道哪个中间接口丢了证据. 扩展可观测性会改变 $U$ 能提出什么, 但新增日志不等于更聪明: 无关字段也会扩大噪声和搜索空间.

信用模型构成另一层偏置. 若改进器把最后一个动作归因给整次失败, 它会不断修汇总器, 忽略早期检索错误. 若只修改最先失败的断言, 可能漏掉使错误可恢复的下游机制. 因果干预昂贵时, 归因只能是近似. 可靠做法是让归因提出少量竞争假设, 再通过组件开关和回放区分, 而非把一次解释直接变成持久更新.

固定目标也会制造盲区. 优化平均正确率看不到尾部风险, 优化当前成本会牺牲未来可审计性, 优化用户停留时间可能奖励冗长回答. L2 可以修改实现来更好地满足目标, 不能判断目标是否应变. 若系统开始改写 rubric、接受阈值或任务定义来让自己更容易通过, 最深改动已到 L4, 不能继续用原 L2 证据自证.

搜索算法影响在紧预算下尤为明显. 贪心把预算集中在当前最好候选, 适合平滑局部空间; Pareto 方法保留不同成本和能力折中, 适合多目标; 锦标赛能在绝对评分不稳时使用相对比较. RoboPhD 的比较表明相同评估次数下算法会得到不同结果. 这不说明某种算法普遍最好, 只说明「固定候选生成器无关紧要」这个假设站不住.

相对比较也有非传递性. A 在代码任务胜 B, B 在检索任务胜 C, C 又在低成本约束下胜 A. Elo 把结果压成一维能力时会丢掉条件. 任务分层与多维前沿能保留差异, 代价是需要更多样本. 若部署分布明确, 可以按真实频率加权; 分布未知时, 保留多个专门版本并由经过验证的路由器选择, 比强行选全局冠军稳妥.

改进器可能过拟合自己的语言偏好. 用同一模型诊断、写补丁和评审, 候选更符合它容易理解的表达, 不一定更适合执行模型. 引入不同模型、执行器和人工抽样能增加错误独立性, 但「多个模型同意」仍可能来自共同训练数据. 最强证据仍是与任务结果相连的可执行检查和密封样本.

探索范围扩大也不是免费进步. 允许修改任意代码、权限和工具, $\mathcal S_U$ 变大, 找到捷径与破坏性候选的概率一起上升. 安全边界应在候选空间之外由不可修改策略强制: 文件范围、网络域、凭证、最大成本和验收数据均不由普通 L2 更新改变. 想修改这些边界, 需要更高层授权与独立审计.

无法产生某类候选时, 正确结论是标出覆盖上限, 而非让改进器用更多同类尝试掩盖. 连续多轮候选只有措辞变化、错误机制不变, 表示当前操作集已饱和. 可以人工扩展表示、引入新的改进器或升级到 L3 研究, 但此前的 L2 结果只证明现有支持集内找到了较好产物.

固定改进器还有一个积极作用: 责任边界清楚. 候选生成规则、预算和接受门可预先审计, 出现退化能回放. L3 让改进器本身可变后, 这种稳定参照会减少. 因而越过 L2 并不自动更可靠; 它只是开放了新的候选来源, 同时要求对更新规则建立更高一层的证据与回滚.

### 5.7 第 3 部分小结

| 层 | 门最严的例子 | 门是什么 | 反例或警示 |
|---|---|---|---|
| 提示与程序 | SHARP | 单条规则编辑 + walk-forward 验证 | 自由改写提示让 Sharpe 转负 |
| 架构与工作流 | AFlow, ADAS | 验证集执行打分, 档案或搜索树 | GPTSwarm 的 GAIA 没用图优化, Mimosa 档案没触发 |
| 技能 | GRASP | 平衡探针上净增益为正且不新增回归 | SkillsBench: 自写技能平均 −1.3 |
| 记忆 | ExpeL, ACE | 投票删除, 增量编辑去重 | CTIM-Rover 所有配置不超过无记忆基线 |
| Harness | Self-Harness | 回归测试通过才采纳 | Meta-Harness 在 TerminalBench-2 上搜索集即评测集 |
| 生命周期 | Ratchet | 按贡献淘汰 + 活跃上限 | 判官误判率达到 $(1-\tau)/2$ 时一个也淘汰不掉 |

五层看下来, 能稳定带来增益的系统都有一个共同结构: 写入前在没有参与挑选的样本上验证净效果, 删除和添加同等对待, 留着回滚路径. 缺了这些, 积累本身不带来能力, 有时还会带来退化.
