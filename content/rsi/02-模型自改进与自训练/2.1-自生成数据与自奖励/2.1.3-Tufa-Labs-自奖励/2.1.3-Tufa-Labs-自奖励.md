# Tufa Labs：冻结的自裁判，不是会升级的改进器

有大模型基础的读者对 RLHF 不陌生：人类偏好训一个奖励模型，再冻住它去 PPO。Tufa Labs 这篇把奖励模型换成**同一家族的 LLM 裁判**，并且故意**不给标准答案**：裁判只看见题目和作答，输出正确 / 不正确。卡住的瓶颈不是「会不会 GRPO」，而是——没有程序化奖励时，生成比验证难这一不对称，能不能撑住一条稳定的训练信号。

本篇是 Model 层里 Self-Rewarding 家族的实验对照，不是另一套坐标系。Meta 的 Self-Rewarding LM 让同一 $\theta$ 既答题又打 1–5 分，迭代 DPO 时裁判跟着运动员一起变；Tufa 把裁判**离线冻死**，只更新解题器。坐标系见 [1.2 Model–Harness–Artifact](../../../01-研究框架与术语/1.2-Model-Harness-Artifact/1.2-Model-Harness-Artifact.md)。**不是** LADDER 专文（递归拆题见 [2.2.2 LADDER](../../2.2-自适应与递归解题/2.2.2-LADDER-递归拆题/2.2.2-LADDER-递归拆题.md)，本篇只用它生成的 9000 道积分变体），**不是** SEAL（那边 self-edit 进 LoRA，奖励来自带标签 $\tau$），**也还不是** RSI：改进器 $I$ 是冻结裁判 + 冻结出题器 + 冻结 GRPO 配方。一手：Simonds, Lopez, Yoshiyama, Garmier，Tufa Labs，[arXiv:2505.08827](https://arxiv.org/abs/2505.08827)。主模型 **Qwen 2.5 7B**；RL 用 **GRPO**，batch size **64**。

## 1. 问题：程序化奖励写不出来时，谁来打分

RL 能抬 LLM，但环境贵。作者点了两类卡点：训练环境要人写接口和奖励；很多领域没有够用的标注。他们举的例子不是数学——给 M4 螺栓写完整的设计规则检查，或给电脑 GUI Agent 搭可编程奖励，成本会高过任务本身。如果验证比生成容易，也许可以让模型当裁判，省掉程序化奖励。

这个不对称叫做 **generator-verifier gap**（生成–验证缺口）。Countdown 是刻意挑的：给 2, 3, 5, 7 凑出 19，搜索空间大，核对「只用了这些数、算术对不对」却很快。积分题也类似：写出原函数难，用 SymPy 或人工核对相对容易。缺口存在，不保证 LLM 裁判是缺口的可靠代理。语言含糊、采样随机，代理奖励非确定性，解题器有机会去黑裁判而不是去学算术。

和 [Self-Rewarding 家族](../2.1.2-Self-Rewarding-家族/2.1.2-Self-Rewarding-家族.md) 的差别要先钉死。那边是偏好：同一模型给开放回答打 1–5 分，抽最好 / 最差做 DPO，裁判头和生成头共享权重、一起迭代。这边是**可验证对错的数学**，裁判输出二元标签，而且**训练全程不更新裁判**。related work 还点了 CodeRL：用单元测试当奖励训代码模型。那是程序化验证。本篇要的是**测完程序化奖励之后**，LLM 代理能不能顶上。Countdown 证明：顶得上，但提示是一等公民。积分证明：顶得上，但冻裁判会封顶。两条都没有把测试套件或裁判写进 $S'$。CodeRL 的单元测试在墙外；Tufa 的 LLM 裁判也在墙外。换皮不换墙。

再拆三处，避免标题党。第一，信号形状：1–5 分连续偏好 vs 0/1 对错。第二，更新边界：Self-Rewarding 的 $M_{t+1}$ 既更好答也更好打分（作者希望如此，观测上是分通胀和变长）；Tufa 的 $M_{t+1}$ 只更好解题，打分头是基座的复印件。第三，墙外的锚：Self-Rewarding 用人类 EFT 种子钉住「什么叫 5 分」；Tufa 用形式验证器在**论文分析**里审计代理，训练步里裁判看不见这个审计。所以 Countdown 的 TNR 曲线是作者画给读者看的，不是解题器的损失函数。

## 2. 冻结裁判：只看答案标签里的东西

方法节很短，但墙画在这里。

裁判是 LLM 奖励模型，**没有 ground truth**。输入是题目 + 解题器的作答，输出正确或错误。实现成离线系统：裁判权重在整段训练里不动，换来稳定的奖励分布。为了少被黑，裁判**只看见指定答案标签里的解**，看不见解题器在标签外写的解释、求饶、格式花样。这是在用接口收缩攻击面，不是在升级裁判。

每个域单独调提示。RL 是 GRPO，所有实验 batch size 64。GRPO 相对 PPO 少一个价值网络，用同一组采样里的相对优势当基线——DeepSeek 数学 RL 那套读者应见过。本篇不重推公式。记三件：更新的是解题器 $\theta$；奖励是冻结裁判的 0/1；组大小和 batch 绑在 64 上。没有价值网络，并不表示没有奖励 hacking 通道——Countdown 三个提示塌了，塌的是裁判接口，不是 GRPO 缺 critic。

合成题来自作者更早的 **LADDER**（递归把难题拆成可练的子题）。MIT Integration Bee 资格考只有 20 道、难度稀疏，原卷不够训。LADDER 按可控难度生成积分变体，训练集 **9000** 道，数学气质尽量贴近 MIT 原题。LADDER 的拆题算法、递归深度、子题验收**不在本篇展开**；这里它是冻结的出题工厂。把 LADDER 和自裁判收成「一篇 RSI」会把两堵墙砌成一堵。

讨论里还有一刀，实验没做：把工具只给裁判、不给解题器，缺口可以人为拉大。积分题让裁判跑代码核对，解题器必须纯推理；算法题让裁判跑多组输入，生成器不能测。这是「验证端开挂」，不是 RSI。本篇积分训练走的是 SymPy 格式 + 人工终评，**没有**把代码执行写进冻结裁判的前向。读讨论时不要把愿景里的工具不对称，听成本文 Table 的设置。

评测和训练用的门不一样。Countdown：形式验证器检查算术是否凑到目标。积分：训练时要求 **SymPy** 格式，便于程序核对；最终数字会加人工，因为基座 Qwen 一开始经常写出程序读不懂、人能看懂的正确积分。作者明确写：要分开「真的会积分」和「只会写合法 SymPy」。LLM 裁判对格式更钝，这是优点也是噪声源——形式验证器判格式错的，裁判可能判对。

## 3. Countdown：四个提示里只有一个没被黑

Countdown：给定若干整数和目标，用四则运算凑出来。作者选它有两条理由。前人用 RL 训这道题能逼出搜索式思维链（他们引 TinyZero / Pan et al. 2025）。验证直观地比生成容易，适合测「自裁判能不能当形式验证器的代理」。

理想情况：自裁判够硬，训练曲线应和形式奖励叠在一起。语言没有对采样 token 的硬约束，代理奖励会抖，解题器可以去找让裁判说「对」的话术，而不是去找合法表达式。作者迭代了 **四个提示**（论文 Figure 1），从简略到把目标数字、可用数字列表、禁止事项写死。

训练动态（Figure 2）用形式验证器另算一条 True Negative Rate 和真奖励。早期四个提示都能把 TNR 顶上去。往后，策略梯度在三个不够显式的提示上找到了黑法，TNR 塌下来，自奖励均值和形式奖励分家，评测跟着垮。只有最后一个最显式的提示撑住了。附录 A 写了前三个提示上的具体 hack 和评测集上的形式奖励均值。

> 图 2：上支三条含糊提示汇进奖励 hacking；下支 Prompt v4 与形式验证器同量级增益。

**图 2 解析**

- **v1–v3**：TNR 先升后塌。自奖励还在涨时，形式奖励已经掉——这就是代理奖励和真任务分家。
- **v4**：最显式。和形式验证器对照（Figure 3）时，两条设置相对基线都大约 **+20%**，均值奖励曲线形状接近，回复长度也以相近速率变长。作者把变长归因于思维链里出现了搜索。
- **形式验证器**：不是训练时的奖励（自裁判实验里训练信号仍是 LLM），是用来审计代理有没有在撒谎。

结论只能说到这一步：在这个生成–验证缺口清楚的域里，**同一只 7B 可以既当生成器又当验证器**，前提是提示把攻击面收够死。换一句软提示，闭环会变成教模型骗裁判。这和混元阶梯 L1 的特征失败（伪标签进权重）是同一类事故，只不过标签来自冻结的自己，不是来自另一只在线法官。

TinyZero 那条线证明的是「形式奖励 + RL 能在 Countdown 上逼出搜索」；本篇多问的是「LLM 代理奖励能不能叠在那条线上」。叠上的条件是提示工程，不是模型突然学会了诚实。四个提示里三个失败，失败可复现、有附录例子，这比「我们设计了自奖励」的摘要更有信息量。

## 4. 积分：噪声裁判也能涨，冻裁判会封顶

先在「有标准解的简单积分」上看裁判噪声。Qwen 2.5 7B 自己判自己。假阴、假大约 **10%** 且相对稳，训练集和测试集上的解题仍在涨（Figure 4）。验证集一开始很低，主因是 Qwen 的输出格式；扣掉格式问题后真实准确率 **54%**。LLM 裁判对格式不敏感，假阳性会掺进「形式验证器读不懂、人能看懂」的解。

有意思的分叉：裁判给出的真阳性奖励一开始偏高，后来涨得比验证分慢。训练/测试抽自同一难度池，这条分叉不是难度漂移。FPR 慢慢升，主因是真阴性变少；FNR 看起来平稳，底下是假阴和真阳按比例一起长。作者仍强调：噪声裁判**没有**挡住积分能力变好。不完美反馈可以驱动真技能，只是你不能把裁判分数直接当成技能分数。

完整自改进环（§4.3）：同一只 Qwen 2.5 7B **出题（经 LADDER）、解题、裁判**。没有外部验证，没有工具调用。训练信号是冻结的基座 Qwen 当裁判。MIT Integration Bee 评测集上，从被格式拖垮的低分走到 **43%**，相对基座 **+8%**，超过 GPT-4o 的 **42%**。后来平台。作者把封顶部分归到**裁判没更新**：一直用基座 Qwen 2.5 7B 当法官。他们写，下一步应让裁判和生成器一起在线变，才可能顶开这层瓶颈。这句话是对 RSI 读者的诱饵，也是本篇**没有做**的事。

MIT 资格考背景（方法节）：20 道积分，资格线常写 73%，多数考生 15–30%，50–73% 算强。把 43% 听成「已经会考 MIT」口径不对；听成「7B 自裁判环超过 GPT-4o 在这张小考上的 42%」才对。

弱监督对照（§4.4）标题容易读反。生成器换成 **Qwen 2.5 7B DeepSeek Distilled**，裁判换成 **GPT-4o**。在这张积分榜上 GPT-4o **42%**，Qwen 基座 **50%**——更强的通用模型在这道题上更弱。作者把它当成 weak-to-strong：任务专长较弱的模型，能不能给专长较强的解题器发奖励。结果：GPT-4o 当裁判时，解题器验证集平均 **67%**（Figure 7）。实验停是因为 API 价钱，曲线还在涨。GPT-4o 对提示扰动明显钝于 Qwen，更抗 hacking。

Burns 等人的 weak-to-strong 原文是：弱监督去引出强模型已经有、但不会用的能力。本设置更拧：GPT-4o 在积分这张小考上分数更低，却能当更稳的奖励源，把蒸馏 7B 从专长优势再往上推。作者的解释偏安全文献：更大的模型更抗 jailbreak 式利用。这解释了「为什么 GPT-4o 当裁判省提示工程」，没有证明「弱模型在任意任务上都能训强模型」。规模、抗利用、任务分数，三件事在 42% vs 50% 这组数上是拆开的。

不要把 67% 和 43% 叠成一条「自改进曲线」。43% 是 7B 判 7B、完全无外部模型；67% 是蒸馏 7B 解题、GPT-4o 在墙外当法官。后者已经把更强（至少更抗黑）的外部 $I$ 请回来了，离「自己当改进器」更远，离「有一台好裁判就能 RL」更近。

Figure 7 右侧还有 o1 的柱。正文只写 approaching O1 levels，**没有**给出 o1 的百分数。本篇不编那根柱的高度。

## 5. 不是 RSI：改的是解题器，不是裁判

按 [1.1 术语](../../../01-研究框架与术语/1.1-RSI-术语辨析/1.1-RSI-术语辨析.md)：$S$ 是解题器权重，$I$ 是（LADDER 出题 ∪ 冻结裁判 ∪ GRPO 配方）。单轮 $S'=I(S)$ 成立——GRPO 之后解题器变了。RSI 还要 $I'\subseteq S'$。本实验的 $I$ 全程在墙外。作者自己把平台期归因于冻裁判，等于承认改进器没进 $S'$。

和同层邻居的分工：

| | 信号 | 裁判动不动 | 算不算 RSI |
|--|------|------------|------------|
| Self-Rewarding LM | 1–5 分偏好 | 同一 $\theta$ 一起迭代 | 否；量表和 Judge prompt 仍在墙外 |
| STaR | 数据集标签 | 标签冻 | 否 |
| SPIN | 人类 $y$ vs 上一轮自己 | 无法官头 | 否 |
| SEAL | 适应后在 $\tau$ 上对不对 | $\tau$ 冻 | 否 |
| Tufa 自裁判 | 冻结 LLM 的 0/1 | 裁判冻 | 否；最像带噪声的 RLVR |
| Tufa + GPT-4o 裁判 | 外部 0/1 | GPT-4o 在墙外 | 更不是 |

混元阶梯上这是 **L1**：改可训练状态，特征失败是伪标签和奖励 hacking。Countdown 的三个塌提示是活标本。积分实验里假阳性慢慢升，是同一失败的慢性版。墙外证据是形式验证器和人工核对的 MIT 评测，不是自裁判分数——作者用形式验证器画 TNR，就是怕有人把自奖励当成功。

讨论节的雄心很大：LLM 裁判让模型直接在人类用的浏览器、操作系统里练，不必先写可编程奖励；和 LADDER 一类出题配在一起，数据稀缺域可以自己出练习。那是愿景。本篇实证停在两个窄域、7B、冻裁判、四个提示里三个被黑。作者也写了回声室：模型可能专出自己会的简单题，或者强化错误模式。出题器如果和裁判同参数，会不会一起把难度压到双方都舒服的区间，实验没有测——LADDER 出题在本设置里是冻的，所以回声室首先表现为**解题器去黑冻裁判**，而不是出题器变简单。生成器变强之后，黑裁判的速度会不会快过裁判变硬，正文当成开放问题，没有标度律。

和 RSIBench-Data 对照一句有用。那边冻的是后训练栈，搜的是 `train_messages.jsonl`，发现有、过程不可靠。这边冻的是裁判，搜的是解题器 $\theta$，Countdown 上过程可以可靠（v4），但换提示就不行。两篇都在说：**冻住 $I$ 之后，剩下的搜索仍可能不单调、仍可能被黑**。都不能当 RSI 样板。

LADDER 不要在本夹展开。那篇（Simonds & Yoshiyama, arXiv:2503.00735）的对象是递归拆题，验证器是数值的，不是 LLM 法官。本篇 related work 写得很清楚：沿用 LADDER 的合成题能力，**换成** LLM-as-a-Judge。两篇论文、两堵墙。花园若以后单开 LADDER 专文，落点仍是 Model 层，不要和本篇合并。

**读**：冻裁判；答案标签契约；Countdown 约 +20% 且必须用最显式提示；积分自环 43% / +8% / GPT-4o 42%；GPT-4o 裁判把蒸馏 7B 送到 67%；9000 道 LADDER 变体；GRPO batch 64。
**不读**：把 8% 听成 RSI、把 LADDER 和自裁判收成一篇算法、把 67% 听成无外部模型的自改进、把讨论里的 M4 螺栓听成实验、把 o1 柱高当成论文给出的数。
