# ReadAgent：页会压，提示冻着

摘要写有效上下文最多拉到 **20×**，NarrativeQA Gutenberg 测试集上相对最好检索基线，LLM 评分涨 **12.97%**、ROUGE-L 涨 **31.98%**。打开 Table 1：QuALITY 开发集 230 篇、2086 题，PaLM 2-L 窗口 8k。全文塞进去 **85.83%**。只拿 gist、不回看原文 **77.52%**。并行回看 1–2 页 **86.16%**，压缩率 **72.17%**，作者写成大约 **3.5×**。人把 20× 听成窗口变成 16 万 token 一次吃完，缺的是：压缩率 \(CR\) 定义在**最后一次答题查询**里，gist 加回看页相对全文短了多少；分页阶段仍要把原文走一遍。12.97% 对得上 Gutenberg 测试 LR-1：ReadAgent-S 1–3 页 **60.55%** 对 BM25 Top-4 **53.60%**，是相对涨幅，不是 12.97 个百分点。分页提示、gist 提示、回看提示都冻着。权重不动。

本篇夹在 [MemoryBank](../7.2.5-MemoryBank-遗忘曲线记忆/7.2.5-MemoryBank-遗忘曲线记忆.md)、[MemGPT](../7.2.1-MemGPT-操作系统式记忆/7.2.1-MemGPT-操作系统式记忆.md) 和 [A-Mem](../7.2.2-A-Mem-卡片盒记忆/7.2.2-A-Mem-卡片盒记忆.md) 旁边。综述把短时压缩写成 ReadAgent、MemoryBank 按遗忘曲线更新。MemoryBank 改的是对话条强度；这边压的是长文档页。MemGPT 用函数换会话页；这边用提示决定文档在哪停、哪页再看。A-Mem 的 LoCoMo 上 ReadAgent 多跳只有 9.15，那是 A-Mem 专文的对照行，不是本表。禁止用 9.15 改 86.16。**不是** RSI。**不是** 改 \(\theta\)。**不是** 术语式 (2)。一手：Lee, Chen, Furuta, Canny, Fischer，Google DeepMind，[arXiv:2402.09727](https://arxiv.org/abs/2402.09727)，ICML 2024，PMLR 235:26396–26415。项目页 [read-agent.github.io](https://read-agent.github.io/)。数字以 HTML Table 1–6、Table 7–8、§3–§4、附录 B/H 为准。禁止用手抄 Figure 2–5 柱高去改表。禁止和 MemoryBank 的 0.716、ChatDB 的 82%、MemGPT 的 93.4、HippoRAG 的 89.1 横加。

## 1. 问题：窗口有上限，塞满也不见得会用

作者写 LLM 既有长度上限，把长文一次塞进去也不稳健。人读长文不是逐字存：细节忘得快， gist（大意、不管原词）留得久，这是模糊痕迹理论；需要细节时再翻原文。ReadAgent 把这三步收成提示系统：决定哪些内容收成一集（一页），把页压成短 gist，答题时按 gist 决定回看哪几页原文。骨干是指令微调的 PaLM 2-L，窗口 8k。方法在训练集上调超参，报到验证 / 测试 / 开发集，避免过拟合配方。开发配方用训练集，不等于在训练集上微调 \(\theta\)。正文写 zero-shot：不在训练集上训练或微调。LoRA 不在本方法里。和 MemoryBank 开源行的 38k 心理对话不是一件事。压缩率写在公式里。\(CR \equiv 100\times\bigl(1-\frac{\text{终查询词数}}{\text{全文词数}}\bigr)\)，终查询词数取所有推理步里最长的那次（gist 加回看页）。72.17% 对应大约 \(1/(1-0.7217)\approx3.6\)，作者写成 3.5×。94.84% 对应大约 19.4，作者写成 \(\sim20\times\)。\(CR\) 不是「分页阶段少读了多少」，分页仍扫原文。

\(S\) 取这次阅读里的 gist 库：每页一条 gist，带页码标签，按原文顺序拼。单轮 \(S'=I(S)\) 可以发生：多一篇文档的 gist，或本题回看页替换进记忆。术语式 (2) 还要 \(I'\subseteq S'\)。下一篇文档仍用同一套分页提示、同一句「shorten」而不是「summarize」、同一套回看提示、同一对 `min_words` / `max_words`。混元台阶上这不是纯 L0：同一篇文档的 gist 可以摊到许多题上。也到不了改改进器。更像 MemoryBank / MemGPT：留下脚手架状态，出状态的程序冻着。作者把 interactive 写成模型自己选停点和回看页。花园读成提示冻着、本题字符串在变。模糊痕迹理论是引言借喻：人记得大意、再翻细节。公式 \(CR\) 和三段提示才是本系统。不要把 Reyna 的心理学论文听成已经证明了 RSI。相关工作把 MemoryBank、Generative Agents 写成检索增强；本实验检索基线是 BM25 和 Gemini 嵌入，没有把 MemoryBank 的 0.716 拉进来当对照。WebGPT / WebShop 学浏览动作找网页答案，作者写成不是为了读懂一篇长文档。PEARL 给长文档写动作计划；Self-Notes 把中间笔记插回原文。这些都处理不了超过窗口的输入。ReadAgent 要处理的是输入已经长过 8k。

和邻居先划线。MemGPT 换的是对话工作上下文；这边原文始终在磁盘式的页库里，回看是把选定页替换进 gist 串。MemoryBank 有遗忘公式 \(R=e^{-t/S}\)；这边没有强度，有压缩率。HippoRAG 建开放知识图；这边不抽三元组。ChatDB 写 SQL；这边不写库表。ReAct 的轨迹随题清空；这边 gist 按文档留。MemWalker 走摘要树，附录 H 作者尽力重实现 PaLM 2-L 上 QuALITY **66.73%**，搜失败 11.7%；全文 85.83%，ReadAgent-P 1–5 页约 86.6%。失败率对比不要听成另一张主表。相关工作还点了 MemoryBank、Generative Agents。本主表没有 LoCoMo。

## 2. 机制：先切页，再压 gist，再按题回看

切页。从上一停点读到 `max_words`，在段与段之间插入编号标签，让模型挑自然停点；`min_words` 之前不插标签，保证每页够长。QuALITY / QMSum 默认 280 / 600；Gutenberg 500 / 3000；电影剧本 600 / 1000。人改这两个数，等于人改 \(I\)。Table 5：LLM 切页 86.83%，均匀切 85.71%，同一套回看。差别不到 1.2 个百分点，作者仍写成自然停点有用。分页算法给的额外遍数上界是 \(\texttt{max\_words}/\texttt{min\_words}\)：QuALITY 600/280≈2.14，Gutenberg 3000/500=6。上界不是实测账单。实测账单用 §3.3 那组词数。Gutenberg 页显著更大，才压得出 96.80% 的 gist 压缩率，也才让 gist 进得了 8k。页太小，gist 会太长，终查询装不下；页太大，细节先被 shorten 掉，回看也救不回。Table 6 已经把这根弦画在 QuALITY 上。

压 gist。提示用 **shorten** 不用 summarize。作者写 summarize 容易改结构，shorten 更保住叙事，才方便把 gist 按页序拼。每条前面加 `<Page n>`。拼起来必须能进窗口。页越大，重复信息越能压掉，细节也越容易没。Table 6：`max_words` 从 400 到 1200，只 gist 的准确率 78.91%→73.97%；带 1–5 页回看时 86.82%→85.67%。默认 600。 gist 压缩率 85.53% 指 gist 本身相对全文，不是终查询的 72.17%。

回看。模型看见全部 gist 和题目，说出要翻哪些页。并行 ReadAgent-P：一次点 1 到 \(k\) 页，提示里写明「I want to look up Page [7, 12]」，不要多选。串行 ReadAgent-S：一次只能写一个页码，或者说 STOP；已经翻过的页列在提示里，不许再点。选中的原文页**替换**对应 gist，保住顺序，再答题。QuALITY / GPT-3.5 的回看提示末尾加过「Take a deep breath and tell me: Which page(s) would you like to read again?」，作者写成和 OPRO 那篇「深呼吸」类似。这是人改提示，不是系统自己加的。检索基线复用 ReadAgent 切好的页，按 BM25 或 Gemini `embedding-001` 点积取 Top-\(k\)。NarrativeQA 页太长，嵌入模型 1 万字符上限，神经检索改嵌 gist，再返回原文页。这是基线的限制，不是 ReadAgent 自己换了编码器。

评分。QuALITY 是四选一准确率，随机 25%。NarrativeQA 和 QMSum 是自由答，除 ROUGE F 外另用 LLM 评分：严提示判是否精确匹配，宽提示判精确或部分匹配。任一严的判精确，就算精确（LR-1）；严的否定、宽的说部分，算部分（计入 LR-2）。多条金标取最高。作者承认换一只评分模型就不好和别人比，ROUGE 又会被回复变长压 F 值，所以 Table 2 / 3 两套都要看，不要只报摘要里的相对百分比。

## 3. 数字：86.16 超过全文 85.83，20× 是终查询压缩

QuALITY 开发集均长 4,122 词、最长 5,967，进得了 8k。gist 均长 650、最长 1,264。Table 1，三次运行均值。BM25 Top-4 **84.42%**，神经 Top-4 **84.88%**，全文 **85.83%**，只 gist **77.52%**。ReadAgent-P 1 页 84.13%，1–2 页 **86.16%**（\(CR\) 72.17%，约 3.5×），1–6 页 86.91%。ReadAgent-S 1–6 页 **87.17%**（\(CR\) 58.53%）。从 1–2 页起超过全文。作者写成不意外：长窗口用不满（Lost in the Middle），干扰也会拖。只 gist 比全文低 8.3 个百分点：压缩能当索引，不能当唯一证据。回看是机制，不是装饰。

NarrativeQA Gutenberg 测试：177 篇、5207 题，均长 70,619 词，最长 343,910。gist 均长 2,217，最长 6,471，gist 压缩率 96.80%。电影剧本测试均长 29,963，最长 63,957，gist 压缩率 91.98%。太长，不做截断全文对照。Table 2 Gutenberg 测试：BM25 Top-4 LR-1 **53.60%**、LR-2 66.16%、R-L **0.197**；神经 Top-4 LR-1 50.62%、R-L 0.191；只 gist LR-1 55.79%、R-L 0.217。ReadAgent-P 1 页 LR-1 **59.98%**、LR-2 73.23%、R-L **0.226**，\(CR\) **94.84%**，\(1/(1-0.9484)\approx19.4\)，摘要写成 \(\sim20\times\)。ReadAgent-S 1–3 页 LR-1 **60.55%**。相对 BM25 Top-4 的 LR-1：\((60.55-53.60)/53.60\approx12.97\%\)。这就是摘要那句相对涨幅。R-L 绝对值 0.226 对 0.197。摘要另写 ROUGE-L 相对 31.98%，Table 2 旁没有标哪一格，花园不把 31.98 听成百分点，也不用手抄柱去改 0.226。电影剧本测试 ReadAgent-S 1–3 页 LR-1 **64.53%** 对 BM25 Top-4 **50.18%**；ROUGE-L 上串行 0.202 并不高于并行 1 页的 0.260。自由答的 ROUGE 会被回复变长压低 F 值。作者把 LLM 评分写成更知情，也承认换裁判模型就不好比。

QMSum 验证：35 篇、272 题，均长约 1 万，最长 2.63 万。截断前/后 6k 词当弱对照，前 6k 的 LR-1 只有 **14.71%**。只 gist LR-1 40.20%、LR-2 89.83%。ReadAgent-S 1–6 页 LR-1 **46.57%**、LR-2 **91.54%**、ROUGE-L 21.15。并行加页在这张表上不一定涨。作者猜会议记录更无结构，要在 gist 里主动搜。许多题其实是「总结整场会」，模型常回复不用翻页、凭记忆总结，平均回看页远低于上限；真正的事实题才会把页数用满。不要把 46.57 听成会议摘要已经接近满分。截断对照把这件事钉死：前 6k 的 LR-1 14.71%，后 6k 10.42%。会议记录不是「截一段就够」。SCROLLS 提供的是拼接后的纯文本，原文来自 QMSum。NarrativeQA 的书和剧本也换成 SCROLLS 去 HTML 的版本，不要拿带标签的古腾堡页去复现 Table 2。

附录 E 把 gist 接到网页导航，Mind2Web 那套数字不进 Table 1。附录 D 用 2712 词短篇「Off Course」做机制说明：8 页，ReadAgent 对 6/8，神经检索 3/8，且 ReadAgent 错的两道神经检索也对不上。例子不当另一张准确率榜。回看提示允许最多 4 页，例子里只点了 2 页。灵活选页是作者写的优点，也说明 \(k\) 是上限不是必须用满。

Table 4：QuALITY 上回看 1 页，提示检索 84.13% 对 gist+神经 Top-1 82.65%。Table 7 GPT-3.5-turbo：全文 **73.30%**，ReadAgent-S **72.10%**，并行 1–5 页 **69.65%** 且平均只翻 1.0 页。同一套提示没为 GPT 重调。花园钉死：PaLM 2-L 上 1–2 页超过全文；GPT-3.5 上串行还略低于全文。骨干换了，配方没换，表现可以裂开。

## 4. 这不是术语式 (2)，20× 也不是改进器升级

gist 变了，下一题可能直接在 gist 串里点到第 8 页。改进器没变。分页提示、shorten、回看格式、`min_words` / `max_words`、8k 窗口都还在。混元 L0 装不下跨题复用的文档 gist；L3 要改提议 / 选择程序。本篇停在留下状态、不改程序。摘要里的 interactive 指本题选页，不是 \(I\) 在改自己。结论写明：不给无限上下文，gist 本身极长时也不打包票。

和 MemoryBank 钉死。0.716 是 97 道合成陪伴探测题的人打分；86.16 是 QuALITY 准确率。遗忘曲线不是 gist。和 MemGPT 钉死。93.4 是 MSC 话题级裁判；这边是长文档 QA。换页政策是函数 schema；这边是三段提示。和 A-Mem 钉死。LoCoMo 多跳 9.15 是 A-Mem 表上的 ReadAgent 行，本实验没有 LoCoMo。和 ChatDB 钉死。82% 是 50 道店账；这边没有 SQL。和 HippoRAG 钉死。89.1 是 2Wiki R@5。和 ReAct 钉死。交错想–做–看随题清空；gist 按文档留。和 MemWalker 钉死。附录重实现 66.73%、失败 11.7%，不是 Table 1 主列。

对有大模型基础的读者，读完应能回答四句。改的是哪一层？Harness 里的分页、gist 和回看提示。权重动了没有？没有。20× 是窗口扩到 16 万吗？不是，是终查询里 gist 加回看页相对全文的压缩。还缺什么才叫花园 RSI？分页提示或 shorten 句进入 \(S'\)，并且下一篇文档用的就是升级后的那份。超参在训练集上调过，这是人改 \(I\)。没有墙外检查「这条 gist 该不该进库」。错 gist 一旦写进串，后面的回看会一起走歪。作者点了幻觉风险：细节被压掉以后，模型可能自己补，还不说。主表没有另报幻觉率。QuALITY 随机基线 25%，87.17 远高于此，仍不是满分；2086 题里大约一成多仍错。错的题没有按「分页错 / gist 错 / 回看错」拆开。100 个错例那种结构在 HippoRAG，本篇没有。花园不编。三次运行的标准差写在 Table 1：全文 \(\pm0.19\)，1–2 页 \(\pm0.12\)，串行 \(\pm0.18\)。86.16 对 85.83 的差大于这些误差，但仍是同一只模型、同一份开发集。不要把 0.33 个百分点听成另一套架构已经赢了。差在回看，不在换 \(\theta\)。

## 5. gist 能翻过窗口，翻过去的不是改进器

同一句「给模型记忆」，至少分六截。加长窗口是改模型或位置编码。MemGPT 是会话分页。MemoryBank 是对话检索加遗忘。HippoRAG 是语料图。ChatDB 是 SQL 账本。ReadAgent 是文档 gist 加按题回看。六截不要收成「都在推理时自我进化」。相关工作还点了 WebGPT / WebShop、PEARL、Self-Notes。附录 E 把同一套 gist 思路接到网页导航，不是 Table 1。主表只有三套长文档 QA。

「20×」要和分页账单一起读。有效上下文按终查询 \(CR\) 算；分页和 gist 仍扫原文。同一篇问 2086 道题，才摊出 20.4% 的词数节省。一篇只问一道题，一次生成 gist 的账摊不薄。Gutenberg 均长 7 万词，8k 窗口本来就装不下全文，20× 说的是「终查询里只放压缩后的一小截」，不是「一次前向就能盯 20 个窗口」。gist 记忆长度仍跟库规模相关。作者写传统检索能撑更大库；ReadAgent 的 gist 必须进窗口，库不能任意涨。这是设计边界，不是没写完的 RSI。

只 gist 的 77.52% 说明压缩会丢答题细节。回看把细节补回窗口，准确率才过全文。全文 85.83% 低于 1–2 页回看，说明 8k 里干扰也在。三件事叠在同一张表上：压缩、回看、长窗口用不满。不要收成一句「自我进化让阅读更强」。均匀切页只低 1.2 个点，说明自然停点有用，也说明配方差一点点仍是人设的 \(I\)，不是系统自己改切页提示。

GPT-3.5 行尤其要钉死。窗口比 PaLM 更大，全文已经装得下 QuALITY，ReadAgent-S 72.10 对全文 73.30。提示不重调，并行几乎只翻 1 页。这是 L2 脚手架在换骨干时裂开的证据：gist 手续冻着，能力跟着基座走。不要用 PaLM 的 87.17 去改 GPT 的 72.10。

项目页不是 Table 1。花园只认 2024 年这篇三套数据。后来别人把 gist 接到产品阅读器，不改 86.16。A-Mem 表上的 9.15 / 643 token 说明 gist 分页在长对话 QA 上可以几乎没分，和本表长文档理解不是同一列。两套分母禁止横加。分页时若把上一页拼进提示，作者写只对 QMSum 看起来有用，QuALITY 上不明显，留给以后。这又是人改 \(I\) 的旋钮，主表默认设定以 Table 8 为准。

生成提示不会因为某次 86.16 就把 shorten 改成另一种压缩。人要改词数帽、把回看交给可训练检索器、把分页提示写进 gist 库当可进化规则，都是改 \(I\)。这和 DGM 改自己的 Python、STOP 改改进器源码正好相反。作者把 ReadAgent 写成缓解上下文长度和上下文使用的提示系统，花园读成 2024 年这篇三套长文档 QA 的定位，不读成已经闭合的递归，也不读成窗口已经扩到 20 倍的实现证明。

**读**：Table 1 的 86.16 / 87.17 对全文 85.83、只 gist 77.52，72.17% \(CR\) 约 3.5×，Gutenberg 测试 LR-1 60.55 对 BM25 53.60 是相对约 13%，94.84% \(CR\) 约 20×，20.4% 是摊销词数，GPT-3.5 上 72.10 低于全文 73.30，不是 9.15，不是式 (2)。
**不读**：把 20× 听成一次吃下 16 万 token、把 12.97 / 31.98 听成百分点、用 0.716 或 82% 改 86.16、说分页提示已经在优化自己、说已经 RSI、把 A-Mem 的 9.15 写进本表、把附录网页导航写进 Table 1。
