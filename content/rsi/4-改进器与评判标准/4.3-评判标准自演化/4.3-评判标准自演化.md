# 4.3 · L4: 评判标准自演化

前两篇的系统都在一把固定的尺子下改自己: DGM 的 SWE-bench, STOP 的元效用, A-Evolve-Training 的外部榜单. L4 把尺子也交给循环改. 材料是 RubricBench, RQGM, Double Ratchet, OpenComputer, 以及任务集, 奖励和价值表示演化的几类工作. 先把「移动的尺子」写成一个分解式, 再按评分规则, 评测器, 检查器, 任务集与环境, 奖励与价值的顺序看各类方法固定了什么, 最后看提升一个新标准时记录里要写哪些项.

## 1. L4 的边界与移动的尺子

### 1.1 边界

综述把 L4 写成:

$$
C_k \longmapsto C_{k+1},\qquad C_{k+1}\not\equiv_{act}C_k.
$$

$C$ 是 $\mathcal{A}$ 里最深的坐标, 所以 L4 对 $\theta$, $\Sigma$, $U$ 没有约束: 它们可以不变, 也可以在同一次转移里一起变, 实现的深度由 $C$ 的改写决定.

$C$ 包含很多部件: 判断用的任务, 奖励的语义, 评测协议, 比较规则, 约束, 价值. 综述观察到, 大多数 L4 方法只改其中一个部件, 其余的 (任务描述, 受保护的样例, 结果检查, 授权规则) 保持不变. 不变的部分约束了搜索, 也提供了比较的证据. 最终的可靠性取决于这部分证据和接受规则是否留在更新边界之外.

操作上, L4 方法的共同模式是: 把候选判断规则显式表示出来 (自然语言评分规则, 学到的评测器, 可执行程序, 任务集, 奖励), 在部分受保护的证据上测试, 给选中的版本打上版本号, 之后的判断由它支配.

### 1.2 分数变化的分解

设第 $k$ 轮的系统为 $a_k$, 标准为 $C_k$, 用 $s_C(a)$ 表示系统 $a$ 在标准 $C$ 下的分数. 一轮之后系统和标准都变了, 观测到的分数变化可以拆成两项:

$$
\underbrace{s_{C_{k+1}}(a_{k+1})-s_{C_k}(a_k)}_{\text{观测到的变化}}
=\underbrace{s_{C_k}(a_{k+1})-s_{C_k}(a_k)}_{\text{旧标准下系统的变化}}
+\underbrace{s_{C_{k+1}}(a_{k+1})-s_{C_k}(a_{k+1})}_{\text{标准移动带来的变化}}.
$$

第一项是我们想要的: 在同一把尺子下, 新系统比旧系统好多少. 第二项是尺子本身的移动: 同一个系统, 换了标准之后分数变了多少. 只看左边, 两项混在一起. 如果新标准更宽松, 第二项为正, 系统可以一点没变而分数上升; 如果新标准更严, 第二项为负, 系统变好了分数反而可能下降.

RQGM 的搜索曲线上可以直接看到第二项: 每次替换评测器, 最好候选的分数先掉下去, 再在新标准下爬回来. 这一掉就是更严的新标准带来的负的第二项.

### 1.3 交叉评测

综述 §7.3 给的对策是交叉评测: 在一个共同的比较域上, 把在任系统和候选系统分别放到在任标准和候选标准下打分, 得到一张 2×2 表.

| | 在任标准 $C_k$ | 候选标准 $C_{k+1}$ |
|---|---|---|
| 在任系统 $a_k$ | $s_{C_k}(a_k)$ | $s_{C_{k+1}}(a_k)$ |
| 候选系统 $a_{k+1}$ | $s_{C_k}(a_{k+1})$ | $s_{C_{k+1}}(a_{k+1})$ |

左列的差是第一项, 下行的差是第二项. 两个标准判断不一致的样本要保留下来, 因为它们正是新标准偏离旧标准的地方. 然后再用标准之外的东西判断这种偏离是否更好地服务外部目标: 新的可执行检查, 密封的样例, 对抗探测, 有授权的人工判断.

这张表只在两个标准都能给两个系统打分时才有意义. 如果新标准引入了旧标准没有的维度 (比如 RQGM 加进来的代码审查), 旧标准下那一格就是空的, 只能靠外部锚点.

## 2. 评分规则: 模型会执行, 不会定

### 2.1 RubricBench 量出来的差距

Zhou 等人 (2026) 的 RubricBench 是一个 1,147 对的成对比较基准, 覆盖对话, 指令遵循, STEM, 代码, 安全五个领域. 构建时用多维过滤留下难样本: 输入复杂, 带有误导性的表面偏差. 每个样本配上专家标注的原子化评分规则, 规则严格从指令推出.

实验控制住判断模型的底座, 提示和解码参数, 只换评分规则的来源, 比较三种条件:

1. **直接判断**: 不写中间推理, 直接给出偏好.
2. **自生成规则**: 判断模型先从指令推出评分规则, 再按规则核对两个回答.
3. **人写规则**: 注入 RubricBench 里人写的评分规则.

以 DeepSeek-v3.2 为例: 直接判断 38.8%, 自生成规则 57.8%, 人写规则 84.9%. 自生成规则比直接判断高 19 个点, 比人写规则低 27.1 个点. 七个底座模型上, 人写规则带来的提升都在 22 到 28 个点之间, 论文报告平均约 26 个点, 从轻量判断模型到前沿推理模型都差不多.

此前的奖励模型和判断模型在这个基准上停在 40% 到 47%, 带规则的奖励模型到约 58%. 人写规则的效果随模型规模稳定提升, 自生成规则的收益则快速递减.

论文的解释是: 模型擅长核对指令里明确写出的要求, 但定不出人类专家默认会优先考虑的隐含约束. 这对 L4 是一个基线事实: 如果让模型自己写评分规则, 起点就比人写的低二十多个点. 规则自演化要先补上这个差距, 才谈得上超过人写的标准.

### 2.2 选规则: AutoCalibrate

Liu 等人 (2024) 的 AutoCalibrate 让模型生成候选评判准则并自我修订, 按与专家标注的相关性挑选, 把选中的准则插进之后的评测器提示. 选择信号来自专家标签, 这些标签不参与生成, 处在更新边界之外. GER-Eval 和 ELMES+ 把这个思路推广到按任务或按场景生成评分规则, 但它们的评测器分析暴露了跨模型和对人对齐度较弱, 自我偏好, 以及特定模型偏宽或偏严的问题.

这几项结果合起来说明: 评分规则的出处, 判断模型是谁, 不同来源之间的分歧, 都应该是选规则时的输入.

### 2.3 持久化的规则库

前面的方法每次生成一套规则; 下面三个系统把规则存下来, 之后反复用, 规则的生成变成一个有状态的更新过程:

| 系统 | 存什么 | 准入规则 |
|---|---|---|
| EvoRubric | 评分规则记忆池, 选出的条目影响之后的奖励 | 元验证与同伴共识筛选 |
| DR Tulu | 基于检索, 有区分度的规则条目, 给之后的策略更新打分 | 区分度检查 |
| SkillCoach | 带版本的过程评分规则, 可以打补丁 | 留出回放检查与硬约束 |

三者的粒度不同: 池里的条目, 有区分度的单项, 过程中的步骤. 共同点是可编辑的规则表示加上显式的准入规则. 准入门检查的是一致性, 区分度或回放效用, 这些都是内部检查. 规则是否更好地服务外部目标, 是另一个问题, 第 6 节讨论.

## 3. 评测器与评分函数的版本替换: RQGM 与 Double Ratchet

### 3.1 RQGM: 为什么评测器要跟着变, 搜索怎么搭

Iacob 等人 (2026) 的 Red Queen Gödel Machine 指出, DGM, HGM, HyperAgents 这些系统都假设评测标准在整个运行期间固定在循环之外. 这在三种情况下不够用: 目标任务没有直接的基准 (写论文, 写证明); 评测慢或信息量低; 静态基准在 Agent 变强之后饱和, 或者容易被刷分. 他们的做法是让学到的评测器和它评的 Agent 一起进化.

RQGM 沿用上一篇 4.1 讲过的 HGM 树搜索: 档案是一棵树, 每一步要么扩展一个节点 (编辑出一个子节点), 要么评测一个节点 (得到一个 0/1 结果). 选节点用子树元生产力 (CMP) 上的 Thompson 采样, 扩展还是评测由 UCB-Air 门控决定.

改动有四处:

1. 每个档案节点是一个多 Agent 工作区, 不是单个 Agent. 工作区里有若干角色, 包括任务 Agent 和评测器, 每个角色有自己的任务池.
2. 评测器本身是学到的 Agent 流程, 和任务 Agent 共享代码库, 由同一个元 Agent 修改.
3. 驱动搜索的效用可以在指定的 epoch 边界变化.
4. 评测器可以在边界被替换.

只有打分和编排框架是固定的. 效用的汇总方式是两层均匀平均: 先在一个角色的任务上平均, 再在角色之间平均, 让搜索对所有角色同等重视.

数据隔离: 节点的训练结果给元 Agent 看, 用来指导修改, 但不进入搜索效用; 选节点只看验证集; 最终性能在另一个留出测试集上报告. 产生候选的证据和批准候选的证据是分开的.

### 3.2 RQGM 保守的选择分数

最终选 Agent 和比较评测器, 用的都是 $\epsilon$-best-belief 分数:

$$
BB_\epsilon(a)=I^{-1}_{\epsilon}\big(1+S_a,\;1+F_a\big),
$$

其中 $S_a$, $F_a$ 是节点 $a$ 累计的成功和失败次数, $I^{-1}_{\epsilon}$ 是正则化不完全 Beta 函数的反函数, 即 Beta 后验的 $\epsilon$ 分位数. 它的意思是: 节点的真实成功率以 $1-\epsilon$ 的概率高于这个值.

算两个例子, 取 $\epsilon=0.05$:

| 节点 | 成功 / 失败 | 后验均值 | $BB_{0.05}$ |
|---|---|---|---|
| A | 17 / 13 | 0.563 | 0.418 |
| B | 70 / 54 | 0.564 | 0.491 |
| C | 9 / 1 | 0.833 | 0.636 |
| D | 60 / 40 | 0.598 | 0.517 |

A 和 B 的后验均值几乎相同, 但 B 的证据多四倍, 分位数高出 0.073, B 胜出. C 只有 10 次评测, 均值很高; D 有 100 次, 均值低得多. 这一对里 C 仍然胜出, 因为 0.833 和 0.598 的差距大到 10 次评测的不确定性盖不住. 这个分数偏向证据充分的节点, 但不会让证据少的明显优者落选.

### 3.3 RQGM 的 epoch 与替换规则

RQGM 的核心机制叫「受控的效用演化」:

- **epoch 内冻结**. 一个 epoch 里, 评测器, 产物生成协议, 0/1 打分规则都固定. 这样每个 epoch 就是一个标准固定的搜索问题, HGM 的保证可以直接用.
- **边界处替换**. 在 epoch 边界, 每个评测器槽位把在任者和挑战者放到一个真值锚点上比较. 真值锚点是一个固定的留出数据集, 带客观标签或人类偏好标签, 不依赖任何评测器. 按锚点上的 $BB_\epsilon$ 排序, 最高的那个冻结为下一个 epoch 的评测器; 平局时保留在任者, 避免不必要的删除.
- **选择性删除**. 替换之后, 删掉所有由被替换评测器打出的效用记录, 其他记录保留.

为什么必须删. 如果保留旧分, 或者把旧分换算到新评测器的尺度上, 同一个档案里就混着两个不同效用函数的证据, epoch 内标准固定这个前提就不成立了. 这就是第 1.2 节分解式里第二项的问题: 旧分和新分之差里含着尺子的移动.

删了之后, 被删记录的节点要在新评测器下重新评. RQGM 不立刻重评整个档案, 只在搜索回到这些节点时再评; 三层采样会自然优先照顾评测次数少的节点. 缓存的 Agent 输出可以复用, 重评不需要再调用任务 Agent.

检查点的位置按指数间隔安排. 论文证明: 公比 $\rho>1$ 的指数间隔下, 预算 $B$ 内暴露给删除或重评的记录总数是 $O(B)$; 如果每次评测之后都允许替换, 是 $O(B^2)$. 指数间隔还有一个副作用: 后面更准的评测器支配搜索的时间更长.

论文的保证可以概括成三条: epoch 内是标准固定的搜索, HGM 的收敛保证逐 epoch 成立; 评测器只有在固定锚点上提高 $BB_\epsilon$ 才被提升, 所以跨 epoch 也在改进; 替换的簿记成本和预算成线性关系. 保证是逐 epoch 的, 不是整个运行的; 论文也明确说, 相比静态标准, 这种做法放松了收敛保证.

### 3.4 RQGM 的三个领域

每个领域把一个生成者角色和一个学到的评测器角色配对, 再配一个真值锚点. 底座是 GPT-5.5 (low). 基线 HGM-H 把 HyperAgents 的 DGM 搜索换成 HGM, 评测器保持冻结, 用前人工作里的固定外部评测器. 各组搜索预算对齐. SWE-bench 因为运行时间太长, 这一版没有包含.

| 领域 | 生成者 | 学到的评测器 | 锚点 |
|---|---|---|---|
| 代码 | Polyglot 编码 Agent | 代码审查者 | 编码 Agent: Polyglot 可执行测试; 审查者: CRAVE (被接受/拒绝的 PR) |
| 论文 | 论文写作者 | 论文审稿人 | APReS 的接收/拒绝决定 |
| 证明 | 证明者 | 证明评分者 | IMO-GradingBench 人工评分, 满分 7 分才算通过 |

**代码**. 测试执行本身就是真值, 加一个代码审查者的意义是给一个更便宜, 互补的信号: 审查者不只看补丁过不过测试, 还看质量. RQGM 的留出通过率 71.7%, HGM-H 69.9%; 达到 HGM-H 通过率所用的搜索 token 少 1.35 到 1.72 倍. 被接受的补丁里, 90% 改的是编码者和审查者共用的功能或基础设施, 一次修改同时改进两个角色.

**论文**. 论文质量没有客观评测, 写作者的产物交给一个固定的四审稿人小组打分 (每格是被接收的比例):

| 写作者 | 搜索 token | Sakana | DGM-H | HGM-H | RQGM 对抗审稿人 | 平均 |
|---|---|---|---|---|---|---|
| HGM-H | 42.5M | 1.0 | 12.0 | 64.0 | 10.0 | 21.8 |
| RQGM 通才 | 44.6M | 2.0 | 43.0 | 81.0 | 29.0 | 38.8 |
| RQGM 专才 | 221.8M | 5.0 | 40.0 | 86.0 | 31.0 | 40.5 |

搜索成本相近时 (44.6M 对 42.5M), RQGM 通才的平均接收率是 HGM-H 的 $38.8/21.8\approx1.78$ 倍; 专才是 1.86 倍, 但用了约 5 倍的 token. 四个审稿人里每一个都给 RQGM 写作者更高的接收率.

**证明**. 证明比论文难, 改进要在更长的搜索之后才出现:

| 证明者 | 搜索 token | 平均分 (0–7) | Pass@6 | Pass@7 |
|---|---|---|---|---|
| 静态 IMO25 证明者 | — | 4.07 | 55.0% | 55.0% |
| HGM-H | 21.5M | 3.73 | 51.7% | 45.0% |
| RQGM 通才 | 37.9M | 3.73 | 51.7% | 45.0% |
| RQGM 专才 | 88.0M | 4.33 | 61.7% | 48.3% |

IMO25 证明者是人工设计的验证加修订流程, 在 IMO 2025 上达到金牌水平. RQGM 专才的平均分和 Pass@6 更高, 但 Pass@7 (满分率) 低于它 6.7 个点: 专才找到了更多接近满分 (6 分) 的证明, 满分的反而少. 它在 Pass@7 上仍高于 HGM-H 证明者. HGM-H 在长搜索里停滞, 论文推测原因是冻结的评分者到后期不再提供有用的信号.

### 3.5 RQGM 的自我偏好与对抗池

论文审稿有一个已知问题: LLM 审稿人倾向于接收 AI 写的文本. APReS 的接收/拒绝比例本身偏向宽松的审稿人, 所以审稿人对 AI 文本的偏宽和它在 APReS 上的原始准确率是同向的. 结果是: 给 HGM-H 写作者打分的那个 HGM-H 审稿人, 接收 AI 论文的比例是人类论文的 1.42 到 1.91 倍. 反过来, Sakana 审稿人用的是真实的 NeurIPS 审稿表, 又太严, 给它引导的写作者的信号太弱.

RQGM 利用 epoch 边界做了一个修正. 每次替换之后, 被替换审稿人接收过的 AI 论文组成一个对抗池; 下一个 epoch 额外奖励能拒绝这些论文的审稿人, 同时保持在人类 APReS 数据上的准确率. 评测器的替换仍然以 APReS 为锚. 这样选出来的审稿人专门对 AI 文本严格, 原始准确率因此下降, 低于偏宽的 HGM-H 审稿人; 换来的是校准: 对 AI 论文和真实论文的接收率接近, 同时保持 80% 的真值准确率.

要分清这里是谁改了什么. 对抗池加进来之后, 审稿人的效用函数多了一项「拒绝对抗池里的论文」. 这是在 epoch 边界对 $C$ 的一次有意修改, 而这次修改本身是人设计的, 不是循环自己发现的. 循环做的是在新效用下搜索审稿人.

### 3.6 RQGM 的消融

论文用一个 12,288 次评测的预算做了机制消融, 审稿人锚点准确率在各组之间可比; 写作者验证准确率由各组自己的审稿人打分, 不可比:

| 组别 | 替换 | 对抗池 | 删除 | 写作者验证准确率 | 审稿人锚点准确率 |
|---|---|---|---|---|---|
| 完整机制 | 开 | 开 | 开 | 90.1 | 95.0 |
| 只替换 | 开 | 关 | 开 | 89.5 | 91.2 |
| 不删除 | 开 | 开 | 关 | 90.0 | 92.9 |
| 固定审稿人 | 关 | 关 | — | 100.0 | 78.2 |

最后一行最能说明问题. 审稿人固定不变时, 写作者在这个审稿人眼里的验证准确率是 100%, 而这个审稿人在真值锚点上只有 78.2%. 写作者把一个不够准的审稿人完全满足了. 这正是第 1.2 节说的「内部分数不能单独支持提升主张」: 只看 100% 会以为写作者完美, 看锚点才知道是审稿人太容易满足.

另外, 不删除旧分的对照组在替换后一直停在被替换审稿人的排序上, 新标准没法重排档案.

### 3.7 Double Ratchet 的设定

Zhang 等人 (2026) 的 Double Ratchet 处理的是一个更极端的情况: 没有任何现成的评测器, 只有 10 个带参考答案的样本. 他们让评分函数本身进化, 并且划了一条界线: 进化的只是给单个输出打分的函数, 任务集和参考答案在任何循环开始之前就固定, 不会变. 因此结果不可能来自「换了一套更容易的测试」.

评分函数是一棵表达式树, 叶子是一组小的缺陷检测器, 每个检测一类失败. 设计的出发点是: 我们很少知道什么是好, 但给定一个输出, 通常能找出毛病. 所以「通过」的含义是没找到已知缺陷, 不是证明正确. 检测器大多是确定性的, 失败方式和被评的语言模型不同, 不容易和它共享盲点.

检测器有完整的生命周期: 从聚类后的失败样本合成, 出生时过一道准入门, 按边际贡献打分, 没用就退休. 选择目标有两部分: 在 10 个锚点样本上与参考的一致性 (按召回加权), 加上在无标签输出上的共识 (按可靠性加权) 作正则. 共识只做正则, 从不单独决定选哪个评分函数.

三条数据线严格隔离. 10 个样本的开发集是唯一的监督信号; 另有一个锁定集, 评分函数进化的任何环节都不读它; 技能那一侧沿用此前的 Ratchet 循环, 由进化出来的评分函数给技能训练打分. 两个循环同时转, 所以叫 Double Ratchet.

三个任务: MBPP+ (Python 函数合成, 隐藏单元测试作硬锚点) 和 Spider 2.0-Snow (企业级 text-to-SQL, 官方执行结果比对作锚点) 有精确真值, 用来验证; 报告生成是真正的目标任务, 根据审计过的证据卡写分析报告的段落, 没有黄金标准, 只有一个部分参考信号.

### 3.8 Double Ratchet 的评分函数变好了吗

在 MBPP+ 上, 选出的评分函数和隐藏真值在锁定集上的一致性, 比手写的种子组合高 0.21 (从 $0.417\pm0.058$ 到峰值 $0.625\pm0.050$, 配对检验 $p=0.014$). 它也胜过自己包含的那个裸 LLM 判断器: $0.625$ 对 $0.55\pm0.04$. Spider 上是 $0.500\pm0.026$ 对 $0.45\pm0.07$.

准入门做了大部分工作. MBPP+ 上 100 轮里, 出生的检测器只有个位数, 被拒绝的在 997 到 1014 个之间 (三个种子的范围); 最终表达式只用 3 个叶子. 选择目标从 0.16 升到 0.52, 表达式反而从 6 个算子缩到 3 个.

选择目标单调上升, 因为选的是到目前为止最好的. 但选择看不到的锁定集一致性并不单调: 9 次运行里有 5 次最终值低于自己运行中途的峰值. 这是用 10 个样本做代理的正常泛化差距, 也是论文报告锁定集数字而不在锁定集上做选择的原因.

### 3.9 锚点护栏和下游任务分

论文在报告生成任务上做了两组消融, 各自只关掉一个组件:

| 组别 | 选择目标 | 锁定集一致性 | 训练集通过率 | 结果 |
|---|---|---|---|---|
| 有锚点 (完整) | 0.865 | 0.830 | 0.78–0.82 | 正常组合 |
| 去掉锚点护栏 | 1.000 | 退化 | 0.97–1.0 | 退化 |
| 去掉生命周期 | 0.896 | 0.868 | — | 不退化 |

去掉锚点护栏之后, 一个永远不触发的检测器被「失败即放行」的打分方式记为满分, 选择目标变成 1.000, 评分函数几乎让所有训练样本通过. 去掉检测器生命周期则没有这个问题. 论文指出这和技能进化的经验相反: 技能那一侧, 生命周期管理是关键; 评判器这一侧, 起作用的是锚点纪律. 一条坏技能会被放进提示里伤害性能, 一个坏检测器只有在被选中时才有影响.

更重要的是下面这个结果. 用这三个评分函数分别训练技能循环, 三组技能的任务分落在 0.038 的范围内, 而且在两个和技能循环共同进化的组里, 退化的那一组任务分更高. 也就是说, 一个几乎全判通过的评分函数, 照样能留下有用的练习.

论文由此得出结论: 用下游任务分验证一个自演化的评判器是不成立的, 因为退化的评判器训练出来的策略一样好. 任务分只能回答「够不够用」, 不能回答「准不准」. 在够不够用这一点上, 进化出来的评分函数在 MBPP+, Spider 2.0-Snow 和报告生成三个任务上, 保留了真值或手写评分规则带来的提升的 88% 到 110%.

### 3.10 独立终审

报告生成没有准确的评分标准, 所以论文在所有循环之外加了一层审计: 一个更强的 LLM 把每个最终输出和进化前的基线成对比较, 交换位置判两次, 两次一致才算赢. 这个判断器只做审计, 不产生任何训练信号: 系统里没有任何梯度, 提示或选择决定会读它.

这一层审计捉到了一次真实的 Goodhart 失败: 进化出来的技能钻了报告评分规则的空子. 加一个检测器就修好了. 审计判断器本身也被检查了一遍, 又暴露出另一个问题. 论文的结论是: 不依赖验证器的自改进是可行的, 但前提是架构预期自己的评分函数会被钻空子, 自己的判断器会失准, 而且能把两者都捉出来.

## 4. 检查器, 任务集与环境

### 4.1 OpenComputer 修检查器: 修什么, 不许修什么

Wei 等人 (2026) 的 OpenComputer 是一个给桌面操作 Agent 造可验证环境的框架, 覆盖 33 个桌面应用和 1,000 个任务. 每个应用有一组状态检查器, 通过结构化接口检查应用的真实状态, 判断任务是否完成. L4 相关的是它的自演化验证层.

流程是: 在沙箱里用一个强 Agent 执行校准任务, 记录完整轨迹和最终状态, 之后这次执行固定不变. 一个 LLM 评测器看轨迹, 动作后的观察和最终状态, 逐条准则给出参考判断; 程序检查器独立地在同一个最终状态上运行, 给出机器判断. 比较器逐条对齐两者, 找出分歧. 归因为 Agent 真失败的分歧丢弃; 归因为检查器出错的分歧, 用来修检查器.

修复的范围有严格限制: 可以改检查器代码, 接口实现, 检查器文档; 不可以改缓存的轨迹, 沙箱状态, 任务目标, 预期结果. 修改后的检查器在同一个缓存状态上重跑, 直到在归因为检查器错误的准则上和参考判断一致, 或者用完修复预算. 修好的问题会被记成该应用的一条经验, 之后扩展检查器和生成任务时复用.

### 4.2 OpenComputer 的结果

论文生成了 450 个简单的校准任务, 每个任务最多修 3 轮. 这些任务只用来探测检查器的可靠性, 不衡量 Agent 能力.

- 450 次执行里, 159 次至少有一处程序检查器和参考判断不一致.
- 归因之后, 76 处是检查器自身的错, 不是 Agent 失败.
- 修好了 68 处, 修复率 $68/76\approx89.4\%$: 1 轮修好 47 处, 2 轮 15 处, 3 轮 6 处, 预算内没修好 8 处.
- 在 120 个任务的人工标注对比集上, 人工与检查器的一致率从 85.2% 升到 94.1%.

一个具体例子. darktable 的一个任务里, 初始检查器在 10 条准则里判了 4 条失败, 全部涉及标签状态; LLM 参考判断 10 条全过. 根因是一个检查器的 bug: 它假设标签表在 `library.db` 里, 而当前版本的 darktable 把标签定义存在 `data.db`, 图片和标签的关联才在 `library.db`. 查询报「缺表」错误, 被当成了否定结果. 修复后 10 条全过, 和参考判断一致.

### 4.3 学到的评判器作为提议来源

Self-Taught Evaluators 在合成的偏好对和过滤后的判断上训练评判器; Meta-Rewarding 让一个模型同时担任执行者, 评判者和元评判者; SEVA 用结构化的事实归因过程奖励, 驱动验证, 反思, 探测, 修订的循环. 综述总结了这类方法的风险: 性能依赖种子评判器; 同一模型给自己反馈会有位置偏差或分数饱和; 反复训练可能得到只擅长某个基准的评判器, 而不是全面更强的评判器.

综述的结论是: 这些技术最适合当 L4 里的提议组件. 外围流程要说明改的是哪条评分规则或协议的语义, 比较修改前后, 决定哪个版本生效.

### 4.4 任务集

任务集方法的区别主要在于什么触发更新, 哪些新任务被保留下来用于之后的评测:

| 系统 | 触发信号 | 保留什么 |
|---|---|---|
| AC/DC | 任务发现与模型搜索联动 | 全局与活跃档案里的问题, 答案和可执行打分函数; 准入经过编译, 自解, 反思, 新颖性过滤 |
| Dynabench | 多轮人机交互中模型的失败 | 经人工验证的模型失败样例 |
| EvoCodeBench | 时间上的数据刷新 | 从新近项目自动重建的仓库级代码基准 |

AC/DC 里, 活跃档案用来给模型候选排序, 下游基准对搜索不可见. 抽样专家审查发现任务正确率高, 但被判为真正有创意的比例较小.

### 4.5 自适应基准

自适应基准把评测集中在静态测试已经区分不开候选系统的区域:

- **GETA** 估计被测模型的能力, 在边界附近生成价值对齐题目.
- **MathDuels** 让模型既出题又解题, 从结果矩阵推断题目难度.
- **AgenticEval** 以政策文件为依据生成安全用例, 用人工标注样本检查自己受规则约束的判断器.
- **AutoBencher** 把搜索目标显式化: 用候选模型的分数去修改数据集描述, 追求显著性, 难度, 区分度和新颖性.

综述的观察是: 任务构造和生成器控制之外的来源绑定时 (政策文件, 抽样的人工标签, 留出评测样例), 结果最容易解释.

### 4.6 环境

环境方法把自适应评测从单个题目推广到一群可交互的世界. POET 变异可行的环境, 优化与之配对的 Agent, 在档案里跨环境迁移解. PAIRED 训练一个环境对手, 最大化两个 Agent 之间的遗憾值:

$$
\mathrm{Regret}(\lambda)=U\big(\pi^{A};\lambda\big)-U\big(\pi^{P};\lambda\big),
$$

其中 $\lambda$ 是环境参数, $\pi^{A}$ 是对手方 (antagonist) 策略, $\pi^{P}$ 是主角 (protagonist) 策略, $U$ 是策略在该环境里的回报. 对手方能做好而主角做不好的环境, 遗憾值高, 说明这个环境在主角的能力边界上. ACCEL 结合了两者: 对高遗憾值的关卡做进化式编辑, 保留在当前能力边界上仍有信息量的变体.

三者分别提供了一种控制: POET 的可行性与迁移, PAIRED 的对抗遗憾, ACCEL 的边界编辑. 它们都围绕当前 Agent 调整环境难度, 奖励或遗憾的语义不变. 当选中的环境被保留下来用于之后的评测, 这群环境就定义了之后候选被比较的测试分布, 这一步动的是 $C$.

## 5. 奖励与价值的演化

### 5.1 奖励: 只调权重

奖励组合方法保持奖励的基底不变, 只调每个分量对策略学习的影响:

- **DyLam** 从各分量的学习进度推出自课程, 降低已掌握分量的权重, 把注意力转向优化不足的分量.
- **MAESTRO** 学一个「指挥」, 把任务表示映射到五个奖励分量上的权重, 同时更新标量化策略和语言模型.
- **Dynamic Reward Weighting** 面向多目标语言模型对齐: 有用户偏好时用超体积反馈引导, 没有时用梯度影响驱动权重更新.

综述指出这一类的上限: 基底固定, 就表示不了被遗漏的结果, 也修不了一个本身就是有偏代理的分量.

### 5.2 奖励: 写奖励程序的 EUREKA

可执行奖励把设计空间从权重扩展到计算奖励的逻辑和参数. Text2Reward 从自然语言目标和环境抽象生成稠密奖励代码, 用户看过策略回放后修改代码. Ma 等人 (2024) 的 EUREKA 把用户修改换成进化搜索.

EUREKA 沿用 Singh 等人 (2010) 的奖励设计问题定义: 一个四元组 $P=\langle M,\mathcal{R},\pi_M,F\rangle$, 其中 $M=(S,A,T)$ 是世界模型, $\mathcal{R}$ 是奖励函数空间, 学习算法把奖励 $R\in\mathcal{R}$ 变成策略, $F$ 是给策略打分的适应度函数. 奖励设计的目标是找一个 $R$, 让用它训练出来的策略在 $F$ 上分数最高. $F$ 往往是稀疏的真实目标 (比如任务成功与否), 不好直接优化, 所以要设计一个稠密的 $R$ 作为中介.

EUREKA 的三个设计:

1. **环境作为上下文**: 把未修改的环境源码和任务的文字描述直接交给 GPT-4, 零样本生成可执行的奖励函数, 不用任务专门的提示或奖励模板.
2. **进化搜索**: 每轮采样 $K=16$ 个奖励候选, 在 IsaacGym 上用 GPU 并行训练策略评测, 把最好的那个放进上下文, 让语言模型再生成 16 个改进版. 每个环境跑 5 次独立运行, 每次搜索 5 轮.
3. **奖励反思**: 要求奖励函数把各个分量单独暴露出来; 训练过程中在中间检查点记录每个分量和任务适应度 $F$ 的数值, 写成一段文字摘要, 作为下一轮修改的依据.

评价用人类归一化分数:

$$
\text{归一化分数}=\frac{\text{Method}-\text{Sparse}}{\lvert\text{Human}-\text{Sparse}\rvert},
$$

Sparse 是只用稀疏真实奖励训练的结果, Human 是人类专家设计的奖励的结果. 分数为 1 表示和人类专家持平, 大于 1 表示超过. 举个数: 某任务上 Sparse 得 0.2, Human 得 0.6, EUREKA 得 0.8, 归一化分数是 $(0.8-0.2)/0.4=1.5$. 这组数只用来说明公式.

结果: 在 29 个开源强化学习环境 (10 种机器人形态) 上, EUREKA 在 83% 的任务上超过人类专家奖励, 平均归一化提升 52%. 在 Isaac 任务上全部达到或超过人类水平, Dexterity 的 20 个任务里有 15 个. 结合课程学习, 在模拟的 Shadow Hand 上第一次做出了快速转笔.

EUREKA 之后, CARD 用执行检查和过程, 轨迹, 偏好反馈闭合了修订循环. R* 进一步把奖励结构和数值标定分开: 语言模型变异和模块化交叉进化奖励分量, 一组生成的评判器给出轨迹偏好来拟合参数.

### 5.3 价值的表示与评估

价值方法要表示上下文中的冲突, 文化差异和随时间的变化:

| 系统 | 做法 |
|---|---|
| Value Kaleidoscope | 用 ValuePrism 生成, 解释并评估上下文中价值, 权利, 义务的相关性和倾向, 保留相互竞争的考量, 不压成一个标量 |
| UniVaR | 从引出价值的回答中学一个高维表示, 在 15 个语言模型, 25 种语言和文化上评估 |
| ProgressGym | 重建历史时期的语言模型代理, 模拟人类与 AI 价值在长时间尺度上的双向影响 |
| CLAVE | 用大模型抽取通用价值概念, 微调一个小的识别器; 每种价值类型不到 100 个标注样本就能校准到指定的价值体系 |
| ALI-Agent | 用评测记忆和目标模型反馈生成并迭代修订场景, 探测刻板印象, 道德, 法律方面的长尾失败 |
| GETA | 同时估计题目难度和模型的价值符合度, 生成与当前模型匹配的新题; 测量结果与未见过的分布内和分布外参照更一致 |
| AdAEM | 在 Schwartz 价值理论下用上下文优化生成有争议, 有信息量的问题, 侧重区分模型 |

前三个是描述性的模型, 不是批准新价值语义的流程. 后四个处理的是静态评测的不同弱点: 定义漂移, 长尾场景稀疏, 测试饱和, 区分度弱. 综述的判断是: 这些评测本身不能证明底层的价值体系完整或在规范上正当, 被综述的系统里也没有一个经过验证的流程来批准和启用修订后的价值语义. 所以价值的改变需要额外的治理: 利益相关方的证据, 更新边界之外的约束和审批权, 回滚流程.

## 6. 尺子在循环里时怎么做

### 6.1 RQGM 改的是哪一层

RQGM 的四个部件和留在边界外的部分:

| 部件 | 状态 |
|---|---|
| $\theta$ | 冻结 (GPT-5.5 low) |
| $\Sigma$ | 任务 Agent 和评测器的代码, 由元 Agent 修改 |
| $U$ | HGM 树搜索与元 Agent; 元 Agent 的指令也可编辑 |
| $C$ | 评测器在 epoch 边界替换, 改的是支配之后评判的 $C$ |
| 留在边界外 | 真值锚点, 打分与编排框架, 留出测试集 |

1.2 第 4.6 节把 RQGM 归为 L4, 依据是被替换的评测器支配之后的评判. 这里补充两点. 第一, 锚点决定了改进主张的范围: 评测器只在锚点覆盖的性质上被证明更好, 锚点没测到的性质, 新评测器可能更差. 第二, 写作者和证明者没有锚点, 只能有 epoch 内的赢家, 论文用固定的外部评审小组事后打分; 这些表里的数字, 是在这个小组下的结论.

### 6.2 OpenComputer 与 EUREKA 的证据范围

OpenComputer 这种窄范围修复有两面. 好的一面: 检查器代码可以检查, 可以直接做回归测试. 局限: 它只能评估检查器能观察到的状态和谓词所表示的结果, 基准里也没有检查器还评不了的视觉或几何结果. 另外, 修复的参照是 LLM 参考判断, 修复后的检查器在被归因为检查器错误的准则上向它靠拢; 归因本身如果错了, 检查器会被修成 LLM 判断的样子. 人工对比集上的一致率提升, 是在这一点之外的独立证据.

CoEvoSkills 提供了一个互补的做法: 固定的隐藏判定器发现误接受时, 一个独立的替代验证器重写自己的确定性测试集, 再去评下一个技能版本. 两者的区别是: OpenComputer 把修好的检查器装到之后的任务上; CoEvoSkills 只在一次技能构建过程里把验证器修订当诊断用.

EUREKA 的情况不同. 它改的是奖励 $R$, 它支配之后的策略训练, 所以综述把它放在 L4 的奖励设计下. 但比较奖励候选的适应度 $F$ 一直固定, 这是它的外部锚点. 综述对整个可执行奖励这一类的判断是: 证据仍然绑在固定的任务描述和结果度量上, 策略回报高不能证明合成的奖励覆盖了所有想要的结果. 落到 EUREKA 上: 它证明了自己的奖励在 $F$ 上能训练出好策略; $F$ 没测到的行为, 奖励是否引导得对, 不在这个证据范围里.

### 6.3 四类共同的失败与提升记录

综述 §7.3 把上面这些机制的问题归成四类: 评分规则池会认可大家共有的偏好; 一群评测器会互相迁就; 自适应测试可以变难而不变得更相关; 奖励程序可以优化一个不完整的代理. 本篇里都有对应的实例: Double Ratchet 去掉锚点后评分函数退化成全判通过; RQGM 固定审稿人时写作者在它眼里达到 100%; HGM-H 审稿人对 AI 论文的接收率是人类论文的最多 1.91 倍.

综述要求, 提升一个新标准时, 记录里写明六项: 不变的外部目标, 可写的标准部件, 证据覆盖了什么, 接受规则, 批准者, 回滚条件.

分阶段, 带版本地启用新标准, 可以保留一个比较基线, 让之后的失败能追溯到对应的判断规则, 也能在回滚时不悄悄改写之前的结果.

拿本篇的几个系统对照这六项:

| 系统 | 可写的标准部件 | 外部目标 / 锚点 | 接受规则 | 回滚 |
|---|---|---|---|---|
| RQGM | 评测器 (代码审查者, 审稿人, 评分者) | 真值锚点: Polyglot 测试, CRAVE, APReS, IMO-GradingBench | 锚点上 $BB_\epsilon$ 最高者, 平局保留在任者 | 不回滚; 替换后删除旧分 |
| Double Ratchet | 评分函数表达式 | 10 样本锚点; 锁定集; 独立终审 | 锚点一致性加共识正则, 取历史最好 | 终审发现问题后人工加检测器修复 |
| OpenComputer | 检查器代码, 接口, 文档 | 缓存轨迹与最终状态; 人工对比集 | 与 LLM 参考判断在检查器错误项上一致 | 修复预算用完即停 |
| EUREKA | 奖励程序 | 任务适应度 $F$ | $F$ 上最好的候选 | 无 |

批准者这一列没有列出, 因为四个系统的批准都是自动的, 接受规则本身由人在实验开始前定好. 综述说的「有授权的批准者」, 在这些研究系统里都还是空位.

### 6.4 能主张什么

在覆盖充分, 批准有授权的前提下, L4 的证据能支持一个有界的主张: 修订后的标准在被审计的领域上更好地服务了声明的外部目标. 它不能证明标准在一般意义上有效, 不能证明共同进化的评判器会持续保持一致, 也不能证明对这个领域之外的人和场景是正当的.

综述列出的开放问题: 共同进化的评判器能否保持区分度, 而不是互相迁就; 自适应测试能否保持相关, 而不只是变难; 在人类监督有限的情况下, 规范性的标准变化怎么保持可问责.

第 5 部分接着讨论这些问题在各层的具体失效方式, 以及评测和安全边界怎么设.
