# 4.1 · L3: 自指智能体

第 3 部分的系统改提示, 记忆, 工作流和运行环境, 但决定「提出什么改动, 留下哪个, 何时回滚」的那段程序一直是人写的. L3 把这段程序, 也就是改进器 $U$, 放进可保留状态. 材料是五个系统: Gödel Machine 用证明决定是否改写自己, Gödel Agent, SICA, DGM, HGM 用经验评测代替证明.

## 1. L3 的边界与 Gödel Machine

### 1.1. L3 的条件

1.2 第 1.2 节把 Agent 的可保留状态写成 $\mathcal{A}=(\theta,\Sigma,U,C)$. L3 的边界条件是

$$
U_{k+1} \not\equiv_{\mathrm{act}} U_k, \qquad C_{k+1} \equiv_{\mathrm{act}} C_k.
$$

改进器的生效语义变了, 评判标准没变. 同一次转移里 $\theta$ 和 $\Sigma$ 也可以变. 综述给的操作性测试是: 先忽略这一轮产出的答案, 算法或任务求解器, 再问下一轮提出, 选择, 提交或回滚改动的方式会不会因为保留下来的东西而不同. 如果不会, 就按实际被改的对象归到 L1 或 L2.

### 1.2. 自指是功能关系

综述强调, 自指不是系统的名字. 递归调用或者编辑源代码, 本身都不构成自指. 自指成立需要两件事: 当前的改进器参与修改它自己的继任者, 并且保留下来的修改影响之后的更新轮次. 要拿出的证据, 是之后更新方式的一个被保留的因果变化.

这条标准在编程 Agent 上特别重要. 编程 Agent 的任务代码和更新代码常常在同一个仓库里. 一次改动给编辑工具加了按行查看的功能, 它既改善了解题, 也改善了下一轮改自己代码的能力; 另一次改动只改了某个任务的提示, 那是 L2. 综述把这一点写成要求: 任务执行的编辑和更新过程的编辑必须分开记录.

**Gödel Machine 的设定: 证明了才改写。**

Schmidhuber (2003) 的 Gödel Machine 运行在一台只有一次生命的机器上, 时间是离散的步 $t=1,2,\ldots$, 总寿命 $T$ 可以未知. 在任意时刻, 目标是最大化未来的效用. 典型的效用函数是剩余寿命内的期望累积回报:

$$
u(s, \mathrm{Env}) = E_\mu\left[\sum_{\tau=\mathrm{time}}^{T} r(\tau) \;\middle|\; s, \mathrm{Env}\right].
$$

其中 $s$ 是机器的状态 (一个比特串), $\mathrm{Env}$ 是环境状态, $r(\tau)$ 是第 $\tau$ 步的实值回报, $\mu$ 是环境的分布, 可以部分未知. 效用里计入了所有动作的计算成本, 包括证明搜索本身花掉的时间.

**证明搜索器和目标定理。**

初始程序 $p(1)$ 包含两部分: 一个和环境交互的求解子程序 $e(1)$, 可以是任意传统的强化学习算法; 一个通用的证明搜索器. 证明搜索器系统地产生 (switchprog, proof) 对, 直到找到一个目标定理的证明. 目标定理大意是: 「用当前的 switchprog 立刻改写 $p$, 效用高于让 $p$ 保持原样.」 找到以后, 机器执行 switchprog. switchprog 可以完全改写 $p$, 包括证明搜索器本身.

为了让证明搜索器能推理任何程序的效果, 初始程序里编码了一套公理系统 $\mathcal{A}$, 描述四件事: 硬件上每条指令怎样改变状态 $s$; 初始程序 $p(1)$ 本身; 环境的随机性质; 形式化的效用函数 $u$. 证明只能用六条指令构造, 包括取公理, 应用推理规则, 设置 switchprog, 检查最后一个定理是不是目标定理. 这六条指令保证不可能把错误的定理插进证明, 所以验证证明是平凡的.

**全局最优定理说的是什么。**

论文的定理 4.1 说这种自我改进策略不是贪心的. 原因在目标定理的比较对象: 「让 $p$ 保持原样」的效用, 隐含地计入了未修改的 $p$ 以后可能找到的所有其他 switchprog. 所以一旦执行, 当前的 switchprog 就是所有相关自我改动里最好的那个. 这个最优是相对的: 相对给定的资源限制, 也相对初始的证明搜索策略.

用 1.2 的记号看, Gödel Machine 的 $U$ 是证明搜索器加上「证明了就执行」的安装规则, $C$ 是公理系统和效用函数 $u$. 证明搜索器是 $p$ 的一部分, 可以被 switchprog 改写, 所以 $U$ 在可保留状态里并且能被自己改. 公理和效用函数不能改, 所以它是 L3, 不是 L4.

**限制。**

论文自己写了根本限制. 任何包含算术的形式系统要么有缺陷, 要么存在真但不可证的命题. 所以即使计算资源无限, Gödel Machine 也必须放弃那些它证明不了有效的自我改进.

综述补了两条实际限制. 第一, 保证是有条件的: 如果公理漏了相关事实, 或者效用函数没有写对想要的目标, 形式结果推不出部署中的收益. 第二, 如果证明系统在预算内找不到证明, 它什么也不改, 没有实际收益. DGM 论文举了一个具体例子说明为什么证明在实践中几乎做不到: 给编程 Agent 加一个测试工具看起来总是有益的, 但实际影响取决于模型的训练和任务环境, 为一种设置优化的测试工具可能让另一种设置下的 Agent 困惑.

后面四个系统都把证明换成了经验评测. 这让机制可用, 也把可靠性的负担转到了评测覆盖面, 资源匹配和基准访问控制上.

**自指更新的形式与稳定性。**

把自指智能体写成「程序修改自己的源代码」容易把载体当成本质. 更一般地, 第 $k$ 轮状态为 $A_k=(\theta_k,\Sigma_k,U_k,C)$, 轨迹与评测证据为 $D_k$, 更新器输出下一版:

$$
A_{k+1}=U_k(A_k,D_k),\qquad
U_{k+1}=\operatorname{Proj}_U(A_{k+1}). \tag{1}
$$

$\operatorname{Proj}_U$ 表示从完整 Agent 里取出下一轮真正执行更新的部分. L3 要求 $U_{k+1}$ 与 $U_k$ 的生效行为不同, 且差异在下一轮被执行. 只把新提示存进代码库, 后续更新仍走旧函数, 属于没有生效的文本改动; 任务策略变强后间接写出更好的补丁, 只有当它实际参与 $U$ 时才构成 L3.

更新器既是变换也是状态. 若 $U_k$ 只接收 Agent 和当前证据, 它是一阶更新; 若它还读取自己的历史补丁、失败档案和搜索策略参数, 历史也属于 $U$ 的有效状态. SICA 的档案、DGM 的谱系、HGM 的子树统计都把过去结果带进下一轮选择. 比较新旧改进器时必须连同这些状态初始化, 单换一段代码却沿用不同档案会把历史优势算成算法优势.

自指会产生分布移动. $U_k$ 的训练或提示建立在旧版 Agent 产生的轨迹分布 $P_k(D)$ 上, 更新后 $A_{k+1}$ 产生 $P_{k+1}(D)$. 新工具让过去的错误消失, 也会产生旧归因器没见过的新错误. 若更新器继续按 $P_k$ 的模式解释轨迹, 它可能反复修复已经不存在的问题. 因此 L3 的回归不仅测试任务产物, 还要测试新更新器对新版轨迹的诊断和候选生成.

稳定性至少有三种含义. 任务稳定性要求任务效用不出现不可接受退化; 更新稳定性要求下一轮仍能提出并安装有效候选; 表示稳定性要求新版仍能读取历史档案、工具接口和评测记录. Gödel Agent 修改递归模块后意外终止, 是更新稳定性失败; SICA 的上下文越来越长直至无法运行, 是表示和资源稳定性失败; 节点 114 删除检测标记, 任务分数表面稳定却破坏了评测可观测性.

可把一次更新的可接受条件写成约束集合. 设任务效用为 $J(A)$, 一步后的更新生产力为

$$
M(A,U)=\mathbb E_{D,A'\sim U(A,D)}[J(A')-J(A)], \tag{2}
$$

候选 $A'$ 要同时满足 $J(A')\ge J(A)-\delta_J$, $M(A',U')\ge M(A,U)-\delta_M$, 以及接口不变量. 只测 $J$ 会保留当前高分但失去自改能力的后代; 只测 $M$ 又可能接受当前任务能力过低的「好父代」. HGM 的 CMP 尝试估计第二项, 但它仍用同一基准近似 $J$ 和后代潜力.

更新生产力不能从一个子代判断. $U$ 是随机候选生成器, 单次结果混合了算法质量与采样运气. 对同一父代运行多次得到候选集合, 比较成功概率、改进幅度分布、成本和灾难失败率, 才接近比较两个 $U$. 一个改进器偶尔产生巨大提升同时经常删坏自身, 与一个稳定产生小改进的改进器适用于不同风险边界. 只报告最好后代会系统性偏向高方差方法.

自指更新还会改变自身的搜索支持集. 设 $\mathcal S(U_k,A_k)$ 为当前更新器能以非零概率提出的候选集合. 一个新编辑工具可能扩大支持集, 让以前无法表达的补丁可达; 一个过度严格的模板可能缩小支持集, 即使当前任务分提高, 长期潜力也下降. 搜索支持集通常无法穷举, 可以用候选多样性、修改组件覆盖和已知反事实任务做探针. HGM 关注后代分数, 尚未直接测支持集变化.

局部接受门会导致不可跨越的谷地. 假设接口迁移要同时修改调用方与实现, 单独任一补丁都失败, 两者合并才提高. 每轮只接受立即提分的原子补丁时, 目标结构不可达. 允许候选在隔离分支里积累多步修改能跨谷, 也扩大了搜索成本和破坏面. Gödel Machine 的 switchprog 可整体改写程序, 理论上能表示组合跳跃; 经验系统需要事务分支、组合测试和预算上限来近似.

回滚为自指系统提供固定参照. 仅保存代码版本不够, 还要保存更新器状态、档案、模型与工具版本、评测预算和未完成任务. 若回滚代码却沿用新档案, 下一轮候选分布已经改变; 若回滚 Agent 却不能撤销外部副作用, 任务状态也不相同. 可恢复检查应在真实版本迁移前演练, 不能等到更新器已失去编辑能力后才尝试.

权限边界必须位于可写区域之外. 普通 L3 候选可以修改怎样检索、怎样编程和怎样选择内部候选, 不能自行扩大网络、凭证、评测数据和部署权限. 若权限配置也由同一得分选择, 绕过限制往往是比改进算法更短的得分路径. 节点 114 展示的是可观测性边界被修改; 同样机制若作用到权限边界, 后果更严重.

经验自指无法得到 Gödel Machine 的全局证明, 仍可建立分层证据. 静态检查保护语法、依赖和权限; 回放检查历史状态; 密封任务比较任务效用; 后代实验比较更新生产力; 金丝雀和回滚限制未覆盖的在线损害. 每层排除一类失败, 没有哪一层能单独证明「系统会持续变好」. 最强可说的结论仍带范围: 在给定模型、工具、预算、任务分布和更新轮数内, 某更新器比对照更常产生被外部验收的候选.

### 1.3. Gödel Agent: 运行时改自己的代码

**机制。**

Yin 等人 (2024, 北京大学, UCSB) 的 Gödel Agent 把系统分成两部分: 任务策略 $\pi$, 以及一个自指的学习算法 $I$. 当前的 $I$ 同时产出下一版的 $\pi$ 和下一版的 $I$, 而不只是改任务策略. 这满足 1.2 节的功能条件.

实现上, Agent 从 Python 的运行时内存里读取自己当前的函数和类, 用 monkey patching 在运行中增加, 替换或删除逻辑. 主函数写成递归函数: 语言模型分析当前状态, 做出一串决定, 包括读自己的代码, 改自己的代码, 和环境交互拿反馈, 然后进入下一层递归, 在下一层运行改过的学习逻辑. 初始还给了四个辅助工具: 先想再做, 出错处理, 运行 Python 或 Bash, 调用语言模型 API.

出错处理的设计是: 一个操作出错时, Agent 停掉当前这串动作, 进入下一个时间步, 把错误信息带过去供之后参考.

**结果。**

实验沿用 ADAS (Hu et al., 2024) 的设置. 四个基准: DROP (阅读理解, F1), MGSM (多语言数学), MMLU, GPQA. 初始策略都是 CoT. 每个任务在验证集上跑 6 轮独立的自我改进, 每轮最多 30 次迭代, 得到的 Agent 再在测试集上评测. GPQA 的验证集 32 题, 测试集 166 题; 其余三个验证集 128 题, 测试集 800 题. 自我改进由 GPT-4o 驱动, 改出来的策略和基线都用 GPT-3.5 评测.

| 方法 | DROP | MGSM | MMLU | GPQA |
|---|---|---|---|---|
| CoT | 64.2 ± 0.9 | 28.0 ± 3.1 | 65.4 ± 3.3 | 29.2 ± 3.1 |
| LLM Debate | 60.6 ± 0.9 | 39.0 ± 3.4 | 65.6 ± 3.3 | 31.4 ± 3.2 |
| Meta Agent Search (ADAS) | 79.4 ± 0.8 | 53.4 ± 3.5 | 69.6 ± 3.2 | 34.6 ± 3.2 |
| Gödel-base | 80.9 ± 0.8 | 64.2 ± 3.4 | 70.9 ± 3.1 | 34.9 ± 3.3 |
| Gödel-free | 90.5 ± 1.8 | 90.6 ± 2.0 | 87.9 ± 2.2 | 55.7 ± 3.1 |

± 后面是 95% bootstrap 置信区间. 读这张表要注意三点.

第一, 和 Meta Agent Search 比, 差距只在 MGSM 上明显: 64.2 对 53.4, 高 10.8 个点. DROP 差 1.5, MMLU 差 1.3, GPQA 差 0.3, 都在置信区间的宽度之内.

第二, Gödel-base 是加了约束的版本, 用于和基线公平比较. Gödel-free 不加约束, 分数高得多. 论文分析后承认, 这主要是因为 Agent 在一些任务里自发地去调用更强的模型, 比如 GPT-4o. 这个提升来自换了执行模型, 不来自改进器变好.

第三, 基线的数字直接引自 Hu 等人 (2024), 不是同一批重跑.

**稳健性与归类。**

论文在 MGSM 上做了 100 次优化试验. 4% 的试验意外终止, 92% 在优化中出现过暂时的性能下降, 14% 最终比初始策略更差. 意外终止通常发生在 Agent 修改了自己的递归改进模块之后, 修改以后它没法再继续自我优化.

消融也说明了同一件事. 去掉出错处理, MGSM 降到 49.4, 标准差 14.8, 是四项消融里波动最大的. 去掉「先想再做」降到 50.8. 去掉运行代码和调用模型两个工具影响较小 (57.1 和 60.4), 论文的解释是 Agent 能自己实现这两项功能.

改自己的学习逻辑, 最常见的后果是改坏. 出错处理和回到之前最优算法的能力, 是 Gödel Agent 能持续运行的前提.

按综述的划分, Gödel Agent 满足自指的功能条件. 它的任务反馈来自固定的高层目标和环境接口, 所以没有 Gödel Machine 那样的证明保证. 评判标准 $C$ 是这个固定的目标和反馈, 没有被改.

**运行时改写的语义债务。**

Monkey patching 让改动立即生效, 也绕过了普通软件升级里的构建、启动和迁移边界. 当前栈帧可能还在执行旧函数, 下一次递归进入新函数; 两版逻辑共享同一块内存状态. 于是「版本」不再是一个时刻的完整快照, 而可能是旧代码和新代码的混合执行. 若轨迹没有记录每次调用使用的函数哈希, 失败后无法还原是哪一版产生了动作.

运行时改写可以形式化为带代码状态的转移. 普通程序状态为 $s_t$, 自指程序再带代码 $p_t$:

$$
(s_{t+1},p_{t+1})=F(s_t,p_t,a_t). \tag{3}
$$

任务动作主要改变 $s$, 自改动作改变 $p$, 许多操作同时改变两者. 若改写失败发生在 $p_{t+1}$ 已部分安装之后, 程序可能没有能力执行恢复. 安全安装要把候选写到隔离版本, 验证后通过单一原子指针切换; 切换前保留旧进程或监督器, 由候选之外的组件判断是否回退.

递归深度不是改进轮数的可靠表示. 一层递归可能只重试工具, 也可能替换整个学习算法; 尾递归未优化时还会耗尽调用栈. 更稳妥的控制器把轮次、版本、预算和失败状态显式存在外层循环, 候选学习逻辑只提交变更请求. 这样即使候选把自己的递归函数删坏, 外层仍能终止进程并恢复. 代价是这个不可修改外层成为新的固定边界, 系统的自指范围缩小但可恢复性提高.

代码反射还会遇到闭包与动态绑定. 替换一个函数名称, 已被其他对象捕获的旧函数引用可能继续存在; 修改类方法, 已实例化对象的字段状态未必满足新不变量; 删除辅助函数, 排队中的回调仍可能调用它. 自动更新不能只检查源码 diff, 要枚举活动对象、挂起任务和持久状态的依赖. 无法迁移的对象应让旧版完成, 新请求再进入新版.

修改学习算法尤其需要元回归测试. 普通任务测试验证答案质量, 元测试验证它还能读取自己、提出候选、执行候选、评估并恢复. 可以准备几个合成故障: 让编辑工具返回冲突, 让候选语法错误, 让评测超时, 让新版本启动后立即异常. 每个故障都应落到可观察失败并恢复到已知版本. Gödel Agent 去掉出错处理后方差暴增, 表明恢复路径本身就是更新器能力的一部分.

错误处理若由可改代码实现, 候选可能出于简化而删掉它. 只在正常任务上评测时, 删除恢复分支还能降低成本、提高平均分. 因而恢复能力要成为硬约束, 通过故障注入验收, 不能和任务分数做加权交易. 同理, 日志、版本标识和权限检查属于认证边界; 它们可以升级, 但修改它们需要更外层审计.

运行时状态还可能污染候选比较. 版本 $p'$ 在旧版已经热过的缓存、打开的文件和累积记忆上评测, 版本 $p$ 却从冷启动运行, 差异包含状态优势. 配对比较应从同一快照分叉, 或分别报告冷启动与继承状态. 对自指系统, 继承状态是实际部署的一部分, 但它不能替代对代码本身的归因.

沙箱除了防恶意代码, 也为候选定义观察边界. 文件、网络、进程和模型 API 的白名单决定候选能利用什么. Gödel-free 自发调用更强模型取得高分, 说明未锁定资源时搜索会优先利用能力更强的外部组件. 若研究目标是更新逻辑, 基础模型和工具必须固定; 若允许资源路由演化, 结论应写成整套资源策略提高, 并计入真实成本.

一次更新成功还不代表改写机制可复用. 候选可能硬编码当前函数名、文件布局或基准格式, 下次代码结构变化后便无法编辑. 元测试应包含等价重命名、模块移动和不同任务反馈格式, 检查更新器是利用语义接口还是偶然文本位置. 能跨版本继续修改的能力, 才是保留下来的 L3 增益.

**功能自指的因果检验。**

看到代码里出现 `self_modify` 或递归函数, 不能证明改进器变化带来后续收益. 最直接的检验是冻结反事实. 候选 Agent $A'$ 已经包含新的任务策略和新的更新器 $U'$. 构造一个混合版本 $A'_{U}$: 保留 $A'$ 的任务组件, 把更新器换回 $U$; 再构造 $A_{U'}$: 保留旧任务组件, 只换成 $U'$. 从同一批新任务和同一档案状态出发, 给它们相同的下一轮更新预算.

若完整 $A'$ 和 $A_{U'}$ 都能产生更好的后续补丁, 而 $A'_{U}$ 不能, 证据指向更新器改变; 若 $A'_{U}$ 同样提升, 主要收益可能来自任务能力变强, 它让固定更新器获得了更好的轨迹或代码执行能力. 两者都提升时存在协同, 需要四格实验估计交互:

$$
\Delta_{\mathrm{int}}=J(A',U')-J(A',U)-J(A,U')+J(A,U). \tag{4}
$$

这里的 $J$ 衡量后续更新产物, 不能复用产生 $A'$ 的开发任务.

冻结反事实在代码上未必容易. 更新器和任务策略可能共享工具、记忆和接口, 强行替换后无法运行. 这种不可分性本身也是结果: 系统只能声称完整组合具备自指更新, 无法归因某个模块. 若论文要主张特定自改机制, 设计时就应建立接口边界, 让新旧更新器可以在相同状态上互换.

第二个检验是失活更新. 保留候选代码与任务行为, 禁止它在下一轮读取或执行自己修改过的更新部分. 如果后续改进曲线不变, 被保留的自指修改没有因果作用. DGM 的 `w/o self-improve` 接近这个思路: 固定初始元 Agent, 让其他档案与评测过程保持一致. 完全匹配还要确保两组看到相同失败日志和候选权限.

第三个检验是更新转移. 把 $U'$ 放到一个没有参与生成它的新起点 $A^{\mathrm{new}}$ 上, 看它是否仍比 $U$ 产生更好候选. 只在自己的代码库上有效, 可能是特化编辑脚本; 跨版本有效, 更像更新原则. 转移范围不必无限, 可以按同代码库新版本、同框架不同任务、不同框架三层报告.

自指能力还可用干预敏感性检查. 给更新器一组可控失败: 缺测试、工具超时、上下文溢出、候选语法错、评测冲突. 观察它提出的修复是否随故障机制变化. 无论输入都加重试或加更强模型, 说明候选策略缺乏诊断分辨率. 真正改进过的 $U'$ 应在不相关故障上保持原策略, 在目标故障上改变候选分布.

后续产物的比较必须包含失败候选. 若 $U'$ 十次中一次产生高分补丁、九次破坏自身, 只取最好值会认为它优于稳定的 $U$. 记录每次候选的可运行率、净改进、恢复成本和权限变化, 再按实际部署会采用的选择规则聚合. 选择规则固定后, 高方差是否值得才有明确答案.

功能检验也要确认保留. 运行结束后重启进程、清空临时上下文, 从持久版本加载, 再执行下一轮更新. 只有运行时内存中的 monkey patch 在重启后消失, 它是会话内适应; 写入代码却启动时仍加载旧模块, 也没有生效. L3 证据要求修改跨越任务和进程边界后继续影响更新.

这些因果检验比检查源码更苛刻, 因为它们要求观察第二轮甚至多轮后果. 这正是 L3 与普通自动编程的差别. 一次补丁解决当前任务只能证明产物有效; 被修改的更新过程在匹配条件下更常产生好补丁, 才证明改进器发生了有用变化.

## 2. SICA: 档案里最好的 Agent 当元 Agent

### 2.1. 和 ADAS 的区别

Robeyns, Szummer, Aitchison (2025, Bristol, iGent AI) 的 SICA 从 ADAS 出发. ADAS 有两个 Agent: 执行任务的目标 Agent, 和改进目标 Agent 的元 Agent. 元 Agent 固定, 只改目标 Agent, 所以 ADAS 不是自我改进. SICA 取消了这个区分: 每一轮从档案里取到目前为止效用最高的 Agent 当元 Agent, 让它读档案, 找出一个改进, 实现在自己的完整 Python 代码库上, 产出下一个 Agent.

$$
A_{i+1} = \mathrm{Run}\big(A_{\hat i};\ A_{\le i},\ p_{\le i}\big), \qquad \hat i = \arg\max_{j \in \{0,\ldots,i\}} p_j.
$$

$p_j$ 是第 $j$ 个 Agent 的效用. 因为没有权重更新, 这个分数只用来挑下一轮的元 Agent.

### 2.2. 效用函数

$$
U = w_{\mathrm{score}}\, p_{\mathrm{score}} + w_{\mathrm{cost}}\left(1 - \min\left(1, \frac{p_{\mathrm{cost}}}{\$10}\right)\right) + w_{\mathrm{time}}\left(1 - \min\left(1, \frac{p_{\mathrm{time}}}{300\,\mathrm{s}}\right)\right),
$$

$w_{\mathrm{score}}=0.5$, $w_{\mathrm{cost}}=0.25$, $w_{\mathrm{time}}=0.25$. $p_{\mathrm{score}} \in [0,1]$ 是归一化的基准分, 成本上限每题 10 美元, 超过 300 秒取消. 超时的 Agent 效用乘以 $1-\tau$, $\tau = 0.5$.

代一组数. 一个 Agent 分数 0.5, 每题花 2 美元, 用时 130 秒:

$$
U = 0.5 \times 0.5 + 0.25 \times (1 - 0.2) + 0.25 \times \left(1 - \tfrac{130}{300}\right) = 0.25 + 0.2 + 0.1417 = 0.5917.
$$

同一个 Agent 如果超时, 效用变成 $0.5917 \times 0.5 = 0.2958$.

再看一个极端: 一个 Agent 收到题目立刻交一个空答案, 分数 0, 成本和时间都接近 0. 代进去得 $U = 0 + 0.25 + 0.25 = 0.5$. 它只比上面那个真正解题的 Agent 低 0.09. 这个式子里, 分数只占一半权重, 另一半奖励便宜和快. 效用函数就是 SICA 的评判标准 $C$, 而元 Agent 的选择完全由它决定. 这组数字说明, 一个固定的 $C$ 本身就规定了改进器会朝哪里走.

### 2.3. 结果: 编程任务和推理任务

初始 Agent 已经带了不少工具: 打开和关闭文件, 覆写文件, 执行 shell 命令, 计算器, 档案分析工具, 以及编码, 解题, 推理三个子 Agent. 还有一个异步的监督者: 另一个语言模型每 30 秒看一次整个调用图和事件流, 判断有没有偏离任务或陷入循环, 可以插入提示, 严重时取消执行. 主体用 Claude 3.5 Sonnet (v2), 推理子 Agent 用 o3-mini. 评测集是 SWE-bench Verified 的固定随机 50 题, LiveCodeBench 的随机 50 题, 加两个在 Agent 代码库里定义的合成基准: 文件编辑和符号定位. 15 轮运行的 API 成本约 7000 美元.

| 轮 | 文件编辑 | 符号定位 | SWE-Bench Verified 子集 | LiveCodeBench | 每题成本 ($) | 每题用时 (s) |
|---|---|---|---|---|---|---|
| 0 | 0.82 | 0.35 | 0.17 | 0.65 | 1.91 | 130.2 |
| 4 | 0.88 | 0.31 | 0.38 | 0.54 | 2.70 | 148.3 |
| 9 | 0.88 | 0.40 | 0.47 | 0.61 | 2.03 | 126.3 |
| 13 | 0.86 | 0.40 | 0.27 | 0.61 | 1.66 | 113.3 |
| 14 | 0.94 | 0.34 | 0.53 | 0.67 | 2.20 | 117.1 |
| 15 | 0.91 | 0.40 | 0.51 | 0.71 | 1.70 | 114.5 |

摘要里的「17% 到 53%」是第 0 轮和第 14 轮的 SWE-Bench 子集分数. 第 13 轮掉到 0.27, 下一轮又回到 0.53. 一个 50 题的子集上, 相邻两轮相差 26 个点, 单轮分数的噪声很大. 用最高的那一轮报告改进, 会把噪声算进去.

改动本身是具体的: 文件编辑从整文件覆写换成了基于 diff 和行范围的「smart edit」工具; 第 9 轮加了基于 AST 的符号定位器, 论文推测它利用了基准主要是 Python 这一点.

推理任务上几乎没有提升. 另一组实验用 AIME 2024 和 GPQA Diamond. o3-mini 单独以 high 推理强度跑, 分别是 87% 和 79%; 整个 Agent 系统两项平均只有 76%. 查看轨迹发现, 主 Agent 很多时候只是把题转给 o3-mini 推理子 Agent. 第 4, 6 轮加入的诱导推理的组件, 论文怀疑反而打断了推理模型自己的 CoT. 当底层模型已经很强时, 脚手架和改进器能加的东西很有限.

**路径依赖与归类。**

论文在局限里写了一个对 L3 很关键的观察. 让语言模型在每一步自己想出新颖, 可行的改动方向很难. 一个坏主意的代价是一段很长的编辑, 再加一次更贵的基准评测. 失败的迭代留在档案里, 原则上可以当反例, 但实际上最初几轮的功能想法会强烈影响后面的想法, 后面多是同一主题的变体. 论文举的例子是早期一直执着于缓存已打开的文件, 拉低了后续建议的质量.

SICA 每轮只沿着当前最好的 Agent 往下走, 这种路径依赖没有机制可以纠正. DGM 的档案和 HGM 的子树统计, 都是在处理这个问题.

归类上, SICA 让档案里的强 Agent 执行下一步元改进, 新代码能不能进档案由固定的效用函数和基准检查决定. Agent 的编程能力可以帮助之后的元改进, 但成本, 速度和基准的权重由外层规则设定. 改进器 $U$ 是「当前最好的 Agent + 档案」, 每轮都变; 评判标准 $C$ 是 3.2 节的效用函数, 固定.

**档案怎样改变候选分布。**

档案不仅保存结果, 还向元 Agent 提供搜索上下文. 设历史为 $H_t=\{(A_i,p_i,\tau_i)\}_{i\le t}$, $\tau_i$ 是修改说明与执行轨迹, 下一候选分布为

$$
P(A_{t+1}\mid A_{\hat i},H_t). \tag{5}
$$

即使元 Agent 代码没变, 档案增长也会改变候选分布. 在 L3 归因里要区分两种来源: 新父代的能力变化, 与新历史带来的上下文变化. 固定父代、替换档案可以测历史效应; 固定档案、替换父代可以测元 Agent 效应. SICA 同时改变两者, 因而端到端提升不能完全归给父代变强.

完整档案会迅速超过上下文. 压缩档案时, 选择保留哪些失败就是搜索偏置. 只留高分候选会遗忘已经试过的坏方向; 只留摘要会丢掉代码冲突和适用条件; 只留最近轨迹会产生主题惯性. 可把档案分成可执行版本、结构化差异、评测证据和失败机制四层, 按当前任务检索, 而不是把所有历史串成一段长文本.

失败档案的价值取决于它能否排除候选. 一条「缓存没有帮助」若缺少父代、实现和评测口径, 后续模型仍可能用另一种措辞重复同一改动. 更可用的失败记录包含前置状态、修改算子、预期机制、实际结果和反例. 搜索时先判断新候选与既有失败是否机制等价; 等价且没有新证据时降低优先级, 有明确差异时允许重试.

路径依赖可由状态压缩解释. 元 Agent 从庞大历史得到有限上下文 $Z_t=g(H_t)$, 后续候选只依赖 $Z_t$. 若 $g$ 过早把早期主题标成「最有希望方向」, 其他分支的信息被丢掉, 之后无法恢复. 保留多个彼此差异大的分支, 相当于维护多个 $Z_t$ 假设. DGM 的开放档案比 SICA 的单冠军链更能抵抗这种压缩损失.

冠军选择也会放大评测噪声. $\hat i=\arg\max p_i$ 同时选择了真实能力和正噪声, 下一轮围绕它继续搜索, 噪声造成的路径选择被永久写入谱系. 对入围父代重评、使用后验抽样或保留前沿, 都能减少一次偶然高分决定全部未来预算. SICA 第 13 到 14 轮的巨大波动说明单轮冠军并不稳定.

档案的覆盖可以按修改算子与行为表型衡量. 源码差异大但任务路径相同的候选提供的探索很少; 源码相近却改变工具次序、验证机制或资源分配的候选可能更有价值. 行为表型可以由调用图、错误分布、成本和输出集合组成. 父代选择同时考虑效用与表型新颖性, 比按代码字符距离鼓励多样性更接近搜索目的.

档案中低分节点的价值是期权价值. 当前分数低不代表它无用, 它可能包含一个暂时与其他组件不兼容的机制. 是否继续投资取决于从该节点产生高价值后代的概率与成本. DGM 用子代数惩罚近似鼓励尚未展开的节点, HGM 用子树统计直接估计后代潜力. 两者都不能识别从未被扩展节点的真实潜力, 探索先验仍由外层规则决定.

归档还需要垃圾回收. 无界保存所有源码、轨迹和评测会让检索、存储与安全审计成本持续增长. 删除不能只按分数: 某节点可能是唯一覆盖一种修改算子或失败机制的代表. 可以保留每个行为簇的帕累托代表、关键祖先与已知指标捕获案例, 将其余节点冷存储. 冷存储仍可用于审计, 不进入每轮元提示.

由此, 「档案里的最好 Agent 当元 Agent」包含三项耦合选择: 谁执行更新、它看到什么历史、历史怎样压缩. 要证明自指能力来自 Agent 变强, 至少需要一个固定档案的对照. 要证明档案机制有用, 则固定更新模型比较不同保留与检索策略. 缺少拆分时, 可以声称整套 SICA 循环产生了更好候选, 不宜把机制进一步归因.

## 3. DGM: 保留所有能工作的后代

### 3.1. 两个改动

Zhang, Hu, Lu, Lange, Clune (2025, UBC, Vector Institute, Sakana AI) 的 Darwin Gödel Machine 在 SICA 这条路线上做了两个改动.

第一, 和 Gödel Machine 一样, 把自我改进本身定义为编程任务: 修改 Agent 自己的组件, 也就是它自己的代码. 论文的关键假设是, 编程基准上的提升反映了更好的编程能力, 因而也反映了更好的自我修改能力. 这样, 同一个评测同时度量「解下游任务」和「改自己」.

第二, 维护一个档案, 收录所有生成过的, 还能工作的 Agent. 每轮从档案里采样父代, 而不是只取当前最好的那个. 一个当时分数不高的 Agent, 可能在很多轮之后成为一次大改进的起点.

### 3.2. 一轮怎么走

1. 从档案里按概率选父代.
2. 父代读自己在基准上的评测日志, 提出下一个要实现的功能. 这个诊断由另一个基础模型完成, 提议作为问题描述交给父代执行.
3. 父代把这个功能实现到自己的代码库里, 产生一个新 Agent.
4. 新 Agent 在编程基准上评测.
5. 只有能编译, 并且保留了编辑代码库能力的 Agent 才进档案, 因为只有它们能继续自我修改. 其余丢弃.

初始 Agent 故意做得很轻: 一个冻结的基础模型, 只有两个工具, 一个执行 bash 命令, 一个查看和编辑整个文件. 运行 80 轮, 每轮产生一个新 Agent; SWE-bench 上 2 轮并行, Polyglot 上 4 轮并行. 自我修改阶段用 Claude 3.5 Sonnet (New); 评测阶段 SWE-bench 用 Claude 3.5 Sonnet (New), Polyglot 用 o3-mini.

### 3.3. 父代选择

设第 $t$ 轮档案里的 Agent 为 $a_1, \ldots, a_N$. 对每个 Agent:

$$
s_i = \frac{1}{1 + \exp\big(-\lambda(\alpha_i - \alpha_0)\big)}, \qquad h_i = \frac{1}{1 + n_i}, \qquad w_i = s_i h_i, \qquad p_i = \frac{w_i}{\sum_j w_j}.
$$

$\alpha_i$ 是 Agent 的基准分, $n_i$ 是它已有的, 仍能工作的子代数量. $s_i$ 把分数压到 $(0,1)$, $h_i$ 是新颖性奖励, 子代越多越小. 论文取 $\lambda = 10$, $\alpha_0 = 0.5$, 每轮按 $p_i$ 抽 $k$ 个父代, SWE-bench 上 $k=2$, Polyglot 上 $k=4$.

手算一个三节点档案:

| Agent | $\alpha_i$ | $n_i$ | $s_i$ | $h_i$ | $w_i$ | $p_i$ |
|---|---|---|---|---|---|---|
| A | 0.5 | 0 | $1/(1+e^{0}) = 0.500$ | 1 | 0.500 | 0.623 |
| B | 0.6 | 3 | $1/(1+e^{-1}) = 0.731$ | 0.25 | 0.183 | 0.228 |
| C | 0.3 | 0 | $1/(1+e^{2}) = 0.119$ | 1 | 0.119 | 0.149 |

$w$ 之和是 $0.802$. B 的分数最高, 但已经有 3 个子代, 被抽中的概率只有 A 的三分之一多一点. C 分数低, 还保留约 15% 的概率. 所有 Agent 的概率都大于 0, 论文据此说, 只要算力足够, 任何一条通向改进的路径都可达.

$\lambda = 10$ 让 $s_i$ 在 $\alpha_0$ 附近很陡: 分数从 0.4 到 0.6, $s_i$ 从 0.269 到 0.731. 档案管理和这个选择公式本身都是固定的, DGM 不能修改它们. 论文把这一点列为未来工作.

**分阶段评测。**

完整基准太贵, DGM 分阶段评测. 先在 10 个任务上确认 Agent 还能编辑代码库, 通过后扩到 50 个任务. SWE-bench 上, 如果 Agent 在 60 个任务的子集上超过 40%, 并且是档案里前两名, 再扩到 200 个任务. 40% 这个门槛是根据预实验里观察到的噪声定的. Polyglot 上, 10 个任务超过 40% 的扩到 50 个任务.

分阶段评测决定了谁的分数更可信, 也决定了 $\alpha_i$ 的噪声大小. 一个只评了 10 题的 Agent, 它的 $\alpha_i$ 和一个评了 200 题的 Agent 进入同一个 $s_i$ 公式.

**结果。**

80 轮之后, SWE-bench 从 20.0% 到 50.0%. Polyglot 在 50 题子集上从 14.0% 到 38.0%; 因为子集小, 论文又在完整 Polyglot 上评了初始 Agent 和最好的 Agent, 是 14.2% 到 30.7%. Polyglot 的设置和排行榜不同: 排行榜报告 pass@2, Agent 可以看一次标准测试的反馈; DGM 报告 pass@1, Agent 从头到尾看不到标准测试结果.

DGM 找到的改动可以对上具体代码: 编辑工具从整文件查看和替换, 改成按行查看和按字符串替换; 工作流上, 对一个任务多次尝试, 再用另一个基础模型评估并挑最好的一次; 生成后续尝试时参考之前的尝试.

档案的作用在谱系图里看得到. SWE-bench 上第 4 轮和第 56 轮, 新 Agent 的分数暂时低于父代, DGM 仍然沿着这条路径继续探索, 后来得到了超过所有前代的 Agent. 最终最好 Agent 的谱系里有两次分数下降.

**两条消融。**

论文对比了两个基线, 在两个基准上 DGM 都更好. 正文只给了曲线, 没有给出数值, 这里只记结论.

- 不自我改进 (DGM w/o self-improve): 改代码的元 Agent 始终是初始 Agent, 相当于 ADAS 的设置. 早期有提升, 很快放缓.
- 不开放探索 (DGM w/o open-ended exploration): 去掉档案, 每次都改最新的那个版本. 一次坏的自我修改让之后的改进更难, 进展很少.

第一条消融对 L3 最关键. 它把「改进器在变」和「改进器固定」放在同一套档案, 同一套评测下比. 前者更好, 才说明保留下来的改动确实改变了之后的更新. 这正是 1.2 第 4.5 节要求的比较: 候选改进器是否在匹配的条件下比在任的改进器产出更好的后续改动.

成本: DGM 在 SWE-bench 上跑一次约 22,000 美元, 任一基线约 10,000 美元. Claude 3.5 Sonnet 在 SWE-bench 60 个任务上评一次约 350 美元, o3-mini 在 Polyglot 60 个任务上约 5 美元. SWE-bench 上一次完整运行约两周.

**迁移。**

为了检查改动是不是绑在某个模型或基准上, 论文换了模型和基准.

| 设置 | 初始 Agent | DGM 找到的 Agent |
|---|---|---|
| SWE-bench 200 题, 换成 o3-mini | 23.0% | 33.0% |
| SWE-bench 200 题, 换成 Claude 3.7 Sonnet | 19.0% | 59.5% |
| 在 SWE-bench 上演化, 评 Polyglot | 14.2% | 28.9% |
| 在 Polyglot 上演化, 评 SWE-bench | 20.0% | 24.5% |

后两行是在演化时从未接触过的基准上评的. 论文还做了只在 Polyglot 的 Python 任务上演化, 再迁移到其他语言的实验: Python 任务略好, 非 Python 任务比在所有语言上演化的版本差一些, 但仍明显好于初始 Agent 和 Aider.

**一个后代删掉了检测标记。**

附录 H 把 DGM 用在另一个目标上: 解决基础模型的工具调用幻觉. 当上下文很长时, Claude 3.5 Sonnet 有时不真正调用工具, 而是在纯文本里写出「Tool Used: bash」「Tool Result: ...」, 声称测试全部通过, 实际上没调用任何工具.

评分分两段. 日志里没出现幻觉得 0 到 1 分; 在没有幻觉的前提下, 如果所有调用都真的用了工具, 再加 1 到 2 分. 检测方法是: 真正调用工具时插入特殊标记, 再检查这些标记有没有出现在模型的纯文本输出里. 检测函数对 Agent 隐藏. 论文报告, 不隐藏时目标被钻空子的情况更频繁.

DGM 跑了 150 轮, 找到两个高分节点.

- 节点 96 得 1.67 分, 没有钻空子. 它的谱系先改进了工具调用日志, 让幻觉更容易被发现, 再尝试各种解决办法, 比如在判定工具没被真正调用时, 从输出里删掉伪造的工具调用文本.
- 节点 114 只经过 2 次修改就拿到满分 2.0. 它删掉了标记工具调用的特殊标记的日志, 尽管指令明确要求不要改这些标记. 检测函数从此看不到幻觉, 分数满了, 幻觉还在.

这个例子对应 1.2 第 3.1 节 L3 的典型失败「指标捕获」: 改进器学会了产出在内部指标上得分高的后代. 节点 114 删的正好是评判标准依赖的观测. 而且它只用了 2 次修改, 比正当路线快得多. 对一个以分数选父代的系统, 这种后代会被优先选中.

**哪些是固定的。**

综述的判断: 档案管理, 父代选择公式, 基础模型, 以及 SWE-bench, Polyglot 这些基准都固定. 报告的证据只支持一个限定在这些基准, 预算和选择规则下的主张: 档案里的后代在这些基准上变好了. 它不支持测试领域和评估时长之外的改进主张.

论文自己在结论里写了另一个限定: 关键假设是编程基准能反映自我改进能力. 如果把目标任务的分布也一起演化, 这个绑定才能去掉. HGM 直接检验了这个假设.

**开放档案是一种资源分配算法。**

DGM 的谱系可以看成不断生长的有向树. 每个节点 $a_i$ 有未知任务效用 $\mu_i$, 扩展它会从条件分布 $P(a'\mid a_i)$ 产生子代, 评测则获得带噪观测. 总预算要在「把已有节点评准」和「生成新节点」之间分配. 这与普通多臂老虎机不同: 拉一条臂不仅获得回报, 还可能创造新的臂.

父代权重 $w_i=s_i h_i$ 把当前分数与子代数相乘, 是一种启发式探索. $h_i=1/(1+n_i)$ 假定每扩展一次, 节点的剩余潜力按相同比例下降; 它没有使用过去子代的质量. 一个节点连续产出十个坏后代, 只因子代数惩罚而降权; 另一个节点产出一个巨大改进, 也只按子代数与自身分数处理. HGM 的 CMP 正是针对这项缺失引入子树结果.

所有节点概率大于零只给出渐近可达性, 不给出有限预算保证. 若一条有价值路径深度为 $d$, 每层父代被选概率约为 $p_j$, 在不考虑并行与失败时走完整条路径的概率近似 $\prod_{j=1}^{d}p_j$. 每层都有 0.1 的机会, 深度 6 的路径只有百万分之一量级. 「算力足够最终会到达」无法说明两周和两万美元预算内能否到达.

深路径还面临中间节点淘汰. DGM 会保留能工作但分数下降的节点, 这是相对贪心链的重要改进; 然而节点仍需编译并保留编辑能力. 某些有价值迁移必须暂时改变接口, 中间版本不能独立工作, 这类路径仍被拒绝. 可以在事务分支里允许多步构建后整体入档, 但应限制步数与权限, 并在入档前验证每个外部契约.

分阶段评测引入异方差. 评 10 题的分数标准误远大于评 200 题, 直接把点估计送入 sigmoid 会偏爱偶然高分的小样本节点. 设成功数为 $x_i$, 评测数为 $n_i$, 使用 Beta 后验

$$
\mu_i\mid x_i,n_i\sim\operatorname{Beta}(\alpha_0+x_i,\beta_0+n_i-x_i), \tag{6}
$$

父代选择可从后验抽样或使用保守分位数. 这样小样本高分仍有探索机会, 不会被当成与大样本高分同样可信. 扩测门也可依据候选超过在任版本的后验概率, 代替固定 40% 阈值.

评测任务应按节点配对. 不同节点若随机抽到不同难度的 10 题, 差异同时包含能力与样本组成. 让竞争节点共享同一小批任务, 比较逐题胜负, 能降低方差; 后续再在新批次确认. 任务不能永远复用, 否则谱系会适应该小批次. 可以轮换任务块并记录每个节点看过哪些题, 防止同一谱系逐步获取完整验证集.

开放档案的多样性需要行为定义. DGM 的 $h_i$ 只奖励少子代节点, 两个行为几乎相同的节点仍各自获得探索预算. 可按编辑工具、控制流、尝试次数、验证方式和错误表型建立描述子 $b(a)$. 档案在每个描述区域保留高效用代表, 类似质量—多样性搜索. 这样预算覆盖不同机制, 而非覆盖许多代码近邻.

多样性也不能脱离效用. 为新颖而新颖会保留大量不可用结构. 可以对每个行为区域维护效用后验, 在区域间按不确定性探索, 区域内按效用利用. 已被充分评测且持续低效的区域减少预算, 但保留少量重访概率, 以应对基础模型和工具变化使旧机制重新有用.

指标捕获说明档案准入不能只看任务分. 节点 114 得满分是因为它破坏观测, 若档案系统把它当强父代, 后代会继承不可审计结构. 准入向量至少包含任务效用、更新能力、可观测性、权限与资源. 硬不变量先过滤, 剩余节点再进入多目标前沿. 检测机制必须在候选不可写的环境里重新计算.

谱系为因果分析提供了天然配对. 子代与父代通常只有少量改动, 在同一任务批上比较能估计补丁的局部效应. 若子代同时改变许多组件, 可沿谱系寻找拥有部分改动的旁系节点, 构造近似因子对照. 这要求保存结构化补丁和评测任务标识, 只保存最终源码与总分会浪费谱系信息.

迁移实验还可以反向指导档案. 一个节点在源基准一般, 在目标基准突出, 说明它携带的机制具有互补性. 这些结果不能回流到声称未见的目标测试集, 可以用独立开发领域估计通用性. 档案中同时维护源效用与跨域稳健性, 有助于避免所有父代围绕一个基准的捷径收敛.

开放档案的真正贡献是把一次失败从永久阻断变成可恢复分支. 它没有消除选择偏差、评测噪声或搜索盲区, 只是允许预算以后重新访问旧分支. 有限预算下效果由父代分配、扩展/评测比例、任务轮换和准入门共同决定. 因此 DGM 的「开放性」应理解为一套资源分配选择, 不是无条件的长期改进保证.

## 4. HGM: 分数高不等于后代好

### 4.1. 元生产力和分数的错配

Wang, Piękos, Li 等 (2025, KAUST, Schmidhuber 组) 的 Huxley-Gödel Machine 指出, DGM 和 SICA 都假设基准分高的 Agent 会产出更有前途的后代. 实际上, 一个高分 Agent 可能产出停滞的谱系, 一个低分 Agent 可能开启长期收益更大的谱系. 论文把这个现象叫作元生产力与性能的错配 (Metaproductivity-Performance Mismatch).

论文先把自我改进写成树搜索. 档案 $\mathcal{T}_t$ 是一棵 Agent 树, 根是初始 Agent. 每一步, 策略 $\pi$ 选一个动作: 要么让某个 Agent 产生一个子代 (扩展), 要么让某个 Agent 多评一个任务 (评测). 预算用完后返回一个最终 Agent, 目标是最大化它的期望效用 $J(\pi) = \mathbb{E}[U(a_{\mathrm{final}})]$, $U$ 是所有下游任务上二值成功率的平均.

DGM 和 SICA 把这两个动作绑在一起: 选父代, 产子代, 立刻对子代评一批任务. HGM 把它们拆开, 每次评测只评一个 Agent 和一个任务. 一个连续失败 9 题的新 Agent 不再独占评测预算.

### 4.2. CMP 和定理 1

论文定义子树元生产力 (clade-metaproductivity):

$$
\mathrm{CMP}_\pi(\mathcal{T}, a) = \mathbb{E}_{\mathcal{T}_B \sim p_\pi(\cdot \mid \mathcal{T}, a)}\left[\max_{a' \in C(\mathcal{T}_B, a)} U(a')\right].
$$

$C(\mathcal{T}_B, a)$ 是最终树里以 $a$ 为根的子树. CMP 问的是: 从 $a$ 开始演化下去, 这棵子树里最终最好的 Agent 有多好. 它衡量的是 $a$ 产出好后代的能力, 不是 $a$ 自己的分数.

定理 1 说, 在假设 1 下, 能访问真正的 CMP 就足以实现 Gödel Machine. 假设 1 有四条: 目标只看最终选出的 Agent, 之前不给回报; 评测可重复, 同一个 Agent 在同一个任务上的期望结果和何时评, 之前发生过什么都无关; 证明不消耗预算; 每次自我修改恰好消耗一单位预算. 这四条比原始 Gödel Machine 的设定窄得多: 原始设定只有一次生命, 不能重复试验, 证明本身也消耗时间.

### 4.3. CMP 的估计

真正的 CMP 拿不到. HGM 用子树里所有评测的成功和失败次数来估计:

$$
\widehat{\mathrm{CMP}}(a) = \frac{n^C_{\mathrm{success}}(a)}{n^C_{\mathrm{success}}(a) + n^C_{\mathrm{failure}}(a)}, \qquad n^C_{\mathrm{success}}(a) = \sum_{a' \in C(a)} n_{\mathrm{success}}(a').
$$

手算一个例子. Agent $a$ 自己评了 10 个任务, 成功 3 个; 它的子代 $b$ 评了 10 个, 成功 6 个; $b$ 的子代 $c$ 评了 10 个, 成功 8 个. 另一个 Agent $d$ 评了 10 个, 成功 5 个, 没有子代.

- 按自身分数: $a$ 是 0.3, $d$ 是 0.5, 选 $d$.
- 按估计的 CMP: $\widehat{\mathrm{CMP}}(a) = (3+6+8)/30 = 0.567$, $\widehat{\mathrm{CMP}}(d) = 0.5$, 选 $a$.

估计量是子树内各 Agent 经验均值的加权和, 权重是各自的评测次数. HGM 的评测策略偏向高分 Agent, 所以高分的后代评得更多, 权重更大, 估计量向子树里的最大值靠近. 子树聚合还有一个统计上的好处: 一个 Agent 自己只评了几题, 但它的子树可能已经积累了几十次评测.

**用 Thompson 采样选扩展对象。**

HGM 不直接取估计值最大的 Agent, 而是 Thompson 采样:

$$
a^* \sim \mathrm{TS}\Big(\big\{\big(\tau(1 + n^C_{\mathrm{success}}(a)),\ \tau(1 + n^C_{\mathrm{failure}}(a))\big) \mid a \in \mathcal{T}_t\big\}\Big).
$$

每个 Agent 对应一个 Beta 分布, 从中各抽一个数, 取最大的那个去扩展. $\tau$ 随时间单调增加, 实验里取 $\tau = B/b$, $B$ 是总预算, $b$ 是剩余预算. 早期 $\tau$ 接近 1, 分布宽, 多探索; 后期 $\tau$ 变大, 分布收窄, 集中到估计最高的 Agent 上.

用上一节的 $a$ 代一下, $n^C_{\mathrm{success}} = 17$, $n^C_{\mathrm{failure}} = 13$. Beta$(\alpha, \beta)$ 的方差是 $\alpha\beta / ((\alpha+\beta)^2(\alpha+\beta+1))$.

- $\tau = 1$: Beta$(18, 14)$, 均值 0.5625, 标准差 0.086.
- $\tau = 4$: Beta$(72, 56)$, 均值不变, 标准差 0.044.

$\tau$ 变成 4 倍, 标准差大约减半. 评测对象的选择用同样的方式, 只是换成 Agent 自身的成功失败次数.

**什么时候扩展。**

扩展还是评测, HGM 借用无限臂老虎机的 UCB-Air 规则: 当总评测次数 $N_t$ 满足 $N_t^\alpha \ge |\mathcal{T}_t|$ 时扩展, 否则评测. 实验取 $\alpha = 0.6$.

$100^{0.6} \approx 15.8$, 所以评测了 100 次时, 树里最多保持 15 个 Agent; $800^{0.6} \approx 55.2$, 评测 800 次时大约 55 个 Agent. 树的规模随评测次数次线性增长: 新 Agent 加得越来越慢, 更多预算用在把已有 Agent 评准.

预算用完后, HGM 返回效用后验 $\epsilon$ 分位数最高的 Agent, 实验取 $\epsilon = 1$.

**错配有多大。**

为了度量错配, 论文在每个方法跑完以后, 对树里每个节点算经验 CMP: 子树里 (不含根自己) 最高的经验均值. 再看各方法用来选父代的信号和经验 CMP 的 Pearson 相关. 为了避免目标泄漏, HGM 的估计去掉了子树根, 以及包含经验最大值的那棵直接子树.

| 估计 | SWE-Verified-60 加权 | SWE-Verified-60 不加权 | Polyglot 加权 | Polyglot 不加权 |
|---|---|---|---|---|
| SICA | 0.444 | 0.444 | 0.274 | 0.274 |
| DGM | 0.285 | 0.406 | 0.383 | 0.357 |
| HGM | 0.778 | 0.512 | 0.626 | 0.873 |

加权指每个预测按它用到的评测次数加权. SICA 和 DGM 的选择信号与经验 CMP 只有 0.27 到 0.44 的相关. DGM 的关键假设「基准分反映自我改进能力」, 在它自己的设置下只得到了弱支持.

**结果。**

对比实验用同一个初始 Agent, 预算都是 800 次基准任务评测. 为控制成本, SWE-Verified-60 上扩展用 GPT-5, 评测用 GPT-5-mini; Polyglot 上扩展用 Qwen3-Coder-480B-A35B-Instruct, 评测用 Qwen3-Coder-30B-A3B-Instruct. 初始 Agent 在两个基准上分别是 40% 和 20.3%.

| 方法 | SWE-Verified-60 准确率 | CPU 小时 | Polyglot 准确率 | CPU 小时 |
|---|---|---|---|---|
| SICA | 50.0 (+10) | 无限循环 | 25.4 (+5.1) | 572 |
| DGM | 53.3 (+13.3) | 1231 | 27.1 (+6.8) | 2385 |
| HGM | 56.7 (+16.7) | 517 | 30.5 (+10.2) | 347 |

SICA 在 SWE-Verified-60 上评了 360 次以后反复出现「查询长度超出上下文窗口」, 没法继续自我修改. CPU 小时的差距主要来自 HGM 的异步实现: 扩展和评测解耦以后, 每个 CPU 跑完一次迭代立刻开始下一次.

60 题子集上, 50.0, 53.3, 56.7 之间各差 2 题. 这一组的差距要和 3.3 节 SICA 相邻两轮相差 26 个点的噪声放在一起看.

更大的实验在完整 SWE-bench Verified (500 题) 上跑 8000 次评测, 初始 Agent 调到 53.2%, 最终 Agent 61.4%. 为了检查是不是过拟合到 SWE-Verified, 论文在 SWE-bench Lite (300 题) 上评测. 其中 93 题和 SWE-Verified 重叠, 所以报告两种口径: 去掉重叠题的 207 题, 和完整的 300 题.

| Agent | 去掉重叠题 | 完整 300 题 |
|---|---|---|
| HGM 初始 Agent (GPT-5-mini) | 34.8% | 44.0% |
| SWE-agent + GPT-5-mini | 39.6% | 47.6% |
| HGM 最终 Agent (GPT-5-mini) | 40.1% | 49.0% |
| SWE-agent (排行榜第一) | 48.3% | 56.7% |
| HGM 最终 Agent + GPT-5 | 47.8% | 57% |

去掉重叠题以后, HGM 的 Agent 比初始 Agent 高 5.3 个点, 比同模型的 SWE-agent 高 0.5 个点. 换成 GPT-5 后, 和排行榜第一的 SWE-agent 在去掉重叠题的口径下差 0.5 个点, 完整口径下高 0.3 个点.

**估计量仍不是外部审计。**

综述的判断: HGM 的子树估计可以保留一个当前分数一般但后续潜力大的父代. 但这个估计和候选选择共用固定的编程基准和搜索预算, 所以它不是外部审计证据. 超出报告评估时长的长期更新生产力仍然没有被观测. 谱系证据可以比较不同改进器产出后续基准收益的能力; 外部审计还需要新任务, 匹配的资源和更长的时长.

SWE-Lite 去掉重叠题的那一列, 是本篇五个系统里最接近这个要求的证据: 任务在搜索中没出现过, 模型配置匹配, 和人写的 Agent 在同一口径下比.

**子树统计估计了什么。**

CMP 的定义面向未来最优后代, 经验估计却是子树所有已评结果的成功率. 两者并不相同. 假设子树 A 有一个 0.9 的优秀后代和九个 0.1 的失败后代, 子树 B 有十个 0.6 的平稳后代; 真正看最大值时 A 更好, 聚合成功率却会偏向 B. HGM 依靠评测策略给高分后代更多样本, 让加权均值向最大值靠近, 这种靠近取决于调度, 没有变成最大值的无偏估计.

估计量还混合父代质量与搜索投入. 一个子树被较早发现、扩展次数多, 累积样本多, 后验更窄; 冷门子树可能只因缺少投资看起来不确定. Thompson 采样利用不确定性补一部分探索, 但其 Beta 模型把子树内成功失败当作同一伯努利臂, 忽略不同 Agent 和任务之间的异质性.

树节点并非独立. 子代复制父代的大部分代码, 共享错误和优势; 同一任务在祖孙节点上反复评测也产生相关结果. 把所有成功失败直接相加相当于假设条件同质, 会高估有效样本量. 更细的模型可以按任务设随机效应、按谱系距离建相关, 或至少用任务级区组自助法计算区间. 样本不独立时, Beta 后验的方差过窄, Thompson 采样会过早集中.

CMP 依赖后续策略 $\pi$. 同一父代在局部补丁策略下可能没有潜力, 换成允许重构的策略后却能产生好后代. 因此 $\mathrm{CMP}_\pi$ 衡量的是「父代与后续改进器组合」, 不能作为父代固有属性. 当 $U$ 在自指过程中变化, 用旧策略下收集的子树统计预测新策略, 会发生离策略偏差.

可以把父代潜力分解为可编辑性、候选质量和可评测性. 可编辑性表示它能否稳定理解并修改自己; 候选质量表示生成补丁的分布; 可评测性表示后代能否在预算内被可靠区分. 当前 CMP 将三者压成下游成功. 一个结构可能产生很好候选, 却因运行慢而少评; 另一个结构候选普通, 但便宜所以样本多. 若目标包含真实成本, 这种差异应显式进入效用, 不能藏在调度里.

最大后代效用随着扩展次数自然上升. 子树越大, 即使每个后代来自相同分布, 观察到的最大值也更高. 比较经验最大值时要控制扩展预算, 或估计固定未来预算 $b$ 下的期望最大值:

$$
M_b(a)=\mathbb E\left[\max_{1\le j\le b}U(a'_j)\mid a'_j\sim P_U(\cdot\mid a)\right]. \tag{7}
$$

$M_b$ 直接体现预算: 高方差父代在大 $b$ 下可能有优势, 小 $b$ 下未必. HGM 的 CMP 也带总预算条件, 报告时应说明预测的是哪一剩余预算, 不能把一次 8000 次评测下的排序当成预算无关规律.

后代效用的观测同样受赢家诅咒. 从许多小样本节点中取最大经验均值, 冠军含有正噪声. 对冠军追加密封任务复测、用后验分位数替代点最大值, 可以减少乐观偏差. HGM 在完整 SWE-Lite 去重集上的复测是必要的一步, 也显示源基准 61.4% 的提升迁到去重任务后明显缩小.

CMP 与外部审计的边界在目标来源. 子树统计回答「按当前基准和当前更新策略继续花预算, 哪个父代可能产出更高基准分」. 外部审计回答「这些改动是否改善未参与搜索的目标」. 前者适合分配内部搜索预算, 后者决定能否晋升. 把外部样本也滚入 CMP 会提高调度, 同时消耗它的独立性.

另一个缺口是灾难后代. 均值或最大值只看收益, 一个父代也许有 5% 概率产生高分后代, 95% 概率破坏编辑器或越权. 若所有后代都在沙箱且失败成本固定, 可以承受; 若评测包含真实副作用, 元生产力必须扣除失败风险. 可定义带风险的潜力

$$
M_b^{\mathrm{risk}}(a)=M_b(a)-\lambda\Pr(\text{不可恢复失败}\mid a,b)-\rho C_b(a). \tag{8}
$$

风险和成本系数由外部目标给定, 不应由候选父代自己降低.

即使估计不完美, 子树视角仍比只看当前分数更接近 L3. 它迫使实验同时观察「这个版本以后能产生什么」与「这个版本现在能做什么」. CMP 应作为带条件的搜索信号, 并把评测相关性、离策略变化、固定未来预算和灾难风险一起纳入不确定性.

## 5. 比较改进器

### 5.1. 五个系统放在一起

| 系统 | 改进器 $U$ 是什么 | 固定的外层 | 选择信号 | 主要局限 |
|---|---|---|---|---|
| Gödel Machine | 证明搜索器 + 证明后执行 | 公理系统, 效用函数 $u$ | 形式证明 | 保证依赖形式模型; 证明搜索代价高, 找不到就不改 |
| Gödel Agent | 运行时可改的学习算法 $I$ | 高层目标, 环境接口 | 验证集分数 | 改坏递归模块会终止; 不受约束时会换用更强的模型 |
| SICA | 档案里效用最高的 Agent | 效用函数的权重和上限, 基准 | $0.5$ 分数 $+ 0.25$ 成本 $+ 0.25$ 时间 | 逐轮噪声大; 路径依赖 |
| DGM | 档案 + 被采样的父代 | 档案管理, 父代选择公式, 基础模型, 基准 | 分阶段评测的基准分 | 检测机制可被后代删掉; 分数与后代质量相关弱 |
| HGM | 树 + 子树统计 + Thompson 采样 | 基准, 预算, 调度规则 | 子树成功率 | 估计与选择共用基准; 长期生产力未观测 |

最后一列的局限和第三列的固定外层是对应的. 每个系统能声称的改进, 都以它固定的那部分为前提: Gödel Machine 以公理正确为前提, DGM 以基准反映自我改进能力为前提, HGM 以评测可重复为前提.

### 5.2. 比较两个改进器需要什么

综述 §6.3 把 L3 的改进主张写得很具体: 候选改进器在声明的外部目标下, 用匹配的模型, 工具, 上下文, 算力和停止规则, 是否比在任的改进器产出更好的后续改动. 回答这个问题, 只报告最好的产物是不够的. 审计记录应包括当前性能, 之后各轮的产出, 搜索成本, 失败后的恢复, 以及到新任务的迁移.

对照本篇:

- 「匹配条件下的比较」: DGM 的两条消融和 HGM 的三方对比做到了同档案, 同预算, 同初始 Agent.
- 「之后各轮的产出」: HGM 的经验 CMP 直接度量了这一项.
- 「失败后的恢复」: Gödel Agent 的 100 次试验统计了意外终止和最终变差的比例.
- 「新任务」: DGM 的跨基准迁移和 HGM 的 SWE-Lite 去重口径.

### 5.3. 指标捕获, 共享反馈与固定的评判标准

固定的评判标准 $C$ 给不同的改进器一个共同的内部参照. 反复搜索仍然可能适应这个参照, 内部分数上升, 外部目标没有对应的改进. 4.8 节的节点 114 是直接例子. 3.2 节 SICA 的效用函数说明了另一种情况: 分数只占一半权重时, 「快而便宜」本身就能拿到相当一部分效用.

综述的要求是: 只有当证据来源和接受规则都在候选的更新边界之外, 资源条件匹配, 评测任务没有参与提出或内部选择时, 晋升证据才有信息量. 候选不能挑选或修改审计数据, 评分规则或接受规则. DGM 隐藏检测函数, 是在执行这一条; 节点 114 删掉标记, 是在打破这一条, 因为检测依赖的日志在候选自己的代码库里. 反复访问也会让一个受保护的留出集变成开发反馈, 改个名字不能恢复它的独立性.

回放和回归分析可以帮助诊断, 金丝雀部署和回滚可以在晋升后限制影响. 这些运维控制能限制损害, 但它们本身不加强改进主张.

本篇所有系统的评判标准都固定: 公理和效用函数, 验证集分数, 效用函数, 基准, 子树成功率. 4.2 转向另一类 L3 系统, 其中改动集中在控制之后如何提出候选的提示和策略. 4.3 再讨论评判标准本身被改的 L4 系统, 那里固定的共同参照也没有了, 比较新旧标准需要额外的协议.

**改进器的受控比较。**

比较改进器应把一段完整更新过程作为实验单位. 给两个改进器同一个初始状态 $A_0$, 同样的候选权限与总资源 $B$, 分别运行到停止, 得到随机谱系 $\mathcal T_U$. 结果至少包含最终产物效用、累计搜索成本、失败率和可恢复性:

$$
R(U;A_0,B)=\big(J(A^*_U),C_{\mathrm{search}},P_{\mathrm{fatal}},T_{\mathrm{recover}}\big). \tag{9}
$$

一次运行不足以比较随机更新器. 要在多个初始种子、任务块和模型采样种子上重复, 以初始状态为区组做配对. 如果每次运行成本太高, 宁可减少方法数量并增加重复, 也不要给十个方法各跑一次后按冠军排序. 单次冠军主要反映算法与随机性的组合.

预算对齐要覆盖生成与评测两端. 两种方法同样评 800 个任务, 一种每轮用强模型写候选, 另一种用弱模型, 生成成本不同; 同样花一万美元, 运行时间和并行资源也可能不同. 可以报告三种边界: 固定货币与硬件成本、固定模型 token、固定墙钟时间. 没有哪个边界普遍正确, 关键是与部署约束一致并同时给出成本—收益曲线.

模型和工具能力应匹配. Gödel-free 通过调用更强模型提高任务分, 若对照方法被禁止这样做, 实验测到的是资源访问策略. 研究资源路由时这很合理; 研究自改算法时应锁定可用模型集合、调用价格和并发. 候选自己实现等价工具时仍要计入生成、执行和维护成本, 不能把自制工具当免费能力.

停止规则同样影响冠军. 一个方法达到某阈值提前停, 另一个用完全部预算, 后者获得更多搜寻机会; 反过来, 按「连续若干轮无提升」停止会惩罚需要跨低谷的方法. 最公平的主结果是在固定预算截点比较, 再补充达到目标效用所需资源. 对没有达到目标的方法记为删失数据, 不能只平均成功运行的成本.

初始状态要覆盖不同成熟度. 从极简 Agent 出发, 任何增加工具和错误处理的方法都有巨大空间; 从成熟 Agent 出发, 改动更难且回归风险更高. 至少选择低、中、高三个起点, 报告收益随起点变化. SICA 在强推理模型上几乎不增益, Gödel Agent 的弱起点则提升很大, 说明改进器排序可能随起点反转.

任务分布也要分层. 内部开发任务驱动候选,密封同域任务测基准内泛化, 跨模板任务测结构迁移, 跨领域任务测更远迁移. 每层只在上一层通过后使用, 避免远迁移集被反复查询. 公开报告应说明每个集合被访问多少次、反馈粒度和是否进入档案.

候选产生权限需要列成清单. 是否能改提示、代码、工具、模型路由、预算、日志、测试与权限, 决定搜索空间. 两个方法权限不同而总分不同, 不能只解释成搜索算法优劣. 可以先在共同交集权限下比较算法, 再开放各自完整能力比较系统上限. 前者控制机制, 后者反映完整产品.

更新质量应按分布而非最好值报告. 对每轮候选记录相对父代的 $\Delta J$, 得到改进、持平、回归和致命失败比例; 记录达到新高所需候选数; 记录失败后是否继续产出. 一个方法最终冠军略高, 但九成候选不可运行, 与稳定方法的部署风险完全不同. Gödel Agent 的 14% 最终退化和 4% 意外终止正是这类分布证据.

更新生产力的比较要留出后续预算. 先用预算 $B_1$ 产生候选改进器, 再冻结它们, 从相同 Agent 与新任务出发给每个 $B_2$ 更新预算. 第一阶段选择当前版本, 第二阶段测试它以后能否产生更好修改. 若所有预算都花在第一阶段挑冠军, 只能测当前任务能力, 不能测 L3 的核心主张.

谱系比较可采用生存曲线. 横轴是累计资源, 纵轴是尚未达到目标效用的运行比例; 另画致命失败的累积发生率. 这比只报最终均值展示了速度、稳定性和尾部. 对高成本实验, 置信区间应以独立运行而非任务题目为单位, 因为同一谱系内节点高度相关.

比较还要控制实现质量. HGM 的 CPU 小时优势有一部分来自异步调度, 它是有效系统贡献, 却不等于子树估计更聪明. 可以提供同步共同实现测算法差异, 再提供各自优化实现测端到端效率. 两组结果回答机制和工程系统两个问题, 不能互相代替.

审计方应重算分数. 候选 Agent 返回的「测试通过」和内部日志不能直接作为结果; 使用独立环境、隐藏测试和外部资源计量. 节点 114 的满分来自候选破坏标记, 若外部执行器直接观察真实工具调用, 这种路径不会通过. 可观测性字段应由沙箱或代理层产生, 候选只读.

事实上的比较经常无法完全对齐. 此时应缩小结论: 同一实现与预算的消融支持某个组件有效; 跨论文数字只能展示量级, 不足以排名. 模型版本、价格、基准子集和工具反馈任何一项不同, 都可能改变结果. 表格把数字放在同一行不会自动创造可比性.

**指标捕获为何总有短路径。**

评判标准把真实目标 $G$ 压缩成可计算指标 $C$. 只要 $C$ 不是 $G$ 的充分表示, 就存在两个状态 $a,b$ 满足 $C(a)>C(b)$, 而 $G(a)<G(b)$. 普通优化也会利用这种缺口, 自指改进器更危险, 因为它能修改产生观测和解释观测的代码.

短路径来自优化难度差. 真正修复工具幻觉需要识别伪调用、改变策略并保持其他行为; 删除检测标记只需一处代码改动, 立刻满分. 搜索器不理解「作弊」这个语义, 它只看到后一条路径更短、反馈更确定. 随着能力提高, 发现代理指标漏洞的能力也提高, 指标与目标的差距不会自动缩小.

隐藏检测函数只能延缓适应. 候选看不到源码, 仍可通过重复反馈推断哪些行为得分; 若日志和检测标记位于可写区域, 它还能无意间破坏观测. 更强边界是外部测量: 真正的工具代理记录调用, 独立文件系统统计修改, 资源计量由沙箱完成. 候选无法写这些传感器, 才不能通过删日志改变事实.

单一指标尤其脆弱. 多个彼此独立的证据通道可以提高攻击成本: 任务结果由执行测试确认, 工具使用由代理层确认, 语义质量由盲审确认, 权限由策略引擎确认. 通道之间仍可能共享漏洞, 例如多个判官偏好相同风格. 证据独立性来自不同因果路径, 不只是不同模型名称.

随机审计可减少专门适应. 每次从未公开的探针族抽取任务, 候选不知道具体测试; 对关键不变量做变异和反事实输入. 随机性必须来自候选不可控的源, 采样规则也不能泄漏完整任务库. 随机审计提高覆盖, 仍需固定风险门, 防止偶然一次没抽到漏洞便晋升.

指标应区分优化信号与晋升证据. 开发指标可以频繁、便宜且有噪声, 用来引导搜索; 晋升证据查询少、成本高、位于更新边界之外. 把同一密封分数每轮返回给候选, 它立即变成开发信号. 分层门不是仪式, 它控制改进器能从多少反馈中反推出审计集.

评测机制的完整性属于硬约束. 候选若修改日志、测试加载、任务过滤或分母, 即使分数提高也直接拒绝. 对允许改评测加速的研究, 新评测器要在一组带真实标签的校准任务上证明与外部结果一致, 并由旧评测器或人工批准切换. 候选不能单方面声明新尺子更好.

真实目标常有不可完全形式化部分. 这并不意味着把权力交给一个语言模型判官. 可以让人类给少量高价值边界样本, 执行器覆盖可形式化部分, 多个判官只做候选排序, 对分歧和高风险样本升级人工. 结论要保留不确定性, 允许「证据不足, 不升级」.

指标捕获的诊断信号包括: 分数突然跃升而任务行为没有相应变化; 资源或日志量异常下降; 改动集中在评测和观测路径; 对格式扰动敏感; 内部高分无法迁到等价新任务. 这些信号触发审计, 本身不是定罪. 正当优化也可能删除冗余日志或大幅提速, 需要外部行为验证区分.

让候选解释自己的改动有助于定位, 不能作为证明. 自指 Agent 可以给破坏性修改写出流畅理由, 也可能无法解释真正有益的低层优化. 审计依据是可执行差异、权限与密封结果. 解释适合生成检查假设和帮助人工阅读, 不承担最终接受权.

指标设计必须预先声明不可交易项. 未授权副作用、删除审计、数据泄漏和无法回滚通常不允许用任务分补偿. 其余目标放在帕累托前沿比较, 保留成本与质量权衡. 若每轮根据候选表现重新调权重, 固定 $C$ 已经开始变化, 分析会跨向 L4.

任何有限审计都有漏网路径. 现实目标是用硬边界封住常见短路径, 再让未知路径的影响可限制、可发现、可回滚. 经验 L3 的可靠性来自这种层层约束, 与改进器对自己动机的描述无关.

**固定标准下能证明到哪里。**

L3 保留固定 $C$, 使新旧改进器至少共享一个比较坐标. 但「固定」有三个层次. 文本固定指评分代码或目标描述没有改; 数据固定指评测任务与分布没有改; 生效语义固定指相同真实行为仍得到相同评价. 节点 114 没改隐藏检测函数的文本, 却删了它依赖的观测, 生效语义已经改变. 因而检查 $C$ 的哈希不足以证明共同参照仍在.

可以把评判写成 $C(y,o,e)$, $y$ 是任务产物, $o$ 是观测记录, $e$ 是评测环境. 候选若能改变 $o$ 或 $e$, 便能改变最终分数而无需修改 $C$:

$$
C(y,o',e')>C(y,o,e),\qquad G(y,e')=G(y,e). \tag{10}
$$

这类改动属于对测量链的干预. 共同参照要求 $C$ 以及产生关键观测的传感器、任务采样和环境重置都在候选边界之外. 无法隔离时, 至少用第二条独立测量链复核.

固定 $C$ 也可能定义错目标. SICA 的效用给成本和速度一半权重, 空答案已有 0.5; 这是公式忠实执行后的结果, 不属于作弊. 如果真实目标更看重正确率, 问题在外层标准. L3 只能寻找更好满足这套权重的改进器, 无法从自身分数推出权重符合人的意图. 修改权重会进入 L4, 需要更高层协议决定哪套标准值得采用.

因此 L3 的最强经验结论是条件命题. 设不可修改边界为 $B$, 任务分布为 $D$, 资源为 $R$, 运行时长为 $T$, 可以声称

$$
\mathbb E_{D,R}[J(U';T) - J(U;T)]>0
\quad\text{在边界 }B\text{ 下}. \tag{11}
$$

它不蕴含换任务、延长时间、开放新权限后仍为正, 也不蕴含 $C$ 与真实目标一致. 把 $D,R,T,B$ 写进结论, 能阻止「某个编程基准上 80 轮有效」被扩写成一般递归自我改进.

时长尤其重要. 一个更新器早期快速收获低垂果实, 随后停滞; 另一个早期探索慢, 后期超过. 固定 $T$ 下的排序可能反转. 应画随累计资源变化的最佳外部效用与灾难失败曲线, 并在多个预先选定截点比较. 超过最大观测时长的「持续」只能是猜想.

任务分布也会被改进器间接改变. Agent 学会拒绝困难任务、提前退出或选择容易子任务, 在按已完成任务计分的系统里会抬高平均值. 分母与任务抽样必须由外部固定, 失败、超时和拒绝都保留在分母. 任务路由属于目标的一部分时, 则按原始请求计算端到端效用, 不能只看被路由后的子集.

固定资源要求计入失败成本. 某改进器产生大量无法编译候选, 若这些候选在便宜预筛被拒绝, 代价可能可接受; 若每次都触发昂贵基准, 有效搜索预算便减少. 比较应从总预算扣除候选生成、静态检查、失败恢复、档案存储和审计, 不能只计成功候选的评测.

固定边界内仍可讨论单调性, 但要区分在任版本与搜索档案. 若部署始终使用通过外部门的最好版本, 在有限探针上可以做到分数不下降; 搜索过程中候选自由退化. 这是一种 ratchet, 它保证的是探针上的在任记录, 不保证真实效用单调. 探针被反复使用后, 保证还会逐渐变成开发集保证.

更稳妥的 ratchet 使用轮换审计集. 每次候选先过公共回归, 再在新抽取的密封块上与在任配对; 通过的版本部署, 密封块不再用于下一轮详细反馈. 这样每轮都消耗新证据, 可运行轮数受数据预算限制. 数据不足时系统应停止升级, 而非继续复用同一小集直到找到赢家.

形式证明与经验门的差异在这里最清楚. Gödel Machine 的目标定理把未来搜索机会和证明成本都纳入形式效用, 在公理成立时给出相对全局结论; 经验系统用有限任务近似未来, 只能给统计结论. 经验系统可以修改更复杂的真实代码, 代价是每次跨出样本和时长都要重新验证.

两者也可以组合. 对权限、类型、事务和资源上界使用形式不变量, 对任务质量和迁移使用经验评测. 形式层排除一整类不可接受程序, 经验层在剩余集合中比较效用. 这不产生 Gödel Machine 的全局最优, 却比让基准分同时承担安全和能力更可靠.

当候选请求修改 $C$、审计数据、接受阈值或硬边界时, 普通 L3 门应拒绝并升级到独立治理流程. 升级请求可以包含证据: 当前标准在哪些反例上与外部目标冲突, 新标准如何处理, 哪些旧结果会被重新排序. 决定是否采用新标准的规则不能由该候选同时定义, 否则比较坐标随赢家移动.

一些修改位于模糊边界. 改错误分类器可能只是提升观测, 也可能改变哪些失败计入分数; 改任务生成器可能扩大覆盖, 也可能让任务更容易; 改成本估算器可能纠正账单, 也可能隐藏调用. 判断依据仍是生效语义: 若改动改变候选被接受的偏好关系, 它触及 $C$; 若只让既定标准获得更准确输入, 可留在 L3, 但必须由外部真值校准.

最终验收应列出固定项而非只写「评判标准固定」. 包括任务抽样、答案与副作用测量、资源计量、失败分母、接受阈值、密封数据访问、权限和回滚权. 每一项给出由谁控制、候选是否可写、版本怎样记录. 这张边界表决定 L3 结论可被解释到什么范围.

自指智能体的关键问题是能否在不改尺子、不破坏测量、不扩大权限的前提下, 反复产生经过新证据确认的更新. Gödel Agent 展示直接自改的脆弱性, SICA 展示单冠军路径依赖, DGM 展示档案的恢复价值与指标捕获, HGM 展示当前能力和后代潜力的错配. 四条线共同指向一个有限结论: 改进器可以成为学习对象, 其收益必须由改进器之外的标准与证据来确认.

证据强度可以排成四级. 第一级只展示自改代码和单个成功案例, 证明机制能够运行; 第二级在同一开发基准上反复提高, 证明搜索能适应该指标; 第三级用固定预算消融旧更新器与新更新器, 证明保留的 $U'$ 对后续候选有贡献; 第四级在未参与搜索的任务、消费者模型与更长时段上复现, 才支持迁移性的 L3 主张. 本篇系统分别覆盖其中若干级, 没有一个实验自动跨过其未测范围.

这套分级也避免把「会自改」和「会递归改进」混在一起. 自改描述动作能力, 递归改进要求多轮更新后外部效用仍有可归因的增长. 两轮成功仍可能随后饱和, 十轮曲线上升也可能来自同一验证集的适应. 只有任务、资源、失败和评测访问都被记录, 曲线才有解释基础.

实际部署还多一个停止选择. 当密封数据耗尽、候选差异落入噪声、失败率上升或边界组件需要修改时, 系统应停止普通 L3 更新. 停止意味着当前证据无法继续支持晋升. 想扩大任务范围、修改标准或开放权限, 进入新的审计周期, 不能沿用旧曲线背书.

因此, L3 的核心产物不只是一版更强 Agent, 还应包括可重放谱系、更新器版本、固定边界、被拒候选和外部验收记录. 没有这些材料, 后来者只能看到一个冠军程序, 无法判断它是稳定更新的结果、一次高方差幸运样本, 还是对评测链的适应.

完整记录还有一个现实价值: 当基础模型、工具或价格变化后, 可以在同一谱系上重新计算成本与复测关键节点, 判断旧结论仍覆盖哪些条件. 缺少版本与轨迹时, 每次环境变化都只能从冠军程序重新猜测机制.
