# GPT-Red：安全红队自博弈与独立评测边界

一句话结论：GPT-Red 把自动红队做成可扩展的攻击者—防御者训练循环，能为后继模型产生更难的对抗数据；论文所说的 safety flywheel 是一条由人设计并运行的安全训练流水线，不是改进器已经进入后继系统的完整 RSI。

> **论文**：[OpenAI《GPT-Red: Automated Red Teaming via Self-Play at Scale》](https://cdn.openai.com/pdf/gpt-red-automated-red-teaming-via-self-play-at-scale.pdf)（2026-07-15；28 页；核对日期 2026-09-01）
> **官方说明**：[GPT-Red: Unlocking Self-Improvement for Robustness](https://openai.com/index/unlocking-self-improvement-gpt-red/)（2026-07-15）
> 本篇只使用上述 OpenAI 一手材料；数字以论文图表和正文为准。

## 1. 威胁模型先于攻击分数

论文研究两类主要攻击面：直接或聊天式 prompt injection，以及出现在网页、工具输出、检索文档和本地文件中的间接 prompt injection；训练环境也覆盖内容政策越狱。攻击目标不是抽象的“让模型说错话”，而是在给定 Agent 任务中诱导越权、泄露模拟敏感数据、运行不可信代码或执行破坏性动作。

GPT-Red 的权限被明确限制：通常只能修改一次工具响应，或修改防御者轨迹中的一小组非特权文件；不能改用户的 `AGENTS.md` 等特权内容。攻击者看到最近用户消息、待注入的原始工具响应或文件片段，并通过有限次数的黑盒查询试探防御模型。攻击提交后，由程序检查和 LLM 检查共同约束格式、长度和可控区域；越过威胁模型的“攻击”应被拒绝而不是计为成功。

这条边界很重要。若攻击者能直接改系统提示、评分器或特权文件，攻击成功率只会证明实验夹具失守，不会证明发现了现实攻击。论文也承认自动约束依赖定性检查，不能把“检查器通过”读成形式化安全证明。

## 2. 攻击者与防御者不是同一个角色

基础博弈包含两个目标相反的种群：攻击者因诱发有效失败而获奖；防御者因抵抗攻击并完成原任务而获奖。防御者变强后，旧攻击失效，迫使攻击者寻找新策略；攻击者变强又为防御训练提供更难数据。

攻击者还运行在 Agentic Harness 中：终端用于生成或编辑攻击文件，`defender_model` 工具把候选注入预定位置并返回防御轨迹、token 对数似然与 judge 信号。顺序查询允许它根据上一次失败继续改攻击，而不是只做相互独立的 best-of-N 采样。

只对单个 defender 训练容易让攻击模式坍缩。论文的预实验用九个冻结 defender 展示：针对某个模型发现的攻击不总能迁移到另八个模型；大规模训练因此使用多样 defender 群体，促使攻击者先识别目标弱点，再选择策略。这是“多种群”的作用，不是把一个模型上一轮输出直接当下一轮唯一对手。

## 3. 留出评测测了什么

论文没有只报告训练内攻击成功率，而是从四个方向留出：

| 留出对象 | 论文做法 | 能支持的结论 |
|---|---|---|
| 红队场景与人类攻击 | 在 2025 Q4 间接 prompt injection challenge 的内部镜像上重做攻击；场景与目标不同于 GPT-Red 训练集 | GPT-Red 能迁移到一组未见场景；官方页面报告场景成功率 84%，人类红队为 13% |
| 目标模型与 Harness | 回放到未参与训练的 GPT 版本，并在不同红队 Harness 中测试 | 攻击策略不只记住一个 defender 或一个交互壳 |
| 数据集与领域 | 每个高层领域留出一个数据集，并完整留出 Agentic coding 领域 | GPT-5.6 的防御增益可跨到部分未训练分布 |
| 攻击类别 | 将较强的一半 GPT-Red 攻击留作评测，并加入人工攻击与外部 TensorTrust | 防御不是只在最弱训练攻击上得分 |

另外，GPT-Red 在 10 个留出的 Codex CLI 数据外泄情景上与使用同一 Harness 的冻结 GPT-5.5 比较，每个攻击者从三个独立初始状态运行。论文结论是 GPT-Red 在难题上继续取得进展，而基线较早停滞；这组内部小样本说明 Harness 迁移，但不能替代公开、可复现的大规模安全基准。

## 4. 防御训练与验收不能混成一个数字

GPT-Red 生成的攻击被加入 GPT-5.6 的 RL 安全训练，同时也用于评测。为减少同源污染，论文额外留出强攻击、数据集、领域、红队练习和人工攻击，并同时检查一般能力与过度拒答。官方材料报告 GPT-5.6 在多组留出上提高鲁棒性，但有三项口径必须保留：

1. 自动 IPI 红队练习没有加入系统级缓解，因此作者明确说它会高估现实攻击成功率。
2. 评测含标签噪声、固有歧义和奖励噪声，部分任务无法达到满分。
3. “GPT-Red 胜过人类”只适用于这组预先规定的环境；论文脚注明确说，人类仍可能发现 GPT-Red 没覆盖的新场景或新攻击类别。

因此，held-out 是比训练内曲线更强的证据，但不是普适安全证明。模型、Harness、监控、权限和真实攻击者变化后仍需重新验收。

## 5. 作者写明的局限

论文结论列出三块训练不足：多模态环境、多轮攻击和内容政策越狱。多数关键数据来自 OpenAI 内部模型、内部镜像和生产 Harness，外部读者无法用公开材料完整复现。攻击有效性还依赖自动 judge 和威胁模型约束；约束遗漏会把无效越权误算成攻击，judge 漏判则会错过真实失败。

GPT-Red 被保留为内部专用攻击模型，不向生产用户部署。这样能把专门训练的恶意能力与生产模型分开，但也意味着外部审计只能核对公开论文描述，不能独立检查训练数据、模型权重和完整失败样本。

## 6. Safety flywheel 为什么不等于完整 RSI

OpenAI 把该流程称为安全飞轮：今天的 GPT-Red 产生攻击，帮助训练明天更稳健的 GPT；更强 defender 又可能为未来 red-teamer 提供更难信号。这是可重复的组织级改进循环，确实比一次性红队更接近持续自改进。

但按本库的 RSI 判定，以下部分仍在更新边界外：威胁模型、可控文件范围、攻击目标、奖励函数、defender 群体选择、训练预算、held-out 划分、是否接受模型、何时训练下一版 GPT-Red。论文没有证明后继系统会自主修改并验收这些改进手续，也没有证明评价标准本身在独立监督下递归升级。

所以最稳妥的落点是：**GPT-Red 是带对抗共进化和留出评测的安全训练飞轮；它提供 RSI 安全工程的重要组件，但不是完整 RSI 的实证。** 进一步的可靠性判定见 [10.3 可靠性与独立监督](../10.3-可靠性与独立监督/10.3-可靠性与独立监督.md)，自对弈结构与 [2.1.1 SPIN](../../02-模型自改进与自训练/2.1-自生成数据与自奖励/2.1.1-SPIN-自对弈微调/2.1.1-SPIN-自对弈微调.md) 不应混为一类。
