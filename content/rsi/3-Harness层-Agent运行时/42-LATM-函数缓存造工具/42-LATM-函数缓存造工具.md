# 42 LATM：函数会缓存，提示冻着

摘要写 closed-loop，还写 LLM 给自己造可复用工具。人把 loop 听成改进器在升级。打开 Table 2：会涨的是某一类请求上的 Python 函数；造函数的提示、核验手续、调度提示都还在。GPT-4 当制造者、GPT-3.5 Turbo 当使用者，六个任务上 79.7 / 99.6 / 92.2 / 98.3 / 100.0 / 100.0，相对同表 CoT 分别多 13.3 / 38.0 / 71.8 / 39.1 / 100.0 / 81.1 个百分点。中国剩余定理上 CoT 两边都是 **0.0**，LATM **100.0**。GPT-4 自己当用户时，逻辑演绎五物体 LATM **86.6** 低于 CoT **88.8**。变的是函数缓存和本题调用。提议函数的提示、核验时只改调用不改函数、包装提示、调度提示冻着。

本篇夹在 [Voyager](../10-Voyager-Minecraft技能库/10-Voyager-Minecraft技能库.md)、[AWM](../35-AWM-工作流记忆/35-AWM-工作流记忆.md) 和 [ReAct](../29-ReAct-推理与动作/29-ReAct-推理与动作.md) 旁边。综述把造工具写成 CREATOR / LATM。Voyager 把 Minecraft 技能写成 JavaScript；这边把 Big-Bench 一类题写成标准库 Python。AWM 留下网页子程序；这边留下函数 API。ReAct 的轨迹随题清空；这边同类请求复用同一份函数。四套数字禁止横加。**不是** RSI。**不是** 术语式 (2)。CREATOR 的 MATH **59.7%** 是另一张表、另一套分母，不要改这边的 79.7。一手：Cai, Wang, Ma, Chen, Zhou；Google DeepMind / 普林斯顿 / 斯坦福；[arXiv:2305.17126](https://arxiv.org/abs/2305.17126)，**ICLR 2024**。代码 [ctlllll/LLM-ToolMaker](https://github.com/ctlllll/LLM-ToolMaker)。数字以会议 PDF Table 2–5、§3–§5、附录 C 提示为准。禁止用手抄 Figure 3 的排列搜索去改 79.7。禁止和 Voyager 的 63 种物品、AWM 的 35.5、CREATOR 的 59.7 横加。

## 1. 问题：会用现成工具，不会给这一类请求造一把

作者写当时的工具增强多半假定计算器、搜索、翻译已经在。人一换任务类型，合适的 API 就不在。人类智能的转折点被他们写成：不只会用现成的，还会给新出现的困难造工具。LATM 把这件事收成两段：制造者从几条示范写出通用 Python 函数；使用者把新题译成函数调用。制造可以交给贵的模型，使用交给便宜的模型。一次造好，后面同类请求只付使用账。

\(S\) 取这次部署里的函数缓存：已经过核验、带调用示范的 Python 工具。单轮 \(S'=I(S)\) 可以发生：调度判定这是新任务，制造者写进库。术语式 (2) 还要 \(I'\subseteq S'\)。下一轮仍用同一句「请写只用标准库的通用函数」、同一套核验格式、同一句包装、同一句调度。混元台阶上这不是 L0：函数跨实例还在。也到不了改改进器。更像 Voyager / AWM：留下脚手架状态，出状态的程序冻着。作者把 closed-loop 写成制造和缓存可以跟着新请求继续发生。花园读成库在长，配方不在变。结论自己写未来工作：让制造者像软件开发那样升级已有工具。主实验没做这一步。

和邻居先划线。Voyager 的 63 是 160 步 Minecraft 物品种类；这边测试集每任务 **240** 题，训练 / 验证各 **3** 条。CREATOR（Qian 等，[arXiv:2305.14318](https://arxiv.org/abs/2305.14318)，Findings of EMNLP 2023）按题造工具：ChatGPT 上 MATH **59.7%**、TabMWP **94.7%**、Creation Challenge **75.5%**，迁移实验最多再加 **15.3** 个百分点（63.0→78.3）。那是竞赛数学和表格题，不是本表六列。LATM 相关工作把 CREATOR 写成并发：拆成抽象创造和具体应用，但没把可复用和贵便宜分工写成主贡献。PoT / PAL 用 Python 解本题算术；这边用 Python 留下给后题用的 API。Chameleon 也接解释器，作者写成解子步骤，不是造可复用工具。Toolformer 学的是何时调已有工具。[ReTool](../../2-Model层-训练时自改进/08-ReTool-代码解释器RL/08-ReTool-代码解释器RL.md) 后来用 PPO 学何时写代码，改的是 \(\theta\)，函数不按类缓存；AIME2024 67.0 不要改这边的 79.7。[ToolRL](../../2-Model层-训练时自改进/09-ToolRL-多工具奖励设计/09-ToolRL-多工具奖励设计.md) 学的是何时调已有 API，也不缓存新函数；3B BFCL 52.98 不要改这边的 79.7。[Gorilla](../../2-Model层-训练时自改进/11-Gorilla-API调用微调/11-Gorilla-API调用微调.md) 调 Hub 里已有的模型卡，改 \(\theta\)，不按类缓存新函数；TorchHub 0-shot 59.13 不要改这边的 79.7。禁止用 59.7 改 79.7。

## 2. 机制：三步造一把，再译成调用

任务定义：先有几条带答案的示范，写出通用函数；再来新题，只生成调用并执行。制造再拆三步。提议：3 条训练示范，按 programming by example 写函数。写出来不能跑，把报错拼进历史再试。核验：3 条验证题生成单元测试，跑提议出来的函数。测不过，只改测试里的函数调用，**不改函数本身**。包装：过了阈值才把函数代码和「题如何变成调用」的示范捆成工具，交给使用者。使用：便宜模型看包装后的提示，一次生成调用，温度钉 **0.0**。选择题再把返回值映射成选项。制造温度 **0.3**，提议和核验最多各重试 **3** 次。过阈值仍失败，这一类任务的制造记失败。

核验在流水线里干两件事：给使用者示范「自然语言怎么变成参数」；用执行检查挡住明显不能跑的函数，让整条链能自动走。作者写 60 次试验里只有 **2** 次是靠报错改对了。不要把 Self-Debug / Self-Refine 听成这里的主列。这里的自修复默认修的是调用，不是算法。函数一旦写歪，核验改调用也救不回来。这是机制，不是附录闲笔。正文写得直白：核验阶段只会改正单元测试里的函数调用，不会去改函数。

调度是第三条模型，实验用 GPT-3.5 Turbo。库里已有工具就交给使用者；没有合适的就当新任务，攒够示范再造。作者把它写成功能缓存：传统 GPTCache 存的是文本相似的回复；这边存的是一类请求的功能。调度提示冻着。100 条六任务混合、五次随机构造，认对已有工具 **95% ± 2%**；四任务已知、再混两个未见，决定「该造还是该用」**96% ± 3%**。这是调度准确率，不是 Table 2 的答题准确率。两套分母禁止横加。

Table 1 只说明制造者常写出什么算法，不当另一张准确率表。逻辑演绎：枚举排列再检查约束。洗牌跟踪：模拟交换。Dyck：栈。词排序：`sorted`。中国剩余：搜索或扩展欧几里得。会议安排：区间求交。五物体逻辑演绎和洗牌跟踪来自 Big-Bench；会议安排是作者按模板造的：时长从 {0.5, 1, 1.5} 小时抽，A/B 空闲从 8:00–18:00 按 30 分钟切，答案取最早够长的交集，没有就写 No time slot works。前四任务的 few-shot CoT 示范来自 Suzgun 等 2022；后两任务正文写的是直接 few-shot，没有 CoT。不要把后两列的 CoT **0.0 / 18.9** 听成「作者给了逐步推理还是零」。

**图 1 解析**

- **Request**：一条自然语言题。还没有函数时，这一步后面会进制造。
- **Make**：提议、核验、包装。只对这一类任务做一次。失败则这一类没有工具。
- **Use**：把题译成调用并执行。骨干可以比制造者弱。
- **Cache**：过核验的函数留下。调度下次先在这里找。

成本写成 \(O(nc+C)\) 对 CoT 的 \(O(nc)\)，以及 GPT-4 两边都当使用者时的 \(O(nC)\)。\(C\) 是一次 GPT-4 调用，\(c\) 是一次 GPT-3.5 Turbo。写论文时 \(C\) 比 \(c\) 贵 **15 倍以上**。这是量级，不是六任务账单。不要手算美元去改 Table 2。摊销成立的前提是：同一类任务的实例足够多，制造那一次 \(C\) 可以被后面的 \(n\) 次使用摊薄。一篇会议安排只问一次，制造账摊不薄。

附录 D 的包装成品要把「留下的是 API，不是逐步想法」钉死。逻辑演绎的函数是 `find_order(objects, constraints)`，体内 `permutations` 穷举，约束是 lambda。使用者要做的事是：把「灰书在橙书右边」译成 `order.index("gray") > order.index("orange")`，再把返回的第三位置映射成 A–E。洗牌跟踪是 `square_dance`，字典里换搭档。Dyck 是栈和闭合映射。词排序就是 `sorted`。中国剩余在上限内枚举。会议是 `datetime` 求交。六把工具的复杂度差一个数量级。`sorted` 几乎不需要制造者聪明；五物体约束需要。Table 3 的 0/5 和 5/5 裂开，部分原因在这里，不是随机抖动。包装提示要求从核验历史里抽出函数和全部验证题的调用示范。人改这句格式，等于人改 \(I\)。

调度实验的构造也要分开读。认已有工具：六任务随机混 100 条，提示里带着各 API 文档，模型填 Task 名，没有合适的填 unknown。五次随机构造才有 95% ± 2%。请求制造：随机指定四个任务为已有，测试里两个未见、两个仍属已有，再混 100 条，决定该造还是该用，96% ± 3%。两套都不是 Table 2。调度认错，后面使用者会拿错函数。作者把调度写成轻量，边际成本低。花园读成又一份冻着的提示，不是改进器。

## 4. 这不是术语式 (2)，升级已有工具写在未来工作里

库变了，下一道同类题可以只生成调用。改进器没变。提议提示、核验格式、包装格式、调度提示、3/3 切分、最多 3 次重试、温度 0.3 / 0.0 都还在。混元 L0 装不下跨实例保持的函数表；L3 要改提议 / 选择程序。本篇停在留下状态、不改程序。摘要里的 closed-loop 指制造和缓存可以继续发生，不是 \(I\) 在改自己。

附录 B 自己写：给模型造工具的自主权，质量可能达不到人定的标准，控制问题这篇没有展开。这不是谦虚套话。核验只跑 3 条验证题，而且默认不改函数。过了 3 条，240 条测试上仍可能把错误算法当成 API。逻辑演绎 GPT-4 制造成功率 3/5，成功的那几次才进 Table 2。失败的两次没有对应的 79.7。把「会造工具」听成已经可靠的自我进化，缺的是制造失败率和核验覆盖都很小。

和 Voyager 钉死。63 种物品是开放世界技能库；这边是六类推理题的函数缓存。那边自验证还是 GPT-4 看背包；这边核验是解释器跑单元测试。和 AWM 钉死。35.5 是 WebArena；这边没有浏览器。和 CREATOR 钉死。59.7 是 MATH 上 ChatGPT，按题创造，迁移最多 +15.3 个百分点；这边摊销的是类级函数。和 PoT 钉死。PoT 解本题；LATM 留后题。和 ReAct 钉死。交错想–做–看随题清空；函数按类留。和 SkillEvolver 钉死。那边写 `SKILL.md`；这边写 Python。和 DGM 钉死。DGM 改的是 Agent 自己的 Python；这边改的是给任务用的工具函数，制造提示不进库。

对有大模型基础的读者，读完应能回答四句。改的是哪一层？Harness 里的函数缓存和调度。权重动了没有？没有，GPT-4 / 3.5 都是查询。79.7 是不是 GPT-4 当制造者仍失败时的数？不是，Table 3 逻辑演绎 GPT-4 也只有 3/5。还缺什么才叫花园 RSI？造工具的提示或核验规则进入 \(S'\)，并且下一类新任务用的就是升级后的那份。作者把「升级已有工具」写成未来工作。主实验没有这一列。没有墙外检查「这把函数该不该进缓存」——核验题和训练题一样少，还是模型自己出调用。错函数一旦包装进去，调度 95% 认对只会让后面 240 题一起用歪。

> 图 2：实线只更新缓存和本题调用。虚线是冻着的模型和配方。

**图 2 解析**

- **左列**：缓存可以多一把函数，本题 \(y\) 可以变。
- **右列**：制造者、使用者、调度的提示和温度仍是人写的。
- **读法**：库在长不等于 \(I\) 在长。未来工作里的「升级已有工具」画在墙外，主实验没有箭头。

同一句「模型给自己造工具」，至少分三截。Toolformer 学何时调已有 API。CREATOR 按题写文档和代码。LATM 按类写函数并摊销。三截不要收成「都在推理时自我进化」。相关工作还点了 HuggingGPT、Chameleon、Voyager。Voyager 已有专文。HuggingGPT 调的是现成模型 API，不是本表六列。

「15 倍」要和摊销前提一起读。\(C>15c\) 是写论文时的标价比；Table 4 的 0.002 / 0.02 也是当时价。价单会变，准确率列不会因为价单变。同一类题够多，制造那一次才摊得薄。调度认错工具，便宜使用者会拿错 API，95% 不是 Table 2。GPT-4 当使用者在逻辑演绎上掉到 86.6，说明「更强骨干 + 同一把工具」不是单调改进。中国剩余 0.0→100.0 说明这一列测的是「会不会把搜索交给代码」，不是「闭循环已经比 GPT-4 更会推理」。

生成提示不会因为某次 100.0 就把核验改成「连函数一起修」。人要加金标检查、把制造提示写进缓存当可进化规则、让模型改重试次数，都是改 \(I\)。这和 DGM 改自己的运行时、STOP 改改进器源码正好相反。作者把 LATM 写成在制造和使用之间分工、用功能缓存摊成本。花园读成 2024 年这篇六任务函数缓存的定位，不读成已经闭合的递归，也不读成 GPT-3.5 已经会造逻辑演绎工具。

**读**：Table 2 的 79.7 / 99.6 / 92.2 / 98.3 / 100.0 / 100.0 对 CoT，中国剩余两边 CoT 都是 0.0，GPT-4 用户逻辑演绎 86.6 低于 88.8，Table 3 难任务 3.5 制造 0/5，Table 5 的 36.8 不是 LATM，95% 是调度不是答题，不是式 (2)。  
**不读**：把 closed-loop 听成 RSI、用 CREATOR 的 59.7 改 79.7、说 GPT-3.5 已经会造五物体演绎工具、把 +71.8 听成相对涨幅、说核验会改函数、说已经在升级已有工具。
