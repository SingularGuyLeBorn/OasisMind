# 35 AWM：工作流在长，配方冻着

摘要写 Mind2Web / WebArena 相对成功率 **24.6%** 和 **51.1%**。打开表：WebArena 同一只 `gpt-4-0613`，BrowserGym **23.5**，AWM **35.5**。差 **12.0** 个百分点；\(12.0/23.5\approx 51.1\%\)，才是那个 51.1。Mind2Web 的 24.6 不是任务做成了。Table 3 里 gpt-4 的逐步成功率 MindAct **36.2**、AWM **45.1**；\((45.1-36.2)/36.2\approx 24.6\%\)。同一行任务级仍是 **4.8** 对 **2.0**。人把「相对成功率」听成准确率柱，缺的是：变厚的是按网站切开的工作流记忆，诱导提示冻着，在线入库还要过一只没有金标的语言模型裁判。

本篇夹在 [ExpeL](../32-ExpeL-跨题经验洞察/32-ExpeL-跨题经验洞察.md)、[Dynamic Cheatsheet](../33-Dynamic-Cheatsheet-测试时备忘录/33-Dynamic-Cheatsheet-测试时备忘录.md)、[BoT](../34-BoT-思维模板缓冲/34-BoT-思维模板缓冲.md) 和 [Voyager](../10-Voyager-Minecraft技能库/10-Voyager-Minecraft技能库.md) 旁边。ExpeL 的洞察来自训练池，评测默认一次；这边 WebArena 没有训练集，只能在测试流上诱导。DC 存策略和脚本；BoT 存带类别的思维模板；Voyager 存过了自验证的 JavaScript。AWM 存的是网页子程序：描述加动作序列，具体商品名换成 `{product-name}`。[ReAct](../29-ReAct-推理与动作/29-ReAct-推理与动作.md) 的轨迹随题清空；这边工作流跨题还在。**不是** RSI。**不是** 改 \(\theta\)。**不是** 术语式 (2)。一手：Wang, Mao, Fried, Neubig，Carnegie Mellon University / MIT，[arXiv:2409.07429](https://arxiv.org/abs/2409.07429)，ICML 2025（PMLR [267:63897–63911](https://proceedings.mlr.press/v267/wang25bx.html)）。代码 [zorazrw/agent-workflow-memory](https://github.com/zorazrw/agent-workflow-memory)。数字以 HTML Table 1–11、§2–§5 为准。禁止用手抄 Figure 1 / 5 柱高去改表。禁止和 ExpeL 的 WebShop、Voyager 的 Minecraft、DC 的 AIME、BoT 的 24 点横加。

## 1. 问题：长程网页轨迹不会自己收成子程序

网页 Agent 已经能点、能填、能停。长一点的任务仍容易散：同一类「按类目逛商品」「按店名找地点」每次从原语重走。现成办法多半把固定示范写进训练或上下文。示范一换网站、一换槽位，就对不上。作者要的是另一层：从轨迹里抽出常复用的 routine，叫 workflow，再送回记忆指导后面的生成。宣传句带上人类从经验里抽象手续。花园要钉的是：抽象手续的程序仍是同一份诱导提示；在线场景里连「这条轨迹算不算成功」都可以是另一只冻着的语言模型。

\(S\) 取这次运行里的工作流记忆 \(M\)（底是 CLICK / TYPE 一类原语文档）。单轮 \(S'=I(S)\) 可以发生：库里多了一条「按名字找地点」。术语式 (2) 还要 \(I'\subseteq S'\)。下一题的诱导提示、动作空间、分组规则、在线裁判都还在。混元台阶上这不是 L0：后面的题读得到前面写下的子程序。也到不了改改进器。更像 DC / ExpeL / BoT：留下脚手架状态，出状态的程序冻着。

和邻居先划线。[ReAct](../29-ReAct-推理与动作/29-ReAct-推理与动作.md) / [LATS](../28-LATS-Agent树搜/28-LATS-Agent树搜.md) 在本题里交错想和做，题换了空。ExpeL 先刷训练题再考试。DC 没有网页执行器，备忘录里可以是代数策略或 Python。BoT 的模板对着 Game of 24 和将杀，不是 accessibility tree。Voyager 的技能是 Minecraft 函数。SteP 用人写了 14 条针对 WebArena 的工作流；AWM 声称不用这种站点特化的人手写稿。Synapse 检索的是完整示范轨迹；作者拿抽象子程序和它对，说具体槽位会把元素选择带偏。

任务形式写成：骨干 \(L\)，文本记忆 \(M\)，指令 \(q\)，状态 \(s_i\) 给出观察 \(o_i\)，\(L(q,M,o_i)\to a_i\)，环境 \(T(s_i,a_i)\to s_{i+1}\)，直到 `STOP` 或步数上限。一条做完的经验 \(e=(q,P^e)\)，步 \(p=(o,a)\)。诱导模块 \(I(\mathcal{E})\to\mathcal{W}\)。两条实验都按网站分组：每个站点自己维护一小撮相关工作流，不是全球一份大库。分组规则也是人钉的 \(I\)：换一种切法，Reddit 的进版手续就可能漏进地图。专文不把「按网站切开」听成模型自己学会了域边界。

## 2. 机制：诱导、入库、再注入；离线一次，在线流式

工作流长得像经验，但目标更粗。先有一段自然语言描述 \(d\)，再有一串步骤。每一步三件套：当前页面状态的自然语言（「订单 `{id}` 已显示」）、为什么选这个动作、可执行程序（`stop()`、`click('…')`）。诱导提示故意把粒度压到子任务：「在亚马逊搜商品」，而不是「买猫粮寄到我家」。槽位换成变量。模型输出按空行切开，各存一条。

离线：有标注或合成的规范轨迹时，把同一网站的训练例拼进一次提示，\(I(\mathcal{E}_{\mathrm{train}})\to\mathcal{W}_{\mathrm{offline}}\)，测试时整库注入，每道测试题共用同一份 \(W\)。Mind2Web 的 cross-task 有训练切分，所以能跑离线。

在线：WebArena 只有测试题，没有对齐的高质量示范。Agent 从默认 \(M\) 起步，对流上第 \(t\) 题生成轨迹 \(e_t\)。裁判 \(L_{\mathrm{eval}}(e_t)\in\{0,1\}\) 用 Pan 等 2024 的语言模型评价器，不是 WebArena 交卷用的执行正确性函数。判成功才 \(I(e_t)\to\{w^t\}\)，写入 \(M^{t+1}\)。失败轨迹不进库。交卷分数仍按 WebArena 的功能正确性算；入库门和交卷尺不是同一把。这和 DC 策展没有金标是同一类病：记忆更新听语言模型的，榜听环境的。

**图 1 解析**

- **Act**：\(L(q,M,o)\to a\)。WebArena 用 BrowserGym 动作空间加 accessibility tree；公平对照是 BrowserGym\(_{\mathrm{ax\text{-}tree}}\)，不是带 HTML 的那一行 23.5。

雪球写在地图站点。先归纳「按名字找地点」，再遇到要邮编的题，前几步复用旧工作流，后几步补上取邮编，收成更复杂的「取某地邮编」。这是工作流当子目标，不是改进器给自己换了诱导配方。Figure 1 正文写滚动几十例之后相对基线可到 **22.5** 个点；那是地图分片上的过程曲线，不要拿 22.5 替换 Table 1 的总分 35.5，也不要替换地图格 43.3。

附录 A 把诱导提示钉死成一段：从多条网页任务里抽出公共子程序，禁止生成互相重叠的工作流，每条至少两步，非固定元素写成描述性变量。WebArena 和 Mind2Web 共用这一段。附录举例包括购物类目浏览、后台改字段保存、Reddit 进版块、GitLab 搜仓库再看贡献者、地图填起终点和交通方式。这些是模型在实验里吐出来的样子，不是另一套人手写的 SteP 稿。质量表只报条数、覆盖、重叠、利用率，没有「这条子程序语义正确」的墙外标注。

## 3. 数字：51.1 和 24.6 都是相对涨幅，尺还不一样

Table 1，WebArena，`gpt-4-0613`，温度 0。SteP（14 条人手写工作流）总分 **33.0**。原始 WebArena **14.9**。AutoEval **20.2**，步数 **46.7**。BrowserGym **23.5**，分站点未报。ax-tree **15.0**（购物 17.2，CMS 14.8，Reddit 20.2，GitLab 19.0，地图 25.5），步数 **7.9**。AWM **35.5**（30.8 / 29.1 / 50.9 / 31.8 / 43.3），步数 **5.9**。摘要 51.1 钉在 35.5 对 23.5。正文另写胜过 SteP **7.6%** 相对涨幅：\((35.5-33.0)/33.0\)，绝对只差 **2.5** 个点。摘要写成 7.9%，花园以正文和表为准。公平对照若改成 ax-tree，35.5 对 15.0 是 **20.5** 个点，相对涨幅会换成另一套说法，论文没拿它当摘要。分站点「相对 BrowserGym 基线 11.8–30.7 个点」对着有分列的 ax-tree：Reddit **50.9−20.2=30.7**。步数比 ax-tree 少约 **2.0**，比 AutoEval 少 **40.8**。少步不是改进器变聪明，是子程序把重复点击收掉。

Table 2 交叉模板子集：每类模板只留一题。AWM **33.2**，ax-tree **20.5**，SteP **32.1**。用来挡住「只是同一模板抄作业」。购物 51 题、CMS 45、Reddit 24、GitLab 45、地图 32。AWM 仍最高，但购物 24.5 低于 SteP 的 26.5，Reddit 与 SteP 打平 52.2。总分赢在别的站点，不是五格全压人手写稿。

Mind2Web 有四把尺：元素准确率、动作 F1、逐步成功率（元素和动作都对）、任务成功率（每一步逐步都要 1）。任务级天然更矮。Table 3 离线 cross-task：gpt-3.5-turbo 上 Synapse 逐步 **30.6**、任务 **2.4**，AWM 逐步 **34.6**、任务 **2.8**，元素 34.0→**39.0**。gpt-4 上 MindAct 逐步 **36.2**、任务 **2.0**，AWM 逐步 **45.1**、任务 **4.8**，元素 41.6→**50.6**。动作 F1 反而略低于 MindAct（57.3 对 60.6）：工作流会把动作往稿子上拉，环境对不上时不知道该岔开。正文「4.0–8.9% relative and 0.4–2.8 absolute」把 Synapse 的逐步 +4.0、MindAct 的逐步 +8.9、任务级 +0.4 / +2.8 搅在一句。花园拆开写。摘要 24.6 只认 gpt-4 逐步那一格的相对比例。结论段把 24.6 和 51.1 都写成 task success rate，Mind2Web 那侧写错了；专文以摘要的 step-wise 和 Table 3 为准。

Table 4，gpt-4。逐步成功率：cross-task MindAct 36.2、离线 45.1（+8.9）、在线 43.6（+7.4）；cross-website 30.1、离线 33.7（+3.6）、在线 33.9（+3.8）；cross-domain 18.6、离线 32.6（+14.0）、在线 35.5（+16.9）。摘要「8.9 到 14.0 绝对点」钉在离线 cross-task 的 +8.9 和离线 cross-domain 的 +14.0。在线跨域可以到 +16.9，摘要没取这格。任务级不要跟着逐步走：跨域离线任务 **0.7**，低于 MindAct 的 **1.0**。逐步涨、整题掉，说明中间步对了更多，仍凑不齐一条全对轨迹。Mind2Web 的任务成功率要求轨迹上每一步逐步都是 1，所以 45.1 的逐步和 4.8 的任务可以同时成立：多数步选对了元素，整条任务仍会在某一步断掉。把摘要 24.6 听成「任务做成了四分之一」，就是把逐步尺收成了任务尺。在线的好处写在分布差上：训练在亚马逊购物、测试在亚马逊招工时，离线库会对错站点手续；在线只看测试查询。坏处也写了：在线从模型自己的轨迹诱导，错轨迹过了裁判就会留下错手续。WebArena 交卷用执行正确性，入库却用语言模型裁判，两把尺可以打架：环境判失败的轨迹进不了库，环境判成功但裁判判失败的轨迹也进不了库。专文不把 35.5 读成「裁判已经等于环境」。

Table 5：WebArena 规则诱导 35.6 / 6.3 步，LM 诱导 35.5 / 5.9 步。总分几乎一样，LM 更细、少走多余步。Table 6：Mind2Web 规则逐步 43.4、任务 2.0；LM 逐步 45.1、任务 4.8。网页元素选择更吃抽象槽位，规则留下的整段具体轨迹会偏。Table 7：把程序步骤改写成「点击提交按钮」这种话，元素 51.2、逐步 45.4，任务掉到 3.6。正文认为文本和代码都能当记忆，任务级仍以代码稿 4.8 为准。Table 8 用 gpt-3.5-turbo：只留自然语言逐步 34.6；只留过滤 HTML 33.8；两者都留 32.9。过滤 HTML 有 **47%** 的步缺掉全部正确元素。加长上下文加上自相矛盾，不是越接地越好。

Table 9 把工作流包成可调用的高阶动作 \(\mathrm{AWM}_{AS}\)。逐步 46.4，比记忆增强 AWM 的 45.1 高 **1.3** 个点。任务级表上是 **3.6**，记忆增强 AWM 是 **4.8**。正文却写「同一成功率 3.2」。花园以表为准，3.2 不进主数字。智能体只在 **18.5%** 的任务里调用新动作。订机票时城市名会弹出附近机场，预存动作序列看不见中间状态，这是作者自己举的硬例子。Table 11 离线加在线：逐步夹在两档中间，任务级 cross-task 掉到 **1.6**。两套库不能当加法。Table 10：神经诱导给出 7.3–7.4 条量级（WebArena 7.4，Mind2Web 7.3），利用率 0.94 / 0.91，功能重叠 0.08 / 0.20，Mind2Web 覆盖 0.40。正文写成 per example；花园只记这个量级，不把它听成「每题往库里塞七条还保证不炸窗口」。

## 4. 这不是术语式 (2)，裁判也不是改进器

工作流记忆变了，下一题可能直接走「先按名字找地点」。改进器没变。诱导提示、按网站分组、BrowserGym 原语、`gpt-4-0613`、在线那只 Pan 评价器都还在。混元 L0 装不下跨题保持；L3 要改提议 / 选择程序。本篇停在留下状态、不改程序。不要用 51.1 听成「已经 51 分」，不要用 24.6 听成任务成功率，不要用 35.5 去改 ExpeL 或 Voyager。

和 SteP 钉死。人手写 14 条，总分 33.0；AWM 35.5。相对 7.6%，绝对 2.5 个点。交叉模板上购物还输给 SteP。和 BrowserGym 钉死。摘要 51.1 对的是 23.5 那一行；ax-tree 15.0 才是同输入的公平对照。和 Synapse 钉死。完整示范 vs 抽象子程序，元素 +5.0、逐步 +4.0，任务仍在 3 以下。和 DC / BoT / ExpeL / Voyager 钉死。备忘录、模板、洞察、JavaScript 技能都不是 accessibility tree 上的网页手续。和 ACE 钉死。ACE 后来批评整本重写；AWM 是追加子程序，没有条目化合并器，也没有把诱导提示交给循环去改。

对有大模型基础的读者，读完应能回答四句。改的是哪一层？Harness 里按网站切开的工作流记忆。权重动了没有？没有。24.6 和 51.1 是不是准确率？不是，一个是逐步成功率的相对涨幅，一个是 WebArena 总分相对 BrowserGym 的相对涨幅。还缺什么才叫花园 RSI？诱导提示或裁判规则进入 \(S'\)，并且下一轮改进器用的就是升级后的那份。作者把动态执行、让工作流动作看见中间状态写成还没做。错手续一旦过裁判，同类题会一起用歪；成功门挡的是「这题像不像做成了」，不挡「子程序抽象得对不对」。

> 图 2：实线只更新工作流库和本题输出。虚线是冻着的模型和配方。

**图 2 解析**

- **会变**：\(\mathcal{W}\)、本题动作轨迹。
- **冻 \(\theta\)**：WebArena 主表 `gpt-4-0613`；Mind2Web 另报 gpt-3.5-turbo。诱导和动作默认同一只模型。
- **冻 \(I\)**：附录 A 那份诱导提示、按网站分组、BrowserGym 动作空间、温度 0。
- **门**：在线是 Pan 等的 \(L_{\mathrm{eval}}\)；交卷是 WebArena 执行正确性或 Mind2Web 逐步 / 任务尺。两把尺不要收成一把。
- **下一题**：库携带。提示不携带「上次该怎么抽象子程序」的升级。

## 5. 子程序能省步，省下来的不是改进器

同一句「从经验里学」，至少分四截。ReAct 在本题里学下一步动作，题换了空。[Reflexion](../11-Reflexion-言语反思记忆/11-Reflexion-言语反思记忆.md) 把失败写成下一 trial 还能读的句子，房间可以再开一局，换一道网页题旧反思帮不上。ExpeL 在训练池里学洞察，考试一次交卷。DC / BoT 在文本或模板库里学解法形状。AWM 在网页轨迹里学可再执行的手续。四截不要收成「都在推理时自我进化」。相关工作还点了 MiniWoB、WebShop、VisualWebArena。本篇主表只有 WebArena 和 Mind2Web。WebShop 数字在 ExpeL 专文，不要搬过来垫 35.5。AlfWorld 的 71% 在 ReAct 专文，也不要搬过来垫 Reddit 的 50.9。

在线前几十题学最快，Figure 5 写在地图分片 0–40 例。之后更复杂的工作流还在长，成功率会在早段高点附近稳住。这是 L2 脚手架在流内变厚的证据，也是配方冻着的证据：每题仍用同一份诱导提示和同一只裁判。人要改诱导粒度、把裁判换成执行器金标、让工作流动作在中间状态上分支，都是改 \(I\)。这和 DGM 改自己的 Python、STOP 改改进器源码正好相反。

规则诱导在 WebArena 能追上 LM，说明这套环境里动作序列本身已经很重复；Mind2Web 跨站元素选择才显出抽象槽位的好处。AWM\(_{AS}\) 几乎不被调用，说明「记忆里有稿」和「动作空间里多了一个函数」不是一回事。订机票弹窗那个例子把病写死了：预存序列看不见中间页面。作者鼓励后续在 AWM 框架里做动态执行；花园读成 2025 年这篇还没把执行器做成可改的改进器。

离线加在线不能加分，说明两套库会互相拖。训练手续和测试手续分布一错，暖启动反而脏。这和 DC 空记忆对满记忆、BoT 关掉 buffer-manager 之后准确率不随轮次涨，是同一类对照：留下的状态有用，怎么留下仍是人钉的 \(I\)。生成提示不会因为某次诱导成功就多一条「以后该怎么切子程序」的规则进仓库。

**读**：Table 1 的 35.5 / 23.5 / 12.0 个百分点、摘要 51.1% 是相对 BrowserGym、ax-tree 15.0 是公平对照、SteP 33.0 相对 7.6%、Mind2Web 摘要 24.6% 是逐步 45.1 对 36.2、任务级 4.8 对 2.0、Table 4 的 +8.9 / +14.0 是逐步绝对点、跨域离线任务 0.7 低于基线、在线入库走 Pan 裁判、不是式 (2)。  
**不读**：把 51.1 或 24.6 听成准确率柱、用 35.5 改 ExpeL / Voyager / DC、用 22.5 替换总分、用正文 3.2 改 Table 9、说诱导提示已经在优化自己、说已经 RSI。
