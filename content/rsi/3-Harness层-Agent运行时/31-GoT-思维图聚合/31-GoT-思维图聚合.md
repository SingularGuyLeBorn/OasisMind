# 31 GoT：思维图可并，跨题清空

摘要写排序质量相对 ToT 高 **62%**，费用同时少 **>31%**。打开正文：那是 \(P=128\) 上中位 **error-scope** 大约少 62%，不是准确率柱从某数涨到 62。同一段还写相对 CoT 质量大约高 **70%**。\(P=64\) 上中位误差相对 CoT 少约 **65%**、相对 IO 少约 **83%**。\(P=32\) 相对 ToT2 几乎不涨。主实验是 **GPT-3.5**，每任务 **100** 条，温度 **1.0**，默认 4k 上下文。文档合并那张图才是 50 条、16k。人把「图比树强」听成自我进化，缺的是：操作图 GoO 执行前就写死，变的只是本题的思维顶点；题换了，图清空。

本篇夹在 [ToT](../27-ToT-本题推理树/27-ToT-本题推理树.md) 和 [RAP](../30-RAP-世界模型规划/30-RAP-世界模型规划.md) 旁边。ToT 的节点是中间思维，边是父子，不能把两条已经分叉的路并回一个顶点。GoT 允许入度大于 1：先把子问题各自做完，再聚合成终局。RAP 的节点是模拟世界状态，搜法是 MCTS；这边节点是任意形态的思维（一段排序、一篇摘要、一个集合），搜法是人预先画好的操作图。**不是** RSI。**不是** 改 \(\theta\)。**不是** 术语式 (2)。一手：Besta, Blach（并列一作），Kubicek, Gerstenberger, Podstawski, Gianinazzi, Gajda, Lehmann, Niewiadomski, Nyczyk, Hoefler，ETH SPCL 等，[arXiv:2308.09687](https://arxiv.org/abs/2308.09687)，AAAI 2024（*Proceedings of the AAAI Conference on Artificial Intelligence* 38(16):17682–17690）。代码 [spcl/graph-of-thoughts](https://github.com/spcl/graph-of-thoughts)。数字以 HTML §5–7、Table 2、附录 Table 5 的 GoO、Figure 5–8 的文字结论为准。禁止用手抄柱高去改那几个「约」。禁止和 Yao 等 GPT-4 Game of 24 的 **74%** 横加：本篇对照的 ToT 是他们用 GPT-3.5 自己跑的排序 / 集合 / 计数，\(k\) 和层数 \(L\) 另配。

另有一篇名字几乎一样的 Graph-of-Thought（Yao, Li, Zhao，[arXiv:2305.16582](https://arxiv.org/abs/2305.16582)）。作者脚注写明：那是微调，要改 \(\theta\)，不是提示方案，本篇不收。GitHub 上还有 qrdlgit/graph-of-thoughts，作者写那是 ToT 加 BFS，不是任意图。两份都不要写进本表。

## 1. 问题：树并不回两条路

IO 一次吐答案。CoT 在中间塞思维。CoT-SC 采 \(k\) 条链再挑最好的，链与链不相交。ToT 把局部探索收成树：能回溯，不能把已经分开的两枝合成一个新顶点。作者写人类想问题不是只走链、也不是只长树：试一条，退回来，发现上一枝里有一句能跟当前这条拼，就并。脑子里有回路。算法执行也常是 DAG。树强加的拓扑把这些变换挡在外面。

GoT 把推理过程写成有向图 \(G=(V,E)\)。顶点是一道题的某个解——初始、中间或终局，具体形态跟任务走：排序是一串数字，写作是一段或一篇。有向边 \((t_1,t_2)\) 表示生成 \(t_2\) 时提示里明确把 \(t_1\) 当直接输入。写作里还可以异构：有的顶点是提纲，有的顶点是段落，用类别映射 \(c\)。形式化成四元组 \((G,\mathcal{T},\mathcal{E},\mathcal{R})\)：图、变换、打分、排序。变换作用在整张 \(G\) 和冻结的 \(p_{\theta}\) 上，通常加顶点加边，也允许人指定删掉不看好的部分，给上下文腾地方。删错了是人的责任。

\(S\) 取「当前这道题的图推理状态」。单轮 \(S'=I(S)\) 可以发生：多一个聚合顶点，或多一次 Improve。术语式 (2) 还要 \(I'\subseteq S'\)。下一道独立题仍用同一份 GoO（操作图）、同一套 Prompter / Parser、同一份打分函数。GoO 是静态的，执行前构造一次；GRS 才是动态的，记下已经执行了哪步、各思维的内容和分数。题换了 GRS 清空，GoO 原样再走。混元 L0：改 \((\text{输出},\text{轨迹})\)，跨独立任务保留的 Agent 状态不变。

和邻居先划线。ToT 专文的 Game of 24 是 GPT-4、合法等式门；本篇排序的门是 error-scope，骨干是 GPT-3.5。两边都叫 ToT，不是一张表。[RAP](../30-RAP-世界模型规划/30-RAP-世界模型规划.md) 用 UCT 在模拟状态上搜，GoO 不存在；这边搜什么、何时并，人提前写成操作序列。[LATS](../28-LATS-Agent树搜/28-LATS-Agent树搜.md) 接真环境观察；这边打分可以是局部函数（排序数错了几个），也可以再问一次 LLM（文档合并）。[Self-Refine](../12-Self-Refine-任务内迭代/12-Self-Refine-任务内迭代.md) 的改稿是线性 Refine；GoT 的 Refine 是图上的自环 \((v,v)\)，还可以跟聚合叠。[PromptAgent](../26-PromptAgent-MCTS提示规划/26-PromptAgent-MCTS提示规划.md) 相关工作把 ToT / RAP 写成本题推理树，自己长提示版本；GoT 的图也是本题的，留下的只有 \(y\)。

![Generate、Aggregate、Score 与 KeepBest、本题输出 y；实线只在本题内转](./images/fig-got-loop.png)

> 图 1：实线是本题内的生成、聚合、打分留优。回到 Generate 的是还留在 GRS 里的顶点，不是已经交卷的 \(y\)。题换了，环断开。

**图 1 解析**

- **Generate**：从一个思维长出 \(k\) 个新思维。ToT / CoT-SC 的分叉收在这一类。
- **Aggregate**：多个入边并成一个顶点。排序里是归并两段已排序子列；计数里是把各段词频加起来。
- **Score + KeepBest**：\(\mathcal{E}\) 打分，\(\mathcal{R}\) 留最高的 \(h\) 个。排序用局部 error-scope，不必再问模型。
- **this-task output y**：GoO 走到终点交出的那个思维。没有跨题缓冲。

温度 1.0。默认 4k 上下文。文档合并才开 16k。Llama-2 试过，通常不如 GPT-3.5，还慢，样本不够。GPT-4 写在架构可插的名单里，主表预算没铺开。这些都是人钉的 \(I\)。

## 2. 机制：三种变换，操作图冻着

图上多出来的能力主要是三类变换。聚合：基本形态 \(V^{+}=\{v^{+}\}\)，\(E^{+}=\{(v_1,v^{+}),\ldots,(v_k,v^{+})\}\)。也可以把几条链的终点并成一个。Refine：\(E^{+}=\{(v,v)\}\)，自环表示在同一个连接上改内容。Generate：从一个 \(v\) 长出 \(k\) 个孩子，把 ToT 那一套收进来。除非另说，删集为空。打分 \(\mathcal{E}(v,G,p_{\theta})\) 看得到整张图，允许相对打分。排序函数 \(\mathcal{R}(G,p_{\theta},h)\) 实验里多半就是留分数最高的 \(h\) 个。

真正跑起来不是「模型自己决定图长什么样」。架构拆成 Prompter（把图结构编进提示）、Parser（从回复抽出思维状态）、Scoring（验对错、打分；排序用局部函数，文档合并可以问 LLM，也可以让人打）、Controller（挑思维、挑变换、决定是否再问一轮）。Controller 里两块：GoO 是静态执行计划，规定变换的种类、顺序和依赖；GRS 是动态账本。当前设计里何时停，由 GoO 说了算，不是模型改停机规则。

排序是写得最完整的用例。数是 0–9，允许重复。作者写：超过某长度，这些 LLM 经常排不稳，因为重复次数对不上。做法是归并式：先切子列，各自排，再两两并。思维就是一串已排序的数。附录 Table 5，32 元的 GoO 写死四步。第一步用 split_prompt 切成两段等长。第二步每段 sort_prompt 排五次、打分、留最好。第三步 merge_prompt 并十次、打分、留最好。第四步 improve_prompt 修十次、打分、留最好。64 / 128 元只改切分长度，提示骨架相同。Improve 的说明书要求按 0–9 逐个对频率，缺的补、多的删。Merge 的说明书按归并步骤写：比两个头、取小的、空了把剩下接上。这不是模型发明了归并排序，是人把归并把步骤写进 \(I\)。

打分用 error-scope \(=X+Y\)。\(X\) 数有多少对相邻颠倒；\(Y\) 对 0–9 每个值，输出频率和输入频率差的绝对值再加总。画图时再 clip 到 \(\min(\text{error-scope},n)\)，因为 IO / CoT 有时错到爆表。禁止把 clip 后的柱高听成未 clip 的误差。集合交的误差是多出来的、漏掉的、再加上重复（模型用自然语言列表表示集合）。正分可以写成 \(\max(n-\text{error-scope},0)\)，附录 Figure 9 / 10 用正分重画 Figure 5 / 6，花园不手抄。关键词计数：按类（实现里是国名）数频率，把文本切成若干段，各段数完再聚合；段数可配置，也可以让模型自己切到句子。分数是每个词「算出来的次数减真值」的绝对值再求和。文档合并：若干份部分重叠的 NDA，目标是少重复、多保留。问 LLM 两个 0–10 的分（冗余、保留），各问三次取平均，再取调和平均。10 表示无冗余 / 全保留。这是模型打模型，门不在墙外执行器上。

集合交的图分解跟排序类似：第二个集合切成子集，各自跟第一个做交，再聚合。评测集合大小 32 / 64 / 128，两集合重叠在 25% 到 75% 之间。附录 Table 12 的 32 元计划比排序少一步 Improve：先把第二个集合切成两半，每半跟第一个做交五次留最好，再把两份交集合并十次留最好。关键词计数 Figure 7 里 GoT4 / GoT8 / GoTx 是切成 4 段、8 段、以及把 few-shot 也缩短的变体。切得越碎，动态部分的 token 变短，静态 few-shot 反而可能占大头；GoTx 就是把示范段落也改小。改 few-shot 是人改 \(I\)。Table 20 的 GoT4 写死：切成大约四段，每段数国名十次留最好，再把词典并三次；并坏了用 improve_merge_prompt 最多再试三次。文档合并把四份部分重叠的 NDA 并成一份；主设定一次并四份，变体 GoT2 分两步并。打分说明书钉死：冗余 0 表示至少一半信息重复，保留 0 表示什么都没留下。写作才用异构图，类别集合写成提纲和段落两类顶点；主评测四任务都没有走这条。体积的形式定义是能沿有向路径到达终局思维的前面那些思维个数。树没有从两片叶子同时走到同一顶点的路，所以体积上不去；并图画进 GoO 之后才有。

作者还定义思维的体积：能沿有向边走到 \(v\) 的前面那些思维的个数。直觉是「有机会对 \(v\) 做过贡献的思维数」。固定总代价 \(\Theta(n)\)、一个思维 \(O(1)\) 时间。CoT 延迟 \(N\)、体积 \(N\)。CoT-SC 两条都除以 \(k\)。ToT 当完全 \(k\) 叉树，延迟 \(\log_k N\)，体积只有 \(O(\log_k N)\)。GoT 把一棵完全 \(k\) 叉树的叶子接到一棵边反过来的镜像树上，延迟同样 \(\log_k N\)，体积回到 \(N\)。这是 Table 2 的组合论证，不是评测表上的误差。聚合让终局可以从图上任一中间思维到达——前提是人把那张镜像并图画进 GoO。

![上排本题 GRS 交 y；下排 GPT-3.5、静态 GoO、Prompter/Parser、打分函数冻着](./images/fig-got-frozen.png)

> 图 2：实线只更新本题顶点。虚线是冻着的 \(p_{\theta}\) 和操作图。

**图 2 解析**

- **会变**：GRS 里的思维内容、分数、本题 \(y\)。
- **冻 \(\theta\)**：主表 GPT-3.5；Llama-2 试过但不是主列。
- **冻 \(I\)**：GoO、四类提示骨架、KeepBest 次数、温度 1.0、上下文长度。
- **门**：排序 / 集合 / 计数用局部误差；文档合并用 LLM 打的调和平均。
- **下一题**：GRS 不携带。GoO 不会因为这题并成功就长出新操作。

## 3. 数字：62% 是中位误差少多少，不是准确率

评测相对 ToT，因为作者写 ToT 已经稳定压过别的方案。仍然带了 IO、CoT、CoT-SC；CoT-SC 若没有新洞察就省略。每任务 100 条，文档合并 50 条。为了费用可比，各方案的思维数尽量对齐。ToT 画两档：一档 \(k\) 大、层浅（图上叫 ToT），一档 \(k\) 小、层深（ToT2）。ToT 通常质量略好、更贵。关键词计数 Figure 7 有一句：80 对 60 次总回复，费用 **$6** 对 **$3**——那是 ToT 两档自己的账单，不要写成 GoT 的主数字。

GoT vs ToT：所有画出来的实例上都赢，费用始终低于 ToT，跟 ToT2 有时贵有时便宜。海报 62% 和 >31% 钉在排序 \(P=128\) 对 ToT。\(P=32\) 相对 ToT2 几乎不涨；\(P=64\) 中位误差相对 ToT2 大约少 **61%**，\(P=128\) 大约少 **69%**。问题越大，拆开再并的好处越明显。IO 随 \(P\) 变差，作者写成符合直觉：一个思维啃不动大实例。GoT vs IO / CoT：质量一直高，费用也一直高。\(P=64\) 排序中位误差相对 CoT 少约 65%、相对 IO 少约 83%。CoT 没有故意把链拉长——拉长若不能涨分就不拉。GoT / ToT 贵，主要因为每次 Generate 都长 \(k\) 个新思维。禁止把 62% 听成「准确率 62」，也禁止听成相对 ToT 专文 74% 的涨幅。

分解的账单有两头。子任务变小，回复和输入的动态部分按比例缩短；few-shot 那截静态提示可能反过来变成大头，关键词计数的 GoT4 到 GoT8 就是这个现象。把示范也改短（GoTx）能把费用压回去。目标写成：拆到「大多数时候一次提示就能做对」，后面的 Improve 才少。并或拼接子结果，通常比从零解大实例容易，所以终局聚合经常成功——这是作者对图的读法，不是另一张准确率表。

体积论证不要拿去改 Figure 5。Table 2 假定每种方案总代价同阶，比较的是拓扑能承载的信息范围。CoT 体积大是因为它是一条长链，延迟也是 \(N\)。GoT 同时要低延迟和高体积，靠的是镜像并图，不是 GPT-3.5 突然会了图算法。

## 4. 这不是术语式 (2)，GoO 也不是改进器

\(y\) 变好了，改进器没变。下一题的 GoO 还是附录里那份切–排–并–修。混元 L0：好处和危害都随本题丢掉。不要用 62% 给 [SEAL](../../2-Model层-训练时自改进/04-SEAL-自适配语言模型/04-SEAL-自适配语言模型.md) 的 LoRA 或 [DGM](../04-DGM-达尔文哥德尔机/04-DGM-达尔文哥德尔机.md) 的自改 Python 背书，也不要用排序误差去改 ToT 专文的 74%，更不要把 AAAI 这篇和那篇要梯度的 Graph-of-Thought 收成一个词。

和 [ToT](../27-ToT-本题推理树/27-ToT-本题推理树.md) 钉死。那边 BFS / DFS 在思维树上走，节点不能并；这边并是一等公民，但走哪一步由 GoO 预先写好，不是搜索算法现场决定拓扑。和 [RAP](../30-RAP-世界模型规划/30-RAP-世界模型规划.md) 钉死。那边 UCT 还在选边，世界模型是另一份提示；这边没有世界模型，状态就是思维字符串本身。和 [LATS](../28-LATS-Agent树搜/28-LATS-Agent树搜.md) 钉死。HumanEval 92.7 是真测试；本篇排序的对错是数相邻颠倒和频率，文档合并甚至是 LLM 打 LLM。和 [ReAct](../29-ReAct-推理与动作/29-ReAct-推理与动作.md) 钉死：没有 search / lookup，也不碰积木环境。和 [Self-Refine](../12-Self-Refine-任务内迭代/12-Self-Refine-任务内迭代.md) 钉死：Improve 十次仍在本题图上，没有跨题 \(p_{\mathrm{fb}}\)。

对有大模型基础的读者，读完应能回答四句。改的是哪一层？本题图上的思维，L0。权重动了没有？没有。62% 能不能当图已经学会自己长？不能，GoO 人写。还缺什么才叫花园 RSI？GoO 或打分规则进入 \(S'\)，并且下一题的改进器用的就是升级后的那份。架构号称可插新变换和新模型，插的人是用户。

## 5. 图比树多的那条边，寿命仍是一道题

同一句「用图推理」，至少分三截。GoT 的图是本题 GRS，题换了空。异构图把提纲和段落分成两类顶点，仍是本题。要梯度的那篇 Graph-of-Thought 改的是 \(\theta\)，寿命在 checkpoint，和本篇不是一种东西。ACE 的 playbook 跨题还在；GoO 跨题是同一份人写计划，不是上一题长出来的新计划。四截不要收成「都在用图自我进化」。

排序能并，因为子列排好之后并是有算法说明书的。文档合并的「并」没有金标文档，分数来自同一只 GPT-3.5 对冗余和保留的打分，三次平均再调和。门在模型嘴里时，L0 照样成立，只是错估会把差的并法留成终局。计数把国名频率当可加的数，并就是加法；这比 NDA 干净得多，也更容易让人以为「图自己会了」。读新闻时先问并的是有局部检查的子结果，还是另一只 LLM 的观感。

few-shot 和 GoO 都不会因为某题并成功就多一条操作进仓库。人要改切成 8 段、改 Improve 次数、把示范改短，都是改 \(I\)。这和 Voyager 的技能入库正好相反。作者把 Long 的 Tree-of-Thought 和 Yao 的 Tree of Thoughts 都算进树这一档，Xie 等的 thought decomposition 算部分支持。Table 1 只有 GoT 在「任意图变换 / 聚合」上打满。花园读成提示方案的拓扑分类，不读成 ToT 专文作废。Plan-and-Solve、Skeleton-of-Thought、多模型级联跟本篇正交：级联换的是上下文和模型身份，GoT 盯的是**同一段对话里**图能不能并。STaR 要筛有效思维链再训，本篇不训。
