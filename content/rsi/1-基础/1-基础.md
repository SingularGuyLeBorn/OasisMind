# 1 · 基础

读自我改进的论文, 难处常在数字之前. 一篇论文报告 SWE-bench 从 20.0% 到 50.0%, 另一篇报告 GSM8K 从 95.5% 掉到 89.0%, 两者都叫自我改进, 但前者保留下来的是 Agent 的代码, 后者只改了一道题的答案. 不先说定被改的是什么, 就不知道该拿哪一种证据去检查这个数字, 也不知道它能外推到哪里.

这一部分的三篇把后面五部分要用的东西一次立好: 一套描述 Agent 状态和一轮改动的记号, 一条按改动深度分层的阶梯, 以及一套判断「改动发生了」能否升级为「改进成立了」的证据规则. 三篇的材料主要来自腾讯混元与浙江大学等的综述 *Diving into Reliable Self-Evolving Agents* 的定义部分和可靠性部分, 再配上 Huang 等人的自我纠错实验, Gao 等人的奖励过优化曲线, PACE 的序贯检验这些可以算出来的例子.

后面各篇遇到一个新系统, 都会回到这里问同一组问题: 它保留下来的是 $\theta$, $\Sigma$, $U$ 还是 $C$; 它的内部选择用了什么信号; 最终证据在不在更新边界之外. 这一部分读扎实了, 后面每篇只需要讲系统本身.

## 1. 三篇的分工

### 1.1. 导读: 把五件事分开

[1.1 · 导读与证据规则](1.1-导读与证据规则/1.1-导读与证据规则.md) 从五个具体结果起笔: GPT-4 自我纠错后准确率下降, R-Zero 的自投票标签准确率从 71.0% 降到 42.2%, SkillsBench 上自写技能平均 −1.3 个百分点, DGM 的后代删掉检测标记拿满分, RQGM 在 epoch 边界替换评估器. 五个例子分别落在 L0 到 L4, 失败方式也各不相同, 这一篇用它们引出坐标系.

1.1 的后半是两段材料. 一段是 1965 到 2026 年的几个节点: Good 的超智能机器论证, Yudkowsky 的 seed AI, Schmidhuber 的 Gödel Machine, AlphaZero, 语言模型进入循环之后的 STaR, Self-Refine, Voyager, DGM, 以及 Karpathy 的 autoresearch 和 OpenAI 的阈值写法. 另一段是九条证据规则, 每条配一个本库读过的实例, 比如 Meta-Harness 的 76.4% 来自搜索集即评测集, Mimosa 的工作流档案在实验中一次都没被检索. 这九条在后面各篇反复被引用.

### 1.2. 定义: 状态, 一轮循环与阶梯

[1.2 · 定义与形式化](1.2-定义与形式化/1.2-定义与形式化.md) 是全库的记号来源. 它先区分演化目标和外部目标: 前者回答这次改了什么, 后者回答拿什么判断改得更好, 后者的语义不能被这次改动修改. 然后把一轮自演化拆成执行, 提出, 选择, 审计四步, 写出 L0–L4 的边界条件, 再从 L3 的条件推出 RSI 的定义.

这一篇的后半用同一组问题走查代表系统: 这一轮保留下来的是什么, 它影响之后的执行, 更新还是评判, 外层哪些部分固定. 走查得出的几条结论后面会反复用到: 论文的命名不决定深度; 「同一个模型既当选手又当裁判」不自动等于 L4; 产物可验证不等于改进器变好; 每个 L3, L4 系统都固定了一部分外层, 被固定的部分就是它的改进主张成立的范围.

### 1.3. 证据: 接受与控制

[1.3 · 证据, 接受与控制](1.3-证据接受与控制/1.3-证据接受与控制.md) 处理采纳一次改动时的三个问题: 证据从哪来, 按什么规则接受, 接受以后谁能回滚. 它把证据按产生方式分成形式证明, 程序执行, 学出来的评判器, 模型自评四种, 按综述的可靠性阶梯列出每层暴露给改动的证据和匹配的审计, 再推导反复挑选带来的偏差.

验收规则一节读 PACE, SEA, RSEA 三种做法. PACE 在同一组题上只看两边结果不同的题, 维护一个 e 过程, 用 Ville 不等式保证任意时刻停止时误采纳概率不超过 $\alpha$; RSEA 把演化池和验证集分开. 最后两节讨论升级之后的事: 谱系和回滚路径要演练过才算控制手段, 组件被攻破以后, 证据收集, 验收, 谱系和恢复权限仍要有效, 审计才算外部的. Zombie Agents 的记忆投毒是这一段的具体例子.

## 2. 共用的记号

### 2.1. 组件与等价关系

可保留状态写成 $\mathcal{A}_k=(\theta_k,\Sigma_k,U_k,C_k)$. 脚手架在第 3 部分进一步拆成 $\Sigma=(p,m,\mathcal{T},g)$, 即结构化提示, 记忆及检索策略, 工具集及调用接口, 控制逻辑. 记忆里执行中可以直接写入的部分记作 $m^{\mathrm{rt}}$. 两个版本在实际起作用的, 与决策相关的语义上等价, 记作 $\equiv_{\mathrm{act}}$; 重命名一个变量, 或者存一份从不被读取的副本, 都还是等价.

一轮的四步各有一个式子. 执行是 $(\tau_k,y_k,e_k)\sim\mathrm{Exec}_b(\cdot\mid\mathcal{A}_k,x_k)$, 其中 $b$ 是资源预算, $e_k$ 是临时的经验摘要. 提出和选择是 $X_k^{\mathrm{cand}}\sim\mathrm{Propose}_{U_k}(\cdot)$ 与 $\tilde{\mathcal{A}}_{k+1}=\mathrm{Select}_{C_k}(X_k^{\mathrm{cand}};H_k)$, $U$ 出现在提出的下标里, $C$ 出现在选择的下标里. 审计是 $d_k=\mathrm{Gate}_G(E_k^{\mathrm{ext}})\in\{\text{accept},\text{reject},\text{escalate}\}$, 证据源 $S$ 和验收策略 $G$ 在 Agent 状态之外. 一个系统改的是提候选的方式, 动的是 $U$; 改的是挑候选的规则, 动的是 $C$.

### 2.2. 几个容易混的词

本库用「自演化」指 L0–L4 的任何改动, 用「RSI」只指 L3 和 L4, 「改进」只在改进主张有外部审计支持时使用. 更新边界划定四件事: 循环可以修改什么, 可以读取哪些证据, 可以用多少资源, 可以授权哪些动作. 审计是不是外部的, 看它由谁控制, 不看它在哪里运行.

开发证据指已经向候选生成或内部选择公开过的证据; 审计证据指没有参与这两步的证据. 一个系统实际完成的转移低于 L4, 但它生成或使用了和评判有关的产物, 却没有改变生效的评判语义, 称为 L4-facing, RLCER 在评分规则不被保留时就是这种情况. 产物指 Agent 状态之外的输出, 比如搜出来的算法或训练好的另一个模型; 产物变好不等于 Agent 演化了, 被装进 $\Sigma$ 才是 L2, 被用来训练 $\theta$ 并保留下来才是 L1.

## 3. 三篇共同落下的判断

### 3.1. 深度不等于可信度

层级排的是改动对象的深度. 证据的强弱要另外看, 而且和层级不是同一个维度: 任何一层都可以用任何一种证据. 下表把 1.3 读过的四种证据来源和它们的代表数字放在一起.

| 证据来源 | 例子 | 数字 | 局限 |
|---|---|---|---|
| 形式证明 | Gödel Machine | 证出目标定理才改写 | 相对固定的公理和效用函数, 找不到证明就不改 |
| 程序执行 | CodeT, Absolute Zero | 执行结果不依赖模型判断 | 只覆盖写进测试的行为, 测试本身可能是模型写的 |
| 学出来的评判器 | PRM 对 ORM 对投票 | MATH 上 78.2%, 72.4%, 69.6% | 优化强度过了拐点后, 代理分和真实目标反向 |
| 模型自评 | Lee 等人的技能评定 | setter 校验 $r=0.88$, 多态 $r=-0.03$ | 语法可检查的维度上一致, 设计层面几乎无关 |

四种来源大致按对被评对象的独立程度排, 但这个排序不能直接当可信度. 程序执行可以测错东西; 学出来的评判器在优化强度低时有用, Gao 等人的拟合曲线显示强度过了 $d^\ast$ 之后金奖励开始下降; 自评在可检查的维度上相关系数可以到 0.88. 综述的说法是, 关键的比较在「改动控制了什么」和「审计由谁控制」之间, 不在层级编号之间.

### 3.2. 挑选会制造增益

设 $N$ 个候选和在任版本的真实差距都是 0, 测量噪声标准差为 $\sigma$, 挑测得增益最大的那个, 挑中者的期望测得增益约为 $\sigma\sqrt{2\ln N}$. 通过率 0.5 左右, 200 道题, 两个版本各自独立测量时 $\sigma=0.05$; $N=20$ 时 $\sqrt{2\ln 20}\approx2.45$, 期望的虚假增益约 12 个百分点. 候选之间相关或配对比较时偏差会小很多, 方向不变.

可选停止有同样的问题: 每多测一道题就看一次, 一旦显著就采纳, 只要一直测下去, 没有改进的候选迟早会显著. 自演化循环天然是序贯的, 所以 PACE 这类在任意停止下仍然有效的检验才派得上用场. PACE 的实验里, 贪心接受有 30–42% 的采纳是假的; 它自己的保证只对单个决定成立, 一轮运行测了 $M$ 个候选, 至少误采纳一次的概率可以到 $M\alpha$. 小样本上的差异也要先算误差: 45 道题, 通过率 42%, 标准误约 7.4 个百分点.

## 4. 读法

### 4.1. 顺序

第一次读按 1.1, 1.2, 1.3 的顺序. 1.1 用具体结果建立直觉, 不要求先懂记号; 1.2 给出记号和边界条件, 读完应能自己把一个新系统归到某一层; 1.3 讨论证据和采纳, 读它时会频繁用到 1.2 的外部审计式子. 后面五部分的每篇开头都只回顾一两句定义, 跳过这一部分直接读后文会缺很多前提.

已经熟悉自演化 Agent 文献的读者, 可以从 1.2 的阶梯和代表系统走查读起, 那一段决定了全库的归类口径, 和一些论文的自我描述并不一致, 例如 AREX 自称 RSI 而被归为 L0, AlphaEvolve 被判为不构成 L3. 读完再扫一遍 1.1 的九条规则, 它们是后面各篇检查数字时的清单.

### 4.2. 按需要查

只想弄清某个系统属于哪一层, 查 1.2 的阶梯和走查, 以及它末尾的论文记录表: 深度, 改动对象, 信号由谁产生, 内部筛选, 外部证据, 外层固定了什么, 保持证据. 后面各篇讲到一个系统时都按这几栏记录, 其中「外层固定了什么」一栏划出了改进主张成立的范围.

想评估一篇论文的改进主张, 查 1.3 末尾的审计记录表, 它和论文记录表配合使用: 前者记录系统改了什么, 后者记录证据怎么支撑改进主张, 逐项检查外部目标, 证据来源, 时间范围, 三个证据属性, 挑选次数, 验收规则, 谱系与回滚, 威胁模型. 关心安全的读者读完 1.3 的攻破与独立性部分, 可以直接接 [第 5 部分](../5-可靠性与安全/5-可靠性与安全.md).
