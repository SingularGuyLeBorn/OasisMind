# 定义与形式化

本章给全库装坐标系。后面每一章的论文，进来先报四个维度——改什么，信号从哪来，闭环到什么程度，验证器站在哪一层——然后才进入正文。看不懂本章的人翻后面任何一章都会迷路。

## 1. Agent 形式化

### 1.1 基础模型 Agent 的配置

2026 年三篇独立综述不约而同给出了同一层面的形式化。我们统一到 Schmidhuber 组的记号（arXiv:2607.13104），它和 Liu(Self-Evolving Agents)、Chen(arXiv:2607.07663)的术语可以逐项对应。

一个基于基础模型的 Agent，在时间步 $t$ 的**配置**是一对：

$$
\mathcal{A}_t = (\theta_t, \Sigma_t). \tag{1}
$$

- $\theta_t$：基础模型的神经参数。改 $\theta$ 意味着训练——慢，贵，稳定，难以回滚。
- $\Sigma_t$：运行时脚手架（**scaffold**）。改 $\Sigma$ 意味着编辑——快，便宜，可回滚，可审计。

$\Sigma$ 不是一个黑箱。它拆成四个可标注的组件：

$$
\Sigma_t := (p_t, m_t, \mathcal{T}_t, g_t). \tag{2}
$$

| 符号 | 名称 | 实例 |
|---|---|---|
| $p_t$ | 结构化提示 | system prompt,few-shot exemplar,rubric |
| $m_t$ | 记忆及检索策略 | 向量库，经验笔记本，Reflexion verbal memory |
| $\mathcal{T}_t$ | 工具集及调用接口 | MCP 工具，代码解释器，搜索 API |
| $g_t$ | 控制逻辑 | 路由，调度，安全约束，停止规则，工作流拓扑 |

**读这张表的方式**：后面遇到任何一篇论文，先问「它改的是 $\theta$ 还是 $\Sigma$ 的哪个分量」。答不出来就还没读懂。

Agent 的**策略**由两者联合决定：

$$
\pi_{\theta_t, \Sigma_t}(A_t \mid X_t), \tag{3}
$$

其中 $X_t$ 是**暂态执行状态**：KV cache，中间计划，当前对话的工作记忆。到下一个任务边界，$X_t$ 通常清空；它不是 Agent 的固有配置，不算「被改进了」。把 $X_t$ 的变化叫自改进，是最常见的术语膨胀。

### 1.2 术语对齐

不同综述用不同记号指向同一层：

| 本库统一 | Schmidhuber 组 | Liu Self-Evolving | Chen Bounded→RSI |
|---|---|---|---|
| $\theta$ | $\theta$ | $\psi$（每个节点） | Model |
| $\Sigma = (p, m, \mathcal{T}, g)$ | $\Sigma = (p, m, \mathcal{T}, g)$ | $C = (P, M)$ + $W$ + $\Gamma$ | Harness |
| 产物（Artifact） | （未独立建模） | （未独立建模） | Artifact |
| 暂态 $X$ | $X_t$ | trajectory $\tau$ | execution context |

三篇综述的共同点：都把 Agent 切成**可持久改写的配置**和**暂态执行状态**，自改进只说前者。

## 2. 自改进算子

### 2.1 核心等式

自改进不是「变好了」。自改进是 Agent 自己执行一段程序，产生学习信号，把信号写回自己的组件。形式化为一个自诱导更新算子 $\mathcal{U}$：

$$
\mathcal{A}_{t+1} = \mathcal{U}\bigl(\mathcal{A}_{1:t},\; \mathcal{E}(\pi_{\theta_t, \Sigma_t};\; \Sigma_t, \mathcal{C}_t)\bigr). \tag{4}
$$

拆开读：

1. **执行阶段** $\mathcal{E}$:Agent 在任务上下文 $\mathcal{C}_t$ 里跑自己的策略。跑出来的东西——轨迹，反思，批评，偏好对，提出的编辑——统称**学习信号** $\mathcal{S}_t$。
2. **更新阶段** $\mathcal{U}$：把学习信号写回 $\theta$ 或 $\Sigma$ 的某个分量。写完之后，配置持久变了，下一次执行用的是新配置。

$\Sigma_t$ 作为 $\mathcal{E}$ 的显式参数，是因为 Agent 可以直接审视自己的提示、工具、控制逻辑，然后提出修改。

### 2.2 两条通道

更新算子 $\mathcal{U}$ 天然分成两条通道：

**θ 慢循环**（参数改进）：

$$
\theta_{t+1} = \mathcal{U}_\theta(\theta_{1:t};\; \mathcal{S}_t), \qquad \Sigma_{t+1} = \Sigma_t. \tag{5}
$$

改基础模型权重。信号 $\mathcal{S}_t$ 可以是自生成的示范（$\mathcal{D}_t$），评价反馈（$e_t$），或环境探索经验（$\tau_t$）。慢，贵，稳。

**Σ 快循环**（脚手架改进）：

$$
\Sigma_{t+1} = \mathcal{U}_\Sigma(\Sigma_{1:t};\; \mathcal{S}_t), \qquad \theta_{t+1} = \theta_t. \tag{6}
$$

改提示、记忆、工具或控制逻辑。信号同上。快，便宜，可回滚。

| 维度 | θ 慢循环 | Σ 快循环 |
|---|---|---|
| 改什么 | 模型权重 | 提示 / 记忆 / 工具 / 控制逻辑 |
| 速度 | 慢（需要训练） | 快（即时修改） |
| 成本 | 高（GPU） | 低（API 调用 / 逻辑编辑） |
| 可回滚 | 难（需 checkpoint） | 易（文本 diff） |
| 持久性 | 全局、跨任务 | 可以全局，也可以只当前会话 |
| 可审计 | 难（参数不可读） | 易（提示和代码是文本） |

### 2.3 学习信号的三种来源

四篇综述在这一层高度一致。不管 $\mathcal{U}$ 改的是 $\theta$ 还是 $\Sigma$，信号 $\mathcal{S}_t$ 总是来自三个源头之一：

| 信号类型 | 符号 | 含义 | 典型方法 |
|---|---|---|---|
| 自生成示范 | $\mathcal{D}_t$ | Agent 自己造训练样本 | STaR bootstrapped rationales, Self-Instruct, Evol-Instruct |
| 评价反馈 | $e_t$ | Agent 自评或内部 judge 打分 | Self-Rewarding LM, constitutional AI, LLM-as-judge |
| 探索经验 | $\tau_t$ | 与环境交互拿到的轨迹和外部反馈 | 执行反馈，单元测试，形式证明，环境奖励 |

信号类型和更新通道是正交的：自生成示范可以用来训练权重（STaR），也可以用来填充记忆（Voyager 技能库）。

**关键观察**（Chen 综述核心论点）：信号质量决定改进天花板。详见第 02 章验证层级。

## 3. 有界精炼 vs 开放 RSI

这条线是全库的中轴。Chen 综述把它叫 central cut。

### 3.1 定义

**有界自精炼**(bounded self-refinement)：系统在一个**固定的、外部的**评估器下改进自己。评估器不变，改进收敛可测。

$$
\text{Bounded}: \quad \mathcal{A}_{t+1} = \mathcal{U}(\mathcal{A}_{1:t};\; \mathcal{S}_t), \quad \text{评估器 } V \text{ 不随 } \mathcal{A} \text{ 变}. \tag{7}
$$

**开放 RSI**(open-ended recursive self-improvement)：系统**同时**改自己**和**改评估器/改进器。没有固定外部锚。

$$
\text{Open RSI}: \quad \mathcal{A}_{t+1} = \mathcal{U}(\mathcal{A}_{1:t};\; \mathcal{S}_t), \quad V_{t+1} = f(\mathcal{A}_{t+1}, V_t). \tag{8}
$$

### 3.2 这条线为什么重要

2024–2026 的几乎所有公开系统都在有界那一端。但 RSI 叙事（Good 的智能爆炸、种子 AI、Gödel Machine）说的全是开放那一端。把有界的改进用开放的词来宣传，是领域最常见的术语膨胀。

| | 有界自精炼 | 开放 RSI |
|---|---|---|
| 评估器 | 固定，外部 | 和 Agent 一起变 |
| 收敛性 | 可证或可观测 | 理论上可能发散 |
| 产业状态（2026） | 已是工程实践 | 无公开系统满足严格定义 |
| 安全风险 | 可控（人审计） | 承重柱（§5）指向的核心风险 |
| 本花园处理 | 大多数论文在这里 | Good/种子/Gödel Machine + system card 能力项 |

不要在有界和开放之间画一条「真 RSI / 假 RSI」的线。它是连续光谱。中间有大量中间态：

- 只改 $\Sigma$ 不改 $\theta$ 的 harness 自改
- 改 $\theta$ 但评估器冻结的 self-play
- 改 $\theta$ 且评估器也在学的 self-rewarding
- 改整个脚手架的 Darwin Gödel Machine（但在固定 benchmark 上验）
- Red Queen：显式共演化 Agent 和评估器

越往右边，证据越少，风险越大。

### 3.3 旧花园的 S' = I(S) 在新框架里的位置

原花园把 RSI 定义为：

$$
S' = I(S), \qquad I' \subseteq S', \qquad S'' = I'(S'). \tag{Good–Schmidhuber}
$$

这个定义在新框架里映射为：$I \subseteq \mathcal{A}$ 且 $I$ 在更新后仍属于 $\mathcal{A}'$。它是开放 RSI 的**必要条件**——改进器必须在被改进的系统之内。

但它不够用。Tang 的 GAI 框架（arXiv:2609.13406）指出，还需要第二个旋钮：标准是否锚定在外。见 §5。

## 4. 闭环程度光谱

Chen 综述的第二根轴。谁验收这次改进？

| 闭环程度 | 谁在验 | 示例 |
|---|---|---|
| **人在环** | 人审查每一次修改 | AI 辅助编码，人点合并 |
| **人监督** | 信号自动生成，人审计结果并把关部署 | 执行反馈 + 人看跑分；reward model 训练后人 spot-check |
| **全闭环** | 系统生成、验收、应用自己的改进，无人审查 | （文献中极少；A-Evolve-Training 最接近） |

**1250 篇论文的分布**（Chen 综述）：几乎全部集中在中间列——人监督。左列太贵（人工成本），右列太危险（失去锚）。

Anthropic 的五阶段（When AI builds itself）：人写全部代码 → 聊天辅助 → 编码 Agent → Agent 委托 Agent → 全闭环。目前产业在第 3–4 阶段。

**安全风险集中在右列 × 评估器也在改的交叉格**。一个自己出卷、自己考、自己批的系统，就是有界精炼滑向开放 RSI 的入口。

## 5. GAI 双旋钮：从 GPI 到 RSI

Tang et al.(arXiv:2609.13406)把强化学习的广义策略迭代（GPI）和递归自改进统一到一个框架 Generalized Agent Iteration(GAI)，用两个旋钮区分所有实例。

### 旋钮 1：改进机制在不在 Agent 里

- **外部**(GPI)：优化器和评价基准都在 Agent 外面。标准 RL，标准 SFT。
- **内部**（RSI 候选）：改进机制是 $\mathcal{A}$ 的一部分，改进结果也写回 $\mathcal{A}$。

旋钮 1 对应旧花园的 $I' \subseteq S'$：改进器在不在系统里。

### 旋钮 2：标准锚在哪

- **锚定（anchored）**：评估标准固定在外（有界精炼）。
- **目标漂移（goal-drift）**：标准随系统共变，但有外部参照减速。
- **全自指（fully self-referential）**：标准也是系统的一部分，无外部锚（纯开放 RSI）。

旋钮 2 是旧花园没有的。它把 §3 的光谱精确化：不只是「改进器在不在里面」，还要问「改进标准在不在里面」。

两个旋钮画成 2×3 的格子：

|  | 标准锚定 | 目标漂移 | 全自指 |
|---|---|---|---|
| **改进器在外（GPI）** | 标准 RL / SFT | — | — |
| **改进器在内（RSI）** | Darwin Gödel Machine（benchmark 固定） | Self-Rewarding LM（judge 也在学） | Gödel Machine（理论） |

左上格是今天的绝大多数论文。右下格是 Good 的智能爆炸。中间的格子才是 2026 最活跃的战场。

## 6. 四词对照（升级版）

旧花园用四个词做邻居关系：Self-Improving / RSI / Continual Learning / Test-Time Training。新框架下重新定位，再加第五个词：

| 术语 | 改什么 | 改进器在哪 | 标准锚在哪 | 持久性 |
|---|---|---|---|---|
| **Self-Improving** | $\theta$ 或 $\Sigma$ 任意 | 不要求在内 | 固定外部 | 跨任务 |
| **RSI** | 改进器本身也在被改的范围里 | 在 $\mathcal{A}$ 内 | 可锚定或漂移 | 跨代 |
| **Self-Evolving Agent** | $\Sigma$ 为主，$\theta$ 可选 | 通常在内（快循环） | 环境反馈做锚 | 持久策略变化 |
| **Continual Learning** | $\theta$ | 外部（固定训练框架） | 固定（旧任务不能掉） | 跨任务序列 |
| **Test-Time Training** | $\theta$ 或 $X$ | 外部（per-query 目标） | 当前查询 | 当前会话 |

**边界**：

- Self-Improving 是伞。RSI 是伞下一个特殊子类（旋钮 1 = 内）。
- Self-Evolving Agent 是 2026 综述用得最多的称呼，多数指 $\Sigma$ 快循环改进。
- CL 问的是旧任务会不会掉。RSI 系统如果灾难性遗忘，递归可能连安全知识一起抹掉，所以 CL 是 RSI 的零件。
- TTT 在训练/推理边界上。改了权重，但只活一个会话。如果 TTT 的适应能稳定积累，它有可能成为递归零件。

## 7. 三层地图（升级版）

旧花园的 Model / Harness / Artifact 三层在新符号下的对应：

| 层 | 旧名 | 新符号 | 改进归哪 | RSI 判定 |
|---|---|---|---|---|
| 底层 | Model | $\theta$ | $\mathcal{U}_\theta$（慢循环） | 改完后改进器是否仍在 $\mathcal{A}'$ 里 |
| 中层 | Harness | $\Sigma = (p, m, \mathcal{T}, g)$ | $\mathcal{U}_\Sigma$（快循环） | 新技能若用来写下一版技能 = 弱 RSI 候选 |
| 顶层 | Artifact | 产物（不在 $\mathcal{A}$ 内） | 不是自改进 | 产物回流进训练栈 ≠ Agent 改了自己 |

**升级点**：

1. Harness 不再是模糊的「运行时」，而是 $(p, m, \mathcal{T}, g)$ 四个可标注的分量。
2. 「Artifact 不是自改进」仍然成立：AlphaEvolve 搜到更快的 kernel，改的是产物，不是 Gemini 的改进器身份。但如果产物被装回到 $\Sigma$（比如发现的 kernel 被编译进 Agent 的工具集），那就是 $\Sigma$ 改进。
3. 技能（Skill）是正交概念：一个被序列化、可复用的更新算子。技能可以存在 $\mathcal{T}$（工具）、$p$（指令）、$m$（记忆）或 $\theta$（权重）中任何一个基底。

## 8. 每篇论文进库的标注协议

后面每一章的单独成篇，进来先填这张表：

| 维度 | 记录什么 | 选项 |
|---|---|---|
| **更新目标** | 改 $\theta$ / $p$ / $m$ / $\mathcal{T}$ / $g$ / 产物 | 单选或多选 |
| **信号来源** | 自生成示范 $\mathcal{D}$ / 评价反馈 $e$ / 探索经验 $\tau$ | 可多选 |
| **闭环程度** | 人在环 / 人监督 / 全闭环 | 单选 |
| **验证层级** | 形式证明 / 执行反馈 / learned judge / 内省 | 详见第 02 章 |
| **光谱位置** | 有界精炼 ← → 开放 RSI | 定性 |
| **GAI 旋钮** | （改进器在内/外）×（标准锚定/漂移/自指） | 2×3 格 |

一篇论文填不满所有格是正常的——很多论文不讨论闭环程度或验证层级。填不了就留空，不要编。
