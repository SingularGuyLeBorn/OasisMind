# MaAS：超网按题采样，控制器冻着

摘要写只要别人 **6%～45%** 的推理成本，分数还高 **0.54%～16.89%**。打开 Table 3 MATH：MaAS 推理 **0.42** 美元，LLM-Debate **6.76**，0.42/6.76≈6.2%；GPTSwarm **0.93**，0.42/0.93≈45.2%。6%～45% 钉的是这张表的美元比，不是准确率柱。0.54 钉 Table 1 MATH：MaAS **51.82** 对 AFlow **51.28**。16.89 钉 MBPP：MaAS **82.17** 对 MacNet **65.28**。PMLR 267 摘要把上界改成 **11.82**，主表没有单独印这一格，花园不估。正文还写相对 AFlow 只要训练费的 **15%**、推理费的 **25%**：3.38/22.50=15.0%，0.42/1.66=25.3%。人把 15、25、6～45 听成同一把尺，缺的是：变的是超网上按题采样出来的那张算子 DAG；控制器、算子目录、\(L=4\)、\(thres=0.3\) 都还在墙外。

本篇夹在 [AFlow](../../8.1-工作流搜索与优化/8.1.1-AFlow-工作流MCTS/8.1.1-AFlow-工作流MCTS.md)、[G-Designer](../8.2.3-G-Designer-任务自适应通信图/8.2.3-G-Designer-任务自适应通信图.md)、[AgentPrune](../8.2.4-AgentPrune-时空图剪边/8.2.4-AgentPrune-时空图剪边.md) 和 [MAS-GPT](../8.2.2-MAS-GPT-一次前向吐MAS/8.2.2-MAS-GPT-一次前向吐MAS.md) 旁边。同一位 Zhang，G-Designer / AgentPrune 那组里也有他。这边不按题出通信图，也不在现成时空图上剪边，而是把候选工作流收成一层一层的算子概率，控制器按题采样。不要和 [MASS](../../8.1-工作流搜索与优化/8.1.3-MASS-提示拓扑分阶段/8.1.3-MASS-提示拓扑分阶段.md) 收成一篇：MASS 不训超网。不要和 MAS-GPT 收成一篇：那边一次前向吐 Python `forward`。不要和 [ANN](../8.2.6-ANN-层状文本反传/8.2.6-ANN-层状文本反传.md) 收成一篇：那边层状选队加文本反传，HumanEval 4o-mini 90.9，创作 9.0 是约 10 分制。不要用 83.59 去改 AFlow 专文 80.3：那边六集、Claude 优化器；这边五列、执行器一律 `gpt-4o-mini-0718`，AFlow 对照还把优化器收成同一只 4o-mini、`max_iteration=20`。不要用 HumanEval 92.85 去改 AFlow 专文 94.7、LATS 92.7、ScoreFlow 95.9。不要用本表 GPTSwarm GAIA 16.33 去改花园 GPTSwarm 专文 18.45。**不是** RSI。**不是** 术语式 (2)。一手：Zhang, Niu, Fang, Wang, Bai, Wang；国大 / 同济 / 南洋理工 / 上海 AI Lab / 中科大；[arXiv:2502.04180](https://arxiv.org/abs/2502.04180)，**ICML 2025 Oral**，PMLR 267:75834–75852。代码 [bingreeky/MaAS](https://github.com/bingreeky/MaAS)。数字以 HTML Table 1–4、Table 6–8、式 (5)–(12)、§3–§4、附录 B–D 为准。禁止用 83.59 去改 ScoreFlow 的 85.3，禁止用 20.69 去改 GPTSwarm 专文的 GAIA。

## 1. 问题：一份复杂工作流伺候所有题

作者把现场写成两难。Dilemma 1：自动化方法爱搜一份又重又贵的系统，几十次 API、再外挂工具。MATH 上抽象代数也许需要，小学算术零样本 I/O 就够。Dilemma 2：GAIA 这种跨域基准，读文件和网页搜索很难共用一份最优拓扑，人只能把基准切开分别优化。他们点名 [GPTSwarm](../8.2.1-GPTSwarm-通信图边概率/8.2.1-GPTSwarm-通信图边概率.md) 做过这种切分。切口于是从「搜一份最好的 MAS」改成「学一份架构分布，按题抽样」。这不是发现改进器该改自己，是人把 NAS 超网那一页搬到 Agent 工作流上。相关工作把自动化收成三刀：提示（Promptbreeder / DSPy / EvoPrompt）、通信（GPTSwarm / DyLAN / AgentPrune / G-Designer）、画像（AgentVerse / EvoAgent / AutoAgents）。ADAS / AgentSquare 把单 Agent 设计摊开，AFlow 用 MCTS 搜代码工作流。作者的判断是：这些高分方法仍在找**一份**最终系统。MaAS 要找的是分布。

\(S\) 取这次部署里学到的层概率 \(\boldsymbol{\pi}\)、改过的算子（提示、温度、节点结构），以及按题采样出的 DAG \(\mathcal{G}\)。单轮 \(S'=I(S)\) 可以发生：训练时 Monte Carlo 推 \(\boldsymbol{\pi}\)，文本梯度改算子；推理时多抽一张子网。术语式 (2) 还要 \(I'\subseteq S'\)。下一类题仍用同一份算子目录、同一档 \(L=4\)、同一条 \(thres=0.3\)、同一组 \(\lambda\in\{10^{-3},5\times10^{-3},10^{-2}\}\)、同一次 \(K=4\) 采样、同一只 MiniLM 编码器、同一份文本梯度提示。混元台阶上这不是 L0：超网可以带到后面的题。也到不了改改进器。人没退出 \(I\)。作者写 fully automated evolution。进化的接口还在墙外。仓库例子走 MetaGPT 配置，`--sample 4`，执行模型默认 `gpt-4o-mini`。改采样次数、换执行器，都是人改 \(I\)。

引言写评了七个基准，数学列点了 GSM8K / MATH / **SVAMP**。§4.1 主实验改成 GSM8K / MATH / **MultiArith**，外加 HumanEval、MBPP、GAIA，一共六份。SVAMP 没有主表。花园按 Table 1 和 Table 2 读，不把引言的七份听成已经跑过 SVAMP。MATH 子集跟 Hong 等 Data Interpreter：组合与概率、数论、初等代数、初等微积分，难度 5，共 **617** 道。Table 6 训练 119、测试 486，相加 605，和 617 对不齐。花园把 617 当作者口径，把 119/486 当实际切分，不把差掉的 12 道估进准确率。切分写 train:test = 1:4。HumanEval 训练只有 **33** 道，测试 131。33 不是 Hendrycks 全量，也不是 AFlow 专文那份验证协议。账单发生在这几十到两百多道训练题上的 \(K=4\) 次采样，不发生在测试时再搜一遍 MCTS。

## 2. 机制：超网是层概率，控制器按题抽 DAG

基本单元叫 agentic operator，定义 3.1 / 式 (1)：若干 LLM 调用、一份提示、若干工具。CoT 是 \(m=1,n=0\)。Self-RAG 多一个检索。辩论是多只、多轮。MAS 收成 DAG \(\mathcal{G}=\{\mathcal{V},\mathcal{E}\}\)，节点是算子。超网定义 3.2：\(L\) 层，每层一份 \(\pi_\ell(\mathcal{O})=p(\mathcal{O}\mid\mathcal{A}_{1:\ell-1})\)。联合分布式 (4) 是各层指示函数的乘积。目标式 (5) 最大化效用减 \(\lambda\) 乘成本。式 (10) 又写成最小化 \(-p+\lambda C\)。两套符号拧着，花园按实验读成：又要答对，又要 token 少。\(\lambda\) 没在主表钉成一列，实现写三个候选。人换 \(\lambda\)，等于人改 \(I\)。

采样式 (7)(8)。控制器 \(\mathbb{Q}_\phi\) 按题、按已经抽出的前几层，决定这一层开哪些算子。碰到早停算子 \(\mathcal{O}_{\text{exit}}\) 就停，不必走满 \(L\) 层。实现写成 MoE 风格打分，式 (9)：按分数从高到低累加，超过 \(thres=0.3\) 为止。一层可以开多个算子，个数随题变。分数来自 FFN，输入是题嵌入拼上前面各层算子嵌入的和。嵌入：先让 LLM 给算子写 profile，再用 MiniLM 压成向量。附录 B.2 的提示要求写出 `description` 和 `interface`。G-Designer 也用 MiniLM，那边压的是角色说明加任务虚节点；这边压的是算子说明书。两只 MiniLM 不要收成同一张 384 维表。

优化分两路。\(\boldsymbol{\pi}\) 不可微地经过 API，式 (11) 用 \(K\) 次 Monte Carlo，重要性权重 \(m_k\) 一边看答对，一边看相对成本。算子这边不能反传数字，式 (12) 用文本梯度：\(\nabla_{\mathbb{O}}\mathcal{L}=\mathbf{T}_{\mathcal{P}}\oplus\mathbf{T}_{\mathcal{T}}\oplus\mathbf{T}_{N}\)，分别改提示、温度、节点结构（合并、拆开、改边）。附录写这套提示部分改编自 ADAS 和 AgentSquare。代码和算子部分改编自 AFlow。花园读成：搜索空间的积木很多是邻居论文留下的，不是超网自己长出算子种类。附录 B.1 初始目录八项：CoT；辩论（三只辩手、最多两轮）；自洽（五条 CoT 投票）；Self-Refine（最多五轮）；Ensemble（三只不同来源再成对排序）；Testing（AgentCoder 的出题器）；ReAct（解释器、网页、知识库）；早停。作者说目录可定制。加人一个算子，等于人改 \(\mathbb{O}\)。式 (1) 里 \(\mathcal{T}\) 是工具，Table 5 又把 \(\mathcal{T}\) 写成温度。同一字母两义。花园按正文：工具在定义 3.1，温度在文本梯度那一刀。

算法 1 对训练题循环：逐层采样，遇早停或到 \(L\) 停下，执行 \(\mathcal{G}\)，再更新 \(\boldsymbol{\pi}\) 和算子。推理丢掉更新，只留采样和执行。这和 G-Designer 测试时丢掉反传、只留按题出图类似：生成器冻着，输出仍按题变。一边吐邻接，一边吐算子 DAG。不要收成同一张 89.84。温度一律 1。骨干除 4o-mini 外还跑过 Qwen-2.5-72B-Instruct 和 Llama-3.1-70B。Table 7 数学列把 Qwen 印成 **2.5-70b**，代码列印成 **2.5-72b**。花园按格子抄，不替他们合并型号。

## 4. 这不是术语式 (2)，按题采样也不是改进器

测试时走的是冻住的 \(\boldsymbol{\pi}\) 加冻住的算子文本。改进器没变。\(L\)、\(thres\)、\(\lambda\)、\(K\)、MiniLM、算子目录、文本梯度提示、1:4 切分，都还在。混元 L0 装不下跨题保持的超网；L3 要改提议 / 选择程序。本篇停在留下分布和算子，不改怎么打分、怎么早停。作者把 one-size-fits-all 写成失败模式。失败模式的对面仍是人写的超网深度。

和邻居钉死。AFlow 搜一份算子图伺候整集；这边每题从分布里抽一张。ScoreFlow 训 Python 生成器的 LoRA；这边不训 8B。MAS-GPT 一次前向吐 `forward`；这边抽的是已有算子的组合，不是新写一份 Python 系统。G-Designer 按题出通信图，节点集合人事先钉死；这边节点是算子，边在采样时出现。AgentPrune 在现成时空图上剪边；这边没有一张要剪的底图，有的是概率。GPTSwarm 学边概率可以一直 REINFORCE；这边测试时 \(\boldsymbol{\pi}\) 冻着。五截不要收成「都已经是 RSI」。[ANN](../8.2.6-ANN-层状文本反传/8.2.6-ANN-层状文本反传.md) 把 Agent 队写成层再走文本反传，90.9 不要和本表 HumanEval 92.85 横加。AutoFlow 的 CoRE 加 REINFORCE 也不是超网。

没有墙外检查「这道题该不该把 Testing 算子写进目录」。错算子一旦在 33 道 HumanEval 训练题上分数高，就会被 \(\boldsymbol{\pi}\) 抬起来。33 道很小。作者把归纳能力写成能消化没见过的辩论算子。消化的前提是人在推理期把这个算子放进 \(\mathbb{O}\)。不放进去，控制器打不出这一维。温度 1，换 0 会动 83.59。AFlow 对照只用 4o-mini、最多 20 轮，花园专文的 80.3 用 Claude 优化器。同一名字两套协议，不要用 82.25 作废 80.3。

对有大模型基础的读者，读完应能回答四句。改的是哪一层？Harness 里那份层概率和算子文本，以及按题抽出的 DAG。4o-mini 权重动了没有？没有。6%～45% 是准确率还是美元比？MATH 推理美元比。还缺什么才叫花园 RSI？\(L\) 或算子目录进入 \(S'\)，并且下一类新基准用的就是升级后的那份采样手续。现在换 \(thres\)、把 VGAE 收进控制器、让模型自己发明算子种类，都是人改 \(I\)。结论写成按难度分配资源。正说明旋钮还在人手里。简单题早停，是控制器学会少花钱，不是改进器改了早停规则。规则仍是式 (9) 的累加阈值。换一批没有早停算子的目录，同一套 \(thres\) 会抽出另一张图。这是目录和阈值的函数，不是改进器在长。仓库 README 把 ICML 2025 Oral 写成 Top ~1% among 12,107 submissions。花园不把中稿率听成 83.59 已经被社区认证成 RSI。主表抬分最大的五列里是 MBPP 相对 Vanilla 的 10.34 个百分点，不是相对 AFlow 的 0.50。相对 AFlow HumanEval 只高 1.92。GAIA 相对 Vanilla 16.04 个百分点（20.69−4.65），相对 GPTSwarm 只有 4.36。摘要三件事（6%～45%、0.54%～16.89%、跨模型可迁移）分属成本表、主表两端、附录 Table 7，不要收成同一张主表的三列。HumanEval 训练 33 道，测试 131 道。33 不是「已经在 HumanEval 上充分搜索」。AFlow 专文那套验证切分更宽，94.7 不要被 92.85 覆盖。MATH 测试 486 道，不是 Hendrycks 全量，也不要和 MAS-GPT 的 MATH 500 横加。617 对 605 对不齐，以 Table 6 的 119/486 为准。引言的 SVAMP 没有列，不要补一列假分。Testing 算子只服务代码，数学列没有测试用例这一维。ReAct 的工具表仍是人写的网页和解释器，不是超网发现该接什么 API。工具名单一变，GAIA 的 20.69 不会自动跟上。换名单是人改 \(I\)。目录外的 API 控制器看不见。看不见就不能采样。

同一句「自动编排多 Agent」，至少分五截。人手写链 / 星 / 树。GPTSwarm 在给定节点上学边。AFlow 用 MCTS 搜代码工作流。G-Designer 用 VGAE 按题出图。MaAS 用超网按题采样。五截不要收成「都已经是 RSI」。AgentPrune 剪边省 token，均分 89.72，表上 27.2% 是保留比。MaAS 的连续更新发生在训练那一小段，不是 AutoFlow 那条 REINFORCE 循环，也不要收成「都在训工作流所以已经是 RSI」。

\(\boldsymbol{\pi}\) 不会因为某次 83.59 就把 \(thres\) 写进 Agent 提示。人要允许新阈值、让模型改 \(L\)、把文本梯度本身放进搜索，都是改 \(I\)。这和 Gödel 改自己的决策函数、DGM 改自己的 Python 正好相反。作者把 MaAS 写成集体智能的自动组织。花园读成 2025 年这篇超网一次训练的定位，不读成已经闭合的递归，也不读成 AFlow 的 80.3 已经被 83.59 作废。执行器切分、是否一份图伺候整集，都不一样。
