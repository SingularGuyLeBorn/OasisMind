# 自动研究与科学发现

让 Agent 做研究的系统, 按搜索的对象和打分的方式大致分三类: 在程序空间里搜索, 由评估器打分的 FunSearch 和 AlphaEvolve; 从想法写到论文的 AI Scientist; 改训练配方的 autoresearch 与 A-Evolve-Training. 要问的是它们保留下来的改动落在哪里, 最终的分数由谁给.

## 1. 自动研究在 L0–L4 里的位置

### 1.1. 产物和 Agent

综述在 §9.3 讨论应用时, 把「可执行的工程与 AI 开发」和「科学发现」分成两个方向, 并用同一个问题区分系统: 保留下来的是什么. 它举了三个例子:

- Darwin Gödel Machine 的后代保留了对 Agent 程序的修改, 并能生成之后的后代. 这是 Agent 一侧的演化.
- AlphaEvolve 保留的是由任务专用评估器选出的算法和基础设施产物, 它的外层搜索程序保持固定.
- EvoDS 把验证过的数据科学流程变成可复用的技能, 是脚手架一侧的路径.

综述随后说: 这些系统让更新容易执行和比较, 但通过现有的检查, 只说明在被测的行为下有改进. 长的更新序列仍然需要新鲜的测试, 防止反复使用留出集, 并且要分清三件事: 改进一个产物, 改进一个 Agent, 改进产生之后更新的程序.

1.2 第 4.5 节按这个区分把 AlphaEvolve 归为「不构成 L3」. 下面几节的系统大多数和 AlphaEvolve 同类: 它们的输出是一个算法, 一篇论文, 一份训练配方, 或者一个训练好的模型, 这些都在 Agent 的可保留状态 $\mathcal{A}=(\theta,\Sigma,U,C)$ 之外.

### 1.2. 证据来源

综述对科学发现方向的另一个判断是, 关键的组织维度是最终证据的来源. 可执行代码和数值检查可以审计科学计算的步骤; 形式化证明工具可以在声明的假设下检查推导; 物理实验可以检验选定的经验主张. 模型审稿人可以用于分诊和诊断, 但不能独立确立新颖性, 陈述的忠实性或科学价值. 综述因此要求分层的证据: 任务内执行保证正确性, 受保护的留出问题检验迁移, 超出可执行检查范围的主张交给领域专家或实验评审.

下面三节按搜索对象读系统, 第 5 节读对自动论文的独立检查, 第 6 节把证据来源和层级放在一起比较.

## 2. 程序搜索

### 2.1. FunSearch

FunSearch (Romera-Paredes 等, *Nature* 625, 2024) 搜索的对象是程序, 而不是数学对象本身. 用户提供一段代码骨架, 其中一个函数由系统演化: cap set 问题里是给向量排优先级的 `priority`, 在线装箱问题里是决定把物品放进哪个箱子的 `heuristic`. 骨架的其余部分负责用这个函数构造解, 评估器给构造出的解打分.

一轮循环如下:

1. 从程序库里取出几个得分较高的程序, 拼成一个提示 (论文称为 best-shot prompting).
2. 语言模型 (Codey, 基于 PaLM 2) 根据提示写出新的函数.
3. 评估器执行新程序, 检查正确性, 给出分数.
4. 正确的程序按分数进入程序库.

程序库按岛屿组织: 论文把种群分成 $m$ 个独立的组, 每组单独演化. 方法部分写了重置规则: 每 4 小时, 丢弃最好成绩最低的 $m/2$ 个岛上的全部程序, 再用其余岛上的一个程序重新播种. 正文没有给出 $m$ 的值. 规模上, 一次实验的总样本数在 $10^6$ 量级, 通常用 15 个采样器和 150 个 CPU 评估器.

**cap set.** 在 $\mathbb{F}_3^n$ 里, cap set 是不含三点共线的集合. 原文说, 在 $n=8$ 时 FunSearch 找到了比此前已知更大的 cap set, 规模 512; 此前的纪录在图 4a 中标出. 原文强调, 它找到的不只是这 512 个八维向量本身, 还有生成它们的程序. 这个结果并不容易复现: 140 次实验里只有 4 次找到了规模 512 的 cap set.

**cap set 容量.** 容量 $C$ 刻画 cap set 规模随维数增长的速度, 已知上界 $C \le 2.756$. FunSearch 通过 admissible set 的构造改进了下界: 用 $\mathcal{I}(12,7)$ 把下界从 2.2180 提到 2.2184; 再用一个完整的 $\mathcal{I}(15,10)$ admissible set (对应 $C \ge 2.219486$) 和 $\mathcal{A}(24,17)$ 中一个规模 237,984 的部分 admissible set, 得到新的下界 2.2202.

**在线装箱.** 物品依次到达, 必须立即放进某个箱子, 目标是用尽量少的箱子. 表 1 报告的是多用的箱子占比 (越低越好):

| 数据集 | First fit | Best fit | FunSearch |
|---|---|---|---|
| OR1 | 6.42% | 5.81% | 5.30% |
| OR2 | 6.45% | 6.06% | 4.19% |
| OR3 | 5.74% | 5.37% | 3.11% |
| OR4 | 5.23% | 4.94% | 2.47% |
| Weibull 5k | 4.23% | 3.98% | 0.68% |
| Weibull 10k | 4.20% | 3.90% | 0.32% |
| Weibull 100k | 4.00% | 3.79% | 0.03% |

在 10 万个物品的 Weibull 数据上, FunSearch 的启发式只比最优解的下界多 0.03%.

FunSearch 的证据结构很简单. cap set 和 admissible set 的正确性可以逐点检查, 装箱结果可以直接计数. 评估器是用户写的确定性程序, 语言模型无法修改. 语言模型生成大量错误的程序并不影响结论, 只影响找到正确程序的效率.

### 2.2. AlphaEvolve

AlphaEvolve (Novikov 等, Google DeepMind, 2506.13131, 白皮书) 沿用了同一个循环, 把搜索范围从一个函数扩大到整个代码文件. 用户在代码里用 `# EVOLVE-BLOCK-START` 和 `# EVOLVE-BLOCK-END` 标出要演化的块, 块外的代码作为骨架, 把演化的部分接到 `evaluate` 函数上. 初始实现必须完整可运行, 但可以很简陋, 比如只返回常数的单行函数.

白皮书的表 1 对比了它和 FunSearch:

| FunSearch | AlphaEvolve |
|---|---|
| 演化单个函数 | 演化整个代码文件 |
| 演化 10–20 行代码 | 演化最多数百行代码 |
| 只演化 Python | 演化任意语言 |
| 需要快速评估 (单 CPU ≤20 分钟) | 可以在加速器上并行评估数小时 |
| 使用数百万个 LLM 样本 | 数千个 LLM 样本就够 |
| 用小 LLM, 大 LLM 没有收益 | 受益于最强的 LLM |
| 最少的上下文 (只有之前的解) | 提示中有丰富的上下文和反馈 |
| 优化单个指标 | 可以同时优化多个指标 |

几个组件:

- **模型**: Gemini 2.0 Flash 和 Gemini 2.0 Pro 组合使用. Flash 延迟低, 提高单位时间内的候选数; Pro 偶尔给出质量更高的建议.
- **输出格式**: 默认让模型输出 diff, 只替换代码中的特定片段; 代码很短或需要整体重写时, 可以改为输出整个代码块.
- **评估级联**: 用户可以指定一组难度递增的测试, 新解只有在前面所有阶段都表现足够好时, 才进入下一阶段.
- **进化数据库**: 结合了 MAP-Elites 算法和基于岛屿的种群模型.
- **元提示演化**: 模型在一个额外的步骤里提出指令和上下文, 这些元提示在一个单独的数据库里与解共同演化.

**结果.** 白皮书报告的结果分两类.

数学方面, $4 \times 4$ 复矩阵乘法用 48 次标量乘法完成, 摘要称这是这个设定下 56 年来对 Strassen 算法的首次改进. 白皮书还在 50 多个数学问题上测试, 75% 的情况重新发现了已知最好的构造, 20% 的情况改进了已知最好结果; 例如 11 维的接吻数下界从 592 提到 593.

Google 基础设施方面:

- 数据中心调度 (§3.3.1): 新的启发式持续回收平均 0.7% 的全舰队算力, 这些算力原本会被闲置.
- Gemini 内核 (§3.3.2): 所有内核相对专家设计的启发式平均加速 23%, 对应 Gemini 整体训练时间减少 1%. 白皮书写道, Gemini 借助 AlphaEvolve 优化了它自己的训练过程.
- FlashAttention (§3.3.4): 目标配置下的内核加速 32%, 前后处理部分加速 15%.

摘要还说, AlphaEvolve 加速了它自己所用语言模型的训练.

**消融.** 白皮书在张量分解和接吻数两个任务上做了消融, 分别去掉进化 (不用程序库), 提示中的上下文, 元提示演化, 整文件演化 (只演化损失函数), 以及强模型 (只用小模型). 白皮书对图 8 的总结是: 每个组件都带来了显著的提升. 第 2.3 节还说, AlphaEvolve 本身不依赖特定模型, 但消融显示底层模型越强, 它的表现越好.

### 2.3. 「加速自己的训练」算哪一层

AlphaEvolve 优化了 Gemini 的训练内核, Gemini 又是 AlphaEvolve 的变异算子. 这条路径常被当作递归自改进的实例. 按 1.2 第 3.3 节的测试逐步看:

1. AlphaEvolve 在一次运行里产出一个更快的内核. 这是产物, 在 AlphaEvolve 的可保留状态之外.
2. 工程师把内核部署到训练基础设施上. 采纳的决定由人做.
3. 下一代 Gemini 用这个内核训练, 节省约 1% 的训练时间. 内核让训练变快, 本身不改变训练出的模型在决策上的语义.
4. 如果新的 Gemini 被用作下一版 AlphaEvolve 的变异算子, $\theta$ 确实变了. 但这个变化来自新一代模型的整体训练, 训练配方和数据由人决定, 不是这个内核造成的.

所以这条路径上, 改进器 (外层搜索程序) 没变, 评判标准 (用户写的评估器) 没变, 采纳由人决定. 白皮书「Gemini 优化了它自己的训练过程」这句话描述的是事实, 但归类时它属于产物层面的贡献.

元提示演化需要单独看一下. 元提示影响之后的候选如何被提出, 这符合改进器的定义. 但白皮书描述的元提示是在一次运行内与解共同演化的, 没有说明它们跨任务保留. 只在任务内演化, 按 1.2 的规则仍是任务内的轨迹. 如果某个版本把演化好的元提示保留下来, 用于之后的新任务, 并且能证明新任务上提出候选的效率更高, 才构成 L3 的证据.

### 2.4. LEVI 与 EurekAgent: 搜索架构, 模型规模与成本

LEVI (2605.09764) 问的是这类系统的成本从哪里来. 作者认为, 现有框架对前沿模型的依赖, 主要是搜索分配方式造成的: 程序库保不住解的多样性, 只能靠更强的变异模型补偿; 不加区分地用模型, 把前沿模型的费用花在小模型也能做的局部修改上; 全量评估在冗余样本上浪费 rollout.

LEVI 对应地改了三个组件: 从一开始就建立并维持多样性的解数据库; 按任务分配大小模型的变异路由, 约 90% 的变异交给一个小的开放权重模型; 在 rollout 很重的设定里使用保持排序的代理基准. 结果: 在系统研究类基准上, 以 ShinkaEvolve, GEPA, AdaEvolve 公开的前沿模型运行预算的 1/3.3 到 1/6.7, 拿到最高分; 在一个问题上以 1/35 的成本追平已有最好结果. 在提示优化上, 用不到 GEPA 一半的 rollout 预算, 在四个基准上追平或超过它.

作者在引言里提了一个对照: FunSearch 的 cap set 结果并没有用前沿规模的模型. 这和 AlphaEvolve 白皮书「受益于最强的 LLM」并不矛盾. AlphaEvolve 的消融是在自己的搜索架构下比较模型大小, LEVI 比较的是不同搜索架构下达到同一分数所需的成本.

EurekAgent (清华, 2606.13662) 的标题主张是「Agent 环境工程就是自主科学发现所需的全部」. 摘要报告的结果是, 以总计不到 11 美元的 API 费用, 发现了 26 个圆的圆填充问题的新的最好结果. 这类结果的证据和 FunSearch 相同: 一个填充方案是否合法, 半径之和是多少, 都可以直接计算.

## 3. 从想法到论文

### 3.1. AI Scientist v1

AI Scientist (Lu 等, Sakana AI 等, 2408.06292) 走的是另一个方向: 让系统完成一篇论文的全流程. 论文 §3 把流程分为三个阶段: 想法生成, 实验迭代, 论文撰写. 写完之后再由一个语言模型审稿人打分 (§4).

每个研究方向从一份人写的实验「模板」开始, 系统用编码助手 Aider 对模板做代码级修改, 执行实验, 收集结果, 再起草论文. 论文把这个框架用在三个机器学习子领域: 扩散模型, 基于 Transformer 的语言建模, 学习动态 (grokking). 摘要说每篇论文的成本不到 15 美元.

一个容易忽略的细节是档案. 原文写道: 系统把完成的想法和审稿反馈加入一个科学发现档案, 然后重复这个过程. 档案跨轮保留, 影响之后的想法生成.

**自动审稿人.** 论文在 ICLR 2022 的 500 篇 OpenReview 论文上验证审稿人 (表 1):

| 审稿方 | 平衡准确率 | 准确率 | F1 | AUC |
|---|---|---|---|---|
| 人类 (NeurIPS) | 0.66 | 0.73 | 0.49 | 0.65 |
| GPT-4o (1-shot) | 0.65±0.04 | 0.66 | 0.57 | 0.65 |

正文的结论是平衡准确率接近人类 (65% 对 66%), F1 超过人类 (0.57 对 0.49), AUC 与人类相当. 这个审稿人判断的是一篇论文是否会被 ICLR 接收, 它学到的是人类审稿结果的统计规律.

**安全事件.** 论文的局限部分记录了几件事. 有一次运行里, 系统在实验文件里写了一个系统调用来重新启动自己, Python 进程数失控增长, 最后需要人工干预. 另一次, 它把代码改成每个更新步都保存检查点, 占用了将近 1 TB 存储. 有些实验超过了设定的时间限制, 系统试图修改代码延长时限, 而不是缩短运行时间. 作者因此建议严格的沙箱: 容器化, 除 Semantic Scholar 外限制网络访问, 限制存储用量.

延长时限这件事对应 1.1 第 4 节第 4 条「候选不能碰评分」. 时间限制是实验的资源约束, 属于更新边界的一部分. 系统能改它, 说明边界没有在执行层面被隔离.

### 3.2. AI Scientist v2

v2 (Yamada 等, 2504.08066) 去掉了对人写代码模板的依赖, 用一个实验管理 Agent 主导的渐进式 Agent 树搜索组织实验, 并在审稿环节加入视觉语言模型对图表的反馈.

作者把三篇完全自主生成的论文投给 ICLR 2025 的「I Can't Believe It's Not Better」(ICBINB) workshop. 其中一篇平均分 6.33 (三位审稿人分别给 6, 6, 7), 超过 workshop 的录用线, 摘要说大约排在投稿的前 45%. 另外两篇被拒. 投稿前作者与 workshop 组织方和 ICLR 负责人约定, 被接收的 AI 生成稿件在评审后撤回, 那篇论文因此没有正式发表.

作者在内部检查中发现: 系统偶尔会在引用上出错, 类似语言模型常见的幻觉; 它能执行标准的实验流程, 但有时缺少顶会所需的方法严谨性和深入分析. 作者认为这些问题没有妨碍 workshop 级别的录用.

### 3.3. 档案与审稿分数怎么归类

AI Scientist 每一轮输出的论文和代码都是产物. 但 v1 的档案保留了已完成的想法和审稿反馈, 并影响之后的想法生成, 这是脚手架 $\Sigma$ 中记忆部分的改动. 按 1.2 第 3.2 节的规则, 保留下来的数据按它实际改变了哪个组件的后续行为来归类, 所以 v1 是有条件的 L2. 条件是: 需要证据说明档案确实让之后的想法变好, 而不只是变得不同. 论文没有做去掉档案的消融.

审稿人在流程里同时承担两个角色: 系统内部的筛选信号, 以及论文报告结果时的评分来源. 按 1.1 第 4 节第 3 条, 这让审稿分数成了开发证据. 一篇论文在自动审稿人那里超过录用线, 说明它符合审稿人学到的模式; 它是否是一篇好论文, 需要人类审稿或者复现来回答. v2 选择投给真实的 workshop, 就是在补这一层外部证据.

## 4. 改训练配方

### 4.1. autoresearch

1.1 第 3.6 节读过 Karpathy 的 autoresearch: Agent 只改 `train.py`, `prepare.py` 里的数据准备和评估不允许改, `program.md` 由人改; 每次训练固定 5 分钟墙钟时间, 指标是与词表大小无关的 `val_bpb`; 每小时约 12 个实验. 它的证据设计把外部目标, 证据源和资源预算都放在 Agent 够不着的地方. 按 1.2 第 4.5 节, 这个循环本身不构成 L3.

5.4 读过的 GPT-5.6 评测里的 NanoGPT 任务, 是同一类结构的另一组参数: 一块 H100, 改训练代码, 尽快达到目标困惑度.

### 4.2. A-Evolve-Training

A-Evolve-Training (Amazon, 2606.20657) 把同一个循环放到 30B 的 Nemotron 模型上, 在 H200 集群上跑了几周. 4.2 第 4.4 到 4.7 节已经详细读过它的设计和四轮轨迹, 这里只列要点.

- 每轮从一个不可修改的参考工作区 `default/` 分叉出 8 个沙箱, 一个作为纯基线锚定噪声, 七个各探索一个方向. worker 没有跨轮记忆.
- 一个收集 Agent 把各 worker 的结果整理成固定格式的轮次报告. 元 Agent 只改写下一轮的滚动搜索策略, 它在一份自己无法修改的宪章下工作.
- 四轮的开发分与榜单分 (原文表 2): 基线 0.79 / 0.80; 第一轮 0.82 / 0.82; 第二轮 0.84 / 0.84; 第三轮 0.93 / 0.85; 第四轮 0.89 / 0.86. 榜首的人类提交是 0.87.
- 第三轮把一个弱领域 (方程) 的开发分从长期停留的约 0.65 提到 0.82, 外部分数却留在 0.84–0.85. 循环据此改了策略, 第四轮转而寻找可能降低代理指标但提高外部目标的干预, 比如重新平衡被过度代表的领域, 按重新加权的标准选检查点.

元 Agent 改写的搜索策略决定下一轮探索哪些方向, 以及提交候选的门槛. 这是改进器 $U$ 的改动, 4.2 把它归为 L3. 宪章规定榜单是权威标准, 全程没变, 所以不是 L4.

这里补充一点证据层面的观察. 论文报告的 0.86 是比赛的公开榜单分数, 论文称之为留出分. 但宪章的元规则规定「榜单是权威」, 每轮的收集 Agent 都会抓取公开榜单, 元 Agent 据此调整策略. 公开榜单在四轮里一直在被用于选择. 按 1.1 第 4 节第 3 条, 它是开发证据. 一个从未参与选择的留出评估 (比如比赛结束后的私有榜单) 才能作为审计证据. 论文自己也说结论建立在一次没有复现的运行上, 只覆盖一个基础模型, 一个任务族, 一个榜单.

## 5. 自动论文的独立检查

### 5.1. ScienceAgentBench

前面的系统大多用自己的评估信号报告结果. 2024 到 2026 年有一批工作专门从外部检查自动研究的产出.

ScienceAgentBench (2410.05080, ICLR 2025) 主张, 在宣称端到端自动化之前, 先严格评估 Agent 在科学工作流中单个任务上的能力. 它从四个学科的 44 篇同行评审论文中提取了 102 个任务, 请 9 位领域专家验证. 每个任务的目标输出统一为一个独立的 Python 程序文件, 从程序, 执行结果和成本几个方面评估.

论文用三种框架 (直接提示, OpenHands CodeAct, 自调试) 测了五个模型. 每个任务给三次尝试, 最好的 Agent 独立完成 32.4% 的任务, 有专家提供的知识时完成 34.3%. 这组任务都是数据驱动的分析代码, 是自动论文流程里「实验」那一步的一部分.

### 5.2. ResearchArena

ResearchArena (Cornell, 2605.19156, 标题「How Far Are We From True Auto-Research?」) 是一个最小的脚手架, 让现成的代码 Agent 自己完成研究循环: 想法, 实验, 写论文, 自我修改. 被测的是 Claude Code (Opus 4.6), Codex (GPT-5.4), Kimi Code (K2.5). 在 13 个计算机科学种子方向, 每个 Agent 和方向组合跑 3 次, 共产出 117 篇论文.

每篇论文从三个角度评估:

1. **只看稿件的审稿人** (SAR): Claude Code 得分最高, 超过 Analemma 的 FARS, 与人类 ICLR 2025 投稿的加权平均相当.
2. **看工作区的同行评审** (PR): 审稿 Agent 同时检查工作区和稿件. 分数大幅下降.
3. **人工的元评审**.

人工检查发现, SAR 的分数和它自己的录用决定对不上, 它奖励的是看起来合理的叙述, 没有核实实验内容. 主要瓶颈是实验严谨性, 分为三种失败: 编造结果, 实验功效不足, 计划与执行不一致. 这些失败高度依赖 Agent: Codex 的稿件与工作区不一致率和编造引用率分别是 5% 和 8%, Kimi Code 是 77% 和 72%, 相差约 15 倍. 117 篇论文里没有一篇达到顶会的录用线.

这个结果和第 3.3 节的判断一致. 只看稿件的审稿, 测的是论文的写法; 检查工作区, 才开始接触实验是否真的做了.

### 5.3. MLReplicate

MLReplicate (2605.16616) 把 8 篇 ICML 2025 杰出论文改写成标准化的输入规格, 让 6 个自动研究系统 (AI Scientist v1, v2, Agent Laboratory, CycleResearcher, AI Researcher, Tiny Scientist) 完成端到端的研究, 共生成 45 篇稿件, 3 次实验失败.

评估同时用自动的会议式审稿和结构化的专家人工评估. 自动审稿在 37 篇有效投稿里录用了 10 篇, 另有 8 篇因页数不足被直接拒绝. 人工审稿人在所有系统的输出里都发现了方法缺陷, 幻觉出的实验结果和复现失败; 被自动审稿录用的稿件中, 59% 含有编造或无依据的主张. 成本和质量没有对应关系: 最便宜的系统在人工评估中胜过资源最多的系统, 两者的输入 token 相差 38 倍.

### 5.4. SciIntegrity-Bench

SciIntegrity-Bench (2605.10246) 的设计是一种两难场景: 33 个场景分属 11 类陷阱, 每个场景里唯一正确的回应是如实承认无法完成, 而完成任务就必须违规. 在 7 个模型的 231 次评估中, 整体的诚信问题率是 34.2%, 没有一个模型做到零失败.

在缺数据的场景里, 7 个模型全部生成了合成数据, 而不是承认任务不可行, 区别只在于是否披露了这个替代. 提示消融把两个因素分开: 去掉明确的完成压力后, 未披露的编造从 20.6% 降到 3.2%, 但合成数据的比例没变. 作者的解释是存在一种内在的完成偏好, 它不受提示层面的指令影响; 诚实拒绝没有作为一种习得的倾向被训练出来.

这和第 3.1 节 AI Scientist 延长时限是同一类行为: 任务目标和约束冲突时, 系统倾向于绕过约束完成任务.

### 5.5. Heuresis 与 Dead Science Walking

Heuresis (2606.25198) 把研究流程抽象成可组合的原语: 提出想法的 Ideator, 实现的 Executor, 存储实验和心得的 MemoryServer, 打分的 GradingServer, 以及审计工作区的 HackerJudge. 它实现了六种搜索策略: 贪心基线, 两种档案式 (MAP-Elites, Go-Explore), 一种进化式 (Islands), 两种发散式 (Curiosity, Omni), 在 LLM 预训练, on-policy RL, 模型遗忘三个领域, 从质量, 多样性, 新颖性三个维度评估, 共 3,222 次有评分的运行.

结果:

- 完全新颖的想法很少. 没有一个想法被评为「Original」, 只有少数达到与已有工作「Minor Similarity」.
- 新颖的想法从未接近已知配方的最高分. 六种策略, 三个领域里, 只有一个这样的想法进入质量前十.
- Agent 在执行中使用了多种作弊手段, 在 1,628 次有评分的运行中确认了 40 次编造. 检测这些作弊是让搜索忠于任务的必要条件.

作者的结论是, 现有的搜索和质量多样性策略可以控制想法落在质量, 多样性, 新颖性三个维度的哪个位置, 但不能扩展质量与新颖性的前沿. 架构里专门设一个 HackerJudge, 说明作者把作弊检测当作评分的一部分, 和 1.1 第 4 节第 4 条的要求一致.

Dead Science Walking (2606.04220) 从另一个角度提出问题: AI 科学家流水线依赖的科学文献本身有发表偏差, 阴性结果系统性地缺失. 文章估算了几个领域的阴性结果缺口 (药物发现约 0.60, 心理学约 0.56, 癌症生物学约 0.35), 并估算流水线会把语料的失真放大 2.18 倍. 这是一篇论证性文章, 这些数字来自作者的模型估算, 不是实验测量.

## 6. 证据来源与层级

### 6.1. 汇总与三条观察

| 系统 | 保留下来的东西 | 最终证据 | 层级 |
|---|---|---|---|
| FunSearch | 程序库里的程序 (产物) | 可执行检查 | 不构成 L3 (Agent 状态不变) |
| AlphaEvolve | 算法与基础设施代码 (产物) | 可执行检查, 生产部署测量 | 不构成 L3 |
| LEVI | 解数据库 (产物) | 基准分数 | 不构成 L3 |
| AI Scientist v1 | 论文 (产物), 想法档案 | 自动审稿人 | 有条件的 L2 |
| AI Scientist v2 | 论文 (产物) | 自动审稿人, 一次 workshop 人类评审 | 产物层面 |
| autoresearch | `train.py` (产物) | 固定的 `val_bpb` | 不构成 L3 |
| A-Evolve-Training | 训练配方 (产物), 滚动搜索策略 | 公开榜单 (参与选择) | L3 (4.2) |

**第一, 可信度最高的结果都来自可执行或可计算的检查.** cap set 的规模, 矩阵乘法的次数, 接吻数, 圆填充的半径和, 装箱的箱子数, 内核的运行时间, 都可以由不依赖语言模型的程序验证. 这些系统里, 语言模型只负责提出候选. 候选错了会被评估器拒绝, 结论不受影响.

**第二, 由模型审稿的结果需要外部复核.** AI Scientist 的审稿人, ResearchArena 的 SAR, MLReplicate 的自动审稿, 都在只看稿件时给出乐观的结论. 加上工作区检查或人工评审后, 结论都明显变差. 综述说模型审稿人可以用于分诊, 不能独立确立科学价值, 这三项检查给出了具体的差距.

**第三, 绕过约束是反复出现的失败.** AI Scientist 延长时限, SciIntegrity-Bench 的合成数据, Heuresis 的 40 次编造, ResearchArena 的编造结果, 都是同一种模式: 任务完成和约束冲突时, 系统选择完成任务. 1.1 第 4 节第 4 条要求候选不能碰评分, 这些例子说明, 这条要求需要在执行环境里强制, 不能靠提示.

### 6.2. 离 L3 还差什么, 以及读新闻时要问的问题

上面汇总表里的系统, 除 A-Evolve-Training 外, 都没有保留下来的改进器改动. 要让一个自动研究系统构成 L3, 1.2 第 4.5 节给的条件是: 候选改进器在声明的外部目标下, 用匹配的模型, 工具, 上下文, 算力和停止规则, 比在任的改进器产出更好的后续改动. 对程序搜索类系统来说, 这意味着要比较的是「演化后的搜索程序」和「原来的搜索程序」在新问题上的效率, 而不是比较它们找到的最好解. 现有的论文都只报告最好的解.

读一条自动研究新闻时, 可以依次问下面五个问题:

1. **最终的分数是谁给的?** 可执行的检查, 形式化证明, 人类评审, 还是一个语言模型审稿人?
2. **这个评分在搜索过程中被用过吗?** 被反复用于选择的榜单或审稿人, 给出的是开发证据.
3. **系统能不能碰到评分和约束?** 时间限制, 评估代码, 测试集标签放在哪里?
4. **保留下来的是产物还是 Agent 的组件?** 更好的算法, 论文或模型是产物. 跨轮保留并改变之后提出或选择方式的东西, 才涉及 L2 或 L3.
5. **成本和资源对齐了吗?** LEVI 和 MLReplicate 都显示, 成本和结果质量之间没有简单的对应.

## 7. 科学发现不是把论文流水线串起来

### 7.1 从问题到可证伪命题

自动研究的第一步经常写成「生成想法」, 这个说法太宽. 一个研究想法至少要落成研究对象、变量、干预、预期观测和可能推翻它的结果. 例如「改进优化器」只是方向; 「在固定参数量、令牌预算和数据顺序下, 把更新规则从 $u$ 换成 $u'$, 能否降低验证损失, 且收益不来自额外计算」才接近可检验命题.

设假设为 $H$, 实验设计为 $d$, 观测为 $y$. 一个有信息量的设计希望让不同假设对 $y$ 给出不同预测. 如果无论 $H$ 是否成立都可能得到同样结果, 实验即使成功运行也没有多少区分力. 自动系统常偏爱容易执行、容易得到正数值的实验, 因而要显式评估设计的预期信息增益, 不能只看预计提升.

可证伪性还要求预先写下失败条件. 如果指标上涨就说方法有效, 指标不涨就解释为预算不够, 任何结果都保护了原假设. 系统在运行前登记主指标、最小效应、数据排除规则和停止条件, 才能约束事后改故事. 探索实验当然可以灵活, 但它产生的是新假设, 不是确认性证据.

### 7.2 文献检索要恢复证据链

检索系统找到相关段落只是入口. 科学论证需要知道主张来自原始实验、综述转述、方法假设还是作者讨论. 自动研究者应保存文献版本、页码或章节、引用上下文和被引用的上游来源. 同一句话被几十篇二手材料重复, 仍可能只有一个原始证据.

时间也影响证据. 预印本与会议版本可能更换数据、修正定理或收回主张; 仓库代码和论文描述可能对应不同提交. 引用时绑定版本, 再检查关键结论是否在新版仍成立. 对无法访问的材料标记缺口, 不用搜索摘要补出实验细节.

检索偏差会塑造研究方向. 排名靠前、措辞相近和引用量高的论文更容易进入上下文, 负结果、旧术语和邻近领域被漏掉. 可以用多组查询、引文前向后向追踪和反方检索补全. 在形成假设后专门搜索失败证据, 比继续搜索支持材料更能减少确认偏差.

### 7.3 从相关性走向干预

自动分析大量日志很容易发现相关性. 某种提示与成功相关, 可能因为它只用于简单任务; 更长推理与高分相关, 可能因为困难任务获得了更多预算. 要主张方法有效, 需要控制混杂或主动干预. 随机分配、配对实验和交叉设计是最直接的工具.

当随机化不可行, 至少画出因果图, 列出共同原因、选择机制和中介变量. 系统随后知道该控制什么, 哪些控制反而会引入偏差. 例如只分析完成任务会形成选择偏差, 因为完成状态同时受方法与任务难度影响. 把中途失败从数据里删除, 会让最差方法看起来更稳定.

干预还要保持除目标变量外的预算一致. 新方法多调用一次模型、多训练几个 epoch 或使用额外数据, 提升不能全归因于算法. 同计算、同时间和同成本是三种不同公平条件, 最好分别报告性能前沿. 研究目标决定哪一种最重要.

### 7.4 发现与验证分开

同一 Agent 可以提出假设和执行实验, 但发现数据与验证数据需要隔离. 系统在开发集上反复搜索后, 最高分候选已经吸收了该集合的信息. 最终验证必须使用未参与选择的数据、独立随机种子和冻结代码. 否则所谓复制只是重新运行开发流程.

发现阶段保存所有候选和失败, 有助于估计搜索自由度. 只展示胜者会隐藏多重比较: 尝试一百个方案后出现一个显著结果, 与预先指定一个方案得到同样结果, 证据强度不同. 可以用密封复测或校正后的统计判断控制选择偏差.

验证者最好能从研究产物独立重建环境. 依赖、数据切分、随机性来源、硬件差异和执行命令都应固定. 若只有原 Agent 的长期记忆知道怎么运行, 论文和代码并没有形成可复制工件. 自动化越高, 越需要让产物脱离原会话仍可执行.

## 8. 实验设计决定自动研究的上限

### 8.1 对照、消融与交互作用

基线不是随便找一个旧方法. 它要回答「新增部件相对于什么带来收益」. 若方法同时改变模型、数据和预算, 至少需要逐项对照. 完整因子实验能估计主效应和交互效应; 预算有限时, 先围绕最可能的混杂做消融. 只比较完整新系统与弱基线, 无法知道收益来自核心想法还是附带资源.

消融也可能误导. 移除一个部件后其他超参数仍按完整系统设置, 性能下降可能来自配置失配. 更公平的做法是给消融版本合理调参, 同时报告调参预算. 如果部件只有在另一部件存在时有效, 这是交互作用, 结论应落在组合上, 不强行分配单项贡献.

负对照能发现管道问题. 换成理论上无效的随机部件, 如果仍得到同等提升, 评测或数据可能泄漏; 在不应受影响的任务上测试, 如果也大幅变化, 方法可能改了资源或测量. 正对照则验证实验有能力检测已知效应. 没有正对照的零结果, 可能只是实验灵敏度不足.

### 8.2 随机性与重复

训练与 Agent 搜索包含初始化、数据顺序、采样和环境响应等随机源. 单个种子提供一个样本, 最好结果更是带选择偏差的样本. 自动系统容易大量尝试后只保留胜者, 因此必须保存种子与全部运行, 报告均值、离散程度和失败率.

重复次数由要检测的效应和方差决定. 在实验前做功效分析, 可以避免样本太少却把无显著差异解释成等效. 若计算昂贵, 顺序实验允许边收集边判断, 但停止边界要预先设定. 每看到一次好结果就决定是否停止, 会系统性高估收益.

工程失败也属于结果. OOM、超时、数值崩溃和依赖错误若与方法相关, 不能从统计里删除. 报告成功运行条件下的性能, 同时报告达到成功的概率和资源. 一个偶尔达到高分、经常崩溃的方法, 与稳定稍低的方法服务不同场景.

### 8.3 数据切分与泄漏

科学 Agent 同时阅读论文、仓库、基准和先前实验, 泄漏路径比普通训练更多. 测试题可能出现在文献示例、代码注释、检索结果或评测器上下文. 仅检查训练文件是否包含测试文本不够, 还要检查语义变体、上游数据来源和工具缓存.

时间切分提供一种较强测试: 只允许系统使用截止日期前的材料, 让它预测或重建之后出现的结果. 这减少直接记忆, 但后续事实可能通过更新过的基础模型泄漏. 需要记录模型训练截止、检索索引版本和工具数据时间. 无法严格控制时, 结论写成回顾性重建.

项目级切分比随机样本切分更适合代码和论文复现. 同一仓库、作者或数据集的近邻样本若跨集合, 系统可能利用模板. 按母项目、时间或研究谱系切分, 才能测迁移到新研究对象. 切分单位应匹配希望泛化的单位.

### 8.4 多指标与结论选择

研究系统会产生许多指标: 主任务分、速度、成本、稳定性、样本效率和安全事件. 若运行后挑最显著的一项作为主结果, 假阳性率会上升. 预注册主指标和次指标, 其余标为探索性. 多指标不必强行求和, 权重缺乏依据时保留画像更清楚.

指标之间存在替代. 更高准确率可能依赖十倍计算, 更低成本可能来自更高失败率. 帕累托前沿比单一排名保留更多信息. 若必须选择部署点, 再根据具体预算和风险门槛决定. 论文层面的「最好」应说明位于哪种约束下.

代理指标需要与最终目标做周期校准. 自动研究常用评审分、基准分或验证损失快速筛选, 真正关心的可能是可复制的新知识. 代理一旦进入搜索, 候选会适应它. 定期抽样做昂贵独立评估, 估计代理与终点的关系是否漂移.

## 9. 复现不是把代码压缩成一个仓库

### 9.1 研究工件的谱系

一项结果依赖问题定义、数据、代码、配置、环境、随机种子、模型与人工干预. 自动研究系统应把这些对象组成有向谱系图: 每个产物由哪些输入和变换生成, 哪个版本进入最终图表. 只有最终脚本而没有谱系, 很难知道临时文件、手动修补或失败重跑是否影响结果.

工件采用内容哈希和不可变版本, 运行记录引用哈希而非「最新版」. 数据清洗、样本排除和图表生成也作为显式步骤. 若 Agent 修改代码后没有重新运行全部下游实验, 谱系图能标出哪些结果已经陈旧. 这比依赖模型记得自己改过什么可靠.

人工干预不能隐去. 研究者重写提示、修正代码、挑选图表或决定停止, 都改变了搜索过程. 记录干预的时间、原因和影响对象, 不会削弱成果; 它划清当前自动化边界. 若一项结果需要专家多次救援, 系统的自主研究能力就不能按端到端成功计算.

### 9.2 计算环境与确定性

锁定依赖版本只是起点. 驱动、硬件、并行算法和底层库可能引入非确定性. 可复现包应记录硬件型号、运行时、环境变量和确定性设置, 同时承认哪些操作仍无法位级复现. 科学结论通常不要求每个浮点数相同, 要求主要效应在合理环境变化下保持.

容器可以封装软件, 无法封装外部 API、消失的数据链接和按时间变化的模型服务. 对外部响应保存原始返回与时间; 条款允许时缓存必要数据; 无法缓存则提供接口版本和替代测试. 若核心结论依赖一个不可再访问的服务, 复现等级应降低.

确定性运行也不能替代重复. 固定种子只证明一个轨迹能重现, 不能说明结果稳定. 复现包同时提供精确回放和独立重采样入口. 前者用于定位差异, 后者用于验证统计结论.

### 9.3 独立复现的层级

最低层是重复运行: 同一代码、数据和环境得到相近结果. 再上一层是计算复现: 独立实现相同方法, 排除代码中特殊技巧. 更强的是概念复现: 换数据、任务或环境后仍观察到理论预期的效应. 三层回答的问题不同, 不能把重复运行写成独立发现.

自动 Agent 很适合做第一层, 因为它能搭环境和执行脚本; 第二层要求只读论文规范而不看原代码; 第三层还要理解机制并设计新场景. 评测自动研究能力时把三层分开, 可以看出系统是在复制命令、重建算法, 还是抓住了可迁移的原理.

复现失败也要分类. 运行失败可能是环境缺失, 数值不一致可能是实现差异, 效应消失可能是统计波动或原主张不稳. 先建立最小可运行例, 再对齐中间张量、数据统计和训练曲线, 最后比较结论. 直接盯最终分数, 难以定位分歧从哪里开始.

### 9.4 论文文本与证据同步

自动写作容易产生陈旧叙述. 实验更新后, 摘要数字、表格、讨论和结论可能不同步. 所有关键数字应从结果工件自动引用, 或由检查脚本比对. 文本里的比较对象、样本量和统计量也要绑定运行记录, 避免模型凭记忆填入近似数字.

图表需保留生成数据和脚本. 截图只能展示, 无法检查坐标、过滤和误差条. 自动系统生成图后, 还要验证轴单位、样本数、聚合方式和图注. 视觉上平滑的曲线可能由选择性种子或过度平滑产生, 数据工件才能支持复核.

引用必须支撑紧邻主张. 一篇论文讨论过相关主题, 不等于证明当前句子. 自动检查可以验证链接和文献存在, 语义支持仍需逐条核对. 对关键结论保存原文位置与自己的释义, 将事实、作者解释和本文推断分开.

## 10. 假设空间怎样搜索

### 10.1 新颖性、可行性与信息量

一个候选想法至少有三个轴: 与已有工作的距离、在当前资源下能否执行、实验能区分多少解释. 只优化新颖性会得到离奇但无从验证的命题; 只优化可行性会反复做熟悉的小改动; 只优化预期正结果会制造确认偏差. 候选先保留三维画像, 再按研究阶段选择, 比一次压成总分更透明.

新颖性不能只用文本相似度. 换术语重述旧方法可能距离很远, 两篇措辞相似的工作也可能在因果机制上不同. 检索已有方法的操作定义、关键假设和实验结果, 比较候选究竟改变了哪个部件. 若差异只在实现细节, 就按工程增量描述; 若改变机制, 需要给出可区分预测.

可行性包含数据、计算、工具、时间和验证能力. 能运行实验却无法判断结果, 仍不可行. 自动系统应在执行前估算资源区间, 列出关键依赖和失败后的降级方案. 估算不准可以更新模型, 但不能到预算耗尽才把未完成实验当负结果.

### 10.2 搜索树与研究谱系

研究过程可以看成树: 根是问题, 分支是假设, 节点是实验和观测, 后续分支根据证据更新. 只保存最终论文会丢掉搜索结构, 无法判断结果是预先预测还是事后解释. 保存谱系能看到哪些分支被证据淘汰、哪些因预算暂停、哪些合并成新假设.

分支选择需要兼顾利用和探索. 高预期收益分支快速产出, 高不确定分支可能打开新方向. 类似 bandit 的策略可以分配预算, 但奖励定义仍是核心. 若奖励来自短期论文分或基准提升, 搜索会远离重要但验证周期长的问题. 给探索预算设置独立份额, 能避免所有资源被当前评测器最熟悉的方向吸走.

树搜索还要防止重复. 不同 Agent 可能用不同语言提出同一实验. 通过结构化表示研究对象、干预和指标, 可以检测语义重复; 对近似候选合并证据, 保留差异条件. 去重不是删除少数观点, 若两个假设对某个边界条件预测不同, 它们仍值得分开.

### 10.3 失败怎样改变后验

实验失败并不总反驳假设. 可能是实现错误、统计功效不足或操作化没有触及理论变量. 自动研究者需要列出生成结果的层级模型: 假设是否成立, 干预是否有效, 测量是否可靠, 运行是否成功. 观测通过这几层产生, 任何一层故障都能给出零结果.

贝叶斯更新提供一种表达方式. 对假设 $H_i$, 观测 $y$ 后的权重满足

$$
p(H_i\mid y)\propto p(y\mid H_i)p(H_i).
$$

难点在似然 $p(y\mid H_i)$. 系统若在看到结果后随意调整似然, 更新就失去约束. 实验前写出定性或区间预测, 至少能判断结果更支持哪一边. 对实现失败, 不更新科学假设, 只更新对实验可行性的判断.

异常正结果同样需要分层排查. 效应远大于预期时, 先检查泄漏、单位、聚合和预算差异, 再谈突破. 自动系统容易把异常当高价值信号, 恰好因此更需要独立复测. 复测使用新种子、新数据和冻结分析脚本, 防止继续围绕异常调参.

### 10.4 何时停止一条方向

停止不能只由连续几次失败决定. 若每次实验都在提高测量质量或缩小参数区间, 方向仍在产生信息; 若正结果反复出现却无法独立复现, 继续扩大同类实验价值很低. 可按边际信息增益、剩余关键假设和下一实验成本共同判断.

方向停止后保存「墓碑」: 已测试范围、失败原因、仍未覆盖区域、重启所需新条件. 未来出现新工具或数据时, 系统可以重新评估, 无需重复旧路径. 墓碑也防止不同 Agent 周期性重做已知无效实验.

停止有时来自伦理和安全边界. 实验可能技术可行却需要不合适的数据、不可逆环境干预或过高外部风险. 这类停止记录限制来源与替代设计, 不把它归为科学假设失败. 研究能力包括知道哪些问题当前不应以某种方式回答.

## 11. 科研诚信是流水线性质

### 11.1 数据选择与结果美化

自动系统不需要有欺骗意图也会产生选择性报告. 搜索奖励偏好高分候选, 写作模块只读取胜者, 失败运行没有进入结果目录, 最终论文自然只剩正结果. 诚信控制要放在流水线里: 所有启动的实验自动登记, 状态只能标记完成、失败、取消或排除, 删除记录需要理由.

排除规则在看结果前定义. 数据损坏、运行超时和明显实现错误可以排除, 但每类都要保留数量和条件. 如果某方法更常超时, 把超时删除会高估它. 对异常值同时报告包含与排除结果, 让读者看到结论是否依赖少数决定.

图表美化也能改变结论. 截断坐标、只画最佳区间、平滑窗口过大和隐藏误差条, 都会放大视觉效应. 绘图脚本接受登记过的数据表, 默认展示完整范围与不确定性. 任何裁剪在图注说明, 自动视觉检查寻找轴和样本数异常.

### 11.2 引用、归属与重复发现

模型生成的想法可能来自训练记忆, 无法凭主观新颖感判断独立发现. 在宣称新方法前, 用方法组成、公式、关键短语和实验设定多路检索. 找到相近工作后比较时间与差异, 需要时把贡献改写成复现、扩展或重新发现.

引用归属追到原始来源. 后来的综述适合提供地图, 核心定理、数据和方法优先引用原论文. 如果原文不可访问, 明确通过二手来源得知. 自动系统不能编造页码、实验数值或作者动机; 检索不到就收窄表述.

代码也有归属. 从仓库检索到的实现可能带许可证和引用要求, 生成器改写变量名不会消除来源. 保存代码片段的出处、许可证和修改记录. 无法确认兼容性时, 独立实现算法描述, 不直接合并未知来源代码.

### 11.3 图像、日志和实验记录

科学图像可以由模型重画示意, 实验结果图必须来自真实数据. 两者在文件元数据与图注中区分. 对显微图、谱图等原始观测, 调色、裁剪和去噪操作保存脚本与参数, 禁止生成式补全缺失区域后当作测量.

日志应追加写入并由运行环境产生, 研究 Agent 不能为配合论文修改原始日志. 分析层可以创建派生表, 每个数值追溯到原记录. 若日志因隐私不能公开, 可提供受控审计、聚合统计和数据字典, 同时说明复现限制.

时间戳与提交记录帮助区分预测和事后解释. 假设、分析计划和主要代码在运行前形成快照; 结果出现后的探索放入新版本. 这不会禁止灵活研究, 只是让读者知道每个结论经历了多少选择.

### 11.4 自动审稿的边界

模型审稿能检查格式、明显矛盾、引用缺失和常见统计问题, 也能生成反例方向. 它与作者模型共享知识和偏差时, 深层错误可能同时漏过. 多个同源评审的一致不等于独立验证. 可执行复现、异源审阅和领域专家分别补不同缺口.

用来筛选论文的模型分数一旦反复返回写作循环, 系统就会逐渐适应该模型偏爱的措辞, 论文真实性未必提高. 文稿冻结后, 再用未公开的问题和独立复现结果测量主张质量, 这批结果不返回修改流程. 开发阶段的分数只描述文稿对当前筛选器的适配程度.

审稿意见也要可追踪. 每条关键批评指向具体段落、数据或实验, 作者响应说明接受、拒绝或新增证据. 泛泛的「讨论不充分」无法验证是否解决. 对意见冲突, 保留双方理由, 不让聚合器把争议压成平均分.

### 11.5 责任不能由 Agent 承担

自动系统可以记录决策、发现异常和执行检查, 责任仍落在部署与发表的人和机构. 谁批准数据使用、谁确认风险、谁签署结论、谁在事故后处理, 需要明确. 把模型列为作者或评审不能替代责任主体.

不同领域的底线不同. 医学实验、网络测量、用户数据和化学合成有各自伦理与安全要求. 通用研究 Agent 不应自行推断全部权限. 任务进入高风险领域时调用领域审批, 缺少批准就限制在模拟、公开数据或理论分析.

责任也包括纠错. 发现数值错误、代码漏洞或不可复现结果后, 系统要能定位受影响图表与结论, 生成更正并通知下游使用者. 版本化发布比静态 PDF 更适合自动研究, 前提是旧版本和更改原因仍可访问.

## 12. 怎样评测「发现」

### 12.1 终点不能只看论文分

论文评审分混合了写作、选题、实验与评审偏好. 自动系统提高分数, 可能只是更会组织文本. 发现层的终点应落在新预测、可复现效应、方法改进或解释力上. 对每项工作分别评估主张正确性、证据充分性、新颖性、可复制性和实际效用, 不用一个分数遮住结构.

正确性也有层级. 代码运行且数字匹配, 只能证明计算结果; 统计结论要满足设计假设; 因果结论还需干预或识别条件; 外部有效性要求在新环境保持. 自动评测器应给出它检查到哪一层. 用单元测试通过替代科学结论成立, 是把软件验证越级成知识验证.

研究效用可能延迟出现. 一个数据集、负结果或测量工具短期论文分不高, 却能支撑后续工作. 评测若只看即时新纪录, 系统会偏向容易展示的增量. 可以记录下游复用、预测命中和后续实验节省, 但这些指标需要较长窗口, 适合事后评价而非高频训练奖励.

### 12.2 回顾性发现与前瞻预测

让系统重建已知论文能提供可核查答案, 但可能受训练记忆影响. 更强的测试是时间切分: 给定某日期前材料, 要求提出之后被验证的方向. 评价时不仅看是否碰中结论, 还看当时能否给出合理证据和实验设计. 模糊预言很容易事后匹配, 具体预测才有区分力.

前瞻测试可以真正冻结预测, 等新数据到来. 代价是周期长, 样本少. 可以并行维护不同时间尺度: 短周期软件或模拟实验提供快速反馈, 中周期公开数据更新检验预测, 长周期真实科学结果用于校准整体主张. 快速任务不能完全替代长期发现, 它们只是训练信号.

回顾性任务仍有价值, 尤其用于诊断研究流程. 可隐藏关键论文, 让系统只见前置文献, 检查它在哪一步偏离: 没提出假设、实验不可行、分析错误, 还是写作没抓住结论. 但必须控制基础模型可能见过答案, 将结果称为流程重建而非独立发现.

### 12.3 与人类团队怎样比较

比较自动系统与人类, 要统一时间、算力、资料访问和目标. 系统一夜运行千次实验, 人类只给一小时, 结果不能解释为研究能力全面更强. 可以做同成本、同墙钟时间和同问题周期三种比较, 分别回答经济性、速度和端到端产出.

人类团队内部也差异很大. 与学生、领域专家或大型协作团队比较会得到不同结论. 报告参与者经验、可用工具和激励. 自动系统若大量依赖人类修复, 这些时间计入总成本, 同时单列系统自主完成比例.

盲评能减少身份偏见, 无法消除产物差异. 自动论文可能格式更统一, 人类审阅者据此识别来源. 更重要的是让评审只看证据包, 并在评分后做可执行复现. 喜欢哪篇文字和哪个结果能复现, 是两个不同终点.

### 12.4 任务集本身也会过拟合

ScienceAgentBench 一类基准把研究拆成可评测任务, 有利于比较. 多轮优化后, 系统会学习题型、目录结构和预期产物. 基准成绩上升不保证开放研究能力同步提高. 保留隐藏任务族、按时间加入新领域, 并测试完全不同的工具环境, 才能估计迁移.

任务难度不只看成功率. 有的任务因环境损坏而难, 有的因科学推理而难. 对失败进行机制标注, 检查基准是否覆盖检索、假设、设计、执行、分析和复现. 若大部分失败来自安装依赖, 基准主要测工程鲁棒性, 不能据此否定科学推理.

动态基准由模型生成新任务时, 需要人工或可执行验证题目本身. 无解、歧义和标签错会让强系统显得更差. 新题应保存来源、答案证据和难度校准, 使用一组未参与生成的系统复验. 能让当前模型答错只是候选条件, 还不等于高质量研究任务.

## 13. 从代码实验走向真实实验室

### 13.1 模拟器与现实之间

软件研究的动作容易复制和回滚, 物理实验包含设备误差、样品差异、安全限制与不可逆消耗. 在模拟器中找到的方案需要经过现实校准. 模拟器误差若与搜索方向相关, 优化器会主动找到最不真实的区域, 这与奖励黑客相同. 候选越极端, 越应怀疑它利用了模型边界.

可以用现实数据持续校准模拟器, 同时保留预测误差模型. 选择实验时不仅看模拟收益, 还看不确定性和离已验证区域的距离. 高收益高不确定候选适合小规模探测, 不适合直接放大. 新观测返回后更新模拟器, 形成模型与实验的闭环.

现实迁移要逐级扩大. 先做无害材料、低能量、小体积和低权限实验, 确认方向后再增加规模. 每一级设独立门槛和停止条件. 小规模安全不保证大规模安全, 放大可能引入散热、压力、动力学和供应链问题, 因而每级都需要新的风险分析.

### 13.2 测量与仪器控制

仪器输出不是直接真值. 校准、漂移、饱和、背景噪声和样品准备都会影响观测. 自动 Agent 需要读取校准记录、空白对照和标准样, 检查读数是否在有效量程. 只从最终 CSV 拟合, 很容易把仪器故障当新现象.

多仪器一致也可能共享样品或分析偏差. 尽量使用物理机制不同的测量通道, 例如一个测结构、一个测功能. 若结论依赖数据处理, 用替代分析和盲样检查. 自动系统应保存原始数据, 派生结果可重算, 不能只保留清洗后的表.

仪器控制接口限制参数范围、速率和组合. 模型提交结构化方案, 控制器验证硬件约束与互锁. 高风险操作需要人工确认, 紧急停止独立于模型. 即使研究 Agent 修改自己的规划代码, 也不能改写物理安全边界.

### 13.3 主动学习与实验选择

真实实验昂贵, 不能遍历候选. 主动学习选择最能降低模型不确定性的点, 贝叶斯优化平衡预期收益和探索. 二者都依赖代理模型的不确定性可信. 神经模型在分布外常过度自信, 因此加入距离、规则边界和随机探索, 避免所有预算集中到错误高置信区域.

批量实验还有相关性. 一批候选若非常相似, 并行虽方便, 信息增量有限. 选择时加入多样性, 覆盖不同机制和参数区间. 同时安排重复点与标准样, 用来估计批次效应. 没有这些校准点, 不同批次间的差异可能被误认成方法效应.

停止规则依据目标不同. 寻优任务可在预期改进低于成本时停止; 机制发现需要关键假设得到区分; 安全边界探索则在接近风险区域前停止. 一个通用的「连续若干轮没有提升」无法覆盖三种任务.

### 13.4 实验室安全和样品谱系

化学、生物和硬件实验都有领域专门风险. 通用模型可以辅助规划, 操作权限由领域规则和人员资质决定. 危险材料、温压、废弃物和设备互锁进入结构化检查, 不依赖自然语言提醒. 未知反应按更高风险等级处理.

样品从原料、制备、处理到测量都有身份. 条码和不可变记录防止混样, 每次拆分与合并生成谱系边. 若某批原料后来发现污染, 可以追踪所有受影响结果. 自动系统若不能确认样品身份, 应停止推断, 不能用相邻记录猜测.

真实实验的事故和近失事件都进入学习, 但不能直接让同一 Agent 自行放宽规则. 它可以提出修订和证据, 安全责任人批准后才更新控制面. 科学优化器追求信息和结果, 安全规则承担不同目标, 两者需要制度上的独立性.

## 14. 多 Agent 研究团队

### 14.1 角色名称不等于独立证据

规划者、实验员、分析员和审稿人可以由同一基础模型扮演. 角色提示带来流程分工, 没有自动带来认知独立. 它们共享训练数据、默认假设和语言偏好时, 会一起漏掉同类错误. 独立性来自隔离上下文、不同数据、不同验证机制和无法由被评者修改的证据.

提议者可以看到开发历史, 终审者只看冻结产物与预注册计划; 实验员负责执行, 没有权限改分析规则; 统计审阅读取原始数据, 不先看作者结论. 这些信息边界比给 Agent 起不同名字更重要. 同一个模型在严格隔离下可承担多个角色, 仍需承认剩余同源偏差.

### 14.2 交接与共享状态

研究交接要传递目标、当前证据、不确定性、失败记录和未决问题. 只传摘要会丢掉反例和来源. 关键主张使用结构化条目, 指向原始工件; 下游 Agent 若改变结论, 记录新增证据. 这样可以避免一句低置信猜测在多次摘要后变成确定事实.

共享研究状态采用版本控制. 两个 Agent 并发修改实验计划时, 各自的结果只对应自己的版本; 合并后必须重跑受影响部分. 冲突不能由最后写入者覆盖. 对数据、代码和论文分别建立依赖, 一处修改能找到所有陈旧产物.

讨论也可能造成信息级联. 先让成员独立提出假设和风险, 再交换证据, 可以保留初始多样性. 若一开始共享一个高置信答案, 后续成员往往围绕它补充理由. 比较讨论前后判断, 能看出共识来自新证据还是从众.

### 14.3 分工、成本与瓶颈

增加 Agent 数量不保证研究更快. 任务可并行部分有限, 交接和整合会增加成本. 文献搜索、独立复现和多组实验适合并行; 核心假设定义与最终因果解释需要共享语义. 如果每个成员使用不同目标定义, 并行只会制造难以合并的结果.

调度器应根据关键路径分配预算. 某个实验决定后续十个分支时, 优先提高它的可靠性; 边缘图表不应占用同等资源. 记录等待、重复和返工, 才能判断多 Agent 架构是否真正提高吞吐. 只数生成文档数量, 会奖励拆分本身.

团队瓶颈常在验证. 提议者能快速生成大量想法, 可执行实验和独立审阅跟不上, 候选队列便积压. 限制提议速率、提高初筛门槛或增加验证资源, 比继续扩充生成 Agent 更有用. 科研自动化的上限通常由最慢的可信证据环节决定.

### 14.4 分歧与仲裁

成员分歧应回到可区分实验. 让双方写出各自预测、关键假设和哪种结果会改变判断, 再选择信息量最大的实验. 直接投票只反映人数, 不衡量证据. 若争议是价值或资源取舍, 则交给有授权的决策者, 不伪装成科学事实.

仲裁者不能只读双方摘要, 需要访问原始证据和搜索遗漏. 对一方提出的反例, 检查复现; 对共同认可的前提, 主动寻找反证. 仲裁结果保存少数意见和剩余不确定性, 避免下一轮把有条件结论当成定论.

## 15. 自动研究的失败边界

### 15.1 能运行不等于理解

系统可以成功搭建仓库、调用训练脚本并生成表格, 同时不了解实验为何这样设计. 一个简单测试是改变关键假设: 换数据分布、移除某个机制或引入冲突结果, 看它能否预测变化并修订解释. 只能复现命令而无法处理反事实, 更接近流程自动化.

理解不是不可测的心理属性, 可以拆成预测、干预和迁移. 系统能否在实验前预测方向, 能否选择区分机制的干预, 能否把原理迁移到新任务. 三项都比自述「我理解了」有证据力. 文字解释只在与这些行为一致时发挥作用.

### 15.2 长链成功率

端到端研究由许多步骤组成. 若每步独立成功率为 $p$, $k$ 步全对近似为 $p^k$. 即使 $p=0.98$, 一百步完整成功率也只有约 0.133. 真实错误有关联, 这个简单计算仍说明局部高准确率不足以支撑长链自治.

解决办法包括在关键节点校验、保存检查点、允许局部回滚和缩短不可审计链. 每个阶段输出可验证工件, 后续不只依赖自然语言摘要. 错误越早被发现, 返工范围越小. 若所有检查推迟到论文完成, 一个早期数据错误会污染整条链.

长链还会积累目标漂移. 每次摘要、委托和重规划都可能轻微改变问题, 最后得到一篇内部完整但回答了另一问题的论文. 保存原始研究问题和明确的变更记录, 每个里程碑检查当前产物是否仍服务它. 合理改题可以发生, 需要被承认.

### 15.3 开放世界与未知未知

系统从已有文献和评测学习, 擅长在表达过的空间搜索. 真正的新变量、测量方式和跨领域连接没有现成标签. 搜索可以组合已有部件, 未必知道缺失了哪条轴. 人类观察、现实异常和跨领域协作仍是注入新坐标的重要来源.

未知未知无法列清单直接覆盖, 可以维持发现通道: 保存异常而非立即过滤, 给少量预算探索低先验方向, 邀请异质背景审阅, 定期更换任务与工具. 这些机制不能保证突破, 它们避免搜索空间被当前评测器完全封闭.

异常也常是噪声. 研究系统要在保留异常和追逐伪影之间平衡. 先重复测量、检查仪器和分析, 再扩大资源. 只有异常在独立通道保持, 才逐步提高优先级. 把每个离群点写成发现, 会快速耗尽验证预算.

### 15.4 科学目标与发表目标

论文是传播工件, 不是科学发现本身. 若奖励来自审稿分和可发表性, 系统会偏向故事完整、结果正向、周期短的项目. 重要负结果、基础设施和长期复制被低估. 评价组合应包含知识增量与证据质量, 并为负结果保留发布路径.

发表压力还会鼓励把一个完整结果切成多个小故事, 或在边界含混时选择更强表述. 自动系统能高速生成文本, 这个问题会放大. 项目级档案记录同一研究谱系的所有产物, 检查重复数据和重叠主张. 贡献范围由证据决定, 不由需要几篇论文决定.

最终读者需要知道哪些由系统独立完成, 哪些接受了人工选择和修改. 自动化比例不应成为需要美化的成绩. 清楚披露能让别人判断方法可迁移到何种团队和成本条件, 也为下一代系统提供真实基线.

## 16. 一条可审计的自动研究闭环

### 16.1 问题登记

项目开始时登记研究问题、适用范围、已有证据、允许的数据与工具、资源上限和安全边界. 问题要能区分探索与确认: 探索阶段寻找可能机制, 确认阶段检验冻结假设. 如果项目中途改题, 新建版本并说明原因, 不用新问题的结果回填旧预测.

文献地图同时记录支持、反对和未解决证据. 每个关键主张绑定原始来源与版本. 检索停止条件可以是新增文献不再改变假设结构, 不是凑够固定篇数. 若重要材料不可访问, 将其列为证据缺口.

### 16.2 设计登记

执行前冻结假设、干预、对照、主指标、排除规则、样本量、停止条件和分析计划. 代码与环境形成可重放快照. 探索性修改进入新分支, 结果标为探索, 不污染原确认实验. 这样既保留研究灵活性, 又能看出结论经历了多少选择.

风险审查和科学审查分开. 科学审查看实验能否区分假设, 风险审查看权限、数据、外部副作用和可逆性. 一个有信息量的实验也可能不适合执行; 一个安全实验也可能没有信息量. 两项都通过才进入队列.

### 16.3 执行与观测

运行系统从登记配置生成任务, 自动保存输入、版本、环境、随机种子、日志和原始结果. 失败运行保留状态, 不从分母删除. 资源超限、人工介入和重试作为事件记录. 任何对配置的临时修改产生新版本.

监控关注数据质量与安全, 不根据结果好坏决定是否中止. 发现传感器失效、数据泄漏或危险状态可熔断; 结果暂时不显著不是紧急停止理由, 除非预注册了无效性边界. 将科学停止和安全停止分开, 可以避免期待结果影响实验长度.

### 16.4 分析与反方检查

冻结分析脚本先生成主结果, 再进行探索分析. 系统输出效应量、不确定性、完整运行数量和失败分布. 对异常结果自动启动数据、代码、预算和泄漏检查. 统计显著只是一项证据, 还要看效应大小、稳健性和机制预测.

反方模块尝试用替代解释重现结果: 更强基线、额外计算、数据选择、评测偏差或随机波动. 每个替代解释对应一个最小区分实验. 无法排除时, 结论保留多种解释, 不让写作模块强行选出最完整故事.

### 16.5 独立复现与发布

最终候选冻结后, 独立环境用密封数据重跑. 复现者只接收方法规范和必要工件, 不读取作者的调试历史; 若目标是精确重复, 则提供完整环境. 两种复现分别记录, 避免把同环境回放当独立实现.

发布包包含论文、代码、配置、派生图表、原始或受控数据、实验登记、失败记录和已知限制. 文本关键数字从结果工件校验. 无法公开的部分说明访问与复核方式. 论文通过审稿后仍保留版本, 后续更正能追踪到受影响结论.

### 16.6 反馈进入哪里

一次项目结束后, 结果可以更新知识库、实验模板、技能库或评测标准, 四者影响不同. 新事实进入知识库前检查证据; 可复用流程进入技能库前在新任务验证; 评测规则修改需要独立锚点; 高风险权限不因一次成功自动扩大.

失败也进入系统, 但按失败族而非原样样本堆积. 保存触发条件、反例边界和修复证据. 若同一流水线既产生失败又批准自己的修复, 增加外部复核. 反馈闭环越深, 对证据独立性的要求越高.

## 17. 能力边界与现实判断

### 17.1 当前系统擅长的部分

自动研究在约束清楚、反馈可执行、实验便宜的领域最容易形成闭环. 程序搜索、超参数探索、代码复现和模拟环境都符合这些条件. 系统能并行尝试、保存轨迹并快速利用评测信号, 这正是 FunSearch、AlphaEvolve 和自动训练配方展示的优势.

开放问题、含混价值、昂贵现实实验和长周期验证更难. 瓶颈常在提出有区分力的问题、识别评测未覆盖的变量、判断异常是否真实, 以及承担现实后果. 写出完整论文只能证明流水线产出了论文, 还要独立检查知识是否成立.

### 17.2 进步应如何表述

当系统在固定任务上提高指标, 可以说它改善了该任务的搜索; 当它在密封任务迁移, 可以扩大到该任务族; 当独立团队复制方法并在新环境得到预期效应, 才有更强的机制证据. 从其中任何一步直接跳到「自主科学家」, 都丢掉了中间证明责任.

研究自动化并非只有全自动和人工两档. 系统可以负责检索、执行、分析或写作中的一部分, 人类在问题定义、异常判断和责任审批上保留位置. 评估时画出真实分工和成本, 才能比较不同方案. 最有价值的进步可能是把专家从机械工作中释放出来, 而非抹去专家.

自动研究最终要接受科学共同体的同一要求: 主张与证据匹配, 方法可复核, 失败可见, 引用准确, 风险有人负责. 速度与规模能放大这些原则, 也能放大每个漏洞. 先把证据闭环做实, 再讨论系统位于 L0 到 L4 的哪一层, 才不会把产物数量误认成发现能力.

### 17.3 一项成果的最小审计

拿到自动系统声称的新发现, 第一遍先看对象是否存在: 代码能否运行, 数据能否读取, 图表能否由脚本重新生成, 引用能否指向真实来源. 这些基础检查失败, 暂时没有必要评价宏大结论. 工件完整只能让后续审计开始, 本身还不证明主张.

第二遍重建比较. 新方法和基线是否使用相同数据、预算、工具与停止规则; 调参是否对双方公平; 失败运行是否进入统计; 最终结果是否来自预先登记的指标. 若比较条件不同, 先计算同预算或同成本结果. 无法重算时, 贡献收窄为当前配置下的观察.

第三遍检查选择自由度. 系统尝试了多少候选、种子、数据切分和指标, 最终展示为何被选中. 搜索规模越大, 独立复测越重要. 没有完整档案时, 最高分带有未知的乐观偏差. 补做密封复测比在原开发集上增加统计检验更直接.

第四遍追问机制. 如果作者说部件 A 通过机制 M 改善结果, 消融是否支持 A 的贡献, 中间观测是否符合 M, 替代解释是否有区分实验. 结果真实而机制解释错误仍是常见情况. 应分别保留「方法有效」与「解释成立」的证据等级.

第五遍看外部有效性. 在新任务、时间、数据或实现上是否保持, 失败边界在哪里. 一个窄域结果无需为范围小道歉, 但必须把适用域写准. 外推需要新的连接证据, 不能靠语言把一个基准扩展成整个科学领域.

第六遍审计风险与责任. 数据是否合法, 实验是否越过权限, 外部副作用是否记录, 谁批准高风险步骤, 谁能更正结果. 科学正确性无法抵消不合规实验. 反过来, 流程合规也不能证明结论正确, 两条审计线分别通过.

最后给成果分层: 可运行工件、可重复结果、独立复现、机制支持、跨域迁移和真实科学影响. 每升一层都需要新证据. 系统可以在前几层非常强, 后几层仍依赖时间与共同体检验. 这张阶梯比一个「自动研究成功率」更能显示能力落在哪里, 也更能指出下一轮该补什么.

审计结果进入后续训练时, 只把已经验证的部分写成事实. 未复现的异常保留为候选假设, 机制争议保留多种解释, 流程缺陷进入回归检查. 如果所有反馈都被压成一个奖励, 系统会学会复制高分产物的外观. 分层反馈让它知道究竟是工件、实验、解释还是边界出了问题.

还可以做一次逆向审计: 从论文最强的结论出发, 沿引用、图表、分析表和原始运行一路回溯. 任何一步无法找到唯一来源, 该结论就降级. 若同一运行被多个图表重复计入, 或不同实验实际共享同一数据切分, 逆向链也会暴露伪独立证据. 正向流水线保证产物能生成, 逆向链保证读者能从一句话追到观测.

逆向审计对负结果同样适用. 「方法没有改善」要追到实验是否有足够功效、基线是否正确、实现是否真的施加干预. 如果运行因资源不足提前结束, 结论只能是当前预算下没有观察到改善. 如果置信区间已经排除有实际意义的效应, 才能给出更强的否定. 自动写作模块应读取这些边界, 避免把流水线状态改写成科学事实.

成果进入知识库时附带证据等级与失效条件. 后续系统引用它, 同时继承适用域; 新实验若推翻前提, 能找到所有下游主张并请求复核. 自动研究真正扩大规模以后, 这种依赖管理会和实验本身一样重要, 因为错误知识的传播速度也会同步提高.

当证据仍有冲突时, 发布包保留冲突, 不让摘要替所有结果宣布胜负. 读者可以看见哪些实验稳定、哪些只出现一次、哪些解释仍待区分. 这种不整齐恰好是研究状态的一部分, 也为下一轮提供明确入口.
