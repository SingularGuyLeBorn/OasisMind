# RSI 安全视角：可靠的自改进需要独立监督

> RSI 专题精读。整理日：2026-08-12。综合：腾讯混元"可靠性阶梯"（L0-L4）、Anthropic 对齐研究、Argus verification-gated 思想。

## 核心命题

**自进化越深，风险越集中在一个矛盾上：谁来验证"改进"确实变好了？**

如果模型自己既当改进者又当裁判，它可能：
- 优化出"看起来更好但实际作弊"的解（reward hacking / 欺骗性度量）
- 通过自证合理巩固错误认知（自我强化的幻觉）
- 在无约束更新中累积灾难性遗忘（把安全知识也忘掉）

## 可靠性阶梯（腾讯混元 L0-L4 + 独立监督）

自进化按深度分五级，每级对应"证据与监督必须独立于更新边界之外"：

| 层级 | 进化目标 | 需要的独立证据 |
|---|---|---|
| L0 Output | 当前输出/动作 | 本任务可验证结果 |
| L1 Model | 可训练模型/策略 | 模型权重外部的评测集 |
| L2 Scaffold | harness/工具链 | 跨任务泛化评测 |
| L3 Improver | 改进机制本身 | 对改进机制的审计 |
| L4 Criterion | 评价标准/准则 | 外部价值判断（人/社会） |

**关键原则**：可靠的自进化**不取决于深度本身**，而取决于"评估与监督是否独立于对应更新边界之外、且覆盖相关任务/条件/约束"。

## 实操对策（按库内已有素材）

### 1. 验证门控（Verification-Gated）
- Argus 的做法：只有通过外部验证的状态才允许写入下一轮——把"能不能改"和"改了什么"分开管。
- 类比：git 的 CI 门禁——合并前必须过测试，测试脚本不属于开发者随便改的范围。

### 2. 外部红队与自对弈
- OpenAI GPT-Red：用独立训练的攻击者群体逼出漏洞，defender 群体保持攻击多样性防坍缩。
- 关键：攻击者和防御者是**同时训练的独立种群**，不是同一个模型的自我表演。

### 3. 对齐研究自动化但评估独立
- Anthropic AAR（Automated W2S Researcher）：9 个并行 agent 做对齐研究，但用**人类设定的 PGR 指标**衡量——研究者可以自动化，裁判标准必须留在人类手里。

### 4. 保留"不可变核心"
- 安全护栏、价值观准则、审计日志应放在自进化边界之外（L4 Criterion 层由人把控）。
- 类似持续学习里的"参数隔离"：把关键知识锁进不可写区域。

## 时间线压力（为什么现在要谈安全）

- Anthropic 预测 2028 年前 RSI 概率 60%；OpenAI 时间表 2028-03 全自动研究员。
- 窗口期只有 2-3 年：现在设计独立监督机制，比 RSI 落地后再补要便宜得多。
