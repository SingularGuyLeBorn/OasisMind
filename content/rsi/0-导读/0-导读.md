# 0 导读：递归自我改进从哪来、现在到哪了

**RSI（Recursive Self-Improvement，递归自我改进）** 的一句话：改进过后的系统，**继续当改进器**。卡住的不是「AI 会不会变好」——蒸馏、RL、技能包、搜 kernel 都会让某样东西变好——而是「变好之后，下一轮改进器是不是升级后的自己」。缺这一条，只是 self-improving；有这一条，才开始谈递归。

本篇给完全没听过这个词的人讲前世今生。术语判定表在 [01 术语辨析](../1-坐标系与术语/01-RSI-术语辨析/01-RSI-术语辨析.md)；Model / Harness / Artifact 的例子在 [02](../1-坐标系与术语/02-Model-Harness-Artifact/02-Model-Harness-Artifact.md)。OPD 公式回 [llm-guide 4.6](../../llm-guide/4-后训练/4.6-OPD/4.6-OPD.md)；产品级 Agent harness 回 [llm-guide 第 13 章](../../llm-guide/13-Agent/13-Agent.md)。本篇**不重推**那些公式，也**不把**融资访谈当机制。

## 1. 一句话，写成能读的符号

把「系统」写成 $S$：当前能被持久改写的那一坨——权重、脚手架、技能文件、记忆，哪一层被改就写进 $S$。把「改进器」写成 $I$：提议修改、选择修改、把修改装进去的那套程序。一次改进就是

$$
S' = I(S). \tag{1}
$$

**单轮自改进**允许 $I$ 住在 $S$ 外面：人、固定训练脚本、冻结的教师。改完之后 $S'$ 更好，但 $I$ 还是原来那个，下一轮仍由墙外的 $I$ 来跑。

**RSI** 多要一件事：$S'$ 里仍然带着改进器（记作 $I'$，$I'$ 可以就是改写过的 $I$），并且 $I'$ 还可以再作用一次：

$$
I' \subseteq S',\qquad S'' = I'(S') \text{ 有定义}. \tag{2}
$$

式 (2) 不是炫技。它只挡住一种最常见的偷换：产出物变好了，就宣布系统在递归改进自己。kernel 更快、论文更多、这一次 checkpoint 更强，都可以是 $S'$ 的一部分；只要 $I$ 仍停在墙外，递归就还没发生。判定清单、失效模式和更严的「证据必须在更新边界之外」写在 [01](../1-坐标系与术语/01-RSI-术语辨析/01-RSI-术语辨析.md) 与 [第 6 章](../6-评测与安全/02-可靠性与独立监督/02-可靠性与独立监督.md)。

![RSI 时间线：1965 Good → 2001 种子 AI → 2003–2006 Gödel machine → 2024–2026 实验室与能力项](./images/fig-rsi-origin-timeline.png)

> 图 1：RSI 前世今生的四个路标（自绘）。这是离散事件，不是分数曲线。

**图 1 解析**

- **1965，浅蓝**：I. J. Good 定义「超智能机器」，并写出智能爆炸——设计机器本身是智力活动，所以第一台超智能机器会设计更好的机器。
- **2001，浅橙**：种子 AI 把故事改成工程口号：先造能理解并改写自己源码的种子，不要一上来造橡树。
- **2003–2006，浅绿**：Schmidhuber 的 Gödel machine 把「自改代码」收成可证改写——证明搜索器也在可改的代码里。
- **2024–2026，浅金**：实验室把 RSI 写成安全能力项；公开生产里绝大多数仍不是「权重递归改自己」。
- **读图方式**：从左到右是叙事变硬，不是能力单调上升。右边的卡片与左边的定理不在同一度量上。

## 2. 前世：智能爆炸、种子、可证自改

### 2.1 Good 1965：超智能机器与智能爆炸

一手是 I. J. Good，《Speculations Concerning the First Ultraintelligent Machine》，*Advances in Computers* 第 6 卷，1965，第 31–88 页。[DOI](https://doi.org/10.1016/S0065-2458(08)60418-0)；Virginia Tech 重印 PDF 见 [VTechWorks](https://vtechworks.lib.vt.edu/items/5085379d-b24c-424e-8861-e70a47b4b2fb)；整卷可在 [Internet Archive](https://archive.org/details/advancesincomput0006unse) 核对目录（第 2 章即此文）。DBLP 条目写作者名为 Irving John Good。

Good 在 §2 把超智能机器定义成：**在一切智力活动上，远超过无论多么聪明的任何人**。设计机器是智力活动之一，于是：

> 一台超智能机器可以设计更好的机器；那时毫无疑问会出现「智能爆炸」，人的智力会被远远甩在后面。因此，第一台超智能机器是人类需要做出的**最后一项发明**——前提是这台机器足够温顺，会告诉我们如何把它置于控制之下。

这已经是 RSI 的非正式形态：改进器（设计下一代机器的能力）被装进被改进的对象里。Good 同时写了一句常被漏掉的条件——**docile enough to tell us how to keep it under control**。爆炸叙事从第一天就带着控制问题，不是 2020 年代才贴上去的安全彩页。

他还提到机器可以「逐渐改进自己、直到认不出来」。那是自改的雏形，但 1965 年没有可运行的证明搜索器，也没有「改权重还是改脚手架」这种分层。本篇把它当**问题陈述**，不当算法。

### 2.2 种子 AI：先造能改自己的种子

2000 年代前后，把 Good 的爆炸收成「自改源码」工程故事的，是种子 AI（seed AI）这条叙事。Eliezer Yudkowsky 的 *General Intelligence and Seed AI*（GISAI，文内称 version 2.3）把定义写在文首：

> A seed AI is an AI capable of self-understanding, self-modification, and recursive self-enhancement.

目标不是一次造出与人对等或超人类的心智，而是造一个**能增强自己、再用更高智力再增强自己**的心智，直到目标点。原文用橡树比喻：任务不是造一棵参天橡树，而是造一粒**humble seed**。我们核对的文本：[Wayback 2012-08-05 快照](https://web.archive.org/web/20120805130100/singularity.org/files/GISAI.html)（原 singularity.org）。文内版本号是 2.3；把「精确定义发表于 2001」写进时间线，依据是 Cunningham 术语年表（[Definitions of RSI](https://tecunningham.github.io/posts/2026-06-05-rsi-definitions.html)），本切片**未另找 2001 纸本**，标 `[OM-FREEPLAY]`。GISAI 是长篇设计笔记，不是已落地系统；本花园**不搬**其认知架构正文，只取「种子 vs 橡树」这一句工程含义。

同一条叙事后来在 LessWrong 2008-12-01 的 [Recursive Self-Improvement](https://www.lesswrong.com/posts/JBadX7rwdcRFzGuju/recursive-self-improvement) 里被拆成优化斜率、资源与效率：把「重新设计你自己的认知算法」交给 AI 当对象级问题，才叫递归；小改进若不能级联成更大改进，种子会 **flatline**。这仍是叙事与分析，不是 2026 的训练配方。

早期「自改代码」故事的要点只有三个：

1. 改进必须落在**自身**（源码、架构），不是只落在外部文档。
2. 每一档改进要打开下一档还能看见的改进机会，否则递归会停。
3. 人可以推第一段；递归一旦接上，人就不再是改进器身份。

2026 年产品里「Agent 会写 `SKILL.md`」常常只满足第 1 条的一个薄切片。不要把种子叙事直接贴到 CLI 功能上。

### 2.3 Gödel machine：先证明改写有用，再改写——包括证明搜索器自己

Schmidhuber 把 Good 的非正式议论收成一类**可证最优**的自指问题求解器。一手：[arXiv:cs/0309048](https://arxiv.org/abs/cs/0309048)（v1：2003-09-25；v5：2006-12-17）；作者主页 [Gödel Machine Home](https://people.idsia.ch/~juergen/goedelmachine.html) 写明：Gödel machine **formalize I. J. Good's informal remarks (1965)**。

机器的状态里有一段软件 $p$。$p$ 一开始包含：一个通常次优的环境策略 $e$，以及一个**证明搜索器**。搜索器枚举一对 $(\texttt{switchprog}, \texttt{proof})$，直到证明一条目标定理——大意是：**现在立刻用 $\texttt{switchprog}$ 改写 $p$，期望效用比继续让 $p$ 原样搜索更高**。然后执行 $\texttt{switchprog}$。$\texttt{switchprog}$ 可以改 $p$ 的任何部分，**包括证明搜索器自己**。

效用取「剩余价值」这种能读的形式（论文式 (1)，记号从简）：

$$
u(s,\mathrm{Env})
=
\mathbb{E}_{\mu}\!\left[
\sum_{\tau=\mathrm{time}}^{T} r(\tau)
\;\middle|\;
s,\mathrm{Env}
\right]. \tag{3}
$$

$r(\tau)$ 是时刻 $\tau$ 的奖励，$T$ 是寿命，$\mu$ 是环境可能服从的分布。目标定理比较的是两个假设状态（论文式 (2) 的可读版）：

$$
u\bigl[s(t_1)\oplus(\texttt{switchbit}=1),\,\mathrm{Env}(t_1)\bigr]
\;>\;
u\bigl[s(t_1)\oplus(\texttt{switchbit}=0),\,\mathrm{Env}(t_1)\bigr]. \tag{4}
$$

左边：在时刻 $t_1$ 把开关拨到 1，让 $\texttt{switchprog}$ 接管。右边：开关保持 0，继续用当前 $p$ 搜别的改写。全局最优定理要说的是：右边已经把「再搜下去可能找到的更好改写」算进继续搜索的效用里了，所以这不是贪心局部改。

请停在能读的程度。本篇**不抄**公理模式、六条证明指令和 BIOPS 初始化——那是论文 §3–§5 的讲义。读者只需要记住三件事：

1. **搜索器在证明上改进自己**：改写的许可来自形式证明，不是来自「看起来更好」。
2. **被改的对象包括改进器**：否则它仍是 Hutter 那类硬编码证明搜索，不是全自指。
3. **限制跟 Gödel 1931 年同一类**：算术够强的形式系统里，有真但不可证的句子。效用不可证的自改，Gödel machine 必须忽略；资源不够时，来不及证完的自改同样吃不到。

Gödel machine 可以在普通计算机上实现，不需要超图灵硬件。公开文献里有 Steunebrink & Schmidhuber 的实现尝试（AGI-11 / 2012 文集），那是理论机器的工程切片，不是 2026 年任何实验室的生产训练循环。它在本花园的位置是：**前世里最硬的「什么叫递归自改」形式**。今生的 SPIN、技能包、system card，都比它松。

![单轮自改进：改进器冻在墙外；RSI：S' 里仍有 I'](./images/fig-rsi-recursive-vs-oneshot.png)

> 图 2：单轮自改进 vs RSI（自绘）。左栏 $I$ 冻在 $S$ 外；右栏 $S'$ 仍含 $I'$。

**图 2 解析**

- **左栏灰虚线框**：改进器身份在系统外面。人、固定 SFT 脚本、冻结教师都可以住在这里。
- **蓝 $S$ → 绿 $S'$**：系统确实变好了。这就是 self-improving 伞下几乎所有 2024–2026 产品。
- **红叉 NOT recursive**：下一轮还是同一个墙外 $I$。缺式 (2)。
- **右栏橙框套绿 $I$**：改进器是 $S$ 的一部分。Good 的「机器设计机器」、种子 AI 的「改自己的源码」、Gödel machine 的「改证明搜索器」，都画在这里。
- **$I$ of $S$ → $S'$ 含 $I'$**：不是「又跑了一次同样的脚本」，而是改进器身份跟着升级（或至少被后继系统接任）。
- **底弧「improved system remains the improver」**：这句是本花园的度量零点。后面各章的例子先问这一句。

## 3. 今生 2024–2026：实验室叙事，还不是权重递归改自己

把前世接到现在，必须先拆开两件被口号揉在一起的事。

**第一件：AI 在加速造 AI。** 模型写代码、改训练脚本、跑实验、提 kernel。人还在选题、定指标、按合并键。这是真实的、可引用的趋势，它**还不是**式 (2)。

**第二件：系统完全自主设计并开发自己的后继者。** 这才是实验室公开文案里的 RSI。Anthropic Institute 的 [When AI builds itself](https://www.anthropic.com/institute/recursive-self-improvement)（Favaro & Clark）原句：

> Taken far enough, and given enough compute, that trend points to an AI system capable of fully autonomously designing and developing its own successor. This is called recursive self-improvement. We are not there yet, and recursive self-improvement is not inevitable. But it could come sooner than most institutions are prepared for.

同一页把「尚未到达」和内部生产率分开写：截至 2026-05，Anthropic 合入代码约 **80%+** 由 Claude 撰写；2026 Q2 每工程师合入行数相对 2024 约 **8×**（原文声明行数高估真实生产率）；给定目标的小训练加速实验，从 2025-05 约 3× 走到 2026-04 约 52×。这些数字支持「执行在自动化」，不支持「后继者已由系统全自主设计」。叙事、数字与缺口的展开在 [第 5 章 Anthropic 文](../5-实验室与公司/03-Anthropic-When-AI-Builds-Itself/03-Anthropic-When-AI-Builds-Itself.md)；**独立监督该怎么放**在 [第 6 章](../6-评测与安全/02-可靠性与独立监督/02-可靠性与独立监督.md)，本篇不重写安全专文。

OpenAI 走的是另一条公开轨道：把 **AI Self-improvement** 写成预备度里的**能力项**，而不是科普比喻。2025-04-15 的 [Preparedness Framework v2](https://openai.com/index/updating-our-preparedness-framework/) 与 [PDF](https://cdn.openai.com/pdf/18a02b5d-6b67-4cec-ab64-68cdfbddebcd/preparedness-framework-v2.pdf) 把 Biological/Chemical、Cybersecurity、AI Self-improvement 列为 Tracked Categories。次日发布的 [o3 / o4-mini system card](https://openai.com/index/o3-o4-mini-system-card/)（2025-04-16）写明：Safety Advisory Group 判定三个 Tracked Category **均未达 High**；AI Self-improvement 一节的摘要是——SWE-bench 一类「规格清楚的编码」变强了，但距离「胜任的自主研究助手」仍远，开放式任务差，故不够 High。更新的官方页 [GPT-5.5 · AI Self-improvement](https://deploymentsafety.openai.com/gpt-5-5/ai-self-improvement) 仍写 **did not meet High**；并把 High 复述为 **equivalent to a performant mid-career research engineer**。Critical 在 PF v2 Table 1 里与 recursively self-improving / 全自动 AI R&D 绑在一起。PDF 文本抽取乱码，本篇不把二手对 Table 1 的逐句转写升格成定理，精确操作化以 [PDF 原文](https://cdn.openai.com/pdf/18a02b5d-6b67-4cec-ab64-68cdfbddebcd/preparedness-framework-v2.pdf) 为准，标 `[OM-FREEPLAY]`。后续型号怎么读卡，见 [04 System Card RSI](../6-评测与安全/04-System-Card-RSI/04-System-Card-RSI.md)：GPT-5.6 全家 Self-improvement 低于 High，GA 页 RSI Index Sol 57.9 不是预备度证书。型号表在兄弟库第 14 章。

Anthropic 的 [Responsible Scaling Policy](https://www.anthropic.com/responsible-scaling-policy) 把 AI R&D 能力阈值拆开：能否完全自动化入门级 AI 研究，以及能否造成有效扩展速度的剧烈加速。RSP v3.0 PDF 把一条工作操作化写成：模型能否把 **2018–2024 两年的 AI 进展压进一年**。这是安全门槛，不是「已经 RSI」的证书。读卡步骤在 [04](../6-评测与安全/04-System-Card-RSI/04-System-Card-RSI.md)，不在导读里重做。

生产里绝大多数公开系统，对照式 (1)(2) 的落点是：

| 你看见的东西 | 改的是什么 | $I$ 在哪 | 本花园的词 |
|--------------|------------|----------|------------|
| OPD / MOPD 把教师压进学生权重 | 这一次训练作业里的 $\theta$ | 训练脚本在墙外，靶是教师分布 | 后训练；**不是 RSI** |
| SPIN / Self-Rewarding / STaR | 权重 | 损失与数据锚大多固定 | Model 层自改进；单轮**不是**递归 |
| 技能包、记忆、验证门控 runtime | Harness | 权重可冻结 | 弱 RSI **候选** |
| AlphaEvolve 类搜 kernel / 论文 | Artifact | Agent 可完全冻结 | 产物迭代；默认**不是** RSI |
| system card 上的 Self-improvement 分 | 评测项 | 不自动等于式 (2) | 能力项；见 [04](../6-评测与安全/04-System-Card-RSI/04-System-Card-RSI.md) |

田渊栋参与的 Recursive Superintelligence 公司是**实验室与融资叙事**，不是本篇要讲的机制。只指针：[第 5 章](../5-实验室与公司/01-RSI公司-田渊栋/01-RSI公司-田渊栋.md)。访谈不要抄进导读。

## 4. 先说清楚「不是」

四个邻居词经常和 RSI 排成一行口号。这里只钉边界，展开在 [01](../1-坐标系与术语/01-RSI-术语辨析/01-RSI-术语辨析.md)。

**不是 OPD。** OPD（On-Policy Distillation）是后训练算法族：学生按自己的策略采样，教师在学生前缀上给 token 级密监督。它改这一次训练里的学生权重，没有「改进改进器」。公式、MiniLLM / GKD 分叉、K3 MOPD 数字，全部在 [llm-guide 4.6](../../llm-guide/4-后训练/4.6-OPD/4.6-OPD.md)。本库禁止重推。把报告里的 OPD 说成 RSI，是 2026 第二常见的用词膨胀。

**不是 harness 产品。** Harness 是模型变成 Agent 的那一层：循环、工具、记忆、沙箱、技能包。一句话仍是 **Agent = Model + Harness**。Claude Code / Codex / Cursor 怎么写技能、怎么接 MCP，是产品问题，落在 [llm-guide 第 13 章](../../llm-guide/13-Agent/13-Agent.md)。本花园第 3 章只写「Harness 作为自进化的一层」：改的是下次怎么干活，基座可以冻结。会写 skill ≠ RSI。

**不是持续学习（CL）。** CL 问跨任务序列时旧任务会不会掉。EWC / Replay / GEM 是零件。RSI 系统如果会灾难性遗忘，递归可能把安全知识一并抹掉——所以 CL 可以被 RSI 征用，本身不是递归。

**不是测试时训练（TTT）。** TTT 问这一次输入上要不要当场改参数或状态。推理结束，这条适应通常不构成下一代改进器。Ilya / SSI 把 TTT 讲成后预训练时代的技术赌注，那是**叙事连接**：如果测试时更新可以稳定积累，它有可能成为递归的零件。不要把 TTT 论文直接标成 RSI。

## 5. 2026 还在变厚的几条轴（折进导读，不当主线）

RSI 不是 2026 年的唯一主题。下面这张表只帮你把邻居轴从本花园的门口请回各自的库，避免导读听起来像「年度口号清单」。改变了训练 / 推理 / 产品哪一块，就写哪一块。

## 6. 一张图走完三层：Model / Harness / Artifact

前世回答「递归是什么」。今生还要回答「改的是哪一层」。社区现在几乎都用同一套坐标，细节与例子在 [02](../1-坐标系与术语/02-Model-Harness-Artifact/02-Model-Harness-Artifact.md)。导读只用一张总图，避免你还没分清层就掉进 SPIN 损失或 AlphaEvolve 循环。

![三层：下 Model、中 Harness、上 Artifact；Agent = Model + Harness](./images/fig-rsi-three-layers.png)

> 图 3：三层地图（自绘）。顶栏是 RSI 判据；栈本身默认都还不是 RSI。

**图 3 解析**

- **顶栏桃底**：真 RSI 只问一句——升级之后改进器是不是还在跑。三层都可以被改；改完若不接任，递归仍缺席。
- **底层蓝 Model**：SPIN、Self-Rewarding、STaR、以及兄弟库的 OPD。改 $p_\theta$。一次或几次训练作业把权重抬上去，改进器（损失、数据锚、教师）常常不动。
- **中层绿 Harness**：循环、工具、记忆、技能。2026 产品里最常见的 self-improving：改干活方式比改基座便宜。新技能若被用来写下一版技能，是弱 RSI 候选，仍通常不改权重。
- **顶层金 Artifact**：kernel、论文、策略。Agent 可以冻结。AlphaEvolve 找到更快的矩阵乘，改的是 kernel，不是 Gemini 的作者身份。
- **左侧括号 Agent = Model + Harness**：编码榜不能只报模型名，分数是两者的乘积。这是系统事实，不是 RSI 证明。
- **右侧 produces**：Agent 产出 Artifact。产出回流进训练栈（更快 kernel → 更便宜的下一轮训练）仍可能整段发生在冻结 Agent 上。回流要单独论证是否写入了 Harness 或权重。

Awesome-Self-Evolving-Agents 还用过 Model / Experience / Co-Evolution。Experience 大致落在 Harness，Co-Evolution 落在多种群一起变。本花园不平行维护第二套分类；碰到这些词，映射回这张图。

混元综述另有更严的深度坐标：结构意义上的 RSI 从改改进器（L3）开始，在改评价标准（L4）加深。那是「有多深」，不是本花园的唯一定义。两套都要会用，写法在 [01](../1-坐标系与术语/01-RSI-术语辨析/01-RSI-术语辨析.md) 与 [第 6 章阶梯](../6-评测与安全/02-可靠性与独立监督/02-可靠性与独立监督.md)。
