# FunSearch：在函数空间里搜，不改自己

语言模型会写代码，也会一本正经地写错。科学发现要的是**可核对的新知识**，不是流畅的假证明。FunSearch（searching in the function space）把这件事收成一条窄设定：只接「好不好」能写成程序、跑完能打分的题。冻结的代码模型负责出新函数，评估器负责扔掉跑不通和分数差的。进化发生在程序数据库里，不发生在 $\theta$ 上。

本篇是 Artifact 层里 [9.3.2 AlphaEvolve](../9.3.2-AlphaEvolve-进化编码智能体/9.3.2-AlphaEvolve-进化编码智能体.md) 的前身。三层坐标见 [1.2 Model–Harness–Artifact](../../../01-研究框架与术语/1.2-Model-Harness-Artifact/1.2-Model-Harness-Artifact.md)。**不是** RSI：改进器 $I$（岛模型、best-shot 提示、$k=2$、骨架）在墙外，下一轮仍用同一套手续去改**另一份** `priority` / `heuristic`。**不是** SPIN / SEAL（那些改权重）。**不是** STOP / DGM / Gödel Agent（那些改 Agent 自己的脚手架或运行时）。一手：Romera-Paredes, Barekatain, Novikov, Balog 等，*Nature* **625**, 468–475（2024-01-18），[doi:10.1038/s41586-023-06924-6](https://doi.org/10.1038/s41586-023-06924-6)；DeepMind 博客 [2023-12-14](https://deepmind.google/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/)；代码 [google-deepmind/funsearch](https://github.com/google-deepmind/funsearch)。主实验用 **Codey**（PaLM 2 族上再训代码的模型），附录对照 **StarCoder**。采样量级约 $10^6$。

## 1. 问题：题可以难解，但不能难评

组合数学和在线算法里有一类题：找一个对象很难，**核对一个对象很容易**。最大独立集、约束满足、把物品塞进箱子，都属于「evaluate 多项式、solve 看起来不是」。FunSearch 只做这类：用户交一个 `evaluate`，再交一个可以很蠢的种子函数。目标是长出 `solve`，让它在关心的输入上拿到更高的分，并且最好超过公开纪录——超过公开纪录才比较像「训练语料里没有现成答案」，而不是模型在背。

直接让 LLM 吐「这 512 个向量就是 cap set」会失败：空间大、幻觉没有门。先前把 LLM 和进化算法接在一起的工作，多半停在合成题、搜网络结构、解谜。FunSearch 要把这条线推到**已经有人研究了几十年的公开题**。作者把成功拆成几件工程，而不是一句「模型更强了」：best-shot 把高分程序喂回提示；骨架把已知结构钉死，只进化最难想的那一小段；岛模型保多样性；采样和评估异步并行。

骨架是关键约束，也是关键加速。cap set 的 `solve` 是贪心：从空集出发，每次加入当前 `priority` 最高、且不破坏「无三点共线」的向量。装箱的 `solve` 是：对每个到来的物品，按 `heuristic` 给现有箱子打分，选最高的那个。FunSearch 只改 `priority` 或 `heuristic`，不改贪心外壳。外壳会切掉一部分程序空间，换来的是 LLM 不必每次重写已经知道的循环，出错面小很多。这和后来 AlphaEvolve 进化整文件、可到数百行，是同一条轴上的两个刻度。

## 2. 循环：采样、生成、丢弃、放回岛

用户最低限度交两样：`evaluate`，以及一个初始实现（可以是常数函数）。实践里再加骨架和 docstring，效果会好一截。之后进入异步三工种：程序数据库、采样器、评估器。

采样器向数据库要提示。数据库先抽一个岛，再在岛内偏向**分数高、代码短**的个体，取出 $k$ 个程序。主实验 $k=2$：两个比一个好，再加收益下降。两个函数按分数从低到高排成 `priority_v0`、`priority_v1`，提示末尾留下空的 `priority_v2` 让模型补全。这叫 **best-shot prompting**。模型不微调，只推理。主结果用 Codey；作者写对具体代码 LLM 不敏感，只要代码语料够——附录用开源 StarCoder 做对照。质量与速度之间他们选了快推理：整篇量级约 **一百万次**采样，而不是少数几次「想很久」。

评估器在一组输入上跑新程序。cap set 的输入是维数 $n$；装箱的输入是不同实例。多分用均值一类聚合收成总分。超时、超内存、输出不合法的直接丢掉，不进库。正确的才进岛。

岛模型（multiple population / deme）让若干子种群独立演化。周期性地：最差一半岛（按该岛最佳个体分数）清空，用幸存岛里某个精英克隆重新初始化。这样既有隔离探索，又有跨岛流动，避免所有岛锁在同一个局部最优。实现上典型规模：**15 个采样器 + 150 个 CPU 评估器**（大约五台 CPU 服务器，每台 32 路评估）。评估可以到分钟级，所以评估必须能水平加机器；LLM 推理放少量加速器。成本叙事是「评估用便宜 CPU，采样用少量加速器」，不是「一次调用一个巨大模型」。

$$
P'=\mathrm{LLM}\bigl(\mathrm{BestShot}_k(\mathcal{D}_{\mathrm{island}})\bigr),\qquad
\mathcal{D}\leftarrow\mathcal{D}\cup\{P':\ \texttt{evaluate}(P')\text{ 合法}\}. \tag{1}
$$

**图 1 解析**

- **User spec**：`evaluate` + 骨架 + 种子。种子可以是平凡常数。装箱实验的种子是 best fit。
- **Best-shot**：同一岛里抽 $k=2$，按分数标成 v0/v1，让模型写 v2。两个程序并排，模型才有机会做「合并想法」。
- **Frozen Codey**：PaLM 2 上的代码模型，**不在 cap set 或装箱数据上微调**。创造性来自采样，正确性来自评估。
- **Evaluator**：挡幻觉的那扇门。跑不通就不存在。
- **Program islands**：多样性的内存。最差一半岛被清空再克隆，不是单轨迹贪心。

分布式还有一层统计：LLM 采样和进化都有随机性。有的题每次 run 都能超过基线，只有幅度在抖——可容许集（admissible set）和在线装箱属于这类；$\mathcal{I}(12,7)$ 上 **60%** 的实验找到满规模可容许集。有的题必须大量重复：直接构造 $n=8$ 的 cap set 很难，**140 次实验里只有 4 次**发现大小 512 的集合。把 512 听成「按一下就出新定理」，和论文自己的成功率相反。

## 3. cap set：512 个向量，以及一条可阅读的程序

$\mathbb{Z}_3^n$ 里的 cap set：没有三个向量相加为零。几何上，没有三点共线。$n=2$ 时论文图 3 画了大小为 4 的例子。Tao 把它称作自己最喜欢的未决问题之一。精确最大值只对 $n\le 6$ 已知；$n=6$ 的最优是 Hill cap，大小 **112**。$n=8$ 时点集本身有 $3^8=6561$ 个元素，子集空间不能穷举。先前最好的高维构造常常依赖「用低维 cap set 拼起来」的复杂组合。FunSearch 的贪心骨架**没有**被明确教过这种拼法，从平凡 `priority` 往上长。

$n=8$ 时 FunSearch 找到大小 **512** 的 cap set，论文写明大于先前已知。后续评论把先前公开纪录写成 **496**；本篇以 Nature 正文「larger than previously known → 512」为主句，496 只作对照阅读，不以评论当一手。更重要的是产出形态：交出的不是 512 行坐标，而是一段 `priority` 程序。人读这段代码，会看到优先级依赖「位置 $i$ 与从末尾数的 $-i$ 是否同值」——于是有了 **reflection** 这个可手写的概念。团队再手工简化，得到图 4c 的显式构造。GitHub 笔记本里的 `build_512_cap()` 按重量（非零坐标个数）和 reflection 数分桶：重量 8 且 reflection $\ge 2$，再加若干重量 4 和重量 5 的族。这是 Artifact 层想要的那种可解释性：对象压缩成短程序，专家能读，还能改问题再搜。

渐近容量 $C=\sup_n c_n^{1/n}$。Ellenberg–Gijswijt 给出上界 $C\le 2.756$。下界走 **constant weight admissible sets**：用 $\{0,1,2\}^n$ 里一组同重量、支撑互异、且满足三点局部条件的向量，描述如何把低维 cap set 拼进高维。满规模记成 $\mathcal{I}(n,w)$。当时 SOTA 靠 SAT 解可容许集。FunSearch 同样进化 `priority`，从常数出发得到一个 $\mathcal{I}(12,7)$，单这一下把容量下界从 **2.2180 推到 2.2184**。读程序发现它对 $n=12$ 的四个坐标三元组 $\{0,4,8\},\ldots$ 高度对称，可容许集在这些三元组的独立循环置换下不变。人把这种对称写回搜索空间（更小、可到更高维），再搜到满规模 $\mathcal{I}(15,10)$（$C\ge 2.219486$）和部分 $\mathcal{A}(24,17)$（大小 **237,984**），推出新下界 **2.2202**。论文称之为二十年来对这条下界最大的一次改进，同时写明离上界仍远。

这条人机回路值得单独钉：模型没有改 `evaluate`，也没有改岛模型公式。人看见对称，**改了题的约束**，再把同一套 $I$ 跑一遍。发现仍在产物上；改题的是数学家。Jordan Ellenberg 在博客里的原话是程序比一串数字在概念上更富，读它们能学到东西——这是可解释性的证词，不是 RSI 的证词。

补充材料还做了 corners problem 和圈图的 Shannon capacity。主文以 cap set 和装箱为样板；其余只作「同一套手续换题」的存在性，数字以 SI 为准，本篇不展开。

**图 2 解析**

- **priority()**：给 $\mathbb{Z}_3^n$ 里每个向量打分，贪心外壳按分往 cap set 里加。
- **heuristic()**：给当前各箱剩余容量打分，外壳选最高分的箱。种子是 best fit。
- **Weights $\theta$**：Codey / StarCoder 推理，不微调。
- **Skeleton + evaluate**：人写。没有富的连续分数信号，FunSearch 会失效——定理证明被作者明确划到范围外，因为对错太稀疏。

## 4. 在线装箱：超额箱子，以及一种「只有很贴才用 best fit」的策略

在线装箱：物品一个个来，来了就要放进某个容量固定的箱子，不能后悔。经典启发式：first fit 放进第一个放得下的箱；best fit 放进剩余空间最小但仍放得下的箱。最坏情况理论界很多，实践里这两条用得最多。FunSearch 把启发式定义成：输入一个物品和各箱剩余容量，输出每个箱的优先级。种子从 best fit 开始。

训练用与 OR1 同等物品数的**生成**实例；测试用 OR-Library 的 OR1–OR4（物品数递增），以及 Weibull 采样（更接近真实调度）。度量是相对离线最优 L2 下界的**超额箱子比例**，越低越好。在线本来就达不到离线最优，所以 0% 不是必须打到的靶。

Nature Table 1：

| | OR1 | OR2 | OR3 | OR4 | Weibull 5k | 10k | 100k |
|--|-----|-----|-----|-----|------------|-----|------|
| First fit | 6.42% | 6.45% | 5.74% | 5.23% | 4.23% | 4.20% | 4.00% |
| Best fit | 5.81% | 6.06% | 5.37% | 4.94% | 3.98% | 3.90% | 3.79% |
| FunSearch | 5.30% | 4.19% | 3.11% | 2.47% | 0.68% | 0.32% | **0.03%** |

只在 OR1 规模上进化，测更大实例时差距还在拉开：OR4 上 best fit 4.94%、FunSearch 2.47%。Weibull 十万件时离 L2 下界只剩 0.03%。论文写装箱和可容许集一样，**每次 run 都能超过基线**，抖的是幅度。读表时记住：这是超额比例，不是分类准确率；也不是数据中心生产调度的墙钟——生产调度是后来 AlphaEvolve 才碰 Borg 的那条线。

读出来的启发式常有同一策略：并不总把物品塞进剩余最小的箱；**只有放进去之后贴得很紧**才用 best-fit 那种箱，否则放到另一个会留下更大空隙的箱，避免留下再也填不上的小缝。图 6 的短程序带人工注释。可部署性是作者反复强调的：交出来的是普通 Python，不需要为神经网络启发式准备专用硬件，规格也更容易目视检查。超启发式 / 遗传规划以前也进化过装箱规则，有的能追上 first/best fit，加上记忆甚至能超过 best fit；FunSearch 的差别被作者写成：变异算子来自在人类代码上训练的 LLM，不必手调遗传算子，并偏向写出短、像人写的程序。

## 5. 为什么搜函数：短、可读、才能到大实例

Discussion 把有效性拆成两层，都不要神化成「模型懂数学」。第一层：LLM 在 FunSearch 里主要是**语法正确、偶尔带点子的程序源**，对题意上下文用得不多；骨架再把它限制在关键函数上，每次只比种群里已有的稍微好一点，进化算法把这些边际改进叠成公开纪录。第二层：搜的是**生成对象的程序**，不是对象本身。结构化问题里，程序通常比枚举更短。论文举的例子：$\mathcal{A}(24,17)$ 的平凡表示超过二十万个向量，生成它的程序只有几行。作者把这称为偏向低 Kolmogorov 复杂度——最短程序的长度——并认为这是能扩到大实例的归纳偏置。传统直接搜构造物的手续没有这条偏置。

可读性是这条偏置的副产品，不是另加的损失项。人读可容许集的 `priority` 才看见四组三元组对称，再把对称写回搜索空间。对称解其实稀，FunSearch 仍更爱它们：指定对称对象所需的信息更少，再加上 LLM 在人类代码上训练、本来就会往「像人写的结构」靠。遗传规划没有这种人类代码偏置，还要手调变异算子。把「可解释」听成模型在教数学，过了；听成「短程序让专家能改题再搜」，才和实验吻合。

提示拼法也在为短程序服务。Methods：从岛里抽 $k$ 个后按分数**从低到高**标成 v0、v1；骨架里真正要进化的函数被剥掉，换成这 $k$ 个，再追加空的 v2；v0 之前出现的其它函数从提示里拿掉，避免上下文被样板代码占满。采样器对每个提示会抽**若干**个续写，提高吞吐。评估器只把跑通的送回数据库。这些都是 $I$ 的零件，实验里由人固定。

范围三条件再读一遍：高效评估器、富的分数、能拆出关键函数。定理证明被划出去，因为对错太稀疏。MAX-SAT 可以用满足子句数。corners 和圈图 Shannon capacity 放在补充材料，主文不当第二套主结果。博客写「第一次用 LLM 在困难公开题上做出新发现」——范围是「有自动评估器的组合构造」，不是任意科学发现，更不是模型权重在数学上自改进。

## 6. 不是 RSI：改的是作业，发现者不动

按 [1.1 术语](../../../01-研究框架与术语/1.1-RSI-术语辨析/1.1-RSI-术语辨析.md)：单轮 $S'=I(S)$ 在这里成立，$S$ 是当前 `priority`，$I$ 是「抽岛 + best-shot + Codey + evaluate」。RSI 还要 $I'\subseteq S'$ 且 $S''=I'(S')$ 有定义。FunSearch 的 $I$ 整段留在墙外：岛怎么淘汰、提示怎么拼、$k$ 取 2、骨架是贪心，都由人固定。下一轮 $I$ 去改的是另一份函数，不是 $I$ 自己。AlphaEvolve 白皮书后来加的 meta prompt evolution 才轻轻碰到「改搜索器自己的提示」；本篇 Nature 实验没有把那一层打开。$n=8$ 的 512 只在 140 次实验里出现 4 次：这是搜索的尾部事件，不是每次采样的均值。把期刊封面读成稳定能力，会和 Methods 的统计打架。

| | 进化对象 | $\theta$ | 评估 | 算不算 RSI |
|--|----------|----------|------|------------|
| FunSearch | 单个短函数（约 10–20 行） | 冻 | 单 CPU，论文对照里 $\le 20$ 分钟是后身表的刻度 | 否 |
| AlphaEvolve | 整文件、可数百行、可加速器评数小时 | 冻 | `evaluate` 仍在墙外 | 否 |
| DGM / STOP / Gödel Agent | Agent 自己的代码 / 改进器 / 运行时 | 冻 | 编码基准或元效用 | 弱候选 |
| SPIN / SEAL | 权重 | 动 | 人类数据或内环任务 | 训练式自改进 |

AlphaEvolve 白皮书 Table 1 把前两行并排：FunSearch 往往要数百万次采样、小模型就够、提示几乎只有以往解、单目标；AlphaEvolve 数千次采样、前沿 Gemini、提示可塞文献和执行反馈、可多目标。本篇是那张表的左列精读。矩阵乘那条线更早还有 AlphaTensor，不经过函数空间搜索；不要把 512-cap 和 48 次复数乘写进同一个机制句子。

失效条件作者写得很干净。(1) 没有高效评估器；(2) 分数几乎是二元的，没有「好一点」的梯度；(3) 不能把关键逻辑从骨架里拆出来。定理证明被举作反例。反过来，MAX-SAT 可以用满足子句数当富信号。范围不是「一切科学发现」，是「易评、难解、能写成函数」的那一刀。

**读**：$n=8$ 的 512；容量 2.2180→2.2202；Table 1 装箱超额；140 次里 4 次才摸到 512；$\theta$ 冻着；人读程序改对称约束。
**不读**：把 Nature 标题听成模型自己在做数学研究、把 512 听成按一次就出、把装箱 0.03% 听成已经改了 Borg、把函数空间搜索听成改了 PaLM 2 的权重。
