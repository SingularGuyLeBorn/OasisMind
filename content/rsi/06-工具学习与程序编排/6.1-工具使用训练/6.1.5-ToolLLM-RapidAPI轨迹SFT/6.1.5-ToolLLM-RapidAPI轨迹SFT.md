# ToolLLM：轨迹 SFT 调一万六千 API

作者把 ToolLLaMA 写成和教师 ChatGPT 几乎打平、只略低于 GPT-4。打开 ICLR 2024 相机稿 Table 4：ToolLLaMA+DFSDT 六列均 pass **66.7**、均 win **60.0**。ChatGPT+DFSDT 是 **64.8 / 64.3**。pass 上学生略高，win 上教师更高。GPT-4+DFSDT 才是 **71.1 / 70.4**。禁止把 66.7 听成准确率柱，也不要用它改 [Gorilla](../6.1.4-Gorilla-API调用微调/6.1.4-Gorilla-API调用微调.md) 的 Oracle TorchHub **67.20**，更不要碰 [ReTool](../6.1.1-ReTool-代码解释器RL/6.1.1-ReTool-代码解释器RL.md) 的 AIME2024 **67.0**、[ToolRL](../6.1.2-ToolRL-多工具奖励设计/6.1.2-ToolRL-多工具奖励设计.md) 的 API-Bank **67.00**。四格小数点碰到一起，分母分别是 ToolEval pass、AST、32 次平均、API-Bank。Xu 等 2023 另有一份也叫 ToolBench、只有 **232** 个 API，Table 1 末列就是它。本篇 RapidAPI **16464**，不要两份题库收成一只。

本篇落在 6.1 工具使用训练。SFT 改的是 \(\theta\)。留下的是 LLaMA-2-7B 权重。RapidAPI 过滤、ChatGPT 教师、DFSDT、ToolEval 那只 ChatGPT 裁判、BERT 检索器、位置插值到 8192，全在墙外。坐标系见 [1.2 三层](../../../01-研究框架与术语/1.2-Model-Harness-Artifact/1.2-Model-Harness-Artifact.md)；信号类型见 [1.3 模仿与 RLVR](../../../01-研究框架与术语/1.3-模仿学习与RLVR/1.3-模仿学习与RLVR.md)。这边更像模仿：金标路径是 ChatGPT 搜出来再留下的，没有 boxed、没有 Jaccard、没有 PPO。**不是** RSI。**不是** 术语式 (2)。**不是** Gorilla：那边 ML Hub **1645** 张卡、AST 子树、单次调用。**不是** ToolRL：那边 GRPO 拆槽位，榜是 BFCL。**不是** [ReAct](../../../05-搜索规划与提示优化/5.2-推理搜索与规划/5.2.3-ReAct-推理与动作/5.2.3-ReAct-推理与动作.md)：ReAct 冻 PaLM，这边把 DFSDT 轨迹写进权重，测试时还可以再开搜索。一手：Qin, Liang, Ye, Zhu, Yan, Lu, Lin 等；清华 / OpenBMB；[arXiv:2307.16789](https://arxiv.org/abs/2307.16789)；**ICLR 2024**；代码 [OpenBMB/ToolBench](https://github.com/OpenBMB/ToolBench)。数字以会议 PDF Table 1–5、§2–§3、附录 A.1–A.5 为准。

## 1. 问题：开源模型不会调真 REST，标路径又太贵

Gorilla 把范围收在三个 ML Hub，一次调一只模型卡，评测看 AST。作者的判断是：真实需求会把几把工具交错起来，还要读真实返回再决定下一步。闭源模型已经靠 function call 在干这件事；开源这边 Vicuna / Alpaca 那种对话 SFT，工具域是空的。Table 4 里两只在六列 pass / win 全是 **0.0**。不是「7B 太小」，是指令微调没覆盖工具。另一头，人手标「这题该调哪几个 API、参数怎么填、失败了怎么撤」标不动 1.6 万个接口。GPT-4 自己用 ReAct 也经常找不到合法路径，标注效率低。

他们把框架收成三截：造数据、训模型、自动评。数据叫 ToolBench。RapidAPI Hub 上先刮 REST 接口。最初收到 **10853** 个 tool、**53190** 个 API。附录 A.1 两道过滤：先测基本能不能调；再看示例响应的时延和质量，太慢、HTML 源码、报错页都丢掉。落到 **16464** 个 API、**3451** 个 tool、**49** 个粗类（体育、金融、天气一类），另有 500+ 个 collection 细类。16464 不是「RapidAPI 上的全部接口」，是过滤后还能当训练环境的那一截。一个 RapidAPI key 就能测这些接口。层级是 category → tool → API，一张卡里有功能说明、HTTP 方法、必选 / 可选参数、请求体、调用代码片段、示例返回。Table 1 把 Gorilla 的 APIBench 写成 1645 个 API、3 个 tool、**0** 次真实调用、平均推理迹 **1.0**、实例 17002。本表 16464、3451、真实调用 **469585**、平均迹 **4.0**、实例 **126486**。1645 和 16464 差一个数量级，不要口算成「大约十倍 Gorilla」。API-Bank 在这张表里是 53 个 API、568 次真实调用、平均迹 2.1；后来 ToolRL 用 API-Bank 当问答向工具榜，不是本篇主表。ToolAlpaca 是 400 个 API、0 次真实调用。Xu 等 2023b 那份也叫 ToolBench：8 个 tool、**232** 个 API、3926 次真实调用、平均迹 **5.9**。5.9 高于本表 4.0，尺度却是 232 对 16464，禁止两份题库收成一只。

指令不靠人写满。从全集抽样一批 API，喂给 `gpt-3.5-turbo-16k` 的 function call：让它写出用得上这些接口的自然语言，并标出相关 API 子集。单工具种子 **12** 条、多工具 **36** 条，每次抽 3 条 in-context。单工具指令 \(I_1\) 按 tool 遍历。多工具不能在 3451 个 tool 里随机搭配，功能对不上。他们用 RapidAPI 的类和 collection：同一类或同一 collection 里抽 2–5 个 tool，每个最多 3 个 API，得到类内多工具 \(I_2\)、collection 内多工具 \(I_3\)。幻觉出来的相关 API 不在抽样集合里就丢掉。过滤后大约 **20 万** 条 (instruction, relevant API)：\(I_1\) **87413**，\(I_2\) **84815**，\(I_3\) **25251**。87413+84815+25251=197479。这还不是训练分母。训练要的是带真实调用的路径。附录 A.7：教师每次被要求写 **10** 条查询，前 7 条要具体、后 3 条要复杂长场景；相关 API 必须落在当次抽样集合里，不同查询之间重叠尽量小。单工具种子会要求一条查询把同一 tool 的多只 API 交错起来，只调一只不算。多工具种子禁止只动一把 tool。Figure 3 右侧那句电影夜示例（山上过夜、推荐片子）是指令形态，不是主表一格。人写的 12 / 36 条种子才是调节教师行为的 \(I\)；其余指令都是抽种子再生成。换这 48 条，20 万条的分布会漂。压缩策略同样：ChatGPT 看一份工具文档加一条示例返回，再配 3 条人手写的「原返回 → 压过的 schema」，给每个 API 抽出删键规则。超过 1024 才压，压完仍长就截前 1024。换这 3 条示范，等于人改响应 \(I\)。

## 2. 机制：DFSDT 给教师撤步，SFT 只吃通过的路径

路径标注把多步决策收成多轮对话。第 \(t\) 轮教师根据历史调用和真实返回 \(r\) 写出动作 \(a_t\)：Thought、API Name、Parameters。额外两个函数：`Finish with Final Answer` 交卷，`Finish by Giving Up` 放弃当前节点。CoT / ReAct 的两个坑写在 §2.3：一步填错会锁进坏循环；只探一条路，动作空间几乎探不到。GPT-4 也经常标不出合法路径。DFSDT 把搜索收成树：可以沿一条看起来有希望的路走，也可以调用放弃函数、扩一个新节点。扩子节点时把已经生成的节点喂回去，明确要求写出不同的下一步。他们选深度优先而不是广度优先：只要找到一条通过的路径就可以停，BFS 会多烧 OpenAI 调用。附录 A.4 再砍一刀：经典 DFS 要给子节点排序，LLM 两两比大约 \(O(n\log n)\) 次调用；他们发现排第一的常常是先生成的那个，于是改成先序遍历，跳过排序。简单题不撤步，DFSDT 退化成 ReAct；复杂题仍能探开。ToolLLaMA 虽然吃的是 DFSDT 标出来的数据，**测试时可以走 ReAct，也可以走 DFSDT**。搜索策略是 \(I\)，不是 \(\theta\) 长出来的。

只留通过的路径，得到 **126486** 对 (instruction, solution path)。从约 20 万指令收到 12.6 万，差的是没标过或没通过的。这 12.6 万才拿去 SFT。骨干 **LLaMA-2-7B**。原上下文 4096，API 返回太长，位置插值扩到 **8192**、插值比 2。附录 A.3：学习率 \(5\times 10^{-5}\)，warmup **0.04**，总 batch **64**，**2** epoch，按开发集挑 checkpoint。function call 字段怎么拼他们不清楚，直接拼进输入当提示。多轮对话格式尽量对齐 ChatGPT。响应超过 1024 token 先按教师从示例里抽出的 schema 压掉次要字段，还长就截前 1024。压缩策略也是教师写的，换 schema 等于人改 \(I\)。

检索器另训。Sentence-BERT，BERT-base，指令和文档编码后算相似度。正例是 §2.2 标的相关 API，负例随机抽。Table 2：他们的检索器 NDCG@1 在 \(I_1/I_2/I_3\) 是 **84.2 / 68.2 / 81.7**，均 **78.0**；@5 是 **89.7 / 77.9 / 87.1**，均 **84.9**。BM25 均 @1 只有 18.5。Ada-002 均 @1 49.6。\(I_2\) 最低，类内多工具比单工具难检。测试主表除最后一行外都喂 **oracle** 相关 API，模拟用户已经圈定接口。最后一行 DFSDT-Retriever 改喂检索器 **top-5**。

ToolEval 是 ChatGPT 裁判，学 AlpacaEval。没有固定金标路径：RapidAPI 会改版，一题也可以有无数条对的路。Pass：有限预算里是否完成指令。Win：同一指令两条路径，裁判按预写标准挑更好的。Pass 要先判指令可解不可解。可解时，放弃函数只有在「接口都试过、什么有用信息都没拿到」才算过；交了最终答案但拒答或没解决问题算不过。不可解时，放弃或拒答反而算过，自己编一段「我做完了」算不过。路径标签是 Pass / Fail / Unsure。每次至少 **4** 次 ChatGPT 预测再多数票。Win 只在两条同为 Pass 或同为 Fail 之间比，标准写了六条：信息是否够、是否属实、失败理由、里程碑数、是否多探了有用接口、同样接口数下少重复调用。附录写人专家自己也会吵：有人喜欢少调几次赶紧交，有人喜欢把接口试遍交叉验证。和人对齐：pass **87.1%**，win **80.3%**。样本是四种方法各 300 条。Table 4 的 win 把平局拆进胜负两边；附录 Table 6 未拆，ToolLLaMA-DFSDT 均 win **55.2**、tie **9.8**，55.2+9.8/2=60.1，才对得上主表 60.0。ChatGPT-DFSDT 未拆是 56.9 / 14.7。Retriever 行未拆 **59.2 / 7.8**，59.2+7.8/2=63.1，对得上主表 win 63.1。学生 ReAct 未拆 42.1 / 9.8。GPT-4-DFSDT 未拆 64.2 / 12.4。花园主表仍报 Table 4。人对齐不是六列全测：四种方法各抽 300 条；pass 对齐的是 ChatGPT-DFSDT、ToolLLaMA-DFSDT、GPT-4-DFSDT；win 对齐的是 ChatGPT-ReAct 对 ChatGPT-DFSDT。87.1 / 80.3 钉在这份抽样，不要听成「裁判已经等于人」。可解时，交了最终答案但接口全程没给有效信息、模型已经把接口试遍、最后仍拒答，也可以算 Pass；不可解时，放弃一律 Pass，自己编「我做完了」才 Fail。可解时只试了几把就放弃，Fail。这把尺比 AST 软，也比 boxed 软。换裁判提示，66.7 会漂。不可解加放弃也算 Pass，会把「认输得对」记进通过率，不要听成六成指令都答对了。

Table 3 是标注阶段、ChatGPT 当解题器，不是 Table 4。ReAct 均 pass **35.3**（I1 37.8、I2 40.6、I3 27.6）；同等费用多次 ReAct（ReAct@N）**44.5**（49.4 / 49.4 / 34.6）；DFSDT **63.8**（58.0 / 70.6 / 62.8）。\(I_2\) 上 DFSDT 70.6 对 ReAct 40.6，比对 \(I_1\) 的 58.0 对 37.8 更宽。ReAct@N 在 \(I_3\) 只到 34.6，仍低于 DFSDT 的 62.8：多开几次单路，补不回撤步。作者写成难指令更吃搜索。花园把它留在标注效率：同样预算能标过更多题。不要把 63.8 填进 Table 4 的 66.7。63.8 是教师自己解题的通过率；66.7 是学生在六列泛化上的通过率。两套分母，教师那张甚至不是 Inst/Tool/Cat 切法。

## 4. 这不是 RSI，也不是放大版 Gorilla

\(S\) 取当前 \(\theta\)。单轮 \(S'=I(S)\) 成立：2 epoch 之后下次推理用新权重。术语式 (2) 还要 \(I'\subseteq S'\)。16464 张卡、ChatGPT 教师、DFSDT 先序、ToolEval 提示、BERT 检索、8192 插值、响应截断 1024，都不进 \(\theta\)。模型不能把裁判从 ChatGPT 换成 AST 来追 Gorilla 的 59.13，不能把 top-5 改成 Oracle 来报 67.3，不能把 Vicuna 的 0.0 听成「开源已经会调工具」。混元台阶上这是 **L1** 的轨迹模仿。和 [1.3 模仿与 RLVR](../../../01-研究框架与术语/1.3-模仿学习与RLVR/1.3-模仿学习与RLVR.md) 表里的 ReTool / ToolRL / ToRL 不是同一格信号。

和邻居钉死。[Gorilla](../6.1.4-Gorilla-API调用微调/6.1.4-Gorilla-API调用微调.md) 是 1645 张 ML 卡、一次调用、AST；本篇 16464 个 REST、平均 4 步、ChatGPT 裁判。Table 5 的 51.16 不要填进 Gorilla 的 59.13。[Toolformer](../6.1.6-Toolformer-自监督插工具调用/6.1.6-Toolformer-自监督插工具调用.md) 是五只固定工具、GPT-J 6.7B、按损失差过滤，T-REx 53.5 不要改本表 66.7。[ToolRL](../6.1.2-ToolRL-多工具奖励设计/6.1.2-ToolRL-多工具奖励设计.md) 相关工作把 Gorilla / ToolLLM 收成轨迹 SFT；本篇没有 Jaccard，没有 BFCL 52.98。[ToRL](../6.1.3-ToRL-从基座做工具RL/6.1.3-ToRL-从基座做工具RL.md) 从 Math Base 做 GRPO，greedy 43.3；43.3 不要改 66.7。[ReTool](../6.1.1-ReTool-代码解释器RL/6.1.1-ReTool-代码解释器RL.md) 的 67.0 是 32B、32 次平均。[LATM](../../6.2-工具创建与文档优化/6.2.1-LATM-函数缓存造工具/6.2.1-LATM-函数缓存造工具.md) 留下一类题的 Python，不改 \(\theta\)。[EASYTOOL](../../6.2-工具创建与文档优化/6.2.2-EASYTOOL-工具文档改写成指令/6.2.2-EASYTOOL-工具文档改写成指令.md) 改已有 REST 的说明书，也不改 \(\theta\)；两列均 pass 69.8 不要改本表 66.7。[ReAct](../../../05-搜索规划与提示优化/5.2-推理搜索与规划/5.2.3-ReAct-推理与动作/5.2.3-ReAct-推理与动作.md) 是 DFSDT 退化时的那条单路；AlfWorld 71% 不要改本表任何一格。[ToT](../../../05-搜索规划与提示优化/5.2-推理搜索与规划/5.2.1-ToT-本题推理树/5.2.1-ToT-本题推理树.md) 被相关工作写成并发：ToT 的动作空间小、可以暴力搜；DFSDT 面向无限决策。种子任务仍是人写的 12 / 36 条，Self-Instruct 手续见 [2.1.2](../../../02-模型自改进与自训练/2.1-自生成数据与自奖励/2.1.2-Self-Rewarding-家族/2.1.2-Self-Rewarding-家族.md)，教师是 ChatGPT 不是被微调的 7B。

作者把结论写成开源 7B 可以掌握未见 API。花园读成：在 RapidAPI 过滤后的 16464、ChatGPT-DFSDT 标过的 126486、ToolEval、oracle 相关集合、测试时再开 DFSDT 这套 \(I\) 里，均 pass 可以走到 66.7。不是「人可以退出 \(I\)」。关掉 DFSDT 只剩 29.0。换检索 top-5 均 pass 再高 0.6，I2-Cat 反而掉。教师和裁判都是 ChatGPT 家族，标注分布和验收分布同族；66.7 含这份亲缘。人专家对「哪条路径更好」会对着干，80.3% 的 win 对齐已经把这份吵写进附录。局限写在机制里：API 会改版，所以不钉金标路径；响应要压到 1024；先序遍历省钱，不等于搜全了树。安全性几乎没有：会调 REST 的策略也可以调错接口、打到付费额度。可靠性专文要的墙外监督，这里缺一份。位置插值比 2、开发集选 checkpoint，同样是人钉的训练 \(I\)。
