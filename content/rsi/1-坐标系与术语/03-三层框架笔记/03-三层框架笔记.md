# 03 社区三层：名字能用，判定不能照搬

2026 年中文技术圈把 self-evolving / RSI 收成三层：改产物、改脚手架、改权重。花园 [02](../02-Model-Harness-Artifact/02-Model-Harness-Artifact.md) 沿用 **Artifact / Harness / Model** 这组名字，方便和专栏、播客对上号。判定不沿用。「三者都算 RSI」和 [01 术语](../01-RSI-术语辨析/01-RSI-术语辨析.md) 冲突：产物迭代默认不是递归；脚手架自改最多是弱自改进；单轮训练也不是式 (2)。

本篇是第 1 章的线索页，不是第二份机制专文。学术闭环见 [05 综述](../05-自进化Agent综述/05-自进化Agent综述.md)。机构通稿见 [第 5 章](../../5-实验室与公司/5-实验室与公司.md)。**不要**把知乎专栏的口算（训练加速百分比、合入代码占比、融资估值）写进判定。那些数字以各专文的 arXiv / 官方 blog / system card / 仓库 README 为准。

## 1. 三层在花园里怎么用

| 社区说法 | 花园用法 | 默认是不是 RSI |
|----------|----------|----------------|
| Artifacts：反复生成–评估产物 | 第 4 章。kernel、论文、可执行世界 | 否。\(I\) 仍在墙外 |
| Harness：改 prompt / 记忆 / 工具 / 路由 | 第 3 章。下次任务还用这套脚手架 | 弱。要看改进器是否进 \(S'\) |
| Model：改 \(\theta\) | 第 2 章。SPIN、RLVR、LoRA | 单轮否。递归要 \(I'\subseteq S'\) |

社区强调三层边界模糊、互相反哺：脚手架经验变成训练数据，基座变强再产出更好产物。花园承认反哺会发生，仍然按**这一次留下的状态**分层，避免一篇文章里三层都叫 RSI。混元可靠性专文按更新边界的深度分层（L0–L4），和这里正交，见 [第 6 章](../../6-评测与安全/02-可靠性与独立监督/02-可靠性与独立监督.md)。

专栏还常引一份社区 taxonomy 博客（lsl.zone，2026-07）。那份把优化对象切成三层，和花园同名。读的时候只借刀法，不借「都算 RSI」的结论。

## 3. 为何不在这里展开机构清单

把融资、SKU、内部 30% 提升写进坐标系章，读者会以为那些就是定义。第 5 章专门放「谁在说什么」。第 1 章只负责：名字从哪来、和式 (1)(2) 差在哪、数字去哪核。Harness 省推理成本、中间档模型更吃脚手架红利——这类主张要回到对应论文或官方 blog；本篇不转述无法指回一手的百分比。

**读**：三层名字；「都算 RSI」不成立；例子表。  
**不读**：把本篇当机构排行榜、当 AlphaEvolve / Auto-Research 的数字来源。
