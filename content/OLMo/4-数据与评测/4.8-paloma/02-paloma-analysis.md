# Paloma 技术解析：把单一困惑度拆成数百个语言领域

语言模型常在一份保留语料上报告perplexity,再把这个数字当作整体语言建模能力.Paloma指出,任何大语料都由许多语言分布构成:学术领域,网站,subreddit,编程语言,方言社群与边缘社区的文本规律不同.总体困惑度下降不意味着每个领域都同步改善,也无法说明改善由哪些高频字符串贡献.

Paloma汇集多种既有语料的细粒度元数据,并新增热门100个subreddit和100种编程语言评测集.它不仅发布数据,还提出公平比较困惑度所需的训练与推理控制,并训练一组1B基线:分别使用C4,mC4-en,Falcon RefinedWeb,The Pile,RedPajama和Dolma,约训练1500亿token,其他因素尽量一致.

## 1. 评测对象与可比性

Paloma 的第一项工作是确定「究竟在测哪一种文本分布」. 同一个数据源内部可以容纳许多语言领域, 而困惑度又同时受 tokenizer,文档边界和取平均方式影响. 这些对象若没有先分开, 后面的模型差异很容易混入数据处理差异.

因此, 可比性来自一组共同约束, 而非某个单独指标. Source,domain 与 token type 给出三种观察尺度; 固定词表,推理格式和样本量, 则让这些尺度上的差值尽量指向模型与训练数据本身.

### 1.1. Source,domain 与数据分布

**两层数据结构.** Source是研究中已有的数据集或其策划子集,如C4,Dolma,M2D2.Domain是依赖元数据划出的细粒度分区,例如Wikipedia视觉艺术,讨论电脑装机的subreddit,Java代码或某个学术学科.一个source可含数百domain. 这个区分防止把数据来源当成语言分布.两个source都含arXiv,预处理却可能完全不同;同一source内部的医学与物理文章也有不同术语.Paloma既比较source宏观平均,也保留domain级结果,用异常定位训练覆盖与清洗差异.

数据组成. 标准语言建模来源包括C4,mC4英文,WikiText,Penn Treebank,RedPajama,Falcon RefinedWeb与Dolma.细粒度来源包括按学科或Wikipedia本体划分的M2D2,C4百站点,新建的Dolma百subreddit与The Stack百编程语言. 社会语言差异由TwitterAAE的African-American与White-aligned English分区提供.Manosphere,Gab和4chan /pol/等边缘来源用于测量模型对毒性话语所在社会语境的拟合,不应把低困惑度解释成价值认可或生成质量.

困惑度只描述文本拟合. 若模型对某domain困惑度低,说明它给该处理后文本较高似然,不代表掌握该社群重视的技能,事实正确或对社群公平.domain差异也可能来自HTML清理,转义,分词和文档切分,而非原作者语言. 论文给出极端例子:同一模型在RedPajama的arXiv上困惑度可达391,171,在Dolma重叠学术来源peS2o上约14.如此巨大差距更可能暴露处理管线或数据表示异常,而不是模型忽然不会读学术论文.Paloma的用途之一正是发现此类异常.

### 1.2. Perplexity,BPB 与文档边界

**每token困惑度.** 对文档集合 $N$ 的总对数似然 $\ell$ 和token数 $T(N)$,每token平均负对数似然为 $-\ell/T(N)$,perplexity为其指数.它可解释为模型在当前tokenizer事件空间中的平均不确定度,越低表示拟合越好. perplexity依赖tokenizer.词表切分改变事件数量与序列长度,即使底层字符串相同,不同模型的每token困惑度也不能直接比较.Paloma优先固定GPT-NeoX-20B词表并增加OLMo使用的3个特殊token.

Bits per byte. 必须比较不同词表时,Paloma用bits per byte,把总负对数似然按UTF-8字节数归一化.字节属于文本本身而非模型分词,跨tokenizer更可比.但BPB仍受Unicode规范化,编码,空白与预处理影响,也不消除模型上下文长度差异. 固定词表比事后归一化更强,因为模型输出空间,稀有字符串切分与训练效率都受词表影响.BPB提供共同单位,不能让不同tokenizer模型变成完全受控实验.

文档推理格式. Paloma按文档独立评测,不把多个文档拼接成最大长度序列.超过上下文上限的文档切成不重叠块.这样避免一个文档尾部为下一文档开头提供虚假上下文,也使模型之间输入格式一致. 不重叠切分会让后续块缺少前文,长文档边界token的loss较高;滑窗方案则重复计算并可能利用更长上下文.二者没有唯一正确选择,关键是所有模型采用同一实现并公开规则.

**去污染,顺序,样本量与词表。**

**预训练去污染.** Paloma用Bloom filter检测预训练文本与评测段落的精确重叠.段落按换行切分;短于13个Unicode分词token的匹配被忽略,纯标点,空白和emoji也忽略,以减少常见短串碰撞.一个预训练文档只要含任一污染段落,整篇删除. 这是高精度规则,不覆盖改写,格式变化或语义重复.整篇删除降低残留上下文泄漏,却可能因一个引用段落丢掉大量无关内容.Bloom filter还存在可控假阳性,参数与哈希配置应纳入复现记录. 代码数据大量短行且高度重复,论文明确不对百编程语言和Dolma Stack domain做这套去污染.这意味着代码领域的perplexity可能包含训练重叠,不能与已去污染自然语言领域作同等泛化解释.

固定训练数据顺序. 现代LM把文档拼成固定最大长度实例,数据顺序决定哪些文本相邻,也有recency效应.仅使用同一语料但随机种子不同,训练轨迹和最终分数仍可能变化.Paloma固定tokenizer,最大长度,随机种子,并提供不随设备数改变顺序的数据加载代码. 固定顺序提高语料对照的内部效度,但单一顺序也可能偶然有利于某数据集.若目标是估计平均训练效果,仍需多顺序重复;Paloma基线更适合「在这套受控运行中比较」.

按领域控制样本量. 困惑度方差随评测token增加而下降.若大domain用百万token,小domain只用几千token,比较稳定性不同,宏平均还会受缺失与噪声影响.作者通过C4子采样实验选择每个source目标100万token,每个domain目标10万token,在推理成本与方差间折中. 等量抽样让每个domain估计精度更接近,也使小社群不会被大型网页源的token量淹没.它不等于真实世界频率加权;宏平均回答「典型domain表现」,不是「随机互联网token表现」.

固定词表. 同词表使per-token perplexity共享事件空间.Paloma自训基线因此采用相同tokenizer.对off-the-shelf模型无法换词表时才转用BPB,并明确比较限制. 词表控制也影响社会语言分析:方言词,emoji和代码标识符若被切得更碎,会增加token数并改变困惑度.按字节指标能部分缓解,但模型训练时仍经历其原生分词.

固定评测格式. 最大序列长度,BOS/EOS处理,长文切块,padding与是否跨文档上下文都会改变loss.Paloma沿用The Pile的文档独立格式并发布统一代码.专有API若实现变化,历史结果可能不可复现,因此作者强调本地开放评测.

**计算预算与学习率日程。**

**参数量与训练token.** 模型perplexity受参数量,训练token和数据组成共同影响.Paloma建议同时报告非硬件特定的参数数与训练token,用于判断谁在相近预算下更好,谁以更少资源达到阈值,以及扩展趋势如何. 这两个代理不等于实际FLOPs,能耗或GPU小时.架构,稀疏激活,序列长度和实现效率都会改变成本,但参数/token比只报模型名称更便于跨硬件复核.

学习率日程的位置. 非恒定学习率训练中,中间检查点可能在退火前表现次优,末期学习率下降后突然改善.比较两个检查点时,应按各自总优化进度比例匹配,而不只按已见token绝对值.否则日程较早进入退火的模型会占优势. 固定训练数据顺序与优化进度共同构成严格控制,也降低了基线对更广泛随机设置的外部效度.论文的目标是建立高密度可比较实验,而非估计所有训练运行的期望表现.

## 2. 基线结果与领域差异

六个 1B 基线把模型规模和训练预算大致固定, 主要改变预训练语料. 这组实验不能给语料排出永久名次, 却能展示不同数据来源如何改变领域覆盖, 也能把宏平均下面的异常尖峰暴露出来.

结果要沿 source,domain 和 token type 三层一起读. 总体困惑度下降可以与局部逆缩放同时发生, 参数增加也可能只改善高频字符串; 单看一个总分, 会漏掉最有诊断价值的部分.

### 2.1. 六个 1B 基线的数据效应

**为什么自行训练基线.** 直接比较公开模型会混入架构,tokenizer,超参数,数据量,去污染和训练顺序差异.Paloma自训约1B参数模型,每个约1500亿token,分别来自六个流行语料,从而把主要变量收敛到预训练corpus. 这种设计能支持「哪种语料在当前配方下产生更广泛领域拟合」的结论.不能据此给语料永久排名,因为其他模型规模,混合权重和训练日程可能改变相对表现.

Common Crawl单一来源的不稳定领域. 只依赖Common Crawl派生语料的基线,在不少细粒度domain上出现不规则gap,随训练token增加甚至不持续改善.包含书籍,论文,代码,Wikipedia和Reddit等异质来源的语料表现更稳定. 这不表示Common Crawl本身缺少所有领域;过滤器可能删掉特定语言现象,网页清洗也会破坏格式.Paloma把异常domain暴露出来,为检查采集与过滤提供方向.

宏平均如何隐藏异常. source宏平均对其domain等权,可展示总体稳定性,却仍会掩盖单个领域.论文按domain中位困惑度排序,再看各模型相对中位线的偏移.稳定模型大致保持平行偏移,不稳定模型在个别domain出现尖峰. The Pile基线在M2D2-S2ORC和百编程语言上有低于中位的不规则gap,可能来自特定领域暴露;Common Crawl基线的异常多为高于中位,像是覆盖缺口.该解释是合理推测,仍需训练数据成员与处理链验证.

### 2.2. 高频词项与总体 loss

**平均loss与总loss的区别.** 高频type通常单次平均loss较低,但出现次数巨大,总loss贡献仍高.论文按GPT-NeoX词表ID近似频率排序,发现domain内ID与频率平均Pearson相关约 $-0.522\pm0.087$.约5%的type贡献约50%的总perplexity loss质量. 因此总体perplexity改善可能主要来自少量常见字符串,低频词,方言形式和专业术语的退化几乎不可见.Paloma额外记录每个type的平均likelihood与出现次数,为细粒度分析提供数据.

更大模型并非每个type都更好. Pythia-7B在所有domain总体困惑度低于Pythia-1B,但每个domain都有一些type由1B预测得更好.此类type比例从C4百domain的8.5%到TwitterAAE的32.1%.比例随词表ID增大而增加,说明低频type更常出现逆缩放. 即便高频区也约有10%的type小模型更好,因此不能全部归因于低样本噪声.论文举例,代词「I」在ICE出现14,703次,1B最终平均loss仍低于7B.原因可能包括训练动态,数据组成或概率质量在词表中的重新分配.

方言领域差异. TwitterAAE是逆缩放type比例最高来源.在1B更好的type中,它在African-American domain胜过7B的比例为77.6%,White-aligned domain为71.3%.存在一组type只在African-American English上表现逆缩放. 这提示总体困惑度和跨domain平均会隐藏社会语言差异.它不能单独证明更大模型对说话者造成下游伤害,但足以要求进一步检查词汇,语境与生成行为.

**训练 token 与参数规模。**

**增加训练token.** 大多数domain随训练改善,但速度差异显著.C4和mC4-en基线分别有65和43个domain在更多预训练后拟合反而变差;其他语料基线只有6个模型—domain对出现恶化.Common Crawl过滤与数据顺序可能使某些domain在后期被遗忘或概率质量转移. 排除这两个异常基线后,改善最快与最慢domain的中位差距仍约1.94倍.慢改善不必然「不想学」,它可能是domain更难,样本少或与训练目标冲突;Paloma提供定位,而不是价值判断.

增加参数规模. Pythia 160M,1B,7B比较中,更大模型所有source宏平均困惑度都降低,且较大模型随训练token下降更快.但domain改善幅度仍不均,改善最快domain约为最慢的2.02倍. 参数扩展比某些Common Crawl训练时长扩展更一致,却没有保证每个type改善.source,domain和type三层结论必须同时看:总体下降,领域不均和词项逆缩放可以并存.

**去污染的适用范围。**

**精确段落匹配的盲区.** Bloom filter规则能有效找逐字段落,却漏掉大小写变化,清洗差异,代码格式变化和改写.13 token阈值减少偶然匹配,也允许短题目或答案残留.对传统小测试集,短文本污染尤其可能逃过. 整篇删除任何含污染段落的训练文档是一种保守处理.报告应给各语料删除比例,以判断基线训练分布是否被不同程度改变.若某语料转载评测内容更多,去污染会额外删掉更多上下文,公平性与真实语料质量影响交织.

代码未去污染. 代码短行重复使自然语言规则产生大量误报,作者选择不对代码来源去污染.这是明确限制.百编程语言的结果适合描述「在当前训练数据可能重叠条件下的拟合」,不适合当作严格未见代码泛化. 后续可采用仓库级split,文件哈希,AST规范化或许可证与时间戳过滤,而不是放弃所有去污染.不同语言的生成代码,模板与依赖文件重复度不同,也需要分语言报告.

**从总体排名回到领域诊断。**

**异常来源与总体排名.** Paloma不是为了产生一个新的单分排行榜.优先看domain曲线中的尖峰,随token恶化的领域,词项逆缩放和社会语言差异,再回到训练数据检查来源覆盖与清洗. 若必须聚合,应同时报告token加权micro平均,domain等权macro平均与完整分布.三者回答不同问题,单一平均会隐藏谁获得了改善.

比较模型的最低要求. 理想对照使用同词表,同推理格式,相同评测样本,训练侧去污染并固定数据顺序,同时匹配参数,训练token与优化进度.无法控制的因素要显式列为限制,并优先用BPB而非直接比较per-token perplexity. 公开模型通常无法满足训练顺序与去污染控制,此时Paloma仍可作诊断,但结论应是「这些发布模型在当前文本上的拟合不同」,而非把差异归因于某个单一语料或算法.

论文的核心启示. 困惑度是对特定文本分布,特定tokenizer和特定推理协议的测量.扩大领域覆盖并控制样本量,才有机会看到语言模型学到了哪些分布,遗漏了哪些分布.Paloma把评测从一份验证集的总平均,扩展成source—domain—type三层剖面. 最值得延续的做法是把可比性写进数据与代码:污染处理,顺序,样本量,词表和格式都能改变结论.细粒度结果用于防止总体改善掩盖局部退化,而非徒增数字.

## 3. 统计口径与污染边界

领域数量增加以后, 聚合方式本身就会改变结论. Token 微平均,文档宏平均和领域宏平均分别对应不同的抽样问题, 指数变换,文档长度与 tokenizer 又会继续改变数值口径.

污染也不是简单的有或没有. 精确重复,近重复,代码模板和时间重叠需要不同检测方法, 文档簇相关性还会让名义样本量高于有效样本量. 这一部分把 Paloma 的结果放回统计对象与数据边界中解释.

### 3.1. 复现,配方与适用边界

若要把论文方法真正复现为长期可维护的评测流程,第一步应冻结数据清单,不要直接运行全部模型.每个来源都应记录版本,下载时间,许可,原始文件摘要,过滤规则,文档数,字符数和最终抽样种子.论文所强调的「来源」必须在数据管线中成为一级字段,不能在预处理后只剩一个混合测试集.否则即使总困惑度能够复现,也无法复现论文关于跨来源差异的核心结论. 第二步是保存污染检测的中间产物.应逐条记录命中的训练文档,测试段落,匹配规则以及删除范围,并分别报告测试集被命中的比例和训练语料被删除的比例.Paloma使用精确段落匹配并对命中文档整篇删除,这一选择便于执行,却会漏掉改写,空白差异,格式变化和短段落,也可能因为一处命中删除大量无关内容.因此复现报告不能只写「已去污染」,还要呈现这一操作对不同训练语料造成了多大且是否均衡的改变.

第三步是锁定模型侧条件.所有检查点要使用一致的上下文截断策略,批大小,损失掩码,边界标记和数值精度;若比较不同分词器,至少同时给出每词元损失与每字节比特,并明确哪些结论只在同一分词器家族内成立.对于代码,多语文本或包含大量特殊符号的数据,字节归一化也不是完美语义单位,所以最好补充字符或词级统计,并公开各域平均词元长度,避免把切分差异误读为建模差异. 第四步是把聚合方式当作实验变量.建议同时输出微平均,按文档宏平均,按来源等权平均,以及按目标应用分布加权的结果.若几种聚合给出的模型排序不同,这种差异说明「最佳模型」依赖部署分布,不该被当作噪声隐藏.Paloma的价值恰恰在于显露这种依赖;复现者应保留完整的来源级矩阵,而不应只发布一个总分.

第五步是审计异常值.对于极端困惑度,突然反向缩放或相邻检查点剧烈波动的来源,应抽取实际样本,检查乱码,模板重复,语言标识错误,代码围栏,文档边界和超长符号串.论文中的arXiv等异常说明,预处理格式能够压过真正的领域知识差异.异常排查记录应与最终结果一同保存,使后来者能够区分数据错误,格式不匹配和模型能力不足.

**对训练数据设计的启示.** Paloma的结果支持一种更谨慎的数据配方观:增加某类数据通常会提升相近来源,但这种收益不必然外溢到所有领域,也可能伴随部分来源退化.因此数据混合不应只根据总体验证损失调节,而应建立「训练成分—评测来源」的响应矩阵.每次更换过滤器,采样权重或去重策略,都应比较固定训练预算下各来源的增益与损失,再决定变化是否值得. 这种矩阵还能帮助识别表面上的规模收益.当模型参数增加而某些来源改善远慢于其他来源时,原因可能来自训练分布覆盖不足,格式不匹配或高频词元掩盖了稀有结构的错误,未必是容量不足.反过来,训练步数增加后少数来源恶化,也不应简单归因于随机波动;它可能暴露数据顺序,过拟合,灾难性干扰或后期学习率阶段对特定分布不利.检查点级曲线因此比终点表格更有诊断价值.

对开放模型项目而言,最实用的做法是把Paloma式评测接入每次数据配方实验:固定抽样与顺序,只改变一个成分;保存来源级损失,词元覆盖,污染统计和置信区间;再以预先声明的部署优先级判断取舍.这样,数据工程的决策就能从「总体损失略有下降」升级为可解释的证据链,也能避免为了一个宏平均指标牺牲关键用户群体或语言风格.

仍需谨慎解释的边界. Paloma主要研究基础模型的续写概率,不等同于指令遵循,事实正确性,推理能力或安全性.较低困惑度通常意味着更好地拟合该文本分布,却不能保证模型会在交互任务中给出更有用的答案.它应与任务评测,生成质量审查和安全测试互补,而不能替代这些评测. 数据来源标签只是分布的代理.同一网站内部可能混合不同作者,年代,主题和写作规范;两个名称不同的来源也可能共享转载文本或相似模板.因此来源级差异能够指出问题在哪里,却未必直接解释为什么.要建立因果解释,还需要更细的元数据,人工样本审阅以及控制变量实验.

论文的宏平均赋予各来源近似相等的地位,这有利于阻止大型网页语料淹没小众分布,但并不天然对应任何真实部署场景.面向科研,编程,社交对话或通用助手的产品会有不同权重.最稳妥的使用方式,是把Paloma保留为透明的诊断面板,再依据明确的目标分布构造附加聚合;两者同时发布,才能让模型改进与价值选择都保持可见.

### 3.2. 交叉熵,聚合与 tokenizer

给定评测token序列 $x_{1:N}$,平均负对数似然为 $H=-N^{-1}\sum_{i=1}^N\log p_\theta(x_i|x_{<i})$,困惑度为 $\exp(H)$.它是几何平均意义下的逆概率,衡量模型对实际下一个token分配多少概率.困惑度2不表示模型每步只有两个候选,而是对平均对数损失的指数变换. 指数会放大loss差异,也让困惑度的算术平均难以解释.跨文档或跨域聚合时,先平均token loss再取指数,与先算每个文档困惑度再平均不同.Paloma式比较需要明确在哪一级求和,除以什么分母以及何时指数化.最可加,最适合统计分析的量通常是负对数似然.

**Token宏平均与文档宏平均.** token微平均把某域全部token放入一个分母,长文档贡献更多;文档宏平均先算每篇平均loss,再让每篇文档同权.前者估计从该域token流随机取一位置的损失,后者估计随机取一篇文档后的平均难度.二者对文档长度分布敏感. 若论坛短帖与长论文混合,token微平均更偏向论文,文档宏平均更偏向大量短帖.没有天然正确选择,关键在研究问题.报告两者及长度分桶结果,可以判断模型差异是否只来自长文本或短文本.

域宏平均与部署微平均. 令域 $d$ 的平均loss为 $H_d$.域宏平均 $D^{-1}\sum_dH_d$ 给每个域相同权重,突出小众域;按部署权重 $w_d$ 的微平均 $\sum_dw_dH_d$ 则反映预期流量.若直接对各域困惑度平均,因指数非线性,结果无法对应任何简单混合分布的交叉熵. Paloma用来源级面板防止大网页域淹没其他分布.产品团队仍需另给部署权重,并保存权重来源.宏平均改进而部署平均下降并不矛盾,它说明模型在覆盖公平与主流流量间发生取舍.

Jensen不等式与聚合. 由于指数函数凸,$\exp(\mathbb E[H_d])\leq\mathbb E[\exp(H_d)]$.因此平均域困惑度通常高于域平均loss再指数化.两个论文若分别采用这两种口径,数字不能直接比较,即使底层域loss完全相同. 跨域报告最好保留每域loss,token数和聚合公式.读者可按自己的权重重算.只发布一个困惑度会丢失可逆信息,也让极难域通过指数对平均产生异常影响.

Tokenizer改变分母. 同一字符串经不同tokenizer会产生不同token数,per-token loss的分母随之改变.词表更大可能用一个token表示常见长片段,从而让数值看起来不同;它既改变预测单位,也改变每步类别空间.跨tokenizer困惑度不具直接可比性. 固定词表能隔离模型与数据因素,却限制比较范围.对于使用原生tokenizer的外部模型,可改用bits per byte或字符级压缩指标,并同时报告原生per-token结果.B​​PB提高了跨分词器可比性,仍会受到文本编码和规范化影响.

Bits per byte的推导. 若文本含 $B$ 个UTF-8字节,总负自然对数似然为 $L$,则bits per byte为 $L/(B\ln2)$.它将模型对token序列的概率转换到原始字节长度尺度.只要tokenization是无损确定映射,总序列概率可以比较,而分母不再依赖token数. 但字节并非语言无关的信息单位.中文字符通常占多个UTF-8字节,不同Unicode规范形式长度也可能不同.BPB适合减少tokenizer混杂,不能自动实现跨语言公平.规范化和编码必须固定.

文档边界的概率条件. 每篇文档从BOS开始独立计分,与把所有文档串成一条流不同.串联时,下一篇开头可条件于上一篇结尾,形成训练中packing带来的人工上下文;独立计分则更接近文档生成.是否对BOS,EOS和分隔符计loss也会改变结果. 短文档中边界token占比高,格式选择影响尤其明显.固定文档推理格式使模型比较可重复,报告时应说明上下文是否跨文档,首token如何处理以及超过窗口的文档怎样切块.

滑动窗口与长文档. 文档超过上下文长度时,可分成不重叠块或用滑动窗口,让每个待测token拥有更多左侧上下文.不重叠块的开头缺少历史,loss偏高;滑动窗口重复计算上下文,成本更大但更接近完整条件概率. stride大小决定多少token处于短上下文.不同实现若stride不同,长文档域分数会变化.评测需只对每个窗口新加入的token计loss,避免重叠区域重复加权.按文档长度分层能发现协议差异集中在哪.

上下文长度的公平性. 模型最大上下文不同.统一截到共同长度控制条件,但压制长上下文模型优势;各用最大长度更贴近原生能力,却改变每个token可见历史.两种协议分别回答受控语言建模和部署能力. Paloma主要关注分布拟合,采用固定格式有利于比较.若研究长上下文收益,应单列实验,按上下文位置画loss曲线,而不把不同窗口结果混入主表.模型能接受更长输入,不保证有效利用更远信息.

位置损失曲线. 将token按在文档或窗口中的位置分桶,可观察开头缺上下文,正文稳定区和长距离依赖.总体loss下降可能只来自常见开头格式,关键长距离位置并未改善.不同域的位置曲线还能揭示文档结构差异. 比较时要控制文档长度,因为只有长文档贡献后部位置.可在相同长度子集上作图,或使用条件加权.位置分析把单个困惑度拆成模型利用上下文的行为证据.

词频分解. 总loss可按token type频率分桶.高频token出现次数多,即使单次loss较低,也主导总体;稀有token平均loss高,却对总量贡献有限.模型整体改进可能主要来自标点,空格和功能词,而专业实体几乎不变. 报告每桶平均loss,token占比与总loss贡献,才能区分.词频依据训练语料,评测语料或统一参考计算会得到不同分桶,必须固定.跨模型词表不同又回到tokenizer不可比问题.

类型平均的陷阱. 先对每个token type平均loss,再对type同权,会让只出现一次的罕见type与出现百万次的常见type权重相同.它适合研究词汇覆盖,却不代表自然文本平均性能.若仅报告type平均,少数异常稀有词会造成大方差. 可以设最小频率或用经验贝叶斯收缩稳定估计,同时保留尾部覆盖率.任何平滑都会改变研究对象,主文应给原始token微平均,类型分析作为诊断.

**领域噪声,方差与配对设计。**

现代子词tokenizer通常没有传统未知词,但罕见字符可能拆成长字节序列.模型为一个字符承担多次预测,per-token困惑度反而可能不高,却在字节或字符尺度代价较大.跨语言和代码域尤其明显. 统计每字符token数,字节回退比例和特殊token频率,可以解释域差异.固定tokenizer保证内部比较,却可能对某些域结构性不利.数据混合优化若只看per-token loss,可能忽略这种表示成本.

**域标签噪声.** 来源网站不等于内容域.新闻站可含评论,体育和财经,学术仓库可含代码,表格和元数据.按source聚合容易解释采集管线,按语义domain更接近能力.两层标签都可能有错误. 抽样人工检查和轻量分类器可估计标签纯度.若来源内部异质性很大,整体loss无法指出具体弱点,应继续按主题,格式或年代分层.细分越多样本越少,方差随之上升,需要在诊断粒度与统计稳定间平衡.

层级模型估计域差异. 小域样本少,独立均值噪声大.层级模型可假设域效果来自共同分布,让小域估计向总体收缩,大域主要由自身数据决定.它能减少极端值由偶然样本造成的误导,并给出后验区间. 收缩也可能掩盖真正独特的小众域.先验结构应按source/domain层级设计,并与非参数bootstrap对照.原始均值,样本量和收缩估计同时发布,读者才能判断结论依赖多强假设.

文档簇方差. 同一作者,网站模板或事件的文档高度相关.把每个token当独立样本会得到极窄误差.应以文档为最小重采样单位,重复或主题簇明显时进一步以簇为单位.有效样本量可能远小于token数. Paloma控制每域样本量有助于平衡,但不能自动消除相关性.报告文档数,来源数与重复簇数,比只报token数更能说明统计信息量.

域间方差与域内方差. 总差异可分成域间平均loss差和域内文档波动.域间方差大说明模型在不同分布上不均衡,域内方差大则可能存在子主题,质量或长度异质.方差分解能指导继续细分还是调整数据权重. 模型比较还可观察差值方差.有些域对所有模型都难,只提高绝对loss;另一些域真正改变模型排序.训练数据研究更关心后者,因为它揭示配方与分布的交互.

配对文档比较. 多个模型在相同文档上计分,差值应按文档配对分析.模型loss高度相关,配对区间通常比独立估计窄.对每域进行文档bootstrap,再聚合差值,可保留结构. 若模型tokenizer不同,文档仍可配对,但指标需转成BPB等共同尺度.缺失或解析失败文档不能静默删除,否则共同子集会随模型变化.数据清理应先于看结果完成.

去重对方差的影响. 重复文本使某些句子被多次计分,既改变域权重,也降低表面标准误,因为重复样本高度相关.去重后均值可能上升或下降,区间通常更符合独立内容量.评测集应在文档,段落和近重复多个层级检查. 过强去重会删除合理的固定表达,改变真实域分布.可保留原始集与去重集两套结果,差值本身反映模板和转载对指标的贡献.去重规则,哈希粒度与阈值必须版本化.

训练—评测重复. 评测段落出现在训练数据中会降低loss,尤其长精确重复.检测可用n-gram,MinHash和精确索引,按匹配长度与覆盖率分级.只检查文档URL会漏掉转载与数据再打包. 污染影响不是二元.短常见片段贡献有限,整篇或长段重合更严重.分别报告清洁子集,疑似子集和完整集,能展示模型排序是否依赖重复.删除后样本量变化需重新估计方差.

**污染,混杂与训练轨迹。**

轻微编辑,格式转换和OCR差异会绕过精确匹配.语义近重复提高召回,却可能把同主题独立文章误判污染.局部哈希适合检测保留大量表面的版本,向量相似只作为候选,再人工核查来源. 若两个文档共享事实但表达独立,这属于模型应学习的知识,不宜删除.污染判定关注评测实例及其表达泄漏,而非所有相关材料.分级规则比单一相似阈值更可靠.

**代码域的特殊污染.** 代码片段常因许可证,样板和常用算法重复.精确重合不一定意味着基准泄漏,变量重命名又会隐藏结构复制.AST规范化与标识符替换能找结构近重复,但会把常见实现聚成大簇. Paloma若包含代码,需单列污染方法和结果.论文已指出代码去污染边界,这意味着代码域低困惑度的解释更谨慎.不能把未检测到污染视为确认清洁.

时间污染. 模型训练截止与评测文档发布日期提供初步边界.截止后文档原则上不应直接出现,但它可能转载早期文本;截止前文档也不一定被收录.时间信息需与数据清单和文本匹配结合. 按年份分层还能研究知识与风格漂移.新文本loss更高,可能来自事实更新,术语变化或来源分布改变,不必然说明模型缺少最近知识.配对同来源不同时段可以减少混杂.

数据质量混杂. 某训练数据混合在Paloma上更好,可能因为覆盖了对应域,也可能因为清洗更接近评测文本风格.去重,语言识别和质量过滤同时变化时,无法把收益归给某一因素.单变量数据消融更有解释力. 固定基础语料,只替换一个来源或过滤器,并保持token预算与顺序,能建立更清楚对照.多因素实验可估计交互,但成本高.小模型筛选后在关键大模型上验证,是现实折中.

训练顺序与评测曲线. 相同数据混合以不同顺序出现,检查点域loss可能不同.近期出现的域短期改善,其他域发生遗忘;最终若尚未充分混合,顺序效应仍会保留.只看终点无法判断模型何时获得某域能力. 沿token进度保存Paloma分域曲线,可识别学习,饱和与回退.横轴应使用已训练token而非step,避免batch变化.数据阶段切换与学习率节点标在同图上,有助于区分原因.

学习率调度混杂. 增加训练token时若延长余弦日程,原预算终点对应的学习率位置改变.性能差异可能来自更高或更低学习率,而非多见数据.比较token扩展需要固定调度语义,或在共同token点对齐学习率. 续训从低学习率重新warmup也会改变轨迹.论文解释规模规律时,应区分同一日程延长,重新调度和独立从头训练.这些设置无法用「训练更多token」概括.

参数规模与计算匹配. 大模型若使用相同token数,训练计算更多;固定FLOPs时,大模型能见的token更少.参数规模曲线和计算最优曲线回答不同问题.Paloma跨规模结果需要同时报告参数,token与估算FLOPs. 若所有规模共享数据顺序,前若干token可配对比较,利于观察容量效应.训练超参数仍可能随规模调整.结论应限定在实际配方,不能从几个点推出普遍幂律.

## 4. 缩放规律与数据决策

全局 Scaling 曲线常把不同领域压成一个平均值, Paloma 则允许逐域观察可约损失,饱和速度和排名变化. 这种拆分能区分容量不足,训练覆盖不足与表示方式不利, 也能发现增加参数或 token 后仍然停滞的领域.

数据配方因此可以写成多目标选择: 某个过滤器或混合权重改善了哪些领域, 又让哪些领域退化. 权重敏感性,Pareto 前沿和配对实验把这种选择显式化, 防止用单个平均数代替部署目标.

### 4.1. 域级缩放与反例

常见缩放表达为 $L_d(C)=A_dC^{-\alpha_d}+E_d$,其中 $C$ 是计算或数据规模,$E_d$ 是不可约项.不同域的系数和指数可能不同,说明增加资源并非均匀改善.用少量规模点拟合多个参数容易不稳定. 拟合应给参数区间,残差和外推验证.若某域曲线在数据阶段切换时出现拐点,单一幂律不合适.缩放律描述观察范围内趋势,不是对任意更大模型的保证.

**不可约损失的解释.** $E_d$ 常被称为不可约损失,但有限实验估计的渐近项可能包含数据噪声,tokenizer限制和模型族偏差.换架构,词表或清洗后它会变化.因此不能把拟合出的 $E_d$ 当成语言本身熵的精确值. 域标签噪声和重复也会影响曲线.把渐近项视为当前实验族的经验下限更准确.外推前需检查新增规模点是否仍沿同一趋势.

高频改善与长尾停滞. 总体loss随规模下降,可能主要来自高频token.对稀有实体,方言拼写和专业符号,样本不足使改善缓慢.按频率和域交叉分桶,可以看到规模是否真正扩展长尾覆盖. 小桶方差很大,需要合并多个检查点或使用收缩估计.即便趋势不显著,也不能断言规模无效;应给检测能力和样本量.长尾结果更适合作为诊断,而非精细排行.

反例:低困惑度与事实错误. 模型可能熟练预测一段流行但错误的说法,获得低loss;面对要求判断真假的问题却给错误答案.困惑度测文本分布拟合,不验证陈述真实性.训练语料中的共识,偏见和错误都会成为可预测模式. 因此事实任务需独立问答和来源核验.Paloma能指出模型对某域语言陌生或熟悉,不能替代事实准确率.低loss最多表明文本在模型分布下不惊讶.

反例:低困惑度与生成退化. 模型在教师强制的真实前缀下逐token预测良好,开放生成时仍可能重复,跑题或陷入循环.评测每一步都提供正确历史,生成则条件于自身先前输出,误差会累积.两种设置存在暴露偏差. 生成质量需要自由续写,人类评审和重复指标.Paloma适合测局部条件建模,是必要诊断之一.将低困惑度直接等同于高质量长文本,会越过评测设计.

反例:平均改善掩盖关键域退化. 大型网页域下降0.01 loss,可能抵消小型医学域上升0.2,token微平均仍改善.若应用依赖医学文本,这个模型更差.宏平均能提高小域可见性,却仍把所有小域同权,未必符合风险. 报告分域矩阵并设置关键域回退阈值,可以防止.聚合用于摘要,训练决策应回到目标域和风险权重.任何「总体更好」都需要附聚合定义.

反例:Tokenizer优势. 模型A的词表专门覆盖某域术语,用更少token表示文本,per-token困惑度可能与模型B不可比.即使BPB更好,也可能部分来自压缩词表而非Transformer能力.Tokenizer本身属于系统设计,优势真实存在,只是归因对象不同. 固定tokenizer模型比较隔离网络与训练数据,原生tokenizer比较评估完整系统.两种实验并列,能够区分表示与建模贡献.不能在一个表中混用而不给说明.

反例:小样本域的极端值. 某个域只有少量文档,一篇异常长,乱码或高度公式化文本就能显著改变loss.极端值可能是真实难例,也可能是处理错误.箱线图,文档级分布和人工抽查比只看域均值更能判断. 稳健均值或截尾均值可作敏感性分析,但主结果不应事后删除不利文档.排除规则在看模型分数前制定,并对所有模型一致应用.保留原始与清洗结果有助于审计.
