# Dolma 技术解析：三万亿 Token 开放语料的设计、验证与边界

arXiv:2402.00159v2 的 64 页论文、官方 LaTeX 与 Dolma Toolkit 对应 Dolma v1.6，文中数字也只适用于这一版本。Dolma 的贡献不只是约三万亿 token 的英语语料，还包括逐来源构建说明、数据消融和开源工具。

## 1. 统计目标、开放边界与实验工具

论文提出四个目标。第一，与已知大模型预训练配方保持一致，使公开数据可以用于研究闭源模型的数据实践；这也使 v1.6 聚焦英语，作者承认它强化“英语是默认语言”的假设。第二，在行业做法不明确时，使用小模型消融支持选择。第三，目标规模为 2–3T token，以研究模型和数据规模关系。第四，开放同时意味着发布数据并记录整理过程，必要时因法律、伦理与实践约束偏离商业配方。 团队没有纳入处于版权争议中心的 Books3, 并主动处理 PII. 这里的开放覆盖来源记录, 删除规则与风险政策, 语料规模只是其中一项. 语料覆盖六类来源、超过 40 亿文档。Common Crawl 约 9,812GB、37.34 亿文档、1.928T Unicode words、2.479T Llama token；GitHub 1,043GB、2.10 亿文档、260B words、411B token；Reddit 339GB、3.77 亿文档、72B words、89B token；Semantic Scholar 268GB、3880 万文档、50B words、70B token；Gutenberg 20.4GB、5.6 万文档、4B words、6B token；Wikipedia/Wikibooks 16.2GB、620 万文档、3.7B words、4.3B token。token 数绑定 tokenizer，不能与字节或 Unicode word 混用。 **1.1. Toolkit 与数据消融.**

Toolkit 把常见操作统一为 filtering 与 mixing。过滤阶段在文档、段落或句子上计算语言、质量、内容和 PII 信号，再删除或替换；Mixer 负责跨文件上/下采样、去重、去污染与输出。属性和文档分离，使阈值改变时不必重跑昂贵分类器。 论文给出性能量级：内部复现 C4 配方时每 TB 约需 122 CPU 小时；用一台 192 vCPU 的 `c6a.48xlarge` 处理约 200TB raw Dolma，估算五天。该数字绑定任务、实例与存储环境，不是任意 tagger 的固定吞吐。Bloom filter 提供线性时间概率去重，也可先放测试片段再做去污染，但存在误报；容量、元素估计、哈希与输入顺序都属于复现参数。

团队用 OLMo 系列 1.2B decoder-only 模型比较数据干预，每个模型训练到 150B token 后停止。评测覆盖八项数据集，使用 zero-shot in-context prompting，把任务转为 ranked text classification。消融比文本统计更接近训练目标，但外推边界明显：1.2B 的早期排名不保证在大模型和多万亿 token 下不变，八项评测也不覆盖生成、安全、多语与长上下文。 **1.2. 数据整理优化的是训练分布.** 设原始来源分布为 $p_0(x,s)$, 其中 $x$ 是文档, $s$ 是来源。过滤器给出接受概率 $a(x,s)\in[0,1]$, 混合器为来源赋权 $w_s$, 去重又给每个等价内容簇分配保留权重 $d(x)$。最终送入训练的分布满足

$$
p_{train}(x,s)=
\frac{p_0(x,s)a(x,s)w_sd(x)}
{\sum_{s'}\int p_0(x',s')a(x',s')w_{s'}d(x')\,dx'}.
$$

这条式子说明过滤、去重与混合没有彼此独立。过滤改变每个来源剩余多少内容, 固定来源权重随后会放大或缩小剩余文档; 去重把高复制内容的经验频率压低, 同时改变域内主题比例。最终 token 数只是归一化后的规模, 无法单独描述训练分布。 语言模型预训练最直接优化 $p_{train}$ 上的交叉熵

$$
R_{train}(\theta)=E_{(x,s)\sim p_{train}}
[-\log p_\theta(x)].
$$

真正关心的却可能是目标域集合 $q_1,\ldots,q_K$ 上的风险。数据整理要在有限 token 预算下选择 $p_{train}$, 使若干 $R_{q_k}(\theta)$ 足够低, 同时满足隐私、许可、毒性、代表性与成本约束。不存在一个脱离目标域的「最高质量」标量; Wikipedia 相似度、Gopher 规则、投票和代码仓库星数都只是不同代理。 Dolma 的设计目标还包含规模下限。若理想过滤器保留概率过低, 训练预算 $B$ 会迫使剩余数据重复多个 epoch, 或要求补入其他来源。设清洗后唯一 token 数为 $U$, 训练预算为 $B$, 则平均重用次数约为 $B/U$。继续收紧过滤可能提高单 token 质量, 也可能增大重复和记忆风险。论文最终选用较宽松 toxicity 阈值, 正是质量改善与语料规模约束共同作用的实例。

### 数据量有四种常被混用的口径



Dolma 同时报告压缩字节、文档数、Unicode word 和 tokenizer token。四者回答不同问题。字节接近存储与扫描成本; 文档数决定文档级抽样和元数据数量; Unicode word 便于不绑定 tokenizer 地比较文本量; token 才直接进入训练步数和损失权重。过滤 10% 文档可能只删除 2% token, 也可能删掉 30%, 取决于被删文档长度。 设来源 $s$ 有 $N_s$ 篇文档, 第 $i$ 篇经过 tokenizer 后长度为 $L_{si}$。来源 token 量为 $T_s=\sum_iL_{si}$。若训练按 token 流均匀采样, 单篇文档被看到的概率与 $L_{si}$ 成正比; 若先均匀抽文档再截取固定长度, 权重会不同。只给 $N_s$ 与 $T_s$ 仍不足以恢复长尾长度分布。

The Stack 的 fertility 明显高于其他来源, 官方 tokenization 附录把它与换行、制表符等空白字符的较高频率联系起来。fertility 指每个 word 或字符被切成多少 token。代码在 LLaMA tokenizer 下 token 膨胀更大, 因而 15% token 比例对应的原始字节或语义单元比例可能远低于 15%。跨 tokenizer 复现 mixture 时, 按文件数量或字节比例复刻会改变训练 token 权重。

文档拼接还会加入 EOS 并把多个短文档打包进定长序列。Reddit 原子评论、百科短页和长篇论文拥有不同边界密度。若每篇都插一个 EOS, 每十亿 token 中的文档边界数量会随 mixture 改变, 模型学到的重置频率也随之变化。配方复现应记录来源 token 比例、文档数量、长度分布和 EOS 密度。 **1.4. 开放性让数据假设可以被证伪.** 开放数据的科学价值不只在可下载。给定稳定文档 ID、来源、属性、过滤规则和版本, 研究者可以回答某项能力来自哪些样本、某条规则删掉了哪些群体、benchmark 是否与预训练文本重叠。若只发布最终文本, 仍能训练模型, 却无法重建接受函数 $a(x,s)$。

属性与正文分离使反事实配方成为可能。假设 toxicity tagger 为每句给出分数 $z$, v1.6 使用阈值 $\tau_h$, 研究者可以从同一属性构造更严格的 $\tau_l$, 保持其他步骤不变。这个设计减少重复计算, 也把反事实限制在 tagger 已保存的信息内。若后来换分类器、修复切句或增加新的群体公平信号, 仍需重新标注原始文本。

可证伪性依赖中间数据完整。只记录某规则删了 15.23% 字符, 无法检查这些字符集中在哪些域; 只记录最终模型提高, 无法判断过滤、去重还是 mixture 造成变化。最有信息量的发布包括规则逐项命中、交集、稳定 ID、版本化 manifest 以及受控训练结果。Dolma 已提供比多数模型数据说明更完整的证据链, 仍没有发布互联网原始快照的全部权利与状态信息。

## 2. 网页过滤、质量定义与代表性

Dolma-Web 约 2.28T token，来自 `2020-05` 至 `2023-06` 的 25 个 Common Crawl snapshot。到 2024 年 2 月共有 97 个 snapshot，团队只下载达到目标规模所需的 shard，并假设清洗至少缩小十倍，因此它不是同期互联网完整镜像。 CCNet 先做语言识别与初始段落去重。FastText 英语阈值为 0.5，按字节移除 61.7%。CCNet 在 snapshot 内的小 shard 组中删除高频段落，约去除 70% 段落，多为导航与页眉。两步合计过滤 84.2%，从 175.1TB 降到 27.7TB。该段落去重是局部分组，不等于全局文档去重。 质量过滤采用 Gopher 全部规则加 C4 NoPunc，而非完整 C4。消融显示 C4 NoPunc 单独优于 C4 All 和 Gopher All，二者组合最好。Gopher 标记 15.23%、NoPunc 标记 22.73% UTF-8 字符，命中可能重叠，不能简单相加。KenLM 的 Wikipedia 相似度把文档分为高 21.9%、中 28.5%、低 49.6%；启发式过滤没有改变这些比例，说明两类信号近似正交。 **2.1. 内容、PII 与规模权衡.**

团队在 Jigsaw Toxic Comments 上训练 hate 与 NSFW 两个 FastText 分类器, 对 BlingFire 切分的句子评分. 高阈值 `τ=0.4` 删除 5.5–7.3%, 低阈值 `τ=0.0004` 删除 29.1–34.9%; 低阈值总体下游表现更好, 但 v1.6 为满足最低 token 规模选择了更宽松的高阈值. 质量, 内容和去重过滤的删除集合重叠很少, 串联后压缩效应很强. 这个阈值是在下游表现与最低语料规模之间做出的取舍. 作者还强调 toxicity 与 quality 都带价值判断。毒性定义随任务、整理者身份和标注者信念变化，检测器也可能歧视边缘群体。公开阈值和删除比例，使外界能研究这些偏差。

PII 过滤聚焦邮箱、IP 和电话号码。每篇不超过五个 PII span 时用特殊 token 替换，影响 0.02% 文档；超过五个则删除整篇，影响 0.001%。模型式检测器在该规模成本过高，因此使用正则以准确率换速度。消融未见删除与替换的性能差异，符合受影响比例极小，但不表示隐私风险已完全解决。 **2.2. 过滤器的接受域决定谁被代表.**

质量规则可以写成特征向量 $z(x)$ 上的接受域 $A$。Gopher All 同时检查长度、符号比例、重复、停用词等多项条件, 只有满足规则集合的文档才能保留; C4 NoPunc 主要删除缺少终止标点的段落。二者组合相当于取接受域交集 $A_G\cap A_C$。交集可能提高平均可读性, 也会系统排除与规则假设不符的文本。

缺少句末标点可能来自导航垃圾, 也可能来自诗歌、聊天、列表、标题、代码注释或使用不同标点习惯的英语变体。规则无法从表面形式完全区分这些情形。若被排除群体在八项评测中占比很低, 模型平均分仍可能提高。代表性分析必须直接检查条件保留率

$$
r_g=P(x\in A\mid g),
$$

其中 $g$ 可以是来源、方言、年代、主题或文体。整体保留率 $P(x\in A)$ 是各 $r_g$ 的加权平均, 可能掩盖某个小群体接近全部消失。 语言识别阈值也属于接受域。FastText 英语分数达到 0.5 才保留, 会移除非英语, 也会影响夹杂代码、公式、专名或多语段落的英语文档。按字节删除 61.7% 表明原始 Common Crawl 中大量内容不符合该范围, 但这个数字不能解释误判率。验证语言过滤需要在阈值附近分层人工标注, 分别估计英语精度与召回。

### 过滤交集需要联合分布

 设规则 $F_i=1$ 表示文档被第 $i$ 个过滤器命中。两个规则组合删除率为

$$
P(F_1\cup F_2)=P(F_1)+P(F_2)-P(F_1\cap F_2).
$$

没有交集项就无法由单项比例推最终规模。若 Gopher 与 NoPunc 分别命中 15.23% 和 22.73% 字符, 完全重合时组合仍只删 22.73%; 完全不重合时可删 37.96%。真实值位于两者之间, 还会因统计单位为字符而不同于文档保留率。 三类以上规则需要更高阶交集。质量、toxicity、PII 和去重若命中近似正交, 组合保留率会快速下降; 若大量命中同一批垃圾文档, 后续规则增量很小。官方附录在高、中、低困惑度桶上计算过滤相关, 并指出 Gopher 与去重在高困惑度尾部呈负相关: 随机字符串会被 Gopher 删除, 却因彼此不重复而不易被去重命中。这解释了为何两类清理具有互补性。

过滤顺序不改变集合交集的理论结果, 会改变实际计算和统计。先删除 Gopher 垃圾后再统计去重命中, 分母已经变小; 报告「去重删除 10%」必须说明相对于原始数据还是当前阶段输入。带状态的 Bloom 去重更复杂, 因为早先插入的内容会决定后来的副本是否命中, 顺序甚至改变保留 ID。

### toxicity 阈值连接性能与价值选择

 论文的 hate 与 NSFW 分类器在 Jigsaw 数据上训练, 对切句后的网页文本评分。句子分数分布近似双峰, 团队比较很低与较高两个阈值。低阈值只要分数略高于零就删除, 高阈值允许更多边界文本。低阈值消融表现更好, 最终 v1.6 仍选择高阈值以保住目标规模。

这个结果不能解释成 toxic 文本越少越好的一般定律。分类器输出混合了真实有害内容、引用讨论、身份词和标注偏差。严格阈值可能删除仇恨表达, 也可能删除对歧视的研究、被攻击群体的自述或少数身份相关语言。八项通用评测不测这些信息损失, 因而性能与代表性需要分开报告。 阈值选择可形式化为约束优化。令 $Q(\tau)$ 是代理质量, $U(\tau)$ 是唯一 token 数, $H_g(\tau)$ 是群体 $g$ 的保留率, 则选择问题类似

$$
\max_\tau Q(\tau)
\quad\text{s.t.}\quad
U(\tau)\ge U_{min},\qquad
H_g(\tau)\ge h_g.
$$

Dolma 明确使用了 $U_{min}$ 规模约束, 没有给出各群体的 $h_g$ 下限。公开分数与阈值让后来者可以补做约束, 前提是保存原始来源和逐句属性。 **2.5. PII 替换也会形成可学习模式.** 把邮箱、IP 与电话替换成特殊 token 能保留句子框架, 降低直接泄露风险。模型仍会学习占位符附近的上下文, 例如「联系」「服务器地址」「电话号码」等。若占位 token 区分类型, 模型还可学习字段类别; 若统一替换, 信息更少。Dolma 的性能消融主要比较删除与替换, 受影响文档比例极低, 无法精确估计细粒度差异。

正则检测有两类错误。假阳性把版本号、示例地址或普通数字当 PII, 造成内容损失; 假阴性漏掉非标准写法、地址、用户名和上下文可识别信息。公开数据的风险更受假阴性影响, 因为一处遗漏会传播给所有下载者。准确率优先的高吞吐规则与隐私召回之间存在明确张力。

文档超过五个命中就整体删除, 会对通讯录、日志、网络配置、论坛索引等文体产生选择性影响。阈值是以命中次数而非文档长度定义, 短文档六个命中与长文档六个命中待遇相同。更细的分析可以报告每千字符命中率、命中类型和来源条件删除率, 再检查删除是否集中于少数合法技术域。

### 分类分数需要校准到实际错误率

 FastText 输出的 0.4 或 0.0004 是模型分数阈值, 不自动等于 40% 或 0.04% 的真实 toxicity 概率。训练数据类别比例、损失和域迁移都会让分数失准。阈值附近抽样人工标注, 才能估计精度、召回和不同来源的条件错误率。

网页句子与 Jigsaw 评论的分布不同。新闻可能引用攻击性语言进行报道, 学术文本可能研究仇恨, 论坛中身份词使用方式也不同。同一分数在各域的实际含义不必相同。全局阈值会给分数分布不同的来源带来不同删除率。 可以按来源 $g$ 绘制校准函数 $P(y=1\mid z,g)$, 再选择满足风险约束的阈值。若某群体的身份词导致假阳性较高, 简单提高全局阈值会同时漏掉其他域的高风险内容; 更合适的修复是改善标注、特征或分域校准。 校准也会随时间漂移。网络语言、新梗与规避写法变化, 固定分类器召回下降。Dolma 公开分类方法使后来者能重标, 但 v1.6 的保存结果仍绑定当时模型与数据。 **2.7. Wikipedia 相似度只是质量的一种坐标.**

KenLM 困惑度按与 Wikipedia 语言模型的相似程度把网页分桶。低困惑度文本更接近百科风格, 高困惑度可能是乱码, 也可能是代码、口语、方言、诗歌或专业符号。把相似度直接叫质量会把文体距离与错误程度混合。 Dolma 没有仅按这一坐标删除, 而是用规则过滤并观察高、中、低桶比例近似不变。这个结果说明 Gopher+C4 NoPunc 与 Wikipedia 相似度捕获的信号不同, 不能说明三桶内部质量完全相同。 若目标是通用模型, 保留一定高困惑度尾部可能增加表达多样性; 若尾部主要由解析垃圾构成, 它会浪费计算。可在每桶内再按规则、来源与人工标签分层, 训练固定 token 的桶混合实验, 观察域能力和训练稳定性。

困惑度还依赖 KenLM tokenizer 和训练语料。换成代码语言模型或 Reddit 语言模型, 同一文档的排序会改变。因此它适合描述「接近哪个参照域」, 不适合脱离参照模型成为永久质量分。 **2.8. 保留率应连同置信区间和抽样设计.** 数十亿文档上的程序计数误差很小, 规则是否符合人类目标的误差却来自有限人工样本。若在某来源抽查 $n$ 篇、观察误删率 $\hat p$, 二项近似标准误为 $\sqrt{\hat p(1-\hat p)/n}$。小群体样本太少时, 整体高精度不能保证其误删率。 简单随机抽样会被常见网页支配。更有信息量的设计按过滤规则、阈值附近、来源、长度和语言分数分层, 对稀有但高风险格过采样, 汇总时再用总体权重还原。这样既能检查边界错误, 也能估计整体影响。

人工标注同样有分歧。quality、toxicity 与页面是否有用并非完全客观, 应报告标注指南、标注者数量和一致性。分歧大的样本可单列, 不强迫一个二元真值掩盖价值冲突。 数据卡里的删除比例属于程序执行事实, 人工审计给出规则有效性的证据。两者缺一, 都不足以证明清洗后的语料达到目标。 **2.9. 最终配方位于多目标前沿.**

数据策展同时关心模型效用 $Q$、唯一 token 数 $U$、代表性 $R$、隐私风险 $P$、许可风险 $L$ 与处理成本 $C$。一个配方 $a$ 若在所有维度都不差于配方 $b$, 且至少一项更好, 才能说 $a$ 支配 $b$。多数现实选择互不支配: 更严格 toxicity 可能提高八项任务表现并降低风险, 却减少 $U$ 和部分群体覆盖; 更强去重降低重复, 也增加计算与误删。 因此最终 v1.6 更接近 Pareto 前沿上的一个点, 位置由 2–3T token 规模、开放分发和当时计算条件共同确定。换成小规模高质量训练、特定领域模型或更严格隐私场景, 合理点会移动。论文公开未采用但表现更好的严格阈值, 让这种移动可以被看见。

比较新配方时应给出向量变化, 例如「任务平均 +0.4、唯一 token -18%、某方言保留率 -9%、PII 命中残留 -30%、处理成本 +12%」。把所有维度压成一个未说明权重的 quality score, 会隐藏价值选择。 模型训练结果只覆盖 $Q$ 的一部分。代表性、许可与隐私还需要数据审计和治理证据。Dolma 的设计意义正在于把这些目标并列记录, 使最终选择能够被重新讨论。

前沿也应按模型规模重算。小模型无法利用的长文档、代码或专业论文, 到更大容量时可能产生收益; 小模型阶段看似便宜的重复文本, 长训练后可能更快进入饱和。固定一组策展权重贯穿所有规模便于复现, 不代表统计最优点不会随训练预算移动。

## 3. 去重、来源配方与混合权重

Web 去重分三步。精确 URL 去重删除 53.2% 文档；精确文档去重在 URL 去重后再删除 14.9%，包括空文档；精确段落去重在 URL 去重后的文档中删除 18.7% 段落，包括空段落。URL 与文档去重先做，可减少后续昂贵处理；段落去重可能扰乱内容分析，所以末尾执行。 去重提升 token 效率并减少记忆风险，但会改变来源分布。新闻、许可证和经典文本天然重复；粗暴去重可能让常见但重要文本代表不足。Bloom filter 误报也会删除未重复项。输入顺序决定保留副本：同一内容出现在高质量来源和网页时，先处理谁可能决定 provenance 与许可。复现必须固定 key、阈值、Bloom 参数和顺序。 **3.1. 代码与社交数据需要不同配方.**

Dolma-Code 含 411B token，来自 2023 年 3 月的 The Stack。The Stack 已用 MinHash 与局部敏感哈希去重，并限定宽松许可仓库。Dolma 再过滤 JSON、CSV 等数据密集文件，组合 RedPajama v1 与 StarCoder 规则：删除重复许可证前导、过长行、数字为主和模板生成文件，筛掉低星仓库、注释比例异常和代码—文本比例低的 HTML。消融显示组合规则相对仅 RedPajama 规则降低代码困惑度并改善通用任务。 代码子集沿用网页 PII 处理，还以 `detect-secrets` 删除包含密钥或软件特有个人信息的文档。这里的误删成本与网页不同：测试 token、示例密钥和占位凭据可能被当真；而漏检真实密钥风险更高。规则版本、匹配类型和删除量应随数据发布。

Dolma-Social 论文正文一处称 80B token，首页表为 89B，分别可能对应版本/计数口径；复现应以最终表与 LaTeX 版本核对。数据来自 2005 年 12 月至 2023 年 3 月的 3.78 亿条 Pushshift 记录。作者比较原子内容、部分线程和完整线程三种线性化，消融显示把每条 submission/comment 当独立文档最好，推测线程组合引入的人为格式损害训练。 质量规则删除短于 500 字符的评论、短于 400 字符的 submission 和长于 40,000 字符的文档；净投票少于 3 的评论也被删除。删除/版主移除/18+ 文档及来自 26,123 个被封禁或 NSFW subreddit 的内容被排除。由于 Reddit 文档短，只要检测到 PII 就删整篇。文档级去重用于消除 copypasta。

投票作为质量信号带明显社会偏差：深层评论天然更少曝光，小众观点和晚发内容也可能低分；情绪化内容与低票的相关性并不等于低信息量。论文用下游消融支持最终选择，但公开数据用户仍应把这种选择视为平台治理与用户行为共同塑造的分布。 **3.2. 其他来源和多源价值.**

C4 会重新经过除 URL 去重外的完整网页管线，进一步清理低质量、重复文本并遮蔽 PII。Semantic Scholar 使用约 4000 万篇开放获取论文组成的 peS2o，后者已针对语言模型完成清洗、过滤、去重和格式化，因此直接使用。Gutenberg 于 2023 年 4 月抓取，保留英语公版书并按书名精确去重。Wikipedia/Wikibooks 使用 2023 年 3 月 English 与 Simple dump，经 WikiExtractor 处理，删除不超过 25 个 Unicode word 的短页。

这些来源规模远小于 Common Crawl，却提供网页之外的代码、学术、书籍与百科分布。论文用 Paloma 的数百细粒度域比较 C4、英语 mC4、RedPajama v1、RefinedWeb、Pile 与 Dolma 上训练的 1.2B 模型。Pile 虽规模小但多源，因此领域拟合好；Dolma 与 RedPajama v1 同样覆盖更广；单一网页来源平均困惑度更高。这支持纳入非网页来源，而非证明某个固定比例永远最优。

### 去重把重复频率改写成样本权重



设内容簇 $c$ 在原始语料出现 $m_c$ 次。未去重时, token 级经验分布中该内容权重近似与 $m_cL_c$ 成正比; 精确文档去重后只保留一份, 权重变为 $L_c$。去重相当于把重复次数这个隐含采样权重压到 1。若重复来自镜像、抓取故障或模板, 这种修正合理; 若重复反映真实语言频率, 全部压平会改变目标分布。

URL、文档和段落去重作用于不同等价关系。URL 去重认为相同地址的多次抓取等价, 可以消除 snapshot 重复; 文档去重忽略 URL, 处理镜像或同内容多地址; 段落去重进一步删除不同文章共享的模板。三层逐渐从「同一对象重复采集」走向「不同对象共享文本」。越往后, 误删真实共用表达的风险越高。

输入顺序决定保留哪个副本。设同一论文同时出现在作者主页、出版站点和抓取镜像, Bloom filter 先看到的版本成为代表。若副本正文相同而元数据、许可或周边文本不同, 保留选择会影响 provenance。确定哈希只保证相同输入顺序可复现, 无法使保留副本与质量目标自动一致。 更明确的策略可先给副本簇排序: 优先保留许可清晰、来源可信、解析完整、时间较早或元数据丰富的成员, 再删除其余副本。Dolma 的高速流式 Bloom 路线换取规模可行性, 没有对每个全局簇做这种昂贵排序。因而去重收益与 provenance 选择要分开理解。 **3.4. Bloom filter 的误报会形成单向删除.** Bloom filter 用 $m$ 位数组和 $k$ 个哈希存储已见元素。插入 $n$ 个元素后, 经典近似误报率为

$$
p_{fp}\approx\left(1-e^{-kn/m}\right)^k.
$$

它没有假阴性前提是状态完整且哈希过程一致, 但会把部分新元素误判为已见。误报在去重中产生单向损失: 文档或段落被删除后不会在后续阶段自动恢复。容量估计偏小、插入元素超预期或重复使用已饱和 filter, 都会提高误报率。 若需要处理十亿级键, 即使 $p_{fp}=10^{-4}$, 期望误删也可达到十万量级。总体比例很小, 仍可能集中伤害后处理来源: filter 随处理推进越来越满, 后来的来源面对更高占用率并且更常被前面来源判重复。固定来源顺序是复现条件, 随机轮换顺序则可用来测顺序敏感性。

去污染复用同一结构时, 误报含义改变。先把 benchmark n-gram 放入 filter, 再检查训练文本, false positive 会把与测试集无关的内容标为污染; false negative 还可能来自归一化、分词或短语改写不一致。公开参数和命中样本比一个「已去污染」标签更有信息。

### 混合比例决定每个来源被训练多少遍

 附录比较四种 mixture。Naive 按所有可用内容各取一次, token 比例约为网页 83.5%、代码 13.8%、参考资料 2.5%、书籍 0.2%。Reference+ 把参考资料与书籍上采样两倍, 比例变为 81.2%、13.5%、4.9%、0.4%。Gopher-like 只取 17% 网页、8% 代码, 同时把参考和书籍上采样两倍, 最终比例为 68.4%、5.4%、24.2%、2.0%。Web-only 则完全移除后三类。 表里的 Sampling 与 Proportion 不能混用。Sampling 说明每个来源相对自身数据读几遍, Proportion 是归一化后的 token 占比。参考资料从 100% 改为 200% 并不自动得到两倍最终比例, 因为其他来源也在变化。给定原始 token 数 $T_s$ 和采样倍数 $u_s$, 最终比例为

$$
\pi_s=\frac{u_sT_s}{\sum_j u_jT_j}.
$$

当训练预算 $B$ 小于混合后总量时, 实际每来源读到的 token 约为 $B\pi_s$; 若超过唯一数据量, 某些来源会重复。小型 Gutenberg 只占约 6B token, 在多万亿预算与上采样下更容易跨 epoch 重用。 mixture 搜索的目标不是让所有来源困惑度同时最低。提高代码权重通常改善代码域, 可能减少网页和自然语言 token; 增加论文有利于学术域, 也可能过度集中正式文体。可以写成多目标风险

$$
J(\pi)=\sum_{k=1}^{K}\lambda_kR_k(\theta(\pi)),
\qquad \sum_s\pi_s=1,
$$

其中 $R_k$ 是目标域风险, $\lambda_k$ 由模型用途决定。论文展示不同 mixture 的域拟合, 没有给出一组脱离用途的最优 $\lambda$。 **3.6. 少量域数据已经可能改变表示.** mixture 实验显示四种配方在 C4 的 100 个网页域上困惑度接近, Web-only 在 HumanEval 代码域明显较差。S2ORC 学术域上, Reference+ 的参考资料占 4.9%, Gopher-like 占 24.2%, 二者结果却近乎相同。这个现象说明域拟合对数据比例可能存在快速收益后饱和, 无法据此认定 4.9% 是普遍阈值。 饱和点同时取决于域内多样性、模型容量、训练 token 和与其他来源的重叠。学术语言也存在于 Common Crawl, 所以 4.9% 显式论文之外还有隐式学术网页; 代码域的语法更独特, 移除 The Stack 后缺口更明显。来源标签不等于语义域的纯分区。

代码比例实验给出更细证据。C4 与 The Stack 按 0%、5%、15% 代码训练后, bAbI ICL 从 0.0 升到 $8.8\pm0.9$、$10.1\pm2.8$; WebNLG 从 $16.8\pm1.1$ 升到 $19.3\pm1.1$、$22.0\pm1.3$。GSM8K 直接 ICL 和普通微调仍为 0, 使用 program-aided language 形式微调后则从 $11.8\pm0.8$ 升到 $14.2\pm1.3$、$14.7\pm0.9$。 这组结果支持代码数据与特定推理、结构生成能力相关, 也暴露任务接口的中介作用。GSM8K 的改善只在要求模型生成 Python 程序的 PAL 设置出现, 因而不能归结为抽象数学推理全面提高。bAbI 与 WebNLG 的样本量、模型规模和 5 个随机种子也限制外推。

### 来源权重还会改变梯度方差

 训练中每个来源产生不同损失尺度和梯度方向。若按来源 $s$ 采样概率为 $\pi_s$, 单步梯度 $g$ 的方差包含来源内方差和来源间均值差异:

$$
\operatorname{Var}(g)=
\sum_s\pi_s\operatorname{Var}(g\mid s)
+\sum_s\pi_s\|E[g\mid s]-E[g]\|^2.
$$

代码、网页与论文交替会让 batch 梯度更异质。mixture 改变的不只有长期知识覆盖, 还会改变优化噪声、损失曲线和学习率适配。小模型上稳定的比例放到更大 batch 或不同 packing 后, 来源间方差的表现可能变化。 如果一个 batch 严格来自单一来源, 来源间差异直接表现为 step 波动; 若 batch 内按 token 混合, 梯度先在 batch 中平均。Dolma 论文主要报告结果配方, 没有把 batch 构造作为 mixture 消融轴。复现时需要记录采样是在 shard、文档、序列还是 token 层发生。 **3.8. Common Crawl snapshot 不应默认等权.** 25 个 snapshot 的页面数量、重复率、语言比例和站点覆盖不同。若简单拼接, 体量大的 snapshot 获得更高权重; 若每个 snapshot 等量采样, 小 snapshot 被相对放大。两种策略对应「按抓取到的页面频率」与「按时间点平均」两种目标。

同一 URL 跨 snapshot 重复时, URL 去重把多次出现压成一份。稳定页面与只出现一次的页面最终权重相同, 时间持久性信号被删除。若保留重复, 长期存在的模板又会支配训练。可以额外保存出现次数, 在硬去重后把它作为分析特征。 snapshot 顺序还影响保留版本。网页在三年间更新, 同 URL 的正文并非严格相同; URL 去重若只看键, 可能直接丢掉后续版本。若先比较内容哈希, 可区分未变副本与真实更新, 代价是更多存储和处理。 时间等权、页面等权和域名等权没有天然赢家。新闻知识需要时间覆盖, 通用语言可能更关心域名多样性。目标决定权重, 报告应给出策略而不只列 snapshot 范围。

### 代码数据的单位可以是文件、仓库或提交



The Stack 把代码文件作为主要文档单元, 但统计依赖存在于仓库。一个自动生成仓库含十万文件, 可能压过许多小型人工项目; 多个 fork 又复制整个文件树。文件级均匀采样隐含偏爱大仓库。 若先均匀抽仓库再抽文件, 每个项目权重更接近; 若按 token 采样, 大文件与大仓库占优; 若按 star 过滤, 社区受欢迎度进入分布。Dolma 组合低星阈值、注释比例和代码文本规则, 改变的不只是文件质量, 也改变项目规模与社区结构。 许可证通常在仓库级, 文档训练却拆成文件。去除重复许可证前导能减少模板, 仍需让每个文件保留可追溯仓库和许可。文件跨仓库重复时, 选择哪个副本决定 provenance。

代码 token fertility 较高, 15% token 代码可能对应更少字符。比较代码比例时应同时给文件、字符、token 与仓库数, 才能判断改善来自更多项目还是更细 tokenization。 **3.10. 社交线程线性化改变条件概率.** 把每条评论当原子文档时, 模型学习 $p(c)$, 缺少它回复的上文; 部分线程让模型学习 $p(c_t\mid c_{<t})$, 但必须引入用户分隔、树到序列的遍历和上下文截断; 完整线程还要决定多个兄弟回复的顺序。三种表示定义了不同训练任务。 Reddit 是树, 任意深度优先或广度优先线性化都会把原本并行的兄弟评论放入同一序列。模型可能误以为后一位用户在回复前一位兄弟, 而实际两者都回复父节点。加入显式层级标记可缓解, 同时产生平台特有 token 与格式。

原子内容在论文 1.2B 消融中最好, 可能说明人为线程格式的代价超过上下文收益。它也可能受模型上下文长度、模板或截断方式影响。对面向对话的后训练, 线程关系价值会更高; 预训练最优表示不必等于聊天训练最优表示。 投票阈值又与树深相关。越深的评论曝光更少, 更难达到净票数 3; 过滤后语料会偏向主干和早期回复。按线程深度报告保留率能区分内容质量与曝光机会。 **3.11. 域权重可以用目标梯度对齐解释.** 某来源是否帮助目标域, 取决于其训练梯度与目标梯度的方向。设来源 $s$ 的平均梯度为 $g_s$, 目标验证风险梯度为 $g_q$。一次小更新 $-\eta g_s$ 对目标风险的一阶变化约为

$$
\Delta R_q\approx-\eta g_q^Tg_s.
$$

内积为正时来源更新倾向降低目标风险, 为负时可能产生干扰。内容相似通常提高对齐, 但代码也可能通过结构或工具使用帮助非代码任务, 论文的 bAbI、WebNLG 与 PAL 结果就显示跨域作用。 梯度对齐随训练阶段变化。早期通用语法尚未学会, 多数高质量文本方向相似; 后期模型进入专业能力分化, 来源冲突更明显。固定 mixture 在全程使用方便, 动态课程可能更有效, 也更难验证和复现。 实际不必保存全模型梯度。可用小模型、低秩投影或短程训练后的验证变化估计来源相容性。任何估计都绑定模型状态, 不能把来源分数当永久属性。

## 4. 数据消融的因果证据与外推边界

团队训练 decoder-only OLMo-1B 做最终管线验证。论文称它相对最可比的 TinyLlama 平均更好，并在八项任务中的四项胜出；但 PDF 双栏抽取容易打乱表 2 列顺序，精确数字必须回到 `tables/1b.tex`。模型的训练 token 也不同：Pythia 少近十倍，StableLM2 在 2T token 上训练两个 epoch但未公开组成，只有 TinyLlama 较接近。 因此表 2 不能视为纯数据集因果比较。模型架构、训练 token、优化器和实现差异都会影响分数。数据选择主要依据控制架构与训练的 1.2B 消融，OLMo-1B 表格用于检查最终管线的端到端表现。论文也指出 1B 模型的 zero-shot 任务较难；这些模型虽超过随机水平，绝对分数仍不宜与大模型直接比较。 **4.1. 开放发布、许可与治理.**

Dolma 数据集采用 ODC-BY，但顶层开放许可不会自动消除每个底层来源的权利差异。团队因诉讼避开 Books3，正说明可分发性是主动约束。GitHub 等来源应保留许可与标识，稳定 `source+id` 支持 provenance、blocklist 和删除请求。 网页规模下仍会漏掉 PII、毒性和版权风险。Datasheet、版本号和删除渠道必须与数据一起使用。研究者不能因“开放下载”就推断所有用途无风险。模型训练后，删除请求也难以从权重中撤销，这要求数据版本和模型 lineage 保持关联。 数据版本不能只写“Dolma”。论文对应 v1.6，Hugging Face 与仓库仍会更新。复现实验必须记录具体 revision、shard manifest、校验和、tokenizer、混合比例和 EOS/文档拼接规则。三万亿 token 是版本化统计，不是永恒属性。 **4.2. 精确复现与验收.**

复现需要保存原始来源 snapshot 和对象 manifest；每个 tagger 的代码、模型、阈值与属性校验和；去重顺序、Bloom filter 参数和文件；Mixer 配置、来源权重、输出 manifest；训练 tokenizer 与 token 统计。远程 glob 若随时间增长，即使配置相同也会漂移，应先解析成不可变清单。 统计验收至少包括每阶段文档、字节、字符、token，按来源/语言分层的过滤率，规则交集，去重命中，PII 替换/删除，失败 shard 与输出校验和。论文中的 61.7%、84.2%、53.2%、14.9%、18.7% 等精确数字是审计锚点；复现明显偏离时，应先查 snapshot、规则版本和计数单位。 消融复现还要固定初始化、优化器、学习率、150B token 调度、batch、评测 prompt、split 和污染检测。只重做过滤但更换训练栈，无法把差异归因于数据决策。多个随机种子和置信区间能避免把小幅波动误当整理收益。 **4.3. 论文自身的限制与贡献.**

Dolma 最重要的贡献是把数据从模型论文中的一句概括展开为可批评的决策：为何只做英语，为何混合六类来源，为何采用 Gopher+C4 NoPunc，为何更严格 toxicity 表现更好却未用于 v1.6，为何用正则处理 PII，以及为何发布 Toolkit。 限制同样清楚：小模型消融不保证尺度外推；Bloom filter 有误报；toxicity/quality 带价值判断；PII 过滤不完备；法律与伦理会改变配方；规模目标迫使团队接受性能并非最优的阈值。Paloma 的领域拟合说明多源有价值，但不证明最终混合比例最优。 Dolma 是带有明确策展政策、已知误差和版本边界的数据产品。“已清洗”只表示执行了对应版本的过滤与去重流程，并不保证语料正确、无风险或适合所有用途。模型结果要与具体 Dolma revision、tokenizer、mixture 和训练预算绑定，后续研究才能验证和修改其中的取舍。

**4.4. 单因素消融识别的是整条配方的局部效应.** 理想的过滤消融从同一原始样本出发, 固定模型、tokenizer、训练 token、初始化和优化过程, 只切换过滤器 $F$。若两模型指标差为

$$
\hat\tau=Y(F=1)-Y(F=0),
$$

它估计的是该原始分布、阈值、模型规模与预算下的局部处理效应。换一批 Common Crawl snapshot、换阈值或先执行另一项过滤, 接受集合改变, $\tau$ 也可能改变。 固定训练 token 很重要。过滤后数据量变小, 若仍训练 150B token, 严格配方可能比宽松配方重复更多内容; 固定 epoch 则严格配方看到更少 token。前者比较等计算预算下的终点, 后者比较每份唯一数据使用相近次数的终点。两个问题都合理, 结论却不同。 消融还可能改变长度分布。删除短页面、无标点段落和模板后, 平均文档变长, packing 浪费与 EOS 密度随之变化。性能差异包含文本内容质量与序列构造变化。要进一步归因, 可从两份配方中按长度、来源和时间重加权出匹配子集, 再比较模型。

### 过滤器之间存在交互项



设质量过滤为 $Q$, 内容过滤为 $C$, 四种处理结果为 $Y_{00},Y_{10},Y_{01},Y_{11}$。两者交互可写为

$$
\Delta_{QC}=Y_{11}-Y_{10}-Y_{01}+Y_{00}.
$$

若为零, 两项效果在该尺度近似可加; 正值表示组合收益超过单项相加; 负值可能说明两者删除相同垃圾、严格组合损失过多数据, 或模型收益已饱和。只分别训练 Q 与 C, 没有 $Y_{11}$ 就无法识别交互。 Dolma 对最终网页管线做了组合实验, 发现质量、内容和去重的改善具有复合效果, 同时删除集合重叠较少。这提供了交互证据, 仍难把交互归到某对规则, 因为完整组合包含多项变化。全因子实验随规则数指数增长, 实践中可优先检查删除量大、统计相关低的规则对。

交互还会跨来源出现。网页过滤变严格后, 固定预算下代码和参考资料相对权重可能上升; 此时观察到的能力变化部分来自 mixture 重归一化。若要测网页规则自身, 应固定最终各来源 token 数。若目标是测真实端到端配方, 则应允许归一化变化, 但结论要绑定整个 mixture。 **4.6. 八项任务无法定义完整的数据效用.** 论文从已有语言模型研究中选择八项任务, 统一为 zero-shot ranked text classification。统一接口降低评测差异, 也使效用集中在多选与排序能力。生成质量、代码执行、事实召回、安全、多语、长上下文与领域专业能力都未直接进入选择目标。

设真实关心的指标向量为 $Z\in\mathbb R^K$, 论文观察投影 $MZ$, 其中 $M$ 只选取八项指标。两个过滤配方可在 $MZ$ 上排序一致, 在未观测维度上相反。严格 toxicity 过滤提高八项平均, 不能推出安全生成一定改善; 代码过滤提高通用任务, 也不能替代代码执行评测。 指标平均还隐藏权重。若八项等权, 一个小众任务与一个核心任务贡献相同; 若按样本数微平均, 大题集支配结果。报告逐任务轨迹比只给平均更能判断效果是否集中。多个随机种子则用于区分小幅差异与优化噪声。 **4.7. 小模型排序外推需要稳定性假设.** 用 1.2B、150B-token 模型选择万亿 token 配方, 隐含假设是处理效果的排序随参数量 $N$ 与训练预算 $D$ 大致稳定。记配方 $a,b$ 的差异为

$$
\Delta(N,D)=Y_a(N,D)-Y_b(N,D).
$$

小模型消融只观察一个或少数 $(N,D)$ 点。要外推到大模型, 需要 $\operatorname{sign}\Delta(N,D)$ 不翻转。数据质量可能在小模型更重要, 因为容量有限; 也可能在大模型更重要, 因为大模型能利用长尾高质量结构。没有缩放网格就无法决定。 训练过程中的曲线比单一终点多一点证据。若配方 A 从早期到 150B token 始终领先 B, 排序较稳; 若两条曲线临近终点才交叉, 延长训练可能再次改变。论文图展示多个训练迭代, 但多数消融仍是单规模, 不能替代跨规模验证。 可采用低成本阶梯实验: 在多个小参数量与 token 预算上训练同一配方对, 拟合 $\Delta(N,D)$ 的趋势, 只把符号稳定且效应大于随机波动的选择升级到大训练。若配方差异随规模缩小到零, 继续扩大实验的价值有限; 若出现交叉迹象, 应保留两条候选。
