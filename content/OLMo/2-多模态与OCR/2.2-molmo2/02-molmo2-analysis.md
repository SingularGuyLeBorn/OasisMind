# Molmo2: 开放数据的视频理解与时空 grounding

Molmo2 是 Ai2 在 2026 年初发布的视觉语言模型系列, 技术报告为 arXiv 2601.10611 (逐段译文见 [Molmo2 对照译稿](01-molmo2-bi.md)). 最有三个规格: Molmo2-4B 和 Molmo2-8B 用 Qwen3 做语言模型, Molmo2-O-7B 用 [OLMo 3](../../1-模型技术报告/1.5-olmo-3/02-olmo-3-analysis.md) 7B Instruct, 后者从视觉编码器到语言模型再到训练数据都可以公开获取. 代码在 [allenai/molmo2](https://github.com/allenai/molmo2), 权重在 Hugging Face 的 [allenai/Molmo2-8B](https://huggingface.co/allenai/Molmo2-8B) 等仓库.

前作 [Molmo](../2.1-molmo/02-molmo-analysis.md) (arXiv 2409.17146) 只处理单张图片, 最的主要贡献是 PixMo 数据: 口述式图像描述, 二维点标注和人工问答, 并且不从闭源 VLM 蒸馏. Molmo2 沿用这条约束, 把输入扩到视频和多图, 输出扩到时空点和跨帧轨迹.

## 1. 从 Molmo 到 Molmo2 的结构改动

### 1.1. 同一个连接器, 多了时间轴

Molmo2 的骨架和 Molmo 一样: 视觉编码器出 patch 特征, 连接器把特征池化后投影进语言模型, 语言模型自回归生成. 视觉编码器换成 SigLIP 2 So400m/14, 输入分辨率 378, 每张裁剪图得到 $27\times27=729$ 个 patch. 连接器取 ViT 倒数第 3 层和倒数第 9 层的特征拼接, 用多头注意力池化, query 是窗口内 patch 的均值, 然后过一个 MLP. 图片用 $2\times2$ 窗口, 视频帧用 $3\times3$ 窗口. 代码按向上取整处理边缘, 一张裁剪图池化后是 $14\times14=196$ 个 token, 一帧视频是 $9\times9=81$ 个 token.

图片的切图方式也沿用 Molmo: 一张缩放到 378 的全局图, 再加最多 $K$ 张重叠裁剪图. 训练时 $K=8$, 推理时 $K=24$. 和 Molmo 不同的是, Molmo2 不再给裁剪图补黑边, 而是直接缩放到 378, 宽高比可以改变, 这和 SigLIP 2 训练时的做法一致. SFT 阶段对 30% 带 pointing 标注的图片把 $K$ 放到 24, 让模型在训练中也见过推理时的切图数量. 需要留意 Hugging Face 上的 processor 默认 `max_crops` 是 8, 想复现论文里的图像分数, 推理时要手动调到 24.

![Molmo2 模型结构](images/model_figure_2.png)

> 图 1: Molmo2 的结构, 视频帧和图像裁剪经 ViT 与连接器后, 与时间戳和图像编号文本交错输入 LLM, 原文 Figure 2

输入序列把视觉 token 与时间标记交错排列. 每帧视频前插入以秒为单位、保留一位小数的文本时间戳, 每张图片前插入图像编号, 然后整体送进 LLM. 模型据此识别时间和顺序, 无需额外的时间位置编码.

另一处结构改动是注意力掩码. 视觉 token 之间改成双向注意力, 跨帧也可以互相看到, 文本 token 仍然是因果掩码. 消融里去掉双向注意力, 视频 QA 平均从 64.8 降到 64.4, 描述 F1 从 39.5 降到 38.5. 去掉时间戳文本时, QA 降到 64.5, 描述 F1 降到 37.4, 描述对时间信息更敏感.

### 1.2. 帧采样与 token 预算

视频按 $S=2$ fps 采样, 帧数上限为 $F$. 视频长度超过 $F/S$ 秒时改为均匀采样 $F$ 帧, 并且总是保留末尾一帧. SFT 阶段 $F=128$, 对应 64 秒以内的视频按 2 fps 完整采样. 长上下文 SFT 和推理时 $F=384$, 对应 192 秒. 论文给出每帧 83 个 token, 其中 81 个来自 $9\times9$ 网格, 文中没有给出另外 2 个的组成, 从输入格式看应来自帧前的时间戳文本.

按这个数字可以算出两个预算. $128\times83=10{,}624$, 约 10.6k token, 放进 16,384 的 SFT 序列后还剩约 5.7k 给问题和回答. $384\times83=31{,}872$, 放进 36,864 的长上下文序列后剩约 5k. 也就是说, 序列长度是按帧上限倒推出来的, 不同阶段的帧数上限和序列长度一一对应.

![帧数上限与长视频性能](images/long_video_average_for_max_frames.png)

> 图 2: 长上下文训练之前的模型在不同最大帧数下的长视频基准平均分, 原文 Figure 7

曲线从 128 帧的 64.57 升到 224 帧的 65.62, 随后逐步下降, 512 帧时降至 63.18. 这组模型只经过 16k 序列 SFT, 训练时最多见过 128 帧; 推理帧数提高到约两倍仍有收益, 继续增加便超出训练分布. 长上下文 SFT 阶段正是为这段分布外区间补训练.

在 TestingTime 增加帧数之外, 论文还试了 SlowFast 编码: 每隔 $p$ 帧取一帧做 $3\times3$ 池化的慢帧 (83 token), 其余帧做 $9\times9$ 池化的快帧, 每帧 $3\times3=9$ 个视觉 token, 加时间戳约 11 个 token. $p$ 取 1, 2, 3, 4 时总帧数分别为 128, 224, 300, 368. 用这些数字复算: $p=4$ 时 $92\times83+276\times11=10{,}672$, $p=3$ 时 $100\times83+200\times11=10{,}500$, $p=2$ 时 $112\times83+112\times11=10{,}528$, 三者都落在 10.6k 附近. 也就是说, SlowFast 把同样的 token 预算摊到更多帧上.

**点, 轨迹与计数共用一种输出格式。**

Molmo 用 XML 风格的 `<point x="..." y="...">` 输出图像点, 坐标是百分比. Molmo2 改成一种更紧凑的纯文本格式: 每个点写成 「图像编号或时间戳, 物体编号, x, y」, 坐标归一化到 0 到 1000 的整数. 点按时间或图像编号排序, 同一帧内按 x 再按 y 排序. 物体编号从 1 开始连续递增, 所以末项编号就是计数结果. 视频的时间戳写成秒数, 多图写成图像编号.

这个格式有两个作用. 一是计数和定位合并成一个任务, 模型先逐个指出物体再报数. 消融里, 只训练直接回答数字时 Molmo2-VideoCount 准确率是 28.1, 改成先点后数后是 34.5. 二是 tracking 可以写成同一种格式: 每个时间戳列出所有目标物体的点, 物体编号跨帧保持不变, 就构成轨迹. 评测时再用 SAM 2 把点转成分割掩码, 和基准的掩码标注比较.

附录 A 给出的输出示例分三组: 第一组是 1 号物体, 第二组是 3 号和 4 号, 第三组是 5 到 7 号, 一共 6 个点, 编号 2 缺失. 按正文规则, 编号应当从 1 开始连续, 末项编号等于计数, 而示例的末尾编号 7 和 6 个点不一致. 这是示例排版错误, 训练数据的格式以代码中的生成逻辑为准. 另外, Hugging Face 模型卡建议做 tracking 时把 `max_fps` 调到 8, 论文的评测设置里没有这一项.

## 2. 九个数据集怎样覆盖视频与多图

### 2.1. 描述数据先解决“看见了什么”

Molmo2 的数据设计没有把“视频理解”压成一个问答集合, 而是拆成描述、问答、指点、跟踪和多图五类能力. 描述侧包含 Molmo2-Cap. 标注流程先把视频切成片段, 让人工标注者逐段口述, 再生成覆盖整个视频的长描述. 逐段标注保留了事件发生的先后顺序, 完整描述则要求把这些局部观察组织成连贯叙述. 报告给出的训练集规模为 17.9 万个视频, 共 95.6 万条描述; 其中逐片段描述和整段描述承担不同作用, 前者提高细节召回, 后者训练跨片段组织.

作者没有把单一人工转录直接当成最终答案. 消融显示, 只用整段人工转录的描述模型弱于加入逐帧描述信息的版本. 原因可以从监督密度理解: 人在连续口述时更关注动作主体和情节, 容易略过背景文字、物体属性和短暂出现的细节; 逐帧信息补足静态观察, 但单独堆叠又缺少时间上的叙事结构. Molmo2-Cap 因而把两种信号合并, 训练目标同时要求细节覆盖和时间连贯.

### 2.2. 问答数据把监督放到时间定位上

Molmo2-AskModelAnything 由标注者观看视频并提出不能靠常识直接回答的问题, 再完成答案. Molmo2-CapQA 从描述材料生成问题, Molmo2-SubtitleQA 则面向带字幕视频, 要求把画面事件与字幕内容对齐. 三者的差别不只是问题来源: 人工自由提问更容易覆盖真实使用意图, 描述派生问答能把长描述中的细节变成短目标, 字幕问答专门训练视觉和文本两条时间流的对应关系.

字幕在模型输入中位于视觉序列之后, 每段字幕也带文本时间戳. 这个安排避免把字幕烧录进图像后再做 OCR, 同时让语言模型直接比较“某句话何时出现”和“对应画面发生什么”. 最的边界也很明确: 字幕时间轴不等于说话者身份, 若视频没有可靠字幕, 模型仍需依赖采样帧; 当关键动作短于 0.5 秒时, 2 fps 采样可能完全漏掉最.

**指点和跟踪把答案变成可检查的坐标。**

Molmo2-VideoPoint 的标注不是只给一个数量. 标注者针对问题在若干帧上指出所有匹配实例, 训练样本最多保留 60 个点. 模型输出点以后再给出计数, 因而错误可以分成漏检、误检、重复计数和数字汇总错误. 报告的消融还表明, Molmo2 自建视频指点数据与学术数据互补: 前者在自建指点指标上更强, 后者在 BURST-VideoCount 上有优势, 混合训练在几个指标间更稳.

Molmo2-VideoTrack 从边界框或分割掩码生成跨帧点轨迹, 同一个对象在各帧沿用同一编号. 训练中还加入两个辅助任务: 预测目标首次和末次出现的时间与位置, 以及从给定点开始跟踪目标. 前一个任务提供粗粒度时间边界, 后一个任务模拟用户点击目标后的交互. 消融中, 加入视频指点数据能改善跟踪, 使用边界框轨迹和 Molmo2-VideoTrack 也有增益; 时间 grounding 有帮助, 单点跟踪辅助任务反而略降, 说明形式相近的监督不必然正迁移.

**多图任务检验跨图索引是否可靠。**

多图侧包括 Molmo2-MultiImageQA、Molmo2-SynMultiImageQA 和 Molmo2-MultiImagePoint. 输入中的每张图都有编号, 回答需要跨图比较、查找或计数. 合成多图问答把文档、图表、表格等材料组成需要跨页取证的问题; 多图指点则在输出坐标前带图像编号. 这样, 图像选择本身也成为预测的一部分, 不能只在每张图内独立作答再拼结果.

这组任务复用了视频输入的核心抽象: 视频帧可以看成带时间戳的有序多图, 普通多图则是带离散编号的序列. 共享连接器和坐标格式减少了任务专用模块, 代价是顺序、时间和空间位置都要由语言模型在一条长序列里区分. 多图数量或视频帧数增加时, 视觉 token 会线性增长, 所以模型的能力上限同时受上下文长度、采样策略和视觉池化粒度约束.

## 3. 三阶段训练怎样分配容量

### 3.1. 轻量预训练先稳定视觉连接

第一阶段使用 PixMo-Cap 的密集描述和转录预测, 再加入 PixMo-Points、PixMo-Count、CoSyn-Point 以及过滤掉非英语和代码的 Tulu SFT 数据. 混合比例为 60% 描述、30% 图像指点、10% 纯文本. 训练 32,000 步, 批大小 128, 序列长度 2,560, 约覆盖 PixMo-Cap 四个 epoch; ViT、连接器和语言模型全部更新, 三部分采用独立学习率. 报告列出的峰值学习率分别是 $6\times10^{-6}$、$2\times10^{-4}$ 和 $2\times10^{-4}$.

把指点提前放进预训练的作用是让坐标生成不再是 SFT 才突然出现的新输出语言. 作者报告这会让指点表现更好也更稳定. 10% 的文本数据则用于减轻全参数视觉训练对原有语言能力的侵蚀. 这里没有单独冻结视觉编码器或 LLM, 所以训练配比不是附属设置, 最直接决定各类梯度对同一组参数施加多大影响.

### 3.2. 联合 SFT 面对的是长度失衡

第二阶段混合 PixMo、九个 Molmo2 数据集、Tulu 和其他开放图像与视频数据. 作者先按任务类别人工设置采样率, 类别内再按数据集大小的平方根采样, 并对大型合成集额外降采样. 训练 30,000 步, 批大小 128, 最大序列长度 16,384; 此阶段 ViT 和连接器学习率均为 $5\times10^{-6}$, LLM 为 $10^{-5}$. 平方根采样压低大数据集的支配程度, 但不能消除不同答案长度带来的损失占比差异.

一条选择题答案可能只有一个 token, 长视频描述却可能超过 4,000 个 token. 若对所有答案 token 等权求损失, 少量长描述就能贡献多数梯度. Molmo2 对视频描述使用 0.1 的固定权重, 对指点使用 0.2; 其他任务按 $4/\sqrt{n}$ 加权, $n$ 是答案 token 数. 这个函数仍让长答案获得更多总信号, 但增长速度从线性降为平方根量级. 消融中去掉 token weighting 后, 视频 QA 平均从 64.8 降到 64.3, 描述 F1 从 39.5 升到 40.1, 展示了短答案与长描述之间的容量竞争.

**packing 和 message tree 解决算力浪费。**

样本长度从几百 token 到 16k 以上不等, 按最长样本补齐会浪费大量计算. Molmo2 用在线 packing 从内存中的小样本池拼出接近上限的序列, 同时打包 ViT 裁剪图和 LLM token. 带多个标注的同一视觉输入则表示为 message tree: 图像或视频是根节点, 不同问答成为分支, 自定义注意力掩码禁止分支互相读取答案.

每个视觉样本平均有 4 条标注. 论文报告, packing 平均能在一条 16,348 token 的序列里放入 3.8 个样本, 结合共享视觉输入得到约 15 倍训练效率. 这个倍数不能理解成模型计算整体加速 15 倍: 最描述的是相对于逐条重复编码视觉输入和大量 padding 的数据利用率改善. 自定义掩码还必须隔离 packed sequence 中的不同样本, 否则后一个问题可能读取前一个样本的答案.

**长上下文阶段只做短程适配。**

第三阶段沿用 SFT 混合, 把上下文扩到 36,864, 帧上限升到 384, 训练 2,000 步. 每个样本由 8 张 GPU 组成上下文并行组, LLM 使用 Ulysses attention; 视觉编码器的逐帧计算和连接器池化也分散到同一组设备. 作者只把最放在末尾做短阶段训练, 因为长序列会显著增加通信和显存开销.

这一步主要改善长视频 QA, 短视频 QA 和图像 QA 变化不大, 描述指标则下降. 最说明延长窗口不是无条件增益: 模型获得了处理更多帧的位置适应, 但联合目标中的描述能力可能因短程训练分布改变而退化. 部署时也不能只把 `max_frames` 从 128 改成 384 就期待同等收益, 因为未经长上下文适配的模型在 224 帧之后已经出现下降.

## 4. 怎样读主结果

### 4.1. 开放模型中的优势集中在哪些任务

主表把 API 模型、只有开放权重的模型、可获得代码和部分训练材料的模型, 以及 Molmo2 家族分开列出. Molmo2-8B 在短视频 QA 平均为 69.9, 长视频 QA 平均为 64.1, 全表平均为 63.1; Molmo2-4B 分别为 69.3、64.5 和 62.8. 8B 并没有在每个长视频基准都胜过 4B, 因此参数量不是表中差异的唯一来源.

更突出的结果出现在描述和计数. Molmo2-8B 的 Molmo2 Caption F1 为 43.2, Molmo2 Count 验证准确率为 35.5; Molmo2-4B 分别为 39.9 和 34.3. 与 Qwen3-VL-8B 表中的 26.7 和 29.6 相比, 自建高密度描述与先指点后计数训练带来明显差异. 但这些数字来自 Molmo2 自建评测, 更适合验证该训练配方是否学到目标格式, 不能单独代表所有真实视频任务.

### 4.2. 人工 Elo 与自动基准回答不同问题

作者还对模型生成的长描述做成对人工比较, 用 Bradley-Terry 模型从胜负关系拟合 Elo. 主表中 Molmo2-8B 的 Elo 为 1057, 排名第 5; Gemini 2.5 Pro 为 1096, 排名第 1. 这个排序衡量的是人工对描述完整性和质量的偏好, 与多项选择准确率并非同一指标. GPT-5 的自动基准平均分高于 Molmo2-8B, 但描述 Elo 为 1031, 也展示了两类评价之间的不一致.

论文用 bootstrap 估计成对胜率的不确定性, 并对长度作了专门检查. 长答案容易因覆盖更多细节而得到偏好, 也可能因重复和幻觉受罚. Elo 把多个对手的比较压成一个标量, 会隐藏模型在哪类视频上获胜; 因此还需同时查看原始胜率、描述 F1 和定性样例.

**tracking 指标依赖点到掩码的转换。**

Molmo2 生成的是点轨迹, 常见跟踪基准提供的却是分割掩码. 评测先把预测点输入 SAM 2 得到掩码, 再计算区域相似度和轮廓质量. 因此最终分数包含两个系统的误差: Molmo2 可能点对目标但 SAM 2 分割失败, 也可能点略有偏移却被 SAM 2 修正. 这个流程适合把文本式点输出接到既有基准, 但不等价于模型直接生成掩码.

作者另外构建了 Molmo2-VideoTrack Benchmark, 强调多目标、目标离开后重现和较长视频. 报告也指出, 视频 grounding 的计数和指点指标没有任何受测模型超过 40%, 而图像 PointBench 常见 70% 到 90%. 视频任务还要求跨帧重识别, 长视频又使用较低有效帧率和空间分辨率, 这几项困难会叠加.

## 5. 失效模式与使用边界

长视频中最常见的错误来自时间采样和身份保持失效, 而非完全看不见目标. 超过三分钟的视频若仍限制在 384 帧, 有效采样率会低于 2 fps; 训练标注固定在 2 fps, 均匀抽帧后标注时间可能不再落到选中帧上. 跟踪输出也会在目标内部漂移, 因为训练轨迹由框或掩码转点时没有始终保证点落在对象的同一相对位置. 对需要像素级稳定性的应用, 应保留原视频时间轴并在模型输出后做专门跟踪或分割, 不应把离散点直接当作完整轨迹.

长描述使用 greedy decoding 时可能在生成数千 token 后重复. 这既与语言模型的长生成退化有关, 也与长描述训练量有限有关. 论文只评测了给定解码设置下的结果; 限制输出长度或采用非贪心解码可以缓解重复, 同时也会改变评测口径. 定性失败样例还包含误报目标、回答与问题对象错配以及漏掉多个实例. 坐标格式通过检查以后, 目标位置仍可能出错.

开放性方面, Molmo2-O-7B 的视觉编码器、OLMo 3 语言模型、训练数据和代码都可获得; 使用 Qwen3 的 4B 与 8B 版本则依赖开放权重语言模型. 报告强调九个新数据集没有用闭源 VLM 蒸馏, 其中部分流程仍使用开放模型生成或整理候选内容, 再由人工标注和验证. 准确说法应是训练链路不依赖闭源模型输出, 而不是所有标签都只由人从空白开始书写.

Molmo2 把帧、时间戳、多图编号和点轨迹统一成语言模型能生成的一条序列, 再用数据配比、token 权重、message tree 和长上下文适配维持联合训练. 这个统一接口便于复用同一套模型和代码, 同时把采样遗漏、序列长度、任务干扰与坐标漂移集中到了一个系统中. 部署评估需要按任务分别核对帧率、最大帧数、`max_crops`、坐标解析和后处理流程；聚合平均分无法暴露某个时间点被跳帧或某条轨迹发生身份切换的问题. 跟踪任务还应逐帧保存原始点、SAM 2 掩码与对象编号, 才能区分采样缺帧、点位漂移和分割后处理三类误差.

## 6. 机制推导、边界与复现

### 6.1. 视频采样先是一个可辨识性问题

把视频记作连续信号 $I(t)$，问题要求恢复事件变量 $Y=g(I_{[0,T]})$。Molmo2 实际观察到的是采样集合

$$
O=\{I(t_1),I(t_2),\ldots,I(t_F)\}.
$$

模型再强，也只能学习 $p(Y\mid O,Q)$。若两个视频在所有采样时刻画面相同，却在相邻采样点之间发生了不同的短事件，那么最们对应同一个 $O$，答案却不同。此时错误来自观测不可辨识，增加语言模型参数无法恢复已经丢掉的帧。2 fps 意味着规则采样间隔为 0.5 秒；挥手、灯光闪烁、物体瞬间落地之类事件只要完整落在两个采样点之间，就可能没有任何直接视觉证据。

均匀抽帧还会产生时间混叠。设某个周期动作的频率为 $f_e$，采样率为 $f_s$。当动作变化快于 $f_s/2$ 时，不同真实频率可能形成相同离散序列。视频模型面对的并非经典的一维正弦波，但「轮子似乎倒转」「重复动作次数算错」仍是同一类现象：离散帧无法唯一决定连续运动。时间戳告诉模型每帧来自何时，可以帮助最解释不等间隔采样，却不会补回缺失的中间状态。

因此，帧数增加的收益应拆成三层。第一层是覆盖率：关键事件至少被一帧击中。第二层是时间分辨率：连续两帧足以判断动作方向和先后。第三层是语义利用率：模型能在更长序列中找到那几帧。前两层由采样决定，第三层才主要由模型与训练决定。论文中 128 帧模型在测试时扩到 224 帧先升后降，恰好说明覆盖率提高与分布外长序列损失在竞争。

### 6.2. 保留末尾一帧改变了采样分布

对长度 $T$ 超过预算的视频，若先均匀取 $F$ 个位置再强制包含末帧，末端状态拥有确定观测，其他局部事件只有按间隔命中的机会。这样做对「末尾发生了什么」「任务最终是否完成」很有利，也使训练分布对结尾形成轻微偏置。若问题关注开头后立即消失的对象，保留末帧没有帮助；若视频末尾包含剪辑片尾，最还可能浪费一个位置。

可把事件持续时间记作 $d$，均匀采样间隔近似为 $\Delta=T/(F-1)$。忽略边界且假设事件起点相对采样网格均匀，当 $d<\Delta$ 时，至少击中一帧的概率约为 $d/\Delta$；当 $d\ge\Delta$ 时接近 1。这个粗算揭示了长视频的代价：固定 $F$ 下，$T$ 加倍会让短事件命中率近似减半。报告长视频平均分时若不按事件持续时间分桶，模型的时间推理错误和采样漏检会混在一起。

更有信息量的评测应同时提供 oracle-frame 结果。先用标注时间段确保关键帧进入输入，再与均匀采样比较：两者差距衡量采样损失；oracle 条件下仍然答错的部分才更接近视觉识别、跨帧关联或语言推理问题。对轨迹任务还可以分别测「目标出现帧命中率」「命中帧上的点精度」和「跨命中帧 ID 一致率」，避免一个 J&F 数字遮住错误来源。

**SlowFast 是时间覆盖与空间精度的预算交换。**

设高分辨率慢帧成本为 $c_s=83$ token，低分辨率快帧成本为 $c_f=11$ token，总预算为 $B$。选择 $n_s$ 个慢帧和 $n_f$ 个快帧时满足

$$
c_s n_s+c_f n_f\le B.
$$

慢帧提供定位和小物体信息，快帧提高短事件命中率。若任务价值可粗略写成 $U(n_s,n_f)$，合理分配要求两类帧的边际收益除以 token 成本相近：

$$
\frac{\partial U/\partial n_s}{c_s}
\approx
\frac{\partial U/\partial n_f}{c_f}.
$$

固定每隔 $p$ 帧取一个慢帧，相当于用规则先验代替学习到的预算分配。最适合事件密度较均匀的视频；对长时间静止、突然发生一次关键动作的样本，规则分配会把大量快帧花在静止区间。内容自适应采样可以把 token 移到场景变化处，但采样器本身可能漏掉语义重要而像素变化很小的事件，例如屏幕上一位数字改变。于是「先用便宜模型挑帧」并没有消除信息瓶颈，只是把瓶颈前移到挑帧器。

### 6.2. 坐标字符串如何对应空间概率

Molmo2 把点写成普通 token 序列。设真实归一化坐标为 $(x,y)\in[0,1000]^2$，输出字符串再经 tokenizer 分成若干 token。训练损失仍是逐 token 交叉熵：

$$
\mathcal L_{point}=-\sum_{j=1}^{m}\log p_\theta(u_j\mid u_{<j},O,Q).
$$

这个目标没有显式使用欧氏距离。把 $x=500$ 预测成 501 与预测成 900，只要对应 token 都错，交叉熵层面未必呈现符合几何距离的差别。模型能够学到数值邻近性，依赖语言模型已有的数字表示、训练数据覆盖以及坐标格式的规律。将坐标量化到 1001 个整数减少了输出空间，却带来最大约半个量化单位的轴向误差；相对于视频中定位与分割误差，这个量化项通常很小。

真正棘手的是序列中的集合对称性。同一帧有多个同类物体时，集合本来没有顺序；自回归损失却要求唯一的下一个 token。按 $x$、再按 $y$ 排序把集合变成确定序列，消除了排列造成的多峰监督。代价出现在两物体横坐标接近并交叉时：细小定位扰动可能交换排序，后续整段编号都变化。视频跟踪又要求 ID 跨帧保持，空间排序与身份连续性可能冲突。训练格式必须明确「首帧按空间排序创建 ID，后续沿用 ID」，否则模型会在每帧重新编号，看起来点都正确，轨迹身份却不断切换。

**先点后数为何能改善计数。**

直接计数学习的是 $p(n\mid O,Q)$，监督只有最终整数。先点后数把任务分解为检测集合 $S=\{(x_i,y_i)\}$ 与确定函数 $n=|S|$。每个实例都贡献坐标 token，监督密度随物体数量增长；漏掉哪个对象也能从输出中定位。其优势类似在最终答案之外增加可验证中间变量。

这项分解并不保证正确。模型可能重复指出同一对象，以连续编号制造过计数；也可能点落在背景上但数字恰好正确。设真实集合为 $G$，预测集合为 $P$，在匹配阈值下可分别计算 precision、recall 与计数误差 $||P|-|G||$。只有三者一起报告，才能区分「对象都找对但汇总错」「数量碰巧对但对象错」以及「重复点导致过计数」。论文表中的计数准确率验证了最终数值，指点评测则补上空间证据，两项不能互相替代。

点经 SAM 2 转掩码时又引入条件概率链：

$$
p(M\mid O,Q)=\sum_P p_{SAM2}(M\mid P,I)\,p_{Molmo2}(P\mid O,Q).
$$

最终掩码错误可能来自点分布，也可能来自给定正确点时的分割器。一个公平的分解实验应加入 ground-truth point 输入 SAM 2 的上界，以及预测点直接用距离阈值评分的结果。前者衡量后处理器在该视频域的损失，后者绕过掩码转换观察 Molmo2 自身。若只给最终 J&F，无法知道改进应落在 VLM 还是分割器。

**联合训练中的梯度竞争。**

多任务混合并非把九个数据集装进同一个 dataloader 就结束。设任务 $k$ 的采样概率为 $q_k$，单样本答案有 $n_k$ 个受监督 token，每 token 权重为 $w_k(n_k)$。忽略梯度相关性后，最对总目标的期望标量贡献近似为

$$
C_k\propto q_k\,\mathbb E[n_k w_k(n_k)].
$$

普通 token 平均令 $w=1$，长描述贡献与长度线性增长。Molmo2 对部分任务使用 $4/\sqrt n$，使总权重变成 $4\sqrt n$：长度从 100 增到 10,000，贡献只增 10 倍，不再增 100 倍。最仍保留长回答更多监督的事实，没有把每条样本硬压成同权。

标量权重只能调节梯度范数，无法控制梯度方向。令任务梯度为 $g_i$ 与 $g_j$，若 $g_i^\top g_j>0$，一次更新可能同时改善两项；若内积为负，两项发生局部冲突。视频描述要求保留细节并持续生成，短问答要求尽快收敛到一个答案；指点要求数字与标点格式极稳，开放描述允许多种措辞。最们共享 LLM 后，出现负内积并不奇怪。消融中取消 token weighting 后描述 F1 上升而 QA 下降，就是容量分配变化的直接信号。

进一步诊断可以在同一 checkpoint 上按任务抽取小批量，测归一化梯度余弦

$$
\rho_{ij}=\frac{g_i^\top g_j}{\|g_i\|\,\|g_j\|}.
$$

还应分别在视觉编码器、连接器和 LLM 层测量。两项任务可能在视觉层共享目标检测特征，在语言出口却因格式不同而冲突。只看全参数拼接后的一个余弦，会让大参数模块支配统计。若冲突集中在输出层，任务前缀或轻量出口即可缓解；若冲突贯穿视觉层，采样率和训练阶段需要重新安排。

**纯文本数据承担的是参数锚定。**

全参数多模态训练会让 LLM 持续接收视觉任务梯度。加入 Tulu 文本数据，相当于周期性要求模型在原语言分布上仍给出合理输出。可把目标写成

$$
L=(1-\alpha)L_{mm}+\alpha L_{text}.
$$

$\alpha$ 太小，语言能力可能漂移；太大，多模态梯度被稀释。文本数据与初始模型原预训练分布也不完全相同，所以最只能锚定一部分能力，不能证明所有 NLP 能力保持。附录的 NLP 基准提供结果层检查，而参数距离或固定提示 KL 可以补充过程层检查。

训练三阶段使用不同长度和混合，意味着最终模型不是在一个静态目标上收敛。长上下文阶段只有 2,000 步，却使用更长视频，单步包含的视觉 token 和时间跨度都发生变化。若这一阶段描述指标下降，可以来自灾难性干扰、长样本比例变化，也可能只是短训练导致尚未重新平衡。要分辨三者，需要保留进入第三阶段前的 checkpoint，并在固定短、长验证集上画随步数变化的曲线。

### Message tree 的掩码语义。

同一视频对应多个问题时，最浪费的做法是复制视觉 token $r$ 次。Message tree 让根部视觉前缀只计算一次，随后分出 $r$ 条问答支路。对支路 $b$ 中的答案位置 $i$，允许读取根节点、该支路的问题与先前答案，禁止读取其他支路。若以节点祖先关系 $\preceq$ 表示可见性，掩码可写成

$$
M_{ij}=\begin{cases}
0,&j\preceq i,\\
-\infty,&\text{其他情况}.
\end{cases}
$$

这与普通因果三角掩码不同：两个在物理序列中前后排列的答案，只要属于兄弟支路，后者也不能读取前者。实现若仅使用 position id 重置而没有真正阻断注意力，便会发生标签泄漏。模型可能从前一个问答直接得知视频内容，离线 loss 很低，独立推理时却失效。

Message tree 的收益还取决于视觉计算占比。若 ViT 与长视觉前缀占主要成本，共享根节点价值很高；若回答极长，LLM 分支计算仍随问题数增长。「约 15 倍」应结合平均 4 条标注、packing 后样本数与被省掉的 padding 理解，无法外推到每个 batch。更稳妥的复现报告会给出有效视觉帧每秒、有效监督 token 每秒、峰值显存和端到端吞吐，而不只给一个合并倍数。

**统一接口的真正边界。**

视频、多图、点与轨迹都能写成 token 序列，说明语言模型可以充当统一的条件计算器和输出协议。最没有消除各任务的统计结构。视频需要对时间采样负责，多图需要对离散索引负责，跟踪需要维护跨帧身份，描述需要处理开放答案。共享格式减少专用头，也把这些约束交给同一个自回归分布。

判断这种统一是否成功，应问三个具体问题。第一，新增任务是否利用了旧任务已经学到的表示，例如指点是否帮助跟踪与计数。第二，共享是否造成可测的负迁移，例如长描述权重上升是否损害短问答。第三，统一协议之外是否仍依赖任务专用系统，例如 SAM 2、视频解码与字幕时间对齐。Molmo2 对第一项给出多组消融，对第二项展示了若干权衡，对第三项则需要读清评测管线才不会把系统分数全部归给主模型。

它的主要价值是给出一套可公开检查的实验对象，并不宣称「一条序列可以替代所有视觉模块」：数据怎样采、坐标怎样编码、不同任务怎样混合、长视频怎样装进上下文、输出又怎样被评分。沿着这条链逐段拆开，读者能把模型能力与观测上限、监督格式、训练权重和后处理误差分别归因。对于开放研究，这种可拆解性本身就是结果的一部分。

**视觉 token 池化损失了什么。**

SigLIP 2 为每张 $378\times378$ 图像产生 $27\times27$ 个 patch 特征。图像路径用 $2\times2$ 窗口池化到约 $14\times14$，视频路径用 $3\times3$ 窗口池化到 $9\times9$。若先忽略边缘，池化相当于把局部特征集合 $X_W=\{x_1,\ldots,x_m\}$ 映射为一个向量：

$$
h_W=\sum_{j=1}^{m}\alpha_j(X_W)x_j,
\qquad
\sum_j\alpha_j=1.
$$

注意力池化比简单平均更有选择性，仍是一种多对一映射。只要两个局部 patch 集合得到同一个 $h_W$，后续 LLM 就无法区分最们。视频采用更大的窗口，把每帧 token 从 196 降至 81，换来更多时间点；细字、小物体边界和窗口内多个实例更容易被合并。这个选择与 SlowFast 的交换方向一致：视频优先时间覆盖，单图优先空间细节。

把 ViT 倒数第 3 层与第 9 层特征拼接，是在语义抽象与局部信息之间取一条折中。较后层通常更受全局语义和预训练目标塑形，较早层保留更多位置与纹理；连接器同时读取两层，使输出 token 不必只依赖最终视觉表征。这个经验解释不能替代消融，严格结论仍应来自替换层位后的结果。若不同层的尺度与统计量差异很大，连接器还要在训练中学会校准最们，拼接本身不保证互补。

池化窗口在网格边缘需要处理 $27$ 不能被 2 整除的问题。向上取整得到 14 个位置，意味着末行或列包含的原始 patch 数较少。若查询由窗口均值构造，边缘窗口的统计量与内部窗口不同；模型可从位置编码和特征分布适应，但边缘对象与内部对象并不完全同分布。图像裁剪之间又存在重叠，同一物体可能在全局图和局部裁剪中出现多次。模型需要学会这是同一场景的多尺度观察，避免在计数时重复。

**多裁剪并不等于更高的原图分辨率。**

全局图让模型知道各裁剪之间的整体布局，局部裁剪提高有效像素密度。设原图宽高为 $(W,H)$，每个裁剪都缩放到 378；局部区域的细节被放大，但裁剪边界外的关系只能通过其他 token 恢复。对于横跨多个裁剪的大物体，局部视图可能各自只显示一部分；对于密集计数，重叠区域又会制造重复证据。

推理从 8 个裁剪提高到 24 个时，输入分布发生两种变化：视觉 token 数增加，裁剪尺度和覆盖密度也改变。若训练只见 8 个裁剪，位置数量与重复模式都分布外。Molmo2 对一部分 pointing 样本在 SFT 中使用 24 个裁剪，正是在目标任务上补这段差距。最没有证明所有图像任务都从 24 裁剪受益；普通问答可能因序列更长而分散注意力，低分辨率图片也没有额外细节可恢复。

可用一个简单的信息预算理解裁剪选择。设第 $k$ 个裁剪带来的条件互信息增量为

$$
\Delta_k=I(Y;C_k\mid C_{1:k-1},G,Q),
$$

其中 $G$ 是全局图。重叠越大，后续裁剪与已有裁剪越冗余，$\Delta_k$ 越小；小目标恰好只在某个裁剪中清晰出现时，增量会很大。固定取前 24 个裁剪没有按问题调整这项价值。问题条件挑裁剪理论上更省 token，但挑选器必须在低分辨率预览上判断什么与问题有关，又会产生新的漏检风险。

### 时间戳为何能由普通文本承担。

每帧前写入「0.0」「0.5」一类时间文本，LLM 通过 tokenizer 把最们变成离散 token。这样做省去了独立时间编码器，也复用了语言模型的数值表示。其能力来自三部分：帧在序列中的位置给出相对顺序，时间字符串给出绝对或近似间隔，训练问答把时间与事件绑定。若采样严格等间隔，顺序已经能表达大部分先后；时间戳对长视频均匀抽帧、不规则采样和要求秒数的 grounding 更重要。

普通文本时间有量化和分词边界。保留一位小数意味着两个相差不足 0.05 秒的时刻会映射到同一字符串；不同数值还可能被 tokenizer 切成不同数量的 token。语言模型对「9.9」到「10.0」的数值邻近性，并不天然像连续位置编码那样平滑。训练覆盖足够时，最可以从共现学到比较和排序；超出训练时长、改变小数位数或改用毫秒格式，都可能破坏这种规律。

时间戳消融对描述 F1 的影响大于 QA，可以从目标结构解释。短问答常只需确认某事件是否出现，帧顺序和画面本身已提供不少信息；长描述需要把多个事件放进正确的时间位置，绝对间隔与段落边界更有价值。若问题直接问「第几秒」，时间戳则从辅助条件变成答案所需的坐标系。

**时间定位误差要先区分三个坐标系。**

原视频有连续时间 $t$，解码器给出帧索引 $i$ 与 presentation timestamp，采样器再选出子序列索引 $j$。模型看到的文本时间应对应原视频时间，而非采样后序号。视频存在可变帧率、剪辑偏移或损坏时间戳时，三者可能不一致。若训练标注按播放器秒数制作，而预处理按假定固定 fps 换算，坐标误差会直接进入监督。

设标注事件区间为 $[a,b]$，采样时间集合为 $S$。最近帧误差为

$$
e=\min_{t_i\in S}\operatorname{dist}(t_i,[a,b]).
$$

当 $S$ 中存在区间内帧时 $e=0$；否则模型只能根据事件前后状态推测。评测若允许一定时间容差，应将容差与采样间隔共同报告。容差大于半个采样间隔时，随机落在最近帧也可能算对；容差很小时，预处理时间戳误差会支配模型差异。

**跨帧身份是一个数据关联问题。**

对第 $t$ 帧的检测集合 $D_t=\{d_{t,1},\ldots\}$，跟踪要求建立从当前检测到历史轨迹的匹配。传统方法会依据位置、外观与运动模型求解关联；Molmo2 把同一问题交给自回归序列，通过历史视觉 token、先前输出与对象编号预测当前 ID。编号本身没有语义，真正需要保持的是一个隐含的对象状态。

若两个相似目标交叉，当前位置接近，单帧外观也近似，关联分布可能多峰。训练标签选择其中一种身份延续，token 交叉熵迫使模型在编号处作决定。一次 ID 交换会传到后续所有帧，即使位置重新准确，轨迹指标仍受影响。这个误差与单帧 pointing 不同：后者每帧可以独立恢复，身份错误具有时间记忆。

可以把一条轨迹的成功概率粗略分解为

$$
P(\text{全程正确})
=P(\text{首帧发现})
\prod_{t=2}^{T}P(\text{正确关联}_t\mid\text{此前正确}).
$$

即使每一步关联准确率为 0.99，跨 100 次关联保持全对的概率也只有约 $0.99^{100}\approx0.366$。真实错误并不独立，这个算式仍说明长轨迹为何显著更难。平均逐帧点精度看起来很高，也可能伴随多次 ID switch。

目标离开画面再回来时，运动连续性中断，只能依赖外观、语义与上下文重识别。若压缩后的视觉 token 丢掉衣服纹理或细小标记，两个同类目标变得不可分。增加帧数解决不了空间特征丢失；增加空间分辨率又会挤压时间预算。这正是视频 grounding 中最核心的二维预算矛盾。

**首末位置辅助任务提供了什么。**

预测目标首次和末次出现的时间与位置，相当于为整条轨迹增加两个全局锚点。逐帧轨迹损失关注局部连续，端点任务要求模型理解对象生命周期。若中间某几帧遮挡，端点仍能约束模型不要过早结束轨迹，也不要在目标已经离开后继续幻觉位置。

端点监督本身可能含糊。对象被完全遮挡但仍在场景中，究竟算「未出现」还是「存在但不可见」；视频剪辑切换后出现相似对象，是否延续原 ID，都需要标注协议决定。模型学到的是协议下的可见轨迹，不是哲学意义上的对象持续存在。复现时若只拿公开框或掩码自动转端点，原数据集对 occlusion 的处理差异会被继承。

单点初始化辅助任务看似与交互式跟踪完全一致，消融却可能负迁移。原因之一是条件分布不同：给定一个准确点时，模型可以把注意力集中到该对象；自然语言问题往往描述一类对象，需要先检测再关联。大量单点任务会鼓励模型依赖显式位置提示，削弱从文本完成目标选择。任务形式接近不代表条件变量相同，辅助目标是否有益要看最与主任务共享哪一步推断。

**描述任务中的覆盖与幻觉。**

长视频描述没有唯一参考答案。一个描述可以事实正确但略去细节，也可以覆盖很广却混入一处幻觉。设视频事实集合为 $F$，生成陈述集合为 $S$，理想评价至少包含事实 precision $|S\cap F|/|S|$ 与 recall $|S\cap F|/|F|$。现实中 $F$ 无法穷举，参考描述只记录一部分事实；自动 F1 往往比较语言匹配或抽取后的内容，人工 Elo 则把覆盖、流畅与错误混成总体偏好。

训练用逐片段口述补 recall，用整段描述学习组织结构。两者合并时存在重复与冲突：同一动作可能在相邻片段被说两次，口述者也可能先猜测后修正。整理过程若简单拼接，模型会学到冗余；若用另一个模型压缩，又可能删除细节或引入改写错误。开放数据的价值正在于研究者能够检查这条处理链，并按自己的评价目标重新整理，而非只拿最终权重猜测数据来源。

Greedy decoding 的长程重复可以从局部条件分布理解。生成到某个状态后，先前句式在上下文中高频出现，模型再次选择同一开头；新句子又把状态带回相似区域，形成吸引环。长度越长，进入重复环的机会越多。降低温度不能必然解决，因为 greedy 本身就是最低温极限；重复惩罚会打破表面 token 循环，也可能压制视频中真实重复发生的动作。

更可靠的分析应按时间段对齐陈述。把输出拆成事件 $(\hat t_i,\hat e_i)$，分别检查时间覆盖、实体正确、动作正确和重复次数。若模型反复描述同一真实事件，事实 precision 未必很低，叙事质量却差；若最把事件放错时段，词汇匹配可能仍然很高。长描述的一个总 F1 很难表达这些区别。
