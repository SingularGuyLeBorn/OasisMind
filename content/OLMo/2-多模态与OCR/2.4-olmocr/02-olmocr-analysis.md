# olmOCR: 用文档锚点把 PDF 页面线性化为训练文本

来源: Luca Soldaini 等, *olmOCR: Unlocking Trillions of Tokens in PDFs with Vision Language Models*, 2025. 对照译稿见同目录 `01-olmocr-bi.md`, 项目代码与模型见 [allenai/olmocr](https://github.com/allenai/olmocr). 文中的数据统计, 评测与成本均对应论文发布时的 olmOCR-7B-0225-preview 与 v0.1.75 管线.

## 1. 从 PDF 页面到线性文本

**1.1. 从页面绘制指令恢复逻辑序列.** PDF 先是一种固定页面的呈现格式. 它可以保存字形, 坐标, 字体与绘制顺序, 却不必保存「这是标题」「这两行属于同一段」「右栏应在左栏之后」之类的逻辑结构. 对原生数字 PDF, 直接抽内部字符常能得到大部分字面内容, 但字符流未必等于阅读顺序; 对扫描 PDF, 页面内部甚至没有可用文本层. 因此面向语言模型的数据处理需要同时完成三个任务: 识别页面上有什么, 恢复各元素的关系, 再把二维布局变成一维序列.

这一步通常称为线性化. 若页面是双栏论文, 一个逐坐标排序的解析器可能把左右两栏同行交错; 若页面含跨栏标题, 脚注和浮动表格, 仅按横纵坐标排序也无法恢复作者预期的阅读路径. 公式与表格还有额外困难: $x^i$ 与 $x_i$ 的字符集合几乎一样, 语义却不同; 表格里单元格值读对了, 行列关系错了, 下游问题仍无法回答. 所以输出质量不能只用字符召回率表示.

olmOCR 把目标定义为适合语言模型使用的干净纯文本: 正文按自然阅读顺序排列, 小节, 列表, 表格和公式尽量保留, 页眉页脚等重复模板则排除. 这不是页面的像素级复刻. 图片没有文字时, 系统不应自行添加图片说明; 版式本身若不承载语义, 也不要求在文本中复现. 这个目标决定了后续的数据生成提示, 训练输出格式和基准测试设计. **1.2. 流水线与端到端模型的取舍.**

传统文档流水线会分别做版面检测, 文本识别, 表格解析, 公式识别和阅读顺序恢复. 好处是每个模块可以单独替换, 错误也容易定位; 代价是接口多, 上游框错一个区域后, 下游模块看不到被裁掉的内容. 端到端 VLM 直接从页面图像生成文本, 可以用同一套参数联合判断字符与布局, 但也可能漏写高密度内容, 改写原句, 或依据常识补出页面不存在的文字.

olmOCR 没有在这两端中二选一. 它保留 VLM 作为最终生成器, 同时把 PDF 内部解析得到的文本块和位置送进提示. 页面图像提供布局与扫描内容, PDF 文本层提供精确字符线索, 生成模型负责决定阅读顺序和输出结构. 这是一种弱耦合组合: 内部文本层有噪声也可以当提示, 不必先变成完全正确的中间文档树. **1.3. Document anchoring 怎样工作.** **1.4. 图像负责布局, 锚点负责字面内容.**

document anchoring 可以译作「文档锚点」. 系统先把 PDF 页渲染为图像, 再用 pypdf 从页面内部抽取文本块与位置. 这份抽取不保证阅读顺序, 还可能混有页眉, 页脚和渲染杂项, 因而不能直接当金标. 它的作用是给 VLM 一组可回到页面位置的字面线索. 当小字在 1024 像素图像上已经模糊时, 锚点仍可能保存正确字符; 当内部文本流顺序混乱时, 页面图像仍能帮助模型判断栏位和邻接关系.

提示长度有限, 系统不会无条件塞入全部内部文本. 论文的数据生成流程从长抽取中采样文本块, 直到达到输入上限, 并优先保留文档开头和结尾附近的文本块与图片. 这项策略照顾了标题, 页首开篇和页尾收束, 但中部高密度页面仍可能被截去部分锚点. 因而文档锚点不是完整转录, 更像给视觉识别加一条带坐标的候选字符通道. Table 4 给出了它对不同模型的影响. GPT-4o 从无锚点的 68.9 升到 69.9, Gemini Flash 2 从 57.8 升到 63.8, olmOCR v0.1.75 从 74.7 升到 75.5. 提升并不恒定: GPT-4o 的老扫描数学分项从 75.5 变为 74.5, olmOCR 的表格分项从 71.4 变为 71.0. 因此锚点总体有益, 但不是每页必然改善. 若 PDF 文本层损坏或坐标错误, 模型还要在图像与锚点冲突时作判断. **1.5. 结构化输出约束生成行为.**

数据生成时, GPT-4o 按 JSON schema 返回结果. 模型先判断语言, 页面方向, 是否有表格等元数据, 再生成自然阅读顺序下的页面文本. 结构化输出有两项直接作用. 第一, 后处理不必从自由文本里猜正文边界; 第二, 明确字段能抑制模型在无文字图片上自行撰写说明. 后者很重要, 因为通用 VLM 往往把「描述图片」视为默认任务, 而 OCR 数据要求没有来源的文字保持缺失. 最终训练样本继续使用同一 JSON 输出, 让学生模型学习的不只是 Markdown 内容, 还包括页面级状态. 损失只计算回答 token, 图像 token 与锚点提示不作为预测目标. 设输入为页面图像 $I$ 与锚点 $A$, 输出为结构化文本 $Y$, 训练目标就是常规自回归条件似然:

$$
\mathcal L=-\sum_{t=1}^{|Y|}\log p_\theta(Y_t\mid I,A,Y_{<t}).
$$

这里的掩码使模型不会因复述提示而得分. 但它也意味着训练只惩罚最终序列与教师输出的差异, 教师漏掉或改写的内容会成为学生监督的一部分. 后续基准超过教师并不矛盾: 学生在 25.9 万页上蒸馏了教师的共同模式, 专用提示缩小了任务范围, 基准分布又与单个训练页面不同. **1.6. 阅读顺序可以写成偏序图.**

页面线性化最容易被误解成给所有文本框按坐标排序。更合适的表示是有向图 $G=(V,E)$: 每个节点 $v_i$ 是标题、段落、表格、脚注或栏内文本块; 边 $(v_i,v_j)$ 表示 $v_i$ 必须先于 $v_j$ 输出。单栏正文会形成近似链式结构, 双栏页面则先在各栏内部形成两条链, 再由跨栏标题、续接段落和脚注引用补充约束。

只要图无环, 任意拓扑排序都满足已知顺序。多个彼此独立的新闻短篇可以交换整体位置, 因而同一页面可能存在多条合法序列。olmOCR-Bench 的 Natural Reading Order 用例正是检查局部边: 某个标题应先于所属正文, 一段中的前句应先于后句; 它刻意不要求两个互不相干的文章块具有唯一先后。这样的判定比整页字符串相等更符合偏序目标。 假设页面有四个块: 跨栏标题 $h$、左栏正文 $a$、右栏正文 $b$、页脚 $f$。有效约束可能只有 $h\prec a$、$h\prec b$, 且 $f$ 应删除。序列 $(h,a,b)$ 与 $(h,b,a)$ 都满足图; 用坐标先按 $y$ 再按 $x$ 排序, 可能得到 $(h,a_1,b_1,a_2,b_2)$, 把两个段落交错。字符全部识别正确也无法弥补这种顺序错误, 因为语言模型接收的是交错后的条件序列。

图中还会出现冲突边。PDF 绘制顺序可能给出 $a\prec b$, 页面布局与人类转写却支持 $b\prec a$; 锚点坐标错误还可能形成 $a\prec b\prec c\prec a$ 的环。生成式模型没有显式求解拓扑排序, 它在隐藏状态中综合图像与锚点后自回归产生一条路径。冲突时必须牺牲部分证据, 所以同一页面在后端、精度或 prompt 改变后可能得到另一条仍局部合理的顺序。

阅读顺序的误差可分成三层。节点错误指内容块被漏掉、合并或虚构; 边错误指两个真实块的先后关系颠倒; 线性扩展差异指两条输出满足相同必要边, 只是对无约束块采用不同次序。全文编辑距离会把三者都算作大量字符移动, 局部顺序测试只直接覆盖第二层。文档级验收需要另报块召回、违反必要边的比例和无约束块的合法变体, 才能区分内容缺失与可接受的线性化差异。

## 2. 监督数据、训练与噪声传播

**2.1. olmOCR-mix-0225 的组成.** 论文 Table 1 的训练集包含 102,825 份文档, 258,641 页. 其中网页爬取 PDF 为 96,929 份, 240,940 页; Internet Archive 公有领域图书为 5,896 份, 17,701 页. 网页样本来自 2.4 亿份公开 PDF 的内部集合, 多为原生数字文档; Internet Archive 部分偏向图像扫描. 每份文档随机取最多三页, 目的是扩大文档多样性, 而不是从少量长文档重复抽页. 数据先用 Lingua 筛除非英文文档, 再去掉 pypdf 无法解析, 含垃圾关键词, 属于可填写表单或文本过短的文档. 按 707 页样本由 GPT-4o 分类得到的估计, 学术文档占 55.9%, 宣传册 11.2%, 法律文档 10.2%, 图书 6.8%, 表格页 5.6%, 图示页 4.7%, 幻灯片 1.9%, 其他 3.7%. 这是一份多类型数据, 但学术内容占比过半, 不能把它当作所有企业表单或多语言票据的均匀样本.

Table 1 还有一个统计矛盾. 若 Internet Archive 的 5,896 份文档每份最多取三页, 上限应是 17,688 页, 表中却是 17,701 页, 多 13 页. HF 数据卡给出过另一组数字: 5,601 份, 16,803 页, 恰好每份三页; LaTeX 源码注释中的旧表也是这组数. 论文没有解释更新统计为何超过上限. 复现时应以实际发布数据清单为准, 不应从正文这三个数字反推抽样程序. **2.2. GPT-4o 银标的能力边界.** 人工逐页重建阅读顺序和 LaTeX 成本很高, 项目改用 gpt-4o-2024-08-06 生成银标. 2024 年 10 月的候选比较中, Gemini 1.5 经常触发 `RECITATION` 错误, GPT-4o mini 幻觉较多, Claude Sonnet 3.5 成本过高, 最终选择 GPT-4o batch 模式. 这项选择是当时可用模型, 价格和稳定性的折中, 不是对所有后续模型的永久排序.

教师生成前加锚点, 是因为单独使用 GPT-4o 在密集页和复杂布局上仍会漏内容, 改写或补全文字, 还可能给图片添加未要求的说明. 训练集的质量上限因此由四部分共同决定: PDF 样本覆盖, 页面渲染清晰度, 锚点抽取, 教师生成. 任一部分出错都可能进入监督. 论文用基准和人工并排比较选择提示, 没有声称 258,641 页都是逐页人工验收的真值. **2.3. 7B 模型的训练配置复算.** 学生从 Qwen2-VL-7B-Instruct 开始微调. 图像最长边缩到 1024 像素, 文本提示限制为 6,000 字符. 一条典型样本约用 1,000 token 编码图像, 1,800 token 表示锚点, 总输入约 3,000 token; 整条样本截断到 8,192 token. 训练使用 AdamW, 学习率 $10^{-6}$, 余弦退火, 共 10,000 step, 硬件为单节点 8 张 80GB H100. 一次训练为 16 节点小时, 全部实验累计 365 节点小时.

正文称有效 batch size 为 4, 同时称 10,000 step 约为 1.2 epoch. 若全局 batch 真是 4, 训练只看过 40,000 页, 即 $40{,}000/258{,}641\approx0.15$ epoch, 两者不能同时成立. 官方训练配置是每卡 batch 1, 梯度累积 4, 启动脚本使用 8 卡 FSDP, 所以全局 batch 为 $1\times4\times8=32$. 10,000 step 对应 320,000 个样本, 即约 1.24 epoch, 与论文的 1.2 epoch 一致. 正文的 4 应理解为每卡累积后的 batch, 不是全局有效 batch. 8,192 token 截断还形成明确边界. 典型输入已占约 3,000 token, 留给 JSON 和正文约 5,000 token; 密集词典页, 长表格或大量公式页可能在输出末端被截断. Long Tiny Text 分项能测部分密集页能力, 却不能保证任意页面完整. 大规模处理时需要把截断, 重复生成和空输出作为可观测失败, 而不是只检查请求是否成功返回. **2.4. OCR 噪声怎样经过 tokenizer 进入预训练.**

OCR 错误进入语言模型前还会经过 tokenizer。正确词片段 $x$ 被识别成 $\tilde x$ 后, token 数可能保持不变, 也可能显著膨胀。常见英文单词通常对应一个或少量高频 token; 插入乱码、断字或错误 Unicode 后, tokenizer 往往退回更细的子词甚至字节。设原文每字符平均产生 $r$ 个 token, OCR 后变为 $\tilde r$, 在固定 50B token 预算下实际覆盖的原始字符比例约缩放为 $r/\tilde r$。噪声既改变监督内容, 也会减少同一 token 预算能看到的文档范围。

例如一个跨行词被错误拆成两个罕见片段, 语言模型需要先预测异常连字符和换行, 再恢复后半词。交叉熵对每个 token 求和时, 被拆成更多 token 的坏片段会获得更多损失项。若一页干净文本有 1000 token, OCR 噪声令其扩到 1200 token, 该页在 token 加权训练中的权重提高 20%, 即便额外 200 个 token 主要是提取错误。固定文档采样和固定 token 采样由此产生不同的噪声暴露。

阅读顺序错误传播得更远。把段落 $A$ 与 $B$ 交错后, $B$ 开头 token 的条件上下文从 $B$ 的标题与前句变成 $A$ 的半句; 随后的所有预测都会在错误历史上计算。一个字符替换通常污染局部目标, 一次块级置换会改变整个区段的条件分布。表格列错位同样会生成稳定却错误的局部共现, 例如数值长期与相邻列标题配对, 模型可能学到错误的字段关系。 可以把 OCR 通道写成 $\tilde X\sim q(\tilde X\mid X)$, 语言模型实际优化

$$
E_{X\sim p_{\mathrm{doc}}}
E_{\tilde X\sim q(\cdot\mid X)}
[-\log p_\theta(\tilde X)].
$$

当错误近似随机且概率很低时, 它更像增加梯度方差; 当页眉、连字、栏序或公式结构以固定规则出错时, $q$ 带有系统偏差, 模型会稳定拟合错误分布。增加训练量可以平均随机错误, 无法自动消除系统错误。论文开头把低保真提取与训练不稳定、下游退化联系起来, 同源 PDF 的 50B token 对照则给出实际效应, 但没有把字符、结构与模板噪声分别消融。

tokenizer 还决定错误严重度。归一化器可能把视觉上等价的 Unicode 合并, 也可能保留数学字母、组合附加符和不可见控制符。两个 OCR 系统字符准确率接近, 产生的 token 长度、稀有 token 比例与字节回退比例可以完全不同。进入预训练前应同时统计每页字符数、token 数、token/字符比、控制字符、替换字符以及语言条件下的稀有 token 比例。

最直接的可证伪实验是从同一批 PDF 生成两套 OCR, 固定文档抽样与 tokenizer, 分别测 token 膨胀和错误类型, 再构造三组训练数据: 固定原始文档数、固定输出字符数、固定 token 数。若收益只在固定 token 设置出现, 可能来自覆盖范围或长度权重; 三种设置都同向, 才更支持文本忠实度本身改变学习。论文固定同源 PDF 并训练相同 50B token, 已控制了最终 token 预算, 尚未控制 OCR 后实际覆盖的字符与文档数量。

## 3. 评测、下游收益与使用成本

**3.1. 用局部不变量代替唯一参考文本.** 同一页面可以有多种合理线性化. Markdown 表和 HTML 表可能表达同一关系, 标题空行与列表符号也有不同合法写法. 若拿整页参考文本做精确匹配, 格式差异会被误判为内容错误; 用编辑距离或 ROUGE 又可能忽略公式上下标, 表格邻接和阅读顺序等小而关键的差异. olmOCR-Bench 改用通过或不通过的局部测试: 输出是否包含某段文字, 是否排除某个页眉, 两段文字次序是否正确, 指定表格单元格关系是否保留, 公式的符号空间关系是否匹配.

公式测试先用 KaTeX 在无头浏览器中渲染参考 LaTeX, 取得符号及视觉包围框, 再检查 OCR 文档中是否有相同符号和相对方位. 对 $f(x)=\int_{-3}^{3}x^2dx$, 测试会检查积分号, $x$, $dx$ 的左右关系以及上下限位置. 这种方法比字符串匹配更容忍等价排版, 又能区分上下标. 它仍不是数学等价判定: 两个代数等价但排版不同的公式可能无法匹配, 自定义宏也要先转换到 KaTeX 可渲染形式. 基准共有 7,010 个用例. 按能力分为文本存在 721, 文本缺失 823, 阅读顺序 1,061, 表格 1,020, 公式 3,385. 文档来源包括 arXiv 数学, 老扫描数学, 表格, 老扫描, 页眉页脚, 多栏和密集小字. 公式用例接近总数一半, 但最终得分不是对 7,010 条直接微平均, 因而公式数量不会按比例支配总分. **3.2. 宏平均改变了每类错误的权重.**

系统先在每个来源组内计算通过率, 再对七个来源和一个 Base 组取平均:

$$
S=\frac{1}{8}\sum_{g=1}^{8}S_g.
$$

Base 检查页面是否产出含字母数字的文本, 末尾是否出现超过 30 次的重复 N-gram, 以及是否发生异常语言或字符集切换. 它虽然不是一种文档来源, 在实现和 Table 4 中却作为第八组参与平均. 例如 anchored olmOCR 的八项为 74.9, 71.2, 71.0, 42.2, 94.5, 78.3, 73.3, 98.3, 算术平均为 75.46, 报告成 75.5. 宏平均让数量较少的来源与 2,927 条 arXiv 公式测试拥有相同权重, 适合强调能力覆盖, 但不代表真实流量中的平均页面成功率. Base 对多数系统都在 94 到 99 分, 固定占八分之一后会把总体成绩一起抬高并压缩差距. Qwen2-VL 的 Base 只有 55.5, 是明显例外. 使用者若更关心法律表格或历史扫描, 应直接看对应分项, 或按自己的文档比例重新加权. **3.3. 基准降低主观性, 没有消除采样偏差.**

用例由自动方法与人工审核共同构建. arXiv 公式从 TeX 源对回 PDF 页面; 老扫描数学公式由人工标注; 表格关系和密集小字候选由模型生成后人工核验; 历史文档借助美国国会图书馆的人工转写; 页眉页脚先由版面模型定位再读取; 多栏测试从连贯区域选取相邻片段. 训练集与基准做了 URL 级去重, 基准又在模型训练结束后才开发, 降低了直接针对测试集迭代的风险.

不过 URL 去重不能发现不同站点托管的同一文件, 局部测试也只覆盖被选中的性质. 一页通过两个阅读顺序用例, 不表示整页每个块都按正确顺序排列. 多栏用例还刻意避开公式和上下标, 所以它测的是较纯粹的栏内次序. 单元测试的优势是失败可解释, 不是对整页忠实度的完备证明. **3.4. 结果、下游收益与成本.** **3.5. 75.5 分来自互补能力.** Table 4 中 anchored olmOCR 总分 75.5, 无锚点版本 74.7, Mistral OCR API 72.0, Marker 70.1, anchored GPT-4o 69.9, Qwen2.5-VL 65.5. olmOCR 并非每列第一: Mistral 的 arXiv 数学为 77.2, GPT-4o 无锚点的老扫描数学为 75.5, 商用 Mistral 的 Base 为 99.4. olmOCR 的优势来自各项较均衡, 并在多栏分项达到 78.3, 老扫描分项达到 42.2.

论文用 10,000 次 bootstrap 给出 95% 置信区间, olmOCR 为 $75.5\pm1.0$, Mistral 为 $72.0\pm1.1$. 区间反映当前基准文档抽样的不确定性, 不覆盖新领域分布变化. 「超过教师 GPT-4o」应理解为这套提示, 输出约束和八组宏平均下的结果; 它不表示 7B 学生在通用视觉理解上超过 GPT-4o. **3.6. 同源 PDF 的 50B token 对照.** OCR 输出最终要进入语言模型, 因而论文还做了下游对照. 两组都从 OLMo-2-1124-7B 的同一个中间检查点继续训练 50B token, 文档集合相同. 基线使用 peS2o 中由 Grobid 加规则得到的 58B 学术 token; 实验组取回同一批 S2ORC 源 PDF, 改用 olmOCR 处理. 控制源文档后, 差异主要来自线性化方式, 比拿两个不同语料库比较更有解释力.

六项平均从 53.9 升到 55.2, 增加 1.3 个百分点. 分项并非全升: MMLU 都是 61.1, ARCC 从 75.0 到 76.4, DROP 从 42.3 到 43.7, HellaSwag 从 57.4 到 62.6; NaturalQuestions 从 29.4 降到 29.1, WinoGrande 从 58.3 降到 58.0. 最大增量来自 HellaSwag, 所以不能把平均提升解释为每类能力一致改善. 该实验支持「更好的 PDF 线性化能改变预训练效果」, 但只覆盖学术 PDF, 一个 7B 检查点和 50B token 的继续训练. **3.7. 百万页成本怎样复算.**

Table 6 对 olmOCR 给出 L40S 上 906 token/s, 每美元 5,697 页, 每百万页 176 美元; H100 上 3,050 token/s, 每美元 5,632 页, 每百万页 178 美元. 论文在讨论 peS2o 时另用了每页约 1,000 个 token 的假设, L40S 单价为 0.79 美元/小时, H100 为 2.69 美元/小时, 并测得 12% 重试率. 表中页成本内部相符: $1{,}000{,}000/5697\approx175.5$ 美元. 但若把 L40S 的裸吞吐直接按每页 1,000 token 换算, $906\times3600/(0.79\times1000)\approx4{,}128$ 页/美元, 并不等于 5,697; 重试只会使页数更少. 因此 `tokens/sec` 与 `pages/USD` 使用的页面平均 token 量或计时边界并不相同, 不能混成一条算式. 成本排名依赖论文采用的云价和页面长度. 公式密集页可能输出少但视觉推理慢, 密集小字页可能接近上下文上限; GPU 利用率也会随批量, 图像尺寸和失败重试变化. Table 6 的结论是在给定后端与价格假设下, olmOCR 约为 GPT-4o batch 的三十五分之一成本, 不是固定报价.

正文另称按每页 1,000 token, 处理全部 peS2o PDF 的 H100 用量要 1,030 万美元, 这个数字无法由 Table 6 复算. 按 H100 的 3,050 token/s 和 2.69 美元/小时, 每 token 约 $2.45\times10^{-7}$ 美元; 58B token 约为 1.42 万美元, 与 1,030 万美元相差数百倍. 文中没有给出对应页数或额外成本项, 因而容量预算应使用 Table 6 的明确假设或实测吞吐, 不应采用这条孤立估算. **3.8. 使用时的检查项.**

olmOCR 的处理单元是页面, 文档级结果还要处理跨页关系. 页尾断句与下一页开头如何连接, 跨页表格是否合并, 重复页眉是否稳定删除, 都不是单页高分自动保证的. 在进入训练集前, 可以记录每页输出长度, 语言, 表格标志, 重试次数与结束原因, 再在文档层检查页序, 重复片段和异常长度跳变. 对 8,192 token 截断的页面尤其要保存失败状态, 避免把被截去的尾部误当成完整输出.

质量抽检应沿基准的五类不变量展开: 内容存在, 模板缺失, 阅读顺序, 表格邻接, 公式结构. 对自己的领域各建一小组可确定判定的测试, 往往比只抽几页主观阅读更容易发现版本回退. 同时保留页面图像, 锚点文本, 原始 JSON 与后处理文本, 才能区分错误来自渲染, PDF 内部解析, 模型生成还是清洗.

批处理调度还要区分可重试故障与确定性坏页. 网络超时, 推理后端退出和临时显存不足适合有限重试; 同一页连续产生重复 N-gram, 空正文或超长截断, 更可能是页面或模型层面的稳定失败. 若所有错误都无条件重试, 论文测得的 12% 重试率会在异常文档上放大成无界成本. 实际队列应以文档哈希和页码作为幂等键, 保存每次尝试的模型版本, 提示版本与结束原因, 达到次数上限后进入人工抽检或降级路径.

对 born-digital 页面, 还可以把锚点覆盖率作为诊断量: 统计内部抽取字符中有多少出现在最终文本, 并按页面区域观察缺失. 这个量不能直接充当质量分, 因为页眉页脚本来就应删除, 锚点顺序也可能错误; 它适合发现整段正文意外消失. 对纯扫描页, 锚点为空是正常情况, 此时应转而检查图像分辨率, 输出长度和语言识别. 把两类页面分开监控, 比用同一字符召回阈值更符合系统的输入差异.

数据治理也不能由公开可访问推导为可任意训练. 项目过滤了既含 PII 又不适合公开传播的文档, Internet Archive 部分限定为公有领域图书;实际部署仍需按来源保存许可, 获取时间和删除标记. 若文档不能发送到专有 API, 本地运行 7B 模型是 olmOCR 的直接价值之一, 但本地化只改变数据传输边界, 不替代授权与隐私审查.

### olmOCR 的关键组合是: 用页面图像判断二维结构, 用带位置的 PDF 文本作字符锚点, 用专用 7B VLM 生成一维文本, 再用局部可验证规则衡量输出

训练数据, 模型和推理管线的开放使这一组合可以落到百万页规模. 它的边界同样具体: 银标继承教师错误, 长页面受上下文限制, 单页基准不覆盖全部跨页结构, 成本依赖硬件与页面分布. 在这些边界内, 同源 PDF 的 50B token 对照给出了最直接的下游证据: 线性化不是数据预处理中的无关细节, 它会改变语言模型最终学到的内容.

### 页面分数需要校准到文档风险

olmOCR-Bench 的基本观测是局部测试是否通过, 最终按来源组宏平均。生产数据的决策单位往往是整份文档: 一篇论文有 20 页, 只要公式页被截断或参考文献栏序严重错误, 文档就可能不适合进入预训练。若单页严重失败概率为 $p$, 暂时假设页面独立, $L$ 页文档至少一次失败的概率为

$$
P(\text{document fail})=1-(1-p)^L.
$$

当 $p=0.02,L=20$ 时, 文档失败概率已约为 33.2%; 对 200 页图书则约为 98.2%。真实页面错误通常正相关: 同一文档共享字体、扫描质量、栏式与生成软件, 独立公式可能高估或低估尾部, 但它足以说明 98% 页面通过率不等于 98% 文档可用率。 文档级校准可以在一批完整 PDF 上同时记录页面测试向量与人工文档判定。设页面特征包括文本存在失败数、顺序违反数、公式失败数、输出截断、重复 N-gram 和锚点覆盖异常, 再估计条件概率 $P(B=1\mid z)$, 其中 $B=1$ 表示文档达到预先定义的用途门槛。校准曲线把「模型自信」换成「具有这些可观测症状的文档有多大概率不可用」, 能用于隔离、重试与抽检采样。

这项概率必须绑定用途。用于全文检索时, 少量公式格式错误可能仍可接受; 用于数学预训练时, 上下标和积分边界属于关键内容; 用于证据引用时, 页码和坐标映射又很重要。同一输出不存在脱离用途的单一完美阈值。比较版本时应固定判定协议, 分别给出检索、预训练与结构抽取等目标下的风险。 **3.10. 文档聚类改变置信区间.**

论文 Table 4 用 10,000 次 bootstrap 给出总分置信区间, 基准包含 1,402 份单页 PDF。实际评测若从一份长 PDF 抽出多页, 页面不再是独立样本。同一模板的页眉、字体和扫描噪声会让错误聚类; 按页面普通 bootstrap 会把相关页当成许多独立证据, 区间偏窄。重采样单位应是原始文档, 每次抽取整份文档的全部页面和测试。 设文档内页面结果的平均相关为 $\rho$, 每份文档平均有 $m$ 页, 设计效应近似为

$$
D=1+(m-1)\rho.
$$

若共有 1000 页、每份 10 页且 $\rho=0.3$, $D=3.7$, 有效独立页数约为 $1000/3.7\approx270$。增加同一模板文档的相邻页面远不如增加新文档有效。基准构建和内部回归集都应保存文档 ID, 否则无法做 cluster bootstrap。 宏平均还需要两层重采样。外层按文档来源或业务域保留既定权重, 内层在每个来源中按文档抽样; 每次先计算来源通过率, 再求宏平均。直接混合全部测试重采样会向公式数量多的来源偏移, 丢掉论文设定的能力覆盖权重。若要比较两个 OCR 版本, 同一次 bootstrap 必须抽取相同文档并计算分数差, 配对区间能消除页面难度的共同波动。

局部测试数量也不能充当置信度。一页可能有十个公式测试, 另一页只有一个 Base 测试; 十个测试共享同一渲染和同一模型输出, 不构成十个独立页面。报告测试级通过率适合定位错误类型, 推断版本差异时独立单位仍应回到文档。只有同时给出测试级、页面级与文档级结果, 才能判断提升来自大量局部公式修复, 还是更多整份文档达到可用门槛。

校准集的文档比例也会改变阈值。若评测集为了暴露缺陷而大量收录老扫描、密集小字与复杂公式, 直接把其中的失败频率当作线上概率会高估普通 born-digital PDF 的风险; 若线上恰好处理历史档案, 论文基准中的学术页面又可能低估风险。可以先在各文档域内估计 $P(B=1\mid z,g)$, 其中 $g$ 是来源或页面类型, 再按目标流量的域权重求和。

部署后还可检查校准漂移。把模型预测风险分成若干区间, 对每个区间抽样人工验收, 比较预计失败率与实际失败率。若「预计 5%」的一组页面实际有 20% 严重失败, 常见原因包括新语言、新扫描设备、不同 PDF 生成器或后处理版本改变。此时应更新域划分与校准映射, 不宜只调高一个全局阈值。

拒绝策略同样要计入评测。系统把高风险页面送入人工或传统 OCR 后, 自动通过集合的质量会上升, 覆盖率会下降。应画出覆盖率—严重失败率曲线: 阈值逐渐收紧时, 有多少页面仍自动接收, 其中有多少严重错误。单报被接收页面的准确率容易通过大量拒绝得到漂亮数字, 单报覆盖率又看不到残留风险。文档级生产指标需要同时包含两者。

## 4. 页面线性化的统计结构与证据边界

把作者希望表达的逻辑文档记作 $D$，PDF 生成器把它变成页面绘制对象 $P$，渲染器再产生图像 $I$。解析时只得到 $I$ 与不一定完整的内部对象 $A$，目标是恢复适合语言模型的序列 $Y$：

$$
D\xrightarrow{\text{排版}}P
\xrightarrow{\text{渲染}}I,
\qquad
(I,A)\xrightarrow{\text{解析}}Y.
$$

排版映射不是可逆函数。原文中的段落、标题层级和表格语义在 PDF 中可能只剩坐标与字形；两个不同逻辑结构也可能渲染成近似相同页面。扫描件更进一步，只保留像素。OCR 模型能恢复的是在训练先验下最可能的逻辑序列，不是数学上唯一的原始文档。 **4.1. 三类信息损失.**

第一类是字形损失。低分辨率渲染、扫描噪声与字体相似使字符不可辨，例如 `l`、`1` 与 `I`。第二类是关系损失。字符都识别正确，行列、上下标和阅读顺序仍可能错误。第三类是语义选择损失。页眉是否删除、图注放在何处、跨栏标题属于哪一节，没有单纯像素级答案。 这三类错误对应不同监督。字符锚点主要补第一类，页面视觉与坐标补第二类，GPT-4o 银标和提示规范补第三类。把所有问题统一称为 OCR，会误以为只需提高字符分类准确率。 **4.2. 为什么全文编辑距离不够.**

设参考序列与预测序列长度为 $n$，一个跨栏顺序错误可能把两段各 $n/2$ 的正确字符交换。字符集合完全正确，编辑距离却可能很大；反过来，一张表按行吐出所有词，字符编辑距离不高，单元格关系已经丢失。公式中的上下标位置错一处，编辑距离只增加一两个字符，数学含义却改变。 因此，质量函数应同时看内容 $C$、顺序 $O$、结构 $S$ 与排除项 $E$：

$$
Q(Y)=w_CQ_C+w_OQ_O+w_SQ_S+w_EQ_E.
$$

olmOCR-Bench 用不同局部测试近似这些维度，再按来源宏平均。它没有假设四项能由一个字符串距离充分表达。 **4.3. Document anchoring 的概率解释.** 模型要估计

$$
p(Y\mid I,A).
$$

页面图像 $I$ 提供布局与视觉字形，锚点 $A$ 提供 PDF 内部字符、坐标和部分顺序。若两条通道条件独立且都可靠，联合证据会收紧后验；现实中它们来自同一页面，错误相关。损坏字体映射可能让 $A$ 系统性错误，低分辨率渲染又让 $I$ 无法反驳，模型便会自信复制错字。 **4.4. 锚点不是额外真值.** 将锚点记作对潜在逻辑文本的噪声观测：

$$
A\sim p(A\mid D,P),
\qquad
I\sim p(I\mid P).
$$

born-digital PDF 中，$A$ 往往字符精确但顺序混乱；扫描 PDF 中，$A$ 可能为空；带隐藏 OCR 层的扫描件中，$A$ 可能由旧 OCR 生成并含错误。模型需要根据视觉一致性、坐标合理性和语言先验动态分配权重。 论文的总体消融只显示有锚点平均更好。不同页面类型的最优权重不相同。若能可靠识别 PDF 类型，可以给原生文本页保留更多锚点，纯扫描页关闭锚点，对异常字体映射页降低权重。统一提示把这项判断交给 VLM 隐式学习。 **4.5. 冲突证据与复制偏差.** 假设图像清楚显示 `2025`，锚点写成 `202S`。自回归模型在输出该位置时综合两条证据。训练银标若教师经常优先复制锚点，学生会学到相同偏差；若教师经常凭语言常识修正，又可能把真实罕见字符串改成常见词。

可构造干预测试：在保持图像不变时随机替换少量锚点字符，观察输出跟随图像还是锚点；再保持锚点不变，对图像做模糊或遮挡。按字符类型、字号和页面来源统计，会得到模型的证据权重曲线。没有这种测试，只看总分无法知道锚点提升来自补字还是诱导复制。 **4.6. 锚点截断是一种非均匀缺失.** 提示预算有限时优先保留开头、结尾或采样块，缺失机制不是随机的。页面中部文字更可能没有字符辅助，标题和页脚更常被保留。若评测文本存在测试偏向页首，小幅增益可能高估整页收益。

设页面区域为 $r$，锚点被保留概率为 $q(r)$。要评估真实覆盖，应按区域报告字符与结构指标，或在构造基准时对位置分层。还可以用视觉密度自适应分配锚点预算：小字、高公式密度区域优先，清晰大标题少占字符。选择器自身若依赖有噪声的 PDF 对象，也要保存选择结果供审计。 **4.7. 二维页面如何变成一维序列.** 页面元素可表示为节点 $v_i=(b_i,t_i)$，$b_i$ 是包围框，$t_i$ 是文本或对象类型。阅读顺序是节点上的偏序关系，例如标题先于正文、左栏先于右栏、表头先于单元格。线性化要找一个满足这些约束的拓扑序。 **4.8. 简单坐标排序为何失败.**

按 $y$ 再按 $x$ 排序隐含「同一水平带从左到右阅读」。双栏页面会在每一行左右栏之间跳转；跨栏标题又需要先于两栏。按 $x$ 分栏再按 $y$，遇到嵌套栏、边注和浮动图表也会失败。 更一般的办法先预测块关系图，再拓扑排序。关系包括 `before`、`contains`、`caption-of`、`same-row` 与 `same-column`。若模型直接生成最终文本，这张图没有显式输出，但内部注意力仍需隐式求解相似问题。 **4.9. 偏序可能不唯一.** 两个并列图注或无关侧栏之间没有语义先后，多种线性化都合理。逐 token SFT 只给一个教师序列，其他合法顺序会被当作错误。这种单参考监督会把教师风格也蒸馏进去。

局部不变量评测缓解了这一点：只检查必须保持的相对顺序，不为无关块规定唯一全序。训练仍是单参考。若要进一步减少任意性，可以生成多种合法序列、对块级偏序做集合损失，或先预测结构图再由确定性规则线性化。 **4.10. 表格是二维关系压缩.** 表格单元格 $(r,c)$ 的含义来自行列标题与跨度。Markdown 用竖线和换行编码二维邻接，HTML 用标签和 rowspan/colspan；纯文本对齐依赖空格，最脆弱。模型若只保留单元格词汇，语言模型无法恢复哪个数属于哪个实体。 设表格值 $x_{rc}$，问答可能需要函数 $f(x_{r_1c_1},x_{r_2c_2})$。线性化若错误交换列，字符识别率不变，$f$ 的输入已错。olmOCR-Bench 的表格关系测试比全文相似度更接近这种下游需求。 **4.11. 银标蒸馏的误差结构.** 教师生成标签 $\tilde Y$，学生最小化

$$
\mathbb E_{I,A,\tilde Y}
[-\log p_\theta(\tilde Y\mid I,A)].
$$

若教师错误是独立随机噪声，大数据可以让共同正确模式占优；若错误与页面类型系统相关，学生会稳定继承。例如教师总在老扫描公式中漏上下标，增加同类银标只会强化偏差。 **4.12. 学生为何可能超过教师.** 专用学生的任务分布更窄，提示固定，25.9 万页提供大量重复结构。教师单次调用还受通用对话先验影响，学生可将跨页面共同模式压进参数。基准宏平均与教师训练选择也不同，因此学生在该基准超过教师不违反蒸馏上界；所谓上界只有在相同输入、相同损失、无限数据且学生仅拟合教师条件分布时才成立。

学生还使用 Qwen2-VL 的预训练视觉能力，不是从银标空白学习。银标负责适配输出协议与文档域，底座已含 OCR 和布局知识。若教师某页出错，底座先验与其他样本可以抵消。 **4.13. 选择性过滤会改变标签分布.** 生成失败、JSON 不合法、语言异常或重复严重的页面若被删除，训练集变成教师容易处理的条件分布。学生在困难页上缺少监督，部署时却仍会遇到。数据卡应报告候选页数、成功率、各失败原因和页面类型，不能只给最终 258,641 页。 失败页也可用于负面训练：让模型输出明确失败状态，而非编造文本。前提是下游系统能处理拒绝。若训练只见成功 JSON，模型更倾向对不可读页面也生成看似合理内容。 **4.14. 多教师与一致性.**

同一页由 GPT-4o、Gemini 或不同提示生成，重合部分更可信，分歧暴露不确定区域。简单多数票适合字符，不适合合法的格式变体。可以先解析为块、表格与公式结构，再做语义对齐。 多教师成本高，可只对高风险页使用：锚点与视觉冲突、输出接近长度上限、公式密集或模型自一致性低。这样把额外标注预算集中到系统误差最大的区域。 **4.15. 训练配置中的有效样本量.** 全局 batch 32、10,000 step 对应 320,000 个样本访问，约 1.24 个数据集遍历。若页面均匀采样，单页未被看到的概率近似

$$
\left(1-\frac1N\right)^{320000}
\approx e^{-320000/N}.
$$

$N=258641$ 时约为 $e^{-1.237}\approx0.29$。有放回采样下，约 29% 页面可能一次也没出现，另一些重复出现；实际 dataloader 若按 epoch 无放回打乱，则第一遍覆盖全部，再进入第二遍约 24%。复现需要知道 sampler 语义，单看「1.2 epoch」不能推导覆盖分布。 **4.16. 文档级相关性.** 每份文档最多取三页，同一文档页面共享字体、模板和主题。按页随机切分训练验证会泄漏版式；应按文档划分。训练中同一 batch 若包含同文档多页，梯度相关使有效 batch 小于 32。扩大文档多样性正是每文档限制页数的主要价值。 **4.17. 输出长度支配 token loss.** 逐 token loss 让长页面贡献更多梯度。一页 5,000 输出 token 的权重约是一页 500 token 的十倍，除非按样本重新归一化。长页通常也是密集、表格或公式页，训练目标会自然偏向它们；截断又删除尾部监督。

应报告按 token 与按页的 loss，并检查不同页面类型梯度占比。若希望每页同权，可将每样本 token loss 先求均值；这又会降低长页每个字符的总权重。选择取决于目标是训练 token 质量还是页面成功率。 **4.18. 基准统计与置信区间.** 7,010 个用例嵌套在页面与来源中，同一页多个测试高度相关。若 bootstrap 按测试项独立重采样，会低估方差；合理单位应是页面或文档，再在抽中页面内保留全部测试。 **4.19. 宏平均的方差.** 总分

$$
S=\frac18\sum_{g=1}^{8}S_g

$$

的方差为

$$
\operatorname{Var}(S)=\frac1{64}
\left[\sum_g\operatorname{Var}(S_g)
+2\sum_{g<h}\operatorname{Cov}(S_g,S_h)\right].
$$

来源组若用不同页面，协方差较小；Base 与其他组共享页面，显著相关。只把八个分项标准误独立相加会漏掉协方差。文档级 bootstrap 可自然保留。 **4.20. 分数差需要配对比较.** 两个 OCR 系统在相同页面与测试上评估，结果是配对 Bernoulli。差值不确定性取决于一方过、另一方不过的用例数，而非两个独立比例方差之和。bootstrap 时每次抽同一批页面，同时计算两个系统，能提高比较精度。 $75.5\pm1.0$ 与 $72.0\pm1.1$ 的区间不重叠提供直观证据，正式差值区间仍应由配对样本计算。跨新领域的泛化不确定性远大于这套固定基准的抽样区间。 **4.21. 测试数量不等于覆盖.**

公式测试 3,385 条，可能集中在较少 arXiv 页面与相似 LaTeX 结构；多栏测试数量较少，却覆盖另一类失败。有效覆盖由文档、模板、字体、年代和语言的多样性决定。发布测试计数之外，最好给独立页面数与来源分布。 **4.22. 下游 50B token 对照怎样解释.** 两组从同一 OLMo 中间 checkpoint、同一 S2ORC 文档集合继续训练，主要差别是 PDF 线性化。这是难得的受控证据。仍需注意 tokenizer 后的 token 序列长度可能不同；固定 50B token 意味着两组看到的文档页数和重复次数未必相同。 **4.23. 固定 token 与固定文档是不同问题.** 若 olmOCR 输出更完整，同一文档产生更多 token。固定 50B token 时，它可能覆盖更少文档；固定文档数时则使用更多计算。论文选择固定训练 token，比较单位计算预算下的数据效用。结果不能直接回答完整处理同一文档集合后哪组更好。

可同时报告每种线性化的总 token、独立文档覆盖、平均重复 epoch 和每 token loss。若 olmOCR 的收益来自保留更多有用结构，即使文档覆盖少也可能胜；若只是文本更长，单位 token 效率未必提高。 **4.24. 六项平均由 HellaSwag 主导增量.** HellaSwag 增加 5.2 点，其余多项小幅变化或下降。简单平均的 +1.3 不能解释为通用能力均匀提升。可能机制包括更自然的段落顺序改善连贯续写、页眉噪声减少，或学术 PDF 的某类文本与任务更匹配。 要验证机制，可分别训练只改变阅读顺序、只清除模板、只增强公式表格的语料版本，并增加文档结构敏感评测。当前实验证明整体管线有下游价值，没有分解每个组件贡献。 **4.25. 适用边界与反例.**

反例一：纯扫描手写表单没有内部文本，锚点优势消失，7B 模型训练数据又以英文数字 PDF 为主。反例二：PDF 文本层来自错误 OCR，坐标合理但字符系统性错，锚点会强化错误。反例三：复杂乐谱、化学结构和工程图的语义不适合线性纯文本，强行输出会丢失关系。 反例四：跨页表格在单页分别解析时重复表头、断开 rowspan，单页基准仍可能高分。反例五：输出长于 8,192 token 被截断，前半页测试全过却缺失尾部。反例六：语言模型根据上下文修正常识拼写，真实页面恰好包含罕见姓名或历史拼法，表面更流畅但不忠实。 **4.26. OCR 与文档理解的边界.**

olmOCR 目标是忠实线性化，不负责回答问题或解释图像。模型输出表格结构已经含一定理解，仍应避免加入页面没有的推论。若下游需要图片说明、图表数据抽取或跨页实体合并，应在 OCR 结果之上另建带来源定位的任务。 **4.27. 本地模型与专有教师的边界.** 训练标签来自 GPT-4o，发布模型可本地运行。数据隐私边界在推理时改善，训练知识仍继承专有教师输出。完全可重现的未来版本需要开放教师或人工结构标注；当前开放的是学生权重、训练混合与代码，而非教师内部过程。 **4.28. 可证伪的实验矩阵.**

第一组固定模型与页面，比较图像、锚点、图像加锚点，并按 born-digital、隐藏 OCR 层和纯扫描分层。第二组人为注入锚点字符与坐标错误，画输出跟随率。第三组改变图像分辨率与锚点预算，建立空间—文本 token 交换曲线。 第四组按页面区域和输出长度测召回，检查截断与非均匀锚点缺失。第五组对多栏、表格和公式分别做结构干预，区分字符正确与关系正确。第六组在下游预训练中固定 token、固定文档和固定计算三种口径，判断收益来自内容、长度还是覆盖。 **4.29. 最小复现记录.** 每页保存 PDF 哈希、页码、渲染器与 DPI、图像尺寸、pypdf 版本、原始锚点、锚点筛选结果、prompt、模型版本、原始 JSON、结束原因与后处理文本。评测保存用例版本和逐项结果，下游训练保存 tokenizer 后 token 数与文档覆盖。

这些字段让错误可以沿链条回溯。若只保留最终 Markdown，无法判断缺字来自原 PDF、渲染、锚点、生成还是清洗，也无法在新模型版本上做配对回归。 **4.30. 方法定位.** olmOCR 的方法价值来自互补观测：像素保留布局与扫描内容，PDF 对象保留精确字符线索，VLM 用语言与视觉先验求一个逻辑序列。它不把内部文本当真值，也没有完全抛弃传统解析器，而是把两者放进同一条件生成问题。 训练与评测也围绕这个目标设计。GPT-4o 银标提供规模，专用 7B 学生把任务分布收窄，局部不变量避开唯一整页参考，50B token 对照检查线性化是否真正改变语言模型学习。每一层都有明确边界：银标系统误差、锚点冲突、上下文截断、单页评测和硬件成本。

因此，判断一个 PDF OCR 系统不应只问「识别了多少字」。还要问二维关系是否保留、无关模板是否删除、证据冲突怎样处理、长页是否完整、跨页是否连贯，以及输出进入预训练后是否提高单位计算的数据效用。olmOCR 的开放材料让这些问题能够分别测量，这比单个总分更重要。
