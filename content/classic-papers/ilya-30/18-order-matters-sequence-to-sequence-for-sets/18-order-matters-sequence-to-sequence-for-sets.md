# Order Matters: Sequence to Sequence for Sets, 集合没有顺序, 但顺序决定一切

> 原始论文: Oriol Vinyals, Samy Bengio, Manjunath Kudlur, "Order Matters: Sequence to Sequence for Sets", ICLR 2016.
> https://arxiv.org/abs/1511.06391
> 这是 Ilya Sutskever 阅读清单的第 18 篇. 紧接第 17 篇 Pointer Networks, 同一个一作, 同一套工具, 解决的是上一个问题暴露出来的下一个问题: 输出可以是指针了, 那输入是无序集合时怎么办.

全文三组公式, 符号表放在最前面, 公式旁边会再讲一遍.

**全文符号表**

| 符号 | 含义 |
|------|------|
| $X = \{x_1, \dots, x_s\}$ | 输入, 序列时是 $s$ 个元素, 集合时元素无天然顺序. §7 实验表格里集合大小记作 $N$, 和 $s$ 同一含义 |
| $Y = \{y_1, \dots, y_t\}$ | 输出序列, $y_t$ 是第 $t$ 个元素, 长度记 $T$ |
| $P(Y \mid X)$ | 条件概率: 给定输入 $X$, 输出是 $Y$ 的概率. 坚线 $\mid$ 读作「在...的条件下」 |
| $\prod_{t=1}^{T}$ | 连乘: 把 $t$ 从 1 到 $T$ 的每一项乘起来. $T$ 在 §2 是输出序列长度, 在 §5 是 Process 模块的演化步数 (§7 实验部分改记 $P$), 靠上下文区分 |
| $h_s$, $g_t$ | encoder 和 decoder 的隐藏状态, $f_{enc}$, $f_{dec}$ 是各自的递推函数 (LSTM) |
| $m_i$ | 记忆向量: Read 模块给集合第 $i$ 个元素算出的 embedding, 集合多大就有多少条 |
| $q_t$ | Process 模块 LSTM 第 $t$ 步的状态; $q_t^*$ 是拼上读出向量后的状态, 星号只表示「拼过 $r_t$」 |
| $e_{i,t}$ | 第 $t$ 步给第 $i$ 条记忆打的匹配分. **注意同名: 第 17 篇 $e_j$ 是编码器隐状态, 本文 $e_{i,t}$ 是分数** |
| $a_{i,t}$ | $e_{i,t}$ 过 softmax 后的注意力权重, 对固定的 $t$, 全部 $i$ 加起来等于 1 |
| $r_t$ | 第 $t$ 步的读出向量: 所有记忆按权重 $a_{i,t}$ 的加权和 |
| $f(\cdot, \cdot)$ | 打分函数, 输入一条记忆和一个 query, 输出一个标量匹配分, 比如点积 |
| $[a; b]$ | 拼接: 两个向量首尾相接, 和第 14, 15 篇同一记号 |
| $\mathrm{LSTM}(\cdot)$ | LSTM 走一步: 输入上一状态, 输出新状态 |
| $\pi(X)$ | 输入 $X$ 的一个排列 (元素的某种输出顺序), 本文的潜变量 |
| $\theta$ | 模型可训练参数, $\theta^*$ 是训练收敛后的最优参数 |
| $M$ | 训练集的样本条数 |
| $\arg\max_\theta$ | 遍历所有参数取值, 返回让后面表达式最大的那个 $\theta$ |

**读公式的方法**: 三组公式三个角色. §2 链式分解是全文地基 (本系列第 14, 17 篇之后第三次出现), 读「连乘加条件前缀」. §5 两条公式合起来是 Process 模块的一步, 按四拍读: 打分, 归一化, 加权读出, 拼回状态. §10 训练目标读两层: 外层求和遍历训练样本, 内层 max 遍历排列, 那个 max 就是「让模型自己选顺序」的全部含义.

## 1. 背景: 2015 年的 seq2seq 帝国

2014 年 Sutskever, Vinyals, Le 的 seq2seq 论文把机器翻译变成了一个公式: encoder LSTM 读完整个输入, 把最终状态交给 decoder LSTM, 一个 token 一个 token 地吐输出. 这个范式背后只有一条数学: 链式法则. 序列的联合概率可以无假设地分解成条件概率的乘积, LSTM 负责把每个条件概率建模出来.

接下来一年, 这个范式像圈地一样扩张. 图像描述是图片到句子, 句法分析是句子到线性化的括号树, 图像描述那篇 Show and Tell, 句法分析那篇 Grammar as a Foreign Language, 一作都是 Vinyals. 2015 年中, 他又把 seq2seq 推进了一步: Pointer Networks, 输出不再是固定词表里的 token, 而是指向输入位置的指针, 凸包, TSP, Delaunay 三角剖分这些组合优化问题第一次被端到端地学习. 那是清单第 17 篇.

Pointer Networks 的论文里有一个没有解决的尴尬. 它的实验对象, 平面上的 n 个点, 本质上是一个集合, 不是序列. 点没有天然顺序, 但 LSTM encoder 必须按某种顺序一个个读. 训练时用什么顺序, 测试时换个顺序, 模型表现立刻波动. 更微妙的是输出侧: 一个凸包可以用顺时针或逆时针两种顺序输出, 从哪个点开始都可以, 这些答案全都正确, 但训练数据只能选一种写法.

这篇 Order Matters 就是来收拾这个残局的. 标题是个双关: 表面上说的是「顺序很重要」, 顺序影响性能; 深一层说的是「给集合排顺序这件事, 本身就是研究对象」. 论文做两件事. 第一, 用一批实验确认顺序确实重要, 哪怕理论上不该重要. 第二, 给出两个工程方案: 输入侧用 Read-Process-Write 架构吃掉顺序, 输出侧用一个训练时搜索顺序的损失函数绕过顺序.

## 2. 问题定义: 序列的数学, 集合的尴尬

先把 seq2seq 的形式骨架摆出来. 给定输入序列 $X = \{x_1, \dots, x_s\}$ 和输出序列 $Y = \{y_1, \dots, y_t\}$, 链式法则给出:

$$
P(Y \mid X) = \prod_{t=1}^{T} P(y_t \mid y_1, \dots, y_{t-1}, X)
$$

这条公式在本系列已经是第三次出现 (第 14, 17 篇各一次), 读法不变: 整串输出的概率拆成逐位条件概率的连乘, $t$ 从 1 乘到输出长度 $T$, 第 $t$ 位以「前 $t-1$ 位已生成的内容」和「整个输入」为条件. 与前两篇的唯一差别在记号: 这里输入是 $X$, 输出是 $Y$, 没有特殊结构, 通用形式.

encoder 递推 $h_s = f_{enc}(h_{s-1}, x_s)$ 读入整个输入, decoder 从 $g_1 = h_s$ 出发, 按 $g_t = f_{dec}(g_{t-1}, y_{t-1})$ 逐个生成, 每一步接一个 softmax. 整个框架对序列是干净的: 句子里的词有天然顺序, 顺着读顺着写就行.

集合打破了这个干净. 论文举的第一个例子就够直白: 输入是 N 个 0 到 1 之间的随机浮点数, 任务是把它们排序输出. 这堆数没有任何天然顺序, 但 encoder 非要按某个顺序读. 同样的问题出现在输出端: 如果输出是图像里检测到的一组物体, 这组物体先报哪个后报哪个, 数据里没写, 模型却必须选一种.

有一个反向观察值得记住: 序列总能编码成集合. 给每个元素附上它的位置编号, 「I like cats」就变成集合 $\{(I,1), (like,2), (cats,3)\}$, 任意打乱都不丢失信息, 因为位置写在元素里. 这个 trick 在后面的 5-gram 实验里会被用作实验装置. 它说明集合是比序列更底层的表示, 序列只是带了位置标签的集合.

处理集合有一个必须满足的不变性: 交换输入里任意两个元素 $x_i$ 和 $x_j$, 编码结果不该变. 最朴素的做法是词袋: 把每个元素的 embedding 加起来. 加法天然满足置换不变, 所以它确实是个合法的集合编码器. 问题在别处.

## 3. 词袋的死穴: 记忆不随集合长大

词袋类方法的致命伤不是精度, 是表示效率. 无论集合里有 5 个元素还是 500 个, 词袋都把它压进同一个固定维度的向量. 论文的论点很直接: 编码一个长度为 T 的集合, 需要的记忆量应该随 T 增长. 固定维度的瓶颈意味着长集合的信息必然被挤掉, 这和把整本书记进一个 256 维向量是同一个病.

顺带一提, 论文认为固定感受野之外的深度卷积编码器也有同样的限制. 这个判断在 2015 年写下, 两年后 Deep Sets 用「置换不变函数必然能分解成 $\rho(\sum_{i=1}^{N} \phi(x_i))$」(对集合里全部 $N$ 个元素各自过 $\phi$ 再求和, 最后过 $\rho$) 的定理把这件事形式化了: 求和池化确实是通用的, 但 $\rho$ 和 $\phi$ 得足够强, 实践里大家还是转向了 attention 类的可变记忆方案. 本文选择的路线正是后者: 把集合的每个元素存成一条独立的记忆, 记忆的条数随集合大小走, 然后用 attention 去读.

这是整篇论文最关键的一个设计判断. 顺序无关性不靠「对顺序不敏感的聚合运算」实现, 而靠「基于内容的寻址」实现: attention 的读出是记忆向量的加权和, 权重由内容相似度决定, 和记忆槽的编号无关. 打乱记忆的物理顺序, 读出结果不变. 置换不变性是被 attention 的寻址方式免费赠送的.

## 4. 输入顺序为什么重要: 三个旧账

论文在提出方案之前, 先翻了三笔旧账, 证明「顺序影响性能」不是新发现, 而是一个被反复目击却没有被正面处理的现象.

第一笔来自 Sutskever 2014 年的 seq2seq 原始论文. 机器翻译里把源语言句子的词序整个倒过来输入, BLEU 涨了 5.0 分. 5 个 BLEU 在 2014 年是什么概念: 这个 trick 让一个纯端到端模型直接追平了高度工程化的当时最佳系统. 倒序之所以有效, 后来比较公认的解释是它把源句和目标句开头对齐, 缩短了早期预测的平均依赖距离. 但无论如何, 一个理论上无关紧要的预处理, 换来了 SOTA 级别的差距.

第二笔来自 Vinyals 自己的句法分析论文. 把输入的英文句子倒序, F1 绝对值涨 0.5%. 幅度小, 但方向一致.

第三笔来自 Pointer Networks 的凸包实验. 如果预处理时把点按极角排序, 凸包问题从 $O(n \log n)$ 的排序加扫描退化成 $O(n)$ 的纯扫描, 模型训练快得多, 最难的 case 上精度绝对值提升高达 10%.

三笔账指向同一个结论, 论文自己的总结是: 出于优化的原因, 输入数据呈现给模型的顺序影响学习效果. 理论上 LSTM 是通用近似器, 任何顺序下都能学会同一个函数; 实践中优化是非凸的, 顺序就是一种隐式先验, 选对了少走很多弯路. 「理论上不重要, 实践上很要命」, 这个模式在深度学习里反复出现, 这篇论文是早期把它摆到台面上的一次.

还要区分两种顺序. 一种是与输入无关的固定变换, 比如翻译里永远倒序. 另一种是依赖输入内容的排序, 比如凸包里按极角排. 后者信息量大得多, 它等于把一部分计算外包给了预处理. 这个区分在讨论输出顺序时同样成立.

## 5. Read-Process-Write: 给模型一段思考时间

核心架构登场. 它分三块, 名字就是工作流程: Read, Process, Write.

Read 模块最简单. 一个小型神经网络 (所有元素共享同一套参数) 把集合里每个元素 $x_i$ 嵌入成一条记忆向量 $m_i$. 集合有多大, 记忆就有多少条. 记忆量随输入规模增长, 词袋的瓶颈被绕开了.

Process 模块是全篇最有想象力的部分. 它是一个没有输入也没有输出的 LSTM, 自顾自地演化 T 步. 每一步它只做一件事: 用当前状态当 query, 对所有记忆做一次 content-based attention, 读出加权和, 拼回自己的状态:

$$
q_t = LSTM(q_{t-1}^*), \quad e_{i,t} = f(m_i, q_t), \quad a_{i,t} = \frac{\exp(e_{i,t})}{\sum_{j=1}^{N} \exp(e_{j,t})}
$$

$$
r_t = \sum_{i=1}^{N} a_{i,t} m_i, \quad q_t^* = [q_t;\, r_t]
$$

两式合起来是 Process 模块的一步, 按四拍读. 第一拍 $q_t = LSTM(q_{t-1}^*)$: LSTM 没有外部输入, 只拿自己上一步拼好的状态 $q_{t-1}^*$ 往前走一步, 这个 $q_t$ 就是本轮的 query. 第二拍 $e_{i,t} = f(m_i, q_t)$: 打分函数 $f$ 拿 query 和每条记忆 $m_i$ 各算一个匹配分, $N$ 条记忆出 $N$ 个分. 第三拍是 softmax: 分子是第 $i$ 条记忆的分数取 exp, 分母是全部 $N$ 条记忆分数取 exp 的总和, 一比得到权重 $a_{i,t}$, 全部加起来等于 1. 第四拍 $r_t = \sum_{i=1}^{N} a_{i,t} m_i$: 所有记忆按权重加权和, 读出向量 $r_t$ 拼到 $q_t$ 后面得到 $q_t^*$, 喂回第一拍开始下一轮.

还是那组熟悉的数. 设集合只有 3 个元素, 某一步三个匹配分是 $(2, 1, 0)$, softmax 之后是 $(0.665, 0.245, 0.090)$ (和第 14, 17 篇同一组数), 读出向量 $r_t = 0.665\,m_1 + 0.245\,m_2 + 0.090\,m_3$. 关键在权重由内容算出: 把三条记忆的存放顺序任意打乱, 分数跟着重排, 加权和分毫不差. 置换不变性就是这么免费得到的.

其中 $f$ 是打分函数, 比如点积. 因为 attention 按内容寻址, 打乱 $m_i$ 的排列不影响 $r_t$, 整个模块对输入顺序免疫. T 步之后得到的状态 $q_T^*$ 是整个集合的编码, 交给下游.

这个设计的含义比它的公式大. 普通 encoder 的计算量和输入长度绑定, 读完就结束了. Process block 把计算量和输入长度解耦: 集合读完之后, 模型还可以「再想 T 步」. 论文把它类比为 Neural Turing Machine 或 Memory Network 的特例, 外部记忆加可微寻址. 放到十年后的视角看, 这就是「thinking time」的雏形: 把一部分计算预算花在输入消化完之后, 输出开始之前. 后来的 Relational Networks (清单第 19-20 篇) 在对象对之间反复做关系计算, 2023 年之后 reasoning 模型用额外 token 换思考深度, 都是同一个思想的不同化身: 计算不必一步到位, 中间可以有酝酿.

Write 模块是上一篇的老朋友: Pointer Network. 它拿 $q_T^*$ 当上下文, 每一步输出一个指向某条记忆的指针, 隐式地指向对应的输入元素. 输出是输入元素的排列, 天然适合排序, 凸包, TSP 这类「答案是输入的子集加顺序」的任务.

## 6. glimpse: 指针之前先看一眼

Write 模块里还有一个新零件, glimpse. 原始 Pointer Network 每一步直接对记忆算一次 attention, 把指针当分类结果输出. 本文在每次出指针之前, 额外插入一次 attention 读出: 先「看一眼」记忆, 把读到的内容拼进状态, 再决定指谁.

glimpse 和 process block 是同一类机制, 区别只在位置: process block 的 attention 发生在全部输出之前, 一口气跑 T 步; glimpse 的 attention 穿插在每一步输出之间, 输出一步看一眼. 一个管输出前的酝酿, 一个管输出中的核对. 论文的评语是这两种机制互补, 实验数字支持这个判断, 下一节给出.

顺带说清楚一个边界: 如果输出来自固定词表, Write 模块退化成普通 LSTM 就行, 不需要指针. 指针是为组合问题准备的, 这类问题的答案必然是输入元素的引用. 整篇论文的实验集中在组合问题上, 所以 Write 一律用 pointer network.

## 7. 排序实验: 处理步数就是正确率

主实验是排序, 一个干净的 set2seq 任务: 输入 N 个 0 到 1 之间的随机浮点数, 输出它们从小到大的顺序. 指标苛刻到不近人情: out-of-sample accuracy 定义为整个序列全部排对才算对, 错一个元素就算失败. 所有模型训练 10000 次迭代, 都收敛了, 也都没有过拟合, 数字可以直接对比.

对照组是 vanilla seq2seq: 输入 LSTM 接输出 LSTM 加 Ptr-Net. 实验组是 Read-Process-Write, 唯一的差别就是编码集合的方式. 两个变量: 处理步数 P 取 0, 1, 5, 10; glimpse 取 0 或 1. 结果 (每格两个数字, 分别是无 glimpse 和有 glimpse):

| N | Ptr-Net | P=0 | P=1 | P=5 | P=10 |
|---|---|---|---|---|---|
| 5 | 81% / 90% | 65% / 84% | 84% / 92% | 88% / 94% | 90% / 94% |
| 10 | 8% / 28% | 7% / 30% | 14% / 44% | 17% / 57% | 19% / 50% |
| 15 | 0% / 4% | 1% / 2% | 0% / 5% | 2% / 4% | 0% / 10% |

表格里能读出三件事. 第一, P=0 时 Read-Process-Write 打不过 baseline, 去掉思考步骤, 新架构反而更差, 说明它的优势完全来自 process block, 不是来自别的什么 trick. 第二, 只要允许至少一步处理, 新架构反超, 且基本随步数单调上升. N=10 无 glimpse 一列最干净: 7%, 14%, 17%, 19%. 第三, glimpse 的效果比 process block 更猛: 最难的 case 上它把精度翻了一倍还多, N=10 加 glimpse 后从 8% 跳到 28%, P=5 时从 17% 跳到 57%.

也要诚实地说, N=15 一行的数字全是零或近零. 全对指标下, 15 个元素的排序对 2015 年的 LSTM 还是太难了, 架构改良没有带来质变. 这篇论文证明的是机制的有效性, 不是排序问题被解决了.

## 8. 输出顺序同样重要: 语言模型与句法树

输入侧讲完, 论文转向输出侧. 链式法则对输出变量的任何排列都成立, 理论上顺序无关. 论文用三个实验说明实践不是这么回事.

第一个是 Penn TreeBank 语言模型. 用 Zaremba 2014 的 medium LSTM 配置, 训练三种词序的数据: 自然序, 整句倒序, 以及一种故意捣乱的 3 词块倒序, 把「This is a sentence .」变成「a is This <pad> . sentence」. 3 词块倒序打碎了句子的 n-gram 结构, 建模难度被人为抬高. 结果: 自然序和倒序的验证困惑度都是 86, 打平; 3 词块倒序掉到 96, 只差了 10 个点. 训练困惑度同样高 10 个点, 说明模型不是泛化变差, 是连训练都更费劲. 一句话: 即使顺序被刻意破坏, LSTM 也只退化了一小截, 但退化是真实存在的, 且方向可预测.

第二个是句法分析. 同一棵括号树可以按深度优先遍历线性化, 也可以按广度优先遍历线性化, 两种编码都无损. 用 Vinyals 2015b 的模型各训一版: 深度优先 89.5% F1, 广度优先 81.5% F1. 8 个点的差距, 而且论文脚注补了一刀: 广度优先版本很多 case 连合法的树都生成不出来, 真实 F1 只会更低. 同样是「理论上等价的输出编码」, 实践表现天差地别. 深度优先赢的原因很直觉: 相邻的括号在树上也相邻, 局部依赖短, 自回归生成的每一步都轻松.

这两个实验共同支撑了论文标题的后半句: 不只是输入顺序, 输出顺序同样是一种可以选, 也应该选的先验.

## 9. n! 个正确答案是个诅咒

输出侧还有一个比「哪种顺序更好」更根本的问题: 有些任务的正确答案本身就不止一个, 而且数量是阶乘级的.

排序任务里, 输出 argsort 的索引, 递增输出是对的, 递减输出换个指标也是对的, 任何一种固定排列下输出都包含同样的信息. 一共 n! 种等价写法. 如果训练数据是随机从这 n! 种写法里采的, 模型就被迫对同一个输入把概率质量平摊到 n! 个输出构型上. 一个完美训练的模型也必须在 n! 个峰之间均分概率, 统计效率极低, 学习信号被摊薄到几乎没有.

论文报告了一个干净的失败: 排序任务如果把输出当集合处理, 允许任意顺序, 哪怕 n 小到 5, 收敛后的性能也永远追不上固定顺序的版本. 5 个元素, 120 种写法, 就足以拖垮训练.

Pointer Networks 里其实已经实践过解法, 只是当时没有上升到原则: 尽可能压缩输出的等价类. TSP 的路径是环, 从哪个城市开始报都一样, 那就规定永远从编号最小的城市开始; 顺时针逆时针都合法, 那就规定永远逆时针. 三角剖分输出一组三角形, 顺序任意, 那就规定按字典序从左到右报. 这些约定让精度普遍涨 5% 以上. 原则一句话: 正确答案的等价类越小, 学习越容易; 把对称性留给数据约定去破, 别让模型自己去学对称性.

这个教训在十年后的 LLM 后训练里换了个马甲重新出现: 同一条推理轨迹有多种等价写法时, 奖励信号会被摊薄. 凡是有 n! 对称性的监督信号, 都值得先问一句能不能用约定消掉.

## 10. 让模型自己找顺序

如果不知道哪种输出顺序好, 能不能让模型训练时自己找? 论文给出的方案是把顺序也纳入优化目标. 设 $\pi(X)$ 是某个让任务变简单的排列, 训练目标从最大化 $\log p(Y|X)$ 变成:

$$
\theta^* = \arg\max_\theta \sum_{i=1}^{M} \max_{\pi(X_i)} \log p(Y_{\pi(X_i)} \mid X_i; \theta)
$$

从外往里三层读. 外层 $\arg\max_\theta$: 遍历所有参数取值, 找出让后面整个表达式最大的那个 $\theta$, 记作 $\theta^*$, 这就是训练收敛后要的参数. 中层 $\sum_{i=1}^{M}$: 遍历训练集的全部 $M$ 条样本, 每条样本出一个分数再相加. 内层 $\max_{\pi(X_i)}$ 是全文的新东西: 对第 $i$ 条样本, 遍历它所有可能的输出排列 $\pi(X_i)$, 只取让对数似然 $\log p(Y_{\pi(X_i)} \mid X_i; \theta)$ 最大的那一个顺序, $Y_{\pi(X_i)}$ 就是按这个顺序重排后的输出. 分号后的 $\theta$ 提醒概率是用当前参数算的: 顺序按当前模型评估, 模型又按选出的顺序更新, 鸡生蛋蛋生鸡的结构就写在这个式子里.

即对每个样本, 在模型当前参数下找让似然最大的输出顺序, 再用这个顺序算梯度. 问题有两个. 排列空间是 n!, 精确搜索不可行. 更阴险的是, 朴素地每步取 max, 模型会锁定在初始化附近随便碰到的第一个顺序上, 然后不断自我强化, 永远出不来. 这是一个先有鸡还是先有蛋的死锁: 顺序要靠模型评估, 模型要靠顺序训练.

两个修复都很朴素. 第一, 预训练 1000 步, 这期间对顺序取均匀分布而不是 max, 相当于把 max 换成期望, 让模型先见识各种顺序. 第二, 预训练结束后不再取 max, 改为按 $p(Y_\pi|X)$ 正比的概率采样一个顺序. 采样可以用 ancestral sampling 从左到右生成, 只需一次模型前向, 复杂度 O(1), 对比朴素搜索的 O(n!).

验证实验是 5-gram 建模: 把每个 5-gram 的词带上位置标签变成集合, 模型要在不知道词序的情况下恢复联合概率. 先确认顺序确实重要: 自然序 (1,2,3,4,5) 训练, 验证困惑度 225; 换成打乱序 (5,1,3,4,2), 困惑度 280. 然后上搜索框架. Easy 设置只在两个顺序里选, 模型很快锁定自然序, 困惑度回到 225. Hard 设置面对全部 5! = 120 种顺序, 模型最终稳定在自然序, 完全倒序 (5,4,3,2,1), 以及它们的小变体上, 困惑度同样是 225. 没有任何先验告诉模型「自然序好」, 它自己找到了人类觉得理所当然的那个答案.

这个实验的规模很小, 5-gram, 120 种排列. 但它示范的东西不小: 顺序本身可以是潜变量, 用「预训练加采样」这套最朴素的近似推断就能处理. 这个思路和后来的 EM 式自举, 以及 reasoning 时代「让模型自己选推理路径」的训练范式, 在精神上是连续的.

## 11. 局限与后续

这篇论文的局限写在它的时代里. 2015 年, 主力工具是 LSTM, attention 刚满一岁, Transformer 还要两年才出生. Process block 的 T 步是串行的, LSTM 一个一个时间步走, 思考越深越慢, 这限制了它在大规模任务上的竞争力. 排序实验在 N=15 就全军覆没, 说明机制对, 容量不够.

后续的接力分三条线. 第一条是集合表示的理论化: 2017 年 Deep Sets 证明了置换不变函数的通用分解形式, 把「怎么编码集合」变成了有定理支撑的设计问题, 2019 年的 Set Transformer 用 self-attention 做集合编码, 可以看作把 process block 的串行思考换成并行的层叠注意力. 第二条是外部记忆这条线本身: 论文反复说自己的架构是 Neural Turing Machine 和 Memory Network 的特例, NTM 就在清单第 22 篇等着. 第三条最远也最值得点出: process block 把「读完输入」和「开始输出」之间插入了一段纯计算, 这是后来一切「thinking time」思想的雏形. Relational Networks (清单第 19-20 篇) 把这段计算专门用于对象间关系, 今天的 reasoning 模型把这段计算拉成几千个 token. 从 T=10 步的 LSTM 到几千步的 chain-of-thought, 中间隔了十年, 但问题是同一个: 输入消化完之后, 给模型多少酝酿的预算.

还有一个诚实的保留. 论文发现的最优顺序, 全都落在人类已知的候选里: 自然序, 倒序, 深度优先. 「发现人类不知道的好顺序」是作者自己立下的 flag, 论文里没有兑现. 自动搜索顺序这件事, 搜到的都是常识, 这到底是方法的上限还是任务太简单, 论文没有回答.

## 12. 在清单里的位置

把第 17 篇和第 18 篇连起来看, 结构非常清楚. 第 17 篇 Pointer Networks 解决输出端: 输出不是词表 token, 而是指向输入的指针, seq2seq 从此能碰组合优化. 第 18 篇解决输入端: 输入不是序列, 而是无序集合, seq2seq 从此能碰集合. 同一个一作, 同一套 LSTM 加 attention 的工具箱, 连续两步把 seq2seq 的适用面从「序列到序列」撑到了「集合到序列」, 论文标题里的 Sequence to Sequence for Sets 就是这个意思.

往清单后面看, 这条线的回声至少有四处. 第 19-20 篇 Relational Networks 系列, 把 process block 式的反复计算专门用于推理关系. 第 22 篇 Neural Turing Machines, 是本文自认的「一般形式」, 外部记忆加可微寻址的完整版. 第 26 篇 Scaling Laws 背后有个共享的信念: 优化是非凸的, 数据呈现方式这种「理论上无关」的选择, 在规模下会被放大成真实的差距, 顺序就是最早的例子之一. 更远的回声在今天: reasoning 模型的 thinking time, 本质就是 process block 的思想被 scale 到千步量级.

这篇论文没有定理, 没有 SOTA 霸榜, 最有冲击力的数字是一张排序正确率表. 但它留下了三个可以反复使用的判断. 第一, 「理论上顺序无关」从来不等于「实践上顺序无关」, 非凸优化会把先验选择放大成性能差距. 第二, 置换不变性最优雅的实现不是设计对称的聚合函数, 而是基于内容的寻址, attention 天然不 care 物理顺序. 第三, 计算可以分段: 读, 想, 写. 中间的「想」当时只值 10 步 LSTM, 十年后值几千个 token, 但分段这个动作本身, 是 2015 年这篇论文先做出来的.
