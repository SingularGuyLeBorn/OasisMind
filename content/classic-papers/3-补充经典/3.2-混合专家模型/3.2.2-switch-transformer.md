# 2.2.2 · Switch Transformer: 每个 token 只走一个专家, 万亿参数预训练快 4 到 7 倍

> 原始论文: William Fedus, Barret Zoph, Noam Shazeer, "Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity", [arXiv:2101.03961](https://arxiv.org/abs/2101.03961), 2021; JMLR 2022.
> 路线 `2.2.2`. `2.2.1` [Sparsely-Gated MoE](3.2.1-sparsely-gated-moe.md) 已经证明稀疏门控可以训练;Switch Transformer 把路由简化为 top-1,放进 Transformer 预训练并扩展到万亿参数.Shazeer 是两项工作的共同作者.

**全文符号表**

| 符号 | 含义 |
|------|------|
| $x$ | 进入 Switch 层的一个 token 表示, 维度 $d_{model}$ |
| $N$ | 一个 Switch 层里的专家数. 这里用大写 $N$, 上一篇用小写 $n$ |
| $E_i(x)$ | 第 $i$ 个专家 (一个 FFN) 对 $x$ 的输出 |
| $W_r$ | 路由器权重, $h(x) = W_r \cdot x$ 给出 $N$ 个 logits |
| $p_i(x)$ | token $x$ 被路由到专家 $i$ 的概率, 即 softmax 后的门控值 |
| $\mathcal{T}$ | 被选中的专家下标集合, Switch 里只有一个元素 |
| $\mathcal{B}$, $T$ | 一个 batch, 以及其中的 token 数 |
| $f_i$ | batch 里实际被派给专家 $i$ 的 token 比例, 离散量, 不可导 |
| $P_i$ | batch 里路由器分给专家 $i$ 的平均概率, 可导 |
| $\alpha$ | 辅助损失系数, 全文取 $10^{-2}$ |
| capacity factor | 容量因子, 每个专家能收的 token 数相对「平均份额」的倍数 |

**读公式的方法.** 全文公式都在回答三个问题. 路由公式回答「token 交给谁」, 盯住求和下标 $\mathcal{T}$ 里有几个元素. 容量公式回答「每个专家最多收多少」, 它是个静态形状, 编译时就要定死. 辅助损失回答「怎么防止大家都挤到一个专家」, 读的时候分清 $f_i$ 和 $P_i$: 一个是实际发生了什么, 一个是路由器心里怎么想的, 梯度只从后者走.

## 背景: MoE 能跑, 但没人用

2017 年的 Sparsely-Gated MoE 把容量做到了 137B, 翻译和语言模型都刷了纪录. 此后四年, 它没有成为主流. 论文开头把原因总结成三个词: 复杂度, 通信成本, 训练不稳定.

复杂度来自路由本身. noisy top-k 要调噪声, 两个辅助损失要调两个系数, $k$ 要调, 还有层次化门控. 通信来自 top-k: 每个 token 要发给 $k$ 个专家, 专家分布在不同设备上. 不稳定则是规模一大就冒出来的问题, 2020 年的 GShard 做到 6000 亿参数, 为了稳住, 整个模型都用 float32 训练.

同一时期, Kaplan 等人的 Scaling Laws (本站路线 `1.6.4`) 把参数量, 数据量, 计算量三个轴的幂律测得很清楚. Switch 的出发点是第四个轴: 每个样本的 FLOPs 固定, 只涨参数. 论文的假设是, 参数量本身就是一个独立的扩展维度, 和总计算量无关.

要验证这个假设, 需要一个足够简单, 足够稳定, 能在 TPU 上高效跑的稀疏层. 这就是 Switch 层.

### Switch 路由: 只选一个专家

先回顾 MoE 路由. 路由器把 token 映成 $N$ 个 logits, 过 softmax:

$$p_i(x) = \frac{e^{h(x)_i}}{\sum_{j=1}^{N} e^{h(x)_j}}, \qquad h(x) = W_r \cdot x$$

$p_i(x)$ 就是 token 去专家 $i$ 的概率. 选出概率最高的若干个专家, 输出是它们的加权和:

$$y = \sum_{i \in \mathcal{T}} p_i(x) E_i(x)$$

Shazeer 2017 的 $\mathcal{T}$ 有 $k \geq 2$ 个元素. 当时的直觉是: 路由器至少要比较两个专家, 才能得到有意义的梯度. Ramachandran 和 Le 2018 年还发现, 路由层多的模型里, 低层用更大的 $k$ 更重要.

Switch 反着来: $k = 1$, $\mathcal{T}$ 只有一个元素. 论文把这种层叫 Switch 层.

代入一组数. 4 个专家, logits 为 $(2.0, 1.0, 0.5, -1.0)$. 完整 softmax: $e^{2} = 7.389$, $e^{1} = 2.718$, $e^{0.5} = 1.649$, $e^{-1} = 0.368$, 和为 12.124, 概率 $(0.609, 0.224, 0.136, 0.030)$. 选专家 1, 输出 $y = 0.609 \cdot E_1(x)$.

注意这里没有重新归一化. 0.609 这个门控值被原样乘到专家输出上, 路由器的梯度就从这个系数流回去. 如果改动 $W_r$ 让 $p_1$ 变大, 输出幅度随之变大, 损失会告诉路由器这样是好是坏. $k = 1$ 也能学路由, 靠的就是这一乘.

论文列了 top-1 的三个好处. 路由计算更少, 一个 token 只去一个地方. 每个专家的 batch (容量) 至少能减半, 因为每个 token 只占一个位置. 实现更简单, 通信更少.

### 专家容量与 capacity factor

TPU 要求张量形状在编译期静态确定, 但路由结果到运行时才产生. 因此每个专家可接收的 token 数需要预先设定上限:

$$\text{expert capacity} = \left(\frac{\text{tokens per batch}}{\text{number of experts}}\right) \times \text{capacity factor}$$

括号里是完全均匀时每个专家的平均份额, 乘上容量因子留出余量. 容量因子大于 1, 就能容忍一定程度的不均衡.

代入数字. 一个 batch $2^{20} = 1048576$ 个 token, 128 个专家, 平均份额 8192. 容量因子 1.0 时每个专家最多收 8192 个; 1.25 时收 10240 个. 超出容量的 token 被丢弃 (dropped tokens): 这一层不算它, 它的表示通过残差连接直接进下一层.

容量因子是一个典型的 tradeoff. 开大了, 丢的 token 少, 但空位要补零, 浪费计算和显存, 还要多通信. 开小了, 计算紧凑, 但丢的 token 多. 论文实验里丢弃率通常低于 1%, 前提是辅助损失的系数够大.

Table 1 把 Switch 和 top-2 MoE 放在同样硬件 (32 个 TPUv3 核), 同样步数下比. 所有稀疏模型都是 128 个专家, 每隔一层 FFN 放一个专家层. 质量用负对数困惑度 (越高越好), 速度是达到 -1.50 所需的小时数.

| 模型 | 容量因子 | 10 万步后质量 | 到达 -1.50 的小时数 | 每秒样本数 |
|---|---|---|---|---|
| T5-Base | — | -1.731 | 没达到 | 1600 |
| T5-Large | — | -1.550 | 131.1 | 470 |
| MoE-Base (top-2) | 2.0 | -1.547 | 68.7 | 840 |
| Switch-Base | 2.0 | -1.554 | 72.8 | 860 |
| MoE-Base (top-2) | 1.25 | -1.559 | 80.7 | 790 |
| Switch-Base | 1.25 | -1.553 | 65.0 | 910 |
| MoE-Base (top-2) | 1.0 | -1.572 | 80.1 | 860 |
| Switch-Base | 1.0 | -1.561 | 62.8 | 1000 |
| Switch-Base+ | 1.0 | -1.534 | 67.6 | 780 |

三个读法. 第一, 按「速度 × 质量」算, Switch 同时赢了调好的稠密模型和 top-2 MoE; 容量因子 1.0 时它最快到达目标, 62.8 小时. 第二, Switch 更省计算, 把它加宽 (隐层 768 → 896, 头数 14 → 16) 做成和 MoE 一样慢的 Switch-Base+, 按步数算也全面领先. 第三, Switch 在小容量因子下表现更好. 显存最紧的大模型场景, 恰好就是要把容量因子压到 1 附近的场景.

### 一个辅助损失管负载均衡

Shazeer 2017 用了两个损失, importance 和 load, 后者还要靠噪声造可导的概率. Switch 沿用 GShard 等工作的简化, 每个 Switch 层只加一个:

$$\text{loss} = \alpha \cdot N \cdot \sum_{i=1}^{N} f_i \cdot P_i$$

$f_i$ 是实际派给专家 $i$ 的 token 比例:

$$f_i = \frac{1}{T} \sum_{x \in \mathcal{B}} \mathbb{1}\{\arg\max p(x) = i\}$$

$P_i$ 是路由器分给专家 $i$ 的平均概率:

$$P_i = \frac{1}{T} \sum_{x \in \mathcal{B}} p_i(x)$$

两个都是长度 $N$ 的向量, 分量和为 1. 损失是它们的点积乘上 $\alpha N$. $f_i$ 来自 argmax, 不可导; $P_i$ 来自 softmax, 可导. 梯度只经 $P$ 走.

完全均匀时 $f_i = P_i = 1/N$, $\sum_i f_i P_i = N \cdot (1/N)^2 = 1/N$, 乘上 $N$ 刚好是 1. 这就是乘 $N$ 的理由: 专家数变了, 损失的基准值不变, $\alpha$ 不用重调.

代入一个塌缩的例子. 4 个专家, 所有 token 都去了专家 1, $f = (1, 0, 0, 0)$, 路由器平均概率 $P = (0.7, 0.1, 0.1, 0.1)$. $\sum_i f_i P_i = 0.7$, 乘 $N = 4$ 得 2.8, 是均匀时的 2.8 倍.

更有意思的是梯度方向. 损失对 $P_i$ 的偏导是 $\alpha N f_i$. 专家 1 分到了全部 token, $f_1 = 1$, 它的概率被使劲往下压; 其余专家 $f_i = 0$, 这一项对它们不施加压力, 但 softmax 的归一化会把压下去的概率分给它们. 分得越多的专家挨罚越重, 负反馈直接写在梯度里.

$\alpha$ 从 $10^{-1}$ 扫到 $10^{-5}$, 论文最终全程用 $10^{-2}$: 足够大, 能很快把负载拉平; 足够小, 不干扰主任务的交叉熵.

### 三个稳定性技巧

稀疏模型比稠密 Transformer 难训. 路由是硬切换, bf16 这类低精度格式又会放大 softmax 的数值问题. 论文给了三招.

第一招是选择性精度. GShard 为了稳定全程 float32, 代价是速度和通信量. Switch 只在路由器函数内部把输入转成 float32, 算完 dispatch 和 combine 张量后再转回 bf16. float32 只存在于单台设备的本地计算里, 不会被 all-to-all 广播出去.

| 精度 | 质量 (负对数困惑度) | 每秒样本数 |
|---|---|---|
| float32 | -1.718 | 1160 |
| bfloat16 | -3.780 (发散) | 1390 |
| 选择性精度 | -1.716 | 1390 |

纯 bf16 快但发散, 纯 float32 稳但慢 17%. 选择性精度拿到了 float32 的质量和 bf16 的速度. 论文说这是第一次用 bf16 训出大型稀疏模型.

第二招是缩小初始化. 权重从截断正态分布采样, 均值 0, 标准差 $\sqrt{s/n}$, $n$ 是扇入, 默认 $s = 1.0$. 论文建议把 $s$ 缩小到十分之一. 32 个专家的模型训 3500 步, 三个随机种子:

| 初始化尺度 | 平均质量 | 质量标准差 |
|---|---|---|
| 0.1 倍 | -2.72 | 0.01 |
| 1.0 倍 | -3.60 | 0.68 |

质量更好, 方差从 0.68 降到 0.01. 同一套初始化从 2.23 亿参数的基线一直用到万亿参数模型.

第三招是专家 dropout, 管的是微调. Switch 的参数远多于 FLOP 对齐的稠密模型, 在小数据下游任务上更容易过拟合. 全局加大 dropout 反而变差; 非专家层保持 0.1, 只把专家 FFN 内部的 dropout 提到 0.4, 四个下游任务都有提升, GLUE 从 84.7 到 85.2.

## 扩展性: 按步数和按时间

扩展实验在 C4 上预训练, 目标是掩码语言模型: 丢掉 15% 的 token, 用哨兵 token 替换, 让模型预测. 为了不被数据卡住, 用了 1800 亿以上目标 token 的 C4, 训到回报递减.

专家数是最省钱的扩展维度. 每个 token 只选一个专家, 专家再多, 单 token 的计算也几乎不变; 路由器要多算一个 $d_{model} \times N$ 的矩阵乘, 相对 FFN 很轻.

按步数看, 从 2.23 亿参数的 T5-Base 出发, 专家数从 2 翻倍到 256 (147 亿参数), 每个 token 的 FLOPs 相同, 测试损失稳定下降. 64 专家的 Switch-Base 在第 6 万步就达到了 T5-Base 第 45 万步的质量, 按步数算快 7.5 倍.

按时间看, 稀疏模型有额外的通信和路由开销, 步数上的优势不一定转化为墙钟时间. 实测同样 32 个 TPUv3 核, 64 专家的 Switch-Base 用 T5-Base 七分之一的时间达到同样的困惑度, 而且还在继续变好.

再拿更大的稠密模型比. T5-Large 每个 token 的 FLOPs 是 Switch-Base 的 3.5 倍, Switch-Base 按样本效率仍然更好, 墙钟时间上快 2.5 倍. 把 Switch 也放大到和 T5-Large 同 FLOPs, 就是 Switch-Large.

### 下游: 微调, 蒸馏, 多语言

预训练收益要转化成下游能力才算数. 微调对照用 T5-Base (2.23 亿) 和 T5-Large (7.39 亿), 分别配 FLOP 对齐的 Switch-Base (70 亿) 和 Switch-Large (260 亿). 所有模型在改进过的 C4 上以每 batch $2^{20}$ 个 token 训 55 万步, 共 5760 亿 token.

| 任务 | T5-Base | Switch-Base | T5-Large | Switch-Large |
|---|---|---|---|---|
| GLUE | 84.3 | 86.7 | 87.8 | 88.5 |
| SuperGLUE | 75.1 | 79.5 | 82.7 | 84.7 |
| Winogrande (XL) | 66.6 | 73.3 | 79.1 | 83.0 |
| 闭卷 TriviaQA | 24.5 | 30.7 | 29.5 | 36.9 |
| ARC Challenge | 35.5 | 32.8 | 35.5 | 35.5 |

SuperGLUE 分别涨 4.4 和 2.0 个点, Winogrande 和闭卷 TriviaQA 涨得更多. 唯一没涨的是 ARC 推理题, Base 档在 Challenge 集上输了, Large 档在 Easy 集上输了. 知识类任务收益最大, 这和「参数存知识」的直觉一致.

万亿参数模型没法部署, 所以论文测了蒸馏. 用教师的非专家权重初始化学生, 再用 0.25 教师概率 + 0.75 真实标签的混合损失. 38 亿参数的 Switch-Base 蒸馏进 2.23 亿的 T5-Base, 保留约 30% 的质量提升, 参数只剩约二十分之一. 压缩 99% 时 (147 亿 → 2.23 亿) 仍保留 28%.

多语言实验在 mC4 的 101 种语言上预训练 100 万步. FLOP 对齐的 mSwitch-Base 在全部 101 种语言上都超过 mT5-Base, 平均按步数快 5 倍, 91% 的语言快 4 倍以上.

### 万亿参数: Switch-XXL 与 Switch-C

最终是把规模推上去. 论文设计了两个大模型, 和 T5-XXL (110 亿参数) 比.

| 模型 | 参数 | 每序列 FLOPs | 专家数 | 层数 | 25 万步质量 | 50 万步质量 |
|---|---|---|---|---|---|---|
| T5-XXL | 11B | 6.3T | — | 24 | -1.147 | -1.095 |
| Switch-XXL | 395B | 6.3T | 64 | 24 | -1.086 | -1.008 |
| Switch-C | 1571B | 890B | 2048 | 15 | -1.096 | -1.043 |

Switch-XXL 和 T5-XXL 每序列 FLOPs 相同, 参数多 36 倍, 需要专家并行, 模型并行和数据并行三者组合. Switch-C 走另一个极端: 只用专家并行, 不用模型并行, 所以宽度, 深度, 头数都比 T5-XXL 小很多 ($d_{model} = 2080$, 15 层, 每层都是专家层), 2048 个专家堆出 1.6 万亿参数, 每序列 FLOPs 只有 T5-XXL 的七分之一.

结果是 Switch-C 达到固定困惑度的速度是 T5-XXL 的 4 倍. 25 万步时两个 Switch 模型都比 T5-XXL 高出 0.061 以上, 作为参照, T5-XXL 再训 25 万步也只涨了 0.052. 论文补了一句, 这个差距是下界: T5-XXL 用的旧版 C4 里有重复片段, 更容易拟合.

稳定性在这里出现了分化. 1.6T 参数, 2048 专家的 Switch-C 完全没有不稳定. 反倒是 FLOPs 大 10 倍的 Switch-XXL 偶尔会不稳, 所以没训满 100 万步. 不稳定和参数量关系不大, 和每个 token 的计算量关系更大.

下游有个奇怪的反差. 上游困惑度相近, Switch-C 在 SQuAD 上只有 87.7, 参数少 4 倍的 Switch-XXL 有 89.6. 差别是 Switch-XXL 每个 token 的 FLOPs 约是 Switch-C 的 10 倍. 论文的原话是: 微调质量, 每 token FLOPs 和参数量之间存在一种理解很少的依赖关系. 参数能存知识, 但推理题似乎还要计算量.

知识类任务上 Switch-XXL 表现好. 只预训练了 5030 亿 token (T5-XXL 的一半左右) 的检查点, 闭卷 Natural Questions 34.4 (此前最好 32.8), WebQuestions 41.0 (37.2), TriviaQA 47.5 (42.9). 但 SuperGLUE 测试集 87.5, 还不如 T5-XXL 的 89.3.

### 局限

Switch Transformer 也并非万能的, 论文最终一节自己列了不少.

第一, 最大模型的稳定性没解决. 三个稳定性技巧对 Switch-Base, Switch-Large, Switch-C 都有效, 对 Switch-XXL 不够. 论文提到正则化和改造的梯度裁剪, 结论是「仍未解决」.

第二, 上游好不等于下游好. Switch-XXL 上游困惑度是 SOTA, 下游只部分转化; Switch-C 参数最多, SQuAD 反而更低. 稀疏模型的微调还需要单独研究.

第三, 显存和部署. 1.6T 参数要全部驻留在某处, 蒸馏只能保住三成收益. 服务一个稀疏大模型需要专门的调度和分片.

第四, 丢 token 是一种隐性损失. 容量因子接近 1 时, 负载稍有波动就会丢 token, 这些 token 在该层等于没算. 丢弃率低于 1% 依赖辅助损失系数够大, 而系数大了又会和主任务拉扯.

第五, 硬件为稠密矩阵乘设计. 论文开头就承认, 当时的库和加速器都偏向稠密计算, Switch 是在这个约束下的妥协: 用静态容量换可编译, 用专家并行换效率.

第六, 专家只放在 FFN 里. 论文试过把专家放进自注意力的 Q, K, V 投影, 有初步收益, 但 bf16 下不稳定, 只能留作后续工作.

### 后续: top-1 并没有一统江湖

Switch 之后, 稀疏模型迅速变多, 但路由的具体选择并没有收敛到 top-1.

2021 年的 GLaM 用 64 个专家, top-2, 做到 1.2 万亿参数. 2022 年 Zoph 等人的 ST-MoE 回头系统研究稳定性, 提出 router z-loss 惩罚过大的路由 logits, 用 top-2 做出了可迁移的稀疏模型. 2023 年底的 Mixtral 8x7B 也是 8 选 2.

Switch 真正留下的, 是一组被反复沿用的工程约定: 固定容量加容量因子, 单一的 $\alpha N \sum f_i P_i$ 辅助损失, 路由器局部高精度, 小初始化, 专家层隔层放. 后来的 MoE 大多在这套约定上做加减法, DeepSeek 系列则进一步把辅助损失换成了可调偏置.

「参数量是独立于计算量的扩展轴」这个假设, 也被后续工作普遍接受. 今天说一个 MoE 模型「总参数多少, 激活参数多少」, 用的就是 Switch 这篇论文确立的语言.

## 从通用 MoE 层到 Transformer 预训练

路线 `2.2.1` [Sparsely-Gated MoE](3.2.1-sparsely-gated-moe.md) 回答稀疏激活能不能跑, 这一篇回答能不能跑得简单, 跑进 Transformer 预训练. 两篇连起来, 条件计算从 LSTM 夹层走到了万亿参数.

它和路线 `1.6.4` [Scaling Laws](../../2-sutskever阅读清单/2.6-训练规模与生成/2.6.4-scaling-laws/2.6.4-scaling-laws.md) 是一对: Kaplan 说损失随参数按幂律降, Switch 说参数可以在计算不变的前提下单独涨. 它的并行设计则站在路线 `1.6.2` [GPipe](../../2-sutskever阅读清单/2.6-训练规模与生成/2.6.2-gpipe/2.6.2-gpipe.md) 这类工作之后, 把数据并行, 模型并行之外的第三个维度 (专家并行) 做成了标准件. 底座是路线 `1.4.2` [Transformer](../../2-sutskever阅读清单/2.4-attention与transformer/2.4.2-transformer.md): Switch 层替换的就是其中的 FFN.

这篇论文沿着 2017 年方案做系统简化:top-2 改为 top-1,两项均衡目标合成一项,FP32 只保留在路由器局部.每项改动都有对应实验,目标是减少大规模 Transformer 预训练中的通信,数值和实现负担.

### 手算一次 top-1 路由

设四个 token 对三个专家的路由概率分别为 $(0.7,0.2,0.1)$,$(0.6,0.3,0.1)$,$(0.1,0.8,0.1)$,$(0.2,0.2,0.6)$.top-1 选择结果为专家 1 接收两个 token,专家 2 和 3 各接收一个.实际 token 比例 $f=(0.5,0.25,0.25)$,平均路由概率 $P=(0.4,0.375,0.225)$.论文的辅助损失为

$$\alpha N\sum_i f_iP_i=\alpha\cdot3\cdot(0.5\times0.4+0.25\times0.375+0.25\times0.225).$$

若所有 token 都挤向同一专家,$f$ 和 $P$ 会同时集中,损失增大.该项用 batch 统计引导均衡,不会强制每个 token 的路由概率均匀.主损失仍可以让不同 token 偏好不同专家.

### 容量与 token dropping

设 batch 有 12 个 token,3 个专家,capacity factor 为 1.0,每个专家容量为 4.若路由分布为 $(7,3,2)$,专家 1 超出的 3 个 token 无法进入其 FFN.Switch 保留残差路径,这些 token 仍能通过层,但少了一次专家变换.增大 capacity factor 到 1.5 后容量变成 6,仍有 1 个溢出,同时所有专家缓冲区都要按 6 预留.

训练报告中的 dropped-token rate 因而要和 capacity factor 一起看.更强的负载损失,更大的 batch 或二次路由都能降低溢出,代价分别是可能干扰专业化,增加内存,或增加通信与计算.论文选择 top-1 和固定容量,是在 TPU 静态形状约束下做出的系统权衡.

### 为什么路由器保留 FP32

专家 FFN 的大矩阵乘适合低精度,路由器输出却直接经过 softmax 与 argmax.当 logits 很接近时,舍入可能改变专家选择;当绝对值很大时,低精度 exp 又可能溢出或让分布过尖.Switch 使用 selective precision:输入先转为 FP32 计算路由,得到分派后,专家主体仍按 bfloat16 执行.额外成本只占很小部分.

这一做法不能单独解决所有不稳定.初始化尺度决定早期 logits 分布,辅助损失决定负载,capacity 决定溢出,学习率与专家数据量决定各专家更新质量.排查训练时应同时记录 router logits 范围,熵,每专家 token 数,溢出率和梯度范数.

## 速度数字如何解读

稀疏模型的理论专家 FLOPs 接近单个 FFN,实际 step time 还包含两次 token 重排与设备通信.同一模型在训练 batch 较大时容易形成饱满 GEMM,在线推理 batch 小时专家输入会碎片化.论文在 TPU 上的速度优势证明其特定布局有效,迁移到不同网络拓扑与 kernel 时需要重新测量.

质量比较也有三种口径.固定 FLOPs 可检验稀疏参数的统计收益;固定总参数可比较显存占用;固定 wall-clock 可把通信和利用率包含进来.只写「1.6T 参数」强调容量,不能说明每 token 成本或服务延迟.现代模型常同时给 total parameters 和 active parameters,仍需补充序列长度,batch 与硬件.

### 从 Switch 继续往后读

top-1 路由降低混合冗余,后续 GLaM,ST-MoE 和 Mixtral 又采用 top-2,说明路由选择仍取决于质量与系统目标.共享专家保证每个 token 都经过一条公共路径,细粒度专家把 FFN 拆得更小,无辅助损失方法尝试用偏置直接调节负载.这些变化都可以回到同一数据流检查:如何选专家,每个 token 激活多少参数,容量如何分配,token 在设备间怎样移动.

Switch 的长期作用是把 MoE 变成可重复的 Transformer 层设计,并给出稳定训练的成套基线.新方法若声称改进路由,至少应与相同激活 FLOPs,相近训练 token 和明确容量设置下的 Switch 基线比较;若声称加速,还需报告 all-to-all 时间和端到端吞吐.

### 训练日志应该留下什么

每一步至少记录主损失,辅助负载损失,路由熵,每个专家接收 token 数和 dropped-token rate.按层统计比全模型平均更有用:早期层可能按词形分工,深层按语义分工,某一层的拥塞会被全局平均掩盖.还应记录 all-to-all 时间占 step time 的比例,否则无法判断瓶颈来自路由学习还是网络通信.

出现损失尖峰时,先对齐时间轴.若尖峰伴随 router logits 绝对值增大和熵骤降,检查学习率,路由精度与 z-loss;若负载集中但 logits 正常,检查数据 batch 的相关性与均衡系数;若负载均匀而吞吐下降,检查 token 排列,GEMM 尺寸和网络拥塞.专家梯度为零则可能是长期未被选中或容量裁剪.

checkpoint 还应保存路由器与专家参数的完整分片映射.恢复训练若改变专家到设备的分配,通信布局和随机噪声可能变化,需要验证输出一致性.做专家增删或合并时,优化器状态也要相应迁移,仅复制权重会改变后续训练轨迹.

### 专家是否真的专门化

可以按语言,领域,token 位置或词类统计路由互信息,也可以给同一 token 换上下文观察专家选择.稳定的专门化应在多个 batch 和随机种子下重复出现,并在干预专家后引起相应能力变化.只展示几个专家的高频 token,很容易被词频与采样噪声误导.

即使没有人类可命名的分工,MoE 仍可能有效.专家可以在高维特征上划分计算区域,这种划分未必对应语言或主题标签.评价标准第一步是固定资源下的质量与效率,可解释路由属于额外分析.反过来,看起来整齐的专家标签也不能证明模型利用了更好的计算分配.

### 推理阶段的额外约束

自回归 decode 每步 token 数少,专家并行容易形成小矩阵,all-to-all 延迟也难以摊薄.服务系统常通过请求批处理,expert parallel 组缩小,专家复制或热门专家缓存改善利用率.这些方案会增加显存或调度复杂度,并可能受动态流量影响.

容量在推理中仍然存在,但处理方式可以与训练不同.批量较小时可使用动态 shape 避免 token dropping,代价是 kernel 与编译更复杂;高吞吐离线推理则可继续用固定容量.报告服务结果时应给 batch,输入输出长度,并发数和延迟分位点,不能直接沿用训练 tokens/s.
