# 复杂度、信息论与智能

这组论文从 Kolmogorov 复杂度出发,建立**「结构 = 可压缩性」**的语言。为什么 Ilya 把这些放在清单里?因为**「学习 = 压缩」是理解 LLM 的一个底层视角**——一个模型能把训练数据压缩得越短,它对数据结构的理解就越深。Shannon 熵度量随机性,Kolmogorov 复杂度度量生成一个对象所需的最短程序,MDL 把二者拉进模型选择框架。这三个工具贯穿后续所有章节。

这一组先建立后续文章反复使用的语言:什么是结构,什么是随机,什么叫压缩,以及这些概念怎样进入学习与智能的定义.编号是本站教学顺序,不是社区重建版本的原始排列.

## 从熵到描述长度

Shannon 熵回答的是「已知概率分布以后,平均至少需要多少 bit 编码一次采样」.若硬币正反面等概率,单次结果需要 1 bit;若正面概率接近 1,平均码长可以更短.这里的对象是分布及其平均行为.算法信息论换了问题:只给定一个具体字符串 $x$,生成它的最短程序有多长?这个长度记作 $K(x)$.规律明显的字符串能由短程序生成,随机字符串通常只能逐位写出.两种复杂度都使用 bit,但一个依赖给定分布,另一个依赖通用计算模型且不可计算.

「结构」和「随机」因此不能只凭视觉判断.重复串看起来整齐,有短生成程序;真正随机的串没有可压缩规律.麻烦在于,纯重复和纯随机都不符合日常所说的复杂对象:前者太规则,后者没有可利用结构.Aaronson 的 complexodynamics 博文引入 sophistication,试图把对象拆成一个可描述的模型和模型内部的随机索引.复杂度最高的区域可能出现在二者同时存在时,这也解释了咖啡与牛奶混合过程为何常呈现先升后降的直觉曲线.

## 从不可计算定义到可运行实验

Kolmogorov complexity 不能由通用算法精确计算,否则可以构造类似 Berry paradox 的矛盾.论文若要画复杂度曲线,就必须选择代理量.Coffee Automaton 使用压缩器估计描述长度,同时讨论熵,sophistication 和统计复杂度等候选定义.压缩后的文件较短可以证明存在较短描述,压不短却不能证明对象随机:也可能只是压缩器没有识别相应规律.实验曲线由此只提供上界和相对比较,不能冒充不可计算量的精确测量.

这种限制在机器学习里很常见.训练损失,验证损失和压缩率都是可计算代理,各自只覆盖目标的一部分.读后面的论文时要反复问两个问题:作者真正想研究的量是什么,实验实际测到的又是什么.二者之间的缺口决定结论能走多远.

## MDL 怎样进入学习

Minimum Description Length 把模型选择写成两部分:描述模型本身需要多少 bit,给定模型后描述数据残差还需要多少 bit.模型太简单,第一部分短而残差很长;模型太灵活,残差可能变短,模型描述却变贵.好的选择让总码长最短.这一形式把拟合与复杂度惩罚放进同一单位,也能导出参数模型中的 NML,regret 和 parametric complexity.

神经网络训练不会直接搜索所有程序,但负对数似然已经是码长.若模型给正确 token 的概率为 $p$,该 token 的理想码长就是 $-\log_2p$.交叉熵降低意味着平均编码长度降低.Hinton 与 van Camp 随后把权重分布的描述长度也放入目标,形成数据项加权重项的两段码.这里可以看见信息论怎样从解释框架变成可微训练目标,也能看见边界:可训练的变分上界不等于真正的最短程序.

## 从环境加权到智能定义

Machine Super Intelligence 把智能定义为智能体在一组可计算环境上的期望表现,复杂环境按 $2^{-K(\mu)}$ 获得较小权重.这一写法把「广泛环境中的目标达成能力」变成一个数学量,但 AIXI 依赖不可计算的 Solomonoff induction.其价值主要在于划清理论边界:没有先验知识的智能体不可能在所有环境里立即最优,可计算近似也受探索速度和资源限制.

五项材料连起来形成三条线.第一条研究复杂度如何随动力学变化;第二条研究描述长度怎样指导模型选择;第三条研究算法概率能否定义随机性和智能.它们共享最短描述这把尺子,却处理不同对象.阅读时把「分布熵」「具体对象的程序长度」「模型与残差的总码长」「环境先验权重」分别记清,后面看到「压缩即学习」时才不会把几种结论混成一句口号.

## 一个可复算的最小例子

设有 100 次抛硬币结果,模型 A 只允许公平硬币,模型 B 可以为正面概率 $p$ 编码一个参数.若数据恰好 50 正 50 反,A 的数据码长约 100 bit,B 即使把 $p$ 拟合为 0.5,还要额外支付参数描述长度,总码长更长.若数据为 95 正 5 反,A 仍需约 100 bit,B 的数据码长降为 $-95\log_2 0.95-5\log_2 0.05\approx28.6$ bit,只要参数编码少于约 71 bit,B 就更合算.这个例子把 MDL 的权衡变成可检查数字:复杂模型必须用残差码长的下降偿还自身描述成本.

同一数据也能说明熵与 Kolmogorov complexity 的区别.经验熵按正反比例计算,不关心 95 个正面出现在什么位置;具体字符串的程序长度却会区分「前 95 个全正,后 5 个全反」与随机散布的排列.前者可能由短规则生成,后者通常需要额外索引.因此分布统计相同不代表单个对象的算法结构相同.

## 结论边界

「能压缩」只表示编码器捕获了某些规律,不保证这些规律对目标任务有用.训练集压得很短也可能来自记住样本,所以模型描述长度必须计入;语言模型交叉熵较低也不自动等于推理能力更强,因为评测分布和交互目标不同.算法复杂度又依赖通用机选择的常数项,只在对象足够长或比较具有渐近意义时较稳定.

这一组提供的价值是一套提问方式:研究对象是什么,概率分布是否已知,编码器是否可计算,模型成本有没有计入,结论针对平均样本还是某个具体对象.这些问题会在正则化,生成模型,规模律和贝叶斯推断中反复出现.

还有一条容易忽略的界线:压缩器给出的只是某种编码方案的长度,Kolmogorov complexity 则对所有程序取最短值.前者能运行和比较,后者用于定义与证明.论文从后者获得方向,实验必须回到前者,两者之间永远隔着近似假设.
