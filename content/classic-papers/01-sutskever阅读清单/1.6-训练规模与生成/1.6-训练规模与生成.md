# 训练、规模与生成

这组论文回答**「怎么把模型做大」**和**「做大之后会怎样」**。GPipe 用微批流水线解决了模型并行的内存瓶颈,Scaling Laws 告诉你参数量、数据量和计算量之间存在幂律关系——给定预算应该怎么分配,Deep Speech 2 示范了从特征到输出的端到端直通管线。MDL Weights 和 VLAE 则从正则化和生成模型的角度补全「怎么约束」和「怎么学表示」这两个子问题。

这一组把模型如何约束,如何训大,规模收益怎样量化,以及生成模型如何学习表示放在一起.它是本站路线的收束,不代表社区重建书目的末尾顺序.

## 参数多了以后,正则化要回答什么

Hinton 与 van Camp 1993 年把神经网络权重从点估计改成概率分布.训练目标包含数据残差的描述长度,以及后验权重分布相对先验的 KL.均值决定常规预测,方差表示权重允许多大扰动;输出对某个权重越不敏感,该权重可以使用更宽的后验,编码代价也更低.这已经包含后来变分贝叶斯神经网络的主要结构.

描述长度视角提醒我们,参数个数不是模型复杂度的唯一代理.同样数量的权重,若能低精度表示或集中在少数混合分量附近,有效码长会不同.实际训练仍需选择先验族,后验近似和退火日程,对角高斯也忽略参数相关性.因此该工作提供可优化的复杂度项,并没有解决所有泛化问题.

## 单卡装不下时怎样切模型

GPipe 按层把网络切成多个连续 cell,每个设备保存一段参数.一个大 batch 再拆成多个 micro-batch,前向像流水线一样依次经过各 cell,反向按相反方向传播.微批数 $M$ 增加后,首尾填充造成的 bubble 占比下降;切分不均衡时,最慢 cell 决定整个流水线周期.

同步更新保证所有 micro-batch 使用同一版本权重,语义更接近普通数据并行.激活重计算只保存分区边界,反向时重新计算分区内部激活,用额外 FLOPs 换显存.这三项分别处理设备放置,流水线利用率和激活内存.通信量,拓扑,分区平衡和 batch size 约束仍需单独考虑,不能只凭可训练参数规模判断系统效率.

## 端到端系统仍然包含大量工程

Deep Speech 2 用卷积,双向循环网络,CTC 和语言模型解码统一语音识别主干.CTC 对所有能折叠成目标文本的帧级对齐求和,避免逐帧标注;卷积处理局部时频模式;深层 RNN 建模上下文.所谓端到端主要指声学特征到字符概率的可微训练,数据清洗,增强,分布式优化和解码器依然构成完整系统.

论文同时分析算法改动和系统吞吐:大规模语料,排序后的 mini-batch,多 GPU all-reduce,自定义内核和数值稳定共同决定最终结果.规模化训练需要数据,优化,通信和评测口径协同,简单增加设备无法保证等比例收益.

## 规模律怎样分配预算

Kaplan 等人观察到测试损失对非 embedding 参数量 $N$,数据量 $D$ 和计算量 $C$ 在一定区间内近似幂律.当其中一个资源不足,继续增加另一个资源会进入瓶颈.拟合曲线可用于估算固定计算预算下模型和数据的分配,但指数来自指定数据,架构和训练配置,外推到远离观测范围的位置存在风险.

后来的 Chinchilla 结果改变了计算最优的参数与 token 配比,说明经验规模律会随实验设计和估计方法修正.正确用法是记录拟合范围,损失定义,训练 token,参数口径和置信区间,再把曲线用于同类系统的预算决策.它描述平均趋势,不能预测某项新架构或数据改进一定带来多少收益.

## 生成目标如何决定潜变量学什么

VAE 的 ELBO 包含重构项和 $q(z|x)$ 相对先验的 KL.当解码器足够强,它可以仅凭此前像素或 token 建模局部结构,最省码长的选择可能是让 $q(z|x)$ 回到先验,从而忽略潜变量.VLAE 限制自回归解码器的局部感受野,迫使全局结构经过 $z$ 传递.生成模型由此成为表示学习实验:通过限制信息通路,控制不同尺度信息存放在哪里.

五篇材料覆盖三个互相牵制的量:模型容量,训练资源和信息分配.MDL Weights 与 VLAE 讨论参数或潜变量承载多少信息;GPipe 与 Deep Speech 2 讨论这些计算如何在硬件上执行;Scaling Laws 讨论资源增加后的经验收益.读完整组后,面对「把模型做大」这一说法,应继续追问参数是否激活,数据是否充足,训练计算如何分配,通信和显存是否成为瓶颈,以及目标函数鼓励模型把信息放在哪里.

## 一张统一的资源表

比较这些工作时可以列六列:总参数,每样本激活参数,训练 token 或样本数,前向与反向 FLOPs,峰值显存,设备间通信.GPipe 主要改变参数和激活怎样分设备,并用重计算交换显存与 FLOPs;Scaling Laws 连接训练计算与损失;MDL Weights 给参数信息量定价;VLAE 给潜变量与残差分配码长.Deep Speech 2 则展示数据清洗和系统吞吐如何决定可用规模.

同一个「更大」会落在不同列.增加未激活专家提高总参数却未必同比提高 FLOPs;增加上下文长度主要推高激活和注意力计算;增加 batch 可以改善设备利用率,也可能改变优化和泛化.若不先说明增长的是哪一项,规模讨论很容易把系统容量,统计效率和硬件效率混为一谈.

## 从单步公式到训练总成本

单次前向 FLOPs 只是训练成本的一部分.反向通常还要计算激活梯度和权重梯度,优化器保存动量或方差状态,数据管线要持续供给设备,失败恢复需要 checkpoint.流水线 bubble,数据并行同步和张量并行通信都会让实际吞吐低于理论峰值.论文给出的 wall-clock 结果必须连同硬件数量,精度格式和利用率解释.

规模律把总计算预算作为统计自变量,系统论文则负责让给定设备真正执行这些计算.两类结论要在 token 数和有效 FLOPs 上对接:若通信使设备长期空闲,名义 GPU 数不会自动变成更多训练计算;若数据重复或质量变化,相同 token 数也不代表同等监督信息.

## 生成与压缩的共同单位

交叉熵可以换算成每 token bit 数,ELBO 也可以解释为期望码长上界.这让语言建模,有损生成和 MDL 正则拥有共同单位,但编码方案与概率模型必须明确.较低码长表示模型对评测分布给出更高概率,不保证样本符合所有人类偏好;潜变量携带更多信息也不保证信息对下游任务有用.统一单位方便比较,无法代替任务定义.
