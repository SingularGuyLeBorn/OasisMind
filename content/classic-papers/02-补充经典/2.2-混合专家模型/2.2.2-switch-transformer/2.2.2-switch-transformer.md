# MoE 经典（二）深度精读：《Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity》

> 原始论文：William Fedus, Barret Zoph, Noam Shazeer（Google Brain），[arXiv:2101.03961](https://arxiv.org/abs/2101.03961)（2021；JMLR 2022）。整理日：2026-08-24。

## 一、问题与动机

Shazeer 2017 证明了稀疏 MoE 可行，但**没有被大规模采用**，卡在四个障碍：
1. **路由复杂**：noisy top-k + 辅助损失，超参多、难调
2. **通信成本**：all-to-all 跨设备通信是性能瓶颈
3. **训练不稳定**：稀疏激活 + 大模型 = 数值不稳，此前只能用高精度训练
4. **实现复杂**：定制 kernel、负载均衡逻辑，工程门槛高

目标：把 MoE **简化到能大规模预训练**，并且压过同等预算的密集模型（T5 系列）。

## 二、方法：Switch 路由（Top-1 稀疏门控）

### 核心简化
Shazeer 2017 是"每个 token 选 top-k 个专家"（k 通常 2），Switch 改成**每个 token 只路由到 1 个专家（top-1）**：

$$y = \sum_{i=1}^{N} p_i(x) \cdot E_i(x), \quad p(x) = \mathrm{softmax}(x \cdot W_g), \quad \text{路由到 } \arg\max_i p_i(x)$$

- 相比 top-2：门控矩阵乘法计算量**减半以上**（少一次专家前向 + 少一路 softmax）
- 专家负载更天然均衡、显存更高效（每个 token 只有一份专家激活）
- 代码实现大幅简化——MoE 第一次"不别扭"

### 辅助负载均衡损失（aux loss）
单纯 top-1 仍会塌缩到少数专家，论文沿用并形式化了辅助损失（论文式 2）：

$$L_{\mathrm{aux}} = \alpha \cdot N \sum_{i=1}^{N} f_i \cdot P_i$$

- $f_i$：该 batch 中被路由到专家 i 的 token 比例（load）
- $P_i$：门控给专家 i 的平均路由概率
- $N$ 为专家数，$\alpha$ 为系数（通常取 0.01）
- 乘积形式让"被选得多"和"概率给得高"互相惩罚，鼓励均匀

### 其他工程细节
- **expert capacity**：每个专家每个 batch 处理的 token 上限，超出部分走残差连接（近似 dropout 效果），防止单个专家过载
- **bfloat16 低精度训练**：首次证明大稀疏模型可低精度训练（此前认为稀疏+不稳定必用 fp32）

## 三、实验与数字

| 模型 | 规模 | 结果 |
|---|---|---|
| Switch-Base（7B，基于 T5-Base） | 7B 参数 | 同 FLOPs 下比 T5-Base **快 7 倍**预训练 |
| Switch-Large（26B，基于 T5-Large） | 26B | 同上，7 倍加速 |
| Switch-C（1.6T） | **1.6T 参数** | 当时最大稀疏模型，C4 语料上比 T5-XXL **快 4 倍** |
| mT5 多语言（Switch-Base） | 7B | **101 种语言全部**超过密集 mT5-Base |

- 30+ 个 NLP 任务（GLUE/SuperGLUE 等）上，同计算预算下超过密集 T5 基线
- 关键规律：**参数量与计算量解耦**——模型参数越多，稀疏相对密集的优势越大

## 四、为什么是经典

1. **把 MoE 变成预训练主流标准组件**：top-1 路由 + aux loss 的配方，后来被几乎所有稀疏 LLM（Mixtral、DeepSeek-MoE、GPT-4 推测架构）沿用
2. **确立稀疏激活扩展范式**：参数可以远超训练 FLOPs——"假装小、其实大"的公开先例
3. **与 Scaling Laws 互补**：Kaplan 2020 说"参数和计算一起涨"，Switch 说"参数可以单独涨、计算保持"——共同定义 2020s 的算力经济学
4. **工程遗产**：bfloat16 稀疏训练、expert capacity、分布式实现（mesh-tensorflow）都是后续稀疏 LLM 的参考实现

## 五、局限

- **显存需求**：所有专家参数必须驻留内存（1.6T 参数意味着巨大的单机显存或复杂分片）
- **辅助损失与主目标拉扯**：aux loss 系数调大保均衡、调小保性能，仍有张力
- **专家利用率**：top-1 下部分专家仍可能长期闲置（dead experts）
- 下游推理/部署复杂度：服务一个 1.6T 稀疏模型仍需专门的调度

## 六、后续谱系（2021 → 2026）

Switch → **GShard**（分片 + 负载均衡细化）→ **GLaM**（1.2T、效率优先）→ **Mixtral 8x7B**（开源 8 专家，社区可跑）→ **DeepSeek-MoE**（细粒度专家 + 共享专家 + 无辅助损失路由）→ 各厂混合架构（部分稠密 + 部分 MoE）成为 2025-2026 前沿模型默认配置。
