# LLaDA-MoE:从头训的稀疏掩码扩散

LLaDA-MoE (Zhu 等人,arXiv:2509.24389) 研究一个具体问题:**掩码扩散能否使用较大的专家参数池, 同时让每个 token 只执行其中一部分计算?** 稠密 Transformer 在每个位置执行同一套 FFN;MoE 让路由器依据隐藏状态选择专家, 再加权合并输出. 这种稀疏计算已用于自回归模型, LLaDA-MoE 将它放进从零训练的双向去噪网络.

模型有 7B 非嵌入参数, 每个 token 在各层从 64 个专家中选择 8 个, 整模型每 token 激活约 1.4B 参数. 前向掩码与 $1/t$ 加权 MLM 沿用吸收态建模, 主要架构变化在 FFN. 因而需要同时理解两条计算链:网络如何通过专家恢复被掩码内容, 采样器又如何用这些预测逐步生成文本. LLaDA 2.0 则从已有 AR 权重开始改编, 与这里从零学习去噪网络的训练起点不同.

## 1. 稀疏的是 FFN,不是扩散过程

网络采用 Transformer 子层结构, 注意力全双向. Table 2 给出 16 层、隐藏维度 2048、16 个注意力头、64 个专家和 Top-8 路由, 专家中间维度 1024, RoPE base 为 50,000. 归一化使用 RMSNorm, 专家使用 SwiGLU, 注意力中加入 QK-LayerNorm. Table 2 的每 token 激活参数为 1.4B;主表使用简写 1B. Figure 2 展示 Top-2 路由示意, 实际模型配置为 Top-8.

![LLaDA-MoE 的逐层残差计算、专家路由与不同 token 门控手算](../images/fig-llada-moe-routing-v7.png)

> 图 1:逐层计算与专家路由,依据 [LLaDA-MoE v1 Figure 2、Table 2 与式 (3)](https://arxiv.org/html/2509.24389v1#S3.SS2), 专家内部双分支参考 [SwiGLU](https://arxiv.org/abs/2002.05202). 实际模型每层从 64 个专家中选 8 个;右侧四专家选二、四位置输入与概率条形为教学示例.中央虚线表示 MoE 局部展开,不表示额外数据输入.非嵌入参数 7B 与每 token 激活约 1.4B 是整模型规格.

先跟随一个位置的隐状态:双向注意力输出与子层输入相加,归一化后送入 MoE.路由器输出选中专家的索引和权重,索引控制隐状态分发,权重用于专家输出求和.这个结果还要与 MoE 子层输入相加,才能进入下一层;完成全部层后才进入词表预测头.训练时位置 1、3 的预测分布与对应原文目标计算重构损失,可见位置 2、4 参与上下文计算但不承担这项损失.

右侧两个 token 选择不同专家,说明同批专家访问范围可能超过单 token 的八个.下一轮去噪重新计算状态时,各层路由也可能重新选择,图中循环箭头连接的是完整的下一轮计算,不是把上轮专家输出直接当作本轮结果.

### 1.1. 图 1 怎么读

- **$h_t$, $d=2048$**:比 LLaDA 8B 的 4096 窄,层数也从 32 收到 16.容量主要堆在专家库,不堆在每层都跑的注意力.
- **router Top-8 of 64**:每个位置根据该层隐状态选择 8 个专家.不同位置可以选择不同集合;去噪状态变化后,后续前向的路由也可能变化.
- **8 experts, dim 1024**:专家本身是窄 FFN,不是 8 份完整 7B.
- **weighted sum, 1.4B active**:未被该 token 选中的专家不处理这个 token,但仍可能处理同批其他位置.1.4B 是整模型每 token 的激活参数量,并非一次专家求和的参数量,也不代表整批只访问同一组 8 个专家.
- **mask predictor $p(x_0\mid x_t)$**:完成全部 Transformer 层后,预测头输出各位置的词表分布.图中单层专家求和与最终预测头之间还包括后续层计算及归一化.
- **$1/t$ MLM**:被 mask 位置的预测分布与原 token 共同决定重构损失,路由辅助损失另行加入训练目标.专家选择处理 FFN 计算,位置提交由采样器处理.

对一个 token 在某个 MoE 层的计算,记该层输入隐状态为 $h_t\in\mathbb R^{2048}$.线性路由器产生 64 维 logits,softmax 得到专家概率,Top-$k$ 选出其中最大的 $k=8$ 项.每个选中专家将隐状态映射到同维输出,再按对应门控概率求和.专家内部的 1024 是 FFN 中间维度,不是最终输出维度.[原论文 §3.2 式 (3)](https://arxiv.org/html/2509.24389v1#S3.SS2) 使用所选项原本的 softmax 权重,这里沿用这一写法:

$$
p_t=\mathrm{Softmax}(\mathrm{Router}(h_t)),\qquad
o_t=\sum_{i\in\mathrm{Top}k(p_t)} p_{t,i}\,E_i(h_t)
\tag{1}
$$

例如教学路由概率为 $(0.4,0.3,0.2,0.1)$,选 Top-2 后输出为 $0.4E_1(h)+0.3E_2(h)$,两个权重之和为 0.7.若把所选权重重新归一化,输出会变成 $(4/7)E_1(h)+(3/7)E_2(h)$,这是另一种门控规则.实际模型的 64 选 8 同理.其他 token 可选另一组专家,因此整批访问的专家集合是各 token 选择集合的并集.

**专家内部还有一道门控.** [SwiGLU](https://arxiv.org/abs/2002.05202) 将同一输入投影到两条中间分支, 用一条分支的 SiLU 激活逐元素调制另一条分支, 再投影回隐藏维度. 用列向量、略去偏置写作 $E_e(h)=W_{e,\mathrm{down}}[\operatorname{SiLU}(W_{e,\mathrm{gate}}h)\odot(W_{e,\mathrm{up}}h)]$. 两个输入投影的 shape 都是 $1024\times2048$, 输出投影为 $2048\times1024$. 因而输入与输出均为 2048 维, 中间乘法发生在 1024 维. SwiGLU 的门控发生在一个专家内部;路由概率则用于合并不同专家的输出, 两者处于不同计算层次.

路由训练另加两项辅助损失.负载均衡项为 $\mathcal L_{\mathrm{LB}}=N\sum_{j=1}^{N}f_jP_j$,其中 $N=64$,$f_j$ 是专家被选频率,$P_j$ 是各 token 分配给该专家的平均概率.Z-loss 对每个 token 的路由 logits $z$ 计算 $(\log\sum_j e^{z_j})^2$,再跨 token 平均;平方不能省掉.权重分别为 0.01 与 0.001.原论文 Figure 4 展示前 1T 训练 token 中两项辅助损失先下降再稳定的曲线,这是该训练设置的观测.

稀疏 FFN 减少每个 token 的专家计算,双向注意力仍参与每轮去噪.其他位置揭开后,已可见 token 的深层表示和 KV 也可能改变,所以专家稀疏本身不提供严格的跨步 KV 缓存.缓存需另外处理可见性与状态更新,详见[缓存与服务调度](../../6-推理加速与系统/6.3-缓存部署与服务/6.3.1-缓存与服务调度.md).

被 mask 与可见位置使用同一套专家参数.路由依赖该层隐状态,隐状态又包含双向注意力读取的上下文,所以改变 mask 集合可能改变专家选择.负载均衡项鼓励流量分散,Z-loss 约束路由 logits 的数值尺度;两者并不要求同一位置跨去噪轮次一直选择同一组专家.专家具体学到怎样的分工,需要结合路由统计与受控任务分析.

与 LLaDA 8B 的 32 层、隐藏维度 4096 相比, 这套网络使用 16 层与隐藏维度 2048, 同时在 FFN 中设置专家参数池. 64 选 8 表示每个 token 在该层执行 12.5% 的路由专家, 这个比例只适用于专家池, 不能用来计算整模型的激活比例. 注意力、归一化与输出头仍是共享计算.

## 2. 损失就是 8B 那条加权 MLM

前向:抽 $t\sim U[0,1]$,每个位置独立以概率 $t$ 变成掩码 $\mathbf{M}$.网络输出 $p_\theta(\cdot\mid y_t)$,交叉熵只落在被掩位置,再乘 $1/t$:

$$
\mathcal{L}_{\mathrm{Pretrain}}(\theta)
=-\mathbb{E}\Big[\frac{1}{t}\sum_{i=1}^{L}\mathbf{1}[y_t^i=\mathbf{M}]\log p_\theta(y^i\mid y_t)\Big]
\tag{2}
$$

式 (2) 的期望覆盖干净文本、均匀抽取的噪声水平及随机掩码. SFT 使用同一种恢复目标, 只掩码回答 $y$, 提示 $x$ 保持可见. 多轮对话抽取目标轮次 $\tau$, 上下文包含此前话轮与本轮用户输入, 预测目标为 $y_\tau$. 短回答用 `[EOS]` 补到批内最长回答, 填充结束符同样参与掩码与损失. 论文在 SFT 中限制样本为 4k, 以减少将短样本大量补到 8k 时结束符监督过多的风险.

预训练还通过少量变长样本缓解固定窗口与推理输入长度的差异:1% 的训练步在 $[8,4096]$ 中抽取长度并截断输入, 其余使用默认 4k. 生成评测采用长度 1024、块长 64 的半自回归设置;对其他已有 MDM, 论文直接引用已发表分数. 因此表中各模型分数并非全部来自这套统一采样设置.

一次训练前向先抽取 $t$ 并逐位置随机掩码, 再将受损序列送入网络. **每个 MoE 层**都根据该层的隐藏状态执行 Top-8 路由与专家加权, 完成全部层后由预测头输出各位置的词表分布. 主预测损失只选取掩码位置, 对原 token 计算交叉熵并乘 $1/t$, 再加入 LB loss 与 Z-loss. 可见位置参与上下文计算, 它们对其他位置预测的贡献仍可接收反向梯度. 路由器选择中间计算使用哪些专家, 采样器则决定生成时提交哪些位置.

生成从全 mask 回答 $\mathbf M^L$ 出发,已提交的词在原吸收态转移中保留.半自回归采样把回答分成 $K=L/B$ 个块,长度 1024、块长 64 对应 16 块;每块先预测尚未提交的位置,按候选置信度决定本轮写入哪些位置,其余仍留作 mask.当前块完成后进入下一块. **块间提交顺序与 attention 可见性是不同设置.** 本模型仍按全双向随机掩码目标训练,不能仅凭逐块提交推断其网络已采用 BD3-LM 的块因果训练结构,也不能直接据此复用前缀 KV.采样输入范围与缓存条件见[采样后验调度与重掩](../../2-数学与生成机制/2.3-生成因式分解与采样/2.3.2-采样后验调度与重掩.md).

## 3. 约 20T:两段混合,再退火,再扩窗

Figure 3 将训练分为五个阶段. 第一段预训练从零使用 10T token 的混合文本, 第二段在同一底库上提高数学和代码的采样权重, 再训练 10T. 随后从第二段平均评测指标最好的检查点开始, 使用 500B 高质量文本退火. 第二段退火接续上一段的最终检查点, 将 RoPE base 从 10,000 提到 50,000, 上下文从 4k 扩展到 8k, 再训练 500B. 最后用问答数据进行 SFT.

两段预训练合计约 20T, 两段退火另合计 1T. 这条路径先学习基础分布, 再调整数据配比与长上下文能力, 最后适配指令回答. 下表按训练起点与目标区分三种模型:

| | 8B 密 | MoE 7B-A1.4B | 2.0 mini/flash |
|---|---|---|---|
| 起点 | 从零 | 从零 | Ling AR MoE |
| 主预测目标与路径 | $1/t$ MLM | $1/t$ MLM,另加路由辅助损失 | AR 权重经 WSD 课程转为块扩散 |
| 数据阶段 | 约 2.3T 预训练 | 约 20T 预训练 + 1T 退火 | 已有 AR 预训练之后进行转换训练 |
| FFN 结构 | 稠密 | 稀疏 Top-8 | 继承 AR MoE 并继续训练 |

从零训练让模型直接用受损文本学习恢复分布;权重改编则利用已有预训练表示, 通过转换课程适应新的注意力与生成方式. 两条路径的预算应分别记录原始预训练和后续转换阶段, 才能比较获得最终能力的成本.

Base 与 Instruct 的 MATH 分数分别为 36.10 和 58.68, 后训练检查点的表现明显提高. Qwen Instruct 为 67.02;OlympiadBench 上, MoE 为 21.04, Qwen 为 30.41. 两项数学任务都仍有差距. 代码和工具调用则呈现不同优势:MoE 的 HumanEval、MBPP 与 BFCL-Live 分数高于表中 Qwen 3B, BigCodeBench-Full 却仍落后. **平均分接近, 可以对应很不一样的能力分布.** 数学推理、函数调用或代码补全的使用需求各不相同, 应分别对照对应任务的结果.

**训练起点决定比较的问题.** LLaDA 8B 与 LLaDA-MoE 都从零学习掩码去噪, 前者使用稠密 FFN, 后者采用 Top-$k$ 专家路由. 两者都以加权 MLM 为主要训练目标, MoE 另外使用路由辅助损失. MoE 的每 token 激活参数约为稠密 8B 的六分之一, 但训练数据量也从 LLaDA 的约 2.3T 增加到约 20T, 还经过两段退火. 最终分数体现这套完整训练方案的效果;若要测量稀疏结构本身的收益, 需要固定数据与训练预算进行比较.

LLaDA 2.0 从已有 AR 权重开始改编, 研究如何保留预训练能力并切换到块扩散生成. LLaDA-MoE 则直接从零训练稀疏去噪网络. **从零学习与权重改编**是两种训练路径, 各自都可以继续研究缓存与部署;服务性能取决于注意力依赖、解码器和运行时的组合, 具体比较见[缓存与服务调度](../../6-推理加速与系统/6.3-缓存部署与服务/6.3.1-缓存与服务调度.md).

Qwen2.5-3B 是另一类参照:它采用自回归生成, 表中 Instruct 的后训练包含 SFT 与 RL, LLaDA-MoE 则只列出 SFT. 两者平均分相近, MATH 和 CEval 上 Qwen 更高, HumanEval、MBPP 和 BFCL-Live 上 MoE 更高. 这种比较展示两套训练与生成方案的最终能力分布, 也提示后续实验应分别控制模型结构、数据和后训练方法.

### 5.1. 注意力共享、专家分工与回答长度

**GQA 共享与跨轮缓存是两件事.** GQA 让多个 query head 共用一组 K/V 投影, 可以减少 K/V 投影的参数与输出大小, 即使每轮重新计算也仍有这种收益. 跨轮缓存则要求先前算出的 K/V 在新输入下保持有效. 全双向网络中的明文位置会读取其他位置的新内容, 深层隐藏状态和 K/V 可能随去噪更新. LLaDA-MoE 使用多头注意力, Table 2 列出 16 个注意力头;这项配置本身不能解释团队为何没有选用 GQA.

**专家分工需要看它实际处理了什么.** Figure 4 展示前 1T token 内 LB loss 与 Z-loss 先下降、后趋于稳定, 支持辅助损失的训练动态分析. 要进一步识别数学或代码专家, 可以固定噪声水平比较不同领域的路由, 再固定内容比较不同掩码状态. 同一个位置的隐藏状态会随上下文变化, 专家选择也可能变化;只看专家使用次数无法确定其语义功能.

**SFT 的长度选择影响结束行为.** 退火阶段将窗口扩展到 8k, SFT 则将每条样本限制在 4k. 论文给出的理由是多数指令样本较短, 大量 EOS 填充位置参与掩码恢复可能让模型生成过多结束符. 实际 SFT 将短回答补到批内最长回答, EOS 同样参与掩码与损失. 生成时扩大画布只增加可用位置, 长回答质量还取决于训练长度分布、位置泛化与结束符预测. 相关机制见[失效模式](../../7-控制-评测与选型/7.2-评测边界与路线选择/7.2.1-并行性评测与失效诊断.md).

从零训练与 AR 权重改编还对应不同的预算问题. 前者完整学习去噪网络, 后者利用已有权重减少重新预训练的需求. LLaDA-MoE 与 Dream 的训练起点、数据量和网络结构不同, 表中平均分用于比较最终检查点的表现. 若要比较训练效率, 还需要统一计算预算并记录达到目标质量的成本.

### 5.2. 路由与训练系统

Top-$k$ 路由先为每个 token 计算专家分数，再选出 $k$ 个专家。设路由概率为 $p_{i,e}$，token $i$ 的 FFN 输出可写成

$$
h_i'=\sum_{e\in\operatorname{TopK}(p_i)}p_{i,e}E_e(h_i).
$$

同一位置在多轮去噪中会接收不同输入:仍被掩码时, 它依靠位置与可见上下文形成表示;揭开之后, 还包含自身 token 的内容. 这些变化可能改变各层专家选择. LB loss 使用选择频率与平均路由概率, Z-loss 约束路由 logits 的 log-sum-exp, 两项辅助目标都作用于网络训练, 前向掩码核保持不变.

若训练系统给专家设置固定容量, 就需要规定超额分配的处理方式. 掩码率不同的输入可能呈现不同负载, 可以分噪声区间统计选择频率和溢出率. 容量与丢弃规则属于具体实现, 其通用计算在后文展开.

专家跨设备分布时, 输入隐藏向量需要按专家分发, 专家输出再送回原位置参与加权. 常见实现使用 all-to-all 交换, 专家在同一设备上的配置则没有这项跨设备交换. 整段多轮前向的成本同时包含专家计算、共享注意力、路由与通信, 参数池还需要存储. 因此 1.4B 每 token 激活参数不能直接换算成服务延迟.

训练诊断可以并列观察主预测损失、LB loss、Z-loss 和专家使用率, 再用固定验证任务判断预测能力是否改善. 数学和代码重采样发生在第二段预训练, 后续退火使用高质量文本;比较阶段负载时应分别记录数据分布与参数变化. 论文 Figure 4 给出的辅助损失曲线覆盖最初 1T token.

**规格卡.**

- 从零稀疏 MDM,预训练约 20T(10T 混合 + 10T 加重数学代码),再两段 500B 退火;SFT 锁 4k.
- Table 2:16 层,2048,16 头,64 专家 Top-8,专家维 1024,RoPE 50k;非嵌入 7B,激活 1.4B.
- 损失:吸收态 $1/t$ MLM + LB 0.01 + Z-loss 0.001.
- Base 平均分 46.94,对引用的 LLaDA-8B 43.53,Dream 46.66,Qwen2.5-3B 50.34.
- Instruct 仅 SFT,平均分 53.12,对有 RL 的 Qwen2.5-3B-Instruct 53.51;GSM8K 82.41,MATH 58.68,HumanEval 61.59.
- 生成评测默认半自回归,长度 1024,块长 64.
- 谱系:从头训练的稀疏 MDM;没有采用 LLaDA 2.0 的 AR→扩散改编,也没有蒸馏 LLaDA 8B.

Top-$k$ 只作用于 FFN;揭开位置由采样器决定, KV 能否精确复用由注意力图案决定. 20T 从零训练扩大的是稀疏模型容量, 吸收态扩散的概率路径保持不变. LLaDA 8B 研究从零扩散训练, LLaDA-MoE 引入稀疏 FFN, LLaDA 2.0 则继承 AR MoE 权重进行改编. 三者的初始化、参数规模和训练预算各不相同.

规格卡上的「1.4B 激活参数」按每个 token 在整套模型中经过的共享模块与选中专家统计, 并非某一层的 FFN 参数量. 一轮前向处理整段序列, 不同 token 可以选中不同专家, 全批次触及的参数集合可能远大于单个 token 的激活集合. 端到端计算还取决于序列长度、注意力计算和去噪轮数.

专家路由还会改变检查点与恢复训练的成本。密模型恢复时主要保证优化器、随机数和数据游标一致；MoE 还要保持专家到设备的映射。若恢复后重新排列专家，却没有同步搬运优化器状态，表面上参数都能加载，实际每个专家拿到的动量来自另一个专家。长程预训练中这种错误未必立刻让 loss 爆炸，更可能表现为路由负载突然重排、退火阶段分数回落。保存检查点时应记录专家编号、并行组拓扑与路由器状态，恢复后的第一批数据要对比逐专家 token 数。

从系统角度看，扩大 Top-$k$ 会让每个 token 获得更多专家容量，也近似线性增加专家计算和通信量。Top-8 是 LLaDA-MoE 的具体配置，不能由「扩散需要更多候选」推出。候选 token 的词表分布发生在输出头，专家选择发生在中间 FFN；两种 top-k 位于不同空间。把路由 Top-8 改成 Top-2，会改变容量与训练动态，却不会把每步揭开的 token 数自动缩小。

### 5.3. 路由器看到的扩散状态

在一个给定的 MoE 层, 令 $h_i^t\in\mathbb R^d$ 为噪声水平 $t$ 下位置 $i$ 的隐藏向量, 路由矩阵为 $W_r\in\mathbb R^{E\times d}$. 该位置的专家概率向量为

$$
g_i^t=\operatorname{softmax}(W_r h_i^t),
\tag{4}
$$

其中 $g_i^t\in\mathbb R^E$, 各分量非负且总和为 1, 再按分量大小选择 Top-$k$ 专家. 上标 $t$ 标记输入状态来自哪个噪声水平;论文的预测器写作 $p_\theta(\cdot\mid y_t)$, 不能由这个上标推断网络额外接收了时间嵌入. 掩码数量、位置和可见内容会改变隐藏状态, 因而同一位置在不同去噪轮可能选择不同专家. 掩码比例提供噪声水平的统计线索, 但有限序列中的实际掩码数有随机波动, 无法精确恢复采样时的 $t$.

**掩码位置与明文位置.** 加权 MLM 只在被掩码位置计入 token 预测损失, 两类位置却都参与网络计算. 明文位置产生的表示可以通过后续注意力影响掩码位置的预测, 因而仍可能收到主损失的梯度. 例如第 $l$ 层明文位置的专家输出进入第 $l+1$ 层 K/V, 被一个掩码位置读取, 梯度就能沿这条依赖路径返回. 「没有本位置的预测损失」与「没有学习信号」应分别理解.

大量掩码位置如果集中选择同一专家, 会提高该专家的负载. 相同的掩码符号也可以因位置和上下文不同产生不同隐藏状态, 所以是否集中路由需要实际统计. 按层、噪声水平以及明文或掩码位置分别记录专家使用率, 可以观察集中发生在哪里;语义分工还需结合领域标签或专家消融判断.

**区分领域与噪声的影响.** 分析专家使用率时, 可以在同一批干净文本上改变噪声水平, 每个水平重复抽取掩码, 记录各层路由的均值与波动. 然后固定噪声水平, 对比代码、数学和自然语言样本. 这样可以分别观察输入领域与受损程度对路由的影响. 某个专家偏向低噪声代码, 既可能与内容有关, 也可能与可见 token 的数量和结构有关, 两项条件需要联合统计.

**相同掩码数量也有不同形状.** 例如八个位置中掩码四个, 可以交替遮住位置, 也可以遮住连续四位或最后四位. 交替遮挡提供较多局部可见邻居, 连续块内部缺少这些线索, 后缀遮挡则只保留此前文本. 在相同干净输入与掩码数量下比较这些形状, 可以观察条件信息布局如何改变预测与路由. 训练中的独立随机掩码与低置信提交产生的状态分布也不同;诊断时应同时记录 token 预测损失、专家使用率以及具体实现中的容量截断, 才能区分去噪难度和路由资源的影响.

**条件计算的概率含义.** MoE 改变去噪网络的参数化函数:每个位置只使用部分 FFN 专家, 输出头仍给出干净 token 的类别分布. 在关闭路由噪声、固定并列分数处理规则时, 给定隐藏状态就能确定 Top-$k$ 集合. 网络按门控权重加总这些专家输出, 无需另对一个随机专家变量求边际.

主损失通过选中专家的输出和门控权重反向传播. 未选专家的 FFN 参数不接收这个 token 的主损失梯度;路由器的 softmax 归一化和辅助损失仍可影响未入选专家对应的分数. **总参数**描述可用参数池, **每 token 激活参数**描述单个 token 经过的子网络. 实际计算量还受序列长度、注意力、通信和采样步数影响.

扩散生成一次需要多轮前向.单轮激活参数较小,总计算仍是激活量乘步数.若MoE模型需要更多步达到同质量,条件计算优势会被部分抵消.表格应同时给每步激活量、平均步数与端到端成本. **专家容量。** 每个专家每批能接收的token数通常有限.容量可写成

$$
C=\left\lceil c\frac{Nk}{E}\right\rceil,
\tag{5}
$$

$N$ 是一次容量统计范围内的 token 数, $k$ 是每 token 选择的专家数, $E$ 是专家数, $c$ 是容量因子. 式 (5) 描述采用固定专家容量的一种通用实现, 其中 $Nk$ 统计 token—专家分配次数. 例如 $N=1024$, $k=8$, $E=64$, $c=1.25$, 平均每个专家接收 128 次分配, 容量为 160. 总容量留有余量, 某个热门专家仍可能超过 160;统计范围也必须与实际路由及专家并行组一致.

达到容量上限后, 实现可以丢弃超额分配、重路由或采用动态缓冲. 丢弃的是某次专家分配时, token 还可能保留其他选中专家的贡献以及残差路径, 不能直接理解成整个 token 从序列中消失. 不设置固定容量、保留全部分配的实现则没有同一种溢出截断. 具体采用哪种处理, 会影响输出与运行成本.

**共享专家是一种额外的架构选择.** 一条对所有 token 执行的专家路径, 可以与稀疏路由路径并行相加, 同时增加固定计算量. 共享路径究竟学到通用能力还是承担某类特定任务, 要通过路由统计与消融分析判断. LLaDA-MoE 的 Table 2 和路由式描述的是 64 个专家中选择 8 个, 这里的容量手算与共享路径讨论用于理解其他 MoE 设计, 不作为该检查点的实现配置.

比较有无共享专家时应固定激活计算,否则收益可能来自多了一条密集FFN.还应测遮掉路由专家后剩余能力,判断共享路径承担了多少任务.

### 5.4. 负载均衡目标

负载均衡项将实际专家选择频率 $f_e$ 与平均路由概率 $p_e$ 相乘. 设这一层共有 $E$ 个专家, 形式为

$$
L_{\mathrm{bal}}=E\sum_{e=1}^{E} f_ep_e.
\tag{6}
$$

这里要明确 Top-$k$ 的计数单位. 设共有 $N$ 个 token, 专家 $e$ 被选择 $n_e$ 次. 若按 token 数归一化, $f_e=n_e/N$, 则 $\sum_e f_e=k$;若按全部分配次数归一化, $f_e=n_e/(Nk)$, 则 $\sum_e f_e=1$. 平均路由概率始终为 $p_e=N^{-1}\sum_i g_{i,e}$, 总和为 1. 两种 $f_e$ 约定会使同一批数据的式 (6) 相差 $k$ 倍, 辅助损失权重也必须与实现口径配套.

例如 Top-8、64 个专家都均匀使用, 按 token 数计有 $f_e=8/64$, $p_e=1/64$, 式 (6) 等于 8;按分配次数计则等于 1. 这个手算说明统计尺度, 不代表一次真实训练的辅助损失值. 论文给出选择频率的描述与 0.01 权重, 复现时还需核对代码中的归一化、统计范围以及是否在容量截断前计数.

**按噪声区间看负载.** 假设高噪声样本集中使用专家 A, 低噪声样本集中使用专家 B, 两类样本数量相同. 合并统计时 A、B 的负载相近, 各区间内部却仍高度集中. 因而可以同时报告总体与分区间的专家占比. 专门化是否影响质量, 还要结合容量截断、预测损失和任务表现判断. 对每个噪声区间分别加均衡项, 则是新的训练约束, 会改变允许形成的路由分工.

**按领域看覆盖.** 代码、数学和自然语言的样本比例不同, 可以按数据源记录专家选择与各领域验证损失. 数据源标签是分析用的分组, 不等同于给专家命名, 混合文本还可能同时包含多个领域. 低频领域使用少数专家也不自动意味着容量不足, 需要看这些专家是否过载、是否获得足够训练以及该领域的预测质量.

**主损失与均衡项如何共同更新.** 记路由参数为 $\phi$, 两项梯度分别为 $a=\nabla_\phi L_{\mathrm{pred}}$ 与 $b=\nabla_\phi L_{\mathrm{bal}}$. 总更新方向包含 $a+\lambda b$. 当 $a$ 与 $b$ 非零时, 可以用余弦记录方向是否一致, 但实际影响还取决于梯度范数与权重 $\lambda$. 局部方向相反不直接决定最终质量;比较不同权重仍需查看完整训练后的负载和验证结果.

### 5.5. 路由稳定性

同一位置在相邻去噪轮会再次经过路由器. 令两轮选中的专家集合为 $S$ 与 $S'$, 可以用 $|S\cap S'|/|S\cup S'|$ 记录集合相似度. Top-8 若只替换一个专家, 交集为 7、并集为 9, 相似度为 $7/9$;这个数只描述专家编号的变化, 不衡量预测质量. 两轮集合相同, 门控权重与隐藏输入仍可能不同.

**路由边界.** 将概率从大到小排列, 第 $k$ 与第 $k+1$ 项的间隔为 $\Delta=g_{(k)}-g_{(k+1)}$. 若每一项概率的变化绝对值都小于 $\Delta/2$, 原来的入选项仍大于未入选项, Top-$k$ 集合保持不变. 小间隔意味着较小扰动就可能改变集合, 但专家替换对输出的影响还取决于门控权重与专家输出. 因此应同时观察集合相似度、加权专家输出和最终 token 分布.

**揭开位置之后的信息传播.** 一个位置从掩码变成明文, 会改变它自己的输入, 也会经注意力影响其他位置. 可以固定其余 token, 对比揭开前后各层的路由集合、权重和预测分布, 观察变化沿哪些依赖传播. 集合变化而输出稳定, 可能来自被替换专家贡献很小或多个贡献相互抵消;仅凭这次观察无法确定专家冗余. 若希望约束相邻状态的路由差异, 可以另行设计连续性正则, 但需测试它是否妨碍新信息到来后的有效切换. LLaDA-MoE 本文采用的是 LB loss 与 Z-loss.

**专家编号的对称性.** 同时置换专家参数和路由器对应的输出分量, 并同步处理相关容量规则与并列分数选择, 可以保持加权输出不变. 只交换专家参数、保留路由器原来的编号关系, 则通常会改变函数. 因此不同随机种子的「第 3 个专家」没有天然对应关系, 应按其路由与输出行为对齐后再比较.

**专家组合图.** 以专家为节点, 用共同入选的次数作为边权, 可以观察哪些专家经常一起处理 token. 这描述共用模式, 互补性还要通过实验判断. 例如固定输入, 分别移除专家 A、专家 B 和两者, 对照预测损失与任务表现的变化. 两个专家共同出现得多, 也可能只是都常用于高频数据, 而非功能相互依赖.

组合数量与参数容量之间没有直接换算关系. 固定组合仍可包含多个较大的专家网络;很少被使用的组合也可能处理重要的长尾任务. 分析时应同时记录组合频率、数据覆盖和任务表现.

**专家消融.** 保持其余选择与权重不变, 将某个专家的加权输出置零, 测量的是当前计算路径对该贡献的依赖. 用次选专家替换它, 测量的是路由系统的替代能力;重新归一化剩余权重又会引入不同干预. 三种实验应分别记录. 单专家消融几乎不掉分, 可能来自贡献较小、其他路径补偿或评测覆盖不足;联合消融与分领域测试可以进一步区分这些情况.

### 5.6. 训练目标与专家学习

加权 MLM 中, 每个被掩码位置的预测损失乘以 $1/t$. 较小 $t$ 下, 单个入选预测位置的权重较大, 但被掩码位置的期望数量也较少. 专家获得的梯度还取决于路由权重、预测误差与上下文依赖, 不能仅由 $1/t$ 或接收 token 数判断.

LB loss 同时使用实际选择频率与平均路由概率, 没有直接衡量专家的主损失梯度. 诊断时可以分别记录专家负载和梯度范数, 并区分明文、掩码位置及噪声区间. 一批数据的总体负载均匀, 某个噪声区间仍可能集中使用少数专家. 若进一步对这些子集分别施加均衡约束, 就改变了训练目标, 需要重新比较预测质量与负载, 而非仅确认统计曲线更平.

**训练阶段之间如何比较.** 数学和代码重采样、上下文扩展、指令微调都会改变网络接收的数据. 可以用一套固定验证样本, 对比各阶段的专家选择频率、门控权重和任务分数;再用该阶段的新数据观察适配情况. 固定样本帮助隔离参数更新的影响, 新数据反映实际输入分布的变化. 若基础能力下降, 还应检查数据覆盖、权重更新和解码设置, 再判断是否存在遗忘.

冻结路由矩阵只固定从隐藏向量到专家分数的映射. 上游注意力与专家参数仍更新时, 隐藏向量可以改变, 专家选择也仍可能变化. 若实验比较冻结路由器、降低其学习率或混入预训练回放, 应同时测量路由行为与基础能力, 才能判断各项干预保留了什么.

### 5.7. 容量与质量的关系

固定专家宽度、Top-$k$ 和训练 token 总数时, 增加专家数 $E$ 会扩大参数池. 在均匀路由下, 每个专家的平均分配次数随 $1/E$ 减少;实际覆盖还取决于路由偏斜与数据分布. 因而扩大参数池需要同时检查各专家获得的训练信号, 不能仅由专家数判断是否欠训练. 固定激活计算比较专家数, 与固定总参数比较 Top-$k$, 回答的是不同的容量问题.

**Top-1 与 Top-2.** 固定专家规模时, Top-2 每 token 执行两个专家, 增加专家计算和分配次数, 输出由两项门控贡献相加. 第二个专家是正常计算的一部分, 并非自动启用的故障备用路径. 两个高分专家也可能同时拥塞, 所以负载是否更均匀仍需统计. 扩散的多轮前向会重复这部分计算;质量收益应同时在固定轮数和固定墙钟预算下比较.

**容量因子.** 在固定路由和按容量截断的实现中, 提高 $c$ 会提高专家接收上限, 减少可能被截断的分配. 若实现使用填充到容量上限的缓冲, 更大的容量也会增加预留空间和填充开销;动态缓冲的代价则取决于实际负载与调度. 应分别记录溢出率、显存和耗时, 再选择容量. 若输出会因批内拥塞而丢弃或改送某些分配, 同一输入的结果还可能受同批其他样本影响, 复现时需要记录批次与溢出规则.

### 5.8. 条件计算与扩散步数

设整段序列一轮前向的主体计算为 $F_{\mathrm{act}}$, 共执行 $T$ 轮, 主体计算近似为 $TF_{\mathrm{act}}$. 路由、通信与缓存操作另计. 比较两种模型时, 需要同时观察质量随轮数与墙钟时间的变化:单轮计算较少的模型, 可能需要更多轮才能达到相同质量.

**路由缓存.** 路由集合、门控权重和专家输出是三个不同对象. 即使相邻轮仍选中同一组专家, softmax 权重和专家输入也可能变化. 只复用专家编号, 仍需计算当前权重与专家输出;同时复用权重或输出, 则需要更强的条件. 在全双向注意力下, 已揭开的 token 会读取其他位置的新内容, 隐藏状态随之变化, 因而「token 没变」不足以保证这些对象可以精确复用. 跨轮固定路由属于近似推理, 应通过质量与耗时实验评估. 若注意力依赖图保证某个完成块的输入与全部前驱状态固定, 才能逐层判断其计算结果是否可精确保留.
