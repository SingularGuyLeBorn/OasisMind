# 规划,填槽与混合解码

纯并行去噪并不是唯一选择.另一类方法先生成结构,再填内容:结构可以是位置顺序,计划 token,句级草稿或若干槽位.这样做把"哪些位置能一起提交"变成显式决策,同时保留局部修订能力.

掩码扩散把许多未知位置放进同一次前向，但网络给出的通常是按位置分解的边际分布。若两个位置必须协调，例如函数名与调用点、主语与谓语、推理步骤与最终答案，同时从旧状态独立采样会丢掉「先确定一个，另一个再以它为条件」的关系。把去噪步数拉长可以缓解这个问题，却会让并行收益逐渐消失。规划与填槽方法选择先确定生成顺序或结构，再让内容生成沿该结构推进。

设待生成位置集合为 $M$，一次并行去噪常写成

$$
p_\theta(x_M\mid x_{\bar M})\approx
\prod_{i\in M}p_\theta(x_i\mid x_{\bar M}).
$$

右侧每个位置都看见同一份已知上下文 $x_{\bar M}$，却看不见同一步刚生成的其他位置。引入排列 $\pi=(\pi_1,\ldots,\pi_{|M|})$ 后，联合分布可以改写为

$$
p(x_M\mid x_{\bar M},\pi)=
\prod_{k=1}^{|M|}p(x_{\pi_k}\mid x_{\bar M},x_{\pi_{<k}},\pi).
$$

排列恢复了条件链，但逐格执行又回到串行。混合方法让 $\pi$ 作用在组或槽上：组间按条件关系推进，组内仍并行生成。实际并行度由任务的依赖图决定，而不仅是固定块长。

## 1. 规划器决定什么

规划器可以输出四类对象。第一类是位置优先级，例如每轮先揭置信度最高的若干格；它几乎没有额外模型成本，但置信度只反映单点尖锐程度，不保证多点组合一致。第二类是显式揭开顺序，模型为每个位置预测「现在是否适合提交」，把生成日程也变成学习目标。第三类是内容计划，例如先生成主题、变量、句级语义寄存器或代码骨架，再根据计划填表面 token。第四类是槽划分，把强依赖位置放进同一条串行槽，把弱依赖槽并行推进。

这些对象对应不同的错误传播方式。位置优先级出错时，低置信位置通常还能留到后续重算；显式顺序出错可能让关键条件出现得太晚；内容计划若先被硬提交，后续只能围绕错误骨架补字；软计划保留在连续隐变量中，可以被反复修订，却会增加一套编码器、扩散器或交叉注意力。规划的价值不只取决于计划本身是否准确，还取决于内容模型在计划错一部分时能否恢复。

DDPD 一类方法把「哪个位置仍然脏」交给规划网络。规划器估计每个位置的脏概率，求和得到剩余噪声量，再通过日程的反函数映射到有效时间 $\tilde t$。若模型发现先前提交的 token 仍不可靠，采样时钟可以回到更高噪声水平，让这些位置再次参与生成。固定时间网格只知道已经走了几步，规划器则根据当前序列的状态决定还需走多少步。

## 2. 任意顺序如何保留条件链

任意顺序语言模型不一定使用扩散过程。训练时随机采样排列 $\pi$，模型在排列前缀条件下预测下一个位置，就能学习多种填充方向。Eso-LM 采用这种思路：序列的原始位置与生成次序分开编码，因果注意力沿生成次序展开，而位置编码仍表示 token 在最终文本中的位置。模型既可从左到右续写，也可先填锚点，再补中间空缺。

这类模型保留了标准化的条件链，联合概率仍由一串条件概率相乘得到；代价是推理必须选一条顺序。若顺序也由模型动态产生，缓存中的可见集合可能不再是连续前缀。普通 KV Cache 依赖「新 token 只追加在右侧」，任意位置插入会改变后续位置的注意力条件。实现可以按生成次序缓存，再用独立位置 ID 表示最终坐标；也可以把一次选择扩展成多个槽，每个槽内部追加。缓存是否成立取决于注意力掩码和坐标设计。

## 3. 槽级并行的计算形状

把 $M$ 个未知位置分为 $S$ 个槽 $G_1,\ldots,G_S$。每个槽内部按某个顺序生成，槽之间同时前进。若第 $s$ 个槽长度为 $|G_s|$，理想调用次数接近 $\max_s|G_s|$，而逐 token 自回归需要 $\sum_s|G_s|$ 次。理论并行度可写成

$$
\rho=\frac{\sum_{s=1}^{S}|G_s|}{\max_s|G_s|}.
$$

这个上界要求每轮各槽都能提交一个 token，且槽间依赖足够弱。规划器若把互相约束的位置拆到不同槽，它们会在同一步基于旧状态作决定，联合错误重新出现；若把太多位置塞进同一槽，质量稳定但 $\rho$ 降低。槽划分本质上是在估计依赖图，并将图整理成若干可并行链。

训练时还要保持逻辑位置与缓冲区位置分离。为了让每个槽的已生成 token 在内存中连续，系统可能把它们搬到掩码区之前；RoPE 或其他位置编码仍应使用最终文本中的原下标，否则模型学到的是临时缓冲区的距离。恢复输出时再按原槽序和位置散射回去。混用两套坐标时，短样例可能正常，长距离引用和括号配对却会明显下降。

## 4. 并行收益的完整成本

规划器增加的开销包括规划前向、顺序采样、位置重排和可能的验证。若规划器与主模型同尺寸，每个去噪周期多跑一次规划网络，节省的主模型调用很容易被抵消。轻量头共享主干表示的成本较低，但规划信号也更依赖主干当下的校准。软计划模型还可能引入连续扩散步骤，使「离散去噪少了」与「总 NFE 下降」成为两个指标。

端到端延迟可以拆成

$$
T_{\mathrm{total}}=T_{\mathrm{plan}}+N_{\mathrm{main}}T_{\mathrm{main}}
+T_{\mathrm{verify}}+T_{\mathrm{reorder}}.
$$

接受率或每步提交数只能解释 $N_{\mathrm{main}}$，无法覆盖其余三项。质量也要在相同输出长度、采样温度与任务协议下比较。计划 token 若计入模型内部计算却不计入输出 token，单看 tok/s 会高估收益；发生回滚时，被拒绝候选消耗的前向同样属于延迟。

### 5.1. 选择问题

1. 计划是否由独立模型生成,额外计算是否抵消并行收益?
2. 计划错误能否在填槽阶段纠正,还是会成为不可逆上游瓶颈?
3. 训练顺序分布与推理顺序是否一致?
4. 报告的加速来自生成顺序,缓存,还是更小的验证器?

这些方法共享「先确定依赖结构，再生成内容」的接口，背后的概率模型并不相同。

### 5.2. 从依赖图得到并行轮数

把待生成单元看作有向无环图 $G=(V,E)$。边 $i\to j$ 表示 $j$ 的正确分布需要先知道 $i$。所有入度为零的节点可以同轮生成，提交后删除对应出边，再处理下一层。理想并行轮数等于图的最长路径长度 $d(G)$，串行调用数是 $|V|$，结构上限为

$$
\rho_G=\frac{|V|}{d(G)}.
$$

固定块或固定槽实际上用一个预设图近似每个样本的真实依赖图。自然语言依赖随内容变化，同一位置在不同句子里可能承担锚点或普通修饰语。规划器的任务可以理解为在线估计部分边，再给出一个近似拓扑层次。

漏边和多余边造成不同损失。漏掉 $i\to j$ 会让两者同轮独立决策，产生联合错误；多加一条不存在的边只会让 $j$ 晚一轮，降低速度。安全优先的规划器可以偏向多预测依赖，吞吐优先则允许更多漏边。只报告平均轮数会把两类错误混在一起，评测应同时给依赖约束违反率与冗余串行率。

真实依赖图通常不可观测，可在合成任务中精确给出。例如表达式树要求父节点运算符决定子节点格式，程序数据流要求变量定义先于依赖类型的使用。自然文本可用干预近似：固定其他位置，改变位置 $i$ 的候选，观察位置 $j$ 的条件分布变化

$$
D_{ij}=D_{\mathrm{KL}}
\left[p(x_j\mid C,x_i=a)\Vert p(x_j\mid C,x_i=b)\right].
$$

$D_{ij}$ 大说明模型认为 $i$ 会影响 $j$，但它仍是模型内部依赖，并非真实语义因果。把它与结构化任务的已知边对照，可以测规划器是否只复制注意力相关性。

### 5.3. 顺序分布与重要性权重

任意顺序训练从分布 $q_{\mathrm{train}}(\pi)$ 采样排列，部署使用 $q_{\mathrm{test}}(\pi)$。若两者差异很大，模型会在很少训练过的条件集合上生成。理论上可用重要性权重

$$
w(\pi)=\frac{q_{\mathrm{test}}(\pi)}{q_{\mathrm{train}}(\pi)}
$$

修正训练期望，前提是测试顺序的支持集包含在训练分布中。排列空间有 $L!$ 个元素，直接估计整条排列概率几乎不可行；实践常按每一步的位置选择概率分解，并限制候选策略族。

均匀随机排列覆盖广，却把大量训练预算花在部署永远不会采用的低质量顺序上；只训练最高置信顺序效率高，但规划器一旦犯错便进入支持外状态。混合分布可以让大部分样本跟随当前规划器，少部分随机探索其他顺序。随着规划器更新，训练分布也会漂移，需要保存策略版本，避免把旧轨迹当成当前 on-policy 数据。

顺序还会改变标签难度。先生成实体类型再生成实体名，后者条件更充分；反过来时模型要在多种实体间猜测。若训练损失只按 token 平均，困难顺序产生更大梯度，模型可能投入大量容量补偿糟糕规划。联合优化规划器与内容模型时，应分别观察顺序价值和条件预测误差，否则内容模型变强会掩盖规划器没有学会依赖。

### 5.4. 计划置信度与不可逆承诺

规划器输出位置分数 $r_i$ 后，常按 top-$k$ 选择本轮提交集合。分数需要同时表达内容置信度和依赖风险。一个 token 的边缘概率很尖锐，仍可能是高影响锚点；若它预测错，会改变大量后继位置。可将提交代价写成

$$
c_i=(1-p_i^{\max})\,I_i,
$$

$p_i^{\max}$ 近似错误概率，$I_i$ 估计该位置对剩余状态的影响。只看 $p_i^{\max}$ 会漏掉影响项，只看 $I_i$ 又会永远推迟关键锚点。选择规则需要在尽早提供信息与避免错误传播之间平衡。

软提交保留多个候选或连续计划表示，后续位置对候选加权；硬提交只保留一个 token。软提交减小早期选择风险，却使状态与计算随候选数增长。若每个槽保留 $K$ 个候选、深度为 $d$，完整树有 $K^d$ 条路径，必须通过剪枝或粒子重采样控制。剪枝后正确路径一旦消失，后续模型再强也无法恢复。

可撤销提交把错误传播变成检测问题。系统需要识别某个已提交 token 与新证据冲突，再重开它及其后继。若仅用该 token 当前概率作判断，错误上下文可能让它持续保持高置信；更可靠的信号包括局部约束失败、替换该 token 后整体能量下降，以及多次采样之间的不一致。

### 5.5. 混合解码的概率账

一个混合系统可能先由规划器采样 $z$，再按槽内因果链生成部分 token，最终用扩散修订。其联合概率形式为

$$
p(x,z)=p_\phi(z)
\prod_{s,k}p_\theta(x_{s,k}\mid x_{s,<k},x_{<s},z)
\,K_\psi(x'\mid x,z),
$$

$K_\psi$ 是修订转移核。若最终输出为 $x'$，精确边缘概率需要对计划、初稿和修订路径求和，通常不可计算。于是不同工作报告的 PPL 可能分别来自因果初稿、变分界或外部评分器，数值含义不相同。

修订核也可能破坏前面条件链的规范化概率。若它只是满足详细平衡的 MCMC 核且目标分布明确，反复运行可保持目标；置信度重掩与启发式替换通常没有这种保证。它们可以提高任务分数，但应被视为完整生成算法的一部分，而非不影响分布的后处理。

验证混合解码可用三组对照：固定规划器，关闭修订以测计划与初稿；固定初稿，替换随机、置信度和约束驱动修订；固定总 NFE，让额外规划计算与更多去噪步竞争。只有这些对照同时存在，才能把收益分给结构规划、内容模型和纠错预算。

### 5.6. 失败样本应怎样归因

计划正确而内容错误，说明条件模型没有利用结构；计划漏边导致同轮冲突，说明依赖估计不足；计划多边导致结果正确但过慢，说明调度过度保守；初稿正确却被修订破坏，说明纠错核的接受规则有问题。四类失败需要保存中间计划和每轮状态，只有最终输出无法区分。

对每条样本可以记录计划深度、实际轮数、撤销次数、净提交数和约束冲突首次出现的轮次。计划深度低但实际轮数高，表示内容置信或验证成为瓶颈；计划深度本就高，则任务依赖不允许太多并行。把两者混在总延迟中，会错误地把任务结构上限归咎于实现。

计划器还可能学到长度或位置捷径。例如总是先填句首、标点和高频词，平均损失很好，却没有识别样本特定依赖。随机平移槽位、交换等价片段、改变模板长度并保持依赖图不变，可以检查策略是否仍选择相同语义锚点。通过这种干预后，规划能力才更可能迁移到新结构。

部署评测还要固定回滚上限；无限修订可以提高成功率，却无法形成可预测的尾延迟和资源预算。

超过上限的样本应单独记为失败，不能从统计中删除。
