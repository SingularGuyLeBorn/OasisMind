# 3.6 预训练评估

训练 loss 每一步都有, 但它在训练分布上算, 说明不了模型会不会做题. 下游基准能说明会不会做题, 但在小模型和早期 checkpoint 上常停在随机水平, 分数还随提示格式, 打分方式和评测实现变化. 预训练评估要在两者之间挑出当前阶段有信号的量, 并知道这个量的误差有多大.

四篇按评估对象分: [3.6.1](./3.6.1-困惑度-PPL/3.6.1-困惑度-PPL.md) 是语言建模本身 (PPL 与每字节比特), [3.6.2](./3.6.2-通用基准/3.6.2-通用基准.md) 是知识与短推理的通用基准, [3.6.3](./3.6.3-大海捞针测试/3.6.3-大海捞针测试.md) 是长上下文, [3.6.4](./3.6.4-特定能力评估/3.6.4-特定能力评估.md) 是代码, 数学和多语言. 后训练模型的对话质量和偏好评测在 [第 4 章 后训练](../../4-后训练/4-后训练.md).

## 1. loss 与下游分数之间

### 1.1 一个 PPL 数字背后的协议

PPL 是每 token 平均负对数似然的指数. 它的第一个问题是单位: 换 tokenizer, token 数就变, 同一段文本的 PPL 不能直接比. 跨模型比较要换成每字节比特, $\mathrm{BPB}=(L_T/L_B)\cdot\ell/\ln2$, $\ell$ 是每 token 的平均 loss (nat), $L_T/L_B$ 是每字节的 token 数, GPT-2 tokenizer 在 The Pile 上是 0.29335. 中文常用汉字在 UTF-8 里占 3 字节, 纯中文文本上每字符比特约为 BPB 的 3 倍, 两者不能放在一起比.

第二个问题是计算协议. Hugging Face 文档给出的例子里, GPT-2 large 在 WikiText-2 测试集上用不重叠切块得 PPL 19.44, 改成步长 512 的滑动窗口得 16.44, 同一个模型同一份数据, 只改切法就低了 15%. 文档是拼接还是逐篇处理, 在短文档语料上差别也很明显. 3.6.1 第 2.3 节列出一个 PPL 数字要能复现必须附上的几项: 计分单位与对数底, 语料与切分, 窗口与步长, 文档处理, 是否去污.

### 1.2 loss 什么时候能代替分数

在一组条件下, loss 和下游分数近似线性. Huang 等人测了 31 个公开基座模型, tokenizer, 窗口, 架构 (含 MoE 和 Transformer-Mamba 混合) 和预训练数据都不同, 在 Common Crawl, GitHub Python 和 arXiv 数学三份新语料上测每字符比特 (BPC), 与 12 个基准的平均分 Pearson 相关为 $-0.93$. 条件是基座模型, 短上下文, 语料和能力对口, 没有泄漏; MMLU 与 Common Crawl 不对口, 相关只有 $-0.890$, 换成教科书语料升到 $-0.930$.

单个模型的训练曲线上, 两者的关系由度量决定. Schaeffer 等人指出, 每 token loss 平滑下降, 但要求 $L$ 个 token 全对的精确匹配准确率约为 $e^{-L\ell}$, 对 loss 是指数关系; $L=5$ 时 loss 从 0.5 降到 0.1 nat, 精确匹配从 0.082 升到 0.607, 在对数横轴上就是一段陡升. 打分格式也有同样的效果: OLMo-7B 训练中, MMLU 的完形填空格式 (CF) 早期就有信号, 多选字母格式 (MCF) 一直停在随机, 约 400B token 时才学会, 之后 MCF 的信号超过 CF. 早期 checkpoint 想看到连续信号, 就用连续度量 (正确答案的对数概率, BPB) 或 CF 格式.

## 2. 四类评估的对照

### 2.1 测什么, 误差从哪来

下表并列四篇的评估对象和各自最大的误差来源:

| | 主要度量 | 判对方式 | 最大的误差来源 | 量级 |
|---|---|---|---|---|
| 3.6.1 语言建模 | PPL, BPB, BPC | 无需判对 | tokenizer, 窗口, 文档切法 | 同模型改切法差 15% |
| 3.6.2 通用基准 | 准确率, pass@k | 比较选项概率或抽取答案 | 提示格式, 打分方式, 聚合方式 | Mistral-7B 在 ARC-C 上 50.1 对 72.4 |
| 3.6.3 长上下文 | NIAH 召回, RULER 有效长度 | 回答是否含目标串 | 提示与回答前缀, 针的位置 | 一句前缀让 Claude 2.1 从 27% 到 98% |
| 3.6.4 代码数学多语言 | pass@k, maj1@k | 单测, 答案等价判定 | 检查器的假阳性与假阴性 | HumanEval+ 让 pass@k 降 19.3% 到 28.9% |

四类的差别集中在「判对」这一列. 语言建模不需要判对, 误差全在协议; 选择题只比较几个概率, 不存在答对了却没认出来的问题, 误差来自格式和打分方式; 代码和数学要靠外部检查器, 检查器本身就会出错. 3.6.4 第 1.1 节把这一点写成三类误差: 假阳性 (单测不足, 推理错但答案碰对), 假阴性 (环境差异, 答案形式不同, 抽取失败), 污染.

长上下文评估的误差更难拆. Claude 2.1 在原版 NIAH 上常回答「文章没有给出确定答案」, Anthropic 解释为训练数据里有专门减少无依据回答的部分, 一句硬插进去的突兀句子正好触发这种保守. 所以 NIAH 分数同时测了检索能力和回答习惯, 两者在热力图上分不开; 比较两张热力图之前, 要先确认针, 问题, 提示和回答前缀都相同.

### 2.2 样本量决定能分辨多小的差距

准确率是 $n$ 道题上伯努利变量的均值, 标准误 $\sqrt{p(1-p)/n}$. $p=0.5$ 时, HumanEval ($n=164$) 约 3.9 个点, MATH-500 约 2.2 个点, MMLU 测试集 ($n=14079$) 约 0.42 个点. 两个代码配比方案在 HumanEval 上相差 3 个点, 落在一个标准误以内, 再叠加原版测试 20% 到 30% 的相对虚高, 这 3 个点不能说明哪个配比更好. 加题量 (HumanEval 加 MBPP, 加 MultiPL-E 的其他语言) 或改看连续度量, 才能把误差压到差距以下.

采样次数改变的是另一种误差. 数学上多数投票 (maj1@k) 不需要外部判定, 是一个可以提交的答案; pass@k 只要 $k$ 个里有一个对, 等于假设存在完美验证器. Minerva 62B 在 MATH 上 pass@256 为 84.5%, 但人工检查显示, 256 个样本里只有一个答对的题约 30% 是推理错误的碰对, 扣除后真实值只能确定高于 68%. 采样越多, 碰对在 pass@k 里的占比越高. 长上下文一侧, RULER 每格 500 个样本, NIAH 原版每格一次, 单个格子的颜色带有很大的随机性.

## 3. 按训练阶段选评估

### 3.1 小模型数据消融

数据消融通常在 400M 或 1B 的模型上比较几种数据方案, 再把胜出的方案用到大模型上. 基准要满足两个条件: 小模型上不在随机水平, 小模型上的排序与大模型一致. MCF 格式的 MMLU 在 400B token 以前不满足第一条. DCLM 的 Core 指标从 53 个任务里选出 22 个小规模上方差也低的任务, 对每个任务做中心化 $(\mathrm{acc}-\mathrm{acc}_{\mathrm{random}})/(1-\mathrm{acc}_{\mathrm{random}})$ 再平均, 0 对应随机, 1 对应全对, 不同选项数的任务可以直接平均.

第二个条件 DCLM 也检查过: 10 种数据方案在 400M-1x, 1B-1x, 3B-1x 上的 Core 分数与 7B-1x 的 Pearson 相关依次是 0.838, 0.956, 0.982. 规模越接近, 迁移越可靠. 这组数字是 [3.1](../3.1-预训练数据/3.1-预训练数据.md) 里所有过滤和配比结论的适用前提, 那些结论大多来自 1B 左右的消融. Llama 3 的另一种做法是在训练到一半的 8B 模型上做 40B token 的退火, 30% 给待评估的新数据, 比较退火后的下游分数 ([3.4.2](../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md) 第 4.1 节).

### 3.2 主训练与长上下文阶段

主训练过程中要看的是趋势. 3.6.2 第 4.2 节的建议是分领域 BPB, CF 格式的常识题和正确答案的对数概率, 单次 greedy 的 GSM8K 噪声太大不适合. 留出集要从训练配比的每个来源各留一份, 与训练集按文档级去重, 再加一两份训练截止日期之后的新语料估计泄漏和漂移. 子集之间 BPB 可以差 3 倍 (Chinchilla 在 Pile 的代码子集上是 0.337, 合成数学题是 1.111), 所以按子集分别画曲线, 只看加权平均会被配比左右.

长上下文阶段用的是门槛. Llama 3 每次加长窗口之前检查两件事: 短上下文评测完全恢复, 当前长度的 NIAH 全部正确, 两条都满足才进入下一阶段 ([3.5](../3.5-继续预训练与长上下文训练/3.5-继续预训练与长上下文训练.md)). NIAH 在这里只是必要条件: RULER 附录里 GPT-4, Llama3.1 8B, Yi 34B, LWM 7B 的 passkey 在 4K 到 128K 全是 100, 按 13 个任务平均分和及格线 85.6 定义的有效长度, Yi 34B 只有 32K, LWM 7B 不到 4K. 成本也要算进去: RULER 全套约 16 亿输入 token, 多数落在 64K 和 128K 的长 prefill 上, 中间 checkpoint 只跑 NIAH 和少量 RULER 任务更可行.

### 3.3 污染贯穿各阶段

测试题或答案出现在预训练数据里, 分数衡量的就有一部分是记忆. 常用检测有 13-gram 重叠 (GPT-3) 和随机取 3 段 50 字符子串 (GPT-4 技术报告), 两者都能被改写或翻译绕过: Yang 等人在改写过的 MMLU 测试题上微调 Llama-2-13B, MMLU 达到 85.9, n-gram 检测查不出来. 他们改用嵌入检索加强模型判别, 在 RedPajama-Data-1T 和 StarCoder-Data 里找到 8% 到 18% 的 HumanEval 题目改写版, 合成数据集 CodeAlpaca 中有 12.8% 是 HumanEval 的改写.

污染因此要在数据和评测两侧同时处理. 数据侧在训练前做 n-gram 去污 ([3.1.3](../3.1-预训练数据/3.1.3-数据处理/3.1.3-数据处理.md) 第 5 节), 合成数据 ([3.1.2](../3.1-预训练数据/3.1.2-合成与改写数据/3.1.2-合成与改写数据.md)) 要单独检查, 因为污染会经由模型生成的文本进入训练集. 评测侧可以报告污染率和未污染子集的分数, 用按发布时间切分的动态基准 (LiveCodeBench), 或在训练截止之后的新语料上测压缩率. 每种做法只挡住一部分来源, 3.6.2 第 5.2 节有一张对照表.

## 4. 读法

### 4.1 按关心的问题进

在训练中盯进度的读者先读 [3.6.1](./3.6.1-困惑度-PPL/3.6.1-困惑度-PPL.md): 第 2 节是 BPB 换算和窗口, 文档切法的影响, 第 4 节讲 BPC 与平均分的线性关系和「涌现」有多少来自度量选择, 第 5.2 节的表把常见的曲线异常 (训练 loss 降而留出 BPB 不降, 某一子集 BPB 突然升) 和要查的东西对应起来. 做数据消融的读者读 [3.6.2](./3.6.2-通用基准/3.6.2-通用基准.md) 第 3 节的格式敏感性和第 4 节的 Core 指标, 复现别人的分数前看第 6.1 节的复现清单.

负责长上下文阶段的读者读 [3.6.3](./3.6.3-大海捞针测试/3.6.3-大海捞针测试.md), 第 4.1 节给出每个 checkpoint 的一套最小检查, 第 3 节的 Lost in the Middle 说明 U 形位置效应在只做过预训练的基座上就已存在, 所以长上下文评测至少要扫开头, 中间, 结尾三个深度并报最差的那个. 关心代码和数学配比的读者读 [3.6.4](./3.6.4-特定能力评估/3.6.4-特定能力评估.md) 第 3.3 节的用法表, 多语言模型看第 3.1, 3.2 节: Global-MMLU 标注出 MMLU 有 28% 的题需要文化相关知识, 中文用 C-Eval 和 CMMLU 这类原生构建的基准.

### 4.2 与其他节的接口

评估结果的主要用途在前面几节. 数据过滤和配比 ([3.1](../3.1-预训练数据/3.1-预训练数据.md)) 靠小模型消融的分数做决定, 学习率日程和退火 ([3.4.2](../3.4-训练过程/3.4.2-预训练策略/3.4.2-预训练策略.md)) 决定中途 checkpoint 的 loss 能不能直接读, WSD 恒定段的 loss 偏高, 衰减之后才反映真实水平. 继续预训练 ([3.5.1](../3.5-继续预训练与长上下文训练/3.5.1-继续预训练/3.5.1-继续预训练.md)) 要同时看目标领域和原有能力两组指标.

tokenizer ([3.2](../3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md)) 影响所有 token 级指标, 也影响长上下文评测里的「128K」: 各评测都按各自模型的 tokenizer 计 token, LongBench 则用词数和字数报长度. Scaling Laws ([3.3.2](../3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md)) 外推的是 loss, 准确率是 loss 的非线性函数, Llama 3 用两步法从下游负对数似然再映射到准确率, 在 ARC Challenge 上外推了 4 个数量级.
