## 问题与显存

### 一个模型要几张卡, 怎么切

训练框架的选择回答两个问题: 模型状态和激活放在哪, 切开后的通信由谁承担. 先把显存的组成算清楚, 再看每种并行切掉哪一块.

![](./images/fig-3d-parallel.png)

> 图 1: 3D 并行. 单机 8 卡内做张量并行, 不同机器承担不同流水线段, 多份完整流水线之间做数据并行, 总卡数 = TP × PP × DP.

**图 1 解析**

- **左侧 Node 0**: 8 张 GPU 共同算同一层, 每张卡持有矩阵的一部分, 每层都要通信, 所以要求 NVLink.
- **中间一列**: Stage 0, 1, 2 位于不同节点, 每段负责连续的若干层, 段之间只传激活.
- **右侧多列**: 每一列是一份完整的模型副本, 各自处理不同的数据, 反向后同步梯度.
- **图里没有的维度**: 序列并行 (在 TP 组内), 上下文并行, 专家并行, 以及 DP 维度上的 ZeRO/FSDP 分片. 它们在第 2, 3, 4.4, 4.5 节.

这里关注的是「选哪种组合」, 每种并行的实现细节 (集合通信算法, 调度器代码, 通信与计算重叠) 放在 [6.1.1](../../../6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md).

**显存的组成: 模型状态 16 字节每参数**

ZeRO (Rajbhandari 等人 2020) 把混合精度 Adam 训练的模型状态拆成三部分. 参数量记 $\Psi$:

$$
M_{\mathrm{states}}=\underbrace{2\Psi}_{\text{FP16 参数}}+\underbrace{2\Psi}_{\text{FP16 梯度}}+\underbrace{K\Psi}_{\text{优化器状态}},\qquad K=12 \tag{1}
$$

$K=12$ 是 FP32 的参数主副本, 动量, 方差各 4 字节. 合计 $16\Psi$ 字节. ZeRO 给出的例子: GPT-2 1.5B 的 FP16 参数只要 3 GB, 模型状态至少 24 GB. 按式 (1):

- 7.5B: 120 GB (ZeRO Table 1 的 DP=1 一行).
- Llama 3 405B: $16\times405\times10^9=6.48$ TB.

BF16 训练同样需要 FP32 主副本和 FP32 优化器状态, 16 字节的口径不变. Llama 3 报告说明梯度累加和跨数据并行的 reduce-scatter 都用 FP32, 这部分在通信缓冲区里另外占显存.

**激活: 逐层公式**

Korthikanti 等人 (2022) 按 Transformer 层逐个张量统计需要为反向保存的激活. 记 $s$ 为序列长度, $b$ 为 micro-batch, $h$ 为隐藏维, $a$ 为头数, 16 位存储:

- 注意力块: QKV 投影输入 $2sbh$, $QK^\top$ 的输入 $4sbh$, softmax 输出 $2as^2b$, dropout mask $as^2b$, dropout 输出 $2as^2b$ 和 V $2sbh$, 输出投影输入 $2sbh$ 与 dropout mask $sbh$, 合计 $11sbh+5as^2b$.
- MLP 块: 两个线性层输入 $2sbh$ 和 $8sbh$, GeLU 输入 $8sbh$, dropout mask $sbh$, 合计 $19sbh$.
- 两个 LayerNorm: $4sbh$.

相加得 (原文式 1):

$$
M_{\mathrm{act}}^{\mathrm{layer}}=sbh\Bigl(34+5\frac{as}{h}\Bigr)\ \text{bytes} \tag{2}
$$

第二项来自注意力矩阵, 随 $s^2$ 增长. GPT-3 ($a=96$, $s=2048$, $h=12288$) 的 $5as/h=80$, MT-NLG ($a=128$, $s=2048$, $h=20480$) 为 64, 都超过其余部分的 34. GPT-3 配置下 $b=1$ 时每层激活约 2.87 GB, 96 层约 275 GB, 远超单卡. 式 (2) 是 GeLU MLP 的统计, SwiGLU 和 FlashAttention 会改变各项系数 (FlashAttention 不保存 $s^2$ 级的 softmax 矩阵), 但「激活随 $s$, $b$ 线性加上随 $s^2$ 增长的一项」这一结构不变.

ZeRO 论文给出另一个参照: GPT-2 1.5B, 序列 1K, batch 32 的激活约 60 GB; 激活检查点 (只存每层输入, 反向时重算) 能把它降到约 8 GB, 代价是约 33% 的重计算开销.

除去模型状态和激活, 还有通信缓冲区和显存碎片. ZeRO 把后两者称为 residual states. 选框架时主要看前两项: 模型状态由 DP 侧的分片 (ZeRO/FSDP) 和模型并行 (TP/PP/EP) 一起切, 激活由 TP+SP, PP, CP 和重计算切.

### 数据并行与 ZeRO / FSDP

**ZeRO 三个阶段**

纯数据并行每张卡持有完整的 $16\Psi$, 卡数增加不减少单卡显存. ZeRO 在 $N_d$ 路数据并行内分片:

| 阶段 | 分片内容 | 单卡模型状态 | 相对 DP 的缩减 |
|------|------|------|------|
| $P_{os}$ (ZeRO-1) | 优化器状态 | $4\Psi+K\Psi/N_d$ | 最多 4 倍 |
| $P_{os+g}$ (ZeRO-2) | 再加梯度 | $2\Psi+14\Psi/N_d$ | 最多 8 倍 |
| $P_{os+g+p}$ (ZeRO-3) | 再加参数 | $16\Psi/N_d$ | 与 $N_d$ 成正比 |

ZeRO Table 1 给出 7.5B 模型的单卡 GB 数:

| $N_d$ | $P_{os}$ | $P_{os+g}$ | $P_{os+g+p}$ |
|------|------|------|------|
| 1 | 120 | 120 | 120 |
| 4 | 52.5 | 41.3 | 30 |
| 16 | 35.6 | 21.6 | 7.5 |
| 64 | 31.4 | 16.6 | 1.88 |
| 256 | 30.4 | 15.4 | 0.47 |
| 1024 | 30.1 | 15.1 | 0.12 |

ZeRO-1 和 ZeRO-2 有下限: 卡数趋于无穷时分别逼近 $4\Psi=30$ GB 和 $2\Psi=15$ GB, 因为每卡仍保留完整的 FP16 参数 (和梯度). 只有 ZeRO-3 随卡数无限下降.

**通信量**

记一次 all-reduce 的数据量为 $2\Psi$: 它等于一次 reduce-scatter 加一次 all-gather, 各 $\Psi$. ZeRO 的分析:

- **DP, ZeRO-1, ZeRO-2**: 反向结束时对梯度做 reduce-scatter ($\Psi$), 各卡更新自己那一片参数后 all-gather ($\Psi$), 合计 $2\Psi$, 与 DP 相同.
- **ZeRO-3**: 前向和反向各需 all-gather 一次参数, 加上梯度的 reduce-scatter, 合计 $3\Psi$, 是 DP 的 1.5 倍.

所以 ZeRO-1/2 的显存节省不增加通信, ZeRO-3 用 1.5 倍通信换参数分片.

### FSDP

PyTorch FSDP (Zhao 等人 2023) 是 ZeRO-3 思路的工程实现, 引入分片因子 $F$:

- $F=1$: 等同 DDP.
- $F=W$ ($W$ 为总卡数): 完全分片, 通信是 DDP 的 1.5 倍.
- $1<F<W$: 混合分片. 在大小为 $F$ 的分片组内 reduce-scatter, 再在副本组之间 all-reduce. 分片组可以放在单机内, 让高频的 all-gather 走机内带宽.

FSDP 的实现要点:

- **FlatParameter**: 把一个 FSDP 单元的所有参数展平拼接后均分到 $F$ 张卡, 填充不超过 $F-1$ 个元素. 峰值参数显存为 $O(\sum_i\psi_i/F+\max_i\psi_i)$, $\psi_i$ 是第 $i$ 个单元的参数量: 常驻的是全部分片, 外加正在计算的那个单元的完整参数.
- **单元粒度**: 论文测得 all-gather 的元素数低于约 33M 时吞吐明显下降, 单元太细会被通信延迟拖慢.
- **限流**: 同时在途的 all-gather 最多 2 个, 防止提前预取占满显存.
- **接口**: `FullyShardedDataParallel` 包装器和 `fully_shard` 函数式接口.

Llama 3 的数据并行用 FSDP, 分片优化器状态和梯度; 前向结束后不重新分片参数, 免去反向时再 all-gather 一次. 这等于在参数上退回 ZeRO-2 的做法, 用显存换掉一次参数通信. DeepSeek-V3 的数据并行只用 ZeRO-1.

## 张量并行与序列并行

### Megatron 的切法

Megatron-LM (Shoeybi 等人 2019) 在层内切矩阵. MLP 的第一个矩阵按列切, 每张卡算出中间激活的一部分, 逐元素的 GeLU 可以在各卡独立做; 第二个矩阵按行切, 各卡输出部分和, 最终 all-reduce. 自注意力按头切: Q, K, V 投影按列切, 每张卡负责若干头; 输出投影按行切. 一个块里两个矩阵乘之间不需要同步.

原文用两个共轭算子描述通信: $f$ 前向恒等, 反向 all-reduce; $g$ 前向 all-reduce, 反向恒等. 每个 Transformer 层前向 2 次 all-reduce, 反向 2 次. 输入嵌入按词表维切, 嵌入后需要一次 all-reduce. Megatron-LM 用这套方法在 512 张 GPU 上训练 8.3B 模型, 全程 15.1 PFLOPs, 相对单卡 39 TFLOPs (峰值的 30%) 的扩展效率 76%.

这套切法的代价是通信. Narayanan 等人 (2021, PTD-P) 给出张量并行的通信量: 每层每 micro-batch 每卡 $8bsh\frac{t-1}{t}$ ($t$ 为张量并行度), 来自前向 2 次加反向 2 次 all-reduce, 每次 ring all-reduce 每卡收发 $2bsh\frac{t-1}{t}$. 这个量与层数成正比, 每层都要同步, 落在计算的关键路径上. 因此 PTD-P 的第一条结论是 TP 不超过单机 GPU 数, 让它走 NVLink. 他们的硬件是每节点 8 张 A100 80GB, 节点间 8 条 200 Gbps HDR InfiniBand.

### 序列并行

TP 只切了矩阵乘的输入输出, LayerNorm 和 dropout 的激活仍在每张卡上完整保存. Korthikanti 等人给出纯 TP 时每层激活为 $sbh(10+24/t+5as/(ht))$: 其中 $10sbh$ 是 LayerNorm 和 dropout 的部分, 不随 $t$ 下降.

序列并行沿序列维切这部分. TP 区域之外的张量在 $t$ 张卡上各持 $s/t$ 段, 进入 TP 区域前 all-gather, 离开时 reduce-scatter. 原来的 all-reduce 被换成 reduce-scatter 加 all-gather, 通信量相同. 激活变为 (原文式 4):

$$
M_{\mathrm{act}}^{\mathrm{TP+SP}}=sbh\Bigl(\frac{10}{t}+\frac{24}{t}+\frac{5as}{ht}\Bigr)=\frac{sbh}{t}\Bigl(34+\frac{5as}{h}\Bigr) \tag{3}
$$

即式 (2) 除以 $t$.

### 选择性重计算

式 (3) 中 $5as/h$ 那一项来自 softmax, dropout 等注意力内部的大张量, 但计算量小. Korthikanti 等人只对这一部分做重计算 (选择性激活重计算), 激活降为 $34sbh/t$. 对 GPT-3 和 MT-NLG 分别节省 70% 和 65% 的激活显存, 只增加 2.7% 和 1.6% 的 FLOPs. 他们 Table 2 汇总各方案的每层激活:

| 方案 | 每层激活 (字节) |
|------|------|
| 无并行 | $sbh(34+5as/h)$ |
| TP | $sbh(10+24/t+5as/(ht))$ |
| TP + SP | $sbh(34/t+5as/(ht))$ |
| TP + 选择性重计算 | $sbh(10+24/t)$ |
| TP + SP + 选择性重计算 | $sbh(34/t)$ |
| 全量重计算 | $2sbh$ |

两项技术合用时激活降到约 1/5, 是全量重计算的 2 倍左右. 在 2240 张 A100 上训练 530B 模型, MFU 从全量重计算的 42.1% 提高到 54.2%.

## 流水线, 上下文与专家并行

### 流水线的气泡

PP 把层分成 $p$ 段放在不同设备上, 一个 batch 拆成 $m$ 个 micro-batch 依次流过. 记号沿用 PTD-P: 总卡数 $n=p\cdot t\cdot d$, micro-batch 数 $m=B/(b\cdot d)$, $B$ 为全局 batch, $b$ 为 micro-batch 大小.

GPipe 和 1F1B 调度的气泡占比相同:

$$
\text{bubble}=\frac{p-1}{m} \tag{4}
$$

1F1B (PipeDream-Flush) 的好处在显存: 每段同时保存激活的 micro-batch 不超过 $p$ 个, GPipe 则要保存 $m$ 个. 交错调度把每张卡上的层再分成 $v$ 个不相邻的块 (虚拟段), 气泡降到:

$$
\text{bubble}_{\mathrm{interleaved}}=\frac{1}{v}\cdot\frac{p-1}{m} \tag{5}
$$

代价是段间通信增加 $v$ 倍. PTD-P 报告交错调度带来 10% 以上的吞吐提升. Llama 3 用的是交错调度, 报告给出的气泡形式同为 $\frac{p-1}{v\cdot m}$.

**PP 不按段数切激活**

PP 把参数按 $p$ 均分, 激活却不是. Korthikanti 等人分析 1F1B: 为了让流水线保持满载, 首段必须同时保存 $p$ 个 micro-batch 的激活, 每段 $L/p$ 层, 合计 $p\times L/p=L$ 层的激活, 与 $p$ 无关. 首段的激活总量 (原文式 5):

$$
M_{\mathrm{act}}^{\mathrm{first\ stage}}=\frac{sbhL}{t}\Bigl(34+\frac{5as}{h}\Bigr) \tag{6}
$$

交错调度要保存 $L\bigl(1+\frac{p-1}{pm}\bigr)$ 层的激活, 这里 $m$ 是原文记的交错段数 (即式 (5) 的 $v$). 所以加 PP 主要缓解参数和优化器状态的压力, 激活要靠 TP+SP 和重计算. 用选择性重计算后, 首段激活降为 $34sbhL/t$.

**流水线的段间通信与段的均衡**

段间只传激活和激活梯度, 每个 micro-batch 在相邻两段之间传 $bsh$ 个元素, 远少于 TP 每层 4 次 all-reduce. 这让 PP 适合跨机. PTD-P 的端到端实验中, PP 用到的二分带宽为 892 GB/s, DP 为 13 TB/s.

通信之外的问题是段的负载不均. 首段多了输入嵌入, 末段多了输出头和 loss, 层数平均分配时两端更慢. Llama 3 从首末两段各去掉一个 Transformer 层; 8K 序列训练时不做激活检查点. DeepSeek-V3 用自研的 DualPipe 调度, 在 16 路 PP 下重叠前向反向的计算与专家并行的通信 (见 [6.1.8](../../../6-训练与推理优化/6.1-训练基础设施/6.1.8-MoE系统与并行/6.1.8-MoE系统与并行.md)).

**上下文并行**

长序列阶段, 单条序列的激活可能超出 TP+SP 能承受的范围. 上下文并行 (CP) 把一条序列切到 CP 组的多张卡上, 每张卡负责一段 query.

Llama 3 的 CP 实现 (§3.3.2):

- **负载均衡**: 序列切成 $2\times\mathrm{CP}$ 块, 第 $i$ 个 rank 拿第 $i$ 块和第 $2\times\mathrm{CP}-1-i$ 块. 因果 mask 下靠后的 query 要看更多 key, 首尾配对让每个 rank 的计算量相近.
- **all-gather 而非 ring**: 先 all-gather 全部 K, V, 再算本地 Q 块. 理由有两条: 这样更容易支持文档 mask 等不同的注意力 mask; GQA 下 K, V 比 Q 小得多, 注意力计算是 $O(S^2)$, all-gather 是 $O(S)$, 暴露的通信延迟可以忽略.

128K 序列阶段, Llama 3 用 CP 16 (Table 4 第三行). ring 方式的 CP 把 K, V 分块在环上传递并与计算重叠, 实现见 6.1.1.

**专家并行**

MoE 的专家参数占总参数的绝大部分 (DeepSeek-V3 路由专家约占 97%, 见 [3.3.1](../../3.3-模型配置与Scaling-Laws/3.3.1-确定模型结构与参数/3.3.1-确定模型结构与参数.md) 第 4 节), 要分布到多张卡上. 专家并行 (EP) 让每张卡持有部分专家, token 经路由后用 all-to-all 发到专家所在的卡, 算完再 all-to-all 发回.

DeepSeek-V3 的配置: 每层专家分布在 8 个节点的 64 张 GPU 上, 并行组合为 16 路 PP, 64 路 EP, ZeRO-1 DP, 不使用 TP. 每个 token 最多路由到 4 个节点, 这一约束限制了跨节点 all-to-all 的流量. 训练用自研 HAI-LLM 框架, FP8 混合精度. DeepSeek-V3 报告训练中没有出现不可恢复的 loss spike, 也没有回滚.

EP 与 TP 的取舍: 不用 TP 就省掉每层 4 次 all-reduce, 但每张卡要放下所在流水线段的完整注意力层和非专家参数, 激活也不再按 $t$ 切分. DeepSeek-V3 的非专家参数只占总参的几个百分点, 专家部分由 64 路 EP 分摊, 16 路 PP 再把层切开, 单卡放得下.

**组合与 MFU**

### PTD-P 的两条规则

PTD-P 给出的组合规则:

1. **TP 放机内, PP 放机间**. TP 通信与层数成正比且在关键路径上, PP 通信只在段边界.
2. **模型并行规模刚好放得下即可**. 设模型并行规模 $M=t\cdot p$, 取能放下模型的最小值, 剩余卡数全部用于 DP. 原因是 PP 的气泡随 $p$ 增大: 固定全局 batch $B$ 和 micro-batch $b$ 时, 记 $b'=B/b$, $t=1$ 时气泡为 $(n-d)/b'$, $d$ 越大气泡越小.

micro-batch 大小本身也影响吞吐, PTD-P 测得最多带来 1.3 倍的单卡差异.

**训练时间估算**

PTD-P 给出 GPT 类模型的参数量和每次迭代 FLOPs ($l$ 层, $h$ 隐藏维, $V$ 词表, $s$ 序列长度, $B$ 全局 batch):

$$
P=12lh^2\Bigl(1+\frac{13}{12h}+\frac{V+s}{12lh}\Bigr),\qquad F=96Bslh^2\Bigl(1+\frac{s}{6h}+\frac{V}{16lh}\Bigr) \tag{7}
$$

$F$ 含激活重计算 (前向算两遍), 所以每 token 系数是 8 而不是 6: $96Bslh^2=8\times Bs\times12lh^2$. 训练 $T$ 个 token, $n$ 张卡, 每卡实际吞吐 $X$ FLOP/s:

$$
\text{训练时间}\approx\frac{8TP}{nX} \tag{8}
$$

代入 GPT-3: $P=175$B, $T=300$B, $n=1024$ 张 A100, $X=140$ TFLOP/s, 得 $2.93\times10^6$ 秒, 约 34 天. 1T 参数模型训练 450B token, 3072 张卡, $X=163$ TFLOP/s, 约 84 天 (原文值; 按式 (8) 算出 83.2 天). 后者的聚合吞吐 502 PFLOP/s, 为峰值的 52%; 他们测试的最小模型为峰值的 44%. PTD-P 还报告在 175B 和 530B 上比 ZeRO-3 (不用模型并行) 吞吐高 70%.

**MFU 的定义**

PaLM (Chowdhery 等人 2022) 附录 B 提出模型 FLOPs 利用率 (MFU): 实际 token 吞吐乘每 token 理论 FLOPs, 除以硬件峰值. 每 token 的矩阵乘 FLOPs 为 $6N$ (前向 $2N$, 反向 $4N$), 注意力另加 $6LH(2QT)$, $L$ 层数, $H$ 头数, $Q$ 头维, $T$ 序列长度. 峰值吞吐 $P$ 下的理论 token 速率:

$$
R=\frac{P}{6N+12LHQT} \tag{9}
$$

MFU 是实测 token 速率除以 $R$. 关键在于分子只计模型本身需要的计算, 不计重计算; 计入重计算的叫硬件 FLOPs 利用率 (HFU). 这样不同的重计算策略之间可以公平比较.

PaLM 540B 的算例: 每秒 238.3K token, 6144 张 TPU v4, 每张峰值 275 TFLOP/s. 不计注意力时 $\frac{238.3\times10^3\times6\times540\times10^9}{275\times10^{12}\times6144}=45.7\%$, 计入注意力为 46.2%; HFU 为 57.8%.

**公开的 MFU**

| 系统 | 硬件 | MFU |
|------|------|------|
| GPT-3 | V100 | 21.3% |
| Gopher | 4096 TPU v3 | 32.5% |
| MT-NLG | 2240 A100 | 30.2% |
| PaLM 540B | 6144 TPU v4 | 46.2% |
| Megatron 530B (TP+SP+选择性重计算) | 2240 A100 | 54.2% |
| MegaScale 175B | 12,288 GPU | 55.2% |
| Llama 3 405B | 8192 至 16384 H100 | 38% 至 43% |

前四行出自 PaLM Table 3. MegaScale (Jiang 等人 2024) 报告比同配置下的 Megatron-LM 高 1.34 倍. 这个倍数在卡数最多时最大: 175B 模型, 全局 batch 6144 条, Megatron-LM 的 MFU 从 3072 卡的 48.7% 降到 12,288 卡的 41.2%, MegaScale 从 59.1% 降到 55.2%. 卡数增加而全局 batch 不变, 每个 DP 组分到的 micro-batch 变少, 式 (5) 的气泡和暴露的通信都变大.

MegaScale 的提升来自几处改动:

- **并行 Transformer 块**: 把 $y=x+\mathrm{MLP}(\mathrm{LN}(x+\mathrm{Attention}(\mathrm{LN}(x))))$ 改写成 $y=x+\mathrm{MLP}(\mathrm{LN}(x))+\mathrm{Attention}(\mathrm{LN}(x))$, 注意力和 MLP 可以同时算. PaLM 也用这种结构, 报告在千亿参数规模上不损失质量.
- **滑动窗口注意力**: 每个 token 只看窗口 $w$ 内的 token, 计算从 $O(s^2)$ 降到 $O(sw)$.
- **LAMB 优化器**: 他们的实验里 LAMB 能把 batch 放大到 4 倍而不损失精度. 一步处理 4 倍 batch 时 $m$ 变为 $4m$, 按式 (5) 气泡占比降为原来的 1/4.
- **通信重叠**: DP 的 all-gather 在每个模型块前向开始前提前发起, reduce-scatter 与反向重叠; PP 把 send 和 receive 拆开, 不让慢的一方阻塞; TP/SP 的 all-gather 和 reduce-scatter 融合进相邻的矩阵乘.

不同硬件, 不同序列长度, 是否计入注意力 FLOPs 都会改变数值, 跨行比较只能看量级.

**Llama 3 405B 的三档配置**

Llama 3 Table 4:

| GPU | TP | CP | PP | DP | 序列长度 | 每 DP 组 batch | 每步 token | TFLOPs/GPU | MFU |
|------|----|----|----|----|------|------|------|------|------|
| 8192 | 8 | 1 | 16 | 64 | 8192 | 32 | 16M | 430 | 43% |
| 16384 | 8 | 1 | 16 | 128 | 8192 | 16 | 16M | 400 | 41% |
| 16384 | 8 | 16 | 16 | 8 | 131072 | 16 | 16M | 380 | 38% |

逐行验证: $8\times1\times16\times64=8192$, $8\times16\times128=16384$, $8\times16\times16\times8=16384$; 每步 token $64\times32\times8192=128\times16\times8192=8\times16\times131072=16.8$M. 三档的全局 batch 相同, 卡数翻倍时每个 DP 组的 batch 减半, 每段流水线的 micro-batch 变少, 气泡占比上升, MFU 从 43% 降到 41%. 第三行把 DP 的 16 倍换成 CP, 处理 128K 序列.

并行维度的顺序是 [TP, CP, PP, DP], 由内到外, 对应通信从密到疏: TP 放在 NVLink 连接的单机 8 卡内, DP 放在最外层, 可以跨越多跳的网络. 报告的说明是: 最内层要求最高带宽和最低延迟, 通常限制在同一台服务器内; 最外层可以跨多跳网络, 要能容忍更高延迟. DP (即 FSDP) 放最外层, 因为它可以异步预取分片权重, 异步归约梯度, 容忍较长的网络延迟. Llama 3 的集群单机 8 张 H100 (700W, 80GB HBM3), RoCE 网络每卡 400 Gbps, 3072 卡组成一个 pod, 汇聚层有 1:7 的超额订阅. 报告还提到他们开发了显存估算器和性能预测工具来搜索并行配置.

估算单卡显存: 405B 的 BF16 参数被 TP 和 PP 切成 128 份, 每卡约 $810/128=6.3$ GB; FSDP 再把梯度和优化器状态 ($14\Psi$, 约 5.67 TB) 按 $128\times64$ 份切, 每卡约 0.69 GB (第一行配置). 模型状态只占 80 GB 的一小部分, 其余留给激活, 这是 8K 序列下能不做激活检查点的前提.

### 算例: 70B 模型在 8K 序列上

用前面的公式走一遍 Llama 3 70B 量级的选择 ($\Psi=70.55$B, $l=80$, $h=8192$, $s=8192$, 80 GB 显存的卡). 激活用式 (2) 的 $34sbh$ 部分估算, 假设注意力用 FlashAttention 类实现, 不保存 $s^2$ 项; 34 这个系数来自 GeLU MLP, 用于 SwiGLU 只能给量级.

**模型状态**. $16\Psi=1.13$ TB.

- 只用 TP 8: 每卡 141 GB, 放不下.
- TP 8 加 ZeRO-1 (DP 64): FP16 参数和梯度 $4\Psi/8=35.3$ GB, 优化器状态 $12\Psi/(8\times64)=1.65$ GB, 合计约 37 GB.
- 不用 TP, 只用 FSDP 64 路完全分片: $16\Psi/64=17.6$ GB, 外加正在计算的那一层的完整参数 (约 1.7 GB).

**激活** ($b=1$).

- 无并行, 不重计算: 每层 $34sbh=2.28$ GB, 80 层 183 GB.
- 全量重计算: 每层只存输入 $2sbh$, 80 层 10.7 GB, 代价是每 token 计算从 $6N$ 变成约 $8N$.
- TP 8 加 SP 加选择性重计算: $34sbh/8$, 80 层 22.8 GB, 重计算开销只有几个百分点.

**通信**. TP 8 每层每 micro-batch 每卡 $8bsh\cdot\frac{7}{8}=470$M 个元素, BF16 下 80 层合计约 75 GB, 每个 micro-batch 都要发生, 而且在关键路径上. DP 的梯度同步是每步一次, $2\Psi=141$B 个元素, 可以与反向计算重叠.

结论与第 5.1 节的规则一致: FSDP 完全分片在模型状态上可行, 但 8K 序列的激活迫使它做全量重计算, 损失约四分之一的有效算力; TP 8 加 SP 加选择性重计算把激活和模型状态都压到 60 GB 左右, 代价是每层的机内通信, 所以 TP 必须放在 NVLink 范围内. 卡数再增加时, 用 PP 跨机, 继续保持每个 DP 组的 batch 足够大以压低气泡.

## 框架怎么选与边界

### 三个框架的分工

前面各节的并行方式由三个主流框架提供, 它们覆盖的范围和对模型代码的要求不同:

| 框架 | 提供的并行 | 侵入性 |
|------|------|------|
| Megatron-LM | TP, SP, PP (含交错), CP, EP, 分布式优化器 | 需要使用它的模型实现或按它的方式改写模型 |
| DeepSpeed | ZeRO-1/2/3, offload, 也可与 Megatron 的 TP/PP 组合 | ZeRO 对模型代码改动小 |
| PyTorch FSDP | 完全分片, 混合分片; 可与 PyTorch 原生 TP 组合 | 对模型代码改动小, 按模块包装 |

侵入性的差别来自切的位置. TP 和 SP 切的是层内的矩阵乘和激活 (第 3 节), 要改写注意力和 MLP 的前向, 所以 Megatron-LM 要求用它的模型实现; ZeRO 和 FSDP 只改参数, 梯度和优化器状态放在哪张卡上 (第 2 节), 模型的前向基本不动. 大规模训练常把两类叠起来用, 下面的公开配置里 OPT-175B 就是 FSDP 加 Megatron TP.

**按约束选**

下面的顺序由第 2 到第 5 节的结论推出:

1. **单卡放得下模型状态和激活**: DDP. 通信最少.
2. **单卡放不下全部模型状态, 但单层的参数和激活放得下**: ZeRO-3 或 FSDP. 不用改模型代码, 通信 1.5 倍. 卡数多时用混合分片把 all-gather 限制在单机内.
3. **单层放不下, 或长序列使激活过大**: 加 TP+SP, $t$ 不超过单机卡数. 再不够加 PP.
4. **几千卡规模追求 MFU**: Megatron 式 TP+PP+SP, 外层 DP 叠 ZeRO-1 或 FSDP. PTD-P 报告比 ZeRO-3 高 70%, Megatron 530B 的 MFU 54.2%.
5. **长上下文阶段或 MoE**: 长上下文加 CP, 并相应减小 DP; MoE 加 EP, 专家放在 EP 组内, 如果非专家部分单卡放得下, 可以像 DeepSeek-V3 那样不用 TP.

### 公开的选择

- **OPT-175B** (Zhang 等人 2022): 992 张 A100 80GB, FSDP 加 Megatron TP, 每卡 147 TFLOP/s.
- **PaLM 540B**: 每个 pod 内 12 路模型并行乘 256 路 FSDP, 两个 pod 之间用 Pathways 做数据并行, 不使用流水线.
- **Llama 3 405B**: FSDP 加自研 TP, CP, PP, 第 5.5 节的三档配置.
- **DeepSeek-V3**: HAI-LLM, PP 16, EP 64, ZeRO-1, DualPipe, FP8, 无 TP.
- **Llemma** (Azerbayev 等人 2023, Code Llama 上继续预训练): GPT-NeoX, 256 张 A100 40GB, 7B 用 TP 2, 34B 用 TP 8, 数据并行叠 ZeRO-1, 用 FlashAttention-2.

PaLM 不用 PP, DeepSeek-V3 不用 TP. PTD-P 的两条规则是在 8 卡 NVLink 加 InfiniBand 的 GPU 集群上总结的; 硬件互连 (TPU pod 内的拓扑, 不同 GPU 的机内带宽) 和模型结构 (MoE 的专家占比) 一变, 哪种通信更便宜也跟着变, 组合要按第 5.6 节的方式重新核算.

### 边界

本文的几个公式都带着假设:

- **式 (1) 只覆盖 Adam**. 换成只保存一个动量的优化器, 或优化器状态用低精度存储, $K$ 会变小.
- **式 (2) 是 GeLU MLP 加标准注意力**. SwiGLU 多一个中间张量, FlashAttention 不保存 softmax 矩阵, GQA 改变 K, V 的大小. 用它估算时要按实际结构重算各项.
- **式 (4) (5) 假设各段耗时相等**. 首末段的额外负载, MoE 层与稠密层的混排都会让实际气泡更大.
- **MFU 依赖 FLOPs 口径**. 是否计入注意力, 是否用 $6N$ 还是逐项计数, 峰值按稠密还是稀疏算, 都会改变数值.

通信与计算的重叠, 集合通信算法 (ring, tree), NCCL 调优, 低精度通信, offload 到 CPU/NVMe 会改变上面的通信和显存估算, 这些在 [6.1.1](../../../6-训练与推理优化/6.1-训练基础设施/6.1.1-分布式训练/6.1.1-分布式训练.md) 和 [6.2.1](../../../6-训练与推理优化/6.2-显存与计算分析/6.2.1-显存占用分析/6.2.1-显存占用分析.md). 故障恢复和 checkpoint 在 [3.4.3](../3.4.3-训练容灾与监控/3.4.3-训练容灾与监控.md).

不同框架和论文给同一件事起了不同的名字. 最常混的是序列并行和上下文并行: Megatron 的序列并行只在 TP 组内切 LayerNorm 和 dropout 的激活 (第 3.2 节), 上下文并行切的是注意力本身 (第 4.4 节). 下表列出几组:

| 名字 | 含义 | 容易混淆的对象 |
|------|------|------|
| 序列并行 (Megatron SP) | TP 组内沿序列切 LayerNorm/dropout 激活, 不切注意力 | 上下文并行 CP, 它切注意力本身 |
| 上下文并行 (CP) | 沿序列切 query, 交换 K, V | ring attention 是 CP 的一种实现, Llama 3 用 all-gather 实现 |
| ZeRO-3 | 参数, 梯度, 优化器状态都分片 | FSDP 完全分片是同一思路的 PyTorch 实现 |
| 模型并行 (PaLM 用语) | 层内切分, 相当于 TP | 有些文献把 TP 和 PP 合称模型并行 |
| MFU / HFU | 前者不计重计算, 后者计入 | 实测 TFLOPs/GPU 通常按 HFU 口径 |
| 分布式优化器 (Megatron) | 优化器状态按 DP 分片 | 等价于 ZeRO-1 |
