# 4.3 参数高效微调 (PEFT)

4.2 节的 SFT 和 4.4 到 4.6 节的 RL, 偏好优化默认更新全部参数. 全参数微调的瓶颈在显存和存储: 每个下游任务都要存一份完整模型, 训练时还要放下梯度和优化器状态. PEFT 冻结底座, 只训练一小部分参数或新增的小模块. 它改的是「哪些参数可训练」, 不改训练目标, 所以 SFT, DPO 和 GRPO 都可以挂在 PEFT 上跑, 后训练框架里的 LoRA 开关就是这个用法.

两篇文章分工明确. [4.3.1 LoRA 低秩适应](./4.3.1-LoRA低秩适应/4.3.1-LoRA低秩适应.md) 只讲一类方法, 从公式, 初始化, 缩放讲到 QLoRA, DoRA 和 rsLoRA, 最终讲 LoRA 的边界. [4.3.2 PEFT 方法全景](./4.3.2-PEFT方法全景/4.3.2-PEFT方法全景.md) 横向比较选择式, 附加式, 重参数化式和混合式四类, 用 He 等人的统一公式把它们放到同一组设计维度上.

## 1. 显存开销与低秩假设

### 1.1 每个参数 16 字节

混合精度 Adam 训练时, 每个参数要存 fp16 权重和梯度各 2 字节, fp32 主权重, 一阶矩, 二阶矩各 4 字节, 合计 16 字节. 7B 模型仅模型状态就约 108GB, 还没算激活. 冻结底座之后, 底座只需 2 字节的权重, 梯度和优化器状态只为可训练参数保留. LoRA 论文在 GPT-3 175B 上报告, 训练显存从 1.2TB 降到 350GB, 检查点从 350GB 降到约 35MB, 训练吞吐提高约 25%.

QLoRA 再往下压一步, 把冻结的底座量化成 4-bit. 它让梯度穿过 4-bit 底座传到 LoRA 参数上, 65B 模型的微调显存从 780GB 以上降到 48GB 以内. 存储也随之改变: 一个底座加若干个几十 MB 的适配器, 可以在部署时按任务切换.

### 1.2 低秩假设成立在哪里

LoRA 的出发点是微调的更新量 $\Delta W$ 本身低秩. 证据来自 Aghajanyan 等人的内在维度实验: 只优化 200 个参数再随机投影回全参数空间, RoBERTa 在 MRPC 上能达到全参数微调 90% 的性能, 而且模型越大, 内在维度越低. LoRA 原论文的秩扫描也支持这一点, 18M 参数预算下 $r=1$ 已接近 $r=64$.

这个假设有边界. Biderman 等人比较了 LoRA 与全参数微调在代码和数学上的表现, 全参数微调学到的扰动秩是常见 LoRA 配置的 10 到 100 倍. 代码继续预训练 200 亿 token 后, HumanEval 上全参数 0.263, LoRA $r=256$ 只有 0.224. LoRA 原论文的 WikiSQL, MNLI, SAMSum 主要是让模型适应格式, 代码和数学的继续预训练要灌入大量新知识, 两者离底座的距离不同, 低秩假设成立的程度也不同.

## 2. 四类方法的设计空间

### 2.1 改哪些参数

Lialin 等人的综述按「改什么参数」把 PEFT 分成选择式, 附加式, 重参数化式, 再加组合前三者的混合式. 下表取 Llama 2 7B 的形状 (32 层, $d=4096$, 线性层无偏置) 算典型配置的参数量:

| 方法 | 类别 | 典型配置参数量 | 推理时额外开销 | 已知弱点 |
|---|---|---|---|---|
| BitFit | 选择式 | 不适用 (无偏置) | 无 | 生成任务上与全参数差 4 到 6 分 ROUGE-1 |
| Prompt Tuning | 附加式 | 0.41M ($l=100$) | 占 100 个位置的上下文 | 小模型上与全参数差距大 |
| Prefix-tuning | 附加式 | 2.62M ($l=10$) | 占用 KV 长度 | 训练需要重参数化 MLP |
| Adapter (Houlsby) | 附加式 | 33.82M ($m=64$) | batch 1 时延迟增加 20.7% 到 30.3% | 不能合并进原权重 |
| LoRA | 重参数化式 | 8.39M (qkvo) / 19.99M (全部线性层) | 合并后无 | 继续预训练上学得少 |

表的最终两列比参数量更影响选型. Prompt Tuning 参数最少, 但占上下文; Adapter 串联在主干上, 在线服务 batch 小, 序列短时延迟代价最明显; LoRA 训练完把 $BA$ 加回 $W_0$, 推理和原模型一样. LLaMA 一类模型的线性层没有偏置, BitFit 无从下手, 这是它在大模型时代很少出现的直接原因.

各类方法在小模型分类任务上的成绩接近: BitFit 只训 0.09% 的参数, GLUE 82.4 对全参数 82.3; Houlsby Adapter 用 3.6% 的参数, 与全参数差 0.4 以内; Prompt Tuning 在 T5-XXL 上追平多任务全参数微调. 差距出现在生成任务和更大的数据上, 这也是 4.3.2 反复提醒的一点: 在 GLUE 上「与全参数相当」的结论, 推不到摘要和翻译上.

### 2.2 统一视角

He 等人 (2022) 把 Prefix-tuning 改写成加法形式后, 发现几类方法都可以写成

$$
h\leftarrow(1-\gamma)\,h+\beta\,\Delta h, \tag{1}
$$

区别在 $\Delta h$ 用什么函数算, 插在注意力还是 FFN, 串联还是并联, 以及 $\beta$ 是否缩放. 在 XSum 和 En-Ro 上的结论有三条: 并联好于串联; 参数多时改 FFN 好, 只有 0.1% 时改注意力的多头方法至少高 1.6 BLEU; 加缩放好于直接相加.

据此组合出的 MAM Adapter 在注意力上用 prefix, FFN 上用缩放的并联 Adapter, 总共 6.7% 参数, XSum 45.06/21.90 对全参数 44.81/21.94, En-Ro 37.5 对 37.3. UniPELT 走另一条路, 把 Adapter, Prefix, LoRA 同时装进模型, 用门控让训练决定激活哪个. LoRA 在式 (1) 里对应的是并联, 带缩放 $\alpha/r$ 的那一格.

## 3. LoRA 一族

### 3.1 公式, 初始化与秩

LoRA 冻结 $W_0\in\mathbb R^{d\times k}$, 只训练 $B\in\mathbb R^{d\times r}$ 和 $A\in\mathbb R^{r\times k}$:

$$
h=W_0x+\frac{\alpha}{r}BAx,\qquad r\ll\min(d,k). \tag{2}
$$

$B$ 初始化为零, 训练开始时 $\Delta W=0$, 模型输出与底座完全一致. $\alpha/r$ 让换秩时不必重调学习率, rsLoRA 指出秩较大时应改用 $\alpha/\sqrt r$, 否则大秩的更新被过度缩小. GPT-3 上 $r=4$ 只适配 $W_q, W_v$, WikiSQL 73.4 对全参数 73.8; 同样 18M 参数, 同时适配 $W_q, W_v$ 比只适配单个矩阵好.

注入位置的结论后来有变化. LoRA 原论文只在注意力上做实验, Biderman 等人在 Llama-2-7B 上发现只适配注意力不如只适配 MLP, 覆盖全部线性层的增益主要来自 MLP. LoRA 学到的更新量也不大: $r=4$ 时 $\|\Delta W_q\|_F=6.91$, 约为 $\|W_q\|_F=61.95$ 的 11%, 而且集中在少数几个方向上, 原论文的分析是它放大了 $W$ 中原本不显著的方向. LoRA 的学习率通常比全参数高一个数量级左右, 照搬全参数的学习率会让适配器几乎学不动.

两种变体各补一个短板. QLoRA 用 NF4 量化底座, 双重量化把缩放常数的开销从每参数 0.5 bit 降到约 0.127 bit, 65B 上约省 3GB, 分页优化器处理显存尖峰; Guanaco 65B 在 Vicuna 基准上达到 ChatGPT 的 99.3%. DoRA 把权重拆成幅度和方向, 方向用 LoRA 更新, 幅度单独训练, LLaMA-7B 常识推理平均从 LoRA 的 74.7 升到 78.4.

### 3.2 学得少, 忘得也少

Biderman 等人的另一半结论是 LoRA 更好地保住了目标领域之外的能力. 以 HellaSwag, ARC-Challenge, WinoGrande 平均作为遗忘指标, 代码继续预训练后全参数为 0.545, LoRA 为 0.617, 代码指令微调后为 0.414 对 0.509. LoRA 的遗忘也少于 weight decay 和 dropout 这类常见正则, 生成多样性保持得更好. 他们的建议是: 用 LoRA 做指令微调, 不做继续预训练; 显存允许时覆盖所有模块, $r=256$, $\alpha=2r$, 学习率通常比全参数高一个数量级.

这个现象和 4.10 节的持续学习结论方向一致. 4.10 节用相对基座的 KL 预测遗忘量, LoRA 的秩约束限制了更新能走的方向数, 同样把模型留在底座附近. 但两者不是一回事: 秩小不保证 KL 小, 4.10 节也明确提醒冻结参数不等于零遗忘, 输出还受适配器和解码配置影响.

## 4. 选型与延伸

### 4.1 按约束选方法

显存是主要约束时, 先用 LoRA, 放不下再上 QLoRA; 4.3.1 第 5 节给出了 QLoRA 的超参和 NF4 的构造. 推理延迟敏感, 要在线切换多个任务时, 选可合并的 LoRA, 不选 Adapter, 理由见 [4.3.2](./4.3.2-PEFT方法全景/4.3.2-PEFT方法全景.md) 第 3.2 节的延迟测量. 任务需要大量新知识, 例如代码或数学的继续预训练, 读 [4.3.1](./4.3.1-LoRA低秩适应/4.3.1-LoRA低秩适应.md) 第 6 节后再决定, 那里的数字显示 LoRA 最大的秩也追不上全参数.

PEFT 在视觉和多模态模型上也常用, 4.3.2 第 6 节整理了视觉 Adapter 和视觉提示的做法. 只想知道 LoRA 怎么配的读者, 4.3.1 的初始化, 缩放和注入位置三小节就够; 想理解为什么 Adapter, Prefix, LoRA 能互相换的读者, 读 4.3.2 第 5 节的统一视角.

### 4.2 与训练目标的组合

PEFT 和训练目标正交. 在 [4.2 SFT](../4.2-SFT/4.2-SFT.md) 上它是最常见的组合; 在 [4.6 偏好优化](../4.6-偏好优化/4.6-偏好优化.md) 上挂 LoRA 时, DPO 的参考模型可以直接用关掉适配器的同一份权重, 省掉一份模型. 在 [4.5 节的 GRPO](../4.5-GRPO家族与RLVR/4.5-GRPO家族与RLVR.md) 上挂 LoRA 同样可行, 参考模型的 KL 项也能这样算; RL 每步还要做大量采样, 这部分开销 LoRA 省不掉.

4.2.3 的 ASFT 需要底座的 logits 做 KL 锚点, LoRA 下底座和策略共享权重, 关掉适配器做一次前向就能拿到, 不必多存一份模型. 多阶段后训练的能力回退和遗忘问题, 统一放在 [4.10 持续学习](../4.10-持续学习/4.10-持续学习.md) 里讨论.
