# 2.6 · MoE

稠密 Transformer 的参数量和每 token 计算量绑在一起: FFN 宽一倍, 每个 token 的矩阵乘也多一倍. MoE (Mixture of Experts) 把一层 FFN 换成 $N$ 个专家和一个路由器, 每个 token 只进入 $K\ll N$ 个专家, 参数按 $N$ 计, 计算按 $K$ 计. 这一拆分带出三个连续的问题: 离散的 Top-$K$ 选择怎样训练, 专家负载怎样保持均匀, 专家怎样切分才分工明确. 下面四篇按这个顺序展开, 这一页先把它们共用的公式和记号定下来.

## 1. 从全部专家加权到稀疏门控

### 1.1 思想起源与条件计算

专家加门控的结构比 Transformer 早得多. Jacobs, Jordan, Nowlan, Hinton 1991 年的 Adaptive Mixtures of Local Experts 已经写出了这种形式: 记 token 隐状态 $x\in\mathbb{R}^d$, 专家 $E_i:\mathbb{R}^d\to\mathbb{R}^d$, 路由矩阵 $W_g\in\mathbb{R}^{N\times d}$, 输出是全部专家的加权和

$$
y=\sum_{i=1}^{N} g_i(x)\,E_i(x),\qquad g(x)=\operatorname{Softmax}(W_g x) \tag{1}
$$

式 (1) 里每个 $g_i(x)>0$, 每个专家都要算一遍, 计算量随 $N$ 线性增长, 专家数加多了并不省算力. 条件计算的做法是把多数门控置零, 只保留选中集合 $\mathcal{S}(x)$:

$$
y=\sum_{i\in\mathcal{S}(x)} g_i(x)\,E_i(x),\qquad |\mathcal{S}(x)|=K\ll N \tag{2}
$$

未被选中的专家这一步不做前向, 也不存激活. Shazeer 等人 2017 年用 noisy Top-$K$ 门控把式 (2) 放进 LSTM 语言模型; GShard (2020) 在 Transformer 里隔层放 MoE, 每 token 选 2 个专家, 在 2048 个 TPU v3 core 上用 4 天训出 600B 参数的翻译模型; Switch Transformer (2021) 把 $K$ 降到 1. 这三步的门控细节在 [02 MoE 路由](02-MoE路由与Top-K可导性/02-MoE路由与Top-K可导性.md) 第 1 节.

### 1.2 四篇共用的记号

各篇统一用 $N$ 表示路由专家数, $K$ 表示每 token 激活的路由专家数, $T$ 表示参与统计的 token 数, $d$ 表示残差流宽度, $H$ 表示专家 FFN 的中间维. 03 与 04 讨论均衡时沿用 Switch 与 K3 报告的小写写法, 用 $k$ 表示每 token 激活数, 用 $m$ 表示一个训练步的 token 数. DeepSeek 系列把共享专家单独计数, 写成 $N_s$ 个共享专家, $N_r$ 个路由专家, 激活 $K_r$ 个; Kimi K3 又多一个路由专家的潜空间宽度 $\ell$.

门控 FFN 的一个专家有门, up, down 三个矩阵, 参数是 $3dH$ (在潜空间里是 $3\ell H$), 各篇估算参数和通信量都从这个数出发. 读 MoE 的配置要分开总参数, 每 token 激活参数, 以及只算路由专家池的稀疏度三个数, 它们的区分和 Mixtral, DeepSeek-V3, Kimi K3 的逐项估算集中在 [03](03-MoE负载均衡与容量/03-MoE负载均衡与容量.md) 第 5.1 节, 其余各篇引用时不再重算.

## 2. 训练一个离散选择

### 2.1 门控顺序与 Top-K 的梯度

Token-Choice 路由里, 每个 token 给全体专家打分, 自己挑 Top-$K$. 同样叫 Top-$K$ 门控, 实现有两种顺序. 先 Top-$K$ 再 Softmax 时, 选中门控之和为 1, Shazeer 2017, Mixtral 和 Qwen 系用这一种; 先 Softmax 再截断时, 门控直接取全局 Softmax 的值, 和小于 1, Switch 和 DeepSeek V1–V2 用这一种. 02 第 1.4 节的例子里, 8 个专家的全局概率中 Top-2 是 0.31 和 0.28, 按第二种写法门控和为 0.59, 按第一种重新归一化为 0.525 和 0.475, 两者选中的专家相同, FFN 分支的输出尺度相差约 1.7 倍. DeepSeek-V3 走第三条路: 逐专家 Sigmoid 打分, 选中后在选中集合上归一化.

匹配也可以反过来做. Expert-Choice 让每个专家在一组 token 里挑固定数量的 token, 负载按构造均匀, 代价是选择依赖同组的后续 token, 02 第 1.3 节推出了它能泄露的信息量下界. 不论哪种匹配, 选中集合对输入是分段常值的, 指示函数没有梯度, 路由器只能经由选中专家的门控值学习. ReMoE 用 ReLU 替换 Top-$K$, Soft-MoE 把离散派遣改成 token 与 slot 的连续混合, SparseMixer 与 GRIN 估计离散选择项的梯度, 三条路线的代价比较在 02 第 3, 4 节.

### 2.2 负载偏斜, 容量与辅助损失

Token-Choice 不约束每个专家收到多少 token, 偏斜还会自我强化: 热门专家拿到更多梯度, 输出变好, 路由器更倾向选它; 冷门专家没有 token, 也就没有梯度. 长期下去少数专家处理大部分 token, 这就是专家坍塌. 固定形状的实现给每个专家 $C=\lceil Tk\gamma/N\rceil$ 个槽位, $\gamma$ 是容量因子, 超出的派遣被跳过, token 只剩残差. [03](03-MoE负载均衡与容量/03-MoE负载均衡与容量.md) 第 1.2 节的例子是 16 个 token 里 10 个挤进同一个专家, $\gamma=1$ 时丢弃率和 padding 率都是 50%, 把 $\gamma$ 提到 1.25 丢弃率只降到约 44%, 空槽反而从 8 个涨到 15 个. 容量因子只能吸收均衡之后剩下的波动, 偏斜本身要靠训练目标压下去.

Switch 的辅助损失是 $L_{\mathrm{balance}}=N\sum_i f_iP_i$, $f_i$ 是专家 $i$ 的 Top-1 选择频率, $P_i$ 是平均路由概率, 系数取 $10^{-2}$. $f_i$ 不可导, 梯度只经过 $P_i$, 方向是把概率从高于平均频率的专家移向低于平均的专家; 03 第 2.2 节说明了它的极小点不在均匀分布上, 均匀成为稳定点靠的是 $f$ 与 $P$ 的耦合. 之后的改法分三路: ST-MoE 的 router z-loss 压住路由 logits 的尺度, MegaBlocks 用块稀疏矩阵乘做到不丢 token (dropless), Loss-Free Balancing 用只参与排序的偏置替代辅助损失. 统计范围也改变约束的含义, 03 第 4.3 节的对照里, 按 batch 统计的辅助损失比按单条序列统计的验证损失更低, 不受序列内均衡约束的偏置方法也呈现更明显的领域分工.

## 3. 专家怎样切分: DeepSeekMoE 与 Stable LatentMoE

### 3.1 细粒度切分与共享专家

[01 DeepSeek-MoE](01-DeepSeek-MoE/01-DeepSeek-MoE.md) 从两个现象出发: 专家数少时一个专家要覆盖多种模式 (知识混杂), 不同专家又各自重复存一份通用变换 (知识冗余). 细粒度切分把每个宽专家沿中间维切成 $m$ 段, 专家数和激活数同时乘 $m$, 参数和 FLOPs 不变, 组合数从 $N=16$ 选 2 的 120 种涨到 64 选 8 的约 44 亿种. 共享专家不经路由, 每个 token 都经过, 系数恒为 1. 2B 验证实验在总参和激活参对齐的条件下给出 Pile loss: Dense 2.060, Hash Layer 1.932, Switch 1.881, GShard 1.867, DeepSeekMoE 1.808; 关掉共享专家改为多激活一个路由专家, loss 升到 2.414.

V2 和 V3 在这个结构上改的是门控和均衡. V2 加了设备受限路由 (每 token 最多去 3 台设备) 和专家级, 设备级, 通信级三级辅助损失; V3 换成 Sigmoid 亲和度, 选中集合归一化, 每步按负载给偏置加减 $\gamma=0.001$, 只保留系数 0.0001 的序列级损失, 并把设备限制改成节点限制 (每 token 最多 4 个节点). 01 第 3.3 节的消融里, 228.7B 模型去掉辅助损失改用偏置后 HumanEval 从 40.2 到 46.3, GSM8K 从 70.7 到 74.5, MMLU 则从 68.3 降到 67.2.

### 3.2 潜空间路由专家与分位数均衡

[04](04-Stable-LatentMoE与Quantile-Balancing/04-Stable-LatentMoE与Quantile-Balancing.md) 处理的是专家数再放大一个量级以后的事. Kimi K3 每层 896 个路由专家选 16 个, 若仍按满宽 $d=7168$ 派发, 每 token 每层单向 dispatch 是 $16\times7168=114688$ 个元素, 比 K2 的 Top-8 翻了一倍. LatentMoE 让路由专家在宽度 $\ell=3584$ 的潜空间里计算, dispatch 回到 $16\times3584=57344$, 与 K2 相同; 路由器仍读满宽的 $x$, 只有派发的对象是降维后的 $z$. K3 在原始 LatentMoE 上加了两处稳定性改动: 聚合后升维前加 RMSNorm, 专家内用 $\beta_1=4$, $\beta_2=25$ 的 SiTU-GLU 给乘积加上界 100.

均衡方面, K3 认为定步长偏置在近 $10^3$ 个专家上跟不上负载变化. Quantile Balancing 在一次前向里取 Top-$(k{+}1)$, 第 $k{+}1$ 名的分数当作每个 token 的截止线, 再对每个专家求 margin 的 $(1-k/n)$ 分位数, 直接解出让它恰好收到 $q=mk/n$ 个 token 的偏置. 04 第 4 节把这一步推成均衡指派线性规划的对偶坐标更新, 定步长的符号更新是同一个对偶目标上的 SignSGD. 偏置只用于下一步, 推理时冻结.

### 3.3 五种门控方案的对照

| 方案 | 亲和度 | 门控归一化 | 负载控制 | 代表 |
|------|--------|-----------|---------|------|
| Switch | 全局 Softmax | 不归一化, $K=1$ | 辅助损失 $10^{-2}$, 容量因子 | Switch Transformer |
| 先 Top-$K$ 再 Softmax | Softmax | 选中集合内和为 1 | 辅助损失 | Mixtral, Qwen |
| DeepSeek V1/V2 | 全局 Softmax | 不归一化, 和小于 1 | 专家, 设备, 通信三级损失 | DeepSeekMoE, V2 |
| aux-loss-free | Sigmoid | 选中集合内和为 1 | 定步长偏置 + 极小序列级损失 | DeepSeek-V3 |
| Quantile Balancing | Sigmoid | 选中集合内和为 1 | 分位数直接求偏置 | Kimi K3 |

表里的分歧集中在两列. 归一化一列决定 FFN 分支的输出尺度: 和小于 1 的写法在 Sparse Upcycling 里会让复制出来的专家输出整体缩小 (01 第 4.1 节), 和为 1 的写法才能在初值处保持原稠密 FFN 的函数. 负载控制一列从「加进损失」走到「只改排序」: 损失项的梯度和主任务争路由器, 偏置不进损失也不改门控数值, 只改变选中集合.

后两行的差别只在偏置怎么更新. 定步长更新要在跟不上与振荡之间取一个 $\gamma$, 分位数更新每步直接算出目标偏置, 不需要这个超参数. 两者推理时都退化成带固定偏置的 Top-$K$, 部署形式相同.

## 4. 读法与相邻章节

### 4.1 按背景选起点

第一次接触 MoE 的读者从 02 读起, 它把式 (2) 的三种匹配方式, 两种门控顺序和 Top-$K$ 的默认反向写到可以手算; 接着读 03, 容量因子和辅助损失的数字例子都用同一组 16 个 token. 这两篇定下的 $f_i$, $P_i$, $C$, $\gamma$ 在后面两篇反复出现. 之后按时间读 01 和 04: 01 是 DeepSeek 从 V1 到 V3 的结构与门控演进, 04 是 Kimi K3 在近千专家规模上对 01 的偏置方案和 LatentMoE 的改写, 04 第 3.1 节直接以 V3 的式子为起点.

带着具体问题来的读者可以直接跳. 训练中少数专家吃满, 先看 03 第 4 节的 dropless 与偏置, 再对照 01 第 3 节各版本的系数. 从一个开源实现迁移到另一个以后输出尺度变了, 多半是门控归一化顺序不同, 02 第 1.4 节的数值例子可以直接复现这个差距. 低精度训练里路由支路激活爆炸, 04 第 2 节的 RMSNorm 和 SiTU-GLU 是 K3 的处理. 想从稠密 checkpoint 起步的, 读 01 第 4.1 节的 Upcycling 与门控和的推导.

### 4.2 与相邻章节的边界

这四篇推导路由, 负载均衡, 专家结构和 Top-$K$ 的梯度, 涉及系统的地方只写到理解机制所需的量级. 专家并行, All-to-All 通信, 冗余专家与 prefill / decode 部署放在 [6.1.8 MoE 系统与并行](../../6-训练与推理优化/6.1-训练基础设施/6.1.8-MoE系统与并行/6.1.8-MoE系统与并行.md); 专家权重的量化方法放在 [6.3.1 量化 05 · MoE 量化](../../6-训练与推理优化/6.3-模型压缩/6.3.1-量化/05-MoE模型量化技术综述/05-MoE模型量化技术综述.md); FPGA, 近数据计算等专用硬件放在 [9.1.5 MoE 硬件与加速](../../9-AI工程化与基础设施/9.1-硬件基础/9.1.5-MoE硬件与加速/9.1.5-MoE硬件与加速.md); 另一种按 token 条件选参数的结构是 [2.8.3 条件记忆与 Engram](../2.8-其他架构方向/2.8.3-条件记忆与Engram/2.8.3-条件记忆与Engram.md), 它用局部 N-gram 做哈希查表, 与 MoE 分摊稀疏参数预算, 选择依据是 token ID 而不是路由器打分.

DeepSeek-V2/V3 和 K3 里与 MoE 同层出现的注意力结构是 MLA. MLA 的潜变量 $c^{KV}$ 进 KV Cache, LatentMoE 的 $\ell$ 维表示只在 FFN 里派发, 两个潜空间位于同一层的不同子层, 互不相干, 见 [03 MLA](../2.2-注意力机制/2.2.2-多头注意力变体/03-MLA-低秩潜变量与解耦RoPE/03-MLA-低秩潜变量与解耦RoPE.md). 把 MLA 的显存收益算进 MoE, 或者把 LatentMoE 的 $\ell$ 当成 KV 压缩维, 都会让参数和带宽估算出错.
