# 2.3 · 注意力的高效实现

标准注意力 $O=\operatorname{softmax}(QK^\top/\sqrt d)V$ 的计算量是 $O(n^2d)$. 当序列长到几千, 先成为瓶颈的往往是显存和带宽: 朴素实现要把 $n\times n$ 的分数矩阵 $S$ 和概率矩阵 $P$ 写进显存再读出来. $n=131072$ 时, 一个头一条序列的 $S$ 按 FP32 计约 68.7 GB, 单卡放不下 (手算见 [01 高效注意力全景图](01-高效注意力全景综述/01-高效注意力全景综述.md) 第 1.2 节). 这一节的方法都计算同一个函数, 输出在浮点误差内与式子逐元素相等, 改的只是数据在存储层次之间怎么走, 运算单元之间怎么排.

它和 [2.4 稀疏注意力](../2.4-稀疏注意力/2.4-稀疏注意力.md), [2.5 线性注意力与状态空间模型](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md) 分开成节, 是因为后两者改的是被计算的函数, 训练好的模型不能直接换上; 这一节的方法可以. 训练好的检查点把 eager 注意力换成 FlashAttention, 权重一个不动.

## 1. 搬运比乘加贵

### 1.1 两级存储与算术强度

GPU 上的数据在两级存储之间移动. HBM 容量大 (几十 GB), 带宽每秒几 TB; 每个 SM 里的 SRAM (共享内存与寄存器) 只有一两百 KB, 带宽高一个量级以上. 记 SRAM 能放下的元素数为 $M$, 头维为 $d$, 序列长为 $n$ (FlashAttention 论文写作 $N$). 一个算子快不快, 看它每从 HBM 读写一个字节能做多少次浮点运算, 也就是算术强度. 低于硬件的平衡点 (H100 SXM 上 FP16 稠密峰值 989 TFLOPs 除以约 3.35 TB/s 的 HBM 带宽, 约 295 FLOPs/字节), 时间由搬运决定.

[05 实现路径对比](05-Attention实现路径对比/05-Attention实现路径对比.md) 第 2.1 节把这件事算到了毫秒. eager 实现分三步, 每步一个 kernel, $S$ 写一次读一次, $P$ 写一次读一次, 主项约 $4BHN^2$ 个元素, 算术强度约 $D/P$ ($D$ 是头维, $P$ 是每个元素的字节数); 融合内核在片上完成 softmax, 主项只剩 $4BHND$, 强度约 $N/P$. 取 $B=64, H=16, N=4096, D=64$, FP16: 计算按峰值约 4.4 ms, eager 的访存约 41 ms, 融合内核约 0.64 ms. eager 的时间九成花在搬 $S$ 和 $P$ 上, 融合后瓶颈回到计算.

### 1.2 一行 softmax 可以分段算

融合的障碍在 softmax. 一行输出依赖整行分数的最大值和分母, 行长为 $n$, 长序列时整行放不进 SRAM. 这一节所有方法共用的办法是在线 softmax: 把一行的 key 切成块, 每块只留两个统计量, 行最大值 $m$ 和指数和 $\ell$, 外加一个未归一化的输出累加器 $\widetilde o$. 处理第 $j$ 块的分数 $s_j$ 时:

$$
m^{(j)}=\max\bigl(m^{(j-1)},\operatorname{rowmax}(s_j)\bigr),\quad
\ell^{(j)}=e^{m^{(j-1)}-m^{(j)}}\ell^{(j-1)}+\operatorname{rowsum}\bigl(e^{s_j-m^{(j)}}\bigr),\quad
\widetilde o^{(j)}=e^{m^{(j-1)}-m^{(j)}}\widetilde o^{(j-1)}+e^{s_j-m^{(j)}}V_j. \tag{1}
$$

全部块处理完, 输出 $o=\widetilde o/\ell$. 式 (1) 里的 $e^{m^{(j-1)}-m^{(j)}}$ 是重标度因子: 行最大值变大时, 之前按旧最大值算的累加量要整体缩一次, 才能和新块对齐. 这一步在实数上精确, 浮点上只改变求和顺序. 减去行最大值是为了数值稳定, $e^{s}$ 不会溢出.

式 (1) 有一个推论贯穿全节: 块与块的合并既可以在时间上串行做 (FlashAttention 沿 KV 块循环), 也可以在空间上并行做 (解码时把一个 query 要读的 KV 切成几段分给不同线程块, 最终按同一公式合并). 反向传播时不必存 $P$: 只要保存每行的 $m,\ell$ (或 v2 起只存 logsumexp $L=m+\log\ell$), 就能按块重算 $P_{ij}=\exp(S_{ij}-L_i)$.

## 2. 从 MEA 到 FlashAttention-4

### 2.1 同一个合并公式, 两个优化目标

[Rabe 和 Staats (2021)](02-Memory-Efficient-Attention/02-Memory-Efficient-Attention.md) 先回答了一个问题: $O(n^2)$ 显存是不是注意力本身的性质. 答案是否定的. 他们把 softmax 的除法挪到最终 (lazy softmax), 单个 query 只需 $d+1$ 个数的工作集; 加上 running max 保证数值稳定, 再在 query 和 key 两个方向都分块, TPU 上的实用实现把额外显存降到 $O(\sqrt n)$. $n=16384$ 时, 推理的额外显存降 59 倍, 求导降 32 倍. 他们的目标只有显存, 论文没有声称更快.

[FlashAttention v1 (Dao 等人, 2022)](03-FlashAttention-IO感知分块/03-FlashAttention-IO感知分块.md) 用同类分块, 目标换成 HBM 访问次数. 论文 Theorem 2 给出标准实现 $\Theta(Nd+N^2)$, FlashAttention $\Theta(N^2d^2/M)$; Proposition 3 证明在 $M\in[d,Nd]$ 上不存在渐近更少访存的精确算法. 反向重算 $P$ 多做约 13% 的 FLOPs, 总耗时降到原来的 18%. GPT-2 设置下注意力算子快 7.6 倍, HBM 访问最多少 9 倍. 两篇的分歧落在硬件模型上: MEA 在 TPU 上数峰值内存, FlashAttention 在 GPU 上数 HBM 与 SRAM 之间的读写.

### 2.2 v2: 访存不变, 利用率翻倍

v1 在 A100 上前向只到峰值的 30% 到 50%. FlashAttention-2 论文找出三个原因: A100 的 FP16 矩阵乘峰值 312 TFLOPs, 非矩阵乘的 FP32 只有 19.5 TFLOPs, 式 (1) 里每块一次的缩放和除法代价被放大 16 倍; 并行只按 (批, 头) 切, 批小时 108 个 SM 占不满; 线程块内按 $K,V$ 切 warp (split-K), 各 warp 的部分结果要经共享内存求和.

v2 的三处改动一一对应: 推迟归一化, 累加器保持未归一化, 最终除一次, 反向只存 logsumexp; 循环交换, 外层改成 query 块, 并行网格扩到 (批, 头, query 块); warp 改成按 $Q$ 切, 输出行互不重叠, 不再需要共享内存通信. 因果掩码下还跳过对角线上方的整块, 这一项单独快 1.7 到 1.8 倍. 03 第 2.4 节的算例显示, $d=128$ 时 v1 约 $131Nd$, v2 约 $130Nd$ 个元素的访存, 两者基本相同. v2 的加速来自更少的非矩阵乘运算和更高的并行度, 前向最高 230 TFLOPs/s, 即峰值 73%.

### 2.3 v3 与 v4: 瓶颈移进 SM 内部

到了 Hopper, HBM 已经不是首要问题. [04 Hopper 与 Blackwell](04-FlashAttention-Hopper与Blackwell/04-FlashAttention-Hopper与Blackwell.md) 第 1.2 节在 $M=N=d=128$ 的块上算周期: H100 上矩阵乘 2048 周期, 指数 1024 周期, 指数约为矩阵乘的一半. 只要两者并行, 指数时间就能被矩阵乘时间覆盖. FlashAttention-3 用 warp 专门化 (生产者 warp 发 TMA 搬数据, 消费者 warp 做 WGMMA 和 softmax), 两个 warpgroup 的 pingpong 调度, 单 warpgroup 内的跨迭代流水实现这种重叠; FP8 路径用块量化加 Hadamard 变换压低离群值的误差. FP16 前向最高 740 TFLOPs/s, 峰值的 75%, 比 FA2 快 1.5 到 2.0 倍; FP8 前向接近 1.2 PFLOPs/s.

B200 的 BF16 Tensor Core 吞吐到 2.25 PFLOPs, 每 SM 每周期 8192 次, 但指数单元 (MUFU) 仍是每周期 16 次, 共享内存读取仍是 128 字节. 同一个块上矩阵乘降到 1024 周期, 指数也是 1024 周期, 单纯重叠只能做到两者中较大的那个. FlashAttention-4 于是减少指数单元本身的工作量: 每行 10% 到 25% 的元素改用 FMA 上的三次多项式算 $2^x$, 舍入到 BF16 后与硬件结果几乎相同; 行最大值涨幅不超过阈值 $\tau=8$ (以 2 为底) 时跳过式 (1) 的重标度; 反向的共享内存流量用 2-CTA MMA 从 3328 周期压到 2688 周期. 最高 1613 TFLOPs/s, 峰值的 71%, 比 cuDNN 9.13 快 1.1 到 1.3 倍.

## 3. 四代与几条执行路径的对照

### 3.1 每一代对着哪个部件

| 版本 | 目标硬件 | 瓶颈部件 | 主要对策 | 前向峰值利用率 |
|---|---|---|---|---|
| MEA | TPU | 设备内存容量 | lazy softmax, 双向分块, checkpoint 块摘要 | 论文只报显存 |
| v1 | A100 | HBM 读写 $S,P$ | 分块, 在线 softmax, 反向重算 | 30% 到 50% |
| v2 | A100 | 非矩阵乘运算, 并行度 | 推迟归一化, query 外层, 按 $Q$ 切 warp | 最高 73% |
| v3 | H100 | 同步执行, 指数占矩阵乘一半 | warp 专门化, pingpong, FP8 块量化 | FP16 最高 75% |
| v4 | B200 | 指数单元与共享内存 | FMA 模拟指数, 条件重标度, 2-CTA MMA | BF16 最高 71% |

表的第三列每一行都是上一代硬件里增长最慢的部件. A100 到 H100, Tensor Core 吞吐涨了约三倍, 特殊函数单元没有跟上; H100 到 B200, Tensor Core 再翻倍, 指数单元和共享内存带宽每 SM 每周期都没变. 所以每代 FlashAttention 都要重写, 前一代的内核在新硬件上跑不满: FA2 原样编译到 H100 只到 335 TFLOPs/s, FA3 依赖的 WGMMA 指令在 Blackwell 上不可用, FA4 论文因此没有给出相对 FA3 的倍数.

最终一列的利用率口径不同, 不能横向比较绝对值. v1, v2 是 A100 的 FP16 峰值, v3 是 H100 FP16, v4 是 B200 BF16. 四代计算的都是精确注意力, 只有 FA3 的 FP8 路径引入量化误差. FA3 论文用 FP64 参考值比较 RMSE, 含离群值输入下标准 FP16 实现为 3.2e-4, FA2 和 FA3 都是 1.9e-4: 融合内核把 softmax 中间量存为 FP32, 反而比 eager 更准 (05 第 2.9 节).

### 3.2 同一个函数, 不同的入口

写模型时很少直接调 FlashAttention 内核. 05 比较了四条路径: eager 每步一个 kernel, 中间矩阵落显存, 便于调试和插入任意修改; PyTorch 的 SDPA 按输入在 FlashAttention-2, Memory-Efficient Attention, cuDNN 和 C++ 参考实现之间派发; flash-attn 包有变长打包, 滑动窗口, ALiBi, softcapping 和分页 KV cache 的专门参数; xFormers 的 `memory_efficient_attention` 是另一个派发入口. 输入布局也不同, eager 与 SDPA 用 `[B, H, N, D]`, flash-attn 与 xFormers 用 `[B, N, H, D]`.

路径之间最容易出问题的是 GQA 和掩码. HuggingFace Llama 的 `repeat_kv` 先把 KV 复制成与 query 同样多的头, Llama-3-70B ($H_q=64, H_{kv}=8, D=128$, 8K 上下文) 每层每步要读的 KV 从 32 MiB 变成 256 MiB, GQA 在解码带宽上的收益全部抵消; 融合内核按头号整除直接索引, 不复制. 掩码方面, 稠密浮点偏置有 $BHLS$ 个元素要从 HBM 读, 又把 $O(N^2)$ 访存带了回来; 因果, 滑动窗口, ALiBi 只依赖 $i-j$, 能在内核里现场算出, 所以 flash-attn 只接受这几种结构化掩码. 一种新的注意力变体能不能走融合内核, 先看它的掩码能不能写成 $(i,j)$ 的简单函数.

## 4. 这一类方法的边界与读法

### 4.1 分块解决不了的两件事

分块和融合降的是额外显存和 HBM 读写, prefill 的计算量仍是 $O(n^2d)$. 128K 量级时每层每头仍有约 $1.72\times10^{10}\times d$ 次乘加, 这时要动注意力图本身, 去读 [2.4 稀疏注意力](../2.4-稀疏注意力/2.4-稀疏注意力.md) (只算一部分连边) 或 [2.5 线性注意力与状态空间模型](../2.5-线性注意力与状态空间模型/2.5-线性注意力与状态空间模型.md) (把历史压进固定大小的状态). 两者都要按新结构训练.

另一件是 decode. 每步只有一个 query, 算术强度只有 $2g/P$ ($g$ 是 GQA 组大小), MHA 在 FP16 下约 1 FLOPs/字节, 时间全由读 KV 决定. 分块对此无能为力, 能做的是少读: 训练期用 GQA, MLA 降每个 token 的字节数 ([2.2.2 多头注意力变体](../2.2-注意力机制/2.2.2-多头注意力变体/2.2.2-多头注意力变体.md)), 推理期驱逐或选读 KV ([2.7.2 KV 缓存压缩与淘汰](../2.7-长上下文与外推技术/2.7.2-KV缓存压缩与淘汰/2.7.2-KV缓存压缩与淘汰.md)), 或者用 [PagedAttention](../2.7-长上下文与外推技术/2.7.3-长上下文推理优化/01-PagedAttention/01-PagedAttention.md) 消除 KV 显存碎片. PagedAttention 管 KV 怎么放, FlashAttention 管怎么算, 两者可以叠加. 解码阶段沿 KV 长度切分的内核见 [6.6.3 Flash-Decoding](../../6-训练与推理优化/6.6-推理框架与高级优化/6.6.3-Flash-Decoding原理与实现/6.6.3-Flash-Decoding原理与实现.md).

### 4.2 按背景选读

第一次接触高效注意力, 从 [01 全景图](01-高效注意力全景综述/01-高效注意力全景综述.md) 进. 它把硬件高效, 稀疏, 线性与核化, KV 表示压缩四类方法放在同一套记号下, 每种方法写复杂度, 推理缓存, 是否精确, 用在训练期还是推理期, 末尾按瓶颈给出选择. 读完再回到这一节的其余几篇, 或者转去 2.4 和 2.5.

想把在线 softmax 推一遍, 按 [02 MEA](02-Memory-Efficient-Attention/02-Memory-Efficient-Attention.md), [03 FlashAttention v1 与 v2](03-FlashAttention-IO感知分块/03-FlashAttention-IO感知分块.md) 的顺序读. 02 的三项小例子和 TPU 两层循环最容易手算, 03 在此基础上加 IO 复杂度, 下界证明和反向的 $D_i=\operatorname{rowsum}(dO_i\odot O_i)$ 推导. 写 CUDA 或 Triton 内核的读者接着读 [04](04-FlashAttention-Hopper与Blackwell/04-FlashAttention-Hopper与Blackwell.md), 它按周期数分析每一代的瓶颈, 第 4 节有 Triton 分块注意力的参考实现. 只关心模型代码跑在哪个 kernel 上, 直接读 [05](05-Attention实现路径对比/05-Attention实现路径对比.md), 第 2.11 节的选择表给出默认用 SDPA, 什么情况下换 flash-attn 或回到 eager.
