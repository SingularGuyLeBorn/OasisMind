# Agent 决策架构:反馈,规划与自我修正

Agent 的「认知架构」常被写成大脑结构的复刻: 感知模块, 记忆模块, 前额叶式的规划模块. 这种写法在工程上用处不大, 因为它给不出任何能测试的条件. 本节换一个定义: 认知架构是系统怎样组织目标, 状态, 候选动作, 环境观察, 验证和停止. 它可以包含模型生成的计划, 也可以包含规则, 搜索, 外部验证器和人工决策.

[13.1 核心组件](../13.1-Agent核心组件/13.1-Agent核心组件.md) 讲的是 Agent 由哪些零件组成 (工具, 记忆, 结构化输出), 本节讲这些零件按什么顺序被调用, 在什么条件下回头, 什么时候停下. ReAct, Tree of Thoughts, Reflexion, Self-Refine 这些论文证明的是特定方法在特定任务和设置下的实验结果, 本节引用它们时只取机制, 不把它们的百分比当成对任意模型的增益保证.

## 1. 决策架构管的是什么

### 1.1 一个离散闭环

[13.2.1 反馈控制视角](./13.2.1-Agent与控制论/13.2.1-Agent与控制论.md) 给出了本节共用的记号. 把第 $t$ 步的可审计状态记为 $s_t$, 目标记为 $g$. 模型或规则 $P$ 根据目标和当前状态提出动作 $\hat a_t=P(g,s_t)$; 策略门 $G$ 结合调用者身份和策略决定是否允许, 得到实际执行的 $a_t$; 执行器 $E$ 产生环境观察 $o_{t+1}=E(a_t)$; 状态更新器 $U$ 生成下一步状态 $s_{t+1}=U(s_t,a_t,o_{t+1})$.

这组记号的作用是划清接口, 它不证明 $P$ 最优, 也不证明循环一定结束. 它把四个工程问题摆到明处: $s_t$ 里保存了什么, $G$ 是否在模型之外, $E$ 有什么副作用, $U$ 会不会把一次错误的观察写成长期事实. 后面三种架构形态, 差别都在 $P$ 怎样产生 $\hat a_t$ 以及 $U$ 怎样处理失败, $G$ 和 $E$ 的要求对三种形态都一样.

### 1.2 可观察接口与控制论术语的边界

一个可审计的决策步要能回答几件事: 当前目标和不可违反的约束是什么; 哪些事实来自环境, 哪些只是模型的假设; 候选动作的参数, 副作用和权限是什么; 执行后得到了什么新证据; 验证器确认的是任务进展, 还是只确认了「调用成功」; 什么条件会触发停止, 回退, 重规划或请求用户. 这些都可以写成测试. 「前额叶」「意识」「涌现」这类说法写不成验收条件.

控制论的语言 (目标, 状态, 反馈, 扰动) 有用, 但 13.2.1 划了一条线: 除非研究明确给出状态空间, 动力学, 控制律和证明条件, 否则不能把 Lyapunov 稳定性, PID 或一致性协议直接套在 LLM 轨迹上, 再宣称 Agent 收敛或稳定. 工程上的「稳定」要拆成能测的性质: 步数, 时间, token 和费用有上限; 连续重复动作而没有新证据时能检测出来; 写操作有幂等或补偿; 状态冲突不静默覆盖; 故障后能从已验证的检查点恢复.

## 2. 三种架构形态

### 2.1 反应式循环与计划—执行

反应式循环每一步读取最新观察, 选下一个动作, 再把结果送回循环. 它适合路径依赖中间结果, 事先无法穷举的任务. [ReAct](https://arxiv.org/abs/2210.03629) 是公开研究中的代表, 论文交错生成推理线索, 动作和观察. [13.2.2 推理与规划](./13.2.2-推理与规划/13.2.2-推理与规划.md) 第 4 节把它改造成生产形式: 每一步只记录动作摘要, 参数, 观察和证据, 不要求暴露自由文本推理, 并用一个只开放计算器的例子走完整条轨迹.

计划—执行—重规划先把目标拆成带依赖的步骤, 执行器逐项推进, 前提失效或结果不符合预期时记录原因并重新规划. 它适合依赖关系清楚, 可以并行, 或需要里程碑的任务. 13.2.2 给计划列了六个质量维度, 其中最要紧的一条是计划可以修订: 最初的计划是猜测, 不能当成事实一直执行到底. 高风险任务常用的分段方式是先执行只读侦察, 再批准写操作.

### 2.2 候选搜索与组合

第三种形态在关键节点生成多个候选状态或动作, 用任务专用的评估器, 规则或有限的模型裁判筛选, 再展开较优的候选. [Tree of Thoughts](https://arxiv.org/abs/2305.10601) 是这一类的研究实例, 一般化的写法是每个节点生成 $b$ 个候选, 保留分数较高的 $k$ 个, 展开有限深度. 它花的是 TestingTime 算力, 代价是调用数按 $b$ 和深度成倍增长, 收益取决于评估器能不能认出真正更好的路径.

三种形态可以组合. 一个常见的配法是先生成粗粒度计划, 每个子任务内部用反应式循环, 遇到关键的不可逆决策时生成多个候选, 交给外部规则或人工选择. 组合的前提是每多一层 (多一个 Planner, 多一个 Critic, 多一轮搜索) 都要通过消融证明它的收益大于新增的成本和失败面. 13.2.2 第 8 节的决策表列出了各种形态的适用条件, 本节 3.1 是它的简化版.

### 2.3 反思与自我修正

[13.2.3 反思与自我修正](./13.2.3-反思与自我修正/13.2.3-反思与自我修正.md) 处理的是 $U$ 遇到失败之后怎么办. 它先把四类常被混为一谈的方法分开: Reflexion 把语言反思写进情节记忆, 影响下一次尝试, 不更新权重; Self-Refine 让同一个模型兼任生成, 反馈和改写; CRITIC 用搜索, 代码解释器等外部工具的返回做验证; Self-RAG 训练了模型生成反思 token 来控制检索, 它更新了权重, 和提示词式的「再想一遍」不是一类东西.

13.2.3 的核心判断是外部证据优先. 论文 Large Language Models Cannot Self-Correct Reasoning Yet 指出, 缺少外部反馈时, 让模型反复自我修正并不稳定, 某些设置下还会把原本正确的答案改错. 所以一次修正循环只有三种出口: 外部检查满足预先定义的成功条件; 需要新权限或人工判断时升级; 达到预算或连续无进展时停止并报告. 失败要先分型 (信息缺失, 事实冲突, 规划错误, 执行错误, 验证错误, 权限阻断), 每一型对应不同的下一步.

## 3. 选架构与评估

### 3.1 选择依据

| 条件 | 更合适的起点 |
|---|---|
| 路径固定, 步骤确定 | 普通工作流, 不必用动态 Agent |
| 每次观察都会改变下一步 | 反应式循环 |
| 依赖关系清楚, 可以并行 | 计划—执行 |
| 少数关键步骤值得额外计算 | 有限候选搜索 |
| 高风险且结果难验证 | 降低自治, 增加预览与人工检查 |
| 反馈只能来自模型自评 | 谨慎使用修正循环, 先补外部验证器 |

表的第一行最容易被跳过. 路径固定的任务用工作流更便宜也更可靠, 改造成自由 Agent 只会增加失败面. 规划也不是越多越好: 任务短, 工具确定时, 额外的 Planner 只增加成本; 任务长, 前提多时, 没有显式状态和重规划又容易累积错误. 最后一行对应 2.3 节的结论, 没有外部验证器时, 先补验证器, 再谈反思循环.

表里的条件不互斥. 同一个 Agent 在读取公开资料时可以用反应式循环, 到了写入生产数据的那一步切换到「降低自治, 人工检查」. 架构的选择按步骤的风险和可验证性来定, 不按整个产品的名字来定.

### 3.2 怎样证明一种架构有用

在同一模型, 工具和预算下做消融, 分别移除规划, 候选搜索或反思, 比较外部验证的任务成功率, 首次成功率和重试后成功率, 以及把正确结果改错的比例. 成本要一起报告: 无效调用, 重复动作, 回退和人工介入的次数, token, 调用数, 端到端延迟和费用. 输入要覆盖正常, 异常, 恶意和环境漂移几种情况, 并报告多次运行的方差.

不同论文里的百分比不能拼成一条「架构演进曲线」. ReAct 和 Tree of Thoughts 用的任务, 模型, 工具和评估器都不同, 结果没有直接可比性. 本节各篇引用论文数字时都附带设置, 读者自己做比较时也要先对齐调用预算: 搜索类方法多花的调用如果不计入, 比较就是不公平的.

## 4. 读法与边界

### 4.1 按背景进入

第一次搭 Agent 的读者, 从 13.2.2 开始, 先弄清直接生成, 逐步行动, 计划执行和有限搜索四种策略各适合什么任务, 再读 13.2.3 的停止条件. 已经有 Agent 在跑, 遇到循环, 重复调用或把对的改错, 直接读 13.2.3 第三, 四节的失败分型和防循环. 习惯用控制论思考系统的读者, 读 13.2.1, 它说明了哪些概念可以转成测试, 哪些只能停在术语层面.

做评测的读者, 3.2 节和 13.2.2 第 9 节给出了消融的最低要求, 具体基准 (SWE-bench, WebArena, OSWorld, GAIA) 的设置在 [13.5.2 Benchmark 与 Eval](../13.5-Agent应用与治理/13.5.2-Benchmark与Eval/13.5.2-Benchmark与Eval.md).

### 4.2 与相邻章节的分工

工具契约, 记忆和结构化输出在 [13.1](../13.1-Agent核心组件/13.1-Agent核心组件.md); 状态机, 检查点, 多 Agent 和沙箱这些把决策落到运行时的部分在 [13.3 系统工程](../13.3-Agent系统工程/13.3-Agent系统工程.md). 本节讲的是推理时怎样组织调用, 不涉及训练; 用强化学习把规划和工具调用训进权重, 在 [13.4 训练与进化](../13.4-Agent训练与进化/13.4-Agent训练与进化.md).

模型内部的长推理 (o1, DeepSeek-R1 一类的 TestingTime 推理) 在 [4.8 推理与 Agent 能力](../../4-后训练/4.8-推理与Agent能力/4.8-推理与Agent能力.md), 它发生在一次生成之内; 本节的规划, 搜索和反思发生在多次调用之间, 由系统编排. 反思写进记忆之后怎样跨任务累积, 进而变成自改进, 见 [RSI 花园](../../../RecursiveSelfImprovement/_garden.md).
