# LaCT 与 TTT-E2E

## 1. 问题与 LaCT 的大块更新

问题: 5.1 留下的两个缺口. [TTT layers 与 fast weights](../5.1-Fast-weights/5.1.1-TTT-layers与fast-weights.md) 的 TTT layer 留下了两个问题.

第一个是硬件. mini-batch 大小 $b = 16$ 时, 每 16 个 token 就要做一次 fast weights 的更新, 中间还要读写 fast weights. 加上 dual form, TTT-Linear 能跑, TTT-MLP 仍被内存 I/O 卡住. 更大的非线性 fast weights 在这个块大小下几乎无法高效实现.

第二个是目标. TTT layer 的内循环在每一层上各自做重建 (式 (2) 的 key-value 重建), 外循环再用下一个 token 预测训练整个网络. 内循环学的东西和最终任务之间, 隔着一个由外循环学出来的投影 $\theta_K, \theta_V$.

LaCT 处理第一个问题, 方向是把块放大到几千个 token 以上. TTT-E2E 处理第二个问题, 方向是让内循环直接优化网络输出端的下一个 token 预测损失. 两篇的作者有交集 (Songlin Yang 是 LaCT 作者, 也是 DeltaNet 和 Gated DeltaNet 的作者; TTT-E2E 与 TTT layer 论文有 Dalal, Li, Sun 等多位共同作者), TTT-E2E 把 LaCT 当作自己推导的起点, 叫它 TTT-KVB (Key-Value Binding).

硬件成本. [LaCT (Zhang, Bi, Hong, Zhang, Luan, Yang, Sunkavalli, Freeman & Tan, 2025)](https://arxiv.org/abs/2505.23884) 来自 MIT 和 Adobe Research, 论文题目是 *Test-Time Training Done Right*. 它的起点是一个测量: 以前的 TTT 层每 16 或 64 个 token 更新一次 fast weights, GPU 的 FLOPs 利用率常低于 5%. LaCT 改成每 2048 到 1M 个 token 更新一次, 不写定制 kernel, 纯 PyTorch 实现在 A100 上利用率最高到 70%.

LaCT 先用一个式子说明小块为什么慢. 考虑一个 $h \times h$ 的 fast weight 矩阵和一个 $b \times h$ 的块输入做矩阵乘, BF16 下每个数 2 字节. 计算量是 $2h^2 b$ 次浮点运算, 访存量是两个输入矩阵加一个输出矩阵 $2h^2 + 4hb$ 字节. 计算与访存之比:

$$
r = \frac{2h^2 b}{2h^2 + 4hb} = \frac{b}{1 + \frac{2b}{h}} \le \min\Big(\frac{h}{2},\ b\Big)
\tag{1}
$$

H100 达到峰值算力所需的比值约为 290 FLOPs/字节, 低于它就是访存受限. 代入几组数:

| $h$ | $b$ | $r = b/(1 + 2b/h)$ | 状态 |
| --- | --- | --- | --- |
| 64 | 16 | $16/1.5 = 10.7$ | 严重访存受限 |
| 64 | 2048 | $2048/65 = 31.5$ | 被 $h/2 = 32$ 封顶 |
| 512 | 2048 | $2048/9 = 227.6$ | 接近峰值 |
| 1024 | 2048 | $2048/5 = 409.6$ | 计算受限 |

第一行是以前 TTT 层的典型配置. 第二行说明只放大块不够, fast weights 也要大; 第三, 四行说明块和 fast weights 同时放大, 比值才能接近或超过 290. 以前的工作为了在小块上跑快, 写定制 kernel 把 fast weights 留在 SRAM 里, 这要求 fast weights 在各个 SM 内基本独立演化, 对大的非线性 fast weights 和 Muon 这类需要全矩阵运算的更新不成立.

更新与应用. LaCT 沿用 TTT 的两个操作. 设 token 投影出 $q_i, k_i, v_i \in \mathbb{R}^d$, fast weights 网络为 $f_W$.

更新操作在整块 $b$ 个 token 的损失和上求一次梯度:

$$
g = \nabla_W \sum_{i=1}^{b} \eta_i\, \mathcal{L}\big(f_W(k_i), v_i\big), \qquad W \leftarrow \text{weight-update}(W, g)
\tag{2}
$$

$\eta_i$ 是每个 token 的学习率, 由输入预测. 应用操作 $o_i = f_W(q_i)$, 块内所有 query 共用同一个更新后的 $W$.

fast weights 网络是无偏置的 SwiGLU-MLP, 三个矩阵 $W = \{W_1, W_2, W_3\}$:

$$
f_W(x) = W_2\big[\text{SiLU}(W_1 x) \circ (W_3 x)\big]
\tag{3}
$$

$\circ$ 是逐元素乘. 损失用点积:

$$
\mathcal{L}\big(f_W(k_i), v_i\big) = -f_W(k_i)^\top v_i
\tag{4}
$$

与 5.1 的平方误差相比, 点积损失不含 $\lVert f_W(k) \rVert^2$ 项, 梯度只朝「让 $f_W(k)$ 与 $v$ 对齐」的方向走, 对 $f_W(k)$ 的长度没有约束. fast weights 的幅度要靠下面的归一化来控制.

非线性更新: 归一化与 Muon. fast weights 反复累加梯度, 幅度会爆炸或衰减. 大块意味着更新次数少, 每次更新可以做得更复杂而不拖慢整体. 基础版本是梯度下降后做 L2 归一化:

$$
\text{weight-update}(W, g) = \text{L2-Normalize}(W - g)
\tag{5}
$$

归一化沿输入维度做, 不用显式的权重衰减. 论文给的解释是: 把序列维度看成一个虚拟网络的深度, 每次 TTT 更新是时间上的一个残差, 归一化相当于 Transformer 里的 post-LN, 约束残差路径上的尺度.

Muon 版本把梯度先正交化再更新:

$$
\text{weight-update}(W, g) = \text{L2-Normalize}\big(W - \text{Muon}(g)\big), \qquad \text{Muon}(g) \approx U V^\top
\tag{6}
$$

$g = U S V^\top$ 是梯度的奇异值分解, Muon 用 Newton-Schulz 迭代近似地把所有奇异值置为 1. 这样 $\eta_i$ 只表示块内 token 之间的相对重要性, 更新的绝对尺度由 Muon 归一化. Muon 只作用在矩阵上, SwiGLU 的三个权重各自处理. 语言建模里还有一个动量版本: $M \leftarrow \beta M + \sum_i \eta_i \nabla_W \mathcal{L}_i$, 再对 $M$ 做 Muon.

### 1.1. 更新与应用的顺序决定了掩码

更新和应用是解耦的, 改变两者的顺序和块大小, 就得到不同的依赖结构. 论文图 3 把它们对应成注意力掩码:

- 块等于整条序列, 先应用再更新: 相当于全注意力 (双向).
- 更新和应用交替: 块级因果掩码, 块大小等于 chunk 大小.
- 交替但先应用后更新 (相对上一种平移一个块): 当前块只看到之前的块, 块内不泄漏未来信息. 语言建模要用这一种.
- 只在一部分块上更新, 在所有块上应用: 带步长的块级因果掩码. 新视角合成和视频扩散用这一种.

窗口注意力补块内结构. 大块 TTT 的更新对块内 token 求和, 不区分顺序和位置, 块内是一个集合. 文本是一维序列, 视频是网格的序列, 块内的局部结构都很重要. LaCT 在 TTT 层旁边加窗口注意力 (因果或双向), 处理块内的局部依赖, TTT 层的固定容量用于块与块之间的非局部依赖. 所以 LaCT 是一个混合架构: 局部用二次复杂度的注意力, 远程用线性复杂度的 TTT.

语言建模里, 窗口注意力是滑动窗口, 窗口大小等于块大小 (2048 或 4096), 和 fast weights 网络共用 Q, K, V (按 GAU 的做法), 再给 Q, K 加逐通道的缩放和平移.

上下文并行. 大块还带来一个便利. 一个块内的梯度是 token 梯度之和, 可以把块里的 token 切到多张卡上, 各自算梯度, 再全局求和:

$$
g = \sum_{j=1}^{\text{shards}} \nabla_W \sum_{i=1}^{s} \eta_i \mathcal{L}_i
\tag{7}
$$

$s$ 是每个分片的 token 数. 这和数据并行在形式上相同, 只是「参数」换成了 fast weights, 「数据」换成了块内的 token. 新视角合成的训练用了这种并行, 吞吐开销只有 1% 到 3%. 小块的 TTT 层很难这样切, 只能按 head 做张量并行.

状态大小到底怎样算. LaCT 所说的「状态」指每一层随序列更新的三块 SwiGLU 权重, 与前向过程中暂存的激活分开统计. 设模型维度为 $d$, TTT 分成 $H$ 个 head, 每个 head 的输入维度 $d_h=d/H$, SwiGLU 中间维度为 $m_h$. 单层 fast weights 的参数量是

$$
S_{\text{layer}}
=H(d_hm_h+m_hd_h+d_hm_h)
=3H d_hm_h.
\tag{8}
$$

若令 $m_h=\rho d_h$, 则

$$
S_{\text{layer}}=3\rho H d_h^2=\frac{3\rho d^2}{H}.
\tag{9}
$$

这个式子解释了论文附录里一个容易忽略的选择: **TTT head 越少, 单个 head 越宽, fast-weight 状态反而越大.** 语言模型默认只用 4 个 TTT head, 与窗口注意力不必使用相同的 head 数. 这和普通多头注意力的直觉不太一样; 普通注意力的投影矩阵总大小大致保持 $O(d^2)$, LaCT 的 fast weights 则在每个 head 内独立成网, head 切得越碎, 被 $1/H$ 压掉的二次项越多.

表里的 $2304d$ 也是总状态量, 不是某一个矩阵的宽度. 以论文 3B 配置的模型维度代入后, 它对应各层各 head 的 $W_1,W_2,W_3$ 之和. GLA 的 $384d$ 和 DeltaNet 的 $128d$ 用同一口径统计递归状态, 因而「6 倍」「18 倍」比较的是随序列变化的状态容量, 不包含所有方法共有的静态网络参数.

这里还要分清 **状态容量** 和 **可无损记住多少 token**. $S$ 个浮点数只给出存储通道的规模, 不意味着能按地址取回 $S$ 个 token. 每块梯度把许多 token 的贡献相加后写进同一组矩阵, 不同 key 的更新会互相干扰; Muon 与 L2 归一化稳定了尺度, 却没有给每条信息分配独立地址. 所以扩大状态通常能改善平均损失, 但不会自动得到 KV cache 那种逐 token 的精确寻址.

一个块究竟何时可见. 把第 $j$ 块记为 $C_j$, 块开始时的状态为 $W_{j-1}$. 因果语言建模采用 apply-then-update:

$$
O_j=f_{W_{j-1}}(Q_j),\qquad
G_j=\nabla_W\sum_{i\in C_j}\eta_i\mathcal L(f_{W_{j-1}}(k_i),v_i),\qquad
W_j=\Phi(W_{j-1},G_j).
\tag{10}
$$

于是 LaCT 分支计算 $O_j$ 时只含 $C_1,\ldots,C_{j-1}$ 写入的状态, 当前块 $C_j$ 要到下一块才进入 fast weights. 当前块内部的因果关系由并行的滑动窗口注意力承担. **窗口大小等于块大小并非随手选的超参数, 它刚好补上 fast weights 晚一块生效留下的空档.** 如果窗口小于块, 同一块里相距超过窗口的 token 既没有进入旧状态, 又不在局部注意力内, 中间会出现真正的依赖盲区.

这也说明块大小的两面性. 把 $b$ 从 16 放到 2048, 更新次数从 $T/16$ 降到 $T/2048$, 大矩阵乘更容易吃满 GPU; 与此同时, 一次更新混合的 token 增加 128 倍, 状态响应新信息的频率下降. 图像集合的一张图, 视频的若干连续帧都有天然块边界, 文本没有. 因此 LaCT 在文本上必须同时依靠更大的非线性状态, Muon 和窗口注意力, 大块本身只解决系统效率, 不负责补回顺序信息.

LaCT 的任务与消融. ### 1.2. 三类任务

论文 Table 1 汇总了三个实验 (状态大小指每个块的 fast weights 大小, $d$ 是模型维度):

| 任务 | 数据结构 | chunk 大小 | 状态大小 | 模型规模 | 最大长度 |
| --- | --- | --- | --- | --- | --- |
| 新视角合成 | 图像集合 | 整条序列 | $6d^2$ | 0.3B | 1M |
| 自回归视频扩散 | 图像序列 | 3 帧 | $3d^2$, $0.75d^2$ | 1.3B, 14B | 56,160 |
| 语言建模 | 一维序列 | 2K, 4K | $0.75d^2$ | 0.7B, 3B | 32,768 |

**新视角合成.** 给定一个静态场景的 $N$ 张带相机位姿的图, 渲染新视角. 窗口注意力正好覆盖一张图的 token, TTT 层用所有输入图的 token 更新一次 fast weights, 再应用到输入和目标 token 上. 更新阶段相当于 prefill, 应用阶段相当于并行 decode; 渲染新视角时, 每个 TTT 层就是一个静态权重层. 论文 Table 2 在 A100 上用 48 张 512×512 输入 (196K 输入 token, 4K 解码 token) 比较: 全注意力 prefill 16.1 秒, 渲染 2.3 FPS; Perceiver 式注意力 16.8 秒, 34.4 FPS; LaCT 1.4 秒, 38.7 FPS, 质量与全注意力相当. 在 960×536 的场景数据上, 输入较少时质量超过 3D Gaussian Splatting, 一直到 128 张输入 (约 1M token) 仍有竞争力; 对照的 LongLRM 只能处理 32 张.

**语言建模.** 在 Long-Data-Collections 上训练, 760M 模型 40B token (窗口 2048), 3B 模型 60B token (窗口 4096), 上下文 32,768, RoPE base 取 1M. 对照全注意力, 以及加了同样滑动窗口的 GLA 和 DeltaNet. 3B, 32K, A100-40GB 上的训练吞吐 (token/秒) 与状态大小:

| 方法 | 状态大小 | 吞吐 | 更新规则 |
| --- | --- | --- | --- |
| Transformer | 随长度增长 | 4.1K | |
| Transformer SWA | 窗口内 | 6.4K | |
| GLA SWA | $384d$ | 5.0K | $S_t \leftarrow S_{t-1}\text{Diag}(\alpha_t) + v_t k_t^\top$ |
| DeltaNet SWA | $128d$ | 5.1K | $S_t \leftarrow S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top$ |
| LaCT GD | $2304d$ | 5.0K | $W \leftarrow \text{L2norm}(W - \sum_i \eta_i \nabla_W \mathcal{L}_i)$ |
| LaCT Muon | $2304d$ | 4.3K | 动量 + Muon + L2norm |

LaCT 的状态是 GLA 的 6 倍, DeltaNet 的 18 倍, 吞吐相当 (Muon 版慢约 14%). 结果 (论文图 5): 两个规模上, LaCT 在靠后位置的逐 token 损失都低于 GLA 和 DeltaNet, S-NIAH 检索精度也更高; Muon 版始终好于动量版.

**自回归视频扩散.** 把预训练的 Wan 2.1 文生视频扩散模型 (双向注意力) 微调成自回归模型: 所有双向注意力层换成 LaCT 层加滑动窗口注意力. 序列里交替排列加噪块和干净块, 只在干净块上更新 fast weights, 在每个块上应用, 保证每次去噪只用到已经生成好的帧. 对照滑动窗口注意力单独使用, Mamba 2 加滑动窗口, 以及全块因果注意力. LaCT 的验证损失与全注意力相当, 好于另外两个线性基线. 14B 模型最长生成 56,160 个视觉 token.

消融与局限. 论文在新视角合成和语言建模上做了四组消融 (图 7, 图 8):

- 状态大小: 越大越好, 两个任务一致. 最大配置每块 $12d^2$, fast weights 合计占模型权重的 40%; 论文统计的以前方法只占 0.1% 到 5%.
- 优化器: Muon 好于普通梯度下降和动量.
- 线性对非线性: SwiGLU fast weights 即使状态更小, 也好于线性 fast weights $f_W(x) = Wx$.
- 块级递推对逐 token 递推: 新视角合成里, 相同状态大小下线性的大块递推好于线性的逐 token 递推 (双向 Mamba 2). 语言建模里, 线性大块递推 (状态 $0.25d^2$, 与 GLA SWA 相同) 一开始不如 GLA SWA, 论文认为是文本没有天然的块结构; 换成更大的非线性状态 ($1.5d^2$) 加 Muon 之后, 超过了所有逐 token 递推的基线.

这组结果表明, 对文本而言大块本身是一个劣势, 是靠更大的状态和更好的优化器补回来的.

局限方面, 论文自己列了三条: 任务覆盖仍有限 (新视角合成带位姿输入, 无位姿重建没做); 语言建模受算力限制, 没有测推理能力, 也没有测参数规模的扩展, 而固定状态模型的主要弱点恰好被认为是推理; 视频生成缺少可靠的可扩展性指标, 只报了验证损失.

TTT-E2E: 直接在下一个 token 预测上学. [TTT-E2E (Tandon, Dalal, Li, Koceja, Rød 等, 2025)](https://arxiv.org/abs/2512.23675) 的摘要第一句是: 把长上下文语言建模表述为持续学习问题, 而不是架构设计问题. 这里的「持续学习」指序列内: 模型读一条很长的上下文时, 一边读一边用读过的部分训练自己, 把上下文压进权重. 读完这条上下文, 状态就丢弃了.

论文先用一个刻意简化的架构说明机制: 把 Transformer 的所有自注意力层去掉, 只留 MLP. 这个模型没有任何历史记忆, 实际上是一个 bigram 模型.

给它记忆的方法是在上下文上训练它. 记网络为 $f$, 权重 $W$, $t$ 时刻的下一个 token 预测损失:

$$
\ell_t(W) = \text{CE}\big(f(x_{t-1}; W), x_t\big)
\tag{11}
$$

CE 是交叉熵. 推理阶段对 $t = 1, \dots, T$ 依次做梯度下降:

$$
W_t = W_{t-1} - \eta\, \nabla \ell_t(W_{t-1})
\tag{12}
$$

模型输出 $\hat{p}_{T+1} = f(x_T; W_T)$. $x_1$ 的信息就这样通过一步梯度存进了 MLP, 预测 $x_3$ 时可以用上.

训练阶段: 元学习初始化. $W_0$ 怎么来? 注意 $\ell_t(W_{t-1})$ 本身就是「看了 $x_0, \dots, x_{t-1}$ 之后预测 $x_t$」的测试损失. 一条序列上的测试损失是

$$
\mathcal{L}(W_0; X) = \frac{1}{T}\sum_{t=1}^{T} \ell_t(W_{t-1})
\tag{13}
$$

直接在大量训练序列上最小化式 (13), 训练损失与测试损失一致, 论文称之为端到端 (E2E). 对照的做法是忽略推理阶段的更新, 只优化

$$
\mathcal{L}_{\text{naive}}(W_0; X) = \frac{1}{T}\sum_{t=1}^{T} \ell_t(W_0)
\tag{14}
$$

这就是普通预训练, 也是动态评估 (dynamic evaluation) 文献的主流做法, 论文称之为 TTT-naive. 玩具例子上 (论文图 2 右), TTT-naive 只比无注意力基线好一点, TTT-E2E 几乎追上全注意力.

对式 (13) 求 $\nabla_{W_0}$ 要穿过式 (12) 里的梯度, 也就是对梯度求梯度. 在元学习的术语里, 对 $\mathcal{L}$ 的梯度步是外循环, 对 $\ell$ 的是内循环.

只看一句「梯度的梯度」很容易把计算量想错. 对一步更新求导可得

$$
\frac{\partial W_t}{\partial W_{t-1}}
=I-\eta H_t,
\qquad
H_t=\nabla^2\ell_t(W_{t-1}).
\tag{15}
$$

因此后面某个损失传回 $W_0$ 时, 要依次乘上这些 Jacobian:

$$
\frac{\partial \ell_t(W_{t-1})}{\partial W_0}
=\frac{\partial \ell_t(W_{t-1})}{\partial W_{t-1}}
\prod_{j=1}^{t-1}(I-\eta H_j).
\tag{16}
$$

实现时不需要显式构造巨大的 Hessian, 自动微分计算的是 Hessian-vector product. 但中间更新的计算图仍要保留或重算, 这就是训练比推理难得多的地方. 推理只执行前向, 一次普通反向和参数更新; 训练初始化 $W_0$ 时, 外循环还要穿过整串内循环. **二阶指的是外循环对内循环梯度求导, 不是每个推理请求都要再做一次二阶优化.**

所以 TTT-E2E 的「端到端」有两层: 推理阶段的内循环直接优化网络最末端的下一个 token 预测损失 (对照 TTT layer 的逐层重建); 训练阶段的外循环直接优化经过 TTT 之后的损失 (对照动态评估).

mini-batch 与滑动窗口. 逐 token 的式 (12) 有两个问题: 串行, 不能并行; 每步只依赖一个 token, 梯度容易偶然爆炸. 换成 mini-batch:

$$
W_i = W_{i-1} - \eta\, \frac{1}{b}\sum_{t=(i-1)b+1}^{ib} \nabla \ell_t(W_{i-1}), \qquad i = 1, \dots, T/b
\tag{17}
$$

外循环的式 (13) 相应改成块内都用 $W_{i-1}$ 计算损失. $b = 1$ 时退回式 (12), (13).

用块写法可以把状态更新时间说得更准确. 第 $i$ 块的 $b$ 个 token 先在同一个 $W_{i-1}$ 下完成预测, 随后把这 $b$ 个损失的平均梯度写成 $W_i$. 第 $i$ 块的信息从第 $i+1$ 块开始通过权重生效. 滑动窗口在块内逐位置移动, 因而当前 token 仍能直接看到窗口内的较早 token; TTT 状态负责的是窗口之外, 已经完成更新的旧块.

设滑动窗口为 $k$, 更新层的参数量为 $P_u$, 序列长度为 $T$. 忽略常数后, prefill 的局部注意力为 $O(Tkd)$, 内循环前向与反向约为 $O(TP_u)$, 状态存储为 $O(P_u)$. 全注意力 prefill 则有 $O(T^2d)$ 的注意力计算和随 $T$ 增长的 KV cache. 这就是 TTT-E2E 在足够长的上下文上追过全注意力的来源. 不过 $O(TP_u)$ 的常数很大: 被更新的是后四分之一 Transformer 块里的完整 MLP, 每个 1K 块都要做一次反向, 不能把它与一次便宜的线性递推更新视为同一成本.

以主实验的 $T=128$K, $b=1$K, $k=8$K 为例, 整段 prefill 一共发生 128 次权重更新. 第 1 块的预测可直接使用至多 1K token 的局部历史; 到第 8 块, 窗口已经覆盖 8K, 更早的块则只能通过 $W_1,\ldots,W_7$ 留下影响; 到第 128 块, 窗口仍只有 8K, 权重状态已经累计 127 次写入. 把 $b$ 改成 2K 会把更新减到 64 次, 系统吞吐更容易提高, 但每条信息要等更久才能写入, 每次梯度也混合更多 token. 把 $k$ 改大只增强局部精确访问, 并不增加 fast weights 的容量. 两个超参数控制的是两条不同路径.

块梯度中的 $1/b$ 也值得单独看. 它让学习率 $\eta$ 不随块大小线性放大, 但梯度方向仍由块内 token 的平均贡献决定. 高频模式会在同一块里反复投票, 单次出现的异常字符串只占 $1/b$ 的权重. 因而较大的 $b$ 同时带来更平稳的更新和更强的平均化. 论文中从 1K 增到 8K 时损失变差, 与这套机制一致: 更新频率下降, 罕见信息权重变小, 而滑动窗口只能补局部依赖, 无法替远处信息重新写一次状态.

但 mini-batch 让玩具模型在块内又变回 bigram: 块内的预测都用块开始时的 $W_{i-1}$, 越靠后的 token 缺的上下文越多, 损失越高, 梯度也越差. 补法是把自注意力加回来, 但限制成滑动窗口, 窗口大小 $k$. 主实验 $T = 128$K, $k = 8$K, $b = 1$K. 必须 $k \ge b$, 块内的上下文由窗口注意力负责, 块与块之间由 TTT 负责.

## 2. 三个实现细节

论文明确说这三条是达到报告结果所必需的, 但也可能只是自己实验设置的产物:

1. **只对 MLP 做 TTT.** 嵌入层, 归一化层, 注意力层在内循环中冻结, 更新它们会让外循环不稳定.
2. **只对后 1/4 个块做 TTT.** 更新的层越多, 存储上下文的容量越大, 但反向传播的计算也越多. 梯度只回传到后 $L/4$ 个块, 不再往下.
3. **每块两个 MLP.** 在被更新的块里加一个静态的第二个 MLP, 作为预训练知识的「安全存储」, 防止 TTT 遗忘预训练学到的东西. 为了总参数量与基线相同, 全网络 MLP 的隐层维度都相应缩小.

生成多个 token 时, 每当解码出的 token 攒满一个 mini-batch, 就在这一批上走一步梯度, 再继续解码.

**从 TTT-KVB 推到 TTT-E2E**

论文给了另一条推导路径, 起点是 LaCT 那一类的 TTT 层加滑动窗口注意力 (TTT-KVB). 760M 模型, DCLM 8K 上的损失 (论文 Table 1):

| 方法 | 损失 | 变化 |
| --- | --- | --- |
| SWA ($k = 8$K) 基线 | 2.827 | |
| TTT-KVB | 2.818 | $-0.009$ |
| TTT-KVB 简化输出规则 | 2.819 | $+0.001$ |
| TTT-E2E 全层多头 | 2.806 | $-0.013$ |
| TTT-E2E | 2.805 | $-0.001$ |

论文把 0.001 的差视为不显著. 三步分别是:

- 简化输出规则: 输出直接用更新前对 $\theta_K x_t$ 的预测, 不再用更新后的权重对 $\theta_Q x_t$ 重算. 几乎无损.
- 关键一步: 把每层的 KV 重建损失换成网络末端的下一个 token 预测损失, 同时去掉每层的 $\theta_K, \theta_V$. 损失从 2.819 降到 2.806, 基本到了最终水平.
- 状态重排: 从「每层都更新一个多头小 MLP (还用了 LoRA)」改成「后 1/4 层各更新一个完整 MLP」. 在 8K 上损失几乎不变, 但 760M 模型的状态从 18M 增加到 88M (5 倍), prefill 延迟减半 (H100 上每 1K token 从 0.017 秒到 0.0086 秒). E2E 损失更新底层的小状态之前, 梯度仍要穿过它上方的大 MLP 和注意力层; 集中在少数高层更新, 可以省掉昂贵的上游梯度准备, 同时给每个更新点更大的状态.

这条推导也说明 TTT-KVB 和 TTT-E2E 都可以看成「训练整个网络」: 都有一次完整前向, 再一次反向. 区别在于 TTT-KVB 的反向来自每层各自的损失, 每层只回传一层就停; TTT-E2E 只有一个末端损失, 回传穿过后 1/4 的网络.

**TTT-E2E 的实验**

**实验设置与结果**

两阶段训练: 8K 上预训练, 再在最终长度 (最长 128K) 上做长度扩展微调. 预训练数据是 DCLM-Baseline, 只保留长于 8K 的文档 (这样训练序列里不会有文档边界, 避免在边界处复位 MLP, 复位会拖慢训练); 长于 128K 的 DCLM 文档质量差, 所以微调和评测用 Books. 五个规模 125M 到 3B, 配置来自 GPT-3 和 Mamba 的配方. 基线: 全注意力, SWA, SWA 与全注意力 5:1 混合, Mamba 2 (混合 SWA), Gated DeltaNet (混合 SWA), TTT-KVB.

**随上下文长度扩展** (3B, 预训练和微调都用 3 倍基础 token 量, 合计 164B 训练 token, 论文图 1). 纵轴是各方法损失减去全注意力损失. 从 8K 到 128K, 其他方法的差随长度变大, TTT-E2E 的差基本不变且为负 (比全注意力损失低). 这里的比较是语言建模损失, 衡量平均预测质量.

逐位置拆开 (图 6, 32K 和 128K), TTT-E2E 是唯一在整个上下文范围内都低于全注意力的方法, 优势主要来自靠前的 token. 在第一个 1K 块之前, TTT-E2E 和全注意力的计算图完全一样, 只是权重不同, 损失却更低. 论文的解释是: 全注意力的权重要为窗口内所有未来位置做准备, TTT-E2E 的权重只需对当前块好, 未来的块由 TTT 产生新的权重.

**窗口和块大小的消融** (760M, DCLM). 窗口越大三种方法都越好, TTT-E2E 对窗口的敏感度与基线相近. 窗口取 8K 时 SWA 就等于全注意力 (预训练长度也是 8K), 此时 TTT-E2E 仍把损失降低 0.018, 说明它的收益不只是在弥补滑动窗口与全注意力之间的差. 块大小从 1K 到 8K, 越大越差; 小于 1K 则硬件利用率和稳定性都变差, 所以取 1K. $b = 8$K 等于不做 TTT, 此时 TTT-E2E 的架构损失 2.825, 与全注意力 2.827 几乎相同, 说明收益来自 TTT 本身而非架构改动.

**更新层数的消融** 显示, 状态越小 (更新的层越少), 随上下文长度的扩展越差. 1/4 是在计算成本与扩展性之间取的点.

把几组消融连起来看, 可以把收益拆成三部分. $b=8$K 时整段预训练上下文只在末尾更新一次, 这次更新来不及帮助当前序列, 2.825 与全注意力 2.827 的接近值给出了「架构改动本身」的参照. 固定 8K 窗口, 把块降到 1K 后损失再降约 0.018, 对应序列内反复更新带来的收益. TTT-KVB 从 2.818 到 E2E 多头版 2.806 的 0.012, 则隔离出把逐层 KV 重建换成末端 next-token loss 的作用. 这些消融每次还会联动少量实现细节, 属于近似分解, 三个差值不宜直接相加成最终提升. 它们共同指向更新目标与更新频率, 静态 MLP 主要承担保留预训练知识的角色.

**重点是状态何时写入, 用什么损失写入以及写入后能否被准确寻址.** LaCT 放大单次更新来换硬件效率, TTT-E2E 把写入目标推进到最终语言模型损失; 二者都依靠滑动窗口保存局部细节, 长距离信息则进入固定大小, 有损的权重状态.

官方实现还公开了 125M, 1B 和 3B 的部分 checkpoint, 包括 DCLM 8K 预训练, Books 长度扩展以及 3B 128K 版本. checkpoint 不含优化器状态, 复现实验只能按参数恢复; 这对普通推理足够, 对继续训练和严格复算训练曲线则少了一部分状态. 论文中的硬件数字也来自作者为各基线做过额外优化后的实现, 因而复现时应同时固定模型规模, 上下文长度, 每批总 token, GPU 型号和是否包含内循环更新, 只报一个 tokens/s 很容易把不同口径混在一起.

**随训练计算量扩展** (图 5). 计算预算小时, TTT-E2E 相对全注意力的优势随计算增加而明显缩小; 预算大时, 趋势与全注意力相近. 论文据此认为大规模训练中 TTT-E2E 应与全注意力保持相同趋势, 这是一个外推判断. 论文还报告了两个零散观察: 分词器从 Llama 2 换到 Llama 3, 3B 模型相对全注意力的优势增加约 0.01; 数据从 SlimPajama 换成 DCLM, 才在 48B token 之后得到与全注意力相同的趋势.

**needle-in-a-haystack 与长序列生成**

论文 3.5 节用 RULER 的三个 S-NIAH 任务测 128K 微调后的 3B 模型: 密码检索, 文中数字检索, 文中 UUID 检索. 结论 (Table 2): 全注意力大幅领先所有其他方法, 包括 TTT-E2E, 长上下文里差距更大. 论文的解释与它的出发点一致: 全注意力的长处是近乎无损的回忆, 每个新 token 都扫描所有历史的 KV; TTT-E2E 的关键机制是压缩, 会丢掉看起来无关的细节, 而 needle 恰好就是一段与上下文无关的字符串.

图 1 所说的「随长度扩展与全注意力一致」只针对语言建模损失; 在需要逐字保留偶发细节的精确检索中, 压缩状态仍明显落后于全注意力.

这里没有矛盾. 交叉熵按所有位置平均, 高频语法, 主题和局部搭配占绝大多数; 模型把这些统计压进权重, 就能降低平均损失. S-NIAH 刻意插入一串密码, 数字或 UUID, 它与周围文本几乎没有统计联系, 出现次数也只有一次. 对 next-token loss 而言, 为这串偶发字符专门留出一块状态的收益极小, 后续大量 token 的梯度还会继续覆盖它. 全注意力保留每个历史 token 的 K/V, 查询时可以直接对那一个位置赋高权重, 因而更适合这种「写入一次, 很久以后按内容精确寻址」的任务.

块大小会进一步决定最早何时能够检索. needle 与查询若在同一个 1K 块内, TTT 更新尚未发生, 只能靠 8K 滑动窗口; 两者间距超过窗口但 needle 所在块已经更新, 查询才会依赖压进 MLP 的痕迹. 距离继续增加时, needle 的状态又要承受更多块的梯度覆盖. 因此精确检索不是一个单独的「最大上下文长度」数字, 它同时受窗口 $k$, 更新块 $b$, 状态容量 $P_u$, 写入后的块数以及 needle 是否符合语言模型目标影响.

**「平均预测更好」和「随机细节可逐字取回」测的是两种能力.** 前者允许有损压缩, 后者接近可寻址存储. TTT-E2E 的实验支持前者, S-NIAH 则明确暴露后者的缺口. 若应用要求引用合同编号, 复制代码片段或返回原文证据, 固定状态不能单凭较低语言模型损失替代全注意力, 外部检索或少量全局注意力层.

长序列生成同样只有初步结果. 论文用 Qwen3-8B-Base 当评估器做了一个尽力而为的测试: 用 Books 的 8K token 填满上下文, 再生成 8K token, 看 Qwen 对整段 16K 的逐 token 损失. 论文承认基础模型没有经过指令微调和强化学习, 难以真实评估长生成, 这个测试只是对「推理阶段在自己生成的 token 上训练」是否可行的初步检查.

### 2.1. 延迟

**prefill.** 论文按每批固定 128K token 测 prefill 延迟 (128K 上下文时每批 1 条, 8K 时每批 16 条). TTT-E2E 和 SWA, RNN 基线一样, 每处理一个 token 的时间不随上下文长度变化, 128K 时比全注意力快 2.7 倍 (H100). 总 prefill 时间仍与上下文长度成正比, 只是比例常数不随长度变大.

**decode.** 每个 token 的生成只涉及窗口内的注意力和固定大小的 MLP, 开销不随已经生成的总长度增长; 每 $b$ 个 token 多一次梯度步. 论文没有另报一张 decode 延迟表, 因为总时间可以拆成两项:

$$
T_{\text{decode}}(N)
\approx N\,t_{\text{SWA-step}}
+\left\lfloor\frac{N}{b}\right\rfloor t_{\text{TTT-update}}.
\tag{18}
$$

第一项是滑动窗口逐 token 解码, 第二项是在累计满一块以后执行的更新, 其延迟与对应块的 prefill 相同. 所以单 token 延迟会呈锯齿状: 大多数步和普通 SWA 一样, 每到块边界暂停一次完成反向与更新. 「恒定复杂度」表示它不随历史总长度增长, 并不表示每一步延迟完全相同, 也不表示常数比 KV cache 解码更小.

**prefill.** 若窗口 $k$ 和更新参数量 $P_u$ 固定, 总成本随 $T$ 线性增长. 全注意力的二次项最终会超过它, 但交叉点由硬件, batch 口径和 kernel 决定. 论文的 2.7 倍来自单张 H100, 每个外循环 batch 固定 128K token 的设置: 128K 时是一条序列, 8K 时是 16 条. 这个控制让 GPU 占用更可比, 也意味着数字不是任意服务 batch 下都能直接复现的常数.

**训练.** 这是主要局限. 训练要对梯度求梯度, 优化程度远不如普通 Transformer 训练. H200 上, 128K 时 TTT-E2E 的训练比全注意力快 1.2 倍, 8K 时慢 3.4 倍. 训练算力大部分花在短上下文预训练上, 所以这个局限分量很重. 每 token 的 FLOPs 恒定, 但 8K 到 32K 之间延迟仍在增长, 因为随时间的梯度检查点要按 $\log T$ 增加. 论文给了两个改进方向: 写支持二阶梯度的注意力 kernel (cuDNN 的 FlashAttention 目前不支持); 从预训练好的 Transformer 初始化, 只用 TTT-E2E 做少量后续训练.

这里的 1.2 倍和 3.4 倍用 H200, 固定每批 128K token 测得, 与 prefill 的 H100 结果不是同一张卡上的横向比较. 128K 时全注意力的 $T^2$ 代价足够大, TTT-E2E 即使背着二阶自动微分仍稍快; 8K 时全注意力已有成熟 kernel, TTT-E2E 的内外循环开销占主导, 于是方向反过来. 这两个数字放在一起, 才能看清它当前真正的工程问题: 长上下文阶段有优势, 训练预算最大的短上下文预训练阶段却更慢.


**两次改动落在不同层级**

**LaCT 改的是序列层的执行方式**

5.1 的 TTT layer 把一小段序列交给快速模型, 让内损失产生梯度, 再把更新后的参数当成隐藏状态. 它面对的基本矛盾是: 逐 token 更新保留完整的在线依赖, 却形成很长的串行链; 把整个块都放在同一个起点求梯度, 矩阵乘效率提高了, 块内的学习顺序也被抹平. LaCT 保留「参数作为状态」与「误差驱动写入」这两个核心设定, 重新安排一次更新覆盖多少 token, 更新结果从何时开始参与预测. 长块训练与应用协议构成方法主体, SGD, 归一化梯度和 Muon 提供不同写入算子.

把第 $c$ 个块记为 $X_c=(x_{c,1},\ldots,x_{c,B})$, 块开始的快速参数为 $W_c$. LaCT 在整个块上计算训练目标

$$
L_c(W_c)=\frac1B\sum_{i=1}^{B}\ell(f_{W_c}(u_{c,i}),v_{c,i}),
\tag{19}
$$

再由优化器 $\mathcal U$ 生成状态增量 $\Delta_c=\mathcal U(\nabla L_c)$, 得到 $W_{c+1}=W_c+\Delta_c$. 关键次序是: $X_c$ 负责训练出下一状态, $W_{c+1}$ 服务后面的块. 若当前块输出直接使用 $W_{c+1}$, 块尾 token 的信息便能倒流到块首输出; 若始终使用 $W_c$, 因果性成立, 但当前块写入要等到后续块才能发挥作用. 因此论文将局部窗口 attention 放在块内, 让近距离关系即时可见, 再让 LaCT 状态承担跨块压缩.

这套协议把串行深度从 token 数 $T$ 降为块数 $T/B$. 块内所有训练样本共享 $W_c$, 梯度能由大矩阵乘一次形成; 块间仍然顺序更新, 状态沿块传播. 它付出的模型代价也很明确: 块内更新顺序消失, 同一块中先出现的事实无法通过快速参数帮助稍后位置, 除非窗口分支覆盖两者. 其效率来自局部显式记忆与粗粒度长期学习之间的交换, 原在线轨迹没有被完整保留.

**TTT-E2E 改的是训练目标所在的位置**

TTT-E2E 处理另一处间接性. TTT layer 的内目标通常是隐藏表示重建: 慢参数要先学会构造 key, value 与 query, 使重建梯度碰巧成为语言模型需要的记忆写入. 最终 next-token loss 位于外循环, 推理时真正执行的内循环却优化代理损失. TTT-E2E 把普通语言模型的 next-token 目标直接放入测试时更新, 让模型在上下文前缀上做若干步语言建模训练, 再用更新后的参数预测后续 token.

设可更新参数为 $\theta$, 冻结或不参与内更新的参数为 $\phi$, 第 $c$ 个训练窗口的 token loss 为

$$
L_c^{\mathrm{LM}}(\theta,phi)
=-\sum_{i\in\mathcal I_c}\log p_{\theta,phi}(x_{i+1}\mid x_{\le i}).
\tag{20}
$$

推理状态按 $\theta_{c+1}=U(\theta_c,\nabla_\theta L_c^{\mathrm{LM}})$ 演化. 状态不再是插在网络中间的一张线性矩阵, 而是模型中被选中的普通参数块; 监督也不再来自投影后的自重建, 而来自真实下一个 token. 这样做消除了代理目标对齐的那一跳, 同时扩大了每次更新影响的函数范围. 更新一层 TTT-MLP 只改变该层的状态变换, 更新语言模型参数会改变从输入表示到词表概率的一整条路径, 收益与风险都更大.

训练 TTT-E2E 时, 初始化 $\theta_0$ 仍由跨序列外循环学习. 每条训练序列都从同一初始化开始, 执行模拟测试时更新, 再对更新后的预测求外层损失. 因而「E2E」指内循环目标与最终语言目标贯通, 也指外梯度穿过这些真实的语言模型更新; 它不代表测试时状态跨用户或跨文档永久保留. 序列结束后复位这一点没有改变.

**两种方法可以组合, 却不能混称**

LaCT 回答「怎样让长块更新具有可接受的并行度」, TTT-E2E 回答「测试时究竟优化什么目标」. 前者可以在隐藏状态重建上运行, 也可以承载语言模型损失; 后者可以逐 token, 小 mini-batch 或长 chunk 更新. 把它们放在一张坐标里, 一条轴是内目标的语义, 另一条轴是更新与应用的时间粒度. 目标相同不意味着执行协议相同, chunk 大小相同也不意味着梯度在训练模型的同一部分传播.

组合时, 第 $c$ 块用语言损失形成 $\theta_{c+1}$, 局部窗口负责块内即时预测, 更新后的模型服务 $c+1$ 块. 这时 LaCT 的一块延迟与 TTT-E2E 的真实 LM 梯度同时存在. 若块太大, 监督与受益位置相隔很远; 若块太小, 反向更新频繁, 吞吐下降. 最佳块长取决于局部窗口, 可更新参数量, 上下文中的主题持续时间和硬件矩阵形状, 无法由「线性复杂度」四个字直接决定.

**LaCT 的状态更新与因果结构**

### 2.2. 从块损失到跨块递推

先考虑普通 SGD. 块梯度为 $g_c=\nabla_WL_c(W_c)$, 更新为

$$
W_{c+1}=W_c-\eta_c g_c.
\tag{21}
$$

展开到第 $C$ 块开始, 可得 $W_C=W_0-\sum_{c<C}\eta_cg_c$. 表面上与外积累加相似, 实际每个 $g_c$ 都在不同的 $W_c$ 上计算, 且由整块样本共同决定. 某块的内容不仅直接改变状态, 还改变后续所有梯度的评估点. 跨块顺序仍被保留; 块内只剩集合式平均, 位置次序要靠位置编码, 因果 LM 计算或局部 attention 进入损失.

对视频扩散等双向块任务, 整块样本可以共同构造训练对, 集合化的伤害较小. 自回归语言模型要求每个位置只使用前缀, 块损失本身必须由因果网络产生. 即便每项 $\ell_i$ 合法, 若更新后的 $W_{c+1}$ 被拿来重算同一块输出, 参数里已经汇入块尾梯度, 仍然发生跨位置泄漏. 因此, 因果性既约束 loss 的前向 mask, 也约束「哪一版参数服务哪个位置」.

用状态时间戳能把实现规则写得很清楚. 令 $s(i)$ 表示位置 $i$ 输出使用的状态版本, $r(j)$ 表示位置 $j$ 的训练信号首次进入哪版状态. 合法条件是, 任何 $j>i$ 都不能满足 $r(j)\le s(i)$. LaCT 令整块的 $r(j)=c+1$, 块内输出使用 $s(i)=c$, 自然满足条件. 滑动更新或重叠 chunk 则要逐位置检查, 单看三角 attention mask 还不够.

**局部窗口如何填补一块延迟**

假设窗口半径为 $w$, 块长为 $B$. 第 $c$ 块内, 位置 $i$ 从窗口 attention 看见最近 $w$ 个 token, 从快速状态 $W_c$ 看见第 $c-1$ 块及更早内容的压缩. 若 $w\ge B$, 同块内任意较早位置都能直接到达当前 token, 一块延迟基本被覆盖; 若 $w<B$, 块首事实对块尾查询可能既未进入 $W_c$, 又已掉出窗口, 形成长度约 $B-w$ 的盲带.

这条盲带可以用构造题直接测量: 在块首写入随机键值, 在块尾查询, 逐渐改变二者距离并固定跨块历史. 准确率在距离超过 $w$ 后突然下降, 跨入下一块又恢复, 指向执行协议产生的周期性可见性缺口, 而非随距离平滑增加的长期遗忘. 随机平移块边界后, 曲线的凹口应随边界移动. 平均困惑度会把这种周期模式淹没, 按「距当前块首的位置」分桶才能看见.

窗口与 LaCT 状态还可能重复保存相同内容. 若写入目标主要由局部 token 决定, 快速模型会把窗口本已能访问的信息再次压入参数, 浪费长期容量. 可在训练目标中遮掉局部可预测成分, 或让值表示包含窗口残差; 是否有效要靠关闭窗口, 冻结 LaCT 更新和随机置换局部上下文的交叉消融判断. 只有联合模型比两条单独分支产生超加性收益, 才能说明它们学会了分工.

**chunk 平均怎样改变学习率语义**

式 (19) 使用均值时, 块长增加不会自动放大梯度总量; 使用求和时, 同一学习率下更新范数大致随有效 token 数增长. 论文实现中的 loss reduction, 梯度累积与优化器归一化共同决定「块长变大」究竟改变统计精度还是同时改变步长. 复算时若只照抄 $\eta$, 却把 sum 改成 mean, 得到的是另一套状态动力学.

均值也会让稀有但关键 token 被大量容易 token 稀释. 设块中只有一个新实体产生梯度 $g_*$, 其余 $B-1$ 个 token 梯度接近零, 平均后写入强度为 $g_*/B$. 若其他 token 梯度方向并不为零, 关键梯度还可能在平均中被抵消. 归一化梯度或 Muon 能改变整体尺度和谱, 却不能凭空恢复已经在样本求和中抵消的方向. token 权重, 惊讶度门控或更小的更新块处理的是不同问题.

反过来, 大块提供更低方差的主题统计. 许多局部证据沿相近方向时, 平均梯度能过滤单 token 噪声, 写入更像一段内容的摘要. LaCT 在视频上的优势与这种结构相容: 相邻时空块高度冗余, 单帧异常不应主导长期状态. 语言中的代码标识符, 随机数字和引用细节恰好更依赖孤立 token, 任务结构不同会改变大块平均是否合适.

**归一化更新与 Muon 的矩阵几何**

将梯度整体归一化为 $g/\lVert g\rVert$, 可以让写入步长不受块难度直接控制, 但同时丢掉「误差已经很小就少写」的自然性质. 简单内容与意外内容获得相近更新范数, 除非另有门控. 它主要解决数值尺度, 未必提供更好的信息选择.

Muon 针对矩阵参数对梯度做近似正交化. 若梯度奇异值分解为 $G=U\Sigma V^\top$, 理想化更新方向接近 $UV^\top$, 不同奇异方向的步长被拉平. 普通 SGD 强调大奇异值方向, 可能让少数主成分占据状态; 正交化让弱方向也获得写入, 有机会提高矩阵状态的有效秩. 代价是噪声小奇异方向也会被放大, 并且正交化迭代本身增加计算.

判断 Muon 带来的收益, 需要同时报告梯度谱, 更新后状态谱和任务误差. 若有效秩提高, 长距细节改善而主题级 loss 不变, 证据支持「容量分配更均匀」; 若所有指标都随更新范数变化, 收益可能只来自重新标定步长. 用具有相同 Frobenius 范数的 SGD 更新作为对照, 才能把方向处理与尺度处理分开.

**LaCT 外循环中的跨块信用**

训练慢参数时, 最终损失通过状态递推回传. 令 $J_c=\partial W_{c+1}/\partial W_c=I-\eta_cH_c$, 后面第 $C$ 块对早期状态的梯度包含 $\prod_{k=c}^{C-1}J_k$. 块变大后, 递推步数减少, 反向链更短; 每个 $H_c$ 却聚合更多样本, 曲率结构也变了. 长块改善优化深度, 并不保证更远内容获得更准的信用, 因为块内 token 共享一次更新, 外梯度无法指出块中哪一步状态本该先改变.

截断跨块反向时, 前向状态仍携带旧块信息, 早期写入规则却只能通过较近损失学习. 若数据主题在多个块间持续, 局部信用足以训练出可泛化的写入; 若某个 token 直到很远处才被查询, 直接元梯度被截断, 模型只能依赖训练中学到的通用「哪些东西值得记」规律. 改变反向截断块数, 再按查询距离分桶, 能测出模型是在获得远程监督, 还是仅凭局部代理形成了记忆习惯.

## 3. TTT-E2E 的双层目标与梯度路径

**一步语言模型更新的元梯度**

对一段支持前缀 $S$ 做一步更新, $\theta'=\theta-\eta\nabla_\theta L_S(\theta,\phi)$; 在后续查询段 $Q$ 上计算 $L_Q(\theta',\phi)$. 初始化的外梯度为

$$
\frac{dL_Q}{d\theta}
=\frac{\partial L_Q}{\partial\theta'}
\left(I-\eta\nabla_\theta^2L_S\right).
\tag{22}
$$

第一项推动初始化直接预测查询, Hessian 项则教初始化怎样经过一次前缀训练后变得更有用. 若采用 first-order 近似丢掉 Hessian, 仍能训练一个不错的静态语言模型, 也能让推理时 SGD 工作, 却削弱了「为了可适应性而塑造初始化」的信号. 完整二阶梯度代价高, 论文报告的短上下文训练减速需要和这条额外路径一起理解.

冻结参数 $\phi$ 也收到两条梯度. 一条来自查询前向, 另一条通过支持段损失改变内梯度:

$$
\frac{dL_Q}{d\phi}
=\frac{\partial L_Q}{\partial\phi}
-\eta\frac{\partial L_Q}{\partial\theta'}
\frac{\partial^2L_S}{\partial\theta\partial\phi}.
\tag{23}
$$

因此, 「冻结」只表示测试时不更新, 训练时它仍能学习怎样产生对 $\theta$ 有用的梯度. 例如冻结层可以调整表示, 使某个实体在可更新 MLP 中产生独特方向. 切断混合二阶项后, 冻结部分只为当前预测服务, 无法主动塑造内循环的可学习性.

**多步更新与信用衰减**

执行 $K$ 步内更新时, 初始化梯度要乘上一串 $I-\eta_kH_k$. 这与训练深层递归网络相似, 可能消失, 爆炸或被少数高曲率方向支配. 序列更长不只增加计算量, 也延长元梯度必须穿越的优化轨迹. 梯度裁剪能限制最终范数, 却无法恢复已经在乘积中消失的方向.

一条可复算的诊断是, 在同一批样本上分别记录第 1,2,4,8,16 步后的查询收益, 以及查询损失对各步更新的梯度范数. 若后续收益继续增加而早期步骤几乎收不到外梯度, 模型的前向记忆长度已经超过可训练信用长度; 若更新几步后收益转负, 当前学习率, 参数子集或正则无法承受更长适应. 只报告最终困惑度会把两种情况混在一起.

梯度检查点和重计算减少激活内存, 不改变数学目标; 截断, stop-gradient 和把若干步合并成同一起点梯度会改变目标. 实验表应明确属于哪一种. 内循环实现若在框架中意外 detach, 训练仍可能正常下降, 因为静态路径还在, 最终模型却没有学到完整的更新规则.

**哪些参数进入内循环**

更新全部模型参数提供最大自由度, 也让 fast state, 反向成本和遗忘风险同时膨胀. 只更新 MLP, 低秩适配器, 归一化尺度或少数层, 对应不同函数族. 更新高层 MLP 更直接改变语义与词表决策; 更新低层表示会影响所有后续计算, 局部错误传播范围更广; 低秩参数限制更新子空间, 以容量换稳定.

若每个 Transformer block 同时保留一条冻结 MLP 与一条可更新 MLP, 冻结支路承载初始化知识, 可更新支路记录上下文偏移. 设输出为 $h'=h+F_\phi(h)+A_{\theta_t}(h)$, 清零 $A$ 便退回稳定底座; 内更新只改变 $A$. 这种分解降低灾难性覆盖, 但并未保证两条支路分工. 外循环可能把大量静态知识塞进 $A_{\theta_0}$, 让冻结支路变弱. 随机复位适配支路, 约束初始输出范数或比较共享与独立初始化, 可以检查底座是否真的承担了锚点作用.

参数子集的公平比较至少有三种口径: 相同可更新参数量, 相同 fast-state 字节, 相同每 token 更新 FLOPs. 低秩适配器在第一种口径下计算更便宜, 可增加 rank; 全矩阵在第二种口径下可能没有优化器状态空间; 不同结论不能混用. TTT-E2E 的优势若只在更大状态预算下出现, 应表述为容量收益, 不宜归结为目标本身.

**next-token 梯度写入了什么**

语言模型梯度混合了实体, 句法, 频率与当前预测误差. 一个罕见字符串产生较大 surprisal, 可能形成强写入; 已经被底座预测正确的事实梯度很小, 即便后面还会查询, 也可能几乎没有进入状态. 误差驱动机制优化「修正当前不会的内容」, 与任务需要的「保存以后有用的内容」并不完全重合.

这会产生一个清楚的反例: 把关键值换成底座极易预测的常见短语, 同时查询要求逐字复现. 支持段 loss 很低, 内更新微弱, 后来查询未必受益; 把值换成随机字符串后, 梯度更大, 模型反而可能记得更牢. 若实验只使用随机 needle, 会高估 surprisal 作为重要性代理的合理性. 按底座初始 surprisal 匹配样本, 再比较未来效用, 能够分离「难所以写得多」与「有用所以应该记」.

next-token loss 还可能把局部统计写入参数. 例如一段代码中某个标识符频繁出现, 更新能提高它的无条件概率, 却未必保存它与定义位置的关系. 查询时命中可能来自词频适应, 而非关系记忆. 保持 token 频率不变, 打乱键值配对, 是区分两者的简单干预.

**因果 mask, 滑动窗口与 mini-batch 近似**

### 3.1. 训练窗口和预测窗口不能混用

设内更新窗口为 $[a,b]$, 预测位置为 $i$. 若 $b\ge i$, 更新梯度已经接触当前位置或未来 token, 预测发生泄漏. 合法做法是让 $b<i$, 或使用严格的 leave-one-prefix 结构, 为每个位置构造只含更早 token 的参数版本. 后者计算昂贵, 实践中常以不重叠 chunk 或带延迟的滑动更新近似.

普通 causal attention mask 只约束一次前向中的激活连接. 梯度更新会把整个训练窗口的信息汇总进参数, 随后任何使用该参数的位置都能间接读取这些信息. 检查因果性时, 要把参数版本看作一条额外边. 修改未来 token 并重跑前缀输出, 是最直接的黑盒测试; 只查看 attention 矩阵无法发现参数通道泄漏.

重叠窗口还有重复训练问题. 若步幅小于窗口长, 一个 token 会参与多次更新, 其有效权重取决于覆盖次数. 序列中部通常比边界 token 被看见更多, 形成位置相关学习率. 对每个 token 统计进入 loss 的次数并做归一化, 可以消除纯粹的三角覆盖偏置; 保留偏置则相当于人为强调中部内容, 需要在方法定义中明确.

**同起点 mini-batch 的误差**

为了并行, 若一个 chunk 内的多个梯度都在 $\theta_c$ 上计算, 再做前缀累积, 得到的是局部线性化的优化轨迹. 真实第二步应该在 $\theta_c-\eta g_1$ 上计算, 其差异的一阶主项是 $-\eta H_2g_1$. 5.1 已经推过这个形式; 在 TTT-E2E 中, $H_2$ 是完整语言模型子网络的 Hessian, token 之间的耦合更强, 近似误差不再局限于一张线性快速矩阵.

误差大小可以直接测, 不必只凭最终 loss 推断. 在小模型和短 chunk 上保存逐步 SGD 的参数轨迹, 与并行近似逐位置比较函数输出, 梯度夹角和查询收益. 参数欧氏距离受重参数化影响, 输出 KL 或固定探针集上的 logit 差更有解释力. 随着 chunk 增大, 若轨迹差迅速上升而任务指标暂时稳定, 说明模型对近似有鲁棒性; 若两者同步恶化, chunk 已越过可接受范围.

**更新延迟和信息新鲜度**

chunk 更新天然有延迟. 某 token 在窗口开始出现, 要等窗口结束, 反向完成后才进入新参数. 对离线 prefill, 这只是计算排布; 对流式生成, 它意味着模型在若干 token 内无法利用刚出现的信息. 窗口越大, 吞吐越好, 状态新鲜度越差.

可以用突发主题切换测延迟: 序列中途突然引入新词表或映射规则, 逐 token 记录适应曲线. 在线 SGD 应平滑改善, chunk 方法在边界处阶跃. 若任务要求规则出现后立即生效, 平均到整段的困惑度不足以表示体验; 边界前后的瞬时损失更重要. 重叠小步幅能降低延迟, 却增加重复计算和覆盖权重问题.

**稳定性, 容量与遗忘**

**端到端更新为何更容易漂移**

隐藏层 TTT 的快速状态通常经过残差与慢参数网络约束, 作用范围局部. TTT-E2E 更新普通模型参数, 微小位移可以经过许多层放大到词表 logits. 若更新后的分布为 $p_{\theta'}$, 可用支持段外的锚点集合测 $D_{KL}(p_{\theta_0}\Vert p_{\theta'})$. 锚点 KL 快速增长而支持 loss 下降, 表示模型正在用全局能力换局部适应.

冻结支路, 权重衰减和 proximal 正则都能提供锚点. 内目标加入 $\frac\lambda2\lVert\theta-\theta_0\rVert^2$ 后, 更新多出拉回初始化的项; 它限制漂移, 也让较早写入按时间衰减.$lambda$ 的合适范围与更新步数相关, 固定每步衰减在更长上下文上会产生更强总遗忘. 比较不同长度时保持单步超参不变, 并不等于保持相同的有效先验强度.

梯度裁剪处理异常大步, 无法阻止许多小步沿同一方向累计. 监控累计路径长度 $\sum_t\lVert\Delta\theta_t\rVert$, 最终位移 $\lVert\theta_T-\theta_0\rVert$ 与函数 KL, 可以区分来回震荡, 单向漂移和参数移动但函数近似不变. 三者对应的修复不同: 震荡需要曲率或步长控制, 单向漂移需要锚定, 函数不变可能说明更新落在冗余参数方向.

## 4. fast-state 参数量不等于可用记忆

TTT-E2E 可更新数百万甚至数十亿参数, 看似容量巨大; 一条序列只执行有限梯度步, 能到达的状态位于这些梯度张成的低维子空间. 若执行 $K$ 步普通 SGD, 不考虑梯度随状态变化, 位移最多落在 $K$ 个梯度方向的张成空间. 参数多提供潜在自由度, 更新次数与梯度多样性决定实际写入了多少方向.

动量和 Adam 增加状态变量, 也会改变可达轨迹. 若论文仅统计可更新权重而忽略优化器矩, 状态预算被低估. 反向激活是临时工作空间, 不随序列持续; 权重与优化器状态才是持久 fast state. 比较 KV cache, SSM 与 TTT-E2E 时, 应同时列持久字节, 每次更新临时字节和每 token 计算, 三者分别约束长序列容量, 峰值显存和吞吐.

容量还受输出任务结构影响. 大量 token 共享主题或风格时, 一个参数方向可服务许多预测; 随机键值要求近乎独立的绑定, 每条事实消耗更多有效维度. 语言 loss 上的良好 scaling 不推出随机检索容量同样 scaling, S-NIAH 的下降正是压缩状态面对独立细节时的压力表现.

**覆盖, 反学习与状态恢复**

构造同一个键先对应值 A, 后来对应值 B. 语言模型更新若未把时间或局部上下文编码进地址, 后一次梯度会把输出推向 B. 查询「最初的值」与「最新的值」分别测历史保存和状态追踪. 只测最新值会把覆盖当成成功适应, 只测旧值又会惩罚合理更新.

再加入 A 的少量证据, 观察恢复需要多少 token. 快速恢复说明初始化或旧状态仍保留相关方向; 完全从头学习说明 B 已覆盖 A; 出现 A/B 混合概率则可能学到条件均值. 保存冲突前状态并在相同后缀上分叉运行, 可以排除生成随机性与上下文差异.

对 TTT-E2E, 还可清空可更新支路, 恢复初始化, 交换两个序列的 fast state. 恢复初始化后长程收益消失, 证明收益依赖测试时更新; 交换状态若把另一序列的实体概率带过来, 证明参数确实携带内容; 交换后只出现普遍的低 loss 改善, 则状态更像领域适配而非情节记忆.

**论文实验如何逐项复算**

**LaCT: 先固定状态与窗口预算**

复算 LaCT 的第一步是把基线拆成相同局部窗口, 相同 backbone, 相同训练 token 与相同状态宽度. 全 attention 拥有随长度增长的缓存, 固定状态方法拥有恒定持久状态, 二者无法同时对齐缓存与精确访问能力, 因此至少要并列报告参数, FLOPs, 峰值显存和持久状态字节. 只对齐总参数会掩盖 LaCT 的块更新工作量, 只对齐 FLOPs又可能给不同模型不同静态容量.

随后复核更新规则. SGD, 归一化 SGD 与 Muon 的学习率不能按数值直接比较, 因为三者方向范数不同. 记录每块 $\lVert\Delta W_c\rVert_F/\lVert W_c\rVert_F$, 梯度谱和状态有效秩, 再匹配实际相对位移, 才能判断 Muon 改善来自矩阵几何还是更大的有效步长.

块长消融要与窗口共同形成二维网格. 固定窗口增大块长, 会扩大盲带; 让窗口随块长增长, 又增加 attention 成本. 论文结果若只沿其中一条路径变化, 无法单独归因于 LaCT 状态. 二维网格中, 等计算预算的对角线最有价值: 它展示把预算从局部精确记忆移到长期参数状态后, 任务怎样变化.

视频任务还要固定帧数, 空间分辨率, 扩散采样设置和条件信息. 语言结论不能直接由视频指标外推, 视频的局部冗余, 双向处理和生成目标都不同. 跨模态一致的证据是大块更新确实提高硬件利用, 固定状态能汇总冗余; 精确自回归检索仍需语言实验单独验证.

**TTT-E2E: 把训练成本和推理收益分开**

TTT-E2E 的训练包含穿过内更新的高阶梯度, 推理也要执行反向; 普通 Transformer prefill 只有前向. 报告端到端速度时, 应分开训练, prefill 更新, 更新后 decode, 并注明是否包含编译, 状态初始化和优化器步骤. 把训练慢 3.4 倍与长上下文推理交叉点放在同一列, 读者才能判断一次昂贵预训练换来了什么部署收益.

困惑度复算需明确每个 token 由更新前还是更新后状态预测, loss 是否包含用于训练自身的 token, 块边界如何处理. 若支持 token 的训练 loss 也计入最终指标, 模型可能因看过标签得到虚低数值. 严格 prequential 评测应先预测 token, 再将其加入后续更新; 块协议则按块先预测, 后训练. 两种口径的数值不可直接混在一张表中.

S-NIAH 需要记录 needle 数, 键值长度, 插入位置, 查询位置, 局部窗口和底座是否可能背诵答案. 随机生成值排除预训练记忆, 多个相似键测试干扰, 查询任意早期键排除「返回最近值」捷径. 按距更新边界和距查询距离双重分桶, 可以区分状态容量下降与 chunk 可见性缺口.

长序列生成还要观察更新是否使用模型自己生成的 token. 若把采样结果继续作为训练目标, 错误会被当作标签强化, 形成确认偏差; 若只在用户提供的上下文上更新, 状态在生成阶段固定, 适应能力不同. 实验协议必须说明 teacher-forced prefill 与 free-running decode 的边界.

### 4.1. 结果数字的最低复核集合

每个主要表格至少保留五类数字: 最终任务指标, 静态参数量, 持久 fast-state 字节, 训练与推理 FLOPs, 实测吞吐或延迟. 再附更新范数, 锚点 KL 与状态有效秩三类中间量. 前五项保证资源公平, 后三项让机制解释有落点. 只复现终点指标, 即使数值接近, 也无法确认实现走的是同一条状态轨迹.

随机种子对测试时更新格外重要. 初始化相同, 样本顺序变化就会改变梯度路径; 块边界偏移又会改变哪些 token 共同平均. 至少报告多个顺序与多个边界 offset 的均值和方差. 某配置若只在固定分块下占优, 收益可能来自数据排布巧合.

失败运行也属于结果. 长链高阶梯度可能 OOM 或 NaN, Muon 正交化可能在低精度失稳, 大块 loss 可能把稀有梯度稀释到不可见. 记录首次异常的长度, 块号, 状态范数和精度, 比删除失败点后拟合一条平滑 scaling 曲线更诚实, 也更能判断方法能否继续扩展.

**反例与可证伪消融**

**块内顺序反例**

把冲突规则分到相邻块, LaCT 又能感知顺序, 因为第二块梯度在更新后的状态上计算. 同一内容只因跨过人工边界就获得顺序语义, 说明模型可能对 chunk 划分敏感. 随机边界训练能缓解固定周期依赖, 却不会恢复单个块内部完整在线轨迹.

**低 surprisal 高价值反例**

支持段写入一句语法极常见, 具体任务却要求远处逐字引用的话. 底座对每个 token 概率都很高, TTT-E2E 梯度很小; 另放一串无关随机字符, surprisal 很高但之后从不查询. 若写入强度只跟 loss 走, 状态会优先吸收无关随机串. 未来效用与当前惊讶度在这个构造中被刻意拆开.

加入由未来查询反传的外循环后, 模型可能通过表示与参数敏感度放大有用常见句子的梯度, 压低无关随机串. 比较完整元梯度, first-order, 停止跨更新梯度三种训练, 能检验这条信用是否真的学成. 三者行为相同, 则「端到端学会记什么」缺少支持.

**静态容量伪装成适应**

增加一条可更新 MLP 会同时增加初始化时的静态参数. 即使推理阶段完全不更新, 更大模型也可能降低困惑度. 冻结内更新并保留同样网络, 给出静态容量基线; 再用等参数普通 MLP 替换可更新支路, 给出结构基线. 完整模型超过两者的差值, 才属于测试时学习.

还可随机打乱支持段梯度与序列的配对. 若错误序列的更新仍带来相近改善, 收益可能来自通用额外计算, 正则或领域平均, 不是内容特异记忆. 若输出被错误序列中的实体系统性诱导, 说明 fast state 确实写入了具体内容, 同时也量化了跨会话状态串用的风险.

**梯度步数的 U 形曲线**

固定支持段, 改变内更新步数. 开始几步降低查询 loss, 过多步骤可能过拟合支持 token, 破坏锚点能力, 形成 U 形曲线. 若性能始终单调改善直到测试上限, 尚未找到稳定边界; 若第一步后立刻恶化, 初始化, 学习率或参数子集不适合适应.

同时画支持 loss, 查询 loss, 锚点 KL 和参数位移. 支持 loss 继续下降而查询回升, 是经典过适应; 支持与查询同时回升更像数值不稳; 锚点 KL 增长但查询仍改善, 表示局部收益正在消耗通用能力. 四条曲线比单个最佳步数更能解释为何某配置有效.

### 4.2. 证明窗口与快速状态各自工作

完整混合模型做四次前向: 两条分支都开, 只开窗口, 只开快速状态, 两条都关. 短距离查询应主要由窗口承担, 跨块远距离查询才应显出快速状态贡献. 若只开窗口已达到完整模型, 更新分支可能没有被读; 若只开快速状态在块内同样好, 需要检查参数版本是否泄漏未来.

进一步把快速状态替换成另一序列, 在某个块边界清零, 或仅删除 needle token 对梯度的贡献. 内容特异性能随这些干预有方向地变化, 才构成因果证据. 状态范数变大, 梯度热图醒目或 attention 权重集中都只能说明内部量发生变化, 不能单独证明模型利用了那段历史.

从整段似然到在线预序列目标. 评测顺序本身就是目标定义. 测试时训练很容易在 loss 口径上发生含混. 对序列 $x_{1:T}$, 标准自回归负对数似然为 $-\sum_t\log p(x_t\mid x_{<t})$. 若状态允许在看到 $x_t$ 后更新, 那么 $x_t$ 只能改善 $t+1$ 及以后预测; 用更新后的状态再次给 $x_t$ 打分, 相当于允许模型先看答案再考试. 把预测与更新交替写开, 合法的预序列过程是

$$
\ell_t=-\log p_{\theta_t}(x_t\mid x_{<t}),\qquad
\theta_{t+1}=U(\theta_t,\nabla_{\theta_t}\ell_t).
\tag{24}
$$

chunk 版本将 token 换成块: 先用 $\theta_c$ 给整块逐位置打分, 再用该块 loss 形成 $\theta_{c+1}$. 只要块内前向保持 causal, 所有被计分 token 都没有进入服务自身预测的 fast state. 论文中的滑动窗口, 缓存复用和并行计算最终都应还原到这个时间次序.

训练时常见的 support/query 划分是同一原则的显式版本. 支持段只产生更新, 查询段只用于外层评估; 滑动执行则让一个位置先作为 query 被计分, 随后成为未来位置的 support. 两者的目标权重不同: 固定 support/query 会丢掉支持段的评测贡献, 完整 prequential loss 给每个位置一次预测机会. 复现若改变划分比例, 既改变训练数据量, 也改变一次更新能服务多少后续 token.

更新收益可以分解成梯度对齐. 对一步小更新, 查询 loss 的变化可一阶近似为

$$
L_Q(\theta-\eta g_S)-L_Q(\theta)
\approx-\eta\langle g_Q,g_S\rangle.
\tag{25}
$$

其中 $g_S$ 是支持段梯度, $g_Q$ 是查询段梯度. 测试时训练有效的最直接条件, 是过去 token 的梯度与未来 token 的梯度正对齐. 主题延续, 重复实体和稳定文体通常提高对齐; 主题突变, 冲突事实或随机噪声可能产生负对齐. 二阶项决定步长较大后的偏离, 但一阶内积已经能解释为何同样的更新规则在不同数据上差异很大.

这个量也把 LaCT 的块平均问题具体化. 令块梯度 $g_S=B^{-1}\sum_i g_i$, 它与查询梯度的内积是各 token 对齐度的平均. 大量无关 token 的期望对齐接近零, 却会降低有效信噪比; 负对齐 token 会直接抵消关键证据. 逐 token 记录 $\langle g_i,g_Q\rangle$, 再按 surprisal, 位置和语义类型分桶, 可以检查高损失是否真的预示未来价值.

若外循环训练成功, 它会塑造表示, 使有未来作用的支持梯度更容易与查询梯度对齐. 比较训练初期与收敛后的对齐分布, 是验证元学习机制的一条路径. 只看到查询 loss 下降, 还可能来自更强静态初始化; 看到内容相关的梯度对齐经过训练系统性增强, 才更接近「学会如何从上下文更新」.

二阶项给出安全步长的局部尺度. 保留二阶展开, 查询变化约为

$$
\Delta L_Q\approx-\eta g_Q^\top g_S
+\frac{\eta^2}{2}g_S^\top H_Qg_S.
\tag{26}
$$

第一项是适应收益, 第二项是查询曲率带来的惩罚. 在 $g_Q^\top g_S>0$ 且二次型为正时, 存在局部最优步长; 盲目增大学习率会越过它. 若梯度负对齐, 任何足够小的正步长都会伤害查询, 此时裁剪只能减少损害, 无法改变方向. 门控应识别负迁移, 预条件器则能旋转或缩放更新方向.

按块学习率可以由块表示预测, 也能由梯度统计决定. 输入门容易学习语义启发, 梯度门直接接触惊讶度与一致性. 两者都要防止利用未来查询信息: 测试时门只能读取当前支持块及已有状态. 训练中若门网络看到了 query loss 或未来隐藏表示, 部署时无法复现同样决策.
