# Dolma 技术解析：三万亿 Token 开放语料的设计、验证与边界

arXiv:2402.00159v2 的 64 页论文、官方 LaTeX 与 Dolma Toolkit 对应 Dolma v1.6，文中数字也只适用于这一版本。Dolma 的贡献不只是约三万亿 token 的英语语料，还包括逐来源构建说明、数据消融和开源工具。

## 1. 统计目标、开放边界与实验工具

论文提出四个目标。第一，与已知大模型预训练配方保持一致，使公开数据可以用于研究闭源模型的数据实践；这也使 v1.6 聚焦英语，作者承认它强化“英语是默认语言”的假设。第二，在行业做法不明确时，使用小模型消融支持选择。第三，目标规模为 2–3T token，以研究模型和数据规模关系。第四，开放同时意味着发布数据并记录整理过程，必要时因法律、伦理与实践约束偏离商业配方。 团队没有纳入处于版权争议中心的 Books3, 并主动处理 PII. 这里的开放覆盖来源记录, 删除规则与风险政策, 语料规模只是其中一项. 语料覆盖六类来源、超过 40 亿文档。Common Crawl 约 9,812GB、37.34 亿文档、1.928T Unicode words、2.479T Llama token；GitHub 1,043GB、2.10 亿文档、260B words、411B token；Reddit 339GB、3.77 亿文档、72B words、89B token；Semantic Scholar 268GB、3880 万文档、50B words、70B token；Gutenberg 20.4GB、5.6 万文档、4B words、6B token；Wikipedia/Wikibooks 16.2GB、620 万文档、3.7B words、4.3B token。token 数绑定 tokenizer，不能与字节或 Unicode word 混用。 **1.1. Toolkit 与数据消融.**

Toolkit 把常见操作统一为 filtering 与 mixing。过滤阶段在文档、段落或句子上计算语言、质量、内容和 PII 信号，再删除或替换；Mixer 负责跨文件上/下采样、去重、去污染与输出。属性和文档分离，使阈值改变时不必重跑昂贵分类器。 论文给出性能量级：内部复现 C4 配方时每 TB 约需 122 CPU 小时；用一台 192 vCPU 的 `c6a.48xlarge` 处理约 200TB raw Dolma，估算五天。该数字绑定任务、实例与存储环境，不是任意 tagger 的固定吞吐。Bloom filter 提供线性时间概率去重，也可先放测试片段再做去污染，但存在误报；容量、元素估计、哈希与输入顺序都属于复现参数。

团队用 OLMo 系列 1.2B decoder-only 模型比较数据干预，每个模型训练到 150B token 后停止。评测覆盖八项数据集，使用 zero-shot in-context prompting，把任务转为 ranked text classification。消融比文本统计更接近训练目标，但外推边界明显：1.2B 的早期排名不保证在大模型和多万亿 token 下不变，八项评测也不覆盖生成、安全、多语与长上下文。 **1.2. 数据整理优化的是训练分布.** 设原始来源分布为 $p_0(x,s)$, 其中 $x$ 是文档, $s$ 是来源。过滤器给出接受概率 $a(x,s)\in[0,1]$, 混合器为来源赋权 $w_s$, 去重又给每个等价内容簇分配保留权重 $d(x)$。最终送入训练的分布满足

$$
p_{train}(x,s)=
\frac{p_0(x,s)a(x,s)w_sd(x)}
{\sum_{s'}\int p_0(x',s')a(x',s')w_{s'}d(x')\,dx'}.
$$

这条式子说明过滤、去重与混合没有彼此独立。过滤改变每个来源剩余多少内容, 固定来源权重随后会放大或缩小剩余文档; 去重把高复制内容的经验频率压低, 同时改变域内主题比例。最终 token 数只是归一化后的规模, 无法单独描述训练分布。 语言模型预训练最直接优化 $p_{train}$ 上的交叉熵

$$
R_{train}(\theta)=E_{(x,s)\sim p_{train}}
[-\log p_\theta(x)].
$$

真正关心的却可能是目标域集合 $q_1,\ldots,q_K$ 上的风险。数据整理要在有限 token 预算下选择 $p_{train}$, 使若干 $R_{q_k}(\theta)$ 足够低, 同时满足隐私、许可、毒性、代表性与成本约束。不存在一个脱离目标域的「最高质量」标量; Wikipedia 相似度、Gopher 规则、投票和代码仓库星数都只是不同代理。 Dolma 的设计目标还包含规模下限。若理想过滤器保留概率过低, 训练预算 $B$ 会迫使剩余数据重复多个 epoch, 或要求补入其他来源。设清洗后唯一 token 数为 $U$, 训练预算为 $B$, 则平均重用次数约为 $B/U$。继续收紧过滤可能提高单 token 质量, 也可能增大重复和记忆风险。论文最终选用较宽松 toxicity 阈值, 正是质量改善与语料规模约束共同作用的实例。 **1.3. 数据量有四种常被混用的口径.**

Dolma 同时报告压缩字节、文档数、Unicode word 和 tokenizer token。四者回答不同问题。字节接近存储与扫描成本; 文档数决定文档级抽样和元数据数量; Unicode word 便于不绑定 tokenizer 地比较文本量; token 才直接进入训练步数和损失权重。过滤 10% 文档可能只删除 2% token, 也可能删掉 30%, 取决于被删文档长度。 设来源 $s$ 有 $N_s$ 篇文档, 第 $i$ 篇经过 tokenizer 后长度为 $L_{si}$。来源 token 量为 $T_s=\sum_iL_{si}$。若训练按 token 流均匀采样, 单篇文档被看到的概率与 $L_{si}$ 成正比; 若先均匀抽文档再截取固定长度, 权重会不同。只给 $N_s$ 与 $T_s$ 仍不足以恢复长尾长度分布。

The Stack 的 fertility 明显高于其他来源, 官方 tokenization 附录把它与换行、制表符等空白字符的较高频率联系起来。fertility 指每个 word 或字符被切成多少 token。代码在 LLaMA tokenizer 下 token 膨胀更大, 因而 15% token 比例对应的原始字节或语义单元比例可能远低于 15%。跨 tokenizer 复现 mixture 时, 按文件数量或字节比例复刻会改变训练 token 权重。

文档拼接还会加入 EOS 并把多个短文档打包进定长序列。Reddit 原子评论、百科短页和长篇论文拥有不同边界密度。若每篇都插一个 EOS, 每十亿 token 中的文档边界数量会随 mixture 改变, 模型学到的重置频率也随之变化。配方复现应记录来源 token 比例、文档数量、长度分布和 EOS 密度。 **1.4. 开放性让数据假设可以被证伪.** 开放数据的科学价值不只在可下载。给定稳定文档 ID、来源、属性、过滤规则和版本, 研究者可以回答某项能力来自哪些样本、某条规则删掉了哪些群体、benchmark 是否与预训练文本重叠。若只发布最终文本, 仍能训练模型, 却无法重建接受函数 $a(x,s)$。

属性与正文分离使反事实配方成为可能。假设 toxicity tagger 为每句给出分数 $z$, v1.6 使用阈值 $\tau_h$, 研究者可以从同一属性构造更严格的 $\tau_l$, 保持其他步骤不变。这个设计减少重复计算, 也把反事实限制在 tagger 已保存的信息内。若后来换分类器、修复切句或增加新的群体公平信号, 仍需重新标注原始文本。

可证伪性依赖中间数据完整。只记录某规则删了 15.23% 字符, 无法检查这些字符集中在哪些域; 只记录最终模型提高, 无法判断过滤、去重还是 mixture 造成变化。最有信息量的发布包括规则逐项命中、交集、稳定 ID、版本化 manifest 以及受控训练结果。Dolma 已提供比多数模型数据说明更完整的证据链, 仍没有发布互联网原始快照的全部权利与状态信息。

## 2. 网页过滤、质量定义与代表性

Dolma-Web 约 2.28T token，来自 `2020-05` 至 `2023-06` 的 25 个 Common Crawl snapshot。到 2024 年 2 月共有 97 个 snapshot，团队只下载达到目标规模所需的 shard，并假设清洗至少缩小十倍，因此它不是同期互联网完整镜像。 CCNet 先做语言识别与初始段落去重。FastText 英语阈值为 0.5，按字节移除 61.7%。CCNet 在 snapshot 内的小 shard 组中删除高频段落，约去除 70% 段落，多为导航与页眉。两步合计过滤 84.2%，从 175.1TB 降到 27.7TB。该段落去重是局部分组，不等于全局文档去重。 质量过滤采用 Gopher 全部规则加 C4 NoPunc，而非完整 C4。消融显示 C4 NoPunc 单独优于 C4 All 和 Gopher All，二者组合最好。Gopher 标记 15.23%、NoPunc 标记 22.73% UTF-8 字符，命中可能重叠，不能简单相加。KenLM 的 Wikipedia 相似度把文档分为高 21.9%、中 28.5%、低 49.6%；启发式过滤没有改变这些比例，说明两类信号近似正交。 **2.1. 内容、PII 与规模权衡.**

团队在 Jigsaw Toxic Comments 上训练 hate 与 NSFW 两个 FastText 分类器, 对 BlingFire 切分的句子评分. 高阈值 `τ=0.4` 删除 5.5–7.3%, 低阈值 `τ=0.0004` 删除 29.1–34.9%; 低阈值总体下游表现更好, 但 v1.6 为满足最低 token 规模选择了更宽松的高阈值. 质量, 内容和去重过滤的删除集合重叠很少, 串联后压缩效应很强. 这个阈值是在下游表现与最低语料规模之间做出的取舍. 作者还强调 toxicity 与 quality 都带价值判断。毒性定义随任务、整理者身份和标注者信念变化，检测器也可能歧视边缘群体。公开阈值和删除比例，使外界能研究这些偏差。

PII 过滤聚焦邮箱、IP 和电话号码。每篇不超过五个 PII span 时用特殊 token 替换，影响 0.02% 文档；超过五个则删除整篇，影响 0.001%。模型式检测器在该规模成本过高，因此使用正则以准确率换速度。消融未见删除与替换的性能差异，符合受影响比例极小，但不表示隐私风险已完全解决。 **2.2. 过滤器的接受域决定谁被代表.**

质量规则可以写成特征向量 $z(x)$ 上的接受域 $A$。Gopher All 同时检查长度、符号比例、重复、停用词等多项条件, 只有满足规则集合的文档才能保留; C4 NoPunc 主要删除缺少终止标点的段落。二者组合相当于取接受域交集 $A_G\cap A_C$。交集可能提高平均可读性, 也会系统排除与规则假设不符的文本。

缺少句末标点可能来自导航垃圾, 也可能来自诗歌、聊天、列表、标题、代码注释或使用不同标点习惯的英语变体。规则无法从表面形式完全区分这些情形。若被排除群体在八项评测中占比很低, 模型平均分仍可能提高。代表性分析必须直接检查条件保留率

$$
r_g=P(x\in A\mid g),
$$

其中 $g$ 可以是来源、方言、年代、主题或文体。整体保留率 $P(x\in A)$ 是各 $r_g$ 的加权平均, 可能掩盖某个小群体接近全部消失。 语言识别阈值也属于接受域。FastText 英语分数达到 0.5 才保留, 会移除非英语, 也会影响夹杂代码、公式、专名或多语段落的英语文档。按字节删除 61.7% 表明原始 Common Crawl 中大量内容不符合该范围, 但这个数字不能解释误判率。验证语言过滤需要在阈值附近分层人工标注, 分别估计英语精度与召回。 **2.3. 过滤交集需要联合分布.** 设规则 $F_i=1$ 表示文档被第 $i$ 个过滤器命中。两个规则组合删除率为

$$
P(F_1\cup F_2)=P(F_1)+P(F_2)-P(F_1\cap F_2).
$$

没有交集项就无法由单项比例推最终规模。若 Gopher 与 NoPunc 分别命中 15.23% 和 22.73% 字符, 完全重合时组合仍只删 22.73%; 完全不重合时可删 37.96%。真实值位于两者之间, 还会因统计单位为字符而不同于文档保留率。 三类以上规则需要更高阶交集。质量、toxicity、PII 和去重若命中近似正交, 组合保留率会快速下降; 若大量命中同一批垃圾文档, 后续规则增量很小。官方附录在高、中、低困惑度桶上计算过滤相关, 并指出 Gopher 与去重在高困惑度尾部呈负相关: 随机字符串会被 Gopher 删除, 却因彼此不重复而不易被去重命中。这解释了为何两类清理具有互补性。

过滤顺序不改变集合交集的理论结果, 会改变实际计算和统计。先删除 Gopher 垃圾后再统计去重命中, 分母已经变小; 报告「去重删除 10%」必须说明相对于原始数据还是当前阶段输入。带状态的 Bloom 去重更复杂, 因为早先插入的内容会决定后来的副本是否命中, 顺序甚至改变保留 ID。 **2.4. toxicity 阈值连接性能与价值选择.** 论文的 hate 与 NSFW 分类器在 Jigsaw 数据上训练, 对切句后的网页文本评分。句子分数分布近似双峰, 团队比较很低与较高两个阈值。低阈值只要分数略高于零就删除, 高阈值允许更多边界文本。低阈值消融表现更好, 最终 v1.6 仍选择高阈值以保住目标规模。

这个结果不能解释成 toxic 文本越少越好的一般定律。分类器输出混合了真实有害内容、引用讨论、身份词和标注偏差。严格阈值可能删除仇恨表达, 也可能删除对歧视的研究、被攻击群体的自述或少数身份相关语言。八项通用评测不测这些信息损失, 因而性能与代表性需要分开报告。 阈值选择可形式化为约束优化。令 $Q(\tau)$ 是代理质量, $U(\tau)$ 是唯一 token 数, $H_g(\tau)$ 是群体 $g$ 的保留率, 则选择问题类似

$$
\max_\tau Q(\tau)
\quad\text{s.t.}\quad
U(\tau)\ge U_{min},\qquad
H_g(\tau)\ge h_g.
$$

Dolma 明确使用了 $U_{min}$ 规模约束, 没有给出各群体的 $h_g$ 下限。公开分数与阈值让后来者可以补做约束, 前提是保存原始来源和逐句属性。 **2.5. PII 替换也会形成可学习模式.** 把邮箱、IP 与电话替换成特殊 token 能保留句子框架, 降低直接泄露风险。模型仍会学习占位符附近的上下文, 例如「联系」「服务器地址」「电话号码」等。若占位 token 区分类型, 模型还可学习字段类别; 若统一替换, 信息更少。Dolma 的性能消融主要比较删除与替换, 受影响文档比例极低, 无法精确估计细粒度差异。

正则检测有两类错误。假阳性把版本号、示例地址或普通数字当 PII, 造成内容损失; 假阴性漏掉非标准写法、地址、用户名和上下文可识别信息。公开数据的风险更受假阴性影响, 因为一处遗漏会传播给所有下载者。准确率优先的高吞吐规则与隐私召回之间存在明确张力。

文档超过五个命中就整体删除, 会对通讯录、日志、网络配置、论坛索引等文体产生选择性影响。阈值是以命中次数而非文档长度定义, 短文档六个命中与长文档六个命中待遇相同。更细的分析可以报告每千字符命中率、命中类型和来源条件删除率, 再检查删除是否集中于少数合法技术域。 **2.6. 分类分数需要校准到实际错误率.** FastText 输出的 0.4 或 0.0004 是模型分数阈值, 不自动等于 40% 或 0.04% 的真实 toxicity 概率。训练数据类别比例、损失和域迁移都会让分数失准。阈值附近抽样人工标注, 才能估计精度、召回和不同来源的条件错误率。

网页句子与 Jigsaw 评论的分布不同。新闻可能引用攻击性语言进行报道, 学术文本可能研究仇恨, 论坛中身份词使用方式也不同。同一分数在各域的实际含义不必相同。全局阈值会给分数分布不同的来源带来不同删除率。 可以按来源 $g$ 绘制校准函数 $P(y=1\mid z,g)$, 再选择满足风险约束的阈值。若某群体的身份词导致假阳性较高, 简单提高全局阈值会同时漏掉其他域的高风险内容; 更合适的修复是改善标注、特征或分域校准。 校准也会随时间漂移。网络语言、新梗与规避写法变化, 固定分类器召回下降。Dolma 公开分类方法使后来者能重标, 但 v1.6 的保存结果仍绑定当时模型与数据。 **2.7. Wikipedia 相似度只是质量的一种坐标.**

KenLM 困惑度按与 Wikipedia 语言模型的相似程度把网页分桶。低困惑度文本更接近百科风格, 高困惑度可能是乱码, 也可能是代码、口语、方言、诗歌或专业符号。把相似度直接叫质量会把文体距离与错误程度混合。 Dolma 没有仅按这一坐标删除, 而是用规则过滤并观察高、中、低桶比例近似不变。这个结果说明 Gopher+C4 NoPunc 与 Wikipedia 相似度捕获的信号不同, 不能说明三桶内部质量完全相同。 若目标是通用模型, 保留一定高困惑度尾部可能增加表达多样性; 若尾部主要由解析垃圾构成, 它会浪费计算。可在每桶内再按规则、来源与人工标签分层, 训练固定 token 的桶混合实验, 观察域能力和训练稳定性。

困惑度还依赖 KenLM tokenizer 和训练语料。换成代码语言模型或 Reddit 语言模型, 同一文档的排序会改变。因此它适合描述「接近哪个参照域」, 不适合脱离参照模型成为永久质量分。 **2.8. 保留率应连同置信区间和抽样设计.** 数十亿文档上的程序计数误差很小, 规则是否符合人类目标的误差却来自有限人工样本。若在某来源抽查 $n$ 篇、观察误删率 $\hat p$, 二项近似标准误为 $\sqrt{\hat p(1-\hat p)/n}$。小群体样本太少时, 整体高精度不能保证其误删率。 简单随机抽样会被常见网页支配。更有信息量的设计按过滤规则、阈值附近、来源、长度和语言分数分层, 对稀有但高风险格过采样, 汇总时再用总体权重还原。这样既能检查边界错误, 也能估计整体影响。

人工标注同样有分歧。quality、toxicity 与页面是否有用并非完全客观, 应报告标注指南、标注者数量和一致性。分歧大的样本可单列, 不强迫一个二元真值掩盖价值冲突。 数据卡里的删除比例属于程序执行事实, 人工审计给出规则有效性的证据。两者缺一, 都不足以证明清洗后的语料达到目标。 **2.9. 最终配方位于多目标前沿.**

数据策展同时关心模型效用 $Q$、唯一 token 数 $U$、代表性 $R$、隐私风险 $P$、许可风险 $L$ 与处理成本 $C$。一个配方 $a$ 若在所有维度都不差于配方 $b$, 且至少一项更好, 才能说 $a$ 支配 $b$。多数现实选择互不支配: 更严格 toxicity 可能提高八项任务表现并降低风险, 却减少 $U$ 和部分群体覆盖; 更强去重降低重复, 也增加计算与误删。 因此最终 v1.6 更接近 Pareto 前沿上的一个点, 位置由 2–3T token 规模、开放分发和当时计算条件共同确定。换成小规模高质量训练、特定领域模型或更严格隐私场景, 合理点会移动。论文公开未采用但表现更好的严格阈值, 让这种移动可以被看见。

比较新配方时应给出向量变化, 例如「任务平均 +0.4、唯一 token -18%、某方言保留率 -9%、PII 命中残留 -30%、处理成本 +12%」。把所有维度压成一个未说明权重的 quality score, 会隐藏价值选择。 模型训练结果只覆盖 $Q$ 的一部分。代表性、许可与隐私还需要数据审计和治理证据。Dolma 的设计意义正在于把这些目标并列记录, 使最终选择能够被重新讨论。

前沿也应按模型规模重算。小模型无法利用的长文档、代码或专业论文, 到更大容量时可能产生收益; 小模型阶段看似便宜的重复文本, 长训练后可能更快进入饱和。固定一组策展权重贯穿所有规模便于复现, 不代表统计最优点不会随训练预算移动。

## 3. 去重、来源配方与混合权重

Web 去重分三步。精确 URL 去重删除 53.2% 文档；精确文档去重在 URL 去重后再删除 14.9%，包括空文档；精确段落去重在 URL 去重后的文档中删除 18.7% 段落，包括空段落。URL 与文档去重先做，可减少后续昂贵处理；段落去重可能扰乱内容分析，所以末尾执行。 去重提升 token 效率并减少记忆风险，但会改变来源分布。新闻、许可证和经典文本天然重复；粗暴去重可能让常见但重要文本代表不足。Bloom filter 误报也会删除未重复项。输入顺序决定保留副本：同一内容出现在高质量来源和网页时，先处理谁可能决定 provenance 与许可。复现必须固定 key、阈值、Bloom 参数和顺序。 **3.1. 代码与社交数据需要不同配方.**

Dolma-Code 含 411B token，来自 2023 年 3 月的 The Stack。The Stack 已用 MinHash 与局部敏感哈希去重，并限定宽松许可仓库。Dolma 再过滤 JSON、CSV 等数据密集文件，组合 RedPajama v1 与 StarCoder 规则：删除重复许可证前导、过长行、数字为主和模板生成文件，筛掉低星仓库、注释比例异常和代码—文本比例低的 HTML。消融显示组合规则相对仅 RedPajama 规则降低代码困惑度并改善通用任务。 代码子集沿用网页 PII 处理，还以 `detect-secrets` 删除包含密钥或软件特有个人信息的文档。这里的误删成本与网页不同：测试 token、示例密钥和占位凭据可能被当真；而漏检真实密钥风险更高。规则版本、匹配类型和删除量应随数据发布。

Dolma-Social 论文正文一处称 80B token，首页表为 89B，分别可能对应版本/计数口径；复现应以最终表与 LaTeX 版本核对。数据来自 2005 年 12 月至 2023 年 3 月的 3.78 亿条 Pushshift 记录。作者比较原子内容、部分线程和完整线程三种线性化，消融显示把每条 submission/comment 当独立文档最好，推测线程组合引入的人为格式损害训练。 质量规则删除短于 500 字符的评论、短于 400 字符的 submission 和长于 40,000 字符的文档；净投票少于 3 的评论也被删除。删除/版主移除/18+ 文档及来自 26,123 个被封禁或 NSFW subreddit 的内容被排除。由于 Reddit 文档短，只要检测到 PII 就删整篇。文档级去重用于消除 copypasta。

投票作为质量信号带明显社会偏差：深层评论天然更少曝光，小众观点和晚发内容也可能低分；情绪化内容与低票的相关性并不等于低信息量。论文用下游消融支持最终选择，但公开数据用户仍应把这种选择视为平台治理与用户行为共同塑造的分布。 **3.2. 其他来源和多源价值.**

C4 会重新经过除 URL 去重外的完整网页管线，进一步清理低质量、重复文本并遮蔽 PII。Semantic Scholar 使用约 4000 万篇开放获取论文组成的 peS2o，后者已针对语言模型完成清洗、过滤、去重和格式化，因此直接使用。Gutenberg 于 2023 年 4 月抓取，保留英语公版书并按书名精确去重。Wikipedia/Wikibooks 使用 2023 年 3 月 English 与 Simple dump，经 WikiExtractor 处理，删除不超过 25 个 Unicode word 的短页。

这些来源规模远小于 Common Crawl，却提供网页之外的代码、学术、书籍与百科分布。论文用 Paloma 的数百细粒度域比较 C4、英语 mC4、RedPajama v1、RefinedWeb、Pile 与 Dolma 上训练的 1.2B 模型。Pile 虽规模小但多源，因此领域拟合好；Dolma 与 RedPajama v1 同样覆盖更广；单一网页来源平均困惑度更高。这支持纳入非网页来源，而非证明某个固定比例永远最优。 **3.3. 去重把重复频率改写成样本权重.**

设内容簇 $c$ 在原始语料出现 $m_c$ 次。未去重时, token 级经验分布中该内容权重近似与 $m_cL_c$ 成正比; 精确文档去重后只保留一份, 权重变为 $L_c$。去重相当于把重复次数这个隐含采样权重压到 1。若重复来自镜像、抓取故障或模板, 这种修正合理; 若重复反映真实语言频率, 全部压平会改变目标分布。

URL、文档和段落去重作用于不同等价关系。URL 去重认为相同地址的多次抓取等价, 可以消除 snapshot 重复; 文档去重忽略 URL, 处理镜像或同内容多地址; 段落去重进一步删除不同文章共享的模板。三层逐渐从「同一对象重复采集」走向「不同对象共享文本」。越往后, 误删真实共用表达的风险越高。

输入顺序决定保留哪个副本。设同一论文同时出现在作者主页、出版站点和抓取镜像, Bloom filter 先看到的版本成为代表。若副本正文相同而元数据、许可或周边文本不同, 保留选择会影响 provenance。确定哈希只保证相同输入顺序可复现, 无法使保留副本与质量目标自动一致。 更明确的策略可先给副本簇排序: 优先保留许可清晰、来源可信、解析完整、时间较早或元数据丰富的成员, 再删除其余副本。Dolma 的高速流式 Bloom 路线换取规模可行性, 没有对每个全局簇做这种昂贵排序。因而去重收益与 provenance 选择要分开理解。 **3.4. Bloom filter 的误报会形成单向删除.** Bloom filter 用 $m$ 位数组和 $k$ 个哈希存储已见元素。插入 $n$ 个元素后, 经典近似误报率为

$$
p_{fp}\approx\left(1-e^{-kn/m}\right)^k.
$$

它没有假阴性前提是状态完整且哈希过程一致, 但会把部分新元素误判为已见。误报在去重中产生单向损失: 文档或段落被删除后不会在后续阶段自动恢复。容量估计偏小、插入元素超预期或重复使用已饱和 filter, 都会提高误报率。 若需要处理十亿级键, 即使 $p_{fp}=10^{-4}$, 期望误删也可达到十万量级。总体比例很小, 仍可能集中伤害后处理来源: filter 随处理推进越来越满, 后来的来源面对更高占用率并且更常被前面来源判重复。固定来源顺序是复现条件, 随机轮换顺序则可用来测顺序敏感性。

去污染复用同一结构时, 误报含义改变。先把 benchmark n-gram 放入 filter, 再检查训练文本, false positive 会把与测试集无关的内容标为污染; false negative 还可能来自归一化、分词或短语改写不一致。公开参数和命中样本比一个「已去污染」标签更有信息。 **3.5. 混合比例决定每个来源被训练多少遍.** 附录比较四种 mixture。Naive 按所有可用内容各取一次, token 比例约为网页 83.5%、代码 13.8%、参考资料 2.5%、书籍 0.2%。Reference+ 把参考资料与书籍上采样两倍, 比例变为 81.2%、13.5%、4.9%、0.4%。Gopher-like 只取 17% 网页、8% 代码, 同时把参考和书籍上采样两倍, 最终比例为 68.4%、5.4%、24.2%、2.0%。Web-only 则完全移除后三类。 表里的 Sampling 与 Proportion 不能混用。Sampling 说明每个来源相对自身数据读几遍, Proportion 是归一化后的 token 占比。参考资料从 100% 改为 200% 并不自动得到两倍最终比例, 因为其他来源也在变化。给定原始 token 数 $T_s$ 和采样倍数 $u_s$, 最终比例为

$$
\pi_s=\frac{u_sT_s}{\sum_j u_jT_j}.
$$

当训练预算 $B$ 小于混合后总量时, 实际每来源读到的 token 约为 $B\pi_s$; 若超过唯一数据量, 某些来源会重复。小型 Gutenberg 只占约 6B token, 在多万亿预算与上采样下更容易跨 epoch 重用。 mixture 搜索的目标不是让所有来源困惑度同时最低。提高代码权重通常改善代码域, 可能减少网页和自然语言 token; 增加论文有利于学术域, 也可能过度集中正式文体。可以写成多目标风险

$$
J(\pi)=\sum_{k=1}^{K}\lambda_kR_k(\theta(\pi)),
\qquad \sum_s\pi_s=1,
$$

其中 $R_k$ 是目标域风险, $\lambda_k$ 由模型用途决定。论文展示不同 mixture 的域拟合, 没有给出一组脱离用途的最优 $\lambda$。 **3.6. 少量域数据已经可能改变表示.** mixture 实验显示四种配方在 C4 的 100 个网页域上困惑度接近, Web-only 在 HumanEval 代码域明显较差。S2ORC 学术域上, Reference+ 的参考资料占 4.9%, Gopher-like 占 24.2%, 二者结果却近乎相同。这个现象说明域拟合对数据比例可能存在快速收益后饱和, 无法据此认定 4.9% 是普遍阈值。 饱和点同时取决于域内多样性、模型容量、训练 token 和与其他来源的重叠。学术语言也存在于 Common Crawl, 所以 4.9% 显式论文之外还有隐式学术网页; 代码域的语法更独特, 移除 The Stack 后缺口更明显。来源标签不等于语义域的纯分区。

代码比例实验给出更细证据。C4 与 The Stack 按 0%、5%、15% 代码训练后, bAbI ICL 从 0.0 升到 $8.8\pm0.9$、$10.1\pm2.8$; WebNLG 从 $16.8\pm1.1$ 升到 $19.3\pm1.1$、$22.0\pm1.3$。GSM8K 直接 ICL 和普通微调仍为 0, 使用 program-aided language 形式微调后则从 $11.8\pm0.8$ 升到 $14.2\pm1.3$、$14.7\pm0.9$。 这组结果支持代码数据与特定推理、结构生成能力相关, 也暴露任务接口的中介作用。GSM8K 的改善只在要求模型生成 Python 程序的 PAL 设置出现, 因而不能归结为抽象数学推理全面提高。bAbI 与 WebNLG 的样本量、模型规模和 5 个随机种子也限制外推。 **3.7. 来源权重还会改变梯度方差.** 训练中每个来源产生不同损失尺度和梯度方向。若按来源 $s$ 采样概率为 $\pi_s$, 单步梯度 $g$ 的方差包含来源内方差和来源间均值差异:

$$
\operatorname{Var}(g)=
\sum_s\pi_s\operatorname{Var}(g\mid s)
+\sum_s\pi_s\|E[g\mid s]-E[g]\|^2.
$$

代码、网页与论文交替会让 batch 梯度更异质。mixture 改变的不只有长期知识覆盖, 还会改变优化噪声、损失曲线和学习率适配。小模型上稳定的比例放到更大 batch 或不同 packing 后, 来源间方差的表现可能变化。 如果一个 batch 严格来自单一来源, 来源间差异直接表现为 step 波动; 若 batch 内按 token 混合, 梯度先在 batch 中平均。Dolma 论文主要报告结果配方, 没有把 batch 构造作为 mixture 消融轴。复现时需要记录采样是在 shard、文档、序列还是 token 层发生。 **3.8. Common Crawl snapshot 不应默认等权.** 25 个 snapshot 的页面数量、重复率、语言比例和站点覆盖不同。若简单拼接, 体量大的 snapshot 获得更高权重; 若每个 snapshot 等量采样, 小 snapshot 被相对放大。两种策略对应「按抓取到的页面频率」与「按时间点平均」两种目标。

同一 URL 跨 snapshot 重复时, URL 去重把多次出现压成一份。稳定页面与只出现一次的页面最终权重相同, 时间持久性信号被删除。若保留重复, 长期存在的模板又会支配训练。可以额外保存出现次数, 在硬去重后把它作为分析特征。 snapshot 顺序还影响保留版本。网页在三年间更新, 同 URL 的正文并非严格相同; URL 去重若只看键, 可能直接丢掉后续版本。若先比较内容哈希, 可区分未变副本与真实更新, 代价是更多存储和处理。 时间等权、页面等权和域名等权没有天然赢家。新闻知识需要时间覆盖, 通用语言可能更关心域名多样性。目标决定权重, 报告应给出策略而不只列 snapshot 范围。 **3.9. 代码数据的单位可以是文件、仓库或提交.**

The Stack 把代码文件作为主要文档单元, 但统计依赖存在于仓库。一个自动生成仓库含十万文件, 可能压过许多小型人工项目; 多个 fork 又复制整个文件树。文件级均匀采样隐含偏爱大仓库。 若先均匀抽仓库再抽文件, 每个项目权重更接近; 若按 token 采样, 大文件与大仓库占优; 若按 star 过滤, 社区受欢迎度进入分布。Dolma 组合低星阈值、注释比例和代码文本规则, 改变的不只是文件质量, 也改变项目规模与社区结构。 许可证通常在仓库级, 文档训练却拆成文件。去除重复许可证前导能减少模板, 仍需让每个文件保留可追溯仓库和许可。文件跨仓库重复时, 选择哪个副本决定 provenance。

代码 token fertility 较高, 15% token 代码可能对应更少字符。比较代码比例时应同时给文件、字符、token 与仓库数, 才能判断改善来自更多项目还是更细 tokenization。 **3.10. 社交线程线性化改变条件概率.** 把每条评论当原子文档时, 模型学习 $p(c)$, 缺少它回复的上文; 部分线程让模型学习 $p(c_t\mid c_{<t})$, 但必须引入用户分隔、树到序列的遍历和上下文截断; 完整线程还要决定多个兄弟回复的顺序。三种表示定义了不同训练任务。 Reddit 是树, 任意深度优先或广度优先线性化都会把原本并行的兄弟评论放入同一序列。模型可能误以为后一位用户在回复前一位兄弟, 而实际两者都回复父节点。加入显式层级标记可缓解, 同时产生平台特有 token 与格式。

原子内容在论文 1.2B 消融中最好, 可能说明人为线程格式的代价超过上下文收益。它也可能受模型上下文长度、模板或截断方式影响。对面向对话的后训练, 线程关系价值会更高; 预训练最优表示不必等于聊天训练最优表示。 投票阈值又与树深相关。越深的评论曝光更少, 更难达到净票数 3; 过滤后语料会偏向主干和早期回复。按线程深度报告保留率能区分内容质量与曝光机会。 **3.11. 域权重可以用目标梯度对齐解释.** 某来源是否帮助目标域, 取决于其训练梯度与目标梯度的方向。设来源 $s$ 的平均梯度为 $g_s$, 目标验证风险梯度为 $g_q$。一次小更新 $-\eta g_s$ 对目标风险的一阶变化约为

$$
\Delta R_q\approx-\eta g_q^Tg_s.
$$

内积为正时来源更新倾向降低目标风险, 为负时可能产生干扰。内容相似通常提高对齐, 但代码也可能通过结构或工具使用帮助非代码任务, 论文的 bAbI、WebNLG 与 PAL 结果就显示跨域作用。 梯度对齐随训练阶段变化。早期通用语法尚未学会, 多数高质量文本方向相似; 后期模型进入专业能力分化, 来源冲突更明显。固定 mixture 在全程使用方便, 动态课程可能更有效, 也更难验证和复现。 实际不必保存全模型梯度。可用小模型、低秩投影或短程训练后的验证变化估计来源相容性。任何估计都绑定模型状态, 不能把来源分数当永久属性。

## 4. 数据消融的因果证据与外推边界

团队训练 decoder-only OLMo-1B 做最终管线验证。论文称它相对最可比的 TinyLlama 平均更好，并在八项任务中的四项胜出；但 PDF 双栏抽取容易打乱表 2 列顺序，精确数字必须回到 `tables/1b.tex`。模型的训练 token 也不同：Pythia 少近十倍，StableLM2 在 2T token 上训练两个 epoch但未公开组成，只有 TinyLlama 较接近。 因此表 2 不能视为纯数据集因果比较。模型架构、训练 token、优化器和实现差异都会影响分数。数据选择主要依据控制架构与训练的 1.2B 消融，OLMo-1B 表格用于检查最终管线的端到端表现。论文也指出 1B 模型的 zero-shot 任务较难；这些模型虽超过随机水平，绝对分数仍不宜与大模型直接比较。 **4.1. 开放发布、许可与治理.**

Dolma 数据集采用 ODC-BY，但顶层开放许可不会自动消除每个底层来源的权利差异。团队因诉讼避开 Books3，正说明可分发性是主动约束。GitHub 等来源应保留许可与标识，稳定 `source+id` 支持 provenance、blocklist 和删除请求。 网页规模下仍会漏掉 PII、毒性和版权风险。Datasheet、版本号和删除渠道必须与数据一起使用。研究者不能因“开放下载”就推断所有用途无风险。模型训练后，删除请求也难以从权重中撤销，这要求数据版本和模型 lineage 保持关联。 数据版本不能只写“Dolma”。论文对应 v1.6，Hugging Face 与仓库仍会更新。复现实验必须记录具体 revision、shard manifest、校验和、tokenizer、混合比例和 EOS/文档拼接规则。三万亿 token 是版本化统计，不是永恒属性。 **4.2. 精确复现与验收.**

复现需要保存原始来源 snapshot 和对象 manifest；每个 tagger 的代码、模型、阈值与属性校验和；去重顺序、Bloom filter 参数和文件；Mixer 配置、来源权重、输出 manifest；训练 tokenizer 与 token 统计。远程 glob 若随时间增长，即使配置相同也会漂移，应先解析成不可变清单。 统计验收至少包括每阶段文档、字节、字符、token，按来源/语言分层的过滤率，规则交集，去重命中，PII 替换/删除，失败 shard 与输出校验和。论文中的 61.7%、84.2%、53.2%、14.9%、18.7% 等精确数字是审计锚点；复现明显偏离时，应先查 snapshot、规则版本和计数单位。 消融复现还要固定初始化、优化器、学习率、150B token 调度、batch、评测 prompt、split 和污染检测。只重做过滤但更换训练栈，无法把差异归因于数据决策。多个随机种子和置信区间能避免把小幅波动误当整理收益。 **4.3. 论文自身的限制与贡献.**

Dolma 最重要的贡献是把数据从模型论文中的一句概括展开为可批评的决策：为何只做英语，为何混合六类来源，为何采用 Gopher+C4 NoPunc，为何更严格 toxicity 表现更好却未用于 v1.6，为何用正则处理 PII，以及为何发布 Toolkit。 限制同样清楚：小模型消融不保证尺度外推；Bloom filter 有误报；toxicity/quality 带价值判断；PII 过滤不完备；法律与伦理会改变配方；规模目标迫使团队接受性能并非最优的阈值。Paloma 的领域拟合说明多源有价值，但不证明最终混合比例最优。 Dolma 是带有明确策展政策、已知误差和版本边界的数据产品。“已清洗”只表示执行了对应版本的过滤与去重流程，并不保证语料正确、无风险或适合所有用途。模型结果要与具体 Dolma revision、tokenizer、mixture 和训练预算绑定，后续研究才能验证和修改其中的取舍。

**4.4. 单因素消融识别的是整条配方的局部效应.** 理想的过滤消融从同一原始样本出发, 固定模型、tokenizer、训练 token、初始化和优化过程, 只切换过滤器 $F$。若两模型指标差为

$$
\hat\tau=Y(F=1)-Y(F=0),
$$

它估计的是该原始分布、阈值、模型规模与预算下的局部处理效应。换一批 Common Crawl snapshot、换阈值或先执行另一项过滤, 接受集合改变, $\tau$ 也可能改变。 固定训练 token 很重要。过滤后数据量变小, 若仍训练 150B token, 严格配方可能比宽松配方重复更多内容; 固定 epoch 则严格配方看到更少 token。前者比较等计算预算下的终点, 后者比较每份唯一数据使用相近次数的终点。两个问题都合理, 结论却不同。 消融还可能改变长度分布。删除短页面、无标点段落和模板后, 平均文档变长, packing 浪费与 EOS 密度随之变化。性能差异包含文本内容质量与序列构造变化。要进一步归因, 可从两份配方中按长度、来源和时间重加权出匹配子集, 再比较模型。 **4.5. 过滤器之间存在交互项.**

设质量过滤为 $Q$, 内容过滤为 $C$, 四种处理结果为 $Y_{00},Y_{10},Y_{01},Y_{11}$。两者交互可写为

$$
\Delta_{QC}=Y_{11}-Y_{10}-Y_{01}+Y_{00}.
$$

若为零, 两项效果在该尺度近似可加; 正值表示组合收益超过单项相加; 负值可能说明两者删除相同垃圾、严格组合损失过多数据, 或模型收益已饱和。只分别训练 Q 与 C, 没有 $Y_{11}$ 就无法识别交互。 Dolma 对最终网页管线做了组合实验, 发现质量、内容和去重的改善具有复合效果, 同时删除集合重叠较少。这提供了交互证据, 仍难把交互归到某对规则, 因为完整组合包含多项变化。全因子实验随规则数指数增长, 实践中可优先检查删除量大、统计相关低的规则对。

交互还会跨来源出现。网页过滤变严格后, 固定预算下代码和参考资料相对权重可能上升; 此时观察到的能力变化部分来自 mixture 重归一化。若要测网页规则自身, 应固定最终各来源 token 数。若目标是测真实端到端配方, 则应允许归一化变化, 但结论要绑定整个 mixture。 **4.6. 八项任务无法定义完整的数据效用.** 论文从已有语言模型研究中选择八项任务, 统一为 zero-shot ranked text classification。统一接口降低评测差异, 也使效用集中在多选与排序能力。生成质量、代码执行、事实召回、安全、多语、长上下文与领域专业能力都未直接进入选择目标。

设真实关心的指标向量为 $Z\in\mathbb R^K$, 论文观察投影 $MZ$, 其中 $M$ 只选取八项指标。两个过滤配方可在 $MZ$ 上排序一致, 在未观测维度上相反。严格 toxicity 过滤提高八项平均, 不能推出安全生成一定改善; 代码过滤提高通用任务, 也不能替代代码执行评测。 指标平均还隐藏权重。若八项等权, 一个小众任务与一个核心任务贡献相同; 若按样本数微平均, 大题集支配结果。报告逐任务轨迹比只给平均更能判断效果是否集中。多个随机种子则用于区分小幅差异与优化噪声。 **4.7. 小模型排序外推需要稳定性假设.** 用 1.2B、150B-token 模型选择万亿 token 配方, 隐含假设是处理效果的排序随参数量 $N$ 与训练预算 $D$ 大致稳定。记配方 $a,b$ 的差异为

$$
\Delta(N,D)=Y_a(N,D)-Y_b(N,D).
$$

小模型消融只观察一个或少数 $(N,D)$ 点。要外推到大模型, 需要 $\operatorname{sign}\Delta(N,D)$ 不翻转。数据质量可能在小模型更重要, 因为容量有限; 也可能在大模型更重要, 因为大模型能利用长尾高质量结构。没有缩放网格就无法决定。 训练过程中的曲线比单一终点多一点证据。若配方 A 从早期到 150B token 始终领先 B, 排序较稳; 若两条曲线临近终点才交叉, 延长训练可能再次改变。论文图展示多个训练迭代, 但多数消融仍是单规模, 不能替代跨规模验证。 可采用低成本阶梯实验: 在多个小参数量与 token 预算上训练同一配方对, 拟合 $\Delta(N,D)$ 的趋势, 只把符号稳定且效应大于随机波动的选择升级到大训练。若配方差异随规模缩小到零, 继续扩大实验的价值有限; 若出现交叉迹象, 应保留两条候选。

**4.8. 域困惑度与下游正确率回答不同问题.** Paloma 评估多种细粒度域的 perplexity, 能直接检查训练分布与目标域拟合。下游多选任务则经过提示模板、候选归一化和有限答案空间。一个 mixture 降低学术论文 perplexity, 不保证提高每项知识问答; 反过来, 多选分数提高也可能来自选项形式适配。 困惑度还受 tokenizer 影响。比较模型若使用同一 tokenizer, 差异可解释为预测能力; tokenizer 不同时, token 级 perplexity 不可直接横比。Dolma 的 1.2B 对照固定训练设置, 域内比较更可靠; 与外部模型表格混合时需核对 tokenizer 与归一方式。 多源语料在 Paloma 上平均更好, 支持更广覆盖。可它也可能略微牺牲某个主域, 换取多域均衡。选择 mixture 时应给每个目标域设权重或最坏域约束, 例如最小化

$$
\sum_k\lambda_kR_k+\gamma\max_k(R_k-r_k),
$$

其中 $r_k$ 是可接受基线。平均指标负责总体表现, 最大项防止小域被完全牺牲。 **4.9. 污染会同时抬高评测与筛选信号.** 若候选数据包含 benchmark 文本, 训练后分数可能提高, 导致被污染配方在消融中胜出。此时污染不仅扭曲最终报告, 还直接影响数据选择。去污染应在消融之前固定, 并对所有候选使用同一匹配规则。 精确 n-gram 匹配可发现题干、答案或整段复制, 无法覆盖释义、翻译和同源教材。测试集相关文本也可能合法提升能力, 例如训练论文解释某项概念, 与直接出现题目不同。污染判定需要匹配位置、长度、上下文和来源, 不能只给命中布尔值。

开放训练数据允许在任务异常高分时回查文档。更稳妥的评测还可使用训练数据截止后创建的动态任务, 或保留不公开测试。Dolma 的贡献是让污染研究成为可执行问题, 没有把开放语料变成自动无污染语料。 **4.10. 选择偏差让过滤后的比较改变问题.** 过滤前后模型面对的训练分布不同, 评测却通常固定。若目标评测分布 $q$ 与被过滤内容差异很大, 过滤提高 $q$ 上表现很自然; 这只说明整理更贴合该目标, 无法说明对原始互联网分布也更好。数据质量结论始终相对于目标任务。

设原始分布为 $p_0(x)$, 接受概率为 $a(x)$, 过滤分布为 $p_F(x)\propto p_0(x)a(x)$。如果想估计原始分布上的风险, 可对过滤样本使用逆接受概率权重 $1/a(x)$; 硬规则使被删样本 $a=0$, 这些区域无法由过滤后数据恢复。过滤造成的是支持集变化, 不只是可重加权的比例变化。 这也是保留原始 snapshot 与属性的原因。只发布过滤后文本, 后续研究无法抽取被拒绝样本检查误删。受法律或隐私约束不能公开原文时, 至少可发布分层统计、不可逆特征与人工审计结果。 选择偏差还进入人工抽检。如果只从保留集抽样, 能估计残留垃圾率, 看不到误删; 只从删除集抽样, 又不能判断整体精度。应按规则、分数区间和来源同时抽取保留与删除文档, 构造混淆矩阵。 **4.11. 固定 token 预算下存在替代效应.**

训练预算为 $B$ token 时, 加入某来源必然挤出其他来源, 除非增加总计算。代码从 0% 增至 15% 意味着自然语言 token 从 100% 降至 85%。观察到代码和部分推理任务提高, 还需要检查被挤出域是否退化。 来源 $s$ 权重增加一个小量 $d\pi_s$, 其他权重必须满足 $\sum_jd\pi_j=0$。效应是沿 simplex 上某个方向的方向导数, 不是来源的独立绝对价值。若从网页等比例挪给代码与从书籍挪给代码, 结果可能不同。 mixture 消融应明确替代基线。论文的 0/5/15% code 实验使用 C4 与 Stack, 替代关系清楚; 四种 Dolma mixture 同时改变多个来源, 更接近方案比较, 不适合给单一来源赋因果贡献。

当总数据量大于训练预算时, 权重决定采样; 当某来源小于分配 token 时, 还决定重复次数。增加小来源同时改变域比例与重复, 两种效应需用更大同域数据或固定重用次数的对照拆分。 **4.12. 数据贡献具有互补与冗余.** 若来源 A 与 B 含相近知识, 单独加入任一都有收益, 同时加入后的增量可能很小; 若 A 提供问题、B 提供解法或代码工具, 组合收益可能超过相加。来源价值取决于已有 mixture。 对来源集合 $S$ 记模型效用为 $V(S)$。A 在背景集合 S 上的边际贡献是

$$
\Delta_A(S)=V(S\cup\{A\})-V(S).
$$

它通常随 S 改变。一个「代码贡献 2 分」的无条件数字没有定义背景 mixture。Shapley value 可以在多个加入顺序上平均边际贡献, 但训练所有子集的成本随来源数指数增长。 实践可用低分辨率设计: 先做 leave-one-source-out 找必要来源, 再对疑似互补的来源做二阶交互。Paloma 域 perplexity帮助确定哪些来源可能冗余, 内容重叠和 n-gram 统计提供训练前线索。 Reference+ 与 Gopher-like 在 S2ORC 上接近, 即使论文比例差约五倍, 可能意味着学术数据已进入收益平台, 也可能因为网页含相似论文内容。没有去掉隐式学术网页的对照, 两种解释不能完全区分。 **4.13. 早期 loss 优势可能来自可预测模板.**

更低训练 loss 不总表示更有用。模板化、重复或格式固定的文本很容易预测, 能迅速拉低交叉熵, 却提供较少新知识。去重后的语料可能训练 loss 更高, 但验证域和下游任务更好。 数据消融应同时看训练 loss、同分布 held-out loss、跨域 loss 与下游能力。若过滤配方只降低训练 loss, 可能保留了更容易的文本; 若跨域同步改善, 泛化证据更强。Dolma 图中同时报告训练轨迹、perplexity 与任务, 价值正在于多视角。 held-out 切分也要在去重簇层完成。若同一模板或文档副本横跨 train 与 validation, 验证 loss 会过于乐观。先聚类再按簇分割比先随机分文档后去重更可靠。

难度本身也不是质量。高困惑度可能是乱码, 也可能是稀有数学、代码或新知识; 低困惑度可能是清晰常识, 也可能是重复模板。质量规则需要内容特征与模型结果共同验证。 **4.14. 记忆风险取决于重复、稀有度与训练次数.** 某段文本被记忆的概率与出现次数、序列稀有度、模型容量和训练步数有关。精确去重减少出现次数, 但上采样小来源又可能重新增加。公版书、许可证和代码模板尤其容易跨文档重复。 设序列 $x$ 在训练流出现 $m_x$ 次, 单次带来的梯度更新近似为 $g_x(\theta_t)$。总影响并非简单 $m_xg_x$, 因为参数随时间变化; 重复仍会让相似方向多次进入优化。相邻重复可能产生更强短期过拟合, 分散重复则长期强化。

可通过 canary 或训练样本抽取测量记忆, 并按重复次数桶、长度和来源分层。若去重配方在相同验证质量下显著降低高重现率, 说明它带来隐私和版权之外的泛化收益。 PII 的低总体命中率不代表单条风险低。罕见电话号码或邮箱一旦在多个镜像重复, 可能比普通句子更易被记住。隐私审计应把 PII 与重复簇联结, 优先处理高重复敏感片段。 **4.15. 随机种子应覆盖模型和数据两条轴.** 模型初始化种子改变参数起点, 数据顺序种子改变 batch 序列。数据配方效应若很小, 两种随机性都可能翻转排名。只重复初始化但固定数据顺序, 或反过来, 都低估完整不确定性。 可用层次模型表示结果

$$
Y_{f,i,j}=\mu+\tau_f+u_i+v_j+(uv)_{ij}+\epsilon,
$$

其中 $f$ 是配方, $i$ 是初始化, $j$ 是数据顺序。$\tau_f$ 是目标效应, 其余项描述随机性。完整交叉成本高, 最少也应让多个配方共享一组配对种子, 用配对差减少共同波动。 图上两条单次曲线分开不等于统计稳定。应报告终点差、训练区间平均差和跨种子区间; 若差异只在某个 step 短暂出现, 不宜上升为配方规律。 论文大量消融的主要作用是给设计提供方向, 不是为每个小差异建立高置信统计定律。后续复用某条结论时, 应按决策成本决定重复规模。 **4.16. 数据消融还需要负面对照.**

若一个规则被认为通过「质量」起作用, 可以构造同删除量随机过滤作为负面对照。质量规则优于随机删除, 才说明收益超出数据变少或重复次数变化。还可按长度与来源匹配随机删除, 排除长度分布效应。 去重对照可随机删除与重复项相同数量的文档。若真实去重更好, 支持重复身份重要; 若两者接近, 收益可能主要来自缩小语料或改变 epoch。段落去重还可保留占位符, 检查文档结构破坏的贡献。 toxicity 过滤可用分数反转或阈值附近随机化做机制检查, 但伦理上不必为实验保留高风险文本进入大模型。小规模受控研究或只做统计足以回答部分问题。

负面对照不会让因果识别完美, 却能排除「任何删除都有效」这类替代解释。Dolma 组合了数据统计与模型消融, 增加匹配随机删除会使规则机制更清晰。

## 5. 从原始文档到训练分布

Dolma 的文档—属性分离设计值得单独强调。语言概率、毒性分数、重复区间和 PII 命中不直接覆盖源文本，而是作为与文档 shard 对齐的派生属性保存。Mixer 在构建具体版本时读取这些属性并应用阈值。这样，同一批昂贵分类结果可以支持多套配方，也能在发现阈值不当时重新生成数据，而不必重新跑全部模型。

代价是属性文件与文档文件必须逐行、逐序对应。它不是按 ID 做任意数据库 join；任何坏 JSON、漏行或排序变化都可能把后续属性错配给其他文档。生产复现必须核对每个 shard 的行数、首尾 ID、顺序摘要与校验和。稳定的 `source+id` 负责跨版本追溯，严格行对齐负责高吞吐读取，二者不能互相替代。 段落和句子属性又绑定字符 offset。若 tagger 后执行 Unicode 规范化、换行转换或清洗，offset 就会漂移。原文一旦进入属性计算阶段应视为不可变；最终删除/替换需要在原坐标上按确定顺序执行，并处理重叠区间。否则 PII span 或重复段落可能删错位置。

最终训练样本还会经历 tokenizer、文档拼接、EOS 插入、序列切块和可能的 packing。论文的 LLaMA token 统计只描述一种 tokenizer 视角；若 OLMo 使用另一 tokenizer，真实训练 token 数和来源占比会变化。公开语料与公开训练配方必须在这里连接起来，否则“3T token”不能准确说明训练预算。 **5.1. 过滤器叠加为何反直觉.** 单个过滤器删除比例不能预测组合后保留量。若两个过滤器高度重叠，第二个只增加少量删除；若近似正交，删除率会复合。Dolma 发现质量、内容与去重命中重叠较少，因此严格 toxicity 虽在单项消融中更好，却会使最终规模低于目标。这个观察是论文最有实践价值的结果之一。

完整统计需要同时报告每条规则的单独命中, 按管线顺序计算的增量命中和多规则交集. 单独一个「某规则删除 20%」无法推出最终语料规模. 过滤顺序还会改变计算成本: 先做便宜的 URL 和精确文档去重, 可以减少分类器需要处理的内容; 段落去重放在末尾, 避免内容分析前破坏文档. 叠加也会改变来源与群体分布。语言过滤、最短长度、投票、toxicity 和去重可能共同压低非标准英语、边缘群体语言或小型社区。整体下游准确率提升不能证明代表性没有受损。理想的数据报告应按语言变体、来源、时间和主要内容类别分层展示保留率。 **5.2. 去污染的能力边界.**

Toolkit 能以测试样本 seed Bloom filter，再对预训练文本查重。这可发现精确或配置定义的 n-gram 重叠，却不能发现释义、翻译、答案单独泄漏或同源材料。Bloom false positive 还可能把无关文本误标污染。论文选择可做污染分析的八项评测，是降低风险，而非数学证明测试从未出现。 公开 benchmark 长期在线，模型还可能通过其他数据集、论文表格、GitHub 评测脚本看到题目。更可靠的报告应列出匹配规则、阈值、命中数量与人工样本，并把有疑问任务单独呈现。训练数据开放使这种追踪成为可能，这正是 Dolma 相对闭源数据的科学价值。 **5.3. 复现中的失败语义.**

数百 TB 管线不可能假设每个对象一次成功。下载中断、损坏 gzip、解析异常、分类器崩溃、临时盘不足与对象存储限流都会留下部分输出。若下游通过通配符扫描“现有文件”，半成品可能静默进入最终 mixture。稳健流程需要任务 manifest、临时输出、完成校验和与成功标记。 坏行也不能简单跳过，因为文档和属性严格对齐。一处跳过会让后续所有属性错位。更安全的做法是让整个 shard 失败，或在每个阶段共享同一 reject manifest 并重新生成对应属性。失败记录至少包含路径、行号、异常、原始对象哈希和处理版本。

重试必须幂等。纯 tagger 对固定输入通常可覆盖同一属性输出；共享 Bloom filter 的去重则受插入顺序影响，重跑一个 shard可能改变“首个副本”。因此去重的并行和恢复策略必须被固定并测试。不同进程数是否得到相同保留 ID 集合，应该用小型 fixture 回归验证，而非从“使用确定哈希”直接推断。 **5.4. 管线每一步都在重新定义分母.** 一条网页从 Common Crawl 进入训练集, 可能依次通过下载成功、WARC 解析、语言阈值、CCNet 高频段落、质量规则、内容规则、PII、URL 去重、文档去重与段落去重。记第 $j$ 步接受事件为 $A_j$, 最终保留概率是

$$
P(A_1,\ldots,A_J)
=\prod_{j=1}^{J}P(A_j\mid A_1,\ldots,A_{j-1}).
$$

每个条件概率的分母都是此前全部步骤保留下来的内容。论文报告从 175.1TB 到 27.7TB 的 CCNet 总体变化, 以及后续规则的字符或文档比例; 这些数字不处在同一分母上, 因而不能顺次相乘恢复最终 token 数。 分层统计可避免混淆。对每个阶段同时保存输入与输出的文档数、字节、Unicode 字符、word 和目标 tokenizer token, 再按 snapshot、域名、语言分数桶、时间与长度桶拆分。这样既能复算总规模, 也能发现某一步对长文档或特定年份异常敏感。 下载和解析失败也属于选择机制。页面若因 WARC 损坏、编码异常或压缩问题无法读取, 它不会进入后续过滤统计。把「未处理成功」归入普通质量删除会掩盖技术性缺失。输入 manifest 应把成功、显式拒绝与处理失败分成三种状态。 **5.5. 属性阈值可以做灵敏度曲线.**

对连续分数 $z(x)$ 只比较两个阈值, 只能看到两个端点。更完整的分析沿阈值 $\tau$ 计算保留 token $U(\tau)$、模型效用 $Y(\tau)$、各群体保留率 $r_g(\tau)$ 与隐私或内容风险 $C(\tau)$。曲线可以显示收益是否集中在极窄区间, 以及规模损失何时突然加速。 toxicity 分数近似双峰时, 中间阈值移动可能影响很少样本, 从 $0.4$ 跳到 $0.0004$ 却会跨过大量低分尾部。两个实验点不足以确定效用曲线单调。若低阈值更好, 仍可能存在保留更多 token 且表现相同的中间点。 质量规则多为离散布尔条件, 也能通过逐条开关构建路径。先对每条规则测边际删除和小模型效应, 再对相关性低的规则做组合。规则次序若只影响计算, 最终集合应相同; 结果集合不同则说明实现有状态、offset 变化或去重顺序效应。 **5.6. token 级损失会给长文档更大权重.**

标准预训练对 token 求平均。若文档 $i$ 长度为 $L_i$, 其总贡献近似与 $L_i$ 成正比。长论文、代码文件与书籍章节因此比短评论获得更多梯度项。Reddit 采用原子内容并删除过短文本后, 仍有大量短文档; peS2o 与 GitHub 文件更长。来源 token 比例已经隐含了长度加权。 若希望每篇文档等权, 可以对文档损失除以 $L_i$ 后再平均, 但这会让一个短评论与一篇完整论文权重相同, 也会改变训练实现。Dolma 与常见语言模型采用 token 级目标, 因而 mixture 的自然单位是 token。讨论「某来源有多少文档」时不能直接把它当训练权重。

packing 会让多个短文档共享序列。若 attention 没有在 EOS 处完全阻断, 后一文档 token 可能看到前一文档上下文; 即便有 EOS, 模型仍学习边界模式。短文档来源增加时, 每序列文档数和 EOS 频率提高。比较 Reddit 线性化方法时, 原子文档胜出可能同时涉及内容组织与边界密度。 **5.7. 近重复需要在相似度与语义频率之间选择.** Dolma 的核心去重强调精确 URL、文档和段落。近重复还包括模板稍改、转载加前言、代码 fork、同一论文不同版本与书籍不同扫描。MinHash 或局部敏感哈希可以发现高 n-gram 相似, 阈值越低, 越可能把真正不同的文档合并。 设两文档 shingles 集合为 $S_i,S_j$, Jaccard 相似度为

$$
J(i,j)=\frac{|S_i\cap S_j|}{|S_i\cup S_j|}.
$$

新闻转载可能 $J$ 很高且核心事实相同; 两份许可证头相同、代码主体不同的文件也可能获得不低相似度; 不同语言翻译则词面 Jaccard 很低但语义重复。单一阈值无法覆盖三种情况。 重复频率本身有统计意义。广泛引用的定义、常用代码和法律条款在自然分布中确实常见。完全去重使模型少见这些模式, 不去重又让爬虫镜像决定权重。可以把簇权重从 $m_c$ 压缩为 $m_c^\alpha$, $0\le\alpha\le1$: $\alpha=0$ 是每簇一份, $\alpha=1$ 保留原频率, 中间值软化极端重复。Dolma 使用更易复现的硬去重, 没有探索这条连续轴。 **5.8. 时间分布是代表性的一部分.** Dolma-Web 使用 2020-05 到 2023-06 的 25 个 snapshot, Reddit 覆盖 2005 年末到 2023 年 3 月, Wikipedia 与 Gutenberg 又有各自抓取日期。来源混合后, 年代分布并不一致。网页对近期事件权重更高, Reddit 含更长历史, 公版书明显偏旧。

时间分布影响事实新鲜度、语言风格和污染。较新的网页更可能包含公开 benchmark、模型生成文本和当代实体; 较旧文本减少这些风险, 也缺少新知识。按 token 只报告来源无法看出年代混合。 去重还会跨时间选择代表副本。相同页面在多个 snapshot 出现时, URL 去重若保留第一次所见版本, 处理顺序决定留下早版还是晚版。网页内容可能更新, 两版 URL 相同却事实不同。固定 snapshot 顺序可复现结果, 仍需明确保留策略。 时间审计可以按月或年报告原始、过滤后和去重后的 token。若某时期因抓取或语言分类异常大幅减少, 模型会出现知识断层。评测也应把训练截止时间作为污染分析的一部分。 **5.9. 代表性不能由来源名称代替.**

Common Crawl 不等于互联网总体, GitHub 不等于全部代码, Reddit 不等于日常对话, Semantic Scholar 也不等于完整科学文献。抓取可达性、robots、平台用户、开放许可和解析能力已经在过滤前造成选择偏差。后续规则再叠加一层。 来源内部需要主题与群体统计。网页可按域名类别、地理顶级域、语言变体和内容形态分层; GitHub 可按编程语言、仓库规模、许可证与活跃度; Reddit 可按 subreddit、年代、线程深度和投票; 学术可按学科、年份与出版渠道。每层同时报告原始和最终比例。 模型式主题分类也会出错, 但仍比完全没有分层更容易发现偏移。关键是固定分类器版本并抽样人工校验, 不把预测标签当真值。对敏感群体还需要参与式评审, 因为「代表性」包含谁有权决定哪些文本应保留。

Paloma 域困惑度提供结果侧检查: 若某类来源被过滤后模型在对应域显著变差, 可回溯数据分布。没有性能下降也不能证明代表性充分, 因为小模型或评测可能不敏感。 **5.10. 污染分析应区分题干、答案与解题材料.** 训练文档包含完整题干和正确答案, 是最直接污染。只含题干可能让模型熟悉表述; 只含答案字符串通常证据较弱, 但在答案罕见时仍有影响; 包含官方解析或评测代码则可能泄露推理和判分方式。四类重叠应分别计数。 令测试样本为 $(q,a)$, 训练片段为 $x$。可以记录 $q$ 匹配、$a$ 匹配、$(q,a)$ 共现和来源距离。完整共现风险最高, 题干近似匹配次之。若只 seed 一种 n-gram, 这些结构会被压成单一命中率。

去污染还会改变训练分布。大量通用短语与题目重合时, 严格 n-gram 规则可能删掉正常教材。Bloom 误报进一步扩大删除。消融时应测去污染前后唯一 token、来源与域性能, 不能默认它没有模型代价。 动态 benchmark 可减少直接曝光, 仍可能依赖旧题模板或公开知识。最终报告最好并列静态标准任务与时间隔离任务, 并公开匹配协议。 **5.11. 数据有效样本量小于 token 数.** 3T token 中存在同源文档、模板、引用与语义重复。若 token 梯度高度相关, 信息量不会随 token 数线性增长。类比聚类样本, 若平均每簇有 $m$ 个相关单元、簇内相关为 $\rho$, 设计效应为 $1+(m-1)\rho$, 有效样本量约为

$$
N_{eff}=\frac{N}{1+(m-1)\rho}.
$$

精确去重降低 $m$, 但无法消除主题和语义相关。10 亿个模板化导航 token 提供的信息可能远少于同量多样正文。规模报告应结合重复簇、域熵和长度分布理解。 上采样会主动降低唯一数据比例。Reference+ 把论文和书籍读两遍, 目的是提高目标域权重, 并非增加新信息。模型每次看到相同序列时参数状态不同, 重复仍可能强化学习; 收益会逐渐饱和, 记忆风险上升。 比较语料时, 唯一 token、训练 token 和有效多样性是三条轴。Dolma 清楚报告前两条的大量统计, 第三条只能由去重与域评测间接观察。

## 6. 治理、版本与可复现结论

ODC-BY 规定 Dolma 数据集层面的许可和归因，但输入来源仍有各自条件。代码文件的许可证、论文的开放获取状态、公版书的司法辖区和网页版权并不相同。`metadata` 中保留来源标识，既服务研究追溯，也服务许可和删除请求。 删除请求需要跨层传播：原始文档、属性、最终 mixture、tokenized shard 和使用它的模型 checkpoint 都应有 lineage。已训练模型无法简单删除单条记忆，但至少应披露哪些版本受影响、后续版本如何处理。若稳定 ID 在新数据版本中改变，blocklist 就无法可靠执行，因此跨版本 ID 稳定是治理能力，不只是工程便利。

PII 正则的高精度目标意味着必然存在召回缺口。邮箱、IP、电话之外还有地址、用户名、身份证号和上下文可识别信息。数据开放会把风险扩散给所有下载者，所以使用者仍需按应用风险增加二次过滤，不能把 Dolma 的基础处理视为合规认证。 **6.1. 如何读论文中的精确数字.** 论文数字有不同分母：有的按原始字节，有的按文档，有的按段落或 UTF-8 字符，还有的按 tokenizer token。例如英语识别移除 61.7% 是字节口径；URL 去重 53.2% 是文档口径；Gopher 15.23% 和 NoPunc 22.73% 是字符口径；段落去重 18.7% 是 URL 去重后文档中的段落口径。把它们直接连乘会得到错误结论。

首页表的 Reddit token 为 89B，而正文标题附近写 80B，可能源自版本更新或四舍五入；这应列为论文内部口径差异，不能擅自选择一个并宣称另一个错误。类似地，总计 3,059B 是表中各来源的 LLaMA token 之和，“三万亿”是便于传播的近似称呼。 精确复现时，优先使用同一版本 LaTeX 表、Datasheet 和实际 shard manifest 交叉校验。PDF 双栏文本抽取会打乱表格列顺序，尤其表 2 模型名与数字。因此对照译稿应保留原表并以 LaTeX 源校对，不能按抽取顺序猜测列映射。 **6.2. 综合评价.** Dolma 的方法论贡献是把预训练数据视为实验对象，而非模型训练前不可见的耗材。它用消融连接整理决策与模型行为，用 Toolkit 连接论文与可执行流程，用 Datasheet 连接统计与风险。即使某些具体阈值未来会被替换，这种证据链仍可复用。

论文没有把最终配方描述为每项指标都最优：严格内容过滤表现更好，却因规模约束未采用；英语范围提高了与既有研究的可比性，同时牺牲语言多样性；正则 PII 处理可扩展，但覆盖并不完备；Bloom 去重速度快，也会产生误报。这些冲突说明最终配方是在质量、规模、代表性、隐私和成本之间取得的具体平衡。 后续研究还需在更多模型规模、训练长度、生成式任务和多语数据上复查这些结论，并同时报告质量、代表性、隐私、许可和成本。可重复实验所需的追溯范围包括数据版本、代码、属性、配置和运行统计。 **6.3. 数据版本需要内容寻址.**

版本号只能标识一次发布, 不能证明下载到的 shard 与论文相同。更强的 manifest 为每个对象记录路径、字节数、压缩格式、文档数与内容哈希, 再对 manifest 自身计算根哈希。任何 shard 缺失、替换或重新压缩都能被发现。 内容哈希还连接属性与正文。若 tagger 输入 shard 哈希为 $h_x$, 属性文件应记录 $h_x$ 与 tagger 配置哈希 $h_t$。最终 mixture manifest 再记录使用了哪些正文、属性和 mixer 配置。这样可以从训练 shard 反向追到原始输入与阈值。 仅靠文件名无法做到这一点。远程存储可能在同一路径覆盖新版本, 通配符会随新增文件改变结果, 分布式任务也可能漏掉部分 shard。复现开始前应解析成冻结清单, 结束后按清单验证输出集合。

tokenized 数据也需要独立版本。改变 tokenizer、Unicode 规范化、EOS、packing 或最大序列长度, 即使原始文本字节完全相同, 训练序列仍会改变。模型 lineage 应指向 tokenized manifest, 再由它指向文本 manifest。 **6.4. 删除请求沿有向依赖图传播.** 一份源文档可能产生语言属性、质量属性、去重键、最终文本、tokenized 序列和多个模型 checkpoint。可把这些产物视为有向无环图: 节点是带版本对象, 边表示派生关系。删除请求命中源节点后, 所有可重建后代都应进入失效集合。 稳定 ID 是图的连接键。URL 可能变化, 同一内容也可能出现在多个 URL; 只按 URL blocklist 会漏掉镜像。内容哈希能发现完全相同副本, 近重复与段落复制还需要簇 ID。删除范围取决于请求依据, 不能默认一个 ID 覆盖所有语义副本。

已发布数据可生成 tombstone manifest, 列出后续版本删除的稳定 ID 与原因类别。下载者据此更新本地副本。已训练模型无法通过删除 shard 自动遗忘, 因此治理记录至少要指出哪些模型使用过受影响版本, 是否进行后续缓解或重新训练。 删除也会破坏复现。历史论文若依赖已撤回内容, 完全隐藏旧 manifest 会使结果不可解释; 继续公开原文又可能违反删除要求。可以保留不可逆哈希、统计和处理记录, 不保留正文, 让外界知道版本差异而无法恢复被删内容。 **6.5. 数据集许可与文档许可位于不同层级.** ODC-BY 描述 Dolma 数据库整体的使用与归因条件, 不会重写每个网页、代码文件、论文和图书的底层权利。The Stack 限定较宽松许可仓库, peS2o 聚焦开放获取论文, Gutenberg 使用公版书, 但网页来源仍然复杂。

训练用途还涉及司法辖区、合理使用与合同条件, 论文无法给所有使用者统一法律结论。技术上能下载与许可证允许再分发是两回事。数据卡应保存来源类别和已知许可字段, 使用者按部署地区与目的评估。 来源许可也影响去重代表副本。相同代码同时出现在许可清晰仓库和无许可镜像, 若流式顺序保留后者, 最终 provenance 变差。质量优先、时间优先与许可优先会选出不同副本。治理目标应进入副本选择策略。 论文避开 Books3 展示了法律风险会改变统计配方。移除争议来源减少书籍分布, 团队用 Gutenberg 等来源补充, 规模与文体仍无法完全等价。这项选择本身属于数据模型设计, 不能在性能分析中视作外部附注。 **6.6. 论文数字需要单位化数据字典.**

复现表格最好为每个数字附五个字段: 指标名称、数值、统计单位、分母阶段、数据版本。例如「61.7%」对应 language filter 删除的 byte fraction, 分母是语言过滤前下载内容; 「53.2%」对应 exact URL dedup 删除的 document fraction, 分母是该阶段输入文档。缺任一字段都容易误连。 同名 token 还要标 tokenizer。Dolma 首页约 3,059B LLaMA token, OLMo 实际 tokenizer 计数可不同。word 也需说明是 Unicode word 分割而非语言学词。GB 若按压缩文件还是解压文本统计, 对存储预算影响巨大。 区间与近似值要分开。约三万亿是传播级概数, 表中各来源求和是更精确的特定 tokenizer 统计; Reddit 的 80B 与 89B 则属于正文和总表的内部差异。复现不应通过四舍五入强行让两者一致。

数据字典还能发现不可能组合。例如把按字节删除率与按文档删除率相乘, 数学上没有共同样本单位; 把段落去重比例直接从 token 总量扣除, 忽略段落长度差异。先统一到同一阶段的 token 或字符再计算。 **6.7. 可复现训练需要把数据顺序纳入版本.** 相同文档集合与 mixture 比例仍可产生不同训练轨迹。shard 顺序、shard 内文档顺序、分布式 worker 切分、shuffle buffer 大小和随机种子决定每一步看到什么。有限训练预算下, 尾部文档甚至可能从未被读取。 记第 $t$ 步 batch 为 $B_t$, 训练结果是整个序列 $(B_1,\ldots,B_T)$ 的函数。manifest 只规定集合, sampler 配置规定序列分布。严格复现要保存随机种子、epoch 边界和采样实现; 机制结论至少要用多个数据顺序检查方向。

上采样时顺序需要单独处理。重复读取同一文件路径可以实现 2x, 两份副本连续出现与分散到训练全程的优化效果不同。连续重复会让相邻梯度高度相关, 分散重复更像长期提高来源权重。 去重状态与训练 shuffle 不应混在一起。去重先生成确定保留集合, 训练再独立随机排序, 可以分别复现内容与优化。边读边去重边训练会让 worker 时序改变保留副本和 batch, 很难解释差异。 **6.8. 一套最小的版本对照矩阵.** 比较 Dolma 新旧版本时, 可把变化拆成原始 snapshot $S$、过滤规则 $F$、去重 $D$、mixture $M$ 和 tokenizer $T$。端到端分数差同时包含五项。最小矩阵先冻结四项只换一项, 再测试关键交互。 例如新版本同时更新 Common Crawl snapshot 与质量规则, 四格为旧 snapshot+旧规则、旧 snapshot+新规则、新 snapshot+旧规则、新 snapshot+新规则。交互项

$$
\Delta_{SF}=Y_{11}-Y_{10}-Y_{01}+Y_{00}
$$

衡量新规则是否特别适配新 snapshot。若只比较对角线 $Y_{11}-Y_{00}$, 无法区分互联网内容变化与清洗改进。 矩阵不必每格训练完整大模型。可先做文本统计和小模型阶梯, 对效应明显或交互不稳定的组合升级训练。文本统计包括保留率、域分布、重复、token fertility、PII 命中与污染; 模型统计包括训练 loss、域 perplexity 和任务曲线。 所有格子使用相同计算预算并报告唯一 token 重用次数。若新版本规模更小导致重复更多, 结果应同时给固定 token 与固定 epoch 对照, 否则清洗效果和重复效果混合。 **6.9. 论文自身可核查的问题.** 第一, Reddit 在正文附近写 80B token, 总统计表写 89B。两者可能来自稿件版本或取整, 论文没有在相邻位置解释。引用总规模时应采用同一张最终表, 并保留这一口径差异。

第二, 过滤比例跨字节、字符、文档与段落多种单位, 正文容易让读者把连续数字当作同一漏斗。论文各处通常写出单位, 没有提供一张统一阶段表把所有分母连接起来。复现需要借助 Toolkit 输出与 shard manifest补齐。 第三, toxicity 更严格阈值在消融中表现较好, v1.6 因规模目标采用较宽松阈值。这是明确的设计取舍, 同时意味着最终配方并非论文实验中的性能最优点。后续模型使用者不能把 v1.6 阈值解释为经实验确定的普遍最优值。 第四, 小模型消融多为 1.2B、150B token, 随机种子与置信区间覆盖有限。结果足以支持工程选择, 无法证明排序在更大规模、多 epoch 与其他架构上保持。论文对这一点有承认, 但具体图表仍容易被二次引用成通用规律。

第五, mixture 附录明确表示 Dolma 不规定唯一混合策略, 部分实验又未包含尚未准备好的 social 数据。因而论文展示的 Naive、Reference+ 与 Gopher-like 不能等同于最终 OLMo 训练 mixture 的完整优化证明。 第六, Bloom filter 的概率误报是已知方法边界, 论文没有为每个具体去重阶段在最终负载下给出统一实测误报率。严格复现需要从参数和插入量计算, 再用保留样本测量误删。 这些问题没有削弱 Dolma 的核心价值。相反, 公开 LaTeX、工具、数据卡与版本让矛盾和边界能够被定位。闭源语料往往连同类问题是否存在都无法检查。
