# TÜLU 2 技术解析: 数据混合、全量微调、DPO 与 QLoRA 的系统对照

TÜLU 2 来自 Allen Institute for AI 与华盛顿大学，论文于 2023 年 11 月发布，题为 *Camels in a Changing Climate: Enhancing LM Adaptation with TÜLU 2*，对应 [arXiv:2311.10702](https://arxiv.org/abs/2311.10702)。项目开放了 [模型与数据集合](https://huggingface.co/collections/allenai/tulu-v2-suite-6551b56e743e6349aab45101) 以及 [Open Instruct 训练和评测代码](https://github.com/allenai/open-instruct)。它围绕一条可复查的后训练路线展开: 以 Llama 2 或 Code Llama 为基座，先用重新组织的指令数据做有监督微调，再视需要加入直接偏好优化，并把全量微调与 QLoRA 放在同一评测框架下比较。

这项工作的价值来自受控对照。模型规模覆盖 7B、13B 和 70B，评测同时包含 MMLU、GSM8K、BBH、TyDiQA、Codex-Eval、AlpacaEval、ToxiGen，以及部分实验中的 TruthfulQA 和 MT-Bench。如此安排可以区分三类变化: 数据混合是否改变基础能力，DPO 是否主要改变开放式回答偏好，低秩量化训练是否以某类能力为代价节省显存。结果并不支持“一个总平均分足以决定配方”的看法；同一改动常在开放式生成上获益，却在多语言问答或推理任务上回落。

## 1. 数据配方决定监督微调学到什么

### 1.1. V2 混合不是简单扩容

TÜLU-V2-mix 共 326,154 条样本，反而少于 V1 的 490,445 条。缩小规模是主动筛选的结果: FLAN v2 取 50,000 条，另取 50,000 条 CoT 子集；Open Assistant 1 从每棵对话树抽取最高分路径，得到 7,708 条；ShareGPT 使用处理后的 114,046 条；GPT4-Alpaca 取 20,000 条，Code-Alpaca 使用 20,022 条。新增数据包括 1,030 条 LIMA、30,000 条 WizardLM Evol-Instruct V2、30,000 条 Open-Orca、7,544 条科学文献任务和 140 条人工编写的身份回答。各项相加会超过最终总数，因为后续还要过滤样本。

过滤针对的是会破坏身份一致性的内容。作者删除含有 GPT-4、Open Assistant、Claude 等其他系统名称的样本，使 140 条身份提示不会与训练语料中的自我指称互相冲突。Dolly 则因先前消融表现较差而被移除，大型数据集也经过下采样。这个配方体现了监督微调的基本约束: 训练目标会平均吸收数据里的任务分布、回答风格与身份信号，数量更多并不自动意味着梯度方向更有用。V2 用较少样本换取更集中、更复杂且来源更互补的监督信号。

### 1.2. 长上下文设置改变有效数据量

最大序列长度从 2,048 提高到 8,192 token。V2 样本平均长度为 1,097 token，第 25 与第 75 百分位分别是 230 和 1,464 token，分布还有明显长尾。若沿用 2,048 的上限，需要截断 63,900 条样本；提高到 8,192 后只截断 20 条。这里没有凭空增加上下文能力，收益来自减少训练标签被裁断的次数，使 ShareGPT 与 Open Assistant 的多轮结构能够以更完整的形式进入损失函数。

全量 SFT 使用 BFloat16，训练 2 个 epoch，权重衰减为 0，warmup 比例为 0.03，有效 batch size 为 128。7B 和 13B 的学习率为 $2\times10^{-5}$，70B 降为 $1\times10^{-5}$，最大序列长度为 8,192。较低的 70B 学习率控制大模型参数整体漂移，而统一的 batch 与轮数让不同规模的结果更容易比较。论文没有单独消融“换用 Llama 2”“改变数据混合”和“扩展上下文”三项的全部组合，因此 V1 到 V2 的总提升不能全部归因于数据筛选；表 2 的同基座混合对照才更接近数据本身的效果。

### 1.3. 混合消融显示能力重新分配

在 Llama 2 7B 上，V2 相比 V1 的平均分从 47.8 提高到 54.2；13B 从 56.0 提高到 60.8；70B 从 71.5 提高到 72.4。三个规模的简单平均相对提升约为 7.3%，与正文概括的“平均约 8%”接近，但两者口径并非逐项绝对分数之和。具体任务并非全线上升: 7B 的 GSM8K 从 37.0 降到 34.0，TyDiQA 从 52.9 降到 46.4；13B 的 GSM8K 从 53.0 降到 46.0，TyDiQA 从 58.8 降到 53.2；70B 的 GSM8K 从 74.5 降到 73.0，TyDiQA 从 56.8 降到 53.6。

另一侧的收益更集中。13B 的 Codex-Eval 从 38.9 提高到 49.0，AlpacaEval 从 67.7 提高到 78.9，ToxiGen 毒性率从 18.7 降到 1.7；70B 的 Codex-Eval 从 65.4 提高到 68.5，AlpacaEval 从 82.8 提高到 86.6，TruthfulQA 从 57.9 提高到 62.2。V2 增加代码、复杂指令、解释轨迹和科学任务后，模型更擅长编码、开放式回答与部分真实性任务，但某些数学和多语言能力没有同步受益。数据混合由此应被视作任务权重配置，而不是无方向的质量提升。

科学文献子混合也展示了这种权重配置的细粒度。7,544 条样本由 Evidence Inference 的 1,678 条医学证据五元组抽取、Qasper 的 2,255 条论文问答、SciERC 的 700 条实体与关系抽取、SciFact 的 919 条事实核查和 SciTLDR 的 1,992 条摘要组成。五项恰好合计 7,544，这套配方把抽取、问答、核查与摘要四类监督明确放进通用指令接口，比“科学文本增强”具体得多。它可能改善科学文档处理，却不能直接推出模型获得了新的科学事实；监督样本教的是输入输出映射，事实覆盖仍受基座预训练与样本内容约束。

数据来源之间还存在格式与生成者偏差。LIMA 和 Open Assistant 更接近人工筛选回答，WizardLM、Open-Orca、GPT4-Alpaca 带有教师模型蒸馏痕迹，ShareGPT 则来自真实对话分享。将它们混合能够增加表达和任务多样性，也会把教师偏好、对话模板与长度分布带入学生模型。论文通过统一模板、过滤系统名称和下采样来缓和冲突，但没有逐来源报告所有梯度贡献。因此，326,154 这个总量可用于复现配方，却不能作为每类数据同等重要的证据。

### 1.4. 样本数不是混合权重，token 数才更接近梯度预算

把每个来源的样本数列出来，只完成了配方描述的第一步。自回归 SFT 的损失通常在回答 token 上逐项累加或取平均，长对话与短分类样本进入优化器的权重取决于打包、损失归一化和标签掩码。一个 3,000 token 的 ShareGPT 对话与一个只输出标签的 FLAN 样本都记作“一条”，前者却可能产生数百倍的监督 token。若训练器先对每个 token 求全局平均，长样本得到更多梯度机会；若先对每条样本平均，再对 batch 平均，短样本的相对权重会上升。论文给出了样本长度分布和总条数，没有把各来源的有效监督 token 占比完整列出。

对第 $k$ 个数据源，记样本集合为 $D_k$，样本 $i$ 中参与损失的回答 token 数为 $m_i$。在 token 平均口径下，该来源的近似权重为

$$
w_k=\frac{\sum_{i\in D_k}m_i}{\sum_j\sum_{i\in D_j}m_i}.
$$

它会受到多轮模板的影响。若只对 assistant 回合计算损失，用户提示、系统消息和分隔符虽然占上下文，却不直接产生交叉熵；若所有 token 都参与损失，模型还会学习复述用户与模板。复现 Tülu 2 时，必须把“最大序列长度 8,192”与“哪些位置有 label”分开记录。相同原始数据在不同掩码实现下，对话行为可能不同。

长序列还有 batch 级影响。固定有效 batch size 为 128，可能表示 128 条序列，也可能表示通过梯度累积得到的样本数；每步 token 数会随长度剧烈波动。按长度分桶和 packing 能减少 padding，却改变同一个 batch 内来源组合。若长 ShareGPT 对话经常独占序列，短 FLAN 任务则被大量打包，它们经历的优化噪声并不相同。分析数据混合时，样本数、监督 token 数、每轮被采样次数和每来源 loss 应当同时看。

### 1.5. 蒸馏数据传递的不只是答案

Open-Orca、WizardLM 与 GPT4-Alpaca 都利用强模型生成内容。教师把推理步骤、段落组织、拒答习惯、措辞偏好与事实错误一起写进目标回复。SFT 最大似然目标不会识别其中哪些部分来自可靠推理，它只提高整条目标序列的条件概率。因此，蒸馏数据的价值来自密集而清晰的行为监督，代价是学生可能继承教师的固定话术和评判器偏好。

复杂指令生成还带来选择机制。WizardLM 的 Evol-Instruct 通过改写把任务变难，Open-Orca 为 FLAN 类提示补充解释。这种数据会增加长回答与显式推理的比例，也会让“复杂”与“高质量”发生混淆：更长的问题可能只是附加限制，更多推理 token 也可能包含无效步骤。合理筛选需要分别检查指令可解性、答案正确性、解释与答案是否一致、来源去重和教师泄漏。Tülu 2 的结果证明该组合整体有效，无法据此断言每个生成来源都贡献正收益。

人工数据与蒸馏数据的作用也不必对立。LIMA 的数量只有 1,030，却经过人工筛选，可能为回答风格提供高密度锚点；大规模生成数据提供任务覆盖。若想知道小而精的数据是否真的改变模型，可以在固定 token 预算下做增量消融，观察加入该来源前后的 per-domain loss 和行为指标。仅按删除一个来源后的总平均分判断，容易漏掉身份、一致性或罕见任务上的局部作用。

### 1.6. 多轮对话怎样变成训练样本

一棵 Open Assistant 对话树包含同一节点的多个候选回复和继续分支。Tülu 2 选择每棵树得分最高的路径，把树压成线性对话。这样能避免把互相矛盾的分支塞入同一上下文，也让监督目标对应一条相对高质量轨迹。代价是丢掉候选之间的比较信息：较差回复为何差、某一轮之后有哪些可行走向，都没有进入 SFT。后续 DPO 使用另一套 UltraFeedback 偏好对，承担候选排序学习。

ShareGPT 的长对话则按复现版数据处理，并把过长会话切为不超过约 4,196 token 的块。切块位置会影响代词指代、先前约束和角色状态。若后半块缺少关键前文，目标回答看起来像无条件补全；若每块重复系统提示，系统身份权重又会上升。把训练上限提高到 8,192 能减少训练器再次截断，却无法恢复数据预处理阶段已经切开的上下文。这里要区分原始会话长度、预处理块长和训练最大长度三个尺度。

多轮 SFT 的核心学习对象是条件行为：模型看到历史消息后预测下一段 assistant 内容。若所有 assistant 回合都计算损失，一条十轮对话会产生多个监督区间；若只训练最后一轮，前面回复只是上下文。两种方法分别强调全程模仿和最终响应。公开代码与具体数据模板决定真实实现，论文中的“样本数”本身不足以还原这一点。

### 1.7. 身份样本为何能以很小数量生效

140 条 hardcoded 样本在 32 万条混合中占比极低，却针对高度集中的提示模式：询问名字、开发者和模型身份。基座和其他指令数据通常没有稳定的“Tülu 2”答案，少量一致目标便能在这一局部区域形成明显梯度。过滤掉提及 GPT-4、Claude、Open Assistant 的训练样本，是为了减少同一区域的冲突标签。这里体现了数据影响取决于条件分布，而非全局占比。

身份训练也有外推边界。模型可能在“你是谁”上回答正确，换成间接问法、其他语言或带有错误前提的追问后仍沿用旧身份。要验证 140 条样本教会了概念，需要构造释义、对抗提示和多轮一致性测试，而非只复现训练句式。若把身份样本增加到很大比例，模型还可能在无关问题中主动提及自身。局部能力需要局部覆盖，过度重复会造成风格污染。

### 1.8. 数据混合本质上是多目标优化

设各来源期望损失为 $L_k(\theta)$，混合训练近似优化 $\sum_k w_kL_k(\theta)$。当不同任务梯度方向一致，加入数据可共同改善；方向冲突时，权重决定牺牲哪一边。V2 在 Codex-Eval、AlpacaEval 和毒性指标上的收益，与 GSM8K、TyDiQA 的下降正是多目标权衡的外显结果。总平均分只是给这些任务再次人工赋权，无法消除训练中的冲突。

可以用梯度余弦相似度检查来源关系：在同一 checkpoint 上分别计算不同数据源的小批量梯度，比较方向。持续负相关说明两个来源争夺参数更新；接近零说明它们相对独立。更便宜的办法是跟踪逐来源验证 loss：某来源加入后自身 loss 下降而另一来源显著上升，便出现干扰。此类测量比“数据质量高低”更具体，也能指导重采样或分阶段训练。

不过，局部梯度冲突不等于必须拆开训练。表示学习可能先冲突后共享，模型规模也会改变容纳能力。论文观察 V2 相对 V1 的优势随规模增大而缩小：7B 改善更明显，70B 只小幅变化。这既可能说明大模型对数据配方较不敏感，也可能是强基座起点高、评测饱和或统一超参未对各规模最优。结果提供现象，机制仍需专门实验。

## 2. SFT 建立能力底座，DPO 调整回答偏好

### 2.1. DPO 在固定参考模型旁优化相对偏好

监督微调对每个目标回复做最大似然学习，能够教会模型遵循指令，却无法直接表达同一提示下两个候选回答的优劣。DPO 使用偏好三元组 $(x,y_w,y_l)$，其中 $x$ 是提示，$y_w$ 是偏好回答，$y_l$ 是非偏好回答。它比较策略模型 $\pi_\theta$ 与固定参考模型 $\pi_{ref}$ 对两种回答给出的相对对数概率，常用目标可写为:

$$
\mathcal{L}_{DPO}=-\mathbb{E}\left[\log\sigma\left(\beta\left(\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right)\right].
$$

括号内第一项要求偏好回答相对参考模型获得更高概率，第二项要求非偏好回答的相对概率更低；两者相减后再经过 sigmoid。$\beta$ 控制相对参考策略偏移的尺度。TÜLU 2 采用 $\beta=0.1$，在二值化并过滤后的 UltraFeedback 上训练 3 个 epoch，BFloat16 精度，有效 batch size 32，warmup 比例 0.1，最大序列长度 8,192。学习率只有 $5\times10^{-7}$，远低于 SFT 的 $10^{-5}$ 量级，作者明确指出这是稳定且有效训练所需的设置。

### 2.2. 为什么选择 DPO 而非 PPO

PPO 路线通常需要奖励模型、在线采样、价值估计与受约束的策略更新，多组件之间的尺度和稳定性会增加工程成本。DPO 把奖励模型隐含进分类式目标，用离线偏好对直接更新语言模型，训练流程更接近普通微调。TÜLU 2 的问题设定正适合这种方法: 研究者已有完成 SFT 的策略模型，也有 UltraFeedback 的成对偏好数据，希望在 7B 到 70B 间使用统一配方验证规模扩展，而不是建立完整的在线强化学习系统。

这种简化没有消除偏好数据的边界。UltraFeedback 使用过 TruthfulQA 提示，因而论文在涉及这些模型的比较中省略 TruthfulQA，避免把数据接触误当作泛化。DPO 的学习目标也只知道成对排序，不会自动保证事实知识、数学推理或多语言问答保持不变。固定参考模型限制偏移，但只要偏好数据与能力评测要求不一致，更新仍可能重新分配概率质量。这正是表 3 中开放式生成显著提高而 TyDiQA 明显下降的原因之一。

### 2.3. DPO 的增益集中在生成偏好

最终论文表 3 显示，7B 的 AlpacaEval 从 73.9 提高到 85.1，增加 11.2 个百分点；13B 从 78.9 提高到 89.5，增加 10.6；70B 从 86.6 提高到 95.1，增加 8.5。三个规模平均增加约 10.1 个百分点。若按相对增幅计算，约为 15.2%、13.4% 和 9.8%，简单平均约 12.8%，这与正文所说“平均提高 13%”对应。正文用的是相对百分比，而表中 $\Delta$ 用的是百分点，两者并不矛盾。

能力任务的变化要复杂得多。7B 的 BBH 降 3.0、TyDiQA 降 1.9，但 Codex-Eval 增 3.1；13B 的 GSM8K 增 3.5，TyDiQA 却降 13.5；70B 的 GSM8K 降 1.5、BBH 降 2.4、TyDiQA 降 17.8。去掉 TruthfulQA 后的总平均分分别变化 +1.6、+0.1 和 -1.7。ToxiGen 的数值代表毒性率，越低越好，7B、13B、70B 分别从 7.0、1.7、0.5 降到 0.5、1.1、0.2。因而“DPO 不损害能力”只适合作为若干任务总体近似稳定的概括，不能覆盖 TyDiQA 的大幅下降，也不能从平均分掩盖各项方向相反的变化。

规模增大也没有让 DPO 的所有收益单调增强。AlpacaEval 的绝对增益从 7B 的 11.2 个百分点降到 70B 的 8.5 个百分点，而 TyDiQA 的损失从 1.9 扩大到 17.8。较强 SFT 模型在开放式偏好指标上起点更高，剩余提升空间可能较小，但这个因素无法单独解释 TyDiQA 的规模趋势。UltraFeedback 的语言和任务组成、固定学习率、每个规模相同的 epoch 数都可能改变有效更新强度。论文没有提供逐规模最优超参搜索，因此这些数字证明的是统一配方下的观测结果，不是 DPO 在所有规模上的固有规律。

### 2.4. 从奖励差到概率比，DPO 目标怎样得到

带 KL 约束的偏好优化常写成在每个提示 $x$ 上最大化

$$
\mathbb E_{y\sim\pi_\theta(\cdot|x)}[r(x,y)]
-\beta D_{\mathrm{KL}}\!\left(\pi_\theta(\cdot|x)\Vert\pi_{ref}(\cdot|x)\right).
$$

对固定奖励函数求最优策略，可得 $\pi^*(y|x)\propto\pi_{ref}(y|x)\exp(r(x,y)/\beta)$。移项后，奖励可表示为策略与参考策略的对数概率比，加上只依赖提示的归一化常数。把两个回答的奖励相减时，该常数抵消：

$$
r(x,y_w)-r(x,y_l)=\beta\left[
\log\frac{\pi^*(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi^*(y_l|x)}{\pi_{ref}(y_l|x)}\right].
$$

再用 Bradley–Terry 假设把奖励差映射成偏好概率，就得到 DPO 的 logistic 损失。这个推导解释了它为何不必显式训练奖励模型：策略概率比本身参数化了隐含奖励。它也说明参考模型不可随意省略。没有 $\pi_{ref}$，优化只会提高 chosen 相对 rejected 的绝对似然，缺少围绕 SFT 策略的锚点。

在实现中，$\log\pi(y|x)$ 是回复 token 对数概率之和。长回答包含更多项，序列长度会影响 log-ratio 尺度。chosen 与 rejected 长度分布若系统性不同，分类器可能利用长度相关信号。按 token 平均概率能缓解尺度差异，却改变原始序列概率语义。Tülu 2 跟随 Zephyr-Beta 配方，论文没有提供多种长度归一化目标的消融，因此开放式指标收益中可能含有回答长度偏好的学习。

### 2.5. chosen 与 rejected 是怎样来的

UltraFeedback 让多个模型对提示生成候选，再由强模型按若干维度提供反馈与评分，其偏好并非来自人类逐对手写答案。Tülu 2 使用经过筛选、二值化的版本：从多候选和多级评分中构造成一个偏好回答与一个非偏好回答。连续分数被压成二元排序后，DPO 只知道哪一个更好，不知道差距是微弱还是悬殊，也不直接知道错误属于事实、指令遵循、诚实性还是表达。

筛选决定训练信号的难度。若 chosen 与 rejected 差距太大，模型很快学会表面线索，梯度随后饱和；差距太小或评判噪声很大，排序标签接近随机。理想数据同时包含清晰负例与细粒度难例，并控制生成模型身份、长度和格式。还要防止某个候选生成器整体更强，导致模型通过风格识别来源，而非比较答案内容。

对每个偏好对，可记录评分差、各维度分数、候选生成器、长度差和评判理由。训练时按置信度加权，或过滤评判器自相矛盾的样本；评测时按这些属性分桶，检查收益来自何处。Tülu 2 的公开结论建立在特定 filtered-and-binarized UltraFeedback 版本上。换成原始多候选数据、其他筛选阈值或人类偏好，所得策略不一定相同。

### 2.6. DPO 梯度同时推 chosen 与 rejected

令

$$
z=\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right].
$$

单个样本损失为 $-\log\sigma(z)$，对 $z$ 的导数是 $\sigma(z)-1$。当策略尚未把 chosen 排在前面，$z$ 较小，梯度幅度大；当排序已经非常确定，梯度逐渐接近零。展开到模型参数后，更新方向包含 $\nabla\log\pi_\theta(y_w|x)-\nabla\log\pi_\theta(y_l|x)$，既提高 chosen 的相对概率，也压低 rejected 的相对概率。

“相对”二字很重要。chosen 的绝对概率可能仍下降，只要 rejected 降得更多，偏好 margin 就会增大。若两条回答共享大量通用 token，差异主要集中在少数位置；但自回归概率会因前面 token 不同而改变后续整段条件分布。查看训练准确率只能知道排序是否满足，无法说明 chosen likelihood、rejected likelihood 和相对参考 KL 各自怎样变化。可靠监控应同时画三条曲线。

$\beta$ 在理论式中对应 KL 正则强度，在常见 DPO 实现里还缩放分类 logit。它与学习率、序列长度和训练轮数共同决定实际偏移。Tülu 2 使用 $\beta=0.1$ 与极低学习率，并观察 7B 至 70B 都能稳定训练；这证明该组合在这些模型上可用，并未比较其他 $\beta$ 是否能改善多语言保持或减少长度偏差。

### 2.7. SFT 与 DPO 的次序为何不能颠倒

SFT 先把基座模型带到能够理解聊天模板、完成指令并输出合格回答的区域。此时参考模型能给 chosen 和 rejected 都分配可计算且不过分极端的概率，偏好对之间的 log-ratio 有可学习空间。若直接对原始基座做 DPO，候选回复可能都处于低概率区，排序更新需要同时学习基本格式与偏好，离线数据又没有覆盖策略偏移后会遇到的新输出。

参考模型通常取 DPO 开始前的 SFT checkpoint。训练过程中保持冻结，给每个回答提供锚点。若参考模型太弱，KL 锚定会限制策略达到高质量区域；若参考模型已经与 chosen 风格高度一致，偏好数据余量变小。Tülu 2 的参考点是自身 V2 SFT 模型，因此 DPO 增益应理解为在该数据配方之上的增量，不能独立搬到任意基座上。

顺序还影响遗忘。SFT 数据覆盖代码、推理、多轮和少量科学任务，DPO 数据以英语开放式提示为主。第二阶段持续三轮只见偏好对，没有显式回放全部 SFT 分布，参数会朝偏好域移动。TyDiQA 下跌与这种阶段性分布收窄一致。可行对照包括在 DPO batch 中混入少量多语言 SFT、加入 chosen 的 SFT 损失，或在偏好阶段后做能力恢复；每种方案都会改变“偏好优化”与“能力保持”的权衡。

### 2.8. 偏好数据污染如何传到评测

UltraFeedback 使用了 TruthfulQA 提示，因此作者在 DPO 模型比较中主动移除 TruthfulQA。这一处理抓住了污染的关键：即使候选答案由其他模型重新生成，只要评测提示已出现在偏好训练中，策略就可能学到题目特定的回答排序。不能因为目标文本不同，就把它算作严格未见评测。

污染还可能通过释义和共享来源发生。开放式评测提示常来自公共指令集合，不同数据集会复制、改写或翻译同一问题。精确字符串去重只能发现最明显交集，更稳妥的流程包括规范化匹配、近重复嵌入检索和人工核验。发现交集后应按提示族整体划分，避免一条改写进训练、另一条留在测试。

对偏好学习而言，评判器污染也值得单独看。训练标签由强模型生成，AlpacaEval 又由 GPT-4-0613 评判；若两者偏好相近，模型可能更擅长迎合同类评判器。MT-Bench同样使用 GPT-4，但问题结构和评分方式不同，结果并未与 AlpacaEval完全同步。加入人类盲评、任务执行正确率和不同家族评判器，才能判断提升能否跨越评判体系。

### 2.9. 多语言下降可以怎样被证伪

论文将 TyDiQA 下降联系到 SFT 与 DPO 数据以英语为主，这是合理解释，却还不是单因素证明。TyDiQA 的提示模板、生成语言、抽取后处理和模型格式遵循都可能影响分数。DPO 后模型若更倾向长篇英语解释，即使内部仍保留答案知识，也可能因输出不匹配而失分。

可以分三步定位。第一步检查目标语言 token 的平均概率和生成语言比例，区分语言切换与知识丢失。第二步用受约束解码或明确的“只输出答案”提示重测；若分数恢复，主要问题在回答策略。第三步在固定英语 UltraFeedback 的基础上混入不同数量的多语言偏好对，画保持曲线。若少量多语言数据即可恢复，说明遗忘来自目标分布偏移；若仍无法恢复，则要检查统一超参、tokenizer覆盖与基座规模效应。

还应对照 SFT-only、DPO 与参考模型在同一问题上的 log probability。若正确答案在 DPO 后绝对概率下降，而错误英语回答上升，偏好阶段直接重排了语言概率；若正确答案概率相近却生成格式改变，则评测抽取更可疑。这样的证伪设计比用“英语数据导致多语言下降”一句话收尾更接近机制。

## 3. QLoRA 节省训练内存，但不是全量微调的等价替代

### 3.1. 量化基座与低秩增量如何配合

LoRA 冻结原权重 $W$，只学习低秩增量 $BA$，前向计算写成 $Wx+sBAx$。其中 $A$ 与 $B$ 的秩 $r$ 远小于权重维度，$s$ 由 alpha 与 rank 决定。QLoRA 进一步以低比特形式保存冻结基座权重，在计算时按需反量化，同时让 LoRA 参数保持可训练精度。这样减少了模型权重、梯度和优化器状态共同占用的显存，使单机或较小集群能够适配更大模型。

TÜLU 2 的 QLoRA 配方训练 5 个 epoch，学习率 $1\times10^{-4}$，warmup 比例 0.03，有效 batch size 128，权重衰减为 0；rank 为 64，alpha 为 16，dropout 为 0.1，适配全部注意力与前馈网络线性层。最大序列长度为 4,096，只有全量 SFT 的一半。QLoRA 模型在 A100 80GB 集群上用 Open Instruct 训练，全量模型则主要使用 256 芯片 TPU v3 pod。这里至少同时改变了参数更新方式、上下文上限、训练轮数、学习率与硬件实现，所以结果衡量的是这套可承受预算内的完整 QLoRA 配方，而不是对量化误差的单变量实验。

### 3.2. 长回答差距比知识任务更明显

与全量 SFT 相比，QLoRA 在 7B、13B、70B 上的总平均分分别从 53.0 降到 47.7、从 60.8 降到 57.2、从 73.4 降到 71.0，绝对差距随规模从 5.3 缩小到 3.6 和 2.4。论文正文将跨任务的相对差距概括为小模型约 10%、大模型约 3%。单项上并非处处落后: 7B QLoRA 的 TyDiQA 为 49.2，高于全量微调的 46.4；13B 的 BBH 为 52.5，高于 49.5，TyDiQA 为 54.6，高于 53.2；70B 的 MMLU、BBH、TyDiQA 也略高。

开放式生成呈现一致差距。AlpacaEval 在 7B 上由 73.9 降到 56.1，13B 由 78.9 降到 65.6，70B 由 86.6 降到 78.6，分别少 17.8、13.3 和 8.0 个百分点。三个 QLoRA 数值相对全量结果的降幅约为 24.1%、16.9% 和 9.2%，平均约 16.7%；论文正文用“约 20% 平均差距”作概括，可能采用了不同的汇总或早期结果口径。无论采用哪一种口径，方向一致: 受限配方在短答案知识任务上可以接近甚至偶尔超过全量微调，但在长篇开放式回答上差距更大。4,096 token 的训练上限、低秩更新容量与量化基座都可能参与其中，现有消融不能把责任单独分给某一项。

### 3.3. QLoRA 没有继续用于偏好优化

作者因 QLoRA 在指令微调阶段表现不够理想，没有继续测试 QLoRA 加 DPO。这个决定让实验矩阵缺少一个重要交叉项: 无法判断参数高效 SFT 的差距会被 DPO 缩小、保持还是放大。已有结果只能支持“该 QLoRA 配方不等价于全量 SFT”，不能推出 QLoRA 一定不适用于偏好优化。论文也提到同期工作曾在基于 PPO 的 RLHF 中取得良好结果，说明训练阶段与算法相互作用不可忽略。

成本比较同样需要限定口径。论文给出了硬件类别和超参数，却没有报告每种方案统一核算的 GPU 小时、吞吐量、峰值显存或能耗，因此不能从表格计算完整的成本收益比。可以确认的是，QLoRA 把训练放到内部 A100 80GB 集群，而全量训练依赖大型 TPU pod；代价则体现在平均性能和 AlpacaEval 的明显差距。若部署目标偏向分类、短问答或资源受限的领域适配，QLoRA 仍可能是合理选择；若目标要求长回答质量，TÜLU 2 的数据支持优先验证全量微调或更强的参数高效配方。

还要区分训练内存和推理成本。QLoRA 主要减少适配阶段需要保存和更新的参数状态，训练结束后是否合并适配器、基座以何种精度加载、服务时采用怎样的 KV cache，都会另行决定推理显存与吞吐。本文没有把这些部署变量纳入实验。因此，从“可以在 A100 集群训练”不能直接推导“线上推理更便宜”；同样，全量微调训练昂贵也不意味着最终模型一定需要更高的推理成本。资源决策应分别核算训练、存储和服务三个阶段。

### 3.4. 低秩约束限制的是更新子空间

对一个 $d_{out}\times d_{in}$ 的线性层，全量微调能在整个矩阵空间中选择更新 $\Delta W$；LoRA 把更新写成 $BA$，其中 $B\in\mathbb R^{d_{out}\times r}$、$A\in\mathbb R^{r\times d_{in}}$，因此 $\operatorname{rank}(\Delta W)\le r$。参数量从 $d_{out}d_{in}$ 变为 $r(d_{out}+d_{in})$。rank 64 对大矩阵节省显著，却预设任务所需更新可以由低维方向表达。

这个预设在分类或局部风格适配上可能成立，面对覆盖多任务、代码、推理和长对话的混合时更难判断。不同来源需要的更新方向可能各自低秩，合在一起的并集秩却上升。即使每层 rank 64 足以拟合单个任务，也未必容纳所有任务之间的折中。Tülu 2 将适配器放到全部注意力和前馈线性层，扩大了可更新位置，但每个矩阵仍受低秩结构约束。

量化带来另一层近似。冻结权重以低比特存储，前向时反量化得到近似矩阵 $Q(W)$，实际函数为 $Q(W)x+sBAx$。适配器可以补偿部分量化误差，也要同时学习指令任务更新。若量化误差方向与任务更新竞争有限的 rank，容量会进一步紧张。单看最终分数无法区分低秩限制与量化近似，需要加入“未量化 LoRA”“量化基座加全秩小层”或不同 rank 的对照。

### 3.5. 为什么统一训练轮数并不代表统一优化强度

全量 SFT 训练 2 个 epoch，QLoRA 训练 5 个 epoch，后者学习率也更高。作者说明这些是在计算预算内得到的较强设置，因而表格是在各自配方下比较可用结果。epoch 数不同意味着模型看到的数据次数不同；学习率、可训练参数量、dropout 和量化噪声又改变每步函数更新幅度。不能把最终差距直接归结为“QLoRA 少更新了参数”。

更公平的比较可有三种口径。计算匹配固定总 FLOPs，观察同预算谁更好；数据匹配固定 token 次数和训练顺序，隔离参数化差异；质量匹配分别调到最佳验证分数，再比较达到该质量所需资源。三者回答不同问题。Tülu 2 更接近预算约束下的配方比较，并没有提供完整 Pareto 曲线。

上下文上限也是明显混杂。全量模型用 8,192，QLoRA 用 4,096；V2 混合恰好强调长 ShareGPT 与 Open Assistant 样本。QLoRA 可能再次截断一部分回复或历史，使开放式长回答监督受损。要验证“低秩更新导致 AlpacaEval 差距”，至少应在相同 4,096 长度下训练一份全量模型，或让 QLoRA 也使用 8,192，再看差距是否保留。

### 3.6. 参数保持也可能解释部分任务的反向优势

QLoRA 在若干 TyDiQA、BBH 和 MMLU 设置中接近或超过全量 SFT。低秩更新幅度受限，冻结基座大部分表示，可能减少英语指令数据对预训练多语言能力的覆盖。这个“保持效应”与 DPO 后 TyDiQA 下降形成呼应：更自由的参数更新能充分吸收目标分布，也更容易移动离目标分布较远的能力。

不过，保持解释需要 checkpoint 级证据。可以测量微调前后各语言验证 loss、参数或表示漂移，以及正确答案 logit 的变化。若 QLoRA 只是因输出格式更适配评测而得分更高，内部多语言保持并非唯一原因。不同硬件代码路径、随机种子和最大长度也可能造成小幅差异。表中零点几到一两分的反向优势不应承担过强机制结论。

这提示参数高效方法的价值不止省显存。它还提供显式容量瓶颈，可作为遗忘控制手段。rank、目标层和缩放系数决定新行为与旧能力之间的通道宽度。合理实验应画 rank 从小到大的能力保持—任务适应曲线，而不是只比较 rank 64 与全量两个端点。

### 3.7. 缺失的 QLoRA+DPO 交叉项意味着什么

实验矩阵有两个轴：SFT 使用全量或 QLoRA，偏好阶段使用或不使用 DPO。论文只覆盖其中三个概念位置中的两条主线，没有训练 QLoRA SFT 后继续 DPO。因而我们不知道较弱的开放式生成起点是否给 DPO 留出更大提升空间，也不知道低秩适配器能否承载偏好更新而不进一步损伤能力。

交叉实验还需定义 DPO 更新哪些参数。可以冻结量化基座，继续更新同一适配器；也可以固定 SFT 适配器，新增第二个偏好适配器；还可合并 SFT 权重后重新挂载 LoRA。第一种让两阶段争用同一低秩子空间，第二种能分离阶段但推理时需组合，第三种引入合并和再量化误差。它们都可被称作参数高效 DPO，机制并不相同。

因此，“作者未继续测试”是一项实验范围说明，不是方法判决。论文同期已有参数高效 RLHF 的积极结果，也明确把该方向留给后续研究。Tülu 2 能支持的结论是：其 QLoRA SFT 配方在多项指标、尤其 AlpacaEval 上落后全量 SFT，团队据此把资源投向全量 DPO。

## 4. 消融结果应按任务与评测口径解读

### 4.1. Code Llama 实验分离了基座先验与指令数据作用

Code TÜLU 2 将同一 V2 混合用于 Code Llama 7B、13B 和 34B。相对 Code Llama 基座，Codex-Eval 分别从 58.7 提高到 68.9、从 69.8 提高到 76.2、从 77.6 提高到 82.5；相对普通 TÜLU 2，7B 与 13B 的代码分数则从 36.9、49.0 提高到 68.9、76.2。代码预训练提供了强先验，而同一指令配方继续改善可执行代码生成。它也说明后训练数据无法完全弥补基座领域暴露的差异。

代码能力增强伴随开放式回答退步。Code TÜLU 2 的 AlpacaEval 在 7B、13B、34B 上为 58.0、64.1、76.8；普通 TÜLU 2 的 7B 和 13B 为 73.9、78.9。与各自 Code Llama Instruct 相比，Code TÜLU 2 的 MMLU、GSM8K、BBH、TyDiQA 和 Codex-Eval 普遍更好，但 AlpacaEval 更低。V2 混合能够把代码基座变成更全面的指令模型，却不能完全消除基座分布对回答风格和通用生成的影响。

### 4.2. 自动评判与长度偏差限制了开放式结论

AlpacaEval 让模型回答 805 个提示，由 GPT-4-0613 与 Davinci-003 的回答成对比较；MT-Bench 含 80 个带追问的问题，共形成 160 个待评分回答，也由 GPT-4-0613 评分。论文专门检查长度相关性，因为偏好模型和自动评判器可能偏爱更长、格式更完整的回答。作者报告 AlpacaEval 与平均回答长度的相关系数为 0.96，而 MT-Bench 为 0.14。这意味着 AlpacaEval 的提升不能直接等同于事实性、推理或任务成功率的同幅提升。

DPO 的效果正集中在开放式生成指标，因此长度是不可回避的混杂变量。更长的回复可能含有更多解释，也可能只是迎合评判器偏好。论文同时保留 MMLU、GSM8K、BBH、TyDiQA、Codex-Eval 与 ToxiGen，能够揭示 AlpacaEval 上升时其他能力并未一致上升。70B DPO 在 MT-Bench 达到 7.89，高于该表中的其他开放权重模型，但其 TyDiQA 与若干推理项仍下降。多指标对照比单一排行榜名次更能描述模型行为变化。

### 4.3. 数字矛盾来自版本与汇总口径，不能交叉拼接

仓库中的 LaTeX 工作文件保留了修订痕迹，与最终论文 PDF 存在若干差异。例如 `dpo_comparisons.tex` 的最终对照给出 70B DPO 的 AlpacaEval 为 95.1，而另一份主表工作稿出现 91.9；最终 QLoRA 对照中 7B、13B、70B 的 AlpacaEval 是 56.1、65.6、78.6，较早主表工作稿则出现 51.7、59.8、76.6。Code TÜLU 2 的 7B、13B、34B AlpacaEval 最终对照为 58.0、64.1、76.8，工作稿中还可见 54.0、58.4、72.0。解析实验时应以最终论文对应的表 3、表 5、表 6 为同一版本证据，不应从工作稿挑选更高或更低的数字拼成一张表。

正文概括也可能采用相对百分比，而表格差值使用百分点。DPO 的“平均提高 13%”与最终表中平均增加约 10.1 个百分点就是一例。QLoRA “从 10% 差距缩小到 3%”描述跨任务汇总趋势，不等于总平均分直接相减；“开放式生成约 20% 差距”也不是三个最终 AlpacaEval 相对降幅的简单平均。复述时必须同时写明分母和汇总方式，无法由公开表格唯一复算的概括应保留为作者报告，而不把它改写成精确百分点。

总平均分本身也混合了方向不同的指标。MMLU 等项目越高越好，ToxiGen 报告的却是毒性百分比，越低越好；汇总前需要进行方向处理。不同表格还会因是否纳入 TruthfulQA 而改变列数和平均值，受 UltraFeedback 污染的模型尤其不能与未污染模型沿用完全相同的平均口径。比较两行模型时，应先确认表号、模型版本、评测列和方向，再讨论平均值，不能只抄录一个末列数字。

### 4.4. 每项评测测量的对象并不相同

MMLU 的零样本多选准确率侧重知识与题目映射；GSM8K 和 BBH 使用特定推理提示与答案抽取，既测推理也测格式遵循；HumanEval 的 pass@10 通过执行测试判断代码功能；TyDiQA 同时受多语言理解、生成语言和答案抽取影响；ToxiGen 用另一个分类器判断生成毒性；AlpacaEval 与 MT-Bench 则让 GPT-4 比较或评分开放回答。把这些数字平均，相当于默认每项尺度和方差可直接相加。

同样增加 5 个点，在不同指标上意义不同。准确率从 50 到 55 对应固定样本上的额外命中；pass@10 还受采样温度和候选相关性影响；AlpacaEval win rate 是相对 Davinci-003 的成对偏好，基准回答不变但评判器可能漂移；毒性率下降则是风险事件减少。严谨比较应先逐项解释，再用平均值作导航。

评测提示也属于实验条件。BBH 采用三条带思维链的 few-shot 示例，并按“So the answer is”抽取；模型更会模仿该格式可能提高得分。HumanEval 以温度 0.8 采样并报告 pass@10，不能与贪心单次生成等同。AlpacaEval 最多允许生成 8,192 token 且没有额外 stop sequence，长回答倾向会显著介入。后训练恰好改变格式与长度，因此评测协议必须与分数一起保存。

### 4.5. 长度相关性为何不能简单做线性扣分

论文观察到 AlpacaEval 分数与平均输出长度相关系数高达 0.96。相关性可能来自评判器偏爱长答案，也可能是较强模型更完整地覆盖问题，因而自然写得更长。直接把长度回归掉，会把真正有用的解释一并删除；完全忽略长度，又会把冗余当质量。需要在相同提示上做配对分析。

可从 DPO 前后回答中抽样，让人工标注新增 token 是否提供事实、推理步骤、例子，或只是重述。也可用长度受控生成：限制相同 token 预算、提示模型简洁回答、或将长答案压缩后重新评判。如果 DPO 优势在等长条件下仍存在，说明内容偏好贡献较大；若优势大幅消失，原 win rate 主要受篇幅驱动。

长度还会与错误机会相互作用。更长回答可能提高覆盖，也增加事实错误、跑题和泄露的概率。单个二选一胜负无法展示这种内部结构。对开放回答同时测事实单元正确率、指令约束满足、冗余率和单位 token 效用，才能看见偏好优化究竟改善了什么。

### 4.6. 规模趋势必须区分天花板与真实敏感性

V2 相对 V1 的平均优势从 7B 到 70B 缩小，DPO 的 AlpacaEval绝对增益也随规模下降。一个直接解释是大模型更能从较弱数据中学习，因而配方重要性降低。但高分指标存在天花板：70B SFT 的 AlpacaEval 起点已经 86.6，最多只剩 13.4 个百分点；7B 从 73.9 开始，空间更大。比较原始增量会把可提升空间混入规模效应。

可用剩余错误关闭率 $(s_1-s_0)/(100-s_0)$ 辅助观察，或选择未饱和、连续 loss 型指标。还应为每个规模单独调学习率、$\beta$ 和 epoch；统一配方检验“能否直接扩展”，逐规模调参才能比较方法上限。Tülu 2 的贡献之一正是展示同一 DPO 设置可稳定跑到 70B，但这与“70B 已得到最佳 DPO 配方”是两回事。

基座能力也改变数据利用。大模型可能从复杂指令中提取更多，也可能已有相似行为，边际收益较小。使用训练 loss、验证 loss 与任务分桶可区分：若大模型在 V1 上已接近 V2 的验证 loss，属于冗余；若 V2 loss 更低但 benchmark 不涨，可能是指标饱和；若统一训练步数下尚未收敛，则是优化口径问题。

### 4.7. Code Llama 对照揭示基座和后训练的非交换性

可以把领域预训练记作变换 $P$，指令微调记作 $S$。Code Llama 路线近似先对 Llama 2 做 $P$，再做 $S$；普通 Tülu 2 只做 $S$。结果显示前者代码能力显著更强，却在部分通用生成上较弱。这说明 $S(P(\theta))$ 不能由简单增加代码指令数据来替代，也无法假定 $P$ 与 $S$ 的顺序可交换。

持续代码预训练改变底座表示和输出先验，SFT 主要把已有能力接到指令接口。7B Code Tülu 2 在 Codex-Eval 已接近最强 Llama 2 路线，说明领域基座能以较小参数量获得强专项能力。相反，通用 AlpacaEval 差距说明同一 V2 混合不足以完全拉回领域化造成的行为变化。

若要归因，可加入四格实验：Llama 2 与 Code Llama，各自使用通用 V2 和代码增强 V2。这样才能分离基座领域暴露、SFT 数据比例及两者交互。论文只覆盖其中一部分组合，所以能证明基座选择重要，无法给出“增加多少代码 SFT 可替代多少代码预训练”的换算。

### 4.8. 自动评判器需要稳定性与交换测试

AlpacaEval 在论文时没有固定线上 GPT-4 版本，作者主动统一为 GPT-4-0613，这是重要的复现控制。同一批回答换评判器版本，偏好可能因安全策略、长度倾向和知识变化而改变。只保存 win rate 不够，应保存模型原始回答、参考回答、完整评判提示和逐样本判决，才能用新评判器复算。

成对评判还要交换回答顺序，检测位置偏差；对同一对答案多次采样，估计判决方差；抽样人工复核，检查评判器是否被回答中的指令或自我声明影响。若 A 对 B 胜、B 对 C 胜、C 又对 A 胜，偏好存在非传递性，单一排行榜分数会掩盖风格簇。

MT-Bench 与 AlpacaEval 都用 GPT-4，却显示不同排序，这反而提供了有价值的交叉验证。前者包含多轮追问和分项评分，后者是对固定参考答案的单轮成对比较。模型在一个指标显著提升、另一个提升有限，说明“GPT-4 评判”并不是同一测量。报告时应保留两套协议的任务结构，而非统称为开放式能力。

### 4.9. 用置信区间判断小差异

许多表格差异只有零点几到一两分。评测样本有限，生成又含随机性，点估计无法说明差异是否稳定。分类准确率可用 bootstrap 或二项区间；AlpacaEval 应按提示重采样成对胜负；HumanEval 需要考虑同一问题多个样本之间相关；MT-Bench 还含评判器随机性。

训练随机种子同样重要。数据顺序、dropout 和分布式数值误差会让微调结果波动。若每种配方只训练一次，表中小幅领先可能位于训练方差内。70B 重复训练成本很高，可以在 7B、13B 做多种子估计，再谨慎讨论大模型差异；至少对生成评测重复解码和评判。

对多个任务同时挑最佳模型还会产生多重比较偏差。一个配方在八项里偶然赢几项并不罕见。预先声明主要指标、报告全部任务，并把探索性发现标出，能减少事后选择。Tülu 2 的多指标表格为此提供了基础，读者仍需避免只摘取最亮眼的 AlpacaEval 数字。

## 5. 一条可复查的开放后训练路线

### 5.1. 配方各阶段解决不同问题

TÜLU 2 的第一阶段是选择基座。Llama 2 相比 Llama 1 使用更多预训练 token，Code Llama 又加入代码领域预训练，这些先验决定了后训练可利用的能力边界。第二阶段是 SFT: V2 混合用任务覆盖、复杂指令、解释轨迹、多轮对话和少量身份样本塑造基本交互能力，并用 8,192 token 上限保留长样本。第三阶段是可选的偏好优化: DPO 用 UltraFeedback 把回答分布推向人类或评判模型更偏好的形式。QLoRA 位于 SFT 阶段，提供资源受限的替代实现。

复现实验时应保留阶段边界。若把 V2 数据、长上下文、Llama 2 基座和 DPO 同时更换，只能得到端到端结果，无法定位收益。较稳妥的顺序是固定基座与评测，先比较 V1/V2 混合，再固定 SFT 检查 DPO，最后在相同数据和尽量相同长度设置下比较全量微调与参数高效微调。污染检查也应随阶段执行；UltraFeedback 接触 TruthfulQA 提示后，该指标便不再适合作为未见数据上的独立证据。

### 5.2. 结果揭示的是帕累托边界，不是唯一最优点

若目标是开放式对话偏好，DPO 的 AlpacaEval 与 MT-Bench 收益有吸引力，但需要接受部分能力项下降和自动评判偏差。若目标是代码，Code Llama 加 V2 SFT 显著优于普通 Llama 2 路线，但通用开放式回答不一定更强。若训练资源有限，QLoRA 降低了硬件门槛，却在本文配方下牺牲长回答质量。不同方案分别位于成本、领域能力、开放式偏好和通用能力的不同位置。

TÜLU 2 最重要的工程贡献是把这些位置连同数据、模型、训练代码和评测设置一并公开。它没有证明某个单一算法可以取代数据治理，也没有证明偏好分数足以代表全部能力。相反，实验显示后训练是多阶段概率分布重塑: 数据混合决定监督信号覆盖范围，SFT 建立指令接口，DPO 改写候选回答排序，QLoRA 改变可训练参数与数值路径。只有逐任务报告结果、区分百分点与相对比例、记录数据接触和版本差异，模型改进才具备可复查的技术含义。

70B DPO 的训练还给出了一个明确的规模参照: 使用 512 核 TPU v3，三个 epoch 约耗时 7 天。这个数字证明作者完成了大规模 DPO 的稳定运行，但不能直接外推到其他硬件或代码栈，因为并行策略、序列长度分布与通信实现都会改变利用率。开放训练代码的作用正在于让复现者核对数据预处理、batch 定义和损失实现，而不是把“7 天”当成固定预算。对后续配方而言，可复查的运行条件与最终分数同样重要。

### 5.3. 从基座到 SFT，概率分布发生了什么

基座模型优化的是自然文本中的下一 token 概率。面对聊天模板时，它可能续写用户、模拟双方对话，或直接接着提示讲述。SFT 把 assistant 回复位置设为监督目标，反复强化“看到系统与用户消息后，由 assistant 完成任务”的条件分布。能力未必在这一阶段凭空出现；许多知识和代码模式已由预训练获得，SFT 负责选择并组织这些能力。

这也解释了基座能力为何仍决定上限。Code Llama 已把概率质量放到可执行代码附近，少量指令监督即可把它接到函数补全接口。普通 Llama 2 即使看到 Code-Alpaca，也很难用有限 SFT token 重现长期代码预训练。反过来，领域预训练使回答先验偏向代码，通用对话 SFT 又未必完全消除这种倾向。

可以把阶段作用拆成格式、选择与增量知识三类。格式看模板遵循和停止位置；选择看同一知识在问题下能否被调用；增量知识看训练后是否能回答基座确实不会的新事实。Tülu 2 主要证明前两类与任务适应，数据中少量科学内容并不足以支持大范围知识注入结论。

### 5.4. 从 SFT 到 DPO，优化单位由单答案变成答案差

SFT 对每条目标回复独立做最大似然。它无法表达“这两条都通顺，但第一条更遵循约束”。DPO 把同一提示下的两个完整序列放在一起，通过概率比学习相对偏好。优化单位从 token 标签扩展为序列对，但梯度仍由每个 token 的 log probability 累加得到。

这种变化适合学习难以写成唯一标准答案的属性，例如帮助程度、结构和语气。它对可执行正确性并无天然保证：如果偏好标签选择了看似完整却代码错误的回答，DPO 会忠实提高它。偏好数据生成与筛选因而相当于隐式任务定义，评判维度决定策略最终追逐什么。

参考模型把阶段连接起来。DPO 衡量当前策略相对 SFT checkpoint 对 chosen 和 rejected 的变化，因此保留多少 SFT 行为取决于参考锚点与 $\beta$。换一份 SFT 混合，即使偏好数据完全相同，参考概率比也不同。DPO 结果不能脱离前置 SFT 单独复用。

### 5.5. 每个阶段都应留下可诊断的 checkpoint

只比较最终模型与原始基座，会把数据混合、SFT 和 DPO 的作用叠在一起。至少保存基座、SFT 中段、SFT 结束、DPO 中段与 DPO 结束 checkpoint，并在固定验证集上测逐任务 loss、生成长度、语言比例和 KL。这样能看出能力在何时出现，又在何时退化。

例如 TyDiQA 若在 SFT 第一轮已下降，主要问题来自 V2 英语混合；若 SFT 保持、DPO 才快速下降，偏好阶段是主因。AlpacaEval 若在 DPO 早期大涨、后续只增加长度，最佳 checkpoint 可能早于第三个 epoch。最终 epoch 只是训练计划终点，不自动等于多目标最优点。

checkpoint 轨迹还能检验学习率解释。70B 使用较低 SFT 学习率，DPO 各规模采用统一低学习率。比较单位 token 的 KL 和参数更新范数，可知道大模型实际移动是否更少。没有轨迹时，规模差异会被误解成模型容量规律。

### 5.6. 一个更完整的阶段消融表

理想消融以同一 Llama 2 基座为起点，依次控制 V1/V2 数据、2,048/8,192 长度、SFT 轮数、UltraFeedback 是否加入、DPO 超参以及多语言回放。每次只改变一项，并保留相同评测协议。资源有限时，可先在 7B 完成全矩阵，再选关键交互到 13B 和 70B 验证。

特别需要测试数据与算法交互。V2 SFT 加 DPO有效，并不代表 V1 SFT 加同一 DPO也有相同收益；更强 SFT 可能提供更好的参考点，也可能已经吸收偏好风格。类似地，多语言 SFT 能否抵抗英语 DPO 遗忘，要通过交叉项判断。只做主效应会遗漏后训练最重要的阶段依赖。

每格实验应同时记录训练 token、监督 token、峰值长度和计算量。若某配方因长上下文实际处理更多 token，性能差异既含数据也含预算。对等样本数、对等 token 和对等 FLOPs 可分别建立对照，答案未必相同。

### 5.7. 开放的意义在于允许重新组合证据

模型权重让人能重跑评测，数据发布让人能统计来源、长度与交集，代码则让模板、掩码和 loss 实现可检查。三者缺一，后训练结果都难以真正解释。只有权重，无法知道能力来自何种数据；只有数据，没有训练实现会遗漏大量细节；只有代码而缺少具体数据快照，复现仍会漂移。

Tülu 2 公开的价值还包括负结果：V2 并未改善所有任务，DPO 明显伤害多语言，QLoRA 在开放生成落后。它们让后续研究能针对问题改配方，而非只复制最高分。公开系统的科学价值并不等同于榜单第一，更重要的是把因果链上的中间对象留下。

## 6. 外推边界与可证伪结论

### 6.1. 论文直接证明了哪些事

在所公开的 Llama 2 7B、13B、70B 设置中，V2 混合的平均评测优于 V1，并显著改善若干开放生成、代码和毒性指标；统一的 DPO 配方能稳定训练到 70B，在 AlpacaEval 与 MT-Bench 获得明显收益；该 QLoRA 配方总体落后全量 SFT，差距随规模缩小；Code Llama 作为基座能大幅提升代码任务。这些结论都有同表对照支持。

论文还直接展示若干代价：V2 在 GSM8K 与 TyDiQA 上多次低于 V1；DPO 后 TyDiQA 尤其在大模型上显著下降；开放生成分数与长度高度相关；UltraFeedback 接触 TruthfulQA 提示，相关模型不能把该项当作未见评测。它们与正向结果同样构成论文结论。

稳定训练到 70B 表示在作者的 TPU、代码、数据和超参下没有出现阻断实验的优化问题。它没有证明任意模型、任意精度或任意偏好集都可原样扩展。类似地，公开权重在当时排行榜领先，只描述特定时间点和评判协议，不是永久排名。

### 6.2. 哪些机制仍未由实验分离

V1 到 V2 同时改变基座代际、数据组成、样本数和最大长度，完整系统差异不能归给单个因素。同基座混合表缓解了部分问题，却仍让来源增删、下采样与过滤一起变化。科学子混合、LIMA、Open-Orca或身份样本的独立贡献没有逐项测量。

QLoRA 与全量 SFT 同时改变最大长度、epoch、学习率、可训练参数和硬件代码路径，因此差距不能单独归因于低秩或量化。DPO 部分没有 PPO、奖励模型路线或其他偏好算法的同预算对照，“比 PPO 简单”属于组件数量与实现复杂度判断，并不等于质量更高。

DPO 多语言下降与英语偏好数据吻合，但缺少多语言回放和格式受控实验。AlpacaEval 提升与长度相关，论文提供了重要警告，却没有完成等长人类评测。阅读结果时，应把这些机制当作待验证解释。

### 6.3. 从 7B—70B 能外推到更大模型吗

三个规模给出趋势，但只有同一 Llama 2 家族，架构、tokenizer和预训练配方高度相关。随着参数继续增大，优化稳定性、数据容量和偏好敏感性可能改变。尤其 70B 已在部分指标接近天花板，收益缩小无法区分饱和与尺度规律。

跨家族外推更谨慎。Mistral、不同 tokenizer、MoE 或更长上下文基座，对同一混合的有效 token、记忆保持和 DPO KL 都可能不同。论文提到 Zephyr-Beta 的强表现也与 Mistral 基座有关，这本身说明底座选择能压过后训练配方差异。

可靠外推需要在多个基座上复现方向，并按起点分数和训练 token 归一化。若 V2、DPO 与能力保持的趋势跨家族一致，才能称作方法规律；若只在 Llama 2 成立，则它仍是有价值的家族配方。

### 6.4. 从英语偏好能外推到多语言吗

现有证据给出的答案偏悲观：英语占主导的 SFT 与 DPO 没有自然保住 TyDiQA。预训练多语言能力仍存在，却可能因输出策略和参数漂移而难以调用。不能用 MMLU 或 BBH 稳定来代替多语言验证，因为它们的输入分布与词表区域不同。

多语言扩展至少要覆盖提示、chosen、rejected 和评判器四层。只翻译提示而候选仍偏英语，模型会学到语言切换；候选翻译质量不稳定，排序标签又会混入翻译偏好；评判器若对低资源语言能力弱，UltraFeedback 式自动评分会放大噪声。更稳妥的方法是在目标语言中原生收集或生成候选，并用相应语言能力可靠的评判体系筛选。

评测也应分解语言保持与偏好改善。在每种语言上同时测封闭式答案、开放回答、拒答和长度，再与 SFT checkpoint 比较。若多语言偏好数据恢复 TyDiQA却损伤英语开放指标，混合权重仍需调整。没有一种全局比例能自动适合所有语言资源。

### 6.5. 从自动偏好能外推到真实用户吗

UltraFeedback 与 GPT-4 评判提供规模化信号，却代表特定评判模型的价值函数。真实用户对简洁、语气、风险和解释深度的偏好分布更宽，同一用户在编程、医疗和闲聊中的要求也不同。自动偏好训练出的单一策略容易向平均风格收缩。

检验外推需要独立人类偏好集，并按用户群与任务分层。还可让用户在等长回答间选择，减少篇幅混杂；收集“不确定或两者都差”标签，避免强迫二选一。若自动评判提升只在与训练评判器同源的指标存在，策略学到的是评判器适配；若跨人群仍稳定，才更接近通用帮助性。

偏好本身还会随部署场景改变。企业内部助手可能重视引用与简洁，教育助手重视推导，创作工具重视多样性。Tülu 2 展示的是一套通用开放模型配方，不提供所有场景的最优答案。部署前应在目标用户任务上重新建立偏好验证集。

### 6.6. 安全指标为何不能由 ToxiGen 一项代表

ToxiGen 使用诱导仇恨内容的提示，再由分类器判断生成是否有毒。数值下降说明在该分布和分类器口径下，模型更少生成被识别为毒性的文本。它不覆盖事实伤害、隐私泄露、危险操作、过度拒答或越狱鲁棒性，也无法判断模型是否通过无条件拒绝获得低毒性。

SFT 和 DPO 都可能改变拒答率。若模型对敏感群体相关的正常问题也拒绝，ToxiGen 仍可能给出好分数。评测应加入良性敏感提示，计算安全与过度拒答的双侧错误；再检查拒答理由是否准确、是否在多语言保持一致。

论文结论中可以说 V2 与 DPO 改善了 ToxiGen 指标，不能扩写成全面安全对齐。开放权重还允许下游再次微调，原有行为可能被覆盖。安全是多维且随使用环境变化的属性，需要独立红队与风险评估。

### 6.7. 数据许可和可追溯性影响可复用范围

混合数据来自人工数据集、共享对话、教师生成内容与科学任务。每个来源的许可、个人信息风险和再分发条件不同。模型与数据公开让研究可复查，不表示所有下游商业用途自动获得相同授权。复用者应沿 mixture manifest 回到各源数据许可，而非只看聚合数据集页面。

ShareGPT 类真实对话还涉及用户是否预期内容被用于训练，网页复现版本与原服务数据是否完全一致也需注意。生成数据可能包含教师服务条款约束和训练材料复现。科学文献任务来自已有 benchmark，其文本来源与许可也可能分层。数据治理不是性能之外的附注，它直接决定配方能否部署。

可追溯记录至少包括源数据版本、转换脚本、过滤规则、样本哈希和移除请求。若某来源后来需要删除，只有保留映射才能重建混合并评估影响。Tülu 2 的开放路线为这种审计提供入口，实际责任仍由使用者承担。

### 6.8. 一套可证伪的后续实验

第一组实验验证数据混合机制：在固定 token 预算下逐项加入 LIMA、科学任务、Open-Orca和身份样本，报告来源验证 loss、梯度冲突和任务分桶。若所谓高质量来源在多种子下没有稳定局部收益，相应解释应被放弃。

第二组实验验证 DPO 机制：控制 chosen/rejected长度，比较原始 DPO、长度归一化、SFT回放和多语言回放；同时记录 chosen likelihood、rejected likelihood、KL 与生成长度。若 AlpacaEval提升在等长人评中消失，收益主要来自评判器长度偏好；若仍保持，偏好内容贡献得到支持。

第三组实验拆分 QLoRA：统一上下文长度、token次数和数据顺序，比较全量、未量化 LoRA、不同 rank QLoRA，再补 QLoRA+DPO。若长度对齐后开放生成差距大幅缩小，原结论主要受截断影响；若 rank 增大持续逼近全量，容量解释更有力。

第四组实验检验外推：换用至少两个基座家族与多语言偏好集，在独立人类评测、执行式任务和安全双侧指标上复现。只有这些方向稳定，才能把 Tülu 2 从一套成功配方提升为更普遍的后训练规律。

### 6.9. 读表时最后做一次归因检查

看到某模型领先，先确认基座是否相同；基座不同，预训练数据与架构都可能主导。基座相同时，再确认 SFT 数据、上下文长度和训练 token 是否相同。比较 DPO 时，确认参考 checkpoint、偏好数据、$\beta$ 和评测污染。比较 QLoRA 时，确认长度、轮数、目标层与量化设置。

随后检查指标方向、样本数、评判器版本和生成参数。开放式分数上升时看长度，能力平均稳定时看单项，多语言下降时看输出格式，代码分数上升时看采样与 pass@k。最后判断差异是否大于随机性，并查阅对应最终表而非工作稿。

按这条顺序，Tülu 2 的证据会变得很清楚：它没有给出一枚万能后训练按钮，而是展示了数据、基座、监督目标和偏好目标怎样共同重塑模型。真正可迁移的经验，是把每一步变化放进受控对照，让收益与代价在同一套指标中出现。

### 6.10. 偏好标签噪声会怎样进入 DPO

假设真实偏好为 $y_a\succ y_b$，自动评判器却以概率 $\epsilon$ 把顺序翻转。DPO 会把错误标签当作确定监督，在翻转样本上提高较差回答的相对概率。若噪声与内容无关且低于一半，大量数据仍可能恢复平均方向；现实中的噪声往往有结构，例如评判器系统性偏爱长答案、熟悉的英文表达或显式分点。这种偏差不会随样本增多抵消，反而被策略稳定吸收。

评分差可作为不完全的置信信号。chosen 与 rejected 评分相差很大时，排序较可靠；只差极小数值时，二值化会夸大确定性。用软标签或按差值加权，可以让模糊样本贡献较小梯度。另一种办法是要求多个评判器一致，代价是数据量下降，且多个同源模型的错误仍可能相关。

噪声对不同提示也不均匀。事实问答可通过外部证据核验，创作和建议更依赖主观偏好，安全问题还涉及规范。把所有偏好对放进同一 logistic 目标，相当于假设标签可靠度一致。更细致的训练应按任务估计噪声，或在损失中引入样本权重。Tülu 2 没有提供这一层消融，因此 DPO 成果应绑定其筛选数据版本。

### 6.11. KL 距离为何只能近似代表能力保持

参考策略约束常被理解为“不要离 SFT 模型太远”。序列级 KL 小，说明在所采样提示和回答上总体概率变化有限，却不保证每个能力区域都保持。模型可以在大量常见英语 token 上几乎不动，同时在罕见语言、特定格式或长尾知识上发生很大相对变化，总平均 KL 仍很小。

能力保持需要分布条件化的 KL。分别在英语偏好提示、多语言问答、代码、数学和安全集合上估计 $D_{KL}(\pi_\theta\Vert\pi_{ref})$，再与任务变化对应。若 TyDiQA 分布上的 KL 显著高于训练域，说明更新外溢；若 KL 不高但准确率下降，少量关键 token 的变化就足以翻转答案。

KL 方向也有区别。$D_{KL}(\pi_\theta\Vert\pi_{ref})$ 强调新策略实际生成的区域，可能忽略参考模型高概率而新模型已丢弃的模式；反向 KL 对这种覆盖丢失更敏感。实际 DPO 通过概率比与参考锚定，并非直接在所有提示上精确计算完整 KL。将“有参考模型”直接等同于“所有能力受保护”，会高估正则的作用。

### 6.12. SFT 数据内部也需要去重与泄漏检查

V2 混合的多个来源并非天然独立。FLAN、Open-Orca 与教师生成数据可能共享底层提示；ShareGPT 对话可能转贴公共题目；代码数据可能含 HumanEval 风格任务。若同一提示以多个答案出现，模型会得到重复或冲突监督。样本总数下降到 326,154 并不自动表示跨来源已经语义去重。

去重可分为提示、回答与整对三个层次。提示重复而回答不同，适合检查是否为有益多样性或标签冲突；回答大段重复，可能来自教师模板；整对重复则直接改变采样权重。精确哈希能去掉字面副本，MinHash 或嵌入近邻用于发现改写。对评测集还要单独做提示族匹配，尤其是 GSM8K、HumanEval、TruthfulQA 这类公开题库。

去重也会改变数据分布。大量相似样本可能代表真实高频需求，全部压成一条会低估重要性；保留全部又会让某个抓取源主导。较好的做法是先聚簇，再给每簇设置上限或权重，并报告去重前后 token 占比。这样“频率”成为显式设计选择。

### 6.13. 训练答案的正确性与可学习性是两条轴

一条回复可以事实正确，却包含跳步、隐含前提或依赖模型尚未掌握的表示，未必是高效监督；也可以结构清晰、容易模仿，却在关键事实出错。SFT 数据筛选若只看语言质量，会把流畅错误写入目标；只看最终答案，又可能保留不可理解的推导。

对推理数据，应分别验证最终答案和中间步骤。错误链条碰巧得到正确答案，会让 token 级最大似然强化错误过程。对代码数据，执行测试比文本评判可靠，但测试覆盖不足仍会放过伪解。科学文献任务要检查答案是否能由给定文档支持，避免模型凭常识答对却忽略证据。

可学习性还与基座有关。同一复杂回答对 70B 可能提供细粒度改进，对 7B 可能超出容量，只留下表面格式。分规模观察训练 loss 不足以判断，因为低 loss 也可能来自复制。需要在改写问题、反事实输入和步骤扰动上测试，确认模型获得可迁移规则。

### 6.14. 为什么平均 loss 与最终任务可能脱钩

SFT 优化所有目标 token 的平均负对数似然，benchmark 往往只关心最后一个答案、代码能否执行或回答是否被偏好。长解释中大量常见连接词容易降低 loss，却对最终正确率贡献有限；少数数字、实体和运算符决定任务成败，却在平均中权重很小。

因此，训练 loss 更低的混合未必有更高任务分数。可将目标 token 按答案核心、推理步骤、格式与普通文本分类，分别统计 loss；或计算关键 token margin，例如正确选项与错误选项的对数概率差。DPO 也类似：偏好分类准确率达到很高后，开放任务仍可能不升，因为模型学会了数据中的简单风格线索。

阶段选择应基于独立验证任务，而非只看训练目标。验证又不能直接复用最终 benchmark 调参，否则多次试验会逐渐过拟合公开测试。建立与目标能力同构、题目独立的开发集，是开放后训练中经常被低估的一步。

### 6.15. 回答风格与能力应设计成正交测试

模型写得更有条理，自动评判器容易认为它更强；模型知道答案却输出格式错误，抽取式 benchmark 又会判错。要分离两者，可以对同一底层问题构造多种输出要求：只给短答案、给推导、给结构化 JSON、以另一种语言回答。底层结论一致时，格式变化揭示指令控制；结论本身变化则涉及能力或知识。

还可以用 oracle 重写。把不同模型的答案交给固定重写器统一长度和风格，再由人或执行器判断内容；或保留原内容，把语气和排版随机化，测试评判器是否改判。重写会引入新误差，却能作为敏感性分析。若 Tülu 2 DPO 的优势在风格统一后明显缩小，就应把收益描述为回答呈现改善，而非推理提升。

反向实验也有价值：给 SFT 模型增加明确格式提示，使其模仿 DPO 回答长度与结构。如果不训练即可追回大量 AlpacaEval差距，偏好阶段主要学到可提示的风格；若仍差很多，DPO 对内容选择或局部概率产生了更深变化。

### 6.16. 复现记录要能重建每个概率目标

SFT 需要保存消息模板、特殊 token、截断方向、packing、label mask、样本顺序和 loss 归一化。缺少任何一项，相同数据与超参也可能得到不同梯度。多轮对话尤其要记录哪些 assistant 回合参与损失，以及切块后是否补回系统提示。

DPO 还需保存 chosen/rejected 原文、筛选版本、参考 checkpoint 哈希、$\beta$、序列概率是求和还是归一、提示与回复的截断规则。chosen 和 rejected 若在不同位置被截断，偏好标签可能失去依据。参考模型是否与策略共享 dropout、是否预先缓存 log probability，也会影响数值复现。

评测侧保存原始生成最重要。自动评判器会更新，只有原回答在手，才能固定其他变量重新评分。每条记录应带模型提交号、生成参数、模板、随机种子、停止原因和评判结果。论文中工作稿与最终表数字不同，正说明版本标识不可省。

当这些信息齐备，复现可以分成三层：训练实现复现检查 loss 轨迹，模型行为复现检查逐样本输出，科学结论复现则在新基座与新数据上验证方向。后两层即使数字不完全相同，也可能支持同一结论；若连实验对象的版本都不清楚，任何差异都无法定位。

### 6.17. 身份、拒答与帮助性可能互相干扰

身份样本要求模型稳定说明自己是 Tülu 2 以及开发者信息，偏好数据又可能奖励礼貌、完整和安全的回答。两类目标在普通问题上相安无事，遇到“假装你是另一个系统”“复述下面的模型自述”或角色扮演时会冲突。模型需要区分陈述事实、引用文本与遵循临时角色，而少量 hardcoded 样本未必覆盖这些语用差别。

拒答也会与帮助性发生冲突。偏好评判器可能把看起来谨慎的回答排在直接回答之前，策略随后扩大拒答范围；也可能偏爱详尽回答，让模型在应当拒绝时提供过多细节。ToxiGen 只观察有毒输出，AlpacaEval偏向一般帮助性，两者都没有直接测量边界是否准确。

可构造配对测试：危险请求与形式相似的良性请求、真实身份询问与文本引用、角色扮演与系统事实。每对只改变决定行为边界的条件，观察 SFT 和 DPO 前后是否同时提高正确接受与正确拒绝。若安全率提高来自全面拒绝，良性对照会立即暴露。

### 6.18. 数据顺序可能改变同一混合的结果

“使用同一批数据训练两轮”仍有多种顺序。完全打乱会让不同来源在局部 batch 中随机混合；按来源分块会形成短暂课程；按长度分桶可提高效率，却让任务类型与长度相关地聚集。优化器带动量，前几个 batch 的梯度会影响后续更新，因而顺序并非理论上可忽略。

课程顺序还可能减轻冲突。先用广覆盖 FLAN 建立格式，再用高质量对话收尾，可能提升开放回答，却也更容易遗忘早期任务；把少量身份数据放在末尾，局部效果可能强于均匀混合。Tülu 2 报告的是其训练管线产生的结果，没有系统比较课程策略。

复现时应固定 shuffle seed 和分布式采样器，记录每来源在训练步上的分布。研究顺序效应可保持每源总 token 完全相同，只改变排列，再测 checkpoint 轨迹。若最终差异显著，“数据配方”就应同时包含混合比例与呈现顺序。

### 6.19. 训练两轮意味着样本被重复看见，但重复价值并不相等

第二个 epoch 再次呈现相同目标。第一轮模型可能主要学会模板和常见任务，第二轮则继续压低少数难 token 的 loss，也可能开始记忆独特回答。高质量罕见样本从重复中受益，带错误或个人信息的样本同样被强化。epoch 是全局计数，无法表示不同来源何时已经饱和。

逐来源验证 loss 可以指导停止：若 ShareGPT loss 继续下降而独立对话质量不升，可能在拟合具体措辞；若科学任务验证 loss仍下降且迁移任务改善，继续训练有价值。还可按来源设置不同重复次数，使小型高质量集不过度复制，大型多样数据得到足够覆盖。

DPO 训练三轮同样面临偏好对记忆。分类准确率趋近饱和后，继续扩大 margin 会推动策略远离参考模型，却未必增加真实偏好。监控验证偏好准确率、KL、长度和能力任务，可以找到早停点。统一三轮展示了可复现配方，不代表每个规模都恰好在第三轮达到最佳平衡。

### 6.20. 如何把 Tülu 2 当作一套研究基线

最有价值的用法是保留其可复查骨架：固定公开基座，明确 SFT mixture，保存中间 checkpoint，再用来源清楚的偏好集做第二阶段。新增方法只替换一个环节，其余数据与评测不动。这样，新结果可以回答“相对 Tülu 2 的哪一步改善”，而非与整套系统同时变化。

若研究数据质量，就固定 SFT 算法和 DPO；若研究偏好目标，就复用同一 SFT checkpoint 与偏好对；若研究参数高效训练，就对齐最大长度、token预算和评测。论文已经提供 V1/V2、SFT/DPO、全量/QLoRA和 Llama/Code Llama 多条对照轴，后续实验应补齐交叉项，而不是只增加一个更高总分。

基线也要随时间冻结。公开仓库会更新依赖、模板和数据脚本，模型集合可能新增版本。论文级复现应指向具体提交与数据哈希。新代码带来的改进可以另作实验，不应静默覆盖旧基线。只有旧结果可重建，新结果的增量才有明确含义。

### 6.21. 最终模型卡应该回答哪些问题

模型卡首先要说明基座、SFT 数据版本和偏好数据版本，并标出已知评测交集。接着列出最大训练长度与推荐推理模板，说明是否只对 assistant token 计算损失。用户若套错聊天模板，模型表现下降不能归因于权重本身；若拿 8,192 的训练长度宣传成任意长度可靠，也超出了实验。

能力部分应保留逐任务结果与评测参数，不能只给总平均。DPO 模型要单列 SFT 对照，让人看到 AlpacaEval收益与 TyDiQA代价；Code Tülu 2 要把代码优势和通用回答差距一起写；QLoRA版本要注明其 4,096 训练上限和未进行 DPO。已知的 TruthfulQA 污染应直接说明为何不报告。

限制部分还应覆盖语言、自动评判、事实性和安全范围。训练数据以英语为主，多语言下降已有实测；GPT-4偏好分数受长度影响；ToxiGen 只覆盖毒性一维；模型可能生成训练数据中的错误或敏感内容。这些限制不会抵消模型价值，却决定使用者该补什么评测。

最后提供可追溯标识：权重哈希、代码提交、数据 manifest、许可证与引用。若同名模型存在 SFT、DPO、QLoRA和 Code 版本，命名必须把阶段写清楚。模型卡承担的是把研究中的条件带到实际使用环节，避免一个“Tülu 2”名称抹平配方之间的重要差别。

部署者还应写明实际采用的量化方式、解码参数和系统提示，因为这些设置会继续改变拒答、长度与任务分数。权重评测给出的是参考运行条件下的行为，不是所有服务配置的保证。上线后的抽样审计要沿用模型卡中的能力分桶，并记录版本升级前后的回归结果；这样，训练阶段发现的多语言、长度和安全边界才不会在服务层被遗忘。

这些记录最终会形成一条完整、可追踪的证据链。
