# Tülu 3 深度解析: 开放后训练如何成为系统工程

Tülu 3 提供了一套可以公开复现的后训练系统, 贡献落在整条流程而非某个孤立算法。它从基础模型出发, 依次组织提示池、监督微调数据、成对偏好数据和可验证奖励任务, 再用监督微调、直接偏好优化与强化学习形成逐级推进的训练链。与只公布最终权重的工作不同, 论文把数据混合、训练配置、基础设施和评测工具一并视为研究产物。由此, 模型性能来自数据选择、目标函数、计算实现与开发反馈的共同作用, 无法归结为单一“秘方”。

这套方法还试图解决开放模型研究中的评测过拟合。团队把开发期反复查看的任务与保留到末尾才使用的 unseen suite 分开, 并对训练提示执行污染检测。这个设计承认一个现实: 即使模型没有直接训练测试答案, 研究者反复依据固定榜单调配数据和超参数, 也会把开发过程拟合到排行榜。Tülu 3 因而既是一条训练流水线, 也是一套约束研发决策的实验制度。

## 1. 从提示池到训练混合的数据工程

### 1.1. 提示策划先于响应生成

后训练数据常被描述为若干“对话样本”, 但 Tülu 3 把提示与响应拆成两个阶段。提示决定模型需要学习哪些技能、覆盖哪些领域以及面对怎样的用户表达; 响应生成或筛选才决定示范质量。若提示分布过窄, 再强的教师模型也只会生成高质量但同质化的答案。论文同时使用公开数据与面向目标技能合成的提示, 在数学、代码、知识、指令遵循和安全等维度补齐覆盖。

这种拆分让数据治理更清晰。公开数据提供真实任务结构与多样表达, 但可能有重复、许可、格式不一致和评测污染问题; 合成提示可定向填补缺口, 却容易继承生成器的语言习惯并产生模板化。合理混合需要先定义能力目标, 统计提示分布, 再检查不同来源是否真正带来互补信号, 单纯增加数量不够。Tülu 3 的大量消融说明, 数据来源的边际价值需要在统一训练设置下判断。

### 1.2. 去污染是开发过程的防火墙

论文对提示进行与评测集的相似性检查, 目的是降低公开后训练数据对目标基准的直接泄漏, 无法据此证明训练语料绝对纯净。仅做精确字符串去重远远不够: 同一道题可能改变标点、选项顺序或措辞, 数学题也可能替换数字而保留结构。因此污染检测需要规范化文本和近似匹配, 同时记录阈值与被移除样本, 否则结果无法复现。

去污染也存在精度与召回的取舍。阈值过松会留下改写题, 阈值过严则会删除大量正常领域知识, 让模型在相关主题上失去训练信号。评测题本身若来自常见网页, 与公开指令数据相似并不必然代表恶意泄漏。最可信的做法是公开匹配规则、报告各来源删除比例, 并对临界样本人工抽查。Tülu 3 将这一步置于数据流水线前部, 使后续 SFT、DPO 与 RLVR 共享更干净的提示基础。

**数据混合比总样本数更重要。**

不同阶段的数据目标不同。SFT 需要覆盖广、格式正确且内容可靠的示范; 偏好优化需要同一提示下可区分的候选及可信偏好标签; RLVR 需要能够自动判定的答案与奖励。把所有样本混成一个池会让目标互相干扰。例如, 长篇知识回答可能在 token 数量上压过短指令遵循样本, 大量容易数学题也可能让训练损失下降却不提升困难推理。

因此混合比例应按任务与来源控制, 并同时观察样本数和 token 数。一个来源只占少量样本, 若响应极长, 仍可能主导梯度。反之, 大量短格式任务会频繁出现但贡献 token 有限。Tülu 3 的数据实验提醒我们, “更多数据”不是独立变量; 真正变量是经过采样器后模型看到的技能、难度和长度联合分布。

## 2. 三阶段训练配方的功能分工

### 2.1. SFT 建立行为接口与能力底座

监督微调最大化参考响应在提示条件下的似然. 它教会基础模型使用聊天模板、遵循角色边界、在合适位置结束回答, 同时把数学、代码和知识示范映射到统一交互接口. 模型具备这些基本行为后, 偏好学习可以在合格候选之间调整概率, 搜索空间也随之缩小.

SFT 也最容易发生过拟合。训练轮数增加时, 模型可能更贴近示范风格, 却损失基础模型原有的多样性和泛化。论文考察训练轮数、学习率、batch 聚合等配置, 说明配方需要通过多任务评测选择, 不能只看训练损失。batch aggregation 还体现了工程与优化的联系: 在分布式环境中保持有效 batch 和 token 统计一致, 是让不同规模实验可比较的前提。

### 2.2. DPO 把相对偏好转化为策略更新

直接偏好优化使用同一提示下的 chosen 与 rejected 响应, 让策略相对参考模型提高优选响应的对数概率差。它绕开显式奖励模型和在线采样, 实现简单且稳定, 很适合开放复现。但 DPO 学到的是数据中体现的比较关系, 并不会自动发现训练集中没有的优质行为。候选质量太低、差异只在表面风格或偏好标注噪声过大, 都会让模型学到错误捷径。

参考模型与温度系数共同约束更新幅度。约束过强, 策略几乎停留在 SFT; 约束过弱, 模型可能过度放大偏好数据中的格式特征并损害通用能力。论文通过超参数和算法实验确定配方, 并建设可扩展 DPO 基础设施。这里的研究结论同样依赖工程正确性: chosen 与 rejected 必须采用相同提示掩码, 长序列截断不能系统性偏向一侧, 分布式聚合也要保持损失定义一致。

**RLVR 提供可验证任务上的在线改进。**

可验证奖励强化学习把数学答案、代码测试或严格指令约束转成自动奖励。与人类偏好不同, 验证器可以低成本评估大量在线采样, 让策略探索 SFT 与 DPO 数据中未出现的解题路径。Tülu 3 将 RLVR 放在后期, 此时模型已经具有稳定聊天接口和较强基础能力, 在线采样更可能产生可被奖励区分的候选。

自动可验不代表奖励完整。数学只检查最终答案时, 模型可能用错误推理碰巧得到正确数值; 指令验证器只覆盖形式约束时, 模型可能牺牲内容质量换取格式分。论文观察到 IFEval 奖励上的过优化风险, 这揭示了 RL 的经典问题: 策略会寻找奖励函数的漏洞。因而训练不能只看 reward 上升, 还要检查独立任务、人工样本与回答长度等副指标。

**阶段顺序形成课程而非简单叠加。**

SFT、DPO、RLVR 的顺序具有因果意义。SFT 提供可用策略和模板规范; DPO 利用离线比较调整帮助性与风格; RLVR 再对可自动检查的能力进行在线强化。若直接从基础模型做 RLVR, 稀疏奖励下有效探索困难; 若在 RLVR 后做覆盖广泛的 SFT, 监督梯度又可能冲淡强化出的推理行为。三个阶段构成从密集教师信号到相对信号、再到任务奖励的课程, 不能随意交换。

不过阶段提升并非单调。某阶段提高数学或指令遵循, 可能降低安全、事实性或开放式对话质量。因此每个阶段都应保存检查点, 在同一评测套件上测量增益与回退, 并保留前一策略作为参考。最终模型是多目标权衡的结果, 不能用单项最高分替代整体选择。

## 3. 评测体系如何约束研发过拟合

### 3.1. 开发集与未见集承担不同职责

开发评测需要运行频繁、成本可控并能快速定位问题。研究者会据此选择数据混合、学习率和算法, 因而这些任务事实上进入了优化反馈循环。即使训练数据没有包含题目, 大量实验后的最佳配置也会适应开发集特性。Tülu 3 单独设计 unseen suite, 在主要决策完成后用于检验这些选择能否迁移。

未见评测不是神秘的一次性榜单。它需要覆盖与开发目标相关但题面、约束或评分维度不同的任务。论文引入 IFEval-OOD 与 HREF 等评测, 前者测试未见指令约束的泛化, 后者扩展对高质量响应的判断。若 unseen suite 与开发集只换了样本而结构完全相同, 它仍可能高估迁移; 若分布差异过大, 又难以解释失败来自训练方法还是任务转移。

### 3.2. OLMES 让基础能力比较可复现

Tülu 3 评测框架结合 OLMES 的标准化思想, 固定提示、few-shot 示例、任务形式和归一化等细节。后训练模型的比较尤其容易受聊天模板与答案解析影响: 一个模型输出“答案是 B”, 另一个输出长解释后再给 B, 解析器差异便可能变成分数差异。标准化配置让训练阶段之间的变化更可能来自模型, 而非评测接口。

同样重要的是逐任务报告。平均分可以掩盖某阶段在一个大任务上的增益与多个小任务上的退化, 也会受任务权重影响。开发者应保存逐题预测、解析失败和置信区间, 对接近的模型使用配对比较。Tülu 3 提供统一工具, 但工具本身仍需版本化; 数据 revision、模板与判分器变化都应触发新的结果版本。

**安全与能力不能共用一个代理指标。**

安全评测既包含拒绝危险请求, 也要避免对正常请求过度拒绝。单纯提高拒绝率可能让模型看似更安全, 实际可用性下降。能力任务上的强模型还可能更会理解和执行有害指令, 因而能力提升不保证安全同步提升。论文把安全作为独立评测维度, 是多目标后训练不可缺少的约束。

自动安全判分通常依赖分类器或评审模型, 它们也会受措辞、语言和长回答影响。可靠报告应结合多种攻击类型、正常请求对照与人工抽查, 并说明判分模型版本。对于开放权重模型, 系统提示并非稳定安全边界, 评测结论应描述模型在给定设置下的行为, 而不是宣称消除了风险。

## 4. 规模化结果、局限与复现路线

### 4.1. 从 8B、70B 到 405B 的缩放含义

将配方扩展到不同参数规模可以检验结论是否依赖单一模型。大模型通常生成更高质量的偏好候选, 也更容易从可验证奖励中探索到有效策略; 小模型则对数据噪声和格式负担更敏感。同一超参数未必在所有规模最优, 因为有效 batch、学习率、序列长度与 KL 约束的影响都会改变。

论文展示 405B 规模实验的意义在于验证流水线可扩展, 而不是证明参数越大即可机械复制全部设置。超大模型训练成本限制了完整消融, 因而很多设计仍来自较小模型。迁移时应区分被多规模验证的原则与只在单规模运行的配置, 避免把工程可行性误读为统计充分的最优性结论。

### 4.2. “无效实验”同样是开放配方的一部分

论文专门讨论未产生预期收益的尝试, 这对后训练研究很重要。只公开成功组合会造成幸存者偏差, 让后来者重复昂贵失败。负结果还能揭示交互效应: 某数据源单独有效, 混入现有配方后可能冗余; 某算法在小规模提升, 扩大 batch 或模型后可能消失。

不过无效并非永恒结论。它只针对特定基础模型、数据版本、预算与评测成立。复现者应记录实验上下文和置信区间, 而不是把一次无提升升级为普遍定律。开放日志最有价值的形式是提供可检验假设, 例如收益是否被数据重叠稀释、是否需要不同学习率, 让后续研究能有针对性地改变一个变量。

**最小可信复现应保存什么。**

完整复现需要固定基础模型、tokenizer 与聊天模板, 并保存每个数据源的 revision、许可证、过滤脚本、去污染阈值和混合权重. 生成数据还要记录生成模型、提示模板、采样参数和质量筛选器. 最终 JSON 只保留处理结果, 上述谱系信息才负责解释样本来源并在上游变化后重建训练集.

训练侧应记录 SFT、DPO、RLVR 每阶段的优化器、学习率调度、有效 batch、最大长度、截断策略、精度和随机种子。DPO 需固定参考模型和偏好损失定义; RLVR 需固定采样策略、奖励解析、优势估计与 KL 控制。每阶段输出独立 checkpoint 和完整评测, 才能判断提升来自哪里。

基础设施侧要对分布式数值一致性做测试。相同样本在单卡与多卡上的掩码、token 数和损失应一致; 恢复训练不能改变数据顺序; 在线生成与训练进程的模型版本必须同步。规模化系统中, 一个陈旧 worker 或错误 padding 就可能产生看似合理但不可复现的结果。

**方法的边界。**

Tülu 3 主要围绕英语开放模型和可获得的公开评测构建, 对多语言、长上下文、工具使用和多模态任务的覆盖有限。其偏好标签和评审过程也不可避免地带有生成模型与数据策划者的价值判断。开放数据提高可审计性, 却不能自动保证代表所有用户与文化。

此外, 基准提升并不等同于真实部署收益。自动验证任务偏向有明确答案的问题, 开放式事实核查、长期对话一致性和复杂代理行为仍难测量。训练数据公开后也可能进入未来模型预训练, 使同一评测随时间失效。因此配方应被视为可演进基线, 而不是封闭终点。

Tülu 3 最重要的启示是, 高质量后训练需要把数据、算法、基础设施与评测作为一个反馈循环共同设计。SFT 建立接口, DPO 塑造相对偏好, RLVR 提供在线可验证信号, 开发与未见评测则约束整个研发过程。开放这条链上的中间产物, 才让社区能够判断结果为何发生、在哪些条件下成立, 并在明确边界内继续改进。

## 5. 关键机制的进一步推演

### 5.1. 偏好数据质量取决于候选间的信息差

成对偏好样本并非只要有 chosen 和 rejected 两列就有效。若两个响应质量相近, 标注误差很容易翻转顺序, 梯度便主要学习评审器的随机波动; 若差距过大, 模型只能学到避免明显错误, 难以获得精细改进。理想样本应在同一核心任务上形成可解释差异, 例如推理完整但结论错误与推理、结论均正确, 或内容同样正确但指令约束遵循程度不同。

候选生成策略决定这种信息差。只由同一个低温模型生成, 响应可能过于相似; 混合不同模型和采样温度可增加多样性, 却也可能让模型身份、长度和措辞成为偏好捷径。数据审计应统计 chosen 与 rejected 的长度差、格式差和来源组合, 再检查偏好收益是否在控制这些表面因素后仍存在。否则 DPO 提升的可能只是“写得更长”或“使用某种固定开场”。

### 5.2. 可验证奖励需要区分结果验证与过程验证

结果验证只判断最终答案或测试用例是否通过, 实现便宜且客观, 但奖励稀疏并允许偶然命中。过程验证可以检查中间步骤、代码安全约束或指令执行轨迹, 信号更密集, 却需要更复杂且可能出错的验证器。Tülu 3 所展示的 RLVR 路线说明, 公开模型可以在无需大规模人工偏好的情况下继续提升, 同时也暴露了验证器覆盖范围就是优化边界。

实践中可组合多级奖励: 先验证输出是否可解析, 再验证硬约束, 末尾验证答案或程序行为。各级奖励应分别记录, 避免汇总标量掩盖模型只优化了最容易的一项。若格式奖励远比正确性奖励容易获得, 策略会先把所有输出塑造成合规外观, 但真实解题率停滞。对 reward、验证通过率、独立准确率和响应长度进行联合监控, 能更早识别这种错位。

**聊天模板是训练和评测共同的接口契约。**

聊天模板定义 system、user、assistant 消息如何编码, 何处插入起止 token, 以及训练损失覆盖哪些 token。模板不匹配会同时损害三个阶段: SFT 可能学习错误终止位置, DPO 的响应掩码可能包含提示, RLVR 采样也可能无法正确停止。模型权重相同但模板不同, 最终行为便可能显著不同, 因而模板必须与 tokenizer 一样被版本化。

评测时还要区分模型原生模板与统一模板。使用原生模板更贴近发布者推荐用法, 却把模板质量纳入模型比较; 使用统一模板控制变量更严格, 却可能让某些模型落在训练分布之外。可信报告可以把原生设置作为主结果, 同时选取关键任务做统一模板敏感性检查。至少不能为每个任务临时挑选得分最高的模板, 那会造成未报告的测试集调参。

**开放发布需要可追踪的数据谱系。**

数据集名称不足以标识真实训练输入。公开数据会修订、删除或改变许可证, 合成数据也可能由远程模型更新后产生不同响应。每条样本最好携带来源、上游样本 ID、处理步骤、生成器版本、质量标签和去污染结果。混合数据发布时, 还应给出从原始记录到最终训练序列的确定性构建脚本与内容哈希。

这样的谱系不仅服务复现, 也服务问题处置。若后来发现某来源包含隐私、错误许可或评测泄漏, 维护者可以定位受影响样本并重建新版本, 而不是废弃整个混合。模型卡则应关联具体数据版本和训练 commit, 让使用者知道两个同名 checkpoint 是否真的来自同一配方。

**公平比较必须核算训练与评测预算。**

后训练方法可能通过更多在线采样、更多评审模型调用或更长输出获得更高分。只比较最终准确率而不报告计算预算, 会把资源差异误认为算法效率。SFT 可报告训练 token 与 FLOPs, DPO 报告偏好对数和参考模型计算, RLVR 则还需报告生成 token、每题采样数、验证成本与策略更新步数。

评测预算同样重要。pass@k、best-of-n 或多次采样投票与单次贪心回答不是同一设置。推理模型通过产生更长思考链提升正确率时, 应同时给出 token 使用量与延迟。Tülu 3 的标准化工具为结果提供共同起点, 后续比较仍需把训练和推理预算纳入表格, 才能回答性能提升是否具有实际效率。

**数据混合是一组隐式任务权重。**

设第 $k$ 类数据分布为 $D_k$，混合权重为 $\alpha_k$，SFT 实际优化 $\sum_k\alpha_k\mathbb E_{D_k}[-\log\pi_\theta(y|x)]$。这里的 $\alpha_k$ 不只由样本条数决定，还受响应长度、重复采样和损失掩码影响。一万条长代码回答产生的梯度量，可能远大于一万条简短安全回答。论文中的混合比例必须结合token占比阅读，样本级百分比无法完整表示真实训练权重。

不同来源还会在同一提示上提出冲突行为：数学数据鼓励完整推导，通用聊天偏好直接回答，安全数据要求在特定边界拒绝。可解释的混合实验需要固定总token，只改变某一来源权重，并分别观察目标能力、邻近能力与总体退化。若数学分数和输出长度同时上升，还要用长度匹配评测区分推理收益与生成预算收益。

**SFT目标的能力边界。**

交叉熵逐token模仿参考响应，在答案唯一且质量稳定时很有效。开放任务存在多种正确表达，SFT却只提高数据中那条路径的概率；参考回答里的冗余、语气和偶然步骤也会被一起学习。它建立指令遵循、工具格式和基本推理，却无法表达「另一个答案也正确但稍差」或「结论正确但过程碰巧」。

长响应还会贡献更多预测位置。按token平均会让长样本占据更多梯度，按样本平均又可能放大极短回答。Tülu 3的数据策划实际上决定哪些行为先被模仿。SFT检查点是后续阶段的共同起点；若起点采样不到某类正确轨迹，DPO只能在现有候选附近重排，RLVR也难以获得有效正奖励。

**DPO目标与参考策略。**

对同一提示的胜者 $y_w$ 和败者 $y_l$，DPO比较策略相对参考模型的对数概率差。参考策略把更新锚定在SFT分布附近，温度系数控制偏好强度与偏离代价。这个目标学习成对排序，并不直接校准绝对质量：胜者和败者都很差时，模型仍会提高相对较好的一个。

偏好对若主要差在长度、语气或固定格式，模型会学到评审偏好而非能力。高价值样本让候选共享大部分内容，只在事实、推理、遵循或安全边界上形成清楚差异。难负例比一眼就能排除的坏答案更能刻画决策边界，也更容易检验DPO的增益来自哪里。

**从DPO进入RLVR。**

DPO提高高质量回答形态的概率，也让在线采样更容易出现可验证正确答案。RLVR随后在数学、代码等存在判定器的任务上，从当前策略采样并按结果更新。顺序的重要性来自探索：基础模型若频繁违反格式，验证器只能反复返回零；经过SFT与DPO后，更多候选落入「格式正确、答案有差异」的区域，奖励才具有区分度。

后阶段也可能覆盖前阶段能力。可验证任务集中在少数领域，持续RL会把概率质量推向适合判定器的输出形式，通用聊天、安全和知识任务可能退化。阶段检查点需要同时测量新增能力与遗忘，最终模型选择不能只看RLVR目标集的最高点。

**可验证奖励验证了哪一层。**

数学答案匹配、代码测试通过和格式解析分别验证不同层级。最终数字正确无法排除碰巧命中，公开测试通过无法保证隐藏输入正确，格式合规则只说明输出能被机器读取。各层奖励合成标量前，需要分别记录通过率，防止模型只优化最容易的一项。

判定器本身也定义训练任务。允许等价表达的数学规范化器比字符串匹配覆盖更广，代码沙箱的测试质量决定哪些错误会漏过。奖励的客观性只存在于规则覆盖范围内。能力迁移要由未参与训练的题型、不同验证器和人工分析确认，不能从训练通过率直接推出一般推理增强。

**阶段收益的消融矩阵。**

三阶段归因至少比较SFT、SFT+DPO、SFT+RLVR和完整链路。前两者观察偏好优化增量，第三个判断DPO是否属于在线训练的必要前置，完整链路检验两种目标是否互补。各条件要共享SFT起点、数据预算和评测协议；完整链路若使用更多token，收益中也包含计算增加。

分项结果同样重要。DPO可能改善指令遵循与风格，却轻微降低某些知识准确率；RLVR可能显著提高可验证推理，对开放问答帮助有限。平均分会让正负变化相互抵消。阶段检查点、任务分项和多个种子共同给出一致趋势，才能把变化可靠归到某个目标。

**从Tülu 2到Tülu 3。**

Tülu 2已经展示开放指令数据混合与偏好优化的价值，Tülu 3进一步把数据策划、标准化评测和可验证在线强化学习纳入同一配方。演进重点是让开发过程可比较，范围超出了简单增加数据：提示池如何筛选，候选响应如何生成，无效实验怎样记录，阶段检查点如何在统一套件上评估。

比较两代时仍要拆开底座、数据、算法和评测。基础模型更强时，最终提升不能全部归于后训练；评测套件更新后，也不能直接横比旧表格。最有解释力的证据是在同一底座和同一评测下复现关键阶段，再观察新数据与新目标各自贡献。开放配方的价值正在允许这种拆解。

**混合比例与梯度冲突。**

同一批次中的不同任务可能给共享参数相反梯度。增加某类数据，不只提高这类目标的出现频率，还会改变优化器动量与后续任务的有效更新方向。观察混合效果时，可以比较各子集梯度夹角、单任务损失和联合训练后的迁移矩阵。若数学数据增加后代码也改善，可能共享了规划与验证能力；若通用问答下降，则说明容量或行为风格发生竞争。

混合实验需要固定训练token和采样顺序的统计特征。单纯追加新数据让总预算上升，会把数据质量与训练时长混在一起。替换实验则回答更清楚的问题：在相同预算下，用新来源替换哪一类旧来源，哪些指标随之变化。多组比例构成剂量曲线，比只比较有无某数据更能发现收益饱和与副作用起点。

**合成响应的教师效应。**

提示可以来自真实用户或人工策划，响应却常由更强模型生成。教师决定答案结构、措辞、拒答边界和推理习惯，学生可能复制这些特征。若多个数据源共享同一教师，表面上的来源多样性并不等于行为多样性。训练记录需要把提示来源与响应生成器分别标识，并对教师版本、采样参数和系统提示留档。

教师正确率也不是唯一质量维度。一个答案事实正确，却可能过长、依赖不可见工具或包含学生无法稳定复现的推理跳步。过滤时应检查可学习性：给定公开上下文，学生是否拥有产生答案所需信息；若没有，SFT会鼓励凭空断言。多教师候选加验证器筛选可以减少单一风格，但筛选器又会引入自己的偏好。

**响应选择改变监督分布。**

为一个提示生成多条候选后选最高分响应，相当于在教师分布上做best-of-n。候选数越大，被选答案越可能符合评审器，却也越偏离教师自然采样分布。学生学到的是经过搜索后的上尾样本，部署时单次生成未必能复现同等质量。因而报告数据生成时需要包含候选数和选择规则。

选择还可能降低多样性。评审器若稳定偏爱某种篇幅或格式，不同提示最终都留下相似答案。保留若干质量接近但路径不同的候选，或按能力类型设置筛选标准，可以维持覆盖。数据质量应同时观察正确性、风格熵、长度分布和答案间结构重复，不能只看教师打分均值。

**去污染的时间边界。**

评测污染不只来自训练文本包含完整题目。题目改写、参考答案、解题博客和同模板变体都可能泄漏。基于字符串n-gram的过滤擅长发现逐字重合，语义近邻可以发现改写，却也会误删同主题正常知识。高风险基准需要结合题目标识、来源时间和人工复核，并公开过滤阈值。

时间切分提供另一种证据：使用数据构建完成后才发布的题目，能减少直接记忆解释。但基础模型预训练截止、教师模型知识和在线工具仍可能不同，因此时间外推也不是绝对无污染。更稳妥的报告同时给已知基准、受控改写和真正新题，并比较有无工具、不同提示下的稳定性。

**DPO中的长度偏差。**

序列对数概率是token项之和，长短回答的概率尺度不同。偏好数据若经常选择较长答案，DPO可能把长度当作胜者特征；反过来，参考模型对长序列累计更低概率，也会影响隐式奖励。可以按长度差分层报告胜率，构造内容相同但篇幅不同的控制对，并观察训练后输出长度变化。

长度本身有时承载真实质量，复杂推导确实需要更多步骤，因此不能简单惩罚长答案。关键是让偏好标签来自事实、推理和遵循差异，并在统计中控制长度。若去掉长度差后偏好准确率明显下降，说明数据或评审器依赖表面代理，后续RL阶段也可能继承这一偏置。

**DPO的隐式奖励。**

DPO最优解可以联系到KL约束奖励最大化：策略相对参考策略的对数比承载隐式奖励。对某响应而言，$r_\theta(x,y)=\beta\log[\pi_\theta(y|x)/\pi_{ref}(y|x)]$。成对损失推动胜者与败者的隐式奖励差增大，同时参考策略限制整体漂移。

这个解释依赖偏好由某个一致奖励模型产生等假设。真实标注混合事实、风格与安全判断，存在循环偏好和噪声，单一标量无法完美表示。DPO仍可作为有效分类目标，但概率差不应被误读成绝对人类效用。对互相矛盾的偏好对、同分候选和跨领域标注者，需要单独检查稳定性。

**参考模型选择。**

参考模型通常取SFT检查点，它定义策略允许偏离的中心。若参考模型很弱，保持接近会限制改进；若已经很强，偏好对的差异可能很小。固定参考与训练过程中更新参考会产生不同目标：前者坐标稳定，后者可能让策略逐步远离初始分布，却难以比较不同时间的隐式奖励。

消融应保持偏好数据不变，只替换参考模型，观察胜率、KL、长度与基础能力。参考模型还需使用完全相同的聊天模板和tokenizer，否则概率比混入编码差异。部署者只保留最终权重时容易忽略这一依赖，但复现DPO轨迹必须保留参考检查点。

**可验证奖励的稀疏性。**

只有最终答案奖励时，大量错误轨迹都得到零分。模型无法区分接近正确、方向正确但计算失误、以及完全无关的回答。组内采样能够通过少数成功样本提供相对信号，但当成功率接近零时，优势方差消失。SFT和DPO提升初始成功率，正是在缓解这个探索问题。

可加入格式、局部测试或子答案奖励提高密度，但每项都改变目标。局部奖励若与最终正确性不一致，模型会停在容易拿分的中间状态。设计时需要测量各奖励分量与独立正确率的相关性，并观察移除某项后的行为。密集反馈的价值是引导探索，最终仍由完整任务验证器决定是否成功。

### 奖励归一化与组内优势。

在同一提示的多个采样中，用组均值和方差标准化奖励，可以降低不同题目难度尺度的影响。若一组全部正确或全部错误，标准化后没有有效差异；若只有一个偶然通过，更新可能过度依赖该样本。组大小、采样温度和题目难度共同决定信号质量。

奖励离散时，大量并列也会降低效率。可以优先抽取当前成功率居中的问题，或增加能区分部分正确的可靠检查，但不能用主观过程分替代硬验证而不报告。按提示归一化还意味着难题的一次成功与易题的一次成功可能贡献相近，需要通过数据采样权重控制训练关注点。

**KL约束与能力保持。**

在线强化学习提高目标奖励时，策略可能迅速远离已有语言能力。KL惩罚限制分布漂移，其作用类似让模型在新目标与旧行为间权衡。系数太大，奖励提升缓慢；系数太小，模型可能形成特殊格式、变长输出或遗忘通用能力。最优系数取决于任务混合和SFT起点，不能从单一任务直接迁移。

KL数值也要按token位置分析。少量关键推理token发生变化可能带来正确答案，整段固定模板变化则不一定有能力价值。只报告平均KL无法判断漂移发生在哪。配合响应长度、词汇分布和通用基准，可以区分有用探索与整体语言退化。

**RLVR向非可验证任务迁移。**

数学与代码训练可能提高分解、检查和长程规划，进而帮助某些开放任务；也可能只让模型更常输出长推理，对知识问答没有帮助。迁移成立需要在未使用相同判定器、题型和模板的任务上观察增益，并控制生成token。若只在相似竞赛题上提升，更准确的结论是域内泛化。

负迁移同样重要。模型可能在简单问题上过度推理，在聊天任务中输出不必要步骤，或对无法验证的问题表现过度自信。按任务类别比较SFT、DPO和RLVR检查点，可以看出能力何时出现、何时被覆盖。平均分上涨不能抵消某个关键能力的大幅回退。

**代码奖励的测试充分性。**

代码题以单元测试作验证器，测试只覆盖有限输入。模型可以生成对公开样例硬编码、依赖未声明库或利用沙箱漏洞的程序。隐藏测试减少直接投机，却仍可能漏掉边界条件。测试通过代表程序满足当前测试集合，并不等价于完整规格正确。

高质量训练题需要属性测试、随机输入、资源限制和安全隔离。失败类型也应区分编译错误、运行时错误、超时和答案错误，它们反映不同能力。若训练奖励只给二值结果，分析仍可保留这些标签，以判断提升来自格式可执行性还是算法正确性。

**数学奖励的等价表达。**

数学答案可能以分数、小数、集合、区间或符号表达。字符串比较会把等价答案判错，过度宽松的符号化简又可能接受未定义或附带错误条件的表达。验证器需要解析最终答案、标准化形式并检查变量假设；推导题还要区分只需结果与要求证明的任务。

模型可能学会把多个候选答案都写进结尾，提高其中一个被解析命中的概率。解析规则应要求唯一明确答案，并对额外矛盾陈述做处理。奖励器版本必须固定，因为规范化规则升级会改变同一轨迹的得分，进而破坏训练曲线可比性。

**安全对齐与能力数据的交互。**

安全偏好常包含拒答与安全改写，能力数据则奖励尽量完成任务。若危险请求在能力集中缺少标签，模型可能把详细回答视为普遍优质；若安全数据权重过高，又可能对无害的相似主题过度拒绝。数据混合需要覆盖边界对：表面词汇相似，但意图、上下文或可操作性不同。

安全评测要同时测量有害请求拒答和无害请求正常完成。只看拒答率会奖励一律拒绝，只看帮助性又忽略风险。DPO适合学习这种成对边界，前提是胜负标签细致；RLVR的硬验证任务若长期不含安全样本，还需在训练后检查安全能力是否漂移。

**评测选择也是训练决策。**

开发团队根据评测选择数据比例、超参数和checkpoint，评测集因而间接进入训练循环。即使样本从未用于梯度，反复观察分数也会造成开发过拟合。调试集可以频繁使用，模型选择集限制查询次数，最终未见集只在配方冻结后运行，三层职责需要明确。

指标数量增加也会产生选择空间。若每次只报告改善的子集，偶然波动会被当成进展。预先规定主指标、能力分组和回退阈值，并保存所有实验，包括失败条件，能减少这种偏差。Tülu 3公开无效实验的意义就在于让最终配方的选择路径可见。

**宏平均的隐藏权重。**

把多个基准取平均，看似让每项同权，实际每个基准内部题目数、分数范围和方差不同。一个小型高噪声基准可能与大型稳定基准拥有相同权重，分数尺度较宽的任务又会主导变化。报告宏平均时，应同时给原始分项、置信区间和归一化方式。

模型选择若直接最大化宏平均，会隐式接受这套权重。针对通用助手，更合理的是先定义能力簇，再在簇内聚合，防止同类数学基准重复计权。不同合理聚合下结论是否稳定，也是结果稳健性的一部分。

**基础模型差异与后训练收益。**

同一配方应用于8B、70B与405B模型时，收益不会线性复制。大模型初始遵循和推理更强，SFT边际收益可能较小，却能从更难偏好对和稀疏RL奖励中获益；小模型受容量限制，过复杂的教师响应可能难以学习。数据和超参数需要随规模调整。

比较绝对终点会把底座能力与后训练混合。阶段增量、相对错误减少和能力分项更能说明配方是否随规模迁移。若只有最大模型受益，方法可能依赖高起点探索；若小模型提升更大但终点仍低，则说明配方主要修复行为接口。

### 随机种子与选择偏差。

后训练数据有限、在线采样随机，单次运行差异可能明显。只发布最佳seed会高估稳定收益，尤其当开发过程尝试很多超参数。至少对关键消融运行多个seed，报告均值、范围和每步曲线；昂贵大模型无法重复时，也可在小规模验证方差，并对大模型结论保持克制。

checkpoint选择也是随机性来源。从同一条噪声曲线挑最高点，会产生赢家偏差。使用平滑开发指标、预定停止规则，并在独立集合复评候选，可以减少偶然峰值影响。最终模型的选择准则应与论文主张一致，不能先看所有测试结果再决定。

**一手论文与发布资产的对应。**

论文描述研究问题、配方和消融，代码仓库给出数据处理与训练实现，模型卡记录具体checkpoint和推荐模板，数据卡说明来源与许可。四类材料回答不同问题，互相引用才能形成完整证据链。仓库后续更新的默认值不能反向当成论文实验设置，模型卡中的最终配方也未必覆盖所有消融条件。

复核某个数字时，应定位对应表格、模型版本、评测提交和生成参数。若公开资产缺少某段链路，就明确复现范围。开放的价值体现在差异能够被发现、追踪和修正；公开材料本身不会自动保持一致。

**失败实验如何支持归因。**

某种数据混合无增益、某个奖励模型导致退化、某段RL训练不稳定，这些结果界定了有效配方的边界。只展示成功组合会让读者无法判断最终选择来自系统搜索还是偶然尝试。失败实验至少记录改变项、预算、主要分项和停止原因。

失败结论也要受条件限制。一次8B短跑无效，不代表方法在更大模型或更长预算下必然无效；训练发散可能来自超参数而非目标本身。将观察与解释分开，并提供可比较对照，负结果才能成为后续研究的有效证据。

**SFT梯度如何受响应长度影响。**

设样本 $i$ 的有效响应token数为 $L_i$。若整个批次按token平均，损失为 $\sum_i\sum_{t=1}^{L_i}\ell_{it}/\sum_iL_i$，长回答自然获得更多总权重；若先对每条样本平均再对样本平均，则每条提示权重相同，短回答中的单个token影响更大。两种归约都合理，却对应不同的数据混合语义。

多来源训练还会叠加来源权重。最终权重可写成来源采样概率、样本权重和token归约的乘积。只公布数据条数，无法重建真实目标。尤其代码、数学推导和安全拒答长度差异很大，归约选择可能改变能力权衡。复现实验需要保存损失掩码、批次构造与归约方式。

**参数更新中的任务干扰。**

对两个任务损失 $L_a,L_b$，梯度内积 $\langle g_a,g_b\rangle$ 为正时局部更新相互促进，为负时存在冲突。这个量不会直接决定最终迁移，却能解释为什么增加高质量数据仍可能损伤另一能力。冲突还会随训练阶段变化：早期共享格式学习可能一致，后期专业行为逐渐分叉。

实际分析可在固定检查点对各数据源取小批次，计算梯度余弦和范数，再与混合消融对应。若某来源梯度范数极大，它即使采样比例不高也可能主导更新。调整学习率、来源权重或交替批次都能改变相互作用，但每种处理都应由能力矩阵验证，不能只凭梯度统计下结论。

**数据质量与数据难度。**

高质量通常指正确、相关、清晰和安全，难度则描述当前模型生成正确回答的概率。质量高但过难的教师答案，可能包含模型尚未掌握的多步跳跃；质量一般但难度适中的样本，反而能提供稳定学习信号。课程设计需要同时估计两者，避免把教师评分直接当作训练价值。

一种可检验方法是记录样本训练前损失、训练后损失下降与独立任务迁移。极低损失样本已被模型掌握，重复训练收益有限；极高损失可能是噪声或能力跨度过大。中间区间常提供更丰富梯度，但不同能力的最佳区间不同。数据路由由此成为动态过程，而非一次性清洗。

**偏好标注的传递性。**

DPO隐含假设胜负关系能够由相对稳定的效用解释，但真实偏好可能出现循环：A比B事实更准，B比C更简洁，C又因更安全胜过A。若把三对同时压进单一标量，模型只能寻找折中，结果受样本频率与温度影响。循环并不一定是标注错误，它可能暴露多个未分离维度。

数据分析应按事实、遵循、风格和安全拆分偏好理由，检查同一维度内部的一致性。对于维度间权衡，可以根据任务条件决定优先级，或保留多属性标签。这样能解释DPO更新究竟推高什么行为，也避免将所有分歧归为噪声。

**DPO梯度的饱和。**

令偏好间隔为 $z=\beta[(\log\pi_\theta(y_w)-\log\pi_\theta(y_l))-(\log\pi_{ref}(y_w)-\log\pi_{ref}(y_l))]$，损失 $-\log\sigma(z)$ 对 $z$ 的导数为 $\sigma(z)-1$。当模型已强烈偏好胜者，梯度趋近零；当它偏好败者，更新幅度较大。这让训练自动关注尚未学会的偏好对。

但错误标签也会因此获得很大梯度，因为模型原有判断与标签相反。对高损失样本抽查，能够发现标注错误、模板错位和真正困难的边界。盲目提高 $\beta$ 会让间隔更快饱和，也可能放大噪声。温度、学习率与偏好数据质量需要联合选择。

**离线偏好覆盖。**

DPO只在数据出现的响应之间学习。若部署策略产生全新失败模式，离线集合没有直接比较信号。覆盖可以从两个方向测量：新策略回答与训练候选的分布距离，以及评审器在新回答上的不确定度。距离增加并不必然有害，但意味着离线归因开始变弱。

迭代生成新候选、重新标注并继续偏好训练，可以缩小分布差；在线RLVR则直接在当前策略采样。Tülu 3把二者串联，等于先用广泛人类或模型偏好塑形，再在可硬验证区域在线纠错。该设计仍把非可验证开放任务留在离线反馈范围内。

**RLVR目标的期望形式。**

对提示 $x\sim D$、轨迹 $y\sim\pi_\theta$ 和验证奖励 $R(x,y)$，基本目标是最大化 $J(\theta)=\mathbb E[R]$。策略梯度为 $\mathbb E[(R-b)\nabla_\theta\log\pi_\theta(y|x)]$，基线 $b$ 不改变期望，却降低方差。组内相对奖励可视为用同题其他采样估计基线。

该梯度把最终奖励分配给轨迹中所有模型token。成功答案里的无关步骤也会被提高，失败答案里的有用前缀也会被压低。大量采样能在统计上缓解误分配，却不能消除。可靠过程验证若存在，可以为局部动作提供信号；缺乏可靠过程标签时，保持结果奖励反而避免引入更强主观偏差。

### 熵与探索。

策略分布过早尖锐化后，多次采样得到相似答案，组内奖励方差下降，训练难以发现新解。熵奖励、较高采样温度或更大的组可以维持探索，但也会增加无效轨迹。探索强度应随成功率调整：早期需要更多多样性，出现稳定正确路径后再逐步收敛。

输出多样性不能只用表面文本衡量。十条措辞不同但算法相同的答案，提供的探索仍很有限。可以比较最终答案、程序结构、推理关键步骤和错误类型。若熵上升只带来语言变化，没有带来解法变化，它不会显著改善可验证奖励。

**验证器假阴性与假阳性。**

假阴性把正确答案判错，降低有效样本率；假阳性把错误答案判对，会直接强化漏洞。二者危害不对称：少量假阳性可能被策略主动寻找并放大，形成奖励投机。因此验证器设计通常宁愿对无法解析的边界样本保守处理，也要持续用对抗样本寻找误接受路径。

估计误差需要人工抽查通过与未通过样本，并按模型版本重复。策略更新后，错误分布会变化，旧验证集上的低误差不能保证长期安全。保存验证器版本与判定细节，才能解释某段奖励突然上升究竟来自能力改善还是新漏洞。

**奖励尺度与多任务训练。**

数学奖励可能是0/1，代码奖励可能包含部分测试比例，格式奖励又是另一范围。直接相加会让尺度大的任务主导梯度。归一化可以统一方差，却可能让极噪声的小任务被放大。更合理的权重需结合验证器可信度、任务重要性和学习进展。

多任务RL还要考虑每类提示采样率。最终贡献近似为采样概率、奖励尺度与优势方差的乘积。报告一个总奖励无法重建这个目标。分任务曲线能显示模型是否真正同时进步，还是用某个容易任务补偿其他任务下降。

**在线训练中的旧策略数据。**

采样和更新并行时，一条轨迹可能由较旧参数生成。策略变化缓慢时影响有限，变化快速时则出现分布偏离。重要性比率可以校正，但长序列概率比容易产生高方差，因此实现常限制策略延迟或裁剪比率。异步效率与目标准确性需要权衡。

记录每条轨迹的生成策略版本，就能按延迟分层观察奖励和更新贡献。若高延迟样本显著偏低或导致不稳定，可以缩短队列、降低更新速度或丢弃过旧数据。这类系统选择会改变实际算法，论文复现不能只记录名义上的RL方法。

**阶段顺序的反事实。**

SFT→DPO→RLVR具有直观课程结构，但顺序优势仍需反事实验证。SFT后直接RLVR可判断偏好阶段对探索和能力保持的作用；RLVR后再DPO可观察离线偏好能否修复在线训练产生的风格与安全漂移；交替训练则检验两类信号是否需要持续平衡。

顺序比较必须控制各阶段token和总更新量。若末阶段总是最接近评测分布，它可能因新近效应占优。还应从多个中间checkpoint开始，排除某次随机初始化差异。最终选择若来自综合能力，而非单一RL任务峰值，三阶段叙事才得到充分支持。

**能力保持的回放数据。**

RLVR期间混入少量SFT或偏好数据，可以约束通用行为遗忘。回放比例太低无法抵抗漂移，太高又稀释在线奖励。它相当于同时优化新目标与旧分布正则，比单一KL更直接地指定需要保留的行为。

回放集应覆盖最易退化的能力，而非随机抽样全部旧数据。简短问答、拒答边界、工具格式和多轮遵循可能需要不同权重。通过阶段消融比较无回放、随机回放和定向回放，能判断能力保持来自数据还是仅来自较小更新幅度。

**评测提示敏感性。**

同一模型在零样本、少样本、系统提示和聊天模板变化下可能得到不同分数。后训练模型尤其会响应格式要求，某个提示更接近其训练分布时优势扩大。公平比较需要预先固定提示，并对关键结论做有限敏感性分析，而非为每个模型挑最佳模板。

敏感性本身也是能力指标。若轻微措辞变化导致大幅波动，模型的指令理解仍不稳定。报告平均性能之外，可以给提示变体方差。Tülu 3依靠标准化评测降低比较噪声，但标准化协议不能代表全部真实交互。

**生成长度与pass@k。**

增加最大生成token或采样次数通常提高找到正确答案的机会。pass@k衡量多次采样至少一次成功，与单次部署质量不同；best-of-n还依赖额外选择器。后训练比较必须对齐 $k$、温度、长度上限和停止条件，否则推理预算差异会伪装成模型能力差异。

RLVR模型可能学会更长的思考链，因此在固定token预算下优势与不限长度时不同。画出准确率随生成token和采样数的曲线，比单个点更能说明效率。若新模型只在大预算下领先，部署价值与算法解释都需要相应调整。

**评审模型与硬验证器的分工。**

硬验证器适合答案可执行或可规范化的任务，评审模型适合开放写作、帮助性和风格。前者精确但覆盖窄，后者覆盖广却有偏差。将两者混合时，应保留分项而非让评审分遮盖硬错误。例如代码未通过测试时，文字解释再好也不能被整体高分抵消。

评审模型还可能与生成数据的教师同源，形成家族偏好。异构评审、人工子集和规则检查能提供独立性。Tülu 3的RLVR贡献应主要由硬验证任务支持，开放能力的变化则依靠标准基准和人工判断，证据类型需要对应主张。

**数据许可证与可复现边界。**

开放配方使用的上游数据可能允许研究使用，却限制再分发；远程教师响应也可能受服务条款约束。无法发布原始样本时，研究者至少可提供来源清单、转换脚本、内容哈希和统计摘要。否则「开放混合」只有名称，外部团队无法确认真实输入。

删除请求或许可证变化会产生新数据版本。旧模型仍由历史数据训练，模型卡需保留当时状态；新训练则使用修订快照。版本差异可能改变分数，不能把后续重建数据视为原实验的完全等价替代。

### 训练集与评测集的模板重合。

即使具体题目不同，共享固定模板也会让模型学习评测接口。例如大量「答案放在方框中」的训练题会直接提高某数学解析器通过率。这个提升部分属于遵循能力，部分属于基准格式适配。改变答案标记、问题顺序或表述，可以测量结果对模板的依赖。

模板去重不能删除所有同类任务，否则也会删掉合理训练信号。更有用的是分别报告原模板与改写模板，并检查推理内容是否稳定。若正确率只在熟悉格式上高，能力外推应保持谨慎。

**数据混合的沙普利视角。**

某个来源的贡献依赖其他来源，单次移除无法完整表示交互。理想情况下可在多个子集组合上训练，用类似Shapley值的平均边际贡献估计每个来源。但来源多时组合数量指数增长，完整计算不可行。

实践可选关键来源做成对与三方消融，重点检查预期互补或冲突的数据。小模型筛选组合，再在大模型验证少数候选，也能降低成本。所得贡献仍受模型规模和预算限制，不能把某次排序当成永久数据价值表。

**能力迁移的中介变量。**

RLVR后开放任务提升，可能由更强推理、更多输出token、更稳定格式或更高采样熵间接造成。要识别中介，可以固定长度重评、强制统一格式、比较隐藏思考关闭与开启、并分析错误类型。若控制这些变量后收益仍在，才更接近一般推理迁移。

同样，DPO带来的安全提升可能由拒答率整体增加，而非边界判断更准。配对的有害与无害请求能区分。机制归因需要把抽象能力拆成可观察行为，再设计控制实验，不能仅凭任务名称推断。

**污染对消融的非均匀影响。**

训练污染不会平均抬高所有检查点。SFT直接见到相似答案时受益最大，DPO若偏好对包含基准风格会进一步强化，RLVR又可能利用解析器模板。污染因此会夸大阶段增量，而非只提高统一起点。每阶段数据都需要独立检查与评测重合。

若无法排除污染，可以比较受影响题与干净题、原题与语义改写、记忆型与组合型子集。结果在干净子集仍成立，结论才稳健。披露疑似重合比简单宣布「已去污染」更有信息，因为任何过滤器都有漏检和误删。

**复现所需的最小状态。**

数据清单与哈希确定输入，模型和参考模型checkpoint确定起点，聊天模板和tokenizer确定编码，阶段配置确定目标，随机种子与批次顺序影响轨迹，验证器版本决定奖励，评测提交记录终点。缺少其中任一项，都可能产生可运行却不等价的复现。

在线阶段还需保存采样参数、每题候选数、奖励分项和策略版本。完整发布不一定包含所有巨大轨迹，但应提供足够样本与汇总，允许外部核对实现。将这些对象连接到模型卡，才能从最终权重追溯到具体配方。

**结果结论的层级。**

单次基准提升证明特定设置下表现更好；多seed和多基准支持稳定性；未见模板、时间外题与不同验证器支持迁移；真实用户盲评再补充部署有效性。证据层级逐步增强，不能跳过中间层直接宣称通用后训练已经解决。

Tülu 3最扎实的贡献是公开一条从数据策划、SFT、偏好优化到可验证强化学习的完整路线，并用标准评测与失败实验展示选择依据。它为开放研究提供可拆解基线。每项增益仍绑定到底座、数据、奖励器和预算，后来者应沿这些变量继续验证，而非把三阶段顺序当成无需检验的固定配方。

**三阶段共享的概率对象。**

SFT、DPO与RLVR都在调整条件分布 $\pi_\theta(y|x)$，差别在于数据从哪里来、好坏如何定义。SFT用固定参考响应提供逐token目标；DPO用固定候选之间的相对偏好约束概率比；RLVR从当前策略采样，再由验证器给整条响应赋值。三者由离线模仿逐步走向在线探索，监督信号也从密集变稀疏。

这种统一视角能解释阶段衔接。SFT先把概率质量放到合法回答区域，DPO把其中更符合偏好的区域抬高，RLVR再搜索当前分布附近能够通过硬验证的解。任何阶段覆盖不足，后续阶段都可能受限：合法区域过窄会减少探索，偏好数据偏置会改变起点，验证器漏洞则会把概率推向错误方向。

**目标函数之间的尺度。**

三阶段损失数值不能直接比较。SFT交叉熵按token累计，DPO损失按偏好对计算，RLVR梯度由奖励优势缩放。即使学习率相同，每步参数变化也可能相差很大。阶段切换需要观察梯度范数、参数位移、KL和能力曲线，而非沿用一个表面统一的学习率。

若RLVR更新幅度过大，前两阶段建立的行为会迅速丢失；幅度过小，又只能在局部微调。参数位移可按层分析，查看变化集中在输出头、高层语义表示还是全网。它不能单独证明能力来源，却能发现某阶段是否实际上覆盖了先前训练。

**数据配比的有效token口径。**

样本经过截断、packing和响应掩码后，进入损失的token数与原始长度不同。一个长对话可能只有末尾一轮assistant消息参与训练，一段代码样本则几乎全部响应都计入损失。有效token占比因此比磁盘大小或样本数更接近训练权重。

packing还会改变批次组成。若长样本经常单独占据序列，短样本则被多条拼接，它们的梯度方差和上下文边界分布不同。数据混合报告应至少给来源级样本数、原始token、有效响应token、截断率与平均长度。这些统计能解释复现者使用相同数据名称却得到不同结果的原因。

**多轮对话的损失掩码。**

多轮数据可以只监督末尾一轮，也可监督所有assistant轮次。前者强调根据完整历史生成最终答复，前面的assistant文本成为条件；后者让每轮都贡献梯度，更充分利用数据，却可能重复强化早期低质量回复。system和user token通常不计损失，但它们决定上下文与行为边界。

若不同数据源采用不同掩码，混合权重会进一步变化。工具调用数据还需决定调用参数、工具观察和最终回答哪些位置属于模型动作。掩码错误可能让模型学习复现环境返回，或完全忽略查询生成。小批次逐token可视化比只看总loss更容易发现这类问题。

### 偏好对的采样机制。

偏好对可以来自同一策略的多次采样，也可以把强教师回答与弱模型回答配对。前者候选接近，提供细微但困难的边界；后者差距大，标签可靠却容易让模型只学表面特征。混合两类对时，需要分别报告胜率和损失，避免大量容易样本掩盖难样本无进展。

候选生成温度也影响学习内容。低温样本相似，差异多集中在局部错误；高温样本多样，却可能充满格式失败。数据构建可以按提示难度调整采样，并保存候选全集。只发布胜负结果会丢失选择过程，也无法重新审查评审偏差。

**偏好标签的不确定度。**

两个回答质量接近时，强制二选一会把微小或随机差异放大。标注者分歧、评审概率或平局标签可以表达不确定度。训练时降低低置信对权重，通常比把它们当作确定胜负更稳健。尤其在风格问题上，用户偏好本来就可能多峰。

不确定度还帮助分析数据价值。高置信容易对适合冷启动，低置信难对刻画决策边界，但需要更多复核。若模型在高分段仍持续提高偏好间隔，可能正在过拟合标签噪声。校准集可以检查隐式奖励差与真实胜率是否对应。

**奖励与答案概率的脱节。**

RLVR优化期望奖励，不保证模型给所有正确答案高概率。它可能集中在一种稳定可验证解法，降低其他同样正确路径的概率。基准准确率提高的同时，解法多样性可能下降。这对需要创造性或多方案比较的任务未必有利。

可在同题多次采样中统计正确解法簇、答案熵与失败类型，观察训练后是否只剩单一路径。保留探索熵、混入SFT回放或使用多样化提示能缓解坍缩。评价应根据部署目标决定稳定单解和多样解法的权衡。

**部分正确奖励的风险。**

数学分步和代码子测试可以提供部分分，降低稀疏性。但子目标若不完备，模型可能优化局部检查而忽略整体。例如通过大多数常见测试却绕开边界，或写出若干正确等式却未完成证明。部分奖励必须与最终通过联合，并检查它对最终成功的预测关系。

权重过高时，模型会偏向容易获得的步骤；权重过低时，又无法帮助探索。课程式权重可以早期强调局部进展，后期逐渐提高完整正确的比例。每次变化都改变训练目标，需要在曲线上标记，防止把奖励设计变化误认为能力突然增长。

**隐藏测试与训练可审计性。**

隐藏测试减少针对公开样例的硬编码，但也让外部研究者难以核实奖励。开放研究可以发布测试生成逻辑、覆盖类别和独立审计结果，同时保留具体用例，或在训练结束后释放历史版本。这样兼顾抗投机与复现。

若验证器依赖私有测试，模型权重虽开放，训练目标仍有不可见部分。论文结论应明确这一边界。替代复现使用另一组测试时，得到相似趋势比逐步奖励一致更有意义，因为它验证了算法对具体测试集合的稳健性。

**训练集正确率的选择效应。**

在线RL会反复看到同一提示分布，模型可能记住特定答案或验证器模式。训练奖励上升既可能来自一般解题能力，也可能来自提示级记忆。保留完全未见提示、同结构新数值题和不同表述变体，可以逐层区分记忆、模板迁移与真正方法迁移。

若原题提升大而结构变体小，继续增加RL步数只会加深专门化。此时扩大提示生成分布或加入程序化变体更有效。训练曲线应同时绘制在线提示和冻结变体集，后者开始下降时可作为停止信号。

**数据生成模型的污染。**

教师模型可能已经见过评测题，即使最终学生数据不含原题，教师生成的解法风格和关键答案仍可能传播。仅对学生训练文本做去重无法排除这条路径。使用多个教师、时间外题和程序化新题，可以降低对单一教师记忆的依赖。

教师用于评审偏好时也存在类似问题：它可能对熟悉题给出更准标签，对陌生领域依赖表面线索。按题目发布时间、领域和教师置信分层，能够发现这种不均匀性。模型蒸馏效果需要与教师已知能力边界一起解释。

**OLMES的可比性作用。**

标准化评测固定提示格式、解码参数、答案抽取和指标实现，减少不同团队脚本差异。它让阶段检查点可以沿同一尺度比较，也能将Tülu系列与其他开放模型放到更一致的条件下。标准化特别重要，因为后训练模型对模板与答案解析高度敏感。

标准化仍不能消除基准自身限制。题目可能饱和、污染或只覆盖单轮能力，统一设置也可能偏离某模型推荐用法。因此OLMES提供可复现坐标系，而非完整能力定义。论文中的分数应与任务构成、生成预算和污染分析一起阅读。

**安全评测的基率问题。**

安全集合中有害与无害请求比例会影响总体准确率。现实流量若绝大多数无害，轻微过拒绝就可能影响大量用户；专门红队集则有害样本比例很高，更适合测防御上限。两个场景不能用同一总分概括。

报告应分开真实正例率与真实负例率，并按危害类别观察。阈值调整会在帮助性和拒答间移动，偏好训练实际上也在选择这个阈值。模型规模或阶段比较时，只有整条权衡曲线优于旧模型，才能说明安全与能力同时改善。

**校准与选择性回答。**

模型可以在不确定时拒答或给出限定条件。若评测强制每题作答，可能奖励猜测；若拒答无成本，又会鼓励保守。选择性准确率把覆盖率与已回答样本正确率联合展示，适合观察后训练是否改善自知之明。

可验证任务中，模型通常无法在生成时直接看到验证结果，但可以根据内部不确定性决定是否继续推理。DPO数据若总把自信长答案选为胜者，可能损害校准。加入证据不足时的优质保留回答，能让偏好目标学习更合理的确定性边界。

### 消融中的预算守恒。

移除DPO后直接进入RLVR，会减少训练token和计算；若结果变差，原因可能是缺少偏好目标，也可能只是总训练不足。严格对照可用额外SFT或等量RL步骤填补预算，再比较。反过来，保持步数却更换数据，也要注意不同序列长度导致实际token变化。

预算守恒不只包含FLOPs，还包括候选生成和评审调用。某种数据筛选若使用更多教师采样，其优势部分来自更大搜索。将固定计算、固定样本与固定质量三种对照分开，能回答算法效率和最佳性能两个不同问题。

**交互效应与主效应。**

假设SFT数据改进带来增益 $a$，DPO带来 $b$，完整组合提升未必等于 $a+b$。若组合大于两者之和，可能存在互补：更好的SFT起点让偏好数据更有效；小于则说明目标重叠或冲突。二乘二消融可以估计主效应与交互效应。

三阶段完整析因实验成本很高，可先在小模型和短预算上筛选，再验证关键交互。小规模结论能否外推仍需检查，因为探索成功率随模型规模变化。至少报告若干关键组合，远比只展示逐步累计分数更有因果解释力。

**Checkpoint平均与阶段选择。**

训练末端奖励波动时，可以平均邻近checkpoint权重或按开发集选择单点。权重平均可能提高稳定性，却也混合不同策略分布；若跨阶段平均，甚至会模糊SFT、DPO与RLVR的贡献。发布时要说明最终权重是否经过平均以及包含哪些步。

选择规则也影响结果。针对综合能力选出的checkpoint，可能不是RLVR奖励最高点，这恰好说明单一训练指标不足。预先定义能力权重和最大允许回退，可以让选择更透明。测试集只用于最终报告，不能参与挑点。

**误差类型比总分更接近机制。**

数学错误可分为理解题意、选择方法、代数计算和答案格式；代码错误可分为算法、边界、复杂度与执行环境；指令任务又有遗漏约束、事实错误和风格问题。阶段对这些错误的影响不同。SFT常减少格式和遵循错误，DPO改善偏好边界，RLVR更直接压低能被验证器捕获的结果错误。

若总分提高但错误类型未按预期变化，机制解释需要重审。例如RLVR只减少格式错误，说明奖励器可能过度依赖解析；DPO若只增加长度，偏好数据可能含长度偏置。错误分类抽样规模不必巨大，却能为消融表提供关键解释。

**与Tülu 2比较的数据控制。**

比较两代配方时，最好在同一基础模型上分别训练，而非直接比较各自发布模型。旧配方可能为上一代底座设计，聊天模板和tokenizer也不同；移植时要保持语义等价，并记录无法对齐的部分。只有这样，差值才主要反映后训练方法。

另一种比较是在各自原生底座上测最终系统，它回答的是时代性产品进步，不适合细分算法贡献。两种比较都有价值，但结论不同。论文叙述若同时引用，应明确哪张表回答配方、哪张表回答最终模型。

**训练数据公开后的反向污染。**

数据和模型发布后，未来基准构建者可能无意中从这些答案衍生题目，形成反向污染。几年后再评测同系列模型，时间顺序已不足以保证独立。数据谱系与公开样本索引能帮助基准作者排除重合，模型维护者也应记录版本。

动态生成、私有保留和真实用户任务能减轻问题，却牺牲完全公开复现。合理体系需要公开基准提供稳定坐标，保留集提供独立验证，两者相互补充。任何单一榜单都会随着使用次数增加而逐渐失去选择价值。

**从统计显著到实际显著。**

大题量下很小分差也可能统计显著，但未必改变使用体验；小题量高噪声基准上较大分差又可能不稳定。除了置信区间，还应报告错误减少数量、任务重要性和推理成本。提升是否值得额外训练阶段，是算法判断之外的部署问题。

配对评测可利用同一题上两个模型的输赢，通常比独立均值更敏感。对开放回答，盲评顺序随机化并报告评审一致度。若优势集中在少数类别，结论应限定到这些类别，不用宏平均制造普遍提升印象。

**Tülu 3配方的适用条件。**

这条路线适合拥有较强基础模型、足够多样的指令数据、可信偏好对，以及一部分可硬验证任务的团队。若任务完全开放、没有稳定验证器，RLVR阶段无法照搬；若SFT起点太弱，在线探索成本会很高；若偏好数据来源单一，DPO还可能放大教师风格。

迁移到新领域时，可以先复现SFT与DPO增量，再判断是否存在真正可靠的结果验证。没有验证器时，保持离线偏好或引入人工反馈可能更稳妥。配方价值在于提供清楚的阶段分工和检查方法，而非要求所有项目复制同一数据比例与步数。

**证据链的最终闭合。**

数据消融说明训练输入贡献，阶段消融说明目标贡献，奖励分析说明在线信号是否可靠，未见评测说明能力能否迁移，污染检查排除记忆解释，预算报告则区分算法与计算收益。六类证据共同出现，最终分数才拥有清楚来源。

Tülu 3公开了足够多的中间资产，使研究者能够沿这条链逐项检查。固定混合比例会随底座与任务变化；更可复用的是一套可拆解的后训练实验：每次新增数据或目标都对应明确假设、对照、失败标准与能力边界。这样得到的模型或许仍会有缺陷，但缺陷可以被定位，下一次改进也有可验证起点。

对实际复现而言，第一轮无需追求完整规模。先在较小模型上固定一组训练与未见题，逐阶段保存检查点，核对有效token、偏好间隔、验证通过率、KL和分项能力。若某阶段只提高训练指标却损伤未见任务，应先查数据重合、奖励漏洞与更新幅度，再决定是否扩大计算。小规模结果无法替代最终实验，却能提前排除目标实现错误，也能让大规模预算用于已经具备因果依据的配方。

当这些指标彼此矛盾时，保留分项和轨迹比强行压成单个总分更有解释力。
