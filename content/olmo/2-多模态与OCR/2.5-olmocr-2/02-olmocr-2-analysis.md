# olmOCR 2 技术解析：把文档识别变成可验证的单元测试

Allen Institute for AI 在 2025 年发布 olmOCR 2，模型仍以 Qwen2.5-VL-7B-Instruct 为视觉语言骨干，但训练目标从监督模仿扩展到带可验证奖励的强化学习。论文、模型、训练数据和推理代码都已公开。它要回答一个更贴近文档使用的问题：当同一页面允许多种等价 Markdown 表达时，怎样判断输出是否满足真正重要的约束，并把这种判断转成稳定的训练信号。

olmOCR 2 的答案由三部分闭合起来。第一部分是 olmOCR-Bench 的二元单元测试，每条测试只判断一个局部事实是否成立。第二部分是 HTML 合成流水线，它把真实页面的内容与版式重新渲染成可控页面，并自动派生大量测试。第三部分是 RLVR 训练，模型每次为同一页面生成一组候选，用测试通过率产生组内相对优势。最终模型在新版 olmOCR-Bench 上从第一版的 68.2 提高到 82.4，同时保留 7B 模型和开放推理栈的部署特点。

## 1. OCR 评分为何需要可执行约束

**1.1. 字符距离混合了内容错误与表示差异.** 传统 OCR 指标常把输出与一条参考字符串对齐，再统计插入、删除和替换。这个做法适合行级纯文本，却不适合结构复杂的 PDF。图、表和图注是浮动元素，图注可以放在相关段落之前，也可以放在之后；只要正文阅读顺序没有被打断，两种 Markdown 都可能正确。字符串指标只能选一条参考顺序，因此会把合法的另一种顺序判成大幅移动。

公式尤其能暴露字符指标的局限. 两个 LaTeX 字符串可能差异很大, 渲染结果却等价; 也可能只差几个字符, 最终的上标、分式或括号结构已经错误. olmOCR-Bench 转而检查渲染后的 DOM 元素与相对位置, 直接比较读者看到的数学结构. 论文示例中, 编辑距离更大的候选通过了视觉结构测试, 编辑距离较小的候选反而失败. 字面距离无法稳定表示公式是否正确.

二元测试把一个含混的总距离拆成若干可解释命题：指定文字是否出现，页眉页脚是否消失，两段正文是否按顺序出现，表格中的一个单元格是否位于另一个单元格上方，公式渲染是否匹配，以及输出是否出现重复片段或异语字符。每条测试只有通过和失败，页面得分是通过比例。它不要求页面只有一种合法序列化形式，却能对关键错误给出明确惩罚。 **1.2. 二元测试改变了误差权重.**

编辑距离让长文本天然拥有更大的权重。一个很长但次要的图注被移动，可能比短小却关键的表格数值错误贡献更多距离。单元测试由设计者决定检查什么，因此误差权重来自任务语义。若表格中的数值和相对位置重要，就为它们建立多条测试；若页码应删除，就建立文本不出现测试。页面上的像素面积和字符串长度不再替代业务优先级。

这种设计也有代价。测试没有覆盖的错误不会进入奖励，错误测试则会稳定地把模型推向错误方向。页面得分是离散测试的平均值，只有当候选输出跨过某条测试的判定边界时，奖励才变化。因此，测试数量、难度与覆盖范围决定了奖励分辨率。olmOCR 2 没有声称二元测试普遍优于所有连续指标，而是把二者的分歧列为后续研究方向：连续指标能提供更密的变化，二元测试则更容易表达等价答案和任务约束。 **1.3. 从评测复用为奖励.**

可执行测试的关键价值在于同一套规则既能评测，也能训练。对于一个页面，模型输出 Markdown 后，评测器逐条执行测试，得到 $r_{test}=k/n$，其中 $n$ 是测试数，$k$ 是通过数。该分数有清晰范围 $[0,1]$，不需要另一个模型在线判断好坏，也无需人工为每个候选排序。 这类奖励属于可验证奖励强化学习，即 RLVR。数学题可以用最终答案或程序执行验证，代码可以用测试套件验证，文档 OCR 则可以用页面级结构测试验证。与偏好模型相比，验证器的判定更可复现，训练时也不会引入一个持续变化的奖励模型。难点从训练奖励模型转移到构造足够多且足够准确的测试，而这正是合成数据流水线要解决的问题。

## 2. HTML 合成页怎样提供规模化监督

**2.1. 真实内容与可控渲染同时保留.** 人工编写 olmOCR-Bench 测试需要逐页阅读和核验，无法直接支持强化学习所需的数据规模。olmOCR 2 从真实 PDF 中抽取含公式、表格、多栏和页眉页脚的困难页面，再让通用 VLM 生成外观相近的语义化 HTML。真实页面提供内容分布和版式多样性，HTML 则提供可查询的结构真值。

生成过程分三轮。第一轮只分析版式，识别栏数、图片、表格、页眉和页脚等元素。第二轮结合版式分析与原图生成与页面尺寸一致的语义 HTML。第三轮把 HTML 渲染成图像，与原图并排交给 VLM，让它修正布局和内容。最终训练对由 HTML 渲染图和生成该图的 HTML 组成。输入图像和监督文本由同一份表示产生，二者在内部是一致的。

论文强调，这一反馈循环对通用 VLM 的 OCR 幻觉具有一定稳健性。若 VLM 把原页中的 `0.60` 抄成 `0.66`，渲染后的合成图里也会显示 `0.66`，从 HTML 派生的测试同样要求 `0.66`。该样本虽然没有忠实复刻原始页，却不会形成“图上是 A、标签要求 B”的矛盾监督。不过这种稳健性只保证合成图与测试一致，并不保证合成分布完全忠于真实文档；过多抄写错误仍会改变词汇与数值分布。 **2.2. 语义 HTML 是测试生成接口.**

HTML 不只是方便渲染，它还是自动生成测试的结构接口。`<header>` 和 `<footer>` 中的文本可以转成“不应出现在 OCR 正文”的测试；正文节点能产生文字出现和阅读顺序测试；表格 DOM 提供行列和单元格相对位置；KaTeX 节点给出公式真值。相比直接从页面像素推断这些约束，HTML 把元素类别、层级和顺序显式编码出来。

最终合成集 olmOCR2-synthmix-1025 只有 2,186 个 PDF 页面，却派生出 30,381 条测试，平均每页约 13.9 条。样本单位仍是页面，奖励的细粒度来自一页上的多条约束。生成所用的 Claude Sonnet 4 每页成本约 0.12 美元，由论文给出的页数和单价相乘可得模型调用成本约为 262 美元，未计渲染、筛选和计算资源。这个数量级说明高质量合成并非免费，但远低于逐条人工标注数万测试的工时。 **2.3. 监督微调数据先建立输出语言.** RL 数据不是从通用 Qwen2.5-VL-7B-Instruct 直接起步。团队先更新监督微调集 olmOCR-mix-1025，它包含 267,962 页，来自超过 10 万份 PDF，其中 9,828 页来自国家档案馆。与早期的 olmOCR-mix-0225 相比，新数据改用 GPT-4.1 处理，统一块级和行内公式格式，表格改为 HTML，并为图片加入基本 alt 文本。

两套 SFT 数据在总分上几乎相同，旧集为 $78.5\pm1.1$，新集为 $78.3\pm1.2$。分项却发生了明显迁移：表格从 72.9 提高到 77.9，多栏从 77.3 提高到 81.3；arXiv 从 78.6 降到 70.8，长小字从 81.2 降到 78.7。这组结果很重要，因为它说明数据格式更新并非所有分布都单调改善。新集的价值还包括与后续合成页、HTML 表格和输出协议对齐，为 RL 阶段建立稳定的可采样策略。

## 3. GRPO 如何使用页面单元测试

**3.1. 同页生成 28 个候选.** 强化学习从经过 olmOCR-mix-1025 微调的 Qwen2.5-VL-7B-Instruct 开始，在一台 8 张 H100 的节点上对 olmOCR2-synthmix-1025 训练一个 epoch。每个文档页面一次生成 28 个 completion。大量同题候选使训练器可以比较同一页面上的相对质量，避免把不同页面的固有难度混进优势估计。 GRPO 按组计算奖励中心和尺度。设同一页面候选奖励为 $r_1,\ldots,r_G$，组均值为 $\mu$，标准差为 $\sigma$，候选的相对优势可写成 $A_i=(r_i-\mu)/(\sigma+\epsilon)$。训练提高高于组均值的输出概率，降低低于组均值的输出概率。困难页面即使绝对得分低，只要某个候选相对更好，仍能贡献正向学习信号；容易页面若所有候选全对，组内没有差异，更新也会自然变弱。

论文给出 KL 系数 $\beta=0.01$，用于约束新策略不要过快偏离参考策略。这里的 KL 项与可验证奖励承担不同职责：测试奖励告诉模型哪些候选更符合页面约束，KL 约束限制为了追逐离散奖励而破坏已有语言和格式能力。一个 epoch 的短训练也减少了在小型合成集上过拟合的风险。 **3.2. 奖励不仅有测试通过率.**

训练实际有三类奖励。第一类是页面单元测试通过率。第二类检查输出是否以 EOS token 结束，是一个二元奖励。第三类检查回复顶部的文档元数据，包括主要语言、旋转校正、表格和图示等字段，取值在 0 到 1 之间。官方训练代码把各项注册为独立 reward function，再由 TRL 的 `reward_weights` 加权合成。

实际训练运行的各项奖励权重没有公开. 代码默认值为 1.0, 只能说明未另行指定时的行为. 若三项等权, 总奖励理论范围是 $[0,3]$; 同一页面的 28 个候选通常都能正常结束并生成元数据时, EOS 与元数据奖励在组内近似常数, 测试通过率承担主要区分作用. 训练早期或困难页面更常出现残缺输出, 此时格式奖励可以阻止少数偶然命中的测试主导更新.

元数据奖励还有一个边界：它把合成过程中的 Claude 原始输出当作字段参照。合成图与 HTML 能保证正文测试的内部一致性，却不能自动纠正主要语言或页面类型判断。若这些字段最初判断错误，格式奖励会继承错误标签。因此“对幻觉稳健”不能扩展成“所有奖励都不受教师错误影响”。 **3.3. 六个随机种子与模型汤.** 团队用六个随机种子重复 RL 训练，再对检查点做权重平均，即 model soup。三次训练采用 token 级重要性采样，三次采用序列级重要性采样。两种估计方式对长序列中策略比率的聚合不同，把它们纳入同一个权重平均，相当于把训练随机性和估计偏差一起做集成。

模型汤不增加推理时的模型数量。若六个模型参数分别为 $\theta_j$，最简单的平均是 $\bar{\theta}=\frac{1}{6}\sum_j\theta_j$，部署时只加载 $\bar{\theta}$。它成立的经验前提是各检查点从同一基座出发，位于可线性连接的相近参数区域。与输出投票相比，权重平均没有六倍推理成本；与只选单个最好种子相比，它降低了小数据 RL 对随机采样路径的敏感性。

## 4. 从训练到推理的工程改动

**4.1. 动态温度处理重复循环.** 第一版 olmOCR 默认温度为 0.8。团队发现较低温度通常带来更好的 OCR 输出，但也更容易陷入重复循环。olmOCR 2 先以低温生成，若没有正常生成 EOS 或输出过长，则提高温度重试。这个策略把确定性和逃离重复的随机性放在不同尝试中，而不是对每一页一开始就使用高温。 论文将温度概括为从 0.1 逐步升到 0.8。固定版本代码中的实际表为 `[0.1, 0.1, 0.2, 0.3, 0.5, 0.8, 0.9, 1.0]`，默认最多尝试 8 次。重试条件包括 `finish_reason` 不是 `stop`，或总 token 超过 16,384。全部失败后，页面回退到 `pdftotext` 的文本层。这一差异不改变机制方向，却影响复现：实际实现重复使用一次 0.1，并允许温度升至 1.0。

动态温度在基准上把总分从 68.2 提高到 72.8，是开发序列中第一个显著增益。它也说明 OCR 系统质量不仅由权重决定，解码失败率会直接落到最终评测。低温本身不是无条件更好；只有配合结束检测、有限重试和明确回退，才成为可部署策略。 **4.2. 提示顺序与缓存命中.** 团队还发现训练与推理提示中图像和文字顺序不一致。统一为文字在前后，总分从 72.8 提高到 75.8。反向顺序在单独实验中没有明显 OCR 差异，因此增益主要来自训练和推理协议对齐，而非“文字在前”具有固有识别优势。

固定文本放在前面还有服务系统上的好处：推理引擎更容易复用共同前缀的 prompt cache。图像内容每页不同，若图像排在固定说明之前，共享前缀会很短；把固定说明置前，可以让不同页面共享更长缓存。这项改动同时连接了模型分布对齐与吞吐优化。 **4.3. YAML、图像尺寸与空白页.** 第一版输出 JSON，olmOCR 2 改为 YAML。JSON 要求引号和括号完整闭合，长文档生成中任何截断都可能使整体无法解析；YAML 的顶层元数据更容易增量生成，正文结束后可以直接输出 EOS。论文没有观察到基准分数变化，但重试率明显下降，因而提升了推理效率。

输入图像最长边从 1024 像素提高到 1288 像素。小字、上下标和细线表格需要更高空间分辨率，代价是视觉 token 与计算量增加。1288 是团队在分数和速度之间扫参后的折中，并非一个与模型无关的最佳尺寸。基座也从 Qwen2-VL 换成 Qwen2.5-VL，配合新训练器、避免权重衰减等超参数调整，这组改动把总分推到 78.5。

空白页暴露了另一类数据问题：旧数据加载器跳过所有空白页，模型从未学习过“没有正文”也是合法答案，推理时便会凭先验编造内容。修复加载器并重训没有改变基准总分，却修正了真实批处理中的高风险行为。基准若缺少空白页，这类修复不会反映在总分上，部署质量仍然会改善。

## 5. 实验结果应如何解释

### 5.1. 增益来自完整训练组合.

开发表给出一条清晰路径：第一版 68.2，动态温度 72.8，提示对齐 75.8，新训练器、YAML、图像尺寸和 Qwen2.5-VL 合计达到 78.5，空白页修复后仍为 78.5，末尾加入合成数据、RLVR 与模型汤达到 $82.4\pm1.1$。末尾阶段相对前一阶段提高 3.9 分，相对第一版提高 14.2 分。 表格分项从末项 SFT 系统的 72.9 提高到 84.9，是 RL 阶段最突出的增益之一；arXiv 从 78.6 提到 83.0，多栏从 77.3 提到 83.7。旧扫描页只从 43.9 提到 47.7，仍是明显短板。基础类别达到 99.7，说明普通页面已接近饱和，继续提高总分更依赖困难扫描、复杂表格和版面。 末行同时加入合成数据、RLVR、六种子训练和权重平均, 论文没有逐项消融. 3.9 分对应的是完整组合, 表格无法分离 GRPO 与模型汤各自的边际贡献; 这需要额外的受控实验. **5.2. 基准与训练奖励共享测试体系

RL 奖励使用 olmOCR-Bench 兼容测试，最终评测也在最新版 olmOCR-Bench 上完成。训练页与基准页并非同一批页面，但奖励形式高度一致，这会让模型特别擅长测试体系显式表达的性质。阅读顺序、表格位置、公式渲染和页眉页脚因此获得直接优化；未被测试覆盖的视觉细节、语义忠实度或下游检索效果不一定同步增长。

这种一致性属于目标对齐，不等同于数据泄漏：训练优化的就是评测定义的能力。但评价模型泛化时，还需要不同标注体系、真实业务文档和人工检查。论文列出的其他 OCR 系统中，带星号的结果来自模型作者报告，其余由团队内部复现，推理配置和版本差异也会影响横向比较。 **5.3. 方法适合什么场景.**

单元测试奖励最适合能把质量拆成局部、可执行约束的文档任务。表格、公式、页眉页脚、段落顺序都有明确判定器，且允许多种等价序列化形式。对于手写批注、图像语义、模糊印章或需要世界知识才能判断的内容，自动测试更难生成，仍可能需要连续视觉指标或人工偏好。

工程上还要评估训练成本与推理需求。RL 阶段需要每页 28 个候选、8 张 H100、六个随机种子，计算量显著高于一次 SFT。模型汤把额外成本留在训练端，部署仍是单个 7B 模型；动态温度在多数页面第一次成功时开销较小，在重复严重的页面上则可能触发多次推理。系统应记录每页尝试次数、回退比例和失败类型，而不能只看平均基准分。

## 6. 方法的可迁移经验

### 6.1. 先定义可接受答案集合.

olmOCR 2 把真值从“一条字符串”改成“一组必须满足的性质”，这一设计比具体采用哪种模型更重要。当输出存在多种等价表示时，先定义可接受答案集合，再设计验证器，比强迫所有输出模仿单一参考更合理。代码生成、网页复刻、图表转结构化数据和科学公式识别都可以采用类似思路。 验证器必须逐项可诊断。页面总分下降时，应能知道是文字缺失、顺序错误、表格关系错误还是重复输出。这样的反馈既方便训练，也方便定位推理系统问题。若只把所有规则压成一个不可解释的相似度，模型改进和回归分析都会变慢。 **6.2. 合成数据要建立自洽反馈循环

从 HTML 同时生成图像与测试，是减少教师抄写错误造成矛盾标签的关键。可迁移的原则是：尽量从同一潜在表示生成输入和可验证目标。例如程序任务可从可执行规格生成题目与测试，图表任务可从结构化数据生成图像与查询。反馈循环保证内部一致，却不能保证分布真实，因此仍需从真实样本采种、筛选版式，并用独立真实集评测。 合成流程也应保留来源和版本。olmOCR 2 给出所用模型、每页成本、页面数、测试数与代码链接，使复现者能检查提示、渲染和测试派生规则。对于奖励训练，数据生成代码与训练代码同样属于模型定义的一部分。 **6.3. 把协议错误视为模型问题的一部分.**

提示顺序、输出格式、空白页过滤和解码重试都曾显著影响 olmOCR。这些细节共同决定模型在生产系统里实际接收的分布与产生的行为。训练和推理消息顺序必须一致，结构化输出要选择易完成和易解析的协议，数据加载器必须覆盖零内容样本，解码失败要有上限明确的恢复路径。

olmOCR 2 因而展示了一条完整路线：用监督数据教会模型文档输出语言，用语义 HTML 生成自洽页面和测试，用 GRPO 从同页多候选中学习局部约束，再通过权重平均与受控重试得到可部署模型。它的性能提升来自评测定义、数据生成、训练目标和推理协议的共同对齐。 **6.4. 页面到文本是一种条件生成.** 给定页面图像 $I$，模型生成结构化序列 $y$，训练目标通常是最小化 $-\sum_t\log p_\theta(y_t|y_{<t},I)$。输出既包含可见字符，也包含段落、标题、表格、公式和阅读顺序的编码。任何序列化规则都会把二维页面压成一维目标，规则本身就是任务定义的一部分。

相同页面可以有多个合理输出：连字符是否合并、页眉是否保留、表格采用Markdown还是HTML、双栏先读哪一栏。若监督只给一个字符串，交叉熵会惩罚其他语义等价表示。olmOCR 2用可执行测试描述可接受集合，减少对唯一参考文本的依赖，但测试覆盖仍决定哪些差异被容许。 **6.5. 文本识别与文档解析.**

传统OCR常分为检测文本区域、识别字符和后处理；端到端视觉语言模型直接从页面生成结构化文本，将这些阶段隐藏在网络内部。优势是语言、布局和结构可以联合推断，代价是错误更难定位。一个漏字可能来自视觉编码、阅读顺序、语言解码或输出协议。 评测需保留多个层次：字符内容、区域覆盖、顺序关系和结构合法性。只看最终编辑距离，会把字符识别准确但布局错误，与布局正确但少量拼写错误混在一起。端到端模型仍需要分解诊断。 **6.6. 二维布局到线性顺序.**

页面元素可表示为带边界框的节点集合，阅读顺序是节点间的有向关系。单栏通常按上到下，双栏需要先完成左栏再到右栏，脚注、侧栏和跨栏标题又会打破简单坐标排序。目标序列隐式编码一个拓扑排序。 若页面关系存在歧义，可能有多个合法拓扑序。评测可以检查必要先后约束，而非要求完整序列逐字相同。例如标题必须先于正文、脚注引用先于脚注内容，同栏段落保持垂直顺序；无依赖的两个侧栏允许交换。部分序约束比唯一参考更贴近结构语义。 **6.7. 阅读顺序图.**

设块节点为 $v_i$，真实先后边集合为 $E$。模型输出序列诱导预测顺序，结构准确率可统计满足的边比例。对每对节点都建边会让相邻关系被大量传递边重复计权，使用Hasse图或只标关键邻接更合理。 图指标还能定位跨栏错误。字符全部正确但两个段落互换时，字符集合指标近乎满分，顺序边会失败。若块检测本身不同，需要先对预测块与真值块匹配，再比较关系，匹配阈值会影响结果。 **6.8. 行、段落与区域层级.** 页面结构具有层级：字符组成词和行，行组成段落，段落属于栏目、列表或表格。错误在不同层级传播。一行漏识别会影响字符召回，段落合并错误会破坏空行与标题，栏目交换则改变大段顺序。

层级评测可分别计算内容与父子关系。树编辑距离能统一表示，却难以解释单个分数。更实用的报告给字符、行匹配、块关系和文档结构分项，并保留失败页面示例。 **6.9. 标题层级.** 标题文字识别正确，却把一级标题写成普通段落，会破坏下游目录和检索。Markdown中的井号数量编码层级，但视觉字号、粗体、编号和留白共同提供证据。模型语言先验可能根据标题内容猜层级，在模板异常时出错。 测试可检查标题文本、层级和父级关系。绝对级别有时不确定，但相对层级必须一致。把所有标题统一降一级在渲染上或许相似，在结构语义上却有系统偏差。 **6.10. 列表结构.**

列表需要识别项目边界、序号、嵌套层级和连续性。换行可能属于同一项目，也可能开启下一项。编号缺失或重复时，语言模型容易自动修正，生成比视觉页面更整齐的列表，却不忠实于原件。 结构测试可从语义HTML知道真实列表树，检查项目数量、顺序与嵌套。项目内部文本再用局部字符指标。将树结构与内容分开，可发现模型究竟漏项还是只错了编号符号。 **6.11. 表格的二维约束.** 表格不仅是按行输出文字，还包含单元格、行列跨度、表头与数据对应。线性编辑距离无法发现列错位：所有数字都出现，归属列错误仍会造成严重数据问题。结构评测需要单元格匹配和行列关系。

语义HTML天然提供表格树与span属性，可生成测试：行列数、指定坐标内容、表头覆盖范围和关键对齐。输出为Markdown时，复杂合并单元格难以表达，测试必须按目标格式允许的能力定义，不能惩罚格式本身无法承载的信息。 **6.12. 公式识别.** 公式视觉上包含二维上下标、分式和矩阵，线性LaTeX是另一种序列化。许多LaTeX字符串渲染等价，例如括号、空格和命令别名。逐字匹配会把表示差异当错误，渲染比较或语法树规范化更合适。 语义等价更难：$a/b$ 与 $\frac{a}{b}$ 常等价，变量替换却可能改变含义。计算机代数系统只能覆盖部分公式。评测可分成可解析、渲染结构和关键符号三层，避免一个黑箱相似度掩盖错误。 **6.13. 图注与浮动对象.**

图表本身可能不转写，图注却应保留并与对应对象相邻。多栏排版中图注位置和阅读顺序可能与正文穿插。仅按坐标扫描容易把图注插入错误段落。 合成页面可保存图对象、图注和正文引用关系，生成配对测试。真实文档缺少结构标注时，可人工抽样。图中嵌入文字是否识别也需明确协议：装饰图、流程图和截图的要求不同。 **6.14. 页眉、页脚与页码.** 页眉页脚在每页重复，对文档内容价值低，却是可见文本。保留它们会污染连续正文，删除它们又可能误删章节标题或脚注。任务规范应定义哪些区域进入输出。

跨页处理可以利用重复性识别页眉页脚，单页模型只能靠位置和样式。合成数据若总在固定位置生成，模型可能学位置捷径，对真实异常布局失效。随机化位置、字体和内容能减少。 **6.15. 脚注与引用.** 脚注标记出现在正文，内容位于页底。线性输出可以在原位置插入、页末集中或保留标记链接，不同规范都合理。唯一字符串监督会造成冲突。结构化测试可检查标记与内容配对，以及正文顺序不被脚注打断。 语言模型可能根据常见短语补齐模糊脚注，这提高可读性却增加幻觉风险。关键编号、作者名和URL需要更强视觉约束。脚注字体小，还是检验分辨率与视觉编码的敏感区域。 **6.16. 多页连续性.**

单页独立OCR会在分页处断开句子、列表和表格。跨页模型需要判断上一页结尾与下一页开头是否连续，并处理重复页眉。文档级顺序比页面级指标多一层。 olmOCR 2若主要按页训练，其结果不能自动外推到整本文档。后处理可拼接页面，但跨页语义错误需单独评测。合成多页样本可以控制连续关系，真实文档则验证分布迁移。 **6.17. 渲染器定义视觉分布.** HTML内容经过浏览器、CSS、字体、纸张尺寸和截图参数生成图像。训练数据看似多样，若渲染器和字体集合固定，视觉分布仍很窄。模型可能学会特定浏览器的抗锯齿、行高和表格样式。

渲染随机化应覆盖字体、字号、边距、栏数、分辨率、缩放和压缩，同时保证语义标签保持正确。过度随机化会产生不自然页面。用真实文档统计校准参数范围，比任意噪声更有效。 **6.18. CSS作为生成语法.** 语义HTML提供内容树，CSS控制布局。两者分离使同一内容可渲染多种页面，也使同一布局可装入不同文本。通过正交采样，模型较难只记内容或模板。 某些CSS组合会导致遮挡、溢出或不可见文字。生成器必须检测渲染后页面，而非假设DOM正确。单元测试也应基于实际可见元素，隐藏DOM文本不应要求模型输出。 **6.19. 合成数据的标签精度.**

合成页最大的优势是结构真值自动可得。DOM知道元素层级、文本和位置，可生成确定测试。标签精确建立在渲染与提取映射正确上；浏览器换行、连字和字体回退可能让DOM字符串与可见字形不完全一致。 抽样保存截图、DOM框和目标输出叠加图，检查标签。生成规模越大，少量系统bug越会被重复放大。标签程序的单元测试与版本记录是数据质量的一部分。 **6.20. 内容来源与布局来源.** 使用真实文本填充合成布局，能保留语言和主题复杂性；布局仍由模板控制。若内容来源与评测重合，会产生文本记忆，哪怕视觉布局新颖。数据构建需对内容去重，并分开记录内容与模板ID。

评估也可交叉组合：训练见过内容未见布局、见过布局未见内容、两者都未见。四格设计能判断模型依赖语言记忆还是视觉结构泛化。只在随机划分页上测试容易让同模板和同文档泄漏。 **6.21. 模板泄漏.** 同一HTML模板换文字生成许多页面，随机按页面划分会让模板同时进入训练和测试。模型可凭固定坐标与样式取得高分。应按模板族、CSS参数或生成程序版本划分，测试真正新布局。 真实文档也有模板族，例如同一期刊或同一政府表格。按文档随机划分同样会泄漏。来源级和模板级分割比页面级更严格，结果通常更能反映迁移。 **6.22. 内容泄漏.**

同一文章被排成不同样式进入训练和测试，视觉不同却文本相同。语言模型能凭前几个词续写，掩盖视觉识别不足。段落级精确和近重复去重需要跨所有渲染版本执行。 对常见公共文本完全去重可能不现实，可按重合度分桶报告。用随机实体、数字和不可预测字符串构造压力测试，可以降低语言记忆帮助，直接测视觉证据。 **6.23. 合成到真实的域差距.** 真实扫描包含透视、阴影、污渍、折痕、纸张纹理、手写和拍照裁切，浏览器截图过于干净。添加噪声能覆盖部分低层变化，真实排版和内容结构仍可能不同。合成训练增益必须在来源独立的真实文档上验证。

域差距可按视觉质量、布局类型和文档年代分层。总体平均改善可能只来自数字原生PDF，对扫描档无效。失败分层指导下一轮合成参数，而非盲目增加页面数。 **6.24. 扫描退化模型.** 可模拟模糊、压缩、旋转、透视、颜色偏移和局部遮挡。每种退化有强度，组合后可能远离真实分布。根据真实样本估计强度分布，并保留无退化样本，避免模型只适应噪声。 退化不应改变标签，严重遮挡却可能让字符不可辨识。此时唯一真值要求模型猜测，训练会强化语言先验。设置可读性阈值或允许缺失标记，区分识别与恢复任务。 **6.25. 分辨率与小字.**

页面缩放到固定图像尺寸后，小字可能只剩数像素。模型无法恢复消失的视觉信息，语言解码器会猜测。评测应记录原始DPI、缩放和最小字符高度，按区间报告准确率。 提高分辨率增加视觉token与计算。裁块或多尺度输入能保留细节，却需要处理块间顺序。质量—计算曲线比单一最佳尺寸更有部署意义。

### 图像压缩

 JPEG在文字边缘产生振铃，PNG通常无损但文件大。训练与测试压缩分布不同会造成性能差。PDF渲染还受抗锯齿与hinting影响。 用多种编码和质量做配对测试，能测模型对低层表示的鲁棒性。同一页面内容保持不变，差值更容易归因视觉退化。协议必须固定解码库和颜色空间。 **6.27. 旋转与方向.**

页面可能整体旋转，表格单元格或侧栏文字又可能局部竖排。预处理自动校正整体方向无法处理局部方向。端到端模型可学习，但合成数据需包含合理分布。 方向评测分别测检测、校正和最终文本。模型若输出正确字符却逆序，字符集合指标仍高。阅读方向是结构的一部分，尤其多语言页面。 **6.28. 字体覆盖.** 训练字体集合决定字形变化。相同Unicode在不同字体差异显著，某些字符又容易混淆。测试未见字体能衡量字形泛化，按字体随机划分页不足，因为同字体泄漏。 字体许可证和真实使用频率也影响选择。只加入大量装饰字体不一定帮助常见扫描。建立字体族层级，按衬线、无衬线、等宽和历史字体分层更可解释。 **6.29. 多语言脚本.**

拉丁、汉字、阿拉伯和天城文的字符结构、书写方向与连写不同。共享视觉编码器可以迁移边缘和布局，识别头与tokenizer覆盖仍有差异。统一字符准确率不能直接比较语言难度。 按Unicode grapheme cluster或字符评测时需固定规范化。混合方向页面的阅读顺序更加复杂。语言宏平均防止高资源语言淹没，部署权重另行报告。 **6.30. 语言先验的两面性.** 视觉字符模糊时，语言模型利用上下文纠正拼写，提高自然文本准确率。对姓名、编号、化学式和随机串，强先验可能把罕见真值改成常见词。总体编辑距离改善会掩盖关键字段错误。

评测应包含自然文本与低可预测字段，并按类型报告。可通过上下文遮蔽或替换构造相同视觉难度的随机串，测量模型依赖先验程度。先验不是错误，未校准的覆盖才是风险。 **6.31. 视觉—语言冲突实验.** 将页面中的一个常见词替换为拼写相近的罕见词，同时保持上下文强烈暗示原词，可以测试模型是否遵循像素。若输出回常见词，说明语言先验压过视觉证据。反向把像素轻微扰动，也能画冲突强度曲线。 这种反事实样本必须保证替换后的字形清晰。多字体、多分辨率重复，避免结论依赖单一渲染。关键实体和数字可建立专门冲突集。 **6.32. 幻觉插入.**

模型可能生成页面上不存在但语言上合理的词句，例如补完整被截断段落、增加标题或修正语法。字符精确率会惩罚插入，但长文档中少量插入占比低。对事实使用而言，一句虚构内容风险很高。 分别统计插入、删除和替换，并按连续幻觉跨度分布。空白区域和截断页面是压力测试：可靠模型应停止或标记不可读，而非续写。奖励中需要明确惩罚无视觉依据内容。 **6.33. 删除错误.** 小字、边缘文本和低对比区域容易被漏掉。语言模型偏好连贯段落，可能自动跨过不可读句，输出看似完整。字符召回与区域覆盖能发现，单纯可读性人工评分可能忽略。

按页面坐标画召回热图，可以诊断边缘、页底和栏间问题。合成数据的元素框提供真值，真实数据则需人工区域标注。删除与插入风险不同，应分开报告。 **6.34. 重复循环.** 自回归解码可能重复行、段落或标记，尤其长页面与表格。动态温度尝试在检测重复时改变采样，却也可能增加字符错误。重复检测规则和温度变化是推理协议一部分。 评测统计重复n-gram、重复块和额外token比例，同时检查是否误把合法表格重复判错。训练奖励若强惩罚重复，模型可能通过过早停止规避。长度和召回需联合观察。 **6.35. 过早停止.**

输出合法结束标记却遗漏页面尾部，格式测试可能通过。奖励需要覆盖内容召回或关键区域测试，不能只看语法。页面长度与生成上限也会造成系统截断。 记录finish reason、输出token与页面文本量估计，按长页面分析。提高上限会增加循环风险，动态停止应基于页面覆盖而非仅语言结束概率。 **6.36. 输出语法.** 结构化文本需要合法Markdown、HTML或YAML。语法错误会使下游解析失败，哪怕文字正确。可执行解析器提供明确奖励，但模型可能生成最简单合法结构，牺牲真实层级。 语法合法性是必要条件，结构忠实度另行测试。奖励分项记录解析、内容、顺序与结构，防止一个容易指标主导。最终用户看到的是完整系统，两层都重要。 **6.37. 可执行测试的覆盖.**

每个页面的测试只检查有限属性。所有测试通过不表示输出完全正确，未被断言的段落仍可能错。测试生成器应覆盖关键元素，并记录覆盖率：多少文本、块和关系至少被一个断言触及。 随机选少量属性能扩展数据，却增加奖励噪声。根据结构风险分层抽样，确保表格、标题和罕见字段有最低覆盖。人工完整标注集用于估计测试通过率与真实质量的关联。 **6.38. 测试独立性.** 同一错误会导致多个断言失败，例如漏掉表格一行同时破坏行数、单元格与文本测试。把每项简单平均会重复惩罚。按结构组件分组，先组内聚合再组间加权，减少相关测试放大。

反过来，一个宽泛测试可能覆盖多个错误却只失败一次。奖励权重表达任务价值，不应由断言数量偶然决定。测试生成模板需要审计其隐式权重。 **6.39. 二元奖励的方差.** 二元测试给清晰信号，但接近阈值的输出可能因一个字符从满分变零，方差较大。部分信用如编辑相似度能平滑，容易被模型优化成近似输出。两者结合时需检查相关性。 GRPO组内候选若全通过或全失败，没有相对信号。页面难度和采样温度决定奖励方差。数据路由可优先选择成功率居中的页面，保留容易与困难页做回放和评测。 **6.40. 奖励黑客.**

模型可能输出测试所需关键词，却省略其余内容；用重复片段提高覆盖；或选择解析器宽松接受的结构。任何公开可执行测试都有被策略利用的可能。对抗样本和隐藏断言可以发现。 奖励训练后比较测试通过率与独立人工质量。二者相关下降时，说明策略找到了漏洞。更新测试后需要回放旧模型，确认提升来自覆盖修复而非难度改变。
