# FlexOlmo: 数据拥有者各训各的专家, 推理时按许可拼装

论文: Weijia Shi, Akshita Bhagia, Kevin Farhat, Sewon Min 等, 「FlexOlmo: Open Language Models for Flexible Data Use」, arXiv 2507.07024v4 (2025-08-23), NeurIPS 2025. 作者来自 Ai2, 华盛顿大学, UC Berkeley, 斯坦福和 MIT. 代码: [github.com/allenai/FlexOlmo](https://github.com/allenai/FlexOlmo); 权重: [allenai/FlexOlmo-7x7B-1T](https://huggingface.co/allenai/FlexOlmo-7x7B-1T) 与 `-RT` 版; 公共模型 `allenai/Flex-public-7B-1T`. 文中的代码行为均以仓库 `main` 分支的训练脚本和 HF `config.json` 为准.

FlexOlmo 要解决的场景是: 若干机构各自持有不能外传的数据, 想合作训练一个语言模型, 而且每份数据在推理时能单独开关. 做法是把 MoE 的专家当作数据的载体, 一份数据只训练一个 FFN 专家和一行路由向量, 其余参数全部来自一个只见过公开数据的 dense 模型. 架构与参数量, 协调训练, 路由初始化, 推理时增删专家和数据提取风险由同一套模块边界串联起来. 公共模型的架构沿用 [OLMo 2](../1.4-olmo-2/02-olmo-2-analysis.md), MoE 的一般训练方式可对照 [OLMoE](../1.7-olmoe/02-olmoe-analysis.md) 和 [MoE 路由与 Top-K 可导性](../../../llm-guide/2-核心原理与架构/2.6-MoE/02-MoE路由与Top-K可导性/02-MoE路由与Top-K可导性.md).

## 1. 模型结构,训练与退出

FlexOlmo 处理的是数据无法集中时的模型组合问题. 每个数据拥有者从同一个公共模型出发, 只训练自己的专家参数; 协调方在推理前拼装专家, 再由 token 级路由选择公共专家与领域专家.

这套结构同时追求可组合与可退出. 参数隔离让专家可以单独加入或删除, 却没有自动解决路由冲突,隐私泄漏和退出后的性能变化. 模型结构,协调训练与安全实验必须放在一起判断.

### 1.1. 问题设定与模型结构

FlexOlmo 的问题设定只有两条约束. 第一条, 训练最终模型 $M_\text{final}$ 时没有任何一方能同时访问全部数据 $\mathcal{D}=\{D_1,\dots,D_n\}$, 每个 $M_i$ 只由 $D_i$ 的拥有者在本地训练. 第二条, 从 $M_\text{final}$ 中删掉 $M_i$, 就等于删掉了 $D_i$ 的全部影响. 第一条决定了训练流程不能有任何跨数据的联合步骤, 第二条决定了 $D_i$ 的信息只能落在可整体摘除的参数里. 这两条约束把联邦学习和 BTX 都排除在外. 联邦学习每一轮都要聚合各方梯度, 共享参数里混着所有数据的信息, 删不掉某一方. BTX 在合并后要用全部数据的并集再训一遍, 违反第一条. 论文选的结构是 MoE: 每份封闭数据对应一个专家, 共享部分 (注意力, 嵌入, 归一化, 输出头) 只用公开数据训练.

**图 1 解析**: 左侧每个数据拥有者手里只有两样东西: 冻结的公共模型和自己的数据. 训练产物是一个 FFN 专家加一行路由嵌入. 右侧推理时, 各方交来的 FFN 并列成专家层, 路由嵌入按行拼成路由矩阵. 图中被模糊处理的 GitHub 专家表示退出: 删掉对应的 FFN 和那一行路由嵌入, 模型其余部分不变, 也不用再训练.

**两条要求如何落到参数上.** 设公共模型为 $M_\text{pub}$, 在公开数据 $D_\text{pub}$ 上训练. FlexOlmo 每层的 MoE 输出是

$$\mathbf{y}=\sum_{i\in\mathrm{Top}k(r(\mathbf{x}))}\mathrm{softmax}(r(\mathbf{x})_i)\,M_i(\mathbf{x}),\qquad r(\mathbf{x})=\mathbf{W}_r\mathbf{x},\ \mathbf{W}_r\in\mathbb{R}^{(n+1)\times h}.$$

$\mathbf{W}_r$ 的第 0 行是公共专家的 $\mathbf{r}_\text{pub}$, 第 $i$ 行是专家 $M_i$ 的 $\mathbf{r}_i$. 要满足第二条, 与 $D_i$ 有关的参数只能是 $M_i$ 的 FFN 权重, $\mathbf{r}_i$, 以及代码里的偏置 $b_i$. 删掉这三样, 剩下的 $\mathbf{W}_r$ 少一行, softmax 在剩余专家上重新归一化, 前向计算照常进行. 这个性质只在不做可选路由训练 (RT) 时严格成立. RT 会在合并后同时微调 $\mathbf{r}_\text{pub}$ 和所有 $\mathbf{r}_j$, 所用代理集由在 $D_i$ 上训练的分类器挑出; 删掉 $M_i$ 后, 其他路由行仍是 RT 之后的值, 其中留有 $D_i$ 的间接信号. §3.1 第 (2) 条要求「移除 $M_i$ 即完全移除 $D_i$」, 与 §3.3.3 的 RT 并存时, 只有表 1 和表 2 中 no RT 的行满足这条要求. 第 4 节还会回到这一点.

公共模型与参数量. 公共模型 $M_\text{pub}$ 是 OLMo 2 7B 架构: 32 层, $d=4096$, FFN 中间维度 11008, 32 头 MHA, 词表 100352, RoPE $\theta=5\times10^5$. HF 上 `Flex-public-7B-1T` 的 `config.json` 是 `Olmo2ForCausalLM`, 维度与此一致. 它在 public mix 上训练 1T token; 训练脚本 `train_public_model.sh` 把余弦调度的总长设为 5T, 在 1T (step 238419) 处截停, 所以学习率没有衰减到底. 随后另有一段 50B token 的退火 (`OLMoE-2x7B-anneal.py`, 11921 步, 每步约 4.19M token), 数据仍是 public mix. §4.4 没有提到这段退火, 但「全部专家合计 400B token」只有把它算作第 8 份 50B 才对得上: 7 个封闭集各 50B 只有 350B. 按这些维度可以复算参数量. 非 FFN 部分: 嵌入与输出头各 $100352\times4096\approx0.41$B, 注意力 $4\times4096^2\times32\approx2.15$B, 合计约 2.97B. 每个专家的 SwiGLU FFN 是 $3\times4096\times11008\times32\approx4.33$B. 8 个专家总参数 $2.97+8\times4.33\approx37.6$B, 激活 4 个时 $2.97+4\times4.33\approx20.3$B, 与论文的 37B / 20B 一致. 路由矩阵每层只有 $8\times4096$ 个参数, 可以忽略.

HF 发布的 `allenai/FlexOlmo-7x7B-1T` 与论文的最终模型不同. 它的 `config.json` 写 `num_experts`=7, `num_experts_per_tok`=7, `norm_topk_prob`=false, 专家依次是 public, math, news, academic, code, creative, reddit, 没有 Educational Text; `domain_embeddings` 目录也只有这 7 个 `.npy` 文件. 按上面的算法, 7 个专家总参数约 33.3B, 与 README 写的 33B 一致; 7 个全部激活, 每个 token 的计算量相当于 33B 的 dense 模型. 论文 §4.4 的口径是 8 个专家, 激活 4 个, 37B / 20B. README 给出的平均分 52.0 (RT 版 52.2) 与表 2 的 52.4 也来自不同的专家集合, 不能直接比较.

### 1.2. 协调训练与域嵌入路由

一般的 MoE 让路由器和全部专家在全部数据上联合训练, 路由器学到的是专家之间的相对偏好. FlexOlmo 不允许任何联合步骤, 每个数据拥有者只能看到公共模型和自己的数据, 于是要回答两个问题: 各方独立训练出的 FFN 合在一起为什么还能协作; 路由器的各行分头学出来, 拼在一起为什么还能比较. 论文给出三件工具: 以冻结公共模型为锚的两专家训练, 用域嵌入初始化路由行, 给封闭专家加负偏置, 另有一个可选的 RT 步骤. 论文描述与代码实现共同确定它们的作用范围.

**以冻结公共模型为锚的两专家训练.** 最直接的做法是让每个拥有者从 $M_\text{pub}$ 出发, 在 $D_i$ 上继续训练整个 dense 模型, 再想办法合并, 这就是 BTM, model soup 和 BTX 这些基线的起点. 论文指出这样训出来的模型彼此之间, 以及与种子模型之间偏离太大, 合并效果差. 表 1 的消融「no training to coordinate」平均 38.8, 比不做 RT 的 FlexOlmo (46.7) 低 7.9 分, 是所有消融里掉得最多的一项; 文中没有说明这一行合并时用的是哪种路由.

FlexOlmo 的做法是: 对每个 $D_i$ 构造一个只有两个专家的 MoE, 两个专家都复制自 $M_\text{pub}$ 的 FFN, 冻结其中一个 (公共专家) 和全部注意力, 嵌入, 归一化, 输出头, 只训练另一个专家和它的路由行 $\mathbf{r}_i$. 代码 `FreezeTransformerTrainModule` 的实现方式是在每步把专家参数和路由权重前一半的梯度置零, 所以 $\mathbf{r}_\text{pub}$ 也是冻结的. 这样每个封闭专家看到的输入分布, 都是同一套冻结注意力产生的隐藏状态; 它学到的是「在公共专家旁边补充什么」. 合并时所有专家共享同一套注意力, 不需要像 BTX 那样对各模型的注意力取平均.

训练脚本 `train_expert_model.sh` 里的设置是: 学习率 $9\times10^{-4}$, warmup 2000 步, 50B token, 路由 `top_k`=2. 两个专家选两个, 每个 token 都同时经过公共专家和封闭专家, 路由器只决定两者的混合权重. 这也意味着 `olmoe_nx7b` 默认带的负载均衡损失 (系数 0.01) 在这一阶段不起作用: 当 $k$ 等于专家数时每个专家的分配比例 $f_i$ 恒为 1, 损失 $N\sum_i f_iP_i=2\sum_iP_i=2$ 是常数, 梯度为零. `capacity_factor` 1.2 同样不会触发丢 token.

用域嵌入初始化路由行. 路由行分头训练, 拼起来能否互相比较, 取决于它们的起点. FlexOlmo 用现成的文本嵌入模型 GritLM-7B 给每个数据源采样 1000 篇文档, 取嵌入均值作为初值:

$$\mathbf{r}_i=\frac{1}{|S_i|}\sum_{d_k\in S_i}\mathbf{E}(d_k),\qquad S_i\subset D_i,\ |S_i|=1000.$$

代码 `get_domain_embeddings.py` 以 GritLM 的 embedding 模式编码, 丢掉含 NaN 的行后求均值; `dense_to_expert_moe.py` 把拼好的 `concat_embed` 直接复制进每一层的路由权重. GritLM-7B 的嵌入维度恰好是 4096, 与 OLMo 2 7B 的隐藏维度相同, 所以可以原样拷贝. 这个初始化有两点要注意. 一是 32 层用的是同一个向量, 而各层隐藏状态的分布差别很大. 二是 GritLM 的嵌入空间和 FlexOlmo 隐藏状态的空间没有对齐关系, 初值只提供「不同领域的路由行彼此分开」这一点; 训练开始后 $\mathbf{r}_i$ 会在 LM 隐藏状态上重新学习. 表 3 比较了两种初值: 用公共模型自己的隐藏状态均值初始化 (Public) 平均 43.5, 用 GRIT 初始化 46.7, 差距主要来自 Code4 (8.7 对 18.2) 和 AGIEval (40.2 对 44.8). 文中没有给出 Public 初值取的是哪一层的隐藏状态.

§5.1 说随机初始化时最终学到的路由嵌入彼此高度相似, 合并后难以区分专家. 这个现象支持用域嵌入初始化, 但表 1 并没有单独隔离它: 消融行只有「no bias」(45.8) 和「no domain embedding init, no bias」(44.4), 两者相差 1.4 分可以归到初始化上, 前提是偏置与初始化之间没有交互; 「只去掉初始化, 保留偏置」这一行不存在.

负偏置: 论文写法与代码实现. 两专家训练只学到「$M_i$ 对 $M_\text{pub}$」的两两比较, 从没见过 $M_1$ 和 $M_2$ 竞争. 论文给每个封闭专家加负偏置 $b_i$, 并写成选择规则:

$$\mathbf{r}_i\cdot\mathbf{x}+b_i>\mathbf{r}_\text{pub}\cdot\mathbf{x}\quad\forall i\in\{1,\dots,n\},$$

满足时选 $M_i$, 否则默认 $M_\text{pub}$. 附录 D 把路由看成 $n+1$ 类分类, 训练时只学 $n$ 个二分类器 $f_i$, 推理时取 $F(\mathbf{x})=\arg\max_i s_i(\mathbf{x})$. 冻结 $\mathbf{r}_\text{pub}$ 让所有二分类器共用同一个参照, 负偏置把每条决策边界 $h_i$ 推向 $C_i$ 的数据点, 使 $f_i$ 学到的更接近「$C_i$ 对非 $C_i$」.

![](images/negative_bias.png)

> 图 5: 负偏置使 $C_\text{pub}$ 与 $C_1$ 之间的决策边界向 $C_1$ 收缩, 原文 Figure 6

**图 5 解析**: 图中两类点分别是公共数据和封闭数据 $C_1$. 不加偏置时, 任何把两类分开的直线都满足约束, 边界可以离 $C_1$ 很远, 把大片空白区域划给 $C_1$. 加上 $b_1<0$ 后, 只有 $\mathbf{r}_1\cdot\mathbf{x}$ 明显大于 $\mathbf{r}_\text{pub}\cdot\mathbf{x}$ 的点才归 $C_1$, 边界贴近 $C_1$ 的点云. 合并后, 一个既不像 $C_1$ 也不像 $C_2$ 的输入更可能落回公共专家, 而不是被某个封闭专家「顺手」接走.

代码与这段描述有三处差别. 第一, `MoERouterWithExpertBias` 里 $b_i$ 是可学习参数 (`nn.Parameter`, 形状为专家数减一), 前向时取 `torch.minimum(b, 0)` 保证非正, 加到除公共专家外各专家的 logit 上; 论文只说「加负偏置」, 没有说它可学习, 也没有给初值或训练后的数值, 代码里该参数用 `torch.empty` 创建. 第二, 训练时 `top_k`=2, 两个专家都参与计算, 偏置只改变 softmax 权重, 不存在「否则默认 $M_\text{pub}$」的硬选择; 附录 D 的二分类图景只对应 top-1. 第三, 公开脚本构建路由器用的是 `olmoe_nx7b`, 带偏置的 `with_expert_bias` 一行被注释掉, 运行名却写着 `top2_grit_learnbias`; HF 版的 `FlexOlmoTopKRouter` 也没有偏置字段. 表 1 中去掉偏置让不做 RT 的 FlexOlmo 从 46.7 降到 45.8, 但从发布的权重看不出偏置是否以某种形式并入了路由行.

可选的路由训练. RT 的前提是数据拥有者愿意在公开数据里挑出与自己数据相似的样本. 每个拥有者训练一个区分 $D_i$ 与 $D_\text{pub}$ 的二分类器: 以 $3\times10^{-6}$ 的学习率微调 2200 万参数的 snowflake-arctic-embed-xs, 训练集是两边各 25 万篇的平衡样本, 准确率很快超过 95%. 再从 $D_\text{pub}$ 中选出分类器最认为属于 $D_i$ 的样本作为代理集 $\hat D_i$, 要求 $|\hat D_i|\ll0.01\times|D_i|$. §3.3.3 原文把这里的公开数据集写作 $M_\text{pub}$, 按上下文应为 $D_\text{pub}$. 合并后, 在 $\hat D_1,\dots,\hat D_n$ 与 $D_\text{pub}$ 的均匀混合上共训练 5B token, 只更新路由矩阵. 脚本 `OLMoE-4x7B.py` 冻结全部专家, 路由 `top_k`=4, 学习率在脚本里被覆盖为 $2\times10^{-3}$, warmup 100 步, `lb_loss_weight`=0. 关掉负载均衡说明作者希望路由按领域偏斜, 不追求专家间均匀.

RT 的收益在两张表里不一致. 表 1 的四专家设定里, RT 把平均分从 46.7 提到 47.8. 表 2 的八专家设定里从 51.3 提到 52.4, 但分项有升有降: GEN5 从 53.2 升到 59.8, BBH 从 42.1 升到 46.4; MMLU Pro 从 34.0 降到 30.9, Math2 从 52.1 降到 48.5, Code4 从 18.6 降到 17.2. 代理集只能从 DCLM 网页里挑, 而数学和代码的封闭集 (Dolmino Math, FineMath, StarCoder) 与网页文本差别较大, 文中没有分析这几项下降的原因. 加上 1.1 节所说 RT 削弱了退出保证, RT 更适合当作一个可选的精度旋钮, 而不是默认配置.

### 实验口径与基线。

FlexOlmo 的实验分三层: 四专家 (public, math, educational text, code) 的小规模消融与基线对比 (表 1), 八专家完整设定 (表 2), 以及在 OLMo 2 7B 的 4T checkpoint 上加两个专家的扩展实验 (表 4). 三层用的样本数不同: 表 1 每个子任务 100 个样本, 表 2 和表 4 每个子任务 1000 个样本, 所以表 1 与表 2 的同名列不能直接相减. 基线都从同一个 $M_\text{pub}$ 出发, 在每个封闭集上不改架构地继续训练出 dense 模型, 再用不同方法合并; 只有 Unrestricted MoE 是在全部数据的并集上训练的参照上界. 这一节先交代数据和评测口径, 再逐个看基线.

**FlexMix 数据与评测任务.** FlexMix 由一个 Public Mix 和七个封闭集组成, 统计在附录 B 的图 5 (一个以图编号的表格): Public Mix 2.37T token, News 158.0B, Creative Writing 201.9B, Math 20.3B, Code (StarCoder) 83.0B, Academic 58.6B, Educational Text 102.2B, Reddit 9.9B. 七个封闭集合计 633.9B. Public Mix 是 DCLM-Baseline 去掉新闻和创意写作后的部分, News 与 Creative Writing 则是用 WebOrganizer 的分类器从 DCLM-Baseline 里切出来的, 三者来源相同而互不重叠. Reddit 经过了检索筛选子版块和 GPT-4o mini 改写成学术问答两步处理, 附录 B 报告改写让 MC9 从 0.74 升到 0.76, MMLU 从 0.62 升到 0.66. 按每个专家 50B token 计, 各封闭集的训练轮数差别很大: Math 约 $50/20.3\approx2.46$ 轮, Reddit 约 $50/9.9\approx5.1$ 轮, Academic 不到 1 轮, Creative Writing 约 0.25 轮. §5.3 的脚注 4 说数学是最小的模拟封闭集, 数学专家训了三轮; 按图 5 的统计, 最小的封闭集是 Reddit, 数学专家约训 2.5 轮. 附录 B 正文写「Table 5 presents the statistics of our training data」, §4.1 写「Figure 5 in §B」; 统计实际在图 5, 表 5 是评测基准表.

评测按 OLMES 标准. §4.2 说 31 个任务, 10 个类别, 但编号里 BBH 和 Math2 都是 (6), 表 2 实际有 11 列类别: MC9, GEN5, MMLU, MMLU Pro, AGIEval, BBH, Math2, NewsG, PoemG, SciRIFF5, Code4. 把 AGIEval 和 BBH 各算一个任务时, $9+5+1+1+1+1+2+1+1+5+4=31$, 与「31 个任务」一致. 表 5 还列了 NarrativeQA, 它不属于 GEN5, 也不在 31 个任务里. 表 4 的两个 FLOPs 说法可以复算. 推理侧, 表注写三专家的推理 FLOPs 是 dense 的 2.5 倍. 每 token 的矩阵乘参数量, dense 为注意力 2.15B + FFN 4.33B + 输出头 0.41B $\approx6.89$B; 三个 FFN 时为 $2.15+3\times4.33+0.41\approx15.55$B, 比值约 2.26, 再计入与上下文长度相关的注意力项, 比值还会更低. 训练侧, 表注写「equivalent training FLOPs」, 按 token 数相等成立; 按计算量, 专家阶段是两专家全激活的 MoE, 前向约 $2\times11.2$ GFLOP/token, 反传的激活梯度与前向相当, 权重梯度只算可训的 4.33B, 合计约 $22.4+22.4+8.7\approx53.5$ GFLOP/token, 而 dense 退火约 $6\times6.89\approx41.3$. 公共专家退火加两个专家阶段合计约为 OLMo 2 三次退火的 $(41.3+2\times53.5)/(3\times41.3)\approx1.2$ 倍. 表 4 Pre-anneal 一行的八项均值为 42.99, 表中印 43.1.

**数据提取与隐私风险。**

FlexOlmo 让数据拥有者共享权重而不是数据. 权重本身是否会泄露数据, 是这套方案能否被采用的前提. §5.3 用 Carlini 等人的训练数据提取攻击做了一次实测, 并据此建议敏感数据配合差分隐私训练. 这一节先列论文口径和结果, 再对照仓库里的 `extraction_analysis.py` 看实际实现.

**实验口径与结果.** 论文口径: 从数学数据采样 10,000 篇文档, 每篇取 32 token 前缀, 用 top-k 50, top-p 0.95, 温度 1.0 采样 256 token 续写, 每个前缀采 10 次; 任一续写与原文的归一化 Levenshtein 相似度不低于 0.9 即算提取成功. 实现先在一个对小数据集训了 100 轮的过拟合模型上验证, 提取率 60%. 选数学数据的理由见 3.1 节, 按图 5 的统计它并不是最小的封闭集. 结果是: 没见过数学数据的公共模型 0.1%, 数学专家 (dense) 1.6%, 包含数学专家的 FlexOlmo 0.7%. 10,000 篇文档下, 0.7% 对应约 70 篇, 二项分布标准误约 $\sqrt{0.007\times0.993/10^4}\approx0.08\%$, 三个数之间的差距远大于抽样误差. 公共模型的 0.1% 不为零, 脚注 5 的人工检查把它归为前缀本身决定了续写: 即使从没见过该文档, 模型也会生成与原文吻合的文本. FlexOlmo 比 dense 专家低, 与路由把数学专家的权重稀释在 4 个专家之间一致.

代码实现与论文口径的差别. `extraction_analysis.py` 与正文有三处不同. 第一, 前缀从文档内随机位置 `idx` 截取, 不是从开头. 第二, 用作比对的「原文」是从 `idx` 开始的 256 token 窗口, 包含那 32 token 前缀; 生成调用 `model.generate(max_length=256)`, `max_length` 包含输入, 实际只新生成 224 token, 解码结果也包含前缀. 两段文本共享 32 token 前缀, 相似度的下限因此被抬高; 按 token 粗算, 前缀约占比对长度的 $32/256=12.5\%$. 第三, `extraction_analysis.sh` 的默认 `NUM_PREFIXES=100`, 后面注释着 `#00`, 改成 10000 才是论文的口径; 源数据按 1% 比例抽样载入. 这些差别不改变「提取率很低」的结论方向, 但影响数字的可比性: 按正文复现得到的提取率与按仓库默认脚本跑出的数字不是同一个口径. 论文没有报告不同阈值或不同采样次数下的曲线, 也没有给出 FlexOlmo 在提取实验中激活了几个专家.

残余风险与差分隐私. 论文的结论是: 只要模型里有在某份数据上训练过的权重, 就可能有一小部分数据可被提取; 能接受这种少量泄露的拥有者可以直接用, 含隐私或敏感信息的拥有者应先用差分隐私训练专家. 差分隐私只作用于 $M_i$ 和 $\mathbf{r}_i$ 的本地训练, 与 FlexOlmo 的合并流程正交, 各方可以各自决定. 文中没有给出 DP 训练的专家在合并后的性能, 这部分代价需要另行评估. 提取攻击之外还有两类风险没有覆盖. 一是成员推断: 判断某篇文档是否在 $D_i$ 中, 所需信号比逐字复现弱得多, 0.7% 的提取率不代表成员推断同样困难. 二是 RT 的代理集分类器: 它在 $D_i$ 上训练, 准确率超过 95%, 本身就编码了 $D_i$ 的分布特征; 若拥有者把分类器或代理集交给协调方, 泄露面会大于单个专家. 这两点加上 4.3 节的退出验证, 是把 FlexOlmo 用在真实封闭数据之前需要补的实验.

## 2. 优化,路由与专家容量

本地训练冻结公共 attention 与其他共享参数, 更新领域 FFN 和对应路由. 两专家 Top-2 使公共路径持续参与计算, 域嵌入和负偏置则控制新专家在训练初期被选中的范围.

专家只能改变 FFN 路径, 能力上限受公共表示约束. 数据分布,重复 epoch 和专家数量会共同改变梯度与路由竞争; 推理时删除或加入专家后, softmax 还会重新归一化剩余权重.

### 2.1. 受约束优化与门控残差

**公共模型先固定共享表示.** 公共参数记作$\theta_s$,公共FFN记作$\phi_0$,公共路由行$r_0$. 它们先在$D_{pub}$上最小化

$$
\min_{\theta_s,\phi_0}E_{x\sim D_{pub}}[-\log p(x_t|x_{<t};\theta_s,\phi_0)]. \tag{1}
$$

每个拥有者$i$复制$\phi_0$为本地专家$\phi_i$,固定$\theta_s,\phi_0,r_0$,只优化$\phi_i,r_i,b_i$:

$$
\min_{\phi_i,r_i,b_i\le0}E_{x\sim D_i}\mathcal L_{LM}
(x;\theta_s,\phi_0,\phi_i,r_0,r_i,b_i). \tag{2}
$$

数据拥有者不上传梯度,不轮流更新共享骨干,私有数据影响被限制在本地FFN与路由参数. 合并只是张量拼接. 代价同样直接:$\theta_s$无法适应封闭域;若公共attention和embedding没有表示某种专门结构,FFN专家很难补齐.

两专家 Top-2 是门控残差. 训练时公共与本地两个专家都计算. 令权重$\alpha_i=e^{z_i}/(e^{z_0}+e^{z_i})$,输出

$$
y=(1-\alpha_i)M_0(h)+\alpha_iM_i(h). \tag{3}
$$

写$M_i=M_0+\Delta_i$,得到$y=M_0(h)+\alpha_i\Delta_i(h)$. 本地专家学习公共FFN之上的域残差. 初始$M_i=M_0$,无论路由权重如何,输出相同;专家偏离是逐步发生的,不会在第一步注入随机函数. 冻结锚点让所有机构都在同一个$M_0$坐标上定义$\Delta_i$. 各自继续训练完整dense模型会连attention和embedding一起漂移,合并时参数语义不再对齐;表1「no training to coordinate」下降7.9分支持这个问题.

负载均衡损失退化成常数. 常见辅助损失$L_{bal}=N\sum_jf_jP_j$. 两专家top-2时$f_0=f_i=1$,$P_0+P_i=1$,所以$L_{bal}=2$,梯度为0. 配置系数0.01实际不约束路由. 概率可以偏向一方,由LM loss,域初始化与偏置决定.

合并函数与退出. 每层沿专家轴堆叠$\phi_0,...,\phi_n$,沿路由行堆叠$r_0,...,r_n$,共享$\theta_s$只留一份:

$$
M_{final}=\operatorname{Concat}(\theta_s;\{(\phi_i,r_i,b_i)\}_{i=0}^{n}). \tag{4}
$$

无RT时删除第$i$组三元组即可消除其参数路径. softmax在剩余专家上重新归一化,即使同一输入以前从不激活$i$,输出概率也可能略变;「移除影响」指私有训练参数不存在,不保证所有输入logit保持不变.

共同参照消除坐标漂移. 二分类只由差值决定. 若每方都更新公共行,得到$r_0^{(i)}$,不同专家logit没有共同参照. 冻结同一$r_0$后,每个专家学习margin

$$
m_i(h)=(r_i-r_0)^Th+b_i. \tag{5}
$$

$m_i>0$表示相对公共专家更适合. 共同锚点消除最明显的不一致,没有保证不同域margin完全校准,因为各域难度,训练轮数和梯度尺度仍不同.

负偏置是 precision-recall 阈值. $b_i<0$要求$(r_i-r_0)^Th>-b_i$才触发专属专家. 绝对值越大,专属区域越小,误路由减少,漏路由增加. 若域内score均值$\mu_i$,标准差$\sigma_i$,触发率由阈值在该分布中的尾概率决定. 最优偏置依赖错用与漏用的代价. 论文描述硬分类,实际top-2训练中偏置改变softmax混合权重. 代码是否启用又与脚本注释冲突,必须查看训练后checkpoint里是否有bias参数,不能仅凭run名判断.

Pairwise 可分不保证专家间无冲突. 同一hidden state可能让$m_{math},m_{code}>0$,例如Python数值题. 两个专家从未彼此竞争,logit尺度可能不匹配. Top-4让二者共同激活,软混合缓解;top-1会被迫选一个. 域嵌入初始化和负偏置减少重叠,不提供多分类最优保证.RT用代理集联合校准路由能提升平均,也打破严格退出隔离.

GritLM 初始化只是一种方向先验. 1000篇文档embedding均值估计域中心. 异质域用单中心会丢失子簇;Math含公式与文字,Code跨语言. GritLM和OLMo隐藏空间虽同为4096维,没有坐标对齐证明. 将向量复制到32层主要让路由行初始彼此分散,随后由LM loss适配. 表3的GRIT 46.7高于Public 43.5,Code4差距尤其大. 这证明初始化有用,没有说明语义空间已天然对齐. 可比较训练前后路由行余弦,各层旋转程度验证.

### 2.2. 专家容量与异质数据

**每个专家约 4.33B 参数.** 32层SwiGLU三个矩阵:

$$
N_{expert}=32\times3\times4096\times11008\approx4.33\text{B}. \tag{6}
$$

这接近完整7B的六成,远大于LoRA. 八专家总约37.6B,top-4激活约20.3B对应矩阵. 总参数决定存储,激活参数近似计算;共享attention只算一次.

FFN 能改知识映射,无法重训 attention. FFN逐token作用,适合域术语,事实,风格与局部变换.Attention负责跨位置读取,已被冻结. 封闭域若需要新长程算法,特殊布局或更长窗口,专家受公共骨干上限约束. Code4提升说明公共模型已有代码表示,仍落后dense code专家可能反映共享层无法适配.

参数隔离不等于机密性. 专家输出,路由模式和权重都可能泄漏训练分布. 当前假设拥有者愿意交专家权重,只是不交原始数据. 若连权重也不能共享,还需远程调用,TEE或安全计算,论文未实现.

同为 50B token,epoch 数差很多. Math池20.3B约2.46轮,Reddit 9.9B约5.05轮,Academic 58.6B约0.85轮,Creative 201.9B约0.25轮. 本地专家训练计算相同,数据重复与覆盖不同.Reddit更易记忆具体样本,Creative只见部分库存. 专家质量差异同时来自域难度与epoch数. 不能将路由使用率或提取率只归因数据类型. 公平消融可固定epoch,但计算不等;或固定token,接受重复差异. 论文选择固定50B以对齐训练成本.

公共表示对各域起点不同. Public Mix从DCLM切出News和Creative,三者来源相近,互不重叠;公共模型仍可能从其它网页学到新闻和文学风格. Math,Code与Academic也可能在public网页中有相似内容. 专家不是从零学域,是在已有能力上增量训练. 若某域离公共分布近,公共专家已强,本地残差较小;离得远则需更大$\Delta_i$,路由更关键. 分项提升应相对公共基线读,绝对分还受评测难度.

Reddit 改写改变数据任务形态. Reddit 经过过滤后,用 MMLU 问题检索 151 个学术子版块,再由 GPT-4o mini 改写成七类 QA. 这已从自然讨论变成合成学术问答. 50/50 DCLM+Reddit 退火实验中,改写版使 MC9 从 0.74 升到 0.76,MMLU 从 0.62 升到 0.66,说明格式对评测迁移重要. 检索查询来自 MMLU 测试问题的改写,可能让数据选择贴近评测主题. 即使没有复制题面,开发反馈已进入数据管线. MMLU 增益应视作目标导向策展结果,不能完全代表开放域 Reddit 知识.

专家训练的梯度冲突被隔离. 普通联合MoE同时在混合数据上更新共享层和专家,不同域梯度可能冲突.FlexOlmo让各$\phi_i$独立,没有跨域梯度相消;推理时才组合. 共享层冻结也无法吸收各域协同信号. Unrestricted MoE看到全部数据,可以学跨域attention与联合路由,全数据全计算时平均51.5高于47.8. 数据隔离带来的3.7分差可看作当前约束成本的一部分,还混有FLOPs与具体基线设置.

**RT,路由尺度与所有权代价。**

**代理集怎样构造.** 每方用25万私有,25万公开文档微调22M分类器,从公开池挑最像$D_i$的少量样本$\hat D_i$. 合并后在所有代理集与公开数据均匀混合的5B token上只训练路由. 专家权重仍冻结. 代理集没有原始私有文本,却由私有分类器选择,携带域边界信息. 数学与代码在DCLM公开池里可能找不到充分代理,这可解释RT后Math2,Code4下降的方向,论文未做因果验证.

RT 为什么破坏严格退出. RT同时更新$r_0,r_1,...,r_n$. 更新梯度依赖$\hat D_i$,而$\hat D_i$由私有$D_i$训练的分类器选择. 删除$(\phi_i,r_i)$后,其它$r_j$与$r_0$仍保留经过该代理混合更新的值. 私有影响已扩散到剩余路由. 若目标只是停止调用某专家,RT可用;若合同要求撤回后参数完全无其影响,应使用no-RT或为每种专家集合重新训练路由. 后者组合数可达$2^n$,不现实.

平均提升掩盖任务交换. 八专家RT平均51.3到52.4,GEN5与BBH涨,MMLU Pro,Math2,Code4降. 路由训练优化代理LM loss,不直接优化各评测. 网页代理更匹配通用生成,可能牺牲专门域. 选择RT应按业务权重,不能只看平均+1.1.

每层每 token 都可换专家. 在第$l$层,位置$t$,路由logit$z_{l,t,i}=r_{l,i}^Th_{l,t}+b_{l,i}$,top-k集合$K_{l,t}$. 同一句话的不同token,同token的不同层可以走不同专家. 图2展示新闻提示中浅层与深层路由模式变化,支持细粒度组合. BTM先用整条输入算每个dense专家的负对数似然,生成全程用同一组模型权重. 对「解释一个数学算法并写Python」这类混合请求,整条选择难兼顾;FlexOlmo可让自然语言,公式和代码位置获得不同专家.

层级分工使路由解释更复杂. 浅层hidden state偏词形与局部格式,深层包含任务语义. 各层$r_i$独立,仅使用相同初值;训练后会分别变化. 观察某token激活Math专家,需说明在哪几层,权重多少,单一专家标签会丢信息. 可定义专家$i$的层位置使用率

$$
u_{l,i}=\frac1T\sum_t\mathbf1[i\in K_{l,t}], \tag{10}
$$

以及概率质量$q_{l,i}=T^{-1}\sum_t p_{l,t,i}$. top-k命中率与实际贡献不同:专家可被选中却权重极小. 论文行为图应结合两者解释.

激活数 k 改变函数而非只改算力. top-k后若归一化,输出权重在所选专家间重新softmax. 从$k=4$改2会删除两个贡献并放大剩余权重;改8会引入原来低logit专家. 因而k是模型定义的一部分,不是无损的推理旋钮. 论文完整模型用8专家top-4,HF七专家配置却`num_experts_per_tok=7`且`norm_topk_prob=false`. 全激活与未归一化权重改变计算和数值,不能把模型卡结果当论文top-4复现. 若未归一化,选中概率和可能小于1,MoE输出尺度随logit分布变化;残差与Norm可能补偿. 复现要锁`norm_topk_prob`.

**专家退出与组合扰动。**

**删除后 softmax 重归一化.** 原选中集合含$i$,概率$p_j=e^{z_j}/\sum_{k\in K}e^{z_k}$. 删除$i$且其余集合不变时

$$
p'_j=\frac{p_j}{1-p_i}. \tag{11}
$$

即使被删专家只占10%,其余贡献都放大约11.1%. 若删除后新的第$k+1$专家补入,集合也变化. 输出不是简单减去$p_iM_i$,还包含替代与归一化效应. 因此「删掉数据影响」是参数来源声明:没有任何保留参数曾由$D_i$直接训练. 函数行为必然变化,甚至无关域也可能小幅变化. 论文表明删除对应专家主要伤对应任务,其它任务相对稳定,属于经验模块性.

退出效果依赖路由专一性. 若Math专家只在Math token高权重,删除主要影响Math2;若路由在通用输入也常用Math,退出会广泛退化. 负偏置提高专一性,公共锚点提供fallback. 专家训练时始终与公共专家混合,使公共路径在域内仍保持参与,退出后不至于完全失效. 可以定义退出影响矩阵

$$
A_{ij}=S_j(M)-S_j(M\setminus i), \tag{12}
$$

行是删哪个专家,列是任务. 理想模块化矩阵接近对角. 论文展示若干退出结果,完整矩阵与置信区间更能检验.

多个专家同时退出. 单个退出稳定不保证组合退出. 删除两个后公共与剩余专家概率大幅重分配,原本由Math+Code协同的任务可能非线性下降. 合同或许可常会同时变化,应测试常见子集. 共有$n$个封闭专家时所有子集$2^n$,无法穷举. 可测单删,成对删,全删至public,再用交互项

$$
I_{ij}=\Delta_{ij}-\Delta_i-\Delta_j \tag{13}
$$

判断非加性. 大交互说明专家并不独立.

加入新专家也会扰动旧路由. No-RT追加新$r_{n+1}$后,它直接参与top-k. 如果logit尺度过高,可抢走旧专家token,即使新域无关. 共同锚点和负偏置降低风险,仍需校准新行范数与bias. 上线前应在旧评测集做回归,观察加入前后路由集合与分数. 「无需再训练」指技术上可拼接,不代表无需验证.

## 3. 风险,基线与实验解释

数据提取实验衡量独立专家与组合模型泄漏训练文本的风险, 但提取率会受采样次数,相似度阈值和攻击方法影响. 较低提取率不构成隐私保证, 路由输出本身也可能暴露输入所属领域.

基线比较则带着不同约束. Model soup,BTM,BTX 与 Unrestricted MoE 在是否共享数据,是否重复计算和是否允许联合训练上并不等价. 消融表只有结合这些约束,训练预算和任务聚合口径, 才能说明哪项机制带来收益.

### 3.1. 数据提取与威胁模型

**十次采样提高攻击成功率.** 设单次生成命中文档概率$q$,十次至少一次成功概率

$$
P_{10}=1-(1-q)^{10}. \tag{14}
$$

当$q$很小时约$10q$. 报告的0.7%是文档级十次攻击成功率,不能当单次输出概率. 更强攻击增加采样次数,优化prompt或访问logits,成功率可能更高. Top-k50,top-p0.95,温度1限制采样分布. Greedy可能更易复现高概率记忆,高温可探索低概率精确串. 一组解码设置无法给隐私上界.

相似度阈值混合了前缀. 代码比较的两段都含32 token共享前缀,最长256,理论基线相似度被抬高约12.5%. Levenshtein还受token解码,空格和重复结构影响. 正文说生成256 token,代码`max_length=256`只新增224,口径需修正后重跑. 更严格实验应从相似度计算中删除已知前缀,只比较新生成部分;同时报告0.8–1.0阈值曲线,最长公共子串与逐字exact match. 当前三模型用同一脚本,相对排序仍有参考价值.

FlexOlmo 低于 dense 专家的原因不唯一. 数学dense专家1.6%,FlexOlmo 0.7%. 路由稀释是一种解释:数学专家只占top-4一部分. 共享公共及其它专家的输出使精确复述概率下降. FlexOlmo专家本身训练方式也不同于dense继续预训练,冻结共享层可能降低记忆. 要分离,可强制FlexOlmo只激活Math,固定其权重为1,与dense专家比较;再逐步加入public和其它专家. 若单独Math仍低,差异来自训练参数范围;加入后才低则来自混合.

提取率低不构成 DP. 差分隐私要求相邻数据集$D,D'$的输出分布满足

$$
P[M(D)\in S]\le e^\epsilon P[M(D')\in S]+\delta. \tag{15}
$$

FlexOlmo没有给$\epsilon,\delta$,经验攻击失败只说明该攻击在该设置下没找到. 成员推断,属性推断,白盒权重分析仍可能成功. 本地DP-SGD需逐样本裁剪,加噪,只作用$\phi_i,r_i,b_i$. 专家4.33B参数,50B token下计算昂贵,噪声也可能伤域能力与路由. 论文列未来方向,没有性能曲线.

协调方可信到什么程度. 协调方持有公共模型和各方专家权重,可按许可拼装. 它被假设不会要求原始数据,但能检查,复制或离线运行专家. 若数据所有者担心权重逆向,当前协议不足. 协调方还决定专家索引,top-k,归一化和是否RT. 恶意配置可强制某专家高频激活,增加提取机会. 模型卡与可审计配置是治理的一部分.

数据拥有者也可能不诚实. 某方可在本地数据中植入后门,训练专家在触发词下输出恶意内容;公共锚点不会阻止$\Delta_i$学后门. 合并方无法查看原始数据,只能通过专家评测,参数扫描与行为测试发现. 负偏置使专家更选择性,攻击者可学习极窄触发区域而不影响普通评测. 专家可插拔让发现后易删除,上线前仍需供应链验证和签名.

路由泄漏域属性. 观察哪些专家被激活可推断输入属于数学,新闻,Reddit等域. 在医疗,法律或企业场景,域标签本身可能敏感. 即使输出不泄漏文本,路由遥测也需访问控制. 可只暴露最终输出,不返回路由日志;服务端仍持有. 隐藏路由不改变模型内部泄漏,只是减少外部观察面.

退出权依赖副本治理. 删除主服务中的专家不等于世界上所有副本删除. 协调方或下游用户可能已下载权重,蒸馏输出或缓存logit. 技术可拆卸性支持未来合规流程,无法强制撤回已复制artifact. RT版还含间接影响,无RT版也可能有公共数据与私有数据重合. 「退出」应明确范围:删除由该方训练的参数,还是保证任何相似知识消失. 后者通常无法实现.
