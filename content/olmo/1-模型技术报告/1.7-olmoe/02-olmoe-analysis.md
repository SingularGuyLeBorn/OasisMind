# OLMoE: 64 选 8 的细粒度 MoE 与全开放的设计消融

来源: Niklas Muennighoff 等, *OLMoE: Open Mixture-of-Experts Language Models*, arXiv:2409.02060, 2024 年 9 月首发, 后续版本在附录 I 补了 2025 年 1 月发布的 OLMoE-1B-7B-0125, 由 Allen Institute for AI (Ai2), Contextual AI, 华盛顿大学与普林斯顿大学合作完成. 权重, 数据, 训练代码与日志全部公开, 代码在 [allenai/OLMoE](https://github.com/allenai/OLMoE), 基座模型配置取自 HF 上 `allenai/OLMoE-1B-7B-0924` 的 `config.json`, 对照译稿见同目录 `01-olmoe-bi.md`. 同家族的 dense 前作见 [OLMo 1 解析](../1.3-olmo-1/02-olmo-1-analysis.md) 与 [OLMo 2 解析](../1.4-olmo-2/02-olmo-2-analysis.md).

## 1. 配置与参数核算

### 1.1. 1.3B 激活与 6.9B 总参数逐项复算

OLMoE-1B-7B 的骨架与 OLMo-1B (0724) 几乎一样: 隐藏维 $d=2048$, 16 层, 16 个注意力头 (MHA, 无 GQA), 词表 50,304, RoPE $\theta=10^4$, 上下文 4096, embedding 与输出头不共享. 差别集中在 FFN: 每层换成 64 个 SwiGLU 专家, 每个专家的中间维只有 1024, 每个 token 激活 8 个. `config.json` 里对应 `num_experts: 64`, `num_experts_per_tok: 8`, `intermediate_size: 1024`, `norm_topk_prob: false`, `router_aux_loss_coef: 0.01`. 按这些字段逐项计算参数:

| 部件 | 每层 | 16 层合计 | 每 token 激活 |
|---|---|---|---|
| 专家 FFN (SwiGLU, 无偏置) | $64\times3\times2048\times1024\approx402.7$M | 6.442B | $8/64$ 即 0.805B |
| 注意力 $W_Q,W_K,W_V,W_O$ | $4\times2048^2\approx16.8$M | 0.268B | 0.268B |
| 路由器线性层 | $2048\times64\approx0.13$M | 2.1M | 2.1M |
| embedding 与输出头 | 不按层计 | $2\times50304\times2048\approx0.206$B | 0.206B |
| 合计 | | 6.919B | 1.282B |

RMSNorm 与 QK-Norm 的增益向量每层 4 个, 共约 0.13M, 不影响前三位. 合计 6.919B 与 1.282B 分别对应 Table 1 的 6.9B 与 1.3B; Table 10 的脚注写明激活参数包含词表参数, 两个输入输出矩阵合计 0.206B, 单个 103M 与 Table 10 的 「# Vocab params 103M」 一致. 去掉这 0.206B, 非 embedding 的激活参数是 1.076B, 名字里的 「1B」 指的是这个量. 专家参数占总参数的 93.1%, 注意力只占 3.9%, 所以 「7B」 几乎全是专家.

这组数字还说明了 OLMoE 与 OLMo-1B 的关系. OLMo-1B 的 SwiGLU 中间维是 8192, 正好等于 $8\times1024$, 也就是说 OLMoE 每个 token 激活的 8 个专家拼起来, 与 OLMo-1B 一层 FFN 一样宽, 单 token 的 FFN 计算量相同, 只多一个 $2048\times64$ 的路由器. 总专家宽度是 $64\times1024=65536$, 为 OLMo-1B FFN 的 8 倍, 16 层合计 6.44B, 恰好是 OLMo-1B 全部 FFN 参数 (0.805B) 的 8 倍. 因此可以把 OLMoE 看成: 把 OLMo-1B 每层 FFN 横向放大 8 倍, 切成 64 份, 每次只用 8 份. 总参数 6.9B 又与 OLMo-7B 相当, 论文因此在 Table 4 里同时拿 1B 激活和 7B 总参数两档 dense 模型对比, 前者近似推理成本, 后者近似显存占用.

### 1.2. 与 dense 的受控对比: 3 倍 token 与 2 倍时间

§4.1.1 用一个受控实验确定激活与总参数: 一个 1.3B 的 dense 模型和一个 1.3B 激活, 6.9B 总参数的 MoE, 其余设置相同. Figure 4 显示 MoE 用约 1/3 的 token 达到 dense 的水平, 因为单 token 激活量相同, 按 FLOPs 也是约 1/3. 但 6.9B 参数要常驻显存, 专家分发还有额外开销, 吞吐从 dense 的每卡每秒 37,500 token 降到 23,600. 两者之比 $37500/23600\approx1.59$, 把 3 倍的 token 效率除以它, 得到约 1.9 倍的墙钟加速, 与正文 「只快约 2 倍」 吻合.

正式训练的吞吐可以从另一头验证. 附录 B 写的是 256 张 H100 训练约 10 天, 预训练加退火共 5,133B token, 平均每卡每秒 $5.133\times10^{12}/(256\times10\times86400)\approx2.32\times10^4$, 与受控实验的 23,600 只差 2%. 训练算力方面, 脚注 4 给的 OLMoE-1B-7B 预算是 $3\times10^{22}$, 对应 $6ND$ 取 $N=1$B, $D=5$T; 若按非 embedding 激活参数 1.076B 与实际的 5,033B 预训练 token 计, 是 $6\times1.076\times10^9\times5.033\times10^{12}\approx3.25\times10^{22}$, 论文的 $3\times10^{22}$ 是取整后的量级.

这组对比把 MoE 的收益拆成两层: 同样算力下 loss 更低, 但吞吐下降会吃掉一部分. OLMoE 后面的稳定性改动 (第 4.2 节) 还会继续降吞吐, RMSNorm 一项约 15%, QK-Norm 一项接近 10%, 两者叠加的总损失文中没有给出, 若按乘法独立计算约为 $1-0.85\times0.9\approx23.5\%$. 受控实验里的 23,600 是在这些改动之前还是之后测得的, 论文没有写; 正式训练的 23,207 与它接近, 说明最终配置下的实际吞吐落在这个量级.

**训练日程与学习率的三处写法。**

Table 10 给的预训练日程是: 每批 1,024 条长 4,096 的序列, 即 $1024\times4096=4{,}194{,}304$ 个 token; 预训练 5,033B token, 折合 $5.033\times10^{12}/4.194\times10^{6}\approx1.2\times10^{6}$ 个 step; 2,500 步 warmup, 峰值学习率 $4.0\times10^{-4}$, 余弦衰减到 $4.0\times10^{-5}$; 之后再用 100B token 线性退火到 0. OLMoE-Mix 共 4,060B GPT-NeoX token (Table 2), 预训练加退火共 5,133B, 正文记为 1.3 个 epoch, 按 $5133/4060\approx1.26$ 取整. 仓库里的预训练配置与此一致: `lr: 4.0e-4`, 余弦日程 `alpha_f: 0.1`, 即最低学习率为峰值的 10%; 退火配置从 `4.0e-5` 线性降到 0.

附录 B 的正文却写退火阶段 「学习率从 5.0E-04 线性衰减到 0」. 5.0E-04 在 Table 10 里属于 JetMoE 一列, OLMoE 的峰值是 4.0E-04, 余弦末端是 4.0E-05, 退火从末端开始, 起点应是 4.0E-05, 与退火配置相符. 2025 年版本的 Changelog 又写成 「max LR 5.0E-04 → 4.0E-05」, 前半与 Table 10 和配置都不一致. 三处写法里, Table 10 和代码配置相互一致, 可以作为准: 峰值 $4\times10^{-4}$, 余弦到 $4\times10^{-5}$, 退火从 $4\times10^{-5}$ 线性到 0.

0924 版的退火不换数据: 末尾 100B token 开始前把整个数据集重新打乱一次, 然后学习率线性降到 0, 做法沿用 OLMo 与 DCLM (见 [OLMo 1 解析](../1.3-olmo-1/02-olmo-1-analysis.md)). Table 13 的 DCLM 评测列了三个检查点: step 1,200,000 是退火的起点, 退火后的检查点即发布的基座, step 1,220,000 是不退火, 按原日程多训 20k 步的对照, 三者并列能把退火的增量与 「多训一段」 的增量分开. Table 7 的适配实验也用了退火前后两个检查点, 退火后的检查点在 SFT 后高 0.2, DPO 后高 1.4.

2025 年 1 月的 OLMoE-1B-7B-0125 保留第一阶段预训练, 改用 OLMo 2 13B 退火所用的那份 100B Dolmino 样本 (Table 15), 后训练换成 Tülu 3 的流程, 多了基于可验证奖励的 RL 一步. Table 16 的 OLMES 平均从 71.1 升到 72.7, 用 Tülu 3 评测设置的 Table 17 平均提高 10 分. 两张表的评测设置不同, 不能跨表比较; 0125 的改动全在退火和后训练, 第 2 至 4 节讨论的结构与预训练消融对两个版本都成立. OLMo 2 的 Dolmino 与 microanneal 见 [OLMo 2 解析](../1.4-olmo-2/02-olmo-2-analysis.md).

## 2. 选 8 为什么胜过更粗的专家

### 2.1. 粒度改变的是可组合路径

MoE 层先由路由器把输入 $x$ 映射为 $N_E$ 个分数, 对全部专家做 softmax, 再保留 top-$k$ 个专家. 若被选中的集合为 $T(x)$, 一层输出可以写成:

$$
\operatorname{MoE}(x)=\sum_{i\in T(x)}p_i(x)E_i(x),\qquad p(x)=\operatorname{softmax}(W_rx).
$$

OLMoE 没有在选出 top-$k$ 后重新归一化概率, HF 配置中的 `norm_topk_prob: false` 与此一致. 因而未入选专家虽然不执行 FFN, 仍通过全体专家参与的 softmax 分母影响被选中专家的权重. 这也解释了为什么路由器不只是在做离散开关: 专家 ID 决定计算路径, $p_i$ 还连续地缩放各路径输出.

在总参数与激活参数固定时, 把一个大专家切成多个小专家, 单 token 执行的 FFN 总宽度不变, 变化的是可以选择的组合数. 论文的受控设置从 8 选 1, 变为 32 选 4, 再变为 64 选 8; 三者可选组合分别是 8, 35,960 与 4,426,165,368. Figure 5 中, 32 选 4 相对 8 选 1 在约 130B token 处让 HellaSwag 与 MMLU Var 提高约 10%, 64 选 8 又提高 1 到 2%. 组合数增长了五个数量级, 后一段收益却明显变小, 所以组合数只能解释容量上限, 不能直接当作有效容量. 路由器是否学会分工, 数据是否支持这些分工, 以及通信开销是否可控, 都会限制实际收益.

64 选 8 因而是实验预算下的折中, 不是普遍最优点. Krajewski 等人的算力最优预测在 $3\times10^{22}$ FLOPs 附近指向 256 个专家, 但该预测针对算力最优训练; OLMoE 用 5T token 训练一个约 1B 非词表激活参数的模型, 属于明显的长训练区间. 论文没有测试 128 或 256 个专家, 不能由现有曲线推出继续切细必然更好. 可以确定的是, 从 32 到 64 仍有正收益, 同时收益已经递减.

### 2.2. 共享专家缩小了路由自由度

共享专家的直觉是把公共知识交给一个始终激活的 FFN, 把剩余计算留给专门化专家. OLMoE 的对照保持总参数, 激活参数与 FLOPs 不变: 基线为 32 个路由专家选 4 个, 共享版本为 31 个路由专家选 3 个, 再加 1 个固定激活专家. 两者的可选路由组合从 $\binom{32}{4}=35{,}960$ 降到 $\binom{31}{3}=4{,}495$, 减少 87.5%. Figure 6 中两者接近, 共享版本略差, 最终模型没有共享专家.

这个结果不等于公共计算无用. 它说明在该规模与该损失设计下, 预先指定哪部分参数处理所有 token, 损失的组合自由度超过了隔离公共知识的收益. 论文还指出一个相互牵制的地方: 若希望模型自行学出高频专家, 负载均衡损失又会惩罚长期偏向少数专家. 因而「是否需要共享专家」与「均衡约束有多强」不是彼此独立的开关. OLMoE 的结论只覆盖 `64 选 8 + LBL` 这一类训练方案.

DeepSeekMoE 路线在另一组专家粒度、激活预算和模型规模下给共享专家正面结果, 两者没有形成直接矛盾. 共享专家固定消耗一部分激活 FLOPs, routed experts 则保留组合自由度; 总专家数、每 token 的 top-$k$、共享宽度和负载约束都会改变取舍. 最小代码可以用 GateNet、top-$k$、逐专家前向和 gate 加权和复现数学语义, 但逐 token 的 Python 循环没有 token permutation、all-to-all 与 Grouped GEMM, 不能用于推断 OLMoE 的系统吞吐.

## 3. 路由, 初始化与辅助损失

### 3.1. token choice 用表现换取调度压力

expert choice (EC) 让每个专家从一批 token 中取固定数量, 天然保证每个专家工作量相同; token choice (TC) 则让每个 token 自己挑固定数量的专家. EC 对训练系统友好, 但一个 token 可能没有被任何专家选中, 也可能被多个专家选中, 而自回归解码每一步通常只有少量新 token, 很难复用训练时按整批排序的选择过程. TC 保证每个 token 都有 $k$ 条专家路径, 代价是不同 token 可能拥向同一个专家.

OLMoE 比较的是 dropless TC 与 EC. Figure 7 中 TC 在所列任务以及补充报告中的 PIQA, SciQ 上都更好, EC 的吞吐则约快 20%: 每设备每秒 29,400 token, TC 为 24,400. 最终选择 TC, 意味着训练系统需要承受不完全均匀的 all-to-all 通信, 再用负载均衡损失降低拥塞. 这项结果也有适用边界: 论文明确保留了多模态场景重新考虑 EC 的可能性, 因为丢弃部分噪声图像 token 的后果可能不同于丢弃文本 token.

### 3.2. 从零训练为何追过稀疏上循环

稀疏上循环先复制 dense 模型的 MLP 权重形成多个专家, 新建路由器, 再继续预训练. 它一开始就继承 dense 检查点的语言能力, 因而在追加算力很少时占优. OLMoE 把训练过 2T token 的 OLMo-1B (0724) 变为 8 选 2 的 MoE, 与从零训练的同配置模型比较. Figure 8 显示, 从零模型约在 500B token 追平, 约 600B token 后反超; 正式模型计划继续训练约 5T token, 所以没有采用上循环.

这里的差别不只来自训练长度. 复制同一个 MLP 会让专家从相同位置起步, 路由器需要在后续训练中把它们分化; 从零训练则允许路由与专家表示共同形成. 上循环还继承 dense 模型的结构决定. 作为起点的 OLMo-1B 没有 QK-Norm, 使用普通正态初始化, 而 OLMoE 的消融认为 QK-Norm 与截断正态初始化有助于稳定训练. 新路由器可以另行初始化, 已有层的初始化历史却不能重来. 论文尝试给复制权重加噪声, 没观察到改善. 因此这组实验支持的是一个带预算条件的判断: 追加训练只有几百 B token 时, 上循环能较快获得可用模型; 训练跨度达到数 T token 且准备改变稳定性配置时, 从零训练给出的终点更好.

**负载均衡损失防止死专家。**

对一个 batch, 设 $f_i$ 为实际路由到专家 $i$ 的 token 比例, $P_i$ 为分配给该专家的平均路由概率. 论文使用的辅助项为:

$$
\mathcal L_{LB}=N_E\sum_{i=1}^{N_E}f_iP_i.
$$

均匀分配时 $f_i=P_i=1/N_E$, 该式为 1; 当离散选择与概率质量同时集中到少数专家时, 损失增大. $f_i$ 来自 top-$k$ 选择, 对路由分数不可微, 梯度主要经 $P_i$ 回到路由器. 这项损失并不要求每个 token 的专家概率均匀, 它约束的是 batch 聚合后的使用量. OLMoE 预训练把它以 0.01 的权重加入交叉熵.

Figure 9 中, 加 LBL 的模型在训练 loss, C4 与 Pile 验证 loss 上都更好, 差异在训练几十亿 token 后已经出现. 不加 LBL 时, Figure 10 的第一层最初几乎把全部 token 交给专家 6, 后来才有一部分流向专家 1, 其余专家长期不工作. 这些参数占用显存却得不到有效更新. 因而 LBL 同时服务于优化和系统利用率, 代价是压制模型把某些领域长期集中到少数专家的自由.

适配阶段呈现了不同结论. Table 7 中, 不加 LBL 的 SFT 平均分为 54.0, 加 LBL 为 52.8; 接 DPO 后分别是 57.7 与 57.1. SFT 数据上的未加权 LBL 还从 12.22 略降到 12.16, Figure 33 的激活模式也基本不变. 这与后文的早期路由饱和相符: 预训练完成后, 短程适配不足以重排大部分专家选择. §4.3, Table 7 与 Figure 33 支持适配时关闭 LBL, 附录 B 却写 SFT 和 DPO 使用了它, 论文在此处存在前后不一致; 57.7 的发布结果对应 Table 7 中不加 LBL 的路径.

后训练中的路由还会遇到预训练实验没有覆盖的问题. Rollout 与训练引擎若使用不同 kernel、精度或 batching, top-$k$ 边界附近的微小数值误差可能把 token 送往不同 experts; 多个 mini-batch 更新又会让当前 policy 偏离生成 rollout 的旧 policy. Routing Replay 保存并重放专家选择, R2 侧重降低策略滞后, R3 侧重对齐推理侧路由. OLMoE 没有做 RL, 因而这些机制只能说明后续部署为何需要额外路由一致性检查, 不能算作论文已经验证的结论.

**router z-loss 约束分数尺度。**

router z-loss 对每个 token 的路由 logits $z$ 加入:

$$
\mathcal L_{RZ}=\frac{1}{B}\sum_{b=1}^{B}\left(\log\sum_{i=1}^{N_E}e^{z_i^{(b)}}\right)^2.
$$

它约束 `logsumexp` 的绝对尺度, 避免路由分数持续变大后使 softmax 数值范围恶化. 它与 LBL 分工不同: LBL 关心一批 token 分给哪些专家, z-loss 关心产生选择的 logits 是否膨胀. OLMoE 最终给 z-loss 的权重是 0.001. 论文的消融显示它对平均下游表现没有明确增益, 但减少了较大的 loss 尖峰; 因为正式训练跨越 5T token, 团队保留了这项低权重稳定器. 这不能推出 z-loss 能消除全部尖峰, 它只对路由器这一处数值尺度施加约束.

## 4. 路由在训练中学到了什么

### 4.1. 饱和度区分专家 ID 与专家权重

论文把中间检查点与最终检查点选中相同专家 ID 的比例称为路由饱和度. 对 64 个专家, 随机选择的期望基线在 top-1 时是 $1/64=1.6\%$, top-8 时是 $8/64=12.5\%$. Figure 20 在 C4 验证集随机 0.5% 上测量: 训练到 1%, 即 5,000 step 或约 20B token 时, 一些层的 top-8 饱和度已接近 60%; 到 40% 训练进度时, 最高约 80%. top-1 饱和得更慢, 后层通常早于前层, 第 0 层尤其慢.

饱和只比较集合成员, 不比较连续概率. 即使一个 token 在两个检查点选中了同样 8 个专家, $p_i(x)$ 的大小仍可变化, 专家内部参数也一直在更新. 因而 60% 饱和不表示模型 1% 时已经学完, 它表示多数计算路径的离散骨架很早形成. 第 0 层接收的表示最贴近词元嵌入, 后续训练中输入几何仍会随 embedding 改变; 论文只把它与第一层较慢的负载均衡联系起来, 没有证明单一因果机制.

早期饱和还能串起预训练与适配阶段的现象. 若大部分 token 的专家集合很早固定, SFT 时去掉 LBL 不会立刻造成大规模路由坍缩, 与 Table 6 和 Figure 33 一致. 反过来, 若希望在后训练阶段重新组织专家分工, 只关闭辅助损失可能不够, 还需要足够长的训练或直接作用于路由的目标; 这属于由实验现象得到的工程推论, 论文没有给出对应训练结果.

### 4.2. 共激活不是对称统计量

专家共激活统计「专家 $i$ 出现时, 专家 $j$ 也出现」的比例, 分母是专家 $i$ 的激活次数. 因此 $C(i,j)$ 与 $C(j,i)$ 一般不同: 一个低频专家可能总与高频专家同行, 后者却只偶尔与前者同行. 100% 表示每次选择 $i$ 都同时选择 $j$, 0% 表示从不同时出现. 若若干专家长期高度共激活, 可以怀疑它们存在冗余, 也可以在部署时把它们放在同一设备以减少通信, 但共激活本身不能证明专家功能相同.

Figure 21 对第 0, 7, 15 层绘制热力图, 整体没有很强的同层共激活, 只有少数组合例外. 第 7 层和第 15 层出现若干二元或三元组合. 这与细粒度设计的目标一致: 64 个专家没有退化为少数固定专家组. 论文题注称每图展示共激活最高的 32 个专家, 实际坐标轴各列 16 个专家; 读图时应以图中坐标为准. 第 7 层专家 48 与 23 的一个方向约为 60%, 后面的词表分析显示两者都偏向 Then, Therefore 一类连接词, 给出了共激活与功能相似之间的具体例子, 但不能推广到全部专家对.

**领域特化与词表特化彼此印证。**

领域特化统计某一领域的 token 被送往专家 $i$ 的比例. OLMoE 在 top-8 下的均匀基线为 12.5%. Figure 22 比较 GitHub, arXiv, Wikipedia, Books 与 C4: arXiv 和 GitHub 对部分专家有明显偏好, 第 0 层有一个专家对 arXiv 的激活比例接近 100%; 混合网页 C4 更接近均匀. 同图中的 Mixtral-8x7B 在各领域大多贴近其 25% 均匀基线. 论文把差异与 Mixtral 可能由 dense 模型上循环联系起来, 这是解释而非受控因果实验, 因为两模型的规模, 数据和训练配方也不同.

词表特化进一步把领域差异落到 token ID. Figure 23 显示后层的特化更强, 且后层更多地按预测输出 token 而不是当前输入 token 特化. 第 7 层专家 27 对若干西里尔字母和天城文字母等非拉丁字符的特化接近 90%; 专家 43 偏向地名; 专家 4 偏向 `sq`, `YR`, `GHz` 等计量单位, 与它在 arXiv 和 GitHub 上较活跃相符; 专家 3 偏向亲属称谓, 也与其在 Books 上较活跃对应. 这些例子说明领域路由不一定由抽象的「学科标签」直接驱动, 领域独特的词元分布本身就能形成稳定分工.

词表统计也有三个限制. 第一, token ID 由分词器决定, 一个专家偏好某段子词不等于它掌握完整概念. 第二, 路由发生在上下文化隐藏状态上, 同一个 token ID 在不同上下文中仍可走不同专家. 第三, 高特化描述的是条件频率, 不直接给出移除专家后的性能变化. 论文用「0% 时可删除而不影响该领域」解释指标端点, 但实际模型含 16 层和多条残差路径, 可靠的删减结论仍需干预实验.

## 5. 如何理解 OLMoE 的收益边界

### 5.1. 稀疏激活增加的究竟是哪一种容量

把 MoE 简写成「计算量不变, 参数变多」很方便, 但这句话会遮住最关键的一层: 新增参数并不会同时参与同一个 token 的计算。对 dense FFN, 输入 $x$ 经过一组固定参数得到 $F(x)$; 对 OLMoE, 输入还决定离散路径 $T(x)$, 实际函数是

$$
F(x)=\sum_{i\in T(x)}p_i(x)E_i(x).
$$

于是容量至少有三种口径。第一种是**存储容量**, 即 6.9B 总参数能记住多少规律; 第二种是**单 token 计算容量**, 即一次前向只调用约 1.3B 参数; 第三种是**条件组合容量**, 即不同 token 可以调用不同的专家子网。OLMoE 的优势主要来自第一种与第三种, 单 token 计算容量并没有增加。每次前向执行的 FFN 宽度保持 8192, 输入相关的 top-8 选择让不同 token 使用不同参数子集。

这个比喻还有一处容易被忽略。64 选 8 并不等于模型拥有四十多亿个彼此独立的子模型。相邻 token 可能只替换一个专家, 所有路径仍共享注意力层、嵌入、归一化和残差流; 即使专家集合不同, 专家输出也要在同一个隐藏空间里相加。组合数 $C(64,8)$ 描述的是路由集合的理论数量, 没有计算这些集合是否真的被数据访问, 也没有计算不同集合实现的函数是否足够不同。若两个专家学到接近的变换, 替换它们几乎不会产生新函数; 若路由长期只访问少数搭配, 大量组合只是纸面容量。

反过来, 组合数也低估了连续自由度。相同的八个专家可以有不同路由权重, 每个专家内部又随上下文产生不同激活。两个 token 即使拥有相同的 $T(x)$, 仍可能沿着完全不同的局部函数前进。因此理解细粒度 MoE 时, 更稳妥的对象是输入空间被路由器切成多少区域、每个区域调用哪些参数、区域边界在训练中如何移动，单看一个巨大的组合数解释不了这些变化。

路由器为专家 $i$ 产生线性分数 $z_i=w_i^Tx$。忽略并列分数时, top-$k$ 选择把隐藏空间分成许多由线性不等式围出的区域: 在某一区域内, 入选专家集合保持不变, 只有 softmax 权重连续变化; 穿过 $z_i=z_j$ 的边界时, 专家集合发生跳变。专家本身是非线性 FFN, 所以整个 MoE 是「分段选择 + 区域内连续混合」的复合函数。细粒度增加的不只是参数量, 还增加了这种条件分区的数量与可重组性。

这也解释 Figure 5 为什么会呈现收益递减。8 选 1 到 32 选 4 同时增加了路径组合和每次参与协作的专家数, 模型从单一路径跃迁到可组合路径; 32 选 4 到 64 选 8 虽然让理论组合数暴涨, 每个 token 的总 FFN 宽度仍保持不变, 单个专家还变得更窄。更窄的专家便于形成细分功能, 也更容易受有限样本、路由噪声和批次负载影响。等到现有数据已经覆盖不了新增分区, 继续切细便只增加调度难度。

### 5.2. top-k 前 softmax 带来的隐藏耦合

OLMoE 对全部 64 个分数做 softmax, 随后保留前 8 个, 且不在这 8 个内部重新归一化。设入选集合为 $T$, 输出权重总和为

$$
s(x)=\sum_{i\in T}p_i(x)\le 1.
$$

这个 $s(x)$ 会随路由分布的尖锐程度变化。若概率几乎都集中在前 8 个专家, $s(x)$ 接近 1; 若 64 个专家概率接近均匀, $s(x)$ 约为 $8/64=0.125$。因此路由器同时决定两件事: 哪些专家工作, 以及 MoE 分支整体以多大幅度写回残差流。若采用 top-k 后重新归一化, 第二个自由度会被拿掉, 选中权重永远和为 1。`norm_topk_prob: false` 使 OLMoE 的门控更接近带可学习总增益的稀疏混合。

这不是说低 $s(x)$ 必然把信号压坏。Transformer 有残差连接, MoE 输出只是残差更新的一部分; 后续 RMSNorm 又会调整尺度。真正需要留意的是, 路由概率的熵、MoE 分支幅度和残差比例彼此耦合。训练初期路由分数较平, 专家分支可能天然较小; 随着路由变尖, 分支幅度随之增大。专家学习与路由学习因而不在固定尺度下进行。

对单个入选专家, 忽略 top-k 边界的离散变化, softmax 给出的局部导数为

$$
\frac{\partial p_i}{\partial z_j}=p_i(\mathbf 1[i=j]-p_j).
$$

未入选专家不执行 $E_j(x)$, 却仍能通过 softmax 分母改变入选权重。也就是说, 「没被调用」不等于「完全没有影响当前前向」。不过这种影响只经过门控概率, 不会给未执行专家的 FFN 参数带来当前 token 的任务梯度。路由器可以从更广的竞争关系中学习, 专家本体仍只从分给自己的 token 学习。这种梯度不对称正是死专家难以自救的原因之一: 一个专家长期落在 top-k 外, 它的 FFN 缺少数据更新; 即便路由器后来偶尔把 token 分给它, 陈旧的专家输出也可能让任务损失把路由重新推开。

top-k 边界还带来局部不连续性。第 8 名和第 9 名分数很接近时, 极小数值扰动就会替换一条专家路径。训练使用大批 token, 这种替换通常被平均掉; 单 token 解码或跨实现复现时, 它会表现为路径差异。论文的结论主要来自固定训练栈, 不能据此假定任意精度、任意 kernel 都会逐 token 选择同一专家。复现若只核对最终平均分, 可能看不见路由轨迹已经不同。

**负载均衡损失约束了什么, 又漏掉了什么。**

令一批共有 $T$ 个 token, 每个 token 选择 $k$ 个专家。可以把专家 $i$ 的离散负载写成

$$
f_i=\frac{1}{Tk}\sum_{t=1}^{T}\mathbf 1[i\in T(x_t)],
$$

平均概率写成

$$
P_i=\frac{1}{T}\sum_{t=1}^{T}p_i(x_t).
$$

此时 $\sum_i f_i=1$, $\sum_iP_i=1$, 完全均衡时两者均为 $1/N_E$。$N_E\sum_i f_iP_i$ 在均衡点取 1。它偏爱「实际选择多的专家, 平均概率不要继续很大」, 从而给路由器一个把概率移向冷门专家的方向。由于 $f_i$ 经离散 top-k 得到, 常规反向传播不会穿过指标函数; 有效梯度主要来自 $P_i$。这是一种带滞后的控制: 当前批次先暴露谁过载, 再通过概率项修正下一步附近的分配。

单看这个内积会发现若干盲区。先, 它只看批次边际分布, 不看哪些 token 被送到一起。两个路由器都能让每位专家收到相同数量的 token, 其中一个按领域形成稳定分工, 另一个近似随机派发; 负载均衡值可以相同, 语言建模能力却差很多。再, 它不直接约束专家共激活。若专家总成对出现, 只要每对出现频率均匀, 边际负载仍然漂亮。再次, 它不检查每台设备的总负载。专家放置不均或高共激活专家集中在同一设备时, 专家计数均衡仍可能产生通信热点。

均衡也不等于每种数据都均衡。OLMoE-Mix 里网页 token 占绝对多数, 一个批次的全局均衡可能由网页样本主导。某个专家可以在 arXiv 上接近饱和, 只要 arXiv 占比小, 总体统计仍不突出。这恰好说明 Figure 22 的领域特化与 LBL 并不冲突: LBL 压制全局垄断, 没有禁止条件分布上的强偏好。若训练时按数据源分批, 每批统计又会产生不同压力; 论文给出的目标式不足以独立确定这种动态, 还需结合实际 batch 构造。

把 $alpha$ 调大也并非免费的保险。极强的均衡压力会迫使语义相近的 token 为满足配额而改走次优专家, 专家很难形成与数据真实频率相称的分工。自然语言里的模式本来就不均匀: 标点、常见连接词和普通网页远多于稀有文字、数学表达与代码。完全平均的利用率适合硬件, 未必对应最好的统计模型。OLMoE 的 0.01 是实验证明可用的折中点, 论文没有给出足以刻画整条权重曲线的扫描, 因此不能把它当成跨规模默认值。

更细的诊断至少要同时看四组量: 每层专家频率 $f_i$, 路由概率 $P_i$, 专家组合的联合分布, 以及条件于数据域或 token 类别的分布。若只见 $f_i$ 接近均匀, 最多说明没有明显死专家; 它不能证明分工有效。若再见验证 loss 改善, 才能说明均衡约束在该训练段没有压过任务目标。Figure 9 与 Figure 10 的价值就在这里: 一张给任务损失, 一张给使用分布, 两类证据共同指向 LBL 的收益。

### router z-loss 与负载均衡并不解决同一个问题。

softmax 对所有 logits 同时加常数保持不变:

$$
\operatorname{softmax}(z+c\mathbf 1)=\operatorname{softmax}(z).
$$

交叉熵通过路由概率观察门控时, 对这个公共平移方向缺少约束。路由器可以让全部分数一同漂移, 选择和概率几乎不变, 数值尺度却越来越不舒服。z-loss 对 $\log\sum_i e^{z_i}$ 的平方施加惩罚, 正好补上这一方向。它关注 logits 的绝对位置, LBL 关注不同专家之间的相对使用量; 两者看似都作用于 router, 几何方向却不同。

z-loss 也会间接影响尖锐程度, 但不能把它理解成简单的熵正则。假设所有 logits 同时减小常数, softmax 熵完全不变, `logsumexp` 却会下降。反之, 把最大 logit 抬高会同时改变绝对尺度与分布尖锐度。z-loss 对二者的反应混在一起, 其首要目标仍是限制归一化常数, 并不保证专家使用均匀。一个路由器可以保持 logits 数值温和, 同时稳定偏爱少数专家; 这时还需要 LBL。

梯度也能看出它的作用。对单个 token 记 $a=\log\sum_i e^{z_i}$, 则

$$
\frac{\partial a^2}{\partial z_i}=2a\,p_i.
$$

所有专家都会收到与概率成比例的梯度, 高概率专家承担更大修正。若 $a$ 很大, 惩罚迅速增强; 若 $a$ 接近零, 梯度相应减弱。平方形式因此像软性的尺度围栏, 而非固定裁剪。它能降低由 router 数值膨胀触发的风险, 对注意力、专家 FFN 或优化器状态造成的尖峰没有直接约束。

论文观察到平均下游指标没有明确提升, 大尖峰却减少, 这类结果很容易被排行榜视角低估。长达 5T token 的训练里, 稳定器的价值取决于尾部风险: 即使绝大多数 step 没有收益, 只要能降低一次不可恢复发散的概率, 就可能值得保留。可是消融运行较短、随机种子有限时, 「少一次尖峰」也可能含有随机性。OLMoE 最终使用 0.001, 合理解释是保守风险管理, 还谈不上已经找到了最优系数。

**dropless token choice 的统计含义。**

token choice 从每个 token 的角度保证计算预算: 每个输入都能得到 $k$ 个专家。expert choice 从每个专家的角度保证容量: 每个专家挑选固定数量 token。两者交换了保障对象。语言模型的监督发生在每个位置, token choice 让所有位置拥有相同数量的 FFN 路径, 梯度覆盖更整齐; expert choice 让专家批量更规整, 却可能让部分 token 得到过多、过少乃至零条路径。

若有残差连接, 零专家 token 不至于让网络断掉, 它仍能沿残差和注意力层传播。但这相当于在部分位置跳过 FFN 更新, 且跳过概率由路由竞争决定。高频、容易识别的模式可能更容易被专家选中, 难例和噪声 token 可能被系统性忽略。训练目标只看最终预测损失, 可以逐步适应这种缺口; 自回归生成时每个新 token 都关系到后续上下文, 训练中形成的选择偏差未必无害。

dropless 又把 token choice 推到更明确的一端: 不靠固定 capacity 抛弃溢出 token。它消除了「路由选中了专家, 系统却因容量不足没有执行」之间的语义裂缝, 代价是实际负载取决于批次。假设每个 token 独立均匀选择专家, 单个专家收到的 token 数近似服从二项分布, 均值为 $Tk/N_E$, 方差随批量与选择概率变化; 学到的路由带相关性后, 尾部会比独立假设更重。系统必须为最大负载而等待, 所以平均均衡不代表每一步都快。

这项选择也影响实验可解释性。dropping 会给模型引入随拥塞变化的隐式噪声, 相同路由概率在不同 batch 里可能执行不同路径; dropless 让论文分析的「被选专家」更接近真正执行的专家。Figure 20 的路由饱和、Figure 21 的共激活和 Figure 22 的领域特化因此有较清楚的对象。如果存在容量丢弃, 这些统计还应区分 router 原始选择与实际执行, 否则容易把系统调度行为误认为模型分工。

**从零训练与上循环是两种不同的优化起点。**

把一个 dense FFN 复制成多个专家时, 初始阶段所有 $E_i(x)$ 几乎相同。若路由权重之和固定, 选择哪组专家对主任务输出影响很小; 路由器收到的区分信号也弱。加入随机噪声可以打破对称, 但噪声太小不足以形成持续差异, 太大又会破坏已有函数。OLMoE 的补充实验没有从加噪中得到收益, 表明「制造不同」本身并不够, 差异还得与数据和损失形成有用对应。

从零训练的情况相反。专家参数一开始就不同, 早期路由选择会让各专家看到略有差异的数据, 数据差异再推动参数进一步分化, 形成正反馈。LBL 在这里充当护栏, 避免早期随机优势把某个专家变成赢家通吃。Figure 20 显示离散路由很早便与终局高度重合, 与这套共同形成机制相符: 专家分工的骨架在训练早期出现, 后续数万亿 token 更多是在既有分工上精炼表示。

上循环拥有另一种优势: dense 模型已经把通用语言规律压进 FFN, 复制后立刻可用。追加预算较小时, 从零模型还在学习基本能力, 上循环自然领先。随着训练延长, 复制起点的同质性和 inherited hyperparameters 逐渐成为束缚, 从零模型才有机会追上。OLMoE 在约 500B token 追平、约 600B 后反超, 给出了该配置下的交叉点; 换更大的 dense 起点、不同路由、不同追加数据, 交叉点会移动。

还要区分「相对追加算力」和「从项目开始计算的总算力」。上循环模型先花 2T token 训练 dense, 再花至多 610B token 训练 MoE; 从零对照只计算后面的 610B。若项目手里已经有 dense 检查点, 前 2T 属于沉没成本, 上循环早期优势很实用。若从头规划同一总预算, 就要把 dense 预训练也算进去, 结论可能更偏向直接训练 MoE。论文关于 25% 原模型预算追平的说法采用前一种追加预算视角, 不应误读为完整生命周期只需四分之一算力。

### 稳定性改动为何要和 MoE 一起读。

OLMoE 除了稀疏专家, 还改变了初始化、归一化、QK-Norm 与 AdamW epsilon。若直接拿最终 OLMoE 和早期 OLMo dense 模型比较, 性能差不能全部归给 MoE。论文专门做受控消融, 正是为了拆开这些因素。这里还可以继续追问: 为什么稀疏结构会让稳定性选择更敏感?

一层 dense FFN 的每个参数都能在大量 token 上持续收到梯度。MoE 专家只处理路由给自己的子集, 每位专家的有效 batch 更小, 数据分布也更偏。即使全局 batch 很大, 某个专家看到的梯度仍可能具有更高方差。路由边界移动还会改变它下一步的数据分布。初始化若产生异常大激活, 不只会污染当前层, 还可能影响路由选择, 继而让异常专家得到更多或更少样本, 把一次尺度问题放大成训练路径差异。

截断正态限制初始权重尾部, 减少极端神经元; RMSNorm 给残差流提供可学习尺度; QK-Norm 控制 query 与 key 的范数, 避免注意力 logits 因内积过大而变尖; 更小的 AdamW epsilon 改变二阶矩很小时的有效步长。这些改动落在不同位置, 最终都影响隐藏状态的尺度与梯度传播。路由器直接读取隐藏状态, 所以注意力侧的稳定性也会传到专家分配。

QK-Norm 的作用可从注意力式看出。普通注意力分数为

$$
a_{ts}=\frac{q_t^Tk_s}{\sqrt{d_h}}.
$$

当 $q_t$ 或 $k_s$ 范数持续增大, 分数绝对值随之扩大, softmax 接近硬选择, 梯度集中在少数位置。对 Q、K 做归一化后, 内积更多反映方向相似度, 尺度漂移受到约束。论文观察到它避免一次较大梯度范数尖峰并略降 loss, 同时吞吐下降近 10%。这是一笔用稳定性换速度的交易, 其收益不能仅按平均 loss 差衡量。

RMSNorm 的参数化增益也值得分清。归一化先把向量按均方根缩放, 再乘学习到的通道增益。非参数版本固定增益, 参数版本允许网络恢复各通道所需尺度。MoE 中不同 token 走不同专家, 写回残差的统计会更异质, 可学习增益提供了一层适配空间。不过论文的消融只能证明最终配置附近的经验收益, 没有把这种机制解释做成因果验证。

**专家特化应当怎样读。**

「专家 4 喜欢计量单位」是一条便于记忆的描述, 可它压缩了三个条件: 这是第 7 层的某个专家; 指标来自 C4 验证集的一个子样本; 特化按 token ID 的条件频率计算。换一层、换数据分布或换 tokenizer, 标签都可能变化。专家也不会只负责一个主题, top-8 让同一 token 同时经过多位专家, 单个专家通常承担若干相关或不相关的局部功能。

路由输入是上下文化隐藏状态, 并非裸 token ID。若同一个子词在数学公式、小说和代码中出现, 前文注意力已经把不同上下文写入表示, 路由器可以作出不同选择。按 token ID 汇总会把这些上下文混合, 最终看到的偏好只是平均效果。反过来, 某领域拥有独特词表时, token ID 本身就能强烈预测领域, 因此领域特化与词表特化很难完全分离。

要证明专家掌握某种能力, 观察相关性还不够。更强的证据是干预: 屏蔽该专家、替换它的输出、交换两个专家, 再测特定样本和对照样本的 loss 变化。若屏蔽「计量单位专家」只显著伤害包含单位的科学文本, 功能标签才更接近因果解释。若所有领域都一起下降, 它可能承担通用计算, 只是因 arXiv token 更常触发而显得专门化。OLMoE 论文提供了描述性统计, 没有完成这套因果定位。

共激活也要结合边际概率。设 $C(i,j)=P(j\in T\mid i\in T)$, 若 $j$ 本来就极高频, $C(i,j)$ 高并不稀奇。可以用提升度

$$
\operatorname{lift}(i,j)=\frac{P(i,j)}{P(i)P(j)}
$$

比较共同出现是否超出独立基线。`lift>1` 表示正关联, `lift<1` 表示互相回避。再配合点互信息、不同领域的分层统计, 才能分辨专家搭档源于功能互补、共同服务高频 token, 还是批次构成。论文的非对称条件比例适合发现候选关系, 不足以完成关系定性。

路由饱和度同样只回答一个窄问题: 中间检查点的专家 ID 与最终检查点重合多少。它不测专家函数是否稳定, 也不测路由概率排序的间隔。一个 token 的第 8、9 名反复交换会降低饱和度, 即便两位专家功能相近、输出几乎无差; 另一 token 的集合始终不变, 专家内部函数却可能彻底改写。将饱和度与输出差异、路由 margin、专家参数距离一起看, 才能得到更完整的训练动力学。

**评测数字中混在一起的因素。**

OLMoE-1B-7B 超过 OLMo-1B, 可能来自稀疏架构、数据混合、训练 token 数、稳定性配置和退火策略共同作用。Figure 4 的受控实验固定多数条件, 更适合回答「同等激活参数时 MoE 是否更省 token」; Table 4 的最终模型横向比较覆盖更多模型, 更接近使用者选型, 却不适合做单因素因果归因。这两类表格回答的问题不同。

激活参数也只是计算代理。一次前向的主要矩阵乘与激活宽度相关, 但路由器、token 排列、跨设备交换、专家 batch 尺寸和权重读取都会改变真实成本。总参数又只是显存代理: 量化精度、优化器状态、训练时是否保存梯度以及专家如何切分, 都会改变占用。Table 4 用 active params 近似速度、total params 近似内存是合理的统一口径, 不是性能预测公式。

同理, MMLU 接近 Llama2-13B 只说明特定评测设置下的一项结果, 不能推出所有任务都达到 13B dense 水平。Table 4 已经展示不同任务排序并不一致。小模型还更容易受多选题格式、长度归一化和 few-shot 示例影响, OLMES 固定这些设置提高了可复现性, 没有消除 benchmark 对真实应用的代表性问题。

SFT 后 GSM8K 大幅上升尤其能说明数据与能力测量的关系。预训练数学占比较低, 后训练加入 MetaMathQA 等数据, 分数增长超过十倍。这个变化证明适配数据能快速显化任务能力, 却难以单独判断模型在预训练时已经形成多少数学表示。模型可能学会了题型与输出格式, 也可能确实补足推理模式。若要区分, 需要污染检查、分布外题型、答案扰动与过程验证, 不能只看一个汇总准确率。

0924 到 0125 的比较也必须保持评测列对齐。OLMES 表中平均提高 1.6、MMLU 提高 2.1, 主要改动是 100B Dolmino 退火; Tülu 评测表里后训练模型平均提高 10 点, 同时换了 SFT、DPO 和带验证器 PPO 的整套配方。后一差值不能归给退火, 也不能直接与前一平均相减。两组实验共同说明末段数据和后训练仍能显著改变一个已训 5T token 的 MoE, 没有给出各改动的完整析因。

**用反例校准几个常见结论。**

第一个反例针对「专家越多越好」。若总激活宽度固定, 专家数增加会让单专家越来越窄; 当每个专家的中间维小到无法表达有用变换, 路由组合再多也无济于事。样本不足时, 每个专家得到的有效训练量还会下降。OLMoE 从 32 到 64 仍有小幅收益, 只能说明它尚未越过该实验的拐点。

第二个反例针对「均衡就是健康」。让 router 用 token 序号的哈希均匀分配, 可以得到极漂亮的负载曲线, 却没有语义路由。健康路由需要利用率、任务 loss 与可解释的条件差异同时成立。OLMoE 不加 LBL 时出现死专家且 loss 更差, 支持其配置需要均衡约束; 这不意味着越均匀越有能力。

第三个反例针对「早期饱和说明专家很早学完」。把专家参数持续随机更新而固定 router, 专家 ID 饱和度可以保持 100%, 函数却一直变化。OLMoE 的饱和曲线证明路径身份较早稳定, 不能替代对专家输出与参数演化的测量。

第四个反例针对「领域专家等同于知识模块」。若 arXiv 文本频繁包含 LaTeX 标记和计量单位, router 可能依据表面词元分布分流; 屏蔽该专家也许先伤害格式处理, 未必伤害科学知识。领域相关性是发现模块的入口, 因果功能仍需干预。

第五个反例针对「1.3B 激活就有 1.3B 模型的全部成本」。单机显存若放不下 6.9B 权重, 必须分片或卸载; 小 batch 解码又难以形成高效专家矩阵乘。此时延迟可能远高于 dense 1.3B。论文的训练吞吐已经展示同激活参数下 MoE 每卡 token/s 更低, 在线推理还会受工作负载影响。

第六个反例针对「共享专家没有用」。OLMoE 的固定预算对照里, 一个共享专家取代一个 routed expert 后略差。若扩大总激活预算、削弱 LBL、改变专家粒度或让共享专家承担不同宽度, 结论可能变化。实验否定的是特定构造在该规模下的收益, 没有否定共享计算这一设计空间。

**从论文证据可以继续做哪些检验。**

OLMoE 每 5000 step 开放检查点, 最适合研究「路由先定型、专家后精炼」这一假说。对固定样本集, 每个检查点记录 top-8 集合、路由概率、专家输出向量与最终 logits。集合 Jaccard 相似度测离散路径, Jensen-Shannon 散度测概率变化, 输出余弦距离测专家函数变化, 最终 KL 散度测预测变化。若集合早稳而输出仍持续变化, 就能把路径形成与能力学习分开。

专家替换实验可以测冗余。对同一 token, 把第 8 名专家替换成第 9 名, 或把高共激活专家中的一位换成频率相近的对照专家, 比较层输出和最终 loss。若大量替换影响极小, 组合数高估了有效容量; 若边界替换也造成明显变化, router margin 虽小, 功能边界仍可能很硬。

领域特化可用配对样本拆解。保留语义而改变表面格式, 例如把数学表达从 LaTeX 改成自然语言; 或保留常见单位 token, 把上下文从科学论文换成虚构文本。观察专家选择跟随语义还是词形, 能区分概念路由与词汇路由。再对专家做屏蔽, 才能检查路由偏好是否对应因果贡献。

均衡损失可以按层分析。论文统一使用系数 0.01, 但各层饱和速度和特化强度不同。记录每层 LBL 梯度与交叉熵梯度的夹角, 可以判断辅助目标是在帮助任务优化、与之近乎正交, 还是持续冲突。前层路由变化较慢, 后层较早饱和, 同一系数未必施加同等实际约束。

末尾是从随机种子验证设计结论。共享专家、z-loss 和若干稳定性消融的差异较小, 单条曲线容易混入训练随机性。开放配置使重复小规模实验成为可能。比起追求完全复刻最终分数, 更有价值的是固定数据顺序与预算, 改变种子后检查结论方向是否一致。若平均差很小而方差很大, 设计建议就应降级为候选偏好; 若多次运行都同向, 才更接近可迁移经验。

**路由与专家之间存在可辨识性问题。**

给某个专家贴上编号, 不代表这个编号有跨训练运行的稳定语义。若同时交换专家 3 与专家 17 的全部参数, 再交换路由器对应的两行权重, 模型函数完全不变。这种置换对称意味着两次独立训练中的「专家 3」没有天然可比性。比较专家功能时, 应先依据激活样本、输出向量或干预效果做匹配, 不能直接对齐 ID。

对称性也影响训练早期。随机初始化给专家带来微小差别, 第一批路由选择把这些差别放大; 换一个种子, 相同功能可能落到另一个编号上。论文展示的特化案例可以说明一条训练轨迹产生了分工, 无法证明某个固定 ID 必然承担该功能。真正稳定的对象更可能是「存在处理非拉丁字符的专家」这类集合性质。

还有函数分解的不唯一性。两个专家可以分别学习变换 $A$ 与 $B$, 也可以在门控权重配合下学习另一组线性组合而得到近似相同的总输出。残差网络又允许某层少做一点、后层补回来。于是单独观察专家权重很难还原其贡献。激活统计告诉我们模型把 token 送到了哪里, 干预实验才接近回答那条路径做了什么。

这种不唯一性并不削弱 MoE 的价值, 它只是限制解释方式。分析目标应从寻找一套唯一的专家词典, 转向寻找可重复的组织规律: 后层是否更依赖预测 token, 稀有文字是否更容易集中, 专家组合是否保持低共激活, 这些规律能否跨样本与随机种子出现。OLMoE 的开放检查点使这类研究可行, 论文自身主要完成了单次训练内的刻画。

### 专家学习速度并不均匀。

对专家 $i$, 有效训练数据来自路由事件构成的条件分布 $x\mid i\in T(x)$，并不覆盖全体 token。即使 LBL 让各专家数量接近, 样本难度、梯度范数与多样性仍可能悬殊。处理普通网页标点的专家会反复看到相似模式, 处理罕见文字的专家则可能看到少量但跨度很大的上下文。相同 token 数不意味着相同信息量。

门控权重还会缩放专家梯度。若输出为 $p_iE_i(x)$, 专家参数收到的任务梯度带有 $p_i$ 因子。两个专家都被选中一百万次, 一个长期位居 top-1、概率较大, 另一个总在第八名附近, 后者的有效更新可能更弱。计数负载均衡没有直接拉平这层差异。诊断死专家时, 除了路由次数, 还应观察累计门控质量、梯度范数与参数更新量。

这也给「激活 8 个专家」增加了一层解释。八条路径在计算上都执行, 对输出的影响未必接近八等分。概率若高度集中, 后几位专家更像低权重修正项; 概率较平时, 多位专家共同承担变换。top-k 只规定稀疏结构, softmax 形状决定实际协作强度。论文的组合数计算把所有入选专家视为等价参与者, 适合描述上限, 不足以量化有效专家数。

可以用逆 Simpson 指数刻画单 token 的有效参与数。先把入选权重在集合内归一化为 $q_i=p_i/\sum_{j\in T}p_j$, 再计算

$$
N_{\mathrm{eff}}(x)=\frac{1}{\sum_{i\in T}q_i^2}.
$$

八个权重相等时它取 8, 一个权重占绝对优势时接近 1。沿训练绘制每层的 $N_{\mathrm{eff}}$, 能补足 top-8 饱和度: 集合可能早早稳定, 集合内部的主次关系仍在变化。论文没有报告这项量, 因而无法从已有图判断 OLMoE 的八位专家究竟是均匀协作还是一主多辅。

**训练分布改变时, 路由可能先成为瓶颈。**

专家只在被路由到的数据上学习, 这使分布迁移形成两道关口。新领域 token 先要被 router 送到合适专家, 随后专家才有机会学习新规律。若 router 沿用预训练分工, 新数据可能集中压到少数旧专家; 若强行保持均衡, 又可能把相近样本拆散。dense 模型只有参数适应问题, MoE 还多了一层分配适应。

OLMoE 的 SFT 实验显示关闭 LBL 后整体路由分布变化不大, 说明这份适配数据与训练长度没有强行重写路由骨架。这个现象对温和域迁移是好事: 预训练形成的专家继续工作, 后训练不必重新协调全部路径。遇到新语言、新模态或代码比例骤增时, 情况未必相同。全局直方图不变也可能掩盖少量关键样本的路径变化, 因此还需逐样本饱和度和条件分布。

若直接冻结 router, 可以稳定专家分配, 代价是新领域只能在旧分区内学习; 若提高 router 学习率, 路径能快速调整, 专家接收分布也会剧烈漂移; 若只训练专家, 冷门专家仍得不到新数据。三种策略对应不同稳定性与可塑性。论文没有做这组对照, 但其早期饱和结果提示: 路由学习率、辅助损失和训练长度应一起设计, 单独切换 LBL 很难控制重组幅度。

0125 版用精选 Dolmino 再退火 100B token, 基础结构与第一阶段预训练不变, 最终 OLMES 平均提高 1.6。这说明既有路由骨架仍容得下更高质量数据带来的提升。可它没有回答改善来自专家内部更新、门控权重微调还是少数 token 换路。开放的 0924 退火前后与 0125 检查点可以用同一批样本比较, 把这三种变化拆开。

**路由 margin 决定路径有多牢固。**

top-8 集合只记录选中了谁, 没有记录第八名和第九名隔多远。定义 $m(x)=z_{(8)}-z_{(9)}$, 其中括号表示按分数排序。$m$ 很大时, 小扰动难以改变集合; $m$ 接近零时, 浮点误差、量化、隐藏状态微变都可能交换边界专家。两个 token 的饱和统计同为 100%, 鲁棒性仍可能完全不同。

margin 还连接训练与部署。训练时 BF16、分布式归约顺序和专家 kernel 共同决定数值误差; 部署可能换精度、框架和批量形状。若大量 token 的边界 margin 很小, 路由复现会变得脆弱。平均任务分数可能稳定, 逐 token 输出却难以严格一致。检查路由时应报告 margin 分布及低 margin token 的比例, 不能只报专家命中率。

边界交换是否有害取决于两位专家的功能距离。若第八和第九名输出接近, 路径变化几乎无影响; 若功能差异很大, 小扰动会放大。可定义局部敏感度为 $\|E_{(8)}(x)-E_{(9)}(x)\|/m(x)$, 同时考虑边界距离和替换后果。论文没有测这一量, 所以早期饱和只能说明 ID 稳定趋势, 还不能证明路由具备数值鲁棒性。

**MoE 的缩放不能只沿总参数轴理解。**

dense 模型常用参数量 $N$ 与训练 token $D$ 描述预算, 粗略计算量随 $ND$ 增长。MoE 至少需要总参数 $N_{total}$、激活参数 $N_{active}$、专家数 $E$、每 token 选择数 $k$ 和数据量 $D$。固定 $N_{active}$ 增加 $N_{total}$, 可以提高条件容量而少增矩阵乘; 固定总参数减小 $k$, 会降低计算却减少每个 token 获得的变换宽度; 固定两种参数继续增大 $E$, 则改变粒度和组合方式。

因此「更大 MoE」可能指三件不同的事: 总专家数更多, 每次调用的专家更宽, 或每个 token 同时调用更多专家。三者对 loss、显存和通信的影响不同。OLMoE 的粒度消融刻意固定总参数与激活参数, 因而隔离的是第三组结构变量; Figure 4 固定激活参数并增加总参数, 隔离的是稀疏容量。把两张图混成一条参数缩放曲线会丢掉实验设计。

每位专家得到的数据量约为 $Dk/E$, 这里只是均匀路由下的期望。OLMoE 中 $k/E=1/8$, 训练 5T token 后, 每层每位专家平均参与约 625B 次 token 路由, 数量并不少。若专家数提高到 256 而保持激活比例或激活宽度的方式不同, 单专家数据量会随之改变。极细粒度能否奏效, 不仅取决于组合数, 还取决于每个小专家是否得到足够而多样的训练信号。

**总参数增加不自动等于记忆容量增加。**

专家参数占用显存, 但只有被路由的数据能把信息写进去。一个长期冷门专家即使拥有数千万参数, 也可能处于欠训练状态。反过来, 热门专家反复处理相似 token, 参数利用率也可能受数据冗余限制。总参数是容量上限, 路由覆盖与条件数据熵决定有多少容量真正被使用。

可以把每位专家的训练覆盖拆成三项: 收到多少 token, 这些 token 来自多少独立文档与领域, 梯度在参数空间覆盖多少方向。第一项容易统计, 后两项更接近有效信息量。只用负载均衡让 token 数一致, 无法保证文档多样性与梯度秩一致。某专家可能收到海量重复网页模板, 另一位收到较少却复杂的数学和代码, 两者的学习负荷不能用计数直接比较。

若要验证 MoE 是否把额外参数转化为记忆, 可以对训练样本做影响或遗忘实验: 找出主要路由到某专家的样本, 屏蔽该专家后测这些样本与邻近未见样本的 loss 变化; 再比较同激活规模 dense 模型。训练样本下降远大于泛化样本时, 额外容量可能偏向记忆; 两者同步改善时, 更像学到可迁移模式。OLMoE 的公开数据和检查点支持这种研究, 原论文的下游评测没有直接区分两者。

### 残差连接让专家贡献具有层间补偿。

MoE 层输出写回残差流后, 后续注意力与专家层还能修正它。某层专家的输出幅度小, 不代表它无用; 它可能写入一个后来被放大的方向。某专家输出范数很大, 也不代表贡献大; 后层可能把该方向消去。用单层激活频率或输出范数给专家排名, 都会忽略层间因果链。

更可靠的干预应保持隐藏状态尺度。直接把专家输出置零会改变残差范数, 观察到的退化可能部分来自分布偏移。可以用同层其他专家的均值替换, 或保持输出范数只旋转方向, 再设置随机专家作为对照。若目标领域在多种干预下都特异受损, 才能更有把握地认为该专家承担相关计算。

层间补偿也解释了为什么单层路由看起来高度特化, 整体模型仍保持通用性。每个 token 在 16 层经历 16 次独立选择, 即使某一层偏向词形, 其他层仍可处理句法、实体和预测目标。完整路径是跨层专家集合的序列, 理论空间远大于单层组合; 同时共享注意力不断混合上下文, 使这些路径无法拆成互不相干的子模型。

**消融的可证伪边界。**

单次消融的结论必须携带控制条件。共享专家实验固定总参数、激活参数与 FLOPs, 因而能比较该构造下的共享与路由自由度; 它无法排除更大模型、不同共享宽度或不同均衡强度下出现反转。细粒度实验同样只覆盖 8、32、64 三个点, 64 优于 32 可以被复现实验直接检验, 却不能外推到 128、256 仍单调改善。

证据强弱还取决于效应量与随机方差。token choice 在多项任务同向领先, 同时吞吐代价明确, 结论较稳; 共享专家差距很小, 单种子不足以把微小差异写成定律; z-loss 主要减少尖峰, 需要多次长训练才能估计尾部风险。读消融时应问「怎样的复现结果会推翻它」, 找不到失败条件的说法只能算设计直觉。

**专家坍缩不只有死专家一种形态。**

最显眼的坍缩是少数专家吞掉大部分 token, 其余专家几乎不更新。Figure 10 展示的就是这种频率坍缩。频率均匀后仍可能出现功能坍缩: 多位专家接收不同 token, 却学出近似相同的映射。此时硬件利用率很好, 参数容量却被重复函数占据。还可能出现组合坍缩, 即专家边际频率均匀, 但总以固定小组共同出现, 可访问路径远少于组合上限。

另一类是梯度坍缩。专家被频繁选中, 门控权重却长期很小, 或其输出被残差与后层抵消, 最终获得的有效任务梯度很弱。领域坍缩则表现为总体使用均匀, 某个小领域的 token 全部挤到单一专家, 数据占比扩大后立刻形成瓶颈。LBL 主要针对频率坍缩, 共激活统计能发现部分组合坍缩, 其余形态还需要输出相似度、累计门控质量、梯度范数和条件负载共同诊断。

功能坍缩可以对固定样本构造专家输出矩阵, 计算专家间余弦相似度。高相似度只是一条线索, 因为两个专家可能在当前样本相似、在各自专属分布上不同。更强的检验是交换路由: 把原本给专家 $i$ 的 token 送给 $j$, 若 loss 几乎不变, 两者在该条件分布上确有冗余。对多个领域重复交换, 才能判断冗余是局部还是全局。

**平均负载与尾部负载控制不同成本。**

均匀情况下每层共有 $Tk$ 次专家调用, 平均每位专家 $Tk/E$ 次。系统不能只按平均值理解容量, 因为一步完成时间往往取决于最忙专家。记专家负载为 $n_i$, 可用 $\max_i n_i/(Tk/E)$ 表示负载放大率。它等于 1 时完美均衡; 达到 2 时, 即使其他设备空闲, 热门专家所在设备仍可能把该层拖慢近一倍。

批量越大, 独立路由下相对波动通常越小; 实际 token 有强相关性, 同一文档中的代码、公式或语言片段会连续触发相似专家, 有效独立样本数远小于 token 数。把长序列放在同一批次会制造局部热点。训练报告的平均吞吐把这些尾部折叠成一个数, 复现容量规划还需查看每步最大负载的高分位数。

dropless 保留全部 token, 容量压力不会表现为丢弃率, 而会表现为等待、额外 padding 或动态缓冲。若为了吞吐重新加入固定 capacity, 模型语义随之变化: 超额 token 走残差、后备专家还是直接丢弃, 都会改变训练信号。OLMoE 的模型结论与 dropless 条件绑定, 替换调度语义后只能算变体。

**计算预算需要分项核算。**

用激活参数估 FLOPs 时, 专家 FFN 主项约与 $kdd_{ff}$ 成正比, router 还需计算 $dE$ 个分数。OLMoE 的路由矩阵远小于八个 SwiGLU 专家的乘法, 把它视作小项合理。专家继续变细、数量继续增加时, $dE$ 线性增长, 主专家计算保持不变, router 占比终会变得显著。

FLOPs 没有包含数据移动。dense FFN 可以做规则的大矩阵乘; 专家并行还要统计目标、重排 token、跨设备发送、按专家成批计算, 再逆向聚合。相同理论 FLOPs 对应不同算术强度与通信量。Figure 4 中 token 效率约三倍、墙钟约两倍, 差额集中体现了这层成本。

训练内存还包括全部参数的优化器状态与梯度。推理只保存权重, Adam 训练通常还保存梯度和一阶、二阶矩; 未被当前 token 激活的专家仍属于优化状态。因此 MoE 的计算经济与内存经济方向不同。选型前要先确定稀缺资源究竟是训练 FLOPs、显存、设备间带宽还是在线延迟。

**从一个训练批次反推专家容量。**

OLMoE 的全局 batch 含 $1024\times4096=4{,}194{,}304$ 个 token。每个 token 选择 8 位专家, 所以一层每步产生 $33{,}554{,}432$ 次专家调用。若 64 位专家完全均匀, 每位专家每步收到

$$
\bar n=\frac{4{,}194{,}304\times8}{64}=524{,}288
$$

个 token。这个数字是全局计数, 不能直接当作一次 Grouped GEMM 的矩阵行数。训练框架先把 batch 切到数据并行、张量并行与专家并行组, 每张设备只处理其中一部分 token; all-to-all 再把属于同一专家的行发送到持有该专家参数的设备。若专家并行组大小为 $G$, 某设备持有 $64/G$ 位专家, 均匀情况下每层接收的专家调用总量仍约为本地输入 token 数的 8 倍, 只是这些行按专家 ID 分成若干矩阵乘。

容量因子可以用这个均值定义。若固定缓冲只容纳 $C\bar n$ 次调用, $C$ 就是 capacity factor。取 $C=1$ 只够装平均负载, 任何偏斜都会溢出; 取 $C=1.25$ 可给单专家多留 25% 空间, 代价是预分配缓冲、padding 与无效计算。OLMoE 使用 dropless 路由, 语义上不依赖固定容量丢 token, 但物理内存仍有上限。实现可以分块发送或按实际负载动态分配, 由等待时间和峰值内存承担偏斜成本。

把前文的负载放大率代入即可看到尾部有多贵。若一步中最忙专家收到 $1.5\bar n$, 该专家要处理 $786{,}432$ 次调用; 其余专家即便低于均值, 同步训练仍要等这条慢路径完成。若使用固定 $C=1.25$, 超出的 $131{,}072$ 次调用必须进入第二轮、转给后备专家或被丢弃。三种处理对应不同函数, 因此复现 OLMoE 时不能只写「top-8」, 还要记录超容量处理规则。

容量还受序列相关性影响。上式把四百多万 token 汇成一个全局平均, 实际调度的统计单位可能是单卡 microbatch。假设每卡某个 microbatch 只有 $M=16{,}384$ 个 token, 均匀时单专家期望调用数为 $Mk/E=2048$。若一批样本恰好集中在代码或 arXiv, 论文观察到的领域偏好会使少数专家远高于 2048。增大全局 batch 不能自动消除局部热点, 因为通信和专家计算在每个 microbatch 内发生。合理的容量测量应同时给出全局、专家并行组与 microbatch 三种尺度。

再看训练全程。按 5,033B 预训练 token 与 $k/E=1/8$ 计算, 每层每位专家平均参与约 $629.1$B 次调用; 100B 退火阶段再贡献约 $12.5$B 次。如此大的平均样本数解释了 1024 中间维的小专家仍能得到充分更新, 但平均值不包含数据熵。若某专家大量接收模板化网页, 六千多亿次调用仍可能高度重复; 若另一专家主要处理公式、代码与多语言碎片, 相同计数对应更复杂的条件分布。专家容量的完整口径至少包含参数数、调用数、样本多样性与门控质量四项。

### dense 与其他 MoE 应该怎样对照。

OLMoE 同时靠近两个 dense 参照。与 OLMo-1B 比, 每 token 的专家 FFN 总宽度同为 8192, 注意力骨架也接近, 适合比较固定激活计算下增加条件参数的收益。与约 7B dense 模型比, 权重存储量较接近, 适合比较固定模型容量下稀疏激活节省多少 FFN 计算。两种比较不能共用一句「同规模」: 前者控制计算规模, 后者控制存储规模。

设 dense 模型每层 SwiGLU 中间维为 $m_d$, MoE 有 $E$ 位宽度为 $m_e$ 的专家并选择 $k$ 位。忽略路由器后, 单 token FFN 参数参与量相等的条件是

$$
m_d=km_e,
$$

总 FFN 参数相等的条件则是

$$
m_d=Em_e.
$$

当 $k<E$ 时两式不能同时成立。OLMoE 取 $m_e=1024$、$k=8$、$E=64$, 所以激活参照的 dense 中间维是 8192, 总参数参照则是 65,536。任何「公平对照」都要先声明固定了哪一式; 同时声称计算量与总参数都相等, 等价于要求 $k=E$, 这时已经退回稠密执行。

与其他 MoE 横向比较时还要控制四个常被模型名遮住的变量。第一是 top-$k$ 后是否重新归一化, 它决定 MoE 分支总增益是否随路由熵变化。第二是共享专家是否占用固定激活预算, 同样写「激活 8 个」可能指 8 个 routed experts, 也可能包含始终执行的 shared experts。第三是 capacity 与丢弃策略, dropless 和带容量上限的模型训练函数不同。第四是训练数据与 token 数, 专家越细, 每位专家获得的条件数据越少, 训练跨度会直接影响粒度结论。

Mixtral-8x7B 在 OLMoE 的领域图上更接近均匀, 只能说明两份已训练模型表现出不同路由统计。Mixtral 的专家宽度、总规模、训练数据与初始化历史均未被控制, 不能据此断言粗专家天然缺少领域特化。DeepSeekMoE 的共享专家结果也类似: 它证明共享与细粒度路由在其配方中有效, 没有推翻 OLMoE 在固定预算消融中的轻微负结果。真正可比的实验需要在同一代码、数据顺序、总参数、激活宽度和训练步数下只替换专家构造。

归因还应把质量增益换算到同一资源轴。若模型 A 达到目标 loss 只用模型 B 三分之一的 token, 但单步吞吐为 B 的 0.63, 则墙钟优势约为 $3\times0.63=1.89$ 倍。若 A 需要更多设备才能放下总参数, 总设备时还要乘设备数。OLMoE 报告的约两倍墙钟优势来自同一硬件设置下的吞吐测量; 换成显存更小、互连更慢的集群, 专家分片数与通信比例上升, 该倍数不会保持不变。

**长上下文会改变路由输入分布。**

OLMoE 的预训练上下文长度为 4096。路由器逐 token 读取当前层隐藏状态 $h_{\ell,t}$, 再计算 $W_{r,\ell}h_{\ell,t}$。路由器本身没有显式查看整个序列, 可隐藏状态已经经过自注意力, 因而携带前文聚合结果。把上下文从 4096 扩到 32K 或 128K 后, 即使 token 词面不变, 更长依赖、位置编码外推误差与注意力分布都会改变 $h_{\ell,t}$, 随后改变专家排序和门控权重。

这种变化通常先在后层显现。浅层隐藏状态较多保留局部词形与短程组合, 后层更依赖全局语义和下一词预测。论文观察到后层路由更早饱和、且对被预测 token 的类别呈现差异, 说明后层专家选择与任务语境联系更紧。长文档加入远距离证据时, 后层 router 可能把同一个局部短语送往不同专家。4096 窗内测得的领域特化不能直接外推到更长窗口。

RoPE 扩展也可能单独扰动路由。设扩窗方法改变注意力输出 $a_{\ell,t}$, 残差流变为 $h'_{\ell,t}=h_{\ell,t}+\Delta a_{\ell,t}$。路由 logit 的变化为

$$
\Delta z_{\ell,t}=W_{r,\ell}\Delta a_{\ell,t}.
$$

当第八与第九位专家的 margin 小于对应分量的扰动时, top-8 集合就会交换。这里没有要求语言能力整体显著下降: 很小的隐藏状态变化已经足以翻转低 margin token 的离散路径。长上下文验证除了测 perplexity 和任务正确率, 还应按位置画路由熵、margin、最大负载比与相对 4096 截断输入的专家集合重合率。

位置相关的负载偏斜会形成新的系统瓶颈。若文档开头多为自然语言、后半逐渐进入代码或表格, 后段 token 可能集中到少数专家。prefill 一次处理整段时, 这种偏斜尚可通过大批量聚合; decode 阶段保留长 KV cache, 每步新增 token 很少, 路由又可能连续命中相同专家。平均每序列负载正常, 单步跨请求的专家分布仍可出现尖峰。长上下文部署需要按绝对位置与内容类型联合统计, 只汇总整条序列会把偏斜抹平。

扩窗微调若继续使用 LBL, 聚合轴也要明确。把所有位置放进同一批次统计, 高频的普通位置会压过长距离尾部; 按位置区间分别均衡, 又可能强迫本来稀少的远端模式平均使用全部专家。更稳妥的实验是先保持 OLMoE 原损失, 测量路由漂移, 再分别比较全局 LBL、分段 LBL 与冻结 router。三者回答不同问题: 全局 LBL 控制总体利用率, 分段 LBL 控制位置条件下的利用率, 冻结 router 检验旧分区能否承接新长度。

### 复现矩阵必须分开模型语义和运行时。

复现 OLMoE 可以先建立四层矩阵。模型语义层固定 $E=64$、$k=8$、专家中间维 1024、全体 softmax 后截取 top-8、top-k 内不重归一化以及 dropless token choice。优化层记录 LBL 权重 0.01、z-loss 权重 0.001、截断正态初始化、QK-Norm、RMSNorm、AdamW epsilon 与学习率日程。数据层记录 OLMoE-Mix 版本、tokenizer、4096 打包规则、样本顺序和退火数据。运行时层记录精度、专家并行组、token permutation、all-to-all 实现、Grouped GEMM kernel 与确定性设置。

这四层的优先级不同。模型语义层有一项不一致, 即使 loss 相近也只能称为结构变体; 优化层不一致会改变稳定性与收敛路径; 数据层不一致使最终能力无法逐项对表; 运行时层主要影响速度, 但浮点归约和 top-k 边界也可能反过来改变路径。复现报告把四层混成一张配置表时, 很难定位差异来自哪里。

最小的逐级验收可以用同一个固定 batch 完成。第一步只跑前向, 对每层保存 router logits、top-8 ID、门控权重、每专家 token 数与最终 logits; 第二步跑一次反向, 比较主损失、LBL、z-loss、router 梯度范数和若干专家梯度; 第三步训练数百步, 比较 loss 曲线、最大负载比与路由熵; 末尾才比较长程吞吐和下游任务。若第一步已经出现专家 ID 差异, 继续对齐最终榜单无法判断实现是否正确。

还可以构造三个小样本验证语义。令 64 个路由 logits 全相等, 未重归一化时选中权重总和应接近 $8/64=0.125$; 令前 8 个 logits 远高于其余项, 权重总和应接近 1; 令第八和第九位仅相差一个很小的 $\epsilon$, 改变精度或归约顺序后允许 ID 交换, 但应记录交换前后的专家输出差异。这三例分别检查 softmax 截取顺序、分支增益和边界敏感性。

训练复现不宜只对最终均值。OLMoE 的公开检查点能提供更强约束: 在约 20B token 附近检查各层 top-8 饱和趋势, 在训练中段检查共激活矩阵, 在最终检查点比较领域条件路由与词表条件路由。最终分数接近而中间统计完全不同, 说明实现可能通过另一条优化路径到达相似能力; 这对使用模型没有问题, 对复现实验的机制结论却不够。

**路由预算可以拆成离散选择与连续质量。**

top-$k$ 给每个 token 固定 8 次专家调用, 因而离散计算预算不随输入变化。连续门控质量却会变化。设入选权重和为 $s(x)=\sum_{i\in T(x)}p_i(x)$, 在集合内部归一化后的权重为 $q_i=p_i/s(x)$, 则 MoE 输出可改写为

$$
\operatorname{MoE}(x)=s(x)\sum_{i\in T(x)}q_i(x)E_i(x).
$$

右侧把路由的两个作用分开: $q_i$ 决定 8 位专家内部怎样分工, $s(x)$ 决定整条专家分支写回残差流的幅度。八次矩阵乘在两种情况下完全相同, 但若一种输入的 $s(x)=0.9$、另一种只有 0.2, 后者使用了同样的 FLOPs, 专家输出对残差的直接影响却弱得多。只报告 top-8 ID 和负载次数会漏掉这种差别。

用一个可复算的小例子看。假设前 8 位专家的 softmax 概率均为 0.1, 其余 56 位合计 0.2, 则 $s=0.8$、$q_i=0.125$, 有效参与数 $N_{\mathrm{eff}}=8$。另一枚 token 的前 8 位概率为 $(0.73,0.01,\ldots,0.01)$, 合计仍为 0.8, 内部归一化后第一位为 0.9125、其余每位为 0.0125, 有效参与数约为

$$
N_{\mathrm{eff}}=\frac{1}{0.9125^2+7\times0.0125^2}\approx1.20.
$$

两枚 token 的分支总增益和调用次数相同, 协作结构却分别接近八位均分与单专家主导。反过来, 两枚 token 可以拥有相同 $N_{\mathrm{eff}}$, 但 $s$ 差很多; 此时内部结构相似, 写回残差的强度不同。$s$ 与 $N_{\mathrm{eff}}$ 应作为两条轴统计。

这种分解还能解释 z-loss 与 LBL 为何没有直接控制有效参与数。LBL 聚合一批 token 的选择频率和平均概率, 不要求单 token 内部的 $q$ 平坦; z-loss 约束全体 logits 的 `logsumexp`, 也不直接规定前 8 位之间的间隔。模型完全可能同时拥有均匀的边际负载、稳定的 logit 尺度和高度尖锐的单 token 门控。若希望改变协作强度, 需要直接作用于选中权重熵或 margin 的目标, 但那会改变 OLMoE 已验证的训练配方。

连续质量也影响专家学习预算。专家 $i$ 在一个 batch 中的原始调用数为 $n_i=\sum_x\mathbf 1[i\in T(x)]$, 更接近梯度规模的加权调用量则是 $w_i=\sum_x p_i(x)\mathbf 1[i\in T(x)]$。两个专家可以有相同 $n_i$, 但 $w_i$ 相差数倍。进一步乘上每个样本的输出梯度范数, 才得到任务梯度暴露量的近似。因而复现矩阵中的负载统计至少应同时保存 $n_i$ 与 $w_i$, 否则「利用率均匀」只覆盖设备执行次数, 没有覆盖优化强度。

**反事实对照怎样定位收益来源。**

要区分路由选择和额外专家参数各自贡献, 可以在同一检查点上构造三种反事实。第一种保留每位专家参数, 把 router 的选择随机打乱, 同时维持每位专家边际负载; 质量下降反映语义分配的贡献。第二种保留原路由, 把 64 位专家替换为同一个平均专家或复制专家; 质量下降反映函数多样性的贡献。第三种保留专家与 top-8 集合, 把集合内权重改为均匀; 差异反映连续门控质量的贡献。

这三种干预都要保持尺度。随机路由若改变每位专家负载, 会把语义分配和容量拥塞混在一起; 平均专家若输出范数变小, 会把函数多样性和残差幅度混在一起; 均匀权重若把原先 $s(x)$ 强制改成 1, 又同时改变分支增益。更严谨的均匀化应令每位入选专家取 $s(x)/8$, 这样集合权重和不变, 只消除内部主次。

反事实还应按数据条件分层。若随机路由主要伤害 arXiv 与 GitHub, 对 C4 影响较小, 可以与 Figure 22 的领域特化互相印证; 若所有领域同步下降, 路由可能主要在分配通用的互补函数。若复制专家对稀有词元伤害更大, 可与词表特化图对应; 若影响只集中在常见 token, 则需要重新检查「稀有形式推动分工」的解释。

这些对照比直接屏蔽专家更容易归因。屏蔽一位专家同时减少计算宽度、改变输出尺度并扰动它负责的所有 token, 得到的大幅退化不一定说明该专家拥有独占知识。保持计算次数、负载和分支尺度后只交换一个因素, 才能回答 64 选 8 的收益究竟来自更多参数、输入相关选择, 还是集合内部的连续加权。OLMoE 的开放权重与数据索引使这套实验可以落到相同样本上, 也是全开放模型比只发布权重更适合机制研究的地方。

OLMoE 让约 1.3B 的激活计算按输入从 6.9B 参数库中取用, 核心收益来自这种稀疏激活。 与约 1B dense 模型相比, 它以接近的矩阵乘计算获得更低 loss; 与约 7B dense 模型相比, 它减少每个 token 的 FFN 激活量. 但权重仍要存储, 专家仍要跨设备交换 token, 所以总参数决定显存下限, 路由分布决定通信尾部延迟. 「1B 激活」不能等同于「所有方面都像 1B dense 一样便宜」.

论文最有价值的部分是把这项取舍拆成可核对的选择链: 细粒度增加组合路径, TC 保证每个 token 得到固定专家数, LBL 避免少数专家垄断训练, z-loss 控制路由 logits 的数值尺度, 从零训练允许专家与路由共同分化. 四类分析又显示最终模型确实形成了较早稳定, 少量共激活, 带领域与词表差异的路由. 这些证据共同支持 64 选 8 的配置, 但没有证明它是其他规模, 数据和硬件上的最优方案.

复现或部署时应分别监控三类量. 优化侧看交叉熵, LBL, z-loss 与各层路由 logits 的范围; 利用率侧看每专家 token 数, 最大与平均负载比, 死专家数量; 系统侧看 all-to-all 时间, 专家计算时间与端到端吞吐. 只看平均任务分数会漏掉路由坍缩, 只看专家使用均匀又可能压掉有用的特化. OLMoE 的开放检查点, 数据, 代码和日志让这三条线可以对应到同一次训练, 也使论文关于早期饱和和专家分工的结论具备可复查基础.

部署容量规划还要把 prefill 与逐 token 解码分开. prefill 能把许多 token 汇成较大的专家批次, 更容易摊薄分发开销; 解码阶段每条序列每步只产生一个新 token, 专家负载更碎, 热门专家造成的等待也更显眼. 因此训练吞吐的相对优势不能原样换算为在线延迟. 若采用专家并行, 设备放置还可参考共激活统计, 但同时要检查各专家的边际频率: 把一组常共同出现的热门专家放到同一设备, 可能减少一次通信, 也可能制造新的算力热点. OLMoE 给出的路由日志适合做这种回放测量, 最终分片仍应由目标硬件上的端到端结果决定.
