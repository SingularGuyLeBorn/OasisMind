# Bolmo: 把 Olmo 3 字节化

Bolmo 是 Ai2 在 2025 年 12 月发布的字节级语言模型, 论文为 arXiv 2512.15586 (v2 于 2026-02-09 更新), 作者来自 Ai2, 剑桥, 华盛顿大学和爱丁堡大学, 第一作者 Benjamin Minixhofer. 权重在 Hugging Face 的 `allenai/Bolmo-7B` 和 `allenai/Bolmo-1B`, 训练代码在 [bolmo-core](https://github.com/allenai/bolmo-core), 是 OLMo-core 的一个分支. 7B 版从 [Olmo 3 7B](../1.5-olmo-3/02-olmo-3-analysis.md) 经过中期训练和长上下文扩展后的 checkpoint 出发, 1B 版从 OLMo 2 1B (`OLMo-2-0425-1B`) 出发.

论文的做法叫**字节化 (byteification)**: 保留子词模型的 Transformer 主干, 换掉输入嵌入和输出头, 在主干两端接上在字节上运行的小型局部编码器和局部解码器, 再用一个边界预测器决定字节如何组成 patch. 总训练量是阶段 1 的 9.8B token 加阶段 2 的 39.3B token. 文中的超参数都与 `bolmo-core` 的训练脚本 (`bolmo_scripts/launch_stage{1,2}_7b.sh`) 和 HF config 做过对照, 两者不一致的地方单独写出.

## 1. 问题与路线

### 1.1. 子词分词的四个毛病

子词分词的问题可以归成四条. (i) token 内部的字符信息丢失, 模型虽然能隐式学到 token 由哪些字符组成, 在拼写, 字符计数一类任务上仍然吃亏. (ii) 分词偏差: 分词器决定边界时会看后文, 提示词停在半个词或以空格结尾时, 模型看到的 token 序列在训练中很少出现, 行为就会异常. (iii) 词表固定且有限, 预训练语料以英语为主, 词表也按英语优化, 其他语言的压缩率低. (iv) 算力分配与 token 绑定, prefill 时每个 token 花同样的计算, 每个 token 占同样的 KV cache. 子词分词的基本做法可以参考 [分词器与 Tokenizer](../../../llm-guide/3-预训练/3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md) 和 [训练 Tokenizer](../../../llm-guide/3-预训练/3.2-分词器与Tokenizer/3.2.1-训练Tokenizer/3.2.1-训练Tokenizer.md).

直接把 token 换成 UTF-8 字节能解决 (i) 到 (iii), 但序列平均长四倍以上, (iv) 反而更糟. 于是出现了「局部编码器 + 全局模型 + 局部解码器」的分层结构: 局部模型在字节上运行, 把若干字节池化成一个 patch, 深层全局模型只在 patch 序列上运行. patch 边界由模型内部决定时, 论文把这类模型统称为 LTLM (Latent Tokenizer Language Model), 前作包括 DTP, BLT 和 H-Net. UTF-8 主要为拉丁文字设计, 字节级模型在非英语上的低效可能依然存在. 论文脚注 2 把这一条记作「problem (ii)」, 按正文的编号, 多语言效率属于 (iii), (ii) 是分词偏差.

**字节化: 继承主干而非从头训练?**

论文认为字节级模型迟迟没有普及, 原因在于几乎所有工作都在从头训一个字节级模型, 再与同样从头训的子词模型比. 而主流子词模型的数据, 架构, 后训练都在快速迭代, 字节级模型若每次都从头追, 成本跟不上. 字节化的思路是直接继承一个训好的子词模型, 用不到常规预训练 1% 的数据把它改成字节级. 这把字节级模型的研发周期挂到了子词模型的发布节奏上: Olmo 3 出了, 字节化一次就有对应的 Bolmo.

字节化不是 Bolmo 首创. BLT 用现有子词模型初始化能对应上的参数, 然后当作从头训练; H-Net 让边界预测去匹配子词边界, 并加一个辅助的嵌入匹配损失. Bolmo 的不同在于两处. 一是架构专为字节化设计, 核心是非因果边界预测和边界符号融合 (第 2 节). 二是训练分两阶段: 先冻结主干, 让局部模型精确复现子词模型的行为, 再端到端训练 (第 3 节). 1B 规模的架构选择都在 OLMo 2 上快速跑阶段 1 定下, 然后原样搬到 Olmo 3 7B.

### 1.1. 架构

![Bolmo 架构](images/bolmo_architecture-cropped.png)

> 图 1: Bolmo 的整体结构, 从下到上是分词与嵌入, mLSTM 局部编码器, 带一字节前瞻的边界预测器, 池化, Transformer 全局模型, 反池化, mLSTM 局部解码器和 LM head, 原文 Figure 1

图左侧是 prefill, 右侧是解码. prefill 时整段输入一次性经过局部编码器, 边界预测器比较相邻两个字节的表示来切 patch, 每个 patch 取末项字节的表示送进全局模型. 解码时边界预测器不再参与, 下一个 patch 在哪里结束由 LM head 输出的「字节 + 边界」融合符号决定. 全局模型每个 patch 调用一次, 局部模型每个字节调用一次, 推理成本由两者的比例决定.

整个前向可以写成一串映射: $e=\mathcal{T}(x)$, $\hat e=\mathcal{E}(e)$, $p=\mathcal{B}(\hat e)$, $h=\mathrm{Pool}(\hat e,p)$, $\hat h=\mathcal{M}(h)$, $z=\mathrm{Depool}(\hat e,\hat h,p)$, $\hat z=\mathcal{D}(z)$, $y=\mathrm{LMHead}(\hat z)$. 其中 $x\in\{0,\dots,255\}^n$ 是字节序列, $h,\hat h\in\mathbb{R}^{k\times d}$ 是 $k$ 个 patch 的表示, 其余张量都是 $n\times d$. 局部模型与全局模型维度相同 ($d=4096$), 这是 Bolmo 与 BLT, H-Net 的一个重要区别.

**嵌入与局部编码器。**

字节嵌入表只有 256 行, 参数量可以忽略. Bolmo 借 BLT 哈希嵌入的思路把嵌入表做大, 但做法不同: 对每个字节, 找出以当前字节结尾的最长子词, 把这个子词在原词表里的嵌入加到字节嵌入上,

$$
e_i=\mathcal{T}_{\text{Byte}}(x_i)+\mathcal{T}_{\text{SubwordSuffix}}(x_{:i}).
$$

子词嵌入表直接沿用 Olmo 3 的 100278 行 (HF config 里 `subword_vocab_size=100278`, `add_expanded_embeddings=true`), 7B 上约 $100278\times4096\approx0.41$B 参数. 这些参数每个位置只激活一行, 查表几乎不花时间. 论文说去掉这张表, 改为加大局部编码器也能达到同样性能, 保留它是因为稀疏参数更便宜. 代码里 BLT 式哈希嵌入也实现了 (`ADD_HASH_EMBEDDINGS`), 但 Bolmo 的脚本把它关掉了.

局部编码器只有 1 层 mLSTM 加 1 层 SwiGLU FFN. mLSTM 是 xLSTM 里矩阵记忆的那一支, 递推形式与线性注意力同族, 见 [线性注意力机制](../../../llm-guide/2-核心原理与架构/2.5-线性注意力与状态空间模型/2.5.1-线性注意力机制/2.5.1-线性注意力机制.md). 表 7 给出的配置是 16 头, QK 维度 128, V 维度 256, 门控软上限 15, 输入门偏置初始化 $-10$, FFN 扩展维度 5504 (1B 为 2816). 一层就够, 是因为子词后缀嵌入已经把「这个字节处在哪个词里」的信息带进来了.

局部维度与全局维度相同, 省掉了升维投影. 作者最初试过更小的局部维度, 发现升维投影会限制表示的秩, 成为性能瓶颈. 附录 E 用嵌入矩阵的奇异值分析支持这一点.

![嵌入矩阵的秩](images/embedding_rank.png)

> 图 2: 多个开源模型输入与输出嵌入矩阵奇异值的解释方差比 (按维度归一化), 横轴是成分占比, 原文 Figure 9

曲线从左到右平缓下降, 直到末尾少数成分才陡降, 说明嵌入矩阵用满了大部分维度, 很难用低秩结构逼近. 若局部编码器维度是 $d_\ell<d$, 再用线性层升到 $d$, 池化表示的秩上限就是 $d_\ell$, 无法匹配子词嵌入. Qwen3-4B-Base 的输入嵌入是图中唯一例外, 论文没有解释原因. Bolmo 因此让局部模型与全局模型同宽, 7B 局部模型的参数量也随之增加.

**非因果边界预测。**

此前的 LTLM 都给边界预测加了因果约束: 第 $t$ 个字节之后是否放边界, 只能看 $\hat e_0,\dots,\hat e_t$. 这看似天经地义, 因为模型要预测下一个字节, 不能偷看它. 但子词分词器本身就在看未来. 以 `_Hello_Wor!` 和 `_Hello_World!` 为例, 两句到第 9 个字节 `r` 为止完全相同, 前一句切成 {`_Hello`, `_Wor`, `!`}, `r` 后面有边界; 后一句切成 {`_Hello`, `_World`, `!`}, `r` 后面没有边界. 子词 LLM 在 token 序列上是因果的, 但 token 本身是看了后文才切出来的. 因果的边界预测器无论怎么训练, 都不可能在这两句上给出不同的答案.

Bolmo 的修改是让边界预测多看一个未来字节,

$$
\mathcal{B}_{\text{Bolmo}}(\hat e)_t=\frac12\left(1-\frac{(W_q\hat e_{t+1})^\top(W_k\hat e_t)}{\|W_q\hat e_{t+1}\|\,\|W_k\hat e_t\|}\right)\in[0,1].
$$

这个余弦距离式与 H-Net 的路由模块相同, 区别只在比较的对象: H-Net 比较 $\hat e_t$ 与 $\hat e_{t-1}$, 预测的是「新 patch 从 $t$ 开始」; Bolmo 比较 $\hat e_t$ 与 $\hat e_{t+1}$, 预测的是「当前 patch 在 $t$ 结束」. 代码 `HNetBoundaryPredictor` 里 $W_q$, $W_k$ 是两个 $d\times d$ 无偏置线性层, 输出取 $\log(1-\cos)-\log2$ 作为边界对数概率, 推理阈值 `boundary_threshold="sample:0"` 等价于概率大于 0.5. 实现上还有两处固定处理: 序列第一个位置 (BOS) 强制放边界; 末项字节没有下一个字节可比, 填成「无边界」, 留给解码阶段决定.

![三种边界策略](images/bolmo_architecture_comparison-cropped.png)

> 图 3: 子词 LLM, 此前的字节级 LTLM 与 Bolmo 在 prefill 和解码阶段如何放置 patch 边界, 以 `the flowerbed` 为例, 原文 Figure 2

图 3 解析: 左栏的子词 LLM 在 prefill 时由外部分词器非因果地切分, 解码时边界随 token 内容一起隐式输出. 中栏的 LTLM 在两个阶段都用轻量预测器因果地切分, 按 H-Net 的做法会得到 `flowerb` 这种 patch, 因为它预测的是下一个子词的起点, 要等看到 `b` 才知道 `flower` 已经结束. 右栏的 Bolmo 在 prefill 时用一字节前瞻得到 `flower` 与 `bed`, 解码时由 LM head 决定当前字节后面是否接边界, 与左栏的子词 LLM 一一对应.

非因果预测只能用在 prefill. 解码时下一个字节还没生成, 只能换一个预测器: 在词表里加符号 `<b>`, 让局部解码器在每个 patch 末尾输出它. 于是 Bolmo 有两个边界预测器, prefill 用浅层的 $\mathcal{B}$ (带前瞻), 解码用深层的 LM head (不带前瞻). 这与子词 LLM 完全对应: prefill 由外部分词器切, 解码时 token 边界随 token 一起生成.

为什么不能像 H-Net 那样端到端学边界? H-Net 把边界分数接进计算图, 用分数平滑 patch 表示, 并对反池化表示用直通估计器. 在非因果设定下, 连续的边界分数里含有下一个字节的信息, bfloat16 下最多能泄露 16 bit, 足以唯一确定下一个字节 (256 种取值只需 8 bit). 模型可能借这个通道把未来信息传给解码器, 学到退化解. 所以 Bolmo 只用外部监督训练边界, 监督目标在阶段 1 和阶段 2 都是子词边界, 在第 5.2 节的高压缩实验里换成子词边界的子集.

**池化, 全局模型, 反池化与解码器。**

**池化**取每个 patch 末项字节的表示, 没有参数. 由于边界放在 patch 末尾, 末项字节的表示 $\hat e_t$ 已经编码了整个 patch, 这与子词模型「每个 token 一个嵌入」的位置正好对齐. 全局模型就是 Olmo 3 7B 本身: HF config 里 32 层, 隐藏维度 4096, 32 个查询头与 32 个 KV 头 (即 MHA), 每 4 层中 3 层是窗口 4096 的滑动窗口注意力, 1 层是全注意力, RoPE $\theta=5\times10^5$ 加 YaRN 因子 8, 原始上下文 8192, 扩展到 65536. 这些都原样继承, 字节化不改动主干的任何结构. Olmo 3 主干本身的设计见 [Olmo 3 技术解析](../1.5-olmo-3/02-olmo-3-analysis.md).

**反池化**在每个字节位置取最近一个已完成 patch 的全局输出 $\hat h$, 加到 $\hat e$ 的线性投影上得到 $z$. 局部解码器是 4 层 mLSTM + FFN, 比编码器多 3 层. 编码器可以借子词嵌入表减负, 解码器这一侧没有办法把 Olmo 3 的输出嵌入矩阵有意义地接回来, 只能靠加层补容量. 原来 100278 行的输出嵌入矩阵 (约 0.41B 参数) 被删掉, 换成 LM head 的小输出层.

**边界符号融合**解决的是 `<b>` 带来的长度问题. 若 `<b>` 作为单独符号, 每个 patch 后多一个位置, 解码器的输入输出长度就从 $n$ 变成 $n+k$. Bolmo 把输出词表从 256 扩到 512, 每个字节多一个「该字节后接边界」的版本, 解码器每一步同时预测字节和是否结束 patch, 长度回到 $n$. HF config 里的 `vocab_size` 是 520, 即 512 个融合符号再加若干特殊符号. 代价是 softmax 的类别数翻倍, 相对一层 4096 维的 mLSTM 可以忽略.

参数量方面, 7B 版共 7.63B, 比 Olmo 3 7B 的 7.30B 多 4.5%. 按表 7 的维度逐项算: 一层 mLSTM 的 $q,k$ 各 $4096\times2048$, $v$ 与输出门各 $4096\times4096$, 输出投影 $4096\times4096$, 合计约 67M; 一层 SwiGLU FFN 为 $3\times4096\times5504\approx67.6$M; 5 层共约 0.67B. 再加边界预测器的两个 $d\times d$ 矩阵 (约 34M), 反池化投影 (约 17M), 新增参数约 0.72B, 减去删掉的 0.41B 输出嵌入, 净增约 0.31 到 0.33B, 与论文的「约 330M」一致. 也就是说, 7B 版增加的参数几乎全在局部模型, 子词后缀嵌入表是从 Olmo 3 的输入嵌入直接继承的, 不额外占参数.

### 1.2. 两阶段字节化训练

**阶段 1: 冻结主干的子词到字节蒸馏。**

字节化开始时, 全局模型从 Olmo 3 checkpoint 初始化, 局部编码器, 局部解码器, 边界预测器和 LM head 随机初始化. 阶段 1 冻结全局模型, 目标是让这些新组件精确复现子词模型的行为. 精确的含义是: 损失取最小值, 当且仅当字节级模型与源子词模型完全一致. 损失由四项组成,

$$
\mathcal{L}_{\text{Stage1}}=\lambda_\mathcal{B}\mathcal{L}_\mathcal{B}+\lambda_\mathcal{E}\mathcal{L}_\mathcal{E}+\lambda_{\mathcal{D},\text{Distill}}\mathcal{L}_{\mathcal{D},\text{Distill}}+\lambda_{\mathcal{D},\text{CE}}\mathcal{L}_{\mathcal{D},\text{CE}},
$$

论文给的权重是 $\lambda_\mathcal{B}=4$, 其余三项都是 1. 第一项 $\mathcal{L}_\mathcal{B}$ 是边界的二元交叉熵, 标签 $\mathcal{B}_\text{subword}(x)_t$ 在每个子词末项字节处为 1. 有一字节前瞻, 这项很快就能到 99% 以上的准确率.

第二项 $\mathcal{L}_\mathcal{E}$ 训练局部编码器. 若池化表示等于对应的子词嵌入, 局部编码器加池化就能完美替代子词嵌入矩阵. H-Net 直接最小化两者的 L2 距离, Bolmo 受模型拼接研究的启发, 把两者都送过全局模型的前 $n$ 层再比较, $\mathcal{L}_\mathcal{E}=\|\mathcal{M}_{:n}(h)-\mathcal{M}_{:n}(\mathcal{T}_\text{subword}(x))\|$. 理由是相近的表示经过后续层未必仍然相近, 让误差在主干内部度量更贴近真实用途. 取 $n=4$ 时明显好于 $n=0$, 反向传播只需穿过 32 层中的前 4 层. 这里池化用的是真实子词边界而非预测边界, 以保证 patch 与子词一一对齐. 论文式中把这一项写成 $\mathrm{Pool}(\mathcal{E}(\hat e,\mathcal{B}_\text{subword}(x)))$, 与其他地方 $\hat e=\mathcal{E}(e)$, $h=\mathrm{Pool}(\hat e,p)$ 的记法不一致, 按上下文应读作 $\mathrm{Pool}(\hat e,\mathcal{B}_\text{subword}(x))$.

第三项 $\mathcal{L}_{\mathcal{D},\text{Distill}}$ 训练局部解码器和 LM head. 先把子词模型末层的表示 $z_\text{subword}$ 反池化后送进局部解码器, 得到 $\hat z_\text{subword}$. 对第 $i$ 个子词 patch, 字节模型给出的似然是 patch 内所有字节 (含融合了边界的末项字节) 的概率之积, 子词模型给出的似然是该 token 的概率. 因为 Bolmo 显式预测 patch 结束, 这两个似然在同一事件上定义, 可以直接比较. 没有输出边界预测的字节模型做不到这一点, 只能退而用近似. 比较函数是带温度的二元交叉熵 $f(\hat y\,\|\,y)=-\left(y^{1/\tau}\log\hat y^{1/\tau}+(1-y^{1/\tau})\log(1-\hat y^{1/\tau})\right)$, $\tau=5$. 第四项 $\mathcal{L}_{\mathcal{D},\text{CE}}$ 是同一路径上普通的下一字节交叉熵, 让模型提前开始利用字节信息.

**脚本里的实际取值**与论文有三处出入. 第一, `loss_weights=[1,1,1,4]` 与论文一致, 但编码器损失内部另有 `encoder_loss_no_lookahead_weight=0.0` 和 `encoder_loss_lookahead_weights=[0.0,0.0,0.0,4.0]`: $n=0$ 那项不参与, 只取第 4 层输出, 并再乘 4, 第 4 层表示损失的有效权重是 4 而非 $\lambda_\mathcal{E}=1$. 距离函数 `rep_compare_fn="l2"` 实现为 $\|x-y\|/\sqrt d$. 第二, 蒸馏用 `div_fn=kl`, 在对数域把 patch 概率除以温度后算二元 KL. 二元 KL 等于上面的二元交叉熵减去教师侧的二元熵, 后者与学生参数无关, 梯度相同, 这一处只是写法不同. 第三, 脚本开了 `do_alm_debiasing=true`, 给教师与学生两侧的 patch 对数概率各加一项「下一个符号属于空格类」的 logsumexp (掩码为 `space_mask_dolma2` 和 `space_mask_bolmo`). 这一项修正的是子词分词「token 通常以空格开头」带来的边界偏差, 论文式中没有它, 正文却称 $\mathcal{L}_{\mathcal{D},\text{Distill}}$ 是精确目标.

阶段 1 的训练量是 75K 步, 每步 32 条序列, 每条最多 4096 token (24576 字节), 合计 $75000\times32\times4096\approx9.83$B token, 按每 token 4.4 字节约 43.1B 字节. 峰值学习率 7B 为 $5\times10^{-4}$, 1B 为 $7\times10^{-4}$, AdamW, 权重衰减 0.1, 梯度裁剪 0.5. 脚本还关掉了 H-Net 的平滑与调制 (`hnet_smooth=false`, `hnet_modulate=false`), 与第 2.2 节「只用外部监督」一致. 阶段 1 还被当作架构筛选工具: 一种局部模型架构如果在阶段 1 后都模仿不了子词模型, 就认为后续训练也救不回来. Bolmo 的局部模型层数与宽度就是这样定下的.

**阶段 2: 端到端训练。**

阶段 2 解冻所有参数, 只保留边界损失与交叉熵, $\mathcal{L}_\text{Stage2}=\lambda_\mathcal{B}\mathcal{L}_\mathcal{B}+\lambda_\text{CE}\mathcal{L}_\text{CE}$, 其中 $\mathcal{L}_\text{CE}$ 用的是真实前向得到的 $\hat z$, 不再借子词模型的表示. 论文没有给出 $\lambda_\text{CE}$ 的取值, 脚本 `launch_stage2_7b.sh` 里 `losses=[ce,boundary]`, `loss_weights=[1,4]`, 即 $\lambda_\text{CE}=1$, $\lambda_\mathcal{B}=4$. 另一个变化是 `teacher_force_boundaries=false`: 阶段 1 前向用真实子词边界, 阶段 2 前向用模型自己预测的边界, 训练时与推理时的切分方式从这里开始一致. `do_alm_debiasing` 在阶段 2 关闭.

阶段 2 是 150K 步, 每步 64 条序列, 合计 $150000\times64\times4096\approx39.3$B token, 约 172.9B 字节. 学习率分组设置: 全局模型峰值 $1.8\times10^{-5}$ (脚本为 `1.83e-5`), 局部模型 $3.7\times10^{-5}$, 都是线性预热 15K 步后线性衰减. 全局模型的学习率很低, 只有阶段 1 局部模型学习率的 1/27, 用意是在适应字节输入的同时尽量少改动 Olmo 3 已有的能力. 基线 Olmo 3 CT 在同一份数据上继续训练同样的 39.3B token, 让全局参数接受的梯度更新量相同, 这个基线把「继续训练本身的影响」与「字节化的影响」分开.

表 8 的吞吐数字需要换算口径. 四组吞吐都满足 BPS $=6\times$ TPS: 7B 阶段 1 为 $59.4/9.9$, 阶段 2 为 $37.8/6.3$, 1B 为 $207/34.5$ 与 $166.2/27.7$, 比值都是 6.0. 6 正是 $24576/4096$, 即每条序列的字节槽位与 token 槽位之比; 而同一张表的 Total Training Bytes 用的是每 token 约 4.4 字节 ($43.1/9.8$, $172.9/39.3$). 若 TPS 是真实 token 吞吐, BPS 就计入了填充槽位, 有效字节吞吐约为表中数字的 $4.4/6\approx73\%$, 例如 7B 阶段 2 每卡约 27.7K bytes/s.

**阶段 1 是否必要。**

为了检验两阶段是否多余, 作者跑了直接从阶段 2 开始的对照: 局部组件随机初始化, 全局模型取自子词模型, 所有参数一起训. 两组比较要对齐算力. 论文的折算是阶段 1 约 $2\times\text{FLOPs}_\mathcal{M}$, 阶段 2 约 $3\times\text{FLOPs}_\mathcal{M}$ (前向 1 份, 反向 2 份), 所以去掉阶段 1 时给阶段 2 补 $9.8\text{B}\times2/3=6.5$B token, 阶段 2 长度增加 $6.5/39.3\approx17\%$.

## 2. 与 BLT, H-Net 等字节级模型的差异

### 2.1. 结构对照

表 1 的对照组里, EvaByte 不做 patch, 直接在字节序列上跑完整的 Transformer, 靠多字节预测提速; TFree-Hat 是 Aleph Alpha 的分层自回归 Transformer, 按规则在词边界切分; BLT 与 H-Net 是与 Bolmo 最接近的两个 LTLM. 下表只比较三个 LTLM 在几个关键维度上的做法, 数据取自各自论文以及 Bolmo 论文的描述.

| 维度 | BLT | H-Net | Bolmo |
|---|---|---|---|
| 边界来源 | 外置小字节模型的熵, 推理时也要运行 | 路由模块端到端学习, 比较 $t$ 与 $t-1$ | 外部监督, 比较 $t$ 与 $t+1$, 只用于 prefill |
| 解码时的边界 | 同一熵模型 | 同一路由模块 (因果) | LM head 输出的融合边界符号 |
| 池化 | 交叉注意力 | 取 chunk 内的路由位置 | 取 patch 末项字节 |
| 局部与全局维度 | 局部更窄 | 局部更窄, 需升维 | 相同, 无升维 |
| 局部层类型 | Transformer | Mamba2 | mLSTM |

第一行与第二行是 Bolmo 与两者的根本区别. BLT 的熵 patch 需要一个约 100M 的字节级模型在推理时持续打分; Bolmo 在第 5.2 节的熵合并实验里也用了一个 370M 的辅助模型, 但它只在训练时产生监督标签, 推理时不需要. H-Net 的边界端到端可学, 但只能因果; Bolmo 放弃端到端学习, 换来一字节前瞻, 并把解码时的边界交给语言模型头. 这对字节化尤其重要, 因为源模型的 patch 就是子词, 子词边界恰恰是非因果的.

字节化的起点也不同. BLT 做过从 Llama 3 初始化的字节化实验, 但训练流程与从头训练相同; H-Net 的字节化加了边界监督和 $n=0$ 的嵌入匹配损失. Bolmo 在两者之上补了三件事: 精确的 patch 似然蒸馏, 在主干前 4 层而非输入层度量的编码器损失, 冻结主干的阶段 1. 表 3 的消融与图 4 的对照分别对应前两件和第三件.

三种方法都有动态 patch, 解决的问题却不同. BLT 用熵变化调节计算落在哪里, H-Net 让路由与表示一起学习. Bolmo 要把已经训练好的子词模型改成字节模型, 同时尽量保住原模型的行为, 所以它先复现原分词器的结束位置, 再用冻结主干的蒸馏把局部模块接上去. Bolmo 的目标是转换现有子词模型; H-Net 研究模型自行学出语义分段, BLT 研究按信息密度分配计算量.

**主结果与对照口径。**

7B 主表上, Bolmo 7B 在所有公开字节级模型中各类别领先, 唯一例外是 GenQA 略低于 TFree-Hat (70.9 对 71.3). 摘要与引言里的「STEM 任务比 BLT 7B 绝对提高 16.5%」对应 MC STEM 一栏 $65.5-49.0$. 参数量口径也要看: BLT 7B 计入哈希嵌入后是 10.55B, BLT 1B 是 4.53B, Bolmo 7B 是 7.63B, Bolmo 1B 是 1.47B. 1B 的对比里 Bolmo 1B (套件均分 58.2) 略低于 BLT 1B (58.5), 但 BLT 1B 的参数是它的三倍; 相对源模型 OLMo 2 1B (58.3) 也低 0.1 分.

代码一栏需要单独看. Bolmo 7B 在代码类均值上超过 Olmo 3, 原因是 pass@16 更高而 pass@1「总体略低」. Code 类均值 40.7 对 39.5 是把 6 个任务的 pass@1 与 5 个 pass@16 共 11 个数一起平均得到的 (按此算法 Bolmo 为 $447.4/11$, Olmo 3 为 $434.8/11$, TFree-Hat 为 $405.7/11\approx36.9$, 都能复现). 只看 pass@1, Bolmo 平均 27.6, Olmo 3 平均 31.1, 方向相反; 其中 HumanEval 40.6 对 49.0 低 8.4, MultiPL HumanEval 低 6.8, DS 1000 低 5.2, 「略低」的说法偏轻. pass@16 高而 pass@1 低, 说明在同样 temperature 0.6, top-p 0.6 下 Bolmo 的采样更分散, 论文也承认没有系统比较质量与多样性的权衡. 表 4 的继续训练基线 Olmo 3 CT 代码均值 37.8, 比原 Olmo 3 还低, 说明在这份数据上继续训练对代码有损, 字节化后的 40.7 不能简单归因于「数据里有代码」.

评测套件的描述也有一处对不上: 实验设置写 7B 套件「因规模原因跳过 GSM Symbolic 和 BigCodeBench」, 而附录 B 的表 5 列出了 BigCodeBench (pass@1, 5 个样本, 最大 1280 token), 表 1 里又没有它的结果. 1B 结果段写「CoQA 高 3.3%」, 表 2 的 CoQA 是 Bolmo 1B 81.7, OLMo 2 1B 77.4, 差值为 4.3; 同一段的 MMLU $-3.2$, Lambada $+5.1$, CUTE $+32.5$ 都与表一致. `bolmo-core` 的 README 结果表把 Code 写成 Bolmo 41.0, Olmo 3 40.1, 与论文表 1 的 40.7, 39.5 也不同, 其余类目一致.

### 2.1. 推理速度与压缩率

**实测速度与局部层的选择。**

字节级模型的推理成本由两部分组成: 全局模型每个 patch 调用一次, 局部模型每个字节调用一次. 压缩率 $c$ (平均每 patch 字节数) 越高, 全局调用越少, 但局部模型的调用次数只与字节数有关. 子词模型在 $c\approx4.4$ 时每 4.4 字节做一次完整前向; Bolmo 在同样的 $c$ 下, 全局部分的成本与 Olmo 3 相同, 再额外加上每字节 5 层 mLSTM + FFN 的成本. 所以在同压缩率下 Bolmo 一定慢于源模型, 只能靠更高的 $c$ 追回来.

![推理速度与局部架构](images/wallclock.png)

> 图 6: 左为 Bolmo 7B 在不同压缩率下与 Olmo 3 7B 的解码吞吐 (bytes/s) 和 prefill 延迟 (首字节时间) 随 prefill 长度的变化, 右为 18K 字节 prefill 时各候选局部架构的解码吞吐, prefill 延迟与 GFLOPs/byte 的关系, batch size 1, H100, 原文 Figure 7

图 6 解析: 左图里 Olmo 3 ($c=4.4$) 的解码吞吐约 150 bytes/s, Bolmo ($c=4.4$) 约 113 到 117 bytes/s, Bolmo ($c=6.6$) 约 155, Bolmo ($c=8.8$) 约 187. prefill 72K 字节时 Olmo 3 约 0.8s, Bolmo ($c=4.4$) 约 1.03s, $c=6.6$ 约 0.7s. 两项指标都在 $c\approx6.6$ 时追平并超过源模型. 右图中每个点是一种局部架构配置, 横轴 GFLOPs/byte 与解码吞吐的拟合 $R^2=0.63$, 与 prefill 延迟的拟合 $R^2=0.66$; 在相近的 GFLOPs/byte 下, mLSTM 的点普遍高于 Mamba2 和 Gated DeltaNet.

正文给出的速度是「解码约 125 bytes/s, 对照子词模型约 150 bytes/s」. 按图 6 读数, Bolmo ($c=4.4$) 的曲线在各 prefill 长度上都低于 120, 右图的选中点也在约 115, 同压缩率下的解码速度约为源模型的 77% 而非 83%. 72K 字节 prefill 约 1s 对 0.8s 与图一致. 这组测量都是 batch size 1, 代表端侧单请求场景; 作者在未来方向 Bit 7 里也提到, 动态 patch 让同一 batch 中各样本的字节数与 patch 数不对齐, 批量推理的 PagedAttention 与连续批处理还没有做.

mLSTM 胜出靠的是 TFLA (Tiled Flash Linear Attention) 内核的实现效率, FLOPs 上它并不占优. 这组对照的结论是: FLOPs/byte 与实际耗时的相关性只有 $R^2\approx0.63$ 到 $0.66$, 用 FLOPs 对齐来选架构可能选错. 另一处 FLOPs 口径问题是输入嵌入. 常用的 Hoffmann 等 (2022) 公式把输入嵌入算成 one-hot 矩阵乘, 实际只是查表. 脚注 18 以 H-Net 论文的基线为例: $d=1536$, $|V|=128256$, 每 patch 4.6 字节, 嵌入一项是 $2\times1536\times128256/4.6\approx0.0857$ GFLOPs/byte, 占基线 0.42 GFLOPs/byte 的约 20%; 扣掉后基线只有约 0.335, 原口径相对它高估 $0.0857/0.335\approx26\%$, 即脚注说的「约 25%」. 字节级模型的嵌入表只有几百行, 这一项可以忽略, 所以按原口径比较对子词基线不利.

**更高压缩率与 softmax 瓶颈。**

子词模型提高压缩率只能扩大词表, 而输出层的计算量与词表大小成正比. 字节级模型的输出层固定是 512 类, 压缩率可以通过改边界监督任意提高. 做法是固定目标压缩率 $t$, 在每个样本内反复合并相邻的子词边界, 直到平均每 patch 字节数达到 $t$, 再用合并后的边界监督阶段 2 的边界预测器. 合并策略有三种: 样本内 BPE (合并最常见的相邻对), 熵合并 (用 370M 辅助子词模型, 合并两者熵之和最小的相邻对), 交叉熵合并 (合并相对真实下一 token 的交叉熵之和最小的相邻对). 子词基线则是把 OLMo 2 1B 迁移到在 OLMo 2 分词器之上训练的 SuperBPE 分词器 (200k 与 400k 词表), 新 token 的嵌入用 FOCUS 初始化.

### 2.2. 字符级增益与后训练迁移

**字符任务增益的口径。**

主表上最醒目的数字是字符理解: Bolmo 7B 的 Char 类均分 75.1, Olmo 3 7B 只有 56.0, 高 19.1 分; CUTE 78.6 对 56.9, EXECUTE 71.6 对 55.1. 1B 上 CUTE 从 OLMo 2 1B 的 27.5 升到 60.0. 此前的字节级模型 (EvaByte 47.3, TFree-Hat 47.9, BLT 49.3) 在 Char 类上都不如子词的 Olmo 3, 说明「换成字节」本身并不自动带来字符能力. 论文的解释是字符理解主要靠规模习得, Olmo 3 训练 token 远多于这些字节级模型, 规模抵消了字节表示的优势.

拆开 19.1 分要看附录 A 的表 4. Bolmo 的训练数据里混入了约 75M token 的 CUTE 风格合成数据 (拼写, 倒序, 字符交换, 删除, 替换, 词表 15 万词, 与 CUTE 测试词无重叠), 占 172B token 混合的 $75\text{M}/172\text{B}\approx0.044\%$. 在同一份数据上继续训练 39.3B token 的 Olmo 3 CT, Char 类已经到 71.0, CUTE 72.9, EXECUTE 69.2. 也就是说, 19.1 分里约 15.0 分来自这批数据和继续训练, 字节化本身在此之上再多 4.1 分 (CUTE 多 5.7, EXECUTE 多 2.4). 「字节级模型字符能力出现得更早」这个结论是成立的, 但主表上的近 20 分不能全部记在字节化名下. 1B 规模没有对应的继续训练基线, 32.5 分的 CUTE 提升无法做同样的拆分.

EXECUTE 是多语言的字符任务, 而合成数据全是英语. Olmo 3 CT 在 EXECUTE 上也从 55.1 涨到 69.2, 说明英语字符任务数据本身就能迁移到其他语言, 这一点与是否字节化无关. 其余类目里表 4 的对照指向同一个方向: Olmo 3 CT 的 Math 49.8, GenQA 71.7, MC STEM 66.1, 都低于原 Olmo 3, 与 Bolmo (48.9, 70.9, 65.5) 接近. 与原模型的差距主要来自这次继续训练, 字节化额外的损失在 1 分以内. 这也是作者在 Bit 4 里提出「无损字节化」, 建议用 PEFT 一类减少遗忘的方法的依据.

## 3. 字节概率怎样与子词概率对齐

### 3.1. patch 似然是字节与边界的联合事件

设文本的 UTF-8 字节序列为 $x_{1:n}$, patch 边界位置组成 $b_{1:k}$, 第 $j$ 个 patch 覆盖区间 $(b_{j-1},b_j]$. Bolmo 的输出类别把字节值与「该字节后是否结束 patch」融合起来. 令 $u_i=(x_i,c_i)$, $c_i=1$ 表示位置 $i$ 后结束 patch, 则一段文本的自回归概率是

$$
p_B(x,b)=\prod_{i=1}^{n}p_B(u_i\mid u_{<i}). \tag{10}
$$

子词模型把同一文本切成 token $s_{1:k}$, 概率为

$$
p_S(x)=\prod_{j=1}^{k}p_S(s_j\mid s_{<j}). \tag{11}
$$

当 Bolmo 的边界与源分词器一致时, token $s_j$ 与对应 patch 的字节和终止边界是一一映射. 第 $j$ 个 patch 的学生概率可以写成

$$
q_j=\prod_{i=b_{j-1}+1}^{b_j}p_B(u_i\mid u_{<i}), \tag{12}
$$

教师概率记为 $p_j=p_S(s_j\mid s_{<j})$. 阶段 1 的解码器蒸馏逐 patch 比较 $q_j$ 与 $p_j$. 若每个上下文、每个合法 patch 都有 $q_j=p_j$, 连乘后整个文本分布也相同. 这就是论文所说「精确」的含义: 学生没有把一个 token 的概率近似分摊给若干字节, 它直接对齐同一个 patch 事件的联合概率.

显式边界是这一等价的必要组成. 假设字节模型只预测内容, patch `cat` 的概率只含 $p(c)p(a\mid c)p(t\mid ca)$. 这个事件同时是 `cat`、`cater`、`catch` 等更长 patch 的前缀, 与教师的 token `cat` 事件并不相同. 加入「t 后结束」后, $q(\texttt{cat}<b>)$ 才对应教师选择 token `cat` 的事件. 输出边界预测因此既控制下一次全局模型何时调用, 也让教师和学生的概率空间可比较.

融合词表把 512 个常规类别理解为 $(x_i,c_i)$ 的笛卡尔积. 它不强制内容和边界条件独立:

$$
p(x_i,c_i\mid h_i)
\ne p(x_i\mid h_i)p(c_i\mid h_i). \tag{13}
$$

一个 512 类 softmax 可以让同一个字节在不同边界状态下拥有不同 logit. 若把两个头分开并相乘, 会施加条件独立假设; 若先预测字节再以字节为条件预测边界, 又多一道顺序计算. 融合头用固定的一次 softmax表达完整联合分布, 输出参数仅约 $520\times4096$, 相对 7B 主干很小.

### 3.2. 温度作用在 patch 概率上

patch 概率是多个小于 1 的字节概率之积, patch 越长越容易接近零. 实现把式 (12) 转到对数域:

$$
\ell_j=\log q_j=\sum_{i=b_{j-1}+1}^{b_j}\log p_B(u_i\mid u_{<i}). \tag{14}
$$

教师 token 的对数概率记为 $r_j=\log p_j$. 温度 $\tau=5$ 后, 论文的二元目标把 $q_j^{1/\tau}=\exp(\ell_j/\tau)$ 与 $p_j^{1/\tau}=\exp(r_j/\tau)$ 比较. 温度大于 1 会把很小的 patch 概率抬高, 使教师对大量非高置信 token 的差异仍能产生可见梯度. 若直接对极小概率做普通浮点乘法, 长 patch 会下溢; 对数求和避免了这一点.

把二元交叉熵写成

$$
\mathcal L_{patch}=-\tilde p_j\log\tilde q_j-(1-\tilde p_j)\log(1-\tilde q_j),
\quad
\tilde p_j=p_j^{1/\tau},\ \tilde q_j=q_j^{1/\tau}. \tag{15}
$$

对学生 patch log-prob $\ell_j$ 求导,

$$
\frac{\partial\mathcal L_{patch}}{\partial\ell_j}
=\frac{1}{\tau}(\tilde q_j-\tilde p_j). \tag{16}
$$

式 (16) 与普通 Bernoulli logit 的「预测减目标」同形, 再平均传到 patch 内每个字节 log-prob. 一个 patch 内的每一步共同承担 token 概率误差. 交叉熵项则逐字节对真实输出施加监督, 允许学生利用教师子词分布没有显式表达的字符信息. 两项组合后, 蒸馏约束源模型行为, 字节 CE 提供越过教师的方向.

脚本用二元 KL 代替论文写的二元交叉熵, 梯度相同. 因为

$$
D_{KL}(\tilde p\Vert\tilde q)=H(\tilde p,\tilde q)-H(\tilde p), \tag{17}
$$

右侧第二项只由教师决定. 训练轨迹的 loss 数值会相差教师熵, 参数更新不受影响. `do_alm_debiasing` 则不是常数变换: 它给教师与学生的 patch log-prob 加入空格类后继的 logsumexp, 改变了被对齐的事件. 复现实验若只照论文公式、不照启动脚本, 会漏掉这一处.

**bits-per-byte 才能跨分词比较。**

子词模型常报告每 token loss, 字节模型每一步对应一个字节, 两个数不能直接比较. 对总字节数 $N_B$ 的语料, 负对数似然为 $L=-\sum\log p$, bits-per-byte 定义为

$$
\operatorname{BPB}=\frac{L}{N_B\log 2}. \tag{18}
$$

若子词模型在 $N_T$ 个 token 上的平均自然对数 loss 为 $\bar L_T$, 平均每 token 含 $c=N_B/N_T$ 字节, 则

$$
\operatorname{BPB}=\frac{\bar L_T}{c\log2}. \tag{19}
$$

同一个子词 loss 在压缩率更高的语言上会得到更低 BPB, 因为每次预测覆盖更多字节. Bolmo 直接逐字节累加式 (10), 再除以真实字节数. 图 4 比较有无阶段 1 时用 BPB 比值, 避免了两组边界预测稍有不同导致 patch 数变化后 loss 口径漂移.

填充也要排除. 表 8 每条样本为 4096 个源 token, 按最大 24576 字节槽位展开, BPS/TPS 固定为 6; 真实文本平均约 4.4 字节/token. 若把填充槽位计入分母, BPB 会虚低, 吞吐也会虚高. 训练量的 172.9B bytes 使用 4.4 的有效比值, 吞吐 BPS 使用 6 的张量槽位, 两处数字服务于不同目的.

### 3.1. 非因果边界的表达力与泄漏边界

**一字节前瞻解决了哪类不可判定。**

因果边界函数在位置 $t$ 只能依赖前缀 $x_{\le t}$. 若存在两条字符串 $x,x'$ 满足 $x_{\le t}=x'_{\le t}$, 但源分词器在 $t$ 的边界不同, 任何确定性因果函数都至少错一条. `_Hello_Wor!` 与 `_Hello_World!` 给出了这样的构造. 形式化地, 对边界标签 $b_t=g(x_{1:n})$, 若条件熵

$$
H(b_t\mid x_{\le t})>0, \tag{20}
$$

仅用前缀就无法达到零错误. 加入下一个字节后, 条件熵变成 $H(b_t\mid x_{\le t+1})$. 对最长匹配式子词分词, 很多歧义在看到一个后继字节后消失, 所以一字节前瞻把错误率显著压低; 它不保证覆盖所有可能需要更长 lookahead 的词表冲突.

Bolmo 的分数是投影后向量的余弦距离:

$$
s_t=\frac12\left(1-\frac{q_{t+1}^{\top}k_t}{\lVert q_{t+1}\rVert\lVert k_t\rVert}\right). \tag{21}
$$

余弦相似度在 $[-1,1]$, 所以 $s_t\in[0,1]$. 阈值 0.5 等价于 $q_{t+1}^{\top}k_t<0$: 两个投影方向夹角超过 90 度时放边界. 这种参数化把向量模长从决策中移除, 让局部编码器主要通过方向表达「延续」或「断开」. $W_q,W_k$ 各是 $d\times d$, 7B 的 $d=4096$, 边界器约 33.6M 参数.

边界准确率超过 99% 容易给人「误差很小」的印象. 若平均 patch 4.4 字节, 正边界比例约为 $1/4.4\approx22.7\%$; 全部预测无边界也有约 77.3% accuracy. 更重要的是错误类型不对称: 漏边界会把相邻 patch 合并, 多放边界会把一个 patch 拆开. 两者都改变后续所有 patch 的对齐, 直到某个边界重新同步. 因而表 3 同时报告 oracle 与预测边界下的任务得分, 比单独 accuracy 更能衡量代价.

**prefill 与 decode 为何采用两个边界器。**

prefill 已知完整输入, 使用 $x_{t+1}$ 不违反语言模型的预测约束: 模型并不拿 prefill 位置的输出作为训练目标去预测已经提供的字节. decode 时 $x_{t+1}$ 尚未生成, 式 (21) 无法计算. Bolmo 让 LM head 在生成 $x_t$ 时同时输出 $c_t$, 决定生成完当前字节后是否结束 patch. 这形成两个条件分布:

$$
p_{prefill}(b_t\mid x_{\le t+1}),\qquad
p_{decode}(c_t\mid x_{\le t}). \tag{22}
$$

它们训练到同一组子词边界标签, 输入信息却不同. prefill 边界器负责压缩已有上下文; decode 边界器属于语言模型输出, 负责决定何时再次调用全局主干. 两者在同一段已知文本上的边界不必逐位完全相同, 但阶段 1 的蒸馏和阶段 2 的 CE 会推动解码分布复现训练边界.

解码过程中, 局部 mLSTM 每生成一个字节都更新状态. 只有生成融合边界类别时, 当前 patch 的局部表示才池化并触发一次全局模型调用; 随后新的全局输出参与下一 patch 的字节生成. 若模型长期不生成边界, 局部模型独自承担长段生成, 全局上下文更新停滞; 若每字节都生成边界, 它退化成全局模型逐字节调用. 边界分布直接决定质量与延迟, 采样温度和 top-p 同时会影响字节内容与边界频率.

**连续边界分数如何泄漏未来。**

若把非因果分数 $s_t$ 作为连续值送入下游, 它是 $x_{t+1}$ 的函数. bfloat16 有 16 个存储 bit, 即使有效尾数较少, 也足以让模型构造多个可区分编码区间. 下游若能观察精确 $s_t$, 可以学习解码函数 $\hat x_{t+1}=d(s_t)$, 绕过语言建模. 离散阈值只留下一个 bit 的边界决定, 信息通道从大量可取浮点值缩到二值:

$$
I(x_{t+1};\mathbf1[s_t>\gamma])\le1\ \text{bit}. \tag{23}
$$

一个字节有 8 bit, 单个二值边界不能唯一编码全部 256 种值. 但它仍可能泄漏某一属性, 例如下个字节是否为空格. Bolmo 接受这一个 bit, 因为源子词分词器的边界本身就携带类似的后文信息; 它拒绝把完整分数通过平滑或直通估计器送入解码路径.

如果未来要端到端学习非因果边界, 约束对象应是信息通道. 一种思路是只让 hard boundary 进入前向, 对梯度使用独立的无未来代理;另一种是给连续分数加量化、噪声或互信息惩罚. 单纯采用 straight-through estimator 只解决离散操作的梯度, 没有消除前向中的未来编码能力. 论文把这一问题列为后续方向, 当前模型仍完全依赖外部边界监督.
