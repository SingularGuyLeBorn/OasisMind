# Olmo 3: 为长推理重排的全开放模型流

Olmo 3 的 118 页报告为 arXiv:2512.13961v2, 对照译稿见 `olmo-3-bi.md`. 数字取自报告 Table 1–55, Figure 1–43 与正文各节; 标为「心算」或「读图」的数值是估算.

## 1. 定位与架构

### 1.1. 谱系坐标: 从 「训得稳」 走到 「为推理而训」

OLMo 2 解决的是全开放 dense 模型能不能稳定训完, 以及退火和 RLVR 能不能把它推到开权重的竞争带. Olmo 3 的骨架几乎原样继承: 仍是 dense 的 7B / 32B, Table 33 里 QK-Norm, 作用在子层输出上的 RMSNorm, z-loss 权重 10⁻⁵, embedding 不做 weight decay, RoPE θ = 5×10⁵ 都与上一代一致, 层数 32 / 64, 32B 继续用 40/8 的 GQA. 变化集中在一个方向上: 整条流水线都在为长推理让路. 预训练上下文从 4096 提到 8192 并引入 **sliding window attention (SWA)**, midtraining 提前混入 thinking trace, RL 的 rollout 上限拉到 32K. 这三处分属架构, 数据和后训练, 目标是同一个.

报告把交付物叫作 **model flow**. Base 经三段训练 (预训练, midtraining, 长上下文扩展) 后分成三条线: Think 先写推理过程再作答, Instruct 不产中间思考, 追求短而快并支持 function calling, RL-Zero 从 Base 直接做 RLVR, 用来研究预训练数据怎样影响强化学习. 每个阶段的数据, 检查点和代码都公开, Figure 1 用这一点把 Olmo, Marin, Apertus 与只放最终权重的开权重模型分成两栏. 对这一代来说, 开放不只是姿态: RL-Zero 能否说明问题, 取决于别人能否查到底座见过什么数据, 这一点在第 4.2 节会再出现.

旗舰数字在 Table 1. Olmo 3.1 Think 32B 的 MATH 96.2, AIME 2025 78.1, LiveCodeBench v3 83.3, IFBench 68.1; 同表 Qwen 3 32B 分别是 95.4 / 70.9 / 90.2 / 37.3, Qwen 3 VL 32B Thinking 是 96.7 / 78.8 / 84.8 / 55.1. 数学和精确指令遵循已经追平或超过, 知识类仍落后: MMLU 86.4 对 88.8, GPQA 57.5 对 67.3, ZebraLogic 80.1 对 88.3. 报告称训练 token 约少 6x. 在 7B 档, 作者把知识类落后于 Qwen 3 归因于后者从自家最大模型蒸馏而来, 这是作者的推测, 没有对照实验.

同表 OLMo 2 Instruct 32B 一列可以说明代际差距来自哪里: MATH 49.2, AIME 2025 0.9, IFBench 36.4. 两代的注意力主体, 归一化和优化器几乎不变, 差距主要落在数据配比, midtraining 的推理原料和长 RL 上. 因此, SWA 的主要用途是让 8K 预训练和 32K 生成付得起算力, 本身不是分数的主要来源.

### 1.2. 注意力怎样为 8K 预训练和 65K 推理让路

§3.2 的 SWA 设定很简单: 每个 token 只看前面 4096 个位置, 每四层里三层用 SWA, 并保证最后一层始终是 full attention. 作者给的理由有两条, 一是让更长序列的预训练可扩展, 二是控制推理成本. 窗口外的信息只能经由 full attention 层或多层堆叠间接传递, 所以全局层的位置 (每四层一层, 且末层必为全局) 决定了远距离依赖的通路. 更系统的高效注意力背景见 [2.3.4-高效注意力全景综述](../../../llm-guide/2-核心原理与架构/2.3-注意力的高效实现/01-高效注意力全景综述/01-高效注意力全景综述.md).

信息传播范围可以逐层计算. 报告只写了比例和末层约束, 按最自然的排法, 每个四层块是三层 SWA 接一层 full attention. 一层 SWA 让位置 $t$ 读到 $[t-4095,t]$, 信息每过一层最多向后挪 4095 个位置, 连续三层 SWA 最远把位置 $s$ 的内容送到 $s+12285$ 附近. 预训练序列只有 8192, 一个块里的三层 SWA 已经能覆盖整条序列, full attention 层在 8K 下提供的是一跳直达. 到 65536 时, 相距超过约 12K 的两个位置需要经过四层块中的 full attention 连通. 若完全依赖 SWA 首尾接力, 覆盖 65536 个位置约需 16 层；7B 共 24 层 SWA, 32B 共 48 层, 结构上存在这条路径, 但每一跳都要把信息传到窗口边缘, 报告没有测量模型是否实际使用它. **末层固定为 full attention** 保证产出 logits 前每个位置都能一步读到全部上文.

推理侧的收益可以按缓存长度估一下. 在 65536 上下文下, full 层要缓存全部位置, SWA 层最多缓存 4096 个, 总 KV 缓存约为全层 full attention 的 29.7% (心算 1/4 + 3/4 × 4096/65536); 在 8192 上下文下约为 62.5%. 32B 再叠加 GQA 的 40/8, 每层缓存再降到同宽 MHA 的 1/5. 报告没有给推理显存或延迟的实测, 这两个比例只是按结构推算, GQA 本身见 [03-GQA-在性能与缓存之间折中](../../../llm-guide/2-核心原理与架构/2.2-注意力机制/2.2.2-多头注意力变体/02-MQA与GQA-共享KeyValue头/02-MQA与GQA-共享KeyValue头.md).

训练侧, OLMo-core 在序列长 8192, 全程 bfloat16 下, 7B 达到每卡 7700 token/s, 32B 1960 token/s, 约合 43% 与 41% MFU. 手段包括 `torch.compile()`, 自定义 attention 与 LM head kernel, 异步批量收集指标和异步写检查点. Table 34 还给出分阶段吞吐: 7B midtraining 用 128 卡跑到 8.5K, 长上下文阶段用 256 卡, 8 路 **context parallelism** 让每张卡处理每条样本的 8K token, 吞吐降到 4.0K; 32B 三段分别是 2.0K / 2.0K / 1.3K. 作者采用基于 all-gather 的 CP 注意力, 理由是它容易支持 SWA 和文档内掩码这类不规则 mask.

扩展到 65536 时, RoPE 怎么改是一个真正的选择. §3.6.4 试了调整基频, position interpolation 和 YaRN, 每种方法又分 「作用于全部 RoPE」 与 「只作用于 full attention 层的 RoPE」 两种, 结论是 **YaRN 只打在 full attention 层上最好** (Figure 13a). 一种解读是: SWA 层看到的相对距离永远不超过 4096, 预训练时早已见过, 改它们的频率只会扰动已学好的局部模式, 真正需要外推的只有全局层. 报告没有给这层机制的消融, YaRN 本身见 [03-长度外推：从PI到YaRN的频率扩展](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/02-RoPE扩展-长上下文,多模态与工程实现/02-RoPE扩展-长上下文,多模态与工程实现.md).

这套设计的代价在 Table 12 的长端. RULER 4K 上, Olmo 3 32B 为 96.10, 是 32B 档最高; 到 65K 降到 79.70, 低于 Mistral Small 3.1 24B 的 88.80 与 Gemma 3 27B 的 84.59. 7B 档更明显: 65K 为 67.96, Llama 3.1 8B 为 86.88, Nemotron Nano 9B 为 85.13. 未参与开发的 HELMET 上, 32B 在 65K 为 43.15, Gemma 3 27B 为 48.60. 短上下文不吃亏, 长端还有缺口, 这与第 2.4 节 「扩展阶段短」 的配方一致.

## 2. Base 的三段训练

### 2.1. 从 9T 池到 6T mix: 数据分配怎样服务后面的阶段

Dolma 3 的预训练池约 9T 清洗 token, 最终训练 mix 约 6T, 另有供低算力实验的 150B 采样 mix (Table 4). 7B 的余弦日程按 5.93T 一个 epoch 设计, 32B 同样按 5.93T 设计但截在 5.5T, 峰值学习率 7B 为 3.0×10⁻⁴, 32B 为 6.0×10⁻⁴, batch 分别是 4M 与 8M token (Table 35). 预训练吃掉整体算力的 90% 以上, 所以作者给数据定了两条原则, 并在 mix 里做了明显的重分配.

重分配从 Table 4 能直接读出来. Common Crawl 在池里有 8.14T, 进 mix 只取 4.51T, 占 76.1%; olmOCR 解析的科学 PDF 池 972B, 取 805B, 占 13.6%; Stack-Edu 池只有 137B, 在 mix 里却占 409B (6.89%), 相当于重复约三遍. 网页被下采样, 代码和学术文本被上采样. 混合优化以逐任务回归预测的平均 bits-per-byte 为目标, 并约束任何域重复不超过约 4–7 次, 小域能拿到的比例由它的可用 token 数封顶.

网页清洗的规模在附录 A.2. 104 个 Common Crawl dump 线性化后是 252.6B 篇文档, DCLM 式启发式过滤加英文过滤后剩 38.7B 篇, 存活率 15.1%, 其中长度过滤一步就去掉 40.42%, 耗时最多的是内部重复检测 (占总时长 31.41%), 整步约 1030 个 i4i.32xlarge 小时, 约 $11,300. 去重分三级: 基于内容哈希的精确去重去掉 66% 文档, 剩 12.7B 篇; 再做 32 路分片的 MinHash 近重去重 (Jaccard 阈值 0.80); 最后用后缀数组去掉重复模板文本. 精确去重与 MinHash 由作者新写的 Rust 工具 Duplodocus 完成.

混合的两件工具值得分开看. **token-constrained mixing** 先用一批小代理模型扫比例 (报告称为 swarm), 再用条件混合把后到的 PDF 域接进已冻结的网页与代码比例, 不必每次重跑整批代理. **quality-aware upsampling** 则在主题比例定下之后, 用一条曲线决定每个质量分位的重复次数: Figure 10 的例子里, 质量最低的 40% 直接丢掉, 最高的 5% 重复 7 次. 网页先按 24 个主题与 20 个质量档切成格子, 两件工具分别在主题轴和质量轴上起作用.

上采样曲线有一套明确的定义. 设某个主题共有 $X$ 个 token, 按质量分成 $Q$ 个有序档, 第 $q$ 档有 $X_q$ 个; Olmix 规定这个主题取 $Z$ 个 token, 任何一档重复不超过 $M$ 次. 问题是找 $Z_q$ 使 $\sum_q Z_q=Z$ 且 $Z_q/X_q\le M$. 为了不在 $Q$ 维上直接搜, 作者把 「质量分位 $x\in[0,1]$ 到重复倍数」 的函数限定为截断幂指数族:

$$f_{p,\lambda}(x)=\begin{cases}0, & x<a\\ C(x-a)^{p}\,e^{\lambda(x-a)}, & x\ge a\end{cases}$$

$a$ 是丢弃线, 分位低于 $a$ 的数据一个 token 都不取; $(x-a)^p$ 决定刚过丢弃线时曲线抬得多快, $e^{\lambda(x-a)}$ 决定高分位的上翘, $C$ 是整体幅度. 三个参数由三条约束解出: $\int_0^1 f\,dx=Z/X$ 让总取量等于 Olmix 给的份额, 这个积分就是该主题的平均重复倍数, 2.0 表示平均取两遍; $\frac{1}{b}\int_{1-b}^{1}f\,dx\le M$ 让最高一档 (宽度 $b$) 不超过 $M$ 次, 曲线单调时最高档一定重复得最多; $\lambda\ge0$ 保证单调. 实现里每个 WebOrganizer 主题都取 **$M=7$, $a=0.40$**, 再数值求出可行的 $p,\lambda,C$; 第 $q$ 档覆盖分位 $[q^-,q^+]$ 时, 它的重复倍数取曲线在这一段的平均 $\frac{1}{q^+-q^-}\int_{q^-}^{q^+}f(x)\,dx$. Figure 10 的 「最低 40% 丢掉, 最高 5% 重复 7 次」 就是这组取值画出的一条曲线, $b$ 的具体数值报告没有写.

这套设计针对的是数据受限的局面: 高质量的独有 token 不够填满 6T, 重复次数就成了可调的旋钮. Table 39 的对照这样搭: 1B 模型训 100B token, 平坦过滤组从 20 个质量档里取最高的若干百分位, 并把重复倍数调到与 「从 4.51T 池里取数」 一致, 例如取前 10% 对应重复 5.6 次, 前 5% 对应 11.1 次; 上采样组用同一套方法, 只把目标池直接设成 100B. 平坦过滤在曲线图上是一个阶跃函数, 线以上同一倍数, 线以下为 0. 模型, 总 token 和候选池都不变, 变的只是各分位分到的重复次数. 结果上采样的 Code BPB 为 0.719, 四种平坦过滤里最好的是 0.880 (越低越好), QA 与 Math 也全面占优. Table 40 再比较主题配比与质量上采样怎样合成一个 (主题, 质量) 格子的取量: 只做配比时 Code 0.872, 只做上采样时 QA 与 Math 最差, 两者取算术或几何平均居中; 去掉 $(x-a)^p$ 只留指数的截断指数族, Code 与最终方案接近 (0.787 对 0.783), QA 与 Math 落后, 截断幂指数族三项都最低. 重复上限卡在 4–7 次, 与 「高质量数据重复几遍收益下降不明显」 的已有经验一致, 这一句是按数据受限 Scaling 文献的一般结论来读的, 报告本身只给了这个上限和 Table 39. Scaling Laws 背景见 [3.3.2-Scaling-Law](../../../llm-guide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md).

### 2.2. midtraining: 把推理的原料提前放进底座

Dolma 3 Dolmino Mix 共 100B token, 学习率线性衰减到 0. 选料方法分两层: 先用 microanneal 在单一来源上快速试, 典型做法是 5B 目标数据加 5B 网页, 与纯网页 10B 的基线比增量; 有希望的来源再收进 100B 的 integration test, 并接一小段 SFT 看底座的 「可后训练性」. 报告一共迭代了五轮候选 mix, Table 6 展示了其中三轮, 分数从第一轮到最后一轮全面上升.

几类新造的推理数据在 microanneal 里效果最明显. **meta-reasoning** 数据针对自我评估, 回溯, 逆向推理等七种认知能力, 用 GPT-4.1 和 o4-mini 生成思考过程, 相对强数学/代码基线让 Minerva Math 涨约 14 分, HumanEval 涨 14 分, MBPP 涨 20 分. 可程序验证的题目约 250M token (放在 5B 的 microanneal 里) 带来 1–2 分. OpenMathReasoning 的 Full-Thoughts 轻改写版共 850M token, 让 MATH 涨 5.5, GSM8K 涨 8.4. 已有的开源 thinking trace 经过滤后让 GSM8K 最多涨 8 分.

Table 10 回答了一个更根本的问题: 把后训练性质的数据 (指令和 thinking trace) 放进 midtraining, 会不会伤底座. 在总 token 不变的 100B integration test 里, 含这类数据的 mix 在每一列都更好: 平均 50.7 对 48.8, Math 48.7 对 43.1, FIM 31.9 对 29.2. 这些数据把底座的输出分布往 「分步作答」 推了一截, 后面的 RL 就有更长的推理可以放大. Figure 25 给了反面例子: 两个早期 midtrained 底座做 RL-Zero, 推理数据不足的那个回复长度始终不涨, 也学不会回溯和验证答案. **midtraining 在这里决定的是 RL 能走多远**.

格式细节也会反过来咬人. 作者在 Tulu 3 SFT 数据上做 microanneal, 发现 midtraining 数据里带 `<|im_start|>` 这类特殊 token 时, 底座推理时会把它们吐出来, GSM8K 从 49.43 掉到 0, CruxEval 从 32.89 掉到 18.91; 只保留聊天模板, 把特殊 token 换成普通文本, 分数是 46.02 与 29.65. 问题出在预训练没见过的新 embedding, 而不在模板本身. 最终指令数据去掉模板和特殊 token, 改用换行分隔, 特殊 token 留到 SFT 再引入.

单一来源常常此涨彼跌. Table 7 里偏数学/代码的 mix 在数学和代码上明显超过最终 mix, 但 MC 与 GenQA 掉分; 偏 GenQA 的 mix 反过来伤数学和代码. Table 8 的 Reddit-to-Flashcards 抬 MCQA, 伤数学; Table 9 的 meta-reasoning 抬数学代码, 伤生成式问答. 去污染对所有 split 下手, 因为部分开发基准会拿 train split 来降噪, 去掉后 DROP, Minerva, SQuAD 等明显掉分, 另一些几乎不动. 32B 的 midtraining 用两个数据顺序种子各跑一次再合并权重, 合并后 MC<sub>STEM</sub> 涨近 1 分, GenQA 0.4 分, Math 相对两次单跑分别 +2.9 与 +1.6; 这与 OLMo 2 的 soup 做法一脉相承.

### 2.3. 让小实验说真话: OlmoBaseEval 与去污染

上面每个数据决策都依赖小算力实验, 而小模型在数学, 代码和选择题上的分数接近随机, 分差容易被噪声淹没. §3.3 的对策有三件. 其一是**按能力聚类取宏平均**: 用约 23K 条开源模型的基准分数做 Ward 层次聚类, 再人工对齐成 MC<sub>STEM</sub>, MC<sub>Non-STEM</sub>, GenQA, Math, Code, Code FIM 六簇. 其二是用 OLMo 2 的一族 Scaling 模型找小算力下仍有信号的代理指标, 再拿约 70 个开权重模型检查高算力端是否饱和. 其三是提高信噪比: 加样本, 调 pass@k 的 n, 把 CruxEval 这类能力相关但噪声大的任务移出宏平均.

结果是两套套件: Base Easy 用 bits-per-byte 或排序式选择, 服务 1B 级消融; Base Main 在大尺度仍留有区分度, 服务 midtraining 实验. 后训练评测也按方差分桶: 14 个模型各跑 3 次, 取标准差均值, 例如 ZebraLogic 0.5638 归 「稳定」, MMLU 0.2219, PopQA 0.1554 归 「很稳定」. 开发 7B 配方期间, 评测消耗了 10%–20% 的算力. 读表里一两分的差距时, 先看该基准落在哪个方差桶.

去污染贯穿全流程. midtraining 数据对评测集的所有 split 去重; 后训练三阶段的数据按 Tülu 3 流程做 8-gram 匹配, 重叠阈值 0.5, 再用启发式压误报. 最后一道检查放在 RL-Zero: 用与回答质量无关的**随机二元奖励**训练底座 (Shao et al., 2025b 的协议), 如果预训练或 midtraining 见过评测题, 随机奖励也能把记住的答案 「激出来」. Figure 27 显示所有基准要么持平, 要么下降, 作者据此认为去污染有效. 这一步把数据, 评测和 RL 连在一起, 只有全开放的底座才能做.

Base 主结果 (Table 2) 与后面的 Think 表可以对照读. Olmo 3 Base 32B 的 Math 复合 61.9, 高于 Marin 32B 的 49.3, Apertus 70B 的 39.7 与 OLMo 2 32B 的 53.9, 接近 Qwen 2.5 32B 的 64.7; Code 复合 39.7, 高于 Marin 的 30.8, 低于 Qwen 2.5 的 48.3. 差距最大的是知识类选择题: MC<sub>STEM</sub> 74.5, Qwen 2.5 32B 为 82.2, MedQA 53.8 对 68.4. Think 表里 MMLU 与 GPQA 的落后, 在底座阶段就已经存在, 后训练没有补上.

### 2.4. 长上下文扩展: 短而专的一段训练

第三段训练的配方可以浓缩成几条: Longmino 长文档占 34%, midtraining 的高质量短数据占 66%; 7B 训 50B, 32B 训 100B; YaRN 只打在 full attention 层; 用文档打包加文档内掩码; 开发看 RULER, HELMET 留作未见套件. 长短配比来自一个 10B 扩展的早期实验: 长 66% / 短 34% 让 OlmoBaseEval 子集掉 2.5 分, 反过来的 34% / 66% 只掉 0.8 分. Figure 13e 显示扩展 token 越多, 长序列上的 RULER 越好, 于是 32B 的预算翻倍.

长文档的主力是 olmOCR 解析的科学 PDF: 超过 8K token 的文档约 22.3M 篇, 合计约 640B token; 超过 32K 的约 4.5M 篇, 约 380B token. 过滤用 gzip 可压缩性, 去掉最容易压缩和最难压缩的各 20%, 只留中间段. 作者也试了用 LongPpl 找依赖长程上下文的关键 token 来过滤, 几种切法都没有胜过 gzip, 最终没有采用. 长上下文的一般背景见 [2.7-长上下文与外推技术](../../../llm-guide/2-核心原理与架构/2.7-长上下文与外推技术/2.7-长上下文与外推技术.md).

自然长文档很少提供 「跨全文汇总信息」 的监督, 作者因此往部分 PDF 里插入合成的聚合任务. 难点在于自举: 没有能读长文的模型, 怎么造长文数据. 他们的办法是先用文档统计量代替模型阅读: 取长度在 32768 到 65536 之间的文档, 切成 8K–32K 的分段, 用 tf-idf 找每段最显著的名词短语, 每个短语取 8 个片段, 再交给 OLMo 2 Instruct 32B 生成任务. 任务分两类: CWE 要求数出若干高频词在分段中出现的确切次数, REX 让模型按 12 种场景 (摘要, 师生对话, 抽认卡, 辩论等) 改写与某个短语相关的内容.

训练细节上有两处改动, 改的是不同的量. 预训练和 midtraining 用的是常规做法: 文档首尾拼接, 再按固定长度切块, 切口落在哪里与文档边界无关, 一篇 40K 的文档很可能被劈成两段分进两条 65K 序列, 任何一条样本里都看不到它的完整上下文. 作者指出这种做法到长上下文阶段会让训练样本平均比原文档短. **best-fit 文档打包** (Ding et al., 2024) 改的是切口: 把文档当作物品装进定长的序列, 每篇放进剩余空间最小但仍放得下的那条, 不超过序列长度的文档就不再被切开, 空隙用 padding 补 (装箱规则按 best-fit 的一般含义来读, 报告只写了 「减少被切开的文档, padding 几乎可忽略」). 它改变的是一篇文档在同一条样本里连续出现的长度, 对照拼接切块, 长上下文基准明显提升.

**文档内掩码**改的是注意力矩阵. 同一条序列里拼着几篇文档时, 位置 $t$ 只能注意同一文档里 $s\le t$ 的位置, 跨文档的块整体不可见. 样本中的 token 保持不变, 每个 token 能看到的上文受到文档边界限制, RoPE 的相对距离也不会跨越两篇无关文档. 打包负责增加完整长文档, 掩码负责阻断无关文档间的注意力, 两项各自处理一个问题. 第 1.2 节提到的 all-gather 式 CP 注意力能直接支持滑窗与文档内掩码这类不规则掩码, 所以两者可以在 8 路 CP 下同时开.

32B 没有像 midtraining 那样多跑几个种子, 而是把扩展末尾三个检查点 (第 10,000, 11,000, 11,921 步) 平均成最终的长上下文底座. Table 11 还说明, 7B 的 50B mix 只用了 olmOCR 中 64K 以下的长度桶: 8K–16K 2.27B (4.55%), 16K–32K 1.85B (3.70%), 32K–64K 4.81B (9.63%); 64K–128K 桶在池里有 96.0B, 在 mix 里为空. 训练最长只到 65536, 更长的文档只作为池子公开. 把这一点和第 1.2 节的 Table 12 放在一起看: 扩展阶段只有 50B–100B, 且没用超长文档, 65K 端落后于扩展预算更大的模型是可以预期的.

## 3. Think 线的后训练

### 3.1. 模仿饱和之后: SFT 与 Delta Learning

Think 线的第一步是 Dolci Think SFT, 为多个领域构造带长推理过程的监督数据. 训练从 Open Instruct 搬到 OLMo-core, 吞吐提升 8×; 所有模型训两个 epoch 防过拟合. 32B 并行扫四个学习率, 每个 256 卡跑 36 小时, 再花约 12 小时评测, 合并和确认, 最终用 mergekit 把两个学习率的检查点线性合并. SFT 基础见 [4.2-SFT](../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md).

第二步的发现是整份报告里最反直觉的一条 (Table 21). chosen 回复由 Qwen3 32B Thinking 生成, 它在该子集上的平均分 83.2; rejected 由 Qwen3 0.6B Thinking 生成, 平均 35.1. 开发中的 7B SFT 检查点平均 70.3. 直接在 chosen 上继续 SFT, 平均掉到 64.5, 每一项都降; 同样的 chosen 配上 rejected 做 DPO, 平均升到 72.9, AIME 2025 从 58.8 到 66.3, LiveCodeBench 从 67.0 到 72.6. 作者的解释是: 这些 chosen 相对模型在 SFT 阶段已见过的数据偏弱, 不再值得模仿, 但与更弱模型的回复配对后, 两者之差仍然指出了 「更好」 的方向.

从目标函数看, 这个现象有据可循. Think DPO 优化的是长度归一的 DPO 目标:

$$\max_{\pi_\theta}\ \mathbb{E}_{(x,y_c,y_r)\sim\mathcal{D}}\left[\log\sigma\left(\frac{\beta}{|y_c|}\log\frac{\pi_\theta(y_c\mid x)}{\pi_{\mathrm{ref}}(y_c\mid x)}-\frac{\beta}{|y_r|}\log\frac{\pi_\theta(y_r\mid x)}{\pi_{\mathrm{ref}}(y_r\mid x)}\right)\right]$$

$\pi_{\mathrm{ref}}$ 是起点的 SFT 模型, 两个对数比衡量策略相对起点把 chosen 与 rejected 各抬高或压低了多少; 除以长度 $|y|$ 把整条回复的对数比换成每 token 平均, 上万 token 的思考轨迹不会因为长就主导差值; $\beta$ 乘在隐式 KL 上, 控制策略离参考模型多远, Table 48 里三组训练都取 5. 记括号内为 $z$, 对参数求导得 $\beta(1-\sigma(z))\left[\frac{1}{|y_c|}\nabla\log\pi_\theta(y_c\mid x)-\frac{1}{|y_r|}\nabla\log\pi_\theta(y_r\mid x)\right]$ (按式推导). 梯度方向是两条回复平均对数似然梯度之差, 权重 $1-\sigma(z)$ 只看策略相对参考模型把两者拉开了多少, 与 chosen 的绝对质量无关.

所以 chosen 比当前策略弱也还有信号. 直接 SFT 时, $\nabla\log\pi(y_c)$ 整个被当作目标, Qwen3 32B 回复里不如 SFT 数据的部分也一并被模仿; 放进差值后, 两条回复共有的格式和常见推理步骤大体相互抵消, 梯度更集中于 32B 与 0.6B 之间的差别. 这就是 Geng et al. (2025) 的 **Delta Learning** 假设: 偏好数据的质量主要取决于两者之差, 而非任一方单独的质量. 数据构造与此配套: chosen 经过主题过滤与模型身份过滤, rejected 完全不过滤, 作者认为答错的 rejected 也能给出有用的对比; 7B / 32B 分别用 150K / 200K 对, 只训 1 个 epoch, 学习率与数据量一起扫, 因为偏好调优存在与任务相关的最优停点, 过了会伤下游 (Figure 23). 作者还指出, 收益不只是把 pass@k 转成 pass@1, AIME 上的 pass@k 也提高了 (Figure 20), 推理能力的上界在扩大. DPO 见 [01-DPO](../../../llm-guide/4-后训练/4.6-偏好优化/4.6.1-离线偏好优化/01-DPO/01-DPO.md).

代价同样在 Table 21 里: IFEval 从 79.7 降到 75.2, MMLU 从 76.1 降到 75.5. 32B 的 Table 14 呈现同样的形状: SFT 到 DPO, AIME 2025 66.2 → 70.7, LiveCodeBench 75.8 → 81.9, AlpacaEval 69.1 → 78.6, 但 IFEval 83.9 → 80.6, IFBench 37.0 → 34.4. DPO 抬高推理和聊天, 顺手伤了精确指令遵循, 这个缺口留给 RL 去补.

Table 22 进一步比较了 RL 的起点 (7B, RLVR 各训 1000 步, 单次运行): SFT 70.1, SFT+DPO 72.7, SFT+RLVR 71.9, SFT+DPO+RLVR 74.1. Figure 19 归纳出三种情形: RL 不优化的指标 (如 AlpacaEval), DPO 的领先会一直保持; RL 直接优化的指标 (如 OMEGA), 两个起点终点相近; 从 DPO 难再提高的指标 (如 AIME 2025), SFT 起点会追上来. 没有一种情形是 SFT 起点在 RL 后反超. 作者还发现 DPO 模型熵更低, AIME 上的 pass@K 却更高, 这与 「RLVR 把 pass@K 转成 pass@1」 的已有观察相容.

### 3.2. OlmoRL: 把 GRPO 改到能跑 32K 回复

OlmoRL 以 GRPO 为底, 吸收了 DAPO 与 Dr GRPO 的多项改动 (§4.4.1): 丢掉组内奖励全相同, 梯度为零的组; 用 active sampling 补足被丢掉的样本, 保持 batch 大小; 损失按 token 总数归一; 去掉 KL 项; 上裁剪边界略高于下边界 (clip-higher); 乘以截断的重要性采样比; 优势不除以组内标准差. 最终目标是式 (1):

$$\mathcal{J}(\theta)=\frac{1}{\sum_{i=1}^{G}|y_i|}\sum_{i=1}^{G}\sum_{t=1}^{|y_i|}\min\left(\frac{\pi(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})}{\pi_{\text{vllm}}(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})},\rho\right)\min\Big(r_{i,t}A_{i,t},\ \mathrm{clip}\big(r_{i,t},1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}}\big)A_{i,t}\Big)$$

其中 $r_{i,t}=\pi(y_{i,t}\mid x,y_{i,<t};\theta)/\pi(y_{i,t}\mid x,y_{i,<t};\theta_{\text{old}})$ 是概率比, 回复 $y_i$ 由 vLLM 按 $\theta_{\text{old}}$ 采样; 优势由式 (2) 给出, $A_{i,t}=r(x,y_i)-\mathrm{mean}(\{r(x,y_i)\}_{i=1}^{G})$, 这里的 $r(x,y_i)$ 是验证器给的奖励, 源文两处共用字母 r. Table 49 给出取值: 每题采 $G=8$ 条, $\varepsilon_{\text{low}}=0.2$, $\varepsilon_{\text{high}}=0.272$, 32B Think 与 RL-Zero 的 $\rho=2.0$, 7B Think 与 7B Instruct 这一格印的是 「-」. 作者还试过 overlong filtering, 没有稳定收益. GRPO 见 [02-GRPO](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/01-GRPO/01-GRPO.md).

式中每一项对应列表里的一条改动. 最前面的 $1/\sum_i|y_i|$ 是 **token 级归一**: 按样本归一写作 $\frac{1}{G}\sum_i\frac{1}{|y_i|}\sum_t$, 一条 30K 回复里每个 token 的权重只有 1K 回复的 1/30, 长回复里的错误几乎罚不动; 改成除以 token 总数后每个 token 权重相同 (正文说按整个 batch 的 token 数归一, 式 (1) 只写了一组). 第一个 min 是**截断重要性采样**: 分子分母都用 $\theta_{\text{old}}$, 比值不含当前参数, 只衡量训练引擎与 vLLM 对同一 token 给的概率差多少, 截在 $\rho$ 是为了不让 vLLM 给了极低概率的 token 把梯度放大. 第二个 min 是 PPO 式裁剪, $\varepsilon_{\text{high}}>\varepsilon_{\text{low}}$ 就是 **clip-higher**: $A>0$ 时比值最多到 1.272, $A<0$ 时最低到 0.8. 对 $\pi_{\text{old}}=0.01$ 的 token, 对称裁剪下一步最多抬到 0.012, clip-higher 下可到约 0.0127 (心算); 上限按比例放, 概率越低的 token 绝对增量越受限, 放宽上界主要照顾它们. 按 DAPO 的说法这可以缓解熵塌缩, 报告本身只写了 「允许更大的更新」. 式里没有 $\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$ 项, 这就是**去 KL**, 作者称去掉后没有出现过优化或训练失稳.

式 (2) 只减组均值, 不除组内标准差. 奖励为 0/1 时可以直接算: 8 条里答对 $k$ 条, 答对者 $A=1-k/8$, 答错者 $A=-k/8$. 若再除以标准差 $\sqrt{p(1-p)}$ ($p=k/8$), $k=1$ 时答对者的优势是 $0.875/0.331\approx2.65$, $k=4$ 时是 $0.5/0.5=1$, 只做对一条的难题被放大到 2.6 倍以上 (心算); 不除时两者是 0.875 与 0.5, 优势只反映奖励本身的差. 这是 Dr GRPO 指出的难度偏置, 见 [03-DrGRPO-去标准差](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/02-DrGRPO-去标准差/02-DrGRPO-去标准差.md). $k=0$ 或 $k=8$ 时组内 $A$ 全为 0, 整组对梯度没有贡献, **丢组**就是把这类组拿掉, 缺口由 active sampling 补. RL-Zero 3.1 还撤回了一个 DAPO 组件: 3.0 版屏蔽被截断的回复, 作者后来发现屏蔽让实际 batch 大小波动, 训练更不稳, 不在超长负样本上训练还让回复更长, 于是 3.1 不再屏蔽, 同时把回复上限从 12K 提到 16K.

**active sampling** 是报告自称的新做法. DAPO 的 dynamic sampling 会生成训练 batch 三倍的提示, 以保证过滤后仍有足够的非零梯度样本; OlmoRL 在全异步框架里持续从结果队列拉取完成的回复, 过滤后不够就继续补, 直到凑满目标数量. Figure 26 在 RL-Zero 数学域上显示, 有 active sampling 时非零优势样本始终占满 batch, 训练 loss 的方差也明显降低; 没有它时, batch 会随训练推进越来越瘦, 这是原版 GRPO 的常见问题.

长推理 RL 的算力形状完全由生成决定 (§4.4.3). rollout 上限 32K, 推理模型平均超过 10K token. 32B 用 8 个 H100 节点训练, 20 个节点推理, learner 约 75% 的时间在等数据, GPU 用量上推理约是训练的 5 倍; 7B 是推理 7 节点对训练 2 节点, 约 14 倍. 一次代表性运行里, 每步平均 1000 秒, 其中训练只占 125 秒, 生成要提速 8 倍以上训练才会成为瓶颈. 32K 上限下平均生成长 14628, 若用静态批处理, 最多浪费 54% 的算力 (心算 (32768 − 14628)/32768).

Table 23 在 2 个 8×A100 节点 (一个训练一个推理) 上逐项加组件: OLMo 2 的 RL 设施 881 token/s, 加 continuous batching 到 975, 改进线程到 1358, 加 inflight updates 到 2949, MBU 从 12.90% 升到 43.21%. **inflight updates** 的做法是训练步结束后直接更新推理引擎的权重, 不暂停生成, 也不清空 KV 缓存; 代价是一条回复可能前半段由旧权重生成, 后半段由新权重生成, 策略略微偏离 on-policy, 截断重要性采样恰好兜住这类偏差 (这是按式 (1) 的结构做的解读). 脚注 43 给了直观对比: 早期一个检查点在 9 个节点上训 14 天才跑完一个 epoch, 加上两项改动后 5 个节点 7 天即可.

### 3.3. RL 之后分数怎样移动

Table 14 把 32B 的四个阶段排在一起 (SFT, DPO, Olmo 3 Think 最终版, Olmo 3.1 Think). 推理与指令遵循一路上升: AIME 2025 66.2 / 70.7 / 72.5 / 78.1, OMEGA 43.1 / 45.2 / 50.6 / 53.4, IFEval 83.9 / 80.6 / 89.0 / 93.8, IFBench 37.0 / 34.4 / 47.6 / 68.1. IFBench 在 3.1 上多出 20.5 分, 是续训 21 天里涨得最多的一项, 精确指令遵循的可验证奖励显然还远没饱和.

另一些格子在 RL 中下降. PopQA 33.1 / 37.0 / 31.9 / 30.9, AlpacaEval 2 LC 69.1 / 78.6 / 74.2 / 69.1, 两项都在 DPO 阶段见顶, 之后随 RL 回落. 长尾知识回忆和开放式聊天没有可验证奖励直接支撑, **长 RL 把模型推向推理与格式服从**, 这两类能力被挤掉一部分. 社区对 Olmo 3 的讨论里也提到 PopQA 下降, 表里的数字可以证实这一点. GPQA 在 Table 14 的 3.1 列是 56.7, Table 1 同一模型写的是 57.5, 引用时要带表号. Safety 在 3.1 上从 68.8 升到 83.6.

混合多个领域的 RL 数据, 是作者对 「过优化」 的主要防线. Figure 20 左显示, 只在 IFEval 上做 RL 时, IFEval 越高 AlpacaEval 越低; 混合训练时有 LM 裁判奖励维持聊天质量, 两者可以兼得. Figure 21 显示混合训练的每个领域训练奖励都低于单领域训练, 下游表现却不差, 作者把它读作 reward hacking 减少的迹象. 最终的 RL 数据把各领域精心过滤后大致等量混合, 起点是 DPO 检查点.

训练动态也有迹可循. Figure 18 里各领域奖励稳定上升, 指令遵循涨得最稳, 代码涨得最慢; 平均回复长度先略降再缓慢上升, 作者的解释是 SFT 与 DPO 已经把回复训练到接近 32K 上限. 这意味着 Think 线的 「推理变长」 主要发生在 SFT 与 DPO 阶段, RL 做的是在长度已饱和的前提下提高正确率, TestingTime 意义上的推理预算在进入 RL 前就基本定型了.

## 4. 另外两条线与成本边界

### 4.1. Instruct: 不思考的那条线

§5 的出发点是: 日常使用大多是求建议和查信息, 用不上 Think 那样的推理预算. Instruct 因此不产中间思考, 追求短而有用, 并专门训练 function calling. SFT 数据加入真实 MCP 轨迹与模拟的 SimFC 多轮工具交互, 并从 Think SFT 检查点热启动 (Table 29), 平均回复长度几乎不被带长. DPO 引入多轮偏好, 并把 chosen 与 rejected 的长度差卡在 100 token 以内, 防止模型靠写长赢偏好. RL 的回复上限按尺度分档: 7B 8K, 32B 16K; 脚注说两种长度在两档上都试过, 评测分几乎不变, 但内部试用中 7B-16K 与 32B-8K 出现不理想行为, 于是按定性测试定档.

Table 25 报的是 Olmo 3.1 32B Instruct, 它的阶段列说明 RL 在 Instruct 上作用更大. MATH 74.4 / 86.6 / 93.4, AIME 2025 8.2 / 23.3 / 57.9, IFBench 29.7 / 36.3 / 39.7. 与 Qwen 3 32B 关闭思考相比, AIME 2025 高 36.6 分 (57.9 对 21.3), IFBench 39.7 对 31.3, LitQA2 55.6 对 46.7; BFCL 58.8 对 63.1, MMLU 80.9 对 85.8, 仍落后. 与 Qwen 3 VL 32B Instruct 相比, AIME 2025 仍差约 6 分 (57.9 对 64.2).

偏好信号的来源在 Table 32 里比较过. 用 Delta Learning 启发式造的对 (大模型回复为 chosen, 小模型为 rejected) 与带 delta 意识的 GPT 裁判造的对, 在不同任务上的增益分布不同, 两者合用平均最好; 只把生成模型换强而不制造对比, 甚至输给 OLMo 2 的旧偏好数据. Figure 23 还显示偏好数据量存在与任务相关的最优点, 过了之后继续加数据会伤下游. 工具评测 (Table 31) 显示给不给工具的分差因模型和任务而异, 不能默认有工具就涨.

### 4.2. RL-Zero: 可复查的 RLVR 实验床

§6 的立论很直接: 现有开源 RLVR 研究多在不公开预训练数据的开权重底座上做, 评测集可能已混入 midtraining 数据, 于是随机奖励也能和真奖励一样有效, 修正提示模板的收益也可能盖过 RL 本身. Olmo 3 RL-Zero 从 Base 出发, 在数学, 代码, 精确指令遵循, 通用聊天和四者混合五个设定上做 RLVR, 数据 Dolci RL-Zero 对预训练和 midtraining 数据再去污染. RLVR 的边界讨论见 [4.4.3-RLVR的局限性与探索边界分析](../../../llm-guide/4-后训练/4.5-GRPO家族与RLVR/09-RLVR的局限性与探索边界/09-RLVR的局限性与探索边界.md).

数学数据来自 DAPO Math, Klear-Reasoner, Open-Reasoner-Zero 与 Omega, 按语义聚类每簇取一题, 再去掉底座 8 次采样全对的题, 得到 13.3K 条. 由于 Dolmino Mix 几乎不含特殊格式, 简单提示模板明显优于带 `<think>` 的后训练模板, 评测提示也去掉 `\boxed{}` 之类的格式. 算法沿用第 3.2 节, 只是训练回复长 16K, 评测回复长 32K, 温度 1.0, 以便报告 pass@k.

Figure 24 显示底座在最初几百步提升很快, 之后缓慢稳定上升, pass@32 也有提升, 说明多样性没有塌掉. 作者称 7B 的起点和终点分数接近 DAPO, 而 DAPO 用的是更大的 Qwen 2.5 32B, 训练步数多一个数量级 (附录 Figure 38, 这是读图比较). 混合设定下每个领域都比单领域训练欠优化, 作者把它定位成多目标 RLVR 的基准. 这条线的价值在于可复查: 改一处 midtraining 数据, 就能在同一套开放流程里看 RL 行为怎样变化.

### 4.3. 训练成本与谱系位置

§2.4 用墙钟而不是单一美元数报成本. 从开始训练到评测 Olmo 3 Think 32B 约 56 天, 集群为 1024 张专供 H100, 按每卡时 $2 折合约 $2.75M. 预训练段约 47 天: 5.5T 的初始预训练先在 512 卡上跑约 9.5 天, 再在 1024 卡上跑 35 天, 含所有崩溃恢复; midtraining 两路各 512 卡并行, 连同合并与评测约 1.5 天; 长上下文扩展连同合并评测约 1 天. 后训练约 9 天: SFT 约两天, DPO 单次学习率扫描约 18 小时 (每任务 64 卡) 但因集群不稳拖了多天, 最终 RL 约 5 天且至少损失一天. 3.1 版是首发后把最好的 RL 再续 21 天 (224 卡) 得到的, 不在 56 天之内.

这组数字的口径要看清. 脚注 2 说明配方是在 7B 或更小模型上开发后快速搬到 32B 的, 56 天只是 「配方定了之后跑一遍」 的时间, 不含配方搜索. 作者也提醒, 预训练占 GPU 小时的大头, 但后训练与阶段切换时的反复评测同样不小, 只报预训练小时会低估整个开发周期. 与 OLMo 2 不同, 这份报告没有能耗, 碳排和用水的表格, 这部分环境成本因此缺席.

Olmo 3 没有采用 MoE 或多模态模块, 训练上下文止于 65536, 更长的文档只在池子里公开. 安全评测位于附录 Table 52–55, 没有专门的安全 RL 阶段; SWA 对推理显存与延迟的收益也没有实测. 知识类基准相对最强开权重模型的差距从底座一直延续到后训练, 报告没有给出针对性的补救实验.

谱系上, OLMo 1 证明全栈可以公开, OLMo 2 把全开放 dense 线训稳并引入退火与 RLVR, Olmo 3 在同一骨架上为长推理重排了数据, 注意力和 RL 设施. SWA 是这一代在注意力上唯一的结构改动, 它的动机是长序列的算力; 同队后续的 Olmo Hybrid 沿着同一个动机更进一步, 用线性循环层替换大部分注意力层. 选型时, 需要长推理选 Think, 需要低延迟和工具调用选 Instruct, 想研究预训练数据与 RL 的关系选 RL-Zero, 引用分数时写全变体名和是否为 3.1.

## 5. 把架构数字放进同一套符号

### 5.1. dense 主干的参数从哪里来

设层数为 $L$, hidden size 为 $d$, FFN 中间维为 $d_f$, 查询头数为 $H_q$, KV 头数为 $H_{kv}$, 每头维度 $d_h=d/H_q$, 词表大小为 $V$. 一层 attention 的 Q 投影参数为 $d^2$, K、V 各为 $d\cdot H_{kv}d_h$, 输出投影为 $d^2$. SwiGLU 有 gate、up、down 三个矩阵, 参数约 $3dd_f$. 忽略 norm 和 bias 后,

$$
P_{layer}\approx2d^2+2dH_{kv}d_h+3dd_f. \tag{3}
$$

若 $H_{kv}=H_q$, 中间两项合成 $2d^2$, attention 共 $4d^2$; GQA 只缩小 K、V, Q 与输出投影仍是 $2d^2$. 总参数再加输入嵌入和 LM head:

$$
P_{total}\approx LP_{layer}+P_{embed}+P_{head}. \tag{4}
$$

OLMo 系列是否共享输入输出嵌入要以发布配置为准, 不能只用 $Vd$ 猜两张表. Table 33 给出的 7B/32B 规模是实际配置汇总, 式 (4) 用于理解参数随层数、宽度与 GQA 怎样变化, 不是替代表中的精确计数.

32B 的 40 个 Q 头与 8 个 KV 头意味着每 5 个查询头共享一组 K、V. 对单层单 token, KV cache 元素数由 MHA 的 $2H_qd_h=2d$ 变为 $2H_{kv}d_h=2d/5$. 若 BF16 每元素 2 字节, $S$ 个缓存位置、$L$ 层、batch 1 的理想 KV 字节数为

$$
M_{KV}=2\text{ bytes}\times 2L H_{kv}d_h S. \tag{5}
$$

再乘 SWA 与 full 层各自保留的位置数. 对四层一组的三层 SWA、一层 full,

$$
M_{KV}^{hybrid}\approx2\text{ bytes}\times2H_{kv}d_hL
\left(\frac34\min(S,W)+\frac14S\right), \tag{6}
$$

$W=4096$. 当 $S=65536$ 时, 括号相对全 full 的比例为 $0.25+0.75/16=0.296875$. 32B 再乘 GQA 的 $1/5$, 相对同层同宽 MHA+full 的理论 KV 比例约 5.94%. 这只是张量主体, 分页、对齐和运行时缓冲会增加实际显存.

### 5.2. SWA 节省的训练计算量

标准 causal attention 在序列长 $S$ 时, 每层 QK 与 AV 的主要乘加量随 $S^2d$ 增长. 窗口 $W<S$ 时约为 $SWd$. 令 full 层比例为 $r=1/4$, 则 attention 二次项相对全 full 的比例为

$$
R_{attn}(S)=r+(1-r)\frac{W}{S}. \tag{7}
$$

$S=8192,W=4096$ 时为 $0.25+0.75\times0.5=0.625$; $S=65536$ 时为 0.296875. 模型总 FLOPs 的下降不会达到这个比例, 因为 MLP、投影和 norm 仍按 $S$ 线性执行. 模型越宽、$d_f$ 越大, 线性项占比越高, SWA 对总训练吞吐的改善越小.

SWA 的 receptive field 也不是简单的 $LW$. 在连续 causal window 层中, 信息每层最多向前传播 $W-1$ 个位置, $m$ 层后理论覆盖约 $1+m(W-1)$; 插入 full 层后, 该层任意位置可以直接读取整个此前序列. 下一组 SWA 再传播的是已经聚合过全局信息的表示. OLMo 3 每四层安排一个 full 层, 让每个深度区间都有全局汇聚点, 代价是四分之一层仍保留 $S^2$ 项.

末层强制 full attention 的作用可以用反例看. 若最后若干层全是 SWA, 序列开头的证据即使在早期 full 层被写入某个中间 token, 也要沿窗口传到当前输出位置;传播失败时 logits 看不到它. 最后一层 full 允许输出位置直接检索所有最终层输入. 这不保证模型会正确使用远处证据, 只保证计算图中存在一跳路径.

### 5.3. QK-Norm、RMSNorm 与 z-loss分别控制什么

对单头 query $q_t$ 与 key $k_s$, QK-Norm 先按 RMS 归一化:

$$
\operatorname{RMS}(q)=\sqrt{\frac1{d_h}\sum_{j=1}^{d_h}q_j^2+\epsilon},
\qquad
\bar q=\gamma_q\odot\frac{q}{\operatorname{RMS}(q)}, \tag{8}
$$

$k$ 同理. attention logit 为 $a_{ts}=\bar q_t^\top\bar k_s/\sqrt{d_h}$. 若没有 QK-Norm, 投影权重或残差尺度增长会同时放大 $\lVert q\rVert\lVert k\rVert$, softmax 进入极尖区域;归一化把主要自由度移到方向与可学习尺度 $\gamma$. 它稳定的是 attention logits, 不约束 MLP 激活或最终词表 logits.

子层输出 RMSNorm 的位置与常见 pre-norm 不完全相同. 抽象写成

$$
x_{l+1}=x_l+\operatorname{RMSNorm}(F_l(x_l)). \tag{9}
$$

归一化作用于残差分支输出, 让每个子层写回 residual stream 的尺度受控. 它没有把主残差 $x_l$ 每层重新归一, 所以残差流仍能积累. 报告把这一设计从 OLMo 2 继承, OLMo 3 的主要增益没有对应的 norm 消融.

z-loss直接约束词表 logits 的 log-partition. 设 logits 为 $z_v$, 则

$$
\mathcal L_z=\lambda_z\left(\log\sum_{v=1}^V e^{z_v}\right)^2,
\qquad \lambda_z=10^{-5}. \tag{10}
$$

交叉熵对所有 logits 加同一常数不变, 因而存在整体漂移方向;z-loss 给这个方向一个小惩罚. QK-Norm、输出 RMSNorm 和 z-loss作用在 attention 内部、残差写回、最终词表三个不同位置, 不能互相替代.

embedding 不做 weight decay 也应与 z-loss 分开. AdamW 对普通权重执行 $w\leftarrow(1-\eta\lambda)w-\eta\hat g$, 稀疏更新的 embedding 行若长时间未出现仍会被持续缩小;排除 weight decay 可以避免低频 token 的向量仅因没被采到而衰减. 这条配方沿用上一代, 没有证据表明它专门导致 OLMo 3 的长推理提升.

## 6. 数据混合是一个有容量约束的分配问题

### 6.1. 9T 数据池与 6T 训练流

设来源 $j$ 的可用独有 token 为 $X_j$, 训练分配为 $Z_j$, 重复上限为 $M_j$. Olmix 的基本约束是

$$
\sum_jZ_j=B,\qquad 0\le Z_j\le M_jX_j, \tag{11}
$$

$B\approx5.93$T 是目标训练流. Common Crawl 池 8.14T 而分配 4.51T, 采样率约 55.4%;olmOCR 科学 PDF 972B 取 805B, 约 82.8%;Stack-Edu 137B 分配 409B, 平均重复约 2.99 次. 「池占比」和「训练占比」由此分开: 大网页池被下采样, 小而高价值的代码池被重复.

若简单按池大小采样, Common Crawl 会压倒其他来源. 若简单给小域高权重, 又可能让少量文档重复几十次. 式 (11) 的上限把主题价值与独有容量连在一起. 报告让重复上限约落在 4–7, 并用代理模型预测不同 $Z_j/B$ 下的下游 BPB. 这仍是经验优化: 代理尺度上最优的比例未必在 32B 完全保持, 所以还需要 integration test.

6T mix相对9T池并非「删掉3T低质数据」这么简单. 某些源未取完, 某些源重复, 最终 token 流中的重复位置也算训练预算. 训练 6T token 不代表看过 6T 独有 token. 对 Stack-Edu, 409B 训练 token只对应137B池;对网页则4.51T训练token来自更大的8.14T候选.

### 6.2. 质量上采样曲线的守恒关系

对一个主题, 质量分位 $x\in[0,1]$ 的重复函数为

$$
f_{p,\lambda}(x)=C(x-a)^pe^{\lambda(x-a)}\mathbf1[x\ge a]. \tag{12}
$$

设主题池有 $X$ token、目标分配 $Z$, 则平均重复数必须满足

$$
\int_0^1f_{p,\lambda}(x)\,dx=\frac ZX. \tag{13}
$$

$a=0.4$ 意味着最低 40% 分位取零次. 剩余 60% 要承担全部 $Z$. 若 $Z/X=2$, 被保留部分的条件平均重复数是 $2/0.6\approx3.33$;最高档还可到 7 次. 因而「平均重复两次」不表示每篇恰好两次, 实际是低质丢弃、高质多次出现.

单调曲线把最高质量档设为最大重复. 对宽度 $b$ 的顶部档,

$$
\frac1b\int_{1-b}^1f(x)dx\le M. \tag{14}
$$

约束 (13) 固定总量, 约束 (14) 限制最高端, $p$ 与 $\lambda$ 决定中间质量的分配. Table 39 的平坦过滤对照相当于 $f(x)$ 是阶跃函数:阈值以上同一重复数, 无法区分「刚过线」和最高分位. 截断幂指数曲线让质量差异连续进入采样次数, Code BPB 0.719 对最佳平坦方案 0.880 的结果支持这种分配, 不能推出任何单独文档的质量分数绝对正确.

BPB 越低表示对验证字节赋予更高似然. 用多个任务的预测 BPB 做混合优化, 相当于在代理模型上求多目标折中. 算术平均让各任务绝对变化等权, 若任务基线尺度不同, 标准化方式会影响最优比例. 报告公开了工具与对照, 仍要把结论限定在其代理模型、评测簇和候选来源上.

### 6.3. 数据清洗数字怎样串起来

Common Crawl 线性化后 252.6B 文档, 启发式与英文过滤剩 38.7B, 存活率

$$
\frac{38.7}{252.6}\approx15.32\%. \tag{15}
$$

随后精确去重去掉约 66%, 若以 38.7B 为基数, 剩约 13.2B, 报告给 12.7B, 差异来自各步精确口径和四舍五入. MinHash 与后缀数组继续删除近重复和模板片段. 过滤与去重回答两类问题: 前者判断单篇是否像高质量文本, 后者判断内容是否在池中反复出现.

精确哈希只能抓完全相同内容;网页模板改一个日期或广告就会逃过. MinHash用 shingles 集合的 Jaccard 近似,

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}, \tag{16}
$$

阈值 0.80 抓大段相同文档. 后缀数组再从文档内部寻找跨样本重复片段. 三层顺序让便宜的精确去重先缩池, 再把昂贵近重复方法用在较小集合上.

去重影响的不只是训练效率. 如果同一道评测题在网页镜像、答案站和 PDF 中多次出现, 上采样还会进一步放大它. OLMo 3 对 midtraining 的所有 split 去污染, 后训练再用 8-gram 重叠, 正是因为每个阶段新增数据都可能重新引入评测内容.

## 7. 三段 Base 训练不是三个互不相干的 checkpoint

### 7.1. token 流与学习率接力

把三个阶段的 token 数写为 $T_{pre},T_{mid},T_{long}$. 7B 约为 5.93T、100B、50B, 总计约 6.08T;32B 初始预训练在 5.5T 截止, 再接 100B midtraining 和 100B 长上下文, 总计约 5.7T. 所以 32B 并未完整走完按 5.93T 设计的预训练 epoch, 报告的「训练 token 少约 6x」应按各比较模型公开口径理解, 不能从单一阶段数字推出.

预训练余弦日程把通用数据上的学习率降下来;midtraining 再用面向高质量数据的衰减到零;长上下文阶段从已有能力出发做短而专的适配. 若每一段都重新用大峰值学习率, 后段小数据会覆盖前段知识. 阶段划分的作用既是换数据, 也是为不同目标选择不同更新强度.

以 batch $B$ token、训练量 $T$ 估算优化器步数 $N=T/B$. 7B 预训练若全程 batch 4M, 5.93T 对应约

$$
N_{pre,7B}=5.93\times10^{12}/(4\times10^6)\approx1.4825\times10^6\text{ steps}. \tag{17}
$$

32B batch 8M、5.5T 对应约 687,500 步. 真实运行可能在 warmup 或恢复时调整, 这个复算用于核对量级. midtraining 100B 若沿用 4M/8M, 分别只有约25K/12.5K步, 每个更新对终局影响更集中.

### 7.2. midtraining 改的是后训练初始分布

自回归预训练最小化

$$
\mathcal L_{LM}(\theta)=-E_{x\sim D}\sum_t\log p_\theta(x_t\mid x_{<t}). \tag{18}
$$

把 thinking trace 混入 $D$ 后, 模型在问题上下文下看到「分解—检查—修正—答案」的完整序列, 这些行为进入条件分布. 后续 RL 的探索仍从当前策略采样;若底座几乎不产生回溯或长推理, 可验证奖励很难给从未采到的行为梯度. Figure 25 中推理数据不足的底座回复长度不增长, 展示了这个支持集限制.

这不等于 midtraining 直接教会最终推理. Table 10 的 100B 对照证明含后训练性质数据的 mix 在该实验上更好, 最终 Think 能力还经过 SFT、DPO 与 RL. 若把后训练分数全部归因于 midtraining, 会忽略后三段更新;若只看 RL, 又会忽略策略能否采到有效轨迹取决于底座.

特殊 token 反例说明「内容相同」仍可能改变目标. 一个新特殊 token 有独立 embedding, midtraining 中频繁出现会让模型学会输出它;推理时模板不期望这些符号, GSM8K 可从49.43掉到0. 换成普通换行后,语义结构保留, 新离散符号消失. 最终方案把特殊 token 留到SFT, 让它在明确聊天协议中学习.

### 7.3. 模型 soup 的条件

32B midtraining 用两个数据顺序种子得到参数 $\theta_1,\theta_2$, 再做权重平均

$$
\theta_{soup}=\frac12(\theta_1+\theta_2). \tag{19}
$$

两条轨迹从同一预训练 checkpoint 出发、数据 mix 与优化日程相同, 因而大概率停在同一低损失盆地附近. 在线性连接路径损失不高时, 参数平均能组合不同顺序带来的误差. 若两个模型来自不同初始化或发生神经元置换, 式 (19) 可能直接破坏功能.

合并后 Math 相对两次单跑分别高 2.9 与 1.6, 证明该工作点有效;它不是「两个模型推理集成」, 部署仍是一份32B权重. 开放两个源 checkpoint、合并脚本与评测配置, 才能判断增益来自平均还是另一次未说明训练.

## 8. 长上下文扩展同时改位置、样本和可见性

### 8.1. best-fit packing 保住文档整体

设序列容量为 $S=65536$, 文档长度为 $\ell_i\le S$. 普通 concat-and-chunk 先连接所有文档再每 $S$ 切一刀, 文档被切概率随长度上升;一篇 40K 文档跨过切口后, 任一训练样本可能只见前半或后半. best-fit packing 把每篇文档作为不可分物品, 放入剩余空间最小且仍容得下的箱子. 目标近似最小化

$$
P_{pad}=1-\frac{\sum_i\ell_i}{NS}, \tag{20}
$$

$N$ 为打包后的序列数. 报告称 padding 几乎可忽略, 同时减少文档切断. 对长程任务而言, 关键收益是同一文档的首尾进入同一 attention 图, 不是 padding 本身.

超过 $S$ 的文档仍必须切分, best-fit 无法保全;低于 $S$ 的很多长文也会与其他文档同箱. 因此还需要文档内 attention mask. 设 token $t$ 的文档 ID 为 $d(t)$, causal 可见性为

$$
M_{ts}=\mathbf1[s\le t]\mathbf1[d(s)=d(t)]. \tag{21}
$$

跨文档位置置为不可见. 不加这项时, 后一篇文档可以把前一篇尾部当上下文, 训练出部署时不稳定的伪关联. mask 不改变 token 数, 会让有效 attention 块变稀疏;实现若仍计算整张矩阵, 语义正确但算力未完全节省.

### 8.2. YaRN 为什么只改 full 层

RoPE 对第 $m$ 对通道使用角频率 $\omega_m$, 位置 $p$ 的旋转角为 $p\omega_m$. 长度扩展改变高位置角度范围. Position interpolation把位置缩为 $p/s$, 直接减慢所有频率;调整 base 则改变频率谱;YaRN按频段混合插值与外推并调整attention尺度.

SWA 层只见相对距离 $|p-q|\le4096$, 预训练阶段已经覆盖该范围. 若给它们也做长度缩放, 同样的局部距离会映射成新角度, 已学局部模式受到扰动. full 层会见到 8K 之外直到65K的距离, 必须扩展频率. Figure 13a 中「仅 full 层 YaRN」最好, 与这个分工一致.

反例是跨窗口信息可能经多层 SWA 接力, 中间每一跳仍是局部距离, 原 RoPE 足够;真正的一跳远距检索只发生在 full 层. 这给出了机制解释, 报告没有逐头分析证明模型按这种方式使用位置.

### 8.3. 长短数据比例保护了什么

长文档 34%、高质量短数据66%的比例来自10B早期对照. 长66%时 OlmoBaseEval 子集掉2.5分, 长34%只掉0.8. 训练总量固定时, 增加长数据必然挤掉短数据;性能变化同时包含序列长度和内容域变化. Longmino 以科学 PDF 为主, 与原短 mix 的主题分布也不同, 所以不能把2.5分全解释成「长序列伤短能力」.

设扩展 mix 为 $D_\alpha=\alpha D_{long}+(1-\alpha)D_{short}$. 目标是同时压低长程损失与保持原能力:

$$
\min_\theta\ \alpha\mathcal L_{long}(\theta)+(1-\alpha)\mathcal L_{short}(\theta), \tag{22}
$$

并受固定 token 预算约束. $\alpha=0.34$ 是当前预算和来源下的经验折中. 32B 从50B增到100B后长基准继续改善, 说明50B未饱和;是否继续增加仍不伤短任务, 报告没有给更远曲线.

gzip 过滤保留可压缩性中间60%. 极易压缩文档常含重复模板、乱码循环或低信息文本;极难压缩可能是随机串、表格噪声或解析失败. 中间区是廉价代理, 不直接测长程依赖. LongPpl筛选未胜过gzip, 表明复杂模型分数在当前管线没有转成更好下游结果.

### 8.4. RULER 与 HELMET 的角色

RULER参与开发, 因此用于选YaRN、数据量和打包方案的结果带有调参适应;HELMET保留为未见套件, 更接近外部验证. 32B在RULER 65K为79.70、HELMET 65K为43.15, 两个绝对分数不可直接比较, 因为任务构成和计分不同;共同趋势是长端仍弱于部分同档模型.

4K优秀、65K下降说明「支持65K输入」只证明位置编码和内存能够运行, 不等于65K内稳定利用信息. 有效上下文应按检索、聚合、长文问答等任务分别测. CWE与REX合成数据提供计数和改写监督, 覆盖不了全部长程推理结构.

## 9. 从 SFT 到 DPO 再到 RL 的统一视角

### 9.1. SFT改变策略支持集

SFT 对回复 $y$ 的 token 负对数似然为

$$
\mathcal L_{SFT}=-\frac{1}{|y|}\sum_{t=1}^{|y|}\log\pi_\theta(y_t\mid x,y_{<t}). \tag{23}
$$

Think 数据包含长推理轨迹, 把策略概率质量移到分步推理、回溯与答案格式上. 若按样本平均, 长短回复各贡献一份总权重, 长回复每 token 权重更小;若按全 batch token 平均, 每 token权重相同, 长回复总贡献更大. 报告不同阶段的归一口径需随实现读取, 不能只看公式名.

SFT规模从小到大时先提升、后饱和. 重复增加相似轨迹会降低边际收益, 还可能固化模板. 数据过滤与多样性比单纯对数增长更重要. 7B和32B使用不同样本量, 也说明大模型容量与最佳数据预算不能从一档直接复制.

### 9.2. Delta Learning构造偏好方向

DPO对chosen $y^+$ 与rejected $y^-$ 优化

$$
\mathcal L_{DPO}=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y^+|x)}{\pi_{ref}(y^+|x)}-
\log\frac{\pi_\theta(y^-|x)}{\pi_{ref}(y^-|x)}
\right]\right). \tag{24}
$$

Delta Learning用能力不同的生成模型制造有方向的差异:较强模型给chosen、较弱模型给rejected, 或让裁判显式关注两者差异. 这比从同一分布随机抽两条再打分更容易得到可学习的能力梯度. 若强弱模型风格差异与能力无关, DPO也可能学到长度、措辞等捷径, 所以Instruct把长度差限制在100 token内.

DPO从SFT到数学、代码和聊天都有提升, 精确指令遵循却下降. 式(24)只保证偏好对上的相对概率变化, 没有约束所有未进入偏好集的能力. 数据量过大时持续沿偏好方向移动, 会越过下游最优点;Figure 23的任务相关停点正是这种过优化.

### 9.3. OlmoRL里两个概率比

OlmoRL目标含两个比值. 策略更新比

$$
r_{i,t}=\frac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{old}(y_{i,t}|x,y_{i,<t})} \tag{25}
$$

控制当前参数离采样策略多远. 引擎修正比

$$
c_{i,t}=\frac{\pi_{old}(y_{i,t}|x,y_{i,<t})}{\pi_{vLLM}(y_{i,t}|x,y_{i,<t})} \tag{26}
$$

衡量训练引擎与 rollout 引擎在同一旧权重下的概率差, 再截断为 $\min(c_{i,t},\rho)$. 两者相乘时,前者随$\theta$产生梯度,后者是样本权重. 将两个比值都叫 importance ratio 容易混淆它们修正的对象.

组奖励为二元值、组大小$G=8$,答对$k$条时,不除标准差的优势为

$$
A^+=1-\frac{k}{8},\qquad A^-=-\frac{k}{8}. \tag{27}
$$

$k=0$或8时全组优势为0,过滤不会损失梯度;active sampling补充新prompt直到凑足目标非零组. 训练后期模型变强,全对组增多,若不补样本,有效batch逐渐缩小. 这解释了Figure26中loss方差的变化.

token级归一把总损失除以$\sum_i|y_i|$. 一条30K回复与一条1K回复中,每token权重相同;长回复总权重大约30倍. 与逐样本归一相比,它避免长链每个token被缩小,同时也让超长轨迹主导batch. 回复上限、长度分布和是否过滤截断样本因此都是目标的一部分.

### 9.4. 长RL为何挤压未奖励能力

混合RL奖励覆盖数学、代码、指令和聊天,每个领域仍只观测有限验证器. 参数更新近似为

$$
\Delta\theta\propto\sum_d w_dE_{(x,y)\sim\pi}[A_d(x,y)\nabla_\theta\log\pi_\theta(y|x)]. \tag{28}
$$

PopQA长尾知识与开放式聊天若没有直接奖励,只能依靠共享参数的正迁移或起点约束维持. 去掉KL后没有显式力把策略拉回参考模型,所以DPO阶段见顶的AlpacaEval、PopQA在RL中回落并不意外. 混合领域降低单域reward hacking,仍无法保护完全未覆盖的能力.

3.1续训让IFBench大涨20.5分,同时AlpacaEval继续下降. 这是一条清晰的Pareto移动,不能用单一平均分概括为全面提升. 选择3.0还是3.1取决于精确指令遵循与开放聊天的权重.

## 10. 开放检查点让哪些实验真正可复现

### 10.1. model flow是一张有向图

把每个公开checkpoint视为节点、训练阶段视为边. Base节点由预训练、midtraining、长上下文扩展串联;之后分叉到Think、Instruct、RL-Zero. Think与Instruct各有SFT、DPO、RL节点,3.1又是最终RL节点的续训. 若只发布叶子权重,观察到的差异无法定位到哪条边;公开中间节点后,可以做配对比较.

例如检验DPO作用,应比较同一SFT起点与对应DPO终点;检验RL作用,比较同一DPO起点与RL终点;检验字节化任务算术时,需要基座OLMo 3、后训练OLMo 3和Bolmo三组同坐标权重. model flow的价值来自节点身份、数据版本和代码commit共同固定.

### 10.2. 数据可追踪性如何支撑RL-Zero

随机奖励污染测试的逻辑是:若模型在预训练中记住题目—答案映射,即使奖励与正确性无关,策略更新也可能放大已存在的正确答案概率;若从未见过,随机奖励平均不提供正确方向. 实验中各基准持平或下降,支持未发现这种记忆放大.

它不是污染的完备证明. 随机RL步数、学习率或探索不足时,已记忆答案也可能未被激活;语义改写污染不一定被8-gram匹配捕获;基准答案若在数据中出现而题干不同,检测也更难. 开放数据允许后续研究用更强匹配和不同随机奖励协议复查,这比一次「无污染」声明更有价值.

去污染还会降低某些公开train split带来的能力信号. DROP、Minerva、SQuAD掉分说明此前训练数据可能合法包含任务训练集,全部split去除改变了训练分布. 评测公平与利用公开监督之间存在选择,报告选择更严格隔离以支持数据实验.

### 10.3. 最小复现实验应固定什么

复现Base阶段至少要固定:数据清单与顺序种子、tokenizer版本、模型config、优化器与学习率日程、全局batch、checkpoint起点、SWA/full层布局、去污染版本. 长上下文还要固定packing、文档内mask、YaRN仅作用full层和CP布局. 后训练再加入prompt模板、采样温度、最大回复长、验证器版本、每题rollout数与过滤策略.

仅对齐token数不够. 两个100B midtraining run若数据顺序、特殊token处理或污染过滤不同,后续RL行为可能明显分叉. 仅对齐最终平均分也不够:同一均分可以由知识高、数学低或相反组合得到,而后训练可塑性不同.

checkpoint复现还应验证连续性. 从保存点恢复后,先比较下一batch的loss、梯度范数、学习率与数据ID;模型参数相同但数据游标或随机数状态不同,长期轨迹会分叉. 报告公开崩溃恢复耗时,说明大训练中的恢复是正常路径,不属于边缘情况.

### 10.4. 结论的适用范围

现有证据能支持:同一dense骨架上,重做数据mix、加入100B推理导向midtraining、做50B/100B长上下文扩展,再用SFT—DPO—RL流程,可以把全开放32B模型推到强数学与指令遵循水平;SWA让长序列成本下降;midtraining数据显著影响RL能否拉长推理;混合RL减少单域过优化但仍会牺牲未奖励能力.

报告没有隔离出每个最终分数分别由SWA、数据mix、midtraining或RL基础设施贡献多少. 两代跨度包含多个同时变化因素,不能把OLMo2到3的全部提升归给某一项. 32B配方主要从7B与更小实验迁移,缺少每个超参数在32B的全量消融. 65K支持仍落后部分同档模型,推理KV和延迟收益是结构估算而非报告实测.

**OLMo 3真正公开的是一条可重新走的训练路径: 数据怎样进入底座, 底座怎样获得长推理的支持集, 长上下文怎样接上, 三条后训练分支又怎样交换能力.** 最终权重是路径末端的一组结果;中间checkpoint与数据版本让反例、替代mix和新RL算法可以从同一个坐标重新实验.

## 11. 评测设计怎样服务数据决策

### 11.1. 为什么按能力簇做宏平均

假设一个类别有 $m$ 个任务, 第 $j$ 个任务有 $n_j$ 个样本、准确率 $a_j$. 微平均按样本数加权:

$$
A_{micro}=\frac{\sum_jn_ja_j}{\sum_jn_j}. \tag{29}
$$

样本多的任务会支配结果. 宏平均则为

$$
A_{macro}=\frac1m\sum_{j=1}^m a_j, \tag{30}
$$

每个任务一票. OLMoBaseEval再向上一层按MC STEM、MC Non-STEM、GenQA、Math、Code、FIM等能力簇聚合, 防止同一题型拥有很多近亲基准后重复计权. Ward聚类用约23K条模型—任务分数寻找变化模式相近的任务, 人工再把统计簇对齐到可解释能力.

聚类不等于任务存在唯一客观分类. MMLU子科目可能同时涉及知识与推理,代码任务也会要求数学. Ward距离受输入模型集合和分数归一化影响;换一批模型可能重排簇. 它的用途是给大量microanneal实验提供稳定仪表盘,不应把簇名解释成模型内部模块.

bits-per-byte与准确率也不能直接平均. BPB越低越好且尺度连续,任务准确率越高越好且存在随机基线. 混合优化用逐任务回归预测BPB,最终能力表再按各自归一口径汇总. 如果把未经变换的0.8 BPB与50%准确率放进一个算术平均,单位没有意义.

### 11.2. 小模型代理何时会撒谎

小模型在难题上接近随机. 选择题有 $K$ 个选项时,随机准确率为$1/K$,样本数$n$下的标准误近似

$$
\operatorname{SE}(\hat p)=\sqrt{\frac{p(1-p)}{n}}. \tag{31}
$$

四选一、$n=100$时,随机点$p=0.25$的标准误约4.3个百分点. 两个数据mix差1分完全可能是噪声. 增加样本数、合并相关任务、改用排序或BPB代理,都能提高信噪比.

代理还可能在高尺度饱和. 某任务对1B模型有清晰梯度,到32B多数模型都接近满分,就无法区分mix. 相反,某任务在1B全是随机,到32B才出现能力,也不适合小实验. 报告用OLMo 2 scaling家族检查低算力信号,再用约70个开权重模型检查高端饱和,筛出Base Easy与Base Main两套仪表.

这套筛选可能偏向已有模型家族能表现出的差异. 如果一种新数据只改善当前套件未覆盖的能力,代理优化看不到它;若任务簇与最终Think/工具使用目标错位,预训练mix也可能被带向局部最优. midtraining后接一小段SFT测试「可后训练性」,就是为了补一层终局相关性.

### 11.3. pass@k怎样改变代码结论

若从一个题目采$n$个候选,其中$c$个通过,无偏pass@$k$估计常写为

$$
\widehat{\operatorname{pass@}k}=1-\frac{\binom{n-c}{k}}{\binom nk}. \tag{32}
$$

它衡量从$n$个样本中无放回抽$k$个至少一条成功的概率. 当$c=0$时为0,当$n-c<k$时为1. pass@1偏向单次可靠性,pass@16同时奖励多样性与覆盖.

Think模型生成长、采样成本高,不同任务可能使用不同$n$与最大长度. 比较两个模型的pass@k时,温度、top-p、停止条件与验证器必须一致. OLMo 3报告AIME上DPO不仅提高pass@1,pass@k也提高,支持能力上界变化;如果只提高pass@1而pass@k不变,更像把已有候选概率集中到正确答案.

RL-Zero报告pass@32不降,用来反驳策略熵完全塌缩. 它仍是任务级行为指标,不等于token熵处处保持. 模型可以在少数决策点保留多样性、其他位置变得确定;也可以产生表面多样但答案等价的轨迹. 结合长度、token熵和去重后的答案多样性更完整.

### 11.4. 方差桶如何约束一两分差距

报告让14个模型各跑3次,按任务统计标准差,再把任务分为不同稳定性档. 若模型A比B高$\Delta$,两者独立运行方差为$\sigma_A^2,sigma_B^2$,差值标准误约

$$
\operatorname{SE}(A-B)=\sqrt{\frac{\sigma_A^2}{r_A}+\frac{\sigma_B^2}{r_B}}. \tag{33}
$$

单次运行$r_A=r_B=1$时,高方差任务上一两分不宜过度解读. 多任务宏平均能降低部分独立噪声,任务误差相关时下降没有$1/\sqrt m$那么快.

开发期间反复查看同一基准还会产生选择偏差. 即使每次噪声均值为零,从几十个配方中挑最高者也会挑到正噪声. HELMET留作未见套件,长上下文最终在它上面的差距比RULER更能检验开发选择是否泛化. 同理,最终安全表没有参与主要RL奖励,作用更像外部审查而非训练目标.

## 12. 长回复RL的系统形状与算法偏差

### 12.1. 为什么生成比训练贵

训练对一条长度$T$的回复可以把所有token并行前向、再反向;生成必须做$T$次顺序decode. 虽然每步复用KV cache,小batch decode的矩阵利用率低,还要等待不同长度请求. 报告32B代表运行平均生成14,628 token、上限32,768,静态padding浪费比例为

$$
1-\frac{14628}{32768}\approx55.36\%. \tag{34}
$$

正文心算54%来自读数与口径取整,精确代入约55%. continuous batching让完成的请求立即腾位,新请求进入,把padding浪费换成动态调度.

32B训练8个H100节点、推理20个,learner约75%时间等数据. 若每步总计约1000秒而训练125秒,生成及等待约875秒. 生成吞吐提高7倍时二者才接近,考虑通信与验证器后报告给「8倍以上」. 增加learner卡不能解除瓶颈,反而可能让等待比例更高.

7B推理7节点、训练2节点,按卡数与时间综合估算推理GPU用量约训练14倍. 模型变小后训练前反向加速显著,自回归顺序长度仍在,所以rollout占比反而上升. RL成本不能只按参数量从32B线性缩放.

### 12.2. inflight updates带来什么off-policy偏差

一条回复在权重版本$\theta^{(v)}$下开始生成,中途learner更新到$\theta^{(v+1)}$,后半段可能由新版本产生. 整条轨迹的行为策略成为

$$
\mu(y|x)=\prod_{t\le t_*}\pi_{\theta^{(v)}}(y_t|h_t)
\prod_{t>t_*}\pi_{\theta^{(v+1)}}(y_t|h_t). \tag{35}
$$

它不等于任一单一checkpoint策略. 若训练端仍把分母写成一个$\pi_{old}$,importance correction只是近似. vLLM记录逐token行为概率,式(26)可以修正实现差异和部分版本偏差,截断$\rho$避免极端权重;截断同时引入偏差,换取方差受控.

不清空KV cache还有另一层问题:缓存中的K、V由旧层权重计算,更新后继续decode时,新query与旧cache共同参与attention. 因而行为分布甚至不等于「前半旧模型、后半新模型」的干净拼接. 实测吞吐从1358升到2949 token/s,表明工程收益巨大;算法上应把它看作受控异步近似,不是严格on-policy GRPO.

若权重更新很小,相邻版本分布接近,偏差有限;更新大或回复极长时,一条轨迹可能跨多个版本. 可监控每条回复跨越的版本数、行为与训练log-prob差、截断比例. 报告公开修正目标,没有给这些分布的完整直方图.

### 12.3. active sampling改变训练数据分布吗

原始prompt分布记为$p(x)$. 某prompt产生非零优势组的概率为$q_\theta(x)$,过滤全对/全错组再补样本后,进入梯度的prompt分布近似

$$
p_{active}(x)\propto p(x)q_\theta(x). \tag{36}
$$

过易题$q$低,因为常全对;过难题也$q$低,因为常全错;决策边界附近$q$高. active sampling维持有效batch,也让训练自适应聚焦当前难度适中的题. 随模型变强,同一道题的$q$会变化,形成隐式课程.

这与简单「补到固定batch」不同:若不做逆概率加权,目标已从原$p(x)$转成$p_{active}(x)$. 对RLVR来说这种聚焦往往有益,但报告的奖励提升不能解释成在原始prompt分布上无偏优化. 若希望恢复原分布,可按$1/q_\theta(x)$加权,小$q$会导致高方差.

每题$G=8$也决定$q$. 对单条正确概率$p$,忽略相关性时全同组概率为$p^8+(1-p)^8$,非零优势概率

$$
q(p)=1-p^8-(1-p)^8. \tag{37}
$$

$p=0.5$时约0.992,$p=0.1$时约0.570,$p=0.01$时仅约0.077. 更大$G$能让极难题更可能出现至少一个正确答案,rollout成本也线性增加.

### 12.4. clip-higher的方向性

PPO式目标对正优势取$\min(rA,(1+\varepsilon_{high})A)$,对负优势由下界$1-\varepsilon_{low}$限制. OLMo 3用$\varepsilon_{low}=0.2,\varepsilon_{high}=0.272$. 对旧概率$p=10^{-3}$的正确低概率token,局部忽略归一化耦合,允许提高到约$1.272\times10^{-3}$;对称0.2只能到$1.2\times10^{-3}$. 差值很小,但长回复每步累积,能帮助罕见正确推理路径增长.

clip-higher不保证熵上升. 它放宽正优势概率增长,若奖励集中在少数固定轨迹,反而可能让这些轨迹更占优势. 熵结果还取决于负样本、采样温度、去KL和多领域数据. 报告借DAPO动机采用该设置,没有单独给OLMo 3的clip对照.

## 13. 三条后训练分支解决不同目标

### 13.1. Think的长度来自哪里

Think在SFT阶段就学习长推理格式,DPO继续提高数学代码与聊天偏好,进入RL前平均回复已接近32K上限. Figure18里RL期间长度先略降再缓慢上升,说明最终能力增长主要来自固定长预算内提高轨迹质量,而非持续增加推理token.

这一区分很重要. 如果分数提高同时长度翻倍,需要判断是算法更会推理还是仅花更多测试时计算;OLMo 3后段长度相对稳定,更支持策略质量变化. 不过不同任务的长度分布可能移动,平均值会掩盖数学变长、代码变短等结构.

3.1取消截断回复屏蔽并把上限从12K提到16K的描述针对RL-Zero版本演进;Think旗舰rollout上限32K. 变体与阶段的长度不能混写. 被截断负样本若完全不训练,策略缺少「别无限写」的信号,回复可能越来越长;保留它们能让验证失败产生负优势.

### 13.2. Instruct为何从Think SFT热启动

Instruct不输出中间思考,仍可复用Think SFT学到的指令理解、知识调用和基础对话. 随后用短回复数据把输出风格拉回,Table29显示平均长度没有明显拖长. 热启动减少从Base学习聊天协议的成本,也可能携带隐藏的长推理倾向;内部试用对长度档的选择补充了自动评测.

function calling数据包含真实MCP轨迹与SimFC模拟多轮交互. 训练目标不仅是输出函数名与参数,还包括工具结果返回后继续对话. BFCL分数低于Qwen同档,说明加入工具数据不等于工具调用达到最强;格式、工具覆盖和多轮状态都可能成为瓶颈.

DPO限制chosen/rejected长度差不超过100 token,切断「更长通常被裁判偏好」的捷径. 这个过滤也会删除确实需要更长解释才能更好的样本,降低偏好覆盖. 它是对已知裁判偏差的保守处理,不是长度与质量无关的证明.

### 13.3. RL-Zero为何必须从Base出发

SFT和DPO已经注入大量外部教师行为,从这些checkpoint做RL很难判断能力来自底座数据还是后训练蒸馏. RL-Zero直接从Base出发,使用可验证奖励,让「底座支持集—探索—奖励」关系更清楚. 简化prompt、去掉`<think>`与`\boxed{}`格式,避免先花RL步骤学习Base从未见过的协议.

数学池从多个来源语义聚类每簇取一题,再去掉底座8次采样全对题,留下13.3K. 去全对题避免把rollout浪费在已掌握样本;没有同样去掉全错题的完全理由,极难题可能始终零优势. active sampling会进一步降低这些题进入梯度的概率.

评测时32K、训练时16K意味着模型可以在评测用更多预算. 如果训练中正确轨迹常超过16K被截断,策略学不到它们;若多数在16K内,评测上限只是防止少数长题截断. 报告应结合长度分布解读pass@k,不能把32K上限当平均推理长度.

### 13.4. 分支之间不能只按最终平均分排序

Think面向数学、代码和长推理,延迟高;Instruct面向短回答、工具与日常交互;RL-Zero面向研究,缺少完整聊天后训练. 三者的prompt模板、回复上限、数据与奖励不同. 将Think的AIME与Instruct的BFCL拼成一个平均值会把使用目标混在一起.

同一分支内部还要区分3.0与3.1. 3.1 Think提高AIME、OMEGA、IFEval和IFBench,PopQA与AlpacaEval下降;它是更偏可验证推理与格式服从的点. 对开放聊天应用,3.0或DPO checkpoint可能更合适. model flow公开中间节点,允许用户在Pareto前沿上选,而不只接受最新叶子.

## 14. 训练成本的复算与边界

### 14.1. 56天包含什么

初始预训练前9.5天用512张H100,后35天用1024张,粗略GPU小时为

$$
9.5\times24\times512+35\times24\times1024
=976{,}896\text{ GPU-hours}. \tag{38}
$$

按$2/GPU-hour约$1.95M. midtraining、长扩展、SFT、DPO、RL与评测把总数推到报告估算约$2.75M. 这个估算包含崩溃恢复和部分低利用时段,不是按理论FLOPs换算的最低成本.

3.1续训21天、224卡另约

$$
21\times24\times224=112{,}896\text{ GPU-hours}, \tag{39}
$$

按同单价约$226K,不在56天内. 只引用首发成本却引用3.1分数,会把额外续训漏掉.

配方开发成本同样未计入56天. 数据mix代理、microanneal、五轮integration、长上下文消融、SFT/DPO学习率扫描、RL候选都消耗算力. 报告说明主要在7B或更小尺度开发,这降低成本,没有给一个可加总总额. 「复现最终run」与「从零发现配方」是两种预算.

### 14.2. token吞吐复算

若32B预训练5.5T token,有效吞吐每卡约2.0K token/s、先512卡9.5天再1024卡35天,简单总处理能力为

$$
2000\times(512\times9.5\times86400+1024\times35\times86400)
\approx6.70\times10^{12}\text{ token}. \tag{40}
$$

高于5.5T,差额可以来自吞吐取代表值、停机、恢复重算、早期阶段硬件变化和有效训练时间少于墙钟. 这个对照说明不能把峰值token/s乘全墙钟当精确训练量;权威token计数来自数据/优化器步记录.

长上下文32B每卡1.3K、256卡时,100B token理论纯训练时间约

$$
\frac{10^{11}}{1300\times256}\approx300{,}481\text{s}\approx3.48\text{天}. \tag{41}
$$

而成本段写长扩展连同合并评测约1天,说明Table34的卡数、并行组、吞吐或该段具体运行配置需要按原表完整口径读取,不能截取三个数字强行相乘. 这里出现的矛盾应促使回查表头,不应选一个顺眼答案. 当前分析保留报告原述,不把手算当事实替换.

### 14.3. 环境成本没有给出

美元与GPU小时不能直接推出能耗. 需要硬件实际平均功率、PUE、地域电力结构和冷却用水. H100标称功耗乘GPU小时只给上界式估算,集群空闲、CPU、网络与存储又在GPU之外. OLMo 3报告没有像OLMo 2那样给能耗、碳和水表,因此不能补一个精确环境数字.

开放项目仍可由后续复现者记录功率遥测,按阶段报告kWh/token与kgCO2e. RL rollout的GPU利用形状与预训练不同,用统一标称功率会误差很大;连续batch与inflight updates不仅省钱,也可能显著降低每条有效轨迹能耗.

## 15. 最终读法

从底座看,OLMo 3没有用新奇层堆出能力:主体仍是dense Transformer,QK-Norm、输出RMSNorm和z-loss沿用OLMo 2,SWA是主要结构变化. 真正重排发生在训练路径:预训练mix提高代码与科学文本权重,midtraining提前放入推理轨迹,短扩展把上下文拉到65K,后训练再分Think、Instruct与RL-Zero.

从因果证据看,最扎实的是阶段内配对消融:质量上采样对平坦过滤、含推理数据对不含、oracle边界式的开发套件并不在本篇;长短mix、YaRN作用层、packing/mask、SFT—DPO—RL逐节点比较. 跨代OLMo2到3或跨模型Qwen的差距包含太多同时变化因素,适合描述最终位置,不适合给单项技术记功.

从开放性看,数据池、mix、检查点、训练代码、后训练数据和评测工具组成了一条可追溯链. 研究者可以从Base替换RL算法、从midtraining替换数据、从长扩展替换位置方法,而不必猜最终模型之前发生了什么. 这也是RL-Zero比又一个数学分数更重要的原因:它把底座数据与强化学习行为放到同一套可查证实验里.

## 16. 两个容易被总分遮住的数据机制

### 16.1. meta-reasoning数据在教什么

meta-reasoning覆盖自我评估、回溯、逆向推理等七类认知行为. 它与普通数学答案数据的区别在监督位置:普通数据主要在最后答案给出正确性信号,thinking trace把「发现前路不通」「回到假设」「换一种表示」写成可预测token. 自回归目标因此能直接提高这些行为在相似上下文中的概率.

用一个简化轨迹表示:

$$
y=(s_1,s_2,\ldots,s_j,\text{检查失败},s'_j,\ldots,a). \tag{42}
$$

训练不仅最大化答案$a$,还最大化失败检测与分支$s'_j$. RL若后来奖励$a$是否正确,就有机会从已经存在的多个分支中重分配概率. 若midtraining只含答案、不含分支,策略采样到回溯的概率可能极低.

microanneal里这类数据让Minerva Math约涨14分、HumanEval14分、MBPP20分,同时部分GenQA下降. 原因可能包括数据主题偏数学代码、输出变长或知识文本被挤出. 100B最终mix必须把它与网页、科学文本和问答混合,单源增益不能按比例外推到完整训练.

生成教师GPT-4.1和o4-mini也给数据带来风格. 模型可能学到特定短语和步骤模板,后训练再强化这些格式. 开放合成数据允许检查重复模板与真实解题贡献;只知道「加入推理数据」无法区分二者.

### 16.2. 长文合成任务为何只覆盖部分能力

CWE从长PDF分段中选高tf-idf名词短语,要求精确计数. 若目标短语在第$r$段出现$c_r$次,答案为

$$
C=\sum_{r=1}^{R}c_r. \tag{43}
$$

模型必须在多段检索并聚合,比needle-in-a-haystack多一步求和. 但tf-idf选择的词通常表面形式明确,不要求解决指代、同义改写或跨段因果. 它测的是分布式精确检索与算术聚合的一部分.

REX把与短语相关的内容改写成摘要、对话、抽认卡、辩论等12种场景,提供跨段收集后生成的训练信号. 生成任务由OLMo 2 Instruct 32B创建,教师本身最长上下文能力有限,管线先用统计量定位片段,再让教师只处理8个片段,绕过一次读完整65K. 学生得到的目标与原长文对齐,教师没有真正做端到端全文推理.

这个自举方法能造出可训练样本,也会把任务限制在「可由局部片段拼起来」的范围. 需要理解全文论证结构、发现远距离矛盾或追踪人物状态的任务未被同等覆盖. RULER短端强、65K下降,与监督覆盖有限相容.

## 17. 去污染的数学口径

### 17.1. 8-gram重叠会出现哪些误报

把评测样本规范化后得到8-gram集合$G_e$,训练文档得到$G_d$. 一种重叠率可写为

$$
R(e,d)=\frac{|G_e\cap G_d|}{|G_e|}. \tag{44}
$$

阈值0.5意味着评测样本至少一半8-gram在文档中出现. 长样本的$|G_e|$大,要跨过阈值需大段重合;很短样本只有少量8-gram,一句常见模板就可能触发. 启发式用于排除许可证、题目格式、固定指令等误报.

若使用Jaccard $|G_e\cap G_d|/|G_e\cup G_d|$,长训练文档的并集巨大,完整包含短评测题也可能分数很低. 因此实际实现选哪种分母会改变召回率. 复现必须读去污染代码与归一化规则,不能只记「8-gram、0.5」.

规范化同样重要. 大小写、空白、LaTeX、Unicode和选项顺序变化都可能让字面8-gram不同. 过强规范化提高语义近似召回,也会误删通用句;过弱则漏掉轻微改写. OLMo 3公开数据与实现,后续可用embedding或模型判别补查.

### 17.2. 去掉所有split的代价

许多基准train split本来就是公开监督数据,合法用于训练通用模型. 为了让validation/test评测更独立,报告连train split也从midtraining移除. 这会减少DROP、SQuAD、Minerva等领域的直接任务监督,分数下降不一定表示清洗破坏通用能力,也可能只是取消了合法迁移.

严格去污染服务于研究解释:当某种mix提升评测时,更有把握来自泛化. 产品训练未必采用同样选择,可能主动使用公开训练集. 两种口径比较时应标出是否排除train split.

随机奖励检查也依赖Base能否通过采样表达记忆. 如果模型背过答案但prompt格式差异大,正确答案概率仍很低,短RL未必激活. 反过来,随机奖励造成下降说明训练确实扰动策略,不能证明每条数据都无重合. 它是对n-gram清洗的功能性补充.

## 18. 多领域RL的梯度冲突

设领域$d$的期望梯度为$g_d$,混合更新为$g=\sum_dw_dg_d$. 两个领域若

$$
g_i^\top g_j<0, \tag{45}
$$

局部上存在冲突:沿一个领域下降会抬高另一个损失. Figure20中只训IFEval时AlpacaEval下降,说明至少在部分轨迹附近两种奖励方向冲突;加入LM裁判聊天奖励后,混合梯度提供反向约束.

混合训练每个领域奖励低于单领域,不一定全是减少reward hacking. 固定总step与batch时,每个领域获得的样本数下降;梯度冲突也会减慢单项优化. 下游不差说明正则化收益或跨域迁移抵消了训练奖励差,需要对照同领域样本量才能拆开原因.

等量混合按样本数等权,长回复token数不同会让token级目标的实际权重变化. 数学轨迹平均10K、指令轨迹2K时,同样prompt数下数学贡献更多token. 验证器成本、通过率和active sampling接受率也会改变每领域有效batch. 「大致等量」不等于梯度等量.

可以监控领域梯度余弦、每域token数、非零优势率和截断比例,再决定动态权重. OLMo 3采用精心过滤后的近等量mix并取得强终点,没有系统比较GradNorm、PCGrad或在线权重控制. 多目标RL仍是RL-Zero最适合继续实验的方向之一.

## 19. checkpoint选择本身也是实验

Instruct在DPO后选两个起点做RL:一个自动平均分最高,另一个试用体验更好. 最终再结合分数、长度与人工试用挑终点. 这说明模型选择目标包含未完全形式化的人类偏好,最终checkpoint不是单一benchmark的argmax.

若对多个候选都跑评测并挑最高,会产生winner's curse. 假设候选真实能力相同、评测噪声标准差$\sigma$,候选越多,最高观测值越可能高于真实均值. 保留独立终测或多seed复评可以减轻. 报告给方差桶与未见套件,但不是每个后训练候选都做多seed.

3.1由最优RL继续21天得到,属于在同一轨迹上延长训练. 它与重新从DPO起点换数据或换seed的对照不同. 指令遵循持续上升说明该目标未饱和,聊天下降说明早停点按综合目标可能早于21天. 发布多个节点让用户能自行选择早停.

对复现实验,最小记录应包含父checkpoint哈希、训练数据manifest、优化器step、累计token、随机seed、评测prompt版本和候选选择规则. 文件名写「final」不足以重建model flow;同一个权重若父节点不明,任务算术和阶段归因都失去坐标.

## 20. Prompt格式也是训练分布

Base、Think、Instruct与RL-Zero对同一道题可能使用不同模板. Base没有系统学过`<think>`、`<|im_start|>`或`\boxed{}`协议,强行加入这些标记会把概率质量浪费在陌生embedding和格式恢复上. RL-Zero改用简单自然语言prompt后,奖励更接近解题能力本身.

设题目内容为$x$,模板变换为$T(x)$. 评测测到的是

$$
E_{x\sim D}[R(\pi_\theta(\cdot\mid T(x)))], \tag{46}
$$

模板变化会同时改变模型条件分布与解析器是否识别答案. 若模型算对但没有`\boxed{}`,严格提取器可能给0;若训练专门奖励格式,分数提升又可能主要来自解析成功率. 报告在RL-Zero去掉格式要求,Think线则显式训练推理与答案格式,两条分数需要配套prompt解读.

function calling更依赖协议. 工具schema、函数名、参数JSON和工具结果包裹符号只要有一处不同,模型可能语义上知道要调用什么,仍因格式不合法失败. BFCL、MCP轨迹与SimFC各自的模板属于模型接口的一部分,发布权重时必须连同chat template提供.

模板污染也会进入midtraining. 特殊token实验中GSM8K跌到0,说明模型学会在不合适位置吐协议符号,输出分布与评测解析发生严重错位. 最终把特殊token推迟到SFT,让底座先学普通文本中的推理结构,再在后训练建立协议边界.

同一个checkpoint比较新算法时应固定$T$与解析器. 否则一次prompt修正的收益可能被记到RL目标、数据mix或模型架构上. OLMo 3公开评测配置的意义也在这里:分数不只依附权重,还依附输入变换与判分程序.

对外报告结果时, 模板、采样参数、最大回复长度和解析规则应与模型版本一起给出, 才能让同名基准真正落到同一实验条件上.
