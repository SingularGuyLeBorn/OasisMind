# OLMo: 全栈公开的 7B Dense 起点

来源: [OLMo: Accelerating the Science of Language Models](https://arxiv.org/abs/2402.00838) (arXiv:2402.00838v4, 2024-06-07), 21 页. 数字以同目录 `olmo-1.md` 的表图为准, 对照译稿见 `olmo-1-bi.md`. 后续几代的解析: [OLMo 2](../olmo-2/olmo-2-analysis.md), [Olmo 3](../olmo-3/olmo-3-analysis.md), [Olmo Hybrid](../olmo-hybrid/olmo-hybrid-analysis.md).

一句话身份: OLMo 是 Allen AI 在 1B 与 7B 两档 Dense decoder-only 上做的第一次 「全栈公开」, 7B 主 checkpoint 训到 2.46T token, 预训练语料是同队的 **Dolma**, 对齐借 **TÜLU 2** 的 **SFT → DPO** 配方. 它在能力上瞄准 Llama 2 7B, 在开放度上瞄准 Pythia 与 BLOOM, 两头都要. Table 3 八项均值 69.3, 离 Llama 2 7B 的 70.5 差 1.2 分; 公开清单则从权重一直列到数据顺序与评测代码.

模型是数据, 架构, 优化器, 硬件, 评测和对齐一起做出来的, OLMo 的每个选择都在几条线之间互相牵制. 比如 Dolma 里网页占比高, 就直接写进了 Paloma 各域的 bits per byte; 学习率收尾的方式, 又写进了八项下游曲线的最后一格. 机制背景可对照: [RoPE 本体](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.4-位置编码/01-RoPE本体-旋转位置编码/01-RoPE本体-旋转位置编码.md), [GLU 到 SwiGLU](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.1-激活函数/02-GLU家族-从GLU到SwiGLU/02-GLU家族-从GLU到SwiGLU.md), [归一化层](../../../llm-guide/2-核心原理与架构/2.1-深度学习基础组件/2.1.2-归一化层/2.1.2-归一化层.md), [分词器](../../../llm-guide/3-预训练/3.2-分词器与Tokenizer/3.2-分词器与Tokenizer.md), [BF16 混合精度](../../../llm-guide/6-训练与推理优化/6.1-训练基础设施/6.1.2-混合精度训练/01-浮点数基础与BF16混合精度训练/01-浮点数基础与BF16混合精度训练.md), [AdamW](../../../llm-guide/6-训练与推理优化/6.5-优化器/6.5.1-优化器综述-从SGD到AdamW/6.5.1-优化器综述-从SGD到AdamW.md), [困惑度](../../../llm-guide/3-预训练/3.6-预训练评估/3.6.1-困惑度-PPL/3.6.1-困惑度-PPL.md), [Scaling Law](../../../llm-guide/3-预训练/3.3-模型配置与Scaling-Laws/3.3.2-Scaling-Laws/3.3.2-Scaling-Laws.md), [SFT](../../../llm-guide/4-后训练/4.2-SFT/4.2-SFT.md), [DPO](../../../llm-guide/4-后训练/4.6-偏好优化/4.6.1-离线偏好优化/01-DPO/01-DPO.md).

## 1. 定位与架构

### 1.1. 谱系坐标: 开放度排成一条线, OLMo 站在最右端

Introduction 把 2023 年前后的发布按开放程度排了一遍: Mixtral 8x7B 给权重加一份短报告, LLaMA 给了详细的适配说明, Mosaic 的 MPT 公开了数据分布但没放数据本身, Falcon 放了部分预训练数据, Pythia 与 BLOOM 最开放, 训练代码, checkpoint 和数据都给. OLMo 把自己放在这条线的最右端, 并点名 LLM360 目标相近. 它的增量有两处: 一是把 「完全开放」 这一侧的能力往 Llama 2 推, Table 3 里 OLMo-7B 均值 69.3, 同为全开放的 Pythia 6.9B 是 63.0, RPJ-INCITE-7B 是 66.6; 二是评测本身也进了公开范围, **Catwalk**, **Paloma** 与 **TÜLU** 评测套件都放出来, 别人拿到的是整条流水线.

Section 5 的发布清单可以按 「能回答什么问题」 来读. 权重侧有 7B, 7B-twin-2T, 1B 终局权重, 每个都附 500+ 个按 1000 step 间隔保存的中间 checkpoint; 数据侧有完整 Dolma, 生成它的代码, **WIMBD** 数据分析工具, 以及能重建 「第 k 步 batch 里有哪些文档」 的工具; 评测侧有 Catwalk 与 Paloma; 适配侧有 Open Instruct 与 OLMo+SFT, OLMo+SFT+DPO 两个模型. 许可是 Apache 2.0. 研究数据与能力因果的人, 第一需要的是中间 checkpoint 和数据顺序; 只想部署聊天的人, 第一需要的是 Table 4 的适配结果. 两类用途依赖同一份发布清单中的不同材料.

7B 档不止一个模型, 这一点常被略过. Introduction 写 7B 放了四个变体, 分别对应不同的架构, 优化器和训练硬件, 全部至少训到 2T token; Section 5 里点名的 7B-twin-2T 就是其中之一. 对只看排行榜的人, 多出的变体只是噪声; 对做训练研究的人, 这是一组现成的对照组, 同一套数据顺序下换硬件或换设定, 终点差多少可以直接比. 报告正文没有逐个展开这几个变体的消融结论, 只在 §3.4 用 LUMI 与 MosaicML 两条曲线在 2T 处几乎重合, 说明硬件这一维的差别可以忽略.

这种定位也决定了报告的写法. 它几乎不推新的 Scaling 公式, Figure 2 里的 Scaling 只是经验对照: 同量级模型随训练 token 增加, bits per byte 大体同向下降. 真正的交付是可复现材料的厚度. 社区当时对 OLMo 的常见概括是 「权重, 代码, 数据, 评测, 指令微调五样都开」, 这个概括和 Section 5 的四栏清单能一一对上, 没有夸大.

### 1.2. 吞吐, 稳定与 「最安全」: 一组互相牵制的默认值

Section 2.1 开头写了选超参的原则: 在自己的硬件上优化吞吐, 同时压低 loss spike 与慢发散的风险, 用训练环内评测做消融. 这条原则同时约束了架构, 优化器和硬件, 所以五项架构改动要和它一起读. **去掉全部 bias** 与 **non-parametric layer norm** (LayerNorm 里不带可学的 gain 与 bias) 被归到稳定性一侧, 作者说无参 LN 是比带参 LN 和 **RMSNorm** 都 「更安全也更快」 的选项; **SwiGLU** 隐宽取约 $(8/3)d$ 再上取到 128 的倍数 (7B 为 11008, 门控使输入维实为 2 × 11008 = 22016), 词表 50280 补到 50304 行 embedding, 这两处都是为吞吐凑整数. **RoPE** 替换绝对位置编码, 和 LLaMA, PaLM 一致.

把这五项放到 Table 5 的同尺度对照里, 分叉点就清楚了. **SwiGLU**, **RoPE**, 无 bias 与 LLaMA2 一致, sequential block 也与 LLaMA2 相同 (Falcon 与 PaLM 用 parallel block). 真正分开的是两处: LLaMA2 用 **RMSNorm** 与 **GQA**, OLMo-7B 用无参 LN 与 full attention; 学习率日程上 LLaMA2 用 cosine, OLMo 用 linear; 序列长 LLaMA2 为 4096, OLMo 为 2048. 所以 OLMo-7B 不是 LLaMA 的复刻, 是在同一代 Dense 7B 配方里挑了更保守的归一化, 注意力留在最朴素的形态, 上下文也更短. 这些选择都不是稀疏路线, 报告里没有 MoE, 也没有 **GQA** 之类的 KV 压缩.

Table 5 另外三列把同代的设计空间摊得更开. OpenLM-7B 与 OLMo 最接近, 同为 full attention, sequential block, SwiGLU, 区别在于用带参 LN 且只在 LN 里保留 bias, 日程用 cosine. Falcon-7B 走得最远: 隐维 4544, 71 个头, MQA, parallel block, GeLU, MLP 倍率 4, 峰值 LR 6.0E-04, β 取 (0.99, 0.999), 梯度 all-reduce 用 BF16. PaLM-8B 同样用 MQA 与 parallel block, 并共享输入输出 embedding, 全局 batch 只有约 1M token. 在 「吞吐与稳定性」 能互换的每一处, 例如注意力是否共享 KV, 梯度规约用什么精度, OLMo 都选了偏稳的一侧, 这与 §2.1 的选参原则一致.

三种归一化差在哪, 写成式子最清楚. 设子层输入为 $\boldsymbol{x}\in\mathbb{R}^d$, 各维均值 $\mu$, 方差 $\sigma^2$: 带参 LN 是 $\boldsymbol{\gamma}\odot\frac{\boldsymbol{x}-\mu}{\sqrt{\sigma^2+\epsilon}}+\boldsymbol{\beta}$; OLMo 用的无参 LN 去掉 $\boldsymbol{\gamma}$ 与 $\boldsymbol{\beta}$, 只剩 $\frac{\boldsymbol{x}-\mu}{\sqrt{\sigma^2+\epsilon}}$; RMSNorm 不减均值, 写作 $\boldsymbol{g}\odot\boldsymbol{x}/\sqrt{\frac1d\sum_i x_i^2+\epsilon}$. 无参 LN 于是没有一个可学参数, 每次归一化后的输出都被固定在零均值, 单位方差上, 各维该放大还是缩小, 只能交给紧接着的线性层去学; RMSNorm 则每维保留一个增益 $\boldsymbol{g}$. 这也和 「去掉全部 bias」 是一路做法: 两者都在减少不参与矩阵乘的零散参数.

关于无参 LN, 后一代给了一个事后注脚. OLMo 2 报告 §3.3.2 写, 早期用无参 LN 一半是为了性能, 一半是为了绕开当时所用库的 bug; 到 OLMo 2 时 bug 已不存在, 硬件也更快, 消融显示两者没有差别, 于是换回 RMSNorm. 这说明 OLMo 1 的 「最安全」 带着当时工具链的约束, 不是一个被证明更优的归一化方案. 读 OLMo 1 的架构节, 最好把 「为能力服务的归纳偏置」 (RoPE, SwiGLU, 无 bias) 和 「为吞吐与工具链服务的约束」 (128 对齐, 无参 LN) 分开.

优化器与架构共用同一条稳定性原则. Table 1 两档都用 **AdamW**, β=(0.9, 0.95), ε=1.0E-5; warmup 后按全局 ℓ2 范数把梯度裁到 1.0; Table 5 里梯度 all-reduce 与优化器状态都是 FP32, weight decay 0.1. ε 这个数在下一代也被改掉: OLMo 2 Figure 9 显示把 ε 降到 1e-8 后早期梯度范数更低更稳. 回看 OLMo 1, 1.0E-5 是当时 LLaMA 系沿用的数, 报告没有对 ε 做消融.

序列长 2048 也是几条线的交点. 它比同期 LLaMA2 的 4096 短一半, full attention 的二次成本和激活显存因此更低; §3.1 写 7B 上每 GPU micro-batch 为 4096 token, 心算即每卡一次只放 2 条 2048 长的样本. 在 MI250X 每个逻辑设备 64GB, A100 只有 40GB 的条件下, 这个长度让两套集群都能用同一份配置跑. 代价落在能力侧: RoPE 只在 2048 以内训练过, 报告没有做任何更长上下文的评测, 下一代 OLMo-0424 才把长度提到 4096.

两档配置之间还有分档差异. **weight tying** 在 1B 为 yes, 7B 为 no; 1B 为 L=16, D=2048, H=16, 峰值 LR 4.0E-4; 7B 为 L=32, H=32, 峰值 LR 3.0E-4. 隐维在 Table 1 写 D=4086, 附录 Table 5 写 4096, 两处分属主文与附录, 引用时带表号即可. warmup 也有类似情况: Table 1 里 1B 写 2000 steps, §3.2 正文写 「所有尺寸都 warmup 5000 steps (约 21B token)」, 源文两处并存.

## 2. 数据与评测

### 2.1. 从 Dolma 到一个 batch: 2.46T token 怎样流进优化器

Dolma 的构建顺序是: 语言过滤, 质量过滤, 内容过滤, 去重, 多源混合, 分词, 各源在策展与发布时都分开保存. Table 2 给出六源: Common Crawl 2180B token (9812 GB, 3734M 文档), GitHub 342B, Reddit 80B, Semantic Scholar 57B, Project Gutenberg 5.2B, Wikipedia 3.7B, 合计 2668B token, 11519 GB, 4367M 文档, token 数按 GPT-NeoX 分词器计. 分词器本身也和数据管道咬合: 它是在 GPT-NeoX-20B BPE 上加了 PII 掩码 token 的改版, Dolma 里被遮蔽的个人信息, 在词表里有对应的占位 token.

进入优化器的并不是全库. §3.3 写训练集是从 Dolma 抽出的 2T token 样本, **每篇文档末尾加 EOS 后首尾拼接**, 再切成 2048 token 的训练实例, **每个 run 的打乱顺序完全一致**, 所以 batch 组成可以从发布物重建. 全部放出的模型至少训完 2T (单 epoch), 部分进入第二 epoch 并换打乱顺序, 作者引用 Muennighoff et al. (2023) 认为少量重复的影响可以忽略. 拼接时是否做文档内注意力掩码, 这份报告没有写; 到 Olmo 3 的长上下文阶段, 文档内掩码才作为配方的一项被单独消融.

CC 占比有两个口径. 用 Table 2 心算, 2180 / 2668 ≈ 81.7%, 这是 Dolma 全库的组成; §4.2 与 Figure 2 题注写的 88.8% 是训练实际用到的混合. 两者差约 7 个百分点, 说明训练样本比全库更偏网页. 报告只给了结果比例, 没有给各源的采样权重, 所以只能说 「训练混合比全库更偏 CC」, 不能反推每个源被上采样或下采样了多少.

Table 2 的文档数与字节数还能算出各源的形状, 它们和 2048 的切块方式直接相关. 平均每篇文档的 token 数: Common Crawl 约 584, Reddit 约 212, Semantic Scholar 约 1470, Wikipedia 约 600, Project Gutenberg 约 9.3 万 (心算, 按 token / 文档数). 于是一条 2048 长的训练样本里, 通常拼着三四篇网页或近十条 Reddit 帖子, 而一本书会被切成约 45 条样本. 每 token 对应的字节数也不同: 代码约 3.0, 网页约 4.5, 论文约 4.7 (心算, 按字节数 / token 数), 代码更碎, 同样字节要花更多 token. 这些形状差异既影响模型在一条样本里能看到多长的连贯上下文, 也解释了第 2.2 节里短文档源 bits per byte 偏高的现象.

「各源分开保存」 这条规矩看上去只是整理习惯, 其实是给后续研究留的接口. Dolma 的六个源在策展和发布时都不合并, 数据配方研究就可以按源增删, 再用环内评测看信号; Dolma 自己的报告正是用中间状态的语料训小模型, 讨论内容过滤, 质量过滤, 去重与多源混合各自的作用. OLMo 这份报告把这些实验结论交给 Dolma 报告, 自己只交代最终配方, 因此去重前后的量化差异需要结合 Dolma 报告与 WIMBD 的语料检查结果判断.

数据怎样流过硬件, 由 §3.1 与 §3.4 决定. 并行用 **ZeRO** 策略, 经 PyTorch **FSDP** 切分权重与优化器状态, 7B 上每 GPU micro-batch 4096 token; 全局 batch 恒约 4M token (2048 条 × 2048). 混合精度走 PyTorch amp: softmax 等算子保持全精度, 其余用 bfloat16; 各 GPU 本地的分片权重与优化器状态为全精度, 前反向物化整块参数时才转 bf16, 梯度以全精度规约. 硬件有两套: LUMI 最多 256 节点, 每节点 4 张 MI250X (双芯模块, 逻辑上 8 个设备); MosaicML 27 节点, 每节点 8 张 A100-40GB. 两边训到 2T 时评测几乎重合, 作者用它证明代码在 AMD 与 NVIDIA 上都能跑. 数据顺序固定, 加上双集群互证, 共同撑起了 「可复现」 这个说法.

batch 的数字在源文里有两处. §3.1 写全局 batch 约 4M token, 即 2048 条 × 2048; 附录 Table 5 的 OLMo-7B 一列写 2160 条, 心算约 4.42M token. §3.4 又说两套集群 「为优化吞吐, batch 略有不同」, 两处数字很可能分别对应两次运行, 报告没有明说哪个数属于哪个集群. 这会影响 「按步号重建 batch」 的用法: batch 大小不同, 同一步号对应的累计 token 数也不同, 要重建第 k 步看到的文档, 先得确认是哪一次运行的 checkpoint (由两处数字推出).

### 2.2. 88.8% 网页比例在困惑度曲线上的回声

内禀评测用 **Paloma** 的 11 个源, 去掉了不可公开, 含边缘或有毒文本, 以及代码且无法按 Paloma 方法去污染的源; 指标是 **bits per byte**, 让不同词表的模型可比. OLMo-7B 被报告称为 「对困惑度评测做了显式去污染的最大模型」: 预训练文档中若有段落泄漏自 Paloma 评测集, 整篇剔除. 没做去污染的模型, 困惑度可能被低估, 也就是样本外拟合被高估. **这是数据管道与评测设计之间的直接接口**, 数据侧多做一步, 评测侧的数才站得住.

为什么用 bits per byte 而不是每 token 困惑度, 也和分词器有关. OLMo 的词表是 50280, Llama 2 是另一套 BPE, 同一段文本切出的 token 数不同, 每 token 的 loss 不能直接比; 把总 loss 折算到原始字节上, 词表差异就被消掉了. 按通常的定义写作 $\mathrm{BPB}=\frac{1}{N_{\text{bytes}}\ln 2}\sum_{t=1}^{N_{\text{tokens}}}-\ln p(x_t\mid x_{<t})$: 分子是整段文本按 token 累加的负对数似然, 除以 $\ln 2$ 换成比特, 再除以原文的字节数. 同一段文本, 词表大的模型切出的 token 少, 每个 token 的 loss 高, 只有两者相乘的总量才对应整段文本; 按 token 平均会偏向切得碎的分词器, 按字节平均只看原文, 所以可以跨词表比. Paloma 本身覆盖 585 个文本域, 来自 18 个数据源, 按分层抽样让小域也有足够权重, 所以它能看出 「网页域强, 百科与论文域弱」 这种分布差异, 单一验证集做不到这一点.

Figure 2 的分源曲线把数据配方写得很清楚. OLMo 在 C4 这类 CC 主导的集合上更占便宜, 甚至超过全部对照; 在 WikiText-103, M2D2 S2ORC / Wikipedia, 以及 CC 占比低的 RedPajama 上样本效率偏弱. §4.2 把这归到非 CC 比例: MPT 27%, LLaMA 18%, RedPajama 12.2%, OLMo 11.2%, 非 CC 最少的 OLMo 在 C4 上最强. MPT-7B 在总图上最靠前, 作者猜测和它非 CC 比例更高, 以及 semantic deduplication 等预处理有关. 附录 Figure 3 里还有一个方向相反的同类现象: Pythia-6.9B 训练 token 比 OLMo 少近一个数量级, 却在 Pile 上最好, 因为它就是在 Pile 上训的.

代码域的读法需要多一层小心. Dolma 100 Programming Languages 上 OLMo 明显领先, 作者提醒可能低估了代码污染, 同时指出同样训过 GitHub 的 RPJ-INCITE 仍差一截, 说明 「同一套后处理产生的分布内效应」 也在起作用. GitHub 342B 在 Table 2 里是第二大源, 但离 CC 的 2180B 很远, 代码域的优势更可能来自后处理一致, 而不是代码 token 量大.

附录 C 还提醒, 其余 5 个面向特定社群的源要谨慎解读. Paloma 发现这些源上的困惑度常被文档平均长度这类表面特征主导, 而不反映模型对该社群语言的真实拟合: TwitterAAE 与 Gab 的文档在 Paloma 里最短, 所以 bits per byte 异常偏高; 除这两者外, ICE, Manosphere 与 4chan 上各模型沿数据 Scaling 趋势挤得很紧, 拉不开差距. 这说明 **bits per byte 虽然消掉了词表差异, 却消不掉文档长度的影响**, 短文档缺少上文, 每个字节都更难预测. 用 Paloma 比较模型时, 分源曲线比总平均更可靠, 短文档源又比长文档源更需要打折扣.

中间 checkpoint 让这张图多了一个维度. Figure 2 里能画出中间虚线的只有 Pythia-6.9B, RPJ-INCITE-7B 与 OLMo-7B 三家, 其余模型只能以终点出现. 作者同时提醒, 曲线陡度受该点落在学习率日程何处影响, 训得更短的模型曲线往往更陡, 不等于固定训程下更省样本. 所以读这张 Scaling 图要拆成三件事: 数据配方是否匹配评测域, 学习率走到了哪一段, 评测集有没有被去污染. 三件事都依赖发布物, 这正是全栈公开在评测上的用处.

### 2.3. 学习率收尾与八项下游: 日程怎样写进评测曲线

主日程见 §3.2: warmup 后从峰值 linear 降到峰值的 1/10, Table 5 的 minimum LR 3.0E-05 对应这一终点, 是 3.0E-04 的十分之一, 不是 0. Section 4 开头又加了一段: 已训到 2.46T 的 checkpoint 在 Dolma 上再跑 1000 step, LR 从主日程终点线性收到 0, 作者称这同时改善了困惑度和下游任务. Figure 1 的八条曲线里, 末端相对倒数第二个点有明显跳升 (读图), 作者把它归于这最后 1000 step. 本文没有做 linear 与 cosine 的受控消融, **能确认的只是 「末段收到 0 有帮助」, 不能推出 linear 本身更好**.

这 1000 step 在家族谱系里有后续. OLMo 2 把 「学习率收到 0」 与 「换一批高质量数据」 合并成独立的 mid-training 阶段, 用 Dolmino 数据退火 50B 到 300B token, 再做权重平均; Olmo 3 又把这一段扩成 100B 的 Dolmino Mix, 并加上长上下文扩展. 在 OLMo 1 里, 收尾只换了学习率, 数据仍是同一个 Dolma, 这是后来退火阶段最早的形态.

下游八项的选择也和训练过程绑在一起. §2.4 写这些任务在开发初期就定下, 理由是都能写成文本补全打分, 且在整个训练过程中给出稳定信号; 训练环内每 1000 step (约 4B token) 评一次, 用来决定架构, 初始化, 优化器, 日程与数据混合. 打分方式是 rank classification: 每个候选答案 $c$ 接在题目 $x$ 后面算似然, 取得分最高的当预测. 得分有几种归一: 不归一就是 $\log P(c\mid x)$; per-token 是 $\frac{1}{|c|}\log P(c\mid x)$, $|c|$ 为候选的 token 数, 免得长选项因为连乘项多而吃亏; per-character 按字符数除; unconditional 减去候选在无信息前缀下的似然, 即 $\log P(c\mid x)-\log P(c\mid x_0)$, 扣掉 「这个答案本身就常见」 的先验, $x_0$ 用什么前缀报告没写. OLMo 按任务分开选: arc 与 openbookqa 用 unconditional, hellaswag / piqa / winogrande 用 per-token, boolq / sciq 不归一化, 因为它们被写成单 token 预测, 候选长度相同, 除不除都一样. 前两组的分法可以按题型理解, arc 与 openbookqa 的选项多是短实体或短语, 常见词天然似然高, 另三项的选项是长短不一的句子续写 (报告只写了分配). 附录另六项 (headqa_en 等) 在 Figure 4 上噪声很大, 有的接近随机基线, 作者明确说不要当主信号. **评测集是按 「训练中能不能给信号」 挑出来的**, 这是开发工具, 不只是排行榜.

附加六项的 Table 7 正好示范了信号差的任务会怎样误导. OLMo-7B 六项均值 47.5, 是七个模型里最高的, RPJ-INCITE-7B 47.3, LLaMA2-7B 46.5, Falcon-7B 最低为 45.4, 七家挤在 2.1 分以内. 细看单格, wic 上各家都在 48–55 之间, OLMo 为 50.2, 接近二分类的随机水平; mrpc 上模型容易总是预测同一个标签, 类别不平衡会把分数抬高或压低; wnli 上 OLMo 56.3, Pythia 只有 38.0, 波动远大于能力差. 作者明确提醒不要在训练过程中或模型之间过度依赖这些任务. 「OLMo 在附加任务上均值第一」 这句话在表里成立, 但几乎不携带信息.

环内评测和线性日程叠在一起, 读早期信号时要多想一步. 线性衰减意味着训练中段的学习率仍然偏高, 下游分数的抬升一部分来自学到新东西, 一部分会在学习率降下来以后才兑现; Figure 1 末段那一跳就是后者的例子. 因此用环内评测比较两个设定时, 只有在同一日程的同一位置上比才公平, 拿一个刚 warmup 完的 run 和一个快收尾的 run 比, 结论会偏. 报告把 「决定架构与数据混合」 的职能交给环内评测, 但没有公开这些中途决策各自依据的曲线, 这一面因此没有.

Table 3 的单格值得看细. OLMo-7B 八项为 48.5 / 65.4 / 73.4 / 76.4 / 50.4 / 78.4 / 93.8 / 67.9, 均值 69.3; Llama 2 7B 70.5, Falcon-7B 70.3, MPT-7B 69.8. arc_challenge 与 Llama 2 同为 48.5, arc_easy 65.4 却明显低于 Llama 2 的 69.5 与 Falcon 的 70.4; piqa 78.4 贴近 Falcon 的 78.5, 高于 Llama 2 的 76.7. 均值接近不代表每格同构. 1B 档均值 60.4, 高于 Pythia 1B 的 54.5 与 TinyLlama 1.1B 的 59.4, 低于 StableLM 1.6B 的 66.5; 作者注明后者参数更多且训练数据未知, 这一行只适合当参照上限.

1B 与 7B 的设定并不一致, 横着比两档时要先扣掉差别: 1B 训 2T token 并共享输入输出 embedding, 7B 训 2.46T 且不共享, 峰值学习率也不同. 所以 「从 1B 到 7B 均值涨了 8.9 分」 (心算 69.3 − 60.4) 混合了参数量, 训练量和 tying 三个因素, 不能读成单纯的参数 Scaling. 报告没有给同设定下的规模扫描, 这类曲线要到 OLMo 2 的 1B 附录与 Olmo Hybrid 的 60M 到 1B 受控实验里才有.

## 3. 对齐, 成本与后续

### 3.1. 借来的对齐配方: TÜLU 2 在非 Llama 底座上的得失

适配走 **TÜLU 2** 的两段式. 附录 D: **SFT** 学习率 2×10⁻⁶, 3 epoch, 前 3% warmup 后线性降到 0, weight decay 与梯度裁剪都是 0, 最长 2048, 数据是改过的 TÜLU V2 SFT mix, 长对话切成 2048 的段, 硬编码片段换成关于 OLMo 的说明. **DPO** 学习率 5×10⁻⁷, β=0.1, 3 epoch, warmup 10%, 数据是去掉 TruthfulQA 提示的 UltraFeedback 修正版. 最长序列与预训练上下文对齐在 2048, 这份配方里没有奖励模型, 也没有在线 RL.

数据上的几处小手术都在防评测串味. SFT 数据替换掉硬编码的身份片段, 避免模型自称别家模型; DPO 数据去掉 TruthfulQA 的提示, 因为 TruthfulQA 正是 Table 4 的评测之一. 这类处理说明作者把 「训练集和评测集是否重叠」 从预训练 (Paloma 去污染) 一直管到了适配阶段. 局限节同时承认, 适配数据大量蒸馏自其他模型, 希望以后减少这种依赖; OLMo 2 把偏好数据的生成池限定在许可允许的模型上, 就是沿这个方向往前走了一步.

Table 4 显示两段各管一摊. base 的 MMLU 0-shot 28.3, ToxiGen 毒性 81.4%, TruthfulQA 真实且有信息 31.6%; **SFT** 后变为 47.3 / 14.4 / 41.2, AlpacaEval 胜率 57.0; 再 **DPO** 后为 46.2 / 1.7 / 52.0, AlpacaEval 69.3. **毒性的大头在 SFT 阶段降下来**, DPO 把剩下的几乎压到零; 真实性与聊天胜率在 DPO 阶段涨得最多; MMLU 相对纯 SFT 回落 1.1 分. 附录 Table 8 把代价摊得更开: GSM8k 8-shot CoT 从 base 8.5 升到 SFT 的 15.5, DPO 后回落到 11.0; BBH 3-shot CoT 36.9 → 35.8; TydiQA 35.2 → 21.7. 同一步偏好对齐, 安全与聊天变好, 数学与多语问答回吐了一部分.

放到同表的官方对话模型里, OLMo+SFT+DPO 的位置更清楚. MPT Chat 为 MMLU 33.8, AlpacaEval 46.8, 毒性 0.1%, TruthfulQA 42.7; Falcon Instruct 为 25.2 / 14.0 / 70.7 / 27.2; RPJ-INCITE Chat 为 27.0 / 38.0 / 46.4 / 53.0. 在公开了预训练数据的这几家里, OLMo 的 MMLU 与聊天胜率最高, 毒性仅高于 MPT Chat. Llama-2-Chat 是另一种取舍: 毒性 0.0%, AlpacaEval 87.3, TruthfulQA 却只有 26.3, 远低于 OLMo 的 52.0. 对齐把哪一项压到极致, 往往就在另一项上付出代价, 单看一列会得出相反的结论. TÜLU 2 的 TruthfulQA 因测试集污染没有报告 (脚注 7), 这一列 OLMo 找不到同配方的对照.

和同表的 TÜLU 2+DPO (Llama 2 底座, MMLU 50.7, AlpacaEval 85.1) 比仍有缺口. 作者给了两个解释: Llama 2 可能有 MMLU 污染; TÜLU 配方原本为 Llama 族设计, 可能没对准 OLMo 自己的强弱项. 文中没有做换配方的对照实验, 这两个解释目前停在假设. 后一代的做法恰好回应了第二点: OLMo 2 沿用 Tulu 3 骨架, 但收紧许可, 重扫 SFT 与 DPO 超参, 再接可验证奖励的 RL, 等于承认 「直接搬 Llama 的配方」 不够.

评测协议决定了这些数能不能与外部横比. 附录 E: ToxiGen 只用原版仇恨提示, 每组 500 条, 由 toxigen RoBERTa 判毒; TruthfulQA 因 GPT-3 弃用, 改用两个基于 LLaMA 2 的判定器; AlpacaEval 是 GPT-4 判对 Davinci-003 的胜率. Table 4 与 Table 8 里 OLMo+SFT+DPO 的 MMLU 分别写 46.2 与 46.1, 两处分属正文和附录, 各带表号引用即可.

### 3.2. 成本, 局限与报告没有的东西

附录 B 的测量方法是: 单节点每 25ms 采一次功耗, 取全程均值乘以节点数, 再乘 PUE 1.1. Table 6 两行合计 135 + 104 = 239 MWh, 与正文 239 MWh 一致. A100-40GB 在澳大利亚训练, 碳强度取 0.610, 心算 104 × 1.1 × 0.610 ≈ 69.8, 对应表中 70 tCO₂eq 与正文 69.78; MI250X 在 LUMI, 按官方水电碳强度 0 记, 若按 0.024 计则为 3.54 tCO₂eq. 作者强调这是**运行期下界**, 制造, 调试, 调参, 宕机都没算进去. 同表 LLaMA-7B 14, LLaMA2-7B 31, 各自的功耗与碳强度假设不同, 不宜当精确排名.

239 MWh 这个总数还要拆开读. 附录 B 写的是 「预训练我们的 7B 模型们」 共耗 239 MWh, 两行分别对应 A100 上训练的模型与 MI250X 上训练的模型, 也就是两次 7B 运行的合计. 单次运行是 104 或 135 MWh, 与同表 LLaMA2-7B 的 74 MWh 同一量级 (后者训 2T token, 用 A100-80GB). 两套硬件跑同一配方, 能耗相差约 30% (心算 135 / 104), 报告没有拆出这部分差距来自芯片效率, 训练时长还是 batch 设置, 所以不能据此判断 MI250X 与 A100 谁更省电. 电网选址的影响则一目了然: 功耗更高的 LUMI 一行按官方口径排放为 0, 澳大利亚那一行贡献了全部 70 吨.

报告没有直接给训练 FLOPs. 按常用的 $C \approx 6ND$ 粗算, 取名义参数 7B 与 2.46T token, 约为 1.0×10²³ FLOPs (参数量取名义值, 没有扣掉 embedding). OLMo 2 报告 Table 6 用同一近似给 OLMo 7B 记的正是 1.0(×10²³), 同表 OLMo 2 7B 为 1.8. 能耗侧只有 7B 的数, 1B 的功耗与排放报告没有.

局限节写明: 预训练以英文为主; 数据仍可能残留有毒, 隐私, 版权内容; 适配主要照搬为 Llama 设计的 TÜLU; 自动评测噪声大, 也不等于真实聊天. Ethics 的立场是公开能减少重复预训练的环境成本, 并加速风险研究. 这些边界写清以后, 「Apache 2.0 全家桶」 才落到可追责的发布内容上.

还有几样东西这份报告里没有. 上下文只有 2048, 没有长上下文扩展, 也没有位置外推实验; 注意力是 full attention, 没有 KV 压缩; 没有多语或代码专项评测; 对齐只到 DPO, 没有奖励模型与 RL; 没有 linear 与 cosine, 无参 LN 与 RMSNorm 的消融结果. Conclusion 提到数据与训练更新后 MMLU 提升 24 分到 52%, 那是脚注里的后续博客, 不属于本文任何一张表.

### 3.3. 往后几代从这里改了什么

OLMo 2 报告 Table 1 把 OLMo 1 (0224), OLMo-0424 与 OLMo 2 并排, 正好可以当作这份报告的 「后来怎样」 来读. 保持不变的是无 bias, SwiGLU, decoder-only; 改掉的是 RoPE θ 从 1×10⁴ 到 5×10⁵, QKV 从不处理到 **QK-Norm**, LN 从无参到 **RMSNorm** 并挪到子层输出侧, z-loss 从 0 到 10⁻⁵, embedding 不再做 weight decay. 上下文则在 OLMo-0424 提到 4096. 这些改动几乎都指向训练稳定性, 说明 OLMo 1 在 7B 这一档上能训完, 但放大到 13B / 32B 时, 当初 「最安全」 的一组选择并不够用.

数据与后训练也沿着这份报告留下的接口往前走. 预训练数据从单一 Dolma 换成以 DCLM 为主的 OLMo 2 Mix, 再到 Olmo 3 的 9T 源池与约 6T 训练混合; 末段 1000 step 的学习率收尾, 长成了带专门数据的 mid-training; 对齐从 TÜLU 2 的 SFT → DPO, 长成 Tulu 3 式的 SFT → DPO → RLVR, 再到 Olmo 3 的 Think / Instruct / RL-Zero 分叉. 评测侧, Paloma 的去污染和 「训练中能给信号」 的选任务原则, 在 OLMES 与 OlmoBaseEval 里继续用.

「开放」 的含义也在变宽. OLMo 1 公开的是终局权重, 中间 checkpoint, 数据和代码; OLMo 2 加上了 mid-training 数据与后训练数据, 以及训练日志; Olmo 3 干脆把 「model flow」 当成交付物, 每个阶段的数据, checkpoint 与依赖都列出来, 并额外做了一条从 Base 直接做 RL 的 RL-Zero 线, 专门研究预训练数据怎样影响强化学习. 从这个方向回看, OLMo 1 的中间 checkpoint 与可重建的数据顺序, 是整个家族 「可干预」 路线的第一块基石.

同一把尺子下的差距, OLMo 2 报告 Table 6 已经量过一次. 在 OLMES 子集上, OLMo 7B 均值 38.3, MMLU 28.3, GSM8K 9.2; 同为约 1.0×10²³ FLOPs 的 OLMo 7B 0424 均值 50.7, MMLU 54.3; OLMo 2 7B 用 1.8×10²³ FLOPs 到 62.9, MMLU 63.7. 训练算力相同时 0424 已经多出 12.4 分, 说明**第一代之后的主要进步先来自数据与训练配方, 然后才是算力**.

所以这份报告在谱系里的角色是起点配置: Dense 7B, 序列 2048, full attention, 无参 LN, linear LR 加末段收 0, 高 CC 的 Dolma, TÜLU 2 的 SFT → DPO. 要比较家族内部的进步, 应该在同一套 Catwalk 八项, 同一套 Paloma 去污染口径下重跑, 而不是把不同评测设定的分数直接相减. 这份报告最耐用的部分, 是它让这种重跑成为可能.

## 4. 「全开放」首先解决实验可识别性

### 4.1. 只有终点权重时,许多因果问题无解

假设两个7B模型最终准确率相差3分. 差异可能来自数据、tokenizer、初始化、学习率、batch、训练长度、硬件数值、checkpoint选择或评测模板. 只有终点权重时,这些变量混在一起,无法从输出反推原因. OLMo发布训练数据、顺序、代码、日志和500多个中间checkpoint,让研究者可以固定其中大部分变量再改一个.

中间checkpoint把终点标量变成时间序列. 对任务$k$,可观察

$$
S_k(D_1),S_k(D_2),\ldots,S_k(D_m), \tag{1}
$$

其中$D_i$是累计token. 两个模型终点相同,学习曲线可能完全不同:一个早期领先后饱和,另一个晚期追上. 数据效率、涌现阈值、遗忘和学习率影响都需要时间维才能判断.

固定数据顺序进一步减少方差. 若架构A与B在第$t$步看到同一batch,loss差更接近模型差;若各自shuffle,某次异常batch或领域簇会把曲线局部推开. 固定顺序也允许把尖峰映射回文档. 代价是对这个顺序过拟合实验结论,换随机种子后仍需复验.

### 4.2. 可重放不等于逐位确定

跨MI250X与A100运行时,矩阵核、规约顺序和编译路径不同. 浮点加法不满足结合律:

$$
(a+b)+c\ne a+(b+c). \tag{2}
$$

数十万步后,微小舍入会让参数逐渐分叉. 报告在2T token处看到两套硬件评测几乎重合,证明统计结果可复现,没有声称参数bitwise相同.

真正的复现目标应分三级:代码能运行;loss与评测曲线落在相近区间;权重逐位一致. OLMo主要交付前两级. 第三级还要求驱动、内核、设备拓扑、随机数与并行规约完全锁定,科学结论通常不需要如此苛刻.

batch数字2048与2160的差异也说明重放要指定run. 同样step编号在两个run中累计token不同,对应数据边界也不同. checkpoint名称、硬件分支、全局batch与数据游标必须一起保存.

## 5. 架构选择的原理与代价

### 5.1. Sequential block 的信息路径

OLMo采用Pre-Norm式顺序block,可概括为

$$
h_l=x_l+\operatorname{Attn}(\operatorname{LN}(x_l)),\qquad
x_{l+1}=h_l+\operatorname{MLP}(\operatorname{LN}(h_l)). \tag{3}
$$

Attention先更新表示,MLP读取更新后的$h_l$. Parallel block则让Attention与MLP都读同一个归一化输入再相加,关键路径更短、并行度更高,两分支无法在同层串联. OLMo选择sequential,与Llama 2一致,保持保守能力路径.

残差恒等项让梯度有直接通道. 无参LayerNorm把输入固定为零均值单位方差,分支线性层接收稳定尺度;它没有可学习gain/bias,减少了每层尺度漂移自由度. 代价是通道重标定必须由后续矩阵完成.

### 5.2. SwiGLU 的参数配平

SwiGLU写成

$$
\operatorname{SwiGLU}(x)=W_o\left[\operatorname{SiLU}(W_gx)\odot W_ux\right]. \tag{4}
$$

包含两个$d\to d_f$上投影和一个$d_f\to d$下投影,主参数约$3dd_f$. 普通两层FFN约$2dd_{ff}$. 为保持参数接近,令$3d_f\approx2d_{ff}$. 若传统FFN取$d_{ff}=4d$,则$d_f\approx8d/3$.

7B中$d=4096$,理论$8d/3=10922.7$,向上对齐到11008. 对齐128便于GPU矩阵核. 参数约$3\times4096\times11008\approx135.3$M/层;32层仅MLP约4.33B,占7B模型大头. Attention四个$d\times d$投影约67.1M/层,总约2.15B.

### 5.3. Full attention 的缓存价格

每层32个KV头,假设头维128. 序列长度$S$、batch1、BF16时KV缓存为

$$
M_{KV}=2S\times32\times128\times2\ \text{bytes}. \tag{5}
$$

$S=2048$时每层约32MiB,32层约1GiB,尚未计框架开销. 若长度扩到4096便约2GiB. GQA共享KV可按KV头数比例下降,OLMo 1为保守训练与能力选择full attention.

训练attention score计算随$S^2$增长,从2048到4096近似增四倍score/value混合量. 每GPU micro-batch 4096 token在2048长度下是2条序列;保持token数而长度翻倍只剩1条. 这解释了2048与跨硬件统一配置的关系.

### 5.4. RoPE 只提供训练范围内的位置机制

RoPE把每对query/key维度旋转位置相关角度. 对位置$m,n$的内积只依赖相对差$m-n$:

$$
(R_mq)^T(R_nk)=q^TR_{n-m}k. \tag{6}
$$

它消除了绝对位置embedding表的固定长度,参数上可输入更长序列. 模型权重只在2048内学过频率组合与attention模式,因此数学上能计算更长位置不等于能力可靠. 报告没有长上下文测试,不能把RoPE存在当成长上下文证据.

## 6. Tokenizer 与数据边界

### 6.1. BPE 决定计算单位

GPT-NeoX-20B BPE词表约50K,再加入PII mask特殊token. BPE把字节序列按合并规则切分,频繁片段变成一个token,罕见串拆得更碎. 训练预算按token计算,tokenizer决定同样2T预算覆盖多少原始字符.

设语料字节数$B$,token数$T$,压缩率$r=B/T$. 固定token预算$D$覆盖约$rD$字节. Table 2手算代码约3字节/token、网页约4.5,所以代码在token采样中占用的算力高于按字节占比.

词表扩到50304行是硬件对齐. 7B不共享输入输出embedding,两份矩阵参数约$2\times50304\times4096\approx412$M;1B权重绑定只计一份,节省对小模型更重要.

### 6.2. 文档拼接改变边界条件

每篇文档末尾加EOS,随后连续拼接并切2048 token. 短网页平均584 token,一条训练实例常含三到四篇;Reddit平均212,可能近十篇. 因果attention若没有文档mask,后文可以读取前一篇无关文档,模型需从EOS学会边界重置.

拼接提高token利用率,避免大量padding. 代价是制造人工跨文档邻接. 长书平均约9.3万token,会被切成约45个2048块;每块开头看不到上块内容. 数据含长文不等于模型学到书级上下文.

### 6.3. 单 epoch 与第二 epoch 的重复

从Dolma抽2T token构造固定训练样本,所有模型至少走一遍. 部分run进入第二epoch并重新shuffle. 第二遍内容相同、邻接和batch组合变化;模型仍会收到重复文本,优化状态也已不同.

报告引用已有研究认为少量重复影响可忽略,没有给OLMo自身的严格重复消融. 2.46T意味着在2T样本上多走约23%,并非完整第二遍. 终点提升同时来自额外token与学习率位置.

## 7. 数据混合怎样写进梯度

### 7.1. 源比例是优化目标的权重

设六个数据源分布为$P_k$,采样比例为$w_k$,预训练目标为

$$
\mathcal L(\theta)=\sum_k w_k\,E_{x\sim P_k}\left[-\log p_\theta(x_t|x_{<t})\right]. \tag{7}
$$

Common Crawl实际占88.8%,其梯度主导更新. Wikipedia、论文和书籍虽单位文本质量高,总权重小,模型更少为这些域牺牲网页loss. Paloma上C4强、Wikipedia与S2ORC偏弱,正符合加权目标.

这一关系并非线性保证. 不同域共享词法、事实与推理表示,网页训练也会改善百科;少量高质量论文可能迁移到多域. 但在容量有限时,提高某域$w_k$通常会改变参数分配. 分域BPB比总平均更能看到这种取舍.

Dolma全库CC约81.7%,训练混合88.8%,说明抽样又提高网页权重. 没有完整采样表,无法精确反推GitHub、Reddit等比例. 全库大小与训练概率应分开,否则会误以为模型按库存比例顺序读完.

### 7.2. 文档长度影响源权重

按token采样时,长文档天然贡献更多训练位置. Project Gutenberg只有约56K文档却有5.2B token,每本文档平均约9.3万token;Wikipedia平均约600. 如果源内均匀读token,一本书的权重远高于一篇百科. 如果先均匀抽文档再截固定长度,权重关系会改变.

长文档也提供更多同一主题连续token,但2048切块限制可见范围. 书籍优势更多来自文体与局部连贯,无法利用整书结构. 短Reddit帖拼接后边界频繁,模型每个token可用的同文上下文更少.

### 7.3. 去重与去污染解决不同问题

去重在训练语料内部移除相同或近似内容,降低热门网页被反复计权;去污染检查训练文档与评测集重合,保护样本外估计. 一个评测段落只出现一次,内部去重不会删除它;某模板重复百万次却不在评测,去污染也不会处理.

Paloma做段落级泄漏检查后删除整篇训练文档,宁可多删上下文也减少残留. 代码域无法沿用同一方法,因为常见片段、许可证与模板高度重复,相似匹配难区分泄漏和语言惯例. Dolma 100 PLs领先因此同时含分布内匹配与污染不确定性.

WIMBD允许搜索字符串、n-gram和来源,可以审计已知测试题. 它无法证明不存在语义改写或答案泄漏;开放工具提高可检查性,没有让污染问题自动消失.

## 8. AdamW、梯度裁剪与混合精度

### 8.1. AdamW 的有效步长

AdamW更新为

$$
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\quad
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2, \tag{8}
$$

$$
\theta_{t+1}=\theta_t-\eta_t\frac{\widehat m_t}{\sqrt{\widehat v_t}+\epsilon}
-\eta_t\lambda\theta_t. \tag{9}
$$

$\beta_1=0.9$平滑约十步方向,$\beta_2=0.95$比常见0.999更快跟踪梯度尺度变化. 当异常batch令$g_t^2$增大,$v_t$较快响应,后续归一化步长下降. $\epsilon=10^{-5}$在小$v_t$坐标上主导分母,抑制更新;OLMo 2后来发现改为$10^{-8}$更稳,说明这一超参作用并不只在防除零.

Decoupled weight decay 0.1每步按学习率缩参数. 末段$\eta$变小,decay也同步减弱. OLMo 1对embedding同样decay,OLMo 2观察到embedding范数下降后取消;第一代没有对应消融.

### 8.2. Global norm clipping 改变整个更新方向的尺度

设全模型梯度拼成向量$g$,阈值$c=1$. 裁剪后

$$
\widetilde g=g\min\left(1,\frac c{\|g\|_2}\right). \tag{10}
$$

所有参数组乘同一系数,保留方向、限制步长. 单个层异常会让全网梯度一起缩小,保护训练也会抑制其他层正常学习. 大模型参数更多,全局范数统计随宽度变化,同一阈值未必等价.

若日志只记录裁剪后范数,所有触发步都显示1,看不到尖峰大小. 研究稳定性应同时记录裁剪前范数和scale factor. OLMo报告强调loss spike风险,没有像OLMo 2那样系统定义spike score.

### 8.3. BF16 前向与 FP32 状态的分工

BF16有8位指数、7位尾数,动态范围接近FP32,精度较低. 权重分片与Adam状态存FP32,前反向物化参数转BF16;矩阵乘利用低精度吞吐,优化器累积保留精度. Softmax等敏感算子保持全精度,避免指数与归一化误差.

梯度FP32 all-reduce让跨卡求和更准确. Falcon使用BF16规约更省通信,舍入误差更大. OLMo优先稳定,接受带宽成本. 两套集群都得到相近曲线,支持这一实现跨厂商可用.

FSDP把参数、梯度和优化器状态切到设备. 每层计算前all-gather权重,反向后reduce-scatter梯度. 7B若全量FP32参数约28GB,Adam一二阶矩再约56GB,单卡40GB无法连同激活容纳;切分是必要条件. 通信拓扑和micro-batch决定吞吐.

## 9. 学习率日程与最后 1000 步

### 9.1. Warmup 按 step 还是 token

附录写5000步,全局约4M token,对应约20B token,与正文约21B一致. Table 1中1B又写2000步,属于源文冲突. Warmup线性从0升到峰值:

$$
\eta_t=\eta_{max}\frac{t}{T_w},\qquad t\le T_w. \tag{11}
$$

它让Adam二阶矩和激活逐渐建立,避免随机初始化时直接大步. 如果batch从2048变2160,相同5000步覆盖token也变化约5.5%,复现应以具体run配置为准.

### 9.2. 主日程只降到峰值十分之一

线性衰减可写为

$$
\eta(t)=\eta_{max}-\left(\eta_{max}-0.1\eta_{max}\right)
\frac{t-T_w}{T-T_w}. \tag{12}
$$

终点仍为$3\times10^{-5}$,模型持续进行有意义更新. 中间checkpoint曲线的斜率同时受数据量增加和学习率下降影响:后期改进慢可能是接近最优,也可能是步长变小.

### 9.3. 收到零相当于局部精修

在2.46T checkpoint后再跑1000步,学习率从$3\times10^{-5}$线性降到0. 若batch约4M token,这段约4B token,只占总量0.16%左右. 学习率面积约$1000\times1.5\times10^{-5}=0.015$,足以移动参数,噪声随末端步长缩小.

八项任务在末端明显跳升,说明终点选择会影响排行榜. 同样训练数据和参数,拿退火前checkpoint比较会低估模型. 这也提醒Scaling曲线不能只按累计token:一个点处在恒定学习率,另一个处在退火末端,样本效率并不等价.

报告没有与「继续1000步保持$3e-5$」或cosine-to-zero对照. 可以确定的是线性收到0后的checkpoint更好,无法把收益分别归给额外4B token和退火形状. OLMo 2用更长microanneal系统化了这个发现.

## 10. Checkpoint 时间序列能做哪些分析

### 10.1. 学习速度与遗忘

每1000步约4B token保存或评测一次,2T训练约500个间隔,与500+ checkpoints一致. 对某任务画$S(D)$,可以估计达到阈值$S^*$所需token,比较架构样本效率. 如果任务先升后降,可对应数据顺序查找域切换或过拟合.

相邻checkpoint差分

$$
\Delta S_i=S(D_{i+1})-S(D_i) \tag{13}
$$

噪声较大,可按多个间隔平滑. 与学习率、训练loss和数据源比例联合回归,能提出哪些batch促进某能力的假说. 固定顺序让其他研究者复核同一时间点.

### 10.2. 参数插值与模式连通

同起点的不同硬件run可做权重插值$\theta(\alpha)=(1-\alpha)\theta_A+\alpha\theta_B$. 若中间loss低,两条轨迹位于连通区域;若高,虽然终点分数相近,参数实现不同. 报告只比较评测曲线,公开权重允许后续做这类实验.

不同训练阶段checkpoint也可用来定位能力形成. 对某层activation做线性探针,观察表征从何时可分;或对相邻checkpoint算参数更新范数. 终点权重无法回答这些过程问题.

### 10.3. 频繁保存有存储与治理成本

7B BF16权重一份约14GB,若连同优化器状态会更大;500份只保存模型也约7TB. 发布通常选择适当格式与托管,并非每个训练瞬间全状态都可得. 要精确恢复训练还需优化器、随机数和数据游标,仅模型checkpoint适合评测与继续微调,未必能无缝续训.

checkpoint也增加模型滥用面:早期模型能力较弱但偏差不同,每个版本都需许可与文档. 科学价值来自时间分辨率,发布责任随数量增加.

## 11. Paloma 与 BPB 的推导

### 11.1. 为什么 token loss 不能跨 tokenizer 比

一段文本被tokenizer A切成$T_A$个token,B切成$T_B$. 每token平均NLL分别为$\bar\ell_A,\bar\ell_B$,直接比较会混入切分粒度. 整段负对数概率为$T\bar\ell$,再除原始字节数$B$并换底:

$$
\operatorname{BPB}=\frac{T\bar\ell}{B\ln2}. \tag{14}
$$

若token切得更长,$T$小、单token预测更难,$\bar\ell$可能大;乘积才对应整段编码长度. BPB=1表示平均每原始字节需要1 bit模型编码,越低越好.

PPL与BPB关系取决于bytes/token $r=B/T$:

$$
\operatorname{PPL}=e^{\bar\ell}=2^{r\cdot BPB}. \tag{15}
$$

同一BPB下,r大的tokenizer每token PPL更高,说明PPL跨词表没有统一尺度.

### 11.2. 文档开头让短文本更难

因果模型在文档开头上下文少. 假设前$c$个token平均loss$\ell_h$,后续loss$\ell_b<\ell_h$,长度$n$文档平均

$$
\bar\ell(n)=\frac{c\ell_h+(n-c)\ell_b}{n}
=\ell_b+\frac c n(\ell_h-\ell_b). \tag{16}
$$

$n$越短,开头惩罚占比越大. TwitterAAE、Gab短文档BPB异常高可能来自这一结构效应,不必代表方言建模特别差. 比较社群语言能力应控制文档长度或只评相同上下文位置.

### 11.3. 分层多域避免大源吞没小源

Paloma覆盖585域、18源,分层抽样让小域也有足够权重. 如果按全量token平均,Common Crawl会淹没百科、论文和社群文本,总BPB几乎复述训练分布. 分域曲线能看迁移与盲区.

总平均仍需指定每域权重. 同样分数可来自网页极强、论文弱或各域均衡. OLMo报告把主要源和排除源分开,对有毒社区语料还指出降低困惑度未必是期望目标. 语言拟合能力与社会价值不能用一个方向解释.

## 12. 为什么核心八项适合训练中监控

### 12.1. 稳定信号比任务数量重要

训练环内每约4B token评一次,指标需要随能力增长大体单调、计算便宜、输出可自动解析. 核心八项都能转成候选文本补全并按似然排序,避免自由生成的格式噪声. 额外六项在Figure 4里上下乱跳,即使终点平均47.5最高,也不适合指导每次架构决策.

一个二分类任务若类别不平衡,模型始终预测多数类也能得到高准确率. MRPC等任务会出现单标签塌缩;WiC接近随机时,几个样本翻转即可改变排名. 训练曲线波动可能来自决策阈值越过,不代表底层语言能力退化.

rank classification对每个候选$c_j$计算条件log-likelihood:

$$
s_j=\sum_{t=1}^{|c_j|}\log p(c_{j,t}\mid x,c_{j,<t}). \tag{17}
$$

若候选长度不同,总和偏好短答案,可用长度归一化;具体任务模板决定口径. Catwalk公开模板和指标,让分数可重跑. 只公开题名而不公开prompt格式,同一模型也可能差数分.

### 12.2. 训练中看评测会形成开发反馈

八项在开发初期选定,随后用于架构、初始化、优化器、日程和数据混合决策. 它们没有直接进入梯度,研究团队却反复依据分数选择run,形成对开发集的人工过拟合. 最终八项成绩应视为开发指标,不能与从未查看的held-out完全等同.

OLMo 1没有像OLMo 2那样明确划出四个held-out任务. Paloma去污染保护语料重合,却无法消除研究者根据曲线调参. 最可靠的外部泛化证据来自额外任务、下游用户或后来统一套件重评.

### 12.3. 最后退火造成的跳升需配对理解

同一模型退火前后在相同题目上评测,可用配对结果判断哪些题翻转. 若多数任务同向提升,证据强于均值由单项拉动. Figure 1读图显示多条曲线末端上升,报告据此归因1000步收尾.

若只看最终模型间横比,OLMo 69.3与Llama 2 70.5相差1.2,可能落在模板和样本噪声范围;Pythia 63.0差6.3更明确. 报告主张接近Llama 2、超过其他全开放7B,没有宣称全面领先.

## 13. SFT 如何改造 Base 模型

### 13.1. 监督目标只落在回答

TÜLU 2 SFT把长对话切成2048块,并把硬编码的模型身份数据替换成OLMo相关内容. 对prompt $x$和回答$y$,典型loss为

$$
\mathcal L_{SFT}=-\sum_t m_t\log\pi_\theta(z_t|z_{<t}), \tag{18}
$$

$m_t=0$屏蔽用户prompt,$m_t=1$训练助手回答. Base预训练预测所有token,SFT改成条件回答分布. 三个epoch、峰值$2\times10^{-6}$、前3% warmup后线性到0,更新幅度远小于预训练.

不做weight decay与gradient clipping说明试点中低学习率已足够稳定,也避免改变底座参数范数. 这不代表所有SFT都无需裁剪;数据长度、batch与模型规模变化会改变梯度.

长对话切块到2048可能把早期system prompt移出后续块. 如果每块重建模板或保留必要上下文,行为不同. 数据集公开使切分规则可查,报告只概括重新切分. 上下文上限限制多轮一致性,评测主要是短指令.

### 13.2. SFT 的能力增益含格式适配

MMLU等题若用chat template,Base模型可能知道答案却不会按要求输出.SFT教会指令格式、选项字母和拒答风格,分数提升不全是新知识. 预训练知识主要存于底座,少量SFT把它映射到可评测输出.

同一TÜLU 2配方在Llama底座上开发,迁到OLMo后数据分布、tokenizer和初始能力不同. Table 4里OLMo适配仍落后TÜLU 2等强对照,报告把它视作后续改进空间. OLMo 2重新扫描学习率并更新数据,说明直接照搬不是终点.

### 13.3. 安全与真实性指标依赖判定器

ToxiGen使用RoBERTa分类器判断生成是否有毒,分类器有误报漏报与方言偏差. TruthfulQA改用两个Llama 2判定器,因为GPT-3接口弃用;与原论文judge口径不同. AlpacaEval由GPT-4比较模型回答与Davinci-003,混入长度、风格和judge偏好.

自动分数适合批量横比,无法替代人工风险评估. SFT降低毒性可能来自更常拒答或更礼貌,不等于事实更准确;Truthfulness提升也受judge模型能力限制. 报告公开评测代码,至少让偏差来源可追踪.

## 14. DPO 如何重排两条回答

### 14.1. 概率比消去参考模型基线

DPO使用修订UltraFeedback,去掉TruthfulQA prompt,chosen由GPT生成的多维评分平均最高者确定. 目标为

$$
\mathcal L_{DPO}=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y^+|x)}{\pi_{ref}(y^+|x)}-
\log\frac{\pi_\theta(y^-|x)}{\pi_{ref}(y^-|x)}
\right]\right), \tag{19}
$$

$\beta=0.1$,学习率$5\times10^{-7}$,3 epoch,前10% warmup后降到0. 参考模型通常为SFT checkpoint,限制策略相对起点的漂移.

若chosen已比rejected高很多,括号为正且sigmoid接近1,梯度变小;模型重点学习尚未满足的偏好对. $\beta$缩放margin,也对应隐含KL强度. 学习率比SFT小四倍,符合偏好阶段在已有回答能力上微调排序.

### 14.2. 移除 TruthfulQA prompt 避免评测直接重合

偏好数据若包含TruthfulQA提示,再在同题评测真实性,分数会受直接训练污染. 删除prompt降低这一风险. 语义相近问题或答案模式仍可能存在,去除题面无法证明完全独立.

UltraFeedback评分由GPT生成,开放数据保留结果,标签生产依赖闭源模型. 全开放在这里指配对数据和训练流程可获得,上游judge无法本地完全重现. 这与预训练Dolma主要来自公开网页的开放链不同.

### 14.3. DPO 提升对话不保证所有基础能力保持

偏好数据偏向有用、详细、无害回答,会改变长度、语气和拒答倾向. 小学习率与参考约束减少灾难性遗忘,仍可能让Base似然或某些知识任务下降. Table 4关注MMLU、AlpacaEval、ToxiGen与Truthfulness,没有覆盖代码、长上下文或多语.

SFT→DPO顺序有意义:SFT先把策略放到能稳定生成回答的区域,DPO再比较回答. 直接从Base做DPO时,chosen/rejected概率可能都很低,概率比梯度与实际生成分布脱节. OLMo 1没有直接DPO对照,后续RL-Zero路线才系统研究跳过SFT的可能性.

## 15. 计算量、吞吐与硬件

### 15.1. 6ND 的手算

Dense decoder训练常以

$$
C\approx6ND \tag{20}
$$

估算FLOPs. 取$N=7\times10^9,D=2.46\times10^{12}$,

$$
C\approx6\times7\times2.46\times10^{21}
=1.033\times10^{23}. \tag{21}
$$

这与OLMo 2后来表中给OLMo 1记$1.0\times10^{23}$一致. 系数6粗略包含前向约2ND、反向约4ND;attention的序列平方项、embedding和归一化未精确计算.

若只算2T主样本,约$8.4\times10^{22}$;多出的0.46T与收尾使项目正式run更贵. 四个7B变体和消融的总研发计算不在单模型$6ND$里.

### 15.2. 每步 token 与总步数

全局batch约4M token,2T需要约500K步,2.46T约615K步. 每1000步约4B token,与评测间隔说明一致. 若batch为2160×2048=4.424M,步数则约556K. 两个口径差约10%,不能混用精确step推数据位置.

7B每GPU micro-batch4096 token. 假设用1024个逻辑设备,一次micro-step约4.19M token,可能无需梯度累积;A100集群216卡则需多次累积或不同全局batch. 报告说为吞吐略调batch,跨硬件曲线按累计token比较更公平.

### 15.3. 能耗与FLOPs不是同一效率

LUMI run 135MWh,A100 run 104MWh,两者终点相近. 能耗取决于芯片吞吐、利用率、通信、运行时间和节点功率. FLOPs相同不保证MWh相同. 训练作业的平均功耗乘时间给能量,不是用芯片标称峰值直接推.

PUE 1.1把GPU侧能耗扩到机房总能耗. A100行排放

$$
104\text{ MWh}\times1.1\times0.610
\approx69.8\text{ tCO}_2e. \tag{22}
$$

LUMI按官方水电强度0记0,若取0.024则$135\times1.1\times0.024\approx3.56$吨. 排放差主要来自电网,不等于硬件能效差.

表格未计制造、调参、失败run、数据处理与推理. 239MWh是两次7B预训练合计,不能当一份checkpoint的能耗. 开放模型可能减少别人重复预训练,也会增加下游部署,完整生命周期未知.

## 16. 跨硬件复现的数值边界

### 16.1. 规约顺序会改变低位

分布式梯度是各卡局部梯度之和. 树形all-reduce顺序因拓扑而变,浮点结果低位不同.FP32规约把误差压小,无法消除. Adam的$m,v$递归会积累差异,最终权重分叉.

验证跨硬件复现应比较训练loss置信带、各任务曲线和终点分布,不要求hash相同. 两条2T曲线几乎重合说明AMD/NVIDIA实现没有产生能力级偏差,单一run仍不足以估计随机种子方差.

### 16.2. 数据顺序固定提高配对效力

设观察loss差$\Delta=L_A-L_B$,两run看到相同batch时,样本难度噪声高度相关,差分方差

$$
\operatorname{Var}(\Delta)=\operatorname{Var}(L_A)+\operatorname{Var}(L_B)
-2\operatorname{Cov}(L_A,L_B). \tag{23}
$$

协方差为正会降低差分噪声. 不同shuffle时协方差接近0,需要更多run才能区分小差异. 固定顺序是昂贵大模型实验中很有效的配对设计.

同顺序也可能让某个配置恰好适应该序列. 最好在小规模多种子确认,再在7B做配对单run. OLMo报告主要展示大规模可重放,没有完整多种子统计.

### 16.3. 硬件等价不覆盖软件升级

PyTorch、Flash Attention、ROCm/CUDA和编译器版本都会改变kernel. 即使设备相同,升级可能改变融合与舍入. 容器、commit和依赖锁是复现材料的一部分. OLMo公开代码降低版本不明风险,长期归档仍要保存镜像或精确环境.

## 17. 训练稳定性的已知与未知

### 17.1. 「安全」是经验选择

无参LN、无bias、FP32规约、FP32优化器状态、global clip和短序列都减少数值风险. 报告通过训练环内消融与正式run选择配置,没有给稳定性定理. 7B能跨两类GPU训到2T以上是直接证据,放大到13B/32B是否仍稳当时未知.

OLMo 2后来发现第一代配方出现loss与梯度尖峰,加入重复过滤、新初始化、QK-Norm、reordered RMSNorm、z-loss并修改Adam epsilon. 后续修订说明OLMo 1的安全裕度有限,也让第一代checkpoint成为研究尖峰的对照.

### 17.2. Full attention 也会产生 logit 尺度问题

Attention logit$a=q^Tk/\sqrt{d_h}$. 若$q,k$范数随训练增大,softmax趋于one-hot,低概率位置梯度消失,最大logit还可能溢出. OLMo 1没有QK-Norm或QKV clip,依赖Pre-Norm、初始化和优化器间接控制.

监控应包含$q,k$范数、logit最大值、attention熵与层级梯度. 只看总loss,可能在发散前看不到内部尺度漂移. OLMo 2增加QK-Norm正是直接约束这一通道.

### 17.3. Weight decay 对 embedding 的慢效应

AdamW每步把参数乘$(1-\eta\lambda)$. 对低频token embedding,数据梯度稀少,decay长期缩小范数. 经过$T$步倍率约

$$
(1-\eta\lambda)^T\approx e^{-\eta\lambda T}. \tag{24}
$$

学习率变化使实际指数为$-\lambda\sum_t\eta_t$. 高频token被梯度持续补偿,低频token更易缩小,造成频率相关尺度. 第一代没有识别为问题,第二代取消embedding decay.

### 17.4. 数据异常与参数状态共同触发尖峰

Dolma包含Base64、数字表、模板重复等异常文本. OLMo 2发现尖峰batch常有长重复n-gram,同一文本换模型或顺序又未必触发. OLMo 1没有对应过滤与loss mask,训练成功说明异常并非必然导致崩溃;尖峰风险仍可能随宽度放大.

固定顺序让研究者能从异常checkpoint回查batch,这是第一代发布设计的价值. 没有训练数据顺序,后续团队很难发现重复模式关联.

## 18. 参数量手算与规格冲突

### 18.1. 7B 主体参数

取$d=4096,L=32,d_f=11008,V=50304$. 每层attention约$4d^2=67.1$M,MLP约$3dd_f=135.3$M,合计约202.4M;32层约6.48B. 输入与输出embedding不共享,约$2Vd=412$M. 加归一化小项,总计约6.9B,符合7B名义.

若主表的$d=4086$被当真,32头无法整除得到常见整数头维,且与附录4096冲突. 架构实现显然应以配置与4096口径核对,引用主表时注明排版差异. 这种小错误正说明发布代码比PDF单表更可靠.

### 18.2. 1B weight tying 的占比

1B取$d=2048,V\approx50K$,单份embedding约103M参数. 不绑定需再加103M输出头,相对1B约10%. Weight tying对小模型显著节省容量;7B多一份约206M,占比约3%,选择不共享换取输入与输出表示独立.

共享时logit矩阵与输入embedding同权,词的输入几何约束输出分类器. 不共享增加表达自由,也增加内存与FLOPs. 两档设计不同,1B与7B并非纯宽深Scaling.

### 18.3. 参数名义值与 FLOPs 口径

$6ND$用7B名义参数,若实际6.9B差约1–2%. 是否计embedding、输出头和激活checkpoint也会改变. 跨论文比较保留一位有效数字足够,写成$1.0332\times10^{23}$会制造虚假精度.

Attention的序列项近似每层$O(S^2d)$. 参数法按$ND$主要计算矩阵权重乘法,在$d$大、$S=2048$时可作量级近似;长上下文或小模型下误差更大.

## 19. 公开 checkpoint 的实验范式

### 19.1. 数据归因

选某个事实或短语,用WIMBD统计其在数据顺序中的首次与累计出现,再沿checkpoint测对应prompt概率. 若出现后概率上升,说明相关;若出现前已会,可能来自泛化或近义文本. 需要对照未出现但难度相近的事实,否则训练整体进步也会造成上升.

可定义暴露计数$c_i$与目标logit$z_i$,研究$\Delta z_i$与新增暴露$\Delta c_i$的关系. 文档顺序固定允许配对,语义改写和共享实体会造成混杂. 因果删除实验仍需重训小模型.

### 19.2. 能力形成

在每个checkpoint跑相同任务,拟合从随机到稳定正确的转折. 单题输出可能来回翻转,任务平均更平滑. 若任务准确率突然上升,可检查loss是否平滑,区分阈值效应与真正训练相变.

早期checkpoint还可用于研究inverse scaling:某能力先改善后恶化. 终点模型隐藏了这种路径. 八项核心任务稳定上升,额外六项随机,恰好展示任务选择对结论的影响.

### 19.3. 优化器与学习率研究

从同一中间checkpoint分叉,改变日程、epsilon或weight decay,比从头训练便宜. 优化器状态若未发布或不匹配,恢复时重新初始化$m,v$会造成瞬态,不能当无缝分叉. 最理想的checkpoint包含模型、优化器、scheduler、数据游标和RNG.

OLMo的500+模型checkpoint主要确保表征与评测研究;精确训练恢复能力需查看具体发布artifact. 「有checkpoint」与「完整训练状态」应区分.

### 19.4. 数据顺序研究的伦理边界

能定位某事实来自哪篇文档,也可能帮助提取个人信息或版权内容. 研究memorization需最小化暴露敏感文本,报告聚合统计,遵守数据许可与删除请求. 开放提高透明度,同时把治理责任分给使用者.

## 20. 与同代模型比较时必须对齐的变量

### 20.1. Llama 2

Llama 2 7B同为32层、4096宽、SwiGLU和RoPE,但上下文4096、GQA、RMSNorm、cosine日程. Table 3均分70.5对OLMo 69.3,训练数据和token量也不同. 相近成绩不能证明架构等价,只能说明OLMo完整配方达到同一能力带.

GQA会减少缓存,4096上下文增加训练成本与长程能力机会,RMSNorm和日程影响稳定与终点. 要做架构因果比较需在同数据、同token、同FLOPs下消融,报告没有完成.

### 20.2. Pythia 与 RPJ-INCITE

这两家也有中间checkpoint,因此Figure 2可画Scaling曲线. Pythia在Pile上强与训练分布一致,token少不妨碍域内BPB领先. RPJ-INCITE同样含GitHub却在100 PLs落后,提示后处理匹配与污染共同作用.

OLMo均分高于它们,同时训练token更多. 「全开放模型中更强」成立于成品横比;每单位计算效率需结合曲线与数据质量,不能只看终点.

### 20.3. MPT、Falcon 与 OpenLM

MPT非CC比例更高、可能有semantic dedup,Paloma总体更强. Falcon采用MQA、parallel block、GeLU、更高学习率与BF16规约,系统目标不同.OpenLM结构最接近OLMo,归一化和日程不同. 多变量横比适合提出假说,不能当单项消融.

### 20.4. 开放度不是单轴排名

可分别记录权重、代码、数据、数据处理、训练顺序、中间checkpoint、日志、评测、SFT/DPO数据与许可证. 某模型可能开放权重和代码却不开放数据;另一个开放数据但许可证限制用途. OLMo 1在这些维度覆盖广,所以称全栈开放.

上游依赖仍有限制:网页版权、GPT judge、硬件固件和第三方库无法全部由Ai2控制. 「全开放」应理解为项目交付范围最大化,不等于从晶体管到每条数据权利都完全自由.

## 21. 后续版本为何改掉第一代设计

### 21.1. 从无参 LN 到输出侧 RMSNorm

第一代认为无参LN安全快速,第二代消融发现RMSNorm性能相当,库bug消失,并用输出侧归一化控制分支写入尺度. 变化说明设计受工具链和规模影响. 第一代结论没有错误,适用范围是当时7B与实现.

### 21.2. 从无 QK 约束到 QK-Norm

模型放大后attention logit更易增长. OLMo-0424曾clip QKV到8,OLMo 2改QK-Norm,连续控制范数. 第一代没有这层保护,是32B不直接沿用配方的重要原因.

### 21.3. 从末段 4B token 到 Dolmino 课程

1000步收到0证明低学习率收尾有效,但数据仍是高CC的Dolma. OLMo 2在50–300B退火段加入高质量网页、数学和指令数据,并用microanneal选料、soup合并. 它把第一代的优化技巧扩成数据课程.

### 21.4. 从 SFT+DPO 到 RLVR

第一代对齐停止在偏好优化,数学正确性只能从示范和偏好间接学习. OLMo 2加入可验证奖励PPO/GRPO,直接优化GSM8K/MATH答案;Olmo 3再扩到长推理. 代际成绩不能只归给底座,后训练目标也逐步增强.

### 21.5. 从 2048 full attention 到混合长上下文

OLMo-0424把长度提4096,Olmo 3到8192并加入SWA,再做长上下文扩展;Olmo Hybrid用GDN替换多数SWA层. 这条线回应第一代full attention缓存与平方计算的成本. OLMo 1提供最朴素对照,后续每次节省都可相对它解释.

## 22. 结论的证据强度

第一档是直接可核对事实:模型规格、Dolma组成、训练token、日程、两套硬件、checkpoint数量、评测表和发布清单. 这些由配置、表格与artifact支持.

第二档是强经验关系:CC占比高与C4 BPB强、最后1000步退火与多项指标上涨、两套硬件终点接近. 它们有曲线和同run前后对照,仍可能受未控制变量影响.

第三档是机制解释:重复网页为何塑造域能力、无参LN为何更稳、末段小步为何改善泛化、后处理为何让100 PLs占优. 数学与后续报告提供合理路径,第一代没有逐项完成因果实验.

第四档是不能由报告支持的外推:RoPE让模型自然支持长上下文;无参LN普遍优于RMSNorm;OLMo全面超过Llama 2;DPO后模型已足够安全;代码BPB领先证明代码推理强. 这些说法都缺对应评测或受污染、口径限制.

## 23. 复现 OLMo 1 的最小实验协议

### 23.1. 数据身份

首先固定Dolma版本、六源文件清单、过滤配置、去重版本与2T抽样manifest. 对每份shard计算hash,记录文档顺序、EOS插入和2048切块逻辑. 数据源相同但revision不同,模型看到的内容就不同;只写「使用Dolma」不足以复现.

Tokenizer需锁vocab、merges、special token ID和预分词规则. 用一组英文、代码、Unicode、PII占位符做golden test,逐个比较token ID. 一个特殊token偏移会让所有embedding索引错位,权重也无法互换.

Paloma去污染应在切块前对文档执行,保存删除文档ID与匹配原因. 若先切块再删命中块,同文其它段落仍泄漏;两种流程的评测意义不同.

### 23.2. 模型身份

确认$d=4096$而非主表排版的4086,32层、32头、FFN 11008、词表pad到50304、7B embedding不绑定. 打印参数量分解,MLP约4.33B、attention约2.15B、双embedding约0.41B,总量应接近6.9B.

逐层确认无bias、non-parametric LayerNorm、sequential Pre-Norm、SwiGLU与RoPE theta. 用固定随机输入比较参考实现和训练实现logit. 参数名相同不保证block顺序相同,checkpoint转换最易在Norm位置出错.

### 23.3. 优化身份

AdamW $\beta=(0.9,0.95),\epsilon=10^{-5}$、weight decay 0.1、global clip 1.0. 参数组是否包含embedding与Norm必须与原配置一致. 学习率峰值$3e-4$,warmup冲突需按目标run的日志确认,主段线性降至$3e-5$,最终1000步再到0.

保存每步累计token,不要只保存step. batch 2048与2160会让同step偏移. 梯度累积、world size和micro-batch共同决定全局batch;跨集群迁移时按token对齐scheduler.

### 23.4. 数值身份

FSDP分片参数与优化器FP32,前反向BF16,softmax等敏感算子FP32,梯度FP32规约. 固定PyTorch、ROCm/CUDA、kernel与容器. 先在单机跑数百步,与公开早期loss和梯度范数比;再扩多机.

跨硬件不要求逐位一致,需预先定义容差:例如验证loss曲线差、八项均分区间与Paloma分域排序. 没有容差时,任何低位差都可被误称复现失败.

### 23.5. 评测身份

锁Catwalk commit、prompt模板、shot数、候选长度归一化和数据版本.Paloma按原始字节计BPB,确认Unicode编码和文档边界. 对adaptation模型使用各自chat template,否则系统/用户标记差异会破坏结果.

自动judge需记录模型版本与日期.GPT服务更新后AlpacaEval不可完全重放,ToxiGen与TruthfulQA本地判定器更可控. 报告数值复现与今天重新评测应分列.

## 24. 四个失败反例

### 24.1. 长上下文检索

把随机字符串放在4096或更远位置,末端要求复述. OLMo 1只训2048,即使推理框架允许更长RoPE位置,模型也可能注意力错位或忽略远处. 失败不能说明RoPE公式错误,说明训练分布没有覆盖.

若截断到2048后成功、4096失败,边界清楚;若两者都失败,可能是随机检索能力不足. 需要与同规模4096训练模型配对.

### 24.2. 非网页专业域

在专业论文、百科细节或法律文本上,高CC混合可能落后于非CC比例更高的模型. 增加总token未必补足,因为目标权重$w_k$持续偏低. Paloma S2ORC/Wikipedia曲线已给方向证据.

这种失败可通过末段高质量域数据改善,OLMo 2的Dolmino正走此路. 直接把Stage 1网页token再翻倍,收益可能低于重配数据.

### 24.3. 重复与异常batch

构造长Base64或单一数字序列,同batch大量重复. 相似token梯度高度相关,global clip虽限制一步,Adam状态和attention logit仍可能异常. OLMo 1没有在线重复loss mask,比OLMo 2更暴露.

若同batch在1B稳定、7B尖峰,说明宽度/深度与参数状态交互. 换checkpoint重复测试能区分文本是否充分触发.

### 24.4. 对齐域外任务

TÜLU 2偏英语通用指令,没有为OLMo tokenizer和底座专门优化. 多语、代码、长对话或强数学任务可能在SFT/DPO后仍弱. AlpacaEval上风格改善不能覆盖这些域.

DPO还可能偏好更长、更礼貌的回答,在要求简短或严格格式时失分. 需要分域评测,不能以单一聊天胜率代表全部对齐质量.

## 25. 从数据暴露到记忆的定量直觉

### 25.1. 稀有文档可能一次也没被抽到

若从$N$个等权样本有放回抽$m$次,某样本零曝光概率

$$
P(K=0)=\left(1-\frac1N\right)^m\approx e^{-m/N}. \tag{25}
$$

当$m=N$时仍约36.8%未见,同时一些样本重复. OLMo数据manifest可能采用无放回遍历而非独立抽样,此式作为参照:「token数等于数据池大小」不自动等于每文档恰见一次.

固定2T样本并走一个epoch意味着该manifest内每token一次,但Dolma全库2.668T,约0.668T未进入首轮抽样. 各源采样权重又非库存比例,未见内容在源间不均匀.

### 25.2. 重复曝光与记忆概率

某序列出现$c$次,每次产生相似梯度,参数对它的拟合通常随$c$增强. 但周围上下文、学习率位置与batch搭配不同,每次作用不等. 第二epoch重新shuffle会改变邻接,减少整段完全相同上下文,核心文档仍重复.

研究记忆应控制字符串频率、长度与可预测性. 常见短语高频却不算隐私记忆;罕见长串一次复述更有意义. 开放数据允许精确计数,是OLMo研究优势.

### 25.3. 检查点定位学习时刻的局限

每1000步保存一次,能力变化只能定位在约4B token窗口. 如果目标文档在窗口中出现,checkpoint后概率上涨,仍可能由同窗口其它相关文档造成. 更细日志或小规模重训才能缩小.

模型也可能先从组合规律推断事实,再见原文强化. 「首次精确字符串出现」不等于首次获得语义信息. WIMBD字符串搜索需要与embedding相似检索或实体链接配合.

## 26. 统计地读取表格差异

### 26.1. 准确率标准误

对$n$道独立题、准确率$p$,标准误

$$
SE=\sqrt{\frac{p(1-p)}n}. \tag{26}
$$

$n=1000,p=0.7$时约1.45个百分点,95%区间约正负2.8. 两模型差1分可能没有统计区分;同一题上的配对bootstrap更有力,因为题目难度被抵消.

八项平均减少单任务噪声,任务并非独立且样本量不同. 等权平均让小任务与大任务同权,没有自然统计含义,只是开发指标.

### 26.2. BPB 差异积累

BPB差$\delta$看似很小,对$B$字节文本总编码差为$B\delta$ bits. 例如$\delta=0.01$,1GB文本约多10MB量级bits/8存储. 语言模型loss上的微小稳定差可对应大量token总似然差.

分域样本量与文档长度不同,BPB区间应按文档bootstrap而非把token当独立. 相邻token强相关,按token算会低估方差. 报告图主要给点估计与趋势,精细排名需补区间.

### 26.3. 多次看榜的赢家偏差

开发中尝试许多配置,选最高八项均分者,其分数包含正噪声. 尝试越多,赢家偏差越大. Held-out或多种子能校正. OLMo开放失败run与过程材料有助于估计搜索规模,但报告没有为所有超参选择给统计修正.

## 27. 训练研究与部署选择是两套问题

训练研究看数据可追踪、中间checkpoint、日志、代码与消融入口. OLMo 1在这些维度领先,即使终点能力略低于闭源数据训练的模型也有独特价值.

部署看延迟、上下文、缓存、指令质量、安全、多语和许可证. Full attention、2048训练长度和早期TÜLU 2让OLMo 1今天不占优势. 公开度不能抵消应用需求.

同一个权重可作为研究对照或生产组件,评价函数不同. 用排行榜否定其科学价值,或用开放度替代部署评测,都会混淆目标.

## 28. 这一代最值得继承的方法

第一是把数据版本、顺序和评测一起发布. 它让后续的稳定性、记忆和数据归因研究有共同坐标. 第二是训练中只监控稳定、有解释的任务,把噪声任务放到终点补充. 第三是跨硬件跑近似同配方,验证软件栈可移植. 第四是保留高频checkpoint,把模型当过程而非单个文件.

架构本身随后大量改变:Norm、QK、z-loss、上下文、GQA/SWA/GDN、数据课程和RL都继续演进. 发布方法却成为OLMo家族持续特色. 第一代能力会过时,可干预的训练记录不会因为新排行榜出现而失去价值.

## 29. Dolma 六类数据的互补与偏差

### 29.1. Common Crawl 提供覆盖,也主导文体

Common Crawl有2180B token、37亿余文档,主题覆盖最广. 过滤后的网页仍包含SEO文本、模板、转载和时间敏感内容. 88.8%的训练权重让模型获得广泛词汇与事实,也让网页常见的短段落、列表和说明文成为默认语言分布.

C4同源于Common Crawl,处理管线虽不同,域距离仍较近. OLMo在C4 BPB领先既反映训练充分,也反映评测与主源接近. 这一成绩不能直接外推到书籍或学术论文.

### 29.2. GitHub 的 token 成本与许可证

GitHub约342B token,是第二大源. 代码标识符、空格和符号让bytes/token更低,同样原始字节消耗更多训练token. 它提供程序语法、API与结构化推理模式,报告没有HumanEval等代码生成评测,100 PLs BPB只能测语言建模.

仓库许可证、复制代码与生成内容会影响可再发布性. Dolma处理和许可文档决定使用边界. 代码去污染困难,benchmark函数可能以轻微变体出现;域内BPB领先要保留污染不确定性.

### 29.3. Reddit 提供对话语气,也带社会偏差

Reddit约80B token、3.77亿文档,平均短. 它为问答、口语和观点表达提供信号,可能帮助后续指令适配;同时含毒性、刻板印象和社区偏差. 质量过滤降低风险,无法消除.

短帖拼接让一条训练序列跨多个主题,EOS边界学习重要. Paloma社群语料的BPB还受短文档开头效应,不能简单解释为模型更懂或更不懂某群体.

### 29.4. Semantic Scholar、Wikipedia 与 Gutenberg 提供稠密长文

Semantic Scholar约57B token,平均文档约1470 token,接近单条训练长度;Wikipedia约3.7B,质量高但权重极小;Gutenberg约5.2B,单文档很长. 三者提供正式写作、知识结构与长段连贯,总量远小于网页.

论文与百科Paloma偏弱说明小权重没有完全抵消域差. Gutenberg被切块后只能训练局部长文风格,无法学习跨章节依赖. OLMo 2后来在末段提高peS2o、Wikipedia等高质量源,正回应这一不平衡.

### 29.5. 数据多样性与容量竞争

若模型容量无限,各域可分别拟合;7B容量有限,共享参数在域间折中. 提高论文权重可能改善学术BPB,也可能牺牲网页平均. 选择mix本质是设定目标任务先验.

用单一总loss挑mix会偏向最大源. 分域Paloma和八项任务提供多目标反馈,开发者再人工取舍. 这也是数据配方无法由一个Scaling Law系数自动决定的原因.

## 30. 训练曲线的三种反事实

### 30.1. 如果不做最后退火

退火前checkpoint已经看过几乎相同数据,能力低于退火后. 差异可能来自额外4B token、学习率下降或两者交互. 最小反事实需从同一2.46T起点分三支:保持$3e-5$、线性到0、直接停止. 只有第二支优于第一支,才能把收益归给退火形状.

报告没有这组三支,所以正文能说末段操作有效,不能说线性到0是唯一原因. 后续OLMo 2更系统的anneal实验补强方向.

### 30.2. 如果提高非网页比例

当前Paloma曲线显示网页强、百科论文弱. 从同一早期checkpoint分叉,一支保持88.8% CC,一支提高非CC,按相同token和日程训练,可测域能力交换. MPT横比提示非CC更多可能改善总Paloma,同时有semantic dedup等混杂.

Dolma各源分开保存使这个反事实可执行. 没有源级存储,只能重新构建整个语料.

### 30.3. 如果换 GQA 或更长序列

保持参数/FLOPs近似,把full attention换GQA,测训练loss、下游与KV缓存;再将2048改4096,按相同总token比较. 序列变长减少batch实例数、改变文档拼接和attention计算,需固定计算预算与token预算两种口径.

Llama 2横比同时改变多项,无法替代这组实验. OLMo后续版本逐步做了相关设计,第一代发布物提供起点.

## 31. 可证伪的机制测试

### 31.1. EOS 是否真的隔离文档

构造两篇无关短文A、B,比较单独输入B与`A<EOS>B`时B各位置logit. 若EOS学会强边界,进入B若干token后差异快速衰减;若持续明显,模型利用跨文档信息. 换A内容重复实验,排除长度位置效应.

再从不同checkpoint画差异,可观察边界行为何时形成. 训练未显式document mask,这个测试直接检验隐式重置假说.

### 31.2. 无参 LayerNorm 是否限制通道尺度

记录每层LN输入均值、方差和下游线性层输出范数. 与同起点RMSNorm小模型run比较,若无参LN确实稳定,跨层激活与梯度分布应更窄、尖峰更少. 只比较最终loss无法确认机制.

还可给RMSNorm gain固定为1与可学习两种消融,分离「不减均值」与「可学习缩放」. OLMo 1只给最终选择,后续报告说性能无差异.

### 31.3. 数据域权重是否预测梯度方向

从同一checkpoint分别取CC、论文、代码batch,计算梯度$g_{cc},g_{paper},g_{code}$及余弦

$$
\cos(g_i,g_j)=\frac{g_i^Tg_j}{\|g_i\|\|g_j\|}. \tag{27}
$$

正值表示局部协同,负值表示冲突. 若论文与CC经常冲突,88.8%权重会压过论文更新;若高度正相关,小论文比例也能借网页迁移. 这比仅凭终点BPB猜容量竞争更直接.

### 31.4. DPO 改的是事实还是表达

对同一知识问题设计多种提示:自由回答、候选似然、只取最终短答案. 若DPO只让自由回答胜率提高、候选知识不变,主要是风格和指令映射;若三者都提高,可能连内部知识使用也改善. 再比较Base、SFT、DPO三个checkpoint,定位变化阶段.

## 32. 最终阅读顺序

先看Table 1与5确定模型和优化器,再看Table 2与§3.3确定数据库存和实际抽样的区别;Figure 1解释下游随token变化,Figure 2与Paloma解释数据域;Table 3只回答Base横比,Table 4与8回答适配. Section 5的发布清单决定哪些结论能由第三方复查.

遇到数字冲突时保留表号与run身份:4096/4086、warmup 2000/5000、batch 2048/2160都不能暗中合并. 它们可能来自排版、模型档位或硬件变体. 代码配置、日志与checkpoint元数据优先于孤立表格.

最后再用OLMo 2和Olmo 3回看哪些选择被保留. 被改掉的设计并不让第一代失去价值;它们标出规模放大时出现的新问题. 无参LN、无QK-Norm、高CC混合和短DPO流程共同定义了一个清楚的历史基线.

OLMo 1最强的论点来自可验证性:2.46T训练如何组成、某个能力何时出现、两套硬件是否一致、评测是否污染,都有材料可追. 它的能力成绩处于同代7B竞争范围,真正拉开差异的是第三方可以重新运行、分叉和反驳整条训练过程.

## 33. 发布物分别支持哪类研究

终局Base权重适合下游微调、表示探针和同代能力比较;SFT与DPO权重适合研究同一底座经过两种适配后行为怎样变化. 三个阶段共享预训练起点,比拿不同组织的chat模型比较更容易归因. 如果SFT后MMLU变化、DPO后AlpacaEval变化,可以把阶段与指标配对观察.

中间checkpoint适合训练动力学、数据记忆和能力形成. 每1000步的时间分辨率对数十万步训练足够细,又不会产生每步保存的巨大成本. 对瞬时尖峰仍可能太粗,需要日志补充. checkpoint与日志一静一动,前者能重跑推理,后者保留优化过程.

Dolma和生成代码支持数据研究. 可以替换过滤器、改变源比例、做语义去重或构造同顺序小模型. WIMBD支持内容搜索与统计,数据manifest把搜索结果映射到训练时间. 数据本身很大,完整重建需要存储、带宽和合规审查,「公开可得」不等于低成本.

训练代码与配置支持架构、优化器和硬件实验. 同一代码跑MI250X与A100证明抽象层可移植,其它集群仍要调整通信与batch. OLMo-core后来重写基础设施,第一代代码的价值还包括记录当时FSDP与AMP的具体实现.

Catwalk和Paloma支持评测重放. Catwalk固定任务模板与候选评分,Paloma固定多域语料与BPB. 评测数据版本、依赖和模型tokenizer仍要锁定;框架开放减少隐藏脚本,不会消除所有环境差异.

Open Instruct和TÜLU数据支持后训练分叉. 研究者可从Base重复SFT、换偏好数据或跳过DPO. GPT生成标签的上游过程未必能完全重现,已发布样本足以复跑相同训练目标.

## 34. 开放许可与科学复现不是同一维度

Apache 2.0允许广泛使用、修改和再分发模型代码与权重,并处理专利授权等软件问题. 训练数据来自大量第三方网页,每条内容的版权、隐私与站点条款仍可能不同. 模型许可证无法替所有源内容重新授权.

科学复现关心方法信息是否充足;法律可用性关心权利边界;安全治理关心模型可能造成的伤害. 一个项目可以在科学上高度透明,仍需数据合规与部署评估. OLMo把材料公开,让这些问题更容易审计,也让使用者直接承担判断责任.

开放训练顺序还会暴露某段文本是否进入模型,这对版权研究有价值,对个人信息则敏感. 合理使用方式是报告文档ID、频率和聚合结果,避免无必要复制敏感原文. 数据删除或修订后,旧checkpoint已经吸收的信息不会自动消失,需要版本化说明.

## 35. 一组最终手算

7B模型2.46T token、全局约4M token/step,得到约61.5万步;每1000步评测一次,约615个时间点,与500+ checkpoint数量相符. Warmup 5000步约20B token,只占总训练0.81%. 最后1000步约4B token,占0.16%,却带来可见终点提升,说明token位置与学习率比单纯数量重要.

Dolma总库2.668T,首轮固定样本2T约占75%. Common Crawl库存占81.7%,训练混合占88.8%,网页相对权重至少提高约7.1个百分点. 7B主模型多走0.46T,相当于首轮样本23%;它没有把整个Dolma完整走一遍再重复.

按6ND估算约$1.0\times10^{23}$ FLOPs,两次硬件run能耗104与135MWh. 只用能耗除FLOPs会得到每FLOP设施效率,但两个run的实际token、batch和利用率可能不同,报告没有足够信息做精确芯片排名. 能确认的是跨硬件能力相近,电网让碳排口径差异很大.

八项均分69.3对Llama 2的70.5差1.2,对Pythia的63.0高6.3. 前一个差距需要考虑评测噪声与配方差,后一个差距更明显但伴随更多训练token. 这些数字支撑「达到同代竞争区间」,不支撑「每项全面领先」.

把这些手算放在一起,第一代的取舍很清楚:用较短上下文、full attention和偏保守数值设置换取跨集群可训练性;用高网页占比换广覆盖,接受专业域较弱;用频繁checkpoint和固定顺序增加研究价值,承担存储成本;用现成TÜLU 2快速验证适配,暂不追求最强后训练. 每个收益都有对应代价,后续版本的改动也能从这些代价逐项找到来源.

因此复现OLMo 1时,最重要的验收不只是终点69.3. 数据顺序是否一致、2T附近曲线是否接近、Paloma是否保持网页强和专业域弱的相对形状、退火前后是否同向改善、两种硬件是否落在相近区间,共同构成更完整的复现结果. 单个平均分对上而过程完全不同,只能算结果碰巧接近.
