# Dolma 技术解析：三万亿 Token 开放语料的设计、验证与边界

本文依据 arXiv:2402.00159v2 的 64 页论文、官方 LaTeX 与 Dolma Toolkit。论文为 Dolma v1.6 准备，因此数字只对应这一版本。Dolma 的贡献不只是约三万亿 token 的英语语料，还包括逐来源构建说明、数据消融和开源工具。

## 1. 设计目标与规模

论文提出四个目标。第一，与已知大模型预训练配方保持一致，使公开数据可以用于研究闭源模型的数据实践；这也使 v1.6 聚焦英语，作者承认它强化“英语是默认语言”的假设。第二，在行业做法不明确时，使用小模型消融支持选择。第三，目标规模为 2–3T token，以研究模型和数据规模关系。第四，开放同时意味着发布数据并记录整理过程，必要时因法律、伦理与实践约束偏离商业配方。

团队没有纳入处于版权争议中心的 Books3, 并主动处理 PII. 这里的开放覆盖来源记录, 删除规则与风险政策, 语料规模只是其中一项.

语料覆盖六类来源、超过 40 亿文档。Common Crawl 约 9,812GB、37.34 亿文档、1.928T Unicode words、2.479T Llama token；GitHub 1,043GB、2.10 亿文档、260B words、411B token；Reddit 339GB、3.77 亿文档、72B words、89B token；Semantic Scholar 268GB、3880 万文档、50B words、70B token；Gutenberg 20.4GB、5.6 万文档、4B words、6B token；Wikipedia/Wikibooks 16.2GB、620 万文档、3.7B words、4.3B token。token 数绑定 tokenizer，不能与字节或 Unicode word 混用。

## 2. Toolkit 与数据消融

Toolkit 把常见操作统一为 filtering 与 mixing。过滤阶段在文档、段落或句子上计算语言、质量、内容和 PII 信号，再删除或替换；Mixer 负责跨文件上/下采样、去重、去污染与输出。属性和文档分离，使阈值改变时不必重跑昂贵分类器。

论文给出性能量级：内部复现 C4 配方时每 TB 约需 122 CPU 小时；用一台 192 vCPU 的 `c6a.48xlarge` 处理约 200TB raw Dolma，估算五天。该数字绑定任务、实例与存储环境，不是任意 tagger 的固定吞吐。Bloom filter 提供线性时间概率去重，也可先放测试片段再做去污染，但存在误报；容量、元素估计、哈希与输入顺序都属于复现参数。

团队用 OLMo 系列 1.2B decoder-only 模型比较数据干预，每个模型训练到 150B token 后停止。评测覆盖八项数据集，使用 zero-shot in-context prompting，把任务转为 ranked text classification。消融比文本统计更接近训练目标，但外推边界明显：1.2B 的早期排名不保证在大模型和多万亿 token 下不变，八项评测也不覆盖生成、安全、多语与长上下文。

## 3. Common Crawl 清洗漏斗

Dolma-Web 约 2.28T token，来自 `2020-05` 至 `2023-06` 的 25 个 Common Crawl snapshot。到 2024 年 2 月共有 97 个 snapshot，团队只下载达到目标规模所需的 shard，并假设清洗至少缩小十倍，因此它不是同期互联网完整镜像。

CCNet 先做语言识别与初始段落去重。FastText 英语阈值为 0.5，按字节移除 61.7%。CCNet 在 snapshot 内的小 shard 组中删除高频段落，约去除 70% 段落，多为导航与页眉。两步合计过滤 84.2%，从 175.1TB 降到 27.7TB。该段落去重是局部分组，不等于全局文档去重。

质量过滤采用 Gopher 全部规则加 C4 NoPunc，而非完整 C4。消融显示 C4 NoPunc 单独优于 C4 All 和 Gopher All，二者组合最好。Gopher 标记 15.23%、NoPunc 标记 22.73% UTF-8 字符，命中可能重叠，不能简单相加。KenLM 的 Wikipedia 相似度把文档分为高 21.9%、中 28.5%、低 49.6%；启发式过滤没有改变这些比例，说明两类信号近似正交。

## 4. 内容、PII 与规模权衡

团队在 Jigsaw Toxic Comments 上训练 hate 与 NSFW 两个 FastText 分类器, 对 BlingFire 切分的句子评分. 高阈值 `τ=0.4` 删除 5.5–7.3%, 低阈值 `τ=0.0004` 删除 29.1–34.9%; 低阈值总体下游表现更好, 但 v1.6 为满足最低 token 规模选择了更宽松的高阈值. 质量, 内容和去重过滤的删除集合重叠很少, 串联后压缩效应很强. 这个阈值是在下游表现与最低语料规模之间做出的取舍.

作者还强调 toxicity 与 quality 都带价值判断。毒性定义随任务、整理者身份和标注者信念变化，检测器也可能歧视边缘群体。公开阈值和删除比例，使外界能研究这些偏差。

PII 过滤聚焦邮箱、IP 和电话号码。每篇不超过五个 PII span 时用特殊 token 替换，影响 0.02% 文档；超过五个则删除整篇，影响 0.001%。模型式检测器在该规模成本过高，因此使用正则以准确率换速度。消融未见删除与替换的性能差异，符合受影响比例极小，但不表示隐私风险已完全解决。

## 5. 三阶段去重

Web 去重分三步。精确 URL 去重删除 53.2% 文档；精确文档去重在 URL 去重后再删除 14.9%，包括空文档；精确段落去重在 URL 去重后的文档中删除 18.7% 段落，包括空段落。URL 与文档去重先做，可减少后续昂贵处理；段落去重可能扰乱内容分析，所以最后执行。

去重提升 token 效率并减少记忆风险，但会改变来源分布。新闻、许可证和经典文本天然重复；粗暴去重可能让常见但重要文本代表不足。Bloom filter 误报也会删除未重复项。输入顺序决定保留副本：同一内容出现在高质量来源和网页时，先处理谁可能决定 provenance 与许可。复现必须固定 key、阈值、Bloom 参数和顺序。

## 6. 代码与社交数据需要不同配方

Dolma-Code 含 411B token，来自 2023 年 3 月的 The Stack。The Stack 已用 MinHash 与局部敏感哈希去重，并限定宽松许可仓库。Dolma 再过滤 JSON、CSV 等数据密集文件，组合 RedPajama v1 与 StarCoder 规则：删除重复许可证前导、过长行、数字为主和模板生成文件，筛掉低星仓库、注释比例异常和代码—文本比例低的 HTML。消融显示组合规则相对仅 RedPajama 规则降低代码困惑度并改善通用任务。

代码子集沿用网页 PII 处理，还以 `detect-secrets` 删除包含密钥或软件特有个人信息的文档。这里的误删成本与网页不同：测试 token、示例密钥和占位凭据可能被当真；而漏检真实密钥风险更高。规则版本、匹配类型和删除量应随数据发布。

Dolma-Social 论文正文一处称 80B token，首页表为 89B，分别可能对应版本/计数口径；复现应以最终表与 LaTeX 版本核对。数据来自 2005 年 12 月至 2023 年 3 月的 3.78 亿条 Pushshift 记录。作者比较原子内容、部分线程和完整线程三种线性化，消融显示把每条 submission/comment 当独立文档最好，推测线程组合引入的人为格式损害训练。

质量规则删除短于 500 字符的评论、短于 400 字符的 submission 和长于 40,000 字符的文档；净投票少于 3 的评论也被删除。删除/版主移除/18+ 文档及来自 26,123 个被封禁或 NSFW subreddit 的内容被排除。由于 Reddit 文档短，只要检测到 PII 就删整篇。文档级去重用于消除 copypasta。

投票作为质量信号带明显社会偏差：深层评论天然更少曝光，小众观点和晚发内容也可能低分；情绪化内容与低票的相关性并不等于低信息量。论文用下游消融支持最终选择，但公开数据用户仍应把这种选择视为平台治理与用户行为共同塑造的分布。

## 7. 其他来源和多源价值

C4 会重新经过除 URL 去重外的完整网页管线，进一步清理低质量、重复文本并遮蔽 PII。Semantic Scholar 使用约 4000 万篇开放获取论文组成的 peS2o，后者已针对语言模型完成清洗、过滤、去重和格式化，因此直接使用。Gutenberg 于 2023 年 4 月抓取，保留英语公版书并按书名精确去重。Wikipedia/Wikibooks 使用 2023 年 3 月 English 与 Simple dump，经 WikiExtractor 处理，删除不超过 25 个 Unicode word 的短页。

这些来源规模远小于 Common Crawl，却提供网页之外的代码、学术、书籍与百科分布。论文用 Paloma 的数百细粒度域比较 C4、英语 mC4、RedPajama v1、RefinedWeb、Pile 与 Dolma 上训练的 1.2B 模型。Pile 虽规模小但多源，因此领域拟合好；Dolma 与 RedPajama v1 同样覆盖更广；单一网页来源平均困惑度更高。这支持纳入非网页来源，而非证明某个固定比例永远最优。

## 8. OLMo-1B 验证应如何解读

团队训练 decoder-only OLMo-1B 做最终管线验证。论文称它相对最可比的 TinyLlama 平均更好，并在八项任务中的四项胜出；但 PDF 双栏抽取容易打乱表 2 列顺序，精确数字必须回到 `tables/1b.tex`。模型的训练 token 也不同：Pythia 少近十倍，StableLM2 在 2T token 上训练两个 epoch但未公开组成，只有 TinyLlama 较接近。

因此表 2 不能视为纯数据集因果比较。模型架构、训练 token、优化器和实现差异都会影响分数。数据选择主要依据控制架构与训练的 1.2B 消融，OLMo-1B 表格用于检查最终管线的端到端表现。论文也指出 1B 模型的 zero-shot 任务较难；这些模型虽超过随机水平，绝对分数仍不宜与大模型直接比较。

## 9. 开放发布、许可与治理

Dolma 数据集采用 ODC-BY，但顶层开放许可不会自动消除每个底层来源的权利差异。团队因诉讼避开 Books3，正说明可分发性是主动约束。GitHub 等来源应保留许可与标识，稳定 `source+id` 支持 provenance、blocklist 和删除请求。

网页规模下仍会漏掉 PII、毒性和版权风险。Datasheet、版本号和删除渠道必须与数据一起使用。研究者不能因“开放下载”就推断所有用途无风险。模型训练后，删除请求也难以从权重中撤销，这要求数据版本和模型 lineage 保持关联。

数据版本不能只写“Dolma”。论文对应 v1.6，Hugging Face 与仓库仍会更新。复现实验必须记录具体 revision、shard manifest、校验和、tokenizer、混合比例和 EOS/文档拼接规则。三万亿 token 是版本化统计，不是永恒属性。

## 10. 精确复现与验收

复现需要保存原始来源 snapshot 和对象 manifest；每个 tagger 的代码、模型、阈值与属性校验和；去重顺序、Bloom filter 参数和文件；Mixer 配置、来源权重、输出 manifest；训练 tokenizer 与 token 统计。远程 glob 若随时间增长，即使配置相同也会漂移，应先解析成不可变清单。

统计验收至少包括每阶段文档、字节、字符、token，按来源/语言分层的过滤率，规则交集，去重命中，PII 替换/删除，失败 shard 与输出校验和。论文中的 61.7%、84.2%、53.2%、14.9%、18.7% 等精确数字是审计锚点；复现明显偏离时，应先查 snapshot、规则版本和计数单位。

消融复现还要固定初始化、优化器、学习率、150B token 调度、batch、评测 prompt、split 和污染检测。只重做过滤但更换训练栈，无法把差异归因于数据决策。多个随机种子和置信区间能避免把小幅波动误当整理收益。

## 11. 论文自身的限制与贡献

Dolma 最重要的贡献是把数据从模型论文中的一句概括展开为可批评的决策：为何只做英语，为何混合六类来源，为何采用 Gopher+C4 NoPunc，为何更严格 toxicity 表现更好却未用于 v1.6，为何用正则处理 PII，以及为何发布 Toolkit。

限制同样清楚：小模型消融不保证尺度外推；Bloom filter 有误报；toxicity/quality 带价值判断；PII 过滤不完备；法律与伦理会改变配方；规模目标迫使团队接受性能并非最优的阈值。Paloma 的领域拟合说明多源有价值，但不证明最终混合比例最优。

Dolma 是带有明确策展政策、已知误差和版本边界的数据产品。“已清洗”只表示执行了对应版本的过滤与去重流程，并不保证语料正确、无风险或适合所有用途。模型结果要与具体 Dolma revision、tokenizer、mixture 和训练预算绑定，后续研究才能验证和修改其中的取舍。

## 12. 从文本属性到最终训练样本

Dolma 的文档—属性分离设计值得单独强调。语言概率、毒性分数、重复区间和 PII 命中不直接覆盖源文本，而是作为与文档 shard 对齐的派生属性保存。Mixer 在构建具体版本时读取这些属性并应用阈值。这样，同一批昂贵分类结果可以支持多套配方，也能在发现阈值不当时重新生成数据，而不必重新跑全部模型。

代价是属性文件与文档文件必须逐行、逐序对应。它不是按 ID 做任意数据库 join；任何坏 JSON、漏行或排序变化都可能把后续属性错配给其他文档。生产复现必须核对每个 shard 的行数、首尾 ID、顺序摘要与校验和。稳定的 `source+id` 负责跨版本追溯，严格行对齐负责高吞吐读取，二者不能互相替代。

段落和句子属性又绑定字符 offset。若 tagger 后执行 Unicode 规范化、换行转换或清洗，offset 就会漂移。原文一旦进入属性计算阶段应视为不可变；最终删除/替换需要在原坐标上按确定顺序执行，并处理重叠区间。否则 PII span 或重复段落可能删错位置。

最终训练样本还会经历 tokenizer、文档拼接、EOS 插入、序列切块和可能的 packing。论文的 LLaMA token 统计只描述一种 tokenizer 视角；若 OLMo 使用另一 tokenizer，真实训练 token 数和来源占比会变化。公开语料与公开训练配方必须在这里连接起来，否则“3T token”不能准确说明训练预算。

## 13. 过滤器叠加为何反直觉

单个过滤器删除比例不能预测组合后保留量。若两个过滤器高度重叠，第二个只增加少量删除；若近似正交，删除率会复合。Dolma 发现质量、内容与去重命中重叠较少，因此严格 toxicity 虽在单项消融中更好，却会使最终规模低于目标。这个观察是论文最有实践价值的结果之一。

完整统计需要同时报告每条规则的单独命中, 按管线顺序计算的增量命中和多规则交集. 单独一个「某规则删除 20%」无法推出最终语料规模. 过滤顺序还会改变计算成本: 先做便宜的 URL 和精确文档去重, 可以减少分类器需要处理的内容; 段落去重放在末尾, 避免内容分析前破坏文档.

叠加也会改变来源与群体分布。语言过滤、最短长度、投票、toxicity 和去重可能共同压低非标准英语、边缘群体语言或小型社区。整体下游准确率提升不能证明代表性没有受损。理想的数据报告应按语言变体、来源、时间和主要内容类别分层展示保留率。

## 14. 去污染不能等同于无污染

Toolkit 能以测试样本 seed Bloom filter，再对预训练文本查重。这可发现精确或配置定义的 n-gram 重叠，却不能发现释义、翻译、答案单独泄漏或同源材料。Bloom false positive 还可能把无关文本误标污染。论文选择可做污染分析的八项评测，是降低风险，而非数学证明测试从未出现。

公开 benchmark 长期在线，模型还可能通过其他数据集、论文表格、GitHub 评测脚本看到题目。更可靠的报告应列出匹配规则、阈值、命中数量与人工样本，并把有疑问任务单独呈现。训练数据开放使这种追踪成为可能，这正是 Dolma 相对闭源数据的科学价值。

## 15. 复现中的失败语义

数百 TB 管线不可能假设每个对象一次成功。下载中断、损坏 gzip、解析异常、分类器崩溃、临时盘不足与对象存储限流都会留下部分输出。若下游通过通配符扫描“现有文件”，半成品可能静默进入最终 mixture。稳健流程需要任务 manifest、临时输出、完成校验和与成功标记。

坏行也不能简单跳过，因为文档和属性严格对齐。一处跳过会让后续所有属性错位。更安全的做法是让整个 shard 失败，或在每个阶段共享同一 reject manifest 并重新生成对应属性。失败记录至少包含路径、行号、异常、原始对象哈希和处理版本。

重试必须幂等。纯 tagger 对固定输入通常可覆盖同一属性输出；共享 Bloom filter 的去重则受插入顺序影响，重跑一个 shard可能改变“首个副本”。因此去重的并行和恢复策略必须被固定并测试。不同进程数是否得到相同保留 ID 集合，应该用小型 fixture 回归验证，而非从“使用确定哈希”直接推断。

## 16. 许可、删除与模型 lineage

ODC-BY 规定 Dolma 数据集层面的许可和归因，但输入来源仍有各自条件。代码文件的许可证、论文的开放获取状态、公版书的司法辖区和网页版权并不相同。`metadata` 中保留来源标识，既服务研究追溯，也服务许可和删除请求。

删除请求需要跨层传播：原始文档、属性、最终 mixture、tokenized shard 和使用它的模型 checkpoint 都应有 lineage。已训练模型无法简单删除单条记忆，但至少应披露哪些版本受影响、后续版本如何处理。若稳定 ID 在新数据版本中改变，blocklist 就无法可靠执行，因此跨版本 ID 稳定是治理能力，不只是工程便利。

PII 正则的高精度目标意味着必然存在召回缺口。邮箱、IP、电话之外还有地址、用户名、身份证号和上下文可识别信息。数据开放会把风险扩散给所有下载者，所以使用者仍需按应用风险增加二次过滤，不能把 Dolma 的基础处理视为合规认证。

## 17. 如何读论文中的精确数字

论文数字有不同分母：有的按原始字节，有的按文档，有的按段落或 UTF-8 字符，还有的按 tokenizer token。例如英语识别移除 61.7% 是字节口径；URL 去重 53.2% 是文档口径；Gopher 15.23% 和 NoPunc 22.73% 是字符口径；段落去重 18.7% 是 URL 去重后文档中的段落口径。把它们直接连乘会得到错误结论。

首页表的 Reddit token 为 89B，而正文标题附近写 80B，可能源自版本更新或四舍五入；这应列为论文内部口径差异，不能擅自选择一个并宣称另一个错误。类似地，总计 3,059B 是表中各来源的 LLaMA token 之和，“三万亿”是便于传播的近似称呼。

精确复现时，优先使用同一版本 LaTeX 表、Datasheet 和实际 shard manifest 交叉校验。PDF 双栏文本抽取会打乱表格列顺序，尤其表 2 模型名与数字。因此对照译稿应保留原表并以 LaTeX 源校对，不能按抽取顺序猜测列映射。

## 18. 综合评价

Dolma 的方法论贡献是把预训练数据视为实验对象，而非模型训练前不可见的耗材。它用消融连接整理决策与模型行为，用 Toolkit 连接论文与可执行流程，用 Datasheet 连接统计与风险。即使某些具体阈值未来会被替换，这种证据链仍可复用。

论文没有把最终配方描述为每项指标都最优：严格内容过滤表现更好，却因规模约束未采用；英语范围提高了与既有研究的可比性，同时牺牲语言多样性；正则 PII 处理可扩展，但覆盖并不完备；Bloom 去重速度快，也会产生误报。这些冲突说明最终配方是在质量、规模、代表性、隐私和成本之间取得的具体平衡。

后续研究还需在更多模型规模、训练长度、生成式任务和多语数据上复查这些结论，并同时报告质量、代表性、隐私、许可和成本。可重复实验所需的追溯范围包括数据版本、代码、属性、配置和运行统计。
