# OLMES 深度解析: 把评测配置变成可复现的实验对象

语言模型排行榜常把一个小数点后的差距解释成模型能力差距, 但分数同时受到模型、数据集、提示格式、上下文示例、答案计分方式、概率归一化和具体实现影响。只报告“某模型在 ARC-Challenge 上得到多少分”, 就像只报告实验结果却省掉仪器设置。论文在同一模型、同一任务上观察到显著波动, 既有研究也曾仅因格式与示例变化而得到差异很大的准确率。OLMES 因而把这些评测步骤固定下来, 让分数对应一套可复现的测量过程。

这项工作的价值尤其体现在基础模型上。指令模型通常理解“从 A、B、C、D 中选择”的交互约定, 较小或训练早期的基础模型却只接受过下一个 token 预测。直接要求它输出答案标签, 测到的可能是对人为格式的适应能力, 而非题目知识。反过来, 只使用为弱模型设计的完形计分, 又可能无法表达“以上皆非”等选择题语义。OLMES 没有用一个形式强行覆盖所有模型, 而是先拆解混杂因素, 再为不同能力阶段制定连贯规则。

## 评测分数为什么不是模型的固有属性

**一个分数背后有一条处理链.** 选择题看似只有“答对或答错”, 实际至少包含六步: 从数据集选取样本, 将字段拼成提示, 选择并排列 few-shot 示例, 将候选答案送入模型, 把 token 概率变成候选分数, 最后聚合为指标。任一步骤改变都可能改变预测。例如, 答案前是否有空格会改变分词; 选项是同行还是换行会改变局部上下文; 示例是否覆盖所有标签会影响标签先验; 对候选总似然还是平均 token 似然排序, 会改变长短答案间的偏置。

模型分数可以写成 $S(M,D,C)$, 其中 $M$ 是模型, $D$ 是数据集, $C$ 是完整配置。对齐 $C$ 之后, 两个模型的分数差才主要来自模型。旧论文若没有公开配置, 新模型在同名任务上的更高数字仍缺少可比基础。OLMES 汇集的 ARC-Challenge 结果恰好显示：同一模型在不同资料中的分数会变, 模型之间的相对差距也会随设置移动。“跨来源抄分比较”缺失了最基本的实验控制。 **内部一致不等于外部可复现.**

排行榜可以保证站内模型由同一套程序运行, 这解决了内部一致性, 却没有自动解决方法选择是否合理、配置是否足够公开以及其他团队能否复现。若排行榜没有说明为何使用某种归一化、示例来自哪里、任务采用 MCF 还是 CF, 研究者仍难以把结果迁移到训练流程或另一套工具。更严重的是, 模型论文经常引用排行榜数字, 同时用另一配置评测自己的模型, 最终把不可比的列放入同一张表。

OLMES 因此把“有文档”与“可复现”区分开来。代码公开只是起点, 标准还要固定数据版本、样本处理、提示字符串、示例身份和顺序、计分公式与实现边界。每个决定需要已有研究或消融实验支持。这样的标准允许独立实现得到相同结果, 也允许后续工作明确指出自己偏离了哪条规则及偏离原因。评测从隐含惯例变成有版本的研究对象。

## 两种任务形式与能力阶段的错位

**MCF 测标签选择, CF 测续写偏好.** 多项选择形式 MCF 将题目和全部选项一起展示, 要求模型预测 A、B、C、D 等答案标签。它与人类答题形式一致, 能自然处理“以上皆是”“以上皆非”和选项间相互指涉。对理解指令和标签约定的模型而言, 这是更忠实的任务表达。然而基础模型可能知道“地核主要由铁组成”, 却不稳定地把知识映射为单字符标签。此时错误混合了知识不足与接口不适配。

完形形式 CF 则把每个候选分别填入句子或答案位置, 计算候选 token 在给定上下文后的条件概率, 再选择得分最高者。它把问题改写为基础语言模型熟悉的续写任务, 对小模型及训练早期检查点更敏感。但 CF 并不等价于原始选择题: 候选彼此不可见, 模型无法利用选项集合的排除关系; 某些候选天然更常见或更短, 原始似然会偏向语言频率而非条件正确性; “以上皆非”被单独代入后甚至失去指称对象。

接口与模型能力之间存在阶段性错位。OLMES 根据实验为每项任务选择形式：较弱模型仍能产生有区分度的信号, 能够稳定遵循选择格式的模型则保留 MCF 更贴近原题的语义。这样既避免早期训练曲线因标签输出失败而长期贴近随机线, 也让成熟模型回到任务原本的作答方式。 **形式切换必须是预先规定的规则.**

如果研究者在看到结果后, 为每个模型挑选分数更高的形式, 就会引入选择偏差。一个模型可能擅长标签输出, 另一个模型可能受益于 CF 的词频结构; 各取最大值会使比较失去共同测量尺度。因此, 混合使用 MCF 与 CF 只有在选择规则与模型结果独立、对所有模型一致执行时才成立。OLMES 的任务级建议和公开配置承担了这一约束。

纵向与横向评测追求的东西并不相同。纵向评测需要连续的训练曲线, 横向评测希望成熟模型使用最贴近任务本义的接口。实际系统可以同时保存两条序列：固定 CF 用于训练诊断, 固定 MCF 表示最终任务表现, OLMES 主指标则承担预先声明的汇总口径。每个数字分别对应清楚且不能事后改写的测量对象。

## 提示、示例与概率归一化如何共同作用

**固定 five-shot 不只是固定数字.** “5-shot”并不足以复现评测。还必须知道具体是哪五个样本、来自哪个 split、顺序如何、是否覆盖全部答案标签、是否包含异常文本, 以及目标样本是否可能与示例重复。随机抽取会给每个运行引入额外方差, 对小型测试集尤其明显。OLMES 采用策划并公开的示例, 目的在于让不同模型看到完全相同的上下文, 同时避开依赖随机种子的隐性变化。

策划示例也会带来治理责任。示例不能按待测模型的表现挑选, 否则标准会过拟合参与选型的模型集合; 也不应包含测试答案泄漏或依赖特殊记忆线索。更稳妥的过程是先声明选择准则, 检查格式、标签覆盖与文本质量, 再冻结样例标识。未来新增模型不应触发重新选样; 若数据版本变化必须更新, 应发布新标准版本而不是悄然替换。

提示格式同样需要按字节级细节理解。冒号、换行、选项前缀、答案标签后的空格都可能进入不同 token 边界。对于生成式标签计分, 要明确读取首个非空 token 还是完整字符串, 大小写和附加解释如何处理。对于概率计分, 要明确上下文末尾与答案开头的连接方式。OLMES 将这些看似琐碎的选择纳入标准, 因为可复现性恰恰由这些“小细节”组成。 **归一化是在消除不同来源的先验偏置.**

CF 中直接比较候选序列的联合概率会偏爱短答案, 因为每乘一个小于一的 token 概率, 联合概率通常继续降低。按字符或 token 长度归一化可缓和长度效应, 但两者并不完全等价: token 长度受模型分词器影响, 字符长度相对跨模型稳定, 却未必对应语义信息量。若跨架构比较采用 token 平均, 同一文本因分词颗粒不同可能受到不同校正。

PMI 风格归一化试图消除候选本身的常见度。直观地说, 它比较“看到问题后候选有多可能”与“在无信息或通用上下文中候选有多可能”的比值。若候选“the United States”在语言中本来就很常见, 条件概率高并不全来自题目证据; 扣除其先验后, 分数更接近问题提供的增量信息。但校准上下文本身也是配置, 选错空提示或领域提示会引入新的偏差。

归一化方式要跟随任务。短标签几乎不受长度归一化影响；长短差异明显的自然短语若不校正, 容易形成系统偏置；候选先验差异突出时, PMI 往往更合适。OLMES 通过任务实验形成固定建议, 防止评测者为每个新模型试遍方法后只报告最高分。归一化由此成为测量定义中的一项协议参数。

## 实验设计与结果应该怎样解读

**十项任务覆盖广度, 十五个模型检验稳健性.** 论文选择十个常用多项选择任务, 覆盖科学问答、常识推理、事实知识和社会情境等类型, 包括 ARC-Easy、ARC-Challenge、BoolQ、CommonsenseQA、HellaSwag、MMLU、OpenBookQA、PIQA、SocialIQA 与 WinoGrande。MMLU 又包含多个学科。这个组合并不代表全部语言能力, 但它对应基础模型开发中最常见、成本可控且早期也能产生信号的一类评测。

模型集合覆盖约 1B 到 70B 参数, 包含 Pythia、OLMo、TinyLlama、StableLM、RPJ-INCITE、MPT、Falcon、Llama、Mistral 等不同家族。广泛选模有两层作用: 一是避免标准只适配某个模型族的分词器和训练习惯; 二是观察配置选择是否在弱模型、强模型间产生不同影响。若一种设置只让参与设计的单个模型获益, 它不适合作为公共标准。

解读结果时应关注三类量, 而非只看平均准确率。第一是重复运行和配置扰动下的方差, 它决定小差距是否可信。第二是模型排序稳定性, 因为排行榜的核心用途是比较; 即使平均分变化不大, 排序频繁翻转也说明协议不稳。第三是与模型规模或训练进度的单调关系, 若更成熟检查点反而因格式障碍持续退化, 指标可能没有测到预期能力。 **标准的结论边界.**

OLMES 对基础语言模型的多项选择评测给出强约束, 但不能自动推广到对话安全、长文本生成、代码执行、数学证明或检索增强系统。这些任务的输出空间和评分器不同, 还会引入解码参数、工具状态、判分模型和人工偏好等变量。正确的扩展方式是沿用 OLMES 的原则: 列出处理链, 对每个自由度做实验, 冻结有依据的配置, 公开资产并进行版本管理, 而不是直接复制某个选择题模板。

论文主要研究开放基础模型, 对现代推理模型、长思考输出和聊天模板覆盖有限。聊天模型使用什么 system prompt、是否强制短答案、怎样从解释中抽取答案, 都需要新增规范。数据污染还会独立影响结论：模型在训练中见过测试集时, 完全复现评测过程依然可能高估泛化能力。OLMES 解决协议可比性, 污染检测与聊天接口规范还要另行补齐。

## 从论文标准落地为评测治理

**配置应当成为版本化产物.** 工程落地时, 最好把每项任务写成可序列化配置, 包含数据集名称与 revision、split、样本过滤规则、提示模板、few-shot 样本 ID 与顺序、MCF 或 CF、归一化公式、分词与空格处理、最大长度、批处理策略、答案解析及指标实现。结果文件同时记录模型 revision、代码 commit、依赖版本和硬件相关设置。这样一个分数才带有足够的谱系信息。

版本号应区分错误修复与测量定义变化。修正不影响样本或得分的注释可以升补丁版本; 更换示例、模板或归一化会改变指标, 应升主版本并避免与旧分数混排。排行榜更新协议后, 应保留旧榜或重新运行全部模型, 不能只让新提交使用新规则。论文表格也应把标准版本写进列名或脚注, 防止“OLMES 分数”在多年后变成含义漂移的标签。

自动检查可以阻止大量静默偏差。例如对渲染后的提示做快照测试, 对每个模型检查标签 token 化, 校验 few-shot 与测试集不重叠, 统计截断样本, 比较两个独立实现的逐题预测, 并保存少量黄金样本的候选对数概率。只比较最终平均分不足以定位问题; 逐题产物允许发现某个实现遗漏前导空格、交换标签或使用错误 split。 **报告不确定性与偏离项.**

采用标准并不意味着禁止创新。研究者可以提出更好的提示或校准方法, 但应同时报告标准配置作为锚点, 再把新方法作为清楚标注的实验列。若受上下文窗口、许可证或计算资源限制而偏离, 应列出偏离项及可能影响。这样既保持跨工作可比性, 又不会让标准冻结研究。

对于接近的模型, 应报告任务级分数、样本数和置信区间, 必要时用配对 bootstrap 比较逐题预测。宏平均的一点提升可能集中于单个小任务, 也可能落在抽样噪声内。标准化消除了许多配置方差, 却不会消除有限测试集的统计不确定性。可信结论应同时满足配置一致、实现可审计和差异具有统计支持。 OLMES 把分数还原成一项带输入、程序、版本和误差范围的测量结果。模型开发团队可以据此解释跨阶段训练曲线, 排行榜维护者也有了协议治理框架。“谁更强”的比较由此对应到一套可复现实验, 其关键条件是公开、论证并冻结评测自由度。 **一套可执行的复现实验流程.**

复现者首先应冻结论文所用数据与模型 revision, 不要直接调用名称相同但已经更新的在线数据集。随后按照标准提供的样本 ID 重建 few-shot 集合, 对每个目标样本保存最终渲染文本。渲染文本比模板源码更重要, 因为模板引擎版本、换行处理和字段缺失策略都可能让相同模板产生不同字符串。抽取若干样本人工核对题干、选项顺序、答案位置与页内说明, 可以在大规模推理前发现字段映射错误。

第二步是分别验证 MCF 与 CF 的最小单元。MCF 要检查候选标签在目标分词器中是否为单 token, 前导空格是否改变 token ID, 以及计分采用标签首 token 还是标签完整序列。CF 要输出每个候选的原始对数似然、长度、归一化后分数与最终排序。若实现 PMI, 还要保存无条件或校准上下文下的分母项。逐项保存中间量虽增加少量存储, 却能让两个框架之间的差异定位到具体算式, 而不是停留在平均分不一致。

第三步才是全量运行与汇总。运行前锁定精度、最大序列长度和截断方向; 运行后统计被截断样本、解析失败样本与并列候选。对于确定性前向计分, 不应出现由采样温度带来的随机性。若不同硬件或算子导致极小浮点差异, 应比较候选分差是否接近零, 并报告可能翻转的题目数量。最终不仅核对总准确率, 还应核对每个任务和每道题的预测, 因为两个错误可能在汇总中相互抵消。 **对训练团队和排行榜的不同建议.**

训练团队可以把 OLMES 配置当作固定探针, 在等量 token 间隔保存检查点并运行同一批任务。由于提示与样例不变, 曲线中的跃迁更可能反映训练数据或优化过程, 而不是评测噪声。任务级曲线还能暴露数据混合变化: 科学问答上升而社会常识停滞, 比单一平均分更有诊断意义。团队若为了速度使用子集, 应固定子集并与完整集定期校准, 不能每次随机抽样后直接连接成曲线。

排行榜面对不同提交者和不断演进的模型, 因而要加强输入验证与公开审计。模型若需要自定义远程代码、特殊聊天模板或非标准 token, 应在结果旁明确标记, 避免把额外适配收益计入模型能力。排行榜还应公开失败日志和有效样本数；解析失败需要单独计数, 不能静默记错或丢弃。模型无法按标准形式运行时, 对应结果应记为缺失并说明原因, 临时换用其他配置会破坏横向可比性。

两种场景共同需要一个标准实现和至少一个独立交叉实现。标准实现保证社区共享锚点, 独立实现则能发现代码库自身的假设。只有当二者在渲染提示、候选分数和逐题预测上接近一致时, “复现”才不只是再次运行同一份代码。OLMES 的开放资产为这种交叉核验提供了基础, 后续维护者需要继续保存历史版本与测试向量。 **仍需继续研究的问题.**

首先是标准对模型能力变化的适应机制。随着基础模型更擅长遵循指令, CF 的诊断优势可能减弱; 但若简单地在某个参数规模切换 MCF, 同规模不同训练质量的模型仍会错配。更可靠的方案是设计与目标任务独立的接口能力测试, 预先判定模型是否能稳定输出标签, 然后依据公开阈值选择形式。阈值及测试集也必须冻结, 否则仍会出现事后选择。

其次是跨语言与跨分词器公平性。字符归一化在拉丁文字任务上便于跨模型比较, 到中文、日文或复合字符语言时, 字符与信息量关系会改变。标签字母对英语语料模型自然, 对其他文字体系也可能形成额外先验。多语言 OLMES 应重新研究候选标签、空格规则与长度单位, 不能把英文设置未经验证地视为语言无关。

最后是污染与动态基准。固定公开样例提高可复现性, 也让测试内容更容易进入后续训练语料。维护者可以在保持协议不变的前提下引入受控的新题集, 或采用私有测试和公开校准集相结合的方案, 同时记录题目版本与访问政策。动态内容依然需要公开出题流程、难度校准和评分程序。标准化回答“怎么测”,抗污染检查“这些题是否仍有效”,两项工作应同时存在。 **评测对象的形式化.** 把模型记作条件分布 $p_\theta(y|x)$，评测协议 $E$ 不只包含题目集合，还包含提示模板、示例、答案候选、概率归一化、解码参数、答案抽取与聚合函数。最终分数可写成 $S(\theta;E)$。同一权重在两个协议下得到不同分数，原因是函数输入已经变化。

因此模型比较要求尽量固定 $E$，协议研究则有意改变其中一个分量，测量敏感度。若同时更换模板、shot数和归一化，很难把差异归到某个设计。OLMES的核心价值正是把这些隐含选择变成可版本化对象，使结果能够被重复和解释。 **单题得分与任务得分.** 选择题单题通常记为 $z_i\in\{0,1\}$，任务准确率 $\hat p=n^{-1}\sum_i z_i$。若题目近似独立同分布，标准误可粗略写成 $\sqrt{\hat p(1-\hat p)/n}$。真实基准常按主题、来源或模板成簇，题目并不独立，简单二项式标准误会过小。 更稳妥的办法是在题目簇上bootstrap，或按原始数据分层重采样。若同一材料派生多道问题，必须让它们一起进入重采样单位。报告样本数而不说明相关结构，无法判断一两个百分点的差异是否稳定。 **模型间的配对比较.**

两个模型回答同一组题，误差具有配对结构。直接把两条准确率当独立比例会丢失信息。可统计A对B的四格表，重点看A对B错与A错B对的题数，并用McNemar检验或配对bootstrap估计差异区间。 配对分析还能定位能力变化。两模型都对的题反映共同上限，都错的题可能过难或有歧义，分歧题才决定排序。人工抽查分歧题比随机看全部样本更容易发现模板、解析或知识差异，但抽查结论仍需按预定类别汇总，不能只展示漂亮案例。 **多任务宏平均.** 设任务 $t$ 得分为 $s_t$，宏平均 $M=T^{-1}\sum_ts_t$ 给每项任务相同权重，不论题目数。微平均则按题目数加权。前者防止大型任务支配，后者更接近从合并题池随机抽一题的正确率。两者回答不同问题，没有天然唯一选择。

任务分数尺度也可能不同。准确率、F1和归一化分数直接平均，会把数值单位当成可交换效用。若必须形成综合分，应先规定归一化与权重，并同时给完整分项。模型排名对合理权重变化很敏感时，单一总分没有稳健优势。 **任务数量与重复计权.** 十个任务不一定代表十种独立能力。若多个基准都测常识选择或小学数学，它们在宏平均中重复强调同一能力；只有一个任务测长文本理解，该能力权重就较低。任务聚类与相关矩阵可以揭示这种重复。 构造能力簇后，可先在簇内平均，再在簇间平均。这样新增一个相似基准不会自动改变能力权重。簇划分包含价值判断，应在看模型排名前确定，并报告不同合理划分下的敏感性。 **排名方差.**

分数小幅波动可能导致相邻模型名次交换，尤其模型数量多、差距小时。排行榜只展示整数名次会夸大确定性。对每次题目bootstrap重新计算排名，可以得到模型位于前k名的概率和成对胜率。 若多个模型置信区间高度重叠，更诚实的表示是同一性能组，而非强行排出次序。模型选择还应考虑推理成本、安全和任务匹配，评测名次只是一维观察。OLMES减少协议噪声，却不会消除有限样本方差。 **提示模板是一项干预.**

模板决定模型如何理解任务、候选答案放在哪里以及输出何种格式。指令微调模型对system和assistant标记尤其敏感，基础模型则可能更适合自然续写。统一模板提高控制程度，却可能让某些模型偏离训练分布；各用原生模板更贴近部署，却把模板优化纳入比较。 两种设置可以并列：标准模板回答受控比较，原生模板回答最佳推荐用法。若只报告其中之一，需要明确研究问题。绝不能在测试集上为每个模型搜索大量模板再挑最高分，而不把搜索预算计入结果。 **模板搜索的多重比较.**

尝试 $K$ 个模板并选择最高分，即使模型真实能力不变，也会因随机波动获得乐观偏差。K越大，最大值偏差越高。可在开发集选模板、冻结后在测试集评估，或者报告所有模板分布和选择规则。 不同模型获得的搜索预算也要相同。为热门模型精调数十个模板、为其他模型只用默认模板，会制造不公平优势。模板鲁棒性本身值得报告：均值高且方差小的模型，比只在一个特殊措辞下达到峰值更可靠。 **Few-shot示例的抽样方差.** 固定five-shot控制了示例数量，却没有控制示例身份、顺序与标签分布。某些示例与测试题主题接近，会提供额外提示；标签顺序不均衡又可能诱发位置偏置。只使用一组示例会把偶然选择固化进基准。

可以预先生成多组平衡示例，对关键模型重复评测，报告均值和组间方差。正式标准为了成本可固定一组，但需证明它在候选组中不异常。示例不得来自测试题近重复，也不能包含测试答案模式的特殊泄漏。 **示例顺序效应.** 语言模型可能更重视最近示例，或延续最后一个标签。将相同five-shot排列打乱，分数和答案分布可能变化。顺序敏感反映模型的上下文学习稳定性，也构成评测不确定性来源。 标准可固定确定性顺序以保证复现，同时用若干排列做敏感性实验。若模型排序随顺序大幅改变，论文结论应报告这一边界。对比模型时使用同一顺序是最低要求，却不能证明该顺序对所有模型同样中性。 **标签置换与位置偏置.**

多项选择模型可能偏爱A、B等特定标签或候选位置。将选项内容随机置换，并同步更新正确标签，可测量这种偏置。若语义不变而准确率明显变化，原分数部分来自接口习惯，而非知识。 评测可对多个置换平均，代价是推理次数增加；也可固定平衡设计，让每个正确位置出现次数接近。答案抽取必须处理模型输出内容而非标签的情况，否则置换会与解析错误混合。 **MCF的打分单位.** 多项选择形式常计算每个候选标签或完整选项的条件似然，选择分数最高者。若候选长度不同，序列总对数概率偏向短答案，token平均又可能偏向由少数高概率token构成的长答案。标签化候选能减少长度差，却引入标签先验。

协议需要明确打分的是标签、选项文本还是包含模板的整段，以及是否除以token数。任何改动都会改变任务。OLMES强调规定形式，目的正是防止不同实现都声称运行同一基准，却实际计算不同量。 **CF续写的概率解释.** 续写形式把候选放到句子结尾，比较模型对候选文本的条件概率。它更贴近基础语言模型目标，但候选本身的词频会影响分数。常见答案即使与问题关系较弱，也可能有较高无条件概率。 归一化可用候选在空上下文或域上下文中的概率校正，近似移除先验。校正强弱取决于参考上下文选择；空字符串、通用提示和任务说明给出的基线不同。标准必须固定参考，并通过消融确认它改善的是任务关系而非另一个偏置。 **PMI式归一化.**

一种常见分数为 $\log p(y|x)-\log p(y|x_0)$，其中 $x_0$ 是内容中性的参考提示。它近似点互信息，奖励候选因问题上下文而获得的概率增量。若某标签无条件特别常见，第二项会抵消部分优势。 $x_0$ 并非真正中性：模板词、任务说明和语言都会改变候选分布。对指令模型，空上下文甚至落在训练分布之外。归一化是否有效要按任务和模型族验证，不能把公式当成普遍无偏估计。 **长度归一化的反例.** 候选A是一个token，候选B是三个token。总概率比较天然惩罚B，平均log概率又可能让B中两个容易token稀释一个关键低概率token。没有一种长度归一化在所有语义下正确。最稳妥的设计是让候选格式尽量对称，减少事后校正负担。

若原始任务候选长度不可控，应报告不同合理打分规则下的排名敏感性。结论只在某一种归一化成立时，其外推范围有限。评测标准的作用是提供共同口径，同时保留该口径不是唯一真值的意识。 **确定性解码与采样评测.** 选择题概率打分通常确定，生成任务则受温度、top-p、seed和最大长度影响。贪心解码方差低，测量单次最可能行为；采样更接近某些部署方式，却需多次运行估计期望。两者不能混合在同一排行榜而不说明。 采样评测要预先固定次数并报告样本均值与方差。best-of-n和pass@k利用额外推理预算，属于不同设置。模型通过更长输出提升分数时，还应报告token和截断率，避免把预算差异当作权重能力。 **停止字符串与截断.**

错误停止条件可能让模型在答案前结束，或继续生成无关内容导致抽取失败。最大token过小会截断长回答，过大则增加成本和后续矛盾。停止设置是协议的一部分，尤其聊天模板中结束token可能因模型而异。 评测应区分模型答错与基础设施截断。记录finish reason、生成长度和原始文本，可以定位问题。若为某模型修正停止token，应重新运行全部相关结果，并把配置版本绑定到提交。 **答案抽取的误差.** 生成文本可能包含推理、多个候选和最终答案。正则抽取器若取第一个标签，模型先讨论错误选项后纠正仍会被判错；取最后一个标签，又可能抓到结尾复述。抽取规则需要在人工标注子集上测精确率。

解析失败率应单独报告。把失败统一计错符合端到端使用，却会混合知识与格式能力。若研究主张是知识提升，还应给人工可恢复答案后的分数或格式控制结果。两种数字共同说明模型是否知道答案以及能否按接口交付。 **浮点精度与概率比较.** 候选概率非常接近时，模型精度、批次布局和后端实现可能改变排序。多数题差距足够大，但边界题会造成少量不确定。保存候选原始logits和分数差，可以识别近似平局。 对分数差低于数值容差的题，可标记为不稳定或用高精度重算。跨框架复现若只有极少边界题不同，不应立刻解释成模型行为差异。环境版本与推理精度仍需记录。 **任务版本漂移.**

公开数据集可能修正文案、标签和split。使用同一名称不保证题目相同。评测记录应包含数据版本、文件哈希、预处理提交与最终样本数，并对被过滤题给出原因。 版本更新后，新旧分数不能无条件拼接。可在共同题目子集上回算桥接，区分模型变化与数据修正。排行榜若静默替换数据，会让历史排名失去可比性。 **标签错误与争议题.** 基准可能有错误答案、多个合理选项或上下文不足。模型在这些题上与标签不一致，不必然表示能力不足。人工审计应优先检查强模型普遍答错、模型间高度分歧和置信度异常高的题。

发现问题后可保留原版以复现历史，同时发布修订版与变更清单。不能只删除让某个模型失分的题。修订规则需盲于模型身份，并重新计算所有模型，避免选择性修正。 **污染的不同层次.** 完整题目和答案进入训练是最直接污染；只见题目、同模板变体、解题解释或数据集说明影响逐渐不同。字符串去重能发现逐字泄漏，语义匹配扩展召回，也增加正常领域知识的误报。污染报告应按层级给出。 高匹配题得分更高仍可能因题目更常见、更容易。时间外新题、数值变体和结构保持改写提供更强对照。污染分析的目标是估计评测独立性，不是把模型接触过的所有相关知识都视为违规。 **开发集的选择偏差.**

团队反复查看开发任务并据此调整数据混合，即使训练样本不含评测题，最终配方也会适应该套能力权重。尝试次数越多，最佳开发分数的乐观偏差越大。保留未见任务能检查这种研发层面的过拟合。 未见集必须在配方冻结后运行。若结果不佳又回头修改，未见集就转化成新的开发集，需要另一层保留数据。记录实验数量和模型选择规则，能让读者判断选择偏差规模。 **Checkpoint选择偏差.** 在一条波动曲线上挑最高开发分检查点，会把随机峰值当作真实性能。预定训练步数、早停规则或滑动平均可以减少偏差。若比较多个checkpoint，应在独立选择集确定，再在测试集评一次。

选择综合分还隐含任务权重。某个checkpoint数学最好，另一个常识更稳，最终选择取决于产品目标。公开选择函数比宣称「最佳模型」更清楚，也让他人能按不同权重重选。 **多模型比较与赢家诅咒.** 同时评估许多模型后，最高分模型更可能受正向噪声影响。模型数越多，榜首乐观偏差越大。对领先差距给配对置信区间，并在新题上复评前几名，可以验证排序。 若研究主要比较预先指定的两种方法，不应因其他模型偶然高低改变主结论。探索性排行榜与验证性假设检验分开，有助于控制多重比较。显著性校正只是工具，预注册比较更直接。 **方差来源的分解.**

评测方差来自题目抽样、few-shot示例、提示措辞、解码采样、模型训练seed和评审器。一次实验通常只测到其中一部分。层级实验可先固定模型改变协议，再固定协议比较训练seed，估计各来源贡献。 若提示方差大于模型差异，继续精确排名意义有限，应先改进协议稳健性。若训练seed方差主导，论文需要多次训练而非只重复推理。方差分解决定预算投向何处。 **置信区间的解释.** 95%置信区间在重复抽样意义下覆盖真实参数，不表示真实分数有95%概率位于本次区间。对固定完整基准，有人认为题目并非随机样本；此时区间表达模型对潜在任务分布的泛化不确定性，需要说明抽样总体。

区间无法覆盖系统性偏差，如污染、错误标签和不合适模板。一个极窄区间也可能围绕错误测量中心。统计精度与测量效度必须分别检查。 **效应量与显著性.** 大样本能让极小差异显著，小样本则可能让实际重要差异不显著。报告百分点差、相对错误减少和每类题改善，比单独p值更有意义。相对错误减少在接近满分时会放大，需要与绝对差一起看。 部署意义还取决于成本。提升0.5点却把生成token翻倍，可能不值得；安全关键任务上的0.5点又可能很重要。评测论文提供统计事实，价值判断需绑定应用。 **缺失结果与选择性报告.**

模型可能因上下文长度、许可或接口失败无法完成某任务。将缺失项从平均中删除会改变任务权重，也让模型间综合分不可比。应报告缺失原因，并使用共同任务子集比较，或预先规定缺失惩罚。 只发布最有利提示、seed和任务同样形成选择性报告。配置注册表与完整运行产物能够暴露这些选择。失败运行不是噪声垃圾，它说明协议在某模型上是否可执行。 **评测缓存的正确使用.** 缓存模型输出与中间logits能降低重复成本，并允许抽取器更新后重算分数。缓存键必须包含模型哈希、模板、数据版本、解码参数和代码提交；遗漏任何一项都可能误用旧结果。

缓存也可能保存含许可限制或敏感内容的题目，访问控制需与数据源一致。公开复现可以发布哈希和汇总，而不一定发布原始内容。缓存服务于确定性和审计，不能成为绕过数据许可的副本。 **评测日志的最小单位.** 每道题应保存原始输入、渲染后提示、模型原始输出、候选分数、抽取答案、金标签和最终判定。任务级平均不足以诊断解析错误、模板异常和争议题。日志还要关联运行配置与环境。 完整逐题记录让配对检验、错误分类和未来规则修订成为可能。若出于许可不能公开，可发布匿名题目标识与分数，至少支持同一数据持有者复核。 **跨硬件与后端复现.**

确定性概率打分在不同推理后端上仍可能因算子精度、tokenizer或批次padding产生细微差异。生成任务还受随机数实现影响。复现报告需要说明硬件、精度、框架与关键库版本，并对少量样本比对logits。 追求逐位相同并非总有必要。预先设定数值容差和允许的题目差异，再检查总分与排序是否稳定。超出容差时先定位编码、模板和抽取，而不是把差异归因于模型随机性。 **评测标准的版本语义.** 协议版本应区分破坏性变化与修补。更换任务、模板或打分公式会改变分数语义，需要主版本；修正不影响结果的文档可用补丁版本。标签修复虽只涉及少数题，也应发布分数桥接。

模型结果绑定精确协议版本，排行榜才可长期维护。用户可以复现历史，也能选择最新修正版。把标准当成演化资产，比静态脚本更符合真实研究过程。 **标准化与模型原生能力.** 统一协议衡量模型在共同接口下的表现，模型原生配置衡量发布者推荐条件下的表现。前者利于科学比较，后者利于使用决策。二者差异本身揭示模型对提示和模板的依赖。 报告可以设标准结果为主表，原生结果为补充，或反过来，但标签必须清楚。若模型只能在高度定制提示下领先，其优势包含提示工程；若统一协议下稳定，则可移植性更强。 **反例：统一协议也可能不公平.**

某些模型以特定聊天模板训练，强行套用通用纯文本格式会破坏角色边界；基础模型使用聊天指令又可能落在未训练分布。形式上完全相同的输入，不代表功能上同等熟悉。公平不等于每个字节一致。 可通过小型开发集选择每类模型的预注册适配规则，如基础模型用续写形式、指令模型用聊天形式，再冻结到测试。规则按模型类别而非单个结果制定，减少逐模型调参，同时尊重接口差异。 **反例：高平均掩盖能力空洞.** 一个模型可能在八个相似常识任务领先，却在数学和安全任务严重落后，宏平均仍很高。另一个模型各项均衡，平均略低但更适合通用部署。总分无法表达最低能力要求。

可以报告能力雷达、最差簇得分和达到门槛的任务比例。部署选择常包含硬约束：某安全指标低于阈值便不可用。聚合分负责摘要，不能代替分项决策。 **反例：提示提升未必是能力提升.** 加入「逐步思考」可能提高数学分数，却增加输出长度和解析成功率；加入任务定义可能直接泄露标签语义。若提示优化只在当前基准有效，不能说明权重能力增强。控制token预算、使用新题和分析错误类型，才能区分。 同一模型的提示前后比较属于推理策略实验，与训练方法比较不同。论文可同时报告，但结论要分别落在权重、协议或计算预算上。OLMES的固定设置正是为减少这类混杂。 **反例：低方差也可能是饱和.**

任务过易时所有模型接近满分，分数方差很低，却没有区分力；任务过难时都接近随机，同样低方差。稳定不等于有效。题目难度应覆盖模型能力区间，并检查项目区分度。 随着模型进步，旧基准会饱和，需要新增更难题。更新时保留锚定题，建立新旧版本桥梁。完全替换会失去历史趋势，只保留旧题又会让排名由微小噪声决定。 **结论的证据等级.** 在固定协议下分数更高，支持该协议覆盖任务上的比较；多个模板、seed和任务簇一致，支持稳健性；时间外新题和污染控制支持独立泛化；真实用户任务与成本约束下仍领先，才更接近部署优势。每增加一层，主张范围才能扩大。

OLMES首先提供共同且可复现的测量坐标。它不能把有限基准变成完整智能定义，也不能消除数据污染和研发选择偏差。其贡献在于让这些变量显式化，研究者能够看见分数在哪里产生、为何变化，以及哪些结论仍需新的证据。

## 统计比较、评测治理与结论边界

**项目反应理论视角.** 同一道题对不同能力水平模型的区分力不同。项目反应理论可将答对概率写成能力参数与题目难度、区分度的函数，例如二参数逻辑模型 $P(z=1|a,b,\theta)=\sigma(a(\theta-b))$。难度 $b$ 决定曲线中心，区分度 $a$ 决定斜率。大量极易或极难题对当前模型排序贡献很小。 这种模型依赖单维潜在能力等假设，语言模型任务往往多维，不能机械套用一个能力值。它仍能帮助筛查低区分题和异常题，并构造覆盖不同难度的短版评测。删题前需要检查它是否代表独特能力，统计冗余不等于内容无价值。 **自适应评测的取舍.**

根据模型前面回答动态选择后续题，可以用更少样本估计能力。强模型收到更难题，弱模型收到基础题，推理成本显著降低。但不同模型看到不同题，逐题配对与公开复现更复杂，选题算法自身也可能偏向某类能力。 静态标准适合可比排行榜，自适应协议适合快速诊断。若采用自适应方式，应发布题库参数、选择规则、停止准则和能力估计不确定性，并用公共锚定题连接不同路径。不能把自适应能力值与原始准确率直接混在一起。 **子群体表现.** 任务平均可能掩盖语言、地区、年代、学科和题目形式差异。预先定义子群体后，分别给出得分与区间，可以发现模型只在高资源主题改善。子群体样本少时区间会宽，不能因方向符合预期便宣称稳定。

多子群体分析又引入多重比较。探索阶段可以完整展示，验证阶段应预注册重点组或校正显著性。最有价值的子群体由使用场景和数据来源决定，而不是在结果出来后寻找领先切片。 **最差组风险.** 通用平均优化允许模型牺牲小群体换取总体提升。若某些群体对应高风险领域，最差组准确率或条件风险更重要。它对小样本噪声敏感，可用置信下界或分层贝叶斯估计稳定判断。 模型选择时同时设平均与最差组门槛，可以避免综合分掩盖严重退化。OLMES提供统一运行条件后，分组标签和风险权重仍需领域方补充。评测标准负责可比性，价值权重来自应用。 **准确率之外的校准.**

概率打分任务能检查模型置信度。Brier分数 $N^{-1}\sum_i(p_i-z_i)^2$ 同时惩罚错误和过度自信，期望校准误差则比较置信分桶与实际正确率。两个准确率相同的模型，校准可能完全不同。 候选概率必须在统一打分协议下获得。生成模型自报「90%置信」与归一化候选概率不是同一量。温度缩放可在开发集校准，却需要独立测试验证。若每个任务单独拟合温度，额外参数和数据使用也应报告。 **选择性预测.** 允许模型在低置信题上拒答，可以画覆盖率—风险曲线。覆盖率下降时，已回答题的错误率是否同步下降，衡量模型能否识别自身不确定。单一拒答率无法区分合理谨慎与普遍退缩。

多项选择模型总会有最大概率候选，但概率间隔可作不确定信号。提示模型输出拒答选项会改变任务，需要独立协议。部署中选择性预测很重要，排行榜若强制全答则测不到这项能力。 **开放生成任务的评审.** 开放答案没有唯一字符串，常用规则、参考模型或人工评审。规则稳定但覆盖窄，语言模型评审覆盖广却存在位置、长度、家族和措辞偏差。评审协议必须固定提示、候选顺序、采样参数与模型版本，并用人工集校准。 成对评审比绝对打分更容易一致，却只能得到相对顺序；绝对量表便于跨运行比较，却需要每个分值有清晰锚点。两者都应随机化回答顺序，对交换前后结论不一致的样本单列。 **评审者一致度.**

人工或模型评审的原始同意率会受类别基率影响。Cohen's kappa等指标扣除偶然一致，仍依赖标签分布。对有序量表，可使用加权kappa或组内相关。指标只描述一致，不保证共同判断正确。 一致度低时，先检查任务定义与评分标准，而非简单增加多数投票。分歧可能集中在真正含糊的答案，保留分布比强行裁决更诚实。高风险结论应由专家规则或事实证据支持。 **LLM评审的自族偏差.** 评审模型可能偏爱与自身训练风格相近的回答，也可能识别特定模型常用措辞。用多个家族交叉评审、隐藏模型身份和控制长度，可以估计偏差。若排序随评审家族变化，综合排名不够稳健。

人工小样本用于校准，但人工也有风格偏好。最强证据来自多种评审方向一致、事实规则支持且分项错误减少。评审模型提供可扩展测量，不应被当成无噪声金标准。 **长度偏置的控制.** 开放评审常把更长答案视为更全面。长度匹配抽样、在提示中强调相关性，以及把事实正确、覆盖和简洁分开评分，可以降低偏置。回归分析也可估计控制长度后的模型效应。 控制长度不表示所有答案必须一样长。复杂问题合理需要更多文字。重点是检查领先是否完全由额外token解释，并报告质量随token预算的曲线。若优势只在两倍长度下出现，推理效率结论需要相应收窄。 **参考答案的局限.**

参考答案可能只展示一种正确路径，评审模型若要求语义接近，会惩罚新颖但正确的回答。多参考、关键事实列表和可执行验证能增加覆盖。参考本身也可能过时或错误，尤其知识更新任务。 评测维护应给参考答案版本和来源。发现新正确答案时，更新评分规则并回算历史模型，而不是只为当前模型人工加分。开放题的测量成本高，无法通过一条标准文本完全自动化。 **污染的时间分析.** 训练截止早于基准发布时间，能减少直接泄漏，却不能排除题目源材料早已公开。反过来，基准早于截止也不证明污染，数据管线未必收录。时间是证据之一，需要与文本匹配和数据清单结合。

按发布时间分桶比较模型表现，可以观察时间外泛化，但新题题型和难度也可能变化。使用同一出题流程持续生成题目，比跨年代拼接不同基准更能控制分布。结论仍需报告题目数量与区间。 **语义去污染的误报.** 语义检索会把同一知识点的正常训练材料标为近似，例如所有教材都解释勾股定理。若一律删除，模型被禁止学习评测所需知识。污染应关注实例级题目、答案与特殊结构泄漏，而非主题重合。 人工复核可区分完整题解、同模板不同数值、共享事实和仅主题相关。不同层级对分数偏差影响不同。报告阈值和样例让外部理解过滤强度，单个「已去污染」标签信息不足。 **基准数据的反向泄漏.**

基准公开后，题目会进入教程、模型卡、论坛和合成数据。后续模型即使原始数据过滤了基准仓库，也可能从这些衍生页面获得答案。来源追踪需要覆盖转载和解释，不只检查官方文件。 保留私有测试可缓解，却损失完全开放。动态题、定期轮换和公开旧版本形成折中。标准化评测体系需要承认基准寿命，并记录模型评测发生在泄漏周期的哪个阶段。 **污染敏感性报告.** 可按匹配阈值从严格到宽松构造多个清洁集，观察模型差距是否稳定。若结论只在某个任意阈值成立，证据较弱。还可对疑似污染题降权而非全部删除，给出分数范围。

清洁集题目变少后方差会增大，比较时必须更新置信区间。删除高频题也会改变任务难度和主题分布。污染控制不能只报告更低的新分数，还要说明新评测对象发生了什么变化。 **训练开发闭环中的泄漏.** 研究者看到某任务低分后，专门加入同类数据，即使没有直接使用测试题，也是在利用评测反馈。若目标是构建高性能系统，这种迭代合理；若目标是证明方法普遍有效，则需要未参与迭代的新任务。 实验日志应记录哪些评测用于数据决策、超参数和checkpoint选择。OLMES将开发套件与未见套件分开，就是控制人类研发者这一额外学习器。模型没有梯度接触测试集，并不代表整个研发过程没有适配它。 **预注册分析计划.**

在运行最终测试前写下主指标、聚合权重、排除规则、显著性方法和模型选择准则，能减少结果导向调整。探索性分析仍可进行，只需与预注册结论分开标记。开放仓库可以版本化保存计划及时间。 预注册不会自动让设计合理，也不能阻止数据污染。它主要限制分析自由度，使读者知道哪些假设事前提出。对成本高的大模型评测，预先明确规则还能避免反复调用造成隐性选择。 **多重假设校正.** 比较许多模型、任务和子群体时，按0.05阈值逐项检验会产生大量偶然显著。Bonferroni控制严格，Benjamini-Hochberg控制假发现率，层级模型则部分共享信息。选择哪种方法取决于验证性还是探索性目标。

更根本的办法是限定少量主比较，其他结果作为描述。排行榜通常强调效应量和区间，不必把每对模型都转成显著性星号。统计校正无法修复协议偏差和污染。 **贝叶斯比较.** 可以为每个模型任务正确率设先验，通过后验分布计算A优于B的概率，或差异超过实际重要阈值的概率。层级模型还能在任务间共享信息，稳定小样本估计。结果依赖先验与层级结构，需要敏感性分析。 贝叶斯概率更符合许多读者直觉，但仍不等于部署胜率。模型、任务与提示是固定还是来自总体，决定概率解释。无论频率学派或贝叶斯方法，清楚的抽样单位比公式选择更重要。 **等效检验.**

普通显著性检验未拒绝零差异，不能证明两模型等效。若关心新模型是否在通用能力上没有明显退化，可预设可接受界限 $\delta$，做等效或非劣检验。置信区间完全落在 $[-\delta,\delta]$ 内才支持等效。 $\delta$ 来自实际意义，不应按结果选择。对安全、数学和常识可以设不同界限。后训练论文常声称「保持基础能力」，非劣设计比看到平均分相近更匹配这一主张。 **缺失值的机制.** 接口失败、超长上下文、解析器崩溃和模型拒答都会造成缺失。完全随机缺失、与任务相关缺失和与模型能力相关缺失需要不同处理。直接删除往往假设过强。

端到端评测可将部署中会发生的失败计为错误，同时另报纯能力子集。若故障来自评测框架，则应修复重跑，而非惩罚模型。原始日志帮助区分两类，聚合表无法完成诊断。 **成本归一化.** 不同模型使用参数量、输出token和推理策略差异很大。固定题目准确率衡量质量，固定计算或固定价格下的准确率衡量效率。两者都值得报告，不能用成本归一化分数替代原始质量。 价格随服务和时间变化，硬件吞吐又依赖实现。较稳定的口径包括输入输出token、FLOPs近似和实测延迟，并附硬件环境。质量—成本帕累托前沿比任意线性加权更少依赖价值选择。 **延迟的分布.**

平均延迟会隐藏长尾。生成任务至少报告中位数、P90/P95和超时率，并区分首token延迟与完整响应时间。批处理和并发会改变结果，测量条件需与实际服务或研究目的对应。 评测框架性能不是模型能力，但超时和截断会影响最终分数。若某模型因后端慢而大量失败，应同时给理想离线分数和受限服务分数，分别回答能力与系统问题。 **能源与碳口径.** 若比较评测资源，GPU小时不足以跨硬件直接换算能耗。功率、利用率、数据中心效率和电力来源都会影响。没有可靠测量时，报告设备时间和token比给一个精确碳数字更诚实。 这类指标属于评测治理的扩展，不应挤压核心统计信息。其价值是提醒排行榜提升可能伴随巨大推理预算，模型选择需要综合考虑。

**安全基准的对抗适应.** 安全评测提示公开后，模型可以针对固定措辞学习拒答，面对语义等价改写仍失败。对抗变体、多轮诱导和时间更新集能检查稳健性。生成变体时要人工确认危害意图与难度保持。 拒答模板本身也可能被答案抽取器当作成功。安全评分需要区分是否拒绝、是否泄漏可操作细节、是否提供安全替代。单一关键词规则容易被格式适配利用。 **事实任务的时间戳.** 动态事实题必须标明问题截止时间与参考来源抓取时间。模型回答后来事实，在历史题上可能反而算错；模型给旧事实，在当前题上则过时。没有时间戳，标签无法稳定。

评测可冻结知识截面，也可定期更新当前事实，两者用途不同。冻结集适合复现，动态集适合部署监控。模型训练截止只是解释变量，不决定答案评分时间。 **多轮评测的状态.** 多轮任务中，后续问题依赖模型先前回答。若第一轮错误，后面输入包含错误历史，得分下降可能反映误差传播。教师强制使用参考历史则隔离每轮能力，却不代表真实交互。 可同时报告自由运行与参考历史条件。前者测端到端稳定，后者定位单轮能力。对话截断、system消息和工具状态也需版本化，单轮协议不能直接外推到多轮代理。 **工具增强评测.**

允许搜索、代码执行或检索后，分数同时取决于模型、工具、调用预算和环境返回。工具失败可能降低结果，更多调用又带来额外计算。比较时需固定工具版本、权限、预算和时间，或明确测量整个系统。 闭卷分数与工具增强分数回答不同问题。工具使用后的提升可拆成会不会调用、能否读懂结果和能否正确整合。只看最终答案无法定位瓶颈，轨迹日志提供必要证据。 **污染与工具检索的区别.** 模型参数中记住测试答案属于评测污染，测试时从允许的公开工具检索答案属于系统能力的一部分，前提是协议明确允许。若搜索直接返回基准参考答案，任务又退化成复制，仍需过滤或设计新题。

工具评测最好使用事件后发布或动态生成问题，并屏蔽包含完整题解的页面。污染分析要覆盖参数数据与实时索引两条路径。两者都可能让分数失去预期含义，却需要不同控制。 **基准难度漂移.** 模型进步后，原本困难的任务会饱和，剩余错误集中在歧义和标签问题。此时继续用同一准确率排名，测量信噪比下降。新增题应保持能力定义，却提高组合深度或覆盖稀有情形。 新旧版本用锚定题连接，可估计难度尺度变化。若新题完全换领域，分数下降不能称为同一标准变难。版本说明应记录能力蓝图与题目生成过程。 **动态基准的复现.**

每次评测从题库抽取新题能降低过拟合，但复现者需要相同随机种子、生成器版本和题库快照。若题目由语言模型生成，还要保存提示、筛选与人工核验。只发布最终分数无法验证难度一致。 可在评测后公开使用过的批次，使历史结果可重算，同时保留下一批。动态性与开放性通过时间延迟协调。统计比较应考虑不同批次难度，可用公共锚定模型校准。 **基准治理与修改权限.** 谁能修改标签、任务权重和协议，会影响排行榜。治理应包含变更提案、公开讨论、版本发布和历史回算。紧急修复严重泄漏可以快速进行，但仍需记录前后差异。

模型开发者发现对自己不利的争议题时，存在利益冲突。盲审、独立维护者和统一申诉规则能提高可信度。标准化不只是一组脚本，也是一套稳定决策程序。 **结果的机器可读发布.** 除论文表格外，结果应包含运行配置、逐题输出哈希、任务分数、区间、成本和偏离标准的项目。机器可读格式便于重算聚合、发现缺失和比较版本。模型卡只引用一个总分会丢失这些上下文。 签名或内容哈希可以证明结果对应特定产物，但不能证明运行诚实。可重复脚本、公开日志抽样和第三方复核共同建立信任。自动排行榜应拒绝缺少协议版本的提交。 **标准偏离的披露.**

有时模型上下文太短、模板不兼容或许可证限制，无法完全遵守标准。偏离并不必然让结果无用，关键是逐项列出并避免与严格标准结果混排。可同时运行共同子集作为桥接。 把偏离藏在脚注会让数字看似可比。结果元数据应直接标记非标准运行，界面也用不同分组。研究者仍可分析原因，却不会误导用户把差异全部归于模型。 **最小复现与完整复现.** 最小复现选少量任务和模型，验证模板渲染、候选概率、答案抽取与聚合是否一致。它适合快速发现实现错误。完整复现再覆盖全部任务、模型与环境，并计算统计区间。

若最小样本逐题结果都无法对齐，扩大运行只会放大成本。先比较原始提示、token和logits，再比较最终分数。分层流程把复现失败定位到数据、编码、推理或评分。 **评测单元测试.** 模板测试检查特殊token与消息顺序，抽取测试覆盖多个答案、空输出和异常格式，指标测试使用手算小例，数据测试验证样本数与标签。单元测试不能证明评测有效，却能阻止实现错误悄悄改变结果。 每次协议升级都在固定小型模型和样例上回归。若结果变化，变更日志解释预期原因。测试资产与协议共同版本化，复现者才能判断差异来自代码还是模型。 **结论如何对应测量.**

若证据来自十项短任务，结论适合描述这些任务覆盖的知识与推理，不宜直接扩展到长上下文、代理或真实安全。若模型在统一five-shot下领先，只能说明该设置表现更好，无法推出所有提示下领先。 扩大结论需要新增对应评测：多轮、工具、动态事实、不同语言和用户盲评。标准化让当前证据更清楚，也让缺失证据更显眼。准确限定并不会削弱成果，反而使后续实验知道从哪里继续。 **决策理论下的模型选择.**

模型选择可写成在应用分布上的期望损失最小化。不同错误的代价并不相同：普通常识答错、医疗建议答错和安全边界失守不能只按一题一分计数。评测任务提供各类风险估计，应用方再给损失权重，二者分开能避免排行榜替用户做价值选择。 权重本身也不确定。可以在一组合理权重上检查哪个模型长期占优，或画出权重变化时的最优区域。若模型选择对微小权重变化非常敏感，结论应呈现为条件决策，而非绝对冠军。统一协议保证输入可比，决策函数仍由实际场景确定。 **最小可检测差异.**

评测设计前可根据题量、基准正确率和配对相关性估计最小可检测差异。若现有样本只能稳定发现三个百分点变化，就不应围绕0.2点差异做强结论。增加题目、提高配对效率或聚焦高区分度项目，都能提升检验力。 事后看到不显著再宣称样本不足容易成为借口。预先做功效分析能指导预算，也能决定等效界限。大模型推理昂贵时，先估计所需题量比盲目跑完整套件更节省资源。 **序贯评测的停止规则.** 为了节省成本，研究者可能边评边看差异，达到显著便停止。普通固定样本p值在这种反复查看下会夸大证据。序贯概率比、alpha spending或预定检查点可以控制错误率。

排行榜日常比较不一定需要正式检验，但方法论文若因中途领先提前结束，应披露规则。反过来，持续加题直到结果有利同样构成选择偏差。评测预算和停止条件属于实验设计的一部分。 **Bootstrap的实现选择.** 非参数bootstrap从题目有放回抽样，重复计算模型差值，适合复杂聚合指标。若任务间先宏平均，应在任务内重采样后再聚合，或对任务与题目做层级bootstrap。直接从合并题池抽样会悄悄变成微平均。 重复派生题、共享文章和多轮对话需要以簇为单位。重采样次数决定蒙特卡洛误差，随机种子应保存。百分位区间简单，偏差校正区间在分布偏斜时更合适，但任何版本都无法修复非随机题库造成的外推偏差。 **置换检验.**

在零假设下，两个模型对同题的结果标签可交换。随机翻转每道题的模型归属，形成差值空分布，能在较少分布假设下检验配对差异。对连续评分也可交换成对分数，但需保证题目独立或按簇交换。 置换检验回答观察差异在交换假设下是否异常，不说明效应是否重要。与差值区间和错误类型结合，才能形成完整判断。多任务聚合时仍需预先固定权重。 **随机基线与机会水平.** 多项选择任务的随机准确率取决于候选数，任务含不同候选数时不能用统一25%。模型分数减机会水平或按可提升空间归一化，可辅助跨任务比较，但会在接近满分或候选数少时改变尺度。

机会校正也不能解决题目偏置。某些选项位置或词形可被浅层启发式利用，使实际无知识基线高于随机。训练一个仅看候选或仅看模板的基线，有助于发现数据捷径。标准中的高分只有超过这些合理基线才体现目标能力。 **基线模型的版本.** 论文常把新模型与若干开放基线比较。基线若使用旧checkpoint、非推荐模板或较小推理预算，差距会被放大。每个基线需要精确版本、权重来源和协议适配记录，不能只写模型系列名。 复跑基线与引用原论文数字也不同。复跑保证当前协议一致，引用数字反映原生设置。两种结果可以并列，主比较应优先同协议复跑。无法复跑时明确标为参考，不纳入严格排名。 **数据集许可与可验证复现.**

某些评测数据不允许公开重分发，第三方拿不到完全相同文件。维护者可以发布下载脚本、上游版本、校验哈希和转换步骤，让有权限者重建。只提交处理后样本数不足以确认内容一致。 许可还可能限制模型输出公开，因为输出包含题目文本。逐题日志可用题目标识、答案和哈希脱敏，同时由独立审计者在受控环境核对。可复现性需要尊重数据权利，不等于把所有内容上传仓库。 **API模型的版本漂移.** 商业API名称可能指向不断更新的后端。相同请求在不同日期得到不同答案，旧结果难以复现。评测应记录精确版本标识、日期、区域、参数和服务返回元数据；提供固定快照时优先使用固定版本。

版本不可固定时，可在短时间窗口重复运行锚定题，估计漂移。API更新后的结果作为新模型版本处理，不能覆盖旧表格。否则排行榜变化无法区分评测协议、服务更新和随机采样。 **量化与推理实现.** 模型权重相同，FP16、BF16、INT8或更低精度推理可能改变候选概率和生成质量。量化属于部署配置，严格模型能力比较应统一或分别标记。若某模型只能以特定量化运行，结果衡量的是该发布形态。 张量并行、注意力内核和KV缓存通常只影响性能，但数值顺序也可能改变边界题。抽样对齐原始logits与最终答案，可以确认实现差异是否可忽略。任何发现都应绑定运行环境，而非笼统归给权重。 **污染与记忆的行为测试.**

文本匹配找到疑似重合后，可对题目做数值替换、实体替换、选项重排和解释追问。模型若只在原题正确，变体大幅下降，记忆解释增强；若规则保持后仍正确，更支持能力迁移。变体必须经过人工确认，避免无意改变难度或答案唯一性。 还可以比较模型对正确答案的概率间隔。污染题上异常高置信、极短响应和特定措辞复现形成更强线索。任何单个行为都非决定证据，多种信号一致才适合调整结论。 **训练数据未知时的边界.** 闭源或未发布数据的模型无法完成直接污染审计。研究者只能用文本搜索、时间信息、成员推断和行为变体提供间接证据。不能因为未发现重合就宣称清洁，也不能因一次相似就认定泄漏。

公平比较可同时给全部模型完整集结果，再对数据透明模型补充清洁集分析。透明模型不应因可发现问题而在排行榜上受到不对称惩罚；更合理的做法是把数据可审计性本身作为独立维度。 **开放评测的博弈效应.** 标准一旦成为模型选择目标，开发者会针对它优化，指标与真实能力的相关性逐渐下降。这是Goodhart效应的具体表现。轮换保留任务、限制最终集查询和新增分布外题，可以延长标准寿命。 但完全隐藏会削弱复现与错误发现。公开开发集承担社区调试，受控测试集承担选择验证，定期释放旧测试集支持审计，形成循环。治理需要在透明与抗过拟合间动态平衡。 **报告负结果.**

协议变化对某些模型无影响、归一化让某些任务下降、提示敏感性高于预期，这些结果说明标准边界。只报告平均改善会让后来者重复无效实验。负结果应包含预算、实现和置信区间，避免把低功效误作无效。 若结论在模型族间异质，报告交互而非强求统一方向。评测标准追求跨模型稳健，但发现没有单一最佳设置同样重要，它可能支持按模型类别预注册不同形式。 **复现失败的诊断树.** 逐题差异出现时，先核对数据哈希和样本顺序，再比较渲染提示与token，随后比较候选logits、生成文本、抽取答案和聚合。最早分叉位置通常指向原因。只比较最终总分会让多个错误互相抵消。

若logits一致而分数不同，问题在抽取或指标；token已不同，检查模板与tokenizer；提示一致而logits偏离，检查权重、精度和后端。诊断树把复现从猜测变成可定位过程。 **评测协议的单一来源.** 配置、论文表格和排行榜若分别手工维护，容易发生字段不一致。可执行配置作为单一来源，自动生成运行清单与表格元数据。论文仍负责解释设计，数字则关联到具体运行产物。 这种工程安排服务统计语义：任何分数都能回到数据、模板、解码和指标。变更配置会产生新版本，不会静默覆盖历史。可追踪性使标准真正成为公共实验接口。 **OLMES与训练反馈的距离.**

训练团队会用OLMES开发任务挑数据和checkpoint，分数因此成为间接优化信号。随着迭代，开发集上的提升越来越可能包含专门适配。未见套件用于估计这种距离，但只使用一次后也会进入团队认知。 长期项目需要不断补充新任务，并保存每个评测首次被查看的时间。模型能力曲线与评测暴露历史一起记录，才能解释提升是广泛迁移还是研发闭环适配。评测系统自身也有生命周期。 **聚合分数的可逆性.** 发布分项和权重后，用户可以重建总分并按自身需求重新聚合。只发布总分不可逆，无法判断模型为何领先，也无法在任务修订后回算。机器可读结果应让聚合保持透明。

任务指标若经过非线性归一化，也需发布原始值和转换公式。任何裁剪、基线校正与缺失处理都会影响排序。可逆性是评测治理的基本要求，它限制后续解释对原始证据的扭曲。 **一份完整的比较陈述.** 严谨表述会同时包含模型版本、协议版本、任务范围、差值、区间、推理预算和已知偏离。例如「在OLMES某版本的十项任务、固定five-shot与指定归一化下，A相对B的宏平均差为若干点，配对区间为何；差异主要来自哪些任务」。这样的句子比「A更强」更长，却准确。 若污染敏感性、模板变化或多seed改变结论，也在相邻位置说明。结论范围随证据扩大，不靠修辞扩大。标准化评测的最终目的正是让一句性能声明拥有可追溯条件。

同样的记录也方便后来者检验新假设：可以重新按能力簇聚合，排除争议题，改变实际重要阈值，或在共同题目上加入新模型，而无需重新猜测旧实验的隐藏设置。只要逐题产物与协议版本仍在，评测结论就能随问题更新，同时保留与历史结果的连接。缺少这些中间材料，论文表格会逐渐变成无法解释的静态数字。 长期维护还应保留废弃配置及原因，让历史数字能够回到当时的测量条件。新协议提高了可靠性，也不应悄悄改写旧结果的语义；通过共同锚定题和版本桥接，研究者才能区分模型进步、数据修订与评分规则变化。 **参考文献.**
