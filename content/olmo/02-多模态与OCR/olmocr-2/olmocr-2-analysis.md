# olmOCR 2 技术解析：把文档识别变成可验证的单元测试

Allen Institute for AI 在 2025 年发布 olmOCR 2，模型仍以 Qwen2.5-VL-7B-Instruct 为视觉语言骨干，但训练目标从监督模仿扩展到带可验证奖励的强化学习。论文、模型、训练数据和推理代码都已公开。它要回答一个更贴近文档使用的问题：当同一页面允许多种等价 Markdown 表达时，怎样判断输出是否满足真正重要的约束，并把这种判断转成稳定的训练信号。

olmOCR 2 的答案由三部分闭合起来。第一部分是 olmOCR-Bench 的二元单元测试，每条测试只判断一个局部事实是否成立。第二部分是 HTML 合成流水线，它把真实页面的内容与版式重新渲染成可控页面，并自动派生大量测试。第三部分是 RLVR 训练，模型每次为同一页面生成一组候选，用测试通过率产生组内相对优势。最终模型在新版 olmOCR-Bench 上从第一版的 68.2 提高到 82.4，同时保留 7B 模型和开放推理栈的部署特点。

## 1. OCR 评分为何需要可执行约束

### 1.1. 字符距离混合了内容错误与表示差异

传统 OCR 指标常把输出与一条参考字符串对齐，再统计插入、删除和替换。这个做法适合行级纯文本，却不适合结构复杂的 PDF。图、表和图注是浮动元素，图注可以放在相关段落之前，也可以放在之后；只要正文阅读顺序没有被打断，两种 Markdown 都可能正确。字符串指标只能选一条参考顺序，因此会把合法的另一种顺序判成大幅移动。

公式尤其能暴露字符指标的局限. 两个 LaTeX 字符串可能差异很大, 渲染结果却等价; 也可能只差几个字符, 最终的上标、分式或括号结构已经错误. olmOCR-Bench 转而检查渲染后的 DOM 元素与相对位置, 直接比较读者看到的数学结构. 论文示例中, 编辑距离更大的候选通过了视觉结构测试, 编辑距离较小的候选反而失败. 字面距离无法稳定表示公式是否正确.

二元测试把一个含混的总距离拆成若干可解释命题：指定文字是否出现，页眉页脚是否消失，两段正文是否按顺序出现，表格中的一个单元格是否位于另一个单元格上方，公式渲染是否匹配，以及输出是否出现重复片段或异语字符。每条测试只有通过和失败，页面得分是通过比例。它不要求页面只有一种合法序列化形式，却能对关键错误给出明确惩罚。

### 1.2. 二元测试改变了误差权重

编辑距离让长文本天然拥有更大的权重。一个很长但次要的图注被移动，可能比短小却关键的表格数值错误贡献更多距离。单元测试由设计者决定检查什么，因此误差权重来自任务语义。若表格中的数值和相对位置重要，就为它们建立多条测试；若页码应删除，就建立文本不出现测试。页面上的像素面积和字符串长度不再替代业务优先级。

这种设计也有代价。测试没有覆盖的错误不会进入奖励，错误测试则会稳定地把模型推向错误方向。页面得分是离散测试的平均值，只有当候选输出跨过某条测试的判定边界时，奖励才变化。因此，测试数量、难度与覆盖范围决定了奖励分辨率。olmOCR 2 没有声称二元测试普遍优于所有连续指标，而是把二者的分歧列为后续研究方向：连续指标能提供更密的变化，二元测试则更容易表达等价答案和任务约束。

### 1.3. 从评测复用为奖励

可执行测试的关键价值在于同一套规则既能评测，也能训练。对于一个页面，模型输出 Markdown 后，评测器逐条执行测试，得到 $r_{test}=k/n$，其中 $n$ 是测试数，$k$ 是通过数。该分数有清晰范围 $[0,1]$，不需要另一个模型在线判断好坏，也无需人工为每个候选排序。

这类奖励属于可验证奖励强化学习，即 RLVR。数学题可以用最终答案或程序执行验证，代码可以用测试套件验证，文档 OCR 则可以用页面级结构测试验证。与偏好模型相比，验证器的判定更可复现，训练时也不会引入一个持续变化的奖励模型。难点从训练奖励模型转移到构造足够多且足够准确的测试，而这正是合成数据流水线要解决的问题。

## 2. HTML 合成页怎样提供规模化监督

### 2.1. 真实内容与可控渲染同时保留

人工编写 olmOCR-Bench 测试需要逐页阅读和核验，无法直接支持强化学习所需的数据规模。olmOCR 2 从真实 PDF 中抽取含公式、表格、多栏和页眉页脚的困难页面，再让通用 VLM 生成外观相近的语义化 HTML。真实页面提供内容分布和版式多样性，HTML 则提供可查询的结构真值。

生成过程分三轮。第一轮只分析版式，识别栏数、图片、表格、页眉和页脚等元素。第二轮结合版式分析与原图生成与页面尺寸一致的语义 HTML。第三轮把 HTML 渲染成图像，与原图并排交给 VLM，让它修正布局和内容。最终训练对由 HTML 渲染图和生成该图的 HTML 组成。输入图像和监督文本由同一份表示产生，二者在内部是一致的。

论文强调，这一反馈循环对通用 VLM 的 OCR 幻觉具有一定稳健性。若 VLM 把原页中的 `0.60` 抄成 `0.66`，渲染后的合成图里也会显示 `0.66`，从 HTML 派生的测试同样要求 `0.66`。该样本虽然没有忠实复刻原始页，却不会形成“图上是 A、标签要求 B”的矛盾监督。不过这种稳健性只保证合成图与测试一致，并不保证合成分布完全忠于真实文档；过多抄写错误仍会改变词汇与数值分布。

### 2.2. 语义 HTML 是测试生成接口

HTML 不只是方便渲染，它还是自动生成测试的结构接口。`<header>` 和 `<footer>` 中的文本可以转成“不应出现在 OCR 正文”的测试；正文节点能产生文字出现和阅读顺序测试；表格 DOM 提供行列和单元格相对位置；KaTeX 节点给出公式真值。相比直接从页面像素推断这些约束，HTML 把元素类别、层级和顺序显式编码出来。

最终合成集 olmOCR2-synthmix-1025 只有 2,186 个 PDF 页面，却派生出 30,381 条测试，平均每页约 13.9 条。样本单位仍是页面，奖励的细粒度来自一页上的多条约束。生成所用的 Claude Sonnet 4 每页成本约 0.12 美元，由论文给出的页数和单价相乘可得模型调用成本约为 262 美元，未计渲染、筛选和计算资源。这个数量级说明高质量合成并非免费，但远低于逐条人工标注数万测试的工时。

### 2.3. 监督微调数据先建立输出语言

RL 数据不是从通用 Qwen2.5-VL-7B-Instruct 直接起步。团队先更新监督微调集 olmOCR-mix-1025，它包含 267,962 页，来自超过 10 万份 PDF，其中 9,828 页来自国家档案馆。与早期的 olmOCR-mix-0225 相比，新数据改用 GPT-4.1 处理，统一块级和行内公式格式，表格改为 HTML，并为图片加入基本 alt 文本。

两套 SFT 数据在总分上几乎相同，旧集为 $78.5\pm1.1$，新集为 $78.3\pm1.2$。分项却发生了明显迁移：表格从 72.9 提高到 77.9，多栏从 77.3 提高到 81.3；arXiv 从 78.6 降到 70.8，长小字从 81.2 降到 78.7。这组结果很重要，因为它说明数据格式更新并非所有分布都单调改善。新集的价值还包括与后续合成页、HTML 表格和输出协议对齐，为 RL 阶段建立稳定的可采样策略。

## 3. GRPO 如何使用页面单元测试

### 3.1. 同页生成 28 个候选

强化学习从经过 olmOCR-mix-1025 微调的 Qwen2.5-VL-7B-Instruct 开始，在一台 8 张 H100 的节点上对 olmOCR2-synthmix-1025 训练一个 epoch。每个文档页面一次生成 28 个 completion。大量同题候选使训练器可以比较同一页面上的相对质量，避免把不同页面的固有难度混进优势估计。

GRPO 按组计算奖励中心和尺度。设同一页面候选奖励为 $r_1,\ldots,r_G$，组均值为 $\mu$，标准差为 $\sigma$，候选的相对优势可写成 $A_i=(r_i-\mu)/(\sigma+\epsilon)$。训练提高高于组均值的输出概率，降低低于组均值的输出概率。困难页面即使绝对得分低，只要某个候选相对更好，仍能贡献正向学习信号；容易页面若所有候选全对，组内没有差异，更新也会自然变弱。

论文给出 KL 系数 $\beta=0.01$，用于约束新策略不要过快偏离参考策略。这里的 KL 项与可验证奖励承担不同职责：测试奖励告诉模型哪些候选更符合页面约束，KL 约束限制为了追逐离散奖励而破坏已有语言和格式能力。一个 epoch 的短训练也减少了在小型合成集上过拟合的风险。

### 3.2. 奖励不仅有测试通过率

训练实际有三类奖励。第一类是页面单元测试通过率。第二类检查输出是否以 EOS token 结束，是一个二元奖励。第三类检查回复顶部的文档元数据，包括主要语言、旋转校正、表格和图示等字段，取值在 0 到 1 之间。官方训练代码把各项注册为独立 reward function，再由 TRL 的 `reward_weights` 加权合成。

实际训练运行的各项奖励权重没有公开. 代码默认值为 1.0, 只能说明未另行指定时的行为. 若三项等权, 总奖励理论范围是 $[0,3]$; 同一页面的 28 个候选通常都能正常结束并生成元数据时, EOS 与元数据奖励在组内近似常数, 测试通过率承担主要区分作用. 训练早期或困难页面更常出现残缺输出, 此时格式奖励可以阻止少数偶然命中的测试主导更新.

元数据奖励还有一个边界：它把合成过程中的 Claude 原始输出当作字段参照。合成图与 HTML 能保证正文测试的内部一致性，却不能自动纠正主要语言或页面类型判断。若这些字段最初判断错误，格式奖励会继承错误标签。因此“对幻觉稳健”不能扩展成“所有奖励都不受教师错误影响”。

### 3.3. 六个随机种子与模型汤

团队用六个随机种子重复 RL 训练，再对检查点做权重平均，即 model soup。三次训练采用 token 级重要性采样，三次采用序列级重要性采样。两种估计方式对长序列中策略比率的聚合不同，把它们纳入同一个权重平均，相当于把训练随机性和估计偏差一起做集成。

模型汤不增加推理时的模型数量。若六个模型参数分别为 $\theta_j$，最简单的平均是 $\bar{\theta}=\frac{1}{6}\sum_j\theta_j$，部署时只加载 $\bar{\theta}$。它成立的经验前提是各检查点从同一基座出发，位于可线性连接的相近参数区域。与输出投票相比，权重平均没有六倍推理成本；与只选单个最好种子相比，它降低了小数据 RL 对随机采样路径的敏感性。

## 4. 从训练到推理的工程改动

### 4.1. 动态温度处理重复循环

第一版 olmOCR 默认温度为 0.8。团队发现较低温度通常带来更好的 OCR 输出，但也更容易陷入重复循环。olmOCR 2 先以低温生成，若没有正常生成 EOS 或输出过长，则提高温度重试。这个策略把确定性和逃离重复的随机性放在不同尝试中，而不是对每一页一开始就使用高温。

论文将温度概括为从 0.1 逐步升到 0.8。固定版本代码中的实际表为 `[0.1, 0.1, 0.2, 0.3, 0.5, 0.8, 0.9, 1.0]`，默认最多尝试 8 次。重试条件包括 `finish_reason` 不是 `stop`，或总 token 超过 16,384。全部失败后，页面回退到 `pdftotext` 的文本层。这一差异不改变机制方向，却影响复现：实际实现重复使用一次 0.1，并允许温度升至 1.0。

动态温度在基准上把总分从 68.2 提高到 72.8，是开发序列中第一个显著增益。它也说明 OCR 系统质量不仅由权重决定，解码失败率会直接落到最终评测。低温本身不是无条件更好；只有配合结束检测、有限重试和明确回退，才成为可部署策略。

### 4.2. 提示顺序与缓存命中

团队还发现训练与推理提示中图像和文字顺序不一致。统一为文字在前后，总分从 72.8 提高到 75.8。反向顺序在单独实验中没有明显 OCR 差异，因此增益主要来自训练和推理协议对齐，而非“文字在前”具有固有识别优势。

固定文本放在前面还有服务系统上的好处：推理引擎更容易复用共同前缀的 prompt cache。图像内容每页不同，若图像排在固定说明之前，共享前缀会很短；把固定说明置前，可以让不同页面共享更长缓存。这项改动同时连接了模型分布对齐与吞吐优化。

### 4.3. YAML、图像尺寸与空白页

第一版输出 JSON，olmOCR 2 改为 YAML。JSON 要求引号和括号完整闭合，长文档生成中任何截断都可能使整体无法解析；YAML 的顶层元数据更容易增量生成，正文结束后可以直接输出 EOS。论文没有观察到基准分数变化，但重试率明显下降，因而提升了推理效率。

输入图像最长边从 1024 像素提高到 1288 像素。小字、上下标和细线表格需要更高空间分辨率，代价是视觉 token 与计算量增加。1288 是团队在分数和速度之间扫参后的折中，并非一个与模型无关的最佳尺寸。基座也从 Qwen2-VL 换成 Qwen2.5-VL，配合新训练器、避免权重衰减等超参数调整，这组改动把总分推到 78.5。

空白页暴露了另一类数据问题：旧数据加载器跳过所有空白页，模型从未学习过“没有正文”也是合法答案，推理时便会凭先验编造内容。修复加载器并重训没有改变基准总分，却修正了真实批处理中的高风险行为。基准若缺少空白页，这类修复不会反映在总分上，部署质量仍然会改善。

## 5. 实验结果应如何解释

### 5.1. 增益来自完整训练组合

开发表给出一条清晰路径：第一版 68.2，动态温度 72.8，提示对齐 75.8，新训练器、YAML、图像尺寸和 Qwen2.5-VL 合计达到 78.5，空白页修复后仍为 78.5，最后加入合成数据、RLVR 与模型汤达到 $82.4\pm1.1$。最后阶段相对前一阶段提高 3.9 分，相对第一版提高 14.2 分。

表格分项从最后一个 SFT 系统的 72.9 提高到 84.9，是 RL 阶段最突出的增益之一；arXiv 从 78.6 提到 83.0，多栏从 77.3 提到 83.7。旧扫描页只从 43.9 提到 47.7，仍是明显短板。基础类别达到 99.7，说明普通页面已接近饱和，继续提高总分更依赖困难扫描、复杂表格和版面。

最后一行同时加入合成数据、RLVR、六种子训练和权重平均, 论文没有逐项消融. 3.9 分对应的是完整组合, 表格无法分离 GRPO 与模型汤各自的边际贡献; 这需要额外的受控实验.

### 5.2. 基准与训练奖励共享测试体系

RL 奖励使用 olmOCR-Bench 兼容测试，最终评测也在最新版 olmOCR-Bench 上完成。训练页与基准页并非同一批页面，但奖励形式高度一致，这会让模型特别擅长测试体系显式表达的性质。阅读顺序、表格位置、公式渲染和页眉页脚因此获得直接优化；未被测试覆盖的视觉细节、语义忠实度或下游检索效果不一定同步增长。

这种一致性属于目标对齐，不等同于数据泄漏：训练优化的就是评测定义的能力。但评价模型泛化时，还需要不同标注体系、真实业务文档和人工检查。论文列出的其他 OCR 系统中，带星号的结果来自模型作者报告，其余由团队内部复现，推理配置和版本差异也会影响横向比较。

### 5.3. 方法适合什么场景

单元测试奖励最适合能把质量拆成局部、可执行约束的文档任务。表格、公式、页眉页脚、段落顺序都有明确判定器，且允许多种等价序列化形式。对于手写批注、图像语义、模糊印章或需要世界知识才能判断的内容，自动测试更难生成，仍可能需要连续视觉指标或人工偏好。

工程上还要评估训练成本与推理需求。RL 阶段需要每页 28 个候选、8 张 H100、六个随机种子，计算量显著高于一次 SFT。模型汤把额外成本留在训练端，部署仍是单个 7B 模型；动态温度在多数页面第一次成功时开销较小，在重复严重的页面上则可能触发多次推理。系统应记录每页尝试次数、回退比例和失败类型，而不能只看平均基准分。

## 6. 方法的可迁移经验

### 6.1. 先定义可接受答案集合

olmOCR 2 把真值从“一条字符串”改成“一组必须满足的性质”，这一设计比具体采用哪种模型更重要。当输出存在多种等价表示时，先定义可接受答案集合，再设计验证器，比强迫所有输出模仿单一参考更合理。代码生成、网页复刻、图表转结构化数据和科学公式识别都可以采用类似思路。

验证器必须逐项可诊断。页面总分下降时，应能知道是文字缺失、顺序错误、表格关系错误还是重复输出。这样的反馈既方便训练，也方便定位推理系统问题。若只把所有规则压成一个不可解释的相似度，模型改进和回归分析都会变慢。

### 6.2. 合成数据要建立自洽反馈循环

从 HTML 同时生成图像与测试，是减少教师抄写错误造成矛盾标签的关键。可迁移的原则是：尽量从同一潜在表示生成输入和可验证目标。例如程序任务可从可执行规格生成题目与测试，图表任务可从结构化数据生成图像与查询。反馈循环保证内部一致，却不能保证分布真实，因此仍需从真实样本采种、筛选版式，并用独立真实集评测。

合成流程也应保留来源和版本。olmOCR 2 给出所用模型、每页成本、页面数、测试数与代码链接，使复现者能检查提示、渲染和测试派生规则。对于奖励训练，数据生成代码与训练代码同样属于模型定义的一部分。

### 6.3. 把协议错误视为模型问题的一部分

提示顺序、输出格式、空白页过滤和解码重试都曾显著影响 olmOCR。这些细节共同决定模型在生产系统里实际接收的分布与产生的行为。训练和推理消息顺序必须一致，结构化输出要选择易完成和易解析的协议，数据加载器必须覆盖零内容样本，解码失败要有上限明确的恢复路径。

olmOCR 2 因而展示了一条完整路线：用监督数据教会模型文档输出语言，用语义 HTML 生成自洽页面和测试，用 GRPO 从同页多候选中学习局部约束，再通过权重平均与受控重试得到可部署模型。它的性能提升来自评测定义、数据生成、训练目标和推理协议的共同对齐。
