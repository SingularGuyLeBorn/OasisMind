# olmOCR: 用文档锚点把 PDF 页面线性化为训练文本

来源: Luca Soldaini 等, *olmOCR: Unlocking Trillions of Tokens in PDFs with Vision Language Models*, 2025. 对照译稿见同目录 `olmocr-bi.md`, 项目代码与模型见 [allenai/olmocr](https://github.com/allenai/olmocr). 本文讨论的是论文发布时的 olmOCR-7B-0225-preview 与 v0.1.75 管线; 论文中的数据统计, 评测与成本数字均按该版本解释.

## 1. PDF OCR 的目标不只是认字

### 1.1. 从页面绘制指令恢复逻辑序列

PDF 首先是一种固定页面的呈现格式. 它可以保存字形, 坐标, 字体与绘制顺序, 却不必保存「这是标题」「这两行属于同一段」「右栏应在左栏之后」之类的逻辑结构. 对原生数字 PDF, 直接抽内部字符常能得到大部分字面内容, 但字符流未必等于阅读顺序; 对扫描 PDF, 页面内部甚至没有可用文本层. 因此面向语言模型的数据处理需要同时完成三个任务: 识别页面上有什么, 恢复各元素的关系, 再把二维布局变成一维序列.

这一步通常称为线性化. 若页面是双栏论文, 一个逐坐标排序的解析器可能把左右两栏同行交错; 若页面含跨栏标题, 脚注和浮动表格, 仅按横纵坐标排序也无法恢复作者预期的阅读路径. 公式与表格还有额外困难: $x^i$ 与 $x_i$ 的字符集合几乎一样, 语义却不同; 表格里单元格值读对了, 行列关系错了, 下游问题仍无法回答. 所以输出质量不能只用字符召回率表示.

olmOCR 把目标定义为适合语言模型使用的干净纯文本: 正文按自然阅读顺序排列, 小节, 列表, 表格和公式尽量保留, 页眉页脚等重复模板则排除. 这不是页面的像素级复刻. 图片没有文字时, 系统不应自行添加图片说明; 版式本身若不承载语义, 也不要求在文本中复现. 这个目标决定了后续的数据生成提示, 训练输出格式和基准测试设计.

### 1.2. 流水线与端到端模型的取舍

传统文档流水线会分别做版面检测, 文本识别, 表格解析, 公式识别和阅读顺序恢复. 好处是每个模块可以单独替换, 错误也容易定位; 代价是接口多, 上游框错一个区域后, 下游模块看不到被裁掉的内容. 端到端 VLM 直接从页面图像生成文本, 可以用同一套参数联合判断字符与布局, 但也可能漏写高密度内容, 改写原句, 或依据常识补出页面不存在的文字.

olmOCR 没有在这两端中二选一. 它保留 VLM 作为最终生成器, 同时把 PDF 内部解析得到的文本块和位置送进提示. 页面图像提供布局与扫描内容, PDF 文本层提供精确字符线索, 生成模型负责决定阅读顺序和输出结构. 这是一种弱耦合组合: 内部文本层有噪声也可以当提示, 不必先变成完全正确的中间文档树.

## 2. document anchoring 怎样工作

### 2.1. 图像负责布局, 锚点负责字面内容

document anchoring 可以译作「文档锚点」. 系统先把 PDF 页渲染为图像, 再用 pypdf 从页面内部抽取文本块与位置. 这份抽取不保证阅读顺序, 还可能混有页眉, 页脚和渲染杂项, 因而不能直接当金标. 它的作用是给 VLM 一组可回到页面位置的字面线索. 当小字在 1024 像素图像上已经模糊时, 锚点仍可能保存正确字符; 当内部文本流顺序混乱时, 页面图像仍能帮助模型判断栏位和邻接关系.

提示长度有限, 系统不会无条件塞入全部内部文本. 论文的数据生成流程从长抽取中采样文本块, 直到达到输入上限, 并优先保留文档开头和结尾附近的文本块与图片. 这项策略照顾了标题, 页首开篇和页尾收束, 但中部高密度页面仍可能被截去部分锚点. 因而文档锚点不是完整转录, 更像给视觉识别加一条带坐标的候选字符通道.

Table 4 给出了它对不同模型的影响. GPT-4o 从无锚点的 68.9 升到 69.9, Gemini Flash 2 从 57.8 升到 63.8, olmOCR v0.1.75 从 74.7 升到 75.5. 提升并不恒定: GPT-4o 的老扫描数学分项从 75.5 变为 74.5, olmOCR 的表格分项从 71.4 变为 71.0. 因此锚点总体有益, 但不是每页必然改善. 若 PDF 文本层损坏或坐标错误, 模型还要在图像与锚点冲突时作判断.

### 2.2. 结构化输出约束生成行为

数据生成时, GPT-4o 按 JSON schema 返回结果. 模型先判断语言, 页面方向, 是否有表格等元数据, 再生成自然阅读顺序下的页面文本. 结构化输出有两项直接作用. 第一, 后处理不必从自由文本里猜正文边界; 第二, 明确字段能抑制模型在无文字图片上自行撰写说明. 后者很重要, 因为通用 VLM 往往把「描述图片」视为默认任务, 而 OCR 数据要求没有来源的文字保持缺失.

最终训练样本继续使用同一 JSON 输出, 让学生模型学习的不只是 Markdown 内容, 还包括页面级状态. 损失只计算回答 token, 图像 token 与锚点提示不作为预测目标. 设输入为页面图像 $I$ 与锚点 $A$, 输出为结构化文本 $Y$, 训练目标就是常规自回归条件似然:

$$
\mathcal L=-\sum_{t=1}^{|Y|}\log p_\theta(Y_t\mid I,A,Y_{<t}).
$$

这里的掩码使模型不会因复述提示而得分. 但它也意味着训练只惩罚最终序列与教师输出的差异, 教师漏掉或改写的内容会成为学生监督的一部分. 后续基准超过教师并不矛盾: 学生在 25.9 万页上蒸馏了教师的共同模式, 专用提示缩小了任务范围, 基准分布又与单个训练页面不同.

## 3. 监督数据与训练规模

### 3.1. olmOCR-mix-0225 的组成

论文 Table 1 的训练集包含 102,825 份文档, 258,641 页. 其中网页爬取 PDF 为 96,929 份, 240,940 页; Internet Archive 公有领域图书为 5,896 份, 17,701 页. 网页样本来自 2.4 亿份公开 PDF 的内部集合, 多为原生数字文档; Internet Archive 部分偏向图像扫描. 每份文档随机取最多三页, 目的是扩大文档多样性, 而不是从少量长文档重复抽页.

数据先用 Lingua 筛除非英文文档, 再去掉 pypdf 无法解析, 含垃圾关键词, 属于可填写表单或文本过短的文档. 按 707 页样本由 GPT-4o 分类得到的估计, 学术文档占 55.9%, 宣传册 11.2%, 法律文档 10.2%, 图书 6.8%, 表格页 5.6%, 图示页 4.7%, 幻灯片 1.9%, 其他 3.7%. 这是一份多类型数据, 但学术内容占比过半, 不能把它当作所有企业表单或多语言票据的均匀样本.

Table 1 还有一个统计矛盾. 若 Internet Archive 的 5,896 份文档每份最多取三页, 上限应是 17,688 页, 表中却是 17,701 页, 多 13 页. HF 数据卡给出过另一组数字: 5,601 份, 16,803 页, 恰好每份三页; LaTeX 源码注释中的旧表也是这组数. 论文没有解释更新统计为何超过上限. 复现时应以实际发布数据清单为准, 不应从正文这三个数字反推抽样程序.

### 3.2. GPT-4o 银标的能力边界

人工逐页重建阅读顺序和 LaTeX 成本很高, 项目改用 gpt-4o-2024-08-06 生成银标. 2024 年 10 月的候选比较中, Gemini 1.5 经常触发 `RECITATION` 错误, GPT-4o mini 幻觉较多, Claude Sonnet 3.5 成本过高, 最终选择 GPT-4o batch 模式. 这项选择是当时可用模型, 价格和稳定性的折中, 不是对所有后续模型的永久排序.

教师生成前加锚点, 是因为单独使用 GPT-4o 在密集页和复杂布局上仍会漏内容, 改写或补全文字, 还可能给图片添加未要求的说明. 训练集的质量上限因此由四部分共同决定: PDF 样本覆盖, 页面渲染清晰度, 锚点抽取, 教师生成. 任一部分出错都可能进入监督. 论文用基准和人工并排比较选择提示, 没有声称 258,641 页都是逐页人工验收的真值.

### 3.3. 7B 模型的训练配置复算

学生从 Qwen2-VL-7B-Instruct 开始微调. 图像最长边缩到 1024 像素, 文本提示限制为 6,000 字符. 一条典型样本约用 1,000 token 编码图像, 1,800 token 表示锚点, 总输入约 3,000 token; 整条样本截断到 8,192 token. 训练使用 AdamW, 学习率 $10^{-6}$, 余弦退火, 共 10,000 step, 硬件为单节点 8 张 80GB H100. 一次训练为 16 节点小时, 全部实验累计 365 节点小时.

正文称有效 batch size 为 4, 同时称 10,000 step 约为 1.2 epoch. 若全局 batch 真是 4, 训练只看过 40,000 页, 即 $40{,}000/258{,}641\approx0.15$ epoch, 两者不能同时成立. 官方训练配置是每卡 batch 1, 梯度累积 4, 启动脚本使用 8 卡 FSDP, 所以全局 batch 为 $1\times4\times8=32$. 10,000 step 对应 320,000 个样本, 即约 1.24 epoch, 与论文的 1.2 epoch 一致. 正文的 4 应理解为每卡累积后的 batch, 不是全局有效 batch.

8,192 token 截断还形成明确边界. 典型输入已占约 3,000 token, 留给 JSON 和正文约 5,000 token; 密集词典页, 长表格或大量公式页可能在输出末端被截断. Long Tiny Text 分项能测部分密集页能力, 却不能保证任意页面完整. 大规模处理时需要把截断, 重复生成和空输出作为可观测失败, 而不是只检查请求是否成功返回.

## 4. olmOCR-Bench 如何避开整页金标

### 4.1. 用局部不变量代替唯一参考文本

同一页面可以有多种合理线性化. Markdown 表和 HTML 表可能表达同一关系, 标题空行与列表符号也有不同合法写法. 若拿整页参考文本做精确匹配, 格式差异会被误判为内容错误; 用编辑距离或 ROUGE 又可能忽略公式上下标, 表格邻接和阅读顺序等小而关键的差异. olmOCR-Bench 改用通过或不通过的局部测试: 输出是否包含某段文字, 是否排除某个页眉, 两段文字次序是否正确, 指定表格单元格关系是否保留, 公式的符号空间关系是否匹配.

公式测试先用 KaTeX 在无头浏览器中渲染参考 LaTeX, 取得符号及视觉包围框, 再检查 OCR 文档中是否有相同符号和相对方位. 对 $f(x)=\int_{-3}^{3}x^2dx$, 测试会检查积分号, $x$, $dx$ 的左右关系以及上下限位置. 这种方法比字符串匹配更容忍等价排版, 又能区分上下标. 它仍不是数学等价判定: 两个代数等价但排版不同的公式可能无法匹配, 自定义宏也要先转换到 KaTeX 可渲染形式.

基准共有 7,010 个用例. 按能力分为文本存在 721, 文本缺失 823, 阅读顺序 1,061, 表格 1,020, 公式 3,385. 文档来源包括 arXiv 数学, 老扫描数学, 表格, 老扫描, 页眉页脚, 多栏和密集小字. 公式用例接近总数一半, 但最终得分不是对 7,010 条直接微平均, 因而公式数量不会按比例支配总分.

### 4.2. 宏平均改变了每类错误的权重

系统先在每个来源组内计算通过率, 再对七个来源和一个 Base 组取平均:

$$
S=\frac{1}{8}\sum_{g=1}^{8}S_g.
$$

Base 检查页面是否产出含字母数字的文本, 末尾是否出现超过 30 次的重复 N-gram, 以及是否发生异常语言或字符集切换. 它虽然不是一种文档来源, 在实现和 Table 4 中却作为第八组参与平均. 例如 anchored olmOCR 的八项为 74.9, 71.2, 71.0, 42.2, 94.5, 78.3, 73.3, 98.3, 算术平均为 75.46, 报告成 75.5.

宏平均让数量较少的来源与 2,927 条 arXiv 公式测试拥有相同权重, 适合强调能力覆盖, 但不代表真实流量中的平均页面成功率. Base 对多数系统都在 94 到 99 分, 固定占八分之一后会把总体成绩一起抬高并压缩差距. Qwen2-VL 的 Base 只有 55.5, 是明显例外. 使用者若更关心法律表格或历史扫描, 应直接看对应分项, 或按自己的文档比例重新加权.

### 4.3. 基准降低主观性, 没有消除采样偏差

用例由自动方法与人工审核共同构建. arXiv 公式从 TeX 源对回 PDF 页面; 老扫描数学公式由人工标注; 表格关系和密集小字候选由模型生成后人工核验; 历史文档借助美国国会图书馆的人工转写; 页眉页脚先由版面模型定位再读取; 多栏测试从连贯区域选取相邻片段. 训练集与基准做了 URL 级去重, 基准又在模型训练结束后才开发, 降低了直接针对测试集迭代的风险.

不过 URL 去重不能发现不同站点托管的同一文件, 局部测试也只覆盖被选中的性质. 一页通过两个阅读顺序用例, 不表示整页每个块都按正确顺序排列. 多栏用例还刻意避开公式和上下标, 所以它测的是较纯粹的栏内次序. 单元测试的优势是失败可解释, 不是对整页忠实度的完备证明.

## 5. 结果, 下游收益与成本

### 5.1. 75.5 分来自互补能力

Table 4 中 anchored olmOCR 总分 75.5, 无锚点版本 74.7, Mistral OCR API 72.0, Marker 70.1, anchored GPT-4o 69.9, Qwen2.5-VL 65.5. olmOCR 并非每列第一: Mistral 的 arXiv 数学为 77.2, GPT-4o 无锚点的老扫描数学为 75.5, 商用 Mistral 的 Base 为 99.4. olmOCR 的优势来自各项较均衡, 并在多栏分项达到 78.3, 老扫描分项达到 42.2.

论文用 10,000 次 bootstrap 给出 95% 置信区间, olmOCR 为 $75.5\pm1.0$, Mistral 为 $72.0\pm1.1$. 区间反映当前基准文档抽样的不确定性, 不覆盖新领域分布变化. 「超过教师 GPT-4o」应理解为这套提示, 输出约束和八组宏平均下的结果; 它不表示 7B 学生在通用视觉理解上超过 GPT-4o.

### 5.2. 同源 PDF 的 50B token 对照

OCR 输出最终要进入语言模型, 因而论文还做了下游对照. 两组都从 OLMo-2-1124-7B 的同一个中间检查点继续训练 50B token, 文档集合相同. 基线使用 peS2o 中由 Grobid 加规则得到的 58B 学术 token; 实验组取回同一批 S2ORC 源 PDF, 改用 olmOCR 处理. 控制源文档后, 差异主要来自线性化方式, 比拿两个不同语料库比较更有解释力.

六项平均从 53.9 升到 55.2, 增加 1.3 个百分点. 分项并非全升: MMLU 都是 61.1, ARCC 从 75.0 到 76.4, DROP 从 42.3 到 43.7, HellaSwag 从 57.4 到 62.6; NaturalQuestions 从 29.4 降到 29.1, WinoGrande 从 58.3 降到 58.0. 最大增量来自 HellaSwag, 所以不能把平均提升解释为每类能力一致改善. 该实验支持「更好的 PDF 线性化能改变预训练效果」, 但只覆盖学术 PDF, 一个 7B 检查点和 50B token 的继续训练.

### 5.3. 百万页成本怎样复算

Table 6 对 olmOCR 给出 L40S 上 906 token/s, 每美元 5,697 页, 每百万页 176 美元; H100 上 3,050 token/s, 每美元 5,632 页, 每百万页 178 美元. 论文在讨论 peS2o 时另用了每页约 1,000 个 token 的假设, L40S 单价为 0.79 美元/小时, H100 为 2.69 美元/小时, 并测得 12% 重试率. 表中页成本内部相符: $1{,}000{,}000/5697\approx175.5$ 美元. 但若把 L40S 的裸吞吐直接按每页 1,000 token 换算, $906\times3600/(0.79\times1000)\approx4{,}128$ 页/美元, 并不等于 5,697; 重试只会使页数更少. 因此 `tokens/sec` 与 `pages/USD` 使用的页面平均 token 量或计时边界并不相同, 不能混成一条算式.

成本排名依赖论文采用的云价和页面长度. 公式密集页可能输出少但视觉推理慢, 密集小字页可能接近上下文上限; GPU 利用率也会随批量, 图像尺寸和失败重试变化. Table 6 的结论是在给定后端与价格假设下, olmOCR 约为 GPT-4o batch 的三十五分之一成本, 不是固定报价.

正文另称按每页 1,000 token, 处理全部 peS2o PDF 的 H100 用量要 1,030 万美元, 这个数字无法由 Table 6 复算. 按 H100 的 3,050 token/s 和 2.69 美元/小时, 每 token 约 $2.45\times10^{-7}$ 美元; 58B token 约为 1.42 万美元, 与 1,030 万美元相差数百倍. 文中没有给出对应页数或额外成本项, 因而容量预算应使用 Table 6 的明确假设或实测吞吐, 不应采用这条孤立估算.

## 6. 工程使用时的检查项

olmOCR 的处理单元是页面, 文档级结果还要处理跨页关系. 页尾断句与下一页开头如何连接, 跨页表格是否合并, 重复页眉是否稳定删除, 都不是单页高分自动保证的. 在进入训练集前, 可以记录每页输出长度, 语言, 表格标志, 重试次数与结束原因, 再在文档层检查页序, 重复片段和异常长度跳变. 对 8,192 token 截断的页面尤其要保存失败状态, 避免把被截去的尾部误当成完整输出.

质量抽检应沿基准的五类不变量展开: 内容存在, 模板缺失, 阅读顺序, 表格邻接, 公式结构. 对自己的领域各建一小组可确定判定的测试, 往往比只抽几页主观阅读更容易发现版本回退. 同时保留页面图像, 锚点文本, 原始 JSON 与后处理文本, 才能区分错误来自渲染, PDF 内部解析, 模型生成还是清洗.

批处理调度还要区分可重试故障与确定性坏页. 网络超时, 推理后端退出和临时显存不足适合有限重试; 同一页连续产生重复 N-gram, 空正文或超长截断, 更可能是页面或模型层面的稳定失败. 若所有错误都无条件重试, 论文测得的 12% 重试率会在异常文档上放大成无界成本. 实际队列应以文档哈希和页码作为幂等键, 保存每次尝试的模型版本, 提示版本与结束原因, 达到次数上限后进入人工抽检或降级路径.

对 born-digital 页面, 还可以把锚点覆盖率作为诊断量: 统计内部抽取字符中有多少出现在最终文本, 并按页面区域观察缺失. 这个量不能直接充当质量分, 因为页眉页脚本来就应删除, 锚点顺序也可能错误; 它适合发现整段正文意外消失. 对纯扫描页, 锚点为空是正常情况, 此时应转而检查图像分辨率, 输出长度和语言识别. 把两类页面分开监控, 比用同一字符召回阈值更符合系统的输入差异.

数据治理也不能由公开可访问推导为可任意训练. 项目过滤了既含 PII 又不适合公开传播的文档, Internet Archive 部分限定为公有领域图书;实际部署仍需按来源保存许可, 获取时间和删除标记. 若文档不能发送到专有 API, 本地运行 7B 模型是 olmOCR 的直接价值之一, 但本地化只改变数据传输边界, 不替代授权与隐私审查.

**olmOCR 的关键组合是: 用页面图像判断二维结构, 用带位置的 PDF 文本作字符锚点, 用专用 7B VLM 生成一维文本, 再用局部可验证规则衡量输出.** 训练数据, 模型和推理管线的开放使这一组合可以落到百万页规模. 它的边界同样具体: 银标继承教师错误, 长页面受上下文限制, 单页基准不覆盖全部跨页结构, 成本依赖硬件与页面分布. 在这些边界内, 同源 PDF 的 50B token 对照给出了最直接的下游证据: 线性化不是数据预处理中的无关细节, 它会改变语言模型最终学到的内容.
