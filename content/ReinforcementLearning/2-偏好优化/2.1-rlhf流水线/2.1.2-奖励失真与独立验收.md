# RLHF 的奖励失真与独立验收

策略能够主动寻找奖励模型的高分区域，因此静态验证集上的排序准确率只是起点。随着 policy 分布离开标注数据，长度、格式、自信措辞与判别器漏洞都可能变成捷径。本篇沿着奖励模型误差怎样进入 advantage、怎样被在线优化放大，以及怎样用独立验证器和人工抽样识别失真展开。

## 6. Reward hacking 与独立验收

Reward model 是有限数据上的代理指标. Policy optimization 会主动寻找提高这个指标的方法, 包括标注者真正喜欢的改进, 也包括长度偏置, 固定高分短语, 格式漏洞, 过度拒答或 RM 分布外模式. 训练 reward 上升只说明 policy 更会获得当前评分器的分数. 应把 reward hacking 看作闭环中的分布问题. RM 在旧候选上训练, PPO 产生新候选, 新候选暴露 RM 盲区, 人类再标注这些边界样本并更新数据. 若缺少这条反馈链, 增加 PPO steps 只会给 policy 更多搜索评分器漏洞的机会.

### 6.1. 可见的作弊模式

若 chosen 回答普遍更长, RM 会把长度当质量, PPO 随后不断延长回答. 若安全数据里拒答常获胜, policy 可能对无害请求也套用拒答模板. 若数学回答的最终格式比推理正确性更容易判, 模型可能学会输出漂亮结构而不是正确过程. 监控至少应包括 RM reward, 回答长度, reference KL, policy entropy, PPO clip fraction, value explained variance, EOS 与 truncation 率, 以及不同任务上的分项 reward. 总 reward 上升而某个切片下降时, 聚合指标会隐藏真实退化.

### 6.2. 独立评估与 holdout judge

最终验收必须使用未参与 reward optimization 的数据和判定. 可以是独立人类评审, 冻结且来源不同的 judge, 可验证任务, 安全红队或事实检查. RM validation accuracy, training reward 与人类胜率回答三个不同问题, 不能互相替代. 评估要保存对照策略和盲化顺序. 只与很早的 SFT baseline 比较, 可能掩盖训练中后期退化. 按 prompt paired evaluation 能减少任务难度差异, 报告置信区间能防止小样本胜率被误读. 对长度和风格敏感的 judge 还要做位置互换与长度分桶.
数据回流与停止条件。 当独立评估发现新型失败, 可以把对应 prompt 与对照回答送回 preference collection, 更新 RM 或构造专门约束. 回流数据必须标明来自哪个 policy 与哪轮挖掘, 否则验证集会逐渐被训练过程污染. 新 RM 也会改变 reward 尺度, 需要重新校准 KL 系数与训练阈值.

停止训练的依据应同时包含外部质量, KL 漂移和优化诊断. Reward 继续上升但独立胜率停滞, 是停止或刷新 RM 的信号; KL 激增且 clip fraction 很高, 表示数据迅速过时; entropy 塌缩可能意味着探索不足. 最终策略需要在目标分布上通过独立验证, 并保留可追踪的数据与模型版本;单个 reward 最高的 checkpoint 无法提供这些保证.
一轮失败怎样回到数据。 假设监控发现 policy 回答长度从平均 300 token 升到 900 token, RM reward 上升 0.8, reference KL 只小幅增加, 独立人类胜率却下降. 第一步应按长度桶检查 RM 分数和 preference data, 而不是直接把 $\beta$ 调大. 如果 chosen 在训练数据中确实普遍更长, 说明 RM 利用了长度相关特征. 接着构造反事实 pair: 内容相同但删去重复段落, 长短不同但正确性相当, 以及长而空洞与短而完整的回答. 让标注者按明确 rubric 比较, 将这些 group 按 prompt 切分回流. 更新 RM 后, 先在原始 holdout 和长度对照集上确认排序改善, 再用固定 SFT policy 校准 reward 尺度.

从同一个 PPO 起点做小规模 A/B rollout,固定 prompt 与生成 token 预算,比较旧 RM 与新 RM 下的长度、reward、KL 和独立胜率. 新 RM 若只压低长度却损害复杂任务,还需检查 rubric 是否过度偏向简洁. 这一轮把现象、数据、评分器和 policy 实验连在一起,比在 policy loss 里临时添加长度惩罚更容易解释和维护. 每次回流都应保留原始失败样本和修复后的对照, 让后续版本重新接受同一组回归测试.
把一条样本从标注追到梯度。 前面的模块只有放进同一条数据链里, 才能看出 RLHF 为什么容易出现「每个局部都像是对的, 合在一起却不工作」. 假设 prompt $x$ 生成两个候选 $y_A,y_B$, 标注者选择 $y_A$. 偏好数据先形成记录
$$
(x,y_A,y_B,\text{producer},\text{decode config},\text{rubric},\text{annotator vote}).
$$
RM 训练只读取其中一部分字段来最小化 $-\log\sigma(r_A-r_B)$, 但其余字段不能因此丢掉. Producer 决定回答来自哪一段支持集; 解码参数影响长度与多样性; rubric 与投票记录决定这个硬标签有多确定. 如果同一个 pair 有 3 名标注者, 票数为 $2:1$, 把它与 $3:0$ 都编码成 label 1 会丢掉分歧信息. 一种直接做法是使用软目标 $q=2/3$, 损失写成
$$
\mathcal L_{mathrm{soft}}
=-q\log\sigma(\Delta)-(1-q)\log\sigma(-\Delta).
$$
它对分差的导数为 $\sigma(\Delta)-q$, 最优预测概率就是经验胜率 $q$. 两票对一票只记录了当前样本中的经验胜率, 不能当作真实偏好概率恰好为 $2/3$: 标注者并非独立同分布, 票数少时估计方差也很大. 软标签的价值在于保留这部分分歧信息, 而不是把少量投票包装成精确概率. 进入 rollout 后, 同一条 prompt 由版本为 $v$ 的策略采样出回答 $y=(y_1,\ldots,y_T)$. 系统至少要保存三个形状不同的量:

- `tokens` 与 `response_mask` 是 $[B,T]$;
- `old_logp`、`ref_logp`、token reward、value 与 advantage 也是按有效动作对齐的 $[B,T]$;
- RM 原始分数通常是 $[B]$,只在末尾有效回答位置散射到 $[B,T]$.

若第 $i$ 条回答有效长度为 $L_i$, mask 给出的 $L_i-1$ 才是最终 reward 位置. `T-1` 只是张量的固定尾部; 遇到左 padding、右 padding 或生成引擎提前补 EOS, 它可能指向 padding. 最小单测应让一个 batch 同时包含长度 2 与长度 5 的回答, 检查两个序列的 reward 总和都等于各自 RM 分数减去各自 KL 成本. 一个四 token 的端到端手算. 设回答有四个有效 token, rollout policy 与 reference 的逐 token log-ratio 为
$$
k=(0.20,-0.10,0.05,0.15),\qquad \beta_{KL}=0.1,\qquad R_{RM}=0.8.
$$
冻结 rollout 时刻的 shaping reward 得到
$$
r=(-0.02,0.01,-0.005,0.8-0.015)
=(-0.02,0.01,-0.005,0.785).
$$
总回报为 $0.77$, 与 $0.8-0.1\times0.30$ 一致. 再令 $\gamma=1,\lambda=1$, value 预测为 $(0.10,0.20,0.25,0.30)$, 终止后的 value 为 0. TD residual 是

$$
\delta=(0.08,0.06,0.045,0.485).
$$
从后向前累加可得 advantage

$$
\hat A=(0.67,0.59,0.53,0.485).
$$
第一项也可用 Monte Carlo return 检查: 从位置 1 起的总 reward 为 $0.77$, 减去 $V(s_1)=0.10$, 正好是 $0.67$. 如果实现结果不同, 应先查终局 reward、value shift 与 mask, 而不是立刻调学习率. 假设更新后四个 token 的 current-old log-prob difference 为 $(0.02,0.01,-0.03,0.00)$, ratio 分别约为 $(1.0202,1.0101,0.9704,1)$. 在这些 advantage 都为正且 $\epsilon=0.2$ 时尚未触发 clipping. 若第一项差值变成 $0.30$, ratio 约为 $1.35$, 该项的正优势目标被截到 $1.2\hat A_1$. **PPO ratio 使用 current 对 old, KL shaping 使用 rollout 对 reference**; 这两个差值恰好能在同一张表出现, 也最容易被变量名混掉. On-policy 不是「只更新一次」.

PPO 常把同一批 rollout 做多个 minibatch epoch, 所以严格说它使用的是短期复用的近似 on-policy 数据. 第一个 epoch 开始时 current 与 old 相同; 随更新进行, current 离 old 变远, importance ratio 才承担分布修正. Clip 会限制部分目标贡献, 却不能把已经过时的数据重新变成当前策略样本.

增加 epoch 能降低采样成本, 也会提高估计偏差. 一批回答里的动作只来自 $\pi_{old}$; 更新后的策略可能在相同 prompt 下生成完全不同的前缀, 那些前缀没有出现在 batch 中. Ratio 只能重加权已经观察到的动作, 无法为未采样轨迹创造 reward. 因此要同时看 sample reuse、current-old KL、clip fraction 与有效 token 数. 当大量正优势 token 被上界裁剪、负优势 token 被下界裁剪时, 继续扫同一批数据往往只让 critic 拟合得更深, policy 获得的新增信息很少.

不同并行 worker 还会制造版本滞后. Worker A 可能用 $v$ 生成, Trainer 已发布到 $v+2$ 才收到该 batch. 只要 old log-prob 与生成策略确实匹配, ratio 在数学上仍可计算, 但方差和 clipping 通常更大. 系统应记录 `policy_version` 并设置最大 lag, 不能用接收时的策略重新计算 old log-prob 后假装样本新鲜.
偏差、方差与数据复用代价。 RLHF 的总噪声不是一个「采样方差」能够概括. Prompt 抽样、token 采样、标注者分歧、RM 估计误差与 value 误差依次进入闭环. 增大 rollout 数可以降低给定 prompt 分布下的 Monte Carlo 方差, 却不会修复 RM 的系统偏差; 增加同一批数据的 PPO epoch 能复用 reward, 却不会增加新的环境信息.

RM 误差尤其危险, 因为优化会选择性放大它. 写成 $\hat r=r^*+\varepsilon$, 即使 $\varepsilon$ 在旧候选上的均值接近零, policy 也会主动搜索 $\varepsilon$ 为正的区域. 优化后的回答上, 条件期望 $\mathbb E[\varepsilon\mid y\sim\pi_\theta]$ 可以明显为正. 这就是普通验证误差很小, 训练后仍发生 reward hacking 的原因: 评测分布与被优化后的分布不同.

GAE 在 value bias 与 Monte Carlo variance 之间交换. 较小 $\lambda$ 更依赖 critic bootstrap, 方差低但会继承 value 偏差; $\lambda$ 接近 1 更接近完整回报, 对终局 RM 的噪声更敏感. Advantage whitening 能稳定尺度, 却会让一个 batch 中样本相互耦合: 加入一个极端高回报样本会改变其他所有样本的标准化优势. 小 batch 或按设备各自 whitening 时, 不同 rank 甚至优化不同尺度. 分布式实现要明确统计量是否跨 data-parallel group 汇总.

数据复用也分三层. SFT 样本可以跨 epoch 复用, 但会有记忆与域权重问题; preference pair 可以反复训练 RM, 但 margin 饱和后主要继续扩大置信度; rollout batch 只能在 old-policy 距离尚可控时短期复用. 把三者都叫「训练数据多跑几遍」会掩盖它们不同的统计含义.
版本化验收表。 一套能够复现的 RLHF 实验, 最少应固定下面这些边界:

| 边界 | 必须保存 | 不一致时会发生什么 |
| --- | --- | --- |
| SFT | checkpoint、tokenizer、chat template、loss mask | reference 与动作空间失配 |
| 偏好数据 | prompt/group id、候选来源、解码参数、rubric、投票 | 切分泄漏, 无法解释标签噪声 |
| RM | checkpoint、校准集、输出变换、截断长度 | reward 尺度漂移, 长回答被截断评价 |
| Rollout | policy version、old log-prob、seed、stop reason | ratio 分母错误, 截断与终止混淆 |
| PPO | KL 配方、$\beta$、$\gamma$、$\lambda$、clip、whitening 范围 | 同名指标对应不同目标 |
| 评测 | 固定 prompt、盲化规则、judge version、置信区间 | 训练信号污染最终结论 |

最终应能从任意一个异常 checkpoint 追到: 它看过哪些 prompt, 哪个策略生成了回答, 哪个 RM 给分, token reward 怎样组成, old/reference 各是谁, 哪些 minibatch 更新使用了这条轨迹. 这份血缘并不会让算法自动正确, 但没有它, 训练失败时只能靠猜. 还要单独验收训练与推理的聊天模板。训练时若在 assistant 起始标记后计算动作概率，部署时却由服务端自动多插入一个标记，模型看到的 prefix 已经不同；离线复算出的 KL、old log-prob 与线上真实采样都不再对应。工具调用场景还应把工具返回视为环境观测，而不是 policy 生成动作，对这些 token 计算 policy loss 会把不可控文本当成模型选择。

一次发布前的 smoke test 可以只用十几个固定 prompt，却要贯穿所有角色：用 rollout 引擎生成，训练框架重算 old log-prob，reference 重算 KL，RM 重算分数，再从保存的 token reward 复原 sequence return。两套引擎的 log-prob 不必逐位达到浮点完全相等，但差异应在预设容差内，并能解释量化、并行归约或 kernel 所带来的误差。若误差只集中在 EOS、特殊 token 或截断边界，应先停止大规模训练；这种分布通常指向动作定义不一致，随机数值噪声不会只挑这些边界出现。 RLHF 流水线的可靠性最终落在可复算性上：每个统计量都能沿版本与 token 边界重新得到相同结果。 这也解释了为什么小规模端到端演练比单独跑通各模块更重要：接口处的版本、顺序和 mask 错误，往往不会让程序报错，只会悄悄改掉优化目标。

### 6.3. 偏好数据与奖励模型校准

偏好标注不是天然真值。它由候选生成分布、展示顺序、标注者群体、rubric 和界面共同产生。奖励模型拟合的是这套观测过程；观测过程与部署目标不一致时，扩大数据只会更精确地学习偏差。 Bradley-Terry 的概率假设. 对同一提示 $x$ 的两个回答 $y_w,y_l$，Bradley-Terry 模型写成
$$
P(y_w\succ y_l\mid x)=
\sigma[r_\phi(x,y_w)-r_\phi(x,y_l)].
$$
它假设比较概率由一个标量效用差决定，并采用 logistic 噪声。若人类偏好具有循环，例如 A 胜 B、B 胜 C、C 又胜 A，单标量无法同时表示全部关系。训练会寻找加权折中，pairwise accuracy 上限低于一不一定是模型容量不足。 对 reward 加任意仅依赖提示的常数 $c(x)$，差值不变，因此绝对零点不可识别。缩放 reward 会改变预测置信度，交叉熵可通过噪声水平约束尺度，却仍受标签温度与正则影响。后续 PPO 使用绝对 reward 尺度时，必须重新校准或 whitening，不能把 RM logit 当成天然统一单位。 Tie、弃权与强度信息.

标注者可能认为两个回答相当，或无法判断。强迫二选一会把随机选择写成有方向标签，增加不可约噪声。tie 可用 Davidson 等扩展模型，或将一对拆成软标签 $0.5$；弃权则应作为缺失机制单独记录。 软标签 $q\in[0,1]$ 的 loss 为
$$
-q\log\sigma(\Delta r)
-(1-q)\log[1-\sigma(\Delta r)].
$$
偏好强度可映射到不同 $q$ 或样本权重，但二者含义不同：软标签改变最优概率，权重改变该比较对总体目标的重要性。界面中的“略好”“明显好”若标注一致性低，细分等级可能只增加噪声。 标注者混合与个体差异. 不同标注者可能有稳定价值差异。把所有标签混合训练单一 reward，学到的是按标注量加权的群体平均；标注多的人或外包组权重更大。若部署用户分布不同，平均偏好会偏移。 可用层级模型写 $r_{\phi,z}$，其中 $z$ 表示标注者群体或偏好维度。这样能分离共同质量与个体差异，也需要足够重复标注才能识别。只在每个样本上随机分配一位标注者，模型很难区分样本噪声和人群差异。

多数票压缩了分歧结构。三人以二比一选择 A，与三人一致选择 A 得到相同 hard label，却有不同置信度。保存原始投票、响应时间与弃权原因，能为 reward calibration 和主动复标提供信息。 标注者可靠度并非常数。某人擅长代码却不擅长医学，统一全局权重会误配。按领域估计混淆矩阵需要足够重叠样本与 gold questions；gold 本身若含争议，也会把专家少数意见误判为低质量。

标注指南更新会形成时间漂移。旧数据按旧 rubric 产生，新数据按新 rubric 产生，把二者直接混合等于训练不一致目标。可版本化 rubric、对一组桥接样本用两版重复标注，估计规则变化后再决定重标、降权或分头建模。

pair 展示中先读哪个回答、是否展开完整内容、代码能否运行、引用链接能否打开，都会改变判断信息。界面版本应成为数据字段。高响应速度可能表示 pair 容易，也可能表示标注者草率；需要结合一致性与 gold 表现解释。 奖励模型若面对多语言，翻译标注与母语标注不等价。机器翻译会抹平语气、错误和文化偏好。应保留原语言评估，并让部署语言分布进入采样权重；英文总体准确率不能代表低资源语言。 展示偏差与随机化.

回答位置、长度和格式会影响选择。若更强模型总在左侧，位置偏差会被 reward 当作内容信号。随机交换顺序并记录展示变量，可估计位置效应；同一 pair 双向展示能直接检查一致性，成本则翻倍。 候选由不同模型产生时，模型身份可能通过措辞或模板泄漏。标注者即使看不到名称，也可能识别风格。数据切分若随机按 pair，近似重复回答会跨 train/test，使泛化指标过高。应按 prompt、来源和时间去重切分。 长度偏差既可能是标注偏见，也可能反映任务真实需求。简单对 reward 做长度回归残差化会去掉两者。更可靠做法是构造长度匹配 pair、在同质量区间分析边际偏好，并由任务 rubric 明确何时简洁有价值。
Reward Model 的泛化与校准。 RM validation accuracy 只衡量给定 pair 的排序。RL policy 会主动寻找高分输出，把输入推向训练分布边缘；需要校准、分布外检测与对抗验证共同评估。 Pairwise Accuracy 的盲区. accuracy 不看置信度，也不看错误代价。一个模型所有 pair 都预测 $0.51$，可能 accuracy 很高却无法提供稳定 reward margin；另一个在关键安全 pair 上犯少数高置信错误，整体 accuracy 仍漂亮。 按偏好强度、任务类别、长度差和来源分层报告 accuracy，配合 log loss、Brier score 与 calibration curve，能观察概率质量。部署 PPO 实际使用 reward 数值，margin 分布比符号更直接影响 advantage。 随机 pair test 还可能过于容易。强弱模型差距大的候选能快速获得高准确率，真正决定 RL 方向的是相近策略输出之间的边界比较。保留 near-tie、同模型多采样和最新策略 hard set，能更接近训练中的决策区域。 Reward 的绝对校准.

BT 训练只约束差值，单回答 reward 的绝对水平需要锚点。可以固定 reference completion 的均值为零，或用一组质量等级明确的 anchor responses 拟合仿射尺度。anchor 必须跨版本保持稳定，才能比较不同 RM。 PPO 常对 batch reward whitening，使平移和整体正缩放影响减弱；KL coefficient、value target、reward clipping 和多来源奖励仍受尺度影响。若换 RM 后只看标准化 advantage，可能看不到原始 reward 分布已经漂移。 Ensemble 分歧的含义. 多个 RM 用不同初始化、数据 bootstrap 或模型结构训练，预测方差可提示 epistemic uncertainty。若它们共享相同偏见与数据缺口，ensemble 会一致地错；分歧低不等于真实可靠。 对 policy 候选，记录 mean reward、分歧、与训练数据距离。高均值高分歧样本适合人工复核，高均值低分歧但分布外样本也不能自动信任。对抗搜索应同时寻找高分和模型间一致性漏洞。

将 pessimistic reward 写为均值减 $k$ 倍标准差，可抑制高不确定输出，同时偏向熟悉保守区域。它改变优化目标并可能阻止真正创新答案。更好的闭环是把高不确定区域送去标注，更新 RM 后重新评估。 Policy-induced Distribution Shift. 初始 RM 数据来自 SFT 或若干基线模型，PPO 更新后输出分布逐渐变化。reward 提高可能来自真实质量，也可能来自进入 RM 外推区域。按训练轮次保留 policy 样本，画 reward 与人工胜率关系，可看到校准何时破裂。 数据回流若只标注 RM 高分样本，会产生选择偏差，低分但可能被误判的区域得不到纠正。混合随机样本、高分样本、高分歧样本与安全风险样本，才能同时估计总体表现和发现漏洞。
KL-Regularized RL 的最优策略。 RLHF 常优化 reward 减 reference KL。这个目标不只是一项工程惩罚，它有闭式的 policy-space 最优解，能解释 KL coefficient 的作用。 单提示上的变分解. 固定提示 $x$，对回答分布求解
$$
\max_\pi
\mathbb E_{y\sim\pi}[r(x,y)]
-\beta D_{KL}(\pi(\cdot\mid x)
\Vert\pi_{ref}(\cdot\mid x)).
$$
加入归一化乘子，对每个 $y$ 求导可得

$$
\pi^*(y\mid x)=
\frac{\pi_{ref}(y\mid x)
\exp(r(x,y)/\beta)}
{Z(x)},
$$
其中 $Z(x)=\mathbb E_{y\sim\pi_{ref}}\exp(r/\beta)$。最优策略是 reference 按指数 reward 重加权。$\beta$ 大时靠近 reference，$\beta$ 小时集中到高 reward 模式。 这个闭式解假设能在完整序列空间自由选择分布，神经自回归策略和有限 PPO 更新只能近似。reference 概率为零的序列在 forward KL 正则下仍不可获得，支持集由 reference 决定。 将最优解代回目标，可得最优值与 log-partition function 有关：

$$
J^*(x)=\beta\log
\mathbb E_{y\sim\pi_{ref}}
[\exp(r(x,y)/\beta)].
$$
它是 reward 的 soft maximum。$\beta$ 趋近零时接近支持集内最大值，$\beta$ 较大时接近 reference 下平均 reward 加小的方差修正。高 reward 尾部会被指数放大，这解释了 RM 极端误差为何危险。 有限候选集上可以精确计算这一定义，作为 PPO 与 DPO 类方法的玩具基准。给定 reference probabilities 和 reward，算出 $\pi^*$，再比较训练策略的 KL 与目标 gap。若小问题都无法靠近闭式解，应先检查 reward、KL 方向和优化符号。 reference 对高 reward 答案概率极低时，指数 reward 与 reference 质量竞争。增大 reward 或减小 $\beta$ 能克服低先验，但重要性采样更重尾，On-policy 探索也难遇到该答案。闭式存在不等于有限采样能找到。

若 reward 只在一个固定候选集合上定义，集合外输出没有可靠分数。神经 RM 给全空间外推，看似解决定义域，实际引入模型假设。KL 将策略限制在 reference 邻域，正是在减少对远距离外推的依赖。 KL Coefficient 与 Reward Scale. 将 reward 乘常数 $c$ 等价于把有效温度 $\beta$ 除以 $c$。因此更换 RM、改变 reward normalization 或加入新奖励项后，原 KL coefficient 未必仍有相同含义。目标由比值 $r/\beta$ 决定。 自适应 KL controller 根据观测 KL 调 $\beta$，是在间接寻找满足某个距离预算的对偶价格。controller 太快会振荡，太慢则长时间偏离目标。target KL 本身也需根据任务质量与安全折中验证，不能由控制器自动决定。 Token KL 与 Sequence KL. 自回归 sequence KL 可按链式规则分解为旧前缀分布下 token KL 之和。将采样 token log-ratio 作为逐 token 负奖励，其轨迹和是 sequence log-ratio；在当前策略采样下期望等于 forward sequence KL。

实现若对 KL reward 按 token 平均而环境 reward按序列给一次，会让正则相对强度随长度变化。使用 token KL 求和能对应 sequence KL；随后整个 policy loss 是否按 token mean，又形成另一层长度权重。 采样 log-ratio 的 token KL reward 可为负，表示当前策略在该 token 上比 reference 概率低。单条轨迹 KL 总和也可能为负，只有对当前策略完整期望才非负。将每 token 负值 clamp 到零会改变 KL estimator，并偏向只惩罚概率上升。 若希望低方差，可在每个旧前缀上计算完整词表解析 KL，它总是非负。前缀仍由采样策略产生，状态分布噪声保留。解析 KL 作为 reward shaping 时，每步对全部 token 概率求和，计算和显存成本明显增加。

reference 和 current 使用不同 tokenizer 时，token 级 log-prob 无法对齐。即使两者能给同一字符串概率，分词路径不同也需要 sequence-level 边缘化，通常不可行。RLHF reference 应共享 tokenizer 与模板，或重新定义可比较的行为单位。 chat template 变化同样改变条件分布。新 policy 用新模板、reference 用旧模板计算 KL，差异混入输入格式而非策略参数。模板必须作为模型版本的一部分冻结，想升级模板应建立新的 reference 基线。 Reference 更新会改变目标. 固定 reference 提供稳定锚点。周期性把 reference 更新为当前 policy，可让局部探索更自由，却把全程目标变成一系列移动约束；模型可能通过许多小步远离初始 SFT，同时每步 KL 都很小。

若目标是限制与初始行为的总漂移，应始终监控 initial-reference KL；若只关心单轮稳定，可用 rolling reference。两者可以同时记录，不能把 rolling KL 小解释成总体保持能力。

### 6.4. 奖励误差到策略更新

RM 输出经过 KL shaping、长度处理、value bootstrap 和 GAE 才成为 PPO advantage。每层变换都可能改变尺度、偏差与时间归因。 Reward Model Error 的梯度投影. 设预测 reward $\hat r=r^*+e$，策略梯度误差为
$$
\Delta g=
\mathbb E[e(x,y)\nabla\log\pi(y\mid x)].
$$
$e$ 平均为零仍可能与 score 相关，policy 会主动利用这种相关。RM MSE 衡量所有方向误差，真正危险的是沿策略可改变方向的误差协方差。 对当前 policy 高概率样本、更新后概率增幅最大的样本和高 reward 尾部单独做人评，能更直接观察可利用误差。随机 validation 主要衡量旧分布平均性能。

可以把 policy 更新前后的概率变化作为审计权重。样本 $y$ 的 log-prob 增量大且人工效用下降，说明 reward error 正好沿可优化方向；分数误差大但概率未变化，对当前训练影响较小。这个视角把静态 RM 误差与动态策略风险连接起来。 离散候选集上可精确计算 RM reward 与人工效用各自诱导的指数重加权分布，比较两者 total variation 或 KL。差异随温度变化：强 KL 时策略靠近 reference，漏洞影响小；温度降低后高分尾部主导，微小排序错误也会被放大。 RM ensemble 的均值误差与分歧可以一起投影到 score。高分歧样本若 score norm 很小，短期影响有限；中等分歧但 score norm 巨大，反而值得优先标注。主动学习 acquisition 可使用预期梯度影响，而非只按 reward variance 排序。

reward error 还会通过 critic 平滑传播。某条终局回答被高估，value 网络可能把其前缀模式普遍高估，随后许多尚未完成的轨迹获得正 advantage。审计不能只查最终作弊文本，还应查 critic 是否把漏洞泛化到相似前缀。 Reward Whitening 的随机目标. batch whitening
$$
\tilde r_i=\frac{r_i-\bar r}{s_r+\epsilon}
$$
让每个样本 reward 依赖同批其他样本。平移去掉 batch 常数，理论上类似 baseline；随机标准差改变每批整体步长，并让任务混合影响权重。 按 prompt 组内 whitening 消除 prompt 难度，优化相对回答；全局 whitening 保留部分跨 prompt 差异。组大小小、奖励全同时，标准差噪声或 $\epsilon$ 会主导。应报告 whitening 前后各 reward 分量分布。 运行均值 whitening 使用历史统计，降低 batch 间抖动，却在 policy 和 RM 分布变化时滞后。切换 reward 版本后旧均值方差可能完全失效，应重置、仿射迁移或经过 warm-up。直接沿用会让早期 advantage 尺度异常。 全局 whitening 把不同任务放在同一尺度，大方差任务对标准差贡献更大。按任务分别 whitening 让任务梯度尺度接近，但抹去业务设定的绝对奖励差。可先按可解释单位校准各 reward，再使用温和全局归一化。

对组内只有两个回答的 pair，中心化后优势必然一正一负，差值大小由 reward margin 决定；再除组标准差后，除 tie 外幅度几乎固定，RM 对偏好强度的表达被丢弃。是否需要这种不变性，应由目标决定。 whitening 统计必须 detach，且只用有效样本。把 padding、无 reward 的失败样本或跨 worker 局部统计混入，会改变中心。失败样本若代表真实低效用，应赋明确定义的 reward，而不是靠 mask 静默删除。 Value Error 沿 GAE 传播. 若 $V_\phi=V^\pi+e_t$，TD error 误差为 $\gamma e_{t+1}-e_t$。GAE 对它做 $(\gamma\lambda)^l$ 加权和。$\lambda$ 越小越依赖局部 value 准确性，越大越依赖长程实际 reward。 终局 RM reward 很稀疏时，早期 token advantage 主要由 critic 预测的前缀价值变化决定。critic 学错某类前缀，PPO 可系统强化表面模式。用独立 rollout 或过程验证检查前缀 value calibration，比只看终局 RM 分数更有诊断力。 多奖励项的权重. 总 reward 可能包含 helpfulness、safety、format、verifier、长度和 KL。线性加权
$$
r=\sum_kw_kr_k
$$
选择一个 Pareto 折中。各项相关、尺度与噪声不同，权重不能只按均值大小设置。某项稀有但损失巨大时，平均线性权重可能无法提供硬保护。 分别训练 value head 可看到每项 advantage 与梯度冲突，再按目标权重组合；单一 value 只拟合总和，难以追踪哪个奖励驱动更新。无论采用哪种结构，最终都要报告分项指标，避免总 reward 上升掩盖安全或能力退化。 多 head critic 还能为每项使用不同折扣与时间边界：即时格式成本、终局正确性和长期用户结果的 horizon 不同。把它们强行用同一 $\gamma,\lambda$ 混合，会让某些信号传播过远、另一些传播不足。组合 actor advantage 前再按业务权重与单位对齐。

梯度冲突可用 $g_i^Tg_j$ 观察。简单线性加权忠实于声明的总 reward，即使梯度冲突也只是多目标本质；PCGrad 等投影会改变这个目标，可能改善均衡但需要新解释。不能把投影称为纯粹消除噪声。 硬规则 reward 往往尺度离散、RM reward 连续。某次明确违规若只在 batch whitening 后成为普通负值，约束力度受同批其他样本影响。不可妥协事件更适合独立 cost constraint 或动作屏蔽，而非和风格分数一起标准化。 reward 项相关时，分别调权重不等于独立控制。例如长度与 RM helpfulness 高度相关，增加长度惩罚同时改变 RM 分布。构造长度匹配评估集和因果干预，才能估计权重的净效果。

### 6.5. 标注预算与在线回流

人类偏好是流水线中最昂贵、最稀缺的信号。随机标注易估计总体表现，却把大量预算用在差异明显的 pair；只标难例能改善决策边界，又会失去总体校准。数据设计需要在估计与学习之间分工。 随机样本用于无偏评估. 从部署 prompt 与当前 policy 随机抽样，能估计总体胜率、违规率与长度分布。只要保留抽样概率，分层过采样后也可加权还原部署指标。这个流量不应由 RM 分数筛选，否则评估会遗漏模型自信但错误的区域。 估计小概率安全事件需要大样本。零次违规不表示概率为零；若 $n$ 个独立样本均无事件，简单 rule-of-three 给 95% 上界约 $3/n$。希望证明风险低于万分之一，几百条标注远远不够。

同一 prompt 的多个回答相关，独立单位仍是 prompt 或用户会话。把所有 pair 当独立样本会低估置信区间。评估切分还应按用户、模板与时间分组，防止近重复泄漏。 主动采样用于提高 RM. RM 最不确定、ensemble 分歧大、不同候选分数接近的 pair 对决策边界最有信息。主动采样优先标这些样本，能用较少预算改善排序；采样分布随 RM 变化，训练 loss 不再代表部署平均风险。

只按不确定性采样容易集中到本身含糊、标注者也无法判断的 pair。结合可判定性、任务价值与覆盖约束更合理。标注后长期保持高分歧的样本可能反映价值冲突，应进入 rubric 修订或多偏好建模，而不是无限复标。 重复标注与噪声估计. 给一部分 pair 多人独立标注，可估计一致率、标注者偏差和任务难度。重复比例太低时，模型无法区分 reward error 与标签噪声；全部重复又降低覆盖。可先随机重复建立基线，再对分歧和高风险样本增加票数。 多数票提高稳定性，但会抹去少数群体偏好。安全 rubric 若有明确事实标准，可由专家仲裁；开放风格偏好更适合保留分布。数据 schema 应保存每张票和标注者元数据，而非只留聚合赢家。

候选生成决定可学习上限. 偏好数据只能比较已生成候选。若两个回答都很差，标注者被迫选“较不差”的一个，RM 会学到局部排序却看不到真正好答案。混合不同温度、不同 checkpoint、搜索结果和人工示范，能扩大质量范围。 候选差异过大，标注容易但提供的边界信息少；差异过小，噪声高。合理数据同时包含 anchor pair、near-tie pair 与安全反例。每类比例应和用途对应：anchor 做尺度与基础质量，near-tie 改善 policy 附近排序，反例保护尾部。

候选生成温度决定难度与覆盖。低温回答彼此相似，pair 常接近 tie；高温扩大差异，也产生大量明显低质样本。可按任务动态设置温度，并记录完整采样概率。后续若用这些数据做离策略分析，缺少行为分布会失去校正依据。 best-of-N 候选经过 RM 预筛后再交给人，会让标注集中到 RM 已偏好的区域。这样可提高高质量 pair 密度，却难以发现 RM 将好回答打低的 false negative。保留一部分不经预筛的随机候选，才能估计筛选召回。 人工示范与模型候选混合时，来源标签可能与质量高度相关。RM 学会识别人工风格后，在训练集上排序很好，policy 只需模仿表面风格就能提分。让强模型、人工和不同模板产生风格交叉，减少来源捷径。

pair 构造也决定权重。一个 prompt 生成 $K$ 个回答后枚举全部 $K(K-1)/2$ 对，会让该 prompt 权重平方增长，且 pair 高度相关。随机选边、构造排序 loss 或先在 prompt 内归一化，分别对应不同统计目标。 主动采样循环中，RM 每次选择下一批数据，最终训练集不是独立同分布。普通 validation 若也从这个池随机切分，会高估边界附近性能。固定独立随机 test 与时间向前 test，能分别衡量部署平均和对新 policy 的迁移。
Reward Hacking 的因果诊断。 RM 分数上涨、人工质量下降时，不能只列举表面模式。需要判断 policy 利用了哪条评分路径，漏洞来自数据、模型、聚合还是部署变换。 相关特征与因果特征. 训练数据中，长回答可能更好，RM 学到长度相关。policy 随后添加重复解释提高分数，长度相关仍存在，真实质量却未改善。观察相关性无法区分“长度携带内容”与“长度本身被奖励”。 可做配对干预：保持核心答案不变，只增删冗余段落、格式标记或引用；也可保持长度相近，替换关键事实。若 RM 对无意义变化敏感、对事实变化迟钝，就找到了可利用路径。干预集应独立于 RM 训练。 Gradient-based 与搜索式攻击.

policy optimization 本身就是对 RM 的黑盒或梯度引导搜索。可在正式 RL 前用 best-of-N、遗传改写或可微 token 优化寻找高分回答，再由人工审计。攻击找到的模式进入 hard-negative 数据，并保留独立复测集。 若每轮把全部攻击样本加入训练，RM 可能记住具体模板而非学会原则。对攻击做语义变体、跨任务迁移和时间 holdout，能检查修复是否泛化。新的 policy 仍可能找到未覆盖漏洞，红队不是一次性步骤。 独立 Judge 为什么仍会共错. 使用另一个模型评估能降低直接训练泄漏，但两个 judge 可能共享预训练数据、架构和表面偏好。它们会一致偏爱流畅冗长文本，也可能共同漏掉专业事实错误。模型间一致不是独立证据的充分条件。

规则验证、可执行测试、检索核对、专家标注与用户结果来自不同信号链，更能形成互补。不同 judge 的分歧样本应重点复核；一致高分但分布外的样本同样需要抽查。 Hacking 与目标错设的区别. 如果 reward 明确鼓励简短回答，policy 变短并非 hacking；若任务真正需要细节，问题在目标权重或 rubric。hacking 更准确地指代理 reward 与期望效用存在可利用差异。二者都表现为“分数上升、体验变差”，修复位置不同。 目标错设需修改评价标准与权重，模型漏洞需补数据或改架构，policy 实现错误则需修 ratio、mask 或 reward 归属。将所有问题都归为 reward hacking，会让团队在错误层面添加补丁。

hacking 还可能发生在 tokenizer 与解析器接口。RM 从截断文本评分，policy 把关键内容放在截断后；结构化输出解析器只读取第一个字段，policy 在未读取区域堆高分短语；Unicode、空白和不可见字符也可能让人类视图与模型输入不同。审计必须使用生产预处理链。

如果 RM 只读取最终回答，policy 可在隐藏思维、工具调用或引用中操纵环境而不影响评分；若 RM 读取完整轨迹，又可能奖励冗长过程或泄露内部信息。评分可见范围应与真正关心的行为边界一致，并逐段标记哪些内容面向用户、工具和裁判。

多 reward ensemble 取均值会降低独立噪声，却可能让一个极端高分模型抵消其他模型警告。取最小值更保守，也容易被某个过度拒绝模型支配。分歧触发人工复核、均值用于常规优化、硬规则处理明确违规，是更可解释的分工。 修复漏洞后需要检查能力侧效应。对“总是先道歉”这类模式施加负样本，可能连合理道歉也被压制。最小对照应包含该模式有益与有害的两类上下文，让 RM 学条件关系而非关键词黑名单。 policy 对 RM 的利用强度随 KL coefficient 和训练步数增加。短试验没有出现 hacking，不代表长程安全。画人工质量相对 RM reward 的校准曲线随 KL 或训练轮次变化，可以找到代理开始失真的区域，用作停止或数据回流阈值。
在线数据回流与版本闭环。 RLHF 不是训练完 RM 再永久使用。policy 改变输出分布，新的偏好数据更新 RM，RM 又改变下一轮 policy。版本关系不清会让实验无法复算。 四类版本必须绑定. 每条 rollout 至少绑定 policy、reference、reward model 和 tokenizer/template 版本。policy 决定行为概率，reference 决定 KL，RM 决定环境 reward，tokenizer 决定动作序列。任何一项变化都会改变 advantage。 重算新 RM reward 可以比较裁判变化，但不能把旧轨迹变成新 policy 的 On-policy 数据。重新计算 log-prob 可得到 ratio，状态分布与支持覆盖仍来自旧 policy。数据新旧要从行为和奖励两个轴分别描述。 回流策略与选择偏差. 只回流线上被用户投诉的样本，会高估失败类型比例；只回流高 RM 分样本，会遗漏低分误判。随机流量用于总体估计，触发流量用于高价值修复，两者应带来源标签并采用不同权重。

policy 生成失败或超时的样本若被管线丢弃，RM 数据只包含成功完成者，形成 survivorship bias。超时、拒答、解析失败都应作为可标注结果保留，或至少统计缺失概率。 线上用户反馈也有选择性。极满意和极不满意用户更愿意评分，中性用户沉默；复杂任务耗时长，反馈返回更晚。把已返回评分直接当随机样本会偏向极端和快速请求。随机邀请、记录曝光与响应概率，可支持加权估计。

隐式反馈如复制、继续追问、会话离开和任务完成，需要因果解释。用户复制可能表示答案有用，也可能为了转发错误；继续追问可能表示投入，也可能表示首答失败。单个代理指标不宜直接成为 reward，应通过受控实验或多信号模型校准。 回流样本若包含当前 policy 明显特征，RM 会逐渐适应该版本。下一版 policy 又寻找新边界，形成追逐。保留跨版本固定 anchor 和旧漏洞回归集，可以测量修复是否遗忘；只看最新分布会不断丢掉历史约束。 人工标注周期慢于 policy 更新时，若连续训练多版 policy 再统一收标，样本来自多个行为分布。每条数据绑定生成版本，RM 可训练全部数据，PPO On-policy 阶段则只能使用当前 rollout。数据湖与优化 batch 的“可复用”标准不同。

删除低质量反馈不能只按 RM 当前分数，因为会形成自确认循环。使用独立规则、标注一致性和来源质量筛选，并抽查被删除样本。否则 RM 不喜欢的反例被清除，validation 也越来越容易。 RM 更新后的回归门槛. 新 RM 上线前，要在固定历史集、最新 policy 集、攻击集和随机部署集分别验证。总体 pairwise accuracy 提高却在最新 policy 上下降，意味着更新没有覆盖当前决策区域；攻击集提高、随机集下降，则可能过拟合补丁。

四类集合不能互相替代。固定历史集衡量遗忘和版本可比性，最新 policy 集衡量当前边界，攻击集衡量已知漏洞，随机部署集给总体估计。为每类预设最低门槛，比将它们混成一个加权平均更能保护尾部。 RM checkpoint 选择也会对 validation 过拟合。训练 epoch、数据混合和正则尝试越多，最高验证准确率越乐观。隐藏 test 只在最终候选上运行，或使用时间后移的新标注集，可减少选择偏差。 RM 推理精度、量化和批处理实现可能改变分数。训练时 FP32 模型通过评估，部署量化服务的 pair 排序可能翻转，特别是 near-tie 样本。发布前在真实服务栈重放 anchor、边界与极端长度样本。

长输入截断策略必须一致。若 RM 只保留开头，policy 可把问题内容放在后半；只保留结尾则可能忽略提示约束。提示与回答分别预算 token，并报告截断率和截断位置，避免“完整回答分数”实际只看局部。 reward 尺度漂移还需单独检查。对同一 anchor responses 比较新旧分数，拟合仿射关系与残差。若主要是平移缩放，可调整 PPO coefficient 与 value 初始化；若排序结构变化，需要视作新目标重新校准。 新 RM 的 tokenizer 或模板变化时，旧 anchor 必须经过对应预处理重算。输入截断长度改变会让分数差异看似语义漂移，实际只是可见文本变化。保存渲染后的精确 RM 输入，才能区分模型与管线。

reward replay 可以把历史 policy 样本同时送入新旧 RM，观察各任务的 rank correlation、margin 和 top-tail 交集。总体相关高但 top 1% 交集低，PPO 最关心的高分区域已经改变，不能只做仿射校准。 critic 从旧 RM 训练出的 value head 也需处理。若新旧 reward 近似仿射，可相应变换 value 输出；若结构变化，继续沿用会给早期 GAE 系统偏差。冻结 actor 先让 critic 在新 reward 上校准若干步，是一种过渡方式。 RM 回滚同样要版本化。发现新 RM 漏洞后恢复旧 RM，policy 已经在新分布上移动，不能假设旧 RM 仍校准。应在当前 policy 样本上复测旧 RM，必要时连 policy 一起回滚到兼容 checkpoint。 数据删除或合规要求也会影响版本链。移除某批标注后重新训练 RM，差异可能扩散到 policy。训练数据 manifest、样本 lineage 与模型 hash 使影响分析成为可能；只有汇总数据量无法追踪具体来源。 何时停止在线 RL.

训练 reward 持续上涨不是继续的充分理由。人工胜率进入平台、RM 与人工相关下降、KL 或长度持续漂移、关键能力退化、有效 advantage 比例过低，都可成为停止条件。 停止规则应在实验前定义，避免追逐随机峰值。保存每轮 policy 并用 validation 选 checkpoint，再在未使用 test 上评估。最新 checkpoint 不一定最好，RM 最高分 checkpoint 也不一定最好。
安全约束与多目标偏好。 helpfulness、harmlessness、honesty 与风格常彼此冲突。压成单一 reward 简单，却隐藏权重和不可接受边界。 线性加权与 Pareto 前沿. 多目标 reward $r=\sum_kw_kr_k$ 选择 Pareto 前沿上的一个点。改变 $w_k$ 会移动折中，单次训练无法说明其他点。用多个权重训练或离线评估近似 frontier，可看到提升 helpfulness 需要牺牲多少安全与简洁。 不同指标尺度必须校准。一个标准差为 100 的 reward 即使权重小，也可能支配总和。按统计尺度归一化只是数值处理，业务交换率仍需由效用定义。 硬约束与 Lagrangian. 对安全成本 $J_C\le d$，可优化
$$
J_R-\lambda(J_C-d),
\qquad
\lambda\ge0.
$$
乘子根据违规程度更新，自动调整成本价格。期望约束只控制平均，无法保证每次输出安全；高风险动作还需规则屏蔽、拒答策略或人工升级。 如果 cost 是二元违规，平均约束 $E[C]\le d$ 直接对应违规概率上界；前提是检测器无误。实际安全 RM 有漏报和误报，约束的是预测违规率。用人工标注估计检测器 confusion matrix，可对真实风险做区间校正，但分布漂移后矩阵也会变化。 CVaR 约束关注最坏尾部损失，适合严重程度连续的风险。估计小尾部需要大量样本，batch 中只有少数事件时乘子梯度方差极高。专门过采样风险场景可提高信息量，再按采样概率还原部署风险。

多约束分别设置乘子比把所有 cost 预先加权更透明。某项长期不活跃时乘子接近零，某项频繁违规时上升；不同乘子尺度仍受 cost 单位影响。日志应展示原始 cost、阈值、乘子和对 actor 梯度贡献。 约束 critic 若和 reward critic 共享骨干，稀有风险梯度可能被大量普通 reward 样本淹没。分头输出、风险样本加权或独立网络能改善，仍要防止训练采样权重改变部署风险估计。 cost critic 与 reward critic 都会有误差。稀有违规样本少时，平均准确率掩盖漏报；需要风险条件评估、保守上界与主动红队。不可行阈值会让 $\lambda$ 持续增大，policy 几乎只优化成本。 条件化偏好策略.

若用户偏好差异合理，可让 policy 条件于明确偏好参数或风格指令，而非用单一平均 reward 抹平。训练数据要覆盖条件与回答的交互，防止模型只学表面标签。 安全底线不能完全交给用户条件。可将不可违反约束与可调风格分层：先保证约束，再在可行集合内优化个性化效用。模型和产品界面都需明确哪些维度可选。 拒答的双重角色. 拒答能降低安全风险，也可能成为逃避困难问题的捷径。若 reward 对违规惩罚远大于有帮助奖励，policy 会扩大拒答范围。按风险类别统计正确拒答、过度拒答与漏拒，才能看到平均安全分背后的行为。

构造安全但可回答的对照样本，是压制过度拒答的关键。只收集明显危险与明显安全样本，决策边界附近没有监督，RM 容易依赖关键词。最小对比 pair 应只改变真正决定风险的条件。 有些请求可在添加限制后回答，例如提供高层原理而不提供危险步骤。二元“回答或拒答”reward 无法表达这种部分帮助。将响应策略分为直接回答、安全改写、澄清和拒答，并针对任务风险标注适当性，能给 policy 更细的可行行为。 安全判定存在上下文依赖。相同词汇在教育、医疗急救、恶意操作和虚构创作中含义不同。只用关键词平衡数据会制造表面对照，真正有效的 pair 要保留主题相似并改变意图、权限或细节层级。

约束项也会被利用。若“包含免责声明”提高安全分，policy 可能先给危险细节再附免责声明。
