# PPO 式 RLHF 流水线

预训练模型学的是语料中下一个 token 的条件分布,它未必知道用户真正喜欢怎样的回答。SFT 让模型模仿一批示范,偏好标注再告诉我们「面对同一个问题,两个回答哪一个更好」。PPO 式 RLHF 把这两类数据接到在线采样和策略更新上。[InstructGPT](https://arxiv.org/abs/2203.02155) 展示的正是示范数据、比较数据、奖励模型与 PPO 依次衔接的训练链。前一步决定后一步能够观察到什么,后一步又会把前一步的缺陷放大。

本节的 [训练流水线](./2.1.1-ppo式rlhf流水线.md) 逐步推导目标与 token 级更新,[奖励失真与独立验收](./2.1.2-奖励失真与独立验收.md) 专门处理代理奖励被优化器钻空子的情形。两篇应连起来读:会算 PPO loss 还不够,必须知道这个 loss 奖励的行为是否真的符合人的判断。

## 1. SFT 给出起点,偏好数据给出比较

SFT 对示范回答最大化条件似然,让模型能稳定进入指令格式并完成常见任务。它的监督是「这一条参考回答的 token 应当有较高概率」;同一道题还可能有许多同样好的写法,单条示范并未排列它们的优劣。偏好数据通常固定 prompt $x$,让标注者在候选 $y_w,y_l$ 中选更好的一个。同题比较能部分控制题目难度:我们关心的是同一条件下两个回答的差,不能把「简单题回答得高分」直接与「困难题回答得低分」混成一条全局排序。

候选来自哪个策略也重要。若只比较早期 SFT 模型生成的回答,标注集会集中在那个模型容易产生的错误上;后续策略学会新写法后,奖励模型要对未见分布外的回答打分。候选应同时覆盖容易判断的优劣和边界情形,包括长度、格式、事实错误和似是而非的推理。数据切分最好按 prompt 或来源隔离,同一问题的改写若同时进入训练与验收,离线准确率会虚高。偏好本身也有分歧:标注者若在「简洁」「详细」「安全」之间侧重不同,硬压成唯一标签会使奖励模型学到一个模糊的平均目标。

## 2. 奖励模型学到的是相对坐标

常用的 Bradley–Terry 形式令奖励模型给出标量 $r_\phi(x,y)$,并用差值预测偏好:

$$
P_\phi(y_w\succ y_l\mid x)=\sigma\bigl(r_\phi(x,y_w)-r_\phi(x,y_l)\bigr).
$$

这一式只约束同一 prompt 内的分差。给该 prompt 的所有候选奖励同时加上 $c(x)$,偏好概率不会变;奖励模型输出的绝对值因此没有跨题目的天然刻度。比较模型时应看同一提示上的排序、校准和独立偏好胜率,不能拿「平均 reward 从 3 涨到 5」直接当成用户体验改善。分数尺度还与偏好噪声温度相关,换了标注口径或训练设置,数字也会变。[训练流水线](./2.1.1-ppo式rlhf流水线.md)从成对损失的梯度出发,说明模型怎样给 winner 和 loser 拉开差距。

奖励模型训练完后,策略却会继续变化。原来只在普通回答之间做排序的裁判,后来可能遇到极长回答、重复堆砌礼貌话术,甚至专门迎合它的格式。优化器总倾向寻找高分区域,裁判的小偏差于是成为可利用的方向。[人类反馈摘要研究](https://arxiv.org/abs/2009.01325) 已把奖励模型分数与人工偏好分开考察;两条曲线不能预先视为同一指标。奖励模型是训练用代理,独立人工或任务评测才是它的外部校验。

## 3. 在线采样后,五个角色各管一件事

当前 policy 生成回答,本轮采样时的快照称为 old policy。old 版本的 token log-prob 随轨迹保存,成为 PPO ratio 的分母。reference policy 通常冻结在 SFT 起点附近,用来计算偏离锚点的 KL;它与每轮更新的 old policy 不同。reward model 对完整回答给出代理分数。critic 则预测「从这个前缀继续按当前策略走,预计还能拿多少回报」,供 GAE 估计每个 token 的 advantage。policy、old、reference、reward model、critic 是五种统计角色;old 可只存日志,reference 与 reward model 只做前向,不要求五个同尺寸模型同时驻留。

对一个回答,常见训练回报把终局奖励与逐 token 的 reference KL 惩罚组合。令 $\pi_{\rm old}$ 表示生成这批轨迹时的策略,第 $t$ 个动作是 token $a_t$,则这批数据上的示意写法是 $\tilde r_t=-\beta[\log\pi_{\rm old}(a_t\mid s_t)-\log\pi_{\rm ref}(a_t\mid s_t)]$,序列末端的有效位置再加 $r_\phi(x,y)$。把逐 token log-ratio 沿回答求和,就回到序列 log-prob 的差;但实现还要确认 EOS、padding 和截断是否计入。critic 的值从同一奖励定义学习,GAE 再把稀疏终局反馈向前分配。同一固定 batch 的 PPO 多轮更新沿用采样时算好的奖励与优势;在这里的策略目标里,当前 $\pi_\theta$ 通过相对 $\pi_{\rm old}$ 的更新比率进入计算,下一轮 rollout 才刷新采样策略与奖励。若在同一旧 batch 的 epoch 之间悄悄改 $\beta$ 或重算奖励,优势目标就变了。

这里有个容易误读的地方:采样到某个 token 时,括号内的 log-ratio 可以为负,所以单位置的 KL 惩罚也可能为正。非负的是在同一前缀下对采样策略的全部可能 token 取期望后得到的 $D_{\rm KL}(\pi_{\rm old}(\cdot\mid s_t)\|\pi_{\rm ref}(\cdot\mid s_t))$,不是任意一条已采样轨迹上的每一项。训练日志若只记录样本 log-ratio,不能把其中的负数直接当成「KL 算错了」。在长回答上,还要分清每 token 平均和整条回答求和;二者随着长度增长的尺度不同,同一个 $\beta$ 不能不经换算就移植。

PPO 更新用 $\pi_\theta(a_t\mid s_t)/\pi_{\rm old}(a_t\mid s_t)$ 判断当前策略相对采样版本走了多远;reference KL 则限制长期漂移。两者的分母不同,对应的问题也不同。若所有 token 都得到同一终局分数,早期的无关措辞和真正决定答案的推理步骤可能被一同强化;critic、过程反馈或更细的验证器才有机会改善这种信用分配,同时也会引入自己的估计误差。

## 4. 用独立结果验收整条链

奖励模型验证集准确率高,只能证明它在那批比较样本上有排序能力。策略一旦直接优化它,就会把新分布送到裁判面前。一个回答变长可能让 RM 分数上升,人工却觉得它啰嗦;格式词反复出现也可能被奖励模型误读成「更安全」。遇到这类现象,应分开看原始 RM 分、长度、reference KL、独立胜率与具体失败样本,才能判断是代理目标失真、优势估计偏差还是单轮 PPO 更新过大。[奖励失真与独立验收](./2.1.2-奖励失真与独立验收.md)把这些偏差追到标注、模型校准和策略回流环节。

独立验收的样本不能只换随机种子。题目来源、时间和任务类型都应与奖励模型训练集有足够隔离;同一 prompt 的轻微改写不算真正的新证据。人工比较可保留并列或分歧,可验证任务则直接看正确率与失败类型。若代理分数继续上涨,独立指标却停滞或下降,应先检查裁判漏洞与数据分布,而非只把 PPO clip 收紧。RLHF 的闭环只有在「模型输出变化—外部评判—新数据回流」之间持续校准时才站得住。

判断 PPO 这一步到底带来了什么,还要把起点模型与更新后模型放在同一批未参与训练的 prompt 上盲评。否则,新增示范数据、奖励模型换代和策略更新同时发生,胜率提高也无法归因到 PPO。对模型输出的比较最好保留原始回答、标注分歧和失败类别,再看长度分布与 KL 曲线:同样是胜率上升,一种可能是真正修正了事实错误,另一种只是答案越来越长、越来越像裁判偏爱的格式。这项对照决定下一轮该补偏好样本、重训裁判,还是调整策略更新。
