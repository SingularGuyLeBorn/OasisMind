# PPO-based RLHF 训练流水线

RLHF 把人的判断变成模型能够反复优化的训练信号. 经典流水线包含三个阶段:示范回答用于 supervised fine-tuning,同一 prompt 下的回答比较用于训练 reward model,当前 policy 再生成新回答并通过 PPO 提高预测奖励,reference policy KL 同时限制行为漂移. 三个阶段解决不同问题. SFT 决定模型最初如何回应指令;preference data 与 reward model 把有限的人类排序扩展为可批量计算的标量;online RL 让 policy 在自身分布上搜索更高奖励的回答. 闭环的难点在于 policy 更新会改变 rollout 分布,reward model 随即评价训练数据中少见的新行为,模型也有机会寻找评分器漏洞.

![PPO-based RLHF 的三阶段数据与模型闭环](images/rlhf-closed-loop.png)

> 图 1: PPO-based RLHF 由三段训练相连: 示范数据得到 SFT policy, 同 prompt 候选回答的偏好对训练 reward model, 当前 policy 的 On-policy rollout 则提供 sequence reward 与 reference token KL, 供 PPO 更新使用.

图 1 解析:

- 第二阶段的 candidate generation 负责把 prompt 变成可比较回答, preference pair 才是 reward model 的直接监督对象.
- 第三阶段从同一 SFT checkpoint 初始化可更新的 $\pi_\theta$ 与冻结的 $\pi_{ref}$; 后续 PPO step 只更新前者.
- reward model 给整条回答的 sequence reward, reference 与当前策略的 log-prob difference 给 token KL. Critic 与 GAE 再把这些信号分配到 token 位置.

## 1. SFT 决定 RL 从哪里开始

令 prompt 为 $x$, completion 为 $y=(y_1,\ldots,y_T)$. 自回归策略分解为
$$
\pi_\theta(y\mid x)=
\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}).
$$
预训练模型会续写文本, SFT 用高质量指令与回答样本把条件分布移到对话任务附近. 这一步同时建立聊天模板, 停止行为, 风格和基本任务格式, 也为 reward model 与 PPO 提供一个可用的探索起点.

### 1.1. Completion-only 交叉熵

对示范样本 $(x,y^*)$, 常用损失为
$$
\mathcal L_{SFT}(\theta)=
-\sum_{t=1}^{T}m_t
\log\pi_\theta(y_t^*\mid x,y_{<t}^*).
$$
$m_t\in\{0,1\}$ 是 loss mask. 系统消息与用户 prompt 参与上下文条件, 通常不承担 assistant completion 的预测损失. Padding 位置必须为 0, EOS 是否计入取决于模板和训练目标, 但必须与生成停止规则一致. 若把 prompt token 加入 loss, 优化目标会额外建模 system/user 文本并改变各角色权重, 还会稀释 assistant completion 的监督预算; 若 EOS 被全部遮掉, 生成长度可能失控.

多轮对话还要决定哪些 assistant turn 进入 loss. 只训练末轮时,每条样本提供的监督较少;训练全部 assistant turn 时,要确保此前回答确实来自目标分布且格式正确. 这个选择会改变每个 token 的权重,应随数据版本保存,不能只记录原始对话 JSON. SFT 的样本权重会延续到 RL 起点。按 token mean 训练时长回答贡献更多，按 sequence mean 时每条回答等权；多轮样本若每个 assistant turn 都训练，又会让长对话获得更多权重。数据条数相同不代表目标相同，最终 reduce 需要写成公式。

示范答案常由人工、强模型和规则模板混合产生。来源比例会塑造 policy 支持：某类任务只有模板拒答，RL 很难从 On-policy 探索中突然发现高质量回答；某类工具调用从未在 SFT 出现，后续动作概率可能接近零。SFT 覆盖是 RL 可搜索空间的实际起点。 去重若只按原始文本，会漏掉模板渲染、空白和轻微改写后的近重复。训练验证间存在同 prompt 变体时，SFT loss 与偏好评估都偏乐观。可用规范化文本、语义 embedding 与来源 id 多层去重，并保留误删审计。 SFT checkpoint 同时作为 PPO 初始化、reference 和常见 RM backbone 时，三条路径共享偏差。使用同一初始化方便对齐表征，却让 RM 更容易偏爱 SFT 风格。独立架构或不同数据初始化可增加 judge 多样性，计算成本也更高。

混入预训练或通用指令数据能保留能力，但其 loss scale 和 token 数可能压过高质量示范。采样比例、loss 权重和序列长度共同决定实际贡献。报告数据集名义比例之外，还需报告有效训练 token 与梯度尺度。

### 1.2. 数据质量与策略支持

SFT 数据既提供目标行为, 也塑造初始策略的高概率区域与有效支持. Softmax LM 对多数 token sequence 仍有非零数学概率, 但概率质量极低的行为在有限 rollout 中几乎采不到. 若某类推理, 拒答或工具调用从未出现, PPO 需要靠随机探索发现它, 成本会很高. 若示范中含有系统性事实错误, reward model 后续又偏爱流畅表达, RL 可能把错误进一步放大.

去重与来源平衡也会改变结果. 同一模板的大量近重复回答会让模型把固定措辞当成指令遵循. 长回答数量偏多会改变长度先验. 数据验收应按任务, 来源, 语言, 长度和拒答类型切片, 并保留从训练 token 回到原始样本的 id.
SFT checkpoint 的三种职责。 完成 SFT 后, checkpoint 通常至少承担三种逻辑职责. 第一份初始化 trainable policy. 第二份冻结为 reference policy, 在 RL 中定义行为锚点. 第三份可以作为产生 preference candidates 的初始策略. 它们开始时参数相同, 版本生命周期却不同. 训练中还会产生 old policy, 即生成当前 rollout batch 的 policy 快照. `old` 与 `reference` 不能混用. Old policy 只用于 PPO probability ratio, 每批更新; reference policy 用于长期 KL, 通常跨许多 batch 固定. 若 ratio 分母误用 reference, 多 epoch 数据复用和策略漂移会被混成同一个量.
SFT 混合比例与能力保留。 Instruction data 通常远小于预训练语料. 若 SFT 只覆盖狭窄任务, 多轮训练可能改善对话格式, 同时削弱补全, 多语言或专业领域能力. 团队可以混入部分预训练样本, 使用较小学习率, 限制 epoch, 或按领域验证来控制这种分布迁移. 每种办法都会改变模型到底在优化什么.

混入预训练数据时, 两类 loss 的 token 数不能直接相加后假设权重合理. 一条长网页和一条短对话贡献的 token 数相差很大. 可以按 token 混合, 按 sequence 混合, 或先分别求均值再加权. 三种方法对长短样本和不同域的权重不同, 配方应明确到公式与 sampler. SFT 结束后的评估也不能只看 instruction benchmark. 需要保留预训练能力, 目标任务, 长度分布, 拒答率与模板鲁棒性等切片, 作为 RL 阶段的初始基线. 后面 policy 发生变化时, 才能判断退化来自 SFT, reward model 还是 PPO.

## 2. 偏好数据把人的判断变成比较

Preference collection 对同一个 prompt 展示多个候选回答, 要求标注者按 rubric 选择更好的一个或给出排序. 比较比绝对打分容易校准: 标注者不必回答"这个回答值 7.3 分", 只需判断两个具体回答谁更符合帮助性, 正确性, 安全性和风格要求. 比较仍然带有主观性. 两位标注者可能对简洁与完整, 拒答与帮助, 风险与可用性作出不同取舍. 这些分歧不是单纯噪声, 它们揭示了最终单标量 reward 将压缩哪些价值冲突.

### 2.1. 候选怎样产生

候选可以来自同一 policy 的不同温度或随机种子, 也可以来自多个 checkpoint 与基线模型. 只比较一个很强和一个明显很差的回答, reward model 容易学到粗糙特征, 却难以区分 policy 训练后遇到的近邻回答. 因此候选难度需要覆盖当前决策边界. 采样元数据应包括 policy version, decoding temperature, top-p, max tokens, stop reason 和模板版本. 长度上限造成的截断回答若与自然 EOS 混在一起, 标注者可能把不完整性学成内容偏好. 同一回答在不同模板下的边界也可能变化.

### 2.2. Pair, ranking 与切分单位

一组 $K$ 个候选可产生最多 $K(K-1)/2$ 个 pair. 这些 pair 共享 prompt 与回答, 统计上高度相关. 若把 pair 随机分到训练集和验证集, 同一个回答可能同时出现在两侧, reward model validation 会虚高. 正确切分单位通常是 prompt 或完整 candidate group. 训练时还要控制每组权重. 一个有 8 个候选的 prompt 能产生 28 个 pair, 若逐 pair 等权, 它会比只有 2 个候选的 prompt 获得 28 倍影响. 可以按 group 归一化, 抽样部分 pair, 或直接使用 listwise objective.
标注一致性与 rubric。 Rubric 需要把事实正确, 指令遵循, 帮助性, 安全性和表达质量写成可操作条件. 如果标注者只看到"选更好", 每个人会自行设定权重, reward model 学到的是混合且随批次漂移的隐含标准. 可以用重复标注估计一致性, 对争议样本保留 tie 或软标签, 并分析分歧集中在哪些任务. 强行把 tie 转成随机 winner 会制造不存在的确定性. 若项目确实需要多个价值维度, 保存分项标签比事后从单一 reward 反推更可靠.
主动采样把标注用在决策边界。 随机抽取候选 pair 简单, 却会产生大量一眼可判的比较. 当 winner probability 已接近 0 或 1, 新标签对 reward model 决策边界提供的信息有限. 可以优先采样 RM 分差接近 0, 多个 RM 意见不一致, 或当前 policy 与 reference 差异较大的回答, 把标注预算集中到难例. 主动采样会改变训练数据分布. 如果只收集最不确定样本, RM 看到的 easy case 减少, 原始 prompt 分布也可能被高风险域占据. 训练时可混合随机样本与主动样本, 保存采样概率, 并在独立自然分布验证集上评估. 否则 validation 也跟着主动分布移动, 很难判断整体质量.

Policy 迭代后, 旧的难例可能变成常见模式, 新漏洞又会出现. 因而 candidate generation 与 annotation 是持续过程. 每批 preference data 都应关联 producer policy version, RM version 和选择规则. 这条血缘能回答一个关键问题: RM 的高分区域究竟被多少真实人类比较覆盖.

## 3. Bradley-Terry 奖励模型

Reward model 接收 $(x,y)$ 并输出标量 $r_\phi(x,y)$. Bradley-Terry 假设回答 $y_w$ 胜过 $y_l$ 的概率只由分数差决定:
$$
P_\phi(y_w\succ y_l\mid x)=
\sigma(r_\phi(x,y_w)-r_\phi(x,y_l)).
$$
模型通常从 SFT 或预训练 checkpoint 初始化,在末尾 token 或专用位置读取 sequence representation,再映射为标量. 单个 $r_\phi(x,y)$ 是 latent score;成对分差 $r_w-r_l$ 才是 sigmoid 使用的 pairwise logit. 这些分数没有经过物理标定,不能直接视为人类效用单位.

### 3.1. Pairwise loss 与梯度

令 $r_w=r_\phi(x,y_w)$, $r_l=r_\phi(x,y_l)$, $\Delta=r_w-r_l$. 负对数似然为
$$
\mathcal L_{RM}=-\log\sigma(\Delta).
$$
利用 $d[-\log\sigma(z)]/dz=\sigma(z)-1$, 得到
$$
\frac{\partial\mathcal L}{\partial r_w}=\sigma(\Delta)-1,
\qquad
\frac{\partial\mathcal L}{\partial r_l}=1-\sigma(\Delta).
$$
若 $r_w=0.2,r_l=-0.1$, 则 $\Delta=0.3$, $\sigma(0.3)\approx0.574$. 梯度下降让 winner 分数增加约 $0.426\eta$, loser 分数下降约 $0.426\eta$, 其中 $\eta$ 是对两个标量直接优化时的学习率. 差值变大, winner probability 随之上升.

### 3.2. Identifiability 的边界

损失只依赖 $r_w-r_l$. 对任意与 prompt 有关的常数 $c(x)$,
$$
(r_w+c(x))-(r_l+c(x))=r_w-r_l.
$$
因此 reward 的绝对零点不可识别. 训练集上的所有分数同时加 10, pairwise probability 完全不变. 单独查看平均 reward 没有固定语义, 除非给出版本, 数据和校准方式. 尺度也受数据可分性与正则化影响. 将所有分差乘得更大, 对已正确排序且近乎可分的数据会继续降低 logistic loss. Weight decay, early stopping, label smoothing 或显式温度共同决定输出尺度. 换一个 RM checkpoint 后, PPO 的 $\beta$, advantage 标准化和 reward clipping 都可能需要重新校准.
验证 reward model。 Pair accuracy 只测 winner 是否得分更高, 对 margin 和校准不敏感. 应同时查看 log loss, 不同任务与长度分桶, 标注分歧组, 以及 policy 新分布上的表现. 若 validation 与训练 candidates 来自同一批模型和模板, 高准确率也不能证明 RM 能评价 PPO 后产生的新行为. 长度偏置是一个常见检查项. 若 chosen 系统性更长, RM 可能学到"更长更好". 可以构造内容近似但长度不同的对照, 在相同长度桶内报告 accuracy, 并检查分数对 token 数的回归斜率. 直接把长度从输入删除不可行, 关键是让偏好数据包含足够反例.
不确定性与 RM ensemble。 单个 RM 给出的 5.0 看起来很确定, 但标量本身不包含认识不确定性. 可以训练多个不同初始化, 数据 bootstrap 或架构的 reward models, 比较同一回答的分数方差. Ensemble 均值用作 reward, 方差可作为分布外警报或主动标注依据. 例如三个 RM 对回答 A 打分 $(1.2,1.1,1.3)$, 对回答 B 打分 $(2.0,-0.5,1.8)$. B 的平均分 1.1 与 A 的 1.2 接近, 模型间分歧却大得多. 直接按均值排序会忽略 B 可能位于训练覆盖之外. 可以对高方差样本降低优化权重, 请求人类复核, 或限制 policy 在该区域继续更新. Ensemble 也会共同继承数据偏差. 所有成员在相同长度偏置数据上训练, 一致高分不代表判断正确. 不确定性诊断只能揭示部分 epistemic uncertainty, 不能替代独立人类评估和有针对性的反事实测试.

## 4. 从 sequence reward 到 token 回报

Policy 生成整个回答后, RM 通常给出一个 sequence-level 标量. PPO 的动作却是逐 token 采样, critic 也在每个 prefix 状态估值. 流水线必须把终局分数, reference KL 和任何规则奖励组合成 token reward, 再用 GAE 分配到各位置. 这一转换最容易出现边界错误. Reward 加在哪个 token, EOS 是否有效, padding 是否泄漏, 长度截断是否 bootstrap, 都会改变整条回答的 advantage, 因而直接属于训练目标.

### 4.1. Reference-policy KL 目标

一个常见序列目标是
$$
J(\theta)=
\mathbb E_{x\sim D,y\sim\pi_\theta}
\left[R_\phi(x,y)-
\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}\right].
$$
因为自回归概率是 token 条件概率的乘积,

$$
\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}
=\sum_{t=1}^{T}
\left(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{ref}(y_t\mid s_t)\right).
$$
对当前 policy 样本取期望时, 这个 log-ratio 估计 $D_{KL}(\pi_\theta\Vert\pi_{ref})$. KL 惩罚使 policy 为离开 SFT 行为付出代价, 限制它进入 RM 缺少覆盖的区域. $\beta$ 控制 reward improvement 与行为漂移的交换率, 不是普适常数.

### 4.2. Token shaping 与可复算例子

理论目标里的 log-ratio 随当前策略 $\pi_\theta$ 变化. 但标准 PPO 实现先由 rollout policy $\pi_v$ 生成 batch, 再固定 $k_t^{v}=\ell_t^{v}-\ell_t^{ref}$ 构造这一批的 token reward、advantage 和 return. 可以令每个位置 reward 为
$$
r_t^{token}=-\beta k_t^{v},
$$
并在末尾有效 completion token 上加 sequence reward $R_\phi(x,y)$. 假设三 token 回答的 $k=(0.1,0.2,-0.1)$,$\beta=0.05$,RM 分数为 1.2. Token reward 为
$$
(-0.005,-0.010,0.005+1.2)
=(-0.005,-0.010,1.205).
$$
总和是 1.19, 等于 $02-0.05\times(0.1+0.2-0.1)$. 这项手算可以检查 KL 符号, token mask 和终局奖励位置. 若 padding 上 log-ratio 被设成极大值, 总 reward 仍应不变. Sampled log-ratio $k=\log\pi_v-\log\pi_{ref}$ 可能逐 token 为负, 虽然其在 $\pi_v$ 下的期望是 $D_{KL}(\pi_v\Vert\pi_{ref})\ge0$. 对同一方向的非负样本近似可以写成 $e^{-k}-1+k$; 若另定义 $\Delta=\log\pi_{ref}-\log\pi_v=-k$, 等价形式才是 $e^{\Delta}-1-\Delta$. 有些系统计算全词表 KL. 若在每个 PPO epoch 用当前 $\pi_\theta$ 重算 reference KL, 它就成为显式 current-reference regularizer, 不再是本批冻结的 reward shaping. 这些口径的数值尺度与梯度性质不同, 不能共用同一 $\beta$ 后直接比较.
Sequence reward 的 credit assignment。 终局 RM 分数没有告诉系统哪个 token 造成偏好. Critic 学习前缀的期望回报, GAE 再把后续 TD residual 传播到此前动作. 对状态 $s_t=(x,y_{<t})$, 令 $d_t$ 表示 bootstrap-stop mask: 真正 termination 必为 1; length truncation 若任务把它视作终局也取 1, 若理论过程仍可继续并保留有效 final state 则取 0. $b_t=1$ 表示这一位置后发生 termination、length truncation 或 batch 中的 sequence boundary. $V_{old}$ 是 rollout 时冻结的 value, $\gamma$ 是回报折扣, $\lambda$ 是 GAE trace 系数:
$$
\delta_t=r_t+\gamma(1-d_t)V_{old}(s_{t+1})-V_{old}(s_t),
$$
$$
\hat A_t=\delta_t+\gamma\lambda(1-b_t)\hat A_{t+1}.
$$
Termination 令 bootstrap 与 trace 都停止; length truncation 是否允许 value bootstrap 取决于任务语义, 但 trace 必须在回答边界停止, 不能把下一条回答的 advantage 传回来. 若 $\gamma=1,\lambda=0.8$, reward 为 $(0,0,1)$, value 为 $(0.2,0.4,0.5)$, 终止后 value 为 0, 则 residual 是 $(0.2,0.1,0.5)$, advantage 是 $(0.6,0.5,0.5)$. 前两个 token 获得正信号, 因为它们位于通向高终局 reward 的轨迹上. 这仍是粗粒度信用分配. 一条回答包含事实, 推理和风格多个因素, 单个标量会把它们一起广播给整段 token. Process reward 或可验证中间结果能提供更局部信号, 但需要新的数据与正确性假设. Sequence RM 的限制不应被 GAE 的数学形式掩盖.
Reward 尺度, whitening 与长度。 固定 sigmoid link 与 temperature 时, RM 的加性零点严格不可识别, 乘法缩放却会改变 pairwise probability. 不过输出尺度仍会被 label noise、temperature、正则、early stopping 和数据可分性强烈影响, 因而不同 checkpoint 的数值不能直接横比. PPO 又会直接使用 reward 数值. 常见做法是在冻结 policy 生成的校准集上估计均值与标准差, 把 RM 输出变换为近似零均值单位方差. 这个变换必须绑定 RM version 和校准分布. Policy 更新后重新用当前样本归一化, 会让目标随 policy 分布移动, 训练 reward 的跨步比较也失去意义. Advantage whitening 又是另一层变换. Reward normalization 改变 return 与 critic target; advantage whitening 只在 policy update 前重新缩放优势. 两者同时使用时, value loss, entropy 和 KL 系数的相对尺度都会变化. 报告"做了 normalization"不足以复现, 需要说明统计量来自哪里, 是否冻结, 按 token 还是 sequence 聚合.

Sequence reward 对每个回答只加一次, KL 成本却按 token 累加. 回答越长, 预期 KL 总成本通常越大. 这会自然形成长度压力, 与 RM 的长度偏置相互作用. 若 RM 偏爱长回答, 两者可能暂时平衡; 若额外再加长度 penalty, 就出现第三个长度信号. 应按长度分桶画 RM, KL 和 total return, 而不是只观察总均值.

## 5. PPO 更新与工程闭环

RLHF 中的 PPO 同时面对两个距离. Probability ratio 衡量当前 policy 离生成 rollout 的 old policy 多远, 用于有限复用一批数据; reference KL 衡量 policy 离长期 SFT 锚点多远, 进入 reward 或 regularizer. 两者分母, 更新频率和目标完全不同. 一次训练迭代需要保存完整版本血缘. Prompt 数据版本, policy version, tokenizer, chat template, decoding 参数, RM version, reference version, value version 和 reward 配方, 都会改变样本语义. 只保存 prompt 和 response 无法复算 PPO loss.

### 5.1. PPO ratio 与 clipped surrogate

Rollout 由 $\pi_{old}$ 产生. 对 token 动作 $y_t$,
$$
\rho_t(\theta)=
\exp(\log\pi_\theta(y_t\mid s_t)-
\log\pi_{old}(y_t\mid s_t)).
$$
PPO-Clip 最大化

$$
L^{clip}=\mathbb E_t\left[
\min(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t)
\right].
$$
若 $\hat A=2,\epsilon=0.2,\rho=1.3$, 原始项 2.6, 裁剪项 2.4, 目标取 2.4. 若 $\hat A=-2,\rho=0.7$, 原始项 -1.4, 裁剪项 -1.6, 目标取 -1.6. 平台只阻止 ratio 沿 advantage 建议方向继续走远, 不是把所有 ratio 硬限制在区间内.

### 5.2. 一批数据的生命周期

Rollout worker 用 policy version $v$ 生成回答, 保存 token, completion mask, old log-prob, stop reason 和 sample id. Reference worker 对同一 token 序列计算 reference log-prob. RM 可以读取原始文本或自己的 tokenizer 输入, 但返回结果必须按 sample id join. Value model 计算每个 prefix 的 $V_{old}$. Trainer 组合 token reward, 计算 fixed advantage 与 return, 再对 batch 做若干 minibatch epoch. 每个 epoch 中 `old_logp`, $V_{old}$, advantage 和 return 不变. 当 current-vs-old approximate KL 达到 PPO 早停阈值, 或达到 epoch 上限后, 发布 policy version $v+1$. 新 rollout 才使用新版本. 异步系统需要限制最大 version lag, 过旧样本即便能算 ratio, 也可能因大量 clipping 而几乎没有有效 policy 梯度.
Mask, tokenizer 与分布式对齐。 Policy 与 reference 必须共享同一个 token action space、chat template 和 prefix 边界, 它们的 log-prob 才能针对完全相同的 token id 逐位求 ratio 与 KL. Value 可以使用独立参数, 但输出时间步必须与 policy token 对齐. Sequence RM 可以独立重编码文本, 前提是保留 completion 边界并按 sample id 回接标量. Chat template 多一个 assistant header, EOS 插入位置不同或左右 padding 混用, 都会让 KL 和 reward 加到错误位置. 最小验收批可含两个样本. 样本 A 自然 EOS, mask 为 $(1,1,1,0)$; 样本 B 达到长度上限, mask 为 $(1,1,1,1)$ 且 `truncated=true`. A 的 RM reward 只加在第三个位置. B 在第四个位置收终局 reward 后, 是否 bootstrap 由任务语义决定. 将 padding log-prob 设成极端值, 最终 reward 和 loss 应完全不变. 令 current log-prob 等于 old log-prob, 所有有效 ratio 应精确为 1.
自适应 KL 与资源开销。 固定 $\beta$ 时, 不同训练阶段的 reference KL 可能差异很大. 一种控制方式是设目标 KL $K_{target}$, 当观测 KL 高于目标时增大 $\beta$, 低于目标时减小. 控制器更新要有时间尺度限制; 若每个 minibatch 都激烈调整, reward 定义会在同一 rollout batch 内变化, fixed advantage 假设也被破坏. 自适应 KL 只控制分布距离, 不直接保证回答质量. 一个 policy 可以在 KL 很小的情况下学到无效的格式偏好, 也可能需要较大 KL 才获得新能力. 目标 KL 应结合独立胜率, reward hacking 诊断和任务风险选择, 不能只追求控制曲线平滑.

资源上, policy training 需要参数, 梯度与 optimizer state; value 可共享骨干或单独部署; reference 与 RM 只前向, 可量化, 分片或卸载; rollout 还可能使用专用推理引擎. 逻辑上有四种角色, 并不要求四个同尺寸模型同时驻留. 真正的大头常是生成 token, 因为回答变长会同时增加 KV cache, policy rollout, reference/RM 前向和 PPO 训练位置数.

终局奖励如何落到 token 上也会改变优势估计。序列奖励通常加在回答末尾的有效 token，随后由 GAE 向前传播；KL 惩罚则逐 token 计算。把序列奖励平均摊到每个位置会让较长回答收到更多次监督，优化目标随之改变。长度截断必须区分「环境真正结束」与「采样预算耗尽」：前者的下一状态价值为零，后者仍可能需要 bootstrap。训练日志记录原始 RM 分数、逐 token KL、组合后 reward、有效 token 数和截断比例，这些量能分辨总 reward 上升来自回答质量、长度偏好还是终止规则。对同一批样本重算一次 token reward 与 return，并逐位比较离线结果和 trainer 输入，可以在正式更新前抓出 mask、终止位和奖励广播错误。再取一个自然结束样本和一个长度截断样本手算 GAE，能把 bootstrap 语义固定下来。这个小测试也覆盖 EOS 位置与 completion mask 的一致性。
