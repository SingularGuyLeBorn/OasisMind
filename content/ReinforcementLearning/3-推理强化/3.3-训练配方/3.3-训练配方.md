# 训练配方

推理强化学习很容易进入「开关越多越先进」的误区。动态采样、难度课程、熵控制、两侧裁剪、长度惩罚、KL、拒绝采样、不同粒度的归一化都可能有效，但它们也会彼此遮蔽。训练配方这一组文章不再只问目标函数长什么样，而是追问：在固定模型、数据、rollout 预算和评测口径后，一个组件是否仍带来稳定收益？如果收益只在某个未对齐的设置里出现，它就不能被归因于算法本身。

## 1. 先建立能工作的简单基线

### 1.1. 把配方拆成可识别的四层

训练配方可以按数据、估计器、代理目标和优化动态四层展开。数据层决定提示分布、每题采样数和轨迹长度；估计器层决定奖励怎样变成优势；代理目标层决定 ratio、裁剪、KL 与聚合；优化层包含 batch、学习率、动量和更新轮数。一次同时修改四层，即使最终分数提高，也无法判断收益来自哪里。

最小基线应保留目标必需部分。对可验证终局奖励，最简单的序列梯度可写成
$$
\hat g=\frac1B\sum_{i=1}^B
\hat A_i\sum_{t=1}^{T_i}\nabla_\theta
\log\pi_\theta(y_{i,t}\mid x_i,y_{i,<t}).
$$
这里仍需声明 $\hat A_i$ 的基线、序列与 token 的 reduce 口径以及样本来自哪个策略。先让这个估计器在小规模数据上满足符号、零奖励、全同组和复制样本测试，后续复杂组件才有可靠参照。

### 1.2. 有效批量由相关性决定

训练日志里的 batch size 常以序列数或 token 数表示，但梯度方差取决于独立信息量。同一提示的多条回答共享题目难度，长回答内 token 又共享一个序列优势。若把 $G$ 条同题回答视作 $G$ 个完全独立样本，会高估有效批量。

设单样本梯度方差为 $\sigma^2$，平均相关系数为 $\rho$，名义样本数为 $N$，均值方差近似为
$$
\operatorname{Var}(\bar g)=\frac{\sigma^2}{N}
\left[1+(N-1)\rho\right].
$$
提示数、每题组大小和每条回答长度应分别记录。固定生成预算下，增加提示数改善任务覆盖，增加组大小改善同题基线；最优分配取决于提示间方差和同题条件方差。盲目扩大组大小可能只得到更多相关轨迹。
多轮更新怎样消耗样本新鲜度。 rollout 来自行为策略 $\mu$，第一个优化 epoch 的当前策略与它接近，后续 epoch 则逐渐远离。定义有效样本量
$$
N_{\rm eff}=\frac{(\sum_i w_i)^2}{\sum_i w_i^2},
\qquad w_i=\frac{\pi_\theta(a_i\mid s_i)}{\mu(a_i\mid s_i)}.
$$
权重出现长尾时，$N_{\rm eff}$ 会远小于名义样本数。裁剪能限制极端权重对代理目标的贡献，却不会恢复已丢失的覆盖。每轮更新都应观察 ratio 分位数、clip fraction、KL 与 $N_{\rm eff}$，并在样本变得过旧前停止复用。

增加 epoch 的收益是每个 rollout 提供更多梯度步，代价是偏离 On-policy 分布。生成昂贵时容易倾向多复用，但这相当于用分布误差交换采样成本。比较配方时，必须同时固定或报告生成 token 和优化 token，不能只对齐更新步数。
优化器状态会保存异常的记忆。 Adam 的一阶与二阶矩为
$$
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\qquad
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2.
$$
一次异常大梯度即使被全局裁剪，仍可能改变多个参数的二阶矩，使后续有效步长 $m_t/(\sqrt{v_t}+\epsilon)$ 降低。奖励尺度、优势标准化或有效 token 数突然变化时，梯度分布也随之改变，历史矩估计会短暂失配。

从 checkpoint 恢复时只加载模型权重，会丢掉这种历史，学习率日程与数据游标也可能错位。可复现配方需要保存优化器、调度器、随机数状态、采样策略版本与数据位置。两次运行若恢复状态不同，曲线不能直接首尾拼接。

可靠实验应从最小闭环开始：固定参考模型和旧策略语义，对每个 prompt 采样同样数量的回答，用可复核验证器给奖励，构造组内优势，计算代理损失并完成更新。这个闭环需要先通过符号、mask、版本和数值验收。只有基线能够重复跑出一致趋势，增加技巧才有解释价值。

JustRL 的意义正在这里。它提醒我们，经过合理的数据、采样和工程配置后，简洁的单阶段 GRPO 基线可能已经很强。复杂方法需要与这类强基线比较，而不是与调参不足的实现比较。所谓「简单」也不等于随意：模型版本、训练 token、生成预算、最大长度、验证器、评测脚本和随机种子都要锁定。

## 2. GHPO：根据样本状态调整训练信号

固定配方默认所有 prompt 在同一训练阶段需要同样处理，但实际数据会随策略能力改变。某些题已经全对，某些题仍全错，还有些题正处在可学习区间。GHPO 一类方法尝试依据难度或组内状态调整引导方式，把计算分给仍能产生信息的样本。

这种自适应最需要防止反馈回路。训练策略决定采样结果，采样结果又决定难度标签，难度标签再影响下一轮训练。如果统计窗口太短，随机波动会被当成能力变化；如果只保留当前可学习样本，训练分布会逐步偏离原始任务。日志应保留调整前后的分布，并在固定评测集上独立判断能力，而不是用训练过滤后的奖励证明自己有效。

### 2.1. 技巧与陷阱：每个开关都改变了估计量

许多技巧表面上只是工程保护，实际会改变优化目标。过滤全同组会改变 prompt 权重；按长度归一会改变长短回答的相对贡献；clip-higher 会改变正负更新的不对称程度；去掉 KL 会扩大探索，也会失去参考策略约束；只保留格式正确样本会让格式验证器参与数据选择。

因此技巧不能按流行程度堆叠。每加入一个开关，都要写清它针对什么可观测症状、改变哪项统计量、预期让哪个监控指标变化，以及失败时如何回退。若没有症状却默认开启，后续收益与退化都难以解释。

一套实用消融顺序是：先固定数据和 rollout；一次只改变一个组件；保持有效训练 token 与生成 token 尽量一致；至少用多个随机种子；同时报告最终指标、学习速度与稳定性；最终做组合实验检查交互。若两个组件分别有效、组合却无额外收益，说明它们可能解决同一瓶颈，不能把单项增益直接相加。

## 3. 计算扩展：算力花在哪里

推理 RL 的总成本远不止反向传播。每个 prompt 的多次长文本生成、验证器执行、旧策略 log-prob 计算、训练端重算、跨节点传输和权重同步都可能成为主瓶颈。扩大训练规模时，需要区分 prompt 数、每题采样数、平均回答长度、更新轮数和模型规模；它们虽然都增加计算，却带来不同的信息增量。

增加 prompt 数扩大任务覆盖；增加组大小改善同题比较和探索；增加长度给复杂推理更多空间，也放大解码成本与信用分配难度；增加更新轮数提高样本复用，但让策略远离行为策略。若只用总 FLOPs 横轴，几条性质不同的扩展路径会被混在一起。

系统指标也应进入配方比较。生成吞吐、训练吞吐、GPU 利用率、验证器延迟、等待比例、样本过期程度和失败重试都会影响同样预算下真正进入更新的数据量。算法论文里的训练步数只有在 batch、序列长度、组大小和有效 token 都对齐时才可比较。

### 3.1. 阅读路线

先读 [GHPO](./3.3.1-ghpo.md)，理解随样本难度调整引导的收益与反馈风险；再读 [JustRL](./3.3.2-justrl.md)，建立强而简洁的对照；随后用 [技巧与陷阱](./3.3.3-技巧与陷阱.md) 检查每个常用组件到底改变了什么；最终进入 [计算扩展](./3.3.4-计算扩展.md)，把单次实验结论放进更大的预算与系统约束中。

这些方法解决的是不同层面的问题：GHPO 调整样本级引导，JustRL 给出简洁基线，技巧审计检查组件之间的耦合，计算扩展处理预算与吞吐。实验时先锁定统计口径和基线，再根据已经出现的症状引入对应机制，最终扩大规模。

## 4. 一份可执行的实验记录

每次实验应记录模型与 tokenizer 标识、数据快照、prompt 采样权重、生成参数、验证器版本、奖励分项、组大小、有效序列数、最大长度、优势归一化、loss 聚合、裁剪区间、KL 方向、优化器、学习率、总生成 token 与总训练 token。评测则同时保留准确率、格式通过率、长度、pass@k、能力回退和多次运行方差。

完整记录用于排除最常见的错误归因。推理强化学习的收益常常只有几个百分点，模板、采样温度、答案解析或 token 预算的小差异就足以制造同等幅度的变化。只有把这些变量固定或明确报告，训练配方才从经验口诀变成可以迁移的知识。

### 4.1. 配方迁移为什么经常失败

一套在数学短答案上有效的配置，迁移到代码、证明或长文本任务后可能立刻失效。数学验证器通常只关心最终答案，代码执行会遇到超时和环境依赖，证明任务有更长的形式约束，开放回答则没有唯一判定。奖励密度、回答长度与失败类型不同，最合适的组大小、过滤比例和最大长度自然也不同。

基础模型同样决定配方。一个已经具备稳定指令跟随和较强推理先验的模型，可能只需要较弱更新；能力较弱的模型生成组长期全错，组内方法没有足够信号。若不报告训练起点，只复制学习率和裁剪参数，所谓复现很可能是在解决另一道题。

## 5. 停止条件也是配方的一部分

训练不能只设置固定步数。应同时观察固定验证集、探索多样性、回答长度、熵、KL、全同组率与能力回退。奖励继续上升而固定验证集停滞，可能表示策略正在适应训练验证器；熵快速下降且 pass@k 下降，可能表示探索过早塌缩；长度持续增长但准确率不变，则说明额外计算没有转化为能力。

一个保守停止策略可以要求核心指标在多个评测周期不再改善，同时没有新的能力维度受益，再决定结束或更换数据。恢复训练时必须保存优化器、调度器、数据游标和策略版本，不能只从模型权重重启后仍把曲线接在一起。

### 5.1. 最终选择不追求统一答案

配方选择取决于瓶颈。如果大量组全同，先处理数据难度和采样；如果 ratio 极端，检查策略版本与聚合，再考虑裁剪；如果多奖励互相吞噬，处理分项校准；如果训练稳定但成本过高，优化 rollout 与验证器系统；如果简单基线已经达到相同效果，就没有理由承担更复杂的实现与调参面。

GHPO、JustRL、技巧审计和计算扩展共同覆盖了配方选择的四个坐标：样本难度、基线强度、组件作用和系统成本。具体配置由瓶颈决定，同一组超参数换到数据分布、生成长度或 rollout 系统不同的实验里，含义也会变化。

### 5.2. 学习率应和有效尺度一起看

同一个名义学习率，在不同 reduce 口径下对应不同更新幅度。若 loss 从序列平均改为 token 总和，梯度大致随有效长度增长；若优势从原始奖励改为单位方差，梯度尺度又随 batch 统计变化。比较配方时应记录参数更新相对权重范数
$$
u_t=\frac{\lVert\theta_{t+1}-\theta_t\rVert_2}
{\lVert\theta_t\rVert_2},
$$
并分层观察注意力、MLP 与输出头。全局范数可能被大参数层主导，掩盖小层的剧烈相对变化。$u_t$ 不能替代 KL，因为参数距离与策略距离没有固定对应；两者联合能区分优化器步长变化和函数输出敏感性变化。

梯度累积也会改变统计组成。把多个 micro-batch 累积后更新，数学上等价于更大 batch 的前提是 loss 分母一致、参数与归一化统计在累积期间不变。若每个 micro-batch 单独做优势标准化，先标准化再合并和整批标准化的结果不同；短序列与长序列分布不均时，按 micro-batch 求均值后再平均也会改变样本权重。
难度采样会改变优化目标。 训练常优先采样当前成功率居中的提示，因为全对或全错组缺少相对信号。设原始任务分布为 $q(x)$，课程采样分布为 $c_t(x)$，实际梯度估计针对的是
$$
J_{c_t}(\theta)=\mathbb E_{x\sim c_t,y\sim\pi_\theta}[R(x,y)].
$$
若不使用 $q(x)/c_t(x)$ 校正，训练目标随策略能力动态变化。这可以提高单位样本信息量，也可能让极难提示长期得不到数据。课程规则需要报告每个难度桶的进入率、有效组率与原分布评测，才能判断收益来自学习效率还是任务重加权。

按当前奖励选择提示还会形成反馈回路：偶然高估的提示被多采样，估计变准；偶然低估的提示被忽略，偏差得不到修正。给每个桶保留最低探索概率，或用置信上界同时考虑均值和不确定性，可以减轻早期噪声造成的永久淘汰。
消融需要检查组件交互。 设基础配置得分为 $S_0$，加入组件 A、B 后分别为 $S_A,S_B$，同时加入为 $S_{AB}$。交互量可写成
$$
I_{AB}=S_{AB}-S_A-S_B+S_0.
$$
$I_{AB}>0$ 表示互补，$I_{AB}<0$ 表示重叠或冲突。这个量仍受随机误差影响，需要多种子区间；它至少阻止把两个单项增益机械相加。优势归一化与学习率、序列聚合与长度过滤、KL 惩罚与 ratio clip 都可能有强交互。

当组件很多时，全因子实验成本过高，可以先按机制分组：数据组件、估计组件、约束组件和优化组件各保留一个基线，再对跨组组合做二阶交互。若复杂配方只在单一种子或单一预算下领先，证据还不足以支持增加长期维护成本。

预算缩放实验还应保持比较对象一致。扩大模型或 rollout 数时，固定学习率、batch 和更新轮数会同时改变每个参数看到的数据量与样本新鲜度。至少报告单位生成 token 的能力增益、单位优化 token 的增益以及固定总计算下的最终结果。三条曲线共同决定方法是在改善统计效率、优化效率，还是单纯消耗更多生成预算。若收益只在某个规模点出现，应先检查超参数是否随尺度重新匹配，再讨论方法本身的扩展规律。
