# JustRL: 固定配方的单阶段 GRPO 基线

论文信息如下：
- **标题**: JustRL: Scaling a 1.5B LLM with a Simple RL Recipe
- **作者**: Bingxiang He, Zekai Qu, Zeyuan Liu 等(清华大学, UIUC, 上海人工智能实验室; 通讯作者 Ning Ding, Zhiyuan Liu)
- **年份**: 2025 年 12 月
- **论文**: [arXiv:2512.16649](https://arxiv.org/abs/2512.16649), [作者代码仓库](https://github.com/thunlp/JustRL)

**前置知识**: GRPO, DAPO

过去一年小模型推理 RL 的工作不断叠加训练阶段, 动态调度和课程策略, JustRL 反着走: 单阶段, 超参数全程不动, 数据不过滤, 只在 veRL 默认 GRPO 上保留 clip-higher 一项技巧. 论文的主张很具体: 在两个 1.5B 蒸馏 backbone 上, 这个固定配方训四千步左右, 没有塌缩, 没有需要干预的长平台, 平均分不低于同期更复杂的方法, 估计 token 预算约为对手的一半; 把两种「标准技巧」加回基线, 分数反而下降. 这篇按开关逐项拆这个配方, 再给训练动态, 消融, 计算量对比和复现清单.

## 1. 动机: 复杂度是否必要

### 1.1. 小模型推理 RL 的技术堆叠

DeepSeek-R1 之后, 1.5B 级别的数学推理 RL 在一年内堆出一长串稳定化技术. STILL 调超参数并在训练中重置 KL 参考; DeepScaleR 把训练切成三段, 上下文逐段加长 8K→16K→24K; FastCuRL 扩到五段, 长短思维链交替压缩与扩展; ProRL 分八段并加计划式长度惩罚, ProRL-V2 换成余弦日程; BroRL 把每题 rollout 加到 512 条; POLARIS 做动态数据过滤加自适应温度; QuestA 用部分推理链做提示, 按难度排课程. 论文表 1 把这九类技术缩写成 EC, THP, TTP, RKL, LC, AT, RR, DS, ST 九列, 除 JustRL 外的每个模型至少勾三列, 勾法几乎不重样.

这种堆叠带来的直接后果是不可归因. 每个方法各自报告收益, 但各自的基线里已经躺着别人的技巧: 在复杂基线上加一个稳定化模块, 收益可能来自模块本身, 也可能来自对既有技巧副作用的补偿, 两种情形在论文的数字里无法区分. 论文给这组堆叠的诊断是一句话: 累积的「最佳实践」可能在互相打架, 而不是在对抗 RL 的根本困难. 多一次阶段切换就多一次数据分布和优化目标的跳变, 每加一个动态调度, 学习率和探索的有效含义就随时间变一次, 模块之间的交互没有人单独测过.

这些工作几乎都从蒸馏模型起步, 初始训练状态相近, 最终采用的组件组合却明显不同. 这说明技巧选择包含路径依赖: 先发表的配方成为后续工作的基线, 新增组件的收益以已有复杂度为条件, 组件越多越难单独归因. 一个不过滤, 不切换, 不动态调参的基线可以减少交互项, 使每项新增复杂度的影响更容易识别.

**新增组件本身也可能引入不稳定性**, 这是论文检验的假设. 如果简单基线没有出现 reward 塌缩, 熵漂移或长度爆炸, 对应干预就缺少明确作用对象, 甚至可能降低性能. JustRL 先完整训练简化基线, 再分别加入两种常用组件, 直接比较它们带来的收益与副作用.

### 1.2. 论文的主张与自我设限

论文的两个主张. 第一, 规模给足后的简单配方够用: 固定超参数在 DeepSeek-R1-Distill-Qwen-1.5B 和 OpenMath-Nemotron-1.5B 上分别训 4380 步与 3440 步, 九基准平均 54.87% 与 64.32%, 不低于九阶段的 ProRL-V2 (53.08%) 和使用课程学习的 QuestA (63.81%), 估计 token 预算约为对手的一半. 第二, 盲目加技巧有代价: 在基线上叠加 DAPO 式长度惩罚, 再叠加更强的验证器, AIME24 从约 55% 掉到约 45%, 伴随策略熵坍缩. 两个训练后的模型和代码随之公开, 这个基线可以被直接拿来当对照.

实验覆盖两个 1.5B backbone, 数学规则验证和四千步量级训练. 平滑曲线说明这套固定配方在这些条件下可以稳定训练, 无法证明简单方法在其他模型与任务上总是更稳, 也没有识别每个复杂技巧对不稳定性的独立贡献. JustRL 自己同样在基线上增加技巧做消融; 区别在于先测量病症, 再决定是否打开对应开关.

评估新技巧时, 基线需要有足够长且稳定的训练记录. 基线仍在明显波动时, 收益数字同时混入组件效应与随机训练波动. JustRL 提供的固定基线减少了后一项, 使组件贡献更容易通过受控消融识别.
配方: 开关逐项。 保留的 GRPO 主体。 优化器是 veRL 的默认 GRPO, 一行奖励一行判别. 奖励是二元结果分: 规则验证器判对 1 判错 0, 验证器直接沿用 DAPO 的轻量规则版, 不引 SymPy 之类的符号库. 组优势按 GRPO 的标准做法: 同一题采 $N=8$ 条, 组内均值标准差归一, 序列级优势广播到该条全部有效 token, old-policy 的 log-prob 用 stop-gradient, padding 不进 token 平均.

奖励侧的选择贴着任务走. 数学推理的 reward 可规则验证: 最终答案和 ground truth 比对即可, 不需要 reward model, 也不需要人工打分, hacking 面集中在答案格式, DAPO 验证器的解析规则已经覆盖. 二元结果分丢掉过程信息 (哪一步推导出错), 换来零成本和零标注偏差; 对组归一的优势估计, 丢过程信息的代价由同题多条对比补偿, 这也是 GRPO 与二元 reward 天然适配的原因 (GRPO 文章的组优势设计).

保留的唯一技巧是 clip-higher, 裁剪区间 $[0.8, 1.28]$, 即负侧 $\epsilon_{low}=0.2$, 正侧 $\epsilon_{high}=0.28$. 机制与 DAPO 的推导一致: 正优势样本的上界放宽, 正确的推理模式可以被强化到位而不在 $1+\epsilon$ 处被截停, 负优势的压制照旧. 单 token 的损失写成
$$
u_t=\min\left(r_t \hat A_i,\ \operatorname{clip}^{+}(r_t,\hat A_i)\,\hat A_i\right),
$$
其中 $r_t=\pi_\theta(y_t|y_{<t})/\pi_{old}(y_t|y_{<t})$ 是逐 token 的重要性比率, $\hat A_i$ 是第 $i$ 条回答的组优势, 正优势时 clip 上界取 $1+\epsilon_{high}$, 负优势时下界取 $1-\epsilon_{low}$. 论文把 clip-higher 算作基线的一部分, 表 2 的 "Clip Ratio Range [0.8, 1.28]" 是全套配置里唯一带技巧色彩的数字. 实现层面, 损失带负号交给梯度下降最小化, 与最大化裁剪代理目标完全等价; veRL 代码里的 loss 下降正是这套符号约定的结果.
移除的每一项。 表 2 的完整开关状态: 不用 KL loss, 不用 entropy regularization, train batch 256, PPO mini batch 64, micro batch 每 GPU 1, 学习率 $1\times10^{-6}$ 常数, 温度 1.0, rollout $N=8$, max prompt 1K, max response 15K, 总上下文 16K. max prompt 1K 加 max response 15K 恰好拼成 16K 总上下文, 训练长度边界由这两个数决定, 超界直接截断. 数据用 DAPO-Math-17k, 不做离线难度过滤, 不做在线动态采样, prompt 后缀固定一句「Please reason step by step, and put your final answer within `\boxed{}`」, 不调.

逐项看移除的理由. 去 KL: 数学规则 reward 的 hacking 面小, KL 锚定的价值从防 hacking 退化为防不稳, clip 已承担这部分, DAPO 同样去 KL (DAPO 文章 §6). 去熵正则: 熵控制由 clip-higher 承担, 目标函数里不再加项. 单阶段: 每多一个阶段就多一次分布与超参的跳变, 阶段切换本身是不稳定的来源. 固定超参: 自适应温度和动态 batch 改变的是学习率与探索的有效含义, 调它们的收益必须大于引入的时变因素才划算. 四项移除指向同一条原则: 每个开关都要有证据支持, 没有证据的开关默认关掉.

优化器的层次结构也要记全. train batch 256 拆成 4 个 PPO mini batch (每个 64), 每个 mini batch 在每张 GPU 上 micro batch 1, 32 张卡各算一份再聚合, 等效于 micro batch 32 的梯度累积. 一份 rollout 数据被 4 个 minibatch 复用一次, 这是 2.4 手算里 ratio 偏离 1 的直接来源, 复用次数越多, 数据的第二次访问离采样点越远, clip 触发的占比随之上升. 学习率 $10^{-6}$ 常数, 没有 warmup 与 decay 日程, 与「超参数全程不动」的约定一致, 代价是训练末段没有学习率退火提供的隐式收敛辅助, 末段涨分斜率变缓时, 先确认这不是自然现象再考虑动日程.

有一处容易读混. 论文表 1 在 EC (entropy control) 一列给 JustRL 打了勾, 表 2 又写 "Use Entropy Regularization: No". 两个表述不矛盾, 说的是两层东西: 表 1 的 EC 按机制归类, 把 clip-higher 视为熵控制手段; 表 2 描述目标函数, 确认 loss 里没有 $\mathbb{E}[\log\pi]$ 之类的熵正则项. 引用时分开: 机制层面 JustRL 有熵控制, 目标函数层面没有熵项.
手算一: 二元奖励下的组优势。 声明假设: $N=8$, 奖励按 $\pm1$ 编码 (论文没写具体编码, 图 2 的 reward 曲线落在 $[-1,1]$ 区间内, 与 $\pm1$ 相容), 优势 $\hat A_i=(R_i-\mu)/\sigma$ 用总体标准差, 除以 $N$, 与 veRL 一致. 取一组 8 条, 3 对 5 错. 第一步算均值: $\mu=(3\times1+5\times(-1))/8=-0.25$. 第二步算方差: 对的 3 条偏差 $1-(-0.25)=1.25$, 平方 $1.5625$; 错的 5 条偏差 $-0.75$, 平方 $0.5625$; 方差 $=(3\times1.5625+5\times0.5625)/8=(4.6875+2.8125)/8=0.9375$. 第三步标准差 $\sigma=\sqrt{0.9375}\approx0.9682$. 第四步优势: 对的每条 $\hat A=(1-(-0.25))/0.9682\approx1.291$, 错的每条 $\hat A=(-0.75)/0.9682\approx-0.775$.

再看无效组. 8 条全对或全错时 $\sigma=0$, 优势无定义, 实现掩成 0, 这组 8 条 rollout 的算力花掉, 梯度贡献为零. 无效组概率随组内通过率 $p$ 变化: $p^8+(1-p)^8$. $p=0.5$ 时 $2\times0.5^8\approx0.78\%$; $p=0.25$ 时 $0.25^8+0.75^8\approx10.0\%$; $p=0.1$ 时 $0.9^8+0.1^8\approx43.0\%$. DAPO 用动态采样过滤全同组再补采 (DAPO 文章 §3), JustRL 明确不这么做, 让无效组留在 batch 里, 换调度简单与 batch 尺寸恒定. **不过滤是一个明确的配方决定**: 代价是低通过率的题上近一半采样注定无效, 论文的判断是这笔固定浪费小于动态补采的系统复杂度与分布漂移.

手算一同时给出监控口径. 全同组占比曲线就是题库难度分布在训练中的镜像: 模型变强, 一批题从「有对有错」滑向「全对」, 占比上移; 某类题塌掉, 滑向「全错」, 同样上移. 训练时把这个占比画出来, 等于免费拿到一份难度迁移记录, 动态采样团队用过滤率看的东西, 不过滤的团队用同一个公式看, 成本只是统计. 另一个附带结论: $N=8$ 时 std 归一把优势幅度放大到 1.3 量级 (上面的 1.291), 与 $N=2$ 或 $N=4$ 相比, 组越大优势方差越小, 学习率的有效含义随 $N$ 变, 换 $N$ 要连带重调学习率.
手算二: clip-higher 的有效梯度区间。 沿用 2.3 的优势值, 看单 token 损失 $u=\min(r\hat A, \operatorname{clip}(r)\hat A)$ 随比率 $r$ 的变化, 假设当前策略刚更新过一步, $r$ 离开 1. 正确链某 token, $\hat A\approx1.291$: $r=1.10$ 时未触 $1.28$ 上界, $u$ 对 $r$ 的斜率就是 $1.291$, 梯度全额; $r=1.28$ 时到达平台起点; $r=1.30$ 时 min 结构取 clip 支, 斜率跳成 0. 错误链某 token, $\hat A\approx-0.775$: $r=0.85$ 时未到 $0.8$ 下界, 斜率 $-0.775$, 负梯度仍在压这条链的概率; $r=0.75$ 时越过下界, 斜率 0.

和对称裁剪 $\epsilon=0.2$ (区间 $[0.8,1.2]$) 并排: 正确链的 $r$ 落在 $1.2$ 到 $1.28$ 之间时, 对称裁剪已经截停, clip-higher 仍给全额梯度. 这个区间为什么重要: train batch 256 分成 4 个 PPO mini batch, 同一份 rollout 数据复用, 每条数据进入更新时策略已经偏离采样点, $r$ 系统性离开 1, 正优势样本的 $r$ 聚集区就在 1.2 附近. clip-higher 放开的恰好是信号最密的一段, 这也是 DAPO 消融里 Clip-Higher 单项贡献显著的同一处机制 (DAPO 文章 §2.3).

顺手留下两个检查口径. 其一, 训练时分别统计正优势触发上界与负优势触发下界的比例, 两侧严重失衡说明更新在「压错」上先饱和, 而「扶正」还有余量, 这是 clip-higher 针对的失衡. 其二, 画 clip 曲线时两个分支分开画, 只有 $A>0$ 的分支相对对称裁剪右移, $A<0$ 的分支纹丝不动, 画成整体右移会重新引入「对称区间」的错误直觉 (DAPO 文章 §2.3 的同一处提醒).
训练动态: 四千步无干预。 三条曲线各说明什么。 论文图 2 对 JustRL-DeepSeek-1.5B 的 4380 步做了逐段记录. 策略熵在后期于 1.0 到 1.6 之间震荡, 中枢 1.2 到 1.4, 没有系统性上移 (探索消失) 也没有系统性下移 (过早收敛). 平均训练 reward 从约 $-0.6$ 单调爬到约 $+0.4$, 有噪声但趋势连续, 没有需要打断的长平台或骤降. 平均响应长度从约 7000 到 8000 token 起步, 前 1000 步自发压到 4000 到 5000, 之后稳定, 全程没有长度惩罚项参与.

三条曲线要合起来读. 熵不降说明采样多样性还在, reward 单调升说明组内对比持续有信号, 长度收敛说明生成成本随训练下降: 同样 2048 条响应, 后期平均 4500 token 对起步的 7500 token, 每步 rollout 的 token 数几乎砍半, 四千步能跑完本身就有长度收敛的功劳. 时间顺序也有信息: 压缩发生在前 1000 步, 早于分数的主要爬升段, 说明长度是最先稳定下来的量, 后续涨分发生在长度已稳的区间里, 不存在「边涨分边失控变长」的耦合.

二元奖励没有直接惩罚冗长推理, 但同题组内对比仍可能推动长度下降: 固定生成预算下, 短而正确的链能够完成更多采样, 组内优势随之把概率质量推向这类回答. 这项机制与论文曲线相容, 尚未经过受控消融. 显式长度惩罚则直接创造长度与正确率之间的对抗压力 (见 DAPO 文章 §5). 两种机制可以通过长度 P50/P99 以及长度—正确率分桶曲线区分.

ProRL-V2 观察到长度漂移, 因此引入计划式余弦长度惩罚; BroRL 遇到平台期, 因此把每题 rollout 提到 512; 多个工作在 KL 发散时重置参考模型. JustRL 的四千步训练没有出现这三类现象: 长度自行收敛, 曲线没有平台期, 目标函数也不含 KL. 这只是跨工作的观测对照, 无法分离组件造成和缓解不稳定性的效应; 它能支持的结论限于当前初始条件下不需要对应干预.
稳定性依赖起点与数据分布。 论文把稳定性归给 clip-higher 与「规模给足」的组合. 规模侧的数字: 4380 步对 DeepScaleR 的 1750 步与 ProRL-V1 的 2450 步, 每步 256 题乘 8 条共 2048 条样本, 组优势的大样本方差被压平, 学习率 $10^{-6}$ 恒定, 不需要日程保护. clip-higher 侧: 正优势不被提前截停, 策略不用拿「模棱两可的稳妥」换稳定, 熵自然停在高位区间 (DAPO 文章 §2.2 对同一机制的解释: Clip-Higher 改的是优化路径不是目标函数). 两个因素各司其职, 缺一个都难说.

DAPO 从 Qwen2.5-32B 基础模型起步, 训练初期熵高, 长度失控风险明显, 因而 shaping 与动态采样有明确作用对象. JustRL 从蒸馏模型起步, 初始熵已经落在稳定区间, 相同组件反而可能干扰训练. 两项工作使用 clip-higher, 相同验证器和相同数据, 其余开关却方向相反, 原因在于基线动态不同. 迁移组件前应先确认自己的基线出现了对应异常.

两个 backbone 都是蒸馏过的推理模型, 起始熵落在可用区间, 没有从随机初始化或弱 SFT 起步; DAPO-Math-17k 对 1.5B 模型又以中等难度题为主, 无效组占比天然较低 (见 2.3 的手算). 因此稳定性同时来自配方, 模型起点与数据难度分布. 换成弱基座, 另一种任务或明显偏难的数据后, 同一配方可能出现不同动态. 小规模试跑应先测全同组占比与起始熵.

## 2. 结果, 计算量与消融

### 2.1. 九个基准的报告口径

硬件与时长: 两个 backbone 各用 32 张 A800-80GB, 训约 15 天. DeepSeek-R1-Distill-Qwen-1.5B 训 4380 步, 九基准平均 54.87, 高于 ProRL-V2 的 53.08 与 DeepScaleR 的 44.88, 九个里六个领先; backbone 自身平均 37.65, 相对起点提升约 17 个点. 分行数字如下 (论文表 3):

|---|---|---|---|---|---|---|---|---|---|
| Backbone | 29.90 | 22.40 | 63.82 | 84.90 | 34.65 | 45.95 | 13.44 | 30.94 | 12.89 |
| JustRL-DeepSeek | 52.60 | 38.75 | 91.02 | 91.65 | 51.47 | 67.99 | 21.98 | 52.71 | 25.63 |

评测协议本身也是配方的一部分: Pass@1 对每题 $N$ 次采样取平均, MATH-500, Minerva Math, OlympiadBench 三家用 $N=4$, 其余六家用 $N=32$; 评测温度 0.7, top-p 0.9, 生成上限 32K, 比训练的 16K 上下文宽一倍, 评测温度也低于训练采样温度 1.0, 两处温度要分开记录, 混用会让 Pass@1 不可比. 训练侧用规则验证器, 评测侧在规则判定之上再加 CompassVerifier-3B 模型判定器处理 false negatives. 这套协议意味着: 单次 greedy accuracy 与论文数字不可互换, 复现报告必须记录 checkpoint step, seed, 采样协议, 生成上限与判定器版本.

### 2.2. 计算量对比与量级复算

论文表 4 与表 6 用近似 token 预算对比总计算: JustRL-DeepSeek 为 $1.4\times10^8$ k, ProRL-V2 为 $2.8\times10^8$ k, BroRL 为 $6.8\times10^8$ k; JustRL-Nemotron 为 $1.1\times10^8$ k, QuestA 为 $2.6\times10^8$ k, 摘要据此给出「约一半计算」. 口径要小心: 对用动态采样的方法按 POLARIS 的 50% 过滤率估算补采成本, 这是估算不是实测, 单位 k 指千 token; 论文声明即使按 0% 过滤 (对 JustRL 有利的假设方向) 计算量仍相当或更低. BroRL 的 6.8×10^8 k 来自每题 512 条 rollout, 是把采样密度推到极致的路线; 这组对比的不是算法优劣, 是两种算力花法: 花在更多题上 (batch 256) 还是花在每题更多条上 (N=512).

用公开配置估算 DeepSeek 侧的计算量. 假设每步 256 题, 每题 8 条响应, 稳态平均响应长度 4500 token, prompt 平均 500 token. 每步 rollout 约为 $2048\times(4500+500)\approx1.0\times10^7$ token; 乘 4380 步得到 $4.4\times10^{10}$ token. 若把训练侧前向反向与 reference 前向合计为约 3 倍 rollout 成本, 总量约 $1.3\times10^{11}$, 与论文报告的 $1.4\times10^{11}$ 同一量级. 由于每步长度分布和分项成本没有公开, 这项计算只用于检查数量级.

Nemotron 一侧的对比方向相同, 细节不同. JustRL 训 3440 步, 比 QuestA 的 2000 步多七成, 总计算反而只有对方的四成出头 ($1.1\times10^8$ k 对 $2.6\times10^8$ k), 差距主要来自三处: QuestA 的上下文上限 32K 是 JustRL 的两倍, rollout N=16 是两倍, 动态采样按 50% 过滤率估算的补采成本再抬一截. 步数多而总算力少, 是「长训练 + 小每步」对「短训练 + 大每步」的直接对照, 论文用这组数字说明拉长训练阶段不需要以计算量为代价, 前提是每步的效率 (上下文长度, 每条长度) 控制住.
消融: 两个开关加回去。 论文在 JustRL-DeepSeek 上运行了超过 3000 步的改动实验. DAPO 式 overlong penalty 覆盖末尾 4K token: 响应进入 12K 到 16K 区间开始扣分, 到 16K 扣满. 配套的验证器版本换用 DeepScaleR 的规则, 目标是减少轻量验证的 false negatives.

AIME24 从约 55% 降到约 50%, 再降到约 45%. 相应版本的终点策略熵落到 0.5 至 0.6, 原配方维持在 1.2 至 1.4 区间.

长度惩罚给推理链施加压缩压力, 采样多样性随之收窄, 组内正确链趋同, 熵下降后有效探索信号变少. 第二组实验在长度惩罚之上同时更换验证器, 因而无法识别验证器的独立效应; 它只表明这项组合没有提升 AIME24. 三个设置均没有重复 seed 或误差区间, 所以约 55, 50 与 45 只能支持方向性判断: 两个新增开关没有兑现收益, 并伴随可观测的熵下降.

消融给出的通用原则是: 增加组件前, 先在基线上确认它针对的异常确实存在. 这个原则不依赖论文的具体模型规模. 异常不存在时保持基线不变; 异常出现时逐项打开对应组件, 并记录受控消融.

消融与主结果的口径差也要记下. 消融只报 AIME24 单基准, 九基准平均在消融组上没有报, 长度惩罚对另外八个基准的影响是未知数, 竞赛基准和课程基准对长度的敏感度不同, 单点结论外推到「长度惩罚全面有害」超出了这份消融能支撑的范围. 复现消融时, 至少把 MATH-500 与 BRUMO 补进评测集, 一个代表近饱和区间, 一个代表高区分度区间, 两点能把单点结论的轮廓补出大概.
实现。 教学实现。

```python
import torch

def group_advantage(rewards):
    # rewards: [B, N]，二元奖励 +1/-1；对应论文 rollout N=8
    # 返回: [B, N] 组优势，全同组（std=0）掩成 0
    mu = rewards.mean(dim=-1, keepdim=True)                 # [B, 1]
    sd = rewards.std(dim=-1, keepdim=True)                  # [B, 1]，总体标准差（除 N）
    adv = (rewards - mu) / (sd + 1e-8)
    return torch.where(sd > 1e-8, adv, torch.zeros_like(adv))

def justrl_loss(new_logp, old_logp, advantages, mask,
                eps_low=0.2, eps_high=0.28):
    # new_logp/old_logp: [B, T] 有效 token 的对数概率
    # advantages: [B] 序列级优势；mask: [B, T] 有效 token 为 1
    # 对应 clip-higher 目标: u_t = min(r_t * A, clip(r_t) * A)
    ratio = torch.exp(new_logp - old_logp.detach())         # [B, T]，old 侧截断梯度
    adv_t = advantages.unsqueeze(-1) * mask                 # 广播到 token
    upper = torch.where(adv_t > 0, torch.full_like(ratio, 1 + eps_high),
                        torch.full_like(ratio, float("inf")))
    lower = torch.where(adv_t < 0, torch.full_like(ratio, 1 - eps_low),
                        torch.full_like(ratio, float("-inf")))
    clipped = ratio.clamp(lower, upper)
    per_tok = torch.min(ratio * adv_t, clipped * adv_t) * mask
    per_resp = per_tok.sum(-1) / mask.sum(-1).clamp(min=1)  # 每回答先按长度平均
    return -per_resp.mean()                                 # 再对回答等权平均

def check_without_model():
    # 手算一的对照组: 3 对 5 错，N=8
    rewards = torch.tensor([[1., 1, 1, -1, -1, -1, -1, -1]])
    adv = group_advantage(rewards).squeeze(0)               # [8]，逐格对照手算一
    T = 5
    new = torch.zeros(8, T, requires_grad=True)             # r = 1，落在未裁剪区
    old = torch.zeros(8, T)
    mask = torch.ones(8, T)
    loss = justrl_loss(new, old, adv, mask)
    loss.backward()
    expect = -adv / (8 * T)                                 # 清单第 3 条的闭式解
    assert torch.allclose(new.grad,
                          expect.unsqueeze(-1).expand(8, T), atol=1e-6)

```
这段代码对应论文表 2 的 loss 侧全部开关: 无 KL 项, 无熵项, 裁剪区间 $[0.8, 1.28]$ 即 `eps_low=0.2`, `eps_high=0.28`, 归约沿用 GRPO 默认 (每回答先按长度平均, 再对回答等权), 没有用 DAPO 的 token-level 归约 (DAPO 文章 §4). rollout 侧的配置不进 loss: $N=8$, batch 256, mini batch 64, 学习率 $10^{-6}$ 常数, 温度 1.0, 总上下文 16K, 这些是调度参数, 与 loss 的验证无关. 实现里两个容易错的点: 其一, `std` 用总体标准差 (除 $N$) 而非样本标准差 (除 $N-1$), 两者差一个因子 $\sqrt{8/7}\approx1.07$, 优势整体缩放, 等效于微调学习率; 其二, `torch.std` 默认总体标准差, 换手写实现时别把分母写成 $N-1$.

`check_without_model` 不加载任何模型: `new_logp` 与 `old_logp` 取零, 比率恰为 1, 落在未裁剪区, 梯度有闭式解 $-\hat A/(N\cdot T)$, 与 eps 取值无关. 把 `new` 整体加 $\log 1.3$ 或 $\log 0.75$, 对应 token 的梯度应立即变 0, 清单第 2 条由此落地; 把 `rewards` 换成全 1, `group_advantage` 输出全 0, 梯度全 0, 清单第 1 条落地. 梯度对数与手算一的 1.291 和 -0.775 逐格对上, 实现和手算就互为印证.
不依赖模型的验证清单。 以下四条只喂合成对数概率与合成奖励, 不需要语言模型, 也不依赖随机种子:

1. 全同组零梯度. 取 `rewards = torch.ones(4, 8)`, 过 `group_advantage` 后应为全 0, 进一步 `justrl_loss` 对任意 `new_logp` 的梯度恒为 0. 这条验证 2.3 的无效组掩码路径, 也验证「全对组不贡献梯度」这一与动态采样相对的设计决定.
2. 裁剪边界位置. 固定 $\hat A=+1$, 扫 $r\in\{1.27, 1.28, 1.29\}$, autograd 给出的 $\partial u/\partial r$ 应在前两点为 1, 第三点跳变为 0; 固定 $\hat A=-1$, 扫 $r\in\{0.81, 0.80, 0.79\}$, 前两点斜率 $-1$, 第三点 0. 这条直接验证 $[0.8, 1.28]$ 两个端点落在实现里.
3. $r=1$ 处的梯度恒等式. 令 `new_logp == old_logp` (即 $r=1$), 损失对 `new_logp` 的梯度应恰为 $-\hat A/(N\cdot T_i)$ 每条回答 (未经裁剪区), 与 eps 取值无关. 这条验证 stop-gradient 接对了位置: 若 old 侧没 detach, 该恒等式立即破坏.
4. mask 不变量. 对任意 padding 位置的 `new_logp` 加一个常数, `justrl_loss` 的返回值应分毫不变. 这条验证 padding 既不进分子也不进分母.

四条全过, loss 侧实现即与配方对齐; 再补一条 rollout 侧的系统级检查: 记录每个 batch 的全同组占比与熵, 对照 2.3 手算的概率公式与图 2 的熵区间. 系统级检查不需要等训练出结果才有意义, 前 100 步的曲线形状 (熵的起点, 占比的初始水平) 就能判断初始条件是否落在论文的温和区间内.

清单的执行顺序也有讲究: 先跑第 1 条和第 4 条 (纯张量操作, 秒级), 再跑第 2 条和第 3 条 (需要 autograd, 分钟级). 前两条挂了说明掩码或归约有错, 后两条挂了说明 clip 或 detach 接错, 按挂的位置直接定位, 比调一通 loss 曲线再回头找快得多. 这个排错顺序对应一个事实: 归约与掩码是结构性错误 (结果整体不对), clip 与 detach 是接线错误 (特定区间不对), 两类错误的症状不同, 检查的次序应该利用这个区别.
边界, 定位与选型。 不能外推的结论。 三条常见外推都不在论文支持范围内. 「单卡可训 7B」: 论文是 32 张 A800-80GB 训 15 天, 与单卡场景无关. 「技巧普遍有害」: 消融只动两个开关, 且第二个开关与长度惩罚纠缠, 被证伪的是这两个开关的叠加, 不是技巧这一大类. 「固定配方换任务仍稳」: 全部是数学规则验证场景, 奖励 hacking 面小, 起点是蒸馏模型; 换 reward model 打分或代码任务, 熵动态与最优裁剪区间都会变. 论文真正支持的范围是: 两个 1.5B backbone, DAPO-Math-17k, 规则验证, 四千步量级, 在这套边界内「固定基线可以长时间平滑训练」.

GRPO 定义组优势与 ratio 裁剪, JustRL 保留算法结构, 只固定训练配置. RLOO 去掉 importance ratio 与裁剪, 改用 leave-one-out 基线; JustRL 则保留 ratio 与 clip. **这里的简单指减少配置决策, 不表示删去所有机制.** DAPO 提供验证器, 数据集与 clip-higher; JustRL 关闭动态采样, token-level loss 和 overlong shaping, 保留 clip-higher, 并延长训练步数.

对社区的直接价值在基线本身. 推理 RL 论文里的对照基线质量参差, 相当一部分复杂方法的收益是相对于一个没被调好的基线报告的; JustRL 把「简单 + 验证过 + 开源 + 四千步」四个条件凑齐, 之后的工作可以拿它当共同参照, 声称超过它之前, 先说明自己加了哪个开关, 治什么病. 这个用法不依赖论文的任何具体数字, 依赖的是它作为参照系的确定性.

更强的验证需要三组补充实验. 多个随机种子可以为平滑曲线给出波动区间; 非蒸馏起点可以分离配方效应与温和初始化; 调高初始温度或换成更难题库, 则能观察固定配方在高熵或高无效组占比下的行为. 这些实验分别检验随机波动, 模型起点和数据难度三个变量.
什么时候照抄, 什么时候逐项决策。 这套固定配方适合蒸馏过的推理基座、规则可验证任务、足够跑四千步的算力，以及无效组占比和初始熵都健康的小规模试跑. 条件齐全时可以直接从固定配方起步, 出现问题后按 §4.3 逐项加入技巧并保留消融. 条件不齐时则回到 §2 重选开关: 弱基座先查初始熵, 难题库先估无效组占比, 长输出任务先确定长度口径, reward 容易被 hack 的任务先加 KL 或更换验证器.

训练判断依赖三个信号: 全同组占比 (2.3 的概率公式给出预期区间), 熵区间 (图 2 的 1.0 到 1.6) 和长度 P99 距 15K 上限的余量. 三者都在健康区间时无需增加稳定化组件; 某项越界后, 只打开直接对应的开关. 验收顺序是 §5.2 的四条 loss 不变量, 前 100 步 reward 与熵趋势, 以及 MATH-500 和 AIME24 两个子集的端点. 三层都通过后再运行九基准全量评测.

固定配方也要求固定数据消费口径. Batch 256 指 prompt 数, 每题 8 条 rollout 后实际生成 2048 条回答; mini batch 64 若按 prompt 切分, 每次更新包含 512 条回答, 若框架按回答切分则只有 64 条. 两种实现的梯度方差和一次 rollout 的复用次数不同. 日志中应同时记录 prompt batch、response batch、有效 token 数和每条 rollout 被消费的次数, 这样学习率 $10^{-6}$ 与 clip fraction 才能跨实现比较.

长序列下还要把吞吐变化与配方效果分开. 回答长度增长会降低每步可容纳的样本数, sequence packing 又会改变 padding 比例; 若训练后半程吞吐下降, 固定 optimizer step 并不等于固定 token 预算. 评测 checkpoint 最好同时按 step 和累计有效 token 对齐, 否则更长回答可能仅因消耗更多计算而获得额外训练量, 被误认为固定配方在后期继续提升.

若显存限制迫使 micro batch 改变, gradient accumulation 要同步保持有效 prompt 数与 response 数不变. 日志里同时给出两种计数, 才能确认配置仍与基线一致.

## 3. 「最小配方」到底最小在哪里

JustRL 的最小化对象是训练过程中的决策数量, 不是把 RLVR 压缩成一条损失. 它仍然需要两份策略状态、同题多回答采样、规则奖励、组内标准化、重要性比、非对称裁剪、长序列并行与分布式 rollout. 省掉的是阶段切换、动态难度筛选、显式长度塑形、KL 项、熵奖励和随训练变化的超参数. 因而「简单」更准确的含义是「固定且可复现」.

把单步数据流列开, 配方共有六段. 第一, 从 DAPO-Math-17k 取 256 个 prompt. 第二, 每题用温度 1.0 采八条回答. 第三, 轻量规则验证器给终局二元分数. 第四, 同题八条分数求均值与标准差, 得到序列级优势. 第五, 优势广播到回答 token, 与新旧策略比一起进入 $[0.8,1.28]$ 的裁剪目标. 第六, 以常数学习率更新, 随后进入下一批. 固定配方的可解释性来自每一步都能单独记录, 不需要先判断当前处于哪个课程阶段.

### 3.1. 固定不等于没有时间变化

超参数固定, 数据分布仍会随策略变化. 模型变强后, 同一道题八条回答中正确条数上升; 平均回答长度可能缩短; ratio 分布会随每次 PPO 更新变化; 全错组逐渐迁往混合组, 混合组又逐渐迁往全对组. 固定的是外部控制器, 内部状态仍是一套动态系统.

这一区分很重要. 若训练后期全对组增加, 有效梯度密度会下降, 即使 batch、学习率和温度完全不动, 每步实际更新强度也在变化. 固定超参数因此不等于固定有效学习率. 可定义
$$
\eta_{\mathrm{eff},t}=\eta\cdot
\frac{N_{\mathrm{active},t}}{N_{\mathrm{total},t}},
$$
其中 $N_{\mathrm{active},t}$ 是优势非零的有效 token 数. 这只是诊断量, 不是论文使用的新学习率; 它能说明同样的 $10^{-6}$ 在不同训练阶段对应多少有效梯度.

### 3.2. 删除组件也会留下隐式替代物

没有 KL loss, 仍有 PPO clip 约束策略移动; 没有熵正则, 温度 1.0 的采样与 clip-higher 仍保留探索; 没有长度惩罚, 上下文上限与终局正确奖励仍会间接选择长度; 没有动态采样, 固定题库与组内全同零优势仍在自动降低过易和过难题的梯度权重. JustRL 的结果不能解读成这些目标完全无人承担, 更准确的说法是显式组件被已有机制部分代替.

例如全对题的优势为零, 等价于它在该步自动退出更新; 全错题同样退出. 这形成一条隐式的中间难度课程, 只是采样成本已经支付, 题目也没有被数据加载器剔除. 动态采样会补入另一道可能有效的题, JustRL 则接受这部分空梯度, 以换取实现与分布的稳定.
奖励、优势与估计误差。 规则奖励看似只有 0 和 1, 实际由答案抽取、规范化、等价判断和异常处理组成. `\boxed{}` 是否完整、分数是否约分、集合顺序是否无关、单位是否允许、多个答案如何对齐, 都会改变最终标签. JustRL 使用轻量 DAPO verifier, 没有用符号系统替每个表达式做完整代数证明. 这种选择速度快, 也使误差集中在表达式等价与格式边界.

设真实正确标签为 $Z\in\{0,1\}$, 验证器输出为 $R$. 假阴性率 $\alpha=P(R=0\mid Z=1)$, 假阳性率 $\beta=P(R=1\mid Z=0)$. 模型真实正确率为 $p$, 则观测正奖励率为
$$
\tilde p=p(1-\alpha)+(1-p)\beta.
$$
假阴性会把正确链当作负优势, 假阳性会强化错误链. 对组相对方法, 错误还会经过组均值扩散: 一条假阳性提高自己的优势, 同时压低组内另外七条回答的相对优势. 验证器的一次误判影响整组基线, 风险高于逐样本独立监督.
二值编码不改变标准化优势。 现稿用 $\{-1,+1\}$ 手算, 代码实现可能使用 $\{0,1\}$. 对组内标准化, 两者给出相同优势. 令 $R'=2R-1$, 则
$$
\frac{R'_i-\bar R'}{s_{R'}}
=\frac{2R_i-1-(2\bar R-1)}{2s_R}
=\frac{R_i-\bar R}{s_R}.
$$
因此奖励曲线的纵轴会变, 策略梯度的标准化优势不变. 这个结论依赖奖励只有仿射变换且标准差非零. 若加入格式分、长度罚或连续验证分, 排序和间距改变, 优势也会改变.
成功条数决定优势幅度。 对 $G$ 条二值奖励, 其中 $k$ 条成功, 成功率 $u=k/G$. 使用总体标准差时, 成功回答优势为
$$
A_+=\sqrt{\frac{1-u}{u}},
$$
失败回答优势为
$$
A_-=-\sqrt{\frac{u}{1-u}}.
$$
$G=8$ 时, $k=1$ 得 $A_+=\sqrt7\approx2.646$, $A_-=-1/\sqrt7\approx-0.378$; $k=4$ 时两侧恰为 $\pm1$; $k=7$ 时镜像翻转. 稀有一侧拥有更大的单样本优势, 多数一侧则靠数量抵消. 在每条回答等权且长度相同的理想条件下, 一组优势之和为零.

回答长度不同后, token 级累计贡献未必抵消. 唯一正确链若长 8000 token, 七条错误链各长 1000 token, token-level 归约会让正侧权重占明显优势; response-level 归约则保持八条轨迹等权. JustRL 沿用默认 GRPO 的响应级处理, 这项选择与奖励公式同样属于配方.
组大小同时控制探索与方差。 $G=8$ 不只是显存参数. 单次成功率为 $p$ 时, 混合组概率为
$$
P_{\mathrm{mix}}=1-p^G-(1-p)^G.
$$
$p=0.1$ 时, $G=4$ 的混合概率约 $34.4\%$, $G=8$ 约 $57.0\%$, $G=16$ 约 $81.5\%$. 增大组大小能让低成功率题更容易出现至少一条正确回答, 却线性增加采样量. BroRL 把每题 rollout 推到 512, 选择的是极高组内探索; JustRL 取 8, 把预算分给更多题与更多步.

固定总回答数 2048 时, $G=8$ 对应 256 道题, $G=16$ 只剩 128 道. 前者覆盖更多题目, 后者提高每题发现稀有成功链的概率. 哪一侧更重要由通过率分布决定. 若大多数题 $p$ 位于 0.2 到 0.8, 八条已足够形成混合组; 若大量题 $p<0.01$, 八条几乎总是全错, 增大组或降低题目难度才会带来信号.
组内相关性削弱有效样本量。 八条回答共享 prompt、模型与解码设置, 并不独立. 用组内奖励相关系数 $\rho$ 近似, 有效样本量可写成
$$
G_{\mathrm{eff}}\approx\frac{G}{1+(G-1)\rho}.
$$
若 $G=8,\rho=0.2$, 有效样本量只有约 3.33; $\rho=0.5$ 时约 1.78. 温度过低、固定首 token 或高度模板化的蒸馏模型都会提高相关性. 这解释了为什么单纯增加 rollout 数有时收益很小: 新回答只是重复同一种错误路径.

可用答案去重率、推理步骤编辑距离或首个分叉位置估计多样性. 如果全错组的文本也高度相似, 问题在探索; 如果路径很多却全部错, 题目可能确实超出能力. 两种情况都表现为零优势, 对策并不相同.
clip-higher 与训练稳定性。 标准 PPO 裁剪通常给新旧概率比一个对称区间. JustRL 使用 $[0.8,1.28]$, 只放宽正优势方向的上界. 对 $A>0$, 当 $r>1.28$ 后梯度被截断; 对 $A<0$, 当 $r<0.8$ 后梯度被截断. 这里的非对称发生在更新约束, 没有改变奖励和优势.

为什么它可能维持探索? 在组相对训练中, 一条稀有正确链常有较大正优势. 对称裁剪若很早截停这条链, 负样本的压制可能相对更充分, 概率质量向少数已有模式集中. 放宽正侧允许成功链获得更长的更新区间, 尤其当 mini-batch 复用让 ratio 已偏离 1 时. 不过这只是机制解释, 熵变化还受数据、温度和回答长度影响, 不能从裁剪区间单独推出.
一个带长度的裁剪手算。 设组内一条正确回答优势 $A_+=2.646$, 长 2000 token; 七条错误回答优势 $A_-=-0.378$, 各长 500 token. 某次更新后, 正确链 token 的平均 ratio 为 1.24, 错误链为 0.82. 在对称 $[0.8,1.2]$ 下, 正确链大部分 token 已触上界; 在 $[0.8,1.28]$ 下仍能更新. 错误链两种配方都未触下界.

若下一次更新把正侧推到 1.30, 负侧压到 0.78, 两侧都进入平台. 此时继续对同一 rollout 做 PPO epoch 不再产生主要梯度, 多次复用数据只是增加计算. clip fraction 按正负优势拆开记录, 能直接看到数据复用何时失效. 固定 mini-batch 配置之所以重要, 正是因为它决定每条样本在离采样策略多远时进入更新.
clip 无法约束的变化。 裁剪只作用于采样到的 token. 模型在未采样 token、其它 prompt 或长链后部的概率变化没有直接边界. 参数共享使一次更新可以改变许多未观察位置, 这也是 KL 有时仍有价值的原因. JustRL 在数学蒸馏模型上没有观察到需要 KL 干预的失稳, 并不意味着 clip 与 KL 在所有场景等价.

奖励容易投机时, 策略可能在少数可获分格式上快速集中, 即使每个已采 token 的 ratio 都受 clip 控制, 多步累积仍会远离起点. 监控参考模型 KL、词表熵和答案格式分布可以提前发现. 配方里没有把 KL 加进目标, 诊断日志仍然可以离线计算它.
稳定曲线需要多个尺度。 reward 单调上升、熵保持区间、长度趋稳是论文展示的主要证据. 复现时还应记录 ratio 均值与尾部、两侧 clip fraction、梯度范数、全错/混合/全对组比例、验证器异常率. reward 平滑可能来自题目抽样平均, 局部题型已经退化;总体熵稳定也可能掩盖某些 token 位置塌缩. 按题型、长度桶和训练阶段切片, 才能看清稳定性发生在哪一层.

## 4. 数据、模型与计算如何归因

JustRL 的结果由四个对象共同产生: 两个已经蒸馏出推理行为的 1.5B backbone, DAPO-Math-17k 的难度与格式, 规则奖励的低噪声, 以及 32 张 A800 持续约十五天的训练规模. 固定配方证明这些条件组合起来足以得到强结果, 还没有把四项贡献逐个分离.

### 4.1. 蒸馏起点提供了什么

DeepSeek-R1-Distill-Qwen-1.5B 与 OpenMath-Nemotron-1.5B 在 RL 前已经会输出较长推理链、遵循答案格式, 也拥有一定数学成功率. 因此八条采样较容易形成混合奖励组, 二元终局奖励可以直接区分好坏. 从普通 base model 起步, 八条可能全错或格式不可解析, 相同优势估计器会长期给零.

检验起点贡献最直接的实验, 是在同架构的 base、SFT、distill 三个 checkpoint 上使用完全相同配方与 token 预算. 报告前一百步全错率、格式通过率、熵与最终零样本准确率. 若只有蒸馏起点稳定, 「简单配方」的适用条件就应明确包含已有推理先验.
