# 验证与长程

数学题、代码题和形式化证明让推理强化学习快速发展，因为结果可以用规则、测试或证明检查器验证。相比训练一个主观奖励模型，可验证奖励更便宜、更稳定，也更容易批量运行。但「答案能验证」并不等于「推理过程已经被监督」。当任务从单轮答案扩展到工具调用、多轮搜索和长程 Agent，终局成败与中间几十乃至几百个动作之间隔着巨大的信用分配距离。

这一组文章沿着奖励信息逐渐稀疏的方向展开。RLVR 研究可靠的终局验证如何驱动在线探索；OREO 研究已有离线推理轨迹怎样被价值一致性利用；长程信用分配进一步讨论多轮环境里，哪一步真正造成成功或失败。三者共享同一个核心问题：我们观察到的反馈，究竟能约束策略的哪些部分？

## 1. 可验证奖励的优势与盲区

设回答 $y$ 经验证器 $V(x,y)$ 得到奖励。若验证器能够确定数学答案、代码测试结果或形式证明是否合法，那么奖励噪声通常低于开放式偏好模型。模型可以生成大量候选，在成功与失败之间学习相对方向。DeepSeek-R1 一类工作展示了这条路线在推理任务上的潜力。

验证器仍有边界。答案解析可能把等价表达判错；公开测试可能被硬编码；格式奖励可能压过内容奖励；执行器超时可能被误记为逻辑错误；证明检查器只能确认形式合法，不能保证解释清晰。更重要的是，终局奖励无法直接指出错误发生在哪一步。模型可能通过偶然路径得到正确答案，也可能在正确推理后因最终的格式问题得到零分。

因此验证器必须像训练代码一样测试。至少要准备确定正确、确定错误、等价表达、边界格式、恶意输出、超时和资源异常样例，并区分「任务失败」「解析失败」「执行失败」与「基础设施失败」。把所有异常统一记零，会让策略学习系统故障的偶然模式。

## 2. 在线 RLVR：探索带来新轨迹

在线训练的价值是策略能不断产生当前数据集里没有的新轨迹。模型能力变化后，采样分布也随之变化，训练可以逐步进入更难区域。但在线 rollout 昂贵，而且行为策略与训练策略的版本差会造成 off-policy 问题。每条样本应携带策略版本、生成参数、模板、旧 log-prob、奖励分项和验证状态，训练端才能判断数据是否仍可用。

pass@k 与单次准确率也要分开。增加采样次数可能显著提高至少一次成功的概率，却不代表单次策略更可靠。训练若只保留成功轨迹，还会放大选择偏差。评测应同时报告 pass@1、pass@k、平均生成成本与失败类型。

### 2.1. OREO：离线轨迹不能凭空探索

离线推理优化利用已有轨迹，省去持续在线生成的成本，也便于复现实验。OREO 把 soft Bellman consistency 引入多步推理，希望从轨迹内学习价值与策略关系。它的关键约束来自数据覆盖：离线集合没有出现过的行为，算法无法仅靠目标函数发现；若轨迹集中在某个模型或某种解题风格，学到的价值也可能只在该分布内可靠。

离线数据必须保留完整生成上下文。仅保存最终文本和总奖励不够，还需要 prompt、步骤边界、行为策略信息、截断原因、验证细节和数据筛选规则。否则价值目标里的状态与动作无法稳定重建，训练结果也难以审计。

## 3. 长程 Agent：奖励要穿过很多决策

### 3.1. 长程的难点是因果链，不是字符串长度

一条轨迹包含状态 $s_t$、动作 $a_t$、环境转移和可能延迟很久才出现的终局奖励。长回答如果没有中间环境变化，仍可视作一次序列生成；多轮 Agent 即使文本不长，只要早期工具选择会改变后续可见信息，就已经形成长程决策。判断 long-horizon 的核心指标是动作对远期状态分布的影响。

终局成功率目标写成
$$
J(\theta)=\mathbb E_{\tau\sim p_\theta(\tau)}[R(\tau)].
$$
score-function 梯度把同一 $R(\tau)$ 乘到整条轨迹的动作对数概率上。随着步数增加，无关动作也携带同样噪声，方差通常上升。状态价值 $V(s_t)=\mathbb E[R(\tau)\mid s_t]$ 能构造时间相关 baseline，但它必须理解工具结果、剩余预算和任务进度；只看文本表面的 critic 很容易遗漏真实环境状态。

### 3.2. 环境状态决定 Markov 性

工具调用后的网页内容、文件变化、数据库写入和权限状态都可能影响未来。若这些信息没有完整进入观测，同一个可见上下文对应多个真实状态，价值函数学到的是混合平均。重放轨迹时只保存模型消息而不保存环境快照，也无法复现原转移。

可复现记录至少包含动作参数、工具版本、返回值、时间与随机种子，以及有副作用操作前后的状态标识。环境无法完全快照时，应区分确定性重放、近似重放与不可重放任务。离线学习依赖这些区分，因为旧轨迹的下一状态可能已不再由当前环境产生。

超时与任务终止也要分开。真正 terminal 表示没有未来回报，时间预算用尽造成的 truncation 只说明采样停止。价值 target 若把所有截断都当终止，会系统性低估靠近预算边界的状态；若无条件 bootstrap，又可能为已失败任务保留虚假价值。
过程奖励会重新定义任务。 把最终成功拆成里程碑 $m_1,\ldots,m_K$ 可以提供密集信号，但里程碑权重会改变最优策略。若「调用更多工具」「写出更长计划」本身得分，策略可能积累过程分而绕开最短成功路径。保持策略不变的一类塑形采用势函数：
$$
F(s_t,a_t,s_{t+1})=\gamma\Phi(s_{t+1})-\Phi(s_t).
$$
沿轨迹求和时中间势项抵消，在适当边界条件下不改变原任务最优策略。实际过程评分通常不满足该形式，因此需要把「加速学习」与「改变偏好」分别评估。

过程验证器也会出错。一个局部步骤形式正确，可能建立在更早的错误假设上；一次工具调用成功返回，不代表它对目标有用。可以用终局结果校准过程分，按前缀继续采样估计成功概率，再检查过程标签与经验价值的一致性。
离线轨迹中的反事实缺口。 离线数据只记录行为策略采取的动作及其结果。对未执行工具、未访问分支和失败后可能的恢复路径没有直接反馈。重要性采样要求目标策略动作被行为策略覆盖，长轨迹权重连乘后方差会迅速扩大，实际系统很难靠纯校正支持大幅策略改变。

行为克隆可以把策略拉到数据支持区域，离线价值学习尝试比较已有动作，在线 rollout 再探索新分支。三者组合时需要标明每批数据来源；旧轨迹数量巨大并不代表对当前策略有高信息量。环境版本变化后，历史成功轨迹甚至可能成为错误监督。

评估恢复能力需要专门构造中间失败。只从任务起点测试，成功率会把规划、执行与恢复混在一起；在固定步骤注入工具错误、无效结果或上下文污染，可以测量策略能否识别失败并回到可行路径。恢复测试比单纯增加轨迹长度更接近长程信用的实质。

Agent 任务包含搜索、阅读、写代码、运行工具、观察结果、修正计划等动作。最终成功可能依赖早期一次正确检索，也可能由后期一次错误覆盖文件而失败。把同一个终局奖励复制给全部 token，虽然实现简单，却给每一步同样责任，方差极高；过度依赖过程奖励，又可能把人为设计的局部指标变成新的投机目标。

长程信用分配需要同时考虑时间尺度和动作层级。token 是模型的原子输出，但工具调用、子任务和阶段目标更接近可解释决策。实际系统可以在多个层次保存轨迹：token log-prob 用于优化，工具调用与观察用于重放，阶段里程碑用于辅助奖励，最终任务结果用于整体约束。不同层次的奖励不能未经校准直接相加。

多轮环境还引入非平稳性。网页会变化，工具可能失败，搜索结果有随机性，外部服务有延迟。一次失败不一定来自策略。训练数据必须区分环境错误和决策错误，并记录可重放所需的版本与输入；否则模型会因基础设施噪声受到惩罚。

## 4. 阅读顺序

[RLVR](./3.4.1-rlvr.md)定义可验证奖励、在线采样与 DeepSeek-R1 案例；[OREO](./3.4.2-oreo.md)进一步处理离线数据覆盖与 Bellman 一致性的取舍；[长程信用分配](./3.4.3-长程信用分配.md)再把单轮推理扩展到工具与 Agent 轨迹。三者依次增加离线约束和时间跨度，形成从终局验证到长轨迹训练的机制顺序。

阅读时始终追踪四个对象：策略真正观察到的状态、策略实际执行的动作、奖励能验证的结果，以及训练目标把奖励分给了哪些动作。四者只要没有对齐，曲线提升就可能来自代理指标，而不是目标能力。

### 4.1. 可靠训练的最低记录

在线或离线系统都应记录任务 ID、环境版本、策略版本、完整消息与工具轨迹、采样参数、终止原因、奖励各分项、验证器日志、异常类型和 token 级 mask。长程任务还要保存阶段边界、重试与回滚动作。评测需要固定环境快照或给出可重复协议，并分别报告成功率、平均步骤数、成本、恢复能力和失败分类。

可验证奖励为推理 RL 提供了少见的清晰信号，但越接近真实 Agent，反馈就越稀疏、环境也越复杂。终局奖励只能证明验证条件是否满足；轨迹结构、价值估计和完整日志负责补足中间决策信息，并暴露验证条件覆盖不到的行为。

## 5. 从单元测试到环境评测

验证器的测试应分层进行。最底层用固定输入检查解析、等价答案和异常分类；中间层检查容器、编译器、测试数据与资源限制；最高层才是完整模型输出。这样一旦奖励异常，可以定位是答案本身、解析逻辑还是运行环境。对于会变化的外部环境，还要保存时间、版本和必要快照。

长程 Agent 的评测不宜只看最终成功率。还应统计达到目标所需步骤、无效工具调用、重复搜索、错误恢复次数、上下文增长和实际成本。同样成功的两条轨迹，稳定性与可部署性可能完全不同。把过程指标用于诊断，不等于把它们全部变成训练奖励；后一种做法会给模型更多可投机的代理目标。

### 5.1. 信用分配的实际折中

纯终局奖励假设轨迹内全部动作共同负责，过程奖励则引入额外判断器。实践中可以让终局验证保持最终权威，同时用价值估计或阶段边界改善方差，再通过消融确认辅助信号没有改变目标。若采用人工或模型生成的过程标签，需要单独测量其一致性，并保留原始终局结果用于校验。

离线与在线数据也可以互补：离线轨迹用于预热价值或行为，在线 rollout 用于探索当前策略尚未覆盖的路径。不过两者来自不同策略与环境版本，混合时必须标明来源并控制权重。否则大量旧数据会拖慢适应，少量在线数据又可能因高方差支配更新。

最终，奖励设计、数据记录和系统可靠性是同一个问题的三面。没有稳定验证器，算法会优化噪声；没有完整轨迹，无法重建信用；没有版本与异常记录，环境变化会伪装成能力变化。把这三部分共同设计，长程强化学习才可能从漂亮的成功案例走向可复现训练。

### 5.2. 多步回报怎样调节时间尺度

终局奖励之外，critic 可以构造 $n$ 步回报
$$
G_t^{(n)}=\sum_{k=0}^{n-1}\\gamma^kR_{t+k+1}
+\\gamma^nV(s_{t+n}).
$$
$n$ 小时更依赖价值 bootstrap，方差较低而偏差受 critic 影响；$n$ 大时接近蒙特卡洛回报，减少 bootstrap 偏差，同时纳入更多环境随机性。$\lambda$-return 对不同 $n$ 步回报做几何加权，把时间尺度变成连续旋钮。长程 Agent 中的合适 $\lambda$ 取决于环境随机性、critic 精度和奖励延迟。

若轨迹包含明确阶段，例如检索、制定方案、执行和验证，可以在阶段边界估计价值，减少每个 token 都做信用判断的负担。阶段划分也可能出错：模型若为了尽早获得阶段奖励而跳过必要步骤，边界就从估计工具变成新的代理目标。阶段价值应以终局成功校准，并检查跨阶段错误传播。
层级动作缩短有效 horizon。 层级强化学习把连续低层动作组织成 option。一个 option 包含启动集合、内部策略和终止条件，高层策略选择 option，低层策略完成一段子任务。若「搜索文档」「运行测试」「修复错误」能成为稳定子策略，高层决策步数会少于原始工具调用数，信用分配的有效 horizon 随之缩短。

收益依赖 option 是否具有可复用边界。过窄的 option 退化为单步动作，过宽则内部失败难以定位；终止条件如果只看表面格式，可能在子目标尚未达成时提前返回。语言模型 Agent 往往用自然语言计划充当隐式 option，但文本标签本身不保证状态抽象成立。应检查同一 option 在不同任务中的成功率、持续步数和终止状态分布。

层级训练还需要决定奖励归属。终局奖励可以更新高层选择，子任务验证器更新低层策略；若低层奖励和全局目标冲突，高层可能偏爱容易完成但无助于最终任务的 option。用终局价值评估 option 的边际贡献，并保留失败后的恢复路径，才能避免局部完成率掩盖整体退化。
