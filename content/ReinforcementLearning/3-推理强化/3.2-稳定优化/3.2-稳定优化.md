# 稳定优化

## 1. 概率口径、聚合尺度与稳定性

稳定性来自采样概率、优势尺度、聚合分母和优化状态的一致配合。下面依次检查这些量怎样进入实际梯度，以及异常曲线对应哪一段统计关系。

一次更新同时涉及采样策略、保存的旧 log probability、当前策略和参考策略。四者承担不同职责：采样策略产生数据，旧 log probability 构造重要性比率，当前策略接收梯度，参考策略提供 KL 坐标。若生成端温度、词表掩码或模型版本与记录不一致，比率从定义上已经错误，后续裁剪无法修复。

令真实行为概率为 $\mu(a\mid s)$，系统却保存 $\tilde\mu(a\mid s)$，计算比率
$$
\tilde r=\frac{\pi_\theta(a\mid s)}{\tilde\mu(a\mid s)}
=\frac{\pi_\theta(a\mid s)}{\mu(a\mid s)}
\frac{\mu(a\mid s)}{\tilde\mu(a\mid s)}.
$$
第二个因子是系统性误差。它与 token、状态和版本相关，不能视为均值为零的噪声。稳定训练的第一步，是让概率口径与实际采样过程完全对应。

### 1.1. 裁剪区间如何作用于不同符号的优势

PPO 风格代理写成
$$
L=\mathbb E\left[
\min\bigl(r_tA_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t\bigr)
\right].
$$
当 $A_t>0$，提高动作概率超过 $1+\epsilon$ 后不再增加代理收益；当 $A_t<0$，把动作概率降到 $1-\epsilon$ 以下后不再增加收益。另两个方向并未被对称阻止：正优势动作概率下降、负优势动作概率上升仍会产生损失。裁剪构造的是悲观代理下界，不是把所有 ratio 数值截进区间。

clip fraction 高可能表示学习率过大、同批数据复用过多、优势尺度过大或 rollout 太陈旧。它是症状，不提供唯一诊断。实际 KL 很大而 clip fraction 较低时，还要检查未采样 token 的分布变化；KL 较小而奖励停滞时，问题可能位于探索或反馈。

### 1.2. token 与序列聚合改变有效权重

一条长度 $T_i$ 的回答有 token loss $\ell_{i,t}$。序列等权目标为
$$
L_{\rm seq}=\frac1B\sum_{i=1}^B\frac1{T_i}\sum_{t=1}^{T_i}\ell_{i,t},
$$
token 等权目标为
$$
L_{\rm tok}=\frac{1}{\sum_iT_i}\sum_{i=1}^B\sum_{t=1}^{T_i}\ell_{i,t}.
$$
前者让每条回答总权重相同，后者让每个 token 权重相同，因此长回答贡献更多。若成功回答系统性更长，两种目标会给成功样本不同权重；改变最大长度也会改变目标。GSPO、DAPO 等方法中的聚合选择需要放回这两个基准理解。

序列 ratio 等于 token ratio 的乘积，其对数为各 token log-ratio 之和。长度增长时方差和数值范围都扩大，直接裁剪序列 ratio 会让长回答更容易触界。按长度平均 log-ratio 可以缓解尺度增长，同时改变概率测度含义。任何归一化都应说明希望每个 token、每条回答还是每个提示获得相等权重。
多奖励归一化与权重漂移。 设总奖励为 $R=\sum_k w_kR_k$。不同分量量纲、方差和稀疏度不同，固定权重并不等于固定影响力：梯度贡献还取决于每项与 score function 的协方差。某项数值方差大，会在组标准化前主导排序；逐项标准化后再相加，又会让原本极少变化的信号被放大。

动态标准差归一化还使目标随 batch 组成变化。同一条回答在一个正确性分布集中的 batch 中权重大，在另一个分散 batch 中权重小。滑动统计可减少波动，却引入滞后。更根本的选择是区分硬约束和软目标：必须满足的可执行性可先过滤，剩余样本再按质量排序，避免用有限权重交换不可违反条件。
熵、KL 与探索的作用不同。 熵衡量当前策略自身的不确定性，KL 衡量它相对参考或旧策略的距离。策略可以在保持相似熵的同时把概率质量移动到完全不同 token，也可以降低熵却仍贴近一个本就尖锐的参考模型。二者曲线不能互相替代。

熵塌缩可能来自奖励过强、温度过低、优势异常值或数据中单一模板长期获胜。简单增加 entropy bonus 会在所有 token 上鼓励不确定性，包括语法和算术位置。更有针对性的办法是改善候选多样性、按提示难度分配采样，或在高层分支处增加搜索。

KL 惩罚系数的自适应控制需要明确时间尺度。系数更新过快，会和策略优化相互振荡；过慢则无法阻止短期漂移。目标 KL 还受序列长度与聚合口径影响，固定 token KL 与固定序列 KL 对长回答施加的压力不同。
用可观测量定位失效环节。 reward 上升而独立验证下降，优先检查反馈漏洞与分布外利用；reward 和 KL 同时不动，检查优势是否全零、学习率及梯度；KL 暴涨伴随高 clip fraction，检查策略陈旧、epoch 数和优势尺度；长度快速增长，检查 token/sequence reduce 与长度相关奖励；熵下降但通过率不升，检查探索覆盖。

单个均值容易隐藏提示异质性。按难度桶报告零方差组比例、ratio 分位数、clip fraction、长度和成功率，可以区分简单题饱和、难题无正样本与中间题真正学习。ratio 的极端分位数通常比均值更能暴露长尾，梯度范数则要和有效 token 数及归一化口径一起看。

稳定性最终要通过重复运行检验。随机种子影响提示抽样、生成轨迹和组内成败构成，早期少量成功样本可能把策略带入不同区域。只报告最好一次会隐藏方法的失败概率；均值、方差和崩溃次数都属于算法结果。

策略优化还有一个容易漏掉的尺度：优势乘以 score 后的实际梯度。优势标准差相同，不同序列长度、模型置信度与 token mask 仍会产生不同梯度范数。观察优势分布时应同步记录未裁剪梯度、裁剪后梯度以及每个有效 token 的归一化范数，才能区分估计器爆炸与网络雅可比放大。

Adam 等自适应优化器还会累积历史二阶矩。一次奖励异常值可能在当前步被梯度裁剪，却抬高后续若干步的二阶矩估计，使有效学习率下降。恢复训练时若只加载模型权重、不加载优化器状态，同一 batch 会走出不同轨迹。稳定性的实验口径因此应包含优化器状态与学习率日程。

组内优势估计给出了无 critic 时的学习信号，训练稳定性还受其他环节制约。推理回答往往很长，长度差异大，奖励又常由多个验证器共同给出。一个看似普通的平均操作，就可能决定短答案还是长答案获得更多梯度；一次裁剪，可能保护策略不发生剧烈漂移，也可能让真正有用的正向更新被截断。DAPO、GSPO、GMPO、GDPO 与 CISPO 都在重新检查样本、序列、token、奖励维度和重要性权重之间的边界。
稳定到底指什么。 训练曲线没有 NaN 只是最低要求。更完整的稳定性至少包含四层。数值稳定要求 log-prob、importance ratio 和优势归一化不溢出；优化稳定要求更新幅度、KL 与裁剪比例处于可解释区间；数据稳定要求每一步看到的难度、长度和奖励分布没有因过滤规则突然改变；能力稳定则要求目标 benchmark 上升时，已有能力不会大面积退化。

这些层次不能靠一个 loss 数值概括。比如平均奖励上涨，可能只是动态采样移除了困难题；KL 很小，可能是大量 token 被裁剪后没有梯度；训练长度变长，可能是模型学会更完整地推理，也可能是序列聚合给长回答更高权重。因此每个算法都要从「它改变了哪一个统计口径」入手。

## 2. DAPO：配方是一体的

DAPO 经常被缩写成非对称裁剪，但它实际把动态采样、clip-higher、token-level policy-gradient loss 和 overlong reward shaping 组合在一起。动态采样排除全对或全错、没有相对信号的组，让算力集中到可学习题目；非对称裁剪给概率上升方向更宽空间；token 级聚合重新分配长短回答的权重；超长处理则避免截断样本把错误信号直接灌入策略。

这些设计互相影响。过滤后 prompt 分布变了，优势分布随之变化；聚合口径改变后，裁剪比例也会变化。只从完整配方里拿一个开关，不能假设仍会复现原结果。实验必须逐项记录启用条件与消融，而不是把「采用 DAPO」当成充分描述。

### 2.1. GSPO：把比率拉回序列

PPO/GRPO 常在 token 级计算 importance ratio。对长序列而言，局部 token 比率可能高度波动，且推理正确性通常由整条回答共同决定。GSPO 转向序列级比率，希望让优化粒度与奖励粒度对齐。它减少了单个 token 极端比率支配更新的机会，但序列级压缩也会隐藏局部异常：模板 token、推理 token 和答案 token 的行为变化被汇入同一个数。

因此，采用序列级目标后仍需保留 token 级诊断。至少画出位置分桶的 KL、ratio 分位数和 mask 覆盖率。序列目标是训练权重，不是放弃细粒度观测的理由。

## 3. GMPO：几何平均改变长度效应

一串 token 比率相乘容易随长度指数变化，直接算术平均又可能让少数极端 token 支配结果。GMPO 从几何平均出发，在 log 空间聚合 token 变化，使序列尺度更可控。几何平均等价于平均 log-ratio 后再指数化，这与概率乘积的结构更自然地对应。

但「长度归一」不是自动公平。长回答包含更多低信息模板 token，也有更多机会出现异常 token；短回答则可能只给结论。几何平均只定义了如何压缩比率，没有决定奖励是否可靠、mask 是否正确，也没有消除采样长度分布带来的选择偏差。

### 3.1. GDPO：多奖励不能先糊成一个数

推理训练常同时使用正确性、格式、长度、代码执行、语言一致性等奖励。若先用固定权重求和再统一标准化，高方差或高频奖励可能吞掉其他目标，甚至让某一维的尺度变化改变全部样本排序。GDPO 的关键问题是把奖励维度解耦后再归一化与组合，使不同信号保留自己的统计尺度。

## 4. CISPO：权重封顶，梯度不断

PPO/GRPO 的裁剪会在比率越过对应边界后形成零梯度平台。长推理训练反复使用同一批 rollout 时，低概率又有正优势的分叉 token 可能在第一轮更新后就退出后续学习。CISPO 不再裁掉 token 更新，而是把重要性比率截断并停止梯度，再让这个有限权重乘到 $\log\pi_\theta$ 上。越界 token 仍有梯度，单个 token 的权重又不会随比率无限增长。

它处理的是数据复用中的梯度利用率，不能代替奖励校验、信用分配或样本新鲜度控制。详细推导见 [CISPO](./3.2.5-cispo.md)。

多奖励方法的核对重点不只是最终权重。要检查缺失奖励如何处理、各维奖励在哪个集合上统计、方差接近零时如何稳定、负奖励方向是否统一，以及跨设备聚合是否一致。一个分项若只在少数样本上定义，直接把缺失值当零会把「未评估」误写成「表现中性」。

### 4.1. 统一诊断表

四类方法可以用同一张脑内表格比较：采样阶段是否过滤；优势在组内怎样归一；importance ratio 在 token 还是序列聚合；loss 对 token、序列、prompt 怎样平均；正负更新的裁剪边界是否对称；多个奖励在合并前是否分别校准；过长与被截断样本怎样进入奖励和损失。只要其中一列不同，实验就不能简单归因于算法名称。

[DAPO](./3.2.1-dapo.md) 给出完整训练配方，[GSPO](./3.2.2-gspo.md) 与 [GMPO](./3.2.3-gmpo.md) 展开序列聚合的两条路径。[CISPO](./3.2.5-cispo.md) 讨论比率越界后应裁掉更新，还是只限制重要性权重；[GDPO](./3.2.4-gdpo.md) 再把单奖励假设扩展到多维反馈。掌握这些差别以后，可以进入训练配方章检验各项机制在受控对照中是否必要。

### 4.2. 从论文数字回到系统

复现时应同时保存策略版本、rollout 引擎版本、tokenizer、聊天模板、采样参数、奖励代码哈希和每种 mask。监控至少包括 reward 分项、回答长度分布、全同组率、有效 token 数、KL、ratio 分位数、上下裁剪率、梯度范数及吞吐。若只保留最终 checkpoint 和总奖励，事后几乎无法判断一次崩溃来自算法、数据、验证器还是推理服务。

稳定优化要求每次变化都有可追踪原因，曲线平滑只是外在表现。可靠配方应该能回答：哪类样本贡献了梯度，哪些更新被裁剪，奖励维度怎样竞争，长度为何改变，以及收益在控制算力和数据后是否仍然存在。

## 5. 从异常现象反推责任层

若奖励突然上涨而验证集不动，先检查动态采样与验证器分布，而不是立刻调学习率。若 KL 与梯度范数同时尖峰，检查策略版本、old log-prob 和 ratio；若 KL 平稳但长度持续增长，检查 token/sequence 聚合与长度奖励；若某一奖励分项改善、其他分项退化，检查多奖励归一化与缺失值处理。把现象与责任层对应起来，能避免用一个超参数掩盖另一层的错误。

裁剪统计需要拆成正优势与负优势两侧。总裁剪率相同，并不代表更新行为相同：大量正优势被上界裁掉会限制提升高质量回答的概率，大量负优势被下界裁掉则会保留不理想行为。还应按回答长度、题目难度和奖励分桶观察。全局平均往往把最需要关注的小群体冲淡。

### 5.1. 公平比较所需的控制量

比较 DAPO、GSPO、GMPO、GDPO 与 CISPO 时，至少固定基础模型、数据快照、聊天模板、生成温度、组大小、最大长度、总生成 token、总训练 token、数据复用轮数与评测脚本。如果某方法因吞吐较低而在相同墙钟时间内看到更少样本，应同时给出等时间与等 token 两种结果。否则系统效率与统计效率会被混成一个数字。

优化器状态也不能忽略。切换目标函数后沿用已有动量，与从同一 checkpoint 重置优化器开始，可能产生明显不同的短期曲线。严格消融应共享起点，并明确是否继承 optimizer、scheduler 与数据游标。多次运行要报告均值和波动，不能只挑最好种子。

### 5.2. 最小故障实验

在全规模训练前，可以构造四类小实验。奖励全相同时，优势与策略梯度应接近零；一条正样本配多条负样本时，正负更新方向应符合预期；把同一回答复制成不同长度的等价序列，可以检查聚合是否无意偏爱长度；人为放大某一奖励维度，可以检查多奖励标准化是否真的解耦。再加一组旧策略与当前策略完全相同时的测试，importance ratio 应接近一。

这些实验不证明最终能力，却能快速排除公式抄对、实现含义却变了的问题。推理强化学习一次大规模 rollout 成本很高，把符号、边界和聚合错误留到正式训练后发现，是最昂贵的调试方式。

不同诊断量还应使用一致分母。按 micro-batch 报告梯度范数、按整批报告 reward、按 token 报告 KL，会让同步关系难以解释。把采样数、有效序列数与有效 token 数同时记录，再明确每个均值的分母，才能判断变化来自策略本身还是 batch 组成。

日志中的策略版本也应进入分桶。把不同延迟的 rollout 混成一个均值，会遮住陈旧样本的 ratio 长尾；按版本差报告 KL、裁剪率与收益，才能验证允许的最大延迟是否合理。
