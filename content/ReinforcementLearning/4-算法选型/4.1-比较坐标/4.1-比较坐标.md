# 离线偏好与在线组采样的比较坐标

给同一道数学题准备四个回答,如果人只能指出哪两个更好,我们得到的是偏好对子;如果有可信的答案检查器,四个回答还可以各自得到对错反馈。这两种训练信号看似都在告诉模型「选好的」,实际能回答的问题不同。对子说明一条回答相对另一条更合意,却不保证赢家真的正确;检查器能判定指定结果,却可能看不见过程漏洞或把格式匹配当成解题。算法选型要从反馈的含义、数据产生时的策略和验证成本出发,再讨论 DPO、PPO、GRPO 等名字。

这里的两条路线也并非互斥。先用人工偏好把模型教到可用,再让它在有可靠检查器的任务上探索,是合理的组合;反过来,在线采样暴露出奖励漏洞后,也可能需要重新收集偏好数据。关键在于每次切换时说清楚:优化器收到的究竟是成对排序、单条二元标签,还是当前策略生成的一组可打分轨迹。下文先建立比较坐标,具体损失与手算分别放在 [DPO 家族比较](./4.1.1-dpo家族比较.md) 和 [GRPO 家族比较](./4.1.2-grpo家族比较.md)。

## 1. 离线偏好只在给定候选之间排序

固定偏好数据的一条样本写作 $(x,y_w,y_l)$:面对同一个 prompt $x$,标注者更喜欢 $y_w$ 而不是 $y_l$。这种比较消除了部分题目难度差异,但没有告诉我们「若模型生成第三个回答会怎样」。[DPO 论文](https://arxiv.org/abs/2305.18290) 利用带 reference 约束的奖励最大化问题,把最优策略与奖励写成 $r(x,y)=\beta\log[\pi(y\mid x)/\pi_{\rm ref}(y\mid x)]+c(x)$。同一 prompt 下两个回答相减,未知的 $c(x)$ 消失;于是可以直接用策略相对 reference 的 log 概率差拟合偏好,省去单独训练奖励模型和在线 rollout。这是它成立的数学入口,不代表任何离线偏好集都等价于真实的人类目标。

为了看清梯度从哪里来,把一条回答的相对分数记为 $h_\theta(x,y)=\log\pi_\theta(y\mid x)-\log\pi_{\rm ref}(y\mid x)$。DPO 让 $\beta[h_\theta(x,y_w)-h_\theta(x,y_l)]$ 增大;排序已明显正确的对子权重逐渐变小。这里用的是整条回答的 token log 概率之和,回答越长,可累积的项也越多。把序列求和改为按长度平均,会改变相同两条回答的分差,并非只做一次无害的数值归一。偏好数据本身还可能同时奖励正确性、措辞和长度;若标注者偏爱详细回答,优化器就可能把长文本当成捷径。

离线数据的优势是同一批对子可以反复训练,不必每一步都等待新模型生成和裁判打分。代价是监督范围由采集时的候选决定。若赢家和输家都错了,DPO 仍会把赢家相对抬高;若新策略产生了数据里没有的奇怪格式,固定对子也不会自行提供新标签。参考模型约束与损失形状可以限制漂移,却不能凭空补上缺失的反事实。独立二元反馈、是否需要 reference、是否包含 SFT 项等变化,对应 [DPO 家族比较](./4.1.1-dpo家族比较.md) 中不同方法的入口条件;不能把所有方法只当作 DPO 换一个名字。

## 2. 在线组采样让当前策略自己提出候选

若检查器可以对新生成的回答给分,就能让当前策略针对同一个 prompt 采样 $G$ 条,逐条计算奖励 $R_i$。[DeepSeekMath](https://arxiv.org/abs/2402.03300) 提出的 GRPO 用组内统计量代替单独训练的价值模型;常见优势写作 $A_i=(R_i-\bar R)/(\operatorname{std}(R)+\epsilon)$。每组的好坏只在同题候选之间比较,优势再广播到该回答的 token 更新。它省掉了 critic 的训练与推理,但要支付多条回答的生成成本,且一个终局分数无法指出哪一步推理真正造成了成败。

一个四样本小组若奖励为 $(0,0,1,1)$,均值是 $0.5$,按总体标准差计算也是 $0.5$,于是两条成功回答的优势约为 $+1$,失败回答约为 $-1$。同一道题若四条全错,组内差异消失,中心化优势全为零。把这些轨迹继续送进损失函数,无法仅凭它们判断哪条「相对没那么错」。二值奖励下,假设每条采样独立且单条成功率为 $p$,一组全同的概率是 $p^G+(1-p)^G$;过难或过易的题都会让采样预算空转。这解释了为什么同样是增加 $G$,在中等难度题上和在极难题上得到的有效信号差别很大。

组内标准差归一还会改变不同题目的权重。一道题里只有一条偶然答对时,成功样本可能获得很大的标准化优势;另一道容易题即使成功样本更多,也可能给出较小的单样本梯度。这种难度重加权是估计器产生的,不等于「难题天然更重要」。[GRPO 家族比较](./4.1.2-grpo家族比较.md)进一步拆开组均值、标准差、按回答或按 token 归约、比率裁剪和动态采样:这些开关作用于不同位置,一个变体的效果不能只归给其中一个开关。

## 3. 用什么反馈,就会暴露什么误差

离线偏好依赖标注者看过的候选,在线训练依赖当前策略能探索到的候选,两者都绕不开反馈质量。数学答案、代码测试之类可执行检查器能把新轨迹快速转成信号,但检查器只覆盖它能检查的属性。模型可能学会利用容错格式、猜中最终答案却写出无效过程,或针对少数公开测试用例过拟合。开放式写作若用奖励模型替代精确检查器,策略又会不断向奖励模型的盲区移动。此时在线采样能力越强,越需要与训练奖励独立的人工或任务评测。

离线偏好也有自己的误差路径。标注者可能因为措辞自信而选错答案,同一 prompt 的候选若都来自较弱的早期模型,后来模型的行为就超出标注分布。检查这些问题,至少要把原始任务成功率、人工偏好、长度分布和训练用的代理分数分开报告。仅有一个偏好胜率或一个平均 reward,无法定位究竟是模型能力进步、回答变长,还是裁判口径发生了偏移。能精确核验的任务优先展示正确率与失败类型;主观任务则保留标注分歧和比较协议。

两条路线的约束变量也不能混为一谈。DPO 的 reference 出现在固定对子相对分数里;PPO/GRPO 的 old policy 记录采样版本,帮助更新时计算重要性比率,reference 则负责限制长期偏离。一个按 token 的 ratio clip 管不到从未采过的回答,KL 约束也不能修好错误标签。长链任务还要看奖励落在哪个位置、是否截断以及损失按回答平均还是按有效 token 平均;同一套超参搬过去,优化的权重可能已经变了。

## 4. 比预算,也比能否发现新证据

比较方法不能只报训练 step 或 epoch。离线方案要算收集多少条高质量对子、每条对子要生成多少候选以及人工比较的成本;在线方案还要算每个 prompt 的 $G$ 条 rollout、检查器执行、重复采样和失败样本过滤。两边都要报训练 token、参考模型或奖励模型的计算负担,以及同一独立题集上的结果。若把已经标好的偏好集当作免费,却把在线生成成本全额计入,结论会偏向离线;反过来只算标注人力、不算在线计算,也会得出相反的假象。

任务条件通常给出更清楚的起点。人工能稳定比较质量、但缺少可信自动检查器时,先建立成对偏好基线;若存在可重复执行的正确性判断,并且模型已经能以非零概率解题,组采样才有机会从新轨迹里挖出增量信号。极低成功率时先改善起点模型、题目难度或采样方式,否则全错组只会消耗预算。若 verifier 存在假阳性,应先修裁判或把独立抽检加进训练循环;换一个更激进的优化器只会更快找到漏洞。

固定基础模型、训练数据来源与验收题集,逐项改变反馈和优化方法,才能判断 DPO 与 GRPO 的差距来自哪里。候选质量、标注密度和题目难度都可能主导结果。一份完整对照应交代样本来源、奖励含义、更新公式及其偏差,并展示模型在新题上解决了什么问题;方法名称只是这些选择的简写。
