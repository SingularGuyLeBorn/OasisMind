# 矩阵视角的一层数据流

一层 Transformer 在公式里通常只占两三行, 但实际数据流包含矩阵投影、head 拆分、局部与全局缓存读取、两次残差和专家路由. 下图把这些对象放回同一条路径. 点击顶部层号可以切换第 1–40 层; 组件会根据层号选择 SWA-only、Full、Reindex 或 Reuse, 并更新全局缓存节点和边标签.

## 1. 从输入矩阵到独立投影

第 $l$ 层输入为 $H_l^{in}\in\mathbb{R}^{N\times5120}$. $N$ 是当前 Prefill 序列长度; Decode 时 $N=1$, 但历史 Key/Value 已存在缓存中. 图把每个 token 表示为一条 5120 维行向量, 多个 token 沿行轴叠成矩阵. 这种画法让 batch 之外的两个核心轴保持可见: 行轴是 token 位置, 列轴是 hidden dimension.

第一次归一化为:

$$
X_l=\operatorname{RMSNorm}(H_l^{in};\gamma_{l,1}).
$$

$X_l$ 的 shape 仍为 $N\times5120$. 随后的投影节点没有把 `WQKV` 写成一个不可分辨的大块, 而是把 Query、局部 Key 和局部 Value 分开. Query 使用压缩与展开两级投影: 先到 1280 维压缩空间, 再展开成 64 个 head, 每个 head dimension 为 512. 图写成 `Wᴽ↓ · Wᴽ↑`, 用箭头标明 5120 → 1280 → 64×512.

局部 Key 与局部 Value 分别由 `Wᴷˡᵒᶜ`、`Wⱽˡᵒᶜ` 产生. 两块权重服务 SWA, 对最近 128 个 token 保持本层私有缓存. 它们必须拆开: Key 进入相似度点积, Value 在 softmax 之后被加权求和, 两者在计算图中的位置不同.

Full 模式额外出现 `Wᴷⱽᵍˡᵒᵇᵃˡ`. 这里的 `KV` 描述 CSA2 global main KV 这一共享缓存表示, 不等同于把局部 `Wᴷ` 与 `Wⱽ` 合成一块. Reindex 模式不运行 global main KV 的生产投影, 但会计算本层 `WᴵQ`; Reuse 模式连 indexer Q 也跳过, 直接读取最近一次有效选择.

## 2. 64 个 head 怎样合并

每个 Query head 都接收 $Q_h$, 并读取由当前层模式确定的 $K_h$、$V_h$. SWA-only 层只读取本层最近 128 行. 其余层还会根据 Top-512 行号从 global main KV 读取全局条目. 对每个 head:

$$
A_h=\operatorname{softmax}\!\left(\frac{Q_hK_h^\top}{\sqrt{d_h}}\right),\qquad O_h=A_hV_h.
$$

图没有把「Attn」写成一个三字母方框. Head 1、Head 2 和 Head 64 都展开了 Q/K/V、缩放点积、softmax 与 Value 加权. 中间的 61 个 head 使用省略号, 因为它们重复相同结构; 关键操作没有被省略.

所有 head 完成后沿特征轴拼接:

$$
O_l=\operatorname{Concat}(O_1,O_2,\ldots,O_{64})W_l^O.
$$

Concat 节点位于各 head 之后, `W_l^O` 位于 Concat 之后. 这样可以区分「每个 head 的输出」与「回到 5120 hidden dimension 的层输出」. 如果把 `W_l^O` 放进任意一个 head, 会错误地暗示 64 个 head 各自完成一份 5120 维输出投影.

## 3. Full、Reindex、Reuse 的侧边缓存

Full 层是 global main KV 的生产者. 它产生 main KV, 从 main KV 投影 indexer K, 再使用本层 indexer Q 得到 Top-512 行号. 图中的共享缓存节点写明三种对象, 从投影节点接收写入边, 再向 attention 节点提供「共享 KV + 新 Top-512」.

Reindex 层读取最近 Full 层产生的 main KV 与 indexer K. 当前层的 indexer Q 对共享 indexer K 重新打分, 得到新的 Top-512. 因为被读取的内容不变、行号可能改变, 图把 Reindex 写成「读取共享 KV, 本层重新选择」, 而不是「重新计算 KV」.

Reuse 层不产生 main KV、indexer K 或新的 Top-K. 当前层 main Q 直接使用最近一次有效 Top-K 从共享 main KV gather 条目. 正式注意力仍然重新执行, 因为当前层 Query 与前层不同. 图中的侧边标签是「共享 KV + Top-512」, 主边仍从当前层 Query 与局部 K/V 投影进入 attention.

第 1、2 层为 SWA-only, 因而共享缓存节点完全消失. 第 3、9、15 层是 Encoder Full; 第 4–8、10–14、16–20 层是 Encoder Reuse. 第 21 层是 Decoder Full; 第 25、29、33、37 层是 Decoder Reindex; 其他 Decoder 层为 Reuse. 顶部层号使用不同颜色标出模式, 点击后整张图只改变真实存在差异的全局路径.

## 4. 残差节点必须接住旁路输入

注意力输出经过 $W_l^O$ 后得到 $O_l$. 第一次残差为:

$$
H_l'=H_l^{in}+O_l.
$$

图中 $H_l^{in}$ 从输入矩阵左侧绕过 RMSNorm、投影与 attention, 直接进入第一次残差节点. 旁路是一条完整的 React Flow edge, 端点附着在节点 Handle 上, 箭头闭合在加法节点边界. 因此缩放页面或改变节点尺寸时, 线仍然连接起点与终点, 不会留下由 CSS 边框拼接造成的小线头.

第二次 RMSNorm 以 $H_l'$ 为输入:

$$
Y_l=\operatorname{RMSNorm}(H_l';\gamma_{l,2}).
$$

MoE 输出为 $O_l^{FFN}$, 第二次残差为:

$$
H_l^{out}=H_l'+O_l^{FFN}.
$$

第二条琥珀色旁路从第一次残差结果直接连接第二次残差. 因而加法节点内部已经写出完整等式, 边上只保留真正沿线传递的变量名, 不再在加号右侧重复一个可能被误认成输出的 `H_l^{in}` 或 `H_l'`.

## 5. Router 的 384 维得分向量

Router 对每个 token 计算一条 384 维得分行向量:

$$
g_l=Y_lW_l^R,\qquad W_l^R\in\mathbb{R}^{5120\times384}.
$$

图把 Router 画成一条有元素格子的向量, 并高亮六个 Top-6 元素. 为了让排序可见, 组件给出 $0.91,0.86,0.79,0.73,0.69,0.64$ 六个示例值; 它们不属于模型固定参数或报告测量值. 实际推理中, 每个 token、每一层都会产生新的 384 个分数, 被选中的专家编号也会改变.

除了 384 个 routed expert, 每层还有 1 个 shared expert. shared expert 不参与 Top-6 竞争, 始终处理输入. 图将 shared expert 与六个入选 routed expert 并列, 但使用不同颜色和 `always` 标签, 避免把「1 共享 + 6 选中」误读成「从 385 个专家里统一选 7 个」.

## 6. 专家内部不是一个黑盒

每个专家展示两条输入分支. 一条经 $W_i^{gate}$ 后通过 SiLU, 另一条经 $W_i^{up}$; 两条中间表示逐元素相乘, 再经 $W_i^{down}$ 投回 hidden dimension. 对一条 token 行向量 $y$ 可以写为:

$$
\operatorname{Expert}_i(y)=\left[\operatorname{SiLU}(yW_i^{gate})\odot(yW_i^{up})\right]W_i^{down}.
$$

MoE 输出包含 shared expert 和 Top-6 routed expert:

$$
O_l^{FFN}=\operatorname{Shared}(Y_l)+\sum_{i\in\operatorname{Top6}(g_l)}g_{l,i}\operatorname{Expert}_i(Y_l).
$$

图展示 Shared、Expert 7、31、96、142、228、351 作为当前 token 的示例路径, 其余专家折叠为「不执行」. 这里省略的是未被选择的重复实例, 不是专家内部网络. 每个可见专家都保留 `Wgate / Wup → SiLU 与逐元素乘法 → Wdown`.

## 7. 阅读态与源结构

Markdown 中只保存 `DeepSeekV41Layer` composition id、静态显示方式、宽高比和初始层号. React 阅读页加载组件后, 从层号计算模式, 再生成节点数组与边数组. 矩阵、head 和专家是自定义 React 节点; 所有跨节点连接由 React Flow 根据 Handle 计算. 这使结构信息与文章正文分离: 正文可以继续修改解释, 图的端点、箭头和模式规则由一份组件源码维护.

当前文章使用阅读态配置, 节点不能拖动、连线不能重接, 以免读者滚动时误改布局. 这不妨碍后续建立独立编辑页面: 同一套节点和边数据可以打开拖动、连接与边标签编辑, 保存后的坐标再作为阅读态布局. 文章本身仍是 Markdown 事实源, 内嵌组件负责把结构数据渲染成图.

### 7.1. 逐层检查时看什么

选择第 1 或第 2 层时, 共享缓存节点应消失, 但 Query、局部 K/V、64 个 head、MoE 和两次残差仍在. 选择第 3、9、15 或 21 层时, Full 节点应显示本层写入 main KV / indexer K 并产生新 Top-512. 选择第 25、29、33 或 37 层时, 图应显示读取共享 KV、计算本层 indexer Q 并重新选择. 选择其余 Reuse 层时, 图应显示读取共享 KV 与最近 Top-512, 同时保留当前层 Query 和正式 attention.

收尾时沿两条残差边回看变量名. 第一次旁路必须从 $H_l^{in}$ 到 $H_l'$, 第二次旁路必须从 $H_l'$ 到 $H_l^{out}$. 如果这两条边正确, 再检查局部 `Wᴷ` 与 `Wⱽ` 是否分开、Head 是否在 Concat 之前、Top-6 是否来自 384 维 Router 得分、每个专家是否展开内部网络. 这些关系共同决定左图能否独立表达矩阵与数据流结构.
