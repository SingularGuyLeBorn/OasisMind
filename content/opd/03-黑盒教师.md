# 黑盒教师怎样提供反馈

白盒 OPD 可以把学生前缀送进教师, 直接取回下一 token 的 logits 或 log-prob. 商业 API 通常只返回文本. 训练器看不到教师在词表上的概率, 也无法询问「学生刚才采到的这个 token 在你看来有多大概率」. 学生状态仍然可以 on-policy, 教师信号却必须先经过一次转换才能进入梯度.

最朴素的方法是让教师从学生前缀继续写, 再把续写当作 SFT 标签. 它保留了「教师看见学生状态」这一点, 后面的监督状态却沿教师续写继续展开. 另一种方法让教师比较学生回答、给分或写批评, 再把结果变成偏好目标或序列奖励. GAD 走了第三条路: 教师只负责产生自己的回答, 判别器学习区分教师文本与当前学生文本, 判别分数再作为学生 on-policy rollout 的奖励.

三条路线都能利用黑盒教师, 传递的信息完全不同. 教师续写提供一条可模仿路径;评价与偏好提供候选之间的相对次序;判别器提供「这条学生回答在多大程度上像教师分布」的学习型标量. 它们都缺少同一前缀上完整的词表反事实, 所以不能直接套用白盒 forward KL 或 reverse KL 的结论.

## 1. 从序列蒸馏到学生状态上的查询

传统 sequence-level knowledge distillation 先让教师对 prompt $x$ 生成回答 $y^T$, 再最小化

$$
\mathcal L_{\mathrm{SeqKD}}(\theta)
=-\sum_t\log\pi_\theta(y_t^T\mid x,y_{<t}^T). \tag{1}
$$

式 (1) 的所有前缀都来自教师. 它适合把知识、格式与推理模式放进学生支持集, 也允许一份教师数据反复训练. 学生部署时产生自己的 token, 一旦走到教师数据没有覆盖的前缀, 监督便中断. 黑盒 on-policy 蒸馏想修补的正是这一处: 先让学生生成 $y^S$, 再让教师或由教师训练出的反馈模型处理 $x,y^S$.

若直接让教师续写学生前缀 $s_t=(x,y^S_{<t})$, 可以得到一个教师 token $a_t^T$. 对这个 token 做交叉熵, 相当于用一次采样近似教师分布. 继续使用学生原前缀能够保持状态对齐;一旦把教师 token 接回上下文并继续生成, 后续前缀便成为学生与教师的混合轨迹. 混合轨迹有时更容易恢复正确答案, 同时减少了对学生深层错误状态的覆盖.

教师 API 若支持固定随机种子、温度和多样本返回, 可以对同一状态查询多条续写. 频率能够粗略反映教师模式, 仍不是可校准的 logits. API 的采样后处理、拒答、安全过滤与隐藏系统提示都会改变观测分布. 重复查询只逼近 API 实际返回文本的分布, 无法恢复底层模型未经服务层处理的概率.

### 1.1. 文本反馈怎样进入更新

教师给出自然语言批评时, 文本本身不是梯度. 一种做法是把批评和原回答交给学生生成修订稿, 再对修订稿做 SFT;另一种做法是让教师据此比较多个候选, 形成 chosen/rejected 对;还可以把批评交给一个评分器, 转成标量奖励. 转换链越长, 信号越容易受中间模型和模板影响.

修订稿 SFT 训练的是「在固定修订文本的前缀上复现答案」. 若希望保持 on-policy 状态, 应明确哪些学生前缀被保留、教师从哪个位置开始接管. 偏好学习训练的是候选间相对排序, 不提供未出现动作的概率. 标量奖励则要经过信用分配才能作用于 token. 黑盒教师省去了 logits 接口, 代价是把一部分问题转移给数据构造与反馈模型.

## 2. GAD 怎样把教师文本变成 on-policy 奖励

[Black-Box On-Policy Distillation of Large Language Models](https://arxiv.org/abs/2511.10643) 提出的 Generative Adversarial Distillation, 把学生视为生成器, 再训练判别器区分教师回答与学生回答. 设教师文本分布为 $p_T(y\mid x)$, 学生策略为 $\pi_\theta(y\mid x)$, 判别器 $D_\phi(x,y)$ 输出回答来自教师的概率. 标准对抗目标可写为

$$
\max_\phi\;
\mathbb E_{y^T\sim p_T}\log D_\phi(x,y^T)
+\mathbb E_{y^S\sim\pi_\theta}\log\!\left(1-D_\phi(x,y^S)\right). \tag{2}
$$

判别器看到固定教师回答与当前学生回答. 学生更新时, $D_\phi(x,y^S)$ 或由它变换出的分数成为序列奖励. 由于负样本持续由当前学生产生, 判别器学到的是教师数据与当前学生分布之间仍然存在的差异. 学生修复某类问题后, 判别器必须转向新的可分特征, 这就是 GAD 所说的 co-evolve.

在理想容量与最优判别器假设下, 生成对抗目标与两个分布的散度有关. 语言模型训练并不满足这些理想条件: 教师数据有限, 判别器要从高维文本中学习, 学生又通过离散采样和策略梯度接收信号. 论文中的有效性最终来自完整训练与实验, 不能仅凭 GAN 的经典最优判别器推导宣布收敛.

### 2.1. 为什么需要 warmup

学生起点很弱时, 教师文本与学生文本可能轻易区分. 判别器只要捕捉格式、长度或流畅度便能接近饱和, 大量学生回答得到相似低分, 奖励对真正的能力差异不敏感. GAD 的官方实现包含 SeqKD 与 warmup 阶段: 先用教师回答对学生做监督学习, 同时为判别训练建立更有挑战性的负样本, 随后再进入学生 rollout、判别器更新与策略更新的循环.

warmup 的作用可从支持集理解. 学生至少要生成近似教师任务域的回答, 判别器才需要学习细粒度差别. 如果学生连格式都没有掌握, 对抗训练会把算力用在纠正表面特征. 这与白盒 OPD 的冷启动条件相似: 教师信号再密, 学生也得先到达有意义的状态.

官方实现把 verl 的 critic 模块改作判别器, 训练流程分成 student rollout、Bradley–Terry 式判别器更新和学生策略更新. 这条代码路径说明 GAD 的梯度接口更接近「学习型 reward model + on-policy RL」, 而非 token KL. 黑盒 OPD 描述的是学生数据分布与教师来源;具体优化器仍然属于奖励驱动的策略学习.

## 3. 判别器到底学到了什么

理想情况下, 判别器捕捉教师回答中可迁移的正确性、推理质量与表达习惯. 现实中最容易学习的是长度、格式、常用短语、拒答风格和模型家族特征. 如果教师回答普遍更长, 学生只要拉长输出便可能提高「像教师」的分数;如果教师使用固定模板, 学生复现模板也能骗过判别器. 这些捷径会让训练 loss 改善, 任务能力却没有同步增长.

因而判别器评测需要拆分特征. 将师生回答做长度匹配、格式归一或风格扰动后再次测试, 可以观察分数是否仍然依赖任务内容. 把正确学生回答与错误教师风格回答交叉组合, 能检查判别器更重视正确性还是来源痕迹. 若判别器无法在这些对照上维持合理排序, 它还不足以充当能力蒸馏信号.

奖励尺度同样重要. 判别器趋于饱和时, 原始概率靠近 0 或 1, 直接用概率作奖励会让中间差异被压扁;使用 logit 或对数赔率能拉开尺度, 尾部又可能形成极端优势. 进入 PPO 或其他策略梯度更新后, group normalization、baseline、裁剪与 KL 约束继续改变有效梯度. GAD 的教师信号要经过判别器输出、奖励变换、优势估计和策略损失四段转换.

### 3.1. 判别器漂移与学生钻空子

判别器和学生交替更新形成非平稳博弈. 判别器更新太快, 当前学生几乎总被识别, 奖励失去分辨率;学生更新太快, 它可能利用判别器尚未见过的文本模式. 固定判别器会让训练稳定一些, 学生最终又可能学会稳定的奖励漏洞. 这不是调一个学习率便能永久解决的问题, 需要观察两边的相对进度与独立任务指标.

保留历史学生回答能扩大判别器负样本, 防止它忘掉旧漏洞;历史样本过多又会让判别器主要解决旧学生问题, 对当前 rollout 反应迟钝. 这里再次出现 near-policy 与 replay 的取舍. 不同之处在于回放同时影响反馈模型, 不只影响学生梯度. 轨迹版本、判别器版本和奖励版本都应进入样本身份.

## 4. GAD 与白盒 OPD 的梯度差在哪里

白盒 full-vocab OPD 在每个前缀上比较 $p_T(a\mid s_t)$ 与 $\pi_\theta(a\mid s_t)$. 一个 token 被压低时, 教师分布同时告诉学生哪些替代 token 应得到概率. GAD 的判别器通常在序列或回答表示上给分. 它可以指出某条回答整体更接近教师, 无法直接给出同一状态上的完整动作排序.

若把判别分数 $R_\phi(x,y)$ 作为序列奖励, 学生梯度近似为

$$
\nabla_\theta J
=\mathbb E_{y\sim\pi_\theta}
\left[(R_\phi(x,y)-b(x))
\sum_t\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})\right]. \tag{3}
$$

同一个优势乘到整条回答上时, 所有 token 共享方向. 过程奖励、token 级判别头或 leave-one-out 扰动可以提高分辨率, 同时需要更多标注假设或计算. 白盒 OPD 天然拥有逐位置教师概率,GAD 则要通过奖励建模补回信用分配. 这是接口差异带来的结构变化, 无法靠换一个算法名称抹平.

两者也有共同点. rollout 都来自学生, 都要处理行为策略与 learner 的版本差, 都可能因为学生支持集太窄而看不到教师模式. 两者组合也可行: 对能访问 logits 的开源教师使用 token 分布, 对只能访问文本的闭源教师使用序列评价. 混合时应分别归一化两路信号, 防止序列奖励因长度或方差尺度压过 token KL.

## 5. SODA 为什么退回 semi on-policy

[SODA](https://arxiv.org/abs/2604.03873) 对完全动态的黑盒 on-policy 路线提出了另一种取舍. 它先保存一个学生静态快照的回答, 再把教师优质回答与学生较差回答组成对齐信号. 学生看见自身典型错误, 却不必在每轮更新后重新生成并训练一个随之变化的判别器. 论文将这种方法称为 semi on-policy.

静态学生快照无法覆盖训练后出现的新错误状态, 因而没有完全消除状态分布偏移. 它换来的是简单、稳定和较低计算. 对能力差距很大的师生, 学生初始错误已经能提供强对比, 动态刷新未必值得;当学生迅速接近教师或错误类型随训练变化时, 静态负样本会逐渐失去针对性.

GAD 与 SODA 的分歧正好体现黑盒蒸馏的核心矛盾. 动态 on-policy 负样本更贴近当前学生, 需要承担 rollout 成本、对抗不稳定与反馈模型漂移;静态或半在线数据稳定便宜, 状态覆盖会逐渐过时. 选择哪条路线应看师生差距、API 成本、学生变化速度和是否有可靠的独立验证器.

## 6. Outcome、偏好与 self-play 放在哪里

教师直接给最终分数时, 信息源来自教师, 接口却已经退化为 outcome. 若分数来自可验证环境, 训练更接近 RLVR. 两者都能使用学生 rollout, 区别在评价者: 教师分数携带教师偏好与盲点, 环境验证器则受判定规则限制. 将教师评价和环境结果混为一个 reward 会掩盖能力上限.

偏好反馈位于两者之间. 教师比较两个学生回答, 可以提供相对排序而无需校准绝对分数. 若候选由当前学生生成, 数据具有 on-policy 成分;更新若采用离线 DPO 类目标, 优化又不等同于 on-policy policy gradient. 应分别描述候选从哪里来、比较者是谁和 learner 怎样更新.

Self-play 可以让同一模型的多个角色产生候选、批评与裁决. 没有外部教师并不代表没有新增信息: 环境结果、多样本共识、工具返回或某个角色额外看见的参考材料都能形成条件差. 如果所有角色共享参数、上下文和盲点, 相互评价很容易饱和. 本库第四章讨论特权自教师, 第五章再把 self-play 与可验证结果放进推理训练链.

## 7. 怎样证明黑盒教师真的传递了能力

最小对照包括教师回答 SeqKD、静态学生负样本、动态学生 rollout、固定判别器和共同演化判别器. 这几组分别测量教师文本、学生错误暴露、on-policy 刷新和对抗更新的贡献. 只拿 GAD 与原始学生比较, 无法判断收益来自 warmup SFT、更多教师文本还是动态奖励.

预算需要单列教师 API token、学生生成 token、判别器训练 token、策略优化 token与墙钟时间. 黑盒方法看似省去教师 logits 传输, 多轮 API 查询与判别训练仍可能很贵. 对比 SeqKD 时, 教师调用次数和生成长度也应一致或给出成本曲线.

任务评测之外, 应检查长度、格式、拒答率、风格相似度和独立 verifier. 将教师答案做风格改写、长度截断或模板替换, 再看判别分数是否保持任务排序, 能暴露来源识别捷径. 学生最终在独立任务指标上提高, 同时判别器对风格扰动稳定, 才更像能力迁移.

黑盒路线的学生状态可以保持在线, 教师分布却无法直接获得. 示范、偏好、批评、判别器或结果评价负责完成中间转换, 也各自带来新的偏差与失败方式. 转换过程决定训练保留了多少教师行为, 以及它从哪里开始转为一般的奖励优化.

### 7.1. 用一个三回答批次跟算信号

设同一个 prompt 下, 当前学生生成三条回答 $y_1,y_2,y_3$, 独立 verifier 判断其中 $y_1$ 正确,$y_2,y_3$ 错误. 判别器给出的 teacher-likeness logit 分别为 $2.0,1.5,-0.5$. 如果直接按判别器排序,$y_2$ 会得到很高奖励, 尽管它的最终答案错误. 这可能意味着 $y_2$ 拥有教师风格、长推理或常见措辞, 也可能表示它前半段正确但结尾计算失误. 单个序列分数无法区分两种情况.

将判别 logit 在组三条回答内标准化, 均值约为 $1.0$, 标准差约为 $1.08$, 三条优势约为 $0.93,0.46,-1.39$. 策略更新会同时提高 $y_1$ 与 $y_2$. 若再将 verifier 结果加权, 例如总奖励 $R_i=R_i^{D}+\lambda R_i^{V}$, $\lambda$ 决定正确性信号能否压过教师风格. 当 $\lambda$ 太小,$y_2$ 继续被强化;太大时, 系统又退回稀疏 RLVR, 判别器提供的细粒度差异几乎消失.

更细的分析应截取 $y_2$ 首次出错位置. 教师若能从错误前的学生前缀续写出正确后半段, 这条轨迹适合做局部纠错;教师若只能从头重写, 现有黑盒接口只证明整条答案较差. 可把原前缀、教师续写和学生原后缀组成三元组, 分别训练续写 SFT、偏好排序和序列奖励, 再比较哪种转换真正修复同类错误.

这个例子也说明 outcome-based 与 teacher-based 信号为何要分开记录. Verifier 判断任务成败, 判别器估计教师分布特征, 两者在错误但「很像教师」的样本上可能冲突. 冲突样本比总体相关系数更有信息: 它们能暴露教师风格捷径、验证器盲区和部分正确轨迹. 把两路分数提前求和再只保存总奖励, 会失去后续诊断所需的来源信息.

### 7.2. 跨 tokenizer 与多轮交互

黑盒反馈天然绕开词表逐位置对齐, 因而适合跨模型家族. 教师可以使用完全不同的 tokenizer, 训练器只交换字符串、结构化评价或环境结果. 这项优势伴随粒度下降: 字符串相同能保证语义载体可交换, 不能告诉学生某个内部 token 边界上应如何分配概率. 教师续写若被学生重新 tokenize, SFT 目标属于学生词表中的 one-hot 序列, 教师原始的不确定性已经消失.

工具与 Agent 任务还要决定评价对象. 教师只看最终文本, 可能忽略工具调用是否真实执行;教师读取完整交互日志, 又可能利用学生部署时不可见的内部字段. 判别器训练数据应采用与学生评测一致的可见状态, 工具结果则由环境单独验证. 一段看起来像教师的伪造日志不应获得高奖励.

多轮任务可以按 turn 查询教师, 也可以到 episode 结束后一次评分. 逐 turn 反馈更密, 容易把局部礼貌、格式与真正目标推进混在一起;终局反馈接近任务结果, 信用分配更稀疏. 若教师能够指出「哪一步造成后续失败」, 训练器仍需决定这段自然语言解释怎样落到具体动作. 黑盒接口扩大了可用教师范围, 没有消除从评价到梯度的建模工作.

### 7.3. 查询预算怎样改变方法选择

闭源教师通常按输入与输出 token 计费, 查询延迟也远高于本地前向. 每个学生前缀都请求一次教师, 能获得更贴近局部状态的反馈, 成本会随序列长度近似线性增加, 还容易触发服务限流. 只在完整回答结束后请求一次, 成本低很多, 信号粒度退化为序列级. 选取少量关键前缀查询, 则需要一个触发器判断哪些位置值得花费预算.

触发器可以依据学生熵、多个学生样本的分歧、verifier 报错位置或判别器不确定性. 高熵位置代表学生犹豫, 未必对应任务关键步骤;verifier 能定位错误时更直接, 却只适用于有结构化检查的任务. 若触发器本身由模型学习, 还要把漏查关键错误与多查无用位置分别计入评测.

教师回答也可以复用. 同一 prompt 的教师完整答案适合 SeqKD 与偏好构造, 对后续学生新出现的错误前缀却缺少针对性. 缓存相似前缀的评价能够降低请求量, 前缀语义与环境状态必须足够接近. 只按字符串相似度命中缓存, 可能把两个表面相同、工具状态不同的 Agent 步骤当成同一状态.

公平比较黑盒方法时, 横轴应给出教师请求数、输入输出 token、学生 rollout token 与总训练计算. GAD 把大量教师查询前移为一份教师回答数据, 之后主要训练判别器;逐前缀查询则持续消耗教师预算. 两种方案在相同步数下的教师成本完全不同, 单看学生更新次数会产生错误结论.

### 7.4. 参考资料

- Ye et al., [Black-Box On-Policy Distillation of Large Language Models](https://arxiv.org/abs/2511.10643). 论文提出 GAD, 用共同演化的判别器把教师文本与学生 on-policy rollout 连接起来.
- [GAD 官方 verl 实现](https://github.com/YTianZHU/verl). 仓库列出 SeqKD、warmup、判别器更新与学生策略更新的代码入口.
- Chen et al., [SODA: Semi On-Policy Black-Box Distillation for Large Language Models](https://arxiv.org/abs/2604.03873). 论文以静态学生负样本换取更低成本和训练稳定性.
- Song & Zheng, [A Survey of On-Policy Distillation for Large Language Models](https://arxiv.org/abs/2604.00626). 综述从 feedback signal、teacher access 与 loss granularity 三条轴组织白盒、黑盒与自蒸馏方法.
