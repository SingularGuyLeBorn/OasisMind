# OPD · On-Policy Distillation · 在线策略蒸馏

2025 年下半年, Thinking Machines Lab 的一篇文章引爆了整个世界, 让 OPD 突然成为研究热点, 也迅速进入各家大模型训练 pipeline. Kevin Lu 与 Thinking Machines Lab 在 2025 年 10 月 27 日发布了官方技术文章 [On-Policy Distillation](https://thinkingmachines.ai/blog/on-policy-distillation/), 并开放了配套的 [Tinker distillation recipe](https://tinker-docs.thinkingmachines.ai/cookbook/recipes/distillation/). 此前, GKD 已在 2023 年提出让学生生成轨迹、教师在这些轨迹上给反馈, 论文于 ICLR 2024 发表;Qwen3 技术报告在 2025 年又给出了强到弱蒸馏的训练结果. TML 把这些目标接入现成的 RL 训练循环, 给出代码、模型组合和成本对照, 让更多团队可以直接复现.

为什么这一步会突然有用? RL 和 SFT 正好各缺一半. RL 让学生自己 rollout, 所以训练会碰到学生部署时真正遇到的错误前缀;但一条几千 token 的回答通常只有一个结果奖励, 模型只知道「整题错了」, 不知道错误从哪一步开始. SFT 或离线蒸馏能逐 token 训练, 监督很密;但前缀来自人工答案或教师答案, 学生一旦在生成时走偏, 后面全是训练时没见过的状态. OPD 把两件事接起来: 学生先生成, 教师再对学生已经走到的每个前缀计算下一 token 概率. 前缀来自学生, 信号来自教师, 每个 token 都有反馈.

TML 的实现之所以传播得快, 还因为它离现有 RL 代码只差很少几步. rollout 仍由学生完成;训练器已经保存学生对已采 token 的 log-prob;再让冻结教师对同一条轨迹做一次并行 Prefill, 取教师 log-prob, 两者相减就是逐 token 的 reverse-KL 信号. TML 报告, 在它的同架构实验里, 蒸馏约用少 7–10 倍的梯度步数恢复 RL 教师水平, 累计训练计算量低约 50–100 倍. 这些倍率对应论文中的模型与训练配置. 工程上的吸引力来自现成接口: 学生 rollout 提供状态, 教师 log-prob 提供逐 token 稠密信号, 训练过程可以省去独立 reward model 和教师完整回答数据集.

「On-Policy」限定受监督前缀由当前学生产生, 「Distillation」限定反馈来自教师行为分布. 教师预先生成答案再做 SFT, 属于 off-policy 蒸馏;学生自己采样但只拿环境的 0/1 奖励, 属于 on-policy RL;旧检查点或回放池产生前缀, 则变成 near-policy 或混合方法. 教师可以是外部大模型, 也可以是同一模型加参考解、反馈或额外上下文形成的条件化教师. 判断一种方法是不是 OPD, 要看谁生成受监督状态, 以及教师在同一状态上给了什么.

OPD 也没有把困难消掉. 每批新 rollout 都要追加教师前向;完整词表蒸馏还要处理 $T\times|V|$ 的 logits. 更麻烦的是, 教师在自己的答案上很强, 不等于它能理解学生已经写坏的前缀. 学生更新后, 刚采集的轨迹也会变旧. 所以后面的技术分歧都从几个具体问题长出来: 教师和学生的思考方式是否兼容, 用 full-vocab、top-$k$ 还是单个采样 token, 轨迹能复用多久, 以及错误前缀上的教师信号还值不值得学.

## 1. 先按教师优势与反馈接口分清路线

OPD 的共同部分只有一条：**受监督状态由学生产生，教师在这些状态上提供比终局奖励更密的方向。** 真正决定训练形态的，是教师为什么比学生强，以及训练器能从教师拿到什么。沿这两个问题展开，比把所有工作塞进一条时间线更容易看懂。

| 路线 | 教师优势来自哪里 | 训练器拿到什么 | 本库中的入口 |
| --- | --- | --- | --- |
| 外部白盒教师 | 参数规模、领域训练或专家分工 | full-vocab logits、top-$k$ 分布或采样 token 的 log-prob | [白盒分布蒸馏](1-基础与算法/1.1-白盒分布蒸馏/1.1-白盒分布蒸馏.md)、[GKD](1-基础与算法/1.1-白盒分布蒸馏/1.1.1-GKD.md)、[MiniLLM](1-基础与算法/1.1-白盒分布蒸馏/1.1.2-MiniLLM.md)、[DistiLLM](1-基础与算法/1.1-白盒分布蒸馏/1.1.3-DistiLLM.md) |
| 外部黑盒教师 | 更强模型或领域专家 | 教师文本、偏好或经过转换的奖励 | 本库用统一目标交代它与白盒 OPD 的边界；只有文本时，还要借助序列蒸馏、偏好学习或奖励建模 |
| 特权自教师 | 参数可以相同，但教师多看了参考解、示范、反馈或长期上下文 | 条件化 logits 或由其构造的逐 token 信号 | [特权教师](2-自蒸馏与稳定性/2.1-特权教师/2.1-特权教师.md)、[OPSD](2-自蒸馏与稳定性/2.1-特权教师/2.1.2-OPSD.md)、[SDFT](2-自蒸馏与稳定性/2.1-特权教师/2.1.3-SDFT.md)、[SDPO](2-自蒸馏与稳定性/2.1-特权教师/2.1.4-SDPO.md)、[OPCD](2-自蒸馏与稳定性/2.1-特权教师/2.1.5-OPCD.md) |

这张表还揭示了两个容易混淆的边界。第一，教师预先写好文本、学生只在教师前缀上做 SFT，属于离线蒸馏；教师文本再强，也不会自动变成 on-policy。第二，同一个模型给自己打分不等于凭空产生能力。参考答案、环境报错、示范或历史经验才是信息增量，模型参数只是把这些信息转成学生当前状态上的条件分布。

读具体方法时，可以继续问四个问题：前缀由哪个策略版本生成，教师额外看见了什么，返回的是完整分布还是压缩信号，学生更新后这批轨迹还能使用多久。四个答案确定以后，方法名称通常只剩下便于检索的标签。

## 2. 理论入口

### 2.1. 从状态分布开始读

[基础与算法](1-基础与算法/1-基础与算法.md) 先建立统一记号, 再把序列建模问题放回交互式模仿学习. 这条线适合第一次系统理解 OPD 的读者. 关键问题只有两个: 谁产生前缀, 教师在前缀上返回什么. 先固定这两个问题, forward KL、reverse KL、JSD、sampled-token reward 才不会被误当成互斥的方法名称.

章内的 [白盒分布蒸馏](1-基础与算法/1.1-白盒分布蒸馏/1.1-白盒分布蒸馏.md) 是第一条技术路线. 路线首页把固定数据蒸馏、学生 rollout 蒸馏和 RL 放到同一组随机变量里, 说明「on-policy」与「KL 方向」是两条独立轴. [GKD](1-基础与算法/1.1-白盒分布蒸馏/1.1.1-GKD.md) 把轨迹来源与局部散度拆开, [MiniLLM](1-基础与算法/1.1-白盒分布蒸馏/1.1.2-MiniLLM.md) 从序列级 reverse KL 处理采样分布对参数的依赖. [DistiLLM](1-基础与算法/1.1-白盒分布蒸馏/1.1.3-DistiLLM.md) 接着讨论 skew KL、历史学生样本复用和双路对比目标,并把离线 CoT SFT 与学生状态上的分布蒸馏放进同一坐标. 三篇一起读, 可以分辨目标函数、轨迹来源与梯度路径各自改变了什么.

### 2.2. 读公式时抓住四个动作

第一, 当前学生 $\pi_{\theta_k}$ 对输入 $x$ 采样回答 $y$. 第二, 在每个学生前缀 $s_t=(x,y_{<t})$ 上, 冻结教师 $\pi_T$ 计算下一 token 分布. 第三, 学生前向得到 $\pi_\theta(\cdot\mid s_t)$, 与教师分布计算损失. 第四, 优化器更新 $\theta$, rollout 服务同步或延迟同步到新参数. 每一步都要分清「生成时使用的学生快照」与「反向传播时更新的学生」; 大批量异步训练里二者通常不是同一个瞬时版本.

状态变化也要明确. rollout 前, 系统持有提示集合、学生快照和教师服务. rollout 后新增学生 token、attention mask 与采样 log-prob. 教师评分后新增教师 logits、top-$k$ 概率或 sampled-token log-prob. 反向传播后只有学生参数变化, 教师参数保持冻结; 若是 EMA 自教师, 教师参数会按平滑规则另行更新. 为节省显存而只保存 top-$k$ 或已采 token 时, 丢掉的是教师在其余词表上的相对概率. 为减少方差而停止对采样过程求导时, 丢掉的是「当前 token 改变后续状态分布」的梯度项.

## 3. 适用条件与工程判断

### 3.1. 教师与学生是否兼容

是否采用 OPD, 不能只比较最终榜单. 如果学生尚不能生成可解析的回答, on-policy batch 会被格式错误和无意义前缀占满, 教师即使逐 token 评分也难以提供稳定方向. 这时先做 SFT 或 off-policy 冷启动更合理. 如果教师与学生 tokenizer 不同, 逐 token logits 不能直接对齐; 需要字符或字节级对齐、教师重分词后的序列目标, 或退到序列级反馈. 如果教师只能通过 API 返回文本, full-vocab KL 不可用, 方法已经转向黑盒反馈蒸馏.

教师能力强也不是充分条件. 教师必须能理解学生的思考路径, 并在学生访问的前缀上给出比学生自身更有信息的条件分布. 教师与学生的推理风格差得过远时, 学生前缀对教师可能是低概率输入; 教师局部打分会抖动, 甚至奖励语法修补而忽略全局解题方向. 因此训练前应同时测任务分数、教师在学生 rollout 上的困惑度、师生 top-token 重合率和教师优势随位置的分布.

### 3.2. 计算与接口是否承受得住

工程上还要把 Prefill 与 Decode 分开核算. 学生生成需要顺序 Decode; 教师对已经完整的学生回答通常可以一次 Prefill 并行评分. 因而「多一次教师前向」不等于把生成耗时简单翻倍, 但教师尺寸、序列长度、词表投影和跨机通信会决定实际瓶颈. full-vocab 反馈信息最全, 通信量约随 $B\times T\times |V|$ 增长; top-$k$ 和 sampled-token 依次降低通信, 同时增加估计偏差或方差.

部署约束会反过来决定算法选择. 单机训练通常优先避免同时物化师生完整 logits;独立教师集群能扩大模型尺寸, 却要承担跨机传输. 在确定损失前先测教师吞吐、链路带宽和学生平均长度, 可以避免选出数学上合适、系统上无法持续供数的配置.

## 4. 阅读与扩展

### 4.1. 一条可执行的阅读顺序

路线首页先把状态 $s_t$、访问分布 $d_{\pi}$ 和条件分布 $\pi(\cdot\mid s_t)$ 分开. GKD 展示固定轨迹比例 $\lambda$ 与散度 $D$ 如何独立变化;MiniLLM 沿序列 reverse KL 的梯度推到 reward-to-go,解释采样过程参与求导后新增的项;DistiLLM 比较当前学生、历史学生和教师轨迹,也由此划开 CoT 数据进入 SFT 与进入特权教师的两种训练方式.

后续扩展可沿三个方向进入. 白盒路线研究完整 logits、top-$k$ 与单 token 估计; 自蒸馏路线研究如何用参考解或反馈构造特权教师; 长时程路线研究多轮环境、前缀回放和信用分配. 三条路线共享本库的判定标准: 学生是否产生受监督状态, 教师是否在同一状态上提供行为目标, 训练时实际保留了教师分布的哪一部分.

### 4.2. 从论文走向训练器

阅读论文公式后, 应立即在训练器里寻找四个对应点: rollout 权重版本、教师前向入口、损失归一化和权重同步. 如果代码只暴露一个名为 `distillation_loss` 的开关, 还不足以确认实现了哪一种 OPD. 需要继续检查轨迹是否每轮刷新、KL 参数顺序、prompt mask 与 response mask, 以及教师 logits 是否被 top-$k$ 截断.

完成小规模验证后再扩大序列长度. 长上下文会同时放大 rollout 时间、logits 内存和策略滞后, 短序列上可忽略的 EOS 偏置也可能累积成明显长度漂移. 扩容应逐项记录吞吐、显存、教师失败率与任务指标, 不能只比较最终准确率.

## 5. 主要来源

### 5.1. 论文

[GKD 原论文](https://openreview.net/forum?id=3zKtaqxLhW)与其 [arXiv 版本](https://arxiv.org/abs/2306.13649)给出混合轨迹和散度实验,[MiniLLM 原论文](https://arxiv.org/abs/2306.08543)推导序列 reverse KL,[DAgger](https://proceedings.mlr.press/v15/ross11a.html)提供状态分布偏移的模仿学习背景.[verl 的 OPD trainer 文档](https://github.com/verl-project/verl/blob/main/examples/on_policy_distillation_trainer/README.md)展示可运行系统中的组件划分.

这些来源承担不同作用. DAgger 给出状态分布偏移的理论背景; GKD 提供现代自回归模型中的可组合目标; MiniLLM 展开序列 reverse KL 的梯度. 三者不应相互替代, 因为它们对数据聚合、采样梯度和教师反馈粒度的假设不同.

### 5.2. 官方实现入口

verl 文档展示学生 rollout、冻结教师与 learner 如何拆成服务, 适合核对分布式数据流. 工程实现迭代快, 配置名与默认值可能变化;引用实现时应固定提交版本, 并回到论文确认损失含义.

严格 OPD 同时要求学生产生受监督前缀、教师在相同状态上提供行为目标. 估计器还必须标明丢掉了哪些教师信息. 仅有 on-policy 采样或教师文本, 都不满足完整定义.

## 6. 一张图景: 到底是谁产生状态, 谁提供方向

把语言模型生成写成有限时域决策过程会很方便. prompt 是初始条件, 已生成前缀 $s_t=(x,y_{<t})$ 是状态, 下一个 token $y_t$ 是动作. 学生策略记作 $\pi_\theta$, 教师策略记作 $\pi_T$. 一条训练样本至少涉及三个分布: prompt 分布 $\mu(x)$、产生前缀的轨迹分布和在前缀上给出的目标分布. SFT 通常读取固定回答形成的前缀, 序列蒸馏读取教师生成形成的前缀, OPD 则让学生生成前缀, 再让教师回答「走到这里以后, 下一个 token 应怎样分配概率」.

这个区分比方法名称可靠. 同一段代码既可能是严格 on-policy, 也可能因为权重同步滞后、轨迹多轮复用而变成 near-policy; 同一篇论文既可能在学生轨迹上用 forward KL, 也可能用 reverse KL 或广义 JSD. **on-policy 描述状态从哪里来, KL 方向描述在同一个状态上怎样比较两个动作分布.** 两者是两根轴, 不能用「用了 reverse KL」反推轨迹一定来自当前学生.

若把教师分布压缩成已采 token 的一个 log-prob, 教师仍能提供逐 token 信号, 但学生看不到其他候选 token 的相对关系. 若返回 top-$k$ 再加尾部概率质量, 训练的是词表粗分后的近似目标. 若返回完整 logits, 可以精确计算局部散度, 代价是 $B\times T\times |V|$ 张量的显存与通信. 三种接口传递的信息不同, 所以「都叫蒸馏」不代表它们拥有相同的梯度.

## 7. 从 SFT、RL 到 OPD

SFT 的优势是简单、稳定, 一条教师示范也能反复训练. 它的问题出现在自由生成阶段: 学生一旦产生教师示范里没有的前缀, 后续每一步都在训练分布之外. DAgger 很早就指出, 序列决策中的单步误差会通过状态转移累积;解决办法是收集学习者真正访问的状态, 再由专家标注这些状态. GKD 可以看成这一思路在自回归语言模型上的分布级版本.

RL 也使用学生轨迹, 但典型终局奖励只告诉模型整条回答好不好. 对长度为 $T$ 的回答, 一个标量需要经过信用分配才能影响 $T$ 个决策. OPD 在每个前缀上得到教师分布, 信号密度随 token 数增加. 代价也很明确: 教师必须理解学生已经犯过错的前缀, 而且教师偏好成为能力上界的一部分. 当目标是发现教师不会的策略时, 环境奖励仍不可替代.

DPO 使用偏好对构造离线分类式目标, 通常不要求当前学生生成回答. 它与 OPD 都可以出现参考策略和 log-ratio, 但数据分布与监督对象不同. DPO 比较 chosen/rejected 的相对偏好;OPD 比较同一学生状态上的师生动作分布. 把二者放进同一训练器没有问题, 前提是分别记录各自的数据来源、归一化与权重.

## 8. 能力从哪里来

教师比学生大只是最常见的情形. 特权教师还可以是同一个参数模型加参考解、工具结果、环境反馈或旧版本能力. 这时「自蒸馏」并非凭空产生知识: 新信息位于教师额外看到的条件中. 学生在自己的前缀上学习怎样利用这些信息诱导出的行为, 最终部署时不再携带特权上下文.

教师优势需要在学生访问的状态上成立. 独立答题分数高, 不保证教师遇到学生的错误推理前缀仍能给出可靠延续. 一个直接诊断是从学生正确与错误轨迹中截取前缀, 比较教师对可恢复动作的概率 margin. 教师若在错误状态上同样混乱, 增加蒸馏步数只会更精确地拟合一份不可靠目标.

学生初始化也决定能否学到教师模式. reverse KL 主要在学生已有支持上重新分配概率;若目标 token 在学生分布中几乎没有质量, 采样很难访问对应路径. 这解释了为什么许多 OPD 配方先做 SFT 或领域中训: 前一阶段负责把有用模式放进支持集, 后一阶段再沿学生会走的路径校正选择.

### 8.1. 如何判断一项结果真的来自 OPD

最基本的对照包含固定前缀 KD、学生前缀 OPD 与只有任务奖励的 on-policy RL. 三组应共享学生起点、prompt 集合、教师版本和尽量一致的优化 token 数. 若只给相同步数, OPD 额外消耗的学生生成与教师评分没有计入;若只给 GPU 小时, 不同硬件并行方式又会改变结论. 因而至少同时报告训练 token、教师 token、总计算和墙钟时间.

能力指标之外还应看回答长度、重复率、熵、师生 KL、学生 rollout 成功率和旧能力保留. KL 下降只能说明学生靠近教师, 不能单独证明任务能力提高. 任务分数上升也可能来自长度或采样策略变化. 把这些曲线放在一起, 才能区分目标有效、估计器稳定和解码碰巧有利.

失败也有清晰分类. 教师在坏前缀上失灵属于目标质量问题;优势长尾和训练振荡属于估计器问题;rollout 版本滞后属于状态分布问题;tokenizer 不同属于动作空间不兼容;EOS 与 mask 错位属于实现问题. 这些故障需要不同修复, 用一个较小学习率同时压住它们只会掩盖原因.

**OPD 最值得抓住的原理是「在学习者会遇到的状态上提供稠密行为监督」.** 状态的新鲜度、教师在这些状态上的可靠性以及教师分布保留到什么粒度, 共同决定了这个原理在实际训练中还剩多少.
