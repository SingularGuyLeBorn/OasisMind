# OPSD:参考解条件化的自蒸馏

推理数据集常常同时拥有两样东西:一道题的参考解,以及一个已经具备基本解题能力、却仍会在自由生成时走偏的模型.直接拿参考解做 SFT,模型只在参考解给出的正确前缀上学习;只做结果奖励 RL,模型又只能在整条回答结束后收到一个稀疏分数.2026 年 1 月发布的 **Self-Distilled Reasoner** 把两者接了起来:先让学生模型生成自己的轨迹,再让同一个模型在额外看见参考解的条件下,沿学生已经生成的前缀给出下一 token 分布.论文把这套方法称为 **On-Policy Self-Distillation,OPSD**.

这里最容易看错的是参考解的位置.学生仍然自己生成训练前缀,参考解只进入教师上下文,帮助同一模型判断走到当前位置以后应该怎样继续.OPSD 关心的是一个更贴近实际生成的问题:模型已经到达自己会访问的状态,参考解能否帮助它从这里作出更好的下一步判断?

## 1. 参考解放在哪里,决定模型学到什么

给定问题 $x$,当前学生策略先生成轨迹

$$
y\sim \pi_{\theta_k}(\cdot\mid x),\qquad s_t=(x,y_{<t}).
$$

$s_t$ 是部署时真实可能出现的状态.其中既有正确推导,也会有符号抄错、分支选错、计算滑移和已经无法挽回的坏前缀.教师随后读取同一个 $s_t$,只是额外看一份经过验证的参考推理 $r^*$:

$$
q_t(v)=\pi_{\bar\theta}(v\mid x,r^*,y_{<t}),\qquad
p_t(v)=\pi_\theta(v\mid x,y_{<t}).
$$

参考解在当前位置带来的局部条件增益可以直接写成

$$
\Delta_t(y_t)=\log \pi_{\bar\theta}(y_t\mid x,r^*,y_{<t})-
\log \pi_{\theta}(y_t\mid x,y_{<t}).
$$

$\Delta_t$ 为正,表示参考解提高了当前 token 在教师视角下的相对可信度;它沿序列的位置变化,也能用来判断参考推理究竟帮助了错误恢复,还是只强化已经正确的前缀.

学生分布 $p_t$ 只看到部署时可得的信息,教师分布 $q_t$ 多看到参考解.教师前向停止梯度,参数更新只作用于学生.论文使用冻结在训练起点的教师参数,把能力差明确地归因于参考解条件,也避免教师跟随学生迅速漂移.**参考解提供方向,学生 rollout 决定训练发生在哪里.**

这项安排与参考解 SFT 有实质差别.设参考解 token 为 $r_t^*$,SFT 优化

$$
\mathcal L_{\mathrm{SFT}}=-\sum_t\log \pi_\theta(r_t^*\mid x,r_{<t}^*).
$$

所有前缀都来自正确轨迹.学生部署时一旦生成 $y_{<t}\neq r_{<t}^*$,后续状态便离开了训练分布.OPSD 保留 $y_{<t}$,让教师在这个前缀上使用参考解.假如学生把变量 $a$ 错写成 $b$,SFT 仍然讲「在正确的 $a$ 后面写什么」,OPSD 问的是「已经写成 $b$ 以后,还有没有可执行的修复动作」.前者适合建立标准解题模式,后者把监督送到模型自己的错误附近.

参考解条件化也不同于把参考答案拼到学生输入里.学生若在训练时直接读到 $r^*$,学到的是带答案条件的策略;部署时移除参考解,输入分布立刻变化.OPSD 必须严格隔离两套可见范围:教师能读参考解,学生不能读;师生共享学生前缀,参考解不能混进学生 attention mask.这条边界若被破坏,loss 可能降得很快,实际却只是在做答案泄漏.

## 2. 从教师分布到可优化的逐 token 目标

OPSD 使用 full-vocabulary 的逐 token 分布监督.以教师到学生的 forward KL 为例:

$$
\mathcal L_t=D_{\mathrm{KL}}(q_t\Vert p_t)
=\sum_{v\in V}q_t(v)\log\frac{q_t(v)}{p_t(v)}.
$$

硬标签只告诉学生哪一个 token 被选中,完整分布还保留替代动作之间的相对关系.例如教师可能同时认为「因此」「由此」和一个公式起始符都合理,只是概率不同;也可能在学生出错后显著提高「回代」「检查」一类恢复动作.这些差异都能进入梯度.一条长度为 $T$ 的错误轨迹在结果奖励下通常只得到一个失败分数,OPSD 则可在 $T$ 个位置产生不同的局部训练信号.相邻 token 高度相关,信息量当然不能简单说成增加 $T$ 倍,但信用分配确实细了许多.

从单个动作看,参考解是否真的有用,可以写成条件优势

$$
A_T(s_t,a)=\log p_{\bar\theta}(a\mid s_t,r^*)-
\log p_{\bar\theta}(a\mid s_t).
$$

若经过过程验证的可接受动作 $a^+$ 在错误前缀上满足 $A_T(s_t,a^+)>0$,参考解提高了教师对恢复动作的判断.若优势只出现在本来就正确的前缀,OPSD 可能主要强化已有路径;若变化集中在标点和格式 token,条件信息并没有触及推理瓶颈.所以,教师最终答案正确率还不够,还应检查错误开始附近的关键 token margin、条件化前后的续写成功率,以及教师能否从学生状态完成恢复.

完整词表 logits 会增加显存、通信和计算压力.论文对逐 token 概率比做裁剪,限制坏前缀上极端小概率造成的异常更新.抽象地写,若某项权重来自师生概率比 $w_t(v)$,训练使用

$$
\widetilde w_t(v)=\operatorname{clip}(w_t(v),1-\epsilon,1+\epsilon).
$$

这里裁剪的是局部分布项,不能与 PPO 的整段策略比率混为一谈.阈值过松时,少数极端位置会支配梯度;阈值过紧时,教师最明确的纠错意见也会被截掉.复现时应同时记录裁剪比例、被裁剪位置的 token 类型、裁剪前后的梯度范数与任务表现,否则只报最终正确率看不出稳定性来自哪里.

KL 的方向也会改变行为.forward KL 倾向覆盖教师给出的多种合理续写,对多解推理更宽容;reverse KL 更偏向学生支持集内的高概率模式,更新通常更集中.无论采用哪种方向,都要保证教师 logits 与学生 logits 对应同一学生前缀、同一响应位置和同一词表.前缀错位一个 token,优化的就不再是同一个条件分布.

## 3. 为什么它可能比结果奖励更省样本

RLVR 依靠可验证奖励发现成功轨迹.当一组 rollout 全部失败时,组内相对优势很难告诉模型哪一步稍好;即使存在成功样本,序列级奖励也要通过整段 log probability 回传,局部动作共享同一结果.OPSD 已经持有经过验证的参考推理,教师可以把这份序列信息转成每个学生状态上的词表分布.学生不必反复采样到成功以后才得到方向,于是论文在数学推理实验中观察到更高的训练 token 效率.

token 效率与计算效率要分开看.OPSD 一次更新包含学生 Decode、参考条件教师前向、学生前向与反向,完整词表路径还可能成为显存瓶颈.GRPO 等方法通常生成更多 rollout 并调用验证器,却不一定保存每个位置的全词表分布.因此「使用更少训练 token」不自动等于「GPU 小时同比减少」.合理的成本表至少同时列出学生生成 token、教师输入 token、教师前向耗时、learner 前反向耗时、峰值显存和最终任务得分.

OPSD 也没有取代搜索.它能把模型在看见参考解时表现出的能力压回参数,却不会凭空产生参考解之外的新策略.环境探索或搜索负责找到新的成功轨迹,OPSD 负责高效吸收这些轨迹,二者可以形成循环:先由搜索扩充经过验证的参考集合,再用自蒸馏把条件能力固化到无参考模型中.如果奖励环境能够发现教师未知的解法,纯 OPSD 的上限仍受现有参考信息约束.

一组清楚的二乘二消融可以拆开收益来源.四组分别是参考轨迹 SFT、参考条件教师配固定参考前缀、参考条件教师配学生前缀、无参考条件的学生前缀自蒸馏.第一组与第二组比较硬标签和软分布;第二组与第三组比较训练状态来源;第三组与第四组衡量参考解带来的条件增益.只比较 OPSD 和某个 RL 基线,会把分布目标、on-policy 状态与特权信息三项变化混在一起.

## 4. 参考解并不天然构成好教师

OPSD 需要一个不太弱的模型起点.教师和学生参数同源,教师的额外能力来自上下文使用,不是参数规模.若模型本来就读不懂参考证明,把证明放进 prompt 不会自动生成更好的局部分布;若学生 rollout 大量无法解析,教师也可能找不到恢复路径.开始训练前,应在冻结轨迹上比较同一模型加入参考解前后的正确续写率.条件视图没有稳定优势时,继续蒸馏只是在拟合另一份近似自身的分布.

错误前缀还分为「可恢复」与「不可恢复」.算错一个中间数值,后续可以重新计算;违反输出协议、删掉必要变量或走进逻辑矛盾后,局部下一 token 未必能挽回.有显式回溯动作的任务适合在错误位置直接学习修复,没有回溯协议的自回归推理则可能需要把未来失败的信用传回更早的分叉点.按错误首次发生位置分桶,再统计教师从各类前缀续写成功的概率,比全局平均 KL 更能说明方法是否工作.

参考轨迹本身也可能引入问题.一题多解时,参考解只代表其中一条路径,教师若把其他正确路线压低,学生的多样性反而会下降.参考解使用不同符号、跳过关键步骤或带有偶然格式时,教师条件变化可能主要反映风格而非推理.比较多个独立参考解、随机更换等价表达,并检查教师对学生已有正确分支的保留程度,可以判断它是在传递解题信息,还是在做表面模仿.

如果参考解有误,稠密分布会比单个硬标签更广泛地传播错误.高奖励轨迹也不必然可靠,尤其在验证器存在漏洞时.用于 OPSD 的参考集合应经过独立验证,最好保存验证器版本、原始轨迹哈希与题目版本.参考条件若来自搜索,还要防止训练集与评测集通过生成轨迹发生语义泄漏.

学生能否在无参考条件下重现教师判断,又是一道单独门槛.教师可能依靠 $r^*$ 中部署时完全不可推断的信息作答.这种情况下,师生 KL 可以下降,学生却只能学到样本相关的统计捷径.逐步减少参考细节、在未见题型上测试、比较教师优势与学生收益的相关性,能够检查条件能力是否真正可迁移.

## 5. 训练流水线和实验应怎样检查

一次可靠更新从版本一致性开始.学生用参数版本 $\theta_k$ 生成 rollout,教师在这些固定前缀上计算条件分布,learner 再完成若干更新.若同一批轨迹复用太久,当前学生已经变成 $\theta_{k+m}$,数据便逐渐失去 on-policy 性质.可以记录行为策略与当前策略在响应 token 上的 KL,超过阈值后重新生成,而不是仅按固定步数猜测轨迹是否仍然新鲜.

每条样本至少保存原问题、学生可见 prompt、参考解来源与哈希、rollout 模型版本、教师模型版本、采样温度、响应掩码、教师 logits 精度、裁剪统计和验证结果.OPSD 还应记录参考轨迹与学生当前前缀的对齐关系.只保存最终拼接字符串很难发现 mask 泄漏;最好分别落盘 student input 与 teacher input,并在 token 级比较二者差异是否只来自特权区域.

实现中有三类常见错位.第一类是学生 mask 意外放开参考解,模型学成带答案策略.第二类是教师沿参考解前缀评分,而不是沿学生前缀评分,训练退回离线蒸馏.第三类是把教师输入新增的参考 token 也纳入响应 loss,导致两侧位置不对应.最小批次测试应构造一个学生明确走错的短例子,逐位置打印师生可见 token、目标 logits 和有效 mask,人工确认损失确实落在学生响应上.

实验报告不能只给最终平均分.OPSD 至少要与参考解 SFT、无参考自蒸馏、外部教师 OPD 和结果奖励方法对照,并使用同一起点、同一题集与明确的 token/计算预算.任务指标之外,还要报告错误前缀恢复率、教师条件增益、输出熵、多解覆盖、被裁剪比例和成本分解.这些量合在一起,才能判断提升来自参考解提供的信息、学生状态覆盖,还是额外计算.

最终可以用三道问题验收:参考解是否让同一模型在学生前缀上更会判断,这种差异是否被正确转换为逐 token 梯度,无参考学生是否在未见样本上重现了改进.三道门槛依次对应教师质量、实现正确性与能力迁移.只要其中一项不成立,更密的监督也可能只是更快地拟合无用目标.

## 6. 与相邻方法的边界

普通 OPD 使用独立的强教师,能力差来自参数规模或专门训练;OPSD 使用同源冻结教师,能力差来自参考解上下文.上下文蒸馏也会把特权 prompt 下的行为写回无特权模型,但若目标序列和前缀固定,仍然属于离线状态.OPSD 的学生 rollout 让监督抵达当前策略真正访问的位置,这正是名称中 on-policy 的含义.

过程奖励模型在每一步给标量,OPSD 教师给完整动作分布.前者可以独立审计,也能在没有参考全文时使用;后者不必额外训练 reward model,却更依赖同源模型对参考解的理解.二者可以互相验证:过程标签确定哪些动作可接受,教师分布补充多个候选动作之间的相对关系.

SDFT 同样让学生生成状态,但特权信息是少量任务示范,目标是把 in-context skill 写入参数并缓解顺序学习遗忘.SDPO 的特权信息来自当前 rollout 触发的环境反馈或成功尝试,反馈会随策略变化.OPSD 的参考解通常在训练前固定,三者之中数据非平稳性最低.这也使 OPSD 更适合参考轨迹质量高、希望提升数学与可验证推理训练效率的场景.

### 6.1. 参考推理怎样变成自教师

Self-Distilled Reasoner 的出发点是: 推理数据常有经过验证的解答轨迹, 普通 OPD 却只用外部教师在学生轨迹上评分, 没有显式利用这些解答. OPSD 让同一个模型一边只看问题作为学生, 一边额外看验证轨迹作为教师. 教师借助参考推理解释学生状态, 再给每个 token 稠密分布. 形式上, prompt 为 $x$, 参考轨迹为 $r^*$, 学生 rollout 为 $y\sim q_\theta(\cdot\mid x)$. 教师读取 $(x,r^*,y_{<t})$, 学生读取 $(x,y_{<t})$. 局部目标可以写成

$$
L_{\mathrm{OPSD}}=
\mathbb E_{y\sim q_\theta}
\left[\frac1T\sum_t
D\big(p_{\bar\theta}(\cdot\mid x,r^*,y_{<t})
\|q_\theta(\cdot\mid x,y_{<t})\big)
\right]. \tag{18}
$$

$r^*$ 不替换学生 rollout, 只改变教师条件. 因此教师是在学生真正访问的错误前缀上利用参考解给方向. 与直接对 $r^*$ 做 SFT 相比, OPSD 的监督位置更接近部署状态;与外部教师 OPD 相比, 它不需要另一套更大参数.

**参考解不能简单拼到 response 前面.** 教师上下文与学生上下文长度不同, response span 的 logits 必须按学生 token 对齐. 教师在读完参考解后, 对学生第一个 response token 的预测位置位于另一绝对索引. 按绝对位置切片会错位.

**固定教师与在线教师.** 若 teacher branch 使用冻结检查点, 目标稳定, 特权条件提供能力差. 若教师与学生共享实时参数, 每次更新同时改变无特权和特权分布, 目标移动. EMA 能平滑变化, 不会创造信息. OPSD 的效果仍取决于参考轨迹能否让教师保持优势.

**4–8 倍 token 效率的口径.** 原论文报告在数学推理任务上相较 GRPO 等 RL 方法达到约 4–8 倍 token 效率. 这来自逐 token 教师信号比终局二值奖励密集. 它对应论文的模型、任务和训练 token 口径, 不表示所有算力维度都减少同样倍数;教师额外前向也要计入计算.

**稠密信号为何提高效率.** 一条 $T$ token 错误解答在 RLVR 中通常只得到 0, 许多动作共享同一个负信号. OPSD 教师能在错误发生前后给不同分布, 每个位置都产生梯度. 学生更快识别哪一步偏离参考思路, 不必靠大量轨迹统计完成信用分配.

**参考轨迹的多样性.** 一个问题可能有多种正确证明. 单一 $r^*$ 会让教师偏向一种风格, reverse KL 进一步集中模式. 若目标需要多样推理, 可给多条验证轨迹、随机选择参考或让教师只读取关键中间结论. 这些处理改变教师条件分布, 应单独比较.

**错误参考的风险.** 被验证的最终答案正确, 中间推理仍可能有漏洞;自动验证器也可能被钻空子. 特权教师会把参考中的错误扩散为每 token 监督. 训练前需要验证轨迹质量, 并在学生错误状态上抽查教师建议.

**能力上限.** OPSD 能把模型在有参考解时表现出的能力压回参数, 不能保证发现参考解之外的新策略. 环境搜索或 RL 负责产生新成功轨迹, OPSD 适合高效吸收这些轨迹. 两者可以交替: 搜索扩充特权信息, 自蒸馏把信息固化.

### 6.2. 目标分解与反例

把 OPSD 的教师记为 $p_{\theta^-}(a\mid s,r^*)$, 学生为 $q_\theta(a\mid s)$. 若用 reverse KL, 单状态损失为

$$
\ell(s)=\sum_a q_\theta(a\mid s)
\log\frac{q_\theta(a\mid s)}{p_{\theta^-}(a\mid s,r^*)}. \tag{22}
$$

教师与学生词表相同, 分布差只来自参考轨迹与可能的参数时间差. 把参考轨迹去掉, 固定教师仍可能因旧检查点产生差异;把参数设为完全相同, 剩余差异才纯粹归因于 $r^*$. 一个干净消融应同时包含「同参数无参考」「旧参数无参考」「同参数有参考」三组.

**参考信息增益.** 定义教师在学生状态上的局部优势

$$
A_T(s)=\log p_T(a^+\mid s,r^*)-log q(a^+\mid s), \tag{23}
$$

其中 $a^+$ 是由过程验证或正确轨迹确定的可接受动作. 若 $A_T$ 在错误前缀上显著为正, 参考解确实让同源模型更会纠错. 只在正确前缀上为正, OPSD 可能主要强化已有路径, 对错误恢复帮助有限.

**参考解与学生前缀的矛盾.** 学生可能已经采用另一条同样正确的证明路线, 与 $r^*$ 表面不同. 教师若机械依赖参考解, 会把合法分支判成错误. 多参考、答案验证或语义过程检查可以降低误伤;单一 token 对齐无法判断两条证明是否等价.

**前缀不可恢复.** 假设学生第一步引入矛盾命题, 后续任何续写都无法形成严格正确证明. 教师在该状态上最合理的动作可能是显式回溯或重启. 如果输出协议不允许回溯 token, 局部蒸馏只能让错误后的文本更连贯, 无法修正第一步. 需要序列信用或从分叉前状态重采.

**参考解过强的复制捷径.** 教师看到完整 $r^*$ 后, 可能忽略学生前缀, 直接输出参考下一 token. 这在与参考同路时很好, 在学生异路时会产生断裂. 可比较教师对学生前缀的注意或行为: 打乱学生前缀后教师分布几乎不变, 说明它主要复制参考.

**答案型与过程型特权.** 只给最终答案, 教师需要自行恢复推理;给完整过程, 教师更容易定位, 也更容易复制. 两者形成信息量与捷径风险的权衡. 实验可分答案、关键中间结论、完整轨迹三档, 观察教师恢复率和学生泛化.

**参考轨迹由谁生成.** 人工或形式验证轨迹可信度高、数量有限;强模型轨迹规模大、可能含隐性错误;搜索得到的轨迹有验证结果, 风格可能狭窄. 数据来源决定特权教师上限. 只报告最终答案验证不足以证明中间步骤可靠.

**OPSD 与直接 SFT 的二乘二.** 以同一参考数据构造四组: 参考轨迹 SFT、参考条件教师配固定前缀、参考条件教师配学生前缀、无参考条件的学生前缀自蒸馏. 第一与第二看软分布作用, 第二与第三看状态来源, 第三与第四看特权信息. 这样才能把 OPSD 收益拆开.

**token 效率与信息密度.** RLVR 一条轨迹给一个标量, OPSD 每个位置给词表分布. 若长度为 $T$, 可用监督位置从 1 增至 $T$, 每位置还含多个候选概率. 信息量不严格等于 $T$ 倍, 因相邻 token 高度相关;但信用分配显著更密, 能解释论文报告的 token 效率.

**计算效率未必同比提高.** OPSD 要做学生 Decode、特权教师前向和学生反向;GRPO 要多条 rollout 与验证, 不一定需要大词表 logits. token 使用减少 4–8 倍, GPU 小时取决于教师实现、词表投影、batch 与并行. 两种口径必须分开.

**参考条件长度.** 很长 $r^*$ 增加教师 Prefill 成本, 还可能挤占学生轨迹上下文. 可压缩为关键步骤, 但压缩可能丢失纠错依据. 参考长度消融应同时测教师优势、训练吞吐和截断率.

**参考解中的风格.** 教师会把参考用词、格式和推理长度一并传给学生. 若目标只要正确性, 可规范化参考或在语义步骤处监督;若部署需要该风格, 则保留. 任务收益与风格迁移应分别评价.

**自教师参数的 stop-gradient.** 即使 teacher 和 student 共享底层权重来源, teacher forward 必须冻结计算图. 否则优化器既移动学生预测又移动目标, KL 可通过两边靠近而下降. EMA 或旧 checkpoint 还需确认没有参数别名.

**参考条件的安全边界.** 参考轨迹可能含敏感推理或数据. 训练后学生有机会记忆并复现. 自蒸馏并不会自动删除特权内容, 只移除部署时上下文. 数据授权和记忆测试仍需执行.

OPSD 把参考解放进教师视角,再在学生真实走过的状态上产生可学习的分布.学生学习局部判断,无需逐字复现标准答案.原论文见 [Self-Distilled Reasoner: On-Policy Self-Distillation for Large Language Models](https://arxiv.org/abs/2601.18734),横向坐标见[自蒸馏首页](04-自蒸馏.md).
