# OPD 到底是什么

自回归模型的训练样本不是一串彼此独立的标签. 第 $t$ 个 token 会进入第 $t+1$ 步的输入, 因而早期预测会改变之后看到的全部状态. 固定数据训练把前缀当作外部给定条件; 自由生成把前缀变成模型自身动作的结果. OPD 的基础问题由此产生: 如果部署时的状态由学生自己诱导, 教师监督是否也应落在这些状态上?

这一章只处理 OPD 的共同骨架. 输入 $x$ 来自任务分布 $\mathcal D$, 学生策略为 $\pi_\theta$, 教师策略为 $\pi_T$. 学生生成 $y=(y_1,\ldots,y_T)$, 第 $t$ 步状态写成 $s_t=(x,y_{<t})$. 轨迹概率为

$$
P_{\pi_\theta}(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid s_t). \tag{1}
$$

式 (1) 说明, 训练时选择谁来生成 $y$, 就等于选择在哪一种状态访问分布上学习. 条件损失可以相同, 外层分布不同仍会得到不同算法. 反过来也成立: 都使用学生 rollout, 但 forward KL、reverse KL 或 sampled-token 估计不同, 梯度性质仍然不同.

## 1. 三层参照系

### 1.1. 状态分布是第一层

固定数据蒸馏从数据分布 $d_{\mathrm{data}}$ 取状态, 教师在这些状态上输出软标签. 严格 OPD 从当前学生诱导的 $d_{\pi_{\theta_k}}$ 取状态, 再让教师对同一状态输出分布. 这里的下标 $k$ 表示第 $k$ 轮采样时冻结的学生快照. 优化器更新的参数仍写成 $\theta$; 把两者分开, 才能讨论多次复用同一批 rollout 后发生的策略滞后.

DAgger 提供了交互式模仿学习的参照: 让学习者访问自己的状态, 查询专家动作, 再聚合数据训练. LLM 的 OPD 与 DAgger 共享「学习者状态、专家监督」这一结构, 但并不完全相同. DAgger 常把历轮状态放进聚合数据集, 因而包含明显的 off-policy 成分; 严格 OPD 更强调用当前学生的新鲜轨迹. LLM 教师还可以返回整个词表分布, 而不是一个离散专家动作.

**「on-policy」回答状态从谁来, 不回答损失是什么.** forward KL 可以在学生状态上计算, reverse KL 也可以; 环境奖励来自学生轨迹, 但没有教师行为目标时仍是 RL. 这个边界能避免把所有在线生成训练都装进 OPD.

### 1.2. 条件分布匹配是第二层

在学生访问的状态 $s$ 上, 最一般的局部目标可以写成

$$
\mathcal L_{\mathrm{local}}(s)=D\!\left(\pi_T(\cdot\mid s),\pi_\theta(\cdot\mid s)\right), \tag{2}
$$

其中 $D$ 可以是 KL、JSD 或更一般的 $f$-散度. forward KL 以教师概率加权, 会惩罚学生漏掉教师支持的 token; reverse KL 以学生概率加权, 重点压低学生放了概率而教师不支持的 token. 「覆盖更多模式」与「集中到主要模式」是有限分布上的有用直觉, 不能脱离采样温度、模型容量和解码方式当作普遍保证.

完整词表计算式 (2) 时, 教师和学生都要输出形状为 $[B,T,|V|]$ 的 logits. top-$k$ 只保留一侧或两侧概率最大的 token, 其余概率可以丢弃或合成尾部桶. sampled-token 只读取学生实际动作 $y_t$ 的两侧 log-prob. 三种接口保留的信息依次减少: full-vocab 知道教师如何重新分配整个词表; top-$k$ 看不到尾部内部结构; sampled-token 连未采中的高概率替代项也看不到.

### 1.3. 序列目标是第三层

把式 (2) 沿学生轨迹求和, 可以得到常见的 stop-gradient 目标:

$$
\mathcal L_{\mathrm{OPD}}(\theta;\theta_k)=
\mathbb E_{x\sim\mathcal D,\,y\sim\pi_{\theta_k}}
\left[\frac{1}{T}\sum_{t=1}^{T}D\!\left(\pi_T(\cdot\mid s_t),\pi_\theta(\cdot\mid s_t)\right)\right]. \tag{3}
$$

式 (3) 中, rollout 被视为固定训练数据, 梯度不穿过 $y\sim\pi_{\theta_k}$. GKD 的 on-policy 版本主要采用这种结构. 如果把采样分布也写成待优化的 $\pi_\theta$, 再对整个序列 reverse KL 求导, 就会出现 policy-gradient 项和未来回报; MiniLLM 属于后一类. 两种目标都能使用学生轨迹, 但估计量、方差和信用分配不同.

[怎样学习教师分布](../02-怎样学习教师分布/02-怎样学习教师分布.md) 对三层关系作统一展开. [GKD](../02-怎样学习教师分布/2.1-外部教师/2.1.1-GKD.md) 适合先读, 因为它把轨迹混合比例与散度显式拆开. [MiniLLM](../02-怎样学习教师分布/2.1-外部教师/2.1.2-MiniLLM.md) 随后展示序列目标对参数求导时不能忽略的项. [DistiLLM](../02-怎样学习教师分布/2.1-外部教师/2.1.3-DistiLLM.md) 再把 skew KL、off-policy 复用和双路数据目标接进来,同时划清离线 CoT 蒸馏与 OPD 的边界.

### 1.4. 用三层参照系给方法定位

给一个训练配方命名之前, 先把三层分别填出来. 例如教师离线生成答案、学生对答案做交叉熵时, 状态来自教师轨迹, 局部目标是 one-hot 标签, 序列采样不参与求导;这是序列级蒸馏或 SFT. 学生生成回答、环境只给最终 0/1 奖励时, 状态来自学生, 局部没有教师分布, 序列目标通过奖励优化;这是 on-policy RLVR. 学生生成回答、教师在相同前缀返回完整分布、训练器把 rollout 停梯度时, 才落到典型 GKD 式 OPD.

还有一些中间情况. 学生生成前半段, 教师接管后半段, 被监督状态一部分来自学生、一部分来自教师;旧学生生成轨迹并被当前 learner 重复使用, 属于 near-policy;学生生成轨迹但教师只返回整条答案评分, 数据侧 on-policy, 信号侧却是 outcome-based. 这些配方可以放进广义 OPD 讨论, 公式必须保留各自真实接口, 不能因为名称相近便都写成 token KL.

一个最小定位表如下:

| 配方 | 状态来源 | 教师或环境返回什么 | 更新保留什么依赖 |
|---|---|---|---|
| 固定数据 SFT | 人工或教师答案 | 目标 token | 固定前缀上的局部交叉熵 |
| GKD 式 OPD | 当前学生 rollout | 同一前缀的词表分布 | 固定 rollout 上的局部散度 |
| MiniLLM 式序列 KD | 学生采样 | 已采动作上的教师概率 | 采样分布对参数的序列依赖 |
| RLVR | 学生 rollout | 可验证结果 | 结果对轨迹动作的优势 |
| 黑盒纠错 | 学生前缀 | 教师续写、批评或偏好 | 经 SFT、偏好或重试转成梯度 |

这张表能处理一个常见争论: sampled-token OPD 看起来像 RL, 到底算哪一种? 若教师 log-ratio 被当作奖励, 再经过 advantage、baseline 与策略梯度更新, 优化器确实沿用 RL 形式;信息源仍然是教师策略. “蒸馏”描述目标从教师来,“策略梯度”描述估计器怎样更新, 两个标签可以同时成立. 真正需要写清的是教师概率、参考策略、行为策略与 learner 分别是谁.

## 2. 训练循环与状态变化

一次同步 OPD 更新包含四段. rollout worker 用冻结学生快照生成 token 并保存采样 log-prob; teacher worker 对完整学生回答做 Prefill, 返回完整 logits 或压缩反馈; learner 重新计算学生 logits 与损失; optimizer 更新参数, 再把权重同步给 rollout worker. 如果每批数据训练多个 epoch, 第一个 epoch 后的数据就不再严格来自当前参数. 此时要么承认算法是 near-policy, 要么用重要性比率限制旧轨迹带来的偏移.

教师不参与反向传播, 所以教师服务可以只做推理. 但「不参与反向传播」不等于教师结果可以无限缓存: 学生前缀每轮变化, 相同 prompt 下的完整回答通常不同. 能稳定缓存的是 prompt token、教师权重和 tokenizer 资产; 学生回答对应的教师 logits 只对该回答有效. 自蒸馏若用 EMA 教师, 还会在优化器更新后执行教师参数的指数滑动平均, 此时教师状态随训练缓慢变化.

### 2.1. 工程边界

师生共用 tokenizer 时, token 位置可以逐项对齐. tokenizer 不同时, 学生一个 token 可能对应教师多个 token, 完整词表也没有共同索引. 直接按位置算 KL 没有数学含义. 可选方案包括约束师生共用 tokenizer、在字节区间上对齐并聚合概率、只让教师对学生 token 串计算序列 log-prob, 或改用文本反馈. 每种方案都改变了教师信息的粒度, 需要在实验中单独标明.

教师前向的算力也要按实际执行拆开. 学生 rollout 是自回归 Decode; 教师拿到完整回答后可以并行 Prefill. 但词表投影和 logits 传输可能超过 Transformer 主干. 例如 $B=32,T=4096,|V|=150000$ 时, 仅一份 bf16 logits 就约为 39GB. 分块计算 KL、只传 top-$k$、让师生同机消费 logits 或在教师侧直接计算部分损失, 都是在减少这块物化与通信.

训练监控至少覆盖四类量: rollout 新鲜度, 即采样版本与学习版本差多少; 教师优势, 即教师与学生在已采 token 上的 log-prob 差; 分布重合, 即 top-$k$ 交集与概率质量; 生成行为, 即长度、重复率、熵和任务成功率. 单看 KL 下降不能判断训练成功, 因为学生可能通过降低熵、缩短回答或进入教师也容易预测的重复区域来降低局部损失.

### 2.2. 监控与样本身份

rollout 新鲜度持续扩大, 说明生成服务同步跟不上 learner; 师生 top-$k$ 重合很高而任务分数不升, 说明教师没有提供新信息; 教师优势只在标点和格式 token 上显著, 说明监督没有进入任务核心步骤. 长度突然收缩时还要分解 EOS 的 KL, 不能把整体 loss 下降当成收敛.

这些指标必须按位置和轨迹质量分桶. 全局均值会把少量极端坏前缀隐藏起来, 也会把正确轨迹与错误轨迹的相反趋势抵消. 至少分别统计答对、答错、截断和重复轨迹, 再决定应调整采样、教师或损失.

要让 on-policy 这件事可检查, 每条轨迹至少保存 prompt 标识、rollout checkpoint、采样配置、生成 token、行为 log-prob、教师 checkpoint、教师输入模板和 learner checkpoint. 只有 token 没有版本, 后面无法判断样本来自当前策略还是历史缓存;只有版本号没有行为 log-prob, 又无法量化一次大更新与十次小更新造成的真实偏移.

教师输入也属于算法定义. 学生与教师必须读取同一段学生前缀, 特权自蒸馏再额外加入参考解、反馈或示范. 若教师模板自动修正了学生格式、删除了错误步骤或重新排列工具观察, 教师实际评分的是另一个状态. 这种预处理可以有价值, 但应写成状态编辑或纠错监督, 不能继续声称两侧条件完全相同.

多轮 Agent 还要保存环境状态标识. 对话文本相同, 文件系统、数据库或浏览器页面不同, 下一动作分布也会不同. 能重放的环境应保存快照或事件日志;不能重放的外部服务至少记录观察内容与时间. OPD 的“同一状态”在语言模型里常被简写成同一前缀, 到工具环境中必须扩展为模型当时真正可见且会影响转移的全部状态.

## 3. 读法与来源

### 3.1. 两篇核心方法的顺序

先用 GKD 理解轨迹来源与散度是两条轴, 再用 MiniLLM 理解采样分布参与求导后新增的未来项. 反过来阅读容易把所有学生采样方法都套进 policy gradient, 忽略大量实现实际采用 stop-gradient token 损失.

读完后可用一个问题检查理解: 给定训练代码, 能否指出 rollout 由哪个参数版本生成、教师在哪些前缀上前向、损失对哪些张量反传、哪些教师概率在压缩时被丢弃. 四项都有答案, 算法才算定义完整.

### 3.2. 论文与实现

基础定义来自 [Agarwal et al., 2024](https://openreview.net/forum?id=3zKtaqxLhW) 与 [Gu et al., 2023](https://arxiv.org/abs/2306.08543). 状态分布的交互式模仿学习背景见 [Ross et al., 2011](https://proceedings.mlr.press/v15/ross11a.html). 可运行系统的组件边界可对照 [verl OPD trainer](https://github.com/verl-project/verl/blob/main/examples/on_policy_distillation_trainer/README.md).

论文负责定义目标与实验范围, 实现文档负责展示当前系统接口. 配置默认值会变化, 引用工程行为时应固定版本;算法解释则回到论文公式, 避免把某个训练器的临时选项写成 OPD 的必要条件.
