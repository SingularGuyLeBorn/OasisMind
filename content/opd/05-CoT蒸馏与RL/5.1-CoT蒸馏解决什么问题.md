# CoT 蒸馏解决什么问题

强教师预先生成长推理轨迹, 学生在这些固定轨迹上做 SFT, 属于离线推理蒸馏. 它能把解题格式、分解习惯、回溯方式和验证步骤放进小模型的支持集. 对原本几乎采不到正确路径的学生, 这是进入 OPD 或 RL 之前最直接的冷启动.

CoT 的价值不等于越长越好. 正确终答、过程一致性、题目难度和轨迹多样性共同决定数据质量. 一段中间逻辑错误、只在结尾碰巧答对的长文本, 会把错误过程稳定写进参数. 数学与代码任务应利用答案检查器和执行器筛选;无法自动验证的任务需要多教师或人工复核.

离线蒸馏仍在教师前缀上训练. 学生自由生成时一旦写出教师数据里没有的步骤, 后续状态便脱离训练分布. OPD 转向学生自己的前缀, 再询问教师下一步应该怎样分配概率, 因而处理的是标准 CoT 没有覆盖的生成状态.

两者最自然的组合是:先用 CoT SFT 让正确模式进入学生可达区域, 再用 OPD 处理真实生成中的岔路. 若直接对极弱学生做 reverse-KL OPD, 学生采不到有价值的动作, 教师只能在低质量前缀上反复纠错. **CoT 蒸馏扩大“会走哪些路”, OPD 改善“走到这里下一步怎么选”.**

评测时要把长输出风格和推理能力分开. 模型学会频繁写“等等”“重新检查”并不表示准确率提高. 应同时报告未见题目上的结果、回答长度、单位 token 收益和简单题是否能及时停止.
