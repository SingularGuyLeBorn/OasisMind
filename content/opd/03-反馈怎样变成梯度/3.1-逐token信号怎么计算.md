# 逐 token 教师信号怎么计算

教师读到学生前缀后, 最完整的返回值是整个词表上的分布 $p_T(a\mid s_t)$. 训练器可以计算精确 token KL, 看到教师希望提高哪些候选、压低哪些候选. 代价是每个位置都要处理 $|V|$ 个数, 长序列与跨机训练下通信量很大.

Top-$k$ 接口只返回高概率候选和剩余尾质量. 它保留了主要替代动作, 但必须说明尾部怎样处理. 直接丢弃、重新归一化、把尾部合为一个桶, 会产生不同梯度. $k$ 不能只按显存选择, 还要统计教师尾质量和正确动作落在 top-$k$ 外的比例.

Sampled-token 接口只保留学生实际动作 $y_t$ 的教师与学生 log-prob:

$$
r_t=\log p_T(y_t\mid s_t)-\log q_\theta(y_t\mid s_t).
$$

它能形成逐 token 的正负方向, 也能直接接入策略梯度训练器. 但当 $y_t$ 被压低时, 接口没有告诉学生概率应该转移给哪个未采动作. Softmax 会自动把质量分给其他 token, 分配结果主要由学生自身分布决定.

因此要分清两个问题. 时间信用决定 $r_t$ 是否影响此前动作;词表路由决定当前动作被压低后谁得到概率. Full-vocab KL 擅长后者, return-to-go、baseline 和 advantage 处理前者. **“每个 token 都有反馈”只能说明信号位置密, 不能说明反事实方向完整.**

实现检查应覆盖 response mask、温度、教师 stop-gradient、EOS、词表一致性与长度归一化. 教师和学生 tokenizer 不同的情况下, 第 $i$ 个 logit 没有共同语义, 不能直接计算 KL. 此时应改用序列反馈或设计显式对齐.
