# OPSD、SDFT 与 SDPO

OPSD、SDFT 与 SDPO 都把同源模型拆成两个条件视图. 学生只看部署时可得的信息 $x$, 自己采样回答 $y$;教师读取同一条学生轨迹, 但额外看到特权信息 $c$. 三者的区别不在「是否自蒸馏」, 而在 $c$ 从哪里来、教师参数怎样更新、师生分布用什么估计器比较, 以及训练希望解决哪一种能力缺口. 共同目标可写为

$$
y\sim\pi_{\theta_k}(\cdot\mid x),\qquad
\mathcal L(\theta)=\mathbb E_y\left[\sum_{t=1}^{T}w_t
D\!\left(\operatorname{sg}[\pi_{\bar\theta}(\cdot\mid x,c,y_{<t})],
\pi_\theta(\cdot\mid x,y_{<t})\right)\right]. \tag{1}
$$

$\theta_k$ 是生成轨迹的学生快照, $\theta$ 是 learner 当前参数, $\bar\theta$ 是教师参数, $w_t$ 是位置权重. 式 (1) 把四个可独立变化的对象分开: 轨迹来自谁、教师多看了什么、教师参数是否跟随学生、局部损失保留多少词表信息.

## 1. 共同机制

### 1.1. 特权信息怎样成为教师能力

参考解或反馈不会直接写进学生答案. 教师先把特权信息与学生前缀一起编码, 计算下一 token 分布. 如果学生在某一步选错变量, 教师可以借助参考解降低错误延续的概率, 提高能恢复推理的 token 概率. 蒸馏损失随后把这次条件变化写进学生参数, 使学生在以后没有 $c$ 时也更可能采取相同行为.

这个过程依赖模型的上下文学习能力. $c$ 只提供文本或结构化反馈, 教师必须能把它用于当前前缀. 小模型、过长示范、矛盾反馈和不兼容模板都会使教师视图不再优于学生视图. 因而「同一模型加参考解」只是教师构造, 不是教师有效性的证明.

### 1.2. 梯度与状态变化

教师分布需要 stop-gradient. student rollout 完成后, 教师对完整序列做一次 Prefill, 产生形状为 $[B,T,|V|]$ 的 logits 或压缩反馈;学生以 teacher-forcing 重算同一前缀, 产生待求导 logits. optimizer 只更新学生参数. 固定教师不变;EMA 教师在更新后执行

$$
\bar\theta\leftarrow\rho\bar\theta+(1-\rho)\theta. \tag{2}
$$

如果师生共用一个模型实例, 实现仍要隔离计算图与输入 mask. 学生意外看见 $c$ 时, loss 会下降得很快, 但部署移除 $c$ 后能力消失. 验证必须直接检查 attention 可见区间, 不能只检查拼接文本.

## 2. OPSD: 参考解条件化

### 2.1. 固定教师与逐点裁剪

OPSD 使用每题参考解作为 $c$. 教师参数固定为训练起点, 避免教师随学生共同漂移. 教师在学生前缀上读取参考解, 并以 full-vocab 分布监督学生. 参考解提供的是解题信息, 学生轨迹仍由当前学生生成, 所以训练状态保持 on-policy.

论文使用逐点裁剪限制师生概率比造成的极端更新. 裁剪作用在 token 级分布项, 与 PPO 对整条策略比率的裁剪不是同一个对象. 它减小坏前缀上教师极低概率带来的梯度, 同时会截掉部分强纠错信号;应报告裁剪比例而不只报告阈值.

### 2.2. 为什么参考解不能直接当 SFT 标签

OPSD 中的参考解 $c$ 与学生轨迹 $y$ 承担不同职责. $y$ 决定训练实际覆盖哪些前缀, $c$ 只改变教师在这些前缀上的下一 token 分布. 设学生已经在第 $t$ 步选错变量, 直接对参考解做 SFT 会回到参考解自己的前缀, 看不到这个错误状态; OPSD 则把错误前缀 $y_{<t}$ 原样交给教师, 再让参考解帮助教师判断接下来怎样恢复. 训练信号因此落在部署时真正可能出现的状态上.

这种设计也限制了参考解的作用. 教师只能通过上下文学习理解 $c$, 不能读取一个脱离题目的答案字符串就自动获得纠错能力. 参考解若省略关键步骤、使用另一套符号或超过上下文截断位置, 教师条件分布可能没有改善. 一个直接诊断是比较同一学生前缀上的教师优势

$$
\Delta_t(y_t)=\log \pi_{\bar\theta}(y_t\mid x,c,y_{<t})-
\log \pi_{\theta}(y_t\mid x,y_{<t}). \tag{3}
$$

对最终错误轨迹, 有效参考解应在错误开始附近明显改变候选 token 的相对概率. 若 $\Delta_t$ 只在格式 token 上波动, 或教师与学生 top-$k$ 几乎完全相同, 额外上下文没有提供足够的新信息. 论文报告 OPSD 在数学推理上相对 GRPO 使用更少训练 token 达到相近或更高表现, 但这项优势依赖模型能否消化特权推理. 规模较小或题目难度超过模型理解阈值时, 同一组参数即使看到参考解也未必成为更好的教师. 因此 OPSD 的关键前提是「条件视图更强」, 而非「模型和自己蒸馏一定有效」.

## 3. SDFT: 从示范学习又不离开学生状态

### 3.1. 示范条件化教师

SDFT 面向没有可执行奖励、但拥有专家示范的持续学习场景. 普通 SFT 直接最大化示范序列 $d$ 的似然:

$$
\mathcal L_{\mathrm{SFT}}=-\sum_t\log\pi_\theta(d_t\mid x,d_{<t}). \tag{4}
$$

训练前缀始终来自专家. 学生部署时一旦生成自己的 token, 后续状态便可能偏离式 (4) 覆盖的分布. SDFT 先让学生生成 $y$, 再让教师读取示范 $d$ 与学生前缀 $y_{<t}$:

$$
q_t(v)=\pi_{\bar\theta}(v\mid x,d,y_{<t}),\qquad
p_t(v)=\pi_\theta(v\mid x,y_{<t}). \tag{5}
$$

优化目标在学生前缀上缩小 $p_t$ 与 $q_t$ 的差异. 示范仍提供任务知识, 却不再规定训练状态必须沿专家答案前进. 这就是 SDFT 与「把示范多训练几轮」的根本差别.

### 3.2. 为什么它可能减少遗忘

持续学习中的遗忘通常来自整个条件分布被新任务数据拉动. SFT 对示范 token 施加强烈的单点目标, 没有被选中的词表概率只通过 softmax 间接变化. SDFT 的软分布保留教师对替代 token 的相对判断, 同时训练前缀由当前学生产生. 对学生已经掌握的旧能力, 教师和学生在许多位置接近, 梯度自然较小; 新任务真正改变条件分布的位置才产生较大更新.

这不等于 SDFT 自动保护全部旧能力. 新示范若与旧任务冲突, 或教师在新示范条件下改变了通用语言分布, 蒸馏梯度仍会覆盖旧参数. 论文的顺序学习实验支持其在相应任务上的遗忘更少, 不能推出任意任务序列都不会退化. 复现实验至少同时报告当前任务、全部旧任务和一个通用能力集合, 并在每次任务切换后保留完整曲线.

### 3.3. 固定教师、在线教师与 EMA

教师参数决定目标是否随训练移动. 固定起点教师易于解释, 但它不会吸收学生后来学到的新能力; 在线复用当前学生最省显存, 目标却可能随每次更新快速漂移. EMA 教师在两者之间:

$$
\bar\theta_{k+1}=(1-\tau)\bar\theta_k+\tau\theta_{k+1}. \tag{6}
$$

$\tau$ 越小, 教师变化越慢; $\tau$ 越大, 教师越接近当前学生. 需要注意, EMA 只平滑参数变化, 教师优势仍来自示范条件 $d$. 当示范无法帮助模型判断学生前缀时, 调整 $\tau$ 只能让无效目标移动得更平滑. 工程实现还要区分「教师权重同步」与「rollout 权重同步」. rollout worker 可能使用 $\theta_k$, learner 已更新到 $\theta_{k+m}$, EMA 教师又是另一个版本. 日志应记录三者版本差, 否则同一个 loss 波动可能来自任务难度、策略滞后或教师同步延迟.

## 4. SDPO: 把环境反馈变成逐 token 信号

### 4.1. 从二值奖励到富反馈

代码、工具调用和科学推理环境常同时返回结果与文本反馈. 单元测试失败不仅给出 0 分, 还可能包含错误类型、失败用例和运行时信息. 传统 RLVR 把这些内容压成序列级标量, 一条长轨迹里的每个 token 共用同一结果. SDPO 保留反馈 $f$ 的 token 序列, 用当前模型构造反馈条件教师:

$$
q_t(v)=\pi_{\bar\theta}(v\mid x,f,y_{<t}),\qquad
p_t(v)=\pi_\theta(v\mid x,y_{<t}). \tag{7}
$$

学生仍在没有反馈的条件下生成. 教师看到同一条失败轨迹和反馈后重新计算下一 token 分布. 两者的差异把「测试告诉模型哪里错了」转成逐位置更新. 官方实现支持完整词表蒸馏, 也支持 top-$k$ 近似. 对已经采到的 token $y_t$, 一个便于观察的稠密信号是

$$
A^{\mathrm{SDPO}}_t=
\log q_t(y_t)-\log p_t(y_t). \tag{8}
$$

$A_t<0$ 表示教师看到反馈后降低了该 token 的概率, $A_t>0$ 表示反馈条件教师更认可它. 这条曲线可以定位错误影响从哪里开始, 但完整的 logit 蒸馏还会更新未采样 token, 信息量高于只使用式 (8) 的单 token 估计.

### 4.2. 没有文本反馈时怎样工作

只有成功/失败标量时, SDPO 可以从同题 rollout 组中选择成功轨迹作为隐式反馈. 失败轨迹仍提供学生前缀, 成功轨迹作为额外上下文帮助教师判断替代动作. 这与直接把成功轨迹做 SFT 不同: 蒸馏位置仍位于失败轨迹的前缀上. 若整组没有成功样本, 二值环境无法提供这种隐式示范, 此时只能等待首次成功、使用外部反馈, 或依赖模型从错误信息中自我诊断. 官方配置中的 `dont_reprompt_on_self_success` 会阻止一条成功轨迹拿自己当示范, `environment_feedback_only_without_solution` 则在没有成功解时才使用环境反馈. 这两个开关改变教师上下文的来源, 应作为算法配置记录, 不能只写「使用 SDPO」.

### 4.3. top-$k$、尾桶与传输成本

完整词表反馈的张量大小为 $B\times T\times |V|$. 词表为 128K、序列为 8K 时, 单条 BF16 logits 已接近 2 GiB. 官方实现允许只取 top-$k$, 默认配置可设 $k=100$, 并用 `distillation_add_tail` 把其余概率聚合成一个尾桶. 尾桶至少保留了未入选 token 的总质量:

$$
q_{\mathrm{tail}}=1-\sum_{v\in\mathcal K}q(v),\qquad
p_{\mathrm{tail}}=1-\sum_{v\in\mathcal K}p(v). \tag{9}
$$

若直接丢弃尾部再归一化, 损失会把「教师只在 top-$k$ 放了多少质量」这一信息抹掉. 加尾桶仍不知道尾部内部怎样分布, 但比完全截断更接近原目标. 还要记录 $\mathcal K$ 由教师还是学生选取; 两种选择分别偏向教师候选与当前策略候选, 产生的梯度并不相同.

### 4.4. EMA 与 trust region 各自控制什么

SDPO 的教师与学生参数同源, 反馈上下文制造条件差异. 训练继续后, 参数本身也会变化. 官方实现提供 EMA 与 trust-region 两种教师正则. EMA 平滑时间上的权重更新; trust region 则限制反馈条件教师相对参考分布的移动. 二者都用于防止目标快速漂移, 不负责创造反馈信息.

当教师看到反馈后依旧和学生近乎相同, 应先检查反馈模板、截断位置与模型的回顾能力. 当教师优势很强但梯度爆炸, 再检查重要性比裁剪、top-$k$ 尾部和教师更新率. 把这两种故障都归因于学习率, 会掩盖教师无效与估计器失稳之间的区别.

## 5. 训练器复用与方法选择

### 5.1. 数据流对照

| 方法 | 学生前缀 | 特权信息 | 教师参数 | 主要用途 |
|---|---|---|---|---|
| OPSD | 当前学生 rollout | 已验证参考解或推理轨迹 | 通常冻结起点 | 数学与可验证推理 |
| SDFT | 当前学生 rollout | 专家示范 | 固定、在线或 EMA | 从示范持续学习 |
| SDPO | 当前学生 rollout | 环境文本反馈或同题成功轨迹 | EMA 或 trust-region 教师 | 富反馈 RL 与测试时适应 |

三者都先生成学生轨迹, 再在相同前缀上运行特权教师. 差异集中在特权信息的来源和教师更新规则. 因此同一个分布式训练器可以复用 rollout、教师评分、学生重算和 learner 更新四段流水, 但 batch schema 必须保存 `privileged_source`、教师版本、反馈截断方式和成功轨迹 ID.

### 5.2. 一个可复查的最小批次

最小测试可以只含一道题和两条 rollout. 第一条成功, 第二条在中途出现可定位错误. 先保存学生在每个位置的 top-20, 再分别构造参考解教师、示范教师和反馈教师. 对三者计算 top-20 重合率、教师优势与 KL. 若实现正确, 更换特权信息只改变教师输入和输出分布, 学生前缀、response mask 与待求导学生 logits 保持一致.

随后检查梯度隔离. 教师 forward 应位于 `no_grad` 或显式 detach 区域, 学生 forward 保留计算图. 把特权信息从教师输入移除后, 师生使用相同参数与相同前缀时损失应接近零; 若仍很大, 通常存在 dropout、权重版本、位置编码、模板或 tokenizer 不一致. 把特权信息误放进学生输入时, 训练 loss 会异常容易下降, 但无特权验证集不会同步提高.

### 5.3. 失败现象怎样定位

回答越来越短时, 先检查 EOS 在教师分布中的优势以及损失是否按长度归一化. 重复段落增多时, 检查失败轨迹是否被高权重反复蒸馏, 以及教师看到反馈后是否真的降低循环 token 的概率. 训练分数上升、旧任务下降时, 对比固定教师与 EMA 教师, 并测旧任务上的师生 KL. 增大模型后收益才出现, 通常说明特权信息依赖较强的上下文学习能力.

SDPO 的官方结果还显示, 它可以在单个困难问题上反复采样、接收反馈并更新, 用较少尝试达到与 best-of-$k$ 或多轮对话相近的发现概率. 这种测试时自蒸馏会改变模型权重, 与只扩展上下文的多轮提示不同. 实验需要隔离每道题的权重副本, 防止前一道测试题的更新污染后一道题.

### 5.4. 已有参考解

数学题、证明题或带标准推理轨迹的数据适合先试 OPSD. 参考解质量和学生起点共同决定教师是否更强. 若学生连题目格式都无法稳定生成, 应先用少量 SFT 建立可用轨迹; 若参考解与学生风格差异很大, 需要在教师模板中明确它是辅助材料, 并测错误前缀上的局部优势.

### 5.5. 只有示范

工具使用、医学问答或新领域知识通常有示范而没有便宜的奖励函数, SDFT 更直接. 评测要沿任务序列报告新任务获得量与旧任务保留量. 单次最终平均分会隐藏「新任务涨很多、旧任务掉很多」的情况, 无法证明持续学习成立.

### 5.6. 环境会返回错误信息

编译器、单元测试、模拟器和结构化判分器能产生富反馈时, SDPO 可以把这些文本直接交给教师. 反馈中若包含答案泄漏, 教师可能只会复制修复结果; 反馈只有含糊的“错误”时, 教师优势又可能太弱. 理想反馈指出违反了哪条约束, 同时不直接给出完整目标序列. 三种方法都依赖同一个可检验条件: **加入特权信息后, 教师在学生真实访问的前缀上必须产生更有用的条件分布.** 参数是否同源只是实现形式, 不能代替这项验证.

## 6. 计算成本、机制验证与实验

### 6.1. 一次更新到底多跑了什么

普通 SFT 对一条长度为 $T$ 的序列做一次带梯度前向与反向. 三种 on-policy 自蒸馏还包含学生 Decode、教师无梯度 Prefill 和学生 teacher-forcing 重算. 若 rollout 服务与 learner 分离, 一次更新的主要阶段为

$$
C_{\mathrm{step}}
=C_{\mathrm{rollout}}
+C_{\mathrm{teacher\ prefill}}
+C_{\mathrm{student\ fwd+bwd}}
+C_{\mathrm{sync}}. \tag{10}
$$

教师与学生同规模并不意味着成本翻倍这么简单. rollout 是逐 token Decode, 教师读取完整轨迹时可以并行 Prefill, learner 则要保存反向所需激活. 长回答下 Decode 往往支配延迟; 大词表下 logits 投影、传输与蒸馏损失又可能成为瓶颈. 性能报告应分别给出四段墙钟时间, 而不是只给 learner 的 tokens/s.

显存也要分清常驻量与瞬时量. 固定教师若独占一组 GPU, 常驻一份教师权重; EMA 教师还要维护参数同步. 同卡执行时可以轮流加载或分片, 但学生反向激活与教师 logits 的峰值可能重叠. top-$k$ 能减少反馈张量, 无法减少教师自身的词表投影计算, 除非输出层也使用专门的候选计算 kernel.

### 6.2. 轨迹复用会怎样改变 on-policy

设 rollout 由 $\pi_{\theta_k}$ 生成, learner 已更新为 $\pi_{\theta}$. 同一批轨迹训练多个 epoch 可以摊薄生成与教师评分成本, 也会让前缀分布逐渐偏离当前学生. 可用已采 token 的重要性比衡量漂移:

$$
w_t=\frac{\pi_\theta(y_t\mid x,y_{<t})}
{\pi_{\theta_k}(y_t\mid x,y_{<t})}. \tag{11}
$$

长序列上的整条比率是多个 $w_t$ 的乘积, 极易出现高方差. 工程上常使用逐 token 裁剪或限制复用轮数. 无论采用哪种办法, 训练已经从严格 on-policy 变成 near-policy; 日志应记录轨迹年龄、版本差与裁剪比例. 只要 batch 仍来自数轮以前的学生, “每轮在线生成”就不能证明 learner 在当前分布上更新.

### 6.3. 必须拆开的四组消融

第一组检查状态来源: 固定专家序列、学生 rollout 与二者混合. 这组回答 on-policy 前缀是否重要. 第二组检查特权信息: 无特权教师、参考解、示范、环境反馈或成功轨迹. 这组回答教师优势来自哪里. 第三组检查估计器: full-vocab、top-$k$ 加尾桶与 sampled-token. 这组回答压缩反馈损失了什么. 第四组检查教师更新: 固定、当前学生、EMA 与 trust region. 这组回答目标漂移如何影响稳定性.

四组同时改变时, 最终分数无法归因. 例如 SDPO 相对 GRPO 的收益同时包含状态级反馈、不同的逐 token 信号和教师正则. 至少要保留「相同 rollout + 去掉反馈」「相同反馈 + 序列级奖励」「相同教师 + 不同反馈粒度」三条对照, 才能判断主要增益落在哪一层.

### 6.4. 质量指标不能只看平均 KL

平均 KL 下降可能表示学生吸收了教师, 也可能表示教师和学生一起退化成低熵分布. 一套更有解释力的监控至少包含:

- 任务成功率与 pass@$k$, 分开观察主模式质量和采样覆盖;
- 正确、错误轨迹上的教师优势分布, 以及优势第一次明显变化的位置;
- 回答长度、EOS 概率、重复率和截断比例;
- 教师 top-$k$ 落入学生 top-$k$ 的概率质量;
- 旧任务与通用任务上的性能, 用于识别遗忘;
- rollout 版本差、反馈缺失率、top-$k$ 尾部质量与重要性比裁剪率.

位置平均还会掩盖长程问题. 若每条序列按 token 平均, 长回答与短回答权重相同; 若直接对全部 token 求平均, 长回答贡献更多. 两种归一化对应不同目标. 报告应同时给出序列长度分布和 loss 的归一化方式, 否则同一个系数无法跨实验比较.

### 6.5. 数据与模板

保存题目 ID、学生原始 prompt、特权上下文、教师 reprompt 模板、截断方向和最大长度. 参考解、成功轨迹与环境反馈要有不同字段, 防止预处理阶段混成一段无法追踪的文本. 对代码任务还要保存测试环境版本、公开测试与隐藏测试的划分, 以及反馈是否泄漏隐藏答案.

### 6.6. 模型与损失

记录 rollout、learner、teacher 三个权重版本, tokenizer 哈希, 散度方向, top-$k$ 选择侧, 尾桶开关, stop-gradient 位置, EMA 更新率或 trust-region 参数. sampled-token 路径还要保存行为 log-prob; 没有它就无法检查轨迹复用产生的 off-policy 偏移.

### 6.7. 系统与结果

分别报告生成、教师评分、learner 前反向、同步和评测耗时. 最终表同时给任务得分、旧能力保留、训练 token、教师 token、GPU 小时与峰值显存. OPSD 宣称的 token 效率、SDFT 的遗忘改善和 SDPO 的样本效率分别对应不同分母, 不能拿“训练步数更少”代替完整成本.

源码级检查可以从 SDPO 的公开配置入手: `full_logit_distillation` 决定完整词表路径, `distillation_topk` 与 `distillation_add_tail` 决定反馈压缩, `teacher_regularization` 和 `teacher_update_rate` 决定教师变化, reprompt 与 feedback 开关决定特权信息从哪里来. 配置值与实际 batch 字段逐项对应后, 才能确认训练器执行的是论文方法而非同名开关.

### 6.8. 特权条件为何能产生新监督

设同一个基础模型在学生条件 $s$ 下给出 $q_\theta(a\mid s)$, 在额外条件 $z$ 下给出教师分布 $p_{\bar\theta}(a\mid s,z)$. $z$ 可以是验证过的推理轨迹、示范、错误反馈、工具结果或成功回答. 即便 $\bar\theta=\theta$, 两个条件分布也不相同. 自蒸馏学习的信号来自条件差, 不是参数凭空复制自己.

若 $z$ 与正确动作在给定 $s$ 后仍有关联, 教师可以利用它提高下一步预测. 学生通过多个训练样本学习 $s$ 与教师行为之间的稳定规律. 对每个样本都独立随机、且无法从 $s$ 推断的特权信息无法被学生泛化. 例如教师看到随机密码, 学生只看到「输入密码」, loss 可以在训练样本下降, 新密码仍不可预测.

OPSD、SDFT 与 SDPO 的差异落在 $z$ 的来源上. OPSD 的 $z$ 是已验证推理轨迹或答案, 教师知道问题应怎样解;SDFT 的 $z$ 是技能示范, 教师在上下文中临时掌握新任务;SDPO 的 $z$ 是环境反馈或成功尝试, 教师知道学生刚才哪里失败. 三者都把额外条件诱导出的分布蒸馏回无特权学生.

**学生状态仍由学生产生.** 特权只进入教师视图, 不应泄漏进学生输入. rollout 由学生在部署条件下生成, 教师再读取同一轨迹与 $z$. 如果学生训练时也看到答案或反馈, 方法变成带特权输入的 SFT, 部署时条件移除会重新产生分布偏移.

**同源参数提供兼容动作空间.** 教师和学生来自同一模型, tokenizer、词表和基本表达风格天然一致, 逐 token 分布容易比较. 外部大教师常有异构 tokenizer, 需要复杂映射. 同源设计省掉这层问题, 代价是教师能力增量完全依赖特权条件.

**教师必须真的使用特权信息.** 可把 $z$ 打乱、遮掉或换成错误内容, 比较教师分布与任务成功率. 正确 $z$ 与随机 $z$ 几乎无差别, 表示教师没有从特权条件获得有效增益;此时蒸馏只是在拟合同源模型的随机差异.

**条件捷径.** 教师看到完整参考答案时, 可能只复制下一个 token, 没有对学生错误前缀做推理. 学生会学到与训练答案相关的表面模式, 未必获得恢复能力. 可以从参考轨迹中遮掉局部步骤, 或给教师一条偏离参考的学生前缀, 检查它是否仍能重建合理后续.

**可辨识性边界.** 若学生状态 $s$ 中没有足够信息区分两种正确动作, 教师依赖 $z$ 作出的选择无法被无特权学生复现. 最优学生只能拟合教师在 $z$ 上的边缘分布. 这会表现为不可消除的师生 KL, 并非优化器失败.

### 6.9. OPSD: 参考推理怎样变成自教师

Self-Distilled Reasoner 的出发点是: 推理数据常有经过验证的解答轨迹, 普通 OPD 却只用外部教师在学生轨迹上评分, 没有显式利用这些解答. OPSD 让同一个模型一边只看问题作为学生, 一边额外看验证轨迹作为教师. 教师借助参考推理解释学生状态, 再给每个 token 稠密分布. 形式上, prompt 为 $x$, 参考轨迹为 $r^*$, 学生 rollout 为 $y\sim q_\theta(\cdot\mid x)$. 教师读取 $(x,r^*,y_{<t})$, 学生读取 $(x,y_{<t})$. 局部目标可以写成

$$
L_{\mathrm{OPSD}}=
\mathbb E_{y\sim q_\theta}
\left[\frac1T\sum_t
D\big(p_{\bar\theta}(\cdot\mid x,r^*,y_{<t})
\|q_\theta(\cdot\mid x,y_{<t})\big)
\right]. \tag{18}
$$

$r^*$ 不替换学生 rollout, 只改变教师条件. 因此教师是在学生真正访问的错误前缀上利用参考解给方向. 与直接对 $r^*$ 做 SFT 相比, OPSD 的监督位置更接近部署状态;与外部教师 OPD 相比, 它不需要另一套更大参数.

**参考解不能简单拼到 response 前面.** 教师上下文与学生上下文长度不同, response span 的 logits 必须按学生 token 对齐. 教师在读完参考解后, 对学生第一个 response token 的预测位置位于另一绝对索引. 按绝对位置切片会错位.

**固定教师与在线教师.** 若 teacher branch 使用冻结检查点, 目标稳定, 特权条件提供能力差. 若教师与学生共享实时参数, 每次更新同时改变无特权和特权分布, 目标移动. EMA 能平滑变化, 不会创造信息. OPSD 的效果仍取决于参考轨迹能否让教师保持优势.

**4–8 倍 token 效率的口径.** 原论文报告在数学推理任务上相较 GRPO 等 RL 方法达到约 4–8 倍 token 效率. 这来自逐 token 教师信号比终局二值奖励密集. 它对应论文的模型、任务和训练 token 口径, 不表示所有算力维度都减少同样倍数;教师额外前向也要计入计算.

**稠密信号为何提高效率.** 一条 $T$ token 错误解答在 RLVR 中通常只得到 0, 许多动作共享同一个负信号. OPSD 教师能在错误发生前后给不同分布, 每个位置都产生梯度. 学生更快识别哪一步偏离参考思路, 不必靠大量轨迹统计完成信用分配.

**参考轨迹的多样性.** 一个问题可能有多种正确证明. 单一 $r^*$ 会让教师偏向一种风格, reverse KL 进一步集中模式. 若目标需要多样推理, 可给多条验证轨迹、随机选择参考或让教师只读取关键中间结论. 这些处理改变教师条件分布, 应单独比较.

**错误参考的风险.** 被验证的最终答案正确, 中间推理仍可能有漏洞;自动验证器也可能被钻空子. 特权教师会把参考中的错误扩散为每 token 监督. 训练前需要验证轨迹质量, 并在学生错误状态上抽查教师建议.

**能力上限.** OPSD 能把模型在有参考解时表现出的能力压回参数, 不能保证发现参考解之外的新策略. 环境搜索或 RL 负责产生新成功轨迹, OPSD 适合高效吸收这些轨迹. 两者可以交替: 搜索扩充特权信息, 自蒸馏把信息固化.

### 6.10. SDFT: 示范怎样缓解顺序学习遗忘

SFT 从示范的固定前缀学习. 新任务数据持续更新参数时, 模型只在示范状态上受到约束, 旧任务行为可能漂移. SDFT 把示范放进同源教师上下文, 学生仍从自己的无示范状态生成, 教师在学生状态上给分布. 它把「从示范学习」改造成 on-policy 条件蒸馏. 设新技能示范为 $d=(x_d,y_d)$. 教师读取示范 $d$ 与当前任务 $x$, 学生只读取 $x$. 学生生成 $y$, 教师在 $(d,x,y_{<t})$ 上预测. 目标为

$$
L_{\mathrm{SDFT}}=
\mathbb E_{d,x,y\sim q_\theta}
\left[\sum_t D\big(
p_{\bar\theta}(\cdot\mid d,x,y_{<t})
\|q_\theta(\cdot\mid x,y_{<t})\big)\right]. \tag{19}
$$

示范通过 in-context learning 临时改变教师策略. 梯度把这种临时能力转入学生参数. 部署时不再需要示范, 因而也可以理解为 context distillation 的 on-policy 版本.

**为何可能减少遗忘.** 学生 rollout 从当前模型出发, 包含其已有行为模式. 教师在示范条件下只对新技能相关决策给出明显差异, 其他位置的同源分布较接近, 更新相对局部. SFT 则沿固定示范 token 强推参数, 更容易覆盖旧行为. 这是可能机制, 不是任何数据上的无遗忘保证.

**旧能力没有显式回放也能保留多少.** 若新任务 prompt 与旧任务完全不同, 学生 rollout 主要覆盖新任务状态, 旧状态仍没有直接约束. SDFT 的保留来自更新更贴合学生分布、同源教师与较温和目标, 并非完整旧任务回放. 长序列持续学习仍应监控旧任务并在必要时加入回放或锚点.

**顺序学习的评价.** 学完任务 $1,ldots,k$ 后, 应同时测当前任务、所有旧任务和平均性能. 遗忘可写成某任务历史最好分数减当前分数, 前向迁移则看旧训练是否帮助新任务. 只报最终平均会掩盖某一旧技能完全消失.

**示范质量与覆盖.** 一个示范只展示一条策略. 任务包含多个子技能时, 教师可能从示范中归纳错误规则. 多示范可提高覆盖, 上下文变长又增加教师成本和注意力干扰. 应按技能结构选示范, 而不是盲目增加数量.

**示范与查询的相似度.** 太相似时, 教师可能做近邻复制;太不相似时, in-context learning 不发生. 可以按语义或任务结构选择示范, 并设置随机示范对照. 真正学到规则应在未见输入上保持增益.

**固定、在线与 EMA 自教师.** 固定旧教师有利于保护旧行为, 但不随学生吸收新技能. 在线教师能利用最新能力, 也可能共同漂移. EMA 在二者之间平滑. SDFT 的持续学习实验要报告教师更新方式, 因为它直接决定旧策略锚定强度.

**与 rehearsal 的关系.** 回放保存旧样本, 在旧状态上明确训练;SDFT 让同源教师在新任务的学生状态上提供分布. 两者可组合. 回放解决旧状态覆盖, SDFT 改善新技能的 on-policy 学习. 若存储受限, SDFT 能减少回放依赖;不能据此推出完全无需旧数据.

**知识获取与技能学习.** 新知识可能无法从少量示范规律推断, 教师看见事实后可在当前问题上回答, 学生通过多样查询把事实写入参数. 技能则表现为跨输入规则, 示范需要覆盖规则边界. 两类任务对 prompt 采样和评测不同.

**冲突任务.** 新示范要求与旧策略相反时, 同一输入无法同时满足两套目标. SDFT 不能消除真实冲突, 只能控制参数更新. 应用任务标识、条件路由或显式优先级解决冲突, 并报告 Pareto 而非声称零遗忘.

### 6.11. SDPO: 丰富反馈怎样变成稠密策略信号

RLVR 常给一条尝试一个标量: 代码通过为 1, 失败为 0. 编译器报错、单元测试、judge 说明或工具返回其实包含更丰富信息. SDPO 把反馈放进同源教师上下文, 让教师重新判断学生轨迹每个位置, 再把分布蒸馏回不看反馈的策略. 设环境对学生轨迹 $y$ 返回反馈 $f(y)$ 与奖励 $R(y)$. 教师读取 $(x,y,f)$ 或由此构造的提示, 学生读取部署状态. 一个抽象目标为

$$
L_{\mathrm{SDPO}}=
\mathbb E_{y\sim q_\theta}
\left[\sum_t w_t(y,f)
D\big(p_{\bar\theta}(\cdot\mid s_t,f)
\|q_\theta(\cdot\mid s_t)\big)\right]. \tag{20}
$$

$w_t$ 可结合轨迹结果、教师置信与策略优化约束. 论文和官方实现还支持完整 logits 蒸馏、散度插值、EMA 或 trust-region 教师正则. 这些组件决定反馈怎样进入梯度.

**反馈不是 reward 的同义词.** 标量 reward 表示整条轨迹好坏, 文本反馈说明错误类型或位置. 教师利用反馈把信息转换为下一 token 分布, 完成一部分信用分配. 若反馈只有 0/1, SDPO 还可以把成功 rollout 作为失败尝试的隐式反馈.

**成功轨迹如何帮助失败轨迹.** 同一问题多次采样后, 成功回答可作为示范放给教师. 教师读取失败前缀与成功轨迹, 判断从当前状态应怎样改变. 学生仍在自己的失败状态上接受监督, 不是直接对成功文本 SFT.

**logit、token 与 sequence 反馈粒度.** full-logit 蒸馏在每个位置传递整个教师分布;token 级只保留选中动作或 top-$k$;sequence 级退化为整条结果. 官方结果强调更密粒度带来更好的信用分配. 比较时需要计入 logits 计算与通信成本.

**没有外部教师.** 自教师由当前模型加反馈形成, 省去独立奖励模型或大教师. 环境反馈仍是外部信息来源. 「无外部教师」不等于无监督, 更不等于模型凭自身输出产生能力.

**EMA teacher.** 官方配置可让参考 worker 保存学生 EMA. 慢教师降低目标随单次更新抖动, 也保留一段历史策略. `teacher_update_rate` 决定时间尺度. EMA 不解释反馈, 反馈条件下的同源模型才提供信息增量.

**trust region teacher.** 另一种稳定方法约束教师或学生不要离参考策略太远. 它与 EMA 的作用位置不同: EMA 平滑参数时间序列, trust region 直接限制策略变化. 配置选择会改变目标, 不能把两者当可互换实现细节.

**散度插值.** 官方实现中的 `alpha` 可在 forward KL、JSD 与 reverse KL 方向间插值. forward 侧传递教师覆盖, reverse 侧压低学生伪模式. rich feedback 教师可能比无反馈学生尖锐, 最佳方向取决于学生支持和任务多解性.

**top-$k$ 与尾部.** `distillation_topk` 压缩反馈, `distillation_add_tail` 决定是否保留尾部总质量. 只返回教师 top-$k$ 可能漏掉学生高概率错误 token;师生并集或 full logits 更能表达 reverse 方向. 近似收益需要与峰值显存和吞吐一起测.

**科学推理、工具使用与代码.** 三类任务都能产生验证或反馈, 结构却不同. 科学选择题的反馈可能只是正确选项, 工具环境有观察与错误消息, 代码有编译和测试. SDPO 的共同点是把反馈条件教师转成稠密动作分布, 具体模板和验证可靠性不能跨任务照搬.

**test-time self-distillation.** 对单个困难问题, 可以多次生成、识别较好尝试, 再把成功或反馈作为教师条件做针对该问题的更新. 论文报告在困难二值奖励任务上, 达到与 best-of-k 或多轮交互相同发现概率时可少用约 3 倍尝试. 这是问题级适应, 需要考虑更新成本和是否污染其他任务.

**测试时更新的边界.** 对每个问题改参数会产生数据隔离、回滚和复现问题. 若只在临时副本更新, 成本高但污染小;若累积更新, 它变成在线持续学习. 同一测试集反复适应还可能泄漏评测信息. 这些属于应用边界, 不改变自蒸馏原理.

**超过初始教师.** SDPO 的教师随训练和反馈改善, 学生最终可超过初始自教师. 能力增量来自环境反馈、成功轨迹与策略更新闭环. 这与固定大教师蒸馏不同, 后者通常受教师行为上限约束.

### 6.12. 三种方法的统一概率图

三种方法都包含五个节点: 无特权状态 $s$, 特权信息 $z$, 自教师分布 $p(\cdot\mid s,z)$, 学生分布 $q(\cdot\mid s)$, 以及产生后续状态的学生动作 $a$. $z$ 不进入部署学生, 只通过教师分布影响梯度. OPSD 的 $z$ 来自验证推理, 数据在训练前通常已存在;SDFT 的 $z$ 是示范, 目标是从上下文能力转成参数能力;SDPO 的 $z$ 由当前 rollout 与环境产生, 会随策略变化. 因而三者的非平稳性依次增强. 统一目标可写成

$$
J(\theta)=
\mathbb E_{x\sim\mu,\,y\sim b}
\left[\sum_t w_t
D_\alpha\left(
p_{\bar\theta}(\cdot\mid s_t,z)
\|q_\theta(\cdot\mid s_t)
\right)\right]. \tag{21}
$$

$b$ 是学生或与教师混合的行为策略, $D_\alpha$ 是散度族, $w_t$ 是选择/重要性/反馈权重, $\bar\theta$ 是固定、在线或 EMA 教师. 一项方法的完整定义就是把这四处写清楚.

**信息来源轴.** 参考解提供「应该怎样做」, 示范提供「这个技能怎样表现」, 环境反馈提供「刚才为什么失败」. 三种信息可组合. 例如代码题既有参考实现又有编译错误, 教师可同时读取;组合后必须消融, 才知道收益来自哪一项.

**时间轴.** OPSD 的参考解通常固定, SDFT 示范可按任务顺序变化, SDPO 反馈随每次尝试变化. 教师条件越动态, 训练数据越难复用. 保存反馈、模板、教师版本与 rollout 版本是复现的必要条件.

**目标轴.** forward KL 倾向覆盖特权教师多种模式, reverse KL 倾向从学生支持中选择教师主模式, JSD 折中并保持有界. 「自蒸馏」不规定散度. 同一个 OPSD/SDFT/SDPO 名称下, 目标方向变化会改变多样性与稳定性.

**状态轴.** 真正 on-policy 要求监督前缀来自当前学生. 轨迹复用、异步 rollout 或教师 roll-in 会形成 near-policy. 状态偏移可用新旧策略在已采 token 上的 KL 测量. 只写「学生生成」不足以证明严格 on-policy.

**教师时间轴.** 固定教师易分析, EMA 教师平滑, 在线教师适应快. 对同源方法, 教师更新过快会让师生 KL 迅速变小, 监督耗尽;更新过慢会阻碍新能力进入. 合适时间尺度取决于反馈到达频率和学生步长.

**监督粒度轴.** full logits、top-$k$ 加尾桶、已采 token log-prob、教师文本和序列 reward 形成从密到疏的层级. 密度提高通常降低信用分配难度, 同时增加计算与对教师校准的依赖.

### 6.13. 稳定性、反例与适用上限

**同源塌缩.** 教师和学生同步更新且没有固定信息锚点时, 两者可能一起收缩到狭窄策略. KL 很低、任务能力也下降. 监控外部任务指标、教师熵与固定参考 KL, 才能发现共同漂移.

**反馈污染.** 工具错误消息可能包含提示注入、无关日志或错误诊断. 教师把它当可信条件后, 会生成系统性错误监督. 反馈模板要区分数据与指令, 并用验证器确认教师建议提高成功率.

**示范冲突.** SDFT 的多个示范规则互相矛盾时, 教师在上下文中可能按顺序或表面相似度选择. 学生蒸馏后得到不稳定规则. 数据应显式标任务条件, 或拆成可路由技能.

**参考解泄漏.** OPSD 训练 pipeline 若把 $r^*$ 意外放进学生 prompt, 评测时移除会大幅退化. 必须在 token 级分别记录 teacher input 与 student input. 原始 JSON 字段正确不代表模板组装后无泄漏.

**错误成功轨迹.** SDPO 用 reward 阈值选成功示范. 验证器被钻空子时, 高奖励轨迹可能语义错误. 自教师会把漏洞解释成稠密分布, 比普通 RL 更快传播. 成功阈值需要配合独立验证与抽查.

**反馈不可归因.** 环境只返回大量日志, 教师无法判断哪部分对应哪个动作. 更长反馈不等于更多可用信息. 可先结构化错误位置、失败测试和关键观察, 再交给教师;否则上下文噪声会稀释信号.

**学生不可辨识.** 教师靠隐藏测试结果选择动作, 学生部署时没有任何可观察线索, 蒸馏只能记住训练题. 未见问题上不会泛化. 特权信息应帮助教师揭示可从 $s$ 学到的规律, 而非替学生完成不可观测决策.

**容量不足.** 同源不代表同能力: 教师借长上下文进行额外计算, 学生要把结果压进固定参数和较短输入. 复杂技能可能超过学生可表达范围. 不可消除 KL、训练集提升而测试无增益都是容量或辨识边界信号.

**支持不足.** reverse-KL 自蒸馏主要修正学生会采的动作. 目标策略位于学生极低概率区域时, 需要 SFT、教师 roll-in 或搜索先扩展支持. 纯学生 rollout 会反复访问同一错误模式.

**信号耗尽.** 学生吸收特权教师后, 师生 KL下降. 若环境没有新反馈、示范没有新技能, 继续训练只会拟合细节或压熵. 教师 advantage 和任务增益共同趋零时应停止.

**多样性损失.** 单一参考解、单一示范或单一成功轨迹会让自教师偏向一种模式. reverse KL 进一步选择主峰. 对需要策略多样性的任务, 应提供多特权视图并报告 pass@k、语义多样性和失败相关性.

**旧能力与新能力冲突.** SDFT 关注持续学习, OPSD/SDPO 也会遇到同样问题. 特权教师只强调当前目标时, 参数更新仍可能损害旧任务. 固定旧教师、旧状态回放或多目标约束分别提供行为锚点、状态覆盖和显式权衡.

**教师超越与教师漂移.** 在线自教师可以随学生和反馈改善, 也能一起走偏. 固定初始教师用于诊断, 移动教师用于吸收新能力, 两者并存比只看当前师生 KL更安全. 可以分别记录学生到固定锚点、学生到移动教师的 KL.

**标量反馈场景.** 没有文本反馈时, SDPO 可用成功 rollout 作隐式示范. 若一批没有任何成功样本, 自教师缺少正向条件, 方法退化. 搜索预算、课程难度或跨题迁移需要先提高发现成功的概率.

**无验证开放任务.** 写作、对话等任务没有可靠成功判定, OPSD 可用人工参考, SDFT 可用示范, SDPO 的环境反馈则较弱. 这类任务更依赖外部教师或偏好数据, 自反馈容易自我确认.

**测试时自蒸馏的过拟合.** 单题多次更新可记住反馈模式, 对该题有效, 不保证相邻题迁移. 评测应分开单题发现率与跨题能力, 并在每题后恢复基础 checkpoint, 避免顺序污染.

**计算上限.** full-logit 自蒸馏需要教师与学生词表分布, 同源也可能要两次前向. 长序列、rollout 与 EMA reference 同时占显存. top-$k$ 和 sampled-token 可降成本, 会改变目标信息量. 原理收益必须在总计算预算下比较.

**适用性判断.** OPSD 适合有高质量验证轨迹、希望把参考推理压入同一模型的任务;SDFT 适合有示范但缺奖励、同时关注顺序学习保持的任务;SDPO 适合环境能返回错误说明、工具观察或至少能筛出成功轨迹的任务. 三者共同要求同源模型在特权条件下确实优于无特权学生.

选择方法前可以做一个冻结诊断. 从当前学生采样轨迹, 分别构造参考解、示范或反馈条件, 比较自教师的续写成功率、正确动作 margin 和熵. 哪种条件带来稳定优势, 就优先选择对应路线. 若三种条件都没有改善, 调蒸馏超参数不会创造教师能力.

### 6.14. OPSD 的目标分解与反例

把 OPSD 的教师记为 $p_{\theta^-}(a\mid s,r^*)$, 学生为 $q_\theta(a\mid s)$. 若用 reverse KL, 单状态损失为

$$
\ell(s)=\sum_a q_\theta(a\mid s)
\log\frac{q_\theta(a\mid s)}{p_{\theta^-}(a\mid s,r^*)}. \tag{22}
$$

教师与学生词表相同, 分布差只来自参考轨迹与可能的参数时间差. 把参考轨迹去掉, 固定教师仍可能因旧检查点产生差异;把参数设为完全相同, 剩余差异才纯粹归因于 $r^*$. 一个干净消融应同时包含「同参数无参考」「旧参数无参考」「同参数有参考」三组.

**参考信息增益.** 定义教师在学生状态上的局部优势

$$
A_T(s)=\log p_T(a^+\mid s,r^*)-log q(a^+\mid s), \tag{23}
$$

其中 $a^+$ 是由过程验证或正确轨迹确定的可接受动作. 若 $A_T$ 在错误前缀上显著为正, 参考解确实让同源模型更会纠错. 只在正确前缀上为正, OPSD 可能主要强化已有路径, 对错误恢复帮助有限.

**参考解与学生前缀的矛盾.** 学生可能已经采用另一条同样正确的证明路线, 与 $r^*$ 表面不同. 教师若机械依赖参考解, 会把合法分支判成错误. 多参考、答案验证或语义过程检查可以降低误伤;单一 token 对齐无法判断两条证明是否等价.

**前缀不可恢复.** 假设学生第一步引入矛盾命题, 后续任何续写都无法形成严格正确证明. 教师在该状态上最合理的动作可能是显式回溯或重启. 如果输出协议不允许回溯 token, 局部蒸馏只能让错误后的文本更连贯, 无法修正第一步. 需要序列信用或从分叉前状态重采.

**参考解过强的复制捷径.** 教师看到完整 $r^*$ 后, 可能忽略学生前缀, 直接输出参考下一 token. 这在与参考同路时很好, 在学生异路时会产生断裂. 可比较教师对学生前缀的注意或行为: 打乱学生前缀后教师分布几乎不变, 说明它主要复制参考.

**答案型与过程型特权.** 只给最终答案, 教师需要自行恢复推理;给完整过程, 教师更容易定位, 也更容易复制. 两者形成信息量与捷径风险的权衡. 实验可分答案、关键中间结论、完整轨迹三档, 观察教师恢复率和学生泛化.

**参考轨迹由谁生成.** 人工或形式验证轨迹可信度高、数量有限;强模型轨迹规模大、可能含隐性错误;搜索得到的轨迹有验证结果, 风格可能狭窄. 数据来源决定特权教师上限. 只报告最终答案验证不足以证明中间步骤可靠.

**OPSD 与直接 SFT 的二乘二.** 以同一参考数据构造四组: 参考轨迹 SFT、参考条件教师配固定前缀、参考条件教师配学生前缀、无参考条件的学生前缀自蒸馏. 第一与第二看软分布作用, 第二与第三看状态来源, 第三与第四看特权信息. 这样才能把 OPSD 收益拆开.

**token 效率与信息密度.** RLVR 一条轨迹给一个标量, OPSD 每个位置给词表分布. 若长度为 $T$, 可用监督位置从 1 增至 $T$, 每位置还含多个候选概率. 信息量不严格等于 $T$ 倍, 因相邻 token 高度相关;但信用分配显著更密, 能解释论文报告的 token 效率.

**计算效率未必同比提高.** OPSD 要做学生 Decode、特权教师前向和学生反向;GRPO 要多条 rollout 与验证, 不一定需要大词表 logits. token 使用减少 4–8 倍, GPU 小时取决于教师实现、词表投影、batch 与并行. 两种口径必须分开.

**参考条件长度.** 很长 $r^*$ 增加教师 Prefill 成本, 还可能挤占学生轨迹上下文. 可压缩为关键步骤, 但压缩可能丢失纠错依据. 参考长度消融应同时测教师优势、训练吞吐和截断率.

**参考解中的风格.** 教师会把参考用词、格式和推理长度一并传给学生. 若目标只要正确性, 可规范化参考或在语义步骤处监督;若部署需要该风格, 则保留. 任务收益与风格迁移应分别评价.

**自教师参数的 stop-gradient.** 即使 teacher 和 student 共享底层权重来源, teacher forward 必须冻结计算图. 否则优化器既移动学生预测又移动目标, KL 可通过两边靠近而下降. EMA 或旧 checkpoint 还需确认没有参数别名.

**参考条件的安全边界.** 参考轨迹可能含敏感推理或数据. 训练后学生有机会记忆并复现. 自蒸馏并不会自动删除特权内容, 只移除部署时上下文. 数据授权和记忆测试仍需执行.

### 6.15. SDFT 的持续学习动力学

设任务序列为 $\mathcal T_1,\ldots,\mathcal T_K$, 学完第 $k$ 个任务后的参数为 $\theta_k$. 普通 SFT 优化新任务示范似然:

$$
L_{\mathrm{SFT}}^{(k)}=-\mathbb E_{(x,y)\sim\mathcal T_k}
\sum_t\log q_\theta(y_t\mid x,y_{<t}). \tag{24}
$$

所有前缀来自示范, 梯度不关心当前学生在哪些位置会偏离. SDFT 改为学生 rollout, 再让 demonstration-conditioned teacher 在这些状态给目标. 新任务梯度更贴近学生现有策略附近的决策边界.

**参数漂移与函数漂移.** 小参数变化也可能在旧任务状态上产生大输出变化. SDFT 直接减少新任务状态上的不必要移动, 不代表旧状态函数一定不变. 用参数距离衡量遗忘不可靠, 应在旧任务输入上比较策略 KL 和任务性能.

**同源教师的隐式锚点.** 教师与学生共享原有知识, 示范只在相关位置改变上下文预测. 对无关 token, 师生分布接近, 梯度较小. 这比 one-hot SFT 在整条示范上强制更新温和, 有助保留旧能力. 若示范提示使教师整体风格改变, 锚点作用会减弱.

**顺序曲线.** 对每个任务 $i$, 记录刚学完时分数 $a_{i,i}$ 与学到任务 $k$ 后分数 $a_{k,i}$. 遗忘量可取 $\max_{j\le k}a_{j,i}-a_{k,i}$. 平均准确率、平均遗忘和当前任务获得需同时报告. 「没有性能回退」应由整条矩阵支持.

**正向迁移.** 学早期技能可能帮助后续任务. SDFT 教师通过 in-context demonstration 激活已有结构, 有机会复用技能. 若新任务学习速度随历史增加而提高, 说明存在正迁移;如果只看最终平均, 无法区分保留与迁移.

**反向迁移.** 新任务训练有时改善旧任务. 同源教师分布比硬标签更平滑, 可能让共享表示得到提升. 应报告旧任务分数上升, 不要把它截断为「遗忘为零」, 因为正向变化也是持续学习的重要结果.

**示范条件选择.** SDFT 可每个查询随机选示范, 或按相似度检索. 随机选择测试规则泛化, 相似选择提高教师即时表现. 如果评测问题与示范重复, 学生可能记忆. 划分应确保语义和模板去重.

**示范数量决定规则能否被识别.** 多个互补示范能排除偶然格式，同时也拉长教师上下文；相互冲突的示范还可能使末尾样本占据过大影响。可画教师优势随示范数变化的曲线，在信息增益趋于饱和处停止追加示范。

**示范标签噪声.** SFT 直接学习错误 token;SDFT 的同源教师可能利用自身知识抵消部分错误示范, 也可能被错误条件误导. 比较教师在干净与噪声示范下的正确动作 margin, 能判断它有无纠错能力.

**知识注入的可验证性.** 给教师一条新事实示范后, 它可能在相关问题中正确回答. 学生蒸馏后要在改写问题、组合问题和冲突事实上评测, 才能区分记忆字符串与知识整合. 持续学习中的「获得知识」比单模板准确率更严格.

**任务标识.** 两个任务输入相似而标签规则不同, 没有 task id 时问题本身不可辨识. 示范教师能从 $d$ 知道规则, 学生部署时无法知道. SDFT loss 会逼学生拟合规则混合, 无法同时完美. 应在学生输入保留可部署任务标识.

**旧模型教师.** 为保护旧能力, 可让 $\theta_{k-1}$ 作为冻结教师的一部分, 当前模型的 demonstration-conditioned 分支负责新技能. 多目标同时约束旧行为和新示范. 权重过高会阻碍学习, 过低会遗忘;用 Pareto 曲线选取.

**EMA 教师的记忆长度.** 衰减 $\tau$ 接近 1 时, 教师汇总很长历史;接近 0 时几乎等于当前学生. 更新频率也影响有效时间常数. 报告一个 $\tau$ 而不报告每多少 step 更新, 无法复现.

**与 EWC 等参数正则的差别.** 参数正则限制重要权重变化, SDFT 在函数输出上给目标. 大模型参数冗余时, 函数约束允许通过不同参数路径学新技能;参数约束可能过严. SDFT 又只覆盖采样状态, 未覆盖旧状态. 两者保护对象不同.

**与经验回放的差别.** 回放直接重现旧任务状态, 成本是存储数据;SDFT 可不存全部旧数据, 依靠同源分布温和更新. 对严重分布转移, 少量回放加 SDFT通常更稳. 存储限制和隐私要求决定组合.

**训练顺序敏感性.** 先学技能 A 再 B 与反向顺序可能产生不同结果. SDFT 降低遗忘, 不消除任务非交换性. 至少随机多个顺序, 或按相关性设计课程并明确报告.

**持续学习停止条件.** 新任务分数达到目标、旧任务下降低于阈值、师生 KL进入平台, 三者共同决定停止. 只按新任务验证 loss 早停可能忽略旧能力持续下降.

### 6.16. SDPO 的反馈到梯度链条

一次 SDPO 更新可以拆成六步. 学生先对 prompt 生成若干尝试;环境运行验证并返回 reward 与 feedback;系统从成功尝试、失败说明或两者构造教师上下文;自教师对学生轨迹给逐 token 分布;训练器计算蒸馏与策略约束;参数更新后重新 rollout.

每一步都可能改变信息. 环境反馈若只保留首个错误, 教师看不到后续测试;成功轨迹筛选阈值决定哪些示范可用;教师模板决定反馈与轨迹如何对应;top-$k$ 决定多少分布结构传回学生. 方法复现必须记录整条链.

**rich feedback 的数学作用.** 令环境反馈为随机变量 $F$. 无反馈教师分布是 $p(a\mid s)$, 有反馈是 $p(a\mid s,F)$. 若 $F$ 有信息, 条件互信息 $I(A;F\mid S)>0$, 两个分布存在可蒸馏差. feedback 与正确动作无关时, 只会增加上下文噪声.

**序列 reward 怎样进入 token 分布.** 环境说「第 17 行类型错误」, 自教师结合代码前缀判断哪些 token 导致类型不匹配, 给替代 token 更高概率. 错误文本需要经过模型已有的语义能力解释，才能形成动作分布；教师自身不理解报错时，稠密化也会失败.

**成功阈值.** 官方配置用 `success_reward_threshold` 判断成功示范. 二值任务阈值直观, 连续 reward 中阈值改变示范质量与数量. 高阈值信号准但稀少, 低阈值覆盖多但可能把部分失败当成功. 应画阈值—成功数—最终质量曲线.

**没有成功样本时.** rich feedback 可直接指导失败修正;只有标量 reward 的环境则缺正向示范. 可以跨 batch 保存历史成功、用相似题成功轨迹, 或增加探索. 如果始终无成功且无文本反馈, SDPO 没有额外信息可用.

**反馈的时效性.** 代码库、工具状态或环境规则变化后, 旧反馈可能失效. 回放旧轨迹需同时恢复环境版本. 文本相同不保证语义状态相同. 对动态环境, 反馈和轨迹应带版本与时间.

**反馈长度与位置.** 编译器日志可能很长, 真正有用的是首个错误和相关栈帧. 截断策略若保留尾部而丢首错, 教师质量下降. 应按结构选字段, 而非简单取前或后若干 token.

**反馈条件的提示注入.** 工具返回可能包含「忽略之前指令」等文本. 教师把反馈包在明确数据标签内, 并限制其权限. 若自教师遵从恶意内容, 蒸馏会把注入行为固化到学生参数.

**成功轨迹与失败反馈的组合.** 成功轨迹告诉目标路径, 失败反馈指出当前路径问题. 教师同时看到两者, 更容易从学生状态映射到替代动作. 单独成功轨迹可能无法定位失败原因, 单独错误说明可能缺修复示例.

**多成功轨迹.** 不同成功解展示多种策略. 可随机选一条、按前缀相似度选、或让教师综合. 相似选择利于局部修复, 随机选择保留策略多样性. 把所有轨迹拼接会超长并引入冲突.

**负反馈是否应蒸馏.** 教师读到失败说明后给出的分布可能强调避免某些动作. forward KL 主要抬高教师候选, reverse KL 更直接压低学生伪模式. 负反馈密集场景可能偏好 reverse 方向, 多解任务仍需防模式收缩.

**轨迹级权重.** 正确与错误轨迹都可训练, 权重决定信息利用. 只训成功接近自训练, 丢失失败状态;只训失败可能缺正向锚点. 可按教师相对无反馈学生的优势加权, 让反馈确实改善分布的轨迹贡献更大.

**token 级权重.** 一条失败代码里多数 token 正确, 错误集中少数位置. 均匀 KL 会在无关位置浪费梯度. 教师分布变化量、反馈定位或验证器归因可生成 token 权重. 定位错误会错过早期根因, 需要与全量监督对照.

**教师正则为何必要.** 在线同源教师若完全跟随学生, 反馈条件分布也会随更新剧烈变化. EMA 提供时间平滑;trust region 限制相对参考的策略距离. 二者都防止闭环放大一次错误反馈.

**学生超过初始自教师的路径.** 第一次教师只会利用少量反馈;学生吸收后, 无反馈基础能力提高;下一轮同一个参数模型在反馈条件下又变成更强教师. 环境持续提供新信息, 形成自举. 固定初始教师无法完成这条循环.

**自举的风险.** 如果初期教师错误却高置信, 学生吸收错误后, 下一轮教师更确信, 同样形成正反馈. 独立环境验证和固定锚点用于区分能力自举与错误自激.

**test-time 更新的目标.** 对单题临时训练, 目标是提高在该题采样预算内发现成功的概率, 不要求全局模型泛化. 因而可接受更强问题特化. 训练后若要保留参数, 就必须测其他任务回退.

**与 best-of-k 的比较.** best-of-k 只增加采样, 不改变策略;test-time SDPO 把早期反馈压入参数, 后续样本分布发生变化. 相同尝试数下, 后者可逐步集中有希望区域. 其额外反向计算需纳入墙钟和 FLOPs.

**与多轮对话的比较.** 多轮把反馈留在上下文, 不改参数;上下文增长占 token, 每轮仍需重新读历史. 自蒸馏把反馈写入临时权重, 后续可短上下文生成. 参数更新有启动成本, 多次尝试后才可能摊薄.

**代码实现字段如何对应公式.** `full_logit_distillation` 决定 $D$ 是否见完整词表;`alpha` 控制散度插值;`success_reward_threshold` 影响 $z$ 的来源;`teacher_regularization` 决定 $\bar\theta$ 的时间关系;`distillation_topk` 与尾桶决定教师分布粗化. 每个字段都对应概率对象, 没有纯装饰配置.

**版本固定.** 官方仓库会更新默认配置. 复现实验应记录 commit、依赖、数据 split 与系统 prompt. 文档当前默认值不能替代论文使用值. 配置与实际 batch 字段还需抽样核对.

### 6.17. 三条路线与 SFT、DPO、RL 的边界

SFT 从固定目标 token 学习, 信息密集、状态离线. OPSD/SDFT/SDPO 让学生产生状态, 自教师在这些状态给软分布. 二者都可使用示范, 差别在示范是学生硬标签还是教师特权条件. DPO 从 chosen/rejected 偏好对优化相对概率, 通常没有逐 token 教师分布. SDPO 可能从成功/失败轨迹构造类似偏好信息, 但它把 feedback 条件化为教师 logits, 监督粒度更细. 把成功轨迹设 chosen、失败设 rejected 会得到另一路线. RLVR 用环境 reward 推动策略发现成功, 能超过现有教师. SDPO 让搜索产生的信息经过自教师解释后进入逐 token 梯度，再由更新后的学生继续搜索，形成反复迭代的闭环.

普通 OPD 使用外部固定教师, 教师能力来源是更大模型或专门训练. 自蒸馏使用同源模型, 能力来源是额外上下文. 外部教师适合没有参考/反馈但有强模型的场景;自教师适合特权信息充足且希望避免独立教师的场景. context distillation 在特权 prompt 下生成目标并训练无特权模型. SDFT 与 OPSD 属于这一思想的 on-policy 扩展: 目标状态来自学生而非固定序列. 状态差异决定它们是否能纠正自由生成错误. 过程奖励模型给每一步标量, 自教师给每一步完整动作分布. 前者可独立训练和审计, 后者无需额外 reward model, 同时更依赖教师校准. 任务有高质量过程标签时, 两者可组合或互相验证.

### 6.18. 一组可复算的小例子

设三 token 词表, 无特权学生 $q=(0.5,0.4,0.1)$, 特权教师 $p=(0.7,0.2,0.1)$. forward KL 梯度对 logits 为 $q-p=(-0.2,0.2,0)$, 直接把第二项概率移向第一项. reverse KL 由学生概率加权, 对学生过高的第二项也给出明显压力. 特权信息真正改变的是前两项排序. 若打乱 $z$ 后教师变成 $p'=(0.48,0.42,0.1)$, 它与学生几乎相同, 蒸馏梯度很小. 这说明信号来自正确特权条件, 不是自教师名称. 若错误 $z$ 使 $p''=(0.2,0.7,0.1)$, 蒸馏会把学生推向错误方向.

**OPSD 两步例子.** 学生第一步选错分支 B, 参考解走 A. 教师看到参考与 B 前缀后, 若能输出「回溯」动作, 当前状态可恢复;若协议没有回溯, 教师只能在 B 分支继续. 前者适合局部蒸馏, 后者需要把未来失败信用传回第一步.

**SDFT 规则例子.** 示范说明输入数字加 2, 查询为 5. 教师看示范给 7 高概率, 学生无示范可能给 5. 多个不同输入示范能表明规则;只给一例「3→5」时, 学生可能学成常数 5 或复制差值. 未见输入评测区分规则学习与记忆.

**SDPO 编译错误例子.** 学生生成变量类型错误, 编译器返回 expected integer but got string. 自教师在错误行前缀上提高转换函数或正确变量的 token 概率. 只给 reward 0 时, 所有代码 token 共享失败信号;rich feedback 把梯度集中到相关位置.

**尾桶例子.** 教师 top-2 概率为 $(0.6,0.25)$, 尾部 0.15;学生对应为 $(0.3,0.2)$, 尾部 0.5. 只重归一 top-2 会隐藏学生大量尾部质量;加入尾桶的粗化 KL能惩罚 0.5 对 0.15 的差距. SDPO 官方的尾部开关直接影响这一信息.

**EMA 例子.** 学生某 logit 连续在 0、2、0、2 间振荡, EMA 教师用大 $\tau$ 给出较平滑中间值. 它降低目标抖动, 也延迟真实能力变化. 如果新技能需要迅速进入教师, 过大 $\tau$ 会拖慢自举.

**冲突示范例子.** 任务 A 要正式回答, 任务 B 要一句话回答, 学生输入没有任务标签. 教师靠示范知道当前规则, 学生无示范无法区分. SDFT 最终只能学混合偏好. 加入部署可见的 task id 后, 问题才可辨识.

**反馈漏洞例子.** 代码验证器只检查输出文件存在, 学生生成空文件获得成功. SDPO 把该轨迹选作示范, 自教师会强化捷径. rich feedback 再密也无法弥补验证目标错误. 更强验证器是前提.

### 6.19. 实验设计与验收

三种方法都应从同一学生起点开始, 固定 prompt、训练 token 和评测解码. 外部信息预算分别记录参考轨迹数、示范数、环境尝试与成功反馈数. 只对齐 gradient step 会掩盖监督量差异. OPSD 至少比较参考 SFT、外部教师 OPD、无参考自蒸馏和参考条件 OPSD. 指标包括任务正确率、token 效率、教师计算、错误前缀恢复率和多样性. 这样才能说明收益来自特权同源教师. SDFT 需要任务序列矩阵. 除新任务得分, 报告平均遗忘、最坏任务回退、正向与反向迁移. 多个任务顺序和随机种子必不可少. 只展示一个有利顺序无法支持持续学习结论.

SDPO 需要 rich-feedback 与 scalar-only 两种环境. 比较 GRPO、成功轨迹 SFT、token 反馈和 full-logit 自蒸馏. 同时报告 avg@k、pass@k、尝试数、墙钟、teacher forward 与峰值显存. 稠密信号和额外计算一起呈现.

**冻结诊断先于训练.** 在同一批学生轨迹上, 构造有/无 $z$ 教师, 比较正确动作 margin、教师熵、续写成功率与分布 KL. 特权教师没有优势时停止, 不用完整训练证明一个输入诊断已否定的前提.

**泄漏检查.** 保存 student token ids 与 teacher token ids, 标出参考、示范、反馈和 response span. 学生输入中不应出现特权 token. 评测构造必须从原始问题重新生成, 不能复用含 $z$ 的训练缓存.

**梯度检查.** 教师参数无梯度, 学生 loss 只覆盖 response, EOS 计一次, padding 不计. full-logit 散度用三分类手算;top-$k$ 验证尾部质量;sampled-token 路径保存行为 log-prob.

**非平稳性检查.** 保存 rollout、student learner、teacher 三个版本. EMA 还保存更新次数与衰减. 用已采 token 上的新旧 KL测版本偏移. 同一个 `step` 字段不足以表示异步系统关系.

**外部信息消融.** 对 $z$ 做打乱、遮蔽、部分保留和错误替换. 正确信息应产生最大教师优势;打乱后仍同样有效, 说明方法可能依赖模板或额外 token 而非语义.

**教师条件消融.** 固定参数比较有/无特权, 固定条件比较旧/新参数. 前者测信息, 后者测教师时间差. 同时变化会让「自」和「特权」贡献混在一起.

**散度消融.** 在同一冻结轨迹比较 forward、reverse、JSD, 看梯度方向、熵和 top-$k$ 覆盖. 不同散度必须共享 logits 接口;sampled-token 近似不能与 full-logit 结果直接归因于散度.

**反馈粒度消融.** full logits、top-$k$ 加尾桶、token 与 sequence reward逐级降低密度. 报告质量和成本曲线, 而非只给最佳点. 如果 token 级已足够, full logits 的额外成本可能不值得.

**教师更新消融.** 固定、EMA 和 trust region 共享其余配置. 固定教师看上限, EMA 看自举, trust region 看约束. 比较师生 KL、固定锚点 KL 和任务能力, 避免低 KL 被误解为稳定.

**错误类型消融.** 按可恢复、不可恢复、反馈正确、反馈错误分桶. 自蒸馏应主要改善可恢复且反馈正确状态. 如果错误反馈桶也大幅学习, 系统缺少选择性保护.

**停止条件.** 新能力、旧能力、teacher advantage、师生 KL 与熵共同观察. 能力平台且 advantage耗尽后停止. 单纯 KL 继续下降可能表示模式收缩.

**先测条件信息究竟增加了多少.** 把学生可见状态记为 $S$，特权条件记为 $Z$，希望生成的正确动作记为 $A^*$. 三种方法成立的第一道门槛都可以写成条件互信息 $I(A^*;Z\mid S)>0$：知道参考、示范或反馈以后，正确动作仍然获得了学生状态没有提供的信息。这个量通常无法直接精确计算，但可以用三个可复算的代理量观察。第一，在固定状态上比较有无 $Z$ 时正确动作的 logit margin；第二，比较两种条件下完成余下任务的成功率；第三，测量 $p(a\mid S,Z)$ 与 $p(a\mid S)$ 的散度，并检查散度是否集中在真正影响答案的位置。只有散度而没有正确率提升，可能只是表达风格变化；只有最终正确率而没有局部 margin 变化，信号也许出现在更后面的决策点。把两类指标放在一起，才看得出特权信息在哪里发挥作用。

条件增益还要和参数增益分开。假设更新后的模型在无特权条件下变强，可能有两种来源：模型从 $Z$ 中提取了可迁移规律，也可能只是训练轮数增加以后重新记住了常见答案。一个直接检验是把特权条件在样本间打乱。正确配对显著优于打乱配对，说明语义关系参与了学习；正确配对和打乱配对几乎相同，则应继续检查模板长度、额外计算步数和答案泄漏。另一种检验是构造等长的无信息条件，使 token 数、位置编码和教师计算量保持一致，只移除有用语义。这样测到的是条件内容带来的差异，不会把「多看了一段文本」误算成自蒸馏收益。

**四个瓶颈决定信息能不能压回学生.** 信息瓶颈要求 $Z$ 确实包含新证据；状态瓶颈要求学生可见的 $S$ 足以区分应采取的动作；支持集瓶颈要求学生分布给教师偏好的动作留下可学习概率；容量瓶颈要求无特权模型能把规律容纳进参数。同一个失败现象可能来自完全不同的瓶颈。教师看到反馈后判断正确，但学生输入缺少任务标识，属于状态不可辨识；教师偏好的 token 在学生处概率接近数值下溢，属于支持集过窄；训练集准确率上升、跨任务能力下降，可能是容量竞争；教师本身无法利用反馈，则信息尚未被模型读懂。依次排查这四层，比调整一串优化器参数更有效。

支持集问题在 on-policy 自蒸馏里尤其突出。学生很少访问某条有效推理路径，教师就没有机会在那条路径上提供局部修正；学生一旦进入不可恢复前缀，后续再精确的 token 分布也无法改变已经提交的早期选择。可以把一次生成分成决策前缀、可恢复区间和终局区间，分别统计教师优势。若优势集中在不可恢复区间，应增加搜索、回溯或前缀重采样，把训练状态搬到关键分叉附近。若优势在可恢复区间稳定存在，局部 KL 才能有效吸收。这里的核心变量是状态覆盖，而非单次教师回答写得多漂亮。

容量瓶颈可以通过压缩曲线观察。逐步增加特权任务数量，记录无特权学生的新任务收益、旧任务损失和教师优势残差。开始阶段，学生能够吸收教师差异，表现为收益上升、残差下降；容量竞争出现后，新任务收益仍在增加，旧任务却快速回退；再继续训练，师生 KL 可能下降，但整体能力不再改善。SDFT 的持续学习特别需要这条曲线，因为示范条件教师可以临时调用多项技能，而无示范学生必须把这些技能共同放进有限参数。OPSD 与 SDPO 同样受限，只是冲突更常表现为推理模式或行为策略被覆盖。

**串联、并联与路由.** 串联方案先用环境产生反馈，再让教师结合反馈和参考轨迹解释错误，随后把解释后的分布蒸馏给学生。它适合验证器能指出失败、参考能展示解法的任务。并联方案分别计算参考教师、示范教师和反馈教师的目标，按样本可信度组合：

$$
L=\lambda_r L_{\text{ref}}+\lambda_d L_{\text{demo}}+\lambda_f L_{\text{feedback}},
\qquad \lambda_r+\lambda_d+\lambda_f=1.
$$

权重不应只按来源名称固定。参考若与学生问题不完全匹配，$\lambda_r$ 应降低；示范规则清晰且跨样本一致时，$\lambda_d$ 可以提高；反馈由严格验证器产生并能定位错误时，$\lambda_f$ 才值得占较大比重。路由方案则让每个状态只选择一种教师条件，减少冲突和计算。选择依据可以是教师 margin、条件增益、验证器置信度与状态可恢复性。并联保留多源信息，串联能形成更完整的因果链，路由适合预算受限场景，三者对应不同假设。

多源教师发生冲突时，平均 logits 往往会制造一个任何教师都没有选择的折中分布。更稳妥的处理方式是先判断冲突属于表达差异还是决策差异。两个教师都导向相同答案，只在措辞上分叉，可以在语义等价集合内合并；一个教师要求继续推理、另一个要求立刻结束，则要回到验证结果和条件可靠性决定主次。可以计算各教师对候选动作的排序相关性，并在关键 token 上保存单独 margin。冲突样本单列训练或延后处理，能够避免大量一致样本被少数矛盾梯度扰动。

**序列目标和局部目标回答的是两类问题.** 序列级 reverse KL 倾向于让学生在自身高概率轨迹附近寻找教师认可的完整行为，适合整体策略选择；局部 stop-gradient KL 在给定前缀上复制下一步分布，适合教师能够明确定位修正点的场景。前者要处理采样分布、长度和重要性权重，后者要处理错误前缀是否可恢复。若直接把局部损失沿序列求和，每个 token 看起来地位相同，但早期分叉可能决定整条轨迹。可以加入位置权重 $w_t$，使其来自教师优势变化、验证器定位或反事实重采样：遮蔽某个决策后成功率变化越大，该位置权重越高。位置权重表达的是因果重要性，教师概率表达的是动作偏好，两者承担不同角色。

长度归一化也会改变学习方向。按 token 平均时，短答案和长答案对 batch 的贡献接近；按序列求和时，长轨迹自然获得更大权重；只在关键决策点计算损失，则依赖可靠定位。数学推理常有大量格式 token，代码任务常有模板和样板语句，如果所有位置等权，真正决定正确性的分叉会被稀释。实践中可以同时报告全序列 KL、关键位置 KL 与最终成功率，观察分布贴近发生在内容 token 还是表面格式。若 KL 大幅下降而关键位置 margin 不变，自蒸馏主要学到了表达形式。

**教师质量需要分成四层诊断.** 第一层是独立能力：没有特权时，教师参数本身能否完成任务。第二层是条件增益：加入 $Z$ 后，同一参数是否更准确。第三层是恢复能力：面对学生已经生成的错误前缀，教师能否找到仍可执行的下一步。第四层是可迁移性：教师利用 $Z$ 做出的判断，能否仅凭学生部署时可见的信息重现。OPSD 常在第三层遇到困难，SDFT 的关键多在第四层，SDPO 同时依赖反馈的条件增益和错误状态恢复。只报教师最终准确率，会把这四种能力压成一个数，无法解释训练为何成功或失败。

这四层还能形成顺序筛选。独立能力很低时，先改善底座或换教师；条件增益很低时，特权信息没有被利用；恢复能力低时，调整 rollout 和前缀构造；可迁移性低时，补充学生可见变量或接受该任务只能依赖外部工具。筛选后的样本更少，却更接近真正可蒸馏的区域。极端追求教师覆盖会把不可迁移样本也塞进训练集，使学生在相同输入上面对互相矛盾的目标，最终输出平均化答案。

**实验记录要能重建每一次条件变化.** 每条样本至少保存原始问题、学生可见 prompt、特权片段的来源和哈希、rollout 模型版本、教师模型版本、采样参数、响应掩码、教师 logits 的精度与截断方式、验证结果以及最终 loss 权重。OPSD 还应记录参考与当前前缀的对齐位置；SDFT 记录示范集合及顺序；SDPO 记录环境反馈对应哪次执行。少掉这些字段，复现实验时很难判断差异来自教师能力、数据版本还是缓存错配。

验收表应同时覆盖能力、分布、代价和失效模式。能力看任务正确率、未见组合与旧任务保持；分布看关键 token margin、师生 KL、熵和尾部质量；代价看教师前向次数、保存 logits 的带宽、训练显存与环境调用；失效模式看泄漏、错误反馈、不可恢复前缀和冲突条件。四组结果共同成立，才能说明方法把特权能力稳定地迁移给了部署模型。只看最终分数会遗漏昂贵但无效的教师调用，只看 KL 又会把模式收缩当成收敛。

迁移测试需要主动移除训练时的表面线索。参考轨迹可以更换措辞和推理顺序，示范可以改变领域名词与版式，反馈可以改写为语义等价的诊断。如果学生只在原模板上受益，参数里保存的多半是条件的表面关联；若它能在新表达、新组合和更长决策链上保持关键动作 margin，才说明教师提供的规律已经进入无特权策略。同源教师和学生天然共享词法偏好，三条路线都需要用这项测试排除表面模仿。

### 6.20. 结论

OPSD、SDFT 与 SDPO 共用一个简单而强的结构: 学生在部署条件下产生状态, 同一个模型借额外信息成为教师, 教师的条件分布再压回无特权学生. 能力来源位于参考解、示范和环境反馈;同源参数提供的是兼容接口与自举可能, 没有替代外部信息.

三条路线解决不同瓶颈. OPSD 把验证推理变成学生错误状态上的稠密监督;SDFT 把 in-context 示范能力转成参数能力, 减轻顺序 SFT 的遗忘;SDPO 把环境反馈和成功尝试变成 token 级信用, 补足 RLVR 的标量瓶颈. 它们之间没有一个可互换的统一配方. 可靠自蒸馏依赖三项条件: 特权信息确实提高教师在学生状态上的判断, 学生可见状态足以预测目标行为, 学生支持与容量能够承接教师模式. 任何一项缺失, 更密的 KL只会更快拟合不可用目标.

稳定性来自明确分工. 固定或 EMA 锚点控制教师时间变化, 散度与 logits 粒度控制局部分布, 状态新鲜度控制 on-policy 程度, 轨迹/token 权重控制反馈可信度, 外部验证器控制能力方向. 把所有问题压到学习率上, 无法修复错误教师、泄漏或不可辨识任务.

**自蒸馏的本质是把「模型在更多信息下会做什么」变成「模型在部署信息下也会做什么」.** 参考、示范和反馈决定更多信息是什么;学生状态决定训练发生在哪里;教师分布决定能力怎样进入梯度. 三者都写清楚, OPSD、SDFT 与 SDPO 才能被准确比较.
