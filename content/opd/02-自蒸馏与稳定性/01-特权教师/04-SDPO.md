# SDPO：用富反馈完成自蒸馏

代码、工具调用和科学推理环境往往不只返回 0 或 1。编译器会给报错位置，单元测试会指出失败用例，工具会返回结构化错误，评测器也可能说明约束在哪里被破坏。传统 RLVR 通常把这些信息压成一个序列级奖励，模型知道「这次失败了」，却看不见哪一步导致失败。**Self-Distillation Policy Optimization（SDPO）** 保留文本反馈：当前模型在额外读到反馈后充当教师，再把反馈条件下的下一 token 分布蒸馏回不带反馈的策略。

设学生生成 $y$ 后，环境返回反馈 $f(x,y)$。教师与学生分别为

$$
q_t(v)=\pi_{\bar\theta}(v\mid x,y_{<t},f),\qquad
p_t(v)=\pi_\theta(v\mid x,y_{<t}).
$$

教师看到「测试 3 越界」以后，可能从数组边界开始改变续写；学生没有在部署输入中看到这条反馈，却可以通过分布损失吸收教师的回顾判断。**反馈先提升同一个模型的条件推理，再由蒸馏把序列级结果展开成 token 级训练信号。**

## 1. 稠密信号从哪里来

SDPO 不训练独立 reward model，也不要求一个更大的外部教师。稠密性来自教师对每个学生前缀重新计算分布。对于长度为 $T$ 的失败回答，一个标量奖励只有一次观测；反馈条件化教师可以在 $T$ 个位置产生局部差异。哪些位置真正获得有效信用，取决于反馈能否定位错误，以及模型能否把反馈映射回原轨迹。

若环境只给标量，论文还利用同一题中的成功 rollout 作为失败尝试的隐式反馈。成功解并不直接替换失败轨迹做 SFT，而是进入教师上下文，帮助教师理解失败前缀接下来应怎样调整。这保留了 on-policy 状态，同时把组内探索结果转成更密的行为目标。

## 2. 与普通 RLVR 的关系

RLVR 的优势是目标直接来自环境，能够奖励教师原本不会的发现；它的瓶颈是信用分配与样本效率。SDPO 借助模型读懂反馈的能力改善信用分配，但教师判断仍可能出错。两者更适合组合，而不是互相替代：环境结果决定方向，条件化教师决定如何把结果分配到局部动作。

如果反馈只是「wrong answer」，教师得到的信息很少，SDPO 会接近结果奖励下的自蒸馏；如果反馈包含失败测试、错误类型和约束冲突，局部信号会更明确。反馈过长也不一定更好：无关日志可能稀释关键证据，甚至让教师根据结果倒推一段表面合理、实际无法从学生状态执行的修复。

## 3. 分布目标与反馈可靠性

SDPO 可以使用 reverse KL、JSD 或压缩后的 top-$k$ 分布。reverse KL 更集中在学生当前支持集附近，适合在已有策略上纠错；JSD 对两侧支持差异更温和；top-$k$ 加尾部桶降低完整 logits 的显存与通信成本。选择哪种估计器，不能脱离反馈质量。错误反馈配上尖锐的 reverse KL，会把错误判断快速压进策略；较软目标虽然稳一些，也无法修复系统性错误的反馈源。

训练日志应把反馈类型、解析成功率和教师增益分开统计。环境返回了文本，不等于教师利用了文本。一个直接消融是随机打乱反馈与样本的配对：正确配对明显优于打乱配对，说明语义反馈确实进入了学习；两者相近，则收益可能来自额外 token、采样次数或成功轨迹泄漏。

## 4. 论文结果意味着什么

原论文在科学推理、工具使用和 LiveCodeBench v6 竞争编程上比较了 SDPO 与强 RLVR 基线，报告更好的样本效率与最终准确率。在只有标量反馈的环境里，使用成功 rollout 作为隐式反馈也能超过基线。论文还把方法用于单题 test-time training，在困难二值奖励任务上，以更少尝试达到与 best-of-$k$ 或多轮对话相近的发现概率。

这些结果说明富反馈值得保留，并不意味着任何报错文本都能稳定提升策略。程序错误通常可以定位，开放式写作反馈却可能互相矛盾；单题测试时训练还会引入额外计算与参数状态管理。把 SDPO 放进训练流水线前，应先测反馈覆盖率、教师读取反馈后的续写增益，以及成功 rollout 在每个 prompt 组里的出现概率。

## 5. 实现检查

每条训练记录至少要保留原问题、学生 rollout、环境原始反馈、反馈解析结果、作为教师条件的最终文本、同组成功样本、师生版本与损失粒度。反馈必须只进入教师输入；学生意外读取反馈会把训练变成带反馈策略，部署时条件不一致。成功样本若直接作为学生标签，方法则变成筛选式 SFT，不能再把收益归因于学生状态上的自蒸馏。

原论文：[Reinforcement Learning via Self-Distillation](https://arxiv.org/abs/2601.20802)，[官方实现](https://github.com/lasgroup/SDPO)。横向比较见[OPSD、SDFT 与 SDPO](01-三种自蒸馏.md)。
