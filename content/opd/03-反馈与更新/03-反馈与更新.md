# 反馈与更新: 从教师判断走到参数变化

OPD 最容易被讲成一句过于顺滑的话:学生 rollout, 教师评分, 然后更新. 真正决定方法差异的恰好藏在「评分」和「更新」之间. 教师可能返回完整分布、一个采样动作的概率、自然语言批评、单元测试结果或整条轨迹的胜负;训练器可能直接反传 KL, 也可能把 log-ratio 当奖励, 再经过优势估计、筛选和加权. **反馈有多密, 不等于梯度就有多准.** 一串逐 token 数值仍可能只在重复表达同一个终局判断, 一个稀疏结果也可能借助可信的过程模型形成有效信用分配.

本章把更新写成四个环节:学生产生状态, 教师读取状态并给出信号, 估计器把信号分配给动作, 优化器更新学生. 这套划分能同时容纳白盒 KL、sampled-token OPD、结果引导自蒸馏和 self-play, 也能清楚标出它们与 RL 的交界.

## 1. 统一的反馈到更新视图

对输入 $x$ 和学生轨迹 $y\sim\pi_{\theta_k}$, 记教师或验证器返回的原始反馈为 $F(x,y,s_t,a)$. 训练器不会直接消费抽象的 $F$;它先构造权重或目标 $w_t$, 再形成

$$
\mathcal L(\theta)=\mathbb E_{x,y}\left[\sum_t w_t\,\ell_t(\theta;s_t,y_t)\right].
$$

$\ell_t$ 可以是 token KL、负 log-likelihood、策略梯度项或对比损失. $w_t$ 可以恒为 1, 也可以由结果奖励、教师置信度、轨迹新鲜度和重要性比共同决定. 许多看起来完全不同的方法, 实际只改了 $F$、$w_t$ 或 $\ell_t$ 中的一项.

直接分布路线让 $F$ 本身就是教师分布, $\ell_t=D(p_T\|q_\theta)$, 梯度低方差但需要白盒访问. Policy-gradient-style 路线把

$$
r_t=\log p_T(y_t\mid s_t)-\log q_{\mathrm{ref}}(y_t\mid s_t)
$$

当作稠密奖励或优势构件, 再优化学生对已采动作的概率. 它能复用 PPO/GRPO 基建, 但 baseline、截断、序列归一化和采样版本都会进入最终估计器. 两条路线可以在相同 rollout 上工作, 数学性质却不同.

## 2. 时间信用与词表路由必须分开

假设第 $t$ 个动作得到负反馈. 时间信用问题问:这份负反馈只惩罚 $y_t$, 还是也影响此前把轨迹带到此处的动作? 即时 log-ratio 只作用当前位置;return-to-go 把后续信号累加到早期动作;折扣回报控制影响范围;baseline 则降低方差并改变相对权重. 长 CoT 与多轮 Agent 任务中, 这个选择会明显改变模型学到「局部措辞修正」还是「更早换一条解题路线」.

词表路由问题问:降低 $q_\theta(y_t\mid s_t)$ 后, 空出来的概率给谁? Full-vocab KL 明确指定教师支持的替代 token;sampled-token 策略梯度只对已采动作给方向, 其余动作通过 softmax 耦合被动变化. **一个估计器能正确处理时间信用, 仍可能不知道概率应转移到哪个反事实动作.** 反过来, 完整教师分布提供了局部替代项, 却不一定知道哪一个早期决定导致最终失败.

这也是 hybrid 目标存在的理由. 结果或验证器选择值得学习的轨迹, 教师 logits 在轨迹内部给出局部方向;或者先用过程反馈定位关键位置, 再对这些位置计算分布匹配. 两类信号互补, 不能简单相加后把权重当作无关紧要的超参数.

## 3. On-policy、near-policy 与回放

严格 on-policy 要求轨迹由当前学生产生. 分布式训练中, rollout worker、learner 和参数同步存在延迟, 所以「当前」必须写成可检查的版本关系. 设行为策略为 $\mu$, 正在更新的学生为 $\pi_\theta$. 当二者不同, 训练已进入 near-policy 或 off-policy 区域. 可用重要性比

$$
\rho_t=\frac{\pi_\theta(y_t\mid s_t)}{\mu(y_t\mid s_t)}
$$

修正动作分布差异, 但长序列上连乘容易爆炸, clipped ratio 又会引入偏差. 实际系统通常限制轨迹版本差、减少复用轮数, 并监控 ratio 分布, 而不是追求形式上的完全无偏.

回放并非天然错误. 新鲜轨迹能跟上学生当前错误, 历史轨迹则提高吞吐并保留罕见失败状态. 有价值的问题是「多旧以后信号开始误导」. 可以按策略 KL、token log-ratio 或 checkpoint 距离分桶, 比较不同新鲜度的梯度一致性与任务收益. **On-policy 的价值来自访问当前学生会犯的错, 不是来自拒绝一切样本复用.**

## 4. Outcome-based 与 self-play 放在哪里

当教师不能返回 logits, 最终答案正确性、单元测试、执行轨迹或偏好判断可以充当 outcome feedback. 如果学生在自己的 rollout 上接收这些反馈, 数据侧仍是 on-policy;若更新只使用标量奖励, 优化侧更接近 RL. 把它纳入广义 OPD 分类有助于比较信号来源, 但写公式时必须直说这是奖励优化, 不能把标量包装成分布蒸馏.

Self-play 进一步改变教师身份. 多个采样互相评议、同一模型扮演解题者与批评者、历史最优策略给当前策略提供对手, 都可能产生 on-policy 信号. 关键仍是信息增量从哪里来:角色提示、工具结果、外部规则、多样本共识或历史策略. 若所有角色共享同一信息且犯同样的错, 自洽只会强化共同偏差.

Outcome 与 logits 的结合正在形成一条重要路线. 结果反馈可过滤错误教师、调整 token 权重或校准教师分布;教师分布又能缓解终局奖励的稀疏信用. SDPO 等特权自蒸馏方法便落在这里, 详细机制放在[特权教师路线](../04-特权自蒸馏/4.1-特权教师/4.1-特权教师.md).

## 5. 一次训练循环中哪些状态在变化

Rollout 前, 系统持有 prompt、学生行为版本、采样配置和教师接口. Rollout 后新增 token、行为 log-prob、终止原因与可选环境结果. 教师评分后新增 teacher log-prob、top-$k$ 分布、文本反馈或轨迹标签. Learner 还要记录 response mask、版本号、归一化尺度与样本权重. 反向传播只更新学生;若教师来自 EMA、周期同步或同源 checkpoint, 教师还有单独的更新规则.

这张台账能抓出许多伪 OPD 实现. 轨迹如果来自静态缓存且没有版本记录, 它只是 off-policy 数据;教师如果只对自己的答案评分, 没有读学生前缀, 它没有监督学生访问的状态;若 loss 把 prompt token 也算进去, 大量梯度会浪费在复述输入;若 learner 重算 log-prob 时模板不同, importance ratio 会失真.

吞吐优化也围绕这些状态展开. 教师读取完整学生回答时可用并行 Prefill, 学生 rollout 仍需顺序 Decode;full-vocab logits 可以边算边消费, 不必全部落盘;同一教师前向可同时产出 top-$k$ 与已采 token log-prob. 原理分析应先说明信号保留了什么, 工程选择再决定怎样搬运它.

## 6. 稳定训练的判据

稳定不能只看 loss 没有 NaN. 至少要同时观察行为策略与 learner 的 KL、师生 KL、教师优势、ratio 尾部、有效 token 数、熵、EOS 概率、回答长度和任务结果. 师生 KL 快速归零而任务不涨, 常表示教师增量不足或学生只学了表面格式;任务分数短期上涨但旧能力骤降, 可能是 prompt 分布过窄或正则不足;ratio 尾部持续扩大, 表示 rollout 供应跟不上 learner.

冷启动同样属于更新问题. 学生若从不访问教师擅长的路径, on-policy 采样不会凭空发现它们. 一轮高质量 SFT、教师轨迹混合或课程式 prompt 选择, 都能先把有用动作放进学生支持集. 随后 OPD 再沿学生真实访问状态修正. **先扩大可达支持集, 再进行 on-policy 校准, 往往比从弱学生直接闭环更可靠.**
