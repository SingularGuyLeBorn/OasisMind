# DistiLLM 与 DistiLLM-2

白盒蒸馏有两个长期纠缠的问题.一边是目标函数:forward KL 容易迫使小学生覆盖教师的长尾,reverse KL 又容易收缩到少数模式;另一边是状态来源:固定数据便宜稳定,却看不到学生部署时自己制造的错误前缀,持续刷新学生 rollout 又会显著增加生成和教师评分成本.DistiLLM 试图同时处理这两个问题,用 skew KL 改善分布匹配的梯度性质,再按训练状态决定何时复用学生历史输出.DistiLLM-2 接着追问一个更细的问题:教师生成的高质量回答与学生生成的低质量回答,为什么要套同一个损失?

两代方法都属于白盒知识蒸馏,需要访问教师在给定前缀上的概率或 logits.它们与严格 OPD 有交集,却不能直接画等号.DistiLLM 的自适应 off-policy 会复用旧学生样本,因此训练状态未必来自当前学生;DistiLLM-2 同时使用教师和学生两路回答,其中教师回答上的目标本来就是离线分布匹配.判断它们是否 on-policy,应查看某个 batch 的轨迹由哪个版本生成,而不是只看方法是否包含学生数据.

## 1. DistiLLM 为什么引入 skew KL

令教师分布为 $p$,学生分布为 $q$.forward KL 为 $D_{\mathrm{KL}}(p\|q)$,教师高概率区域决定梯度;reverse KL 为 $D_{\mathrm{KL}}(q\|p)$,学生当前支持决定梯度.师生容量差大时,前者可能要求学生覆盖自己装不下的模式;后者允许学生集中到少数主模式,但教师某个概率接近零时,学生在该 token 上的代价会非常尖锐.普通 KL 还要求两侧支持关系良好,学生前缀质量较差时,数值与梯度都可能被极端概率比控制.

DistiLLM 把其中一侧替换成师生插值分布.一种 skew forward KL 写成

$$
D_{\mathrm{SKF}}^{\alpha}(p\|q)
=D_{\mathrm{KL}}\!\left(p\middle\|\alpha p+(1-\alpha)q\right),
\qquad 0<\alpha<1.
$$

对应的 skew reverse KL 可以写成

$$
D_{\mathrm{SKR}}^{\alpha}(p\|q)
=D_{\mathrm{KL}}\!\left(q\middle\|(1-\alpha)p+\alpha q\right).
$$

关键动作是把比较对象变成含有自身概率的混合分布.教师支持上的混合概率至少含有 $\alpha p$,学生支持上的混合概率至少含有 $\alpha q$,极端概率比因而受到控制.这个结构让散度有界,也缓和师生支持差异带来的梯度尖峰.$\alpha$ 不是普通温度:温度同时重塑整个 softmax,而 $\alpha$ 直接决定教师与学生在分母混合分布中的占比.

当 $\alpha$ 靠近边界时,skew 目标会接近相应的 KL 方向;处在中间区域时,它牺牲一部分精确分布匹配,换取更平滑的优化.因此不能只把 skew KL 理解成「新的散度名字」.它明确承认有限容量学生不一定能完整复刻教师,并把支持不重合带来的风险写进目标.实验仍需观察输出熵、长度与多样性,因为有界不等于不会模式收缩,混合系数也没有跨任务通用的最优值.

逐 token 损失要在同一个前缀上计算.给定状态 $s_t=(x,y_{<t})$,教师和学生分别输出 $p_T(\cdot\mid s_t)$ 与 $q_\theta(\cdot\mid s_t)$.完整词表计算保留最多信息,top-$k$ 压缩则必须说明候选集取教师 top-$k$、学生 top-$k$ 还是二者并集,其余概率是否合成尾桶.只保存教师 top-$k$ 并重归一化,可能完全看不到学生高概率但教师反对的 token,尤其会扭曲 reverse 一侧的作用.

## 2. 自适应 off-policy 怎样节省 rollout

学生生成序列能缓解训练与部署的前缀分布失配,代价是 Decode 昂贵.每个 optimizer step 都重新采样,还要让教师在新前缀上计算分布.把一批 rollout 反复训练又会产生策略滞后:生成轨迹的学生是 $q_{\theta_k}$,正在更新的 learner 已经变成 $q_{\theta_j}$.DistiLLM 没有假装两者始终相同,而是把历史学生输出作为可复用的 off-policy 数据,根据验证表现自适应决定何时启用它们.

这项设计处理的是采样预算,并没有把旧轨迹重新变成 on-policy.设缓存轨迹来自行为策略 $b$,当前学生为 $q_\theta$,经验目标可写成

$$
\mathcal L_{\mathrm{cache}}=
\mathbb E_{y\sim b(\cdot\mid x)}
\left[\sum_t D_{\mathrm{skew}}
\bigl(p_T(\cdot\mid s_t),q_\theta(\cdot\mid s_t)\bigr)\right].
$$

局部损失仍然直接可微,外层状态分布却属于 $b$.若缓存太旧,训练预算会集中到当前学生不再访问的前缀.复现时应保存生成版本、复用次数和新旧学生在已采 token 上的 KL,不能只写「使用 replay」.论文报告相对近期蒸馏方法最高达到 4.3 倍加速,这个数字对应其模型、数据、硬件与比较口径,说明自适应复用可以显著省去在线采样,并不保证任意系统都同比缩短墙钟时间.

自适应开关的直觉是让训练反馈决定数据来源.当当前策略从学生历史输出中仍能获得验证收益时,继续复用比较划算;收益减弱或退化时,再刷新数据.固定每批复用 $K$ 次无法感知训练速度差异,同一个 $K$ 在大学习率和小学习率下对应完全不同的策略偏移.验证驱动机制更贴近「旧数据是否仍可教」,但它也引入了验证集选择、测量噪声和额外评估成本.

缓存内容不只有文本.若教师固定,可以保存对应 logits 省去重复教师前向,但完整词表张量体积很大;只缓存文本则每次仍需教师评分.如果教师、模板或 tokenizer 版本改变,旧 logits 全部失效.一个可复现缓存条目至少包含 prompt 与回答 token、行为策略版本、教师版本、模板哈希、响应 mask、采样配置和教师分布的压缩方式.

## 3. DistiLLM-2 为什么拆开两路数据

许多蒸馏方法把教师生成回答与学生生成回答混进同一个数据池,再对两类前缀使用相同散度.DistiLLM-2 认为两类数据承担的功能不同.教师回答展示希望学生提高概率的行为,学生回答暴露当前模型自身容易生成、却可能质量较差的行为.前者天然带有正向含义,后者更像需要压低的负向样本.若两边都只做对称的分布靠近,这种数据类型差异没有进入目标.

DistiLLM-2 因此构造对比式蒸馏:在教师回复上提高学生似然,在学生回复上降低其相对似然,同时用教师概率判断哪些响应真正值得拉近或推远.抽象地,对同一提示 $x$ 的教师回复 $y^T$ 与学生回复 $y^S$,可以把目标理解为扩大

$$
\Delta_\theta(x)=
\log q_\theta(y^T\mid x)-\log q_\theta(y^S\mid x),
$$

但论文的具体损失并非把普通 DPO 原样套过来.教师对两类回复的概率提供蒸馏依据,不同数据类型使用与其作用相配的损失.论文动机正来自一个观察:以往工作常把同一损失同时用于教师数据与学生数据,忽略了「什么数据配什么目标」的协同关系.

这里的「降低学生回复似然」需要谨慎理解.学生采到的回答不一定全错,教师回答也不一定始终更好.如果无条件把所有 $y^S$ 当 rejected,模型会压低自己的正确模式,甚至通过长度或格式捷径扩大对比差.教师概率、任务验证或质量过滤必须确认两路回答之间确实存在可教差距.论文还讨论了简单用教师替换 DPO 参考模型可能出现的 reward hacking,DistiLLM-2 的目标设计正是为了避免仅靠一个可被利用的相对分数.

两路数据还改变了状态覆盖.教师回复提供规整的高质量前缀,帮助学生进入当前几乎访问不到的正确区域;学生回复提供部署时常见的错误前缀,暴露需要压低或修复的模式.这与模仿学习中的 expert roll-in 和 learner roll-in 相似.两类 batch 的比例决定训练究竟偏向扩大正确支持,还是清理学生伪模式.比例、长度归一化和每路损失尺度应一起报告,否则回答更长的一侧会仅凭 token 数取得更大权重.

DistiLLM-2 的实验覆盖 instruction following 与代码生成,并展示了偏好对齐和视觉语言扩展等应用.这些结果说明对比式框架能够迁移到多种数据类型,但并不把它变成通用偏好算法.蒸馏目标仍以强教师为知识来源,教师没有覆盖的高回报行为不会因为对比结构自动出现.

## 4. 与 GKD、MiniLLM 和 OPD 的关系

GKD 把两个轴拆得最清楚:序列可以来自固定数据或学生,局部散度可以选择 forward KL、reverse KL 或广义 JSD.常见实现把 rollout 停梯度,因此优化的是已收集状态上的条件分布.MiniLLM 从序列 reverse KL 出发,保留采样分布对参数的依赖,需要策略梯度式估计并处理 reward-to-go 方差.DistiLLM 主要沿「怎样让局部目标更稳、怎样少生成一些新轨迹」推进,DistiLLM-2 则沿「两类序列不应共享同一训练含义」推进.

四者都可能使用学生生成文本,但 on-policy 程度不同.GKD 每轮用当前学生生成并立即训练时最接近严格 OPD;MiniLLM 的序列期望本身定义在学生分布上;DistiLLM 主动允许历史样本复用,属于自适应 off-policy;DistiLLM-2 同时引入教师与学生数据,是混合状态分布.**OPD 描述的是监督落在学生当前访问状态上,DistiLLM 描述的是一套包含散度和数据复用的蒸馏框架.** 两个标签可以重叠,不能互相替代.

离线序列级 KD 的边界更明显.它让教师先生成完整回答,学生随后对教师 token 做 SFT:

$$
\mathcal L_{\mathrm{seqKD}}
=-\mathbb E_{y^T\sim p_T(\cdot\mid x)}
\sum_t\log q_\theta(y_t^T\mid x,y_{<t}^T).
$$

这条路线只需要教师文本,师生 tokenizer 可以不同,训练状态全部来自教师回答.它没有学生前缀上的教师分布,因而不属于 OPD.DistiLLM-2 虽然也使用教师回答,还额外使用学生回答与白盒概率构成对比,所以不能简化成普通序列级 KD.

## 5. 推理蒸馏与 OPD 的完整边界

CoT 蒸馏通常指让强教师生成带推理步骤的完整轨迹,再对学生做 SFT.无论轨迹是简短 rationale、长 CoT,还是带回溯与验算的 think block,只要学生在教师给出的固定前缀上最大化 token 似然,它仍属于离线序列级蒸馏.推理内容改变了训练数据的信息密度,没有改变状态来源.学生部署时若走到教师轨迹以外的前缀,训练目标没有直接教它怎样恢复.

Distilling Step-by-Step 又有自己的目标结构.它从 LLM 获取标签与 rationale,把二者作为多任务监督训练较小的任务模型.它证明 rationale 可以减少达到目标性能所需的数据量,但其状态仍由离线样本给定.把 rationale 当额外目标与把教师 logits 放到学生 rollout 上,解决的是两件不同的事:前者丰富一条样本告诉学生什么,后者改变监督发生在哪里.

长 CoT 推理蒸馏的优势是接口简单.教师可以是闭源 API,师生大小、架构和 tokenizer 都可不同;数学和代码还能用答案验证筛选轨迹.代价是学生只看见一条或少数教师采样路径,学到的可能混有教师风格、冗长习惯和不忠实的中间推理.终答正确也不能保证过程每一步正确,将长轨迹逐 token 模仿会把过程漏洞一并写入学生.

OPD 需要更强的接口,通常要求共享或可对齐的输出空间,教师还要对学生生成前缀逐位置给分布.它的优势是能处理学生自己访问的状态,把教师信号送到错误附近;代价是 rollout、在线教师前向与 logits 处理更贵.教师若无法理解学生坏前缀,OPD 也只会给出局部流畅而全局无效的修正.

两者可以按顺序组合.先用经过验证的长 CoT 做离线 SFT,把学生带到基本可用的推理区域;再让学生 rollout,由教师在这些前缀上做 OPD,针对自由生成时的错误分布精修.若环境能给最终奖励,还可在后面加入 RL 探索教师之外的策略.三段分别承担支持集建立、学生状态纠错与能力上限探索,不能用「都是蒸馏」把作用混在一起.

也可以把参考 CoT 作为教师特权上下文,教师读取参考轨迹和学生前缀,学生只读自己的前缀.这时方法已经从普通 CoT SFT 转向 OPSD:参考推理不再是学生照抄的标签,而是教师解释学生状态的额外信息.同一份 CoT 数据因此能支持两种完全不同的训练方式,分界落在学生训练前缀与教师条件,不在文件名是否包含 reasoning.

## 6. 复现与验收

复现 DistiLLM 时,先固定教师、学生、tokenizer 与聊天模板,用短序列验证 skew KL 的数值和每个 logit 的梯度方向.随后分别比较固定数据、当前学生数据与缓存学生数据,记录生成版本和复用次数.只有在相同总计算或墙钟预算下,4.3 倍加速一类结论才有可比性;相同步数会忽略每步是否包含 Decode 与教师前向.

复现 DistiLLM-2 时,应分别统计教师回答与学生回答的数量、长度、教师 log-prob、验证质量和损失贡献.交换两路损失、随机打乱教师/学生标签、只保留教师路或学生路,可以判断收益是否真的来自数据类型与损失的协同.若简单增加教师数据就获得同样提升,对比目标的独立贡献便没有建立.

两代方法都要同时监控生成指标与分布指标.训练 loss 下降但任务分数不升,可能是回答缩短、熵坍缩、EOS 概率改变或缓存过旧.按正确/错误、长/短、教师高低置信分桶观察,比一个平均 KL 更容易定位问题.词表压缩时还需报告保留概率质量,否则不同 top-$k$ 设置下的损失数值不能直接比较.

冷启动质量会直接改变两代方法的数据含义.学生尚不能稳定生成合法格式时,学生路几乎全是语法和模板错误,对比目标很容易先学会压低这些表面模式,却接触不到任务核心决策.先用教师回复做一轮序列级 SFT,或提高教师轨迹比例,可以把学生带入可教区域.等 rollout 成功率、格式通过率和教师在学生前缀上的恢复率达到基本水平,再增加学生路与缓存复用.这套日程应由可观察指标驱动;固定在某个预设 step 切换,很可能提前把大量坏前缀送进训练器,或在学生已经成熟后仍把预算花在教师轨迹上.

教师数据同样需要分层.教师高似然回复通常更符合教师自身分布,却不一定通过外部任务验证;验证成功的回复也可能位于教师概率较低的创新区域.只按教师 log-prob 筛选会偏向常见表达,只按终局奖励筛选又可能保留过程漏洞.可把教师置信、环境验证与多样性分别记录,让采样器在高置信常规样本和低频正确样本之间保留明确配额.DistiLLM-2 的对比结构依赖教师路确实提供较好行为,数据筛选若把这项前提破坏,损失再精巧也无法恢复正确方向.

长度归一化尤其容易造成暗中的目标偏移.教师回复通常更完整,学生回复可能更短或更早输出 EOS.按 token 求和会让长教师回答自然获得更大权重,按每条序列平均又会让短学生回答中的单个错误 token 占比过高.比较两种数据路时,应同时报告总 token、每序列损失和按位置分桶的梯度范数.若训练后长度明显靠近教师,还要判断这是任务质量改善,还是归一化让模型单纯复制教师篇幅.

缓存更新可以用三个信号共同控制.第一是策略新鲜度,比较行为学生与当前学生在已采 token 上的 log-ratio;第二是可教性,观察教师相对当前学生在缓存前缀上的优势是否仍然存在;第三是任务收益,检查用缓存更新后独立验证集是否改善.只看版本差会忽略每步更新大小,只看训练 loss 会鼓励复用容易拟合却已经过时的数据.当策略偏移过大、教师优势消失或验证收益转负时,刷新 rollout 才有明确依据.

跨 tokenizer 蒸馏是另一条边界.DistiLLM 的逐 token skew KL 和 DistiLLM-2 的白盒概率比较都默认输出事件能够对齐.教师一个 token 对应学生多个 token 时,按位置比较 logits 没有概率意义.可以退回教师文本上的序列级 SFT,也可以在字节或字符串区间上构造概率映射,但后一种方法会引入新的近似和计算成本.若实验使用不同 tokenizer,必须说明对齐事件和归一化方式,不能仍按共享词表公式解释结果.

公平比较还要统一教师调用预算.离线序列级 KD 可能只让教师生成一次,DistiLLM 要在给定前缀上读取分布,DistiLLM-2 又同时持有两路回答.相同训练 token 不代表相同教师 FLOPs,相同 optimizer step 也不代表相同数据新鲜度.至少给出教师生成 token、教师 Prefill token、学生 Decode token、learner token、峰值显存和墙钟.如果目标是部署压缩,还应把学生最终延迟和显存放回同一张表,否则训练效率提升与部署收益彼此脱节.

目标实现还应通过退化测试.把 skew 系数推向相应边界时,数值应接近预期 KL;关闭学生路时,训练应退回教师数据上的蒸馏;关闭教师路时,需要明确剩余目标究竟在压低哪些学生样本.把教师设成学生且输入完全一致,局部分布差应趋近零.这些小测试不依赖大规模 benchmark,却能发现最常见的方向写反、混合系数颠倒、教师梯度未停止和响应 mask 错位.

还可以构造一个三 token 的精确算例.手工给定师生概率,先计算 forward KL、reverse KL 与两种 skew KL,再用自动微分检查每个学生 logit 的梯度符号.随后为同一提示准备一条教师回答和一条学生回答,观察对比目标是否确实提高前者相对似然并降低后者.等有限词表结果完全可复算以后再扩大模型,能把公式错误与训练噪声分开.

最终可用一张三轴表验收任何蒸馏实验:外层轨迹来自教师、当前学生还是历史学生;局部信号是硬 token、完整分布、粗化分布还是对比差;梯度是否穿过采样分布.序列级 KD、CoT SFT、GKD、MiniLLM、DistiLLM 与 DistiLLM-2 都能落到这张表中.方法名称只提供索引,三个概率对象才决定模型到底学了什么.
