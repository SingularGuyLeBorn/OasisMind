# 推理与混合目标: CoT、RLVR 与 OPD

推理模型把 OPD 推到台前, 也让几个概念挤在了一起. 强教师生成长 CoT 后让学生 SFT, 学生自己 rollout 后接受可验证奖励, 教师在学生前缀上返回逐 token 分布, 三者都可能提升数学或代码能力, 训练日志里也都会出现 response token、log-prob 和正确率. 但它们对状态分布、信息来源与信用分配的处理并不相同. **CoT 描述监督内容的形态, on-policy 描述状态由谁产生, distillation 描述目标从谁那里来.**

这一章把推理训练拆成三层. 第一层让学生获得可用的推理语言与基本解题路径;第二层让学生在自己的错误状态上得到局部方向;第三层用结果奖励鼓励教师也未覆盖的新策略. 这三层可以组成流水线, 也可以在同一批 rollout 中形成混合目标.

## 1. 离线 CoT 蒸馏解决冷启动

教师预先生成完整推理轨迹, 学生在这些固定 token 上做最大似然, 属于 sequence-level KD 或 reasoning SFT. 它的优点是稳定、便宜、容易筛选, 特别适合把长推理格式和基本搜索策略放进小模型支持集. DeepSeek-R1-Distill、s1、LIMO 等工作展示了高质量推理轨迹的价值, 但训练时的前缀来自教师数据, 因而仍存在自由生成后的状态失配.

这个阶段的核心变量是数据. 答案正确只是最低条件;还要检查轨迹有没有中途逻辑错误、是否靠泄漏答案完成、长度与难度是否匹配、不同题型是否覆盖. 把错误但写得像推理的长文本交给学生, 只会训练出稳定的错误风格. 对可验证任务, 执行器和答案校验应先筛掉失败轨迹;对开放任务, 多教师或人工复核更可靠.

离线 CoT 对弱学生尤其重要. Reverse-KL 风格的 on-policy 更新主要重排学生已经访问的模式;若学生连合法解题步骤都采不到, 教师在其乱码前缀上逐 token 指导也很难产生新路径. SFT 先把路径放进支持集, OPD 再处理学生沿路径走偏后的局部状态.

## 2. OPD 校正学生自己的推理状态

进入 OPD 后, 学生针对题目生成 $y\sim\pi_\theta$, 教师在每个 $s_t=(x,y_{<t})$ 上读取相同前缀并返回条件分布. 教师此时面对的可能是一段正确推理、一个尚可恢复的岔路, 或已经破坏语义的前缀. 只有教师能在这些状态上持续提供更好的下一步分布, 稠密监督才有意义.

推理风格兼容性因而比独立 benchmark 分数更关键. 一个擅长简短符号推导的教师, 未必能稳定续写学生的自然语言探索;一个习惯从头重做的教师, 在被迫接受错误前缀时可能只会修辞而不会纠错. 可从学生 rollout 截取不同位置, 测教师对可恢复动作的 margin、困惑度和终局成功率. **教师要在学生访问的状态上更强, 不是只在自己的轨迹上更强.**

逐 token 信号也不等于真实过程监督. 教师概率差可能集中在少数位置, 其余 token 只是风格对齐;同源教师还可能和学生共享盲点. 近期 token-level 分析发现, 稠密损失的有效纠正位置可能相当稀疏. 因此需要把 KL 峰值位置与语义角色、后续结果和反事实替换结合分析, 不能用「每个 token 都有 loss」直接推出「每一步推理都被教会」.

## 3. RLVR 负责探索教师之外的策略

RLVR 让学生在自己的轨迹上接受可验证结果奖励. 数学答案、单元测试、形式证明检查器或工具执行结果不要求教师给出正确下一 token, 因而有机会奖励教师没有展示过的新解法. 代价是信号稀疏, 长轨迹上的信用分配困难, 采样成本也更高.

OPD 与 RLVR 的能力来源不同. OPD 把教师已有行为迁移到学生访问状态, 上限受教师在这些状态上的判断约束;RLVR 用环境结果选择策略, 理论上能够越过固定教师, 但探索效率取决于学生初始能力和奖励可验证性. 把「OPD 比 RL 样本高效」理解成 RL 已经没用, 会漏掉最重要的边界:教师能教的部分适合蒸馏, 教师也不会的部分仍要探索.

二者可以共享 rollout. 对成功轨迹, 环境奖励确认终局有效, 教师分布提供局部替代动作;对失败轨迹, 结果奖励给出负方向, 教师判断哪些前缀尚可恢复. 一个常见混合式目标写成

$$
\mathcal L=\lambda_{\mathrm{distill}}\mathcal L_{\mathrm{OPD}}-\lambda_{\mathrm{rl}}\mathcal J_{\mathrm{RLVR}}+\lambda_{\mathrm{reg}}\mathcal L_{\mathrm{anchor}}.
$$

权重不能只按 loss 数值调到相近. 三项的 token 覆盖、梯度方差和序列长度归一化不同, 应比较梯度范数、夹角与各任务切片的变化.

## 4. 过程反馈与结果反馈怎样配合

结果反馈可信但稀疏, 过程反馈密集却可能错. 最简单的组合是 outcome gating:只有答案通过验证的轨迹才做自蒸馏, 或按结果给 token KL 加权. 更细的方案用执行日志、编译错误、证明器状态或教师批评定位关键步骤, 再对局部区间分配更高权重. 还可以让教师在看到结果后重新评估学生前缀, 把「这条轨迹失败了」转成条件分布变化.

这里要防止答案泄漏. 特权教师可以看到参考解或执行反馈, 学生部署时看不到. 教师对学生已采前缀给分时, 参考答案不能被拼进学生输入、缓存或 label mask 错位的区域. 否则训练指标会很好看, 模型学到的却是读取答案位置. 特权信息只用于构造教师分布, 学生侧上下文必须严格保持部署形态.

另一个风险是 outcome 把探索多样性压没. 若只蒸馏当前能成功的轨迹, 学生会越来越集中在少数容易模式;困难题的失败状态得不到监督. 可保留「失败但教师可恢复」的轨迹, 或按教师优势而非最终成败选样. **结果负责判断整条路线是否奏效, 教师优势负责判断当前状态是否仍值得教.**

## 5. 长 CoT 带来的特殊问题

长序列放大策略滞后. 一次 rollout 生成数千 token, 等教师评分和 learner 更新完成时, 行为策略可能已落后多个版本. 样本复用进一步扩大差异. 监控应按位置统计 importance ratio 与师生 KL, 因为长尾位置通常最旧、方差也最高.

长度本身还会成为捷径. 教师更短时, reverse KL 可能过早抬高 EOS;教师更长时, 学生可能学会无效展开. 任务正确率、平均长度、正确样本长度、错误样本长度和单位 token 收益应放在一起看. 对简单题保持短答、困难题增加计算, 比统一拉长 CoT 更接近真正的推理提升.

多轮工具任务把状态从文本前缀扩展为环境状态. 工具调用改变外部世界, 教师若只读取对话文本却没有相同工具结果, 条件分布就不在同一个状态上. Agent-level distillation 需要记录动作、观察、工具版本和环境转移, 并处理跨回合信用. 这也是 OPD 从单轮推理走向 long-horizon 时最明显的研究缺口.

## 6. 一条更稳的训练顺序

先用经过验证的 CoT 数据完成冷启动, 让学生能够生成格式正确且偶尔成功的轨迹. 随后在学生 rollout 上做分布蒸馏, 修正真实暴露的错误前缀. 当师生差距缩小、教师增益开始耗尽时, 增加 RLVR 权重, 用环境奖励探索教师之外的策略. 训练全程保留通用数据或锚定损失, 避免推理专项吞掉对话与知识能力.

这不是固定配方. 强学生可以直接进入 OPD;黑盒教师只能先做 CoT 数据或偏好信号;没有可靠验证器的开放任务更依赖教师分布. 判断顺序的依据是支持集、教师增益与奖励可靠性, 不是方法发布时间.
