# knowledge-garden

## 创建入口

用户说「创建知识库」「新增一个领域库」「把专题拆出去」时，使用本技能，不必等斜杠命令。补已有库时先 `garden_get`、`post_list`，确认原有结构与链接。

创建前读取仓库的 `docs/knowledge-base-design.md`，尤其 §0 文件契约、§3 类型选择与 §4 页面职责；同时读 `docs/writing-spec.md` §3.5 与正文、公式、配图要求。完整英文目录标识区分大小写，显示标题说明领域。按领域的问题与知识关系分类，专题算法库与团队模型谱系库各自组织。

## 目录与标题

- 一级 `1-章/1-章.md`，二级 `1.1-路线/1.1-路线.md`，都必须有同名目录与首页。
- 三级 `1.1.1-主题.md` 可以成为叶子；继续展开时使用同名目录和首页，内部材料用 `01-…` 局部编号，不生成 `1.1.1.1`。
- 编号同时写进 frontmatter `title`：`1.1.1 · 主题`。前端使用此标题，不会从文件名补编号。`_garden.md` 不编号。
- 文件头使用 `title/category/tags/published/excerpt`，不写 `garden`。正文 `## 1.`、`### 1.1.` 使用本篇局部节号，不能遗漏，也不沿用文件层级继续续号。
- 首页解释领域和主线，章首页建立共同问题，路线首页讲方法分叉，叶子完成具体论证。文体与小节名称随材料变化，不机械套同一篇模板。

## 写入与调研

先用 `garden_list` 确认没有重复库，`garden_create` 创建 `_garden.md`；先建父首页，再建子页。文章用 `post_create` / `post_update`，禁止 `write_file` 直写 `content/`（除 uploads）。

例如创建叶子：`garden="ResearchNotes"`，`slug="1-研究对象/1.1-共同基线/1.1.1-目标与约束"`，`title="1.1.1 · 目标与约束"`。`slug` 不含 `.md`；`content` 传正文，元数据分别作为工具参数。创建同名首页也传完整 slug，例如 `1-研究对象/1.1-共同基线/1.1-共同基线`，不用 `createFolderIndex` 生成另一份 `index.md`。

先搜索综述、代表论文和官方实现，再确认目录。社区材料用来补理解与找问题，技术结论回查原始来源；知乎检索和正文获取先读 `docs/zhihu-cli-usage.md`。不要只依靠预训练知识。公式、数值、证据来源和作者评价遵守写作规范，正文通常 8000–12000 汉字，材料不足时说明缺口，不灌水。相关链接写实际相对路径与中文标题，不生成尚不存在的目标。

参考文件头见 `templates/article.md`，首页写法见 `templates/home.md`；两者只作起稿材料，不能把占位符、状态说明或过程记录写进读者正文。新文默认草稿，公开发布按用户授权执行。

## 验收

运行 `node scripts/content-check.mjs --garden=<目录标识> tree files links frontmatter markers structure --list`，新库必须全部通过。逐个确认新改文件 NUL 为 0，回读事实、公式与段落，按仓库去 AI 味规则做轻度检查。再从界面走一遍卡片 → 首页 → 章 → 路线 → 叶子：编号可见、返回父节点正确、正文页内导航可用，图片流向和变量说明完整。

运行环境没有终端时，通过可用文件工具逐项核验相同要求，并明确哪些自动检查未执行，不能报成全绿。需要长时间任务时，仅在用户要求 Goal 或过夜运行时设置目标；服务重启不自动续跑。

## 长材料

阅读结果带 `nextOffset` 或 `truncated` 时，继续分段读取至结束；不能基于残缺材料写结论。调研记录保留在运行时资料目录，交付正文不夹带执行日志。
